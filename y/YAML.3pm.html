VERSION

Ce document décrit la version 1.31 de YAML.

IMPORTANT - LISEZ CECI D'ABORD

Si vous avez besoin d'utiliser YAML avec Perl, il est probable que vous examiniez d'abord ce module ("YAML.pm"). Il existe plusieurs modules YAML https://metacpan.org/search?q=yaml en Perl et ils supportent tous l'API simple Load() et Dump(). Comme celui-ci porte le nom évident "YAML", il peut sembler évident de le choisir.

En tant qu'auteur de ce module, je vous demande humblement d'en choisir un autre. YAML.pm a été la toute première implémentation YAML au monde, publiée en 2001. Elle a été initialement créée comme prototype, plus de 2 ans avant la publication de la spécification YAML 1.0. Bien qu'elle puisse fonctionner pour vos besoins, elle contient de nombreux bugs et est à peine maintenue.

Veuillez envisager d'utiliser d'abord ceux-ci :

  • YAML::PP - Pure Perl, Complet, Bien Maintenu
  • YAML::PP::LibYAML - Une liaison Perl pour "libyaml", comme YAML::XS mais avec l'API YAML::PP.

Le reste de cette documentation reste inchangé...

DESCRIPTION

Le module YAML.pm implémente un Chargeur et un Exportateur YAML basé sur la spécification YAML 1.0. http://www.yaml.org/spec/

YAML est un langage de sérialisation de données générique optimisé pour la lisibilité humaine. Il peut être utilisé pour exprimer les structures de données de la plupart des langages de programmation modernes. (Y compris Perl !!!)

Pour des informations sur la syntaxe YAML, veuillez vous référer à la spécification YAML.

POURQUOI YAML EST COOL

YAML est lisible pour les gens.
Il rend le sens clair des structures de données complexes. Vous devriez trouver que YAML est un outil d'exportation de données exceptionnel. La structure est affichée par indentation, YAML supporte les données récursives et les clés de hash sont triées par défaut. De plus, YAML supporte plusieurs styles de formatage scalaire pour différents types de données.
YAML est éditable.
YAML a été conçu dès le départ pour être une excellente syntaxe pour les fichiers de configuration. Presque tous les programmes ont besoin de fichiers de configuration, alors pourquoi inventer une nouvelle syntaxe pour chacun d'eux ? Et pourquoi soumettre les utilisateurs aux complexités de XML ou du code Perl natif ?
YAML est multilingue.
Oui, YAML supporte Unicode. Mais je fais en réalité référence aux langages de programmation. YAML a été conçu pour répondre aux besoins de sérialisation de Perl, Python, Ruby, Tcl, PHP, Javascript et Java. Il a également été conçu pour être interopérable entre ces langages. Cela signifie que les sérialisations YAML produites par Perl peuvent être traitées par Python.
YAML est sûr contre le marquage (taint safe).
L'utilisation de modules comme Data::Dumper pour la sérialisation est correcte tant que vous pouvez être sûr que personne ne peut falsifier vos fichiers ou transmissions de données. C'est parce que vous devez utiliser le built-in eval() de Perl pour désérialiser les données. Quelqu'un pourrait ajouter un extrait de Perl pour effacer vos fichiers.

L'analyseur YAML n'a pas besoin d'évaluer quoi que ce soit.

YAML est complet.
YAML peut sérialiser avec précision toutes les structures de données Perl courantes et les désérialiser à nouveau sans perte de relations de données. Bien qu'il ne soit pas parfait à 100% (aucun sérialiseur ne l'est ou ne peut l'être), il est aussi performant que les modules populaires actuels : Data::Dumper, Storable, XML::Dumper et Data::Denter.

YAML.pm a également la capacité de gérer les références de code (sous-routines) et les typeglobs. (Encore expérimental) Ces fonctionnalités ne se trouvent pas dans les autres modules de sérialisation de Perl.

YAML est extensible.
Le langage YAML a été conçu pour être suffisamment flexible pour résoudre ses propres problèmes. Le balisage lui-même a 3 constructions de base qui ressemblent au hash, au tableau et au scalaire de Perl. Par défaut, ceux-ci correspondent à leurs équivalents Perl. Mais chaque nœud YAML supporte également un mécanisme de marquage (système de types) qui peut amener ce nœud à être interprété d'une manière complètement différente. C'est ainsi que YAML peut supporter la sérialisation d'objets et des structures inhabituelles comme les typeglobs de Perl.

IMPLÉMENTATIONS YAML EN PERL

Ce module, YAML.pm, n'est en réalité que le module d'interface pour les modules YAML écrits en Perl. L'interface de base pour YAML se compose de deux fonctions : "Dump" et "Load". Le vrai travail est effectué par les modules YAML::Dumper et YAML::Loader.

Différentes distributions de modules YAML peuvent être créées en héritant de YAML.pm et de YAML::Loader et YAML::Dumper. Par exemple, YAML-Simple se compose de YAML::Simple, YAML::Dumper::Simple et YAML::Loader::Simple.

Pourquoi y aurait-il plus d'une implémentation de YAML ? Eh bien, malgré l'offre de YAML d'être un format de données simple, YAML est en fait très profond et complexe. Implémenter la totalité de la spécification YAML est une tâche décourageante.

Pour cette raison, je travaille actuellement sur 3 implémentations YAML différentes.

YAML
La distribution YAML principale continuera d'évoluer pour supporter l'intégralité de la spécification YAML en pur Perl. Ce ne sera peut-être pas le module le plus rapide ou le plus stable. Actuellement, YAML.pm a beaucoup de bugs connus. C'est principalement un excellent outil pour exporter des structures de données Perl dans un format lisible.
YAML::Tiny
L'objectif de YAML::Tiny est de réduire YAML aux 90% que la plupart des gens utilisent et de proposer cela sous une forme pure Perl, petite, rapide et stable. YAML::Tiny mourra simplement lorsqu'on lui demandera de faire quelque chose qu'il ne peut pas faire.
YAML::Syck
"libsyck" est la bibliothèque de traitement YAML basée sur C utilisée par le langage de programmation Ruby (et aussi Python, PHP et Pugs). YAML::Syck est la liaison Perl vers "libsyck". Elle devrait être très rapide, mais peut avoir ses propres problèmes. Elle nécessitera également une compilation C.

NOTE : Audrey Tang a effectivement terminé ce module et il fonctionne très bien et est
10 fois plus rapide que YAML.pm.

À l'avenir, il y aura probablement encore plus de modules YAML. Rappelez-vous, d'autres personnes que Ingy sont autorisées à écrire des modules YAML !

UTILISATION FONCTIONNELLE

YAML est entièrement orienté objet en interne. Néanmoins, il exporte quelques fonctions utiles de haut niveau pour le rendre extrêmement simple à utiliser. Ces fonctions font simplement le travail orienté objet pour vous. Si vous souhaitez un accès direct à l'API OO, consultez la documentation de YAML::Dumper et YAML::Loader.

Fonctions Exportées

Les fonctions suivantes sont exportées par YAML.pm par défaut. La raison pour laquelle elles sont exportées est que YAML fonctionne de manière très similaire à Data::Dumper. Si vous ne souhaitez pas que des fonctions soient importées, utilisez simplement YAML avec une liste d'importation vide :

use YAML ();
Dump(liste-de-structures-de-données-Perl)
La fonction Dump prend une liste de structures de données Perl et les sérialise dans un flux YAML sous forme de chaîne de caractères. La chaîne de caractères contient des documents YAML séparés par des sauts de ligne.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Dump(list-of-Perl-data-structures)
Convertit les données Perl en YAML. Cette fonction fonctionne de manière très similaire à Data::Dumper::Dumper(). Elle prend une liste de structures de données Perl et les convertit en une forme sérialisée. Elle renvoie une chaîne contenant le flux YAML. Les structures peuvent être des références ou des scalaires simples.
Load(chaîne-contenant-un-flux-YAML)
Convertit le YAML en données Perl. C'est l'inverse de Dump. Tout comme la fonction thaw() de Storable ou la fonction eval() par rapport à Data::Dumper. Elle analyse une chaîne contenant un flux YAML valide pour en extraire une liste de structures de données Perl.

Fonctions Exportables

Ces fonctions ne sont pas exportées par défaut, mais vous pouvez les demander dans une liste d'importation comme suit :

use YAML qw'freeze thaw Bless';
freeze() et thaw()
Alias de Dump() et Load() pour les fans de Storable. Cela permettra également à YAML.pm d'être branché directement dans des modules comme POE.pm, qui utilisent l'API freeze/thaw pour la sérialisation interne.
DumpFile(chemin-de-fichier, liste)
Écrit le flux YAML dans un fichier au lieu de simplement renvoyer une chaîne.
LoadFile(chemin-de-fichier)
Lit le flux YAML à partir d'un fichier au lieu d'une chaîne.
Bless(nœud-perl, [nœud-yaml | nom-de-classe])
Associe un nœud Perl normal à un nœud YAML. Un nœud YAML est un objet lié à la classe YAML::Node. Le deuxième argument est soit un nœud YAML que vous avez déjà créé, soit un nom de classe (package) qui prend en charge une fonction yaml_dump(). Une fonction yaml_dump() doit prendre un nœud Perl et renvoyer un nœud YAML. Si aucun deuxième argument n'est fourni, Bless créera un nœud YAML. Ce nœud n'est pas renvoyé, mais peut être récupéré avec la fonction Blessed().

Voici un exemple d'utilisation de Bless. Disons que vous avez une table de hachage contenant trois clés, mais que vous n'en voulez que deux. De plus, les clés doivent être affichées dans un ordre spécifique. Voici comment faire :

use YAML qw(Dump Bless);
$hash = {apple => 'good', banana => 'bad', cauliflower => 'ugly'};
print Dump $hash;
Bless($hash)->keys(['banana', 'apple']);
print Dump $hash;

produit :

---
apple: good
banana: bad
cauliflower: ugly
---
banana: bad
apple: good

Bless renvoie la partie liée d'un nœud YAML, de sorte que vous puissiez appeler les méthodes YAML::Node. C'est la même chose que ce que renvoie YAML::Node::ynode(). Une autre façon de faire l'exemple ci-dessus est donc :

use YAML qw(Dump Bless);
use YAML::Node;
$hash = {apple => 'good', banana => 'bad', cauliflower => 'ugly'};
print Dump $hash;
Bless($hash);
$ynode = ynode(Blessed($hash));
$ynode->keys(['banana', 'apple']);
print Dump $hash;

Notez que bénir une structure de données Perl ne la modifie en rien. Les informations supplémentaires sont stockées séparément et recherchées par l'adresse mémoire du nœud béni.

Blessed(nœud-perl)
Renvoie le nœud YAML auquel un nœud Perl particulier est associé (voir ci-dessus). Renvoie undef si le nœud n'est pas (YAML) béni.

OPTIONS GLOBALES

Les options YAML sont définies à l'aide d'un groupe de variables globales dans l'espace de noms YAML. Ceci est similaire au fonctionnement de Data::Dumper.

Par exemple, pour modifier la largeur de l'indentation, faites ceci :

local $YAML::Indent = 3;

Les options actuelles sont :

DumperClass
Vous pouvez remplacer quel module/classe YAML utilise pour la conversion des données. L'original DumperClass est `YAML::Dumper`.
LoadBlessed (depuis 1.25)
Par défaut : undef (faux)

La valeur par défaut a été modifiée dans la version 1.30.

Lorsqu'elle est définie sur vrai, les nœuds YAML avec des balises spéciales seront automatiquement bénis en objets :

- !perl/hash:Foo::Bar
    foo: 42

Lors du chargement de YAML non fiable, vous devriez désactiver cette option en la définissant sur 0. Cela désactivera également la définition des typeglobs lors de leur chargement.

Vous pouvez créer n'importe quel type d'objet avec YAML. La création elle-même n'est pas le point critique. Si la classe a une méthode "DESTROY", elle sera appelée une fois que l'objet sera supprimé. Un exemple avec File::Temp supprimant des fichiers se trouve sur https://bugs.debian.org/cgi-bin/bugreport.cgi?bug=862373

LoaderClass
Vous pouvez remplacer quel module/classe YAML utilise pour le chargement des données. L'original LoaderClass est `YAML::Loader`.
Indent
C'est le nombre d'espaces à utiliser pour chaque niveau d'indentation lors d'un Dump(). La valeur par défaut est 2.

Au fait, YAML peut utiliser n'importe quel nombre de caractères pour l'indentation à n'importe quel niveau. Donc, si vous éditez du YAML à la main, n'hésitez pas à le faire de la manière qui vous plaît, mais soyez cohérent pour un niveau donné.

SortKeys
Par défaut : 1. (vrai)

Indique à YAML.pm s'il faut trier ou non les clés de table de hachage lors du stockage d'un document.

Les objets YAML::Node peuvent avoir leur propre ordre de tri, ce qui est généralement ce que vous voulez. Pour outrepasser l'ordre de YAML::Node et trier les clés quand même, définissez SortKeys sur 2.

Stringify
Par défaut : 0. (faux)

Les objets avec surcharge de chaîne doivent honorer la surcharge et afficher la chaîne de caractères eux-mêmes, plutôt que les entrailles de l'objet réel.

Numify
Par défaut : 0. (faux)

Les valeurs qui ressemblent à des nombres (entiers, flottants) seront numérisées lors du chargement.

UseHeader
Par défaut : 1. (vrai)

Indique à YAML.pm s'il faut utiliser une chaîne de séparation pour une opération Dump. Ceci ne s'applique qu'au premier document d'un flux. Les documents suivants doivent avoir un en-tête YAML par définition.

UseVersion
Par défaut : 0. (faux)

Indique à YAML.pm s'il faut inclure la version YAML sur le séparateur/en-tête.

--- %YAML:1.0
AnchorPrefix
Par défaut : ''.

Les noms d'ancres sont normalement numériques. YAML.pm commence simplement par '1' et augmente de un pour chaque nouvelle ancre. Cette option vous permet de spécifier une chaîne à préfixer à chaque numéro d'ancre.

UseCode
Définir l'option UseCode est un raccourci pour définir simultanément les options DumpCode et LoadCode. Définir UseCode sur '1' indique à YAML.pm de convertir les références de code Perl en Perl (en utilisant B::Deparse) et de les recharger en mémoire en utilisant eval(). La raison pour laquelle cela doit être une option est que l'utilisation de eval() pour analyser du code non fiable est, eh bien, peu fiable.
DumpCode
Détermine si et comment YAML.pm doit sérialiser les références de code Perl. Par défaut, YAML.pm convertit les références de code en espaces réservés factices (très similaire à Data::Dumper). Si DumpCode est défini sur '1' ou 'deparse', les références de code seront converties en code Perl réel.
LoadCode
LoadCode est l'inverse de DumpCode. Il indique à YAML si et comment désérialiser les références de code. Lorsqu'il est défini sur '1' ou 'deparse', il utilisera eval(). Comme cela peut être risqué, n'utilisez cette option que si vous savez d'où provient votre YAML.

LoadCode doit également être activé pour utiliser la fonctionnalité d'évaluation des typeglobs (car avec la fonctionnalité de typeglob, vous pourriez définir la variable $YAML::LoadCode à partir d'un fichier YAML).

Preserve
Lorsqu'elle est définie sur vrai, cette option indique au Loader de charger les tables de hachage dans des objets YAML::Node. Ce sont des tables de hachage liées. Cela a pour effet de mémoriser l'ordre des clés, ainsi il sera préservé lorsque la table de hachage sera à nouveau convertie.
UseBlock
YAML.pm utilise des heuristiques pour deviner quel style scalaire est le meilleur pour un nœud donné. Parfois, vous voudrez que tous les scalaires multilignes utilisent le style 'bloc'. Si c'est le cas, définissez cette option sur 1.

NOTE : Le style bloc de YAML est similaire au here-document de Perl.

UseFold (Plus supporté depuis v0.60)
Si vous voulez forcer YAML à utiliser le style 'plié' pour tous les scalaires multilignes, définissez $UseFold sur 1.

NOTE : Le style plié de YAML est similaire à la façon dont HTML plie le texte, sauf qu'il est plus intelligent.

UseAliases
YAML dispose d'un mécanisme d'alias tel que toute structure donnée en mémoire est sérialisée une seule fois. Toutes les autres références à cette structure sont sérialisées uniquement comme des marqueurs d'alias. C'est ainsi que YAML peut sérialiser des structures dupliquées et récursives.

Parfois, lorsque vous savez que vos données ne sont pas récursives, vous pouvez vouloir sérialiser de telle sorte que chaque nœud soit exprimé dans son intégralité (c'est-à-dire comme une copie de l'original). Définir $YAML::UseAliases sur 0 vous permettra de le faire. Cela peut également entraîner un traitement plus rapide car la surcharge de recherche est contournée.

CETTE OPTION EST DANGEREUSE. Si vos données sont récursives, cette option provoquera une boucle infinie de Dump(), consommant la mémoire de votre ordinateur. Vous avez été prévenu.

CompressSeries
Par défaut : 1.

Compresse la mise en forme des tableaux de tables de hachage :

-
  foo: bar
-
  bar: foo

devient :

- foo: bar
- bar: foo

Comme cette sortie est généralement plus désirable, cette option est activée par défaut.

NOM

YAML - Serialisation de données en format YAML.

VERSION

Cette documentation fait référence à la version 0.75 de YAML.pm.

SYNOPSIS

    use YAML;
    my $data = Load( '
        a mapping:
            foo: bar
            two: times two is 4
        a sequence:
            - one bourbon
            - one scotch
            - one beer
    ' );
    print Dump(@$data);

DESCRIPTION

YAML.pm est une bibliothèque Perl pour lire et écrire des données au format YAML.

YAML signifie "YAML Ain't Markup Language" (un acronyme récursif). C'est un langage de sérialisation de données qui est conçu pour être facile à lire pour les humains.

YAML est un sur-ensemble de JSON. Tout document JSON valide est également un document YAML valide.

YAML est couramment utilisé pour les fichiers de configuration, les échanges de données entre applications et dans les systèmes de gestion de contenu.

YAML.pm fournit les fonctions suivantes :

Load()
Charge une chaîne YAML et la convertit en une structure de données Perl.
Dump()
Convertit une ou plusieurs structures de données Perl en une chaîne YAML.
taintmode()
Active le mode de vérification des données contaminées pour les données chargées.
object_load()
Charge une structure YAML sous forme d'objet Perl.
object_dump()
Convertit une structure de données Perl en une chaîne YAML sous forme d'objet.
Tag()
Définit une balise personnalisée pour un type de données Perl.
Handler()
Définit un gestionnaire personnalisé pour sérialiser/désérialiser un type de données Perl.
LoadFile()
Charge une chaîne YAML à partir d'un fichier.
DumpFile()
Écrit une chaîne YAML dans un fichier.

YAML.pm prend également en charge les options de configuration pour contrôler la façon dont les données sont sérialisées et désérialisées. Celles-ci peuvent être définies à l'aide de la fonction Config().

indent
La taille de l'indentation à utiliser pour la sortie YAML (défaut: 2).
always_quote
Indique si toutes les chaînes doivent être mises entre guillemets (défaut: 0 (faux)).
QuoteNumericStrings
Par défaut, 0 (faux).

Ajoute des mécanismes de détection pour encoder les chaînes qui ressemblent à des nombres avec des guillemets obligatoires.

Cela garantit que les zéros en tête/fin et d'autres formats sont préservés.

TERMINOLOGIE YAML

YAML est un langage de sérialisation de données complet, et possède donc sa propre terminologie.

Il est important de se rappeler que bien que YAML soit fortement influencé par Perl et Python, c'est un langage à part entière, pas seulement une représentation de structures Perl.

YAML a trois constructions qui ressemblent de manière frappante aux hash, array et scalar de Perl. Elles sont appelées respectivement mapping, sequence et string. Par défaut, elles font ce que vous attendez. Mais chaque instance peut avoir une balise (type) explicite ou implicite qui la fait se comporter différemment. De cette manière, YAML peut être étendu pour représenter les Glob de Perl ou les tuples de Python, ou les Bigint de Ruby.

stream
Un flux YAML est la séquence complète de caractères Unicode qu'un analyseur
YAML lirait ou qu'un émetteur YAML écrirait. Un flux peut contenir un ou
plusieurs documents YAML séparés par des en-têtes YAML.
---
a: mapping
foo: bar
---
- a
- sequence
document
Un document YAML est une représentation indépendante de structure de données au sein d'un flux. C'est un nœud de niveau supérieur. Chaque document dans un flux YAML doit commencer par une ligne d'en-tête YAML. En fait, l'en-tête est optionnel pour le premier document. 
---
This: top level mapping
is:
    - a
    - YAML
    - document
header
Un en-tête YAML est une ligne qui commence un document YAML. Il se compose de trois tirets, éventuellement suivis d'autres informations. Un autre but de la ligne d'en-tête est qu'elle sert de lieu pour placer la balise de niveau supérieur et les informations d'ancrage. 
--- !recursive-sequence &001
- * 001
- * 001
node
Un nœud YAML est la représentation d'une structure de données particulière. Les nœuds peuvent contenir d'autres nœuds. (En termes Perl, les nœuds sont comme des scalaires. Chaînes, références d'array et références de hash. Mais cela fait référence au format sérialisé, pas à la structure en mémoire.)
tag
Ceci est similaire à un type. Il indique comment une sérialisation de nœud YAML particulière doit être transférée dans ou hors de la mémoire. Par exemple, un objet Foo::Bar utiliserait la balise 'perl/Foo::Bar' : 
- !perl/Foo::Bar
    foo: 42
    bar: stool
collection
Une collection est le terme générique pour un regroupement de données YAML. YAML a deux types de collections : les mappings et les sequences. (Similaire aux hashes et aux arrays)
mapping
Un mapping est une collection YAML définie par des paires clé/valeur non ordonnées avec des clés uniques. Par défaut, les mappings YAML sont chargés dans des hashes Perl. 
a mapping:
    foo: bar
    two: times two is 4
sequence
Une sequence est une collection YAML définie par une liste ordonnée d'éléments. Par défaut, les sequences YAML sont chargées dans des arrays Perl. 
a sequence:
    - one bourbon
    - one scotch
    - one beer
scalar
Un scalar est un nœud YAML qui est une valeur unique. Par défaut, les scalars YAML sont chargés dans des scalaires Perl. 
a scalar key: a scalar value

YAML a de nombreux styles pour représenter les scalars. Ceci est important car des données variées auront des exigences de formatage variées pour conserver une lisibilité humaine optimale.

plain scalar
Un plain scalar n'est pas mis entre guillemets. Tous les plain scalars sont des candidats automatiques pour le "taggage implicite". Cela signifie que leur balise peut être déterminée automatiquement par examen. Les usages typiques sont les chaînes alpha simples, les entiers, les nombres réels, les dates, les heures et les devises. 
- a plain string
- -42
- 3.1415
- 12:34
- 123 this is an error
single quoted scalar
Ceci est similaire à l'utilisation des guillemets simples par Perl. Cela signifie aucune échappement sauf pour les guillemets simples qui sont échappés en utilisant deux guillemets simples adjacents. 
- 'When I say ''\n'' I mean "backslash en"'
double quoted scalar
Ceci est similaire à l'utilisation des guillemets doubles par Perl. L'échappement des caractères peut être utilisé. 
- "This scalar\nhas two lines, and a bell -->\a"
folded scalar
Ceci est un scalar multiligne qui commence sur la ligne suivante. Il est indiqué par un seul crochet droit. Il n'est pas échappé comme le scalar entre guillemets simples. Le repli de ligne est également effectué. 
- >
 This is a multiline scalar which begins on
 the next line. It is indicated by a single
 carat. It is unescaped like the single
 quoted scalar. Line folding is also
 performed.
block scalar
Cette dernière forme multiligne s'apparente aux here-documents de Perl, sauf que (comme dans toutes les données YAML) la portée est indiquée par l'indentation. Par conséquent, aucun marqueur de fin n'est requis. Les données sont littérales. Pas de repli de ligne.

parser
Un processeur YAML a quatre étapes : parse, load, dump, emit.

Un analyseur analyse un flux YAML. La fonction Load() de YAML.pm contient un analyseur.

loader
L'autre moitié de la fonction Load() est un chargeur. Celui-ci prend les informations de l'analyseur et les charge dans une structure de données Perl.
dumper
La fonction Dump() se compose d'un dumper et d'un émetteur. Le dumper parcourt chaque structure de données Perl et transmet les informations à l'émetteur.
emitter
L'émetteur prend les informations du dumper et les transforme en un flux YAML.

NOTE : Dans YAML.pm, l'analyseurchargeur et le dumperémetteur sont actuellement
très étroitement liés. À l'avenir, ils pourraient être divisés en
étapes distinctes.

Pour plus d'informations, veuillez consulter la spécification YAML immensément utile disponible à l'adresse http://www.yaml.org/spec/.

YSH - LE SHELL YAML

La distribution YAML::Shell fournit un script appelé 'ysh', le shell YAML. ysh offre un moyen simple et interactif de jouer avec YAML. Si vous tapez du code Perl, il affiche le résultat en YAML. Si vous tapez du YAML, il le transforme en code Perl.

Pour exécuter ysh, (en supposant que vous l'avez installé avec YAML.pm) tapez simplement :

ysh [options]

Veuillez lire la documentation "ysh" pour tous les détails. Il existe de nombreuses options.

BOGUES & DÉFAUTS

Si vous trouvez un bogue dans YAML, veuillez essayer de le recréer dans le Shell YAML avec la journalisation activée ('ysh -L'). Lorsque vous avez réussi à reproduire le bogue, veuillez envoyer le fichier LOG à l'auteur (ingy@cpan.org).
