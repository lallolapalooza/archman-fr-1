NOM

YAML::Syck - Chargeur et déchargeur YAML rapide et léger

SYNOPIS

use YAML::Syck;
# Définir ceci pour l'interopérabilité avec d'autres liaisons YAML/Syck :
# par exemple, Load('Yes') devient 1 et Load('No') devient ''.
$YAML::Syck::ImplicitTyping = 1;
$data = Load($yaml);
$yaml = Dump($data);
# $file peut être un objet IO ou un nom de fichier
$data = LoadFile($file);
DumpFile($file, $data);
# Une chaîne contenant plusieurs flux YAML
$yaml = Dump(@data);
@data = Load($yaml);
# Déchargement dans un tampon de sortie préexistant
my $yaml;
DumpInto(\$yaml, @data);

DESCRIPTION

Ce module fournit une interface Perl à la bibliothèque de sérialisation de données libsyck. Il exporte les fonctions "Dump" et "Load" pour convertir les structures de données Perl en chaînes YAML, et vice versa.

NOTE : Si vous travaillez avec des liaisons YAML/Syck d'autres langages (comme Ruby), veuillez définir $YAML::Syck::ImplicitTyping à 1 avant d'appeler les fonctions "Load"/"Dump". Le réglage par défaut vise à préserver la compatibilité descendante avec "YAML.pm".

Gestion des erreurs

Certains appels sont conçus pour mourir plutôt que de retourner YAML. Vous devriez envelopper vos appels dans eval pour vous assurer de ne pas obtenir de résultats inattendus.

INDICATEURS

$YAML::Syck::Headless

Par défaut : faux. Définir ceci sur une valeur vraie fera omettre "Dump" le marqueur préfixe "---\n".

$YAML::Syck::SortKeys

Par défaut : faux. Définir ceci sur une valeur vraie fera trier les clés de hachage par "Dump".

$YAML::Syck::SingleQuote

Par défaut : faux. Définir ceci sur une valeur vraie fera émettre des guillemets simples au lieu de chaînes nues par "Dump".

$YAML::Syck::ImplicitTyping

Par défaut : faux. Définir ceci sur une valeur vraie fera reconnaître par "Load" divers types implicites en YAML, tels que "true", "false" non cités, ainsi que les entiers et les nombres à virgule flottante. Sinon, seul "~" est reconnu comme "undef".

$YAML::Syck::ImplicitUnicode

Par défaut : faux. Pour Perl 5.8.0 ou plus récent, définir ceci sur une valeur vraie fera définir le drapeau Unicode par "Load" pour chaque chaîne contenant des séquences UTF8 valides, et fera retourner une chaîne unicode par "Dump".

Indépendamment de cet indicateur, les chaînes Unicode sont déchargées telles quelles sans échappement ; les chaînes d'octets avec des octets de poids fort seront déchargées avec échappement par antislash.

Cependant, comme YAML ne fait pas de distinction entre ces deux types de chaînes, cet indicateur affectera le chargement des deux variantes de chaînes.

Si vous souhaitez utiliser LoadFile ou DumpFile avec unicode, vous êtes tenu d'ouvrir votre propre fichier afin de vous assurer qu'il est encodé en UTF8 :

open(my $fh, ">:encoding(UTF-8)", "out.yml");
DumpFile($fh, $hashref);

$YAML::Syck::ImplicitBinary

Par défaut : faux. Pour Perl 5.8.0 ou plus récent, définir ceci sur une valeur vraie fera générer par "Dump" des données encodées en Base64 "!!binary" pour tous les scalaires non Unicode contenant des octets de poids fort.

$YAML::Syck::UseCode / $YAML::Syck::LoadCode / $YAML::Syck::DumpCode

Ces indicateurs contrôlent si oui ou non on tente d'évaluer/déparsir du code source perl ; chacun d'eux est faux par défaut.

Définir $YAML::Syck::UseCode sur une valeur vraie équivaut à définir $YAML::Syck::LoadCode et $YAML::Syck::DumpCode sur vrai.

$YAML::Syck::LoadBlessed

Par défaut : faux. Définir sur vrai permettra à YAML::Syck de bénir les objets lors de l'importation d'objets. Ce défaut a changé en 1.32.

Vous pouvez créer n'importe quel type d'objet avec YAML. La création elle-même n'est pas l'élément critique. Si la classe a une méthode DESTROY, elle sera appelée une fois que l'objet sera supprimé. Un exemple avec File::Temp supprimant des fichiers se trouve à https://bugs.debian.org/cgi-bin/bugreport.cgi?bug=862373

BOGUES

Le déchargement des valeurs Glob/IO ne fonctionne pas encore.

Le déchargement des variables liées (Tied) n'est pas pris en charge.

Le déchargement dans des variables liées (ou autres variables magiques) avec "DumpInto" pourrait ne pas fonctionner correctement dans tous les cas.

AVERTISSEMENTS

Ce module implémente la spécification YAML 1.0. Pour traiter des données en YAML 1.1, veuillez utiliser le module "YAML::XS" à la place.

L'implémentation actuelle regroupe le code source de libsyck ; si votre système dispose d'une libsyck partagée au niveau du système, elle ne sera pas utilisée.

Les noms de balises tels que "!!perl/hash:Foo" sont bénis dans le paquet "Foo", mais les balises "!hs/foo" et "!!hs/Foo" sont bénies dans "hs::Foo". Notez que cela reste vrai même si la balise contient des caractères non alphanumériques ; par exemple, "!haskell.org/Foo" est bénie dans "haskell.org::Foo". Veuillez utiliser Class::Rebless pour la caster vers d'autres paquets définis par l'utilisateur. Vous pouvez également définir l'indicateur LoadBlessed à faux pour désactiver toute bénédiction.

Ce module a beaucoup de problèmes connus https://rt.cpan.org/Public/Dist/Display.html?Name=YAML-Syck et n'a été que semi-activement maintenu depuis 2007. Si vous rencontrez un problème avec, il ne sera probablement pas corrigé à moins que vous ne fournissiez un correctif http://github.com/toddr/YAML-Syck dans Git, prêt pour la publication.

Il y a toujours de bonnes raisons d'utiliser ce module, comme une meilleure interopérabilité avec d'autres wrappers syck (comme celui de Ruby), ou certains cas limites de la syntaxe YAML qu'il gère mieux. Il fonctionnera probablement parfaitement pour vous, mais si ce n'est pas le cas, vous pourriez vouloir examiner YAML::XS, ou peut-être un autre format de sérialisation comme JSON.
