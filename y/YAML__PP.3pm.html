NOM

YAML::PP - Processeur YAML 1.2

SYNOPIS

AVERTISSEMENT : La plupart de l'API interne n'est pas encore stable.

Voici quelques exemples des méthodes de base de chargement et de déchargement :

use YAML::PP;
my $ypp = YAML::PP->new;
my $yaml = <<'EOM';
--- # Document un est un mappage
name: Tina
age: 29
favourite language: Perl
--- # Document deux est une séquence
- plain string
- 'en guillemets simples'
- "en guillemets doubles, il y a des échappements ! comme \t et \n"
- | # un scalaire de bloc littéral
  ligne1
  ligne2
- > # un scalaire de bloc replié
  ceci est tout une
  seule ligne car les
  sauts de ligne seront repliés
EOM
my @documents = $ypp->load_string($yaml);
my @documents = $ypp->load_file($filename);
my $yaml = $ypp->dump_string($data1, $data2);
$ypp->dump_file($filename, $data1, $data2);
# Activer les types de données et objets Perl
my $ypp = YAML::PP->new(schema => [qw/ + Perl /]);
my $yaml = $yp->dump_string($data_with_perl_objects);
# Interface héritée
use YAML::PP qw/ Load Dump LoadFile DumpFile /;
my @documents = Load($yaml);
my @documents = LoadFile($filename);
my @documents = LoadFile($filehandle);
my $yaml = = Dump(@documents);
DumpFile($filename, @documents);
DumpFile($filenhandle @documents);

Quelques scripts utilitaires, principalement utiles pour le débogage :

# Charger YAML dans une structure de données et décharger avec Data::Dumper
yamlpp-load < file.yaml
# Charger et Décharger
yamlpp-load-dump < file.yaml
# Afficher les événements du parseur au format yaml-test-suite
yamlpp-events < file.yaml
# Analyser et émettre des événements directement sans charger
yamlpp-parse-emit < file.yaml
# Créer du YAML coloré en ANSI. Peut aussi être utile pour du YAML invalide,
# vous montrant l'emplacement exact de l'erreur
yamlpp-highlight < file.yaml

DESCRIPTION

YAML::PP est un processeur YAML modulaire.

Il vise à supporter "YAML 1.2" et "YAML 1.1". Voir https://yaml.org/. Certains éléments de syntaxe (rares) ne sont pas encore pris en charge et documentés ci-dessous.

YAML est un langage de sérialisation. L'entrée YAML est appelée "Flux YAML". Un flux se compose d'un ou plusieurs "Documents", séparés par une ligne avec un marqueur de début de document "---". Un document se termine optionnellement par le marqueur de fin de document "...".

Cela permet de traiter des flux continus en plus d'un fichier ou d'une chaîne d'entrée fixe.

L'interface YAML::PP chargera actuellement tous les documents, et ne retournera que le premier si appelée avec un contexte scalaire.

Le backend YAML est implémenté de manière modulaire, ce qui permet d'ajouter une gestion personnalisée des balises YAML, des objets Perl et des types de données. L'API interne n'est pas encore stable. Vos suggestions sont les bienvenues.

Vous pouvez consulter tous les résultats de parsage et de chargement actuels à partir de la yaml-test-suite ici : https://perlpunk.github.io/YAML-PP-p5/test-suite.html

MÉTHODES

new

my $ypp = YAML::PP->new;

# Utiliser le schéma Failsafe YAML 1.2
my $ypp = YAML::PP->new( schema => ['Failsafe'] );
# Utiliser le schéma JSON YAML 1.2
my $ypp = YAML::PP->new( schema => ['JSON'] );
# Utiliser le schéma Core YAML 1.2
my $ypp = YAML::PP->new( schema => ['Core'] );

# Mourir lors de la détection de références cycliques
my $ypp = YAML::PP->new( cyclic_refs => 'fatal' );

my $ypp = YAML::PP->new(
    boolean => 'perl',
    schema => ['Core'],
    cyclic_refs => 'fatal',
    indent => 4,
    header => 1,
    footer => 0,
    version_directive => 0,
);

Options :

boolean
Valeurs : "perl" (actuellement par défaut), "JSON::PP", "boolean", "perl_experimental"

Cette option concerne le chargement et le déchargement.

Dans le cas de perl 5.36 et supérieur, les booléens intégrés devraient fonctionner directement (depuis YAML::PP >= 0.38.0).

print YAML::PP->new->dump_string([ builtin::true, !1 ]);
# ---
# - true
# - false

Pour les versions antérieures de perl, vous pouvez utiliser des booléens "pseudo" comme documenté dans les exemples suivants.

# charger/décharger les booléens via boolean.pm
my $ypp = YAML::PP->new( boolean => 'boolean' );
# charger/décharger les booléens via JSON::PP::true/false
my $ypp = YAML::PP->new( boolean => 'JSON::PP' );

Vous pouvez également spécifier plusieurs classes, séparées par des virgules. Ceci est important pour le déchargement.

boolean => 'JSON::PP,boolean'
Les booléens seront chargés comme des booléens JSON::PP, mais lors du déchargement,
les objets 'boolean' seront également reconnus
boolean => 'JSON::PP,*'
Les booléens seront chargés comme des booléens JSON::PP, mais lors du déchargement, toutes
les classes booléennes actuellement prises en charge seront reconnues
boolean => '*'
Les booléens seront chargés comme des booléens Perl, mais lors du déchargement, toutes
les classes booléennes actuellement prises en charge seront reconnues
boolean => ''
Les booléens seront chargés comme des booléens Perl, mais lors du déchargement, rien
ne sera reconnu comme booléen.
Cette option est pour la compatibilité ascendante pour les versions de perl < 5.36,
si vous comptez sur [!!1, !1] étant déchargés comme [1, ''].

L'option "perl_experimental" a été introduite lorsque le support expérimental des booléens a été ajouté à perl 5.36. Puisqu'il ne sera plus expérimental dans perl 5.40 \o/, l'option est obsolète et identique à "perl".

schema
Défaut : "['Core']"

Cette option concerne le chargement et le déchargement.

Référence d'un tableau. Ici, vous pouvez définir quel schéma utiliser. Les schémas standards supportés sont : "Failsafe", "JSON", "Core", "YAML1_1".

Pour avoir un aperçu du comportement des différents schémas, voir https://perlpunk.github.io/YAML-PP-p5/schemas.html

De plus, vous pouvez ajouter d'autres schémas, par exemple "Merge".

cyclic_refs
Défaut : "fatal" (depuis 0.037)

Avant, la valeur par défaut était "allow", mais cela pouvait entraîner des fuites de mémoire lors du chargement de données non fiables, elle a donc été changée en "fatal" par défaut.

Cette option concerne uniquement le chargement.

Définit ce qu'il faut faire lorsqu'une référence cyclique est détectée lors du chargement.

# fatal  - mourir (erreur)
# warn   - Avertir simplement et remplacer par undef
# ignore - Remplacer par undef
# allow  - Valeur par défaut
duplicate_keys
Défaut : 0

Depuis la version 0.027

Cette option concerne le chargement.

La spécification YAML stipule que les clés de mappage dupliquées doivent être interdites.

Lorsqu'elle est définie sur vrai, les clés dupliquées dans les mappages sont autorisées (et écraseront la clé précédente).

Lorsqu'elle est définie sur faux, les clés dupliquées entraîneront une erreur lors du chargement.

Ceci est particulièrement utile lorsque vous avez un mappage long et que vous ne voyez pas la clé dupliquée dans votre éditeur :

---
a: 1
b: 2
# .............
a: 23 # erreur
indent
Défaut : 2

Cette option concerne le déchargement.

Utiliser autant d'espaces pour l'indentation

width
Depuis la version 0.025

Défaut : 80

Cette option concerne le déchargement.

Nombre maximum de colonnes lors du déchargement.

Ceci n'est respecté que lors du déchargement de collections de flux pour le moment.

À l'avenir, cela sera également utilisé pour le retour à la ligne des longues chaînes.

header
Défaut : 1

Cette option concerne le déchargement.

Imprimer l'en-tête du document "---"

footer
Défaut : 0

Cette option concerne le déchargement.

Imprimer le pied de page du document "..."

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

;

require_footer
Par défaut : 0

Exigera un "..." à la fin de chaque document. Cela peut être utile dans un contexte où vous souhaitez vous assurer d'avoir reçu le contenu complet, par exemple sur un réseau.

# Bien
---
a: 1
...
---
a: 2
...
# Mauvais
---
a: 1
---
a: 2
yaml_version
Depuis la version 0.020

Cette option est pour le chargement et le vidage.

Par défaut : 1.2

Notez que dans ce cas, une directive "%YAML 1.1" sera essentiellement ignorée et tout sera chargé avec le schéma "1.2 Core".

Si vous souhaitez prendre en charge à la fois YAML 1.1 et 1.2, vous devez le spécifier, et le schéma ("Core" ou "YAML1_1") sera choisi automatiquement.

my $yp = YAML::PP->new(
    yaml_version => ['1.2', '1.1'],
);

C'est la même chose que

my $yp = YAML::PP->new(
    schema => ['+'],
    yaml_version => ['1.2', '1.1'],
);

car le "+" représente le schéma par défaut par version.

Lors du chargement, et s'il n'y a pas de directive %YAML, 1.2 sera considéré comme par défaut, et le schéma "Core" sera utilisé.

S'il y a une directive "%YAML 1.1", le schéma "YAML1_1" sera utilisé.

Bien sûr, vous pouvez également faire de 1.1 la valeur par défaut :

my $yp = YAML::PP->new(
    yaml_version => ['1.1', '1.2'],
);

Vous pouvez également spécifier uniquement 1.1 :

my $yp = YAML::PP->new(
    yaml_version => ['1.1'],
);

Dans ce cas également, les documents avec "%YAML 1.2" seront chargés avec le schéma "YAML1_1".

version_directive
Depuis la version 0.020

Cette option est pour le vidage.

Par défaut : 0

Imprime la directive de version "%YAML 1.2" (ou "%YAML 1.1") en haut de chaque document YAML. Elle utilisera la première version spécifiée dans l'option "yaml_version".

preserve
Depuis la version 0.021

Par défaut : false

Cette option est pour le chargement et le vidage.

La préservation des styles scalaires est encore expérimentale.

use YAML::PP::Common qw/ :PRESERVE /;
# Préserver l'ordre des clés de hachage
my $yp = YAML::PP->new( preserve => PRESERVE_ORDER );
# Préserver le style de guillemets des scalaires
my $yp = YAML::PP->new( preserve => PRESERVE_SCALAR_STYLE );
# Préserver le style bloc/flux (depuis 0.024)
my $yp = YAML::PP->new( preserve => PRESERVE_FLOW_STYLE );
# Préserver les noms d'alias (depuis 0.027)
my $yp = YAML::PP->new( preserve => PRESERVE_ALIAS );
# Combiner, par exemple préserver l'ordre et le style scalaire
my $yp = YAML::PP->new( preserve => PRESERVE_ORDER | PRESERVE_SCALAR_STYLE );

NE VOUS REPOSEZ PAS sur l'implémentation interne de cette option.

Si vous chargez l'entrée suivante :

---
z: 1
a: 2
---
- plain
- 'single'
- "double"
- |
  literal
- >
  folded
---
block mapping: &alias
  flow sequence: [a, b]
same mapping: *alias
flow mapping: {a: b}

avec ce code :

my $yp = YAML::PP->new(
    preserve => PRESERVE_ORDER | PRESERVE_SCALAR_STYLE
                | PRESERVE_FLOW_STYLE | PRESERVE_ALIAS
);
my ($hash, $styles, $flow) = $yp->load_file($file);
$yp->dump_file($hash, $styles, $flow);

Alors le vidage retournera la même sortie.

Notez que YAML autorise les définitions répétées d'ancres. Elles ne peuvent pas être préservées avec YAML::PP pour le moment. Exemple :

---
- &seq [a]
- *seq
- &seq [b]
- *seq

Comme les données pourraient être mélangées avant d'être vidées à nouveau, la définition de l'ancre pourrait être corrompue. Dans ce cas, les noms d'ancres répétés seront ignorés lors du chargement et vidés avec des ancres numériques comme d'habitude.

Implémentation :

Lors du chargement, les hachages seront liés à une classe interne ("YAML::PP::Preserve::Hash") qui conserve l'ordre des clés.

Les scalaires seront retournés sous forme d'objets d'une classe interne ("YAML::PP::Preserve::Scalar") avec surcharge. Si vous assignez à un tel scalaire, l'objet sera remplacé par un scalaire simple.

# affectation, le style est perdu
$styles->[1] .= ' append';

Vous pouvez également passer 1 comme valeur. Dans ce cas, toutes les options de préservation seront activées, même si de nouvelles options sont ajoutées à l'avenir.

Il existe également des méthodes pour créer des nœuds préservés à partir de zéro. Voir les méthodes preserved_(scalar|mapping|sequence) ci-dessous.

load_string

my $doc = $ypp->load_string("foo: bar");
my @docs = $ypp->load_string("foo: bar\n---\n- a");

L'entrée doit être en caractères Unicode.

Donc, si vous lisez à partir d'un fichier, vous devriez le décoder, par exemple avec Encode::decode().

Notez que dans un contexte scalaire, "load_string" et "load_file" retournent le premier document (comme YAML::Syck), tandis que YAML et YAML::XS retournent le dernier.

load_file

my $doc = $ypp->load_file("file.yaml");
my @docs = $ypp->load_file("file.yaml");

Les chaînes de caractères seront chargées sous forme de caractères Unicode.

dump_string

my $yaml = $ypp->dump_string($doc);
my $yaml = $ypp->dump_string($doc1, $doc2);
my $yaml = $ypp->dump_string(@docs);

Les chaînes d'entrée doivent être en caractères Unicode.

La sortie retournera des caractères Unicode.

Donc, si vous voulez écrire cela dans un fichier (ou le passer à YAML::XS, par exemple), vous l'encodez généralement via Encode::encode().

dump_file

$ypp->dump_file("file.yaml", $doc);
$ypp->dump_file("file.yaml", $doc1, $doc2);
$ypp->dump_file("file.yaml", @docs);

Les données d'entrée doivent être en caractères Unicode.

dump

Cela videra vers un écrivain prédéfini. Par défaut, il utilisera simplement YAML::PP::Writer et produira une chaîne de caractères.

my $writer = MyWriter->new(\my $output);
my $yp = YAML::PP->new(
    writer => $writer,
);
$yp->dump($data);

preserved_scalar

Depuis la version 0.024

Expérimental. Veuillez signaler les bogues ou me faire savoir si cela est utile et fonctionne.

Vous pouvez définir un certain style scalaire lors du vidage des données. Déterminer le meilleur style est une tâche difficile et pratiquement impossible à bien faire dans tous les cas. C'est aussi une question de goût.

use YAML::PP::Common qw/ PRESERVE_SCALAR_STYLE YAML_LITERAL_SCALAR_STYLE /;
my $yp = YAML::PP->new(
    preserve => PRESERVE_SCALAR_STYLE,
);
# une seule nouvelle ligne serait normalement vidée avec des guillemets doubles : "\n"
my $scalar = $yp->preserved_scalar("\n", style => YAML_LITERAL_SCALAR_STYLE );
my $data = { literal => $scalar };
my $dump = $yp->dump_string($data);
# sortie
---
literal: |+
...

preserved_mapping, preserved_sequence

Depuis la version 0.024

Expérimental. Veuillez signaler les bogues ou me faire savoir si cela est utile et fonctionne.

Avec cela, vous pouvez définir quels nœuds sont vidés avec le style de flux plus compact au lieu du style bloc.

Si vous ajoutez "PRESERVE_ORDER" à l'option "preserve", cela conservera également l'ordre des clés dans un hachage.

use YAML::PP::Common qw/
    PRESERVE_ORDER PRESERVE_FLOW_STYLE
    YAML_FLOW_MAPPING_STYLE YAML_FLOW_SEQUENCE_STYLE
/;
my $yp = YAML::PP->new(
    preserve => PRESERVE_FLOW_STYLE | PRESERVE_ORDER
);
my $hash = $yp->preserved_mapping({}, style => YAML_FLOW_MAPPING_STYLE);
# Ajouter les valeurs après initialisation pour préserver l'ordre
%$hash = (z => 1, a => 2, y => 3, b => 4);
my $array = $yp->preserved_sequence([23, 24], style => YAML_FLOW_SEQUENCE_STYLE);
my $data = $yp->preserved_mapping({});
%$data = ( map => $hash, seq => $array );
my $dump = $yp->dump_string($data);
# sortie
---
map: {z: 1, a: 2, y: 3, b: 4}
seq: [23, 24]

FONCTIONS

Les fonctions "Load", "LoadFile", "Dump" et "DumpFile" sont fournies en remplacement direct d'autres processeurs YAML existants. Aucune fonction n'est exportée par défaut.

Notez que dans un contexte scalaire, "Load" et "LoadFile" retournent le premier document (comme YAML::Syck), tandis que YAML et YAML::XS retournent le dernier.

dernier.

Load
use YAML::PP qw/ Load /;
my $doc = Load($yaml);
my @docs = Load($yaml);

Fonctionne comme "load_string".

LoadFile
use YAML::PP qw/ LoadFile /;
my $doc = LoadFile($file);
my @docs = LoadFile($file);
my @docs = LoadFile($filehandle);

Fonctionne comme "load_file".

Dump
use YAML::PP qw/ Dump /;
my $yaml = Dump($doc);
my $yaml = Dump(@docs);

Fonctionne comme "dump_string".

DumpFile
use YAML::PP qw/ DumpFile /;
DumpFile($file, $doc);
DumpFile($file, @docs);
DumpFile($filehandle, @docs);

Fonctionne comme "dump_file".

IMPLÉMENTATION

Le processus de chargement et de déchargement est divisé en étapes suivantes :

Load:
YAML Stream        Tokens        Event List        Data Structure
          --------->    --------->        --------->
            lex           parse           construct
Dump:
Data Structure       Event List        YAML Stream
            --------->        --------->
            represent           emit

Vous pouvez décharger des types perl de base comme les hachages, les tableaux, les scalaires (chaînes, nombres). Pour décharger des objets bénis et des choses comme des appels de fonction, regardez YAML::PP::Perl/YAML::PP::Schema::Perl.

YAML::PP::Lexer
Le Lexer lit le flux YAML en tokens. Cela permet de générer une sortie YAML avec coloration syntaxique.

Notez que l'API pour récupérer les tokens changera.

YAML::PP::Parser
Le Parser récupère les tokens du Lexer. Le contenu YAML principal est alors analysé avec la Grammaire.
YAML::PP::Grammar
YAML::PP::Constructor
Le Constructeur crée une structure de données à partir des événements du Parser.
YAML::PP::Loader
Le Loader combine le constructeur et le parser.
YAML::PP::Dumper
Le Dumper délèguera au Representer
YAML::PP::Representer
Le Representer créera des événements d'émission à partir de la structure de données fournie.
YAML::PP::Emitter
L'Emitter crée un flux YAML.

YAML::PP::Constructor

Le Constructeur prend maintenant en charge les trois schémas YAML 1.2 : Failsafe, JSON et Core. De plus, vous pouvez choisir le schéma pour YAML 1.1 sous le nom de "YAML1_1".

Pour voir quelles chaînes sont résolues comme booléens, nombres, null, etc., regardez https://perlpunk.github.io/YAML-PP-p5/schema-examples.html.

Vous pouvez choisir le Schéma comme ceci :

my $ypp = YAML::PP->new(schema => ['JSON']); # le défaut est 'Core'

Les Tags "!!seq" et "!!map" sont toujours ignorés pour l'instant.

Il prend en charge :

Gestion des ancres/alias
Comme dans des modules tels que YAML, le Constructeur utilisera des références pour les mappings et les séquences, mais évidemment pas pour les scalaires.

YAML::XS utilise de vrais alias, ce qui permet également d'aliaser les scalaires. Je pourrais ajouter une option pour cela car l'aliasing est maintenant disponible en pur Perl.

Gestion des booléens
Vous pouvez choisir entre 'perl' (1/'', le défaut actuel), 'JSON::PP' et 'boolean'.pm pour la gestion des types booléens. Cela vous permet de décharger la structure de données avec l'un des modules JSON sans perdre d'informations sur les booléens.
Nombres
Les nombres sont créés comme de vrais nombres au lieu de chaînes, de sorte qu'ils soient correctement déchargés par des modules comme JSON::PP ou JSON::XS, par exemple.
Clés complexes
Les clés de mapping en YAML peuvent être plus que de simples scalaires. Bien sûr, vous ne pouvez pas charger cela dans une structure Perl native. Le Constructeur stringifiera ces clés avec Data::Dumper au lieu de simplement retourner quelque chose comme HASH(0x55dc1b5d0178).

Exemple :

use YAML::PP;
use JSON::PP;
my $ypp = YAML::PP->new;
my $coder = JSON::PP->new->ascii->pretty->allow_nonref->canonical;
my $yaml = <<'EOM';
complex:
    ?
        ?
            a: 1
            c: 2
        : 23
    : 42
EOM
my $data = $yppl->load_string($yaml);
say $coder->encode($data);
__END__
{
   "complex" : {
      "{'{a => 1,c => 2}' => 23}" : 42
   }
}

À faire :

Arbre d'analyse
J'aimerais générer un arbre d'analyse complet, qui vous permettrait de manipuler la structure de données et de la décharger également, y compris tous les espaces blancs et les commentaires. La spécification dit que ce contenu est jetable, mais j'ai lu que beaucoup de gens souhaitent pouvoir conserver les commentaires.

YAML::PP::Dumper, YAML::PP::Emitter

Le Dumper devrait pouvoir décharger correctement les chaînes, en ajoutant des guillemets chaque fois qu'un scalaire simple ressemblerait à une chaîne spéciale, comme "true", ou lorsqu'elle contient ou commence par des caractères non autorisés.

La plupart des chaînes seront déchargées comme des scalaires simples sans guillemets. Si elles contiennent des caractères spéciaux ou ont une signification spéciale, elles seront déchargées avec des guillemets simples. Si elles contiennent des caractères de contrôle, y compris <"\n">, elles seront déchargées avec des guillemets doubles.

Il reconnaîtra les objets JSON::PP::Boolean et boolean.pm et les déchargera correctement.

Les nombres qui ont également un indicateur "PV" seront reconnus comme des nombres et non comme des chaînes :

my $int = 23;
say "int: $int"; # $int aura maintenant aussi un indicateur PV

Cela signifie que si vous utilisez accidentellement une chaîne dans un contexte numérique, elle sera également reconnue comme un nombre :

my $string = "23";
my $something = $string + 0;
print $yp->dump_string($string);
# w

DESCRIPTION

This module handles YAML. It implements the YAML 1.1 and 1.2 specification. It can parse and load YAML files.

YAML::PP is a YAML 1.2 compliant parser and loader.

It aims to be the most compatible Perl module to the YAML specification. It can be used via the YAML::PP API, or via the YAML::PP::LibYAML API, which provides a libyaml binding for parsing but uses the YAML::PP loader.

The layout of the YAML file is described using the YAML::PP::Schema classes. The default schema is the YAML 1.2 Core Schema, which can be used for a lot of applications.

The specification defines a lot of schemas, but the core schema is the most used one. It is specified that all documents MUST be valid according to the Core Schema. Therefore YAML::PP tries to be compatible with it.

For example, a standard mapping for a JSON document is:

#json
{
  "key": "value"
}

This will be parsed as:

#yaml
key: value

The output will be a hash reference:

{ 'key' => 'value' }

A list of strings will be parsed as a Perl array reference:

- a
- b
- c

This will be parsed as:

[ 'a', 'b', 'c' ]

When dumping, the layout is like libyaml output:

key:
- a
- b
- c
---
- key1: 1
  key2: 2
  key3: 3
---
- - a1
  - a2
- - b1
  - b2

FAQ - Foire aux questions

Les clés de fusion "<<" sont-elles prises en charge ?
Oui, cela peut être activé en option, voir YAML::PP::Schema::Merge
Existe-t-il un linter / formateur pour YAML
Il existe le "yamllint" largement utilisé https://yamllint.readthedocs.io/, basé sur PyYAML de python. Il est très configurable et signalera les erreurs ou les avertissements. Il ne peut pas formater.

Il existe maintenant aussi YAML::Tidy, qui formatera le fichier donné conformément à votre configuration. Jusqu'à présent, seules quelques options de configuration existent, mais elles peuvent déjà être très utiles.

Quel module YAML dois-je utiliser ?

Il existe de nombreux modules YAML sur CPAN. Pour des raisons historiques, certains d'entre eux ne gèrent pas correctement YAML.

La plupart d'entre eux ne sont pas compatibles avec la spécification YAML et entre eux, ce qui signifie qu'ils peuvent interpréter le même YAML différemment.

Les comportements dont nous discutons ici peuvent être divisés en problèmes d'analyse (syntaxe) et en problèmes de chargement/construction (par exemple, la résolution de types qui décide de ce qui est un nombre, un booléen ou nul).

Voir aussi https://matrix.yaml.info/ (analyse) et https://perlpunk.github.io/YAML-PP-p5/schema-examples.html (chargement).

"YAML.pm"
Il a été écrit avant même que la spécification YAML 1.0 ne soit terminée et a ainsi permis aux utilisateurs de Perl de traiter YAML très tôt. Il peut fonctionner pour vous si vous avez des données simples, mais il manque de nombreuses fonctionnalités et peut également produire du YAML qui ne revient pas. De nos jours, il pourrait être judicieux de passer à autre chose.
YAML::XS
Une liaison libyaml qui est robuste et largement utilisée. Cependant, il y a deux points à considérer.

1. (syntaxe) libyaml a divergé de la spécification à plusieurs égards. Ils sont cependant rares. 2. La résolution des types n'adhère pas à YAML 1.1 ou YAML 1.2, ce qui signifie qu'elle est
incompatible avec d'autres bibliothèques YAML en Perl ou dans d'autres langues.

YAML::Tiny
Il implémente à la fois un sous-ensemble minuscule de YAML, mais aussi un sur-ensemble. Cela signifie qu'il acceptera volontiers certains documents YAML qui ne sont pas officiellement valides. La résolution des types n'est pas non plus implémentée conformément à la spécification.
YAML::Syck
Une liaison à libsyck. Elle est encore moins compatible avec YAML que libyaml. De plus, la résolution des types n'est pas implémentée conformément à la spécification.
YAML::PP
Concernant la syntaxe YAML, c'est le deuxième module Perl le plus compatible avec YAML 1.2. Les cas qu'il ne peut (encore) pas analyser ne sont pas pertinents en programmation Perl, par exemple les clés de hachage qui ne sont pas des chaînes. Concernant la résolution des types, il est compatible avec le schéma de base YAML 1.2, il devrait donc être possible d'échanger des données au format YAML avec d'autres bibliothèques dans d'autres langues. Un inconvénient est que c'est le module YAML Perl le plus lent.
YAML::Parser
Ceci est un analyseur généré par la grammaire YAML, et il passe tous les tests officiels. Il existe un frontend YAML::PP::Ref que vous pouvez utiliser comme YAML::PP. Il est assez lent (bien qu'il puisse convenir pour de petits fichiers selon le cas d'utilisation). Les messages d'erreur qu'il génère sur un YAML invalide ne sont actuellement pas utiles.
YAML::PP::LibYAML
Cela combine la liaison YAML::LibYAML::API pour l'analyse avec le frontend YAML::PP pour le chargement et la résolution des types. Il est plus rapide que YAML::PP mais plus lent que YAML::XS. La divergence par rapport à la spécification YAML concernant la syntaxe n'est généralement pas un problème, et en même temps vous avez l'avantage d'être compatible avec le schéma de base YAML 1.2.

POURQUOI

Pourquoi ai-je commencé à écrire un nouveau module YAML ?

Tous les analyseurs et chargeurs disponibles pour Perl se comportent différemment, et plus important encore, ne sont pas conformes à la spécification. YAML::XS s'en sort plutôt bien, mais "libyaml" ne gère que YAML 1.1 et diverge un peu de la spécification. Les chargeurs purement Perl manquent de prise en charge d'un certain nombre de fonctionnalités.

J'ai examiné les problèmes de YAML.pm fin 2016, intégré d'anciens correctifs de rt.cpan.org et créé moi-même quelques demandes d'extraction. J'ai réalisé qu'il serait difficile de patcher YAML.pm pour analyser YAML 1.1 ou même 1.2, et cela casserait également les utilisations existantes qui dépendent du comportement actuel.

En 2016, Ingy döt Net a lancé deux projets vraiment intéressants :

"YAML TEST SUITE"
"YAML EDITOR"

Ces projets sont d'une grande aide pour tout développeur. J'ai donc eu l'idée d'écrire mon propre analyseur et j'ai commencé le jour du Nouvel An 2017. Sans la suite de tests et l'éditeur, je n'aurais jamais commencé.

J'ai également lancé un autre projet de test YAML qui permet d'avoir un aperçu rapide des frameworks qui prennent en charge quelles fonctionnalités YAML :

"YAML TEST MATRIX"

SUITE DE TESTS YAML

https://github.com/yaml/yaml-test-suite

Elle contient près de 400 cas de test et des événements d'analyse attendus et plus encore. D'autres tests arriveront. Cette suite de tests vous permet d'écrire des analyseurs sans avoir à transformer vous-même les exemples de la spécification en tests. De plus, les exemples ne couvrent pas complètement tous les cas - la suite de tests vise à le faire.

Merci également à Felix Krause, qui écrit un analyseur YAML en Nim. Il a transformé tous les exemples de spécification en cas de test.

ÉDITEUR YAML

C'est un outil pour jouer avec plusieurs analyseurs et chargeurs YAML dans vim.

https://github.com/yaml/yaml-editor

Le projet contient le code pour construire les frameworks (16 à l'heure où j'écris) et les intégrer dans une grande image Docker.

Il contient également l'éditeur yaml lui-même, qui lancera un vim dans le conteneur docker. Il utilise beaucoup de vimscript fantaisiste qui rend le jeu avec lui facile et utile. Vous pouvez choisir les frameworks que vous souhaitez tester et voir la sortie dans une grille de fenêtres vim.

En particulier lors de l'écriture d'un analyseur, il est extrêmement utile d'avoir tous les cas de test et de pouvoir jouer avec vos propres exemples pour voir comment ils sont gérés.

MATRICE DE TESTS YAML

J'étais curieux de voir comment les différents frameworks gèrent les cas de test, alors, en utilisant la suite de tests et l'image docker, j'ai écrit du code qui exécute les tests, manipule la sortie pour la comparer à la sortie attendue, et a créé une vue matricielle.

https://github.com/perlpunk/yaml-test-matrix

Vous pouvez trouver la dernière construction sur https://matrix.yaml.info
