NOM

YAML::XS - Sérialisation YAML Perl utilisant XS et libyaml

SYNTAXE

use YAML::XS;
# Interface fonctionnelle classique
my $yaml = Dump [ 1..4 ];
my $array = Load $yaml;
# EXPÉRIMENTAL : Interface orientée objet pour YAML 1.2
# Incompatible avec l'interface fonctionnelle !
my $xs = YAML::XS->new;
my $yaml = $xs->dump([ 1..4 ]);
my $array = $xs->load($yaml);

DESCRIPTION

La "libyaml" de Kirill Simonov est sans doute la meilleure implémentation YAML. La bibliothèque C est écrite précisément selon la spécification YAML 1.1. Elle était à l'origine liée à Python et plus tard à Ruby.

Ce module est une liaison XS Perl à libyaml qui offre à Perl le meilleur support YAML à ce jour.

Ce module exporte les fonctions "Dump", "Load", "DumpFile" et "LoadFile". Ces fonctions sont censées fonctionner exactement comme les fonctions correspondantes de "YAML.pm". Seules "Load" et "Dump" sont exportées par défaut.

CONFIGURATION

L'interface orientée objet est décrite ci-dessous : "INTERFACE ORIENTÉE OBJET"

  • $YAML::XS::LoadBlessed (depuis v0.69)

    Par défaut : faux.

    La valeur par défaut a été modifiée dans la version 0.81.

    Lorsqu'elle est définie sur faux, elle ne bénira pas les données en objets, ce qui peut poser un problème de sécurité lors du chargement de YAML provenant d'une source non fiable. Elle ignorera silencieusement la balise et chargera simplement les données sans bénir.

    Dans PyYAML, cela s'appelle SafeLoad.

    Si elle est définie sur vrai, elle chargera les éléments YAML suivants en tant qu'objets :

    ---
local: !Foo::Bar [a]
perl: !!perl/hash:Foo::Bar { a: 1 }
regex: !!perl/regexp:Foo::Bar pattern

    Vous pouvez créer n'importe quel type d'objet avec YAML. La création elle-même n'est pas la partie critique. Si la classe a une méthode "DESTROY", elle sera appelée une fois que l'objet sera supprimé. Un exemple avec File::Temp supprimant des fichiers peut être trouvé à https://bugs.debian.org/cgi-bin/bugreport.cgi?bug=862373.

  • $YAML::XS::ForbidDuplicateKeys (depuis 0.84)

    Par défaut : faux

    Lorsqu'elle est définie sur vrai, "Load" mourra lors de la rencontre d'une clé dupliquée dans une table de hachage, par exemple :

    key: value
key: another value

    Cela peut être utile pour des documents YAML plus grands où ce n'est pas si évident, et il est recommandé de la définir sur vrai. C'est aussi ce qu'un chargeur YAML devrait faire par défaut selon la spécification YAML.

  • $YAML::XS::UseCode
  • $YAML::XS::DumpCode
  • $YAML::XS::LoadCode

    Si activé, prend en charge la déparse et l'évaluation des blocs de code.

    Notez que le support du chargement de code a été ajouté dans la version 0.75, bien que $LoadCode ait déjà été documenté dans les versions antérieures.

  • $YAML::XS::QuoteNumericStrings

    Lorsqu'elle est vraie (par défaut), les chaînes qui ressemblent à des nombres mais qui n'ont pas été numérisées seront mises entre guillemets lors de la sérialisation.

    Cela garantit que, par exemple, les zéros non significatifs et d'autres formats sont préservés.

  • $YAML::XS::Boolean (depuis v0.67)

    Par défaut : indéfini

    Depuis YAML::XS 0.89 : Lorsqu'il est utilisé avec perl 5.36 ou plus récent, les booléens intégrés fonctionneront immédiatement. Ils seront créés par "Load" et reconnus par "Dump" automatiquement (depuis YAML::XS 0.89).

    say Dump({ truth => builtin::true });
# truth: true

    Depuis YAML::XS v0.902 : les booléens chargés ne sont plus en lecture seule.

    Pour les anciennes versions de perl, vous pouvez utiliser la configuration suivante pour sérialiser les données en booléens YAML :

    Lorsqu'elle est définie sur "JSON::PP" ou "boolean", les chaînes simples (non entre guillemets) "true" et "false" seront chargées en tant qu'objets "JSON::PP::Boolean" ou "boolean.pm". Ces objets seront à leur tour sérialisés en tant que simples "true" ou "false".

    Il tentera de charger [JSON::PP] ou [boolean] et mourra s'il ne peut pas être chargé.

    Avec cela, il est possible d'ajouter de nouveaux booléens "réels" à une structure de données :

    local $YAML::XS::Boolean = "JSON::PP"; # ou "boolean"
my $data = Load("booltrue: true");
$data->{boolfalse} = JSON::PP::false;
my $yaml = Dump($data);
# boolfalse: false
# booltrue: true

    Cela permet également aux booléens de survivre lors du chargement de YAML via YAML::XS et de les encoder en JSON via l'un des divers encodeurs JSON, qui prennent la plupart du temps en charge les booléens JSON::PP.

    Veuillez noter que JSON::PP::Boolean et boolean.pm se comportent de manière légèrement différente. Idéalement, vous ne devriez les utiliser que dans un contexte booléen.

    Si elle n'est pas définie, les booléens sont chargés en tant que variables perl spéciales "PL_sv_yes" et "PL_sv_no", qui ont l'inconvénient d'être en lecture seule, et vous ne pouvez pas les ajouter à une structure de données existante avec du pur perl.

    Si vous avez simplement besoin de charger des "booléens perl" qui sont vrais ou faux dans un contexte booléen, vous serez satisfait du réglage par défaut.

  • $YAML::XS::Indent (depuis v0.76)

    La valeur par défaut est 2.

    Définit le nombre d'espaces pour l'indentation pour "Dump".

UTILISATION DE YAML::XS AVEC UNICODE

La gestion correcte de l'unicode en Perl peut être une corvée. YAML::XS ne traite que des flux d'octets utf8. Gardez simplement à l'esprit ceci :

$perl = Load($utf8_octets);
$utf8_octets = Dump($perl);

Il y a beaucoup, beaucoup d'endroits où les choses peuvent mal tourner avec l'unicode. Si vous rencontrez des problèmes, utilisez Devel::Peek sur tous les points de données possibles.

INTERFACE ORIENTÉE OBJET

Depuis la version v0.904.0, EXPÉRIMENTAL

+++NOTE : Ceci est incompatible avec l'interface fonctionnelle et traitera les valeurs YAML différemment.+++

Cela présente deux MAJEURES différences avec l'ancienne interface fonctionnelle :

Objet avec options
Cela fournit une interface où vous créez un objet YAML::XS avec des options (au lieu de l'ancienne interface avec des variables globales).
Schéma de base YAML 1.2
Il implémente le schéma de base YAML 1.2.

(Notez que l'interface fonctionnelle n'implémente pas YAML 1.1, en ce qui concerne le chargement des nombres, des booléens, des null, etc. Elle implémente son propre ensemble de règles.)

Voici un exemple (incomplet !) de valeurs qui sont traitées différemment qu'avec l'interface fonctionnelle. Les valeurs YAML qui correspondent à certains modèles ne sont pas chargées comme des chaînes, mais comme d'autres types :

# Interface fonctionnelle : valeurs spéciales (non compatibles avec d'autres modules YAML)
- [true, false]                             # booléens
- [null, ~]                                 # indéfini
- [inf, INF, iNf, iNF, InF, INf, -inf, ...] # Inf
- [100_000]                                 # 100000
- # anything that looks_like_number()       # nombre
# Valeurs spéciales de l'OOP YAML 1.2
- [true, True, TRUE, false, False, FALSE]   # booléens
- [null, Null, NULL, ~]                     # indéfini
- [.inf, .Inf, .INF, -.inf, -.Inf, -.INF]   # Inf
- [.nan, .NAN, .NaN]                        # nan
- [42, 0x10, 0o10]                          # déc 42, hex 16, oct 8

Pour des différences plus subtiles concernant les nombres, consultez les données complètes ici :

Définitions YAML 1.1 / 1.2 : <https://perlpunk.github.io/

NAME

YAML::XS - YAML 1.2.x serializer and deserialiser using XS

SYNOPSIS

use YAML::XS ();
my $xs = YAML::XS->new;
my $yaml = "foo: bar";
# Load single (first) document:
my $data = $xs->load($yaml);
$yaml = $xs->dump($data);
# Or to load all documents:
my @data = $xs->load($yaml);
$yaml = $xs->dump(@data);

DESCRIPTION

YAML::XS is a YAML 1.2.x serializer and deserialiser implemented in XS.

It aims to be compatible with the official YAML test suite:

Test suite: Schema <https://perlpunk.github.io/yaml-test-schema/schemas.html>
Test data: <https://perlpunk.github.io/yaml-test-schema/data.html>

This way the OOP interface is compatible to YAML::PP and YAML processors in other languages supporting YAML 1.2.

"load" will return the first document in scalar context
The functional interface returns the last.
Numbers don't have string flags
Booleans currently are only preserved for the new builtin booleans
Adding a JSON::PP boolean option for older perls is planned
References, objects, globs, regexes and coderefs cannot be loaded or dumped
This is planned.

CONFIGURATION

Usage

use YAML::XS ();
my $xs = YAML::XS->new;
my $yaml = "foo: bar";
# Load single (first) document:
my $data = $xs->load($yaml);
$yaml = $xs->dump($data);
# Or to load all documents:
my @data = $xs->load($yaml);
$yaml = $xs->dump(@data);

METHODS

new

use YAML::XS;
my $xs = YAML::XS->new(
    # load options
    # require_footer => 0,
    # dump options
    # indent => 2,
    # header => 1,
    # footer => 0,
    # width => 80,
    # anchor_prefix => '',
    # load and dump options
    # utf8 => 0,
);

Options:

indent
Default: 2

Sets the number of spaces for indentation for dumping.

utf8
Default: false

When false, the loader will accept unencoded character strings, and the dumper returns unencoded character strings.

When true, the loader accepts a UTF-8 encoded string of bytes, and the dumper returns a UTF-8 encoded string of bytes. This typically makes sense when you read from / write to a file directly.

header
Default: 1

Writes a "---" before every document

footer
Default: 0

Writes a "..." at the end of every document.

width
Set the maximum number of colums for dumping. If a value has too many characters, it will be split into multiple lines.
require_footer
Default: 0

Can be useful in a use case where you want to make sure you received the complete document from the sender.

anchor_prefix
Default: ''

If set to a string like "ANCHOR", anchors and aliases will be prefixed with this instead of just being numbers:

# my $xs = YAML::XS->new( anchor_prefix => 'ANCHOR' );
# my $hash = { some => "mapping" };
# say $xs->dump([$hash, $hash]);
- &ANCHOR1
  some: mapping
- *ANCHOR1

load

my $yaml = <<'EOM';
---
- 23
---
some: mapping
EOM
my $array = $xs->load($yaml);
# [23]
my @documents = $xs->load($yaml);
# (
#   [23],
#   { some => "mapping" }
# )

In scalar context, if the YAML string contains more than one document, it will return the first document.

dump

$yaml = $xs->dump($data);
$yaml = $xs->dump($data1, $data2, $data3);
$yaml = $xs->dump(@data);

USING YAML::XS WITH UNICODE

YAML.pm and YAML::Syck use Perl's internal unicode representation. However, they do not necessarily rely on Perl's internal unicode representation. For example, they might handle utf-8 strings directly.

YAML::XS does the same when the utf8 option is enabled.

Default: disabled

When utf8 is false, the loader will accept unencoded character strings, and the dumper returns unencoded character strings. When true, the loader accepts a UTF-8 encoded string of bytes, and the dumper returns a UTF-8 encoded string of bytes. This typically makes sense when you read from / write to a file directly.
