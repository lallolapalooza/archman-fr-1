NOM

YAML::Tiny - Lire/écrire des fichiers YAML avec le moins de code possible

VERSION

version 1.76

PRÉAMBULE

La spécification YAML est énorme. Vraiment, vraiment énorme. Elle contient toutes les fonctionnalités de XML, sauf avec la flexibilité et le choix, ce qui la rend plus facile à lire, mais avec une spécification formelle plus complexe que XML.

L'implémentation pure Perl originale de YAML coûte un peu plus de 4 mégaoctets de mémoire à charger. Tout comme avec les fichiers .ini de Windows (3 mégaoctets à charger) et CSS (3,5 mégaoctets à charger), la situation demande un module YAML::Tiny, un sous-ensemble incomplet mais correct et utilisable des fonctionnalités, dans le moins de code possible.

Comme les autres modules "::Tiny", YAML::Tiny n'a pas de dépendances non essentielles, ne nécessite pas de compilateur pour s'installer, est rétrocompatible avec Perl v5.8.1, et peut être intégré dans d'autres modules si nécessaire.

En échange de cette extrême flexibilité, il ne fournit qu'un support limité pour un sous-ensemble de YAML. Mais le sous-ensemble pris en charge contient la plupart des fonctionnalités pour les utilisations les plus courantes de YAML.

SYNOPSIS

En supposant un fichier file.yml comme suit :

---
rootproperty: blah
section:
  one: two
  three: four
  Foo: Bar
  empty: ~

Lire et écrire le fichier file.yml comme suit :

use YAML::Tiny;
# Ouvrir la configuration
my $yaml = YAML::Tiny->read( 'file.yml' );
# Obtenir une référence au premier document
my $config = $yaml->[0];
# Ou lire les propriétés directement
my $root = $yaml->[0]->{rootproperty};
my $one  = $yaml->[0]->{section}->{one};
my $Foo  = $yaml->[0]->{section}->{Foo};
# Changer les données directement
$yaml->[0]->{newsection} = { this => 'that' }; # Ajouter une section
$yaml->[0]->{section}->{Foo} = 'Not Bar!';     # Changer une valeur
delete $yaml->[0]->{section};                  # Supprimer une valeur
# Sauvegarder le document dans le fichier
$yaml->write( 'file.yml' );

Pour créer un nouveau fichier YAML à partir de zéro :

# Créer un nouvel objet avec un seul document hashref
my $yaml = YAML::Tiny->new( { wibble => "wobble" } );
# Ajouter un document arrayref
push @$yaml, [ 'foo', 'bar', 'baz' ];
# Sauvegarder les deux documents dans un fichier
$yaml->write( 'data.yml' );

Alors data.yml contiendra :

---
wibble: wobble
---
- foo
- bar
- baz

DESCRIPTION

YAML::Tiny est une classe Perl pour lire et écrire des fichiers de type YAML, écrite avec le moins de code possible, réduisant le temps de chargement et la surcharge mémoire.

La plupart du temps, il est admis que les applications Perl utilisent beaucoup de mémoire et de modules. La famille de modules ::Tiny a pour but spécifique de fournir une alternative ultra-légère et sans dépendances à de nombreux modules standards plus complets.

Ce module est principalement destiné à lire des fichiers écrits par des humains (comme de simples fichiers de configuration) et à générer des fichiers très simples lisibles par l'homme. Notez que j'ai dit lisibles par l'homme et non lisibles par les geeks. Le genre de fichiers que votre manager ou secrétaire moyen devrait pouvoir regarder et comprendre.

YAML::Tiny ne génère pas de commentaires, il ne préservera pas nécessairement l'ordre de vos hachages, et il normalisera si vous lisez puis réécrivez.

Il ne prend en charge qu'un sous-ensemble très basique de la spécification YAML complète.

L'utilisation est ciblée sur des fichiers comme le META.yml de Perl, pour lesquels un module petit et facilement intégrable est extrêmement attractif.

Les fonctionnalités ne seront ajoutées que si elles sont lisibles par l'homme et peuvent être écrites en quelques lignes de code. S'il vous plaît, ne soyez pas offensé si votre demande est refusée. Quelqu'un doit tracer la ligne, et pour YAML::Tiny, ce quelqu'un c'est moi.

Si vous avez besoin de quelque chose de plus puissant, passez à YAML (7 mégaoctets de surcharge mémoire) ou YAML::XS (6 mégaoctets de surcharge mémoire et nécessite un compilateur C).

Pour réitérer, YAML::Tiny ne préserve pas vos commentaires, espaces blancs ou l'ordre de vos données YAML. Mais il devrait fonctionner sans problème de la structure Perl au fichier et retour.

MÉTHODES

new

Le constructeur "new" crée un objet "YAML::Tiny" comme référence de tableau typé. Tous les arguments fournis sont pris comme des documents séparés à sérialiser.

read $nom_fichier

Le constructeur "read" lit un fichier YAML à partir d'un nom de fichier, et retourne un nouvel objet "YAML::Tiny" contenant le contenu analysé.

Retourne l'objet en cas de succès ou lance une erreur en cas d'échec.

read_string $chaîne;

Le constructeur "read_string" lit des données YAML à partir d'une chaîne de caractères, et retourne un nouvel objet "YAML::Tiny" contenant le contenu analysé. Si vous avez lu la chaîne à partir d'un fichier vous-même, assurez-vous de l'avoir correctement décodée en caractères au préalable.

Retourne l'objet en cas de succès ou lance une erreur en cas d'échec.

write $nom_fichier

La méthode "write" génère le contenu du fichier pour les propriétés, et l'écrit sur disque en utilisant l'encodage UTF-8 vers le nom de fichier spécifié.

Retourne vrai en cas de succès ou lance une erreur en cas d'échec.

write_string

Génère le contenu du fichier pour l'objet et le retourne sous forme de chaîne de caractères. Celle-ci peut contenir des caractères non-ASCII et devrait être encodée avant d'être écrite dans un fichier.

Retourne vrai en cas de succès ou lance une erreur en cas d'échec.

errstr (DÉPRÉCIÉ)

Avant la version 1.57, certaines erreurs étaient fatales et d'autres n'étaient disponibles que via la variable $YAML::Tiny::errstr, laquelle était accessible via la méthode errstr().

Depuis la version 1.57, toutes les erreurs sont fatales et lèvent des exceptions.

La variable $errstr est toujours définie lorsque des exceptions sont levées, mais $errstr et la méthode errstr() sont dépréciées et pourraient être supprimées dans une future version. La première utilisation de errstr() émettra un avertissement de dépréciation.

FONCTIONS

YAML::Tiny implémente un certain nombre de fonctions pour ajouter la compatibilité avec l'API YAML. Celles-ci devraient être un remplacement direct.

Dump

my $chaîne = Dump(liste-de-structures-de-données-Perl);

Transformer des données Perl en YAML. Cette fonction fonctionne très comme Data::Dumper::Dumper().

Elle prend une liste de structures de données Perl et les déverse dans un format sérialisé.

Elle retourne une chaîne de caractères contenant le flux YAML. Assurez-vous de l'encoder en UTF-8 avant de la sérialiser vers un fichier ou une socket.

Les structures peuvent être des références ou des scalaires simples.

Lève une exception en cas d'erreur.

Load

my @structures_de_données = Load(chaîne-contenant-un-flux-YAML);

Transformer du YAML en données Perl. C'est l'inverse de Dump.

Tout comme la fonction thaw() de Storable ou la fonction eval() par rapport à Data::Dumper.

Elle analyse une chaîne de caractères contenant un flux YAML valide en une liste de structures de données Perl représentant les documents YAML individuels. Assurez-vous de décoder correctement la chaîne si elle provient d'un fichier ou d'une socket.

my $dernière_structure_de_données = Load(chaîne-contenant-un-flux-YAML);

Pour la cohérence avec YAML.pm, lorsque Load est appelé en contexte scalaire, il retourne la structure de données correspondant au dernier des documents YAML trouvés dans le flux d'entrée.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

>

Se termine en cas d'erreur.

freeze() et thaw()

Alias de Dump() et Load() pour les fans de Storable. Cela permettra également à YAML::Tiny d'être branché directement sur des modules comme POE.pm, qui utilisent l'API freeze/thaw pour la sérialisation interne.

DumpFile(filepath, list)

Écrit le flux YAML dans un fichier avec encodage UTF-8 au lieu de retourner simplement une chaîne.

Se termine en cas d'erreur.

LoadFile(filepath)

Lit le flux YAML à partir d'un fichier encodé en UTF-8 au lieu d'une chaîne.

Se termine en cas d'erreur.

SPÉCIFICATION YAML TINY

Cette section de la documentation fournit une spécification pour « YAML Tiny », un sous-ensemble de la spécification YAML.

Elle est basée et décrite comparativement à la spécification YAML 1.1 Working Draft 2004-12-28, située à http://yaml.org/spec/current.html.

La terminologie et les numéros de chapitre sont basés sur cette spécification.

1. Introduction et Objectifs

L'objectif de la spécification YAML Tiny est de décrire un sous-ensemble utile de la spécification YAML qui peut être utilisé pour des cas d'utilisation typiques orientés document tels que les fichiers de configuration et les simples dumps de structures de données.

De nombreux éléments de spécification qui ajoutent de la flexibilité ou de l'extensibilité sont intentionnellement supprimés, tout comme le support des structures de données complexes, de la programmation orientée objet et des classes.

En général, le langage YAML Tiny cible uniquement les structures de données disponibles en JSON, avec la limitation supplémentaire que seules les clés simples sont prises en charge.

En conséquence, tous les documents YAML Tiny possibles devraient pouvoir être transformés en un document JSON équivalent, bien que l'inverse ne soit pas nécessairement vrai (mais sera vrai dans les cas simples).

En conséquence de ces simplifications, la spécification YAML Tiny devrait être implémentable dans une quantité de code (relativement) petite dans n'importe quel langage qui prend en charge les expressions régulières compatibles Perl (PCRE).

2. Introduction

YAML Tiny prend en charge trois structures de données. Ce sont les scalaires (sous diverses formes), les séquences au format bloc et les mappages au format bloc. Les séquences et les mappages au style flux ne sont pas pris en charge, à quelques exceptions mineures détaillées plus loin.

L'utilisation de trois tirets « --- » pour indiquer le début d'un nouveau document est prise en charge, et plusieurs documents par fichier/flux sont autorisés.

Les commentaires de ligne et en ligne sont pris en charge.

Les scalaires sont pris en charge via le style simple, les guillemets simples et doubles, ainsi que les scalaires multilignes de style littéral et de style replié.

L'utilisation de tags explicites n'est pas prise en charge.

L'utilisation de scalaires de type « null » est prise en charge via le caractère ~.

L'utilisation de scalaires de type « bool » n'est pas prise en charge.

Cependant, les implémentations de sérialisation doivent prendre soin d'échapper explicitement les chaînes qui correspondent à un mot-clé « bool » dans l'ensemble suivant afin d'empêcher d'autres implémentations qui prennent en charge « bool » de lire accidentellement une chaîne comme un booléen

y|Y|yes|Yes|YES|n|N|no|No|NO
|true|True|TRUE|false|False|FALSE
|on|On|ON|off|Off|OFF

L'utilisation d'ancres et d'alias n'est pas prise en charge.

L'utilisation de directives est prise en charge uniquement pour la directive %YAML.

3. Traitement des informations YAML Tiny

Traitement

La spécification YAML dicte une sérialisation en trois phases et une désérialisation en trois phases.

La spécification YAML Tiny ne prescrit aucune méthodologie ou mécanisme particulier pour l'analyse syntaxique.

Tout analyseur conforme n'est tenu d'analyser qu'un seul document à la fois. La capacité de prendre en charge les flux de documents est facultative et très probablement atypique.

Comme les ancres et les alias ne sont pas pris en charge, le graphe de représentation résultant est donc dirigé mais (contrairement à la spécification YAML principale) acyclique.

Les références/pointeurs circulaires ne sont pas possibles, et tout sérialiseur YAML Tiny détectant une référence circulaire doit générer une erreur avec un message approprié.

Flux de Présentation

YAML Tiny lit et écrit des fichiers encodés en UTF-8. Les opérations sur les chaînes attendent ou produisent des caractères Unicode et non des octets encodés en UTF-8.

Points de Défaillance de Chargement

Il n'est pas attendu que les analyseurs et émetteurs YAML Tiny se remettent ou s'adaptent aux erreurs. La modalité d'erreur spécifique de toute implémentation n'est pas dictée (codes de retour, exceptions, etc.) mais est attendue comme étant cohérente.

4. Syntaxe

Jeu de Caractères

Les flux YAML Tiny sont traités en mémoire comme des caractères Unicode et lus/écrits avec un encodage UTF-8.

L'échappement et le déséchappement des échappements YAML 8 bits est requis.

L'échappement et le déséchappement des échappements YAML 16 bits et 32 bits n'est pas requis.

Caractères Indicateurs

Le support de l'indicateur null/indéfini « ~ » est requis.

Les implémentations peuvent le représenter de manière appropriée pour le langage sous-jacent.

Le support de l'indicateur de séquence bloc « - » est requis.

Le support de l'indicateur de clé de mappage « ? » n'est pas requis.

Le support de l'indicateur de valeur de mappage « : » est requis.

Le support de l'indicateur de collection flux « , » n'est pas requis.

Le support de l'indicateur de séquence flux « [ » n'est pas requis, avec une exception (détaillée ci-dessous).

Le support de l'indicateur de séquence flux « ] » n'est pas requis, avec une exception (détaillée ci-dessous).

Le support de l'indicateur de mappage flux « { » n'est pas requis, avec une exception (détaillée ci-dessous).

Le support de l'indicateur de mappage flux « } » n'est pas requis, avec une exception (détaillée ci-dessous).

Le support de l'indicateur de commentaire « # » est requis.

Le support de l'indicateur d'ancre « & » n'est pas requis.

Le support de l'indicateur d'alias « * » n'est pas requis.

Le support de l'indicateur de tag « ! » n'est pas requis.

Le support de l'indicateur de bloc littéral « | » est requis.

Le support de l'indicateur de bloc replié « > » est requis.

Le support de l'indicateur de guillemet simple « ' » est requis.

Le support de l'indicateur de guillemet double « " » est requis.

Le support de l'indicateur de directive « % » est requis, mais uniquement pour le cas spécial d'une directive de version %YAML avant l'en-tête de document « --- », ou sur la même ligne que l'en-tête de document.

Par exemple :

%YAML 1.1
---
- Une séquence avec un seul élément

Exception Spéciale :

Pour permettre le support des séquences et mappages vides, le support des constructions [] (séquence vide) et {} (mappage vide) est requis.

Par exemple,

%YAML 1.1
# Un document constitué uniquement d'un mappage vide
--- {}
# Un document constitué uniquement d'une séquence vide
--- []
# Un document constitué d'un mappage vide dans une séquence
- foo
- {}
- bar

Primitives de Syntaxe

Autre que les cas de séquence et de mappage vides décrits ci-dessus, YAML Tiny ne prend en charge que le groupe de contextes de style bloc basé sur l'indentation.

Les cinq contextes scalaires sont pris en charge.

Les espaces d'indentation fonctionnent conformément à la spécification YAML dans tous les cas.

Les commentaires fonctionnent conformément à la spécification YAML dans tous les cas simples. Le support des commentaires multilignes indentés n'est pas requis.

Les espaces de séparation fonctionnent conformément à la spécification YAML dans tous les cas.

Flux de Caractères YAML Tiny

La seule directive prise en charge par la spécification YAML Tiny est l'identificateur de langue/version %YAML. Bien que détectée, cette directive n'aura aucun contrôle sur l'analyse syntaxique elle-même.

L'analyseur doit reconnaître les deux formats YAML 1.0 et YAML 1.1+ de cette directive (ainsi que la forme commentée, bien qu'aucun code explicite ne devrait être nécessaire pour gérer ce cas, étant un commentaire de toute façon)

C'est-à-dire que tout ce qui suit doit être pris en charge.

--- #YAML:1.0
- foo
%YAML:1.0
---
- foo
% YAML 1.1
---
- foo

Le support de la directive %TAG n'est pas requis.

Le support de directives supplémentaires n'est pas requis.

Le support du marqueur de délimitation de document « --- » est requis.

Le support du marqueur de délimitation de document « ... » n'est pas requis.

Si nécessaire, une délimitation de document doit simplement être indiquée par un marqueur « --- », sans marqueur « ... » précédent.

Le support des flux vides (ne contenant aucun document) est requis.

Le support des départs de document implicites est requis.

C'est-à-dire que ce qui suit doit être équivalent.

# Forme complète
%YAML 1.1
---
foo: bar
# Forme implicite
foo: bar

Nœuds

Le support des propriétés optionnelles d'ancre et de tag des nœuds n'est pas requis.

Le support des ancres de nœud n'est pas requis.

Le support des tags de nœud n'est pas requis.

Le support des nœuds alias n'est pas requis.

Le support des nœuds flux n'est pas requis.

Le support des nœuds bloc est requis.

Styles Scalaires

Le support des cinq styles scalaires est requis conformément à la spécification YAML, bien que le support des scalaires entre guillemets s'étendant sur plusieurs lignes ne soit pas requis.

Le support des documents scalaires multilignes commençant sur l'en-tête n'est pas requis.

Le support des indicateurs de mordillage sur les styles scalaires multilignes est requis.

Styles de Collection

Le support dor block-style sequences is required.

Support for flow-style sequences is not required.

Support for block-style mappings is required.

Support for flow-style mappings is not required.

Both sequences and mappings should be able to be arbitrarily nested.

Support for plain-style mapping keys is required.

Support for quoted keys in mappings is not required.

Support for "?"-indicated explicit keys is not required.

Here endeth the specification.

Notes supplémentaires spécifiques à Perl

Pour certaines applications Perl, il est important de savoir si vous avez vraiment un nombre et non une chaîne de caractères.

Autrement dit, dans certains contextes, il est important que 3 le nombre soit distinct de "3" la chaîne de caractères.

Étant donné que même Perl lui-même n'est pas trivialement capable de comprendre la différence (certainement sans modules basés sur XS), les implémentations Perl de la spécification YAML Tiny ne sont pas tenues de conserver la distinction entre 3 et "3".
