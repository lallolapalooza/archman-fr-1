NOM

YAML::PP::Schema::Merge - Permet les clés de fusion YAML pour les mappings

SYNOPSIS

use YAML::PP;
my $yp = YAML::PP->new( schema => [qw/ + Merge /] );
my $yaml = <<'EOM';
---
- &CENTER { x: 1, y: 2 }
- &LEFT { x: 0, y: 2 }
- &BIG { r: 10 }
- &SMALL { r: 1 }
# All the following maps are equal:
- # Explicit keys
  x: 1
  y: 2
  r: 10
  label: center/big
- # Merge one map
  << : *CENTER
  r: 10
  label: center/big
- # Merge multiple maps
  << : [ *CENTER, *BIG ]
  label: center/big
- # Override
  << : [ *BIG, *LEFT, *SMALL ]
  x: 1
  label: center/big
EOM
my $data = $yp->load_string($yaml);
# $data->[4] == $data->[5] == $data->[6] == $data->[7]

DESCRIPTION

Voir https://yaml.org/type/merge.html pour la spécification.

Citation :

"Specify one or more mappings to be merged with the current one.

The "<<" merge key is used to indicate that all the keys of one or more specified maps should be inserted into the current map. If the value associated with the key is a single mapping node, each of its key/value pairs is inserted into the current mapping, unless the key already exists in it. If the value associated with the merge key is a sequence, then this sequence is expected to contain mapping nodes and each of these nodes is merged in turn according to its order in the sequence. Keys in mapping nodes earlier in the sequence override keys specified in later mapping nodes."

L'implémentation de ceci de manière générique n'est pas triviale, car nous devons également gérer les clés dupliquées, et YAML::PP vous permet d'écrire votre propre gestionnaire pour le traitement des mappings.

L'API interne n'est donc pas stable à ce stade.

Notez que si vous activez ce schéma, un scalaire simple `<<` sera considéré comme spécial n'importe où dans votre document, donc si vous voulez un littéral `<<`, vous devez le mettre entre guillemets.

Notez que la fusion effectuée n'est pas une "fusion profonde". Seules les clés de premier niveau sont fusionnées.
