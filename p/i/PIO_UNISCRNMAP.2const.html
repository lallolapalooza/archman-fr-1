ioctl_kd(2) Manuel des appels système ioctl_kd(2)

NOM

ioctl_kd - ioctls pour terminal console et consoles virtuelles

SYNTAXE

#include <linux/kd.h>  /* Définition des constantes d'opération */
#include <sys/ioctl.h>
int ioctl(int fd, unsigned long op, void *argp);

DESCRIPTION

Les opérations ioctl(2) suivantes, spécifiques à Linux, sont supportées pour les terminaux consoles et les consoles virtuelles.

KDGETLED
Obtenir l'état des LEDs. argp pointe vers un char. Les trois bits inférieurs de *argp sont mis à l'état des LEDs, comme suit :
LED_CAP 0x04 LED du verrouillage majuscule
LED_NUM 0x02 LED du verrouillage numérique
LED_SCR 0x01 LED du verrouillage de défilement
KDSETLED
Définir les LEDs. Les LEDs sont mises à correspondre aux trois bits inférieurs de l'entier non signé dans argp. Cependant, si un bit d'ordre supérieur est défini, les LEDs reviennent à la normale : affichant l'état des fonctions du clavier des verrouillages majuscule, numérique et de défilement.

Avant Linux 1.1.54, les LEDs reflétaient simplement l'état des indicateurs correspondants du clavier, et KDGETLED/KDSETLED changeaient également les indicateurs du clavier. Depuis Linux 1.1.54, les LEDs peuvent afficher des informations arbitraires, mais par défaut, elles affichent les indicateurs du clavier. Les deux ioctls suivants sont utilisés pour accéder aux indicateurs du clavier.

KDGKBLED
Obtenir les indicateurs du clavier Verrouillage Maj, Verrouillage Num, Verrouillage Défil. (pas les lumières). argp pointe vers un char qui est mis à l'état de l'indicateur. Les trois bits de poids faible (masque 0x7) obtiennent l'état actuel de l'indicateur, et les bits de poids faible de la nibble suivante (masque 0x70) obtiennent l'état par défaut de l'indicateur. (Depuis Linux 1.1.54.)
KDSKBLED
Définir les indicateurs du clavier Verrouillage Maj, Verrouillage Num, Verrouillage Défil. (pas les lumières). argp est un entier non signé qui contient l'état désiré de l'indicateur. Les trois bits de poids faible (masque 0x7) contiennent l'état de l'indicateur, et les bits de poids faible de la nibble suivante (masque 0x70) contiennent l'état par défaut de l'indicateur. (Depuis Linux 1.1.54.)
KDGKBTYPE
Obtenir le type de clavier. Renvoie la valeur KB_101, définie comme 0x02.
KDADDIO
Ajouter un port d'E/S comme valide. Équivalent à ioperm(arg,1,1).
KDDELIO
Supprimer un port d'E/S comme valide. Équivalent à ioperm(arg,1,0).
KDENABIO
Activer les E/S vers la carte vidéo. Équivalent à ioperm(0x3b4, 0x3df-0x3b4+1, 1).
KDDISABIO
Désactiver les E/S vers la carte vidéo. Équivalent à ioperm(0x3b4, 0x3df-0x3b4+1, 0).
KDSETMODE
Définir le mode texte/graphique. argp est un entier non signé contenant l'une des valeurs suivantes :
KD_TEXT 0x00
KD_GRAPHICS 0x01
KDGETMODE
Obtenir le mode texte/graphique. argp pointe vers un int qui est mis à l'une des valeurs indiquées ci-dessus pour KDSETMODE.
KDMKTONE
Générer un son de durée spécifiée. Les 16 bits inférieurs de l'entier non signé dans argp spécifient la période en cycles d'horloge, et les 16 bits supérieurs indiquent la durée en millisecondes. Si la durée est zéro, le son est désactivé. Le contrôle retourne immédiatement. Par exemple, argp = (125<<16) + 0x637 spécifierait le bip normalement associé à un ctrl-G. (Donc, depuis Linux 0.99pl1 ; bugué dans Linux 2.1.49-50.)
KIOCSOUND
Démarrer ou arrêter la génération de son. Les 16 bits inférieurs de argp spécifient la période en cycles d'horloge (c'est-à-dire, argp = 1193180/fréquence). argp = 0 désactive le son. Dans les deux cas, le contrôle retourne immédiatement.
GIO_CMAP
Obtenir la table des couleurs par défaut actuelle du noyau. argp pointe vers un tableau de 48 octets. (Depuis Linux 1.3.3.)
PIO_CMAP
Changer la table des couleurs par défaut en mode texte. argp pointe vers un tableau de 48 octets qui contient, dans l'ordre, les valeurs Rouge, Vert et Bleu pour les 16 couleurs d'écran disponibles : 0 est éteint, et 255 est pleine intensité. Les couleurs par défaut sont, dans l'ordre : noir, rouge foncé, vert foncé, marron, bleu foncé, violet foncé, cyan foncé, gris clair, gris foncé, rouge vif, vert vif, jaune, bleu vif, violet vif, cyan vif, et blanc. (Depuis Linux 1.3.3.)
GIO_FONT
Obtenir la police d'écran 256 caractères sous forme étendue. argp pointe vers un tableau de 8192 octets. Échoue avec le code d'erreur EINVAL si la police actuellement chargée est une police de 512 caractères, ou si la console n'est pas en mode texte.
GIO_FONTX
Obtenir la police d'écran et les informations associées. argp pointe vers une struct consolefontdesc (voir PIO_FONTX). À l'appel, le champ charcount doit être défini au nombre maximum de caractères qui tiendraient dans le tampon pointé par chardata. Au retour, charcount et charheight sont remplis avec les données respectives pour la police actuellement chargée, et le tableau chardata contient les données de la police si la valeur initiale de charcount indiquait que suffisamment d'espace était disponible ; sinon, le tampon est intact et errno est mis à ENOMEM. (Depuis Linux 1.3.1.)
PIO_FONT
Définir la police d'écran 256 caractères. Charge la police dans le générateur de caractères EGA/VGA. argp pointe vers une carte de 8192 octets, avec 32 octets par caractère. Seuls les N premiers sont utilisés pour une police 8xN (0 < N <= 32). Cet appel invalide également le mappage Unicode.
PIO_FONTX
Définit la police d'écran et les informations de rendu associées. argp pointe vers une

struct consolefontdesc {
    unsigned short charcount;  /* nombre de caractères dans la police
                                  (256 ou 512) */
    unsigned short charheight; /* lignes de balayage par
                                  caractère (1-32) */
    char          *chardata;   /* données de la police sous
                                  forme étendue */
};

Si nécessaire, l'écran sera redimensionné de manière appropriée, et SIGWINCH sera envoyé aux processus concernés. Cet appel invalide également le mappage Unicode. (Depuis Linux 1.3.1.)
PIO_FONTRESET
Réinitialise la police d'écran, la taille et le mappage Unicode aux valeurs par défaut au démarrage. argp n'est pas utilisé, mais doit être défini à NULL pour garantir la compatibilité avec les futures versions de Linux. (Depuis Linux 1.3.28.)
GIO_SCRNMAP
Obtenir la table de mappage d'écran du noyau. argp pointe vers une zone de taille E_TABSZ, qui est chargée avec les positions de police utilisées pour afficher chaque caractère. Cet appel est susceptible de retourner des informations inutilisables si la police actuellement chargée dépasse 256 caractères.
GIO_UNISCRNMAP
Obtenir le mappage complet de l'écran Unicode du noyau. argp pointe vers une zone de taille E_TABSZ*sizeof(unsigned short), qui est chargée avec les Unicodes que chaque caractère représente. Un ensemble spécial d'Unicodes, commençant à U+F000, est utilisé pour représenter les mappages "directement dans la police". (Depuis Linux 1.3.1.)
PIO_SCRNMAP
Charge la table "définissable par l'utilisateur" (quatrième) dans le noyau qui mappe les octets aux symboles de l'écran de la console. argp pointe vers une zone de taille E_TABSZ.

NOM

ioctl_keyboard - contrôle du clavier Linux

SYNOPSIS

#include <linux/kd.h>
#include <linux/major.h>

int ioctl(int fd, unsigned long request, ...);

DESCRIPTION

Le périphérique de console Linux (généralement /dev/console, /dev/tty0, /dev/ttyN pour N=1,2,...) supporte une série de requêtes ioctl pour contrôler son comportement. Ce manuel décrit les requêtes relatives au clavier.

PIO_UNISCRNMAP
Charge la table « définissable par l'utilisateur » (quatrième) dans le noyau qui mappe les octets en Unicodes, lesquels sont ensuite traduits en symboles d'écran selon la carte de mappage Unicode-vers-police actuellement chargée. Des Unicodes spéciaux commençant à U+F000 peuvent être utilisés pour mapper directement aux symboles de la police. (Depuis Linux 1.3.1.)
GIO_UNIMAP
Obtenir le mappage Unicode-vers-police du noyau. argp pointe vers une

struct unimapdesc {
    unsigned short  entry_ct;
    struct unipair *entries;
};

où entries pointe vers un tableau de

struct unipair {
    unsigned short unicode;
    unsigned short fontpos;
};

(Depuis Linux 1.1.92.)
PIO_UNIMAP
Placer le mappage unicode-vers-police dans le noyau. argp pointe vers une struct unimapdesc. (Depuis Linux 1.1.92)
PIO_UNIMAPCLR
Effacer la table, éventuellement en conseillant un algorithme de hachage. argp pointe vers une

struct unimapinit {
    unsigned short advised_hashsize;  /* 0 si pas d'avis */
    unsigned short advised_hashstep;  /* 0 si pas d'avis */
    unsigned short advised_hashlevel; /* 0 si pas d'avis */
};

(Depuis Linux 1.1.92.)
KDGKBMODE
Obtenir le mode actuel du clavier. argp pointe vers un long qui est défini à l'une des valeurs suivantes :
K_RAW 0x00 /* Mode scancode brut */
K_XLATE 0x01 /* Traduction des codes de touches à l'aide de la table des touches */
K_MEDIUMRAW 0x02 /* Mode scancode intermédiaire brut */
K_UNICODE 0x03 /* Mode Unicode */
K_OFF 0x04 /* Mode désactivé (depuis Linux 2.6.39) */
KDSKBMODE
Définir le mode actuel du clavier. argp est un long égal à l'une des valeurs indiquées pour KDGKBMODE.
KDGKBMETA
Obtenir le mode de gestion de la touche META. argp pointe vers un long qui est défini à l'une des valeurs suivantes :
K_METABIT 0x03 définir le bit de poids fort
K_ESCPREFIX 0x04 préfixe d'échappement
KDSKBMETA
Définir le mode de gestion de la touche META. argp est un long égal à l'une des valeurs indiquées ci-dessus pour KDGKBMETA.
KDGKBENT
Obtenir une entrée dans la table de traduction des touches (code de touche vers code d'action). argp pointe vers une

struct kbentry {
    unsigned char  kb_table;
    unsigned char  kb_index;
    unsigned short kb_value;
};

avec les deux premiers membres remplis : kb_table sélectionne la table de touches (0 <= kb_table < MAX_NR_KEYMAPS), et kb_index est le code de touche (0 <= kb_index < NR_KEYS). kb_value est défini au code d'action correspondant, ou K_HOLE s'il n'y a pas de telle touche, ou K_NOSUCHMAP si kb_table est invalide.
KDSKBENT
Définir une entrée dans la table de traduction. argp pointe vers une struct kbentry.
KDGKBSENT
Obtenir une chaîne de touche de fonction. argp pointe vers une

struct kbsentry {
    unsigned char kb_func;
    unsigned char kb_string[512];
};

kb_string est défini à la chaîne (terminée par null) correspondant au code d'action de la kb_func-ième touche de fonction.
KDSKBSENT
Définir une entrée de chaîne de touche de fonction. argp pointe vers une struct kbsentry.
KDGKBDIACR
Lire la table des caractères diacritiques du noyau. argp pointe vers une

struct kbdiacrs {
    unsigned int   kb_cnt;
    struct kbdiacr kbdiacr[256];
};

où kb_cnt est le nombre d'entrées dans le tableau, chacune étant une

struct kbdiacr {
    unsigned char diacr;
    unsigned char base;
    unsigned char result;
};

KDGETKEYCODE
Lire une entrée de la table des codes de touches du noyau (scan code vers code de touche). argp pointe vers une

struct kbkeycode {
    unsigned int scancode;
    unsigned int keycode;
};

keycode est défini pour correspondre au scancode donné. (Seulement 89 <= scancode <= 255. Pour 1 <= scancode <= 88, keycode==scancode.) (Depuis Linux 1.1.63.)
KDSETKEYCODE
Écrire une entrée de la table des codes de touches du noyau. argp pointe vers une struct kbkeycode. (Depuis Linux 1.1.63.)
KDSIGACCEPT
Le processus appelant indique sa volonté d'accepter le signal argp lorsqu'il est généré en appuyant sur une combinaison de touches appropriée. (1 <= argp <= NSIG). (Voir spawn_console() dans linux/drivers/char/keyboard.c.)

VALEUR RENVOYÉE

En cas de succès, 0 est renvoyé (sauf indication contraire). En cas d'échec, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EINVAL
argp est invalide.

STANDARDS

Linux.

VOIR AUSSI
