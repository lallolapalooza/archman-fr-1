ioctl_kd(2) Manuel des appels système ioctl_kd(2)

NOM

ioctl_kd - ioctls pour terminaux console et consoles virtuelles

SYNTAXE

#include <linux/kd.h>  /* Définition des constantes d'opération */
#include <sys/ioctl.h>
int ioctl(int fd, unsigned long op, void *argp);

DESCRIPTION

Les opérations ioctl(2) suivantes, spécifiques à Linux, sont supportées pour les terminaux console et les consoles virtuelles.

KDGETLED
Obtenir l'état des LEDs. argp pointe vers un char. Les trois bits de poids faible de *argp sont réglés sur l'état des LEDs, comme suit :
LED_CAP 0x04 LED du verrouillage majuscule (Caps Lock)
LED_NUM 0x02 LED du verrouillage numérique (Num Lock)
LED_SCR 0x01 LED du défilement (Scroll Lock)
KDSETLED
Régler les LEDs. Les LEDs sont réglées pour correspondre aux trois bits de poids faible de l'entier non signé argp. Cependant, si un bit de poids fort est positionné, les LEDs reviennent à la normale : affichant l'état des fonctions du clavier du verrouillage majuscule, du verrouillage numérique et du défilement.

Avant Linux 1.1.54, les LEDs reflétaient simplement l'état des indicateurs correspondants du clavier, et KDGETLED/KDSETLED changeaient également les indicateurs du clavier. Depuis Linux 1.1.54, les LEDs peuvent afficher des informations arbitraires, mais par défaut, elles affichent les indicateurs du clavier. Les deux ioctls suivants sont utilisés pour accéder aux indicateurs du clavier.

KDGKBLED
Obtenir les indicateurs du clavier CapsLock, NumLock, ScrollLock (pas les lumières). argp pointe vers un caractère qui est réglé sur l'état de l'indicateur. Les trois bits de poids faible (masque 0x7) obtiennent l'état actuel de l'indicateur, et les bits de poids faible du nibble suivant (masque 0x70) obtiennent l'état par défaut de l'indicateur. (Depuis Linux 1.1.54.)
KDSKBLED
Régler les indicateurs du clavier CapsLock, NumLock, ScrollLock (pas les lumières). argp est un entier non signé qui contient l'état désiré de l'indicateur. Les trois bits de poids faible (masque 0x7) ont l'état de l'indicateur, et les bits de poids faible du nibble suivant (masque 0x70) ont l'état par défaut de l'indicateur. (Depuis Linux 1.1.54.)
KDGKBTYPE
Obtenir le type de clavier. Retourne la valeur KB_101, définie comme 0x02.
KDADDIO
Ajouter un port d'E/S comme valide. Équivalent à ioperm(arg,1,1).
KDDELIO
Supprimer un port d'E/S comme valide. Équivalent à ioperm(arg,1,0).
KDENABIO
Activer les E/S vers la carte vidéo. Équivalent à ioperm(0x3b4, 0x3df-0x3b4+1, 1).
KDDISABIO
Désactiver les E/S vers la carte vidéo. Équivalent à ioperm(0x3b4, 0x3df-0x3b4+1, 0).
KDSETMODE
Définir le mode texte/graphique. argp est un entier non signé contenant l'une des valeurs suivantes :
KD_TEXT 0x00
KD_GRAPHICS 0x01
KDGETMODE
Obtenir le mode texte/graphique. argp pointe vers un int qui est réglé sur l'une des valeurs indiquées ci-dessus pour KDSETMODE.
KDMKTONE
Générer une tonalité d'une durée spécifiée. Les 16 bits de poids faible de l'entier non signé argp spécifient la période en cycles d'horloge, et les 16 bits de poids fort donnent la durée en millisecondes. Si la durée est de zéro, le son est désactivé. Le contrôle retourne immédiatement. Par exemple, argp = (125<<16) + 0x637 spécifierait le bip normalement associé à un Ctrl-G. (Donc, depuis Linux 0.99pl1 ; bugué dans Linux 2.1.49-50.)
KIOCSOUND
Démarrer ou arrêter la génération du son. Les 16 bits de poids faible de argp spécifient la période en cycles d'horloge (c'est-à-dire, argp = 1193180/fréquence). argp = 0 désactive le son. Dans tous les cas, le contrôle retourne immédiatement.
GIO_CMAP
Obtenir la carte de couleurs par défaut actuelle du noyau. argp pointe vers un tableau de 48 octets. (Depuis Linux 1.3.3.)
PIO_CMAP
Changer la carte de couleurs par défaut en mode texte. argp pointe vers un tableau de 48 octets qui contient, dans l'ordre, les valeurs Rouge, Vert et Bleu pour les 16 couleurs d'écran disponibles : 0 est éteint, et 255 est intensité maximale. Les couleurs par défaut sont, dans l'ordre : noir, rouge sombre, vert sombre, marron, bleu sombre, violet sombre, cyan sombre, gris clair, gris sombre, rouge vif, vert vif, jaune, bleu vif, violet vif, cyan vif et blanc. (Depuis Linux 1.3.3.)
GIO_FONT
Obtient une police d'écran de 256 caractères sous forme étendue. argp pointe vers un tableau de 8192 octets. Échoue avec le code d'erreur EINVAL si la police actuellement chargée est une police de 512 caractères, ou si la console n'est pas en mode texte.
GIO_FONTX
Obtient la police d'écran et les informations associées. argp pointe vers une struct consolefontdesc (voir PIO_FONTX). Lors de l'appel, le champ charcount doit être réglé sur le nombre maximum de caractères qui tiendraient dans le tampon pointé par chardata. Au retour, charcount et charheight sont remplis avec les données respectives pour la police actuellement chargée, et le tableau chardata contient les données de la police si la valeur initiale de charcount indiquait qu'assez d'espace était disponible ; sinon, le tampon reste inchangé et errno est réglé sur ENOMEM. (Depuis Linux 1.3.1.)
PIO_FONT
Définit une police d'écran de 256 caractères. Charge la police dans le générateur de caractères EGA/VGA. argp pointe vers une carte de 8192 octets, avec 32 octets par caractère. Seuls les N premiers sont utilisés pour une police de 8xN (0 < N <= 32). Cet appel invalide également le mappage Unicode.
PIO_FONTX
Définit la police d'écran et les informations de rendu associées. argp pointe vers une

struct consolefontdesc {
    unsigned short charcount;  /* nombre de caractères dans la police
                                  (256 ou 512) */
    unsigned short charheight; /* lignes de balayage par
                                  caractère (1-32) */
    char          *chardata;   /* données de la police sous
                                  forme étendue */
};

Si nécessaire, l'écran sera redimensionné de manière appropriée, et SIGWINCH sera envoyé aux processus appropriés. Cet appel invalide également le mappage Unicode. (Depuis Linux 1.3.1.)
PIO_FONTRESET
Réinitialise la police d'écran, la taille et le mappage Unicode aux valeurs par défaut du démarrage. argp n'est pas utilisé, mais doit être réglé sur NULL pour assurer la compatibilité avec les futures versions de Linux. (Depuis Linux 1.3.28.)
GIO_SCRNMAP
Obtient la carte d'écran du noyau. argp pointe vers une zone de taille E_TABSZ, qui est chargée avec les positions de police utilisées pour afficher chaque caractère. Cet appel est susceptible de retourner des informations inutiles si la police actuellement chargée contient plus de 256 caractères.
GIO_UNISCRNMAP
Obtient la carte d'écran Unicode complète du noyau. argp pointe vers une zone de taille E_TABSZ*sizeof(unsigned short), qui est chargée avec les Unicodes que chaque caractère représente. Un ensemble spécial d'Unicodes, commençant à U+F000, est utilisé pour représenter les mappages "direct vers la police". (Depuis Linux 1.3.1.)
PIO_SCRNMAP
Charge la table "définissable par l'utilisateur" (la quatrième) dans le noyau, qui mappe les octets vers les symboles d'écran de la console. argp pointe vers une zone de taille E_TABSZ.

NOM

PIO_UNISCRNMAP, GIO_UNIMAP, PIO_UNIMAP, PIO_UNIMAPCLR, KDGKBMODE, KDSKBMODE, KDGKBMETA, KDSKBMETA, KDGKBENT, KDSKBENT, KDGKBSENT, KDSKBSENT, KDGKBDIACR, KDGETKEYCODE, KDSETKEYCODE, KDSIGACCEPT - contrôles de terminal console Linux

SYNTAXIS

#include <sys/ioctl.h>
#include <linux/kd.h>

int ioctl(int fd, int request, ...);

DESCRIPTION

Ces appels système modifient ou interrogent la configuration du clavier et de la console du noyau Linux.

PIO_UNISCRNMAP
Charge la table (la quatrième) "définissable par l'utilisateur" dans le noyau, qui mappe les octets en Unicodes, lesquels sont ensuite traduits en symboles d'écran conformément à la carte Unicode vers police actuellement chargée. Des Unicodes spéciaux commençant à U+F000 peuvent être utilisés pour mapper directement vers les symboles de police. (Depuis Linux 1.3.1.)
GIO_UNIMAP
Obtient le mappage Unicode vers police depuis le noyau. argp pointe vers une

struct unimapdesc {
    unsigned short  entry_ct;
    struct unipair *entries;
};

où entries pointe vers un tableau de

struct unipair {
    unsigned short unicode;
    unsigned short fontpos;
};

(Depuis Linux 1.1.92.)
PIO_UNIMAP
Place le mappage Unicode vers police dans le noyau. argp pointe vers une struct unimapdesc. (Depuis Linux 1.1.92)
PIO_UNIMAPCLR
Efface la table, éventuellement en conseillant l'algorithme de hachage. argp pointe vers une

struct unimapinit {
    unsigned short advised_hashsize;  /* 0 si pas d'avis */
    unsigned short advised_hashstep;  /* 0 si pas d'avis */
    unsigned short advised_hashlevel; /* 0 si pas d'avis */
};

(Depuis Linux 1.1.92.)
KDGKBMODE
Obtient le mode actuel du clavier. argp pointe vers un long qui est défini à l'une des valeurs suivantes :
K_RAW 0x00 /* Mode brut (scancode) */
K_XLATE 0x01 /* Traduire les codes de touches en utilisant la table de clavier */
K_MEDIUMRAW 0x02 /* Mode moyen brut (scancode) */
K_UNICODE 0x03 /* Mode Unicode */
K_OFF 0x04 /* Mode désactivé (depuis Linux 2.6.39) */
KDSKBMODE
Définit le mode actuel du clavier. argp est un long égal à l'une des valeurs indiquées pour KDGKBMODE.
KDGKBMETA
Obtient le mode de gestion de la touche meta. argp pointe vers un long qui est défini à l'une des valeurs suivantes :
K_METABIT 0x03 définir le bit de poids fort
K_ESCPREFIX 0x04 préfixe d'échappement
KDSKBMETA
Définit le mode de gestion de la touche meta. argp est un long égal à l'une des valeurs indiquées ci-dessus pour KDGKBMETA.
KDGKBENT
Obtient une entrée dans la table de traduction des touches (code de touche vers code d'action). argp pointe vers une

struct kbentry {
    unsigned char  kb_table;
    unsigned char  kb_index;
    unsigned short kb_value;
};

avec les deux premiers membres remplis : kb_table sélectionne la table de touches (0 <= kb_table < MAX_NR_KEYMAPS), et kb_index est le code de touche (0 <= kb_index < NR_KEYS). kb_value est défini au code d'action correspondant, ou K_HOLE s'il n'y a pas de telle touche, ou K_NOSUCHMAP si kb_table est invalide.
KDSKBENT
Définit une entrée dans la table de traduction. argp pointe vers une struct kbentry.
KDGKBSENT
Obtient une chaîne de touche fonctionnelle. argp pointe vers une

struct kbsentry {
    unsigned char kb_func;
    unsigned char kb_string[512];
};

kb_string est défini comme la chaîne (terminée par un nul) correspondant au code d'action de touche fonctionnelle kb_func.
KDSKBSENT
Définit une entrée de chaîne de touche fonctionnelle. argp pointe vers une struct kbsentry.
KDGKBDIACR
Lit la table d'accents du noyau. argp pointe vers une

struct kbdiacrs {
    unsigned int   kb_cnt;
    struct kbdiacr kbdiacr[256];
};

où kb_cnt est le nombre d'entrées dans le tableau, chacune étant une

struct kbdiacr {
    unsigned char diacr;
    unsigned char base;
    unsigned char result;
};

KDGETKEYCODE
Lit une entrée de la table des codes de touches du noyau (code de scan vers code de touche). argp pointe vers une

struct kbkeycode {
    unsigned int scancode;
    unsigned int keycode;
};

keycode est défini pour correspondre au scancode donné. (Seulement 89 <= scancode <= 255. Pour 1 <= scancode <= 88, keycode==scancode.) (Depuis Linux 1.1.63.)
KDSETKEYCODE
Écrit une entrée dans la table des codes de touches du noyau. argp pointe vers une struct kbkeycode. (Depuis Linux 1.1.63.)
KDSIGACCEPT
Le processus appelant indique sa volonté d'accepter le signal argp lorsqu'il est généré en appuyant sur une combinaison de touches appropriée. (1 <= argp <= NSIG). (Voir spawn_console() dans linux/drivers/char/keyboard.c.)

VALEUR DE RETOUR

En cas de succès, 0 est retourné (sauf indication contraire). En cas d'échec, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EINVAL
argp est invalide.

NORMES

Linux.

VOIR AUSSI

ioctl(2), ioctl_console(2)
