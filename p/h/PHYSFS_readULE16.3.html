Documentation de la structure

typedef struct PHYSFS_Version

Représente une version de la bibliothèque PhysicsFS. Ce type est utilisé par PHYSFS_getLinkedVersion() et PHYSFS_init() pour spécifier la version de la bibliothèque.

Vous pouvez vérifier la version de la bibliothèque compilée avec votre application en comparant les membres de cette structure avec ceux de la macro PHYSFS_VERSION. Ceci est déterminé par l'en-tête que le compilateur utilise. Notez que si vous avez lié dynamiquement la bibliothèque, vous pourriez avoir une version légèrement plus récente ou plus ancienne à l'exécution. Cette version peut être déterminée avec PHYSFS_getLinkedVersion(), qui, contrairement à PHYSFS_VERSION, n'est pas une macro.

Paramètres

x Un pointeur vers une structure PHYSFS_Version à initialiser.

PHYSFS_EnumerateCallback

PHYSFS_enumerate

C'est la même chose que PHYSFS_EnumFilesCallback de PhysicsFS 2.0, sauf qu'il peut retourner un résultat du rappel : à savoir : si vous recherchez quelque chose de spécifique, une fois que vous l'avez trouvé, vous pouvez dire à PhysicsFS d'arrêter d'énumérer davantage. Ceci est utilisé avec PHYSFS_enumerate(), que nous espérons avoir bien fait cette fois-ci. :)

Paramètres

data Pointeur de données défini par l'utilisateur, transmis par l'API qui a finalement appelé le rappel.
origdir Une chaîne contenant le chemin complet, en notation indépendante de la plateforme, du répertoire contenant ce fichier. Dans la plupart des cas, il s'agit du répertoire sur lequel vous avez demandé l'énumération, transmis dans le rappel pour votre commodité.
fname Le nom du fichier qui est énuméré. Il peut ne pas être dans un ordre alphabétique par rapport à d'autres rappels qui ont été déclenchés, et il ne conterra pas le chemin complet. Vous pouvez recréer le chemin complet avec $origdir/$fname ... Le fichier peut être un sous-répertoire, un fichier, un lien symbolique, etc.

Retours

Une valeur de PHYSFS_EnumerateCallbackResult. Toutes les autres valeurs sont (actuellement) indéfinies ; ne les utilisez pas.

typedef void(* physfs_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Signature de fonction pour les rappels qui énumèrent les fichiers.

Avertissement

Depuis PhysicsFS 2.1, utilisez PHYSFS_EnumerateCallback avec PHYSFS_enumerate() à la place ; cela vous donne plus de contrôle sur le processus.

Ils sont utilisés pour rapporter une liste d'entrées de répertoire à un appelant d'origine, un fichier/répertoire/lien symbolique par rappel. Toutes les chaînes sont encodées en UTF-8. Les fonctions ne doivent pas essayer de modifier ou de libérer la mémoire d'une chaîne.

Ces rappels sont utilisés, à partir de PhysicsFS 1.1, comme une alternative aux fonctions qui retournaient des listes qui devaient être nettoyées avec PHYSFS_freeList(). Le rappel signifie que la bibliothèque n'a pas besoin d'allouer une liste entière et toutes les chaînes à l'avance.

Soyez conscient que l'ordre des données promis dans les versions de liste n'est pas nécessairement le cas dans les versions de rappel. Consultez la documentation des API spécifiques, mais les chaînes peuvent ne pas être triées comme vous l'attendez et vous pourriez obtenir des chaînes dupliquées.

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Obtenir une liste de fichiers d'un répertoire de chemin de recherche, en utilisant une fonction de rappel définie par l'application, avec des erreurs rapportées. En interne, PHYSFS_enumerateFiles() n'appelle que cette fonction, puis construit une liste avant de la renvoyer à l'application, donc la fonctionnalité est identique, à l'exception de la manière dont les informations sont présentées à l'application.

Différent de PHYSFS_enumerateFiles(), cette fonction ne renvoie pas un tableau. Au lieu de cela, elle appelle une fonction spécifiée par l'application une fois pour chaque élément du chemin de recherche :

static physfs_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * Nous avons obtenu [%s] dans [%s].\n", fname, origdir);
    return PHYSfs_ENUM_OK;  // Donnez-moi plus de données, s'il vous plaît.
}
// ...
PHYSFS_enumerate("/some/path", printDir, NULL);

Les éléments envoyés à la fonction de rappel ne sont garantis dans aucun ordre particulier. Aucun tri n'est effectué à ce niveau, et si vous en avez besoin, vous devriez utiliser PHYSFS_enumerateFiles(), qui garantit le tri alphabétique. Cette forme signale ce qui se trouve dans chaque archive avant de passer à la suivante. Même au sein d'une seule archive, nous ne pouvons pas garantir l'ordre dans lequel les données sont découvertes. Tout ordre que vous trouverez dans ces fonctions de rappel est purement le fruit du hasard. Ne comptez pas dessus. Comme cela parcourt toutes les archives, vous pourriez recevoir des noms de fichiers dupliqués.

Cette API et les fonctions de rappel elles-mêmes peuvent signaler des erreurs. Avant cette API, les fonctions de rappel devaient accepter chaque élément énuméré, même si elles ne recherchaient qu'un objet spécifique et voulaient s'arrêter là, ou si elles avaient une erreur grave et ne pouvaient en alerter personne. De plus, si PhysicsFS lui-même avait un problème (erreur de disque ou autre), il ne pourrait pas le signaler à l'application, il ignorerait simplement les éléments ou arrêterait l'énumération, et l'appelant ne saurait pas qu'il a perdu des données en cours de route.

Maintenant, l'appelant peut être assuré qu'il a obtenu un ensemble complet de données, et si cela lui convient, sa fonction de rappel a le contrôle sur l'arrêt anticipé de l'énumération. Voir la documentation de PHYSFS_EnumerateCallback pour les détails sur le comportement attendu de votre fonction de rappel.

c Fonction de rappel pour être notifié des éléments du chemin de recherche.
d Données définies par l'application transmises à la fonction de rappel. Peut être NULL.

Retourne

Non nul en cas de succès, zéro en cas d'échec. Utilisez PHYSFS_getLastErrorCode() pour obtenir l'erreur spécifique. Les fonctions de rappel renvoyant PHYSFS_ENUM_ERROR feront en sorte que cette fonction renvoie zéro et définissent le code d'erreur sur PHYSFS_ERR_APP_CALLBACK.

char **rc = PHYSFS_enumerateFiles("savegames");
char **i;
for (i = rc; *i != NULL; i++)
    printf(" * Nous avons obtenu [%s].\n", *i);
PHYSFS_freeList(rc);
* Nous avons obtenu [x.sav].
* Nous avons obtenu [y.sav].
* Nous avons obtenu [z.sav].
* Nous avons obtenu [w.sav]..fi

void PHYSFS_permitSymbolicLinks (int allow)

Permet d'activer ou de désactiver le suivi des liens symboliques. Certains systèmes de fichiers physiques et architectures contiennent des fichiers qui ne sont que des pointeurs vers d'autres fichiers. L'ouverture d'un lien symbolique sur un système de fichiers physique ouvrira de manière transparente le fichier auquel il pointe.

Par défaut, PhysicsFS vérifiera si un fichier est réellement un lien symbolique lors des appels d'ouverture et échouera si c'est le cas. Sinon, le lien pourrait vous faire sortir des chemins de lecture et d'écriture, compromettant ainsi la sécurité.

Si vous souhaitez prendre ce risque, appelez cette fonction avec une valeur non nulle. Notez que cela vise davantage à limiter le langage de script d'un programme, au cas où des scripts non fiables tenteraient de compromettre le système. Les liens symboliques ne seront explicitement vus que lorsque des noms de fichiers seront traités dans une notation indépendante de la plateforme. C'est-à-dire que lorsque vos chemins de recherche et d'écriture, etc., sont définis, les liens symboliques ne seront jamais vus.

allow non nul pour autoriser les liens symboliques, zéro pour désactiver le lien.

int PHYSFS_setRoot (const char * archive, const char * subdir)

Make a subdirectory of an archive its root directory. This lets you narrow down the accessible files in a specific archive. For example, if you have x.zip with a file in y/z.txt, mounted to /a, if you call PHYSFS_setRoot("x.zip", "/y"), then the call PHYSFS_openRead("/a/z.txt") will succeed.

Detailed Description

Ces fonctions sont des fonctions utilitaires pour lire et écrire des entiers sur des flux de données, en assurant que l'ordre des octets est correct (big-endian ou little-endian) indépendamment de l'ordre des octets natif de la plate-forme. Elles sont particulièrement utiles pour lire et écrire des fichiers de format qui spécifient un ordre d'octets particulier, comme des formats de fichiers d'image, d'audio ou d'autres types de données.

Les fonctions de lecture renvoient la valeur lue. Les fonctions d'écriture renvoient un entier non nul en cas de succès et zéro en cas d'échec. En cas d'échec, vous pouvez obtenir la raison de l'échec à l'aide de PHYSFS_getLastErrorCode().
