PHYSFS_EnumerateCallbackResult typedef void(* PHYSFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname) Signature de fonction pour les callbacks qui énumèrent des fichiers. Avertissement À partir de PhysicsFS 2.1, utilisez
PHYSFS_EnumerateCallback avec PHYSFS_enumerate() à la place ; cela vous donne plus de contrôle sur le processus.
Ces callbacks sont utilisés pour signaler une liste d'entrées de répertoire à un appelant original, un fichier/répertoire/lien symbolique par callback. Toutes les chaînes sont encodées en UTF-8. Les fonctions ne doivent pas essayer de modifier ou de libérer la mémoire de n'importe quelle chaîne. Ces callbacks sont utilisés, à partir de PhysicsFS 1.1, comme une alternative aux fonctions qui retourneraient des listes à nettoyer avec
PHYSFS_freeList() . Le callback signifie que la bibliothèque n'a pas besoin d'allouer toute la liste et toutes les chaînes d'avance. Soyez conscient que l'ordre des données promis dans les versions de liste n'est pas nécessairement le même dans les versions de callback. Vérifiez la documentation des APIs spécifiques, mais les chaînes peuvent ne pas être triées comme vous l'attendez et vous pouvez obtenir des chaînes en double.

Cela permet aux archives d'être utilisées pour remplacer les révisions précédentes ; vous pouvez utiliser le mécanisme de montage pour placer des archives à un point spécifique dans l'arbre de fichiers et empêcher les chevauchements ; cela est utile pour les mods téléchargeables qui pourraient écraser les données de l'application ou les uns les autres, par

exemple.

Le point de montage n'a pas besoin d'exister avant le montage, ce qui est différent de ce que ceux familiers avec le concept Unix de "montage" pourraient s'attendre. De plus, plus d'un archive peut être monté sur le même point de montage, ou les points de montage et le contenu des archives peuvent chevaucher... le mécanisme

Active ou désactive le suivi des liens symboliques. Certains systèmes de fichiers physiques et archives contiennent des fichiers qui sont juste des pointeurs vers d'autres fichiers. Sur le système de fichiers physique, l'ouverture d'un tel lien ouvrira (de manière transparente) le fichier qui est pointé. Par défaut, PhysicsFS vérifiera si un fichier est vraiment un lien symbolique lors des appels d'ouverture et échouera s'il l'est. spécifique en leur permettant, vous devriez les permettre.
