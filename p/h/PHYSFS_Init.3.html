Signature des fonctions qui énumèrent des fichiers.

Note

Depuis PhysicsFS 2.1, utilisez PHYSFS_EnumerateCallback avec PHYSFS_enumerate() pour un contrôle accru sur le processus.

Ceux-ci sont utilisés pour rapporter une liste d'entrées de répertoire à un appelant d'origine, une entrée par callback. Toutes les chaînes sont encodées en UTF-8. Les fonctions ne doivent pas tenter de modifier ou de libérer la mémoire des chaînes.

Veuillez noter que le tri promis dans les versions de liste n'est pas nécessairement respecté dans les versions de callback. Consultez la documentation spécifique des API, mais les chaînes peuvent ne pas être triées comme vous vous y attendez et vous pourriez obtenir des chaînes dupliquées.

int PHYSFS_caseFold(const PHYSFS_uint32 from, PHYSFS_uint32 * to)

"Plie" un point de code Unicode vers un équivalent en minuscules. (Ceci est pour un usage limité et très pointu. Si vous ne voyez pas immédiatement un besoin pour cela, vous pouvez probablement ignorer cette fonction pour toujours.)

Ceci convertira un point de code Unicode en son équivalent en minuscules. Les points de code invalides et ceux sans équivalent en minuscules seront retournés sans conversion.

Notez que vous pourriez obtenir plusieurs points de code en retour ! L'Eszett allemand, par exemple, sera plié en deux points de code latins 's' en minuscules. La théorie est que si vous pliez deux chaînes, l'une avec un Eszett et l'autre avec "SS", elles correspondront.

Attention

Quiconque a étudié Unicode connaît le problème du "I turc". Cette API ne le gère pas. Supposons que cette unique lettre dans tout Unicode sera pliée de manière un peu incorrecte. Si vous ne savez pas de quoi il s'agit, vous pouvez probablement ignorer ce problème pour la majeure partie de la planète, mais la perfection est impossible.

Paramètres

from Le point de code à plier.
to Tampon pour stocker les valeurs des points de code pliés. Ceci doit pointer vers de l'espace pour au moins 3 emplacements de PHYSFS_uint32.

Retourne

Le nombre de points de code produits par le pliage. Entre 1 et 3.

int PHYSFS_deinit(void )

Désinitialise la bibliothèque PhysicsFS. Ceci ferme tous les fichiers ouverts via PhysicsFS, efface les chemins de recherche/écriture, libère la mémoire et invalide toutes vos poignées de fichier.

Notez que cet appel peut ÉCHOIR s'il y a un fichier ouvert en écriture qui refuse de se fermer (par exemple, le système d'exploitation sous-jacent mettait en mémoire tampon les écritures sur un système de fichiers réseau, et le serveur de fichiers a planté, ou un disque dur a échoué, etc.). Il est généralement préférable de fermer vous-même toutes les poignées d'écriture avant d'appeler cette fonction, afin de pouvoir gérer gracieusement une défaillance spécifique.

Une fois désinitialisé avec succès, PHYSFS_init() peut être appelé à nouveau pour redémarrer le sous-système. Tous les états par défaut de l'API sont restaurés à ce stade, à l'exception de tout allocateur personnalisé que vous auriez pu spécifier, qui survit entre les initialisations.

Retourne

une valeur non nulle en cas de succès, zéro en cas d'erreur. Les détails de l'erreur peuvent être obtenus à partir de PHYSFS_getLastError(). En cas d'échec, l'état de PhysFS est indéfini, et probablement gravement endommagé.

int PHYSFS_delete(const char * filename)

Supprime un fichier ou un répertoire. (filename) est spécifié en notation indépendante de la plateforme par rapport au répertoire d'écriture.

Un répertoire doit être vide avant que cet appel puisse le supprimer.

La suppression d'un lien symbolique supprimera le lien, pas ce à quoi il pointe, que vous ayez ou non activé "permitSymLinks".

Donc, si vous avez défini le répertoire d'écriture sur "C:\mygame\writedir" et que vous appelez PHYSFS_delete("downloads/maps/level1.map"), alors le fichier "C:\mygame\writedir\downloads\maps\level1.map" est supprimé du système de fichiers physique, s'il existe et si le système d'exploitation autorise la suppression.

Notez que sur les systèmes Unix, la suppression d'un fichier peut réussir, mais le fichier réel ne sera pas supprimé tant que tous les processus qui ont une poignée de fichier ouverte dessus (y compris votre programme) ne l'auront pas fermée.

Il y a de fortes chances que les bits qui composent le fichier existent encore, ils sont simplement rendus disponibles pour être écrasés plus tard. Ne considérez pas cela comme une méthode de sécurité ou quoi que ce soit. :)

Paramètres

filename Nom du fichier à supprimer.

Retourne

une valeur non nulle en cas de succès, zéro en cas d'erreur. Utilisez PHYSFS_getLastErrorCode() pour obtenir l'erreur spécifique.

int PHYSFS_deregisterArchiver(const char * ext)

Supprime un archiveur du système. Si, pour une raison quelconque, vous ne souhaitez que votre archiveur précédemment enregistré soit actif que pendant une partie de la durée de vie de votre application, vous pouvez le retirer du système une fois que vous avez terminé avec lui via cette fonction.

Cela échoue s'il reste des archives ouvertes qui utilisent cet archiveur.

Cette fonction peut également supprimer les archiveurs fournis en interne, comme le support .zip ou autre. Cela pourrait être utile dans certaines situations, comme désactiver complètement leur support ou les remplacer par votre propre implémentation. Une fois qu'un archiveur interne est désactivé de cette manière, PhysicsFS ne fournit aucun mécanisme pour les récupérer, à moins d'appeler PHYSFS_deinit() et PHYSFS_init() à nouveau.

int PHYSFS_mount (const char * newDir, const char * mountPoint, int appendToPath)

Ajoute un archive ou un répertoire au chemin de recherche. S'il s'agit d'un doublon, l'entrée ne sera pas ajoutée, bien que la fonction réussisse. Vous ne pouvez pas ajouter le même archive à deux points de montage différents : la vérification des doublons se fait par rapport à l'archive et non par rapport au point de montage.

Lors du montage d'un archive, celui-ci est ajouté à un système de fichiers virtuel... tous les fichiers de tous les archives sont entrelacés dans un arbre de répertoires unique. Deux archives montés au même endroit (ou un archive avec des fichiers qui se superposent à un autre point de montage) peuvent avoir des fichiers qui se superposent : dans ce cas, le fichier le plus précoce dans le chemin de recherche est sélectionné, et les autres fichiers ne sont pas accessibles au programme. void PHYSFS_permitSymbolicLinks (int allow)

Enables or disables the following of symbolic links. Some physical and archive filesystems contain files that are simply pointers to other files. When opening a symbolic link on a physical filesystem, it will transparently open the file it refers to.

By default, PhysicsFS checks if a file is actually a symbolic link during open calls and fails if it is. Otherwise, the link could point outside of the read/write paths, compromising security.

If you wish to take that risk, call this function with a non-zero value. Note that this is mostly for sandboxing a program's scripting language, in case untrusted scripts try to compromise the system. Generally, a user might have a legitimate reason to set up a symbolic link, so you shouldn't disable it unless you feel there is specific danger.

Symbolic links are only checked when dealing with platform-independent notation filenames. That is, when setting up your search and write paths, etc., symbolic links are never checked.

Note: PHYSFS_stat() always follows the specified path; if that path is a symbolic link, it will not be followed in any case. If not permitted through this function, PHYSFS_stat() ignores symbolic links and would treat the query as if the path did not exist.

Symbolic link permissibility can be enabled or disabled at any time after you have called PHYSFS_init(), and it is disabled by default.

Parameters

allow non-zero to permit symbolic links, zero to disallow linking.

Fait d'un sous-répertoire d'une archive son répertoire racine. Cela vous permet de réduire les fichiers accessibles dans une archive spécifique. void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

Convert a UTF-8 string to a Latin1 string. Latin1 strings are 8-bits per character: a popular "high ASCII" encoding.

To ensure that the destination buffer is large enough for the conversion, please allocate a buffer that is double the size of the source buffer. UTF-8 expands latin1 codepoints over 127 from 1 to 2 bytes, so the string may grow in some cases.

Strings that don't fit in the destination buffer will be truncated, but will always be null-terminated and never have an incomplete UTF-8 sequence at the end. If the buffer length is 0, this function does nothing.

Please note that we do not supply a UTF-8 to Latin1 converter, since Latin1 can't express most Unicode codepoints. It's a legacy encoding; you should be converting away from it at all times.

Parameters

src Null-terminated source string in Latin1 format.
dst Buffer to store converted UTF-8 string.
len Size, in bytes, of destination buffer.

Attention

Cette fonction ne signalera pas d'erreur s'il y a des séquences UTF-8 invalides dans la chaîne source. Elle les remplacera par un caractère '?' et continuera.
