Description détaillée

Interface abstraite pour fournir un support d'archives personnalisées.

Avertissement

Ceci est un contenu avancé et difficile. Vous n'en avez pas besoin, à moins que vous ne sachiez vraiment ce que vous faites. La plupart des applications n'en auront pas besoin.

Historiquement, PhysicsFS fournissait un moyen de monter divers formats de fichiers d'archives et de répertoires physiques dans le système de fichiers natif. Cependant, les applications étaient limitées aux formats de fichiers fournis par la bibliothèque. Cette interface permet à une application de fournir ses propres types de fichiers d'archives.

Conceptuellement, un PHYSFS_Archiver fournit des entrées de répertoire, tandis que PHYSFS_Io fournit des flux de données pour ces entrées de répertoire. L'utilisation la plus évidente de PHYSFS_Archiver est de fournir un support pour un type de fichier d'archive qui n'est pas directement disponible par PhysicsFS : peut-être un format propriétaire que seule votre application doit comprendre.

En interne, tous les supports d'archives préinstallés utilisent cette interface, donc les meilleurs exemples pour construire un PHYSFS_Archiver sont le code source de PhysicsFS lui-même.

Un archiveur est enregistré auprès du système avec PHYSFS_registerArchiver(), et sera ensuite utilisé automatiquement avec PHYSFS_mount() ; si un fichier donné peut être géré par votre archiveur, il lui sera donné le contrôle approprié.

Ces méthodes gèrent des poignées de répertoire. Vous avez une instance de votre archiveur, et il génère une poignée unique et opaque pour chaque archive ouverte dans sa méthode openArchive(). Comme la durée de vie de l'archiveur (pas d'une archive) est généralement la durée de vie complète du processus, et qu'il est supposé être un singleton, nous ne fournissons aucune donnée d'instance pour l'archiveur lui-même ; vous pouvez utiliser des variables statiques si nécessaire.

Les symboles de liaison doivent toujours être suivis (sauf dans stat()) ; PhysicsFS utilisera la méthode stat() pour vérifier les symboles et prendre une décision quant à la poursuite avec d'autres méthodes en fonction de cela.

Les archiveurs, si nécessaire, doivent définir l'état d'erreur de PhysicsFS avec PHYSFS_setErrorCode() avant de retourner. PhysicsFS transmettra ces erreurs sans déranger l'application dans la plupart des cas.

Sécurité des threads : les implémentations de PHYSFS_Archiver ne sont pas garanties d'être sécurisées pour les threads. PhysicsFS fournit la sécurité des threads lorsqu'il appelle un archiveur donné dans la bibliothèque, mais ne promet pas que l'utilisation du même PHYSFS_File sur deux threads simultanés soit sûre ; par conséquent, votre PHYSFS_Archiver peut supposer que la protection des threads est gérée par vous, à condition que le PHYSFS_Io que vous retournez de PHYSFS_open* ne modifie aucun état de votre archiveur, car le PHYSFS_Io ne sera pas protégé agressivement.

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Détruit une archive précédemment ouverte. Ferme cette archive et libère toute mémoire associée, y compris le PHYSFS_Io original et (opaque) lui-même, si applicable. L'implémentation peut supposer qu'elle ne sera pas appelée s'il reste des fichiers ouverts de cette archive.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Liste tous les fichiers dans (dirname). Chaque fichier est passé à (cb), où une copie est générée si approprié, vous pouvez donc la disposer lors du retour du callback. (dirname) est en notation indépendante de la plateforme. S'il y a une défaillance, appelez PHYSFS_SetErrorCode() avec le code qui semble approprié et retournez PHYSFS_ENUM_ERROR. Si le callback retourne PHYSFS_ENUM_ERROR, appelez PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) et retournez également PHYSFS_ENUM_ERROR. Vous ne devez jamais rappeler le callback dans quelque circonstance que ce soit. Si le callback retourne PHYSFS_ENUM_STOP, arrêtez l'énumération et retournez également PHYSFS_ENUM_STOP. Vous ne devez jamais rappeler le callback dans quelque circonstance que ce soit. N'estableissez pas de code d'erreur dans ce cas. Les callbacks ne retournent qu'une seule valeur à partir de PHYSFS_EnumerateCallbackResult. Tout autre résultat a un comportement indéfini. Tant que le callback retourne PHYSFS_ENUM_OK et que vous n'avez pas rencontré d'erreurs de votre côté, énumérez jusqu'à ce que tout soit terminé, puis retournez PHYSFS_ENUM_OK sans définir de code d'erreur.

Avertissement

PHYSFS_enumerate retourne 0 ou non zéro (succès ou échec), vous devez donc être conscient que ce pointeur de fonction peut retourner des valeurs différentes !

PHYSFS_Archiver::info

Informations de base sur cet archiveur. Ceci est utilisé pour identifier votre archiveur et est retourné par PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crée un répertoire dans l'archive. Si l'application essaie de créer plusieurs répertoires, PhysicsFS les divisera en plusieurs appels avant de les transmettre à votre pilote. Si l'archive est en lecture seule, cette opération doit échouer. Retourne non zéro en cas de succès, zéro en cas d'échec. Ce nom de fichier est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Ouvre un fichier dans cette archive pour y ajouter. Si le fichier n'existe pas, il doit être créé. L'offset d'écriture doit être à la fin du fichier. Si l'archive est en lecture seule, cette opération doit échouer. Ce nom de fichier est en notation indépendante de la plateforme. Retourne NULL en cas d'échec, appelez PHYSFS_setErrorCode(). Retourne non NULL en cas de succès. Le pointeur retourné sera utilisé comme paramètre "opaque" pour les appels de fichiers ultérieurs.

NAME

PHYSFS_Archiver - Structure representing an archive type

SYNOPSIS

In header:
physfs.h

A structure that describes a type of archive and how to manage it. You will need to fill out one of these structures to register a new archive format with the library.

Detailed Description

This structure contains function pointers and data that the PhysFS library uses to manage a specific archive format.

int (*PHYSFS_Archiver::destroy) (void *opaque)

This function is called when an archive is being unmounted. It should free any memory allocated and close any file handles that were opened by the archive implementation. The (opaque) parameter is the same pointer that was returned by the mount function.

Return non-zero on success, zero on failure. If it fails, PHYSFS_setErrorCode() must be called.

PHYSFS_Io *(*PHYSFS_Archiver::openRead) (void *opaque, const char *fnm)

Open a file within the archive for reading. The filename is given in platform-independent notation. Returns NULL on failure and calls PHYSFS_setErrorCode(). Returns a valid PHYSFS_Io(3) pointer on success. The returned pointer will be passed as the "opaque" parameter for subsequent calls related to this file handle.

PHYSFS_Io *(*PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Open a file within the archive for writing. If the file does not exist, it should be created. If it exists, it should be truncated to zero bytes. The writing offset should be the start of the file. If the archive is read-only, this operation should fail. This filename is in platform-independent notation. Returns NULL on failure and calls PHYSFS_setErrorCode(). Returns a valid PHYSFS_Io(3) pointer on success. The returned pointer will be passed as the "opaque" parameter for subsequent calls related to this file handle.

int (*PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Delete a file or directory within the archive. This same call is used for both files and directories; there is not a separate rmdir() call. Directories are only meant to be removed if they are empty. If the archive is read-only, this operation should fail.

Return non-zero on success, zero on failure. This filename is in platform-independent notation. On failure, call PHYSFS_setErrorCode().

int (*PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtain basic file metadata. On success, fill in all the fields in (stat), using reasonable defaults for fields that apply to your archive.

Returns non-zero on success, zero on failure. This filename is in platform-independent notation. On failure, call PHYSFS_setErrorCode().

PHYSFS_uint32 PHYSFS_Archiver::version

Binary compatibility information. This must be set to zero at this time. Future versions of this struct will increment this field, so we know what a given implementation supports. We'll presumably keep supporting older versions as we offer new features, though.

int (*PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Create a directory within the archive. If the archive is read-only, this operation should fail.

Return non-zero on success, zero on failure. This filename is in platform-independent notation. On failure, call PHYSFS_setErrorCode().

void (*PHYSFS_Archiver::enumerate) (const char *dirname, PHYSFS_EnumerateCallback callback, void *callbackdata, void *opaque)

Called when the application wants to iterate over the contents of a directory. The archive implementation should call the provided callback for every file and directory within (dirname). The (dirname) is given in platform-independent notation.

The callback function should be called as: callback(callbackdata, filename); where (filename) is the platform-independent name of the file or directory.

If the callback returns non-zero, the enumeration should stop immediately. The archive implementation should not return an error if the directory does not exist; it should simply not call the callback for anything.

int (*PHYSFS_Archiver::mount) (const char *filename, const char *mountpoint, void *opaque, int appendToPath)

Attempt to open an archive for reading. The (filename) is the path to the archive file. The (mountpoint) is the directory within the virtual filesystem where the archive's contents should appear. The (opaque) pointer is for the archiver's use; it should allocate and return a pointer to any data it needs to manage this archive instance. The (appendToPath) flag indicates whether this archive should be appended to the search path or inserted at the beginning.

The (claimed) parameter is a pointer to an integer. If your archiver can identify this file as a potential archive of its type (e.g. by checking a magic number), it should set (*claimed) to 1, even if it fails to open the archive for other reasons. We use this to decide if we should stop trying other archivers if you fail to open it. For example: the .zip archiver will set this to 1 for something that's got a .zip file signature, even if it failed because the file was also truncated. No sense in trying other archivers here, we already tried to handle it with the appropriate implementation!. Return NULL on failure and set (claimed) appropriately. If no archiver opened the archive or set (claimed), PHYSFS_mount() will report PHYSFS_ERR_UNSUPPORTED. Otherwise, it will report the error from the archiver that claimed the data through (claimed). Return non-NULL on success. The pointer returned will be passed as the "opaque" parameter for later calls.

PHYSFS_Io *(*PHYSFS_Archiver::openRead) (void *opaque, const char *fnm)

Open a file in this archive for reading. This filename, (fnm), is in platform-independent notation. Fail if the file does not exist. Returns NULL on failure, and calls PHYSFS_setErrorCode(). Returns non-NULL on success. The pointer returned will be passed as the "opaque" parameter for later file calls.

PHYSFS_Io *(*PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Open a file in this archive for writing. If the file does not exist, it should be created. If it exists, it should be truncated to zero bytes. The writing offset should be the start of the file. If the archive is read-only, this operation should fail. This filename is in platform-independent notation. Returns NULL on failure, and calls PHYSFS_setErrorCode(). Returns non-NULL on success. The pointer returned will be passed as the "opaque" parameter for later file calls.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Delete a file or directory in the archive. This same call is used for both files and directories; there is not a separate rmdir() call. Directories are only meant to be removed if they are empty. If the archive is read-only, this operation should fail.

Return non-zero on success, zero on failure. This filename is in platform-independent notation. On failure, call PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtain basic file metadata. On success, fill in all the fields in (stat), using reasonable defaults for fields that apply to your archive.

Returns non-zero on success, zero on failure. This filename is in platform-independent notation. On failure, call PHYSFS_setErrorCode().

PHYSFS_uint32 PHYSFS_Archiver::version

Binary compatibility information. This must be set to zero at this time. Future versions of this struct will increment this field, so we know what a given implementation supports. We'll presumably keep supporting older versions as we offer new features, though.
