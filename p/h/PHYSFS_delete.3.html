#define PHYSFS_file PHYSFS_File

Define de compatibilité API 1.0. PHYSFS_file est identique à PHYSFS_File. Ce #define est présent pour la compatibilité ascendante avec l'API 1.0, qui avait une convention de capitalisation incohérente dans ce cas. Le nouveau code doit utiliser PHYSFS_File, car ce #define pourrait disparaître un jour.

PHYSFS_enumerate

C'est la même chose que PHYSFS_EnumFilesCallback de PhysicsFS 2.0, sauf qu'elle peut renvoyer un résultat du rappel : à savoir : si vous recherchez quelque chose de spécifique, une fois que vous l'avez trouvé, vous pouvez indiquer à PhysicsFS d'arrêter d'énumérer davantage. Ceci est utilisé avec PHYSFS_enumerate(), que nous avons espérons bien fait cette fois-ci. :)

Paramètres

data Pointeur de données défini par l'utilisateur, transmis depuis l'API qui a finalement appelé le rappel.
origdir Une chaîne contenant le chemin complet, en notation indépendante de la plateforme, du répertoire contenant ce fichier. Dans la plupart des cas, il s'agit du répertoire sur lequel vous avez demandé l'énumération, passé dans le rappel pour votre commodité.
fname Le nom de fichier qui est énuméré. Il peut ne pas être dans un ordre alphabétique par rapport aux autres rappels qui ont été déclenchés, et il ne conterra pas le chemin complet. Vous pouvez recréer le chemin complet avec $origdir/$fname ... Le fichier peut être un sous-répertoire, un fichier, un lien symbolique, etc.

Retourne

Une valeur de PHYSFS_EnumerateCallbackResult. Toutes les autres valeurs sont (actuellement) indéfinies ; ne les utilisez pas.

typedef void(* physFS_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Signature de fonction pour les rappels qui énumèrent des fichiers.

Avertissement

Depuis PhysicsFS 2.1, utilisez plutôt PHYSFS_EnumerateCallback avec PHYSFS_enumerate() ; cela vous donne plus de contrôle sur le processus.

Ceux-ci sont utilisés pour signaler une liste d'entrées de répertoire à un appelant d'origine, un fichier/répertoire/lien symbolique par rappel. Toutes les chaînes sont encodées en UTF-8. Les fonctions ne doivent pas essayer de modifier ou de libérer la mémoire d'une chaîne.

Ces rappels sont utilisés, à partir de PhysicsFS 1.1, comme alternative aux fonctions qui renverraient des listes qui doivent être nettoyées avec PHYSFS_freeList(). Le rappel signifie que la bibliothèque n'a pas besoin d'allouer une liste entière et toutes les chaînes à l'avance.

Sachez que l'ordre des données promis dans les versions de liste ne l'est pas nécessairement dans les versions de rappel. Consultez la documentation des API spécifiques, mais les chaînes peuvent ne pas être triées comme vous l'attendez et vous pourriez obtenir des chaînes dupliquées.

origdir Une chaîne contenant le chemin complet, en notation indépendante de la plateforme, du répertoire contenant ce fichier. Dans la plupart des cas, il s'agit du répertoire sur lequel vous avez demandé l'énumération, passé dans le rappel pour votre commodité.

Vous pouvez recréer le chemin complet avec $origdir/$fname ... Le fichier peut être un sous-répertoire, un fichier, un lien symbolique, etc.

int PHYSFS_deinit (void )

Deinitialize the PhysicsFS library. This closes any files opened via PhysicsFS, blanks the search/write paths, frees memory, and invalidates all of your file handles.

Note that this call can FAIL if there's a file open for writing that refuses to close (for example, the underlying operating system was buffering writes to network filesystem, and the fileserver has crashed, or a hard drive has failed, etc). int PHYSFS_delete (const char * filename)

Delete a file or directory. (filename) is specified in platform-independent notation in relation to the write dir.

A directory must be empty before this call can delete it.

Deleting a symlink will remove the link, not what it points to, regardless of whether you "permitSymLinks" or not.

So if you've got the write dir set to "C:\mygame\writedir" and call PHYSFS_delete("downloads/maps/level1.map") then the file "C:\mygame\writedir\downloads\maps\level1.map" is removed from the physical filesystem, if it exists and the operating system permits the deletion.

int PHYSFS_enumerate (const char * dir, PHYSFS_EnumerateCallback c, void * d)

Obtenez une liste de fichiers d'un répertoire du chemin de recherche, en utilisant un rappel défini par l'application, avec signalement des erreurs. Interne, PHYSFS_enumerateFiles() appelle simplement cette fonction puis construit une liste avant de retourner à l'application, donc la fonctionnalité est identique sauf pour la façon dont l'information est représentée à l'application.

Contrairement à PHYSFS_enumerateFiles(), cette fonction ne retourne pas de tableau. Elle appelle plutôt une fonction spécifiée par l'application une fois par élément du chemin de recherche :

static PHYSFS_EnumerateCallbackResult printDir(void *data, const char *origdir, const char *fname)
{
    printf(" * Nous avons [%s] dans [%s].\n", fname, origdir);
    return PHYSFS_ENUM_OK;  // donnez-moi plus de données, s'il vous plaît.
}
// ...
PHYSFS_enumerate("/quelque/chemin", printDir, NULL);

Les éléments envoyés au rappel ne sont garantis dans aucun ordre quelconque. Aucun tri n'est effectué à ce niveau, et si vous en avez besoin, vous devriez probablement utiliser PHYSFS_enumerateFiles() à la place, qui garantit un tri alphabétique. Cette forme signale ce qui est découvert dans chaque archive avant de passer à la suivante. Même au sein d'une archive, nous ne pouvons garantir l'ordre dans lequel elle découvrira les données. Tout tri que vous trouverez dans ces appels de rappel n'est que de la pure chance. Ne vous y fiez pas. Comme cela parcourt toute la liste des archives, vous pouvez recevoir des noms de fichiers dupliqués.

Cette API et les rappels eux-mêmes sont capables de signaler des erreurs. Avant cette API, les rappels devaient accepter chaque élément énuméré, même s'ils ne cherchaient qu'une chose spécifique et voulaient s'arrêter après, ou s'ils avaient une erreur grave et ne pouvaient alerter personne. De plus, si PhysicsFS lui-même avait un problème (erreur de disque ou autre), il ne pouvait pas le signaler à l'application appelante, il devait simplement ignorer des éléments ou arrêter l'énumération, et l'appelant ne saurait pas qu'il a perdu certaines données en cours de route.

Maintenant, l'appelant peut être sûr d'avoir obtenu un ensemble de données complet, et son rappel a le contrôle s'il souhaite que l'énumération s'arrête plus tôt. Voir la documentation de PHYSFS_EnumerateCallback pour plus de détails sur le comportement attendu de votre rappel.

Paramètres

dir Répertoire, en notation indépendante de la plateforme, à énumérer.
c Fonction de rappel pour notifier les éléments du chemin de recherche.
d Données définies par l'application passées au rappel. Peut être NULL.

Retourne

Non-zéro en cas de succès, zéro en cas d'échec. Utilisez PHYSFS_getLastErrorCode() pour obtenir l'erreur spécifique. Si le rappel retourne PHYSFS_ENUM_STOP pour arrêter prématurément, cela sera considéré comme un succès. Les rappels retournant PHYSFS_ENUM_ERROR feront retourner zéro à cette fonction et définiront le code d'erreur à PHYSFS_ERR_APP_CALLBACK.

const char *PHYSFS_getPrefDir (const char * org, const char * app)

Obtient le chemin d'accès au répertoire d'écriture spécifique à l'utilisateur et au programme. C'est une fonction d'aide.

Obtient le "pref dir". C'est là que les utilisateurs peuvent écrire des fichiers personnels (préférences et sauvegardes de jeux, etc.) spécifiques au programme. Ce répertoire est unique par utilisateur et par programme.

Cette fonction décide de l'emplacement approprié dans le système de fichiers natif, crée le répertoire si nécessaire et renvoie une chaîne en notation système, adaptée pour être passée à PHYSFS_setWriteDir().

Sous Windows, cela pourrait ressembler à : "C:\\Users\\bob\\AppData\\Roaming\\My Company\\My Program Name"

Sous Linux, cela pourrait ressembler à : "/home/bob/.local/share/My Program Name"

Sous Mac OS X, cela pourrait ressembler à : "/Users/bob/Library/Application Support/My Program Name"

(etc.)

Vous devriez utiliser le pref dir pour votre chemin d'écriture et également le placer en haut de votre liste de recherche. Les anciennes versions de PhysicsFS n'offraient que PHYSFS_getUserDir() et laissaient les utilisateurs décider où placer les fichiers sous cet arbre. Cette fonction trouve l'emplacement approprié pour n'importe quelle plateforme, qui change non seulement entre les systèmes d'exploitation, mais aussi entre les versions du même système d'exploitation.

  • Essayez d'utiliser la même chaîne d'organisation (sensibilité à la casse incluse) pour toutes les applications utilisant cette fonction.
  • Utilisez toujours une chaîne d'application unique pour chacune, et assurez-vous qu'elle ne change pas pour une application une fois que vous l'avez décidée.
  • Les caractères Unicode sont valides tant qu'ils sont encodés en UTF-8, mais...
  • ... utilisez uniquement des lettres, des chiffres et des espaces. Évitez les caractères comme "Nom du jeu 2: La Revanche du Méchant !" ... "Nom du jeu 2" suffit.

Ajoute un archive, contenu dans un handle PHYSFS_File, à la liste de recherche.

Attention

À moins que vous n'ayez un besoin de bas niveau spécial, vous devriez utiliser PHYSFS_mount() à la place.

Les archives dans les archives peuvent être très lentes ! Bien qu'un PHYSFS_File puisse rechercher même lorsque les données sont compressées, il peut le faire en soustrayant du début et en décompressant tout avant le point de recherche. L'utilisation normale des archives peut effectuer de nombreuses recherches en arrière-plan. En tant que tel, si vous montez cet archive de cette manière, vous pourriez trouver l'utilisation normale des archives extrêmement difficile. Prévoyez en conséquence : si, par exemple, vous avez un fichier .zip auto-extractible et que vous souhaitez monter quelque chose à l'intérieur, archivez les contenus de l'archive intérieure et assurez-vous que l'archive extérieure ne compresse pas trop l'archive intérieure.

void PHYSFS_permitSymbolicLinks (int allow)

Active ou désactive le suivi des liens symboliques. Certains systèmes de fichiers physiques et archives contiennent des fichiers qui ne sont que des pointeurs vers d'autres fichiers. Sur le système de fichiers physique, l'ouverture d'un tel lien ouvrira (transparence) le fichier auquel il pointe.

Par défaut, PhysicsFS vérifie si un fichier est réellement un lien symbolique lors des appels d'ouverture et échoue s'il l'est. Sinon, le lien pourrait vous faire sortir des chemins d'écriture et de recherche, et compromettre la sécurité.

Si vous souhaitez prendre ce risque, appelez cette fonction avec un paramètre non nul. Notez que cela est davantage destiné à la mise en quarantaine du langage de script d'un programme, au cas où des scripts non fiables tenteraient de compromettre le système. D'une manière générale, un utilisateur pourrait très bien avoir une raison légitime de créer un lien symbolique, donc à moins que vous ne sentiez qu'il y ait un danger spécifique à les autoriser, vous devriez les autoriser.

Les liens symboliques ne sont explicitement vérifiés que lors du traitement des noms de fichiers dans la notation indépendante de la plateforme. C'est-à-dire que lors de la configuration de vos chemins de recherche et d'écriture, etc., les liens symboliques ne sont jamais vérifiés.

Veuillez noter que PHYSFS_stat() vérifiera toujours le chemin spécifié ; si ce chemin est un lien symbolique, il ne sera suivi dans aucun cas. Si les liens symboliques ne sont pas autorisés par cette fonction, PHYSFS_stat() les ignore et traiterait la requête comme si le chemin n'existait pas du tout.

La permission des liens symboliques peut être activée ou désactivée à tout moment après avoir appelé PHYSFS_init(), et est désactivée par défaut.

Paramètres

allow non nul pour autoriser les liens symboliques, zéro pour refuser le lien.

int PHYSFS_setRoot (const char * archive, const char * subdir)

Establece un subdirectorio de un archivo como su directorio raíz. Esto permite acotar los archivos accesibles dentro de un archivo específico. Por ejemplo, si tienes x.zip con un archivo en y/z.txt montado en /a, si llamas a PHYSFS_setRoot("x.zip", "/y"), entonces la llamada a PHYSFS_openRead("/a/z.txt") se cumplirá.

Puedes cambiar la raíz de un archivo en cualquier momento, alterando el árbol de archivos interpolado (dependiendo de dónde se muevan las rutas, puede proporcionar diferentes archivos de un archivo distinto). Si estableces la raíz a NULL o a "/", el archivo se tratará como si no tuviera raíz especial (como si el archivo se hubiera montado normalmente).

Cambiar la raíz solo afecta a las operaciones futuras en las rutas de archivo; un archivo que se abrió desde una ruta que cambió debido a un setRoot no se verá afectado.

Establecer una nueva raíz no se limita a los archivos en el directorio de búsqueda; puedes establecerla en el directorio de escritura también, lo que puede ser útil si tienes archivos abiertos para escritura y no puedes cambiar el directorio de escritura en este momento.

No es un error establecer un subdirectorio que no exista como raíz de un archivo, aunque no se mostrarán archivos en este caso. Si los directorios faltantes terminan siendo creados (una mkdir en el sistema de archivos físico, etc.), esto se reflejará en el árbol interpolado.

Parámetros

archive Directorio/archivo sobre el cual cambiar la raíz.
subdir Nuevo subdirectorio a establecer como raíz de este archivo.

Retorna

Distinto de cero en caso de éxito, cero en caso de fallo. Usa PHYSFS_getLastErrorCode() para obtener el error específico.

int PHYSFS_setSaneConfig (const char * organization, const char * appName, const char * archiveExt, int includeCdRoms, int archivesFirst)

Configura rutas sencillas y predeterminadas. Una función de ayuda.

El directorio de escritura se establecerá en el prefdir devuelto por

PHYSFS_getPrefDir(organization, appName)

, que se crea si no existe.

La parte anterior es suficiente para asegurar que el directorio de configuración de tu programa esté separado de otros archivos desordenados y sea independiente del sistema operativo.

La ruta de búsqueda será:

  • Directorio de escritura (creado si no existe)
  • Directorio base (PHYSFS_getBaseDir())
  • Todos los directorios de CD-ROM encontrados (opcional)

Estos directorios se buscan por extensiones (archiveExt), que, si son válidas y soportadas, también se agregan a la ruta de búsqueda. Si especificaste "PKG" para (archiveExt) y hay un archivo llamado data.PKG en el directorio base, se verificará. Los archivos pueden ser añadidos o antepuestos a la ruta de búsqueda en orden alfabético, independientemente de dónde se encuentren. Todos los archivos se montan en la raíz del sistema de archivos virtual ("/") .

Todo lo anterior puede ser hecho por la aplicación, pero esto lo hace todo por ti. Puedes añadir más a la ruta de búsqueda manualmente, también.

archiveExt Extensión utilizada por tu programa para especificar un archivo. Por ejemplo, Quake 3 usa "pk3", aunque sean simplemente archivos zip. Especifica NULL para no buscar automáticamente archivos. No especifiques el punto; si quieres buscar archivos ZIP, especifícalo como "ZIP" y no como ".ZIP"... la búsqueda de archivos no distingue entre mayúsculas y minúsculas.

Esto puede causar un bloqueo significativo mientras se accede a los discos, y si no hay discos en la unidad (o incluso no montados en sistemas Unix), pueden no estar disponibles. Puedes especificar cero y manejar la configuración de discos tú mismo.

Distinto de cero en caso de éxito, cero en caso de error. Usa PHYSFS_getLastErrorCode() para obtener el error específico.

void PHYSFS_utf8FromLatin1 (const char * src, char * dst, PHYSFS_uint64 len)

Pour s'assurer que le tampon de destination est suffisamment grand pour la conversion, veuillez allouer un tampon deux fois plus grand que le tampon source. UTF-8 étend les points de code latin1 supérieurs à 127 de 1 à 2 octets, de sorte que la chaîne peut croître dans certains cas.

Convertir una cadena UTF-8 a una cadena UCS-4.

Nota de advertencia

Esta función no reportará un error si hay secuencias de UTF-8 inválidas en la cadena de entrada. Reemplazará estas secuencias con un carácter '?' y continuará.
