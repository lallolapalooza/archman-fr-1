Description détaillée

Interface abstraite pour fournir un support pour des archives définies par l'utilisateur.

Avertissement

Ceci est un sujet avancé et hardcore. Vous n'avez pas besoin de ce sujet, sauf si vous savez vraiment ce que vous faites. La plupart des programmes n'auront pas besoin de ceci.

Historiquement, PhysicsFS a fourni un moyen de monter divers formats de fichiers d'archive et de répertoires physiques dans le système de fichiers natif. Cependant, les programmes ont été limités aux formats de fichiers fournis par la bibliothèque. Cette interface permet à un programme de fournir ses propres types de fichiers d'archive.

Conceptuellement, un PHYSFS_Archiver fournit des entrées de répertoire, tandis que PHYSFS_Io fournit des flux de données pour ces entrées de répertoire. L'utilisation la plus évidente de PHYSFS_Archiver est de fournir un support pour un type de fichier d'archive qui n'est pas directement fourni par PhysicsFS : peut-être un format propriétaire que seule votre application doit comprendre.

En interne, tout le support des fichiers d'archive préconçu utilise cette interface, donc les meilleurs exemples pour construire un PHYSFS_Archiver sont les codes sources de PhysicsFS lui-même.

Un archiveur est enregistré auprès du système avec PHYSFS_registerArchiver(), puis il sera disponible pour être utilisé avec PHYSFS_mount() ; si un fichier donné peut être géré par votre archiveur, il lui sera donné le contrôle approprié.

Ces fonctions traitent des handles de répertoire. Vous avez une instance de votre archiveur, et il produit un handle unique et opaque pour chaque archive ouverte dans sa méthode openArchive(). Comme la durée de vie d'un Archiveur (pas d'un fichier) est généralement la durée de vie du processus, et qu'il est supposé être un singleton, aucune donnée d'instance n'est fournie pour l'archiveur lui-même ; le programme peut simplement utiliser des variables statiques si nécessaire.

Les barres obliques des répertoires doivent toujours être suivies (sauf dans stat()) ; PhysicsFS utilisera la méthode stat() pour vérifier s'il s'agit de barres obliques et évaluer s'il faut continuer à appeler d'autres méthodes en fonction de cela.

Les archiveurs, lorsque nécessaire, doivent définir l'état d'erreur de PhysicsFS avec PHYSFS_setErrorCode() avant de retourner. PhysicsFS transmettra ces erreurs sans déranger le programme dans la plupart des cas.

Sécurité des threads : Les implémentations de PHYSFS_Archiver ne garantissent pas la sécurité des threads. PhysicsFS fournit la sécurité des threads lorsqu'il appelle un archiveur spécifique dans la bibliothèque, mais il ne garantit pas que l'utilisation du même PHYSFS_File à partir de deux threads simultanément soit sûre ; par conséquent, votre PHYSFS_Archiver peut supposer que l'accès à son état est géré par vous, tant que le PHYSFS_Io renvoyé par PHYSFS_open* ne modifie aucun état de votre archiveur, car le PHYSFS_Io ne sera pas protégé de manière aussi agressive.

Documentation des champs

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Détruit une archive précédemment ouverte. Ferme cette archive et libère toute mémoire associée, y compris le PHYSFS_Io d'origine et (opaque) lui-même, le cas échéant. L'implémentation peut supposer qu'elle ne sera pas appelée s'il reste des fichiers ouverts de cette archive.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Liste tous les fichiers dans (dirname). Chaque fichier est passé à (cb), où une copie est créée si approprié, vous pouvez donc vous en débarrasser après le retour de la fonction de rappel. (dirname) est en notation indépendante du système de fichiers. S'il y a une erreur, appelle PHYSFS_setErrorCode() avec le code approprié et renvoie PHYSFS_ENUM_ERROR. Si la fonction de rappel renvoie PHYSFS_ENUM_ERROR, appelle PHYSFS_setErrorCode(PHYSFS_ERR_APP_CALLBACK) et renvoie également PHYSFS_ENUM_ERROR. Ne rappelle pas la fonction de rappel dans quelque situation que ce soit. Si la fonction de rappel renvoie PHYSFS_ENUM_STOP, arrêtez l'énumération et renvoyez également PHYSFS_ENUM_STOP. Ne rappelle pas la fonction de rappel dans quelque situation que ce soit. N'établit pas de code d'erreur dans ce cas. Les fonctions de rappel ne doivent renvoyer qu'une valeur de PHYSFS_EnumerateCallbackResult. Tout autre résultat a un comportement indéfini. Bien que la fonction de rappel ait renvoyé PHYSFS_ENUM_OK et que vous n'ayez rencontré aucune erreur de votre côté, énumérez jusqu'à ce que vous ayez terminé et renvoyez PHYSFS_ENUM_OK sans définir de code d'erreur.

Avertissement

PHYSFS_enumerate renvoie 0 ou non zéro (succès ou échec), vous devez donc être conscient que ce pointeur de fonction peut renvoyer différentes valeurs !

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Informations de base sur cet archiveur. Ceci est utilisé pour identifier votre archiveur, et est renvoyé par PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crée un répertoire dans l'archive. Si l'application tente de créer plusieurs répertoires, PhysicsFS les fractionnera en plusieurs appels avant de les transmettre à votre pilote. Si l'archive est en lecture seule, cette opération doit échouer. Renvoie une valeur non nulle en cas de succès, zéro en cas d'échec. Ce nom de fichier est en notation indépendante du système de fichiers. En cas d'erreur, appelle PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Ouvre un fichier dans cette archive en mode ajout. Si le fichier n'existe pas, il doit être créé. Le décalage d'écriture doit être à la fin du fichier. Si l'archive est en lecture seule, cette opération doit échouer. Renvoie NULL en cas d'erreur, et appelle PHYSFS_setErrorCode(). Renvoie non NULL en cas de succès. Le pointeur renvoyé est passé comme paramètre "opaque" pour les appels de fichier ultérieurs.

void *(* PHYSFS_Archiver::openArchive) (PHYSFS_Io *io, const char *name, int forWrite, int *claimed)

Ouvre une archive fournie par (io). C'est là que les ressources sont allouées et que les données sont analysées lors du montage d'une archive. (name) est un nom de fichier associé à (io), mais il ne correspond pas nécessairement à quelque chose, même à un nom réel. Ce nom potentiellement significatif peut être en notation dépendante du système. (forWrite) est non nul s'il est utilisé pour le répertoire d'écriture, et nul s'il est utilisé pour un élément de fichier. Cette fonction renvoie NULL en cas d'erreur, et appelle PHYSFS_setErrorCode(). Renvoie non NULL en cas de succès. Le pointeur renvoyé est passé comme paramètre "opaque" pour les appels de fichier ultérieurs.

l'arborescence de recherche. (claimed) doit être défini à 1 si il s'agit clairement d'une archive que votre implémentation d'archiveur peut gérer, même si l'ouverture échoue. Nous l'utilisons pour décider si nous devons arrêter d'essayer d'autres archiveurs si vous échouez à l'ouvrir. Par exemple : l'archiveur .zip définira cette valeur à 1 pour quelque chose qui possède une signature de fichier .zip, même si cela échoue parce que le fichier a été tronqué. Il n'y a aucun intérêt à essayer d'autres archiveurs ici, nous avons déjà essayé de le gérer avec l'implémentation appropriée !. Retourne NULL en cas d'échec et définit (claimed) de manière appropriée. Si aucun archiveur n'a ouvert l'archive ou défini (claimed), PHYSFS_mount() rapportera PHYSFS_ERR_UNSUPPORTED. Sinon, il rapportera l'erreur de l'archiveur qui a revendiqué les données via (claimed). Retourne une valeur non-NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels ultérieurs.

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque, const char *fnm)

Ouvre un fichier dans cette archive en lecture. Ce nom de fichier, (fnm), est en notation indépendante de la plateforme. Échoue si le fichier n'existe pas. Retourne NULL en cas d'échec, et appelle PHYSFS_setErrorCode(). Retourne une valeur non-NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels de fichiers ultérieurs.

PHYSFS_Io *(* PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Ouvre un fichier dans cette archive en écriture. Si le fichier n'existe pas, il doit être créé. S'il existe, il doit être tronqué à zéro octet. La position d'écriture doit être le début du fichier. Si l'archive est en lecture seule, cette opération doit échouer. Ce nom de fichier est en notation indépendante de la plateforme. Retourne NULL en cas d'échec, et appelle PHYSFS_setErrorCode(). Retourne une valeur non-NULL en cas de succès. Le pointeur retourné sera passé comme paramètre "opaque" pour les appels de fichiers ultérieurs.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Supprime un fichier ou un répertoire dans l'archive. Cet appel est utilisé à la fois pour les fichiers et les répertoires ; il n'y a pas d'appel rmdir() séparé. Les répertoires ne doivent être supprimés que s'ils sont vides. Si l'archive est en lecture seule, cette opération doit échouer.

Retourne une valeur non nulle en cas de succès, zéro en cas d'échec. Ce nom de fichier est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtient les métadonnées de base du fichier. En cas de succès, remplit tous les champs de (stat), en utilisant des valeurs par défaut raisonnables pour les champs qui s'appliquent à votre archive.

Retourne une valeur non nulle en cas de succès, zéro en cas d'échec. Ce nom de fichier est en notation indépendante de la plateforme. En cas d'échec, appelez PHYSFS_setErrorCode().

PHYSFS_uint32 PHYSFS_Archiver::version

Informations de compatibilité binaire. Doit être défini à zéro à l'heure actuelle. Les futures versions de cette structure incrémenteront ce champ, nous saurons ainsi ce qu'une implémentation donnée supporte. Nous supporterons probablement les anciennes versions tout en proposant de nouvelles fonctionnalités, cependant.
