Description détaillée

Une interface E/S abstraite.

Attention

Ceci est du matériel avancé. Vous n'en avez pas besoin à moins de savoir vraiment ce que vous faites. La plupart des applications n'en auront pas besoin.

Historiquement, PhysicsFS fournissait un accès au système de fichiers physique et aux archives à l'intérieur de ce système de fichiers. Cependant, il faut parfois plus de puissance que cela. Peut-être avez-vous besoin de fournir une archive entièrement contenue en RAM, ou vous avez besoin de relier une autre API d'E/S de fichiers à PhysicsFS, ou vous avez besoin de traduire les bits (peut-être avez-vous un fichier .zip standard chiffré, et vous devez le déchiffrer à la volée pour l'archiveur zip inconscient).

Un PHYSFS_Io est l'interface que les archiveurs utilisent pour obtenir les données d'archive. Historiquement, cela correspondait aux E/S de fichiers vers le système de fichiers physique, mais depuis PhysicsFS 2.1, les applications peuvent fournir leurs propres implémentations d'E/S à l'exécution.

Cette interface n'est pas nécessairement un bon ajustement universel pour les E/S. Il y a quelques exigences à noter :

  • Elles ne font que des E/S bloquantes (du moins, pour l'instant).
  • Elles doivent être capables de se dupliquer. Si vous avez un descripteur de fichier de fopen(), vous devez être capable de créer un clone unique de celui-ci (afin que nous ayons deux descripteurs pour le même fichier qui puissent tous deux chercher/lire/etc sans se marcher sur les pieds).
  • Elles doivent connaître la taille de l'ensemble de leurs données.
  • Elles doivent être capables de chercher et de rembobiner à la demande.

... en bref, vous n'allez probablement pas écrire une implémentation HTTP.

Thread-safety : les implémentations PHYSFS_Io ne sont pas garanties d'être thread-safe en elles-mêmes. Sous le capot, là où PhysicsFS les utilise, la bibliothèque fournit ses propres verrous. Si vous prévoyez de les utiliser directement à partir de threads séparés, vous devriez soit utiliser des mutex pour les protéger, soit ne pas utiliser le même PHYSFS_Io à partir de deux threads en même temps.

Documentation des champs

void(* PHYSFS_Io::destroy) (struct PHYSFS_Io *io)

Nettoyer et désallouer l'instance d'E/S. Libérer les ressources associées, y compris (opaque) le cas échéant.

Cette fonction doit toujours réussir : à ce titre, elle renvoie void. Le système peut appeler votre méthode flush() avant cela. Vous pouvez signaler un échec là si nécessaire. Cette méthode peut toujours être appelée si flush() échoue, auquel cas vous devrez abandonner les données non vidées et d'autres conditions d'échec et nettoyer.

Une fois cette méthode appelée pour une instance donnée, le système supposera qu'il est dangereux de toucher à nouveau cette instance et rejettera toute référence à celle-ci.

Paramètres

s L'instance d'E/S à détruire.

struct PHYSFS_Io *(* PHYSFS_Io::duplicate) (struct PHYSFS_Io *io)

Dupliquer cette instance d'E/S. Cela doit résulter en une copie complète de ce PHYSFS_Io, qui peut vivre de manière complètement indépendante. La copie doit être capable d'effectuer toutes ses opérations sans altérer l'original, y compris que l'un ou l'autre objet soit détruit séparément (donc, par exemple : ils ne peuvent pas partager un descripteur de fichier ; chacun a besoin du sien).

Si vous ne pouvez pas dupliquer un descripteur, il est légal de retourner NULL, mais vous avez presque certainement besoin de cette fonctionnalité si vous voulez utiliser ce PHYSFS_Io pour prendre en charge une archive.

Paramètres

io L'instance d'E/S à dupliquer.

Retours

Une nouvelle valeur pour le champ (opaque) d'un flux, ou NULL en cas d'erreur.

int(* PHYSFS_Io::flush) (struct PHYSFS_Io *io)

Vider les ressources sur le support, ou ailleurs. C'est l'occasion de signaler un échec pour les écritures qui avaient revendiqué le succès auparavant, mais qui avaient encore une chance de réellement échouer. Cette méthode peut être NULL si le vidage n'est pas nécessaire.

Cette fonction peut être appelée avant destroy(), car elle peut signaler un échec et destroy() ne le peut pas. Elle peut également être appelée à d'autres moments.

Paramètres

io L'instance d'E/S à vider.

Retours

Zéro en cas d'erreur, non nul en cas de succès.

PHYSFS_sint64(* PHYSFS_Io::length) (struct PHYSFS_Io *io)

Déterminer la taille de l'ensemble de données de l'instance d'E/S. Retourne le nombre d'octets disponibles dans le fichier, ou -1 si vous ne parvenez pas à le déterminer. Un échec sera presque certainement fatal à une utilisation ultérieure de ce flux, vous ne pouvez donc pas laisser cela non implémenté.

Paramètres

io L'instance d'E/S à interroger.

Retours

Taille totale, en octets, de l'ensemble de données.

void* PHYSFS_Io::opaque

Données d'instance pour cette structure. Chaque instance a un pointeur associé qu'elle peut utiliser pour stocker tout ce qu'elle souhaite. Ce pointeur est par instance de flux, donc il changera probablement lors de l'appel à duplicate(). Il peut être désalloué lors de la méthode destroy().

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buf, PHYSFS_uint64 len)

Lire plus de données. Lire (len) octets depuis l'interface, à la position actuelle des E/S, et les stocker dans (buffer). La position actuelle des E/S doit avancer du nombre d'octets lus avec succès.

Vous n'avez pas à implémenter cela ; définissez-le à NULL si non implémenté. Ceci ne sera utilisé que si le fichier est ouvert en lecture. S'il est défini à NULL, une implémentation par défaut qui signale immédiatement l'échec sera utilisée.

Paramètres

io L'instance d'E/S à lire.
buf Le tampon dans lequel stocker les données. Il doit être d'au moins (len) octets et ne peut pas être NULL.
len Le nombre d'octets à lire depuis l'interface.

Retours

nombre d'octets lus depuis le fichier, 0 en fin de fichier, -1 en cas d'échec complet.

int(* PHYSFS_Io::seek) (struct PHYSFS_Io *io, PHYSFS_uint64 offset)

Déplacer la position d'E/S à un décalage d'octet donné depuis le début. Cette méthode déplace la position d'E/S, donc la prochaine lecture/écriture se fera à l'octet à l'offset (offset). Les recherches au-delà de la fin du fichier devraient être autorisées, mais elles ne devraient pas être autorisées si elles visent un décalage trop grand.

Vous n'avez pas à implémenter cela ; définissez-le à NULL si non implémenté. Ceci ne sera utilisé que si le fichier est ouvert en lecture ou en écriture. Si elle est définie à NULL, une implémentation par défaut qui signale immédiatement l'échec sera utilisée.

Paramètres

io L'instance d'E/S à chercher.
offset L'offset d'octet, à partir du début, où déplacer la position d'E/S.

Retours

Zéro en cas d'erreur, non nul en cas de succès.

PHYSFS_sint64(* PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Rapporter la position actuelle des E/S. Retourne l'octet actuel dans le fichier où se trouve la position des E/S. Retourne -1 en cas d'erreur. Un échec sera presque certainement fatal à une utilisation ultérieure de ce flux, vous ne pouvez donc pas laisser cela non implémenté.

Paramètres

io L'instance d'E/S à interroger.

Retours

La position actuelle d'E/S, en octets, depuis le début du fichier.

PHYSFS_uint32 PHYSFS_Io::version

Informations de compatibilité binaire. Les nouvelles implémentations devraient toujours initialiser cela à la valeur de la macro PHYSFS_IO_VERSION. Cela peut être utilisé pour vérifier la compatibilité binaire entre les bibliothèques et les applications.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Écrire plus de données. Écrire (len) octets du (buffer) vers l'interface, à la position actuelle des E/S. La position actuelle des E/S devrait avancer du nombre d'octets écrits avec succès. Vous pouvez écrire dans des fichiers qui sont plus longs que ce qu'ils étaient au départ.

Vous n'avez pas à implémenter cela ; définissez-le à NULL si non implémenté. Ceci ne sera utilisé que si le fichier est ouvert en écriture. Si elle est définie à NULL, une implémentation par défaut qui signale immédiatement l'échec sera utilisée.

Paramètres

io L'instance d'E/S dans laquelle écrire.
buffer Le tampon contenant les données à écrire. Il doit être d'au moins (len) octets et ne peut pas être NULL.
len Le nombre d'octets à écrire dans l'interface.

Retours

nombre d'octets écrits dans le fichier, ou -1 en cas d'échec complet.

PHYSFS_sint64(* PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Signaler la position actuelle des E/S. Renvoie le décalage en octets, ou -1 si impossible à déterminer. Un échec est probablement fatal pour une utilisation ultérieure de ce flux, ne le laissez donc pas implicite.

Paramètres

io L'instanciation des E/S à interroger.

Retour

Le décalage actuel en octets des E/S, -1 si inconnu.

PHYSFS_uint32 PHYSFS_Io::version

Informations de compatibilité binaire. Ceci doit être défini à zéro pour le moment. Les futures versions de cette structure incrémenteront ce champ, nous saurons ainsi quelles implémentations sont prises en charge. Nous continuerons probablement à prendre en charge les anciennes versions tout en offrant de nouveaux éléments.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Écrire plus de données. Écrit (len) octets depuis (buffer) vers l'interface à la position actuelle des E/S. La position actuelle des E/S devrait avancer du nombre d'octets écrits avec succès.

Vous n'avez pas à l'implémenter ; définissez-le à NULL si vous ne l'implémentez pas. Il ne sera utilisé que si le fichier est ouvert en écriture. Si vous le définissez à NULL, une implémentation par défaut sera utilisée, qui signale immédiatement un échec.

Vous pouvez mettre en mémoire tampon ; une écriture peut réussir ici puis échouer lors du vidage. Notez que PHYSFS_setBuffer() peut fonctionner à un niveau supérieur à vos E/S, vous ne devriez donc normalement pas implémenter vos propres mémoires tampons.

Paramètres

io L'instanciation des E/S à écrire.
buffer Le tampon de données à lire. Doit contenir au moins (len) octets et ne peut pas être NULL.
len Le nombre d'octets à lire du tampon (buffer).

Retour

Nombre d'octets écrits dans le fichier, -1 en cas d'échec complet.
