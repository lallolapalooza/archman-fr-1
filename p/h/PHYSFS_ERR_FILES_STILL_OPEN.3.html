PHYSFS_enumerate

C'est la même chose que PHYSFS_EnumFilesCallback de PhysicsFS 2.0, sauf qu'il peut retourner un résultat du callback : à savoir : si vous cherchez quelque chose de spécifique, une fois que vous l'avez trouvé, vous pouvez dire à PhysicsFS d'arrêter d'énumérer davantage. Ceci est utilisé avec PHYSFS_enumerate(), que nous avons espérons bien fait cette fois. :)

Vous pouvez recréer le chemin complet avec $origdir/$fname ... Le fichier peut être un sous-répertoire, un fichier, un lien symbolique, etc.

typedef void(* physfs_EnumFilesCallback) (void *data, const char *origdir, const char *fname)

Signature de fonction pour les callbacks qui énumèrent des fichiers.

Avertissement

À partir de PhysicsFS 2.1, utilisez PHYSFS_EnumerateCallback avec PHYSFS_enumerate() à la place ; cela vous donne plus de contrôle sur le processus.

Ils sont utilisés pour rapporter une liste d'entrées de répertoire à un appelant d'origine, un fichier/répertoire/lien symbolique par callback. Toutes les chaînes sont encodées en UTF-8. Les fonctions ne doivent pas essayer de modifier ou de libérer la mémoire de ces chaînes.

Ces callbacks sont utilisés, à partir de PhysicsFS 1.1, comme une alternative aux fonctions qui retournaient des listes qui devaient être nettoyées avec PHYSFS_freeList(). Le callback signifie que la bibliothèque n'a pas besoin d'allouer une liste entière et toutes les chaînes à l'avance.

Soyez conscient que l'ordre des données promis dans les versions de liste n'est pas nécessairement le même dans les versions de callback. Vérifiez la documentation des API spécifiques, mais les chaînes peuvent ne pas être triées comme vous l'attendez et vous pourriez obtenir des chaînes dupliquées.

Paramètres

data Pointeur de données défini par l'utilisateur, transmis depuis l'API qui a finalement appelé le callback.
origdir Une chaîne contenant le chemin complet, en notation indépendante de la plateforme, du répertoire contenant ce fichier. Dans la plupart des cas, il s'agit du répertoire sur lequel vous avez demandé l'énumération, passé dans le callback pour votre commodité.
fname Le nom du fichier qui est énuméré. Il peut ne pas être en ordre alphabétique par rapport à d'autres callbacks qui ont été déclenchés, et il ne contiendra pas le chemin complet. Vous pouvez recréer le chemin complet avec $origdir/$fname ... Le fichier peut être un sous-répertoire, un fichier, un lien symbolique, etc.

This function adds an archive file to the current search path. The search path is a list of directories and archives that PhysFS will search through when you try to open a file. The first archive in the path that contains the file will be used.

(newDir) must be a unique string to identify this archive. void PHYSFS_permitSymbolicLinks (int allow)

Active ou désactive le suivi des liens symboliques. Certains systèmes de fichiers physiques et archives contiennent des fichiers qui ne sont que des pointeurs vers d'autres fichiers. Lorsque vous ouvrez un lien symbolique physique, le fichier auquel il fait référence sera ouvert de manière transparente.

Par défaut, PhysicsFS vérifie si un fichier est réellement un lien symbolique lors des appels d'ouverture et échoue si c'est le cas. Sinon, le lien pourrait vous faire sortir des chemins de lecture et d'écriture, compromettant la sécurité.

Si vous souhaitez prendre ce risque, appelez cette fonction avec une valeur non nulle. Ceci est davantage destiné au sandboxing d'un langage de script, au cas où des scripts non fiables tenteraient de compromettre le système. Généralement, un utilisateur pourrait avoir une raison légitime de créer un lien symbolique, vous ne devriez donc pas les désactiver, sauf si vous ressentez un danger spécifique.

Les liens symboliques seront explicitement visibles uniquement lorsqu'il s'agira de noms de fichiers dans une notation indépendante de la plateforme. C'est-à-dire que lorsque le chemin de recherche et le chemin d'écriture, etc., sont définis, les liens symboliques ne seront jamais visibles.

La permission des liens symboliques peut être activée ou désactivée à tout moment après avoir appelé PHYSFS_init(), et elle est désactivée par défaut.

Paramètres

allow non nul pour autoriser les liens symboliques, zéro pour refuser le lien.
