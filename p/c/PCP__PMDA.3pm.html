PMDA(3) Documentation Perl Contribuée par l'Utilisateur PMDA(3)

NOM

PCP::PMDA - Extension Perl pour les Agents de Domaine de Métriques de Performance

SYNTAXE

use PCP::PMDA;
$pmda = PCP::PMDA->new('monnom', $DOMAINE_MON);
$pmda->connect_pmcd;
$pmda->add_metric($pmid, $type, $indom, $sem, $unites, 'nom', '', '');
$pmda->add_indom($indom, [0 => 'blanc', 1 => 'noir', ...], '', '');
$pmda->set_fetch(\&methode_fetch);
$pmda->set_refresh(\&methode_refresh);
$pmda->set_instance(\&methode_instance);
$pmda->set_fetch_callback(\&methode_callback_fetch);
$pmda->set_store_callback(\&methode_callback_store);
$pmda->set_user('pcp');
$pmda->run;

DESCRIPTION

Le module Perl PCP::PMDA contient les liaisons de langage pour construire des Agents de Domaine de Métriques de Performance (PMDA) en utilisant Perl. Chaque PMDA exporte des données de performance pour un domaine spécifique, par exemple le noyau du système d'exploitation, les routeurs Cisco, une base de données, une application, etc.

MÉTHODES

PCP::PMDA->new(nom, domaine)
Constructeur de la classe PCP::PMDA. nom est une chaîne qui devient le nom du PMDA pour les messages et le préfixe par défaut pour les noms des fichiers externes utilisés par le PMDA. domaine est un numéro de domaine entier pour le PMDA, généralement issu du registre des numéros de domaine trouvé dans $PCP_VAR_DIR/pmns/stdpmid.
$pmda->run()
Une fois toute la configuration locale terminée (c'est-à-dire que les domaines d'instance et les métriques sont enregistrés, les callbacks enregistrés - comme expliqué ci-dessous), le PMDA doit se connecter à pmcd(1) pour finaliser son initialisation et commencer à répondre aux requêtes des clients pour ses métriques. C'est le rôle joué par run, et lors de son invocation, toutes les interactions au sein du PMDA se font via des routines de rappel (c'est-à-dire que dans des circonstances normales, la routine run ne retourne pas).

Le comportement de la méthode run est différent en présence des variables d'environnement PCP_PERL_PMNS ou PCP_PERL_DOMAIN. Celles-ci peuvent être utilisées pour générer les fichiers de l'espace de noms ou du numéro de domaine, qui sont utilisés dans le cadre du processus d'installation du PMDA.

$pmda->connect_pmcd()
Permet au PMDA d'établir le canal IPC avec pmcd(1) et de finaliser l'authentification avec pmcd(1). Si connect_pmcd n'est pas explicitement appelé, l'établissement et l'authentification seront effectués lors de l'appel à la méthode run.

L'avantage d'appeler explicitement connect_pmcd tôt dans la vie du PMDA est que cela réduit le risque d'un délai d'attente fatal pendant l'authentification, ce qui peut être un problème si le PMDA a un travail considérable à effectuer, par exemple, déterminer quelles métriques et quels domaines d'instance sont disponibles, avant d'appeler run.

$pmda->add_indom(indom, insts, aide, aide_longue)
Définir un nouveau domaine d'instance. L'identifiant du domaine d'instance est indom, qui est un entier et unique parmi tous les domaines d'instance pour un seul PMDA.

Les instances du domaine d'instance sont définies par insts qui peuvent être spécifiées sous forme de liste ou de hachage.

Sous forme de liste, le contenu de la liste doit fournir des paires consécutives d'identifiant (un entier, unique parmi toutes les instances du domaine d'instance) et de nom d'instance externe (une chaîne, doit être unique jusqu'au premier espace, le cas échéant, parmi toutes les instances du domaine d'instance). Par exemple :

@couleurs = [0 => 'rouge', 1 => 'vert', 2 => 'bleu'];

Sous forme de hachage, l'identifiant d'instance externe (chaîne) est utilisé comme clé de hachage. Une valeur arbitraire peut être stockée avec la clé (cette valeur est souvent utilisée comme un moyen pratique de conserver la dernière valeur pour chaque instance de métrique, par exemple).

%tranches_temps = ('sec' => 42, 'min' => \&func_min, 'heure' => '0');

Les chaînes aide et aide_longue sont interprétées comme le texte d'aide sur une ligne et le texte d'aide développé à utiliser pour ce domaine d'instance, comme décrit plus en détail dans pmLookupInDomText(3).

Se référer également à la discussion sur replace_indom() ci-dessous pour plus de détails sur la manipulation des domaines d'instance.

$pmda->add_metric(pmid, type, indom, sem, unites, nom, aide, aide_longue)
Définir une nouvelle métrique identifiée par le PMID pmid et le nom complet de la métrique nom.

Les métadonnées de la métrique sont définies par type, indom, sem et unites et ces paramètres sont utilisés pour configurer la structure pmDesc comme décrit dans pmLookupDesc(3).

Les chaînes aide et aide_longue sont interprétées comme le texte d'aide sur une ligne et le texte d'aide développé à utiliser pour la métrique, comme décrit plus en détail dans pmLookupText(3).

$pmda->replace_indom(index, insts)
Chaque fois qu'un domaine d'instance identifié par index, précédemment enregistré à l'aide de add_indom(), change d'une quelconque manière, ce changement doit être reflété en remplaçant la correspondance existante par une nouvelle (insts).

La correspondance de remplacement doit être un hachage si le domaine d'instance a été initialement enregistré avec add_indom() sous forme de hachage, sinon ce doit être une liste.

Se référer à la discussion précédente sur add_indom() concernant ces deux types différents de définitions de domaines d'instance.

$pmda->load_indom(index)
Lorsque des domaines d'instance basés sur des hachages sont utilisés, les changements sont automatiquement persistants lors de l'utilisation de replace_indom() - cet indom persistant peut être restauré (par exemple, au démarrage) en utilisant cette interface.

Le domaine d'instance à charger est identifié par index, précédemment enregistré à l'aide de add_indom().

Se référer à la discussion précédente sur add_indom() concernant les deux types différents de définitions de domaines d'instance - seuls les domaines d'instance basés sur des hachages sont persistants.

$pmda->add_pipe(commande, callback, données)
Permet d'injecter des données dans le PMDA en utilisant un pipe(2).

La commande donnée est exécutée tôt dans la vie du PMDA, et un tuyau est formé entre le PMDA et la commande. Une sortie orientée ligne est supposée (sinon une troncature se produira), et à la réception de chaque ligne de texte sur le tuyau, la fonction callback sera appelée.

Le paramètre optionnel données peut être utilisé pour spécifier des données supplémentaires à passer à la routine de callback.

$pmda->add_sock(hote, port, callback, données)
Crée une connexion socket(2) à la paire hote, port. Chaque fois que des données arrivent (comme ci-dessus, un protocole orienté ligne est préférable), la fonction callback sera appelée.

Le paramètre optionnel données peut être utilisé pour spécifier des données supplémentaires à passer à la routine de callback.

Un identifiant opaque de taille entière pour le socket sera retourné, qui pourra ensuite être utilisé dans des appels à put_sock() comme décrit ci-dessous.

$pmda->put_sock(id, sortie)
Écrit une chaîne de sortie dans le socket identifié par id, qui doit se référer à un socket précédemment enregistré à l'aide de add_sock().
$pmda->add_tail(nom_fichier, callback, données)
Surveille le nom_fichier donné pour l'arrivée d'informations nouvellement ajoutées. Une entrée orientée ligne est supposée (sinon une troncature se produira), et à la réception de chaque ligne de texte sur le tuyau, la fonction callback sera appelée.

Le paramètre optionnel données peut être utilisé pour spécifier des données supplémentaires à passer à la routine de callback.

Cette interface gère le problème du renommage du fichier (comme lors de la rotation quotidienne des fichiers journaux), et tentera de rediriger automatiquement les informations du nouveau fichier journal si cela se produit.

$pmda->add_timer(delai, callback, données)
Enregistre un minuteur avec le PMDA, de sorte que lors de l'expiration d'un delai, une routine de callback sera appelée. Il s'agit d'un minuteur répétitif.

Le paramètre optionnel données peut être utilisé pour spécifier des données supplémentaires à passer à la routine de callback.

$pmda->err(message)
Signaler un message d'erreur horodaté dans le fichier journal du PMDA.
$pmda->error(message)
Signaler un message d'erreur horodaté dans le fichier journal du PMDA.
$pmda->log(message)
Signaler un message d'information horodaté
PCP::PMDA(3pm) — PCP Perl API

NAME

PCP::PMDA — Interface to the Performance Metrics Domain Agent (PMDA) framework

SYNOPSIS

  use PCP::PMDA;

  # Constructor
  my $pmda = PCP::PMDA->new( domain=> $domain_number,
                              <...> );

  # Registering callbacks
  $pmda->set_init_callback( \&init_pmda );
  $pmda->set_fetch_callback( \&fetch_pmda );
  $pmda->set_store_callback( \&store_pmda );
  $pmda->set_close_callback( \&close_pmda );

  # Registering metadata functions
  $pmda->set_fetch( \&fetch_metrics );
  $pmda->set_instance( \&fetch_instances );
  $pmda->set_refresh( \&refresh_pmda );

  # Configuration
  $pmda->set_log_level( level );
  $pmda->set_log_indent( indent );
  $pmda->set_log_function( \&log_function );
  $pmda->set_fetch_interval( seconds );
  $pmda->set_command_file( filename );

  # Network Configuration
  $pmda->set_inet_socket( port );
  $pmda->set_ipv6_socket( port );
  $pmda->set_unix_socket( socket_name );

  # User/Group configuration
  $pmda->set_user( username );
  $pmda->set_group( groupname );

  # Initialisation and control
  $pmda->pmda_init();
  $pmda->pmda_run();
  $pmda->pmda_shutdown();

  # Helper methods
  my $pmid = $pmda->pmda_pmid( cluster, item );
  my $name = $pmda->pmda_pmid_name( cluster, item );
  my $text = $pmda->pmda_pmid_text( cluster, item );
  my $inst_name = $pmda->pmda_inst_name( index, instance );
  my $inst_val = $pmda->pmda_inst_lookup( index, instance );
  my $units = $pmda->pmda_units( ... );
  my $config_val = $pmda->pmda_config( name );
  my $uptime_str = $pmda->pmda_uptime( now );
  my $long_type = $pmda->pmda_long();
  my $ulong_type = $pmda->pmda_ulong();
  my $is_install = $pmda->pmda_install();

  # Macros
  PM_TYPE_32, PM_TYPE_U32, PM_TYPE_64, PM_TYPE_U64, PM_TYPE_FLOAT, PM_TYPE_DOUBLE, PM_TYPE_STRING, PM_TYPE_NOSUPPORT

  # Debugging
  $ENV{PCP_PERL_DEBUG} = "all";

DESCRIPTION

The PCP::PMDA module provides a Perl interface to the PCP PMDA framework. It allows Perl scripts to act as Performance Metrics Domain Agents (PMDAs), exporting performance metrics to the Performance Co-Pilot (PCP) system.

A PMDA is a daemon that exports performance metrics for a particular domain. PCP uses PMDAs to gather metrics from various sources (e.g., the kernel, hardware devices, user-space applications).

This module simplifies the process of writing a PMDA in Perl by providing object-oriented methods to manage the PMDA lifecycle, register callbacks, define metric metadata, and handle communication with the Performance Metrics Collector Daemon (pmcd(1)).

METHODS

$pmda = PCP::PMDA->new( domain => $domain_number, [name => $pmda_name] )
Constructor for the PCP::PMDA object.
domain
The domain number for this PMDA. This number is usually assigned by PCP and should be unique.
name
Optional name for the PMDA. If not provided, it defaults to the domain number.
$pmda->set_init_callback(cb_function)
Register a callback function that will be called once when the PMDA is initialized. This is where you typically set up your PMDA's data structures and define its metrics.
$pmda->set_fetch_callback(cb_function)
Register a callback function that will be called whenever PCP requests metrics from this PMDA. The cb_function should return a list of fetched values.
$pmda->set_store_callback(cb_function)
Register a callback function that will be called when a value is stored into the PMDA using pmStore(3). This is used for controlling metrics.
$pmda->set_close_callback(cb_function)
Register a callback function that will be called when the PMDA is shutting down. This is useful for cleaning up resources.
$pmda->set_log_level(level)
Set the logging level for the PMDA. This controls the verbosity of messages logged to the PMDA log file.
$pmda->set_log_indent(indent)
Set the indentation level for log messages. This helps in structuring log output.
$pmda->set_log_function(cb_function)
Register a custom callback function for handling log messages. If not provided, messages are written to the PMDA log file.
$pmda->set_fetch_interval(seconds)
Set the interval (in seconds) at which the PMDA should fetch metrics. This is mainly for periodic updates and may not be directly used by PCP, which typically polls on demand.
$pmda->set_command_file(filename)
Specify a file containing commands to be executed by the PMDA. This is rarely used in Perl PMDAs.
$pmda->set_fetch(function)
Register a fetch function, as used by pmdaInit(3). This function is responsible for fetching metric values.
$pmda->set_instance(function)
Register an instance function, as used by pmdaInit(3). This function is responsible for fetching instance information for metrics.
$pmda->set_refresh(function)
Register a refresh function, which will be called once per metric cluster, during the fetch operation. Only clusters being requested during this fetch will be refreshed, allowing selective metric value updates within the PMDA.
$pmda->set_inet_socket(port)
Specify the IPv4 socket port to be used to communicate with pmcd(1).
$pmda->set_ipv6_socket(port)
Specify the IPv6 socket port to be used to communicate with pmcd(1).
$pmda->set_unix_socket(socket_name)
Specify the filesystem socket_name path to be used for communication with pmcd(1).
$pmda->set_user(username)
Run the PMDA under the username user account, instead of the default (root) user.
$pmda->set_group(groupname)
Run the PMDA under the groupname group, instead of the default (root) group.
$pmda->pmda_init()
Initializes the PMDA environment. This should be called after setting up all callbacks and configurations.
$pmda->pmda_run()
Starts the main PMDA event loop, waiting for requests from pmcd(1). This function typically blocks until the PMDA is shut down.
$pmda->pmda_shutdown()
Shuts down the PMDA gracefully. This should be called before the script exits.

HELPER METHODS

pmda_pmid(cluster, item)
Construct a Performance Metric Identifier (PMID) from the domain number (passed as an argument to the new constructor), the cluster (an integer in the range 0 to 2^12-1) and the item (an integer in the range 0 to 2^10-1).

Every performance metric exported from a PMDA must have a unique PMID.

pmda_pmid_name(cluster, item)
Perform a reverse metric identifier to name lookup - given the metric cluster and item numbers, returns the metric name string.
pmda_pmid_text(cluster, item)
Returns the one-line metric help text string - given the metric cluster and item numbers, returns the help text string.
pmda_inst_name(index, instance)
Perform a reverse instance identifier to instance name lookup for the instance domain identified by index. Given the internal instance identifier, returns the external instance name string.
pmda_inst_lookup(index, instance)
Given an internal instance identifier (key) for the instance domain identified by index with an associated indom hash, return the value associated with that key. The value can be any scalar value (this includes references, of course, so complex data structures can be referenced).
pmda_units(dim_space, dim_time, dim_count, scale_space, scale_time, scale_count)
Construct a pmUnits structure suitable for registering a metrics metadata via add_metric().
pmda_config(name)
Lookup the value for configuration variable name from the /etc/pcp.conf file, using pmGetConfig(3).
pmda_uptime(now)
Return a human-readable uptime string, based on now seconds since the epoch.
pmda_long()
Return either PM_TYPE_32 or PM_TYPE_64 depending on the platform size for a signed long integer.
pmda_ulong()
Return either PM_TYPE_U32 or PM_TYPE_U64 depending on the platform size for an unsigned long integer.
pmda_install()
Boolean result indicating whether PMDA installation is in progress, or if this is an actual PMDA invocation via pmcd(1).

MACROS

Most of the PM_* macros from the PCP C headers are available.

For example the type of a metric's value may be directly specified as one of PM_TYPE_32, PM_TYPE_U32, PM_TYPE_64, PM_TYPE_U64, PM_TYPE_FLOAT, PM_TYPE_DOUBLE, PM_TYPE_STRING or PM_TYPE_NOSUPPORT.

DEBUGGING

Perl PMDAs do not follow the -D convention of other PCP applications for enabling run-time diagnostics and tracing. Rather the environment variable PCP_PERL_DEBUG needs to be set to a string value matching the syntax accepted for the option value for -D elsewhere, see pmSetDebug(3).

This requires a little trickery. The pmcd(1) configuration file (PCP_PMCDCONF_PATH from /etc/pcp.conf) needs hand editing. This is best demonstrated by example.

Replace this line

foo  242  pipe  binary  python  /somepath/foo.py

with

foo  242  pipe  binary  python  \
    sh -c "PCP_PERL_DEBUG=pdu,fetch /usr/bin/python /somepath/foo.py"
