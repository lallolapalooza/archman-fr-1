NOM

PCPCompat, pcp-collectl, pmmgr, pmwebd - compatibilité ascendante pour le Performance Co-Pilot (PCP)

INTRODUCTION

Le Performance Co-Pilot (PCP) est un ensemble d'outils conçus pour surveiller et gérer les performances du système. Ces services sont distribués et évolutifs pour s'adapter aux configurations système les plus complexes et aux problèmes de performance.

Pour atteindre ces objectifs de manière efficace, une compatibilité des protocoles et des formats de disque entre les différentes versions de PCP est fournie. Il est possible (et même recommandé) d'utiliser les outils PCP actuels pour interroger n'importe quel système distant, une ancienne ou une nouvelle version de pmcd(1) et également pour rejouer tout fichier historique PCP (la suite de tests PCP contient des fichiers PCP créés il y a plus de 20 ans !).

Parfois, les développeurs de PCP abandonnent et suppriment d'anciens outils PCP, les remplaçant par de nouvelles versions offrant des fonctionnalités similaires. Cette page décrit les outils de remplacement pour les outils historiques de PCP.

PYTHON2

PCP fournit des interfaces python(1) pour l'PMAPI(3) (API de métriques système), le PMDA(3) (API d'agent de métriques système), l'mmv_stats_register(3) (API de statistiques en mémoire mappée) et la création de fichiers PCP LOGIMPORT(3).

Avec la fin de vie de la version python 2 en 2020, tout support pour cette version a été supprimé (à partir de la version 7 de PCP et ultérieurement). Tous les API PCP et les outils basés sur python supportent python 3 et sont utilisés depuis plusieurs années - la mise à niveau est fortement recommandée.

QT4

PCP fournit des interfaces graphiques optionnelles basées sur la bibliothèque Qt, notamment pmchart(1) et pmtime(1).

Avec la fin de vie de Qt v4 en 2015, le support de toutes les versions antérieures à Qt v5 a été supprimé. De plus, certains éléments sont absents des premières versions de Qt v5, qui sont maintenant requis lors de la construction et de l'utilisation des outils PCP basés sur Qt. Par conséquent, la version minimale requise de Qt pour PCP v6 et ultérieur est maintenant Qt 5.6.

NSS

Les versions de PCP antérieures à v6 utilisaient une combinaison de Mozilla NSS (Network Security Services) et OpenSSL pour une partie des fonctionnalités de chiffrement des sockets sécurisés. Depuis PCP v6, cela a été simplifié pour n'utiliser qu'OpenSSL pour tous les usages de chiffrement dans PCP. Ce changement affecte la configuration des fonctionnalités optionnelles dans pmcd(1) et PMAPI(3) utilisant des sockets sécurisés.

L'effet net de ce changement est que le chiffrement est configuré de la même manière, en utilisant les mêmes certificats, dans la fonctionnalité HTTPS de pmproxy(1), ainsi que dans la fonction de protocole chiffré entre pmcd, pmproxy et les clients PMAPI. De plus, le serveur de service clé-valeur utilisé par pmseries(1) et pmproxy utilise également exclusivement OpenSSL, et de manière similaire à PCP, ce qui rend la gestion de ces services considérablement plus simple.

SAR2PCP, IOSTAT2PCP

Les utilitaires sar2pcp(1) et iostat2pcp(1) sont obsolètes et seront supprimés dans une future version de PCP (v7). Ils seront remplacés par un support natif pour la génération de fichiers PCP au sein des paquets sysstat (qui fournissent sar lui-même, ainsi que l'utilitaire sadf qui génère des fichiers PCP via l'option -l).

PMLOGCONF-SETUP

Les anciennes versions de PCP (avant v5.1.1) fournissaient un script shell utilisé en interne par pmlogconf(1), situé dans le répertoire PCP_BINADM_DIR, appelé pmlogconf-setup. Ce script a été retiré. La fonctionnalité équivalente est toujours disponible dans les rares cas où elle est nécessaire via l'option -s ou --setup de pmlogconf(1).

Le format de configuration de l'ancien pmlogconf-setup (d'IRIX) a également été retiré dans cette version, après plus de 10 ans de transition automatique vers le format v2 par pmlogconf.

PMMGR

Le gestionnaire de démons PCP pmmgr a été retiré depuis la version v5.2.0 de PCP. Il a été désactivé au profit du plus simple pmfind(1) pour configurer des ``farms'' de systèmes de collecte PCP pour pmie(1) et pmlogger(1), découverts avec pmfind_check(1). Les nouveaux mécanismes, en particulier lorsqu'ils sont intégrés avec systemd, ne requièrent aucun service supplémentaire et sont mieux intégrés aux services pmie et pmlogger utilisés ailleurs dans PCP.

PCP-COLLECTL

L'outil pcp-collectl a été remplacé par pmrep(1) depuis la version v5 de PCP.

L'équivalent de pcp-collectl dans le reporting des systèmes de collecte est obtenu comme suit :

pmrep :collectl-sc
Vue du sous-système processeur.
pmrep :collectl-sm
Vue du sous-système mémoire.
pmrep :collectl-sd
Vue des disques.
pmrep :collectl-sD
Vue par périphérique disque.
pmrep :collectl-dm-sD
Vue du mapper de périphériques.
pmrep :collectl-sn
Vue du sous-système réseau.

APPLICATIONS WEB PCP

Les applications web distinctes qui étaient incluses avec les anciennes versions de PCP ont été remplacées par grafana-server(1) avec le plugin grafana-pcp https://github.com/performancecopilot/grafana-pcp.

Ce plugin fournit une implémentation de l'application Vector, ainsi que des sources de données pour pmdabpftrace(1) (scripts bpftrace(8)) et pmseries(1) (analyse de séries temporelles rapide, évolutive et distribuée).

PMWEBD

Le démon pmwebd a été remplacé par pmproxy(1) depuis la version v5 de PCP.

Par défaut, pmproxy écoutera maintenant sur ses ports d'origine (44322) et sur le port de l'API web de PCP (44323) lorsque le support des séries temporelles est activé.

pmproxy fournit une implémentation compatible des interfaces actives de PMWEBAPI(3) traditionnellement utilisées par l'application web Vector (voir la section ``APPLICATIONS WEB PCP''). Il fournit également des extensions aux API REST originaux de pmwebd (comme les métriques dérivées, les requêtes d'espace de noms et les profils de domaines d'instances), le support du protocole HTTPS et des requêtes de séries temporelles rapides et évolutives utilisant l'API REST pmseries(1) avec un serveur clé-valeur distribué comme https://valkey.io/).

L'émulation partielle de l'API Graphite fournie par pmwebd n'a pas été réimplémentée ; les applications souhaitant utiliser des services similaires peuvent utiliser les API évolutives de séries temporelles décrites dans PMWEBAPI(3).
