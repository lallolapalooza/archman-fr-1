NAME

PCPIntro - introduction to the Performance Co-Pilot (PCP) libraries

INTRODUCTION

Performance Co-Pilot (PCP) is a toolkit designed for monitoring and managing system-level performance.

The PCP libraries support the APIs required to create new performance monitoring tools and new agents (or PMDAs) to export performance data. The libpcp library is used in both cases. The libpcp_pmda library is used only for PMDAs.

Individual library routines are documented in their own manual page entries.

Most routines return an integer value; greater than equal to zero for success and less than zero for an error. The error codes have symbolic names defined in <pcp/pmapi.h>. Other negative values are used to encode errors that can be mapped to the traditional errno values defined in <errno.h>, with the value negated. To translate all PCP error codes into useful messages use either pmerr(1) or pmErrStr(3); the latter may also be used to decode the -errno cases.

GENERAL ERRORS

These common errors may occur in various PCP interactions.

PM_ERR_TIMEOUT
Timeout waiting for a response from PMCD
Many interactions between PCP applications involve synchronous message passing, and these are subject to timeout constraints. These errors are most frequently encountered when using network connections with slow data rates or long latencies.

For client-pmcd timeouts, refer to PCPIntro(1) for environment variables that may be used to modify the timeout thresholds. For pmcd-PMDA timeouts refer to the -t and -q options of pmcd(1) and the PCP metric pmcd.control.timeout that can be dynamically changed with pmstore(1).

PM_ERR_APPVERSION
Metric not supported by this version of monitored application
Some performance metrics are unavailable from specific versions of the associated PMDA, or may be unavailable because the underlying instrumentation has changed or is not installed or is not enabled. This error is used in results from pmFetch(3) to indicate these situations.
PM_ERR_IPC
IPC protocol failure
Generic protocol failure on a pipe or socket connecting two PCP applications, e.g. client-pmcd, or client-pmtime, or PMDA-pmcd or pmlc-pmlogger.
PM_ERR_TEXT
One-line or help text is not available
Set by a PMDA, and passed back to a PCP client, to indicate that the PMDA is unable to supply the requested metric or instance domain help text.
PM_ERR_VALUE
Missing metric value(s)
This error is used for a number of conditions in which the value of a performance metric is inappropriate for the context in which it is being used, e.g.
(a)
Bad value for the metric pmcd.timezone when trying to set the timezone via pmNewContextZone(3) for a remote or archive context.
(b)
Attempting to interpolate values for a metric with non-numeric data type from a set of PCP archives.
(c)
A bad result data structure passed to pmStore(3).
PM_ERR_NAME
Unknown metric name
Just what the message says.
PM_ERR_PMID
Unknown or illegal metric identifier
Just what the message says.
PM_ERR_INDOM
Unknown or illegal instance domain identifier
A request nominates an instance domain that is unknown or PM_INDOM_NULL. May occur as a consequence of the instance domain identifier passed by a PCP client to pmGetInDom(3), pmLookupInDom(3), pmNameInDom(3), pmGetInDomArchive(3), pmLookupInDomArchive(3), pmNameInDomArchive(3) or a request passed from pmcd(1) to a PMDA.
PM_ERR_EOF
IPC channel closed
End of file on a pipe or socket connecting two PCP applications, e.g. client-pmcd, or client-pmtime or PMDA-pmcd.
PM_ERR_NOCONTEXT
Attempt to use an illegal context
Typically caused by a PCP client that tries to make calls before calling pmNewContext(3) or after calling pmDestroyContext(3).
PM_ERR_PERMISSION
No permission to perform requested operation
PCP-specific access controls apply to pmcd(1) and pmlogger(1). Platform-specific permission errors are returned as -EPERM.
PM_ERR_CONV
Impossible value or scale conversion
Some value conversion requests are illegal, e.g. bad debug flag symbolic name for -D/--debug option, or asking pmExtractValue(3) to translate non-numeric data types to numbers and vice versa.
PM_ERR_TRUNC
Truncation in value conversion
Some conversion requests to pmExtractValue(3) cannot be performed based on the metric types and values involved, in this case conversion would result in loss of precision.
PM_ERR_SIGN
Negative value in conversion to unsigned
Some conversion requests to pmExtractValue(3) cannot be performed based on the metric types and values involved, in this case converting a negative value to an unsigned value.
PM_ERR_TYPE
Unknown or illegal metric type
The metric type is held in the metric descriptor and sometimes encoded in the metric values returned from a call to pmFetch(3). Legal values for the metric type are defined by the PM_TYPE_* macros in <pcp/pmapi.h>.
PM_ERR_UNIT
Illegal pmUnits specification
Some conversion requests to pmConvScale(3) cannot be performed due to illegal or incompatible specifications of the source and destination units.
PM_ERR_PROFILE
Explicit instance identifier(s) required
Some PMDAs, especially the proc PMDA, will not return ``all instances'' for a pmFetch(3) request due to the cost. The client must explicitly built an instance profile using pmAddProfile(3) and/or pmDelProfile(3) before calling pmFetch(3). See also the -F/--fetchall option to pminfo(1).
PM_ERR_INST
Unknown or illegal instance identifier
A request to a PMDA nominates an instance that is unknown. May occur as a consequence of the profile established prior to a pmFetch(3) call, or an explicit instance name or identifier
PM_ERR_MODE
Spécification de mode invalide
Erreur dans la spécification de mode invalide pour pmSetMode(3).
PM_ERR_PROFILESPEC
Profil introuvable
Paramètres invalides passés d'un client PCP à pmAddProfile(3).
PM_ERR_TOOSMALL
Nombre d'éléments insuffisant dans la liste
Erreur de passage de paramètres lors de l'appel à pmFetch(3), pmLookupName(3) ou pmStore(3).
PM_ERR_FAULT
Exception QA injectée
Version de libpcp avec injection d'exception QA, à utiliser lors des tests de qualité PCP (QA).
PM_ERR_THREAD
Opération non supportée dans les applications multi-threads
Comme documenté dans PMAPI(3) et ailleurs, certaines routines de libpcp sont conçues pour être utilisées dans des applications mono-thread uniquement.
PM_ERR_NOCONTAINER
Conteneur introuvable
Le nom du conteneur fourni par l'utilisateur ne correspond à aucun conteneur connu.
PM_ERR_BADSTORE
Entrée invalide pour pmstore
La valeur de la métrique fournie pour une opération pmStore(3) est dans un format invalide, ou d'un type incorrect, ou a un nombre incorrect de valeurs.
PM_ERR_TOOBIG
Taille de résultat dépassée
Indique une erreur grave dans le protocole de transmission de messages (ou PDU) entre deux applications PCP. Il s'agit d'une erreur interne et, à moins d'une défaillance réseau extrême, elle ne devrait pas se produire.
PM_ERR_RESET
Reset de PMCD ou changement de configuration
Non utilisé.

Voir pmFetch(3) pour un mécanisme alternatif qui peut notifier un client PCP lorsque pmcd(1) a subi une ou plusieurs modifications de configuration depuis la dernière requête du client. Ces modifications impliquent généralement un changement dans l'espace de noms exposé par pmcd et/ou des modifications dans les PMDAs sous le contrôle de pmcd.

PM_ERR_FAULT
Exception QA injectée
Utilisé uniquement pour les tests de qualité PCP (QA).
PM_ERR_NYI
Fonctionnalité non implémentée
Explicatif et rarement utilisé.
PM_ERR_GENERIC
Erreur générale, déjà signalée ci-dessus
Rarement utilisé, peut être retourné lorsque l'état d'erreur est consécutif à une erreur précédente et qu'une caractérisation plus précise n'est pas possible.
PM_ERR_BADDERIVE
Définition d'une métrique dérivée échouée
Lors de l'enregistrement d'une métrique dérivée, l'expression de la métrique est incorrecte syntaxiquement ou sémantiquement.
PM_ERR_NOLABELS
Pas de prise en charge des métadonnées de métrique
L'opération nécessite des métadonnées de métrique, mais aucune n'est disponible.

CLIENT-PMCD ERREURS

Ces erreurs peuvent survenir lors de l'interaction entre un client PCP et pmcd(1), qui fournit des données de performance en temps réel.

PM_ERR_NOAGENT
Aucun agent PMCD pour le domaine de la requête
Une requête adressée à pmcd(1) nécessite des informations d'un agent ou d'un PMDA qui n'existe pas. Cela indique généralement que l'espace de noms utilisé par l'application cliente contient des noms de métriques d'un PMDA précédemment installé.
PM_ERR_CONNLIMIT
Limite de connexion pour cet hôte dépassée
La limite de connexion client pour pmcd(1) est contrôlée par les contrôles d'accès dans $PCP_PMCDCONF_PATH. Par défaut, il n'y a pas de limite imposée par le code de libpcp, et cette erreur ne sera donc pas rencontrée.
PM_ERR_AGAIN
Réessayez. Informations non mises à jour
Utilisé pour informer un client PCP que le PMDA responsable de la fourniture des informations est temporairement inaccessible. Voir également PM_ERR_PMDANOTREADY.
PM_ERR_NOPROFILE
Profil manquant - erreur de protocole
Erreur interne dans la communication entre une application cliente et pmcd(1) - ne devrait pas se produire.
PM_ERR_NEEDCLIENTCERT
PMCD nécessite un certificat client
Échec de l'authentification.
PM_ERR_PMDAFENCED
Le PMDA est actuellement isolé et ne peut pas répondre aux requêtes
Un utilisateur privilégié a décidé d'isoler un PMDA de pmcd(1) en utilisant une opération pmStore(1) sur la métrique pmcd.agent.fenced, ce qui signifie que toutes les requêtes de niveau fetch vers ce PMDA sont bloquées.

CLIENT-ARCHIVE ERREURS

Ces erreurs peuvent survenir lors de l'interaction entre un client PCP et les routines de bibliothèque qui fournissent des données de performance historiques à partir d'archives PCP créées avec pmlogger(1).

PM_ERR_LOGFILE
Fichier d'archive manquant
Chaque archive PCP se compose de plusieurs fichiers physiques tels que décrits dans pmlogger(1). Cette erreur se produit lorsqu'un des fichiers physiques est manquant ou ne peut être ouvert en lecture.
PM_ERR_EOL
Fin de l'archive PCP
Tentative de lecture après la fin du dernier fichier de volume d'un ensemble d'archives PCP, ou après la fin de la plage horaire (telle que spécifiée avec une option -T/--finish) d'un ensemble d'archives PCP.
PM_ERR_NOTHOST
Opération nécessitant un contexte avec une source de métriques d'hôte
Les appels à pmStore(3) nécessitent un contexte d'hôte et ne sont pas pris en charge pour les archives PCP.

Pour les archives créées avec des versions antérieures à 4.0 de libpcp, les appels à pmLookupText(3) et pmLookupInDomText(3) retourneront ce code pour les contextes PMAPI d'archives (l'aide et le texte sur une ligne n'étaient pas précédemment enregistrés dans les archives).

PM_ERR_LOGREC
Enregistrement corrompu dans une archive PCP
Les archives PCP peuvent être corrompues pour diverses raisons, mais la plus courante est l'interruption prématurée de pmlogger(1) sans écrire ses buffers de sortie.
PM_ERR_LABEL
Enregistrement d'étiquette invalide au début d'un fichier d'archive PCP
Chaque fichier physique d'une archive PCP doit commencer par un enregistrement d'étiquette commun. Il s'agit d'un cas particulier des erreurs PM_ERR_LOGREC.
PM_ERR_NODATA
Fichier d'archive vide
Un fichier physique vide ne peut jamais faire partie d'une archive PCP valide (au moins l'enregistrement d'étiquette devrait être présent). Il s'agit d'un cas particulier des erreurs PM_ERR_LOGREC.
PM_ERR_NOTARCHIVE
Opération nécessitant un contexte avec une source d'archives de métriques
Un appel à l'une des routines variantes d'archives, c'est-à-dire pmFetchArchive(3), pmGetInDomArchive(3), pmLookupInDomArchive(3) ou pmNameInDomArchive(3), alors que le contexte actuel n'est pas associé à un ensemble d'archives PCP.
PM_ERR_PMID_LOG
Métrique non définie dans l'archive PCP
Un client PCP a demandé des informations sur une métrique, et aucune information correspondante n'est présente dans l'ensemble d'archives PCP. Cela ne devrait pas se produire pour les clients PCP bien comportés.
PM_ERR_INDOM_LOG
Identifiant de domaine d'instances non défini dans l'archive PCP
Un client PCP a demandé des informations sur une métrique d'instances à partir d'une ou plusieurs métriques de performance, et aucune information correspondante n'est présente dans l'ensemble d'archives PCP. Si le client utilise les descriptions de métriques des archives pour identifier le domaine d'instances, cela est moins probable.

Étant donné que les domaines d'instances peuvent varier dans le temps, les clients peuvent avoir besoin d'utiliser les routines variantes pmGetInDomArchive(3) ou pmLookupInDomArchive(3) ou pmNameInDomArchive(3) pour manipuler l'union des instances dans un domaine d'instances pendant la durée de vie d'une archive.

PM_ERR_INST_LOG
Identifiant d'instance non défini dans l'archive PCP
Un client PCP a demandé des informations sur une instance spécifique d'une métrique de performance, et aucune information correspondante n'est présente dans l'ensemble d'archives PCP. Cela ne devrait pas se produire pour les clients PCP bien comportés.
PM_ERR_PMID_LOG
Métrique non définie dans l'archive PCP
Un client PCP a demandé des informations sur une métrique, et aucune information correspondante n'est présente dans l'ensemble d'archives PCP. Cela ne devrait pas se produire pour les clients PCP bien comportés.
