PDF::API2::Basic::PDF::File(3) Documentation Perl contribuée par les utilisateurs PDF::API2::Basic::PDF::File(3)

NOM

PDF::API2::Basic::PDF::File - Accès au fichier PDF de bas niveau

SYNTAXE

$p = PDF::API2::Basic::PDF::File->open("nom_fichier.pdf", 1);
$p->new_obj($ref_obj);
$p->free_obj($ref_obj);
$p->append_file;
$p->close_file;
$p->release;       # IMPORTANT!

DESCRIPTION

Cette classe maintient l'aspect répertoire d'un fichier PDF. Il y a deux parties dans le répertoire : le répertoire racine, qui est le parent de tous les objets, et une chaîne de tables de références croisées et de dictionnaires de fin correspondants, commençant par le répertoire racine.

VARIABLES D'INSTANCE

Au sein de cette hiérarchie de classes, plutôt que de rendre tout accessible via des méthodes, ce qui représenterait un travail énorme, plusieurs variables d'instance sont accessibles via des références de dictionnaire. Pour distinguer les variables d'instance des variables de contenu (qui peuvent provenir du contenu PDF lui-même), chacune de ces variables commencera par un espace.

Les variables ne commençant pas par un espace reflètent des éléments d'un dictionnaire PDF. Dans le cas de PDF::API2::Basic::PDF::File, les éléments reflètent ceux d'un dictionnaire de fin.

Comme certaines variables ne sont pas destinées à être consultées par les utilisateurs, elles sont marquées dans la documentation par (R) pour indiquer que cette entrée ne doit être utilisée qu'en lecture seule. (P) indique que l'information est privée et n'est pas destinée à l'usage de l'utilisateur, mais est incluse dans la documentation pour garantir que personne n'essaie de l'utiliser.

newroot
Cette variable permet de créer une nouvelle entrée de racine pour qu'elle apparaisse dans le dictionnaire de fin, qui est généré lors de l'écriture ou de l'ajout du fichier. Si vous souhaitez écraser l'élément racine du dictionnaire, utilisez cette entrée pour indiquer de ne pas perdre l'élément racine actuel. Notez que newroot doit pointer vers un objet de niveau PDF, pas seulement vers un dictionnaire qui n'a pas d'état d'objet.
INFILE (R)
Contient le handle de fichier utilisé pour lire ces informations dans ce répertoire PDF. C'est un objet IO.
fname (R)
C'est le nom de fichier qui est reflété dans INFILE, ou l'objet IO d'origine qui a été passé.
update (R)
Indique que le fichier lu a été ouvert en mode mise à jour et que, à un moment donné, $p->appendfile() peut être appelé pour mettre à jour le fichier avec les modifications apportées à la représentation en mémoire.
maxobj (R)
Contient le plus petit numéro d'objet disponible supérieur à tous ceux qui sont déjà apparus dans le fichier jusqu'à présent.
outlist (P)
C'est une liste d'Objind qui seront affichées lorsque appendfile ou outfile sera activé.
firstfree (P)
Contient le premier objet libre dans la liste des objets libres. Les objets libres sont retirés de l'avant de la liste et ajoutés à la fin.
lastfree (P)
Contient le dernier objet libre dans la liste des objets libres. Il peut être le même que firstfree s'il n'y a qu'un seul objet libre.
objcache (P)
Chaque objet est conservé dans le cache pour garantir qu'un système n'ait qu'une seule occurrence de chaque objet. En effet, la classe objind agit comme une classe conteneur de type classe pour stocker la structure des objets PDF, et elle serait inutile s'il y avait plusieurs emplacements identiques flottant dans un système.
epos (P)
La position finale du fichier lu.

Chaque dictionnaire de fin contient plusieurs variables d'instance privées qui stockent la chaîne de références.

loc (P)
Contient l'emplacement du début de la table des références croisées qui précède la fin.
xref (P)
Contient un tableau anonyme de chaque entrée de la table des références croisées.
prev (P)
Un pointeur vers la table précédente. Notez que cela diffère de l'entrée Prev, qui contient l'emplacement de la table des références croisées précédente.

MÉTHODES

PDF::API2::Basic::PDF::File->new

Crée un nouvel objet de fichier vide qui peut agir comme hôte pour d'autres objets PDF. Comme il n'a pas de fichier associé, on suppose que l'objet a été créé en préparation de la création d'un nouveau fichier PDF.

$p = PDF::API2::Basic::PDF::File->open($filename, $update)

Ouvre le fichier et lit toutes les fins et tables de références croisées pour construire un répertoire complet d'objets.

$update indique si le fichier est ouvert pour mise à jour et édition, ou simplement pour lecture.

$filename peut être un objet IO.

$p->version($version)

Obtient/définit la version du PDF (exemple : 1.4).

$version = $p->header_version($version)

Obtient/définit la version du PDF enregistrée dans l'en-tête du fichier.

$version = $p->trailer_version($version)

Obtient/définit la version du PDF enregistrée dans le catalogue du document.

$prev_version = $p->require_version($version)

Garantit que la version du PDF est au moins $version.

$p->release()

Libère toute la mémoire utilisée par le document PDF et tous ses composants. Après avoir appelé cette méthode, ne vous attendez à rien de restant dans l'objet "PDF::API2::Basic::PDF::File" (donc si vous avez besoin de sauvegarder, faites-le avant d'appeler cette méthode).

NOTE, il est important d'appeler cette méthode sur tout objet "PDF::API2::Basic::PDF::File" lorsque vous le désinitialisez et libérez sa mémoire. En interne, les fichiers PDF ont un grand nombre de références croisées, ce qui provoque des références cycliques dans les structures internes. L'appel à release() force une suppression forcée des structures, libérant toute la mémoire. Même après avoir appelé cette méthode, ne vous attendez pas à pouvoir faire autre chose avec l'objet "PDF::API2::Basic::PDF::File" ; il sera dans un état interne nul.

$p->append_file()

Ajoute les objets pour la sortie vers le fichier, puis ajoute la table appropriée.

$p->out_file($fname)

Écrit un fichier PDF dans un fichier portant le nom donné, selon la liste actuelle des objets à sortir. Crée le dictionnaire de fin basé sur les informations de $self.

$fname peut être un objet IO ;

MÉTHODES

La classe PDF::API2::Basic::PDF::File implémente les méthodes suivantes :

$p->open($fname, $mode)

Ouvre le fichier spécifié par $fname pour la lecture ou l'écriture. Le mode $mode peut être r pour lire, w pour écrire, ou a pour ajouter.

Si $fname est omis, il utilise le fichier actuellement ouvert.

Retourne undef en cas d'erreur.

$p->open_file($fname)

Ouvre le fichier spécifié par $fname pour l'écriture. La sortie PDF sera écrite dans ce fichier. Un descripteur de fichier peut être passé à la place d'un nom de fichier.

Si aucun fichier n'est spécifié, il est supposé que le fichier est le fichier ouvert lors de la création de l'objet PDF.

$p->set_version($version)

Définit la version du PDF qui sera généré. La version est un flottant (par exemple, 1.3). Il est recommandé de s'assurer que la variable $p->{' version'} est correctement définie avant d'appeler cette fonction.

$p->clone_file($fname)

Crée une copie du fichier d'entrée au nom de fichier spécifié et l'utilise comme fichier de sortie pour les écritures futures. Un descripteur de fichier peut être passé à la place d'un nom de fichier.

$p->close_file

Ferme le fichier ouvert en sortie en écrivant la bande finale, etc.

($value, $str) = $p->readval($str, %opts)

Lit une valeur PDF depuis la position actuelle dans le fichier. Si $str est trop court, lit davantage depuis la position actuelle dans le fichier jusqu'à ce que tout l'objet soit lu. Ceci est un appel récursif qui peut ingérer un flux entier (non traité).

Retourne la structure de données récursive lue et également la valeur actuelle de $str qui a été lue depuis le fichier.

$ref = $p->read_obj($objind, %opts)

Étant donné une référence d'objet indirect, la localise et lit l'objet, retournant l'objet lu.

$ref = $p->read_objnum($num, $gen, %opts)

Retourne un objet complètement lu du numéro et de la génération donnés dans ce fichier.

$objind = $p->new_obj($obj)

Crée une nouvelle référence d'objet libre basée sur l'espace libre dans la chaîne de références croisées. S'il n'y a rien de libre, il invente un nouveau numéro. Si $obj est défini, transforme cet objet en ce nouvel objet plutôt que de retourner un nouvel objet.

$p->out_obj($objind)

Indique que la référence d'objet donnée doit apparaître dans le tableau de références croisées de sortie, qu'elle contienne des données ou qu'elle soit libérée.

$p->free_obj($objind)

Marque une référence d'objet pour sortie comme étant libérée.

$p->remove_obj($objind)

Supprime l'objet de tous les endroits où nous pourrions nous en souvenir.

$p->ship_out(@objects)

Envoie les objets donnés (ou tous les objets à envoyer en sortie si @objects est vide) vers le fichier de sortie actuellement ouvert (en supposant qu'il y en ait un). Les objets libérés ne sont pas envoyés, et une fois qu'un objet est envoyé, il est basculé de telle sorte que ce fichier devienne sa source et il ne sera pas renvoyé à moins que out_obj ne soit appelé à nouveau. Notez qu'un objet expédié peut être réémis ou même libéré, mais cela ne fera pas en sorte que les données déjà envoyées soient modifiées.

$p->copy($outpdf, \&filter)

Itère sur chaque objet du fichier, lit l'objet, appelle le filtre avec l'objet et diffuse le résultat. Si le filtre n'est pas défini, il copie simplement l'entrée vers la sortie.

MÉTHODES ET FONCTIONS PRIVÉES

Les méthodes et fonctions suivantes sont considérées comme privées pour cette classe. Cela ne signifie pas que vous ne pouvez pas les utiliser si vous en avez besoin, simplement qu'elles ne sont pas vraiment conçues pour les utilisateurs de cette classe.

$offset = $p->locate_obj($num, $gen)

Retourne un décalage de fichier vers l'objet demandé en suivant la chaîne des tables de références croisées jusqu'à ce qu'il trouve celle que vous voulez.

update($fh, $str, $instream)

Continue à lire $fh pour plus de données afin de s'assurer que $str contient au moins une ligne complète pour que "readval" puisse fonctionner. À ce moment, nous profitons également de l'occasion pour ignorer les commentaires.

$objind = $p->test_obj($num, $gen)

Teste le cache pour voir si une référence d'objet (qui peut avoir été ou non getobj()ée) a été mise en cache. La retourne si c'est le cas.

$p->add_obj($objind)

Ajoute l'objet donné au cache d'objets interne.

$tdict = $p->readxrtr($xpos)

Fonction récursive qui lit successivement chacune des tables de références croisées et des tables de remorque jusqu'à ce qu'il n'y en ait plus.

Retourne un dictionnaire correspondant à la chaîne des remorques. Chaque remorque inclut également la table de références croisées correspondante.

La structure de l'élément privé xref dans un dictionnaire de remorque est celle d'une table de hachage anonyme d'éléments de références croisées par numéro d'objet. Chaque élément se compose d'un tableau de 3 éléments correspondant aux trois éléments lus [emplacement, numéro de génération, libre ou utilisé]. Voir la spécification PDF pour les détails.

$p->out_trailer($tdict)

Écrit le corps et la remorque d'un fichier PDF en écrivant tous les objets de la liste 'outlist', puis en écrivant une table de références croisées pour ces objets et tous les objets libérés. Il écrit ensuite le dictionnaire de remorque et le code de remorque.

PDF::API2::Basic::PDF::File->_new

Crée un objet de fichier PDF très vide (utilisé par new et open).
