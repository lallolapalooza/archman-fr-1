NOM

PDF::Builder::Content::Text - Méthodes supplémentaires spécialisées liées au texte

Hérite de PDF::Builder::Content

Note : Si vous avez utilisé certaines de ces méthodes dans PDF::Builder avec un objet de type graphique (par exemple, $page->gfx()->method()), vous devrez peut-être passer à un objet de type texte (par exemple, $page->text()->method()).

MÉTHODES

Lignes uniques à partir d'une chaîne

text_left

$width = $content->text_left($text, %opts)
Alias de "text". Implémenté par symétrie, pour ceux qui utilisent beaucoup "text_center" et "text_right", et désirent un "text_left" correspondant.

Ajoute du texte à la page (justifié à gauche), à la position actuelle. Notez qu'il n'y a pas de largeur maximale, et rien pour vous empêcher de déborder physiquement de la page sur la droite ! La largeur utilisée (en points) est retournée.

text_center

$width = $content->text_center($text, %opts)
Comme "text", mais centré au point actuel.

Ajoute du texte à la page (centré). La largeur utilisée (en points) est retournée.

text_right

$width = $content->text_right($text, %opts)
Comme "text", mais aligné à droite au point actuel.

Ajoute du texte à la page (justifié à droite). Notez qu'il n'y a pas de largeur maximale, et rien pour vous empêcher de déborder physiquement de la page sur la gauche ! La largeur utilisée (en points) est retournée.

text_justified

$width = $content->text_justified($text, $width, %opts)
Comme "text", mais étire le texte en utilisant "wordspace", "charspace", et (en dernier recours) "hscale", pour remplir la $width désirée (disponible). Notez que si la largeur désirée est inférieure à la largeur naturelle prise par le texte, elle sera condensée pour s'adapter, en utilisant les trois mêmes routines.

La $width inchangée est retournée, sauf s'il y a eu une raison de la modifier (par exemple, débordement).

Options :

'nocs' => value
Si cette option vaut 1 (par défaut 0), ne pas utiliser d'espacement inter-caractères. Ceci est utile pour les caractères connectés, tels que les polices pour l'arabe, le devanagari, l'écriture manuscrite cursive latine, etc. Vous ne voulez pas ajouter d'espace supplémentaire entre les caractères lors de la justification, ce qui les déconnecterait.

Les valeurs d'espacement de mots (inter-mots) (explicites ou par défaut) sont doublées si nocs vaut 1. Ceci afin de compenser le manque d'espacement inter-caractères ajouté/soustracté.

'wordsp' => value
Le pourcentage d'un caractère espace (par défaut 100) qui constitue la quantité maximale à ajouter (à chaque) espacement inter-mots pour étendre la ligne. Si "nocs" vaut 1, doubler "value".
'charsp' => value
Si l'ajout d'espace de mots n'a pas été suffisant, le pourcentage d'un em (par défaut 100) qui constitue la quantité maximale à ajouter (à chaque) espacement inter-caractères pour étendre davantage la ligne. Si "nocs" vaut 1, forcer "value" à 0.
'wordspa' => value
Si l'ajout d'espace de mots n'a pas été suffisant, le pourcentage d'un caractère espace (par défaut 100) qui constitue la quantité maximale supplémentaire à ajouter (à chaque) espacement inter-mots pour étendre davantage la ligne. Si "nocs" vaut 1, doubler "value".
'charspa' => value
Si l'ajout d'espace de mots supplémentaire n'a pas été suffisant, le pourcentage d'un em (par défaut 100) qui constitue la quantité maximale supplémentaire à ajouter (à chaque) espacement inter-caractères pour étendre davantage la ligne. Si "nocs" vaut 1, forcer "value" à 0.
'condw' => value
Le pourcentage d'un caractère espace (par défaut 25) qui constitue la quantité maximale à soustraire (de chaque) espacement inter-mots pour condenser la ligne. Si "nocs" vaut 1, doubler "value".
'condc' => value
Si la suppression d'espace de mots n'a pas été suffisante, le pourcentage d'un em (par défaut 10) qui constitue la quantité maximale à soustraire (de chaque) espacement inter-caractères pour condenser davantage la ligne. Si "nocs" vaut 1, forcer "value" à 0.

Si les changements d'expansion (ou de réduction) d'espacement de mots et de caractères n'ont pas suffi à faire tenir la ligne dans la largeur désirée, utilisez hscale() pour terminer l'expansion ou la condensation de la ligne afin qu'elle tienne.

Lignes multiples à partir d'une chaîne

La chaîne est divisée aux espaces réguliers (espaces, x20) pour trouver la plus longue sous-chaîne qui rentrera dans la $width. Si un seul mot est plus long que $width, il débordera. Pour rester strictement dans les limites désirées, définissez l'option "spillover"=>0 pour interdire le débordement.

Césure

Si la césure est activée, les méthodes qui divisent une chaîne en plusieurs lignes (les méthodes de remplissage de texte, de paragraphe et de section) tenteront de diviser le mot qui déborde de la ligne, afin de compacter le texte encore plus ("césure gloutonne" des lignes). Il existe un certain nombre de contrôles sur l'endroit où un mot peut être divisé, mais notez qu'il n'y a rien de spécifique à une langue (c'est-à-dire qu'il ne suit pas les règles d'une langue donnée pour l'endroit où un mot peut être divisé). Ceci est laissé à d'autres paquets.

Il existe des minimums codés en dur de 2 lettres avant la division, et 2 lettres après la division. Voir "Hyphenate_basic.pm". Notez que ni la césure ni la simple division de ligne ne tentent d'empêcher les veuves et les orphelins, d'empêcher la division du dernier mot dans une colonne ou une page, ou de s'engager autrement dans une mise en forme de paragraphe plus souhaitable.

'hyphenate' => value
0 : pas de césure (par défaut), 1 : effectuer une césure basique. Permet toujours de diviser à un trait d'union logiciel (\xAD). Le trait d'union Unicode (U+2010) et le trait d'union non-séparable (U+2011) sont ignorés comme points de division.
'spHH' => value
0 : ne pas diviser à un trait d'union (\x2D), 1 : OK pour diviser (par défaut)
'spOP' => value
0 : ne pas diviser après la plupart des signes de ponctuation, 1 : OK pour diviser (par défaut)
'spDR' => value
0 : ne pas diviser après une séquence d'un ou plusieurs chiffres, 1 : OK pour diviser (par défaut)
'spLR' => value
0 : ne pas diviser après une séquence d'une ou plusieurs lettres ASCII, 1 : OK pour diviser (par défaut)
'spCC' => value
0 : ne pas diviser en camelCase entre une lettre minuscule et une lettre majuscule, 1 : OK pour diviser (par défaut)
'spRB' => value
0 : ne pas diviser sur un Espace Requis (&nbsp;), est le défaut. 1 : OK pour diviser sur un Espace Requis. Essayez d'éviter cela ; c'est un coup de désespoir !
'spFS' => value
0 : ne pas diviser là où cela tiendrait juste (milieu d'un mot !), est le défaut. 1 : OK pour diviser afin de remplir juste l'espace disponible. Essayez d'éviter cela ; c'est un coup de désespoir extrême, et la division n'aura probablement aucun sens linguistique !
'min_prefix' => value
Nombre minimum de lettres avant le point de division du mot (point de césure). Le défaut est 2.
'min_suffix' => value
Nombre minimum de lettres après le point de division du mot (point de césure). Le défaut est 3.

Méthodes

text_fill_left, text_fill

($width, $leftover) = $content->text_fill_left($string, $width, %opts)
Remplit une ligne de 'width' avec autant de texte que possible, et l'affiche justifié à gauche. La largeur réellement utilisée, et le texte restant (qui n'a pas tenu), sont retournés.
($width, $leftover) = $content->text_fill($string, $width, %opts)
Alias de text_fill_left().

Segments de texte plus grands

paragraph

($overflow_text, $unused_height) = $txt->paragraph($text, $width,$height, $continue, %opts)
($overflow_text, $unused_height) = $txt->paragraph($text, $width,$height, %opts)
$overflow_text = $txt->paragraph($text, $width,$height, $continue, %opts)
$overflow_text = $txt->paragraph($text, $width,$height, %opts)
Imprime une seule chaîne dans une zone rectangulaire de la page, de largeur et de hauteur maximales données. La ligne de base de la première ligne (en haut) est à la position actuelle du texte.

Applique le texte à l'intérieur du rectangle et retourne tout texte restant (s'il n'a pas pu tenir entièrement dans le rectangle). Si appelé dans un contexte de tableau, la hauteur inutilisée est également retournée (peut être 0 ou négative s'il a juste rempli le rectangle).

$continue est facultatif, avec une valeur par défaut de 0. Une liste %opts peut être donnée après les paramètres fixes, que $continue soit explicitement donné ou non.

Si $continue est 1, la première ligne ne reçoit pas de traitement spécial pour l'indentation ou la sortie, car nous imprimons la continuation du paragraphe qui a été interrompu précédemment. S'il est 0, la première ligne peut être indentée ou sortie.

Options :

'pndnt' => $indent
Donne le montant de l'indentation (positive) ou de la sortie (négative, pour une "accroche") pour les premières lignes de paragraphe). Ce réglage est ignoré pour le texte centré.
'align' => $choice
$choice est 'justified', 'right', 'center', 'left' ; la valeur par défaut est 'left'. Voir "text_justified" pour les options permettant de contrôler comment une ligne est étendue ou condensée si $choice est 'justified'. $choice peut être abrégé en première lettre.
'last_align' => place
où place est 'left' (par défaut), 'center', ou 'right' (peut être abrégé en première lettre) vous permet de spécifier l'alignement de la dernière ligne affichée, mais ne s'applique que lorsque "align" est 'justified'.
'underline' => $distance
'underline' => [ $distance, $thickness, ... ]
Si un scalaire, distance sous la ligne de base, sinon une référence de tableau avec des paires de distance et d'épaisseur de ligne.
'spillover' => $over
Contrôle si les mots d'une ligne qui dépassent la largeur donnée doivent être "débordés" des limites, ou si une nouvelle ligne doit être utilisée pour ce mot.

$over est 1 ou 0, avec la valeur par défaut 1 (déborde de la largeur).

Exemple :

$txt->font($font,$fontsize);
$txt->leading($leading);
$txt->translate($x,$y);
$overflow = $txt->paragraph( 'long paragraphe ici ...',
                             $width,
                             $y+$leading-$bottom_margin );

Note : si vous avez besoin de changer un traitement de texte quelconque à l'intérieur d'un paragraphe (texte en gras ou en italique, par exemple), cela ne peut pas être géré. Seul le texte brut (toute la même police, taille, etc.) peut être composé avec paragraph(). De plus, il y a actuellement une césure de ligne très limitée (hyphenation) pour mieux s'adapter à une largeur donnée, et rien n'est fait pour les "veuves et orphelins".

section, paragraphs

($overflow_text, $continue, $unused_height) = $txt->section($text, $width,$height, $continue, %opts)
$overflow_text = $txt->section($text, $width,$height, $continue, %opts)
Le $text contient une chaîne avec un ou plusieurs paragraphes de largeur $width, à partir de la position actuelle du texte, avec un retour à la ligne \n entre chaque paragraphe. Chaque paragraphe est affiché (voir "paragraph") jusqu'à ce que la limite $height soit atteinte (un paragraphe partiel peut se trouver en bas). Ce qui n'a pas été affiché sera retourné. Si appelé dans un contexte de tableau, la hauteur inutilisée et le drapeau "continue" du paragraphe sont également retournés.

$continue est 0 pour le premier appel de section(), puis utilisez la valeur retournée de l'appel précédent (1 si un paragraphe a été coupé en milieu) pour éviter les indentations ou sorties indésirables de la première ligne imprimée.

Pour la compatibilité avec les changements récents de PDF::API2, paragraphs est accepté comme un alias pour "section".

Options :

'pvgap' => $vertical
Espace vertical supplémentaire (unité : pt) entre les paragraphes (par défaut 0). Notez que cet espace sera également ajouté après le dernier paragraphe imprimé.

Voir "paragraph" pour les autres %opts que vous pouvez utiliser, tels que "align" et "pndnt".

Nom alternatif : paragraphs

Ceci est pour la compatibilité avec PDF::API2.

textlabel

$width = $txt->textlabel($x,$y, $font, $size, $text, %opts)
Place une ligne de texte à une position arbitraire "[$x,$y]" sur la page, avec divers réglages de texte (traitements) spécifiés dans l'appel.
$font
Une police précédemment créée.
$size
La taille de la police (points).
$text
Le texte à imprimer (une seule ligne).

Options :

'rotate' => $deg
Fait pivoter de $deg degrés dans le sens antihoraire par rapport à l'Est.
'color' => $cspec
Un nom de couleur ou une spécification autorisée, tel que "#CCE840", pour le remplissage des caractères.
'strokecolor' => $cspec
Un nom de couleur ou une spécification autorisée, tel que "#CCE840", pour le contour des caractères.
'charspace' => $cdist
Distance supplémentaire entre les caractères.
'wordspace' => $wdist
Distance supplémentaire entre les mots.
'hscale' => $hfactor
Mode de mise à l'échelle horizontale (pourcentage de la normale, par défaut 100).
'render' => $mode
Mode de rendu des caractères (contour seul, remplissage seul, etc.). Voir l'appel "render".
'left' => 1
Aligner à gauche sur le point donné. C'est la valeur par défaut.
'center' => 1
Centrer le texte sur le point donné.
'right' => 1
Aligner à droite sur le point donné.
'align' => $placement
Alternative à gauche, centre, et droite. $placement est 'left' (par défaut), 'center', ou 'right'.

D'autres options disponibles pour "text", comme le soulignement, peuvent être utilisées ici.

La largeur utilisée (en points) est retournée.

Veuillez noter que textlabel() n'a pas été conçu pour interopérer avec d'autres opérations de texte. C'est une opération autonome et elle ne laisse pas de position "prochain écrit" (ou tout autre réglage) pour une autre opération en mode "text". Un écrit suivant sera probablement à "(0,0)", et non à la position attendue.

textlabel() est destiné à être une fonction de commodité "tout en un" pour les lignes de texte uniques, comme une étiquette sur des graphiques, et non comme partie de la mise en place de plusieurs éléments de texte. Il est possible de déterminer la position d'un écrit suivant (soit "textlabel", soit "text") en ajoutant la largeur retournée à la valeur x de la position d'origine (en supposant un positionnement à gauche).

Sortie de colonne complexe avec balisage

column

($rc, $next_y, $unused) = $text->column($page, $text, $grfx, $markup, $txt, %opts)
Cette méthode remplit une colonne de texte sur une page, renvoyant toute portion inutilisée qui n'a pas pu être insérée, et où elle s'est arrêtée sur la page.

Les noms de balises, les entrées CSS, le type de balisage, etc., sont sensibles à la casse (généralement des lettres minuscules uniquement). Par exemple, vous ne pouvez pas donner un paragraphe <P> en HTML ou un sélecteur P en style CSS.

$page est le contexte de la page. Actuellement, sa seule utilisation est pour les annotations de page pour les liens ('md1' []() et 'html' <a>), donc si vous ne les utilisez pas, vous pouvez passer n'importe quoi comme "undef" pour $page si vous le souhaitez.

$text est le contexte du texte, de sorte que diverses opérations de police et de sortie de texte puissent être effectuées. C'est souvent, mais pas nécessairement toujours, le même objet que celui qui contient la méthode "column".

$grfx est le contexte graphique (gfx). Il peut s'agir d'un dummy (par exemple, undef) si aucun graphique ne doit être dessiné, mais des éléments graphiques tels que le contour de la colonne ('outline' option) un

(règle horizontale) sera utilisée. Actuellement, text-decoration soulignement (par défaut pour les liens, 'md1') "[]()" et 'html' "<a>") ou barré ouoverline utilisent le contexte du texte, mais à l'avenir, un contexte graphique valide peut être requis. Les images (lorsqu'elles seront implémentées) nécessiteront un contexte graphique.

$markup est une information sur le type de markup utilisé pour le formatage et la mise en page du texte de la colonne :

'pre'
Le matériel d'entrée a déjà été traité et est dans le format souhaité. $txt est une liste d'index de hachages. Ceci doit être utilisé lors de l'appel à column() une deuxième (ou ultérieure) fois pour obtenir le matériel restant du premier appel. Il peut également être utilisé lorsque l'appelant a déjà traité le texte dans le format approprié et qu'aucun autre type de markup n'est utilisé.
'none'
Si 'none' est spécifié, aucun markup n'est utilisé. Au maximum, un espace blanc ou un nouvel élément de texte spécifie un nouveau paragraphe, et c'est tout. $txt peut être une chaîne unique ou un tableau (liste) de chaînes.

L'entrée txt est une liste (référence de tableau anonyme) de chaînes, chacune contenant un ou plusieurs paragraphes et d'autres markups. Une seule chaîne peut également être fournie. Un espace blanc entre les paragraphes peut être utilisé pour séparer les paragraphes. Les paragraphes ne peuvent pas s'étendre sur les éléments du tableau.

Il existe d'autres types de markup, donc d'autres types de mdn peuvent être définis à l'avenir, tels que le code POD de Perl.

'md1'
Ceci spécifie un certain type de Markdown compatible avec Text::Markdown : 
* ou _ italique, ** gras, *** gras + italique ; 
    liste à puces *, liste numérotée 1. 2. etc. ; 
    #, ## etc. titres et sous-titres ; 
    ---, ===, ___ règle horizontale ;
    [label](URL) liens externes (vers une page HTML ou dans ce document, voir 'a') ;
    ` (apostrophes) section de code

HTML (voir ci-dessous) peut être mélangé à volonté (bien que pas dans les blocs de code délimités par des apostrophes, où <, > et & sont convertis en entités HTML, désactivant les balises prévues). Le Markdown sera converti en HTML, qui sera ensuite interprété en PDF. Notez que Text::Markdown peut produire du HTML pour certains aspects, qui ne sont pas encore pris en charge par le traitement HTML (voir la section 'html'). Veuillez prévenir si vous avez besoin d'une telle fonctionnalité !

L'entrée txt est une liste (référence de tableau anonyme) de chaînes, chacune contenant un ou plusieurs paragraphes et d'autres markups. Une seule chaîne peut également être fournie. Selon le formatage Markdown, un espace blanc entre les paragraphes peut être utilisé pour séparer les paragraphes. Les éléments de tableau séparés seront d'abord joints en une seule chaîne avant le traitement, permettant aux paragraphes de s'étendre sur les éléments de tableau si désiré.

Il existe d'autres types de Markdown, donc d'autres mdn peuvent être définis à l'avenir, comme le code POD de Perl.

'html'
Ceci spécifie qu'un sous-ensemble de balisage HTML sera utilisé avec certains attributs et CSS. Actuellement, les balises HTML standard : 
'i'/'em' (italique), 'b'/'strong' (gras), 
    'p' (paragraphe), 
    'font' (nom de police - font-family, couleur - color, taille - font-size), 
    'span' (nécessite un attribut style= avec CSS pour faire quelque chose d'utile), 
    'ul', 'ol', 'li' (listes à puces, numérotées), 
    'img' (TBD, image, vide. hspace - margin-left/right, vspace - margin-top/bottom, width, height), 
    'a' (lien/hyperlien, URL de page web ou cible dans ce document #p[-x-y[-z]]), 
    'pre', 'code' (TBD, blocs préformatés et de code), 
    'h1' à 'h6' (titres), 
    'hr' (règle horizontale), 
    'br' (TBD, sauts de ligne, vide), 
    'sup', 'sub' (TBD, exposant et indice), 
    's', 'strike', 'del' (barré), 
    'u', 'ins' (souligné), 
    'blockquote' (citation de bloc)

et d'autres balises HTML non standard (extensions).

'_marker' (permet de modifier les marqueurs de liste. s'il est fourni, il doit être immédiatement avant une balise <li>. attributs : style). le texte du marqueur sera rempli pour vous (s'il est vide ou blanc), et une boîte de fermeture est facultative si le texte du marqueur est vide.
'_move' (permet de se déplacer n'importe où dans la base actuelle. utile pour le positionnement avant le centrage et l'alignement à droite avec la propriété text-align CSS. attributs : x = N nombre sans espace (pts), Npt, ou N% 0/0% = gauche, 50% = centre, 100% = droite, nouvelle position relative au début de la ligne et à la largeur de la ligne.
   attention : si vous vous déplacez vers le bord dans l'une ou l'autre direction, les résultats seront imprévisibles)
'_sl' (liste simple, comme 'ul' mais sans marqueur)
'_ovl' (TBD -- exposant similaire à l'indice/barré)
'_k' (TBD -- décalage de crénage gauche/droite. haut/bas aussi ?)

sont pris en charge (entièrement ou partiellement sauf 'TBD'), ainsi que CSS limité pour la couleur, la taille de police, le nom de police, etc. <style> peut être placé dans une section optionnelle <head> ou à l'intérieur de <body>. Dans ce dernier cas, les balises de style seront extraites du corps et ajoutées (dans l'ordre) à la fin de tout groupe de balises de style défini dans une section de tête. Plusieurs balises de style seront condensées en un seul groupe (les définitions ultérieures ayant une priorité égale aux précédentes). Ces styles auront un effet global, comme s'ils étaient définis dans l'en-tête. Comme avec le CSS normal, la hiérarchie d'une propriété donnée (par ordre de priorité décroissante) est :

apparition dans un attribut style= d'une balise
apparition dans un attribut de balise (nom potentiellement différent de la propriété)
apparition dans un sélecteur #IDname d'un <style>
apparition dans un sélecteur .classname d'un <style>
apparition dans un sélecteur de nom de balise d'un <style>

Les sélecteurs sont assez simples : un seul nom de balise (par exemple, body), une classe (.cname), ou un ID (#iname). Il n'y a pas de combinaisons (par exemple, "p.abstract" ou "ol, ul"), de hiérarchies (par exemple, "ol > li"), de nombre d'occurrences spécifié, ou de complications similaires au CSS d'un navigateur. Désolé !

[*] Note sur list-style-position : 'outside' (par défaut) = 100 (%) retrait, 'inside' = 0 retrait, valeur numérique (exprimée en %) = pourcentage entre inside/0 et outside/100, ou une longueur en pts. Une valeur numérique est une extension du CSS.

[**] Note sur text-align : si vous alignez au centre ou à droite, gardez le texte suffisamment court pour qu'il tienne dans les limites gauche et droite du paragraphe. L'alignement au centre et à droite nécessite une position explicite (généralement via <_move>) et ne s'ajustera pas correctement à une nouvelle ligne.

Propriétés CSS non standard. Vous pourriez vouloir les définir en CSS :

_marker-before (texte constant à insérer avant le marqueur <ol>, par défaut rien)
_marker-after (texte constant à insérer après le marqueur <ol>, par défaut un point)
_marker-text (définit le texte à utiliser comme marqueur à la place du marqueur par défaut)
_marker-color (change la couleur par rapport à la couleur par défaut, par exemple, la couleur des titres de liste)
_marker-font (change la police du marqueur)
_marker-style (change le style de la police du marqueur, par exemple, italique)
_marker-size (change la taille de la police du marqueur)
_marker-weight (change le poids de la police du marqueur)
_marker-align (aligner à gauche/centre/droite dans _marker_width)
list-style-position numérique (voir les notes ci-dessus)

Il existe également les paramètres "marker_width" et "marker_gap" (voir ci-dessus) qui positionnent la première ligne de l'élément de liste uniformément, permettant à toutes les listes de s'aligner plus ou moins.

Note : éventuellement, nous pourrions prendre en charge "li::marker", qui est maintenant du CSS standard, mais il ne semble pas y avoir de moyen de prendre en charge les modifications via "style=", car les mêmes noms de propriétés (par exemple, color) s'appliquent à la fois au texte du marqueur et au texte de l'élément de liste. Cela nécessite des changements importants dans le style CSS pour permettre des sélections complexes, ce que column() n'offre pas actuellement. Même si cela était fait, nous pourrions conserver les balises "marker" actuelles et le CSS introduit ici. Je pense que le W3C aurait pu négliger un "_marker" optionnel pour permettre des propriétés normales pour les marqueurs, mais configurables en ligne avec "style=").

Propriétés CSS non standard. Ne sont généralement pas définies dans CSS :

_fs (taille de police actuelle en points dans la pile de propriétés)
_href (URL pour <a>, normalement fournie par l'attribut href=)
_left (nombre de points pour indenter à gauche, depuis margin-left et le nesting de liste)
_left_nest (montant pour indenter la prochaine liste imbriquée)
_right (nombre de points pour indenter à droite, depuis margin-right)

Les tailles peuvent être en % (de la taille de la police) ou en pt (unité par défaut). Plus de prise en charge pourrait être ajoutée à l'avenir. ATTENTION : les commentaires /* et */ ne sont actuellement pas pris en charge dans le CSS - peut-être à l'avenir.

Les entités numériques (décimales &#nnn; et hexadécimales &#xnnn;) sont prises en charge, ainsi que les entités nommées (&mdash; par exemple).

L'entrée txt est une liste (référence de tableau anonyme) de chaînes, chacune contenant un ou plusieurs paragraphes et d'autres markups. Une seule chaîne peut également être fournie. Selon la pratique normale du HTML, les balises de paragraphe doivent être utilisées pour marquer les paragraphes. Notez que HTML::TreeBuilder est configuré pour marquer automatiquement le texte de niveau supérieur du corps avec des balises de paragraphe, au cas où vous oublieriez de le faire, bien qu'il soit probablement préférable de le faire vous-même pour conserver plus de contrôle sur le traitement. Les éléments de tableau séparés seront d'abord joints en une seule chaîne avant le traitement, permettant aux paragraphes de s'étendre sur les éléments de tableau si désiré.

Le moteur de mise en page peut prendre en charge des balises HTML et des propriétés CSS étendues supplémentaires afin de mieux contrôler la mise en page du document, telles que des contrôles pour forcer un saut de page à un point désiré sous une condition donnée. Les listes simples (sans marqueurs) et de définition, ainsi qu'au moins une mise en page de tableau basique, sont à l'étude. Du CSS supplémentaire non standard pourra également être ajouté.

Il existe d'autres langages de balisage, tels que Pango (similaire à HTML), les pages de manuel (similaires à nroff) et le POD de Perl, qui pourraient être pris en charge à l'avenir. Il est très peu probable que TeX ou LaTeX soient jamais pris en charge, car ils disposent déjà tous deux d'une excellente sortie PDF.

$txt est le texte d'entrée : une chaîne, une référence de tableau vers plusieurs chaînes ou une référence de tableau vers des hachages. Voir $markup pour plus de détails.

%opts Options -- un certain nombre d'entre elles sont, bien sûr, obligatoires.

'rect' => [x, y, width, height]
Ceci définit une colonne comme une zone rectangulaire d'une largeur et d'une hauteur données (en points) sur la page actuelle. À l'avenir, on s'attend à ce que des zones non rectangulaires plus élaborées soient définissables, mais pour l'instant, un simple rectangle est tout ce qui est autorisé. La coordonnée du coin supérieur gauche de la colonne est "x, y".

La ligne de base supérieure du texte est supposée être relative au coin UL (basé sur la hauteur de ligne déterminée), et le contour de la colonne coupe cette ligne de base, tout comme les lignes de base supplémentaires plus bas sur la page (l'espacement inter-lignes est "leading" multiplié par la plus grande "font_size" ou la hauteur d'image nécessaire sur cette ligne).

Actuellement, 'rect' est requis, car c'est la seule forme de colonne prise en charge.

'relative' => [ x, y, scale(s) ]
'relative' vaut par défaut "[ 0, 0, 1, 1 ]", et permet à un contour de colonne (actuellement uniquement 'rect') d'être absolu ou relatif. "x" et "y" sont ajoutés à chaque paire de coordonnées "x,y", après mise à l'échelle. Valeurs de mise à l'échelle :
(none) La mise à l'échelle est de 1 par défaut dans les dimensions x et y (aucun changement).
scale (une valeur) La mise à l'échelle dans les dimensions x (largeur) et y (hauteur) utilise cette valeur.
scale_x, scale_y (deux valeurs) Il y a deux facteurs de mise à l'échelle distincts pour la dimension x (largeur) et la dimension y (hauteur).

Cela permet de définir un contour de forme générique, de le mettre à l'échelle (peut-être sans préserver le rapport d'aspect) et de le placer n'importe où sur la page. Cela peut vous éviter d'avoir à définir plusieurs fois des colonnes de forme similaire à partir de zéro. Si vous souhaitez définir un contour relatif, le coin inférieur gauche (qu'il contienne ou non un point, et qu'il s'agisse ou non du premier listé) serait généralement "0, 0", pour que la mise à l'échelle fonctionne comme prévu. Autrement dit, votre modèle de contour doit se trouver dans le coin inférieur gauche de la page.

'start_y' => $start_y
Si omis, on suppose que vous souhaitez commencer en haut de la colonne définie (la valeur maximale de "y" moins l'étendue verticale maximale de cette ligne). Si utilisé, la valeur normale est le "next_y" retourné par l'appel précédent à column(). C'est l'étendue la plus profonde atteinte par la ligne précédente (plus le leading), et c'est le point le plus haut de la nouvelle première ligne de cet appel column().

Notez que la position "x" sera déterminée par la forme et la taille de la colonne (le point le plus à gauche de la ligne de base), il n'y a donc pas d'endroit pour définir explicitement une position "x" de départ.

'font_size' => $font_size
C'est la taille de police de départ (en points) à utiliser. Au fil du texte, elle peut être modifiée par le balisage.

La taille de police de départ peut être définie de plusieurs manières. Elle peut être héritée d'une instruction "$text->font(..., font-size)" précédente ; elle peut être définie via l'option "font_size" (annulant tout héritage de méthode de police) ; elle peut être de 12 points par défaut (si aucune méthode explicite n'est donnée). Pour le balisage HTML, elle peut bien sûr être modifiée par la balise "font" ou par le style CSS "font-size". Pour Markdown, elle peut être modifiée par le style CSS.

'marker_width' => $marker_width
'marker_gap' => $marker_gap
C'est la largeur de la gouttière à gauche d'un élément de liste, où (pour la première ligne de l'élément) se trouve le marqueur. Le marqueur contient le symbole (pour les listes à puces/non ordonnées) ou le numéro formaté et le texte "avant" et "après" (pour les listes numérotées/ordonnées). Les deux ont un espace avant le début du texte de l'élément. Le numéro est une longueur, en points.

La valeur par défaut est 2 fois la font_size passée à column(), et n'est pas ajustée pour les changements de font_size dans le balisage. Une valeur explicite est également inchangée -- la largeur de la gouttière pour le marqueur sera la même dans toutes les listes (les maintenant alignées). Si vous prévoyez d'avoir des marqueurs exceptionnellement longs, tels qu'une liste ordonnée d'années en chiffres romains, par exemple, (MCMXCIX), vous pourriez vouloir élargir un peu cette gouttière.

Une valeur peut être donnée pour marker_gap, qui est l'espace entre le marqueur (de largeur $marker_width) et le début du texte de l'élément de liste. La valeur par défaut est de $fs points (1 em), définie par la font_size dans le balisage.

La propriété CSS "list-style-position" peut être donnée comme la valeur standard 'outside' (par défaut) ou 'inside', ou (extension CSS) pour indenter le côté gauche des deuxième, troisième, etc. lignes

  • vers une position intermédiaire entre les positions 'inside' et 'outside'.

    • 'leading' => $leading
    C'est le ratio de leading utilisé dans tout le texte de la colonne. La position "$x, $y" jusqu'à "$x + width" est supposée être la première ligne de base du texte. La ligne suivante sera à "$y - $leading*$font_size". Si la font_size change pour une raison quelconque au cours de la colonne, l'espacement des lignes de base (leading * font_size) changera également. Le ratio de leading **par défaut** est de 1,125 (12,5 % ajoutés à la police).
    'para' => [ $indent, $top-margin ]
    Lors du démarrage d'un nouveau paragraphe, ce sont l'indentation par défaut (en points) et l'espacement vertical supplémentaire pour une marge supérieure d'un paragraphe. La valeur par défaut est "[ 1*$font_size, 0 ]". L'un ou l'autre peut être annulé par les paramètres CSS appropriés. Une retrait peut être définie avec une valeur d'indentation négative. Ceux-ci s'appliquent à tous les types de $markup.
    'outline' => "chaîne de couleur"
    Vous pouvez éventuellement demander que la colonne soit délimitée par une couleur donnée, pour aider au débogage des problèmes d'ajustement.
    'color' => "chaîne de couleur"
    La couleur dans laquelle dessiner le texte (ou la règle ou tout autre graphique). La valeur par défaut est le noir (#000000).
    'style' => "style CSS"
    Vous pouvez définir du CSS (sélecteurs et listes de propriétés) pour annuler les valeurs par défaut intégrées du CSS. Elles seront appliquées à l'intégralité de l'appel column(). Vous pouvez l'utiliser, ou les balises "style" dans 'html', mais pour 'none' ou 'md1', vous devrez utiliser cette méthode pour définir le style.
    'substitute' => [ [ 'caractère ou chaîne', 'avant', 'remplacer', 'après'],... ]
    Lorsqu'un certain point de code Unicode (caractère) ou une chaîne est trouvé, insérez avant le texte avant le caractère, remplacez le caractère ou la chaîne par le texte remplacer, et insérez le texte après après le caractère. Cela peut faciliter l'insertion de code HTML (police, couleur, etc.) dans du texte Markdown, si les paramètres et le caractère souhaités ne peuvent pas être produits par votre éditeur Markdown. Cela s'applique aux balisages 'md1' et 'html'. Plusieurs substitutions peuvent être définies via plusieurs éléments de tableau. Si vous souhaitez laisser le caractère ou la chaîne d'origine lui-même inchangé, vous devez définir le texte remplacer pour qu'il soit le même que le 'caractère ou chaîne'. Le texte 'avant' et/ou 'après' peut être une chaîne vide si vous ne souhaitez pas y insérer une sorte de balisage.

    Exemple : pour insérer une croix rouge (X barré) et une coche verte

    'substitute' => [
  [ '%cross%', '<font face="ZapfDingbats" color="red">', '8', '</font>' ],
  [ '%tick%', '<font face="ZapfDingbats" color="green">', '4', '</font>' ],
]

    devrait changer "%cross%" dans le texte Markdown ('md1') ou HTML ('html') en "<font face="ZapfDingbats" color="green">8</font>" et de même pour "%tick%". Ceci est fait après que le Markdown est converti en HTML (mais avant que le HTML ne soit analysé), donc assurez-vous que votre texte macro (par exemple, "%tick%") n'est pas quelque chose que Markdown essaiera d'interpréter par lui-même ! De plus, le parseur d'expressions régulières de Perl semble mal supporter certains caractères, tels que "|", donc ne les utilisez pas comme délimiteurs (par exemple, "|cross|"). Vous n'êtes pas obligé d'encapsuler votre nom de macro dans des délimiteurs, mais cela peut rendre la structure du texte plus claire, et peut être nécessaire pour ne pas faire de substitutions au mauvais endroit.

    'restore' => indicateur
    Cet indicateur entier détermine le type de nettoyage que column() effectuera à la sortie, pour restaurer (ou non) l'état de la police (nom, graisse normale ou épaisse, style normal ou italique, taille et couleur).
    pour rc = 0 (tout le balisage d'entrée a été utilisé, sans manquer de colonne)
    restore => 0
    C'est la valeur **par défaut**. À la sortie, column() tentera de restaurer l'état à ce que l'on verrait si
    il y avait encore plus de texte à produire. Notez que ce n'est pas nécessairement ce que l'on verrait si l'état entier était restauré aux conditions initiales. L'intention est qu'un autre appel à column() puisse être fait immédiatement, en utilisant l'état de police laissé par l'appel précédent, comme si les entrées de balisage des deux appels étaient concaténées.
    restore => 1
    Cette valeur de "restore" commande qu'aucun changement ne soit apporté à l'état de la police, c'est-à-dire que column() se termine avec l'état de police laissé par la dernière sortie de texte. Cela peut être souhaitable ou non, surtout si la dernière sortie de texte a laissé le texte dans un état inattendu.
    restore => 2
    Cette valeur de "restore" tente de ramener l'état de la police à ce qu'il était à l'*entrée* de la routine, comme si elle n'avait jamais été appelée. Notez que si column() a été appelée sans réglages globaux de police, cela ne peut pas être annulé, bien que la couleur puisse être ramenée à son état d'origine, généralement le noir.

    ATTENTION : Le gestionnaire de polices n'est pas synchronisé avec l'état vers lequel la police est retournée. Vous ne devriez pas demander la police 'actuelle', mais la définir explicitement sur une graisse, etc., spécifique, ce qui réinitialise 'actuel'.

    for rc = 1 (manque d'espace de colonne avant que tout le balisage d'entrée ne soit utilisé)
    restore => 0
    Ceci est la valeur par défaut. À la sortie, aucun changement ne sera apporté à l'état de la police. Comme le code sera au milieu d'une sortie, l'état de la police est conservé, de sorte que le prochain appel column() (pour le dépassement) puisse reprendre là où l'appel précédent s'est arrêté, en ce qui concerne l'état de la police.

    C'est équivalent à "restore = 1".

    restore => 1
    Ceci est identique à "restore = 0".
    restore => 2
    Cette valeur de "restore" tente de ramener l'état de la police à ce qu'il était à l'*entrée* de la routine, comme si elle n'avait jamais été appelée. Notez que si column() a été appelée sans réglages globaux de police, cela ne peut pas être annulé, bien que la couleur puisse être ramenée à son état d'origine, généralement le noir.

    ATTENTION : Le gestionnaire de polices n'est pas synchronisé avec l'état vers lequel la police est retournée. Vous ne devriez pas demander la police 'actuelle', mais la définir explicitement sur une graisse, etc., spécifique, ce qui réinitialise 'actuel'.

    Données retournées par cet appel

    S'il y a plus de texte que ce que la taille de la colonne peut accueillir, la portion inutilisée est retournée, avec un code de retour de 1. C'est une liste vide si tout le texte a pu être formaté, et le code de retour est 0. "next_y" est la coordonnée y où tout texte supplémentaire (column() appel) pourrait être ajouté à une colonne (comme "start_y") qui n'a pas été entièrement remplie. Ce serait au point de départ d'une nouvelle colonne (c'est-à-dire que le dernier paragraphe est terminé). Notez que le code de l'application doit vérifier si cette position est trop bas sur la page (dans la marge inférieure) et ne pas l'utiliser aveuglément ! De plus, comme 'md1' est d'abord converti en HTML, toute portion inutilisée sera retournée en balisage 'pre', plutôt qu'en Markdown ou HTML. Assurez-vous de spécifier 'pre' pour toute continuation de la colonne (avec un ou plusieurs appels column() supplémentaires), plutôt que 'none', 'md1', ou 'html'.

    $rc
    Le code de retour.
    '0'
    Un code de retour de 0 indique que l'appel s'est terminé, tout en utilisant tout le texte d'entrée $txt. Il n'a pas manqué d'espace de colonne défini.

    NOTE : si "restore" a la valeur 1, l'appel column() ne fait aucun effort pour "restaurer" les conditions à des valeurs de départ. Si votre dernier fragment de texte a laissé la police "actuelle" avec une graisse/famille/taille "étrange", en italique, en gras, ou colorée ; c'est ce qui sera utilisé par le prochain appel de colonne (ou d'autres appels de texte PDF::Builder). Ceci est fait pour vous permettre de chaîner facilement d'une colonne à l'autre, sans avoir à dire manuellement au système quelle police, couleur, etc. vous souhaitez rétablir. D'un autre côté, dans certains cas, vous voudrez peut-être commencer avec les mêmes conditions initiales que d'habitude. Vous pourriez vouloir ajouter des appels get_font(), font(), fillcolor(), et strokecolor() si nécessaire avant la prochaine sortie de texte, pour obtenir les caractéristiques de texte attendues. Ou, vous pouvez simplement laisser "restore" par défaut à 0 pour obtenir le même effet.

    '1'
    Un code de retour de 1 indique que l'appel s'est terminé en remplissant l'espace de colonne défini. Il n'a pas manqué de texte d'entrée $txt. Vous devrez faire un ou plusieurs appels avec un espace de colonne vide (à remplir), pour utiliser le texte d'entrée restant (avec un balisage "pre").

    Si "restore" est par défaut à 0 (ou est réglé sur 1), les paramètres de texte de la police "actuelle" sont laissés tels quels, de sorte que tout ce que vous faisiez lorsque vous avez manqué de colonne définie (concernant la graisse/famille de police, la taille, les états italique et gras, et la couleur) devrait automatiquement être le même lorsque vous ferez le prochain appel column() pour produire plus de sortie.

    D'autres codes de retour pourraient être ajoutés à l'avenir, pour indiquer des échecs d'une sorte ou d'une autre.

    $next_y
    La prochaine coordonnée "y" de page pour commencer, si vous utilisez la même définition de colonne que la définition précédente de column() (c'est-à-dire que vous n'avez pas complètement rempli la colonne, et avez reçu un code de retour de 0). Dans ce cas, $next_y donnerait la coordonnée "y" de page à passer à column() (comme "start_y") pour commencer un nouveau paragraphe.

    Si le code de retour $rc était 1 (la colonne a été utilisée), $next_y retourné sera -1, car il serait dénué de sens de l'utiliser.

    $unused
    C'est la portion inutilisée du texte d'entrée (code de retour $rc est 1), dans un format ("pre" $markup) approprié pour être entré comme $txt. Ce sera une référence à un tableau de hachages.

    Si $rc est 0 (tout le texte d'entrée a été utilisé), $unused est un tableau anonyme vide. Il ne contient rien à utiliser.

    Il y a des informations supplémentaires sur ce sujet dans "MARKUP" dans PDF::Builder::Docs.
