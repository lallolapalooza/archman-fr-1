NOM

PDF::Builder::Page - Méthodes pour interagir avec les pages individuelles

Hérite de PDF::Builder::Basic::PDF::Pages

SYNOPIS

 my $pdf = PDF::Builder->new();
 # Ajouter une page à un PDF nouveau ou existant
 my $page = $pdf->page();
 # Définir la taille physique (du support) de la page
 # Définir les limites de prépresse, une fonction pratique pour les cas où
 # il n'est pas nécessaire de définir d'autres limites de page (liées à l'impression) de prépresse
 $page->size('letter'); # par nom de taille courante
#$page->size([0, 0, 612, 792]); # par points BBx,BBy, Hax,Hay
 # alternativement, on peut définir (ou obtenir) les limites de prépresse
 $page->boundaries('media' => '12x18', 'trim' => 0.5 * 72);
 # Ajouter une image
 my $image = $pdf->image('/chemin/vers/fichier.jpg');
 $page->object($image, $x,$y, $w,$h);
 # Créer un objet de contenu pour le texte
 my $text = $page->text();
 # Créer un objet de contenu pour dessiner des formes
 my $canvas = $page->graphics();  # ou gfx()
 # Maintenant, pour dessiner des graphiques (en utilisant l'objet $canvas) et du texte (en utilisant l'objet $text).
 # NOTEz que tout dans l'objet graphiques (canvas) sera posé sur
 # la page AVANT que quoi que ce soit dans l'objet texte ne soit posé. C'est-à-dire que
 # le texte couvrira les graphiques, mais pas l'inverse. Ceci est simplement dû à
 # l'ordre dans lequel les objets ont été définis.

rotate, rotation

$page->rotate($deg)
Fait pivoter la page du nombre de degrés indiqué, qui doit être un multiple de 90. Un angle qui n'est pas un multiple de 90 sera arrondi au multiple de 90 le plus proche, avec un message.

Notez que l'angle de rotation est dans le sens horaire pour une valeur positive ! Par exemple, une rotation de +90 (ou -270) aura le bord inférieur du papier sur la gauche de l'écran. Après avoir fait pivoter la page de 180 degrés, "[0, 0]" (initialement le coin inférieur gauche) sera dans le coin supérieur droit de la page, plutôt que dans le coin inférieur gauche. X augmentera vers la droite et Y vers le bas.

(Cela vous permet de faire pivoter automatiquement en mode paysage sans changer la boîte média ! Il existe d'autres moyens d'y parvenir, comme utiliser la méthode size(), qui ne modifiera pas le système de coordonnées (ne déplacera pas l'origine).)

Notez que certains utilisateurs ont signalé des problèmes avec l'utilisation de "rotate", indiquant que les dimensions étaient limitées au plus petit de la hauteur ou de la largeur d'origine. Si vous rencontrez ce problème, assurez-vous de vérifier si vous effectuez une sorte de rognage de boîte ou une autre coupure, qui pourrait ne pas pivoter comme prévu avec le reste de la page. En d'autres termes, vous devrez peut-être ajuster manuellement les dimensions de la boîte de rognage.

Ne confondez pas cet appel rotate() avec la rotation du contexte graphique (Content.pm) rotate(), qui autorise n'importe quel angle, est de direction opposée et ne décale pas l'origine !

Nom alternatif : "rotation"

Ceci a été ajouté pour la compatibilité avec PDF::API2.

size

$page->size($taille)  # Définir
@rectangle = $page->size()  # Obtenir
Définit la taille physique de la page ou renvoie les coordonnées du rectangle englobant la taille physique de la page. Ceci est une méthode alternative fournie pour la compatibilité avec PDF::API2. 
# Définir la page physique (du support) en utilisant un nom de taille courante
$page->size('letter');
# Définir la taille de la page en utilisant des coordonnées en points (X1, Y1, X2, Y2)
$page->size([0, 0, 612, 792]);
# Obtenir les coordonnées de la page en points
my @rectangle = $page->size();

Voir Tailles de Page ci-dessous pour les valeurs possibles. La méthode size est un raccourci pratique pour définir la boîte média du PDF lorsque d'autres limites de page (liées à l'impression) de prépresse ne sont pas requises. Elle est équivalente à ce qui suit :

# Définir
$page = $page->boundaries('media' => $taille);
# Obtenir
@rectangle = $page->boundaries()->{'media'}->@*;

boundaries

$page = $page->boundaries(%limites)
\%limites = $page->boundaries()
Définit les limites de page de prépresse pour faciliter l'impression. Retourne les limites de page actuelles si appelée sans arguments. Th
une méthode alternative est fournie pour la compatibilité avec PDF::API2. 
# Définir
$page->boundaries(
    # taille physique de la feuille 13x19 pouces
    'media' => '13x19',
    # le contenu de la feuille est 11x17 avec 0,25" de fond perdu
    'bleed' => [0.75 * 72, 0.75 * 72, 12.25 * 72, 18.25 * 72],
    # taille finale coupée 11x17 pouces
    'trim'  => 0.25 * 72,
);
# Obtenir
%boundaries = $page->boundaries();
($x1,$y1, $x2,$y2) = $page->boundaries('trim');

Le hachage %boundaries contient une ou plusieurs clés de limites de page (voir Limites de page) à définir ou à remplacer, chacune avec une taille correspondante (voir Tailles de page).

S'il est appelé sans arguments, le hashref retourné contiendra (Obtenir) les cinq limites. S'il est appelé avec un seul argument de chaîne, il renvoie les coordonnées de la limite de page spécifiée. Si plus d'un type de limite est donné, seule la première est traitée, et un avertissement est donné que le reste est ignoré.

Limites de page

PDF définit cinq limites de page. Lors de la création de PDF pour les imprimeries, vous utiliserez le plus souvent uniquement la boîte média et la boîte de coupe. Les imprimeries traditionnelles peuvent également utiliser la boîte de fond perdu lors de l'ajout de marques d'imprimeur et d'autres informations.

media
La boîte média définit les limites du support physique sur lequel la page doit être imprimée. Elle peut inclure toute zone étendue entourant la page finie pour le fond perdu, les marques d'impression ou à d'autres fins similaires. La valeur par défaut est celle définie pour PDF, une page US lettre (8,5" x 11"). ATTENTION : La plupart des imprimantes ne peuvent *pas* imprimer jusqu'au bord du support physique (papier, etc.). Un espace autour des bords sera réservé aux rouleaux de pincement, etc. pour déplacer le papier sans tacher le toner ou l'encre.
crop
La boîte de rognage définit la région à laquelle le contenu de la page sera recadré (coupé) lors de l'affichage ou de l'impression. La valeur par défaut est la boîte média de la page. Il s'agit d'une limite de page historique. Vous voudrez probablement définir plutôt les boîtes de fond perdu et/ou de coupe.
bleed
La boîte de fond perdu définit la région à laquelle le contenu de la page sera recadré lors de la sortie dans un environnement de production. Cela peut inclure toute zone de fond perdu supplémentaire nécessaire pour s'adapter aux limitations physiques des équipements de coupe, de pliage et de finition. La page imprimée réelle (boîte média) peut inclure des marques d'impression qui tombent en dehors de la boîte de fond perdu. La valeur par défaut est la boîte de rognage de la page.
trim
La boîte de coupe définit les dimensions prévues de la page finie après la coupe. Elle peut être plus petite que la boîte média pour permettre le contenu lié à la production, tel que les instructions d'impression, les marques de coupe ou les barres de couleur. La valeur par défaut est la boîte de rognage de la page.
art
La boîte artistique définit l'étendue du contenu significatif de la page (y compris l'espace blanc potentiel) tel qu'entendu par le créateur de la page. La valeur par défaut est la boîte de rognage de la page.

Tailles de page

Les tailles de page PDF sont stockées sous forme de coordonnées rectangulaires. Pour plus de commodité, PDF::Builder prend également en charge un certain nombre d'alias et de raccourcis plus conviviaux. Les formats suivants sont disponibles :

une taille de papier standard
$page->boundaries('media' => 'A4');

Des alias pour les tailles de papier les plus courantes sont intégrés (insensibles à la casse). US : Letter, Legal, Ledger, Tabloid (et autres) Métrique : 4A0, 2A0, A0 - A6, 4B0, 2B0, et B0 - B6 (et autres)

une chaîne "LxH" en pouces
$page->boundaries('media' => '8.5x11');

De nombreuses tailles de papier américaines sont couramment identifiées par leur taille en pouces plutôt que par un nom particulier. Celles-ci peuvent être passées sous forme de chaînes avec la largeur et la hauteur séparées par un "x". Exemples : "4x6", "12x18", "8.5x11"

un nombre représentant une réduction (en points) par rapport à la boîte immédiatement supérieure
Par exemple, une feuille physique de 12" x 18" à réduire à une feuille de 11" x 17" peut être spécifiée comme suit : 
# Note : Il y a 72 points par pouce
$page->boundaries('media' => '12x18', 'trim' => 0.5 * 72);
# Équivalent
$page->boundaries('media' => [0,        0,        12   * 72, 18   * 72],
                  'trim'  => [0.5 * 72, 0.5 * 72, 11.5 * 72, 17.5 * 72]);

Cet exemple montre une feuille physique de 12" x 18" qui sera réduite à une taille finale de 11" x 17" en coupant 0,5" de chaque bord. La limite de page plus petite est supposée être centrée dans la plus grande.

La boîte immédiatement supérieure suit cet ordre, s'arrêtant à la première valeur définie :

art -> trim -> bleed -> media
crop -> media

Cette option n'est pas disponible pour la boîte média, car elle est par définition la limite la plus grande.

[$largeur, $hauteur] en points
$page->boundaries('media' => [8.5 * 72, 11 * 7.2]);

Pour d'autres tailles de page ou de limites, la largeur et la hauteur (en points) peuvent être fournies directement sous forme de tableau.

[$x1, $y1, $x2, $y2] en points
$page->boundaries('media' => [0, 0, 8.5 * 72, 11 * 72]);

Enfin, les coordonnées absolues (brutes) des coins inférieur gauche et supérieur droit d'un rectangle peuvent être spécifiées.

gfx, graphics

$gfx = $page->gfx(%opts)
$gfx = $page->gfx($prepend)
$gfx = $page->gfx()
Renvoie un objet de contenu graphique, pour dessiner des chemins et des formes.

Vous pouvez spécifier le drapeau "prepend" de l'ancienne ou de la nouvelle manière. L'ancienne manière consiste à donner une seule valeur booléenne (0 faux, non nul vrai). La nouvelle manière consiste à donner un élément de hachage nommé 'prepend', avec les mêmes valeurs.

gfx(boolean_value $prepend)
gfx('prepend' => boolean_value)

Si $prepend est *vrai*, ou si l'option 'prepend' est donnée avec une valeur *vraie*, le contenu sera ajouté au début du flux de contenu de la page (au début du flux de contenu de la page). Sinon, il sera ajouté à la fin. La valeur par défaut est *faux*.

gfx('compress' => boolean_value)

Vous pouvez spécifier un drapeau de compression indiquant si les instructions de dessin doivent être compressées. Si aucune n'est donnée, la valeur par défaut est le paramètre de compression global du PDF (activé par défaut).

Vous pouvez avoir plus d'un objet *gfx*. Ils et les objets *text* seront produits sous forme d'objets et de flux *dans l'ordre où les objets sont* définis, toutes les actions relatives à cet objet *gfx* apparaissant dans un flux. Cependant, notez que les objets graphiques et textuels ne sont pas entièrement indépendants les uns des autres : l'état de sortie (épaisseur de ligne, couleur de trait, etc.) d'un objet est l'état d'entrée du prochain objet dans la ligne à produire, et ainsi de suite.

Si vous mélangez plusieurs objets *gfx* et *text* sur une page, les résultats peuvent être confus. Supposons que vous ayez $gfx1, $text1, $gfx2 et $text2 sur votre page (créés dans cet ordre). PDF::Builder produira tous les appels $gfx1-> *action* dans un flux, puis tous les appels $text1-> *action* dans le flux suivant, et de même pour l'utilisation de $gfx2 et enfin $text2.

Ensuite, c'est au tour de PDF de vous confondre. PDF traitera l'intégralité du flux d'objets $gfx1, accumulant l'état graphique jusqu'à la fin du flux, et l'utilisant comme état d'entrée dans $text1. De même, $gfx2 et $text2 sont lus, traités et rendus. Ainsi, un changement, par exemple, du modèle de tirets au milieu de $gfx1, *après* avoir produit du matériel de $gfx2, $text1 et $text2, peut soudainement apparaître au début de $text1 (et continuer à travers $gfx2 et $text2) !

Il est possible d'utiliser plusieurs objets graphiques, pour éviter d'avoir à changer constamment les paramètres, mais vous voudrez peut-être envisager de réinitialiser tous vos paramètres au premier appel de chaque objet, afin de partir d'une base connue. Cela peut être fait plus facilement en utilisant $type-> restore() et -> save() juste après la création de $type :

$text1 = $page->text();
  $text1->save();
$grfx1 = $page->gfx();
  $grfx1->restore();
  $grfx1->save();
$text2 = $page->text();
  $text2->restore();
  $text2->save();
$grfx2 = $page->gfx();
  $grfx1->restore();

En général, vous voudrez définir l'objet graphique en premier, puis l'objet texte après cela. Cela définit l'ordre dans lequel les flux seront rendus (graphiques d'abord), ce qui est généralement souhaitable si vous définissez une couleur d'arrière-plan, ou si vous avez d'autres graphiques sur lesquels vous souhaitez superposer du texte. Parfois, cependant, vous pouvez souhaiter superposer du texte avec des graphiques, auquel cas vous pourriez soit définir les objets texte puis graphiques, soit définir un deuxième flux graphique pour superposer le texte. La plupart du temps, peu importe lequel vient en premier (car le texte et les graphiques n'interagissent pas ou ne se superposent pas), mais dans tous les cas, soyez conscient des états reportés de la fin d'un flux dans le suivant.

Nom alternatif : "graphics"
