PDF::Builder::FontManager(3) Documentation Perl fournie par l'utilisateur PDF::Builder::FontManager(3)

NOM

PDF::Builder::FontManager - Gestion de la bibliothèque de polices pour PDF::Builder

SYNOPSIS

Ces routines sont appelées depuis la classe PDF::Builder (voir les méthodes get_font(), add_font()).

# les polices de base sont préchargées
# Ajout d'une nouvelle famille de polices et de ses variantes
my $rc = $pdf->add_font(
    'face' => $nom_unique_famille,  # famille de polices, par ex. Times
    'type' => 'core',             # noter que les polices de base sont préchargées
    'style' => 'serif',           # également sans-serif, script (cursive),
                                  #  et symbole
    'width' => 'proportional',    # également constant
    'settings' => { 'encode' => $encodage },
    # noter que ce sont les noms réels des polices de base plutôt que des chemins de fichiers
    'file' => { 'roman'       => 'Times-Roman',      
                'italic'      => 'Times-Italic',
                'bold'        => 'Times-Bold',
                'bold-italic' => 'Times-BoldItalic' },
            # pour les polices non de base, ce seraient les chemins réels des fichiers
            # préfixés par les chemins de recherche de polices 
);
$rc = $pdf->add_font(
    'face' => 'DejaVuSans',       # famille Deja Vu sans serif
    'type' => 'ttf',              # otf utilise 'ttf'
    'style' => 'sans-serif',
    'width' => 'proportional',
    'settings' => { 'encode' => 'utf8' },
    # les chemins de polices définis seront préfixés pour trouver le chemin réel
    'file' => { 'roman'       => 'DejaVuSans.ttf',
                'italic'      => 'DejaVuSans-Oblique.ttf',
                'bold'        => 'DejaVuSans-Bold.ttf',
                'bold-italic' => 'DejaVuSans-BoldOblique.ttf' }
);

Certaines données globales, qui peuvent être réinitialisées via la méthode font_settings() :

* default-face:  initialisé à Times-Roman (base), utilisé si vous commencez
  à formater du texte sans définir explicitement une famille
* default-serif: initialisé à Times-Roman (base), utilisé si vous voulez
  un type de police générique "serif"
* default-sansserif: initialisé à Helvetica (base), utilisé si vous voulez
  un type de police générique "sans-serif"
* default-constant: initialisé à Courier (base), utilisé si vous voulez
  un type de police générique à largeur constante
* default-script: NON initialisé (pas de défaut), utilisé si vous voulez
  un type de police générique "script" (cursive)
* default-symbol initialisé à Symbol (base), utilisé si vous voulez
  un type de police générique "symbole"
* font-paths: C:/Windows/Fonts pour les systèmes Windows pour TTF, d'autres types
  sont dans des chemins non standard, et pour les systèmes non Windows, tout est possible

L'utilisation de get_font() est de spécifier la famille et les variantes, puis à chaque fois, de spécifier si italic et bold doivent être activés ou désactivés. Si le fichier désiré n'est pas encore ouvert, il le sera, et le $font sera retourné. Si la police a déjà été créée auparavant, le $font sauvegardé sera retourné.

my $font = $pdf->get_font(
     'face' => 'Times',
     'italic' => 0,     # désire Roman (droit)
     'bold' => 0,       # désire une graisse moyenne
);
# si $font est undef, nous avons un problème...
$text->font($font, $taille_police);
$text->...  # utiliser cette police (police de base Times-Roman de graisse moyenne)
$font = $pdf->get_font('italic' => 1);
$text->...  # passage en italique
$font = $pdf->get_font('italic' => 0);
$text->...  # retour au texte Roman (droit)

MÉTHODES

new

PDF::Builder::FontManager->new(%opts)
Ceci est appelé depuis new() de Builder.pm. Actuellement, aucune option n'est sélectionnable. Il mettra en place le système de gestion des polices et le préchargera avec les polices de base. Divers paramètres par défaut seront définis pour la famille (Times-Roman de base), la famille serif générique (Times-Roman de base), la famille sans-serif générique (Helvetica de base), la famille à largeur constante (pitch fixe) (Courier de base), et une police symbole (Symbol de base). Il n'y a pas de défaut pour une police script (cursive) à moins que vous n'en définissiez une en utilisant la méthode font_settings().

font_settings

@liste = $pdf->font_settings()  # Obtenir
$pdf->font_settings(%info)  # Définir
Obtient ou définit des informations sur les polices, en particulier les polices à utiliser à des fins "génériques".

Le mode "Obtenir" renvoie une liste (un tableau) du nom de la famille de police par défaut, de la famille serif générique par défaut, de la famille sans-serif générique par défaut, de la famille à largeur constante générique par défaut, de la famille symbole générique par défaut, et de la famille script (cursive) générique par défaut. Il est possible qu'un élément soit indéfini (par exemple, la famille script générique est "undef").

Le mode "Définir" modifie un ou plusieurs paramètres par défaut :

'font' => famille à utiliser pour la famille de police par défaut (initialisée à Times)
'serif' => famille à utiliser pour la famille serif générique (initialisée à Times)
'sans-serif' => famille à utiliser pour la famille sans serif générique 
                (initialisée à Helvetica)
'constant' => famille à utiliser pour la famille à largeur constante générique 
              (initialisée à Courier)
'script' => famille à utiliser pour la famille script générique (non initialisée)
'symbol' => famille à utiliser pour la famille symbole générique 
            (initialisée à Symbol)

add_font_path

$rc = $pdf->add_font_path("un chemin de répertoire", %opts)
Cette méthode ajoute un chemin de recherche à la liste des chemins à explorer. Dans la méthode get_font(), chaque chemin de recherche défini sera préfixé à l'entrée "file" (sauf pour les polices de base) à tour de rôle, jusqu'à ce que le fichier de police soit trouvé. Cependant, si l'entrée "file" commence par / ou ./ ou ../, elle sera utilisée seule. Une entrée "file" commençant par .../ est un cas particulier, qui est transformé en ../ avant que le chemin de recherche ne soit préfixé. Cela vous permet de donner un chemin de recherche que vous vous attendez à remonter d'un ou plusieurs répertoires.

La liste de recherche des chemins de polices inclut toujours le répertoire courant (.), et est initialisée dans "Builder.pm" sous le nom @font_path. Pour le système d'exploitation Windows, "/Windows/Fonts" contient généralement un certain nombre de polices TTF fournies par défaut avec Windows, elle est donc ajoutée par défaut. Tout le reste, y compris tous les systèmes Linux (et autres systèmes non Windows), devra être ajouté en fonction de votre système particulier. Voici quelques endroits courants :

Windows (NOTE : utilisez / et non \\ dans les chemins Windows !). Les systèmes Linux peuvent ou non gérer les espaces dans les noms de répertoires correctement !

/Windows/Fonts
/WinNT/Fonts
/Program Files/MikTex 2.9/fonts/type1/urw/bookman (URW Bookman pour MikTex)
/Program Files (x86)/MikTex 2.9/fonts/type1/urw/bookman (anciennes versions)
/Program Files/Adobe/Acrobat DC/Resource/CIDFont (polices Adobe Reader)
GhostScript peut avoir ses propres répertoires

Notez que les noms de répertoires avec des espaces (par exemple, "/Program Files") peuvent ne pas bien fonctionner avec certains systèmes Linux, ils ne sont donc pas inclus par défaut.

Linux, etc.

/usr/share/fonts (base commune)
/usr/local/share/fonts (base commune)
/usr/share/fonts/dejavu-sans-fonts  (Deja Vu Sans TTF spécifiquement)
/usr/share/fonts/truetype/ttf-dejavu
/usr/share/fonts/truetype/dejavu
/usr/lib/defoma/gs.d/devs/fonts   (GhostScript ?)
/usr/share/fonts/type1/gsfonts    (GhostScript PS)
/usr/share/X11/fonts/urw-fonts    (URW PS)

Les installations d'applications tierces, telles qu'Adobe Acrobat Reader, peuvent également être une source de polices installées.

Un code de retour de 0 signifie que le chemin a été ajouté avec succès, tandis que 1 signifie qu'un problème a été rencontré (et un message a été émis).

Aucune option n'est actuellement définie.

add_font

$rc = add_font(%info)
Ajoute une nouvelle entrée de police (par famille et variantes) à la liste des polices connues du Gestionnaire de polices.

Éléments %info à définir :

face => 'nom de famille'
Cela devrait être une chaîne de caractères unique pour identifier une seule entrée dans la table des polices du Gestionnaire de polices. C'est-à-dire, vous ne devriez pas avoir deux "Times" (l'un une police de base et l'autre une police TTF). Donnez-leur des noms différents (les noms de famille sont sensibles à la casse, donc 'Times' est différent de 'times'). Le nom de "face" est utilisé pour récupérer la police désirée.
type => 'chaîne de type'
Ceci indique quelle routine de police de Builder utiliser pour charger la police. Les types autorisés sont
core
Ceci est une police de base, chargée via la routine CoreFont(). Notez que les polices de base sont préchargées automatiquement (y compris d'autres sur les systèmes Windows), de sorte que vous ne devriez pas avoir besoin de charger explicitement l'une de ces polices de base (du moins, les 14 plus basiques). Toutes les installations PDF devraient inclure ces 14 polices de base, mais le type de fichier exact peut varier d'une installation à l'autre, et des substitutions peuvent être faites (tant que les métriques correspondent). Actuellement, les polices de base sont limitées aux codages mono-octet.

Sur les systèmes Windows, il y a 14 polices de base supplémentaires qui sont normalement chargées. Il s'agit de Georgia, Verdana, Trebuchet, Wingdings et Webdings. Il faut être prudent lors de l'utilisation de ces polices supplémentaires, car les systèmes non-Windows peuvent ne pas les inclure sans une installation explicite de ces polices. Ces polices peuvent être utilisées en toute sécurité si vous savez que tous vos lecteurs PDF fonctionneront sur des systèmes Windows.

ttf
Il s'agit d'une police TrueType (.)ttf ou OpenType (.)otf, chargée via la routine ttfont(). C'est actuellement le seul type qui peut être utilisé avec des codages multi-octets (par exemple, utf8) ainsi qu'avec des codages mono-octets (comme Latin-1). C'est également le seul type qui peut être utilisé avec HarfBuzz::Shaper. De nombreux systèmes incluent plusieurs polices TTF, mais contrairement aux polices de base, aucune n'est automatiquement chargée par le gestionnaire de polices PDF::Builder, et doit être chargée explicitement via add_font().
type1
Il s'agit d'une police PostScript (Type1), chargée via la routine psfont(), qui était couramment utilisée auparavant, mais qui est maintenant rarement utilisée, car elle a été principalement remplacée par le format TTF, plus performant. Certains systèmes peuvent inclure des polices Type1, mais Windows, par exemple, n'en est pas fourni avec. Aucune police Type1 n'est automatiquement chargée par le gestionnaire de polices PDF::Builder, et doit être chargée explicitement via add_font().

On suppose que le fichier de métriques (.afm ou .pfm) porte le même nom de fichier de base que le fichier de police (.pfa ou .pfb), se trouve dans le même répertoire, et peut fonctionner avec les deux. Si vous avez besoin d'un répertoire différent, d'un nom de base différent ou d'un fichier de métriques spécifique à un fichier de police particulier, veuillez me le faire savoir afin que je puisse ajouter cette fonctionnalité. Sinon, vous devrez utiliser explicitement la routine psfont() pour spécifier ces chemins différents.

cjk
Il s'agit d'une police d'Asie de l'Est (Chinois-Japonais-Coréen), chargée via la routine cjkfont(). Notez que les polices cjk n'ont jamais été bien prises en charge par PDF::Builder, et dépendent de certaines fonctionnalités obsolètes (anciennes) et de fichiers externes (.cmap et .data). Je suggère qu'au lieu d'aller directement aux fichiers cjk, vous essayiez d'abord d'utiliser directement les fichiers TTF (généralement au format TTF), au format TTF. Peu de systèmes sont livrés avec des polices cjk installées. Aucune police cjk n'est automatiquement chargée par le gestionnaire de polices PDF::Builder, et doit être chargée explicitement via add_font().
bdf
Il s'agit d'un format de distribution de bitmaps d'Adobe, chargé via la routine bdfont(), un ancien format de bitmaps datant des débuts du système X11. Contrairement aux formes de ligne douces utilisées dans la plupart des polices modernes, les BDF sont une grille de pixels noirs et blancs. Soyez patient avec vos lecteurs et utilisez ce format avec modération, par exemple uniquement pour les titres ou les en-têtes de chapitre ! Peu de systèmes sont livrés avec des polices BDF installées. Aucune police BDF n'est automatiquement chargée par le gestionnaire de polices PDF::Builder, et doit être chargée explicitement via add_font().
settings => { 'encode' => string, ... }
Ceci est un ensemble de toute autre configuration, de drapeaux, etc. acceptés par ce type de police. Voir le POD pour "corefont", "ttfont", etc. (par type pour les entrées autorisées. Une entrée importante sera l'encodage, que vous devrez spécifier si vous utilisez des caractères au-delà de l'ASCII de base.

Actuellement, toutes les polices peuvent utiliser n'importe quel encodage mono-octet de votre choix (la valeur par défaut est CP-1252). Seules les polices TTF (y compris OTF et cjk) peuvent spécifier un encodage multi-octets comme utf8. Cependant, le texte que vous passez aux routines de texte doit être conforme à l'encodage donné. Il ne vous obligera pas à utiliser le même encodage pour toutes les polices définies, mais si vous souhaitez mélanger les encodages, il est de votre responsabilité de définir votre texte pour qu'il utilise l'encodage spécifié pour la police utilisée !

En particulier, lorsque vous utilisez des entités qui (si elles sont numériques) sont données sous forme de nombre Unicode. Lorsqu'elles sont hors de la plage d'un seul octet (x00-xFF), les résultats seront imprévisibles si vous utilisez un entier qui ne tombe pas dans la plage de l'encodage ! Vous devriez également vérifier les résultats des points Unicode dans la plage x80-xFF si vous utilisez l'encodage utf8.

style => 'styling'
Ceci spécifie le style de la police : serif, sans-serif, constant (largeur constante ou type fixe), script (cursive), ou symbol (non alphabétique). Cela n'a aucun effet sur la façon dont une police est chargée ou utilisée, mais peut être utile pour définir une police de style générique.
width => 'relative widths'
Actuellement, proportional (largeur variable) et constant (largeur constante) peuvent être spécifiés. Cela n'a aucun effet sur la façon dont une police est chargée ou utilisée, mais peut être utile pour définir une police de style générique.
file => {anonymous hash of source files}
Ceci indique au gestionnaire de polices où trouver le fichier de police réel. Pour les polices de base, il s'agit du nom standard, plutôt que d'un fichier (et rappelez-vous, elles sont préchargées). Pour les autres types, listez une à quatre variantes des éléments suivants :
roman => 'path to Roman'
Ceci spécifie la variante "Roman" ou "régulière" de la police. La plupart des polices disponibles incluent une variante "Roman" (normale, droite) d'épaisseur normale (moyenne).
italic => 'path to Italic'
Ceci spécifie la variante "Italic", "slanted" ou "oblique" de la police. La plupart des polices disponibles incluent une variante "Italic" d'épaisseur normale (moyenne).
bold => 'path to Bold'
Ceci spécifie la variante "Bold" ou "heavy" de la police. La plupart des polices disponibles incluent une variante "Bold" (épaisseur forte) avec une posture normale (Roman).
bold-italic => 'path to BoldItalic'
Ceci spécifie la variante "Bold" et "Italic" de la police. De nombreuses polices disponibles incluent une variante "Bold" (épaisseur forte) avec une posture italique.
symbol => 'path to Symbol'
Pour les polices de type "symbol" (non alphabétique), au lieu de risquer la confusion en réutilisant le terme "roman", le terme "symbol" est utilisé pour spécifier ce qui est généralement la seule variante d'une police de type "symbol". Il peut y avoir des variations de bold, italic et même bold-italic d'un fichier de type "symbol", mais si c'est le cas, elles ne sont pas actuellement prises en charge.

Vous pouvez donner le chemin complet du fichier de police, dans un chemin absolu, si vous le souhaitez. Cependant, il est généralement moins fastidieux d'utiliser add_font_path() pour spécifier une liste de répertoires de polices à rechercher, et de ne donner que le nom (et éventuellement un sous-répertoire) ici dans add_font().

get_font

@current = $pdf->get_font()  # Get
$font = $pdf->get_font(%info)  # Set
Si aucun paramètre n'est donné ("@current = $pdf->get_font()"), une liste (tableau) des paramètres actuels de la police est renvoyée : nom de la face, drapeau italic 0/1, drapeau bold 0/1, type ('core', 'ttf', etc.), une référence de hachage des settings, comme encoding ('utf8', etc.), valeur style, valeur width, et une référence de liste des variantes (roman, bold, etc.). S'il n'y a pas de police explicitement définie, la police actuelle sera la police par défaut.

Si au moins un paramètre est donné (hachage %info), le gestionnaire de polices tentera de trouver la police appropriée (dans la liste des polices), de la charger si elle n'est pas déjà chargée, et de renvoyer la valeur $font. Si undef est renvoyé, il y a eu une erreur.

%info champs :

face => face name string
Il s'agit du nom de la famille de polices (face) chargée avec les polices de base (par exemple, Times), ou avec des appels à "$pdf->add_font()". De plus, vous pouvez demander la famille de polices actuelle ou la famille de polices par défaut, la famille de polices serif (serif), la famille de polices sans-serif (sans-serif), la famille de polices à largeur constante (constant width), ou la famille de polices script (script, cursive) (si définie), peut être demandée.

Si vous donnez le "face" d'entrée, les autres paramètres ("italic", "bold", etc.) ne seront pas réinitialisés, sauf s'il est impossible d'utiliser le paramètre actuel. Si le "face" d'entrée n'est pas donné, le paramètre current sera mis à jour (bold, italic sont activés/désactivés, etc.). Vous pouvez toujours donner current pour indiquer clairement dans votre code que vous ne souhaitez pas changer la famille de polices.

italic => flag
Ceci demande l'utilisation de la variante italique (slanted, oblique) de la police, dans la famille actuelle ("face" non donné dans cet appel) ou dans la nouvelle famille. La valeur est 0 ou 1 pour "off" (posture Roman/droite) et "o

NOM

PDF::Builder::FontManager

SYNOPIS

use PDF::Builder::FontManager;

PDF::Builder::FontManager est un module qui fournit des méthodes pour gérer les tables de polices.

MÉTHODES

italic => indicateur
Cela demande l'utilisation de la variante italique (penchée) de la police, dans la graisse actuelle ("face" non donnée dans cet appel) ou dans la nouvelle graisse. La valeur est 0 ou 1 pour "désactivé" (graisse normale) et "activé" (penchée).
bold => indicateur
Cela demande l'utilisation de la variante grasse (poids fort) de la police, dans la graisse actuelle ("face" non donnée dans cet appel) ou dans la nouvelle graisse. La valeur est 0 ou 1 pour "désactivé" (graisse normale) et "activé" (poids fort).
