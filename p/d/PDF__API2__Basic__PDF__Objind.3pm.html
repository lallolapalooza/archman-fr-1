NOM

PDF::API2::Basic::PDF::Objind - Objet PDF indirect de bas niveau

VARIABLES D'INSTANCE

Les variables d'instance diffèrent des variables de contenu en ce qu'elles commencent toutes par un espace.

parent
Pour un objet qui est une référence à un objet dans une source, cela contient la référence à l'objet source, de sorte que si la référence doit être déréférencée, alors nous savons où aller chercher l'information.
objnum (R)
Le numéro d'objet dans la source (uniquement pour les références d'objet)
objgen (R)
La génération d'objet dans la source

Il existe d'autres variables d'instance utilisées par le parent pour le contrôle du fichier.

isfree
Ceci indique si l'objet se trouve dans la liste des objets libres et disponible pour être réutilisé comme un autre objet ailleurs dans le fichier.
nextfree
Contient une référence directe vers le prochain objet libre dans la liste des objets libres.

MÉTHODES

PDF::API2::Basic::PDF::Objind->new()

Crée un nouvel objet indirect

uid

Retourne un identifiant unique pour cet objet, en en créant un s'il n'en avait pas déjà un.

$r->release

Libère TOUTE la mémoire utilisée par cet objet indirect et tous ses objets composants/enfants. Cette méthode est appelée automatiquement par '"PDF::API2::Basic::PDF::File->release"' (vous n'avez donc pas besoin de l'appeler vous-même).

Note : il est important que cette méthode soit appelée à un moment donné avant la destruction effective de l'objet. En interne, les fichiers PDF ont une quantité énorme de références croisées et cela provoque des références circulaires dans nos propres structures de données internes. Appeler 'release()' force le nettoyage de ces références circulaires et la purge de l'ensemble de la structure de données interne.

$r->val

Retourne la valeur de cet objet ou lit l'objet puis retourne sa valeur.

Notez que toutes les sous-classes directes *doivent* créer leurs propres versions de cette sous-routine, sinon nous pourrions entrer dans une boucle très profonde !

$r->realise

S'assure que l'objet est entièrement lu, etc.

$r->outobjdeep($fh, $pdf)

Si vous voulez vraiment sortir cet objet, vous devez d'abord le lire. Cela signifie également que toutes les sous-classes directes doivent prendre une sous-classe de cette méthode ou boucler à l'infini !

$r->outobj($fh)

S'il s'agit d'un objet complet, il sort une référence à l'objet, sinon il appelle outobjdeep pour sortir le contenu de l'objet à ce moment-là.

$r->elements

Remplissage abstrait de la fonction de la classe mère. Retourne `self` ici mais devrait retourner quelque chose de plus utile s'il s'agit d'un tableau.

$r->empty

Vide tout le contenu de cet objet pour libérer de la mémoire ou pour être lu afin de passer l'objet dans la liste des objets libres. Définit simplement à undef toutes les variables d'instance autres que le numéro et la génération de l'objet.

$r->merge($objind)

Ceci fusionne les informations de contenu dans un espace réservé de référence d'objet. Cela se produit lorsqu'une référence d'objet est lue avant la définition de l'objet et que les informations des données lues doivent être fusionnées dans l'espace réservé de l'objet.

$r->is_obj($pdf)

Retourne si cet objet est un objet complet avec son propre numéro d'objet ou s'il s'agit purement d'un sous-objet. $pdf indique dans quel fichier de sortie nous nous préoccupons que l'objet soit un objet.

$r->copy($pdf, $res)

Retourne une nouvelle copie de cet objet. L'objet est supposé être une sorte de tableau associatif et la copie est une copie profonde pour les éléments qui ne sont pas des objets PDF, selon $pdf, et une copie superficielle pour ceux qui le sont. Notez que l'appel à "copy" sur un objet force au moins une copie d'un niveau, même s'il s'agit d'un objet PDF. L'objet retourné perd cependant son statut d'objet PDF.

Si $res est défini, la copie va dans cet objet plutôt que d'en créer un nouveau. Il incombe à l'appelant de bénir $res, etc. Notez que les éléments de $self ne sont pas copiés dans $res s'il existe déjà une entrée pour eux dans $res.
