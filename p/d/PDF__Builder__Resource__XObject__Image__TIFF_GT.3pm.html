NOM

PDF::Builder::Resource::XObject::Image::TIFF_GT - Support des images TIFF (avec Graphics::TIFF activé)

Hérite de PDF::Builder::Resource::XObject::Image

MÉTHODES

new

$res = PDF::Builder::Resource::XObject::Image::TIFF_GT->new($pdf, $fichier, %opts)
Retourne un objet image TIFF. $pdf est l'objet PDF auquel on ajoute, $fichier est le fichier TIFF d'entrée, et le nom optionnel $nom du nouvel objet image parent par défaut est IxAAA.

Si le paquet Graphics::TIFF est installé, et que son utilisation n'est pas supprimée via le drapeau "nouseGT" (voir la documentation de Builder pour "image_tiff"), la bibliothèque TIFF_GT sera utilisée. Sinon, la bibliothèque TIFF sera utilisée à la place.

Options :

'notrans' => 1
Ignore toute couche alpha (transparence) et rend l'image totalement opaque.
'name' => 'chaîne'
C'est le nom que vous pouvez donner à l'objet image TIFF. Le défaut est Ixnnnn.

Le support TIFF (lors de l'utilisation de Graphics::TIFF) concerne les valeurs de "PhotometricInterpretation" 0 (binaire/gris, blanc est 0), 1 (binaire/gris, noir est 0), 2 (RVB), et 3 (couleur palette). Il ne supporte actuellement pas 4 (masque de transparence), 5 (CMJN séparé), 6 (YCbCr), 8 (CIELab), ou plus. Il y a un support limité pour un canal Alpha (transparence) (en raison de cas de test extrêmement limités). Certains tags ne sont pas supportés, et une PlanarConfiguration de 2 est inconnue jusqu'à ce que nous ayons quelques cas de test.

Certaines applications semblent prendre des libertés étranges avec les tags TIFF, comme l'ajout d'un SamplePerPixel sans spécifier le type ExtraSamples. Dans de tels cas, nous traitons un échantillon supplémentaire (non défini autrement) comme un canal Alpha, et espérons le meilleur !

En cas de tags invalides ou de valeurs de champs invalides dans un tag, la bibliothèque Graphics::TIFF tentera d'afficher une boîte de dialogue d'avertissement, plutôt que d'ignorer simplement les éléments invalides. Si nous pouvons trouver un commutateur pour désactiver ce comportement, nous l'ajouterons comme option. Selon le propriétaire de Graphic::TIFF (ticket RT 133955), cela provient directement de libtiff (via sortie sur STDERR), donc il ne peut rien y faire !

Enfin, bien que Graphics::TIFF ne supporte pas directement le passage d'un descripteur de fichier (généralement un GLOB), PDF::Builder tentera de détecter ce problème et écrira le contenu (du descripteur de fichier) dans un fichier temporaire, et le passera comme un fichier normal. Certains systèmes d'exploitation semblent avoir du mal à effacer ce fichier temporaire, alors soyez conscient que de tels fichiers peuvent s'accumuler avec le temps !

usesLib

$mode = $tif->usesLib()
Retourne 1 si Graphics::TIFF est installé et utilisé, 0 s'il n'est pas installé, ou -1 s'il est installé mais pas utilisé (option nouseGT donnée à "image_tiff").

Attention : cette méthode ne peut être utilisée qu'après la création de l'objet image. Elle ne peut pas vous dire si Graphics::TIFF est disponible avant son utilisation réelle, au cas où vous voudriez utiliser une fonctionnalité disponible uniquement dans TIFF_GT. Voir l'appel **LA_GT()** de PDF::Builder si vous avez besoin de le savoir à l'avance.
