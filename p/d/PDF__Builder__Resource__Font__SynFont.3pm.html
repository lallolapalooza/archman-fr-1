NOM

PDF::Builder::Resource::Font::SynFont - Module pour créer des Polices synthétiques temporaires

Hérite de PDF::Builder::Resource::Font

SYNOPSIS

Ce module vous permet de créer une « nouvelle » police (chargée temporairement, mais pas stockée de manière permanente) basée sur une police existante, où vous pouvez modifier certains attributs de la police originale, tels que :

* inclinaison/obliquité
* graisse/gras supplémentaire (en dessinant les contours des glyphes avec diverses
  épaisseurs de ligne, plutôt qu'en remplissant simplement les zones)
* condensation/expansion (caractères plus étroits ou plus larges)
* espace supplémentaire entre les caractères
* petites capitales (synthétisées, sans utiliser celles fournies avec une police)
* changer l'encodage
$pdf = PDF::Builder->new();
$cft = $pdf->font('Times-Roman');  # corefont, ttfont, etc. fonctionnent aussi
$sft = $pdf->synfont($cft, 'condense' => .75);  # condense de 25%

Cela fonctionne pour les polices de base, les polices PS, et les polices TTF/OTF ; mais ne fonctionne pas pour les polices CJK ou les polices bitmap. Voir aussi « Polices synthétiques » dans PDF::Builder::Docs.

Nom alternatif : "synthetic_font"

Ceci est pour la compatibilité avec les changements récents dans PDF::API2.

MÉTHODES

new

$font = PDF::Builder::Resource::Font::SynFont->new($pdf, $fontobj, %opts)
Retourne un objet synfont. $fontobj est un objet de police normal lu à partir d'un fichier, et $font est la sortie modifiée.

Les options valides %opts sont :

encode
Change l'encodage de la police par rapport à son défaut. Voir Encode de Perl pour les valeurs supportées. **Attention :** seuls les encodages monooctets sont supportés. Les encodages multioctets tels que UTF-8 sont invalides.
pdfname
Change le nom de référence de la police par rapport à son défaut. Le nom de référence est normalement généré automatiquement et peut être récupéré via $pdfname=$font->name().

Nom alternatif : "name" (pour la compatibilité PDF::API2)

condense
Facteur de condensation/expansion de la largeur des caractères (0.1-0.9 = condense, 1 = normal/défaut, 1.1+ = expand). C'est le multiplicateur à appliquer à la largeur de chaque caractère.

Noms alternatifs : "hscale" et "slant" (pour la compatibilité PDF::API2)

L'option slant est un nom déprécié dans PDF::Builder et PDF::API2. Sa valeur est la même que la valeur de condense (1 = normal, échelle inchangée). Pour l'option hscale, la valeur est en pourcentage (%), 100 étant normal, et d'autres valeurs étant 100 fois la valeur de condense. **Utilisez une seule (au plus) de ces trois noms d'option.**

oblique
Angle d'inclinaison italique ou penchée (+/-) en degrés, où la boîte du caractère est déformée (ciselée), le haut vers la droite. Bien qu'il soit improbable que quelqu'un souhaite incliner les caractères à +/-360 degrés, il faut savoir que ceux-ci seront traités comme un angle de 0 degré (deg2rad() effectue un retour à la ligne). Un angle d'inclinaison italique (obliquité) de 0 degré est le défaut.

Nom alternatif : "angle" (pour la compatibilité PDF::API2)

**Utilisez une seule (au plus) de ces deux noms d'option.**

bold
Facteur d'épaississement (0.1+, gras=1, lourd=2, ...). C'est une **épaisseur de contour** supplémentaire (linewidth), qui agrandit le caractère (glyphe) vers l'extérieur (ainsi que réduit les zones remplies non fermées comme les trous et les contre-formes). Normalement, le contour du glyphe n'est pas dessiné (il est seulement rempli) ; ceci ajoute un épais contour. Les unités sont en 1/100èmes d'une unité de texte.

Si utilisé avec le nom d'entrée alternatif "synthetic_font", l'unité est 1/1000ème d'une unité de texte, donc vous aurez besoin d'une valeur 10 fois plus grande qu'avec l'entrée "synfont" pour obtenir le même effet.

space
Espacement de caractères supplémentaire en millièmes d'un em.
caps
Créer des petites capitales synthétiques. 0 = non, 1 = oui. Ce sont des capitales de lettres minuscules, à 80% de hauteur et 88% de largeur. Notez que cela garantit de couvrir uniquement les lettres minuscules ASCII - les caractères accentués mono-octets fonctionnent **habituellement**, mais nous ne pouvons faire aucune promesse concernant les caractères accentués en général, ainsi que les ligatures !

Nom alternatif : "smallcaps" (pour la compatibilité PDF::API2)

**Utilisez une seule (au plus) de ces deux noms d'option.**

Notez que seules les lettres minuscules qui apparaissent dans la police « standard » (plan 0 pour les polices de base et les polices PS) seront en petites capitales. Cela peut inclure le eszett (s allemand), qui devient SS, et les i et j sans point qui deviennent I et J respectivement. Il existe de nombreuses autres lettres accentuées de l'alphabet latin qui **peuvent** apparaître dans les plans 1 et supérieurs. Les ligatures (par exemple, ij et ffl) n'ont pas d'équivalents en majuscules, pas plus que le s long. Si vous avez du texte qui inclut de tels caractères, vous voudrez peut-être envisager de le prétraiter pour les remplacer par des expansions de caractères latins (par exemple, i+j et f+f+l) avant de les transformer en petites capitales.
