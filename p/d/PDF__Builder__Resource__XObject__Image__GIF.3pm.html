NOM

PDF::Builder::Resource::XObject::Image::GIF - Routines de support pour la bibliothèque d'images GIF

Hérite de PDF::Builder::Resource::XObject::Image

Historique

Spécification GIF89a : https://www.w3.org/Graphics/GIF/spec-gif89a.txt

Une description assez complète du format GIF peut être trouvée dans http://giflib.sourceforge.net/whatsinagif/bits_and_bytes.html.

Code original de PDF::Create, PDF::Image::GIFImage - Support d'images GIF Auteur : Michael Gross <mdgrosse@sboxtugraz.at>

Formats Pris en Charge

Les en-têtes GIF87a et GIF89a sont pris en charge. Le bloc d'image (x2C) est pris en charge.

Le bloc d'extension de contrôle graphique (x21 + xF9) est pris en charge pour le contrôle de la transparence. L'animation n'est pas prise en charge.

Les blocs d'extension de commentaire (x21 + xFE), le bloc de texte brut (x21 + x01) et le bloc d'extension d'application (x21 + xFF) sont lus, mais ignorés. Tout autre bloc ou bloc d'extension sera signalé comme une erreur.

Si présents, les tables de couleurs locales sont lues et utilisées, permettant soi-disant plus de 256 couleurs à utiliser globalement dans l'image (malgré la profondeur de table de couleurs de 8 bits).

Options

notrans
Lorsque défini et différent de 0, "notrans" supprime l'utilisation de la transparence si elle est définie dans le fichier GIF.
name => 'chaîne'
C'est le nom que vous pouvez donner à l'objet image GIF. La valeur par défaut est Gxnnnn.
multi
Lorsque défini et différent de 0, "multi" continue le traitement après la fin du premier bloc d'image. L'ancien comportement, qui est maintenant le comportement par défaut, est d'arrêter le traitement à la fin du premier bloc d'image.

MÉTHODES

new

PDF::Builder::Resource::XObject::Image::GIF->new()
Crée un objet image à partir d'un fichier d'entrée GIF. N'oubliez pas que cela doit être appelé via la méthode Builder.pm !
