NOM

PDF::Builder::Content - Méthodes pour ajouter des graphiques et du texte à un PDF

Hérite de PDF::Builder::Basic::PDF::Dict

SYNTAXE

# Commencer avec une page PDF (nouvelle ou ouverte)
my $pdf = PDF::Builder->new();
my $page = $pdf->page();
# Ajouter de nouveaux objets de contenu
my $content = $page->graphics();  # ou gfx()
#   et/ou (comme objet nommé séparé)
my $content = $page->text();
# Puis appeler les méthodes suivantes pour ajouter des graphiques et du texte à la page.
# Remarque : les coordonnées négatives peuvent avoir des effets imprévisibles, alors gardez vos coordonnées positives !

Ces méthodes ajoutent du contenu aux flux de texte ou graphiques. Sauf indication contraire, nombre des méthodes mentionnées ici s'appliquent également aux flux de texte et graphiques. Il est possible que certaines n'aient aucun effet sur un type de flux ou l'autre, mais il n'existe actuellement aucun moyen de les empêcher d'être insérées dans un flux inapplicable.

MÉTHODES

Toutes les méthodes publiques mentionnées, sauf indication contraire, renvoient $self pour faciliter le chaînage des appels.

Transformations de coordonnées

Les méthodes de cette section modifient le système de coordonnées pour l'objet de contenu actuel par rapport au reste du document. Remarque : les modifications sont relatives aux coordonnées *originales* de la page (et donc absolues), et non à la position précédente ! Par conséquent, "translate(10, 10); translate(10, 10);" finit par déplacer l'origine à "[10, 10]", plutôt qu'à "[20, 20]". Il existe un appel, transform_rel(), qui rend vos modifications *relatives* à la position précédente.

Si vous appelez plus d'une méthode de ce type, la norme PDF recommande de les appeler dans l'ordre suivant : translate, rotate, scale, skew. Chaque modification s'appuie sur la précédente, et vous pouvez obtenir des résultats inattendus en les appelant dans un ordre différent.

ATTENTION : un objet de texte ($content) se comporte un peu différemment. Les appels individuels à translate, rotate, scale et skew annulent toute configuration précédente. Si vous souhaitez combiner plusieurs transformations pour le texte, utilisez la méthode "transform".

translate

$content->translate($dx,$dy)
Déplace l'origine le long des axes x et y vers $dx et $dy respectivement.

rotate

$content->rotate($degrees)
Fait pivoter le système de coordonnées dans le sens antihoraire autour de l'origine actuelle. Utilisez un argument négatif pour pivoter dans le sens horaire. Remarque : 360 degrés est traité comme 0 degrés.

Remarque : Sauf si vous avez déjà déplacé (translating) l'origine, le même y restera dans le schéma inférieur gauche de la feuille visible. Il ne sera pas automatiquement déplacé vers un autre schéma. Par exemple, une rotation de +90 degrés (antihoraire) laisserait la feuille entière visible dans le territoire Y négatif (0 sur le bord gauche, -largeur_originale sur le bord droit), tandis que X resterait dans le territoire positif (0 en bas, hauteur_originale en haut).

Ce rotate() autorise n'importe quel angle. Ne pas confondre avec la rotation de la page "rotate", qui n'autorise que des incréments de 90 degrés (de signe opposé !), mais qui déplace l'origine vers un autre schéma de la feuille.

scale

$content->scale($sx,$sy)
Met à l'échelle (étire) les systèmes de coordonnées sur les axes x et y. Plusieurs multiplicateurs sont fournis pour x et y.

skew

$content->skew($skx,$sky)
Incliner le système de coordonnées de $skx degrés (antihoraire) par rapport à l'axe x et de $sky degrés (horaire) par rapport à l'axe y. Remarque : 360 degrés est traité comme 0 degrés.

transform

$content->transform(%opts)
Utilisez une ou plusieurs des options fournies %opts : 
$content->transform(
    'translate' => [$dx,$dy],
    'rotate'    => $degrees,
    'scale'     => [$sx,$sy],
    'skew'      => [$skx,$sky],
    'matrix'    => [$a, $b, $c, $d, $e, $f],
    'point'     => [$x,$y]
    'repeat'    => $boolean
)

Une liste de 6 éléments peut être fournie ("matrix") pour une transformation matricielle supplémentaire :

$a = cos(rot) * facteur d'échelle pour X 
$b = sin(rot) * tan(inclinaison pour X)
$c = -sin(rot) * tan(inclinaison pour Y)
$d = cos(rot) * facteur d'échelle pour Y 
$e = translation pour X
$f = translation pour Y

Effectue plusieurs transformations de coordonnées en un seul appel, dans l'ordre recommandé par la norme PDF (translate, rotate, scale, skew). Ceci est équivalent à effectuer chaque transformation séparément, dans l'ordre indiqué. Une matrice de 6 valeurs peut également être fournie ("matrix"). La matrice de transformation est mise à jour. Un "point" peut être fourni (un point à multiplier [transformé] par la matrice terminée). Les options omises restent inchangées.

Si "repeat" est vrai, et s'il ne s'agit pas du premier appel à une méthode de transformation, la transformation précédente sera réappliquée, modifiée par tous les autres arguments fournis.

transform_rel

$content->transform_rel(%opts)
Effectue des transformations similaires à "transform", sauf qu'il ajoute aux valeurs précédemment définies, plutôt que de les remplacer (sauf pour scale, qui multiplie les nouvelles valeurs par les anciennes).

Contrairement à "transform", "matrix" et "point" ne sont pas pris en charge.

matrix

$content->matrix($a, $b, $c, $d, $e, $f)
(Avancé) Définit manuellement la matrice de transformation actuelle. Sauf si vous avez une raison particulière de définir manuellement des transformations, vous devriez utiliser la méthode "transform" à la place. 
$a = cos(rot) * facteur d'échelle pour X 
$b = sin(rot) * tan(inclinaison pour X)
$c = -sin(rot) * tan(inclinaison pour Y)
$d = cos(rot) * facteur d'échelle pour Y 
$e = translation pour X
$f = translation pour Y

En mode texte, la matrice de texte est renvoyée. En mode graphique, $self est renvoyé.

Paramètres d'état des graphiques

Les appels suivants affectent également l'état du texte.

linewidth, line_width

$content->linewidth($width)
Définit la largeur de la ligne (en points). C'est la limite de ligne en mode graphique, ou la limite de ligne d'un caractère en mode texte (avec le mode de rendu "render" approprié). Si $width n'est pas fourni, la valeur actuelle est renvoyée. Si la largeur est en train d'être définie, $self est renvoyé afin que les appels puissent être chaînés.

Alternative : "line_width"

Ceci est fourni pour la compatibilité avec PDF::API2.

linecap, line_cap

$content->linecap($style)
Définit le style à utiliser aux extrémités d'une ligne. Ceci s'applique aux lignes qui se terminent à une extrémité libre, pas aux coins d'un polygone (voir "linejoin").

Alternative : "line_cap"

Ceci est fourni pour la compatibilité avec PDF::API2.

"butt" ou "b" ou 0 = Extrémité plate (par défaut)
La ligne se termine à l'extrémité du chemin, sans projection.
"round" ou "r" ou 1 = Extrémité arrondie
Un demi-cercle de rayon égal à la largeur de la ligne est dessiné autour de l'extrémité du chemin et rempli.
"square" ou "s" ou 2 = Extrémité carrée projetée
La ligne s'étend au-delà de l'extrémité du chemin de la moitié de la largeur de la ligne.

Si $style n'est pas fourni, la valeur actuelle est renvoyée. Si le style est en train d'être défini, $self est renvoyé afin que les appels puissent être chaînés.

set, $self est retourné afin que les appels puissent être chaînés.

Peut être un nombre ou une chaîne (insensible à la casse).

linejoin, line_join

$content->linejoin($style)
Définit le style de jointure pour les coins d'un tracé (dans une polyligne multisegmentée).

Alternative : "line_join"

Ceci est fourni pour la compatibilité avec PDF::API2.

"miter" ou "m" ou 0 = Miter Join, par défaut
Les bords extérieurs des traits s'étendent jusqu'à ce qu'ils se rencontrent, jusqu'à la limite spécifiée par miterlimit. Si la limite est dépassée, une jointure en bevel est utilisée. Pour une largeur donnée, un angle plus aigu (plus proche de 0 degré) implique un rapport plus grand de la longueur du miter à sa largeur, et c'est ce que miterlimit contrôle — une jointure miter très pointue est remplacée par un bevel.
"round" ou "r" ou 1 = Round Join
Un cercle plein dont le diamètre est égal à linewidth est dessiné autour du point d'angle, produisant un angle arrondi. La courbe s'ajustera aux lignes en une tangente douce.
"bevel" ou "b" ou 2 = Bevel Join
Un triangle plein est dessiné pour remplir l'entaille entre les deux traits.

Si $style n'est pas spécifié, la valeur actuelle est retournée. Si le style est défini, $self est retourné afin que les appels puissent être chaînés.

Peut être un nombre ou une chaîne (insensible à la casse).

miterlimit, miter_limit

$content->miterlimit($ratio)
Définit la limite de miter lorsque le style de jointure est un miter.

Le ratio est la longueur maximale du miter (du sommet intérieur à l'extérieur) divisée par la largeur de la ligne. Tout miter dépassant ce ratio sera converti en une jointure en bevel. L'effet pratique est que les lignes se rencontrant à des angles chauds sont coupées au lieu de produire des angles pointus prolongés.

La limite de miter par défaut est 10.0 (environ 11,5 degrés de coupure). Plus la limite est petite, plus l'angle de coupure est grand.

Si $ratio n'est pas spécifié, la valeur actuelle est retournée. Si le ratio est défini, $self est retourné afin que les appels puissent être chaînés.

Alternative : "miter_limit"

Ceci est fourni pour la compatibilité avec PDF::API2. Anciennement, cette méthode était mal nommée meterlimit, mais cela a été supprimé il y a longtemps. Tout code utilisant ce nom devrait être mis à jour !

linedash, line_dash_pattern

$content->linedash()
$content->linedash($length)
$content->linedash($dash_length, $gap_length, ...)
$content->linedash('pattern' => [$dash_length, $gap_length, ...], 'shift' => $offset)
Définit le motif de ligne discontinue.

Si appelée sans arguments, une ligne pleine est dessinée.

Si appelée avec un argument, les traits et les espaces (lignes et blancs) ont des longueurs égales.

Si appelée avec deux arguments ou plus, les arguments représentent les longueurs alternées de trait et d'espace.

Si appelée avec un hash d'arguments, le tableau pattern peut avoir un ou plusieurs éléments, spécifiant les longueurs des traits et des espaces. Un décalage de trait (shift) peut être défini, qui est un entier positif spécifiant la distance dans le motif à partir de laquelle la ligne discontinue commencera. Note : si vous souhaitez définir un shift, vous devez utiliser "pattern" au lieu d'un ou deux éléments.

Si un nombre impair d'éléments de tableau de trait est donné, le tableau est répété par le logiciel de lecture pour former un nombre pair d'éléments (paires).

Si un argument de -1 est donné, la valeur actuelle est retournée. Il s'agit d'un tableau à deux éléments : un tableau anonyme avec le motif de trait (par défaut : vide) et le montant du décalage (par défaut : 0). Il peut être utilisé directement dans un appel à linedash(), car linedash reconnaîtra le motif spécial [tableau, nombre].

Si le motif de trait est défini, $self est retourné afin que les appels puissent être chaînés.

Alternative : "line_dash_pattern"

Ceci est fourni pour la compatibilité avec PDF::API2.

flatness, flatness_tolerance

$content->flatness($tolerance)
(Avancé) Définit la variation maximale en pixels lors du dessin de courbes. La plage définie de $tolerance est de 0 à 100, 0 signifiant utiliser la valeur par défaut de la planéité de l'appareil. Selon la spécification PDF, vous ne devez pas essayer de forcer des segments visibles (l'approximation de la courbe) ; les résultats seront imprévisibles. Généralement, les résultats pour différentes valeurs de planéité seront indiscernables à l'œil nu.

La valeur de $tolerance est silencieusement limitée entre 0 et 100.

Si $tolerance n'est pas spécifié, la valeur actuelle est retournée. Si la tolérance est définie, $self est retourné afin que les appels puissent être chaînés.

Alternative : "flatness_tolerance"

Ceci est fourni pour la compatibilité avec PDF::API2.

egstate

$content->egstate($object)
(Avancé) Ajoute un état graphique étendu object contenant des paramètres supplémentaires.

Construction de tracés (Dessin)

move

$content->move($x,$y)
Commence un nouveau tracé aux coordonnées spécifiées. Notez que plusieurs paires x,y peuvent être fournies, bien que cela ne soit pas très utile (seule la dernière paire aura un effet).

close

$content->close()
Ferme et termine le tracé en étendant une ligne de la position actuelle à la position de départ.

Constructeurs de lignes droites

Note : Aucune de ces lignes ne sera visible tant que "stroke", "fill" ou "fillstroke" n'aura pas été appelée. Elles servent simplement à configurer le tracé pour le dessin.

line

$content->line($x,$y)
$content->line($x,$y, $x2,$y2,...)
Étends le tracé en une ligne des coordonnées actuelles aux coordonnées spécifiées, et met à jour la position actuelle aux nouvelles coordonnées.

Plusieurs paires de "[$x,$y]" sont autorisées pour dessiner plusieurs segments de ligne connectés. Note : ceci n'est pas équivalent à une polyligne (voir "poly"), car la première paire de coordonnées dans une polyligne est un move et la seconde est un linecap. De plus, "line_join" est utilisé au lieu de "line_cap" pour contrôler l'apparence des extrémités des segments.

hline, vline

$content->hline($x)
$content->vline($y)
Lignes horizontales et verticales tracées à partir de la position actuelle. Elles sont similaires à line(), mais à la nouvelle coordonnée x et la coordonnée y actuelle ("hline"), ou à la coordonnée x actuelle et à la nouvelle coordonnée y ("vline").

polyline

$content->polyline($x1,$y1, ..., $xn,$yn)
C'est un raccourci pour créer un tracé de polyligne à partir de la position actuelle. Le tracé est étendu en segments de ligne selon les coordonnées spécifiées. La position actuelle est déplacée vers la dernière paire "[$x,$y]" fournie.

La distinction critique entre la méthode "polyline" et la méthode "poly" est que dans cette méthode ("polyline"), les premières paires de coordonnées sont traitées comme un draw (contrairement au move dans "poly").

Ainsi, bien qu'elle soit proposée pour la compatibilité avec PDF::API2, ce n'est pas vraiment un alias ou un nom alternatif pour "poly" !

poly

$content->poly($x1,$y1, ..., $xn,$yn)
C'est un raccourci pour créer un tracé de polyligne. Il se déplace vers "[$x1,$y1]", puis étend le tracé en segments de ligne selon les coordonnées spécifiées. La position actuelle est déplacée vers la dernière paire "[$x,$y]" fournie.

La différence entre une polyligne et une ligne avec plusieurs "[$x,$y]" est que les premières paires dans une polyligne sont un move, tandis que dans une ligne, ce sont un draw. De plus, "line_join" est utilisé au lieu de "line_cap" pour contrôler l'apparence des extrémités des segments.

La distinction critique entre la méthode "polyline" et la méthode "poly" est que dans cette méthode ("poly"), les premières paires de coordonnées sont traitées comme un move.

rectangle

$content = $content->rectangle($x1, $y1, $x2, $y2)
Crée un nouveau tracé de forme rectangulaire entre les deux points d'angle "[$x1,$y1]" et "[$x2,$y2]". Si nécessaire, les points d'angle sont échangés de manière à ce que "1" soit le coin inférieur gauche et "2" le coin supérieur droit (x2 > x1 et y2 > y1). L'objet (ici, $content) est retourné pour permettre le chaînage.

Notez que ce n'est pas un alias ou un nom alternatif pour "rect". Il ne gère qu'un seul rectangle et prend les coordonnées des sommets pour le sommet "2", plutôt que la largeur et la hauteur.

rect

$content = $content->rect($x,$y, $w,$h)
$content = $content->rect($x1,$y1, $w1,$h1, ..., $xn,$yn, $wn,$hn)
Ceci crée des tracés pour un ou plusieurs rectangles, avec leurs points d'angle inférieurs à "[$x,$y]" et des largeurs spécifiées (dans la direction +x) et des hauteurs (dans la direction +y). Les largeurs négatives et les hauteurs sont autorisées, ce qui dessine vers la gauche (-x) et vers le bas (-y) du point d'angle donné. La position actuelle est déplacée vers la paire "[$x,$y]" fournie.

Notez que ce n'est pas un alias ou un nom alternatif pour "rectangle". Il ne gère qu'un seul rectangle et prend les coordonnées des sommets pour le sommet "2", plutôt que la largeur et la hauteur.

Ceci crée un chemin rectangulaire, avec “[<span class="Li">$x1,$y1</span>”]” et “[<span class="Li">$x2,$y2</span>”]” spécifiant les “sommets opposés”. Il peut s‘agir du coin inférieur gauche et du coin supérieur droit, ou du coin supérieur gauche et du coin inférieur droit, dans n‘importe quel ordre, tant qu‘ils sont “opposés” l‘un à l‘autre. La position actuelle est déplacée vers “[<span class="Li">$x1,$y1</span>”]” (le premier).

Ceci n‘est pas “un alias ou un nom alternatif” pour “rectangle”, car il permet de spécifier les points des sommets dans n‘importe quel ordre.

Constructions de courbes

Note: Aucune de celles-ci ne sera réellement “visible” tant que “stroke”, “fill” ou “fillstroke” ne sera pas appelée. Elles ne font que configurer le chemin à dessiner.

circle

$content->circle($xc,$yc, $radius)
Ceci crée un chemin circulaire centré sur “[<span class="Li">$xc,$yc</span>”]” avec le rayon spécifié. Il ne change pas la position actuelle.

ellipse

$content->ellipse($xc,$yc, $rx,$ry)
Ceci crée un chemin elliptique fermé centré sur “[<span class="Li">$xc,$yc</span>”]”, avec les rayons des axes (demi-diamètres) spécifiés par “$rx</span> (axe x)” et “$ry</span> (axe y)”. Il ne change pas la position actuelle.

arc

$content->arc($xc,$yc, $rx,$ry, $alpha,$beta, $move, $dir)
$content->arc($xc,$yc, $rx,$ry, $alpha,$beta, $move)
Ceci étend le chemin en un arc d‘ellipse centré sur “[<span class="Li">$xc,$yc</span>”]”. Les demi-diamètres de la courbe elliptique sont “$rx</span> (axe x)” et “$ry</span> (axe y)”, et l‘arc s‘étend de “$alpha</span> degrés à “$beta</span> degrés. La position actuelle est définie au point final de l‘arc.

Mettez “$move</span> à “true” si cet arc est le début d‘un nouveau chemin au lieu de continuer un chemin existant. Dans ce cas, la position actuelle sera mise à jour à la fin de l‘arc. Utilisez “$rx == $ry</span> pour un arc circulaire.

Le paramètre optionnel “$dir</span>” pour la direction de rotation de l‘arc est par défaut 0 (“False”), pour un tour dans le sens antihoraire/rotation. Mettez 1 (“True”) pour un tour dans le sens horaire.

pie
$content->pie($xc,$yc, $rx,$ry, $alpha,$beta, $dir)
$content->pie($xc,$yc, $rx,$ry, $alpha,$beta)
Crée un chemin en forme de part de tarte (circulaire) d‘une ellipse centrée sur “[<span class="Li">$xc,$yc</span>”]”. Les rayons des axes de l‘ellipse sont “$rx</span> (axe x)” et “$ry</span> (axe y)”, et l‘arc s‘étend de “$alpha</span> degrés à “$beta</span> degrés. Il ne change pas la position actuelle. Selon les directions et les angles, il peut dessiner la part de tarte “coupée” ou le reste de l‘ellipse (avec une coupe). Utilisez “$rx == $ry</span> pour une part de tarte circulaire. Utilisez un “[<span class="Li">$xc,$yc</span>”]” différent pour la coupe, pour la décaler du reste de l‘ellipse.

Le paramètre optionnel “$dir</span>” pour la direction de rotation de l‘arc est par défaut 0 (“False”), pour un tour dans le sens antihoraire/rotation. Mettez 1 (“True”) pour un tour dans le sens horaire.

Ceci est un raccourci pour dessiner une section d‘arc elliptique (ou circulaire) et la relier au centre de l‘ellipse ou à la circonférence, pour former une part de tarte.

curve
$content->curve($cx1,$cy1, $cx2,$cy2, $x,$y)
Ceci étend le chemin à partir du point actuel jusqu‘à “[<span class="Li">$x,$y</span>”]”, en utilisant les deux points spécifiés comme points de contrôle pour créer une “courbe de Bézier quadratique” et met à jour la position actuelle au nouveau point (“[<span class="Li">$x,$y</span>”]”).

Sur un objet “text”, la ligne de base du texte suit la courbe de Bézier.

Notez que même si plusieurs ensembles de trois “[<span class="Li">$x,$y</span>”]” sont autorisés comme points de contrôle, ils sont traités comme des “courbes de Bézier indépendantes”. Aucun effort n‘est fait pour lisser une courbe avec la suivante.

qbspline, spline
$content->qbspline($cx1,$cy1, $x,$y)
Ceci étend le chemin à partir du point actuel jusqu‘à “[<span class="Li">$x,$y</span>”]”, en utilisant les deux points spécifiés comme points de contrôle pour créer une “courbe de Bézier quadratique” et met à jour la position actuelle au nouveau point.

En interne, ces courbes sont une ou plusieurs courbes de Bézier quadratiques (voir “curve”). Les deux points de contrôle sont synthétisés à partir des deux points donnés (un point de contrôle et la fin d‘une “courbe de Bézier quadratique”).

Notez que même si plusieurs ensembles de deux “[<span class="Li">$x,$y</span>”]” sont autorisés comme points de contrôle, ils sont traités comme des “courbes de Bézier indépendantes”. Aucun effort n‘est fait pour lisser une courbe avec la suivante.

De plus, notez que cette “courbe” ne correspond pas à la définition courante d‘une courbe comme une “courbe continue” passant par tous les points donnés. C‘est une courbe de Bézier non continue. Utilisez avec prudence et ne faites pas d‘hypothèses sur les courbes pour vous-même ou vos lecteurs. Vous pourriez envisager d‘utiliser l‘appel “bspline” pour obtenir une courbe continue et lisse passant par tous les points donnés.

Des paires de points (point de contrôle et fin) sont consommées en boucle. S‘il reste un point ou une coordonnée à la fin, il est ignoré (comme c‘est la pratique habituelle pour les données excédentaires). Aucun contrôle des points dupliqués ou d‘autres déformations n‘est effectué.

Nom alternatif: “spline”

Cette méthode suit le nom “spline” dans PDF::API2, elle peut donc être utilisée ici. Comme il existe à la fois des courbes quadratiques et cubiques disponibles dans PDF, il est préférable d‘utiliser des noms plus descriptifs comme “qbspline” et “cbspline” pour minimiser la confusion.

bspline, cbspline
$content->bspline($ptsRef, %opts)
Ceci étend le chemin à partir du point actuel jusqu‘à la fin d‘une liste de paires de coordonnées dans le tableau référencé par “$ptsRef”. Des courbes de Bézier cubiques continues et lisses sont utilisées pour créer une courbe qui passe par tous les points donnés. Plusieurs points de contrôle sont synthétisés; ils ne sont pas fournis dans l‘appel. La position actuelle est mise à jour au dernier point.

En interne, ces courbes sont une courbe de Bézier cubique (voir “curve”) pour chaque paire de points d‘entrée, avec les deux points de contrôle synthétisés à partir des points tangents à chaque point, tels que définis par la ligne brisée reliant chaque point à ses voisins. Le but est que la courbe résultante suive approximativement une ligne brisée reliant les points, en évitant des excursions importantes. Voir les discussions ci-dessous pour la gestion des points de contrôle aux extrémités (point actuel et dernier point d‘entrée). Le point final de la dernière ligne ou courbe dessinée devient le nouveau point actuel.

Les options “%opts”

'firstseg' => 'mode'
où mode est
curve
C‘est le comportement “par défaut”. Cela force le dessin de la première section (du point actuel au premier point donné) comme une courbe de Bézier cubique. Cela signifie que la direction de la courbe sortant du point actuel n‘est pas restreinte (elle serait un reflet de la tangente au premier point donné).
line1
Cela force le dessin de la première section (du point actuel au premier point donné) comme une courbe, avec la tangente au point actuel restreinte à être parallèle au segment de ligne brisée.
line2

Il s'agit d'un segment de cercle défini par l'intersection de deux cercles d'un rayon donné, avec les deux points d'intersection comme entrées. Il existe quatre arcs possibles, qui peuvent être sélectionnés avec $larger et $reverse.)

Ceci prolonge le chemin le long d'un arc de cercle de rayon spécifié entre "[$x1,$y1]" et "[$x2,$y2]". La position courante est ensuite définie au point final de l'arc ("[$x2,$y2]").

Définissez $move sur une valeur vraie si cet arc est le début d'un nouveau chemin au lieu de la continuation d'un chemin existant. Notez que la valeur par défaut ($move = faux) n'est pas une ligne droite vers P1 puis l'arc, mais une fusion dans la courbe à partir du point courant. Elle ne passera souvent pas par P1 !

Définissez $larger sur une valeur vraie pour dessiner l'arc le plus grand ("extérieur") entre les deux points, au lieu du plus petit. Les deux arcs sont dessinés dans le sens des aiguilles d'une montre de P1 à P2. La valeur par défaut de faux dessine l'arc le plus petit. Notez que le plus grand arc de l'autre cercle est utilisé (le point central est "renversé" sur la ligne entre P1 et P2), plutôt que d'utiliser le "reste" du cercle de l'arc le plus petit (ce qui nécessiterait d'inverser la direction du déplacement le long de l'arc -- voir $reverse).

Définissez $reverse sur une valeur vraie pour dessiner l'image miroir de l'arc spécifié (le retourner, de sorte que son centre soit de l'autre côté de la ligne reliant les deux points). Les deux arcs sont dessinés dans le sens inverse des aiguilles d'une montre de P1 à P2. La valeur par défaut (faux) dessine des arcs dans le sens des aiguilles d'une montre. Un arc est toujours dessiné de P1 à P2 ; la direction (sens horaire ou anti-horaire) peut être choisie.

La valeur $radius ne peut pas être inférieure à la moitié de la distance entre "[$x1,$y1]" et "[$x2,$y2]". Si elle est trop petite, le rayon sera défini à la moitié de la distance entre les points (résultant en un arc qui est un demi-cercle). C'est une erreur silencieuse, car même si les points sont corrects, en raison des arrondis, etc., ils peuvent ne pas tomber exactement sur les deux cercles.

Vous pouvez penser à "regarder" de P1 vers P2. Dans le cas dégénéré, où le rayon est exactement la moitié de la distance entre les points, il n'y a pas de différence entre les arcs "petits" et "grands", et les deux cercles coïncideront avec leur centre à mi-chemin entre P1 et P2. Seule la direction compte. Une fois le rayon légèrement plus grand, les deux cercles deviennent distincts. Le cercle principal est centré à votre droite, dont le petit arc est horaire sur votre gauche ; le cercle secondaire est centré à votre gauche, dont le petit arc est anti-horaire sur votre droite. Les arcs "grands" sont les arcs utilisant le reste des cercles : le grand arc horaire fait partie du cercle gauche (secondaire), et le grand arc anti-horaire fait partie du cercle droit (principal).

ATENCIÓN: Ten cuidado al usar "charspace" si estás usando una fuente conectada ("script") (como árabe, devanagari, cursiva latina, etc.). No querrás dejar espacios entre caracteres o causar solapamientos. Para estas fuentes y tipografías conectadas, puedes deber establecer explícitamente el espaciado "charspace" a 0 si lo has establecido de forma no nula. PDF::Builder podría no ser capaz de determinar que una fuente dada es una fuente de tipo conectado y suprimir automáticamente el espaciado no nulo. Alternativas: "character_spacing" y "char_space" character_spacing se proporciona para compatibilidad con PDF::API2, mientras que char_space se proporciona para ser consistente con los cambios de nombre de método en PDF::API2.

wordspace, word_spacing, word_space

$spacing = $content->wordspace($spacing)
Establece el espaciado horizontal adicional entre palabras en una línea. Los sistemas de escritura vertical no son soportados. Está en puntos y es inicialmente cero (es decir, el ancho del espacio, sin nada adicional). Puede ser negativo para cerrar un párrafo un poco. Si $spacing se proporciona, el valor actual se reemplaza por ese valor y $self se devuelve (para permitir la concatenación). Si $spacing no se proporciona, el valor actual se devuelve. Nota: El ajuste del tracking se menciona en la nota de "charspace" y su efecto sobre "wordspace". Ambas llamadas pueden usarse juntas para obtener resultados óptimos (aunque resulta en un tamaño de archivo PDF ligeramente mayor). Nota: Es una limitación de la especificación PDF (a partir de la versión 1.7, sección 9.3.3) que solo se ajuste el espaciado con un espacio ASCII (x20). No se ajusta tampoco los espacios no separables (xA0) ni ningún espacio multibyte (incluyendo espacios delgados y anchos). Sin embargo, cada espacio entre palabras se expande. Por ejemplo, si tienes un doble espacio x20 entre palabras, ¡recibirá dos veces la expansión de un espacio simple! Además, el espaciado de caracteres (Tc) también se agrega a cada espacio, además del espaciado de palabra (Tw). Alternativas: "word_spacing" y "word_space" word_spacing se proporciona para compatibilidad con PDF::API2, mientras que word_space se proporciona para ser consistente con los cambios de nombre de método en PDF::API2.

hscale

$scale = $content->hscale($scale)
Establece el porcentaje de escalado del texto horizontal (tamaño relativo, no espaciado). Esto se inicializa en 100 (porcentaje, es decir, sin escalado). Un escalado mayor que 100 estira el texto, mientras que un escalado menor que 100 comprime el texto. Si $scale se proporciona, el valor actual se reemplaza por ese valor y $self se devuelve (para permitir la concatenación). Si $scale no se proporciona, el valor actual se devuelve. Nota: El escalado afecta a todos los anchos de caracteres, espaciado entre letras y espaciado entre palabras. Es inadecuado escalar o comprimir el texto en grandes cantidades, ya que hará que el texto sea difícil de leer. Si tu objetivo es justificar el texto, suele ser mejor usar "charspace" y "wordspace" para expandir (o condensar ligeramente) una línea para que ocupe un ancho deseado. Ver también las llamadas "text_justify" para este propósito.

leading

$leading = $content->leading($leading)
$leading = $content->leading()
Establece el interlineado, que es la distancia entre las líneas base. Esto se inicializa en 0 (es decir, las líneas se imprimirán una encima de la otra). La unidad de interlineado es puntos. Si $leading se proporciona, el valor actual se reemplaza por ese valor y $self se devuelve (para permitir la concatenación). Si $leading no se proporciona, el valor actual se devuelve. Nota: El "leading" aquí se define como se usa en tipografía electrónica y en la especificación PDF, que es el espaciado completo (distancia entre las líneas base, en puntos). En tipografía de metal caliente, el "leading" era usualmente el espaciado adicional entre líneas más allá de la altura de la fuente en sí, creado insertando espacios de metal (tipo de aleación de hierro).

render

$mode = $content->render($mode)
Establece el modo de renderizado del texto.
0 = Relleno de texto
1 = Trazo de texto (contorno)
2 = Relleno, luego trazo de texto
3 = Ni relleno ni trazo de texto (invisible)
4 = Relleno de texto y añadir al trazado para recorte
5 = Trazo de texto y añadir al trazado para recorte
6 = Relleno, luego trazo de texto y añadir al trazado para recorte
7 = Añadir texto al trazado para recorte

Si $mode se proporciona, el valor actual se reemplaza por ese valor y $self se devuelve (para permitir la concatenación). Si $mode no se proporciona, el valor actual se devuelve.

rise

$dist = $content->rise($dist)
Ajusta la posición de la línea base del texto hacia arriba o hacia abajo desde su posición actual. Se inicializa en 0. Una $dist mayor que 0 mueve la línea base del texto hacia arriba de la página (y aumenta la coordenada y). Úsalo para crear superíndices o subíndices (generalmente junto con un ajuste del tamaño de fuente). Si $dist se proporciona, el valor actual se reemplaza por ese valor y $self se devuelve (para permitir la concatenación). Si $dist no se proporciona, el valor actual se devuelve.

textstate

%state = $content->textstate(charspace => $value, wordspace => $value, ...)
Es un atajo para establecer múltiples parámetros de estado de texto al mismo tiempo. Si se establece algún parámetro, se devuelve una hash vacía. También se puede usar sin argumentos para recuperar los valores actuales del estado de texto (se devuelve una hash de estado). Nota: Esto no funciona con los comandos "save" y "restore".

font

$content->font($font_object, $size)  # Establecer
($font_object, $size) = $content->font()  # Obtener
Establece u obtiene el tipo y tamaño de fuente. $font es un objeto creado llamando a "font" en PDF::Builder para agregar la fuente al documento. 
# Ejemplo (Helvetica 12 puntos)
my $pdf = PDF::Builder->new();
my $font = $pdf->font('Helvetica');
$text->font($font, 24);
$text->position(72, 720);
$text->text('Hola, Mundo!');
$pdf->save('sample.pdf');

O, obtén el objeto de fuente y el tamaño actuales: 

my ($font, $size) = $text->font();

Los resultados ($font y $size) son indeterminados si font() no se llamó previamente con ellos.

distance

$content->distance($dx,$dy)
Ceci se déplace vers le début de la ligne précédemment écrite, plus un décalage par les montants donnés, qui sont tous deux requis. "[0,0]" écraserait la ligne précédente, tandis que "[0,36]" placerait la nouvelle ligne 36 points au-dessus de l'ancienne ligne (y plus élevé). Le $dx se déplace vers la droite, s'il est positif.

"distance" est analogue au "move" du graphique, sauf qu'il est relatif au début de la dernière écriture de texte, et non à l'origine des coordonnées. Notez que les écritures de texte ultérieures seront relatives à ce nouveau point de départ (gauche) et à cette nouvelle position Y ! Par exemple, si vous donnez un $dx non nul, les lignes suivantes seront indentées de ce montant.

cr

$content->cr()
$content->cr($vertical_offset)
$content->cr(0)
Si appelé sans argument, se déplace (vers le bas) au début de la ligne suivante (distance définie par "leading"). Ceci est similaire à nl().

Si appelé avec un argument, la distance de "leading" est ignorée et la ligne suivante commence à cette distance en haut de la page (valeur positive) ou en bas de la page (valeur négative) par rapport à la ligne actuelle. "Y" augmente vers le haut, donc une valeur négative serait normalement utilisée pour passer à la ligne suivante vers le bas.

Un argument de 0 retournerait simplement au début de la ligne présente, la surchargeant avec un nouveau texte. C'est-à-dire qu'il agit comme un simple retour chariot, sans saut de ligne.

Notez que tout réglage de "leading" est ignoré. Si vous souhaitez prendre en compte le réglage "leading", vous pourriez utiliser la méthode "crlf" à la place.

nl

$content->nl()
$content->nl($indent)
$content->nl(0)
Se déplace au début de la ligne suivante (voir "leading"). Si $indent n'est pas donné, ou est 0, il n'y a pas d'indentation. Sinon, indente de ce montant (désindente si une valeur négative). L'unité de mesure est centièmes d'une "unité d'espace de texte", ou environ 88 par em.

Notez que tout réglage de "leading" est ignoré. Si vous souhaitez prendre en compte le réglage "leading", vous pourriez utiliser la méthode "crlf" à la place.

crlf

$content = $content->crlf()
Se déplace au début de la ligne suivante, en fonction du réglage "leading". Il renvoie son propre objet, pour faciliter le chaînage.

Si le interligne n'est pas défini, une distance par défaut de 120% de la taille de la police sera utilisée.

Ajouté pour la compatibilité avec les changements de PDF::API2 ; peut être utilisé pour remplacer les méthodes "cr" et "nl".

advancewidth, text_width

$width = $content->advancewidth($string, %opts)
Renvoie le nombre de points qui seront utilisés (horizontalement) par la chaîne d'entrée. Ceci suppose une seule ligne (pas de retour à la ligne).

Options %opts:

'font' => $f3_TimesRoman
Change la police utilisée, en remplaçant $self->{' font'}. La police doit avoir été créée précédemment (c'est-à-dire qu'il ne s'agit pas du nom). Exemple : utiliser Times-Roman.
'fontsize' => 12
Change la taille de la police, en remplaçant $self->{' fontsize'}. Exemple : police de 12 points.
'wordspace' => 0.8
Change l'espacement supplémentaire des mots, en remplaçant $self->wordspace(). Exemple : ajouter 0,8 pt entre les mots.
'charspace' => -2.1
Change l'espacement supplémentaire des caractères, en remplaçant $self->charspace(). Exemple : soustraire 2,1 pt entre les lettres, pour condenser le texte.
'hscale' => 125
Change le facteur d'échelle horizontal, en remplaçant $self->hscale(). Exemple : étirer le texte jusqu'à 125 % de sa largeur naturelle.

Renvoie la largeur de la chaîne ($string) (lorsqu'elle est définie comme une ligne de texte), basée sur tous les attributs d'état de texte actuellement définis. Ceux-ci peuvent éventuellement être remplacés par %opts. Notez que ces valeurs remplacent temporairement les valeurs existantes, sans les mettre à l'échelle vers le haut ou vers le bas. Par exemple, si l'espacement des caractères existant est de 2, et que vous donnez dans les options une valeur de 3, la valeur utilisée est 3, pas 5.

Note : Cela n'affecte en rien le PDF. Cela indique seulement l'espace horizontal qu'une chaîne de texte occupera.

Nom alternatif : "text_width"

Ceci est fourni pour la compatibilité avec PDF::API2.

Rendu du texte

Lignes uniques

text

$width = $content->text($text, %opts)
Ajoute du texte à la page (justifié à gauche par défaut). La largeur utilisée (en points) est renvoyée.

Options :

'align' => position
Aligner le texte, en supposant une direction d'écriture de gauche à droite (RTL/bidirectionnel n'est pas actuellement pris en charge).
'l' ou 'left' (insensible à la casse).
par défaut. Le texte commence à la position de texte actuelle.
'c' ou 'center' (insensible à la casse).
Le texte est centré à la position de texte actuelle.
'r' ou 'right' (insensible à la casse).
Le texte finit (est justifié à droite) à la position de texte actuelle.

Dans tous les cas, la position finale du texte se trouve à l'extrémité (droite) du texte. Si vous mélangez différents alignements, vous devez explicitement placer la position de texte actuelle afin de ne pas écraser le texte précédent.

'indent' => $distance
Indente le texte du nombre de points (une valeur inférieure à 0 donne un désalignement). Le montant de l'indentation déplace le texte vers la gauche (indentation négative) ou vers la droite (indentation positive), quelle que soit l'alignement. Cela permet d'obtenir des effets d'alignement souhaités (pour centré et droite) qui ne sont pas exactement alignés sur la position actuelle. Par exemple, considérez une colonne de nombres décimaux centrés sur une position x souhaitée, mais alignés sur leurs points décimaux. L'"indent" serait sur une base par ligne, ajusté par la longueur du nombre et la position décimale.
'underline' => 'none'
'underline' => 'auto'
'underline' => $distance
'underline' => [$distance, $thickness, ...]
Souligne le texte. $distance est le nombre d'unités sous la ligne de base, et $thickness est la largeur de la ligne. Plusieurs soulignements peuvent être réalisés en passant plusieurs distances et épaisseurs. Une valeur de 'none' signifie aucun soulignement (c'est la valeur par défaut).

Exemple :

# 3 soulignements :
#   distance 4, épaisseur 1, couleur rouge
#   distance 7, épaisseur 1.5, couleur jaune
#   distance 11, épaisseur 2, couleur (couleur de trait par défaut)
'underline' => [4,[1,'red'],7,[1.5,'yellow'],11,2],
'strikethru' => 'none'
'strikethru' => 'auto'
'strikethru' => $distance
'strikethru' => [$distance, $thickness, ...]
Biffe le texte (comme la balise s HTML). Une valeur de 'auto' place la ligne environ 30% de la taille de la police au-dessus de la ligne de base, ou une $distance spécifiée (au-dessus de la ligne de base) et $thickness (en points). Plusieurs biffures peuvent être réalisées en passant plusieurs distances et épaisseurs. Une valeur de 'none' signifie aucune biffure. C'est la valeur par défaut.

Exemple :

# 2 biffures :
#   distance 4, épaisseur 1, couleur rouge
#   distance 7, épaisseur 1.5, couleur jaune
'strikethru' => [4,[1,'red'],7,[1.5,'yellow']],
'strokecolor' => color_spec
Définit la couleur de la ligne de soulignement ou de biffure, si elle est différente de la couleur du texte.

textHS

$width = $content->textHS($HSarray, $settings, %opts)
Prend un tableau de hachages produit par HarfBuzz::Shaper et les sort dans le fichier de sortie PDF. HarfBuzz produit des identifiants de glyphes CIDs et des informations de positionnement. Il peut réorganiser et échanger des caractères (glyphes), et le résultat peut ne ressembler en rien à la liste des points Unicode d'origine. Vous devriez consulter examples/HarfBuzz.pl, qui montre un certain nombre d'exemples avec du texte latin et non latin, ainsi que de l'écriture verticale. https://www.catskilltech.com/Examples contient un exemple disponible au cas où vous voudriez voir des exemples de ce que HarfBuzz peut faire, et que vous n'avez pas encore installé HarfBuzz::Shaper.
$HSarray
C'est la référence vers le tableau de hachages produit par HarfBuzz::Shaper, normalement inchangé après sa création (mais peut être modifié). Voir "Using Shaper" dans PDF::Builder::Docs pour certaines choses qui peuvent être faites.
$settings
C'est une référence à un hachage contenant diverses informations dont textHS() a besoin pour fonctionner. Elles incluent :
'script' => 'script_name'
C'est le code standard de 4 lettres (par exemple, 'Latn') pour le script (alphabet et système d'écriture) que vous utilisez. Actuellement, seuls les Latn (systèmes d'écriture occidentaux) permettent le crénage, et 'Latn' est la valeur par défaut. HarfBuzz::Shaper pourra généralement déterminer le script à partir des points Unicode utilisés, et vous pourrez peut-être utiliser l'appel set_script() pour remplacer sa supposition. Cependant, PDF::Builder et HarfBuzz::Shaper ne communiquent pas sur le script utilisé.
'features' => array_of_features
Cet élément est requis, mais peut être vide, par exemple, "$settings->{'features'} = ();". Il peut inclure des commutateurs utilisant la nomenclature HarfBuzz standard, et un commutateur + ou -, tel que '-liga' pour désactiver les ligatures. '-liga' et '-kern', pour désactiver les ligatures et le crénage, sont les seuls fonctionnalités prises en charge actuellement. Notez que ceci est distinct de tout commutateur de fonctionnalités que vous envoyez à HarfBuzz::Shaper (avec "$hb->add_features()", etc.) lorsque vous l'exécutez (avant textHS()).
'language' => 'language_code'
Cet élément est facultatif et ne semble actuellement avoir aucun impact substantiel.
'align' => 'flag'
Donne à ce texte un alignement à gauche (L, la valeur par défaut), à droite (R), de haut en bas (T) ou de bas en haut (B). De la manière dont le script est utilisé (points Unicode), HarfBuzz::Shaper peut généralement déduire la direction dans laquelle le texte doit être écrit. De plus, HarfBuzz::Shaper ne partage pas ses informations avec PDF::Builder — vous devez spécifier la direction séparément, sauf si vous souhaitez accepter la direction par défaut (LTR). Vous pouvez utiliser l'appel get_direction() (en plus de get_language() et get_script()) pour voir quelle est la direction correcte selon HarfBuzz. set_direction() peut être utilisé pour outrepasser la supposition de HarfBuzz concernant la direction.

Par exemple, si la direction est RTL, HarfBuzz inversera le texte et renverra un tableau avec le dernier caractère en premier (pour être écrit en LTR). De même, pour BTT, HarfBuzz inversera le texte et renverra une chaîne pour être écrite de haut en bas. Les langues généralement écrites horizontalement sont généralement verticales avec une direction TTB. Si vous écrivez du texte verticalement, les ligatures et le crénage, ainsi que la connexion des caractères pour les scripts cursifs, sont automatiquement désactivés. Par conséquent, ne laissez pas la direction par défaut être LTR ou RTL dans l'appel à Shaper, puis essayez de la corriger dans textHS().

align => 'flag'
Donne à ce texte un alignement à gauche (L, la valeur par défaut), au centre (C) ou à droite (E). La valeur par défaut est B. Center est similaire à l'utilisation de text_center(), et End est similaire à l'utilisation de text_right(). Des alignements similaires s'appliquent à TTB et BTT.
'dump' => flag
Définit à 1, imprime des informations sur la position et le CID des glyphes (dans STDOUT) pour chaque glyphe dans le bloc. La valeur par défaut est 0 (aucune information de vidage).
'minKern' => amount (default 1)
Si la valeur du crénage (largeur de caractère dans la police différente de la valeur ax du glyphe) est plus grande que ce nombre d'unités de grille, utilisez la valeur ax non ajustée pour la largeur (textHS() affichera une valeur de crénage dans l'opération TJ). Sinon, ignorez le crénage et utilisez la valeur réelle de la largeur du caractère. Le but est d'éviter que le code PDF ne se bloque avec des ajustements de crénage inutiles dans l'opération TJ.
%opts
Ceci est une hash d'options.
'underline' => underlining_instructions
Voir text() pour les instructions disponibles.
'strikethru' => strikethrough_instructions
Voir text() pour les instructions disponibles.
'strokecolor' => line_color
Couleur du trait (par exemple, 'green', '#FF3377') pour le soulignement ou le barré, si non spécifiée dans un tableau avec ses instructions.

Le texte est envoyé séparément à HarfBuzz::Shaper en 'blocs' d'un seul script (alphabet), d'une seule direction (LTR, RTL, TTB ou BTT), d'une seule police et d'une seule taille de police. Un bloc peut être constitué d'une grande quantité de texte, mais actuellement, textHS() ne peut émettre qu'une seule ligne. Pour les lignes longues qui doivent être divisées en lignes de largeur de colonne, la meilleure façon pourrait être de prendre le tableau de hashes renvoyé par HarfBuzz::Shaper et de le diviser en petits blocs aux espaces et autres blancs. Vous pourriez devoir interroger la police pour connaître les CID des espaces et autres caractères utilisés.

Il est attendu que lorsque textHS() est appelé, la police et la taille de police aient déjà été définies dans le code de PDF::Builder, car ces informations sont nécessaires pour interpréter ce que HarfBuzz::Shaper renvoie et l'écrire dans le fichier PDF. Bien qu'il faille dire que la police doit être ouverte à partir du même fichier que celui donné à HarfBuzz::Shaper (ttfont() seul, avec .ttf ou .otf), et que la taille de police doit être la même. L'emplacement approprié sur la page doit également avoir été spécifié précédemment.

advancewidthHS, text_widthHS

$width = $content->advancewidthHS($HSarray, $settings, %opts)
Renvoie la largeur du bloc de texte (en points) pour le tableau de glyphes défini par HarfBuzz::Shaper. Il s'agit de la largeur horizontale pour les directions LTR et RTL, et de la hauteur verticale pour les directions TTB et BTT. Note : Vous devez définir la police et la taille de police avant d'appeler advancewidthHS().
$HSarray
Le tableau de références de glyphes créé par l'appel à HarfBuzz::Shaper. Voir textHS() pour plus de détails.
$settings
La référence de hash de configuration. Voir textHS() pour plus de détails.
'dir' => 'L' etc.

%opts

'doKern' => flag (default 1)

Sinon, ignorez le crénage et utilisez la valeur réelle de la largeur du caractère. Le but est d'éviter que le code PDF ne se bloque avec des ajustements de crénage inutiles dans l'opération TJ.

Renvoie la largeur totale en points.

Nom alternatif : "text_widthHS"

Méthodes Avancées

save

$content->save()
Sauvegarde l'état graphique actuel sur la pile PDF. Voir les définitions PDF 8.4.2 à 8.4.4 pour plus de détails. Cela inclut la largeur de ligne, le style de trait de ligne, le style de jointure de ligne, la limite de rencontre, le motif de ligne, la couleur de ligne, la couleur de remplissage, la matrice de transformation actuelle, le port de découpage actuel, la planéité et le nom du dictionnaire.

Cette méthode ne s'applique qu'aux objets gfx/graphics. Si vous l'essayez avec des objets text, vous recevrez un message d'avertissement (à l'exécution) et vous devrez mettre à jour votre code pour ne pas utiliser save() et restore() sur un objet text. Seul save() génère le message, car probablement chaque restore() a déjà effectué un save().

restore

$content->restore()
Restaure l'état graphique le plus récent (voir "save"), en le retirant de la pile. Vous ne pouvez pas restaurer l'état graphique (le retirer de la pile) à moins d'avoir effectué au moins un save (l'avoir mis sur la pile). Cette méthode s'applique aux objets text et gfx/graphics.

add

$content->add(@content)
Ajoute du contenu (texte arbitraire) au flux PDF. Généralement, vous devriez utiliser les autres méthodes de cette classe, sauf si vous en avez besoin pour implémenter une opération PDF que PDF::Builder ne prend pas en charge. Vous pouvez passer un tableau de plusieurs chaînes ; elles seront concaténées avec des espaces entre elles.

Soyez prudent lorsque vous faites cela, car vous jouez avec les tueurs noirs, en configurant directement des opérations PDF ! Une utilisation intéressante est de diviser un flux trop long qui vous pose des problèmes lors de l'exploration d'un PDF. Ajoutez un saut de ligne add("\n") toutes les quelques centaines d'octets de sortie pour ce faire. Vous devez utiliser des guillemets doubles (guillemets doubles), pas des apostrophes (guillemets simples).

Utilisez une extrême prudence lorsque vous insérez BT et ET dans le flux PDF. Vous pourriez vouloir utiliser les appels textstart() et textend() à la place, et même ainsi, il y a des effets secondaires. Il n'est généralement pas utile de suspendre le mode texte avec ET/textend et BT/textstart, mais c'est possible si vous en avez vraiment besoin.

Une autre utilisation utile est lorsque votre entrée PDF provient du navigateur Chrome imprimant une page en PDF avec des en-têtes et/ou des pieds de page. Dans certaines versions, cela laisse un PDF avec une mise à l'échelle inhabituelle (comme la hauteur de la page en points divisée par 3300) et l'axe Y inversé, 0 en haut. Cela pose des problèmes lors de l'ajout de texte ou de graphiques supplémentaires dans un nouveau flux de texte ou graphique, où le texte est inversé (miroir) et se retrouve en bas de la page. Si cela se produit, vous pourriez corriger le problème en ajoutant

$scale = .2399999; # exemple, 792/3300, examinez le PDF ou expérimentez !
 ...
if ($scale != 1) {
    my @pageDim = $page->mediabox();     # par exemple, 0 0 612 792
    my $size_page = $pageDim[3]/$scale;  # 3300 = 792/.23999999
    my $invScale = 1.0/$scale;           # 4.16666684
    $text->add("$invScale 0 0 -$invScale 0 $size_page cm");
}

comme première sortie dans le flux de $text. Bien qu'il soit difficile de prédire exactement quelle devrait être la valeur de $scale, car il pourrait s'agir de 3300 unités par page, ou d'une valeur fixe. Vous devrez peut-être examiner un fichier PDF non compressé pour voir ce qui est utilisé. Il pourrait être possible d'obtenir le PDF d'entrée (original) dans une chaîne et de rechercher un motif spécifique de sortie "cm".

.2399999 0 0 -.23999999 0 792 cm

ou similaire, qui ne se trouve pas dans un save/restore (q/Q). Si le flux est déjà compressé, cela pourrait ne pas être possible.

addNS

$content->addNS(@content)
Comme add(), mais n'assure pas d'espaces entre chaque élément et avant et après le nouveau contenu. C'est à vous de vous assurer que les espaces nécessaires dans le flux PDF y sont placés explicitement !

compressFlate

$content->compressFlate()
Marque le contenu comme étant compressé avec l'algorithme Flate. La méthode s'applique aux objets gfx/graphics et text.
nt pour la compression à la sortie. Ceci est fait automatiquement dans presque tous les cas, donc vous ne devriez pas avoir besoin de l'appeler vous-même.

L'appel new() peut définir le paramètre compress sur 'flate' (par défaut) pour compresser tous les flux d'objets, ou sur 'none' pour supprimer la compression et vous permettre d'examiner la sortie dans un éditeur.

textstart

$content->textstart()
Démarre un objet texte (ignoré si déjà dans un objet texte). Vous voudrez probablement utiliser la méthode text() (contexte de texte, pas sortie de texte) à la place.

Notez que l'appel de cette méthode, en plus de produire un marqueur BT, réinitialisera la plupart des paramètres de texte à leurs valeurs par défaut. De plus, BT lui-même réinitialisera certaines matrices de transformation.

textend

$content->textend()
Termine un objet texte (ignoré si non dans un objet texte).

Notez que l'appel de cette méthode, en plus de produire un marqueur ET, produira tout contenu de *poststream* accumulé.
