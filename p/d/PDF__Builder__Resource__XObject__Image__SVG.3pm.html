PDF::Builder::Resource::XObject::Image::SVG(3) Documentation Perl fournie par l'utilisateur PDF::Builder::Resource::XObject::Image::SVG(3)

NOM

PDF::Builder::Resource::XObject::Image::SVG - Routines de support pour la bibliothèque d'images SVG (Scalable Vector Graphics)

Hérite de PDF::Builder::Resource::XObject::Image

Notez que, contrairement à la sortie d'autres formats d'image, "image_svg()" retourne un tableau de hachages anonymes, un pour chaque balise <svg> dans l'entrée SVG. Voir "Ce qui est retourné" ci-dessous pour les détails.

MÉTHODES

new

$res = PDF::Builder::Resource::XObject::Image::SVG->new($pdf, $file, %opts)

$file donne l'entrée SVG (voir la bibliothèque SVGPDF pour les détails et les limitations). Il peut s'agir d'un nom de fichier, d'une référence de chaîne (avec le contenu SVG) ou d'un descripteur de fichier.

Options :
subimage => n
Si plusieurs entrées "svg" se trouvent dans un fichier SVG, et qu'elles ne sont pas combinées par l'option "combine" de SVGPDF en une seule image, ceci permet de sélectionner quelle image afficher. Tout n peut être donné, de 0 jusqu'au nombre d'images "svg" moins 1. L'élément n-ième sera conservé, et tous les autres rejetés. La valeur par défaut est de retourner l'ensemble du tableau, et de ne supprimer aucun élément, permettant l'affichage de plusieurs images dans l'ordre désiré. Voir la discussion sur la combinaison de plusieurs images "Traitement de plusieurs objets image, et leur combinaison". Le comportement par défaut de la routine d'affichage ("object") est d'afficher uniquement le premier élément (il doit y en avoir au moins un).
MScore => drapeau
Si réglé sur vrai (une valeur non nulle), une fonction de rappel de police pour les 14 extensions "core" de Microsoft Windows sera ajoutée à toutes les autres fonctions de rappel de police données par l'utilisateur. Celles-ci incluent les polices serif "Georgia", sans-serif "Verdana" et sans-serif "Trebuchet", ainsi que les polices de symboles "Wingdings" et "Webdings". Les systèmes non-Windows n'incluent généralement pas ces polices "core", il peut donc être risqué de les utiliser.

Cette option est activée pour tous les systèmes d'exploitation, pas seulement pour MS Windows, vous pouvez donc créer des PDF qui utilisent les polices "core" de Windows (extension). Cela ne garantit pas que ces polices *seront* disponibles sur la machine utilisée pour lire le PDF résultant !

compress => drapeau
Si réglé sur vrai (une valeur non nulle ; par défaut 1), le flux XObject résultant sera compressé. C'est ce que vous feriez normalement. D'un autre côté, le régler sur faux (0) laisse le flux non compressé. Vous pourriez vouloir faire cela si vous voulez examiner le flux dans le PDF finalisé, comme c'est fait pour le test t.

Options SVGPDF :

Ce sont des options qui, si elles sont données, sont transmises à la bibliothèque SVGPDF. Certaines d'entre elles sont fixées par "image_svg" et ne peuvent pas être modifiées, tandis que d'autres sont définies par défaut par "image_svg" mais *peuvent* être remplacées par l'utilisateur.

Vous devriez consulter la documentation de la bibliothèque SVGPDF pour plus de détails sur ces options.

pdf => objet PDF
Ceci est automatiquement défini par la routine SVG, et ne peut *pas* être remplacé par l'utilisateur. Il est passé à "SVGPDF->new()".
fontsize => n
C'est la taille de police (en points) que SVGPDF doit utiliser pour mettre à l'échelle le texte et calculer les tailles em et ex. La valeur par défaut est 12 points. Elle est passée à la fois aux méthodes SVGPDF "SVGPDF->new()" et "$svg->process()".
pagesize => [ largeur, hauteur ]
Ce sont les dimensions maximales de l'objet résultant, au cas où aucune dimension n'est donnée, ou si elles sont trop grandes pour être affichées. La valeur par défaut est 595 pt x 842 pt (taille de page A4), interne à SVGPDF. Elle est passée à "SVGPDF->new()".
grid => n
La valeur par défaut est 0. Une valeur supérieure à 0 indique l'espacement (en points) d'une grille à des fins de développement/débogage. Elle est passée à "SVGPDF->new()".
verbose => n
La valeur par défaut est 0 (messages fatals uniquement), mais l'utilisateur peut la régler sur une valeur plus élevée pour afficher des messages d'information. Elle est passée à "SVGPDF->new()".
fc => \&fonction_rappel_police
C'est une liste d'un ou plusieurs rappels pour le gestionnaire de polices. Si le drapeau "MScore" est vrai (voir ci-dessus), un autre rappel sera ajouté à la liste pour gérer les polices "core" de MS Windows. Il est passé à "SVGPDF->new()".

Notez que certains packages de support, tels que GnuPlot, utilisent des polices Windows comme **Arial**, qui peuvent ou non être installées sur des plateformes non-Windows, et même pour Windows, devraient être ajoutées à FontManager. Vous devriez vérifier les fichiers SVG résultants produits par les packages tiers pour voir quelles polices ils attendent. MathJax crée des caractères textuels sous forme de contours remplis en SVG, et ne semble pas utiliser de polices standard.

combine => 'méthode'
S'il y a plusieurs XObjects définis par un SVG (en raison de plusieurs entrées "svg"), ils peuvent être combinés en un seul XObject. La valeur par défaut est **none**, qui ne combine *pas* les XObjects. Actuellement, la seule autre méthode prise en charge est **stacked**, qui empile verticalement les images, avec un espacement de "sep" entre elles. À l'heure actuelle, la méthode de combinaison **bbox** n'est *pas* prise en charge par SVGPDF, mais pourrait l'être à l'avenir. Elle est passée à "$svg->process()".
sep => n
Espace vertical (en points) à ajouter entre les images individuelles lorsque "combine" n'est pas 'none'. La valeur par défaut est 0 (aucun espace entre les images). Elle est passée à "$svg->process()".

Ce qui est retourné

Retourne une image au format SVG. Contrairement aux autres formats d'image, il ne s'agit pas réellement d'une forme d'objet image, mais d'un tableau (d'au moins un élément) contenant des XObjects de SVG convertis en commandes graphiques et textuelles PDF. Si un SVG inclut une image basée sur des pixels, cette image sera mise à l'échelle vers le haut et vers le bas de la manière habituelle des images, tandis que les graphiques et le texte PDF sont toujours entièrement redimensionnables, à la fois lors de la définition d'une taille d'image *et* lors du zoom avant et arrière dans un lecteur PDF.

Un "objet" retourné est toujours un tableau de hachages (incluant le XObject comme l'un des éléments), un par balise "svg". Notez que les "svg" doivent être des pairs (au niveau supérieur), et ne peuvent *pas* être imbriqués les uns dans les autres ! Dans la plupart des applications, un fichier SVG aura une seule balise "svg" et donc un seul élément dans le tableau. Cependant, certains SVG produiront plusieurs éléments de tableau à partir de plusieurs balises "svg".

Traitement de plusieurs objets image, et leur combinaison

Si vous ne définissez pas "subimage", le tableau complet sera retourné. Si vous définissez "subimage => n", où n est un numéro d'élément valide (0...), tous les éléments *sauf* le n-ième seront supprimés, laissant un tableau à un seul élément. Lorsqu'il sera temps pour object() d'afficher ce tableau XObject, le premier élément (0ème) sera affiché, et tous les autres éléments seront ignorés. Ainsi, le comportement par défaut est effectivement "subimage => 0". Vous pouvez appeler soit "object" soit "image", car "image" transmettra simplement tout à "object".
