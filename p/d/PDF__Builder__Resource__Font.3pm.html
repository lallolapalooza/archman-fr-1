automap

$font->automap()
Ceci s'applique aux polices de base ("$pdf->corefont()") et aux polices PostScript ("$pdf->psfont()"). Celles-ci ne peuvent pas utiliser de texte encodé en UTF-8 (ou autre caractère multibyte) ; seulement des caractères à un seul octet. Ceci limite une police à un maximum de 256 glyphes (l'encodage à un seul octet "standard" utilisé). Tous les autres glyphes fournis avec la police sont inaccessibles.

"automap" divise une police contenant plus de 256 glyphes en "plans" de polices à un seul octet, jusqu'à 256 glyphes, de sorte que tous les glyphes soient accessibles dans des "polices" séparées. Un tableau de nouvelles polices sera retourné, avec [0] étant la page de code standard (de l'encodage sélectionné). S'il y a des glyphes au-delà de xFF sur la page d'encodage standard, ils seront retournés dans un ou plusieurs plans supplémentaires de 223 glyphes chacun. Pourquoi 223 ? Les 32 premiers sont réservés comme caractères de contrôle (bien qu'ils n'aient pas de glyphes), et le nombre x20 est un espace. Ceci, plus 223, donne 256 au total (le dernier plan peut avoir moins de 223 glyphes). Ces "polices" sont temporaires (dynamiques), bien qu'utilisables comme toute autre police.

Notez qu'un plan peut être vide (seulement espace à x20 et éventuellement un caractère inutilisable à x21) si le plan précédent était complet. Vous pourriez vouloir vérifier si un caractère dans le plan a une valeur Unicode (sinon, il est vide).

L'ordre de ces 223 glyphes dans chaque plan suivant ne semble pas suivre un schéma officiel particulier, alors assurez-vous de consulter quelque chose comme "examples/020_corefonts" pour voir ce qui est disponible, et quel point de code un glyphe occupe (par exemple, un 'A' dans le flux de texte imprimera quelque chose de différent si vous n'êtes pas sur le plan 0). Pour un fichier de police donné, ils devraient être cohérents. Par exemple, dans la police de base Times-Roman, un \x21 ou ! dans plane[1] donnera toujours un A+macron. De plus, les nouvelles éditions de fichiers de polices publiées à l'avenir peuvent contenir des modifications à la liste des glyphes et à l'ordre (affectant le plan sur lequel un glyphe apparaît), donc utilisez automap() avec prudence. Il semble que les glyphes soient triés par numéro Unicode, mais si un nouveau glyphe est inséré, cela pourrait décaler d'autres glyphes vers de nouvelles positions, et même vers le plan suivant.

Un exemple :

$fnt = $pdf->corefont('Times-Roman', 'encode' => 'latin1');
@planes = ($fnt, $fnt->automap());  # deux plans
$text->font($planes[0], 15);  # ou juste $fnt fonctionnera
$text->text('!');  # imprime !
$text->font($planes[1], 15);
$text->text('!');  # imprime A+macron

Si vous aviez utilisé l'encodage 'latin2', un \x21 sur le plan 1 donnera un ! inversé (&iexcl; entité HTML).

Notez que "$planes[$n]->fontname()" devrait toujours être la police de base désirée (par exemple, Times-Roman), tandis que "$planes[$n]->name()" sera l'ID de la police (par exemple, TiRoCBC) pour le plan 0, tandis que pour les autres plans, un suffixe unique sera ajouté (par exemple, TiRoCBCam0).

Si vous n'avez qu'un caractère occasionnel hors du plan 0 (ou une séquence de caractères), il peut être acceptable de passer d'un plan à l'autre comme ceci, tout comme taper une entité HTML de temps en temps lorsque vous avez besoin d'une lettre grecque sur une page Web est acceptable pour la plupart des gens. Cependant, si vous tapez beaucoup de texte grec, un clavier dédié peut vous être plus utile. De même, passer à une police TTF pour pouvoir utiliser UTF-8 peut être plus facile.
