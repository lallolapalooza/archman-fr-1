Perl::Critic(3pm) Documentation des paquets contribuant à Perl Perl::Critic(3pm)

NOM

Perl::Critic - Examiner le code Perl pour de meilleures pratiques.

SYNTAXE

use Perl::Critic;
my $file = shift;
my $critic = Perl::Critic->new();
my @violations = $critic->critique($file);
print @violations;

DESCRIPTION

Perl::Critic est un cadre extensible pour créer et appliquer des normes de codage à du code Perl. Essentiellement, c'est un moteur d'analyse statique de code Perl. Perl::Critic est livré avec plusieurs modules Perl::Critic::Policy qui tentent d'appliquer différentes directives de style de code. La plupart des modules de politique sont basés sur le livre de Damian Conway Perl Best Practices. Cependant, Perl::Critic n'est pas limité à PBP et supportera même des politiques qui contredisent Conway. Vous pouvez activer, désactiver et personnaliser ces politiques via l'interface de Perl::Critic. Vous pouvez également créer de nouveaux modules de politique pour répondre à vos goûts.

Pour une interface de ligne de commande de Perl::Critic, consultez la documentation de perlcritic. Si vous souhaitez intégrer Perl::Critic dans votre processus de construction, Test::Perl::Critic fournit une interface appropriée pour les programmes de test. De plus, Test::Perl::Critic::Progressive est utile pour appliquer progressivement des normes de codage à du code existant. Pour une commodité maximale (malgré une certaine flexibilité), consultez le pragma de critique.

Si vous souhaitez essayer Perl::Critic sans rien installer, un service en ligne est disponible sur http://perlcritic.com. Le service en ligne ne prend pas encore en charge toutes les fonctionnalités disponibles dans l'API Perl::Critic native, mais il devrait vous donner une idée de ce qu'il fait.

De plus, ActivePerl inclut une interface graphique très soignée pour Perl-Critic appelée "perlcritic-gui". Vous pouvez obtenir une version gratuite de l'édition communautaire d'ActivePerl sur http://www.activestate.com.

SUPPORT D'INTERFACE

Le module "Perl::Critic" est considéré comme une classe publique. Tout changement à son interface sera soumis à un cycle de dépréciation.

new()
Renvoie un objet de type Perl::Critic. Les arguments les plus courants sont transmis directement à Perl::Critic::Config, mais je les ai présentés ici également. La valeur par défaut de tous les arguments peut être définie dans votre fichier .perlcriticrc. Voir la section "CONFIGURATION" pour plus d'informations. Tous les arguments sont des paires clé-valeur facultatives comme suit :

-profile est le chemin d'accès à un fichier de configuration. Si $FILE n'est pas défini, Perl::Critic::Config tente de trouver un fichier .perlcriticrc dans le répertoire courant, puis dans votre répertoire utilisateur. Alternativement, vous pouvez définir la variable d'environnement "PERLCRITIC" pour pointer vers un fichier ailleurs. Si aucun fichier de configuration ne peut être trouvé, ou si $FILE est une chaîne vide, alors tous les modules de politique seront chargés avec leurs configurations par défaut. Voir "CONFIGURATION" pour plus d'informations.

-severity est le niveau de gravité minimum. Seuls les modules de politique dont la gravité est supérieure à $N seront appliqués. Les valeurs de gravité sont des nombres entiers allant de 1 (la gravité la plus légère) à 5 (la plus grave). La valeur par défaut est 5. La réduction de "-severity" pour un profil donné "-profile" révèle généralement plus de violations de politique. Vous pouvez définir la valeur par défaut pour cette option dans votre fichier .perlcriticrc. Les utilisateurs peuvent redéfinir le niveau de gravité de tout module de politique dans leur fichier .perlcriticrc. Voir "CONFIGURATION" pour plus d'informations.

Si vous avez du mal à vous souvenir si le niveau de gravité "5" est le plus restrictif ou le moins restrictif, vous pouvez utiliser l'une de ces valeurs nommées :

NOM DE GRAVITÉ   ...équivaut à...   NUMÉRO DE GRAVITÉ
--------------------------------------------------------
-severity => 'gentle'                     -severity => 5
-severity => 'stern'                      -severity => 4
-severity => 'harsh'                      -severity => 3
-severity => 'cruel'                      -severity => 2
-severity => 'brutal'                     -severity => 1

Les noms reflètent la manière dont le code est critiqué : une critique "gentle" signale uniquement les violations les plus graves, et ainsi de suite jusqu'à une critique "brutal" qui signale même les plus petites violations.

-theme est une expression spéciale qui détermine quels modules de politique sont appliqués en fonction de leurs thèmes. Par exemple, le code suivant ne chargera que les modules de politique dont le thème est 'bugs' et 'pbp' :

my $critic = Perl::Critic->new( -theme => 'bugs && pbp' );

Le "-severity" n'est pas spécifié si le "-theme" l'est, et le "-severity" est automatiquement réglé sur 1. Vous pouvez définir la valeur par défaut pour cette option dans votre fichier .perlcriticrc. Voir la section "THÈMES DE POLITIQUE" pour plus d'informations sur les thèmes.

-include est une référence à une liste de chaînes @PATTERNS. Les modules de politique qui correspondent à au moins un "m/$PATTERN/ixms" seront toujours chargés, indépendamment des autres paramètres. Par exemple :

my $critic = Perl::Critic->new(-include => ['layout'], -severity => 4);

Cela amènerait Perl::Critic à appliquer tous les modules de politique "CodeLayout::*" même si leur niveau de gravité est inférieur à 4. Vous pouvez définir la valeur par défaut pour cette option dans votre fichier .perlcriticrc. Vous pouvez également utiliser "-include" conjointement avec "-exclude". Remarque : "-exclude" a la priorité sur "-include" lorsqu'un module de politique correspond aux deux modèles.

-exclude est une référence à une liste de chaînes @PATTERNS. Les modules de politique qui correspondent à au moins un "m/$PATTERN/ixms" ne seront pas chargés, indépendamment des autres paramètres. Par exemple :

my $critic = Perl::Critic->new(-exclude => ['strict'], -severity => 1);

Cela amènerait Perl::Critic à ne pas appliquer les modules de politique "RequireUseStrict" et "ProhibitNoStrict" même si leur niveau de gravité est supérieur à 1. Vous pouvez définir la valeur par défaut pour cette option dans votre fichier .perlcriticrc. Vous pouvez également utiliser "-exclude" conjointement avec "-include". Remarque : "-exclude" a la priorité sur "-include" lorsqu'un module de politique correspond aux deux modèles.

-single-policy est une chaîne "PATTERN". Seul un module de politique correspondant à "m/$PATTERN/ixms" sera utilisé. Les modules qui ne correspondent pas sont exclus. Cette option a la priorité sur les autres options telles que "-severity", "-theme", "-include", "-exclude" et "-only". Vous pouvez définir la valeur par défaut pour cette option dans votre fichier .perlcriticrc.

-top est le nombre maximum de violations à renvoyer lorsqu'elles sont triées par niveau de gravité. Il doit s'agir d'un nombre positif. Les violations sont triées par ordre de gravité. Il doit s'agir d'un nombre positif.

MÉTHODES

critique( $file | $code )
La méthode principale de Perl::Critic. Elle prend un nom de fichier ou une chaîne de code Perl comme argument. Elle renvoie une liste des violations trouvées dans le code.
loaded_policy_count()
Renvoie le nombre de modules de politique qui sont actuellement chargés.
loaded_policies()
Renvoie une liste de tous les modules de politique actuellement chargés.
policy_count()
Renvoie le nombre total de modules de politique qui ont été trouvés.
policies()
Renvoie une liste de tous les modules de politique qui ont été trouvés.
active_policy_count()
Renvoie le nombre de modules de politique qui sont actuellement actifs.
active_policies()
Renvoie une liste de tous les modules de politique qui sont actuellement actifs.

CONFIGURATION

Perl::Critic utilise un fichier de configuration pour déterminer quels modules de politique charger et comment les configurer. Le fichier de configuration par défaut est .perlcriticrc et il est recherché dans le répertoire courant, puis dans le répertoire personnel de l'utilisateur. Les fichiers de configuration peuvent également être spécifiés à l'aide de l'option "-profile" lors de la création d'un objet Perl::Critic.

Les fichiers de configuration sont des fichiers Perl normaux. Chaque fichier de configuration doit commencer par la ligne suivante :

    use strict;
    use warnings;

Ensuite, vous pouvez spécifier quelles politiques vous souhaitez utiliser, ainsi que leurs paramètres. Par exemple, le fichier de configuration suivant désactive la politique "SuboptimalCode" et définit le niveau de gravité de la politique "RequireArgUnpacking" sur 3:

    {
        project = myproject
        # Désactive la politique SuboptimalCode.
        exclude = SuboptimalCode
        # Définit le niveau de gravité de la politique RequireArgUnpacking
        # à 3.
        severity = RequireArgUnpacking 3
    }

Voici une liste des différentes instructions de configuration qui peuvent être utilisées dans un fichier de configuration :

project = NAME
Définit le nom du projet. La valeur de NAME est incluse dans toutes les violations de politique qui sont enregistrées.
theme = REGEXP
Charge uniquement les modules de politique qui correspondent à la REGEXP. La REGEXP est évaluée comme une expression normale Perl.
severity = SEVERITY
Définit le niveau de gravité minimum pour tous les modules de politique. Les valeurs de gravité sont des entiers allant de 1 (la gravité la plus légère) à 5 (la plus grave). La valeur par défaut est 5.
severity = POLICY SEVERITY
Définit le niveau de gravité du module de politique spécifié par POLICY à SEVERITY. POLICY peut être le nom d'un module de politique (par exemple, "SuboptimalCode") ou une expression régulière qui correspond à un ou plusieurs noms de modules de politique (par exemple, "CodeLayout::*").
include = PATTERN
Inclut toujours le module de politique correspondant à PATTERN, indépendamment des autres paramètres.
exclude = PATTERN
Exclut toujours le module de politique correspondant à PATTERN, indépendamment des autres paramètres.
single-policy = PATTERN
Charge uniquement le module de politique correspondant à PATTERN. Tous les autres modules de politique sont exclus.
allow-unsafe = <true|false>
Autorise ou refuse l'utilisation de politiques qui pourraient potentiellement ralentir considérablement le processus d'analyse. La valeur par défaut est false.
verbose = LEVEL
Définit le niveau de verbosité de la sortie. LEVEL est un entier allant de 0 à 5.
color = <true|false>
Active ou désactive la coloration syntaxique de la sortie. La valeur par défaut est true.
pager = PAGED
Spécifie le programme de pagination à utiliser pour afficher la sortie. Par exemple, "more" ou "less".

Pour plus d'informations sur les options de configuration disponibles, consultez la documentation de Perl::Critic::Config.

THÈMES DE POLITIQUE

Perl::Critic permet d'organiser les politiques en thèmes. Les thèmes sont simplement des chaînes de caractères qui sont associées à chaque politique. Les thèmes peuvent être utilisés pour charger ou exclure des ensembles de politiques. Voici quelques exemples de thèmes courants :

  • "bugs" : Politiques qui identifient les bogues potentiels dans le code.
  • "complexity" : Politiques qui identifient le code complexe.
  • "documentation" : Politiques relatives à la documentation du code.
  • "idioms" : Politiques relatives aux idiomes Perl.
  • "maintainability" : Politiques relatives à la maintenabilité du code.
  • "pbp" : Politiques basées sur le livre Perl Best Practices de Damian Conway.
  • "performance" : Politiques relatives aux performances du code.
  • "readability" : Politiques relatives à la lisibilité du code.
  • "style" : Politiques relatives au style de codage.
  • "testing" : Politiques relatives aux tests.

Vous pouvez combiner des thèmes en utilisant les opérateurs logiques "&&" (AND) et "||" (OR). Par exemple, pour charger uniquement les politiques liées aux bugs et aux meilleures pratiques, vous utiliseriez :

    -theme => 'bugs && pbp'

Pour afficher les thèmes disponibles pour une politique donnée, vous pouvez utiliser la commande perlcritic avec l'option --verbose=4.

Correspondingly, "$PROFILE_STRICTNESS_QUIET" in Perl::Critic::Utils::Constants makes Perl::Critic shut up about these things.

-force is a boolean value that controls whether Perl::Critic observes the magical "## no critic" annotations in your code. If set to a true value, Perl::Critic will analyze all code. If set to a false value (which is the default) Perl::Critic will ignore code that is tagged with these annotations. See "BENDING THE RULES" for more information. You can set the default value for this option in your .perlcriticrc file.

-verbose can be a positive integer (from 1 to 11), or a literal format specification. See Perl::Critic::Violation for an explanation of format specifications. You can set the default value for this option in your .perlcriticrc file.

METHODS

critique( $source_code )
Runs the $source_code through the Perl::Critic engine using all the Policies that have been loaded into this engine. If $source_code is a scalar reference, then it is treated as a string of actual Perl code. If $source_code is a reference to an instance of PPI::Document, then that instance is used directly. Otherwise, it is treated as a path to a local file containing Perl code. This method returns a list of Perl::Critic::Violation objects for each violation of the loaded Policies. The list is sorted in the order that the Violations appear in the code. If there are no violations, this method returns an empty list.
"add_policy( -policy => $policy_name, -params => \%param_hash )"
Creates a Policy object and loads it into this Critic. If the object cannot be instantiated, it will throw a fatal exception. Otherwise, it returns a reference to this Critic.

-policy is the name of a Perl::Critic::Policy subclass module. The 'Perl::Critic::Policy' portion of the name can be omitted for brevity. This argument is required.

-params is an optional reference to a hash of Policy parameters. The contents of this hash reference will be passed into to the constructor of the Policy module. See the documentation in the relevant Policy module for a description of the arguments it supports.

policies()
Returns a list containing references to all the Policy objects that have been loaded into this engine. Objects will be in the order that they were loaded.
config()
Returns the Perl::Critic::Config object that was created for or given to this Critic.
statistics()
Returns the Perl::Critic::Statistics object that was created for this Critic. The Statistics object accumulates data for all files that are analyzed by this Critic.

FONCTIONAL INTERFACE

Pour ceux qui préfèrent une interface fonctionnelle, la méthode "critique" peut être exportée sur demande et appelée comme une fonction statique. Si le premier argument est un hashref, son contenu est utilisé pour construire un nouvel objet Perl::Critic en interne. Les clés de ce hash doivent être les mêmes que celles prises en charge par la méthode Perl::Critic::new(). Voici quelques exemples:

use Perl::Critic qw(critique);
# Utiliser les paramètres par défaut...
@violations = critique( $some_file );
# Utiliser des paramètres personnalisés...
@violations = critique( {-severity => 2}, $some_file );
# Comme un one-liner
%> perl -MPerl::Critic=critique -e 'print critique(shift)' some_file.pm

Aucune des autres méthodes d'objet n'est actuellement prise en charge en tant que fonctions statiques. Désolé.

CONFIGURATION

La plupart des paramètres de Perl::Critic et de chacun des modules de politique peuvent être contrôlés par un fichier de configuration. Le fichier de configuration par défaut s'appelle .perlcriticrc. Perl::Critic recherchera ce fichier dans le répertoire courant d'abord, puis dans votre répertoire personnel. Alternativement, vous pouvez définir la variable d'environnement "PERLCRITIC" pour pointer explicitement vers un fichier différent dans un autre emplacement. Si aucun de ces fichiers n'existe, et que l'option "-profile" n'est pas fournie au constructeur, alors tous les modules trouvés dans l'espace de noms Perl::Critic::Policy seront chargés avec leur configuration par défaut.

Le format du fichier de configuration est une série de blocs de style INI contenant des paires clé-valeur séparées par '='. Les commentaires doivent commencer par '#' et peuvent être placés sur une ligne séparée ou après les paires nom-valeur si vous le souhaitez.

Les paramètres par défaut pour Perl::Critic lui-même peuvent être définis avant le premier bloc nommé. Par exemple, placer n'importe lequel ou tous les éléments suivants en haut de votre fichier de configuration définira la valeur par défaut pour l'argument correspondant du constructeur.

severity  = 3                                     # Entier ou niveau nommé
only      = 1                                     # Zéro ou Un
force     = 0                                     # Zéro ou Un
verbose   = 4                                     # Entier ou spécificateur de format
top       = 50                                    # Un entier positif
theme     = (pbp || security) && bugs             # Une expression thématique
include   = NamingConventions ClassHierarchies    # Liste délimitée par des espaces
exclude   = Variables  Modules::RequirePackage    # Liste délimitée par des espaces
criticism-fatal = 1                               # Zéro ou Un
color     = 1                                     # Zéro ou Un
allow-unsafe = 1                                  # Zéro ou Un
pager     = less                                  # pagineur vers lequel rediriger la sortie

Le reste du fichier de configuration est une série de blocs comme celui-ci:

[Perl::Critic::Policy::Category::PolicyName]
severity = 1
set_themes = foo bar
add_themes = baz
maximum_violations_per_document = 57
arg1 = value1
arg2 = value2

"Perl::Critic::Policy::Category::PolicyName" est le nom complet d'un module qui implémente la politique. Les modules de politique distribués avec Perl::Critic ont été regroupés en catégories selon la table des matières du livre de Damian Conway, Perl Best Practices. Pour plus de brièveté, vous pouvez omettre la partie 'Perl::Critic::Policy' du nom du module.

"severity" est le niveau d'importance que vous souhaitez attribuer à la politique. Tous les modules de politique sont définis avec une valeur de sévérité par défaut allant de 1 (moins sévère) à 5 (plus sévère). Cependant, vous pouvez ne pas être d'accord avec la sévérité par défaut et choisir de lui donner une sévérité plus élevée ou plus faible, en fonction de votre propre philosophie de codage. Vous pouvez définir la "severity" sur un entier de 1 à 5, ou utiliser l'un des noms équivalents:

NOM DE SÉVÉRITÉ ...est équivalent à... NUMÉRO DE SÉVÉRITÉ
----------------------------------------------------
gentle                                             5
stern                                              4
harsh                                              3
cruel                                              2
brutal                                             1

Les noms reflètent la sévérité avec laquelle le code est critiqué : une critique "gentle" ne signale que les violations les plus sévères, et ainsi de suite jusqu'à une critique "brutal" qui signale même les violations les plus mineures.

"set_themes" définit le thème de la politique et remplace son thème par défaut. L'argument est une chaîne d'un ou plusieurs mots alphanumériques délimités par des espaces. Les thèmes ne sont pas sensibles à la casse. Voir "POLICY THEMES" pour plus d'informations.

"add_themes" ajoute aux thèmes par défaut de cette politique. L'argument est une chaîne d'un ou plusieurs mots délimités par des espaces. Les thèmes ne sont pas sensibles à la casse. Voir "POLICY TH

EMES" pour plus d'informations.

"maximum_violations_per_document" limite le nombre de violations que la Politique renverra pour un document donné. Certaines Politiques ont une limite par défaut ; consultez la documentation des Politiques individuelles pour voir s'il en existe une. Pour forcer une Politique à ne pas avoir de limite, spécifiez "no_limit" ou une chaîne vide pour la valeur de ce paramètre.

Les paires clé-valeur restantes sont des paramètres de configuration qui seront passés au constructeur de cette Politique. Les constructeurs de la plupart des objets Policy ne prennent pas en charge d'arguments, et ceux qui le font devraient avoir des valeurs par défaut raisonnables. Consultez la documentation du module Policy approprié pour plus de détails.

Au lieu de redéfinir la sévérité pour une Politique donnée, vous pouvez désactiver complètement une Politique en ajoutant un '-' au début du nom du module dans votre fichier de configuration. De cette manière, la Politique ne sera jamais chargée, quelle que soit la valeur de "-severity" donnée au constructeur de Perl::Critic.

Une configuration simple pourrait ressembler à ceci :

#--------------------------------------------------------------
# Je pense que ceux-ci sont vraiment importants, alors chargez-les toujours
[TestingAndDebugging::RequireUseStrict]
severity = 5
[TestingAndDebugging::RequireUseWarnings]
severity = 5
#--------------------------------------------------------------
# Je pense que ceux-ci sont moins importants, alors chargez-les seulement sur demande
[Variables::ProhibitPackageVars]
severity = 2
[ControlStructures::ProhibitPostfixControls]
allow = if unless  # Ma configuration personnalisée
severity = cruel   # Équivalent à "severity = 2"
#--------------------------------------------------------------
# Donnez à ces politiques un thème personnalisé. Je peux activer seulement
# ces politiques en disant `perlcritic -theme larry`
[Modules::RequireFilenameMatchesPackage]
add_themes = larry
[TestingAndDebugging::RequireTestLabels]
add_themes = larry curly moe
#--------------------------------------------------------------
# Je ne suis pas du tout d'accord avec ceux-ci, alors ne les chargez jamais
[-NamingConventions::Capitalization]
[-ValuesAndExpressions::ProhibitMagicNumbers]
#--------------------------------------------------------------
# Pour toutes les autres Politiques, j'accepte la sévérité par défaut,
# donc aucune configuration supplémentaire n'est requise pour elles.

Pour des exemples de configuration supplémentaires, consultez le fichier perlcriticrc inclus dans ce répertoire examples de cette distribution.

La configuration Perl::Critic de Damian Conway est également incluse dans cette distribution sous le nom examples/perlcriticrc-conway.

LES POLITIQUES

Un grand nombre de modules de Politique sont distribués avec Perl::Critic. Ils sont décrits brièvement dans le document compagnon Perl::Critic::PolicySummary et plus en détail dans les modules individuels eux-mêmes. Dites "perlcritic -doc PATTERN" pour voir le perldoc de tous les modules de Politique qui correspondent à l'expression régulière "m/PATTERN/ixms".

Il existe un certain nombre de distributions de politiques supplémentaires sur CPAN. Si Perl::Critic ne contient pas la politique que vous souhaitez, quelqu'un l'a peut-être déjà écrite. Consultez la section "VOIR AUSSI" ci-dessous pour une liste de certaines de ces distributions.

THÈMES DE POLITIQUES

Chaque Politique est définie avec un ou plusieurs "thèmes". Les thèmes peuvent être utilisés pour créer des groupes arbitraires de Politiques. Ils sont destinés à fournir un mécanisme alternatif pour sélectionner votre ensemble préféré de Politiques. Par exemple, vous pourriez souhaiter désactiver un certain sous-ensemble de Politiques lors de l'analyse de programmes de test. Inversement, vous pourriez souhaiter activer uniquement un sous-ensemble spécifique de Politiques lors de l'analyse de modules.

Les Politiques fournies avec Perl::Critic ont été réparties dans les thèmes suivants. Ce n'est qu'une tentative de fournir quelques regroupements logiques de base. Vous êtes libre d'inventer de nouveaux thèmes qui correspondent à vos besoins.

THÈME             DESCRIPTION
--------------------------------------------------------------------------
core              Toutes les politiques fournies avec Perl::Critic
pbp               Politiques provenant directement de "Perl Best Practices"
bugs              Politiques qui préviennent ou révèlent des bugs
certrec           Politiques recommandées par le CERT
certrule          Politiques considérées comme des règles par le CERT
maintenance       Politiques qui affectent la santé à long terme du code
cosmetic          Politiques qui n'ont qu'un effet superficiel
complexity        Politiques spécifiquement liées à la complexité du code
security          Politiques liées aux problèmes de sécurité
tests             Politiques spécifiques aux programmes de test

Toute Politique peut appartenir à plusieurs thèmes. Dites "perlcritic -list" pour obtenir une liste de toutes les Politiques disponibles et des thèmes qui y sont associés. Vous pouvez également modifier le thème de toute Politique dans votre fichier .perlcriticrc. Consultez la section "CONFIGURATION" pour plus d'informations.

En utilisant l'option "-theme", vous pouvez créer une règle arbitrairement complexe qui détermine quelles Politiques seront chargées. La précédence est la même que pour le code Perl normal, et vous pouvez utiliser des parenthèses pour imposer la précédence également. Les opérateurs pris en charge sont :

Opérateur    Alternative    Exemple
-----------------------------------------------------------------
&&          and            'pbp && core'
||          or             'pbp || (bugs && security)'
!           not            'pbp && ! (portability || complexity)'

Les noms de thèmes ne sont pas sensibles à la casse. Si "-theme" est défini sur une chaîne vide, alors il évalue toutes les Politiques comme vraies.

PLIER LES RÈGLES

Perl::Critic adopte une approche stricte envers votre code : soit vous vous y conformez, soit vous ne le faites pas. Dans le monde réel, il n'est pas toujours pratique (ni même possible) de se conformer entièrement aux normes de codage. Dans de tels cas, il est sage de montrer que vous violez sciemment les normes et que vous avez une Très Bonne Raison (TBR) pour le faire.

Pour vous aider dans ces situations, vous pouvez demander à Perl::Critic d'ignorer certaines lignes ou blocs de code en utilisant des annotations :

require 'LegacyLibaray1.pl';  ## no critic
require 'LegacyLibrary2.pl';  ## no critic
for my $element (@list) {
    ## no critic
    $foo = "";               # Viole 'ProhibitEmptyQuotes'
    $barf = bar() if $foo;   # Viole 'ProhibitPostfixControls'
    # Encore du code maléfique...
    ## use critic
    # Du bon code...
    do_something($_);
}

Les annotations "## no critic" demandent à Perl::Critic d'ignorer les lignes de code restantes jusqu'à ce qu'une annotation "## use critic" soit trouvée. Si l'annotation "## no critic" se trouve sur la même ligne qu'une instruction de code, seule cette ligne de code est ignorée. Pour demander à perlcritic d'ignorer les annotations "## no critic", utilisez l'option "--force".

Une annotation nue "## no critic" désactive toutes les Politiques actives. Si vous souhaitez désactiver uniquement des Politiques spécifiques, ajoutez une liste de noms de Politiques en tant qu'arguments, comme vous le feriez pour les pragmas "no strict" ou "no warnings". Par exemple, cela désactiverait les politiques "ProhibitEmptyQuotes" et "ProhibitPostfixControls" jusqu'à la fin du bloc ou jusqu'à la prochaine annotation "## use critic" (selon ce qui vient en premier) :

## no critic (EmptyQuotes, PostfixControls)
# Désormais exempt de ValuesAndExpressions::ProhibitEmptyQuotes
$foo = "";
# Désormais exempt de ControlStructures::ProhibitPostfixControls
$barf = bar() if $foo;
# Toujours soumis à ValuesAndExpression::RequireNumberSeparators
$long_int = 10000000000;

Étant donné que les noms de Politiques sont mis en correspondance avec les arguments de "## no critic" en tant qu'expressions régulières, vous pouvez abréger les noms de Politiques ou désactiver toute une famille de Politiques en une seule fois comme ceci :

## no critic (NamingConventions)
# Désormais exempt de NamingConventions::Capitalization
my $camelHumpVar = 'foo';
# Désormais exempt de NamingConventions::Capitalization
sub camelHumpSub {}

La liste des arguments doit être entourée de parenthèses ou de crochets et doit contenir un ou plusieurs mots vides séparés par des virgules (par exemple, n'utilisez pas de guillemets). Les annotations "## no critic" peuvent être imbriquées, et les Politiques nommées par une annotation interne seront désactivées avec celles déjà désactivées par une annotation externe.

Certaines Politiques comme "Subroutines::ProhibitExcessComplexity" s'appliquent à tout un bloc de code. Dans ces cas, l'annotation "## no critic" doit apparaître sur la ligne où la violation est signalée. Par exemple :

sub complicated_function {  ## no critic (ProhibitExcessComplexity)
    # Votre code ici...
}

Les Politiques telles que "Documentation::RequirePodSections" s'appliquent à l'ensemble du document, auquel cas les violations sont signalées à la ligne 1.

Utilisez cette fonctionnalité judicieusement. Les annotations "## no critic" doivent être utilisées dans la portée la plus petite possible, ou uniquement sur des lignes de code individuelles. Et vous devez toujours être aussi spécifique que possible quant aux Politiques que vous souhaitez désactiver (c'est-à-dire n'utilisez jamais un "## no critic" nu). Si Perl::Critic se plaint de votre code, essayez de trouver une solution conforme avant de recourir à cette fonctionnalité.

LA PHILOSOPHIE_Perl::Critic

Les normes de codage sont profondément personnelles et hautement subjectives. L'objectif de Perl::Critic est de vous aider à écrire du code qui est conforme à un ensemble de bonnes pratiques. Notre objectif principal n'est pas de dicter quelles sont ces pratiques, mais plutôt de mettre en œuvre les pratiques découvertes par d'autres. En fin de compte, c'est vous qui définissez les règles -- Perl::Critic n'est qu'un outil pour encourager la cohérence. S'il existe une politique que vous jugez importante ou que nous avons négligée, nous serions très reconnaissants de vos contributions, ou vous pouvez simplement charger votre propre ensemble privé de politiques dans Perl::Critic.

La conception modulaire de Perl::Critic est destinée à faciliter l'ajout de nouvelles Politiques. Vous devrez avoir une certaine compréhension de PPI, mais la plupart des modules de Politique sont assez simples et ne nécessitent qu'environ 20 lignes de code. Veuillez consulter le

    use Perl::Critic;

    my $critic = Perl::Critic->new(
        policy_store => 'Perl::Critic::Policy::Theme::$$authorname::$$policyname',

    my @violations = $critic->critique_files('MyModule.pm');
    if (@violations) {
        print $critic->formatted_violations(@violations);
        exit 1;
    }

    # or, to critique a string of code:
    my @violations = $critic->critique_string($code_string);
    if (@violations) {

        exit 1;
    }

    # or, to critique a file:
    my $violations = $critic->critique_file('MyModule.pm');
    if ($violations) {
        print $critic->formatted_violations($violations);
        exit 1;
    }

    # to use a policy theme:
    my $critic = Perl::Critic->new(
        policy_store => 'Perl::Critic::Policy::Theme::Core',
    );

    # to set a minimum severity level:
    my $critic = Perl::Critic->new(
        policy_store => 'Perl::Critic::Policy::Theme::Core',
        severity     => 'criticisms',
    );

    my $critic = Perl::Critic->new(

    my $critic = Perl::Critic->new(

    my $critic = Perl::Critic->new(
        policy_store => 'Perl::Critic::Policy::Theme::Core',
        configure    => {
            'Subroutines::ProhibitSubcontext' => {
                severity_level => 'harmless',
            },
            'Values::RequireDecimal' => {
                severity_level => 'harmless',
            },
        },
    );

    my $critic = Perl::Critic->new(

            'Perl::Critic::Policy::Theme::Core',
            'Perl::Critic::More',

    my $critic = Perl::Critic->new();

DESCRIPTION

Perl::Critic is a code-checking utility that finds Perl code that violates your organization's coding standards. It can be used to enforce a wide range of coding standards, from simple stylistic preferences to complex requirements for the proper use of language features.

Perl::Critic is designed to be highly configurable. Its policies can be organized into themes, and you can create your own themes to fit your organization's needs. It can also be extended with new policies.

Perl::Critic is written in Perl and uses the PPI module to parse Perl code. This allows it to analyze code in a way that is independent of Perl version, and to provide detailed and accurate information about the code's structure.

INTERFACE SUPPORT

The Perl::Critic interface is stable and will not be broken behind your back. Any changes to the interface will be clearly documented, and will be announced on the Perl::Critic mailing list.

CONSTRUCTOR

The constructor for Perl::Critic is new().

It accepts the following options:

policy_store
A string, arrayref, or scalarref that specifies which policies to load. Can be:
'local': Load policies from the current directory. 'all': Load all policies from all installed Policy modules. A string representing a single Policy module or Theme. An arrayref of strings, where each string is a Policy module or Theme. A scalarref to a file containing a list of Policy modules or Themes, one per line.
severity
A string that specifies the minimum severity level to report. Can be 'harmless', 'criticisms', 'recommendations', or 'violations'. Defaults to 'violations'.
exclude
An arrayref of strings that specifies the policies to exclude. Each string is the name of a policy to exclude.
include
An arrayref of strings that specifies the policies to include. Each string is the name of a policy to include. If include is specified, only the listed policies will be used.
configure
A hashref that specifies configuration options for policies. The keys are policy names, and the values are hashrefs of configuration options.
threads
An integer that specifies the number of threads to use. Defaults to the number of CPU cores available.

METHODS

critique_files(@filenames)
Critiques the given files and returns a list of violations.
critique_string($string)
Critiques the given string and returns a list of violations.
critique_file($filename)
Critiques the given file and returns a list of violations.
formatted_violations(@violations)
Formats the given violations into a human-readable string.

FUNCTIONAL INTERFACE

The following functions are available:

Perl::Critic::critique_files(@filenames)
A functional interface to critique files.
Perl::Critic::critique_string($string)
A functional interface to critique strings.
Perl::Critic::critique_file($filename)
A functional interface to critique files.
Perl::Critic::formatted_violations(@violations)
A functional interface to format violations.

CONFIGURATION

Perl::Critic can be configured using a configuration file named .perlcriticrc in the current directory or in your home directory. The configuration file uses the same format as the constructor options.

THE POLICIES

Perl::Critic comes with a set of built-in policies that are organized into themes. The default theme is Perl::Critic::Policy::Theme::Core.

You can create your own policies by subclassing Perl::Critic::Policy and implementing the desired behavior.

For a step-by-step demonstration of how to create new Policy modules, see the DEVELOPER file included in this distribution.

If you develop any new Policy modules, feel free to send them to "<team@perlcritic.com>" and I'll be happy to consider putting them into the Perl::Critic distribution. Or if you would like to work on the Perl::Critic project directly, you can fork our repository at https://github.com/Perl-Critic/Perl-Critic.git.

The Perl::Critic team is also available for hire. If your organization has its own coding standards, we can create custom Policies to enforce your local guidelines. Or if your code base is prone to a particular defect pattern, we can design Policies that will help you catch those costly defects before they go into production. To discuss your needs with the Perl::Critic team, just contact "<team@perlcritic.com>".

POLICY THEMES

Policies are organized into themes. The default theme is Perl::Critic::Policy::Theme::Core. You can create your own themes by subclassing Perl::Critic::Policy::Theme.

BENDING THE RULES

If you need to break a rule, you can do so by adding a comment in your code like this:

    # perlcritic: CODE             # My reason for breaking the rule

Where CODE is the name of the policy you are breaking. For example:

    # perlcritic: Subroutines::ProhibitSubcontext # This is a callback function

You can also disable rules for a block of code:

    # perlcritic: begin
    # perlcritic: Subroutines::ProhibitSubcontext
    # perlcritic: Values::RequireDecimal
    # ... code ...
    # perlcritic: end
