Perl::Critic::Utils(3pm) Documentation Perl fournie par l'utilisateur Perl::Critic::Utils(3pm)

NOM

Perl::Critic::Utils - sous-routines utilitaires générales et constantes pour Perl::Critic et les distributions dérivées.

DESCRIPTION

Ce module fournit plusieurs sous-routines statiques et variables qui sont utiles pour développer des sous-classes de Perl::Critic::Policy. Sauf si vous écrivez des modules de politique, ce paquet ne vous intéressera probablement pas.

SUPPORT D'INTERFACE

Ce module est considéré comme public. Tout changement de son interface passera par un cycle de dépréciation.

SOUS-ROUTINES IMPORTABLES

"find_keywords( $doc, $keyword )"
DÉPRÉCIÉ : Depuis la version 0.11, chaque politique est évaluée à chaque élément du document. Vous ne devriez donc pas avoir besoin de rechercher un mot-clé particulier. Si vous souhaitez utiliser cette fonction, veuillez l'importer via la balise ":deprecated", plutôt que directement, pour marquer le module comme nécessitant une mise à jour.

Étant donné un PPI::Document sous $doc, retourne une référence vers un tableau contenant tous les éléments PPI::Token::Word qui correspondent à $keyword. Cela peut être utilisé pour trouver n'importe quelle fonction intégrée, appel de méthode, bareword ou mot-clé réservé. Cela ne correspondra pas aux variables, noms de sous-routines, chaînes littérales, nombres ou symboles. Si le document ne contient aucune correspondance, retourne undef.

is_assignment_operator( $element )
Étant donné un PPI::Token::Operator ou une chaîne de caractères, retourne vrai si ce jeton représente l'un des opérateurs d'affectation (par exemple, "= &&= ||= //= += -= etc.).
is_perl_global( $element )
Étant donné un PPI::Token::Symbol ou une chaîne de caractères, retourne vrai si ce jeton représente l'une des variables globales fournies par le module English, ou l'une des variables globales intégrées comme %SIG, %ENV, ou @ARGV. Le sigil du symbole est ignoré, donc des éléments comme $ARGV ou $ENV retourneront toujours vrai.
is_perl_builtin( $element )
Étant donné un PPI::Token::Word, PPI::Statement::Sub, ou une chaîne de caractères, retourne vrai si ce jeton représente un appel à l'une des fonctions intégrées.
is_perl_bareword( $element )
Étant donné un PPI::Token::Word, PPI::Statement::Sub, ou une chaîne de caractères, retourne vrai si ce jeton représente un bareword (par exemple, "if", "else", "sub", "package").
is_perl_filehandle( $element )
Étant donné un PPI::Token::Word, ou une chaîne de caractères, retourne vrai si ce jeton représente l'un des descripteurs de fichiers globaux (par exemple, "STDIN", "STDERR", "STDOUT", "ARGV"). Notez que cette fonction retournera faux si un descripteur de fichier est représenté par un typeglob (par exemple, *STDIN)
is_perl_builtin_with_list_context( $element )
Étant donné un PPI::Token::Word, PPI::Statement::Sub, ou une chaîne de caractères, retourne vrai si ce jeton représente un appel à l'une des fonctions intégrées qui fournissent un contexte de liste aux jetons suivants.
is_perl_builtin_with_multiple_arguments( $element )
Étant donné un PPI::Token::Word, PPI::Statement::Sub, ou une chaîne de caractères, retourne vrai si ce jeton représente un appel à l'une des fonctions intégrées qui **peuvent** prendre plusieurs arguments.
is_perl_builtin_with_no_arguments( $element )
Étant donné un PPI::Token::Word, PPI::Statement::Sub, ou une chaîne de caractères, retourne vrai si ce jeton représente un appel à l'une des fonctions intégrées qui **ne peuvent pas** prendre d'arguments.
is_perl_builtin_with_one_argument( $element )
Étant donné un PPI::Token::Word, PPI::Statement::Sub, ou une chaîne de caractères, retourne vrai si ce jeton représente un appel à l'une des fonctions intégrées qui prend **un et un seul** argument.
is_perl_builtin_with_optional_argument( $element )
Étant donné un PPI::Token::Word, PPI::Statement::Sub, ou une chaîne de caractères, retourne vrai si ce jeton représente un appel à l'une des fonctions intégrées qui prend **pas plus d'un** argument.

Les ensembles de valeurs pour lesquels is_perl_builtin_with_multiple_arguments(), is_perl_builtin_with_no_arguments(), is_perl_builtin_with_one_argument(), et is_perl_builtin_with_optional_argument() retournent vrai sont disjoints et leur union est précisément l'ensemble des valeurs pour lesquelles is_perl_builtin() retournera vrai.

is_perl_builtin_with_zero_and_or_one_arguments( $element )
Étant donné un PPI::Token::Word, PPI::Statement::Sub, ou une chaîne de caractères, retourne vrai si ce jeton représente un appel à l'une des fonctions intégrées qui prend zéro et/ou un argument.

Retourne vrai si l'une des fonctions is_perl_builtin_with_no_arguments(), is_perl_builtin_with_one_argument(), et is_perl_builtin_with_optional_argument() retourne vrai.

is_qualified_name( $name )
Étant donné une chaîne de caractères, un PPI::Token::Word, ou un PPI::Token::Symbol, répond si elle a un composant de module, c'est-à-dire contient "::".
precedence_of( $element )
Étant donné un PPI::Token::Operator ou une chaîne de caractères, retourne la précédence de l'opérateur, où 1 est la précédence la plus élevée. Retourne undef si la précédence ne peut pas être déterminée (ce qui est généralement parce que ce n'est pas un opérateur).
is_hash_key( $element )
Étant donné un PPI::Element, retourne vrai si l'élément est une clé de hachage littérale. PPI ne fait pas de distinction entre les barewords ordinaires (comme les mots-clés ou les appels de sous-routines) et les barewords dans les sous-scripts de hachage (qui sont considérés comme littéraux). Cette sous-routine est donc utile si votre politique recherche des éléments PPI::Token::Word et que vous souhaitez filtrer la variété des sous-scripts de hachage. Dans les deux exemples suivants, "foo" est considéré comme une clé de hachage : 
$hash1{foo} = 1;
%hash2 = (foo => 1);

Mais si le bareword est suivi d'une liste d'arguments, alors perl le traite comme un appel de fonction. Donc, dans ces exemples, "foo" n'est **pas** considéré comme une clé de hachage :

$hash1{ foo() } = 1;
&hash2 = (foo() => 1);
is_included_module_name( $element )
Étant donné un PPI::Token::Word, retourne vrai si l'élément est le nom d'un module qui est inclus via "use", "require", ou "no".
is_integer( $value )
Répond si le paramètre, sous forme de chaîne, ressemble à une valeur entière.
is_class_name( $element )
Étant donné un PPI::Token::Word, retourne vrai si l'élément qui suit immédiatement cet élément est l'opérateur de déréférencement "->". Lorsqu'un bareword a un "->" du côté **droit**, cela signifie généralement qu'il s'agit du nom de la classe (à partir de laquelle une méthode est appelée).
is_label_pointer( $element )
Étant donné un PPI::Token::Word, retourne vrai
Mantén toda la estructura del archivo.
is_method_call( $element )
Étant donné un PPI::Token::Word, renvoie vrai si l'élément qui précède immédiatement cet élément est l'opérateur de déréférencement « - ». Quand un bareword a un « - » sur le côté gauche, cela signifie généralement qu'il s'agit du nom d'une méthode (qui est appelée depuis une classe).
is_package_declaration( $element )
Étant donné un PPI::Token::Word, renvoie vrai si l'élément est le nom d'un package qui est déclaré.
is_subroutine_name( $element )
Étant donné un PPI::Token::Word, renvoie vrai si l'élément est le nom d'une déclaration de sous-routine. Ceci est utile pour distinguer les barewords et les appels de fonction des déclarations de sous-routines.
is_function_call( $element )
Étant donné un PPI::Token::Word, renvoie vrai si l'élément semble être un appel à une fonction statique. Spécifiquement, cette fonction renvoie vrai si « is_hash_key », « is_method_call », « is_subroutine_name », « is_included_module_name », « is_package_declaration », « is_perl_bareword », « is_perl_filehandle », « is_label_pointer » et « is_subroutine_name » renvoient tous faux pour l'élément donné.
first_arg( $element )
Étant donné un PPI::Element supposé être un appel de fonction (qui est généralement un PPI::Token::Word), renvoie le premier argument. Ceci est similaire à parse_arg_list() et suit la même logique. Notez que pour le code : 
int($x + 0.5)

cette fonction ne renverra que le $x, pas toute l'expression. Ceci est différent du comportement de parse_arg_list(). Une autre mise en garde est :

int(($x + $y) + 0.5)

qui renvoie « ($x + $y) » en tant qu'instance PPI::Structure::List.

parse_arg_list( $element )
Étant donné un PPI::Element supposé être un appel de fonction (qui est généralement un PPI::Token::Word), divise les expressions d'arguments en tableaux de tokens. Renvoie une liste contenant des références à chacun de ces tableaux. Ceci est utile car les parenthèses sont facultatives lors de l'appel d'une fonction, et PPI les analyse très différemment. Donc, cette méthode est un parseur d'arbres bon marché de nœuds PPI. Ce n'est pas infaillible car elle ne respecte pas la précédence. En général, je n'aime pas la façon dont cette fonction fonctionne, donc ne comptez pas sur sa stabilité (ou même sa présence).
split_nodes_on_comma( @nodes )
Ceci a le même type de retour que parse_arg_list() mais attend de recevoir les nœuds qui représentent l'intérieur d'une liste, comme : 
'foo', 1, 2, 'bar'
is_script( $document )
Cette sous-routine est obsolète et sera supprimée dans une future version. Vous devriez utiliser la méthode « is_program() » dans Perl::Critic::Document à la place.
is_in_void_context( $token )
Étant donné un PPI::Token, répond s'il semble être dans un contexte vide.
policy_long_name( $policy_name )
Étant donné un nom de classe de politique sous forme longue ou courte, renvoie la forme longue.
policy_short_name( $policy_name )
Étant donné un nom de classe de politique sous forme longue ou courte, renvoie la forme courte.
all_perl_files( @directories )
Étant donné une liste de répertoires, recherche récursivement dans tous les répertoires (en profondeur d'abord) et renvoie une liste de chemins pour tous les fichiers qui sont des fichiers de code Perl. Tous les fichiers administratifs pour CVS ou Subversion sont ignorés, tout comme les éléments qui ressemblent à des fichiers temporaires ou de sauvegarde.

Un fichier de code Perl est :

  • Tout fichier se terminant par .PL, .pl, .pm, .psgi, ou .t
  • Tout fichier dont la première ligne contient un shebang avec « perl »
severity_to_number( $severity )
Si $severity est donné sous forme d'entier, cette fonction renvoie $severity mais normalisé pour se situer entre $SEVERITY_LOWEST et $SEVERITY_HIGHEST. Si $severity est donné sous forme de chaîne, cette fonction renvoie le numéro de sévérité correspondant. Si la chaîne n'a pas de numéro correspondant, cette fonction lèvera une exception.
is_valid_numeric_verbosity( $severity )
Répond si l'argument a une traduction vers un format de Violation.
verbosity_to_format( $verbosity_level )
Étant donné un niveau de verbosité entre 1 et 10, renvoie la chaîne de format prédéfinie correspondante. Ces formats conviennent pour être passés à la méthode « set_format » dans Perl::Critic::Violation. Voir la documentation de perlcritic pour une liste des formats prédéfinis.
hashify( @list )
Étant donné @list, renvoie une table de hachage où @list se trouve dans les clés et chaque valeur est 1. Les doublons dans @list sont silencieusement écrasés.
interpolate( $literal )
Étant donné une chaîne $literal qui peut contenir des caractères de contrôle (par exemple, '\t' '\n'), cette fonction effectue une double interpolation sur la chaîne et la renvoie comme si elle avait été déclarée entre guillemets doubles. Par exemple : 
'foo \t bar \n' ...devient... "foo \t bar \n"
shebang_line( $document )
Étant donné un PPI::Document, teste s'il commence par « #! ». Si c'est le cas, renvoie cette ligne. Sinon, renvoie undef.
words_from_string( $str )
Étant donné une chaîne de configuration $str, renvoie tous les mots de la chaîne. C'est plus sûr que de diviser par les espaces blancs.
"is_unchecked_call( $element, $autodie_modules )"
Étant donné un PPI::Element, teste s'il contient un appel de fonction dont la valeur de retour n'est pas vérifiée. Le deuxième argument est une référence de tableau de noms de modules qui exportent « autodie ». Le module « autodie » est toujours inclus par défaut dans cette liste.

VARIABLES IMPORTABLES

$COMMA

$DQUOTE

$PERIOD

$EMPTY
$EQUAL
$SPACE
$SLASH

$LEFT_PAREN

Ces constantes de caractères donnent des noms clairs à des chaînes couramment utilisées qui peuvent être difficiles à lire lorsqu'elles sont entourées de guillemets et d'autres ponctuations. Peuvent être importées en une seule fois via la balise « :characters ».
$SEVERITY_HIGHEST
$SEVERITY_HIGH
$SEVERITY_MEDIUM
$SEVERITY_LOW
$SEVERITY_LOWEST
Ces constantes numériques définissent la sévérité relative de la violation de chaque Perl::Critic::Policy. Les méthodes « get_severity » et « default_severity » de chaque sous-classe de Policy doivent renvoyer l'une de ces valeurs. Peuvent être importées via la balise « :severities ».
$DEFAULT_VERBOSITY
La verbosité numérique par défaut.
$DEFAULT_VERBOSITY_WITH_FILE_NAME
La verbosité numérique qui correspond au format indiqué par « $DEFAULT_VERBOSITY », mais avec le nom du fichier préfixé.
$TRUE
$FALSE
Ce sont de simples booléens. 1 et 0 respectivement. Soyez prudent lorsque vous les utilisez avec l'égalité de chaînes. « $FALSE ne $EMPTY » . Peuvent être importés via la balise « :booleans ».
