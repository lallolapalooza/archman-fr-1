NOM

Perl::Critic::Policy::Subroutines::RequireArgUnpacking - Toujours déballer "@_" en premier.

AFFILIATION

Cette politique fait partie de la distribution de base de Perl::Critic.

DESCRIPTION

Les sous-routines qui utilisent @_ directement au lieu de déballer les arguments dans des variables locales en premier ont deux problèmes majeurs. Premièrement, elles sont très difficiles à lire. Si vous allez faire référence à vos variables par leur numéro au lieu de leur nom, vous pourriez aussi bien écrire en assembleur ! Deuxièmement, @_ contient des alias vers les variables originales ! Si vous modifiez le contenu d'une entrée de @_, vous modifiez la variable en dehors de votre sous-routine. Par exemple :

sub print_local_var_plus_one {
    my ($var) = @_;
    print ++$var;
}
sub print_var_plus_one {
    print ++$_[0];
}
my $x = 2;
print_local_var_plus_one($x); # affiche "3", $x est toujours 2
print_var_plus_one($x);       # affiche "3", $x vaut maintenant 3 !
print $x;                     # affiche "3"

C'est une action fantôme à distance et très difficile à déboguer si ce n'est pas intentionnel et bien documenté (comme "chop" ou "chomp").

Une exception est faite pour l'idiome de délégation habituel "$object->SUPER::something( @_ )". Seuls "SUPER::" et "NEXT::" sont reconnus (bien que cela soit configurable) et la liste d'arguments pour le délégué doit consister uniquement en "( @_ )".

CONFIGURATION

Cette politique est tolérante pour les sous-routines qui ont "N" instructions ou moins au plus haut niveau, où "N" vaut par défaut ZÉRO. Vous pouvez outrepasser ceci pour le définir à un nombre plus élevé avec le réglage "short_subroutine_statements". Ce n'est pas recommandé, mais peut-être avez-vous VRAIMENT besoin de hautes performances. Pour ce faire, placez des entrées dans un fichier .perlcriticrc comme ceci :

[Subroutines::RequireArgUnpacking]
short_subroutine_statements = 2

Par défaut, cette politique ne vous permet pas de spécifier des indices de tableau lorsque vous déballez des arguments (c'est-à-dire par une tranche de tableau ou en référençant des éléments individuels). Si vous souhaitez autoriser cela, vous pouvez le faire en utilisant le réglage "allow_subscripts". Par défaut, il est faux. Vous pouvez le définir à vrai comme ceci :

[Subroutines::RequireArgUnpacking]
allow_subscripts = 1

La logique de délégation peut être configurée pour autoriser la délégation autre que vers "SUPER::" ou "NEXT::". L'élément de configuration est "allow_delegation_to", et il prend une liste séparée par des espaces des délégués autorisés. Si un délégué donné se termine par deux points, tout dans l'espace de noms donné est autorisé. S'il ne se termine pas ainsi, seul ce sous-programme est autorisé. Par exemple, pour autoriser "next::method" de "Class::C3" et _delegate depuis l'espace de noms actuel en plus de SUPER et NEXT, la configuration suivante pourrait être utilisée :

[Subroutines::RequireArgUnpacking]
allow_delegation_to = next::method _delegate

Les outils de validation d'arguments tels que Params::Validate génèrent une fermeture qui est utilisée pour déballer et valider les arguments d'un sous-programme. Afin de reconnaître les fermetures comme un moyen valide de déballer les arguments, vous devez les activer explicitement :

[Subroutines::RequireArgUnpacking]
allow_closures = 1

LIMITATIONS

PPI ne détecte pas actuellement les sous-programmes anonymes, nous ne les vérifions donc pas. Cela devrait fonctionner lorsque PPI gagnera cette fonctionnalité.

Nous ne vérifions pas @ARG, l'alias de @_ de English.pm. C'est de toute façon déprécié.
