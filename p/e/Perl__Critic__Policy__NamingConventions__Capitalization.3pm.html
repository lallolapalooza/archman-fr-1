NOM

Perl::Critic::Policy::NamingConventions::Capitalization - Distinguer les différents composants du programme par la casse.

AFILATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Conway recommande de distinguer les différents composants du programme par la casse.

Les sous-routines, méthodes et variables normales sont toutes en minuscules.

my $foo;            # ok
my $foo_bar;        # ok
sub foo {}          # ok
sub foo_bar {}      # ok
my $Foo;            # pas ok
my $foo_Bar;        # pas ok
sub Foo     {}      # pas ok
sub foo_Bar {}      # pas ok

Les noms de paquets et de classes sont capitalisés.

package IO::Thing;     # ok
package Web::FooBar    # ok
package foo;           # pas ok
package foo::Bar;      # pas ok

Les constantes sont entièrement en majuscules.

Readonly::Scalar my $FOO = 42;  # ok
Readonly::Scalar my $foo = 42;  # pas ok

Il existe d'autres opinions sur les spécificités, par exemple dans perlstyle. Cette politique peut être configurée pour correspondre à presque n'importe quel style que vous pouvez imaginer.

CONFIGURATION

Vous pouvez spécifier des règles de casse pour les éléments suivants : "packages", "subroutines", "local_lexical_variables", "scoped_lexical_variables", "file_lexical_variables", "global_variables", "constants", et "labels".

"constants" sont des éléments déclarés via constant ou Readonly.

use constant FOO => 193;
Readonly::Array my @BAR => qw< a b c >;

"global_variables" sont tout ce qui est déclaré en utilisant "local", "our", ou vars. "file_lexical_variables" sont des variables déclarées à la portée du fichier.

"scoped_lexical_variables" sont des variables déclarées à l'intérieur de blocs nus qui sont en dehors de toute sous-routine ou autre structure de contrôle ; elles sont généralement créées pour limiter la portée des variables à un sous-ensemble donné de sous-routines. Par exemple.

sub foo { ... }
{
    my $thingy;
    sub bar { ... $thingy ... }
    sub baz { ... $thingy ... }
}

Toutes les autres déclarations de variables sont considérées comme "local_lexical_variables".

Chacune des options "packages", "subroutines", "local_lexical_variables", "scoped_lexical_variables", "file_lexical_variables", "global_variables", "constants", et "labels" peut être spécifiée comme l'une des options : ":single_case", ":all_lower", ":all_upper:", ":starts_with_lower", ":starts_with_upper", ou ":no_restriction" ou une expression régulière ; toute valeur qui ne commence pas par deux-points, ":", est considérée comme une expression régulière. Le tag ":single_case" signifie qu'un nom peut être entièrement en minuscules ou entièrement en majuscules. Si une expression régulière est spécifiée, elle est entourée de "\A" et "\z".

"packages" a par défaut la valeur ":starts_with_upper". "subroutines", "local_lexical_variables", "scoped_lexical_variables", "file_lexical_variables", et "global_variables" ont par défaut la valeur ":single_case". Et "constants" et "labels" ont par défaut la valeur ":all_upper".

Il existe des options correspondantes "package_exemptions", "subroutine_exemptions", "local_lexical_variable_exemptions", "scoped_lexical_variable_exemptions", "file_lexical_variable_exemptions", "global_variable_exemptions", "constant_exemptions", et "label_exemptions" qui sont des listes d'expressions régulières à exempter de la règle de casse correspondante. Ces valeurs finissent également par être entourées de "\A" et "\z".

"package_exemptions" a par défaut la valeur "main". "global_variable_exemptions" a par défaut la valeur "\$VERSION @ISA @EXPORT(?:_OK)? %EXPORT_TAGS \$AUTOLOAD %ENV %SIG \$TODO". "subroutine_exemptions" a par défaut la valeur "AUTOLOAD BUILD BUILDARGS CLEAR CLOSE DELETE DEMOLISH DESTROY EXISTS EXTEND FETCH FETCHSIZE FIRSTKEY GETC NEXTKEY POP PRINT PRINTF PUSH READ READLINE SCALAR SHIFT SPLICE STORE STORESIZE TIEARRAY TIEHANDLE TIEHASH TIESCALAR UNSHIFT UNTIE WRITE" qui devrait couvrir toutes les sous-routines standard de Perl ainsi que celles de Moose.

Notez que "package_exemptions" ne vérifie pas les noms de paquets complets. Pour "Foo::Bar::baz", il vérifiera "Foo", "Bar" et "baz" séquentiellement.

Par exemple, si vous voulez que toutes les variables locales soient en minuscules et que les variables globales commencent par "G_" et ne contiennent pas d'autres traits d'union, mais que vous voulez exempter toute variable dont le nom contient "THINGY", vous pouvez mettre ce qui suit dans votre .perlcriticrc :

[NamingConventions::Capitalization]
local_lexical_variables = :all_lower
global_variables = G_(?:(?!_)\w)+
global_variable_exemptions = .*THINGY.*

A FAIRE

Gérer "use vars". Traiter les sous-routines constantes comme des variables constantes. Gérer les descripteurs de fichiers nus. Il faudrait des "schémas" ou des moyens de spécifier "perlstyle" ou "pbp". Différencier les constantes lexicales Readonly dans les scopes.

BOGUES

Cette politique ne détectera pas les problèmes avec la déclaration de $y ci-dessous :

for (my $x = 3, my $y = 5; $x < 57; $x += 3) {
    ...
}
