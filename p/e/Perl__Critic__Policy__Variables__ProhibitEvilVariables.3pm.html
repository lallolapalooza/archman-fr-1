NOM

Perl::Critic::Policy::Variables::ProhibitEvilVariables - Interdire les variables qui ne sont pas approuvées par votre magasin.

AFILATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Utilisez cette politique si vous souhaitez interdire l'utilisation de variables spécifiques. Il peut s'agir de variables globales signalées dans "perlvar", ou simplement de variables dont les noms ne vous plaisent pas.

CONFIGURATION

L'ensemble des variables interdites est configurable via les options "variables" et "variables_file".

La valeur de "variables" doit être une chaîne de noms de variables entièrement qualifiés et/ou d'expressions régulières, séparés par des espaces. Un exemple d'interdiction de deux variables spécifiques dans un fichier .perlcriticrc :

[Variables::ProhibitEvilVariables]
variables = $[ $^S $SIG{__DIE__}

Si vous interdisez un tableau ou une table de hachage (par exemple @INC), l'utilisation d'éléments du tableau ou de la table de hachage sera également interdite. Si vous spécifiez une variable avec un indice (par exemple $SIG{__DIE__}), seul l'indice littéral spécifié sera détecté. Le fichier <.perlcritic> ci-dessus, par exemple, fera en sorte que "perlcritic (1)" détecte "$SIG{__DIE__} = \&foo", mais pas

my $foo = '__DIE__';
$SIG{$foo} = \&foo;

Les expressions régulières sont identifiées par des valeurs commençant et se terminant par des barres obliques. Toute variable dont le nom correspond à "m/pattern/sm" sera interdite. Par exemple :

[Variables::ProhibitEvilVariables]
variables = /acme/

interdirait toutes les variables qui correspondent à "m/acme/". Si vous souhaitez une vérification insensible à la casse, vous pouvez utiliser (?i: ... ). Par exemple :

[Variables::ProhibitEvilVariables]
variables = /(?i:acme)/

interdit les variables qui correspondent à "m/acme/smi".

De plus, vous pouvez remplacer le message par défaut ("Variable interdite "variable" utilisée") par le vôtre, afin de donner des suggestions d'action alternative. Pour ce faire, placez votre message entre accolades après le nom de la variable ou l'expression régulière. Comme ceci :

[Variables::ProhibitEvilVariables]
variables = $[ {Utilisation de $[ trouvée. Programmez plutôt avec un index de base 0}

Si votre message contient des accolades, vous pouvez l'encadrer avec des parenthèses, des chevrons ou des crochets à la place.

De même, l'option "variables_file" donne le nom d'un fichier contenant les spécifications des variables interdites. Une seule spécification de variable est autorisée par ligne et les commentaires commencent par un octothorpe et vont jusqu'à la fin de la ligne ; aucune accolade n'est nécessaire pour délimiter les messages :

$[      # Interdire la variable "$[" et utiliser le message par défaut.
# Interdire la variable "$^S" et donner un message de remplacement.
$^S     Avoir à penser à $^S dans les gestionnaires d'exception est juste mal
# Utiliser une expression régulière.
/acme/  Pas de coyotes autorisés.

Par défaut, il n'y a pas de variables interdites, bien que je puisse en imaginer quelques-unes qui devraient l'être. Voir "perldoc perlvar" pour quelques suggestions.

RESTRICTIONS

Les variables de la forme "${^foo}" ne sont pas reconnues par PPI à partir de la version 1.206. Lorsque PPI les reconnaîtra, cette politique fonctionnera également pour elles.

Seules les références directes aux variables interdites et les indices littéraux seront reconnus. Par exemple, si vous interdisez $[, la première ligne dans

my $foo = \$[;
$$foo = 1;

sera signalée comme une violation, mais pas la seconde, même si la seconde, en fait, assigne à $[. De même, si vous interdisez $SIG{__DIE__}, cette politique ne reconnaîtra pas

my $foo = '__DIE__';
$SIG{$foo} = sub {warn 'Je ne peux pas mourir!'};

comme une affectation à $SIG{__DIE__}.

NOTES

Cette politique s'appuie fortement sur Perl::Critic::Policy::Modules::ProhibitEvilModules de Jeffrey Ryan Thalhammer.
