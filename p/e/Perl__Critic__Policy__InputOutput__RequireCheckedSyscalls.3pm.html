NOM

Perl::Critic::Policy::InputOutput::RequireCheckedSyscalls - La valeur de retour des fonctions signalées est ignorée.

AFFILIATION

Cette politique fait partie de la distribution centrale de Perl::Critic.

DESCRIPTION

Ceci fonctionne de manière identique à InputOutput::RequireCheckedOpen/Close, sauf que ceci est configurable pour s'appliquer à n'importe quelle fonction, qu'elle soit native ou définie par l'utilisateur.

Si votre module utilise Fatal, Fatal::Exception, ou autodie, toutes les fonctions encapsulées par ces modules ne déclencheront pas cette politique. Par exemple :

use Fatal qw(open);
open my $fh, $filename;  # pas de violation
close $fh;               # violation
use autodie;
open $filehandle, $mode, $filename;   # pas de violation

Actuellement, autodie n'est pas correctement traité comme un pragma ; ses effets lexicaux ne sont pas pris en compte.

CONFIGURATION

Cette politique surveille une liste configurable de noms de fonctions. Par défaut, elle s'applique à "open", "print", "say" et "close". Vous pouvez remplacer cela pour définir une liste différente de fonctions avec les paramètres "functions" et "exclude_functions". Pour ce faire, placez des entrées dans un fichier .perlcriticrc comme ceci :

[InputOutput::RequireCheckedSyscalls]
functions = open opendir read readline readdir close closedir

Nous avons défini quelques raccourcis pour créer cette liste :

[InputOutput::RequireCheckedSyscalls]
functions = :defaults opendir readdir closedir
[InputOutput::RequireCheckedSyscalls]
functions = :builtins
[InputOutput::RequireCheckedSyscalls]
functions = :all

Le raccourci ":builtins" ci-dessus représente toutes les fonctions natives qui ont des conditions d'erreur (environ 65 d'entre elles, dont beaucoup sont plutôt obscures).

Vous pouvez exiger la vérification de toutes les fonctions natives, sauf "print", en combinant "functions" et "exclude_functions" :

[InputOutput::RequireCheckedSyscalls]
functions = :builtins
exclude_functions = print

C'est beaucoup plus facile à lire que l'alternative.

Le ":all" est le cas insensé : vous devez vérifier la valeur de retour de CHAQUE appel de fonction, même "return" et "exit". Oui, cette « fonctionnalité » est exagérée et gaspille des cycles CPU sur votre ordinateur simplement en existant. Nyah nyah. Je ne devrais pas coder après minuit.

Si vous créez un module qui exporte "autodie", vous pouvez en informer cette politique avec le paramètre "autodie_modules" :

[InputOutput::RequireCheckedSyscalls]
autodie_modules = My::Thing
