Perl::Critic::Policy::Variables::ProhibitPackageVars(3pm) Documentation Perl fournie par l'utilisateur Perl::Critic::Policy::Variables::ProhibitPackageVars(3pm)

NOM

Perl::Critic::Policy::Variables::ProhibitPackageVars - Éliminer les variables globales déclarées avec "our" ou "use vars".

AFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Conway suggère d'éviter complètement les variables de package, car elles exposent vos éléments internes à d'autres packages. N'utilisez jamais une variable de package lorsqu'une variable lexicale suffira. Si votre package doit conserver un état dynamique, envisagez d'utiliser un objet ou des closures pour garder l'état privé.

Cette politique suppose que vous utilisez "strict vars" afin que les déclarations de variables nues ne soient pas des variables de package par défaut. Par conséquent, elle se plaint si vous déclarez une variable avec "our" ou "use vars", ou si vous faites référence à une variable avec un nom de package entièrement qualifié.

$Some::Package::foo = 1;    # pas ok
our $foo            = 1;    # pas ok
use vars '$foo';            # pas ok
$foo = 1;                   # non autorisé par 'strict'
local $foo = 1;             # mauvais goût, mais techniquement ok.
use vars '$FOO';            # ok, car c'est TOUT EN MAJUSCULES
my $foo = 1;                # ok

En pratique cependant, il n'est pas vraiment possible d'interdire toutes les variables de package. Les variables courantes comme $VERSION et @EXPORT sont nécessaires pour être globales, tout comme les variables que vous souhaitez exporter. Pour contourner cela, la politique ignore toutes les variables qui sont TOUT EN MAJUSCULES. Cela vous oblige à mettre toutes vos variables exportées en majuscules aussi, ce qui semble être la pratique habituelle de toute façon.

CONFIGURATION

Il y a place pour des exceptions. Certains modules, comme le module de base File::Find, utilisent les variables de package comme seule interface, et d'autres comme Data::Dumper utilisent les variables de package comme leur interface la plus courante. Ces modules peuvent être spécifiés à partir de votre fichier .perlcriticrc, et la politique les ignorera.

[Variables::ProhibitPackageVars]
packages = Data::Dumper File::Find FindBin Log::Log4perl

C'est le réglage par défaut. L'utilisation de "packages =" remplacera ces valeurs par défaut.

Vous pouvez également ajouter des packages aux valeurs par défaut comme ceci :

[Variables::ProhibitPackageVars]
add_packages = My::Package

Vous pouvez ajouter le package "main" à la liste des packages, mais cela n'autorisera que les variables explicitement dans le package "main".
