Perl::Critic::Policy::Variables::ProhibitPunctuationVars(3pm) Documentation Perl fournie par les contributeurs Perl::Critic::Policy::Variables::ProhibitPunctuationVars(3pm)

NOM

Perl::Critic::Policy::Variables::ProhibitPunctuationVars - Écrire "$EVAL_ERROR" au lieu de "$@".

AFFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Le vocabulaire de Perl composé de variables de ponctuation telles que $!, $., et $^ est peut-être la principale cause de sa réputation en tant que bruit de ligne impénétrable. L'alternative simple est d'utiliser le module English pour leur donner des noms clairs.

$| = undef;                      #pas ok
use English qw(-no_match_vars);
local $OUTPUT_AUTOFLUSH = undef; #ok

CONFIGURATION

Les variables temporaires $_ et @_ sont très courantes et bien comprises, elles sont donc exemptées de cette politique. Il en va de même pour le descripteur de fichier par défaut moins fréquemment utilisé "_" utilisé par stat(). Toutes les variables de capture d'expressions régulières ($1, $2, ...) sont également exemptées. $] est exempté car il n'a pas d'équivalent en anglais et Module::CoreList est basé dessus.

Vous pouvez ajouter d'autres exceptions à votre configuration. Dans votre fichier perlcriticrc, ajoutez un bloc comme celui-ci :

[Variables::ProhibitPunctuationVars]
allow = $@ $!

La propriété "allow" doit être une liste de variables de ponctuation séparées par des espaces.

D'autres options de configuration contrôlent l'analyse des chaînes interpolées dans la recherche de variables interdites. Elles n'ont aucun effet sur la détection des variables de ponctuation en dehors des chaînes interpolées.

[Variables::ProhibitPunctuationVars]
string_mode = thorough

L'option "string_mode" contrôle si et comment les chaînes interpolées sont analysées à la recherche de variables de ponctuation. En réglant "string_mode = thorough", la valeur par défaut, on vérifie les cas spéciaux qui peuvent ressembler à des variables de ponctuation mais ne le sont pas, par exemple $#foo, un indice de tableau ; $$bar, une déréférenciation scalaire ; ou $::baz, un symbole global.

En réglant "string_mode = disable", toutes les chaînes interpolées sont ignorées entièrement.

En réglant "string_mode = simple", on utilise une expression régulière simple pour trouver les correspondances. Dans ce mode, les variables magiques $$, "$'", $# et $: sont ignorées dans les chaînes interpolées en raison du risque élevé de faux positifs. Le mode simple est conservé à partir d'une version antérieure du code des chaînes interpolées. Son utilisation n'est recommandée que comme solution de contournement si des bogues apparaissent en mode thorough.

L'option "string_mode" disparaîtra lorsque l'analyse des chaînes interpolées sera implémentée dans PPI. Voir "CAVEATS" ci-dessous.

BOGUES

Les variables de ponctuation qui confondent l'analyse du document de PPI peuvent ne pas être détectées correctement ou pas du tout, et peuvent empêcher la détection des suivantes. En particulier, $" est connue pour causer des difficultés dans les chaînes interpolées.

CAVEATS

ProhibitPunctuationVars s'appuie exclusivement sur PPI pour trouver les variables de ponctuation dans le code, mais effectue toute l'analyse elle-même pour les chaînes interpolées. Lorsque, à un moment donné, cette fonctionnalité sera transférée à PPI, ProhibitPunctuationVars cessera d'effectuer l'interpolation et l'option "string_mode" disparaîtra.
