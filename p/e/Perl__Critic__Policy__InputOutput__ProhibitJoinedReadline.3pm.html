Perl::Critic::Policy::InputOutput::ProhibitJoinedReadline(3pm) Documentation Perl fournie par l'utilisateur Perl::Critic::Policy::InputOutput::ProhibitJoinedReadline(3pm)

NOM

Perl::Critic::Policy::InputOutput::ProhibitJoinedReadline - Utiliser "local $/ = undef" ou Path::Tiny au lieu de readline joint.

AFFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Il est très facile d'absorber tout un fichier à la fois avec "join q{}, <$fh">, mais c'est inefficace -- Perl se donne la peine de diviser le fichier en lignes pour que ce travail soit jeté.

Pour économiser des performances, absorbez le fichier sans le diviser ainsi :

do { local $/ = undef; <$fh> }

ou utilisez Path::Tiny, qui est encore plus rapide.

Note : si la politique "ProhibitPunctuationVars" est également en vigueur, elle se plaindra de l'utilisation de $/ dans la ligne ci-dessus. Dans ce cas, écrivez ceci à la place :

use English '-no_match_vars';
do { local $INPUT_RECORD_SEPARATOR = undef; <$fh> };

CONFIGURATION

Cette politique n'est pas configurable, à l'exception des options standard.

CAVEATS

En raison d'un bug dans la version actuelle de PPI (v1.119_03) et antérieures, l'opérateur readline est souvent mal interprété comme les opérateurs inférieur et supérieur après une virgule. Par conséquent, cette politique ne fonctionne bien qu'avec le descripteur de fichier vide, "<>". Lorsque PPI sera corrigé, cela commencera à fonctionner.
