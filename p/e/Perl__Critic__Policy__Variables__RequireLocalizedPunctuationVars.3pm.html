Perl::Critic::Policy::Variables::RequireLocalizedPunctuationVars(3pm) Documentation Perl fournie par l'utilisateur Perl::Critic::Policy::Variables::RequireLocalizedPunctuationVars(3pm)

NOM

Perl::Critic::Policy::Variables::RequireLocalizedPunctuationVars - Les variables magiques doivent être assignées avec "local".

AFFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Les variables de ponctuation (et leurs équivalents dans English.pm) sont des variables globales. Jouer avec les globales est dangereux dans un programme complexe car cela peut conduire à des bugs très subtils et difficiles à corriger. Si vous devez changer une variable magique dans un programme non trivial, faites-le dans une portée locale.

Par exemple, pour aspirer un descripteur de fichier dans un scalaire, il est courant de définir le séparateur d'enregistrements sur undef au lieu d'un saut de ligne. Si vous choisissez de faire cela (au lieu d'utiliser Path::Tiny !), assurez-vous de localiser le global et de le changer pour la plus courte durée possible.

# MAUVAIS :
$/ = undef;
my $content = <$fh>;
# MIEUX :
my $content;
{
    local $/ = undef;
    $content = <$fh>;
}
# Un idiome populaire :
my $content = do { local $/ = undef; <$fh> };

Cette politique autorise également l'utilisation de "my". Perl empêche l'utilisation de "my" avec les variables de ponctuation "correctes", mais autorise $a, @ARGV, les noms déclarés par English, etc. Ce n'est cependant pas une bonne pratique de codage, et ce n'est pas le but de cette politique spécifique de s'en plaindre.

Il existe des exemptions pour $_ et @_, ainsi que pour l'équivalent anglais $ARG.

CONFIGURATION

Vous pouvez configurer vos propres exemptions en utilisant l'option "allow" :

[Variables::RequireLocalizedPunctuationVars]
allow = @ARGV $ARGV

Ces variables sont ajoutées aux exemptions par défaut.
