Perl::Critic::Policy::RegularExpressions::ProhibitEscapedMetacharacters(3pm) Documentation Perl fournie par l'utilisateur Perl::Critic::Policy::RegularExpressions::ProhibitEscapedMetacharacters(3pm)

NOM

Perl::Critic::Policy::RegularExpressions::ProhibitEscapedMetacharacters - Utiliser des classes de caractères pour les métacaractères littéraux au lieu des échappements.

AFFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Avez-vous déjà entendu parler du syndrome du cure-dent penché ? Cela provient de l'écriture d'expressions régulières qui correspondent à des caractères significatifs dans les expressions régulières. Par exemple, l'expression pour faire correspondre quatre barres obliques ressemble à ceci :

m/\/\/\/\//;

Eh bien, cette politique ne résout pas ce problème (écrivez-la plutôt comme "m{////}" !) mais résout un problème connexe. Comme vu ci-dessus, les échappements rendent l'expression difficile à analyser visuellement. Une solution consiste à utiliser des classes de caractères. Vous voyez, à l'intérieur des classes de caractères, les seuls caractères spéciaux sont "\", "]", "^" et "-", donc vous n'avez pas besoin d'échapper les autres. Donc, au lieu du comparateur d'adresses IPv4 lâche suivant :

m/ \d+ \. \d+ \. \d+ \. \d+ /x;

Vous pourriez écrire :

m/ \d+ [.] \d+ [.] \d+ [.] \d+ /x;

ce qui est certainement plus lisible, bien que moins reconnaissable avant la publication des Perl Best Practices. (Bien sûr, vous devriez vraiment utiliser Regexp::Common::net pour faire correspondre les adresses IPv4 !)

Plus précisément, cette politique interdit les barres obliques inverses immédiatement avant les caractères suivants :

{ } ( ) . * + ? | #

Nous faisons une exception spéciale pour "$" car "/[$]/" se transforme en "/[5.008006/" pour Perl 5.8.6. Nous faisons également une exception pour "^" car il a une signification spéciale (négation) dans une classe de caractères. Enfin, "[" et "]" sont exemptés, bien sûr, car ils sont difficiles à représenter dans les classes de caractères.

Notez que cette politique n'interdit pas les échappements inutiles. Alors, allez-y et (sans but) échappez les caractères "!".

CONFIGURATION

Cette politique n'est configurable qu'avec les options standard.

BOGUES

Perl traite "m/[#]/x" de manière inattendue. Je pense que c'est un bogue dans Perl lui-même, mais je ne suis pas sûr à 100% de ne pas avoir simplement mal compris...

Cette partie a du sens :

"#f" =~ m/[#]f/x;     # correspondance
"#f" =~ m/[#]a/x;     # pas de correspondance

Celle-ci n'a pas de sens :

$qr  = qr/f/;
"#f" =~ m/[#]$qr/x; # pas de correspondance

Ni celle-ci :

print qr/[#]$qr/x;  # produit '(?x-ism:[#]$qr
                            )'
