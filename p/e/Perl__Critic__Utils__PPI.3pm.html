Perl::Critic::Utils::PPI(3pm) Documentation contributive de Perl Perl::Critic::Utils::PPI(3pm)

Nom

Perl::Critic::Utils::PPI - Fonctions utilitaires pour travailler avec des objets PPI.

Description

Fournit une classification des objets PPI::Elements.

Support de l'interface

Ceci est considéré comme une librairie publique. Tout changement dans son interface suivra un cycle de désuétude.

Sous-programmes importables

is_ppi_expression_or_generic_statement( $element )
Renvoie si le paramètre est une expression ou une instruction générique. Autrement dit, le paramètre est un PPI::Statement::Expression ou la classe du paramètre est PPI::Statement et ce n'est pas une de ses sous-classes sauf "Expression".
is_ppi_generic_statement( $element )
Renvoie si le paramètre est une instruction générique, c'est-à-dire que le paramètre est un PPI::Statement mais pas une de ses sous-classes.
is_ppi_statement_subclass( $element )
Renvoie si le paramètre est une instruction spéciale, c'est-à-dire que le paramètre est un PPI::Statement mais que la classe du paramètre n'est pas PPI::Statement.
is_ppi_simple_statement( $element )
Renvoie si le paramètre représente une instruction simple, c'est-à-dire si le paramètre est un PPI::Statement, PPI::Statement::Break, PPI::Statement::Include, PPI::Statement::Null, PPI::Statement::Package ou PPI::Statement::Variable.
is_ppi_constant_element( $element )
Renvoie si le paramètre représente une valeur constante, c'est-à-dire si le paramètre est un PPI::Token::Number, PPI::Token::Quote::Literal, PPI::Token::Quote::Single, ou PPI::Token::QuoteLike::Words, ou est un PPI::Token::Quote::Double ou PPI::Token::Quote::Interpolate qui ne contient pas de variables interpolées.

Ce sous-programme n'interprète aucune forme de here document comme une valeur constante, et pourrait ne pas le faire tant que PPI::Token::HereDoc n'aura pas acquis les parties pertinentes de l'interface de PPI::Token::Quote.

Ce sous-programme n'interprète pas non plus les entités créées par le module Readonly ou le pragma const, étant donné que l'infrastructure permettant de détecter ceux-ci semble absente, et que l'auteur de ce sous-programme (pas M. Shank ni M. Thalhammer) manque de connaissances/expertise/goût pour les implémenter.

is_subroutine_declaration( $element )
Le paramètre est-il une déclaration de sous-routine, nommée ou non ?
is_in_subroutine( $element )
Le paramètre est-il une sous-routine ou se trouve-t-il à l'intérieur d'une ?
get_constant_name_element_from_declaring_statement($statement)
Ce sous-programme est obsolète. Vous devriez utiliser "get_constant_name_elements_from_declaring_statement()" dans PPIx::Utils::Traversal.

Étant donné un PPI::Statement, si l'état est une utilisation de "constant" ou une déclaration Readonly, renvoie le nom de l'élément défini.

Étant donné

use constant 1.16 FOO => 'bar';

renverra "FOO". De même, étant donné

Readonly::Hash my %FOO => ( bar => 'baz' );

renverra "%FOO".

Remarque : Dans le cas de constantes multiples déclarées en utilisant le même "use constant" (exemple : "use constant { FOO => 1, BAR => 2 };"), ce sous-programme renverra un PPI::Structure::Constructor. Dans le cas de "use constant 1.16 { FOO => 1, BAR => 2 };", il peut renvoyer un PPI::Structure::Block au lieu d'un PPI::Structure::Constructor en raison d'un bug d'analyse dans PPI.

get_next_element_in_same_simple_statement( $element )
Renvoie l'élément suivant dans la même instruction simple telle que définie par is_ppi_simple_statement(). S'il n'y a pas d'élément suivant, renvoie undef.

Si le $element est indéfini ou n'est pas béni, renvoie simplement undef.

Si le $element satisfait is_ppi_simple_statement(), renvoie undef, sauf s'il a un parent qui est une PPI::Structure::List.

Si le $element est le dernier élément significatif de son PPI::Node, il remplace cela par son parent et ré-itère.

Sinon, renvoie "$element->snext_sibling()".

get_previous_module_used_on_same_line( $element )
Renvoie l'élément PPI::Element qui représente le nom du module inclus par le précédent "use" ou "require" sur la même ligne que le $element. S'il n'en trouve pas, renvoie undef.

Par exemple, avec la ligne

use version; our $VERSION = ...;

étant donné l'instance PPI::Token::Symbol pour $VERSION, renvoie "version".

Si l'élément donné se trouve à l'intérieur d'un "use" ou "require", renvoie le "use" ou "require" précédent sur la même ligne, s'il existe.
