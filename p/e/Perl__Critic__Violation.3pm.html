Perl::Critic::Violation(3pm) Documentation Perl fournie par l'utilisateur Perl::Critic::Violation(3pm)

NOM

Perl::Critic::Violation - Une violation d'une politique trouvée dans du code source.

SYNOPSIS

use PPI;
use Perl::Critic::Violation;
my $elem = $doc->child(0);      # $doc est un objet PPI::Document
my $desc = 'Code fautif';     # Décrit la violation
my $expl = [1,45,67];          # Numéros de page de PBP
my $sev  = 5;                  # Niveau de sévérité de cette violation
my $vio  = Perl::Critic::Violation->new($desc, $expl, $node, $sev);

DESCRIPTION

Perl::Critic::Violation est la représentation générique d'une violation de politique individuelle. Son objectif principal est de fournir une couche d'abstraction afin que les clients de Perl::Critic n'aient pas à connaître PPI. La méthode "violations" de toutes les sous-classes de Perl::Critic::Policy doit retourner une liste de ces objets Perl::Critic::Violation.

SUPPORT D'INTERFACE

Ceci est considéré comme une classe publique. Tout changement de son interface fera l'objet d'un cycle de dépréciation.

CONSTRUCTEUR

"new( $description, $explanation, $element, $severity )"
Retourne une référence vers un nouvel objet "Perl::Critic::Violation". Les arguments sont une description de la violation (sous forme de chaîne de caractères), une explication de la politique (sous forme de chaîne de caractères) ou une série de numéros de page dans PBP (sous forme de référence de tableau), une référence vers l'élément PPI qui a causé la violation, et la sévérité de la violation (sous forme d'entier).

MÉTHODES

description()
Retourne une brève description de la violation spécifique. En d'autres termes, cette valeur peut changer pour chaque violation.
explanation()
Retourne une explication de la politique sous forme de chaîne de caractères ou de référence à un tableau de numéros de page dans PBP. Cette valeur ne changera généralement pas en fonction du code spécifique qui viole la politique.
location()
N'utilisez pas cette méthode. Utilisez plutôt les méthodes line_number(), logical_line_number(), column_number(), visual_column_number() et logical_filename().

Retourne une référence de tableau à cinq éléments contenant le numéro de ligne et les numéros de colonne réels et virtuels, ainsi que le numéro logique et le nom de fichier logique où cette Violation s'est produite, comme dans PPI::Element.

line_number()
Retourne le numéro de ligne physique où la violation a été trouvée.
logical_line_number()
Retourne le numéro de ligne logique où la violation a été trouvée. Cela peut différer du numéro de ligne physique lorsqu'il y avait des directives "#line" dans le code.
column_number()
Retourne la colonne physique où la violation a été trouvée. Cela signifie que les caractères de tabulation comptent comme un seul caractère.
visual_column_number()
Retourne la colonne où la violation a été trouvée, telle qu'elle apparaîtrait si les caractères de tabulation étaient étendus, en fonction de la valeur de "tab_width [ $width ]" dans PPI::Document.
filename()
Retourne le chemin du fichier où cette Violation s'est produite. Dans certains cas, le chemin peut être indéfini car le code source n'a pas été lu directement depuis un fichier.
logical_filename()
Retourne le chemin logique du fichier où la Violation s'est produite. Cela peut différer de filename() lorsqu'il y avait une directive "#line" dans le code.
severity()
Retourne la sévérité de cette Violation sous forme d'entier allant de 1 à 5, où 5 est le plus sévère.
sort_by_severity( @violation_objects )
Si vous devez trier les Violations par sévérité, utilisez cette routine pratique : 
@sorted = Perl::Critic::Violation::sort_by_severity(@violations);
sort_by_location( @violation_objects )
Si vous devez trier les Violations par emplacement, utilisez cette routine pratique : 
@sorted = Perl::Critic::Violation::sort_by_location(@violations);
diagnostics()
Retourne une chaîne formatée contenant une discussion complète sur la motivation et les détails du module de politique qui a créé cette Violation. Ces informations sont automatiquement extraites de la section "DESCRIPTION" du POD du module de politique.
policy()
Retourne le nom de la politique Perl::Critic::Policy qui a créé cette Violation.
source()
Retourne la chaîne de code source qui a causé cette exception. Si le code s'étend sur plusieurs lignes (par exemple, des instructions sur plusieurs lignes, des sous-routines ou d'autres blocs), seule la ligne contenant la violation sera retournée.
element_class()
Retourne la sous-classe PPI::Element du code qui a causé cette exception.
set_format( $format )
Méthode de classe. Définit le format pour tous les objets Violation lorsqu'ils sont évalués dans un contexte de chaîne. Le format par défaut est '%d à la ligne %l, colonne %c. %e'. Voir "Surchargeurs" pour les options de formatage.
get_format()
Méthode de classe. Retourne le format actuel pour tous les objets Violation lorsqu'ils sont évalués dans un contexte de chaîne.
to_string()
Retourne une représentation sous forme de chaîne de caractères de cette violation. Le contenu de la chaîne dépend de la valeur actuelle de la variable du package $format. Voir "Surchargeurs" pour les détails.

SURCHARGEURS

Perl::Critic::Violation surcharge l'opérateur "" pour produire des messages concis lorsqu'il est évalué dans un contexte de chaîne.

Les formats sont une combinaison de littéraux et de caractères d'échappement similaires à la façon dont fonctionne "sprintf". Si vous souhaitez connaître les capacités de formatage spécifiques, regardez String::Format. Les caractères d'échappement valides sont :

Echappement    Signification
-----------   ----------------------------------------------------------------
%c            Numéro de colonne où la violation s'est produite
%d            Discussion diagnostique complète de la violation (DESCRIPTION dans le POD)
%e            Explication de la violation ou numéros de page dans PBP
%F            Juste le nom du fichier logique où la violation s'est produite.
%f            Chemin du fichier logique où la violation s'est produite.
%G            Juste le nom du fichier physique où la violation s'est produite.
%g            Chemin du fichier physique où la violation s'est produite.
%l            Numéro de ligne logique où la violation s'est produite
%L            Numéro de ligne physique où la violation s'est produite
%m            Brève description de la violation
%P            Nom complet du module de politique qui a créé la violation
%p            Nom de la politique sans le préfixe Perl::Critic::Policy::
%r            La chaîne de code source qui a causé la violation
%C            La classe de l'élément PPI qui a causé la violation
%s            Le niveau de sévérité de la violation

Perl::Critic::Violation — Perl criticism framework

NAME

Perl::Critic::Violation - A single violation discovered by Perl::Critic

SYNOPSIS

 use Perl::Critic;
 my $critic = Perl::Critic->new();
 my @violations = $critic->critique_string($code);
 foreach my $violation (@violations) {
  print $violation->formatted();
 }

DESCRIPTION

This module represents a single violation discovered by Perl::Critic. It stores the violation message, the policy that found the violation, the source file, the line number, the column number, the original line of code, and a more detailed explanation.

You will typically never need to construct a Perl::Critic::Violation object yourself. They are created by the Perl::Critic object and returned by the critique() and critique_string() methods.

INTERFACE SUPPORT

This module is part of the Perl::Critic system and is only intended for use by that system. It is not intended for use by end-users of Perl::Critic.

CONSTRUCTOR

There is no public constructor for Perl::Critic::Violation objects. They are created by Perl::Critic objects.

METHODS

The following methods are available:

column()
Returns the column number (character offset) of the violation. Returns undef if the violation is not associated with a specific column.
description()
Returns the detailed explanation of the violation. This is typically the text from the policy's POD. Returns undef if there is no description.
file()
Returns the name of the file in which the violation was found. Returns undef if the violation was found in a string, not a file.
formatted()
Returns a string representing the violation in the format specified by Perl::Critic::Violation::set_format().

See also "Plain Old Comments (Not!)" in perlsyn for the details. Under normal circumstances, the values of %F, %f, and %l will match the values of %G, %g, and %L, respectively. In the presence of a "#line" directive, the values of %F, %f, and %l will change to take that directive into account. The values of %G, %g, and %L are unaffected by those directives.

Here are some examples:

Perl::Critic::Violation::set_format("%m at line %l, column %c.\n");
        # looks like "Mixed case variable name at line 6, column 23."
        Perl::Critic::Violation::set_format("%m near '%r'\n");
        # looks like "Mixed case variable name near 'my $theGreatAnswer = 42;'"
        Perl::Critic::Violation::set_format("%l:%c:%p\n");
        # looks like "6:23:NamingConventions::Capitalization"
        Perl::Critic::Violation::set_format("%m at line %l. %e. \n%d\n");
        # looks like "Mixed case variable name at line 6.  See page 44 of PBP.
          Conway's recommended naming convention is to use lower-case words
          separated by underscores.  Well-recognized acronyms can be in ALL
          CAPS, but must be separated by underscores from other parts of the
          name."
level()
Returns the numeric level of the violation. Policies can be configured to have different levels.
message()
Returns the short, human-readable message of the violation.
policy()
Returns the Perl::Critic::Policy object that generated this violation.
reason()
Returns the same value as message(). Provided for compatibility with other modules.
related_code()
Returns the line of code in which the violation was found. Returns undef if the violation is not associated with a specific line of code.
line()
Returns the line number (1-based) of the violation. Returns undef if the violation is not associated with a specific line number.
source()
Returns the source object that generated this violation. This will be a Perl::Critic::Parse::Source object.

OVERLOADS

The following operators are overloaded:

eq
Compares two violations for equality. Returns true if the messages, file, line, and column are all the same.
lt
Compares two violations for ordering. The violations are ordered first by file, then by line number, then by column number, then by message, and finally by policy name.
fallback
Stringifies the violation using the formatted() method.
