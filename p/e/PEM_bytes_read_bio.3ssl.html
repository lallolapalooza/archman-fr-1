PEM_bytes_read_bio(3ssl)

Paquet: openssl

Licences: Apache-2.0

PEM_bytes_read_bio(3ssl) OpenSSL PEM_bytes_read_bio(3ssl)

NOM

PEM_bytes_read_bio, PEM_bytes_read_bio_secmem - lire des données au format PEM à partir d'un BIO

SYNTAXE

#include <openssl/pem.h>
int PEM_bytes_read_bio(unsigned char **pdata, long *plen, char **pnm,
                       const char *name, BIO *bp, pem_password_cb *cb,
                       void *u);
int PEM_bytes_read_bio_secmem(unsigned char **pdata, long *plen, char **pnm,
                              const char *name, BIO *bp, pem_password_cb *cb,
                              void *u);

DESCRIPTION

PEM_bytes_read_bio() lit des données au format PEM (IETF RFC 1421 et IETF RFC 7468) depuis le BIO bp pour le type de données spécifié par name (RSA PRIVATE KEY, CERTIFICATE, etc.). S'il y a plusieurs structures de données encodées en PEM dans le même flux, PEM_bytes_read_bio() ignorera les types de données non correspondants et continuera la lecture. Des données non-PEM présentes dans le flux peuvent causer une erreur.

L'en-tête PEM peut indiquer que les données suivantes sont chiffrées ; si c'est le cas, les données seront déchiffrées, attendant une saisie utilisateur pour fournir la phrase de passe si nécessaire. Le rappel de mot de passe cb et le pointeur u sont utilisés pour obtenir la phrase de passe de déchiffrement, le cas échéant.

Certains types de données ont des alias de compatibilité, comme un fichier contenant un CERTIFICATE X509 correspondant à une demande pour le type déprécié CERTIFICATE. Le type réel indiqué par le fichier est retourné dans *pnm si pnm n'est pas NULL. L'appelant doit libérer la mémoire pointée par *pnm.

Les données retournées sont la forme encodée DER du type demandé, dans *pdata avec la longueur *plen. L'appelant doit libérer la mémoire pointée par *pdata.

PEM_bytes_read_bio_secmem() est similaire à PEM_bytes_read_bio(), mais utilise la mémoire du tas sécurisé pour ses tampons temporaires et le stockage retourné dans *pdata et *pnm. Par conséquent, l'appelant doit utiliser OPENSSL_secure_free() pour libérer ce stockage.

NOTES

PEM_bytes_read_bio_secmem() garantit uniquement que le tas sécurisé est utilisé pour le stockage alloué au sein de la pile de traitement PEM. La pile BIO à partir de laquelle les entrées sont lues peut également utiliser des tampons temporaires, qui ne sont pas nécessairement alloués à partir du tas sécurisé. Dans les cas où il est souhaitable de s'assurer que le contenu du fichier PEM n'apparaît que dans la mémoire du tas sécurisé, des précautions sont nécessaires lors de la génération du BIO passé en tant que bp. En particulier, l'utilisation de BIO_s_file() indique l'utilisation des fonctionnalités de mise en mémoire tampon de l'E/S standard du système d'exploitation ; BIO_s_fd() sera probablement plus approprié dans de tels cas.

Ces fonctions ne font aucune supposition concernant la phrase de passe reçue du rappel de mot de passe. Elle sera simplement traitée comme une séquence d'octets.

VALEUR DE RETOUR

PEM_bytes_read_bio() et PEM_bytes_read_bio_secmem() retournent 1 en cas de succès ou 0 en cas d'échec.

VOIR AUSSI

HISTORIQUE
