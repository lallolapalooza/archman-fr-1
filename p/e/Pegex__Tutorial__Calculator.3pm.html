Pegex Tutoriel Calculatrice

Une calculatrice Pegex

Lorsque vous cherchez des informations sur l'analyse syntaxique sur le web, vous trouvez inévitablement de nombreux exemples sur la façon d'écrire un analyseur de précédence pour les expressions mathématiques.

  • http://en.wikipedia.org/wiki/Operator-precedence_parser
  • http://eli.thegreenplace.net/2010/01/02/top-down-operator-precedence-parsing/
  • http://www.hokstad.com/operator-precedence-parser.html
  • http://www.perlmonks.org/?node_id=554516

Ce tutoriel est la version Pegex de cela. Pegex est livré avec un répertoire d'exemples qui contient deux programmes de calculatrice d'analyse/évaluation d'expressions arithmétiques :

  • https://github.com/ingydotnet/pegex-pm/blob/master/eg/calculator/calculator1.pl
  • https://github.com/ingydotnet/pegex-pm/blob/master/eg/calculator/calculator2.pl

Ils font tous deux la même chose mais en utilisant différentes approches d'analyse. Nous allons les couvrir en détail. J'espère que vous trouverez que Pegex gère élégamment l'analyse de précédence des opérateurs.

Le Problème

Les analyseurs de précédence sont intéressants car vous devez gérer des opérateurs qui ont la même précédence, des précédences différentes et une associativité aussi bien à gauche qu'à droite.

Considérez l'équation :

1 - 2 ^ 3 ^ 4 + 5 * 6 / 7

Les règles normales de précédence et d'associativité la rendent identique à :

(1 - (2 ^ (3 ^ 4)) + ((5 * 6) / 7))

Notre calculatrice devrait produire le même résultat pour les deux. Notez que cela signifie que nous allons analyser des nombres, 5 opérateurs, des parenthèses et séparer les espaces.

Voici un exemple du programme de calculatrice en cours d'exécution :

> perl eg/calculator1.pl
Entrez une équation : 1+2*3
1+2*3 = 7
Entrez une équation : (1 + 2) * 3
(1 + 2) * 3 = 9

Les Solutions

La plupart des solutions que vous lirez sur le web impliquent (ou supposent) une étape de lexing/tokenisation avant l'analyse. Pegex analyse toujours un flux d'entrée directement, en extrayant les « jetons » dont il a besoin à l'aide de captures regex. L'analyse se déroule donc en une seule opération, ce qui présente de nombreux avantages.

Mais comment y intégrer les règles de précédence des opérateurs ? Eh bien, nous avons 2 manières différentes :

calculator1.pl - Ascension de précédence des opérateurs

Remarque : Le code de cet exemple est copié/collé depuis « calculator/ » dans les fichiers d'exemple. Le code de ces fichiers en cours d'exécution est légèrement différent mais réécrit pour avoir plus de sens dans ce document.

Notre premier exemple de calculatrice utilise ce que l'on appelle la méthode d'Ascension de Précédence des Opérateurs (Operator Precedence Climbing - OPCM). Voir : http://en.wikipedia.org/wiki/Operator-precedence_parser#Precedence_climbing_method.

C'est essentiellement une technique astucieuse pour spécifier nos règles de grammaire de telle sorte qu'elles impliquent la précédence. Voici la grammaire pegex du code :

expr: add-sub
add-sub: mul-div+ % /- ( [ '+-' ])/
mul-div: power+ % /- ([ '*/' ])/
power: token+ % /- '^' /
token: /- '(' -/ expr /- ')'/ | number
number: /- ( '-'? DIGIT+ )/

C'est un peu bancal mais ça marche. Cela dit que toute expression est une addition/soustraction et qu'une addition/soustraction est en fait une multiplication/division, etc. Finalement, après le dernier opérateur vient le jeton nombre et les parenthèses.

Cela semble un peu à l'envers. L'un des plus grands inconvénients de l'OPCM est qu'il devient de moins en moins efficace avec de plus en plus d'opérateurs. Il doit parcourir tout l'arbre, juste pour trouver chaque nombre.

Mais ça marche et le code est minimal. La classe réceptrice obtient les nombres dans le bon ordre, évalue immédiatement la réponse et renvoie la réponse pour chaque niveau. Quelle que soit la valeur de retour de l'opération finale, elle devient le résultat de l'analyse. Voici la classe réceptrice :

{
    package Calculator;
    use base 'Pegex::Tree';
    sub gotrule {
        my ($self, $list) = @_;
        return $list unless ref $list;
        # Associativité droite :
        if ($self->rule eq 'power') {
            while (@$list > 1) {
                my ($a, $b) = splice(@$list, -2, 2);
                push @$list, $a ** $b;
            }
        }
        # Associativité gauche :
        else {
            while (@$list > 1) {
                my ($a, $op, $b) = splice(@$list, 0, 3);
                unshift @$list,
                    ($op eq '+') ? ($a + $b) :
                    ($op eq '-') ? ($a - $b) :
                    ($op eq '*') ? ($a * $b) :
                    ($op eq '/') ? ($a / $b) :
                    die;
            }
        }
        return @$list;
    }
}

Comme vous pouvez le voir, elle a une méthode d'action pour chaque niveau de précédence. Elle parcourt l'expression, l'évaluant. Qu'elle parcourt de gauche à droite ou de droite à gauche dépend de l'associativité que nous voulons utiliser.

Notre code d'exécution ressemble à ceci :

while (1) {
    print "\nEntrez une équation : ";
    my $expr = <> || '';
    chomp $expr;
    last unless length $expr;
    calc($expr);
}
sub calc {
    my ($expr) = @_;
    my $result = pegex($grammar, 'Calculator')->parse($expr);
    if ($@) {
        warn $@;
        return;
    }
    print "$expr = $result\n";
}

Et c'est tout. Nous avons une calculatrice fonctionnelle comme spécifié !

Cependant, le véritable objectif est d'explorer de bonnes techniques d'analyse, et l'OPCM nous laisse désireux d'essayer quelque chose de plus efficace. Essayons une autre approche...

calculator2.pl - Algorithme Shunting-Yard

Une vieille méthode pour analyser les expressions consiste à obtenir d'une manière ou d'une autre les nombres et les opérateurs dans une pile RPN (Notation Polonaise Inverse), où chaque opérande est suivi de son opérateur. Une fois sous cette forme, la précédence et l'associativité sont prises en compte.

Par exemple :

1 / 2 - ( -3 * 4 )

devient :

1, 2, /, -3, 4, *, -

Pour évaluer une RPN, vous retirez un opérateur, puis vous essayez de retirer un opérande. Si l'opérande est un autre opérateur, vous récursez. Lorsque vous avez 2 opérandes, vous effectuez l'opération et remettez le résultat sur la pile. Lorsqu'il ne reste qu'un seul élément sur la pile, vous avez terminé. C'est votre résultat.

Regardons notre nouvelle grammaire dans "calculator2.pl" :

expr: operand (operator operand)*
operator: /- (['+-*/^'])/
operand: num | /- '('/ expr /- ')'/
num: /- ('-'? DIGIT+)/

C'est beaucoup plus facile à comprendre. Nous extrayons simplement les jetons. Dans un sens (très réel), nous utilisons Pegex comme analyseur lexical.

Regardons maintenant la classe réceptrice :

{
    package Calculator;
    use base 'Pegex::Tree', 'Precedence';
    my $operator_precedence_table = {
        '+' => {p => 1, a => 'l'},
        '-' => {p => 1, a => 'l'},
        '*' => {p => 2, a => 'l'},
        '/' => {p => 2, a => 'l'},
        '^' => {p => 3, a => 'r'},
    };
    sub got_expr {
        my ($self, $expr) = @_;
        $self->precedence_rpn($expr, $operator_precedence_table);
    }
}

C'est aussi beaucoup plus simple. Il n'y a qu'une seule méthode. Que se passe-t-il ? Eh bien, le secret est que j'ai mis le code pour transformer les jetons en RPN dans une classe de base séparée appelée « lib/Precedence.pm » dans l'exemple.

Il s'agit d'une implémentation du célèbre algorithme Shunting-yard d'Edsger Dijkstra datant de 1961 ! Il ne fait que 20 lignes de Perl. Je ne l'inclurai pas ici, mais jetez-y un œil par vous-même. https://github.com/ingydotnet/pegex-pm/blob/master/eg/calculator/lib/Precedence.pm

L'algorithme Shunting-yard prend simplement une liste de jetons d'expression et les transforme en une pile RPN. Il utilise des informations provenant d'une table de précédence/associativité comme celle ci-dessus.

Mais nous écrivons une calculatrice et nous devons encore évaluer ce petit programme. J'ai modifié le code du lanceur pour qu'il ressemble à ceci :

sub calc {
    my $expr = shift;
    my $calculator = pegex($grammar, 'Calculator');
    my $rpn = eval { $calculator->parse($expr) };
    my $result = RPN::evaluate($rpn);
    print $@ || "$expr = $result\n";
}

Donc, dans l'ensemble, cette deuxième solution était un peu plus de code, mais elle semble aussi plus solide à plusieurs niveaux.

Conclusion

Pegex s'efforce d'être le moyen le plus agréable et le plus réutilisable d'écrire de nouveaux analyseurs. Les analyseurs de précédence d'opérateurs sont une partie nécessaire de l'analyse des expressions mathématiques et des langages informatiques. Ce tutoriel vous a montré 2 façons de le faire. Au fur et à mesure que les demandes pour Pegex augmentent, nous pourrions voir encore plus de façons de le faire.
