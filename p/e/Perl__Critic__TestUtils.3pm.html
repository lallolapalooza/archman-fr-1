Perl::Critic::TestUtils(3pm) Documentation Perl fournie par l'utilisateur Perl::Critic::TestUtils(3pm)

NOM

Perl::Critic::TestUtils - Fonctions utilitaires pour tester de nouvelles politiques.

PRISE EN CHARGE DE L'INTERFACE

Ceci est considéré comme un module public. Tout changement dans son interface sera soumis à un cycle de dépréciation.

SYNOPSIS

use Perl::Critic::TestUtils qw(critique pcritique fcritique);
my $code = '<<END_CODE';
package Foo::Bar;
$foo = frobulator();
$baz = $foo ** 2;
1;
END_CODE
# Critiquer le code par rapport à toutes les politiques chargées...
my $perl_critic_config = { -severity => 2 };
my $violation_count = critique( \$code, $perl_critic_config);
# Critiquer le code par rapport à une seule politique...
my $custom_policy = 'Miscellanea::ProhibitFrobulation'
my $violation_count = pcritique( $custom_policy, \$code );
# Critiquer le code par rapport à une politique liée au nom de fichier...
my $custom_policy = 'Modules::RequireFilenameMatchesPackage'
my $violation_count = fcritique( $custom_policy, \$code, 'Foo/Bar.pm' );

DESCRIPTION

Ce module est utilisé par Perl::Critic uniquement pour ses tests internes. Il fournit quelques sous-programmes pratiques pour tester de nouveaux modules Perl::Critic::Policy. Regardez les programmes de test fournis avec Perl::Critic pour plus d'exemples sur la façon d'utiliser ces sous-programmes.

EXPORT

assert_version( $version )
Affirme que le $version passé correspond à la version de Perl::Critic.
block_perlcriticrc()
Si un utilisateur possède un fichier ~/.perlcriticrc, cela peut interférer avec les tests. Cette méthode pratique désactive la recherche de ce fichier -- appelez-la simplement en haut de votre programme .t. Notez que ce n'est pas facilement réversible, mais cela ne devrait pas avoir d'importance.
critique_with_violations( $code_string_ref, $config_ref )
Teste un bloc de code par rapport à l'instance Perl::Critic::Config spécifiée (ou "undef" pour la valeur par défaut). Renvoie les violations qui se sont produites.
critique( $code_string_ref, $config_ref )
Teste un bloc de code par rapport à l'instance Perl::Critic::Config spécifiée (ou "undef" pour la valeur par défaut). Renvoie le nombre de violations qui se sont produites.
pcritique_with_violations( $policy_name, $code_string_ref, $config_ref )
Similaire à critique_with_violations(), mais ne teste qu'une seule politique au lieu de toutes.
pcritique( $policy_name, $code_string_ref, $config_ref )
Similaire à critique(), mais ne teste qu'une seule politique au lieu de toutes.
fcritique_with_violations( $policy_name, $code_string_ref, $filename, $config_ref )
Similaire à pcritique_with_violations(), mais fait comme si le code avait été chargé depuis le nom de fichier spécifié. Ceci est utile pour tester des politiques comme "Modules::RequireFilenameMatchesPackage" qui se soucient du nom de fichier à partir duquel la source est dérivée.

Le paramètre $filename doit être un chemin relatif, pas absolu. Le fichier et tous les sous-répertoires nécessaires seront créés via File::Temp et seront automatiquement supprimés.

fcritique( $policy_name, $code_string_ref, $filename, $config_ref )
Similaire à pcritique(), mais fait comme si le code avait été chargé depuis le nom de fichier spécifié. Ceci est utile pour tester des politiques comme "Modules::RequireFilenameMatchesPackage" qui se soucient du nom de fichier à partir duquel la source est dérivée.

Le paramètre $filename doit être un chemin relatif, pas absolu. Le fichier et tous les sous-répertoires nécessaires seront créés via File::Temp et seront automatiquement supprimés.

subtests_in_tree( $dir )
Recherche le répertoire spécifié de manière récursive pour les fichiers .run. Chacun trouvé est analysé et un hash d'une liste d'hashes est renvoyé. Le hash externe est indexé par le nom court de la politique, comme "Modules::RequireEndWithOne". Le hash interne spécifie un seul test à passer à pcritique() ou fcritique(), y compris la chaîne de code, le nom du test, etc. Voir ci-dessous pour la syntaxe des fichiers .run.
should_skip_author_tests()
Indique si les tests d'auteur doivent être exécutés.
get_author_test_skip_message()
Renvoie une chaîne contenant le message qui devrait être émis lorsqu'un test est ignoré parce qu'il s'agit d'un test d'auteur alors que les tests d'auteur ne sont pas activés.
starting_points_including_examples()
Renvoie une liste des répertoires contenant du code qui doit être testé lorsqu'il est souhaité que les exemples soient inclus.
bundled_policy_names()
Renvoie une liste des modules de Politique qui sont fournis avec ce module. Cela fonctionne en recherchant dans MANIFEST les fichiers lib/Perl/Critic/Policy/*.pm et convertit les résultats en noms de modules.
names_of_policies_willing_to_work( %configuration )
Renvoie une liste des modules de politiques qui sont disposés à fonctionner sur le système actuel en utilisant la configuration spécifiée.

Informations sur les fichiers .run

Tester une politique suit un schéma très simple :

* Nom de la politique
    * Nom du sous-test
    * Paramètres optionnels
    * Nombre d'échecs attendus
    * Exception optionnelle attendue
    * Nom de fichier optionnel pour le code

Chacun des sous-tests pour une politique est collecté dans un seul fichier .run, avec les propriétés du test comme commentaires devant chaque bloc de code qui décrit comment nous nous attendons à ce que Perl::Critic réagisse au code. Par exemple, disons que vous avez une politique appelée Variables::ProhibitVowels :

(Dans le fichier t/Variables/ProhibitVowels.run)
## name Basics
## failures 1
## cut
my $vrbl_nm = 'foo';    # Bon nom, sans voyelles
my $wango = 12;         # Mauvais nom, prononçable
## name Sometimes Y
## failures 1
## cut
my $yllw = 0;       # "y" n'est pas une voyelle ici
my $rhythm = 12;    # Mais ici, ça l'est

Ceux-ci sont appelés "sous-tests", et deux sont montrés ci-dessus. La beauté de l'intégration de plusieurs sous-tests dans un fichier est que le fichier .run est lui-même un fichier Perl (principalement) valide, et non caché dans un HEREDOC, donc la coloration de votre éditeur fonctionne toujours, et il est beaucoup plus facile de travailler avec le code et le POD.

Si vous avez besoin de passer des paramètres de configuration pour votre sous-test, faites-le comme ceci :

## parms { allow_y => '0' }

Notez que toutes les valeurs de ce hash doivent être des chaînes de caractères car c'est ce que Perl::Critic vous fournira à partir d'un .perlcriticrc.

S'il s'agit d'un sous-test TODO (probablement à cause d'un coin bizarre de PPI que nous avons exercé et qu'Adam est en train de corriger, n'est-ce pas ?), alors faites une entrée "##TODO".

## TODO Devrait passer lorsque PPI 1.xxx sortira

Si le code est censé déclencher une exception dans la politique, indiquez-le comme ceci :

## error 1

Si vous souhaitez tester le message d'erreur, marquez-le avec "/.../" pour indiquer un test like() :

## error /Impossible de charger Foo::Bar/

Si la politique que vous testez se soucie du nom de fichier du code, vous pouvez l'indiquer en utilisant "fcritique" comme ceci (voir "fcritique" pour plus de détails) :

## filename lib/Foo/Bar.pm

La valeur de "parms" sera

get "eval"é et passé à pcritique(), donc soyez prudent.

En général, un document de sous-test s'exécute à partir de la balise "## cut" qui le démarre jusqu'à la suivante "## name" ou la fin du fichier. Dans des circonstances très rares, vous pourriez avoir besoin de terminer le document de test plus tôt. Une seconde "## cut" fera cela. Le seul besoin connu pour cela est dans t/Miscellanea/RequireRcsKeywords.run, où il est utilisé pour empêcher les mots-clés RCS dans le pied de page du fichier de produire de faux positifs ou négatifs lors du dernier test.

Notez qu'à aucun moment dans le fichier .run lui-même vous ne spécifiez la politique que vous testez. Celle-ci est implicite dans le nom du fichier.

BOGUES ET REMARQUES ET POINTS À FAIRE

Tester que nous avons un t/*/*.run pour chaque lib/*/*.pm

Nous permettre de spécifier la nature des échecs, et lequel. S'il y a 15 lignes de code, et que six d'entre elles échouent, comment savoir si ce sont les bonnes six ?
