NOM

Perl::Critic::Policy::ValuesAndExpressions::RequireConstantVersion - Exiger que $VERSION soit une constante plutôt qu'une valeur calculée.

AFFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

La variable $VERSION d'un module doit être une constante simple - soit un nombre, une chaîne entre apostrophes simples, soit un objet 'use version'. Dans ce dernier cas, le 'use version;' doit apparaître sur la même ligne que la construction de l'objet.

Le calcul de la version pose des problèmes de sévérité variable.

La violation la plus bénigne consiste à calculer la version à partir (par exemple) d'un numéro de révision Subversion :

our ($VERSION) = q$REVISION: 42$ =~ /(\d+)/;

Le problème ici est que la version est liée à un seul dépôt. Le code ne peut pas être déplacé vers un autre dépôt (même du même type) sans changer sa version, potentiellement dans la mauvaise direction.

Cette politique accepte les chaînes v ("v1.2.3" ou simplement 1.2.3), car celles-ci sont déjà signalées par Perl::Critic::Policy::ValuesAndExpressions::ProhibitVersionStrings.

CONFIGURATION

La manière appropriée de définir le $VERSION d'un module à un objet "version" est d'"use version;" sur la même ligne de code qui assigne la valeur de $VERSION. De cette façon, ExtUtils::MakeMaker et Module::Build peuvent extraire la version lors de l'empaquetage du module pour CPAN. Par défaut, cette politique déclare une erreur si cela n'est pas fait.

Si vous souhaitez autoriser les objets de version sans charger le module version sur la même ligne, ajoutez ce qui suit à votre fichier de configuration :

[ValuesAndExpressions::RequireConstantVersion]
allow_version_without_use_on_same_line = 1

AVERTISSEMENTS

Il y aura de faux négatifs si le $VERSION apparaît du côté gauche d'une affectation de liste qui affecte plus d'une variable, ou à "undef".

Il peut y avoir de faux positifs si le $VERSION se voit assigner la valeur d'un here document. Cela restera probablement le cas jusqu'à ce que PPI::Token::HereDoc acquière les parties pertinentes de l'interface de PPI::Token::Quote.

Il y aura de faux positifs si $VERSION se voit assigner la valeur d'une constante créée par le module Readonly ou le pragma constant, car l'infrastructure nécessaire semble ne pas exister, et l'auteur du présent module manquait de connaissances/expertise/audace pour la mettre en place.

Actuellement, l'idiome

our $VERSION = '1.005_05';
$VERSION = eval $VERSION;

provoquera une violation sur la deuxième ligne de l'exemple.
