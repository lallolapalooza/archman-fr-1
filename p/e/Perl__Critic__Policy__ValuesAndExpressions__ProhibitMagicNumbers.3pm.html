NAME

Perl::Critic::Policy::ValuesAndExpressions::ProhibitMagicNumbers - Ne pas utiliser de valeurs qui n'expliquent pas leur signification.

AFFILIATION

Cette politique fait partie du noyau de la distribution Perl::Critic.

DESCRIPTION

Qu'est-ce qu'un nombre magique ? Un nombre magique est un nombre qui apparaît dans le code sans explication ; par exemple,

"$bank_account_balance *= 57.492;"

Même si vous voyez ce nombre, vous devez vous demander d'où il vient. Parce que vous ne comprenez pas la signification du nombre, vous ne comprenez pas le code.

En général, les littéraux numériques à l'exception de 0 ou 1 ne devraient pas être utilisés. Utilisez le module pragma constant, ou le module Readonly ou Const::Fast pour donner un nom descriptif au nombre.

Cependant, il existe des exceptions lorsque cette règle devrait s'appliquer. Un bon exemple est la position des objets dans certains conteneurs, comme les éléments d'un plan ou les widgets dans une interface utilisateur. Dans ces cas, la signification d'un nombre peut être facilement déterminée par le contexte.

Le nombre maximum de violations par document pour cette politique par défaut est de 10.

Façons dont ce module applique cette règle.

Par défaut, cette règle est relâchée, autorisant 2 pour permettre des choses courantes comme l'alternance, le handle de fichier STDERR, etc.

Les littéraux numériques sont autorisés dans les instructions « use » et « require » pour permettre des choses comme les restrictions de version de Perl et les plans de Test::More. Les déclarations de variables de paquet $VERSION sont autorisées. L'utilisation de « Readonly », « Readonly::Scalar », « Readonly::Array » et « Readonly::Hash » du module Readonly est valide, mais l'utilisation de « Readonly::Scalar1 », « Readonly::Array1 » et « Readonly::Hash1 » n'est pas prise en charge.

L'utilisation de nombres binaires, exponentiels, hexadécimaux, octaux et de versions, même pour 0 et 1, en dehors des instructions « use »/« require »/« Readonly » n'est pas autorisée (mais vous pouvez changer cela).

Il existe une exception spéciale pour accéder au dernier élément d'un tableau, c'est-à-dire $x[-1].

$x = 0;                                   # ok
$x = 0.0;                                 # ok
$x = 1;                                   # ok
$x = 1.0;                                 # ok
$x = 1.5;                                 # pas ok
$x = 0b0                                  # pas ok
$x = 0b1                                  # pas ok
$x = 0x00                                 # pas ok
$x = 0x01                                 # pas ok
$x = 000                                  # pas ok
$x = 001                                  # pas ok
$x = 0e1                                  # pas ok
$x = 1e1                                  # pas ok
$frobnication_factor = 42;                # pas ok
use constant FROBNICATION_FACTOR => 42;   # ok
use 5.6.1;                                # ok
use Test::More plan => 57;                # ok
plan tests => 39;                         # ok
our $VERSION = 0.22;                      # ok
$x = $y[-1]                               # ok
$x = $y[-2]                               # pas ok
foreach my $solid (1..5) {                # pas ok
    ...
}
use Readonly;
Readonly my $REGULAR_GEOMETRIC_SOLIDS => 5;
foreach my $solid (1..$REGULAR_GEOMETRIC_SOLIDS) {  #ok
    ...
}

CONFIGURATION

Cette politique a quatre options :

  • "allowed_values"
  • "allowed_types"
  • "allow_to_the_right_of_a_fat_comma"
  • "constant_creator_subroutines"

"allowed_values"

Le paramètre "allowed_values" est un ensemble de valeurs de nombres autorisés, séparés par des espaces ; cela n'affecte pas les formats autorisés pour les nombres. Les valeurs par défaut sont équivalentes à avoir dans votre fichier .perlcriticrc :

[ValuesAndExpressions::ProhibitMagicNumbers]
allowed_values = 0 1 2

Note : Cette politique force les valeurs 0 et 1 à être dans les valeurs autorisées. Par conséquent, spécifier :

allowed_values =

est équivalent à lister simplement 0 et 1 :

allowed_values = 0 1

La valeur spéciale "all_integers" autorise tous les entiers, à condition que les restrictions sur les types numériques soient respectées.

Les plages peuvent être spécifiées comme deux nombres (éventuellement fractionnaires) séparés par deux points, éventuellement suffixés par un incrément utilisant la syntaxe Perl 6 ":by()". Par exemple :

allowed_values = 7..10

autorisera 0, 1, 7, 8, 9 et 10 comme valeurs littérales. Utiliser des valeurs fractionnaires comme ceci :

allowed_values = -3.5..-0.5:by(0.5)

autorisera -3.5, -3, -2.5, -2, -1.5, -1, -0.5, 0 et 1. Sans aucun doute, l'incrément par défaut est de 1, ce qui signifie que :

allowed_values = -3.5..-0.5

générera -3.5, -2.5, -1.5, -0.5, 0 et 1 comme valeurs valides.

Les plages ne sont pas paresseuses, c'est-à-dire que vous devez avoir une grande quantité de mémoire disponible si vous utilisez une plage de "1..1000:by(0.01)". Rappelez-vous que tout cela est fait avec des calculs en virgule flottante, ce qui signifie que "1..10:by(0.3333)" ne sera probablement pas très utile.

Attention, spécifier une limite supérieure inférieure à la limite inférieure ne générera aucune valeur pour cette plage. Les incréments négatifs ne sont pas autorisés.

Plusieurs plages sont autorisées.

Pour résumer tout cela, ce qui suit est une entrée valide, bien que peu susceptible d'être utilisée, dans un fichier .perlcriticrc :

[ValuesAndExpressions::ProhibitMagicNumbers]
allowed_values = 3.1415269 82..103 -507.4..57.8:by(0.2) all_integers

"allowed_types"

Le paramètre "allowed_types" est un ensemble de sous-classes de PPI::Token::Number séparées par des espaces.

Les entiers décimaux sont toujours autorisés. Par défaut, les nombres flottants sont également autorisés.

Par exemple, pour autoriser les littéraux hexadécimaux, vous pourriez configurer cette politique comme suit :

[ValuesAndExpressions::ProhibitMagicNumbers]
allowed_types = Hex

mais sans rien spécifier pour "allowed_values", les littéraux hexadécimaux autorisés seront "0x00", "0x01" et "0x02". De plus, rappelez-vous que, une fois que vous avez spécifié une valeur pour ce paramètre, vous devez inclure "Float" dans la liste pour continuer à utiliser des littéraux flottants. Cet effet peut être utilisé pour restreindre les littéraux aux seuls entiers décimaux :

[ValuesAndExpressions::ProhibitMagicNumbers]
allowed_types =

Si vous autorisez la notation exponentielle, vous autorisez automatiquement également les valeurs flottantes car une exponentielle est un sous-type de flottant dans PPI.

"allow_to_the_right_of_a_fat_comma"

Si cette valeur est activée, vous pouvez placer n'importe quel nombre à droite d'une virgule grasse.

my %hash =     ( a => 4512, b => 293 );         # ok
my $hash_ref = { a => 4512, b => 293 };         # ok
some_subroutine( a => 4512, b => 293 );         # ok

Actuellement, cela signifie uniquement "directement" à droite de la virgule grasse. Par défaut, cette valeur est "vraie".

="Ss">

"constant_creator_subroutines"

Ce paramètre vous permet de spécifier les noms des sous-routines qui créent des constantes, en plus de "Readonly", "Const::Fast", et leurs similaires. Par exemple, si vous utilisez un module personnalisé de type "Const::Fast" qui prend en charge une sous-routine "create_constant" pour créer des constantes, vous pourriez ajouter quelque chose comme suit à votre fichier .perlcriticrc:

[ValuesAndExpressions::ProhibitMagicNumbers]
constant_creator_subroutines = create_constant

Si vous avez plus d'un nom à ajouter, séparez-les par des espaces.

Le nom de la sous-routine doit apparaître exactement tel qu'il est dans votre code. Par exemple, si votre code n'importe pas la sous-routine de création de constante, vous devrez configurer cette politique comme suit:

[ValuesAndExpressions::ProhibitMagicNumbers]
constant_creator_subroutines = create_constant Constant::Create::create_constant

BUGS

Il n'y a actuellement aucun moyen de permettre les numéros de version dans le code régulier, même si vous les incluez dans "allowed_types". Certains pourraient considérer cela comme une fonctionnalité.
