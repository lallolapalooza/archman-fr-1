Perl::Critic::Policy::Modules::RequireExplicitPackage(3pm) Documentation Perl fournie par l'utilisateur Perl::Critic::Policy::Modules::RequireExplicitPackage(3pm)

NOM

Perl::Critic::Policy::Modules::RequireExplicitPackage - Toujours rendre le "package" explicite.

AFILATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

En général, la première instruction de tout module ou bibliothèque Perl doit être une instruction "package". Sinon, tout le code qui précède l'instruction "package" est exécuté dans le package de l'appelant, et vous n'avez aucune idée de qui il s'agit. Une bonne encapsulation et une décence commune exigent que votre module garde ses entrailles pour lui seul.

Il existe de bonnes raisons de ne pas avoir de déclaration "package" du tout. Mais assurez-vous de les comprendre avant de supposer que vous devriez le faire aussi.

L'une de ces raisons est d'avoir une ligne "use VERSION" comme première ligne de votre fichier Perl. Elle déclare la version du langage Perl pour le code qui suit. Comme l'effet est lexical, les remarques précédentes sur le package de l'appelant ne s'appliquent pas.

Le nombre maximum de violations par document pour cette politique est de 1 par défaut.

CONFIGURATION

Comme pour les programmes, la plupart des gens comprennent que le package par défaut est "main", donc cette politique ne s'applique pas aux fichiers qui commencent par un shebang perl. Si vous voulez exiger une déclaration "package" explicite dans tous les fichiers, y compris les programmes, ajoutez ce qui suit à votre fichier .perlcriticrc

[Modules::RequireExplicitPackage]
exempt_scripts = 0

Certains utilisateurs peuvent trouver souhaitable d'exempter le chargement de modules spécifiques de cette politique. Par exemple, Perl ne supporte pas les noms de modules Unicode en raison de problèmes de portabilité. Les utilisateurs qui ne sont pas concernés par cela et qui ont l'intention d'utiliser des noms de modules "UTF-8" devront spécifier "use utf8;" avant la déclaration du package. Pour ce faire, ajoutez ce qui suit à votre fichier .perlcriticrc

[Modules::RequireExplicitPackage]
allow_import_of = utf8

L'option de configuration "allow_import_of" accepte plusieurs noms de modules, séparés par des espaces.

CHANGEMENTS IMPORTSANTS

Cette politique s'appelait autrefois "ProhibitUnpackagedCode", ce qui semblait un peu étrange. Si vous obtenez de nombreuses erreurs "Cannot load policy module", vous devrez probablement changer "ProhibitUnpackagedCode" en "RequireExplicitPackage" dans votre fichier .perlcriticrc.
