DESCRIPTION

Toutes les fonctions décrites sur cette page dont le type est DH, DSA et RSA sont dépréciées. Les applications devraient utiliser OSSL_ENCODER_to_bio(3) et OSSL_DECODER_from_bio(3) à la place.

Les fonctions PEM lisent ou écrivent des structures au format PEM. En ce sens, le format PEM est simplement des données encodées en base64 entourées de lignes d'en-tête.

Pour plus de détails sur la signification des arguments, voir la section ARGUMENTS DES FONCTIONS PEM.

Chaque opération a quatre fonctions associées. Par souci de concision, le terme "fonctions TYPE" sera utilisé ci-dessous pour désigner collectivement les fonctions PEM_read_bio_TYPE(), PEM_read_TYPE(), PEM_write_bio_TYPE() et PEM_write_TYPE().

Certaines opérations ont des variantes supplémentaires qui prennent un contexte de bibliothèque libctx et une chaîne de requête de propriété propq. Les objets X509, X509_REQ et X509_CRL peuvent avoir un contexte de bibliothèque ou une chaîne de requête de propriété associés, mais il n'y a pas de variantes de ces fonctions qui prennent un paramètre de contexte de bibliothèque ou de chaîne de requête de propriété. Dans ce cas, il est possible de définir le contexte de bibliothèque ou la chaîne de requête de propriété appropriée en créant un objet X509, X509_REQ ou X509_CRL vide à l'aide de X509_new_ex(3), X509_REQ_new_ex(3) ou X509_CRL_new_ex(3) respectivement. Ensuite, passez l'objet vide comme paramètre à la fonction PEM pertinente. Voir la section "EXEMPLES" ci-dessous.

Les fonctions PrivateKey lisent ou écrivent une clé privée au format PEM en utilisant une structure EVP_PKEY. Les routines d'écriture utilisent le format de clé privée PKCS#8 et sont équivalentes à PEM_write_bio_PKCS8PrivateKey(). Les fonctions de lecture gèrent de manière transparente les clés cryptées et non cryptées, au format traditionnel et PKCS#8.

PEM_write_bio_PrivateKey_traditional() écrit une clé privée au format "traditionnel" avec un marqueur de clé privée simple et ne doit être utilisée que pour la compatibilité avec les programmes hérités.

PEM_write_bio_PKCS8PrivateKey() et PEM_write_PKCS8PrivateKey() écrivent une clé privée dans une structure EVP_PKEY au format PKCS#8 EncryptedPrivateKeyInfo en utilisant des algorithmes de chiffrement basés sur un mot de passe PKCS#5 v2.0. L'argument cipher spécifie l'algorithme de chiffrement à utiliser : contrairement à certaines autres routines PEM, le chiffrement est appliqué au niveau PKCS#8 et non dans les en-têtes PEM. Si cipher est NULL, aucun chiffrement n'est utilisé et une structure PKCS#8 PrivateKeyInfo est utilisée à la place.

PEM_write_bio_PKCS8PrivateKey_nid() et PEM_write_PKCS8PrivateKey_nid() écrivent également une clé privée sous forme de PKCS#8 EncryptedPrivateKeyInfo, mais utilisent plutôt des algorithmes de chiffrement PKCS#5 v1.5 ou PKCS#12. L'algorithme à utiliser est spécifié dans le paramètre nid et doit être le NID de l'OBJECT IDENTIFIER correspondant (voir la section NOTES).

Les fonctions PUBKEY traitent une clé publique à l'aide d'une structure EVP_PKEY. La clé publique est encodée en tant que structure SubjectPublicKeyInfo.

Les fonctions RSAPrivateKey traitent une clé privée RSA à l'aide d'une structure RSA. Les routines d'écriture utilisent le format traditionnel. Les routines de lecture gèrent les mêmes formats que les fonctions PrivateKey, mais une erreur se produit si la clé privée n'est pas RSA.

Les fonctions RSAPublicKey traitent une clé publique RSA à l'aide d'une structure RSA. La clé publique est encodée en utilisant une structure PKCS#1 RSAPublicKey.

Les fonctions RSA_PUBKEY traitent également une clé publique RSA à l'aide d'une structure RSA. Cependant, la clé publique est encodée à l'aide d'une structure SubjectPublicKeyInfo et une erreur se produit si la clé publique n'est pas RSA.

Les fonctions DSAPrivateKey traitent une clé privée DSA à l'aide d'une structure DSA. Les routines d'écriture utilisent le format traditionnel. Les routines de lecture gèrent les mêmes formats que les fonctions PrivateKey, mais une erreur se produit si la clé privée n'est pas DSA.

Les fonctions DSA_PUBKEY traitent une clé publique DSA à l'aide d'une structure DSA. La clé publique est encodée à l'aide d'une structure SubjectPublicKeyInfo et une erreur se produit si la clé publique n'est pas DSA.

Les fonctions Parameters lisent ou écrivent des paramètres de clé au format PEM en utilisant une structure EVP_PKEY. L'encodage dépend du type de clé ; pour les paramètres de clé DSA, ce sera une structure Dss-Parms telle que définie dans la RFC 3370, et pour les paramètres de clé DH, ce sera une structure PKCS#3 DHparameter. Ces fonctions n'existent que pour le type BIO.

Les fonctions DSAparams traitent les paramètres DSA à l'aide d'une structure DSA. Les paramètres sont encodés à l'aide d'une structure Dss-Parms telle que définie dans la RFC 3370.

Les fonctions DHparams traitent les paramètres DH à l'aide d'une structure DH. Les paramètres sont encodés à l'aide d'une structure PKCS#3 DHparameter.

Les fonctions X509 traitent un certificat X509 à l'aide d'une structure X509. Elles traitent également un certificat X509 approuvé, mais tous les paramètres d'approbation sont ignorés.

Les fonctions X509_ACERT traitent un certificat d'attribut X509 à l'aide d'une structure X509_ACERT.

Les fonctions X509_AUX traitent un certificat X509 approuvé à l'aide d'une structure X509.

Les fonctions X509_REQ et X509_REQ_NEW traitent une demande de certificat PKCS#10 à l'aide d'une structure X509_REQ. Les fonctions d'écriture X509_REQ utilisent CERTIFICATE REQUEST dans l'en-tête, tandis que les fonctions X509_REQ_NEW utilisent NEW CERTIFICATE REQUEST (comme requis par certaines CA). Les fonctions de lecture X509_REQ gèrent l'une ou l'autre forme, il n'y a donc pas de fonctions de lecture X509_REQ_NEW.

Les fonctions X509_CRL traitent une CRL X509 à l'aide d'une structure X509_CRL.

Les fonctions PKCS7 traitent une PKCS#7 ContentInfo à l'aide d'une structure PKCS7.

ARGUMENTS DES FONCTIONS PEM

Les fonctions PEM ont de nombreux arguments communs.

L'argument bp BIO (s'il est présent) spécifie le BIO à lire ou à écrire. L'argument bp BIO NE DOIT PAS être NULL.

L'argument fp FILE (s'il est présent) spécifie le pointeur FILE à lire ou à écrire.

Les fonctions de lecture PEM prennent toutes un argument TYPE **x et retournent un pointeur TYPE *. Où TYPE est la structure que la fonction utilise. Si x est NULL, le paramètre est ignoré. Si x n'est pas NULL mais *x est NULL, la structure retournée sera écrite dans *x. Si ni x ni *x ne sont NULL, une tentative est faite pour réutiliser la structure à *x (mais voir les sections BUGS et EXEMPLES). Indépendamment de la valeur de x, un pointeur vers la structure est toujours retourné (ou NULL si une erreur s'est produite). L'appelant conserve la propriété de l'objet retourné et doit le libérer lorsqu'il n'est plus nécessaire, par exemple en utilisant X509_free() pour les objets X509 ou EVP_PKEY_free() pour les objets EVP_PKEY.

Les fonctions PEM qui écrivent des clés privées prennent un argument enc qui spécifie l'algorithme de chiffrement à utiliser, le chiffrement étant effectué au niveau PEM. Si ce paramètre est défini sur NULL, la clé privée est écrite sous forme non chiffrée.

L'argument cb est la fonction de rappel à utiliser lors de la requête de la phrase secrète utilisée pour les structures PEM chiffrées (normalement uniquement les clés privées).

Pour les routines d'écriture PEM, si le paramètre kstr n'est pas NULL, alors klen octets à kstr sont utilisés comme phrase secrète et cb est ignoré.

Si le paramètre cb est défini sur NULL et que le paramètre u n'est pas NULL, alors le paramètre u est interprété comme une chaîne terminée par NUL à utiliser comme phrase secrète. Si cb et u sont NULL, la routine de rappel par défaut est utilisée, qui demandera généralement la phrase secrète sur le terminal actuel sans écho.

Le rappel de phrase secrète par défaut est parfois inapproprié (par exemple dans une application GUI), une alternative peut donc être fournie. La routine de rappel a la forme suivante :

int cb(char *buf, int size, int rwflag, void *u);

buf est le tampon dans lequel écrire la phrase secrète. size est la longueur maximale de la phrase secrète (c'est-à-dire la taille de buf). rwflag est un indicateur qui est défini à 0 lors de la lecture et à 1 lors de l'écriture. Une routine typique demandera à l'utilisateur de vérifier la phrase secrète (par exemple, en la demandant deux fois) si rwflag est 1. Le paramètre u a la même valeur que le paramètre u passé à la routine PEM. Il permet à des données arbitraires d'être passées au rappel par l'application (par exemple, un handle de fenêtre dans une application GUI). Le rappel doit retourner le nombre de caractères de la phrase secrète ou -1 si une erreur s'est produite. La phrase secrète peut être des données arbitraires ; dans le cas où il s'agit d'une chaîne, elle n'est pas terminée par NUL. Voir la section "EXEMPLES" ci-dessous.

Certaines implémentations peuvent avoir besoin d'utiliser des algorithmes cryptographiques pendant leurs opérations. Si tel est le cas et que les paramètres libctx et propq ont été passés, toute récupération d'algorithme utilisera ce contexte de bibliothèque et cette chaîne de requête de propriété. Sinon, le contexte de bibliothèque et la chaîne de requête de propriété par défaut seront utilisés.

NOTES

Les fonctions de lecture PEM ignoreront tout contenu superflu ou toute donnée PEM d'un type différent de celui attendu. Cela permet, par exemple, d'avoir un certificat (ou plusieurs certificats) et une clé au format PEM dans un seul fichier.

NOM

PEM_READ_BIO_PrivateKey

SYNTAXIS

int PEM_read_bio_PrivateKey(BIO *bp, EVP_PKEY *pkey, int flags, char *passphrase);

DESCRIPTION

Cette fonction lit une clé privée à partir d'un BIO en utilisant la routine PEM_read_bio_PrivateKey(). Elle est adaptée aux applications qui doivent lire des clés privées au format PEM. La fonction est sécurisée et utilise un nombre d'itérations de 2048 pour le processus de dérivation de clé, ce qui est plus sécurisé que les routines traditionnelles qui utilisent un compte de 1.

ARGUMENTS DE LA FONCTION PEM

La fonction PEM_read_bio_PrivateKey() a les arguments suivants :

- bp : Un pointeur BIO vers les données d'entrée.

- pkey : Un pointeur vers la clé privée à lire.

- flags : Indicateurs pour contrôler le comportement de la fonction.

- passphrase : Une phrase secrète à utiliser pour le déchiffrement.

NOTES

La fonction PEM_read_bio_PrivateKey() est sécurisée et utilise un nombre d'itérations de 2048 pour le processus de dérivation de clé, ce qui est plus sécurisé que les routines traditionnelles qui utilisent un compte de 1.

La fonction est adaptée aux applications qui doivent lire des clés privées au format PEM. Elle est plus sécurisée car elle utilise un nombre d'itérations de 2048 pour le processus de dérivation de clé, alors que les routines traditionnelles utilisent un compte de 1.

FORMAT DE CHIFFREMENT PEM

Ces anciennes routines PrivateKey utilisent une technique non standard pour le chiffrement.

La clé privée (ou d'autres données) prend la forme suivante :

-----BEGIN RSA PRIVATE KEY-----
Proc-Type: 4,ENCRYPTED
DEK-Info: DES-EDE3-CBC,3F17F5316E2BAC89
...données encodées en base64...
-----END RSA PRIVATE KEY-----

La ligne commençant par Proc-Type contient la version et la protection des données encapsulées. La ligne commençant par DEK-Info contient deux valeurs séparées par une virgule : le nom de l'algorithme de chiffrement tel qu'utilisé par EVP_get_cipherbyname() et un vecteur d'initialisation utilisé par le chiffrement encodé sous forme de chiffres hexadécimaux. Après ces deux lignes se trouvent les données chiffrées encodées en base64.

La clé de chiffrement est dérivée en utilisant EVP_BytesToKey(). Le vecteur d'initialisation du chiffrement est passé à EVP_BytesToKey() comme paramètre salt. En interne, PKCS5_SALT_LEN octets du sel sont utilisés (indépendamment de la taille du vecteur d'initialisation). Le mot de passe de l'utilisateur est passé à EVP_BytesToKey() en utilisant les paramètres data et datal. Enfin, la bibliothèque utilise un nombre d'itérations de 1 pour EVP_BytesToKey().

La key dérivée par EVP_BytesToKey() ainsi que le vecteur d'initialisation d'origine sont ensuite utilisés pour déchiffrer les données chiffrées. Le iv produit par EVP_BytesToKey() n'est pas utilisé ou nécessaire, et NULL doit être passé à la fonction.

Le pseudo-code pour dériver la clé ressemblerait à ceci :

EVP_CIPHER* cipher = EVP_des_ede3_cbc();
EVP_MD* md = EVP_md5();
unsigned int nkey = EVP_CIPHER_get_key_length(cipher);
unsigned int niv = EVP_CIPHER_get_iv_length(cipher);
unsigned char key[nkey];
unsigned char iv[niv];
memcpy(iv, HexToBin("3F17F5316E2BAC89"), niv);
rc = EVP_BytesToKey(cipher, md, iv /*salt*/, pword, plen, 1, key, NULL /*iv*/);
if (rc != nkey)
    /* Erreur */
/* En cas de succès, utiliser key et iv pour initialiser le chiffrement */

BOGUES

Les routines de lecture PEM de certaines versions d'OpenSSL ne réutilisent pas correctement une structure existante. Par conséquent, ce qui suit :

PEM_read_bio_X509(bp, &x, 0, NULL);

où x contient déjà un certificat valide, peut ne pas fonctionner, tandis que :

X509_free(x); x = PEM_read_bio_X509(bp, NULL, 0, NULL);

est garanti de fonctionner. Il est toujours acceptable que x contienne un objet X509 nouvellement alloué et vide (par exemple, alloué via X509_new_ex(3)).

VALEURS DE RETOUR

Les routines de lecture retournent soit un pointeur vers la structure lue, soit NULL si une erreur s'est produite.

Les routines d'écriture retournent 1 en cas de succès, ou 0 en cas d'échec.

EXEMPLES

Bien que les routines PEM prennent plusieurs arguments, dans presque toutes les applications, la plupart d'entre eux sont définis sur 0 ou NULL.

Pour lire un certificat avec un contexte de librairie au format PEM à partir d'un BIO :

X509 *x = X509_new_ex(libctx, NULL);
if (x == NULL)
    /* Erreur */
if (PEM_read_bio_X509(bp, &x, 0, NULL) == NULL)
    /* Erreur */

Lire un certificat au format PEM à partir d'un BIO :

X509 *x;
x = PEM_read_bio_X509(bp, NULL, 0, NULL);
if (x == NULL)
    /* Erreur */

Méthode alternative :

X509 *x = NULL;
if (!PEM_read_bio_X509(bp, &x, 0, NULL))
    /* Erreur */

Écrire un certificat dans un BIO :

if (!PEM_write_bio_X509(bp, x))
    /* Erreur */

Écrire une clé privée (en utilisant le format traditionnel) dans un BIO en utilisant le chiffrement triple DES, la phrase secrète est demandée :

if (!PEM_write_bio_PrivateKey(bp, key, EVP_des_ede3_cbc(), NULL, 0, 0, NULL))
    /* Erreur */

Écrire une clé privée (en utilisant le format PKCS#8) dans un BIO en utilisant le chiffrement triple DES, en utilisant la phrase secrète « hello » :

if (!PEM_write_bio_PKCS8PrivateKey(bp, key, EVP_des_ede3_cbc(),
                                   NULL, 0, 0, "hello"))
    /* Erreur */

Lire une clé privée à partir d'un BIO en utilisant une fonction de rappel pour la phrase secrète :

key = PEM_read_bio_PrivateKey(bp, NULL, pass_cb, "Ma Clé Privée");
if (key == NULL)
    /* Erreur */

Fonction de rappel de phrase secrète squelette :

int pass_cb(char *buf, int size, int rwflag, void *u)
{
    /* Nous ferions probablement autre chose si 'rwflag' est 1 */
    printf("Entrez la phrase secrète pour \"%s\"\n", (char *)u);
    /* Obtenez la phrase secrète, longueur 'len' dans 'tmp' */
    char *tmp = "hello";
    if (tmp == NULL) /* Une erreur s'est produite */
        return -1;
    size_t len = strlen(tmp);
    if (len > size)
        len = size;
    memcpy(buf, tmp, len);
    return len;
}

HISTORIQUE

Les anciennes séquences de certificats Netscape n'étaient plus documentées dans OpenSSL 1.1.0 ; les applications devraient utiliser la norme PKCS7 à la place car elles seront formellement dépréciées dans les futures versions.

PEM_read_bio_PrivateKey_ex(), PEM_read_PrivateKey_ex(), PEM_read_bio_PUBKEY_ex(), PEM_read_PUBKEY_ex() et PEM_read_bio_Parameters_ex() ont été introduits dans OpenSSL 3.0.
