NOM

Perl::Critic::Policy::Documentation::PodSpelling - Vérifie l'orthographe de votre code.

AFFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Avez-vous écrit la documentation ? Vérifié.

Avez-vous documenté toutes les méthodes publiques ? Vérifié.

Votre documentation est-elle lisible ? Hmm...

Idéalement, nous aimerions que Perl::Critic vous signale lorsque votre documentation est inadéquate. C'est cependant difficile à coder. Ainsi, inspiré par Test::Spelling, ce module vérifie l'orthographe de votre POD. Il y parvient en extrayant le texte du code et en le passant à un correcteur orthographique externe. Il ignore les mots que vous avez signalés pour ignorer. Si le correcteur orthographique renvoie des mots mal orthographiés, cette politique émet une violation.

Si quelque chose d'autre se produit -- nous ne pouvons pas trouver le programme de correction orthographique ou (horreur !) votre module n'a pas de POD -- alors cette politique est satisfaite.

Pour ajouter des exceptions sur une base module par module, ajoutez "stopwords" comme décrit dans Pod::Spell. Par exemple :

=for stopwords gibbles
=head1 Gibble::Manip -- manipulez vos gibbles
=cut

CONFIGURATION

Cette politique peut être configurée pour spécifier quel correcteur orthographique utiliser ou pour définir une liste globale d'exceptions orthographiques. Pour ce faire, ajoutez des entrées dans un fichier .perlcriticrc comme ceci :

[Documentation::PodSpelling]
spell_command = aspell list
stop_words = gibbles foobar
stop_words_file = some/path/with/stop/words.txt

La commande de correction par défaut est "aspell list" et elle est interprétée comme une commande shell. Nous analysons les arguments individuels via Text::ParseWords, n'hésitez donc pas à utiliser des guillemets autour de vos arguments. Si le chemin de l'exécutable est un nom de fichier absolu, il est utilisé tel quel. S'il s'agit d'un nom de fichier relatif, nous utilisons File::Which pour le convertir en un chemin absolu via la variable d'environnement "PATH". Comme décrit dans Pod::Spell et Test::Spelling, le correcteur orthographique doit accepter du texte sur STDIN et imprimer les mots mal orthographiés un par ligne sur STDOUT.

Vous pouvez spécifier des mots vides globaux via les options "stop_words" et "stop_words_file". Le premier est simplement divisé par les espaces. Le second est lu ligne par ligne, avec tout ce qui suit un octothorp ("#") supprimé, puis les espaces de début et de fin supprimés. Exemple absurde de contenu de fichier valide :

# C'est un commentaire !
foo
arglbargl    # Un autre commentaire.
bar

Les valeurs de "stop_words" et "stop_words_file" sont fusionnées en une seule liste d'exemptions.

NOTES

Un programme de correction orthographique n'est pas inclus avec Perl::Critic.

Les résultats des échecs pour cette politique peuvent être déroutants lorsque aspell se plaint de mots contenant de la ponctuation comme des tirets et des apostrophes. Dans ce cas, aspell n'émettra souvent qu'une partie du mot qu'il pense être mal orthographié. Par exemple, si vous demandez à aspell de vérifier "foobie-bletch", la sortie se plaint uniquement de "foobie". Malheureusement, vous devrez parcourir votre POD pour déterminer quel est le vrai mot dont aspell se plaint. Une chose à essayer est de regarder la sortie de "perl -MPod::Spell -e 'print Pod::Spell->new()->parse_from_file("lib/Your/Module.pm")'" pour voir ce qui est réellement vérifié pour l'orthographe.

PREREQUISITES

Cette politique s'auto-désactivera si File::Which n'est pas disponible.
