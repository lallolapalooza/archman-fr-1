L'API Pegex

Pegex peut être utilisé de plusieurs façons : à l'intérieur de scripts, depuis la ligne de commande, ou comme base d'un framework d'analyse syntaxique modulaire. Ce document détaille les différentes façons d'utiliser Pegex.

Au niveau le plus abstrait, Pegex fonctionne comme suit :

$result = $parser->new($grammar, $receiver)->parse($input);

Ce qui signifie, abstraitement : un analyseur Pegex, sous la direction d'une grammaire Pegex, analyse un flux d'entrée et signale les correspondances à un récepteur Pegex, produisant un résultat.

L'analyseur, la grammaire, le récepteur et même l'entrée sont des objets Pegex. Ces 4 objets sont impliqués dans chaque opération d'analyse Pegex, nous allons donc les examiner brièvement :

Pegex::Parser
Le moteur d'analyse de Pegex. Ce moteur applique la logique de la grammaire à un texte d'entrée. Un analyseur contient une grammaire et un récepteur. Sa méthode principale est appelée "parse". Le moteur d'analyse par défaut est sans retour arrière, décentralisé. Cependant, il existe des sous-classes d'analyseurs pour différents types d'analyses alternatives.
Pegex::Grammar
Une grammaire Pegex commence comme un fichier/texte composé dans la syntaxe Pegex. Avant de pouvoir être utilisée par un analyseur, elle doit être compilée. Après compilation, elle devient un arbre de données composé de règles et d'expressions régulières. Dans les modules basés sur une grammaire Pegex, la grammaire sera compilée dans un fichier de classe. Pegex lui-même utilise une classe Pegex appelée Pegex::Pegex::Grammar pour analyser différentes grammaires Pegex.
Pegex::Receiver
Un analyseur en soi ne sait pas quoi faire avec le texte qu'il a trouvé. Un récepteur Pegex est une classe qui contient des méthodes correspondant aux règles d'une grammaire. Lorsqu'une règle de grammaire correspond, sa méthode correspondante (si elle existe) est appelée avec les données qui ont correspondu. C'est le rôle du récepteur d'agir sur les données, généralement en les construisant dans une nouvelle structure. Pegex utilisera Pegex::Tree::Wrap comme récepteur par défaut ; il produit un arbre de données lisible.
Pegex::Input
Pegex abstrait ses flux d'entrée en une interface objet. Toute opération qui peut prendre une chaîne d'entrée peut également prendre un objet d'entrée. Pegex convertit les chaînes régulières en ces objets. C'est probablement le concept d'API que vous verrez le moins, mais il est couvert ici complètement.

Toutes ces classes d'objets peuvent être héritées pour obtenir divers résultats. Normalement, vous écrirez votre propre grammaire Pegex et un récepteur Pegex pour atteindre un objectif.

Commencer Simple - La Fonction pegex

La fonction `pegex` du module Pegex peut être utilisée pour des tâches plus petites. Voici un exemple :

use Pegex;
use YAML;
$grammar = "
expr: num PLUS num
num: /( DIGIT+ )/
";
print Dump pegex($grammar)->parse('2+2');

Ce programme produirait :

expr:
- num: 2
- num: 2

Examinons ce qui se passe ici. La fonction `pegex` du module Pegex exporte une fonction appelée `pegex`. Cette fonction prend une chaîne de grammaire Pegex en entrée. En interne, cette fonction compile la chaîne de grammaire et crée un objet de grammaire. Ensuite, elle crée un objet analyseur contenant l'objet de grammaire et le renvoie.

La méthode `parse` est appelée sur la chaîne d'entrée : '2+2'. La chaîne d'entrée correspond et une belle structure de données est renvoyée.

Comment cette structure de données a-t-elle été créée ? Par l'objet récepteur, en fait ! Mais nous ne l'avons pas spécifié, n'est-ce pas ? Non. Il a utilisé le récepteur par défaut, `Pegex::Tree::Wrap`. Nous aurions pu dire :

print Dump pegex($grammar, 'Pegex::Tree::Wrap')->parse('2+2');

Ce récepteur génère essentiellement une carte où les noms des règles correspondantes sont les clés et les valeurs feuilles sont les captures d'expressions régulières.

Le récepteur le plus basique, `Pegex::Tree`, génère un arbre de séquences ne contenant que les données (sans les noms de règles). Ce code :

print Dump pegex($grammar, 'Pegex::Tree')->parse('2+2');

produirait :

- 2
- 2

Si nous écrivons notre propre classe de récepteur nommée `Calculator` comme ceci :

package Calculator;
use base 'Pegex::Tree';
sub got_expr {
    my ($receiver, $data) = @_;
    my ($a, $b) = @$data;
    return $a + $b;
}

Alors, ceci :

print pegex(grammar, 'Calculator')->parse('2+2');

imprimerait :

4

Utilisation Plus Détaillée

Pour continuer avec l'exemple précédent, voyons comment le faire plus formellement.

use Pegex::Parser;
use Pegex::Grammar;
use Pegex::Tree;
use Pegex::Input;
use YAML;
$grammar_text = "
expr: num PLUS num
num: /( DIGIT+ )/
";
$grammar = Pegex::Grammar->new(text => $grammar_text);
$receiver = Pegex::Tree->new();
$parser = Pegex::Parser->new(
    grammar => $grammar,
    receiver => $receiver,
);
$input = Pegex::Input->new(string => '2+2');
print Dump $parser->parse($input);

Ce code fait la même chose que l'exemple précédent, mais dans ce cas, nous avons créé tous les objets nous-mêmes.

Grammaires Précompilées

Si vous envoyez une grammaire Pegex dans le cadre d'une distribution CPAN, vous souhaitez qu'elle soit précompilée dans un module. Pegex rend cela facile.

Supposons que le texte de grammaire ci-dessus soit stocké dans un fichier nommé `share/expr.pgx`. Si vous créez un module nommé `lib/MyThing/Grammar.pm` avec un contenu similaire :

package MyThing::Grammar;
use base 'Pegex::Grammar';
use constant file => './share/expr.pgx';
sub make_tree {
}
1;

Puis exécutez cette commande de ligne :

perl -Ilib -MMyThing::Grammar=compile

Cela réécrira votre module pour qu'il ressemble à ceci :

package MyThing::Grammar;
use base 'Pegex::Grammar';
use constant file => './share/expr.pgx';
sub make_tree {
  { '+toprule' => 'expr',
    'PLUS' => { '.rgx' => qr/\G\+/ },
    'expr' => {
      '.all' => [
        { '.ref' => 'num' },
        { '.ref' => 'PLUS' },
        { '.ref' => 'num' }
      ]
    },
    'num' => { '.rgx' => qr/\G([0-9]+)/ }
  }
}
1;

Cette commande a trouvé le fichier où se trouve votre grammaire, l'a compilée et a utilisé `Data::Dumper` pour la renvoyer dans la méthode `make_tree` de votre module.

C'est à quoi ressemble une grammaire Pegex précompilée. Dès que ce module est chargé, la grammaire est prête à être utilisée par Pegex.

Recompilation automatique pendant le développement avec une variable d'environnement

Si vous vous trouvez à devoir compiler votre module de grammaire plusieurs fois pendant le développement, définissez simplement cette variable d'environnement comme suit :

export PERL_PEGEX_AUTO_COMPILE=MyThing::Grammar

Maintenant, chaque fois que le module de grammaire est chargé, il vérifiera s'il doit le recompiler et le fera à la volée.

Si vous avez plus d'une grammaire à recompiler, listez simplement tous les noms séparés par des virgules.

Recompilation automatique pendant le développement à l'aide de"make"

Alternativement, si votre module utilise "ExtUtils::MakeMaker", vous pouvez faire en sorte que "make" recompile automatiquement votre classe "Grammar" si votre fichier ".pgx" est mis à jour.

Ajoutez simplement cette ligne à la fin de votre "Makefile.PL" :

sub MY::postamble {
  <<EOF;
lib/MyThing/Grammar.pm : share/expr.pgx
\t\$(PERL) -Ilib -MMyThing::Grammar=compile
EOF
}
