Perl::Critic::Policy::InputOutput::ProhibitBacktickOperators(3pm) Documentation Perl fournie par l'utilisateur Perl::Critic::Policy::InputOutput::ProhibitBacktickOperators(3pm)

NOM

Perl::Critic::Policy::InputOutput::ProhibitBacktickOperators - Décourager les choses comme "@files = `ls $directory`".

AFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Les backticks sont super pratiques, surtout pour les programmes CGI, mais je trouve qu'ils font beaucoup de bruit en remplissant STDERR avec des messages lorsqu'ils échouent. Je pense qu'il vaut mieux utiliser IPC::Open3 pour intercepter toute la sortie et laisser l'application décider quoi en faire.

use IPC::Open3 'open3';
$SIG{CHLD} = 'IGNORE';
@output = `some_command`;                      # pas bon
my ($writer, $reader, $err);
open3($writer, $reader, $err, 'some_command'); # bon;
@output = <$reader>;  # Sortie ici
@errors = <$err>;     # Erreurs ici, au lieu de la console

CONFIGURATION

Alternativement, si vous souhaitez utiliser des backticks, vous pouvez restreindre les vérifications aux contextes vides en ajoutant ce qui suit à votre fichier .perlcriticrc:

[InputOutput::ProhibitBacktickOperators]
only_in_void_context = 1

Le but des backticks est de capturer la sortie d'une commande externe. Leur utilisation dans un contexte vide est probablement un bug. Si la sortie n'est pas réellement requise, system() devrait être utilisé. Sinon, assignez le résultat à une variable.

`some_command`;                      # pas bon
$output = `some_command`;            # bon
@output = `some_command`;            # bon

NOTES

Cette politique interdit également la forme généralisée des backticks vue comme "qx{}".

Voir perlipc pour plus de discussion sur l'utilisation de wait() au lieu de "$SIG{CHLD} = 'IGNORE'".

Vous pourriez envisager d'utiliser la fonction capture() du module IPC::System::Simple pour une manière plus sûre de faire ce que font les backticks, en particulier sous Windows. Le module dispose également d'un wrapper sécurisé autour de system().
