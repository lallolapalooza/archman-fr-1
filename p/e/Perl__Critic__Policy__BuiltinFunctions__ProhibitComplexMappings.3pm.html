Perl::Critic::Policy::BuiltinFunctions::ProhibitComplexMappings(3pm) Documentation Perl fournie par l'utilisateur Perl::Critic::Policy::BuiltinFunctions::ProhibitComplexMappings(3pm)

NOM

Perl::Critic::Policy::BuiltinFunctions::ProhibitComplexMappings - Les blocs map doivent comporter une seule instruction.

AFFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

La fonction map peut être déroutante pour les novices dans les meilleures circonstances. Les mappages comportant plusieurs instructions sont encore pires. Ils sont également un cauchemar pour les mainteneurs car toute complexité ajoutée diminue considérablement la lisibilité. Pourquoi ? Parce que map est traditionnellement un one-liner convertissant un tableau en un autre. Essayer de caser beaucoup de fonctionnalités dans un one-liner est une mauvaise idée en général.

Les meilleures solutions à un mappage complexe sont : 1) écrire une sous-routine qui effectue la manipulation et l'appeler depuis map ; 2) réécrire le map en une boucle for.

AVERTISSEMENTS

Cette politique manque actuellement certaines instructions composées à l'intérieur du map. Par exemple, le code suivant déclenche incorrectement une violation :

map { do { foo(); bar() } } @list

CONFIGURATION

Par défaut, cette politique signale tous les mappages comportant plus d'une instruction. Bien que nous ne le recommandions pas, vous pouvez augmenter cette limite comme suit dans un fichier .perlcriticrc :

[BuiltinFunctions::ProhibitComplexMappings]
max_statements = 2
