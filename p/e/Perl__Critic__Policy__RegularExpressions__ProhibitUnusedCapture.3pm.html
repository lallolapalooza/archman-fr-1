Perl::Critic::Policy::RegularExpressions::ProhibitUnusedCapture(3pm) Documentation Perl fournie par l'utilisateur Perl::Critic::Policy::RegularExpressions::ProhibitUnusedCapture(3pm)

NOM

Perl::Critic::Policy::RegularExpressions::ProhibitUnusedCapture - N'utilisez un groupe de capture que si vous prévoyez d'utiliser la valeur capturée.

AFFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Les expressions régulières Perl ont plusieurs types de syntaxe de regroupement. Les parenthèses de base (par exemple "m/(foo)/") capturent dans la variable magique $1. Les groupes non capturants (par exemple "m/(?:foo)/") sont utiles car ils ont de meilleures performances d'exécution et ne copient pas les chaînes aux variables magiques globales de capture.

C'est aussi plus facile pour le programmeur de maintenance si vous utilisez de manière cohérente les groupes capturants et non capturants, car ce programmeur peut dire plus facilement quelles expressions régulières peuvent être refactorisées sans casser le code environnant qui pourrait utiliser les valeurs capturées.

CONFIGURATION

Cette politique n'est pas configurable sauf pour les options standard.

CAVEATS

Interpolation de "qr//"

Cette politique peut être confondue par l'interpolation d'éléments "qr//", mais ce sont toujours des faux négatifs. Par exemple:

my $foo_re = qr/(foo)/;
my ($foo) = m/$foo_re (bar)/x;

Un humain peut dire que cela devrait être une violation car il y a deux captures mais seule la première capture est utilisée, pas la seconde. La politique ne remarque que qu'il y a une capture dans l'expression régulière et reste satisfaite.

"@-", "@+", $LAST_MATCH_START et $LAST_MATCH_END

Cette politique ne reconnaîtra les groupes de capture référencés par ces variables que si leur utilisation est indexée par un entier littéral.

$^N et $LAST_SUBMATCH_RESULT

Cette politique ne reconnaîtra pas les groupes de capture référencés uniquement par ces variables, car il n'y a en général aucun moyen par analyse statique de déterminer quel groupe de capture est référencé. Par exemple,

m/ (?: (A[[:alpha:]]+) | (N\d+) ) (?{$foo=$^N}) /smx

utilise le premier groupe de capture si cela correspond, ou le second groupe de capture si le premier ne correspond pas mais le second le fait.

split()

Normalement, cette politique pense que si une capture est utilisée du tout, elle doit être utilisée avant la prochaine expression régulière dans le même scope. L'expression régulière dans un split() doit être exemptée car elle n'affecte pas les variables de capture de l'appelant.

À l'heure actuelle, cette politique reconnaît et exempte les expressions régulières dans

split /.../, ...

et

split( /.../, ... )

mais une syntaxe plus exotique peut produire des faux positifs.
