PerlIO(3perl) Manuel de référence du programmeur Perl PerlIO(3perl)

NOM

PerlIO - Chargeur à l'exécution pour les couches PerlIO et la racine de l'espace de noms PerlIO::*

SYNTAXE

# Support pour les fichiers natifs et les fichiers texte avec CRLF
open(my $fh, "<:crlf", "my.txt") or die "open failed: $!";
# Ajouter du texte encodé en UTF-8
open(my $fh, ">>:encoding(UTF-8)", "some.log") 
  or die "open failed: $!";
# ouvrir un fichier binaire en lecture
open(my $fh, "<", "his.jpg") or die "open failed: $!";
binmode($fh) or die "binmode failed: $!";
Shell:
  PERLIO=:perlio perl ....

DESCRIPTION

Lorsqu'une couche 'foo' non définie est rencontrée dans une spécification "open" ou "binmode", le code C exécute l'équivalent de :

use PerlIO 'foo';

La partie code Perl dans PerlIO.pm essaie de localiser une couche en faisant :

require PerlIO::foo;

Par ailleurs, le paquet "PerlIO" est un espace réservé pour les fonctions relatives à PerlIO.

COUCheS

D'une manière générale, les couches PerlIO (précédemment connues sous le nom de « disciplines ») sont une pile ordonnée appliquée à un handle (spécifiquement, une chaîne de caractères séparée par des espaces ou des deux-points, généralement écrite avec un préfixe deux-points). Chaque couche effectue une opération sur le contenu d'entrée ou de sortie, sauf lorsqu'elle est transmise telle quelle lors de "sysread" ou "syswrite". Les opérations de lecture traversent la pile dans l'ordre où elles sont définies (de gauche à droite), et les opérations d'écriture dans l'ordre inverse.

Il existe également des couches qui définissent réellement des drapeaux dans les couches inférieures, ou des couches qui modifient la pile actuelle mais ne persistent pas dans celle-ci ; celles-ci sont appelées couches pseudo.

Lors de l'ouverture d'un handle, celui-ci sera ouvert avec les couches spécifiées dans l'appel open() (ou avec les défauts du système, si un préfixe deux-points est spécifié sans couches).

Si aucune couche n'est explicitement spécifiée, le handle sera ouvert avec les couches spécifiées par la variable ${^OPEN} (généralement configurée via le pragma open dans une portée de bloc ou le paramètre "-C" sur la ligne de commande ou le paramètre "PERL_UNICODE" dans la portée principale du programme).

Si aucune couche n'est spécifiée dans l'appel open() ou dans la variable ${^OPEN}, le handle sera ouvert avec la pile de couches par défaut configurée pour cette architecture ; voir « Défauts et comment les surcharger ».

Certaines couches inséreront automatiquement les couches inférieures nécessaires si elles ne sont pas présentes ; par exemple, ":perlio" insérera ":unix" sous lui-même pour les E/S de bas niveau, et ":encoding" insérera les couches par défaut pour les E/S bufferisées.

La fonction "binmode" peut être appelée sur un handle ouvert pour insérer des couches supplémentaires dans la pile, qui peuvent également modifier les couches existantes. La fonction "binmode" appelée sans couches spécifiées supprimera ou désactivera toutes les couches qui transforment le flux d'octets, rendant le handle approprié pour les données binaires.

Les couches suivantes sont actuellement définies :

:unix
La couche la plus basse qui fournit des opérations PerlIO de base en termes d'appels de descripteurs UNIX/POSIX (open(), read(), write(), lseek(), close()). Elle est utilisée même sur des architectures non-UNIX et presque toutes les autres couches opèrent dessus.
:stdio
Une couche qui appelle "fread", "fwrite" et "fseek"/"ftell" etc. Notez qu'il s'agit du "vrai" stdio, il ignorera toutes les couches en dessous de lui et passera directement aux systèmes d'exploitation via la bibliothèque C, implémentant à la fois les E/S de bas niveau et la bufferisation. Cependant, il est rarement utilisé sur les architectures modernes.
:perlio
Implémentation de bufferisation à partir de zéro pour PerlIO. Elle offre un accès rapide à la bufferisation pour "sv_gets", qui implémente les fonctions de lecture de Perl (readline/<>) et tente en général de minimiser la copie de données.

Le ":perlio" insère une couche ":unix" sous lui-même pour effectuer des E/S de bas niveau.

:crlf
Une couche qui implémente les fins de ligne de type CRLF (DOS/Windows). En lecture, elle convertit les paires CR, LF en un seul caractère de nouvelle ligne « \n ». En écriture, elle convertit chaque « \n » en une paire CR, LF. Notez que cette couche sera silencieusement rejetée si elle est empilée sur elle-même.

Elle n'imite actuellement pas MS-DOS comme prévu dans la gestion du Control-Z comme marqueur de fin de fichier.

Sur les architectures similaires à DOS/Windows où cette couche fait partie des défauts, elle agit également comme la couche ":perlio", et la suppression de la traduction CRLF (comme avec ":raw") ne fera que désactiver le drapeau de traduction CRLF. Depuis Perl 5.14, vous pouvez également appliquer une autre couche ":crlf" après, comme lorsque le CRLF doit être traduit après une couche d'encodage. Sur d'autres architectures, c'est une couche de traduction CRLF normale et elle peut être ajoutée et supprimée normalement.

# traduire CRLF après encodage en Perl 5.14 ou supérieur
binmode $fh, ":raw:encoding(UTF-16LE):crlf"
  or die "binmode failed: $!";
:utf8
Une couche pseudo qui déclare que le flux accepte l'encodage interne de caractères de Perl, qui est approximativement UTF-8 sur les machines ASCII, mais UTF-EBCDIC sur les machines EBCDIC. Cela permet de lire ou d'écrire n'importe quel caractère que Perl peut représenter dans le flux.

Cette couche (qui définit en fait un drapeau dans la couche précédente, et est implicitement définie par toute couche ":encoding") ne traduira ni ne validera les séquences d'octets. Au lieu de cela, elle indique que le flux d'octets a été organisé par les couches précédentes pour être fourni dans l'encodage interne de Perl, qui sera interprété comme des caractères Unicode par le code Perl (et le code XS correctement écrit).

ATTENTION : N'utilisez pas cette couche pour traduire des octets UTF-8, car des données invalides ou binaires peuvent entraîner des chaînes malformées en Perl. Bien qu'elle ne produise pas de séquences UTF-8 invalides en sortie, elle produira du UTF-EBCDIC sur les systèmes EBCDIC. La couche ":encoding(UTF-8)" (avec un trait d'union, ce qui est significatif) est préférée car elle garantit la traduction entre des octets UTF-8 valides et des caractères Unicode valides.

:bytes
Ceci est l'inverse de la couche pseudo ":utf8". La couche inférieure est désactivée de sorte que les données lues à partir de celle-ci soient considérées comme l'encodage interne de Perl déchargé, ce qui est interprété comme l'encodage d'octets natif Latin-1 ou EBCDIC. De même en sortie, Perl signalera si un caractère « large » (un point de code non compris dans la plage 0..255) est écrit dans un tel flux.

Ceci est très dangereux lors de l'utilisation d'une couche ":encoding" pour ajouter à un handle, car une telle couche suppose qu'elle travaille avec l'encodage interne déchargé de Perl, vous obtiendrez donc un résultat mal formé. Utilisez plutôt ":raw" ou ":pop" pour supprimer les couches d'encodage.

:raw
La couche ":raw" est *définie* comme étant identique à l'appel de binmode($fh) : le flux est rendu approprié pour passer des données binaires, c'est-à-dire que chaque octet est passé tel quel. Le flux restera bufferisé (bien qu'il ne l'ait pas été avant Perl 5.14).

Dans Perl 5.6 et certains livres, la couche ":raw" est documentée comme étant l'inverse de la couche ":crlf". Ce n'est plus le cas : d'autres couches qui altèrent le caractère binaire du flux sont également désactivées. Si vous souhaitez avoir des fins de ligne UNIX sur un système qui effectue normalement la traduction CRLF, mais que vous souhaitez conserver les valeurs UTF-8 ou les défauts d'encodage, la chose à faire est d'ajouter ":perlio" à la variable d'environnement PERLIO, ou d'ouvrir explicitement le handle avec cette couche, pour remplacer les défauts du système.

:perlio
Une couche qui implémente la bufferisation à partir de zéro pour PerlIO. Elle offre un accès rapide à la bufferisation pour "sv_gets", qui implémente les fonctions de lecture de Perl (readline/<>) et tente en général de minimiser la copie de données.

Le ":perlio" insère une couche ":unix" sous lui-même pour effectuer des E/S de bas niveau.

PROPRIÉTÉS DES COUCHES

Les couches peuvent avoir des propriétés qui sont spécifiées avec un préfixe deux-points. Par exemple, ":crlf" a la propriété ":crlf" et ":raw" a la propriété ":raw".

Les propriétés sont spécifiques à chaque couche et sont utilisées pour indiquer comment la couche se comporte. Par exemple, ":raw" est utilisé pour empêcher le flux d'être bufferisé, et ":crlf" est utilisé pour traduire les fins de ligne.

NAME

PerlIO::Layers - PerlIO layer management

SYNOPSIS

  use PerlIO;

  # Example using layers within open()
  open(my $fh, ">:encoding(UTF-8)", $filename) or die ...;

  # Example using binmode()
  binmode($fh, ":perlio"); # Use the default perl IO layer

  # Example using a pseudo-layer
  binmode($fh, ":raw");

  # Example using a custom layer
  binmode($fh, ":via(Compress::Zlib)");

  # Getting the layers
  my @layers = PerlIO::get_layers($fh);
  my @output_layers = PerlIO::get_layers($fh, output => 1);

  # Getting layers with details
  my @details = PerlIO::get_layers($fh, details => 1);

DESCRIPTION

This module describes the PerlIO layer system and the built-in layers that are available.

PerlIO provides a framework for pluggable I/O layers. When you open a file, Perl uses a sequence of layers to read from or write to the filehandle. These layers can modify the data stream, for example by translating character encodings, compressing data, or switching between text and binary mode.

The layers are specified as a colon-separated string, either in the open() call or using the binmode() function. The order of the layers matters, as they are processed sequentially.

Built-in Layers

:crlf
Translates between carriage return/line feed ("\r\n") and line feed ("\n"). This is typically used on systems like DOS/Windows where text files are expected to use "\r\n" as line endings.
:dos
This is a synonym for ":crlf".
:unix
This is a synonym for ":perlio".
:perlio
The default layer on most Unix-like systems. It provides basic buffering and I/O operations.
:stdio
Uses the system's standard C library stdio functions (fopen, fread, etc.). This layer is often faster than :perlio" but is less portable and may have different buffering behavior.
:raw
This is a pseudo-layer that causes the layer stack to be reset to a minimal state, typically just the binary layer. It's primarily used to ensure that subsequent layers are applied to a raw binary stream, overriding any default translations or platform-specific behaviors. The implementation of ":raw" is as a pseudo-layer which when "pushed" pops itself and then any layers which would modify the binary data stream. (Undoing ":utf8" and ":crlf" may be implemented by clearing flags rather than popping layers but that is an implementation detail.)
As a consequence of the fact that ":raw" normally pops layers, it usually only makes sense to have it as the only or first element in a layer specification. When used as the first element it provides a known base on which to build e.g.
open(my $fh,">:raw:encoding(UTF-8)",...)
  or die "open failed: $!";
will construct a "binary" stream regardless of the platform defaults, but then enable UTF-8 translation.
:pop
A pseudo-layer that removes the top-most layer. Gives Perl code a way to manipulate the layer stack. Note that ":pop" only works on real layers and will not undo the effects of pseudo-layers or flags like ":utf8". An example of a possible use might be:
open(my $fh,...) or die "open failed: $!";
...
binmode($fh,":encoding(...)") or die "binmode failed: $!";
# next chunk is encoded
...
binmode($fh,":pop") or die "binmode failed: $!";
# back to un-encoded
A more elegant (and safer) interface is needed.

Custom Layers

It is possible to write custom layers in addition to the above builtin ones, both in C/XS and Perl, as a module named "PerlIO::<layer name>". Some custom layers come with the Perl distribution.

:encoding
Use :encoding(ENCODING) to transparently do character set and encoding transformations, for example from Shift-JIS to Unicode. Note that an ":encoding" also enables ":utf8". See PerlIO::encoding for more information.
:mmap
A layer which implements "reading" of files by using mmap() to make a (whole) file appear in the process's address space, and then using that as PerlIO's "buffer". This may be faster in certain circumstances for large files, and may result in less physical memory use when multiple processes are reading the same file.

Files which are not mmap()-able revert to behaving like the ":perlio" layer. Writes also behave like the ":perlio" layer, as mmap() for write needs extra house-keeping (to extend the file) which negates any advantage.

The ":mmap" layer will not exist if the platform does not support mmap(). See PerlIO::mmap for more information.

:via
:via(MODULE) allows a transformation to be applied by an arbitrary Perl module, for example compression / decompression, encryption / decryption. See PerlIO::via for more information.
:scalar
A layer implementing "in memory" files using scalar variables, automatically used in place of the platform defaults for IO when opening such a handle. As such, the scalar is expected to act like a file, only containing or storing bytes. See PerlIO::scalar for more information.

Alternatives to raw

To get a binary stream an alternate method is to use:

open(my $fh,"<","whatever") or die "open failed: $!";
binmode($fh) or die "binmode failed: $!";

This has the advantage of being backward compatible with older versions of Perl that did not use PerlIO or where ":raw" was buggy (as it was before Perl 5.14).

To get an unbuffered stream specify an unbuffered layer (e.g. ":unix") in the open call:

open(my $fh,"<:unix",$path) or die "open failed: $!";

Defaults and how to override them

If the platform is MS-DOS like and normally does CRLF to "\n" translation for text files then the default layers are:

:unix:crlf

Otherwise if "Configure" found out how to do "fast" IO using the system's stdio (not common on modern architectures), then the default layers are:

:stdio

Otherwise the default layers are

:unix:perlio

Note that the "default stack" depends on the operating system and on the Perl version, and both the compile-time and runtime configurations of Perl. The default can be overridden by setting the environment variable PERLIO to a space or colon separated list of layers, however this cannot be used to set layers that require loading modules like ":encoding".

This can be used to see the effect of/bugs in the various layers e.g.

cd .../perl/t
PERLIO=:stdio  ./perl harness
PERLIO=:perlio ./perl harness

For the various values of PERLIO see "PERLIO" in perlrun.

The following table summarizes the default layers on UNIX-like and DOS-like platforms and depending on the setting of $ENV{PERLIO}:

PERLIO     UNIX-like                   DOS-like
------     ---------                   --------
unset / "" :unix:perlio / :stdio [1]   :unix:crlf
:stdio     :stdio                      :stdio
:perlio    :unix:perlio                :unix:perlio
# [1] ":stdio" if Configure found out how to do "fast stdio" (depends
# on the stdio implementation) and in Perl 5.8, else ":unix:perlio"

Querying the layers of filehandles

The following returns the names of the PerlIO layers on a filehandle.

my @layers = PerlIO::get_layers($fh); # Or FH, *FH, "FH".

The layers are returned in the order an open() or binmode() call would use them, and without colons.

By default the layers from the input side of the filehandle are returned; to get the output side, use the optional "output" argument:

my @layers = PerlIO::get_layers($fh, output => 1);

(Usually the layers are identical on either side of a filehandle but for example with sockets there may be differences.)

There is no set_layers(), nor does get_layers() return a tied array mirroring the stack, or anything fancy like that. This is not accidental or unintentional. The PerlIO layer stack is a bit more complicated than just a stack (see for example the behaviour of ":raw"). You are supposed to use open() and binmode() to manipulate the stack.

Implementation details follow, please close your eyes.

The arguments to layers are by default returned in parentheses after the name of the layer, and certain layers (like ":utf8") are not real layers but instead flags on real layers; to get all of these returned separately, use the optional "details" argument:

my @layer_and_args_and_flags = PerlIO::get_layers($fh, details => 1);

The result will be up to be three times the number of layers: the first element will be a name, the second element the arguments (unspecified arguments will be "undef"), the third element the flags, the fourth element a name again, and so forth.
