NOM

Perl::Critic::Policy::ValuesAndExpressions::ProhibitCommaSeparatedStatements - Ne pas utiliser l'opérateur virgule comme séparateur d'instructions.

AFFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Le séparateur d'instructions virgule de Perl a une précédence très basse, ce qui conduit à du code qui ressemble à l'utilisation du séparateur d'éléments de liste virgule alors qu'il n'en est rien. Conway suggère de ne pas utiliser le séparateur d'instructions afin d'éviter cette situation.

La confusion causée par le séparateur d'instructions est principalement due au fait que les opérateurs d'affectation ont une précédence plus élevée.

Par exemple, essayer de combiner deux tableaux dans un autre comme ceci ne fonctionnera pas :

@x = @y, @z;

car cela est équivalent à

@x = @y;
@z;

Inversement, il existe des fonctions intégrées, comme "print", qui forcent normalement le reste de l'instruction dans un contexte de liste, mais ne le font pas lorsqu'elles sont appelées comme des sous-routines.

Il est peu probable que cela produise ce qui est attendu :

print join q{, }, 2, 3, 5, 7, ": the single-digit primes.\n";

La solution évidente est d'ajouter des parenthèses. Les placer comme

print join( q{, }, 2, 3, 5, 7 ), ": the single-digit primes.\n";

fonctionnera, mais

print ( join q{, }, 2, 3, 5, 7 ), ": the single-digit primes.\n";

ne fonctionnera pas, car cela est équivalent à

print( join q{, }, 2, 3, 5, 7 );
": the single-digit primes.\n";

CONFIGURATION

Cette politique peut être configurée pour autoriser la dernière instruction dans un bloc "map" ou "grep" à être séparée par une virgule. Ceci est fait via l'option "allow_last_statement_to_be_comma_separated_in_map_and_grep" comme ceci :

[ValuesAndExpressions::ProhibitCommaSeparatedStatements]
allow_last_statement_to_be_comma_separated_in_map_and_grep = 1

Avec cette option désactivée (par défaut), le code suivant enfreint cette politique.

%hash = map {$_, 1} @list;

Avec cette option activée, cette instruction est autorisée. Même si cette option est désactivée, l'utilisation d'une virgule grasse "=>" fonctionne, mais cela force la stringification de la première valeur, ce qui n'est peut-être pas ce que vous voulez.

BOGUES

Doit vérifier "scalar( something, something )".
