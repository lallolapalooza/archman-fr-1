Perl::Critic::Policy::Variables::ProhibitAugmentedAssignmentInDeclaration(3pm) Documentation Perl fournie par la communauté Perl::Critic::Policy::Variables::ProhibitAugmentedAssignmentInDeclaration(3pm)

NOM

Perl::Critic::Policy::Variables::ProhibitAugmentedAssignmentInDeclaration - Ne pas écrire " my $foo .= 'bar'; ".

AFFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Les déclarations de variables qui font également l'initialisation avec '=' sont courantes. Perl permet également d'utiliser des opérateurs comme '.=', '+=', etc., mais il est plus clair de ne pas le faire.

my $foo .= 'bar';              # identique à my $foo = 'bar';
our $foo *= 2;                 # identique à our $foo = 0;
my ( $foo, $bar ) += ( 1, 2 ); # identique à my ( $foo, $bar ) = ( undef, 2 );
local $Carp::CarpLevel += 1;   # identique à local $Carp::CarpLevel = 1;
state $foo += 2;               # ajoute 2 à chaque fois qu'il est rencontré

De telles constructions sont généralement le résultat d'un copier-coller raté, et sont souvent des bugs. Certaines génèrent des avertissements.

CONFIGURATION

Il existe une option booléenne "allow_our" pour cette politique. Si elle est définie, les affectations augmentées sont autorisées lors de la déclaration des variables "our". Comme les variables "our" sont globalement accessibles, certains modules voudront permettre aux utilisateurs d'initialiser la variable avant que le module n'utilise la variable. Les modules peuvent également souhaiter utiliser la même variable `our` dans différentes portées sans la déclarer dans la portée externe.

Avec cette option activée, les éléments suivants sont signalés comme indiqué :

our $DEBUG //= 1;           # ok

Cela peut être activé dans votre fichier .perlcriticrc :

[Perl::Critic::Policy::Variables::ProhibitAugmentedAssignmentInDeclaration]
allow_our = 1
