NOM

Perl::Critic::Policy::Modules::ProhibitExcessMainComplexity - Minimiser la complexité dans le code qui est extérieur aux sous-programmes.

AFFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

À conditions égales par ailleurs, un code complexe est plus sujet aux erreurs et plus coûteux à maintenir qu'un code plus simple. La première étape pour gérer la complexité est d'établir des métriques de complexité formelles. Une de ces métriques est le score de McCabe, qui décrit le nombre de chemins possibles à travers un bloc de code. Cette politique approxime le score de McCabe en additionnant le nombre d'instructions conditionnelles et d'opérateurs à l'intérieur d'un bloc de code. Des recherches ont montré qu'un score de McCabe supérieur à 20 est un signe de code à haut risque, potentiellement non testable. Voir http://en.wikipedia.org/wiki/Cyclomatic_complexity pour une discussion sur le nombre de McCabe et d'autres métriques de complexité.

Alors que Perl::Critic::Policy::Subroutines::ProhibitExcessComplexity évalue la complexité de chaque sous-programme, cette politique évalue la complexité totale de tout le code qui se trouve en dehors de toute déclaration de sous-programme.

La prescription habituelle pour réduire la complexité est de refactoriser le code en sous-programmes plus petits. Le livre de Mark Dominus, « Higher Order Perl », décrit également les rappels, la récursion, la mémoïsation, les itérateurs et d'autres techniques qui aident à créer un code Perl simple et extensible.

CONFIGURATION

Le score de McCabe maximum acceptable peut être défini avec l'élément de configuration "max_mccabe".

Si la somme de tout le code en dehors de tout sous-programme a un score de McCabe supérieur à ce nombre, cela générera une violation de la politique. La valeur par défaut est 20. Un exemple de section pour un .perlcriticrc :

[Modules::ProhibitExcessMainComplexity]
max_mccabe = 30

NOTES

"Tout devrait être rendu aussi simple que possible, mais pas plus simple."
                                                -- Albert Einstein

La complexité est subjective, mais les métriques de complexité formelles sont toujours incroyablement utiles. Chaque problème a un niveau de complexité inhérent, il n'est donc pas nécessairement optimal de minimiser le nombre de McCabe. Ne vous offusquez donc pas si votre code déclenche cette politique. Demandez-vous simplement s'il pourrait y avoir un moyen plus simple de faire le travail.
