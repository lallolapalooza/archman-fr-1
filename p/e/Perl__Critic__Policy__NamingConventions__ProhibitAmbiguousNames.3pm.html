Perl__Critic__Policy__NamingConventions__ProhibitAmbiguousNames(3pm)

Perl::Critic::Policy::NamingConventions::ProhibitAmbiguousNames(3pm) Documentation Perl contribuée par les utilisateurs Perl::Critic::Policy::NamingConventions::ProhibitAmbiguousNames(3pm)

NOM

Perl::Critic::Policy::NamingConventions::ProhibitAmbiguousNames - N'utilisez pas de noms de variables ou de sous-routines ambigus comme 'last' ou 'record'.

AFFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Conway liste une collection de mots anglais qui sont très ambigus comme noms de variables ou de sous-routines. Par exemple, $last peut signifier précédent ou final.

Cette politique vérifie une liste de mots ambigus pour les noms de variables.

CONFIGURATION

La liste par défaut de mots interdits est :

abstract bases close contract last left no record right second set

Cette liste peut être modifiée en donnant une valeur pour "forbid" qui est une série de mots interdits séparés par des espaces.

Par exemple, si vous décidez que "bases" est un nom acceptable pour les variables (par exemple, en bioinformatique), alors mettez quelque chose comme ce qui suit dans "$HOME/.perlcriticrc" :

[NamingConventions::ProhibitAmbiguousNames]
forbid = last set left right no abstract contract record second close

BOGUES

Actuellement, cette politique vérifie la variable entière et le nom de la sous-routine, pas des parties du nom. Par exemple, elle attrape $last mais pas $last_record. Espérons que les futures versions attraperont les deux cas.

Certaines instructions de variables provoqueront des faux positifs si elles ont des affectations où le côté droit utilise des noms interdits. Par exemple, dans ce cas, "last" déclenche incorrectement une violation.

my $previous_record = $Foo::last;
