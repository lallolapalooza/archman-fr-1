Perl::Critic::Policy::Variables::RequireLexicalLoopIterators(3pm) Documentation Perl fournie par l'utilisateur Perl::Critic::Policy::Variables::RequireLexicalLoopIterators(3pm)

NOM

Perl::Critic::Policy::Variables::RequireLexicalLoopIterators - Écrire "for my $element (@liste) {...}" au lieu de "for $element (@liste) {...}".

AFILIIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Cette politique vous demande d'utiliser des variables d'itérateur de boucle lexicales de style "my":

foreach my $zed (...) {
    ...
}

Sauf si vous utilisez "my", les boucles "for"/"foreach" utilisent une variable globale dont la valeur est "local" au bloc. En d'autres termes,

foreach $zed (...) {
    ...
}

est plus ou moins équivalent à

{
    local $zed
    foreach $zed (...) {
        ...
    }
}

Cela peut ne pas sembler être un grand problème jusqu'à ce que vous voyiez du code comme

my $velo;
for $velo (@choses_attachees_au_porte-bagages) {
    if (
            $velo->est_rouge()
        and $velo->a_carte_de_baseball_dans_les_rayons()
        and $velo->a_béquille_pliée()
    ) {
        $velo->retirer_verrou();
        last;
    }
}
if ( $velo and $velo->est_deverrouille() ) {
    rentrer_a_la_maison($velo);
}

qui ne vous permettra pas d'arriver à temps pour dîner avec votre famille car le $velo extérieur à la boucle n'est pas modifié par la boucle. Vous avez peut-être déverrouillé votre vélo, mais vous ne vous souvenez pas duquel il s'agissait.

Les variables de boucle lexicales ont été introduites dans Perl 5.004. Cette politique ne signale pas de violations sur le code qui spécifie explicitement une version antérieure de Perl (par exemple, "require 5.002;").

CONFIGURATION

Cette politique n'est configurable qu'avec les options standard.
