NOM

Perl::Critic::Policy::RegularExpressions::ProhibitCaptureWithoutTest - Variable de capture utilisée en dehors d'une condition.

AFILATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Si une correspondance d'expression régulière échoue, alors toutes les variables de capture ($1, $2, ...) ne seront pas affectées. Elles conserveront les anciennes valeurs qu'elles pourraient avoir. Il est donc important de vérifier la valeur de retour d'une correspondance avant d'utiliser ces variables.

'12312123' =~ /(2)/;
print $1;    # Affiche 2
'123123123' =~ /(X)/;
print $1;    # Affiche 2, car $1 n'a pas changé.

Notez que puisque les valeurs de $1 etc. ne seront pas affectées, vous ne pouvez pas déterminer si une correspondance a réussi en vérifiant si les variables de capture ont des valeurs.

# FAUX
$str =~ /foo(.+)/;
if ( $1 ) {
    print "J'ai trouvé $1 après 'foo'";
}

Cette politique vérifie que l'expression régulière précédente pour laquelle la variable de capture est dans la portée est soit dans une condition, soit provoque une exception ou un autre transfert de contrôle (c'est-à-dire "next", "last", "redo", "return", ou parfois "goto") si la correspondance échoue.

Un "goto" est seulement accepté par cette politique s'il s'agit d'un appel de coroutine (c'est-à-dire "goto &foo") ou d'un "goto LABEL" où l'étiquette ne se trouve pas entre le "goto" et la variable de capture dans la portée du "goto". Un "goto" calculé (c'est-à-dire quelque chose comme "goto (qw{foo bar baz})[$i]") n'est pas accepté par cette politique car sa cible ne peut pas être déterminée statiquement.

Cette politique ne vérifie pas si cette condition teste réellement le résultat d'une expression régulière, ni si une expression régulière contient réellement une capture. Ces vérifications sont trop difficiles.

Cette politique ne vérifie pas non plus les conditions arbitrairement complexes qui protègent les résultats des expressions régulières, à peu près pour la même raison. Les choses simples comme

m/(foo)/ or die "Pas de foo !";
die "Pas de foo !" unless m/(foo)/;

seront gérées, mais quelque chose comme

m/(foo)/ or do {
  ... beaucoup de calculs compliqués ici ...
  die "Pas de foo !";
};

est hors de sa portée.

CONFIGURATION

Par défaut, cette politique considère "die", "croak", et "confess" comme lançant des exceptions. Si vous avez des sous-programmes ou méthodes supplémentaires qui peuvent être utilisés à la place de l'un de ceux-ci, vous pouvez les configurer dans votre perlcriticrc comme suit :

[RegularExpressions::ProhibitCaptureWithoutTest]
exception_source = my_exception_generator

BOGUES

Cette politique ne reconnaît pas les variables de capture nommées. Pas encore.
