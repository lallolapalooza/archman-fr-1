PerlIO::via(3perl) Guide de référence du programmeur Perl PerlIO::via(3perl)

NOM

PerlIO::via - Classe d'aide pour les couches PerlIO implémentées en Perl

SYNOPIS

use PerlIO::via::Layer;
open($fh,"<:via(Layer)",...);
use Some::Other::Package;
open($fh,">:via(Some::Other::Package)",...);

DESCRIPTION

Le module PerlIO::via vous permet de développer des couches PerlIO en Perl, sans avoir à entrer dans les détails de la programmation en C avec XS comme interface vers Perl.

Un exemple de module, PerlIO::via::QuotedPrint, est inclus avec Perl 5.8.0, et d'autres exemples de modules sont disponibles sur CPAN, tels que PerlIO::via::StripHTML et PerlIO::via::Base64. Le module PerlIO::via::StripHTML par exemple, vous permet de dire :

use PerlIO::via::StripHTML;
open( my $fh, "<:via(StripHTML)", "index.html" );
my @line = <$fh>;

pour obtenir le texte d'un fichier HTML dans un tableau avec toutes les balises HTML automatiquement supprimées.

Veuillez noter que si la couche est créée dans l'espace de noms PerlIO::via::, elle n'a pas besoin d'être entièrement qualifiée. Le module PerlIO::via préfixera l'espace de noms PerlIO::via:: si le nom du module spécifié n'existe pas en tant que nom de module entièrement qualifié.

MÉTHODES ATTENDUES

Pour créer un module Perl qui implémente une couche PerlIO en Perl (par opposition à une implémentation en C utilisant XS comme interface vers Perl), vous devez fournir certaines des sous-routines suivantes. Il est recommandé de créer ces modules Perl dans l'espace de noms PerlIO::via::, afin qu'ils puissent être facilement trouvés sur CPAN et utiliser la fonctionnalité d'espace de noms par défaut du module PerlIO::via lui-même.

Veuillez noter qu'il s'agit d'un domaine de développement récent en Perl et que l'interface décrite ici est donc susceptible de changer (et espérons qu'elle aura une meilleure documentation et plus d'exemples).

Dans les descriptions des méthodes ci-dessous, $fh sera une référence à un glob qui peut être traité comme une poignée de fichier Perl. Il fait référence à la couche en dessous. $fh n'est pas passé si la couche est en bas de la pile, pour cette raison et pour maintenir un certain niveau de "compatibilité" avec les classes TIEHANDLE, il est passé en dernier.

Détail : $class->PUSHED([$mode,[$fh]])
Doit retourner un objet ou la classe, ou -1 en cas d'échec. (Comparer à TIEHANDLE.) Les arguments sont une chaîne de mode optionnelle ("r", "w", "w+", ...) et une poignée de fichier pour la couche PerlIO en dessous. Obligatoire.

Lorsque la couche est empilée dans le cadre d'un appel "open", "PUSHED" sera appelé *avant* que l'ouverture réelle n'ait lieu, que ce soit via "OPEN", "SYSOPEN", "FDOPEN" ou en laissant une couche inférieure effectuer l'ouverture.

Détail : $obj->POPPED([$fh])
Optionnel - appelé lorsque la couche est sur le point d'être supprimée.
Détail : $obj->UTF8($belowFlag,[$fh])
Optionnel - s'il est présent, il sera appelé immédiatement après le retour de PUSHED. Il doit retourner une valeur vraie si la couche attend des données encodées en UTF-8. S'il retourne vrai, le résultat est comme si l'appelant avait fait 
":via(YourClass):utf8"

S'il n'est pas présent ou s'il retourne faux, le flux est laissé avec le drapeau UTF-8 désactivé. L'argument $belowFlag sera vrai s'il existe une couche en dessous et que cette couche attendait de l'UTF-8.

Détail : $obj->OPEN($path,$mode,[$fh])
Optionnel - s'il n'est pas présent, une couche inférieure effectue l'ouverture. S'il est présent, est appelé pour les ouvertures normales après que la couche est empilée. Cette fonction est sujette à modification car il n'y a pas de moyen facile d'amener une couche inférieure à effectuer l'ouverture puis à reprendre le contrôle.
Détail : $obj->BINMODE([$fh])
Optionnel - s'il n'est pas présent, la couche est dépilée lors de binmode($fh) ou lorsque ":raw" est empilé. S'il est présent, il doit retourner 0 en cas de succès, -1 en cas d'erreur, ou undef pour dépiler la couche.
Détail : $obj->FDOPEN($fd,[$fh])
Optionnel - s'il n'est pas présent, une couche inférieure effectue l'ouverture. S'il est présent, est appelé après que la couche est empilée pour les ouvertures qui passent un descripteur de fichier numérique. Cette fonction est sujette à modification car il n'y a pas de moyen facile d'amener une couche inférieure à effectuer l'ouverture puis à reprendre le contrôle.
Détail : $obj->SYSOPEN($path,$imode,$perm,[$fh])
Optionnel - s'il n'est pas présent, une couche inférieure effectue l'ouverture. S'il est présent, est appelé après que la couche est empilée pour les ouvertures de style sysopen qui passent un mode numérique et des permissions. Cette fonction est sujette à modification car il n'y a pas de moyen facile d'amener une couche inférieure à effectuer l'ouverture puis à reprendre le contrôle.
Détail : $obj->FILENO($fh)
Retourne une valeur numérique pour un descripteur de fichier de type Unix. Retourne -1 s'il n'y en a pas. Optionnel. La valeur par défaut est fileno($fh).
Détail : $obj->READ($buffer,$len,$fh)
Retourne le nombre d'octets placés dans $buffer (doit être undef pour indiquer une erreur ou un entier non négatif inférieur ou égal au minimum de $len et de la longueur du $buffer mis à jour). Optionnel. Par défaut, utilise FILL à la place.
Détail : $obj->WRITE($buffer,$fh)
Retourne le nombre d'octets de $buffer qui ont été écrits avec succès.
Détail : $obj->FILL($fh)
Doit retourner une chaîne à placer dans le tampon. Optionnel. Si non fournie, doit fournir READ ou rejeter les poignées ouvertes en lecture dans PUSHED.
Détail : $obj->CLOSE($fh)
Doit retourner 0 en cas de succès, -1 en cas d'erreur. Optionnel.
Détail : $obj->SEEK($posn,$whence,$fh)
Doit retourner 0 en cas de succès, -1 en cas d'erreur. Optionnel. Par défaut, échoue, mais cela sera probablement modifié à l'avenir.
Détail : $obj->TELL($fh)
Retourne la position du fichier. Optionnel. Par défaut à déterminer.
Détail : $obj->UNREAD($buffer,$fh)
Retourne le nombre d'octets de $buffer qui ont été sauvegardés avec succès pour être retournés lors des futurs appels FILL/READ. Optionnel. Par défaut, les données sont poussées dans une couche temporaire au-dessus de celle-ci.
Détail : $obj->FLUSH($fh)
Vide toutes les données d'écriture mises en mémoire tampon. Peut potentiellement être appelé sur des poignées lisibles également. Doit retourner 0 en cas de succès, -1 en cas d'erreur.
Détail : $obj->SETLINEBUF($fh)
Optionnel. Pas de retour.
Détail : $obj->CLEARERR($fh)
Optionnel. Pas de retour.
Détail : $obj->ERROR($fh)
Optionnel. Retourne l'état d'erreur. Par défaut, aucune erreur jusqu'à ce qu'un mécanisme de signalisation d'erreur (die ?) soit mis au point.
Détail : $obj->EOF($fh)
Optionnel. Retourne l'état de fin de fichier. Par défaut, est une fonction de la valeur de retour de FILL ou READ.

EXEMPLES

Vérifiez l'espace de noms PerlIO::via sur CPAN pour des exemples de couches PerlIO implémentées en Perl. Pour vous donner une idée de la simplicité de l'implémentation d'une couche PerlIO, un exemple simple est inclus ici.

Exemple - une poignée hexadécimale

Étant donné le module suivant, PerlIO::via::Hex :

package PerlIO::via::Hex;
sub PUSHED
{
 my ($class,$mode,$fh) = @_;
 # Lors de l'écriture, nous mettons en mémoire tampon les données
 my $buf = '';
 return bless \$buf,$class;
}
sub FILL
{
 my ($obj,$fh) = @_;
 my $line = <$fh>;
 return (defined $line) ? pack("H*", $line) : undef;
}
sub WRITE
{
 my ($obj,$buf,$fh) = @_;
 $$obj .= unpack("H*", $buf);
 return length($buf);
}
sub FLUSH
{
 my ($obj,$fh) = @_;
 print $fh $$obj or return -1;
 $$obj = '';
 return 0;
}
1;

Le code suivant ouvre une poignée de sortie qui convertira toute sortie en un vidage hexadécimal des octets de sortie : par exemple "A" sera converti en "41" (sur les machines basées sur ASCII, sur les plateformes EBCDIC le "A" deviendra "c1")

use PerlIO::via::Hex;
open(my $fh, ">:via(Hex)", "foo.hex");

et le code suivant lira le hexdump et le convertira à la volée en octets :

open(my $fh, "<:via(Hex)", "foo.hex");
