Perl::Critic::Policy::BuiltinFunctions::ProhibitShiftRef(3pm) Documentation Perl fournie par l'utilisateur Perl::Critic::Policy::BuiltinFunctions::ProhibitShiftRef(3pm)

NOM

Perl::Critic::Policy::BuiltinFunctions::ProhibitShiftRef - Interdire "\shift" dans le code

AFFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Interdire l'utilisation de "\shift", car il est associé à des bugs dans Perl et ses modules.

Contexte

Souvent, "\shift" est utilisé pour créer des références qui agissent de manière similaire à un alias. En créant un "alias" nommé, le code devient plus lisible. Par exemple,

sub routine {
    my $longstring = \shift;
    print $$longstring;
}

est plus lisible que

sub routine {
    print $_[0];    # longstring
}

Malheureusement, cette lisibilité accrue apporte avec elle de nouveaux et passionnants problèmes, détaillés dans la section suivante.

Problèmes avec "\shift"

En évitant "\shift", plusieurs problèmes dans Perl peuvent être évités, notamment :

Fuite de mémoire depuis Perl 5.22
Le problème #126676 a été introduit dans Perl 5.21.4 et est déclenché lorsque "\shift" est utilisé. Le bug n'a pas été résolu à partir de Perl 5.28.

En bref, le bug provoque l'incrémentation du compteur de références pour la variable aliasée lors de l'exécution de la sous-routine, mais il n'est pas décrémenté par la suite après le retour de la sous-routine. En plus de fuir de la mémoire, ce problème peut également retarder le nettoyage des objets jusqu'à la Destruction Globale, ce qui peut entraîner d'autres problèmes.

Pour plus d'informations, voir https://rt.perl.org/Public/Bug/Display.html?id=126676.

Plantages de Devel::Cover
Un problème distinct et de longue date dans Devel::Cover (depuis au moins 1.21) provoque des crashs occasionnels du code de test. Cela empêche l'écriture des données de couverture, ce qui donne de mauvaises métriques.

Le bug lui-même n'est pas réellement causé par "\shift", il apparaît plutôt dans du code comme suit :

sub myopen {
    open ${ \$_[0] }, ">test";
}

Cependant, ce code serait rarement vu en production. Il se manifesterait plus probablement avec "\shift", comme c'est le cas ci-dessous :

sub myopen {
    my $fh = \shift;
    open $$fh, ">test";
}

Donc, bien que "\shift" ne soit pas la cause, il est souvent associé au problème.

Pour plus d'informations, voir https://github.com/pjcj/Devel--Cover/issues/125.

CONFIGURATION

Cette politique n'est pas configurable, à l'exception des options standard.
