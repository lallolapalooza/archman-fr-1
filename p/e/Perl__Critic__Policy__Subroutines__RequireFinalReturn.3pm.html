Perl::Critic::Policy::Subroutines::RequireFinalReturn(3pm) Documentation Perl fournie par l'utilisateur Perl::Critic::Policy::Subroutines::RequireFinalReturn(3pm)

NOM

Perl::Critic::Policy::Subroutines::RequireFinalReturn - Terminer chaque chemin d'une sous-routine par une instruction "return" explicite.

AFILIATION

Cette politique fait partie de la distribution principale de Perl::Critic.

DESCRIPTION

Exige que toutes les sous-routines se terminent explicitement par l'une des instructions suivantes : "return", "carp", "croak", "die", "exec", "exit", "goto", ou "throw".

Les sous-routines sans instruction de retour explicite à leur fin peuvent être déroutantes. Il peut être difficile de déduire quelle sera la valeur de retour.

De plus, si le programmeur n'avait pas l'intention d'avoir une valeur de retour significative et omet une instruction de retour, une partie des données internes de la sous-routine peut fuir vers l'extérieur. Considérez ce cas :

package Password;
# chaque fois que l'utilisateur devine mal le mot de passe, sa valeur
# est tournée d'un caractère
my $password;
sub set_password {
    $password = shift;
}
sub check_password {
    my $guess = shift;
    if ($guess eq $password) {
        unlock_secrets();
    } else {
        $password = (substr $password, 1).(substr $password, 0, 1);
    }
}
1;

Dans ce cas, la dernière instruction de check_password() est l'affectation. Le résultat de cette affectation est la valeur de retour implicite, donc une mauvaise supposition renvoie le bon mot de passe ! Ajouter un "return;" à la fin de cette sous-routine résout le problème.

La seule exception autorisée est une sous-routine vide.

Soyez prudent lorsque vous corrigez les problèmes identifiés par cette politique ; ne mettez pas aveuglément une instruction "return;" à la fin de chaque sous-routine.

CONFIGURATION

Si vous avez créé vos propres fonctions terminales qui se comportent comme "die" ou "exit", vous pouvez configurer Perl::Critic pour reconnaître ces fonctions également. Il suffit de mettre quelque chose comme ceci dans votre .perlcriticrc :

[Subroutines::RequireFinalReturn]
terminal_funcs = quit abort bailout

Si vous avez créé vos propres méthodes terminales, vous pouvez configurer Perl::Critic pour les reconnaître également, mais la classe ne sera pas prise en compte. Par exemple, si vous définissez throw_exception comme terminal, alors toute méthode de ce nom sera terminale, quelle que soit sa classe. Il suffit de mettre quelque chose comme ceci dans votre .perlcriticrc :

[Subroutines::RequireFinalReturn]
terminal_methods = throw_exception

BOGUES

Nous ne recherchons pas les retours dans les opérateurs ternaires. Cette construction est trop compliquée à analyser pour le moment. De plus, une meilleure forme est le retour en dehors du ternaire comme ceci : "return foo ? 1 : bar ? 2 : 3"
