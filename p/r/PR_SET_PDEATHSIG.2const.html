PR_SET_PDEATHSIG(2const) PR_SET_PDEATHSIG(2const)

NOM

PR_SET_PDEATHSIG - définir le signal de décès du parent du processus appelant

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/prctl.h>  /* Définition des constantes PR_* */
#include <sys/prctl.h>
int prctl(PR_SET_PDEATHSIG, long sig);

DESCRIPTION

Définit le signal de décès du parent du processus appelant à sig (soit une valeur de signal dans la plage [1, NSIG - 1], soit 0 pour effacer). C'est le signal que le processus appelant recevra lorsque son parent mourra.

Le signal de décès du parent est envoyé lors de la terminaison subséquente du thread parent et également lors de la terminaison de chaque processus sous-réapsack (voir PR_SET_CHILD_SUBREAPER(2const)) auquel l'appelant est ultérieurement rattaché. Si le thread parent et tous les ancêtres sous-réapsack ont déjà été terminés au moment de l'opération PR_SET_PDEATHSIG, aucun signal de décès de parent n'est envoyé à l'appelant.

Le signal de décès du parent est dirigé vers le processus (voir signal(7)) et, si l'enfant installe un gestionnaire à l'aide de l'indicateur SA_SIGINFO de sigaction(2), le champ si_pid de l'argument siginfo_t du gestionnaire contient le PID du processus parent terminé.

Le paramètre du signal de décès du parent est effacé pour l'enfant d'un fork(2). Il est également (depuis Linux 2.4.36 / 2.6.23) effacé lors de l'exécution d'un binaire set-user-ID ou set-group-ID, ou d'un binaire qui a des capacités associées (voir capabilities(7)) ; sinon, cette valeur est conservée lors des execve(2). Le paramètre du signal de décès du parent est également effacé lors des changements de l'un des identifiants suivants du thread : identifiant utilisateur effectif, identifiant groupe effectif, identifiant utilisateur du système de fichiers, ou identifiant groupe du système de fichiers.

VALEUR DE RETOUR

En cas de succès, 0 est retourné. En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

EINVAL
sig n'est pas un numéro de signal valide.

NORMES

Linux.

HISTORIQUE

Linux 2.1.57.

AVERTISSEMENTS

Le "parent" dans ce cas est considéré comme le thread qui a créé ce processus. En d'autres termes, le signal sera envoyé lorsque ce thread se terminera (par exemple, via pthread_exit(3)), plutôt qu'après la terminaison de tous les threads dans le processus parent.

VOIR AUSSI

prctl(2), PR_GET_PDEATHSIG(2const)
