PR_SET_FP_MODE(2const) PR_SET_FP_MODE(2const)

NOM

PR_SET_FP_MODE - définit le mode virgule flottante du processus appelant

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <linux/prctl.h>  /* Définition des constantes PR_* */
#include <sys/prctl.h>
int prctl(PR_SET_FP_MODE, unsigned long mode);

DESCRIPTION

Sur l'architecture MIPS, le code utilisateur peut être compilé en utilisant un ABI qui permet de lier avec du code ayant des exigences plus restrictives en virgule flottante (FP). Par exemple, le code utilisateur peut être compilé pour cibler l'ABI O32 FPXX et lié avec du code compilé pour l'un des ABI plus restrictifs FP32 ou FP64. Lorsque du code plus restrictif est lié, l'exigence globale pour le processus est d'utiliser le mode virgule flottante le plus restrictif.

Étant donné que le noyau n'a aucun moyen de savoir à l'avance dans quel mode le processus doit être exécuté, et que ces restrictions peuvent changer au cours de la vie du processus, l'opération PR_SET_FP_MODE est fournie pour permettre le contrôle du mode virgule flottante depuis l'espace utilisateur.

L'argument mode est un masque de bits décrivant le mode de virgule flottante utilisé :

PR_FP_MODE_FR
Lorsque ce bit est non défini (mode dit FR=0 ou FR0), les 32 registres virgule flottante ont une largeur de 32 bits, et les registres de 64 bits sont représentés comme une paire de registres (numéro pair et impair, le registre de numéro pair contenant les 32 bits inférieurs, et le registre de numéro impair contenant les 32 bits supérieurs).
Lorsque ce bit est défini (sur du matériel pris en charge), les 32 registres virgule flottante ont une largeur de 64 bits (mode dit FR=1 ou FR1). Notez que les implémentations MIPS modernes (MIPS R6 et plus récent) ne prennent en charge que le mode FR=1.
Les applications qui utilisent l'ABI O32 FP32 ne peuvent fonctionner que lorsque ce bit est non défini (FR=0 ; ou elles peuvent être utilisées avec FRE activé, voir ci-dessous). Les applications qui utilisent l'ABI O32 FP64 (et l'ABI O32 FP64A, qui existe pour fournir la capacité d'opérer avec du code FP32 existant ; voir ci-dessous) ne peuvent fonctionner que lorsque ce bit est défini (FR=1). Les applications qui utilisent l'ABI O32 FPXX peuvent fonctionner avec FR=0 ou FR=1.
PR_FP_MODE_FRE
Active l'émulation du mode virgule flottante 32 bits. Lorsque ce mode est activé, il émule les opérations virgule flottante 32 bits en générant une exception d'instruction réservée sur chaque instruction qui utilise des formats 32 bits et le noyau gère alors l'instruction en logiciel. (Le problème réside dans la divergence de la gestion des registres à numéros impairs qui sont les 32 bits supérieurs des registres 64 bits avec des numéros pairs en mode FR=0 et les parties inférieures de 32 bits des registres à numéros impairs de 64 bits en mode FR=1.) L'activation de ce bit est nécessaire lorsque du code avec l'ABI O32 FP32 doit opérer avec du code avec des ABI O32 FPXX ou O32 FP64A compatibles (qui nécessitent le mode FPU FR=1) ou lorsqu'il est exécuté sur du matériel plus récent (MIPS R6 et supérieur) qui ne prend pas en charge le mode FR=0 lorsqu'un binaire avec l'ABI FP32 est utilisé.
Notez que ce mode n'a de sens que lorsque le FPU est en mode 64 bits (FR=1).
Notez que l'utilisation de l'émulation a intrinsèquement un impact significatif sur les performances et doit être évitée si possible.

Dans les ABI N32/N64, le mode virgule flottante 64 bits est toujours utilisé, donc l'émulation FPU n'est pas nécessaire et le FPU opère toujours en mode FR=1.

Cette opération est principalement destinée à être utilisée par le lieur dynamique (ld.so(8)).

VALEUR DE RETOUR

En cas de succès, 0 est retourné. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EOPNOTSUPP
mode a une valeur invalide ou non prise en charge.

NORMES

Linux. MIPS uniquement.

HISTORIQUE

Linux 4.0 (MIPS).

VOIR AUSSI

prctl(2), PR_GET_FP_MODE(2const)
