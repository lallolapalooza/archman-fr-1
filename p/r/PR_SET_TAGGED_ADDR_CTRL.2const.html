PR_SET_TAGGED_ADDR_CTRL(2const) PR_SET_TAGGED_ADDR_CTRL(2const)

NOM

PR_SET_TAGGED_ADDR_CTRL - contrôler la prise en charge du passage d'adresses de l'espace utilisateur étiquetées au noyau

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/prctl.h>  /* Définition des constantes PR_* */
#include <sys/prctl.h>
int prctl(PR_SET_TAGGED_ADDR_CTRL, long mode, 0L, 0L, 0L);

DESCRIPTION

Contrôle la prise en charge du passage d'adresses de l'espace utilisateur étiquetées au noyau (c'est-à-dire, des adresses où les bits 56 à 63 ne sont pas tous à zéro).

Le niveau de prise en charge est sélectionné par support, qui peut être l'une des valeurs suivantes :

0L
Les adresses passées dans le but d'être déréférencées par le noyau doivent être non étiquetées.
PR_TAGGED_ADDR_ENABLE
Les adresses passées dans le but d'être déréférencées par le noyau peuvent être étiquetées, à l'exception des exceptions résumées ci-dessous.

En cas de succès, le mode spécifié dans mode est défini pour le thread appelant.

Si prctl(PR_SET_TAGGED_ADDR_CTRL, 0L, 0L, 0L, 0L) échoue avec EINVAL, alors toutes les adresses passées au noyau doivent être non étiquetées.

Indépendamment du mode défini, les adresses passées à certaines interfaces doivent toujours être non étiquetées :

•
brk(2), mmap(2), shmat(2), shmdt(2), et l'argument new_address de mremap(2).
(Avant Linux 5.6, ces appels acceptaient des adresses étiquetées, mais le comportement pourrait ne pas être celui que vous attendez. Ne vous y fiez pas.)
•
Interfaces ‘polymorphiques’ qui acceptent des pointeurs vers des types arbitraires castés en void * ou un autre type générique, spécifiquement prctl(), ioctl(2), et généralement setsockopt(2) (seules certaines options spécifiques de setsockopt(2) autorisent les adresses étiquetées).

Cette liste d'exclusions peut diminuer lors du passage d'une version du noyau à une version ultérieure. Bien que le noyau puisse faire certaines garanties pour des raisons de compatibilité descendante, pour les logiciels nouveaux, l'effet du passage d'adresses étiquetées à ces interfaces est non spécifié.

Le mode défini par cet appel est hérité par fork(2) et clone(2). Le mode est réinitialisé par execve(2) à 0 (c'est-à-dire, les adresses étiquetées ne sont pas autorisées dans l'ABI utilisateur/noyau).

VALEUR DE RETOUR

En cas de succès, 0 est renvoyé. En cas d'erreur, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

ERREURS

EINVAL
mode est invalide ou non pris en charge.
EINVAL
Cette fonctionnalité est désactivée via /proc/sys/abi/tagged_addr_disabled.

FICHIERS

/proc/sys/abi/tagged_addr_disabled

NORMES

Linux. arm64 uniquement.

HISTORIQUE

Linux 5.4 (arm64).

ATTENTION

Cet appel est principalement destiné à être utilisé par l'environnement d'exécution. Un appel réussi à PR_SET_TAGGED_ADDR_CTRL ailleurs peut faire planter le processus appelant. Les conditions d'utilisation sûre sont complexes et dépendent du système. Ne l'utilisez pas à moins de savoir ce que vous faites.

VOIR AUSSI

prctl(2), PR_SET_TAGGED_ADDR_CTRL(2const)

Pour plus d'informations, voir le fichier source du noyau Documentation/arm64/tagged-address-abi.rst.
