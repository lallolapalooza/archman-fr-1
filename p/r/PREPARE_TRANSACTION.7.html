NOM

PREPARE TRANSACTION - préparer la transaction courante pour un commit en deux phases

SYNTAXE

PREPARE TRANSACTION identifiant_transaction

DESCRIPTION

PREPARE TRANSACTION prépare la transaction courante pour un commit en deux phases. Après cette commande, la transaction n'est plus associée à la session courante ; son état est entièrement stocké sur disque, et il y a une très forte probabilité qu'elle puisse être validée avec succès, même si un crash de la base de données survient avant que le commit ne soit demandé.

Une fois préparée, une transaction peut être ultérieurement validée ou annulée avec COMMIT PREPARED ou ROLLBACK PREPARED, respectivement. Ces commandes peuvent être émises depuis n'importe quelle session, pas seulement celle qui a exécuté la transaction originale.

Du point de vue de la session émettrice, PREPARE TRANSACTION n'est pas sans rappeler une commande ROLLBACK : après son exécution, il n'y a plus de transaction courante active, et les effets de la transaction préparée ne sont plus visibles. (Les effets redeviendront visibles si la transaction est validée.)

Si la commande PREPARE TRANSACTION échoue pour une raison quelconque, elle devient un ROLLBACK : la transaction courante est annulée.

PARAMETRES

identifiant_transaction

Un identifiant arbitraire qui identifiera plus tard cette transaction pour COMMIT PREPARED ou ROLLBACK PREPARED. L'identifiant doit être écrit comme une chaîne littérale et ne doit pas dépasser 200 octets. Il ne doit pas être le même que celui utilisé pour une transaction déjà préparée.

NOTES

PREPARE TRANSACTION n'est pas destiné à être utilisé dans des applications ou des sessions interactives. Son but est de permettre à un gestionnaire de transactions externe d'effectuer des transactions globales atomiques sur plusieurs bases de données ou d'autres ressources transactionnelles. À moins que vous n'écriviez un gestionnaire de transactions, vous ne devriez probablement pas utiliser PREPARE TRANSACTION.

Cette commande doit être utilisée à l'intérieur d'un bloc de transaction. Utilisez BEGIN pour en démarrer un.

Il n'est pas actuellement permis de PREPARE une transaction qui a exécuté des opérations impliquant des tables temporaires ou l'espace de noms temporaire de la session, créé des curseurs WITH HOLD, ou exécuté LISTEN, UNLISTEN, ou NOTIFY. Ces fonctionnalités sont trop étroitement liées à la session courante pour être utiles dans une transaction à préparer.

Si la transaction a modifié des paramètres d'exécution avec SET (sans l'option LOCAL), ces effets persistent après PREPARE TRANSACTION, et ne seront pas affectés par un COMMIT PREPARED ou ROLLBACK PREPARED ultérieur. Ainsi, à cet égard, PREPARE TRANSACTION se comporte plus comme COMMIT que comme ROLLBACK.

Toutes les transactions préparées actuellement disponibles sont listées dans la vue système pg_prepared_xacts.


Attention

Il est déconseillé de laisser des transactions dans l'état préparé pendant une longue période. Cela interférera avec la capacité de VACUUM à récupérer de l'espace, et dans des cas extrêmes pourrait provoquer l'arrêt de la base de données pour éviter le dépassement de l'identifiant de transaction (voir la Section 24.1.5). Gardez également à l'esprit que la transaction continue de détenir les verrous qu'elle avait. L'usage prévu de cette fonctionnalité est qu'une transaction préparée soit normalement validée ou annulée dès qu'un gestionnaire de transactions externe a vérifié que d'autres bases de données sont également prêtes à valider.

Si vous n'avez pas configuré un gestionnaire de transactions externe pour suivre les transactions préparées et vous assurer qu'elles sont traitées rapidement, il est préférable de désactiver la fonctionnalité de transaction préparée en réglant max_prepared_transactions à zéro. Cela empêchera la création accidentelle de transactions préparées qui pourraient ensuite être oubliées et causer des problèmes.

EXEMPLES

Préparer la transaction courante pour un commit en deux phases, en utilisant foobar comme identifiant de transaction :

PREPARE TRANSACTION 'foobar';

COMPATIBILITE

PREPARE TRANSACTION est une extension de PostgreSQL. Elle est destinée à être utilisée par des systèmes externes de gestion de transactions, dont certains sont couverts par des normes (telles que X/Open XA), mais le côté SQL de ces systèmes n'est pas standardisé.
