PR_RISCV_SET_ICACHE_FLUSH_CTX(2const) PR_RISCV_SET_ICACHE_FLUSH_CTX(2const)

NOM

PR_RISCV_SET_ICACHE_FLUSH_CTX - Activer/désactiver les instructions de vidage du cache d'instructions (icache) dans l'espace utilisateur.

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/prctl.h>  /* Définition des constantes PR_* */
#include <sys/prctl.h>
int prctl(PR_RISCV_SET_ICACHE_FLUSH_CTX, unsigned long ctx,
          unsigned long scope);

DESCRIPTION

Le contexte et la portée peuvent être fournis en utilisant respectivement ctx et scope.

Lorsque la portée est définie sur PR_RISCV_SCOPE_PER_PROCESS, tous les threads du processus sont autorisés à émettre des instructions de vidage de l'icache. Chaque fois qu'un thread du processus est migré, l'icache du hart correspondant sera garanti d'être cohérent avec le stockage des instructions. Cela n'impose aucune garantie en dehors de la migration. Si un thread modifie une instruction qu'un autre thread pourrait tenter d'exécuter, l'autre thread doit toujours émettre une instruction de vidage de l'icache avant de tenter d'exécuter l'instruction potentiellement modifiée. Ceci doit être effectué par le programme en espace utilisateur.

Dans le contexte par thread (par exemple, la portée est définie sur PR_RISCV_SCOPE_PER_THREAD), seul le thread appelant cette fonction est autorisé à émettre des instructions de vidage de l'icache. Lorsque le thread est migré, l'icache du hart correspondant sera garanti d'être cohérent avec le stockage des instructions.

Sur les noyaux configurés sans SMP, ce prctl PR_RISCV_SET_ICACHE_FLUSH_CTX est un NOP car les migrations entre les harts ne se produiront pas.

Les valeurs suivantes pour ctx peuvent être spécifiées :

PR_RISCV_CTX_SW_FENCEI_ON (depuis Linux 6.10)
Autorise `fence.i` dans l'espace utilisateur.
PR_RISCV_CTX_SW_FENCEI_OFF (depuis Linux 6.10)
Interdit `fence.i` dans l'espace utilisateur. Tous les threads d'un processus seront affectés lorsque la portée est définie sur PR_RISCV_SCOPE_PER_PROCESS. Par conséquent, la prudence doit être de mise ; utilisez ce drapeau uniquement lorsque vous pouvez garantir qu'aucun thread du processus n'émettra `fence.i` à partir de ce moment.

Les valeurs suivantes pour scope peuvent être spécifiées :

PR_RISCV_SCOPE_PER_PROCESS (depuis Linux 6.10)
Garantit que l'icache de tout thread de ce processus est cohérent avec le stockage des instructions lors de la migration.
PR_RISCV_SCOPE_PER_THREAD (depuis Linux 6.10)
Garantit que l'icache du thread courant est cohérent avec le stockage des instructions lors de la migration.

EXEMPLES

Les fichiers suivants sont destinés à être compilés et liés les uns aux autres. La fonction modify_instruction() remplace un `add` par zéro par un `add` par un, provoquant le changement de la séquence d'instructions dans get_value() de retournant zéro à retournant un.

Source du programme : cmodx.c

#include <stdio.h>
#include <sys/prctl.h>
extern int get_value(void);
extern void modify_instruction(void);
int
main(void)
{
    int value = get_value();
    printf("Valeur avant cmodx: %d\n", value);
    // Appeler prctl avant le premier appel à fence.i
    prctl(PR_RISCV_SET_ICACHE_FLUSH_CTX, PR_RISCV_CTX_SW_FENCEI_ON,
          PR_RISCV_SCOPE_PER_PROCESS);
    modify_instruction();
    // Appeler prctl après le dernier appel à fence.i dans le processus
    prctl(PR_RISCV_SET_ICACHE_FLUSH_CTX, PR_RISCV_CTX_SW_FENCEI_OFF,
          PR_RISCV_SCOPE_PER_PROCESS);
    value = get_value();
    printf("Valeur après cmodx: %d\n", value);
    return 0;
}

Source du programme : cmodx.S

.option norvc
.text
.global modify_instruction
modify_instruction:
lw a0, new_insn
lui a5,%hi(old_insn)
sw  a0,%lo(old_insn)(a5)
fence.i
ret
.section modifiable, "awx"
.global get_value
get_value:
li a0, 0
old_insn:
addi a0, a0, 0
ret
.data
new_insn:
addi a0, a0, 1

Résultat attendu

Valeur avant cmodx: 0
Valeur après cmodx: 1

NORMES

Linux. RISC-V uniquement.

HISTORIQUE

Linux 6.10 (RISC-V).
