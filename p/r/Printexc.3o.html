Fonctions pour imprimer les exceptions et inspecter la pile d'appels actuelle.

type t = exn = ..

Le type des valeurs d'exception.

val to_string : exn -> string

Printexc.to_string e renvoie une représentation de l'exception e sous forme de chaîne.

val to_string_default : exn -> string

Printexc.to_string_default e renvoie une représentation de l'exception e sous forme de chaîne, en ignorant tous les imprimeurs d'exceptions enregistrés.

Depuis 4.09

val print : ('a -> 'b) -> 'a -> 'b

Printexc.print fn x applique fn à x et renvoie le résultat. Si l'évaluation de fn x lève une exception, le nom de l'exception est imprimé sur la sortie standard et l'exception est relancée. L'utilisation typique est de capturer et signaler les exceptions qui s'échappent d'une application de fonction.

val catch : ('a -> 'b) -> 'a -> 'b

Obsolète. Cette fonction n'est plus nécessaire.

Printexc.catch fn x est similaire à Printexc.print, mais termine le programme avec le code de sortie 2 après avoir imprimé l'exception non capturée. Cette fonction est obsolète : le système d'exécution peut désormais imprimer les exceptions non capturées avec une précision égale à celle de Printexc.catch. De plus, l'appel à Printexc.catch rend plus difficile le suivi de l'emplacement de l'exception à l'aide du débogueur ou de la fonction de trace (backtrace). Par conséquent, Printexc.catch ne doit pas être utilisé dans de nouveaux programmes.

val print_backtrace : out_channel -> unit

Printexc.print_backtrace oc imprime la trace arrière (backtrace) de l'exception sur le canal de sortie oc. La trace arrière liste les emplacements du programme où l'exception la plus récente a été levée et où elle a été propagée par des appels de fonction.

Si l'appel n'est pas effectué dans un gestionnaire d'exception, la trace arrière renvoyée est indéterminée. Si l'appel est effectué après un code de capture d'exception (avant le gestionnaire ou pendant la correspondance d'exception dans le gestionnaire), la trace arrière peut correspondre à une exception ultérieure à celle qui a été gérée.

Depuis 3.11

val get_backtrace : unit -> string

Printexc.get_backtrace () renvoie une chaîne contenant la même trace arrière d'exception que celle que Printexc.print_backtrace imprimerait. La même restriction d'utilisation que Printexc.print_backtrace.

Depuis 3.11

val record_backtrace : bool -> unit

Printexc.record_backtrace b active ou désactive l'enregistrement des traces arrière d'exception. Par défaut, aucune trace arrière n'est enregistrée, à moins que le paramètre b ne soit défini via la variable d'environnement OCAMLRUNPARAM.

Depuis 3.11

val backtrace_status : unit -> bool

Printexc.backtrace_status() renvoie true si les traces arrière d'exception sont actuellement enregistrées, false sinon.

Depuis 3.11

val register_printer : (exn -> string option) -> unit

Printexc.register_printer fn enregistre fn comme un imprimeur d'exceptions. L'imprimeur doit renvoyer None ou lever une exception s'il ne sait pas comment convertir l'exception passée, et Some avec s s'il peut convertir l'exception passée. Les exceptions levées par l'imprimeur sont ignorées.

Lorsqu'une exception est convertie en chaîne, les imprimeurs sont appelés dans l'ordre inverse de leur enregistrement, jusqu'à ce qu'un imprimeur renvoie une valeur Some s (s'il n'existe pas un tel imprimeur, le runtime utilisera un imprimeur générique).

Lors de l'utilisation de ce mécanisme, il faut être conscient qu'une trace arrière d'exception est associée au fil d'exécution qui a vu l'exception, et non à l'exception elle-même. En pratique, cela signifie que le code lié à fn ne doit pas utiliser la trace arrière s'il a levé une exception avant lui-même.

Depuis 3.11.2

val use_printers : exn -> string option

Printexc.use_printers e renvoie None s'il n'y a pas d'imprimeurs enregistrés et Some s avec s la chaîne résultante dans le cas contraire.

Depuis 4.09

Traces arrière brutes (Raw backtraces)

type raw_backtrace

Le type raw_backtrace stocke une trace arrière dans un format de bas niveau, qui peut être converti en un format utile à l'aide de raw_backtrace_entries et backtrace_slots_of_raw_entry ci-dessous.

La conversion des traces arrière en backtrace_slot est plus lente que la capture des traces arrière. Si un programme traite de nombreuses traces arrière, il peut être utile d'utiliser raw_backtrace pour éviter ou retarder la conversion.

Les traces arrière brutes ne peuvent pas être sérialisées. Si vous avez besoin de sérialisation, vous devriez utiliser le tableau renvoyé par la fonction backtrace_slots de la section suivante.

Depuis 4.01

type raw_backtrace_entry = private int

Un raw_backtrace_entry est un élément d'un raw_backtrace.

Chaque raw_backtrace_entry est un entier opaque, dont la valeur n'est pas stable entre différents programmes, ni même entre différentes exécutions du même binaire.

Un raw_backtrace_entry peut être converti en un format utile à l'aide de backtrace_slots_of_raw_entry. Il convient de noter qu'en raison de l'inlining, un seul raw_backtrace_entry peut se convertir en plusieurs backtrace_slot. Étant donné que les valeurs d'un raw_backtrace_entry ne sont pas stables, elles ne peuvent pas être sérialisées. Si elles doivent être converties, la conversion doit être effectuée par le processus qui les a générées.

Encore une fois, en raison de l'inlining, il peut y avoir plusieurs valeurs distinctes de raw_backtrace_entry qui convergent vers les mêmes backtrace_slot. Cependant, si deux raw_backtrace_entry sont identiques en tant qu'entiers, ils représentent les mêmes backtrace_slot.

Depuis 4.12

val raw_backtrace_entries : raw_backtrace -> raw_backtrace_entry array

Depuis 4.12

val get_raw_backtrace : unit -> raw_backtrace

Printexc.get_raw_backtrace () renvoie la même trace arrière d'exception que celle que Printexc.print_backtrace imprimerait, mais au format brut. La même restriction d'utilisation que Printexc.print_backtrace.

Depuis 4.01

val print_raw_backtrace : out_channel -> raw_backtrace -> unit

Imprime une trace arrière brute dans le même format que celui utilisé par Printexc.print_backtrace.

Depuis 4.01

val raw_backtrace_to_string : raw_backtrace -> string

Renvoie une chaîne à partir d'une trace arrière brute, dans le même format que celui utilisé par Printexc.get_backtrace.

Depuis 4.01

val raise_with_backtrace : exn -> raw_backtrace -> 'a

Lève l'exception en utilisant la trace arrière donnée comme origine de l'exception.

Depuis 4.05

Pile d'appels actuelle

val get_callstack : int -> raw_backtrace

Printexc.get_callstack n renvoie une description de la partie supérieure de la pile d'appels au point actuel du programme (pour le fil d'exécution actuel), avec au maximum n entrées. (Note : cette fonction n'est pas du tout liée aux exceptions, bien qu'elle fasse partie du module Printexc.)

Depuis 4.01

Exceptions non capturées

val default_uncaught_exception_handler : exn -> raw_backtrace -> unit

Printexc.default_uncaught_exception_handler imprime l'exception et la trace arrière sur la sortie standard.

Depuis 4.11

val set_uncaught_exception_handler : (exn -> raw_backtrace -> unit) -> unit

Printexc.set_uncaught_exception_handler fn enregistre fn comme gestionnaire pour les exceptions non capturées. Le gestionnaire par défaut est Printexc.default_uncaught_exception_handler.
