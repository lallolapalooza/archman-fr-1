NOM

Proc::Simple -- lancer et contrôler des processus en arrière-plan

SYNOPIS

use Proc::Simple;
$myproc = Proc::Simple->new();        # Créer un nouvel objet de processus
$myproc->start("ligne-de-commande-shell"); # Lancer un programme externe
$myproc->start("commande",             # Lancer un programme externe
               "param", ...);         # avec des paramètres

$myproc->start(sub { ... });          # Lancer une sous-routine Perl
$myproc->start(\&subroutine);         # Lancer une sous-routine Perl
$myproc->start(\&subroutine,          # Lancer une sous-routine Perl
               $param, ...);          # avec des paramètres
$running = $myproc->poll();           # Examiner le processus
$exit_status = $myproc->wait();       # Attendre la fin du processus
$proc->kill_on_destroy(1);            # Agir comme kill lors de la destruction
$proc->signal_on_destroy("KILL");     # Spécifier le signal à envoyer
                                      # lors de la destruction
$myproc->kill();                      # Terminer le processus (SIGTERM)
$myproc->kill("SIGUSR1");             # Envoyer le signal spécifié
$myproc->exit_status();               # Retourner le statut de sortie du processus
Proc::Simple::debug($level);          # Activer le débogage

DESCRIPTION

La classe Proc::Simple fournit des objets qui imitent de vrais processus du point de vue de l'utilisateur. Un nouvel objet de processus est créé en utilisant

$myproc = Proc::Simple->new();

On peut lancer et contrôler à la fois des programmes externes et des sous-routines Perl comme processus en arrière-plan.

Un processus d'attente de 10 secondes, par exemple, peut être lancé comme programme externe, comme suit :

$myproc->start("/bin/sleep 10");    # ou
$myproc->start("/bin/sleep", "10");

ou comme sous-routine Perl, comme suit :

sub mysleep { sleep(shift); }    # Définir mysleep()
$myproc->start(\&mysleep, 10);   # Le lancer.

ou même comme ceci :

$myproc->start(sub { sleep(10); });

La méthode start retourne immédiatement après avoir lancé le processus spécifié en arrière-plan, c'est-à-dire qu'elle n'est pas bloquante. Elle retourne 1 si le processus a été lancé avec succès et 0 sinon.

La méthode poll vérifie si le processus est toujours en cours d'exécution

$running = $myproc->poll();

et retourne 1 s'il l'est, 0 sinon. Finalement,

$myproc->kill();

arrête le processus en lui envoyant le signal SIGTERM. Optionnellement, un autre signal peut être spécifié.

$myproc->kill("SIGUSR1");

envoie le signal SIGUSR1 au processus en cours d'exécution. La méthode kill retourne 1 si elle parvient à envoyer le signal, 0 sinon.

Les méthodes sont discutées plus en détail dans la section suivante.

Un destructeur est fourni pour qu'un signal puisse être envoyé au processus fils automatiquement si l'objet de processus est détruit ou si le processus est terminé. Par défaut, cette option est désactivée (voir les méthodes kill_on_destroy et signal_on_destroy).

MÉTHODES

Les méthodes suivantes sont disponibles :

new (Constructeur)
Crée un nouvel objet de cette classe en écrivant

$proc = new Proc::Simple;

ou

$proc = Proc::Simple->new();

Il n'accepte aucun argument.

start
Démarre un nouveau processus. La méthode start peut être utilisée pour lancer à la fois des programmes externes (comme /bin/echo) et des sous-routines propres à l'utilisateur (comme foo()) dans un nouveau processus.

$status = $proc->start("nom-programme");

Pour lancer un programme externe, appelez

$status = $proc->start("nom-programme");

Si vous souhaitez passer plusieurs paramètres au programme lancé, il y a deux options : vous pouvez les passer sous forme d'un seul argument, comme dans

$status = $proc->start("/bin/echo bonjour le monde");

ou sous forme de plusieurs arguments, comme dans

$status = $proc->start("/bin/echo", "bonjour", "le monde");

Comme pour la méthode system() de Perl, il y a une grande différence entre les deux méthodes : si vous passez un argument qui contient une ligne de commande séparée par des espaces, votre shell traitera tout caractère méta (si vous décidez d'en utiliser un) avant que le processus ne soit réellement lancé :

$status = $proc->start("/bin/ls -l /etc/initt*");

cet exemple développe /etc/initt* en /etc/inittab avant d'exécuter la commande /bin/ls. Si, au lieu de cela, vous dites

$status = $proc->start("/bin/ls", "-l", "*");

le * sera laissé non développé, ce qui signifie que vous rechercherez un fichier dont le nom est littéralement * (ce qui est peu probable sur votre système, sauf si vous créez accidentellement des fichiers avec des noms déroutants). Pour plus d'informations à ce sujet, consultez perldoc -f exec.

Si, au lieu de cela, vous voulez lancer une sous-routine Perl en arrière-plan, fournissez simplement la référence à la sous-routine comme

$status = $proc->start(\&votre_fonction);

ou fournissez une sous-routine anonyme :

$status = $proc->start( sub { sleep(1) } );

Vous pouvez également fournir des paramètres supplémentaires à passer à la sous-routine :

$status = $proc->start(\&printme, "bonjour", "le monde");

La méthode start retourne immédiatement après avoir lancé le processus spécifié en arrière-plan, c'est-à-dire en mode non bloquant. Elle retourne 1 si le processus a été lancé avec succès et 0 sinon.

poll
La méthode poll vérifie si le processus est toujours en cours d'exécution

$running = $myproc->poll();

et retourne 1 s'il l'est, 0 sinon.

kill
La méthode kill :

$myproc->kill();

arrête le processus en lui envoyant le signal SIGTERM. Optionnellement, un autre signal peut être spécifié.

$myproc->kill("SIGUSR1");

envoie le signal SIGUSR1 au processus en cours d'exécution. La méthode kill retourne 1 si elle parvient à envoyer le signal, 0 sinon.

kill_on_destroy
Configure un indicateur pour déterminer si le processus associé à cet objet doit être terminé lorsque l'objet est détruit. Par défaut, cet indicateur est désactivé. La valeur actuelle est retournée.

$current = $proc->kill_on_destroy;
$proc->kill_on_destroy(1); # Active l'indicateur
$proc->kill_on_destroy(0); # Désactive l'indicateur
signal_on_destroy
Méthode pour configurer le signal qui sera envoyé au processus lorsque l'objet sera détruit (en supposant que kill_on_destroy est actif). Retourne la valeur actuelle de la configuration.

$current = $proc->signal_on_destroy;
$proc->signal_on_destroy("KILL");
redirect_output
Redirige la sortie standard et/ou stderr d'un processus vers un fichier. Spécifiez undef pour laisser les descripteurs stdout/stderr du processus intacts.

# stdout vers un fichier, stderr non modifié
$proc->redirect_output ("/tmp/someapp.stdout", undef);

# stderr vers un fichier, stdout non modifié
$proc->redirect_output (undef, "/tmp/someapp.stderr");

# stdout et stderr vers un fichier séparé
$proc->redirect_output ("/tmp/someapp.stdout", "/tmp/someapp.stderr");

Appelez cette méthode avant d'appeler la méthode start.

pid
Retourne le pid du processus fils associé à cet objet

$pid = $proc->pid;
t0
Retourne le temps de démarrage (t0) du processus fils associé à cet objet

$t0 = $proc->t0();
t1
Retourne le temps de fin (t1) du processus fils associé à cet objet

$t1 = $proc->t1();

NOM

Proc::Simple - Contrôle de processus

SYNOPIS

use Proc::Simple;

Crée un nouveau processus.

DESCRIPTION

Proc::Simple fournit une interface simple pour le contrôle de processus. Il vous permet de démarrer, surveiller et gérer des processus en Perl.

MÉTHODES

NEW
Crée un nouveau processus. La méthode est appelée avec les arguments du processus.
START
Démarre le processus. Cette méthode est appelée avec les arguments du processus.
STOP
Arrête le processus. Cette méthode est appelée avec les arguments du processus.
KILL
Tue le processus. Cette méthode est appelée avec les arguments du processus.
WAIT
Attend que le processus se termine. Cette méthode est appelée avec les arguments du processus.
DEBUG
Active et désactive les messages de débogage. Proc::Simple::debug(1) les active, Proc::Simple::debug(0) garde Proc::Simple silencieux.
CLEANUP
Proc::Simple conserve les données des processus terminés, par exemple vous pouvez vérifier via t0() et t1() combien de temps un processus a fonctionné, même s'il a disparu depuis longtemps. Au fil du temps, ces données occupent de plus en plus de mémoire et si vous avez un programme de longue durée, vous voudrez peut-être exécuter "Proc::Simple->cleanup()" de temps en temps pour supprimer les données relatives aux processus qui ne sont plus utilisés.

NOTE

Veuillez garder à l'esprit qu'il n'y a aucune garantie que le signal SIGTERM termine réellement un processus. Les processus peuvent avoir des gestionnaires de signaux définis qui évitent l'arrêt. En cas de doute sur l'existence d'un processus, vérifiez-le à plusieurs reprises avec la routine poll après avoir envoyé le signal.

Processus Shell

Si vous passez un programme shell à Proc::Simple, il utilisera exec() pour le lancer. Comme noté dans la page de manuel Perl exec(), les commandes simples pour la version à un argument de exec() seront transmises directement à execvp(), tandis que les commandes contenant des caractères tels que ";" ou "*" seront transmises à un shell pour s'assurer qu'elles bénéficient du traitement d'expansion du shell.

Cela a pour effet secondaire intéressant que si vous lancez quelque chose comme

$p->start("./womper *");

alors vous verrez deux processus dans votre liste de processus :

$ ps auxww | grep womper
mschilli  9126 11:21 0:00 sh -c ./womper *
mschilli  9127 11:21 0:00 /usr/local/bin/perl -w ./womper ...

Un kill() régulier sur le PID du processus ne tuerait que le premier processus, mais le kill() de Proc::Simple utiliserait un signal négatif et l'enverrait au premier processus (9126). Comme il a marqué le processus comme chef de groupe de processus lors de sa création précédente (via setsid()), cela amènera les deux processus ci-dessus à recevoir le signal envoyé par kill().
