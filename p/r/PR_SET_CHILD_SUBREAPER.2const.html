PR_SET_CHILD_SUBREAPER(2const) PR_SET_CHILD_SUBREAPER(2const)

NOM

PR_SET_CHILD_SUBREAPER - définir/annuler l'attribut « child subreaper » du processus appelant

BIBLIOTHÉQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/prctl.h>  /* Définition des constantes PR_* */
#include <sys/prctl.h>
int prctl(PR_SET_CHILD_SUBREAPER, long set);

DESCRIPTION

Si set est non nul, définit l'attribut « child subreaper » du processus appelant ; si set est zéro, annule l'attribut.

Un sous-récupérateur remplit le rôle de init(1) pour ses processus descendants. Lorsqu'un processus devient orphelin (c'est-à-dire que son parent immédiat se termine), ce processus sera re-parenté au plus proche ancêtre sous-récupérateur encore vivant. Par la suite, les appels à getppid(2) dans le processus orphelin retourneront désormais le PID du processus sous-récupérateur, et lorsque l'orphelin se terminera, c'est le processus sous-récupérateur qui recevra un signal SIGCHLD et sera capable d'wait(2) sur le processus pour découvrir son statut de terminaison.

La définition de l'attribut « child subreaper » n'est pas héritée par les enfants créés par fork(2) et clone(2). La définition est préservée lors des appels à execve(2).

L'établissement d'un processus sous-récupérateur est utile dans les cadres de gestion de session où un groupe hiérarchique de processus est géré par un processus sous-récupérateur qui doit être informé lorsqu'un des processus — par exemple, un démon doublement forké — se termine (peut-être pour pouvoir redémarrer ce processus). Certains cadres d'init(1) (par exemple, systemd(1)) utilisent un processus sous-récupérateur pour des raisons similaires.

VALEUR DE RETOUR

En cas de succès, 0 est retourné. En cas d'erreur, -1 est retourné, et errno est définie pour indiquer l'erreur.

NORMES

Linux.

HISTORIQUE

Linux 3.4.

VOIR AUSSI

prctl(2), PR_GET_CHILD_SUBREAPER(2const)
