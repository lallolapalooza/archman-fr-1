NOM

PMAPI_INTERNAL - détails internes de l'interface de programmation d'application des métriques de performance

SYNTAXE C

#include "pmapi.h"
#include "libpcp.h"

... diverses routines ...

cc ... -lpcp

ATTENTION

Cette documentation est destinée à un usage interne par les développeurs de Performance Co-Pilot (PCP).

Ces interfaces ne font pas partie des API PCP dont la stabilité est garantie d'une version à l'autre, et elles pourraient ne pas fonctionner, ou présenter une sémantique différente, à l'avenir.

DESCRIPTION

Se référer à PMAPI(3) pour des informations générales sur les interfaces externes définies dans <pcp/pmapi.h>. Les interfaces décrites ici supposent ce contexte.

APPLICATIONS MULTI-THREADÉES

Les groupes de fonctions et services internes suivants dans libpcp sont restreints à l'appel depuis un seul thread, et ceci est appliqué en retournant PM_ERR_THREAD lorsqu'une tentative d'appel des routines de chaque groupe depuis plus d'un thread est détectée.

1.
Les services de minuterie d'intervalle utilisent un état global dont la sémantique exige qu'il ne soit utilisé que dans le contexte d'un seul thread, donc __pmAFregister(3), __pmAFunregister(3), __pmAFblock(3), __pmAFunblock(3) et __pmAFisempty(3).
2.
Les routines de manipulation de contrôle d'accès suivantes sont principalement destinées aux applications mono-threadées : __pmAccAddOp, __pmAccSaveHosts, __pmAccRestoreHosts, __pmAccFreeSavedHosts, __pmAccAddHost, __pmAccAddClient, __pmAccDelClient et __pmAccDumpHosts.
3.
Les routines suivantes qui identifient les ports de contrôle de pmlogger et sont principalement destinées aux applications mono-threadées : __pmLogFindPort et __pmLogFindLocalPorts.
