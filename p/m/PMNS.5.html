NAME

PMNS - espace de noms des métriques de performance

SYNOPSIS

$PCP_VAR_DIR/pmns

DESCRIPTION

Lors de l'utilisation de l'interface de programmation des métriques de performance (PMAPI) de Performance Co-Pilot (PCP), les métriques sont identifiées par un nom externe dans l'espace de noms hiérarchique des métriques de performance (PMNS) et un identifiant interne, l'identifiant de métrique (PMID).

Un PMNS spécifie l'association entre le nom d'une métrique et son PMID.

Un PMNS est défini dans un ou plusieurs fichiers ASCII.

Le chargement d'un PMNS se fait en appelant pmLoadNameSpace(3) ou pmLoadASCIINameSpace(3).

Depuis la version 3.10.3 de PCP, les noms dupliqués pour le même PMID sont autorisés dans un PMNS, bien que pmLoadASCIINameSpace(3) offre une interface alternative avec un contrôle personnalisé sur le traitement des noms dupliqués dans le PMNS. Le format externe d'un PMNS suit la syntaxe et la sémantique décrites dans les sections suivantes.

Il existe un PMNS par défaut dans les fichiers $PCP_VAR_DIR/pmns, bien que les utilisateurs et les développeurs puissent créer et utiliser leurs propres PMNS. Pour un exemple de ceci, voir le tutoriel PCP dans $PCP_DEMOS_DIR/Tutorial.

Bien qu'une application puisse appeler pmLoadNameSpace(3), elle est normalement effectuée directement pour l'option de ligne de commande -n où un fichier PMNS racine explicite est spécifié. Depuis la version 2 de PCP, le PMNS peut être obtenu à distance d'un PMCD ou directement à partir des métadonnées d'un fichier. Si le fichier source du PMNS est une version 1 (voir PCPIntro(1)), le PMNS local est cependant chargé via le chemin spécifié par la variable d'environnement PMNS_DEFAULT.

PMNS DISTRIBUÉ

Dans PCP version 1, les fonctions PMNS opéraient via l'API avec un PMNS chargé localement à partir d'un fichier. Cependant, depuis PCP version 2, les fonctions PMNS peuvent obtenir les informations PMNS à distance d'un PMCD ou directement à partir des métadonnées d'un fichier.

STRUCTURE DE TRAITEMENT

La spécification du PMNS est d'abord passée à pmcpp(1). Cela signifie que les fonctionnalités suivantes peuvent être utilisées dans la spécification :

+
Commentaires de style C
+
Directives #include
+
Directives #define et substitution de macros
+
Traitement conditionnel avec #ifdef ... #endif

Lors de l'exécution de pmcpp(1), les répertoires standard sont considérés comme le répertoire courant et $PCP_VAR_DIR/pmns.

Le traitement avec pmcpp(1) peut être omis dans certains cas où le PMNS ne contient pas de commentaires de style C, de directives de préprocesseur ou de macros. Consultez les descriptions de pmLoadASCIINameSpace(3) et pmLoadNameSpace(3) pour plus de détails.

SYNTAXE

La syntaxe générale pour un nœud non-feuille dans le PMNS est la suivante :

pathname {
        name      [pmid]
        ...
}

Où pathname est le chemin complet de la racine du PMNS à ce nœud non-feuille, avec chaque composant séparé par un ``.''. Le nœud racine du PMNS doit avoir le nom spécial ``root'', mais le préfixe commun ``root.'' doit être omis dans tous les chemins. Chaque composant du chemin est extrait de ASCII(7), commençant par un caractère alphabétique suivi de zéro ou plusieurs caractères alphabétiques, de chiffres et du caractère ``_''. Les caractères alphabétiques dans un composant de chemin sont considérés comme sensibles à la casse.

Les nœuds non-feuilles dans le PMNS peuvent être définis dans n'importe quel ordre.

Les nœuds descendants sont définis par l'ensemble des noms, relatifs au chemin du nœud parent. Pour les nœuds descendants, les nœuds feuilles ont un pmid spécifié, tandis que les nœuds non-feuilles n'en ont pas. La syntaxe du pmid spécifié a été choisie pour aider à gérer l'allocation des identifiants de métriques entre différents domaines d'administration et d'implémentation. Chaque pmid consiste en trois parties entières séparées par des deux-points, par exemple 14:27:11. Ce système de numérotation hiérarchique est conçu pour refléter la hiérarchie d'implémentation du domaine des métriques de performance, des groupes de métriques (structure ou similarité opérationnelle) et des métriques individuelles. En pratique, les deux premiers composants sont susceptibles d'être des macros dans la spécification du PMNS. pmcpp(1) transformera ces macros en entiers. Les macros initiales des composants de pmid sont susceptibles d'être définies dans un fichier d'inclusion standard, par exemple $PCP_VAR_DIR/pmns/stdpmid, ou dans le fichier source actuel.

Pour prendre en charge les métriques dynamiques, où l'existence d'une métrique est connue d'un PMDA mais n'est pas visible dans le PMNS, une syntaxe variante pour le pmid est prise en charge, c'est-à-dire un numéro de domaine suivi d'astérisques pour les autres composants du pmid, par exemple 14:*:*. La forme du nom de la métrique correspond à la racine d'un arbre de noms dynamiques défini dans le PMDA correspondant identifié par le numéro de domaine.

L'affectation actuelle des composants de haut niveau (PMD ou domaine) des identifiants de métriques est structurée comme suit :

Plage Affectation
0 Réservé
1-384 IDs des PMDA des paquets PCP
385-510 IDs des PMDA des utilisateurs finaux (affectés en ordre décroissant)
511 Réservé pour les entrées PMNS dynamiques

EXEMPLE

#define KERNEL 1
#define FOO 387
root {
    network
    cpu
    dynamic     FOO:*:*
}
#define NETWORK 26
network {
    intrate     KERNEL:NETWORK:1
    packetrate
}
network.packetrate {
    in          KERNEL:NETWORK:35
    out         KERNEL:NETWORK:36
}
#define CPU 10
cpu {
    syscallrate KERNEL:CPU:10
    util
}
#define USER 20
#define SYSTEM 21
#define IDLE 22
cpu.util {
    user        KERNEL:CPU:USER
    sys         KERNEL:CPU:SYSTEM
    idle        KERNEL:CPU:IDLE
}
