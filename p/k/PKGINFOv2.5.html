(5) Manuel des formats de fichiers (5)

NOM

PKGINFO - Informations sur les paquets basés sur ALPM (version 2).

DESCRIPTION

Le format PKGINFO est un format textuel qui décrit les métadonnées d'un paquet. Ces fichiers se trouvent à la racine des paquets ALPM et sont nommés .PKGINFO. Ils sont utilisés, par exemple, par les gestionnaires de paquets pour évaluer et présenter le contexte d'un paquet au sein de son écosystème. Les cas d'utilisation incluent la représentation des métadonnées communes et la relation avec d'autres paquets.

Le format PKGINFO existe en plusieurs versions. Les informations de ce document concernent la version 2, qui est la version actuelle et a été introduite avec la sortie de pacman 6.1.0 le 04/03/2024.

Format général

Un fichier PKGINFO consiste en une série de lignes, chacune fournissant des informations sur un aspect d'un paquet. Les lignes commençant par un signe ‘#’ sont des commentaires et sont toujours ignorées. Les espaces blancs en début de ligne sont toujours ignorés.

Sauf indication contraire, les informations contenues dans un fichier PKGINFO sont considérées comme couvertes par l'ensemble des 95 caractères imprimables ASCII[1].

Changements depuis la dernière version

Le nouveau mot-clé xdata a été ajouté pour suivre les données supplémentaires d'un paquet.

Mots-clés

Chaque ligne encode des informations représentant une affectation de mot-clé. Toutes les affectations de mots-clés consistent en une clé de la liste suivante, immédiatement suivie d'un espace blanc, d'un signe ‘=’, d'un autre espace blanc et d'une valeur.

Par défaut, une seule affectation de mot-clé doit être présente par mot-clé dans un PKGINFO. Par exception à cette règle, les mots-clés license, replaces, group, conflict, provides, backup, depend, optdepend, makedepend et checkdepend peuvent être fournis zéro ou plusieurs fois. Comme exception supplémentaire, le mot-clé xdata est fourni une ou plusieurs fois.

pkgname

Le nom du paquet. La valeur est un alpm-package-name (par exemple, exemple).

pkgbase

La base de nom de paquet alpm du paquet. La valeur est une alpm-package-base (par exemple, exemple).

xdata

Les données extra associées au paquet. Ce mot-clé doit être affecté une fois pour définir une valeur spécifique, mais peut être fourni plusieurs fois par la suite pour fournir des données supplémentaires. La valeur est une chaîne encodée en UTF-8, qui représente une autre paire clé-valeur, délimitée par un signe ‘=’ (par exemple, clé=valeur).

Un PKGINFO doit contenir une affectation de mot-clé xdata qui définit une affectation pkgtype dans sa valeur (par exemple, pkgtype=pkg). Les valeurs valides de pkgtype sont debug (pour les paquets de débogage), pkg (pour les paquets simples), src (pour les paquets source) et split (pour les paquets éclatés).

Des affectations de mots-clés xdata supplémentaires peuvent être fournies en suivant les règles générales concernant le formatage de ses valeurs.

pkgver

La version complète du paquet. Notez qu'il ne faut pas confondre ceci avec alpm-pkgver, qui ne représente qu'un sous-ensemble de ce mot-clé ! La valeur est une alpm-package-version, soit sous forme complète, soit sous forme complète avec epoch (par exemple, 1.0.0-1 ou 1:1.0.0-1, respectivement).

pkgdesc

La description du paquet. La valeur est une chaîne UTF-8, d'une longueur nulle ou plus (par exemple, Un projet utilisé pour quelque chose). Les descriptions de paquets ne doivent pas avoir d'espaces blancs en début ou fin de ligne, ne doivent contenir aucun caractère d'espace blanc à l'exception de l'espace “ “ et pas d'espaces successifs. Il est également suggéré qu'elle soit “courte” et qu'elle ne contienne pas le nom du paquet (voir pkgname).

url

L'URL du projet du paquet. La valeur est une URL valide ou une chaîne vide (par exemple, https://example.org).

builddate

La date à laquelle la construction du paquet a commencé. La valeur doit être numérique et doit représenter les secondes depuis l'Époque, alias le temps Unix (par exemple, 1729181726).

packager

L'identifiant utilisateur de l'entité qui a construit le paquet. La valeur est destinée à être utilisée pour des recherches d'identité et représente un Identifiant Utilisateur OpenPGP[2]. En tant que tel, la valeur est une chaîne encodée en UTF-8, qui est conventionnellement composée d'un nom et d'une adresse e-mail, ce qui correspond au format décrit dans la RFC 28223.

size

La taille du contenu du paquet (non compressé et non décompressé) en octets. La valeur est un entier non négatif représentant la taille absolue du contenu du paquet, les fichiers multiples en lien dur étant comptés une seule fois (par exemple, 181849963).

arch

L'architecture du paquet (voir alpm-architecture pour plus d'informations). La valeur doit être couverte par l'ensemble des caractères alphanumériques et ‘_’ (par exemple, x86_64 ou any).

license

Une licence qui s'applique au paquet. Ce mot-clé peut être affecté zéro ou plusieurs fois. La valeur représente un identifiant de licence, qui est une chaîne de longueur non nulle (par exemple, GPL). Bien qu'aucune restriction spécifique ne soit appliquée à la valeur hormis sa longueur, il est fortement recommandé de s'appuyer sur les expressions de licence SPDX (par exemple, GPL-3.0-or-later ou Apache-2.0 OR MIT). Voir la Liste des licences SPDX[4] pour plus d'informations.

replaces

Un autre composant virtuel ou paquet, que le paquet remplace lors de l'installation. Ce mot-clé peut être affecté zéro ou plusieurs fois. La valeur est une alpm-package-relation de type replacement (par exemple, exemple ou exemple=1.0.0).

group

Une chaîne de caractères arbitraire, qui désigne un groupe au niveau de la distribution dont fait partie le paquet. Les groupes sont utilisés, par exemple, par les gestionnaires de paquets pour regrouper des paquets et permettre leur installation en bloc, ou par d'autres logiciels pour afficher des informations sur ces paquets liés. Ce mot-clé peut être affecté zéro ou plusieurs fois. La valeur est représentée par une chaîne UTF-8. Bien qu'il soit possible d'utiliser une chaîne UTF-8, il est fortement recommandé de se baser sur le format pkgname pour la valeur à la place, car les gestionnaires de paquets peuvent utiliser group pour installer un groupe entier de paquets.

conflict

Un autre composant virtuel ou paquet, avec lequel le paquet est en conflit. Ce mot-clé peut être affecté zéro ou plusieurs fois. La valeur est une alpm-package-relation de type conflict (par exemple, exemple ou exemple=1.0.0).

provides

Un autre composant virtuel ou paquet, que le paquet fournit. Ce mot-clé peut être affecté zéro ou plusieurs fois. La valeur est une alpm-package-relation de type provision (par exemple, exemple ou exemple=1.0.0).

backup

Une liste de fichiers ou de répertoires qui seront sauvegardés lors de la mise à jour du paquet. Ce mot-clé peut être affecté zéro ou plusieurs fois. La valeur est un chemin d'accès relatif au répertoire d'installation du paquet, et peut inclure des jokers (par exemple, etc/fstab ou usr/share/some/dir/*).

depend

Une dépendance requise pour que le paquet fonctionne. Ce mot-clé peut être affecté zéro ou plusieurs fois. La valeur est une alpm-package-relation de type dependency (par exemple, coreutils ou bash>=5.0).

optdepend

Une dépendance optionnelle pour le paquet. Ce mot-clé peut être affecté zéro ou plusieurs fois. La valeur est une alpm-package-relation de type dependency (par exemple, imagemagick ou gtk2<2.24).

makedepend

Une dépendance requise lors de la construction du paquet. Ce mot-clé peut être affecté zéro ou plusieurs fois. La valeur est une alpm-package-relation de type dependency (par exemple, gcc ou cmake>=3.10).

checkdepend

Une dépendance requise lors de la vérification du paquet (par exemple, pour les tests). Ce mot-clé peut être affecté zéro ou plusieurs fois. La valeur est une alpm-package-relation de type dependency (par exemple, python ou pytest).

valid_pkg_relations

Un paquet est défini par son nom (par exemple, bash), son nom et sa version (par exemple, bash=5.0) ou son nom et un opérateur de comparaison de version (par exemple, bash>5.0, bash<5.0, bash>=5.0, bash<=5.0, bash!=5.0).

De plus, les relations peuvent spécifier un epoch (par exemple, bash=1:5.0). Si un epoch est spécifié, il doit être précédé d'un deux-points (par exemple, 1:). Si aucun epoch n'est spécifié, il est considéré comme étant 0.

Les relations peuvent également spécifier un paquet virtuel, qui est un identifiant de chaîne (par exemple, java-runtime). Les paquets virtuels ne sont pas limités à des versions spécifiques.

Les relations peuvent être combinées avec des opérateurs logiques AND et OR. Les opérateurs doivent être écrits en majuscules (par exemple, bash>=5.0 AND systemd).

Les relations peuvent également être précédées de modificateurs: ! (NOT) et ? (OR). Le modificateur ? est un alias pour OR, et le modificateur ! est un alias pour NOT.

Les relations peuvent être définies comme dépendantes d'un paquet spécifique, ou comme fournissant une fonctionnalité, qui est ensuite référencée par d'autres paquets (par exemple, depends=foo ou provides=bar).

NOTES

Les informations contenues dans les fichiers PKGINFO sont utilisées par pacman pour gérer les paquets sur un système Arch Linux. La structure et les mots-clés décrits ici permettent une description complète des paquets et de leurs relations.

Un chemin de fichier relatif d'un fichier dans le paquet, qui désigne un fichier pour que le gestionnaire de paquets conserve des sauvegardes au cas où il serait modifié ou supprimé lors d'une action de mise à jour de paquet (voir les fichiers ‘.pacnew’ et ‘.pacsave’ de pacman). Ce mot-clé peut être assigné zéro ou plusieurs fois. La valeur doit être un chemin de fichier Unix relatif valide (par exemple etc/package.conf).

depend

Une dépendance d'exécution du paquet (composant virtuel ou paquet). Ce mot-clé peut être assigné zéro ou plusieurs fois. La valeur est une relation-de-paquet-alpm de type dépendance d'exécution (par exemple example ou example=1.0.0).

optdepend

Une dépendance optionnelle du paquet (composant virtuel ou paquet). Ce mot-clé peut être assigné zéro ou plusieurs fois. La valeur est une relation-de-paquet-alpm de type dépendance optionnelle (par exemple example ou example: ceci est une description).

makedepend

Une dépendance de compilation du paquet (composant virtuel ou paquet). Ce mot-clé peut être assigné zéro ou plusieurs fois. La valeur est une relation-de-paquet-alpm de type dépendance de compilation (par exemple example ou example=1.0.0).

checkdepend

Une dépendance pour exécuter les tests du projet en amont du paquet. Ce mot-clé peut être assigné zéro ou plusieurs fois. La valeur est une relation-de-paquet-alpm de type dépendance de test (par exemple example ou example=1.0.0).

EXEMPLES

pkgname = example
pkgbase = example
xdata = pkgtype=pkg
pkgver = 1:1.0.0-1
pkgdesc = Un projet qui fait quelque chose
url = https://example.org
builddate = 1729181726
packager = John Doe <john@example.org>
size = 181849963
arch = any
license = GPL-3.0-or-later
license = LGPL-3.0-or-later
replaces = other-package>0.9.0-3
group = package-group
group = other-package-group
conflict = conflicting-package<1.0.0
conflict = other-conflicting-package<1.0.0
provides = some-component
provides = some-other-component=1:1.0.0-1
backup = etc/example/config.toml
backup = etc/example/other-config.txt
depend = glibc
depend = gcc-libs
optdepend = python: pour special-python-script.py
optdepend = ruby: pour special-ruby-script.rb
makedepend = cmake
makedepend = python-sphinx
checkdepend = extra-test-tool
checkdepend = other-extra-test-tool
