NOM

PKCS12_create, PKCS12_create_ex, PKCS12_create_cb, PKCS12_create_ex2 - créer une structure PKCS#12

SYNTAXIS

 #include <openssl/pkcs12.h>
 PKCS12 *PKCS12_create(const char *pass, const char *name, EVP_PKEY *pkey,
                       X509 *cert, STACK_OF(X509) *ca,
                       int nid_key, int nid_cert, int iter, int mac_iter, int keytype);
 PKCS12 *PKCS12_create_ex(const char *pass, const char *name, EVP_PKEY *pkey,
                          X509 *cert, STACK_OF(X509) *ca, int nid_key, int nid_cert,
                          int iter, int mac_iter, int keytype,
                          OSSL_LIB_CTX *ctx, const char *propq);
 typedef int PKCS12_create_cb(PKCS12_SAFEBAG *bag, void *cbarg);
 PKCS12 *PKCS12_create_ex2(const char *pass, const char *name, EVP_PKEY *pkey,
                           X509 *cert, STACK_OF(X509) *ca, int nid_key, int nid_cert,
                           int iter, int mac_iter, int keytype,
                           OSSL_LIB_CTX *ctx, const char *propq,
                           PKCS12_create_cb *cb, void *cbarg);
=head1 DESCRIPTION

PKCS12_create() crée une structure PKCS#12.

pass est le mot de passe à utiliser. name est le friendlyName à utiliser pour le certificat et la clé fournis. pkey est la clé privée à inclure dans la structure et cert son certificat correspondant. ca, s'il n'est pas NULL, est un ensemble optionnel de certificats à inclure également dans la structure.

nid_key et nid_cert sont les algorithmes de chiffrement qui doivent être utilisés pour la clé et le certificat respectivement. Les modes GCM, CCM, XTS et OCB ne sont pas supportés. iter est le nombre d'itérations de l'algorithme de chiffrement à utiliser et mac_iter le nombre d'itérations du MAC à utiliser. keytype est le type de clé.

PKCS12_create_ex() est identique à PKCS12_create() mais permet un contexte de bibliothèque ctx et une requête de propriétés propq pour sélectionner les implémentations d'algorithmes.

PKCS12_create_ex2() est identique à PKCS12_create_ex() mais permet une fonction de rappel définie par l'utilisateur cb de type PKCS12_create_cb et un argument optionnel cbarg à passer à la fonction de rappel.

Si cb est spécifié, cette fonction sera appelée pour chaque sac sécurisé (safebag) ajouté à la structure PKCS12 et permet un traitement optionnel sur le sac sécurisé associé. Par exemple, l'un des usages pourrait être d'ajouter des attributs au sac sécurisé.

NOTES

Les paramètres nid_key, nid_cert, iter, mac_iter et keytype peuvent tous être mis à zéro et des valeurs par défaut raisonnables seront utilisées.

Ces valeurs par défaut sont : chiffrement par mot de passe (PBES2 avec PBKDF2 et AES-256-CBC) pour les clés privées et les certificats, le nombre d'itérations de PBKDF2 et MAC de PKCS12_DEFAULT_ITER (actuellement 2048), et l'algorithme MAC HMAC avec SHA2-256. L'algorithme de dérivation de clé MAC pour la structure PKCS#12 externe est PKCS12KDF.

Le nombre d'itérations par défaut est de 1 pour maintenir la compatibilité avec les anciens logiciels qui n'interprétaient pas les nombres d'itérations MAC. Si cette compatibilité n'est pas requise, mac_iter doit être défini à PKCS12_DEFAULT_ITER.

keytype ajoute un cadre au magasin de clés privées. Il s'agit d'une extension non standard qui n'est interprétée que par MSIE. S'il est défini sur zéro, le cadre est omis ; s'il est défini sur KEY_SIG, la clé ne peut être utilisée que pour la signature ; s'il est défini sur KEY_EX, elle peut être utilisée pour la signature et le chiffrement. Cette option était utile pour les anciens logiciels qui pouvaient utiliser des clés de signature de toute taille mais avaient des restrictions sur la taille des clés pouvant être utilisées pour le chiffrement.

Si name est NULL et cert contient un alias, celui-ci sera utilisé pour le friendlyName correspondant dans la structure PKCS12 au lieu de la clé. De même, si pkey est NULL et cert contient un keyid, celui-ci sera utilisé pour le localKeyID correspondant dans la structure PKCS12 au lieu de la clé calculée à partir de pkey.

Pour tous les certificats dans ca, si un certificat contient un alias ou un keyid, celui-ci sera utilisé pour le friendlyName ou le localKeyID correspondant dans la structure PKCS12.

Il peut être NULL pkey, cert ou les deux pour indiquer qu'aucune clé ou certificat n'est requis. Dans les versions précédentes, les deux devaient être présents ou une erreur fatale était renvoyée.

nid_key ou nid_cert peut être défini à -1 indiquant qu'aucun chiffrement ne doit être utilisé.

mac_iter peut être défini à -1 et le MAC sera complètement omis. Cela peut être utile lors de l'exécution avec le fournisseur FIPS, car PKCS12KDF n'est pas un algorithme approuvé par FIPS.

PKCS12_create() fait des suppositions sur le codage du mot de passe fourni. Voir passphrase-encoding(7) pour plus d'informations.

Si cb est spécifié, il doit renvoyer 1 en cas de succès et -1 en cas d'erreur fatale. Renvoyer 0 est considéré comme ne pas ajouter le sac sécurisé après tout.

VALEURS DE RETOUR

PKCS12_create() renvoie une structure PKCS12 valide ou NULL si une erreur s'est produite.

HISTORIQUE

PKCS12_create_ex() a été ajouté dans OpenSSL 3.0. PKCS12_create_ex2() a été ajouté dans OpenSSL 3.2.

Les valeurs par défaut pour les algorithmes de chiffrement, l'algorithme MAC et l'itération de dérivation de clé MAC ont été modifiées dans OpenSSL 3.0 pour suivre des standards plus modernes.
