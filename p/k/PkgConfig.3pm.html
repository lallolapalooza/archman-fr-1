NOM

PkgConfig - Remplacement Perl pour pkg-config

SYNOPSIS

Comme remplacement pour « pkg-config »

$ ppkg-config --libs --cflags --static gio-2.0
#sorties (lignes artificiellement coupées pour la lisibilité) :
# -I/usr/include/glib-2.0 -I/usr/lib/glib-2.0/include
# -pthread -lgio-2.0 -lz -lresolv -lgobject-2.0
# -lgmodule-2.0 -ldl -lgthread-2.0 -pthread -lrt -lglib-2.0

« pkg-config.pl » peut être utilisé comme alias pour « ppkg-config » sur les plateformes qui le prennent en charge. Il peut également être installé en tant que « pkg-config », bien que ce ne soit pas recommandé si votre système dispose d'un « pkg-config » natif.

Comparé à :

#sorties ( «  » ) :
# -pthread -I/usr/include/glib-2.0 -I/usr/lib/glib-2.0/include
# -pthread -lgio-2.0 -lz -lresolv -lgobject-2.0 -lgmodule-2.0
# -ldl -lgthread-2.0 -lrt -lglib-2.0

Depuis un autre module Perl

use PkgConfig;
my $o = PkgConfig->find('gio');
if($o->errmsg) {
    #gérer l'erreur
} else {
    my $prefix = $o->get_var('prefix');
    my @cflags = $o->get_cflags;
    my @ldflags = $o->get_ldflags;
}

DESCRIPTION

« PkgConfig » offre un remplacement Perl unique pour l'utilitaire « pkg-config ».

Ceci n'est pas une description des utilisations de « pkg-config », mais des différences entre la version C et la version Perl.

Alors que « pkg-config » est un exécutable compilé lié à glib, la version Perl n'a pas de telles exigences et peut être exécutée partout où Perl (>= 5.6) est présent.

Les options principales prises en charge sont :

les communes :

--libs

(Aussi) imprime les options de l'éditeur de liens. Les dépendances sont parcourues dans l'ordre. Les dépendances de niveau supérieur apparaissent avant les dépendances de niveau inférieur dans la ligne de commande.

--libs-only-L

Imprime la partie -L/-R de « --libs ». Définit le chemin de recherche des bibliothèques, mais sans bibliothèques à lier.

--libs-only-l

Imprime la partie -l de « --libs ».

--libs-only-other

Imprime la partie de « --libs » qui n'est pas couverte par « --libs-only-L » et « --libs-only-l », comme « --pthread ».

--list-all

Liste tous les paquets connus.

--cflags

(Aussi) imprime les options du compilateur et du préprocesseur C.

--cflags-only-I

Imprime la partie -I de « --cflags ».

--cflags-only-other

Imprime les parties de « --cflags » qui ne sont pas couvertes par « --cflags-only-I ».

--modversion

Imprime la version d'un paquet donné.

--static

Utilise les dépendances et les bibliothèques supplémentaires si vous liez avec une version statique du paquet demandé.

--exists

Retourne succès (0) si le paquet existe dans le chemin de recherche.

--with-path=PATH

Ajoute « PATH » à la liste des chemins de recherche qui contiennent les fichiers « .pc ».

Cette option peut être spécifiée plusieurs fois avec différents chemins et tous seront ajoutés.

--env-only

En utilisant cette option, seuls les chemins spécifiés dans « PKG_CONFIG_PATH » sont reconnus et tous les défauts codés en dur sont ignorés.

--guess-paths

Appelle « gcc » et « ld » pour déterminer les chemins par défaut de l'éditeur de liens et des includes. Les chemins par défaut sont exclus des options explicites -L et -I.

--define-variable=VARIABLE=VALUE

Définit une variable, remplacée par toute définition dans le fichier .pc, et permet à votre valeur d'être interpolée avec des utilisations ultérieures.

--variable=VARIABLE

Retourne la valeur d'une variable définie dans un fichier .pc du paquet.

--print-variables

Imprime toutes les variables définies dans les fichiers .pc.

--version

La version émulée de « pkg-config ».

--real-version

La version réelle de ce script.

--debug

Imprime des informations de débogage.

--silence-errors

Désactive les erreurs. C'est le défaut pour les arguments non-librairie/cflag/modversion.

--print-errors

Imprime les erreurs sur STDERR et a la priorité sur « --silence-errors ».

--short-errors

Ignoré, mais reconnu pour la compatibilité.

--errors-to-stdout

Imprime les erreurs sur STDOUT et a la priorité sur « --print-errors ».

ENVIRONNEMENT

Les variables « PKG_CONFIG_PATH » et « PKG_CONFIG_LIBDIR » sont respectées et utilisées comme une liste séparée par des deux-points (: ; sous Windows).

D'autres variables d'environnement reconnues par « pkg-config » et PkgConfig incluent :

PKG_CONFIG_ALLOW_SYSTEM_CFLAGS
PKG_CONFIG_ALLOW_SYSTEM_LIBS

Si Win32API::Registry est installé, sous Windows (mais pas sous Cygwin), PkgConfig consultera également ces clés de registre. Les noms sont ignorés, mais les valeurs sont des chemins contenant des fichiers .pc.

HKEY_CURRENT_USER\Software\pkgconfig\PKG_CONFIG_PATH
HKEY_LOCAL_MACHINE\Software\pkgconfig\PKG_CONFIG_PATH

Le support du registre devrait être considéré comme expérimental, susceptible d'évoluer à l'avenir, bien que pas sans bonne raison. La raison de cet avertissement est que cette fonctionnalité est documentée à plusieurs endroits, mais je n'ai pas encore trouvé d'implémentation fonctionnelle qui réalise cette fonctionnalité.

Options du module

PkgConfig->find

mon $resultat = PkgConfig->trouver($librairie, %options);

Trouve une librairie et retourne un objet résultat. « $librairie » peut être un nom de librairie seul ou un tableau de noms de librairies.

Les options sont sous forme de paires clé-valeur, et sont reconnues comme suit :

"search_path"
"search_path_override"
Précède les chemins de recherche supplémentaires dans le chemin spécifié dans $ENV{PKG_CONFIG_PATH}. La valeur est une référence de tableau. La variante « _override » ignore les valeurs par défaut (comme « PKG_CONFIG_PATH »).
"file_path"
Indique le chemin complet du fichier .pc que vous souhaitez charger. Il n'a pas besoin d'être dans le chemin de recherche (bien que les dépendances devront l'être). Utile si vous connaissez le chemin complet du fichier .pc exact que vous voulez.
"exclude_cfl" (non terminé)

PkgConfig(3pm)

NAME

PkgConfig - Perl interface to the pkg-config utility

SYNOPSIS 

  use PkgConfig;

  my $pkg = PkgConfig->new('gtk+-3.0', 'glib-2.0');
  if ($pkg->pkg_exists) {
    print "-I", join(" -I", $pkg->get_cflags), "\n";
    print $pkg->get_ldflags, "\n";
  }

  my $pkg_no_deps = PkgConfig->new('gtk+-3.0', { no_recurse => 1 });
  if ($pkg_no_deps->pkg_exists) {
    # ...
  }

  my $pkg_with_vars = PkgConfig->new('gtk+-3.0', {
    VARS => {
      prefix => '/usr',
      libdir => '/usr/lib',
    }
  });

DESCRIPTION

This module provides a Perl interface to the pkg-config utility.

"exclude_ldflags_override"
Some ".pc" files specify default compiler and linker paths, for example "-I/usr/include -L/usr/lib". Specifying these on the command line can be problematic, as it drastically alters the search order.

The above options will add to or replace the excluded and filtered options.

The default linker and compiler options can be obtained via @PkgConfig::DEFAULT_EXCLUDE_LFLAGS and @PkgConfig::DEFAULT_EXCLUDE_CFLAGS, respectively.

"static"
Also, specifies static libraries.
"no_recurse"
Do not recurse into dependencies. This is useful for only doing version checks.
"VARS"
Define a hashref of variables to replace any variable definitions within the .pc files. This is equivalent to the command line --define-variable option.

A PkgConfig object is returned and can be queried about the results:

$o->errmsg

An error message, if any. This is a string and indicates an error.

$o->pkg_exists

Boolean, true if the package exists.

$o->pkg_version

The version of the package.

$o->get_cflags

Returns the compiler flags.

$o->get_ldflags

Returns the linker flags.

In list context, these methods return a list with each argument split on unescaped spaces.

In list context returns a list of compiler and linker flags, respectively.

In scalar context returns a string of compiler and linker flags with spaces and quotes correctly escaped.

$o->get_var($name)

Gets the variable with the given name.

PkgConfig::Guess

This is a class method, and will replace the default linker and include paths with those discovered by invoking ld(1) and cpp(1).

Currently only works with the ld and cpp provided by GCC.

INSTALL

The Makefile.PL that comes with PkgConfig can take one or more --script options to rename the scripts or scripts that are installed.

--script ppkg-config
This is the default and works on all platforms
--script pkg-config.pl
This is installed by default on all platforms except Windows, where the .pl might confuse the shell and cause the script to open in a text editor.
--script pkg-config
This is the default name of the real pkg-config and so must be explicitly enabled if desired.
--script none
Do not install any scripts.

Example, installing all script names:

% perl Makefile.PL --script ppkg-config --script pkg-config.pl --script pkg-config

Example, do not install any scripts:

% perl Makefile.PL --script none

You can also set the PERL_PKG_CONFIG_SCRIPTS environment variable to the desired value (separating each script name with a comma ,) to ensure that future updates of PkgConfig do the same.

CAVEATS

On Strawberry Perl "ppkg-config" acts like Strawberry is the system. This means that

  • The .pc files that ship with Strawberry are looked up by default.
  • The Strawberry include and library folders are used to calculate exclude lists.

As of Strawberry 5.20.0.1, PkgConfig is bundled with Strawberry and pkg-config is installed by default (though ppkg-config is not bundled with Strawberry).

For details on how to fix the .pc files from older versions of Strawberry, see the README.win32 that ships with this distribution.

BUGS

The order of flags is not exactly the same as with pkg-config. From my own observation, it seems this module does a better job, but I could be wrong.

Unlike pkg-config, the --exists function of the scripts will return non-zero if a package or any of its dependencies is missing. This differs from pkg-config's behavior, which only checks for the definition of the package itself (without dependencies).
