PKCS7_VERIFY(3ssl) OpenSSL PKCS7_VERIFY(3ssl)

NOM

PKCS7_verify, PKCS7_get0_signers - vérifier une structure signedData PKCS#7

SYNOPSIS

#include <openssl/pkcs7.h>
int PKCS7_verify(PKCS7 *p7, STACK_OF(X509) *certs, X509_STORE *store,
                 BIO *indata, BIO *out, int flags);
STACK_OF(X509) *PKCS7_get0_signers(PKCS7 *p7, STACK_OF(X509) *certs, int flags);

DESCRIPTION

PKCS7_verify() est très similaire à CMS_verify(3). Elle vérifie une structure signedData PKCS#7 donnée dans p7. Le paramètre optionnel certs fait référence à un ensemble de certificats dans lequel rechercher les certificats du signataire. Il est également utilisé comme source de certificats d'AC intermédiaires non fiables pour la construction de la chaîne. p7 peut contenir des certificats d'AC supplémentaires non fiables qui peuvent être utilisés pour la construction de la chaîne ainsi que des CRL qui peuvent être utilisés pour la validation des certificats. store peut être NULL ou pointer vers le magasin de certificats de confiance à utiliser pour la vérification de la chaîne. indata fait référence aux données signées si le contenu est détaché de p7. Sinon, indata doit être NULL, et alors les données signées doivent être dans p7. Le contenu est écrit dans le BIO out sauf s'il est NULL. flags est un ensemble optionnel d'indicateurs qui peuvent être utilisés pour modifier l'opération.

PKCS7_get0_signers() récupère les certificats du signataire à partir de p7, elle ne vérifie pas leur validité ni si des signatures sont valides. Les paramètres certs et flags ont les mêmes significations que dans PKCS7_verify().

PROCESSUS DE VERIFICATION

Normalement, le processus de vérification se déroule comme suit.

Initialement, quelques vérifications de cohérence sont effectuées sur p7. Le type de p7 doit être SignedData. Il doit y avoir au moins une signature sur les données et si le contenu est détaché, indata ne peut pas être NULL. Si le contenu n'est pas détaché et que indata n'est pas NULL, alors la structure a un contenu à la fois intégré et externe. Pour traiter cela comme une erreur, utilisez l'indicateur PKCS7_NO_DUAL_CONTENT. Le comportement par défaut le permet, par souci de compatibilité avec les anciennes versions d'OpenSSL.

Une tentative est faite pour localiser tous les certificats du signataire, en cherchant d'abord dans le paramètre certs (s'il n'est pas NULL). Ensuite, ils sont recherchés dans tous les certificats contenus dans la structure p7, à moins que PKCS7_NOINTERN ne soit défini. Si un des certificats du signataire ne peut être localisé, l'opération échoue.

Chaque certificat de signataire est vérifié en chaîne en utilisant le but smimesign et le magasin de certificats de confiance store s'il est fourni. Tous les certificats internes du message, qui peuvent avoir été ajoutés à l'aide de PKCS7_add_certificate(3), sont utilisés comme AC non fiables, à moins que PKCS7_NOCHAIN ne soit défini. Si la vérification CRL est activée dans store et que PKCS7_NOCRL n'est pas défini, tous les CRL internes, qui peuvent avoir été ajoutés à l'aide de PKCS7_add_crl(3), sont utilisés en plus de tenter de les rechercher dans store. Si store n'est pas NULL et qu'une vérification de chaîne échoue, un code d'erreur est retourné.

Enfin, le contenu signé est lu (et écrit dans out sauf s'il est NULL) et la signature est vérifiée.

Si toutes les signatures sont vérifiées correctement, la fonction réussit.

N'importe lequel des indicateurs suivants (combinés par OU bit à bit) peut être passé dans le paramètre flags pour modifier le comportement de vérification par défaut. Seul l'indicateur PKCS7_NOINTERN est significatif pour PKCS7_get0_signers().

Si PKCS7_NOINTERN est défini, les certificats dans le message lui-même ne sont pas recherchés lors de la localisation des certificats du signataire. Cela signifie que tous les certificats du signataire doivent être dans le paramètre certs.

Si PKCS7_NOCRL est défini et que la vérification CRL est activée dans store, alors tous les CRL dans le message lui-même sont ignorés.

Si l'indicateur PKCS7_TEXT est défini, les en-têtes MIME de type "text/plain" sont supprimés du contenu. Si le contenu n'est pas de type "text/plain", une erreur est retournée.

Si PKCS7_NOVERIFY est défini, les certificats du signataire ne sont pas vérifiés en chaîne.

Si PKCS7_NOCHAIN est défini, alors les certificats contenus dans le message ne sont pas utilisés comme AC non fiables. Cela signifie que toute la chaîne de vérification (à l'exception des certificats du signataire) doit être contenue dans le magasin de confiance.

Si PKCS7_NOSIGS est défini, alors les signatures sur les données ne sont pas vérifiées.

NOTES

Une application de PKCS7_NOINTERN consiste à n'accepter que les messages signés par un petit nombre de certificats. Les certificats acceptables seraient passés dans le paramètre certs. Dans ce cas, si le certificat du signataire n'est pas l'un des certificats fournis dans certs, la vérification échouera car le signataire ne peut pas être trouvé.

Il faut faire attention lors de la modification du comportement de vérification par défaut, par exemple, définir "PKCS7_NOVERIFY|PKCS7_NOSIGS" désactivera totalement toute vérification et tout message signé sera considéré comme valide. Cette combinaison est cependant utile si l'on souhaite simplement écrire le contenu dans out et que sa validité n'est pas considérée comme importante.

La vérification de chaîne devrait, selon toute vraisemblance, être effectuée en utilisant l'heure de signature plutôt que l'heure actuelle. Cependant, puisque l'heure de signature est fournie par le signataire, elle ne peut pas être fiable sans preuve supplémentaire (comme un horodatage de confiance).

VALEUR DE RETOUR

PKCS7_verify() retourne 1 en cas de succès de la vérification et 0 si une erreur se produit.

PKCS7_get0_signers() retourne tous les signataires ou NULL si une erreur s'est produite.

L'erreur peut être obtenue à partir de ERR_get_error(3).

BOGUES

Le magasin de certificats de confiance n'est pas recherché pour les certificats du signataire. Ceci est principalement dû aux insuffisances de la fonctionnalité actuelle d'X509_STORE.

L'absence de traitement en une seule passe signifie que le contenu signé doit être entièrement conservé en mémoire s'il n'est pas détaché.
