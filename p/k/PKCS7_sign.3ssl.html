Paquet: openssl

Licences: Apache-2.0

PKCS7_SIGN(3ssl) OpenSSL PKCS7_SIGN(3ssl)

NOM

PKCS7_sign_ex, PKCS7_sign - créer une structure PKCS#7 signedData

SYNTAXE

#include <openssl/pkcs7.h>
PKCS7 *PKCS7_sign_ex(X509 *signcert, EVP_PKEY *pkey, STACK_OF(X509) *certs,
                     BIO *data, int flags, OSSL_LIB_CTX *libctx,
                     const char *propq);
PKCS7 *PKCS7_sign(X509 *signcert, EVP_PKEY *pkey, STACK_OF(X509) *certs,
                  BIO *data, int flags);

DESCRIPTION

PKCS7_sign_ex() crée et retourne une structure PKCS#7 signedData. signcert est le certificat utilisé pour la signature, pkey est la clé privée correspondante. certs est un ensemble optionnel de certificats supplémentaires à inclure dans la structure PKCS#7 (par exemple, les CA intermédiaires de la chaîne). Le contexte de bibliothèque libctx et la requête de propriétés propq sont utilisés pour récupérer les algorithmes auprès des fournisseurs.

Les données à signer sont lues depuis le BIO data.

flags est un ensemble optionnel d'indicateurs.

N'importe lesquels des indicateurs suivants (combinés par OR) peuvent être passés dans le paramètre flags.

De nombreux clients S/MIME s'attendent à ce que le contenu signé inclue des en-têtes MIME valides. Si l'indicateur PKCS7_TEXT est défini, des en-têtes MIME de type "text/plain" sont précédés aux données.

Si PKCS7_NOCERTS est défini, le certificat du signataire et les certificats supplémentaires certs ne seront pas inclus dans la structure PKCS7. Le certificat du signataire doit cependant toujours être fourni dans le paramètre signcert. Cela peut réduire la taille des signatures si les certificats du signataire peuvent être obtenus par d'autres moyens : par exemple, un message précédemment signé.

Les données signées sont incluses dans la structure PKCS7, sauf si PKCS7_DETACHED est défini, auquel cas elles sont omises. Ceci est utilisé pour les signatures PKCS7 détachées qui sont utilisées dans les messages signés en texte brut S/MIME, par exemple.

Normalement, le contenu fourni est traduit en format canonique MIME (comme requis par les spécifications S/MIME). Si PKCS7_BINARY est défini, aucune traduction n'a lieu. Cette option doit être utilisée si les données fournies sont en format binaire, sinon la traduction les corrompra.

La structure signedData inclut plusieurs PKCS#7 authenticatedAttributes y compris l'heure de signature, le type de contenu PKCS#7 et la liste des chiifres pris en charge dans un attribut SMIMECapabilities. Si PKCS7_NOATTR est défini, aucun authenticatedAttributes ne sera utilisé. Si PKCS7_NOSMIMECAP est défini, seuls les SMIMECapabilities sont omis.

Si présent, l'attribut SMIMECapabilities indique la prise en charge des algorithmes suivants : triple DES, RC2 128 bits, RC2 64 bits, DES et RC2 40 bits. Si l'un de ces algorithmes est désactivé, il ne sera pas inclus.

Si l'indicateur PKCS7_STREAM est défini, la structure PKCS7 retournée est juste initialisée pour effectuer l'opération de signature. La signature n'est cependant pas effectuée et les données à signer ne sont pas lues à partir du paramètre data. La signature est différée jusqu'à ce que les données aient été écrites. De cette manière, les données peuvent être signées en une seule passe.

Si l'indicateur PKCS7_PARTIAL est défini, une structure PKCS7 partielle est générée, à laquelle des signataires et des capacités supplémentaires peuvent être ajoutés avant la finalisation.

Si l'indicateur PKCS7_STREAM est défini, la structure PKCS7 retournée n'est pas complète et son affichage via une fonction qui ne finalise pas correctement la structure PKCS7 donnera des résultats imprévisibles.

Plusieurs fonctions, y compris SMIME_write_PKCS7(), i2d_PKCS7_bio_stream(), PEM_write_bio_PKCS7_stream(), finalisent la structure. Alternativement, la finalisation peut être effectuée en obtenant directement le BIO ASN1 en streaming à l'aide de BIO_new_PKCS7().

Si un signataire est spécifié, il utilisera le digest par défaut pour l'algorithme de signature. Il s'agit de SHA256 pour les clés RSA et DSA.

Les paramètres certs, signcert et pkey peuvent tous être NULL si l'indicateur PKCS7_PARTIAL est défini. Un ou plusieurs signataires peuvent être ajoutés en utilisant la fonction PKCS7_sign_add_signer(). PKCS7_final() doit également être appelé pour finaliser la structure si le streaming n'est pas activé. Des digests de signature alternatifs peuvent également être spécifiés en utilisant cette méthode.

Si signcert et pkey sont NULL, une structure PKCS#7 contenant uniquement des certificats est générée.

Dans les versions d'OpenSSL antérieures à 1.0.0, les paramètres signcert et pkey ne doivent pas être NULL.

PKCS7_sign() est similaire à PKCS7_sign_ex(), sauf qu'il utilise les valeurs par défaut NULL pour le contexte de bibliothèque libctx et la requête de propriétés propq. Ceci est conservé pour la compatibilité de l'API.

BOGUES

Certains attributs avancés tels que les contre-signatures ne sont pas pris en charge.

VALEURS DE RETOUR

PKCS7_sign_ex() et PKCS7_sign() retournent soit une structure PKCS7 valide, soit NULL en cas d'erreur. L'erreur peut être obtenue à partir de ERR_get_error(3).

VOIR AUSSI

ERR_get_error(3), PKCS7_verify(3)

HISTORIQUE

La fonction PKCS7_sign_ex() a été ajoutée dans OpenSSL 3.0.

L'indicateur PKCS7_PARTIAL, et la possibilité pour les paramètres certs, signcert et pkey d'être NULL ont été ajoutés dans OpenSSL 1.0.0.

L'indicateur PKCS7_STREAM a été ajouté dans OpenSSL 1.0.0.
