PKCS7_encrypt(3ssl)

Paquet: openssl

Licences: Apache-2.0

PKCS7_ENCRYPT(3ssl) OpenSSL PKCS7_ENCRYPT(3ssl)

NOM

PKCS7_encrypt_ex, PKCS7_encrypt - créer une structure envelopedData PKCS#7

SYNTAXE

#include <openssl/pkcs7.h>
PKCS7 *PKCS7_encrypt_ex(STACK_OF(X509) *certs, BIO *in,
                        const EVP_CIPHER *cipher, int flags,
                        OSSL_LIB_CTX *libctx, const char *propq);
PKCS7 *PKCS7_encrypt(STACK_OF(X509) *certs, BIO *in, const EVP_CIPHER *cipher,
                     int flags);

DESCRIPTION

PKCS7_encrypt_ex() crée et retourne une structure envelopedData PKCS#7. certs est une liste de certificats de destinataires. in est le contenu à chiffrer. cipher est le chiffrement symétrique à utiliser. flags est un ensemble optionnel de drapeaux. Le contexte de bibliothèque libctx et la requête de propriété propq sont utilisés lors de la récupération des algorithmes auprès des fournisseurs.

Seules les clés RSA sont prises en charge dans PKCS#7 et envelopedData, les certificats de destinataires fournis à cette fonction doivent donc tous contenir des clés publiques RSA, bien qu'ils n'aient pas besoin d'être signés à l'aide de l'algorithme RSA.

EVP_des_ede3_cbc() (triple DES) est l'algorithme de choix pour l'utilisation S/MIME car la plupart des clients le prendront en charge.

Certains anciens clients "grade export" ne peuvent prendre en charge qu'un chiffrement faible utilisant RC2 40 ou 64 bits. Ceux-ci peuvent être utilisés en passant EVP_rc2_40_cbc() et EVP_rc2_64_cbc() respectivement.

L'algorithme passé dans le paramètre cipher doit prendre en charge le codage ASN1 de ses paramètres.

De nombreux navigateurs implémentent une option "signer et chiffrer", qui n'est simplement qu'un envelopedData S/MIME contenant un message signé S/MIME. Ceci peut être facilement produit en stockant le message signé S/MIME dans un BIO mémoire et en le passant à PKCS7_encrypt().

Les drapeaux suivants peuvent être passés dans le paramètre flags.

Si le drapeau PKCS7_TEXT est défini, les en-têtes MIME de type text/plain sont préfixés aux données.

Normalement, le contenu fourni est traduit au format canonique MIME (tel qu'exigé par les spécifications S/MIME) ; si PKCS7_BINARY est défini, aucune traduction n'a lieu. Cette option doit être utilisée si les données fournies sont au format binaire, sinon la traduction les corrompra. Si PKCS7_BINARY est défini, alors PKCS7_TEXT est ignoré.

Si le drapeau PKCS7_STREAM est défini, une structure PKCS7 partielle est générée, adaptée aux E/S en flux : aucune donnée n'est lue depuis le BIO in.

Si le drapeau PKCS7_STREAM est défini, la structure PKCS7 retournée n'est pas complète et la sortie de son contenu via une fonction qui ne finalise pas correctement la structure PKCS7 donnera des résultats imprévisibles.

Plusieurs fonctions, y compris SMIME_write_PKCS7(), i2d_PKCS7_bio_stream(), PEM_write_bio_PKCS7_stream(), finalisent la structure. Alternativement, la finalisation peut être effectuée en obtenant directement le BIO ASN1 de flux à l'aide de BIO_new_PKCS7().

PKCS7_encrypt() est similaire à PKCS7_encrypt_ex() mais utilise les valeurs par défaut NULL pour le contexte de bibliothèque libctx et la requête de propriété propq.

VALEURS DE RETOUR

PKCS7_encrypt_ex() et PKCS7_encrypt() retournent soit une structure PKCS7, soit NULL si une erreur s'est produite. L'erreur peut être obtenue via ERR_get_error(3).

VOIR AUSSI

ERR_get_error(3), PKCS7_decrypt(3)

HISTORIQUE

La fonction PKCS7_encrypt_ex() a été ajoutée dans OpenSSL 3.0.

Le drapeau PKCS7_STREAM a été ajouté dans OpenSSL 1.0.0.
