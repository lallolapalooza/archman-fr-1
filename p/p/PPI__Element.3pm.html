PPI::Element(3) Documentation Perl fournie par les contributeurs PPI::Element(3)

NOM

PPI::Element - La classe Element abstraite, une base pour tous les objets source

HÉRÉDITÉ

PPI::Element est la racine de l'arbre PDOM

DESCRIPTION

La classe abstraite "PPI::Element" sert de classe de base pour tous les objets liés à la source, d'un seul jeton d'espace blanc à un document entier. Elle fournit un ensemble de méthodes de base pour offrir une interface commune et des implémentations de base.

MÉTHODES

significant

Étant donné que nous traitons les espaces blancs et autres éléments non-code comme des Jetons (afin de pouvoir "round-tripper" le PPI::Document vers un fichier), la méthode "significant" nous permet de distinguer les jetons qui font partie du code, et les jetons qui ne sont pas significatifs, tels que les espaces blancs, le POD, ou la partie d'un fichier après (et incluant) le jeton "__END__".

Retourne vrai si l'Élément est significatif, ou faux sinon.

class

La méthode "class" est fournie par commodité, et ne fait en réalité rien d'autre que de retourner ref($self). Cependant, certaines personnes ont trouvé qu'elles appréciaient la paresse de "$Foo->class eq 'whatever'", j'ai donc cédé à la demande populaire et l'ai incluse.

Retourne la classe de l'Élément sous forme de chaîne.

tokens

La méthode "tokens" retourne une liste d'objets PPI::Token pour l'Élément, récupérant essentiellement cette partie du document comme si elle n'avait pas été lexée.

Cela signifie également qu'il n'y a pas d'Instructions ni de Structures dans la liste, uniquement les classes de Jetons.

content

Pour n'importe quel "PPI::Element", la méthode "content" reconstitue le code de base sous forme d'une seule chaîne. Cette méthode est également celle utilisée pour surcharger la stringification. Lorsqu'un Élément est utilisé dans une chaîne entre guillemets doubles, par exemple, c'est cette méthode qui est appelée.

ATTENTION:

Vous devez être conscient que, compte tenu de la manière dont les here-docs sont gérés, le contenu des here-doc n'est pas inclus dans "content", et par conséquent, vous ne devriez pas évaluer ou exécuter le résultat s'il contient des PPI::Token::HereDoc.

La méthode PPI::Document "serialize" doit être utilisée pour convertir un document PDOM en quelque chose qui peut être exécuté comme prévu.

Retourne le code de base sous forme de chaîne (excluant le contenu des here-docs).

parent

Les Éléments eux-mêmes ne sont pas conçus pour contenir d'autres Éléments, cette tâche est laissée à la classe abstraite PPI::Node, une sous-classe de "PPI::Element". Cependant, tous les Éléments peuvent être contenus dans un Nœud parent.

Si un Élément est à l'intérieur d'un Nœud parent, la méthode "parent" retourne le Nœud.

descendant_de $element

Indique si un "PPI::Element" est contenu dans un autre.

Les "PPI::Element"s sont considérés comme des descendants d'eux-mêmes.

ancestor_de $element

Indique si un "PPI::Element" en contient un autre.

Les "PPI::Element"s sont considérés comme des ancêtres d'eux-mêmes.

statement

Pour un "PPI::Element" qui est contenu (à une certaine profondeur) dans une PPI::Statement, la méthode "statement" retournera le premier objet Instruction parent se trouvant lexicalement "au-dessus" de l'Élément.

Retourne un objet PPI::Statement, qui peut être le même Élément si l'Élément est lui-même un objet PPI::Statement.

Retourne faux si l'Élément n'est pas à l'intérieur d'une Instruction et n'est pas une Instruction lui-même.

top

Pour un "PPI::Element" qui est contenu dans un arbre PDOM, la méthode "top" retournera le Nœud de plus haut niveau de l'arbre. La plupart du temps, il devrait s'agir d'un objet PPI::Document, mais ce ne sera pas toujours le cas. Par exemple, si une sous-routine a été retirée de son Document pour être déplacée vers un autre Document.

Retourne l'objet PDOM le plus haut, qui peut être le même Élément s'il n'est pas contenu dans un objet PDOM parent.

document

Pour un Élément contenu dans un objet PPI::Document, la méthode "document" retournera le Document de plus haut niveau pour l'Élément.

Retourne le PPI::Document pour cet Élément, ou faux si l'Élément n'est pas contenu dans un Document.

next_sibling

Tous les objets PPI::Node (spécifiquement, notre Nœud parent) contiennent un certain nombre d'objets "PPI::Element". La méthode "next_sibling" retourne le "PPI::Element" qui suit immédiatement le courant, ou faux s'il n'y a pas de frère suivant.

snext_sibling

Comme pour les autres méthodes commençant par 's', la méthode "snext_sibling" retourne le prochain frère significatif de l'objet "PPI::Element".

Retourne un objet "PPI::Element", ou faux s'il n'y a pas de frère significatif 'suivant'.

previous_sibling

Tous les objets PPI::Node (spécifiquement, notre Nœud parent) contiennent un certain nombre d'objets "PPI::Element". La méthode "previous_sibling" retourne l'Élément qui précède immédiatement le courant, ou faux s'il n'y a pas d'objet "PPI::Element" 'précédent'.

sprevious_sibling

Comme pour les autres méthodes commençant par 's', la méthode "sprevious_sibling" retourne le frère significatif précédent de l'objet "PPI::Element".

Retourne un objet "PPI::Element", ou faux s'il n'y a pas de frère significatif 'précédent'.

first_token

En tant que méthode de support pour les algorithmes de haut niveau traitant spécifiquement des jetons et du contenu Perl réel, la méthode "first_token" trouve le premier objet PPI::Token à l'intérieur ou égal à celui-ci.

C'est-à-dire, si elle est appelée sur une sous-classe de PPI::Node, elle descendra jusqu'à trouver un PPI::Token. Si elle est appelée sur un objet PPI::Token, elle retournera le même objet.

Retourne un objet PPI::Token, ou plante en cas d'erreur (ce qui devrait être extrêmement rare et ne se produire que si un PPI::Statement vide illégal existe quelque part sous l'Élément courant).

last_token

En tant que méthode de support pour les algorithmes de haut niveau traitant spécifiquement des jetons et du contenu Perl réel, la méthode "last_token" trouve le dernier objet PPI::Token à l'intérieur ou égal à celui-ci.

C'est-à-dire, si elle est appelée sur une sous-classe de PPI::Node, elle descendra jusqu'à trouver un PPI::Token. Si elle est appelée sur un objet PPI::Token, elle retournera le même objet.

Retourne un objet PPI::Token, ou plante en cas d'erreur (ce qui devrait être extrêmement rare et ne se produire que si un PPI::Statement vide illégal existe quelque part sous l'Élément courant).

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

find_token

This method is used to find the first PPI::Token object that is part of the given Element.

If called on a PPI::Node subclass, it will descend until it finds a PPI::Token. If called on a PPI::Token object, it will return the itself.

Returns a PPI::Token object, or dies on error (which should be extremely rare and only occur if an illegal empty PPI::Statement exists below the current Element somewhere.)

next_token

En tant que méthode de support pour les algorithmes d'ordre supérieur qui traitent spécifiquement des jetons et du contenu Perl réel, la méthode "next_token" trouve l'objet PPI::Token qui se trouve immédiatement après l'Element courant, même s'il ne se trouve pas dans le même parent PPI::Node que celui pour lequel la méthode est appelée.

Notez que ce n'est pas défini comme une méthode spécifique à PPI::Token, car il peut être utile de trouver le jeton suivant qui se trouve après, par exemple, un PPI::Statement, bien qu'il soit évidemment inutile de vouloir le jeton suivant après un PPI::Document.

Retourne un objet PPI::Token, ou false s'il n'y a plus de jetons après l'Element.

previous_token

En tant que méthode de support pour les algorithmes d'ordre supérieur qui traitent spécifiquement des jetons et du contenu Perl réel, la méthode "previous_token" trouve l'objet PPI::Token qui se trouve immédiatement avant l'Element courant, même s'il ne se trouve pas dans le même parent PPI::Node que celui-ci.

Notez que ce n'est pas défini comme une méthode réservée à PPI::Token, car il peut être utile de trouver le jeton qui se trouve avant, par exemple, un PPI::Statement, bien qu'il soit évidemment inutile de vouloir le jeton suivant avant un PPI::Document.

Retourne un objet PPI::Token, ou false s'il n'y a plus de jetons avant l'"Element".

presumed_features

Retourne une table de hachage qui indique quelles fonctionnalités semblent être actives pour l'élément donné.

clone

Conformément au module Clone, la méthode "clone" crée une copie parfaite d'un objet Element. Dans le cas général, l'implémentation est effectuée à l'aide du mécanisme du module Clone lui-même. Dans les cas d'ordre supérieur, comme pour les Nœuds, il y a plus de travail impliqué pour maintenir intacts les liens parent-enfant.

insert_before @Elements

La méthode "insert_before" vous permet d'insérer du contenu lexical Perl, sous forme d'objets "PPI::Element", avant l'appel de la méthode "Element". Vous devez être très prudent lors de la modification du code Perl, car il est facile de tout casser.

Dans sa première incarnation, cette méthode vous permet d'insérer un seul Element et effectuera des vérifications de base pour vous empêcher d'insérer quelque chose qui serait structurellement incorrect (en termes PDOM).

À l'avenir, cette méthode pourrait être améliorée pour permettre l'insertion de plusieurs Elements, de chaînes de code analysées en ligne ou d'objets PPI::Document::Fragment.

Retourne true si l'Element a été inséré, false s'il ne peut pas être inséré, ou "undef" si vous ne fournissez pas d'objet "PPI::Element" en paramètre.

insert_after @Elements

La méthode "insert_after" vous permet d'insérer du contenu lexical Perl, sous forme d'objets "PPI::Element", après l'appel de la méthode "Element". Vous devez être très prudent lors de la modification du code Perl, car il est facile de tout casser.

Dans sa première incarnation, cette méthode vous permet d'insérer un seul Element et effectuera des vérifications de base pour vous empêcher d'insérer quelque chose qui serait structurellement incorrect (en termes PDOM).

À l'avenir, cette méthode pourrait être améliorée pour permettre l'insertion de plusieurs Elements, de chaînes de code analysées en ligne ou d'objets PPI::Document::Fragment.

Retourne true si l'Element a été inséré, false s'il ne peut pas être inséré, ou "undef" si vous ne fournissez pas d'objet "PPI::Element" en paramètre.

remove

Pour un "PPI::Element" donné, la méthode "remove" le supprimera de son parent intact, avec tous ses enfants.

Retourne l'"Element" lui-même par commodité, ou "undef" si une erreur se produit lors de la tentative de suppression de l'"Element".

delete

Pour un "PPI::Element" donné, la méthode "delete" le supprimera de son parent, en supprimant immédiatement l'"Element" et tous ses enfants (s'il en a).

Retourne true si l'"Element" a été supprimé avec succès, ou "undef" si une erreur se produit lors de la tentative de suppression de l'"Element".

replace $Element

Bien que certaines classes de niveau supérieur prennent en charge des formes plus exotiques de remplacement, au niveau de base, la méthode "replace" prend un seul "Element" comme argument et remplace l'"Element" courant par celui-ci.

Pour éviter des dommages accidentels au code, dans cette implémentation initiale, l'élément de remplacement doit être de la même classe (ou d'une sous-classe) que celui qui est remplacé.

En cas de succès, retourne l'élément de remplacement. Sinon, retourne "undef".

location

Si l'Element existe dans un PPI::Document qui a indexé les emplacements des éléments à l'aide de "PPI::Document::index_locations", la méthode "location" retournera l'emplacement du premier caractère de l'Element dans le Document.

Retourne l'emplacement sous forme de référence à un tableau de cinq éléments sous la forme "[ $ligne, $caractere_ligne, $colonne, $ligne_logique, $nom_fichier_logique ]". Les valeurs sont au format lisible, le premier caractère du fichier étant situé à "[ 1, 1, 1, ?, 'quelque chose' ]".

Les deuxième et troisième nombres sont similaires, à la différence que le deuxième est le caractère horizontal littéral, et le troisième est la colonne visuelle, en tenant compte des tabulations (voir "tab_width [ $largeur ]" dans PPI::Document).

Le quatrième nombre est le numéro de ligne, en tenant compte des directives "#line". Le cinquième élément est le nom du fichier dans lequel l'élément a été trouvé, le cas échéant, en tenant compte des directives "#line".

Retourne "undef" en cas d'erreur, ou si l'objet PPI::Document n'a pas été indexé.

line_number

Si l'Element existe dans un PPI::Document qui a indexé les emplacements des éléments à l'aide de "PPI::Document::index_locations", la méthode "line_number" retournera le numéro de ligne du premier caractère de l'Element dans le Document.

Retourne "undef" en cas d'erreur, ou si l'objet PPI::Document n'a pas été indexé.

column_number

Si l'Element existe dans un PPI::Document qui a indexé les emplacements des éléments à l'aide de "PPI::Document::index_locations", la méthode "column_number" retournera le numéro de colonne du premier caractère de l'Element dans le Document.

Retourne "undef" en cas d'erreur, ou si l'objet PPI::Document n'a pas été indexé.

visual_column_number

Si l'Element existe dans un PPI::Document qui a indexé les emplacements des éléments à l'aide de "PPI::Document::index_locations", la méthode "visual_column_number" retournera le numéro de colonne visuel du premier caractère de l'Element dans le Document, conformément à la valeur de "tab_width [ $largeur ]" dans PPI::Document.

Retourne "undef" en cas d'erreur, ou si l'objet PPI::Document n'a pas été indexé.

logical_line_number

Si l'Element existe dans un PPI::Document qui a indexé les emplacements des éléments à l'aide de "PPI::Document::index_locations", la méthode "logical_line_number" retournera le numéro de ligne du premier caractère de l'Element dans le Document, en tenant compte des directives "#line".

Retourne "undef" en cas d'erreur, ou si l'objet PPI::Document n'a pas été indexé.

logical_filename

Si l'Element existe dans un PPI::Document qui a indexé les emplacements des éléments à l'aide de "PPI::Document::index_locations", la méthode "logical_filename" retournera le nom de fichier logique contenant le premier caractère de l'Element dans le Document, en tenant compte des directives "#line".

Retourne

NOM

PPI::Element

HIÉRARCHIE

PPI::Element

DESCRIPTION

PPI::Element est un module qui fournit une classe pour représenter les éléments textuels d'un document, tels que des balises, des phrases ou toute structure textuelle pouvant être indexée.

MÉTHODES

PPI::Element possède des méthodes pour accéder aux propriétés et effectuer des opérations sur les éléments du document.

À FAIRE

Il serait utile que "location" puisse être utilisé de manière ad-hoc. C'est-à-dire, si un élément est appelé dans un document non indexé, il effectuera un calcul unique pour trouver sa position. Si quelqu'un commençait à l'utiliser fréquemment sans indexer le document, cela pourrait être très difficile, mais ce serait utile pour les choses qui ne sont utilisées qu'une seule fois, comme la gestion des erreurs.
