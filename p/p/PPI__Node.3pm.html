NOM

PPI::Node - Classe de base abstraite pour les classes d'éléments qui peuvent contenir d'autres éléments

HÉRITAGE

PPI::Node
isa PPI::Element

SYNOPSIS

# Créer un nœud typique (un Document dans ce cas)
my $Node = PPI::Document->new;

# Ajouter un élément à ce nœud (un token dans ce cas)
my $Token = PPI::Token::Word->new('my');
$Node->add_element( $Token );

# Obtenir les éléments du nœud
my @elements = $Node->children;

# Trouver tous les barewords dans un nœud
my $barewords = $Node->find( 'PPI::Token::Word' );

# Trouver selon des critères plus complexes
my $my_tokens = $Node->find( sub { $_[1]->content eq 'my' } );

# Supprimer les espaces blancs
$Node->prune( 'PPI::Token::Whitespace' );

# Supprimer selon des critères plus complexes
$Node->prune( sub { $_[1]->content eq 'my' } );

DESCRIPTION

La classe "PPI::Node" fournit une classe de base abstraite pour les classes d'éléments qui peuvent contenir d'autres éléments "PPI::Document", "PPI::Statement" et "PPI::Structure".

En plus de celles mentionnées ci-dessous, toutes les méthodes applicables aux objets "PPI::Element" s'appliquent également aux objets "PPI::Node".

MÉTHODES

scope

La méthode "scope" renvoie vrai si le nœud représente une limite de portée lexicale, ou faux si ce n'est pas le cas.

add_element $Element

La méthode "add_element" ajoute un objet "PPI::Element" à la fin d'un "PPI::Node". Comme les éléments conservent des liens vers leur parent, un élément ne peut être ajouté qu'à un seul nœud.

Renvoie vrai si l'objet "PPI::Element" a été ajouté. Renvoie "undef" si l'élément est déjà dans un autre nœud, ou si la méthode a reçu un objet qui n'est pas "PPI::Element".

elements

La méthode "elements" accède à tous les éléments enfants structurellement à l'intérieur de l'objet "PPI::Node". Note : dans la base des classes "PPI::Structure", ce "DOES" inclut les tokens de parenthèses au début et à la fin de la structure.

Renvoie une liste de zéro ou plusieurs objets "PPI::Element".

Alternativement, si elle est appelée dans le contexte scalaire, la méthode "elements" renvoie le nombre d'éléments.

first_element

La méthode "first_element" accède au premier élément structurellement à l'intérieur de l'objet "PPI::Node". Comme la méthode "elements", cela inclut les tokens de parenthèses pour les objets "PPI::Structure".

Renvoie un objet "PPI::Element", ou "undef" si l'objet "PPI::Node" ne contient aucun élément.

last_element

La méthode "last_element" accède au dernier élément structurellement à l'intérieur de l'objet "PPI::Node". Comme la méthode "elements", cela inclut les tokens de parenthèses pour les objets "PPI::Structure".

Renvoie un objet "PPI::Element", ou "undef" si l'objet "PPI::Node" ne contient aucun élément.

children

La méthode "children" accède à tous les éléments enfants lexicalement à l'intérieur de l'objet "PPI::Node". Note : dans le cas des classes "PPI::Structure", cela n'inclut pas les tokens de parenthèses au début et à la fin de la structure.

Renvoie une liste de zéro ou plusieurs objets "PPI::Element".

Alternativement, si elle est appelée dans le contexte scalaire, la méthode "children" renvoie le nombre d'enfants lexicaux.

schildren

La méthode "schildren" est en fait une variation pratique et significative de la méthode normale "children".

Dans le contexte de liste, renvoie une liste d'enfants significatifs. Dans le contexte scalaire, renvoie le nombre d'enfants significatifs.

child $index

La méthode "child" accède à un objet "PPI::Element" par sa position dans le nœud.

Renvoie un objet "PPI::Element", ou "undef" s'il n'y a pas d'élément enfant à cet index.

schild $index

La structure lexicale du langage Perl ignore les "éléments non significatifs", tels que les espaces blancs et les commentaires, tandis que PPI les traite comme des tokens valides afin de pouvoir reconstruire le fichier à tout moment. Pour cette raison, il existe souvent un besoin de trouver un élément dans un nœud par son index, en ne comptant que les éléments lexicalement significatifs.

La méthode "schild" renvoie un élément enfant par index, en ignorant les éléments non significatifs. L'index d'un élément enfant est spécifié de la même manière que dans un tableau normal, le premier élément étant à l'index 0, et les indices négatifs étant utilisés pour identifier une position "à partir de la fin".

contains $Element

La méthode "contains" est utilisée pour déterminer si un autre objet "PPI::Element" est logiquement "à l'intérieur" d'un "PPI::Node". Pour le cas spécial des tokens de parenthèses entourant un objet "PPI::Structure", ceux-ci sont généralement considérés comme "à l'intérieur" d'un objet "PPI::Structure", même s'ils ne sont pas réellement dans les éléments de cet objet.

Renvoie vrai si l'objet "PPI::Element" est à l'intérieur de nous, faux si ce n'est pas le cas, ou "undef" en cas d'erreur.

find $class | \&wanted

La méthode "find" est utilisée pour rechercher des objets "PPI::Element" dans un arbre de code qui satisfont une condition spécifique.

Pour spécifier la condition, la méthode peut accepter une classe simple (complète ou courte), ou une référence à une "CODE"/fonction.

# Trouver toutes les guillemets simples dans un document (qui est un nœud)
$Document->find('PPI::Quote::Single');

# Le même type de recherche avec une classe courte
$Document->find('Quote::Single');

# Pour quelque chose de plus complexe, on utilise la sub
$Document->find( sub {
      # Au niveau supérieur du fichier...
      $_[1]->parent == $_[0]
      and (
              # ...trouver les commentaires et POD
              $_[1]->isa('PPI::Token::Pod')
              or
              $_[1]->isa('PPI::Token::Comment')
      )
} );

La fonction recevra deux arguments, le nœud "PPI::Node" supérieur dans lequel on recherche et l'élément "PPI::Element" qui est testé.

La fonction doit renvoyer l'une des trois valeurs suivantes : vrai indique une correspondance, faux (0 ou '') indique une non-correspondance, et "undef" indique une non-correspondance sans descendance.

Dans ce dernier cas, le parcours de l'arbre sautera tout ce qui se trouve sous l'élément qui renvoie "undef" et passera à l'élément suivant au même niveau.
