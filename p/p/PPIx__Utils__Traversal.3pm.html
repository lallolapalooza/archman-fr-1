NOM

PPIx::Utils::Traversal - Fonctions utilitaires pour parcourir les documents PPI

SYNOPIS

use PPIx::Utils::Traversal ':all';

DESCRIPTION

Ce paquet est un composant de PPIx::Utils qui contient des fonctions pour le parcours des documents PPI.

FONCTIONS

Toutes les fonctions peuvent être importées par leur nom, ou avec le tag ":all".

first_arg

my $first_arg = first_arg($element);

Étant donné un élément PPI qui est présumé être un appel de fonction (ce qui est généralement un PPI::Token::Word), renvoie le premier argument. Ceci est similaire à "parse_arg_list" et suit la même logique. Notez que pour le code :

int($x + 0.5)

cette fonction renverra uniquement $x, et non toute l'expression. Ceci est différent du comportement de "parse_arg_list". Une autre mise en garde est :

int(($x + $y) + 0.5)

qui renvoie "($x + $y)" en tant qu'instance de PPI::Structure::List.

parse_arg_list

my @args = parse_arg_list($element);

Étant donné un élément PPI qui est présumé être un appel de fonction (ce qui est généralement un PPI::Token::Word), divise les expressions d'arguments en tableaux de tokens. Renvoie une liste contenant des références à chacun de ces tableaux. Ceci est utile car les parenthèses sont facultatives lors de l'appel d'une fonction, et PPI les analyse très différemment. Ainsi, cette méthode est un arbre d'analyse rudimentaire de nœuds PPI. Elle n'est pas infaillible car elle ne respecte pas la précédence. En général, je n'aime pas la façon dont cette fonction fonctionne, alors ne comptez pas sur elle pour être stable (ou même présente).

split_nodes_on_comma

my @args = split_nodes_on_comma(@nodes);

Ceci a le même type de retour que "parse_arg_list" mais attend qu'on lui passe les nœuds qui représentent l'intérieur d'une liste, comme :

'foo', 1, 2, 'bar'

get_next_element_in_same_simple_statement

my $element = get_next_element_in_same_simple_statement($element);

Étant donné un élément PPI, cette sous-routine renvoie le prochain élément dans la même instruction simple telle que définie par "is_ppi_simple_statement" dans PPIx::Utils::Classification. Si aucun élément suivant ne peut être trouvé, cette sous-routine renvoie simplement "undef".

Si le $element est indéfini ou non béni, nous renvoyons simplement "undef".

Si le $element satisfait "is_ppi_simple_statement" dans PPIx::Utils::Classification, nous renvoyons "undef", sauf s'il a un parent qui est une PPI::Structure::List.

Si le $element est le dernier élément significatif dans son PPI::Node, nous le remplaçons par son parent et itérons à nouveau.

Sinon, nous renvoyons "$element->snext_sibling()".

get_previous_module_used_on_same_line

my $element = get_previous_module_used_on_same_line($element);

Étant donné un élément PPI, renvoie l'élément PPI représentant le nom du module inclus par le précédent "use" ou "require" sur la même ligne que l'$element. Si aucun n'est trouvé, renvoie simplement "undef".

Par exemple, avec la ligne

use version; our $VERSION = ...;

étant donné l'instance PPI::Token::Symbol pour $VERSION, ceci renverra "version".

Si l'élément donné se trouve dans un "use" ou un "require", le retour provient du précédent "use" ou "require" sur la ligne, le cas échéant.

get_constant_name_elements_from_declaring_statement

my @constants = get_constant_name_elements_from_declaring_statement($statement);

Étant donné une instruction PPI, si l'instruction est une déclaration Readonly, ReadonlyX ou Const::Fast ou un "use constant", renvoie les noms des choses qui sont définies.

Étant donné

use constant 1.16 FOO => 'bar';

ceci renverra le PPI::Token::Word contenant 'FOO'. Étant donné

use constant 1.16 { FOO => 'bar', 'BAZ' => 'burfle' };

ceci renverra une liste des PPI::Tokens contenant 'FOO' et 'BAZ'. De même, étant donné

Readonly::Hash my %FOO => ( bar => 'baz' );

ou

const my %FOO => ( bar => 'baz' );

ceci renverra le PPI::Token::Symbol contenant '%FOO'.

split_ppi_node_by_namespace

my $subtrees = split_ppi_node_by_namespace($node);

Renvoie les sous-arbres pour chaque espace de noms dans le nœud sous forme de référence à un hachage de références à des tableaux de PPI::Nodes. Supposons que nous ayons le code suivant :

#!perl
my $x = blah();
package Foo;
my $y = blah_blah();
{
    say 'Whee!';
    package Bar;
    something();
}
thingy();
package Baz;
da_da_da();
package Foo;
foreach ( blrfl() ) {
    ...
}

Appeler cette fonction sur un PPI::Document pour le code ci-dessus renvoie une valeur qui ressemble à ceci, en utilisant des littéraux de chaînes multilignes pour les parties de code réelles au lieu d'arbres PPI pour rendre cela plus facile à lire :

{
    main    => [
        q<
            #!perl
            my $x = blah();
        >,
    ],
    Foo     => [
        q<
            package Foo;
            my $y = blah_blah();
            {
                say 'Whee!';
            }
            thingy();
        >,
        q<
            package Foo;
            foreach ( blrfl() ) {
                ...
            }
        >,
    ],
    Bar     => [
        q<
            package Bar;
            something();
        >,
    ],
    Baz     => [
        q<
            package Baz;
            da_da_da();
        >,
    ],
}

Notez que la valeur de retour contient des copies des nœuds d'origine, et non les nœuds eux-mêmes, en raison de la nécessité de gérer les espaces de noms qui ne sont pas au niveau du fichier. (Remarquez comment le premier élément pour "Foo" ci-dessus diffère du code d'origine.)
