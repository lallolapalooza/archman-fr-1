PPIx::Regexp::Tokenizer(3) Documentation Perl fournie par l'utilisateur PPIx::Regexp::Tokenizer(3)

NOM

PPIx::Regexp::Tokenizer - Tokeniser une expression régulière

SYNTAXE

use PPIx::Regexp::Dumper;
PPIx::Regexp::Dumper->new( 'qr{foo}smx' )
    ->print();

HERITAGE

"PPIx::Regexp::Tokenizer" est un PPIx::Regexp::Support.

"PPIx::Regexp::Tokenizer" n'a pas de descendants.

DESCRIPTION

Cette classe fournit la tokenisation de l'expression régulière.

METHODES

Cette classe fournit les méthodes publiques suivantes. Les méthodes non documentées ici (ou documentées ci-dessous sous "TOKENIZERS EXTERNES") sont privées, et non supportées dans le sens où l'auteur se réserve le droit de les modifier ou de les supprimer sans préavis.

new

my $tokenizer = PPIx::Regexp::Tokenizer->new( 'xyzzy' );

Cette méthode statique instancie le tokenizer. Vous devez lui passer l'expression régulière à parser, soit sous forme de chaîne, soit sous forme de PPI::Element. Vous pouvez également passer des paires d'arguments nom/valeur optionnelles. Les noms d'option sont spécifiés **sans** le tiret initial. Les options supportées sont :

default_modifiers reference_tableau
Cet argument spécifie les modificateurs d'instruction par défaut. Il est optionnel, mais s'il est spécifié, doit être une référence à un tableau. Voir la documentation de PPIx::Regexp new() pour les détails.
encoding nom
Cette option spécifie l'encodage de la chaîne à tokeniser. Si spécifiée, un "Encode::decode" est effectué sur la chaîne (ou le "content" de la classe PPI) avant sa tokenisation.
index_locations
Cette option booléenne spécifie que les emplacements des tokens générés doivent être calculés.
strict booléen
Cette option spécifie si la tokenisation doit supposer que "use re 'strict';" est en vigueur.

Le pragma 'strict' a été introduit dans Perl 5.22, et sa documentation indique qu'il est expérimental, et qu'il n'y a aucun engagement envers la compatibilité ascendante. Il en va de même pour la tokenisation produite lorsque cette option est activée.

trace nombre
Spécifier une valeur positive pour cette option déclenche une trace de la tokenisation. Cette option n'est pas supportée dans le sens où l'auteur se réserve le droit de la modifier sans préavis.

Si cette option n'est pas spécifiée, la valeur provient de la variable d'environnement "PPIX_REGEXP_TOKENIZER_TRACE" (voir "VARIABLES D'ENVIRONNEMENT"). Si cette variable d'environnement n'existe pas, la valeur par défaut est 0.

Les options non documentées ne sont pas supportées.

La valeur retournée est le tokenizer instancié, ou "undef" si l'instanciation a échoué. Dans ce dernier cas, un appel à "errstr" renverra la raison.

content

print $tokenizer->content();

Cette méthode retourne la chaîne qui est tokenisée. Ce sera le résultat de la méthode PPI::Element->content() si l'objet a été instancié avec un PPI::Element.

default_modifiers

print join ', ', @{ $tokenizer->default_modifiers() };

Cette méthode retourne une référence à une copie du tableau passé à l'argument "default_modifiers" de new(). Si cet argument n'a pas été utilisé pour instancier l'objet, le retour est une référence à un tableau vide.

encoding

Cette méthode retourne l'encodage des données en cours de parsing, si un encodage a été défini lors de l'instanciation de la classe ; sinon, elle retourne simplement undef.

errstr

my $tokenizer = PPIx::Regexp::Tokenizer->new( 'xyzzy' )
    or die PPIx::Regexp::Tokenizer->errstr();

Cette méthode statique retourne une description d'erreur si l'instanciation du tokenizer a échoué.

failures

print $tokenizer->failures(), " échecs de tokenisation\n";

Cette méthode retourne le nombre d'échecs de tokenisation rencontrés. Un échec de tokenisation est représenté dans le flux de tokens de sortie par un PPIx::Regexp::Token::Unknown.

modifier

$tokenizer->modifier( 'x' )
    and print "Tokenisation d'une expression régulière étendue\n";

Cette méthode retourne vrai si le caractère modificateur donné a été trouvé à la fin de l'expression régulière, et faux sinon.

À partir de la version 0.036_01, si l'argument est un modificateur monocaractère suivi d'un astérisque (destiné à être un caractère joker), le retour est le nombre de fois où ce modificateur apparaît. Dans ce cas, une exception sera levée si vous spécifiez un modificateur multi-caractères (par exemple, 'ee*'), ou si vous spécifiez l'un des modificateurs de sémantique de correspondance (par exemple, 'a*').

Si appelée par un tokenizer externe, cette méthode retourne vrai si le modificateur donné était vrai au point actuel de la tokenisation.

next_token

my $token = $tokenizer->next_token();

Cette méthode retourne le prochain token du flux de tokens, ou rien s'il n'y a plus de tokens.

significant

Cette méthode existe simplement pour la commodité de PPIx::Regexp::Dumper. Elle retourne toujours vrai.

tokens

my @tokens = $tokenizer->tokens();

Cette méthode retourne tous les tokens restants dans le flux de tokens.

TOKENIZERS EXTERNES

Cette classe effectue très peu de tokenisation par elle-même. Au lieu de cela, les classes de tokens contiennent des routines de tokenisation externes, dont le nom est '__PPIX_TOKENIZER__' concaténé avec le mode actuel du tokenizer ('regexp' pour les expressions régulières, 'repl' pour la chaîne de remplacement).

Ces tokenizers externes sont appelés en tant que méthodes statiques, et reçoivent l'objet "PPIx::Regexp::Tokenizer" et le caractère actuel dans le flux de caractères.

Si le tokenizer externe souhaite créer un ou plusieurs tokens, il retourne un tableau contenant soit la longueur en caractères pour les tokens de la propre classe du tokenizer, soit les résultats d'un ou plusieurs appels "make_token" pour les tokens d'une classe arbitraire.

Si le tokenizer externe ne s'intéresse pas aux caractères commençant à la position actuelle, il retourne simplement.

Les méthodes suivantes sont destinées à l'utilisation des tokenizers externes, et **ne font pas partie de l'interface publique de cette classe**.

capture

if ( $tokenizer->find_regexp( qr{ \A ( foo ) }smx ) ) {
    foreach ( $tokenizer->capture() ) {
        print "$_\n";
    }
}

Cette méthode retourne tout le contenu des tampons de capture de l'appel précédent à "find_regexp". Le premier élément du tableau (c'est-à-dire l'élément 0) correspond à $1, et ainsi de suite.

Les captures sont effacées par "make_token", ainsi que par un autre appel à "find_regexp".

cookie

$tokenizer->cookie( foo => sub { 1 } );
my $cookie = $tokenizer->cookie( 'foo' );
my $old_hint = $tokenizer->cookie( foo => undef );

Cette méthode crée, supprime ou accède à un cookie.

Un cookie est une référence de code

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

expect

$tokenizer->expect( 'PPIx::Regexp::Token::Code' );

Cette méthode insère une classe donnée en tête du scan des tokens, pour la prochaine itération seulement. Plus d'une classe peut être spécifiée. Les noms de classes peuvent être abrégés en supprimant la partie préfixée "PPIx::Regexp::".

Si aucune classe n'est spécifiée, cette méthode ne fait rien.

L'attente dure du prochain appel à "get_token" jusqu'au prochain appel à "make_token" qui produira un token significatif, ou jusqu'à ce que "expect" soit appelée si elle est appelée.

find_regexp

my $end = $tokenizer->find_regexp( qr{ \A \w+ }smx );
my ( $begin, $end ) = $tokenizer->find_regexp(
    qr{ \A \w+ }smx );

Cette méthode trouve l'expression régulière donnée dans le contenu, en commençant par la position actuelle. Si elle est appelée en contexte scalaire, elle renvoie la distance entre la position actuelle et la fin de la chaîne correspondante. Si elle est appelée en contexte de liste, elle renvoie les distances de part et d'autre de la chaîne correspondante.

find_matching_delimiter

my $offset = $tokenizer->find_matching_delimiter();

Cette méthode est utilisée par les tokeniseurs pour trouver le délimiteur correspondant au caractère actuel dans la chaîne de contenu. Si le délimiteur est un crochet ouvrant d'un type quelconque, la gestion de l'imbrication des crochets est prise en compte.

Lors de la recherche du délimiteur correspondant, le caractère antislash est pris en compte pour échapper le caractère suivant, de sorte que les délimiteurs échappés par antislash seront ignorés. Aucun autre mécanisme de citation n'est reconnu, bien que les délimiteurs à l'intérieur des guillemets comptent toujours. C'est en fait comme ça que fonctionne Perl, comme le montre

$ perl -e 'qr<(?{ print "}" })>'

montre.

Cette méthode renvoie la distance entre la position actuelle dans la chaîne de contenu et le délimiteur correspondant (qui sera toujours positif), ou undef s'il n'est pas possible de trouver de correspondance.

get_mode

Cette méthode renvoie le nom du mode actuel du tokeniseur.

get_start_delimiter

my $start_delimiter = $tokenizer->get_start_delimiter();

Cette méthode est utilisée par les tokeniseurs pour accéder au délimiteur de début de l'expression régulière.

get_token

my $token = $tokenizer->make_token( 3 );
my @tokens = $tokenizer->get_token();

Cette méthode renvoie le prochain token qui peut être créé à partir de la chaîne d'entrée. Elle ne fait pas partie de l'interface externe, mais est destinée à être utilisée par un tokeniseur externe qui l'appelle après avoir créé et conservé son propre token pour voir le prochain token (s'il y en a un) dans la chaîne d'entrée.

Si un tokeniseur externe appelle get_token sans avoir d'abord appelé make_token, une erreur fatale se produit ; c'est préférable à la récursion infinie qui se produirait si la condition n'était pas interceptée.

Un tokeniseur externe doit renvoyer toute valeur renvoyée par get_token ; sinon, les tokens seront perdus.

interpolates

Cette méthode renvoie vrai si la structure de haut niveau en cours de tokenisation s'interpole ; c'est-à-dire si le délimiteur n'est pas un guillemet simple.

make_token

return $tokenizer->make_token( 3, 'PPIx::Regexp::Token::Unknown' );

Cette méthode est utilisée par cette classe (et potentiellement par des tokeniseurs individuels) pour créer un token. Ses arguments sont le nombre de caractères à inclure dans le token et, éventuellement, la classe du token. Si aucun nom de classe n'est fourni, la classe de l'appelant est utilisée. Les noms de classes peuvent être abrégés en supprimant la partie préfixée "PPIx::Regexp::", qui sera restaurée par cette méthode.

Le token sera créé à partir des caractères donnés, en commençant par la position actuelle, qui sera ajustée.

Si le nombre donné inclut des caractères au-delà de la fin de la chaîne de tokenisation, le nombre sera réduit en conséquence. Si cela se traduit par un token sans caractères, rien n'est renvoyé.

match

if ( $tokenizer->find_regexp( qr{ \A \w+ }smx ) ) {
    print $tokenizer->match(), "\n";
}

Cette méthode renvoie la chaîne correspondante de la dernière invocation de "find_regexp".

Le match est mis à "undef" par "make_token" ainsi que par une autre invocation de "find_regexp".

modifier_duplicate

$tokenizer->modifier_duplicate();

Cette méthode duplique les modifications sur la pile de modifications, dans le but de créer une copie locale des modifications. Elle ne doit être appelée que par un tokeniseur externe qui crée réellement une portée de modification. En d'autres termes, uniquement lorsqu'un token de type "PPIx::Regexp::Token::Structure" dont le contenu est "(" est créé.

modifier_modify

$tokenizer->modifier_modify( name => $value ... );

Cette méthode définit de nouvelles valeurs pour les modifications dans la portée locale. Seules les modifications dont les noms sont effectivement passés voient leurs valeurs modifiées.

Cette méthode est utilisée pour appeler la méthode de modifications après la création d'un token de type "PPIx::Regexp::Token::Modifier", et reçoit les résultats de sa méthode "modifiers".

modifier_pop

$tokenizer->modifier_pop();

Cette méthode supprime les modifications sur la pile de modifications au sommet. Elle ne doit être appelée que par un tokeniseur externe qui termine une portée de modification. En d'autres termes, uniquement lorsqu'un token de type "PPIx::Regexp::Token::Structure" dont le contenu est ")" est créé.

Note : Cette méthode ne supprimera jamais le dernier élément de la pile de modifications, afin de se protéger contre les parenthèses droites non correspondantes.

modifier_seen

$tokenizer->modifier_seen( 'i' )
    and print "/i a été vu à un moment donné.\n";

Contrairement à "modifier()", cette méthode renvoie une valeur vraie si le modificateur donné a été vu dans n'importe quelle portée visible depuis l'emplacement actuel dans l'analyse. Il n'y a pas de magie pour la sémantique de groupe ( /a, /aa, /d, /l, /u) ou les modificateurs qui peuvent être répétés, comme /x et /xx, ou /e et /ee.

peek

my $character = $tokenizer->peek();
my $next_char = $tokenizer->peek( 1 );

Cette méthode renvoie le caractère à la position donnée par rapport à la position actuelle. Si aucun décalage n'est spécifié, un décalage de 0 est utilisé.

Si un décalage négatif ou hors limites de la chaîne est demandé, "undef" est renvoyé.

ppi_document

Cette méthode génère un document PPI à partir du reste de la chaîne et le renvoie.

prior_significant_token

$tokenizer->prior_significant_token( 'can_be_quantified' )
   and print "Le token précédent peut être quantifié.\n";

Cette méthode appelle la méthode nommée sur le token le plus récent qui a été instancié, et renvoie le résultat. Tous les arguments après le nom de la méthode sont passés à la méthode.

Étant donné que cette méthode est conçue pour être utilisée dans le système de tokenisation, elle générera une erreur si la méthode nommée n'existe pas.

Si elle est appelée sans arguments, le token le plus récent qui a été instancié est renvoyé.

strict

say 'L'analyse est ', $tokenizer->strict() ? 'stricte' : 'tolérante';

Cette méthode renvoie simplement vrai ou faux, selon que l'option "strict" de la méthode "new()" était vraie ou fausse.

VARIABLES ENVIRONNEMENT

Une trace du tokeniseur peut être demandée en définissant la variable d'environnement PPIX_REGEXP_TOKENIZER_TRACE à une valeur numérique autre que 0. L'utilisation de cette variable d'environnement est déconseillée de la même manière que l'option "trace" de la méthode "new()" est déconseillée. La spécification explicite de l'option "trace" de la méthode "new()" outrepassera la variable d'environnement.

La raison principale pour laquelle ceci est documenté est de donner à l'utilisateur un moyen de diagnostiquer une sortie étrange du tokeniseur.

NOM

PPIx::Regexp

SYNOPSIS

use PPIx::Regexp;

HÉRITAGE

PPIx::Regexp étend PPIx::Tokenizer

DESCRIPTION

PPIx::Regexp est un module Perl qui fournit un analyseur lexical (tokenizer) pour les expressions régulières.

MÉTHODES

Le module fournit les méthodes suivantes :

  • token() - retourne un jeton (token)

  • tokenize() - retourne une chaîne de caractères tokenisée

  • tokenize_regex() - retourne une chaîne de caractères tokenisée à partir d'une expression régulière

ANALYSEURS LEXICAUX EXTERNES

Le module prend en charge les analyseurs lexicaux externes via la méthode tokenize.

VARIABLES D'ENVIRONNEMENT

Le module utilise les variables d'environnement suivantes :

  • REGEX_TOKENIZER - spécifie l'analyseur lexical à utiliser
