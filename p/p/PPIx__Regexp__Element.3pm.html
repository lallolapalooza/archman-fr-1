PPIx::Regexp::Element(3) Documentation Perl fournie par l'utilisateur PPIx::Regexp::Element(3)

NOM

PPIx::Regexp::Element - Base de la hiérarchie PPIx::Regexp.

SYNTAXE

Aucune pièce interne utilisable par l'utilisateur.

HÉRITAGE

« PPIx::Regexp::Element » n'est hérité d'aucune autre classe.

« PPIx::Regexp::Element » est le parent de PPIx::Regexp::Node et PPIx::Regexp::Token.

DESCRIPTION

Cette classe est la base de la hiérarchie des objets PPIx::Regexp. Elle fournit le même type de fonctionnalités de navigation que celles fournies par PPI::Element.

MÉTHODES

Cette classe fournit les méthodes publiques suivantes. Les méthodes non documentées ici sont privées et non prises en charge dans le sens où l'auteur se réserve le droit de les modifier ou de les supprimer sans préavis.

accepts_perl

$token->accepts_perl( '5.020' )
    and say 'Ceci fonctionne sous Perl 5.20';

Cette méthode retourne une valeur vraie si le jeton est acceptable sous la version spécifiée de Perl, et une valeur fausse sinon. À moins que le jeton (ou son contenu) n'ait été equivocé, le résultat est simplement ce que vous attendriez en testant les résultats de perl_version_introduced() et perl_version_removed() par rapport à la version de Perl donnée.

Cette méthode a été ajoutée dans la version 0.051_01.

ancestor_of

Cette méthode retourne vrai si l'objet est un ancêtre de l'argument, et faux sinon. Par la définition de cette méthode, $self est son propre ancêtre.

can_be_quantified

$token->can_be_quantified()
    and print "Cet élément peut être quantifié.\n";

Cette méthode retourne vrai si l'élément peut être quantifié.

class

Cette méthode retourne le nom de la classe de l'élément. C'est la même chose que « ref $self ».

column_number

Cette méthode retourne le numéro de colonne du premier caractère de l'élément, ou « undef » si cela ne peut être déterminé.

comment

Cette méthode retourne vrai si l'élément est un commentaire et faux sinon.

content

Cette méthode retourne le contenu de l'élément.

descendant_of

Cette méthode retourne vrai si l'objet est un descendant de l'argument, et faux sinon. Par la définition de cette méthode, $self est son propre descendant.

explain

Cette méthode retourne une brève explication de ce que fait l'élément. Le retour sera soit une chaîne, soit « undef » en contexte scalaire, mais peut être plusieurs valeurs ou un tableau vide en contexte de liste.

Cette méthode doit être considérée comme expérimentale. Ce qu'elle retourne peut changer sans préavis à mesure que ma compréhension de toutes les pièces/parties d'une expression régulière Perl évolue. Le pire des cas est qu'elle s'avère totalement infaisable à implémenter de manière satisfaisante, auquel cas elle sera soumise à un cycle de dépréciation et retirée.

error

say $token->error();

Si un élément fait partie des classes qui représentent une erreur d'analyse, cette méthode peut retourner un bref message indiquant pourquoi. Sinon, elle retournera « undef ».

is_matcher

Cette méthode indique si l'élément correspond potentiellement à quelque chose. Les retours possibles sont une valeur vraie s'il correspond, une valeur fausse (mais définie) s'il ne correspond pas, ou « undef » si cela ne peut être déterminé.

L'idée est de classifier les éléments en fonction de leur capacité à correspondre potentiellement à quelque chose dans la chaîne cible.

Cette méthode est redéfinie pour retourner « undef » dans PPIx::Regexp::Token::Code, PPIx::Regexp::Token::Interpolation et PPIx::Regexp::Token::Unknown.

Cette méthode est redéfinie pour retourner une valeur vraie dans PPIx::Regexp::Token::Assertion, PPIx::Regexp::Token::CharClass, PPIx::Regexp::Token::Literal et PPIx::Regexp::Token::Reference.

Pour PPIx::Regexp::Node, cette méthode est redéfinie pour retourner une valeur calculée à partir des enfants du nœud.

Pour tout le reste, cette méthode retourne une valeur fausse (mais définie).

in_regex_set

Cette méthode retourne une valeur vraie si l'invocant est contenu dans une classe de caractères entre crochets étendue (également appelée ensemble d'expressions régulières), et une valeur fausse sinon. Cette méthode retourne vrai si l'invocant est un PPIx::Regexp::Structure::RegexSet.

is_quantifier

$token->is_quantifier()
    and print "Cet élément est un quantificateur.\n";

Cette méthode retourne vrai si l'élément est un quantificateur. Vous ne pouvez pas le savoir à partir de la classe de l'élément, car une accolade fermante peut représenter un quantificateur dans le but de déterminer si un jeton d'avidité est possible.

line_number

Cette méthode retourne le numéro de ligne du premier caractère de l'élément, ou « undef » si cela ne peut être déterminé.

location

Cette méthode retourne une référence vers un tableau décrivant la position de l'élément dans l'expression régulière, ou « undef » si les positions n'ont pas été indexées.

Le tableau est compatible avec la méthode correspondante de PPI::Element.

logical_filename

Cette méthode retourne le nom de fichier logique (en tenant compte des directives « #line ») du fichier contenant le premier caractère de l'élément, ou « undef » si cela ne peut être déterminé.

logical_line_number

Cette méthode retourne le numéro de ligne logique (en tenant compte des directives « #line ») du premier caractère de l'élément, ou « undef » si cela ne peut être déterminé.

main_structure

Cette méthode retourne la structure PPIx::Regexp::Structure::Main qui contient l'élément. En pratique, il s'agira d'une PPIx::Regexp::Structure::Regexp ou d'une PPIx::Regexp::Structure::Replacement.

Si l'élément n'est contenu dans aucune structure de ce type, « undef » est retourné. Cela se produira si l'élément est un PPIx::Regexp ou l'un de ses enfants immédiats.

modifier_asserted

$token->modifier_asserted( 'i' )
    and print "Correspondance sans tenir compte de la casse.\n";

Cette méthode retourne vrai si le modificateur donné est effectif pour l'élément, et faux sinon.

Elle parcourt l'élément à rebours jusqu'à ce qu'elle trouve un objet modificateur qui spécifie le modificateur, qu'il soit asserté ou nié, et retourne la valeur spécifiée. Si personne ne spécifie le

next_element

Cette méthode ne fonctionnera pas de manière fiable si elle est appelée depuis la sortie du tokenizer.

next_sibling

Cette méthode renvoie l'élément frère suivant, ou rien s'il n'y en a pas.

next_token

Cette méthode renvoie le token suivant, ou rien s'il n'y en a pas.

Contrairement à next_element(), celle-ci parcourra l'arbre d'analyse.

parent

Cette méthode renvoie le parent de l'élément, ou undef s'il n'y en a pas.

perl_version_introduced

Cette méthode renvoie la version de Perl dans laquelle l'élément a été introduit. Ce sera au moins 5.000. Avant 5.006, je me suis appuyé sur la documentation de perldelta, perlre et perlop, car je n'ai pas pu construire des Perls plus anciens. Comme j'ai trouvé de la documentation avant 5.003, je suppose que tout ce qui a été trouvé dans 5.003 est également présent dans 5.000.

Comme cela dépend de ma capacité à lire et à comprendre de grandes quantités de documentation, les résultats de cette méthode doivent être considérés avec prudence, voire avec méfiance.

Il existe également des cas ambigus à divers égards. Pour ces cas, voir la documentation de PPIx::Regexp, en particulier les changements dans le symbole.

Parfois, un construit sera supprimé puis ajouté à nouveau. Si cela se produit, cette méthode renverra la version la plus petite dans laquelle le construit est apparu. Pour les cas connus, voir la documentation de PPIx::Regexp, en particulier "Mistakes".

perl_version_removed

Cette méthode renvoie la version de Perl dans laquelle l'élément a été supprimé. Si l'élément est toujours valide, la valeur renvoyée sera "undef".

Toutes les mises en garde de perl_version_introduced() s'appliquent également ici, bien qu'avec une sévérité moindre, car de nombreuses fonctionnalités ont été introduites depuis 5.0, peu ont été supprimées.

Parfois, un construit est supprimé puis ajouté à nouveau. Si cela se produit, cette méthode renverra "undef" si le construit est présent dans la dernière version de Perl (qu'il s'agisse de production ou de développement), ou la version juste après la dernière dans laquelle il est apparu sinon. Pour les cas connus, voir la documentation de PPIx::Regexp, en particulier "Mistakes".

previous_element

Cette méthode renvoie l'élément précédent, ou rien s'il n'y en a pas.

Contrairement à previous_sibling(), celle-ci traversera du contenu d'une structure vers les éléments qui définissent la structure, ou vice versa.

previous_sibling

Cette méthode renvoie l'élément frère précédent, ou rien s'il n'y en a pas.

Cette méthode est analogue à la méthode homonyme de PPI::Element, en ce sens qu'elle ne traversera pas du contenu d'une structure vers les éléments qui définissent la structure.

previous_token

Cette méthode renvoie le token précédent, ou rien s'il n'y en a pas.

Contrairement à previous_element(), celle-ci parcourra l'arbre d'analyse.

raw_width

my ( $raw_min, $raw_max ) = $self->raw_width();

Cette méthode publique renvoie la largeur minimale et maximale des éléments correspondants avant de prendre en compte les détails tels que la nature de l'élément et sa quantification. Les deux éléments peuvent être "undef" si la largeur ne peut pas être déterminée, et le maximum peut être "Inf".

Cette méthode a été ajoutée dans la version 0.085_01.

remove_insignificant

Cette méthode renvoie un nouvel objet généré à partir de l'invocateur, mais contenant uniquement les éléments pour lesquels "$elem->significant()" renvoie une valeur vraie.

Si vous appelez cette méthode sur un objet PPIx::Regexp::Node, vous obtiendrez un clone profond, mais sans les éléments insignifiants.

Si vous appelez cette méthode sur tout autre objet PPIx::Regexp, vous obtiendrez l'invocateur ou rien. Cela pourrait passer à un clone de l'invocateur ou à rien si des problèmes inattendus surviennent lors du renvoi de l'invocateur, ou si les objets deviennent mutables (bien que peu probable, mais pas impossible).

requirements_for_perl

say $token->requirements_for_perl();

Cette méthode renvoie une chaîne représentant les exigences de Perl pour un module donné. Ceci ne doit être utilisé qu'à des fins informatives, car le format de la chaîne peut changer.

Actuellement, les valeurs renvoyées peuvent être :

version <= $]
version <= $] < version
two or more of the above joined by '||'
! $]

Le dernier signifie que, bien que tous les composants de l'expression régulière puissent être compilés par une version de Perl, aucune version ne peut compiler tous les composants.

Je le répète : la chaîne renvoyée est susceptible de changer, peut-être sans préavis.

Cette méthode a été ajoutée dans la version 0.051_01.

scontent

Cette méthode renvoie le contenu significatif de l'élément. Cela signifie que, si elle est appelée sur l'analyse de '/ f u b a r /x', elle renvoie '/fubar/x'. Si l'invocateur ne contient aucun élément insignifiant, c'est la même chose que content(). Si elle est appelée sur un élément insignifiant, elle renvoie rien — c'est-à-dire "undef" en contexte scalaire, et une liste vide en contexte liste.

Cette méthode a été inspirée par la question de jb sur Perl Monks concernant la suppression des commentaires et des espaces dans une expression régulière : https://www.perlmonks.org/?node_id=1207556

Cette méthode a été ajoutée dans la version 0.053_01.

significant

Cette méthode renvoie vrai si l'élément est significatif et faux sinon.

snext_element

Cette méthode renvoie l'élément suivant significatif, ou rien s'il n'y en a pas.

Contrairement à snext_sibling(), celle-ci traversera du contenu d'une structure vers les éléments qui définissent la structure, ou vice versa.

snext_sibling

Cette méthode renvoie l'élément frère suivant significatif, ou rien s'il n'y en a pas.

Cette méthode est analogue à la méthode homonyme de PPI::Element, en ce sens qu'elle ne traversera pas du contenu d'une structure vers les éléments qui définissent la structure.

sprevious_element

Cette méthode renvoie l'élément précédent significatif, ou rien s'il n'y en a pas.

Contrairement à sprevious_sibling(), celle-ci traversera du contenu d'une structure vers les éléments qui définissent la structure, ou vice versa.

sprevious_sibling

Cette méthode renvoie l'élément frère précédent significatif, ou rien s'il n'y en a pas.

Cette méthode est analogue à la méthode homonyme de PPI::Element, en ce sens qu'elle ne traversera pas du contenu d'une structure vers les éléments qui définissent la structure.

statement

Cette méthode renvoie le PPI::Statement qui contient cet élément, ou rien si l'instruction ne peut pas être déterminée.

En général, cette méthode ne renverra quelque chose que dans les conditions suivantes :

  • L'élément est contenu dans un objet PPIx::Regexp ;
  • Cet objet a été initialisé à partir d'un PPI::Element ;
  • Le PPI::Element est contenu dans une instruction.

tokens

Cette méthode renvoie tous les tokens contenus dans l'élément.

top

Cette méthode renvoie le sommet de la hiérarchie.

unescaped_content

Cette méthode renvoie le contenu de l'élément, sans échappement.

visual_column_number

Cette méthode renvoie le numéro de colonne visuel (en tenant compte des tabulations) de la première caractéristique de l'élément, ou "undef" si elle ne peut pas être déterminée.

whitespace

Cette méthode renvoie vrai si l'élément est un espace blanc et faux sinon.

width

my ( $min, $max ) = $self->width();

Cette méthode renvoie le nombre minimum et maximum de caractères que cet élément peut correspondre.

Les deux éléments peuvent être "undef" si le nombre ne peut pas être déterminé. Par exemple, pour "/$foo/", les deux éléments seront "undef".

"undef". Les récursions retourneront "undef" car elles ne peuvent pas être analysées statistiquement -- ou du moins je ne suis pas assez intelligent pour le faire. Les références peuvent retourner "undef" si le groupe référencé ne peut pas être déterminé de manière unique.

Il est possible que $max soit "Inf". Par exemple, pour "/x*/" $max sera "Inf".

Les éléments qui ne correspondent à rien retourneront des zéros.

Note : Cette méthodologie a été ajoutée car je voulais améliorer la détection des look-behinds de longueur variable. raw_width() (ci-dessus) et celle-ci doivent être considérées comme assez expérimentales.

Cette méthodologie a été ajoutée dans la version 0.085_01.

nav

Cette méthodologie retourne des informations de navigation depuis la racine de la hiérarchie jusqu'à ce nœud. Le retour est une liste de noms de méthodes et de références à leurs listes d'arguments. L'idée est que étant donné $elem, qui se trouve un niveau plus bas que $top,

my @nav = $elem->nav();
my $obj = $top;
while ( @nav ) {
    my $method = shift @nav;
    my $args = shift @nav;
    $obj = $obj->$method( @{ $args } ) or die;
}
# À ce stade, $obj devrait contenir le même objet que $elem.
