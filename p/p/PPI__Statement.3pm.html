PPI::Statement(3) Documentation Perl fournie par la communauté PPI::Statement(3)

NOM

PPI::Statement - La classe de base pour les instructions Perl

HÉRÉDITE

PPI::Statement
isa PPI::Node
    isa PPI::Element

DESCRIPTION

PPI::Statement est la classe racine pour toutes les instructions Perl. Cela inclut (d'après perlsyn) les "Déclarations", les "Instructions simples" et les "Instructions composées".

La classe PPI::Statement elle-même représente une "Instruction simple" telle que définie dans la page de manuel perlsyn.

CLASSES D'INSTRUCTION

Veuillez noter que sauf documentation spécifique, ces classes ne sont pas encore figées/finalisées. Les noms peuvent légèrement changer ou être ajoutés ou supprimés.

PPI::Statement::Scheduled

Cela couvre tous les blocs "programmés", des morceaux de code qui sont exécutés séparément du corps principal du code, à un moment particulier. Cela inclut tous les blocs "BEGIN", "CHECK", "UNITCHECK", "INIT" et "END".

PPI::Statement::Package

Une déclaration de package, telle que définie dans perlfunc.

PPI::Statement::Include

Une instruction qui charge ou décharge un autre module.

Cela inclut les instructions 'use', 'no', et 'require'.

PPI::Statement::Sub

Une déclaration de sous-routine nommée, ou une déclaration anticipée.

PPI::Statement::Variable

Une instruction de déclaration de variable. Cela peut être une déclaration simple ou aussi une expression.

Cela inclut toutes les instructions 'my', 'state', 'local' et 'our'.

PPI::Statement::Compound

Cela couvre toute la famille des instructions "composées", telles que décrites dans perlsyn.

Cela inclut toutes les instructions commençant par 'if', 'unless', 'for', 'foreach' et 'while'. Notez que cela n'inclut PAS 'do', car il est traité différemment.

Toutes les instructions composées ont des fins implicites. C'est-à-dire qu'elles ne se terminent pas par un terminateur d'instruction ';'.

PPI::Statement::Break

Une instruction qui interrompt une structure.

Cela inclut toutes les instructions 'redo', 'goto', 'next', 'last' et 'return'.

PPI::Statement::Given

Le type d'instruction introduit dans Perl 5.10 qui commence par 'given'. Celle-ci a une fin implicite.

PPI::Statement::When

Le type d'instruction introduit dans Perl 5.10 qui commence par 'when' ou 'default'. Celle-ci a également une fin implicite.

PPI::Statement::Data

Une instruction spéciale qui englobe un bloc entier "__DATA__", y compris le jeton '__DATA__' initial lui-même et tout son contenu.

PPI::Statement::End

Une instruction spéciale qui englobe un bloc entier __END__, y compris le jeton '__END__' initial lui-même et tout son contenu, y compris tout PPI::Token::POD parsé qui pourrait s'y trouver.

PPI::Statement::Expression

PPI::Statement::Expression est un peu plus spéculatif et est destiné à aider à représenter les règles spéciales relatives aux "expressions" telles que dans :

# Plusieurs exemples d'instructions d'expression

# Conditions booléennes
if ( expression ) { ... }

# Listes, comme pour les arguments
Foo->bar( expression )

PPI::Statement::Null

Une instruction nulle est un cas spécial pour les situations où nous rencontrons deux terminateurs d'instruction consécutifs. ( ;; )

Le deuxième terminateur se voit attribuer sa propre instruction, mais une instruction qui ne sert à rien. D'où une instruction 'nulle'.

Théoriquement, en supposant un parsing correct d'un fichier perl, toutes les instructions nulles sont superflues et devraient pouvoir être supprimées sans endommager le fichier.

Mais ne le faites pas, au cas où PPI aurait mal interprété quelque chose.

PPI::Statement::UnmatchedBrace

Comme PPI est destiné à être utilisé lors du parsing de code incorrect ou incomplet, le problème se pose de savoir quoi faire avec une accolade fermante errante.

Plutôt que de planter, elle se voit attribuer sa propre instruction "accolade non appariée", ce qui signifie réellement "accolade fermante non appariée". Une accolade ouvrante non appariée à la fin d'un fichier deviendrait une structure sans contenu et sans accolade fermante.

Si le document chargé est censé être correct et valide, trouver un PPI::Statement::UnmatchedBrace dans le PDOM est généralement indicatif d'une erreur de parsing.

PPI::Statement::Unknown

Ceci est utilisé temporairement en cours de parsing pour contenir les instructions dont le lexer ne peut pas encore déterminer la classe, généralement parce qu'il y a des indices insuffisants, ou parce que cela peut être plus d'une chose.

Vous ne devriez jamais rencontrer ces éléments dans un arbre PDOM entièrement parsé.

MÉTHODES

"PPI::Statement" lui-même a très peu de méthodes. La plupart du temps, vous travaillerez avec les méthodes plus génériques de PPI::Element ou PPI::Node, ou l'une des méthodes spécifiques à la sous-classe.

étiquette

Un facteur commun à la plupart des instructions est leur capacité à être étiquetées.

La méthode "label" renvoie l'étiquette d'une instruction, si elle a été définie, mais sans le double point final. Prenez l'exemple suivant :

MONÉTIQUETTE: while ( 1 .. 10 ) { last MONÉTIQUETTE if $_ > 5 }

Pour l'instruction ci-dessus, la méthode "label" renverrait 'MONÉTIQUETTE'.

Renvoie faux si l'instruction n'a pas d'étiquette.

spécialisé

Indique s'il s'agit d'une instruction simple ou d'une instruction ayant plus de signification.

Renvoie vrai si l'instruction est une sous-classe de celle-ci, faux sinon.

stable

Tout comme la méthode PPI::Document du même nom, la méthode ->stable convertit une instruction en source puis la reconvertit, pour déterminer si une instruction modifiée est toujours légale et ne sera pas interprétée différemment.

Renvoie vrai si l'instruction est stable, faux sinon, ou "undef" en cas d'erreur.
