PPI::Document(3) Documentation Perl fournie par l'utilisateur PPI::Document(3)

NOM

PPI::Document - Représentation objet d'un document Perl

HIÉRARCHIE

PPI::Document
isa PPI::Node
    isa PPI::Element

SYNOPSIS

use PPI;

# Charger un document depuis un fichier
my $Document = PPI::Document->new('My/Module.pm');

# Supprimer les commentaires
$Document->prune('PPI::Token::Comment');

# Trouver toutes les sous-routines nommées
my $sub_nodes = $Document->find( 
      sub { $_[1]->isa('PPI::Statement::Sub') and $_[1]->name }
);
my @sub_names = map { $_->name } @$sub_nodes;

# Sauvegarder le fichier
$Document->save('My/Module.pm.stripped');

DESCRIPTION

La classe "PPI::Document" représente un seul "document" Perl. Un objet "PPI::Document" agit comme une racine de PPI::Node, avec des méthodes supplémentaires pour charger et sauvegarder, et travailler avec les emplacements ligne/colonne des Éléments dans un fichier.

L'exception à son comportement de type PPI::Node est que l'objet "PPI::Document" ne peut JAMAIS avoir de nœud parent, et est toujours le nœud racine dans un arbre.

Support Storable

"PPI::Document" implémente les crochets nécessaires "STORABLE_freeze" et "STORABLE_thaw" pour fournir un support natif pour Storable, si vous l'avez installé.

Cependant, si vous voulez cloner un Document, il est fortement recommandé d'utiliser la méthode "$Document->clone" plutôt que la fonction "dclone" de Storable (bien que "dclone" devrait toujours fonctionner).

MÉTHODES

La plupart des choses que vous voudrez probablement faire avec un Document impliqueront les méthodes de la classe PPI::Node, dont c'est une sous-classe.

Les méthodes listées ici sont les quelques méthodes restantes qui sont véritablement spécifiques au Document.

new

# Construction simple
$doc = PPI::Document->new( $filename );
$doc = PPI::Document->new( \$source  );

# Avec l'attribut readonly défini
$doc = PPI::Document->new( $filename,
        readonly => 1,
);

Le constructeur "new" prend comme argument une variété de sources différentes de code Perl, et crée un seul "PPI::Document" Perl cohérent pour cela.

Si un nom de fichier est passé comme chaîne normale, il tentera de charger le document depuis le fichier.

Si une référence à un "SCALAR" est passée, ceci est considéré comme du code source et est analysé directement pour créer le document.

Si aucun argument n'est passé, un document "vide" sera créé, ne contenant aucun contenu.

Dans tous les cas, le document est considéré comme "anonyme" et n'est pas lié à l'endroit où il a été créé. Spécifiquement, si vous créez un PPI::Document à partir d'un nom de fichier, le document ne se souviendra PAS d'où il a été créé.

Retourne un objet "PPI::Document", ou "undef" si l'analyse échoue. Des objets PPI::Exception peuvent également être lancés en cas de problèmes d'analyse.

Le constructeur accepte également des indicateurs d'attributs.

readonly

Définir "readonly" à vrai permettra à divers systèmes de fournir des optimisations et des caches supplémentaires. Notez que comme "readonly" est un indicateur d'optimisation, il est désactivé par défaut et vous devrez l'activer explicitement.

feature_mods

Définir feature_mods avec un hashref permet de définir des fonctionnalités d'analyse perl à activer pour l'ensemble du document (par exemple, lorsque le code est supposé être exécuté comme une ligne de commande).

custom_feature_includes

custom_feature_includes =>
  { strEct => { signatures => "Syntax::Keyword::Try" } }

Définir custom_feature_includes avec un hashref permet de définir des noms d'inclusion qui agissent comme des pragmas activant des fonctionnalités d'analyse dans leur portée.

C'est principalement utile lorsque votre projet de travail a son propre module boilerplate.

Il peut également être fourni en JSON ou YAML dans la variable d'environnement PPI_CUSTOM_FEATURE_INCLUDES, comme ceci :

PPI_CUSTOM_FEATURE_INCLUDES='strEct: {signatures: perl}' \
  perlcritic lib/OurModule.pm
PPI_CUSTOM_FEATURE_INCLUDES='{"strEct":{"signatures":"perl"}}' \
  perlcritic lib/OurModule.pm

custom_feature_include_cb

custom_feature_include_cb => sub {
  my ($statement) = @_;
  return $statement->module eq "strEct" ? { signatures => "perl" } : ();
},

Définir custom_feature_include_cb avec une référence de code provoque l'appel de cette sous-routine lors de toutes les inspections des inclusions avant toute autre inspection. La sous-routine peut décider de retourner un hashref de fonctionnalités à activer ou désactiver, qui sera utilisé pour la portée dans laquelle l'inclusion a été appelée, ou undef pour continuer avec les inspections par défaut. L'argument de la sous-routine sera l'objet PPI::Statement::Include.

Cela peut être utile lorsque votre projet de travail a un module boilerplate complexe.

set_cache $cache

Depuis PPI 1.100, "PPI::Document" prend en charge la mise en cache de l'analyseur.

La classe de cache par défaut PPI::Cache fournit une mise en cache basée sur Storable ou le document analysé basé sur le hachage MD5 du document en tant que chaîne.

La méthode statique "set_cache" est utilisée pour définir l'objet cache que "PPI::Document" doit utiliser lors du chargement des documents. Elle prend comme argument un objet PPI::Cache (ou quelque chose qui "isa" la même).

Si "undef" est passé, cette méthode arrêtera d'utiliser le cache actuel, le cas échéant.

Pour plus d'informations sur la mise en cache, voir PPI::Cache.

Retourne vrai en cas de succès, ou "undef" si le paramètre passé n'est pas valide.

get_cache

Si un cache de document est actuellement défini, la méthode "get_cache" le retournera.

Retourne un objet PPI::Cache, ou "undef" s'il n'y a pas de cache actuellement défini pour "PPI::Document".

filename

L'accesseur "filename" retourne le nom du fichier dans lequel le document est stocké.

readonly

L'attribut "readonly" indique si le document est destiné à être en lecture seule et ne sera jamais modifié. C'est un indicateur consultatif, que les auteurs de systèmes liés à PPI peuvent ou non utiliser pour activer des optimisations et des caches pour votre document.

Retourne vrai si le document est en lecture seule ou faux sinon.

tab_width [ $width ]

Afin de gérer correctement le support de "location", les "Documents" doivent comprendre le concept d'onglets et de largeur d'onglet. La méthode "tab_width" est utilisée pour obtenir et définir la taille de la largeur d'onglet.

À l'heure actuelle, PPI ne prend en charge que les onglets "naïfs" (largeur 1), mais nous prévoyons de prendre en charge des largeurs d'onglets arbitraires, par défaut et auto-détectées plus tard.

Retourne la largeur d'onglet sous forme d'entier, ou "die" si vous tentez de définir la largeur d'onglet.

NAME

PPI::Document - The overall document object

INHERITANCE

PPI::Document extends PPI::Node.

SYNOPSIS

  my $document = PPI::Document->new();
  $document->parse_from_file( 'My/Module.pm' );
  my @statements = $document->find( 'PPI::Statement' );
  $document->save( 'My/Module.pm.bak' );

DESCRIPTION

This is the main document object. It is also the root of the document's Element tree, and as such inherits from PPI::Node.

The PPI::Document object is a representation of an entire Perl document, as parsed by PPI. It holds the entire structure of the document, from the package declaration down to the individual tokens.

This object is also responsible for loading and saving Perl documents, and contains a number of utility methods for working with the document as a whole.

METHODS

custom_feature_includes { module_name => { feature_name => $provider } }

A method to determine if a document contains a specific feature.

custom_feature_include_cb sub { ... }

A callback hook for features.

save

$document->save( $file )

The "save" method serializes the "PPI::Document" object and saves the resulting Perl document to a file. Returns "undef" on failure to open or write to the file.

serialize

Unlike the "content" method, which shows only the immediate content within an element, Document objects also have to be able to be written out to a file again.

When doing this we need to take into account some additional factors.

Primarily, we need to handle here-docs correctly, so that are written to the file in the expected place.

The "serialize" method generates the actual file content for a given Document object. The resulting string can be written straight to a file.

Returns the serialized document as a string.

hex_id

The "hex_id" method generates an unique identifier for the Perl document.

This identifier is basically just the serialized document, with Unix-specific newlines, passed through MD5 to produce a hexadecimal string.

This identifier is used by a variety of systems (such as PPI::Cache and Perl::Metrics) as a unique key against which to store or cache information about a document (or indeed, to cache the document itself).

Returns a 32 character hexadecimal string.

index_locations

Within a document, all PPI::Element objects can be considered to have a "location", a line/column position within the document when considered as a file. This position is primarily useful for debugging type activities.

The method for finding the position of a single Element is a bit laborious, and very slow if you need to do it a lot. So the "index_locations" method will index and save the locations of every Element within the Document in advance, making future calls to <PPI::Element::location> virtually free.

Please note that this index should always be cleared using "flush_locations" once you are finished with the locations. If content is added to or removed from the file, these indexed locations will be wrong.

flush_locations

When no longer needed, the "flush_locations" method clears all location data from the tokens.

normalized

The "normalized" method is used to generate a "Layer 1" PPI::Document::Normalized object for the current Document.

A "normalized" Perl Document is an arbitrary structure that removes any irrelevant parts of the document and refactors out variations in style, to attempt to approach something that is closer to the "true meaning" of the Document.

See PPI::Normal for more information on document normalization and the tasks for which it is useful.

Returns a PPI::Document::Normalized object, or "undef" on error.

complete

The "complete" method is used to determine if a document is cleanly structured, all braces are closed, the final statement is fully terminated and all heredocs are fully entered.

Returns true if the document is complete or false if not.

errstr

For error that occur when loading and saving documents, you can use "errstr", as either a static or object method, to access the error message.

If a Document loads or saves without error, "errstr" will return false.
