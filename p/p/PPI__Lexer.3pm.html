PPI::Lexer(3) Documentation Perl fournie par les contributeurs PPI::Lexer(3)

NOM

PPI::Lexer - Le lexer PPI

SYNTAXE

use PPI;

# Créer un nouveau Lexer
my $Lexer = PPI::Lexer->new;

# Construire un objet PPI::Document à partir d'un flux de tokens
my $Tokenizer = PPI::Tokenizer->load('Mon/Module.pm');
my $Document = $Lexer->lex_tokenizer($Tokenizer);

# Construire un objet PPI::Document pour du code source brut
my $source = "print 'Bonjour le monde!'; kill(Humains->tous);";
$Document = $Lexer->lex_source($source);

# Construire un objet PPI::Document pour un nom de fichier particulier
$Document = $Lexer->lex_file('Mon/Module.pm');

DESCRIPTION

C'est le lexer de PPI. Dans l'ensemble, son travail consiste à prendre des flux de tokens, sous diverses formes, et à les "lexer" en structures imbriquées.

Presque tout dans ce module se déroule en coulisses pour le moment. En fait, pour l'instant, vous n'avez pas vraiment besoin d'instancier le lexer, les trois méthodes principales s'instancieront automatiquement un objet "PPI::Lexer" si nécessaire.

Toutes les méthodes effectuent une seule opération : "lexer ceci et me donner un objet PPI::Document".

En fait, si vous lisez ceci, ce que vous voulez probablement faire, c'est simplement "charger un document", auquel cas vous pouvez le faire de manière beaucoup plus directe et concise avec l'une des méthodes suivantes.

use PPI;

$Document = PPI::Document->load( $filename );
$Document = PPI::Document->new( $string );

Voir PPI::Document pour plus de détails.

Pour des tâches plus inhabituelles, n'hésitez pas à continuer.

MÉTHODES

new

Le constructeur "new" crée un nouvel objet "PPI::Lexer". L'objet lui-même est simplement utilisé pour contenir divers tampons et données d'état pendant le processus de lexing, et ne contient aucune donnée significative entre les appels ->lex_xxxxx.

Retourne un nouvel objet "PPI::Lexer"

lex_file $nom_de_fichier

La méthode "lex_file" prend un nom de fichier comme argument. Elle charge ensuite le fichier, crée un PPI::Tokenizer pour le contenu et fait le lexing du flux de tokens produit par le tokenizer. Essentiellement, une méthode tout-en-un pour obtenir un objet PPI::Document à partir d'un nom de fichier.

Les arguments supplémentaires sont transmis au tokenizer sous forme de hash.

Retourne un objet PPI::Document, ou "undef" en cas d'erreur.

lex_source $chaîne

La méthode "lex_source" prend une chaîne scalaire normale comme argument. Elle crée un objet PPI::Tokenizer pour la chaîne, puis fait le lexing du flux de tokens résultant.

Les arguments supplémentaires sont transmis au tokenizer sous forme de hash.

Retourne un objet PPI::Document, ou "undef" en cas d'erreur.

lex_tokenizer $Tokenizer

La méthode "lex_tokenizer" prend un objet PPI::Tokenizer comme argument. Elle fait le lexing du flux de tokens du tokenizer en un objet PPI::Document.

Les arguments supplémentaires sont définis sur le PPI::Document produit.

Retourne un objet PPI::Document, ou "undef" en cas d'erreur.

errstr

Pour toute erreur survenant, vous pouvez utiliser "errstr", soit comme méthode statique, soit comme méthode d'objet, pour accéder au message d'erreur.

Si aucune erreur ne se produit pour une action particulière, "errstr" retournera faux.
