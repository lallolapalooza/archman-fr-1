NOM

PPI::Statement::Package - Une instruction de package

HÉRITAGE

PPI::Statement::Package
isa PPI::Statement
    isa PPI::Node
        isa PPI::Element

DESCRIPTION

La plupart des sous-classes de PPI::Statement sont attribuées en fonction de la valeur du premier jeton ou mot trouvé dans l'instruction. Lorsque PPI rencontre une instruction commençant par 'package', il la convertit en un objet "PPI::Statement::Package".

Lorsque vous travaillez avec des instructions de package, n'oubliez pas que les packages n'existent que dans leur portée, et que la prise en charge correcte des portées n'est pas encore achevée dans PPI.

Cependant, si le parent immédiat de l'instruction de package est l'objet PPI::Document de niveau supérieur, elle peut être considérée comme définissant tout ce qui est trouvé jusqu'à la prochaine instruction de package à portée de fichier ("file scoped") de niveau supérieur.

Un fichier peut toutefois contenir des packages imbriqués temporaires, auquel cas vous êtes largement seul :)

MÉTHODES

"PPI::Statement::Package" possède un certain nombre de méthodes en plus des méthodes standard PPI::Statement, PPI::Node et PPI::Element.

namespace

La plupart des déclarations de package sont simples et se présentent comme suit :

package Foo::Bar;

La méthode "namespace" renvoie le nom du package déclaré, dans l'exemple ci-dessus 'Foo::Bar'. Elle le renvoie exactement tel qu'il est écrit et n'essaie pas de nettoyer ou de résoudre des choses comme ::Foo vers main::Foo.

Si l'instruction de package est faite différemment, elle renvoie faux.

version

Certaines déclarations de package peuvent inclure une version :

package Foo::Bar 1.23;
package Baz v1.23;

La méthode "version" renvoie la version sous forme de chaîne telle qu'elle apparaît dans le document (s'il y en a une), sinon une chaîne vide.

file_scoped

Indépendamment du fait qu'elle soit nommée ou non, la méthode "file_scoped" vérifie si la déclaration de package est une instruction de premier niveau "à portée de fichier" ou non, en fonction de son emplacement.

En général, renvoie vrai si c'est une déclaration de package "à portée de fichier" avec un parent immédiat du Document de niveau supérieur, ou faux sinon.

Notez que si l'arbre DOM de PPI n'a **pas** d'objet PPI::Document comme élément racine, cela renverra faux. De même, cela renverra également faux si l'élément racine est un PPI::Document::Fragment, car un fragment de fichier ne représente pas une portée.
