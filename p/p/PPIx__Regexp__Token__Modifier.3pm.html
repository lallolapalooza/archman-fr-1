PPIx::Regexp::Token::Modifier(3) Documentation Perl fournie par l'utilisateur PPIx::Regexp::Token::Modifier(3)

NOM

PPIx::Regexp::Token::Modifier - Représente les modificateurs.

SYNOPSIS

use PPIx::Regexp::Dumper;
PPIx::Regexp::Dumper->new( 'qr{foo}smx' )
    ->print();

Le "smx" final sera représenté par cette classe.

Cette classe représente également l'intégralité d'éléments tels que "(?ismx)". Mais les modificateurs dans quelque chose comme "(?i:foo)" sont représentés par une PPIx::Regexp::Token::GroupType::Modifier.

HÉRITAGE

"PPIx::Regexp::Token::Modifier" est un PPIx::Regexp::Token.

"PPIx::Regexp::Token::Modifier" est le parent de PPIx::Regexp::Token::GroupType::Modifier.

DESCRIPTION

Cette classe représente les caractères modificateurs à la fin de l'expression régulière. Par exemple, dans "qr{foo}smx" cette classe représenterait le terminal "smx".

Les modificateurs "a", "aa", "d", "l", et "u"

Les modificateurs "a", "aa", "d", "l" et "u", introduits à partir de Perl 5.13.6, sont utilisés pour forcer soit la sémantique des motifs Unicode ("u"), la sémantique de localisation ("l"), la sémantique par défaut ("d", la sémantique Perl traditionnelle, qui peut également signifier 'dual' car elle signifie Unicode si le bit UTF-8 de la chaîne est activé, et locale si le bit UTF-8 est désactivé), ou la sémantique par défaut restreinte ("a"). Ceux-ci sont mutuellement exclusifs, et un seul peut être affirmé à la fois. L'affirmation de l'un de ceux-ci remplace la valeur héritée de l'un des autres. La méthode asserted() signale comme affirmé le dernier qu'elle voit, ou aucun d'entre eux si elle n'en a vu aucun.

Par exemple, étant donné "PPIx::Regexp::Token::Modifier" $elem représentant le fragment d'expression régulière invalide "(?dul)", "$elem->asserted( 'l' )" retournerait vrai, mais "$elem->asserted( 'u' )" retournerait faux. Notez que "$elem->negated( 'u' )" retournerait également faux, car "u" n'est pas explicitement nié.

Si $elem représentait le fragment d'expression régulière "(?i)", "$elem->asserted( 'd' )" retournerait faux, car même si "d" représente le comportement par défaut, il n'est pas explicitement affirmé.

Le modificateur caret ("^")

Appeler le "^" un modificateur est un terme un peu impropre. La construction "(?^...)" a été introduite dans Perl 5.13.6, pour empêcher l'héritage des modificateurs. La documentation appelle le caret un raccourci équivalent à "d-imsx", et c'est ainsi que cette classe le gère.

Par exemple, étant donné "PPIx::Regexp::Token::Modifier" $elem représentant le fragment d'expression régulière "(?^i)", "$elem->asserts( 'd' )" retournerait vrai, car en l'absence d'un "l" ou "u" explicite, cette classe considère le "^" comme affirmant explicitement "d".

La gestion du caret est compliquée par le fait que le modificateur 'n' a été introduit dans 5.21.8, moment auquel le caret est devenu équivalent à "d-imnsx". Je n'ai pas jugé pouvoir ajouter inconditionnellement le "-n" à l'expansion du caret, car cela produirait une sortie confuse de méthodes telles que explain(). Je ne pouvais pas non plus le rendre conditionnel à la version minimale de perl, car cette information n'est pas disponible assez tôt dans l'analyse. Ce que j'ai fait, c'est d'étendre le caret en "d-imnsx" si et seulement si 'n' était en vigueur à un moment donné dans la portée dans laquelle le modificateur a été analysé.

Pour continuer l'exemple ci-dessus, "$elem->asserts( 'n' )" et "$elem->modifier_asserted( 'n' )" retourneraient tous deux faux, mais "$elem->negates( 'n' )" retournerait vrai si et seulement si le modificateur '/m' a été affirmé quelque part avant et dans la portée de ce jeton. La méthode modifier_asserted( 'n' ) est héritée de PPIx::Regexp::Element.

MÉTHODES

Cette classe fournit les méthodes publiques suivantes. Les méthodes non documentées ici sont privées et non supportées dans le sens où l'auteur se réserve le droit de les modifier ou de les supprimer sans préavis.

asserts

$token->asserts( 'i' ) and print "le jeton affirme i";
foreach ( $token->asserts() ) { print "le jeton affirme $_\n" }

Cette méthode retourne vrai si le jeton affirme explicitement le modificateur donné. L'exemple retournerait vrai pour le modificateur dans "(?i:foo)", mais faux pour "(?-i:foo)".

À partir de la version 0.036_01, si l'argument est un modificateur d'un seul caractère suivi d'un astérisque (utilisé comme caractère générique), le retour est le nombre de fois où ce modificateur apparaît. Dans ce cas, une exception sera levée si vous spécifiez un modificateur multi-caractères (par exemple, 'ee*').

Si elle est appelée sans argument, ou avec un argument indéfini, tous les modificateurs explicitement affirmés par ce jeton sont retournés.

match_semantics

my $sem = $token->match_semantics();
defined $sem or $sem = 'undefined';
print "Ce jeton a une sémantique de correspondance $sem\n";

Cette méthode retourne la sémantique de correspondance affirmée par le jeton, sous forme de l'une des chaînes 'a', 'aa', 'd', 'l', ou 'u'. Si aucune sémantique de correspondance explicite n'est affirmée, cette méthode retourne "undef".

modifiers

my %mods = $token->modifiers();

Retourne tous les modificateurs affirmés ou niés par ce jeton, et les valeurs définies (vrai pour affirmé, faux pour nié). Si elle est appelée en contexte scalaire, retourne une référence à un hachage contenant les valeurs.

negates

$token->negates( 'i' ) and print "le jeton nie i\n";
foreach ( $token->negates() ) { print "le jeton nie $_\n" }

Cette méthode retourne vrai si le jeton nie explicitement le modificateur donné. L'exemple retournerait vrai pour le modificateur dans "(?-i:foo)", mais faux pour "(?i:foo)".

Si elle est appelée sans argument, ou avec un argument indéfini, tous les modificateurs explicitement niés par ce jeton sont retournés.
