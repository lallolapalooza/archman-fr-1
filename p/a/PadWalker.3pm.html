NOM

PadWalker - manipuler les variables lexicales d'autres personnes

SYNOPSIS

use PadWalker qw(peek_my peek_our peek_sub closed_over);
...

DESCRIPTION

PadWalker est un module qui vous permet d'inspecter (et même de modifier !) les variables lexicales de toute sous-routine qui vous a appelé. Il ne montrera que les variables qui sont dans la portée au moment de l'appel.

PadWalker est particulièrement utile pour le débogage. Il est même utilisé par le débogueur intégré de Perl. (Il peut aussi être utilisé pour le mal, bien sûr.)

Je ne recommanderais pas d'utiliser PadWalker directement dans du code de production, mais c'est votre choix. Certains modules qui utilisent PadWalker en interne sont certainement sûrs et utiles en production.

peek_my NIVEAU
peek_our NIVEAU
L'argument NIVEAU est interprété comme l'argument de "caller". Ainsi, peek_my(0) retourne une référence à une table de hachage de toutes les variables "my" qui sont actuellement dans la portée ; peek_my(1) retourne une référence à une table de hachage de toutes les variables "my" qui sont dans la portée au moment où la sous-routine actuelle a été appelée, et ainsi de suite.

"peek_our" fonctionne de la même manière, sauf qu'il liste les variables "our" plutôt que les variables "my".

La table de hachage associe chaque nom de variable à une référence vers sa valeur. Les noms de variables incluent le sigil, donc la variable $x est représentée par la chaîne '$x'.

Par exemple :

my $x = 12;
my $h = peek_my (0);
${$h->{'$x'}}++;
print $x;  # affiche 13

Ou un exemple plus complexe :

sub increment_my_x {
  my $h = peek_my (1);
  ${$h->{'$x'}}++;
}
my $x=5;
increment_my_x;
print $x;  # affiche 6
peek_sub SUB
La routine "peek_sub" prend un coderef comme argument et retourne une table de hachage des variables "my" utilisées dans cette sous-routine. Les valeurs seront généralement indéfinies à moins que la sous-routine ne soit en cours d'utilisation (c'est-à-dire dans la chaîne d'appels) au moment donné. Par contre : 
my $x = "Bonjour !";
my $r = peek_sub(sub {$x})->{'$x'};
print "$$r\n";        # affiche 'Bonjour !'

Si la sous-routine définit plusieurs variables "my" du même nom, vous obtiendrez la dernière. Je ne connais aucune utilisation de "peek_sub" qui ne soit pas cassée en conséquence, et elle sera probablement dépréciée dans une future version en faveur d'une interface alternative.

closed_over SUB
"closed_over" est similaire à "peek_sub", sauf qu'il ne liste que les variables "my" qui sont utilisées dans la sous-routine mais définies à l'extérieur : en d'autres termes, les variables qu'elle ferme. Ceci a des utilisations raisonnables : voir Data::Dump::Streamer, par exemple (une future version de ce dernier pourrait en fait utiliser "closed_over").
set_closed_over SUB, HASH_REF
"set_closed_over" réaffecte les variables du pad qui sont fermées par la sous-routine.

Le second argument est une table de hachage de références, très similaire à celle retournée par "closed_over".

var_name NIVEAU, VAR_REF
var_name SUB, VAR_REF
"var_name(sub, var_ref)" retourne le nom de la variable référencée par "var_ref", à condition qu'il s'agisse d'une variable "my" utilisée dans la sous-routine. Le paramètre "sub" peut être une référence CODE ou un nombre. S'il s'agit d'un nombre, il est traité de la même manière que l'argument de "peek_my".

Par exemple,

my $foo;
print var_name(0, \$foo);    # affiche '$foo'

sub my_name {
  return var_name(1, shift);
}
print my_name(\$foo);        # idem
