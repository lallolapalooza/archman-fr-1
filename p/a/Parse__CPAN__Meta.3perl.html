Parse::CPAN::Meta(3perl) Guide de référence des programmeurs Perl Parse::CPAN::Meta(3perl)

NOM

Parse::CPAN::Meta - Analyse les fichiers de métadonnées CPAN META.yml et META.json

VERSION

version 2.150010

SYNOPIS

#############################################
# Dans votre fichier
---
name: My-Distribution
version: 1.23
resources:
  homepage: "http://example.com/dist/My-Distribution"
#############################################
# Dans votre programme
use Parse::CPAN::Meta;
my $distmeta = Parse::CPAN::Meta->load_file('META.yml');
# Lecture des propriétés
my $name     = $distmeta->{name};
my $version  = $distmeta->{version};
my $homepage = $distmeta->{resources}{homepage};

DESCRIPTION

Parse::CPAN::Meta est un analyseur pour les fichiers META.json et META.yml, utilisant JSON::PP et/ou CPAN::Meta::YAML.

Parse::CPAN::Meta fournit trois méthodes : "load_file", "load_json_string" et "load_yaml_string". Celles-ci liront et désérialiseront les métadonnées CPAN, et sont décrites ci-dessous en détail.

Parse::CPAN::Meta fournit une API héritée de seulement deux fonctions, basées sur les fonctions YAML du même nom. Dans la mesure du possible, les mêmes sémantiques d'appel sont utilisées. Celles-ci ne peuvent être utilisées qu'avec des sources YAML.

Tous les rapports d'erreurs sont effectués par exceptions (die'ing).

Notez que les fichiers META sont censés être en encodage UTF-8 uniquement. Lorsqu'il s'agit de données sous forme de chaînes de caractères, elles doivent d'abord être décodées depuis UTF-8.

MÉTHODES

load_file

my $structure_metadonnees = Parse::CPAN::Meta->load_file('META.json');
my $structure_metadonnees = Parse::CPAN::Meta->load_file('META.yml');

Cette méthode lira le fichier nommé et le désérialisera en une structure de données, déterminant s'il s'agit de JSON ou de YAML en fonction du nom de fichier. Le fichier sera lu en utilisant la couche IO ":utf8".

load_yaml_string

my $structure_metadonnees = Parse::CPAN::Meta->load_yaml_string($chaine_yaml);

Cette méthode désérialise la chaîne YAML donnée et retourne le premier document qu'elle contient. (Les fichiers de métadonnées CPAN ne devraient toujours contenir qu'un seul document.) Si la source était encodée en UTF-8, la chaîne doit être décodée avant d'appeler "load_yaml_string".

load_json_string

my $structure_metadonnees = Parse::CPAN::Meta->load_json_string($chaine_json);

Cette méthode désérialise la chaîne JSON donnée et le résultat. Si la source était encodée en UTF-8, la chaîne doit être décodée avant d'appeler "load_json_string".

load_string

my $structure_metadonnees = Parse::CPAN::Meta->load_string($une_chaine);

Si vous ne savez pas si une chaîne contient des données YAML ou JSON, cette méthode utilisera quelques heuristiques pour deviner. Si elle ne peut pas déterminer, elle suppose YAML.

yaml_backend

my $backend = Parse::CPAN::Meta->yaml_backend;

Retourne le nom du module du sérialiseur YAML. Voir "ENVIRONNEMENT" pour plus de détails.

json_backend

my $backend = Parse::CPAN::Meta->json_backend;

Retourne le nom du module du sérialiseur JSON. Si "CPAN_META_JSON_BACKEND" est défini, ce sera ce à quoi il est défini. Sinon, ce sera soit JSON::PP, soit JSON. Si "PERL_JSON_BACKEND" est défini, cela retournera JSON car la délégation supplémentaire est gérée par le module JSON. Voir "ENVIRONNEMENT" pour plus de détails.

json_decoder

my $decoder = Parse::CPAN::Meta->json_decoder;

Retourne le nom du module du décodeur JSON. Contrairement à "json_backend", ce n'est pas nécessairement un module complet de style JSON, mais seulement quelque chose qui fournira une sous-routine "decode_json". Si "CPAN_META_JSON_DECODER" est défini, ce sera ce à quoi il est défini. Sinon, ce sera ce qui a été sélectionné comme "json_backend". Voir "ENVIRONNEMENT" pour plus de notes.

FONCTIONS

Pour des raisons de clarté de maintenance, aucune fonction n'est exportée par défaut. Ces fonctions sont disponibles uniquement pour des raisons de compatibilité ascendante et il est préférable de les éviter au profit de "load_file".

Load

my @yaml = Parse::CPAN::Meta::Load( $string );

Analyse une chaîne contenant un flux YAML valide en une liste de structures de données Perl.

LoadFile

my @yaml = Parse::CPAN::Meta::LoadFile( 'META.yml' );

Lit le flux YAML à partir d'un fichier au lieu d'une chaîne de caractères.

ENVIRONNEMENT

CPAN_META_JSON_DECODER

Par défaut, JSON::PP sera utilisé pour désérialiser les données JSON. Si la variable d'environnement "CPAN_META_JSON_DECODER" existe, elle devrait être le nom d'un module chargeable qui fournit une sous-routine "decode_json", qui sera alors utilisée pour la désérialisation. Le fait de ne s'appuyer que sur l'existence de ladite sous-routine permet une compatibilité maximale, car cette API est fournie par JSON::PP, JSON::XS, Cpanel::JSON::XS, JSON::MaybeXS, JSON::Tiny et Mojo::JSON.

CPAN_META_JSON_BACKEND

Par défaut, JSON::PP sera utilisé pour désérialiser les données JSON. Si la variable d'environnement "CPAN_META_JSON_BACKEND" existe, elle devrait être le nom d'un module chargeable qui fournit l'API JSON, car le code en aval s'attend à pouvoir appeler "new" sur cette classe. Ainsi, bien que JSON::PP, JSON::XS, Cpanel::JSON::XS et JSON::MaybeXS fonctionnent pour cela, utiliser Mojo::JSON ou JSON::Tiny pour le décodage nécessite de définir "CPAN_META_JSON_DECODER".

PERL_JSON_BACKEND

Si la variable d'environnement "CPAN_META_JSON_BACKEND" n'existe pas, et si la variable d'environnement "PERL_JSON_BACKEND" existe, est vraie et n'est pas "JSON::PP", alors le module JSON (version 2.5 ou supérieure) sera chargé et utilisé pour interpréter "PERL_JSON_BACKEND". Si JSON n'est pas installé ou est trop ancien, une exception sera levée. Notez qu'au moment de la rédaction, les seules valeurs utiles sont 1, qui demandera à JSON de deviner, ou JSON::XS - si vous voulez utiliser un module JSON plus récent, voir "CPAN_META_JSON_BACKEND".

PERL_YAML_BACKEND

Par défaut, CPAN::Meta::YAML sera utilisé pour désérialiser les données YAML. Si la variable d'environnement "PERL_YAML_BACKEND" est définie, alors elle est interprétée comme un module à utiliser pour la désérialisation. Le module donné doit être installé, doit se charger correctement et doit implémenter la fonction Load() ou une exception sera levée.
