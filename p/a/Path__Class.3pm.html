NOM

Path::Class - Manipulation de chemins multiplateforme

VERSION

version 0.37

SYNOPIS

use Path::Class;

my $dir  = dir('foo', 'bar');       # Objet Path::Class::Dir
my $file = file('bob', 'file.txt'); # Objet Path::Class::File

# Se sérialise en 'foo/bar' sous Unix, 'foo\bar' sous Windows, etc.
print "dir: $dir\n";

# Se sérialise en 'bob/file.txt' sous Unix, 'bob\file.txt' sous Windows
print "file: $file\n";

my $subdir  = $dir->subdir('baz');  # foo/bar/baz
my $parent  = $subdir->parent;      # foo/bar
my $parent2 = $parent->parent;      # foo

my $dir2 = $file->dir;              # bob
# Travailler avec des chemins étrangers
use Path::Class qw(foreign_file foreign_dir);
my $file = foreign_file('Mac', ':foo:file.txt');
print $file->dir;                   # :foo:
print $file->as_foreign('Win32');   # foo\file.txt

# Interagir avec le système de fichiers :

# $dir_handle est un objet IO::Dir
my $dir_handle = $dir->open or die "Impossible de lire $dir: $!";

# $file_handle est un objet IO::File
my $file_handle = $file->open($mode) or die "Impossible de lire $file: $!";

DESCRIPTION

"Path::Class" est un module pour la manipulation de chemins (chaînes de caractères décrivant leur emplacement, comme '/home/ken/foo.txt' ou 'C:\Windows\Foo.txt') de manière multiplateforme. Il est compatible avec presque tous les systèmes d'exploitation sur lesquels Perl s'exécute, y compris Unix, Windows, Mac, VMS, Epoc, Cygwin, OS/2 et NetWare.

Le module bien connu "File::Spec" fournit également ce service, mais il est un peu fastidieux à utiliser correctement, il est donc parfois évité ou utilisé d'une manière qui ne fonctionne pas correctement sur des plateformes autres que celles sur lesquelles le code a été testé.

En fait, "Path::Class" utilise "File::Spec" en interne, en couvrant tous les détails fastidieux afin que vous puissiez vous concentrer sur votre code d'application. Contrairement à "File::Spec", qui fournit des fonctions pour manipuler des chemins courants, "Path::Class" offre un modèle orienté objet de la réalité des chemins et de leurs significations sous-jacentes. "File::Spec" ne crée pas d'objets, et ses classes représentent différentes manières dont les chemins doivent être manipulés sur différentes plateformes (un concept pas très intuitif). "Path::Class" crée des objets représentant des fichiers et des répertoires, et offre des méthodes relatives entre eux. Par exemple, le code suivant de "File::Spec" : 

my $absolute = File::Spec->file_name_is_absolute(
                 File::Spec->catfile( @dirs, $file )
               );
peut être écrit en utilisant "Path::Class" comme suit : 
my $absolute = Path::Class::File->new( @dirs, $file )->is_absolute;
ou même comme : 
my $absolute = file( @dirs, $file )->is_absolute;

Des améliorations de lisibilité similaires devraient se produire partout lors de l'utilisation de "Path::Class".

L'utilisation de "Path::Class" peut aider à résoudre de vrais problèmes dans votre code - par exemple, combien de personnes tiennent réellement compte du « volume » (comme "C:" sous Windows) lorsqu'elles écrivent du code qui utilise "File::Spec" ? Je ne pense pas. Mais si vous utilisez "Path::Class", vos objets de fichier et de répertoire connaîtront les volumes auxquels ils se réfèrent et feront ce qu'il faut.

Le cœur de "Path::Class" réside dans les modules Path::Class::File et Path::Class::Dir, veuillez donc consulter la documentation de ces modules pour plus de détails sur leur utilisation.

EXPORT

Les fonctions suivantes sont exportées par défaut.

file
Un alias pour "Path::Class::File->new".
dir
Un alias pour "Path::Class::Dir->new".

Si vous souhaitez éviter leur exportation, vous pouvez passer une liste vide à "use" de Perl, c'est-à-dire "use Path::Class ()".

Les éléments suivants sont exportés uniquement sur demande.

foreign_file
Un alias pour "Path::Class::File->new_foreign".
foreign_dir
Un alias pour "Path::Class::Dir->new_foreign".
tempdir
Crée un objet Path::Class::Dir pointant vers un répertoire temporaire. 
my $temp = Path::Class::tempdir(CLEANUP => 1);

Un alias pour "Path::Class::Dir->new(File::Temp::tempdir(@_))".

Notes sur la compatibilité multiplateforme

Bien qu'il soit plus facile d'écrire du code multiplateforme avec ce module qu'avec "File::Spec", il y a toujours quelques problèmes à garder à l'esprit.

•
Sur certaines plateformes, notamment VMS et certaines anciennes versions de DOS (je suppose), tous les fichiers doivent avoir une extension. Par conséquent, si vous créez un fichier nommé foo/bar et demandez ensuite une liste de fichiers dans le répertoire foo, vous pourriez trouver un fichier nommé bar. au lieu de bar que vous attendiez. Il pourrait donc être judicieux d'utiliser une extension dès le départ.
