NOM

PAR::Environment - Index et référence des variables d'environnement PAR

DESCRIPTION

PAR utilise diverses variables d'environnement à la fois lors du processus de construction des exécutables ou des archives PAR et lors de leur utilisation. La richesse des combinaisons et des paramètres pouvant confondre l'un ou l'autre (comme moi), ce document est destiné à documenter toutes les variables d'environnement que PAR utilise.

Partout où je souhaite faire référence à l'entrée du hash d'environnement $ENV{FOO}, je parlerai généralement de la variable "FOO" par souci de brièveté.

INDEX DES VARIABLES D'ENVIRONNEMENT

Veuillez noter que ceci est encore très, très incomplet ! Contributions bienvenues !

Pour chaque variable, il devrait y avoir une description de ce qu'elle contient, quand on peut s'attendre à ce qu'elle existe (et contienne des informations significatives), quand il est judicieux de la définir soi-même, et quel effet cela a.

Bien entendu, la description peut utiliser des exemples.

PAR_0

Si le programme en cours d'exécution est lancé depuis une archive PAR ou un exécutable produit par pp, cette variable contient le nom du programme extrait (c'est-à-dire le fichier .pl). Ceci est utile si vous voulez ouvrir le fichier source du programme en cours d'exécution.

Par exemple, si vous emballez un fichier foo.pl dans bar.par et que vous exécutez foo.pl avec cette commande

par.pl foo.par bar.pl

alors la variable "PAR_0" contiendra quelque chose comme "/tmp/par-youser/cache-b175f53eb731da9594e0dde337d66013ddf25a44/495829f0.pl" où "youser" est votre nom d'utilisateur et "/tmp/par-youser/cache-b175f53eb731da9594e0dde337d66013ddf25a44/" est le répertoire cache de PAR ("PAR_TEMP").

Le nom du répertoire cache de PAR peut prendre un certain nombre de formes différentes, utilisez donc "PAR_0" si vous voulez trouver le fichier .pl du programme extrait -- tenter de construire le nom soi-même nécessite une logique complexe qui a déjà produit la valeur dans "PAR_0".

Cela fonctionne de la même manière pour les binaires exécutables (.exe, ...).

Si vous recherchez le nom et le chemin du fichier binaire pp-ed, veuillez vous référer à la variable "PAR_PROGNAME".

PAR_CLEAN

Les utilisateurs devraient plutôt définir "PAR_GLOBAL_CLEAN".

Recréée à partir de "PAR_GLOBAL_CLEAN" et de la valeur de "-C" du fichier YAML par le chargeur PAR, et utilisée dans le chargeur pour contrôler le comportement initial de l'extraction, et le comportement final du nettoyage. L'utilisateur peut référencer "PAR_CLEAN" dans l'application pour déterminer quel comportement est utilisé pour cette exécution de l'application.

PAR_DEBUG

Les utilisateurs devraient plutôt définir "PAR_GLOBAL_DEBUG".

Si cette variable est définie à une valeur vraie et que par.pl est exécuté, une sortie détaillée est envoyée à STDOUT ou au descripteur de fichier de journalisation. Ceci est remplacé par l'option "-q" de par.pl, pour les étapes après l'analyse des arguments.

Ceci n'influence actuellement que par.pl. Il reste à vérifier si c'est le comportement prévu.

PAR_GLOBAL_CLEAN

La définition de "PAR_GLOBAL_CLEAN" modifie le comportement des applications PAR qui voient cette variable d'environnement au lancement. "PAR_GLOBAL_CLEAN" remplace l'option "-C". Les valeurs 0 et 1 sont supportées. 0 correspond à ne pas utiliser "-C" sur la ligne de commande de pp ; 1 correspond à utiliser "-C" sur la ligne de commande de pp. "PAR_GLOBAL_CLEAN" est ignoré si "PAR_GLOBAL_TEMP" est définie, mais elle contrôle la forme de "PAR_TEMP" lorsque "PAR_GLOBAL_TEMP" n'est pas définie.

PAR_GLOBAL_DEBUG

Le chargeur PAR devient plus détaillé lorsque "PAR_DEBUG" est définie. Définir "PAR_GLOBAL_DEBUG" garantit que "PAR_DEBUG" sera définie en interne, initialement. Voir "PAR_DEBUG" pour plus de détails.

PAR_GLOBAL_TEMP

Contribue au calcul de "PAR_TEMP", et est expliqué plus en détail là.

PAR_GLOBAL_TMPDIR

Contribue au calcul de "PAR_TEMP", et est expliqué plus en détail là.

PAR_INITIALIZED

Cette variable d'environnement est réservée à un usage interne par le chargeur binaire PAR uniquement. Documentée uniquement pour éviter les surprises si des applications lancées s'attendent à voir une valeur initialisée par l'utilisateur.

PAR_PROGNAME

"PAR_PROGNAME" est défini sur le chemin d'accès complet du programme exécutable. Sous Windows, cela est obtenu de manière fiable à partir de l'API "GetModuleFileName". Sur d'autres OS, si le runtime C reçoit un nom de chemin qualifié, il est utilisé, ou le nom de fichier non qualifié donné est qualifié en parcourant le chemin. Ceci est raisonnablement fiable étant donné les conventions normales de lancement de programmes, mais ne peut être garanti comme étant correct dans toutes les circonstances.

PAR_APP_REUSE

Strictement interne. Sautez cette section si vous n'êtes pas un développeur PAR.

La variable ne devrait jamais être exposée au code utilisateur et les applications empaquetées ne devraient pas dépendre de sa définition ou de sa non-définition.

Si une application a été empaquetée avec l'option "--reusable", le code de démarrage définira cette variable d'environnement sur le nom du programme à exécuter à la place du programme empaqueté. Le script de chargeur main.pl récupère le nom de fichier, supprime la variable d'environnement, puis exécute le programme donné.

PAR_RUN

Cette variable d'environnement était définie lors de la construction des objets "PAR::Packer" (généralement uniquement lors des exécutions de pp) par les versions de PAR jusqu'à 0.957. Depuis PAR 0.958, cette variable est inutilisée.

PAR_SPAWNED

Cette variable est utilisée en interne par le chargeur binaire parl pour signaler au processus enfant qu'il est l'enfant.

Vous ne devriez pas vous fier à cette variable en dehors du code du chargeur binaire PAR. Pour une discussion légèrement plus détaillée, veuillez vous référer au fichier de documentation who_am_i.txt dans la distribution source de PAR, qui a été contribué par Alan Stewart.

Documentée uniquement pour éviter les surprises si des applications lancées s'attendent à voir une valeur initialisée par l'utilisateur.

PAR_TEMP

Les utilisateurs devraient plutôt définir "PAR_GLOBAL_TEMP". "PAR_TEMP" est calculé à partir de diverses autres variables. Voir la section "NOTES" dans le pod de PAR.pm pour une description complète de la manière dont le calcul procède. "PAR_TEMP", une fois calculé, est utilisé comme emplacement où PAR stocke son cache de fichiers extraits et temporaires.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

PAR_TMPDIR

Devient partiellement le calcul de "PAR_TEMP", et est expliqué plus en détail là-bas. Les utilisateurs devraient plutôt définir "PAR_GLOBAL_TMPDIR".

PAR_VERBATIM

La variable "PAR_VERBATIM" contrôle la manière dont le code Perl est encapsulé dans un fichier PAR ou un exécutable binaire. Si une valeur vraie est définie pendant le processus d'encapsulation, les modules (et scripts) ne sont pas passés à travers le filtre par défaut "PAR::Filter::PodStrip", qui supprime toute la documentation POD du code. Il faut se rappeler que le filtre "PAR::Filter::PatchContent" est toujours appliqué.

L'option "-F" du programme pp écrase la valeur de "PAR_VERBATIM". Cela signifie que si vous définissez "PAR_VERBATIM=1" mais que vous spécifiez "-F PodStrip" sur la ligne de commande de "pp", le filtre "PodStrip" sera appliqué.

"PAR_VERBATIM" n'est pas utilisé par le programme PAR.

PAR_VERBOSE

Définir cette variable d'environnement à un nombre positif a le même effet que d'utiliser l'option "-verbose" du programme pp.

PP_OPTS

Lors d'une exécution de pp, le contenu de la variable "PP_OPTS" est traité comme s'il faisait partie de la ligne de commande. Dans les versions plus récentes de PAR, vous pouvez également écrire les options dans un fichier et exécuter pp comme suit pour lire les options du fichier :

pp @FILENAME

Cela peut être combiné avec d'autres arguments de ligne de commande pour pp ou avec la variable "PP_OPTS".

TMP, TEMP, TMPDIR, TEMPDIR

Veuillez vous référer à "PAR_TMPDIR".
