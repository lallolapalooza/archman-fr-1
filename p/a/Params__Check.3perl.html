Params::Check(3perl) Manuel de référence pour les développeurs Perl Params::Check(3perl)

NAME

Params::Check - Un outil générique de validation des entrées/sorties.

SYNOPSIS

use Params::Check qw[check allow last_error];
sub fill_personal_info {
    my %hash = @_;
    my $x;
    my $tmpl = {
        firstname   => { required   => 1, defined => 1 },
        lastname    => { required   => 1, store => \$x },
        gender      => { required   => 1,
                         allow      => [qr/M/i, qr/F/i],
                       },
        married     => { allow      => [0,1] },
        age         => { default    => 21,
                         allow      => qr/^\d+$/,
                       },
        phone       => { allow => [ sub { return 1 if /$valid_re/ },
                                    '1-800-PERL' ]
                       },
        id_list     => { default        => [],
                         strict_type    => 1
                       },
        employer    => { default => 'NSA', no_override => 1 },
    };
    ### check() renvoie un hashref des arguments parsés en cas de succès ###
    my $parsed_args = check( $tmpl, \%hash, $VERBOSE )
                        or die qw[Impossible de parser les arguments !];
    ... code restant ...
}
my $ok = allow( $colour, [qw|blue green yellow|] );
my $error = Params::Check::last_error();

DESCRIPTION

Params::Check est un outil générique de validation des entrées/sorties.

Il permet aux utilisateurs de valider les entrées à l'aide d'un modèle. La seule exigence est que les arguments soient nommés.

Params::Check peut effectuer les actions suivantes :

  • Convertir toutes les clés en minuscules
  • Vérifier si tous les arguments requis ont été fournis
  • Définir les arguments non fournis à leurs valeurs par défaut
  • Supprimer les arguments non pris en charge et en informer l'utilisateur
  • Valider les arguments fournis par rapport à des chaînes de caractères, des expressions régulières, des listes ou même des sous-routines
  • Imposer l'intégrité des types si nécessaire

La majeure partie de la puissance de Params::Check provient de son modèle, qui sera discuté plus loin :

Modèle

Comme vous pouvez le voir dans l'exemple de syntaxe, selon votre modèle, les arguments fournis seront validés.

Le modèle peut avoir différentes règles par clé utilisée.

Les règles suivantes sont disponibles :

default
C'est la valeur par défaut si elle n'a pas été fournie par l'utilisateur. C'est également la valeur que "strict_type" verra lors de la vérification de l'intégrité des types (voir ci-dessous).
required
Un drapeau booléen indiquant si cet argument était un argument obligatoire. S'il est marqué comme obligatoire et n'a pas été fourni, check() échouera.
strict_type
Ceci effectue une vérification de "ref() de l'argument fourni. Le "ref" de l'argument doit être le même que le "ref" de la valeur par défaut pour que la vérification soit valide.
Ceci est très utile si vous souhaitez prendre une référence d'array comme argument, par exemple.
defined
Si cette clé est vraie, elle impose que si l'utilisateur fournit cette clé, sa valeur doit être "defined". Cela signifie simplement que l'utilisateur ne peut pas passer "undef" comme valeur pour cette clé et est équivalent à :
allow => sub { defined $_[0] && AUTRES TESTS }
no_override
Permet de spécifier des "constantes" dans votre modèle. Par exemple, les clés qui ne peuvent pas être modifiées par l'utilisateur. C'est presque comme vous permettre de garder toutes vos données "configurables" au même endroit ; le modèle de "Params::Check".
store
Permet de passer une référence vers un scalaire, dans lequel les données seront stockées :
my $x;
my $args = check(foo => { default => 1, store => \$x }, $input);
Ceci est essentiellement un raccourci pour dire :
my $args = check( { foo => { default => 1 }, $input });
my $x    = $args->{foo};
Vous pourrez modifier la variable globale $Params::Check::NO_DUPLICATES pour contrôler si la clé "store" sera toujours présente dans votre résultat. Voir la section sur les "Variables Globales" pour plus de détails.
Cette fonction gère le "allow" dans le modèle.

Fonctions

check( \%tmpl, \%args, [$verbose] );

Cette fonction n'est pas exposée par défaut, vous devrez donc la demander comme ceci :

use Params::Check qw[check];

ou utilisez son nom complet à la place.

"check" prend une liste d'arguments, comme suit :

Modèle
Il s'agit d'une référence à un modèle tel qu'expliqué dans les sections "SYNOPSIS" et "TEMPLATE".
Arguments
Il s'agit d'une référence à un hash d'arguments qui sont en cours de vérification.
Verbose
Un booléen indiquant si "check" doit être bavard et signaler ce qui a échoué dans une vérification.

"check" renverra faux en cas d'échec, ou un hashref avec des clés en minuscules des arguments parsés en cas de succès.

Ainsi, un appel typique à "check" ressemblerait à ceci :

my $parsed = check( \%template, \%arguments, $VERBOSE )
                or warn q[Les arguments n'ont pas pu être parsés !];

Une grande partie du comportement de "check() peut être modifiée en définissant des variables de paquet. Voir la section sur les "Variables Globales" pour plus de détails à ce sujet.

allow( $test_me, \@criteria );

La fonction qui gère le "allow" dans le modèle peut également être utilisée indépendamment.

La fonction prend comme premier argument une clé à tester et comme second argument toute forme de critère également prise en charge par le "allow" dans le modèle.

Vous pouvez utiliser les types de valeurs suivants pour "allow" :

string
L'argument fourni doit être égal à la chaîne de caractères pour que la vérification soit valide.
regexp
L'argument fourni doit correspondre à l'expression régulière pour que la vérification soit valide.
subroutine
La sous-routine fournie doit renvoyer vrai pour que la vérification soit valide et que l'argument soit accepté. (Ceci est particulièrement utile pour des données plus complexes).
La référence d'array doit contenir tous les types mentionnés ci-dessus.

Renvoie vrai si la clé correspond aux critères, sinon faux.

last_error()

Renvoie une chaîne contenant tous les avertissements et erreurs signalés lors de la dernière vérification de "check".

NOM

Params::Check - Vérification des paramètres

SYNTAXE

Cet outil est utile si vous souhaitez signaler les paramètres différemment lorsque le flag verbeux est actif.

DESCRIPTION

Le comportement de Params::Check peut être modifié en modifiant les variables globales suivantes :

$Params::Check::VERBOSE

Cette valeur contrôle si Params::Check émet des avertissements et explique pourquoi certains éléments peuvent avoir échoué. Si vous le réglez sur 0, Params::Check n'émettra aucun avertissement.

La valeur par défaut est 1 lorsque les avertissements sont activés, 0 dans les autres cas.

$Params::Check::STRICT_TYPE

Ce comportement fonctionne de manière similaire à l'option "strict_type" que vous pouvez passer à "check", qui active "strict_type" globalement pour tous les appels à "check".

La valeur par défaut est 0.

$Params::Check::ALLOW_UNKNOWN

Si vous définissez ce flag, les paramètres inconnus seront toujours présents dans la valeur renvoyée, au lieu d'être filtrés. Ceci est utile si votre sous-routine ne s'intéresse qu'à quelques arguments et souhaite transmettre le reste sans modification, probablement à une autre sous-routine.

La valeur par défaut est 0.

$Params::Check::STRIP_LEADING_DASHES

Si vous définissez ce flag, les clés suivantes passeront par le mode suivant :

function( -key => 'val' );

leurs traits d'union initiaux seront supprimés.

$Params::Check::NO_DUPLICATES

S'il est défini sur true, toutes les clés du modèle qui sont marquées comme stockées dans un scalaire seront également supprimées de l'ensemble des résultats.

La valeur par défaut est false, ce qui signifie que lorsque vous utilisez "store" comme clé du modèle, "check" le placera à la fois dans le scalaire que vous avez spécifié et dans le hashref qu'il renvoie.

$Params::Check::PRESERVE_CASE

S'il est défini sur true, Params::Check ne convertira pas toutes les clés d'entrée de l'utilisateur en minuscules, mais s'attendra à ce qu'elles soient dans le cas que vous avez fourni dans le modèle. Ceci est utile lorsque vous souhaitez utiliser des clés avec différentes capitalisations dans vos modèles.

Vous comprenez que cela supprime la fonctionnalité d'insensibilité à la casse de cette bibliothèque.

La valeur par défaut est 0.

$Params::Check::ONLY_ALLOW_DEFINED

S'il est défini sur true, Params::Check exigera que toutes les valeurs transmises soient "defined". Si vous souhaitez l'activer par clé individuelle, utilisez l'option du modèle "defined".

La valeur par défaut est 0.

$Params::Check::SANITY_CHECK_TEMPLATE

S'il est défini sur true, Params::Check effectuera une vérification des modèles, validant les erreurs et les clés inconnues. Bien que très utile pour le débogage, cela peut être lent dans du code très utilisé et dans de grandes boucles.

Pour désactiver cette vérification, définissez cette variable sur "false".

La valeur par défaut est 1.

$Params::Check::WARNINGS_FATAL

S'il est défini sur true, Params::Check émettra un "croak" lorsqu'une erreur se produit pendant la validation du modèle, au lieu de renvoyer "false".

La valeur par défaut est 0.

$Params::Check::CALLER_DEPTH

Cette variable globale modifie l'argument passé à caller() par l'appelant de Params::Check::check() et est utile si vous avez une fonction d'enveloppement personnalisée autour de Params::Check::check(). La valeur doit être un entier, indiquant le nombre de fonctions d'enveloppement insérées entre l'appel réel et Params::Check::check().

Exemple de fonction d'enveloppement, utilisant une pile d'appels personnalisée :

sub check {
    my ($template, $args_in) = @_;
    local $Params::Check::WARNINGS_FATAL = 1;
    local $Params::Check::CALLER_DEPTH = $Params::Check::CALLER_DEPTH + 1;
    my $args_out = Params::Check::check($template, $args_in);
    my_stacktrace(Params::Check::last_error) unless $args_out;
    return $args_out;
}

La valeur par défaut est 0.
