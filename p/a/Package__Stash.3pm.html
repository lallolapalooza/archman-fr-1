NAME

Package::Stash - Routines pour manipuler les stashes (tables de symboles de Perl)

VERSION

version 0.40

SYNOPSIS

my $stash = Package::Stash->new('Foo');
$stash->add_symbol('%foo', {bar => 1});
# $Foo::foo{bar} == 1
$stash->has_symbol('$foo') # false
my $namespace = $stash->namespace;
*{ $namespace->{foo} }{HASH} # {bar => 1}

DESCRIPTION

La manipulation des stashes (tables de symboles de Perl) est parfois nécessaire, mais c'est très fastidieux et facile de faire des erreurs. Ce module masque tout cela derrière une API simple.

NOTE : La plupart des méthodes de cette classe requièrent une spécification de variable qui inclut un sigil. Si ce sigil n'est pas présent, il est supposé qu'il représente le slot d'entrée.

En raison des limites de l'API glob de Perl et de la lenteur de la manipulation des globs en Perl, ce module fournit deux implémentations - une en pur Perl et une utilisant XS. L'implémentation en pur Perl est préférable pour les utilisations courantes ; l'implémentation XS est fournie pour les cas où il n'est pas possible d'utiliser des modules XS. L'implémentation actuellement utilisée peut être définie via la variable d'environnement $ENV{PACKAGE_STASH_IMPLEMENTATION} ou $Package::Stash::IMPLEMENTATION avant de charger Package::Stash (la valeur de l'environnement ayant préséance), sinon il utilisera l'implémentation XS si possible, et en cas d'impossibilité, utilisera l'implémentation en pur Perl.

MÉTHODES

new $package_name

Crée un objet "Package::Stash" pour le paquet donné comme seul argument.

name

Renvoie le nom du paquet représenté par cet objet.

namespace

Renvoie la table de symboles elle-même.

add_symbol $variable $value %opts

Ajoute un nouveau symbole de paquet, pour le symbole donné comme $variable, et lui donne éventuellement une valeur initiale de $value. $variable doit être le nom de la variable incluant le sigil, donc

Package::Stash->new('Foo')->add_symbol('%foo')

créera %Foo::foo.

Les options valides (toutes optionnelles) sont "filename", "first_line_num" et "last_line_num".

Les valeurs $opts{filename}, $opts{first_line_num} et $opts{last_line_num} peuvent être utilisées pour indiquer où le symbole est considéré comme défini. Actuellement, ces valeurs ne sont utilisées que si le symbole est une fonction (symbole "&"), et seulement si "$^P & 0x10" est vrai, auquel cas la table %DB::sub est mise à jour pour enregistrer les valeurs de "filename", "first_line_num" et "last_line_num" de la fonction. Si ces valeurs ne sont pas fournies, leurs valeurs seront déduites (autant que possible) à partir des informations de "caller").

remove_glob $name

Supprime tous les symboles de paquet du nom donné, quel que soit leur sigil.

has_symbol $variable

Renvoie si le symbole donné existe dans le paquet (y compris son sigil).

get_symbol $variable

Renvoie la valeur du symbole donné dans le paquet (y compris son sigil).

get_or_add_symbol $variable

Comme "get_symbol", mais renvoie un hashref ou un arrayref vide si le symbole n'existe pas.

remove_symbol $variable

Supprime le symbole de paquet décrit par $variable (y compris son sigil) ; les autres symboles du même nom mais avec un sigil différent resteront intacts.

list_all_symbols $type_filter

Renvoie une liste de noms de symboles dans le paquet sans leurs sigils. Si un "type_filter" est passé, il est utilisé pour sélectionner les symboles d'un type donné, où les types valides sont les slots d'un type glob (SCALAR, CODE, HASH, etc.). Note : Si le paquet contenait des blocs "BEGIN", Perl laisserait un type glob vide dans le slot "BEGIN", il sera donc affiché si aucun filtre n'est utilisé (et de même pour "INIT", "END", etc).

get_all_symbols $type_filter

Renvoie un hashref, indexé par les noms des symboles du paquet. Si $type_filter est passé, le hash contiendra chaque symbole de ce type dans le paquet comme valeurs, sinon il contiendra les typoglob correspondants aux noms des symboles (essentiellement, une copie du stash).

Ceci est particulièrement utile pour les débogueurs et les profileurs qui utilisent %DB::sub pour déterminer où le code source d'une fonction peut être trouvé. Voir http://perldoc.perl.org/perldebguts.html#Debugger-Internals pour plus d'informations sur %DB::sub.

TRAVAIL AVEC DES VARIABLES

Il est important de noter que lors du travail avec des variables scalaires, le comportement par défaut est de copier les valeurs.

my $stash = Package::Stash->new('Some::Namespace');
my $variable = 1;
# $Some::Namespace::name est une copie de $variable
$stash->add_symbol('$name', $variable);
$variable++
# $Some::Namespace::name == 1, $variable == 2

Cela pourrait confondre les utilisateurs qui s'attendent à ce que cela fonctionne comme l'affectation de typoglob, qui crée simplement de nouvelles références à des variables existantes.

my $variable = 1;
{
    no strict 'refs';
    # affecte $Package::Stash::name = $variable
    *{'Package::Stash::name'} = \$variable;
}
$variable++ # affecte les deux noms

Si vous souhaitez ce comportement lors de l'utilisation de Package::Stash, passez simplement une référence à un scalaire à Package::Stash :

my $stash = Package::Stash->new('Some::Namespace');
my $variable = 1;
# $Some::Namespace::name est maintenant $variable
$stash->add_symbol('$name', \$variable);
$variable++
# $Some::Namespace::name == 2, $variable == 2

Ce serait ce que vous voudriez si vous travaillez avec des variables en lecture seule :

use Readonly;
Readonly my $value, 'hello';
$stash->add_symbol('$name', \$value); # référence
print $Some::Namespace::name; # hello
# Essayer de modifier le 'hello' en lecture seule échoue.
$Some::Namespace::name .= " world";
$stash->add_symbol('$name', $value); # copie
print $Some::Namespace::name; # hello
# Aucun problème, modification d'une copie, pas de l'original
$Some::Namespace::name .= " world";

BUGS / MISES EN GARDE

  • Avant Perl 5.10, les slots scalaires ne sont considérés comme existants que s'ils sont définis

    • Ceci est dû à une limitation de Perl lui-même. Voir « Making References » au point 7 de perlref.

  • Les variables GLOB et FORMAT ne sont pas accessibles via ce module
