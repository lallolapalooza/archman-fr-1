NOM

Path::Class::File - Objets représentant des fichiers

VERSION

version 0.37

SYNOPIS

use Path::Class;  # Exporte file() par défaut
my $file = file('foo', 'bar.txt');  # Objet Path::Class::File
my $file = Path::Class::File->new('foo', 'bar.txt'); # Identique
# Se stringifie en 'foo/bar.txt' sur Unix, 'foo\bar.txt' sur Windows, etc.
print "fichier: $file\n";
if ($file->is_absolute) { ... }
if ($file->is_relative) { ... }
my $v = $file->volume; # Peut être 'C:' sur Windows, chaîne vide
                       # sur Unix, 'Macintosh HD:' sur Mac OS
$file->cleanup; # Effectue un nettoyage logique du chemin
$file->resolve; # Effectue un nettoyage physique du chemin
my $dir = $file->dir;  # Un objet Path::Class::Dir
my $abs = $file->absolute; # Transformer en chemin absolu
my $rel = $file->relative; # Transformer en chemin relatif

DESCRIPTION

La classe "Path::Class::File" contient des fonctionnalités pour manipuler les noms de fichiers de manière multiplateforme.

MÉTHODES

$file = Path::Class::File->new( <dir1>, <dir2>, ..., <file> )
$file = file( <dir1>, <dir2>, ..., <file> )
Crée un nouvel objet "Path::Class::File" et le retourne. Les arguments spécifient le chemin du fichier. Tout volume peut également être spécifié comme premier argument, ou dans le premier argument. Vous pouvez utiliser une syntaxe neutre par rapport à la plateforme : 
my $file = file( 'foo', 'bar', 'baz.txt' );

ou une syntaxe native de la plateforme :

my $file = file( 'foo/bar/baz.txt' );

ou un mélange des deux :

my $file = file( 'foo/bar', 'baz.txt' );

Les trois exemples ci-dessus créent des chemins relatifs. Pour créer un chemin absolu, utilisez soit la syntaxe native de la plateforme pour cela :

my $file = file( '/var/tmp/foo.txt' );

soit utilisez une chaîne vide comme premier argument :

my $file = file( '', 'var', 'tmp', 'foo.txt' );

Si la seconde forme semble maladroite, c'est en partie intentionnel - les chemins comme "/var/tmp" ou "\Windows" ne sont pas des concepts multiplateformes en soi, donc ils ne devraient probablement pas apparaître dans votre code si vous essayez d'être multiplateforme. La première forme est parfaitement acceptable, car les chemins comme ceux-ci peuvent provenir de fichiers de configuration, d'entrées utilisateur, ou autre.

$file->stringify
Cette méthode est appelée en interne lorsqu'un objet "Path::Class::File" est utilisé dans un contexte de chaîne, donc les éléments suivants sont équivalents : 
$string = $file->stringify;
$string = "$file";
$file->volume
Retourne le volume (par ex. "C:" sous Windows, "Macintosh HD:" sous Mac OS, etc.) de l'objet, s'il existe. Sinon, retourne la chaîne vide.
$file->basename
Retourne le nom du fichier sous forme de chaîne, sans la partie répertoire (le cas échéant).
$file->components
Retourne une liste des composants du répertoire de ce fichier, suivie du nom de base.

Note : contrairement à "$dir->components", cette méthode n'accepte actuellement aucun argument pour sélectionner les éléments de la liste qui seront retournés. Elle pourrait le faire à l'avenir. Actuellement, elle lève une exception si de tels arguments sont présents.

$file->is_dir
Retourne une valeur booléenne indiquant si cet objet représente un répertoire. Sans surprise, les objets "Path::Class::File" retournent toujours faux, et les objets Path::Class::Dir retournent toujours vrai.
$file->is_absolute
Retourne vrai ou faux selon que le fichier fait référence à un spécificateur de chemin absolu (comme "/usr/local/foo.txt" ou "\Windows\Foo.txt").
$file->is_relative
Retourne vrai ou faux selon que le fichier fait référence à un spécificateur de chemin relatif (comme "lib/foo.txt" ou ".\Foo.txt").
$file->cleanup
Effectue un nettoyage logique du chemin du fichier. Par exemple : 
my $file = file('/foo//baz/./foo.txt')->cleanup;
# $file représente maintenant '/foo/baz/foo.txt';
$dir->resolve
Effectue un nettoyage physique du chemin du fichier. Par exemple : 
my $file = file('/foo/baz/../foo.txt')->resolve;
# $file représente maintenant '/foo/foo.txt', en supposant aucun lien symbolique

Cela consulte réellement le système de fichiers pour vérifier la validité du chemin.

$dir = $file->dir
Retourne un objet "Path::Class::Dir" représentant le répertoire contenant ce fichier.
$dir = $file->parent
Un synonyme de la méthode dir().
$abs = $file->absolute
Retourne un objet "Path::Class::File" représentant $file en tant que chemin absolu. Un argument optionnel, donné sous forme de chaîne ou d'objet Path::Class::Dir, spécifie le répertoire à utiliser comme base de la relativité - sinon le répertoire de travail courant sera utilisé.
$rel = $file->relative
Retourne un objet "Path::Class::File" représentant $file en tant que chemin relatif. Un argument optionnel, donné sous forme de chaîne ou d'objet "Path::Class::Dir", spécifie le répertoire à utiliser comme base de la relativité - sinon le répertoire de travail courant sera utilisé.
$foreign = $file->as_foreign($type)
Retourne un objet "Path::Class::File" représentant $file tel qu'il serait spécifié sur un système de type $type. Les types connus incluent "Unix", "Win32", "Mac", "VMS" et "OS2", c'est-à-dire tout ce pour quoi il existe une sous-classe de "File::Spec".

Tous les objets générés (sous-répertoires, fichiers, parents, etc.) conserveront également ce type.

$foreign = Path::Class::File->new_foreign($type, @args)
Retourne un objet "Path::Class::File" représentant un fichier tel qu'il serait spécifié sur un système de type $type. Les types connus incluent "Unix", "Win32", "Mac", "VMS" et "OS2", c'est-à-dire tout ce pour quoi il existe une sous-classe de "File::Spec".

Les arguments dans @args sont les mêmes que ceux qui seraient spécifiés dans new().

$fh = $file->open($mode, $permissions)
Transmet les arguments donnés, y compris $file, à "IO::File->new" (qui appelle à son tour "IO::File->open" et retourne le résultat sous forme d'objet IO::File. Si l'ouverture échoue, "undef" est retourné et $! est défini.
$fh = $file->openr()
Un raccourci pour 
$fh = $file->open('r') or croak "Impossible de lire $file: $!";
$fh = $file->openw()
Un raccourci pour 
$fh = $file->open('w') or croak "Impossible d'écrire dans $file: $!";
$fh = $file->opena()
Un raccourci pour 
$fh = $file->open('a') or croak "Impossible d'ajouter à $file: $!";
$file->touch
Définit l'heure de modification et d'accès du fichier donné à l'instant actuel, si le fichier existe. S'il n'existe pas, touch() le fera exister, et - OUI ! - définira son heure de modification et d'accès à l'instant actuel.

Path::Class::File(3pm) - Perl manual page

NAME

Path::Class::File - File objects

VERSION

0.37

SYNOPSIS

    use Path::Class::File;

    my $file = Path::Class::File->new('/path/to/file.txt');
    my $file = Path::Class::File->new('dir', 'subdir', 'file.txt');
    my $file = Path::Class::File->new( Path::Class::Dir->new('dir'), 'file.txt');

    print $file->slurp;
    $file->spew_lines(['line1', 'line2']);

    if ($file->exists) {
        $file->remove;
    }

DESCRIPTION

Path::Class::File is a subclass of Path::Class::Entity. It provides an object-oriented interface for manipulating files.

METHODS

$file->slurp()
Reads the entire contents of the file into a scalar context, or as a list of lines in a list context. If the file can't be read, this method will throw an exception.

If you want chomp() run on each line of the file, pass a true value for the "chomp" or "chomped" parameters:

my @lines = $file->slurp(chomp => 1);

You may also use the "iomode" parameter to pass in an IO mode to use when opening the file, usually IO layers (though anything accepted by the MODE argument of open() is accepted here). Just make sure it's a reading mode.

my @lines = $file->slurp(iomode => ':crlf');
my $lines = $file->slurp(iomode => '<:encoding(UTF-8)');

The default "iomode" is "r".

Lines can also be automatically split, mimicking the perl command-line option "-a" by using the "split" parameter. If this parameter is used, each line will be returned as an array ref.

my @lines = $file->slurp( chomp => 1, split => qr/\s*,\s*/ );

The "split" parameter can only be used in a list context.

$file->spew( $content );
The opposite of "slurp", this takes a list of strings and prints them to the file in write mode. If the file can't be written to, this method will throw an exception.

The content to be written can be either an array ref or a plain scalar. If the content is an array ref then each entry in the array will be written to the file.

You may use the "iomode" parameter to pass in an IO mode to use when opening the file, just like "slurp" supports.

$file->spew(iomode => '>:raw', $content);

The default "iomode" is "w".

$file->spew_lines( $content );
Just like "spew", but, if $content is a plain scalar, appends $/ to it, or, if $content is an array ref, appends $/ to each element of the array.

Can also take an "iomode" parameter like "spew". Again, the default "iomode" is "w".

$file->traverse(sub { ... }, @args)
Calls the given callback on $file. This doesn't do much on its own, but see the associated documentation in Path::Class::Dir.
$file->remove()
This method will remove the file in a way that works well on all platforms, and returns a boolean value indicating whether or not the file was successfully removed.

remove() is better than simply calling Perl's unlink() function, because on some platforms (notably VMS) you actually may need to call unlink() several times before all versions of the file are gone - the remove() method handles this process for you.

$st = $file->stat()
Invokes File::stat::stat() on this file and returns a File::stat object representing the result.
$st = $file->lstat()
Same as stat(), but if $file is a symbolic link, lstat() stats the link instead of the file the link points to.
$class = $file->dir_class()
Returns the class which should be used to create directory objects.

Generally overridden whenever this class is subclassed.

$copy = $file->copy_to( $dest );
Copies the $file to $dest. It returns a Path::Class::File object when successful, "undef" otherwise.
$moved = $file->move_to( $dest );
Moves the $file to $dest, and updates $file accordingly.

It returns $file is successful, "undef" otherwise.
