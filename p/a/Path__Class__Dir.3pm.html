Path::Class::Dir(3pm) Documentation Perl fournie par l'utilisateur Path::Class::Dir(3pm)

NOM

Path::Class::Dir - Objets représentant des répertoires

VERSION

version 0.37

SYNOPSIS

use Path::Class;  # Exporte dir() par défaut

my $dir = dir('foo', 'bar');       # Objet Path::Class::Dir
my $dir = Path::Class::Dir->new('foo', 'bar');  # Idem

# Se convertit en chaîne 'foo/bar' sur Unix, 'foo\bar' sur Windows, etc.
print "dir: $dir\n";

if ($dir->is_absolute) { ... }
if ($dir->is_relative) { ... }

my $v = $dir->volume; # Pourrait être 'C:' sous Windows, chaîne vide
                      # sur Unix, 'Macintosh HD:' sur Mac OS

$dir->cleanup; # Effectue un nettoyage logique du nom de chemin
$dir->resolve; # Effectue un nettoyage physique du nom de chemin

my $file = $dir->file('file.txt'); # Un fichier dans ce répertoire
my $subdir = $dir->subdir('george'); # Un sous-répertoire
my $parent = $dir->parent; # Le répertoire parent, 'foo'

my $abs = $dir->absolute; # Transformer en chemin absolu
my $rel = $abs->relative; # Transformer en chemin relatif
my $rel = $abs->relative('/foo'); # Relatif à /foo

print $dir->as_foreign('Mac');   # :foo:bar:
print $dir->as_foreign('Win32'); #  foo\bar
# Itérer avec les méthodes de IO::Dir :
my $handle = $dir->open;
while (my $file = $handle->read) {
  $file = $dir->file($file);  # Transformer en objet Path::Class::File
  ...
}

# Itérer avec les méthodes de Path::Class :
while (my $file = $dir->next) {
  # $file est un objet Path::Class::File ou Path::Class::Dir
  ...
}

DESCRIPTION

La classe "Path::Class::Dir" contient des fonctionnalités pour manipuler les noms de répertoires de manière multiplateforme.

MÉTHODES

$dir = Path::Class::Dir->new( <dir1>, <dir2>, ... )
$dir = dir( <dir1>, <dir2>, ... )
Crée et retourne un nouvel objet "Path::Class::Dir". Les arguments spécifient les noms de répertoires qui seront joints pour créer un objet répertoire unique. Un volume peut également être spécifié comme premier argument, ou dans le premier argument. Vous pouvez utiliser une syntaxe neutre vis-à-vis de la plateforme : 
my $dir = dir( 'foo', 'bar', 'baz' );

ou une syntaxe native à la plateforme :

my $dir = dir( 'foo/bar/baz' );

ou un mélange des deux :

my $dir = dir( 'foo/bar', 'baz' );

Les trois exemples ci-dessus créent des chemins relatifs. Pour créer un chemin absolu, utilisez soit la syntaxe native de la plateforme pour le faire :

my $dir = dir( '/var/tmp' );

soit utilisez une chaîne vide comme premier argument :

my $dir = dir( '', 'var', 'tmp' );

Si la deuxième forme semble maladroite, c'est un peu intentionnel - les chemins comme "/var/tmp" ou "\Windows" ne sont pas des concepts multiplateformes en premier lieu (de nombreuses plateformes non-Unix n'ont pas la notion d'un "répertoire racine"), donc ils ne devraient probablement pas apparaître dans votre code si vous essayez d'être multiplateforme. La première forme est parfaitement naturelle, car les chemins comme ceux-ci peuvent provenir de fichiers de configuration, de l'entrée utilisateur, ou autre.

Comme cas spécial, puisqu'il n'a pas d'autre signification utile et qu'il est pratique de le définir ainsi, "Path::Class::Dir->new()" (ou dir()) fait référence au répertoire courant ("File::Spec->curdir"). Pour obtenir le répertoire courant sous forme de chemin absolu, faites "dir()->absolute".

Enfin, comme autre cas spécial, dir(undef) retournera undef, car c'est généralement un accident de la part de l'appelant, et retourner le répertoire racine serait une mauvaise surprise qui ne demanderait qu'à causer des problèmes quelques lignes plus loin.

$dir->stringify
Cette méthode est appelée en interne lorsqu'un objet "Path::Class::Dir" est utilisé dans un contexte de chaîne, donc les éléments suivants sont équivalents : 
$string = $dir->stringify;
$string = "$dir";
$dir->volume
Retourne le volume (par ex. "C:" sous Windows, "Macintosh HD:" sur Mac OS, etc.) de l'objet répertoire, s'il y en a un. Sinon, retourne la chaîne vide.
$dir->basename
Retourne le dernier nom de répertoire du chemin sous forme de chaîne.
$dir->is_dir
Retourne une valeur booléenne indiquant si cet objet représente un répertoire. Sans surprise, les objets Path::Class::File retournent toujours faux, et les objets "Path::Class::Dir" retournent toujours vrai.
$dir->is_absolute
Retourne vrai ou faux selon que le répertoire fait référence à un spécificateur de chemin absolu (comme "/usr/local" ou "\Windows").
$dir->is_relative
Retourne vrai ou faux selon que le répertoire fait référence à un spécificateur de chemin relatif (comme "lib/foo" ou "./dir").
$dir->cleanup
Effectue un nettoyage logique du chemin de fichier. Par exemple : 
my $dir = dir('/foo//baz/./foo')->cleanup;
# $dir représente maintenant '/foo/baz/foo';
$dir->resolve
Effectue un nettoyage physique du chemin de fichier. Par exemple : 
my $dir = dir('/foo//baz/../foo')->resolve;
# $dir représente maintenant '/foo/foo', en supposant qu'il n'y a pas de liens symboliques

Ceci consulte réellement le système de fichiers pour vérifier la validité du chemin.

$file = $dir->file( <dir1>, <dir2>, ..., <file> )
Retourne un objet Path::Class::File représentant une entrée dans $dir ou l'un de ses sous-répertoires. Interne ment, cela appelle simplement "Path::Class::File->new( @_ )".
$subdir = $dir->subdir( <dir1>, <dir2>, ... )
Retourne un nouvel objet "Path::Class::Dir" représentant un sous-répertoire de $dir.
$parent = $dir->parent
Retourne le répertoire parent de $dir. Notez qu'il s'agit du parent *logique*, pas nécessairement du parent physique. Cela signifie vraiment que nous supprimons des éléments de la fin de la liste des répertoires jusqu'à ce que nous ne puissions plus en supprimer. Si le répertoire est relatif, nous commençons à utiliser les formes relatives des répertoires parents.

Le code suivant démontre le comportement sur les répertoires absolus et relatifs :

$dir = dir('/foo/bar');
for (1..6) {
  print "Absolu : $dir\n";
  $dir = $dir->parent;
}

$dir = dir('foo/bar');
for (1..6) {
  print "Relatif : $dir\n";
  $dir = $dir->parent;
}

@list = $dir->children
Retourne une liste d'objets Path::Class::File et/ou "Path::Class::Dir" répertoriés dans ce répertoire, ou dans un contexte scalaire, le nombre de tels objets. Il est évidemment nécessaire que $dir existe et soit lisible pour trouver ses enfants.

Notez que les enfants sont retournés comme sous-répertoires de $dir, c'est-à-dire que les enfants de foo seront foo/bar et foo/baz, pas bar et baz.

Normalement, children() n'inclura pas les entrées self et parent "." et ".." (ou leurs équivalents sur les systèmes non-Unix), car cela relève du genre « je suis mon propre grand-père ». Si vous souhaitez toutes les entrées du répertoire, y compris celles-ci, passez une valeur vraie pour le paramètre "all" :

@c = $dir->children(); # Juste les enfants
@c = $dir->children(all => 1); # Toutes les entrées

De plus, il existe un paramètre "no_hidden" qui exclura toutes les entrées normalement "cachées" - sur Unix, cela signifie exclure toutes les entrées commençant par un point (".") :

@c = $dir->children(no_hidden => 1); # Juste les entrées normalement visibles

r->absolute
Retourne un objet "Path::Class::Dir" représentant $dir comme un chemin absolu. Un argument optionnel, donné sous forme de chaîne de caractères ou d'objet "Path::Class::Dir", spécifie le répertoire à utiliser comme base de relativité - sinon le répertoire de travail actuel sera utilisé.
$rel = $dir->relative
Retourne un objet "Path::Class::Dir" représentant $dir comme un chemin relatif. Un argument optionnel, donné sous forme de chaîne de caractères ou d'objet "Path::Class::Dir", spécifie le répertoire à utiliser comme base de relativité - sinon le répertoire de travail actuel sera utilisé.
$booléen = $dir->subsumes($other)
Retourne vrai si cette spécification de répertoire englobe l'autre spécification, et faux sinon. Pensez à "englobe" comme "contient", mais nous ne regardons que les *spécifications*, pas si $dir contient réellement $other sur le système de fichiers.

L'argument $other peut être un objet "Path::Class::Dir", un objet Path::Class::File, ou une chaîne de caractères. Dans ce dernier cas, nous supposons qu'il s'agit d'un répertoire.

# Exemples:
dir('foo/bar' )->subsumes(dir('foo/bar/baz'))  # Vrai
dir('/foo/bar')->subsumes(dir('/foo/bar/baz')) # Vrai
dir('foo/..')->subsumes(dir('foo/../bar'))      # Vrai
dir('foo/bar' )->subsumes(dir('bar/baz'))      # Faux
dir('/foo/bar')->subsumes(dir('foo/bar'))      # Faux
dir('foo/..')->subsumes(dir('bar'))            # Faux! Utilisez C<contains> pour résoudre ".."
$booléen = $dir->contains($other)
Retourne vrai si ce répertoire contient réellement $other sur le système de fichiers. $other n'a pas besoin d'être un enfant direct de $dir, il doit juste être englobé après que les deux chemins aient été résolus.
$foreign = $dir->as_foreign($type)
Retourne un objet "Path::Class::Dir" représentant $dir tel qu'il serait spécifié sur un système de type $type. Les types connus incluent "Unix", "Win32", "Mac", "VMS", et "OS2", c'est-à-dire tout ce pour quoi il existe une sous-classe de "File::Spec".

Tous les objets générés (sous-répertoires, fichiers, parents, etc.) conserveront également ce type.

$foreign = Path::Class::Dir->new_foreign($type, @args)
Retourne un objet "Path::Class::Dir" représentant $dir tel qu'il serait spécifié sur un système de type $type. Les types connus incluent "Unix", "Win32", "Mac", "VMS", et "OS2", c'est-à-dire tout ce pour quoi il existe une sous-classe de "File::Spec".

Les arguments dans @args sont les mêmes que ceux qui seraient spécifiés dans new().

@list = $dir->dir_list([OFFSET, [LENGTH]])
Retourne la liste des chaînes de caractères représentant en interne cette structure de répertoire. Chaque membre successif de la liste est compris comme une entrée dans la liste de répertoire de son prédécesseur. Par contrat, "Path::Class->new( $dir->dir_list )" devrait être équivalent à $dir.

Les sémantiques de cette méthode sont similaires aux fonctions Perl "splice" ou "substr" ; elles retournent "LENGTH" éléments à partir de "OFFSET". Si "LENGTH" est omis, retourne tous les éléments à partir de "OFFSET" jusqu'à la fin de la liste. Si "LENGTH" est négatif, retourne les éléments de "OFFSET" jusqu'à la fin, à l'exception des "-LENGTH" derniers éléments. Si "OFFSET" est négatif, il compte à rebours depuis la fin de la liste. Si "OFFSET" et "LENGTH" sont tous deux omis, la liste entière est retournée.

Dans un contexte scalaire, dir_list() sans argument retourne le nombre d'entrées dans la liste de répertoire ; dir_list(OFFSET) retourne l'élément unique à cet offset ; "dir_list(OFFSET, LENGTH)" retourne le dernier élément qui aurait été retourné dans un contexte de liste.

$dir->components
Identique à dir_list(). Il existe car il y a une méthode analogue dir_list() dans la classe "Path::Class::File" qui retourne également la chaîne de nom de base, donc cette méthode permet à quelqu'un d'appeler components() sans se soucier de savoir si l'objet est un fichier ou un répertoire.
$fh = $dir->open()
Passe $dir à "IO::Dir->open" et retourne le résultat comme un objet IO::Dir. Si l'ouverture échoue, "undef" est retourné et $! est défini.
$dir->mkpath($verbose, $mode)
Passe tous les arguments, y compris $dir, à File::Path::mkpath() et retourne le résultat (une liste de tous les répertoires créés).
$dir->rmtree($verbose, $cautious)
Passe tous les arguments, y compris $dir, à File::Path::rmtree() et retourne le résultat (le nombre de fichiers supprimés avec succès).
$dir->remove()
Supprime le répertoire, qui doit être vide. Retourne une valeur booléenne indiquant si le répertoire a été supprimé avec succès ou non. Cette méthode est principalement fournie par souci de cohérence avec la méthode remove() de "Path::Class::File".
$dir->tempfile(...)
Une interface à la fonction tempfile() de File::Temp. Tout comme cette fonction, si vous l'appelez dans un contexte scalaire, la valeur de retour est le descripteur de fichier et le fichier est "unlink"é dès que possible (ce qui est immédiat sur les plateformes de type Unix). Si appelée dans un contexte de liste, les valeurs de retour sont le descripteur de fichier et le nom du fichier.

Le répertoire donné est passé comme paramètre "DIR".

Voici un exemple d'utilisation assez bonne qui ne permet pas les conditions de concurrence, ne laissera pas de fichiers temporaires désagréables sur votre système de fichiers, etc. :

my $fh = $dir->tempfile;
print $fh "Voici quelques données...\n";
seek($fh, 0, 0);
while (<$fh>) { faire quelque chose... }

Ou en combinaison avec un "fork" :

my $fh = $dir->tempfile;
print $fh "Voici encore plus de données...\n";
seek($fh, 0, 0);
if ($pid=fork()) {
  wait;
} else {
  quelquechose($_) while <$fh>;
}
$dir_ou_fichier = $dir->next()
Une manière pratique d'itérer sur le contenu d'un répertoire. La première fois que next() est appelée, elle ouvrira le répertoire et lira le premier élément, retournant le résultat comme un objet "Path::Class::Dir" ou Path::Class::File (selon, bien sûr, son type réel). Chaque appel subséquent à next() itérera simplement sur le contenu du répertoire, jusqu'à ce qu'il n'y ait plus d'éléments dans le répertoire, et alors la valeur indéfinie sera retournée. Par exemple, pour itérer sur tous les fichiers réguliers d'un répertoire : 
while (my $file = $dir->next) {
  next unless -f $file;
  my $fh = $file->open('r') or die "Impossible de lire $file: $!";
  ...
}

Si une erreur se produit lors de l'ouverture du répertoire (par exemple, il n'existe pas ou n'est pas lisible), next() lèvera une exception avec la valeur de $!.

$dir->traverse( sub { ... }, @args )
Appelle la fonction de rappel donnée pour la racine, en lui passant une fonction de continuation qui, lorsqu'elle est appelée, s'appellera récursivement sur chacun de ses enfants. La fonction de rappel doit avoir la forme : 
sub {
  my ($child, $cont, @args) = @_;
  # ...
}

Par exemple, pour calculer le nombre de fichiers dans un répertoire, vous pouvez faire ceci :

my $nfiles = $dir->traverse(sub {
  my ($child, $cont) = @_;
  return sum($cont->(), ($child->is_dir ? 0 : 1));
});

ou pour calculer la profondeur maximale d'un répertoire :

my $depth = $dir->traverse(sub {
  my ($child, $cont, $depth) = @_;
  return max($cont->($depth + 1), $depth);
}, 0);

Vous pouvez également choisir de ne pas appeler la fonction de rappel dans certaines situations :

$dir->traverse(sub {
  my ($child, $cont) = @_;
  return if -l $child; # ne pas suivre les liens symboliques
  # faire quelque chose avec $child
  return $cont->();
});
$dir->traverse_if( sub { ... }, sub { ... }, @args )
Traverse avec une fonction de rappel supplémentaire "faut-il visiter cet enfant ?". Particulièrement utile si l'arbre examiné contient des répertoires inaccessibles.

Exemple canonique :

$dir->traverse_if(
  sub {
     my ($child, $cont) = @_;
     # faire quelque chose avec $child
     return $cont->();
  },
  sub {
     my ($child) = @_;
     # Traiter uniquement les éléments lisibles
     return -r $child;
  });

La deuxième fonction de rappel reçoit un seul paramètre : l'enfant. Seuls les enfants pour lesquels elle retourne vrai seront traités par la première fonction de rappel.

Les paramètres restants sont interprétés comme dans traverse, en particulier "traverse_if(callback, sub { 1 }, @args" est équivalent à "traverse(callback, @args)".

$dir->recurse( callback => sub {...} )
Itère à travers ce répertoire et tous ses enfants, et tous les enfants de ses enfants, etc., en appelant la sous-routine "callback" pour chaque entrée. C'est très similaire à ce que fait le module File::Find, et bien sûr "File::Find" fonctionnera bien sur Path::Cla

NOM

Path::Class

VERSION

0.37-12

SYNTAXE

Utilisez le module Path::Class pour manipuler les chemins.

DESCRIPTION

Le module Path::Class fournit un ensemble de méthodes pour manipuler les chemins de manière structurée. Il prend en charge les opérations récursives, les fonctions de rappel et divers paramètres pour contrôler l'ordre de parcours.

METHODES

Le module Path::Class offre plusieurs méthodes pour manipuler les chemins. Ces méthodes permettent le parcours récursif, les fonctions de rappel et le contrôle de l'ordre de la récursion.
