Path::Tiny(3) Documentation contribuée de Perl Path::Tiny(3) 

$path = path("foo/bar");
$path = path("/tmp", "file.txt"); # liste
$path = path(".");                # cwd

Crée un objet "Path::Tiny". Peu importe si vous lui passez un chemin de fichier ou de répertoire. Il est encore tôt jusqu'à ce que les méthodes de répertoire ne soient appelées que sur des répertoires et les méthodes de fichier que sur des fichiers. Cette méthode est exportée automatiquement par défaut.

Le premier argument doit être défini et avoir une longueur non nulle, sinon une exception sera levée. Cela évite des erreurs subtiles et dangereuses dans du code comme "path( maybe_undef() )->remove_tree".

OBSOLÈTE: Si et seulement si le premier caractère du premier argument de "path" est un tilde ('~'), une substitution de tilde sera effectuée sur le premier segment du chemin. Un seul tilde sera remplacé par glob('~') et un tilde suivi d'un utilisateur sera remplacé par le résultat de glob('~username'). aucune autre méthode n'effectue de substitution de tilde sur ses arguments. Voir "Expansion de tilde (obsolète)" pour plus d'informations.

Sous Windows, si le chemin est un identifiant de lecteur sans composant de chemin ("C:" ou "D:"), il sera développé en chemin absolu du répertoire courant sur ce volume en utilisant Cwd::getdcwd().

Si elle est appelée avec un seul argument "Path::Tiny", l'original est retourné, sauf si l'original conserve une référence à un fichier ou répertoire temporaire, auquel cas une copie stringifiée est retournée.

$path = path("foo/bar");
$temp = Path::Tiny->tempfile;
$p2 = path($path); # similaire à $p2 = $path
$t2 = path($temp); # similaire à $t2 = path( "$temp" )

Cela optimise les copies sans propager de références inattendues si des copies sont effectuées par du code hors de votre contrôle.

API actuelle disponible depuis 0.017.

$path = Path::Tiny->new("foo/bar");

Ceci est juste comme "path", mais avec un surcoût d'appel de méthode. (Pourquoi le feriez-vous ?)

API actuelle disponible depuis 0.001.

$path = Path::Tiny->cwd; # path( Cwd::getcwd )
$path = cwd; # exportation optionnelle

Vous donne le chemin absolu du répertoire courant sous forme d'objet "Path::Tiny". C'est légèrement plus rapide que "path(".")->absolute".

"cwd" peut être exporté sur demande et utilisé comme fonction au lieu d'une méthode.

API actuelle disponible depuis 0.018.

$path = Path::Tiny->rootdir; # /
$path = rootdir;             # exportation optionnelle

Vous donne "File::Spec->rootdir" sous forme d'objet "Path::Tiny" si vous êtes trop paresseux pour utiliser "path("/").

"rootdir" peut être exporté sur demande et utilisé comme fonction au lieu d'une méthode.

API actuelle disponible depuis 0.018.

$temp = Path::Tiny->tempfile( @options );
$temp = Path::Tiny->tempdir( @options );
$temp = $dirpath->tempfile( @options );
$temp = $dirpath->tempdir( @options );
$temp = tempfile( @options ); # exportation optionnelle
$temp = tempdir( @options );  # exportation optionnelle

"tempfile" transmet les options à "File::Temp->new" et retourne un objet "Path::Tiny" avec le nom du fichier. L'option "TMPDIR" est activée par défaut, mais vous pouvez la remplacer en passant "TMPDIR => 0" avec les options. (Si vous utilisez une option "TEMPLATE" absolue, vous voudrez désactiver "TMPDIR".)

L'objet "File::Temp" est mis en cache. Lorsque l'objet "Path::Tiny" est détruit, l'objet "File::Temp" sera également détruit.

"File::Temp" exige que vous spécifiiez un modèle personnalisé sous différentes formes selon la méthode ou la fonction que vous utilisez, mais "Path::Tiny" vous permet d'ignorer cela et d'utiliser un modèle comme préfixe ou l'option "TEMPLATE".

$temp = Path::Tiny->tempfile( "customXXXXXXXX" );             # ok
$temp = Path::Tiny->tempfile( TEMPLATE => "customXXXXXXXX" ); # ok

L'objet "tempfile" est normalisé pour avoir un chemin absolu, même s'il est créé dans un répertoire relatif en utilisant "DIR". Si vous voulez qu'il ait le "realpath", passez une option de hachage comme ceci :

$real_temp = tempfile({realpath => 1}, @options);

"tempdir" est juste comme "tempfile", mais appelle "File::Temp->newdir" à la place.

Les deux "tempfile" et "tempdir" peuvent être exportés sur demande et utilisés comme fonctions au lieu de méthodes.

Les méthodes peuvent être appelées sur des instances représentant un répertoire. Dans ce cas, le répertoire est utilisé comme base pour créer le fichier/répertoire temporaire, en définissant l'option "DIR" sur File::Temp.

my $target_dir = path('/to/destination');
my $tempfile = $target_dir->tempfile('foobarXXXXXX');
$tempfile->spew('A lot of data...');  # non atomique
$tempfile->move($target_dir->child('foobar')); # devrait être atomique

Dans ce cas, toute valeur définie pour l'option "DIR" est ignorée.

Note : pour les fichiers temporaires, les descripteurs de fichiers de File::Temp sont fermés et non réutilisés. Ce n'est pas aussi sûr que d'utiliser des descripteurs de fichiers directement, mais c'est moins susceptible de provoquer des blocages ou des problèmes d'accès sur certaines plateformes. Considérez ce que "Path::Tiny" vous donne comme juste un nom de fichier temporaire qui sera nettoyé.

Note 2 : si vous ne voulez pas que ces fichiers soient nettoyés automatiquement lorsque l'objet est détruit, File::Temp nécessite des options différentes pour les répertoires et les fichiers. Utilisez "CLEANUP => 0" pour les répertoires et "UNLINK => 0" pour les fichiers.

Note 3 : ne perdez pas l'objet temporaire lors de l'appel d'une méthode au lieu de le stocker :

my $lost = tempdir()->child("foo"); # l'objet tempdir est nettoyé immédiatement

Note 4 : l'objet cache peut être accédé via la méthode "cached_temp". Conserver une référence ou modifier l'objet cache peut briser le comportement documenté et n'est pas pris en charge. Utilisez à vos propres risques.

API actuelle disponible depuis 0.119.

$abs = path("foo/bar")->absolute;
$abs = path("foo/bar")->absolute("/tmp");

Retourne un nouvel objet "Path::Tiny" avec un chemin absolu (ou lui-même s'il est déjà absolu). Si aucun argument n'est donné, le répertoire courant est utilisé comme base pour le chemin absolu. Si un argument est donné, il est converti en chemin absolu (s'il ne l'est pas déjà) et utilisé comme base pour le chemin absolu.

Cela ne résout pas les répertoires parents ("foo/../bar") sauf si "canonpath" dans File::Spec le ferait normalement sur votre plateforme. Si vous avez besoin de les résoudre, vous devez appeler la méthode plus coûteuse "realpath".

Sous Windows, un chemin absolu sans composant de volume sera ajouté en fonction du lecteur courant.

API actuelle disponible depuis 0.101.

path("foo.txt")->append(@data);
path("foo.txt")-"append(\@data);
path("foo.txt")->append({binmode => ":raw"}, @data);
path("foo.txt")->append_raw(@data);
path("foo.txt")->append_utf8(@data);

Ajoute des données à un fichier. Le fichier est verrouillé avec "flock" avant d'écrire et fermé après. Une référence de hachage optionnelle peut être utilisée pour passer des options. Les options valides sont :

L'option "truncate" est un mode pour remplacer le contenu d'un fichier au lieu d'écrire dans un fichier temporaire puis de remplacer l'original (s'il existe).

"append_raw" est comme "append" avec un "binmode" de ":unix" pour une écriture rapide, sans tampon et en format brut.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

"append_utf8" est similaire à "append" avec un "binmode" non tamponné :unix:encoding(UTF-8) (ou ":unix:utf8_strict" avec PerlIO::utf8_strict). Si Unicode::UTF8 0.58+ est installé, une écriture brute non tamponnée sera effectuée sur les données encodées avec "Unicode::UTF8".

API actuelle disponible depuis 0.060.

$path = path("foo.txt")->assert( sub { $_->exists } );

Retourne l'invocant après avoir asserté qu'une référence de code fournie retourne vrai. Lorsque la référence de code d'assertion est exécutée, l'objet invocant sera dans la variable $_. Si elle retourne faux, une exception sera levée. La référence de code d'assertion peut également lever sa propre exception.

Si aucune assertion n'est fournie, l'invocant est retourné sans erreur.

$name = path("foo.txt")->basename(qr/.txt/);  # foo

Retourne la partie fichier ou la partie dernier répertoire d'un chemin.

Étant donné une liste de suffixes sous forme de chaînes ou d'expressions régulières, ceux qui correspondent à la fin de la partie fichier ou dernier répertoire seront supprimés avant que le résultat ne soit retourné.

Retourne une chaîne avec le format canonique du nom de chemin pour la plateforme. En particulier, cela signifie que les séparateurs de répertoire seront "\" sur Windows.

API actuelle disponible depuis 0.001.

Retourne l'objet mis en cache "File::Temp" ou "File::Temp::Dir" si l'objet "Path::Tiny" a été créé avec ou . S'il n'y a pas d'objet correspondant, cette méthode lève une exception.

API actuelle disponible depuis 0.101.

$file = path("/tmp")->child("foo.txt"); # "/tmp/foo.txt"
$file = path("/tmp")->child(@parts);

Retourne un nouvel objet "Path::Tiny" relatif à l'original. Fonctionne comme "catfile" ou "catdir" de File::Spec, mais sans se soucier des fichiers ou des répertoires.

ATTENTION : comme l'argument peut contenir ou référencer des liens symboliques, il n'y a aucune garantie que le nouveau chemin référence un descendant réel de l'original. Si cela est important pour vous, transformez le parent et l'enfant avec et vérifiez-les avec .

API actuelle disponible depuis 0.001.

@paths = path("/tmp")->children;
@paths = path("/tmp")->children( qr/\.txt\z/ );

Retourne une liste d'objets "Path::Tiny" pour tous les fichiers et répertoires contenus dans un répertoire. Exclut et automatiquement.

Si un argument optionnel "qr//" est fourni, seuls les objets dont le nom d'enfant correspond à l'expression régulière donnée sont retournés. Seul le nom de base est utilisé pour la correspondance :

@paths = path("/tmp")->children( qr/^foo/ );
# correspond aux enfants comme le glob foo*

API actuelle disponible depuis 0.028.

path("foo.txt")->chmod(0777);
path("foo.txt")->chmod("0755");
path("foo.txt")->chmod("go-w");
path("foo.txt")->chmod("a=r,u+wx");

Définit les permissions de fichier ou de répertoire. L'argument peut être un mode numérique, une chaîne octale commençant par un ou un sous-ensemble limité du mode symbolique utilisé par /bin/chmod.

Le mode symbolique doit être une liste de clauses de mode délimitées par des virgules. Les clauses doivent correspondre à "qr/\A([augo]+)([=+-])([rwx]+)\z/", ce qui définit les paramètres "qui", "op" et "perms" pour chaque clause. Contrairement à /bin/chmod, les trois paramètres sont requis pour chaque clause, plusieurs ops ne sont pas autorisés et les permissions ne sont pas supportées. (Voir File::chmod pour des besoins plus complexes.)

API actuelle disponible depuis 0.053.

path("/tmp/foo.txt")->copy("/tmp/bar.txt");

Copie le chemin actuel vers la destination donnée en utilisant la fonction "copy" de File::Copy. En cas de succès, retourne l'objet "Path::Tiny" du fichier nouvellement copié.

API actuelle disponible depuis 0.070.

$obj = path("/tmp/foo.txt")->digest;        # SHA-256
$obj = path("/tmp/foo.txt")->digest("MD5"); # sélectionné par l'utilisateur
$obj = path("/tmp/foo.txt")->digest( { chunk_size => 1e6 }, "MD5" );

Retourne un digest hexadécimal pour un fichier. Un hachage optionnel de configurations peut être donné. La seule configuration est "chunk_size". Si "chunk_size" est donné, ce nombre d'octets sera lu à la fois. Sinon, le fichier entier sera chargé en mémoire pour calculer le digest.

Tous les arguments suivants sont passés au constructeur de Digest pour sélectionner un algorithme. Si aucun argument n'est donné, la valeur par défaut est SHA-256.

API actuelle disponible depuis 0.056.

$name = path("/tmp/foo.txt")->dirname; # "/tmp/"

Retourne la partie répertoire que vous obtiendriez en appelant "File::Spec->splitpath( $path->stringify )" ou pour un chemin sans partie de répertoire parent. Parce que File::Spec est incohérent, le résultat peut ou peut ne pas avoir une barre oblique finale. Pour cette raison, cette méthode est **dépréciée**.

Une approche meilleure et plus cohérente est probablement parent->stringify", qui n'aura pas de barre oblique finale sauf pour un répertoire racine.

Déprécié en 0.056.

path("foo.txt")->edit( \&callback, $options );
path("foo.txt")->edit_utf8( \&callback );
path("foo.txt")->edit_raw( \&callback );

Ce sont des méthodes pratiques qui permettent "d'éditer" un fichier à l'aide d'un seul argument de rappel. Elles chargent le fichier en utilisant "slurp", placent le contenu dans une variable $_ localisée, appellent la fonction de rappel (sans arguments), puis écrivent $_ (probablement muté) dans le fichier avec "spew".

Un hachage optionnel peut être utilisé pour passer des configurations. La seule configuration est "binmode", qui est passé à "slurp" et "spew".

"edit_utf8" et "edit_raw" agissent comme leurs méthodes "slurp_*" et "spew_*" respectives.

API actuelle disponible depuis 0.077.

path("foo.txt")->edit_lines( \&callback, $options );
path("foo.txt")->edit_lines_utf8( \&callback );
path("foo.txt")->edit_lines_raw( \&callback );

Ce sont des méthodes pratiques qui permettent "d'éditer" les lignes d'un fichier à l'aide d'un seul argument de rappel. Elles itèrent sur le fichier : pour chaque ligne, la ligne est placée dans une variable $_ localisée, la fonction de rappel est exécutée (sans arguments) puis $_ est écrite dans un fichier temporaire. Lorsque l'itération est terminée, le fichier temporaire est renommé atomiquement par-dessus l'original.

Un hachage optionnel peut être utilisé pour passer des configurations. La seule configuration est "binmode", qui est passé à la méthode qui ouvre les descripteurs pour la lecture et l'écriture.

"edit_lines_raw" est similaire à "edit_lines" avec un "binmode" tamponné de .

"edit_lines_utf8" est similaire à "edit_lines" avec un "binmode" tamponné ":raw:utf8_strict" avec PerlIO::utf8_strict).

API actuelle disponible depuis 0.077.

if ( path("/tmp")->exists ) { ... }     # -e
if ( path("/tmp")->is_dir ) { ... }     # -d
if ( path("/tmp")->is_file ) { ... }    # -e && ! -d

Implémente des opérations de test de fichier, cela signifie que le fichier ou le répertoire doit réellement exister sur le système de fichiers. Jusqu'alors, ce n'est qu'un chemin.

Note : "is_file" n'est pas car n'est pas l'opposé de . signifie "fichier ordinaire", excluant les liens symboliques, les périphériques, etc., qui peuvent souvent être lus comme des fichiers.

Utilisez à la place si vous voulez vraiment vérifier un fichier ordinaire.

API actuelle disponible depuis 0.053.

$fh = path("/tmp/foo.txt")->filehandle($mode, $binmode);
$fh = path("/tmp/foo.txt")->filehandle({ locked => 1 }, $mode, $binmode);
$fh = path("/tmp/foo.txt")->filehandle({ exclusive => 1  }, $mode, $binmode);

Retourne un descripteur de fichier ouvert. L'argument $mode doit être une chaîne de mode lecture/écriture de style Perl ("<" ,">", ">>", etc.). Si un $binmode est donné, il est défini lors de l'appel "open".

Un hachage optionnel peut être utilisé pour passer des configurations.

L'option "locked" contrôle le verrouillage de fichier ; si elle est vraie, les descripteurs ouverts en écriture, ajout ou lecture/écriture sont verrouillés avec ; sinon, ils sont verrouillés avec . Lors de l'utilisation de , les modes " ou " déverrouilleront

lay truncation until after the lock is acquired.

L'option "exclusive" provoque l'échec de l'appel open() si le fichier existe déjà. Ceci correspond à l'indicateur O_EXCL de sysopen / open(2). "exclusive" implique "locked" et le définira pour vous si vous l'oubliez.

Voir "openr", "openw", "openrw" et "opena" pour le sucre syntaxique.

API actuelle disponible depuis 0.066.

if ( path("foo.txt")->has_same_bytes("bar.txt") ) {
   # ...
}

Cette méthode renvoie vrai si l'invocant et l'argument peuvent être ouverts comme des descripteurs de fichiers et que les descripteurs contiennent les mêmes octets. Elle renvoie faux si leurs contenus diffèrent. Si l'un ou l'autre ne peut pas être ouvert comme un fichier (par exemple, un répertoire ou un fichier inexistant), la méthode lève une exception. Si les deux peuvent être ouverts et ont le même "realpath", la méthode renvoie vrai sans scanner aucune donnée.

Booléen indiquant si le chemin est le répertoire racine du volume. C'est-à-dire que le "dirname" est "q[/]" et le "basename" est "q[]".

API actuelle disponible depuis 0.038.

$iter = path("/tmp")->iterator( \%options );

Renvoie une référence de code qui parcourt un répertoire de manière paresseuse. Chaque invocation renvoie un objet "Path::Tiny" ou `undef` lorsque l'itérateur est épuisé.

$iter = path("/tmp")->iterator;
while ( $path = $iter->() ) {
    ...
}

Les entrées de répertoire courant et parent ("." et "..") ne seront pas incluses.

Si l'option "recurse" est vraie, l'itérateur parcourra le répertoire récursivement, en largeur d'abord. Si l'option "follow_symlinks" est également vraie, les liens de répertoire seront suivis récursivement. Il n'y a aucune protection contre les boucles lors du suivi des liens. Si un répertoire n'est pas lisible, il ne sera pas suivi.

La valeur par défaut est la même que :

$iter = path("/tmp")->iterator( {
    recurse         => 0,
    follow_symlinks => 0,
} );

Pour un itérateur récursif plus puissant avec évitement de boucles intégré, voir Path::Iterator::Rule.

Voir aussi "visit".

API actuelle disponible depuis 0.016.

@contents = path("/tmp/foo.txt")->lines;
@contents = path("/tmp/foo.txt")->lines(\%options);
@contents = path("/tmp/foo.txt")->lines_raw;
@contents = path("/tmp/foo.txt")->lines_utf8;
@contents = path("/tmp/foo.txt")->lines( { chomp => 1, count => 4 } );

Renvoie une liste de lignes d'un fichier. Prend éventuellement une référence de hash d'options. Les options valides sont "binmode", "count" et "chomp".

Si "binmode" est fourni, il sera défini sur le descripteur avant la lecture.

Si un "count" positif est fourni, ce nombre de lignes sera renvoyé à partir du début du fichier. Si un "count" négatif est fourni, le fichier entier sera lu, mais seulement abs(count) sera conservé et renvoyé. Si abs(count) dépasse le nombre de lignes dans le fichier, toutes les lignes seront renvoyées.

Si "chomp" est défini, toute séquence de caractères de fin de ligne ("CR", "CRLF" ou "LF") sera supprimée des lignes renvoyées.

Parce que le retour est une liste, "lines" en contexte scalaire renverra le nombre de lignes (et ignorera les données).

$number_of_lines = path("/tmp/foo.txt")->lines;

"lines_raw" est comme "lines" avec un "binmode" de ":raw". Nous utilisons ":raw" au lieu de ":unix" pour que la mise en tampon PerlIO puisse gérer la lecture par ligne.

"lines_utf8" est comme "lines" avec un "binmode" de :raw:encoding(UTF-8) (ou ":raw:utf8_strict" avec PerlIO::utf8_strict). Si Unicode::UTF8 0.58+ est installé, une lecture brute, non mise en tampon de UTF-8 sera effectuée, puis les lignes seront séparées. C'est en fait plus rapide que de s'appuyer sur les couches IO, bien qu'un peu gourmand en mémoire. Si l'utilisation de la mémoire est une préoccupation, envisagez "openr_utf8" et l'itération directe sur le descripteur.

Voir aussi "slurp" si vous voulez charger un fichier en tant que morceau entier.

API actuelle disponible depuis 0.065.

path("foo/bar/baz")->mkdir;
path("foo/bar/baz")->mkdir( \%options );

Comme appeler "make_path" de File::Path. Une référence de hash optionnelle est passée à "make_path". Les erreurs seront interceptées et une exception sera levée. Renvoie l'objet chemin pour faciliter le chaînage.

NOTE : contrairement à la fonction intégrée "mkdir" de Perl, cela créera des chemins intermédiaires similaires à la commande Unix "mkdir -p". Cela ne générera pas d'erreur si appliqué à un répertoire existant.

Passer un argument défini *autre* qu'une référence de hash est une erreur, et une exception sera levée.

API actuelle disponible depuis 0.125.

Comme appeler "mkdir", mais renvoie la liste des répertoires créés ou une liste vide si les répertoires existent déjà, tout comme "make_path".

Passer un argument défini *autre* qu'une référence de hash est une erreur, et une exception sera levée.

Obsolète en 0.125.

path("foo.txt")->move("bar.txt");

Déplace le chemin courant vers la destination donnée en utilisant la fonction "move" de File::Copy. En cas de succès, renvoie l'objet "Path::Tiny" du fichier nouvellement déplacé.

Si la destination existe déjà et est un répertoire, et que la source n'est pas un répertoire, alors le fichier source sera renommé dans le répertoire spécifié par la destination.

Si possible, move() renommera simplement le fichier. Sinon, il copiera le fichier vers le nouvel emplacement et supprimera l'original. Si une erreur se produit pendant ce processus de copie et de suppression, vous pourriez vous retrouver avec une copie (potentiellement partielle) du fichier sous le nom de destination.

API actuelle disponible depuis 0.124. Les versions précédentes utilisaient la fonction de renommage intégrée (et moins robuste) de Perl et ne renvoyaient pas d'objet.

$fh = path("foo.txt")->openr($binmode);  # lecture
$fh = path("foo.txt")->openr_raw;
$fh = path("foo.txt")->openr_utf8;
$fh = path("foo.txt")->openw($binmode);  # écriture
$fh = path("foo.txt")->openw_raw;
$fh = path("foo.txt")->openw_utf8;
$fh = path("foo.txt")->opena($binmode);  # ajout
$fh = path("foo.txt")->opena_raw;
$fh = path("foo.txt")->opena_utf8;
$fh = path("foo.txt")->openrw($binmode); # lecture/écriture
$fh = path("foo.txt")->openrw_raw;
$fh = path("foo.txt")->openrw_utf8;

Renvoie un descripteur de fichier ouvert dans le mode spécifié. Les méthodes de style "openr" prennent un seul argument "binmode". Toutes les méthodes "open*" ont des équivalents "open*_raw" et "open*_utf8" qui utilisent des couches d'E/S mises en tampon ":raw" et :raw:encoding(UTF-8) (ou ":raw:utf8_strict" avec PerlIO::utf8_strict).

Une référence de hash optionnelle peut être utilisée pour passer des options. La seule option est "locked". Si vraie, les descripteurs ouverts pour l'écriture, l'ajout ou la lecture-écriture sont verrouillés avec "LOCK_EX" ; sinon, ils sont verrouillés avec "LOCK_SH".

$fh = path("foo.txt")->openrw_utf8( { locked => 1 } );

Voir "filehandle" pour plus d'informations sur le verrouillage.

API actuelle disponible depuis 0.011.

$parent = path("foo/bar/baz")->parent; # foo/bar

SYNOPSIS

use Path::Tiny;
# Création d'objets Path::Tiny
my $dir = path("/tmp");
my $foo = path("foo.txt");
my $subdir = $dir->child("foo");
my $bar = $subdir->child("bar.txt");
# Stringifie comme chemin propre
my $file = path("./foo.txt");
print $file; # "foo.txt"
# Lecture de fichiers
my $guts = $file->slurp;
   $guts = $file->slurp_utf8;
my @lines = $file->lines;
   @lines = $file->lines_utf8;
my ($head) = $file->lines( {count => 1} );
my ($tail) = $file->lines( {count => -1} );
# Écriture de fichiers
$bar->spew( @data );
$bar->spew_utf8( @data );
# Lecture de répertoires
for ( $dir->children ) { ... }
my $iter = $dir->iterator;
while ( my $next = $iter->() ) { ... }

DESCRIPTION

Ce module fournit un petit utilitaire rapide pour travailler avec des chemins de fichiers. Il est plus convivial que File::Spec et offre un accès facile aux fonctions de plusieurs modules de manipulation de fichiers de base. Il vise à être plus petit et plus rapide que de nombreuses alternatives sur CPAN, tout en aidant les utilisateurs à faire beaucoup de choses courantes de manière cohérente et avec moins d'erreurs.

Path::Tiny n'essaie pas de fonctionner pour quoi que ce soit d'autre que les plateformes Unix-like et Win32. Même ainsi, il pourrait se casser si vous essayez quelque chose de particulièrement obscur ou tordu. (Attention ! Que signifie "///../../..//./././a//b/.././c/././" ?)

Tous les chemins sont forcés d'avoir des barres obliques de style Unix. La stringification de l'objet vous renvoie le chemin (après quelques ajustements).

Les méthodes d'entrée/sortie de fichier "flock" sont gérées avant la lecture ou l'écriture, selon le cas (si elle est prise en charge par la plateforme et/ou le système de fichiers).

Les méthodes *_utf8 (comme "slurp_utf8", "lines_utf8", etc.) fonctionnent en mode brut. Sous Windows, cela signifie qu'elles n'auront pas de traduction CRLF du calque IO ":crlf". L'installation de Unicode::UTF8 0.58 ou une version ultérieure accélérera les cas *_utf8 et est fortement recommandée. Alternativement, l'installation de PerlIO::utf8_strict 0.003 ou une version ultérieure sera utilisée à la place de la valeur par défaut ":encoding(UTF-8)".

Ce module repose fortement sur les calques PerlIO pour un fonctionnement correct et nécessite donc Perl 5.008001 ou une version ultérieure.

AVERTISSEMENTS

Sous-classe non prise en charge

Pour des raisons de vitesse, cette classe est implémentée comme un objet basé sur un tableau et utilise de nombreux appels de fonctions internes directs. Vous ne pouvez pas sous-claser et vous attendre à ce que les choses fonctionnent correctement.

Expansion du tilde (obsolète)

L'expansion du tilde était une bonne idée, mais elle ne peut pas être appliquée de manière cohérente dans toute l'API. Elle était une source d'erreurs et de confusion pour les utilisateurs. Par conséquent, elle a été désactivée et son utilisation doit être évitée. Les limitations du comportement existant et ancien persistent.

L'expansion du tilde ne se produira que si le premier argument de "path" commence par un tilde. Aucune autre méthode n'effectue d'expansion de tilde sur ses arguments. Si vous souhaitez une expansion de tilde sur les arguments, vous devez explicitement les encapsuler dans un appel à "path".

path( "~/foo.txt" )->copy( path("~/bar.txt") );

Si vous avez besoin d'un tilde littéral en entrée, utilisez path("./~whatever") pour que l'argument de "path" ne commence pas par un tilde, mais que le chemin résolve vers le répertoire actuel.

Le comportement de l'expansion du tilde avec un utilisateur inexistant dépend du résultat de "glob" sur le système.

Verrouillage de fichier

Si le verrouillage n'est pas pris en charge sur une plateforme, il ne sera pas utilisé même s'il est demandé.

Dans les situations où une plateforme prend normalement en charge le verrouillage, mais que le verrouillage échoue en raison d'une limitation du système de fichiers, Path::Tiny a quelques heuristiques pour le détecter et émettra un avertissement une fois, puis continuera en mode non sécurisé. Si vous souhaitez que cet échec soit fatal, vous pouvez fataliser la catégorie d'avertissement "flock" :

use warnings FATAL => 'flock';

Voir plus d'avertissements ci-dessous.

NFS et BSD

Sur BSD, l'implémentation de flock de Perl ne fonctionne pas pour verrouiller les fichiers sur un système de fichiers NFS. Si détectée, cette situation émettra un avertissement une fois, comme décrit ci-dessus.

Lustre

Le système de fichiers Lustre ne prend pas en charge le verrouillage. Si détecté, cette situation émettra un avertissement une fois, comme décrit ci-dessus.

AIX et verrouillage

AIX nécessite un handle d'écriture pour le verrouillage. Par conséquent, les appels qui ouvrent normalement un handle de lecture et obtiennent un verrou partagé ouvrent un handle de lecture-écriture et obtiennent un verrou exclusif. Si l'utilisateur n'a pas la permission d'écrire, aucun verrou ne sera utilisé.

utf8 vs UTF-8

Toutes les méthodes *_utf8 utilisent par défaut ":encoding(UTF-8)" - soit ":unix:encoding(UTF-8)" (non tamponné, pour les opérations sur fichier complet) soit ":raw:encoding(UTF-8)" (tamponné, pour les opérations linéaires). Ceux-ci sont stricts selon le schéma Unicode et évitent les caractères illégaux ou les séquences UTF-8.

Cependant, ":encoding(UTF-8)" est très, très lent. Si vous installez Unicode::UTF8 0.58 ou une version ultérieure, ce module sera utilisé par certaines méthodes *_utf8 pour coder ou décoder les données après une opération d'E/S binaire, ce qui est beaucoup plus rapide. Alternativement, si vous installez PerlIO::utf8_strict 0.003 ou une version ultérieure, il sera utilisé à la place de ":encoding(UTF-8)" et est également très rapide.

Si vous avez besoin de vitesse et que vous pouvez accepter le risque de sécurité, "slurp({binmode => ":unix:utf8"})" sera plus rapide que ":unix:encoding(UTF-8)" (mais pas aussi rapide que "Unicode::UTF8").

Remarque : Les méthodes *_utf8 lisent en mode brut. Il n'y a pas de traduction CRLF sous Windows. Si vous avez besoin d'une traduction CRLF, utilisez les méthodes d'E/S régulières avec un binmode approprié :

$path->spew_utf8($data);                            # brut
$path->spew({binmode => ":encoding(UTF-8)"}, $data; # LF -> CRLF

Calques IO par défaut et le pragma open

Si vous avez Perl 5.10 ou une version ultérieure, les méthodes d'E/S ("slurp", "spew", etc.) et les méthodes d'ouverture de haut niveau ("filehandle", "openr", "openw", etc.) respectent les codages par défaut définis par le paramètre ou les configurations d'ouverture lexicales de l'appelant. Pour UTF-8, c'est presque certainement plus lent que d'utiliser les méthodes dédiées "_utf8" si vous avez Unicode::UTF8 ou PerlIP::utf8_strict.
