Les fonctions ci-dessous peuvent être utilisées pour parser des Longident en toute sécurité.

val longident : Lexing.lexbuf -> Longident.t

La fonction longident est garantie d'analyser toutes les sous-classes de Longident.t utilisées en OCaml : valeurs, constructeurs, chemins de modules simples ou étendus, et types ou signatures de modules.

Cependant, cette fonction accepte des entrées qui ne sont pas acceptées par le compilateur, car elles combinent des applications de foncteurs et des opérateurs infixes. Dans la syntaxe OCaml valide, seuls les identifiants de niveau valeur peuvent se terminer par des opérateurs infixes Foo.( + ). De plus, dans les identifiants de niveau valeur, le chemin du module Foo doit être simple ( M.N plutôt que F(X)) : les applications de foncteurs ne peuvent apparaître que dans les identifiants de niveau type. Par conséquent, un chemin tel que F(X).( + ) n'est pas un identifiant OCaml valide ; mais il est accepté par cette fonction.

Les fonctions suivantes sont spécialisées pour une sous-classe de Longident.t

val val_ident : Lexing.lexbuf -> Longident.t

Cette fonction analyse un chemin syntaxiquement valide pour une valeur. Par exemple, x , M.x et (+.) sont valides. Inversement, M.A , F(X).x et true sont rejetés.

Les Longident pour les valeurs OCaml ne peuvent pas contenir d'application de foncteur. Le dernier composant du Longident.t n'est pas capitalisé, mais peut être un opérateur A.Path.To.(.%.%.(;..)<-)

val constr_ident : Lexing.lexbuf -> Longident.t

Cette fonction analyse un chemin syntaxiquement valide pour un constructeur de variante. Par exemple, A , M.A et M.(::) sont valides, mais M.a et F(X).A sont tous deux rejetés.

Les Longident pour les constructeurs de variantes OCaml ne peuvent pas contenir d'application de foncteur. Le dernier composant du Longident.t est capitalisé, ou il peut s'agir de l'un des constructeurs spéciaux : true , false , () , [] , (::). Parmi ces constructeurs spéciaux, seul (::) peut être préfixé par un chemin de module ( A.B.C.(::) ).

val simple_module_path : Lexing.lexbuf -> Longident.t

Cette fonction analyse un chemin syntaxiquement valide pour un module. Par exemple, A et M.A sont valides, mais M.a et F(X).A sont tous deux rejetés.

Les Longident pour les modules OCaml ne peuvent pas contenir d'application de foncteur. Le dernier composant du Longident.t est capitalisé.

val extended_module_path : Lexing.lexbuf -> Longident.t

Cette fonction analyse un chemin syntaxiquement valide pour un module étendu. Par exemple, A.B et F(A).B sont valides. Inversement, (.%()) ou [] sont tous deux rejetés.

Le dernier composant du Longident.t est capitalisé.

val type_ident : Lexing.lexbuf -> Longident.t

Cette fonction analyse un chemin syntaxiquement valide pour un type ou une signature de module. Par exemple, A , t , M.t et F(X).t sont valides. Inversement, (.%()) ou [] sont tous deux rejetés.

Dans les chemins pour les types et les signatures de modules, seuls les opérateurs et les constructeurs spéciaux sont rejetés.
