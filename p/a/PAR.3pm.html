NAME

PAR - Toolkit d'archives Perl

SYNOPSIS

(Si vous souhaitez créer un exécutable autonome contenant tous les modules, scripts et fichiers de données, consultez l'utilitaire pp. pp faisait partie de la distribution PAR, mais il est maintenant distribué séparément avec la distribution PAR::Packer.)

Les exemples suivants supposent un fichier foo.par au format ZIP.

Pour utiliser Hello.pm depuis ./foo.par :

% perl -MPAR=./foo.par -MHello
% perl -MPAR=./foo -MHello          # le .par est facultatif

Idem, mais rechercher foo.par dans @INC :

% perl -MPAR -Ifoo.par -MHello
% perl -MPAR -Ifoo -MHello          # idem

Les chemins dans un fichier PAR sont recherchés comme suit :

/lib/
/arch/
/i386-freebsd/              # c'est-à-dire $Config{archname}
/5.8.0/                     # c'est-à-dire $Config{version}
/5.8.0/i386-freebsd/        # les deux ci-dessus
/

Les fichiers dans un fichier PAR peuvent aussi contenir (récursivement) d'autres fichiers PAR. Tous les fichiers sous les chemins suivants sont considérés comme des fichiers PAR et recherchés comme tels :

/par/i386-freebsd/          # c'est-à-dire $Config{archname}
/par/5.8.0/                 # c'est-à-dire $Config{version}
/par/5.8.0/i386-freebsd/    # les deux ci-dessus
/par/

Exécuter script/test.pl ou test.pl depuis foo.par :

% perl -MPAR foo.par test.pl        # seulement si $0 se termine par .par

Cependant, si le fichier .par contient soit script/main.pl, soit main.pl, ce dernier sera utilisé :

% perl -MPAR foo.par test.pl        # exécute main.pl ; @ARGV est 'test.pl'

Utilisation dans un programme :

use PAR 'foo.par';
use Hello; # lit dans foo.par
# PAR::read_file() renvoie un fichier dans n'importe quel PAR chargé
my $conf = PAR::read_file('data/MyConfig.yaml');
# PAR::par_handle() renvoie un objet Archive::Zip
my $zip = PAR::par_handle('foo.par')
my $src = $zip->memberNamed('lib/Hello.pm')->contents;

Vous pouvez également utiliser des caractères génériques :

use PAR '/home/foo/*.par';  # charge tous les fichiers PAR dans ce répertoire

Depuis la version 0.950, vous pouvez utiliser une syntaxe différente pour charger les fichiers .par :

use PAR { file => 'foo.par' }, { file => 'otherfile.par' };

Pourquoi ? Parce que vous pouvez aussi faire ceci :

use PAR { file => 'foo.par, fallback => 1 };
use Foo::Bar;

Foo::Bar sera d'abord recherché dans les bibliothèques système et chargé depuis foo.par s'il n'est pas trouvé !

use PAR { file => 'foo.par', run => 'myscript' };

Cela chargera foo.par comme d'habitude, puis exécutera le fichier script/myscript du fichier. Vous devez noter que votre programme ne reprendra jamais le contrôle. Lorsque script/myscript se termine, votre programme principal fait de même. Pour le rendre plus utile, vous pouvez reporter cela au moment de l'exécution : (sinon équivalent)

require PAR;
PAR->import( { file => 'foo.par', run => 'myscript' } );

Si vous avez installé PAR::Repository::Client, vous pouvez faire ceci :

use PAR { repository => 'http://foo/bar/' };
use Module; # non installé localement !

Et PAR chargera tout module que vous n'avez pas depuis le dépôt spécifié. Pour plus de détails sur le fonctionnement, consultez la section NOTES. Au lieu d'une URL ou d'un chemin local, vous pouvez construire manuellement un objet PAR::Repository::Client et le passer à PAR. Si vous spécifiez l'option install => 1 dans la ligne use PAR ci-dessus, la distribution contenant Module sera installée en permanence sur votre système. ("use PAR { repository => 'http://foo/bar', install => 1 };")

En outre, il existe une option "upgrade => 1" qui vérifie les mises à jour dans le dépôt en plus de l'installation. Veuillez noter qu'une version mise à jour d'un module n'est chargée qu'à la prochaine exécution de votre application.

L'option "dependencies => 1" active la résolution statique des dépendances de PAR::Repository::Client (PAR::Repository::Client 0.23 et versions ultérieures).

Enfin, vous pouvez combiner les options "run" et "repository" pour exécuter un programme directement depuis un dépôt ! (Vous pouvez également spécifier l'option "install".)

use PAR { repository => 'http://foo/bar/', run => 'my_app' };
# N'atteindra jamais ce point car vous avez exécuté my_app,

DESCRIPTION

Ce module vous permet de charger des modules Perl spécialisés dans des fichiers zip, appelés Perl Archives, comme des bibliothèques à partir desquelles des modules Perl peuvent être chargés.

Il prend en charge le chargement de modules XS via des méthodes d'initialisation DynaLoader ; il écrit un fichier d'objet partagé dans un fichier temporaire au moment où nécessaire.

Un fichier .par est principalement un zip du répertoire blib après le processus de construction d'une distribution CPAN. Pour générer vous-même un fichier .par, il suffit de zipper les modules des répertoires arch/ et lib/, par exemple :

% perl Makefile.PL
% make
% cd blib
% zip -r mymodule.par arch/ lib/

Ensuite, vous pouvez utiliser mymodule.par n'importe où dans votre @INC, utiliser PAR, et cela fonctionne simplement. La prise en charge de la génération de fichiers .par est dans la prochaine version (plus de 0.2805) de Module::Build.

Pour plus de commodité, vous pouvez définir la variable d'environnement PERL5OPT à -MPAR pour activer le traitement PAR globalement (la surcharge est faible si vous ne l'utilisez pas) ; la définir à -MPAR=/path/to/mylib.par chargera un fichier PAR spécifique. Alternativement, envisagez d'utiliser l'utilitaire par.pl qui est fourni avec la distribution PAR::Packer, ou d'utiliser l'utilitaire parl qui est également distribué avec PAR::Packer sur les machines sans PAR.pm installé.

Note : Les scripts et exécutables autonomes créés avec par.pl et pp peuvent également être utilisés comme fichiers .par :

% pp -o packed.exe source.pl        # génère packed.exe (voir PAR::Packer)
% perl -MPAR=packed.exe other.pl    # fonctionne aussi
% perl -MPAR -Ipacked.exe other.pl  # idem

Veuillez consulter la section SYNOPSIS pour les cas d'utilisation typiques.

NOTES

Les paramètres dans META.yml à l'intérieur du fichier PAR peuvent affecter le fonctionnement de PAR. Par exemple, pp fournit l'option -C ("--clean") pour contrôler le comportement par défaut de la création de fichiers temporaires.

Actuellement, les fichiers générés par pp peuvent avoir quatre attributs spécifiques à PAR stockés dans META.yml :

par:
  clean: 0          # valeur par défaut de PAR_CLEAN
  signature: ''     # clé ID du fichier SIGNATURE
  verbatim: 0       # les PODs des dépendances précédentes ont-ils été préservés ?
  version: x.xx     # version de PAR.pm qui a généré ce PAR

Les variables d'environnement définies par l'utilisateur, telles que PAR_GLOBAL_CLEAN, remplacent toujours celles définies dans META.yml. L'algorithme de génération du cache/temporaire est alors le suivant :

  • Si PAR_GLOBAL_TEMP est spécifié, il est utilisé comme répertoire de cache pour les bibliothèques extraites, et il n'est pas nettoyé après l'exécution.
  • Si PAR_GLOBAL_TEMP n'est pas spécifié, mais que PAR_GLOBAL_CLEAN l'est, PAR_GLOBAL_TEMP est défini sur "TEMP/par-USERHEX/temp-PID/", et nettoyé après l'exécution.
  • Si aucun des deux n'est spécifié, "TEMP/par-USERHEX/cache-HASH/" est utilisé comme PAR_GLOBAL_TEMP, en réutilisant tous les fichiers existants à l'intérieur.

Voici une description des variables mentionnées ci-dessus.

  • TEMP est un répertoire temporaire, qui peut être défini via $ENV{PAR_GLOBAL_TMPDIR}, $ENV{TMPDIR}, $ENV{TEMPDIR}, $ENV{TEMP} ou $ENV{TMP}, dans cet ordre de priorité. Si aucun de ceux-ci n'est défini, C:\\TEMP, /tmp sont examinés et s'ils n'existent pas, . est utilisé.
  • USERHEX est dérivé du nom d'utilisateur, ou de SYSTEM s'il ne peut pas être trouvé. Sur Win32, il s'agit de $Win32::LoginName

Le comportement des variables mentionnées ci-dessus est décrit ci-dessous.

NOM

PAR - Perl Archive - description

SYNOPSIS

    use PAR;
    use PAR qw(PAR);
    use PAR qw(PAR $par_path);
    use PAR qw(PAR $par_path PAR_TEMP);
    use PAR qw(PAR $par_path PAR_TEMP $par_autoflush);
    use PAR qw(PAR $par_path PAR_TEMP $par_autoflush $par_strip);
    use PAR qw(PAR $par_path PAR_TEMP $par_autoflush $par_strip $par_no_exec);

    my $par = PAR->new($par_path);
    my $par = PAR->new($par_path, PAR_TEMP => '/tmp');
    $par->import();
    $par->import( file => 'foo.par' );
    $par->import( repository => 'http://foo/bar/' );
    $par->import( file => 'foo.par', fallback => 0 );
    $par->import( repository => 'http://foo/bar/', fallback => 1 );

    PAR->run();
    PAR->run( file => 'foo.par' );
    PAR->run( repository => 'http://foo/bar/' );
    PAR->run( file => 'foo.par', fallback => 0 );
    PAR->run( repository => 'http://foo/bar/', fallback => 1 );
    PAR->run( run => 'script/runme.pl' );

    my $par_obj = PAR->new;
    my $par_path = $par_obj->par_path; # The current par file
    my $par_temp = $par_obj->par_temp; # The temp dir for unpacking
    my $par_autoflush = $par_obj->par_autoflush; # Auto-flush flag
    my $par_strip = $par_obj->par_strip; # POD stripping flag
    my $par_no_exec = $par_obj->par_no_exec; # No exec flag

    my $user = $par_obj->user; # The user running the par
    my $pid = $par_obj->pid;   # The PID of the current process
    my $hash = $par_obj->hash; # The PAR hash

    # Re-importing modules
    use PAR;
    PAR->import( 'Some::Module' );
    PAR->import( 'Some::Module', file => 'foo.par' );
    PAR->import( 'Some::Module', repository => 'http://foo/bar/' );
    PAR->import( 'Some::Module', file => 'foo.par', fallback => 0 );
    PAR->import( 'Some::Module', repository => 'http://foo/bar/', fallback => 1 );

    # Ignoring POD sections
    use PAR qw(PAR $par_path $par_strip);
    PAR->import( file => 'foo.par', par_strip => 0 );

    # Forcing unpacking of shared libraries
    use PAR qw(PAR $par_path $par_no_shlib_unpack);
    PAR->import( file => 'foo.par', no_shlib_unpack => 0 );

DESCRIPTION

This module provides support for running Perl scripts packed with PAR (Perl Archive).

It allows you to create self-contained Perl executables that bundle your scripts, modules, and data files. The packed files can be executed directly without needing to install them into the system's Perl library path.

The core functionality includes:

  • Packing: Using the pp utility to bundle Perl code and dependencies into a .par or .par2 file.
  • Unpacking: Automatically unpacking the archive contents into a temporary directory when the script is executed.
  • Execution: Running the packed script and its dependencies as if they were installed normally.
  • Importing: Allowing other Perl scripts to use modules bundled within a PAR file.

The module also provides mechanisms for handling various aspects of PAR execution, such as temporary directory management, POD stripping, and shared library handling.

NOTES

When PAR is used, it modifies the @INC array to include the unpacked contents of the PAR archive. This allows Perl's module loading mechanism to find and load modules from within the archive.

The following environment variables can influence PAR's behavior:

PAR_TEMP
Specifies a directory where PAR can unpack its contents. If not set, PAR will try to use the system's temporary directory (e.g., /tmp).
PAR_STRIP
If set to a true value (e.g., 1), PAR will strip POD documentation sections from bundled modules. This can reduce the size of the unpacked files. By default, POD sections are stripped.
PAR_DEBUG
If set to a true value, PAR will print debugging messages to standard error, which can be helpful for diagnosing issues.
PAR_NO_EXEC
If set to a true value, PAR will not execute the packed script. Instead, it will unpack the archive and exit. This is useful for inspecting the contents of a PAR file or for debugging the packing process.

The following variables are available via use PAR:

  • $par_path: The path to the current PAR archive file. If the script is not run from a PAR archive, this will be undefined.
  • $par_temp: The path to the temporary directory used for unpacking.
  • $par_autoflush: A boolean flag indicating whether output should be automatically flushed. Defaults to true.
  • $par_strip: A boolean flag indicating whether POD sections should be stripped. Defaults to true.
  • $par_no_exec: A boolean flag indicating whether the script should be executed. Defaults to false.

When importing modules from a PAR file, the following formatters are used:

  • USERHEX: The raw bytes of the user name, encoded as two hex digits per byte. On Windows, this is typically $ENV{USERNAME}. On Unix, this is $ENV{USERNAME} or $ENV{USER}. Encode the raw bytes of the user name each as two hex digits to obtain USERHEX.
  • PID: The process ID. Forked children use the parent's PID.
  • HASH: A crypto-hash of the entire par file or executable, calculated at creation time. This value can be overloaded with "pp"'s --tempdir parameter.

options d'import

Lorsque vous faites "use PAR {...}" ou que vous appelez PAR->import({...}), les options suivantes sont disponibles.

PAR->import({ file => 'foo.par' });
# ou
PAR->import({ repository => 'http://foo/bar/' });
file
Le nom du fichier par.

Vous devez passer une option parmi 'file' ou 'repository'.

repository
Un dépôt par (exclusif de file)
fallback
Rechercher dans le @INC du système avant le par.

Désactivé par défaut pour charger les fichiers .par via "file =" ...>. Activé par défaut pour les dépôts PAR.

Pour préférer charger les modules d'un dépôt plutôt que les modules installés localement, vous pouvez charger le dépôt comme suit :

use PAR { repository => 'http://foo/bar/', fallback => 0 };
run
Le nom d'un script à exécuter dans le par. Se termine lorsqu'il est terminé.
no_shlib_unpack
Ignorer le déballage des bibliothèques dynamiques groupées de shlib/$archname. Le client peut les avoir installées, ou vous pouvez souhaiter les mettre en cache vous-même. Dans tous les cas, elles doivent se retrouver dans l'emplacement d'installation standard (tel que /usr/local/lib/) ou dans $ENV{PAR_TEMP} avant que vous n'exigiez le module qui en a besoin. Si elles ne sont pas accessibles avant que vous n'exigiez le module dépendant, perl mourra avec un message tel que "cannot open shared object file..."

PAR::Tutorial

La distribution PAR::Packer qui contient les utilitaires de packaging : par.pl, parl, pp.

PAR::Dist pour les détails sur les distributions PAR.

PAR::Repository::Client pour les détails sur l'accès aux dépôts PAR. PAR::Repository pour les détails sur la manière de configurer un tel dépôt.

Steffen Mueller a des diapositives détaillées sur l'utilisation de PAR pour le déploiement d'applications à http://steffen-mueller.net/talks/appdeployment/.
