PAR::Dist(3) Documentation des paquets contribués pour Perl PAR::Dist(3)

NOM

PAR::Dist - Créer et manipuler des distributions PAR

SYNOPSIS

En tant que commande shell :

% perl -MPAR::Dist -eblib_to_par

Dans les programmes :

use PAR::Dist;
my $dist = blib_to_par(); # créer une distribution PAR en utilisant ./blib/
install_par($dist);       # l'installer sur le système
uninstall_par($dist);     # la désinstaller du système
sign_par($dist);          # la signer avec Module::Signature
verify_par($dist);        # la vérifier avec Module::Signature
install_par("http://foo.com/DBI-1.37-MSWin32-5.8.0.par"); # fonctionne aussi
install_par("http://foo.com/DBI-1.37"); # autonomise le nom de l'architecture + version de Perl
install_par("cpan://SMUELLER/PAR-Packer-0.975"); # utilise le répertoire de l'auteur de CPAN

DESCRIPTION

Ce module crée et manipule des distributions PAR. Ce sont des fichiers PAR spécifiques à l'architecture, qui contiennent tout sous le répertoire blib/ des distributions CPAN après leur étape de "make" ou "Build", un META.yml décrivant les métadonnées de la distribution originale de CPAN, et un MANIFEST détaillant tous les fichiers qu'il contient. Les distributions PAR signées numériquement contiendront également un fichier SIGNATURE.

La convention de nommage pour de telles distributions est :

$NAME-$VERSION-$ARCH-$PERL_VERSION.par

Par exemple,

PAR-Dist-0.01-i386-freebsd-5.8.0.par

correspond à la version 0.01 de "PAR-Dist" sur CPAN, construite pour la version Perl 5.8.0 sur l'architecture "i386-freebsd".

FONCTIONS

Plusieurs fonctions sont exportées par défaut. Sauf indication contraire, elles peuvent prendre soit un hash de paramètres nommés, un seul argument (pris comme $path pour "blib_to_par" et $dist pour d'autres fonctions), ou aucun argument (auquel cas le premier PAR du répertoire courant est utilisé).

Ainsi, dans un répertoire ne contenant qu'un seul test.par, toutes les invocations ci-dessous sont équivalentes :

% perl -MPAR::Dist -e"install_par( dist => 'test.par' )"
% perl -MPAR::Dist -e"install_par( 'test.par' )"
% perl -MPAR::Dist -einstall_par;

Si $dist ressemble à une URL, "LWP::Simple::mirror" est appelé pour le copier localement sous $ENV{PAR_TEMP} (ou "$TEMP/par/" si non spécifié), et la fonction agira sur le fichier local obtenu. Si l'URL commence par "cpan://AUTHOR/", il sera automatiquement développé vers le répertoire de l'auteur de CPAN (par exemple, "http://www.cpan.org/modules/by-authors/id/A/AU/AUTHOR/").

Si $dist n'a pas d'extension de fichier commençant par une lettre ou un underscore, un trait d'union et le $suffix (par défaut "ARCH-$PERL_VERSION.par") lui seront ajoutés.

blib_to_par

Prend des paires clé-valeur comme paramètres ou un seul paramètre indiquant le chemin contenant le répertoire blib/.

Crée une distribution PAR à partir du répertoire blib/ sous "path", ou sous le répertoire courant si non spécifié. Si blib/ n'existe pas, il exécute automatiquement Build, make, Build.PL ou Makefile.PL pour le créer.

Retourne le nom du fichier PAR généré.

Les paramètres valides sont :

path
Définit le chemin contenant le répertoire blib/ à partir duquel la distribution PAR est générée.
name, version, suffix
Ces attributs définissent le nom, la version et le suffixe spécifique de la distribution. Le nom et la version peuvent être déterminés automatiquement à partir des fichiers META.yml ou Makefile.PL de la distribution. Le suffixe est généré à partir de votre nom d'architecture et de votre version de Perl par défaut.
dist
Le nom du fichier PAR à générer.
quiet
Défini à vrai pour supprimer autant de sorties que possible.

install_par

Installe une distribution PAR sur le système, en utilisant "ExtUtils::Install::install_default".

Si un seul paramètre est fourni, il est traité comme la valeur du paramètre "dist".

Les paramètres nommés valides sont :

dist
Le fichier .par à installer. Les heuristiques décrites dans les FONCTIONS s'appliquent.
prefix
Cette chaîne est ajoutée au début de tous les chemins d'installation. Si elle n'est pas spécifiée, la valeur de la variable d'environnement "PERL_INSTALL_ROOT" est utilisée.
uninstall_shadows
Correspond à l'option "uninstall_shadows" de ExtUtils::Install. Selon son manuel : Si "uninstall_shadows" est défini à vrai, toute version différente dans @INC sera désinstallée. Ceci correspond à "make install UNINST=1".
verbose
Correspond à l'option "verbose" de ExtUtils::Install. Selon son manuel : Si "verbose" est vrai, chaque fichier supprimé sera imprimé. Ceci correspond à "make install VERBINST=1". Les valeurs de "verbose" allant de 1 à 5 affichent de plus en plus de sortie de diagnostic. Le niveau de verbosité par défaut pour PAR::Dist est 1.

Si vous installez uniquement dans le perl en cours d'exécution, vous pouvez arrêter de lire le reste de cette section.

De plus, vous pouvez utiliser plusieurs paramètres pour modifier les destinations d'installation par défaut. Vous n'avez généralement pas à vous en soucier, sauf si vous installez dans un répertoire d'utilisateur local. La section suivante énumère les noms de paramètres et leurs valeurs par défaut :

Paramètre         De          À
inst_lib          blib/lib      $Config{installsitelib} (*)
inst_archlib      blib/arch     $Config{installsitearch}
inst_script       blib/script   $Config{installscript}
inst_bin          blib/bin      $Config{installbin}
inst_man1dir      blib/man1     $Config{installman1dir}
inst_man3dir      blib/man3     $Config{installman3dir}
packlist_read                   $Config{sitearchexp}/auto/$name/.packlist
packlist_write                  $Config{installsitearch}/auto/$name/.packlist

Le paramètre "packlist_write" est utilisé pour contrôler où le fichier .packlist est écrit. (Il est nécessaire pour la désinstallation.) Le paramètre "packlist_read" spécifie un fichier .packlist à fusionner s'il existe. En définissant l'une des destinations d'installation ci-dessus à "undef", vous pouvez supprimer cette destination complètement. Par exemple, passer "inst_man1dir => undef, inst_man3dir => undef" signifie que les pages de manuel qu'il contient ne seront pas installées. Ceci n'est pas disponible pour les listes de paquets.

Encore une fois, les valeurs par défaut seront les site normaux de %Config.

(*) Si le inst_archlib du ".par" (normalement "blib/arch") n'est pas vide, le code dans inst_lib (normalement "blib/lib") est également installé dans le chemin inst_archlib. Cela a du sens pour les modules XS. Si, cependant, vous remplacez "inst_lib", cette conversion automatique est également écrasée ! Vous pouvez utiliser le paramètre nommé "auto_inst_lib_conversion => 1" pour réactiver la conversion pour les inst_lib personnalisés.

NAME

PAR::Dist - A module to distribute Perl programs as PAR archives

SYNOPSIS

  use PAR::Dist;
  
  # Create a PAR archive from a distribution directory
  blib_to_par('MyDist');
  
  # Install a PAR archive
  install_par('MyDist.par');
  
  # Uninstall a PAR archive
  uninstall_par('MyDist.par');
  
  # Sign a PAR archive
  sign_par('MyDist.par', signer => 'autrijus');
  
  # Verify a PAR archive
  verify_par('MyDist.par');
  
  # Merge PAR archives
  merge_par('foo.par', 'bar.par', 'baz.par');
  
  # Remove man pages from a PAR archive
  remove_man('MyDist.par');
  
  # Get META.yml from a PAR archive
  my $meta = get_meta('MyDist.par');
  
  # Parse distribution name
  my ($name, $version, $arch) = parse_dist_name('MyDist-1.0.tar.gz');
  
  # Generate a stub for a new PAR distribution
  generate_blib_stub(name => 'MyApp', version => '1.00');
  
  # Check if a PAR archive contains binaries
  if (contains_binaries('MyDist.par')) {
      print "This archive contains platform-specific binaries.\n";
  }

DESCRIPTION

This module provides a set of functions for creating, installing, uninstalling, signing, verifying, merging, and manipulating PAR archives. PAR (Perl Archive) is a packaging format for Perl modules and executables, allowing for self-contained and distributable Perl applications.

FUNCTIONS

blib_to_par

Creates a PAR archive from the contents of the blib directory. It requires that you have run "Build" or "MakeMaker" to create the blib directory and its contents.

The first argument is the name of the PAR distribution, used for naming the output file (e.g., "MyApp" becomes "MyApp.par"). If omitted, it defaults to "blib".

It accepts the following named parameters:

"dist"
The name of the distribution. Defaults to the base name of the current directory or "blib".
"version"
The distribution version string (e.g., "1.00"). Defaults to "0.00".
"archive"
The name of the output PAR archive file. Defaults to "$dist-$version.par".
"targetdir"
The directory where the PAR archive will be created. Defaults to the current directory.
"compress"
The compression level (0-9). Defaults to "6".
"manifest"
A reference to a hash containing manifest entries. This allows you to customize the contents of the archive.
"author"
The name of the author.
"email"
The email address of the author.
"license"
The license of the distribution.
"depends"
A reference to an array of distribution dependencies.
"build_depends"
A reference to an array of build dependencies.
"configure_depends"
A reference to an array of configure dependencies.
"provides"
A reference to a hash describing modules provided by the distribution.
"packlist_write"
A reference to a subroutine that will be called to write the .packlist file. It receives the list of installed files and the name of the packlist file.

This function is not exported by default.

install_par

Installs a PAR distribution using "ExtUtils::Install::install". It extracts the PAR archive to a temporary directory and then installs its contents.

It takes the name of the PAR archive as the first argument. Subsequent arguments are treated as named parameters:

"targetdir"
The target installation directory. Defaults to "blib".
"scriptdir"
The directory to install scripts to. Defaults to "blib/script".
"install_base"
The base installation directory (e.g., ".", "site", "vendor"). Defaults to "site".
"destdir"
A directory prefix for installation, useful for staging installs.
"checksums"
If true, checksums are verified before installation.
"custom_targets"
A reference to a hash of custom installation targets. This allows you to install files from the PAR archive to arbitrary locations on the filesystem. For example:

custom_targets => { 'blib/my_data' => '/some/path/my_data' }

This can be used to install the contents of PAR archives to arbitrary locations.

This function is not exported by default.

uninstall_par

Uninstalls all previously installed contents of a PAR distribution, using "ExtUtils::Install::uninstall".

Takes almost the same parameters as "install_par", but naturally, the installation target parameters do not apply. The only exception to this is the "packlist_read" parameter which specifies the .packlist file to read the list of installed files from. It defaults to "$Config::Config{installsitearch}/auto/$name/.packlist".

Additionally, the "uninstall_shadows" parameter of "install_par" isn't available.

sign_par

Digitally sign a PAR distribution using "gpg" or Crypt::OpenPGP, via Module::Signature.

verify_par

Verify the digital signature of a PAR distribution using "gpg" or Crypt::OpenPGP, via Module::Signature.

Returns a boolean value indicating whether verification passed; $! is set to the return code of "Module::Signature::verify".

merge_par

Note: Since version 0.32 of PAR::Dist, this function requires a YAML reader. The order of precedence is:

YAML:XS YAML YAML::Syck YAML::Tiny

Merges two or more PAR distributions into one. First argument must be the name of the distribution you want to merge all others into. Any following arguments will be interpreted as the file names of further PAR distributions to merge into the first one.

merge_par('foo.par', 'bar.par', 'baz.par')

This will merge the distributions "foo.par", "bar.par" and "baz.par" into the distribution "foo.par". "foo.par" will be overwritten!

The original META.yml of "foo.par" is retained, but augmented with any "provides", "requires", "recommends", "build_requires", and "configure_requires" sections from the other ".par" files.

remove_man

Remove the man pages from a PAR distribution. Takes one named parameter: dist which should be the name (and path) of the PAR distribution file. The calling conventions outlined in the "FUNCTIONS" section above apply.

The PAR archive will be extracted, stripped of all "man\d?" and "html" subdirectories and then repackaged into the original file.

get_meta

Opens a PAR archive and extracts the contained META.yml file. Returns the META.yml file as a string.

Takes one named parameter: dist. If only one parameter is passed, it is treated as the dist parameter. (Have a look at the description in the "FUNCTIONS" section above.)

Returns undef if no PAR archive or no META.yml within the archive were found.

parse_dist_name

First argument must be a distribution file name. The file name is parsed into distribution name, distribution version, architecture name, and perl version.

Returns the results as a list in the above order. If any or all of the above cannot be determined, returns undef instead of the undetermined elements.

Supported formats are:

Math-Symbolic-0.502-x86_64-linux-gnu-thread-multi-5.8.7

Math-Symbolic-0.502

The ".tar.gz" or ".par" extensions as well as any preceding paths are stripped before parsing. Starting with "PAR::Dist" 0.22, versions containing a preceding "v" are parsed correctly.

This function is not exported by default.

generate_blib_stub

Creates a blib/lib subdirectory in the current directory and prepares a META.yml with meta information for a new PAR distribution. First argument should be the name of the PAR distribution in a format understood by parse_dist_name(). Alternatively, named arguments resembling those of "blib_to_par" are accepted.

After running "generate_blib_stub" and injecting files into the blib directory, you can create a PAR distribution using "blib_to_par". This function is useful for creating custom PAR distributions from scratch. (I.e. not from an unpacked CPAN distribution) Example:

use PAR::Dist;
use File::Copy 'copy';
generate_blib_stub(
  name => 'MyApp', version => '1.00'
);
copy('MyApp.pm', 'blib/lib/MyApp.pm');
blib_to_par(); # generates the .par file!

"generate_blib_stub" will not overwrite existing files.

contains_binaries

This function is not exported by default.

Opens a PAR archive tries to determine whether that archive contains platform-specific binary code.

Takes one named parameter: dist. If only one parameter is passed, it is treated as the dist parameter. (Have a look at the description in the "FUNCTIONS" section above.)

Throws a fatal error if the PAR archive could not be found.

Returns one if the PAR was found to contain binary code and zero otherwise.
