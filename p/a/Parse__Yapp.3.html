NOM

Parse::Yapp - Extension Perl pour générer et utiliser des analyseurs LALR.

SYNTAXE

yapp -m MonAnalyseur fichier_grammaire.yp
...
use MonAnalyseur;
$analyseur=new MonAnalyseur();
$valeur=$analyseur->YYParse(yylex => \&lexer_sub, yyerror => \&error_sub);
$nb_erreurs=$analyseur->YYNberr();
$analyseur->YYData->{DATA}= [ 'N\'importe quoi', 'Que vous voulez' ];
$data=$analyseur->YYData->{DATA}[0];

DESCRIPTION

Parse::Yapp (Yet Another Perl Parser compiler) est une collection de modules qui vous permet de générer et d'utiliser des analyseurs LALR avec une interface orientée objet Perl.

Le script yapp est un frontal pour le module Parse::Yapp et vous permet de créer facilement un analyseur orienté objet Perl à partir d'un fichier de grammaire.

Le fichier de grammaire

"Commentaires"
Les commentaires sont présents dans tous vos fichiers, ils peuvent être de style Perl, introduits par # jusqu'à la fin de la ligne, ou de style C, entre /* et */.
"Tokens et chaînes littérales"
Dans tous les fichiers de grammaire, deux types de symboles peuvent apparaître : non-terminaux, aussi appelés côtés gauches, qui sont les noms de vos règles, et terminaux, aussi appelés tokens.

Les tokens sont les symboles que la fonction lexer de votre programme enverra à l'analyseur (voir ci-dessous). Ils sont de deux types : tokens symboliques et chaînes littérales.

Les non-terminaux et les tokens symboliques partagent la même syntaxe d'identification :

[A-Za-z][A-Za-z0-9_]*

Les chaînes littérales sont entourées de guillemets simples et peuvent contenir presque n'importe quoi. Elles seront représentées dans votre fichier d'analyseur sous forme de chaînes doubles, rendant tout caractère spécial comme tel. Les guillemets, $ et @ seront échappés par \, rendant leur écriture plus naturelle. D'un autre côté, si vous avez besoin d'un guillemet dans une chaîne littérale, vous l'échappez simplement avec \.

Vous ne pouvez pas avoir une chaîne littérale 'error' dans votre grammaire, car cela pourrait confondre le driver avec le token 'error'. Utilisez plutôt un token symbolique à la place. Si vous l'utilisez par erreur, cela générera un avertissement qui vous dira que vous auriez dû écrire 'error' et le traitera comme s'il s'agissait du token 'error', ce qui n'est clairement pas ce que vous voulez.

Le fichier est divisé en trois sections, séparées par "%%" :
section d'en-tête
%%
section de règles
%%
section de pied de page
La section d'en-tête peut éventuellement contenir :
  • Un bloc de code entre "%{" et "%}" comme dans yacc. Il peut contenir tout code Perl valide et est copié littéralement au début du module analyseur. Ils ne sont pas aussi utiles que dans yacc, mais vous pouvez les utiliser, par exemple, pour des déclarations de variables globales, bien que vous remarquiez plus tard que ces variables globales peuvent être évitées pour rendre un module analyseur réentrant.
  • Des déclarations de précédence, introduites par %left, %right et %nonassoc, qui spécifient l'associativité, suivies de la liste des tokens ou des littéraux qui ont la même précédence et associativité. La précédence déclarée en dernier aura le niveau le plus élevé (voir l'explication dans les manuels de yacc ou bison, car ils sont implémentés exactement de la même manière dans Parse::Yapp).
  • %start suivi d'un côté gauche de règle, déclarant que cette règle sera la règle de départ de votre grammaire. Par défaut, lorsque %start n'est pas utilisé, c'est la première règle de votre section de grammaire.
  • %token suivi d'une liste de symboles, les forçant à être reconnus comme tokens, générant une erreur de syntaxe s'ils sont utilisés dans la partie gauche d'une déclaration de règle. Note : dans Parse::Yapp, vous n'avez pas besoin de déclarer les tokens comme dans yacc : tout symbole n'apparaissant pas comme côté gauche d'une règle est considéré comme un token. D'autres déclarations de yacc comme %type et %union sont parsées mais (à peu près) ignorées.
  • %expect suivi d'un nombre, supprimant les avertissements sur les conflits Shift/Reduce lorsque les deux nombres correspondent, comme dans bison.
La section de règles contient vos règles de grammaire :
Une règle se compose d'un symbole de côté gauche, suivi d'un : et d'une ou plusieurs parties de droite séparées par '|' et terminées par ';' : 
exp:    exp '+' exp
    |   exp '-' exp
    ;

Une partie de droite peut être vide :

input:  #empty
    |   input line
    ;

(si vous avez plus d'une partie de droite vide, Parse::Yapp émettra un avertissement, car c'est généralement une erreur, et vous aurez probablement un conflit reduce/reduce)

Une partie de droite peut être suivie d'une directive optionnelle %prec, suivie d'un token, donnant à la règle un niveau de précédence explicite (voir les manuels de yacc pour sa signification exacte) et d'un bloc d'action sémantique optionnel (voir ci-dessous).

exp:   '-' exp %prec NEG { -$_[1] }
    |  exp '+' exp       { $_[1] + $_[3] }
    |  NUM
    ;

Note : dans Parse::Yapp, un côté gauche ne peut pas apparaître plus d'une fois comme nom de règle (cela diffère de yacc).

"La section de pied de page"
peut contenir tout code Perl valide et sera ajouté à la fin du module analyseur. Vous pouvez y écrire votre lexer, vos rapports d'erreur et tout ce qui est pertinent pour votre analyseur.
"Actions sémantiques"
Les actions sémantiques sont exécutées chaque fois qu'il y a une réduction dans le flux d'analyse et doivent retourner une valeur sémantique.

Elles sont (généralement, mais voir ci-dessous "Dans les actions de règle") écrites à la fin de la partie de droite, entre "{ }", et sont copiées littéralement dans le fichier d'analyseur, à l'intérieur de la table des règles.

Soyez conscient que dans Perl, le décalage des accolades dans les chaînes est beaucoup plus difficile qu'en C : à l'intérieur des chaînes, elles n'ont pas besoin de correspondre. Alors qu'en C il est très facile de détecter le début d'un bloc de chaîne, c'est beaucoup plus difficile en Perl, en raison des nombreuses façons d'écrire de tels littéraux. Par conséquent, il n'y a actuellement aucun contrôle. Si vous avez besoin d'une accolade dans une chaîne double, vous l'échappez simplement ("\{" ou "\}"). Pour les chaînes simples, vous aurez besoin d'un commentaire qui correspond à elle dans le bon ordre. Désolé pour le désagrément.

{
    "{ Mon bloc de chaîne }".
    "\{ Mon autre bloc de chaîne \}".
    qq/ Mon accolade non correspondante \} /.
    # Forcer la correspondance : {
    q/ pour mon accolade de fermeture } /
    q/ Mon accolade ouvrante { /
    # doit être fermée : }
}

Tous ces construits devraient fonctionner.

Dans Parse::Yapp, les actions sémantiques sont appelées comme des appels de sous-routine Perl normaux, avec leurs arguments passés dans @_, et leur valeur sémantique est leur valeur de retour.

$_[1] à $_[n] sont les paramètres tout comme $1 à $n dans yacc, tandis que $_[0] est l'objet analyseur lui-même.

Avoir $_[0] comme objet analyseur permet d'appeler les méthodes de l'analyseur. C'est ainsi que les macros yacc sont implémentées :

yyerrok est fait en appelant $_[0]->YYErrok
YYERROR est fait en appelant $_[0]->YYError
YYACCEPT est fait en appelant $_[0]->YYAccept
YYABORT est fait en appelant $_[0]->YYAbort

Toutes ces méthodes retournent `undef` de manière pratique.

YYRECOVERING est fait en appelant $_[0]->YYRecovering

Quatre méthodes utiles dans la sous-routine de récupération d'erreur

$_[0]->YYCurtok
$_[0]->YYCurval
$_[0]->YYExpect
$_[0]->YYLexer

retournent les résultats.

PARSEURS AUTONOMES

Par défaut, les modules de parseur générés nécessitent que la bibliothèque Parse::Yapp soit installée sur le système pour fonctionner. Ils utilisent Parse::Yapp::Driver, qui peut être partagé en toute sécurité entre les parseurs du même script.

Si vous préférez générer un module autonome, utilisez le commutateur -s avec yapp : cela copiera automatiquement le code du pilote dans votre module, vous permettant de l'utiliser/distribuer sans avoir besoin de la bibliothèque Parse::Yapp, le rendant ainsi un parseur véritablement autonome.

Si vous le faites, n'oubliez pas d'inclure la notification de copyright de Parse::Yapp dans la licence de votre module principal, afin que d'autres soient informés de la bibliothèque Parse::Yapp.

NUMÉROS DE LIGNE DU FICHIER SOURCE

Par défaut, les numéros de ligne sont inclus dans le module de parseur généré, ce qui aide à trouver la ligne coupable dans votre fichier source en cas d'erreur de syntaxe. Vous pouvez désactiver cela en compilant votre grammaire avec le commutateur -n.
