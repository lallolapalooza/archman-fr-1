Params::ValidationCompiler(3) Documentation Perl fournie par l'utilisateur Params::ValidationCompiler(3)

NOM

Params::ValidationCompiler - Créez un validateur de paramètres de sous-routine optimisé une fois, utilisez-le pour toujours

VERSION

version 0.31

SYNOPSIS

use Types::Standard qw( Int Str );
use Params::ValidationCompiler qw( validation_for );
{
    my $validator = validation_for(
        params => {
            foo => { type => Int },
            bar => {
                type     => Str,
                optional => 1,
            },
            baz => {
                type    => Int,
                default => 42,
            },
        },
    );
    sub foo {
        my %args = $validator->(@_);
    }
}
{
    my $validator = validation_for(
        params => [
            { type => Int },
            {
                type     => Str,
                optional => 1,
            },
        ],
    );
    sub bar {
        my ( $int, $str ) = $validator->(@_);
    }
}
{
    my $validator = validation_for(
        params => [
            foo => { type => Int },
            bar => {
                type     => Str,
                optional => 1,
            },
        ],
        named_to_list => 1,
    );
    sub baz {
        my ( $foo, $bar ) = $validator->(@_);
    }
}

DESCRIPTION

Ce module crée une sous-routine personnalisée et très efficace pour la vérification des paramètres. Il peut gérer des paramètres nommés ou positionnels, et peut renvoyer les paramètres sous forme de paires clé/valeur ou d'une liste de valeurs.

En plus des vérifications de type, il prend également en charge les valeurs par défaut des paramètres, les paramètres optionnels et les paramètres supplémentaires "slurpy".

PARAMETRES

Ce module a deux options exportées, "validation_for" et "source_for". Ces deux sous-routines acceptent les mêmes options :

params

Un tableau référence ou un hachage référence contenant une spécification de paramètre.

Si vous passez un hachage référence, la sous-routine validatrice générée attendra des paramètres nommés. La valeur de "params" doit être un hachage référence où les noms des paramètres sont les clés et les spécifications sont les valeurs.

Si vous passez un tableau référence et que "named_to_list" est faux, le validateur attendra des paramètres positionnels. Chaque élément du tableau référence "params" doit être une spécification de paramètre.

Si vous passez un tableau référence et que "named_to_list" est vrai, le validateur attendra des paramètres nommés, mais renverra une liste de valeurs. Dans ce cas, le tableau référence doit contenir une *liste* de paires clé/valeur, où les noms des paramètres sont les clés et les spécifications sont les valeurs.

Chaque spécification peut contenir soit un booléen, soit un hachage référence. Si la spécification est un booléen, cela indique requis (vrai) ou optionnel (faux).

Le hachage référence de spécification accepte les clés suivantes :

  • type

    Un objet type. Il peut s'agir d'un type Moose (de Moose ou MooseX::Types), d'un type Type::Tiny, ou d'un type Specio.

    Si le type a des coercitions, elles seront toujours utilisées.

  • default

    Cela peut être un scalaire simple (non référence) ou une référence de sous-routine. La référence de sous-routine sera appelée sans aucun argument (pour l'instant).

  • optional

    Un booléen indiquant si le paramètre est optionnel ou non. Par défaut, les paramètres sont requis à moins que vous ne fournissiez une valeur par défaut.

slurpy

Si c'est une simple valeur vraie, alors la sous-routine générée accepte des arguments supplémentaires non spécifiés dans "params". Par défaut, les arguments supplémentaires provoquent une exception.

Vous pouvez également passer une contrainte de type ici, auquel cas tous les arguments supplémentaires doivent être des valeurs du type spécifié.

named_to_list

Si c'est vrai, la sous-routine générée attendra une liste de paires clé-valeur ou un hachage référence et elle renverra une liste ne contenant que des valeurs. Les "params" que vous passez doivent être un tableau référence de paires clé-valeur. L'ordre de ces paires détermine l'ordre dans lequel les valeurs sont renvoyées.

Vous ne pouvez pas combiner "slurpy" avec "named_to_list" car il n'y a aucun moyen de savoir comment ordonner les valeurs de retour supplémentaires.

return_object

Si c'est vrai, la sous-routine générée renverra un objet au lieu d'un hachage référence. Vous ne pouvez pas définir cette option sur vrai si vous avez défini "slurpy" ou "named_to_list".

Les méthodes de l'objet correspondent aux noms des paramètres passés à la sous-routine. Bien que l'appel de méthodes sur un objet soit plus lent que l'accès à un hachage référence, l'avantage est que si vous faites une faute de frappe dans un nom de paramètre, vous obtiendrez une erreur utile.

Si vous avez Class::XSAccessor installé, il sera utilisé pour créer les méthodes de la classe, ce qui le rend assez rapide.

L'objet renvoyé se trouve dans une classe générée. Ne vous fiez pas au nom de cette classe en particulier, et ne vérifiez pas cet objet en utilisant "isa", "DOES", ou quoi que ce soit de similaire.

Lorsque "return_object" est vrai, la spécification du paramètre hachage référence accepte également les clés supplémentaires suivantes :

  • getter

    Utilisez ceci pour définir un nom de méthode d'accesseur explicite pour le paramètre. Par défaut, le nom de la méthode sera le même que le nom du paramètre. Notez que si le nom du paramètre n'est pas un nom de sous-routine valide, vous obtiendrez une erreur lors de la compilation de la sous-routine de validation, à moins que vous ne spécifiiez un accesseur pour le paramètre.

  • predicate

    Utilisez ceci pour demander la création d'une méthode prédicat pour ce paramètre. La méthode prédicat renvoie vrai si le paramètre a été passé et faux s'il ne l'a pas été. Notez que ceci n'est utile que pour les paramètres optionnels, mais vous pouvez demander un prédicat pour n'importe quel paramètre.

EXPORT

Les sous-routines exportées sont :

validation_for(...)

Ceci renvoie une sous-routine qui implémente la vérification spécifique des paramètres. Cette sous-routine attend de recevoir les paramètres à valider dans @_. Si tous les paramètres sont valides, elle renverra les paramètres validés (avec les valeurs par défaut appropriées), soit sous forme de liste de paires clé-valeur, soit sous forme de liste de valeurs uniquement. Si l'un des paramètres est invalide, elle lèvera une exception.

Pour les validateurs qui attendent des paramètres nommés, la sous-routine générée accepte soit une liste de paires clé-valeur, soit un hachage référence unique. Sinon, le validateur attend une liste de valeurs.

Pour l'instant, vous devez décaler l'invocant vous-même.

Cette sous-routine accepte les paramètres supplémentaires suivants :

  • name

    Si ceci est fourni, alors la sous-routine générée sera nommée en utilisant Sub::Util. Ceci est fortement recommandé car cela permet de distinguer différentes sous-routines de vérification lors du profilage ou dans les traces de pile.

    Ce nom sera également utilisé dans certains messages d'exception, même si Sub::Util n'est pas disponible.

    Notez que vous devez installer Sub::Util vous-même séparément, car il n'est pas requis par cette distribution, afin d'éviter d'exiger un compilateur.

  • name_is_optional

    Si ceci est vrai, alors le nom est ignoré lorsque "Sub::Util" n'est pas installé. Si ceci est faux, alors passer un nom lorsque Sub::Util ne peut pas être chargé provoque une exception.

    Ceci est utile pour les modules CPAN où vous souhaitez définir un nom si possible, mais vous ne souhaitez pas ajouter de prérequis sur Sub::Util.

  • debug

    Définit la variable d'environnement "EVAL_CLOSURE_PRINT_SOURCE" sur vrai avant d'appeler Eval::Clos

NAME

Eval::Closure - Create and return closures with lexically scoped data

SYNOPSIS

  use Eval::Closure qw( Eval::Closure );

  my $string = "print \$x;";
  my $sub = Eval::Closure->new(
    CODE => $string,
    VARS => { x => 1 },
  );

  $sub->(); # prints 1

DESCRIPTION

This module allows you to create Perl subroutines (closures) from strings of Perl code. Unlike the built-in eval(), Eval::Closure allows you to provide lexical variables that the code string can use.

This is useful for generating subroutines on the fly. You can generate a subroutine that uses data that is available at compile time, and then pass that subroutine around. The data will be available to the subroutine whenever it is called.

PARAMETERS

CODE

A string containing the Perl code to be evaluated. This code will be executed within the context of the subroutine.

VARS

A hashref where the keys are the names of the variables that you want to be available to the CODE, and the values are the values of those variables.

For example:

  VARS => {
      x => 1,
      y => [1, 2, 3],
      z => { a => 1 },
    }

In this example, the CODE string can use $x, @y, and %z.

VARS_LIST

A reference to an array of variable names to be exported into the scope of the generated subroutine. This is an alternative to VARS.

For example:

  VARS_LIST => [qw( x y z )]

This is useful when you want to create a closure that uses variables from the surrounding scope, but you don't want to explicitly list them in the VARS hashref.

SUBS

A hashref where the keys are subroutine names and the values are references to subroutines. These subroutines will be available within the generated subroutine.

QUIET

If set to a true value, this will prevent the source code from being printed to STDOUT when the subroutine is generated. By default, the source code is printed.

EXPORTS

This module exports the Eval::Closure coderef. This coderef can be used to create new closures. The coderef itself is actually an object with a new method.

For example:

  use Eval::Closure qw( Eval::Closure );
  my $sub = Eval::Closure->new( ... );

This is done so that you can have multiple Eval::Closure objects in your program, each with its own set of options.

  • Eval::Closure::eval_closure() This function is equivalent to calling Eval::Closure->new(@_)->create(). It is provided for convenience.

  • Eval::Closure::source_for() This function returns the source code for a generated subroutine. This is useful for debugging.

When QUIET is false (the default), the source code of the generated subroutine is printed to STDOUT before it is "eval"'d.

source_for(...)

This returns a two element list. The first is a string containing the source code for the generated sub. The second is a hashref of "environment" variables to be used when generating the subroutine. These are the arguments that are passed to Eval::Closure.
