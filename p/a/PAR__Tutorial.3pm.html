NOM

PAR::Tutorial - Empaquetage et déploiement multiplateforme avec PAR

SYNOPSIS

Ceci est un tutoriel sur PAR, apparu pour la première fois à la 7ème Perl Conference. La version HTML de ce tutoriel est disponible en ligne sur http://search.cpan.org/perldoc?PAR::Tutorial

DESCRIPTION

Sur le déploiement d'applications Perl

% sshnuke.pl 10.2.2.2 -rootpw="Z1ON0101"
Perl v5.6.1 requis -- ceci n'est que v5.6.0, arrêté à la ligne 1 de sshnuke.pl.
BEGIN a échoué -- compilation abandonnée à la ligne 1 de sshnuke.pl.
  • Q : « Au secours ! Je ne peux pas exécuter votre programme ! »
  • R1 : Installez Perl et "perl -MCPAN -e'install(...)'"
  • Comment savoir quels modules sont nécessaires ?
  • Les nouvelles versions des modules CPAN peuvent casser "sshnuke.pl"
•
R2 : Installez Perl et "tar zxf my_perllib.tgz"
•
Écrase potentiellement les modules existants ; pas du tout multiplateforme
•
R3 : Utilisez l'exécutable généré par "perlcc sshnuke.pl"
•
Impossible à déboguer ; "perlcc" ne fonctionne généralement pas de toute façon

PAR, le Perl Archive Toolkit

•
Faire pour Perl ce que JAR (Java Archive) fait pour Java
  • Agrège les modules, scripts et autres fichiers dans un fichier Zip
  • Facile à générer, mettre à jour et extraire
  • Cohérence des versions : résout les problèmes de compatibilité ascendante
  • Développé par la communauté : "par@perl.org"
•
Les fichiers PAR peuvent être empaquetés dans des scripts autonomes
  • Analyse automatiquement le script Perl pour trouver les dépendances
  • Regroupe tous les modules tiers nécessaires avec lui
  • Nécessite uniquement Perl de base pour fonctionner sur la machine cible
  • PAR est également livré avec "pp", le Perl Packager : 
    % pp -o sshnuke.exe sshnuke.pl # exécutable autonome !

Empaquetage simple

  • Les fichiers PAR sont juste des fichiers Zip contenant des modules
  • Tous les outils Zip peuvent les générer : 
    % zip foo.par Hello.pm World.pm        # empaqueter deux modules
% zip -r bar.par lib/          # récupérer tous les modules dans lib/
  • Pour charger des modules depuis des fichiers PAR : 
    use PAR;
use lib "foo.par";             # la partie .par est optionnelle
use Hello;
  • Ceci fonctionne aussi : 
    use PAR "/home/mylibs/*.par";  # les mettre tous dans @INC
use Hello;

Chargeurs PAR

  • Utilisez "par.pl" pour exécuter des fichiers à l'intérieur d'une archive PAR : 
    % par.pl foo.par               # recherche 'main.pl' par défaut
% par.pl foo.par test.pl       # exécute script/test.pl dans foo.par
  • Même chose, avec le "parl" ou "parl.exe" autonome : 
    % parl foo.par                 # pas besoin de perl ou PAR.pm !
% parl foo.par test.pl         # idem
  • Le chargeur PAR peut s'ajouter en préfixe à un fichier PAR :
  • "-b" regroupe les modules non essentiels nécessaires à "PAR.pm" : 
    % par.pl -b -O./foo.pl foo.par # script autonome
  • "-B" regroupe les modules essentiels en plus de "-b" : 
    % parl -B -O./foo.exe foo.par  # binaire autonome

Analyse des dépendances

  • Analyse récursive des dépendances avec "scandeps.pl" : 
    % scandeps.pl sshnuke.pl
# Légende : [C]ore [X]ternal [S]ous-module [?]Pas sur CPAN
'Crypt::SSLeay'       => '0', #  X   #
'Net::HTTP'           => '0', #      #
'Crypt::SSLeay::X509' => '0', # S    # Crypt::SSLeay
'Net::HTTP::Methods'  => '0', # S    # Net::HTTP
'Compress::Zlib'      => '0', #  X   # Net::HTTP::Methods
  • Analyser une ligne de commande, lister tous les fichiers impliqués : 
    % scandeps.pl -V -e "use Dynaloader;"
...
# auto/DynaLoader/dl_findfile.al [autoload]
# auto/DynaLoader/extralibs.ld [autoload]
# auto/File/Glob/Glob.bs [data]
# auto/File/Glob/Glob.so [shared]
...

Perl Packager : "pp"

  • Combine l'analyse, la compression Zip et l'intégration du chargeur : 
    % pp -o out.exe src.pl         # .exe autonome
% out.exe                      # s'exécute partout sur le même OS
  • Regrouper des modules supplémentaires : 
    % pp -o out.exe -M CGI src.pl  # empaqueter CGI et ses dépendances, aussi
  • Empaqueter des lignes de commande : 
    % pp -o out.exe -e 'print "Salut !"'   # transforme une ligne de commande en exécutable
  • Générer des fichiers PAR au lieu d'exécutables : 
    % pp -p src.pl                 # crée 'source.par'
% pp -B -p src.pl              # inclure les modules essentiels

Comment ça marche

•
Les options en ligne de commande sont presque identiques à celles de "perlcc"
•
Supporte également les options longues style "gcc" : 
% pp --gui --verbose --output=out.exe src.pl
  • Faible surcharge initiale ; aucune surcharge à l'exécution
  • Les dépendances sont purgées de leurs POD avant l'empaquetage
  • Charge les modules directement en mémoire à la demande
  • Les bibliothèques partagées (DLL) sont extraites avec File::Temp
  • Fonctionne sur Perl 5.6.0 ou supérieur
  • Testé sur Win32 (VC++ et MinGW), FreeBSD, NetBSD, Linux, MacOSX, Cygwin, AIX, Solaris, HP-UX, Tru64...

Agrégation de plusieurs programmes

  • Une question fréquente : 
    > J'ai utilisé pp pour créer plusieurs applications autonomes qui fonctionnent
> très bien, le seul problème est que pour chaque exécutable que je crée, je
> suppose que parl.exe est d'une manière ou d'une autre intégré dans l'exécutable
> résultant.
  • La solution évidente : 
    Vous pouvez distribuer parl.exe seul, avec des fichiers .par créés
par "pp -p", et exécuter ces fichiers PAR en les associant à parl.exe.
  • Sur les plateformes qui ont "ln", il existe une meilleure solution : 
    % pp --output=a.out a.pl b.pl  # deux scripts en un !
% ln a.out b.out               # le lien symbolique fonctionne aussi
% ./a.out                      # exécute a.pl
% ./b.out                      # exécute b.pl

Packages multiplateformes

  • Bien sûr, il n'existe pas de format binaire multiplateforme
  • Les packages PAR pure-Perl sont multiplateformes par défaut
  • Cependant, les modules XS sont spécifiques à la version de Perl et à la plateforme
  • Plusieurs versions d'un module XS peuvent coexister dans un fichier PAR
  • Supposons que nous ayons besoin de "out.par" sur Win32 et Finix : 
    C:\> pp --multiarch --output=out.par src.pl
...copier src.pl et out.par sur une machine Finix...
% pp --multiarch --output=out.par src.pl
  • Maintenant, cela fonctionne sur les deux plateformes : 
    % parl out.par                 # exécute src.pl

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

% perl -MPAR=out.par -e '...' # utiliza módulos dentro de out.par

La Anatomía de un archivo PAR

  • Los módulos pueden estar ubicados en varios directorios: 
    /                      # empaquetado informal solamente
/lib/                  # ubicación estándar
/arch/                 # para construir desde blib/
/i386-freebsd/         # por ejemplo, $Config{archname}
/5.8.0/                # por ejemplo, número de versión de Perl
/5.8.0/i386-freebsd/   # combinación de los dos anteriores
  • Los scripts se almacenan en uno de los dos lugares: 
    /                      # empaquetado informal solamente
/script/               # ubicación estándar
  • Las bibliotecas compartidas pueden ser específicas de la arquitectura o de la versión de Perl: 
    /shlib/(5.8.0/)?(i386-freebsd/)?
  • Los archivos PAR pueden contener recursivamente otros archivos PAR: 
    /par/(5.8.0/)?(i386-freebsd/)?

Archivos especiales

•
MANIFEST
  • Índice de todos los archivos dentro del PAR
  • Puede ser parseado con "ExtUtils::Manifest"
•
META.yml
  • Dependencias, licencias, opciones de ejecución
  • Puede ser parseado con "YAML"
•
SIGNATURE
  • Firma digital PGP pública
  • Puede ser parseado y verificado con "Module::Signature"

Ventajas sobre perlcc, PerlApp y Perl2exe

•
Esto no es una guerra de llamas
•
Los tres mantenedores han contribuido directamente a PAR; agradecimientos
•
perlcc
  • "El código generado en este modo no está garantizado que funcione... Debe evitarse su uso en producción." (de perldoc perlcc)
  • "No garantizado que funcione" es más preciso
•
PerlApp / Perl2exe
  • Costoso: Requiere pago por cada actualización
  • No portable: Solo disponible en plataformas limitadas
  • Propietario: No puedes extender sus características ni corregir errores
  • Ofuscado: El proveedor y los ciberdelincuentes pueden ver tu código, pero tú no
  • Infle xible: No funciona con instalaciones Perl existentes

MANIFEST: Mejor visto con Mozilla

  • La URL del archivo MANIFEST dentro de "/home/autrijus/foo.par": 
    jar:file:///home/autrijus/foo.par!/MANIFEST
  • Abre en un navegador Gecko (por ejemplo, Netscape 6+) con JavaScript activado:
  • No es necesario descomprimir nada; simplemente haz clic en los archivos para verlos

META.yml: Metadatos galácticos

•
Metadatos estáticos y legibles por máquina
•
Soportado por "Module::Build", "ExtUtils::MakeMaker", "Module::Install"
  • Un ejemplo típico de "META.yml" generado por "pp" se ve así: 
    build_requires: {}
conflicts: {}
dist_name: out.par
distribution_type: par
dynamic_config: 0
generated_by: 'Perl Packager version 0.03'
license: unknown
par:
  clean: 0
  signature: ''
  verbatim: 0
  version: 0.68
  • Los ajustes de par: controlan su comportamiento de ejecución

SIGNATURE: Firmado y verificado de paquetes

•
Un mensaje PGP firmado con cálculos SHA1
•
Soportado por "Module::Signature", "CPANPLUS" y "Module::Build"
  • Un ejemplo típico de "SIGNATURE" se ve así: 
    -----BEGIN PGP SIGNED MESSAGE-----
Hash: SHA1
SHA1 8a014cd6d0f6775552a01d1e6354a69eb6826046 authors
...
-----BEGIN PGP SIGNATURE-----
...
-----END PGP SIGNATURE-----
  • Usa "pp" y "cpansign" para trabajar con firmas: 
    % pp -s -o foo.par bar.pl      # crear y firmar foo.par desde bar.pl
% cpansign -s foo.par  # firmar este archivo PAR
% cpansign -v foo.par  # verificar este archivo PAR

Servlets de Perl con Apache::PAR

•
Framework para aplicaciones web autocontenidas
  • Similar a la arquitectura WAR (Web Application Archive) de Java
  • Funciona con mod_perl 1.x o 2.x
•
Una aplicación web completa dentro de un archivo .par
  • Configuración de Apache, archivos estáticos, módulos Perl...
  • Soporte para manejadores Static, Registry y PerlRun
  • Puede cargar todos los PARs en un directorio
•
Un archivo especial adicional: "web.conf" 
Alias /myapp/cgi-perl/ ##PARFILE##/
<Location /myapp/cgi-perl>
    Options +ExecCGI
    SetHandler perl-script
    PerlHandler Apache::PAR::Registry
</Location>

Hon Dah, A-par-che!

  • Primero, genera un "hondah.par" desde una sola línea: 
    # usa el "web.conf" anterior
% pp -p -o hondah.par -e 'print "Hon Dah!\n"' \
     --add web.conf
% chmod a+x hondah.par
  • Añade esto a "httpd.conf", luego reinicia Apache: 
    <IfDefine MODPERL2>
PerlModule Apache2
</IfDefine>
PerlAddVar PARInclude /home/autrijus/hondah.par
PerlModule Apache::PAR
  • Prueba: 
    % GET http://localhost/myapp/cgi-perl/main.pl
Hon Dah!
  • ¡Una aplicación web en una sola línea que funciona!

Recuperación de bibliotecas de forma on-demand

  • Con LWP instalado, puedes usar archivos PAR remotos: 
    use PAR;
use lib 'http://aut.dyndns.org/par/DBI-latest.par';
use DBI;    # ¡siempre actualizado!
  • Los módulos ahora se mantienen en $ENV{PAR_GLOBAL_TEMP}
  • Actualizaciones automáticas con "LWP::Simple::mirror"
  • Descarga solo si ha sido modificado
  • Seguro para uso offline después de la primera vez
  • Puede usar "SIGNATURE" para prevenir suplantación de identidad DNS
•
Facilita la escalabilidad de implementaciones grandes
  • Actualizaciones desde un lugar central
  • No se necesitan instaladores

Obfuscación de código

•
También conocida como tecnologías de ocultación de fuente
  • No es criptografía
  • Ofrecida por PerlApp, Perl2Exe, Stunnix...
•
Normalmente fácil de revertir
  • Volcar el árbol de operaciones (optree) en memoria, alimentar a "B::Deparse"
  • Si solo quieres detener una búsqueda casual con "grep", el "deflate" ya funciona
•
PAR ahora soporta filtros de entrada conectables con "pp -f"
  • Incluye filtros prácticos: Bleach, PodStrip y PatchContent
  • Criptografía real usando "Crypt::*"
  • o incluso _activación de producto_ en internet
•
Alternativamente, mantén el cómputo en tu servidor y usa RPC

Acceso a archivos empaquetados

  • Para obtener el archivo anfitrión desde un programa empaquetado: 
    my $zip = PAR::par_handle($0); # un objeto Archive::Zip
my $content = $zip->contents('MANIFEST');
  • Lo mismo, pero con read_file(): 
    my $content = PAR::read_file('MANIFEST');
  • Los archivos PAR cargados se almacenan en %PAR::LibCache: 
    use PAR '/home/mylibs/*.par';
while (my ($filename, $zip) = each %PAR::LibCache) {
    print "[$filename - MANIFEST]\n";
    print $zip->contents('MANIFEST');
}

Empaquetar aplicaciones GUI

  • Las bibliotecas GUI a menudo necesitan enlazarse con bibliotecas compartidas: 
    # busca libncurses en rutas de bibliotecas y empaqueta
% pp -l ncurses curses_app.pl  # lo mismo para Tk, Wx, Gtk, Qt...
  • Usa "pp --gui" en Win32 para eliminar la ventana de consola: 
    # empaqueta 'src.pl' en un 'out.exe' sin ventana de consola (solo Win32)
% pp --gui -o out.exe src.pl
  • "No se puede localizar"
Maintén toda la estructura del archivo.

Distributions CPAN précompilées

•
L'installation des extensions XS depuis CPAN était difficile
  • Certaines plateformes ne fournissent pas de compilateur (Win32, MacOSX...)
  • Certains headers ou bibliothèques peuvent être manquants
  • PAR.pm lui-même souffrait de ces deux problèmes
  • ...mais ce n'est plus le cas. "Module::Install" à la rescousse ! 
    # même vieux Makefile.PL, avec quelques changements
use inc::Module::Install;      # était "use ExtUtils::MakeMaker;"
WriteMakefile( ... );          # identique à l'original
check_nmake();                 # s'assurer que nmake est présent
par_base('AUTRIJUS');          # votre ID CPAN ou une URL
fetch_par() unless can_cc();   # utiliser uniquement PAR précompilé si nécessaire
  • Les utilisateurs ne remarqueront rien, sauf que cela fonctionne maintenant
  • Bien sûr, vous devez toujours taper "make par" et téléverser le paquet précompilé
  • Les utilisateurs peuvent l'installer directement avec "parl -i"

Aperçu de l'implémentation de PAR.pm

•
C'est ici que commence la partie horrible
  • Des monstres, des dragons et des jabberwocks apparaissent...
  • Vous êtes sur le point d'apprendre des choses étranges sur le fonctionnement interne de Perl
•
PAR fait appel à quatre domaines de l'arcana Perl :
  • Références de code dans @INC
  • Filtrage de source en temps réel
  • Remplacement de DynaLoader::bootstrap() pour les modules XS
  • Génération d'exécutables autonomes
•
Les deux premiers ne fonctionnent que sur 5.6 ou plus tard
  • DynaLoader et %INC existent depuis la naissance de Perl 5
  • PAR nécessite 5.6, mais un port 5.005 est possible

Références de code dans @INC

•
Le 19/07/1999, Ken Fox a envoyé un patch à P5P
  • Pour _permettre l'utilisation de modules distants_ en plaçant un hook dans @INC
  • Il a été accepté pour Perl 5.6, mais n'a été documenté qu'en 5.8
  • Utilisez "perldoc -f require" pour lire les détails
  • Les coderefs dans @INC peuvent retourner un fh, ou undef pour 'passer' : 
    push @INC, sub {
    my ($coderef, $filename) = @_;  # $coderef est \&my_sub
    open my $fh, "-|", "wget ftp://example.com/$filename";
    return $fh;        # utilisation de modules distants, oui !
};
  • Perl 5.8 permet d'ouvrir un handle de fichier sur une chaîne, alors nous utilisons juste cela : 
    open my $fh, "<", \($zip->memberNamed($filename)->contents);
return $fh;
  • mais Perl 5.6 ne l'a pas, et je ne veux pas utiliser de fichiers temporaires...

Filtrage de source sans modules Filter::*

•
... des fonctionnalités non documentées à la rescousse !
  • Il a été découvert que @INC peut retourner deux valeurs
  • La première est toujours le handle de fichier
  • La seconde est une référence de code pour un filtrage ligne par ligne
•
C'est ainsi que fonctionne "Acme::use::strict::with::pride" : 
# Forcer tous les modules utilisés à utiliser strict et warnings
open my $fh, "<", $filename or return;
my @lines = ("use strict; use warnings;\n", "#line 1 \"$full\"\n");
return ($fh, sub {
    return 0 unless @lines;    
    push @lines, $_; $_ = shift @lines; return length $_;
});

Filtrage de source sans modules Filter::* (suite)

  • Nous n'avons pas de handle pour quoi que ce soit
  • Une fonctionnalité non documentée sauve la situation !
  • Nous pouvons omettre complètement la première valeur de retour : 
    # Retourner tout le contenu ligne par ligne depuis le fichier dans PAR
my @lines = split(
    /(?<=\n)/,
    $zip->memberNamed($filename)->contents
);
return (sub {
    $_ = shift(@lines);
    return length $_;
});

Remplacement de DynaLoader::bootstrap

•
Les modules XS ont des bibliothèques chargées dynamiquement
  • Ils ne peuvent pas être chargés comme partie d'un zip, alors nous les extrayons
  • Nous devons intercepter le processus de recherche de bibliothèques de DynaLoader
•
Les noms de modules sont passés à "bootstrap" pour le chargement XS
  • Pendant le processus, il appelle "dl_findfile" pour localiser le fichier
  • Nous installons donc des pré-hooks autour de ces deux fonctions
•
Notre "_bootstrap" vérifie simplement si la bibliothèque est dans les PARs
•
Si c'est le cas, elle l'extrait dans un fichier temporaire avec "File::Temp"
•
Le fichier sera automatiquement nettoyé lorsque le programme se terminera
  • Ensuite, il passe les arguments à l'"bootstrap" original
  • Enfin, notre "dl_findfile" intercepte les noms connus et retourne le fichier

Anatomie d'un exécutable PAR autonome

•
Le script par ($0) lui-même
•
Il peut être en texte brut ou dans un format exécutable natif
•
Un nombre quelconque de fichiers embarqués
  • Utilisé pour le bootstrap des diverses dépendances de PAR
  • Chaque section commence par la chaîne magique "FILE"
  • Longueur du nom en pack('N') et le nom (auto/.../)
  • Longueur en pack('N') et contenu du fichier (non compressé)
•
Un fichier PAR
•
Un fichier ZIP standard avec la chaîne magique "PK\003\004"
•
Section de fin
  • Nombre en pack('N') de la longueur totale de FILE et PAR
  • Enfin, il doit y avoir une chaîne magique de 8 octets : "\012PAR.pm\012"
