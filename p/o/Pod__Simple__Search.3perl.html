Pod::Simple::Search(3perl) Guide du programmeur Perl Pod::Simple::Search(3perl)

NOM

Pod::Simple::Search - trouver des documents POD dans des arbres de répertoires

SYNTAXE

use Pod::Simple::Search;
my $name2path = Pod::Simple::Search->new->limit_glob('LWP::*')->survey;
print "Regardez ce que j'ai trouvé : ",
  join(' ', sort keys %$name2path), "\n";
print "Docs LWP::UA = ",
  Pod::Simple::Search->new->find('LWP::UserAgent') || "?",
  "\n";

DESCRIPTION

Pod::Simple::Search est une classe que vous utilisez pour effectuer des recherches de fichiers Pod. Un objet de cette classe possède plusieurs attributs (principalement des options pour contrôler les options de recherche), et quelques méthodes pour rechercher en fonction de ces attributs.

La façon d'utiliser cette classe est de créer un nouvel objet de cette classe, de définir les options souhaitées, puis d'appeler l'une des options de recherche (probablement "survey" ou "find"). Les sections ci-dessous discutent des syntaxes pour tout cela.

CONSTRUCTEUR

Cette classe fournit un seul constructeur, appelé "new". Il ne prend aucun paramètre :

use Pod::Simple::Search;
my $search = Pod::Simple::Search->new;

ACCESSEURS

Cette classe définit plusieurs méthodes pour définir (et, occasionnellement, lire) le contenu d'un objet. À deux exceptions près (discutées à la fin de cette section), ces attributs servent uniquement à contrôler la manière dont les recherches sont effectuées.

Notez que chacune de ces méthodes renvoie $self lorsque vous les appelez comme "$self->quelque_chose(valeur)". Cela vous permet de chaîner les appels de définition d'attributs comme ceci :

my $name2path =
  Pod::Simple::Search->new
  -> inc(0) -> verbose(1) -> callback(\&blab)
  ->survey(@there);

...ce qui fonctionne exactement comme si vous aviez fait ceci :

my $search = Pod::Simple::Search->new;
$search->inc(0);
$search->verbose(1);
$search->callback(\&blab);
my $name2path = $search->survey(@there);
$search->inc( vrai-ou-faux );
Cet attribut, s'il est défini sur une valeur vraie, signifie que les recherches doivent implicitement inclure les chemins @INC de Perl. Cela prend automatiquement en compte les chemins spécifiés dans l'environnement "PERL5LIB" car ils sont ajoutés au début de @INC par l'interpréteur Perl lui-même. La valeur par défaut de cet attribut est VRAI. Si vous souhaitez rechercher uniquement des répertoires spécifiques, définissez $self->inc(0) avant d'appeler $inc->survey ou $inc->find.
$search->verbose( nombre-non-négatif );
Cet attribut, s'il est défini sur une valeur positive non nulle, fera en sorte que les recherches affichent (via "warn") des notes sur ce qu'elles font pendant leur exécution. Cette option peut être utile pour le débogage d'un module lié à pod. La valeur par défaut de cet attribut est zéro, ce qui signifie qu'aucun message "warn" n'est produit. (Définir verbose à 1 active certains messages, et le définir à 2 active encore plus de messages, c'est-à-dire rend les recherches suivantes encore plus verbeuses que ce que 1 ferait.)
$search->limit_glob( chaîne-glob-quelconque );
Cette option signifie que vous souhaitez limiter les résultats aux éléments dont les noms de pod correspondent à l'expression glob/caractère de remplacement donnée. Par exemple, vous pourriez limiter votre recherche à "LWP::*", pour rechercher uniquement les modules commençant par "LWP::*" (mais sans inclure le module "LWP" lui-même) ; ou vous pourriez limiter votre recherche à "LW*" pour voir uniquement les modules dont les noms (complets) commencent par "LW" ; ou vous pourriez rechercher "*Find*" pour rechercher tous les modules contenant "Find" quelque part dans leur nom complet. (Vous pouvez également utiliser "?" dans une expression glob ; ainsi "DB?" correspondra à "DBI" et "DBD".)
$search->callback( \&une_routine );
Cet attribut signifie que chaque fois que cette recherche trouve un fichier Pod correspondant, elle doit appeler cette routine de rappel. La routine est appelée avec deux paramètres : le nom de fichier du fichier actuel et son nom de pod. (Par exemple : "("/etc/perljunk/File/Crunk.pm", "File::Crunk")" serait dans @_.)

La valeur de retour de la routine de rappel n'est utilisée à aucune fin.

La valeur par défaut de cet attribut est fausse, ce qui signifie qu'aucun rappel n'est effectué.

$search->laborious( vrai-ou-faux );
À moins que vous ne définissiez cet attribut sur une valeur vraie, Pod::Search appliquera des heuristiques spécifiques à Perl pour trouver rapidement les PODs de modules corrects. La valeur par défaut de cet attribut est fausse. Vous n'aurez normalement pas besoin de le définir sur vrai.

Plus précisément : activer cette option désactivera les heuristiques pour ne voir que les fichiers avec des extensions de type Perl, omettre les sous-répertoires qui sont numériques mais qui ne correspondent PAS à l'ID de version de l'interpréteur Perl actuel, supprimer site_perl comme nom de hiérarchie de modules, etc.

$search->recurse( vrai-ou-faux );
À moins que vous ne définissiez cet attribut sur une valeur fausse, Pod::Search parcourra récursivement les sous-répertoires des répertoires de recherche.
$search->shadows( vrai-ou-faux );
À moins que vous ne définissiez cet attribut sur une valeur vraie, Pod::Simple::Search ne considérera que le premier fichier d'un nom de module donné lorsqu'il parcourt les répertoires spécifiés ; c'est-à-dire qu'avec cette option désactivée, si Pod::Simple::Search a déjà vu un "somepathdir/Foo/Bar.pm" lors de cette recherche, il ne vérifiera pas un "somelaterpathdir/Foo/Bar.pm" plus tard dans cette recherche, car ce fichier est simplement une "ombre". Mais si vous activez "$self->shadows(1)", ces fichiers "ombres" seront également inspectés et notés dans le hachage de retour pathname2podname.

La valeur par défaut de cet attribut est fausse ; et normalement, vous n'aurez pas besoin de l'activer.

$search->is_case_insensitive( vrai-ou-faux );
Pod::Simple::Search supposera par défaut en interne, en fonction du système de fichiers sous-jacent où le fichier de classe est trouvé, s'il est sensible à la casse ou non.

S'il est déterminé qu'il n'est pas sensible à la casse, lors de survey(), il peut ignorer les fichiers/modules pod qui correspondent par nom à ceux qu'il a déjà vus, en ignorant la casse.

Cependant, il est possible d'avoir des fichiers distincts dans des répertoires différents portant intentionnellement le même nom, différant uniquement par la casse, qui devraient être signalés. Par conséquent, vous pouvez forcer le comportement en définissant ceci sur vrai ou faux.

$search->limit_re( expression-régulière-quelconque );
Définir cet attribut (à une valeur qui est une expression régulière) signifie que vous souhaitez limiter les résultats aux éléments dont les noms de pod correspondent à l'expression régulière donnée. Normalement, cette option n'est pas nécessaire, et l'attribut "limit_glob" plus efficace est utilisé à la place.
$search->dir_prefix( valeur-chaîne-quelconque );
Définir cet attribut sur une valeur de chaîne signifie que les recherches doivent commencer dans le nom du sous-répertoire spécifié (comme "Pod" ou "File::Find", également exprimable en "File/Find"). Par exemple, l'option de recherche "$search->limit_glob("File::Find::R*")" est identique à la combinaison des options de recherche "$search->limit_re("^File::Find::R") -> dir_prefix("File::Find")".

Normalement, vous n'avez pas besoin de connaître l'option "dir_prefix", mais je l'inclus au cas où elle pourrait s'avérer utile pour quelqu'un, quelque part.

(Implémentationnellement, la recherche avec limit_glob finit par définir limit_re et généralement dir_prefix.)

$search->progress( objet-de-progression-quelconque );
Si vous définissez une valeur pour cet attribut, la valeur est supposée être un objet (probablement d'une classe que vous définissez) qui possède une méthode "reach" et une méthode "done". Ceci est destiné à signaler la progression pendant la recherche, si vous ne souhaitez pas utiliser une simple

Normalement, vous n'avez pas besoin de connaître l'option "progress", mais je l'inclus au cas où elle pourrait s'avérer utile pour quelqu'un quelque part.

Pendant qu'une recherche est en cours, les méthodes "reach" et "done" de l'objet progress sont appelées comme suit :

# Chaque fois qu'un fichier est scanné pour pod :
$progress->reach($count, "Scanning $file");   ++$count;
# Et ensuite à la fin de la recherche :
$progress->done("Noted $count Pod files total");

En interne, nous définissons souvent cela sur un objet de classe Pod::Simple::Progress. Cette classe n'est probablement pas documentée, mais vous pourriez souhaiter examiner sa source.

$name2path = $self->name2path;
Cet attribut n'est pas un paramètre de recherche, mais il est utilisé pour rapporter le résultat de la méthode "survey", comme discuté dans la section suivante.
$path2name = $self->path2name;
Cet attribut n'est pas un paramètre de recherche, mais il est utilisé pour rapporter le résultat de la méthode "survey", comme discuté dans la section suivante.

METHODES DE RECHERCHE PRINCIPALES

Une fois que vous avez défini les options souhaitées (le cas échéant), vous pouvez utiliser les méthodes suivantes pour rechercher des fichiers Pod de manière particulière.

"$search->survey( @directories )"

La méthode "survey" recherche des documents POD dans un ensemble donné de fichiers et/ou de répertoires. Elle effectue la recherche conformément aux diverses options définies par les accesseurs ci-dessus. (Par exemple, si l'attribut "inc" est activé, comme c'est le cas par défaut, les répertoires @INC de Perl sont implicitement ajoutés à la liste des répertoires (le cas échéant) que vous spécifiez.)

La valeur de retour de "survey" est composée de deux hachages :

"name2path"
Un hachage qui mappe du nom de pod au spécificateur de fichier (comme "Stuff::Thing" => "/whatever/plib/Stuff/Thing.pm")
"path2name"
Un hachage qui mappe du spécificateur de fichier Pod à son nom de pod (comme "/whatever/plib/Stuff/Thing.pm" => "Stuff::Thing")

En plus de sauvegarder ces hachages comme attributs hashref "name2path" et "path2name", l'appel de cette fonction retourne également ces hashrefs. En contexte de liste, la valeur de retour de "$search->survey" est la liste "(\%name2path, \%path2name)". En contexte scalaire, la valeur de retour est "\%name2path". Ou vous pouvez simplement l'appeler en contexte vide.

Indépendamment du contexte d'appel, l'appel de "survey" sauvegarde ses résultats dans ses attributs "name2path" et "path2name".

Par exemple, lors de la recherche dans $HOME/perl5lib, le fichier $HOME/perl5lib/MyModule.pm obtiendrait le nom POD MyModule, tandis que $HOME/perl5lib/Myclass/Subclass.pm serait Myclass::Subclass. Les informations de nom peuvent être utilisées pour les traducteurs POD.

Seuls les fichiers texte contenant au moins une commande POD valide sont trouvés.

En mode verbeux, un avertissement est imprimé si des ombres sont trouvées (c'est-à-dire plus d'un fichier POD avec le même nom POD trouvé, par exemple CPAN.pm dans différents répertoires). Cela indique généralement des occurrences dupliquées de modules dans le chemin de recherche @INC, ce qui est occasionnellement involontaire (mais est souvent simplement le cas d'un répertoire de chemin d'un utilisateur ayant une version plus récente que les répertoires de chemin généraux du système en général).

Les options pour cet argument sont une liste de répertoires qui sont recherchés récursivement, ou de fichiers. (Habituellement, vous ne spécifieriez pas de fichiers, juste des répertoires.) Ou vous pouvez simplement spécifier une liste vide, comme dans $name2path ; avec l'option "inc" activée, comme c'est le cas par défaut.

Les noms POD des fichiers sont les noms de base simples avec toute extension de type Perl (.pm, .pl, .pod) retirée, et les séparateurs de chemin remplacés par des "::".

Appeler Pod::Simple::Search->search(...) est un raccourci pour Pod::Simple::Search->new->search(...). C'est-à-dire qu'un objet jetable avec des valeurs d'attribut par défaut est utilisé.

"$search->simplify_name( $str )"

La méthode simplify_name est équivalente à basename, mais retire également les extensions de type Perl (.pm, .pl, .pod) et les extensions comme .bat, .cmd sous Win32 et OS/2, ou .com sous VMS, respectivement.

"$search->find( $pod )"

"$search->find( $pod, @search_dirs )"

Retourne l'emplacement d'un fichier Pod, étant donné un nom de Pod/module/script (comme "Foo::Bar" ou "perlvar" ou "perldoc"), et une idée des fichiers/répertoires à rechercher. Il recherche conformément aux diverses options définies par les accessseurs ci-dessus. (Par exemple, si l'attribut "inc" est activé, comme c'est le cas par défaut, les répertoires @INC de Perl sont implicitement ajoutés à la liste des répertoires (le cas échéant) que vous spécifiez.)

Cela retourne le chemin complet de la première occurrence du fichier. Les noms de package (par ex. 'A::B') sont automatiquement convertis en noms de répertoire dans le répertoire sélectionné. De plus, '.pm', '.pl' et '.pod' sont automatiquement ajoutés à la recherche selon les besoins. (Ainsi, par exemple, sous Unix, "A::B" est converti en "somedir/A/B.pm", "somedir/A/B.pod", ou "somedir/A/B.pl", selon le cas.)

Si aucun fichier Pod de ce type n'est trouvé, cette méthode retourne undef.

Si l'un des répertoires de recherche donnés contient un sous-répertoire pod/, alors il est recherché. (C'est ainsi que nous trouvons perlfunc, par exemple, qui se trouve généralement dans pod/perlfunc dans la plupart des distributions Perl.)

Les attributs "verbose" et "inc" influencent le comportement de cette recherche ; notamment, "inc", s'il est vrai, ajoute @INC et aussi $Config::Config{'scriptdir'} à la liste des répertoires à rechercher.

Il est courant de simplement dire "$filename = Pod::Simple::Search-> new ->find("perlvar")" afin que seuls les répertoires @INC (bien, et scriptdir) soient recherchés. (Cela se produit parce que l'attribut "inc" est vrai par défaut.)

Appeler Pod::Simple::Search->find(...) est un raccourci pour Pod::Simple::Search->new->find(...). C'est-à-dire qu'un objet jetable avec des valeurs d'attribut par défaut est utilisé.

"$self->contains_pod( $file )"

Retourne vrai si le nom de fichier fourni (pas le module POD) contient une documentation Pod.

Pod::Simple::Search(3pm)

Pod::Simple::Search — Recherche dans les fichiers Pod

NOM

Pod::Simple::Search — Recherche dans les fichiers Pod

SYNOPSIS

use Pod::Simple::Search;

my $searcher = Pod::Simple::Search->new( @paths );
my @files = $searcher->run();
# ou
my @files = Pod::Simple::Search::run( @paths );

DESCRIPTION

Pod::Simple::Search est une classe pour trouver des fichiers Pod. Il est destiné à être utilisé par des programmes qui doivent trouver des fichiers Pod pour les traiter, tels que les scripts qui génèrent de la documentation HTML à partir de Pod.

Il est conçu pour être aussi simple que possible. S'il est trop simple pour vous, vous devriez jeter un coup d'œil à Pod::Find ou à Pod::Tree.

Le principal avantage de cette classe est qu'elle ne se soucie pas des fichiers non Pod. Elle les ignore silencieusement. Elle tente de trouver des fichiers Pod dans les chemins que vous lui donnez, et elle renvoie une liste de noms de fichiers qui correspondent aux critères de recherche.

MÉTHODES

Pod::Simple::Search::search( @paths )
Ceci est une méthode de classe. Elle prend une liste de chemins de répertoires et/ou de fichiers à rechercher. Elle renvoie une liste de noms de fichiers qui contiennent du Pod.
Pod::Simple::Search::run( @paths )
Ceci est une autre méthode de classe. Elle est identique à search(). Elle est fournie pour la cohérence avec d'autres modules d'interface Pod.

MÉTHODES DE RECHERCHE AIN

Le module Pod::Simple fournit des méthodes pour examiner le contenu des fichiers Pod. Ce module ne fait que trouver les fichiers.
