Pod::Find(3) Documentation Perl fournie par l'utilisateur Pod::Find(3)

NOM

Pod::Find - trouver des documents POD dans des arborescences de répertoires

SYNOPSIS

use Pod::Find qw(pod_find simplify_name);
my %pods = pod_find({ -verbose => 1, -inc => 1 });
foreach(keys %pods) {
   print "trouvé POD de bibliothèque `$pods{$_}' dans $_\n";
}
print "nom_pod=",simplify_name('a/b/c/mymodule.pod'),"\n";
$location = pod_where( { -inc => 1 }, "Pod::Find" );

DESCRIPTION

NOTE: Ce module est considéré comme obsolète ; les versions modernes de Perl (5.31.1 et supérieures) vont supprimer Pod-Parser du noyau et utiliser Pod::Simple pour toutes les choses liées à POD.

Pod::Find fournit un ensemble de fonctions pour localiser des fichiers POD. Notez qu'aucune fonction n'est exportée par défaut pour éviter la pollution de votre espace de noms, alors assurez-vous de les spécifier dans l'instruction use si vous en avez besoin :

use Pod::Find qw(pod_find);

À partir de cette version, les répertoires typiques de SCM (gestion de configuration logicielle) sont ignorés. Ce sont : RCS, CVS, SCCS, .svn, .hg, .git, .sync

"pod_find( { %opts } , @directories )"

La fonction pod_find recherche les documents POD dans un ensemble donné de fichiers et/ou de répertoires. Elle renvoie une table avec les noms de fichiers comme clés et le nom du POD comme valeur. Le nom du POD est dérivé du nom du fichier et de sa position dans l'arborescence des répertoires.

Par exemple, lors de la recherche dans $HOME/perl5lib, le fichier $HOME/perl5lib/MyModule.pm recevrait le nom de POD MyModule, tandis que $HOME/perl5lib/Myclass/Subclass.pm serait Myclass::Subclass. Les informations de nom peuvent être utilisées pour les traducteurs POD.

Seuls les fichiers texte contenant au moins une commande POD valide sont trouvés.

Un avertissement est imprimé si plus d'un fichier POD avec le même nom de POD est trouvé, par exemple CPAN.pm dans différents répertoires. Cela indique généralement des occurrences dupliquées de modules dans le chemin de recherche @INC.

OPTIONS Le premier argument de pod_find peut être une référence de table avec des options. Les autres sont soit des répertoires qui sont recherchés récursivement, soit des fichiers. Les noms POD des fichiers sont les noms de base bruts avec toute extension de type Perl (.pm, .pl, .pod) supprimée.

"-verbose => 1"
Imprimer les informations de progression pendant le balayage.
"-perl => 1"
Appliquer des heuristiques spécifiques à Perl pour trouver les POD corrects. Cela inclut la suppression des extensions de type Perl, l'omission des sous-répertoires qui sont numériques mais ne correspondent *pas* à l'ID de version de l'interpréteur Perl actuel, la suppression de site_perl en tant que nom de hiérarchie de module, etc.
"-script => 1"
Rechercher les POD dans le répertoire des scripts d'installation de l'interpréteur Perl actuel. Ceci est tiré du module Config local.
"-inc => 1"
Rechercher les POD dans les chemins @INC de l'interpréteur Perl actuel. Cela prend automatiquement en compte les chemins spécifiés dans l'environnement "PERL5LIB" car cela est inclus dans @INC par l'interpréteur Perl lui-même.

simplify_name( $str )

La fonction simplify_name est équivalente à basename, mais supprime également les extensions de type Perl (.pm, .pl, .pod) et les extensions comme .bat, .cmd sous Win32 et OS/2, ou .com sous VMS, respectivement.

"pod_where( { %opts }, $pod )"

Renvoie l'emplacement d'un document pod étant donné un répertoire de recherche et un nom de module (par exemple "File::Find") ou de script (par exemple "perldoc").

Options :

"-inc => 1"
Rechercher dans @INC pour le pod et également dans le "scriptdir" défini dans le module Config.
"-dirs => [ $dir1, $dir2, ... ]"
Référence à un tableau de répertoires de recherche. Ceux-ci sont recherchés dans l'ordre avant de chercher dans @INC (si -inc). Le répertoire courant est utilisé si aucun n'est spécifié.
"-verbose => 1"
Lister les répertoires au fur et à mesure de leur recherche.

Renvoie le chemin complet de la première occurrence du fichier. Les noms de paquets (par exemple 'A::B') sont automatiquement convertis en noms de répertoires dans le répertoire sélectionné. (par exemple sous Unix 'A::B' est converti en 'A/B'). De plus, '.pm', '.pl' et '.pod' sont automatiquement ajoutés à la recherche si nécessaire.

Un sous-répertoire pod/ est également vérifié s'il existe dans l'un des répertoires de recherche donnés. Cela garantit que par exemple perlfunc est trouvé.

On suppose que si un nom de module est fourni, ce nom correspond au nom du fichier. Les POD ne sont pas ouverts pour vérifier l'entrée 'NAME'.

Une vérification est effectuée pour s'assurer que le fichier trouvé contient bien de la documentation pod.

"contains_pod( $file , $verbose )"

Renvoie vrai si le nom de fichier fourni (pas le module POD) contient des informations pod.
