NAME

POE::Component::IKC::Server - Serveur de communication inter-noyaux POE

SYNOPSIS

use POE;
use POE::Component::IKC::Server;
POE::Component::IKC::Server->spawn(
    ip=>$ip, 
    port=>$port,
    name=>'Server');
...
$poe_kernel->run();

DESCRIPTION

Ce module implémente un serveur de communication inter-noyaux POE. Un serveur IKC écoute les connexions entrantes des clients IKC. Lorsqu'un client se connecte, il négocie certains paramètres de connexion. Après cela, le serveur POE et le client sont pratiquement identiques.

FONCTIONS EXPORTÉES

"create_ikc_server"

Obsolète. Utilisez "spawn" dans POE::Component::IKC::Server.

MÉTHODES DE CLASSE

"spawn"

Cette méthode lance tout le travail pour construire le serveur IKC. Les paramètres sont :

"ip"
Adresse à écouter. Peut être une adresse quad-pointée ('127.0.0.1') ou un nom d'hôte ('foo.pied.nu'). La valeur par défaut est '0.0.0.0', c'est-à-dire INADDR_ANY.
"port"
Port à écouter. Peut être numérique (80) ou un service ('http'). S'il n'est pas défini, le port par défaut est 603. Si vous définissez le port sur 0, un port aléatoire sera choisi et "spawn" renverra le numéro du port. 
my $port = POE::Component::IKC::Server->spawn( port => 0 );
warn "Écoute sur le port $port";
"unix"
Chemin du socket Unix à écouter. Notez que ce chemin est déconnecté avant de tenter le socket ! Attention.
"name"
Nom du noyau local. C'est ainsi que nous nous annonçons aux autres noyaux. C'est un alias de noyau. Ce paramètre est temporaire, en attendant l'ajout de vrais noms dans le noyau POE. Ce nom et tous les alias seront enregistrés auprès du répartiteur afin que vous puissiez publier dessus comme s'ils étaient distants.
"aliases"
Tableau d'alias supplémentaires pour ce noyau. Étonnant, étonnant !
"verbose"
Affiche des informations supplémentaires sur STDERR si vrai. Cela permet de voir ce qui se passe et potentiellement de localiser les problèmes et autres.
"processes"
Active le code du serveur pré-fork. Si une valeur positive est définie, IKC va forker des processus -1 fils. Les demandes IKC ne seront servies que par les fils. Par défaut, c'est 1 (c'est-à-dire aucun processus forké).
"babysit"
Le temps en secondes entre les invocations de l'événement de gardien.
"connections"
Nombre de connexions qu'un fils acceptera avant de se terminer. Actuellement, les connexions sont traitées simultanément, car il n'y a aucun moyen de savoir quand une requête est terminée. La valeur par défaut est 1 (c'est-à-dire une connexion par fils).
"concurrency"
Nombre de connexions simultanées autorisées. Par défaut, c'est 0 (illimité). Notez qu'il s'agit par instance de IKC::Server ; si vous avez plusieurs façons de vous connecter au même serveur IKC (par exemple, port TCP/IP et pipe Unix), ils ne partageront pas le nombre de connexions simultanées.
"protocol"
Quel protocole de négociation IKC utiliser. Le protocole original (IKC) avait une poignée de main synchrone lente. Le nouveau protocole (IKC0) envoie toutes les informations de poignée de main en une seule fois. IKC0 peut se dégrader en IKC si le client et le serveur ne correspondent pas.

Par défaut, c'est IKC0.

"on_error"
Une référence à un code qui est appelé pour toutes les erreurs. Vous pouvez l'utiliser pour surveiller les problèmes lors du fork de processus ou de l'ouverture du socket. Les paramètres sont "$operation, $errnum and $errstr", qui correspondent à l'événement FailureEvent de POE::Wheel::SocketFactory, voir ce module.

Cependant, le mécanisme le plus puissant pour détecter les erreurs est offert par POE::Component::IKC::Responder. Notez également que le code s'exécutera depuis une session IKC, pas la vôtre. Cela signifie que des choses comme "$poe_kernel"->delay_set() ne feront pas ce que vous attendez.

"POE::Component::IKC::Server::spawn" renvoie "undef" sauf si vous spécifiez un "port"=0, auquel cas "spawn" renvoie le port qui a été choisi.

ÉVÉNEMENTS

shutdown

Cet événement fait que le serveur ferme son socket, nettoie ses affaires et part. Normalement, il n'est publié que par POE::Responder.

BUGS

Le pré-forking est un peu un hack. En particulier, vous devez vous assurer que vos sessions permettent aux fils de se terminer. Cela signifie que si vous avez une boucle "delay()" ou une boucle d'événements, les fils ne se termineront pas. Une fois que POE aura des événements de multidiffusion, je changerai ce comportement.
