NOM

POE::Wheel::FollowTail - suivre la fin d'un fichier qui s'agrandit constamment

SYNOPIS

#!perl
use POE qw(Wheel::FollowTail);
POE::Session->create(
  inline_states => {
    _start => sub {
      $_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
        Filename => "/var/log/system.log",
        InputEvent => "got_log_line",
        ResetEvent => "got_log_rollover",
      );
    },
    got_log_line => sub {
      print "Log: $_[ARG0]\n";
    },
    got_log_rollover => sub {
      print "Log permuté.\n";
    },
  }
);
POE::Kernel->run();
exit;

DESCRIPTION

POE::Wheel::FollowTail surveille les nouvelles données à la fin d'un fichier et déclenche de nouveaux événements lorsque des changements se produisent dans le fichier. Son paramètre "Filter" définit comment analyser les données d'un fichier surveillé. Chaque nouvel élément est envoyé à la session créatrice sous forme d'événement "InputEvent". Le changement de permutation de fichier déclenche un événement "ResetEvent".

POE::Wheel::FollowTail ne lit qu'un seul fichier, il n'implémente donc pas de méthode put().

MÉTHODES PUBLIQUES

new

new() retourne un nouvel objet POE::Wheel::FollowTail. Tant que cet objet existera, il déclenchera des événements lorsque l'état correspondant du fichier sera modifié.

new() accepte un petit ensemble de paramètres nommés :

Driver

Le paramètre optionnel "Driver" spécifie quel driver utiliser lors de la lecture du fichier surveillé. S'il n'est pas spécifié, POE::Wheel::FollowTail utilisera POE::Driver::SysRW. C'est presque toujours le bon choix.

Filter

"Filter" est un paramètre optionnel qui spécifie comment analyser les données du fichier surveillé. Par défaut, POE::Wheel::FollowTail utilisera POE::Filter::Line pour analyser les fichiers comme du texte brut, séparé par des lignes.

$_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
  Filename => "/var/log/snort/alert",
  Filter => POE::Filter::Snort->new(),
  InputEvent => "got_snort_alert",
);

PollInterval

POE::Wheel::FollowTail doit vérifier périodiquement les nouvelles données dans le fichier surveillé. "PollInterval" spécifie le nombre de secondes à attendre entre chaque vérification. Les applications qui doivent vérifier une fois par seconde peuvent omettre "PollInterval", car la valeur par défaut est de 1.

Des intervalles de polling plus longs peuvent être utilisés pour réduire la surcharge de polling sur les fichiers à faible taux de mise à jour.

$_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
  ...,
  PollInterval => 10,
);

Seek

S'il est spécifié, "Seek" demande à POE::Wheel::FollowTail de se repositionner à un endroit spécifique dans le fichier surveillé avant de commencer à lire à partir de celui-ci. Une valeur positive de "Seek" est interprétée comme le nombre d'octets à rechercher depuis le début du fichier. Une valeur négative de "Seek" se comporte comme un index négatif dans un tableau. Une valeur de zéro pour "Seek" commence la lecture depuis le début du fichier.

Il faut être prudent lors de l'utilisation de "Seek", car il est très facile de se positionner au milieu d'un enregistrement. En cas de doute, et lors du démarrage depuis la fin du fichier, omettez complètement "Seek". POE::Wheel::FollowTail recherchera 4 kilo-octets avant la fin du fichier, puis analysera et rejettera tous les enregistrements jusqu'à la fin du fichier. Tant que les enregistrements du fichier sont inférieurs à 4 kilo-octets, cela garantira que le premier enregistrement renvoyé sera complet.

"Seek" peut également être utilisé avec la méthode tell() de la roue pour restaurer la position du fichier après un redémarrage du programme. Sauvegardez la valeur de tell() avant de quitter, puis rechargez et "Seek" à cette valeur au démarrage de chaque redémarrage.

SeekBack

"SeekBack" se comporte comme l'inverse de "Seek". Une valeur positive agit comme une valeur négative de "Seek". Une valeur négative agit comme une valeur positive de "Seek". Une valeur de zéro pour "SeekBack" demande à POE::Wheel::FollowTail de commencer depuis la fin du fichier.

"Seek" et "SeekBack" s'excluent mutuellement. Voir "Seek" pour les avertissements, les techniques et une explication de la magie qui se produit lorsque "Seek" et "SeekBack" ne sont pas spécifiés.

Handle

POE::Wheel::FollowTail peut suivre un fichier qui a déjà été ouvert avec "Handle". Cependant, il ne peut pas suivre les permutations de fichiers ainsi, car il ne pourra pas rouvrir le fichier une fois qu'il aura été permuté. Les applications qui doivent suivre les permutations doivent utiliser "Filename" à la place.

"Handle" est utile pour les fichiers qui ne seront jamais permutés, ou pour les périphériques qui nécessitent une configuration en dehors de la portée de POE::Wheel::FollowTail.

"Handle" et "Filename" s'excluent mutuellement. L'un d'eux est requis, même s'il n'est pas présent.

Filename

Spécifie le "Filename" à suivre. POE::Wheel::FollowTail attendra que le fichier existe s'il ne le trouve pas. La roue rouvrira également le fichier s'il disparaît, comme lorsqu'il a été permuté ou que le fichier a été corrompu. Dans le cas d'une permutation, POE::Wheel::FollowTail déclenchera également un événement "ResetEvent", s'il a été demandé.

"Handle" et "Filename" s'excluent mutuellement. L'un d'eux est requis, même s'il n'est pas présent.

Voir l'exemple dans "SYNOPIS".

IdleEvent

"IdleEvent" est un événement optionnel. S'il est spécifié, il sera déclenché chaque fois que POE::Wheel::FollowTail vérifie l'activité mais ne trouve rien. Il a été ajouté dans POE 1.362 comme moyen de faire avancer certains programmes de test sans avoir à attendre de manière conservatrice de longues périodes.

"IdleEvent" est décrit dans "PUBLIC EVENTS".

InputEvent

"InputEvent" est un paramètre obligatoire et spécifie l'événement à déclencher lorsque de nouvelles données arrivent dans le fichier surveillé. "InputEvent" est décrit en détail dans "PUBLIC EVENTS".

ResetEvent

"ResetEvent" est un événement optionnel. Il spécifie le nom de l'événement qui indique la permutation ou la réinitialisation d'un fichier. Veuillez voir "PUBLIC EVENTS" pour plus de détails.

ErrorEvent

POE::Wheel::FollowTail peut déclencher des événements optionnels "ErrorEvent" lorsqu'il rencontre un problème. Les données accompagnant cet événement sont expliquées dans "PUBLIC EVENTS".

event

event() permet à une session de changer les événements déclenchés par une roue sans détruire et reconstruire l'objet. Il accepte un ou plusieurs des événements mentionnés dans "PUBLIC EVENTS". Les noms d'événements indéfinis désactivent ces événements.

Arrêter de surveiller les permutations de logs :

sub some_event_handler {
  $_[HEAP]{tailor}->event( ResetEvent => undef );
}

Les événements sont décrits plus en détail dans "PUBLIC EVENTS".

ID

La méthode ID() retourne l'identifiant unique de la roue. Il est utile pour stocker la roue dans un hash. Tous les événements de POE::Wheel doivent être accompagnés d'un identifiant de roue, ce qui permet de référencer la roue dans ses gestionnaires d'événements.

sub setup_tailor {
  my $wheel = POE::Wheel::FollowTail->new(... incomplete ...);
  $_[HEAP]{tailors}{$wheel->ID} = $wheel;
}

Voir l'exemple dans "ErrorEvent" pour un gestionnaire qui retrouvera cette roue.

NAME

POE::Wheel::FollowTail - POE wheel for watching files for changes

SYNOPSIS

    use POE::Wheel::FollowTail;

    # In your session's main handler:
    sub POE::Session::my_session_name::event_handler {
      my ($heap, $input) = @_[HEAP, ARG0];

      # ... process input ...
    }

    # When creating the wheel:
    $heap->{tailor} = POE::Wheel::FollowTail->new(
      Filename => '/path/to/some/file',
      InputEvent => 'event_handler', # The name of the handler in this session
      # Other options ...
    );

DESCRIPTION

POE::Wheel::FollowTail is a POE wheel that will watch a file for changes. It's like the command-line tail command, but it emits POE events when data is found.

It can be configured to watch a file by name, or to follow an already-opened file descriptor.

It also has support for files that are rotated, though this requires that the wheel be watching the file by name.

PUBLIC METHODS

new

A POE::Wheel::FollowTail object is created with POE::Wheel::FollowTail->new(). It takes the following parameters:

  • Filename: The name of the file to watch.
  • Handle: An already-opened file handle. If this is specified, Filename will be ignored.
  • InputEvent: The name of the event that will be emitted when new data is read from the file. (Default: "InputEvent")
  • IdleEvent: The name of the event that will be emitted when no data is read from the file for a period of time. (Default: "IdleEvent")
  • ResetEvent: The name of the event that will be emitted when the file is detected to have been reset. (Default: "ResetEvent")
  • ErrorEvent: The name of the event that will be emitted when an error occurs. (Default: "ErrorEvent")
  • Filter: A filter object, which is expected to have a filter() method. This method will be called with the data read from the file, and its return value will be emitted in the InputEvent.
  • Seek: A file offset. The wheel will start reading the file from this offset.

tell()

tell() returns the current position for the file being watched by POE::Wheel::FollowTail. It may be useful for saving the position program termination. new()'s "Seek" parameter may be used to resume watching the file where tell() left off.

sub handle_shutdown {
  # Not robust.  Do better in production.
  open my $save, ">", "position.save" or die $!;
  print $save $_[HEAP]{tailor}->tell(), "\n";
  close $save;
}
sub handle_startup {
  open my $save, "<", "position.save" or die $!;
  chomp(my $seek = <$save>);
  $_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
    ...,
    Seek => $seek,
  );
}

PUBLIC EVENTS

POE::Wheel::FollowTail emits a small number of events.

IdleEvent

"IdleEvent" specifies the name of an event to be fired when POE::Wheel::FollowTail doesn't detect activity on the watched file.

$_[ARG0] contains the ID of the POE::Wheel::FollowTail object that fired the event.

InputEvent

"InputEvent" sets the name of the event to emit when new data arrives into the tailed file. The event will be accompanied by two parameters:

$_[ARG0] contains the data that was read from the file, after being parsed by the current "Filter".

$_[ARG1] contains the wheel's ID, which may be used as a key into a data structure tracking multiple wheels. No assumption should be made about the nature or format of this ID, as it may change at any time. Therefore, track your wheels in a hash.

See the "SYNOPSIS" for an example.

ResetEvent

"ResetEvent" names the event to be emitted whenever the wheel detects that the followed file has been reset. It's only available when watching files by name, as POE::Wheel::FollowTail must reopen the file after it has been reset.

"ResetEvent" comes with only one parameter, $_[ARG0], which contains the wheel's ID. See "InputEvent" for some notes about what may be done with wheel IDs.

See the "SYNOPSIS" for an example.

ErrorEvent

"ErrorEvent" names the event emitted when POE::Wheel::FollowTail encounters a problem. Every "ErrorEvent" comes with four parameters that describe the error and its situation:

$_[ARG0] describes the operation that failed. This is usually "read", since POE::Wheel::FollowTail spends most of its time reading from a file.

$_[ARG1] and $_[ARG2] contain the numeric and stringified values of $!, respectively. They will never contain EAGAIN (or its local equivalent) since POE::Wheel::FollowTail handles that error itself.

$_[ARG3] contains the wheel's ID, which has been discussed in "InputEvent".

This error handler logs a message to STDERR and then shuts down the wheel. It assumes that the session is watching multiple files.

sub handle_tail_error {
  my ($operation, $errnum, $errstr, $wheel_id) = @_[ARG0..ARG3];
  warn "Wheel $wheel_id: $operation error $errnum: $errstr\n";
  delete $_[HEAP]{tailors}{$wheel_id};
}

BUGS

This wheel can't tail pipes and consoles on some operating systems.

POE::Wheel::FollowTail generally reads ahead of the data it returns, so the tell() position may be later in the file than the data an application has already received.

NOM

POE::Wheel::FollowTail - Roue POE pour surveiller les fichiers pour les changements

SYNTAXE

    use POE::Wheel::FollowTail;

    # Dans le gestionnaire principal de votre session :
    sub POE::Session::my_session_name::event_handler {
      my ($heap, $input) = @_[HEAP, ARG0];

      # ... traiter l'entrée ...
    }

    # Lors de la création de la roue :
    $heap->{tailor} = POE::Wheel::FollowTail->new(
      Filename => '/chemin/vers/un/fichier',
      InputEvent => 'event_handler', # Le nom du gestionnaire dans cette session
      # Autres options ...
    );

DESCRIPTION

POE::Wheel::FollowTail est une roue POE qui surveillera un fichier pour détecter les changements. C'est comme la commande tail en ligne de commande, mais elle émet des événements POE lorsque des données sont trouvées.

Elle peut être configurée pour surveiller un fichier par son nom, ou pour suivre un descripteur de fichier déjà ouvert.

Elle prend également en charge les fichiers qui sont pivotés, bien que cela nécessite que la roue surveille le fichier par son nom.

MÉTHODES PUBLIQUES

new

Un objet POE::Wheel::FollowTail est créé avec POE::Wheel::FollowTail->new(). Il prend les paramètres suivants :

  • Filename: Le nom du fichier à surveiller.
  • Handle: Une poignée de fichier déjà ouverte. Si celle-ci est spécifiée, Filename sera ignoré.
  • InputEvent: Le nom de l'événement qui sera émis lorsque de nouvelles données seront lues du fichier. (Défaut : "InputEvent")
  • IdleEvent: Le nom de l'événement qui sera émis lorsqu'aucune donnée ne sera lue du fichier pendant un certain temps. (Défaut : "IdleEvent")
  • ResetEvent: Le nom de l'événement qui sera émis lorsque le fichier sera détecté comme ayant été réinitialisé. (Défaut : "ResetEvent")
  • ErrorEvent: Le nom de l'événement qui sera émis lorsqu'une erreur se produira. (Défaut : "ErrorEvent")
  • Filter: Un objet filtre, qui est censé avoir une méthode filter(). Cette méthode sera appelée avec les données lues du fichier, et sa valeur de retour sera émise dans l' InputEvent.
  • Seek: Un décalage de fichier. La roue commencera à lire le fichier à partir de ce décalage.

tell()

tell() renvoie la position actuelle du fichier surveillé par POE::Wheel::FollowTail. Cela peut être utile pour sauvegarder la position à la terminaison du programme. Le paramètre "Seek" de new() peut être utilisé pour reprendre la surveillance du fichier là où tell() s'est arrêté.

sub handle_shutdown {
  # Pas robuste. Faites mieux en production.
  open my $save, ">", "position.save" or die $!;
  print $save $_[HEAP]{tailor}->tell(), "\n";
  close $save;
}
sub handle_startup {
  open my $save, "<", "position.save" or die $!;
  chomp(my $seek = <$save>);
  $_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
    ...,
    Seek => $seek,
  );
}

ÉVÉNEMENTS PUBLICS

POE::Wheel::FollowTail émet un petit nombre d'événements.

IdleEvent

"IdleEvent" spécifie le nom d'un événement à déclencher lorsque POE::Wheel::FollowTail ne détecte aucune activité sur le fichier surveillé.

$_[ARG0] contient l'identifiant de l'objet POE::Wheel::FollowTail qui a déclenché l'événement.

InputEvent

"InputEvent" définit le nom de l'événement à émettre lorsque de nouvelles données arrivent dans le fichier suivi. L'événement sera accompagné de deux paramètres :

$_[ARG0] contient les données qui ont été lues du fichier, après avoir été analysées par le "Filter" actuel.

$_[ARG1] contient l'identifiant de la roue, qui peut être utilisé comme clé dans une structure de données suivant plusieurs roues. Aucune supposition ne doit être faite quant à la nature ou au format de cet identifiant, car il peut changer à tout moment. Par conséquent, suivez vos roues dans une table de hachage.

Voir le "SYNTAXE" pour un exemple.

ResetEvent

"ResetEvent" nomme l'événement à émettre chaque fois que la roue détecte que le fichier suivi a été réinitialisé. Il n'est disponible que lorsque l'on surveille des fichiers par nom, car POE::Wheel::FollowTail doit rouvrir le fichier après sa réinitialisation.

"ResetEvent" ne comporte qu'un seul paramètre, $_[ARG0], qui contient l'identifiant de la roue. Voir "InputEvent" pour quelques notes sur ce qui peut être fait avec les identifiants de roue.

Voir le "SYNTAXE" pour un exemple.

ErrorEvent

"ErrorEvent" nomme l'événement émis lorsque POE::Wheel::FollowTail rencontre un problème. Chaque "ErrorEvent" est accompagné de quatre paramètres qui décrivent l'erreur et sa situation :

$_[ARG0] décrit l'opération qui a échoué. Il s'agit généralement de "read", car POE::Wheel::FollowTail passe la plupart de son temps à lire dans un fichier.

$_[ARG1] et $_[ARG2] contiennent les valeurs numérique et sous forme de chaîne de $!, respectivement. Ils ne contiendront jamais EAGAIN (ou son équivalent local) car POE::Wheel::FollowTail gère lui-même cette erreur.

$_[ARG3] contient l'identifiant de la roue, qui a été discuté dans "InputEvent".

Ce gestionnaire d'erreurs enregistre un message dans STDERR puis arrête la roue. Il suppose que la session surveille plusieurs fichiers.

sub handle_tail_error {
  my ($operation, $errnum, $errstr, $wheel_id) = @_[ARG0..ARG3];
  warn "Roue $wheel_id: erreur d'opération $errnum : $errstr\n";
  delete $_[HEAP]{tailors}{$wheel_id};
}

BOGUES

Cette roue ne peut pas suivre les tubes et les consoles sur certains systèmes d'exploitation.

POE::Wheel::FollowTail lit généralement en avance par rapport aux données qu'il renvoie, de sorte que la position de tell() peut être plus loin dans le fichier que les données qu'une application a déjà reçues.
