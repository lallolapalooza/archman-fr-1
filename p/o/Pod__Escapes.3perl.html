Pod::Escapes(3perl) Guide de référence du programmeur Perl Pod::Escapes(3perl)

NOM

Pod::Escapes - pour résoudre les séquences E<...> de Pod

SYNOPIS

use Pod::Escapes qw(e2char);
... la la la, analyse de POD, la la la...
$text = e2char($e_node->label);
unless(defined $text) {
  print "Séquence E inconnue \"", $e_node->label, "\"!";
}

DESCRIPTION

Ce module fournit des éléments utiles pour décoder les séquences E<...> de Pod. Vraisemblablement, il ne devrait être utilisé que par des analyseurs et/ou des formateurs de Pod.

Par défaut, Pod::Escapes n'exporte aucun de ses symboles. Mais vous pouvez demander que n'importe lequel soit exporté. Soit demandez-les individuellement, comme avec "use Pod::Escapes qw(symbolname symbolname2...);", soit vous pouvez faire "use Pod::Escapes qw(:ALL);" pour obtenir tous les symboles exportables.

GOODIES

e2char($e_content)
Donnée un nom ou un nombre qui peut apparaître dans une séquence "E<name_or_num>", ceci retourne la chaîne qu'il représente. Par exemple, e2char('sol'), e2char('47'), e2char('0x2F'), et e2char('057') retournent tous "/", car "E<sol>", "E<47>", "E<0x2f>", et "E<057>", signifient tous "/". Si le nom n'a pas de valeur connue (comme pour un nom "qacute") ou est syntaxiquement invalide (comme pour un nom "1/4"), ceci retourne undef.
e2charnum($e_content)
Donnée un nom ou un nombre qui peut apparaître dans une séquence "E<name_or_num>", ceci retourne le nombre du caractère Unicode qu'il représente. Par exemple, e2char('sol'), e2char('47'), e2char('0x2F'), et e2char('057') retournent tous 47, car "E<sol>", "E<47>", "E<0x2f>", et "E<057>", signifient tous "/", dont le numéro Unicode est 47. Si le nom n'a pas de valeur connue (comme pour un nom "qacute") ou est syntaxiquement invalide (comme pour un nom "1/4"), ceci retourne undef.
$Name2character{name}
Mappe les noms (comme dans "E<name>") comme "eacute" ou "sol" à la chaîne que chacun représente. Notez que ceci n'inclut pas les numériques (comme "64" ou "x981c"). Sous les anciennes versions de Perl (avant 5.7), vous obtenez un "?" à la place des caractères dont la valeur Unicode est supérieure à 255.
$Name2character_number{name}
Mappe les noms (comme dans "E<name>") comme "eacute" ou "sol" à la valeur Unicode que chacun représente. Par exemple, $Name2character_number{'eacute'} est 201, et $Name2character_number{'euro'} est 8364. Vous obtenez la valeur Unicode correcte, quel que soit la version de Perl que vous utilisez -- ce qui diffère du comportement de %Name2character sous les Perl pré-5.7.

Notez que ce hash n'inclut pas les numériques (comme "64" ou "x981c").

$Latin1Code_to_fallback{integer}
Pour les nombres dans la plage 160 (0x00A0) à 255 (0x00FF), ceci mappe le code du caractère d'un caractère Latin-1 (comme 233 pour le e-accent aigu minuscule) au caractère US-ASCII qui l'approxime le mieux (comme "e"). Vous pourriez trouver cela utile si vous rendez du Pod dans un format qui, selon vous, ne gère bien que les caractères US-ASCII.
$Latin1Char_to_fallback{character}
Tout comme ci-dessus, mais mappe les caractères (comme "\xE9", e-accent aigu minuscule) à des caractères (comme "e").
$Code2USASCII{integer}
Ceci mappe les codes US-ASCII (comme 32) au caractère correspondant (comme l'espace, pour 32). Seuls les caractères de 32 à 126 sont définis. Ceci est destiné à être utilisé par e2char($x) lorsqu'il détecte qu'il s'exécute sur une plateforme non-ASCII (où chr(32) ne vous donne pas un espace -- mais $Code2USASCII{32} le fera). Il est documenté ici juste au cas où vous le trouveriez utile.

CAVEATS

Sur les versions de Perl antérieures à 5.7, les caractères Unicode avec une valeur supérieure à 255 (comme lambda ou le tiret cadratin) ne peuvent pas être transmis. Ce module fonctionne sous de telles versions antérieures de Perl, mais à la place de chaque caractère, vous obtenez un "?". Les caractères Latin-1 (caractères 160-255) ne sont pas affectés.

Sur les plateformes EBCDIC, e2char($n) peut ne pas être toujours le même que "chr(e2charnum($n))", et idem pour $Name2character{$name} et chr($Name2character_number{$name}), car les chaînes sont retournées nativement, et les nombres sont retournés en Unicode. Cependant, pour les Perl à partir de la v5.8, e2char($n) est le même que "chr(utf8::unicode_to_native(e2charnum($n)))", et idem pour $Name2character{$name} et "chr(utf8::unicode_to_native($Name2character_number{$name}))".
