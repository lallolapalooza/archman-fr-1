NOM

Pod::PlainText - Convertir des données POD en texte ASCII formaté

SYNTAXE

use Pod::PlainText;
my $parser = Pod::PlainText->new (sentence => 0, width => 78);
# Lire le POD depuis STDIN et écrire sur STDOUT.
$parser->parse_from_filehandle;
# Lire le POD depuis file.pod et écrire sur file.txt.
$parser->parse_from_file ('file.pod', 'file.txt');

DESCRIPTION

NOTE : Ce module est considéré comme obsolète ; les versions récentes de Perl (5.31.1 et plus) vont supprimer Pod-Parser du cœur et utiliser Pod::Simple pour toutes les manipulations de POD.

Pod::PlainText est un module qui peut convertir la documentation au format POD (la langue préférée pour documenter Perl) en texte ASCII formaté. Il n'utilise aucun contrôle de formatage ou code spécial, et sa sortie est donc adaptée à presque tous les appareils.

En tant que classe dérivée de Pod::Parser, Pod::PlainText prend en charge les mêmes méthodes et interfaces. Voir Pod::Parser pour tous les détails ; en bref, on crée un nouveau parseur avec "Pod::PlainText->new()" puis on appelle soit parse_from_filehandle(), soit parse_from_file().

new() peut accepter des options, sous forme de paires clé/valeur, qui contrôlent le comportement du parseur. Les options actuellement reconnues sont :

alt
Si défini à une valeur vraie, sélectionne un format de sortie alternatif qui, entre autres choses, utilise un style d'en-tête différent et marque les entrées "=item" avec un deux-points dans la marge gauche. Par défaut, il est faux.
indent
Le nombre d'espaces pour indenter le texte régulier, et l'indentation par défaut pour les blocs "=over". Par défaut, il est de 4.
loose
Si défini à une valeur vraie, une ligne vide est imprimée après les en-têtes "=headN". Si défini à faux (par défaut), aucune ligne vide n'est imprimée après "=headN". C'est le défaut car c'est le formatage attendu pour les pages de manuel ; si vous formatez des documents textuels arbitraires, le définir à vrai peut produire une sortie plus agréable.
sentence
Si défini à une valeur vraie, Pod::PlainText supposera que chaque phrase se termine par deux espaces, et essaiera de préserver cet espacement. Si défini à faux, tout espace blanc consécutif dans les paragraphes non-verbatim est compressé en un seul espace. Par défaut, il est vrai.
width
La colonne à laquelle le texte doit être coupé sur le côté droit. Par défaut, il est de 76.

La méthode standard de Pod::Parser, parse_from_filehandle(), prend jusqu'à deux arguments, le premier étant le descripteur de fichier à lire et le second étant le descripteur de fichier où écrire la sortie formatée. Le premier vaut STDIN par défaut s'il n'est pas donné, et le second vaut STDOUT. La méthode parse_from_file() est presque identique, sauf que ses deux arguments sont les fichiers disque d'entrée et de sortie. Voir Pod::Parser pour les détails spécifiques.

DIAGNOSTICS

Espace bizarre dans item
(W) Quelque chose s'est mal passé dans le traitement interne de "=item". Ce message indique un bug dans Pod::PlainText ; vous ne devriez jamais le voir.
Impossible d'ouvrir %s en lecture : %s
(F) Pod::PlainText a été invoqué via l'interface de mode de compatibilité pod2text() et le fichier d'entrée qui lui a été donné n'a pas pu être ouvert.
Échappement inconnu : %s
(W) La source POD contenait un échappement "E<>" que Pod::PlainText ne connaissait pas.
Séquence inconnue : %s
(W) La source POD contenait une séquence interne non standard (quelque chose de la forme "X<>") que Pod::PlainText ne connaissait pas.
=back non apparié
(W) Pod::PlainText a rencontré une commande "=back" qui ne correspondait à aucune commande "=over".

RESTRICTIONS

Les caractères Ctrl-A (octal 001) intégrés dans l'entrée seront mappés en espaces en sortie, en raison d'un détail d'implémentation interne.

NOTES

Ceci est un remplacement d'un module Pod::Text antérieur écrit par Tom Christiansen. Il a une interface remaniée, car il utilise maintenant Pod::Parser, mais une interface à peu près compatible avec l'ancienne fonction Pod::Text::pod2text() est toujours disponible. Veuillez changer pour la nouvelle convention d'appel, cependant.

Le Pod::Text original contenait du code pour faire le formatage via des séquences termcap, bien qu'il ne soit pas activé par défaut et qu'il était problématique de le faire fonctionner. Cette réécriture n'essaie même pas cela, mais une de ses sous-classes le fait. Cherchez Pod::Text::Termcap.
