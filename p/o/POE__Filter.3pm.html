POE::Filter(3) Documentation Perl fournie par l'utilisateur POE::Filter(3)

NOM

POE::Filter - abstractions de protocole pour POE::Wheel et utilisation autonome

SYNOPSIS

Pour utiliser avec les classes POE::Wheel, passez un objet POE::Filter à l'un des paramètres du constructeur "...Filter" :

#!perl
use POE qw(Filter::Line Wheel::FollowTail);
POE::Session->create(
  inline_states => {
    _start => sub {
      $_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
        Filename => "/var/log/system.log",
        InputEvent => "got_log_line",
        Filter => POE::Filter::Line->new(),
      );
    },
    got_log_line => sub {
      print "Log: $_[ARG0]\n";
    }
  }
);
POE::Kernel->run();
exit;

Utilisation autonome sans POE :

#!perl
use warnings;
use strict;
use POE::Filter::Line;
my $filter = POE::Filter::Line->new( Literal => "\n" );
# Affiche trois lignes : one, two three.
$filter->get_one_start(["one\ntwo\nthr", "ee\nfour"]);
while (1) {
  my $line = $filter->get_one();
  last unless @$line;
  print $line->[0], "\n";
}
# Affiche deux lignes : four, five.
$filter->get_one_start(["\nfive\n"]);
while (1) {
  my $line = $filter->get_one();
  last unless @$line;
  print $line->[0], "\n";
}

DESCRIPTION

Les objets POE::Filter se connectent aux roues (wheels) et définissent comment les données seront sérialisées pour l'écriture et analysées après la lecture. Les objets POE::Wheel sont responsables du déplacement des données, et les objets POE::Filter définissent l'apparence des données.

Les objets POE::Filter sont simples par conception. Ils n'utilisent pas POE en interne, ils sont donc limités à la sérialisation et à l'analyse. Cela peut compliquer la mise en œuvre de certains protocoles (comme HTTP 1.x), mais permet aux filtres d'être utilisés dans des programmes autonomes.

L'utilisation autonome est très importante. Elle permet aux développeurs d'applications de créer des bibliothèques légères et bloquantes qui peuvent être utilisées comme clients simples pour les serveurs POE. POE::Component::IKC::ClientLite en est un exemple notable. Ce client léger et bloquant de passage d'événements prend en charge les clients légers pour les applications POE distribuées. Le cas d'utilisation canonique est d'injecter des événements dans une application ou une grille IKC à partir d'interfaces CGI, qui nécessitent une utilisation légère des ressources.

Les filtres et pilotes POE passent les données sous forme de références de tableaux. C'est un peu maladroit, mais cela minimise la quantité de données qui doivent être copiées sur la pile de Perl.

INTERFACE PUBLIQUE

Toutes les classes POE::Filter doivent supporter l'interface minimale, définie ici. Des filtres spécifiques peuvent implémenter et documenter des méthodes supplémentaires.

PARAMÈTRES de new

new() crée et initialise un nouveau filtre. Les paramètres du constructeur varient d'une sous-classe de POE::Filter à l'autre, veuillez donc consulter la documentation de votre filtre souhaité.

clone

clone() crée et initialise un nouveau filtre basé sur les paramètres du constructeur de celui existant. Le nouveau filtre est une copie quasi identique, à l'exception de ses tampons qui sont vides.

Certains composants, tels que POE::Component::Server::TCP, utilisent clone(). Ces composants acceptent un filtre maître ou modèle lors de leur création, puis le clone() pour chaque nouvelle connexion.

my $new_filter = $old_filter->clone();

get_one_start ARRAYREF

get_one_start() accepte une référence de tableau contenant des morceaux de flux non traités. Les morceaux sont ajoutés au tampon interne du filtre pour être analysés par get_one().

Le "SYNOPSIS" montre get_one_start() en utilisation.

get_one

get_one() analyse zéro ou un élément complet à partir du tampon interne du filtre. Les données sont renvoyées sous forme de référence de tableau (ARRAYREF) appropriée pour être transmise à un autre filtre ou à un objet POE::Wheel. Les filtres renverront des références de tableaux vides s'ils n'ont pas assez de données brutes pour construire un élément complet.

get_one() est la forme paresseuse de get(). Il analyse un seul élément à la fois à partir du tampon du filtre. C'est vital pour les applications qui peuvent changer de filtre en cours de flux, car cela garantit que le bon filtre est utilisé à tout moment.

Le "SYNOPSIS" montre get_one() en utilisation. Notez comment il suppose que le retour est toujours une référence de tableau et comment il gère implicitement les références vides.

get ARRAYREF

get() est la forme gourmande (greedy) de get_one(). Il accepte une référence de tableau contenant des morceaux de flux non traités, ajoute ces données au tampon interne du filtre. Ensuite, il analyse autant d'éléments complets que possible à partir du tampon et les renvoie dans une autre référence de tableau. Toutes les données non traitées restent dans le tampon du filtre pour l'appel suivant.

Comme pour get_one(), get() renverra une référence de tableau vide si le filtre ne contient pas assez de données brutes pour construire un élément complet.

En fait, get() est implémenté dans POE::Filter en termes de get_one_start() et get_one().

Voici la forme get() de l'exemple autonome du SYNOPSIS :

#!perl
use warnings;
use strict;
use POE::Filter::Line;
my $filter = POE::Filter::Line->new( Literal => "\n" );
# Affiche trois lignes : one, two three.
my $lines = $filter->get(["one\ntwo\nthr", "ee\nfour"]);
foreach my $line (@$lines) {
  print "$line\n";
}
# Affiche deux lignes : four, five.
$lines = $filter->get(["\nfive\n"]);
foreach my $line (@$lines) {
  print "$line\n";
}

get() ne doit pas être utilisé avec des roues qui prennent en charge le changement de filtre. Sa nature gourmande signifie qu'il analyse souvent les flux bien avant les événements d'une roue. Au moment où une application change le filtre de la roue, il est trop tard : l'ancien filtre a déjà analysé le reste des données reçues.

Considérez un flux de lettres, de chiffres et de points. Les points signalent quand changer de filtre, passant de celui qui analyse les lettres à celui qui analyse les chiffres.

Dans notre application hypothétique, les lettres doivent être traitées une par une, mais les chiffres peuvent être traités par morceaux. Nous utiliserons POE::Filter::Block avec une taille de bloc (BlockSize) de 1 pour analyser les lettres, et POE::Filter::Line avec un terminateur littéral (Literal) de "." pour gérer les chiffres.

Voici le flux d'exemple :

abcdefg.1234567.hijklmnop.890.q

Nous commencerons avec une roue ReadWrite configurée pour analyser les caractères.

$_[HEAP]{wheel} = POE::Wheel::ReadWrite->new(
  Filter => POE::Filter::Block->new( BlockSize => 1 ),
  Handle => $socket,
  InputEvent => "got_letter",
);

Le gestionnaire "got_letter" sera appelé 8 fois. Une fois pour chaque lettre de a à g, et une fois pour le point suivant g. En recevant le point, il passera la roue en mode numérique.

sub handle_letter {
  my $letter = $_[ARG0];
  if ($letter eq ".") {
    $_[HEAP]{wheel}->set_filter(
      POE::Filter::Line->new( Literal => "." )
    );
    $_[HEAP]{wheel}->event( InputEvent => "got_number" );
  }
  else {
    print "Got letter: $letter\n";
  }
}

Si le get() gourmand était utilisé, l'intégralité du flux d'entrée aurait été analysée comme des caractères avant le premier appel à handle_letter(). L'appel à set_filter() aurait été inutile, car il n'y aurait plus de données à analyser.

Le gestionnaire "got_number" reçoit des séquences contiguës de chiffres comme lignes terminées par un point. Le get() gourmand causerait un problème similaire à celui ci-dessus.

sub handle_numbers {
  my $numbers = $_[ARG0];
  print "Got number(s): $numbers\n";
  $_[HEAP]->{wheel}->set_filter(
    POE::Filter::Block->new( BlockSize => 1 )
  );
  $_[HEAP]->{wheel}->event( InputEvent => "got_letter" );
}

Alors, ne le faites pas !

put ARRAYREF

put() sérialise les éléments en un flux d'octets qui peut être écrit dans un fichier ou envoyé sur une socket. Il accepte une référence à une liste d'éléments et renvoie une référence à une liste de morceaux de flux mis en forme. Le nombre de morceaux de sortie n'est pas nécessairement lié au nombre d'éléments d'entrée.
