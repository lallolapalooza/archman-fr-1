Pod::ParseLink(3perl) Guide de référence du programmeur Perl Pod::ParseLink(3perl)

NOM

Pod::ParseLink - Analyser un code de formatage L<> dans le texte POD

SYNTAXE

use Pod::ParseLink;
my $link = get_link();
my ($text, $inferred, $name, $section, $type) = parselink($link);

DESCRIPTION

Ce module ne fournit qu'une seule fonction, parselink(), qui prend le texte d'un code de formatage L<> et l'analyse. Il renvoie le texte d'ancrage du lien (s'il y en a), le texte d'ancrage éventuellement inféré à partir du nom et de la section, le nom ou l'URL, la section le cas échéant, et le type de lien. Le type sera l'un des éléments suivants : "url", "pod", ou "man", indiquant une URL, un lien vers une page POD, ou un lien vers une page de manuel Unix.

L'analyse est implémentée selon perlpodspec. Pour la compatibilité descendante, les liens où il n'y a pas de section et où le nom contient des espaces, ou les liens où tout le lien (sauf le texte d'ancrage s'il est donné) est entouré de guillemets doubles sont interprétés comme des liens vers une section (L</section>).

Le texte d'ancrage inféré est implémenté selon perlpodspec :

L<name>         =>  L<name|name>
L</section>     =>  L<"section"|/section>
L<name/section> =>  L<"section" dans name|name/section>

Le nom peut contenir des codes de formatage E<> et Z<> incorporés, et la section, le texte d'ancrage, et le texte d'ancrage inféré peuvent contenir n'importe quels codes de formatage. Les guillemets doubles entourant la section sont supprimés dans le cadre de l'analyse, tout comme les espaces blancs en début ou fin de texte.

Si le texte de l'échappement L<> est entièrement entouré de guillemets doubles, il est interprété comme un lien vers une section pour des raisons de compatibilité ascendante.

Aucune tentative n'est faite pour résoudre les codes de formatage. Cela doit être fait après l'appel à parselink() (car les codes de formatage E<> peuvent être utilisés pour échapper des caractères qui seraient autrement significatifs pour l'analyseur, et leur résolution avant l'analyse entraînerait une mauvaise analyse d'un code de formatage tel que :

L<verticalE<verbar>barE<sol>slash>

qui devrait être interprété comme un lien vers la page POD "vertical|bar/slash" et non comme un lien vers la section "slash" de la page POD "bar" avec un texte d'ancrage de "vertical". Notez que non seulement le texte d'ancrage devra avoir ses codes de formatage développés, mais la cible du lien devra également l'être (pour gérer les codes de formatage E<> et Z<>), et une gestion spéciale de la section peut être nécessaire selon que le traducteur souhaite que le balisage dans les sections soit significatif lors de la résolution des liens. Voir perlpodspec pour plus d'informations.
