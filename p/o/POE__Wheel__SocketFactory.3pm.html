POE::Wheel::SocketFactory(3) Documentation contribuée par Perl POE::Wheel::SocketFactory(3)

NOM

POE::Wheel::SocketFactory - création de sockets non bloquants

SYNTAXE

Voir "SYNTAXE" dans POE::Component::Server::TCP pour une version simplifiée de ce programme.

#!perl
use warnings;
use strict;
use IO::Socket;
use POE qw(Wheel::SocketFactory Wheel::ReadWrite);
POE::Session->create(
  inline_states => {
    _start => sub {
      # Démarrer le serveur.
      $_[HEAP]{server} = POE::Wheel::SocketFactory->new(
        BindPort => 12345,
        SuccessEvent => "on_client_accept",
        FailureEvent => "on_server_error",
      );
    },
    on_client_accept => sub {
      # Commencer à interagir avec le client.
      my $client_socket = $_[ARG0];
      my $io_wheel = POE::Wheel::ReadWrite->new(
        Handle => $client_socket,
        InputEvent => "on_client_input",
        ErrorEvent => "on_client_error",
      );
      $_[HEAP]{client}{ $io_wheel->ID() } = $io_wheel;
    },
    on_server_error => sub {
      # Arrêter le serveur.
      my ($operation, $errnum, $errstr) = @_[ARG0, ARG1, ARG2];
      warn "Erreur du serveur $operation $errnum: $errstr\n";
      delete $_[HEAP]{server};
    },
    on_client_input => sub {
      # Gérer l'entrée du client.
      my ($input, $wheel_id) = @_[ARG0, ARG1];
      $input =~ tr[a-zA-Z][n-za-mN-ZA-M]; # ASCII rot13
      $_[HEAP]{client}{$wheel_id}->put($input);
    },
    on_client_error => sub {
      # Gérer l'erreur client, y compris la déconnexion.
      my $wheel_id = $_[ARG3];
      delete $_[HEAP]{client}{$wheel_id};
    },
  }
);
POE::Kernel->run();
exit;

DESCRIPTION

POE::Wheel::SocketFactory crée des sockets lorsque cela est nécessaire. Il peut créer des sockets sans connexion, mais il excelle vraiment dans le travail client/serveur où la création de connexions bloque normalement.

MÉTHODES PUBLIQUES

new

new() crée un objet POE::Wheel::SocketFactory. Pour les sockets qui listen() pour des connexions et accept() des connexions, la roue génère de nouveaux sockets pour chaque client accepté. Les fabriques de sockets pour les sockets unidirectionnels, tels que les datagrammes UDP ou les clients établis avec connect(), émettent un seul socket et peuvent être détruits par la suite sans effets négatifs.

new() renvoie toujours un objet POE::Wheel::SocketFactory même si le socket n'a pas pu être établi. Cela permet de consulter l'objet après qu'il ait envoyé à sa session un "FailureEvent".

new() accepte un nombre conséquent de paramètres nommés, chacun régulant un aspect de la création du socket.

Création du socket

La création du socket est effectuée à l'aide de la fonction Perl intégrée socket(). Les paramètres new() commençant par "Socket" déterminent comment socket() sera appelé.

Domaine du socket

"SocketDomain" demande à la roue de créer un socket dans un domaine spécifique. Les domaines pris en charge sont "AF_UNIX", "AF_INET", "AF_INET6", "PF_UNIX", "PF_INET" et "PF_INET6". S'il n'est pas spécifié, le socket sera créé dans le domaine "AF_INET".

POE::Wheel::SocketFactory contient un tableau des domaines pris en charge et des instructions nécessaires pour les créer. Veuillez soumettre des correctifs pour prendre en charge d'autres domaines, si nécessaire.

Remarque : "AF_INET6" et "PF_INET6" sont fournis par le module Socket inclus dans Perl 5.8.0 ou version ultérieure. Les versions de Perl antérieures à 5.8.0 ne devraient pas tenter d'utiliser IPv6, à moins que quelqu'un ne contribue à une solution de contournement.

La prise en charge d'IPv6 nécessite un module Socket qui implémente getaddrinfo() et unpack_sockaddr_in6(). D'autres modules peuvent effectuer ces fonctions, mais la plupart d'entre eux sont devenus obsolètes avec l'avènement de la prise en charge appropriée d'IPv6 dans les modules de support principaux.

Type de socket

"SocketType" fournit à l'appel socket() un type de socket spécifique, qui peut être "SOCK_STREAM" ou "SOCK_DGRAM". "SOCK_STREAM" est le type par défaut si "SocketType" n'est pas spécifié.

Protocole du socket

"SocketProtocol" définit le type de protocole pour l'appel socket(). Les protocoles peuvent être spécifiés par numéro ou par nom. "SocketProtocol" est ignoré pour les sockets de type UNIX.

Le protocole par défaut est « tcp » pour les sockets de domaine INET. Il n'y a pas de valeur par défaut pour les autres domaines de socket.

Configuration des options du socket

POE::Wheel::SocketFactory utilise ioctl(), fcntl() et setsockopt() pour configurer les options du socket après sa création. Tous les sockets sont configurés en mode non bloquant, et les sockets liés peuvent être réutilisés.

Réutilisation

Lorsqu'il est défini, le paramètre "Reuse" permet de réutiliser immédiatement un port déjà lié. "Reuse" est considéré comme activé s'il contient « yes », « on » ou une valeur numérique vraie. Toutes les autres valeurs désactivent la réutilisation du port, et omettre "Reuse" le fait également.

Pour des raisons de sécurité, un port ne peut pas être réutilisé une fois que le serveur l'a libéré. Cela laisse aux clients le temps de remarquer que le port a été abandonné. Sinon, un service malveillant pourrait capturer le port et usurper le service légitime.

Il est également très ennuyeux d'attendre une minute ou plus entre les invocations du serveur, surtout pendant le développement.

Liaison du socket à une adresse et un port spécifiques

Un socket peut être lié à une interface et un port spécifiques. L'adresse "INADDR_ANY" peut être utilisée pour lier un port spécifique sur toutes les interfaces.

Les sockets sont liés à l'aide de bind(). Les paramètres new() commençant par "Bind" contrôlent la manière dont bind() est appelé.

BindAddress

"BindAddress" définit une adresse à laquelle le point de terminaison local du socket est lié. "INADDR_ANY" sera utilisé si "BindAddress" n'est pas spécifié.

"BindAddress" peut contenir une chaîne de caractères ainsi qu'une adresse Internet (pour les sockets de type INET). Le paramètre chaîne doit être une adresse numérique ou un nom d'hôte résoluble. Remarque : le nom d'hôte sera résolu à l'aide d'un appel bloquant. Si cela n'est pas souhaité, utilisez POE::Component::Client::DNS pour une résolution non bloquante.

Lorsqu'il est utilisé pour lier un socket de type UNIX, "BindAddress" doit contenir un chemin décrivant le nom de fichier du socket. Ceci est nécessaire pour les sockets serveur et les sockets datagrammes clients. "BindAddress" n'a pas de valeur par défaut pour les sockets de type UNIX.

BindPort

"BindPort" n'est significatif que pour les sockets de type INET. Il contient un port sur l'interface "BindAddress" auquel le socket sera lié. Par défaut, s'il n'est pas spécifié, le port est 0, ce qui provoquera un appel à bind() pour choisir un port indéterminé et non lié.

"BindPort" peut être un numéro de port ou un nom pouvant être recherché dans la base de données des services système (ou équivalent).

Sockets connectés de manière non bloquante

Les sockets connectés de manière non bloquante peuvent interagir avec des points de terminaison distants sans nécessiter listen() ou connect() à des adresses distantes.

Cette classe de sockets est terminée après l'appel bind().

Connexion du socket à un point de terminaison distant

Un socket peut soit attendre l'arrivée des connexions, soit initier des connexions à un point de terminaison distant, soit être connecté de manière non bloquante (comme dans le cas des sockets UDP).

POE::Wheel::SocketFactory initiera une connexion client lorsque new() sera capable de décrire un point de terminaison distant. Dans tous les autres cas, le socket attendra les connexions ou sera connecté en fonction du type de socket.

>Les paramètres suivants décrivent le point de terminaison distant d'une socket. Ils déterminent comment POE::Wheel::SocketFactory appellera la fonction intégrée connect() de Perl.

RemoteAddress

"RemoteAddress" spécifie l'adresse distante à laquelle une socket doit se connecter. Si elle est présente, POE::Wheel::SocketFactory créera une socket client qui tentera de se connecter à l'adresse "RemoteAddress". Sinon, si le protocole le justifie, la roue créera une socket d'écoute et tentera d'accepter des connexions.

Comme pour l'adresse de liaison, "RemoteAddress" peut être une chaîne contenant un quadrupède décimal ou un nom d'hôte résoluble. Il peut également s'agir d'une adresse Internet packettée, ou d'un chemin de socket UNIX. Elle sera packettée, avec ou sans "RemotePort" associé, selon les besoins du domaine de socket.

RemotePort

"RemotePort" est le port auquel la socket doit se connecter. Il est requis pour les sockets clients "INET", car le point de terminaison distant doit contenir à la fois une adresse et un port.

Le port distant peut être numérique, ou il peut s'agir d'un nom symbolique trouvé dans /etc/services ou son équivalent pour votre système d'exploitation.

Écoute des connexions

Les sockets de flux qui n'ont pas de point de terminaison distant sont considérées comme des sockets serveur. POE::Wheel::SocketFactory appellera listen() pour les connexions à ces sockets, accept() les nouveaux clients, et enverra des événements à l'application avec les nouvelles sockets clientes.

Les paramètres du constructeur POE::Wheel::SocketFactory commençant par "Listen" contrôlent la manière dont la fonction listen() est appelée.

ListenQueue

"ListenQueue" spécifie la longueur de la file d'attente listen() de la socket. Elle est par défaut à "SOMAXCONN" si elle est omise. Les valeurs de "ListenQueue" supérieures à "SOMAXCONN" seront limitées à "SOMAXCONN". Des valeurs de "ListenQueue" excessivement grandes ne sont pas nécessairement portables et peuvent causer des erreurs dans de rares cas.

Émission d'événements

POE::Wheel::SocketFactory émet un petit nombre d'événements en fonction de ce qui se passe lors de la configuration de la socket ou lors de l'écoute de nouvelles connexions.

Voir "ÉVÉNEMENTS PUBLICS" pour plus de détails.

SuccessEvent

"SuccessEvent" nomme l'événement qui sera émis chaque fois que POE::Wheel::SocketFactory réussira à créer une nouvelle socket.

Pour les sockets sans connexion, "SuccessEvent" se produit juste après la création de la socket.

Pour les connexions clientes, "SuccessEvent" est déclenché lorsque la connexion a été établie avec succès avec le point de terminaison distant.

Les sockets serveur émettent un "SuccessEvent" pour chaque client accepté avec succès.

FailureEvent

"FailureEvent" nomme l'événement que POE::Wheel::SocketFactory émettra en cas de problème. Il représente généralement une erreur d'appel de fonction intégrée. Voir "ÉVÉNEMENTS PUBLICS" pour plus de détails, car certaines erreurs sont gérées en interne par cette roue.

event

event() permet à une session de modifier les événements émis par une roue sans détruire et recréer la roue. Il accepte un ou plusieurs des événements listés dans "ÉVÉNEMENTS PUBLICS". Les noms d'événements indéfinis désactivent ces événements.

event() est décrit plus en détail dans POE::Wheel.

getsockname

getsockname() se comporte comme la fonction intégrée du même nom. Il renvoie les informations du point de terminaison local pour la socket d'écoute encapsulée par POE::Wheel::SocketFactory.

getsockname() permet aux applications de déterminer l'adresse et le port auxquels POE::Wheel::SocketFactory a lié sa socket d'écoute.

Les applications de test peuvent utiliser getsockname() pour trouver la socket serveur après que POE::Wheel::SocketFactory s'est lié au port 0 de INADDR_ANY.

Comme il n'y a pas d'événement déclenché immédiatement après la création réussie d'une socket d'écoute, les applications peuvent utiliser getsockname() pour vérifier cela.

use Socket 'unpack_sockaddr_in';
my $listener = POE::Wheel::SocketFactory->new(
    BindPort     => 123,
    SuccessEvent => 'got_client',
    FailureEvent => 'listener_failed',
    Reuse        => 'on',
);
my ($port, $addr) = unpack_sockaddr_in($listener->getsockname);
print "Socket successfully bound\n" if $port;

ID

ID() renvoie l'identifiant unique de la roue. L'identifiant sera également inclus dans chaque événement que la roue génère. Les applications peuvent faire correspondre les événements aux objets qui les ont générés.

pause_accept

Les applications peuvent occasionnellement avoir besoin de bloquer les connexions entrantes. pause_accept() met en pause le watcheur d'événements qui déclenche accept(). Les nouvelles connexions entrantes s'accumuleront dans la file d'attente listen() de la socket jusqu'à ce que la file déborde ou que l'application appelle resume_accept().

La mise en pause de accept() peut limiter la charge générée par un serveur. Elle est également utile dans les serveurs pré-forkés lorsque le processus maître ne doit pas accepter du tout de connexions.

pause_accept() et resume_accept() sont plus rapides et plus fiables que de détruire et recréer dynamiquement un objet POE::Wheel::SocketFactory.

resume_accept

resume_accept() reprend le watcheur qui déclenche accept(). Voir "pause_accept" pour une discussion plus détaillée.

ÉVÉNEMENTS PUBLICS

POE::Wheel::SocketFactory émet deux événements publics.

SuccessEvent

"SuccessEvent" nomme un événement qui sera envoyé à la session créatrice chaque fois qu'un POE::Wheel::SocketFactory aura créé une nouvelle socket. Pour les sockets sans connexion, c'est au moment de la création de la socket. Pour les clients qui se connectent, c'est après l'établissement de la connexion. Et pour les serveurs qui écoutent, "SuccessEvent" est déclenché après l'acceptation de chaque nouveau client.

Paramètres communs de SuccessEvent

Dans tous les cas, $_[ARG0] contient le descripteur de fichier de la nouvelle socket, et $_[ARG3] contient l'identifiant de POE::Wheel::SocketFactory. D'autres paramètres varient en fonction du domaine de la socket et si elle écoute ou se connecte. Voir ci-dessous pour les différences.

Paramètres SuccessEvent INET

Pour les sockets INET, $_[ARG1] et $_[ARG2] contiennent respectivement l'adresse et le port distants de la socket. L'adresse est packettée ; voir "inet_ntop" dans Socket si une adresse lisible par l'homme est nécessaire.

sub handle_new_client {
  my $accepted_socket = $_[ARG0];
  my $peer_host = inet_ntop(
    ((length($_[ARG1]) == 4) ? AF_INET : AF_INET6),
    $_[ARG1]
  );
  print(
    "Wheel $_[ARG3] accepted a connection from ",
    "$peer_host port $peer_port\n"
  );
  spawn_connection_session($accepted_handle);
}

Paramètres SuccessEvent Client UNIX

Pour les sockets clients UNIX, $_[ARG1] contient souvent (mais pas toujours) l'adresse du serveur. Certains systèmes ne peuvent pas récupérer l'adresse distante d'une socket UNIX. $_[ARG2] est toujours indéfini pour les sockets clients UNIX.

Paramètres SuccessEvent Serveur UNIX

Selon le *Perl Cookbook*, l'adresse distante renvoyée par accept() sur les sockets UNIX est indéfinie, donc $_[ARG1] et $_[ARG2] sont également indéfinis dans ce cas.

FailureEvent

"FailureEvent" nomme l'événement qui sera émis lorsqu'une erreur de socket se produit. POE::Wheel::SocketFactory gère "EAGAIN" en interne, donc il n'est pas considéré comme une erreur.

Les événements "FailureEvent" incluent les paramètres d'événement d'erreur standard :

$_[ARG0] décrit quelle partie de la création de la socket a échoué. Il contient souvent le nom d'une fonction intégrée de Perl.

$_[ARG1] et $_[ARG2] décrivent comment l'opération a échoué. Ils contiennent les versions numérique et chaînes de $!, respectivement. Une application ne peut pas simplement vérifier la variable globale $! car elle peut changer pendant la distribution des événements.

Enfin, $_[ARG3] contient l'identifiant de l'instance de POE::Wheel::SocketFactory qui a généré l'événement. Voir "ID" et "ID" dans POE::Wheel pour les utilisations des identifiants de roue.

Un exemple de gestionnaire d'événement FailureEvent :

sub handle_failure {
  my ($operation, $errnum, $errstr, $wheel_id) = @_[ARG0..ARG3];
  warn "Wheel $wheel_id generated $operation error $errnum: $errstr\n";
  delete $_[HEAP]{wheels}{$wheel_id}; # shut down that wheel
}

VOIR AUSSI

POE::Wheel décrit les opérations de base de toutes les roues plus en profondeur. Vous devez connaître cela.

Socket::GetAddrInfo est requis pour le travail avec IPv6. POE::Wheel::SocketFactory le chargera automatiquement s'il est installé. SocketDomain => AF_INET6 est requis pour déclencher les comportements IPv6. AF_INET6 est exporté par le module Socket sur toutes les versions de Perl 5 sauf les plus anciennes. Si votre module Socket ne fournit pas AF_INET6, essayez d'installer Socket6 à la place.

La section SEE ALSO de POE contient une table des matières couvrant l'ensemble de la distribution POE.

BOGUES

Beaucoup (sinon toutes) les instructions croak/carp/warn/die devraient plutôt déclencher "FailureEvent".

SocketFactory n'est testé qu'avec les flux UNIX et les sockets INET utilisant les protocoles UDP et TCP. D'autres

BUGS

The internal configuration tables of the module should be updated by the calling application, and the POE::Kernel should not be restarted. This should work after the module's internal configuration tables are updated. Please send patches.
