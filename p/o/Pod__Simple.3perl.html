DESCRIPTION

Pod::Simple est une bibliothèque Perl pour l'analyse de texte dans le langage de balisage Pod ("plain old documentation") qui est typiquement utilisé pour écrire de la documentation pour Perl et pour les modules Perl. Le format Pod est expliqué dans perlpod ; le formateur le plus courant s'appelle "perldoc".

Assurez-vous de lire "ENCODING" si votre Pod contient des caractères non ASCII.

Les formateurs Pod peuvent utiliser Pod::Simple pour analyser les documents Pod et les rendre en texte brut, HTML, ou tout autre format. Typiquement, ces formateurs seront des sous-classes de Pod::Simple, et ils hériteront donc de ses méthodes, comme "parse_file". Mais notez que Pod::Simple ne comprend pas et n'analyse pas correctement Perl lui-même, donc si vous avez un fichier qui contient un programme Perl ayant une chaîne de caractères multi-lignes qui ressemble à du Pod, Pod::Simple le traitera comme du Pod. Cela peut être évité si le fichier utilise plutôt des here-documents indentés.

Si vous lisez ce document juste parce que vous avez une sous-classe de traitement de Pod que vous souhaitez utiliser, ce document (plus la documentation de la sous-classe) est probablement tout ce que vous avez besoin de lire.

Si vous lisez ce document parce que vous voulez écrire une sous-classe de formateur, continuez à le lire puis lisez Pod::Simple::Subclassing, et ensuite éventuellement même lisez perlpodspec (dont une partie est pour les écrivains de parseurs, mais une grande partie consiste en notes pour les écrivains de formateurs).

METHODES PRINCIPALES

"$parser = SomeClass->new();"
Ceci retourne un nouvel objet parseur, où "SomeClass" est une sous-classe de Pod::Simple.
"$parser->output_fh( *OUT );"
Ceci définit le flux de sortie vers lequel la sortie de $parser sera écrite. Vous pouvez passer *STDOUT ou *STDERR, sinon vous devriez probablement faire quelque chose comme ceci : 
my $outfile = "output.txt";
open TXTOUT, ">$outfile" or die "Can't write to $outfile: $!";
$parser->output_fh(*TXTOUT);

... avant d'appeler une des méthodes "$parser->parse_quelque chose".

"$parser->output_string( \$chaine );"
Ceci définit la chaîne de caractères vers laquelle la sortie de $parser sera envoyée, au lieu d'un flux de sortie.
"$parser->parse_file( $nom_fichier );"
"$parser->parse_file( *FLUX_ENTREE );"
Ceci lit le contenu Pod du fichier (ou flux) que vous spécifiez, et le traite avec cet objet $parser, conformément au fonctionnement de la classe de $parser, et conformément aux options de parseur que vous avez définies pour cet objet $parser.
"$parser->parse_string_document( $contenu_complet );"
Ceci fonctionne comme "parse_file" sauf que cela lit le contenu Pod non pas à partir d'un fichier, mais à partir d'une chaîne que vous avez déjà en mémoire.
"$parser->parse_lines( ...@lignes..., undef );"
Ceci traite les lignes de @lines (où chaque élément de la liste doit être une valeur définie, et doit contenir exactement une ligne de contenu -- donc aucun élément comme "foo\nbar" n'est autorisé). Le "undef" final est utilisé pour indiquer la fin du document en cours d'analyse.

Les autres méthodes "parser_quelque chose" sont censées être appelées une seule fois par objet $parser ; mais "parse_lines" peut être appelée autant de fois que vous le souhaitez par objet $parser, tant que le dernier appel (et seulement le dernier appel) se termine par une valeur "undef".

"$parser->content_seen"
Ceci retourne vrai seulement s'il y a eu du contenu réel vu pour ce document. Retourne faux dans les cas où le document contient du contenu, mais n'utilise aucune balise Pod.
"SomeClass->filter( $filename );"
"SomeClass->filter( *FLUX_ENTREE );"
"SomeClass->filter( \$contenu_document );"
C'est une méthode raccourcie pour créer un nouvel objet parseur, définir le flux de sortie sur STDOUT, puis traiter le fichier spécifié (ou le flux, ou le document en mémoire). C'est pratique pour les one-liners comme ceci : 
perl -MPod::Simple::Text -e "Pod::Simple::Text->filter('thingy.pod')"

METHODES SECONDAIRES

Certaines de ces méthodes pourraient intéresser les utilisateurs généraux, ainsi que les écrivains de formateurs.

Notez que le schéma général ici est que les méthodes d'accès lisent la valeur de l'attribut avec "$value = $parser->attribut" et définissent la valeur de l'attribut avec "$parser->attribut(nouvelle_valeur)". Pour chaque accesseur, je mentionne typiquement une seule syntaxe ou une autre, en fonction de celle que vous êtes le plus susceptible d'utiliser.

"$parser->parse_characters( VALEUR_QUELCONQUE )"
Le parseur Pod s'attend normalement à lire des octets et à convertir ces octets en caractères en fonction de la déclaration "=encoding" dans la source Pod. Définissez cette option à une valeur vraie pour indiquer que la source Pod est déjà un flux de caractères Perl. Cela indique au parseur d'ignorer toute commande "=encoding" et de sauter tous les chemins de code impliquant le décodage d'octets.
"$parser->no_whining( VALEUR_QUELCONQUE )"
Si vous définissez cet attribut à une valeur vraie, vous supprimerez les plaintes du parseur concernant les irrégularités dans le codage Pod. Par défaut, la valeur de cet attribut est fausse, ce qui signifie que les irrégularités seront signalées.

Notez que passer cet attribut à vrai ne supprimera pas un ou deux types de plaintes concernant des erreurs irrécupérables rarement rencontrées.

"$parser->no_errata_section( VALEUR_QUELCONQUE )"
Si vous définissez cet attribut à une valeur vraie, vous empêcherez le parseur de générer une section "POD ERRORS" à la fin du document. Par défaut, la valeur de cet attribut est fausse, ce qui signifie qu'une section d'errata sera générée, si nécessaire.
"$parser->complain_stderr( VALEUR_QUELCONQUE )"
Si vous définissez cet attribut à une valeur vraie, il enverra les rapports d'erreurs d'analyse à STDERR. Par défaut, la valeur de cet attribut est fausse, ce qui signifie qu'aucune sortie n'est envoyée à STDERR.

Définir "complain_stderr" définit également "no_errata_section".

"$parser->source_filename"
Ceci retourne le nom de fichier à partir duquel cet objet parseur a été configuré pour lire.
"$parser->doc_has_started"
Ceci retourne vrai si $parser a lu à partir d'une source et y a vu du contenu Pod.
"$parser->source_dead"
Ceci retourne vrai si $parser a lu à partir d'une source et atteint la fin de cette source.
"$parser->strip_verbatim_indent( VALEUR_QUELCONQUE )"
La spécification perlpod pour un paragraphe Verbatim est "Il doit être reproduit exactement...", ce qui signifie que les espaces que vous avez utilisés pour indenter vos blocs verbatim seront préservés dans la sortie. Cela peut être gênant pour des sorties comme HTML, où ces espaces resteront devant chaque ligne. C'est un cas malheureux où la syntaxe est transformée en sémantique.

Si le Pod que vous analysez adhère à une politique d'indentation cohérente, vous pouvez faire en sorte que cette indentation soit supprimée du début de chaque ligne de vos blocs verbatim. Cette méthode indique à Pod::Simple quoi supprimer. Pour des indentations de deux espaces, vous utiliseriez :

$parser->

strip_verbatim_indent(' ');

Pour les indentations par tabulation, vous utiliseriez un caractère de tabulation :

$parser->strip_verbatim_indent("\t");

Si le POD est incohérent quant à l'indentation des blocs verbatim, mais que vous avez déterminé une heuristique pour déterminer le degré d'indentation d'un bloc verbatim particulier, vous pouvez passer une référence de code à la place. La référence de code sera exécutée avec un argument, une référence de tableau de toutes les lignes du bloc verbatim, et devrait renvoyer la valeur à supprimer de chaque ligne. Par exemple, si vous décidez d'utiliser la première ligne du bloc verbatim pour définir la norme d'indentation du reste du bloc, vous pouvez examiner la première ligne et retourner la valeur appropriée, comme ceci :

$new->strip_verbatim_indent(sub {
    my $lines = shift;
    (my $indent = $lines->[0]) =~ s/\S.*//;
    return $indent;
});

Si vous préférez traiter chaque ligne individuellement, vous pouvez le faire aussi, en les transformant sur place dans la référence de code et en retournant "undef". Supposons que vous ne vouliez aucune ligne indentée. Vous pouvez faire quelque chose comme ceci :

$new->strip_verbatim_indent(sub {
    my $lines = shift;
    sub { s/^\s+// for @{ $lines },
    return undef;
});
"$parser->expand_verbatim_tabs( n )"
Par défaut : 8

Si, après toute suppression d'indentation dans les blocs verbatim, il reste des tabulations, cet appel de méthode indique ce qu'il faut en faire. 0 signifie les laisser comme tabulations, tout autre nombre indique que chaque tabulation doit être traduite de manière à avoir des arrêts de tabulation tous les "n" colonnes.

Ceci est indépendant des autres méthodes (sauf qu'il s'exécute après toute suppression d'entrée verbatim effectuée).

Comme les autres méthodes, le paramètre d'entrée n'est pas vérifié pour sa validité. "undef" ou un contenu non numérique a le même effet que 8.

MÉTHODES TERIAIRES

"$parser->abandon_output_fh()"
Annule la sortie vers le descripteur de fichier. Tout POD lu par le $parser n'est pas affecté.
"$parser->abandon_output_string()"
Annule la sortie vers la chaîne de sortie. Tout POD lu par le $parser n'est pas affecté.
"$parser->accept_code( @codes )"
Alias de accept_codes.
"$parser->accept_codes( @codes )"
Permet à $parser d'accepter une liste de "codes de mise en forme" dans perlpod. Ceci peut être utilisé pour implémenter des codes définis par l'utilisateur.
"$parser->accept_directive_as_data( @directives )"
Permet à $parser d'accepter une liste de directives pour les paragraphes de données. Une directive est le libellé d'un "paragraphe de commande" dans perlpod. Un paragraphe de données est délimité par des directives "=begin/=for/=end". Ceci peut être utilisé pour implémenter des directives définies par l'utilisateur.
"$parser->accept_directive_as_processed( @directives )"
Permet à $parser d'accepter une liste de directives pour les paragraphes traités. Une directive est le libellé d'un "paragraphe de commande" dans perlpod. Un paragraphe traité est également connu sous le nom de "paragraphe ordinaire" dans perlpod. Ceci peut être utilisé pour implémenter des directives définies par l'utilisateur.
"$parser->accept_directive_as_verbatim( @directives )"
Permet à $parser d'accepter une liste de directives pour les "paragraphes verbatim" dans perlpod. Une directive est le libellé d'un "paragraphe de commande" dans perlpod. Ceci peut être utilisé pour implémenter des directives définies par l'utilisateur.
"$parser->accept_target( @targets )"
Alias de accept_targets.
"$parser->accept_target_as_text( @targets )"
Alias de accept_targets_as_text.
"$parser->accept_targets( @targets )"
Accepte les cibles pour les sections "=begin/=for/=end" du POD.
"$parser->accept_targets_as_text( @targets )"
Accepte les cibles pour les sections "=begin/=for/=end" qui doivent être analysées comme du POD. Pour plus de détails, voir "À propos des paragraphes de données" dans perlpodspec.
"$parser->any_errata_seen()"
Utilisé pour vérifier si des errata ont été vues.

Exemple :

die "trop d'erreurs\n" if $parser->any_errata_seen();
"$parser->errata_seen()"
Retourne une référence de hachage de tous les errata vus, qu'il s'agisse d'avertissements ou de cris. Les clés de la référence de hachage sont le numéro de ligne et la valeur est une référence de tableau des erreurs pour cette ligne.

Exemple :

if ( $parser->any_errata_seen() ) {
   $logger->log( $parser->errata_seen() );
}
"$parser->detected_encoding()"
Retourne l'encodage correspondant à "=encoding", mais uniquement si l'encodage a été reconnu et géré.
"$parser->encoding()"
Retourne l'encodage du document, même si l'encodage n'est pas correctement géré.
"$parser->parse_from_file( $source, $to )"
Analyse depuis le fichier $source vers le fichier $to. Similaire à "parse_from_file" dans Pod::Parser.
"$parser->scream( @error_messages )"
Enregistre une erreur qui ne peut être ignorée.
"$parser->unaccept_code( @codes )"
Alias de unaccept_codes.
"$parser->unaccept_codes( @codes )"
Supprime @codes en tant que codes valides pour l'analyse.
"$parser->unaccept_directive( @directives )"
Alias de unaccept_directives.
"$parser->unaccept_directives( @directives )"
Supprime @directives en tant que directives valides pour l'analyse.
"$parser->unaccept_target( @targets )"
Alias de unaccept_targets.
"$parser->unaccept_targets( @targets )"
Supprime @targets en tant que cibles valides pour l'analyse.
"$parser->version_report()"
Retourne une chaîne décrivant la version.
"$parser->whine( @error_messages )"
Enregistre une erreur sauf si "$parser->no_whining( TRUE );".

ENCODAGE

L'analyseur Pod::Simple s'attend à lire des octets. L'analyseur décode les octets en la représentation de chaîne de caractères interne de Perl en utilisant la valeur de la déclaration "=encoding" dans la source POD.

Si la source POD n'inclut pas de déclaration "=encoding", l'analyseur tentera de deviner l'encodage (en sélectionnant UTF-8 ou CP 1252) en examinant les premiers octets non ASCII et en appliquant l'heuristique décrite dans perlpodspec. (Si la source POD ne contient que des octets ASCII, l'encodage est supposé être ASCII.)

Si vous définissez l'option "parse_characters" à une valeur vraie, l'analyseur s'attend à recevoir des caractères plutôt que des octets ; ignorera tout "=encoding" ; et ne fera aucune tentative de décodage de l'entrée.

NOM

Pod::Simple — Une interface de base pour analyser les documents Pod.

SYNOPSIS

use Pod::Simple::Framework;
use Pod::Simple::Search;

# Exemple d'utilisation simple
my $parser = Pod::Simple::Framework->new;
$parser->parse_file("mon_script.pl");

# Exemple avec recherche
my $finder = Pod::Simple::Search->new(directories => ["/usr/share/perl5/vendor_perl"]);
my $pod_file = $finder->find_pod_by_command("SomeCommand");
if ($pod_file) {
    print "Trouvé : $pod_file\n";
}

DESCRIPTION

Pod::Simple est une bibliothèque Perl conçue pour faciliter l'analyse et le traitement des documents Pod (Plain Old Documentation). Elle fournit une architecture flexible qui permet de créer des analyseurs personnalisés pour diverses tâches, telles que la conversion en HTML, la recherche d'informations ou la validation de la structure Pod.

MÉTHODES PRINCIPALES

  • new() : Constructeur pour créer une nouvelle instance de Pod::Simple.
  • parse_file($filename) : Analyse un fichier Pod donné.
  • parse_string($string) : Analyse une chaîne de caractères contenant du Pod.
  • set_output($output_handler) : Définit le gestionnaire de sortie pour la sortie analysée.

MÉTHODES SECONDAIRES

  • set_error($error_handler) : Définit un gestionnaire pour les erreurs d'analyse.
  • set_debug($debug_handler) : Définit un gestionnaire pour les messages de débogage.

MÉTHODES TERIAIRES

  • visit_paragraph($text) : Méthode appelée lors de la visite d'un paragraphe. (Peut être surchargée par des sous-classes).
  • visit_verbatim($text) : Méthode appelée lors de la visite d'un bloc de texte verbatim. (Peut être surchargée).

ENCODAGE

Pod::Simple prend en charge l'encodage UTF-8 pour les documents Pod.

VOIR AUSSI

perlpod, Pod::Simple::Framework, Pod::Simple::Search, Pod::Simple::HTML.
