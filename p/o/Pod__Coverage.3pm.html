Pod::Coverage(3) Documentation Perl fournie par l'utilisateur Pod::Coverage(3)

NOM

Pod::Coverage - Vérifie si la documentation d'un module est complète

SYNOPSIS

# au début...
perl -MPod::Coverage=Pod::Coverage -e666
# en une seule invocation
use Pod::Coverage package => 'Fishy';
# purement orienté objet
use Pod::Coverage;
my $pc = Pod::Coverage->new(package => 'Pod::Coverage');
print "Nous sommes géniaux !" if $pc->coverage == 1;

DESCRIPTION

Les développeurs détestent écrire de la documentation. Ils la détesteraient encore plus si leur ordinateur les dénonçait, mais peut-être qu'ils seront encore plus reconnaissants à long terme. Même si ce n'est pas le cas, perlmodstyle vous le dit, donc vous devez obéir.

Ce module fournit un mécanisme pour déterminer si le pod d'un module donné est complet.

Il s'attend à trouver un bloc "=head(n>1)" ou un bloc "=item" documentant une sous-routine.

Considérez :
# un imaginaire Foo.pm
package Foo;

=item foo
Le sous-programme foo
= cut
sub foo {}
sub bar {}
1;
__END__

Dans cet exemple, "Foo::foo" est couvert, mais "Foo::bar" ne l'est pas, donc le paquet "Foo" n'est couvert qu'à 50 % (0,5)

Méthodes

Pod::Coverage->new(package => $package)
Crée un nouvel objet Pod::Coverage.

"package" le nom du paquet à analyser

"private" un tableau de expressions régulières qui définissent quels symboles sont considérés comme privés (et donc n'ont pas besoin d'être documentés) par défaut : [ qr/^_/, qr/^(un)?import$/, qr/^DESTROY$/, qr/^AUTOLOAD$/, qr/^bootstrap$/,
qr/^(TIE( SCALAR | ARRAY | HASH | HANDLE ) |
FETCH | STORE | UNTIE | FETCHSIZE | STORESIZE |
POP | PUSH | SHIFT | UNSHIFT | SPLICE | DELETE |
EXISTS | EXTEND | CLEAR | FIRSTKEY | NEXTKEY | PRINT | PRINTF |
WRITE | READLINE | GETC | READ | CLOSE | BINMODE | OPEN |
EOF | FILENO | SEEK | TELL | SCALAR )$/x,
qr/^( MODIFY | FETCH )_( REF | SCALAR | ARRAY | HASH | CODE |
GLOB | FORMAT | IO )_ATTRIBUTES$/x,
qr/^CLONE(_SKIP)?$/, ]

Cela devrait couvrir toutes les méthodes magiques habituelles pour les objets tie()d, les attributs, généralement toutes les méthodes qui ne sont typiquement pas appelées par un utilisateur, mais plutôt utilisées en interne par perl.

"also_private" les éléments sont ajoutés à la liste privée

"trustme" un tableau d'expressions régulières qui définissent quels symboles vous voulez simplement que nous supposions qu'ils sont correctement documentés même si nous ne trouvons aucune documentation pour eux

Si "pod_from" est fourni, ce fichier est analysé pour la documentation, plutôt que d'utiliser Pod::Find

Si "nonwhitespace" est fourni, seuls les sections POD contenant des caractères non-blancs seront considérées comme documentées.

$object->coverage
Donne la couverture sous forme d'une valeur comprise entre 0 et 1
$object->why_unrated
"$object->coverage" peut retourner "undef", pour indiquer qu'il n'a pas pu déduire la couverture d'un paquet. Si cela se produit, vous devriez pouvoir vérifier "why_unrated" pour obtenir une excuse utile.
$object->naked/$object->uncovered
Retourne une liste de sous-routines non couvertes, appellera implicitement la couverture si elle n'a pas déjà été appelée.

Notez que les identificateurs privés et 'trustme' seront ignorés.

$object->covered
Retourne une liste de sous-routines couvertes, appellera implicitement la couverture si elle n'a pas déjà été appelée.

Comme avec "naked", les identificateurs privés et 'trustme' seront ignorés.

Support de débogage

Afin de permettre le débogage interne, tout en permettant à l'optimiseur de faire son travail, "Pod::Coverage" utilise des sous-constantes pour définir comment il trace.

Utilisez-les comme ceci

sub Pod::Coverage::TRACE_ALL () { 1 }
use Pod::Coverage;

Les constantes supportées sont :

TRACE_ALL
Traçage de tout.

Eh bien, c'est tout ce qu'il y a pour l'instant, êtes-vous content d'être venu ?

Interface d'héritage

Ces méthodes abstraites, bien que fonctionnelles dans "Pod::Coverage", peuvent vous faciliter la vie si vous souhaitez étendre "Pod::Coverage" pour qu'il corresponde mieux à votre style interne.

NOTE Veuillez considérer cette interface comme en cours de modification jusqu'à ce que ce commentaire disparaisse.

$object->_CvGV($symbol)
Retourne le GV pour le coderef fourni. Utilisé par "_get_syms" pour identifier le code défini localement.

Vous n'aurez probablement pas besoin de remplacer celle-ci.

$object->_get_syms($package)
retourne une liste de symboles à vérifier à partir du paquet spécifié
_get_pods
Extrait les marqueurs de pod du paquet actuellement actif.

Retourne un typereference ou undef en cas d'échec.

_private_check($symbol)
retourne vrai si le symbole doit être considéré comme privé
_trustme_check($symbol)
retourne vrai si le symbole est un symbole 'trustme'

BOGUES

En raison de la méthode utilisée pour identifier les sous-routines documentées, "Pod::Coverage" peut complètement ignorer votre style interne et déclarer votre code non documenté. Les correctifs et/ou les tests échoués sont les bienvenus.

À FAIRE

Élargir les règles pour identifier la documentation
Améliorer la couverture de code de la suite de tests. "Devel::Cover" déchire tellement.

VOIR AUSSI

Test::More, Devel::Cover
