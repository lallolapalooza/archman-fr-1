NOM

POE::Component::IKC::ClientLite - Petit client pour IKC

SYNTAXE

use POE::Component::IKC::ClientLite;
$poe = POE::Component::IKC::ClientLite->new(port=>1337);
die POE::Component::IKC::ClientLite::error() unless $poe;
$poe->post("Session/event", $param)
    or die $poe->error;

# mauvaise façon de récupérer une valeur de retour
my $foo=$poe->call("Session/other_event", $param)
    or die $poe->error;
# meilleure façon de récupérer une valeur de retour
my $ret=$poe->post_respond("Session/other_event", $param)
    or die $poe->error;
# s'assurer que la connexion est active
$poe->ping() 
    or $poe->disconnect;

DESCRIPTION

ClientLite est un client léger, une implémentation Perl pure pour IKC. Il est très basique car il est destiné à être utilisé dans des endroits où POE ne convient pas, comme mod_perl.

Il gère la reconnexion automatique. Lorsque vous envoyez un événement, ClientLite essaie d'envoyer le paquet sur le réseau. Si cela échoue, il essaie de se reconnecter. S'il ne peut pas, il renvoie une erreur. S'il le peut, il renverra le paquet. Si cela échoue, désolé.

MÉTHODES

spawn

my $poe = POE::Component::IKC::ClientLite->spawn( %params );

Crée un objet POE::Component::IKC::ClientLite. Les paramètres sont compatibles avec POE::Component::IKC::Client, mais les sockets Unix ne sont pas encore gérés... De plus, il y a 3 paramètres supplémentaires :

block_size
Taille, en octets (unités de 8 bits), de chaque bloc lu depuis le socket. La valeur par défaut est 65535.
timeout
Le temps, en secondes, que "call" et "post_respond" attendront une réponse. La valeur par défaut est 30 secondes.
connect_timeout
Le temps, en secondes, pendant lequel la phase de négociation de la connexion est attendue. La valeur par défaut est "timeout". Il y a 4 phases de négociation, donc un temps de "connect_timeout" de 30 secondes peut potentiellement prendre 2 minutes pour se connecter.
protocol
Quel protocole de négociation IKC utiliser. L'original ("IKC") était synchrone et lent. Le nouveau protocole ("IKC0") envoie toutes les informations en une seule fois. Le protocole IKC0 rétrogradera en douceur vers IKC si le client et le serveur ne correspondent pas.

connect

$poe->connect or die $poe->error;

Se connecte au kernel distant s'il n'est pas déjà connecté. Vous pouvez utiliser cette méthode pour vous assurer que la connexion est ouverte avant d'essayer quoi que ce soit.

Renvoie true si la connexion a réussi, false sinon. Vous pouvez consulter le problème avec "error" pour savoir quel était le problème.

disconnect

Se déconnecte du serveur IKC distant.

error

my $error=POE::Component::IKC::ClientLite::error();
$error=$poe->error();

Renvoie la dernière erreur. Peut être appelé en tant que méthode objet ou fonction globale.

post

$poe->post($specifier, $data);

Envoie l'événement spécifié par $specifier au kernel distant. $data est tout paramètre que vous souhaitez envoyer avec l'événement. Renvoie 1 en cas de succès (c'est-à-dire que les données ont pu être envoyées... pas nécessairement que l'événement a été reçu) et undef si nous n'avons pas pu nous connecter ou nous reconnecter au kernel distant.

post_respond

my $ret=$poe->post_respond($specifier, $data);

Envoie l'événement spécifié par $specifier au kernel distant. $data est tout paramètre que vous souhaitez envoyer avec l'événement. Attend que le kernel distant envoie un message et renvoie sa charge utile. Le temps d'attente est prolongé selon la valeur que vous avez passée à POE::Component::IKC::Client->spawn.

Les événements de l'autre côté doivent être conscients de post_respond. En particulier, ARG0 n'est pas $data comme vous vous y attendriez, mais un arrayref contenant $data suivi d'un spécificateur qui doit être utilisé pour poster en retour.

sub my_event
{
    my($kernel, $heap, $args)=@_[KERNEL, HEAP, ARG0];
    my $p=$args->[0];
    $heap->{rsvp}=$args->[1];
    # ... faire beaucoup de travail ici
}
# finalement, nous avons terminé
sub finished
{
    my($kernel, $heap, $return)=@_[KERNEL, HEAP, ARG0];
    $kernel->post(IKC=>'post', $heap->{rsvp}, $return);
}

responded

my $ret = $poe->responded( $state );
my @ret = $poe->responded( $state );

Attend l'état $state du kernel distant. $state doit être un état simple. Toute requête du kernel distant pour d'autres états sera rejetée. Un gestionnaire distant répondra en utilisant l'expéditeur proxy.

call

my $ret=$poe->call($specifier, $data);

C'est la mauvaise façon d'obtenir des informations d'un événement distant. Il suit la sémantique attendue de POE standard. Il fonctionne mieux que post_respond, mais ne vous oblige pas à modifier votre interface ou à écrire un wrapper.

ping

unless($poe->ping) {
    # la connexion est déconnectée! la connexion est déconnectée!
}

Sommes-nous connectés au kernel distant ? Cette méthode NE tentera PAS de se reconnecter au serveur.

name

Renvoie notre nom local. C'est ainsi que le kernel distant nous appelle. Je ne peux pas vraiment dire que c'est le nom du kernel distant, car, eh bien, ce n'est pas vraiment un kernel. Mais bon.
