Pod::Simple::XHTML(3perl) Manuel développeur Perl Pod::Simple::XHTML(3perl)

NOM

Pod::Simple::XHTML — Formater du Pod en XHTML valide

SYNOPSIS

use Pod::Simple::XHTML;
my $parser = Pod::Simple::XHTML->new();
...
$parser->parse_file('chemin/vers/fichier.pod');

DESCRIPTION

Cette classe est un formatteur qui prend du Pod et le rend en HTML XHTML valide.

Cette classe est une sous-classe de Pod::Simple::Methody et hérite de toutes ses méthodes. L'implémentation est complètement différente de celle de Pod::Simple::HTML, mais elle préserve presque l'interface.

Code minimal

use Pod::Simple::XHTML;
my $psx = Pod::Simple::XHTML->new;
$psx->output_string(\my $html);
$psx->parse_file('chemin/vers/Module/Nom.pm');
open my $out, '>', 'sortie.html' or die "Impossible d'ouvrir 'sortie.html': $!\n";
print $out $html;

Vous pouvez aussi contrôler l'encodage des caractères et des entités. Par exemple, si vous êtes sûr que le POD est correctement encodé (en utilisant la directive "=encoding"), vous pouvez empêcher l'encodage des caractères à bit élevé en entités HTML et déclarer le jeu de caractères de sortie comme UTF-8 avant de parser, comme suit :

  $psx->html_charset('UTF-8');
use warnings;
  $psx->html_encode_chars(q{&<>'"});

MÉTHODES

Pod::Simple::XHTML offre plusieurs méthodes qui modifient le formatage du HTML de sortie. Appelez-les après avoir créé l'objet parser, mais avant d'appeler "parse_file":

my $parser = Pod::PseudoPod::HTML->new();
$parser->set_optional_param("valeur");
$parser->parse_file($fichier);

perldoc_url_prefix

Que faut-il mettre avant "Foo%3a%3aBar" lors de la conversion de Foo::Bar en http://whatever/Foo%3a%3aBar ? Par défaut : "https://metacpan.org/pod/".

perldoc_url_postfix

Que faut-il mettre après "Foo%3a%3aBar" dans l'URL ? Cette option n'a pas de valeur par défaut.

man_url_prefix

Que faut-il mettre avant "1/crontab" lors de la conversion de "crontab" (5) en http://whatever/man/1/crontab ? Par défaut : "http://man.he.net/man".

man_url_postfix

Que faut-il mettre après "1/crontab" dans l'URL ? Cette option n'a pas de valeur par défaut.

title_prefix, title_postfix

Que faut-il mettre avant et après le titre dans la balise `` ? Les valeurs doivent déjà être échappées avec `&`.

html_css

$parser->html_css('chemin/vers/style.css');

L'URL ou le chemin relatif d'un fichier CSS à inclure. Cette option n'a pas de valeur par défaut.

html_javascript

L'URL ou le chemin relatif d'un fichier JavaScript à inclure. Cette option n'a pas de valeur par défaut.

html_doctype

La balise du type de document pour le fichier. Cette option n'a pas de valeur par défaut.

html_charset

Le jeu de caractères à déclarer dans la balise meta content-type par défaut pour "html_header_tags". Note : Cette option sera ignorée si la valeur de "html_header_tags" est modifiée. La valeur par défaut est "ISO-8859-1".

html_header_tags

Balises HTML supplémentaires pour l'en-tête du document. La valeur par défaut est juste une balise content-type :

<meta http-equiv="Content-Type" content="text/html; charset=ISO-8859-1">

Ajoutez d'autres balises meta ici, ou des blocs CSS ou JavaScript (encapsulés dans les balises appropriées).

html_encode_chars

Une chaîne de caractères contenant tous les caractères qui doivent être encodés en entités HTML, spécifiés en utilisant la syntaxe des classes de caractères d'expressions régulières (ce qui se trouve entre crochets dans les expressions régulières). Cette valeur est passée comme deuxième argument à la fonction "encode_entities" de HTML::Entities. Si HTML::Entities n'est pas installé, tout caractère autre que &lt; et &gt; sera encodé numériquement.

html_h_level

C'est le niveau de l'élément HTML "Hn" auquel correspond un "head1" de Pod. Par exemple, si "html_h_level" est défini à 2, un head1 produira un H2, un head2 un H3, et ainsi de suite.

default_title

Définit un titre par défaut pour la page si celui-ci ne peut être déterminé à partir du contenu. La valeur de cette chaîne doit déjà être échappée avec `&`.

force_title

Force un titre pour la page (n'essaie pas de le déterminer à partir du contenu). La valeur de cette chaîne doit déjà être échappée avec `&`.

html_header, html_footer

Définit le HTML de sortie au début et à la fin de chaque fichier. L'en-tête par défaut inclut un titre, une balise doctype (si "html_doctype" est définie), une balise de contenu (personnalisée par "html_header_tags"), une balise CSS (si "html_css" est définie) et une balise JavaScript (si "html_javascript" est définie). Le pied de page par défaut ferme les balises "html" et "body".

Les options mentionnées ci-dessus personnalisent des parties de l'en-tête par défaut, mais la définition de "html_header" ou "html_footer" remplace complètement l'en-tête ou le pied de page par défaut. Cela peut être utile si vous souhaitez utiliser des balises de template au lieu de HTML statique ou si vous intégrez des pages converties depuis du POD dans un site web plus large.

Si vous ne souhaitez afficher ni en-tête ni pied de page dans le HTML, définissez ces options à une chaîne vide.

index

Inclure une table des matières sur chaque page (appelée index par tradition) ?

anchor_items

Ancrer chaque directive "=item" de définition ? Ceci doit être activé si vous souhaitez créer des liens spécifiques vers les directives "=item", qui apparaissent comme des éléments "<dt>". Désactivé par défaut.

backlink

Créer un lien vers le début de la page pour chaque directive "head1" ?

SOUS-CLASSEMENT

Si les options standard ne suffisent pas, vous pourriez vouloir hériter de Pod::Simple::XHMTL. Ce sont les méthodes les plus susceptibles d'être remplacées lorsque vous héritez.

handle_text

Cette méthode traite le corps du texte à l'intérieur de n'importe quel élément : c'est le corps d'un paragraphe, ou tout ce qui se trouve entre une balise « =begin » et la balise « =end » correspondante, ou le texte à l'intérieur d'une entité L, etc. Vous voudriez remplacer cette méthode si vous ajoutez un type d'élément personnalisé qui fait plus que simplement afficher du texte formaté. Peut-être ajouter un moyen de générer des tableaux HTML à partir d'une version étendue de POD.

Ainsi, disons que vous voulez ajouter un élément personnalisé appelé « foo ». Dans la méthode "new" de votre sous-classe, après avoir appelé "SUPER::new", vous appelleriez :

$new->accept_targets_as_text( 'foo' );

Ensuite, remplacez la méthode "start_for" dans la sous-classe pour vérifier quand « $flags->{'target'} » est égal à « 'foo' » et définissez un indicateur qui marque que vous êtes dans un bloc foo (peut-être « $self->{'in_foo'} = 1 »). Ensuite, remplacez la méthode "handle_text" pour vérifier l'indicateur, et passez $text à votre sous-routine personnalisée pour construire la sortie HTML pour les éléments « foo », quelque chose comme :

sub handle_text {
    my ($self, $text) = @_;
    if ($self->{'in_foo'}) {
        $self->{'scratch'} .= build_foo_html($text);
        return;
    }
    $self->SUPER::handle_text($text);
}

handle_code

Cette méthode traite le corps du texte marqué comme code. Vous pourriez, par exemple, la remplacer pour intégrer un surligneur de syntaxe. L'implémentation de base échappe simplement le texte.

Les méthodes de rappel "start_code" et "end_code" émettent les balises "code" avant et après l'invocation de "handle_code", vous pourriez donc vouloir les remplacer avec "handle_code" si cet emballage ne convient pas.

Notez que le code peut être divisé en plusieurs segments s'il y a des codes de formatage imbriqués dans une séquence "C<...>". Entre les appels à "handle_code", d'autres balises de balisage pourraient avoir été émises dans ce cas. Il en va de même pour les sections verbatim si l'option "codes_in_verbatim" est activée.

accept_targets_as_html

Cette méthode se comporte comme "accept_targets_as_text", mais marque également la région comme une région dont le contenu doit être émis littéralement, sans échappement d'entités HTML ni emballage dans un élément "div".

resolve_pod_page_link

my $url = $pod->resolve_pod_page_link('Net::Ping', 'INSTALL');
my $url = $pod->resolve_pod_page_link('perlpodspec');
my $url = $pod->resolve_pod_page_link(undef, 'SYNOPSIS');

Résout une cible de lien POD (typiquement un nom de module ou de fichier POD) et un nom de section en une URL. Le lien résultant sera retourné pour les exemples ci-dessus comme :

https://metacpan.org/pod/Net::Ping#INSTALL
https://metacpan.org/pod/perlpodspec
#SYNOPSIS

Notez que lorsqu'il n'y a qu'un argument de section, l'URL sera simplement un lien vers une section du document actuel.

resolve_man_page_link

my $url = $pod->resolve_man_page_link('crontab(5)', 'EXAMPLE CRON FILE');
my $url = $pod->resolve_man_page_link('crontab');

Résout une cible de lien de page man et une section numérique en une URL. Le lien résultant sera retourné pour les exemples ci-dessus comme :

http://man.he.net/man5/crontab
http://man.he.net/man1/crontab

Notez que le premier argument est requis. Le numéro de section sera analysé à partir de celui-ci, et s'il est manquant, il sera par défaut à 1. Le deuxième argument est actuellement ignoré, car le site man.he.net http://man.he.net n'inclut actuellement pas d'identifiants ou de noms d'ancres sur lesquels on peut cliquer sur ses pages. Remplacez cette méthode pour lier vers un autre serveur de pages man.

idify

my $id   = $pod->idify($text);
my $hash = $pod->idify($text, 1);

Cette méthode transforme une chaîne arbitraire en une valeur d'attribut d'ID XHTML valide. Les règles appliquées, suivant http://webdesign.about.com/od/htmltags/a/aa031707.htm, sont :

  • L'id doit commencer par une lettre (a-z ou A-Z)
  • Tous les caractères suivants peuvent être des lettres, des chiffres (0-9), des tirets (-), des traits de soulignement (_), des deux-points (:) et des points (.).
  • Le dernier caractère ne peut pas être un tiret, un deux-points ou un point. Les URL se terminant par ces caractères, bien qu'autorisées par XHTML, peuvent être difficiles à extraire de texte brut.
  • Chaque id doit être unique dans le document.

De plus, la valeur retournée sera unique dans le contexte de l'objet Pod::Simple::XHTML, sauf si un deuxième argument est passé avec une valeur vraie. Les attributs d'ID doivent toujours être uniques dans un seul document XHTML, mais passez la valeur vraie si vous créez non pas un ID mais un hachage d'URL pour pointer vers un ID (c'est-à-dire si vous devez mettre « #foo » dans "<a href="#foo">foo</a>").

batch_mode_page_object_init

$pod->batch_mode_page_object_init($batchconvobj, $module, $infile, $outfile, $depth);

Appelée par Pod::Simple::HTMLBatch afin que la classe ait une chance d'initialiser le convertisseur. En interne, elle définit la propriété "batch_mode" à vrai et définit batch_mode_current_level(), mais Pod::Simple::XHTML n'utilise pas actuellement ces fonctionnalités. Les sous-classes pourraient le faire, cependant.
