Pod::Usage(3perl) Manuel des développeurs Perl Pod::Usage(3perl)

NOM

Pod::Usage - extrait la documentation POD et affiche les informations d'utilisation

SYNOPSIS

use Pod::Usage;
my $message_text  = "Ce texte précède le message d'utilisation.";
my $exit_status   = 2;          ## Le code de sortie à utiliser
my $verbose_level = 0;          ## Le niveau de verbosité à utiliser
my $filehandle    = \*STDERR;   ## Le fichier de sortie à utiliser
pod2usage($message_text);
pod2usage($exit_status);
pod2usage( { -message => $message_text ,
             -exitval => $exit_status  ,
             -verbose => $verbose_level,
             -output  => $filehandle } );
pod2usage(   -msg     => $message_text ,
             -exitval => $exit_status  ,
             -verbose => $verbose_level,
             -output  => $filehandle );
pod2usage(   -verbose => 2,
             -noperldoc => 1  );
pod2usage(   -verbose => 2,
             -perlcmd => $path_to_perl,
             -perldoc => $path_to_perldoc,
             -perldocopt => $perldoc_options );

ARGUMENTS

pod2usage doit recevoir un seul argument ou une liste d'arguments correspondant à un tableau associatif (un "hash"). Lorsqu'un argument unique est donné, il doit correspondre exactement à l'un des éléments suivants :

  • Une chaîne contenant le texte d'un message à imprimer *avant* le message d'utilisation
  • Une valeur numérique correspondant au code de sortie désiré
  • Une référence à un hash

Si plus d'un argument est donné, la liste complète est supposée être un hash. Si un hash est fourni (soit en tant que référence, soit en tant que liste), il doit contenir un ou plusieurs éléments avec les clés suivantes :

-message string
-msg string
Le texte d'un message à imprimer *immédiatement avant* le message d'utilisation du programme.
-exitval valeur
Le code de sortie désiré à passer à la fonction exit(). Ce doit être un entier, ou sinon la chaîne "NOEXIT" pour indiquer que le contrôle doit simplement revenir sans terminer le processus appelant.
-verbose valeur
Le niveau de "verbosité" désiré à utiliser lors de l'impression du message d'utilisation. Si la valeur est 0, seules les sections SYNOPSIS et/ou USAGE de la documentation POD seront imprimées. Si la valeur est 1, les sections SYNOPSIS et/ou USAGE seront imprimées, ainsi que toute section intitulée OPTIONS, ARGUMENTS ou OPTIONS AND ARGUMENTS. Si la valeur correspondante est 2 ou plus, l'intégralité de la page de manuel sera imprimée, en utilisant perldoc si disponible; sinon, Pod::Text sera utilisé pour le formatage. Pour une meilleure lisibilité, les titres en majuscules seront convertis en majuscule en première lettre et le reste en minuscules, par exemple SYNOPSIS => Synopsis.
-sections spéc
Il existe deux façons de spécifier la sélection. Soit une chaîne (scalaire) représentant une sélection regex pour les sections à imprimer lorsque -verbose est 99, par exemple : 
NAME|SYNOPSIS|DESCRIPTION|VERSION
,
avec le regex ci-dessus, tout le contenu suivant (et inclus) de toute section "=head1" sera affiché. Il est possible de limiter la sortie à des sous-sections spécifiques, par exemple :
DESCRIPTION/Algorithm
Cette sortie n'affichera que la section "=head2 Algorithm" et le contenu de la section "=head1 DESCRIPTION". Le lien regex est plus fort que le séparateur de section, donc par exemple :
DESCRIPTION|OPTIONS|ENVIRONMENT/Caveats
n'affichera que la section "=head2 Caveats" (uniquement) au sein de l'une des trois sections "=head1".
Alternativement, une référence de tableau de spécifications de sections peut être utilisée :
pod2usage(-verbose => 99, -sections => [
  qw(DESCRIPTION DESCRIPTION/Introduction) ] );
Cette sortie n'affichera que le contenu de la section "=head1 DESCRIPTION" et de la section "=head2 Introduction", mais pas d'autres "=head2", ni d'autres "=head1".
-output handle
Une référence de fichier de sortie, ou le nom d'un fichier vers lequel le message d'utilisation doit être écrit. La valeur par défaut est "\*STDERR", sauf lorsque le code de sortie est inférieur à 2 (auquel cas la valeur par défaut est "\*STDOUT").
-input handle
Une référence de fichier d'entrée, ou le nom d'un fichier à partir duquel la documentation du script exécuté doit être lue. La valeur par défaut est le fichier désigné par $0 ($PROGRAM_NAME pour les utilisateurs de English.pm).
-pathlist string
Une liste de répertoires. Si le fichier d'entrée n'existe pas, il sera recherché dans les répertoires donnés (dans l'ordre des répertoires de la liste). La valeur par défaut est la liste des répertoires implicites par $ENV{PATH}. La liste peut être spécifiée par une référence à un tableau, ou par une chaîne de répertoires utilisant le même séparateur que $ENV{PATH} sur votre système (par exemple, ":" pour Unix, ";" pour MSWin32 et DOS).
-noperldoc
Par défaut, Pod::Usage appelle perldoc lorsque -verbose est >= 2. Cela ne fonctionne pas bien si le script a été packagé avec PAR. Cette option supprime l'appel externe à perldoc et utilise le simple formateur (Pod::Text) pour afficher le POD.
-perlcmd
Par défaut, Pod::Usage appelle perldoc lorsque -verbose est >= 2. En cas d'installations Perl spéciales ou non standards, cette option peut être utilisée pour spécifier le chemin de l'exécutable Perl qui doit exécuter perldoc.
-perldoc
Par défaut, Pod::Usage appelle perldoc lorsque -verbose est >= 2. Si perldoc n'est pas installé là où l'interpréteur Perl pense qu'il est (voir Config), l'option -perldoc peut être utilisée pour spécifier le chemin correct de perldoc.
-perldocopt
Par défaut, Pod::Usage appelle perldoc lorsque -verbose est >= 2. Cette option peut être utilisée pour spécifier des options à perldoc. La chaîne peut contenir plusieurs options, séparées par des espaces.

Classe de base de formatage

Le formateur par défaut est Pod::Text. La classe de base pour Pod::Usage peut être définie au préalable en définissant $Pod::Usage::Formatter *avant* de charger Pod::Usage, par exemple :

BEGIN { $Pod::Usage::Formatter = 'Pod::Text::Termcap'; }
use Pod::Usage qw(pod2usage);

Le module Pod::Usage utilise la méthode _handle_element_end() de Pod::Simple pour implémenter la sélection de sections, et dans le cas de -verbose <<= 2, il met en majuscule la première lettre et le reste en minuscules, et ajoute un point ou une virgule à la fin des titres, pour une meilleure lisibilité. Ceci s'applique également à -verbose = 99.

Options de passage

Les options suivantes sont transmises au formateur sous-jacent. Consultez les pages de manuel de ces modules pour plus d'informations.

alt code indent loose margin quotes sentence stderr utf8 width

DESCRIPTION

La fonction pod2usage imprimera un message d'utilisation pour le script appelant, en utilisant sa documentation POD, puis s'arrêtera avec le code de sortie désiré. Le message d'utilisation peut avoir l'un des trois niveaux de "verbosité" : Si le niveau de verbosité est 0, seule la syntaxe sera imprimée. Si le niveau de verbosité est 1, la syntaxe et/ou la section d'utilisation seront imprimées, ainsi que toute section intitulée OPTIONS, ARGUMENTS ou OPTIONS AND ARGUMENTS. Si la valeur correspondante est 2 ou plus, l'intégralité de la page de manuel sera imprimée, en utilisant perldoc si disponible; sinon, Pod::Text sera utilisé pour le formatage. Pour une meilleure clarté, les titres en majuscules seront convertis en majuscule en première lettre et le reste en minuscules, par exemple SYNOPSIS => Synopsis.

Le niveau spécial 99 nécessite également la spécification du paramètre -sections; ces sections seront alors extraites et imprimées.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Garder la structure du fichier. Si la valeur de `vel` est 1, le résumé et une description (si elle est présente) des options et arguments de la ligne de commande sont imprimés. Si le niveau de verbosité est 2, la page de manuel entière est imprimée. Sauf indication contraire explicite, les valeurs par défaut pour le code de sortie, le niveau de verbosité et le flux de sortie sont déterminées comme suit : - Si ni le code de sortie ni le niveau de verbosité ne sont spécifiés, la valeur par défaut est un code de sortie de 2 avec un niveau de verbosité de 0. - Si un code de sortie est spécifié mais que le niveau de verbosité ne l'est pas, le niveau de verbosité sera par défaut à 1 si le code de sortie est inférieur à 2, et à 0 sinon. - Si le code de sortie n'est pas spécifié mais que le niveau de verbosité l'est, le code de sortie sera par défaut à 2 si le niveau de verbosité est 0, et à 1 sinon. - Si le code de sortie utilisé est inférieur à 2, la sortie est imprimée sur STDOUT, sinon sur STDERR. Bien que le contenu ci-dessus puisse sembler un peu déroutant au début, il fait généralement la bonne chose dans la plupart des cas. Cette détermination des valeurs par défaut est basée sur les conventions Unix typiques suivantes : - Un code de sortie de 0 implique un « succès ». Par exemple, diff(1) se termine avec un code de sortie 0 si les deux fichiers ont un contenu identique. - Un code de sortie de 1 implique une fin de programme anormale mais pas défectueuse. Par exemple, grep(1) se termine avec un code de sortie 1 s'il ne trouve pas de ligne correspondant à l'expression régulière donnée. - Un code de sortie de 2 ou plus implique une erreur grave. Par exemple, ls(1) se termine avec un code de sortie 2 si une option invalide (inexistante) est spécifiée sur la ligne de commande. - Les messages d'utilisation émis en raison d'une erreur de syntaxe sur la ligne de commande doivent aller vers STDERR. Cependant, les messages d'utilisation émis en raison d'une demande explicite d'impression de l'utilisation (comme la spécification de -help sur la ligne de commande) doivent aller vers STDOUT, au cas où l'utilisateur souhaiterait rediriger la sortie vers un pager (comme more(1)). - Si l'utilisation du programme a été explicitement demandée par l'utilisateur, il est souvent souhaitable de se terminer avec un code de sortie de 1 (au lieu de 0) après avoir imprimé le message d'utilisation demandé par l'utilisateur. Il est également souhaitable de fournir une description plus détaillée de l'utilisation du programme dans ce cas. pod2usage ne vous impose pas ces conventions, mais utilisera ces conventions par défaut si vous ne lui donnez pas d'indications explicites. La capacité de pod2usage() à accepter un nombre ou une chaîne le rend pratique à utiliser comme fonction de gestion d'erreurs inoffensive : ```perl use strict; use Pod::Usage; use Getopt::Long; ## Parse options my %opt; GetOptions(\%opt, "help|?", "man", "flag1") || pod2usage(2); pod2usage(1) if ($opt{help}); pod2usage(-exitval => 0, -verbose => 2) if ($opt{man}); ## Check for too many filenames pod2usage("$0: Too many files given.\n") if (@ARGV > 1); ``` Certains utilisateurs peuvent estimer que « l'économie d'expression » ci-dessus n'est pas particulièrement lisible ou cohérente et préfèrent faire quelque chose de plus similaire à ce qui suit : ```perl use strict; use Pod::Usage qw(pod2usage); use Getopt::Long qw(GetOptions); ## Parse options my %opt; GetOptions(\%opt, "help|?", "man", "flag1") || pod2usage(-verbose => 0); pod2usage(-verbose => 1) if ($opt{help}); pod2usage(-verbose => 2) if ($opt{man}); ## Check for too many filenames pod2usage(-verbose => 2, -message => "$0: Too many files given.\n") if (@ARGV > 1); ``` Comme pour tout dans Perl, il y a plus d'une façon de faire les choses, et pod2usage() suit cette philosophie. Si vous voulez voir un certain nombre de façons différentes d'appeler pod2usage (bien qu'elle ne soit pas exhaustive), veuillez vous référer à "EXAMPLES". ### Scripts La distribution Pod::Usage inclut un script appelé pod2usage qui offre une interface en ligne de commande pour la fonctionnalité de Pod::Usage. Voir pod2usage. ### Exemples Chaque appel à pod2usage() suivant imprimera uniquement la section SYNOPSIS sur STDERR et se terminera avec le code de sortie 2 : ```perl pod2usage(); pod2usage(2); pod2usage(-verbose => 0); pod2usage(-exitval => 2); pod2usage({-exitval => 2, -output => \*STDERR}); pod2usage({-verbose => 0, -output => \*STDERR}); pod2usage(-exitval => 2, -verbose => 0); pod2usage(-exitval => 2, -verbose => 0, -output => \*STDERR); ``` Chaque appel à pod2usage() suivant imprimera un message d'erreur "Syntax error." (avec un retour à la ligne) sur STDERR, suivi de la section SYNOPSIS (également imprimée sur STDERR) et se terminera avec le code de sortie 2 : ```perl pod2usage("Syntax error."); pod2usage(-message => "Syntax error.", -verbose => 0); pod2usage(-msg => "Syntax error.", -exitval => 2); pod2usage({-msg => "Syntax error.", -exitval => 2, -output => \*STDERR}); pod2usage({-msg => "Syntax error.", -verbose => 0, -output => \*STDERR}); pod2usage(-msg => "Syntax error.", -exitval => 2, -verbose => 0); pod2usage(-message => "Syntax error.", -exitval => 2, -verbose => 0, -output => \*STDERR); ``` Chaque appel à pod2usage() suivant imprimera la section SYNOPSIS et toute section d'options ou d'arguments sur STDOUT et se terminera avec le code de sortie 1 : ```perl pod2usage(1); pod2usage(-verbose => 1); pod2usage(-exitval => 1); pod2usage({-exitval => 1, -output => \*STDOUT}); pod2usage({-verbose => 1, -output => \*STDOUT}); pod2usage(-exitval => 1, -verbose => 1); pod2usage(-exitval => 1, -verbose => 1, -output => \*STDOUT); ``` Chaque appel à pod2usage() suivant imprimera la page de manuel entière sur STDOUT et se terminera avec le code de sortie 1 : ```perl pod2usage(-verbose => 2); pod2usage({-verbose => 2, -output => \*STDOUT}); pod2usage(-exitval => 1, -verbose => 2); pod2usage({-exitval => 1, -verbose => 2, -output => \*STDOUT}); ``` ### Utilisation recommandée Les scripts doivent imprimer un message d'utilisation sur STDERR en cas d'erreur de syntaxe sur la ligne de commande. Ils doivent également fournir une option (généralement -H ou -help) pour imprimer un message d'utilisation (probablement plus détaillé) sur STDOUT. Certains scripts peuvent même permettre d'imprimer leur documentation complète sur STDOUT (probablement via une option -man). L'exemple complet suivant utilise Pod::Usage conjointement avec Getopt::Long pour tout faire cela : ```perl use strict; use Getopt::Long qw(GetOptions); use Pod::Usage qw(pod2usage); my $man = 0; my $help = 0; ## Parse options and print usage if there is a syntax error, ## or if usage was explicitly requested. GetOptions('help|?' => \$help, man => \$man) or pod2usage(2); pod2usage(1) if $help; pod2usage(-verbose => 2) if $man; ## If no arguments were given, then allow STDIN to be used only ## if it's not connected to a terminal (otherwise print usage) pod2usage("$0: No files given.") if ((@ARGV == 0) && (-t STDIN)); __END__ =head1 NAME sample - Using GetOpt::Long and Pod::Usage =head1 SYNOPSIS sample [options] [file ...] Options: -help brief help message -man full documentation =head1 OPTIONS =over 4 =item B<-help> Prints a brief help message and exits. =item B<-man> Prints the manual page and exits. =back =head1 DESCRIPTION This program will read the given input file(s) and do something useful with the contents thereof. =cut ``` ### LIMITATIONS Par défaut, pod2usage() utilisera $0 comme chemin d'accès au fichier de documentation pod. Heureusement, tous les systèmes sur lesquels Perl s'exécute ne définiront pas $0 correctement (bien que si $0 n'est pas trouvé, pod2usage() recherchera dans $ENV{PATH} ou la liste spécifiée par l'option -pathlist). Si c'est le cas pour votre système, vous pourriez avoir besoin de spécifier explicitement le chemin d'accès aux documents pod pour le script appelé avec quelque chose de similaire à ce qui suit : ```perl pod2usage(-exitval => 2, -input => "/path/to/your/pod/docs"); ``` Dans le cas pathologique où un script est appelé par un nom de chemin relatif et que le script lui-même modifie le répertoire courant (voir "chdir" dans perlfunc) avant d'appeler pod2usage(), Pod::Usage échouera même sur des plateformes robustes. Ne faites pas cela. Ou utilisez FindBin pour localiser le script : ```perl use FindBin; pod2usage(-input => $FindBin::Bin . "/" . $FindBin::Script); ``` ### SUPPORT Ce module est géré sur un dépôt GitHub, https://github.com/Dual-Life/Pod-Usage Vous pouvez forker et contribuer, ou cloner et soumettre des correctifs !
