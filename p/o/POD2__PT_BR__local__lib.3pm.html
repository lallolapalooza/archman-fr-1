NOM

local::lib~[pt_br] - créez et utilisez un répertoire lib/ local pour les modules Perl avec PERL5LIB

SYNOPSE

Dans le code -

use local::lib; # configure un lib local dans ~/perl5
use local::lib '~/foo'; # idem, mais ~/foo
# Ou...
use FindBin;
use local::lib "$FindBin::Bin/../support";  # bibliothèques de support locales pour l'application

Via la ligne de commande (shell) -

# Installe LWP et ses dépendances non trouvées dans le répertoire '~/perl5'
perl -MCPAN -Mlocal::lib -e 'CPAN::install(LWP)'
# Affiche simplement quelques commandes utiles pour le shell
$ perl -Mlocal::lib
export PERL_MB_OPT='--install_base /home/username/perl5'
export PERL_MM_OPT='INSTALL_BASE=/home/username/perl5'
export PERL5LIB='/home/username/perl5/lib/perl5/i386-linux:/home/username/perl5/lib/perl5'
export PATH="/home/username/perl5/bin:$PATH"

La technique de 'bootstrapping'

Une méthode courante pour installer local::lib est d'utiliser ce qu'on appelle la technique de « bootstrapping ». C'est une bonne approche si votre administrateur système n'a pas installé local::lib. Dans ce cas, vous devrez installer local::lib dans votre répertoire utilisateur.

Si vous avez les privilèges d'administrateur, vous devrez quand même configurer vos variables d'environnement, comme expliqué à l'étape 4 ci-dessous. Sans elles, vous installerez toujours les modules dans le CPAN du système et vos scripts Perl n'utiliseront pas le chemin vers le lib/ que vous avez défini avec local::lib.

Par défaut, local::lib installe les modules CPAN et lui-même dans ~/perl5.

Les utilisateurs Windows doivent lire « Différences lors de l'utilisation de ce module sous Win32 ».

1. Téléchargez et décompressez local::lib depuis CPAN (recherchez « Download » sur la page CPAN de local::lib). Faites-le en tant qu'utilisateur normal, pas en tant que root ou administrateur. Décompressez le fichier dans votre répertoire utilisateur ou à tout autre endroit pratique.

2. Exécutez ceci :

perl Makefile.PL --bootstrap

Si le système vous demande s'il doit tout configurer automatiquement, vous devriez probablement répondre oui.

Pour installer local::lib dans un répertoire autre que celui par défaut, vous devrez le spécifier lors de l'appel au bootstrap, comme suit :

perl Makefile.PL --bootstrap=~/foo

3. Exécutez ceci : (local::lib suppose que vous avez la commande 'make' installée sur votre système)

make test && make install

4. Maintenant, nous devons configurer les variables d'environnement appropriées afin que Perl utilise notre répertoire lib/ nouvellement créé. Si vous utilisez bash ou un autre shell Bourne, vous pouvez le faire en ajoutant la ligne suivante dans votre script d'initialisation de shell :

echo 'eval $(perl -I$HOME/perl5/lib/perl5 -Mlocal::lib)' >>~/.bashrc

Si vous utilisez le shell C, vous pouvez faire ceci :

/bin/csh
echo $SHELL
/bin/csh
perl -I$HOME/perl5/lib/perl5 -Mlocal::lib >> ~/.cshrc

Si vous avez passé un répertoire autre que celui par défaut au bootstrap, vous devrez l'indiquer dans l'appel à local::lib, comme ceci :

echo 'eval $(perl -I$HOME/foo/lib/perl5 -Mlocal::lib=$HOME/foo)' >>~/.bashrc

Après avoir mis à jour votre fichier de configuration de shell, assurez-vous de le recharger pour que les modifications prennent effet dans votre shell actuel. Les shells Bourne utilisent « . ~/.bashrc » pour cela, tandis que les shells C utilisent « source ~/.cshrc ».

Si vous êtes sur une machine lente ou si vous avez des contraintes d'espace disque importantes, vous pouvez désactiver la génération automatique de manpages à partir du POD lors de l'installation de modules. Pour ce faire, il suffit de passer l'argument « --no-manpages » lors du bootstrap :

perl Makefile.PL --bootstrap --no-manpages

Pour éviter d'avoir à faire plusieurs bootstraps pour différents environnements de modules Perl sur le même compte utilisateur - par exemple si vous utilisez local::lib pour développer différentes applications indépendantes - vous pouvez utiliser une seule installation bootstrap de local::lib pour installer des modules dans différents répertoires comme suit :

cd ~/monrepdossier1
perl -Mlocal::lib=./
eval $(perl -Mlocal::lib=./)  ### Pour configurer l'environnement uniquement dans cette shell
printenv                      ### Voyez que ~/monrepdossier1 est dans PERL5LIB
perl -MCPAN -e install ...    ### Les modules que vous voulez
cd ../monrepdossier2
... REPETEZ ...

Pour plusieurs environnements destinés à plusieurs applications, vous devrez peut-être inclure une version modifiée des instructions « use FindBin » dans l'exemple « Dans le code » ci-dessus. Si vous avez fait quelque chose comme ce qui a été décrit ci-dessus, vous aurez un ensemble de modules Perl dans « ~/monrepdossier1/lib ». Si vous avez un script dans « ~/monrepdossier1/scripts/monscript.pl », vous devrez lui indiquer où trouver les modules que vous avez installés pour lui dans « ~/monrepdossier1/lib ».

Dans « ~/monrepdossier1/scripts/monscript.pl » :

use strict;
use warnings;
use local::lib "$FindBin::Bin/..";  ### pointe vers ~/monrepdossier1 et local::lib trouve le lib/
use lib "$FindBin::Bin/../lib";     ### pointe vers ~/monrepdossier1/lib

Placez cela avant tout bloc BEGIN { ... } qui nécessite les modules installés.

Différences lors de l'utilisation de ce module sous Win32

Pour configurer les variables d'environnement appropriées pour votre session actuelle de « CMD.exe », vous pouvez faire ceci :

C:\>perl -Mlocal::lib
set PERL_MB_OPT=--install_base C:\DOCUME~1\ADMINI~1\perl5
set PERL_MM_OPT=INSTALL_BASE=C:\DOCUME~1\ADMINI~1\perl5
set PERL5LIB=C:\DOCUME~1\ADMINI~1\perl5\lib\perl5;C:\DOCUME~1\ADMINI~1\perl5\lib\perl5\MSWin32-x86-multi-thread
set PATH=C:\DOCUME~1\ADMINI~1\perl5\bin;%PATH%
### Pour configurer l'environnement uniquement pour cette shell
C:\>perl -Mlocal::lib > %TEMP%\tmp.bat && %TEMP%\tmp.bat && del %TEMP%\temp.bat
### au lieu de $(perl -Mlocal::lib=./)

Si vous souhaitez que les configurations d'environnement persistent, vous devrez les ajouter dans le Panneau de configuration -> Système, ou utiliser App::local::lib::Win32Helper.

Le « ~ » est transformé en répertoire de profil utilisateur (le répertoire portant le nom de l'utilisateur dans « Documents and Settings » (Windows XP ou antérieur) ou « Utilisateurs » (Windows Vista et plus récents)) à moins que $ENV{HOME} n'existe. Après cela, le nom du répertoire est raccourci et les sous-répertoires sont créés (ce qui signifie que le répertoire doit exister).

MOTIVATION

La version d'un paquet Perl sur votre machine n'est pas toujours celle dont vous avez besoin. Évidemment, la meilleure chose à faire serait de la mettre à jour vers la version souhaitée. Cependant, vous pourriez être dans une situation qui vous empêche de le faire. Peut-être n'avez-vous pas les privilèges d'administrateur système ; ou peut-être utilisez-vous un système de gestion de paquets comme celui de Debian, et il n'existe pas encore de paquet disponible dans la version souhaitée.

local::lib résout ce problème en permettant la création de votre propre répertoire de paquets Perl obtenus depuis CPAN (sur les systèmes multi-utilisateurs, cela se trouve normalement dans le répertoire de votre utilisateur).   • MOTIVATION

Conserve toda la estructura del archivo.

El módulo ofrece una forma rápida y conveniente para crear un repositorio de módulos locales al usuario, dentro del directorio del mismo. También monta y muestra para el usuario una lista de variables de ambiente utilizando la sintaxis de la shell actual del usuario (como especificado por la variable de ambiente "SHELL"), pronta para ser añadida directamente al archivo de configuración de la shell.

Generalizando, el local::lib permite la creación y uso de un directorio que contenga módulos Perl fuera de @INC de Perl. Esto facilita la producción de aplicaciones con una versión específica de un módulo, o colección de módulos. También es útil cuando el mantenedor de un módulo no ha aplicado un parche que el usuario necesita para su aplicación.

Durante el "import", el local::lib define valores adecuados para las siguientes variables de ambiente:

PERL_MB_OPT
PERL_MM_OPT
PERL5LIB
PATH
los valores se añadirán al PATH, en lugar de substituirlo.

Estos valores también están disponibles para referencia por cualquier otro código después del "import".

MÉTODOS

ensure_dir_structure_for

Argumentos: $ruta_del_directorio
Valor de Retorno: Ninguno

Intenta crear la ruta proporcionada, y todos los directorios superiores necesarios. Genera una excepción en caso de fallo.

print_environment_vars_for

Argumentos: $ruta_del_directorio
Valor de Retorno: Ninguno

Imprime en la salida estándar las variables listadas arriba, ajustadas para utilizar la ruta proporcionada como directorio base.

build_environment_vars_for

Argumentos: $ruta_del_directorio, $interpolar
Valor de Retorno: %variables_de_ambiente

Retorna un hash con las variables de ambiente listadas arriba, ajustadas para utilizar la ruta proporcionada como directorio base.

setup_env_hash_for

Argumentos: $ruta_del_directorio
Valor de Retorno: Ninguno

Construye las claves en %ENV para la ruta proporcionada, llamando a "build_environment_vars_for".

install_base_perl_path

Argumentos: $ruta_del_directorio
Valor de Retorno: $ruta_base_de_instalacion

Retorna una ruta de directorio indicando dónde instalar los módulos Perl para esta instalación local de bibliotecas. Añade los directorios "lib" y "perl5" al final de la ruta proporcionada.

install_base_arch_path

Argumentos: $ruta_del_directorio
Valor de Retorno: $ruta_base_de_instalacion_arch

Retorna una ruta de directorio indicando dónde instalar los módulos Perl de arquitecturas específicas para esta instalación local de bibliotecas. Se basa en el valor de retorno del método "install_base_perl_path", añadiendo el valor de $Config{archname}.

install_base_bin_path

Argumentos: $ruta_del_directorio
Valor de Retorno: $ruta_base_de_instalacion_bin

Retorna una ruta de directorio indicando dónde instalar programas ejecutables para esta instalación local de bibliotecas. Se basa en el valor de retorno del método "install_base_perl_path", añadiendo el directorio "bin".

resolve_empty_path

Argumentos: $ruta_del_directorio
Valor de Retorno: $ruta_base_de_instalacion

Crea y retorna la ruta de directorio raíz en la que se debe realizar la instalación local de módulos. El valor por defecto es "~/perl5".

resolve_home_path

Argumentos: $ruta_del_directorio
Valor de Retorno: $ruta_a_home

Busca el directorio de usuario (home) del usuario. Genera una excepción si no encuentra un resultado definitivo.

resolve_relative_path

Argumentos: $ruta_del_directorio
Valor de Retorno: $ruta_absoluta

Transforma la ruta proporcionada en una ruta absoluta.

resolve_path

Argumentos: $ruta_del_directorio
Valor de Retorno: $ruta_absoluta

Invoca los siguientes métodos en secuencia, pasando el resultado del método anterior al siguiente, en el intento de descubrir dónde configurar el ambiente para la instalación local de bibliotecas: "resolve_empty_path", "resolve_home_path", "resolve_relative_path". Se pasa la ruta de directorio proporcionada a "resolve_empty_path", que retorna un resultado que se pasa a "resolve_home_path", que a su vez pasa el resultado a "resolve_relative_path". El resultado final de esta llamada se devuelve por "resolve_path".

UNA ADVERTENCIA SOBRE UNINST=1

Tenga cuidado al usar local::lib junto con "make install UNINST=1". La intención de esta opción es desinstalar la versión anterior de un módulo antes de instalar la más reciente. Sin embargo, no posee una verificación de seguridad que garantice que la versión antigua y la nueva se refieren al mismo directorio. Usada en combinación con local::lib, usted puede potencialmente borrar una versión globalmente accesible de un módulo e instalar la versión más nueva en el directorio local. Solo use "make install UNINST=1" junto con local::lib si entiende estas posibles consecuencias.

LIMITAÇÕES

Les outils auxiliaires de Perl ne peuvent pas gérer les noms de répertoires contenant des espaces, donc il n'est pas possible de faire leur amorçage depuis local::lib dans un répertoire contenant des espaces. Ce que vous pouvez faire est de déplacer votre local::lib dans un répertoire contenant des espaces **après** avoir installé tous les modules à l'intérieur. Mais sachez que vous ne pourrez pas mettre à jour ou installer d'autres modules CPAN dans ce répertoire local après le déplacement.

La détection du shell est relativement basique. Actuellement, tout ce qui contient csh dans son nom sera traité comme la C shell ou compatible, et tout le reste sera traité comme Bourne, sauf sur les systèmes Win32. Si la variable d'environnement "SHELL" n'est pas disponible, nous supposerons qu'il s'agit d'un shell compatible Bourne.

La technique d'amorçage est un hack et utilisera CPAN.pm pour ExtUtils::MakeMaker même si vous avez installé CPANPLUS.

Détruit toute valeur préexistante dans les variables d'environnement PERL5LIB, PERL_MM_OPT et PERL_MB_OPT.

Devrait probablement auto-configurer CPAN si cela n'a pas déjà été fait.

Les correctifs sont les bienvenus pour l'un des points ci-dessus.

Sur les systèmes Win32, il n'y a pas moyen d'écrire dans le registre les variables d'environnement créées, de sorte qu'elles persistent après un redémarrage.

RÉSOLUTION DES PROBLÈMES

Si vous avez configuré local::lib pour installer des modules CPAN dans un endroit de votre répertoire personnel ('home'), et que vous avez ensuite tenté d'installer un module en faisant "cpan -i Foo::Bar", mais que cela a échoué avec une erreur telle que : "Warning: You do not have permissions to install into /usr/lib64/perl5/site_perl/5.8.8/x86_64-linux at /usr/lib64/perl5/5.8.8/Foo/Bar.pm" et quelque part dans votre log d'installation il y a une erreur disant "'INSTALL_BASE' is not a known MakeMaker parameter name", alors vous avez d'une manière ou d'une autre perdu votre ExtUtils::MakeMaker mis à jour.

Pour remédier à la situation, relancez la procédure d'amorçage décrite ci-dessus.

Ensuite, exécutez "rm -r ~/.cpan/build/Foo-Bar*"

Enfin, exécutez à nouveau "cpan -i Foo::Bar" et il devrait s'installer sans problème.

ENVIRONNEMENT

SHELL
COMSPEC
local::lib recherche la variable d'environnement "SHELL" de l'utilisateur lors du traitement et de l'affichage des commandes à ajouter dans le fichier de configuration du shell.

Sur les systèmes Win32, "COMSPEC" sera également examiné.
