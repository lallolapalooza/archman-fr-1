POSIX(3perl) Guide de référence du programmeur Perl POSIX(3perl)

NOM

POSIX - Interface Perl pour IEEE Std 1003.1

SYNOPSIS

use POSIX ();
use POSIX qw(setsid);
use POSIX qw(:errno_h :fcntl_h);
printf "EINTR est %d\n", EINTR;
my $sess_id = POSIX::setsid();
my $fd = POSIX::open($path, O_CREAT|O_EXCL|O_WRONLY, 0644);
    # note : c'est un descripteur de fichier, PAS un handle de fichier

DESCRIPTION

Le module POSIX permet d'accéder à tous (ou presque) les identifiants standard POSIX 1003.1. Beaucoup de ces identifiants ont reçu des interfaces à la manière de Perl.

Ce document fournit une liste condensée des fonctionnalités disponibles dans le module POSIX. Consultez les pages de manuel de votre système d'exploitation pour des informations générales sur la plupart des fonctionnalités. Consultez perlfunc pour les fonctions qui sont notées comme étant identiques ou presque identiques aux fonctions intégrées de Perl.

La première section décrit les fonctions POSIX de la spécification 1003.1. La deuxième section décrit certaines classes pour les objets de signal, les objets TTY et d'autres objets divers. Les sections restantes listent diverses constantes et macros dans une organisation qui suit approximativement IEEE Std 1003.1b-1993.

La notation "[C99]" indique les fonctions qui ont été ajoutées dans la version ISO/IEC 9899:1999 du standard du langage C. Certaines peuvent ne pas être disponibles sur votre système s'il adhère à une norme antérieure. Les tentatives d'utilisation de l'une d'entre elles manquant entraîneront un message d'erreur d'exécution fatal.

CAVEATS

Tout est exporté par défaut (avec une poignée d'exceptions). C'est une regrettable fonctionnalité de rétrocompatibilité et son utilisation est fortement déconseillée. Vous devriez soit empêcher l'exportation (en disant "use POSIX ();", comme d'habitude) et ensuite utiliser des noms entièrement qualifiés (par exemple, "POSIX::SEEK_END"), soit donner une liste d'importation explicite. Si vous ne faites ni l'un ni l'autre et optez pour le défaut (comme dans "use POSIX;"), vous importerez des centaines et des centaines de symboles dans votre espace de noms.

Quelques fonctions ne sont pas implémentées car elles sont spécifiques au C. Si vous tentez de les appeler, elles afficheront un message indiquant qu'elles ne sont pas implémentées et suggéreront d'utiliser l'équivalent Perl, s'il en existe un. Par exemple, tenter d'accéder à l'appel setjmp() provoquera le message ""setjmp() est spécifique au C : utilisez plutôt eval {}"".

De plus, certains fournisseurs malhonnêtes prétendront être conformes à 1003.1, mais en fait ne le seront pas : ils ne passeront pas les PCTS (POSIX Compliance Test Suites). Par exemple, un fournisseur peut ne pas définir "EDEADLK", ou la sémantique des valeurs d'errno définies par open(2) pourrait ne pas être tout à fait correcte. Perl n'essaie pas de vérifier la conformité POSIX. Cela signifie que vous pouvez actuellement dire avec succès "use POSIX", et plus tard dans votre programme, vous constaterez que votre fournisseur a été laxiste et qu'il n'y a pas de macro "ICANON" utilisable après tout. Cela pourrait être interprété comme un bug.

FONCTIONS

"_exit"
Ceci est identique à la fonction C _exit(). Elle quitte le programme immédiatement, ce qui signifie entre autres que les E/S en tampon ne sont pas vidées.

Notez qu'en utilisant des threads et sous Linux, ce n'est pas une bonne façon de quitter un thread car sous Linux, les processus et les threads sont un peu la même chose (Note : bien que ce soit la situation début 2003, des projets sont en cours pour avoir des threads avec des sémantiques plus POSIX sous Linux). Si vous ne voulez pas revenir d'un thread, détachez le thread.

"abort"
Ceci est identique à la fonction C abort(). Elle termine le processus avec un signal "SIGABRT" à moins qu'il ne soit capturé par un gestionnaire de signal ou si le gestionnaire ne retourne pas normalement (il fait par exemple un "longjmp").
"abs"
Ceci est identique à la fonction intégrée de Perl abs(), renvoyant la valeur absolue de son argument numérique (sauf que POSIX::abs() doit recevoir une valeur explicite (plutôt que de s'appuyer sur un implicite $_) : 
$valeur_absolue = POSIX::abs(42);   # bon
$valeur_absolue = POSIX::abs();     # lève une exception
"access"
Détermine l'accessibilité d'un fichier. 
if( POSIX::access( "/", &POSIX::R_OK ) ){
        print "a la permission de lecture\n";
}

Retourne "undef" en cas d'échec. Note : n'utilisez pas access() à des fins de sécurité. Entre l'appel à access() et l'opération que vous préparez, les permissions pourraient changer : une condition de concurrence classique.

"acos"
Ceci est identique à la fonction C acos(), renvoyant l'arc cosinus de son argument numérique. Voir aussi Math::Trig.
"acosh"
Ceci est identique à la fonction C acosh(), renvoyant l'arc cosinus hyperbolique de son argument numérique [C99]. Voir aussi Math::Trig. Ajouté dans Perl v5.22.
"alarm"
Ceci est identique à la fonction intégrée de Perl alarm(), soit pour armer soit pour désarmer le timer "SIGARLM", sauf que POSIX::alarm() doit recevoir une valeur explicite (plutôt que de s'appuyer sur un implicite $_) : 
POSIX::alarm(3)     # bon
POSIX::alarm()      # lève une exception
"asctime"
Ceci est identique à la fonction C asctime(). Elle renvoie une chaîne de la forme 
"Ven Juin  2 18:22:13 2000\n\0"

et elle est appelée ainsi

$asctime = asctime($sec, $min, $hour, $mday, $mon,
                   $year, $wday, $yday, $isdst);

Le $mon est basé sur zéro : Janvier équivaut à 0. L'$year est basé sur 1900 : 2001 équivaut à 101. $wday et $yday valent par défaut zéro (et sont généralement ignorés de toute façon), et $isdst vaut par défaut -1.

Notez que le résultat est toujours en anglais. Utilisez plutôt "strftime" pour obtenir un résultat adapté à la locale courante. Le format %c de cette fonction produit la représentation préférée de la locale.

"asin"
Ceci est identique à la fonction C asin(), renvoyant l'arc sinus de son argument numérique. Voir aussi Math::Trig.
"asinh"
Ceci est identique à la fonction C asinh(), renvoyant l'arc sinus hyperbolique de son argument numérique [C99]. Voir aussi Math::Trig. Ajouté dans Perl v5.22.
"assert"
Non implémenté, mais vous pouvez utiliser "die" dans perlfunc et le module Carp pour obtenir des choses similaires.
"atan"
Ceci est identique à la fonction C atan(), renvoyant l'arc tangent de son argument numérique. Voir aussi Math::Trig.
"atanh"
Ceci est identique à la fonction C atanh(), renvoyant l'arc tangent hyperbolique de son argument numérique [C99]. Voir aussi Math::Trig. Ajouté dans Perl v5.22.
"atan2"
Ceci est identique à la fonction intégrée de Perl atan2(), renvoyant l'arc tangent défini par ses deux arguments numériques, la coordonnée y et la coordonnée x. Voir aussi Math::Trig.
"atexit"
Non implémenté. atexit() est spécifique au C : utilisez plutôt "END {}", voir perlmod.
"atof"
Non implémenté. atof() est spécifique au C. Perl convertit les chaînes en nombres de manière transparente. Si vous avez besoin de forcer un scalaire en nombre, ajoutez-lui zéro.
"atoi"
Non implémenté. atoi() est spécifique au C. Perl convertit les chaînes en nombres de manière transparente. Si vous avez besoin de forcer un scalaire en nombre, ajoutez-lui zéro. Si vous avez besoin de n'avoir que la partie entière, voir "int" dans perlfunc.

"localeconv"
Obtenir des informations de formatage numérique. Retourne une référence à une table hash contenant les valeurs de formatage de la locale qui sous-tend actuellement le programme, que ce soit appelé ou non depuis le scope de "use locale". Les utilisateurs de cette fonction devraient également lire perllocale, qui fournit une discussion complète sur la gestion des locales par Perl, y compris une section consacrée à cette fonction. Avant Perl 5.28, ou lors de l'opération dans un environnement non thread-safe, il ne doit pas être utilisé dans une application multithreadée à moins qu'il ne soit certain que la locale sous-jacente est C ou POSIX. my $lconv = POSIX::localeconv();
foreach my $property (qw(
        decimal_point
        thousands_sep
        grouping
        int_curr_symbol
        currency_symbol
        mon_decimal_point
        mon_thousands_sep
        mon_grouping
        positive_sign
        negative_sign
        int_frac_digits
        frac_digits
        p_cs_precedes
        p_sep_by_space
        n_cs_precedes
        n_sep_by_space
        p_sign_posn
        n_sign_posn
        int_p_cs_precedes
        int_p_sep_by_space
        int_n_cs_precedes
        int_n_sep_by_space
        int_p_sign_posn
        int_n_sign_posn
))
{

                $property, $lconv->{$property};
}

"nan"
my $nan = nan();

Retourne "NaN", not-a-number [C99]. Ajouté dans Perl v5.22.

Le NaN retourné est toujours un NaN *silencieux*, par opposition à un NaN *signalant*.

Avec un argument, peut être utilisé pour générer un NaN avec une *charge utile* (payload). L'argument est d'abord interprété comme un nombre flottant, mais ensuite toutes les parties fractionnaires sont tronquées (vers zéro), et la valeur est interprétée comme un entier non signé. Les bits de cet entier sont stockés dans les bits inutilisés du NaN.

Le résultat a une double nature : c'est un NaN, mais il contient également l'entier. L'entier peut être récupéré avec "getpayload". Notez cependant que la charge utile n'est pas propagée, même lors des copies, et certainement pas dans les opérations arithmétiques.

Le nombre de bits qui tiennent dans le NaN dépend du type de virgule flottante utilisé, mais sur les plateformes les plus courantes (IEEE 754 64 bits, ou les doubles longs x86 80 bits) il y a respectivement 51 et 61 bits disponibles. (Il y en aurait 52 et 62, mais le bit silencieux/signalant des NaN en prend un.) Cependant

, en raison des conversions de flottants vers entiers et vice-versa, veuillez tester soigneusement pour voir si vous récupérez ce que vous avez mis. Si vos entiers ne font que 32 bits de largeur, vous ne devriez probablement pas vous fier à plus de 32 bits de charge utile.

La différence entre un NaN « de signalement » et un NaN « silencieux » dépend de la plateforme. Notez également que la charge utile du NaN par défaut (aucun argument pour nan()) n'est pas nécessairement zéro ; utilisez « setpayload » pour définir explicitement la charge utile. Sur certaines plateformes comme le x86 32 bits (sauf si vous utilisez les doubles longs 80 bits), le bit de signalement n'est pas du tout pris en charge.

Voir aussi « isnan », « NaN », « setpayload » et « issignaling ».

"setlocale"
ATTENTION ! Avant Perl 5.28 ou sur un système qui ne prend pas en charge les opérations de locale thread-safe, N'UTILISEZ PAS cette fonction dans un thread. La locale changera dans tous les autres threads en même temps, et si votre thread est mis en pause par le système d'exploitation, et qu'un autre est démarré, ce thread n'aura pas la locale attendue. Sur certaines plateformes, il peut y avoir une condition de concurrence entraînant des segfaults si deux threads appellent cette fonction presque simultanément. Cet avertissement ne s'applique pas aux builds non threadés, ou aux perls où « ${^SAFE_LOCALES}" existe et est non nul ; à savoir Perl 5.28 et versions ultérieures compilées pour être thread-safe pour la locale.

Cette fonction modifie et interroge la locale sous-jacente du programme. Les utilisateurs de cette fonction doivent lire perllocale, qui fournit une discussion complète sur la gestion des locales dans Perl, une connaissance de laquelle est nécessaire pour utiliser correctement cette fonction. Elle contient une section dédiée à cette fonction. La discussion ici est simplement une référence sommaire pour se. Notez que Perl lui-même est presque entièrement non affecté par la locale, sauf dans la portée de "use locale". (Les exceptions sont listées dans "Pas dans la portée de "use locale"" dans perllocale, et les fonctions dépendantes de la locale dans le module POSIX SONT toujours affectées par la locale actuelle.)

Les exemples suivants supposent que

use POSIX qw(setlocale LC_ALL LC_CTYPE);

a été exécuté.

Ce qui suit définira le comportement traditionnel du système d'exploitation UNIX (le deuxième argument "C").

$loc = setlocale( LC_ALL, "C" );

Ce qui suit interrogera la catégorie "LC_CTYPE" actuelle. (Aucun deuxième argument ne signifie 'interroger'.)

$loc = setlocale( LC_CTYPE );

Ce qui suit définira le comportement "LC_CTYPE" conformément aux variables d'environnement de la locale (le deuxième argument ""). Veuillez consulter la documentation de setlocale(3) de votre système pour connaître la signification des variables d'environnement de locale ou consultez perllocale.

$loc = setlocale( LC_CTYPE, "" );

Ce qui suit définira le comportement "LC_COLLATE" pour l'espagnol argentin. NOTE : La dénomination et la disponibilité des locales dépendent de votre système d'exploitation. Veuillez consulter perllocale pour savoir comment trouver quelles locales sont disponibles sur votre système.

$loc = setlocale( LC_COLLATE, "es_AR.ISO8859-1" );

"strftime"
Convertit les informations de date et d'heure en chaîne en fonction du locale sous-jacent actuel du programme (à l'exception de toute heure d'été). Retourne la chaîne.

Synopsis :

strftime(fmt, sec, min, hour, mday, mon, year,
         wday = -1, yday = -1, isdst = 0)

Le mois ("mon") commence à zéro, par exemple, janvier est 0, pas 1. L'année ("year") est donnée en années depuis 1900, par exemple, l'année 1995 est 95 ; l'année 2001 est 101. Consultez la page de manuel strftime() de votre système pour plus de détails sur ces arguments et les autres.

Les paramètres "wday" et "yday" sont tous deux ignorés. Leurs valeurs sont toujours déterminables à partir des autres paramètres.

"isdst" doit être 1 ou 0, selon que l'heure d'été est en vigueur pour l'heure donnée ou non.

Si vous souhaitez que votre code soit portable, votre argument de format ("fmt") ne doit utiliser que les spécificateurs de conversion définis par la norme ANSI C (C99, pour jouer la sécurité). Ce sont "aAbBcdHIjmMpSUwWxXyYZ%". Mais même alors, les résultats de certains spécificateurs de conversion ne sont pas portables. Par exemple, les spécificateurs "aAbBcpZ" changent en fonction des paramètres du locale de l'utilisateur, et à la fois comment définir les locales (les noms de locales) et quel résultat attendre sont non standard. Le spécificateur "c" change en fonction des paramètres de fuseau horaire de l'utilisateur et des règles de calcul de fuseau horaire du système d'exploitation. Le spécificateur "Z" n'est notoirement pas portable car les noms des fuseaux horaires ne sont pas standard. S'en tenir aux spécificateurs numériques est la voie la plus sûre.

Les arguments, à l'exception de "isdst", sont rendus cohérents comme si mktime() avait été appelé avant d'appeler la fonction strftime() de votre système. Pour obtenir des résultats corrects, vous devez définir "isdst" sur la valeur appropriée. Lorsqu'il est omis, la fonction suppose que l'heure d'été n'est pas en vigueur.

La chaîne du mardi 12 décembre 1995 dans le locale "C".

$str = POSIX::strftime( "%A, %B %d, %Y",
                         0, 0, 0, 12, 11, 95,
                         2 );
print "$str\n";

"strtod"
Traduction chaîne vers double. Retourne le nombre analysé et le nombre de caractères dans la partie non analysée de la chaîne. Les systèmes véritablement conformes à POSIX définissent $! ($ERRNO) pour indiquer une erreur de traduction, donc effacez $! avant d'appeler "strtod". Cependant, les systèmes non-POSIX peuvent ne pas vérifier le dépassement de capacité et, par conséquent, ne définiront jamais $!.

"strtod" respecte tous les paramètres POSIX setlocale() "LC_NUMERIC", que ce soit ou non appelé à partir d'un code Perl dans la portée de "use locale". Avant Perl 5.28, ou lors de l'exécution dans un environnement non thread-safe, il ne doit pas être utilisé dans une application multithreadée, sauf s'il est certain que le locale sous-jacent est C ou POSIX. En effet, il modifie sinon le locale, ce qui affecte globalement tous les threads simultanément.

Pour analyser une chaîne $str en tant que nombre à virgule flottante, utilisez

$! = 0;
($num, $n_unparsed) = POSIX::strtod($str);

Le deuxième élément retourné et $! peuvent être utilisés pour vérifier la validité de l'entrée :

if (($str eq '') || ($n_unparsed != 0) || $!) {
    die "Entrée non numérique $str" . ($! ? ": $!\n" : "\n");
}

Lorsqu'il est appelé dans un contexte scalaire, "strtod" retourne le nombre analysé.

"strtol"
Traduction chaîne vers entier (long). Retourne le nombre analysé et le nombre de caractères dans la partie non analysée de la chaîne. Les systèmes véritablement conformes à POSIX définissent $! ($ERRNO) pour indiquer une erreur de traduction, donc effacez $! avant d'appeler "strtol". Cependant, les systèmes non-POSIX peuvent ne pas vérifier le dépassement de capacité et, par conséquent, ne définiront jamais $!.

Pour analyser une chaîne $str comme un nombre dans une base $base, utilisez

La base doit être zéro ou comprise entre 2 et 36, inclus. Lorsque la base est zéro ou omise, "strtol" utilisera la chaîne elle-même pour déterminer la base : un préfixe "0x" ou "0X" signifie hexadécimal ; un préfixe "0" signifie octal ; tout autre préfixe signifie décimal. Ainsi, "1234" est analysé comme un nombre décimal, "01234" comme un nombre octal, et "0x1234" comme un nombre hexadécimal.

Le deuxième élément retourné et $! peuvent être utilisés pour vérifier la validité de l'entrée :

if (($str eq '') || ($n_unparsed != 0) || !$!) {
    die "Entrée non numérique $str" . $! ? ": $!\n" : "\n";
}

Lorsqu'il est appelé dans un contexte scalaire, "strtol" retourne le nombre analysé.

"POSIX::SigRt"

%SIGRT
Un hachage des gestionnaires de signaux POSIX temps réel. C'est une extension du %SIG standard, le $POSIX::SIGRT{SIGRTMIN} est à peu près équivalent au $SIG{SIGRTMIN}, mais les bonnes opérations POSIX (voir ci-dessous) sont effectuées avec "POSIX::SigSet" et "POSIX::sigaction" au lieu d'accéder au %SIG.

Vous pouvez définir les éléments de %POSIX::SIGRT pour définir les gestionnaires de signaux POSIX temps réel, utiliser "delete" et "exists" sur les éléments, et utiliser "scalar" sur le %POSIX::SIGRT pour savoir combien de signaux POSIX temps réel sont disponibles "(SIGRTMAX - SIGRTMIN + 1", le "SIGRTMAX" est un signal POSIX temps réel valide).

Définir les éléments de %SIGRT équivaut à appeler ceci :

sub new {
  my ($rtsig, $handler, $flags) = @_;
  my $sigset = POSIX::SigSet($rtsig);
  my $sigact = POSIX::SigAction->new($handler,$sigset,$flags);
  sigaction($rtsig, $sigact);
}

Les drapeaux sont par défaut à zéro, si vous voulez quelque chose de différent vous pouvez soit utiliser "local" sur $POSIX::SigRt::SIGACTION_FLAGS, soit dériver de POSIX::SigRt et définir votre propre new() (la méthode STORE du hachage lié de %SIGRT appelle "new($rtsig, $handler, $SIGACTION_FLAGS)", où le $rtsig varie de zéro à "SIGRTMAX - SIGRTMIN + 1)").

Tout comme avec n'importe quel signal, vous pouvez utiliser "sigaction($rtsig, undef, $oa)" pour récupérer le gestionnaire de signal installé (ou plutôt, l'action de signal).

NOTE : le fait que les signaux POSIX temps réel fonctionnent réellement sur votre système, ou que Perl ait été compilé de manière à fonctionner avec eux, est hors de cette discussion.

NAME

POSIX - Perl interface to POSIX constants and functions

SYNOPSIS

 use POSIX qw(:sys_wait_h :stdio_h :fcntl_h);
 use POSIX qw(EXIT_SUCCESS);

DESCRIPTION

This module provides access to the POSIX constants and functions that are typically defined in C header files. It is loaded automatically by the Symbol(3pm) module, and you usually don't need to load it explicitly.

You can load specific constants or groups of constants using the use statement.

For example, to load all constants related to file permissions, you can say:

 use POSIX qw(S_IRUSR S_IWUSR S_IXUSR);

Or to load all constants for file types:

 use POSIX qw(:f_cntl_h);

The available groups are:

:all
All constants.
:f_cntl_h
Constants defined in <fcntl.h>.
:float_h
Constants defined in <float.h>.
:limits_h
Constants defined in <limits.h>.
:locale_h
Constants defined in <locale.h>.
:math_h
Constants defined in <math.h>.
:signal_h
Constants defined in <signal.h>.
:stat_h
Constants defined in <stat.h>.
:stdio_h
Constants defined in <stdio.h>.
:stdlib_h
Constants defined in <stdlib.h>.
:sys_stat_h
Same as :stat_h.
:sys_wait_h
Constants defined in <sys/wait.h>.
:time_h
Constants defined in <time.h>.
:unistd_h
Constants defined in <unistd.h>.
:winsock_h
Constants defined in <winsock.h>. (Windows only.)

You can also import functions from the C library. These are usually not exported by default. To import them, you can explicitly list them in the use statement.

 use POSIX qw( ceil floor);

The following functions are available:

ceil
floor
_exit

The POSIX module also provides constants for common errors, defined in <errno.h>. These are usually imported automatically when you use the Errno(3pm) module.

 use Errno qw(:E);
 print $EAGAIN, "\n";

The available constants are:

:E
All standard POSIX error constants.
:ERRLIST
The sys_errlist and sys_nerr variables.

See also Errno(3pm).

CAVEATS

Some systems define constants like RAND_MAX in <stdlib.h>. If Perl is compiled with -Dusedefaults, then RAND_MAX will be 32767. Otherwise, it will be whatever the system's C library defines.

The constants from <sys/stat.h> are defined as octal numbers. So, if you want to use them in a numeric context, you might need to convert them to decimal.

 use POSIX qw(S_IRWXU);
 printf "%o\n", S_IRWXU; # prints 700
 printf "%d\n", S_IRWXU; # prints 448

"WNOHANG"
Do not suspend the calling process until a child process changes state but instead return immediately.
"WUNTRACED"
Catch stopped child processes.
Macros
"WIFEXITED" "WEXITSTATUS" "WIFSIGNALED" "WTERMSIG" "WIFSTOPPED" "WSTOPSIG"
"WIFEXITED"
WIFEXITED(${^CHILD_ERROR_NATIVE}) returns true if the child process exited normally (exit() or by falling off the end of main())
"WEXITSTATUS"
WEXITSTATUS(${^CHILD_ERROR_NATIVE}) returns the normal exit status of the child process (only meaningful if WIFEXITED(${^CHILD_ERROR_NATIVE}) is true)
"WIFSIGNALED"
WIFSIGNALED(${^CHILD_ERROR_NATIVE}) returns true if the child process terminated because of a signal
"WTERMSIG"
WTERMSIG(${^CHILD_ERROR_NATIVE}) returns the signal the child process terminated for (only meaningful if WIFSIGNALED(${^CHILD_ERROR_NATIVE}) is true)
"WIFSTOPPED"
WIFSTOPPED(${^CHILD_ERROR_NATIVE}) returns true if the child process is currently stopped (can happen only if you specified the WUNTRACED flag to waitpid())
"WSTOPSIG"
WSTOPSIG(${^CHILD_ERROR_NATIVE}) returns the signal the child process was stopped for (only meaningful if WIFSTOPPED(${^CHILD_ERROR_NATIVE}) is true)
