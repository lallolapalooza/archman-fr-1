NOM

POE::Component - objets ou sous-systèmes pilotés par événements

SYNOPSIS

Voir les composants spécifiques.

DESCRIPTION

Les « composants » POE sont des modules pilotés par événements qui encapsulent généralement des fonctionnalités de programme de niveau moyen à élevé. Par exemple, POE::Component::Client::DNS effectue des recherches asynchrones asynchrones basées sur des messages. POE::Component::Server::TCP est un serveur réseau asynchrone de base.

L'espace de noms POE::Component a été créé comme un endroit permettant aux contributeurs de publier leurs modules basés sur POE sans nécessiter de coordination avec la distribution principale de POE. L'espace de noms est antérieur à la convention -X, sinon vous liriez également sur POEx.

Comme beaucoup de choses en Perl, il existe plus d'une façon d'implémenter des interfaces de composants. Les composants plus récents arborent des interfaces OO, et certains utilisent même Moose, mais les plus anciens sont uniquement pilotés par message.

COMPOSANTS ORIENTÉS OBJET

Une façon de créer des composants orientés objet consiste à intégrer une instance de POE::Session dans un objet. Ceci est fait en créant la session pendant le constructeur de l'objet, en définissant l'alias de la session sur quelque chose d'unique, et en sauvegardant une copie de l'alias dans l'objet.

package Asynchrotron;
my $alias_index = 0;
sub new {
  my $class = shift;
  my $self = bless {
    alias => __PACKAGE__ . " " . ++$alias_index;
  }, $class;
  POE::Session->create(
    object_states => [
      $self => {
        _start       => "_poe_start",
        do_something => "_poe_do_something",
      },
    ],
  );
  return $self;
}
sub _poe_start {
  $_[KERNEL]->alias_set($_[OBJECT]->{alias});
}

L'alias permet aux méthodes de l'objet de transmettre des événements dans la session sans avoir à stocker quelque chose à propos de la session. L'appel call() de POE::Kernel transfère l'exécution du contexte de la session appelante vers la session du composant.

sub do_something {
  my $self = shift;
  print "Inside the caller's session right now: @_\n";
  $poe_kernel->call($self->{alias}, "do_something", @_);
}
sub _poe_do_something {
  my @args = @_[ARG0..$#_];
  print "Inside the component's session now: @args\n";
  $_[OBJECT]{count}++;
}

[HEAP] et [OBJECT] sont tous deux visibles dans la session du composant. [HEAP] peut être utilisé pour une encapsulation ultra-privée, tandis que [OBJECT] peut être utilisé pour des données visibles par les accesseurs.

sub get_count {
  my $self = shift;
  return $self->{count}; # $_[OBJECT]{count} above
}

Trop de sessions peuvent ralentir la création et la destruction d'objets, alors évitez d'en créer pour chaque objet.

VOIR AUSSI

La section VOIR AUSSI dans POE contient une table des matières couvrant toute la distribution POE.

POE::Stage est un projet naissant visant à formaliser les composants POE, à rendre POE::Kernel plus orienté objet et à fournir un sucre syntaxique et sémantique pour de nombreux aspects courants du développement de POE::Component. Il est également plus facile à taper. Veuillez enquêter sur le projet. Des idées et des tuits sont désespérément nécessaires pour aider le projet à décoller.
