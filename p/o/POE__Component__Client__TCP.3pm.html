NAME

POE::Component::Client::TCP - un client TCP simplifié

SYNOPSIS

#!perl
use warnings;
use strict;
use POE qw(Component::Client::TCP);
POE::Component::Client::TCP->new(
  RemoteAddress => "yahoo.com",
  RemotePort    => 80,
  Connected     => sub {
    $_[HEAP]{server}->put("HEAD /");
  },
  ServerInput   => sub {
    my $input = $_[ARG0];
    print "from server: $input\n";
  },
);
POE::Kernel->run();
exit;

DESCRIPTION

POE::Component::Client::TCP implémente un client de session générique. Il utilise en interne POE::Wheel::SocketFactory pour établir la connexion et POE::Wheel::ReadWrite pour interagir avec le serveur.

POE::Component::Client::TCP est personnalisé en fournissant des callbacks pour les opérations communes. Les opérations les plus communes ont des callbacks par défaut raisonnables, de sorte que les clients peuvent être créés avec le moins d'effort possible.

Considérations sur les performances

La facilité d'utilisation de POE::Component::Client::TCP a un prix. Le composant est générique, donc il n'est pas optimisé pour les performances dans des applications spécifiques.

Si les performances sont votre objectif principal, select_read() et select_write() de POE::Kernel ont des performances similaires à celles de IO::Select, mais votre code sera portable entre tous les cycles d'événements que POE supporte.

Méthodes publiques

new

new() démarre un client basé sur POE::Component::Client::TCP et retourne l'identifiant de la session qui gérera l'interaction avec le serveur.

new() retourne immédiatement, ce qui peut se produire avant que le client ait établi sa connexion. Il est toujours fiable d'attendre le callback "Connected" avant d'envoyer des données au serveur.

Le constructeur du client peut sembler prendre un nombre impressionnant de paramètres. Comme avec la plupart des modules POE, POE::Component::Client::TCP essaie de faire autant que possible dans le constructeur afin que le chemin de code d'exécution soit relativement léger.

Paramètres du constructeur affectant la session

Les paramètres de cette section affectent la manière dont l'objet POE::Session du client sera créé.

Alias

"Alias" est un nom symbolique optionnel pour la session du client. Il permet à d'autres sessions d'envoyer des événements au client, tels que "shutdown" et "reconnect". Le client lui-même peut yield() ces événements, donc un alias n'est généralement pas nécessaire.

Alias => "client",

Args

"Args" est optionnel. Lorsqu'il est spécifié, il contient une reference de tableau qui est passée au callback "Started" via @_[ARG0..$#_]. Cela permet de passer des informations supplémentaires à la session du client.

InlineStates

"InlineStates" est optionnel. S'il est spécifié, il doit contenir un hashref avec des callbacks nommés. Sa syntaxe est la même que celle des inline_states de POE::Session->create().

ObjectStates

Si "ObjectStates" est spécifié, il doit contenir une reference de tableau d'objets et les événements qu'ils gèrent. La reference de tableau doit suivre la syntaxe de object_states de POE::Session->create().

PackageStates

Lorsque le paramètre optionnel "PackageStates" est défini, il doit contenir une reference de tableau de noms de packages et les événements qu'ils gèrent. La reference de tableau doit suivre la syntaxe de package_states de POE::Session->create().

PreConnect

"PreConnect" est appelé avant "Connected" et a des paramètres différents : $_[ARG0] contient une copie du socket avant qu'il ne soit donné à POE::Wheel::ReadWrite pour la gestion. La plupart des membres de HEAP sont définis, à l'exception de $_[HEAP]{server}, car l'objet POE::Wheel::ReadWrite n'a pas encore été créé. "PreConnect" peut activer le SSL sur le socket en utilisant POE::Component::SSLify. "PreConnect" doit retourner un socket valide pour compléter la connexion ; le client se déconnectera si quoi que ce soit est retourné.

PreConnect => {
  # Convertir le socket en un socket SSL.
  my $socket = eval { Client_SSLify($_[ARG0]) };
  # Déconnecter si le SSL échoue.
  return if $@;
  # Retourner le socket SSLifié.
  return $socket;
}

SessionType

Chaque client est créé dans sa propre session. "SessionType" est le nom de la classe qui sera utilisée pour créer la session.

SessionType => "POE::Session::MultiDispatch",

"SessionType" est optionnel. Le composant utilisera "POE::Session" par défaut.

SessionParams

"SessionParams" spécifie des paramètres supplémentaires qui seront passés au constructeur de la classe "SessionType" au moment de sa création. Ce doit être une reference de tableau.

SessionParams => [ options => { debug => 1, trace => 1 } ],

Note : POE::Component::Client::TCP fournit ses propres paramètres de constructeur POE::Session. Les collisions entre ceux-ci et "SessionParams" peuvent entraîner un comportement erroné du composant. Pour éviter de tels problèmes, veuillez limiter "SessionParams" aux paramètres "options" du hash. Consultez POE::Session pour une liste connue d'options.

Nous pouvons activer d'autres options plus tard. S'il vous plaît, dites-moi si vous avez besoin de quelque chose.

Started

"Started" définit un callback optionnel qui sera invoqué dans la session du client lorsqu'elle aura démarré. Les paramètres du callback sont ceux habituels pour le handler _start de la session.

"Args" peut être utilisé pour passer des paramètres supplémentaires à "Started". Ceci peut être utilisé pour éviter des problèmes introduits par les fermetures. Les valeurs de "Args" seront incluses dans les paramètres @_[ARG0..$#_] du handler.

sub handle_started {
  my @args = @_[ARG0..$#_];
  # ...
}

Paramètres du constructeur POE::Wheel::SocketFactory

Les paramètres du constructeur dans cette section affectent la manière dont l'objet POE::Wheel::SocketFactory du client sera créé.

BindAddress

"BindAddress" spécifie l'adresse d'interface locale à laquelle se connecter avant de commencer la connexion. Cela permet au client de se connecter depuis une adresse spécifique lorsque plusieurs interfaces sont disponibles.

"BindAddress" est optionnel. S'il est spécifié, sa valeur sera passée directement au constructeur de POE::Wheel::SocketFactory pour BindAddress.

BindPort

"BindPort" définit le port local du socket auquel le client se connectera avant de commencer la connexion. Cela permet au client de se connecter depuis un port spécifique.

Il n'est pas courant d'avoir besoin de se lier à un port spécifique, donc "BindPort" est optionnel et désactivé par défaut.

S'il est spécifié, la valeur de "BindPort" sera passée directement au constructeur de POE::Wheel::SocketFactory pour BindPort.

ConnectError

"ConnectError" est un callback optionnel pour gérer les erreurs de POE::Wheel::SocketFactory. Ces erreurs se produisent lorsque le socket ne peut pas être créé ou qu'il y a une difficulté à se connecter à l'hôte distant.

Les paramètres suivants seront passés au callback avec les paramètres habituels de POE : $_[ARG0] décrit ce qui se passait au moment de l'échec. $_[ARG1] et $_[ARG2] contiennent les versions numériques et de chaîne de $!, respectivement.

  warn "$operation error $error_number occurred: $error_string";
  if (error_is_recoverable($error_number)) {

POE::Component::Client::TCP s'arrêtera après ConnectError si une reconnexion n'est pas demandée.

Connecté

Les connexions sont établies de manière asynchrone et peuvent prendre du temps à se terminer. "Connected" est une fonction de rappel optionnelle qui informe un programme lorsque la connexion a été finalement établie.

Il s'agit d'une fonction de rappel informative qui se produit après la création d'un objet POE::Wheel::ReadWrite. Les programmes ne devraient pas avoir besoin d'en créer un eux-mêmes.

"Connected" est appelé en réponse à l'événement SuccessEvent de POE::Wheel::SocketFactory. En plus des paramètres d'événement POE habituels, il inclut une copie du descripteur de socket établi dans $_[ARG0]. POE::Component::Client::TCP gérera le socket, donc une application devrait rarement avoir besoin d'en conserver une copie. $_[ARG1] et $_[ARG2] contiennent l'adresse et le port distants tels que retournés par getpeername().

Connected => {
  my ($socket, $peer_addr, $peer_port) = @_[ARG0, ARG1, ARG2];
  # ...
}

Voir "PreConnect" pour modifier le socket avant qu'il ne soit donné à POE::Wheel::ReadWrite.

ConnectTimeout

"ConnectTimeout" est le nombre maximum de secondes à attendre pour qu'une connexion soit établie. S'il est omis, Client::TCP s'appuie sur le système d'exploitation pour abandonner les appels connect() bloqués.

L'application sera informée d'un délai d'attente via la fonction de rappel ConnectError. Dans le cas d'un délai d'attente, $_[ARG0] contiendra "connect", et $_[ARG1] et $_[ARG2] contiendront les représentations numérique et textuelle de l'erreur ETIMEDOUT.

Domain

"Domain" définit l'espace d'adressage ou la famille de protocoles dans laquelle opérer. Le "Domain" peut être n'importe quelle valeur prise en charge par POE::Wheel::SocketFactory. AF_INET (espace d'adressage Internet) est utilisé par défaut.

Utilisez AF_INET6 pour la prise en charge d'IPv6. Cette constante est exportée par Socket. Assurez-vous également d'avoir installé Socket::GetAddrInfo, qui est requis par POE::Wheel::SocketFactory pour la prise en charge d'IPv6.

RemoteAddress

"RemoteAddress" contient l'adresse du serveur auquel se connecter. Elle est obligatoire et peut contenir un nom d'hôte ("poe.perl.org"), une adresse numérique séparée par des points ou des deux-points (selon le Domaine), ou une adresse de socket packagée. Pratiquement tout ce que le paramètre RemoteAddress de POE::Wheel::SocketFactory fait.

RemotePort

"RemotePort" contient le port du serveur auquel se connecter. Il est obligatoire et peut être un nom de service ("echo") ou un numéro (7).

Paramètres du constructeur POE::Wheel::ReadWrite

Les paramètres de cette section contrôlent la configuration de l'objet POE::Wheel::ReadWrite du client.

Disconnected

"Disconnected" est une fonction de rappel optionnelle pour informer un programme qu'un socket établi a été déconnecté. Elle ne contient aucun paramètre spécial.

Il peut être utile de se reconnecter depuis la fonction de rappel Disconnected, dans le cas de bots MUD ou de services de longue durée. Par exemple :

Disconnected => sub {
  $_[KERNEL]->delay( reconnect => 60 );
},

Le composant s'arrêtera si la connexion cesse sans être reconnectée.

Filter

"Filter" spécifie le type d'objet POE::Filter qui analysera les entrées et sérialisera les sorties vers un serveur. Il peut s'agir d'un scalaire, d'une référence de tableau ou d'un objet POE::Filter.

Si "Filter" est un scalaire, il sera attendu qu'il contienne un nom de classe POE::Filter :

Filter => "POE::Filter::Line",

"Filter" est optionnel. Dans la plupart des cas, le "POE::Filter::Line" par défaut convient.

Si "Filter" est une référence de tableau, le premier élément du tableau sera traité comme un nom de classe POE::Filter. Les éléments restants seront passés au constructeur du filtre. Dans cet exemple, la barre verticale sera utilisée comme terminateur d'enregistrement de POE::Filter::Line :

Filter => [ "POE::Filter::Line", Literal => "|" ],

S'il s'agit d'un objet, il sera cloné à chaque connexion du client :

Filter => POE::Filter::Line->new(Literal => "|"),

Assurez-vous d'"use" la sous-classe POE::Filter appropriée lorsque vous spécifiez un "Filter" autre que celui par défaut.

ServerError

"ServerError" est une fonction de rappel optionnelle qui sera appelée lorsqu'une connexion serveur établie a rencontré un certain type d'erreur. Elle est déclenchée par l'événement ErrorEvent de POE::Wheel::ReadWrite. Par défaut, le composant enregistrera toutes les erreurs sur STDERR. Cela peut être supprimé en définissant une fonction de rappel ServerError plus silencieuse.

Comme avec "ConnectError", elle est appelée avec les paramètres d'erreur habituels : $_[ARG0] contiendra le nom de l'opération qui a échoué. $_[ARG1] et $_[ARG2] contiendront les formes numérique et textuelle de $!, respectivement.

Les composants se déconnectent généralement en cas d'erreur. POE::Component::Client::TCP s'arrêtera si le socket se déconnecte sans être reconnecté.

ServerFlushed

"ServerFlushed" est une fonction de rappel optionnelle pour informer un programme que les tampons de sortie de ReadWrite ont été complètement vidés. Elle n'a pas de paramètres spéciaux.

Le composant s'arrêtera après un vidage serveur si $heap->{shutdown} est défini.

ServerInput

"ServerInput" est une fonction de rappel requise. Elle est appelée pour chaque enregistrement d'entrée entièrement analysé reçu par POE::Wheel::ReadWrite. $_[ARG0] contient l'enregistrement d'entrée, dont le format est déterminé par le paramètre de constructeur "Filter".

"SeverInput" cessera d'être appelé lorsque $_[HEAP]{shutdown} sera vrai. La manière la plus fiable de définir le membre "shutdown" est d'appeler $_[KERNEL]->yield("shutdown").

Événements Publics

POE::Component::Client::TCP gère un petit nombre de messages "commande" publics. Ceux-ci peuvent être postés dans le client à partir d'une session externe, ou yieldés depuis l'intérieur du client.

connect

L'événement "connect" amène POE::Component::Client::TCP à commencer la connexion à un serveur. Il inclut éventuellement un nouveau RemoteHost et RemotePort, qui seront tous deux utilisés pour les reconnexions ultérieures.

$_[KERNEL]->post(alias => connect => "127.0.0.1", 80);

Si le client est déjà connecté à un serveur, il se déconnectera immédiatement avant de commencer la procédure de nouvelle connexion. Les entrées et sorties mises en mémoire tampon seront perdues.

reconnect

La commande "reconnect" amène POE::Component::Client::TCP à déconnecter immédiatement sa connexion actuelle et à commencer à se reconnecter à son RemoteHost et RemotePort les plus récemment définis. Toutes les entrées et sorties mises en mémoire tampon seront perdues.

shutdown

La commande "shutdown" indique à POE::Component::Client::TCP de vider ses tampons, de se déconnecter et de commencer les procédures de DESTRUCTION.

Toutes les entrées seront supprimées après la réception de "shutdown". Toutes les sorties en attente seront écrites sur le socket serveur avant la déconnexion et la destruction.

Membres de Heap Réservés

POE::Component::Client::TCP nécessite un certain espace de heap pour sa propre tenue de registres. Les membres suivants sont utilisés et doivent être utilisés comme indiqué, ou avec précaution.

Ce gestionnaire d'entrée d'exemple illustre la plupart des membres de heap réservés :

sub handle_input {
  # Entrée en attente depuis que nous étions connectés.
  return unless $_[HEAP]{connected};
  # Nous avons été arrêtés.
  return if $_[HEAP]{shutdown};
  my $input = $_[ARG0];
  $_[HEAP]{server}->put("vous avez envoyé : $input");
}

server

Le membre de heap "server", en lecture seule, contient l'objet POE::Wheel utilisé pour se connecter au serveur ou lui parler. Pendant que le composant se connecte, "server" sera un objet POE::Wheel::SocketFactory. Après que la connexion a été établie, "server" est remplacé par un objet POE::Wheel::ReadWrite.

La manière la plus fiable d'éviter d'utiliser prématurément "server" est de d'abord vérifier le membre de heap réservé "connected". Voir l'exemple ci-dessus.

shutdown

"shutdown" est un drapeau en lecture seule qui indique au composant qu'il est en train de s'arrêter. Il ne doit être utilisé que par l'événement "shutdown", qui effectue d'autres nettoyages.

"shutdown" peut être vérifié pour éviter de démarrer de nouveau travail pendant la procédure d'arrêt d'un client. Voir l'exemple ci-dessus.

connected

"connected" est un drapeau en lecture seule qui indique si le composant est actuellement connecté.

shutdown_on_error

"shutdown_on_error" est un drapeau en lecture seule qui régit le comportement d'arrêt en cas d'erreur du composant. Lorsque ce drapeau est vrai, POE::Component::Client::TCP s'arrêtera automatiquement lorsqu'il rencontrera une erreur.
