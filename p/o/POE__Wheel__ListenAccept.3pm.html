POE::Wheel::ListenAccept(3) Documentation Perl fournie par la communauté POE::Wheel::ListenAccept(3)

NOM

POE::Wheel::ListenAccept - accepter des connexions depuis des sockets d'écoute normaux

SYNOPIS

Voir "SYNOPSIS" dans POE::Wheel::SocketFactory pour une version plus simple de ce programme.

#!perl
use warnings;
use strict;
use IO::Socket;
use POE qw(Wheel::ListenAccept Wheel::ReadWrite);
POE::Session->create(
  inline_states => {
    _start => sub {
      # Démarre le serveur.
      $_[HEAP]{server} = POE::Wheel::ListenAccept->new(
        Handle => IO::Socket::INET->new(
          LocalPort => 12345,
          Listen => 5,
        ),
        AcceptEvent => "on_client_accept",
        ErrorEvent => "on_server_error",
      );
    },
    on_client_accept => sub {
      # Commence l'interaction avec le client.
      my $client_socket = $_[ARG0];
      my $io_wheel = POE::Wheel::ReadWrite->new(
        Handle => $client_socket,
        InputEvent => "on_client_input",
        ErrorEvent => "on_client_error",
      );
      $_[HEAP]{client}{ $io_wheel->ID() } = $io_wheel;
    },
    on_server_error => sub {
      # Arrête le serveur.
      my ($operation, $errnum, $errstr) = @_[ARG0, ARG1, ARG2];
      warn "Erreur du serveur $operation $errnum: $errstr\n";
      delete $_[HEAP]{server};
    },
    on_client_input => sub {
      # Gère l'entrée du client.
      my ($input, $wheel_id) = @_[ARG0, ARG1];
      $input =~ tr[a-zA-Z][n-za-mN-ZA-M]; # ASCII rot13
      $_[HEAP]{client}{$wheel_id}->put($input);
    },
    on_client_error => sub {
      # Gère l'erreur client, y compris la déconnexion.
      my $wheel_id = $_[ARG3];
      delete $_[HEAP]{client}{$wheel_id};
    },
  }
);
POE::Kernel->run();
exit;

DESCRIPTION

POE::Wheel::ListenAccept implémente des appels accept() non bloquants pour les sockets serveur d'écoute classiques. L'application fournit le socket, en utilisant des moyens normaux tels que socket(), IO::Socket::INET ou IO::Socket::UNIX. POE::Wheel::ListenAccept surveille le socket d'écoute et émet des événements chaque fois qu'un nouveau client est accepté.

Veuillez consulter POE::Wheel::SocketFactory si vous avez besoin de connect() non bloquant ou d'une solution d'écoute/acceptation plus riche en fonctionnalités.

POE::Wheel::ListenAccept n'accepte que les connexions client. Il ne lit ni n'écrit de données, donc il n'a pas besoin de méthode put() et ne l'inclut pas. POE::Wheel::ReadWrite gère généralement le socket client accepté.

MÉTHODES PUBLIQUES

new

new() crée un nouvel objet POE::Wheel::ListenAccept pour un socket d'écoute donné. L'objet générera des événements relatifs au socket tant qu'il existera.

new() accepte deux paramètres nommés requis :

Handle

Le paramètre constructeur "Handle" doit contenir un descripteur de socket d'écoute. POE::Wheel::FollowTail surveillera ce socket et accept()era les nouvelles connexions à leur arrivée.

AcceptEvent

"AcceptEvent" est un nom d'événement requis que POE::Wheel::ListenAccept émettra pour chaque socket client accepté. "ÉVÉNEMENTS PUBLICS" le décrit en détail.

ErrorEvent

"ErrorEvent" est un nom d'événement optionnel qui sera émis en cas de problème sérieux. Veuillez consulter "ÉVÉNEMENTS PUBLICS" pour plus de détails.

event

event() permet à une session de changer les événements émis par une roue sans détruire et recréer l'objet. Il accepte un ou plusieurs des événements listés dans "ÉVÉNEMENTS PUBLICS". Les noms d'événements indéfinis désactivent ces événements.

Ignorer les connexions :

sub ignore_new_connections {
  $_[HEAP]{tailor}->event( AcceptEvent => "on_ignored_accept" );
}
sub handle_ignored_accept {
  # ne fait rien
}

ID

La méthode ID() renvoie l'identifiant unique de la roue. Il est utile pour stocker la roue dans une table de hachage. Tous les événements POE::Wheel doivent être accompagnés d'un ID de roue, ce qui permet de référencer la roue dans leurs gestionnaires d'événements.

sub setup_listener {
  my $wheel = POE::Wheel::ListenAccept->new(... etc  ...);
  $_[HEAP]{listeners}{$wheel->ID} = $wheel;
}

ÉVÉNEMENTS PUBLICS

POE::Wheel::ListenAccept émet quelques événements.

AcceptEvent

"AcceptEvent" nomme l'événement qui sera émis pour chaque socket client nouvellement accepté. Il est accompagné de trois paramètres :

$_[ARG0] contient le descripteur du socket client nouvellement accepté. Il appartient à l'application de faire quelque chose avec ce socket. La plupart des cas d'utilisation impliquent de passer le socket à un constructeur POE::Wheel::ReadWrite.

$_[ARG1] contient la valeur de retour de l'appel accept(), qui est souvent l'extrémité distante encodée du socket.

$_[ARG2] contient l'identifiant unique de l'objet POE::Wheel::ListenAccept. C'est la même valeur que celle renvoyée par la méthode ID() de la roue.

Un exemple de gestionnaire "AcceptEvent" :

sub accept_state {
  my ($client_socket, $remote_addr, $wheel_id) = @_[ARG0..ARG2];
  # Rend l'adresse distante lisible par l'homme.
  my ($port, $packed_ip) = sockaddr_in($remote_addr);
  my $dotted_quad = inet_ntoa($packed_ip);
  print(
    "La roue $wheel_id a accepté une connexion de ",
    "$dotted_quad port $port.\n"
  );
  # Lance une session pour interagir avec le socket.
  create_server_session($handle);
}

ErrorEvent

"ErrorEvent" nomme l'événement qui sera généré chaque fois qu'une nouvelle connexion n'a pas pu être acceptée avec succès. Cet événement est accompagné de quatre paramètres :

$_[ARG0] contient le nom de l'opération qui a échoué. Il s'agit généralement de 'accept', mais gardez à l'esprit que ce n'est pas nécessairement un nom de fonction.

$_[ARG1] et $_[ARG2] contiennent les valeurs numérique et textuelle de $!, respectivement. POE::Wheel::ListenAccept sait comment gérer EAGAIN (et les équivalents dépendant du système), donc cette erreur ne sera jamais renvoyée.

$_[ARG3] contient l'identifiant unique de la roue, ce qui peut être utile pour arrêter une roue particulière parmi un groupe.

Un exemple de gestionnaire d'événement "ErrorEvent". Cela suppose que les roues sont sauvegardées comme dans l'exemple "ID".

sub error_state {
  my ($operation, $errnum, $errstr, $wheel_id) = @_[ARG0..ARG3];
  warn "La roue $wheel_id a généré une erreur $operation $errnum: $errstr\n";
  delete $_[HEAP]{listeners}{$wheel_id};
}

VOIR AUSSI

POE::Wheel décrit les opérations de base de toutes les roues plus en profondeur. Vous devez savoir cela.

POE::Wheel::ReadWrite pour une façon possible de gérer les clients une fois que vous avez leurs sockets.
