POE::Filter::Reference(3) Documentation Perl fournie par l'utilisateur POE::Filter::Reference(3)

NOM

POE::Filter::Reference - geler et dégeler des données Perl arbitraires

SYNOPSIS

#!perl
use YAML;
use POE qw(Wheel::ReadWrite Filter::Reference);
POE::Session->create(
  inline_states => {
    _start => sub {
      pipe(my($read, $write)) or die $!;
      $_[HEAP]{io} = POE::Wheel::ReadWrite->new(
        InputHandle => $read,
        OutputHandle => $write,
        Filter => POE::Filter::Reference->new(),
        InputEvent => "got_perl_data",
      );
      $_[HEAP]{io}->put(
        { key_1 => 111, key_2 => 222 }
      );
    },
    got_perl_data => sub {
      print "Got data:\n", YAML::Dump($_[ARG0]);
      print "Bye!\n";
      delete $_[HEAP]{io};
    }
  }
);
POE::Kernel->run();
exit;

DESCRIPTION

POE::Filter::Reference permet aux programmes d'envoyer et de recevoir des structures de données Perl arbitraires sans se soucier d'un protocole de ligne. Sa méthode put() sérialise les données Perl en un flux d'octets adapté à la transmission. get_one() analyse les structures de données à partir d'un tel flux.

Par défaut, POE::Filter::Reference utilise Storable pour sa magie. Un autre sérialiseur peut être spécifié lors de la construction.

MÉTHODES DE FILTRE PUBLIQUES

new

new() crée et initialise un objet POE::Filter::Reference. Il accepte une liste de paramètres nommés.

Serializer

Toute classe qui prend en charge nfreeze() (ou freeze()) et thaw() peut être utilisée comme Serializer. Si un Serializer implémente à la fois nfreeze() et freeze(), alors la version "réseau" (nfreeze) sera utilisée.

Serializer peut être un nom de classe :

# Utiliser Storable explicitement, spécifié par le nom du package.
my $filter = POE::Filter::Reference->newer( Serializer=>"Storable" );
# Utiliser YAML à la place. Compresser sa sortie, car elle peut être verbeuse.
my $filter = POE::Filter::Reference->new("YAML", 1);

Serializer peut également être un objet :

# Utiliser un objet.
my $serializer = Data::Serializer::Something->new();
my $filter = POE::Filter::Reference->newer( Serializer => $serializer );

Si Serializer est omis ou indéfini, le filtre Reference essaiera d'utiliser Storable, FreezeThaw et YAML dans cet ordre. POE::Filter::Reference mourra s'il ne trouve pas l'un de ces sérialiseurs, mais cela arrive rarement maintenant que Storable et YAML sont inclus avec Perl.

Compression

Si Compression est vrai, Compress::Zlib sera appelé pour réduire la taille des données sérialisées. Il décompressera également les données du flux entrant.

MaxBuffer

"MaxBuffer" définit la quantité maximale de données que le filtre conservera tout en essayant de construire une nouvelle référence. Par défaut, 512 Mo.

NoFatals

Si NoFatals est vrai, les messages seront décongelés à l'intérieur d'un bloc eval. Par défaut, cependant, thaw() est autorisé à mourir normalement. Si une erreur se produit alors que NoFatals est actif, POE::Filter::Reference retournera une chaîne contenant le contenu de $@ au moment où l'eval a échoué. Donc, lors de l'utilisation de NoFatals, il est important de vérifier si l'entrée est réellement une référence :

sub got_reference {
  my $message = $_[ARG0];
  if (ref $message) {
    print "Got data:\n", YAML::Dump($message);
  }
  else {
    warn "Input decode error: $message\n";
  }
}

new() essaiera de charger toutes les classes dont il a besoin pour la "Compression" ou le "Serializer".

new [SERIALIZER [, COMPRESSION [, NO_FATALS]]]

C'est l'ancienne syntaxe du constructeur. Elle n'est pas conforme à la syntaxe normale des paramètres du constructeur POE::Filter. Veuillez utiliser la nouvelle syntaxe à la place.

Appeler "new" de cette manière est équivalent à

POE::Filter::Reference->new( Serializer => SERIALIZER,
                             Compression => COMPRESSION,
                             NoFatals  => NO_FATALS );

Veuillez noter que si vous avez une classe de sérialiseur personnalisée appelée "Serializer", vous devrez mettre à jour votre code vers la nouvelle syntaxe.

API DU SÉRIALISEUR

Voici ce que POE::Filter::Reference attend de ses sérialiseurs.

thaw SERIALIZED

thaw() est requis. Il accepte deux paramètres : $self et une scalaire contenant un flux d'octets SERIALIZED représentant une seule structure de données Perl. Il retourne une structure de données Perl reconstituée.

sub thaw {
  my ($self, $stream) = @_;
  my $reference = $self->_deserialization_magic($stream);
  return $reference;
}

nfreeze REFERENCE

Soit nfreeze(), soit freeze() est requis. Ils se comportent identiquement, sauf que nfreeze() est garanti d'être portable sur les réseaux et entre les architectures de machines.

Ces congélateurs acceptent deux paramètres : $self et une REFERENCE à des données Perl. Ils retournent une version sérialisée des données référencées.

sub nfreeze {
  my ($self, $reference) = @_;
  my $stream = $self->_serialization_magic($reference);
  return $stream;
}

freeze REFERENCE

freeze() est une forme alternative de nfreeze(). Il a la même signature d'appel que nfreeze(), mais il ne garantit pas que les données sérialisées seront portables entre les architectures de machines.

Si vous devez choisir entre implémenter freeze() et nfreeze() pour une utilisation avec POE::Filter::Reference, optez pour nfreeze().

BOGUES

Pas tant des bogues que des mises en garde :

Il est important d'utiliser des sérialiseurs identiques de chaque côté d'une connexion. Même différentes versions du même sérialiseur peuvent corrompre les données en transit.

La plupart (sinon tous) des sérialiseurs re-béniront les données à la destination, mais beaucoup d'entre eux ne chargeront pas les classes nécessaires pour faire fonctionner ces bénédictions. Assurez-vous que les mêmes classes et versions sont disponibles des deux côtés du fil.

POE::Filter::Reference(3pm)

NOM

POE::Filter::Reference - Un filtre de référence pour les événements POE

SYNOPSIS

use POE::Filter::Reference;

my $filter = POE::Filter::Reference->new( ... );
$filter->get_username;

DESCRIPTION

POE::Filter::Reference est un filtre POE qui manipule les événements de la pile d'appels POE. Il permet de personnaliser la façon dont les événements sont sérialisés et désérialisés, en particulier pour les références. Le but principal est de fournir un mécanisme pour manipuler les références à travers les contextes de sérialisation.

PUBLIC FILTER METHODS

  • new(...): Constructeur du filtre. Accepte des options pour personnaliser le comportement.
  • get_username: Méthode d'exemple pour montrer comment interagir avec le filtre. (Note : Ceci peut être un exemple hypothétique, la documentation réelle peut varier).

SERIALIZER API

Ce filtre implémente une API pour la sérialisation. Les méthodes spécifiques incluent généralement des opérations pour convertir des objets ou des structures de données en un format sérialisé et vice versa. Le détail de cette API dépend de la manière dont le filtre est conçu pour s'intégrer dans un framework de sérialisation.

VOIR AUSSI

  • POE - La bibliothèque principale de POE.
  • POE::Filter - La classe parente pour les filtres POE.

BOGUES

Signaler les bogues sur le système de suivi des problèmes de POE ou via le canal de communication approprié.
