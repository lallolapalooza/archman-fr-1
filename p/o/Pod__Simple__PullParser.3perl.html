Pod::Simple::PullParser(3perl) Guide du programmeur Perl Pod::Simple::PullParser(3perl)

NOM

Pod::Simple::PullParser -- une interface d'analyse basé sur le tirage (pull-parser) pour analyser le Pod

SYNOPSIS

my $parser = SomePodProcessor->new;
$parser->set_source( "whatever.pod" );
$parser->run;

Ou:

my $parser = SomePodProcessor->new;
$parser->set_source( $some_filehandle_object );
$parser->run;

Ou:

my $parser = SomePodProcessor->new;
$parser->set_source( \$document_source );
$parser->run;

Ou:

my $parser = SomePodProcessor->new;
$parser->set_source( \@document_lines );
$parser->run;

Et ailleurs:

require 5;
package SomePodProcessor;
use strict;
use base qw(Pod::Simple::PullParser);
sub run {
  my $self = shift;
 Token:
  while(my $token = $self->get_token) {
    ...process each token...
  }
}

DESCRIPTION

Cette classe est destinée à utiliser Pod::Simple pour construire un processeur de Pod -- mais un qui utilise une interface basée sur un flux d'objets jetons (token), plutôt que basée sur des événements.

C'est une sous-classe de Pod::Simple et elle hérite de toutes ses méthodes.

Une sous-classe de Pod::Simple::PullParser devrait définir une méthode "run" qui appelle "$token = $parser->get_token" pour tirer les jetons.

Voir le code source de Pod::Simple::RTF pour un exemple de formateur qui utilise Pod::Simple::PullParser.

MÉTHODES

my $token = $parser->get_token
Ceci renvoie le prochain objet jeton (qui sera d'une sous-classe de Pod::Simple::PullParserToken), ou undef si le flux du parseur a atteint la fin du document.
$parser->unget_token( $token )
$parser->unget_token( $token1, $token2, ... )
Ceci restaure le ou les objets jetons au début du flux du parseur.

La source doit être définie avant que vous puissiez analyser quoi que ce soit. La méthode la plus bas niveau est d'appeler "set_source":

$parser->set_source( $filename )
$parser->set_source( $filehandle_object )
$parser->set_source( \$document_source )
$parser->set_source( \@document_lines )

Ou vous pouvez appeler ces méthodes, que Pod::Simple::PullParser a définies pour fonctionner comme les méthodes du même nom de Pod::Simple:

$parser->parse_file(...)
$parser->parse_string_document(...)
$parser->filter(...)
$parser->parse_from_file(...)

Pour que ces méthodes fonctionnent, la sous-classe de Pod::Simple::PullParser qui traite le Pod doit avoir défini une méthode $parser->run -- il est donc conseillé à toutes les sous-classes de Pod::Simple::PullParser de le faire. Voir la Synopsis ci-dessus, ou le code source de Pod::Simple::RTF.

Les auteurs de sous-classes de formateurs pourraient trouver ces méthodes utiles à appeler sur un objet parseur à partir duquel vous n'avez pas encore commencé à tirer des jetons:

my $title_string = $parser->get_title
Ceci essaie d'obtenir la chaîne de titre à partir de $parser, en obtenant quelques jetons, en les analysant pour trouver le titre, puis en les remettant de côté afin que vous puissiez traiter le flux de jetons depuis le début.

Par exemple, supposez que vous ayez un document qui commence par:

=head1 NAME
Hoo::Boy::Wowza -- Stuff B<wow> yeah!

$parser->get_title sur ce document renverra "Hoo::Boy::Wowza -- Stuff wow yeah!". Si le document commence par:

=head1 Name
Hoo::Boy::W00t -- Stuff B<w00t> yeah!

Alors vous devrez passer l'option "nocase" pour reconnaître "Name":

$parser->get_title(nocase => 1);

Dans les cas où get_title ne trouve pas le titre, il renverra une chaîne vide ("").

my $title_string = $parser->get_short_title
Ceci est juste comme get_title, sauf qu'il renvoie uniquement le nom du module, si le titre semble être de la forme "SomeModuleName -- description".

Par exemple, supposez que vous ayez un document qui commence par:

=head1 NAME
Hoo::Boy::Wowza -- Stuff B<wow> yeah!

Alors $parser->get_short_title sur ce document renverra "Hoo::Boy::Wowza".

Mais si le document commence par:

=head1 NAME
Hooboy, stuff B<wow> yeah!

Alors $parser->get_short_title sur ce document renverra "Hooboy, stuff wow yeah!". Si le document commence par:

=head1 Name
Hoo::Boy::W00t -- Stuff B<w00t> yeah!

Alors vous devrez passer l'option "nocase" pour reconnaître "Name":

$parser->get_short_title(nocase => 1);

Si le titre ne peut pas être trouvé, alors get_short_title renvoie une chaîne vide ("").

$author_name = $parser->get_author
Ceci fonctionne comme get_title sauf qu'il renvoie le contenu de la section "=head1 AUTHOR\n\nParagraph...\n", en supposant que cette section n'est pas excessivement longue. Pour reconnaître une section "=head1 Author\n\nParagraph\n", passez l'option "nocase": 
$parser->get_author(nocase => 1);

(Cette méthode tolère aussi "AUTHORS" au lieu de "AUTHOR".)

$description_name = $parser->get_description
Ceci fonctionne comme get_title sauf qu'il renvoie le contenu de la section "=head1 DESCRIPTION\n\nParagraph...\n", en supposant que cette section n'est pas excessivement longue. Pour reconnaître une section "=head1 Description\n\nParagraph\n", passez l'option "nocase": 
$parser->get_description(nocase => 1);
$version_block = $parser->get_version
Ceci fonctionne comme get_title sauf qu'il renvoie le contenu du bloc "=head1 VERSION\n\n[BIG BLOCK]\n". Notez que ceci ne renvoie PAS la $VERSION du module !! Pour reconnaître une section "=head1 Version\n\n[BIG BLOCK]\n", passez l'option "nocase": 
$parser->get_version(nocase => 1);

NOTE

Vous n'êtes pas réellement obligé de définir une méthode "run". Si vous écrivez une classe de formatage de Pod, vous devriez définir une "run" juste pour que les utilisateurs puissent appeler "parse_file" etc., mais vous n'êtes pas obligé de le faire.

Et si vous n'écrivez pas une classe de formatage, mais écrivez simplement un programme qui fait quelque chose de simple avec un objet Pod::PullParser (et non un objet d'une sous-classe), alors il n'y a aucune raison de vous embêter à sous-classer pour ajouter une méthode "run".
