POE::Component::Resolver(3) Documentation Perl contribuée par les utilisateurs POE::Component::Resolver(3)

NOM

POE::Component::Resolver - Un résolveur getaddrinfo() non bloquant

VERSION

version 0.921

SYNOPSIS

#!/usr/bin/perl
use warnings;
use strict;
use POE;
use POE::Component::Resolver qw( AF_INET AF_INET6 );
my $r = POE::Component::Resolver->new(
        max_resolvers => 8,
        idle_timeout  => 5,
        af_order      => [ AF_INET6, AF_INET ],
        # sidecar_program => $path_to_program,
);
my @hosts = qw( ipv6-test.com );
my $tcp   = getprotobyname("tcp");
POE::Session->create(
        inline_states => {
                _start => sub {
                        foreach my $host (@hosts) {
                                $r->resolve(
                                        host    => $host,
                                        service => "http",
                                        event   => "got_response",
                                        hints   => { protocol => $tcp },
                                ) or die $!;
                        }
                },
                _stop => sub { print "client session stopped\n" },
                got_response => sub {
                        my ($error, $addresses, $request) = @_[ARG0..ARG2];
                        use YAML; print YAML::Dump(
                                {
                                        error => $error,
                                        addr => $addresses,
                                        req => $request,
                                }
                        );
                },
        }
);
POE::Kernel->run();

DESCRIPTION

POE::Component::Resolver effectue des appels à Socket::getaddrinfo() dans des sous-processus où ils sont autorisés à bloquer aussi longtemps que nécessaire.

Par défaut, il exécutera huit sous-processus et préférera les familles d'adresses dans l'ordre de retour par getaddrinfo(). Ces paramètres par défaut peuvent être remplacés par des paramètres du constructeur. getaddrinfo() délègue au résolveur du système d'exploitation, qui peut être reconfiguré selon les conventions habituelles.

MÉTHODES PUBLIQUES

new

Crée un nouveau résolveur. Renvoie un objet qui doit être conservé et utilisé pour effectuer des requêtes. Voir le synopsis.

Accepte jusqu'à quatre paramètres nommés optionnels.

"af_order" peut contenir un arrayref avec les familles d'adresses à autoriser, dans l'ordre de préférence. Sans "af_order", le composant préférera les adresses IPv4 aux adresses IPv6 pour des raisons de compatibilité héritée. Cela pourrait changer à l'avenir à mesure que l'IPv6 gagne en acceptation. Voir "VARIABLES D'ENVIRONNEMENT" pour une façon de remplacer la valeur par défaut sans modifier les modules.

# Préférer les adresses IPv6, mais aussi renvoyer les adresses IPv4.
my $r1 = POE::Component::Resolver->new(
        af_order => [ AF_INET6, AF_INET ]
);
# Ne renvoyer que les adresses IPv6,
# ou rien dans les cas où seules des adresses IPv4 existent.
my $r2 = POE::Component::Resolver->new(
        af_order => [ AF_INET6 ]
);

"idle_timeout" détermine combien de temps conserver les sous-processus de résolveur inactifs avant de les nettoyer, en secondes. La valeur par défaut est de 15.0 secondes.

"max_resolvers" contrôle le parallélisme du composant en définissant le nombre maximum de processus secondaires à gérer. La valeur par défaut est de 8, mais moins ou plus de processus peuvent être configurés en fonction des ressources dont vous disposez et du degré de parallélisme requis.

# Un à la fois, mais sans le blocage gênant.
my $r3 = POE::Component::Resolver->new( max_resolvers => 1 );

"sidecar_program" contient l'emplacement sur disque d'un programme qui effectuera des recherches bloquantes sur l'entrée standard et imprimera les résultats sur la sortie standard. Le programme secondaire n'est nécessaire que dans des environnements spéciaux où le regroupement et l'exécution d'utilitaires supplémentaires sont délicats. PAR est un tel environnement.

Le programme secondaire doit contenir au moins deux instructions:

use POE::Component::Resolver::Sidecar;
POE::Component::Resover::Sidecar->main();

resolve

resolve() lance une nouvelle requête pour résoudre un domaine. La requête sera mise en file d'attente dans le composant jusqu'à ce qu'un processus secondaire puisse la traiter. resolve() renvoie un ID de requête qui peut être utilisé pour cancel() une requête avant sa complétion (ou undef si la requête n'a pas pu démarrer, par exemple lors de l'arrêt). Resolve nécessite deux paramètres et accepte certains paramètres optionnels supplémentaires.

"host" et "service" sont obligatoires et contiennent l'hôte (nom ou adresse Internet) et le service (nom ou port numérique) qui seront passés tels quels à getaddrinfo(). Voir Socket pour plus de détails.

"event" est optionnel ; il contient le nom de l'événement qui contiendra la réponse du résolveur. S'il est omis, il sera par défaut "resolver_response"; vous pourriez vouloir spécifier un nom d'événement plus court.

"hints" est optionnel. S'il est spécifié, il doit contenir un hashref d'indices exactement comme getaddrinfo() les attend. Voir Socket pour plus de détails.

"misc" est une donnée de continuation optionnelle qui sera renvoyée dans la réponse. Elle peut contenir tout type de données requis par l'application.

cancel

Annule une requête, étant donné l'ID de la requête.

my $request_id = $resolver->resolve("poe.dyndns.org", "http");
$resolver->cancel($request_id);

shutdown

Arrête le résolveur. POE::Component::Resolver conserve les ressources, y compris les processus enfants, pendant jusqu'à "idle_timeout" secondes. Cela peut faire fonctionner les programmes jusqu'à "idle_timeout" secondes de plus qu'ils ne le devraient.

POE::Component::Resolver libérera ses ressources (y compris les processus enfants) lorsque sa méthode shutdown() sera appelée.

unpack_addr

En contexte scalaire, unpack_addr($response_addr_hashref) renvoie l'élément addr de $response_addr_hashref sous une forme numérique appropriée pour la famille d'adresses.

sub handle_resolver_response {
        my ($error, $addresses, $request) = @_[ARG0..ARG2];
        foreach my $a (@$addresses) {
                my $numeric_addr = $resolver->unpack_addr($a);
                print "$request->{host} = $numeric_addr\n";
        }
}

En contexte de liste, il renvoie le port et l'adresse numériques.

sub handle_resolver_response {
        my ($error, $addresses, $request) = @_[ARG0..ARG2];
        foreach my $a (@$addresses) {
                my ($$numeric_addr, $port) = $resolver->unpack_addr($a);
                print "$request->{host} = $numeric_addr\n";
        }
}

unpack_addr() est un wrapper pratique autour de getnameinfo() de Socket. Vous êtes certainement invité à utiliser la fonction discrète à la place.

unpack_addr() renvoie une absence regrettable en cas d'échec, quel que soit le contexte. Vous pouvez vérifier le retour undef.

ÉVÉNEMENTS PUBLICS

resolver_response

L'événement de réponse du résolveur comprend trois paramètres.

$_[ARG0] et $_[ARG1] contiennent les valeurs de retour de l'appel getaddrinfo() de Socket. Il s'agit d'un message d'erreur (si l'appel a échoué) et d'un arrayref de structures d'adresses si l'appel a réussi.

Le composant fournit son propre message d'erreur, 'component shut down'. Cette réponse est donnée pour chaque requête en attente au moment où l'utilisateur arrête le composant.

$_[ARG2] contient un hashref d'informations fournies à la méthode resolve(). Spécifiquement, les valeurs des paramètres "host", "service" et "misc" de resolve().

VARIABLES D'ENVIRONNEMENT

POCO_RESOLVER_IPV

La variable d'environnement POCO_RESOLVER_IPV définit l'ordre de recherche de protocole Internet par défaut de ce composant. Si la variable existe, elle doit contenir une chaîne avec les chiffres 4 et/ou 6. POE::Component::Resolver les traitera comme des versions de protocole Internet à considérer, dans l'ordre de préférence.

POE::Component::Resolver(3pm) - Perl manual page

NAME

POE::Component::Resolver - A POE component for asynchronous DNS resolution

VERSION

0.921

SYNOPSIS

 use POE::Component::Resolver;

 my $resolver = POE::Component::Resolver->spawn;

 POE::Kernel->run;

 # send events to the resolver
 $poe_kernel->post( $resolver => 'resolve', 'www.perl.com' );
 $poe_kernel->post( $resolver => 'lookup', '192.0.2.1' );

 # handle responses from the resolver
 sub handle_resolved {
     my ($where, $host) = @_[ARG0, ARG1];
     # ... process $host ...
 }
 sub handle_looked_up {
     my ($where, $ip) = @_[ARG0, ARG1];
     # ... process $ip ...
 }

 $poe_kernel->subscribe( resolved => \&handle_resolved );
 $poe_kernel->subscribe( looked_up => \&handle_looked_up );

 # later, when done
 $resolver->shutdown;

DESCRIPTION

POE::Component::Resolver is a POE component that handles DNS resolution via a pool of child processes. This prevents your main POE event loop from blocking during potentially long DNS lookups.

It provides two main methods: resolve and lookup.

resolve HOSTNAME to IP_ADDRESS
Resolves a hostname to one or more IP addresses. Emits a resolved event with the original request and a list of IP addresses.
lookup IP_ADDRESS to HOSTNAME
Looks up an IP address to find its canonical hostname. Emits a looked_up event with the original request and the hostname.

The component spawns a pool of child processes to perform the actual DNS lookups. This is configured via the process_count option during spawning. The default is to spawn as many processes as there are CPUs on the system.

You can also configure the idle_timeout for the child processes. This is the amount of time a child process will remain idle before exiting. The default is 15.0 seconds.

The component automatically handles signals like HUP to reload the configuration.

ENVIRONMENT VARIABLES

The behavior of the resolver can be influenced by the following environment variables:

Default to IPv4 addresses only:

export POCO_RESOLVER_IPV=4

Default to IPv6 addresses only:

export POCO_RESOLVER_IPV=6

Prefer IPv6, but accept IPv4 if needed:

export POCO_RESOLVER_IPV=64

Prefer IPv4, but accept IPv6 if needed:

export POCO_RESOLVER_IPV=46

COMPATIBILITY ISSUES

Microsoft Windows

This module requires "Microsoft TCP/IP version 6" to be installed. Steps for Windows XP Pro (the steps for your particular version of Windows may be subtly or drastically different):

  • Open your Control Panel
  • Open your Network Connections
  • Select your network connection from the available one(s)
  • In the Local Area Connection Status dialog, click the Properties button
  • If "Microsoft TCP/IP version 6" is listed as an item being used, you are done.
  • Otherwise click Install...
  • Choose to add a Protocol
  • And install "Microsoft TCP/IP version 6" from the list of network protocols.

BUGS

There is no timeout on requests.

There is no way to cancel a pending request.

TROUBLESHOOTING

programs linger for several seconds before exiting

Programs should shutdown() their POE::Component::Resolver objects when they are through needing asynchronous DNS resolution. Programs should additionally destroy their resolvers if they intend to run awhile and want to reuse the memory they consume.

In some cases, it may be necessary to shutdown components that perform asynchronous DNS using POE::Component::Resolver... such as POE::Component::IRC, POE::Component::Client::Keepalive and POE::Component::Client::HTTP.

By default, the resolver subprocesses hang around for idle_timeout, which defaults to 15.0 seconds. Destroying the Resolver object will clean up the process pool. Assuming only that is keeping the event loop active, the program will then exit cleanly.

Alternatively, reduce idle_timeout to a more manageable number, such as 5.0 seconds.

Otherwise something else may also be keeping the event loop active.

NOM

POE::Component::Resolver - Un composant POE pour la résolution DNS asynchrone

VERSION

0.921

SYNOPSIS

 use POE::Component::Resolver;

 my $resolver = POE::Component::Resolver->spawn;

 POE::Kernel->run;

 # envoyer des événements au résolveur
 $poe_kernel->post( $resolver => 'resolve', 'www.perl.com' );
 $poe_kernel->post( $resolver => 'lookup', '192.0.2.1' );

 # gérer les réponses du résolveur
 sub handle_resolved {
     my ($where, $host) = @_[ARG0, ARG1];
     # ... traiter $host ...
 }
 sub handle_looked_up {
     my ($where, $ip) = @_[ARG0, ARG1];
     # ... traiter $ip ...
 }

 $poe_kernel->subscribe( resolved => \&handle_resolved );
 $poe_kernel->subscribe( looked_up => \&handle_looked_up );

 # plus tard, quand c'est fini
 $resolver->shutdown;

DESCRIPTION

POE::Component::Resolver est un composant POE qui gère la résolution DNS via un pool de processus enfants. Cela empêche votre boucle d'événements POÉ principale de se bloquer pendant des recherches DNS potentiellement longues.

Il fournit deux méthodes principales : resolve et lookup.

resolve NOM_HOTE vers ADRESSE_IP
Résout un nom d'hôte en une ou plusieurs adresses IP. Émet un événement resolved avec la requête d'origine et une liste d'adresses IP.
lookup ADRESSE_IP vers NOM_HOTE
Recherche une adresse IP pour trouver son nom d'hôte canonique. Émet un événement looked_up avec la requête d'origine et le nom d'hôte.

Le composant lance un pool de processus enfants pour effectuer les recherches DNS réelles. Ceci est configuré via l'option process_count lors du lancement. La valeur par défaut est de lancer autant de processus qu'il y a de CPU sur le système.

Vous pouvez également configurer le idle_timeout pour les processus enfants. C'est le temps pendant lequel un processus enfant restera inactif avant de se terminer. La valeur par défaut est de 15.0 secondes.

Le composant gère automatiquement les signaux tels que HUP pour recharger la configuration.

VARIABLES D'ENVIRONNEMENT

Le comportement du résolveur peut être influencé par les variables d'environnement suivantes :

Par défaut, uniquement les adresses IPv4 :

export POCO_RESOLVER_IPV=4

Par défaut, uniquement les adresses IPv6 :

export POCO_RESOLVER_IPV=6

Préférer IPv6, mais accepter IPv4 si nécessaire :

export POCO_RESOLVER_IPV=64

Préférer IPv4, mais accepter IPv6 si nécessaire :

export POCO_RESOLVER_IPV=46

PROBLEMES DE COMPATIBILITE

Microsoft Windows

Ce module nécessite que "Microsoft TCP/IP version 6" soit installé. Étapes pour Windows XP Pro (les étapes pour votre version particulière de Windows peuvent être subtilement ou radicalement différentes) :

  • Ouvrez votre Panneau de configuration
  • Ouvrez vos Connexions réseau
  • Sélectionnez votre connexion réseau parmi celles disponibles
  • Dans la boîte de dialogue État de la connexion au réseau local, cliquez sur le bouton Propriétés
  • Si "Microsoft TCP/IP version 6" est listé comme un élément utilisé, vous avez terminé.
  • Sinon, cliquez sur Installer...
  • Choisissez d'ajouter un Protocole
  • Et installez "Microsoft TCP/IP version 6" à partir de la liste des protocoles réseau.

BOGUES

Il n'y a pas de délai d'attente pour les requêtes.

Il n'y a aucun moyen d'annuler une requête en attente.

DEPANNAGE

les programmes s'attardent plusieurs secondes avant de sortir

Les programmes devraient appeler shutdown() sur leurs objets POE::Component::Resolver lorsqu'ils n'ont plus besoin de résolution DNS asynchrone. Les programmes devraient également détruire leurs résolveurs s'ils ont l'intention de fonctionner longtemps et de réutiliser la mémoire qu'ils consomment.

Dans certains cas, il peut être nécessaire de fermer des composants qui effectuent une résolution DNS asynchrone en utilisant POE::Component::Resolver... tels que POE::Component::IRC, POE::Component::Client::Keepalive et POE::Component::Client::HTTP.

Par défaut, les sous-processus du résolveur restent actifs pendant la durée de idle_timeout, qui est de 15.0 secondes par défaut. La destruction de l'objet Resolver nettoiera le pool de processus. En supposant que ce soit la seule chose qui maintient la boucle d'événements active, le programme se terminera alors proprement.

Alternativement, réduisez idle_timeout à un nombre plus gérable, tel que 5.0 secondes.

Sinon, quelque chose d'autre pourrait également maintenir la boucle d'événements active.
