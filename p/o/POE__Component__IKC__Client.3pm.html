NOM

POE::Component::IKC::Client - Client de communication inter-noyau POE (IKC)

SYNOPSIS

use POE;
use POE::Component::IKC::Client;
POE::Component::IKC::Client->spawn(
    ip=>$ip, 
    port=>$port,
    name=>"Client$$",
    subscribe=>[qw(poe:/*/timserver)]
);
...
$poe_kernel->run();

DESCRIPTION

Ce module implémente un client IKC de POE. Un client IKC tente de se connecter à un serveur IKC. Si la connexion réussit, il négocie certains paramètres de connexion. Après cela, le serveur et le client POE sont pratiquement identiques.

FONCTIONS EXPORTÉES

create_ikc_client

Syntaxe abrégée pour POE::Component::IKC::Client->spawn.

MÉTHODES DE CLASSE

spawn

Cette méthode initie tout le travail de connexion à un serveur IKC. Les paramètres sont :

"ip"
Adresse de connexion. Peut être un quad-dotted ('127.0.0.1') ou un nom d'hôte ('foo.pied.nu'). Par défaut '127.0.0.1', alias INADDR_LOOPBACK.
"port"
Port de connexion. Peut être numérique (80) ou un service ('http').
"unix"
Chemin vers le socket de domaine Unix sur lequel le serveur écoute.
"name"
Nom du noyau local. C'est ainsi que nous devons nous "annoncer" aux noyaux étrangers. Il agit comme un "alias de noyau". Ce paramètre est temporaire, en attendant l'ajout de vrais noms de noyau dans le noyau POE. Ce nom, et tous les alias, seront enregistrés auprès du répondeur afin que vous puissiez leur envoyer des messages comme s'ils étaient distants.
"aliases"
Tableau de références d'alias supplémentaires pour ce noyau. Amusant, amusant, amusant !
"on_connect"
Référence de code qui est appelée lorsque la connexion a été établie avec le noyau étranger. Normalement, vous l'utiliseriez pour démarrer les sessions qui envoient des événements aux noyaux étrangers.

Notez également que la référence de code sera exécutée depuis une session de canal IKC, PAS depuis votre propre session. Cela signifie que des choses comme $poe_kernel->delay_set() ne feront pas ce que vous pensez qu'elles devraient faire.

Cependant, cela signifie que vous pouvez obtenir l'ID de session du canal IKC pour cette connexion.

POE::Component::IKC::Client->spawn(
    ....
        on_connect=>sub {
            $heap->{channel} = $poe_kernel->get_active_session()->ID;
        },
    ....
    );

Cependant, IKC/monitor fournit un mécanisme plus puissant pour détecter les connexions. Voir POE::Component::IKC::Responder.

"on_error"
Référence de code qui est appelée pour toutes les erreurs de connexion. Vous pourriez l'utiliser pour redémarrer la tentative de connexion. Les paramètres sont $operation, $errnum et $errstr, qui correspondent à l'événement FailureEvent de POE::Wheel::SocketFactory, à consulter.

Cependant, IKC/monitor fournit un mécanisme plus puissant pour détecter les erreurs. Voir POE::Component::IKC::Responder.

Notez également que la référence de code sera exécutée depuis une session IKC, PAS depuis votre propre session. Cela signifie que des choses comme $poe_kernel->delay_set() ne feront pas ce que vous pensez qu'elles devraient faire.

"subscribe"
Référence de tableau de spécificateurs (soit des sessions étrangères, soit des états étrangers) auxquels vous souhaitez vous abonner. on_connect ne sera appelé que lorsque IKC aura réussi à s'abonner à tous les spécificateurs. S'il ne peut pas, il mourra(). C'est nul. "monitor" nous sauvera tous.
"serializers"
Référence de tableau ou scalaire des paquets que vous souhaitez utiliser pour la sérialisation des données. D'abord, IKC essaie de charger chaque paquet. Ensuite, lors de la connexion à un serveur, il interroge le serveur sur chacun d'eux jusqu'à ce que le serveur accepte un sérialiseur qui fonctionne de son côté.

Un paquet sérialiseur nécessite 2 fonctions : freeze (ou nfreeze) et thaw. Voir "POE::Filter::Reference".

La valeur par défaut est "[qw(Storable FreezeThaw POE::Component::IKC::Freezer)]". "Storable" et "FreezeThaw" sont des modules en C sur CPAN. Ils sont beaucoup, beaucoup, beaucoup plus rapides que le sérialiseur intégré d'IKC "POE::Component::IKC::Freezer". Ce sérialiseur utilise "Data::Dumper" et "eval $code" pour accomplir la tâche. Il y a un problème de sécurité évident ici. Cependant, il a l'avantage d'être en Perl pur et tous les modules sont inclus dans la distribution Perl de base.

Il convient de noter que vous devriez avoir la même version de "Storable" des deux côtés, car certaines versions ne sont pas mutuellement compatibles.

"protocol"
Quel protocole de négociation IKC utiliser. Le protocole original ("IKC") était synchrone et lent. Le nouveau protocole ("IKC0") envoie toutes les informations en une seule fois. IKC0 se dégradera gracieusement vers IKC, si le client et le serveur ne correspondent pas.

Par défaut, c'est IKC0.
