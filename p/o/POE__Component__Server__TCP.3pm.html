NOM

POE::Component::Server::TCP - un serveur TCP simplifié

SYNTAXE

#!perl
use warnings;
use strict;
use POE qw(Component::Server::TCP);
POE::Component::Server::TCP->new(
  Port => 12345,
  ClientConnected => sub {
    print "connexion reçue de $_[HEAP]{remote_ip}\n";
    $_[HEAP]{client}->put("Smile from the server!");
  },
  ClientInput => sub {
    my $client_input = $_[ARG0];
    $client_input =~ tr[a-zA-Z][n-za-mN-ZA-M];
    $_[HEAP]{client}->put($client_input);
  },
);
POE::Kernel->run;
exit;

DESCRIPTION

POE::Component::Server::TCP implémente un serveur générique multi-sessions. Des services simples peuvent être assemblés en quelques lignes de code. Par exemple, un serveur qui renvoie l'entrée au client :

use POE qw(Component::Server::TCP);
POE::Component::Server::TCP->new(
  Port => 12345,
  ClientInput => sub { $_[HEAP]{client}->put($_[ARG0]) },
);
POE::Kernel->run();

Accepter les connexions soi-même

POE::Component::Server::TCP a un mode par défaut où il accepte les nouvelles connexions et crée les sessions pour les gérer. Les programmes peuvent le faire eux-mêmes en fournissant leurs propres callbacks "Acceptor". Voir "Acceptor" pour les détails.

Session d'écoute maîtresse

Lors de la création, POE::Component::Server::TCP démarre une POE::Session pour écouter les nouvelles connexions. L'"Alias" du composant fait référence à cette session maîtresse.

Si "Acceptor" est spécifié, alors il appartient à ce callback de traiter les sockets nouvellement acceptés. Ses paramètres sont ceux de "SuccessEvent" de POE::Wheel::SocketFactory.

Sinon, le callback par défaut "Acceptor" démarrera une nouvelle session pour gérer chaque connexion. Ces sessions enfants n'ont pas leurs propres alias, mais leurs callbacks "ClientConnected" et "ClientDisconnected" peuvent être utilisés pour enregistrer et désenregistrer les sessions avec un espace de noms partagé, comme une table indexée par les identifiants de session, ou un objet qui gère une telle table.

my %client_namespace;
sub handle_client_connected {
  my $client_session_id = $_[SESSION]->ID;
  $client_namespace{$client_session_id} = \%anything;
}
sub handle_client_disconnected {
  my $client_session_id = $_[SESSION]->ID;
  $client_namespace{$client_session_id} = \%anything;
}

Le callback "Started" du composant est invoqué à la fin de la routine de démarrage de la session maîtresse. Les paramètres @_[ARG0..$#_] sont définis à une copie des valeurs du paramètre de constructeur "ListenerArgs" du serveur. Les autres paramètres sont standards pour les gestionnaires _start de POE::Session.

Le callback "Stopped" du composant est invoqué au début de la routine _stop de la session maîtresse. Les paramètres sont standards pour les gestionnaires _stop de POE::Session.

Le callback "Error" du composant est invoqué lorsque le serveur rencontre un problème d'écoute des connexions. "Error" peut également être appelé si l'accepteur par défaut du composant a des difficultés à accepter une connexion. "Error" reçoit les paramètres habituels pour "FailureEvent" dans POE::Wheel::SocketFactory et "ErrorEvent" dans POE::Wheel::ReadWrite.

Sessions enfants de connexion par défaut

Si "Acceptor" n'est pas spécifié, le gestionnaire par défaut de POE::Component::Server::TCP démarrera une nouvelle session pour chaque nouvelle connexion client. Comme mentionné ci-dessus, ces sessions enfants n'ont pas d'alias propres, mais elles peuvent définir des alias ou s'enregistrer d'une autre manière lors de leurs callbacks "ClientConnected" et "ClientDisconnected".

On ne saurait trop insister sur le fait que les callbacks suivants sont exécutés dans le contexte de sessions enfants dynamiques---une par connexion client---et non dans la session d'écoute maîtresse. Cela a été un point majeur de confusion. Nous accueillons les suggestions pour rendre cela plus clair.

Le callback "ClientInput" du composant définit comment les sessions enfants géreront les entrées de leurs clients. Ses paramètres sont ceux de "InputEvent" de POE::Wheel::ReadWrite.

Comme mentionné, "ClientConnected" est appelé à la fin de la routine "_start" de la session enfant. Le callback "ClientConneted" reçoit les mêmes paramètres que le _start de la session client. Le tableau passé au paramètre "Args" du constructeur est aplati et inclus dans les paramètres de "ClientConnected" comme @_[ARG0..$#_].

sub handle_client_connected {
  my @constructor_args = @_[ARG0..$#_];
  ...
}

"ClientPreConnect" est appelé avant "ClientConnected", et son but est de permettre aux programmes de rejeter des connexions ou de conditionner des sockets avant qu'ils ne soient gérés par POE::Wheel::ReadWrite.

Le gestionnaire "ClientPreConnect" est appelé avec le socket client dans $_[ARG0], et sa valeur de retour est significative. Il doit retourner un socket client valide si la connexion est acceptable. Il doit retourner undef pour rejeter la connexion.

La plupart des valeurs de $_[HEAP] sont valides dans le gestionnaire "ClientPreConnect". Évidemment, $_[HEAP]{client} ne l'est pas car cette roue n'a pas encore été créée.

Dans l'exemple suivant, le gestionnaire "ClientPreConnect" retourne le socket client après qu'il ait été mis à niveau vers une connexion SSL.

sub handle_client_pre_connect {
  # Assurez-vous que l'adresse et le port distants sont valides.
  return undef unless validate(
    $_[HEAP]{remote_ip}, $_[HEAP]{remote_port}
  );
  # SSLify le socket, qui est dans $_[ARG0].
  my $socket = eval { Server_SSLify($_[ARG0]) };
  return undef if $@;
  # Retourne le socket SSLifié.
  return $socket;
}

"ClientDisconnected" est appelé lorsque le client s'est déconnecté, soit parce que le point d'extrémité distant du socket a été fermé, soit parce que le point d'extrémité local a été fermé par le serveur. Cela ne signifie pas que la session du client est terminée, mais la session le sera très probablement très bientôt. "ClientDisconnected" est appelé depuis plusieurs endroits distincts au sein du composant, donc ses paramètres ne sont ni cohérents ni généralement utiles.

"ClientError" est appelé lorsqu'une erreur s'est produite sur le socket. Ses paramètres sont ceux de "ErrorEvent" de POE::Wheel::ReadWrite.

"ClientFlushed" est appelé lorsque toutes les sorties en attente ont été envoyées vers le socket client. Ses paramètres proviennent de "ErrorEvent" de POE::Wheel::ReadWrite.

Considérations de performance

Cette facilité d'utilisation a un prix : POE::Component::Server::TCP est souvent significativement plus lent qu'un serveur comparable écrit avec POE::Wheel::SocketFactory et POE::Wheel::ReadWrite.

Si la performance est votre objectif principal, select_read() et select_write() de POE::Kernel ont des performances similaires à IO::Select, mais votre code sera portable sur toutes les boucles d'événements supportées par POE.

Considérations pour besoins spéciaux

POE::Component::Server::TCP est écrit pour être facile à utiliser dans les cas les plus courants. Les programmes ayant des besoins plus spécifiques devraient plutôt envisager d'utiliser POE::Wheel::SocketFactory et POE::Wheel::ReadWrite. MÉTHODES PUBLIQUES

new

new() démarre un serveur basé sur POE::Component::Server::TCP et renvoie un ID de session pour la session maître d'écoute. Toute la gestion des erreurs est effectuée à l'intérieur du serveur, via les rappels "Error" et "ClientError".

Le serveur peut être arrêté en envoyant un événement "shutdown" à la session maître, soit par son ID, soit par le nom qui lui a été donné par le paramètre "Alias".

POE::Component::Server::TCP effectue beaucoup de travail dans son constructeur. L'objectif de conception est de reporter autant de frais généraux que possible dans la construction unique, de sorte que l'exécution continue ait moins de frais généraux. Pour cette raison, le constructeur du serveur peut prendre un nombre de paramètres assez impressionnant.

POE::Component::Server::TCP renvoie toujours un ID de session POE::Session pour la session qui écoutera les nouvelles connexions.

Beaucoup des paramètres du constructeur ont déjà été décrits. Ils sont brièvement repris ci-dessous.

Configuration de la session serveur

Ces paramètres du constructeur affectent la session d'écoute principale de POE::Component::Server::TCP.

Acceptor

"Acceptor" définit une référence de CODE qui déclenchera l'événement "SuccessEvent" de POE::Wheel::SocketFactory pour gérer les nouvelles connexions. Par conséquent, les paramètres passés à "Acceptor" sont identiques à ceux donnés à "SuccessEvent".

"Acceptor" est facultatif ; le gestionnaire par défaut créera une nouvelle session pour chaque connexion. Tous les paramètres du constructeur "Client" sont utilisés pour personnaliser cette session. En d'autres termes, "ClientInput" et ainsi de suite **ne sont pas utilisés lorsque** "Acceptor" **est défini**.

L'"Acceptor" par défaut ajoute une commodité et une flexibilité considérables à POE::Component::Server::TCP, mais il ne convient pas toujours à toutes les applications. Dans certains cas, un "Acceptor" personnalisé ou même la création de son propre serveur avec POE::Wheel::SocketFactory et POE::Wheel::ReadWrite peuvent être meilleurs et/ou plus rapides.

Acceptor => sub {
  my ($socket, $remote_address, $remote_port) = @_[ARG0..ARG2];
  # Configurer quelque chose pour interagir avec le client.
}

Address

"Address" définit une adresse d'interface unique à laquelle le serveur sera lié. Il utilise par défaut INADDR_ANY ou INADDR6_ANY, lors de l'utilisation d'IPv4 ou d'IPv6, respectivement. Il est souvent utilisé avec "Port".

La valeur dans "Address" est passée au paramètre "BindAddress" de POE::Wheel::SocketFactory, elle peut donc être sous quelque forme que ce module supporte. Au moment de la rédaction, cela peut être un quad IPv4 pointé, une adresse IPv6, un nom d'hôte, ou une adresse Internet packée. Voir également "Hostname".

Address => '127.0.0.1'   # Localhost IPv4
Address => "::1"         # Localhost IPv6

Alias

"Alias" est un nom facultatif qui sera donné à la session d'écoute maître du serveur. Les événements envoyés à ce nom ne seront pas livrés aux connexions individuelles.

L'"Alias" du serveur peut être important s'il est nécessaire d'arrêter un serveur.

sub sigusr1_handler {
  $_[KERNEL]->post(chargen_server => 'shutdown');
  $_[KERNEL]->sig_handled();
}

Concurrency

"Concurrency" contrôle combien de connexions peuvent être actives en même temps. Il est par défaut à -1, ce qui permet à POE::Component::Server::TCP d'accepter des connexions simultanées jusqu'à ce que le processus manque de ressources.

Définir "Concurrency" à 0 empêche le serveur d'accepter de nouvelles connexions. Cela peut être utile si un serveur doit effectuer une initialisation longue avant d'autoriser les connexions. Une fois l'initialisation terminée, il peut faire un yield(set_concurrency => -1) pour activer les connexions. De même, un serveur en cours d'exécution peut faire un yield(set_concurrency => 0) ou tout autre nombre pour ajuster dynamiquement sa concurrence. Voir "EVENTS" pour plus d'informations sur l'événement set_concurrency.

Remarque : Pour que "Concurrency" fonctionne avec un "Acceptor" personnalisé, la session d'écoute du serveur doit recevoir un événement "disconnected" chaque fois que les clients se déconnectent. Sinon, l'écouteur ne pourra pas médiatiser entre ses connexions.

Exemple :

Acceptor => sub {
  # ....
  POE::Session->create(
    # ....
    inline_states => {
      _start => sub {
        # ....
        # se souvenir de qui est son parent
        $_[HEAP]->{server_tcp} = $_[SENDER]->ID;
        # ....
      },
      got_client_disconnect => sub {
        # ....
        $_[KERNEL]->post( $_[HEAP]->{server_tcp} => 'disconnected' );
        # ....
      }
    }
  );
}

Domain

"Domain" définit l'espace d'adressage ou la famille de protocoles dans laquelle opérer. Le "Domain" peut être toute valeur supportée par POE::Wheel::SocketFactory. AF_INET (espace d'adressage Internet) est utilisé par défaut.

Utilisez AF_INET6 pour le support IPv6. Cette constante est exportée par Socket ou Socket6, selon votre version de Perl. Assurez-vous également d'avoir installé Socket::GetAddrInfo, qui est requis par POE::Wheel::SocketFactory pour le support IPv6.

Error

"Error" est le rappel qui sera invoqué lorsque le socket serveur signalera une erreur. Le rappel Error sera utilisé pour gérer l'événement FailureEvent de POE::Wheel::SocketFactory, il recevra donc les mêmes paramètres que ceux décrits là.

Un gestionnaire d'erreurs par défaut sera fourni si Error est omis. Le gestionnaire par défaut enregistrera l'erreur dans STDERR et arrêtera le serveur. Les connexions actives seront autorisées à terminer leurs transactions.

Error => sub {
  my ($syscall_name, $err_num, $err_str) = @_[ARG0..ARG2];
  # Gérer l'erreur.
}

Hostname

"Hostname" est le nom facultatif non packé de l'interface à laquelle le serveur TCP sera lié. Le nom d'hôte sera toujours résolu via inet_aton() et peut donc être un quad pointé ou un nom. La résolution de noms est une action de démarrage unique ; il n'y a pas de pénalité d'exécution continue à l'utiliser.

"Hostname" garantit la résolution de noms, là où "Address" ne le fait pas. Il est donc préférable d'utiliser "Hostname" dans les cas où la résolution doit toujours être effectuée.

InlineStates

"InlineStates" est facultatif. S'il est spécifié, il doit contenir un hashref de rappels nommés. Sa syntaxe est celle du paramètre inline_states de POE:Session->create().

Rappel : Ces gestionnaires InlineStates seront ajoutés aux sessions clients, pas à la session d'écoute principale. Un yield() dans l'écouteur n'atteindra pas ces gestionnaires.

Si POE::Kernel::ASSERT_USAGE est activé, le constructeur fera un croak() s'il détecte un état qu'il utilise en interne. Par exemple, veuillez utiliser les rappels "Started" et "Stopped" si vous souhaitez spécifier vos propres événements "_start" et "_stop" respectivement.

ObjectStates

Si "ObjectStates" est spécifié, il doit contenir un arrayref d'objets et les événements qu'ils géreront. L'arrayref doit suivre la syntaxe du paramètre object_states de POE::Session->create().

Rappel : Ces gestionnaires ObjectStates seront ajoutés aux sessions clients, pas à la session d'écoute principale. Un yield() dans l'écouteur n'atteindra pas ces gestionnaires.

Si POE::Kernel::ASSERT_USAGE est activé, le constructeur fera un croak() s'il détecte un état qu'il utilise en interne. Par exemple, veuillez utiliser les rappels "Started" et "Stopped" si vous souhaitez spécifier vos propres événements "_start" et "_stop" respectivement.

PackageStates

Lorsque "PackageStates" facultatif est défini, il doit contenir un arrayref de noms de paquets et les événements qu'ils géreront. L'arrayref doit suivre la syntaxe du paramètre package_states de POE::Session->create().

Rappel : Ces gestionnaires PackageStates seront ajoutés aux sessions clients, pas à la session d'écoute principale. Un yield() dans l'écouteur n'atteindra pas ces gestionnaires.

Si POE::Kernel::ASSERT_USAGE est activé, le constructeur fera un croak() s'il détecte un état qu'il utilise en interne. Par exemple, veuillez utiliser les rappels "Started" et "Stopped" si vous souhaitez spécifier vos propres événements "_start" et "_stop" respectivement.

Port

"Port" contient le port auquel le socket d'écoute sera lié. Il est par défaut à 0, ce qui permet généralement au système d'exploitation de choisir un port au hasard.

Port => 30023

Il est souvent utilisé avec "Address".

Started

"Started" définit un rappel facultatif qui sera invoqué dans le contexte de la session serveur principale. Il notifie le serveur qu'il a complètement démarré. Les paramètres du rappel sont les habituels pour un gestionnaire _start de session.

Stopped

"Stopped" définit un rappel facultatif qui sera invoqué dans le contexte de la session serveur principale. Il notifie le serveur qu'il s'est complètement arrêté. Les paramètres du rappel sont les habituels pour un gestionnaire _stop de session.

ListenerArgs

"ListenerArgs" est passé à la session d'écoute en tant que paramètre "args". En d'autres termes, il doit s'agir d'un arrayref, et les valeurs sont passées dans le gestionnaire "Started" sous forme de ARG0, ARG1, etc.

Configuration de la session de connexion

Ces paramètres du constructeur affectent les sessions individuelles qui interagissent avec les connexions établies.

ClientArgs

"ClientArgs" est facultatif. Lorsqu'il est spécifié, il contient un ARRAYREF qui sera développé d'un niveau et passé au rappel "ClientConnected" dans @_[A

RG0..$#_].

ClientConnected

Chaque nouvelle connexion client est gérée par une nouvelle instance de POE::Session. "ClientConnected" est une fonction de rappel qui notifie l'application lorsque la session d'un client est démarrée et prête à fonctionner. Des bannières sont souvent envoyées au client distant à partir de cette fonction de rappel.

Les paramètres @_[ARG0..$#_] pour "ClientConnected" sont une copie des valeurs de la référence de tableau du paramètre de constructeur "ClientArgs". Les autres membres de @_ sont standard pour un gestionnaire _start de POE::Session.

"ClientConnected" est appelée une fois par démarrage de session. Elle ne sera jamais appelée deux fois pour la même connexion.

ClientConnected => sub {
  $_[HEAP]{client}->put("Bonjour, client !");
  # Autre initialisation client ici.
},

ClientDisconnected

"ClientDisconnected" est une fonction de rappel qui sera invoquée lorsque le client se déconnectera ou aura été déconnecté par le serveur. Elle est utile pour nettoyer les informations globales du client, telles que les structures de salon de discussion. Les fonctions de rappel "ClientDisconnected" reçoivent les paramètres POE habituels, mais rien de spécial n'est inclus.

ClientDisconnected => sub {
  warn "Client déconnecté"; # le journaliser
}

ClientError

La fonction de rappel "ClientError" est invoquée lorsqu'un socket client signale une erreur. "ClientError" est appelée avec les paramètres habituels de POE, plus les paramètres d'erreur courants : $_[ARG0] décrit ce qui se passait au moment de l'échec. $_[ARG1] et $_[ARG2] contiennent les versions numérique et textuelle de $!, respectivement.

"ClientError" est facultative. Si elle est omise, POE::Component::Server::TCP fournira une fonction de rappel par défaut qui enregistre la plupart des erreurs sur STDERR.

Si "ClientShutdownOnError" est défini, la connexion sera fermée après le retour de "ClientError". Si "ClientDisconnected" est spécifié, il sera appelé lors du nettoyage de la session client.

"ClientError" est déclenchée par l'événement ErrorEvent de POE::Wheel::ReadWrite, elle suit donc le format de cet événement. Veuillez consulter la documentation d'ErrorEvent dans POE::Wheel::ReadWrite pour plus de détails.

ClientError => sub {
  my ($syscall_name, $error_num, $error_str) = @_[ARG0..ARG2];
  # Gérer l'erreur client ici.
}

ClientFilter

"ClientFilter" spécifie l'objet POE::Filter ou la classe qui analysera l'entrée de chaque client et sérialisera la sortie avant qu'elle ne soit envoyée à chaque client.

"ClientFilter" peut être un SCALAR, auquel cas il doit nommer la classe POE::Filter à utiliser. Chaque nouvelle connexion recevra un filtre fraîchement instancié de cette classe. Aucun paramètre de constructeur ne sera passé.

ClientFilter => "POE::Filter::Stream",

Certains filtres nécessitent des paramètres de constructeur. Ceux-ci peuvent être spécifiés par un ARRAYREF. Le premier élément est le nom de la classe POE::Filter, et les éléments suivants sont passés au constructeur de la classe.

ClientFilter => [ "POE::Filter::Line", Literal => "\n" ],

"ClientFilter" peut également se voir attribuer un OBJET POE::Filter archétypal. Dans ce cas, chaque nouvelle session client recevra un clone() de l'objet donné.

ClientFilter => POE::Filter::Line->new(Literal => "\n"),

"ClientFilter" est facultatif. Le composant utilisera "POE::Filter::Line" s'il est omis. Il existe "ClientInputFilter" et "ClientOutputFilter" si vous souhaitez spécifier un filtre différent pour les deux directions.

Les modules de filtre ne sont pas chargés automatiquement. Assurez-vous que le programme charge la classe avant de l'utiliser.

ClientFlushed

"ClientFlushed" expose l' "FlushedEvent" de POE::Wheel::ReadWrite sous forme de fonction de rappel. Elle est appelée chaque fois que le tampon de sortie du client a été complètement vidé vers le socket client. À ce stade, il est sûr de fermer le socket sans perdre de données.

"ClientFlushed" est utile pour les serveurs de streaming, où un événement "flushed" signale la nécessité d'envoyer plus de données.

ClientFlushed => sub {
  my $data_source = $_[HEAP]{file_handle};
  my $read_count = sysread($data_source, my $buffer = "", 65536);
  if ($read_count) {
    $_[HEAP]{client}->put($buffer);
  }
  else {
    $_[KERNEL]->yield("shutdown");
  }
},

L' "Acceptor" par défaut de POE::Component::Server::TCP garantit que les données sont vidées avant de terminer une fermeture de client.

ClientInput

"ClientInput" définit une fonction de rappel par connexion pour gérer l'entrée client. Cette fonction de rappel reçoit ses paramètres directement de l' "InputEvent" de POE::Wheel::ReadWrite. ARG0 contient l'enregistrement d'entrée, dont le format est défini par "ClientFilter" ou "ClientInputFilter". ARG1 contient l'ID unique de la roue, et ainsi de suite. Veuillez consulter POE:Wheel::ReadWrite pour une description approfondie de l' "InputEvent".

"ClientInput" et "Acceptor" sont mutuellement exclusifs. L'activation de l'un interdit l'autre.

ClientInput => sub {
  my $input = $_[ARG0];
  $_[HEAP]{wheel}->put("Vous avez dit : $input");
},

ClientInputFilter

"ClientInputFilter" est utilisé avec "ClientOutputFilter" pour spécifier différents protocoles pour l'entrée et la sortie. Les deux doivent être utilisés ensemble. Les deux suivent la même utilisation que "ClientFilter". Remplace le filtre défini par "ClientFilter".

ClientInputFilter  => [ "POE::Filter::Line", Literal => "\n" ],
ClientOutputFilter => 'POE::Filter::Stream',

ClientOutputFilter

"ClientOutputFilter" est utilisé avec "ClientInputFilter" pour spécifier différents protocoles pour l'entrée et la sortie. Les deux doivent être utilisés ensemble. Les deux suivent la même utilisation que "ClientFilter". Remplace le filtre défini par "ClientFilter".

ClientInputFilter  => POE::Filter::Line->new(Literal => "\n"),
ClientOutputFilter => 'POE::Filter::Stream',

ClientShutdownOnError

"ClientShutdownOnError" indique au composant si les connexions client doivent être fermées automatiquement en cas d'erreur détectée. La valeur par défaut est "true". Le définir sur false (0, undef, "") désactive cette fonctionnalité.

L'application est responsable de la gestion des erreurs client si cette fonctionnalité est désactivée. Ne pas le faire peut amener le composant à émettre un flux constant d'erreurs, finissant par ralentir l'application avec des connexions mortes qui s'emballent.

SessionParams

"SessionParams" spécifie des paramètres supplémentaires qui seront passés au constructeur de "SessionType" au moment de la création. Ce doit être une référence de tableau.

SessionParams => [ options => { debug => 1, trace => 1 } ],

Remarque : POE::Component::Server::TCP fournit ses propres paramètres de constructeur POE::Session. Les conflits entre ceux-ci et "SessionParams" peuvent entraîner un comportement erratique du composant. Pour éviter de tels problèmes, veuillez limiter SessionParams à la table de hachage "options". Voir POE::Session pour les options connues.

Nous pourrons activer d'autres options plus tard. Veuillez nous faire savoir si vous avez besoin de quelque chose.

SessionType

"SessionType" spécifie la sous-classe POE::Session qui sera créée pour chaque nouvelle connexion client. "POE::Session" est la valeur par défaut.

SessionType => "POE::Session::MultiDispatch"

ÉVÉNEMENTS

Il est possible de manipuler un composant serveur TCP en lui envoyant des messages.

Commandes principales du serveur

Ces événements doivent être envoyés au serveur principal, généralement par l'alias défini dans son paramètre Alias.

disconnected

L'événement "disconnected" informe le serveur TCP qu'une connexion a été fermée. Il est nécessaire lorsque vous utilisez "Concurrency" avec une fonction de rappel "Acceptor". L'Acceptor personnalisé doit fournir sa propre notification de déconnexion afin que la logique de comptage des connexions du serveur fonctionne.

Sinon, les clients Concurrency seront acceptés, puis plus aucun. Le serveur ne saura jamais quand les clients se sont déconnectés.

set_concurrency

"set_concurrency" définit le nombre de connexions simultanées que le serveur acceptera. Voir "Concurrency" pour plus de détails. "set_concurrency" doit avoir un paramètre : le nouveau nombre maximum de connexions.

$kernel->call("mon_alias_serveur", "set_concurrency", $max_count);

shutdown

L'événement "shutdown" démarre une fermeture de serveur gracieuse. Aucune nouvelle connexion ne sera acceptée. Les connexions existantes seront autorisées à se terminer. Le serveur sera détruit après la fin de la dernière connexion.

Commandes par connexion

Ces commandes affectent chaque session de connexion client.

shutdown

Envoyer "shutdown" à une session client individuelle demande au serveur de fermer gracieusement cette connexion. Aucune nouvelle entrée ne sera reçue, et toute sortie mise en mémoire tampon sera envoyée avant la fin de la session.

Les sessions client font généralement yield("shutdown") lorsqu'elles souhaitent déconnecter le client.

ClientInput => sub {
  if ($_[ARG0] eq "quit") {
    $_[HEAP]{client}->put("Au revoir !");
    $_[KERNEL]->yield("shutdown");
    return;
  }
  # Gérer d'autres entrées ici.
},

NOM

POE::Component::Server::TCP - Un serveur TCP simple mais extensible

SYNOPSIS

  use POE::Component::Server::TCP;

  #
  # Démarrer un serveur TCP sur le port 8080.  Les clients seront
  # gérés par un gestionnaire d'événements de session de POE qui
  # sera créé pour chaque connexion.
  #
  POE::Component::Server::TCP->new(
      Port => 8080,
      ClientConnected => \&client_connected,
      ClientDisconnected => \&client_disconnected,
      ClientInput => \&client_input,
  );

  #
  # Démarrer un autre serveur TCP, mais cette fois pour écouter
  # sur un port de socket spécifique.
  #
  POE::Component::Server::TCP->new(
      SocketDomain => AF_UNIX,
      SocketPath   => '/tmp/myserver.sock',
      ClientConnected => \&client_connected,
      ClientDisconnected => \&client_disconnected,
      ClientInput => \&client_input,
  );

  #
  # Démarrer un serveur TCP qui utilise des alias pour
  # identifier différentes configurations de serveur.
  #
  POE::Component::Server::TCP->new(
      Alias        => 'my_tcp_server',
      Port         => 1234,
      ClientInput  => \&my_server_handler,
  );

  #
  # Démarrer plusieurs serveurs avec des alias
  #
  POE::Component::Server::TCP->new(
      Alias        => 'server1',
      Port         => 8001,
      ClientInput  => \&handler1,
  );
  POE::Component::Server::TCP->new(
      Alias        => 'server2',
      Port         => 8002,
      ClientInput  => \&handler2,
  );

  # La boucle d'événements principale de POE
  POE::Kernel->run();

  sub client_connected {
      my ($session, $client_heap) = @_;
      # $session->{heap}{alias} contiendra l'alias du serveur (si défini)
      # $session->{heap}{remote_ip} contiendra l'adresse IP du client
      # $session->{heap}{remote_port} contiendra le port du client
      printf "Client connecté: %s:%d\n", $session->{heap}{remote_ip}, $session->{heap}{remote_port};
      # Envoyer un message au client
      $client_heap->{client}->put("Bienvenue !\n");
      return 1; # Retourner une valeur vraie pour continuer la session
  }

  sub client_disconnected {
      my ($session, $reason) = @_;
      printf "Client déconnecté: %s\n", $reason;
      return 1; # Retourner une valeur vraie pour continuer la session
  }

  sub client_input {
      my ($session, $input) = @_;
      printf "Données reçues du client: %s\n", $input;
      # Répondre au client
      $session->{heap}{client}->put("Vous avez dit: $input\n");
      return 1; # Retourner une valeur vraie pour continuer la session
  }

  sub handler1 {
      # Gestionnaire pour server1
      return 1;
  }

  sub handler2 {
      # Gestionnaire pour server2
      return 1;
  }

DESCRIPTION

POE::Component::Server::TCP est un composant POE qui permet de créer des serveurs TCP. Il gère l'acceptation des connexions entrantes et l'envoi de rappels à votre code de gestion des événements pour chaque connexion.

Il s'agit d'un composant simple, mais extensible. La plupart des fonctionnalités sont implémentées dans le noyau POE.

Ce composant utilise POE::Wheel::SocketFactory pour écouter les connexions entrantes et POE::Wheel::ReadWrite pour interagir avec les clients connectés.

Les gestionnaires d'événements (par exemple, ClientInput, ClientConnected, ClientDisconnected) sont appelés avec la session du client comme premier argument et les données spécifiques à l'événement comme arguments suivants.

Les sessions du client reçoivent un objet POE::Wheel::ReadWrite dans leur HEAP sous la clé client, qui peut être utilisé pour lire et écrire des données pour cette connexion client spécifique.

La gestion des erreurs est gérée par le paramètre ShutdownOnError. Si ce paramètre est défini sur une valeur vraie, la connexion client sera fermée lorsqu'une erreur se produira.

Le composant prend en charge l'utilisation d'alias pour différents serveurs, vous permettant de définir plusieurs configurations de serveurs avec des gestionnaires d'événements distincts.

PUBLIC METHODS

new

Crée un nouveau composant de serveur TCP.

Les options suivantes sont acceptées :

Alias
Un alias pour ce serveur. Peut être utilisé pour identifier le serveur dans les gestionnaires d'événements.
Concurrency
Le nombre maximum de connexions simultanées autorisées. Par défaut, il n'y a pas de limite.
ClientConnected
Un rappel à appeler lorsque un client se connecte.
ClientDisconnected
Un rappel à appeler lorsqu'un client se déconnecte.
ClientInput
Un rappel à appeler lorsqu'un client envoie des données.
DefaultHandler
Le gestionnaire d'événements par défaut à utiliser si aucun gestionnaire spécifique n'est fourni pour les événements. Il sera appelé avec l'événement et les arguments passés à post_event.
HandleListenError
Un rappel à appeler lorsqu'une erreur se produit lors de l'écoute des connexions. Il sera appelé avec l'erreur.
HandleReadError
Un rappel à appeler lorsqu'une erreur se produit lors de la lecture à partir d'un client.
HandleWriteError
Un rappel à appeler lorsqu'une erreur se produit lors de l'écriture sur un client.
ListenArgs
Une liste d'arguments à passer à POE::Wheel::SocketFactory::new. Les options SocketDomain, SocketPath, Port, et Address peuvent être spécifiées ici.
Port
Le port sur lequel écouter. Peut être spécifié ici ou dans ListenArgs.
Address
L'adresse IP sur laquelle écouter. Par défaut, toutes les interfaces sont écoutées. Peut être spécifié ici ou dans ListenArgs.
SocketDomain
Le domaine de socket à utiliser (par exemple, AF_INET, AF_UNIX). Par défaut, AF_INET. Peut être spécifié ici ou dans ListenArgs.
SocketPath
Le chemin du socket à utiliser pour les sockets de domaine Unix. Peut être spécifié ici ou dans ListenArgs.
ShutdownOnError
Si cette valeur est définie sur une valeur vraie, la connexion client sera fermée lorsqu'une erreur se produit. Par défaut, une valeur vraie.
SessionParams
Une référence à une table de hachage contenant les paramètres à passer à la création de la session du client.
ReuseAddr
Définit l'option de socket SO_REUSEADDR. Par défaut, une valeur vraie.

EVENTS

POE::Component::Server::TCP génère les événements suivants :

ClientConnected
Appelé lorsqu'un nouveau client se connecte. Les arguments sont la session du client et un pointeur vers le HEAP de la session du client.
ClientDisconnected
Appelé lorsqu'un client se déconnecte. Les arguments sont la session du client et la raison de la déconnexion.
ClientInput
Appelé lorsqu'un client envoie des données. Les arguments sont la session du client et les données reçues.
HandleListenError
Appelé lorsqu'une erreur se produit lors de l'écoute des connexions. L'argument est l'erreur.
HandleReadError
Appelé lorsqu'une erreur se produit lors de la lecture à partir d'un client. Les arguments sont la session du client et l'erreur.
HandleWriteError
Appelé lorsqu'une erreur se produit lors de l'écriture sur un client. Les arguments sont la session du client et l'erreur.

Reserved HEAP Members

Contrairement à la plupart des modules POE, POE::Component::Server::TCP stocke des données dans les HEAPs des sessions client. Ces valeurs sont fournies comme commodités pour les développeurs d'applications.

HEAP Members for Master Listening Sessions

La session d'écoute principale détient des données différentes de celles des connexions client.

alias

$_[HEAP]{alias} contient l'Alias du serveur.

concurrency

$_[HEAP]{concurrency} se souvient du paramètre "Concurrency" du serveur.

connections

$_[HEAP]{connections} est utilisé pour suivre le nombre actuel de connexions client simultanées. Il est incrémenté chaque fois qu'une nouvelle connexion est acceptée et décrémenté chaque fois qu'un client se déconnecte.

listener

$_[HEAP]{listener} contient l'objet POE::Wheel::SocketFactory utilisé pour écouter les connexions et les accepter.

HEAP Members for Connection Sessions

Ces membres de données existent au sein des sessions des connexions individuelles.

client

$_[HEAP]{client} contient un objet POE::Wheel::ReadWrite utilisé pour interagir avec le client. Toutes les méthodes POE::Wheel::ReadWrite fonctionnent.

got_an_error

$_[HEAP]{got_an_error} se souvient si la connexion client a déjà rencontré une erreur. Il fait partie de la procédure d'arrêt en cas d'erreur.

remote_ip

$_[HEAP]{remote_ip} contient l'adresse numérique du client distant sous forme lisible par l'homme.

remote_port

$_[HEAP]{remote_port} contient le port numérique de la socket du client distant sous forme lisible par l'homme.

remote_addr

$_[HEAP]{remote_addr} contient l'adresse de socket packagée du client distant sous forme lisible par l'ordinateur.

shutdown

$_[HEAP]{shutdown} est vrai si le client est en cours de fermeture. Le composant l'utilise pour ignorer les entrées client pendant la fermeture et pour fermer la connexion après que la sortie en attente ait été vidée.

shutdown_on_error

$_[HEAP]{shutdown_on_error} se souvient si la connexion client doit se fermer automatiquement en cas d'erreur.

BUGS

Cela ne ressemble en rien à ce qu'Ann avait imaginé.

Ce composant n'accepte actuellement pas plusieurs des options que POE::Wheel::SocketFactory accepte.

Ce composant ne se liera pas à plusieurs adresses à la fois. Il peut s'agir d'une limitation de SocketFactory, mais ce n'est pas intentionnel.

Ce composant a besoin d'une meilleure gestion des erreurs.

Certains cas d'utilisation nécessitent des classes de session différentes pour l'écouteur et les gestionnaires de connexion. Ceci n'est pas actuellement pris en charge. S'il vous plaît, envoyez des patchs. :)
