POE::Component::Client::DNS(3) Documentation Perl fournie par l'utilisateur POE::Component::Client::DNS(3)

NOM

POE::Component::Client::DNS - client DNS non bloquant et parallèle

VERSION

version 1.054

SYNTAXE

use POE qw(Component::Client::DNS);
my $named = POE::Component::Client::DNS->spawn(
  Alias => "named"
);
POE::Session->create(
  inline_states  => {
    _start   => \&start_tests,
    response => \&got_response,
  }
);
POE::Kernel->run();
exit;
sub start_tests {
  my $response = $named->resolve(
    event   => "response",
    host    => "localhost",
    context => { },
  );
  if ($response) {
    $_[KERNEL]->yield(response => $response);
  }
}
sub got_response {
  my $response = $_[ARG0];
  my @answers = $response->{response}->answer();
  foreach my $answer (@answers) {
    print(
      "$response->{host} = ",
      $answer->type(), " ",
      $answer->rdatastr(), "\n"
    );
  }
}

DESCRIPTION

POE::Component::Client::DNS fournit des requêtes DNS non bloquantes et parallèles en utilisant Net::DNS. En utilisant POE, cela permet à d'autres tâches de s'exécuter pendant que l'on attend les réponses des serveurs de noms.

Pour une résolution de noms simple, y compris la gestion intelligente des adresses IPv6, veuillez consulter POE::Component::Resolver.

MÉTHODES PUBLIQUES

spawn
Un programme doit invoquer au moins une instance de POE::Component::Client::DNS avant de pouvoir effectuer des requêtes DNS en arrière-plan. Chaque instance représente une connexion à un ou plusieurs serveurs de noms. Si un programme n'a besoin que de faire des requêtes DNS à un seul serveur, il n'a besoin que d'une seule instance de POE::Component::Client::DNS.

Depuis la version 0.98, vous pouvez remplacer le délai d'expiration par défaut de chaque requête. À partir de maintenant, il n'est plus nécessaire d'invoquer plusieurs instances pour affecter différents délais d'expiration à chaque requête.

La méthode "spawn" de PoCo::Client::DNS accepte plusieurs paramètres nommés :

Alias définit l'alias du composant. Les requêtes sont envoyées à cet alias. L'alias par défaut du composant est « resolver » si aucun n'est fourni. Les programmes qui invoquent plusieurs composants clients DNS doivent spécifier des alias pour N-1 d'entre eux, sinon des conflits d'alias se produiront.

Alias => $alias_session,  # par défaut « resolver »

Timeout définit le délai d'expiration par défaut du composant. Le délai d'expiration peut être remplacé par requête. Voir l'événement « request », plus loin. Si aucun délai d'expiration n'est défini, le composant attend 90 secondes par requête par défaut.

Les délais d'expiration peuvent être des nombres réels. Les délais d'expiration sont plus précis si vous avez Time::HiRes installé. POE (et donc ce composant) utilisera automatiquement Time::HiRes s'il est disponible.

Timeout => $secondes_a_attendre,  # par défaut 90

Nameservers maintient une référence à une liste de serveurs de noms à interroger. La liste est transmise directement à la méthode nameservers() de Net::DNS::Resolver. Par défaut, POE::Component::Client::DNS interroge les serveurs de noms répertoriés dans /etc/resolv.conf ou son équivalent.

Nameservers => \@serveurs_noms,  # par défaut ceux de /etc/resolv.conf

HostsFile (facultatif) maintient le nom d'un fichier hosts spécifique pour résoudre des adresses fixes. Par défaut, il recherche un fichier nommé /etc/hosts.

Sur les systèmes Windows, il peut rechercher dans les emplacements suivants :

$ENV{SystemRoot}\System32\Drivers\Etc\hosts
$ENV{SystemRoot}\System\Drivers\Etc\hosts
$ENV{SystemRoot}\hosts
resolve
resolve() demande au composant de résoudre un nom d'hôte. Il renverra une référence de hachage (décrite dans MESSAGES DE RÉPONSE, ci-dessous) s'il peut satisfaire la demande immédiatement (éventuellement à partir d'un cache). Sinon, il renvoie undef s'il doit interroger un résolveur de manière asynchrone.

Les requêtes sont envoyées sous forme de liste de champs nommés.

$resolver->resolve(
  class       => $classe_enregistrement_dns,  # par défaut « IN »
  type        => $type_enregistrement_dns,   # par défaut « A »
  host        => $hote_requete,      # obligatoire
  context     => $contexte_requete,   # obligatoire
  event       => $evenement_reponse,    # obligatoire
  timeout     => $delai_requete,   # par défaut le Timeout de spawn()
  nameservers => $serveurs_noms,       # par défaut le Nameservers du resolver
);

Les champs « class » et « type » spécifient quel type d'informations retourner sur un nom d'hôte. Dans la plupart des cas, les adresses IP sont demandées pour les noms d'hôtes, donc la classe et le type par défaut sont « IN » (Internet) et « A » (adresse), respectivement.

Le champ « host » désigne le nom d'hôte à rechercher. Il est obligatoire.

Le champ « event » indique quel événement envoyer lorsqu'une réponse est disponible. Il est obligatoire, mais ne sera pas utilisé si resolve() peut renvoyer immédiatement une réponse mise en cache.

« timeout » indique combien de temps attendre pour une réponse à cette requête. La valeur par défaut est le Timeout donné à la méthode spawn().

« context » inclut des données externes qui relient les réponses à leurs requêtes. Le contexte de données est fourni par le programme qui utilise POE::Component::Client::DNS. Le composant transmettra le contexte tel quel au programme. Le paramètre « context » est obligatoire et peut contenir tout ce qui rentre dans un scalaire.

shutdown
shutdown() demande au composant de se terminer proprement. Il terminera le traitement des requêtes en attente et se fermera.
get_resolver
POE::Component::Client::DNS utilise un objet Net::DNS::Resolver en interne. get_resolver() renvoie cet objet afin qu'il puisse être interrogé ou modifié. Consultez Net::DNS::Resolver pour connaître les options.

Vous pouvez définir le résolveur pour qu'il vérifie sur un port non standard 1153 :

$poco_client_dns->get_resolver()->port(1153);

MESSAGES DE RÉPONSE

POE::Component::Client::DNS répond de deux manières. Sa méthode resolve() renverra une réponse immédiatement si elle peut la trouver dans le cache du composant. Sinon, le composant renverra la réponse dans $_[ARG0]. Dans les deux cas, la réponse est une référence de hachage contenant les mêmes champs :

host     => $hote_requete,
type     => $type_requete,
class    => $classe_requete,
context  => $contexte_requete,
response => $paquet_net_dns,
error    => $erreur_net_dns,

Les champs « host », « type », « class » et « context » sont identiques à ceux donnés dans le message de requête.

« response » contient un objet Net::DNS::Packet si la requête a réussi, ou undef si elle a échoué. L'objet Net::DNS::Packet décrit la réponse à la demande du programme. Il peut contenir plusieurs enregistrements DNS. Consultez Net::DNS et Net::DNS::Packet pour plus d'informations.

« error » contient une description de toute erreur survenue. Il n'est valide que si « response » est indéfini.

VOIR AUSSI

POE - POE::Component::Client::DNS repose fortement sur POE.

POE::Component::Resolver - Un système de résolution de noms, y compris la prise en charge d'IPv6 et de ce que votre système prend en charge.

Net::DNS - Ce module utilise Net::DNS en interne.

Net::DNS::Packet - Les réponses sont renvoyées sous forme d'objets Net::DNS::Packet.

DÉPRÉCATIONS

Les interfaces basées sur des listes ne sont plus documentées depuis la version 0.98. Elles sont en cours de suppression. L'interface basée sur des méthodes, implémentée dans la version 0.98, remplacera les interfaces obsolètes après une période de suppression de 6 mois.

La version 0.98 a été publiée en octobre 2004. Les interfaces obsolètes continueront de fonctionner sans avertissement jusqu'au 1er janvier 2005.

À partir du 1er janvier 2005, les programmes utilisant les interfaces obsolètes continueront de fonctionner sans avertissement.
