NOM

POE::Component::Client::Keepalive - gérer les connexions, avec keep-alive

VERSION

version 0.272

SYNOPSIS

use warnings;
use strict;
use POE;
use POE::Component::Client::Keepalive;
POE::Session->create(
  inline_states => {
    _start    => \&start,
    got_conn  => \&got_conn,
    got_error => \&handle_error,
    got_input => \&handle_input,
  }
);
POE::Kernel->run();
exit;
sub start {
  $_[HEAP]{ka} = POE::Component::Client::Keepalive->new();
  $_[HEAP]{ka}->allocate(
    scheme  => "http",
    addr    => "127.0.0.1",
    port    => 9999,
    event   => "got_conn",
    context => "données arbitraires (même une référence) ici",
    timeout => 60,
  );
  print "La connexion est en cours.\n";
}
sub got_conn {
  my ($kernel, $heap, $response) = @_[KERNEL, HEAP, ARG0];
  my $conn    = $response->{connection};
  my $context = $response->{context};
  if (defined $conn) {
    if ($response->{from_cache}) {
      print "La connexion a été établie immédiatement.\n";
    }
    else {
      print "La connexion a été établie de manière asynchrone.\n";
    }
    $conn->start(
      InputEvent => "got_input",
      ErrorEvent => "got_error",
    );
    return;
  }
  print(
    "La connexion n'a pas pu être établie : ",
    "$response->{function} erreur $response->{error_num}: ",
    "$response->{error_str}\n"
  );
}
sub handle_input {
  my $input = $_[ARG0];
  print "$input\n";
}
sub handle_error {
  my $heap = $_[HEAP];
  delete $heap->{connection};
  $heap->{ka}->shutdown();
}

DESCRIPTION

POE::Component::Client::Keepalive crée et gère des connexions pour d'autres composants. Il maintient un cache de connexions keep-alive pour une réutilisation rapide. Il est écrit spécifiquement pour les clients qui peuvent bénéficier de connexions keep-alive, comme les clients HTTP. Son utilisation pour des connexions ponctuelles serait probablement stupide.

new
Crée un nouveau gestionnaire de connexions keep-alive. Un programme peut contenir plusieurs gestionnaires de connexions. Chacun fonctionnera indépendamment des autres. Aucun ne connaîtra les limites définies dans les autres, il est donc possible de dépasser vos descripteurs de fichiers pour un processus si vous ne faites pas attention.

new() accepte jusqu'à cinq paramètres. Tous sont optionnels.

Pour limiter le nombre de connexions simultanées à un hôte particulier (défini par une combinaison de schéma, adresse et port) :

max_per_host => $max_connexions_simultanees_par_hote, # par défaut 4

Pour limiter le nombre total de connexions qui peuvent être ouvertes à la fois, utilisez

max_open     => $nombre_maximum_de_connexions_ouvertes, # par défaut 128

Les programmes sont tenus de rendre les connexions au gestionnaire une fois qu'ils ont terminé. Voir la méthode free() pour savoir comment cela fonctionne. Le gestionnaire de connexions conservera les connexions actives pendant un certain temps avant de les recycler. Le temps maximum de keep-alive peut être défini avec

keep_alive   => $secondes_pour_garder_les_connexions_libres_actives, # par défaut 15

Les programmes peuvent ne pas vouloir attendre longtemps qu'une connexion soit établie. Ils peuvent définir le délai d'attente de la requête pour modifier le temps pendant lequel le composant conserve une requête avant de générer une erreur.

timeout      => $secondes_pour_traiter_une_requete, # par défaut 120

Spécifiez une adresse de liaison (bind_address) pour lier toutes les sockets client à une adresse locale particulière. La valeur de bind_address sera passée directement à POE::Wheel::SocketFactory. Voir la documentation de ce module pour les détails d'implémentation.

allocate
Alloue une nouvelle connexion. Allocate() retournera immédiatement un identifiant de requête. La connexion allouée, cependant, sera renvoyée à la session demanderesse. Cela se produit même si la connexion a été trouvée dans le cache keep-alive du composant. C'est un peu plus lent, mais les cas d'utilisation sont plus clairs ainsi.

Allocate() nécessite cinq paramètres et a un sixième optionnel.

Spécifiez le schéma qui sera utilisé pour communiquer sur la connexion (typiquement http ou https). Le schéma est requis, mais vous êtes libre d'inventer quelque chose ici. Il est utilisé en interne pour différencier les différents types de sockets (par exemple, ssl vs. texte clair) sur la même adresse et le même port.

scheme  => $schéma_de_connexion,

Demande une connexion à une adresse et un port particuliers. L'adresse et le port doivent être numériques. L'adresse et le port sont requis.

address => $adresse_distante,
port    => $port_distant,

Spécifiez le nom de l'événement à envoyer lorsqu'une réponse asynchrone est prête. Ceci est bien sûr requis.

event   => $événement_de_retour,

Définissez le délai d'attente de la connexion, en secondes. Le gestionnaire de connexions renverra un message d'erreur s'il ne parvient pas à établir une connexion dans le temps imparti. Ce paramètre est optionnel. Il utilisera par défaut le délai d'attente maître fourni au constructeur du gestionnaire de connexions.

timeout => $délai_d_attente_de_connexion,

Spécifiez des données contextuelles supplémentaires. Le contexte définit le but de la connexion. Il est utilisé pour maintenir la continuité entre un appel à allocate() et une réponse asynchrone. Un contexte est extrêmement utile, mais il est optionnel.

context => $données_de_contexte,

En résumé :

$mgr->allocate(
  scheme   => "http",
  address  => "127.0.0.1",
  port     => 80,
  event    => "got_a_connection",
  context  => \%connection_context,
);

L'événement de réponse ("got_a_connection" dans cet exemple) contient plusieurs champs, passés sous forme de liste de paires clé/valeur. La liste peut être affectée à une table de hachage pour plus de commodité :

sub got_a_connection {
  my %response = @_[ARG0..$#_];
  ...;
}

Quatre des champs servent à renvoyer vos données :

$response{address}    = $adresse_requete_initiale;
$response{context}    = $contexte_requete_initial;
$response{port}       = $port_requete_initial;
$response{scheme}     = $schéma_requete_initial;

Un champ renvoie l'objet de connexion si la connexion a réussi, ou undef s'il y a eu un échec :

$response{connection} = $nouveau_handle_de_socket;

En cas de succès, un autre champ vous indique si la connexion contient entièrement de nouveaux éléments. C'est-à-dire si la connexion a été recyclée depuis le cache du composant ou créée à partir de zéro.

$response{from_cache} = $statut;

Le statut from_cache peut être "immediate" si la connexion était immédiatement disponible depuis le cache. Il sera "deferred" si la connexion a été réutilisée, mais qu'un autre utilisateur a dû la libérer d'abord. Enfin, from_cache sera faux si la connexion a dû être créée pour satisfaire allocate().

Trois autres champs renvoient des informations d'erreur si la connexion a échoué. Ils ne sont pas présents si la connexion a réussi.

$response{function}   = $nom_de_la_fonction_en_echec;
$response{error_num}  = $! sous forme de nombre;
$response{error_str}  = $! sous forme de chaîne;
free
Free() notifie le gestionnaire de connexions lorsque les connexions peuvent être réutilisées. Les connexions libérées sont entrées dans le pool keep-alive et peuvent être retournées par des appels ultérieurs à allocate(). 
$mgr->free($socket);

Pour l'instant, free() est appelée avec un socket, pas avec un objet de connexion. Ce n'est généralement pas un problème, car les objets POE::Component::Connection::Keepalive appellent free() pour vous lorsqu'ils sont détruits.

Ne pas appeler free() entraînera une fuite de connexions dans le programme. Ce n'est pas non plus un problème général, car free() est appelée automatiquement chaque fois que les objets de connexion sont détruits.

deallocate
Annule une connexion qui n'a pas encore été établie. Nécessite un paramètre, l'identifiant de requête retourné par allocate().
shutdown

DESCRIPTION

La classe POE::Component::Client::Keepalive est une implémentation d'un gestionnaire de connexion pour le système POE, qui fournit un pool de connexions pour maintenir les connexions actives et éviter la perte de données.
