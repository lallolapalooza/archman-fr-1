Pod::Text(3perl) Guide de référence des programmeurs Perl Pod::Text(3perl)

NOM

Pod::Text - Convertir des données POD en texte formaté

SYNTAXE

use Pod::Text;
my $parser = Pod::Text->new (sentence => 1, width => 78);
# Lire la POD de STDIN et écrire sur STDOUT.
$parser->parse_from_filehandle;
# Lire la POD du fichier file.pod et écrire sur file.txt.
$parser->parse_from_file ('file.pod', 'file.txt');

DESCRIPTION

Pod::Text est un module qui peut convertir la documentation au format POD (le langage préféré pour documenter Perl) en texte formaté. Il n'utilise aucun contrôle ou code de formatage spécial, et sa sortie est donc adaptée à presque tous les appareils.

Encodage

Pod::Text utilise la logique suivante pour choisir un encodage de sortie, par ordre de priorité :

1.
Si une couche d'encodage PerlIO est définie sur le descripteur de fichier de sortie, aucun encodage de sortie n'est effectué et on s'en remet à la couche d'encodage PerlIO.
2.
Si les options "encoding" ou "utf8" sont définies, utilisez l'encodage de sortie spécifié par ces options.
3.
Si l'encodage d'entrée du fichier source POD a été explicitement spécifié (en utilisant "=encoding") ou automatiquement détecté par Pod::Simple, utilisez-le également comme encodage de sortie.
4.
Sinon, si l'on s'exécute sur un système non-EBCDIC, utilisez UTF-8 comme encodage de sortie. Comme il s'agit d'un sur-ensemble de l'ASCII, cela résultera en une sortie ASCII sauf si l'entrée POD contient des caractères non-ASCII sans déclarer ou détecter automatiquement un encodage (généralement via des échappements E<>).
5.
Sinon, pour les systèmes EBCDIC, sortez sans effectuer d'encodage et espérez que cela fonctionne.

Une mise en garde : Pod::Text doit s'engager sur un encodage de sortie dès qu'il émet un caractère non-ASCII, puis s'y tenir pour assurer la cohérence. Cependant, les commandes "=encoding" ne doivent pas nécessairement être au début d'un document POD. Si quelqu'un utilise un caractère non-ASCII tôt dans un document avec un échappement, tel que E<0xEF>, puis place "=encoding iso-8859-1" plus tard, idéalement Pod::Text suivrait la règle 3 et sortirait tout le document en ISO 8859-1. Au lieu de cela, il s'engagera sur UTF-8 en suivant la règle 4 dès qu'il verra cet échappement, et s'en tiendra à cet encodage pour le reste du document.

Malheureusement, il n'y a pas de choix universellement bon pour un encodage de sortie. Chaque choix sera incorrect dans certaines circonstances. Cette approche a été choisie principalement pour des raisons de compatibilité ascendante. Les appelants devraient envisager de forcer l'encodage de sortie via "encoding" s'ils ont des informations sur l'encodage que l'utilisateur pourrait attendre.

En particulier, envisagez d'importer le module Encode::Locale, s'il est disponible, et de définir "encoding" sur "locale" pour utiliser un encodage de sortie approprié à la locale de l'utilisateur. Mais sachez que si l'utilisateur n'utilise pas de locales ou utilise une locale "C", Encode::Locale définira l'encodage de sortie sur US-ASCII. Cela fera que tous les caractères non-ASCII seront remplacés par "?" et produira une série d'avertissements sur les caractères non supportés, ce qui peut ou peut ne pas être ce que vous voulez.

MÉTHODES DE CLASSE

new(ARGS)
Crée un nouvel objet Pod::Text. ARGS doit être une liste de paires clé/valeur, où les clés sont choisies parmi les suivantes. Chaque option est annotée avec la version de Pod::Text dans laquelle cette option a été ajoutée avec sa signification actuelle.
alt
[2.00] Si défini à une valeur vraie, sélectionne un format de sortie alternatif qui, entre autres choses, utilise un style d'en-tête différent et marque les entrées "=item" avec un deux-points en marge gauche. Par défaut à faux.
code
[2.13] Si défini à une valeur vraie, les parties non-POD du fichier d'entrée seront incluses dans la sortie. Utile pour visualiser le code documenté avec des blocs POD avec la POD rendue et le code laissé intact.
encoding
[5.00] Spécifie l'encodage de la sortie. La valeur doit être un encodage reconnu par le module Encode (voir Encode::Supported). Si la sortie contient des caractères qui ne peuvent pas être représentés dans cet encodage, c'est une erreur qui sera signalée comme configurée par l'option "errors". Si la gestion des erreurs est autre que "die", le caractère non représentable sera remplacé par le caractère de substitution d'Encode (normalement "?").

Si le descripteur de fichier de sortie a une couche d'encodage PerlIO définie, ce paramètre sera ignoré et aucun encodage ne sera effectué par Pod::Man. Il s'appuiera plutôt sur la couche d'encodage pour effectuer les transformations d'encodage de sortie souhaitées.

ATTENTION : L'encodage d'entrée de la source POD est indépendant de l'encodage de sortie, et la définition de cette option n'affecte pas l'interprétation de l'entrée POD. Sauf si votre source POD est en US-ASCII, son encodage doit être déclaré avec la commande "=encoding" dans la source, aussi près que possible du début du fichier. Si cela n'est pas fait, Pod::Simple tentera de deviner l'encodage et peut réussir s'il s'agit de Latin-1 ou UTF-8, mais il produira des avertissements. Voir perlpod(1) pour plus d'informations.

errors
[3.17] Comment signaler les erreurs. "die" signifie lancer une exception en cas d'erreur de formatage POD. "stderr" signifie signaler les erreurs sur l'erreur standard, mais ne pas lancer d'exception. "pod" signifie inclure une section POD ERRORS dans la documentation résultante résumant les erreurs. "none" ignore complètement les erreurs POD, dans la mesure du possible.

La valeur par défaut est "pod".

guesswork
[5.01] Par défaut, Pod::Text applique quelques règles de formatage par défaut basées sur des conjectures et des expressions régulières destinées à faciliter la documentation Perl et à nécessiter moins de balises explicites. Ces règles ne sont pas toujours appropriées, en particulier pour la documentation qui ne concerne pas Perl. Cette option permet de les désactiver en totalité ou en partie.

La valeur spéciale "all" active toutes les conjectures. C'est aussi la valeur par défaut pour des raisons de compatibilité ascendante. La valeur spéciale "none" désactive toutes les conjectures. Sinon, la valeur de cette option doit être une liste de mots-clés séparés par des virgules, l'un ou plusieurs des mots-clés suivants :

quoting
Si aucune conjecture n'est activée, tout texte entouré de C<> est entouré de guillemets dans la sortie nroff (terminal) sauf si le contenu est déjà cité. Lorsque cette conjecture est activée, les guillemets seront également supprimés pour les variables Perl, les noms de fonctions, les appels de fonctions, les nombres et les constantes hexadécimales.

Toute conjecture inconnue est ignorée silencieusement (pour une potentielle compatibilité future), alors faites attention à l'orthographe.

indent
[2.00] Le nombre d'espaces pour indenter le texte normal, et l'indentation par défaut pour les blocs "=over". Par défaut à 4.
loose
[2.00] Si défini à une valeur vraie, une ligne vide est imprimée après un en-tête "=head1". Si défini à faux (par défaut), aucune ligne vide n'est imprimée après un "=head1", bien qu'une soit toujours imprimée après un "=head2". Ceci est le défaut car c'est le formatage attendu pour les pages manuelles ; si vous formatez des documents texte arbitraires, définir ceci à vrai peut produire une sortie plus agréable.
marge
[2.21] La largeur de la marge gauche en espaces. La valeur par défaut est 0. Il s'agit de la marge pour l'intégralité du texte, y compris les en-têtes, et non du pourcentage auquel le texte normal dévie; pour ce dernier, voir l'option indent. Pour définir la marge droite, voir l'option width.
nourls
[3.17] Normalement, les codes de format L<> avec une URL mais un texte de lien sont formatés pour afficher à la fois le texte du lien et l'URL. Autrement dit: 
L<foo|http://example.com/>
est formaté comme: 
foo <http://example.com/>
Cette option, si elle est définie sur une valeur vraie, supprime l'URL lorsqu'un texte de lien est fourni, de sorte que cet exemple serait formaté uniquement comme "foo". Cela peut produire une sortie plus propre dans les cas où les URL ne sont pas particulièrement importantes.
guillemets
[4.00] Définit les signes de ponctuation entourant le texte C<>. Si la valeur est un seul caractère, il est utilisé à la fois comme signe d'ouverture et de fermeture. Sinon, la chaîne est divisée en deux et la première moitié est utilisée comme signe d'ouverture, tandis que la seconde moitié est utilisée comme signe de fermeture.

Il peut également être défini sur la valeur spéciale "none", auquel cas aucun signe de ponctuation n'est ajouté au texte C<>.

phrase
[3.00] Si cette option est définie sur une valeur vraie, Pod::Text suppose que chaque phrase se termine par deux espaces et essaie de préserver cet espacement. Si elle est définie sur fausse, les espaces consécutifs dans les paragraphes non verbatim sont compressés en un seul espace. La valeur par défaut est fausse.
stderr
[3.10] Envoie les messages d'erreur concernant les erreurs POD à stderr au lieu de les ajouter à une section POD ERRORS dans la sortie générée. Ceci est équivalent à définir "errors" sur "stderr" si "errors" n'est pas déjà défini. C'est un retour en arrière compatible.
utf8
[3.12] Si cette option est définie sur une valeur vraie, le jeu de caractères de sortie est défini sur UTF-8. Ceci est équivalent à définir "encoding" sur "UTF-8" si "encoding" n'est pas déjà défini. C'est un retour en arrière compatible.
largeur
[2.00] Le numéro de colonne auquel le texte est coupé sur la droite. La valeur par défaut est 76.

MÉTHODES D'INSTANCE

En tant que classe dérivée de Pod::Simple, Pod::Text prend en charge les mêmes méthodes et interfaces. Voir Pod::Simple pour les détails. Cette section résumera les méthodes les plus couramment utilisées et celles ajoutées par Pod::Text.

output_fh(FH)
Dirige la sortie de parse_file(), parse_lines() ou parse_string_document() vers le handle de fichier FH au lieu de "STDOUT".
output_string(REF)
Dirige la sortie de parse_file(), parse_lines() ou parse_string_document() vers la variable scalaire pointée par REF au lieu de "STDOUT". Par exemple: 
my $man = Pod::Man->new();
my $output;
$man->output_string(\$output);
$man->parse_file('/some/input/file');

La sortie dans cette variable est déjà encodée (voir "Encodage").

parse_file(PATH)
Lit le code POD à partir de PATH et le formate. Par défaut, la sortie est envoyée à "STDOUT", mais cela peut être modifié avec les méthodes output_fh() ou output_string().
parse_from_file(INPUT, OUTPUT)
parse_from_filehandle(FH, OUTPUT)
Lit le code POD à partir de INPUT, le formate et envoie la sortie à OUTPUT.

parse_from_filehandle() est rétrocompatible pour les anciennes versions de Pod::Man. Utilisez plutôt parse_from_file().

parse_lines(LINES[, ...[, undef]])
Parse les lignes fournies comme code POD et les écrit sur STDOUT ou sur le handle de fichier assigné avec les méthodes output_fh() ou output_string(). Cette méthode peut être appelée plusieurs fois pour fournir plus de lignes d'entrée. Une "undef" explicite doit être passée pour indiquer la fin de l'entrée.

Attend des octets bruts, pas des caractères décodés.

parse_string_document(INPUT)
Parse la variable scalaire fournie comme code POD et l'écrit sur STDOUT ou sur le handle de fichier assigné avec les méthodes output_fh() ou output_string().

Attend des octets bruts, pas des caractères décodés.

FONCTIONS

Pod::Text expose une fonction pour la compatibilité avec les versions antérieures. Cette fonction est dépréciée; utilisez l'interface orientée objet décrite ci-dessus.

pod2text([[-a,] [-NNN,]] INPUT[, OUTPUT])
Convertit le code POD en texte et l'écrit sur OUTPUT. Si OUTPUT n'est pas fourni, la valeur par défaut est "STDOUT". INPUT peut être n'importe quelle expression qui serait utilisée comme deuxième argument à la fonction open() à deux arguments.

Si -a est fourni comme premier argument, il transmet l'option "alt" au constructeur Pod::Text. Cela active le formatage alternatif.

Si -NNN est fourni comme premier argument, il transmet l'option "width" au constructeur Pod::Text avec la valeur "NNN" comme argument. Cela définit la largeur de ligne de coupure à NNN.

DIAGNOSTICS

Espace inhabituel dans l'élément
Élément appelé sans étiquette
(W) Quelque chose s'est mal passé dans le traitement interne de "=item". Ces messages indiquent un bug dans Pod::Text; ils ne devraient jamais apparaître.
Impossible d'ouvrir %s pour lecture: %s
(F) Pod::Text a été appelé via l'interface de compatibilité pod2text() et le fichier d'entrée qu'il a reçu n'a pas pu être ouvert.
Erreur invalide lors de la définition de "%s"
(F) Le paramètre "errors" du constructeur Pod::Text a été défini sur une valeur inconnue.
Schéma de guillemets invalide "%s"
(F) Le schéma de guillemets fourni (l'option "quotes" au constructeur) était invalide. Un schéma de guillemets doit être composé d'un seul caractère ou d'un nombre pair (plus d'un caractère) de caractères.
Document POD avec des erreurs de syntaxe
(F) Le document POD en cours de formatage contient des erreurs de syntaxe et le paramètre "errors" a été défini sur "die".

COMPATIBILITÉ

Pod::Text 2.03 (basé sur Pod::Parser) a été la première version de ce module incluse avec Perl, dans Perl 5.6.0. Les anciennes versions de Perl avaient un module Pod::Text différent avec une API différente.

L'API basée sur Pod::Simple a été ajoutée dans Pod::Text 3.00. Pod::Text 3.01 a été inclus dans Perl 5.9.3, la première version de Perl à intégrer ces modifications. C'était la première version qui prenait correctement en charge toute la syntaxe POD moderne. La méthode parse_from_filehandle() a été réintroduite pour la rétrocompatibilité dans Pod::Text 3.07, inclus dans Perl 5.9.4.

Pod::Text 3.12, inclus dans Perl 5.10.1, a été le premier à tenter d'aligner le jeu de caractères de sortie sur le jeu de caractères d'entrée des fichiers POD, sauf indication contraire via l'option "utf8" ou (ajoutée plus tard) l'option "encoding").

La prise en charge du texte de lien de type URL dans L<> a été ajoutée dans Pod::Text 3.14, inclus dans Perl 5.11.5.

parse_lines(), parse_string_document() et parse_file() définissent un handle de sortie par défaut de "STDOUT" s'il n'avait pas été précédemment défini dans Pod::Text 3.18, inclus dans Perl 5.19.5.

Pod::Text 4.00, inclus dans Perl 5.23.7, a aligné la version du module et la version de la distribution podlators. Tous les modules inclus dans podlators et la distribution podlators elle-même partagent le même numéro de version à partir de ce moment.

Pod::Text 4.09, inclus dans Perl 5.25.7, a corrigé un bug sérieux sur les systèmes EBCDIC, présent dans toutes les versions depuis 3.00, qui causait la disparition des crochets ouvrants lors de leur ouverture.

Pod::Text 5.00 et les versions ultérieures, incluses dans Perl 5.37.7, utilisent par défaut le jeu de caractères UTF-8 si un caractère non ASCII est détecté dans l'entrée et que le jeu de caractères d'entrée n'est pas spécifié. Ils s'engagent également à utiliser un jeu de caractères avec le premier caractère non ASCII et ne changent pas le jeu de caractères de sortie si le jeu de caractères d'entrée change. Le module Encode est maintenant utilisé pour tous les jeux de caractères de sortie au lieu des couches PerlIO, ce qui résout d'anciens problèmes avec la sortie vers des scalaires.

AVERTISSEMENTS

La coupure de ligne s'effectue uniquement sur les espaces et les tabulations ASCII, et non selon un algorithme de coupure de ligne approprié pour Unicode.
