NOM

POE::Test::Sequence - Aide de test POE pour vérifier une séquence d'événements

SYNTAXE

Désolé, il n'y a pas de synopsis pour le moment.
Cependant, consultez t/90_regression/whjackson-followtail.t dans la suite
de tests de POE pour un exemple complet.

DESCRIPTION

POE::Test::Sequence est une aide de test qui abstrait une grande partie des astuces fastidieuses nécessaires pour vérifier l'ordre relatif des événements.

Avec ce module, on peut tester la séquence des événements sans nécessairement dépendre de délais spécifiques entre eux.

create_generic_session

La méthode create_generic_session() crée une POE::Session qui route tous les événements à travers l'objet POE::Test::Sequence. Elle renvoie l'objet POE::Session, mais le programme de test n'a pas besoin de le stocker quelque part. En fait, il est recommandé de ne pas le faire sans en comprendre les implications.

Les implications peuvent être trouvées dans la documentation de POE::Kernel et POE::Session.

Un exemple de create_generic_session() peut être trouvé dans le programme de test POE t/90_regression/leolo-alarm-adjust.t.

new

Crée un nouvel objet séquence. Prend des paires de paramètres nommés, actuellement juste "sequence", qui référence un tableau d'étapes. Chaque étape est une référence de tableau contenant l'événement attendu, un paramètre requis pour cet événement, et une référence de code pour l'étape suivante optionnelle à suivre après avoir vérifié cet événement.

my $sequence = POE::Test::Sequence->new(
  sequence => [
  [ got_idle_event => 0, sub { append_to_log("text") } ],
  ...,
]
);

next() utilise les deux premiers éléments de l'étape pour vérifier que les étapes se déroulent dans l'ordre. Le troisième élément est renvoyé par next() et peut être utilisé comme cible de goto(). Voir la méthode next() pour plus de détails.

next

La méthode next() requiert un nom d'événement et un paramètre scalaire. Ceux-ci sont comparés aux deux premiers éléments de la prochaine étape de la séquence pour s'assurer que les événements se produisent dans l'ordre dans lequel ils devraient se produire.

sub handle_start_event {
  goto $sequence->next("got_start_event", 0);
}

test_count

test_count() renvoie le nombre d'étapes de test dans l'objet séquence. Il est destiné à être utilisé pour la planification des tests.

use Test::More;
my $sequence = POE::Test::Sequence->new( ... );
plan tests => $sequence->test_count();

BUGS

create_generic_session() est codé en dur pour passer uniquement le nom de l'événement et la valeur numérique 0 à next(). Ceci convient seulement pour les séquences les plus génériques.
