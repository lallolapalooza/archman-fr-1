POE::Queue(3) Documentation des paquets contribués pour Perl POE::Queue(3)

NOM

POE::Queue - une API générique et flexible pour les files d'attente prioritaires

SYNOPSIS

POE::Queue spécifie des méthodes supplémentaires non illustrées ici.

#!perl
use warnings;
use strict;
use POE::Queue::Array;
my $pqa = POE::Queue::Array->new();
# Mettre en file d'attente plusieurs éléments.
foreach my $priority (505, 404, 303, 202, 101) {
  $pqa->enqueue($priority, "payload $priority");
}
# Retirer jusqu'à ce que la file soit vide.
while (1) {
  my ($priority, $queue_id, $payload) = $pqa->dequeue_next();
  last unless defined $priority;
  print(
    "déqueue id($queue_id) ",
    "priorité($priority) ",
    "payload($payload)\n",
  );
}

Sortie d'exemple :

déqueue id(5) priorité(101) payload(payload 101)
déqueue id(4) priorité(202) payload(payload 202)
déqueue id(3) priorité(303) payload(payload 303)
déqueue id(2) priorité(404) payload(payload 404)
déqueue id(1) priorité(505) payload(payload 505)

DESCRIPTION

Les files d'attente prioritaires peuvent être implémentées de nombreuses manières, mais elles se comportent généralement de manière similaire à des listes qui maintiennent l'ordre via une sorte de « priorité ». Les éléments de la file d'attente sont stockés de telle sorte que le prochain élément à récupérer est celui ayant la priorité la plus élevée. Les récupérations suivantes renvoient le niveau de priorité suivant, et ainsi de suite jusqu'à ce que la file soit vide.

Les files d'attente prioritaires (également connues sous le nom de files d'attente de priorité) tentent de faire cela tout en consommant le moins de ressources possible. Lisez-en davantage ! C'est intéressant !

Éléments POE::Queue

Les éléments de POE::Queue se composent de trois champs : une priorité, un identifiant unique attribué au moment de la mise en file d'attente et une charge utile (payload). La priorité et la charge utile sont spécifiées par l'appelant, tandis que l'identifiant unique est généré par POE::Queue lors de la mise en file d'attente d'un élément.

POE::Queue impose deux contraintes aux priorités : les priorités doivent être numériques, et les nombres plus petits indiquent des priorités plus élevées. En dehors de cela, POE::Queue ne se soucie pas de la signification des nombres.

Les identifiants uniques sont des références à la file d'attente. POE::Queue les génère et les renvoie au fur et à mesure que de nouveaux éléments sont mis en file d'attente. Certaines méthodes manipulent des éléments et utilisent des identifiants pour identifier les éléments à modifier.

Les charges utiles des éléments sont des données d'application arbitraires. POE::Queue n'examine ni ne modifie les charges utiles par elle-même. Toute méthode nécessitant l'examen des charges utiles acceptera une fonction de filtre. Les fonctions de filtre examinent les charges utiles afin que POE::Queue ne le fasse pas.

Méthodes publiques

POE::Queue est une spécification d'API. Des classes comme POE::Queue::Array fournissent des implémentations réelles.

new

Crée une nouvelle file d'attente prioritaire. Renvoie une référence à la file d'attente.

my $queue = POE::Queue::Array->new();

enqueue PRIORITY, PAYLOAD

Met en file d'attente une PAYLOAD, qui peut être presque n'importe quoi tenant dans un scalaire Perl, à un niveau de priorité spécifique. enqueue() renvoie un identifiant unique qui peut être utilisé pour manipuler directement la charge utile ou sa priorité.

Dans la tradition UNIX, les nombres de priorité plus petits indiquent des priorités plus élevées. La charge utile avec le nombre de priorité le plus bas sera retirée en premier. Si deux charges utiles ont la même priorité, elles seront retirées dans l'ordre où elles ont été mises en file d'attente.

Dans cet exemple, une file d'attente est utilisée pour gérer un certain nombre d'alarmes. La « prochaine » alarme sera celle qui sonnera le plus tôt.

my $payload_id = $queue->enqueue($alarm_time, [ "stuff" ]);

dequeue_next

Retire le prochain élément de la file d'attente, le renvoyant sous forme de trois champs : priorité, identifiant et charge utile.

Le « prochain » élément est celui avec la priorité la plus basse. Si plusieurs éléments existent avec la même priorité, dequeue_next() renvoie le premier à avoir reçu cette priorité.

ITEM: while (1) {
  my ($priority, $id, $payload) = $queue->dequeue_next();
  last ITEM unless defined $priority;
  ...;
}

get_next_priority

Renvoie la priorité de l'élément en tête de la file d'attente. C'est le niveau de priorité le plus bas dans la file d'attente.

get_next_priority() peut être utile pour savoir s'il est temps de retirer certains éléments. Dans ce cas, la file d'attente gère plusieurs alarmes et il n'y a rien à faire si la prochaine alarme n'est pas encore à l'heure.

ALARM: while ($queue->get_item_count()) {
  my $next_alarm_time = $queue->get_next_priority();
  last ALARM unless defined $next_alarm_time;
  if ($next_alarm_time - time() > 0) {
    sleep($next_alarm_time - time());
  }
  my ($priority, $id, $payload) = $queue->dequeue_next();
  ...;
}

get_item_count

Renvoie le nombre d'éléments dans la file d'attente. C'est une autre façon de savoir si la file d'attente a été complètement vidée. Voici une version alternative de l'exemple pour get_next_priority().

ALARM: while ($queue->get_item_count()) {
  my $next_alarm_time = $queue->get_next_priority();
  if ($next_alarm_time - time() > 0) {
    sleep($next_alarm_time - time());
  }
  my ($priority, $id, $payload) = $queue->dequeue_next();
  ...;
}

remove_item ITEM_ID, FILTER_FUNCTION

Retire un élément par son identifiant, mais seulement si la charge utile de l'élément passe le test de la fonction de filtre.

Si une charge utile correspondant à l'identifiant donné est trouvée, elle est passée à la FILTER_FUNCTION pour examen. Si la FILTER_FUNCTION renvoie vrai, l'élément est retiré de la file d'attente et renvoyé sous forme de trois champs.

my ($priority, $id, $payload) = $queue->remove_item(
  $target_id, \&monkeys
);
sub monkeys {
  my $payload = shift;
  $payload->{type} eq "monkey";
}

La valeur de retour $priority sera indéfinie en cas d'échec, et $! sera définie à la raison pour laquelle l'élément n'a pas pu être retiré. Ce sera ESRCH si l'identifiant n'a pas été trouvé dans la file d'attente, ou EPERM si la fonction de filtre a renvoyé faux.

remove_items FILTER_FUNCTION [, MAX_ITEM_COUNT ]

Retire et renvoie les éléments de la file d'attente qui correspondent à une fonction de filtre. remove_items() renverra immédiatement si MAX_ITEM_COUNT est spécifié et que autant d'éléments que la valeur indiquée ont été retirés. MAX_ITEM_COUNT est une petite optimisation si le programme sait à l'avance combien d'éléments correspondront à la fonction de filtre.

Renvoie une liste d'éléments retirés. Chaque élément est une référence à un tableau contenant la priorité, l'identifiant et la charge utile. Renvoie rien si la fonction de filtre ne correspond à aucun élément.

# Supprime jusqu'à 12 singes.
my @monkeys = $queue->remove_items(\&monkeys, 12);
foreach my $monkey (@monkeys) {
  my ($priority, $id, $payload) = @$monkey;
  print(
    "Singe supprimé :\n",
    "  priorité = $priority\n",
    "  id file = $id\n",
    "  payload  = $payload\n",
  );
}

Il n'y a aucune garantie quant aux éléments qui seront supprimés si MAX_ITEM_COUNT est trop bas.

peek_items FILTER_FUNCTION [, MAX_ITEM_COUNT ]

peek_items() renvoie jusqu'à MAX_ITEM_COUNT éléments qui correspondent à une fonction de filtre sans les retirer de la file d'attente.

my @entire_queue = $queue->peek_items(sub { 1 });
foreach my $item (@entire_queue) {
  my ($priority, $id, $payload) = @$item;
  print(
    "Élément :\n",
    "  priorité = $priority\n",
    "  id file = $id\n",
    "  payload  = $payload\n",
  );
}

POE::Queue(3pm) - Perl manual page

NAME

POE::Queue - Queue implementations for POE sessions.

SYNOPSIS

  use POE::Queue;

  # Default queue (Array-based)
  my $queue = POE::Queue->new();

  # Create a specific queue type
  my $queue = POE::Queue::FIFO->new();

  # Add an item to the queue
  $queue->insert( $item );

  # Get an item from the queue
  my $item = $queue->get();

  # Adjust or set priority
  my $new_priority = $queue->adjust_priority( $item_id, \&filter_sub, $delta );
  my $new_priority = $queue->set_priority( $item_id, \&filter_sub, $absolute_priority );

DESCRIPTION

POE provides a set of queue implementations for managing items within POE sessions. These queues are typically used to buffer events, requests, or data between different parts of a POE application.

The default queue implementation is POE::Queue::Array, which is an array-based queue providing basic FIFO (First-In, First-Out) behavior.

POE::Queue also provides methods for manipulating the priority of items within a queue. These methods are particularly useful for implementing priority-based scheduling or for handling time-sensitive events.

Public Methods

new

Creates a new queue object. The default queue type (e.g., POE::Queue::Array) is used unless a specific queue class is specified.

  my $queue = POE::Queue->new();
  my $fifo_queue = POE::Queue::FIFO->new();

insert ITEM

Inserts an ITEM into the queue. The item is typically a reference to a POE::Event or other data structure used by the session.

  $queue->insert( $event_ref );

get

Retrieves and removes the next item from the queue, according to the queue's ordering policy (e.g., FIFO). Returns undef if the queue is empty.

  my $item = $queue->get();

peek

Returns the next item from the queue without removing it. Returns undef if the queue is empty.

  my $item = $queue->peek();

flush

Removes all items from the queue.

  $queue->flush();

count

Returns the number of items currently in the queue.

  my $num_items = $queue->count();

adjust_priority ITEM_ID, FILTER_FUNCTION, DELTA

Adjusts an item's priority by adding DELTA to its current priority. The item is identified by its ITEM_ID, and the change will only be allowed to happen if the item's payload satisfies a FILTER_FUNCTION. DELTA may be negative.

my $new_priority = $queue->adjust_priority(
  $item_id, \&one_of_mine, 100
);
sub one_of_mine {
  my $payload = shift;
  return $payload->{owner} == $me;
}

Returns undef if the item's priority could not be adjusted, and sets $! to explain why: ESRCH means that the ITEM_ID could not be found, and EPERM means that the FILTER_FUNCTION was not satisfied.

set_priority ITEM_ID, FILTER_FUNCTION, ABSOLUTE_PRIORITY

Sets an item's priority to a new ABSOLUTE_PRIORITY. The item is identified by its ITEM_ID, and the change will only be allowed to happen if the item's payload satisfies a FILTER_FUNCTION. Returns the new priority, which should match ABSOLUTE_PRIORITY.

Returns undef if the item's priority could not be set, and sets $! to explain why: ESRCH means that the ITEM_ID could not be found, and EPERM means that the FILTER_FUNCTION was not satisfied.

my $new_priority = $queue->set_priority(
  $item_id, \&one_of_mine, time() + 60
);
unless (defined $new_priority) {
  die "one of our submarines is missing: $item_id" if $! == ESRCH;
  die "set_priority disallowed for item $item_id" if $! == EPERM;
  die $!;
}
sub one_of_mine {
  $_[0]{owner} == $me;
}
