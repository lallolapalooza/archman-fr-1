NOM

POE::Component::IKC -- Communication inter-noyaux POE

SYNTAXE

IKC serveur

use POE::Component::IKC::Server;
# créez toutes vos sessions
POE::Component::IKC::Server->spawn(
            port=>30, name=>'Server'
    ); # options supplémentaires disponibles
$poe_kernel->run();

IKC client

use POE::Component::IKC::Client;
POE::Component::IKC::Client->spawn(
            host=>name,
            port=>30,
            name=>'Client',
            on_connect=>\&build);
$poe_kernel->run();
sub build
{
    # créez des sessions qui dépendent du noyau externe.
}

Poster un état sur un noyau étranger

$kernel->post('IKC', 'post', 'poe://Server/session/state', $ONE_arg);

L'IKC est pair-à-pair.

Le serveur peut poster à un client.

$kernel->post('IKC', 'post', 'poe://Client/session/state', $ONE_arg);

Appeler un état sur un noyau distant

La sémantique d'appel est impossible, car elle bloquerait POE. L'appel IKC est un peu différent. C'est un 'post', mais avec un paramètre RSVP supplémentaire.

$kernel->post('IKC', 'call', 'poe://Server/hello/world', $ONE_arg,
              'poe:callback');

Cela provoquera l'envoi de la valeur de retour de l'état du noyau externe à l'état 'callback' dans la session actuelle. Vous pourriez vouloir que le callback soit dans une autre session, mais je ne pense pas que ce soit une bonne idée.

$kernel->post('IKC', 'call', 'poe://Server/hello/world', $ONE_arg,
              'poe:/elsewhere/hi');

Remarque : si vous utilisez ->call('IKC'), il renverra le nombre de noyaux externes auxquels l'état a été posté. Ceci est utile pour savoir si vous êtes toujours connecté à un noyau externe.

Un peu de magie

Si un état est posté par un noyau externe, $_[SENDER] n'est valide que pendant cet état. Cependant, vous pourrez poster en retour.

$kernel->post($_[SENDER], 'something', 'the answer is foo');

L'appelant distant doit avoir posté des états pour pouvoir être appelé, n'est-ce pas ?

Publier / S'abonner

Vous devez publier l'interface d'une session pour qu'elle soit accessible par des noyaux externes.

Si vous vous abonnez à une session distante, vous pourrez y accéder comme s'il s'agissait d'une session locale.

Premièrement, une session publie ses interfaces :

$kernel->post('IKC', 'publish', 'session_alias',
                    [qw(state1 state2 state3 state4)], );

Ensuite, un noyau externe s'y abonne :

# Chercher une session dans tous les noyaux connus
$kernel->post('IKC', 'subscribe', [qw(poe://*/session_alias/)]);
# Chercher une session dans un noyau spécifique
$kernel->post('IKC', 'subscribe', [qw(poe://Pulse/timeserver)]);
# Assurez-vous que la session a un état donné
$kernel->post('IKC', 'subscribe', [qw(poe://*/timeserver/connect)]);

Après l'abonnement, une session proxy est créée qui peut être accédée comme n'importe quelle session normale, bien que ->call() agisse comme ->post() pour des raisons évidentes :

$kernel->post('poe:/Pulse/timeserver', 'state', $arg1, $arg2...);

Actuellement, l'alias de session utilisé lors de la publication vers la session proxy doit être le même que lors de l'abonnement. Comme les noyaux ont plusieurs noms, si vous utilisez '*' comme nom de noyau lors de l'abonnement, l'alias de session pourrait ne pas être ce que vous attendez. Voir "Moniteur" pour plus de détails.

Bien sûr, essayer de poster à une session proxy avant sa création sera problématique. Pour être notifié lorsque la session proxy est créée, un état de rappel peut être spécifié :

$kernel->post('IKC', 'subscribe', [qw(poe://*/timeserver)],
        'timeserver_subscribed');

Le rappel est appelé avec une liste de toutes les sessions auxquelles il a réussi à s'abonner. Vous devriez voir cette liste avant de continuer. Mieux encore, vous pouvez utiliser le moniteur IKC (voir ci-dessous).

Vous pouvez également laisser POE::Component::IKC::Client->spawn gérer tous les détails.

POE::Component::IKC::Client->spawn(
        port=>31337, name=>$name,
        subscribe=>[qw(poe://*/timeserver)],
        on_connect=>\&create_me,
    );

'on_connect' est appelé lorsque tous les abonnements ont été acceptés. Si un abonnement a été rejeté, create_ikc_client échouera. Si plusieurs noyaux externes ont été interrogés pour une session (comme dans l'exemple ci-dessus), l'abonnement est considéré comme réussi si au moins un noyau accepte l'abonnement.

Pour annuler les choses :

$kernel->post(IKC=>'retract', 'session_alias'=>[qw(states)]);
$kernel->post(IKC=>'unsubscribe', [qw(poe://Pulse/timeserver)]);

Moniteur

Vous dites que vous voulez surveiller tous les noyaux externes qui se connectent à vous :

$kernel->post(IKC=>'monitor', '*'=>{register=>'some_event'});
sub some_event
{
    my($name, $real)=@_[ARG1, ARG2];
    print "- Noyau ", ($real ? '' : "alias "), "$name connecté\n";
}

Ensuite, vous voulez savoir quand une session spécifique se déconnecte :

$kernel->post(IKC=>'monitor', some_kernel=>{unregister=>'bye_bye'});

Ou peut-être pensez-vous qu'une session devrait nettoyer et se terminer lorsque IKC le fait.

$kernel->post(IKC=>'monitor', '*'=>{shutdown=>'other_event'});
sub other_event
{
    # terminez les roues, les alarmes, les sélections et les alias ici
}

Voir le "moniteur" dans POE::Component::IKC::Responder pour plus de détails.

Arrêt

Lorsque vous sentez que le moment est venu et que vous voulez supprimer toutes les sessions liées à IKC, faites simplement ceci :

$kernel->post(IKC=>'shutdown');

Et tout devrait disparaître. Dans le pire des cas, certains pourraient encore avoir des alias enregistrés, mais cela n'empêchera pas le noyau de se fermer.

Le noyau local

Vous pouvez poster à votre noyau local comme s'il était distant :

$kernel->post(IKC=>'post',
                "poe://$kernel->ID/session/state'=>$ONE_arg);

Cependant, vous ne pouvez actuellement pas vous abonner à des sessions locales. Je ne sais pas comment résoudre cela.

DESCRIPTION

Il s'agit de la communication inter-noyaux POE. Elle est utilisée pour obtenir des événements d'un noyau POE à un autre.

VOIR AUSSI

POE::Component::IKC::Responder -- Cœur du système

POE::Component::IKC::Server -- Crée un processus qui écoute d'autres noyaux.

POE::Component::IKC::Client -- Crée un processus qui se connecte à d'autres noyaux.

POE::Component::IKC::ClientLite -- Implémentation légère d'IKC pour les endroits où POE ne peut pas être utilisé, comme mod_perl.

POE::Component::IKC::Channel -- Gestion de la communication avec d'autres noyaux.

POE::Component::IKC::Proxy -- Session proxy créée lorsque vous vous abonnez à une session distante.

POE::Component::IKC::Freezer -- Méthode de sérialisation pure Perl.

POE::Component::IKC::Specifier -- Routines d'aide pour l'analyse des spécificateurs IKC.
