NOM

Pod::POM::View::Restructured - Vue pour Pod::POM qui génère du reStructuredText

SYNTAXE

use Pod::POM::View::Restructured;

my $view = Pod::POM::View::Restructured->new;
my $parser = Pod::POM->new;
my $pom = $parser->parse_file("$top_dir/lib/Pod/POM/View/Restructured.pm");
my $out = $pom->present($view);

DESCRIPTION

Ce module génère du reStructuredText qui est censé être utilisé avec Sphinx. Les sections verbatim (paragraphes indentés) dans le POD seront générées avec une coloration syntaxique pour le code Perl par défaut. Voir "Commandes POD spécifiquement pour le reStructuredText" pour savoir comment changer cela pour un bloc particulier.

Ce module peut être téléchargé depuis https://metacpan.org/release/Pod-POM-View-Restructured.

MÉTHODES

new(\%paramètres)

Constructeur. \%paramètres est optionnel. S'il est présent, les clés suivantes sont valides :

"callbacks"
Voir la documentation ci-dessous pour convert_file().
"namespace"
Si un espace de noms est déclaré, alors les liens vers cet espace de noms sont convertis en références croisées et une ancre est ajoutée pour chaque balise de titre.

"convert_file($fichier_source, $titre, $fichier_destination, $callbacks)"

Convertit le POD dans $fichier_source en reStructuredText. Si $fichier_destination est défini, il écrit la sortie là-bas. Si $titre est défini, il est utilisé pour le titre du document. Sinon, une tentative est faite pour déduire le titre de la section NOM (vérifie si le corps ressemble à "/\A\s*(\w+(?:::\w+)+)\s+-\s+/s").

Retourne la sortie sous forme de chaîne de caractères.

$fichier_source et $fichier_destination peuvent être des noms de fichiers ou des descripteurs de fichiers.

"convert_files($spécification_fichier, $fichier_index, $titre_index, $répertoire_sortie)"

Convertit les fichiers donnés dans $spécification_fichier en reStructuredText. Si $fichier_index est fourni, c'est le chemin vers le fichier d'index à créer (avec une table des matières pointant vers tous les fichiers créés). Si $titre_index est fourni, il est utilisé comme titre de section pour le fichier d'index. $répertoire_sortie est le répertoire où les fichiers générés seront écrits.

$spécification_fichier est une référence à un tableau de hachages spécifiant les attributs de chaque fichier à convertir. Les clés valides sont :

"source_file"
Fichier à convertir.
"dest_file"
Fichier où générer le reStructuredText. S'il n'est pas fourni, un nom de fichier sera généré en fonction du titre.
"title"
Titre de section pour le reStructuredText généré. S'il n'est pas fourni, une tentative sera faite pour déduire le titre de la section NOM dans le POD, s'il existe. En dernier recours, un titre sera généré comme "section_(\d+)".
"callbacks"
Une référence à un hachage contenant des noms et les fonctions de rappel correspondantes.

Actuellement, la seule fonction de rappel valide est "link". Elle reçoit le texte à l'intérieur d'une section L<> du POD, et est censée retourner un tuple "($url, $label)". Si la valeur retournée pour $label est indéfinie, la valeur de $url est utilisée comme étiquette.

"no_toc"
Empêche l'élément d'être imprimé dans l'index ou retourné dans le champ "toc".

Cette méthode retourne un hachage de référence avec une table des matières (le champ "toc") adaptée pour une table des matières reStructuredText.

Exemple :

my $conv = Pod::POM::View::Restructured->new;

my $files = [
              { source_file => "$base_dir/Restructured.pm" },
              { source_file => "$base_dir/DWIW.pm" },
              { source_file => "$base_dir/Wrapper.pm" },
             ];

my $rv = $conv->convert_files($files, "$dest_dir/index.rst", 'Mon Grand Test', $dest_dir);

Commandes POD spécifiquement pour le reStructuredText

Les séquences suivantes peuvent être utilisées dans le POD pour demander des actions spécifiques à ce module.

=for pod2rst bloc-code-suivant: langue

Cela configure le prochain bloc verbatim, c'est-à-dire le prochain paragraphe indenté, pour être mis en évidence selon la syntaxe du langage de programmation/balisage/configuration langue. Les blocs verbatim sont supposés être du code Perl par défaut. Sphinx utilise Pygments pour la coloration syntaxique dans ces sections, vous pouvez donc utiliser n'importe quelle valeur pour langue que Pygments supporte, par exemple Python, C, C++, Javascript, SQL, etc.

EXEMPLES

Conversion d'un fichier unique avec "pod2rst"
pod2rst --infile=Restructured.pm --outfile=restructured.rst

À FAIRE

coloration syntaxique
Actuellement, un bloc verbatim (paragraphe indenté) est généré comme un bloc de code Perl par défaut en reStructuredText. Il devrait y avoir une option (par exemple, dans le constructeur) pour changer la langue à des fins de coloration, ou désactiver la coloration syntaxique et en faire simplement un paragraphe préformaté. Il existe un moyen de le faire en POD (voir "Commandes POD spécifiquement pour le reStructuredText"), mais il devrait également y avoir une option dans le constructeur.
améliorer l'échappement
Les blocs de texte ne sont pas correctement échappés, il est donc actuellement possible d'invoquer une commande en reStructuredText par accident.
