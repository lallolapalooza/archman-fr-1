NOM

local::lib~[de] - Créer et utiliser des modules Perl dans un répertoire lib/ local avec PERL5LIB

SYNOPSIS

Dans le code -

use local::lib; # Utilise le répertoire ~/perl5 pour créer le répertoire lib/ local
use local::lib '~/foo'; # Idem, mais avec ~/foo
# Ou...
use FindBin;
use local::lib "$FindBin::Bin/../support";  # Collection de modules spécifique à l'application

Depuis le shell -

# Installe LWP et toutes les dépendances nécessaires dans le répertoire '~/perl5'
perl -MCPAN -Mlocal::lib -e 'CPAN::install(LWP)'
# Affiche les commandes shell pour préparer l'environnement
$ perl -Mlocal::lib
export PERL_MB_OPT='--install_base /home/username/perl5'
export PERL_MM_OPT='INSTALL_BASE=/home/username/perl5'
export PERL5LIB='/home/username/perl5/lib/perl5/i386-linux:/home/username/perl5/lib/perl5'
export PATH="/home/username/perl5/bin:$PATH"

La méthode de bootstrap

Une manière typique d'utiliser local::lib est la méthode dite de "bootstrap". Cette méthode est utilisée lorsqu'aucun local::lib n'est encore installé sur le système. Dans ce cas, vous pouvez simplement installer local::lib directement dans votre répertoire personnel.

Même si vous avez des droits d'administrateur, il est important que les variables d'environnement de l'étape 4 soient définies dans votre script de démarrage de shell. Sans cette étape, les modules de CPAN continueront d'être installés dans le système et les scripts Perl que vous lancez n'utiliseront pas le répertoire lib/ créé par local::lib.

Par défaut, local::lib s'installe dans ~/perl5.

Les utilisateurs de Windows doivent également lire ceci : "Différences d'utilisation de ce module avec Win32".

1. Téléchargez l'archive tar depuis CPAN (Recherchez "Download" sur la page CPAN de local::lib) et décompressez-la dans un répertoire quelconque. Pour éviter le problème ci-dessus, vous devriez le faire en tant qu'utilisateur normal et non en tant que root ou administrateur.

2. Lancez la commande suivante dans le répertoire créé :

perl Makefile.PL --bootstrap

Si le système vous propose de configurer certaines choses automatiquement, il est dans presque tous les cas tout à fait acceptable de répondre simplement "yes".

Si vous ne souhaitez pas installer local::lib dans le répertoire par défaut, vous devez spécifier ce répertoire en paramètre :

perl Makefile.PL --bootstrap=~/foo

3. Ensuite, lancez la commande suivante : (local::lib s'attend à ce que make soit installé sur le système)

make test && make install

4. Maintenant, nous devons définir les variables d'environnement nécessaires pour que Perl utilise notre répertoire lib/ nouvellement généré. Si vous utilisez bash ou un autre shell Bourne, vous pouvez l'ajouter à votre script de démarrage de shell de cette manière :

echo 'eval $(perl -I$HOME/perl5/lib/perl5 -Mlocal::lib)' >>~/.bashrc

Si vous utilisez le C Shell, vous pouvez obtenir le même résultat avec :

/bin/csh
echo $SHELL
/bin/csh
perl -I$HOME/perl5/lib/perl5 -Mlocal::lib >> ~/.cshrc

Si vous avez utilisé un répertoire différent de celui par défaut lors du bootstrap, vous devez spécifier ce répertoire en paramètre lors du chargement du module local::lib :

echo 'eval $(perl -I$HOME/foo/lib/perl5 -Mlocal::lib=$HOME/foo)' >>~/.bashrc

Une fois ces modifications apportées à votre script de démarrage de shell, il est important que ces variables d'environnement soient également définies dans votre environnement actuel. Dans les shells Bourne, cela se fait par exemple avec ". ~/.bashrc", et dans le C Shell, cela se ferait avec : "source ~/.cshrc".

Si vous avez un système très lent, ou si vous devez vivre sous des réglementations drastiques concernant l'espace disque, vous pouvez désactiver la génération automatique des pages man à partir du POD lors de l'installation du module lors du bootstrap avec le paramètre "--no-manpages" :

perl Makefile.PL --bootstrap --no-manpages

Pour éviter de faire plusieurs bootstraps afin d'utiliser, par exemple, des installations local::lib séparées pour différentes applications, vous pouvez utiliser l'une de ces environnements pour simplement installer des modules dans d'autres répertoires quelconques et ainsi obtenir d'autres environnements lib/ indépendants :

cd ~/mydir1
perl -Mlocal::lib=./
eval $(perl -Mlocal::lib=./)  ### Pour définir les variables d'environnement pour
                              ### le shell actuel
printenv                      ### Vous pouvez voir ici que ~/mydir1
                              ### est dans la variable d'environnement
                              ### PERL5LIB
perl -MCPAN -e install ...    ### quels que soient les modules ...
cd ../mydir2
... RÉPÉTER ...

Pour plusieurs environnements sous cette forme, vous avez besoin d'une modification dans l'utilisation de "use FindBin" dans l'exemple "Dans le code" ci-dessus. Si vous faites cela, et que vous avez par exemple installé des modules Perl dans "~/mydir1/lib" et que vous avez un script dans "~/mydir1/scripts/myscript.pl", vous devez y indiquer que les modules dont il a besoin se trouvent dans le répertoire "~/mydir1/lib".

Dans "~/mydir1/scripts/myscript.pl" se trouve :

use strict;
use warnings;
use local::lib "$FindBin::Bin/..";  ### pointe vers ~/mydir1 et local::lib
                                    ### y trouve lib
use lib "$FindBin::Bin/../lib";     ### pointe vers ~/mydir1/lib

Placez ceci avant tout bloc BEGIN { ... } qui utilise les modules que vous avez installés.

Différences d'utilisation de ce module avec Win32

Pour définir les variables d'environnement nécessaires pour ces variables dans la session actuelle avec "CMD.EXE", vous pouvez utiliser la commande suivante :

C:\>perl -Mlocal::lib
set PERL_MB_OPT=--install_base C:\DOCUME~1\ADMINI~1\perl5
set PERL_MM_OPT=INSTALL_BASE=C:\DOCUME~1\ADMINI~1\perl5
set PERL5LIB=C:\DOCUME~1\ADMINI~1\perl5\lib\perl5;C:\DOCUME~1\ADMINI~1\perl5\lib\perl5\MSWin32-x86-multi-thread
set PATH=C:\DOCUME~1\ADMINI~1\perl5\bin;%PATH%
### Pour définir les variables d'environnement pour ce shell uniquement
C:\>perl -Mlocal::lib > %TEMP%\tmp.bat && %TEMP%\tmp.bat && del %TEMP%\temp.bat
### au lieu de $(perl -Mlocal::lib=./) dans bash.

Si vous souhaitez que les variables d'environnement soient définies de manière permanente, vous devrez les ajouter vous-même de manière permanente dans le Panneau de configuration / Système ou utiliser App::local::lib::Win32Helper.

Le " ~ " est traduit en répertoire de profil utilisateur (le répertoire connu sous le nom de "Documents and Settings" sous Windows XP et avant, ou le répertoire "Utilisateurs" sous Windows Vista et après), sauf si $ENV{HOME} est défini. Le répertoire est converti ici en son nom court correct, et doit donc absolument exister, et est étendu avec les sous-répertoires nécessaires.

PRINCIPE DE BASE

La version des paquets Perl dont vous avez besoin pour des tâches spécifiques n'est très souvent pas la bonne ou pas correctement installée sur le système. Une mise à jour de ces modules est dans de nombreux cas simplement impossible car les droits nécessaires manquent. De plus, il n'est généralement pas bon de modifier soi-même les versions des modules sur le système, car bien sûr le reste du système attend la version installée par la gestion du système.

local::lib résout ce problème, il vous permet d'avoir votre propre répertoire complet pour vos modules CPAN et ainsi vous n'êtes pas obligé d'utiliser les modules du système ou, inversement, de forcer d'autres utilisateurs à réviser leur code avec des souhaits de modules individuels, parce que certains modules sont mis à jour centralement pour tous à des versions plus récentes. L'installation se fait alors par exemple dans le répertoire personnel. Seules les variables d'environnement sont définies pour inciter le Perl installé à utiliser les modules installés dans le répertoire personnel, en plus et en priorité.

Mantén toda la estructura del archivo.

DESCRIPTION

Ce module offre une méthode rapide et valide pour effectuer une amorce semblable à ce que l'on appelle "bootstrapping" pour installer un ensemble de modules dans le répertoire personnel de l'utilisateur. Il crée également les variables d'environnement nécessaires pour utiliser ces modules, de manière appropriée pour le shell que l'utilisateur a indiqué dans la variable "SHELL", afin de les intégrer directement dans les configurations correspondantes du shell.

De plus, local::lib peut utiliser des modules qui ne se trouvent pas dans le chemin standard @INC de Perl. Cela permet à certaines applications d'installer plus facilement un ensemble spécifique de modules sans avoir à en installer d'autres sur le système d'une manière ou d'une autre. Ainsi, il est plus sûr d'installer des modules que le mainteneur n'a pas encore publiés en tant que release.

Lors de l'importation, local::lib définit les variables d'environnement suivantes aux valeurs nécessaires :

PERL_MB_OPT
PERL_MM_OPT
PERL5LIB
PATH
Est ajouté naturellement au PATH, et ne le remplace pas.

Ces valeurs sont alors accessibles à tout code qui sera importé par la suite.

CRÉER UN ENSEMBLE AUTONOME DE MODULES

Avec lib::core::only, il existe une opportunité de traiter cela, mais gardez à l'esprit qu'il existe de nombreuses défaillances et problèmes, et vous devez toujours garder à l'esprit que vous construisez un Perl qui a été très peu modifié (c'est-à-dire que les répertoires site et vendor sont aussi vides que possible).

MÉTHODES

ensure_dir_structure_for

Paramètres : $path
Valeur de retour : Aucune

Tente de créer le répertoire donné, avec tous les répertoires nécessaires au-dessus. En cas d'erreur, une exception sera levée.

print_environment_vars_for

Paramètres : $pfad
Valeur de retour : Aucune

Étant donné que le répertoire fourni est le répertoire de base à utiliser, il imprime les variables d'environnement nécessaires.

build_environment_vars_for

Paramètres : $pfad, $interpolate
Valeur de retour : \%umgebungs_variablen

Étant donné que le répertoire fourni est le répertoire de base à utiliser, il renvoie un hachage avec les variables nécessaires pour installer dans le répertoire fourni.

setup_env_hash_for

Paramètres : $pfad
Valeur de retour : Aucune

Définit les entrées %ENV en se basant sur l'appel à build_environment_vars_for.

install_base_perl_path

Paramètres : $pfad
Valeur de retour : $module_installations_pfad

Étant donné que le répertoire fourni est le répertoire de base à utiliser, il renvoie le répertoire qui sera utilisé pour installer les modules Perl. En principe, seuls les éléments "lib" et "perl5" sont autorisés comme répertoires.

install_base_arch_path

Paramètres : $pfad
Valeur de retour : $architektur_module_installations_pfad

Étant donné que le répertoire fourni est le répertoire de base à utiliser, il renvoie le répertoire qui sera utilisé pour installer les modules compilés basés sur le répertoire fourni. En se basant sur ce que renvoie install_base_perl_path, il ajoute la valeur de $Config{archname}.

install_base_bin_path

Paramètres : $pfad
Valeur de retour : $ausfuehrbare_programme_installations_pfad

Étant donné que le répertoire fourni est le répertoire de base à utiliser, il renvoie le répertoire qui sera utilisé pour installer les programmes exécutables. En principe, seuls les éléments "bin" sont autorisés comme répertoires.

resolve_empty_path

Paramètres : $pfad
Valeur de retour : $basis_pfad

Crée et renvoie le répertoire qui sera utilisé comme base pour installer les modules. Par défaut, il s'agit de "~/perl5".

resolve_home_path( $path )

Paramètres : $pfad
Valeur de retour : $home

Tente de trouver le répertoire personnel de l'utilisateur actuel. Une exception sera levée si le répertoire personnel ne peut pas être trouvé.

resolve_relative_path

Paramètres : $pfad
Valeur de retour : $absoluter_pfad

Convertit le répertoire donné en un répertoire absolu.

resolve_path

Paramètres : $pfad
Valeur de retour : $absoluter_pfad

Le répertoire donné est fourni en entrée aux méthodes suivantes : "resolve_empty_path", "resolve_home_path", "resolve_relative_path". Le résultat du premier est passé au second, et le résultat du second est passé au troisième. Le résultat final est passé au dernier.

UN AVERTISSEMENT CONCERNANT UNINST=1

Si local::lib est utilisé en combinaison avec "make install UNINST=1", vous devez faire attention à la situation où le processus effectue une installation non suffisamment sûre, car il ne sait pas où installer. Cela peut entraîner que lors de la désinstallation d'un module, le module global soit désinstallé (si les permissions sont valides), mais que la nouvelle version ne soit installée que dans la version locale. C'est pourquoi il est très important d'utiliser "make install UNINST=1" et local::lib uniquement lorsque vous êtes sûr des conséquences.

RESTRICTIONS

Les outils Perl utilisés pour installer des paquets (l'appel à la chaîne d'outils, semblable à ce que l'on appelle "toolchain") ne peuvent pas gérer correctement les répertoires contenant des espaces blancs et, par conséquent, local::lib ne peut pas installer directement dans un répertoire avec des espaces blancs. Ce que l'on peut faire, c'est déplacer l'ensemble du répertoire local::lib et les modules que l'on possède dans local::lib vers ce répertoire. local::lib peut gérer les répertoires avec des espaces blancs. Veuillez noter qu'il ne sera pas possible d'installer ou de mettre à jour des paquets avec le programme CPAN en raison d'une installation ou d'une mise à jour ultérieure.

local::lib(3pm) — Perl module local::lib

NAME

local::lib — gestion de bibliothèques Perl locales

SYNOPSIS

    use local::lib;
    use local::lib '~/perl5';
    use local::lib '/opt/perl5/site';
    use local::lib '/opt/perl5', '/opt/perl5/site';
    use local::lib-%>ENV;
    use local::lib-%>ENV '~/perl5';
    use local::lib-%>ENV '/opt/perl5/site';
    use local::lib-%>ENV '/opt/perl5', '/opt/perl5/site';

GRUNDPRINZIP

Si vous souhaitez installer des modules Perl et qu'ils n'apparaissent pas lorsque vous exécutez "perl -MModule::Name", vous avez probablement besoin de local::lib.

local::lib est un module qui vous permet d'installer des modules Perl dans des répertoires spécifiques au lieu de les installer dans le répertoire global du système (par exemple, "/usr/lib/perl5").

Il ajoute également les chemins de ces répertoires à vos variables déenvironnement PERL5LIB, PERL_MM_OPT et PERL_MB_OPT, de sorte que Perl puisse trouver et utiliser les modules que vous avez installés.

BESCHREIBUNG

Le module local::lib fournit une fonctionnalité pour la gestion de bibliothèques Perl locales. En particulier, il permet d'installer des modules Perl dans des emplacements spécifiques qui ne sont pas accessible en écriture pour l'utilisateur moyen.

Cela est particulièrement utile dans les environnements multi-utilisateurs où l'installation de modules dans le répertoire système global est restreinte. Avec local::lib, chaque utilisateur peut installer ses propres modules dans son répertoire personnel sans affecter les autres utilisateurs ou le système.

Le module s'intègre également bien avec les outils standard de construction de modules Perl comme Extutils::MakeMaker et Module::Build.

ERSTELLEN EINES EIGENSTÄNDIGE SAMMLUNG VON MODULEN

Si vous avez besoin d'une collection de modules Perl pour votre propre usage, vous pouvez utiliser local::lib pour les installer dans votre répertoire personnel. Cela vous permet d'avoir vos propres versions des modules sans interférer avec les versions installées par le système.

Pour ce faire, vous devez d'abord configurer local::lib dans votre environnement. Cela se fait généralement en ajoutant une ligne à votre fichier de configuration de shell (par exemple, ~/.bashrc ou ~/.zshrc) qui définit les chemins où les modules doivent êt;re installés.

Une fois la configuration effectuée, vous pouvez utiliser l'outil en ligne de commande cpan pour installer des modules. Par exemple, pour installer le module Foo::Bar, vous utiliseriez la commande suivante :

    cpan -i Foo::Bar

Si vous rencontrez des problèmes avec les permissions, vous pouvez spécifier explicitement le répertoire d'installation en utilisant l'option -l de local::lib.

METHODEN

local::lib prend en charge plusieurs méthodes pour configurer votre environnement Perl. Les méthodes les plus courantes sont :

use local::lib;
Cette méthode utilise les chemins par défaut pour l'installation des modules (généralement dans le répertoire personnel de l'utilisateur).
use local::lib '~perl5';
Cette méthode permet de spécifier un répertoire personnalisé pour l'installation des modules.
use local::lib '/opt/perl5/site';
Cette méthode permet de spécifier un répertoire système pour l'installation des modules.
use local::lib '/opt/perl5', '/opt/perl5/site';
Cette méthode permet de spécifier plusieurs répertoires pour l'installation des modules.
use local::lib->ENV;
Cette méthode configure local::lib pour qu'il utilise les variables d'environnement existantes pour déterminer les chemins d'installation.
use local::lib->ENV '~perl5';
Cette méthode configure local::lib pour qu'il utilise les variables d'environnement et un répertoire personnalisé pour l'installation des modules.

EINE WARNUNG VOR UNINST=1

Si votre environnement local::lib est configuré avec UNINST=1, cela signifie que local::lib tentera de supprimer les modules installés lorsque le script Perl se terminera. Ceci peut êt;re utile pour des tests temporaires, mais peut êt;re désastreux si vous avez des modules importants installés.

Il est fortement recommandé de ne pas utiliser UNINST=1 dans un environnement de production.

EINSCHRÄNKUNGEN

Bootstrap est malheureusement un hack et utilisera toujours CPAN.pm pour Extutils::MakeMaker, même si CPANPLUS est installé.

Il redéfinit définitivement PERL5LIB, PERL_MM_OPT et PERL_MB_OPT, et efface toute valeur précédemment définie.

Il devrait peut-être effectuer une correction automatique de la configuration de CPAN si ce n'est pas déjà fait.

"Patches Welcome" - Les patches sont toujours les bienvenus chez l'auteur ou les autres contributeurs.

Sur les systèmes Win32, les variables d'environnement ne sont pas directement écrites dans le registre afin qu'elles persistent après les redémarrages.

FEHLERANALYSE

Si vous avez configuré local::lib pour installer des modules CPAN dans votre répertoire personnel, et que vous essayez ensuite d'installer un module avec "cpan -i Foo::Bar" et que vous obtenez une erreur telle que : "Warning: You do not have permissions to install into /usr/lib64/perl5/site_perl/5.8.8/x86_64-linux at /usr/lib64/perl5/5.8.8/Foo/Bar.pm" et qu'une erreur dans la sortie d'installation indique "'INSTALL_BASE' is not a known MakeMaker parameter name", alors vous avez perdu votre nouvelle version d'Extutils::MakeMaker pour une raison quelconque.

Pour corriger cela, lancez simplement la méthode de bootstrap à nouveau, comme décrit ci-dessus.

Ensuite, lancez "rm -r ~/.cpan/build/Foo-Bar*"

Enfin, réinstallez avec "cpan -i Foo::Bar" et les problèmes devraient avoir disparu.

UMGEBUNGSVARIABLEN

SHELL
COMSPEC
local::lib examine la variable d'environnement "SHELL" pour ajouter les commandes correctes à la configuration du shell.

Sur les systèmes Win32, "COMSPEC" est également analysé.
