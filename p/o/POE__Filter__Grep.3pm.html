NOM

POE::Filter::Grep - sélectionne ou supprime des éléments basés sur des règles simples

SYNOPSIS

#!perl
use POE qw(
  Wheel::FollowTail
  Filter::Line Filter::Grep Filter::Stackable
);
POE::Session->create(
  inline_states => {
    _start => sub {
      my $parse_input_as_lines = POE::Filter::Line->new();
      my $select_sudo_log_lines = POE::Filter::Grep->new(
        Put => sub { 1 },
        Get => sub {
          my $input = shift;
          return $input =~ /sudo\[\d+\]/i;
        },
      );
      my $filter_stack = POE::Filter::Stackable->new(
        Filters => [
          $parse_input_as_lines, # premier pour get, dernier pour put
          $select_sudo_log_lines, # premier pour put, dernier pour get
        ]
      );
      $_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
        Filename => "/var/log/system.log",
        InputEvent => "got_log_line",
        Filter => $filter_stack,
      );
    },
    got_log_line => sub {
      print "Log: $_[ARG0]\n";
    }
  }
);
POE::Kernel->run();
exit;

DESCRIPTION

POE::Filter::Grep sélectionne ou supprime des éléments basés sur des tests simples. Il peut être utilisé pour filtrer l'entrée, la sortie, ou les deux. Ce filtre est nommé et modélisé d'après la fonction intégrée grep() de Perl.

POE::Filter::Grep est conçu pour être combiné avec d'autres filtres via POE::Filter::Stackable. Dans l'exemple de la "SYNOPSIS", une pile de filtres est créée pour analyser les journaux sous forme de lignes et supprimer toutes les entrées qui ne concernent pas un processus sudo. (Ou si votre verre est à moitié plein, la pile ne sélectionne que les entrées qui mentionnent sudo.)

MÉTHODES DE FILTRE PUBLIQUES

En plus des méthodes POE::Filter habituelles, POE::Filter::Grep prend également en charge les suivantes.

new

new() construit un nouvel objet POE::Filter::Grep. Il doit soit être appelé avec un seul paramètre Code, soit avec les paramètres Put et Get. Les valeurs pour Code, Put et Get sont des références de code qui, lorsqu'elles sont invoquées, retournent vrai pour sélectionner un élément ou faux pour le rejeter. Une fonction Code sera utilisée pour l'entrée et la sortie, tandis que les fonctions Get et Put permettent de filtrer l'entrée et la sortie de différentes manières. L'élément en question sera passé comme seul paramètre de la fonction.

sub reject_bidoofs {
  my $pokemon = shift;
  return 1 if $pokemon ne "bidoof";
  return;
}
my $gotta_catch_nearly_all = POE::Filter::Grep->new(
  Code => \&reject_bidoofs,
);

Forcer le comportement en lecture seule :

my $read_only = POE::Filter::Grep->new(
  Get => sub { 1 },
  Put => sub { 0 },
);

modify

modify() modifie le comportement d'un objet POE::Filter::Grep à l'exécution. Il accepte les mêmes paramètres que new() et remplace les tests existants par de nouveaux.

# Ne pas donner nos Dialgas.
$gotta_catch_nearly_all->modify(
  Get => sub { 1 },
  Put => sub { return shift() ne "dialga" },
);
