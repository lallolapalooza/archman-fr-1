POE::Filter::Line(3) Documentation Perl fournie par l'utilisateur POE::Filter::Line(3)

NOM

POE::Filter::Line - sérialise et analyse les enregistrements terminés (lignes)

SYNTAXE

#!perl
use POE qw(Wheel::FollowTail Filter::Line);
POE::Session->create(
  inline_states => {
    _start => sub {
      $_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
        Filename => "/var/log/system.log",
        InputEvent => "got_log_line",
        Filter => POE::Filter::Line->new(),
      );
    },
    got_log_line => sub {
      print "Log: $_[ARG0]\n";
    }
  }
);
POE::Kernel->run();
exit;

DESCRIPTION

POE::Filter::Line analyse les données de flux en enregistrements terminés. Le parseur par défaut interprète les sauts de ligne comme terminateurs d'enregistrement, et le sérialiseur par défaut ajoute des sauts de ligne réseau (CR/LF, ou "\x0D\x0A") aux enregistrements sortants.

Les terminateurs d'enregistrement sont supprimés des données que POE::Filter::Line retourne.

POE::Filter::Line prend en charge plusieurs autres façons d'analyser les lignes. Les paramètres du constructeur peuvent spécifier des sauts de ligne littéraux, des expressions régulières, ou que le filtre doit détecter les sauts de ligne par lui-même.

MÉTHODES PUBLIQUES DU FILTRE

La méthode new() de POE::Filter::Line accepte des paramètres intéressants.

new

new() accepte une liste de paramètres nommés.

Dans tous les cas, les données interprétées comme terminateur d'enregistrement sont supprimées des données que POE::Filter::Line retourne.

"InputLiteral" peut être utilisé pour analyser les enregistrements terminés par une chaîne littérale. Par exemple, POE::Filter::Line peut être utilisé pour analyser et émettre des lignes de style C, qui sont terminées par un NUL ASCII :

my $c_line_filter = POE::Filter::Line->new(
  InputLiteral => chr(0),
  OutputLiteral => chr(0),
);

"OutputLiteral" permet à un filtre de put() des enregistrements avec un terminateur d'enregistrement différent de celui qu'il analyse. Ceci peut être utile dans les applications qui doivent traduire les terminateurs d'enregistrement.

"Literal" est un raccourci pour le cas courant où les littéraux d'entrée et de sortie sont identiques. L'exemple précédent peut être écrit comme suit :

my $c_line_filter = POE::Filter::Line->new(
  Literal => chr(0),
);

Une application peut également permettre à POE::Filter::Line de déterminer quel saut de ligne utiliser. Ceci est fait en spécifiant "InputLiteral" à undef :

my $whichever_line_filter = POE::Filter::Line->new(
  InputLiteral => undef,
  OutputLiteral => "\n",
);

"InputRegexp" peut être utilisé à la place de "InputLiteral" pour reconnaître les terminateurs de ligne basés sur une expression régulière. Dans cet exemple, l'entrée est terminée par deux sauts de ligne consécutifs ou plus. En sortie, le séparateur de paragraphe est "---" sur une ligne à part.

my $paragraph_filter = POE::Filter::Line->new(
  InputRegexp => "([\x0D\x0A]{2,})",
  OutputLiteral => "\n---\n",
);

"MaxBuffer" définit la quantité maximale de données que le filtre conservera tout en essayant de trouver une fin de ligne. La valeur par défaut est de 512 Mo.

"MaxLength" définit la longueur maximale d'une ligne. La valeur par défaut est de 64 Mo.

Si la contrainte "MaxLength" ou "MaxBuffer" est dépassée, "POE::Filter::Line" lèvera une exception.

MÉTHODES PUBLIQUES DU FILTRE

POE::Filter::Line n'a pas de méthodes publiques supplémentaires.

SOUS-CLASSEMENT

POE::Filter::Line exporte la constante FIRST_UNUSED. Celle-ci pointe vers le premier élément inutilisé de la référence de tableau $self. Les sous-classes devraient stocker leurs propres données en commençant ici, et elles devraient exporter leurs propres constantes FIRST_UNUSED pour aider les futurs sous-classseurs.

BOGUES

Le parseur de saut de ligne d'entrée par défaut est une expression régulière qui présente une condition de concurrence fâcheuse. Voici l'expression régulière :

/(\x0D\x0A?|\x0A\x0D?)/

Bien qu'elle reconnaisse rapidement la plupart des formes de saut de ligne, elle peut parfois détecter une ligne vide supplémentaire. Cela se produit lorsqu'un caractère de saut de ligne à deux octets est divisé entre deux lectures. Considérez cette situation :

données de fluxquelconquesCR
LFautres données de flux

L'expression régulière verra le premier CR sans son LF correspondant. Le filtre retournera correctement "données de fluxquelconques" comme ligne. Lorsque le paquet suivant arrivera, le "LF" en tête sera traité comme le terminateur d'une ligne de 0 octet. Le filtre retournera fidèlement cette ligne vide.

Il est conseillé de spécifier des sauts de ligne littéraux ou d'utiliser la fonction de détection automatique dans les applications où les lignes vides sont importantes.
