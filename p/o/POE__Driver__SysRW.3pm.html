POE::Driver::SysRW(3) Documentation Perl fournie par l'utilisateur POE::Driver::SysRW(3)

NOM

POE::Driver::SysRW - I/O tamponné et non bloquant utilisant sysread et syswrite

SYNOPIS

"SYNOPSIS" dans POE::Driver illustre comment l'interface fonctionne. Ce module n'est qu'une implémentation.

DESCRIPTION

Ce driver implémente POE::Driver en utilisant sysread et syswrite.

MÉTHODES PUBLIQUES

POE::Driver::SysRW introduit certaines fonctionnalités supplémentaires non couvertes dans l'interface de base.

new [BlockSize => OCTETS]

new() crée un nouveau driver d'E/S tamponné qui utilise sysread() pour lire les données d'un descripteur et syswrite() pour vider les données vers ce descripteur. Le constructeur accepte un paramètre nommé optionnel, "BlockSize", qui indique le nombre maximum d'OCTETS à lire à la fois.

"BlockSize" est de 64 kilo-octets (65536 octets) par défaut. Des valeurs plus élevées peuvent améliorer les performances dans les applications de streaming, mais le compromis est une granularité d'événements plus faible et une utilisation accrue de la mémoire résidente.

Des valeurs "BlockSize" plus basses réduisent légèrement la consommation de mémoire avec des pénalités de débit correspondantes.

my $driver = POE::Driver::SysRW->new;
my $driver = POE::Driver::SysRW->new( BlockSize => $block_size );

Les drivers sont couramment instanciés dans les appels de constructeur de POE::Wheel :

$_[HEAP]{wheel} = POE::Wheel::ReadWrite->new(
  InputHandle => \*STDIN,
  OutputHandle => \*STDOUT,
  Driver => POE::Driver::SysRW->new(),
  Filter => POE::Filter::Line->new(),
);

Les applications utilisent presque toujours POE::Driver::SysRW, donc les objets POE::Wheel en créeront presque toujours un si aucun Driver n'est spécifié.

Toutes les autres méthodes

POE::Driver::SysRW documente l'interface abstraite documentée dans POE::Driver. Veuillez consulter POE::Driver pour plus de détails sur les méthodes suivantes :

flush
get
get_out_messages_buffered
put
