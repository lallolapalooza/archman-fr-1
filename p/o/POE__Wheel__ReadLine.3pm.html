POE::Wheel::ReadLine(3) Documentation Perl fournie par l'utilisateur POE::Wheel::ReadLine(3)

NOM

POE::Wheel::ReadLine - Term::ReadLine non bloquant pour POE

SYNOPSIS

#!perl
use warnings;
use strict;
use POE qw(Wheel::ReadLine);
POE::Session->create(
  inline_states=> {
    _start => \&setup_console,
    got_user_input => \&handle_user_input,
  }
);
POE::Kernel->run();
exit;
sub handle_user_input {
  my ($input, $exception) = @_[ARG0, ARG1];
  my $console = $_[HEAP]{console};
  unless (defined $input) {
    $console->put("$exception attrapé. Au revoir !");
    $_[KERNEL]->signal($_[KERNEL], "UIDESTROY");
    $console->write_history("./test_history");
    return;
  }
  $console->put("  Vous avez entré : $input");
  $console->addhistory($input);
  $console->get("Go: ");
}
sub setup_console {
  $_[HEAP]{console} = POE::Wheel::ReadLine->new(
    InputEvent => 'got_user_input'
  );
  $_[HEAP]{console}->read_history("./test_history");
  $_[HEAP]{console}->clear();
  $_[HEAP]{console}->put(
    "Entrez du texte.",
    "Ctrl+C ou Ctrl+D pour quitter."
  );
  $_[HEAP]{console}->get("Go: ");
}

DESCRIPTION

POE::Wheel::ReadLine est une forme non bloquante de Term::ReadLine compatible avec POE. Il utilise Term::Cap pour interagir avec l'affichage du terminal et Term::ReadKey pour interagir avec le clavier.

POE::Wheel::ReadLine gère presque toutes les touches d'édition courantes. Il fournit une liste d'historique des entrées. Il possède des modes vi et emacs. Il prend en charge la recherche incrémentale des entrées. Il est entièrement personnalisable et compatible avec les implémentations readline(3) standard telles que Term::ReadLine::Gnu.

POE::Wheel::ReadLine est configuré en plaçant des commandes dans un fichier d'initialisation "inputrc". Le nom du fichier est tiré de la variable d'environnement "INPUTRC", ou ~/.inputrc par défaut. POE::Wheel::ReadLine lira le fichier inputrc et se configurera selon les commandes et les variables qu'il contient. Voir readline(3) pour les détails sur les fichiers inputrc.

Le mode d'édition par défaut sera de style emacs, bien que cela puisse être configuré en définissant la variable 'editing-mode' dans un fichier inputrc. Si tout le reste échoue, POE::Wheel::ReadLine déterminera l'éditeur préféré de l'utilisateur en examinant la variable d'environnement EDITOR.

MÉTHODES PUBLIQUES

Constructeur

La plupart des interactions de POE::Wheel::ReadLine se font via son constructeur, new().

new

new() crée et retourne un nouvel objet POE::Wheel::ReadLine. Assurez-vous d'en instancier un seul, car plusieurs lecteurs de console entreraient en conflit.

InputEvent

"InputEvent" nomme l'événement qui indiquera une nouvelle ligne d'entrée console. Voir "ÉVÉNEMENTS PUBLICS" pour plus de détails.

PutMode

"PutMode" contrôle comment la sortie est affichée lorsque put() est appelé pendant l'entrée utilisateur.

Lorsqu'il est défini sur "immediate", put() interrompt immédiatement l'utilisateur. L'invite de saisie et l'entrée de l'utilisateur jusqu'à présent sont réaffichées après que put() soit terminé.

Le "PutMode" "after" indique à put() d'attendre la fin de l'entrée de l'utilisateur ou son annulation.

Enfin, "idle" permettra à put() d'interrompre l'entrée de l'utilisateur si l'utilisateur arrête de taper pendant "IdleTime" secondes. Ce mode se comporte comme "after" si l'utilisateur ne peut pas arrêter de taper assez longtemps. C'est le mode par défaut de POE::Wheel::ReadLine.

IdleTime

"IdleTime" indique à POE::Wheel::ReadLine combien de temps le clavier doit rester inactif avant que put() ne devienne immédiat ou que le texte mis en mémoire tampon ne soit vidé sur l'affichage. Il n'est pertinent que lorsque "PutMode" est "idle". "IdleTime" vaut 2 secondes par défaut.

AppName

"AppName" enregistre un nom d'application utilisé pour récupérer les liaisons de touches spécifiques à l'application depuis le fichier inputrc. L'"AppName" par défaut est "poe-readline".

# Si vous utilisez POE::Wheel::ReadLine, définissez
# le mappage de touches en mode emacs et
# déclenchez la sortie de débogage sur une certaine
# séquence de touches.
$if poe-readline
set keymap emacs
Control-xP: poe-wheel-debug
$endif

Gestion de la liste d'historique

POE::Wheel::ReadLine prend en charge un historique des entrées, avec recherche.

add_history

add_history() accepte une liste de lignes à ajouter à l'historique des entrées. Généralement, il est appelé avec une seule ligne : la dernière ligne d'entrée reçue du terminal. Le "SYNOPSIS" montre add_history() en action.

get_history

get_history() retourne une liste contenant l'historique des entrées actuel de POE::Wheel::ReadLine. Il peut ne pas contenir tout ce qui a été entré dans la roue.

write_history

write_history() écrit l'historique actuel des entrées dans un fichier. Il accepte un paramètre optionnel : le nom du fichier où l'historique des entrées sera écrit. write_history() écrira dans ~/.history si aucun nom de fichier n'est spécifié.

Retourne vrai en cas de succès, ou faux sinon.

Le "SYNOPSIS" montre un exemple de write_history() et le read_history() correspondant.

read_history

read_history(FILENAME, START, END) lit un historique d'entrée précédemment sauvegardé à partir d'un fichier nommé, ou depuis ~/.history si aucun nom de fichier n'est spécifié. Il peut également lire un sous-ensemble du fichier d'historique s'il reçoit les paramètres optionnels START et END. Le fichier sera lu à partir du début si START est omis ou zéro. Il sera lu jusqu'à la fin si END est omis ou antérieur à START.

Retourne vrai en cas de succès, ou faux sinon.

Le "SYNOPSIS" montre un exemple de read_history() et le write_history() correspondant.

Lire les dix premières lignes de l'historique :

$_[HEAP]{console}->read_history("filename", 0, 9);

history_truncate_file

history_truncate_file() tronque un fichier d'historique à un certain nombre de lignes. Il accepte deux paramètres : le nom du fichier à tronquer et le nombre maximum de lignes d'historique à laisser dans le fichier. Le fichier d'historique sera entièrement vidé si le nombre de lignes est zéro ou omis.

Le fichier à tronquer est par défaut ~/.history. Ainsi, appeler history_truncate_file() sans paramètres efface ~/.history.

Retourne vrai en cas de succès, ou faux sinon.

Notez que history_trucate_file() supprime les lignes les plus anciennes du fichier. Les lignes ultérieures restent intactes car ce sont celles qui ont été saisies le plus récemment.

Garder ~/.history sous 100 lignes gérables :

$_[HEAP]{console}->history_truncate_file(undef, 100);

Méthodes de liaison de touches

bind_key

bind_key(KEYSTROKE, FUNCTION) lie une FUNCTION à une séquence de touche nommée KEYSTROKE. La séquence de touches peut être dans l'une des formes définies dans readline(3). La fonction doit être soit un nom prédéfini, tel que "self-insert", soit une référence de fonction. La liaison est effectuée dans la map de touches actuelle. Utilisez la méthode rl_set_keymap() pour changer de map de touches, si vous le souhaitez.

add_defun NAME FN

add_defun(NAME, FUNCTION) définit une nouvelle FUNCTION globale, lui donnant un NAME spécifique. La fonction peut ensuite être liée à des séquences de touches par ce NAME.

Méthodes d'E/S Console

clear

Efface le terminal.

terminal_size

Retourne ce que POE::Wheel::ReadLine pense être les dimensions actuelles du terminal. Retourne une liste de deux valeurs : le nombre de colonnes et le nombre de lignes, respectivement.

sub some_event_handler {
  my ($columns, $rows) = $_[HEAP]{console}->terminal_size;
  $_[HEAP]{console}->put(
    "Colonnes du terminal : $columns",
    "Lignes du terminal : $rows",
  );
}

get

get() fait que POE::Wheel::ReadLine affiche un message de prompte, puis attend l'entrée de l'utilisateur. L'entrée n'est pas notifiée, même si get() a activé le watcher d'E/S de la roue elle-même.

Après l'appel de get(), la ligne suivante d'entrée ou d'erreur sur la console déclenchera un événement "InputEvent" avec les paramètres appropriés. POE::Wheel::ReadLine entrera dans un état inactif jusqu'à ce que get() soit rappelé.

Un appel à get() sans paramètre préservera le message de prompte actuel. Un appel à get() avec un paramètre avant de recevoir une ligne d'entrée complète modifiera le message de prompte en temps réel.

Voir le "SYNOPSIS" pour des exemples d'utilisation.

put

put() accepte une liste de lignes à afficher dans le terminal. POE::Wheel::ReadLine est basé sur les lignes. Voir POE::Wheel::Curses pour d'autres options d'affichage plus élaborées.

Il ne faut pas utiliser print() avec POE::Wheel::ReadLine. print() obtient toujours le mauvais caractère de nouvelle ligne, laissant la sortie d'un programme dans le terminal comme une étape. De plus, put() comprend quand un utilisateur tape du texte, et le "PutMode" peut être utilisé pour éviter d'interrompre l'utilisateur.

ReadLine Option Methods

attribs

attribs() retourne une référence vers un hash d'options readline. Le hash retourné peut être utilisé pour interroger ou modifier le comportement de POE::Wheel::ReadLine.

option

option(NAME) retourne un membre spécifique du hash retourné par attribs(). C'est une façon plus pratique d'interroger les options de POE::Wheel::ReadLine.

PUBLIC EVENTS

POE::Wheel::ReadLine n'émet qu'un seul événement.

InputEvent

"InputEvent" est l'événement émis lorsqu'une entrée complète est entrée dans le terminal. Chaque gestionnaire d'"InputEvent" reçoit trois paramètres :

"$_[ARG0]" contient une ligne d'entrée. Il peut s'agir d'une chaîne vide si l'utilisateur a entré une ligne vide. Si aucune valeur définie n'est spécifiée, cela indique une erreur telle que la fin de l'entrée, que l'utilisateur a annulé son entrée ou qu'il a appuyé sur C-c (^C).

"$_[ARG1]" décrit une erreur, si une s'est produite. Il peut contenir l'une des chaînes suivantes :

cancel
L'exception "cancel" indique qu'un utilisateur a annulé une ligne d'entrée. Elle est envoyée lorsque l'utilisateur déclenche la fonction "abort", qui est associée à C-g (^G) par défaut.
eot
"eot" est le code ASCII pour "end of tape". Il est émis lorsque l'utilisateur demande la fermeture du terminal. Par défaut, il est déclenché lorsque l'utilisateur appuie sur C-d (^D) sur une ligne vide.
interrupt
"interrupt" est envoyé suite à l'appui sur C-c (^C) ou à d'autres événements qui déclenchent la fonction "interrupt".

Enfin, "$_[ARG2]" contient l'identifiant de l'objet POE::Wheel::ReadLine qui a envoyé l'événement "InputEvent".

CUSTOM BINDINGS

POE::Wheel::ReadLine permet de lier des fonctions personnalisées à des touches. La fonction doit être visible par la roue avant de pouvoir être liée. Pour enregistrer une fonction, utilisez la méthode add_defun() de POE::Wheel::ReadLine :

POE::Wheel::ReadLine->add_defun('reverse-line', \&reverse_line);

Lors de l'ajout d'une nouvelle defun, vous pouvez fournir un paramètre optionnel qui est une séquence de touches à lier. Elle doit être dans le même format que celui compris par le parseur inputrc.

Les fonctions liées reçoivent trois paramètres : une référence à l'objet de la roue, la séquence de touches qui a déclenché la fonction (sous forme de texte imprimable), et la séquence de touches brute. La fonction liée doit inspecter les membres de POE::Wheel::ReadLine pour effectuer son travail et afficher le contenu de la nouvelle ligne.

Ceci est moins idéal et pourrait changer à l'avenir.

CUSTOM COMPLETION

Une application peut modifier la fonction de complétion de POE::Wheel::ReadLine pour personnaliser la façon dont l'entrée sera complétée. La nouvelle fonction de complétion doit accepter trois paramètres scalaires : le mot à compléter, le texte complet, et la position dans le texte d'entrée du mot à compléter.

La fonction de complétion doit retourner une liste de correspondances possibles. Par exemple :

my $attribs = $wheel->attribs();
$attribs->{completion_function} = sub {
  my ($text, $line, $start) = @_;
  return qw(a list of candidates to complete);
}

C'est la seule forme de complétion actuellement prise en charge.

IMPLEMENTATION DIFFERENCES

Bien que POE::Wheel::ReadLine soit calqué sur la bibliothèque readline(3), certaines zones n'ont pas été implémentées. Les options qui ont un effet sur cette implémentation sont : le style de l'alarme, le mode d'édition, les terminateurs de recherche, le début des commentaires, l'affichage horizontal des complétions, l'affichage de tout si ambigu, et la fonction de complétion.

La fonction 'tab-insert' n'est pas implémentée et les tabulations ne sont pas affichées correctement.

BUGS

POE::Wheel::ReadLine présente quelques problèmes connus :

Perl 5.8.0 is Broken

L'entrée non bloquante avec Term::ReadKey ne fonctionne pas avec Perl 5.8.0, en particulier sur les systèmes Linux, pour des raisons inconnues. Il est fortement recommandé de mettre à jour Perl pour résoudre ce problème. Si vous ne pouvez pas mettre à jour Perl, envisagez des méthodes alternatives comme Term::Visual.

Les tickets http://rt.cpan.org/Ticket/Display.html?id=4524 et d'autres expliquent le problème en détail. Si vous suspectez que votre système a un Term::ReadKey défectueux, vous pouvez exécuter ce programme de test pour vous en assurer.

#!/usr/bin/perl
use Term::ReadKey;
print "Press 'q' to quit this test.\n";
ReadMode 5; # Désactive les touches de contrôle
while (1) {
  while (not defined ($key = ReadKey(-1))) {
    print "Didn't get a key.  Sleeping 1 second.\015\012";
    sleep (1);
  }
  print "Got key: $key\015\012";
  ($key eq 'q') and last;
}
ReadMode 0; # Réinitialise le mode avant de quitter
exit;

Non-Optimal Code

La dissociation des curseurs d'entrée et de visualisation a introduit un grand nombre de lignes de code. Une grande partie de ce code a été écrite à la hâte et pourrait être implémentée avec moins de travail.

Unimplemented Features

L'édition de l'entrée n'est pas maintenue sur une seule ligne. Si elle se croise et que le terminal ne peut pas diviser une ligne, le curseur sera perdu.

Support Unicode. Je suis très désolé de perdre la représentation native de tous les caractères à 8 bits. Je n'ai aucune idée de comment faire cela, et je n'ai pas de système pour tester cela. Les patchs sont les bienvenus.

GOTCHAS / FAQ

Lost Prompts

Q : Pourquoi est-ce que je perds mon message de prompte chaque fois que j'envoie une sortie à l'écran ?

R : Vous utilisez peut-être print ou printf pour écrire la sortie à l'écran. POE::Wheel::ReadLine ne suit pas STDOUT lui-même, il ne sait donc pas quand rafraîchir le message de prompte après son utilisation. Utilisez la méthode put() de POE::Wheel::ReadLine pour écrire des lignes dans la console.

Edit Keystrokes Display as ^C

Q : Aucune des touches d'édition ne fonctionne. Ctrl-C affiche "^c" au lieu de générer une interruption. Les touches fléchées n'affichent pas l'historique d'entrée dans mon historique. C'est généralement une mauvaise expérience.

R : Vous êtes peut-être un utilisateur de vi/vim. S'il n'y a pas de fichier ~/.inputrc, POE::Wheel::ReadLine examine votre variable d'environnement EDITOR pour les préférences d'édition. S'il y voit /vi/, il démarre en mode vi. Vous pouvez remplacer cela en créant un fichier ~/.inputrc avec la ligne "set editing-mode emacs" ou en ajoutant cette ligne à votre fichier ~/.inputrc existant. Tant que vous y êtes, vous devriez vous familiariser avec tout ce que vous pouvez faire d'utile avec les fichiers .inputrc.

Lack of Windows Support

Q : Pourquoi POE::Wheel::ReadLine ne fonctionne-t-il pas sous Windows ? Term::ReadLine le fait.

R : POE::Wheel::ReadLine nécessite select(), car c'est ce que POE utilise par défaut pour détecter les frappes sans blocage. Environ 50 % des versions de Perl sous Windows implémentent select() en termes de la même fonction dans la bibliothèque WinSock, ce qui limite select() uniquement aux sockets. Votre console n'est pas un socket, donc select() ne fonctionne pas avec votre version de Perl sous Windows.

Des solutions de contournement très bonnes existent mais ne sont pas disponibles au moment de la rédaction. Elles impliquent d'écrire une boucle POE spéciale pour Windows qui utilise un module Win32 spécifique pour un meilleur multiplexage, qui capture l'entrée, ou qui utilise des watchers d'E/S bloquants dans des threads séparés.

Cygwin Support

Q : Pourquoi POE::Wheel::ReadLine ne fonctionne-t-il pas sous Cygwin ? Term::ReadLine le fait.

R : POE::Wheel::ReadLine nécessite select(), car c'est ce que POE utilise par défaut pour détecter les frappes sans blocage. Environ 50 % des versions de Perl sous Cygwin implémentent select() en termes de la même fonction dans la bibliothèque WinSock, ce qui limite select() uniquement aux sockets. Votre console n'est pas un socket, donc select() ne fonctionne pas avec votre version de Perl sous Cygwin.

Q: Pourquoi POE::Wheel::ReadLine se plaint-il de mon terminal "dumb" ?

R: Avez-vous installé Strawberry Perl ? En raison de son fonctionnement, lors de l'installation, il définit une variable d'environnement globale sous MSWin32 pour TERM=dumb. (cela peut être corrigé dans une future version, mais c'est là pour le moment, ha !) Dans ce cas, se connecter au shell Cygwin via le lanceur cygwin.bat entraîne un readline non fonctionnel.

Normalement, Cygwin définit TERM=cygwin dans le lanceur. Cependant, si TERM était déjà défini, il ne modifiera pas la valeur. Par conséquent, le "bug" apparaît ! Ce que vous pouvez faire est de modifier le fichier cygwin.bat pour ajouter cette ligne :

SET TERM=cygwin

D'autres utilisateurs ont signalé que vous pouvez obtenir de meilleurs résultats en modifiant le fichier ~/.bash_profile pour définir TERM=cygwin, car lors d'une mise à niveau de Cygwin, le fichier cygwin.bat est écrasé.

Alternativement, vous pourriez installer d'autres terminaux comme "xterm" ou "rxvt" comme montré ici : http://c2.com/cgi/wiki?BetterCygwinTerminal. Veuillez nous faire savoir si vous rencontrez des problèmes en utilisant un autre terminal que "dumb".

Si vous vous sentez courageux, vous pouvez consulter le ticket RT à l'adresse http://rt.cpan.org/Ticket/Display.html?id=55365 pour plus d'informations sur ce problème.
