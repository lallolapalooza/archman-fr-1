POE::Driver(3) Documentation Perl fournie par l'utilisateur POE::Driver(3)

NOM

POE::Driver - une interface abstraite pour les E/S tamponnées et non bloquantes

SYNTAXE

Ceci est un exemple 만든 pour montrer comment les objets POE::Filter et POE::Driver peuvent être utilisés dans une application autonome.

mon $driver = POE::Driver::SysRW->new();
mon $filter = POE::Filter::Line->new();
mon $liste_de_morceaux_d_octets = $filter->put("Une ligne de texte.");
$driver->put( $liste_de_morceaux_d_octets );
mon $octets_restants_dans_le_tampon = $driver->flush($descripteur_fichier);
mourir "impossible de tout vider" si $octets_restants_dans_le_tampon;
tant que (1) {
  mon $liste_d_octets = $driver->get($descripteur_fichier);
  mourir $! unless defined $liste_d_octets;
  $filter->get_one_start($liste_d_octets);
  tant que (mon $ligne = $filter->get_one()) {
    imprimer "Entrée : $ligne\n";
  }
}

La plupart des programmes utiliseront les objets POE::Filter et POE::Driver comme paramètres pour les constructeurs POE::Wheel. Voir les synopses des classes particulières pour plus de détails.

DESCRIPTION

POE::Driver est une API commune pour les pilotes d'E/S qui peuvent lire et écrire à partir de divers fichiers, sockets, pipes et autres périphériques.

Les "pilotes" POE implémentent les spécificités de la lecture et de l'écriture sur les périphériques. Les pilotes se branchent sur les objets POE::Wheel afin que les roues puissent prendre en charge un grand nombre de types de périphériques sans implémenter de sous-classe distincte pour chacun.

Comme mentionné dans la SYNOPSIS, les objets POE::Driver peuvent être utilisés dans des applications autonomes.

Méthodes Publiques de Pilote

Ces méthodes constituent l'interface générique du pilote, et chaque pilote doit les implémenter. Les pilotes spécifiques peuvent avoir des méthodes supplémentaires liées à leurs tâches particulières.

new

new() crée, initialise et retourne un nouveau pilote. Les pilotes spécifiques peuvent avoir des paramètres de constructeur différents. Les paramètres de constructeur par défaut doivent configurer le pilote pour le cas d'utilisation le plus courant.

get FICHIER_DESC

get() essaie immédiatement de lire des informations à partir d'un FICHIER_DESC. Il retourne une référence de tableau en cas de succès — même si rien n'a été lu à partir du FICHIER_DESC. get() retourne undef en cas d'erreur, et $! sera défini avec la raison de l'échec de get().

La référence de tableau retournée sera vide si rien n'a été lu à partir du FICHIER_DESC.

Dans une condition de fin de fichier (EOF), get() retourne undef avec la valeur numérique de $! définie à zéro.

La référence de tableau retournée par get() peut être passée à la méthode get() ou get_one_start() de n'importe quel POE::Filter. Les roues font exactement cela en interne.

put REFERENCE_TABLEAU
put() accepte une REFERENCE_TABLEAU de morceaux d'octets bruts. Ces octets sont ajoutés à la file d'attente ou au tampon de sortie interne du pilote. put() retourne le nombre d'octets en attente de sortie après que les nouveaux octets ont été mis en tampon.

Certains pilotes peuvent vider les données immédiatement à partir de leurs méthodes put().

flush FICHIER_DESC
flush() tente d'écrire les données tamponnées d'un pilote dans un FICHIER_DESC donné. Le pilote doit vider autant de données que possible en un seul appel à flush().

flush() retourne le nombre d'octets restant dans la file d'attente ou le tampon de sortie du pilote après que le volume maximal de données a été écrit.

flush() indique le succès ou l'échec par la valeur de $! après son retour. $! sera toujours numériquement égal à zéro en cas de succès. En cas d'échec, $! contiendra la valeur habituelle d'Errno. Dans les deux cas, flush() retournera le nombre d'octets dans la file d'attente de sortie du pilote.

get_out_messages_buffered
get_out_messages_buffered() retourne le nombre de messages mis en file d'attente dans la file de sortie du pilote, arrondi au message entier supérieur. Certaines applications nécessitent le nombre de messages plutôt que le nombre d'octets.

Les messages sont des morceaux d'octets bruts mis en file d'attente par put(). L'appel suivant à put() met en file d'attente deux messages pour un total de six octets :

$filter->put( [ "un", "deux" ] );

Il est possible qu'un appel à flush() écrive une partie d'un message. Un message partiel compte toujours comme un message.

VOIR AUSSI

La section VOIR AUSSI de POE contient une table des matières couvrant l'ensemble de la distribution POE.

POE::Wheel - Une classe de base pour les mixins POE::Session.

POE::Filter - Une classe de base pour les analyseurs et sérialiseurs de données.

POE::Driver::SysRW - Un pilote qui encapsule sysread() et syswrite() tamponné.

BOGUES

Il n'y a pas de POE::Driver::SendRecv, mais personne n'en a eu besoin jusqu'à présent. sysread() et syswrite() parviennent à faire presque tout ce dont les gens ont besoin.

En théorie, les pilotes devraient être largement interchangeables. En pratique, il semble y avoir une barrière infranchissable entre les différents types SOCK_*.
