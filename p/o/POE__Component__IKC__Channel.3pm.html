NOM

POE::Component::IKC::Channel - Session d'E/S pour la communication Inter-Kernel (IKC) de POE

SYNTAXE

use POE;
use POE::Component::IKC::Channel;
POE::Component::IKC::Channel->spawn( %params );

DESCRIPTION

Vous n'utiliserez jamais directement un canal IKC. Ils sont créés par POE::Component::IKC::Server et POE::Component::IKC::Client selon les besoins.

Ce module implémente une E/S IKC de POE. Lorsqu'une nouvelle connexion est établie, "IKC::Server" et "IKC::Client" créent un "IKC::Channel" pour gérer les E/S.

La communication IKC se déroule en 2 phases : phase de négociation et phase normale.

La phase de négociation utilise "Filter::Line" et sert à échanger divers paramètres entre les noyaux (exemple : noms des noyaux, type de freeze/thaw à utiliser, etc.). Après la négociation, "IKC::Channel" bascule sur un "Filter::Reference" et crée un "IKC::Responder", si nécessaire. Après cela, le canal transfère les lectures et écritures entre "Wheel::ReadWrite" et le Responder.

"IKC::Channel" est également en charge du nettoyage des noms de noyaux lorsque le noyau distant se déconnecte.

MÉTHODES

spawn

POE::Component::IKC::Channel->spawn(%param);

Crée un nouveau canal IKC pour gérer les négociations puis les données réelles.

Les paramètres sont structurés comme suit :

handle
Le handle Perl à passer à "Wheel::ReadWrite::new".
kernel_name
Le nom du noyau local. Ceci est une solution temporaire jusqu'à ce que la nomination des événements soit résolue.
on_connect
Référence de code appelée lorsque la phase de négociation est terminée. Normalement, vous l'utiliseriez pour démarrer les sessions qui envoient des événements aux noyaux étrangers.
subscribe
Référence de tableau de spécificateurs (soit des sessions étrangères, soit des états étrangers) auxquels vous souhaitez vous abonner. $on_connect ne sera appelé que si vous pouvez vous abonner à tous ces spécificateurs. Sinon, il mourra().
unix
Un indicateur précisant si le handle est un socket de domaine Unix ou non.
aliases
Référence de tableau d'alias pour le noyau local.
serializers
Référence de tableau ou scalaire des paquets que vous souhaitez utiliser pour la sérialisation des données. Un paquet sérialiseur nécessite 2 fonctions : freeze (ou nfreeze) et thaw. Voir "POE::Component::IKC::Client".
"protocol"
Quel protocole de négociation IKC utiliser. Le protocole original ("IKC") était synchrone et lent. Le nouveau protocole ("IKC0") envoie toutes les informations en une seule fois. IKC0 se dégradera gracieusement vers IKC si le client et le serveur ne correspondent pas.

La valeur par défaut est actuellement IKC, mais passera à IKC0 dès que je serai confiant dans le nouveau protocole.

ÉVÉNEMENTS

shutdown

Cet événement provoque la fermeture du socket du serveur et son départ. Normalement, il n'est posté que par IKC::Responder.

Si vous souhaitez poster cet événement vous-même, vous pouvez obtenir l'identifiant de session du canal à partir de on_connect de IKC::Client :

POE::Component::IKC::Client->spawn(
    ....
        on_connect=>sub {
            $heap->{channel} = $poe_kernel->get_active_session()->ID;
        },
    ....
    );

Ensuite, lorsqu'il sera temps de se déconnecter :

$poe_kernel->call($heap->{channel} => 'shutdown');

Oui, c'est une solution de contournement. Un mécanisme plus propre doit être fourni.
