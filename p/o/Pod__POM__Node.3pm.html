Pod::POM::Node(3) Documentation Perl soumise par l'utilisateur Pod::POM::Node(3)

NOM

Pod::POM::Node - classe de base pour un nœud du modèle POM

SYNTAXE

package Pod::POM::Node::Over;
use parent qw( Pod::POM::Node );
use vars qw( @ATTRIBS @ACCEPT $EXPECT $ERROR );
@ATTRIBS =   ( indent => 4 );
@ACCEPT  = qw( over item begin for text verbatim );
$EXPECT  =  q( back );
package main;
my $list = Pod::POM::Node::Over->new(8);
$list->add('item', 'First Item');
$list->add('item', 'Second Item');
...

DESCRIPTION

Ce document décrit le fonctionnement interne de la classe Pod::POM::Node et donne une brève explication de la relation entre elle et ses classes dérivées. Il s'agit plutôt d'un guide pour les personnes intéressées par le fonctionnement interne des programmeurs que d'une documentation générale pour les utilisateurs. Voir Pod::POM pour des informations sur l'utilisation des classes.

Cette classe implémente une classe de nœud de base qui est sous-classée pour représenter différents éléments du modèle objet Pod.

package Pod::POM::Node::Over;
use parent qw( Pod::POM::Node );
use vars qw( @ATTRIBS $ERROR );
@ATTRIBS = ( indent => 4 );
package main;
my $list = Pod::POM::Node::Over->new();

La caractéristique d'un nœud peut être spécifiée en définissant certaines variables dans la classe dérivée. La liste @ATTRIBS peut être utilisée pour indiquer les attributs que le nœud doit accepter. Dans le cas d'un nœud "=over", par exemple, un attribut "indent" peut être spécifié qui est autrement fixé à 4.

package Pod::POM::Node::Over;
use parent qw( Pod::POM::Node );
use vars qw( @ATTRIBS $ERROR );
@ATTRIBS = ( indent => 4 );

La méthode new() attend maintenant un argument pour définir la valeur de l'indentation, ou utilisera 4 comme valeur par défaut si aucun argument n'est fourni.

my $list = Pod::POM::Node::Over->new(8);    # indent: 8
my $list = Pod::POM::Node::Over->new();    # indent: 4

Si la valeur par défaut est indéfinie, l'argument est obligatoire.

package Pod::POM::Node::Head1;
use parent qw( Pod::POM::Node );
use vars qw( @ATTRIBS $ERROR );
@ATTRIBS = ( title => undef );
package main;
my $head = Pod::POM::Node::Head1->new('My Title');

Si un argument obligatoire n'est pas fourni, le constructeur renverra undef pour indiquer un échec. La variable $ERROR dans la classe dérivée est définie pour contenir une chaîne de la forme "$type attendait un attribut $attribute".

# produira une erreur : "head1 attendait un titre"
my $head = Pod::POM::Node::Head1->new()
    || die $Pod::POM::Node::Head1::ERROR;

Pour plus de commodité, la sous-routine error() peut être appelée en tant que méthode de classe pour obtenir cette valeur.

my $type = 'Pod::POM::Node::Head1';
my $head = $type->new()
    || die $type->error();

La variable @ACCEPT peut être utilisée pour indiquer les types de nœuds acceptés comme enfants d'un nœud.

package Pod::POM::Node::Head1;
use parent qw( Pod::POM::Node );
use vars qw( @ATTRIBS @ACCEPT $ERROR );
@ATTRIBS =   ( title => undef );
@ACCEPT  = qw( head2 over begin for text verbatim );

La méthode add() peut être appelée sur un nœud pour ajouter un nouveau nœud enfant dans le cadre de son contenu.

$head->add('over', 8);

Le premier argument indique le type de nœud. La liste @ACCEPT est examinée pour s'assurer que le type de nœud enfant est acceptable pour le nœud parent. Si c'est valide, le constructeur de la classe correspondante du nœud enfant est appelé en passant les arguments restants comme attributs. Le nouveau nœud est ensuite renvoyé.

my $list = $head->add('over', 8);

La méthode error() peut être appelée sur le nœud parent pour obtenir les erreurs générées par le nœud enfant.

my $list = $head->add('over', 8);
die $head->error() unless defined $list;

Si le nœud enfant n'est pas acceptable par le nœud parent, la méthode add() renvoie l'une des valeurs IGNORE, REDUCE ou REJECT, telles que définies dans Pod::POM::Constants. Ces valeurs sont utilisées par le module d'analyse Pod::POM pour implémenter un analyseur simple de type décalage/réduction.

Dans le cas le plus courant, IGNORE est renvoyé pour indiquer que le nœud parent ne sait rien du nouveau nœud enfant. L'analyseur utilise cela comme un indicateur qu'il doit reculer dans la pile d'analyse jusqu'à ce qu'il trouve un nœud qui *devrait* accepter ce nœud enfant. Grâce à ce mécanisme, l'analyseur peut implicitement terminer certains blocs POD. Par exemple, une liste d'éléments initiée par une balise "=item" n'acceptera pas une autre balise "=item", mais renverra IGNORE. L'analyseur reculera jusqu'à ce qu'il trouve le nœud "=over" qui *devrait* l'accepter. Par conséquent, une nouvelle balise "=item" termine implicitement toute balise "=item" précédente.

La variable $EXPECT peut être utilisée pour indiquer le type de nœud qu'un parent s'attend à terminer lui-même. Un nœud "=over", par exemple, doit toujours être terminé par une balise "=back". Lorsque cette correspondance est effectuée, la méthode add() renvoie REDUCE pour indiquer la terminaison réussie.

package Pod::POM::Node::Over;
use parent qw( Pod::POM::Node );
use vars qw( @ATTRIBS @ACCEPT $EXPECT $ERROR );
@ATTRIBS =   ( indent => 4 );
@ACCEPT  = qw( over item begin for text verbatim );
$EXPECT  =  q( back );
package main;
my $list = Pod::POM::Node::Over->new();
my $item = $list->add('item');
$list->add('back');                 # renvoie REDUCE

Si un nœud enfant n'est pas spécifié dans la liste @ACCEPT ou ne correspond à aucun $EXPECT spécifié, REJECT est renvoyé. Le nœud parent définit une erreur interne de la forme "$type attendait un terme $expect". L'analyseur utilise cela pour détecter les balises POD manquantes. Dans presque tous les cas, l'analyseur est suffisamment intelligent pour corriger la structure incorrecte et transformer toute erreur en avertissement.

# produira une erreur "over attendait un terme back"
ref $list->add('head1', 'My Title')     # renvoie REJECT
    || die $list->error();

Chaque nœud contient un champ 'type' qui contient une chaîne simple indiquant le type de nœud, par exemple 'head1', 'over', etc. Les variables $NODES et $NAMES (dans la classe de base) font référence à des listes de hachages qui associent ces noms aux noms de paquets et vice versa (par exemple, head1 <=> Pod::POM::Node::Head1).

print $list->{ type };      # 'over'

Une méthode AUTOLOAD est fournie pour accéder à de tels éléments internes pour ceux qui ne veulent pas violer l'encapsulation d'un objet.

print $list->type();

Les nœuds contiennent également une liste 'content' qui, dans la classe Pod::POM::Node::Content, contient le contenu (enfants) du nœud. La méthode AUTOLOAD renvoie ceci comme une référence à une liste ou comme une liste d'éléments selon le contexte dans lequel elle est appelée.

my $items = $list->content();
my @items = $list->content();

Chaque nœud contient également une liste 'content' pour chaque type d'enfant individuel qu'il peut accepter.

my @items = $list->item();
my @text  = $list->text();
my @vtext = $list->verbatim();

La méthode present() est utilisée pour afficher un nœud via une vue spécifique. Cela associe simplement le type de nœud à une méthode appelée sur l'objet de vue. C'est ce qu'on appelle la 'double dispatch'.

my $view = 'Pod::POM::View::HTML';
print $list->present($view);

Le nom de la méthode est construit à partir du type de nœud précédé de 'view_'. Par conséquent, les éléments suivants sont approximativement équivalents.

$list->present($view);
$view->view_list($list);

L'avantage du premier sur le second est, évidemment, que l'appelant n'a pas besoin de connaître ou de déterminer le type du nœud. Le nœud lui-même est le mieux placé pour déterminer son propre type.
