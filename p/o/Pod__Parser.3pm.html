NOM

Pod::Parser - classe de base pour créer des filtres et des traducteurs POD

SYNTAXE

use Pod::Parser;
package MyParser;
@ISA = qw(Pod::Parser);
sub command { 
    my ($parser, $command, $paragraph, $line_num) = @_;
    ## Interpréter la commande et son texte ; exemples d'actions :
    if ($command eq 'head1') { ... }
    elsif ($command eq 'head2') { ... }
    ## ... autres commandes et leurs actions
    my $out_fh = $parser->output_handle();
    my $expansion = $parser->interpolate($paragraph, $line_num);
    print $out_fh $expansion;
}
sub verbatim { 
    my ($parser, $paragraph, $line_num) = @_;
    ## Mettre en forme le paragraphe en mode verbatim ; exemples d'actions :
    my $out_fh = $parser->output_handle();
    print $out_fh $paragraph;
}
sub textblock { 
    my ($parser, $paragraph, $line_num) = @_;
    ## Traduire/Mettre en forme ce bloc de texte ; exemples d'actions :
    my $out_fh = $parser->output_handle();
    my $expansion = $parser->interpolate($paragraph, $line_num);
    print $out_fh $expansion;
}
sub interior_sequence { 
    my ($parser, $seq_command, $seq_argument) = @_;
    ## Expansion de séquence intérieure ; exemples d'actions :
    return "*$seq_argument*"     if ($seq_command eq 'B');
    return "`$seq_argument'"     if ($seq_command eq 'C');
    return "_${seq_argument}_'"  if ($seq_command eq 'I');
    ## ... autres commandes de séquence et leur texte résultant
}
package main;
## Créer un objet parser et le faire parser le nom de fichier donné
## sur la ligne de commande (utiliser STDIN si aucun fichier n'est spécifié).
$parser = new MyParser();
$parser->parse_from_filehandle(\*STDIN)  if (@ARGV == 0);
for (@ARGV) { $parser->parse_from_file($_); }

REQUIERT

perl5.005, Pod::InputObjects, Exporter, Symbol, Carp

EXPORTE

Aucun.

DESCRIPTION

NOTE : Ce module est considéré comme obsolète ; les versions récentes de Perl (5.31.1 et supérieures) vont supprimer Pod-Parser du noyau et utiliser Pod::Simple pour tout ce qui concerne le formatage POD.

Pod::Parser est une classe de base pour créer des filtres et des traducteurs POD. Elle gère la majeure partie de l'effort nécessaire à l'analyse des sections POD d'un flux d'entrée, laissant aux classes filles le soin de se concentrer uniquement sur la traduction du texte.

Pod::Parser analyse les PODs et appelle des méthodes pour gérer les divers composants d'une section POD. Les classes filles de Pod::Parser redéfinissent ces méthodes pour traduire le POD dans le format de sortie désiré.

APERÇU RAPIDE

Pour créer un filtre POD afin de convertir la documentation POD dans un autre format, créez une classe fille de Pod::Parser qui redéfinira généralement uniquement les implémentations des méthodes suivantes :

  • command()
  • verbatim()
  • textblock()
  • interior_sequence()

Vous pourriez également souhaiter redéfinir les méthodes begin_input() et end_input() pour effectuer toute initialisation ou nettoyage spécifique à un fichier ou un document.

Si vous avez besoin d'effectuer un prétraitement avant l'analyse, vous pourriez vouloir redéfinir une ou plusieurs méthodes preprocess_line() et/ou preprocess_paragraph().

Parfois, il peut être nécessaire de faire plusieurs passes sur les fichiers d'entrée. Si c'est le cas, vous avez plusieurs options. Vous pouvez effectuer la première passe en utilisant Pod::Parser et redéfinir vos méthodes pour stocker les résultats intermédiaires en mémoire afin que end_pod() les traite. Vous pourriez également utiliser Pod::Parser pour plusieurs passes avec un état variable approprié pour contrôler l'opération pour chaque passe. Si votre source d'entrée ne peut pas être réinitialisée depuis le début, vous pourriez la stocker dans une autre structure telle qu'une chaîne de caractères ou un tableau et faire en sorte que cette structure implémente une méthode getline() (ce que parse_from_filehandle() utilise pour lire l'entrée).

Vous pouvez ajouter tous les champs de données dont vous avez besoin pour suivre des éléments tels que le type de source actuel, le décalage d'indentation, la position horizontale ou verticale, ou tout autre élément qui vous intéresse. Assurez-vous de lire "MÉTHODES ET DONNÉES PRIVÉES" pour éviter les collisions de noms.

En général, la classe de base Pod::Parser devrait être capable de gérer la majeure partie de l'analyse de l'entrée pour vous et vous laisser libre de vous concentrer sur l'interprétation des commandes et la traduction du résultat.

Note : Ce que nous avons décrit ici dans cet aperçu est l'utilisation la plus simple et la plus directe de Pod::Parser pour une analyse basée sur un flux. Il est également possible d'utiliser la fonction Pod::Parser::parse_text pour une analyse plus sophistiquée basée sur des arbres. Consultez "ANALYSE BASÉE SUR DES ARBRES".

OPTIONS D'ANALYSE

Une option d'analyse est simplement une option nommée de Pod::Parser avec une valeur correspondant à une action spécifique. Ces diverses actions de Pod::Parser peuvent être activées/désactivées en définissant ou en annulant la définition d'une ou plusieurs options d'analyse à l'aide de la méthode parseopts(). L'ensemble des options actuellement acceptées est le suivant :

-want_nonPODs (défaut : non défini)
Normalement (par défaut), Pod::Parser ne fournit l'accès qu'aux sections POD de l'entrée. Les paragraphes qui ne font pas partie de la documentation POD ne sont pas rendus accessibles à l'appelant (pas même via preprocess_paragraph()). En définissant cette option sur une valeur non vide et non nulle, preprocess_paragraph() pourra voir les sections d'entrée non-POD ainsi que les sections POD. La méthode cutting() peut être utilisée pour déterminer si le paragraphe correspondant est une section POD ou une autre section d'entrée.
-process_cut_cmd (défaut : non défini)
Normalement (par défaut), Pod::Parser gère la directive POD "=cut" de manière autonome et ne la transmet pas à l'appelant pour traitement. Définir cette option sur une valeur non vide et non nulle amènera Pod::Parser à transmettre la directive "=cut" à l'appelant comme toute autre commande POD (et pourrait donc être traitée par la méthode command()).

Pod::Parser interprétera toujours la directive "=cut" comme indiquant que le mode de coupure a été entré (ou ré-entré), mais l'appelant aura la possibilité de capturer le paragraphe correspondant à "=cut" pour quelque raison que ce soit.

-warnings (défaut : non défini)
Normalement (par défaut), Pod::Parser reconnaît un minimum d'erreurs et d'avertissements dans la syntaxe POD et émet des messages diagnostiques pour les erreurs, mais pas pour les avertissements. (Utilisez Pod::Checker pour une vérification de syntaxe POD plus complète.) En définissant cette option sur une valeur non vide et non nulle, Pod::Parser émettra des messages diagnostiques pour les avertissements reconnus et les erreurs.

Veuillez consulter "parseopts()" pour une description complète de l'interface permettant de définir et d'annuler les options d'analyse.

REDÉFINITIONS DE FONCTIONS/MÉTHODES RECOMMANDÉES

Pod::Parser fournit plusieurs méthodes que les classes filles voudront probablement redéfinir. Ces méthodes sont les suivantes :

command()

$parser->command($cmd,$text,$line_num,$pod_para);

Cette méthode doit être redéfinie par les classes filles pour prendre l'action appropriée lorsqu'une ligne de paragraphe POD (indiquée par une ligne commençant par "=") est rencontrée. Lorsqu'une telle directive POD est rencontrée dans l'entrée, cette méthode est appelée et les paramètres suivants lui sont passés :

$cmd
le nom de la commande pour cette section POD
$text
le texte du paragraphe pour la commande POD de cette section
$line_num
le numéro de ligne de début du paragraphe
$pod_para
une référence à un objet de type "Pod::Paragraph" contenant plus d'informations sur la section de paragraphe de commande (voir Pod::InputObjects pour les détails).

La méthode command() est appelée lorsqu'une directive POD commençant par "=" est détectée. Lorsqu'elle est rencontrée dans l'entrée, cette méthode est appelée et les paramètres susmentionnés lui sont passés.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Nota

Notez que cette méthode est appelée pour les paragraphes "=pod".

L'implémentation de la classe de base de cette méthode traite simplement la commande textuelle "=pod" comme un bloc de texte de paragraphe normal (en appelant la méthode textblock() avec le paragraphe de commande).

verbatim()

$parser->verbatim($text,$line_num,$pod_para);

Cette méthode peut être redéfinie par les sous-classes pour prendre les mesures appropriées lorsqu'un bloc de texte verbatim est rencontré. Les paramètres suivants sont passés :

$text
le bloc de texte pour le paragraphe verbatim
$line_num
le numéro de ligne de départ du paragraphe
$pod_para
une référence à un objet "Pod::Paragraph" qui contient plus d'informations sur le paragraphe (voir Pod::InputObjects pour plus de détails).

L'implémentation de la classe de base de cette méthode imprime simplement le texte du bloc (sans modification) dans le fichier de sortie.

textblock()

$parser->textblock($text,$line_num,$pod_para);

Cette méthode peut être redéfinie par les sous-classes pour prendre les mesures appropriées lorsqu'un bloc de texte POD normal est rencontré (bien que l'implémentation de la classe de base de la méthode générale fera ce que vous voulez). Les paramètres suivants sont passés :

$text
le bloc de texte pour le paragraphe POD
$line_num
le numéro de ligne de départ du paragraphe
$pod_para
une référence à un objet "Pod::Paragraph" qui contient plus d'informations sur le paragraphe (voir Pod::InputObjects pour plus de détails).

Pour traiter les séquences internes, les implémentations de cette méthode des sous-classes voudront probablement d'abord appeler interpolate() ou parse_text(), en leur passant le bloc de texte $text, et le numéro de ligne correspondant $line_num, puis effectuer le traitement désiré sur le résultat retourné.

L'implémentation de la classe de base de cette méthode imprime simplement le bloc de texte tel qu'il est apparu dans le flux d'entrée.

interior_sequence()

$parser->interior_sequence($seq_cmd,$seq_arg,$pod_seq);

Cette méthode doit être redéfinie par les sous-classes pour prendre les mesures appropriées lorsqu'une séquence interne est rencontrée. Une séquence interne est une commande intégrée dans un bloc de texte qui apparaît comme un nom de commande (généralement une seule lettre majuscule) suivi immédiatement d'un texte entouré d'angles. Cette méthode est appelée avec la commande de séquence $seq_cmd et le texte correspondant $seq_arg. Elle est appelée par la méthode interpolate() pour chaque séquence interne qui apparaît dans la chaîne qui lui est passée. Elle doit retourner le texte désiré pour remplacer la séquence interne. Le paramètre $pod_seq est une référence à un objet "Pod::InteriorSequence" qui contient plus d'informations sur la séquence interne. Veuillez consulter Pod::InputObjects pour plus de détails si vous souhaitez accéder à ces informations supplémentaires.

Les implémentations de cette méthode des sous-classes peuvent vouloir appeler la méthode nested() de l'objet $pod_seq pour voir si elle est imbriquée dans une autre séquence interne (et si oui, de quel type).

L'implémentation de la classe de base de la méthode interior_sequence() retourne simplement le texte de la séquence interne (tel qu'il est apparu dans l'entrée) à l'appelant.

SOUS-PROGRAMME / MÉTHODES OPTIONNELS À REDÉFINIR

Pod::Parser fournit plusieurs méthodes que les sous-classes peuvent redéfinir pour effectuer tout prétraitement / posttraitement spécial. Ces méthodes ne doivent pas nécessairement être redéfinies, mais il peut être utile pour les sous-classes de les exploiter.

new()

my $parser = Pod::Parser->new();

C'est le constructeur de Pod::Parser et de ses sous-classes. Vous n'avez pas besoin de redéfinir cette méthode ! Elle est capable de construire des objets de sous-classe ainsi que des objets de classe de base, tant que vous utilisez l'un des styles d'invocation de constructeur suivants :

my $parser1 = MyParser->new();
my $parser2 = new MyParser();
my $parser3 = $parser2->new();

où "MyParser" est une sous-classe de Pod::Parser.

Utiliser la syntaxe MyParser::new() pour invoquer le constructeur n'est pas recommandé, mais si vous le souhaitez, alors la sous-classe devra redéfinir la méthode new() de l'objet nouvellement bénéficiaire. Si vous la redéfinissez, vous devez vous assurer d'appeler la méthode initialize() de l'objet nouvellement créé.

En utilisant l'une de ces invocations, le premier argument du constructeur est toujours le nom de la classe correspondante (ou une référence à un objet). Aucun autre argument n'est requis, mais si vous le souhaitez, vous pouvez passer un tableau associatif (ou une table de hachage) à la fonction new(), comme ceci :

my $parser1 = MyParser->new( MYDATA => $value1, MOREDATA => $value2 );
my $parser2 = new MyParser( -myflag => 1 );

Tous les arguments passés au constructeur new() sont traités comme des paires clé/valeur dans une table de hachage. L'objet nouvellement construit est initialisé en copiant le contenu de la table donnée (elle a pu être vide). Le constructeur new() de cette classe et de toutes ses sous-classes retourne une référence bénéficiaire à un objet initialisé (table de hachage).

initialize()

$parser->initialize();

Cette méthode effectue toute initialisation nécessaire pour l'objet. Elle n'accepte aucun argument (sauf l'objet instancié, qui est copié dans une variable locale nommée $self). Si les sous-classes redéfinissent cette méthode, elles doivent s'assurer d'appeler "$self->SUPER::initialize()".

begin_pod()

$parser->begin_pod();

Cette méthode est appelée au début du traitement de chaque document POD rencontré dans l'entrée. Les sous-classes doivent redéfinir cette méthode pour effectuer toute initialisation par document.

begin_input()

$parser->begin_input();

Cette méthode est appelée par parse_from_filehandle() avant le traitement du contenu d'un fichier. L'implémentation de la classe de base ne fait rien, mais les sous-classes peuvent la redéfinir pour effectuer toute initialisation par fichier.

Notez que si plusieurs fichiers sont traités pour un document POD (potentiellement suite à une directive "=include"), cette méthode est appelée pour chaque fichier traité. Si vous souhaitez effectuer certaines initialisations une fois par document, vous devriez alors utiliser begin_pod().

end_input()

$parser->end_input();

Cette méthode est appelée par parse_from_filehandle() après le traitement du contenu d'un fichier. L'implémentation de la classe de base ne fait rien, mais les sous-classes peuvent la redéfinir pour effectuer tout nettoyage par fichier.

Notez que si plusieurs fichiers sont traités pour un document POD (potentiellement suite à une directive "=include"), cette méthode est appelée pour chaque fichier traité. Si vous souhaitez effectuer certaines actions de nettoyage une fois par document, vous devriez alors utiliser end_pod().

end_pod()

$parser->end_pod();

Cette méthode est appelée à la fin du traitement de chaque document POD rencontré dans l'entrée. Les sous-classes doivent redéfinir cette méthode pour effectuer toute finalisation par document.

preprocess_line()

$textline = $parser->preprocess_line($text, $line_num);

Cette méthode doit être redéfinie par les sous-classes qui souhaitent effectuer tout type de pré-traitement pour chaque ligne d'entrée (avant qu'il ait été déterminé si elle fait partie d'un paragraphe POD). Le paramètre $text est la ligne d'entrée ; et le paramètre $line_num est le numéro de ligne correspondant à la ligne de texte.

La valeur retournée doit correspondre au nouveau texte à utiliser à la place. Si vous retournez une chaîne vide ou une valeur indéfinie, aucun traitement supplémentaire ne sera effectué pour cette ligne.

Notez que la méthode preprocess_line() est appelée avant la méthode preprocess_paragraph(). Après avoir rassemblé toutes les lignes d'un paragraphe (et après avoir déterminé son état de coupure), et après avoir confirmé que le paragraphe fait partie de la documentation POD à partir de l'une des sections sélectionnées, la méthode preprocess_paragraph() est appelée.

L'implémentation de la classe de base de cette méthode retourne le texte donné.

preprocess_paragraph()

$textblock = $parser->preprocess_paragraph($text, $line_num);

Cette méthode doit être redéfinie par les sous-classes qui souhaitent effectuer tout type de pré-traitement pour chaque bloc (paragraphe) de documentation POD qui apparaît dans le flux d'entrée. Le paramètre $text est le paragraphe POD du fichier d'entrée ; et le paramètre $line_num est le numéro de ligne correspondant au début du paragraphe.

La valeur retournée doit correspondre au nouveau texte à utiliser à la place. Si vous retournez une chaîne vide ou une valeur indéfinie, le texte donné $text est ignoré (non traité).

Cette méthode est appelée après avoir rassemblé toutes les lignes d'un paragraphe et après avoir déterminé son état de coupure, mais avant de tenter de les analyser ou de les interpréter. Après que preprocess_paragraph() retourne, l'état de coupure actuel (qui est retourné par "$self->cutting()") est examiné. S'il s'évalue à vrai, le texte d'entrée (y compris le texte donné $text) est coupé (non traité) jusqu'à ce que la prochaine directive POD soit rencontrée.

Notez que la méthode preprocess_line() est appelée avant la méthode preprocess_paragraph(). Après avoir rassemblé toutes les lignes (potentiellement prétraitées) d'un paragraphe et après avoir déterminé que le paragraphe fait partie de la documentation POD d'une des sections sélectionnées ou après avoir déterminé qu'une séquence interne se trouve dans le texte d'entrée, la méthode preprocess_paragraph() est appelée.

L'état de coupure actuel (qui est retourné par "$self->cutting()") est examiné. S'il s'évalue à vrai, le texte d'entrée (y compris le texte donné $text) est coupé (non traité) jusqu'à ce que la prochaine directive POD soit rencontrée.

MÉTHODES POUR L'ANALYSE ET LE TRAITEMENT

L'implémentation de cette méthode dans la classe de base renvoie le texte donné.

parse_text()

$ptree1 = $parser->parse_text($text, $line_num);
$ptree2 = $parser->parse_text({%opts}, $text, $line_num);
$ptree3 = $parser->parse_text(\%opts, $text, $line_num);

Cette méthode est utile si vous avez besoin de réaliser votre propre interpolation de séquences intérieures et que vous ne pouvez pas vous fier à la méthode interpolate pour les développer de bas en haut.

Le paramètre $text est une chaîne ou un bloc de texte à analyser pour les séquences intérieures ; et le paramètre $line_num est le numéro de ligne correspondant au début de $text.

parse_text() analysera le texte donné en un arbre d'analyse de "nœuds" et de séquences intérieures. Chaque "nœud" dans l'arbre d'analyse est une chaîne de texte ou un objet Pod::InteriorSequence. Le résultat renvoyé est un arbre d'analyse de type Pod::ParseTree. Veuillez consulter Pod::InputObjects pour plus d'informations sur Pod::InteriorSequence et Pod::ParseTree.

Si vous le souhaitez, un paramètre optionnel de type référence à une table de hachage peut être spécifié comme premier argument pour personnaliser certains aspects de l'arbre d'analyse créé et renvoyé. L'ensemble des mots-clés reconnus sont :

-expand_seq => code-ref|method-name
Normalement, l'arbre d'analyse renvoyé par parse_text() contiendra un objet "Pod::InteriorSequence" non développé pour chaque séquence intérieure trouvée. Spécifier -expand_seq indique à parse_text() de "développer" chaque séquence intérieure qu'il rencontre en appelant la fonction (ou méthode) référencée (ou méthode de l'objet parseur) et en utilisant la valeur renvoyée comme résultat développé.
-expand_text => code-ref|method-name
Normalement, l'arbre d'analyse renvoyé par parse_text() contiendra une chaîne de texte pour chaque séquence de caractères consécutifs en dehors d'une séquence intérieure. Spécifier -expand_text indique à parse_text() de "prétraiter" chaque chaîne de texte de ce type en appelant la fonction (ou méthode) référencée (ou méthode de l'objet parseur) et en utilisant la valeur renvoyée comme résultat prétraité (ou "développé"). [Note : Si le résultat est une séquence intérieure, elle ne sera pas développée comme spécifié par l'option -expand_seq ; tout développement récursif de ce type doit être géré par la routine de rappel spécifiée.]

Si une référence à une sous-routine a été fournie, elle sera appelée comme suit :

&$code_ref( $parser, $sequence )

et si un nom de méthode a été fourni, il sera appelé comme suit :

$parser->method_name( $sequence )

où $parser est une référence à l'objet parseur, et $sequence est une référence à l'objet séquence intérieure. [NOTE : Si la méthode interior_sequence() est spécifiée, elle sera appelée selon l'interface spécifiée dans "interior_sequence()".]

-expand_ptree => code-ref|method-name
Au lieu de renvoyer un "Pod::ParseTree", passe l'arbre d'analyse comme argument à la sous-routine (ou méthode) référencée (ou méthode de l'objet parseur) et renvoie le résultat à la place de l'objet d'analyse.

Si une référence à une sous-routine a été fournie, elle sera appelée comme suit :

&$code_ref( $parser, $ptree )

et si un nom de méthode a été fourni, il sera appelé comme suit :

$parser->method_name( $ptree )

où $parser est une référence à l'objet parseur, et $ptree est une référence à l'objet d'analyse.

interpolate()

$textblock = $parser->interpolate($text, $line_num);

Cette méthode traduit tout le texte (y compris toute séquence intérieure intégrée) dans la chaîne de texte donnée $text et renvoie le résultat interpolé. Le paramètre $line_num est le numéro de ligne correspondant au début de $text.

La méthode interpolate() appelle une méthode privée pour développer les séquences intérieures imbriquées de bas en haut (la séquence la plus interne en premier). Si vous avez besoin de développer des séquences imbriquées dans un ordre différent, utilisez parse_text à la place.

parse_from_filehandle()

$parser->parse_from_filehandle($in_fh,$out_fh);

Cette méthode prend un fichier d'entrée (supposé déjà ouvert en lecture) et lit le flux complet à la recherche de blocs (paragraphes) de documentation POD à traiter. Si le premier argument n'est pas fourni, le fichier d'entrée "STDIN" est utilisé par défaut.

Le paramètre $in_fh peut être tout objet fournissant une méthode getline() pour obtenir une ligne de texte d'entrée (ainsi, un objet approprié pourrait être utilisé pour analyser les documents POD à partir d'une seule chaîne ou d'une liste de chaînes).

En utilisant "$in_fh->getline()", le texte est lu ligne par ligne et construit en paragraphes ou blocs (qui sont séparés par des lignes ne contenant que des espaces blancs). Chaque bloc de documentation POD fait l'objet d'un appel à une méthode pour analyser le paragraphe donné.

Si un deuxième argument est fourni, il doit correspondre à un fichier de sortie où le texte doit être envoyé. Si un deuxième argument n'est pas fourni, le fichier de sortie "STDOUT" est utilisé par défaut s'il n'y a pas de fichier de sortie.

NOTE : Pour des raisons de performance, cette méthode conserve le flux d'entrée dans une variable locale au sommet de la pile. Toute tentative par les clients de modifier le contenu de la pile pendant le traitement, pendant l'exécution de cette méthode, n'affectera pas le flux d'entrée utilisé par l'appel actuel de la méthode.

Cette méthode n'a généralement pas besoin d'être redéfinie par les sous-classes.

parse_from_file()

$parser->parse_from_file($filename,$outfile);

Cette méthode prend un nom de fichier et effectue les actions suivantes :

  • ouvre les fichiers d'entrée et de sortie en lecture (crée les descripteurs appropriés).
  • appelle la méthode parse_from_filehandle() en lui passant les descripteurs d'entrée et de sortie correspondants.
  • ferme les fichiers d'entrée et de sortie.

Si le nom de fichier spécial "" ou "-" ou "<&STDIN" est fourni, le descripteur d'entrée STDIN est utilisé (et aucune ouverture ou fermeture n'est effectuée). Si aucun nom de fichier d'entrée n'est spécifié, "-" est implicite. Des références à des fichiers ou des objets prenant en charge les opérations d'E/S régulières (comme "<$fh>" ou "$fh-<Egt"getline>) sont également acceptées ; les descripteurs doivent déjà être ouverts.

Si un deuxième argument est fourni, il doit s'agir du nom du fichier de sortie souhaité. Si le nom de fichier de sortie spécial "-" ou ">&STDOUT" est fourni, le descripteur de sortie STDOUT est utilisé (et aucune ouverture ou fermeture n'est effectuée). Si le nom de fichier de sortie spécial ">&STDERR" est fourni, le descripteur d'erreur STDERR est utilisé (et aucune ouverture ou fermeture n'est effectuée). Si aucun fichier de sortie n'est utilisé et aucun nom de fichier de sortie n'est spécifié, "-" est implicite. Alternativement, des références à des fichiers ou des objets prenant en charge les opérations d'E/S régulières (comme "print", par exemple, IO::String) sont également acceptées ; les objets doivent déjà être ouverts.

Cette méthode n'a généralement pas besoin d'être redéfinie par les sous-classes.

MÉTHODES D'ACCÈS

Les clients de Pod::Parser doivent utiliser les méthodes suivantes pour accéder aux champs de données des instances :

errorsub()

$parser->errorsub("method_name");
$parser->errorsub(\&warn_user);
$parser->errorsub(sub { print STDERR, @_ });

Définit la sous-routine ou la méthode à utiliser pour afficher les messages d'erreur concernant la syntaxe POD. La méthode/sous-routine fournie *doit* renvoyer TRUE lors de l'affichage réussi du message. Si "undef" est fourni, le builtin carp est utilisé pour émettre les messages d'erreur (c'est le comportement par défaut).

my $errorsub = $parser->errorsub();
my $errmsg = "This is an error message!\n";
(ref $errorsub) and &{$errorsub}($errmsg)
    or (defined $errorsub) and $parser->$errorsub($errmsg)
        or  carp($errmsg);

Renvoie un nom de méthode, ou une référence à la sous-routine fournie par le client pour afficher les messages d'erreur. Renvoie "undef" si le builtin carp est utilisé pour émettre les messages d'erreur (c'est le comportement par défaut).

cutting()

$boolean = $parser->cutting();

Renvoie l'état actuel de "cutting" : un scalaire booléen qui renvoie TRUE si le texte d'entrée est en cours de "coupe" (c'est-à-dire qu'il n'est pas considéré comme faisant partie du document POD).

$parser->cutting($boolean);

Définit l'état actuel de "cutting" aux valeurs données et renvoie le résultat.

parseopts()

Lorsqu'il est appelé avec des arguments supplémentaires, parseopts renvoie une table d'association contenant toutes les options d'analyse actuelles.

## Vérifier si nous analysons les sections non-POD ainsi que les POD
my %opts = $parser->parseopts();
$opts{'-want_nonPODs}' and print "-want_nonPODs\n";

Lorsqu'il est appelé avec une seule chaîne, parseopts traite la chaîne comme le nom d'une option d'analyse et renvoie sa valeur correspondante si elle existe (renvoie "undef" si elle n'existe pas).

## Demandons-nous de voir les paragraphes =cut ?
my $want_cut = $parser->parseopts('-process_cut_cmd');
$want_cut and print "-process_cut_cmd\n";

Lorsqu'il est appelé avec plusieurs arguments, parseopts les traite comme des paires clé-valeur et définit les valeurs spécifiées pour les options d'analyse mentionnées. Les options non spécifiées ne sont pas affectées.

## Revenir aux valeurs par défaut
$parser->parseopts(-warnings => 0);

Lorsqu'une référence de hachage unique est passée, parseopts utilise cette hachage pour réinitialiser complètement les options d'analyse actuelles ; toutes les valeurs précédentes des options d'analyse sont perdues.

## Réinitialiser toutes les options aux valeurs par défaut
$parser->parseopts( { } );

Voir « OPTIONS D'ANALYSE » pour plus d'informations sur le nom et la signification de chaque option d'analyse actuellement reconnue.

output_file()

$fname = $parser->output_file();

Renvoie le nom du fichier de sortie en cours d'écriture.

output_handle()

$fhandle = $parser->output_handle();

Renvoie le descripteur de fichier de sortie.

input_file()

$fname = $parser->input_file();

Renvoie le nom du fichier d'entrée en cours de lecture.

input_handle()

$fhandle = $parser->input_handle();

Renvoie le descripteur de fichier d'entrée actuel.

MÉTHODES ET DONNÉES PRIVÉES

Pod::Parser utilise plusieurs méthodes et champs de données internes que les clients ne sont pas censés voir ou utiliser. Afin d'éviter les collisions de noms pour les données et méthodes des clients, ces méthodes et champs sont brièvement discutés ici. Les hackers déterminés peuvent en apprendre davantage en lisant le code source de Pod::Parser.

Les champs de données privés sont stockés dans l'objet de hachage dont le pointeur est renvoyé par le constructeur new() de cette classe. Les noms de toutes les méthodes et de tous les champs de données privés utilisés par Pod::Parser commencent par un préfixe « _ » et correspondent au modèle régulier "/^_\w+$/".

ANALYSE BASÉE SUR LES ARBRES

Si l'analyse basée sur les flux ne répond pas à vos besoins (ce qui est probable pour des tâches telles que la conversion de POD en balisage structuré comme HTML ou XML), vous pourriez avoir besoin d'adopter une approche basée sur les arbres. Au lieu de tout effectuer en une seule passe et d'appeler la méthode interpolate() pour développer les séquences en texte, il pourrait être souhaitable de créer un arbre d'analyse à l'aide de la méthode parse_text() pour renvoyer une structure arborescente qui peut contenir une liste ordonnée d'enfants (chacun pouvant être une chaîne de texte ou une structure arborescente similaire).

Vous devez prêter une attention particulière aux méthodes d'analyse et de traitement décrites dans « MÉTHODES D'ANALYSE ET DE TRAITEMENT » et aux objets décrits dans Pod::InputObjects. Le premier décrit les détails et les paramètres pour personnaliser et étendre le comportement de Pod::Parser. Pod::InputObjects fournit divers objets qui peuvent être utilisés de manière interchangeable comme structures d'analyse. L'objet le plus évident est Pod::ParseTree. Il définit l'interface de base et les fonctionnalités que tous les éléments qui tentent d'être un arbre d'analyse doivent posséder. Un Pod::ParseTree est défini de telle manière que chaque « nœud » peut être une chaîne de texte ou une référence vers un autre arbre d'analyse. Chaque objet Pod::Paragraph et chaque objet Pod::InteriorSequence prend également en charge l'interface d'arbre d'analyse de base.

La méthode parse_text() prend un paragraphe de texte donné et renvoie un arbre d'analyse contenant un ou plusieurs enfants, chacun pouvant être une chaîne de texte ou un objet InteriorSequence. Il existe également des options de rappel qui peuvent être transmises à la méthode parse_text() pour personnaliser la manière dont elle développe ou transforme les séquences intérieures, ainsi que le résultat renvoyé. Ces rappels peuvent être utilisés pour créer un arbre d'analyse avec des objets personnalisés (qui peuvent ou non prendre en charge l'interface d'arbre d'analyse, selon votre choix).

Si vous souhaitez convertir un document POD complet en un arbre d'analyse, ce processus est assez simple. La méthode parse_text() est la clé pour y parvenir. Chaque rappel de paragraphe (c'est-à-dire les méthodes polymorphiques command(), verbatim() et textblock()) prend un objet Pod::Paragraph comme argument. Chaque objet paragraphe a une méthode parse_tree() qui peut être utilisée pour obtenir ou définir un arbre d'analyse correspondant. Ainsi, pour chacune de ces méthodes de rappel de paragraphe, appelez simplement la méthode parse_text() avec les options souhaitées, puis utilisez l'arbre d'analyse renvoyé pour l'attribuer à l'objet paragraphe donné.

Vous obtenez ainsi un arbre d'analyse pour chaque paragraphe - il ne vous reste plus qu'une liste ordonnée de paragraphes. Vous pouvez la conserver vous-même comme élément de données dans l'objet/la hachage. La méthode la plus simple serait simplement d'utiliser une référence de tableau, avec les valeurs souhaitées des options personnalisées pour chaque appel de parse_text. Supposons que l'ensemble d'options souhaité soit donné par la hachage %options. Nous pourrions alors faire quelque chose comme ceci :

package MyPodParserTree;
@ISA = qw( Pod::Parser );
...
sub begin_pod {
    my $self = shift;
    $self->{'-paragraphs'} = [];  ## initialiser la liste des paragraphes
}
sub command { 
    my ($parser, $command, $paragraph, $line_num, $pod_para) = @_;
    my $ptree = $parser->parse_text({%options}, $paragraph, ...);
    $pod_para->parse_tree( $ptree );
    push @{ $self->{'-paragraphs'} }, $pod_para;
}
sub verbatim { 
    my ($parser, $paragraph, $line_num, $pod_para) = @_;
    push @{ $self->{'-paragraphs'} }, $pod_para;
}
sub textblock { 
    my ($parser, $paragraph, $line_num, $pod_para) = @_;
    my $ptree = $parser->parse_text({%options}, $paragraph, ...);
    $pod_para->parse_tree( $ptree );
    push @{ $self->{'-paragraphs'} }, $pod_para;
}
...
package main;
...
my $parser = new MyPodParserTree(...);
$parser->parse_from_file(...);
my $paragraphs_ref = $parser->{'-paragraphs'};

Bien que, selon l'auteur de ce module, je préférerais utiliser l'objet Pod::ParseTree existant au lieu d'une simple référence de tableau. Ainsi, tout ce qu'il contient, paragraphes et séquences, répond à la même interface de base pour tous les nœuds de l'arbre d'analyse. Le résultat serait quelque chose comme ceci :

package MyPodParserTree2;
...
sub begin_pod {
    my $self = shift;
    $self->{'-ptree'} = new Pod::ParseTree;  ## initialiser l'arbre d'analyse
}
sub parse_tree {
    ## méthode d'accès pour obtenir/définir l'arbre d'analyse pour l'ensemble du POD
    (@_ > 1)  and  $_[0]->{'-ptree'} = $_[1];
    return $_[0]->{'-ptree'};
}
sub command { 
    my ($parser, $command, $paragraph, $line_num, $pod_para) = @_;
    my $ptree = $parser->parse_text({<<options>>}, $paragraph, ...);
    $pod_para->parse_tree( $ptree );
    $parser->parse_tree()->append( $pod_para );
}
sub verbatim { 
    my ($parser, $paragraph, $line_num, $pod_para) = @_;
    $parser->parse_tree()->append( $pod_para );
}
sub textblock { 
    my ($parser, $paragraph, $line_num, $pod_para) = @_;
    my $ptree = $parser->parse_text({<<options>>}, $paragraph, ...);
    $pod_para->parse_tree( $ptree );
    $parser->parse_tree()->append( $pod_para );
}
...
package main;
...
my $parser = new MyPodParserTree2(...);
$parser->parse_from_file(...);
my $ptree = $parser->parse_tree;
...

Vous avez maintenant le document POD complet sous la forme d'un grand arbre d'analyse. Vous pouvez même utiliser l'option -expand_seq dans parse_text pour insérer des objets complètement différents. Ne vous attendez pas à ce que Pod::Parser sache quoi faire avec eux par la suite. Cela devra être dans votre code. Alternativement, vous pouvez insérer tout objet qui répond à l'interface Pod::ParseTree.

On pourrait l'utiliser pour créer des classes filles de Pod::Paragraphs et Pod::InteriorSequences pour des commandes spécifiques (ou créer vos propres nœuds de type personnalisés dans l'arbre) et ajouter une méthode emit() à chaque objet nœud/classe personnalisé. Ainsi, la seule chose que vous auriez à faire serait de parcourir récursivement l'arbre dans l'ordre souhaité, en traitant les enfants (probablement de gauche à droite) s'il s'agit de chaînes de texte, ou en appelant leur méthode emit() s'il s'agit d'objets/références.

MISE EN GARDE

Remarque : Le POD a la notion de « paragraphes » : c'est quelque chose qui commence *après* une ligne vide (c'est-à-dire vide), à l'exception du début du fichier, qui commence également un paragraphe. Cela signifie notamment qu'une commande (par exemple, "=head1") *doit* être précédée d'une ligne vide ; "__END__" n'est pas une ligne vide.

VOIR AUSSI

Pod::InputObjects, Pod::Select

Pod::InputObjects définit les objets d'entrée POD correspondant aux paragraphes de commande, aux arbres d'analyse et aux séquences intérieures.

Pod::Select est une sous-classe de Pod::Parser qui offre la possibilité d'inclure ou d'exclure des parties spécifiques d'un document POD en fonction du titre, sous-titre, sous-sous-titre, etc. actuel.
