POE::Filter::Map(3) Documentation Perl fournie par l'utilisateur POE::Filter::Map(3)

NOM

POE::Filter::Map - transformer l'entrée et/ou la sortie au sein d'une pile de filtres

SYNOPIS

#!perl
use POE qw(
  Wheel::FollowTail
  Filter::Line Filter::Map Filter::Stackable
);
POE::Session->create(
  inline_states => {
    _start => sub {
      my $parse_input_as_lines = POE::Filter::Line->new();
      my $redact_some_lines = POE::Filter::Map->new(
        Code => sub {
          my $input = shift;
          $input = "[REDACTED]" unless $input =~ /sudo\[\d+\]/i;
          return $input;
        },
      );
      my $filter_stack = POE::Filter::Stackable->new(
        Filters => [
          $parse_input_as_lines, # premier à la réception, dernier à l'envoi
          $redact_some_lines, # premier à l'envoi, dernier à la réception
        ]
      );
      $_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
        Filename => "/var/log/system.log",
        InputEvent => "got_log_line",
        Filter => $filter_stack,
      );
    },
    got_log_line => sub {
      print "Log: $_[ARG0]\n";
    }
  }
);
POE::Kernel->run();
exit;

DESCRIPTION

POE::Filter::Map transforme les données à l'intérieur de la pile de filtres. Il peut être utilisé pour transformer l'entrée, la sortie, ou les deux selon la façon dont il est construit. Ce filtre est nommé et calqué sur la fonction intégrée map() de Perl.

POE::Filter::Map est conçu pour être combiné avec d'autres filtres via POE::Filter::Stackable. Dans l'exemple de la "SYNOPSIS", une pile de filtres est créée pour analyser les journaux sous forme de lignes et pour rediger toutes les entrées qui ne concernent pas un processus sudo.

MÉTHODES PUBLIQUES DU FILTRE

En plus des méthodes habituelles de POE::Filter, POE::Filter::Map prend également en charge les suivantes.

new

new() construit un nouvel objet POE::Filter::Map. Il doit soit être appelé avec un seul paramètre Code, soit avec les deux paramètres Put et Get. Les valeurs pour Code, Put et Get sont des références de code qui, lorsqu'elles sont invoquées, retournent des versions transformées de leurs paramètres uniques. Une fonction Code sera utilisée pour l'entrée et la sortie, tandis que les fonctions Get et Put permettent de filtrer l'entrée et la sortie de différentes manières.

# Décrypter rot13.
sub decrypt_rot13 {
  my $encrypted = shift;
  $encrypted =~ tr[a-zA-Z][n-za-mN-ZA-M];
  return $encrypted;
}
# Crypter rot13.
sub encrypt_rot13 {
  my $plaintext = shift;
  $plaintext =~ tr[a-zA-Z][n-za-mN-ZA-M];
  return $plaintext;
}
# Décrypter rot13 à la réception, et le crypter à l'envoi.
my $rot13_transcrypter = POE::Filter::Map->new(
  Get => \&decrypt_rot13,
  Put => \&encrypt_rot13,
);

Rot13 est symétrique, donc l'exemple ci-dessus peut être simplifié pour utiliser une seule fonction Code.

my $rot13_transcrypter = POE::Filter::Map->new(
  Code => sub {
    local $_ = shift;
    tr[a-zA-Z][n-za-mN-ZA-M];
    return $_;
  }
);

modify

modify() modifie le comportement d'un objet POE::Filter::Map à l'exécution. Il accepte les mêmes paramètres que new() et remplace les transformations existantes par de nouvelles.

# Passer au chiffrement "inversé" pour les tests.
$rot13_transcrypter->modify(
  Code => sub { return scalar reverse shift }
);
