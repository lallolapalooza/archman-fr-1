POE::Filter::Stackable(3) Documentation Perl fournie par l'utilisateur POE::Filter::Stackable(3)

NOM

POE::Filter::Stackable - combiner plusieurs objets POE::Filter

SYNOPIS

#!perl
use POE qw(
  Wheel::FollowTail
  Filter::Line Filter::Grep Filter::Stackable
);
POE::Session->create(
  inline_states => {
    _start => sub {
      my $parse_input_as_lines = POE::Filter::Line->new();
      my $select_sudo_log_lines = POE::Filter::Grep->new(
        Put => sub { 1 },
        Get => sub {
          my $input = shift;
          return $input =~ /sudo\[\d+\]/i;
        },
      );
      my $filter_stack = POE::Filter::Stackable->new(
        Filters => [
          $parse_input_as_lines, # premier sur get, dernier sur put
          $select_sudo_log_lines, # premier sur put, dernier sur get
        ]
      );
      $_[HEAP]{tailor} = POE::Wheel::FollowTail->new(
        Filename => "/var/log/system.log",
        InputEvent => "got_log_line",
        Filter => $filter_stack,
      );
    },
    got_log_line => sub {
      print "Log: $_[ARG0]\n";
    }
  }
);
POE::Kernel->run();
exit;

DESCRIPTION

POE::Filter::Stackable combine plusieurs filtres de telle sorte qu'ils apparaissent comme un seul filtre. Toutes les méthodes habituelles de POE::Filter fonctionnent, mais les données sont secrètement transmises à travers les filtres empilés avant d'être retournées. Les objets POE::Wheel et les programmes autonomes n'ont pas besoin de modifications pour fonctionner avec une pile de filtres.

Dans la "SYNOPIS", POE::Filter::Line et POE::Filter::Grep sont combinés en un seul filtre qui ne retourne qu'un type particulier de ligne. Cela peut être plus efficace que de filtrer les lignes dans l'espace applicatif, car moins d'événements peuvent avoir besoin d'être dispatchés et traités.

Internement, les filtres sont stockés dans un tableau.

Les données ajoutées par get_one_start() circuleront dans le tableau de filtres dans l'ordre d'index croissant. Le filtre n°0 aura la première occasion de traiter les données, suivi du filtre n°1, et ainsi de suite. L'appel get_one() retournera un élément après qu'il ait traversé le dernier filtre.

put() transmet les données à travers les filtres dans l'ordre d'index décroissant. Les données passeront d'abord par le filtre avec l'indice le plus élevé, et put() retournera les résultats après que les données aient traversé le filtre n°0.

MÉTHODES PUBLIQUES DE FILTRE

En plus des méthodes habituelles de POE::Filter, POE::Filter::Stackable supporte également les méthodes suivantes.

new

Par défaut, new() crée une pile de filtres vide qui se comporte comme POE::Filter::Stream. Il peut recevoir des paramètres optionnels pour initialiser la pile avec un tableau de filtres.

my $sudo_lines = POE::Filter::Stackable->new(
  Filters => [
    POE::Filter::Line->new(),
    POE::Filter::Grep->new(
      Put => sub { 1 }, # met tous les éléments
      Get => sub { shift() =~ /sudo\[\d+\]/i },
    ),
  ]
);

pop

Se comporte comme la fonction intégrée pop() de Perl pour la pile de filtres. Le filtre avec l'indice le plus élevé est retiré de la pile et retourné. Toutes les données restantes dans le tampon d'entrée du filtre sont perdues, mais une application peut toujours appeler "get_pending" dans POE::Filter sur le filtre retourné.

my $last_filter = $stackable->pop();
my $last_buffer = $last_filter->get_pending();

shift

Se comporte comme la fonction intégrée shift() de Perl pour la pile de filtres. Le filtre n°0 est retiré de la pile et retourné. Toutes les données restantes dans le tampon d'entrée du filtre sont transmises au nouveau début de la pile, ou elles sont perdues si la pile devient vide. Une application peut également appeler "get_pending" dans POE::Filter sur le filtre retourné pour examiner le tampon d'entrée du filtre.

my $first_filter = $stackable->shift();
my $first_buffer = $first_filter->get_pending();

push FILTRE[, FILTRE]

push() ajoute un ou plusieurs nouveaux FILTREs à la fin de la pile. Les FILTREs nouvellement ajoutés traiteront l'entrée en dernier, et ils géreront la sortie en premier.

# Inverse les données lues à travers la pile.
# Encode les données rot13 envoyées à travers la pile.
$stackable->push(
  POE::Filter::Map->(
    Get => sub { return scalar reverse shift() },
    Put => sub { local $_ = shift(); tr[a-zA-Z][n-za-mN-ZA-M]; $_ },
  )
);

unshift FILTRE[, FILTRE]

unshift() ajoute un ou plusieurs nouveaux FILTREs au début de la pile. Les FILTREs nouvellement ajoutés au début traiteront l'entrée en premier, et ils géreront la sortie en dernier.

filters

filters() retourne une liste des filtres à l'intérieur du filtre Stackable, dans l'ordre natif de la pile.

Appeler "$filter_stack->filters()" dans la "SYNOPIS" retournerait une liste de deux objets filtres:

POE::Filter::Line=ARRAY(0x8b5ee0)
POE::Filter::Grep=ARRAY(0x8b5f7c)

filter_types

filter_types() retourne une liste des noms de classes pour chaque filtre dans la pile, dans l'ordre natif de la pile.

Appeler "$filter_stack->filter_types()" dans la "SYNOPIS" retournerait une liste de deux noms de classes:

POE::FIlter::Line
POE::Filter::Grep

Il pourrait facilement être remplacé par:

my @filter_types = map { ref } $filter_stack->filters;
