NOM

WWW::Mechanize - Navigation web pratique dans un objet Perl

VERSION

version 2.20

SYNOPSIS

WWW::Mechanize permet d'effectuer une séquence de récupérations de pages, y compris le suivi des liens et la soumission de formulaires. Chaque page récupérée est analysée et ses liens et formulaires sont extraits. Un lien ou un formulaire peut être sélectionné, les champs du formulaire peuvent être remplis et la page suivante peut être récupérée. Mech stocke également un historique des URL que vous avez visitées, qui peut être consulté et revisité.

use WWW::Mechanize ();
my $mech = WWW::Mechanize->new();
$mech->get( $url );
$mech->follow_link( n => 3 );
$mech->follow_link( text_regex => qr/télécharger ceci/i );
$mech->follow_link( url => 'http://host.com/index.html' );
$mech->submit_form(
    form_number => 3,
    fields      => {
        username    => 'mungo',
        password    => 'lost-and-alone',
    }
);
$mech->submit_form(
    form_name => 'search',
    fields    => { query  => 'pot of gold', },
    button    => 'Search Now'
);
# Activer le traitement strict des formulaires pour détecter les fautes de frappe et les champs de formulaire inexistants.
my $strict_mech = WWW::Mechanize->new( strict_forms => 1);
$strict_mech->get( $url );
# Cet appel de méthode échouera, vous faisant gagner beaucoup de temps pour trouver le bug.
$strict_mech->submit_form(
    form_number => 3,
    fields      => {
        usernaem     => 'mungo',           # faute de frappe dans le nom du champ
        password     => 'lost-and-alone',
        extra_field  => 123,               # champ inexistant
    }
);

DESCRIPTION

"WWW::Mechanize", ou Mech pour faire court, est un module Perl pour la navigation web programmatique avec état, utilisé pour automatiser l'interaction avec des sites web.

Les fonctionnalités incluent :

  • Toutes les méthodes HTTP
  • Support de haut niveau pour les hyperliens et les formulaires HTML, sans avoir à analyser le HTML vous-même
  • Support SSL
  • Cookies automatiques
  • En-têtes HTTP personnalisés
  • Gestion automatique des redirections
  • Proxys
  • Authentification HTTP

Mech est bien adapté pour être utilisé dans le test d'applications web. Si vous utilisez l'un des modules Test::*, comme Test::HTML::Lint, vous pouvez vérifier le contenu récupéré et l'utiliser comme entrée pour un appel de test.

use Test::More;
like( $mech->content(), qr/$expected/, "Got expected content" );

Chaque récupération de page stocke son URL dans une pile d'historique que vous pouvez parcourir.

$mech->back();

Si vous souhaitez un contrôle plus fin sur vos récupérations de pages, vous pouvez utiliser ces méthodes. follow_link() et submit_form() ne sont que des enveloppes de haut niveau autour d'elles.

$mech->find_link( n => $number );
$mech->form_number( $number );
$mech->form_name( $name );
$mech->field( $name, $value );
$mech->set_fields( %field_values );
$mech->set_visible( @criteria );
$mech->click( $button );

WWW::Mechanize est une sous-classe appropriée de LWP::UserAgent et vous pouvez également utiliser n'importe laquelle des méthodes de LWP::UserAgent.

$mech->add_header($name => $value);

Veuillez noter que Mech ne prend PAS en charge JavaScript, vous avez besoin d'un logiciel supplémentaire pour cela. Veuillez consulter "JavaScript" dans WWW::Mechanize::FAQ pour plus d'informations.

CONSTRUCTEUR ET DÉMARRAGE

new()

Crée et retourne un nouvel objet WWW::Mechanize, ci-après dénommé l'"agent".

my $mech = WWW::Mechanize->new()

Le constructeur de WWW::Mechanize surcharge deux des paramètres du constructeur LWP::UserAgent :

agent => 'WWW-Mechanize/#.##'
cookie_jar => {}    # un objet HTTP::Cookies vide, en mémoire uniquement

Vous pouvez outrepasser ces surcharges en passant des paramètres au constructeur, comme suit :

my $mech = WWW::Mechanize->new( agent => 'wonderbot 1.01' );

Si vous ne voulez aucune surcharge d'un cookie jar, ou si vous ne voulez pas que votre bot accepte les cookies, vous devez explicitement le désactiver, comme ceci :

my $mech = WWW::Mechanize->new( cookie_jar => undef );

Voici les paramètres que WWW::Mechanize reconnaît. Ceux-ci n'incluent pas les paramètres reconnus par LWP::UserAgent.

  • "autocheck => [0|1]"

    Vérifie chaque requête effectuée pour voir si elle a réussi. Cela vous évite de devoir vérifier manuellement. Toute erreur trouvée est une erreur, pas un avertissement.

    La valeur par défaut est ACTIVÉE, sauf si elle est sous-classée, auquel cas elle est DÉSACTIVÉE. Cela signifie que les instances WWW::Mechanize autonomes ont autocheck activé, ce qui est protecteur pour la grande majorité des utilisateurs de Mech qui ne prennent pas la peine de vérifier la valeur de retour de get() et post() et qui ne comprennent pas pourquoi leur code échoue. Cependant, si WWW::Mechanize est sous-classé, comme pour Test::WWW::Mechanize ou Test::WWW::Mechanize::Catalyst, ce n'est peut-être pas un défaut approprié, donc il est désactivé.

  • "noproxy => [0|1]"

    Désactive l'appel automatique à la fonction "env_proxy" de LWP::UserAgent.

    Ceci doit être explicitement désactivé si vous utilisez Crypt::SSLeay pour accéder à un site https via un serveur proxy. Remarque : vous devez toujours définir votre variable d'environnement HTTPS_PROXY de manière appropriée.

  • "onwarn => \&func"

    Référence à une fonction compatible "warn", telle que "Carp::carp", qui est appelée lorsqu'un avertissement doit être affiché.

    Si ceci est défini sur "undef", aucun avertissement ne sera jamais affiché. Cependant, il est probablement préférable d'utiliser la méthode "quiet" pour contrôler ce comportement.

    Si cette valeur n'est pas passée, Mech utilise "Carp::carp" si Carp est installé, ou "CORE::warn" sinon.

  • "onerror => \&func"

    Référence à une fonction compatible "die", telle que "Carp::croak", qui est appelée en cas d'erreur fatale.

    Si ceci est défini sur "undef", aucune erreur ne sera jamais affichée.

    Si cette valeur n'est pas passée, Mech utilise "Carp::croak" si Carp est installé, ou "CORE::die" sinon.

  • "quiet => [0|1]"

    Ne pas se plaindre des avertissements. Définir "quiet => 1" équivaut à appeler "$mech->quiet(1)". Par défaut, c'est désactivé.

  • &qu

CONFIGURATION OPTIONS

WWW::Mechanize offers a number of options that can be passed to its constructor or set on the object using the option() method. These include:

  • "stack_depth => $value"

    Définit la profondeur de la pile de pages qui garde une trace de toutes les pages téléchargées. La valeur par défaut correspond à une taille de pile infinie. Si la pile consomme trop de mémoire, définissez cette valeur sur un nombre plus petit, par exemple 5 ou 10. La définir sur zéro signifie que Mech ne conservera aucune historique.

De plus, WWW::Mechanize vous permet d'activer globalement les modes strict et verbeux pour la gestion des formulaires, ce qui est fait avec HTML::Form.

  • "strict_forms => [0|1]"

    Définit globalement le drapeau strict de HTML::Form, ce qui provoque un croak lors de la soumission d'un formulaire si l'un des champs passés n'existe pas dans le formulaire, et/ou si une valeur n'existe pas dans un élément de sélection. Ceci peut toujours être désactivé dans des appels individuels à submit_form().

    Par défaut, désactivé.

  • "verbose_forms => [0|1]"

    Définit globalement le drapeau verbeux de HTML::Form, ce qui provoque un avertissement lors de la soumission d'un formulaire à propos de toute mauvaise construction de formulaire HTML rencontrée. Ceci ne peut pas être désactivé ultérieurement.

    Par défaut, désactivé.

  • "marked_sections => [0|1]"

    Définit globalement le drapeau des sections marquées de HTML::Parser, ce qui permet de respecter les sections CDATA de HTML « CDATA[[ ». Ceci ne peut pas être désactivé ultérieurement.

    Par défaut, activé.

Pour prendre en charge les formulaires, le constructeur de WWW::Mechanize ajoute POST à la liste "requests_redirectable" de l'agent (voir aussi LWP::UserAgent.)

$mech->agent_alias( $alias )

Définit la chaîne de l'agent utilisateur sur la version étendue à partir d'une table de chaînes d'agents réels. $alias peut être l'une des suivantes :

  • Windows IE 6
  • Windows Mozilla
  • Mac Safari
  • Mac Mozilla
  • Linux Mozilla
  • Linux Konqueror

alors elle sera remplacée par une plus intéressante. Par exemple,

$mech->agent_alias( 'Windows IE 6' );

définit votre User-Agent sur

Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1)

La liste des alias valides peut être obtenue via known_agent_aliases(). La liste actuelle est :

  • Windows IE 6
  • Windows Mozilla
  • Mac Safari
  • Mac Mozilla
  • Linux Mozilla
  • Linux Konqueror

$mech->known_agent_aliases()

Retourne une liste de tous les alias d'agent que Mech connaît. Ceci peut également être appelé en tant que méthode de paquet ou de classe.

@aliases = WWW::Mechanize::known_agent_aliases();
@aliases = WWW::Mechanize->known_agent_aliases();
@aliases = $mech->known_agent_aliases();

MÉTHODES DE RÉCUPÉRATION DE PAGE

$mech->get( $uri )

Étant donné une URL/URI, la récupère. Renvoie un objet HTTP::Response. $uri peut être une chaîne d'URL bien formée, un objet URI ou un objet WWW::Mechanize::Link.

Les résultats sont stockés en interne dans l'objet agent, mais vous n'avez pas à le savoir. Utilisez simplement les accesseurs listés ci-dessous. Explorer les détails internes est déprécié et sujet à changement dans le futur.

get() est une version surchargée bien comportée de la méthode de LWP::UserAgent. Cela vous permet de faire des choses comme

$mech->get( $uri, ':content_file' => $filename );

et vous pouvez être assuré que les paramètres seront correctement filtrés. Voir "get" dans LWP::UserAgent pour plus de détails.

NOTE : Le fichier dans ":content_file" contiendra le contenu brut de la réponse. Si le contenu de la réponse est encodé (par exemple, encodé en gzip), le fichier sera également encodé. Utilisez $mech->save_content si vous avez besoin du contenu décodé.

NOTE : Parce que ":content_file" fait que le contenu de la page est stocké dans un fichier au lieu de l'objet réponse, certaines fonctions de Mech qui s'attendent à ce qu'il soit présent ne fonctionneront pas comme prévu. Utilisez avec prudence.

Voici une liste non exhaustive des méthodes qui ne fonctionnent pas comme prévu avec ":content_file" : forms() , current_form() , links() , title() , content(...) , text() , toutes les méthodes de gestion de contenu, toutes les méthodes de lien, toutes les méthodes d'image, toutes les méthodes de formulaire, toutes les méthodes de champ, save_content(...) , dump_links(...) , dump_images(...) , dump_forms(...) , dump_text(...)

$mech->post( $uri, content => $content )

POST le $content vers $uri. Renvoie un objet HTTP::Response. $uri peut être une chaîne d'URL bien formée, un objet URI ou un objet WWW::Mechanize::Link.

$mech->put( $uri, content => $content )

PUT le $content vers $uri. Renvoie un objet HTTP::Response. $uri peut être une chaîne d'URL bien formée, un objet URI ou un objet WWW::Mechanize::Link.

my $res = $mech->put( $uri );
my $res = $mech->put( $uri , $field_name => $value, ... );

$mech->head ($uri )

Effectue une requête HEAD vers $uri. Renvoie un objet HTTP::Response. $uri peut être une chaîne d'URL bien formée, un objet URI ou un objet WWW::Mechanize::Link.

$mech->delete ($uri )

Effectue une requête DELETE vers $uri. Renvoie un objet HTTP::Response. $uri peut être une chaîne d'URL bien formée, un objet URI ou un objet WWW::Mechanize::Link.

$mech->reload()

Agit comme le bouton de rechargement dans un navigateur : répète la requête actuelle. L'historique (conformément à la méthode back()) n'est pas modifié.

Renvoie l'objet HTTP::Response du rechargement, ou "undef" s'il n'y a pas de requête en cours.

$mech->back()

L'équivalent de cliquer sur le bouton "retour" d'un navigateur. Revient à la page précédente. N'ira pas au-delà de la première page. (Vraiment, que ferait-il s'il le pouvait ?)

Renvoie vrai s'il a pu revenir en arrière, ou faux sinon.

$mech->clear_history()

Supprime toutes les entrées de l'historique et renvoie vrai.

$mech->history_count()

Renvoie le nombre d'éléments dans l'historique du navigateur. Ce nombre inclut l'élément le plus récent de la requête et de la réponse.

$mech->history($n)

Renvoie le n-ième élément de l'historique. L'élément 0 est la requête et la réponse les plus récentes, qui seraient traitées par des méthodes telles que find_link(). L'élément 1 est l'état auquel vous reviendriez si vous appeliez back().

La valeur maximale utile pour $n est "$mech->history_count - 1". Les requêtes au-delà de cette limite renverront "undef".

Les éléments d'historique sont renvoyés sous forme de références de hash, sous la forme :

{ req => $http_request, res => $http_response }

MÉTHODES D'ÉTAT

$mech->success()

Renvoie un booléen indiquant si la dernière requête a réussi. S'il n'y a pas eu d'opération auparavant, renvoie faux.

C'est une fonction pratique qui encapsule "$mech->res->is_success".

$mech->uri()

Renvoie l'URI actuel sous forme d'objet URI. Cet objet se stringify en l'URI elle-même.

$mech->response() / $mech->res()

Renvoie la réponse actuelle sous forme d'objet HTTP::Response.

Synonyme de "$mech->response()".

$mech->status()

Renvoie le code d'état HTTP de la réponse. Il s'agit d'un nombre à 3 chiffres comme 200 pour OK, 404 pour non trouvé, et ainsi de suite.

$mech->ct() / $mech->content_type()

Renvoie le type de contenu de la réponse.

$mech->base()

Renvoie l'URI de base pour la réponse actuelle.

$mech->forms()

Lorsqu'elle est appelée dans un contexte de liste, renvoie une liste des formulaires trouvés dans la dernière page récupérée. Dans un contexte scalaire, renvoie une référence à un tableau contenant ces formulaires. Les formulaires renvoyés sont tous des objets HTML::Form.

$mech->current_form()

Retourne le formulaire actuel sous forme d'objet HTML::Form.

$mech->links()

Lorsqu'elle est appelée dans un contexte de liste, retourne une liste des liens trouvés dans la dernière page récupérée. Dans un contexte scalaire, elle retourne une référence à un tableau contenant ces liens. Chaque lien est un objet WWW::Mechanize::Link.

$mech->is_html()

Retourne vrai/faux si notre contenu est HTML, en fonction des en-têtes HTTP.

$mech->title()

Retourne le contenu de la balise "<TITLE>", tel qu'analysé par HTML::HeadParser. Retourne "undef" si le contenu n'est pas HTML.

$mech->redirects()

Méthode pratique pour obtenir les redirections de la réponse HTTP la plus récente.

Notez que vous pouvez également utiliser is_redirect pour voir si la réponse la plus récente était une redirection, comme ceci.

$mech->get($url);
do_stuff() if $mech->res->is_redirect;

MÉTHODES DE GESTION DU CONTENU

$mech->content(...)

Retourne le contenu que le mech utilise en interne pour la dernière page récupérée. Normalement, c'est la même chose que "$mech->response()->decoded_content()", mais cela peut différer pour les documents HTML si "update_html" est surchargé (auquel cas la valeur passée à l'implémentation de la classe de base sera retournée), et/ou si des arguments nommés supplémentaires sont passés à content() :

$mech->content( format => 'text' )
Retourne une version textuelle de la page, avec tout le balisage HTML supprimé. Cette fonctionnalité nécessite que HTML::TreeBuilder version 5 ou supérieure soit installée, sinon une erreur fatale sera levée. Cela ne fonctionne que si le contenu est du HTML.
$mech->content( base_href => [$base_href|undef] )
Retourne le document HTML, modifié pour contenir un balisage "<base href="$base_href">" dans l'en-tête. $base_href est "$mech->base()" s'il n'est pas spécifié. C'est utile pour passer le HTML à, par exemple, HTML::Display. Cela ne fonctionne que si le contenu est du HTML.
$mech->content( raw => 1 )
Retourne "$self->response()->content()", c'est-à-dire le contenu brut de la réponse.
$mech->content( decoded_by_headers => 1 )
Retourne le contenu après application de tous les en-têtes "Content-Encoding", mais sans aucune manipulation supplémentaire.
$mech->content( charset => $charset )
Retourne "$self->response()->decoded_content(charset => $charset)" (voir HTTP::Response pour les détails).

Pour préserver la compatibilité ascendante, les paramètres supplémentaires seront ignorés, sauf si aucun des éléments "raw | decoded_by_headers | charset" n'est spécifié et que le texte est du HTML, auquel cas une erreur sera déclenchée.

Une nouvelle instance de WWW::Mechanize retournera "undef" lorsque "$mech->content()" est appelée, car aucun contenu n'est présent avant qu'une requête n'ait été effectuée.

$mech->text()

Retourne le texte du contenu HTML actuel. Si le contenu n'est pas HTML, $mech mourra.

Le texte est extrait en analysant le contenu, puis le texte extrait est mis en cache, alors ne vous souciez pas des performances d'un appel répété.

MÉTHODES DE LIENS

$mech->links()

Liste tous les liens de la page actuelle. Chaque lien est un objet WWW::Mechanize::Link. En contexte de liste, retourne une liste de tous les liens. En contexte scalaire, retourne une référence de tableau de tous les liens.

$mech->follow_link(...)

Suit un lien spécifié sur la page. Vous spécifiez la correspondance à trouver en utilisant les mêmes paramètres que ceux utilisés par find_link().

Voici quelques exemples :

  • 3ème lien appelé "download" 
    $mech->follow_link( text => 'download', n => 3 );
  • premier lien dont l'URL contient "download", quelle que soit la casse : 
    $mech->follow_link( url_regex => qr/download/i );

    ou

    $mech->follow_link( url_regex => qr/(?i:download)/ );
  • 3ème lien sur la page 
    $mech->follow_link( n => 3 );
  • le lien avec l'URL 
    $mech->follow_link( url => '/other/page' );

    ou

    $mech->follow_link( url => 'http://example.com/page' );

Retourne le résultat de la méthode "GET" (un objet HTTP::Response) si un lien a été trouvé.

Si la page n'a pas de liens, ou si le lien spécifié n'a pas pu être trouvé, retourne "undef". Si "autocheck" est activé, une exception sera levée à la place.

$mech->find_link( ... )

Trouve un lien dans la page actuellement récupérée. Il retourne un objet WWW::Mechanize::Link qui décrit le lien. (Vous serez probablement le plus intéressé par la propriété url().) S'il ne parvient pas à trouver de lien, il retourne "undef".

Vous pouvez prendre la partie URL et la passer à la méthode get(). Si c'est votre intention, vous pourriez aussi bien utiliser directement la méthode follow_link(), car elle effectue le get() pour vous automatiquement.

Notez que les balises "<FRAME SRC="...">" sont analysées à partir du HTML et traitées comme des liens, donc cette méthode fonctionne avec elles.

Vous pouvez sélectionner le lien à trouver en passant une ou plusieurs des paires clé/valeur suivantes :

  • "text => 'string'," et "text_regex => qr/regex/,"

    "text" compare le texte du lien à string, qui doit correspondre exactement. Pour sélectionner un lien dont le texte est exactement "download", utilisez

    $mech->find_link( text => 'download' );

    "text_regex" compare le texte du lien à regex. Pour sélectionner un lien dont le texte contient "download" n'importe où, quelle que soit la casse, utilisez

    $mech->find_link( text_regex => qr/download/i );

    Notez que le texte extrait des liens de la page est coupé. Par exemple, "<a> foo </a>" est stocké sous le nom 'foo', et la recherche d'espaces en début ou en fin échouera.

  • "url => 'string'," et "url_regex => qr/regex/,"

    Compare l'URL du lien à string ou regex, selon le cas. L'URL peut être une URL relative, comme foo/bar.html, en fonction de la façon dont elle est codée sur la page.

  • "url_abs => string" et "url_abs_regex => regex"

    Compare l'URL absolue du lien à string ou regex, selon le cas. L'URL sera une URL absolue, même si elle est relative sur la page.

  • "name => string" et "name_regex => regex"

    Compare le nom du lien à string ou regex, selon le cas.

  • "rel => string" et "rel_regex => regex"

    Compare le rel du lien à string ou regex, selon le cas. Cela peut être utilisé pour trouver des feuilles de style, des favicons, ou des liens que l'auteur de la page ne veut pas que les bots suivent.

  • "id => string" et "id_regex => regex"

    Compare l'attribut 'id' du lien à string ou regex, selon le cas.

  • "class => string" et "class_regex => regex"

    Compare l'attribut 'class' du lien à string ou regex, selon le cas.

  • "tag => string" et "tag_regex => regex"

    Compare la balise d'où provient le lien à string ou regex, selon le cas. Le "tag_regex" est probablement le plus utile pour vérifier plusieurs balises, comme suit :

    $mech->find_link( tag_regex => qr/^(a|frame)$/ );

    Les balises et attributs examinés sont définis ci-dessous.

Si "n" n'est pas spécifié, il est par défaut à 1. Par conséquent, si vous ne spécifiez aucun paramètre, cette méthode cherche par défaut le premier lien de la page.

Notez que vous pouvez spécifier plusieurs paramètres de texte ou d'URL, qui seront combinés par un ET logique. Par exemple, pour trouver le premier lien avec le texte "News" et avec "cnn.com" " dans l'URL, utilisez :

$mech->find_link( text => 'News', url_regex => qr/cnn\.com/ );

La valeur de retour est une référence à un tableau contenant un objet WWW::Mechanize::Link pour chaque lien dans "$self->content".

Les liens proviennent des éléments suivants :

"<a href=...>"
"<area href=...>"
"<frame src=...>"
"<iframe src=...>"
"<link href=...>"
"<meta content=...>"

$mech->find_all_links( ... )

Retourne tous les liens de la page actuelle qui correspondent aux critères. La méthode de spécification des critères de lien est la même que pour find_link(). Chacun des liens retournés est un objet WWW::Mechanize::Link.

Dans un contexte de liste, find_all_links() retourne une liste des liens. Sinon, elle retourne une référence à la liste des liens.

find_all_links() sans paramètres retourne tous les liens de la page.

$mech->find_all_inputs( ... critères ... )

find_all_inputs() retourne un tableau de tous les contrôles d'entrée dans le formulaire actuel dont les propriétés correspondent à toutes les expressions régulières passées. Les contrôles retournés sont tous dérivés de HTML::Form::Input. Voir "INPUTS" dans HTML::Form pour les détails.

Si aucun critère n'est passé, toutes les entrées seront retournées.

S'il n'y a pas de page actuelle, pas de formulaire sur la page actuelle, ou pas de contrôles de soumission dans le formulaire actuel, alors le retour sera un tableau vide.

Vous pouvez utiliser une expression régulière ou une chaîne littérale :

# obtenir tous les contrôles textarea dont les noms commencent par "customer"
my @customer_text_inputs = $mech->find_all_inputs(
    type       => 'textarea',
    name_regex => qr/^customer/,
);
# obtenir tous les contrôles text ou textarea nommés "customer"
my @customer_text_inputs = $mech->find_all_inputs(
    type_regex => qr/^(text|textarea)$/,
    name       => 'customer',
);

$mech->find_all_submits( ... critères ... )

find_all_submits() fait la même chose que find_all_inputs() sauf qu'elle ne retourne que les contrôles qui sont des contrôles de soumission, ignorant les autres types de contrôles d'entrée comme le texte et les cases à cocher.

MÉTHODES D'IMAGE

$mech->images

Liste toutes les images de la page actuelle. Chaque image est un objet WWW::Mechanize::Image. En contexte de liste, retourne une liste de toutes les images. En contexte scalaire, retourne une référence de tableau de toutes les images.

$mech->find_image()

Recherche une image dans la page actuelle. Elle retourne un objet WWW::Mechanize::Image qui décrit l'image. Si elle ne parvient pas à trouver une image, elle retourne "undef".

Vous pouvez sélectionner l'image à trouver en passant une ou plusieurs des paires clé/valeur suivantes :

  • "alt => 'chaîne'" et "alt_regex => qr/regex/"

    "alt" correspond à l'attribut ALT de l'image par rapport à la chaîne string, qui doit être une correspondance exacte. Pour sélectionner une image avec une balise ALT exactement égale à "download", utilisez

    $mech->find_image( alt => 'download' );

    "alt_regex" correspond à l'attribut ALT de l'image par rapport à une expression régulière. Pour sélectionner une image dont l'attribut ALT contient "download" n'importe où, sans tenir compte de la casse, utilisez

    $mech->find_image( alt_regex => qr/download/i );
  • "url => 'chaîne'" et "url_regex => qr/regex/"

    Correspond à l'URL de l'image par rapport à la chaîne string ou à l'expression régulière regex, selon le cas. L'URL peut être une URL relative, comme foo/bar.html, selon la façon dont elle est codée sur la page.

  • "url_abs => chaîne" et "url_abs_regex => regex"

    Correspond à l'URL absolue de l'image par rapport à la chaîne string ou à l'expression régulière regex, selon le cas. L'URL sera une URL absolue, même si elle est relative sur la page.

  • "tag => chaîne" et "tag_regex => regex"

    Correspond à la balise d'où provient l'image par rapport à la chaîne string ou à l'expression régulière regex, selon le cas. La "tag_regex" est probablement la plus utile pour vérifier plusieurs balises, comme dans :

    $mech->find_image( tag_regex => qr/^(img|input)$/ );

    Les balises prises en charge sont "<img>" et "<input>".

  • "id => chaîne" et "id_regex => regex"

    "id" correspond à l'attribut id de l'image par rapport à la chaîne string, qui doit être une correspondance exacte. Pour sélectionner une image avec l'id exact "download-image", utilisez

    $mech->find_image( id => 'download-image' );

    "id_regex" correspond à l'attribut id de l'image par rapport à une expression régulière. Pour sélectionner la première image dont l'id contient "download" n'importe où, utilisez

    $mech->find_image( id_regex => qr/download/ );
  • "classs => chaîne" et "class_regex => regex"

    "class" correspond à l'attribut class de l'image par rapport à la chaîne string, qui doit être une correspondance exacte. Pour sélectionner une image avec la classe exacte "img-fuid", utilisez

    $mech->find_image( class => 'img-fluid' );

    Pour sélectionner une image avec les attributs de classe "rounded float-left", utilisez

    $mech->find_image( class => 'rounded float-left' );

    Notez que les classes doivent être mises en correspondance en tant que chaîne complète, dans l'ordre exact où elles apparaissent dans le code source du site.

    "class_regex" correspond à l'attribut class de l'image par rapport à une expression régulière. Utilisez ceci si vous voulez un nom de classe partiel, ou si une image a plusieurs classes, mais que vous ne vous souciez que d'une seule.

    Pour sélectionner la première image avec la classe "rounded", où il y a plusieurs images qui peuvent également avoir la classe "float-left" ou "float-right", utilisez

    $mech->find_image( class_regex => qr/\brounded\b/ );

    La sélection d'une image avec plusieurs classes où l'ordre d'apparition dans le code source du site n'a pas d'importance n'est pas actuellement prise en charge.

Si "n" n'est pas spécifié, il vaut par défaut 1. Par conséquent, si vous ne spécifiez aucun paramètre, cette méthode recherche par défaut la première image de la page.

Notez que vous pouvez spécifier plusieurs paramètres ALT ou URL, qui seront combinés par un ET logique. Par exemple, pour trouver la première image avec le texte ALT "News" et contenant "cnn.com" dans l'URL, utilisez :

$mech->find_image( image => 'News', url_regex => qr/cnn\.com/ );

La valeur de retour est une référence à un tableau contenant un objet WWW::Mechanize::Image pour chaque image dans "$mech->content".

$mech->find_all_images( ... )

Retourne toutes les images de la page actuelle qui correspondent aux critères. La méthode de spécification des critères d'image est la même que pour find_image(). Chacune des images retournées est un objet WWW::Mechanize::Image.

Dans un contexte de liste, find_all_images() retourne une liste des images. Sinon, elle retourne une référence à la liste des images.

find_all_images() sans paramètres retourne toutes les images de la page.

MÉTHODES DE FORMULAIRE

Ces méthodes vous permettent de travailler avec les formulaires d'une page. L'idée est de choisir un formulaire que vous utiliserez ensuite avec les méthodes de champ ci-dessous.

$mech->forms

Liste tous les formulaires de la page actuelle. Chaque formulaire est un objet HTML::Form. En contexte de liste, retourne une liste de tous les formulaires. En contexte scalaire, retourne une référence de tableau de tous les formulaires.

$mech->form_number($number)

Sélectionne le numéro-ème formulaire de la page comme cible pour les appels ultérieurs à field() et click(). Retourne également le formulaire qui a été sélectionné.

S'il est trouvé, le formulaire est retourné sous forme d'objet HTML::Form et est défini en interne pour une utilisation ultérieure avec les méthodes de formulaire de Mech telles que field() et click(). Lorsqu'il est appelé dans un contexte de liste, le numéro du formulaire trouvé est également retourné comme seconde valeur.

Émet un avertissement et retourne "undef" si aucun formulaire n'est trouvé.

Le premier formulaire est le numéro 1, et non zéro.

$mech->form_action( $action )

Sélectionne un formulaire par son action, en utilisant une expression régulière contenant $action. S'il y a plus d'un formulaire sur la page correspondant à cette action, le premier est utilisé et un avertissement est généré.

S'il est trouvé, le formulaire est retourné sous forme d'objet HTML::Form et est défini en interne pour une utilisation ultérieure avec les méthodes de formulaire de Mech telles que field() et click().

Retourne "undef" si aucun formulaire n'est trouvé.

$mech->form_name( $name [, \%args ] )

Sélectionne un formulaire par son nom.

Par défaut, le fi

rst form qui a ce nom sera renvoyé.

my $form = $mech->form_name("order_form");

Si vous voulez la deuxième, troisième ou nième occurrence, passez une référence de hachage d'arguments optionnelle comme dernier paramètre avec la clé "n" pour choisir quelle instance vous voulez. La numérotation commence à 1.

my $third_product_form = $mech->form_name("buy_now", { n => 3 });

Renvoie "undef" si aucun formulaire n'est trouvé.

Si vous voulez la deuxième, troisième ou nième occurrence, passez une référence de hachage d'arguments optionnelle comme dernier paramètre avec la clé "n" pour choisir quelle instance vous voulez. La numérotation commence à 1.

my $third_product_form = $mech->form_id("buy_now", { n => 3 });

Si le paramètre "n" n'est pas passé, et qu'il y a plus d'un formulaire sur la page portant cet ID, alors le premier est utilisé, et un avertissement est généré.

S'il est trouvé, le formulaire est renvoyé sous forme d'objet HTML::Form et défini en interne pour une utilisation ultérieure avec les méthodes de formulaire de Mech telles que field() et click().

Renvoie "undef" s'il aucun formulaire n'est trouvé. Cela déclenchera également un avertissement, sauf si "quiet" est activé.

$mech->all_forms_with_fields( @fields )

Sélectionne un formulaire en passant une liste de noms de champs qu'il doit contenir. Tous les formulaires correspondants (éventuellement aucun) sont renvoyés sous forme de liste d'objets HTML::Form.

Sélectionne un formulaire en passant une liste de noms de champs qu'il doit contenir. Par défaut, le premier formulaire qui correspond à tous ces noms de champs sera renvoyé.

my $form = $mech->form_with_fields( qw/sku quantity add_to_cart/ );

Si vous voulez la deuxième, troisième ou nième occurrence, passez une référence de hachage d'arguments optionnelle comme dernier paramètre avec la clé "n" pour choisir quelle instance vous voulez. La numérotation commence à 1.

my $form = $mech->form_with_fields( 'sky', 'qty', { n => 2 } );

MÉTHODES DE CHAMPS

Ces méthodes vous permettent de définir les valeurs des champs d'un formulaire donné.

$mech->field( $name, $value, $number )

$mech->field( $name, \@values, $number )

$mech->field( $name, \@file_upload_values, $number )

Étant donné le nom d'un champ, définit sa valeur à la valeur spécifiée. Ceci s'applique au formulaire actuel (tel que défini par la méthode form_name() ou form_number() ou par défaut au premier formulaire de la page).

Si le champ est de type "file", sa valeur doit être une référence d'array. Exemple :

$mech->field( $file_input, ['/tmp/file.txt'] );

Exemples de valeurs pour les entrées de type "file", suivis de l'explication de ce que chaque index signifie :

# 0: chemin_fichier      1: nom_fichier    3: en-têtes
['/tmp/file.txt']
['/tmp/file.txt', 'filename.txt']
['/tmp/file.txt', 'filename.txt', @headers]
['/tmp/file.txt', 'filename.txt', Content => 'some content']
[undef,           'filename.txt', Content => 'content here']

L'index 0 est le *chemin du fichier* qui sera lu depuis le disque. L'index 1 est le nom du fichier qui sera utilisé dans le corps de la requête HTTP ; s'il n'est pas fourni, le chemin du fichier (index 0) est utilisé à la place. Si Content => 'content here' est utilisé comme montré, alors le *chemin du fichier* sera ignoré.

Le paramètre optionnel $number est utilisé pour distinguer entre deux champs portant le même nom. Les champs sont numérotés à partir de 1.

$mech->select($name, $new_or_additional_single_value)

$mech->select($name, $new_or_additional_single_value, $number)

$mech->select($name, \%new_single_value_by_number)

$mech->select($name, \@new_list_of_values)

$mech->select($name, \%new_list_of_values_by_number)

Étant donné le nom d'un champ "select", définit sa valeur à la valeur spécifiée.

# sélectionner 'foo'
$mech->select($name, 'foo');

Le paramètre optionnel $number est utilisé pour distinguer entre deux champs portant le même nom. Les champs sont numérotés à partir de 1. Notez que cela ne fonctionne que pour la sélection de valeurs simples, pas pour la sélection de plusieurs valeurs à la fois.

# sélectionner le deuxième champ nommé 'foo'
$mech->select($name, 'foo', 2);

Si le champ n'est pas "<select multiple>" et que $value est une référence d'array, seule la **première** valeur sera définie. [Note : jusqu'à la version 1.05_03, la documentation prétendait que seule la dernière valeur était définie, mais c'était incorrect.]

# sélectionner 'bar'
$mech->select($name, ['bar', 'ignored', 'ignored']);

Passer $value sous forme de référence de hachage avec une clé "n" sélectionne un élément par son numéro.

# sélectionner la troisième valeur
$mech->select($name, {n => 3});

La numérotation commence à 1. Ceci s'applique au formulaire actuel.

Si vous avez un champ avec "<select multiple>" et que vous passez une seule $value, alors $value sera ajouté à la liste des champs sélectionnés, sans effacer les autres.

# ajouter 'bar' à la liste des valeurs sélectionnées
$mech->select($name, 'bar');

Cependant, si vous passez une référence d'array, toutes les valeurs précédemment sélectionnées seront effacées et remplacées par toutes les valeurs contenues dans la référence d'array.

# remplacer la sélection par 'foo' et 'bar'
$mech->select($name, ['foo', 'bar']);

Cela fonctionne également lors de la sélection par numéros, dans ce cas, la valeur de la clé "n" sera une référence d'array des numéros de valeur que vous souhaitez utiliser pour remplacer la sélection.

# remplacer la sélection par le 2ème et le 4ème élément
$mech->select($name, {n => [2, 4]});

Pour ajouter plusieurs valeurs supplémentaires à la liste des champs sélectionnés sans effacer, appelez "select" sous la forme simple $value avec chaque valeur unique dans une boucle.

# ajouter toutes les valeurs du tableau à la sélection
$mech->select($name, $_) for @additional_values;

Renvoie vrai si la valeur a été définie avec succès. En cas d'échec, renvoie faux et appelle "$self->warn()" avec un message d'erreur.

$mech->set_fields( $name => $value ... )

$mech->set_fields( $name => \@value_and_instance_number )

$mech->set_fields( $name => \$value_instance_number )

$mech->set_fields( $name => \@file_upload )

Cette méthode définit plusieurs champs du formulaire actuel. Elle prend une liste de paires nom de champ et valeur. S'il y a plus d'un champ portant le même nom, le premier trouvé est défini. Si vous souhaitez choisir lequel des champs dupliqués définir, utilisez une valeur qui est un tableau anonyme contenant la valeur du champ et son numéro comme 2 éléments.

# définir le deuxième champ $name sur 'foo'
$mech->set_fields( $name => [ 'foo', 2 ] );

Le

valeur d'un champ de type "fichier" doit être un arrayref comme décrit dans field(). Exemples :

$mech->set_fields( $champ_fichier => ['/tmp/file.txt'] );
$mech->set_fields( $champ_fichier => ['/tmp/file.txt', 'nom_fichier.txt'] );

La valeur pour une entrée de type "fichier" peut également être un arrayref contenant un arrayref et un nombre, comme documenté dans submit_form(). Le nombre sera utilisé pour trouver le champ dans le formulaire. Exemple :

$mech->set_fields( $champ_fichier => [['/tmp/file.txt'], 1] );

Les champs sont numérotés à partir de 1.

Pour les champs qui ont un ensemble prédéfini de valeurs, vous pouvez également fournir une référence à un entier, si vous ne connaissez pas les options pour le champ, mais que vous savez que vous voulez (par exemple) la première.

# sélectionner la première valeur dans la boîte de sélection $name
$mech->set_fields( $name => \0 );
# sélectionner la dernière valeur dans la boîte de sélection $name
$mech->set_fields( $name => \-1 );

Ceci s'applique au formulaire courant.

$mech->set_visible( @critères )

Cette méthode définit les champs du formulaire courant sans avoir à connaître leurs noms. Ainsi, si vous avez un écran de connexion qui demande un nom d'utilisateur et un mot de passe, vous n'avez pas besoin de récupérer le formulaire et d'inspecter la source (ou d'utiliser l'utilitaire mech-dump, installé avec WWW::Mechanize) pour connaître les noms des champs ; vous pouvez simplement dire :

$mech->set_visible( $nom_utilisateur, $mot_de_passe );

et le premier et le deuxième champ seront définis en conséquence. La méthode est appelée set_visible car elle n'agit que sur les champs visibles ; les entrées de formulaire cachées ne sont pas prises en compte. L'ordre des champs est l'ordre dans lequel ils apparaissent dans le code source HTML, ce qui est presque toujours l'ordre dans lequel quelqu'un qui voit la page les penserait, mais un travail créatif avec des tableaux pourrait changer cela ; utilisateur averti.

Chaque élément de @critères est soit une valeur de champ, soit un spécificateur de champ. Une valeur de champ est un scalaire. Un spécificateur de champ vous permet de spécifier le *type* de champ d'entrée que vous souhaitez définir et est dénoté par un arrayref contenant deux éléments. Ainsi, vous pourriez spécifier le premier bouton radio avec :

$mech->set_visible( [ radio => 'KCRW' ] );

Les valeurs de champ et les spécificateurs peuvent être mélangés, donc :

$mech->set_visible( 'fred', 'secret', [ option => 'Checking' ] );

définirait les deux premiers champs à "fred" et "secret", et le *prochain* champ de menu "OPTION" à "Checking".

Les types de spécificateurs de champ possibles sont : "text", "password", "hidden", "textarea", "file", "image", "submit", "radio", "checkbox" et "option".

"set_visible" renvoie le nombre de valeurs définies.

$mech->tick( $name, $value [, $set ] )

"Coche" la première case à cocher qui a à la fois le nom et la valeur associés sur le formulaire courant.
S'il n'y a pas de valeur pour l'entrée, passez simplement une chaîne vide comme valeur. Se termine si aucune case à cocher nommée n'existe pour la valeur donnée, si une valeur est donnée. Passer une valeur fausse comme troisième argument optionnel fera décocher la case à cocher. Le troisième argument n'a pas besoin d'être défini si vous souhaitez simplement cocher la case.

$mech->tick('extra', 'fromage');
$mech->tick('extra', 'champignons');
$mech->tick('pas_de_valeur', ''); # <input type="checkbox" name="pas_de_valeur">

$mech->untick($name, $value)

Décoche la case à cocher. Raccourci pour "tick($name,$value,undef)"

$mech->value( $name [, $nombre ] )

Étant donné le nom d'un champ, retourne sa valeur. Ceci s'applique au formulaire courant.

Le paramètre optionnel $nombre est utilisé pour distinguer deux champs portant le même nom. Les champs sont numérotés à partir de 1.

Si le champ est de type fichier (champ de téléchargement de fichier), la valeur est toujours effacée pour empêcher les sites distants de télécharger vos fichiers locaux. Pour télécharger un fichier, spécifiez explicitement son nom de fichier.

$mech->click( $bouton [, $x, $y ] )

A pour effet de cliquer sur un bouton du formulaire courant. Le premier argument est le nom du bouton à cliquer. Les deuxième et troisième arguments (optionnels) vous permettent de spécifier les coordonnées (x,y) du clic.

S'il n'y a qu'un seul bouton sur le formulaire, "$mech->click()" sans argument clique simplement sur ce bouton.

Retourne un objet HTTP::Response.

$mech->click_button( ... )

A pour effet de cliquer sur un bouton du formulaire courant en spécifiant ses attributs. Les arguments sont une liste de paires clé/valeur. Un seul des clés nom, id, nombre, input ou valeur doit être spécifié dans les clés.

Se termine si aucun bouton n'est trouvé.

  • "name => nom"

    Clique sur le bouton nommé *nom* dans le formulaire courant.

  • "id => id"

    Clique sur le bouton avec l'id *id* dans le formulaire courant.

  • "number => n"

    Clique sur le *n*-ième bouton de type *submit* dans le formulaire courant. La numérotation commence à 1.

  • "value => valeur"

    Clique sur le bouton avec la valeur *valeur* dans le formulaire courant.

  • "input => $objet_entree"

    Clique sur le bouton référencé par $objet_entree, une instance de HTML::Form::SubmitInput obtenue par exemple de :

    $mech->current_form()->find_input( undef, 'submit' )

    $objet_entree doit appartenir au formulaire courant.

  • "x => x"
  • "y => y"

    Ces arguments (optionnels) vous permettent de spécifier les coordonnées (x,y) du clic.

$mech->submit()

Soumet le formulaire courant, sans spécifier de bouton à cliquer. En fait, aucun bouton n'est cliqué.

Retourne un objet HTTP::Response.

Ceci était auparavant un synonyme de "$mech->click( 'submit' )", mais ne l'est plus.

$mech->submit_form( ... )

Cette méthode vous permet de sélectionner un formulaire de la page précédemment récupérée, de remplir ses champs et de le soumettre. Elle combine les méthodes "form_number"/"form_name", "set_fields" et "click" en un seul appel de niveau supérieur. Ses arguments sont une liste de paires clé/valeur, toutes optionnelles.

  • "fields => \%champs"

    Spécifie les champs à remplir dans le formulaire courant.

  • "with_fields => \%champs"

    Probablement tout ce dont vous avez besoin pour le cas courant. Elle combine un sélecteur de formulaire intelligent et la définition de données en une seule opération. Elle sélectionne le premier formulaire qui contient tous les champs mentionnés dans "\%champs". C'est pratique car vous n'avez pas besoin de connaître le nom ou le numéro du formulaire pour le faire.

    (appelle form_with_fields() et set_fields()).

    Si vous choisissez "with_fields", l'option "fields" sera ignorée. Les options "form_number", "form_name" et "form_id" seront toujours utilisées. Une exception sera levée à moins qu'exactement un formulaire ne corresponde à tous les critères fournis.

  • "form_number => n"

    Sélectionne le *n*-ième formulaire (appelle form_number(). Si ce paramètre n'est pas spécifié, le formulaire actuellement sélectionné est utilisé.

  • "form_name => nom"

    Sélectionne le formulaire nommé *nom* (appelle form_name())

  • "form_id => ID"

    Sélectionne le formulaire avec l'ID *ID* (appelle form_id())

  • "button => bouton"

    Clique sur le bouton *bouton* (appelle click())

  • "x => x, y => y"

    Définit les valeurs x ou y pour click()

  • "strict_forms => bool"

    Définit le drapeau strict de HTML::Form qui fait que la soumission du formulaire échoue si l'un des champs passés n'existe pas sur la page, et/ou qu'une valeur n'existe pas dans un élément select. Par défaut, HTML::Form définit cette valeur à false.

    Ce comportement peut également être activé globalement en passant "strict_forms => 1" à "WWW::Mechanize->new". Si vous le faites, vous pouvez toujours le désactiver pour des appels individuels en passant "strict_forms => 0" ici.

Si aucun formulaire n'est sélectionné, le premier formulaire trouvé est utilisé.

Si *bouton* n'est pas passé, alors la méthode submit() est utilisée à la place.

Si vous souhaitez soumettre un fichier et obtenir son contenu à partir d'un scalaire plutôt que d'un fichier sur le système de fichiers, vous pouvez utiliser :

$mech->submit_form(with_fields => { logfile => [ [ undef, 'whatever', Content => $content ], 1 ] } );

Retourne un objet HTTP::Response.

MÉTHODES DIVERSES

$mech->add_header( nom => $valeur [, nom => $valeur... ] )

Définit les en-têtes HTTP pour que l'agent les ajoute ou les supprime de la requête HTTP.

$mech->add_header( Encoding => 'text/klingon' );

Si une *valeur* est "undef", alors cet en-tête sera supprimé de toute requête future. Par exemple, pour ne jamais envoyer d'en-tête Referer :

$mech->
<code>
$mech->add_header( Referer => undef );
</code>

Si vous souhaitez supprimer un en-tête, utilisez "delete_header".

Retourne le nombre de paires nom/valeur ajoutées.

NOTE : Cette méthode était très différente dans WWW::Mechanize avant la version 1.00. À l'époque, les en-têtes étaient stockés dans une table de hachage de package, et non en tant que membre de l'instance de l'objet. Appeler add_header() modifiait les en-têtes pour chaque objet WWW::Mechanize, même après que votre objet n'existait plus.

$mech->delete_header( nom [, nom ... ] )

Supprime les en-têtes HTTP de la liste des en-têtes spéciaux de l'agent. Par exemple, vous pourriez avoir besoin de faire quelque chose comme :

# Ne pas envoyer de Referer pour cette URL
$mech->add_header( Referer => undef );
# Obtenir l'URL
$mech->get( $url );
# Revenir au comportement par défaut
$mech->delete_header( 'Referer' );

$mech->quiet(vrai/faux)

Permet de supprimer les avertissements affichés à l'écran.

$mech->quiet(0); # active les avertissements (par défaut)
$mech->quiet(1); # désactive les avertissements
$mech->quiet();  # retourne l'état actuel de la discrétion

$mech->autocheck(vrai/faux)

Permet d'activer et de désactiver la vérification automatique.

La vérification automatique vérifie chaque requête effectuée pour s'assurer qu'elle a réussi. Cela vous évite d'avoir à le faire manuellement. Toutes les erreurs trouvées sont des erreurs, pas des avertissements. Veuillez vous référer à la section "new" pour plus de détails.

$mech->autocheck(1); # active la vérification automatique des requêtes (par défaut)
$mech->autocheck(0); # désactive la vérification automatique des requêtes
$mech->autocheck();  # retourne l'état actuel de la vérification automatique

$mech->stack_depth( $profondeur_max )

Obtient ou définit la profondeur de la pile de pages. Utilisez ceci si vous effectuez beaucoup de scraping de pages et que vous manquez de mémoire.

Une valeur de 0 signifie "pas d'historique du tout". Par défaut, la profondeur maximale de la pile est énormément grande, conservant ainsi tout l'historique.

$mech->save_content( $nom_fichier, %opts )

Enregistre le contenu de "$mech->content" dans $nom_fichier. $nom_fichier sera écrasé. L'opération échoue en cas d'erreurs.

Si le type de contenu ne commence pas par "text/", le contenu est enregistré en mode binaire (c'est-à-dire que binmode() est appliqué au descripteur de fichier de sortie).

Des arguments supplémentaires peuvent être passés sous forme de paires clé/valeur :

$mech->save_content( $nom_fichier, binary => 1 )
Le descripteur de fichier est défini avec "binmode" sur ":raw" et le contenu est obtenu en appelant "$self->content(decoded_by_headers => 1)". Identique à l'appel de : 
$mech->save_content( $nom_fichier, binmode => ':raw',
                     decoded_by_headers => 1 );

C'est la manière la plus sûre de sauvegarder le contenu tel quel.

$mech->save_content( $nom_fichier, binmode => $binmode )
Le descripteur de fichier est défini en mode binaire. Si $binmode commence par ':', il est passé comme paramètre à "binmode" : 
binmode $fh, $binmode;

sinon, le descripteur de fichier est mis en mode binaire si $binmode est vrai :

binmode $fh;
tous les autres arguments
sont passés tels quels à "$mech->content(%opts)". En particulier, "decoded_by_headers" peut s'avérer utile si vous souhaitez annuler l'effet de la compression de ligne effectuée par le serveur web, mais sans interpréter davantage le contenu (par exemple, le décoder selon le jeu de caractères).

$mech->dump_headers( [$fh] )

Affiche un résumé des en-têtes de réponse HTTP de la réponse la plus récente. Si $fh n'est pas spécifié ou est "undef", il affiche sur STDOUT.

Contrairement au reste des méthodes "dump_*", $fh peut être un scalaire. Il sera utilisé comme nom de fichier.

$mech->dump_links( [[$fh], $absolu] )

Affiche un résumé des liens de la page actuelle sur $fh. Si $fh n'est pas spécifié ou est "undef", il affiche sur STDOUT.

Si $absolu est vrai, les liens affichés sont absolus, pas relatifs.

$mech->dump_images( [[$fh], $absolu] )

Affiche un résumé des images de la page actuelle sur $fh. Si $fh n'est pas spécifié ou est "undef", il affiche sur STDOUT.

Si $absolu est vrai, les liens affichés sont absolus, pas relatifs.

La sortie inclura des lignes vides pour les images qui n'ont pas d'attribut "src" et donc pas d'URL.

$mech->dump_forms( [$fh] )

Affiche un résumé des formulaires de la page actuelle sur $fh. Si $fh n'est pas spécifié ou est "undef", il affiche sur STDOUT. Exécuter ce qui suit :

my $mech = WWW::Mechanize->new();
$mech->get("https://www.google.com/");
$mech->dump_forms;

affichera :

GET https://www.google.com/search [f]
  ie=ISO-8859-1                  (hidden readonly)
  hl=en                          (hidden readonly)
  source=hp                      (hidden readonly)
  biw=                           (hidden readonly)
  bih=                           (hidden readonly)
  q=                             (text)
  btnG=Google Search             (submit)
  btnI=I'm Feeling Lucky         (submit)
  gbv=1                          (hidden readonly)

$mech->dump_text( [$fh] )

Affiche le texte de la page actuelle sur $fh. Si $fh n'est pas spécifié ou est "undef", il affiche sur STDOUT.

MÉTHODES DE_LWP::UserAgent_ENVOYÉES_MODIFIÉES

$mech->clone()

Duplique l'objet mech. Le clone utilisera le même magasin de cookies que l'original.

$mech->redirect_ok()

Une version surchargée de redirect_ok() dans LWP::UserAgent. Cette méthode est utilisée pour déterminer si une redirection dans la requête doit être suivie.

Notez que le constructeur de WWW::Mechanize ajoute POST à la liste "requests_redirectable" de l'agent.

$mech->request( $requête [, $arg [, $taille]])

Version surchargée de request() dans LWP::UserAgent. Effectue la requête réelle. Normalement, si vous utilisez WWW::Mechanize, c'est que vous ne voulez pas vous soucier de ce niveau de détail de toute façon.

Notez que $requête sera modifiée.

Retourne un objet HTTP::Response.

$mech->update_html( $html )

Permet de remplacer le HTML trouvé par le mech. Met à jour les arbres d'analyse des formulaires et des liens que le mech utilise en interne.

Disons que vous avez une page dont vous savez qu'elle a une sortie mal formée, et que vous voulez la mettre à jour pour que les liens soient corrects :

my $html = $mech->content;
$html =~ s[</option>.{0,3}</td>][</option></select></td>]isg;
$mech->update_html( $html );

Cette méthode est également utilisée en interne par le mech lui-même pour mettre à jour son propre contenu HTML lors du chargement d'une page. Cela signifie que si vous souhaitez effectuer systématiquement la substitution HTML ci-dessus, vous surchargeriez "update_html" dans une sous-classe comme suit :

package MyMech;
use parent 'WWW::Mechanize';
sub update_html {
    my ($self, $html) = @_;
    $html =~ s[</option>.{0,3}</td>][</option></select></td>]isg;
    $self->WWW::Mechanize::update_html( $html );
}

Si vous faites cela, le mech utilisera le HTML nettoyé au lieu de l'original, à la fois lors de l'analyse pour ses propres besoins et pour vous le retourner via content().

Surcharger cette méthode est également le moyen recommandé d'implémenter des étapes de validation supplémentaires (par exemple, des vérificateurs de liens) pour chaque page HTML reçue. "warn" et "die" seraient alors utiles pour signaler les erreurs de validation.

$mech->credentials( $nom_utilisateur, $mot_de_passe )

Fournit les identifiants à utiliser pour l'authentification HTTP Basic pour tous les sites et domaines jusqu'à nouvel ordre.

La forme à quatre arguments décrite dans LWP::UserAgent est toujours prise en charge.

$mech->get_basic_credentials( $domaine, $uri, $est_proxy )

Retourne les identifiants pour le domaine et l'URI.

$mech->clear_credentials()

Supprime tous les identifiants configurés avec credentials().

MÉTHODES INTERNES UNIQUEMENT

Ces méthodes sont utilisées uniquement en interne. Vous n'avez probablement pas besoin de les connaître.

$mech->_update_page($request, $response)

Met à jour toutes les variables internes de $mech comme si $request venait d'être effectuée, et retourne $response. La pile de pages n'est **pas** modifiée par cette méthode, il appartient à l'appelant (par exemple "request") de le faire.

$mech->_modify_request( $req )

Modifie un HTTP::Request avant que la requête ne soit envoyée, pour les requêtes GET et POST.

Nous ajoutons un en-tête "Referer", ainsi qu'un en-tête indiquant que nous pouvons accepter du contenu codé gzip, si Compress::Zlib est installé.

$mech->_make_request()

Méthode de commodité pour faciliter l'interception de la requête par des sous-classes comme WWW::Mechanize::Cached.

$mech->_reset_page()

Réinitialise les champs internes qui suivent les éléments analysés de la page.

$mech->_extract_links()

Extrait les liens du contenu d'une page Web et peuple la propriété "{links}" avec des objets WWW::Mechanize::Link.

$mech->_push_page_stack()

L'agent conserve une pile de pages visitées, qu'il peut dépiler lorsqu'il doit revenir en arrière, etc.

La page actuelle doit être poussée sur la pile avant que nous obtenions une nouvelle page, et la pile doit être dépilée lorsque l'on revient en arrière.

Aucune de ces méthodes ne prend d'arguments, elles opèrent simplement sur l'objet $mech.

warn( @messages )

Méthode d'avertissement centralisée, pour le diagnostic et les problèmes non fatals. Par défaut, elle appelle "CORE::warn", mais peut être remplacée en définissant "onwarn" dans le constructeur.

die( @messages )

Méthode d'erreur centralisée. Par défaut, elle appelle "CORE::die", mais peut être remplacée en définissant "onerror" dans le constructeur.

BONNES PRATIQUES

Les paramètres par défaut peuvent vous permettre de démarrer rapidement, mais il existe des paramètres que vous pouvez modifier pour vous faciliter la vie.

autocheck
"autocheck" peut vous éviter la surcharge de la vérification des codes de statut de succès. Vous pourriez le dépasser à mesure que vos besoins deviennent plus sophistiqués, mais c'est une option sûre pour commencer. 
my $agent = WWW::Mechanize->new( autocheck => 1 );
cookie_jar
Il est recommandé d'installer Mozilla::PublicSuffix et d'utiliser HTTP::CookieJar::LWP comme gestionnaire de cookies. HTTP::CookieJar::LWP offre un meilleur modèle de sécurité correspondant à celui des navigateurs Web actuels lorsque Mozilla::PublicSuffix est installé. 
use HTTP::CookieJar::LWP ();
my $jar = HTTP::CookieJar::LWP->new;
my $agent = WWW::Mechanize->new( cookie_jar => $jar );
protocols_allowed
Cette option est héritée directement de LWP::UserAgent. Elle peut être utilisée pour autoriser des protocoles arbitraires. 
my $agent = WWW::Mechanize->new(
    protocols_allowed => [ 'http', 'https' ]
);

Cela vous empêchera de suivre involontairement des URL telles que "file:///etc/passwd"

protocols_forbidden
Cette option est également héritée directement de LWP::UserAgent. Elle peut être utilisée pour interdire des protocoles arbitraires. 
my $agent = WWW::Mechanize->new(
    protocols_forbidden => [ 'file', 'mailto', 'ssh', ]
);

Cela vous empêchera de suivre involontairement des URL telles que "file:///etc/passwd"

strict_forms
Envisagez d'activer l'option "strict_forms" lors de la création d'un nouveau Mech. Cela effectuera une vérification de santé utile sur les champs de formulaire à chaque soumission de formulaire, ce qui peut vous économiser beaucoup de temps de débogage. 
my $agent = WWW::Mechanize->new( strict_forms => 1 );

Si vous ne souhaitez pas avoir cette option globalement, vous pouvez toujours l'activer pour des formulaires individuels.

$agent->submit_form( fields => { foo => 'bar' } , strict_forms => 1 );
