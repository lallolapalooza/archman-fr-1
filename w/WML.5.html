NOM

WML — Le format de fichier de langage méta de widget pour créer des compilateurs uil

DESCRIPTION

Le système de langage méta de widget (WML) est utilisé pour générer les composants du compilateur de langage d'interface utilisateur (UIL) qui peuvent changer en fonction de l'ensemble de widgets. En utilisant WML, vous pouvez ajouter le support dans UIL pour de nouveaux widgets à l'ensemble de widgets Motif ou pour un ensemble de widgets totalement nouveau.

FICHIER

Les fichiers WML sont des fichiers ASCII que vous pouvez modifier avec n'importe quel éditeur de texte standard. Ils sont accessibles dans le répertoire tools/wml par WML. Par convention, les fichiers WML ont le suffixe .wml. L'ensemble de widgets Motif est décrit dans le fichier motif.wml. C'est également le fichier WML par défaut lors de l'utilisation du système WML.

Lors de l'ajout de nouveaux widgets ou de la modification des caractéristiques des widgets, vous devriez commencer par une copie du fichier motif.wml. Si vous créez un nouvel ensemble de widgets à utiliser avec UIL, vous devriez partir de zéro. Dans les deux cas, le fichier motif.wml est un bon exemple de syntaxe WML, et vous devriez vous y familiariser avant d'écrire votre propre fichier WML.

Les fichiers WML ont une syntaxe simple, similaire en structure à UIL. Elle est composée des éléments suivants :

•
Commentaires
•
Définitions de types de données
•
Définitions d'ensembles de caractères
•
Définitions d'ensembles d'énumérations
•
Définitions de listes de contrôle
•
Définitions de classes
•
Définitions d'enfants
•
Définitions de ressources

Vous pouvez utiliser des espaces, des tabulations ou des sauts de ligne n'importe où dans la syntaxe, tant que vous ne divisez pas les mots-clés ou les chaînes de caractères, sauf que les commentaires se terminent à un saut de ligne. L'ordre des éléments n'a pas d'importance pour la syntaxe.

Cette description utilise les conventions supplémentaires suivantes pour décrire la syntaxe du langage méta de widget :

[  ]
Indique des éléments optionnels.
...
Indique où un élément de syntaxe peut être répété.
|
Indique un choix parmi plusieurs éléments.

COMMENTAIRES

Vous pouvez inclure des commentaires dans le fichier WML. Les commentaires ont la syntaxe suivante :

[any.element]!any.comment

Les commentaires commencent par un point d'exclamation et s'étendent jusqu'à la fin de la ligne. Un commentaire peut commencer sur une ligne seule ou suivre n'importe quelle partie d'un autre élément. Un commentaire ne modifie pas la signification d'un autre élément. Par exemple :

!Ceci est un commentaire
!  qui s'étend sur deux lignes.
DataType    !Ceci est un commentaire suivant du code.

DÉFINITIONS DE TYPES DE DONNÉES

Les définitions de types de données enregistrent tous les types de données de ressources utilisés dans le fichier. Vous devez enregistrer tous les types de données utilisés dans votre fichier WML. Les définitions de types de données ont la syntaxe suivante :

DataType
     any.datatype [{ InternalLiteral = internal.name |
          DocName = "chaîne"; [...]}];
     [...]

Une définition de type de données commence par le mot-clé DataType. Après le mot-clé DataType se trouve une liste de types de données qui peuvent être modifiés davantage avec

InternalLiteral
Ceci force la valeur de la définition du littéral de la table des symboles interne du nom du type de données. Ce modificateur est uniquement utilisé pour contourner les définitions de table des symboles codées en dur dans le compilateur UIL. Il devrait être rarement utilisé.
DocName
Ceci donne une chaîne de caractères arbitraire pour utilisation dans la documentation. Cette chaîne est destinée à fournir un nom différent pour le type de données pour utilisation dans la documentation, ou un nom unique pour le type de données si le type de données a des alias.

Par exemple :

DataType OddNumber {DocName="OddNumber";};
         NewString;

DÉFINITIONS D'ENSEMBLES DE CARACTÈRES

Les définitions d'ensembles de caractères enregistrent le nom de la boîte à outils Motif et d'autres informations pour les noms d'ensembles de caractères utilisés dans UIL. Les définitions d'ensembles de caractères ont la syntaxe suivante :

CharacterSet
     any.character.set
          { [ FontListElementTag | XmStringCharsetName ] = "chaîne";
               [ Alias = "chaîne" ...; |
               Direction = [ LeftToRight | RightToLeft ]; |
               ParseDirection = [ LeftToRight | RightToLeft ]; |
               CharacterSize = [ OneByte | TwoByte ]; ]
               [ ... ] };
     [ ... ]

Une définition d'ensemble de caractères commence par le mot-clé CharacterSet. Après le mot-clé CharacterSet se trouve une liste d'ensembles de caractères qui peuvent être modifiés davantage avec

FontListElementTag | XmStringCharsetName
Spécifie le nom de l'ensemble de caractères, qui deviendra le composant d'ensemble de caractères d'un segment de chaîne composite créé en utilisant cet ensemble de caractères. Ce modificateur est requis.
Alias
Spécifie un ou plusieurs alias pour le nom de l'ensemble de caractères. Chaque alias peut être utilisé dans UIL pour faire référence au même ensemble de caractères.
Direction
Spécifie la direction d'un segment de chaîne composite créé en utilisant cet ensemble de caractères. La valeur par défaut est LeftToRight.
ParseDirection
Spécifie la direction dans laquelle une chaîne d'entrée est analysée lors de la création d'un segment de chaîne composite à l'aide de cet ensemble de caractères. La valeur par défaut est celle spécifiée par Direction.
CharacterSize
Spécifie le nombre d'octets par caractère d'un segment de chaîne composite créé en utilisant cet ensemble de caractères. La valeur par défaut est OneByte.

Par exemple :

CharacterSet
  iso_latin1
    { XmStringCharsetName = "ISO8859-1";
      Alias = "ISOLatin1"; };
  iso_hebrew_lr
    { XmStringCharsetName = "ISO8859-8";
      Alias = "iso_latin8_lr";
      Direction = RightToLeft;
      ParseDirection = LeftToRight; };
  ksc_korean
    { XmStringCharsetName = "KSC5601.1987-0";
      CharacterSize = TwoByte; };

DÉFINITIONS D'ENSEMBLES D'ÉNUMÉRATIONS

Les définitions d'ensembles d'énumérations enregistrent les constantes nommées utilisées dans la boîte à outils Motif pour spécifier certaines valeurs de ressources. Les définitions d'ensembles d'énumérations ont la syntaxe suivante :

EnumerationSet
     resource.name: resource.type
          { enum.value.name; [ ... ] };

Une définition d'ensemble d'énumérations commence par le mot-clé EnumerationSet. Pour chaque ensemble d'énumérations défini, le nom et le type de la ressource sont listés. Le nom de la ressource est le nom de la ressource de la boîte à outils Motif, avec le XmN de début supprimé et avec la première lettre capitalisée. Par exemple, le nom de la ressource Motif XmNrowColumnType est RowColumnType. Le type de ressource est le type de données de la ressource ; pour la plupart des ressources, il s'agit d'un *entier*. Après le nom et le type de la ressource se trouve une liste de noms de valeurs d'énumération qui peuvent être utilisés comme paramètres pour la ressource. Ces noms sont les mêmes que ceux de la boîte à outils Motif.

Par exemple :

EnumerationSet
  RowColumnType: integer
    { XmWORK_AREA; XmMENU_BAR; XmMENU_POPUP;
      XmMENU_PULLDOWN; XmMENU_OPTION; };

Les ensembles d'énumérations prennent également en charge les valeurs booléennes.

DÉFINITIONS DE LISTES DE CONTRÔLE

Les définitions de listes de contrôle assignent un nom à des groupes de contrôles. Vous pouvez utiliser ces listes de contrôle plus tard dans les définitions de classes pour simplifier la structure de votre fichier WML. Les définitions de listes de contrôle

ControlList
     any.control.list [{ any.control; [...]}];

Une définition de liste de contrôle commence par le mot-clé ControlList. Après le mot-clé ControlList se trouvent autant de définitions de listes de contrôle que nécessaire. Les définitions de listes de contrôle sont constituées d'un nom de liste de contrôle suivi de l'ensemble des contrôles qu'elle représente. Par exemple :

ControlList
        Buttons {PushButton;
                 RadioButton;
                 CascadeButton;
                 NewCascadebutton;};

Chaque contrôle spécifié dans la liste de contrôle doit être défini comme une classe dans le fichier.

Définitions de classe

Les définitions de classe décrivent une classe de widget particulière, y compris sa position dans la hiérarchie des classes, la fonction de commodité du toolkit, ses ressources et ses contrôles. Il devrait y avoir une définition de classe pour chaque widget ou gadget de l'ensemble de widgets que vous souhaitez prendre en charge dans UIL. Les définitions de classe ont la syntaxe suivante :

Class class.name: MetaClass | Widget | Gadget
     [{[
     SuperClass = class.name; |
     ParentClass = parent.class.name; |
     InternalLiteral = internal.name; |
     Alias = alias; |
     ConvenienceFunction = convenience.function; |
     WidgetClass = widget.class; |
     DocName = "string"; |
     DialogClass = True | False; |
     Resources { any.resource.name [{
               Default = new.default.value; |
               Exclude = True |
               False;
               [...]} ];
          [...]}; |
     Controls { any.control.name; [...]};
     Children { any.child.name; [...] };
     [...]
     ]}];

Les définitions de classe commencent par le mot-clé Class. Pour chaque classe définie, le nom de la classe et s'il s'agit d'une métaclasse, d'un widget ou d'un gadget sont répertoriés. Chaque définition de classe peut être modifiée davantage avec les mots-clés décrits dans la liste suivante.

SuperClass
Indique le nom de la classe parente. Seule la racine de la hiérarchie ne spécifie pas de SuperClass.
ParentClass
Indique le nom de la classe parente automatiquement créée du widget s'il en existe une. Cela permet d'utiliser les ressources de cette classe parente automatiquement créée dans les instances de cette classe. Par exemple, XmBulletinBoardDialog crée à la fois un XmBulletinBoard et un XmDialogShell. Pour accéder aux ressources de la classe parente XmDialogShell, elle doit être spécifiée ici.
InternalLiteral
Force la valeur de la définition littérale de la table des symboles internes du nom de la classe. Ce modificateur est uniquement utilisé pour contourner les définitions de table des symboles codées en dur dans le compilateur UIL. Il doit être rarement utilisé.
Alias
Indique des noms alternatifs pour la classe à utiliser dans une spécification UIL.
ConvenienceFunction
Indique le nom de la fonction de commodité de création pour cette classe. Toutes les classes de widgets et de gadgets doivent avoir une ConvenienceFunction.
WidgetClass
Indique la classe de widget associée aux classes de type gadget. Actuellement, rien n'est fait avec cette valeur.
DocName
Définit une chaîne de caractères arbitraire à utiliser dans la documentation. Actuellement, rien n'est fait avec cette valeur.
DialogClass
Indique si la classe est une classe de dialogue. Actuellement, rien n'est fait avec cette valeur.
Resources
Répertorie les ressources de la classe de widget. Ce mot-clé peut être modifié davantage avec :
Default
Spécifie une nouvelle valeur par défaut pour cette ressource. Les valeurs par défaut des ressources sont généralement définies dans la définition de la ressource. Si la valeur par défaut d'une ressource héritée est modifiée par la classe, la nouvelle valeur par défaut doit être notée ici.
Exclude
Spécifie si une ressource héritée doit être exclue de la liste des ressources de la classe. Exclude est False par défaut.
Children
Répertorie les noms des enfants automatiquement créés de cette classe, afin que ces enfants puissent être référencés dans le fichier UIL.
Controls
Répertorie les contrôles que la classe de widget autorise. Les contrôles peuvent être d'autres classes ou une liste de contrôles de la définition de liste de contrôles.

L'exemple suivant utilise les exemples des définitions de types de données et des définitions de listes de contrôle ci-dessus.

Class
     TopLevelWidget: MetaClass
          {
          Resources
               {
               XtbNfirstResource;
               XtbNsecondResource;
               };
          };
     NewWidget: Widget
          {
          SuperClass = TopLevelWidget;
          ConvenienceFunction =
              XtbCreateNewWidget;
          Resources
               {
               XtbNnewResource;
               XtbNfirstResource
                  {Default="XtbNEW_VALUE";};
               XtbNsecondResource
                  {Exclude=True;};
               };
          Controls
               {
               NewWidget;
               Buttons;
               };
          };

Définitions d'enfants

Les définitions d'enfants enregistrent les classes des enfants créés automatiquement. Les enfants créés automatiquement sont référencés ailleurs dans un fichier uil en utilisant le mot-clé Children dans une définition de classe. Les définitions d'enfants ont la syntaxe suivante :

Child child.name : class.name; [...]

Où child.name est le nom de l'enfant créé automatiquement et class.name est le nom de la classe de cet enfant.

Définitions de ressources

Les définitions de ressources décrivent une ressource particulière, y compris son type et sa valeur par défaut. Il devrait y avoir une définition de ressource pour chaque nouvelle ressource référencée dans les définitions de classe. Les définitions de ressources ont la syntaxe suivante :

Resource
     resource.name: Argument | Reason | Constraint | SubResource
          [{[
          Type = type;
          [ResourceLiteral = resource.literal; ]
          [InternalLiteral = internal.name; ]
          [Alias = alias; ]
          [Related = related; ]
          [Default = default; ]
          [DocName = doc.name; ]
          [...]}]
     [...]

Les définitions de ressources commencent par le mot-clé Resource. Pour chaque définition de ressource, le nom de la ressource et s'il s'agit d'un argument, d'une raison, d'une contrainte ou d'une sous-ressource sont répertoriés.

Argument
Indique une ressource standard
Reason
Indique une ressource de rappel
Constraint
Indique une ressource de contrainte
SubResource
Actuellement, rien n'est fait avec cette valeur

La définition de ressource peut être modifiée davantage avec les mots-clés suivants :

Type
Indique le type de données de la ressource. Il doit être répertorié dans la définition du type de données.
ResourceLiteral
Indique le mot-clé utilisé dans le fichier UIL pour référencer la ressource. Dans Motif, le nom de la ressource est le même que le ResourceLiteral.
InternalLiteral
Force la valeur de la définition littérale de la table des symboles internes du nom de la ressource. Ce modificateur est uniquement utilisé pour contourner les définitions de table des symboles codées en dur dans le compilateur UIL. Il doit être rarement utilisé.
Alias
Indique des noms alternatifs pour la ressource à utiliser dans une spécification UIL.
Related
Il s'agit d'un champ à usage spécial qui permet de relier des ressources agissant comme un compteur pour les ressources actuelles à la ressource. UIL définit automatiquement la valeur de cette ressource liée au nombre d'éléments dans l'instance compilée de type resource.name.
Default
Indique la valeur par défaut de la ressource.
DocName
Définit une chaîne de caractères arbitraire à utiliser dans la documentation. Actuellement, rien n'est fait avec cette valeur.

NAME

    
WML - Widget Manipulation Language





    
DESCRIPTION

    
The Widget Manipulation Language (WML) is a programming language for the Motif toolkit. It allows developers to create graphical user interfaces (GUIs) using a declarative syntax. WML files are preprocessed and compiled into C code, which can then be linked with the Motif library to create executable applications.

    
WML provides a way to define widgets, their properties, and their behavior. It supports a wide range of Motif widgets, including buttons, labels, text fields, menus, and dialogs. WML also allows for the creation of custom widgets and the definition of event handlers to respond to user interactions.

    
Here is a simple example of a WML code snippet:

    

widget main_window : Window {
    title = "My Application";
    width = 400;
    height = 300;

    widget ok_button : PushButton {
        label = "OK";
        position = { x = 150, y = 250 };
        action = "handle_ok_click";
    };
};


    
This code defines a main window with a title and dimensions, and an "OK" button placed within the window. The `action` attribute specifies the function to be called when the button is clicked.

    
WML simplifies the process of GUI development by abstracting away much of the complexity of the underlying Motif API. This allows developers to focus on the design and functionality of their applications rather than the intricate details of widget creation and management.

    
WML files typically have a `.wml` extension. They are processed by the WML compiler, which generates C source code. This C code can then be compiled and linked with the Motif libraries to produce a Motif application.

    
The WML language has evolved over time, with different versions offering varying features and syntax. The specific version of WML used may depend on the Motif toolkit installation and the desired application features.

    
It's important to note that WML is a tool specifically for the Motif toolkit. If you are working with other GUI toolkits, you would use different languages or frameworks designed for those toolkits.

    
Further details about WML syntax, directives, and advanced features can be found in the official WML documentation or related resources.

    

#include <Xm/Xm.h>

}
