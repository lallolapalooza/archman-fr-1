JavaScript

J'ai une page web avec du JavaScript, et mon programme Mech ne fonctionne pas.

C'est parce que WWW::Mechanize n'opère pas sur le JavaScript. Il ne comprend que les parties HTML de la page.

Je pensais que Mech était censé fonctionner comme un navigateur web.

Il le fait à peu près, mais il ne prend pas en charge JavaScript.

J'ai ajouté quelques tentatives basiques pour récupérer les URL dans les appels "window.open()" et les retourner dans "$mech->links". Cela fonctionne parfois.

Étant donné que JavaScript est entièrement visible par le client, il ne peut pas être utilisé pour empêcher un scraper de suivre des liens. Mais il peut compliquer les choses. Si vous souhaitez extraire des pages spécifiques, une solution est toujours possible.

Une utilisation typique de JavaScript est de vérifier les arguments avant de poster sur le serveur. L'URL que vous voulez est probablement juste enfouie dans la fonction JavaScript. Effectuez une correspondance par expression régulière sur "$mech->content()" pour trouver le lien que vous voulez et "$mech->get" directement (cela suppose que vous savez ce que vous cherchez à l'avance).

Dans les cas plus difficiles, JavaScript est utilisé pour la manipulation d'URL afin de répondre aux besoins de certains middlewares. Dans ce cas, vous devez comprendre ce que fait le JavaScript (pourquoi ces URL sont-elles toujours très longues ?). Il y a probablement une fonction avec un ou plusieurs arguments qui calcule la nouvelle URL. Première étape : utilisez votre navigateur préféré, obtenez les URL avant et après et enregistrez-les dans des fichiers. Modifiez chaque fichier, en remplaçant les séparateurs d'arguments ('?', '&' ou ';') par des nouvelles lignes. Il est alors facile d'utiliser diff ou comm pour savoir ce que JavaScript a fait à l'URL. Deuxième étape : trouvez l'appel de fonction qui a créé l'URL - vous devrez analyser et interpréter sa liste d'arguments. Le débogueur JavaScript dans l'extension Firebug pour Firefox aide à l'analyse. À ce stade, il est assez trivial d'écrire votre propre fonction qui émule le JavaScript pour les pages que vous souhaitez traiter.

Voici une autre approche qui répond à la question : « Ça marche dans Firefox, mais pourquoi pas Mech ? ». Tout ce que le serveur web sait du client est présent dans la requête HTTP. Si deux requêtes sont identiques, les résultats devraient être identiques. La vraie question est donc : « Qu'est-ce qui est différent entre la requête Mech et la requête Firefox ? »

L'extension Firefox « Tamper Data » est un outil efficace pour examiner les en-têtes des requêtes vers le serveur. Comparez-les à ce qu'envoie LWP. Une fois les deux identiques, l'action du serveur devrait être la même.

Je dis « devrait », car c'est une simplification excessive - certaines valeurs sont naturellement uniques, par exemple un SessionID, mais si un SessionID est présent, c'est probablement suffisant, même si la valeur sera différente entre la requête LWP et la requête Firefox. Le serveur pourrait utiliser la session pour stocker des informations gênantes, mais ce n'est pas le premier endroit à chercher (et il est très peu probable que ce soit pertinent lorsque vous demandez la page de connexion de votre site).

En général, le problème se trouve dans les arguments POSTDATA manquants ou incorrects, les Cookies, les User-Agents, les Accepts, etc. Si vous utilisez Mech, alors les redirections et les cookies ne devraient pas être un problème, mais ils sont listés ici par souci d'exhaustivité. Si des en-têtes manquent, "$mech->add_header" peut être utilisé pour ajouter les en-têtes dont vous avez besoin.

Quels modules fonctionnent comme Mechanize et prennent en charge JavaScript ?

Sans ordre particulier : Gtk2::WebKit::Mechanize, WWW::Mechanize::Firefox, WWW::Mechanize::Chrome, WWW::Scripter, WWW::Selenium

Comment faire X ?

Puis-je faire [tel ou tel chose] avec WWW::Mechanize ?

Si c'est possible avec LWP::UserAgent, alors oui. WWW::Mechanize est une sous-classe de LWP::UserAgent, donc toute la magie merveilleuse de cette classe est héritée.

Comment utiliser WWW::Mechanize via un serveur proxy ?

Voir la documentation de LWP::UserAgent sur l'utilisation du proxy. Version courte :

$mech->proxy(['http', 'ftp'], 'http://proxy.example.com:8000/');

ou obtenir les spécifications de l'environnement :

$mech->env_proxy();
# Environnement défini ainsi :
gopher_proxy=http://proxy.my.place/
wais_proxy=http://proxy.my.place/
no_proxy="localhost,my.domain"
export gopher_proxy wais_proxy no_proxy

Comment voir quels champs se trouvent sur les formulaires ?

Utilisez l'utilitaire mech-dump, éventuellement installé avec Mechanize.

$ mech-dump --forms http://search.cpan.org
Dumping forms
GET http://search.cpan.org/search
  query=
  mode=all                        (option)  [*all|module|dist|author]
  <NONAME>=CPAN Search            (submit)

Comment faire en sorte que Mech gère l'authentification ?

use MIME::Base64;
my $agent = WWW::Mechanize->new();
my @args = (
    Authorization => "Basic " .
        MIME::Base64::encode( USER . ':' . PASS )
);
$agent->credentials( ADDRESS, REALM, USER, PASS );
$agent->get( URL, @args );

Si vous souhaitez utiliser les identifiants pour toutes les requêtes futures, vous pouvez également utiliser la méthode default_header() de LWP::UserAgent au lieu des arguments supplémentaires pour get()

$mech->default_header(
    Authorization => 'Basic ' . encode_base64( USER . ':' . PASSWORD ) );

Comment faire en sorte que WWW::Mechanize exécute ce JavaScript ?

Vous ne pouvez pas. JavaScript est entièrement côté client, et WWW::Mechanize est un client qui ne comprend pas JavaScript. Voir la partie supérieure de cette FAQ.

Comment cocher une case qui n'a pas de valeur définie ?

Définissez-la à la valeur « on ».

$mech->field( my_checkbox => 'on' );

Comment gérer les cadres (frames) ?

Vous ne les traitez pas en tant que cadres, à proprement parler, mais en tant que liens. Extrayez-les avec

my @frame_links = $mech->find_link( tag => "frame" );

La récupération des en-têtes HTTP et leurs valeurs ?

Toutes les méthodes HTTP::Headers fonctionnent sur un objet HTTP::Response qui est retourné par les méthodes get(), reload(), "response()/res()", click(), submit_form() et request().

my $mech = WWW::Mechanize->new( autocheck => 1 );
$mech->get( 'http://my.site.com' );
my $response = $mech->response();
for my $key ( $response->header_field_names() ) {
    print $key, " : ", $response->header( $key ), "\n";
}

Comment puis-je activer keep-alive ?

Puisque WWW::Mechanize est une sous-classe de LWP::UserAgent, vous pouvez utiliser le même mécanisme pour activer keep-alive :

use LWP::ConnCache;
...
$mech->conn_cache(LWP::ConnCache->new);

Comment puis-je changer/spécifier le paramètre action d'un formulaire HTML ?

Vous pouvez accéder à l'action du formulaire en utilisant l'objet HTML::Form retourné par l'une des méthodes spécifiant le formulaire.

En utilisant "$mech->form_number($number)" :

my $mech = WWW::mechanize->new;
$mech->get('http://someurlhere.com');
# Accéder au formulaire en utilisant son index basé sur zéro par ordre DOM
$mech->form_number(0)->action('http://newAction'); #URL ABSOLUE

En utilisant "$mech->form_name($number)" :

my $mech = WWW::mechanize->new;
$mech->get('http://someurlhere.com');
#Accéder au formulaire en utilisant son index basé sur zéro par ordre DOM
$mech->form_name('trgForm')->action('http://newAction'); #URL ABSOLUE

Comment puis-je sauvegarder une image ? Comment puis-je sauvegarder un gros tarball ?

Une image n'est que du contenu. Vous récupérez l'image et la sauvegardez.

$mech->get( 'photo.jpg' );
$mech->save_content( '/path/to/my/directory/photo.jpg' );

Vous pouvez également sauvegarder n'importe quel contenu directement sur le disque en utilisant le drapeau ":content_file" pour get(), qui fait partie de LWP::UserAgent.

$mech->get( 'http://www.cpan.org/src/stable.tar.gz',
            ':content_file' => 'stable.tar.gz' );
