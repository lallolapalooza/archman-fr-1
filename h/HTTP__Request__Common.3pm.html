N

Ce module fournit des fonctions qui retournent des objets "HTTP::Request" nouvellement créés. Ces fonctions sont généralement plus pratiques à utiliser que le constructeur standard "HTTP::Request" pour les requêtes les plus

courantes.

Notez que LWP::UserAgent possède plusieurs méthodes de commodité, y compris "get", "head", "delete", "post" et "put"

.

Les fonctions suivantes sont fournies

$url

...
La fonction "GET" retourne un objet HTTP::Request initialisé avec la méthode "GET" et l'URL spécifiée. Elle est grossièrement équivalente à l'appel suivant 
HTTP::Request->new(
   GET => $url,
   HTTP::Headers->new(Header => Value,..
.), )

mais est moins verbeuse. La différence est qu'un en-tête nommé "Content" initialisera la partie contenu de la requête au lieu de définir un champ d'en-tête. Notez que les requêtes GET ne devraient normalement pas avoir de contenu, donc ce bricolage a plus de sens pour les fonctions "PUT", "PATCH"
et "POST" décrites

ci-dessous.

"POST", "PATCH" et "PUT" fonctionnent tous avec les mêmes paramètres. 
%data = ( title => 'something', body => something else' );
$ua = LWP::UserAgent->new();
$request = HTTP::Request::Common::POST( $url, [ %data ] );
$response = $ua->request($request)
;

Elles prennent un second paramètre facultatif qui est une référence de tableau ou de hachage $form_ref. Le contenu peut aussi être spécifié directement en utilisant le pseudo-en-tête "Content", et vous pouvez aussi fournir le $form_ref de cette

manière.

Le pseudo-en-tête "Content" vole un peu de l'espace de noms des champs d'en-tête car il n'y a aucun moyen de spécifier directement un en-tête réellement appelé "Content". Si vous en avez vraiment besoin, vous devez mettre à jour la requête retournée dans une instruction

séparée.

L'argument $form_ref peut être utilisé pour passer des paires clé/valeur pour le contenu du formulaire. Par défaut, nous initialiserons une requête en utilisant le type de contenu "application/x-www-form-urlencoded". Cela signifie que vous pouvez émuler un POST de formulaire HTML <form>

comme ceci : 
POST 'http://www.perl.org/survey.cgi',
     [ name   => 'Gisle Aas',
       email  => 'gisle@aas.no',
       gender => 'M',
       born   => '1964',
       perc   => '3%',
];

Cela créera un objet HTTP::Request qui ressemble à

ceci : 
POST http://www.perl.org/survey.cgi
Content-Length: 66
Content-Type: application/x-www-form-urlencoded
name=Gisle%20Aas&email=gisle%40aas.no&gender=M&born=1964&perc
=3%25

Les champs de formulaire à valeurs multiples peuvent être spécifiés soit en répétant le nom du champ, soit en passant la valeur sous forme de référence de

tableau.

La méthode POST prend également en charge le contenu "multipart/form-data" utilisé pour l'envoi de fichiers basé sur formulaire tel que spécifié dans la RFC 1867. Vous déclenchez ce format de contenu en spécifiant un type de contenu 'form-data' comme l'un des en-têtes de la requête. Si l'une des valeurs dans le $form_ref est une référence de tableau, elle est traitée comme une spécification de partie de fichier avec l'interprétation

suivante : 
[ $file, $filename, Header => Value... ]
[ undef, $filename, Header => Value,..., Content => $content
]

La première valeur du tableau ($file) est le nom d'un fichier à ouvrir. Ce fichier sera lu et son contenu placé dans la requête. La routine échouera si le fichier ne peut pas être ouvert. Utilisez un "undef" comme valeur de $file si vous voulez spécifier le contenu directement avec un en-tête "Content". Le $filename est le nom de fichier à rapporter dans la requête. Si cette valeur est indéfinie, alors le nom de base du $file sera utilisé. Vous pouvez spécifier une chaîne vide comme [[1]] $filename si vous souhaitez supprimer l'envoi du nom de fichier lorsque

vous
