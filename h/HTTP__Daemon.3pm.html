HTTP::Daemon(3) Documentation Perl fournie par les utilisateurs HTTP::Daemon(3)

NOM

HTTP::Daemon - Une classe de serveur http simple

VERSION

version 6.16

RÉSUMÉ

use HTTP::Daemon;
use HTTP::Status;
my $d = HTTP::Daemon->new || die;
print "Please contact me at: <URL:", $d->url, ">\n";
while (my $c = $d->accept) {
    while (my $r = $c->get_request) {
    if ($r->method eq 'GET' and $r->uri->path eq "/xyzzy") {
            # remember, this is *not* recommended practice :-)
        $c->send_file_response("/etc/passwd");
    }
    else {
        $c->send_error(RC_FORBIDDEN)
    }
    }
    $c->close;
    undef($c);
}

DESCRIPTION

Les instances de la "HTTP::Daemon" classe sont des serveurs HTTP/1.1 qui écoutent sur une socket les requêtes entrantes. La "HTTP::Daemon" est une sous-classe de "IO::Socket::IP", vous pouvez donc effectuer des opérations de socket directement dessus aussi.

Veuillez noter que "HTTP::Daemon" était autrefois une sous-classe de "IO::Socket::INET". Pour prendre en charge IPv6, elle a changé de classe parent pour "IO::Socket::IP" à la version 6.05. Voir « SUPPORT IPv6 » pour les détails.

La accept() méthode se terminera lorsqu'une connexion d'un client est disponible. La valeur retournée sera un objet "HTTP::Daemon::ClientConn" qui est une autre "IO::Socket::IP" sous-classe. Appeler la get_request() méthode sur cet objet lira des données du client et retournera un objet "HTTP::Request" . L'objet ClientConn fournit également des méthodes pour envoyer diverses réponses.

Ce démon HTTP n'effectue pas de fork(2) pour vous. Votre application, c'est-à-dire l'utilisateur de la "HTTP::Daemon" est responsable du fork si cela est souhaitable. Notez également que l'utilisateur est responsable de générer des réponses conformes au protocole HTTP/1.1.

Les méthodes suivantes de "HTTP::Daemon" sont nouvelles (ou améliorées) par rapport à la "IO::Socket::IP" classe de base :

$d = HTTP::Daemon->new
$d = HTTP::Daemon->new( %opts )
La méthode constructeur prend les mêmes arguments que le "IO::Socket::IP" constructeur, mais contrairement à sa classe de base, elle peut aussi être appelée sans aucun argument. Le démon mettra alors en place une file d'attente d'écoute de 5 connexions et allouera un numéro de port aléatoire.

Un serveur qui souhaite se lier à une adresse spécifique sur le port HTTP standard sera construit comme ceci :

$d = HTTP::Daemon->new(
         LocalAddr => 'www.thisplace.com',
         LocalPort => 80,
     );

Voir IO::Socket::IP pour une description des autres arguments qui peuvent être utilisés pour configurer le démon lors de la construction.

$c = $d->accept
$c = $d->accept( $pkg )
($c, $peer_addr) = $d->accept
Cette méthode fonctionne de la même manière que celle fournie par la classe de base, mais elle retourne par défaut une référence "HTTP::Daemon::ClientConn" . Si un nom de paquet est fourni comme argument, l'objet retourné sera béni dans la classe donnée. C'est probablement une bonne idée de faire de cette classe une sous-classe de "HTTP::Daemon::ClientConn".

La méthode accept retournera "undef" si des délais d'attente ont été activés et qu'aucune connexion n'est établie dans le temps imparti. La timeout() méthode est décrite dans IO::Socket::IP.

En contexte liste, à la fois l'objet client et l'adresse du pair seront retournés ; voir la description de la méthode accept de IO::Socket pour les détails.

$d->url
Retourne une chaîne URL qui peut être utilisée pour accéder à la racine du serveur.
$d->product_tokens
Retourne le nom que ce serveur utilisera pour s'identifier. C'est la chaîne qui est envoyée avec l'en-tête de réponse "Server" . La raison principale d'avoir cette méthode est que les sous-classes peuvent la redéfinir si elles souhaitent utiliser un autre nom de produit.

La valeur par défaut est la chaîne "libwww-perl-daemon/#.##" où "#.##" est remplacé par le numéro de version de ce module.

La "HTTP::Daemon::ClientConn" est une sous-classe de "IO::Socket::IP". Les instances de cette classe sont retournées par la accept() méthode de "HTTP::Daemon". Les méthodes suivantes sont fournies :

$c->get_request
$c->get_request( $headers_only )
Cette méthode lit des données du client et les transforme en un objet "HTTP::Request" qui est retourné. Elle retourne "undef" si la lecture échoue. Si elle échoue, l'objet "HTTP::Daemon::ClientConn" ($c) doit être abandonné, et vous ne devriez pas essayer d'appeler cette méthode à nouveau sur lui. La $c->reason méthode pourrait vous donner des informations sur la raison pour laquelle $c->get_request a échoué.

La get_request() méthode ne retournera normalement pas avant que la requête entière ait été reçue du client. Cela pourrait ne pas être ce que vous voulez si la requête est l'envoi d'un gros fichier (et avec l'encodage de transfert par blocs, HTTP peut même supporter des messages de requête infinis - l'envoi d'audio en direct par exemple). Si vous passez une valeur VRAIE comme argument $headers_only , alors get_request() retournera immédiatement après l'analyse des en-têtes de requête et vous serez responsable de lire le reste du contenu de la requête. Si vous allez appeler $c->get_request à nouveau sur la même connexion, vous feriez mieux de lire le bon nombre d'octets.

$c->read_buffer
$c->read_buffer( $new_value )
Les octets lus par $c->get_request, mais non utilisés, sont placés dans le tampon de lecture .La prochaine fois que $c->get_request est appelée, elle consommera les octets de ce tampon avant de lire plus de données de la connexion réseau elle-même. Le tampon de lecture est invalide après $c->get_request a échoué.

Si vous gérez vous-même la lecture du contenu de la requête, vous devez vider ce tampon avant de lire plus de données et vous devez y placer les octets non consommés. Vous avez aussi besoin de ce tampon si vous implémentez des services comme 101 Switching Protocols.

Cette méthode retourne toujours l'ancien contenu du tampon et peut optionnellement remplacer le contenu du tampon si vous lui passez un argument.

$c->reason
Quand $c->get_request retourne "undef" vous pouvez obtenir une courte chaîne décrivant pourquoi cela s'est produit en appelant $c->reason.
$c->proto_ge( $proto )
Retourne VRAI si le client a annoncé un protocole avec un numéro de version supérieur ou égal à l'argument donné. L' $proto argument peut être une chaîne comme "HTTP/1.1" ou juste "1.1".
$c->antique_client
Retourne VRAI si le client parle le protocole HTTP/0.9. Aucun code de statut et aucun en-tête ne doivent être retournés à un tel client. Cela devrait être équivalent à !$c->proto_ge("HTTP/1.0").
$c->head_request
Retourne VRAI si la dernière requête était une requête "HEAD" . Aucun corps de contenu ne doit être généré pour ces requêtes.
$c->force_last_request
S'assurer que $c->get_request n'essaiera pas de lire d'autres requêtes sur cette connexion. Si vous générez une réponse qui n'est pas auto-délimitée, vous devriez signaler ce fait en appelant cette méthode.

Cet attribut est activé automatiquement si le client annonce le protocole HTTP/1.0 ou moins et n'inclut pas d'en-tête "Connection: Keep-Alive". Il est aussi activé automatiquement quand les clients HTTP/1.1 ou plus récents envoient l'en-tête de requête "Connection: close".

$c->send_status_line
$c->send_status_line( $code )
$c-&gt;envoyer_ligne_statut( $code, $mess )
$c->envoyer_ligne_statut( $code, $mess, $proto )
Envoyer la ligne de statut au client. Si $code est omis, 200 est supposé. Si $mess est omis, un message correspondant à $code est inséré. Si $proto est manquant, le contenu de la variable $HTTP::Daemon::PROTO est utilisé.
$c->envoyer_crlf
Envoyer la séquence CRLF au client.
$c->envoyer_en_tete_basique
$c->envoyer_en_tete_basique( $code )
$c->envoyer_en_tete_basique( $code, $mess )
$c->envoyer_en_tete_basique( $code, $mess, $proto )
Envoyer la ligne de statut et les en-têtes "Date :" et "Server :" au client. Cet en-tête est supposé être continu et ne se termine pas par une ligne CRLF vide.

Voir la description de send_status_line() pour la description des arguments acceptés.

$c->envoyer_en_tete( $field, $value )
$c->envoyer_en_tete( $field1, $value1, $field2, $value2, ... )
Envoyer une ou plusieurs lignes d'en-tête.
$c->envoyer_reponse( $res )
Écrire un objet "HTTP::Response" au client en guise de réponse. Nous faisons de notre mieux pour que la réponse soit autodélimitée afin que la connexion puisse rester persistante pour d'autres échanges requête/réponse.

L'attribut de contenu de l'objet "HTTP::Response" peut être une chaîne normale ou une référence de sous-routine. S'il s'agit d'une sous-routine, tout ce que cette routine de rappel renvoie est renvoyé au client comme contenu de la réponse. La routine sera appelée jusqu'à ce qu'elle renvoie une valeur indéfinie ou vide. Si le client est conscient de HTTP/1.1, nous utiliserons le codage de transfert par morceaux (chunked transfer encoding) pour la réponse.

$c->envoyer_redirection( $loc )
$c->envoyer_redirection( $loc, $code )
$c->envoyer_redirection( $loc, $code, $corps_entite )
Envoyer une réponse de redirection au client. L'emplacement ($loc) peut être une URL absolue ou relative. Le $code doit être l'un des codes de statut de redirection, et par défaut "301 Moved Permanently".
$c->envoyer_erreur
$c->envoyer_erreur( $code )
$c->envoyer_erreur( $code, $message_erreur )
Envoyer une réponse d'erreur au client. Si le $code est manquant, une erreur "Bad Request" est signalée. Le $message_erreur est une chaîne qui est incorporée dans le corps de l'entité HTML.
$c->envoyer_reponse_fichier( $nom_fichier )
Envoyer une réponse avec le fichier spécifié $nom_fichier comme contenu. Si le fichier est un répertoire, nous essayons de générer un index HTML de celui-ci.
$c->envoyer_fichier( $nom_fichier )
$c->envoyer_fichier( $fd )
Copier le fichier vers le client. Le fichier peut être une chaîne (qui sera interprétée comme un nom de fichier) ou une référence à un "IO::Handle" ou un glob.
$c->daemon
Retourne une référence à l'objet "HTTP::Daemon" correspondant.

SUPPORT IPv6

Depuis la version 6.05, "HTTP::Daemon" est une sous-classe de "IO::Socket::IP" plutôt que "IO::Socket::INET", de sorte qu'il prend en charge IPv6.

Pour certaines raisons, vous pourriez vouloir forcer "HTTP::Daemon" à écouter uniquement sur les adresses IPv4. Passez alors l'argument "Family" à "HTTP::Daemon->new" :

use HTTP::Daemon;
use Socket 'AF_INET';
my $d = HTTP::Daemon->new(Family => AF_INET);
