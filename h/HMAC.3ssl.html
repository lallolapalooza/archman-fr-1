HMAC(3ssl)

Paquet: openssl

HMAC(3ssl) OpenSSL HMAC(3ssl)

NOM

HMAC, HMAC_CTX_new, HMAC_CTX_reset, HMAC_CTX_free, HMAC_Init, HMAC_Init_ex, HMAC_Update, HMAC_Final, HMAC_CTX_copy, HMAC_CTX_set_flags, HMAC_CTX_get_md, HMAC_size - Code d'authentification de message HMAC

SYNTAXE

#include <openssl/hmac.h>
unsigned char *HMAC(const EVP_MD *evp_md, const void *key, int key_len,
                    const unsigned char *data, size_t data_len,
                    unsigned char *md, unsigned int *md_len);

Les fonctions suivantes ont été dépréciées depuis OpenSSL 3.0, et peuvent être entièrement masquées en définissant OPENSSL_API_COMPAT avec une valeur de version appropriée, voir openssl_user_macros(7):

HMAC_CTX *HMAC_CTX_new(void);
int HMAC_CTX_reset(HMAC_CTX *ctx);
int HMAC_Init_ex(HMAC_CTX *ctx, const void *key, int key_len,
                 const EVP_MD *md, ENGINE *impl);
int HMAC_Update(HMAC_CTX *ctx, const unsigned char *data, size_t len);
int HMAC_Final(HMAC_CTX *ctx, unsigned char *md, unsigned int *len);
void HMAC_CTX_free(HMAC_CTX *ctx);
int HMAC_CTX_copy(HMAC_CTX *dctx, HMAC_CTX *sctx);
void HMAC_CTX_set_flags(HMAC_CTX *ctx, unsigned long flags);
const EVP_MD *HMAC_CTX_get_md(const HMAC_CTX *ctx);
size_t HMAC_size(const HMAC_CTX *e);

La fonction suivante a été dépréciée depuis OpenSSL 1.1.0, et peut être entièrement masquée en définissant OPENSSL_API_COMPAT avec une valeur de version appropriée, voir openssl_user_macros(7):

int HMAC_Init(HMAC_CTX *ctx, const void *key, int key_len,
              const EVP_MD *md);

DESCRIPTION

HMAC est un MAC (code d'authentification de message), c'est-à-dire une fonction de hachage avec clé utilisée pour l'authentification de message, qui est basée sur une fonction de hachage.

HMAC() calcule le code d'authentification de message des key_len octets de data en utilisant la fonction de hachage evp_md et la clé key qui fait key_len octets de long. La key peut également être NULL avec key_len étant 0.

Elle place le résultat dans md (qui doit avoir de la place pour la sortie de la fonction de hachage, qui ne dépasse pas EVP_MAX_MD_SIZE octets). Si md est NULL, le digest est placé dans un tableau statique. La taille de la sortie est placée dans md_len, sauf si elle est NULL. Note : passer une valeur NULL pour md afin d'utiliser le tableau statique n'est pas thread-safe.

evp_md est un digest de message tel que EVP_sha1(), EVP_ripemd160() etc. HMAC ne prend pas en charge les digests à longueur de sortie variable tels que EVP_shake128() et EVP_shake256().

HMAC() utilise le OSSL_LIB_CTX par défaut. Utilisez EVP_Q(3) à la place si un contexte de bibliothèque est requis.

Toutes les fonctions décrites ci-dessous sont dépréciées. Les applications devraient plutôt utiliser EVP_MAC_CTX_new(3), EVP_MAC_CTX_free(3), EVP_MAC_init(3), EVP_MAC_update(3) et EVP_MAC_final(3) ou la fonction MAC "rapide" en une seule passe EVP_Q(3).

HMAC_CTX_new() crée un nouveau HMAC_CTX en mémoire du tas.

HMAC_CTX_reset() efface un HMAC_CTX existant et ses ressources associées, le rendant utilisable pour de nouveaux calculs comme s'il venait d'être créé avec HMAC_CTX_new().

HMAC_CTX_free() efface la clé et les autres données du HMAC_CTX, libère toutes les ressources associées et libère enfin le HMAC_CTX lui-même. Si l'argument est NULL, rien n'est fait.

Les fonctions suivantes peuvent être utilisées si le message n'est pas entièrement stocké en mémoire :

HMAC_Init_ex() initialise ou réutilise une structure HMAC_CTX pour utiliser la fonction de hachage evp_md et la clé key. Si les deux sont NULL, ou si key est NULL et evp_md est le même que lors de l'appel précédent, alors la clé existante est réutilisée. ctx doit avoir été créé avec HMAC_CTX_new() avant la première utilisation d'un HMAC_CTX dans cette fonction.

Si HMAC_Init_ex() est appelée avec key NULL et evp_md n'est pas le même que le digest précédent utilisé par ctx, une erreur est retournée car la réutilisation d'une clé existante avec un digest différent n'est pas prise en charge.

HMAC_Init() initialise une structure HMAC_CTX pour utiliser la fonction de hachage evp_md et la clé key qui fait key_len octets de long.

HMAC_Update() peut être appelée de manière répétée avec des morceaux du message à authentifier (len octets à data).

HMAC_Final() place le code d'authentification du message dans md, qui doit avoir de la place pour la sortie de la fonction de hachage.

HMAC_CTX_copy() copie tout l'état interne de sctx dans dctx.

HMAC_CTX_set_flags() applique les drapeaux spécifiés aux EVP_MD_CTXs internes. Ces drapeaux ont la même signification que pour EVP_MD_CTX_set_flags(3).

HMAC_CTX_get_md() renvoie le EVP_MD qui a été précédemment défini pour le HMAC_CTX fourni.

HMAC_size() renvoie la longueur en octets de la sortie de la fonction de hachage sous-jacente.

VALEURS DE RETOUR

HMAC() renvoie un pointeur vers le code d'authentification du message ou NULL si une erreur s'est produite.

HMAC_CTX_new() renvoie un pointeur vers un nouveau HMAC_CTX en cas de succès ou NULL si une erreur s'est produite.

HMAC_CTX_reset(), HMAC_Init_ex(), HMAC_Update(), HMAC_Final() et HMAC_CTX_copy() renvoient 1 en cas de succès ou 0 si une erreur s'est produite.

HMAC_CTX_get_md() renvoie le EVP_MD précédemment défini pour le HMAC_CTX fourni ou NULL si aucun EVP_MD n'a été défini.

HMAC_size() renvoie la longueur en octets de la sortie de la fonction de hachage sous-jacente ou zéro en cas d'erreur.

CONFORMITÉ

RFC 2104

VOIR AUSSI

SHA1(3), EVP_Q(3), evp(7)

HISTORIQUE

Toutes les fonctions sauf HMAC() ont été dépréciées dans OpenSSL 3.0.

HMAC_CTX_init() a été remplacé par HMAC_CTX_reset() dans OpenSSL 1.1.0.

HMAC_CTX_cleanup() existait dans OpenSSL avant la version 1.1.0.

HMAC_CTX_new(), HMAC_CTX_free() et HMAC_CTX_get_md() sont nouveaux dans OpenSSL 1.1.0.

HMAC_Init_ex(), HMAC_Update() et HMAC_Final() ne renvoyaient pas de valeurs dans OpenSSL avant la version 1.0.0.
