Description détaillée

Plusieurs fonctions peuvent éventuellement être appelées entre hwloc_topology_init() et hwloc_topology_load() pour configurer la manière dont la détection doit être effectuée, par exemple pour ignorer certains types d'objets, définir une topologie synthétique, etc.

Documentation du type énumération

enum hwloc_topology_flags_e

Drapeaux à définir sur un contexte de topologie avant le chargement. Les drapeaux doivent être donnés à hwloc_topology_set_flags(). Ils peuvent également être renvoyés par hwloc_topology_get_flags().

Énumérateur

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Détecter tout le système, ignorer les réservations, inclure les objets non autorisés. Rassembler toutes les ressources en ligne, même si certaines ont été désactivées par l'administrateur. Par exemple, ignorer les Cgroup/Cpusets de Linux et rassembler tous les processeurs et nœuds mémoire. Cependant, les PU et nœuds NUMA hors ligne sont toujours ignorés.

Lorsque ce drapeau n'est pas défini, les PU et nœuds NUMA non autorisés ne sont pas ajoutés à la topologie. Les objets parents (paquet, cœur, cache, etc.) ne sont ajoutés que si certains de leurs enfants sont autorisés. Tous les PU et nœuds NUMA existants dans la topologie sont autorisés. hwloc_topology_get_allowed_cpuset() et hwloc_topology_get_allowed_nodeset() sont égaux au cpuset et au nodeset de l'objet racine.

Lorsque ce drapeau est défini, les ensembles réels de PU et de nœuds NUMA autorisés sont donnés par hwloc_topology_get_allowed_cpuset() et hwloc_topology_get_allowed_nodeset(). Ils peuvent être plus petits que le cpuset et le nodeset de l'objet racine.

Si la topologie actuelle est exportée en XML et réimportée ultérieurement, ce drapeau doit être défini à nouveau dans la topologie réimportée afin que les ressources non autorisées soient également réimportées.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Supposer que le backend sélectionné fournit la topologie du système sur lequel nous exécutons. Cela force hwloc_topology_is_thissystem() à renvoyer 1, c'est-à-dire que hwloc suppose que le backend sélectionné fournit la topologie du système sur lequel nous exécutons, même s'il ne s'agit pas du backend spécifique à l'OS mais du backend XML par exemple. Cela signifie que les fonctions d'attachement appellent réellement les appels système spécifiques à l'OS et effectuent réellement l'attachement, alors que le backend XML fournirait autrement des hooks vides renvoyant simplement le succès.

Définir la variable d'environnement HWLOC_THISSYSTEM peut également entraîner le même comportement.

Cela peut être utilisé pour des raisons d'efficience afin de détecter la topologie une seule fois, de la sauvegarder dans un fichier XML, puis de la recharger rapidement plus tard via le backend XML, tout en ayant les fonctions d'attachement qui effectuent réellement l'attachement.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtenir l'ensemble des ressources autorisées à partir du système d'exploitation local même si la topologie a été chargée à partir de XML ou d'une description synthétique. Si la topologie a été chargée à partir de XML ou d'une chaîne synthétique, la restreindre en appliquant les restrictions du processus actuel telles que les Cgroup/Cpusets de Linux.

C'est utile lorsque la topologie n'est pas chargée directement à partir de la machine locale (par exemple pour des raisons de performance) et qu'elle contient toutes les ressources, alors que le processus en cours d'exécution est limité à seulement une partie de la machine.

Ce drapeau est ignoré sauf si HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM est également défini, car la topologie chargée doit correspondre à la machine sous-jacente d'où les restrictions seront collectées.

Définir la variable d'environnement HWLOC_THISSYSTEM_ALLOWED_RESOURCES entraînerait le même comportement.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importer les fonctionnalités de la topologie importée. Lors de l'importation d'une topologie XML à partir d'une machine distante, l'attachement est désactivé par défaut (voir HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Cette désactivation est également marquée en mettant des zéros dans les bits de fonctionnalités supportées correspondants rapportés par hwloc_topology_get_support().

Le drapeau HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT importe réellement les bits de support depuis la machine distante. Il définit également le drapeau imported_support dans le tableau de la structure hwloc_topology_misc_support . Si le XML importé ne contenait aucune information de support (le hwloc exporteur est trop ancien), ce drapeau n'est pas défini.

Notez que ces fonctionnalités supportées ne sont pertinentes que pour l'installation hwloc qui a effectivement exporté la topologie XML (elles peuvent varier selon le système d'exploitation, ou selon la manière dont hwloc a été compilé).

Notez que définir ce drapeau n'active cependant pas l'attachement pour la topologie hwloc importée localement, il rapporte seulement ce que le hwloc et la machine distante supportent.

HWLOC_TOPOLOGY_FLAGS

Flags for hwloc_topology_set_flags(), hwloc_topology_get_flags(), hwloc_topology_load(), hwloc_topology_restrict(), and hwloc_set_type_filter().

enum hwloc_topology_flags_e

The topology object may be created with various flags. These flags control the discovery process and the resulting topology object.

The flags are passed to hwloc_topology_set_flags() before calling hwloc_topology_load() or are passed directly to hwloc_topology_load().

Enumerator

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
The topology is that of the system where the application is running. This is the default behavior. If this flag is not set, hwloc assumes the topology may be from another system (e.g. loaded from XML). This affects various checks within hwloc, for example, to avoid using OS-specific mechanisms that might not be available or might behave differently on non-native systems.
HWLOC_TOPOLOGY_FLAG_WHOLE_SYSTEM
Discover the entire system topology, even if parts of it are not accessible to the current process. This requires appropriate privileges (e.g. root access). If privileges are insufficient, hwloc will do its best to discover as much as possible, but this flag will essentially be ignored.
This flag is implicitly enabled if the user has root privileges.
HWLOC_TOPOLOGY_FLAG_IO_BRIDGES
Discover I/O bridges. If this flag is set, hwloc will try to discover I/O bridges (PCI bridges, etc.) and insert them into the topology. This discovery requires specific system access (e.g. root privileges on Linux).
This flag is implicitly enabled if the user has root privileges.
HWLOC_TOPOLOGY_FLAG_IO_SYSTEM
Discover I/O devices. If this flag is set, hwloc will try to discover I/O devices (PCI devices, etc.) and insert them into the topology. This discovery requires specific system access (e.g. root privileges on Linux).
This flag is implicitly enabled if the user has root privileges.
HWLOC_TOPOLOGY_FLAG_DISTANCES
Discover distances. If this flag is set, hwloc will try to discover distances between processing units and memory nodes. This discovery uses OS-specific mechanisms and may require specific privileges.
This flag is implicitly enabled if the user has root privileges.
HWLOC_TOPOLOGY_FLAG_ADD_BINDINGS
Add binding information. If this flag is set, hwloc will try to discover the current CPU and memory binding of the process and its ancestors. This information will be stored in the topology object.
HWLOC_TOPOLOGY_FLAG_GROUP_CPU_BINDING
Group NUMA nodes by CPU binding. If this flag is set, hwloc will try to group NUMA nodes that are part of the same CPU binding. This can be useful to get a topology that reflects the process's view of the system.
HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
Do not consider resources outside of the process CPU binding. If the binding of the process is limited to a subset of cores, ignore the other cores during discovery.

The resulting topology is identical to what a call to hwloc_topology_restrict() would generate, but this flag also prevents hwloc from ever touching other resources during the discovery.

This flag especially tells the x86 backend to never temporarily rebind a thread on any excluded core. This is useful on Windows because such temporary rebinding can change the process binding. Another use-case is to avoid cores that would not be able to perform the hwloc discovery anytime soon because they are busy executing some high-priority real-time tasks.

If process CPU binding is not supported, the thread CPU binding is considered instead if supported, or the flag is ignored.

This flag requires HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM as well since binding support is required.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
Do not consider resources outside of the process memory binding. If the binding of the process is limited to a subset of NUMA nodes, ignore the other NUMA nodes during discovery.

The resulting topology is identical to what a call to hwloc_topology_restrict() would generate, but this flag also prevents hwloc from ever touching other resources during the discovery.

This flag is meant to be used together with HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING when both cores and NUMA nodes should be ignored outside of the process binding.

If process memory binding is not supported, the thread memory binding is considered instead if supported, or the flag is ignored.

This flag requires HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM as well since binding support is required.

HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
Do not ever modify the process or thread binding during discovery. This flag disables all hwloc discovery steps that require a change of the process or thread binding. This currently only affects the x86 backend which gets entirely disabled.

This is useful when hwloc_topology_load() is called while the application also creates additional threads or modifies the binding.

This flag is also a strict way to make sure the process binding will not change to due thread binding changes on Windows (see HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING).

HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
Ignore distances. Ignore distance information from the operating systems (and from XML) and hence do not use distances for grouping.
HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
Ignore memory attributes and tiers. Ignore memory attribues from the operating systems (and from XML) Hence also do not try to build memory tiers.
HWLOC_TOPOLOGY_FLAG_NO_CPUKINDS
Ignore CPU Kinds. Ignore CPU kind information from the operating systems (and from XML).

enum hwloc_type_filter_e

Type filtering flags. By default, most objects are kept (HWLOC_TYPE_FILTER_KEEP_ALL). Instruction caches, memory-side caches, I/O and Misc objects are ignored by default (HWLOC_TYPE_FILTER_KEEP_NONE). Group levels are ignored unless they bring structure (HWLOC_TYPE_FILTER_KEEP_STRUCTURE).

Note that group objects are also ignored individually (without the entire level) when they do not bring structure.

Enumerator

HWLOC_TYPE_FILTER_KEEP_ALL
Keep all objects of this type. Cannot be set for HWLOC_OBJ_GROUP (groups are designed only to add more structure to the topology).
HWLOC_TYPE_FILTER_KEEP_NONE
Ignore all objects of this type. The bottom-level type HWLOC_OBJ_PU, the HWLOC_OBJ_NUMANODE type, and the top-level type HWLOC_OBJ_MACHINE may not be ignored.
HWLOC_TYPE_FILTER_KEEP_STRUCTURE
Only ignore objects if their entire level does not bring any structure. Keep the entire level of objects if at least one of these objects adds structure to the topology. An object brings structure when it has multiple children and it is not the only child of its parent.

If all objects in the level are the only child of their parent, and if none of them has multiple children, the entire level is removed.

Cannot be set for I/O and Misc objects since the topology structure does not matter there.

HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Only keep likely-important objects of the given type. It is only useful for I/O object types. For HWLOC_OBJ_PCI_DEVICE and HWLOC_OBJ_OS_DEVICE, it means that only objects of major/common kinds are kept (storage, network, OpenFabrics, CUDA, OpenCL, RSMI, NVML, and displays). Also, only OS devices directly attached on PCI (e.g. no USB) are reported. For HWLOC_OBJ_BRIDGE, it means that bridges are kept only if they have children.

This flag equivalent to HWLOC_TYPE_FILTER_KEEP_ALL for Normal, Memory and Misc types since they are likely important.

const struct hwloc_topology_support * hwloc_topology_get_support (hwloc_topology_t restrict topology)

Retrieve the topology support. Each flag indicates whether a feature is supported. If set to 0, the feature is not supported. If set to 1, the feature is supported, but the corresponding call may still fail in some corner cases.

These features are also listed by hwloc-info --support

The reported features are what the current topology supports on the current machine. If the topology was exported to XML from another machine and later imported here, support still describes what is supported for this imported topology after import. By default, binding will be reported as unsupported in this case (see HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM).

Topology flag HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT may be used to report the supported features of the original remote machine instead. If it was successfully imported, imported_support will be set in the struct hwloc_topology_misc_support array.

Returns

A pointer to a support structure.

Note

The function cannot return NULL.

The returned pointer should not be freed, it belongs to the hwloc library.

This function may be called before or after hwloc_topology_load() but the support structure only contains valid information after.

int hwloc_topology_set_flags (hwloc_topology_t topology, unsigned long flags)

Définit des drapeaux combinés par un OU (OR) sur une topologie pas encore chargée. Définit un ensemble de drapeaux combinés par un OU (OR) de hwloc_topology_flags_e sur une topologie qui n'a pas encore été chargée.

Définit le pointeur de données utilisateur spécifique à la topologie. Chaque topologie peut stocker un pointeur de données privées fourni par l'application. Il est initialisé à NULL. hwloc ne le modifiera jamais.
