Côté hôte d'un pont, uniquement possible en amont.
HWLOC_OBJ_BRIDGE_PCI

Énumérateur

Cache unifié.
HWLOC_OBJ_CACHE_DATA
Cache de données.
HWLOC_OBJ_CACHE_INSTRUCTION
Cache d'instructions (filtré par défaut).

enum hwloc_obj_osdev_type_e

Type d'un périphérique du système d'exploitation.

Énumérateur

HWLOC_OBJ_OSDEV_BLOCK
Périphérique de bloc du système d'exploitation, ou périphérique de mémoire non volatile. Par exemple 'sda' ou 'dax2.0' sous Linux.
HWLOC_OBJ_OSDEV_GPU
Périphérique GPU du système d'exploitation. Par exemple ':0.0' pour un affichage GL, 'card0' pour un périphérique DRM Linux.
HWLOC_OBJ_OSDEV_NETWORK
Périphérique réseau du système d'exploitation. Par exemple l'interface 'eth0' sous Linux.
HWLOC_OBJ_OSDEV_OPENFABRICS
Périphérique openfabrics du système d'exploitation. Par exemple le HCA InfiniBand 'mlx4_0', l'interface Omni-Path 'hfi1_0', ou le HCA BXI Atos/Bull 'bxi0' sous Linux.
HWLOC_OBJ_OSDEV_DMA
Périphérique moteur DMA du système d'exploitation. Par exemple le canal DMA 'dma0chan0' sous Linux.
HWLOC_OBJ_OSDEV_COPROC
Périphérique coprocesseur du système d'exploitation. Par exemple 'opencl0d0' pour un périphérique OpenCL, 'cuda0' pour un périphérique CUDA.

enum hwloc_obj_type_t

Type d'objet de topologie.

Note

Ne vous fiez pas à l'ordre ou à l'exhaustivité des valeurs car de nouvelles pourraient être définies à l'avenir ! Si vous devez comparer des types, utilisez plutôt hwloc_compare_types().

Énumérateur

HWLOC_OBJ_MACHINE
Machine. Un ensemble de processeurs et de mémoire avec cohérence de cache. Ce type est toujours utilisé pour l'objet racine d'une topologie, et n'est jamais utilisé ailleurs. Par conséquent, son parent est toujours NULL.
HWLOC_OBJ_PACKAGE
Paquet physique. Le paquet physique qui est généralement inséré dans un socket sur la carte mère. Un paquet de processeur contient généralement plusieurs cœurs, et potentiellement plusieurs dies.
HWLOC_OBJ_CORE
Cœur. Une unité de calcul (peut être partagée par plusieurs PU, alias processeurs logiques).
HWLOC_OBJ_PU
Unité de Traitement, ou Processeur (Logique). Une unité d'exécution (peut partager un cœur avec d'autres processeurs logiques, par exemple dans le cas d'un cœur SMT). C'est le plus petit objet représentant des ressources CPU, il ne peut avoir aucun enfant sauf des objets Misc.

Les objets de ce type sont toujours rapportés et peuvent donc être utilisés comme solution de repli lorsque d'autres ne le sont pas.

Cache de niveau 1 de données (ou unifié).
HWLOC_OBJ_L2CACHE
Cache de niveau 2 de données (ou unifié).
HWLOC_OBJ_L3CACHE
Cache de niveau 3 de données (ou unifié).
HWLOC_OBJ_L4CACHE
Cache de niveau 4 de données (ou unifié).

int hwloc_compare_types (hwloc_obj_type_t type1, hwloc_obj_type_t

type2)

Compare la profondeur de deux types d'objets. Les types ne devraient pas être comparés tels quels, car de nouveaux pourraient être ajoutés à

l'avenir.

Renvoi

e
Un entier négatif si les objets de type1 incluent généralement les objets de type2.

Un entier positif si les objets de type1 sont généralement inclus dans les objets de

type2.

0 si les objets de type1 et type2 sont les

mêmes.

HWLOC_TYPE_UNORDERED si les objets ne peuvent pas être compa

rés (car aucun n'est génér
alement contenu dans l'autre).

Not

e
Les types d'objets contenant des CPU peuvent toujours être comparés (généralement, une machine contient des boîtiers, qui contiennent des caches, qui contiennent des cœurs, qui contiennent des PU).

HWLOC_OBJ_PU sera toujours le plus profond, tandis que HWLOC_OBJ_MACHINE est toujours le plus

haut.

Cela ne signifie pas que la topologie réelle respecte

ra cet ordre : par ex. aujourd'hui les cœurs peuve
nt aussi contenir des caches, et les boîtiers peuvent
aussi contenir des nœuds. C'est donc juste à cons
idérer comme une méthode de comparaison de secours.
