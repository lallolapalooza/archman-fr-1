Hash::Merge - Fusionne des

hashes de profondeur arbi
traire en un hash unique

SYNOPSI

S 
my %a = (
    'foo'    => 1,
    'bar'    => [qw( a b e )],
    'querty' => { 'bob' => 'alice' },
);
my %b = (
    'foo'    => 2,
    'bar'    => [qw(c d)],
    'querty' => { 'ted' => 'margeret' },
);

my %c = %{ merge( \%a, \%b ) };

Hash::Merge::set_behavior('RIGHT_PRECEDENT');

# Ceci est équivalent à ce qui précède

Hash::Merge::add_behavior_spec(
    {   'SCALAR' => {
            'SCALAR' => sub { $_[1] },
            'ARRAY'  => sub { [ $_[0], @{ $_[1] } ] },
            'HASH'   => sub { $_[1] },
        },
        'ARRAY' => {
            'SCALAR' => sub { $_[1] },
            'ARRAY'  => sub { [ @{ $_[0] }, @{ $_[1] } ] },
            'HASH'   => sub { $_[1] },
        },
        'HASH' => {
            'SCALAR' => sub { $_[1] },
            'ARRAY'  => sub { [ values %{ $_[0] }, @{ $_[1] } ] },
            'HASH'   => sub { Hash::Merge::_merge_hashes( $_[0], $_[1] ) },
        },
    },
    'Mon comportement',
);

# Il existe également une interface orientée objet.

my $merger = Hash::Merge->new('LEFT_PRECEDENT');
my %c = %{ $merger->merge( \%a, \%b ) };

# Tous les changements de comportement (par ex. $merge->set_behavior(...)) appelés sur un objet restent spécifiques à cet objet
# L'ancien comportement de "réglage global" n'est respecté que lorsque new est appelé en tant que fonction non orientée objet.
# réutiliser le comportement spécifié globalement
my $merger = Hash::Merge->new();
$merger->add_behavior_spec(Hash::Merge::get_behavior_spec("Mon comportement"), "Mon comportement");
my %c = %{ $merger->merge( \%a, \%b ) };
# réutiliser un comportement spécifié externe
use Hash::Merge::Extra ();
my $merger = Hash::Merge->new();
$merger->add_behavior_spec(Hash::Merge::Extra::L_REPLACE, "L_REPLACE");
my %c = %{ $merger->merge( \%a, \%b )
}
;

DESCRIPTIO

N

Hash::Merge fusionne deux hashes de profondeur arbitraire en un hash unique. C'est-à-dire qu'à tout niveau, il ajoutera les paires clé-valeur non conflictuelles d'un hash à l'autre, et suit un ensemble de règles spécifiques en cas de conflit de clés et de valeurs (comme détaillé ci-dessous). Le hash est parcouru récursivement, de sorte que les hashes imbriqués profondément et situés au même niveau seront fusionnés lorsque les hashes parents seront fusionnés. Veuillez noter que les hashes auto-référentiels ou les références récursives ne sont pas bien gérés par cette

méthode.

Les valeurs dans les hashes sont considérées comme étant soit des références ARRAY, soit des références HASH, soit traitées comme des SCALARs. Par défaut, les données passées à la fonction de fusion seront clonées à l'aide du module Clone ; cependant, si nécessaire, ce comportement peut être modifié pour utiliser autant de valeurs originales que possible. (Voir "set_clone_beha

vior").

Étant donné qu'il existe plusieurs façons possibles de vouloir fusionner des valeurs lorsque les clés sont en conflit, Hash::Merge fournit plusieurs méthodes prédéfinies pour votre commodité, ainsi qu'un moyen de définir les vôtres. Ce sont (actuellement)

:
Précédence
gauche
C'est le comportement par défaut.

Les valeurs enfouies dans le hash de gauche ne seront jamais perdues ; toutes les valeurs pouvant être ajoutées depuis le hash de droite tenteront d'être

ajoutées. 
my $merge = Hash::Merge->new();
my $merge = Hash::Merge
->new('LEFT_PRECEDENT'); $merge->set_behavior('LEFT_PR
ECEDENT'); Hash::Merge::set_behavior('LEFT_PRECEDENT');
Précédence
droite
Identique à la précédence gauche, mais avec les valeurs du hash de droite jamais perdues 
my $merge = Hash::Merge->new('RIGHT_PRECEDENT
'); $merge->set_behavior('RIGHT_PRECEDENT');
Hash::Merge::set_behavior('RIGHT_PRECEDENT');
Précédence de
stockage
Si des clés conflictuelles ont deux supports de stockage différents, le support le plus 'grand' l'emportera ; les tableaux sont préférés aux scalaires, les hashes à l'un et à l'autre. L'autre support essaiera d'être adapté dans l'autre, mais si ce n'est pas possible, les données sont abandonnées. 
my $merge = Hash::Merge->new('STORAGE_PRECEDENT
'); $merge->set_behavior('STORAGE_PRECEDENT');
Hash::Merge::set_behavior('STORAGE_PRECEDENT');
Précédence de
conservation
Aucune donnée ne sera perdue ; les scalaires seront joints aux tableaux, et les scalaires et les tableaux seront 'hashifiés' pour les faire entrer dans un hash. 
my $merge = Hash::Merge->new('RETAINME
NT_PRECEDENT'); $merge->set_behavior(
'RETAINMENT_PRECEDENT'); Hash::Merge:
:set_behavior('RETAINMENT_PRECEDENT');

Des descriptions spécifiques du fonctionnement de ces méthodes sont détaillées

ci-dessous.
merge ( <hashref>, <hashref>
)
Fusionne deux hashes selon les règles spécifiées. Renvoie une référence vers le nouveau
hash.
_hashify( <scalar>|<arrayref> ) -- FONCTION
INTERNE
Renvoie une référence vers un hash créé à partir du scalaire ou de la référence de tableau, où, pour la valeur scalaire, ou chaque élément du tableau, il y a une clé et sa valeur égales à cette valeur spécifique. Exemple, si vous passez le scalaire '3', le hash sera { 3 =>
3 }.
_merge_hashes( <hashref>, <hashref> ) -- FONCTION
INTERNE
Effectue réellement l'évaluation clé par clé de deux hashes et renvoie le nouveau hash fusionné. Notez que cela appelle récursivement "merge
".
set_clone_behavior( <scalar>
)
Définit la manière dont le clonage des données est géré par Hash::Merge. Si c'est vrai, les données seront clonées ; si c'est faux, les données d'origine seront utilisées chaque fois que possible. Par défaut, le clonage est activé (réglé sur
vrai).
get_clone_behavior(
)
Renvoie le comportement actuel pour le clonage des
données.
set_behavior( <scalar>
)
Spécifie le comportement intégré de fusion désiré. Le scalaire doit être l'un de ceux donnés
ci-dessous.
get_behavior(
)
Renvoie le comportement actuellement utilisé par Hash::
Merge.
specify_behavior( <hashref>, [<nom>] )
[obsolète]
Alias pour "add_behavior
_spec".
add_behavior_spec( <hashref>, [<nom>
] )
Ajoute une spécification de comportement de fusion personnalisée pour Hash::Merge. Cela doit être un hashref défini avec (au moins) 3 clés : SCALAR, ARRAY et HASH ; chacune de ces clés doit avoir un autre hashref avec (au moins) les mêmes 3 clés définies. De plus, les valeurs dans ces hashes doivent être des références de code. Celles-ci seront appelées avec deux arguments, les valeurs de gauche et de droite pour la fusion. Votre référence de code doit renvoyer soit un scalaire, soit une référence de tableau ou de hash selon votre comportement prévu. Si nécessaire, utilisez les fonctions _hashify et _merge_hashes comme fonctions d'aide pour celles-ci. Par exemple, si vous voulez ajouter le SCALAR de gauche à l'ARRAY de droite, votre spécification de comportement peut inclure : 
%spec = ( ...SCALAR => { ARRAY => sub { [ $_[0], @$_[1] ] }, ... }
} );

Notez que vous pouvez importer _hashify et

_merge_hashes dans l'espace de noms
de votre programme avec la balise 'custom'.
get_behavior_spec( [<nom>
] )
Renvoie une spécification de comportement de fusion définie précédemment. Si le nom n'est pas spécifié, le même défaut que pour add_behavior_spec est appliqué.

Si aucun nom connu

ne correspond à une
spécification de co
mportement,
rien n'est renvoyé.

COMPORTEMENTS

INTÉGRÉS

Voici les détails sur la manière dont les comportements internes actuels sont appelés, et ce que chacun fait. Supposons que la valeur de gauche est donnée comme $a, et celle de droite comme $b (ce sont soit des scalaires, soit des références

appropriées) 
TYPE DE GAUCHE    TYPE DE DROITE    LEFT_PRECEDENT       RIGHT_PRECEDENT
 SCALAR       SCALAR        $a                   $b
 SCALAR       ARRAY         $a                   ( $a, @$b )
 SCALAR       HASH          $a                   %$b
 ARRAY        SCALAR        ( @$a, $b )          $b
 ARRAY        ARRAY         ( @$a, @$b )         ( @$a, @$b )
 ARRAY        HASH          ( @$a, values %$b )  %$b
 HASH         SCALAR        %$a                  $b
 HASH         ARRAY         %$a                  ( values %$a, @$b )
 HASH         HASH          merge( %$a, %$b )    merge( %$a, %$b )
TYPE DE GTYPE    TYPE DE DROITE    PRÉCÉDENCE_STOCKAGE    PRÉCÉDENCE_CONSERVATION
 SCALAIRE       SCALAIRE        $a                   ( $a ,$b )
 SCALAIRE       TABLEAU         ( $a, @$b )          ( $a, @$b )
 SCALAIRE       HASH            %$b                  merge( hashify( $a ), %$b )
 TABLEAU        SCALAIRE        ( @$a, $b )          ( @$a, $b )
 TABLEAU        TABLEAU         ( @$a, @$b )         ( @$a, @$b )
 TABLEAU        HASH            %$b                  merge( hashify( @$a ), %$b )
 HASH           SCALAIRE        %$a                  merge( %$a, hashify( $b ) )
 HASH           TABLEAU         %$a                  merge( %$a, hashify( @$b ) )
 HASH           HASH            merge( %$a, %$b )    merge( %$a, %$b
)

(*) notez que merge app

elle _merge_hashes, hash
ify appelle _hashify.
