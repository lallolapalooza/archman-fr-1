Description détaillée

Plusieurs fonctions peuvent être appelées optionnellement entre hwloc_topology_init() et hwloc_topology_load() pour configurer la manière dont la détection doit être effectuée, par exemple pour ignorer certains types d'objets, définir une topologie synthétique, etc.

Documentation du type énuméré

enum hwloc_topology_flags_e

Indicateurs à définir sur un contexte de topologie avant le chargement. Les indicateurs doivent être passés à hwloc_topology_set_flags(). Ils peuvent également être retournés par hwloc_topology_get_flags().

Énumérateur

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Détecter l'ensemble du système, ignorer les réservations, inclure les objets non autorisés. Collecter toutes les ressources en ligne, même si certaines ont été désactivées par l'administrateur. Par exemple, ignorer les Cgroup/Cpusets Linux et collecter tous les processeurs et nœuds mémoire. Cependant, les PU et nœuds NUMA hors ligne sont toujours ignorés.

Lorsque cet indicateur n'est pas défini, les PU et les nœuds NUMA qui ne sont pas autorisés ne sont pas ajoutés à la topologie. Les objets parents (package, core, cache, etc.) sont ajoutés uniquement si certains de leurs enfants sont autorisés. Toutes les PU et nœuds NUMA existants dans la topologie sont autorisés. hwloc_topology_get_allowed_cpuset() et hwloc_topology_get_allowed_nodeset() sont égaux aux cpuset et nodeset de l'objet racine.

Lorsque cet indicateur est défini, les ensembles réels de PU et de nœuds NUMA autorisés sont donnés par hwloc_topology_get_allowed_cpuset() et hwloc_topology_get_allowed_nodeset(). Ils peuvent être plus petits que les cpuset et nodeset de l'objet racine.

Si la topologie actuelle est exportée en XML et réimportée plus tard, cet indicateur doit être redéfini dans la topologie réimportée afin que les ressources non autorisées soient également réimportées.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Supposer que le backend sélectionné fournit la topologie du système sur lequel nous nous exécutons. Ceci force hwloc_topology_is_thissystem() à retourner 1, c'est-à-dire fait supposer à hwloc que le backend sélectionné fournit la topologie du système sur lequel nous nous exécutons, même s'il ne s'agit pas du backend spécifique au système d'exploitation, mais du backend XML par exemple. Cela signifie que les fonctions de liaison appellent réellement les appels système spécifiques au système d'exploitation et effectuent réellement la liaison, alors que le backend XML fournirait autrement des crochets vides qui ne feraient que retourner succès.

La définition de la variable d'environnement HWLOC_THISSYSTEM peut également aboutir au même comportement.

Ceci peut être utilisé pour des raisons d'efficacité afin de détecter d'abord la topologie une fois, de la sauvegarder dans un fichier XML, et de la recharger rapidement plus tard via le backend XML, tout en ayant toujours les fonctions de liaison qui effectuent réellement la liaison.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtenir l'ensemble des ressources autorisées du système d'exploitation local, même si la topologie a été chargée à partir d'une description XML ou synthétique. Si la topologie a été chargée à partir d'un XML ou d'une chaîne synthétique, restreignez-la en appliquant les restrictions du processus actuel telles que les Cgroup/Cpuset Linux.

Ceci est utile lorsque la topologie n'est pas chargée directement depuis la machine locale (par exemple, pour des raisons de performance) et qu'elle contient toutes les ressources, tandis que le processus en cours est limité à certaines parties de la machine.

Cet indicateur est ignoré à moins que HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM ne soit également défini, car la topologie chargée doit correspondre à la machine sous-jacente à partir de laquelle les restrictions seront collectées.

La définition de la variable d'environnement HWLOC_THISSYSTEM_ALLOWED_RESOURCES aboutirait au même comportement.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importer le support depuis la topologie importée. Lors de l'importation d'une topologie XML provenant d'une machine distante, la liaison est désactivée par défaut (voir HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Cette désactivation est également marquée en mettant des zéros dans les bits de fonctionnalités supportées correspondants retournés par hwloc_topology_get_support().

L'indicateur HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT importe en fait les bits de support de la machine distante. Il définit également l'indicateur imported_support dans le tableau de la structure hwloc_topology_misc_support. Si le XML importé ne contenait aucune information de support (l'exportateur hwloc est trop ancien), cet indicateur n'est pas défini.

Notez que ces fonctionnalités supportées ne sont pertinentes que pour l'installation hwloc qui a réellement exporté la topologie XML (cela peut varier en fonction du système d'exploitation, ou de la manière dont hwloc a été compilé).

Notez que la définition de cet indicateur n'active pas la liaison pour la topologie hwloc importée localement, elle rapporte seulement ce que le hwloc et la machine distante supportent.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
Ne pas considérer les ressources en dehors de la liaison CPU du processus. Si la liaison du processus est limitée à un sous-ensemble de cœurs, ignorer les autres cœurs pendant la détection

La topologie résultante est identique à celle qu'une appel à hwloc_topology_restrict() générerait, mais ce drapeau empêche également hwloc de toucher d'autres ressources pendant la découverte.

Ce drapeau indique spécifiquement au backend x86 de ne jamais déplacer temporairement un thread sur un cœur exclu. Ceci est utile sous Windows car un tel déplacement temporaire peut modifier le déplacement du processus. Un autre cas d'utilisation est d'éviter les cœurs qui ne seraient pas en mesure d'effectuer la découverte hwloc dans l'immédiat car ils sont occupés à exécuter des tâches temps réel à haute priorité.

Si le déplacement CPU du processus n'est pas supporté, le déplacement CPU du thread est considéré s'il est supporté, sinon le drapeau est ignoré.

Ce drapeau nécessite également HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM puisque le support de déplacement est requis.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
Ne pas considérer les ressources extérieures au déplacement mémoire du processus. Si le déplacement du processus est limité à un sous-ensemble de nœuds NUMA, ignorer les autres nœuds NUMA pendant la découverte.

La topologie résultante est identique à celle qu'une appel à hwloc_topology_restrict() générerait, mais ce drapeau empêche également hwloc de toucher d'autres ressources pendant la découverte.

Ce drapeau est destiné à être utilisé conjointement avec HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING lorsque les cœurs et les nœuds NUMA doivent être ignorés en dehors du déplacement du processus.

Si le déplacement mémoire du processus n'est pas supporté, le déplacement mémoire du thread est considéré s'il est supporté, sinon le drapeau est ignoré.

Ce drapeau nécessite également HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM puisque le support de déplacement est requis.

HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
Ne jamais modifier le déplacement du processus ou du thread pendant la découverte. Ce drapeau désactive toutes les étapes de découverte hwloc qui nécessitent un changement du déplacement du processus ou du thread. Cela affecte actuellement uniquement le backend x86 qui est entièrement désactivé.

Ceci est utile lorsque hwloc_topology_load() est appelé alors que l'application crée également des threads supplémentaires ou modifie le déplacement.

Ce drapeau est également une manière stricte de s'assurer que le déplacement du processus ne changera pas en raison des changements de déplacement de thread sous Windows (voir HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING).

HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
Ignorer les distances. Ignorer les informations de distance des systèmes d'exploitation (et de XML) et donc ne pas utiliser les distances pour le groupement.
HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
Ignorer les attributs mémoire et les niveaux mémoire. Ignorer les attributs mémoire des systèmes d'exploitation (et de XML). Par conséquent, ne pas essayer de construire des niveaux mémoire.
HWLOC_TOPOLOGY_FLAG_NO_CPUKINDS
Ignorer les types de CPU. Ignorer les informations de type de CPU des systèmes d'exploitation (et de XML).

enum hwloc_type_filter_e

Drapeaux de filtrage de type. Par défaut, la plupart des objets sont conservés (HWLOC_TYPE_FILTER_KEEP_ALL). Les caches d'instructions, les caches côté mémoire, les objets I/O et Misc sont ignorés par défaut (HWLOC_TYPE_FILTER_KEEP_NONE). Les niveaux de groupe sont ignorés à moins qu'ils n'apportent de la structure (HWLOC_TYPE_FILTER_KEEP_STRUCTURE).

Notez que les objets de groupe sont également ignorés individuellement (sans le niveau entier) lorsqu'ils n'apportent pas de structure.

Énumérateur

HWLOC_TYPE_FILTER_KEEP_ALL
Conserver tous les objets de ce type. Ne peut pas être défini pour HWLOC_OBJ_GROUP (les groupes sont conçus uniquement pour ajouter plus de structure à la topologie).
HWLOC_TYPE_FILTER_KEEP_NONE
Ignorer tous les objets de ce type. Le type de niveau inférieur HWLOC_OBJ_PU, le type HWLOC_OBJ_NUMANODE et le type de niveau supérieur HWLOC_OBJ_MACHINE ne peuvent pas être ignorés.
HWLOC_TYPE_FILTER_KEEP_STRUCTURE
Ignorer uniquement les objets si leur niveau entier n'apporte aucune structure. Conserver le niveau entier d'objets si au moins un de ces objets ajoute de la structure à la topologie. Un objet apporte de la structure lorsqu'il a plusieurs enfants et qu'il n'est pas le seul enfant de son parent.

Si tous les objets du niveau sont le seul enfant de leur parent, et si aucun d'entre eux n'a plusieurs enfants, le niveau entier est supprimé.

Ne peut pas être défini pour les objets I/O et Misc car la structure de la topologie n'a pas d'importance.

HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Ne conserver que les objets probablement importants du type donné. Ceci est uniquement utile pour les types d'objets I/O. Pour HWLOC_OBJ_PCI_DEVICE et HWLOC_OBJ_OS_DEVICE, cela signifie que seuls les objets de types majeurs/courants sont conservés (stockage, réseau, OpenFabrics, CUDA, OpenCL, RSMI, NVML, et écrans). De plus, seuls les périphériques OS directement connectés sur PCI (par exemple, pas USB) sont rapportés. Pour HWLOC_OBJ_BRIDGE, cela signifie que les ponts ne sont conservés que s'ils ont des enfants.

Ce drapeau est équivalent à HWLOC_TYPE_FILTER_KEEP_ALL pour les types Normaux, Mémoire et Misc car ils sont probablement importants.

HWLOC_TYPE_FILTER_KEEP_ALL(3)

NAME

hwloc_topology_set_all_types_filter, hwloc_topology_set_cache_types_filter, hwloc_topology_set_flags, hwloc_topology_set_icache_types_filter, hwloc_topology_set_io_types_filter, hwloc_topology_set_type_filter, hwloc_topology_set_userdata - modify topology object filtering and userdata

SYNOPSIS

#include <hwloc.h>

int
hwloc_topology_set_all_types_filter(struct hwloc_topology *topology,
    enum hwloc_type_filter_e filter);

int
hwloc_topology_set_cache_types_filter(struct hwloc_topology *topology,
    enum hwloc_type_filter_e filter);

int
hwloc_topology_set_flags(struct hwloc_topology *topology,
    unsigned long flags);

int
hwloc_topology_set_icache_types_filter(struct hwloc_topology *topology,
    enum hwloc_type_filter_e filter);

int
hwloc_topology_set_io_types_filter(struct hwloc_topology *topology,
    enum hwloc_type_filter_e filter);

int
hwloc_topology_set_type_filter(struct hwloc_topology *topology,
    hwloc_obj_type_t type, enum hwloc_type_filter_e filter);

void
hwloc_topology_set_userdata(struct hwloc_topology *topology,
    const void *userdata);

DESCRIPTION

This functions let the user modify the filtering of topology objects according to their type, set flags on the topology object, or attach private user data.

hwloc_topology_set_all_types_filter() sets the filtering for all object types. If some types do not support this filtering, they are silently ignored.

hwloc_topology_set_cache_types_filter() sets the filtering for all CPU cache object types. Memory-side caches are not involved since they are not CPU caches.

hwloc_topology_set_icache_types_filter() sets the filtering for all CPU instruction cache object types. Memory-side caches are not involved since they are not CPU caches.

hwloc_topology_set_io_types_filter() sets the filtering for all I/O object types.

hwloc_topology_set_type_filter() sets the filtering for the given object type.

hwloc_topology_set_flags() sets OR'ed flags to a topology that has not yet been loaded. If this function is called multiple times, the last invocation will erase and replace the set of flags that was previously set. By default, no flags are set (0). The flags set in a topology may be retrieved with hwloc_topology_get_flags().

hwloc_topology_set_userdata() sets the topology-specific userdata pointer. Each topology may store one application-given private data pointer. It is initialized to NULL. hwloc will never modify it. Use it as you wish, after hwloc_topology_init() and until hwloc_topolog_destroy(). This pointer is not exported to XML.

The filter argument MUST be one of:

  • HWLOC_TYPE_FILTER_KEEP_ALL: Keep all objects of the given type.
  • HWLOC_TYPE_FILTER_REMOVE_ALL: Remove all objects of the given type.
  • HWLOC_TYPE_FILTER_KEEP_IMPORTANT: Keep only important objects of the given type.
  • HWLOC_TYPE_FILTER_REMOVE_IMPORTANT: Remove only important objects of the given type.

The available flags for hwloc_topology_set_flags() are defined in hwloc_topology_flags_e.

See also hwloc_topology_get_type_or_above_filter(3).

RETURN VALUES

On success, these functions return 0. On error, they return -1 (for example, if flags are invalid).
