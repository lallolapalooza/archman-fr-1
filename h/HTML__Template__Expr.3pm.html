HTML::Template::Expr - Extension de HTML::Template ajoutant la prise en

charge des expressions

SYN

OP
SIS

use HTML::Template::Expr; my $template = HTML::Template::Expr->new(filename => 'foo.tmpl'); $template->param(banana_count => 10); print

$template->output(); 
DESC
RIP
TION

Ce module fournit une extension à HTML::Template qui permet d'utiliser des expressions dans la syntaxe des gabarits. Il s'agit purement d'un ajout - toutes les options, la syntaxe et les comportements normaux de HTML::Template continuent de fonctionner. Voir HTML::Template

pour plus de détails.

La prise en charge des expressions inclut les comparaisons, les opérations mathématiques, les opérations sur les chaînes et un mécanisme vous permettant d'ajouter vos propres fonctions à l'exécution. La syntaxe de base est

:

<TMPL_IF EXPR="banana_count > 10"> J'ai beaucoup de bananes.

</TMPL_IF> 
Cela affichera "J'ai beaucoup de bananes" si vous appelez
:

$template->param(banana_count => 100)

; 
Dans votre script. Les <TMPL_VAR> fonctionnent aussi avec les expressions
:

Je voudrais avoir <TMPL_VAR EXPR="banana_count * 2">

bananes. 
Cela affichera "Je voudrais avoir 200 bananes." avec le même
appel

param() que ci-

des
sus.

MOTIVATIO

N

Certains d'entre vous se demandent peut-être si j'ai été remplacé par un pod. Juste pour l'information, je pense toujours que ce genre de choses devrait être évité. Cependant, je reconnais qu'il existe des situations où permettre à l'auteur du gabarit une certaine latitude programmatique peut être

inestimable.

Si vous n'aimez pas cela, n'utilisez pas ce module. Continuez à utiliser le bon vieux HTML::Template - je

sais que je le ferai ! Cependant, si vous vous retrouvez à avoir besoin d'un peu de programmation dans votr
e gabarit, pour quelque raison que ce soit, alors ce module pourrait peut-être vous sauver de HTML::Mason.

SYNTAXE DE

BASE

Les variables sont des chaînes alphanumériques non quotées avec les mêmes restrictions que les noms de variables dans HTML::Template. Leurs valeurs sont définies via param(

) 
, tout comme les variables HTML::Template normales. Par exemple, ces deux lignes sont équivalentes
:

<TMPL_VAR EXPR="foo"> <TMPL_VAR

NAME="foo"> 
Les nombres sont des chaînes non quotées de chiffres et peuvent avoir un seul "." pour indiquer un nombre à virgule flottante. Par
exemple :

<TMPL_VAR EXPR="10 + 20.

5"> 
Les constantes de chaînes doivent être entourées de guillemets, simples ou doubles. Par exemple
:

<TMPL_VAR EXPR="sprintf('%d', foo)

"> 
Vous pouvez enchaîner des opérateurs pour produire des booléens complexes
:

<TMPL_IF EXPR="(foo || bar || baz || (bif

&& bing) || (bananas > 10))"> Je sui
s dans une situation complexe. </TMPL_IF>

L'analyseur est assez simple, vous devrez donc peut-être utiliser des parenthèses pour obtenir la priorité

désirée.

Pour définir une nouvelle fonction, passez une

option 
"functions
"

à new

: 
$t = HTML::Template::Expr->new(filename => 'foo.tmpl',
                               functions => 
                                 { func_name =>
\&func_handler
});

Ou, vous pouvez utiliser la méthode de

classe

"register_function" pour enregistrer la fonction globalement

HTML::Template::Expr->register_function(func_name => \&func_handler)
;

Vous fournissez une référence à une sous-routine qui sera appelée lors de la sortie. Elle recevra en arguments les paramètres spécifiés dans le gabarit. Par exemple, voici une fonction qui vérifie si un répertoire existe : sub directory_exists { my $dir_name = shift; return 1 if -d $dir_name; return 0;

} 
Si vous appelez HTML::Template::
Expr->

new(

)

argument

"functions": $t = HTML::Template::Expr->new(filename => 'foo.tmpl', functions => { directory_exists => \&directory_exists

}); 
Alors vous pouvez l'utiliser dans votre gabarit
:

<tmpl_if expr="directory_exists('/home/sam')

"> 
Cela peut être abusé de manière à me faire grincer des
dents.

ASTUCE

POUR M
OD_PERL

La méthode de classe "register_functi

on"

peut être appelée dans le fichier startup.pl de mod_perl pour définir des fonctions communes largement utilisées pour HTML::Template::Expr. Ajoutez quelque chose comme ceci à votre startup.pl

: 
use HTML::Template::Expr;
HTML::Template::Expr->register_function(foozicate => sub { ... });
HTML::Template::Expr->register_function(barify    => sub { ... });
HTML::Template::Expr->register_function(baznate   => sub { ... })
;

Vous pourriez aussi vouloir précompiler certains ga

barits couramment utilisés et les mettre en cache. V
oir la FAQ de HTML::Template pour les instructions.

AVERTISSEMEN

TS

Actuellement, le module force l'activation de l'option global_vars de HTML::Template. Cela disparaîtra espérons-le dans une version future, donc si vous avez besoin de global_vars dans vos gabarits, vous devriez l'activer

explicitement.

Le module ne fonctionnera pas avec les modes file_cache ou shared_cache de HTML::Template, mais la mise en cache normale en mémoire devrait fonctionner. J'espère traiter cela dans une version

future.

Le module est inefficace, tant dans l'analyse que dans l

'évaluation. Je travaillerai là-dessus pour les futures
versions et les correctifs sont toujours les bienvenus.
