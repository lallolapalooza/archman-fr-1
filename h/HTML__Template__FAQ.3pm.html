NOM

HTML::Template::FAQ - Foire Aux Questions sur HTML::Template

SYNOPSIS

Dans le but de favoriser une meilleure compréhension, j'ai commencé une section FAQ dans la documentation perl. Veuillez la consulter avant de m'envoyer un courriel.

FOIRE AUX QUESTIONS

Existe-t-il un endroit où discuter de HTML::Template et/ou obtenir de l'aide ?

Il existe une liste de diffusion pour discuter de HTML::Template à html-template-users@lists.sourceforge.net. Inscrivez-vous sur :

http://lists.sourceforge.net/lists/listinfo/html-template-users

Si vous souhaitez simplement recevoir un courriel lorsque de nouvelles versions sont disponibles, vous pouvez rejoindre la liste d'annonces ici :

http://lists.sourceforge.net/lists/listinfo/html-template-announce

Existe-t-il une archive consultable pour la liste de diffusion ?

Oui, vous pouvez trouver une archive de la liste SourceForge ici :

http://dir.gmane.org/gmane.comp.lang.perl.modules.html-template

Je veux la prise en charge de <TMPL_XXX> ! Qu'en pensez-vous ?

Peut-être. J'encourage vivement les gens à discuter de leurs idées pour HTML::Template sur la liste de diffusion. Veuillez être prêt à m'expliquer comment la nouvelle balise s'intègre dans la mission de HTML::Template qui est de fournir un système rapide et léger pour utiliser des modèles HTML.

NOTE : Proposer de programmer ladite extension et de la fournir sous la forme d'un patch pour la version la plus récente de HTML::Template aura certainement un effet apaisant sur les opposants potentiels !

J'ai trouvé un bug, pouvez-vous le corriger ?

Cela dépend. M'avez-vous envoyé la VERSION de HTML::Template, un script de test et un modèle de test ? Si oui, alors presque certainement.

Si vous êtes vraiment aventureux, HTML::Template est publiquement disponible sur GitHub (https://github.com/mpeters/html-template). N'hésitez pas à le forker et à m'envoyer une pull request avec les modifications que vous avez.

Les <TMPL_VAR> du modèle principal ne fonctionnent pas à l'intérieur d'une <TMPL_LOOP> ! Pourquoi ?

C'est le comportement attendu. "<TMPL_LOOP>" introduit une portée distincte pour les "<TMPL_VAR>" tout comme un appel de sous-programme en Perl introduit une portée distincte pour les variables "my".

Si vous voulez que vos "<TMPL_VAR>"s soient globales, vous pouvez définir l'option "global_vars" lorsque vous appelez new(). Voir ci-dessus pour la documentation de l'option "global_vars" de new().

Comment puis-je précharger mes modèles en utilisant le cache-mode et mod_perl ?

Ajoutez quelque chose comme ceci à votre fichier startup.pl :

use HTML::Template;
use File::Find;
print STDERR "Pre-loading HTML Templates...\n";
find(
    sub {
        return unless /\.tmpl$/;
        HTML::Template->new(
            filename => "$File::Find::dir/$_",
            cache    => 1,
        );
    },
    '/path/to/templates',
    '/another/path/to/templates/'
);

Notez que vous devrez modifier la ligne "return unless" pour spécifier l'extension que vous utilisez pour vos fichiers de modèle - j'utilise .tmpl, comme vous pouvez le voir. Vous devrez également spécifier le chemin vers vos fichiers de modèle.

Un problème potentiel : le /path/to/templates/ doit être EXACTEMENT le même chemin que celui que vous utilisez lorsque vous appelez "HTML::Template->new()". Sinon, le cache ne saura pas qu'il s'agit du même fichier et chargera une nouvelle copie - au lieu d'obtenir une augmentation de vitesse, vous doublerez votre utilisation de la mémoire. Pour savoir si cela se produit, définissez "cache_debug =" 1> dans le code de votre application et recherchez les messages "CACHE MISS" dans les journaux.

Quels caractères sont autorisés dans les noms TMPL_* ?

Chiffres, lettres, '.', '/', '+', '-' et '_'.

Comment puis-je exécuter un programme depuis l'intérieur de mon modèle ?

Réponse courte : vous ne pouvez pas. Réponse longue : vous ne devriez pas, car cela viole le concept fondamental derrière HTML::Template - la conception et le code doivent être séparés.

Mais, inévitablement, certaines personnes veulent toujours le faire. Si c'est votre cas, alors vous devriez jeter un œil à HTML::Template::Expr. En utilisant HTML::Template::Expr, il devrait être facile d'écrire une fonction run_program() . Ensuite, vous pouvez faire des choses terribles comme :

<tmpl_var expr="run_program('foo.pl')">

Juste, s'il vous plaît, ne me le dites pas. Je me sens déjà assez coupable d'avoir écrit HTML::Template::Expr en premier lieu.

Quelle est la meilleure façon de créer un élément de formulaire <select> en utilisant HTML::Template ?

Il y a beaucoup de désaccord sur cette question. Ma préférence personnelle est d'utiliser les excellentes fonctions popup_menu() et scrolling_list() de CGI.pm pour remplir une seule variable "<tmpl_var select_foo>" .

Pour certaines personnes, cela ressemble à mélanger HTML et code d'une manière qu'ils espéraient que HTML::Template les aiderait à éviter. À cela, je répondrais que le HTML est une violation du principe de séparer la conception de la programmation. Il n'y a pas de séparation claire entre les éléments programmatiques des balises "<form>" et la mise en page des balises "<form>" . Vous devrez tracer la ligne quelque part - clairement, le concepteur ne peut pas être entièrement en charge de la création de formulaires.

C'est un équilibre et vous devez peser le pour et le contre de chaque côté. Il est tout à fait possible de produire un élément "<select>" entièrement à l'intérieur du modèle. Ce que vous obtenez est un écheveau de boucles et de conditionnels. Alternativement, vous pouvez renoncer à une certaine flexibilité en échange d'une simplification considérable de vos modèles. Je choisis généralement ce dernier.

Une autre option est d'étudier HTML::FillInForm, dont certains ont rapporté avoir réussi à utiliser pour résoudre ce problème.
