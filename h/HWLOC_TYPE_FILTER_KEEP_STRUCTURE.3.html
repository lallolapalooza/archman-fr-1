Description détaillée

Plusieurs fonctions peuvent éventuellement être appelées entre hwloc_topology_init() et hwloc_topology_load() pour configurer la manière dont la détection doit être effectuée, par exemple pour ignorer certains types d'objets, définir une topologie synthétique, etc.

Documentation du type énuméré

enum hwloc_topology_flags_e

Drapeaux à définir sur un contexte de topologie avant le chargement. Les drapeaux doivent être donnés à hwloc_topology_set_flags(). Ils peuvent également être renvoyés par hwloc_topology_get_flags().

Énumérateur

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Détecter tout le système, ignorer les réservations, inclure les objets non autorisés. Rassembler toutes les ressources en ligne, même si certaines ont été désactivées par l'administrateur. Par exemple, ignorer les Cgroup/Cpusets Linux et rassembler tous les processeurs et nœuds mémoire. Cependant, les PU et nœuds NUMA hors ligne sont toujours ignorés.

Lorsque ce drapeau n'est pas défini, les PU et nœuds NUMA non autorisés ne sont pas ajoutés à la topologie. Les objets parents (paquet, cœur, cache, etc.) ne sont ajoutés que si certains de leurs enfants sont autorisés. Tous les PU et nœuds NUMA existants dans la topologie sont autorisés. hwloc_topology_get_allowed_cpuset() et hwloc_topology_get_allowed_nodeset() sont égaux au cpuset et au nodeset de l'objet racine.

Lorsque ce drapeau est défini, les ensembles réels de PU et de nœuds NUMA autorisés sont donnés par hwloc_topology_get_allowed_cpuset() et hwloc_topology_get_allowed_nodeset(). Ils peuvent être plus petits que le cpuset et le nodeset de l'objet racine.

Si la topologie actuelle est exportée en XML et réimportée ultérieurement, ce drapeau doit être défini à nouveau dans la topologie réimportée afin que les ressources non autorisées soient également réimportées.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Supposer que le backend sélectionné fournit la topologie du système sur lequel nous exécutons. Cela force hwloc_topology_is_thissystem() à renvoyer 1, c'est-à-dire que hwloc suppose que le backend sélectionné fournit la topologie du système sur lequel nous exécutons, même s'il ne s'agit pas du backend spécifique à l'OS mais du backend XML par exemple. Cela signifie que les fonctions d'attachement appellent réellement les appels système spécifiques à l'OS et effectuent réellement l'attachement, alors que le backend XML fournirait autrement des crochets vides renvoyant simplement le succès.

Définir la variable d'environnement HWLOC_THISSYSTEM peut également entraîner le même comportement.

Cela peut être utilisé pour des raisons d'efficacité afin de détecter la topologie une seule fois, de la sauvegarder dans un fichier XML et de la recharger rapidement plus tard via le backend XML, tout en ayant les fonctions d'attachement qui effectuent réellement l'attachement.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtenir l'ensemble des ressources autorisées depuis le système d'exploitation local même si la topologie a été chargée depuis XML ou une description synthétique. Si la topologie a été chargée depuis XML ou depuis une chaîne synthétique, la restreindre en appliquant les restrictions du processus actuel telles que les Cgroup/Cpusets Linux.

C'est utile lorsque la topologie n'est pas chargée directement depuis la machine locale (par exemple pour des raisons de performance) et qu'elle contient toutes les ressources, alors que le processus en cours d'exécution est limité à seulement une partie de la machine.

Ce drapeau est ignoré sauf si HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM est également défini, car la topologie chargée doit correspondre à la machine sous-jacente d'où les restrictions seront collectées.

Définir la variable d'environnement HWLOC_THISSYSTEM_ALLOWED_RESOURCES entraînerait le même comportement.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importer le support depuis la topologie importée. Lors de l'importation d'une topologie XML depuis une machine distante, l'attachement est désactivé par défaut (voir HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Ce désactivation est également marquée en mettant des zéros dans les bits de fonctionnalité supportée correspondants rapportés par hwloc_topology_get_support().

Le drapeau HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT importe réellement les bits de support depuis la machine distante. Il définit également le drapeau imported_support dans le tableau de la struct hwloc_topology_misc_support . Si le XML importé ne contenait aucune information de support (hwloc de l'exportateur est trop ancien), ce drapeau n'est pas défini.

Notez que ces fonctionnalités supportées ne sont pertinentes que pour l'installation hwloc qui a réellement exporté la topologie XML (elles peuvent varier selon le système d'exploitation, ou selon la manière dont hwloc a été compilé).

Notez que définir ce drapeau n'active cependant pas l'attachement pour la topologie hwloc importée localement, il rapporte seulement ce que le hwloc distant et la machine supportent.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
Ne pas considérer les ressources en dehors de l'attachement CPU du processus. Si l'attachement du processus est limité à un sous-ensemble de cœurs, ignorer les autres cœurs pendant

Énumérations

enum hwloc_topology_flags_e

Flags for hwloc topology discovery.

These flags may be set by calling hwloc_topology_set_flags() before hwloc_topology_load().

Enumerator

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
The topology context comes from the system running this program. This flag is implicitly set when no file system root is specified with hwloc_topology_set_fsroot() or no XML file with hwloc_topology_set_xml().
HWLOC_TOPOLOGY_FLAG_WHOLE_SYSTEM
Do not restrict the topology discovery to the current process's CPU or memory binding. Discover the whole system. This is the default behavior when not running as root or when the binding cannot be changed.
HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
Do not consider resources outside of the process CPU binding. If the binding of the process is limited to a subset of cores, ignore the other cores during discovery.

The resulting topology is identical to what a call to hwloc_topology_restrict() would generate, but this flag also prevents hwloc from ever touching other resources during the discovery.

This flag especially tells the x86 backend to never temporarily rebind a thread on any excluded core. This is useful on Windows because such temporary rebinding can change the process binding. Another use-case is to avoid cores that would not be able to perform the hwloc discovery anytime soon because they are busy executing some high-priority real-time tasks.

If process CPU binding is not supported, the thread CPU binding is considered instead if supported, or the flag is ignored.

This flag requires HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM as well since binding support is required.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
Do not consider resources outside of the process memory binding. If the binding of the process is limited to a subset of NUMA nodes, ignore the other NUMA nodes during discovery.

The resulting topology is identical to what a call to hwloc_topology_restrict() would generate, but this flag also prevents hwloc from ever touching other resources during the discovery.

This flag is meant to be used together with HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING when both cores and NUMA nodes should be ignored outside of the process binding.

If process memory binding is not supported, the thread memory binding is considered instead if supported, or the flag is ignored.

This flag requires HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM as well since binding support is required.

HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
Do not ever modify the process or thread binding during discovery. This flag disables all hwloc discovery steps that require a change of the process or thread binding. This currently only affects the x86 backend which gets entirely disabled.

This is useful when hwloc_topology_load() is called while the application also creates additional threads or modifies the binding.

This flag is also a strict way to make sure the process binding will not change to due thread binding changes on Windows (see HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING).

HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
Ignore distances. Ignore distance information from the operating systems (and from XML) and hence do not use distances for grouping.
HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
Ignore memory attributes and tiers. Ignore memory attribues from the operating systems (and from XML) Hence also do not try to build memory tiers.
HWLOC_TOPOLOGY_FLAG_NO_CPUKINDS
Ignore CPU Kinds. Ignore CPU kind information from the operating systems (and from XML).

enum hwloc_type_filter_e

Type filtering flags. By default, most objects are kept (HWLOC_TYPE_FILTER_KEEP_ALL). Instruction caches, memory-side caches, I/O and Misc objects are ignored by default (HWLOC_TYPE_FILTER_KEEP_NONE). Group levels are ignored unless they bring structure (HWLOC_TYPE_FILTER_KEEP_STRUCTURE).

Note that group objects are also ignored individually (without the entire level) when they do not bring structure.

Enumerator

HWLOC_TYPE_FILTER_KEEP_ALL
Keep all objects of this type. Cannot be set for HWLOC_OBJ_GROUP (groups are designed only to add more structure to the topology).
HWLOC_TYPE_FILTER_KEEP_NONE
Ignore all objects of this type. The bottom-level type HWLOC_OBJ_PU, the HWLOC_OBJ_NUMANODE type, and the top-level type HWLOC_OBJ_MACHINE may not be ignored.
HWLOC_TYPE_FILTER_KEEP_STRUCTURE
Only ignore objects if their entire level does not bring any structure. Keep the entire level of objects if at least one of these objects adds structure to the topology. An object brings structure when it has multiple children and it is not the only child of its parent.

If all objects in the level are the only child of their parent, and if none of them has multiple children, the entire level is removed.

Cannot be set for I/O and Misc objects since the topology structure does not matter there.

HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Only keep likely-important objects of the given type. It is only useful for I/O object types. For HWLOC_OBJ_PCI_DEVICE and HWLOC_OBJ_OS_DEVICE, it means that only objects of major/common kinds are kept (storage, network, OpenFabrics, CUDA, OpenCL, RSMI, NVML, and displays). Also, only OS devices directly attached on PCI (e.g. no USB) are reported. For HWLOC_OBJ_BRIDGE, it means that bridges are kept only if they have children.

This flag equivalent to HWLOC_TYPE_FILTER_KEEP_ALL for Normal, Memory and Misc types since they are likely important.

unsigned long hwloc_topology_get_flags (hwloc_topology_t topology)

Obtenir les drapeaux OR-és d'une topologie. Obtient l'ensemble OR-é des hwloc_topology_flags_e d'une topologie.

Si hwloc_topology_set_flags() n'a pas été appelée précédemment, aucun drapeau n'est défini (0 est retourné).

Retourne

les drapeaux précédemment définis avec hwloc_topology_set_flags().

Note

Cette fonction peut également être appelée après hwloc_topology_load().

const struct hwloc_topology_support * hwloc_topology_get_support (hwloc_topology_t restrict topology)

Récupérer le support de la topologie. Chaque drapeau indique si une fonctionnalité est supportée. S'il est défini à 0, la fonctionnalité n'est pas supportée. S'il est défini à 1, la fonctionnalité est supportée, mais l'appel correspondant peut toujours échouer dans certains cas limites.

Ces fonctionnalités sont également listées par hwloc-info --support

Les fonctionnalités rapportées sont celles que la topologie actuelle supporte sur la machine actuelle. Si la topologie a été exportée en XML depuis une autre machine et importée ici plus tard, le support décrit toujours ce qui est supporté pour cette topologie importée après l'importation. Par défaut, l'attachement sera rapporté comme non supporté dans ce cas (voir HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM).

Le drapeau de topologie HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT peut être utilisé pour rapporter les fonctionnalités supportées de la machine distante d'origine à la place. Si elle a été importée avec succès, imported_support sera défini dans le tableau struct hwloc_topology_misc_support.

Retourne

Un pointeur vers une structure de support.

Note

La fonction ne peut pas retourner NULL.

Le pointeur retourné ne doit pas être libéré, il appartient à la bibliothèque hwloc.

Cette fonction peut être appelée avant ou après hwloc_topology_load(), mais la structure de support ne contient des informations valides qu'après.

Detailed Description

This set of functions allows to configure how objects found during topology discovery are filtered, and how user data can be attached to the topology.

int hwloc_topology_set_cache_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

int hwloc_topology_set_flags (hwloc_topology_t topology, unsigned long flags)

Set OR'ed flags to non-yet-loaded topology. Set a OR'ed set of hwloc_topology_flags_e onto a topology that was not yet loaded.

If this function is called multiple times, the last invocation will erase and replace the set of flags that was previously set.

By default, no flags are set (0).

The flags set in a topology may be retrieved with hwloc_topology_get_flags().

Returns

0 on success.

-1 on error, for instance if flags are invalid.

void hwloc_topology_set_userdata (hwloc_topology_t topology, const void * userdata)

Set the topology-specific userdata pointer. Each topology may store one application-given private data pointer. It is initialized to NULL. hwloc will never modify it.

Use it as you wish, after hwloc_topology_init() and until hwloc_topolog_destroy().

This pointer is not exported to XML.
