Description détaillée

La liaison de mémoire peut être effectuée de trois manières :

  • allocation explicite de mémoire grâce à hwloc_alloc_membind() et fonctions similaires : la liaison aura effet sur la mémoire allouée par ces fonctions.
  • liaison de mémoire implicite via une politique de liaison : hwloc_set_membind() et fonctions similaires définissent seulement la politique actuelle du processus, qui sera appliquée aux appels ultérieurs de malloc() et fonctions similaires.
  • migration de plages de mémoire existantes, grâce à hwloc_set_area_membind() et fonctions similaires, qui déplacent des données déjà allouées.

Tous les systèmes d'exploitation ne prennent pas en charge les trois méthodes. hwloc_topology_get_support() peut être utilisé pour interroger le support réel de la liaison de mémoire dans le système d'exploitation actuellement utilisé.

Lorsque l'opération de liaison de mémoire demandée n'est pas disponible et que le drapeau HWLOC_MEMBIND_STRICT a été passé, la fonction retourne -1. errno sera positionné à ENOSYS lorsque le système ne supporte pas l'action ou la politique spécifiée (par exemple, certains systèmes ne permettent de lier la mémoire qu'au niveau d'un thread, tandis que d'autres ne permettent de lier la mémoire que pour tous les threads d'un processus). errno sera positionné à EXDEV lorsque l'ensemble demandé ne peut pas être appliqué (par exemple, certains systèmes ne permettent de lier la mémoire qu'à un seul nœud NUMA).

Si HWLOC_MEMBIND_STRICT n'a pas été passé, la fonction peut également échouer, ou le système d'exploitation peut utiliser une opération légèrement différente (avec des effets secondaires, un ensemble de liaison plus petit, etc.) lorsque l'opération demandée n'est pas exactement prise en charge.

La forme la plus portable qui devrait être préférée aux autres dès que possible est la suivante. Elle alloue une certaine quantité de mémoire en espérant qu'elle sera liée à l'ensemble spécifié. Pour ce faire, hwloc devra éventuellement changer la politique de liaison de mémoire actuelle afin d'obtenir effectivement la liaison de la mémoire, si le système d'exploitation ne fournit aucun autre moyen de simplement allouer de la mémoire liée sans changer la politique pour toutes les allocations. C'est la différence avec hwloc_alloc_membind(), qui ne changera jamais la politique de liaison de mémoire actuelle.

hwloc_alloc_membind_policy(topology, size, set,
                           HWLOC_MEMBIND_BIND, 0);

Chaque fonction de liaison de mémoire hwloc prend un argument bitmap qui est par défaut un ensemble de CPU, ou un ensemble de nœuds mémoire NUMA si le drapeau HWLOC_MEMBIND_BYNODESET est spécifié. Voir Ensembles d'objets (hwloc_cpuset_t et hwloc_nodeset_t) et L'API bitmap pour une discussion sur les ensembles de CPU et les ensembles de nœuds mémoire NUMA. Il est également possible de convertir entre ensembles de CPU et ensembles de nœuds en utilisant hwloc_cpuset_to_nodeset() ou hwloc_cpuset_from_nodeset().

La liaison de mémoire par ensemble de CPU ne peut pas fonctionner pour les nœuds mémoire NUMA sans CPU. La liaison par ensemble de nœuds devrait donc être préférée lorsque cela est possible.

Documentation du type énuméré

enum hwloc_membind_flags_t

Drapeaux de liaison de mémoire. Ces drapeaux peuvent être utilisés pour affiner la politique de liaison. Tous les drapeaux peuvent être combinés logiquement par OU, à l'exception de HWLOC_MEMBIND_PROCESS et HWLOC_MEMBIND_THREAD ; ces deux drapeaux sont mutuellement exclusifs.

Tous les systèmes ne prennent pas en charge toutes les sortes de liaison. hwloc_topology_get_support() peut être utilisé pour interroger le support réel de la liaison de mémoire dans le système d'exploitation actuellement utilisé. Voir la section 'Description détaillée' de Liaison de mémoire pour une description des erreurs qui peuvent survenir.

Énumérateur

HWLOC_MEMBIND_PROCESS
Définit la politique pour tous les threads du processus spécifié (éventuellement multithreadé). Ce drapeau est mutuellement exclusif avec HWLOC_MEMBIND_THREAD.
HWLOC_MEMBIND_THREAD
Définit la politique pour un thread spécifique du processus courant. Ce drapeau est mutuellement exclusif avec HWLOC_MEMBIND_PROCESS.
HWLOC_MEMBIND_STRICT
Demande une liaison stricte auprès du système d'exploitation. La fonction échouera si la liaison ne peut pas être garantie / complètement appliquée.

Ce drapeau a des significations légèrement différentes selon la fonction avec laquelle il est utilisé.

HWLOC_MEMBIND_MIGRATE
Migre la mémoire allouée existante. Si la mémoire ne peut pas être migrée et que le drapeau HWLOC_MEMBIND_STRICT est passé, une erreur sera retournée.
HWLOC_MEMBIND_NOCPUBIND
Évite tout effet sur la liaison de CPU. Sur certains systèmes d'exploitation, certaines fonctions de liaison de mémoire sous-jacentes lient également l'application aux CPU correspondants. L'utilisation de ce drapeau fera en sorte que hwloc évite d'utiliser les fonctions du système d'exploitation qui pourraient potentiellement affecter les liaisons de CPU. Notez cependant que l'utilisation de NOCPUBIND peut réduire le support global de liaison de mémoire de hwloc. Plus précisément : certaines fonctions de liaison de mémoire de hwloc peuvent échouer avec errno défini à ENOSYS lorsqu'elles sont utilisées avec NOCPUBIND.
HWLOC_MEMBIND_BYNODESET
Considère l'argument bitmap comme un ensemble de nœuds. L'argument bitmap est considéré comme un ensemble de nœuds si ce drapeau est donné, ou comme un ensemble de CPU par défaut.

La liaison de mémoire par ensemble de CPU ne peut pas fonctionner pour les nœuds mémoire NUMA sans CPU. La liaison par ensemble de nœuds devrait donc être préférée lorsque cela est possible.

_membind_policy_t

Politique de liaison de mémoire. Ces constantes peuvent être utilisées pour choisir la politique de liaison. Une seule politique peut être utilisée à la fois (c'est-à-dire que les valeurs ne peuvent pas être combinées par OR).

Tous les systèmes ne prennent pas en charge tous les types de liaison. hwloc_topology_get_support() peut être utilisé pour interroger le support de la politique de liaison de mémoire dans le système d'exploitation actuellement utilisé. Voir la section 'Description détaillée' de Liaison de mémoire pour une description des erreurs qui peuvent survenir.

Énumérateur

HWLOC_MEMBIND_DEFAULT
Réinitialiser la politique d'allocation mémoire à la valeur par défaut du système. Selon le système d'exploitation, cela peut correspondre à HWLOC_MEMBIND_FIRSTTOUCH (Linux, FreeBSD) ou à HWLOC_MEMBIND_BIND (AIX, HP-UX, Solaris, Windows). Cette politique n'est jamais renvoyée par les fonctions get membind. L'argument nodeset est ignoré.
HWLOC_MEMBIND_FIRSTTOUCH
Allouer chaque page mémoire individuellement sur le nœud NUMA local du thread qui la touche. Le nodeset donné doit généralement être hwloc_topology_get_topology_nodeset() afin que le thread qui touche puisse s'exécuter et allouer sur n'importe quel nœud du système.

Sur AIX, si le nodeset est plus petit, les pages sont allouées localement (si le nœud local est dans le nodeset) ou à partir d'un nœud non local aléatoire (sinon).

HWLOC_MEMBIND_BIND
Allouer la mémoire sur les nœuds spécifiés. Le comportement réel peut varier légèrement entre les systèmes d'exploitation, en particulier lorsque (certains des) nœuds demandés sont pleins. Sous Linux, par défaut, la politique MPOL_PREFERRED_MANY (ou MPOL_PREFERRED) est utilisée. Cependant, si le drapeau strict de hwloc est également donné, la politique Linux MPOL_BIND est plutôt utilisée.
HWLOC_MEMBIND_INTERLEAVE
Allouer la mémoire sur les nœuds donnés de manière entrelacée / en cercle. La disposition précise de la mémoire sur plusieurs nœuds NUMA est spécifique à l'OS/système. L'entrelacement peut être utile lorsque les threads distribués sur les nœuds NUMA spécifiés accéderont tous à la plage mémoire complète simultanément, car l'entrelacement équilibrera alors les références mémoire.
HWLOC_MEMBIND_WEIGHTED_INTERLEAVE
Allouer la mémoire sur les nœuds donnés de manière entrelacée / pondérée. La disposition précise de la mémoire sur plusieurs nœuds NUMA est spécifique à l'OS/système. L'entrelacement pondéré peut être utile lorsque les threads distribués sur les nœuds NUMA spécifiés avec des capacités de bande passante différentes accéderont tous à la plage mémoire complète simultanément, car l'entrelacement équilibrera alors les références mémoire.
HWLOC_MEMBIND_NEXTTOUCH
Pour chaque page liée avec cette politique, lors de la prochaine touche (et seulement lors de la prochaine touche), elle est déplacée de son emplacement actuel vers le nœud NUMA local du thread où la référence mémoire s'est produite (si elle doit être déplacée).
HWLOC_MEMBIND_MIXED
Renvoi par les fonctions get_membind() lorsque plusieurs threads ou parties d'une zone mémoire ont des politiques de liaison mémoire différentes. Également renvoyé lorsque la liaison est inconnue car les hooks de liaison sont vides lorsque la topologie est chargée à partir de XML sans HWLOC_THISSYSTEM=1, etc.

void * hwloc_alloc (hwloc_topology_t topology, size_t len)

Allouer de la mémoire. Ceci est équivalent à malloc(), sauf qu'il essaie d'allouer de la mémoire alignée sur page auprès de l'OS.

Retourne

un pointeur vers la zone allouée, ou NULL en cas d'erreur.

Note

La mémoire allouée doit être libérée avec hwloc_free().

void * hwloc_alloc_membind (hwloc_topology_t topology, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags)

Allouer de la mémoire sur les nœuds mémoire NUMA spécifiés par set.

Retourne

un pointeur vers la zone allouée.

NULL avec errno défini à ENOSYS si l'action n'est pas prise en charge et que HWLOC_MEMBIND_STRICT est donné.

NULL avec errno défini à EXDEV si la liaison ne peut pas être appliquée et que HWLOC_MEMBIND_STRICT est donné.

NULL avec errno défini à ENOMEM si l'allocation mémoire a échoué avant même d'essayer de lier.

Si HWLOC_MEMBIND_BYNODESET est spécifié, set est considéré comme un nodeset. Sinon, c'est un cpuset.

Note

La mémoire allouée doit être libérée avec hwloc_free().

void * hwloc_alloc_membind_policy (hwloc_topology_t topology, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags) [inline]

Allouer de la mémoire sur les nœuds mémoire NUMA spécifiés par set. D'abord, essayer d'allouer correctement avec hwloc_alloc_membind(). En cas d'échec, la politique de liaison mémoire du processus ou du thread actuel est modifiée avec hwloc_set_membind() avant d'allouer la mémoire. Ainsi, cette fonction fonctionne dans plus de cas, au détriment de la modification de l'état actuel (affectant potentiellement les allocations futures qui ne spécifieraient aucune politique).

Si HWLOC_MEMBIND_BYNODESET est spécifié, set est considéré comme un nodeset. Sinon, c'est un cpuset.

Retourne

un pointeur vers la zone allouée, ou NULL en cas d'erreur.

int hwloc_free (hwloc_topology_t topology, void * addr, size_t len)

Libérer la mémoire précédemment allouée par hwloc_alloc() ou hwloc_alloc_membind().

Retourne

0 en cas de succès, -1 en cas d'erreur.

int hwloc_get_area_membind (hwloc_topology_t topology, const void * addr, size_t len, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int flags)

Interroger les CPU proches des nœud(s) NUMA physiques et la politique de liaison de la mémoire identifiée par (addr, len ). Le bitmap set (préalablement alloué par l'appelant) est rempli avec la liaison de la zone mémoire.

Cette fonction a deux paramètres de sortie : set et policy. Les valeurs renvoyées dans ces paramètres dépendent à la fois des drapeaux passés en argument et des politiques de liaison mémoire et des nodesets des pages dans la plage d'adresses.

Si HWLOC_MEMBIND_STRICT est spécifié, les pages cibles sont d'abord vérifiées pour voir si elles ont toutes la même politique de liaison mémoire et le même nodeset. Si ce n'est pas le cas, -1 est renvoyé et errno est défini à EXDEV. Si elles sont identiques sur toutes les pages, le set et la politique sont renvoyés dans set et policy, respectivement.

Si HWLOC_MEMBIND_STRICT n'est pas spécifié, l'union de tous les nœud(s) NUMA contenant des pages dans la plage d'adresses est calculée. Si toutes les pages dans la cible ont la même politique, elle est renvoyée dans policy. Sinon, policy est défini à HWLOC_MEMBIND_MIXED.

Si HWLOC_MEMBIND_BYNODESET est spécifié, set est considéré comme un nodeset. Sinon, c'est un cpuset.

Si d'autres drapeaux sont spécifiés, -1 est renvoyé et errno est défini à EINVAL.

Retourne

0 en cas de succès.

-1 avec errno défini à EINVAL si len est 0.

int hwloc_get_area_memlocation (hwloc_topology_t topology, const void * addr, size_t len, hwloc_bitmap_t set, int flags)

Obtenir les nœuds NUMA où la mémoire identifiée par (addr, len ) est physiquement allouée. Le bitmap set (préalablement alloué par l'appelant) est rempli en fonction des nœuds NUMA où les pages de la zone mémoire sont physiquement allouées. Si aucune page n'est réellement allouée, set peut être vide.

Si les pages s'étendent sur plusieurs nœuds, il n'est pas spécifié si elles s'étendent équitablement, ou si la plupart d'entre elles se trouvent sur un seul nœud, etc.
