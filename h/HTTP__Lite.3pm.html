HTTP::Lite(3) Documentation Perl fournie par l'utilisateur HTTP::Lite(3)

NOM

HTTP::Lite - Implémentation HTTP légère

SYNTAXE

use HTTP::Lite;
$http = HTTP::Lite->new;
$req = $http->request("http://www.cpan.org/") 
    or die "Impossible d'obtenir le document : $!";
print $http->body();

DESCRIPTION

Note : vous devriez examiner HTTP::Tiny ou LWP avant d'utiliser ce module.

HTTP::Lite est une implémentation HTTP/1.1 légère et autonome pour Perl. Il n'est pas destiné à remplacer le module LWP aux fonctionnalités complètes. Au lieu de cela, il est destiné à être utilisé dans des situations où il est souhaitable d'installer le nombre minimal de modules pour obtenir un support HTTP, ou lorsque LWP n'est pas un bon candidat en raison de la charge de processeur, comme sur des processeurs plus lents. HTTP::Lite est également significativement plus rapide que LWP.

HTTP::Lite est idéal pour les programmes CGI (ou mod_perl) ou pour être regroupé pour redistribution avec des paquets plus importants où seules les fonctionnalités HTTP GET et POST sont nécessaires.

HTTP::Lite prend uniquement en charge les opérations POST et GET de base. Depuis la version 0.2.1, HTTP::Lite prend en charge HTTP/1.1 et est conforme à l'en-tête Host, nécessaire pour l'hébergement virtuel basé sur le nom. De plus, HTTP::Lite prend désormais en charge les proxys.

Depuis la version 2.0.0, HTTP::Lite prend en charge une fonction de rappel (callback) pour permettre le traitement des données de requête au fur et à mesure de leur arrivée. Ceci est utile pour gérer des fichiers très volumineux sans consommer de mémoire.

Si vous avez besoin de plus de fonctionnalités, telles que FTP ou HTTPS, veuillez consulter libwwwperl (LWP). LWP est un paquet beaucoup plus complet et meilleur que HTTP::Lite, et devrait être utilisé à la place de HTTP::Lite chaque fois que possible.

CONSTRUCTEUR

new
Ceci est le constructeur pour HTTP::Lite. Il n'accepte actuellement aucun argument. Une future version de HTTP::Lite pourrait accepter des paramètres.

METHODES

request ( $url, $data_callback, $cbargs )
Initie une requête vers l'URL spécifiée.

Retourne undef si une erreur d'E/S est rencontrée, sinon le code d'état HTTP sera retourné. Les codes d'état de la série 200 représentent un succès, 300 des erreurs temporaires, 400 des erreurs permanentes, et 500 des erreurs serveur.

Voir http://www.w3.org/Protocols/HTTP/HTRESP.html pour des informations détaillées sur les codes d'état HTTP.

Le paramètre $data_callback, s'il est utilisé, est un moyen de filtrer les données au fur et à mesure de leur réception ou de gérer des transferts volumineux. Ce doit être une référence de fonction, et elle recevra : une référence à l'instance de la requête http effectuant le rappel, une référence au bloc de données actuel sur le point d'être ajouté au corps, et le paramètre $cbargs (qui peut être n'importe quoi). Elle doit retourner une référence aux données à ajouter au corps du document, ou undef.

Si set_callback est utilisé, $data_callback et $cbargs ne sont pas utilisés. $cbargs peut être un scalaire ou une référence.

Le callback de données est appelé comme suit :
&$data_callback( $self, $dataref, $cbargs )

Un exemple d'utilisation pour enregistrer un document dans un fichier est :

# Écrire les données dans le descripteur de fichier $cbargs
sub savetofile {
  my ($self,$phase,$dataref,$cbargs) = @_;
  print $cbargs $$dataref;
  return undef;
}
$url = "$testpath/bigbinary.dat";
open OUT, '>','bigbinary.dat';
$res = $http->request($url, \&savetofile, OUT);
close OUT;
set_callback ( $functionref, $dataref )
À différentes étapes de la requête, des rappels peuvent être utilisés pour modifier le comportement ou surveiller l'état de la requête. Ceux-ci fonctionnent comme le paramètre $data_callback de request(), mais sont plus polyvalents. L'utilisation de set_callback désactive $data_callback dans request().

Les rappels sont appelés comme suit :
callback ( $self, $phase, $dataref, $cbargs )

Les phases actuelles sont :

connect - la connexion a été établie et les en-têtes sont en cours de
          transmission.
content-length - la valeur de retour est utilisée comme content-length. Si undef,
          et prepare_post() a été utilisé, la longueur du contenu est
          calculée.
done-headers - tous les en-têtes ont été envoyés
content - la valeur de retour est utilisée comme contenu et est envoyée au client. Retourner
          undef pour utiliser le contenu interne défini par prepare_post().
content-done - le contenu a été transmis avec succès.
data - Un bloc de données a été reçu. Les données sont référencées par
          $dataref. La valeur de retour est déréférencée et remplace le
          contenu passé. Retourner undef pour éviter d'utiliser la mémoire pour les documents volumineux.
done - La requête est terminée.
prepare_post ( $hashref )
Prend une référence à un tableau associatif de variables de formulaire à télécharger. Crée le corps HTTP et définit la méthode sur POST.
http11_mode ( 0 | 1 )
Active ou désactive le support HTTP/1.1. Ceci est désactivé par défaut en raison de serveurs HTTP/1.1 défectueux. Utilisez 1 pour activer le support HTTP/1.1.
add_req_header ( $header, $value )
get_req_header ( $header )
delete_req_header ( $header )
Ajoute, supprime ou récupère un ou plusieurs en-têtes HTTP pour la requête. Ces fonctions vous permettent de remplacer n'importe quel en-tête. Actuellement, Host, User-Agent, Content-Type, Accept et Connection sont prédéfinis par le module HTTP::Lite. Vous ne pouvez pas remplacer Host, Connection ou Accept.

Si vous appelez add_req_header() avec $value défini à "undef", alors l'en-tête ne sera pas ajouté.

Pour fournir une authentification (proxy) ou une autorisation, vous utiliseriez :

use HTTP::Lite;
use MIME::Base64;
$http = HTTP::Lite->new;
$encoded = encode_base64('username:password');
$http->add_req_header("Authorization", $encoded);

NOTE : L'implémentation actuelle vous limite à une seule instance de chaque en-tête.

body
Retourne le corps du document renvoyé par le serveur distant.
headers_array
Retourne un tableau des en-têtes HTTP renvoyés par le serveur distant.
headers_string
Retourne une représentation sous forme de chaîne des en-têtes HTTP renvoyés par le serveur distant.
get_header ( $header )
Retourne un tableau des valeurs pour l'en-tête demandé.

NOTE : Les requêtes HTTP ne sont pas limitées à une seule instance de chaque en-tête. Par conséquent, il peut y avoir plus d'une entrée pour chaque en-tête.

protocol
Retourne l'identifiant du protocole HTTP, tel que rapporté par le serveur distant. Ce sera généralement HTTP/1.0 ou HTTP/1.1.
proxy ( $proxy_server )
L'URL ou le nom d'hôte du proxy à utiliser pour la prochaine requête.
status
Retourne le code d'état HTTP renvoyé par le serveur. Ceci est également rapporté comme valeur de retour de request().
status_message
Retourne la description textuelle du code d'état telle que renvoyée par le serveur. La chaîne de statut n'est pas obligée de respecter un format particulier, bien que la plupart des serveurs HTTP utilisent un ensemble standard de descriptions.
reset
Vous devez appeler ceci avant de réutiliser un descripteur HTTP::Lite, sinon les résultats ne sont pas définis.
lo

EXEMPLES

# Obtenir et imprimer les en-têtes et le corps de la page d'accueil CPAN
use HTTP::Lite;
$http = HTTP::Lite->new;
$req = $http->request("http://www.cpan.org/")
    or die "Impossible d'obtenir le document : $!";
die "La requête a échoué ($req) : ".$http->status_message()
  if $req ne "200";
@headers = $http->headers_array();
$body = $http->body();
foreach $header (@headers)
{
  print "$header$CRLF";
}
print "$CRLF";
print "$body$CRLF";
# POST une requête au moteur de recherche USENET deja news
use HTTP::Lite;
$http = HTTP::Lite->new;
%vars = (
         "QRY" => "perl",
         "ST" => "MS",
         "svcclass" => "dncurrent",
         "DBS" => "2"
        );
$http->prepare_post(\%vars);
$req = $http->request("http://www.deja.com/dnquery.xp")
  or die "Impossible d'obtenir le document : $!";
print "req: $req\n";
print $http->body();

NON IMPLEMENTE

- FTP
- HTTPS (SSL)
- L'authentification/Autorisation/Proxy-Authorization
  ne sont pas directement pris en charge et nécessitent MIME::Base64.
- Les redirections (Location) ne sont pas suivies automatiquement
- Les POST multipart/form-data ne sont pas directement pris en charge (nécessaire
  pour les transferts de fichiers).

BOGUES

Certains serveurs HTTP/1.1 défectueux envoient des tailles de blocs incorrectes lors du transfert de fichiers. Le mode HTTP/1.1 est maintenant désactivé par défaut.

VOIR AUSSI

Ce module (HTTP::Lite) n'est très probablement pas le meilleur module pour vos besoins.

Pour la plupart des utilisations, HTTP::Tiny est un bon choix. Si vous avez besoin de plus de fonctionnalités, regardez du côté de LWP.

Vous pouvez également lire cette critique des modules CPAN pour effectuer des requêtes HTTP http://neilb.org/reviews/http-requesters.html.
