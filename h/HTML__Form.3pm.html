DESCRIPTIO

N

Les objets de la classe "HTML::Form" représentent une seule instance "<form> ... </form>" HTML. Un formulaire se compose d'une séquence d'entrées qui ont généralement des noms et qui peuvent prendre différentes valeurs. L'état d'un formulaire peut être ajusté, et on peut ensuite lui demander de fournir des objets HTTP::Request qui peuvent être passés à la méthode request() de LWP::

UserAgent.

Les méthodes suivantes sont disponibles

:
@forms = HTML::Form->parse( $html_document, $base_uri
)
@forms = HTML::Form->parse( $html_document, base => $base_uri, %opt
)
@forms = HTML::Form->parse( $response, %opt
)
La méthode de classe parse() analysera un document HTML et construira des objets "HTML::Form" pour chaque élément <form> trouvé. Si elle est appelée en contexte scalaire, elle ne renvoie que le premier <form>. Elle renvoie une liste vide s'il n'y a aucun formulaire à trouver.

Les arguments requis sont le document HTML à analyser ($html_document) et l'URI utilisée pour récupérer le document ($base_uri). L'URI de base est nécessaire pour résoudre les URI d'action relatives. Le document HTML fourni doit être une chaîne Unicode (ou US-ASCII)

.

Par défaut, HTML::Form suppose que le document d'origine était encodé en UTF-8 et encode donc les formulaires qui ne spécifient pas un accept-charset explicite en UTF-8. Le jeu de caractères supposé peut être remplacé en fournissant l'option "charset" à parse(). C'est une bonne idée d'être explicite à propos de ce paramètre également, ainsi l'invocation la plus simple recommandée

devient : 
my @forms = HTML::Form->parse(
    Encode::decode($encoding, $html_document_bytes),
    base => $base_uri,
    charset => $encoding,
);

Si le document a été récupéré avec LWP, l'objet response fournit des méthodes pour obtenir une valeur appropriée pour "base" et "charse

t" : 
my $ua = LWP::UserAgent->new;
my $response = $ua->get("http://www.example.com/form.html");
my @forms = HTML::Form->parse($response->decoded_content,
    base => $response->base,
    charset => $response->content_charset,
);

En fait, la méthode parse() peut analyser directement à partir d'un objet HTTP::Response, donc l'exemple ci-dessus peut être écrit plus commodément

comme ceci : 
my $ua = LWP::UserAgent->new;
my $response = $ua->get("http://www.example.com/form.html");
my @forms = HTML::Form->parse($response)
;

Notez que tout objet qui implémente une méthode decoded_content(), base() et content_charset() avec un comportement similaire à HTTP::Response

conviendra.

ENTRÉE

S

Un objet "HTML::Form" contient une séquence d' entrées. Les références aux entrées peuvent être obtenues avec les méthodes $form->inputs ou $form->find_

input.

Notez qu'il n'y a pas de correspondance un-à-un entre les objets entrée et les éléments <input> dans le document HTML. Un objet entrée représente essentiellement une paire nom/valeur, donc lorsque plusieurs éléments HTML contribuent à la même paire nom/valeur dans le formulaire soumis, ils sont

combinés.

Les éléments d'entrée qui sont mappés un-à-un sont "text", "textarea", "password", "hidden", "file", "image", "submit" et "checkbox". Pour les entrées "radio" et "option", l'histoire n'est pas aussi simple : Tous les éléments <input type="radio"> avec le même nom contribueront au même objet entrée radio. Le nombre d'objets entrée radio sera le même que le nombre de noms distincts utilisés pour les éléments <input type="radio">. Pour un élément <select> sans l'attribut "multiple", il y aura un objet entrée de type "option". Pour un élément <select multiple>, il y aura un objet entrée pour chaque élément <option> contenu. Chacun de ces objets option aura le même

nom.
