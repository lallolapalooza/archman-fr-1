Description détaillée

Certains systèmes d'exploitation ne prennent en charge que la liaison des threads ou des processus à une seule PU. D'autres permettent la liaison à des ensembles plus grands tels que des cœurs entiers ou des paquets, ou même des ensembles aléatoires d'unités de traitement individuelles. Dans de tels systèmes d'exploitation, le planificateur est libre d'exécuter la tâche sur l'une de ces PU, puis de la migrer vers une autre PU, etc. Il est souvent utile d'appeler hwloc_bitmap_singlify() sur l'ensemble CPU cible avant de le passer à la fonction de liaison pour éviter ces migrations coûteuses. Voir la documentation de hwloc_bitmap_singlify() pour plus de détails.

Certains systèmes d'exploitation ne fournissent pas tous les mécanismes pris en charge par hwloc pour lier les processus, les threads, etc. hwloc_topology_get_support() peut être utilisé pour interroger le support réel de la liaison CPU dans le système d'exploitation actuellement utilisé.

Lorsque l'opération de liaison demandée n'est pas disponible et que le drapeau HWLOC_CPUBIND_STRICT a été passé, la fonction renvoie -1. errno est défini sur ENOSYS lorsqu'il n'est pas possible de lier le type d'objet demandé (processus/threads). errno est défini sur EXDEV lorsque l'ensemble CPU demandé ne peut pas être appliqué (par exemple, certains systèmes n'autorisent qu'un seul CPU, et d'autres systèmes n'autorisent qu'un seul nœud NUMA).

Si HWLOC_CPUBIND_STRICT n'a pas été passé, la fonction peut également échouer, ou le système d'exploitation peut utiliser une opération légèrement différente (avec des effets secondaires, un ensemble de liaison plus petit, etc.) lorsque l'opération demandée n'est pas exactement prise en charge.

La version la plus portable qui devrait être préférée aux autres, dans la mesure du possible, est la suivante qui ne fait que lier le programme actuel, en supposant qu'il est mono-thread :

hwloc_set_cpubind(topology, set, 0),

Si le programme peut être multi-thread, la version suivante devrait être préférée pour ne lier que le thread actuel :

hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD),

Note

Pour annuler la liaison, appelez simplement la fonction de liaison avec un ensemble d'unités centrales complet ou un ensemble d'unités centrales égal à l'ensemble du système.

Sur certains systèmes d'exploitation, la liaison CPU peut avoir des effets sur la liaison mémoire, voir HWLOC_CPUBIND_NOMEMBIND

L'exécution de lstopo --top ou hwloc-ps peut être un outil très pratique pour vérifier comment la liaison s'est réellement déroulée.

Documentation du type d'énumération

enum hwloc_cpubind_flags_t

Drapeaux de liaison de processus/thread. Ces drapeaux binaires peuvent être utilisés pour affiner la politique de liaison.

Par défaut (0), il s'agit de lier le processus actuel, supposé mono-thread, d'une manière non stricte. C'est la méthode la plus portable pour lier, car tous les systèmes d'exploitation la fournissent généralement.

Note

Tous les systèmes ne prennent pas en charge tous les types de liaison. Voir la section 'Description détaillée' de liaison CPU pour une description des erreurs qui peuvent survenir.

Énumérateur

HWLOC_CPUBIND_PROCESS
Lier tous les threads du processus actuel (potentiellement multi-thread).
HWLOC_CPUBIND_THREAD
Lier le thread actuel du processus actuel.
HWLOC_CPUBIND_STRICT
Demande de liaison stricte du système d'exploitation. Par défaut, lorsque les CPU désignées sont toutes occupées tandis que d'autres CPU sont inactives, les systèmes d'exploitation peuvent exécuter le thread/processus sur ces autres CPU au lieu des CPU désignées, pour leur permettre de progresser quand même. La liaison stricte signifie que le thread/processus ne s'exécutera _jamais_ sur d'autres CPU que celles désignées, même lorsqu'elles sont occupées par d'autres tâches et que d'autres CPU sont inactives.

Note

Selon le système d'exploitation, la liaison stricte peut ne pas être possible (par exemple, le système d'exploitation ne l'implémente pas) ou non autorisée (par exemple, pour des raisons administratives), et la fonction échouera dans ce cas.

Lors de la récupération de la liaison d'un processus, ce drapeau vérifie si tous ses threads ont effectivement la même liaison. Si le drapeau n'est pas donné, la liaison de chaque thread sera accumulée.

Note

Ce drapeau n'a pas de sens lors de la récupération de la liaison d'un thread.
HWLOC_CPUBIND_NOMEMBIND
Éviter tout effet sur la liaison mémoire. Sur certains systèmes d'exploitation, certaines fonctions de liaison CPU lieraient également la mémoire sur le nœud NUMA correspondant. Ce n'est souvent pas un problème pour l'application, mais si c'est le cas, définir ce drapeau empêchera hwloc d'utiliser des fonctions du système d'exploitation qui lieraient également la mémoire. Cela réduira cependant la prise en charge des liaisons CPU, c'est-à-dire qu'elle pourrait potentiellement renvoyer -1 avec errno défini sur ENOSYS dans certains cas.

Ce drapeau n'est significatif que lorsqu'il est utilisé avec des fonctions qui définissent la liaison CPU. Il est ignoré lorsqu'il est utilisé avec des fonctions qui obtiennent des informations de liaison CPU.

DESCRIPTION

These functions all get or set the CPU binding of the current process or thread, or of another specific process or thread.

The CPU binding is the set of logical processors on which a process or thread is allowed to run.

hwloc_get_cpubind

Get the current physical binding of the calling process or thread. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the process or thread was last bound to.

flags can include either HWLOC_CPUBIND_PROCESS or HWLOC_CPUBIND_THREAD to specify whether the query should be for the whole process (union of all CPUs on which all threads are running), or only the current thread. If the process is single-threaded, flags can be set to zero to let hwloc use whichever method is available on the underlying OS.

Returns

0 on success, -1 on error.

hwloc_get_proc_cpubind

Get the current physical binding of process pid. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the process was last bound to.

Returns

0 on success, -1 on error.

Note

hwloc_pid_t is pid_t on Unix platforms, and HANDLE on native Windows platforms.

As a special case on Linux, if a tid (thread ID) is supplied instead of a pid (process ID) and HWLOC_CPUBIND_THREAD is passed in flags, the binding for that specific thread is returned.

On non-Linux systems, HWLOC_CPUBIND_THREAD can not be used in flags.

hwloc_get_proc_last_cpu_location

Get the last physical CPU where a process ran. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the process last ran on.

The operating system may move some tasks from one processor to another at any time according to their binding, so this function may return something that is already outdated.

Returns

0 on success, -1 on error.

Note

hwloc_pid_t is pid_t on Unix platforms, and HANDLE on native Windows platforms.

As a special case on Linux, if a tid (thread ID) is supplied instead of a pid (process ID) and HWLOC_CPUBIND_THREAD is passed in flags, the last CPU location of that specific thread is returned.

On non-Linux systems, HWLOC_CPUBIND_THREAD can not be used in flags.

hwloc_get_thread_cpubind

Get the current physical binding of thread tid. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the thread was last bound to.

Returns

0 on success, -1 on error.

Note

hwloc_thread_t is pthread_t on Unix platforms, and HANDLE on native Windows platforms.

HWLOC_CPUBIND_PROCESS can not be used in flags.

hwloc_set_cpubind

Bind current process or thread on CPUs given in physical bitmap set.

Returns

0 on success.

-1 with errno set to ENOSYS if the action is not supported.

-1 with errno set to EXDEV if the binding cannot be enforced.

hwloc_set_proc_cpubind

Bind a process pid on CPUs given in physical bitmap set.

Returns

0 on success, -1 on error.

Note

hwloc_pid_t is pid_t on Unix platforms, and HANDLE on native Windows platforms.

As a special case on Linux, if a tid (thread ID) is supplied instead of a pid (process ID) and HWLOC_CPUBIND_THREAD is passed in flags, the binding is applied to that specific thread.

On non-Linux systems, HWLOC_CPUBIND_THREAD can not be used in flags.

hwloc_set_thread_cpubind

Bind a thread thread on CPUs given in physical bitmap set.

Returns

0 on success, -1 on error.

Note

hwloc_thread_t is pthread_t on Unix platforms, and HANDLE on native Windows platforms.

HWLOC_CPUBIND_PROCESS can not be used in flags.
