NOM

HTTP::Cache::Transparent - Met en cache le résultat des requêtes http de type get de manière persistante.

SYNTAXE

use LWP::Simple;
use HTTP::Cache::Transparent;
HTTP::Cache::Transparent::init( {
  BasePath => '/tmp/cache',
} );
my $data = get( 'http://www.sn.no' );

DESCRIPTION

Une implémentation de http get qui maintient un cache local des pages récupérées pour éviter de récupérer les mêmes données depuis le serveur si elles n'ont pas été mises à jour. Le cache est stocké sur disque et est donc persistant entre les invocations.

Utilise les en-têtes http If-Modified-Since et ETag pour laisser le serveur décider si la version dans le cache est à jour ou non.

Le cache est implémenté en modifiant la classe LWP::UserAgent pour mettre en cache de manière transparente le résultat de toutes les requêtes qui peuvent être mises en cache.

INITIALISATION DU CACHE

HTTP::Cache::Transparent fournit une méthode `init` qui définit les paramètres du cache et surcharge une méthode de LWP::UserAgent pour activer le cache. Après l'appel à `init`, les méthodes LWP normales (LWP::Simple ainsi que les méthodes LWP::Request plus complètes) doivent être utilisées comme d'habitude.

init
Initialise le cache HTTP. Prend un seul paramètre qui est un hashref contenant des arguments nommés pour l'objet. 
 HTTP::Cache::Transparent::init( {
   # Répertoire où stocker le cache.
   BasePath  => "/tmp/cache",
   # Combien d'heures les éléments doivent être conservés dans le cache
   # après leur dernière demande ?
   # La valeur par défaut est 8*24.
   MaxAge    => 8*24,
   # Affiche des messages de progression sur STDERR.
   # La valeur par défaut est 0.
   Verbose   => 1,
   # Si une requête est faite pour une URL qui a été demandée
   # au serveur il y a moins de `NoUpdate` secondes, la
   # réponse sera générée à partir du cache sans
   # contacter le serveur.
   # La valeur par défaut est 0.
   NoUpdate  => 15*60,
   # Lorsqu'une URL a été téléchargée et que la réponse indique
   # qu'elle a été modifiée par rapport au contenu du cache,
   # la fonction de rappel `ApproveContent` est appelée avec le HTTP::Response.
   # La fonction de rappel doit retourner vrai si la réponse doit être utilisée et
   # stockée dans le cache, ou faux si la réponse doit être écartée
   # et la réponse du cache utilisée à la place.
   # Ce mécanisme peut être utilisé pour contourner les serveurs qui renvoient des erreurs
   # de manière intermittente. La valeur par défaut est d'accepter toutes les réponses.
   ApproveContent => sub { return $_[0]->is_success },
} );

Le répertoire où le cache est stocké doit être inscriptible. Il doit également ne contenir que des fichiers créés par HTTP::Cache::Transparent.

Initialisation depuis la ligne use
Une manière alternative d'initialiser HTTP::Cache::Transparent est de fournir des paramètres dans la ligne `use`. Cela vous permet d'écrire 
use HTTP::Cache::Transparent ( BasePath => '/tmp/cache' );

ce qui est exactement équivalent à

use HTTP::Cache::Transparent;
HTTP::Cache::Transparent::init( BasePath => '/tmp/cache' );

L'avantage d'utiliser cette méthode est que vous pouvez écrire

perl -MHTTP::Cache::Transparent=BasePath,/tmp/cache monscript.pl

ou même définir la variable d'environnement PERL5OPT

PERL5OPT=-MHTTP::Cache::Transparent=BasePath,/tmp/cache
monscript.pl

et faire en sorte que toutes les requêtes http effectuées par monscript.pl passent par le cache sans modifier monscript.pl

INSPECTION DU COMPORTEMENT DU CACHE

HTTP::Cache::Transparent insère trois en-têtes spéciaux dans l'objet HTTP::Response. Ceux-ci peuvent être accessibles via la méthode HTTP::Response::header().

X-Cached
Cet en-tête est inséré et défini à 1 si la réponse est délivrée depuis le cache au lieu du serveur.
X-Content-Unchanged
Cet en-tête est inséré et défini à 1 si le contenu retourné est le même que le contenu retourné la dernière fois que cette URL a été récupérée. Cet en-tête est toujours inséré et défini à 1 lorsque la réponse est délivrée depuis le cache.
X-No-Server-Contact
Cet en-tête est inséré et défini à 1 si le contenu retourné a été délivré sans aucun contact avec le serveur externe, c'est-à-dire qu'aucune requête GET http conditionnelle ou inconditionnelle n'a été envoyée, le contenu a été délivré directement depuis le cache. Ceci peut être utile pour contrôler le chargement du serveur externe.

LIMITATIONS

Ce module a un certain nombre de limitations dont vous devriez être conscient avant de l'utiliser.

  • Il n'y a pas de limite supérieure à l'espace disque requis par le cache. Le seul mécanisme de limitation est que les données pour les URL qui n'ont pas été demandées dans les dernières MaxAge heures seront retirées du cache la prochaine fois que le programme se terminera.
  • Actuellement, seules les requêtes get qui stockent le résultat en mémoire (c'est-à-dire qui n'utilisent pas l'option pour que le résultat soit stocké directement dans un fichier ou délivré via une fonction de rappel) sont mises en cache. J'ai l'intention de supprimer cette limitation dans une future version.
  • Le support des Ranges est un peu primitif. Il crée un nouvel objet dans le cache pour chaque combinaison unique d'URL et de Range. Cela fonctionnera correctement tant que vous demanderez toujours les mêmes plages pour une URL.
  • Le cache ne vérifie et ne stocke pas correctement tous les en-têtes de la requête et de la réponse HTTP. Par conséquent, si vous demandez la même URL à plusieurs reprises avec des ensembles d'en-têtes différents (cookies, accept-encoding, etc.), et que ces en-têtes affectent la réponse du serveur, le cache peut renvoyer la mauvaise réponse.
  • HTTP::Cache::Transparent n'a pas été testé avec les threads, et ne fonctionnera très probablement pas si vous les utilisez.

FORMAT DU CACHE

Le cache est stocké sur disque sous la forme d'un fichier par objet mis en cache. Le nom du fichier est égal au md5sum de l'URL et de l'en-tête Range s'il existe. Le fichier contient un ensemble de paires clé/valeur avec des métadonnées (une entrée par ligne) suivies d'une ligne vide, puis des données réelles retournées par le serveur.

La date de dernière modification du fichier de cache est définie sur l'heure à laquelle l'objet de cache a été demandé pour la dernière fois par un utilisateur.
