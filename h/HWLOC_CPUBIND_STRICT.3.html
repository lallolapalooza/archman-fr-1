Description détaillée

Certains systèmes d'exploitation ne prennent en charge que la liaison des threads ou des processus à une seule PU. D'autres permettent la liaison à des ensembles plus grands tels que des Cœurs entiers ou des Paquets, ou même des ensembles arbitraires de PU individuelles. Dans de tels systèmes d'exploitation, l'ordonnanceur est libre d'exécuter la tâche sur l'une de ces PU, puis de la migrer vers une autre PU, etc. Il est souvent utile d'appeler hwloc_bitmap_singlify() sur l'ensemble de CPU cible avant de le passer à la fonction de liaison pour éviter ces migrations coûteuses. Voir la documentation de hwloc_bitmap_singlify() pour plus de détails.

Certains systèmes d'exploitation ne fournissent pas tous les mécanismes pris en charge par hwloc pour lier les processus, les threads, etc. hwloc_topology_get_support() peut être utilisé pour interroger la prise en charge réelle de la liaison du CPU dans le système d'exploitation actuellement utilisé.

Lorsque l'opération de liaison demandée n'est pas disponible et que le drapeau HWLOC_CPUBIND_STRICT a été passé, la fonction renvoie -1. errno est défini à ENOSYS lorsqu'il est impossible de lier le type d'objet demandé (processus/threads). errno est défini à EXDEV lorsque l'ensemble de CPU demandé ne peut pas être appliqué (par exemple, certains systèmes n'autorisent qu'un seul CPU, et certains autres systèmes n'autorisent qu'un seul nœud NUMA).

Si HWLOC_CPUBIND_STRICT n'a pas été passé, la fonction peut également échouer, ou le système d'exploitation peut utiliser une opération légèrement différente (avec des effets de bord, un ensemble de liaison plus petit, etc.) lorsque l'opération demandée n'est pas exactement prise en charge.

La version la plus portable, qui devrait être préférée aux autres, chaque fois que c'est possible, est la suivante, qui lie simplement le programme actuel, en supposant qu'il est mono-thread :

hwloc_set_cpubind(topology, set, 0),

Si le programme peut être multi-thread, la suivante devrait être préférée pour ne lier que le thread actuel :

hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD),

Voir aussi

Des codes d'exemple sont disponibles sous doc/examples/ dans l'arborescence source.

Note

Pour délier, appelez simplement la fonction de liaison avec soit un ensemble de CPU complet, soit un ensemble de CPU égal à l'ensemble de CPU du système.

Sur certains systèmes d'exploitation, la liaison du CPU peut avoir des effets sur la liaison de la mémoire, voir HWLOC_CPUBIND_NOMEMBIND

Exécuter lstopo --top ou hwloc-ps peut être un outil très pratique pour vérifier comment la liaison s'est réellement produite.

Documentation du type énumération

enum hwloc_cpubind_flags_t

Drapeaux de liaison Processus/Thread. Ces drapeaux de bits peuvent être utilisés pour affiner la politique de liaison.

La valeur par défaut (0) est de lier le processus actuel, supposé être mono-thread, de manière non stricte. C'est la façon la plus portable de lier, car tous les systèmes d'exploitation la fournissent généralement.

Note

Tous les systèmes ne prennent pas en charge tous les types de liaison. Voir la section « Description détaillée » de Liaison du CPU pour une description des erreurs qui peuvent survenir.

Énumérateur

HWLOC_CPUBIND_PROCESS
Lie tous les threads du processus actuel (éventuellement) multi-thread.
HWLOC_CPUBIND_THREAD
Lie le thread actuel du processus actuel.
HWLOC_CPUBIND_STRICT
Demande une liaison stricte au niveau du système d'exploitation. Par défaut, lorsque les CPU désignés sont tous occupés alors que d'autres CPU sont inactifs, les systèmes d'exploitation peuvent exécuter le thread/processus sur ces autres CPU au lieu des CPU désignés, pour leur permettre de progresser quand même. Une liaison stricte signifie que le thread/processus ne s'exécuta _jamais_ sur d'autres CPU que les CPU désignés, même lorsque ceux-ci sont occupés par d'autres tâches et que d'autres CPU sont inactifs.

Note

Selon le système d'exploitation, une liaison stricte peut ne pas être possible (par exemple, le système d'exploitation ne l'implémente pas) ou pas autorisée (par exemple, pour des raisons administratives), et la fonction échouera dans ce cas.

Lors de la récupération de la liaison d'un processus, ce drapeau vérifie si tous ses threads ont réellement la même liaison. Si le drapeau n'est pas donné, la liaison de chaque thread sera accumulée.

Note

Ce drapeau est sans signification lors de la récupération de la liaison d'un thread.
HWLOC_CPUBIND_NOMEMBIND
Évite tout effet sur la liaison de la mémoire. Sur certains systèmes d'exploitation, certaines fonctions de liaison du CPU lieraient également la mémoire sur le nœud NUMA correspondant. Ce n'est souvent pas un problème pour l'application, mais si c'est le cas, définir ce drapeau fera en sorte que hwloc évite d'utiliser les fonctions du système d'exploitation qui lieraient également la mémoire. Cela réduira cependant la prise en charge des liaisons de CPU, c'est-à-dire qu'elle peut potentiellement renvoyer -1 avec errno défini à ENOSYS dans certains cas.

Ce drapeau n'a de sens que lorsqu'il est utilisé avec les fonctions qui définissent la liaison du CPU. Il est ignoré lorsqu'il est utilisé avec les fonctions qui récupèrent les informations de liaison du CPU.

Documentation des fonctions

int hwloc_get_cpubind (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Récupère la liaison du processus ou du thread actuel. L'ensemble de CPU set (préalablement alloué par l'appelant) est rempli avec la liste des PU auxquelles le processus ou le thread (selon flags) a été lié pour la dernière fois.

Renvoie

0 en cas de succès, -1 en cas d'erreur.

int hwloc_get_last_cpu_location (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Récupère le dernier processeur physique où le processus ou le thread actuel s'est exécuté. L'ensemble de CPU set (préalablement alloué par l'appelant) est rempli avec la liste des PU sur lesquelles le processus ou le thread (selon flags)

s'est exécuté pour la dernière fois. Le système d'exploitation peut déplacer certaines tâches d'un processeur à un autre à tout moment en fonction de leur liaison, donc cette fonction peut renvoyer quelque chose qui est déjà obsolèteobsolète.

drapeaux peuvent inclure soit HWLOC_CPUBIND_PROCESS ou HWLOC_CPUBIND_THREAD pour spécifier si la requête doit porter sur l'ensemble du processus (union de tous les CPU sur lesquels tous les threads s'exécutent), ou seulement sur le thread courant. Si le processus est mono-thread, les drapeaux peuvent être mis à zéro pour laisser hwloc utiliser la méthode disponible sur le système d'exploitation sous-jacent.

Renvoie

0 en cas de succès, -1 en cas d'erreur.

int hwloc_get_proc_cpubind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Obtient la liaison physique courante du processus pid. L'ensemble de CPU set (préalablement alloué par l'appelant) est rempli avec la liste des PU auxquels le processus était dernier lié.

Renvoie

0 en cas de succès, -1 en cas d'erreur.

Note

hwloc_pid_t est pid_t sur les plateformes Unix, et HANDLE sur les plateformes Windows natives.

En tant que cas particulier sur Linux, si un tid (identifiant de thread) est fourni à la place d'un pid (identifiant de processus) et que HWLOC_CPUBIND_THREAD est passé dans les drapeaux, la liaison de ce thread spécifique est renvoyée.

Sur les systèmes non Linux, HWLOC_CPUBIND_THREAD ne peut pas être utilisé dans les drapeaux.

int hwloc_get_proc_last_cpu_location (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Obtient le dernier CPU physique où un processus s'est exécuté. L'ensemble de CPU set (préalablement alloué par l'appelant) est rempli avec la liste des PU sur lesquels le processus s'est dernièrement exécuté.

Le système d'exploitation peut déplacer certaines tâches d'un processeur à un autre à tout moment selon leur liaison, de sorte que cette fonction peut renvoyer quelque chose qui est déjà obsolète.

Renvoie

0 en cas de succès, -1 en cas d'erreur.

Note

hwloc_pid_t est pid_t sur les plateformes Unix, et HANDLE sur les plateformes Windows natives.

En tant que cas particulier sur Linux, si un tid (identifiant de thread) est fourni à la place d'un pid (identifiant de processus) et que HWLOC_CPUBIND_THREAD est passé dans les drapeaux, la dernière localisation CPU de ce thread spécifique est renvoyée.

Sur les systèmes non Linux, HWLOC_CPUBIND_THREAD ne peut pas être utilisé dans les drapeaux.

int hwloc_get_thread_cpubind (hwloc_topology_t topology, hwloc_thread_t thread, hwloc_cpuset_t set, int flags)

Obtient la liaison physique courante du thread tid. L'ensemble de CPU set (préalablement alloué par l'appelant) est rempli avec la liste des PU auxquels le thread était dernier lié.

Renvoie

0 en cas de succès, -1 en cas d'erreur.

Note

hwloc_thread_t est pthread_t sur les plateformes Unix, et HANDLE sur les plateformes Windows natives.

HWLOC_CPUBIND_PROCESS ne peut pas être utilisé dans les drapeaux.

int hwloc_set_cpubind (hwloc_topology_t topology, hwloc_const_cpuset_t set, int flags)
