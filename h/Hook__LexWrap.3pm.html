DESCRIPTIO

N

Hook::LexWrap vous permet d'installer un emballage préalable ou postérieur (ou les deux) autour d'une sous-routine existante. Contrairement à d'autres modules qui fournissent cette capacité (par exemple Hook::PreAndPost et Hook::WrapSub), Hook::LexWrap implémente les emballages de telle manière que la fonction standard "caller" fonctionne correctement à l'intérieur de la sous-routine

emballée.

Pour installer un emballage préalable, vous écrivez

: 
     use Hook::LexWrap;
     wrap 'subroutine_name', pre => \&
#ou : wrap *subroutine_name,  pre => \&some_other_sub
;

Le premier argument de "wrap" est une chaîne contenant le nom de la sous-routine à emballer (ou le typeglob la contenant, ou une référence vers elle). Le nom de la sous-routine peut être qualifié, et la sous-routine doit déjà être définie. Le deuxième argument indique le type d'emballage appliqué et doit être soit 'pre' ou 'post'. Le troisième argument doit être une référence vers une sous-routine qui implémente

l'emballage.

Pour installer un emballage postérieur, vous écrivez

: 
     wrap 'subroutine_name', post => \&
#ou : wrap *subroutine_name,  post => \&yet_another_sub
;

Pour installer les deux à la fois

: 
wrap 'subroutine_name',
     pre  => \&some_other_sub,
     post => \&yet_another_sub
;

ou

: 
wrap *subroutine_name,
     post => \&yet_another_sub,  # l'ordre dans lequel les emballages
     pre  => \&   # sont spécifiés n'a pas
d'importance

Une fois installés, les emballages préalable et postérieur seront appelés avant et après la sous-routine elle-même, et recevront la même liste

d'arguments.

Les emballages préalable et postérieur ainsi que la sous-routine d'origine voient tous les mêmes valeurs (correctes !) de "caller" et "wantarray"

.

Valeurs de retour à court-circuit et à

long-circuit

Les emballages préalable et postérieur reçoivent tous deux un argument supplémentaire dans leurs tableaux @_. Cet argument supplémentaire est ajouté à la liste d'arguments d'origine (c'est-à-dire qu'il peut toujours être accédé comme $_[-1]) et sert de substitut pour la valeur de retour de la sous-routine

d'origine.

Dans un emballage préalable, $_[-1] est -- pour des raisons évidentes -- "undef". Cependant, $_[-1] peut recevoir une assignation dans un emballage préalable, auquel cas Hook::LexWrap suppose que la sous-routine d'origine a été "préemptée", et que ni elle, ni l'emballage postérieur correspondant, ni aucun emballage qui a été appliqué avant que l'emballage préalable préemptant ne soit installé, n'ont besoin d'être exécutés. Notez que tout emballage postérieur qui a été installé après l'emballage préalable préemptant sera toujours appelé avant que l'appel à la sous-routine d'origine ne se

termine.

Dans un emballage postérieur, $_[-1] contient la valeur de retour produite par la sous-routine emballée. Dans un contexte de retour scalaire, cette valeur est la valeur de retour scalaire. Dans un contexte de retour liste, cette valeur est une référence vers le tableau des valeurs de retour. $_[-1] peut recevoir une assignation dans un emballage postérieur, et cela modifie la valeur de retour en

conséquence.

L'accès aux arguments et à la valeur de retour est utile pour implémenter des techniques telles que la mémoïsation

: 
my %cache;
wrap fibonacci =>
        pre  => sub { $_[-1] = $cache{$_[0]} if $cache{$_[0]} },
        post => sub { $cache{$_[0]} = $_[-1] }
;

ou pour convertir les arguments et les valeurs de retour de manière cohérente

: 
# set_temp attend et retourne des degrés Fahrenheit,
# mais nous voulons utiliser Celsius
wrap set_temp =>
        pre   => sub { splice @_, 0, 1, $_[0] * 1.8 + 32 },
        post  => sub { $_[-1] = ($_[0] - 32) / 1.8
}
;

Emballages à portée

lexicale

Normalement, tout emballage installé par "wrap" reste attaché à la sous-routine jusqu'à ce qu'elle soit indéfinie. Cependant, il est possible de rendre des emballages spécifiques liés lexicalement, de sorte qu'ils ne fonctionnent que jusqu'à la fin de la portée dans laquelle ils sont créés (ou jusqu'à un autre point spécifique dans le code)

.

Si "wrap" est appelé dans un contexte non vide

: 
my $lexical = wrap 'sub_name', pre =>
\&

il retourne un objet spécial correspondant à l'emballage particulier placé autour de la sous-routine d'origine. Lorsque cet objet est détruit -- lorsque sa variable conteneur sort de portée, ou lorsque son nombre de références tombe autrement à zéro (par exemple "undef $lexical"), ou lorsqu'il est explicitement détruit ("$lexical->DESTROY") -- l'emballage correspondant est retiré d'autour de la sous-routine d'ori

gine. Notez cependant que tous les autres emb
allages autour de la sous-routine sont préservés.

Emballages

anonymes

Si la sous-routine à emballer est passée comme une référence (plutôt que par nom ou par typeglob), "wrap" n'installe pas les emballages autour de la sous-routine d'origine. À la place, il génère une nouvelle sous-routine qui se comporte comme si elle était l'originale avec ces emballages autour d'elle. Il retourne ensuite une référence vers cette nouvelle sous-routine. Seuls les appels à l'originale via cette référence emballée invoquent les emballages. Les appels directs par nom à l'originale, ou les appels via une autre référence, ne les invoquent

pas.

Si l'originale est ensuite emballée par nom, la référence à la sous-routine emballée anonymement ne voit pas ces emballages. En d'autres termes, les emballages installés via une référence à une sous-routine sont complètement indépendants de ceux installés via le nom de la sous-routine (ou le typeglob)

.

Par exemple

: 
sub original { print "ray" }
# Emballer anonymement...
my $anon_wrapped = wrap \&original, pre => sub { print "do..." };
# Montrer les effets... original(); # affiche "ray" $anon_wrapped->(); # affiche "do..ray" # Emballer no
mmément... wrap *original, pre => sub { print "fa.." }, post => sub { print "..mi" }; # Montrer les eff
ets... original(); # maintenant affiche "fa..ray..mi" $anon_wrapped->(); # affiche toujours "do...ray"

%s"
Une tentative a été faite d'emballer une sous-routine qui n'était pas définie au point
d'emballage.
"'pre' value is not a subroutine
reference"
La valeur passée à "wrap" après le drapeau 'pre' n'était pas une référence à une sous-routine. Typiquement, quelqu'un a oublié le "sub" sur la sous-routine anonyme : 
wrap 'subname', pre => { your_code_here()
};

et Perl a interprété le der

nier argument comme un con
structeur de hachage.
"'post' value is not a subroutine

La valeur passée à "wrap" après le drapeau 'post' n'était pas une référence à une
sous-routine.
"Uselessly wrapped subroutine reference in void context" (avertissement
seulement)
Lorsque la sous-routine à emballer est passée comme une référence à une sous-routine, "wrap" n'installe pas l'emballage autour de l'originale, mais retourne à la place une référence vers une sous-routine qui emballnal (voir « Anonymous wrappers »).

Cependant, cela ne sert

à rien de le faire si v
ous ne récupérez pas
la référence à la
