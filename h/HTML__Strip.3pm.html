HTML__Strip(3pm)

Paquet: perl-html-strip

Strip(3) Documentation Perl fournie par l'utilisateur Strip(3)

NOM

HTML::Strip - Extension Perl pour supprimer le balisage HTML du texte.

SYNOPSIS

use HTML::Strip;
my $hs = HTML::Strip->new();
my $clean_text = $hs->parse( $raw_html );
$hs->eof;

DESCRIPTION

Ce module supprime simplement le balisage de type HTML du texte, rapidement et brutalement. Il pourrait facilement être utilisé pour supprimer également du balisage XML ou SGML - mais comme la suppression du HTML est un problème beaucoup plus courant, ce module vit dans l'espace de noms HTML::.

Il est écrit en XS, et donc environ cinq fois plus rapide que l'utilisation d'expressions régulières pour la même tâche.

Il ne fait pas de vérification de syntaxe. Si vous en voulez, utilisez HTML::Parser. Au lieu de cela, il applique simplement les règles suivantes :

1.
Tout ce qui ressemble à une balise, ou à un groupe de balises, sera remplacé par un seul espace. Les balises sont considérées comme tout ce qui commence par un "<" et se termine par un ">" ; avec la réserve qu'un caractère ">" peut apparaître dans l'un ou l'autre des cas suivants sans terminer la balise :
Guillemets
Les guillemets sont considérés comme commençant par un caractère "'" ou un caractère """, et se terminant par un caractère correspondant non précédé par un nombre pair de slashes échappés (c'est-à-dire que "\"" ne termine pas le guillemet mais "\\\\"" le fait).
Commentaire
Si la balise commence par un point d'exclamation, elle est supposée être une déclaration ou un commentaire. Dans de telles balises, les caractères ">" ne terminent pas la balise s'ils apparaissent entre des paires de tirets doubles (par exemple, "<!-- <a href="old.htm">ancienne page</a> -->" serait complètement supprimé). Aucun parsing de guillemets n'est effectué dans les commentaires, donc par exemple "<!-- commentaire avec les deux types de guillemets ' et " -->" serait entièrement supprimé.
2.
Tout ce qui apparaît entre les balises que nous appelons balises à supprimer est supprimé. Par défaut, ces balises sont "title", "script", "style" et "applet".

HTML::Strip maintient l'état entre les appels, vous pouvez donc analyser un document par morceaux si vous le souhaitez. Si un appel à parse() se termine à moitié dans une balise, un guillemet ou un commentaire ; le prochain appel à parse() attendra que son entrée continue à partir de ce point.

Si ce n'est pas le comportement que vous souhaitez, vous pouvez soit appeler eof() entre les appels à parse(), soit définir "auto_reset" à vrai (soit dans le constructeur, soit avec "set_auto_reset") afin que l'analyseur se réinitialise après chaque appel.

MÉTHODES

new()
Constructeur. Peut optionnellement prendre un hash de paramètres (avec des clés correspondant aux méthodes "set_" ci-dessous).

Exemple :

my $hs = HTML::Strip->new(
    striptags   => [ 'script', 'iframe' ],
    emit_spaces => 0
);
parse()
Prend une chaîne de caractères comme argument, la retourne débarrassée du HTML.
eof()
Réinitialise les informations d'état actuelles, prêt à analyser un nouveau bloc de HTML.
clear_striptags()
Efface l'ensemble actuel des balises à supprimer.
add_striptag()
Ajoute la chaîne passée en argument à l'ensemble actuel des balises à supprimer.
set_striptags()
Prend une référence à un tableau de chaînes, qui remplacent l'ensemble actuel des balises à supprimer.
set_emit_spaces()
Prend une valeur booléenne. Si elle est définie sur faux, HTML::Strip ne tentera pas de convertir les balises en espaces. Par défaut, elle est sur vrai.
set_emit_newlines()
Prend une valeur booléenne. Si elle est définie sur vrai, HTML::Strip affichera des nouvelles lignes après les balises "<br>" et "<p>". Par défaut, elle est sur faux.
set_decode_entities()
Prend une valeur booléenne. Si elle est définie sur faux, HTML::Strip ne décodera pas les entités HTML. Par défaut, elle est sur vrai.
filter_entities()
Si HTML::Entities est disponible, cette méthode se comporte comme l'invocation de HTML::Entities::decode_entities, sauf qu'elle respecte le paramètre actuel de 'decode_entities'.
set_filter()
Définit un filtre à appliquer après la suppression des balises. Il peut accepter le nom d'une méthode (comme 'filter_entities') ou une référence de code. Par défaut, sa valeur est 'filter_entities' si HTML::Entities est disponible, ou "undef" sinon.
set_auto_reset()
Prend une valeur booléenne. Si elle est définie sur vrai, "parse" se réinitialise après chaque appel (équivalent à appeler "eof"). Sinon, l'analyseur se souvient de son état d'un appel à "parse" à un autre, jusqu'à ce que vous appeliez "eof" explicitement. Par défaut, elle est sur faux.
set_debug()
Affiche des informations de débogage détaillées sur l'état interne pendant l'analyse. Non destiné à être utilisé par quiconque sauf le mainteneur du module.
decode_entities()
filter()
auto_reset()
debug()
Accesseurs en lecture seule pour leurs paramètres respectifs.

LIMITATIONS

Espaces blancs
Bien qu'il ne produise qu'un seul caractère d'espace par groupe de balises, et évite de le faire lorsque les balises sont bordées par des espaces ou le début ou la fin de chaînes, HTML::Strip peut souvent produire plus que souhaité ; par exemple avec le HTML suivant : 
<h1> HTML::Strip </h1> <p> <em> <strong> rapide et brutal </strong> </em> </p>

Ce qui donne le résultat suivant :

" HTML::Strip    rapide, et brutal   "

Ainsi, vous pourriez vouloir post-traiter la sortie de HTML::Strip pour supprimer les espaces blancs excessifs (par exemple, en utilisant "tr/ / /s;"). (Ceci a été amélioré depuis les versions précédentes, mais reste un problème)

Entités HTML
HTML::Strip tentera de décoder les entités HTML uniquement si HTML::Entities est installé.

EXPORT

Aucun par défaut.
