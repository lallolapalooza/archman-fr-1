NOM

HTML::TableExtract - Module Perl pour extraire le contenu contenu dans les tableaux d'un document HTML, soit sous forme de texte, soit sous forme d'arbres d'éléments encodés.

SYNTAXE

# Les tableaux correspondants sont retournés sous forme d'objets tableau ; les tableaux peuvent être identifiés
# en utilisant les en-têtes de colonne, la profondeur, le nombre dans une profondeur, les attributs de la balise table,
# ou une combinaison des quatre.
# Exemple : Utilisation des informations sur les en-têtes de colonne.
# Supposons un document HTML avec des tableaux contenant "Date", "Prix" et
# "Coût" quelque part dans une ligne. Les colonnes sous ces en-têtes sont
# ce que vous voulez extraire. Elles seront retournées dans le même ordre que
# vous avez spécifié les en-têtes puisque 'automap' est activé par défaut.
use HTML::TableExtract;
my $te = HTML::TableExtract->new( headers => [qw(Date Prix Coût)] );
$te->parse($html_string);
# Examiner tous les tableaux correspondants
foreach my $ts ($te->tables) {
  print "Tableau (", join(',', $ts->coords), "):\n";
  foreach my $row ($ts->rows) {
     print join(',', @$row), "\n";
  }
}
# Raccourci... la méthode rows() de niveau supérieur suppose le premier tableau trouvé dans
# le document si aucun argument n'est fourni.
foreach my $row ($te->rows) {
   print join(',', @$row), "\n";
}
# Exemple : Utilisation des informations de profondeur et de nombre.
# Chaque tableau du document a un tuple unique de profondeur et de nombre, donc
# lorsque les deux sont spécifiés, il s'agit d'un tableau unique. La profondeur et le nombre commencent tous deux
# à 0, donc dans ce cas, nous cherchons un tableau (profondeur 2)
# dans un tableau (profondeur 1) dans un tableau (profondeur 0, qui est le document HTML de niveau supérieur). De plus, ce doit être la troisième (count 2)
# instance d'un tableau à cette profondeur.
my $te = HTML::TableExtract->new( depth => 2, count => 2 );
$te->parse_file($html_file);
foreach my $ts ($te->tables) {
   print "Tableau trouvé à ", join(',', $ts->coords), ":\n";
   foreach my $row ($ts->rows) {
      print "   ", join(',', @$row), "\n";
   }
}
# Exemple : Utilisation des attributs de balise table.
# Si plusieurs attributs sont spécifiés, tous doivent être présents et égaux
# pour qu'une correspondance se produise.
my $te = HTML::TableExtract->new( attribs => { border => 1 } );
$te->parse($html_string);
foreach my $ts ($te->tables) {
  print "Tableau avec border=1 trouvé à ", join(',', $ts->coords), ":\n";
  foreach my $row ($ts->rows) {
     print "   ", join(',', @$row), "\n";
  }
}
# Exemple : Extraction sous forme de structure d'arbre HTML::Element
# Plutôt que d'extraire du texte brut, le html peut être converti en une
# structure d'arbre d'objets élément. Le document HTML est composé de
# HTML::Element objets et les tableaux sont des structures HTML::ElementTable. En utilisant cela, le contenu des tableaux dans un document peut
# être modifié sur place.
use HTML::TableExtract qw(tree);
my $te = HTML::TableExtract->new( headers => qw(Frais Fie Foe Fum) );
$te->parse_file($html_file);
my $table = $te->first_table_found;
my $table_tree = $table->tree;
$table_tree->cell(4,4)->replace_content('Oie d'or');
my $table_html = $table_tree->as_HTML;
my $table_text = $table_tree->as_text;
my $document_tree = $te->tree;
my $document_html = $document_tree->as_HTML;

DESCRIPTION

HTML::TableExtract est une sous-classe de HTML::Parser qui sert à extraire les informations des tableaux d'intérêt contenus dans un document HTML. Les informations de chaque tableau extrait sont stockées dans des objets tableau. Les tableaux peuvent être extraits en tant que texte, HTML ou structures HTML::ElementTable (pour la modification ou la manipulation sur place).

Il existe actuellement quatre contraintes disponibles pour spécifier quels tableaux vous souhaitez extraire d'un document : Headers (En-têtes), Depth (Profondeur), Count (Nombre) et Attributes (Attributs).

Headers, la plus flexible et adaptative des techniques, implique de spécifier du texte dans un tableau que vous vous attendez à trouver au-dessus des données dans les tableaux d'intérêt. Une fois tous les en-têtes localisés dans une ligne de ce tableau, toutes les cellules suivantes sous les colonnes qui correspondent à vos en-têtes sont extraites. Toutes les autres colonnes sont ignorées : pensez-y comme à des coupes verticales à travers un tableau. De plus, TableExtract réorganise automatiquement chaque ligne dans le même ordre que les en-têtes que vous avez fournis. Si vous souhaitez désactiver cela, définissez automap sur 0 lors de la création de l'objet, et comptez plutôt sur la méthode column_map() pour savoir dans quel ordre les en-têtes ont été trouvés. De plus, TableExtract compensera automatiquement les problèmes d'espacement des cellules afin que les colonnes soient réellement les mêmes colonnes que celles que vous verriez visuellement dans un navigateur. Ce comportement peut être désactivé en définissant le paramètre gridmap sur 0. Le HTML est dépouillé de tout le contenu textuel d'une cellule avant que les correspondances d'en-tête ne soient tentées - à moins que le paramètre keep_html n'ait été activé.

Depth et Count sont des moyens plus spécifiques de spécifier les tableaux les uns par rapport aux autres. Depth représente à quelle profondeur un tableau réside dans d'autres tableaux. La profondeur d'un tableau de niveau supérieur dans le document est de 0. Un tableau dans un tableau de niveau supérieur a une profondeur de 1, et ainsi de suite. Chaque profondeur peut être considérée comme une couche ; les tableaux partageant la même profondeur sont sur la même couche. Au sein de chacune de ces couches, Count représente l'ordre dans lequel un tableau a été vu à cette profondeur, en commençant par 0. La fourniture à la fois d'une depth et d'un count spécifiera de manière unique un tableau au sein d'un document.

Attributes correspondent en fonction des attributs de la balise <table> html, par exemple, les largeurs de bordure ou la couleur de fond.

Chacune des spécifications Headers, Depth, Count et Attributes sont cumulatives dans leur effet sur l'extraction globale. Par exemple, si vous spécifiez uniquement une Depth, alors vous obtenez tous les tableaux à cette profondeur (notez que ceux-ci pourraient très bien résider dans des tableaux de niveau supérieur séparés tout au long du document car la profondeur s'étend à travers les tableaux). Si vous ne spécifiez qu'un Count, alors les tableaux à ce Count de toutes les profondeurs sont retournés (c'est-à-dire, la n-ième occurrence d'un tableau à chaque profondeur). Si vous ne spécifiez que des Headers, alors vous obtenez tous les tableaux du document contenant ces en-têtes de colonne. Si vous avez spécifié plusieurs contraintes de Headers, Depth, Count et Attributes, alors chaque contrainte a un pouvoir de veto sur la question de savoir si un tableau particulier est extrait.

Si aucun Headers, Depth, Count ou Attributes n'est spécifié, alors tous les tableaux correspondent.

Lors de l'extraction uniquement du texte des tableaux, le texte est décodé avec HTML::Entities par défaut ; cela peut être désactivé en définissant le paramètre decode sur 0.

Modes d'extraction

Le mode d'extraction par défaut pour HTML::TableExtract est le texte brut ou le HTML. Dans ce mode, les tables incorporées sont complètement découplées les unes des autres. Dans ce cas, HTML::TableExtract est une sous-classe de HTML::Parser :

use HTML::TableExtract;

Alternativement, les tables peuvent être extraites sous forme de structures HTML::ElementTable, qui sont à leur tour intégrées dans un arbre HTML::Element représentant l'intégralité du document HTML. Les tables incorporées ne sont pas découplées les unes des autres puisque cette structure arborescente doit être maintenue. Dans ce cas, HTML::TableExtract est une sous-classe de HTML::TreeBuilder (elle-même une sous-classe de HTML:::Parser) :

use HTML::TableExtract qw(tree);

Dans les deux cas, l'interface de base pour HTML::TableExtract et les objets tableau résultants reste la même - tout ce qui change est ce que vous pouvez faire avec les données résultantes.

HTML::TableExtract est une sous-classe de HTML::Parser, et à ce titre hérite de toutes ses méthodes de base telles que parse() et parse_file(). Pendant les analyses, start(), end(), et text() sont utilisés. N'hésitez pas à les remplacer, mais si vous ne les appelez pas éventuellement dans la classe SUPER avec du contenu, les résultats ne sont pas garantis.

Conseils

Le point principal de ce module était de fournir une méthode flexible pour extraire des informations tabulaires des documents HTML sans trop dépendre de la mise en page du document. Pour cette raison, je suggère d'utiliser Headers chaque fois que possible - de cette façon, vous ancrez votre extraction sur ce que le document essaie de communiquer plutôt que sur une caractéristique du HTML qui compose le document (autre que le fait que les données sont contenues dans un tableau).

DESCRIPTION

Ce module facilite l'extraction de tableaux à partir de documents HTML. Il est particulièrement utile lorsque le document HTML n'est pas bien formé, car il s'appuie sur le module HTML::Parser(3) pour la tâche de balisage.

Il existe deux modes d'extraction : le mode par défaut et le mode 'tree'.

En mode par défaut, le module renvoie des tableaux sous forme de listes de listes des contenus des cellules. Le contenu des cellules peut être le texte brut ou le code HTML tel qu'il apparaît dans le fichier source.

En mode 'tree', le module renvoie des références aux structures d'arbre d'éléments HTML qui représentent le tableau. Cela permet une manipulation plus poussée des éléments du tableau.

METHODS

new(%args)

Renvoie la ligne d'en-tête sous forme de liste lorsque des en-têtes ont été spécifiés comme contrainte. Si "keep_headers" a été spécifié initialement, ceci est équivalent à la première ligne renvoyée par la méthode rows().
column_map()
Renvoie l'ordre (via les indices) dans lequel les en-têtes fournis ont été trouvés. Ces indices peuvent être utilisés comme tranches sur les lignes pour soit ordonner les lignes dans le même ordre que les en-têtes, soit restaurer les lignes dans leur ordre naturel, en fonction du fait que les lignes aient été pré-ajustées à l'aide du paramètre automap.

Le chemin est une liste de références de tableau contenant les valeurs de profondeur, de compte, de ligne et de colonne pour chaque tableau ancêtre impliqué. NOTES ON TREE EXTRACTION MODE

Comme mentionné ci-dessus, HTML::TableExtract peut être appelé en mode 'tree' où le code HTML résultant et les tableaux extraits sont encodés dans des structures d'arbre HTML::Element :

use HTML::TableExtract 'tree';

Il y a un certain nombre de choses à noter lors de l'utilisation de ce mode. Le document HTML entier est encodé dans un arbre HTML::Element. Chaque tableau fait partie de cette structure, mais est néanmoins suivi séparément via une structure HTML::ElementTable, qui est une forme spécialisée d'arbre HTML::Element.

Les objets HTML::ElementTable sont accessibles en appelant la méthode tree() depuis chaque objet Table retourné par HTML::TableExtract. Les objets HTML::ElementTable ont leurs propres méthodes row(), col(), et cell() (entre autres). Celles-ci ne doivent pas être confondues avec les méthodes row() et column() fournies par les objets HTML::TableExtract::Table.

Par exemple, la méthode row() de HTML::ElementTable fournira une référence à un 'glob' de tous les éléments de cette ligne. Les actions (telles que la définition d'attributs) effectuées sur cette référence de ligne affecteront tous les éléments de cette ligne. D'autre part, la méthode row() de l'objet HTML::TableExtract::Table renverra un tableau (par référence ou par liste, selon le contexte) du contenu de chaque cellule de la ligne. En mode arbre, le contenu est représenté par des références individuelles à chaque cellule -- ce sont des références aux mêmes objets HTML::Element qui résident dans l'arbre HTML::Element.

Les méthodes cell() fournies dans les deux cas renverront donc des références au même objet. L'exception est lorsqu'une 'cellule' dans la grille du tableau était à l'origine 'couverte' en raison de problèmes de rowspan ou de colspan -- dans ce cas, le contenu de la cellule sera undef. De même, les méthodes row() ou column() des objets HTML::TableExtract::Table renverront des tableaux contenant potentiellement un mélange de références d'objets et de undefs. Si vous allez effectuer de nombreuses manipulations des éléments du tableau, il pourrait être plus efficace d'y accéder via les méthodes fournies par l'objet HTML::ElementTable à la place. Voir HTML::ElementTable(3) pour plus d'informations sur la façon de manipuler ces objets.

Une alternative à la méthode cell() dans HTML::TableExtract::Table est la méthode space(). Elle est en grande partie similaire à cell(), sauf lorsqu'elle reçoit les coordonnées d'une cellule qui était couverte en raison d'effets de rowspan ou de colspan, elle renverra le contenu de la cellule qui couvrait cet espace plutôt que undef. Ainsi, si, par exemple, la cellule (0,0) avait un rowspan de 2 et un colspan de 2, cell(1,1) renverrait undef et space(1,1) renverrait le même contenu que cell(0,0) ou space(0,0).
