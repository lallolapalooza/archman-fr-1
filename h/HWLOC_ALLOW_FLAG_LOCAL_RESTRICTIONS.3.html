hwloc_obj_t hwloc_topology_insert_group_object (hwloc_topology_t topology, hwloc_obj_t group)

Ajoute une structure à la topologie en insérant un Groupe intermédiaire. L'appelant doit d'abord allouer un nouvel objet Groupe avec hwloc_topology_alloc_group_object(). Ensuite, il doit configurer au moins un de ses ensembles de CPU ou de nœuds pour spécifier l'emplacement final du Groupe dans la topologie. Ensuite, l'objet peut être passé à cette fonction pour insertion effective dans la topologie.

Le cas d'utilisation principal de cette fonction est de regrouper un sous-ensemble de frères et sœurs dans la liste des enfants sous un parent unique. Par exemple, si l'on regroupe 4 cœurs sur un socket à 8 cœurs, la liste logique des cœurs sera réordonnée de sorte que les 4 cœurs groupés soient consécutifs. Ensuite, si nécessaire, une nouvelle profondeur est ajoutée entre le parent et ces enfants, et le Groupe y est inséré. Au final, les 4 cœurs groupés sont maintenant des enfants du Groupe, qui les remplace comme enfant du parent d'origine.

En pratique, les objets groupés sont spécifiés par des ensembles de CPU (cpusets) et/ou des ensembles de nœuds (nodesets), par exemple en utilisant hwloc_obj_add_other_obj_sets() de manière itérative. Il est donc possible de regrouper des objets qui ne sont pas enfants du même parent, par exemple certains PU sous les 4 cœurs dans l'exemple ci-dessus. Cependant, ce cas général peut échouer si le Groupe attendu entre en conflit avec la hiérarchie existante. Par exemple, si chaque cœur possède deux PU, il n'est pas possible d'insérer un Groupe contenant une seule PU de chaque cœur.

Pour spécifier les objets à regrouper, soit le champ cpuset, soit le champ nodeset (ou les deux, s'ils sont compatibles) doit être défini sur un bitmap non vide. Le cpuset complet ou le nodeset complet peuvent être définis à la place si l'insertion se fait par rapport à la topologie complète (y compris les objets interdits, hors ligne ou inconnus). Ces ensembles ne peuvent pas être plus grands que la topologie actuelle, sinon ils seraient silencieusement restreints. Le cœur configurera les autres ensembles après insertion effective.

L'attribut subtype de l'objet peut être défini avec hwloc_obj_set_subtype() pour afficher autre chose que 'Group' comme nom de type pour cet objet dans lstopo. Des paires nom-valeur personnalisées peuvent être ajoutées avec hwloc_obj_add_info() après insertion.

L'attribut dont_merge du groupe peut être défini à 1 pour empêcher le cœur hwloc de fusionner cet objet avec un autre objet hiérarchiquement identique. Ceci est utile lorsque le Groupe lui-même décrit une caractéristique importante qui ne peut être exposée nulle part ailleurs dans la hiérarchie.

L'attribut kind du groupe peut être défini à une valeur élevée telle que 0xffffffff pour indiquer à hwloc que ce nouveau Groupe doit toujours être écarté au profit de tout Groupe existant ayant la même localité.

Note

L'insertion d'un groupe ajoute des informations de localité à la topologie, par conséquent les objets existants peuvent être réordonnés (y compris les PU et les nœuds NUMA), et leurs indices logiques peuvent changer.

Si l'insertion échoue, l'objet groupe d'entrée est libéré.

Si l'objet groupe doit être écarté au lieu d'être inséré, il peut être passé à hwloc_topology_free_group_object() à la place.

topology doit être le même que celui passé précédemment à hwloc_topology_alloc_group_object().

Retourne

L'objet inséré s'il a été correctement inséré.

Un objet existant si le Groupe a été fusionné ou écarté parce que la topologie contenait déjà un objet au même emplacement (le Groupe n'a ajouté aucune information hiérarchique).

NULL si l'insertion a échoué en raison de conflits d'ensembles dans l'arbre de la topologie.

NULL si les objets Groupe sont filtrés hors de la topologie (HWLOC_TYPE_FILTER_KEEP_NONE).

NULL si l'objet a été écarté parce qu'aucun ensemble n'a été initialisé dans le Groupe avant l'insertion, ou s'ils étaient tous vides.

hwloc_obj_t hwloc_topology_insert_misc_object (hwloc_topology_t topology, hwloc_obj_t parent, const char * name)

Ajoute un objet MISC comme feuille de la topologie. Un nouvel objet MISC sera créé et inséré dans la topologie à la position donnée par parent. Il est ajouté à la liste des enfants MISC existants, sans jamais ajouter de niveau hiérarchique intermédiaire. Ceci est utile pour annoter la topologie sans changer réellement la hiérarchie.

name est supposé être unique parmi tous les objets Misc de la topologie. Il sera dupliqué pour configurer les attributs du nouvel objet.

Le nouvel objet feuille n'aura pas de cpuset.

L'attribut subtype de l'objet peut être défini avec hwloc_obj_set_subtype() après une insertion réussie.

Retourne

le nouvel objet créé

NULL en cas d'erreur.

NULL si les objets Misc sont filtrés hors de la topologie (HWLOC_TYPE_FILTER_KEEP_NONE).

Note

Si name contient des caractères non imprimables, ils seront supprimés lors de l'exportation en XML, voir hwloc_topology_export_xml() dans hwloc/export.h.

int hwloc_topology_refresh (hwloc_topology_t topology)

Actualise les structures internes après modification de la topologie. La modification de la topologie (en restreignant, ajoutant des objets, modifiant des structures telles que les distances ou les attributs mémoire, etc.) peut rendre certains caches internes invalides. Ces caches sont automatiquement actualisés lors de leur accès, mais cette actualisation n'est pas thread-safe.

Cette fonction n'est pas non plus thread-safe, mais c'est un bon moyen de terminer une phase de modification de topologie non thread-safe. Une fois cette actualisation effectuée, plusieurs threads peuvent consulter simultanément la topologie, les objets, les distances, les attributs, etc.

Voir aussi Thread Safety

Retourne

0 en cas de succès.

-1 en cas d'erreur, par exemple si une réallocation interne a échoué.

int hwloc_topology_restrict (hwloc_topology_t restrict topology, hwloc_const_bitmap_t set, unsigned long flags)

Restreint la topologie à l'ensemble de CPU ou de nœuds donné. La topologie topology est modifiée de manière à supprimer tous les objets qui ne sont pas inclus (ou partiellement inclus) dans l'ensemble de CPU set. Tous les ensembles de CPU et de nœuds des objets sont ajustés en conséquence.

Par défaut, set est un ensemble de CPU. Cela signifie que l'ensemble des PU dans la topologie est restreint. Une fois que certaines PU ont été supprimées, leurs parents peuvent également être supprimés récursivement s'ils n'ont plus d'enfants.

Si HWLOC_RESTRICT_FLAG_BYNODESET est passé dans flags, set est considéré comme un ensemble de nœuds au lieu d'un ensemble de CPU. Cela signifie que l'ensemble des nœuds NUMA dans la topologie est restreint (au lieu des PU). Une fois que certains nœuds NUMA ont été supprimés, leurs parents peuvent également être supprimés récursivement s'ils n'ont plus d'enfants.

flags est un ensemble OR de hwloc_restrict_flags_e.

Note

La restriction de la topologie supprime des informations de localité, par conséquent les objets restants peuvent être réordonnés (y compris les PU et les nœuds NUMA), et leurs indices logiques peuvent changer.

Cet appel ne peut pas être annulé en restreignant à nouveau à un ensemble plus grand. Une fois supprimés lors de la restriction, les objets ne peuvent pas être réintroduits, sauf en chargeant une autre topologie avec hwloc_topology_load().

Retourne

0 en cas de succès.

-1 avec errno défini à EINVAL si l'ensemble d'entrée est invalide. La topologie n'est pas modifiée dans ce cas.

-1 avec errno défini à ENOMEM en cas d'échec d'allocation de données internes. La topologie est réinitialisée dans ce cas. Elle doit être soit détruite avec hwloc_topology_destroy() soit configurée et chargée à nouveau.
