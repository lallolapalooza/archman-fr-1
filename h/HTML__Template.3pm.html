DESCRIPTIO

N

Ce module tente de rendre l'utilisation des gabarits HTML simple et naturelle. Il étend le HTML standard avec quelques nouvelles balises de type HTML - "<TMPL_VAR>" "<TMPL_LOOP>", "<TMPL_INCLUDE>", "<TMPL_IF>", "<TMPL_ELSE>" et "<TMPL_UNLESS>". Le fichier écrit avec HTML et ces nouvelles balises est appelé un gabarit. Il est généralement enregistré séparément de votre script - éventuellement même créé par quelqu'un d'autre ! En utilisant ce module, vous remplissez les valeurs des variables, des boucles et des branches déclarées dans le gabarit. Cela vous permet de séparer la conception - le HTML - des données, que vous générez dans le script

Perl.

MOTIVATIO

N

Il est vrai qu'il existe un certain nombre de paquets pour faire des gabarits HTML. D'un côté, vous avez des choses comme HTML::Embperl qui vous permet de mélanger librement Perl avec HTML. De l'autre côté se trouvent des solutions de substitution de variables faites maison. On espère que le module peut trouver une place entre les

deux.

Un avantage de ce module par rapport à une solution complète de type HTML::Embperl est qu'il impose une division importante - conception et programmation. En limitant le programmeur à n'utiliser que des variables simples et des boucles dans le HTML, le gabarit reste accessible aux concepteurs et aux autres personnes non perl. L'utilisation d'une syntaxe de type HTML va plus loin pour rendre le format compréhensible pour les autres. À l'avenir, cette similarité pourrait être utilisée pour étendre les éditeurs/analyseurs HTML existants afin de prendre en charge HTML::

Template.

Un avantage de ce module par rapport aux schémas de remplacement de balises fait maison est la prise en charge des boucles. Dans mon travail, on me demande souvent de produire des tableaux de données en html. Les produire avec des gabarits HTML simplistes entraîne des programmes contenant beaucoup de HTML puisque le HTML lui-même ne peut pas représenter des boucles. L'introduction d'instructions de boucle dans le HTML simplifie considérablement cette situation. Le concepteur peut mettre en page une seule ligne et le programmeur peut la remplir autant de fois que nécessaire - tout ce sur quoi ils doivent se mettre d'accord est les noms des

paramètres.

Pour tout cela, je pense que la meilleure chose à propos de ce module est qu'il ne fait qu

'une seule chose et qu'il le fait rapidement et soigneusement. Il n'essaie pas de remplacer
Perl et HTML, il les augmente juste pour interagir un peu mieux. Et il est plutôt rapide.

TMPL_LOO

P 
<TMPL_LOOP NAME="LOOP_NAME"> ...
</TMPL_LOOP>

La balise "<TMPL_LOOP>" est un peu plus compliquée que "<TMPL_VAR>". La balise "<TMPL_LOOP>" vous permet de délimiter une section de texte et de lui donner un nom. Dans cette boucle nommée, vous placez des "<TMPL_VAR>". Maintenant, vous passez à param() une liste (une référence de tableau) d'assignations de paramètres (références de hachage) pour cette boucle. La boucle itère sur la liste et produit une sortie à partir du bloc de texte pour chaque passage. Les paramètres non définis sont ignorés. Voici un exemple

:

Dans le gabarit

: 
<TMPL_LOOP NAME=EMPLOYEE_INFO>
   Name: <TMPL_VAR NAME=NAME> <br>
   Job:  <TMPL_VAR NAME=JOB>  <p>
</TMPL_LOOP>

Dans votre code Perl

: 
$template->param(
    EMPLOYEE_INFO => [{name => 'Sam', job => 'programmer'}, {name => 'Steve', job => 'soda jerk'}]
);
print $template->output()
;

La sortie est

: 
Name: Sam
Job: programmer
Name: Steve
Job: soda
jerk

Comme vous pouvez le voir ci-dessus, le "<TMPL_LOOP>" prend une liste d'affectations de variables puis itère sur le corps de la boucle en produisant la

sortie.

Souvent, vous voudrez générer le contenu d'un "<TMPL_LOOP>" de manière programmatique. Voici un exemple de la façon dont cela peut être fait (il existe de nombreuses autres façons !)

: 
# quelques tableaux de données à mettre dans une boucle :
my @words     = qw(I Am Cool);
my @numbers   = qw(1 2 3);
my @loop_data = ();              # initialiser un tableau pour contenir votre boucle
while (@words and @numbers) {
    my %row_data;      # obtenir un nouveau hachage pour les données de la ligne
    # remplir cette ligne
    $row_data{WORD}   = shift @words;
    $row_data{NUMBER} = shift @numbers;
    # l'étape cruciale - pousser une référence à cette ligne dans la boucle !
    push(@loop_data, \%row_data);
}
# enfin, assigner les données de boucle au paramètre de boucle, encore une fois avec une référence :
$template->param(THIS_LOOP => \@loop_data)
;

L'exemple ci-dessus fonctionnerait avec un modèle comme

: 
<TMPL_LOOP NAME="THIS_LOOP">
  Word: <TMPL_VAR NAME="WORD">     
  Number: <TMPL_VAR NAME="NUMBER">
</TMPL_LOOP>

Il produirait une sortie comme

: 
Word: I
Number: 1
Word: Am
Number: 2
Word: Cool
Number:
3

Les "<TMPL_LOOP>"s dans les "<TMPL_LOOP>"s sont acceptables et fonctionnent comme vous vous y attendez. Si la syntaxe de l' appel param() vous déroute, voici un exemple d'appel à param avec une boucle imbriquée

Fondamentalement, chaque "<TMPL_LOOP>" reçoit une référence de tableau. À l'intérieur du tableau se trouvent un certain nombre de références de hachage. Ces hachages contiennent les paires nom=>valeur pour un seul passage sur le modèle de

boucle.

À l'intérieur d'un "<TMPL_LOOP>", les seules variables utilisables sont celles du "<TMPL_LOOP>". Les variables dans les blocs extérieurs ne sont pas visibles à l'intérieur d'une boucle de modèle. Pour les geeks de l'informatique parmi vous, un "<TMPL_LOOP>" introduit une nouvelle portée tout comme un appel de sous-routine perl. Si vous voulez que vos variables soient globales vous pouvez utiliser l'option "global_vars" de new() décrit

TMPL_INCLUD

E 
<TMPL_INCLUDE NAME="filename.
tmpl">

Cette balise inclut un modèle directement dans le modèle courant à l'endroit où la balise est trouvée. Le contenu du modèle inclus est utilisé exactement comme si son contenu était physiquement inclus dans le modèle

principal.

Le fichier spécifié peut être un chemin absolu (commençant par un '/' sous Unix, par exemple). S'il n'est pas absolu, le chemin vers le fichier englobant est essayé d'abord. Ensuite, le chemin dans la variable d'environnement "HTML_TEMPLATE_ROOT" est essayé, s'il existe. Ensuite, l'option "path" est consultée, d'abord telle quelle puis avec "HTML_TEMPLATE_ROOT" préfixé si disponible. En dernier recours, le nom de fichier est passé à open() directement. Voir ci-dessous pour plus d'informations sur "HTML_TEMPLATE_ROOT" et l' option "path" de new(

).

En guise de protection contre les inclusions récursives infinies, une limite arbitraire de 10 niveaux de profondeur est imposée. Vous pouvez modifier cette limite avec l' option "max_includes". Voir l'entrée pour l' option "max_includes" ci-dess

ous pour pl

TMPL_I

F 
<TMPL_IF NAME="PARAMETER_NAME"> ...
</TMPL_IF>

La balise "<TMPL_IF>" vous permet d'inclure ou de ne pas inclure un bloc du modèle en fonction de la valeur de un nom de paramètre donné. Si le paramètre reçoit une valeur vraie pour Perl - comme '1' - alors le bloc est inclus dans la sortie. S'il n'est pas défini, ou reçoit une valeur fausse - comme '0' - alors il est ignoré. Les paramètres sont spécifiés de la même manière qu'avec "<TMPL_VA

R>".

Exemple de modèle

: 
<TMPL_IF NAME="BOOL">
  Un texte qui ne s'affiche que si BOOL est vrai !
</TMPL_IF>

Maintenant, si vous appelez "$template->param(BOOL => 1)" alors le bloc ci-dessus sera inclus dans la

sortie.

Les blocs "<TMPL_IF> </TMPL_IF>" peuvent inclure n'importe quel construct HTML::Template valide - "VAR"s et "LOOP"s et d'autres "IF"/"ELSE" blocs. Notez cependant que croiser un "<TMPL_IF>" et un "<TMPL_LOOP>" est

invalide. 
Ne fonctionnera pas :
<TMPL_IF BOOL>
  <TMPL_LOOP SOME_LOOP>
</TMPL_IF>
</TMPL_LOOP>

Si le nom d'un "<TMPL_LOOP>" est utilisé dans un "<TMPL_IF>", le bloc "IF" produira une sortie si la boucle a au moins une ligne. Exemple

: 
<TMPL_IF LOOP_ONE>
  Ceci sera produit si la boucle n'est pas vide.
</TMPL_IF>
<TMPL_LOOP LOOP_ONE>
  ....
</TMPL_LOOP>

AVERTISSEMENT : Une grande partie des avantages de HTML::Template réside dans le découplage de votre Perl et de votre HTML. Si vous introduisez de nombreux cas où vous avez des "TMPL_IF" et des "if" Perl correspondants, vous créerez un problème de maintenance pour garder les deux synchronisés. Je vous suggère d'adopter la pratique de n'utiliser "TMPL_IF" que si vous pouvez le faire sans nécessiter un "if" correspondant dan

s votre
code Perl.

NOTE

S

Les balises de HTML::Template sont censées imiter les balises HTML normales. Cependant, elles ont le droit de « violer les règles ». Quelque chose comme

: 
<img src="<TMPL_VAR IMAGE_SRC>
">

n'est pas vraiment du HTML valide, mais c'est une utilisation parfaitement valide et fonctionnera comme

prévu.

Le "NAME=" dans la balise est facultatif, bien que pour des raisons d'extensibilité je recommande de l'utiliser. Exemple - "<TMPL_LOOP LOOP_NAME>" est

acceptable.

Si vous êtes un fanatique du HTML valide et que vous souhaitiez que vos modèles se conforment à la syntaxe HTML valide, vous pouvez éventuellement taper les balises de modèle sous la forme de commentaires HTML. Cela peut être utile aux auteurs HTML qui souhaiteraient valider la syntaxe HTML de leurs modèles avant le traitement par HTML::Template, ou qui utilisent des outils d'édition compatibles

DTD. 
<!-- TMPL_VAR NAME=PARAM1
-->

Afin de réaliser une économie spectacula

ire de bande passante, les balises stand
ard (non commentaires) seront utilis
ées tout au long de cette documentation.

# Pour les simples TMPL_VARs :

    PARAM  => 'value',
    PARAM2 => 'value'

# Et avec quelques TMPL_LOOPs :
$self->param(
    PARAM              => 'value',
    PARAM2             => 'value',
    LOOP_PARAM         => [{PARAM => VALUE_FOR_FIRST_PASS}, {PARAM => VALUE_FOR_SECOND_PASS}],
    ANOTHER_LOOP_PARAM => [{PARAM => VALUE_FOR_FIRST_PASS}, {PARAM => VALUE_FOR_SECOND_PASS}],

5 - Pour définir la valeur d'un certain nombre de paramètres à l'aide d'une référence de hachage :

output

output() retourne le résultat final du modèle. Dans la plupart des situations, vous voudrez l'imprimer, comme ceci :

print $template->output();

Lorsque la sortie est appelée, chaque occurrence de "<TMPL_VAR NAME=name>" est remplacée par la valeur attribuée à « name » via param(). Si un paramètre nommé n'est pas défini, il est simplement remplacé par ''. Les "<TMPL_LOOP>" sont évalués une fois par ensemble de paramètres, accumulant la sortie à chaque passage.

L'appel à output() est garanti de ne pas modifier l'état de l'objet HTML::Template, au cas où vous vous poseriez la question. Cette propriété est surtout importante pour l'implémentation interne des boucles.

Vous pouvez éventuellement fournir un handle de fichier vers lequel imprimer automatiquement au fur et à mesure de la génération du modèle. Cela peut améliorer les performances et réduire la consommation de mémoire. Exemple :

$template->output(print_to => *STDOUT);

La valeur de retour est indéfinie lorsque l'option "print_to" est utilisée.

query

Cette méthode vous permet d'obtenir des informations sur la structure du modèle. Elle peut être appelée de plusieurs manières. L'utilisation la plus simple de query est simplement de vérifier si un nom de paramètre existe dans le modèle, en utilisant l'option "name" :

if ($template->query(name => 'foo')) {
    # faire quelque chose si une variable de tout type nommée FOO est dans le modèle
}

Cette même utilisation retourne le type du paramètre. Le type est le même que celui de la balise moins le préfixe 'TMPL_'. Ainsi, par exemple, un paramètre "TMPL_VAR" retourne 'VAR' à partir de query().

if ($template->query(name => 'foo') eq 'VAR') {
    # faire quelque chose si FOO existe et est un TMPL_VAR
}

Notez que les variables associées aux "TMPL_IF" et "TMPL_UNLESS" seront identifiées comme 'VAR' sauf si elles sont également utilisées dans une "TMPL_LOOP", auquel cas elles retourneront 'LOOP'.

  <TMPL_VAR NAME="BOP">

    <TMPL_VAR NAME="INNER_BOP">
  </TMPL_LOOP>
</TMPL_LOOP>

# retourne 'LOOP'
$type = $template->query(name => 'EXAMPLE_LOOP');
# retourne ('bop', 'bee', 'example_inner_loop')
@param_names = $template->query(loop => 'EXAMPLE_LOOP');
# les deux retournent 'VAR'
$type = $template->query(name => ['EXAMPLE_LOOP', 'BEE']);
$type = $template->query(name => ['EXAMPLE_LOOP', 'BOP']);
# et celui-ci retourne 'LOOP'
$type = $template->query(name => ['EXAMPLE_LOOP', 'EXAMPLE_INNER_LOOP']);
# et enfin, ceci retourne ('inner_bee', 'inner_bop')
@inner_param_names = $template->query(loop => ['EXAMPLE_LOOP', 'EXAMPLE_INNER_LOOP']);
# pour les noms de paramètres inexistants, vous obtenez undef. Ceci retourne undef.
$type = $template->query(name => 'DWEAZLE_ZAPPA');
# appeler loop sur un nom de paramètre qui n'est pas une boucle provoquera une erreur. Ceci plante :
$type = $template->query(loop => 'DWEAZLE_ZAPPA');

Comme vous pouvez le voir ci-dessus, l'option "loop" retourne une liste de noms de paramètres et les options "name" et "loop" acceptent des références de tableau afin de faire référence à des paramètres à l'intérieur des boucles. Il est interdit d'utiliser "loop" avec un paramètre qui n'est pas une boucle.

Notez que tous les noms sont retournés en minuscules et les types sont en majuscules.

Tout comme param(), query() sans arguments retourne tous les noms de paramètres au niveau supérieur du modèle.

VALEURS PAresseuses

Comme mentionné ci-dessus, les valeurs "TMPL_VAR" et "TMPL_LOOP" peuvent être des références de code. Ces références de code ne sont exécutées que si la variable ou la boucle est utilisée dans le modèle. C'est extrêmement utile si vous souhaitez rendre une variable disponible aux concepteurs de modèles mais que son calcul peut être coûteux, vous ne voulez donc le faire que si nécessaire.

Peut-être qu'un exemple aidera à illustrer. Supposons que vous ayez un modèle comme celui-ci :

<tmpl_if we_care>
  <tmpl_if life_universe_and_everything>
</tmpl_if>

Si le calcul de "life_universe_and_everything" est coûteux, nous pouvons encapsuler son calcul dans une référence de code et HTML::Template n'exécutera ce code que si "we_care" est également vrai.

$tmpl->param(life_universe_and_everything => sub { calculate_42() });

Votre référence de code recevra un seul argument, l'objet HTML::Template en cours d'utilisation. Dans l'exemple ci-dessus, si nous voulions que calculate_42() ait cet objet, nous ferions quelque chose comme ceci :

$tmpl->param(life_universe_and_everything => sub { calculate_42(shift) });

Cette même approche peut également être utilisée pour les "TMPL_LOOP"s :

<tmpl_if we_care>
  <tmpl_loop needles_in_haystack>
    Found <tmpl_var __counter>!
  </tmpl_loop>
</tmpl_if>

Et dans votre code Perl :

$tmpl->param(needles_in_haystack => sub { find_needles() });

La seule différence dans le cas de "TMPL_LOOP" est que la sous-routine doit retourner une référence à un TABLEAU, pas seulement une valeur scalaire.
