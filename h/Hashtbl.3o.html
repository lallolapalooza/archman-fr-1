Tables de hachage et fonctions de hachage.

Les tables de hachage sont des tables d'association hachées, avec modification en place. Comme la plupart des opérations sur une table de hachage modifient leur entrée, elles sont plus couramment utilisées dans le code impératif. La recherche de la valeur associée à une clé (voir Hashtbl.find , Hashtbl.find_opt ) est normalement très rapide, souvent plus rapide que la recherche équivalente dans Map .

Les foncteurs Hashtbl.Make et Hashtbl.MakeSeeded peuvent être utilisés lorsque la performance ou la flexibilité sont essentielles. L'utilisateur fournit des fonctions personnalisées d'égalité et de hachage pour le type de clé, et obtient un type de table de hachage personnalisé pour ce type particulier de clé.

Attention, une table de hachage n'est bonne que dans la mesure où sa fonction de hachage l'est. Une mauvaise fonction de hachage transformera la table en une liste d'association dégénérée, avec une recherche en temps linéaire au lieu d'un temps constant.

La table de hachage Hashtbl.t polymorphique est utile dans des cas plus simples ou dans des environnements interactifs. Elle utilise la fonction de hachage polymorphique Hashtbl.hash définie dans le runtime OCaml (au moment de la rédaction, il s'agit de SipHash), ainsi que l'égalité polymorphique (=) .

Voir Hashtbl.examples .

Alert unsynchronized_access. Les accès non synchronisés aux tables de hachage sont une erreur de programmation.

Accès non synchronisés

Les accès non synchronisés à une table de hachage peuvent entraîner un état de table de hachage invalide. Par conséquent, les accès concurrents aux tables de hachage doivent être synchronisés (par exemple avec un Mutex.t ).

Interface générale

type (!'a, !'b) t

Le type des tables de hachage de type 'a vers type 'b .

val create : ?random:bool -> int -> ('a, 'b) t

Hashtbl.create n crée une nouvelle table de hachage vide, avec une taille initiale supérieure ou égale à la taille suggérée n . Pour de meilleurs résultats, n doit être de l'ordre du nombre attendu d'éléments qui seront dans la table. La table grossit si nécessaire, donc n est juste une estimation initiale. Si n est très petit ou négatif, il est ignoré et une petite taille par défaut est utilisée.

Le paramètre optionnel ~random (un booléen) contrôle si l'organisation interne de la table de hachage est aléatoire à chaque exécution de Hashtbl.create ou déterministe sur toutes les exécutions.

Une table de hachage créée avec ~random mis à false utilise une fonction de hachage fixe ( Hashtbl.hash ) pour distribuer les clés entre les compartiments. Par conséquent, les collisions entre clés se produisent de manière déterministe. Dans les applications web ou d'autres applications sensibles à la sécurité, les modèles de collision déterministes peuvent être exploités par un utilisateur malveillant pour créer une attaque par déni de service : l'attaquant envoie une entrée conçue pour créer de nombreuses collisions dans la table, ralentissant ainsi l'application.

Une table de hachage créée avec ~random mis à true utilise la fonction de hachage indexée Hashtbl.seeded_hash avec un index choisi aléatoirement au moment de la création de la table de hachage. En fait, la fonction de hachage utilisée est sélectionnée aléatoirement parmi 2^{30} fonctions de hachage différentes. Toutes ces fonctions de hachage ont des modèles de collision différents, rendant inefficace l'attaque par déni de service décrite ci-dessus. Cependant, en raison de la randomisation, l'énumération de tous les éléments de la table de hachage à l'aide de Hashtbl.fold ou Hashtbl.iter n'est plus déterministe : les éléments sont énumérés dans des ordres différents à chaque exécution du programme.

Si aucun paramètre ~random n'est donné, les tables de hachage sont créées par défaut en mode non aléatoire. Cette valeur par défaut peut être modifiée soit par programmation en appelant Hashtbl.randomize , soit en définissant le drapeau R dans la variable d'environnement OCAMLRUNPARAM .

Avant 4.00 , le paramètre ~random était absent et toutes les tables de hachage étaient créées en mode non aléatoire.

Vide une table de hachage. Utilisez reset au lieu de clear pour réduire la taille de la table des compartiments à sa taille initiale.

val reset : ('a, 'b) t -> unit

Vide une table de hachage et réduit la taille de la table des compartiments à sa taille initiale.

val copy : ('a, 'b) t -> ('a, 'b) t

Retourne une copie de la table de hachage donnée.

val add : ('a, 'b) t -> 'a -> 'b -> unit

Hashtbl.add tbl key data ajoute une liaison de key à data dans la table tbl .

Attention : Les liaisons précédentes pour key ne sont pas supprimées, mais simplement masquées. C'est-à-dire qu'après avoir effectué Hashtbl.remove tbl key , la liaison précédente pour key , le cas échéant, est restaurée. (Même comportement qu'avec les listes d'association.)

Si vous souhaitez le comportement classique de remplacement des éléments, voir Hashtbl.replace .

val find : ('a, 'b) t -> 'a -> 'b

Hashtbl.find tbl x retourne la liaison actuelle de x dans tbl , ou lève Not_found si aucune liaison de ce type n'existe.

val find_opt : ('a, 'b) t -> 'a -> 'b option

Hashtbl.find_opt tbl x retourne la liaison actuelle de x dans tbl , ou None si aucune liaison de ce type n'existe.

Depuis 4.05

val find_all : ('a, 'b) t -> 'a -> 'b list

Hashtbl.find_all tbl x retourne la liste de toutes les données associées à x dans tbl . La liaison actuelle est renvoyée en premier, puis les liaisons précédentes, dans l'ordre inverse de leur introduction dans la table.

val mem : ('a, 'b) t -> 'a -> bool

Hashtbl.mem tbl x vérifie si x est lié dans tbl .

val remove : ('a, 'b) t -> 'a -> unit

Hashtbl.remove tbl x supprime la liaison actuelle de x dans tbl , restaurant la liaison précédente si elle existe. Elle ne fait rien si x n'est pas lié dans tbl .

val replace : ('a, 'b) t -> 'a -> 'b -> unit

Hashtbl.replace tbl key data remplace la liaison actuelle de key dans tbl par une liaison de key à data . Si key n'est pas liée dans tbl , une liaison de key à data est ajoutée à tbl . Ceci est fonctionnellement équivalent à Hashtbl.remove tbl key suivi de Hashtbl.add tbl key data .

val iter : ('a -> 'b -> unit) -> ('a, 'b) t -> unit

Hashtbl.iter f tbl applique f à toutes les liaisons de la table tbl . f reçoit la clé comme premier argument, et la valeur associée comme deuxième argument. Chaque liaison est présentée exactement une fois à f .

L'ordre dans lequel les liaisons sont passées à f n'est pas spécifié. Cependant, si la table contient plusieurs liaisons pour la même clé, elles sont passées à f dans l'ordre inverse de leur introduction, c'est-à-dire que la liaison la plus récente est passée en premier.

Si la table de hachage a été créée en mode non aléatoire, l'ordre dans lequel les liaisons sont énumérées est reproductible entre les exécutions successives du programme, et même entre les versions mineures d'OCaml. Pour les tables de hachage aléatoires, l'ordre d'énumération est entièrement aléatoire.

Le comportement n'est pas spécifié si la table de hachage est modifiée par f pendant l'itération.

val filter_map_inplace : ('a -> 'b -> 'b option) -> ('a, 'b) t -> unit

Hashtbl.filter_map_inplace f tbl applique f à toutes les liaisons de la table tbl et met à jour chaque liaison en fonction du résultat de f . Si f retourne None , la liaison est supprimée. Si elle retourne Some new_val , la liaison est mise à jour pour associer la clé à new_val .

Les autres commentaires pour Hashtbl.iter s'appliquent également.

val length : ('a, 'b) t ->

int

Hashtbl.length tbl renvoie le nombre de liaisons dans tbl . Cela prend un temps constant. Les liaisons multiples sont comptées une fois chacune, donc Hashtbl.length donne le nombre de fois que Hashtbl.iter appelle son premier

argument.

val randomize : unit ->

unit

Après un appel à Hashtbl.randomize() , les tables de hachage sont créées en mode aléatoire par défaut : Hashtbl.create renvoie des tables de hachage aléatoires, sauf si le paramètre optionnel ~random:false est fourni. Le même effet peut être obtenu en définissant le paramètre R dans la variable d'environnement

OCAMLRUNPARAM.

Il est recommandé que les applications ou les frameworks Web qui doivent se protéger contre l'attaque par déni de service décrite dans Hashtbl.create appellent Hashtbl.randomize() au moment de l'initialisation avant que tout domaine ne soit

créé.

Notez qu'une fois Hashtbl.randomize() appelé, il n'y a aucun moyen de revenir au comportement par défaut non aléatoire de Hashtbl.create . C'est intentionnel. Les tables de hachage non aléatoires peuvent toujours être créées en utilisant Hashtbl.create ~rand

om:false .

val rebuild : ?random:bool -> ('a, 'b) t -> ('a, 'b)

t

Renvoie une copie de la table de hachage donnée. Contrairement à Hashtbl.copy , Hashtbl.rebuild h re-hache toutes les entrées (clé, valeur) de la table originale h . La table de hachage renvoyée est aléatoire si h était aléatoire, ou si le paramètre optionnel random est true, ou si le défaut est de créer des tables de hachage aléatoires ; voir Hashtbl.create pour plus

d'informations.

Hashtbl.rebuild peut être utilisé en toute sécurité pour importer une table de hachage construite par une ancienne version du module Hashtbl , puis sérialisée vers un stockage persistant. Après la désérialisation, appliquez Hashtbl.rebuild pour produire une table de hachage pour la version actuelle du module Hashtbl

Interface

functorielle

L'interface functorielle permet l'utilisation de fonctions de comparaison et de hachage spécifiques, soit pour des raisons de performance/sécurité, soit parce que les clés ne sont pas hachables/comparables avec les fonctions polymorphiques

intégrées.

Par exemple, on pourrait vouloir spécialiser une table pour des clés entières

        struct
          type t = int

          let hash i = i land max_int
        end
      module IntHashtbl = Hashtbl.Make(IntHash)
      let h = IntHashtbl.create 17 in
      IntHashtbl.add h 12

polymorphes

val hash : 'a ->

int

Hashtbl.hash x associe un entier non négatif à toute valeur de n'importe quel type. Il est garanti que si x = y ou Stdlib.compare x y = 0 , alors hash x = hash y . De plus, hash termine toujours, même sur des structures

cycliques.

val hash_param : int -> int -> 'a ->

int

Hashtbl.hash_param meaningful total x calcule une valeur de hachage pour x , avec les mêmes propriétés que pour hash . Les deux paramètres entiers supplémentaires meaningful et total donnent un contrôle plus précis sur le hachage. Le hachage effectue une traversée en largeur, de gauche à droite de la structure x , s'arrêtant après que meaningful nœuds significatifs ont été rencontrés, ou nœuds (significatifs ou non) ont été rencontrés. Si total tel que spécifié par l'utilisateur dépasse une certaine valeur, actuellement 256, alors il est plafonné à cette valeur. Les nœuds significatifs sont : les entiers ; les nombres flottants ; les chaînes de caractères ; les caractères ; les booléens ; et les constructeurs constants. Des valeurs plus grandes de meaningful et total signifient que plus de nœuds sont pris en compte pour calculer la valeur de hachage finale, et donc les collisions sont moins susceptibles de se produire. Cependant, le hachage prend plus de temps. Les paramètres meaningful et total régissent le compromis entre précision et vitesse. Comme choix par défaut, Hashtbl.hash et Hashtbl.seeded_hash prennent meaningful = 10 et total = 100

.
