HTML::TokeParser -

Interface alternat
ive à HTML::Parser

SYNOPSI

S 
require HTML::TokeParser;
$p = HTML::TokeParser->new("index.html") ||
     die "Can't open: $!";
$p->empty_element_tags(1);  # configure its behaviour
while (my $token = $p->get_token) {
    #...
}

DESCRIPTIO

N

Le module "HTML::TokeParser" est une interface alternative à la classe "HTML::Parser". C'est une sous-classe de "HTML::PullParser" avec un ensemble prédéfini de types de jetons. Si vous souhaitez que les jetons soient rapportés différemment, vous voudrez probablement utiliser "HTML::PullParser" di

rectement.

Les méthodes suivantes sont disponibles

:
$p = HTML::TokeParser->new( $filename, %opt
);
$p = HTML::TokeParser->new( $filehandle, %opt
);
$p = HTML::TokeParser->new( \$document, %opt
);
L'argument du constructeur d'objet est soit un nom de fichier, soit un objet fichier, soit le document complet à analyser. Des options supplémentaires peuvent être fournies sous forme de paires clé/valeur et sont traitées comme documenté dans les classes de base.

Si l'argument est un scalaire simple, il est alors considéré comme le nom d'un fichier à ouvrir et à analyser. Si le fichier ne peut pas être ouvert en lecture, le constructeur renverra "undef" et $! vous indiquera pourquoi cela a

échoué.

Si l'argument est une référence à un scalaire simple, ce scalaire est alors considéré comme le document littéral à analyser. La valeur de ce scalaire ne doit pas être modifiée avant que tous les jetons aient été

extraits.

Sinon, l'argument est considéré comme un objet que le "HTML::TokeParser" peut read() lorsqu'il a besoin de plus de données. Typiquement, il s'agira d'un fichier de quelque type. Le flux sera read() jusqu'à la fin de fichier (EOF), mais pas

fermé.

Un nouvel objet "HTML::TokeParser" diffère de ses classes de base par l'activation de l'attribut "unbroken_text" par défaut. Voir HTML::Parser pour une description de cet attribut et d'autres attributs qui influencent la façon dont le document est analysé. Il est souvent judicieux d'activer le comportement "empty_element_tag

s".

Notez que le résultat de l'analyse ne sera probablement pas valide si du UTF-8 brut non décodé est utilisé comme source. Lors de l'analyse de fichiers encodés en UTF-8, activez le décodage

UTF-8 : 
open(my $fh, "<:utf8", "index.html") || die "Can't open 'index.html': $!";
my $p = HTML::TokeParser->new( $fh );
# ...

Si un $filename est passé au constructeur, le fichier sera ouvert en mode brut et le résultat de l'analyse ne sera valide que si son contenu est en Latin-1 ou en ASCII

pur.

Si vous analysez depuis une chaîne de caractères encodée en UTF-8, décodez-la

d'abord : 
utf8::decode($document);
my $p = HTML::TokeParser->new( \$document );
#
...
$p->
get_token
Cette méthode renverra le prochain jeton trouvé dans le document HTML, ou "undef" à la fin du document. Le jeton est renvoyé sous forme de référence de tableau. Le premier élément du tableau sera une chaîne de caractères indiquant le type de ce jeton : "S" pour balise de début, "E" pour balise de fin, "T" pour texte, "C" pour commentaire, "D" pour déclaration, et "PI" pour instruction de traitement. Le reste du tableau de jetons dépend du type comme ceci : 
["S",  $tag, $attr, $attrseq, $text]
["E",  $tag, $text]
["T",  $text, $is_data]
["C",  $text]
["D",  $text]
["PI", $token0,
$text]

où $attr est une référence de hachage, $attrseq est une référence de tableau et le reste sont des scalaires

simples. La section "Argspec" de HTML
::Parser explique les détails.
$p->unget_token( @tokens
)
Si vous avez lu trop de jetons, vous pouvez les remettre en file d'attente pour qu'ils soient renvoyés la prochaine fois que $p->get_token est
appelée.
$p->
get_tag
$p->get_tag( @tags
)
Cette méthode renvoie la prochaine balise de début ou de fin (en ignorant tout autre jeton), ou "undef" s'il n'y a plus de balises dans le document. Si un ou plusieurs arguments sont donnés, nous ignorons les jetons jusqu'à ce que l'un des types de balises spécifiés soit trouvé. Par exemple : 
$p->get_tag("font", "/font")
;

trouvera la prochaine balise de début ou de fin pour un élément

font.

Les informations de la balise sont renvoyées sous forme de référence de tableau de la même manière que pour $p->get_token ci-dessus, mais le code de type (le premier élément) est absent. Une balise de début sera renvoyée comme

ceci : 
[$tag, $attr, $attrseq,
$text]

Le nom de balise des balises de fin est préfixé par "/", c'est-à-dire qu'une balise de fin est renvoyée

comme ceci : 
["/$t
ag", $
text]
$p->
get_text
$p->get_text( @endtags
)
Cette méthode renvoie tout le texte trouvé à la position actuelle. Elle renverra une chaîne de caractères de longueur nulle si le jeton suivant n'est pas du texte. Toutes les entités seront converties en leur caractère correspondant.

Si un ou plusieurs arguments sont donnés, nous renvoyons tout le texte survenant avant la première des balises spécifiées trouvées. Par

exemple : 
$p->get_text("p",
"br");

renverra le texte jusqu'à un élément de paragraphe ou de saut de

ligne.

Le texte peut s'étendre sur des balises qui devraient être converties en texte. Cela est contrôlé par l'attribut $p->{textify}, qui est un hachage définissant comment certaines balises peuvent être traitées comme du texte. Si le nom d'une balise de début correspond à une clé de ce hachage, alors cette balise est convertie en texte. La valeur du hachage est utilisée pour spécifier l'attribut de balise à partir duquel obtenir le texte. Si cet attribut de balise est manquant, alors le nom de la balise en majuscules entouré de crochets est renvoyé, par ex. "[IMG]". La valeur du hachage peut aussi être une référence de sous-programme. Dans ce cas, la routine est appelée avec le contenu du jeton de balise de début comme argument et la valeur de retour est traitée comme le

texte.

La valeur par défaut de $p->{textify}

est : 
{img => "alt", applet =>
"alt"}

Cela signifie que les balises <IMG> et <APPLET> sont traitées comme du texte, et que le texte à substituer peut être trouvé dans l'attribut

ALT.
$p->
get_trimmed_text
$p->get_trimmed_text( @endtags
)
Identique à $p->get_text ci-dessus, mais réduira toute séquence d'espaces blancs à un seul caractère espace. Les espaces blancs de début et de fin sont
supprimés.
$p->
get_phrase
Cela renverra tout le texte trouvé à la position actuelle en ignorant les balises de niveau phrasal. Le texte est extrait jusqu'à la première balise non de niveau phrasal. La conversion des balises en texte est la même que pour get_text(). Cette méthode réduira les espaces blancs de la même manière que get_trimmed_text().

La définition des <i>

balises de niveau ph
rasal</i> est
obtenue à partir du
module HTML::Tagset.

EXEMPLE

S

Cet exemple extrait tous les liens d'un document. Il imprimera une ligne pour chaque lien, contenant l'URL et la description textuelle entre les balises <A>...</A>

: 
use HTML::TokeParser;
$p = HTML::TokeParser->new(shift||"index.html");
while (my $token = $p->get_tag("a")) {
    my $url = $token->[1]{href} || "-";
    my $text = $p->get_trimmed_text("/a");
    print "$url\t$text\n";
}

Cet exemple extrait le <TITLE> du document

: 
use HTML::TokeParser;
$p = HTML::TokeParser->new(shift||"index.html");
if ($p->get_tag("title")) {
    my $title = $p->get_trimmed_text;
    print "Title: $title\n";
}
