HTML::Element::traverse(3pm) Documentation Perl fournie par l'utilisateur HTML::Element::traverse(3pm)

NOM

HTML::Element::traverse - discussion de la méthode traverse de HTML::Element

VERSION

Ce document décrit la version 5.07 de HTML::Element::traverse, publiée le 31 août 2017 dans le cadre de HTML-Tree.

SYNOPSIS

# $element->traverse est inutile et obscur.
#   Ne l'utilisez pas dans du nouveau code.

DESCRIPTION

"HTML::Element" fournit une méthode "traverse" qui parcourt l'arbre et appelle des routines de rappel spécifiées par l'utilisateur pour chaque nœud, en préordre ou postordre. Cependant, l'utilisation de la méthode est assez superflue : si vous voulez visiter récursivement chaque nœud de l'arbre, il est presque toujours plus simple d'écrire une sous-routine qui fait exactement cela, plutôt que de regrouper le code préordre et/ou postordre dans des routines de rappel pour la méthode "traverse".

EXEMPLES

Supposons que vous vouliez parcourir un nœud $tree et ses descendants et attribuer un attribut 'id' aux éléments s'ils n'en ont pas déjà un.

Vous pouvez utiliser la méthode "traverse" :

{
  my $counter = 'x0000';
  $start_node->traverse(
    [ # Callbacks;
      # rappel préordre :
      sub {
        my $x = $_[0];
        $x->attr('id', $counter++) unless defined $x->attr('id');
        return HTML::Element::OK; # continuer le parcours
      },
      # rappel postordre :
      undef
    ],
    1, # ne pas appeler les routines de rappel pour les nœuds texte
  );
}

Ou vous pouvez simplement faire simple et clair (et ne pas avoir à comprendre le format d'appel de "traverse") en écrivant une sous-routine qui parcourt l'arbre en s'appelant elle-même :

{
  my $counter = 'x0000';
  sub give_id {
    my $x = $_[0];
    $x->attr('id', $counter++) unless defined $x->attr('id');
    foreach my $c ($x->content_list) {
      give_id($c) if ref $c; # ignorer les nœuds texte
    }
  };
  give_id($start_node);
}

Voyez, n'est-ce pas agréable et clair ?

Mais, si vous avez vraiment besoin de savoir :

LA MÉTHODE TRAVERSE

La méthode traverse() est une méthode générale pour parcourir un arbre ou un sous-arbre et appeler des routines de rappel spécifiées par l'utilisateur. Elle accepte les syntaxes suivantes :

$h->traverse(\&callback)
ou $h->traverse(\&callback, $ignore_text)
ou $h->traverse( [\&pre_callback,\&post_callback] , $ignore_text)

Toutes ces syntaxes signifient de parcourir l'élément et tous ses enfants. C'est-à-dire que cette méthode commence au nœud $h, visite $h en "préordre", parcourt ses enfants, puis visitera $h en "postordre". "Visiter" signifie que la routine de rappel est appelée, avec ces arguments :

$_[0] : le nœud (élément ou segment de texte),
$_[1] : un indicateur de début, et
$_[2] : la profondeur

Si le paramètre $ignore_text est donné et vrai, alors l'appel préordre *ne se* produira *pas* pour le contenu textuel.

L'indicateur de début vaut 1 lorsque nous entrons dans un nœud (c'est-à-dire dans les appels préordre) et 0 lorsque nous quittons le nœud (dans les appels postordre).

Notez cependant que les appels postordre ne se produisent pas pour les nœuds qui sont des segments de texte ou qui sont des éléments prototypiquement vides (comme "br", "hr", etc.).

Si nous visitons les nœuds texte (c'est-à-dire, à moins que $ignore_text ne soit donné et vrai), alors lorsque les nœuds texte sont visités, nous passerons également deux arguments supplémentaires à la routine de rappel :

$_[3] : l'élément qui est le parent
         de ce nœud texte
$_[4] : l'index de ce nœud texte
         dans la liste de contenu de son parent

Notez que vous pouvez spécifier que la routine préordre peut être une routine différente de celle postordre :

$h->traverse( [\&pre_callback,\&post_callback], ...);

Vous pouvez également spécifier qu'aucun appel postordre ne doit être effectué, en fournissant une valeur fausse comme routine postordre :

$h->traverse([ \&pre_callback,0 ], ...);

Et de même pour supprimer les rappels préordre :

$h->traverse([ 0,\&post_callback ], ...);

Notez que ces deux syntaxes spécifient la même opération :

$h->traverse([\&foo,\&foo], ...);
$h->traverse( \&foo       , ...);

Les valeurs de retour des appels à vos routines préordre ou postordre sont significatives et sont utilisées pour contrôler la récursion dans l'arbre.

Voici les valeurs que vous pouvez retourner, classées par ordre décroissant de mon estimation de leur utilité :

HTML::Element::OK, 1, ou toute autre valeur vraie
...pour continuer le parcours.

Notez que "HTML::Element::OK" et al sont des constantes. Donc, si vous exécutez sous "use strict" (comme j'espère que vous le faites), et que vous écrivez : "return HTML::Element::PRUEN" le compilateur signalera une erreur (un bareword non autorisé, spécifiquement), alors que si vous écrivez PRUNE correctement, le compilateur ne se plaindra pas.

undef, 0, '0', '', ou HTML::Element::PRUNE
...pour bloquer le parcours sous le contenu de l'élément actuel. (Ceci est ignoré s'il est reçu d'un rappel postordre, car la récursion a déjà eu lieu.) Si ceci est retourné par un rappel préordre, aucun rappel postordre pour le nœud actuel n'aura lieu. (Rappelez-vous que si votre routine de rappel se termine simplement par "return;", elle retourne undef - au moins en contexte scalaire, et "traverse" appelle toujours vos routines de rappel en contexte scalaire.)
HTML::Element::ABORT
...pour abandonner immédiatement tout le parcours. Ceci est souvent utile lorsque vous recherchez juste le premier nœud dans l'arbre qui répond à un critère donné.
HTML::Element::PRUNE_UP
...pour abandonner la poursuite du parcours dans ce nœud et son nœud parent. Aucun rappel postordre pour le nœud actuel ou parent n'aura lieu.
HTML::Element::PRUNE_SOFTLY
Comme PRUNE, sauf que l'appel postordre pour le nœud actuel n'est pas bloqué.

Presque toutes les tâches liées à l'extraction d'informations d'un arbre peuvent être exprimées en termes d'opérations de parcours (généralement en une seule passe, et généralement en ne prêtant attention qu'au préordre, ou qu'au postordre), ou d'opérations basées sur le parcours. (En fait, de nombreuses autres méthodes de cette classe sont essentiellement des appels à traverse() avec des arguments particuliers.)

Le code source de HTML::Element et HTML::TreeBuilder contient plusieurs exemples d'utilisation de la méthode "traverse" pour collecter des informations sur le contenu des arbres et des sous-arbres.

(Note : vous ne devriez pas modifier la structure d'un arbre *pendant* que vous le parcourez.)

[Fin de la documentation pour la méthode traverse()]

Parcours avec des Routines Anonymes Récursives

Maintenant, si vous avez trop lu *Structure et Interprétation des Programmes Informatiques*, peut-être voulez-vous même une lambda récursive. Allez-y :

{
  my $counter = 'x0000';
  my $give_id;
  $give_id = sub {
    my $x = $_[0];
    $x->attr('id', $counter++) unless defined $x->attr('id');
    foreach my $c ($x->content_list) {
      $give_id->($c) if ref $c; # ignorer les nœuds texte
    }
  };
  $give_id->($start_node);
  undef $give_id;
}

C'est un peu fou, et c'est *toujours* plus concis qu'un appel à la méthode "traverse" !

Il est laissé comme exercice au lecteur de trouver comment faire la même chose sans utiliser du tout de symbole $give_id.

Il est également laissé comme exercice au lecteur de

pour comprendre pourquoi je annule $give_id, ci-dessus ; et pourquoi j'ai pu obtenir le même effet avec n'importe lequel de :

 $give_id = 'I like pie!';
# ou...
 $give_id = [];
# ou même ;
 $give_id = sub { print "Mmmm pie!\n" };

Mais pas :

 $give_id = sub { print "I'm $give_id and I like pie!\n" };
# ni...
 $give_id = \$give_id;
# ni...
 $give_id = { 'pie' => \$give_id, 'mode' => 'a la' };

Faire des Choses Récurrentes de Manière Itérative

Notez que vous pouvez parfois voir une implémentation itérative du parcours en pré-ordre, comme ceci :

{
  my @to_do = ($tree); # nœud de départ
  while(@to_do) {
    my $this = shift @to_do;
    # "Visiter" le nœud :
    $this->attr('id', $counter++)
     unless defined $this->attr('id');
    unshift @to_do, grep ref $_, $this->content_list;
     # Mettre les enfants sur la pile -- ils seront visités ensuite
  }
}

Cela peut dans certaines circonstances être plus efficace qu'une simple routine récursive, mais au prix d'être plutôt obscur. Cela gagne en efficacité en évitant la surcharge des appels de fonction, mais comme il y a plusieurs appels de méthode quoi que vous fassiez (pour "attr" et "content_list"), la surcharge d'un simple appel de fonction est insignifiante.

Élagage et Autres Choses

La "traverse" méthode a effectivement les fonctionnalités assez pratiques des signaux "ABORT", "PRUNE_UP" et "PRUNE_SOFTLY" . Aucune de celles-ci ne peut être implémentée totalement de manière simple avec des routines récursives, mais c'est tout à fait possible. Un comportement de type "ABORT"peut être implémenté soit en utilisant un retour non local avec "eval"/"die":

my $died_on; # si vous avez besoin de savoir où...
sub thing {
  ... visite $_[0]...
  ... peut-être mettre $died_on à $_[0] et die "ABORT_TRAV" ...
  ... sinon appeler thing($child) pour chaque enfant...
  ...toute visite en post-ordre de $_[0]...
}
eval { thing($node) };
if($@) {
  if($@ =~ m<^ABORT_TRAV>) {
    ...il est mort (a aborté) sur $died_on...
  } else {
    die $@; # une VRAIE erreur s'est produite
  }
}

ou vous pouvez simplement le faire avec des drapeaux :

my($abort_flag, $died_on);
sub thing {
  ... visite $_[0]...
  ... peut-être mettre $abort_flag = 1; $died_on = $_[0]; return;
  foreach my $c ($_[0]->content_list) {
    thing($c);
    return if $abort_flag;
  }
  ...toute visite en post-ordre de $_[0]...
  return;
}
$abort_flag = $died_on = undef;
thing($node);
...si $abort_flag est défini, il est mort sur $died_on
