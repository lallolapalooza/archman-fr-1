HTTP__Config(3pm)

Paquet: perl-http-message

Licences: Artistic-1.0-Perl OR GPL-1.0-or-later

HTTP::Config(3) Documentation Perl fournie par la communauté HTTP::Config(3)

SYNOPSIS

use HTTP::Config;
my $c = HTTP::Config->new;
$c->add(m_domain => ".example.com", m_scheme => "http", verbose => 1);

use HTTP::Request;
my $request = HTTP::Request->new(GET => "http://www.example.com");

if (my @m = $c->matching($request)) {
   print "Yadayada\n" if $m[0]->{verbose};
}

DESCRIPTION

Un objet "HTTP::Config" est une liste d'entrées qui peuvent être comparées à des requêtes ou à des paires requête/réponse. Son but est de conserver des données de configuration qui peuvent être recherchées en fonction d'un objet requête ou réponse.

Chaque entrée de configuration est une table de hachage. Certaines clés spécifient la correspondance à effectuer avec les attributs des objets requête/réponse. D'autres clés peuvent être utilisées pour conserver des données utilisateur.

Les méthodes suivantes sont fournies :

$conf = HTTP::Config->new
Construit un nouvel objet "HTTP::Config" vide et le retourne.
$conf->entries
Retourne la liste des entrées dans l'objet de configuration. En contexte scalaire, retourne le nombre d'entrées.
$conf->empty
Retourne vrai s'il n'y a pas d'entrées dans l'objet de configuration. C'est juste un raccourci pour "not $conf->entries".
$conf->add( %matchspec, %other )
$conf->add( \%entry )
Ajoute une nouvelle entrée à la configuration. Vous pouvez soit passer des paires clé/valeur séparées, soit une référence de table de hachage.
$conf->remove( %spec )
Supprime (et retourne) les entrées qui correspondent à toutes les paires clé/valeur dans %spec. Si %spec est vide, cela correspondra à toutes les entrées ; le résultat sera donc de vider l'objet de configuration.
$conf->matching( $uri, $request, $response )
$conf->matching( $uri )
$conf->matching( $request )
$conf->matching( $response )
Retourne les entrées qui correspondent au triplet $uri, $request et $response donné.

Si appelé avec un seul objet $request, alors le $uri est obtenu en appelant sa méthode 'uri_canonical'. Si appelé avec un seul objet $response, alors l'objet requête est obtenu en appelant sa méthode 'request'; puis le $uri est obtenu comme si une seule $request avait été fournie.

Les entrées sont retournées avec les correspondances les plus spécifiques en premier. En contexte scalaire, retourne la correspondance la plus spécifique ou "undef" si aucune correspondance n'est trouvée.

$conf->add_item( $item, %matchspec )
$conf->remove_items( %spec )
$conf->matching_items( $uri, $request, $response )
Enveloppes qui masquent les entrées elles-mêmes.

Correspondance

Les clés suivantes d'une entrée de configuration spécifient la correspondance. Pour toutes ces clés, vous pouvez fournir un tableau de valeurs au lieu d'une seule valeur. L'entrée correspond si au moins une des valeurs du tableau correspond.

Les entrées qui nécessitent une correspondance avec un attribut d'objet réponse ne correspondront jamais, sauf si un objet réponse a été fourni.

m_scheme => $scheme
Correspond si l'URI utilise le schéma spécifié ; par exemple, "http".
m_secure => $bool
Si $bool est VRAI ; correspond si l'URI utilise un schéma sécurisé. Si $bool est FAUX ; correspond si l'URI n'utilise pas de schéma sécurisé. Un exemple de schéma sécurisé est "https".
m_host_port => "$hostname:$port"
Correspond si la méthode host_port de l'URI retourne la valeur spécifiée.
m_host => $hostname
Correspond si la méthode host de l'URI retourne la valeur spécifiée.
m_port => $port
Correspond si la méthode port de l'URI retourne la valeur spécifiée.
m_domain => ".$domain"
Correspond si la méthode host de l'URI retourne une valeur qui se trouve dans le domaine donné. Le nom d'hôte "www.example.com" correspondra par exemple au domaine ".com".
m_path => $path
Correspond si la méthode path de l'URI retourne la valeur spécifiée.
m_path_prefix => $path
Correspond si le chemin de l'URI est le chemin spécifié ou a le chemin spécifié comme préfixe.
m_path_match => $Regexp
Correspond si l'expression régulière correspond au chemin de l'URI. Par exemple, qr/\.html$/.
m_method => $method
Correspond si la méthode de requête correspond à la valeur spécifiée. Par exemple, "GET" ou "POST".
m_code => $digit
m_code => $status_code
Correspond si le code d'état de la réponse correspond. Si un seul chiffre est spécifié ; correspond à tous les codes d'état de réponse commençant par ce chiffre.
m_proxy => $url
Correspond si la requête doit être envoyée au serveur Proxy donné.
m_media_type => "*/*"
m_media_type => "text/*"
m_media_type => "html"
m_media_type => "xhtml"
m_media_type => "text/html"
Correspond si le type de média de la réponse correspond.

Avec une valeur de "html", correspond si $response->content_is_html retourne VRAI. Avec une valeur de "xhtml", correspond si $response->content_is_xhtml retourne VRAI.

m_uri__$method => undef
Correspond si l'objet URI fournit la méthode.
m_uri__$method => $string
Correspond si la méthode $method de l'URI retourne la valeur donnée.
m_header__$field => $string
Correspond si la requête ou la réponse a un en-tête $field avec la valeur donnée.
m_response_attr__$key => undef
m_response_attr__$key => $string
Correspond si l'objet réponse a cette clé, ou si l'entrée a la valeur donnée.
