DESCRIPTIO

N

Les objets de la classe "HTML::Parser" reconnaîtront le balisage et le sépareront du texte brut (alias contenu de données) dans les documents HTML. Au fur et à mesure que les différents types de balisage et de texte sont reconnus, les gestionnaires d'événements correspondants sont

invoqués.

"HTML::Parser" n'est pas un analyseur SGML générique. Nous avons essayé de le rendre capable de traiter le HTML qui est réellement « là-bas », et il analyse normalement aussi près que possible de la façon dont les navigateurs web populaires le font, au lieu de suivre strictement l'une des nombreuses spécifications HTML du W3C. Lorsqu'il y a désaccord, il y a souvent une option que vous pouvez activer pour obtenir le comportement

officiel.

Le document à analyser peut être fourni en morceaux arbitraires. Cela rend possible l'analyse à la volée au fur et à mesure que les documents sont reçus depuis le

réseau.

Si l'analyse pilotée par événements ne vous convient pas pour votre application, vous pourriez vouloir utiliser "HTML::PullParser". C'est une sous-classe d'"HTML::Parser" qui permet une structure de programme plus

conventionnelle
.

MÉTHODE

S

La méthode suivante est utilisée pour construire un nouvel objet "HTML::Parser"

:
$p = HTML::Parser->new( %options_et_gestionnaires
)
Cette méthode de classe crée un nouvel objet "HTML::Parser" et le retourne. Des paires clé/valeur peuvent être fournies pour assigner des gestionnaires d'événements ou initialiser des options de l'analyseur. Les gestionnaires et les options de l'analyseur peuvent également être définis ou modifiés plus tard par les appels de méthode décrits ci-dessous.

Si une clé de premier niveau est de la forme "<événement>_h" (par ex., "text_h"), elle assigne un gestionnaire à cet événément, sinon elle initialise une option de l'analyseur. La valeur de spécification du gestionnaire d'événements doit être une référence de tableau. Plusieurs gestionnaires peuvent également être assignés avec l'option 'handlers => [%handlers]'. Voir les exemples

ci-dessous.

Si new() est appelé sans aucun argument, il créera un analyseur qui utilise des méthodes de rappel compatibles avec la version 2 de "HTML::Parser". Voir la section sur la « compatibilité avec la version 2 » ci-dessous pour plus de

détails.

L'option de construction spéciale 'api_version => 2' peut être utilisée pour initialiser les rappels de version 2 tout en définissant d'autres options et gestionnaires. L'option 'api_version => 3' peut être utilisée si vous ne voulez définir aucune option et ne voulez pas revenir au mode compatible

v2.

Exemples

: 
$p = HTML::Parser->new(
  api_version => 3,
  text_h => [ sub {...}, "dtext"
] );

Cela crée un nouvel objet analyseur avec un sous-programme de gestionnaire d'événement de texte qui reçoit le texte original avec les entités générales

décodées. 
$p = HTML::Parser->new(
  api_version => 3,
  start_h => [ 'my_start', "self,tokens"
] );

Cela crée un nouvel objet analyseur avec une méthode de gestionnaire d'événement de début qui reçoit le $p et le tableau de

tokens. 
$p = HTML::Parser->new(
  api_version => 3,
  handlers => {
    text => [\@array, "event,text"],
    comment => [\@array, "event,text"],
} );

Cela crée un nouvel objet analyseur qui stocke le type d'événement et le texte original dans @array pour les événement

Tokenpos fait qu'une référence à un tableau de positions de jetons est transmise. Pour chaque chaîne qui apparaît dans s="Li">"tokens", ce tableau contient deux nombres. Le premier nombre est le décalage du début du token dans le "text" original et le second nombre est la longueur du token.

Les attributs booléens dans un événement "start" auront (0,0) pour le décalage et la longueur de la valeur de l'attribut.

Ceci renvoie undef s'il n'y a pas de tokens dans l'événement (par exemple, "text") et pour les événements "end" artificiels déclenchés par des balises d'éléments vides.

Si vous utilisez ces décalages et longueurs pour modifier le "text", vous devriez travailler de droite à gauche, ou être très prudent pour calculer les changements apportés aux décalages.

"tokens"
Tokens provoque le passage d'une référence à un tableau de chaînes de tokens. Les chaînes sont exactement telles qu'elles ont été trouvées dans le texte original, aucune décodage ou modification de casse n'est appliqué.

Pour les événements "declaration", le tableau contient chaque mot, commentaire et chaîne délimitée commençant par le type de déclaration.

Pour les événements "comment", cela contient chaque sous-commentaire. Si $p->strict_comments est désactivé, il n'y aura qu'un seul sous-commentaire.

Pour les événements "start", cela contient le nom de la balise original suivi des paires nom/valeur d'attributs. Les valeurs des attributs booléens seront soit la valeur définie par $p->boolean_attribute_value, soit le nom de l'attribut si aucune valeur n'a été définie par $p->boolean_attribute_value.

Pour les événements "end", cela contient le nom de la balise original (toujours un token).

Pour les événements "process", cela contient les instructions de traitement (toujours un token).

Ceci renvoie "undef" pour les événements "text".

"text"
Text provoque le passage du texte source (y compris les délimiteurs d'éléments de balisage).
"undef"
Passe une valeur indéfinie. Utile comme remplissage lorsque la même routine de gestionnaire est enregistrée pour plusieurs événements.
'...'
Une chaîne littérale de 0 à 255 caractères entourée de guillemets simples (' ) ou doubles (") est passée telle quelle.

L'ensemble de la chaîne argspec peut être encapsulé dans '@{...}' pour signaler que le tableau d'événements résultant doit être aplati. Cela ne fait une différence que si une référence de tableau est utilisée comme cible du gestionnaire. Considérez cet exemple :

$p->handler(text => [], 'text');
$p->handler(text => [], '@{text}']);

Avec deux événements de texte ; "foo", "bar" ; alors le premier exemple se retrouvera avec [ ["foo"], ["bar"]] et le second avec ["foo", "bar"] dans le tableau cible du gestionnaire.

Événements

Les gestionnaires pour les événements suivants peuvent être enregistrés :

"comment"
Cet événement est déclenché lorsqu'un commentaire de balisage est reconnu.

Exemple :

<!-- Ceci est un commentaire -- -- Ceci aussi -->
"declaration"
Cet événement est déclenché lorsqu'une déclaration de balisage est reconnue.

Pour les documents HTML typiques, la seule déclaration que vous trouverez probablement est <!DOCTYPE ...>.

Exemple :

<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN"
    "http://www.w3.org/TR/html4/strict.dtd">

Les DTD à l'intérieur de <!DOCTYPE ...> perturberont HTML::Parser.

"default"
Cet événement est déclenché pour les événements qui n'ont pas de gestionnaire spécifique. Vous pouvez configurer un gestionnaire pour cet événement afin de capturer ce que vous ne vouliez pas attraper explicitement.
"end"
Cet événement est déclenché lorsqu'une balise de fin est reconnue.

Exemple :

</A>
"end_document"
Cet événement est déclenché lorsque $p->eof est appelé et après que tout texte restant a été vidé. Il n'y a pas de texte de document associé à cet événement.
"process"
Cet événement est déclenché lorsqu'une instruction de traitement de balisage est reconnue.

Le format et le contenu des instructions de traitement dépendent du système et de l'application.

Exemples :

<? instructions de traitement HTML ?>
<? instructions de traitement XML ?>
"start"
Cet événement est déclenché lorsqu'une balise de début est reconnue.

Exemple :

<A HREF="http://www.perl.com/">
"start_document"
Cet événement est déclenché avant tout autre événement pour un nouveau document. Un gestionnaire pour celui-ci peut être utilisé pour initialiser des éléments. Il n'y a pas de texte de document associé à cet événement.
"text"
Cet événement est déclenché lorsqu'un texte brut (caractères) est reconnu. Le texte peut contenir plusieurs lignes. Une séquence de texte peut être interrompue entre plusieurs événements de texte à moins que $p->unbroken_text ne soit activé.

L'analyseur s'assurera de ne pas couper un mot ou une séquence d'espaces blancs entre deux événements de texte.

Unicode

"HTML::Parser" peut analyser des chaînes Unicode lors de l'exécution sous perl-5.8 ou une version supérieure. Si Unicode est passé à $p->parse(), des blocs d'Unicode seront signalés aux gestionnaires. Les spécifications d'arguments de décalage et de longueur rapporteront également leur position en termes de caractères.

Il est sûr d'analyser du UTF-8 brut non décodé si vous évitez de décoder les entités et vous assurez de ne pas utiliser de argspecs qui le font, ou si vous activez le mode "utf8_mode" pour l'analyseur. L'analyse de UTF-8 non décodé peut être utile lors de l'analyse depuis un fichier où vous avez besoin que les décalages et longueurs rapportés correspondent aux décalages d'octets dans le fichier.

Si un nom de fichier est passé à $p->parse_file(), le fichier sera lu en mode binaire. Cela conviendra si le fichier ne contient que des caractères ASCII ou Latin-1. Si le fichier contient du texte encodé en UTF-8, il faudra prendre des précautions lors du décodage des entités comme décrit au paragraphe précédent, mais il est préférable d'ouvrir le fichier avec la couche UTF-8 afin qu'il soit correctement décodé :

open(my $fh, "<:utf8", "index.html") || die "...: $!";
$p->parse_file($fh);

Si le fichier contient du texte encodé dans un jeu de caractères autre qu'ASCII, Latin-1 ou UTF-8, un décodage sera toujours nécessaire.

COMPATIBILITÉ VERSION 2

Lorsqu'un objet "HTML::Parser" est construit sans arguments, un ensemble de gestionnaires est automatiquement fourni, compatible avec les anciennes méthodes de rappel de HTML::Parser version 2.

Cela équivaut aux appels de méthode suivants :

$p->handler(start   => "start",   "self, tagname, attr, attrseq, text");
$p->handler(end     => "end",     "self, tagname, text");
$p->handler(text    => "text",    "self, text, is_cdata");
$p->handler(process => "process", "self, token0, text");
$p->handler(
    comment => sub {
        my ($self, $tokens) = @_;
        for (@$tokens) { $self->comment($_); }
    },
    "self, tokens"
);
$p->handler(
    declaration => sub {
        my $self = shift;
        $self->declaration(substr($_[0], 2, -1));
    },
    "self, text"
);

La mise en place de ces gestionnaires peut également être demandée avec l'option du constructeur "api_version => 2".

SOUS-CLASSEMENT

La classe "HTML::Parser" peut être sous-classée. Les objets analyseurs sont des hachages simples et "HTML::Parser" ne réserve que les clés de hachage commençant par "_hparser". L'état de l'analyseur peut être configuré en appelant la méthode init(), qui prend les mêmes arguments que new().

EXEMPLES

Le premier exemple simple montre comment on peut supprimer les commentaires d'un document HTML. Nous y parvenons en configurant un gestionnaire de commentaires qui ne fait rien et un gestionnaire par défaut qui affichera tout le reste :

use HTML::Parser ();
HTML::Parser->new(
    default_h => [sub { print shift }, 'text'],
    comment_h => [""],
)->parse_file(shift || die)
    || die $!;

Une implémentation alternative est :

use HTML::Parser ();
HTML::Parser->new(
    end_document_h => [sub { print shift }, 'skipped_text'],
    comment_h      => [""],
)->parse_file(shift || die)
    || die $!;

Dans la plupart des cas, ce sera beaucoup plus efficace car un seul rappel sera effectué.

L'exemple suivant affiche le texte contenu dans l'élément <title> d'un document HTML. Ici, nous commençons par configurer un gestionnaire de début. Lorsqu'il voit la balise de début de titre, il active un gestionnaire de texte qui affiche tout texte trouvé et un gestionnaire de fin qui terminera l'analyse dès que la balise de fin de titre sera vue :

use HTML::Parser ();
sub start_handler {
    return if shift ne "title";
    my $self = shift;
    $self->handler(text => sub { print shift }, "dtext");
    $self->handler(
        end => sub {
            shift->eof if shift eq "title";
        },
        "tagname,self"
    );
}
my $p = HTML::Parser->new(api_version => 3);
$p->handler(start => \&start_handler, "tagname,self");
$p->parse_file(shift || die) || die $!;
print "\n";

HTML::Parser - Parse HTML and other SGML documents

NOM

HTML::Parser - Analyser les documents HTML et autres documents SGML

SYNOPIS

    use HTML::Parser;

    my $p = HTML::Parser->new(
        start_char => '<',
        end_char   => '>',
        # options
    );

    # Register handlers
    $p->handler(start => \&my_start_handler, "tagcontent");
    $p->handler(end   => \&my_end_handler,   "tagname");
    $p->handler(text  => \&my_text_handler,  "text");
    $p->handler(process => \&my_proc_handler, "dtext");
    $p->handler(comment => \&my_comment_handler, "comment");
    $p->handler(declaration => \&my_decl_handler, "declaration");

    # Start parsing
    $p->parse($string);
    $p->parse_file($filename);
    $p->parse_io($io_object);

    # Control options
    $p->strict_comment(1);
    $p->boolean_attribute_value(1);
    $p->xml_mode(1);
    $p->unmatched_closing_tags(1);
    $p->case_sensitive(1);
    $p->utf8_mode(1);

    # Access parser state
    my $tag = $p->tag;
    my @attr = $p->attr;
    my $text = $p->text;
    my $comment = $p->comment;
    my $declaration = $p->declaration;
    my $cdata = $p->cdata;
    my $script = $p->script;
    my $style = $p->style;

    # For HTML::PullParser compatibility
    $p->mark(1);
    my $token = $p->get_token;

    # Other methods
    $p->eof;
    $p->error;
    $p->max_parse_depth(1000);
    $p->parse_length;

DESCRIPTION

HTML::Parser is a flexible HTML parser, written in C, that can be used as a basis for a number of other modules, such as HTML::Entities, HTML::PullParser, HTML::TokeParser, HTML::HeadParser, HTML::LinkExtor and HTML::Form. It also provides the basic parsing functionality for the HTML::TreeBuilder module.

The parser provides a callback mechanism for reporting different types of tags and text found in the HTML source. It is configurable to handle various SGML constructs, including comments, declarations, processing instructions, CDATA sections, scripts, and styles.

The parser supports different modes, such as strict comment handling, boolean attribute values, XML mode, and case sensitivity control.

It also offers compatibility features for HTML::PullParser and methods to access the parser's internal state.

METHODS

The following methods are available:

new([OPTIONS])
Constructs a new HTML::Parser object. Options are passed as key/value pairs. Known options are:
  • start_char: The character used to start tags (default: "<").
  • end_char: The character used to end tags (default: ">").
  • case_sensitive: If set to 1, tag and attribute names will be case-sensitive (default: 0).
  • xml_mode: If set to 1, the parser will operate in XML mode, meaning it will treat the input as XML (default: 0).
  • strict_comment: If set to 1, comments will be parsed strictly (default: 0).
  • boolean_attribute_value: If set to 1, boolean attributes will be treated as having a value equal to their name (default: 0).
  • unmatched_closing_tags: If set to 1, unmatched closing tags will be reported (default: 0).
  • utf8_mode: If set to 1, the parser will handle UTF-8 encoded input (default: 0).
  • api_version: Reserved for future extensions.
handler(EVENT, SUB, ARG_SPEC)
Registers a handler for a specific event. EVENT is one of "start", "end", "text", "process", "comment", or "declaration". SUB is the subroutine or method to call. ARG_SPEC specifies what arguments to pass to the handler.
parse(STRING)
Parses the given string.
parse_file(FILENAME)
Parses the file with the given filename.
parse_io(IO_OBJECT)
Parses input from the given IO object.
eof
Returns true if the end of the input has been reached.
error
Returns the last error message, or an empty string if no error occurred.
tag
Returns the current tag name being processed.
attr
Returns a list of attribute name/value pairs for the current tag.
text
Returns the text content of the current element.
comment
Returns the content of the current comment.
declaration
Returns the content of the current declaration.
cdata
Returns the content of the current CDATA section.
script
Returns the content of the current script block.
style
Returns the content of the current style block.
mark([BOOLEAN])
Enables or disables marking of token positions for compatibility with HTML::PullParser.
get_token
Returns the next token for compatibility with HTML::PullParser.
max_parse_depth(INTEGER)
Sets the maximum nesting depth for parsing.
parse_length
Returns the number of characters parsed so far.

VERSION 2 COMPATIBILITY

HTML::Parser version 3.x is backward compatible with version 2.x. However, some methods have been deprecated or removed. It is recommended to use the new API whenever possible.

SUBCLASSING

HTML::Parser can be subclassed to create custom parsers. When subclassing, you should ensure that your subclass properly initializes the parser object and defines the necessary handler methods.

EXAMPLES

The eg/ directory contains several examples of how to use HTML::Parser. You can browse the eg/ directory online from the [Browse] link on the http://search.cpan.org/~gaas/HTML-Parser/ page.

Here is a simple example of how to extract all the links from an HTML document:

    use HTML::Parser;

    my @links;
    my $p = HTML::Parser->new();
    $p->handler(start => sub {
        my ($tag, $attr) = @_;
        if ($tag eq 'a' and defined $attr->{href}) {
            push @links, $attr->{href};
        }
    });
    $p->parse_file('index.html');

    # @links now contains all the links

Note that the script and style sections do not end with the first "</", but require the complete corresponding end tag. The standard behavior is not entirely practical.

BUGS

Les sections <style> et <script> ne se terminent pas avec le premier "</", mais nécessitent la balise de fermeture complète correspondante. Le comportement standard n'est pas vraiment pratique.

Lorsque l'option strict_comment est activée, nous reconnaissons toujours les commentaires où il y a autre chose que des espaces blancs entre les marqueurs "--" pairs et impairs.

Une fois que $p->boolean_attribute_value a été défini, il n'y a aucun moyen de restaurer le comportement par défaut.

Il n'y a actuellement aucun moyen d'obtenir les deux caractères de guillemet dans le même argspec littéral.

Les balises vides, par exemple "<>" et "</>", ne sont pas reconnues. SGML leur permet de répéter la balise de début précédente ou de fermer la balise de début précédente respectivement.

Les balises NET, par exemple "code/.../" ne sont pas reconnues. C'est un raccourci SGML pour "<code>...</code>".

Les balises de début ou de fin incomplètes, par exemple "<tt<b>...</b</tt>" ne sont pas reconnues.

Analyse d'UTF-32 non décodé

Analyse d'UTF-16 non décodé
(W) Le parseur a trouvé la signature Unicode UTF-16 "BOM" au début du document. Le résultat de l'analyse sera probablement incorrect.
