HTTP::Response(3) Documentation Perl fournie par l'utilisateur HTTP::Response(3)

SYNOPSIS

Les objets de réponse sont retournés par la méthode request() de "LWP::UserAgent" :

# ...
$response = $ua->request($request);
if ($response->is_success) {
    print $response->decoded_content;
}
else {
    print STDERR $response->status_line, "\n";
}

DESCRIPTION

La classe "HTTP::Response" encapsule les réponses de type HTTP. Une réponse se compose d'une ligne de réponse, de quelques en-têtes et d'un corps de contenu. Notez que la bibliothèque LWP utilise des réponses de style HTTP même pour les schémas de protocoles non-HTTP. Les instances de cette classe sont généralement créées et retournées par la méthode request() d'un objet "LWP::UserAgent".

"HTTP::Response" est une sous-classe de "HTTP::Message" et hérite donc de ses méthodes. Les méthodes supplémentaires suivantes sont disponibles :

$r = HTTP::Response->new( $code )
$r = HTTP::Response->new( $code, $msg )
$r = HTTP::Response->new( $code, $msg, $header )
$r = HTTP::Response->new( $code, $msg, $header, $content )
Construit un nouvel objet "HTTP::Response" décrivant une réponse avec le code de réponse $code et un message optionnel $msg. L'argument optionnel $header doit être une référence à un objet "HTTP::Headers" ou une référence de tableau simple de paires clé/valeur. L'argument optionnel $content doit être une chaîne d'octets. Les significations de ces arguments sont décrites ci-dessous.
$r = HTTP::Response->parse( $str )
Construit un nouvel objet de réponse en analysant la chaîne donnée.
$r->code
$r->code( $code )
Est utilisé pour obtenir/définir l'attribut de code. Le code est un nombre à 3 chiffres qui encode le résultat global d'une réponse HTTP. Le module "HTTP::Status" fournit des constantes qui offrent des noms mnémotechniques pour l'attribut de code.
$r->message
$r->message( $message )
Est utilisé pour obtenir/définir l'attribut de message. Le message est une courte chaîne lisible par l'homme expliquant le code de réponse.
$r->header( $field )
$r->header( $field => $value )
Est utilisé pour obtenir/définir les valeurs des en-têtes et il est hérité de "HTTP::Headers" via "HTTP::Message". Voir HTTP::Headers pour les détails et d'autres méthodes similaires qui peuvent être utilisées pour accéder aux en-têtes.
$r->content
$r->content( $bytes )
Est utilisé pour obtenir/définir le contenu brut et il est hérité de la classe de base "HTTP::Message". Voir HTTP::Message pour les détails et d'autres méthodes qui peuvent être utilisées pour accéder au contenu.
$r->decoded_content( %options )
Retourne le contenu après le décodage de tout "Content-Encoding" et des jeux de caractères. Voir HTTP::Message pour les détails.
$r->request
$r->request( $request )
Est utilisé pour obtenir/définir l'attribut de requête. L'attribut de requête est une référence à la requête qui a causé cette réponse. Ce n'est pas nécessairement la même requête passée à la méthode $ua->request(), car il aurait pu y avoir des redirections et des tentatives d'autorisation entre-temps.
$r->previous
$r->previous( $response )
Est utilisé pour obtenir/définir l'attribut précédent. L'attribut précédent est utilisé pour lier des chaînes de réponses. Vous obtenez des chaînes de réponses si la première réponse est une redirection ou une autorisation refusée. La valeur est "undef" s'il s'agit de la première réponse d'une chaîne.

Notez que la méthode $r->redirects est fournie comme moyen plus pratique d'accéder à la chaîne de réponses.

$r->status_line
Retourne la chaîne "<code> <message>". Si l'attribut de message n'est pas défini, alors le nom officiel de <code> (voir HTTP::Status) est substitué.
$r->base
Retourne l'URI de base pour cette réponse. La valeur retournée sera une référence à un objet URI.

L'URI de base est obtenu à partir de l'une des sources suivantes (par ordre de priorité) :

1.
Intégré dans le contenu du document, par exemple <BASE HREF="..."> dans les documents HTML.
2.
Un en-tête "Content-Base:" dans la réponse.

Pour des raisons de compatibilité descendante avec les anciennes implémentations HTTP, nous chercherons également l'en-tête "Base:".

3.
L'URI utilisé pour demander cette réponse. Ce pourrait ne pas être l'URI original qui a été passé à la méthode $ua->request(), car nous aurions pu recevoir des réponses de redirection au préalable.

Si aucune de ces sources ne fournit d'URI absolue, undef est retourné.

Note : les versions précédentes de HTTP::Response prenaient également en compte un en-tête "Content-Location:", comme indiqué par la RFC 2616 https://www.rfc-editor.org/rfc/rfc2616. Mais cela n'a jamais été largement implémenté par les navigateurs, et maintenant la RFC 7231 https://www.rfc-editor.org/rfc/rfc7231 indique qu'il ne faut plus en tenir compte.

Lorsque les modules de protocole LWP produisent l'objet HTTP::Response, alors tout URI de base intégré dans le document (étape 1) aura déjà initialisé l'en-tête "Content-Base:". (Voir "parse_head" dans LWP::UserAgent). Cela signifie que cette méthode n'effectue que les 2 dernières étapes (le contenu n'est pas toujours disponible non plus).

$r->filename
Retourne un nom de fichier pour cette réponse. Notez que la validation du nom de fichier retourné (par exemple, supprimer les caractères qui ne peuvent pas être utilisés sur le système de fichiers cible où le nom de fichier serait utilisé, et le nettoyer à des fins de sécurité) relève de la responsabilité de l'appelant ; la seule chose connexe effectuée par cette méthode est qu'elle tente simplement de retourner un nom de fichier simple sans segments de chemin précédents.

Le nom de fichier est obtenu à partir de l'une des sources suivantes (par ordre de priorité) :

1.
Un en-tête "Content-Disposition:" dans la réponse. Le décodage correct des noms de fichiers encodés RFC 2047 nécessite les modules "MIME::QuotedPrint" (pour l'encodage "Q"), "MIME::Base64" (pour l'encodage "B"), et "Encode".
2.
Un en-tête "Content-Location:" dans la réponse.
3.
L'URI utilisé pour demander cette réponse. Ce pourrait ne pas être l'URI original qui a été passé à la méthode $ua->request(), car nous aurions pu recevoir des réponses de redirection au préalable.

Si un nom de fichier ne peut pas être dérivé d'une de ces sources, undef est retourné.

$r->as_string
$r->as_string( $eol )
Retourne une représentation textuelle de la réponse.
$r->is_info
$r->is_success
$r->is_redirect
$r->is_error
$r->is_client_error
$r->is_server_error
Ces méthodes indiquent si la réponse était informationnelle, réussie, une redirection ou une erreur. Voir HTTP::Status pour la signification de celles-ci.
$r->error_as_HTML
Retourne une chaîne contenant un document HTML complet indiquant quelle erreur s'est produite. Cette méthode ne doit être appelée que lorsque $r->is_error est VRAI.
$r->redirects
Retourne la liste des réponses de redirection qui mènent à cette réponse en suivant la chaîne $r->previous. L'ordre de la liste est du plus ancien au plus récent.

En contexte scalaire, retourne le nombre de réponses de redirection qui mènent à celle-ci.

$r->current_age
Calcule l'"âge actuel" de la réponse tel que spécifié par la section 13.2.3 de la RFC 2616. L'âge d'une réponse est le temps écoulé depuis qu'elle a été envoyée par le serveur d'origine. La valeur retournée est un nombre représentant l'âge en secondes.
$r->freshness_lifetime( %opt )
