NOM

HTML::Element - Classe pour les objets représentant des éléments HTML

VERSION

Ce document décrit la version 5.07 de HTML::Element, publiée le 31 août 2017 dans le cadre de HTML-Tree.

SYNOPSIS

use HTML::Element;
$a = HTML::Element->new('a', href => 'http://www.perl.com/');
$a->push_content("The Perl Homepage");
$tag = $a->tag;
print "$tag starts out as:",  $a->starttag, "\n";
print "$tag ends as:",  $a->endtag, "\n";
print "$tag\'s href attribute is: ", $a->attr('href'), "\n";
$links_r = $a->extract_links();
print "Hey, I found ", scalar(@$links_r), " links.\n";
print "And that, as HTML, is: ", $a->as_HTML, "\n";
$a = $a->delete;

DESCRIPTION

(Cette classe fait partie de la distribution HTML::Tree.)

Les objets de la classe HTML::Element peuvent être utilisés pour représenter des éléments d'arbres de documents HTML. Ces objets ont des attributs, notamment des attributs qui désignent le parent et le contenu de chaque élément. Le contenu est un tableau de segments de texte et d'autres objets HTML::Element. Un arbre avec des objets HTML::Element comme nœuds peut représenter l'arbre syntaxique d'un document HTML.

COMMENT NOUS REPRÉSENTONS LES ARBRES

Considérons ce document HTML :

<html lang='en-US'>
  <head>
    <title>Stuff</title>
    <meta name='author' content='Jojo'>
  </head>
  <body>
   <h1>I like potatoes!</h1>
  </body>
</html>

Construire un arbre syntaxique à partir de celui-ci crée une structure arborescente en mémoire qui pourrait être représentée comme ceci :

              html (lang='en-US')
               / \
             /     \
           /         \
         head        body
        /\               \
      /    \               \
    /        \               \
  title     meta              h1
   |       (name='author',     |
"Stuff"    content='Jojo')    "I like potatoes"

C'est la façon traditionnelle de représenter un arbre, avec la « racine » en haut, et c'est ce type de diagramme que les gens ont en tête quand ils disent, par exemple, que « l'élément meta est sous l'élément head au lieu d'être sous l'élément body ». (La même chose est dite avec « à l'intérieur » au lieu de « sous » — l'utilisation de « à l'intérieur » a plus de sens quand on regarde le code source HTML.)

Une autre façon de représenter l'arbre ci-dessus est d'utiliser l'indentation :

html (attributs : lang='en-US')
  head
    title
      "Stuff"
    meta (attributs : name='author' content='Jojo')
  body
    h1
      "I like potatoes"

Par ailleurs, la représentation par indentation fonctionne beaucoup mieux pour les très grands arbres, et est plus facile à générer pour un programme. La "$tree->dump" méthode utilise l'indentation de cette façon.

Quelle que soit la façon dont vous représentez l'arbre, il est stocké de la même manière en mémoire — c'est un réseau d'objets, chacun ayant des attributs comme ceci :

élément #1 :  _tag : 'html'
             _parent : aucun
             _content : [élément #2, élément #5]
             lang : 'en-US'
élément #2 :  _tag : 'head'
             _parent : élément #1
             _content : [élément #3, élément #4]
élément #3 :  _tag : 'title'
             _parent : élément #2
             _content : [segment de texte "Stuff"]
élément #4   _tag : 'meta'
             _parent : élément #2
             _content : aucun
             name : author
             content : Jojo
élément #5   _tag : 'body'
             _parent : élément #1
             _content : [élément #6]
élément #6   _tag : 'h1'
             _parent : élément #5
             _content : [segment de texte "I like potatoes"]

Le caractère « arborescent » de la structure que ces éléments composent n'est pas un aspect d'un objet particulier, mais émerge de la relation entre les attributs (_parent et _content) de ces objets-éléments et de la façon dont vous les utilisez pour passer d'un élément à l'autre.

Bien que vous puissiez accéder au contenu d'un arbre en écrivant du code qui dit « accéder à l'attribut 'src' du premier enfant de la racine, septième enfant de celui-ci, troisième enfant », il est plus probable que vous deviez parcourir le contenu d'un arbre, à la recherche des nœuds, ou des types de nœuds, avec lesquels vous voulez faire quelque chose. La façon la plus simple de parcourir un arbre est de le « parcourir » (traverse) ; une méthode HTML::Element ("$h->traverse") est fournie à cette fin ; et plusieurs autres méthodes HTML::Element sont basées dessus.

(Pour tout ce que vous avez toujours voulu savoir sur les arbres, et même plus, voir l'ouvrage de Niklaus Wirth Algorithms + Data Structures = Programs ou celui de Donald Knuth The Art of Computer Programming, Volume 1.)

Références faibles

Résumé TL;DR : "use HTML::TreeBuilder 5 -weak;" et oubliez la méthode "delete" (sauf pour élaguer un nœud d'un arbre).

Parce que HTML::Element stocke une référence vers l'élément parent, la collecte des orphelins par comptage de références de Perl ne fonctionne pas correctement avec les arbres HTML::Element. À partir de la version 5.00, HTML::Element utilise des références faibles (si disponibles) pour éviter ce problème. Les références faibles ont été introduites dans Perl 5.6.0, mais vous avez aussi besoin d'une version de Scalar::Util qui fournit la fonction "weaken" .

Les références faibles sont activées par défaut. Si vous voulez être certain qu'elles sont utilisées, vous pouvez dire "use HTML::Element 5 -weak;". Vous devez inclure le numéro de version ; les versions précédentes de HTML::Element ignoraient complètement la liste d'importation.

Pour désactiver les références faibles, vous pouvez dire "use HTML::Element -noweak;". C'est un réglage global. Cette fonctionnalité est obsolète et est fournie uniquement comme solution de contournement rapide pour du code cassé. Si votre code ne fonctionne pas correctement avec les références faibles, vous devriez le corriger immédiatement, car les références faibles peuvent devenir obligatoires dans une version future. En général, tout ce que vous devez faire est de conserver une référence vers la racine de l'arbre jusqu'à ce que vous ayez fini de travailler avec.

Parce que HTML::TreeBuilder est une sous-classe de HTML::Element, vous pouvez aussi importer "-weak" ou "-noweak" depuis HTML::TreeBuilder : par exemple "use HTML::TreeBuilder: 5 -weak;".

MÉTHODES DE BASE

new

$h = HTML::Element->new('tag', 'attrname' => 'value', ... );

Cette méthode constructeur retourne un nouvel objet HTML::Element. Le nom de balise est un argument requis ; il sera forcé en minuscules. Optionnellement, vous pouvez spécifier d'autres attributs initiaux lors de la création de l'objet.

attr

$value = $h->attr('attr');
$old_value = $h->attr('attr', $new_value);

Retourne (ou définit optionnellement) la valeur de l'attribut donné de $h. Le nom de l'attribut (mais pas la valeur, si elle est fournie) est forcé en minuscules. Si vous essayez de lire la valeur d'un attribut absent pour cet élément, la valeur retournée est undef. Si vous définissez une nouvelle valeur, l'ancienne valeur de cet attribut est retournée.

Si des méthodes sont fournies pour accéder à un attribut (comme "$h->tag" pour "_tag", "$h->content_list", etc. ci-dessous), utilisez celles-ci au lieu d'appeler attr "$h->attr", que ce soit pour lire ou définir.

Notez que définir un attribut à "undef" (par opposition à "", la chaîne vide) supprime réellement l'attribut.

tag

$tagname = $h->tag();
$h->tag('tagname');

Retourne (ou définit optionnellement) le nom de balise (aussi connu comme identifiant générique) pour l'élément $h. Lors de la définition, le nom de balise est toujours converti en minuscules.

MÉTHODES DE DUMPAGE

dump

$h->dump()
$h->dump(*FH)  ; # ou *FH{IO} ou $fh_obj

Affiche l'élément et tous ses enfants sur STDOUT (ou sur une poignée de fichier spécifiée), dans un format utile uniquement pour le débogage. La structure du document est montrée par indentation (pas de balises de fin).

as_HTML

$s = $h->as_HTML();
$s = $h->as_HTML($entities);
$s = $h->as_HTML($entities, $indent_char);
$s = $h->as_HTML($entities, $indent_char, \%optional_end_tags);

Retourne une chaîne représentant en HTML l'élément et ses descendants. L'argument optionnel $entities spécifie une chaîne des entités à encoder. Pour la compatibilité avec les versions précédentes, spécifiez '<>&' ici. Si omis ou undef, tous les caractères non sûrs sont encodés en entités HTML. Voir HTML::Entities pour plus de détails. Si on passe une chaîne vide, aucune entité n'est encodée.

Si $indent_char est spécifié et défini, le HTML à sortir est indenté, en utilisant la chaîne que vous spécifiez (que vous devriez probablement définir à "\t", ou à un certain nombre d'espaces, si vous le spécifiez).

Si "\%optional_end_tags" est spécifié et défini, cela devrait être une référence vers un hash qui contient une valeur vraie pour chaque nom de balise dont la balise de fin est optionnelle. Par défaut, c'est "\%HTML::Element::optionalEndTag", qui est un alias vers %HTML::Tagset::optionalEndTag, qui, au moment de la rédaction, contient des valeurs vraies pour "p, li, dt, dd". Une valeur utile à passer est un hashref vide, "{}", ce qui signifie qu'aucune balise de fin n'est optionnelle pour ce dump. Sinon, vous pouvez envisager de copier %HTML::Tagset::optionalEndTag dans un hash qui vous appartient, en ajoutant ou supprimant des valeurs comme vous le souhaitez, et en passant une référence vers ce hash.

as_text

$s = $h->as_text();
$s = $h->as_text(skip_dels => 1);

Retourne une chaîne consistant uniquement en parties de texte des descendants de l'élément. Tout espace blanc à l'intérieur de l'élément est inclus inchangé, mais l'espace blanc qui n'est pas dans l'arbre n'est jamais ajouté. Mais rappelez-vous que l'espace blanc peut être ignoré ou compacté par HTML::TreeBuilder pendant l'analyse (selon la valeur des "ignore_ignorable_whitespace" et "no_space_compacting" attributs). De plus, puisque l'espace blanc n'est jamais ajouté pendant l'analyse,

HTML::TreeBuilder->new_from_content("<p>a</p><p>b</p>")
                 ->as_text;

retourne "ab", et non "a b" ou "a\nb".

Le texte sous "<script>" ou "<style>" les éléments n'est jamais inclus dans ce qui est retourné. Si "skip_dels" est vrai, alors le contenu textuel sous les nœuds "<del>" n'est pas inclus dans ce qui est retourné.

as_trimmed_text

$s = $h->as_trimmed_text(...);
$s = $h->as_trimmed_text(extra_chars => '\xA0'); # supprimer &
$s = $h->as_text_trimmed(...); # alias

C'est exactement comme as_text(...) sauf que l'espace blanc en début et en fin est supprimé, et tout espace blanc interne est compacté.

Cela ne supprimera pas les espaces insécables, les espaces Unicode, ou tout autre espace blanc non-ASCII à moins que vous ne fournissiez les caractères supplémentaires comme argument de chaîne (par ex. "$h->as_trimmed_text(extra_chars => '\xA0')"). "extra_chars" peut être toute chaîne qui peut apparaître à l'intérieur d'une classe de caractères, y compris des plages comme "a-z", des classes de caractères POSIX comme "[:alpha:]", et des échappements de classe de caractères comme "\p{Zs}".

$s = $h->as_XML()

Retourne une chaîne représentant en XML l'élément et ses descendants.

Le XML n'est pas indenté.

$s = $h->as_Lisp_form();

Retourne une chaîne représentant l'élément et ses descendants sous la forme d'une forme Lisp. Les caractères non sûrs sont encodés en échappements octaux.

La forme Lisp est indentée, et contient les attributs externes ("href", etc.) ainsi que les attributs internes ("_tag", "_content", "_implicit", etc.), sauf pour "_parent", qui est omis.

Prend un deuxième argument qui est une référence vers un formateur.

MÉTHODES STRUCTURELLES SECONDAIRES

Toutes ces méthodes impliquent un aspect structurel de l'arbre ; soit elles rapportent un aspect de la structure de l'arbre, soit elles impliquent une descente dans l'arbre, ou une remontée dans l'arbre.

is_inside

$inside = $h->is_inside('tag', $element, ...);

Retourne vrai si l'élément $h est, ou est contenu n'importe où à l'intérieur d'un élément qui est l'un de ceux listés, ou dont le nom de balise est l'un des noms de balises listés. Vous pouvez utiliser n'importe quel mélange d'éléments et de noms de balises.

is_empty

$empty = $h->is_empty();

Retourne vrai si $h n'a pas de contenu, c'est-à-dire, n'a pas d'éléments ou de segments de texte en dessous de lui. En d'autres termes, cela retourne vrai si $h" est une feuille, AKA un nœud terminal. Ne confondez pas ce sens de "vide" avec un autre sens qu'il peut avoir dans la terminologie SGML/HTML/XML, qui signifie que l'élément en question est de le type (comme le HTML ="li">"<hr>", "<br>", "<img>", etc.) qui ne peuvent avoir aucun contenu.

C'est-à-dire qu'un "<p>" particulier peut se retrouver sans contenu, de sorte que $that_p_element->is_empty sera vrai -- même si l'élément "<p>" prototypique n'est pas "vide" (pas au sens où l'élément "<hr>" prototypique l'est).

Si vous pensez que cela pourrait donner un code potentiellement déroutant, envisagez simplement d'utiliser l'équivalent exact plus clair : not($h->content_list).

pindex

$index = $h->pindex();

Renvoie l'index de l'élément dans le tableau de contenu de son parent, de sorte que $h serait égal à

$h->parent->content->[$h->pindex]
# ou
($h->parent->content_list)[$h->pindex]

en supposant que $h n'est pas la racine. Si l'élément $h est la racine, alors "$h->pindex" renvoie "undef".

left

$element = $h->left();
@elements = $h->left();

En contexte scalaire : renvoie le nœud qui est le frère immédiat à gauche de $h. Si $h est l'enfant le plus à gauche (ou le seul) de son parent (ou n'a pas de parent), alors cela renvoie undef.

En contexte liste : renvoie tous les nœuds qui sont les frères à gauche de $h (en commençant par le plus à gauche). Si $h est l'enfant le plus à gauche (ou le seul) de son parent (ou n'a pas de parent), alors cela renvoie une liste vide.

(Voir aussi "$h->preinsert(LIST)".)

right

$element = $h->right();
@elements = $h->right();

En contexte scalaire : renvoie le nœud qui est le frère immédiat à droite de $h. Si $h est l'enfant le plus à droite (ou le seul) de son parent (ou n'a pas de parent), alors cela renvoie "undef".

En contexte liste : renvoie tous les nœuds qui sont les frères à droite de $h, en commençant par le plus à gauche. Si $h est l'enfant le plus à droite (ou le seul) de son parent (ou n'a pas de parent), alors cela renvoie une liste vide.

(Voir aussi "$h->postinsert(LIST)".)

address

$address = $h->address();
$element_or_text = $h->address($address);

La première forme (sans paramètre) renvoie une chaîne représentant l'emplacement de $h dans l'arbre dont il est membre. L'adresse se compose de nombres séparés par un '.', commençant par '0', suivis des pindexes des nœuds dans l'arbre qui sont des ancêtres de $h, en partant du sommet.

Ainsi, si le chemin pour atteindre un nœud en partant de la racine est d'aller à l'enfant 2 de la racine, puis à l'enfant 10 de celui-ci, puis à l'enfant 0 de celui-ci, et vous y êtes -- alors l'adresse de ce nœud est "0.2.10.0".

En tant que cas particulier, l'adresse de la racine est simplement "0".

Je prévois que cela sera principalement utilisé pour le débogage, mais vous pourriez trouver vos propres usages.

$element_or_text = $h->address($address);

Cette forme renvoie le nœud (qu'il soit élément ou segment de texte) à l'adresse donnée dans l'arbre dont $h fait partie. (C'est-à-dire que l'adresse est résolue en partant de "$h->root".)

S'il n'y a pas de nœud à l'adresse donnée, cela renvoie "undef".

Vous pouvez spécifier une "adressage relatif" (c'est-à-dire que l'indexation doit commencer à partir de $h et non de "$h->root") en faisant commencer l'adresse par un point -- par exemple, "$h->address(".3.2")" regardera l'enfant 3 de $h, et l'enfant 2 de celui-ci.

depth

$depth = $h->depth();

Renvoie un nombre exprimant la $h's profondeur dans son arbre, c'est-à-dire le nombre de pas qui la séparent de la racine. Si $h n'a pas de parent (c'est-à-dire est la racine), sa profondeur est 0.

root

$root = $h->root();

Renvoie l'élément qui est le sommet de l'arbre de $h. Si $h est la racine, cela renvoie simplement $h. (Si vous voulez tester si $h est la racine, au lieu de demander quelle est sa racine, testez simplement not($h->parent).)

@lineage = $h->lineage();

Renvoie la liste des ancêtres de $h, en commençant par son parent, puis le parent de ce parent, et ainsi de suite, jusqu'à la racine. Si $h est la racine, cela renvoie une liste vide.

Si vous voulez simplement un compte du nombre d'éléments dans la $h's lignée, utilisez "$h->depth".

@names = $h->lineage_tag_names();

Renvoie la liste des noms de balises des ancêtres de $h, en commençant par son parent, puis le parent de ce parent, et ainsi de suite, jusqu'à la racine. Si $h est la racine, cela renvoie une liste vide. Exemple de sortie : "('em', 'td', 'tr', 'table', 'body', 'html')"

Équivalent à :

En contexte liste, renvoie la liste de tous les éléments descendants de $h, listés en pré-ordre (c'est-à-dire qu'un élément apparaît avant ses éléments de contenu). Les segments de texte N'APPARAISSENT PAS dans la liste. En contexte scalaire, renvoie un compte de tous ces éléments.

Cette méthode est déconseillée au profit de la méthode plus expressive "look_down" , que le nouveau code devrait utiliser à la place.

look_down

@elements = $h->look_down( ...criteria... );

Cela commence à $h et parcourt ses descendants élément (en pré-ordre), cherchant les éléments correspondant aux critères que vous spécifiez. En contexte liste, renvoie tous les éléments qui correspondent à tous les critères donnés ; en contexte scalaire, renvoie le premier tel élément (ou undef, si rien ne correspond).

Il y a trois types de critères que vous pouvez spécifier :

(attr_name, attr_value)
Cela signifie que vous cherchez un élément ayant cette valeur pour cet attribut. Exemple : "alt", "pix!". Notez que vous pouvez aussi rechercher sur des valeurs d'attributs internes : "_tag", "p".
(attr_name, qr/.../)
Cela signifie que vous cherchez un élément dont la valeur pour cet attribut correspond à l'objet Regexp spécifié.
une référence de code
Cela signifie que vous cherchez des éléments pour lesquels coderef->(chaque_élément) renvoie vrai. Exemple : 
my @wide_pix_images = $h->look_down(
  _tag => "img",
  alt  => "pix!",
  sub { $_[0]->attr('width') > 350 }
);

C'est-à-dire, dans l'exemple ci-dessus, la référence de sous n'est appelée que pour les éléments qui ont déjà passé le critère d'avoir un attribut "_tag" avec la valeur "img", et un attribut "alt" avec la valeur "pix!". Dans chaque référence de tableau de cette structure, les différents types de valeurs sont traités comme suit

    • Segments de texte

      Les segments de texte au début de tout tableau arrayref seront considérés comme spécifiant le nom de l'élément à construire à partir du tableau arrayref actuel ; tous les autres segments de texte seront considérés comme spécifiant des segments de texte en tant qu'enfants pour le tableau arrayref actuel.

      Les objets éléments existants sont soit insérés dans la structure treelet construite, soit des clones d'entre eux le sont. C'est-à-dire, lorsque l'arbre lol-tree est parcouru et que les éléments sont construits en fonction de ce qu'il contient, si un objet élément existant est trouvé, s'il n'a pas de parent, il est ajouté directement à la structure treelet construite ; mais s'il a un parent, alors "$that_node->clone" est ajouté à la structure treelet à l'endroit approprié.

objectify_text

$h->objectify_text();

Cela transforme tous les nœuds de texte sous $h de simples segments de texte (chaînes de caractères) en véritables objets, des pseudo-éléments avec un nom de balise de "~text", et le contenu textuel réel dans un attribut appelé "text". (Pour une discussion sur les pseudo-éléments, voir la méthode "tag", bien au-dessus.) Cette méthode est fournie car, à certaines fins, il est commode ou nécessaire de pouvoir, pour un nœud de texte donné, demander quel élément est son parent ; et il est clair que ce n'est pas possible si un nœud n'est qu'une chaîne de caractères.

Notez que ces objets "~text" ne sont pas reconnus comme des nœuds de texte par des méthodes comme "as_text". On suppose que vous voudrez appeler "$h->objectify_text", effectuer la tâche pour laquelle vous en aviez besoin, puis appeler "$h->deobjectify_text" avant d'appeler quoi que ce soit comme "$h->as_text".

deobjectify_text

$h->deobjectify_text();

Cela annule l'effet de "$h->objectify_text". C'est-à-dire qu'il prend tous les pseudo-éléments "~text" dans l'arbre à/sous $h, et supprime chacun d'eux, le remplaçant par le contenu de son attribut "text".

Notez que si $h lui-même est un pseudo-élément "~text", il sera détruit -- une condition que vous devrez peut-être traiter spécialement dans votre code appelant (car cela signifie que vous ne pourrez pas faire grand-chose avec $h après cela). Pour que vous puissiez détecter cette condition, si $h est lui-même un pseudo-élément "~text", alors cette méthode retourne la valeur de l'attribut "text", qui devrait être une valeur définie ; dans tous les autres cas, elle retourne undef.

(Cette méthode suppose qu'aucun pseudo-élément "~text" n'a d'enfants.)

number_lists

$h->number_lists();

Pour chaque élément UL, OL, DIR et MENU à/sous $h, cela définit un attribut "_bullet" pour chaque élément enfant LI. Pour les enfants LI d'un OL, la valeur de l'attribut "_bullet" sera quelque chose comme "4.", "d.", "D.", "IV.", ou "iv.", en fonction de l'attribut "type" de l'élément OL. Les enfants LI d'un UL, DIR ou MENU reçoivent leur attribut "_bullet" défini à "*". Il ne devrait y avoir aucun autre LI (c'est-à-dire, sauf en tant qu'enfants d'éléments OL, UL, DIR ou MENU), et s'il y en a, ils ne sont pas affectés.

has_insane_linkage

$h->has_insane_linkage

Cette méthode sert à tester si cet élément ou les éléments en dessous ont des attributs de liaison (_parent et _content) dont les valeurs sont profondément aberrantes : s'il y a des undefs dans une liste de contenu ; si un élément apparaît dans les listes de contenu de plus d'un élément ; si l'attribut _parent d'un élément ne correspond pas à son parent réel ; ou si un élément apparaît comme son propre descendant (c'est-à-dire, s'il y a une cyclicité dans l'arbre).

Cela retourne une liste vide (ou faux, en contexte scalaire) si les méthodes de liaison du sous-arbre sont saines ; sinon, cela retourne deux éléments (ou vrai, en contexte scalaire) : l'élément où l'erreur s'est produite, et une chaîne décrivant l'erreur.

Cette méthode est fournie principalement pour le débogage et le dépannage -- il devrait être * tout à fait impossible * pour tout document construit via HTML::TreeBuilder de parser en un arbre non sain (car ce n'est pas le contenu de l'arbre en soi qui est en question, mais si l'arbre en mémoire a été correctement construit) ; et il * devrait * être impossible pour vous de produire un arbre non sain juste par une utilisation raisonnable des méthodes de modification de structure normales documentées. Mais si vous construisez vos propres arbres, et que votre programme entre dans des boucles infinies lors des appels à traverse() ou à l'une des méthodes structurelles secondaires, dans le cadre du débogage, envisagez d'appeler "has_insane_linkage" sur l'arbre.

element_class

$classname = $h->element_class();

Cette méthode retourne la classe qui sera utilisée pour les nouveaux éléments. Elle est par défaut HTML::Element, mais peut être remplacée par héritage ou des moyens ésotériques qu'il est préférable de laisser à ceux qui liront le code source et ne se plaindront pas ensuite lorsque ces moyens ésotériques changeront. (Héritez simplement.)

MÉTHODES DE CLASSE

Use_Weak_Refs

$enabled = HTML::Element->Use_Weak_Refs;
HTML::Element->Use_Weak_Refs( $enabled );

Cette méthode vous permet de vérifier si le support des références faibles est activé, et de l'activer ou de le désactiver. Pour plus de détails, voir "Références Faibles". $enabled est vrai si les références faibles sont activées.

Vous ne devriez pas changer cela en cours de programme, et vous ne devriez probablement pas l'utiliser du tout. Les arbres existants ne sont pas affectés par cette méthode (jusqu'à ce que vous commenciez à modifier des nœuds dans ceux-ci).

Lève une exception si vous tentez d'activer les références faibles et que votre Perl ou Scalar::Util ne les supporte pas.

La désactivation du support des références faibles est dépréciée.

BOGUES

* Si vous souhaitez libérer la mémoire associée à un arbre construit à partir de nœuds HTML::Element, et que vous avez désactivé les références faibles, vous devrez le supprimer explicitement en utilisant la méthode "delete". Voir "Références Faibles".

* Il n'y a presque rien qui vous empêche de créer un "arbre" avec des cyclicites (boucles) en son sein, ce qui pourrait, par exemple, faire entrer la méthode traverse dans une boucle infinie. Donc, ne créez pas de cyclicites ! (Si tout ce que vous faites est d'analyser des fichiers HTML et de regarder les arbres résultants, cela ne vous posera jamais de problème.)

* Il n'y a aucun moyen de représenter des commentaires ou des directives de traitement dans un arbre avec HTML::Elements. Pas encore, du moins.

* Rien (actuellement) ne vous empêche d'utiliser une valeur indéfinie comme segment de texte. Si vous exécutez sous "perl -w", cependant, cela peut faire en sorte que le code de HTML::Element produise une avalanche d'avertissements.

NOTES SUR L'HÉRITAGE

Vous êtes bienvenu de dériver des sous-classes de HTML::Element, mais vous devez être conscient que le code de HTML::Element fait certaines suppositions sur les éléments (et j'utilise le terme "élément" pour signifier UNIQUEMENT un objet de classe HTML::Element, ou d'une sous-classe de HTML::Element) :

* La valeur de l'attribut _parent d'un élément doit être soit indéfinie ou autrement fausse, soit un élément.

* La valeur de l'attribut _content d'un élément doit être soit indéfinie ou autrement fausse, soit une référence à un tableau (non béni). Le tableau peut être vide ; mais s'il contient des éléments, ils doivent TOUS être soit de simples chaînes de caractères (segments de texte), soit des éléments.

* La valeur de l'attribut _tag d'un élément doit, au minimum, être une chaîne de caractères imprimables.

De plus, gardez ces règles à l'esprit :

* Ne cassez pas l'encapsulation des objets. C'est-à-dire, accédez à leur contenu uniquement via $obj->attr ou des méthodes plus spécifiques.

* Vous devriez réfléchir à deux fois avant de complètement écraser l'une des méthodes fournies par HTML::Element. (Écraser avec une méthode qui appelle la méthode de la superclasse n'est cependant pas si mal.)
