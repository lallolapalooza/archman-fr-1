NOM

HTML::Tagset - tables de données utiles pour l'analyse de HTML

VERSION

Version 3.24

RÉSUMÉ

use HTML::Tagset;
# Puis utiliser n'importe lequel des éléments du paquet HTML::Tagset
#  selon les besoins

DESCRIPTION

Ce module contient plusieurs tables de données utiles pour divers types d'opérations d'analyse HTML.

Notez que tous les noms de balises utilisés sont en minuscules.

Dans la documentation suivante, un « hashset » est un hash utilisé comme un ensemble -- le hash indique que ses clés sont présentes, et les valeurs réelles associées aux clés ne sont pas significatives. (Mais les valeurs qui y sont présentes sont toujours vraies.)

VARIABLES

Notez qu'aucune de ces variables n'est exportée.

hashset %HTML::Tagset::emptyElement

Ce hashset contient comme valeurs les noms de balises (GI) des éléments qui ne peuvent pas avoir de contenu. (Par exemple, « base », « br », « hr ».) Ainsi $HTML::Tagset::emptyElement{'hr'} existe et est vrai. $HTML::Tagset::emptyElement{'dl'} n'existe pas, et n'est donc pas vrai.

hashset %HTML::Tagset::optionalEndTag

Ce hashset liste les noms de balises des éléments qui peuvent avoir du contenu, mais dont les balises de fin sont généralement, « en toute sécurité », omisibles. Exemple : $HTML::Tagset::emptyElement{'li'} existe et est vrai.

hash %HTML::Tagset::linkElements

Les valeurs de ce hash sont les noms de balises des éléments qui peuvent contenir des liens, et la valeur pour chacun est une référence vers un tableau des noms d'attributs dont les valeurs peuvent être des liens.

hash %HTML::Tagset::boolean_attr

Ce hash (et non hashset) liste quels attributs de quels éléments peuvent être affichés sans montrer la valeur (par exemple, l'attribut « noshade » des éléments « hr »). Pour les éléments avec un seul tel attribut, sa valeur est simplement le nom de cet attribut. Pour les éléments avec plusieurs tels attributs, la valeur est une référence vers un hashset contenant tous ces attributs.

hashset %HTML::Tagset::isPhraseMarkup

Ce hashset contient tous les éléments de niveau phrase.

hashset %HTML::Tagset::is_Possible_Strict_P_Content

Ce hashset contient tous les éléments de niveau phrase qui peuvent être le contenu d'un élément P, pour un modèle strict de HTML.

hashset %HTML::Tagset::isHeadElement

Ce hashset contient tous les éléments qui devraient être présents uniquement dans l'élément 'head' d'un document HTML.

hashset %HTML::Tagset::isList

Ce hashset contient tous les éléments qui peuvent contenir des éléments « li ».

hashset %HTML::Tagset::isTableElement

Ce hashset contient tous les éléments qui ne se trouvent que dans/sous un élément « table ».

hashset %HTML::Tagset::isFormElement

Ce hashset contient tous les éléments qui ne se trouvent que dans/sous un élément « form ».

hashset %HTML::Tagset::isBodyElement

Ce hashset contient tous les éléments qui ne se trouvent que dans/sous l'élément « body » d'un document HTML.

hashset %HTML::Tagset::isHeadOrBodyElement

Ce hashset inclut tous les éléments que j'ai remarqués pouvant se trouver soit dans le head soit dans le body.

hashset %HTML::Tagset::isKnown

Ce hashset liste tous les éléments HTML connus.

hashset %HTML::Tagset::canTighten

Ce hashset liste les éléments qui peuvent avoir des espaces blancs ignorables comme enfants ou frères.

tableau @HTML::Tagset::p_closure_barriers

Ce tableau a une signification dont j'ai seulement eu besoin dans "HTML::TreeBuilder", mais je l'inclus ici au cas où quelqu'un pourrait le trouver utile :

Quand nous voyons un jeton « <p> », nous remontons la lignée à la recherche d'un élément p que nous pourrions avoir à minimiser. À première vue, nous pourrions dire que s'il y a un p n'importe où dans la lignée de ce nouveau p, il devrait être fermé. Mais c'est faux. Considérons ce document :

<html>
  <head>
    <title>foo</title>
  </head>
  <body>
    <p>foo
      <table>
        <tr>
          <td>
             foo
             <p>bar
          </td>
        </tr>
      </table>
    </p>
  </body>
</html>

Le deuxième p est tout à fait légalement à l'intérieur d'un p beaucoup plus haut.

Ma formalisation de la raison pour laquelle c'est légal, mais ceci :

<p>foo<p>bar</p></p>

ne l'est pas, est que quelque chose à propos de la table constitue une « barrière » à l'application de la règle concernant ce que le p doit minimiser.

Ainsi @HTML::Tagset::p_closure_barriers est la liste de toutes ces balises-barrières.

hashset %isCDATA_Parent

Ce hashset inclut tous les éléments dont le contenu est du CDATA.

AVERTISSEMENTS

Vous pourriez trouver utile d'altérer le comportement de modules (comme "HTML::Element" ou "HTML::TreeBuilder") qui utilisent "HTML::Tagset"'s tables de données en altérant les tables de données elles-mêmes. Vous êtes libre d'essayer, mais soyez prudent ; et sachez que différents modules peuvent ou non réagir différemment aux changements des tables de données.

Notez qu'il peut être inapproprié d'utiliser ces tables pour produire du HTML -- par exemple, %isHeadOrBodyElement liste les noms de balises pour tous les éléments qui peuvent apparaître soit dans le head soit dans le body, tels que « script ». Cela ne signifie pas que je dis que votre code qui produit du HTML devrait se sentir libre de mettre des éléments script n'importe où ! Si vous produisez des programmes qui crachent du HTML, vous devriez être intimement familier avec les DTD pour HTML ou XHTML (disponibles sur «http://www.w3.org/»), et vous devriez les obéir servilement, et non les tables de données de ce document.
