DESCRIPTIO

N

Ceci est un serveur HTTP autonome simple. Par défaut, il ne crée ni threads ni processus fils. Il agit toutefois comme une interface simple qui peut être utilisée pour construire une application web autonome ou pour transformer un CGI en une telle

application.

Il est possible d'utiliser les classes Net::Server pour créer des serveurs avec fork, pré-fork, et d'autres types de serveurs plus complexes ; voir

"net_server".

Par défaut, le serveur intercepte quelques signaux

:
HU
P
Quand vous envoyez "kill -HUP" au serveur, il laisse la requête en cours se terminer, puis utilise la méthode "restart" pour se ré-exécuter. Veuillez noter que pour fournir un redémarrage sur SIGHUP, HTTP::Server::Simple définit un gestionnaire de SIGHUP lors de l'initialisation. Si votre code de traitement des requêtes crée des processus fils, vous devez vous assurer de réinitialiser ceci, sinon des choses inattendues se produiront si quelqu'un envoie un HUP à tous les processus en cours d'exécution lancés par votre application (par ex. par "kill -HUP <script>
")
PI
PE
Si le serveur détecte une pipe cassée lors de l'éc
riture de la sortie vers le client, il igno
re le signal. Sinon, un client qui ferme la
connexion prématurément pourrait tuer le serveur.

headers([Header => $value, ...]

)

Reçoit les en-têtes HTTP et fait quelque chose d'utile avec eux. Cela est appelé par la méthode setup() par

défaut.

Vous avez de nombreuses options quant à la manière dont vous recevez les

en-têtes.

Vous pouvez, si vous le voulez vraiment, définir parse_headers() et les analyser vous-même à l'état

brut.

Deuxièmement, vous pouvez les intercepter légèrement préparés via la méthode setup(),

ci-dessus.

Troisièmement, vous pouvez laisser l'en-tête setup() tel quel (ou appeler la méthode de la superclasse setup() pour les éléments de requête inconnus). Ensuite, vous pouvez définir headers() dans votre sous-classe et les recevoir tous en une

fois.

Enfin, vous pouvez définir des gestionnaires pour recevoir des en-têtes HTTP individuels. Cela peut être utile pour des serveurs SOAP très simples (pour nommer une norme surstimulée qui définit ses propres en-têtes HTTP spéciaux)

.

Pour ce faire, vous voudrez définir la méthode header() dans votre sous-classe. Cette méthode recevr

a une paire (clé,valeur) du nom
de l'en-tête et de sa valeur.
