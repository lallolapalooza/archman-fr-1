DESCRIPTIO

N

Ce module fournit une implémentation complète de l'algorithme de négociation de contenu HTTP spécifié dans draft-ietf-http-v11-spec-00.ps chapitre 12. La négociation de contenu permet la sélection d'une représentation de contenu préférée en se basant sur les attributs des variantes négociables et la valeur des différents champs d'en-tête Accept* dans la

requête.

Les variantes sont ordonnées par préférence en appelant la fonction choose

().

Le premier paramètre est une référence vers un tableau des variantes parmi lesquelles choisir. Chaque élément de ce tableau est un tableau avec les valeurs [$id, $qs, $content_type, $content_encoding, $charset, $content_language, $content_length] dont les significations sont décrites ci-dessous. Le $content_encoding et $content_language peuvent être soit une valeur scalaire unique, soit une référence de tableau s'il y a plusieurs

valeurs.

Le deuxième paramètre optionnel est soit un objet HTTP::Headers, soit un objet HTTP::Request dans lequel chercher les en-têtes "Accept*". Si ce paramètre est absent, la spécification accept est initialisée à partir des variables d'environnement CGI HTTP_ACCEPT, HTTP_ACCEPT_CHARSET, HTTP_ACCEPT_ENCODING et HTTP_ACCEPT_LANGUAGE

.

Dans un contexte de tableau, choose() retourne une liste de tuples [identifiant de variante, qualité calculée, taille]. Les valeurs sont triées par qualité, la plus haute qualité d'abord. Si la qualité calculée est la même pour deux variantes, elles sont alors triées par taille (la plus petite d'abord). Par exemp

le : 
(['var1', 1, 2000], ['var2', 0.3, 512], ['var3', 0.3, 1024])
;

Notez que les variantes de qualité zéro sont aussi incluses dans la liste retournée même si elles ne devraient jamais être servies au

client.

Dans un contexte scalaire, cela retourne l'identifiant de la variante avec le score le plus élevé, ou "undef" si aucune n'a une qualité non

nulle.

Si la variable $HTTP::Negotiate::DEBUG est définie à TRUE, beaucoup de bruit est généré sur STDOUT pendant l'évaluation de choo

se(
).

EN-TÊTES

ACCEPT

Les en-têtes Accept* suivants peuvent être utilisés pour décrire les préférences de contenu dans une requête (Cette description est un extrait édité de draft-ietf-http-v11-spec-00.ps)

:
Acce
pt
Cet en-tête peut être utilisé pour indiquer une liste de plages de médias acceptables comme réponse à la requête. Le caractère "*" est utilisé pour regrouper les types médias en plages, avec "*/*" indiquant tous les types médias et "type/*" indiquant tous les sous-types de ce type.

Le paramètre q est utilisé pour indiquer le facteur de qualité, qui représente la préférence de l'utilisateur pour cette plage de types médias. Le paramètre mbx donne la taille maximale acceptable du contenu de la réponse. Les valeurs par défaut sont : q=1 et mbx=infini. Si aucun en-tête Accept n'est présent, le client accepte alors tous les types médias avec

q=1.

Par

exemple : 
Accept: audio/*;q=0.2;mbx=200000,
audio/basic

signifierait : "Je préfère audio/basic (de n'importe quelle taille), mais env

oyez-moi n'importe quel type audio si c'est le meilleur disponible après une r
éduction de 80% de la qualité et si sa taille est inférieure à 200000 octets"
Accept-Chars
et
Utilisé pour indiquer quels jeux de caractères sont acceptables pour la réponse. Le jeu de caractères "us-ascii" est supposé être acceptable pour tous les agents utilisateurs. Si aucun champ Accept-Charset n'est donné, la valeur par défaut est que n'importe quel jeu de caractères est acceptable. Exemple : 
Accept-Charse
t: iso-8859-1
, unicode-1-1
Accept-Encod
ing
Restreint les valeurs de Content-Encoding qui sont acceptables dans la réponse. Si aucun champ Accept-Encoding n'est présent, le serveur peut supposer que le client acceptera n'importe quel encodage de contenu. Un Accept-Encoding vide signifie qu'aucun encodage de contenu n'est acceptable. Exemple : 
Accept-Encoding: compress,
gzip
Accept-Langu
age
Ce champ est similaire à Accept, mais restreint l'ensemble des langues naturelles préférées dans une réponse. Chaque langue peut avoir une valeur de qualité associée qui représente une estimation de la compréhension de cette langue par l'utilisateur. Par exemple : 
Accept-Language: no, en-gb;q=0.8, de;
q=0.55

signifierait : "Je préfère le

norvégien, mais j'accepterai l
'anglais britannique (avec 80%
de compréhension) ou l'alleman
d (avec 55% de compréhension).
