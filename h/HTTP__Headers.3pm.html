$h->content_type
Le champ d'en-tête Content-Type indique le type de média du contenu du message. Par ex.:

La valeur retournée sera convertie en minuscules, et les paramètres éventuels seront tronqués et retournés comme une valeur séparée si dans un contexte liste. S'il n'y a pas de tel champ d'en-tête, la chaîne vide est retournée. Cela permet de faire ce qui suit en toute sécurité :

   # trouve être 'TEXT/HTML; version=3.0'
   ...

Cet en-tête devrait contenir une adresse e-mail Internet pour l'utilisateur humain qui contrôle l'agent utilisateur faisant la requête. L'adresse devrait être utilisable par une machine, telle que définie par la RFC822. Par ex. :

Cet en-tête ne fait plus partie de la norme HTTP.

$h->referer
Utilisé pour spécifier l'adresse (URI) du document à partir duquel l'adresse de la ressource demandée a été obtenue.

Le « Free On-line Dictionary of Computing » dit ceci à propos du mot referer:

<World-Wide Web> Une faute d'orthographe de "referrer" qui
a d'une certaine manière réussi à entrer dans la norme {HTTP}. Le
referer (sic) d'une {page web} donnée est l'{URL} de la
page web quelconque qui contient le lien que l'utilisateur a suivi pour
arriver à la page courante. La plupart des navigateurs transmettent cette
information dans le cadre d'une requête.
(1998-10-19)

À la demande populaire, "referrer" existe comme alias pour cette méthode afin que vous puissiez éviter cette faute d'orthographe dans vos programmes tout en envoyant la bonne chose sur le réseau.

Lors du réglage du referrer, cette méthode supprime le fragment de l'URI donnée s'il est présent, comme l'exige la RFC2616. Notez que la suppression ne se fait pas automatiquement si vous utilisez les méthodes header(), push_header() ou init_header() pour définir le referrer.

$h->www_authenticate
Cet en-tête doit être inclus dans une "401 Unauthorized" réponse. La valeur du champ se compose d'un défi qui indique le schéma d'authentification et les paramètres applicables à l'URI demandée.
$h->proxy_authenticate
Cet en-tête doit être inclus dans une "407 Proxy Authentication Required" réponse.
$h->authorization
$h->proxy_authorization
Un agent utilisateur qui souhaite s'authentifier auprès d'un serveur ou d'un proxy peut le faire en incluant ces en-têtes.
$h->authorization_basic
Cette méthode est utilisée pour obtenir ou définir un en-tête d'autorisation qui utilise le « Basic Authentication Scheme ». Dans un contexte liste, elle retournera deux valeurs ; le nom d'utilisateur et le mot de passe. Dans un contexte scalaire, elle retournera "uname:password" sous forme d'une chaîne de caractères unique.

Lorsqu'elle est utilisée pour définir la valeur de l'en-tête, elle attend deux arguments. Par ex.:

$h->authorization_basic($uname, $password);

La méthode émettra une erreur fatale si $uname contient un deux-points ':'.

$h->proxy_authorization_basic
Identique à authorization_basic() mais définira l'en-tête "Proxy-Authorization" à la place.

NOMS DE CHAMPS NON CANONICALISÉS

L'orthographe du nom de champ d'en-tête est normalement canonicalisée, y compris la traduction de '_' en '-'. Il existe certaines applications pour lesquelles cela n'est pas approprié. Préfixer les noms de champs avec ':' vous permet d'imposer une orthographe spécifique. Par exemple, si vous voulez vraiment qu'un nom de champ d'en-tête apparaisse comme "foo_bar" au lieu de "Foo-Bar", vous pourriez le définir ainsi :

$h->header(":foo_bar" => 1);

Ces noms de champs sont retournés avec le ':' intact pour $h->header_field_names et le rappel$h ->scan, mais les deux-points n'apparaissent pas dans$h

->as_string. 2025-10-28
