Description détaillée

Les plates-formes avec mémoire hétérogène nécessitent des moyens pour décider si un tampon doit être alloué sur de la mémoire « rapide » (comme la HBM), de la mémoire « normale » (DDR) ou même de la mémoire « lente » mais de grande capacité (mémoire non volatile). Ces nœuds mémoire sont appelés « Cibles » tandis que le CPU qui y accède est appelé « Initiateur ». Les performances d'accès dépendent de leur localité (plateformes NUMA) ainsi que des performances intrinsèques des cibles (plateformes hétérogènes).

Les attributs suivants décrivent les performances des accès mémoire d'un initiateur à une cible mémoire, par exemple leur latence ou leur bande passante. Les initiateurs effectuant ces accès mémoire sont généralement des PUs ou des Cœurs (décrits comme un ensemble de CPU). Ainsi, un cœur peut choisir où allouer un tampon mémoire en comparant les attributs des différents nœuds mémoire cibles à proximité.

Il existe également des attributs qui sont à l'échelle du système. Leur valeur ne dépend pas d'un initiateur spécifique effectuant un accès. La capacité du nœud mémoire est un exemple d'un tel attribut sans initiateur.

Une façon d'utiliser cette API est de commencer avec un ensemble de CPU décrivant les Cœurs sur lesquels un programme est lié. Le meilleur nœud NUMA cible pour allouer de la mémoire dans ce programme sur ces Cœurs peut être obtenu en passant cet ensemble de CPU comme initiateur à hwloc_memattr_get_best_target() avec l'attribut mémoire pertinent. Par exemple, si le code est limité en latence, utilisez l'attribut Latence.

Une approche plus flexible consiste à obtenir la liste des objets NUMA locaux en passant cet ensemble de CPU à hwloc_get_local_numanode_objs(). Les valeurs d'attributs pour ces nœuds, le cas échéant, peuvent ensuite être obtenues avec hwloc_memattr_get_value() et comparées manuellement aux critères souhaités.

Les attributs mémoire sont également utilisés en interne pour construire des Tiers Mémoire qui fournissent un moyen facile de distinguer les nœuds NUMA de différents types, comme expliqué dans Mémoire Hétérogène.

Outre les tiers, hwloc définit un ensemble de nœuds « par défaut » à partir desquels les allocations mémoire normales devraient être effectuées (voir hwloc_topology_get_default_nodeset()). Ceci est également utile pour diviser la machine en un ensemble de domaines NUMA non superposés, par exemple pour lier les tâches par domaine.

Voir aussi

Un exemple est disponible dans doc/examples/memory-attributes.c dans l'arborescence source.

Note

L'API prend également en charge des objets spécifiques comme initiateurs, mais ce n'est pas utilisé en interne par hwloc actuellement. Les utilisateurs peuvent par exemple l'utiliser pour fournir des valeurs de performance personnalisées pour les accès mémoire hôte effectués par les GPU.

L'interface accepte en fait également des cibles qui ne sont pas des nœuds NUMA.

typedef unsigned hwloc_memattr_id_t

Un identifiant d'attribut mémoire. hwloc pré-définit des attributs couramment utilisés dans hwloc_memattr_id_e. On peut ensuite enregistrer dynamiquement des attributs personnalisés avec hwloc_memattr_register(), ils se verront attribuer des ID immédiatement après ceux prédéfinis. Voir Gestion des attributs mémoire pour plus d'informations sur les ID d'attributs existants.

Documentation des types énumérés

enum hwloc_local_numanode_flag_e

Indicateurs pour la sélection des nœuds NUMA cibles.

Énumérateur

HWLOC_LOCAL_NUMANODE_FLAG_LARGER_LOCALITY
Sélectionne les nœuds NUMA dont la localité est plus grande que l'ensemble de CPU donné. Par exemple, si un seul PU (ou son ensemble de CPU) est donné dans initiator, sélectionne tous les nœuds proches du package qui contient ce PU.
HWLOC_LOCAL_NUMANODE_FLAG_SMALLER_LOCALITY
Sélectionne les nœuds NUMA dont la localité est plus petite que l'ensemble de CPU donné. Par exemple, si un package (ou son ensemble de CPU) est donné dans initiator, sélectionne également les nœuds qui ne sont attachés qu'à la moitié de ce package.
HWLOC_LOCAL_NUMANODE_FLAG_INTERSECT_LOCALITY
Sélectionne les nœuds NUMA dont la localité intersecte l'ensemble de CPU donné. Cela inclut les localités plus grandes et plus petites ainsi que les localités qui sont partiellement incluses. Par exemple, si la localité est un cœur des deux packages, un nœud NUMA local à un package n'est ni plus grand ni plus petit que cette localité, mais il l'intersecte.
HWLOC_LOCAL_NUMANODE_FLAG_ALL
Sélectionne tous les nœuds NUMA de la topologie. L'initiateur initiator est ignoré.

int hwloc_topology_get_default_nodeset (hwloc_topology_t topology, hwloc_nodeset_t nodeset, unsigned long flags)

Retourne l'ensemble des nœuds NUMA par défaut. Dans les machines à mémoire hétérogène, certains nœuds NUMA sont considérés comme les nœuds par défaut, c'est-à-dire d'où les allocations de base devraient être effectuées. Ce sont généralement des nœuds DRAM.

D'autres nœuds peuvent être réservés à des usages spécifiques (mémoire d'appareils I/O, par exemple mémoire GPU), mémoire petite mais haute performance (HBM), mémoire grande mais lente (NVM), etc. Les tampons ne devraient généralement pas y être alloués à moins que cela ne soit explicitement requis.

Cette fonction remplit nodeset avec les bits des nœuds NUMA considérés comme par défaut.

Il est garanti que ces nœuds ont des ensembles de CPU qui ne s'intersectent pas, c'est-à-dire que les cœurs ne peuvent plus avoir plusieurs nœuds NUMA locaux. Ainsi, cela peut être utilisé pour itérer sur la plateforme divisée en localités NUMA séparées, par exemple pour lier une tâche par domaine NUMA.

Tout cœur qui avait un ou plusieurs nœuds NUMA locaux dans la topologie initiale devrait toujours en avoir un dans l'ensemble par défaut. Les cas limites où cela serait incorrect concernent les plateformes asymétriques avec des nœuds DRAM manquants, ou les topologies qui étaient déjà restreintes à moins de nœuds NUMA.

L'ensemble de nœuds retourné peut être passé à hwloc_topology_restrict() avec HWLOC_RESTRICT_FLAG_BYNODESET pour supprimer tous les nœuds non-défaut de la topologie. La topologie résultante sera plus facile à utiliser lors de l'itération sur des nœuds NUMA (maintenant homogènes).

Les heuristiques pour trouver les nœuds par défaut reposent sur les niveaux de mémoire et les sous-types (voir Mémoire Hétérogène) ainsi que sur l'hypothèse que les fournisseurs de matériel listent les nœuds par défaut en premier dans les tables matérielles.

flags doit être 0 pour l'instant.

Retourne

0 en cas de succès.

-1 en cas d'erreur.

Remarque

L'ensemble de nœuds retourné contient généralement tous les nœuds d'un même niveau de mémoire, probablement celui de la DRAM.

L'ensemble de nœuds retourné est inclus dans la liste des nœuds disponibles retournés par hwloc_topology_get_topology_nodeset(). Il est strictement plus petit si la machine a une mémoire hétérogène.

Les heuristiques peuvent renvoyer un ensemble de nœuds sous-optimal si hwloc n'a pas pu deviner les types de mémoire et/ou si certains nœuds par défaut ont été supprimés précédemment de la topologie (par exemple avec hwloc_topology_restrict()).
