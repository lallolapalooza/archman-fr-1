DESCRIPTGtk2-Perl traduit les erreurs d'exécution GError de GLib en exceptions Perl, en créant des objets d'exception basés sur Glib::Error. Glib::Error surcharge l'opérateur de conversion en chaîne, de sorte qu'un objet Glib::Error se comportera pr
ou

warn(

)

, donc la plupart du code

utilisant $@ ne verr
a même pas la différence.

L'intérêt d'avoir des objets d'exception, cependant, est que les messages d'erreur dans les GErrors sont souvent localisés avec la traduction NLS. Ainsi, il n'est pas bon pour votre code d'essayer de gérer les erreurs par correspondance de chaîne sur le message d'erreur. Glib::Error fournit un moyen

d'obtenir le code d'erreur déterministe. 
Vous traiterez généralement avec des objets qui héritent de
    Glib::Error, tels que Glib::Convert::Error, Glib::File::Error,
    Gtk2::Gdk::Pixbuf::Error, etc ; ces classes sont fournies par les
    b
ibliothèques qui définissent les domaines d'erreur. Cependant, il est possible d'obtenir un Glib::Error de base lorsque les liaisons rencontrent un domaine d'erreur inconnu ou non lié. L'interfa
ce utilisée ici se dégrade gracieusement dans une telle situation, mais en général, vous devriez soumettre un rapport de bogue au mainteneur des liaisons si vous obtenez une telle exception.
