DESCRIPTIO

N

Ce module fournit aux scripts Perl un moyen facile d'interagir avec le système de contrôle de version Git. Les modules offrent une méthode simple et bien testée pour appeler des commandes Git arbitraires ; à l'avenir, l'interface fournira également des méthodes spécialisées pour effectuer facilement des opérations qui ne sont pas totalement triviales à réaliser via l'interface générique de

commandes.

Bien que certaines commandes puissent être exécutées en dehors de tout contexte (par exemple 'version' ou 'init'), la plupart des opérations nécessitent un contexte de dépôt, ce qui en pratique signifie obtenir une instance de l'objet Git à l'aide du constructeur repository(). (À l'avenir, nous disposerons également d'un constructeur new_repository().) Toutes les commandes appelées en tant que méthodes de l'objet sont ensuite exécutées dans le contexte du

dépôt.

L'"état du dépôt" comprend également des informations sur le chemin de la copie de travail associée (sauf si vous travaillez avec un dépôt nu). Vous pouvez également naviguer à l'intérieur de la copie de travail à l'aide de la méthode wc_chdir(). (Notez que l'objet dépôt est autonome et ne changera pas le répertoire de travail de votre processus.

)

À FAIRE : À l'avenir, nous pourrions également

faire 
my $remoterepo = $repo->remote_repository (Name => 'cogito', Branch => 'master');
$remoterepo ||= Git->remote_repository ('http://git.or.cz/cogito.git/');
my @refs = $remoterepo->refs()
;

Actuellement, le module enveloppe simplement des appels aux outils Git externes. À l'avenir, il fourn

ira un moyen beaucoup plus rapide d'interagir avec Git en se liant directement à libgit. Cela devrait
être complètement opaque pour l'utilisateur, cependant (à part l'augmentation des performances).

repository
()
Construit un nouvel objet dépôt. "OPTIONS" sont passées de manière similaire à un hachage, en utilisant des paires clé/valeur. Les options possibles sont :

Repository - Chemin vers le dépôt

Git.

WorkingCopy - Chemin vers la copie de travail associée ; non strictement requis car de nombreuses commandes fonctionneront volontiers sur un dépôt

nu.

WorkingSubdir - Sous-répertoire de la copie de travail dans lequel travailler. Laissez simplement indéfini si vous ne souhaitez pas limiter la portée des

opérations.

Directory - Chemin vers le répertoire de travail Git dans sa configuration habituelle. Le répertoire ".git" est recherché dans le répertoire et tous les répertoires parents ; s'il est trouvé, "WorkingCopy" est défini sur le répertoire qui le contient et "Repository" sur le répertoire ".git" lui-même. Si aucun répertoire ".git" n'a été trouvé, le "Directory" est supposé être un dépôt nu, "Repository" est défini pour pointer vers lui et "WorkingCopy" est laissé indéfini. Si la variable d'environnement $GIT_DIR est définie, les choses se comportent comme prévu

également.

Vous ne devriez pas utiliser à la fois "Directory" et soit "Repository" soit "WorkingCopy" - les résultats de cela sont

indéfinis.

Alternativement, un chemin de répertoire peut être passé comme argument scalaire unique au constructeur ; cela équivaut à définir seulement le champ d'option "Directory

".

Appeler le constructeur sans aucune option équivaut à l'appeler avec "Directory => '.'". En général, si vous construisez une commande porcelain standard, faire simplement "Git->repository()" devrait faire les choses c

orrectement et configurer
