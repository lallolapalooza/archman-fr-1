SYNOPSI

S 
eval "use Glib::MakeHelper; 1"
    or complain_that_glib_is_too_old_and_die();

%xspod_files = Glib::MakeHelper->do_pod_files (@xs_files);
package MY;
sub postamble {
    return Glib::MakeHelper->postamble_clean ()
         . Glib::MakeHelper->postamble_docs (@main::xs_files)
         . Glib::MakeHelper->postamble_rpms (
                MYLIB     => $build_reqs{MyLib},
           );
}

DESCRIPTIO

N

Le Makefile.PL de votre module typique basé sur Glib est énorme et complexe, grâce à toutes les folles manœuv

res que vous devez effectuer pour que tout fonctionne correctement. Ce module regroupe certaines des parties l
es plus intenses et sujettes aux erreurs afin de réduire la quantité de code copié et le potentiel d'erreurs.

MÉTHODE

S
HASH = Glib::MakeHelper->do_pod_files
(@xs_files)
Analyse les @xs_files et retourne un hash décrivant les fichiers pod qui seront créés. C'est au format voulu par WriteMakefile(). Si @ARGV contient la chaîne "disable-apidoc", une liste vide sera retournée et ainsi aucun pod apidoc ne sera généré, ce qui accélère le processus de
construction.
LIST = Glib::MakeHelper->select_files_by_version ($stem, $major,
$minor)
Retourne une liste de tous les fichiers qui correspondent à "$stem-\d+\.\d+" et pour lesquels le premier nombre est plus grand que $major et le deuxième nombre est plus grand que $minor. Si $minor est impair, il sera incrémenté de un afin que le numéro de version d'une prochaine version stable puisse être utilisé pendant le développement
également.
LIST = Glib::MakeHelper->read_source_list_file
($filename)
Lit $filename, supprime tous les commentaires (commençant par "#") et les espaces blancs en début et en fin, et retourne une liste de toutes les lignes qui ont survécu au
traitement.
string = Glib::MakeHelper->get_configure_requires_yaml (%module_to_versi
on)
Génère du code YAML qui liste chaque module trouvé dans %module_to_version sous la clé "configure_requires". Cela peut être utilisé avec le paramètre "EXTRA_META" d'ExtUtils::MakeMaker pour spécifier quels modules sont nécessaires au moment de l'exécution de Makefile.PL.

Cette fonction est dépréciée depuis que ExtUtils::MakeMaker 6.46 a supprimé le support pour "EXTRA_META" au profit des nouvelles clés "META_MERGE" et "META_A

DD
".
string = Glib::MakeHelper->postamble_clean
(@files)
Crée et retourne le texte d'une règle realclean qui nettoie après une grande partie de la génération automatique effectuée par les modules basés sur Glib. Tout dans @files sera également supprimé (il peut être vide).

La raison d'utiliser cela au lieu de simplement vous faire utiliser les clé

s 'clean' ou 'realclean' est que cela évite de devoir se souvenir de mettre
les éléments de Glib dans les arguments WriteMakefile de votre Makefile.PL.

(@xs_files)

string = Glib::MakeHelper->postamble_rpms
(HASH)
Crée et retourne le texte des règles Makefile pour gérer la construction de RPM. Vous mettriez cela dans le MY::postamble de votre Makefile.PL.

HASH est un ensemble de clés de recherche et de remplacement pour le fichier spec. Toutes les occurrences de @key@ dans le fichier spec modèle perl-$(DISTNAME).spec.in seront remplacées par value. 'VERSION' et 'SOURCE' vous sont fournis. Par

exemple : 
Glib::MakeHelper->postamble_rpms (
       MYLIB     => 2.0.0, # nous pouvons travailler avec tout à partir de cela
       MYLIB_RUN => 2.3.1, # nous sommes réellement compilés contre celui-ci
       PERL_GLIB => 1.01,  # vous devez avoir cette version de
Glib );

remplacera @MYLIB@, @MYLIB_RUN@, et @PERL_GLIB@ dans le fichier spec. Voir les configurations de construction de Glib et Gtk2 pour des

exemples.

Remarque : Cette fonctio

n retourne simplement un
e chaîne vide sur Win32.
string = Glib::MakeHelper->postamble_precompiled_headers
(@headers)
Crée et retourne le texte des règles Makefile pour une cible 'precompiled-headers' qui précompile @headers. Si vous appelez cela avant d'appeler "postamble_clean", tous les fichiers
temporaires seront
supprimés par la
cible 'realclean'.
