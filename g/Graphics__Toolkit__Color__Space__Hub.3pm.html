NOM

Graphics::Toolkit::Color::Space::Hub - convertir, formater et mesurer les valeurs de couleur

SYNOPIS

Hub central pour toutes les opérations mathématiques relatives aux valeurs de couleur. Peut gérer des vecteurs de tous les espaces mentionnés dans le paragraphe suivant et traduit également vers et depuis différents formats tels que RGB hex ('#AABBCC').

use Graphics::Toolkit::Color::Space::Hub;
my $vrai = Graphics::Toolkit::Color::Space::Hub::is_space( 'HSL' );
my $HSL = Graphics::Toolkit::Color::Space::Hub::get_space( 'HSL');
my $RGB = Graphics::Toolkit::Color::Space::Hub::base_space();
Graphics::Toolkit::Color::Space::Hub::space_names();     # tous les noms d'espaces
$HSL->normalize([240,100, 0]);         # 2/3, 1, 0
$HSL->convert([240, 100, 0], 'RGB');   #   0, 0, 1
$HSL->deconvert([0, 0, 1], 'RGB');     # 2/3, 1, 0
$RGB->denormalize([0, 0, 1]);          #   0, 0, 255
$RGB->format([0, 0, 255], 'hex');      #   '#0000ff'
my ($valeurs, $nom_espace) = Graphics::Toolkit::Color::Space::Hub::deformat( '#0000ff' );
# [0, 0, 255] , 'RGB'

DESCRIPTION

Ce module est destiné à être utilisé par Graphics::Toolkit::Color et non directement, il n'exporte donc aucun symbole et possède une API beaucoup moins "Do What I Mean" que le module principal.

ESPACES DE COULEURS

Les noms des espaces colorimétriques peuvent être écrits dans n'importe quelle combinaison de majuscules et de minuscules.

RGB

possède trois valeurs entières : red (0 .. 255), green (0 .. 255) et blue (0 .. 255). Toutes vont de l'absence (0) à la quantité maximale (255) de lumière de cette couleur, de sorte que (0,0,0) est noir, (255,255,255) est blanc et (0,0,255) est bleu.

CMY

est l'inverse du RGB mais avec la plage : 0 .. 1. cyan est la valeur inverse de red, magenta est l'inverse de green et yellow est l'inverse de blue. Inverse signifiant que quand une couleur a la valeur maximale de red, elle doit avoir la valeur minimale de cyan.

CMYK

est une extension du CMY avec une quatrième valeur nommée key (également 0 .. 1), qui est essentiellement la quantité de noir mélangée à la couleur CMY.

HSL

possède trois valeurs entières : hue (0 .. 359), saturation (0 .. 100) et lightness (0 .. 100). La teinte (hue) représente une couleur sur un arc-en-ciel : 0 = rouge, 15 approxime l'orange, 60 - jaune, 120 - vert, 180 - cyan, 240 - bleu, 270 - violet, 300 - magenta, 330 - rose. 0 et 360 pointent vers la même coordonnée. Ce module ne renvoie que 0, même s'il accepte 360 en entrée. La saturation va de 0 = gris à 100 = couleur la plus claire définie par la teinte. La luminosité (lightness) va de 0 = noir à 50 (teinte ou gris) à 100 = blanc.

HSV

Semblable à HSL, nous avons la hue et la saturation, mais la troisième valeur est nommée value. En HSL, la couleur blanche est toujours obtenue lorsque la lightness = 100. En HSV, la saturation doit également être à zéro pour obtenir du blanc. Quand en HSV la value est à 100 et la saturation est également à 100, alors nous avons la couleur la plus vive et la plus claire de la teinte définie.

HSB

C'est un alias pour HSV, où la valeur est renommée brightness.

HWB

Un HSV inversé, où les couleurs pures se trouvent à l'intérieur du cylindre. Il conserve toujours la dimension circulaire de la hue, comme décrit dans "HSL". Les deux autres dimensions linéaires (également 0 .. 100 [pourcent]) sont la whiteness (blancheur) et la blackness (noirceur), décrivant la quantité de blanc ou de noir ajoutée. Si les deux sont à zéro, nous avons une couleur pure. Une whiteness de 100 conduit toujours au blanc pur et une blackness de 100 conduit toujours au noir pur.

YIQ

Possède les dimensions linéaires : luminance (une sorte de luminosité, plage 0..1), in-phase (cyan - orange - équilibre, plage -0.5959 .. 0.5959) et quadrature (magenta - vert - équilibre, plage: -0.5227 .. 0.5227).

FORMATS

Ces formats sont disponibles dans tous les espaces colorimétriques.

string

'RGB: 10, 20, 30'

css_string

'rgb(10, 20, 30)'

array

[RGB, 10, 20, 30]

hash

{ red => 10, green => 20, blue => 30 }

char_hash

{ r => 10, g => 20, b => 30 }

ROUTINES

Ce package fournit deux ensembles de routines. Le premier est juste une recherche des objets d'espace colorimétrique disponibles. Le second ensemble se compose de trois paires de routines concernant 3 opérations essentielles sur les valeurs numériques et leur inversion. Le pipeline complet pour la traduction des valeurs de couleur est :

1. deformat (en une liste de valeurs)
2. normaliser (en plage 0..1)
3. convertir/déconvertir (en espace colorimétrique cible)
4. dénormaliser (en plage cible)
5. formater (en format cible)

space_names

Renvoie une liste de chaînes de caractères, qui sont les noms de tous les espaces colorimétriques disponibles. Voir "ESPACES DE COULEURS".

is_space

Nécessite un argument, qui est censé être un nom d'espace colorimétrique. Si c'est le cas, le résultat est 1, sinon 0 (pseudo booléen perlesque).

get_space

Nécessite un argument, qui est censé être un nom d'espace colorimétrique. Si c'est le cas, le résultat est l'objet d'espace colorimétrique correspondant, sinon undef.

base_space

Renvoie l'objet d'espace colorimétrique de l'espace nommé (actuellement) RGB. Cet espace nommé est spécial car chaque objet d'espace colorimétrique fournit des convertisseurs depuis et vers RGB, mais RGB lui-même n'a pas de convertisseur.

normalize

Normal au sens mathématique signifie que la plage des valeurs acceptables est comprise entre zéro et un. La normalisation consiste donc à modifier les valeurs des nombres pour qu'elles s'insèrent dans cette plage. Par exemple, les valeurs RGB standard sont des entiers compris entre zéro et 255. Les normaliser revient essentiellement à les diviser par 255.

my @rgb = Graphics::Toolkit::Color::Space::Hub::normalize( [0,10,255], 'RGB' );

Elle a un argument obligatoire et deux optionnels. Le premier est une référence ARRAY contenant le vecteur ou les valeurs d'une couleur. Le second argument est le nom d'un espace colorimétrique. Ceci est nécessaire dans la plupart des cas, car tous les espaces colorimétriques connaissent leurs plages de valeurs standard (étant par exemple 3 x 0 .. 255 pour RGB). Si vous souhaitez normaliser à partir de plages spéciales comme RGB16, vous devez utiliser le troisième argument, qui doit être une définition de plage de valeurs valide.

my @rgb = Graphics::Toolkit::Color::Space::Hub::normalize( [0, 1000, 34000], 'RGB', 2**16 );
# ce qui est identique à :
my @rgb = Graphics::Toolkit::Color::Space::Hub::normalize( [0, 1000, 34000], 'RGB', [[0,65536].[0,65536].[0,65536]] );

denormalize

Fonction inverse de normalize, prenant les mêmes arguments. Si le résultat doit être un entier (plage maximale supérieure à 1), il sera arrondi.

my @rgb = Graphics::Toolkit::Color::Space::Hub::denormalize( [0,0.1,1], 'RGB' );
my @rgb = Graphics::Toolkit::Color::Space::Hub::denormalize( [0,0.1,1], 'RGB', 2**16 );

convert

Convertit un va

e vector (premier argument) de l'espace de base (RGB) vers n'importe quel espace mentionné (second argument - voir "COLOR-SPACES"). Les valeurs doivent être normalisées (entre 0 et 1). Si elles sont hors de la plage acceptable, elles seront bornées, de sorte que le résultat sera également normal.

# convertir de RGB vers HSL
my @hsl = Graphics::Toolkit::Color::Space::Hub::convert( [0.1, 0.5, .7], 'HSL' );

deconvert

Convertit un tuple de valeurs (vecteur - premier argument) de n'importe quel espace de couleur (second argument) en espace de base (RGB).

# convertir de HSL vers RGB
my @rgb = Graphics::Toolkit::Color::Space::Hub::deconvert( [0.9, 0.5, 0.5], 'HSL' );

format

Met une liste de valeurs (dans une référence ARRAY - premier argument) de n'importe quel espace de couleur pris en charge (second argument) dans un autre format de données (troisième argument, voir /FORMATS).

my $hex = Graphics::Toolkit::Color::Space::Hub::format( [255, 0, 10], 'hex' );       # 'ff00a0'
my $string = Graphics::Toolkit::Color::Space::Hub::format( [255, 0, 10], 'string' ); # 'RGB: 255, 0, 10'

deformat

Fonction inverse de format, mais qui devine également l'espace de couleur. C'est pourquoi elle ne prend qu'un seul argument, un scalaire qui peut être une chaîne, une référence ARRAY ou une référence HASH. Le résultat sera de deux valeurs. La première est un ARRAY avec toutes les valeurs inchangées, non bornées et non normalisées. La seconde est le nom de l'espace de couleur reconnu.

my ($values, $space) =  Graphics::Toolkit::Color::Space::Hub::deformat( 'ff00a0' );
# [255, 10 , 0], 'RGB'
($values, $space) =  Graphics::Toolkit::Color::Space::Hub::deformat( [255, 10 , 0] ); # même résultat

partial_hash_deformat

C'est un cas spécial deformat pour le format hash et char_hash (voir /FORMATS). Elle peut tolérer des valeurs manquantes. Le résultat sera également un hash
