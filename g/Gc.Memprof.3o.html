MODULE

Module Gc.Memprof

DOCUMENTATION

Module Memprof
: sig end

Memprof est un moteur de profilage qui échantillonne aléatoirement les mots mémoire alloués. Chaque mot alloué a une probabilité d'être échantillonné égale à un taux d'échantillonnage configurable. Une fois qu'un bloc est échantillonné, il devient suivi. Un bloc suivi déclenche une fonction de rappel définie par l'utilisateur dès qu'il est alloué, promu ou désalloué.

Les blocs étant composés de plusieurs mots, un bloc peut potentiellement être échantillonné plusieurs fois. Si un bloc est échantillonné plusieurs fois, alors chacune des fonctions de rappel est appelée une fois pour chaque événement de ce bloc : la multiplicité est donnée dans le champ n_samples de la structure allocation.

Ce moteur permet d'implémenter un profileur mémoire à faible surcharge sous forme de bibliothèque OCaml.

Note : cette API est EXPÉRIMENTALE. Elle peut changer sans préavis.

type t

le type d'un profil

type allocation_source =
| Normal
| Marshal
| Custom
| Map_file

val string_of_allocation_source : allocation_source -> string

type allocation = private {
n_samples : int ; (* Le nombre d'échantillons dans ce bloc (>= 1).
*)
size : int ; (* La taille du bloc, en mots, hors en-tête.
*)
source : allocation_source ; (* La cause de l'allocation.
*)
callstack : Printexc.raw_backtrace ; (* La pile d'appels pour l'allocation.
*)
}

Le type de métadonnées associées aux allocations. C'est le type des enregistrements passés à la fonction de rappel déclenchée par l'échantillonnage d'une allocation.

type ('minor, 'major) tracker = {
alloc_minor : allocation -> 'minor option ;
alloc_major : allocation -> 'major option ;
promote : 'minor -> 'major option ;
dealloc_minor : 'minor -> unit ;
dealloc_major : 'major -> unit ;
}

Un ('minor, 'major) tracker décrit comment memprof doit suivre les blocs échantillonnés tout au long de leur vie, en conservant un morceau de métadonnées défini par l'utilisateur pour chacun d'eux : 'minor est le type de métadonnées à conserver pour les blocs mineurs, et 'major le type de métadonnées pour les blocs majeurs.

Les fonctions membres dans un tracker sont appelées des fonctions de rappel.

Si une fonction de rappel d'allocation ou de promotion lève une exception ou renvoie None, memprof arrête de suivre le bloc correspondant.

val null_tracker : ('minor, 'major) tracker

Les fonctions de rappel par défaut renvoient simplement None ou ()

val start : sampling_rate:float -> ?callstack_size:int -> ('minor, 'major) tracker -> t

Démarre un profil avec les paramètres donnés. Lève une exception si un profil échantillonne déjà dans le domaine courant.

L'échantillonnage commence immédiatement. Le paramètre sampling_rate est le taux d'échantillonnage en échantillons par mot (en-têtes inclus). Habituellement, avec des fonctions de rappel peu coûteuses, un taux de 1e-4 n'a aucun effet visible sur les performances, et 1e-3 ralentit le programme de quelques pour cent. 0.0 <= sampling_rate <= 1.0.

Le paramètre callstack_size est la longueur de la pile d'appels enregistrée à chaque échantillon. Sa valeur par défaut est max_int.

Le paramètre tracker détermine comment suivre les blocs échantillonnés tout au long de leur vie dans le tas mineur et majeur.

L'échantillonnage et l'exécution des fonctions de rappel sont temporairement désactivés sur le thread courant lors de l'appel d'une fonction de rappel, donc les fonctions de rappel n'ont pas besoin d'être réentrantes si le programme est monothread et monodomaine. Cependant, si des threads ou plusieurs domaines sont utilisés, il est possible que plusieurs fonctions de rappel s'exécutent en parallèle. Dans ce cas, les fonctions de rappel doivent être réentrantes.

Notez qu'une fonction de rappel peut être légèrement retardée après l'événement réel. La pile d'appels passée à une fonction de rappel d'allocation reflète toujours fidèlement l'allocation, mais l'état du programme peut avoir évolué entre l'allocation et l'appel de la fonction de rappel.

Si un nouveau thread ou domaine est créé lorsque le domaine courant échantillonne pour un profil, le thread ou domaine enfant rejoint ce profil (en utilisant le même sampling_rate, callstack_size et les fonctions de rappel du tracker).

Une fonction de rappel d'allocation est toujours exécutée par le thread qui a alloué le bloc. Si le thread se termine ou si le profil est arrêté avant que la fonction de rappel ne soit appelée, la fonction de rappel d'allocation n'est pas appelée et le bloc n'est pas suivi.

Chaque fonction de rappel suivante est généralement exécutée par le domaine qui a alloué le bloc. Si le domaine se termine ou si le profil est arrêté avant que la fonction de rappel ne soit appelée, la fonction de rappel peut être exécutée par un domaine différent.

Différents domaines peuvent échantillonner pour différents profils simultanément.

val stop : unit -> unit

Arrête l'échantillonnage pour le profil courant. Échoue si aucun profil n'échantillonne dans le domaine courant. Arrête l'échantillonnage dans tous les threads et domaines partageant le profil.

Les fonctions de rappel de promotion et de désallocation d'un profil peuvent s'exécuter après l'appel de stop, jusqu'à ce que discard soit appliqué au profil.

Un profil est implicitement arrêté (mais pas rejeté) si tous les domaines et threads qui l'utilisent sont terminés.

val discard : t -> unit

Rejette tout état de profilage pour un profil arrêté, ce qui empêche toute nouvelle fonction de rappel pour celui-ci. Lève une exception si appelée sur un profil qui n'a pas été arrêté.
