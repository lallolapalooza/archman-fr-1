DESCRIPTIO

N

Les programmes pilotés par événements ont besoin d'une sorte de boucle qui surveille les événements et lance les actions appropriées. Glib::MainLoop fournit cette

fonctionnalité.

Les boucles principales ont un contexte, fourni par l'objet MainContext. Pour la plupart, vous pouvez utiliser le contexte par défaut (voir « default »), mais si vous souhaitez créer un sous-contexte pour une boucle imbriquée qui n'a pas les mêmes sources d'événements, etc., vous le

pouvez.

Les sources d'événements, attachées aux contextes principaux, surveillent la survenue d'événements et lancent les actions appropriées. Glib fournit quelques sources d'événements toutes faites : Glib::Timeout, Glib::Idle et la surveillance d'E/S (« Glib::IO->add_watch »)

.

En interne, Gtk+ ajoute des sources d'événements pour les GdkEvents afin de distribuer les événements à vos widgets. En fait, Gtk2 fournit une abstraction de Glib::MainLoop (voir « Gtk2->main » et ses amis), vous n'aurez donc peut-être que rarement à utiliser Glib::MainLoop

directement.

Remarque : À partir de la version 1.080, le module Glib utilise une source d'événements personnalisée pour garantir q

ue la gestion sûre des signaux de perl et la boucle d'événements de polling de glib fonctionnent bien ensemble. Il n'e
st plus nécessaire d'installer un timeout pour garantir que les signaux asynchrones soient traités en temps opportun.

CONSTANTE

S

« SOURCE_REMOVE » et « SOURCE_CONTINUE » sont conçues pour être utilisées comme valeurs de retour des fonctions de source de timeout, d'inactivité et de surveillance d'E/S. Elles retournent vrai pour continuer à s'exécuter ou faux pour se retirer elles-mêmes. Ces constantes peuvent vous aider à obtenir le bon

résultat. 
Glib::SOURCE_CONTINUE
# vrai Glib::SOUR
CE_REMOVE # faux
