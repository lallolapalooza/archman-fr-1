Analyse les fichiers xs pour les signatures xsub et le pod. Écrit sur la sortie
standard une structure de données adaptée à l'évaluation dans un autre script
Perl, décrivant tout ce qui a été trouvé. La sortie contient trois variables :
$xspods =
RÉFÉRENCE_TABLEAU
tableau des pods trouvés dans la portion C verbatim du fichier XS, listés dans l'ordre où ils ont été trouvés. On suppose qu'ils concernent l'API XS/C, et non l'API Perl. Tout paragraphe "=for apidoc" suivant un paragraphe "=object" dans les sections verbatim est supprimé (comme les paragraphes "=object"), et apparaîtra à la place dans "$data->{$package
}{pods}".
$data = RÉFÉRENCE_TABLEAU_ASSO
CIATIF
grand tableau associatif indexé par nom de package (tel que trouv
é dans la ligne MODULE), contenant sous chaque clé un tableau ass
ociatif avec tous les xsubs et pods de ce package, dans l'ordre t
rouvé. Les packages sont consolidés à travers plusieurs fichiers.

Pour information, cela crée un nouvel analyseur et appelle "parse_file" sur lui pour chaque nom de fichier en entrée ; puis appelle "swizzle_pods" pour s'assurer que tous les pods "=for apidoc name" sont associés à leurs xsubs cibles ; et enfin appelle Data::Dumper pour écrire les donn

ées sur stdout. Donc, si vous voulez un contrôle plus fin
sur la création de la sortie, ou conserver toutes les don
nées en interne, maintenant vous savez comment faire. :-)

Analyse un en-tête xsub, sous la forme d'une liste de lignes, en une structure de données décrivant l'xsub. Cela inclut l'extraction des types d'arguments, des alias et du type de code.

Sans intelligence artificielle, nous ne pouvons pas déterminer de manière fiable quoi que ce soit sur les types ou le nombre de paramètres renvoyés par les xsubs avec des corps

PPCODE.

Les paramètres OUTLIST sont extraits de la liste des arguments et placés dans une clé "outlist". Les paramètres IN_OUTLIST sont placés dans les

deux.

Les noms de types de données ne sont pas modifiés

du tout.

Notez que la méthode peut prendre soit une liste de lignes, soit une référence à une l

iste de lignes. La forme liste plate est fournie pour compatibilité ; la forme référen
ce est préférée, pour éviter de dupliquer une potentiellement grande liste de chaînes.
