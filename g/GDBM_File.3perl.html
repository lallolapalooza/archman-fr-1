DESCRIPTIO

N

GDBM_File est un module qui permet aux programmes Perl d'utiliser les fonctionnalités fournies par la bibliothèque GNU gdbm. Si vous comptez utiliser ce module, vous devriez vraiment avoir une copie du manuel GDBM à portée de main. Le manuel est disponible en ligne à l'adresse https://www.gnu.org.ua/software/gdbm/manual

.

La plupart des fonctions gdbm sont accessibles via l'interface GDBM_File

.

Contrairement aux tables de hachage intégrées de Perl, il n'est pas sûr de « supprimer » l'élément courant d'une table de hachage liée à un GDBM_File pendant qu'on la parcourt avec « each ». C'est une limitation de la bibliothèque

gdbm.

Ti

e

Utilisez la fonction intégrée Perl tie pour associer une base de données GDBM à une table de hachage Perl

: 
tie %hash, 'GDBM_File', $filename, $flags,
$mode;

Ici, $filename est le nom du fichier de base de données à ouvrir ou à créer. $flags est un OU bit à bit du mode d'accès et d'éventuels modificateurs. Le mode d'accès est l'un des suivants

:
GDBM_READ
ER
Ouvrir un fichier de base de données existant en mode lecture
seule.
GDBM_WRIT
ER
Ouvrir un fichier de base de données existant en mode
lecture-écriture.
GDBM_WRCRE
AT
Si le fichier de base de données existe, l'ouvrir en mode lecture-écriture. Sinon, le créer d'abord puis l'ouvrir en
lecture-écriture.
GDBM_NEW
DB
Créer une nouvelle base de données et l'ouv
rir en lecture-écriture. Si la base de donn
ées existe déjà, la tronquer d'abord.

Un certain nombre de modificateurs peuvent être combinés par un OU au mode d'accès. La plupart d'entre eux sont rarement nécessaires (voir https://www.gnu.org.ua/software/gdbm/manual/Open.html pour la liste complète), mais il y en a un qui mérite d'être mentionné. Le modificateur GDBM_NUMSYNC, lorsqu'il est utilisé avec GDBM_NEWDB, indique à GDBM de créer la base de données dans un format étendu (appelé numsync). Ce format convient le mieux aux implémentations tolérantes aux pannes. Voir TOLÉRANCE AUX PANNES ci-dessous pour plus

d'informations.

Le paramètre $mode est le mode du fichier pour la création d'un nouveau fichier de base de données. Utilisez une constante octale ou une combinaison de constantes « S_I* » du module Fcntl. Ce paramètre est utilisé si $flags vaut GDBM_NEWDB ou GDBM_WRCREAT

.

En cas de succès, tie renvoie un objet de classe GDBM_File. En cas d'échec, elle renvoie undef. Il est recommandé de toujours vérifier la valeur de retour, pour vous assurer que votre table de hachage est correctement associée au fichier de base de données. Voir GESTION DES ERREURS c

GDBM_versio

n 
$str = GDBM_File->GDBM_version;

GDBM_version;

Renvoie le numéro de version de la bibliothèque libgdbm sous-jacente. En contexte scalaire, renvoie la version de la bibliothèque formatée sous forme de chaîne

: 
MINOR.MAJOR[.PATCH][ (GUESS)
]

où MINOR, MAJOR et PATCH sont des numéros de version, et GUESS est un niveau de supposition (voir ci-dessous)

.

En contexte liste, renvoie une liste

: 
( MINOR, MAJOR, PATCH [, GUESS]
)

Le composant GUESS n'est présent que si la version de libgdbm est 1.8.3 ou antérieure. C'est parce que les versions antérieures de libgdbm n'incluaient pas d'informations sur leur version et que le module GDBM_File doit implémenter certaines suppositions afin de la déterminer. GUESS est une description textuelle en contexte chaîne, et un nombre positif indiquant la précision de la supposition en contexte liste. Les valeurs possibles sont

:
1 - supposition
exacte
Les numéros de version majeure et mineure sont garantis corrects. Le niveau de correctif est très probablement deviné correctement, mais peut être inférieur de 1 à 2 par rapport à ce qui est
indiqué.
2 -
approximatif
Les numéros majeur et mineur sont garantis corrects. Le niveau de correctif est fixé à la borne
supérieure.
3 - supposition
approximative
La version est garantie ne pas être plus récente que MAJOR.MINOR
.

gdbm_errno

Lorsqu'il est référencé en contexte numérique, récupère la valeur courante de la variable gdbm_errno, c'est-à-dire un code numérique décrivant l'état de la dernière opération sur n'importe quelle base de données gdbm. Chaque code numérique a un nom symbolique associé. Pour une liste complète de ceux-ci, voir https://www.gnu.org.ua/software/gdbm/manual/Error-codes.html. Remarquez que cette liste inclut tous les codes d'erreur définis pour la version la plus récente de gdbm. Selon la version réelle de la bibliothèque avec laquelle GDBM_File est compilé, certains d'entre eux peuvent

manquer.

En contexte chaîne, $gdbm_errno renvoie une description lisible de l'erreur. Si nécessaire, cette description inclut la valeur de $!. Cela permet de l'utiliser dans des messages de diagnostic. Par exemple, la séquence habituelle de liaison

est

gdbm_errno";

L'exemple suivant, plus complexe, illustre comment vous pouvez revenir en mode lecture seule si les permissions du fichier de base de données interdisent l'accès en lecture-écriture

use Errno qw(EACCES);
unless (tie(%hash, 'GDBM_File', $filename, GDBM_WRCREAT, 0640)) {
    if ($GDBM_File::gdbm_errno == GDBM_FILE_OPEN_ERROR
        && $!{EACCES}) {
        if (tie(%hash, 'GDBM_File', $filename, GDBM_READER, 0640)) {
            die "$GDBM_File::gdbm_errno";
        }
    } else {
        die "$GDBM_File::gdbm_errno";
    }
}

Crée un export de la base de données dans $filename. Un tel fichier peut être utilisé comme copie de sauvegarde ou envoyé sur le réseau pour recréer la base de données sur une autre machine. Pour créer une base de données à partir du fichier d'export, utilisez la méthode load

GDBM prend en charge deux formats d'export : l'ancien binaire et le nouveau ascii. Le format binaire n'est pas portable entre architectures et est obsolète. Il a été introduit avec la version 1.11 de gdbm et est le format d'export préféré. La méthode dump crée des exports ascii par

défaut.

TOLÉRANCE AUX

PLANTAGES

La tolérance aux pannes est une nouvelle fonctionnalité qui, avec un support approprié du système d'exploitation et du système de fichiers, garantit qu'un état récent logiquement cohérent de la base de données peut être récupéré après un crash, tel qu'une coupure de courant, un panique du noyau de l'OS, ou la

sorte.

Le support de la tolérance aux pannes est apparu dans gdbm version 1.21. La théorie derrière celle-ci est expliquée dans "Crashproofing the Original NoSQL Key-Value Store", par Terence Kelly (https://queue.acm.org/detail.cfm?id=3487353). Une discussion détaillée de l'implémentation gdbm est disponible dans le Manuel GDBM (https://www.gnu.org.ua/software/gdbm/manual/Crash-Tolerance.html). Les informations ci-dessous décrivent l'interface

Perl.

Pour une robustesse maximale, nous recommandons d'utiliser le format de base de données étendu pour les bases de données tolérantes aux pannes. Pour créer une base de données au format étendu, utilisez l'option GDBM_NEWDB|GDBM_NUMSYNC lors de l'ouverture de la base de données, par exemple

: 
$db = tie %hash, 'GDBM_File', $filename,
          GDBM_NEWDB|GDBM_NUMSYNC,
0640;

Pour convertir une base de données existante au format étendu, utilisez la méthode convert, décrite ci-dessus, par exemple

: 
$db->convert(GDBM_NUMSYNC)
;

Active la tolérance aux pannes pour la base de données $db. Les arguments sont les chemins de deux fichiers qui seront créés et remplis avec des instantanés du fichier de base de données. Les deux fichiers ne doivent pas exister lorsque cette méthode est appelée et doivent se trouver sur le même système de fichiers que le fichier de base de données. Ce système de fichiers doit prendre en charge l'opération reflink (https://www.gnu.org.ua/software/gdbm/manual/Filesystems-sup

porting-crash-tolerance.html>.

Après un appel réussi à failure_atomic, chaque appel à la méthode-sync> fera un instantané reflink efficace du fichier de base de données dans l'un de ces fichiers ; les appels consécutifs à sync alternent entre les deux, d'où les

noms.

Le plus récent de ces fichiers peut être utilisé pour récupérer la base de données après un crash. Pour sélectionner le bon instantané, utilisez la méthode statique

latest_snapshot
.

récent.

En contexte scalaire, elle renvoie le nom du fichier sélectionné ou undef en cas

d'échec.

En contexte tableau, elle renvoie une liste de deux éléments : le nom du fichier et le code de statut. En cas de succès, le nom du fichier est défini et le code est GDBM_SNAPSHOT_OK. En cas d'erreur, le nom du fichier est undef, et le statut est l'un des suivants

données.

SÉCURITÉ ET

PORTABILITÉ

Les fichiers GDBM ne sont pas portables entre les plateformes. Si vous souhaitez transférer un fichier GDBM sur le réseau, convertissez-le d'abord dans un format

portable.

N'acceptez pas de fichiers GDBM provenant de sources non

fiables.

La robustesse de GDBM contre les bases de données corrompues dépend fortement de sa version. Les versions antérieures à 1.15 n'implémentaient aucune vérification de validité, de

sorte qu'un fichier de base de données corrompu ou malveillant pouvait faire planter perl ou même exposer une faille de sécurité. Les versions entre 1.15 et 1.20 ont été progressi
vement renforcées contre les entrées invalides. Enfin, la version 1.21 a subi un contrôle flou approfondi qui a prouvé sa capacité à résister à tous types d'entrées sans planter.
