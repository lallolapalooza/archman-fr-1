COULEUR

S

Toutes les références aux couleurs dans les options de ce module ont été

COULEURS

La plupart des noms de couleur sont raccourcis, par exemple, "black" en "blk", "red" en "red", "blue" en "blu". Cela a été fait pour éviter les ambiguïtés avec la manière dont les gens épellent les noms de couleur. Par exemple, "grey" et "gray". Les noms raccourcis sont toujours les mêmes quel que soit le système d'exploitation.

Aussi, le nom "color" dans le code a été raccourci en "clr". La raison principale était que je ne voulais pas supporter deux orthographes pour le même mot ("colour" et "color").

Partout où une couleur est requise, un nom de couleur doit être utilisé à partir du paquetage GD::Graph::colour. "perldoc GD::Graph::colour" devrait vous donner la documentation de ce module, contenant tous les noms de couleur valides. Je vais probablement changer cela pour lire le fichier rgb.txt du système s'il est disponible.

POLICES

Selon votre version de GD, cela accepte les polices intégrées de GD ou le nom d'un fichier de police TrueType. Dans le cas d'une police TrueType, vous devez spécifier la taille de la police. Voir GD::Text pour plus de détails et d'autres informations, car toute la gestion des polices dans GD::Graph y est déléguée.

Exemples :

$graph->set_title_font('/fonts/arial.ttf', 18);
$graph->set_legend_font(gdTinyFont);
$graph->set_legend_font(
    ['verdana', 'arial', gdMediumBoldFont], 12)

(La discussion ci-dessus est basée sur GD::Text 0.65. Les versions plus anciennes ont un comportement plus restrictif).

ZONES ACTIVES

Notez qu'il s'agit d'une fonctionnalité expérimentale, et son interface peut, et changera probablement, à l'avenir. Elle ne fonctionne pas actuellement pour les graphiques en aires ou les graphiques circulaires.

Un problème connu avec les zones actives pour GD::Graph::hbars est que les coordonnées x et y sont transposées. Cela ne sera probablement pas corrigé avant la refonte de cette section

GD::Graph conserve un ensemble interne de coordonnées pour chaque point de données et pour certaines caractéristiques d'un graphique, comme le titre et les étiquettes des axes. Cette spécification est très similaire à la spécification des cartes d'image HTML, et existe en fait principalement à cette fin. Vous pouvez accéder à ces zones actives avec la méthode "get_hotspot" pour les points de données, et "get_feature_coordinates" pour les caractéristiques du graphique.

La méthode <get_hotspot> accepte deux arguments optionnels, le numéro de l'ensemble de données qui vous intéresse, et le numéro du point dans cet ensemble de données qui vous intéresse. Lorsqu'elle est appelée avec deux arguments, la méthode renvoie une liste d'une des formes suivantes :

'rect', x1, y1, x2, y2
'poly', x1, y1, x2, y2, x3, y3, ....
'line', xs, ys, xe, ye, width

Les paramètres pour "rect" sont les coordonnées des coins du rectangle, les paramètres pour "poly" sont les coordonnées des sommets du polygone, et les paramètres pour la "line" sont les coordonnées du point de départ et d'arrivée, et la largeur de la ligne. Il devrait être possible de traduire presque directement ces listes en spécifications de cartes d'image HTML.

Si le deuxième argument de "get_hotspot" est omis, une liste de références vers des tableaux sera renvoyée. Cette liste représente tous les points de l'ensemble de données spécifié, et chaque tableau référencé est de la forme décrite ci-dessus.

['rect', x1, y1, x2, y2 ], ['rect', x1, y1, x2, y2], ...

Si les deux arguments de "get_hotspot" sont omis, la liste qui revient contiendra des références vers des tableaux pour chaque ensemble de données, qui à leur tour contiennent des références vers des tableaux pour chaque point.

[
  ['rect', x1, y1, x2, y2 ], ['rect', x1, y1, x2, y2], ...
],
[
  ['line', xs, ys, xe, ye, w], ['line', xs, ys, xe, ye, w], ...
],...

La méthode "get_feature", lorsqu'elle est appelée avec le nom d'une caractéristique, renvoie une seule référence de tableau avec un type et des coordonnées comme décrit ci-dessus. Lorsqu'elle est appelée sans arguments, une référence de hachage est renvoyée avec les clés étant toutes les caractéristiques actuellement définies et configurées, et les valeurs étant des références de tableaux avec le type et les coordonnées pour chacune de ces caractéristiques.

GESTION DES ERREURS

Les objets GD::Graph héritent de la classe GD::Graph::Error (et non l'inverse), ils se comportent donc de la même manière. La principale caractéristique de ce comportement est que vous disposez de la méthode error() pour obtenir des informations sur ce qui s'est mal passé. Les méthodes GD::Graph renvoient toutes undef si quelque chose s'est mal passé, vous devriez donc pouvoir écrire des programmes sûrs comme ceci :

my $graph = GD::Graph->new()    or die GD::Graph->error;
$graph->set( %attributes )      or die $graph->error;
$graph->plot($gdg_data)         or die $graph->error;

Une utilisation plus avancée est possible, et il y a quelques réserves avec cette gestion des erreurs, qui sont toutes expliquées dans GD::Graph::Error.

Malheureusement, il est presque impossible de récupérer gracieusement d'une erreur dans GD::Graph, vous devriez donc vraiment vous débarrasser de l'objet et le recréer à partir de zéro si vous souhaitez récupérer. Par exemple, pour ajuster l'attribut correct_width si vous obtenez l'erreur "Horizontal size too small" ou "Vertical size too small" (dans le cas de hbar), vous pourriez faire quelque chose comme :

sub plot_graph
{
    my $data    = shift;
    my %attribs = @_;
    my $graph   = GD::Graph::bars->new()
       or die GD::Graph->error;
    $graph->set(%attribs)     or die $graph->error;
    $graph->plot($data)       or die $graph->error;
}

my $gd;
eval { $gd = plot_graph(\@data, %attribs) };
if ($@)
{
    die $@ unless $@ =~ /size too small/;
    $gd = plot_graph(\@data, %attribs, correct_width => 0);
}

Bien sûr, vous pourriez également ajuster la largeur de cette manière, et vous pouvez vérifier d'autres erreurs.

BOGUES

Les objets GD::Graph ne peuvent pas être réutilisés. Pour créer un nouveau graphique, vous devez créer un nouvel objet GD::Graph.

Les graphiques pivotés (ceux avec l'axe X à gauche) ne peuvent actuellement être créés que pour les barres. Avec un peu de travail, cela fonctionnera également pour tous les autres. S'il vous plaît, soyez patient :)

D'autres bogues en suspens peuvent (hélas) probablement être trouvés dans la file d'attente RT pour cette distribution, à http://rt.cpan.org/Public/Dist/Display.html?Name=GDGraph

Si vous pensez avoir trouvé un bogue, veuillez d'abord vérifier s'il a déjà été signalé. S'il ne l'a pas été, veuillez le faire (vous pouvez utiliser l'interface web ci-dessus ou envoyer un e-mail à <bug-GDGraph@rt.cpan.org>). Les rapports de bogues doivent contenir autant que possible des éléments suivants :

  • une description concise du comportement défectueux et en quoi il diffère de ce que vous attendiez,
  • les versions de Perl, GD::Graph et GD que vous utilisez,
  • un court script de démonstration qui montre le bogue en action,
  • un correctif qui le résout. :-)

De tous ces éléments, le troisième est probablement le plus important, car la production d'un cas de test rend généralement l'explication beaucoup plus concise et compréhensible, tout en simplifiant grandement la démonstration que le bogue a été corrigé. Comme avantage accessoire, si le bogue se trouve en fait dans du code extérieur à GD::Graph, il deviendra apparent pendant que vous écrivez le cas de test, économisant ainsi du temps et de la confusion pour toutes les personnes concernées.
