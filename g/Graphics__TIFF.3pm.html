SYNOPSI

S

Liaisons Perl pour la bibliothèque libtiff. Ce module vous permet d'accéder aux images TIFF d'une manière perlienne et orientée objet, vous libérant des conversions de types et de la gestion de la mémoire en C, tout en restant très fidèle à l'esprit de l'API

originale.

L'extrait suivant peut être utilisé pour lire les données d'image d'un TIFF

: 
use Graphics::TIFF ':all';
my $tif = Graphics::TIFF->Open( 'test.tif', 'r' );
my $stripsize =
$tif->StripSize; for my $stripnum ( 0 .. $tif->NumberOfStrips - 1 ) { my $buffer = $tif->Re
adEncodedStrip( $stripnum, $stripsize ); # faire quelque chose avec $buffer } $tif->Close;

ReadDirectory

Lit le répertoire suivant du fichier spécifié et le définit comme répertoire courant. Les applications n'ont besoin d'appeler ReadDirectory que pour lire plusieurs sous-fichiers dans un seul fichier TIFF - le premier répertoire d'un fichier est automatiquement lu lorsque Open est

appelé.

Note

s

Si la bibliothèque est compilée avec STRIPCHOP_SUPPORT activé, alors les images qui ont une seule bande ou tuile de données non compressée sont automatiquement traitées comme si elles étaient composées de plusieurs bandes ou tuiles d'environ 8 kilooctets chacune. Cette opération n'est effectuée qu'en mémoire ; elle n'altère pas le contenu du fichier. Cependant, la construction des « bandes découpées » est visible pour l'application à travers le nombre de bandes [tuiles] retourné par NumberOfStrips [NumberOfTiles]

.

Valeurs de

retour

Si le répertoire suivant a été lu avec succès, 1 est

retourné. Sinon, 0 est retourné si une erreur a été
rencontrée, ou s'il n'y a plus de répertoires à lire.

$tif->

WriteDirectory

WriteDirectory écrit le contenu du répertoire courant dans le fichier et se prépare à créer un nouveau sous-fichier dans le même fichier. Les applications n'ont besoin d'appeler WriteDirectory que lors de l'écriture de plusieurs sous-fichiers dans un seul fichier TIFF. WriteDirectory est automatiquement appelé par Close et Flush pour écrire un répertoire modifié si le fichier est ouvert en

écriture.

La fonction RewriteDirectory fonctionne de manière similaire à WriteDirectory, mais peut être appelée avec des répertoires précédemment lus ou écrits qui ont déjà un emplacement établi dans le fichier. Elle réécrira le répertoire, mais au lieu de le placer à son ancien emplacement (comme le ferait TIFFWriteDirectory), elle le placera à la fin du fichier, en corrigeant le pointeur du répertoire précédent ou de l'en-tête de fichier pour qu'il pointe vers son nouvel emplacement. C'est particulièrement important dans les cas où la taille du répertoire et des données pointées a augmenté, de sorte qu'il ne tient pas dans l'espace disponible à l'ancien

emplacement.

CheckpointDirectory écrit l'état actuel du répertoire tiff dans le fichier pour rendre lisible ce qui s'y trouve actuellement. Contrairement à WriteDirectory, CheckpointDirectory ne libère pas les structures de données du répertoire en mémoire, de sorte qu'elles peuvent être mises à jour (au fur et à mesure que les bandes/tuiles sont écrites) et réécrites. En lisant un tel fichier partiel, vous obtiendrez au pire une erreur de lecture tiff pour la première bande/tuile incomplète rencontrée, mais vous obtiendrez au moins toutes les données valides du fichier avant celle-ci. Lorsque le fichier est complet, utilisez simplement WriteDirectory comme d'habitude pour le terminer

proprement.

Valeurs de

retour

1 est retourné lorsque le contenu est écrit avec succès d

ans le fichier. Sinon, 0 est retourné si une erreur a ét
é rencontrée lors de l'écriture du contenu du répertoire.

$tif->GetFieldDefaulted(tag)

Identique à GetField, sauf que si une balise n'est pas définie dans le répertoire actuel et qu'elle a une valeur par défaut, alors la valeur par défaut est retournée.

$tif->SetField(tag, ...)

Définit la valeur d'un champ ou d'une pseudo-balise dans le répertoire actuel associé au fichier TIFF ouvert tif. Voir GetField pour les valeurs possibles de la balise.

$tif->IsTiled

Retourne une valeur non nulle si les données de l'image ont une organisation en tuiles. Zéro est retourné si les données de l'image sont organisées en bandes.

$tif->ScanlineSize

Retourne la taille en octets d'une ligne de données telle qu'elle serait retournée dans un appel à ReadScanline, ou telle qu'elle serait attendue dans un appel à WriteScanline.

$tif->StripSize

Retourne la taille équivalente pour une bande de données telle qu'elle serait retournée dans un appel à ReadEncodedStrip ou telle qu'elle serait attendue dans un appel à WriteEncodedStrip.

$tif->NumberOfStrips

Retourne le nombre de bandes dans l'image.

$tif->TileSize

Retourne la taille équivalente pour une tuile de données telle qu'elle serait retournée dans un appel à ReadTile ou telle qu'elle serait attendue dans un appel à WriteTile.

$tif->TileRowSize

Retourne le nombre d'octets d'une ligne de données dans une tuile.

$tif->ComputeStrip(row, sample)

Retourne la bande qui contient les coordonnées spécifiées. Une bande valide est toujours retournée ; les valeurs de coordonnées hors limites sont bornées aux limites de l'image. Le paramètre row est toujours utilisé pour calculer une bande. Le paramètre sample n'est utilisé que si les données sont organisées en plans séparés (PlanarConfiguration=2).

$tif->ReadEncodedStrip(strip, size)

Retourne un tampon d'au plus size octets d'informations décompressées.

La valeur de strip est un "numéro de bande brut". C'est-à-dire, l'appelant doit tenir compte du fait que les données soient organisées ou non en plans séparés (PlanarConfiguration=2). Pour lire une bande complète de données, le tampon de données devrait typiquement être au moins aussi grand que le nombre retourné par StripSize.

La bibliothèque tente de masquer les différences d'ordre des bits et des octets entre l'image et la machine native en convertissant les données à l'ordre de la machine native. L'inversion des bits est effectuée si la balise FillOrder est opposée à l'ordre des bits de la machine native. Les échantillons de 16 et 32 bits sont automatiquement échangés d'octets si le fichier a été écrit avec un ordre d'octets opposé à l'ordre d'octets de la machine native.

$tif->WriteEncodedStrip(strip, data, size)

Compresse size octets de données brutes à partir de buf et écrit le résultat dans la bande spécifiée ; remplaçant toute donnée précédemment écrite. Notez que la valeur de strip est un "numéro de bande brut". C'est-à-dire, l'appelant doit tenir compte du fait que les données soient organisées ou non en endroits séparés (PlanarConfiguration=2).

La bibliothèque écrit les données encodées en utilisant l'ordre des octets de la machine native. Les lecteurs TIFF correctement implémentés sont censés effectuer tout échange d'octets nécessaire pour traiter correctement les données d'image avec un BitsPerSample supérieur à 8.

Le numéro de bande doit être valide selon les réglages actuels des balises ImageLength et RowsPerStrip. Une image peut être étendue dynamiquement en augmentant la valeur de ImageLength avant chaque appel à TIFFWriteEncodedStrip.

-1 est retourné si une erreur a été rencontrée. Sinon, la valeur de size est retournée.

$tif->ReadRawStrip(strip, size)

Retourne le contenu de la bande spécifiée. Notez que la valeur de strip est un "numéro de bande brut". C'est-à-dire, l'appelant doit tenir compte du fait que les données soient organisées ou non en plans séparés (PlanarConfiguration=2). Pour lire une bande complète de données, le tampon de données devrait typiquement être au moins aussi grand que le nombre retourné par StripSize.

$tif->ReadTile(x, y, z, s)

Retourne les données pour la tuile contenant les coordonnées spécifiées. Les données sont retournées décompressées et, typiquement, dans l'ordre des octets et des bits natifs, mais sont sinon groupées (voir plus loin). Le tampon doit être suffisamment grand pour contenir une tuile entière de données. Les applications devraient appeler la routine TIFFTileSize pour connaître la taille (en octets) d'un tampon de tuile. Les paramètres x et y sont toujours utilisés par ReadTile. Le paramètre z est utilisé si l'image a plus d'une tranche (ImageDepth>1). Le paramètre sample n'est utilisé que si les données sont organisées en plans séparés (PlanarConfiguration=2).

La bibliothèque tente de masquer les différences d'ordre des bits et des octets entre l'image et la machine native en convertissant les données à l'ordre de la machine native. L'inversion des bits est effectuée si la balise FillOrder est opposée à l'ordre des bits de la machine native. Les échantillons de 16 et 32 bits sont automatiquement échangés d'octets si le fichier a été écrit avec un ordre d'octets opposé à l'ordre d'octets de la machine native.

$tif->CurrentDirectory()

Retourne un numéro d'index du répertoire actuel dans le fichier TIFF spécifié.

$tif->PrintDirectory(file, flags)

Imprime une description du répertoire actuel dans le fichier TIFF spécifié sur le flux de sortie standard I/O fd. Le paramètre flags est utilisé pour contrôler le niveau de détail des informations imprimées, et est un opérateur OU bit à bit des valeurs suivantes :

TIFFPRINT_NONE TIFFPRINT_STRIPS TIFFPRINT_CURVES TIFFPRINT_COLORMAP TIFFPRINT_JPEGQTABLES TIFFPRINT_JPEGACTABLES TIFFPRINT_JPEGDCTABLES

Graphics::TIFF::ReverseBits(data, taille)

Remplace chaque octet de data par sa valeur inversée en bits. Cette opération est effectuée avec une table de consultation.

DÉPENDANCES

À l'exécution

Les dépendances à l'exécution sont uniquement libtiff elle-même. Sous Windows, cela est satisfait par Alien::libtiff.

À la compilation

Les dépendances à la compilation sont en plus les en-têtes de développement pour libtiff et Perl.

Tests

En plus de ce qui précède, le module Perl Image::Magick est requis pour exécuter certains des tests.
