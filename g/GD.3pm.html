DESCRIPTIO

N

GD.pm est une interface Perl à la bibliothèque graphique gd de Thomas Boutell (version 2.01 ou supérieure ; voir ci-dessous). GD vous permet de créer des dessins en couleur en utilisant un grand nombre de primitives graphiques, et d'émettre les dessins sous forme de fichiers

PNG.

GD définit les quatre classes suivantes

:
"GD::
Image"
Une classe d'image, qui contient les données de l'image et accepte les appels de méthode des primitives
graphiques.
"GD::
Font"
Une classe de police, qui contient des informations statiques sur les polices et est utilisée pour le rendu du
texte.
"GD::
Polygon"
Un objet polygone simple, utilisé pour stocker des listes de sommets avant de rendre un polygone dans une
image.
"GD::
Simple"
Une classe « simple » qui simplifie l'API de GD::Image et ajoute ensuite un ensemble de méthodes de dessin orientées objet utilisant la
graphique à tortue, une gestion simplifiée des polices, la capacité de travailler en coordonnées polaires, les espaces de couleur HSV et
des noms de couleur lisibles par l'humain comme « lightblue ». Veuillez consulter GD::Simple pour une description de ces méthodes.

Un exemple simple

use GD;

Notes

:
1. Pour créer une nouvelle image vide, envoyez un message new() à GD::Image, en lui passant la largeur et la hauteur de l'image que vous souhaitez créer. Un objet image sera renvoyé. D'autres méthodes de classe vous permettent d'initialiser une image à partir de fichiers d'image existants au format JPG, PNG, GD, GD2, XBM ou d'autres formats pris en
charge.
2. Ensuite, vous ajouterez généralement des couleurs à la table de couleurs de l'image. Les couleurs sont ajoutées à l'aide d'un appel de méthode colorAllocate(). Les trois paramètres de chaque appel sont les triplets rouge, vert et bleu (rgb) pour la couleur souhaitée. La méthode renvoie l'index de cette couleur dans la table de couleurs de l'image. Vous devriez stocker ces index pour une utilisation
ultérieure.
3. Maintenant, vous pouvez dessiner ! Les différentes primitives graphiques sont décrites ci-dessous. Dans cet exemple, nous faisons du dessin de texte, créons un ovale, et créons et dessinons un
polygone.
4. Les polygones sont créés avec un message new() à GD::Polygon. Vous pouvez ajouter des points au polygone renvoyé un à la fois en utilisant la méthode addPt(). Le polygone peut ensuite être transmis à une image pour le
rendu.
5. Lorsque vous avez terminé de dessiner, vous pouvez convertir l'image au format PNG en lui envoyant un message png() (ou tout autre format d'image pris en charge). Elle renverra une valeur scalaire (potentiellement grande) contenant les données binaires de l'image. Ordinairement, vous l'imprimerez à ce moment-là ou l'écrirez dans un fichier. Pour assurer la portabilité sur les plateformes qui différencient les fichiers texte et binaires, assurez-vous d'appeler binmode() sur le fichier dans lequel vous écrivez
l'image.

Contrôle des couleurs

Ces méthodes vous permettent de contrôler et de manipuler la table des couleurs de GD::Image pour les images de palette, non truecolor.

$index = $image->colorAllocate(red,green,blue)
Ceci alloue une couleur avec les composantes rouge, verte et bleue spécifiées et renvoie son index dans la table des couleurs, si spécifié. La première couleur allouée de cette manière devient la couleur d'arrière-plan de l'image. (255,255,255) est blanc (tous les pixels allumés). (0,0,0) est noir (tous les pixels éteints). (255,0,0) est rouge pleinement saturé. (127,127,127) est gris 50 %. Vous pouvez trouver de nombreux exemples dans /usr/X11/lib/X11/rgb.txt.

Si aucune couleur n'est allouée, cette fonction renvoie -1.

Exemple :

$black = $myImage->colorAllocate(0,0,0); # couleur d'arrière-plan
$white = $myImage->colorAllocate(255,255,255);
$peachpuff = $myImage->colorAllocate(255,218,185);

Canaux Alpha

Les méthodes de canal alpha vous permettent de contrôler la façon dont les dessins sont traités selon le canal alpha. Lorsque la couleur réelle est activée, les couleurs sont codées sur quatre octets, dont les trois derniers octets sont les valeurs de couleur RVB, et le premier octet est le canal alpha. Par conséquent, la représentation hexadécimale d'une couleur RVB non transparente sera : C=0x00(rr)(bb)(bb)

Lorsque le blending alpha est activé, vous pouvez utiliser le premier octet de la couleur pour contrôler la transparence, ce qui signifie qu'un rectangle peint avec la couleur 0x00(rr)(bb)(bb) sera opaque, et un autre peint avec 0x7f(rr)(gg)(bb) sera transparent. La valeur Alpha doit être >= 0 et <= 0x7f.

$image->alphaBlending($integer)
La méthode alphaBlending() permet deux modes de dessin différents sur les images en couleur réelle. En mode blending, qui est activé par défaut (libgd 2.0.2 et supérieur), le composant canal alpha de la couleur fournie à toutes les fonctions de dessin, telles que "setPixel", détermine la quantité de couleur sous-jacente qui doit être autorisée à transparaître. En conséquence, GD effectue un blending automatique de la couleur existante à ce point avec la couleur de dessin, et stocke le résultat dans l'image. Le pixel résultant est opaque. En mode non-blending, la couleur de dessin est copiée littéralement avec son information de canal alpha, remplaçant le pixel de destination. Le mode blending n'est pas disponible lors du dessin sur des images en palette.

Passez une valeur de 1 pour le mode blending, et 0 pour le mode non-blending.

$image->saveAlpha($saveAlpha)
Par défaut, GD (libgd 2.0.2 et supérieur) n'essaie pas de sauvegarder les informations complètes du canal alpha (par opposition à la transparence de couleur unique) lors de la sauvegarde d'images PNG. (PNG est actuellement le seul format de sortie pris en charge par gd qui peut accueillir des informations de canal alpha.) Cela permet d'économiser de l'espace dans le fichier de sortie. Si vous souhaitez créer une image avec des informations de canal alpha à utiliser avec des outils qui la prennent en charge, appelez saveAlpha(1) pour activer la sauvegarde de ces informations, et appelez alphaBlending(0) pour désactiver le blending alpha dans la bibliothèque afin que les informations de canal alpha soient effectivement stockées dans l'image plutôt que d'être composées immédiatement au moment où les fonctions de dessin sont invoquées.
