Glib::Object::Introspection(3) Documentation Perl fournie par l'utilisateur Glib::Object::Introspection(3)

NOM

Glib::Object::Introspection - Créer dynamiquement des liaisons pour le langage Perl

SYNOPSIS

use Glib::Object::Introspection;
Glib::Object::Introspection->setup(
  basename => 'Gtk',
  version => '3.0',
  package => 'Gtk3');
# maintenant GtkWindow, pour n'en citer qu'un exemple, est disponible sous
# Gtk3::Window, et vous pouvez appeler gtk_window_new comme Gtk3::Window->new

DESCRIPTION

Glib::Object::Introspection utilise les projets gobject-introspection et libffi pour créer dynamiquement des liaisons Perl pour une grande variété de bibliothèques. Les exemples incluent Gtk, webkit, libsoup et bien d'autres.

DESCRIPTION POUR LES UTILISATEURS DE BIBLIOTHÈQUES

Pour permettre à Glib::Object::Introspection de créer des liaisons pour une bibliothèque, la bibliothèque doit avoir un fichier typelib installé, par exemple "$prefix/lib/girepository-1.0/Gtk-3.0.typelib". Dans votre code, appelez simplement "Glib::Object::Introspection->setup" avec les paires clé-valeur suivantes pour tout configurer :

basename => $basename
Le nom de base de la bibliothèque qui doit être encapsulée. Si votre typelib s'appelle "Gtk-3.0.typelib", alors le nom de base est 'Gtk'.
version => $version
La version particulière de la bibliothèque qui doit être encapsulée, sous forme de chaîne de caractères. Pour "Gtk-3.0.typelib", c'est '3.0'.
package => $package
Le nom du paquet Perl où toutes les classes et méthodes de la bibliothèque doivent être ancrées. Si une bibliothèque avec le nom de base 'Gtk' contient une classe 'GtkWindow', et que vous choisissez 'Gtk3' comme paquet, alors cette classe sera disponible sous 'Gtk3::Window'.

Les wrappers Perl créés par "Glib::Object::Introspection" suivent les conventions du module Glib et des anciennes liaisons écrites à la main comme Gtk2. Vous pouvez utiliser l'outil inclus "perli11ndoc" pour consulter la documentation de toutes les bibliothèques installées, organisée et affichée conformément à ces conventions. Les principes directeurs sous-jacents à ces conventions sont décrits ci-dessous.

Espaces de noms et Objets

Les espaces de noms des bibliothèques C sont mappés sur des paquets Perl conformément à l'option "package" spécifiée, par exemple :

gtk_ => Gtk3
gdk_ => Gtk3::Gdk
gdk_pixbuf_ => Gtk3::Gdk::Pixbuf
pango_ => Pango

Les classes, interfaces et types fondamentaux et enveloppés obtiennent leurs propres espaces de noms, en quelque sorte, car le concept de GType est complètement remplacé dans les liaisons Perl par le nom du paquet Perl.

GtkButton => Gtk3::Button
GdkPixbuf => Gtk3::Gdk::Pixbuf
GtkScrolledWindow => Gtk3::ScrolledWindow
PangoFontDescription => Pango::FontDescription

Avec ce mappage de paquets et la recherche de méthodes intégrée de Perl, les liaisons peuvent effectuer des conversions de type d'objet pour vous. Cela nous donne une syntaxe orientée objet plutôt confortable, utilisant les sémantiques normales des objets Perl :

en C :
  GtkWidget * b;
  b = gtk_check_button_new_with_mnemonic ("_Something");
  gtk_toggle_button_set_active (GTK_TOGGLE_BUTTON (b), TRUE);
  gtk_widget_show (b);
en Perl :
  my $b = Gtk3::CheckButton->new_with_mnemonic ('_Something');
  $b->set_active (1);
  $b->show;

Vous voyez à partir de cela que les macros de conversion ne sont pas nécessaires et que vous n'avez pas besoin de taper les préfixes d'espace de noms aussi souvent, donc votre code est beaucoup plus court.

Drapeaux et Énumérations

Les drapeaux (flags) et les valeurs d'énumération sont gérés comme des chaînes de caractères, car c'est beaucoup plus lisible que des nombres, et parce que c'est magique grâce au système GType. Les valeurs sont désignées par leurs pseudonymes ; en gros, supprimez le préfixe commun, mettez-le en minuscules et convertissez éventuellement '_' en '-' :

GTK_WINDOW_TOPLEVEL => 'toplevel'
GTK_BUTTONS_OK_CANCEL => 'ok-cancel' (ou 'ok_cancel')

Les drapeaux sont un cas spécial. Vous ne pouvez pas (raisonnablement) faire un OU bit à bit de ces constantes chaînes, vous fournissez donc plutôt une référence à un tableau d'entre elles. Les tableaux anonymes sont utiles ici, et un tableau anonyme vide est un moyen simple de dire 'aucun drapeau'.

FOO_BAR_BAZ | FOO_BAR_QUU | FOO_BAR_QUUX => [qw/baz quu qux/]
0 => []

Dans certains cas, vous devez vérifier si un bit est défini dans un champ de bits ; les méthodes retournant des drapeaux retournent donc un objet surchargé. Voir Glib pour plus de détails sur les opérations autorisées sur ces objets de drapeaux, mais voici un exemple rapide :

en C :
  /* event->state est un champ de bits */
  if (event->state & GDK_CONTROL_MASK) g_printerr ("control was down\n");
en Perl :
  # $event->state est un objet spécial
  warn "control was down\n" if $event->state & "control-mask";

Mais cela fonctionne aussi :

warn "control was down\n" if $event->state * "control-mask";
warn "control was down\n" if $event->state >= "control-mask";
warn "control and shift were down\n"
                          if $event->state >= ["control-mask", "shift-mask"];

Gestion de la mémoire

Les fonctions pour référencer et déréférencer des objets et libérer des structures enveloppées ne sont même pas mappées en Perl, car tout est géré automatiquement par les liaisons. Les objets seront maintenus en vie tant que vous aurez un scalaire Perl pointant dessus ou que l'objet sera référencé d'une autre manière, par exemple depuis un conteneur.

La seule chose à laquelle vous devez faire attention est la durée de vie des structures non comptées par référence, ce qui inclut la plupart des éléments dérivés de "Glib::Boxed". Si cela provient d'un rappel de signal, cela pourrait n'être valable que jusqu'à votre retour, ou si c'est l'intérieur d'un autre objet, cela pourrait n'être valable que tant que cet objet existe. En cas de doute, vous pouvez utiliser "copy". Les structures provenant de "copy" ou "new" vous appartiennent et vivent tant qu'elles sont référencées depuis Perl.

Callbacks (Rappels)

Utilisez les astuces normales de rappel/closure de Perl avec les rappels. L'utilisation la plus courante des rappels sera avec la méthode Glib "signal_connect" :

$widget->signal_connect (event => \&event_handler, $user_data);
$button->signal_connect (clicked => sub { warn "hi!\n" });

$user_data est facultatif, et avec les closures Perl, vous n'en avez souvent pas besoin (voir "Persistent variables with closures" dans perlsub).

Les données utilisateur sont conservées dans un scalaire, initialisé à partir de ce que vous fournissez dans "signal_connect" etc. Elles sont passées au rappel dans le style habituel de Perl "appel par référence", ce qui signifie que le rappel peut modifier son dernier argument, c'est-à-dire $_[-1], pour modifier les données utilisateur conservées. C'est un peu subtil, mais vous pouvez l'utiliser pour un certain "état" associé à la connexion.

$widget->signal_connect (activate => \&my_func, 1);
sub my_func {
  print "activation count: $_[-1]\n";
  $_[-1] ++;
}

Étant donné que les données utilisateur conservées sont un nouveau scalaire, il n'y a aucun changement à la variable (etc.) que vous avez initialement passée à "signal_connect".

Si vous avez un objet parent dans les données utilisateur (ou la closure), vous devez faire attention aux références circulaires qui empêchent la destruction du parent et de l'enfant. Voir "Two-Phased Garbage Collection" dans perlobj à ce sujet en général. Les widgets de niveau supérieur comme "Gtk3::Window" nécessitent toujours un appel explicite à "$widget->destroy", donc leur signal "destroy" est un bon endroit pour casser les références circulaires. Mais pour d'autres widgets, il est généralement plus simple d'éviter les circularités dès le départ, soit en utilisant des références faibles dans les données utilisateur, soit éventuellement en localisant un parent dynamiquement avec "$widget->get_ancestor".

Gestion des exceptions

Tout ce qui utilise GError en C échouera avec un "croak", en définissant $@ sur un objet d'exception magique, qui est surchargé pour imprimer le message d'erreur retourné. L'idéologie ici est que GError est utilisé pour les exceptions d'exécution, et "croak" est la façon de faire cela en Perl. Vous pouvez attraper un croak très facilement en enveloppant la fonction dans un eval

: 
eval {
  my $pixbuf = Gtk3::Gdk::Pixbuf->new_from_file ($filename);
  $image->set_from_pixbuf ($pixbuf);
};
if ($@) {
  print "$@\n"; # imprime le message d'erreur éventuellement localisé
  if (Glib::Error::matches ($@, 'Gtk3::Gdk::Pixbuf::Error',
                                'unknown-format')) {
    change_format_and_try_again ();
  } elsif (Glib::Error::matches ($@, 'Glib::File::Error', 'noent')) {
    change_source_dir_and_try_again ();
  } else {
    # ne sait pas comment gérer cela
    die $@;
  }
}

Cela a l'avantage supplémentaire de vous permettre de regrouper les choses comme vous le feriez avec un bloc try/throw/catch en C++ -- vous obtenez un code

plus propre. En utilisant les objets d'exception Glib::Error, vous n'avez pas à vous fier à la correspondance de chaînes sur un message d'erreur éven
tuellement localisé ; vous pouvez faire correspondre les erreurs par des conditions explicites et prévisibles. Voir Glib::Error pour plus d'informations.

Arguments de sortie listes,

hachages

En C, vous ne pouvez retourner qu'une seule valeur d'une fonction, et il est courant de modifier les pointeurs passés pour simuler le retour de plusieurs valeurs. En Perl, vous pouvez retourner des listes ; toute fonction qui modifie des arguments est modifiée pour les retourner à la

place.

Les arguments et les valeurs de retour qui ont les types GList ou GSList ou qui sont des t

ableaux C de valeurs seront convertis en et depuis des références vers des tableaux Perl n
ormaux. Il en va de même pour GHashTable et les références vers des hachages Perl normaux.

Fonctions de classe

d'objet

Les fonctions de classe d'objet comme "Gtk3::WidgetClass::find_style_propery" peuvent être appelées soit avec un nom de paquet, soit avec une instance du paquet. Par exemple

: 
Gtk3::WidgetClass::find_style_property ('Gtk3::Button', 'image-spacing')
my $button = Gtk3::Button->new;
Gtk3::WidgetClass::find_style_property ($button,
'image-spacing'
)

Redéfinition des fonctions

virtuelles

Lors de la sous-classification d'une classe gtk+ ou lors de la mise en œuvre d'une interface gtk+ avec Glib::Object::Subclass, vous pouvez redéfinir toutes les fonctions virtuelles que la classe a en définissant simplement des sous-routines avec des noms obtenus en capitalisant les noms originaux des fonctions virtuelles. Ainsi, par exemple, si vous mettez en œuvre une sous-classe personnalisée de "Gtk3::CellRenderer" et voulez redéfinir sa fonction virtuelle "render", vous fournissez une sous-routine avec le nom "RENDER" dans votre

paquet.

Redéfinition

s

Pour redéfinir le comportement d'une fonction ou d'une méthode spécifique, créez une sous-routine avec un nom approprié dans le bon paquet et faites-la appeler "Glib::Object::Introspection->invoke". Disons que vous voulez redéfinir "Gtk3::Window::list_toplevels", alors faites ceci

: 
sub Gtk3::Window::list_toplevels {
  # ...faire quelque chose...
  my $ref = Glib::Object::Introspection->invoke (
              'Gtk', 'Window', 'list_toplevels',
              @_);
  # ...faire quelque chose...
  return wantarray ? @$ref : $ref->[$#$ref];
}

Le nom et le paquet de la sous

-routine doivent être ceux ap
rès les corrections de noms.

Conversion d'une variable Perl en

GValue

Si vous devez marshaller dans un GValue, alors Glib::Object::Introspection ne peut pas le faire automatiquement car les informations de type sont manquantes. Si vous avez cependant ces informations dans votre module, vous pouvez utiliser Glib::Object::Introspection::GValueWrapper pour faire la conversion. Dans le wrapper pour une fonction qui attend un GValue, faites ceci

: 
...
my $type = ...; # obtenir d'une manière ou d'une autre le nom du paquet qui
                # correspond au bon GType
my $wrapper =
  Glib::Object::Introspection::GValueWrapper->new ($type, $value);
# maintenant utiliser Glib::Object::Introspection->invoke et
# substituer $wrapper là où vous utiliseriez $value
..
.
