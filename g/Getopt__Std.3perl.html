Getopt::Std(3perl) Guide du programmeur Perl Getopt::Std(3perl)

NOM

Getopt::Std - Traite les options à caractère unique avec regroupement d'options

SYNTAXE

use Getopt::Std;
getopts('oif:');  # -o & -i sont des drapeaux booléens, -f prend un argument
                  # Définit les variables globales $opt_* comme effet secondaire
getopts('oif:', \my %opts);  # Options comme ci-dessus, valeurs dans %opts
getopt('oDI');    # -o, -D & -I prennent des arguments
                  # Définit les variables globales $opt_* comme effet secondaire
getopt('oDI', \my %opts);    # -o, -D & -I prennent des arguments, valeurs dans %opts

DESCRIPTION

La fonction getopts() traite les options à caractère unique avec regroupement d'options. Passez un argument qui est une chaîne contenant toutes les options à reconnaître. Pour chaque option trouvée, si un argument est attendu et fourni, getopts() définit $opt_x (où "x" est le nom de l'option) à la valeur de l'argument. Si un argument est attendu mais qu'aucun n'est fourni, $opt_x est défini à une valeur indéfinie. Si une option ne prend pas d'argument, $opt_x est défini à 1.

Les options qui prennent un argument ne se soucient pas de savoir s'il y a un espace entre l'option et l'argument. Si des options non spécifiées sont trouvées sur la ligne de commande, l'utilisateur sera averti qu'une option inconnue a été donnée.

La fonction getopts() renvoie vrai sauf si une option invalide a été trouvée.

La fonction getopt() est similaire, mais son argument est une chaîne contenant toutes les options qui prennent un argument. Si aucun argument n'est fourni pour une option, disons, "y", le correspondant $opt_y sera défini à une valeur indéfinie. Les options non spécifiées sont acceptées silencieusement. L'utilisation de getopt() est fortement déconseillée.

Notez que si votre code s'exécute sous le pragma recommandé "use strict vars", vous devrez déclarer ces variables de paquet avec "our" :

our($opt_x, $opt_y);

Pour ceux d'entre vous qui n'aiment pas la création de variables globales supplémentaires, getopt() et getopts() accepteront également une référence de hachage comme argument optionnel. Les clés de hachage seront "x" (où "x" est le nom de l'option) avec des valeurs de clé la valeur de l'argument ou 1 si aucun argument n'est spécifié.

Pour permettre aux programmes de traiter des arguments qui ressemblent à des options, mais qui ne le sont pas, les deux fonctions arrêteront de traiter les options lorsqu'elles verront l'argument "--". Le "--" sera supprimé de @ARGV.

"--aide" et "--version"

Si "-" n'est pas une lettre d'option reconnue, getopts() prend en charge les arguments "--help" et "--version". Si main::HELP_MESSAGE() et/ou main::VERSION_MESSAGE() sont définis, ils sont appelés ; les arguments sont le descripteur de fichier de sortie, le nom du paquet de traitement des options, sa version et la chaîne des options. Si les sous-routines ne sont pas définies, une tentative est faite pour générer des messages intelligents ; pour de meilleurs résultats, définissez $main::VERSION.

Si une documentation intégrée (au format pod, voir perlpod) est détectée dans le script, "--help" montrera également comment accéder à la documentation.

Notez qu'en raison d'une paranoïa excessive, si $Getopt::Std::STANDARD_HELP_VERSION n'est pas vrai (le défaut est faux), alors les messages sont imprimés sur "STDERR", et le traitement continue après que les messages sont imprimés. Ceci étant l'opposé du comportement conforme aux normes, il est fortement recommandé de définir $Getopt::Std::STANDARD_HELP_VERSION à vrai.

On peut changer le descripteur de fichier de sortie des messages en définissant $Getopt::Std::OUTPUT_HELP_VERSION. On peut imprimer les messages de "--help" (sans la ligne "Usage:") et "--version" en appelant les fonctions help_mess() et version_mess() avec la chaîne des options comme argument.
