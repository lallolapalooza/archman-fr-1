NOM

Glib::Signal - Personnalisation d'objets et notification à usage général

DESCRIPTION

Cette page décrit quelques fonctions liées aux signaux dans Glib. Comme la plupart des choses que vous pouvez faire avec les signaux sont liées aux instances de Glib::Object, la majorité des fonctions de signal sont documentées là.

Sécurité des threads

Certaines bibliothèques, notamment GStreamer, invoquent parfois des gestionnaires de signaux à partir d'un thread étranger qui n'a pas d'interpréteur Perl associé. Lorsque cela se produit, nous n'avons pas d'autre choix que de confier la gestion à la boucle principale qui, à son tour, réveille plus tard le thread principal et le laisse gérer la requête. Nous ne pouvons pas invoquer le gestionnaire de signaux depuis le thread étranger car l'interpréteur Perl ne peut pas être utilisé simultanément.

L'inconvénient de cette approche est que le thread étranger est bloqué jusqu'à ce que le thread principal ait fini d'exécuter le gestionnaire de signaux. Cela peut entraîner des interblocages. Il peut être utile dans ce cas d'encapsuler les parties cruciales du gestionnaire de signaux dans un rappel Glib::Idle afin que le gestionnaire de signaux puisse retourner directement.

MÉTHODES

entier = Glib->install_exception_handler ($func, $data=undef)

  • $func (sous-routine)
  • $data (scalaire)

Installe une sous-routine à exécuter lorsqu'une émission de signal intercepte une exception (un croak ou un die). $func doit retourner un booléen (vrai si le gestionnaire doit rester installé) et s'attendre à recevoir un seul scalaire. Ce scalaire sera une copie privée de $@ que le gestionnaire peut modifier à sa guise.

Retourne un identifiant qui peut être utilisé avec "remove_exception_handler".

Voir gperl_install_exception_handler() dans Glib::xsapi.

Glib->remove_exception_handler ($tag)

•
$tag (entier)

Supprime le gestionnaire d'exceptions identifié par $tag, tel que retourné par "install_exception_handler". Si $tag ne peut être trouvé, ceci ne fait rien.

ATTENTION : N'appelez pas cette fonction depuis un gestionnaire d'exceptions. Si vous souhaitez supprimer votre gestionnaire pendant son exécution, faites-le simplement retourner faux.

Voir gperl_remove_exception_handler() dans Glib::xsapi.
