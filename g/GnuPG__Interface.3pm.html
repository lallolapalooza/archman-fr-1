GnuPG::Interface(3) Documentation Perl fournie par l'utilisateur GnuPG::Interface(3)

NOM

GnuPG::Interface - Interface Perl pour GnuPG

SYNTAXE

# Un exemple simple
use IO::Handle;
use GnuPG::Interface;
# mise en place de la situation
my $gnupg = GnuPG::Interface->new();
$gnupg->options->hash_init( armor   => 1,
                            homedir => '/home/foobar' );
# Notez que vous pouvez définir les destinataires même si vous ne chiffrez pas !
$gnupg->options->push_recipients( 'ftobin@cpan.org' );
$gnupg->options->meta_interactive( 0 );
# comment nous créons des poignées pour interagir avec GnuPG
my $input   = IO::Handle->new();
my $output  = IO::Handle->new();
my $handles = GnuPG::Handles->new( stdin  => $input,
                                   stdout => $output );
# Maintenant, nous allons procéder au chiffrement avec les options déjà définies
my @plaintext = ( 'foobar' );
my $pid = $gnupg->encrypt( handles => $handles );
# Maintenant, nous écrivons dans l'entrée de GnuPG
print $input @plaintext;
close $input;
# maintenant, nous lisons la sortie
my @ciphertext = <$output>;
close $output;
waitpid $pid, 0;

DESCRIPTION

GnuPG::Interface et ses modules associés sont conçus pour fournir une méthode orientée objet pour interagir avec GnuPG, en permettant d'effectuer des fonctions telles que, mais sans s'y limiter, le chiffrement, la signature, le déchiffrement, la vérification et l'analyse de listes de clés.

Comment les méthodes d'accesseur aux données membres sont créées

Chaque module de la suite GnuPG::Interface repose sur Moo pour générer les méthodes get/set utilisées pour définir les membres de données de l'objet. C'est très important à comprendre. Cela signifie que tout membre de données qui est une liste a des méthodes spéciales qui lui sont attribuées pour ajouter, retirer et vider la liste.

Comprendre la communication bidirectionnelle

Il est également impératif de comprendre que ce package utilise des méthodes de communication inter-processus similaires à celles utilisées dans IPC::Open3 et dans la section "Bidirectional Communication with Another Process" de perlipc, et que les utilisateurs de ce package doivent comprendre comment utiliser cette méthode car ce package n'abstrait pas grandement ces méthodes pour l'utilisateur. Ce package n'est pas conçu pour les abstraire entièrement (en partie pour des raisons de sécurité), mais plutôt pour simplement aider à créer des appels 'propres' et bien formés à GnuPG, et pour implémenter l'analyse des listes de clés. Veuillez vous référer à "Bidirectional Communication with Another Process" dans perlipc pour apprendre à gérer ces méthodes.

Utiliser ce package pour traiter des messages implique généralement la création d'un objet GnuPG::Interface, la création d'un objet GnuPG::Handles, la définition de certaines options dans son membre de données options, puis l'appel d'une méthode qui invoque GnuPG, telle que clearsign. On interagit ensuite avec les poignées de manière appropriée, comme décrit dans "Bidirectional Communication with Another Process" dans perlipc.

Versions de GnuPG

À partir de cette version de GnuPG::Interface, trois versions de GnuPG sont prises en charge : 1.4.x, 2.2.x et 2.4.x. La page de téléchargement de GnuPG https://gnupg.org/download/index.html contient des informations actualisées sur les versions actuellement prises en charge.

GnuPG a publié les versions 2.0 et 2.1 par le passé et certains systèmes de gestion de paquets peuvent encore les fournir si vous installez les paquets par défaut "gpg", "gnupg", "gnupg2", etc. Les versions 2.0 et 2.1 ne sont pas prises en charge, vous devrez donc peut-être trouver des dépôts de paquets supplémentaires ou compiler à partir des sources pour obtenir la version mise à jour.

Méthodes d'objet utilisant un objet GnuPG::Handles

verify( % )
import_keys( % )
export_keys( % )
recv_keys( % )
send_keys( % )
search_keys( % )
Ces méthodes correspondent directement ou sont très similaires à une commande GnuPG décrite dans gpg. Chacune de ces méthodes prend une table de hachage, qui doit actuellement contenir une clé handles dont la valeur est un objet GnuPG::Handles. Une autre clé optionnelle est command_args, qui doit avoir la valeur d'une référence de tableau ; ces arguments seront passés à GnuPG en tant qu'arguments de commande. Ces arguments de commande sont utilisés pour déterminer les clés à lister dans la méthode export_keys, par exemple. Veuillez noter que les arguments de commande GnuPG ne sont pas la même chose que les options GnuPG. Pour comprendre ce qui est une option et ce qui est un argument de commande, veuillez lire "COMMANDS" dans gpg et "OPTIONS" dans gpg.

Chacun de ces appels renvoie le PID du processus GnuPG résultant. On peut utiliser ce PID dans un appel "waitpid" au lieu d'un appel "wait" si un nettoyage plus précis du processus est nécessaire.

Ces méthodes attacheront les poignées spécifiées dans l'objet handles à l'objet GnuPG en cours d'exécution, afin qu'une communication bidirectionnelle puisse être établie. C'est-à-dire que les poignées stdin, stdout, stderr, status, logger, et passphrase définies optionnellement seront attachées respectivement à l'entrée, la sortie, l'erreur standard de GnuPG, la poignée créée en définissant status-fd, la poignée créée en définissant logger-fd, et la poignée créée en définissant passphrase-fd. Ce lien de poignées est similaire à ce qui est fait dans IPC::Open3.

Si vous souhaitez que le processus GnuPG lise ou écrive directement dans une poignée de fichier déjà ouverte, vous ne pouvez pas le faire via les mécanismes normaux d'IPC::Open3. Pour ce faire, définissez le membre de données handles approprié à la poignée de fichier déjà ouverte, puis définissez l'option direct à vrai pour cette poignée, comme décrit dans "options" dans GnuPG::Handles. FA

Q
Comment faire pour que GnuPG::Interface lise/écrive directement depuis un filehandle
?
Vous devez définir l'option direct de GnuPG::Handles à true pour les filehandles concernés. Voir « options » dans GnuPG::Handles et « Object Methods which use a GnuPG::Handles Object » pour plus
d'informations.
Pourquoi rendre si difficile l'accès à GnuPG pour qu'il écrive/lise depuis un filehandle ? Dans le shell, je peux simplement appeler GnuPG avec l'option --outfile
!
Il y a de nombreux problèmes lorsqu'on essaie de dire à GnuPG de lire/écrire directement depuis un fichier, comme si le fichier n'existe pas, ou s'il existe et que vous voulez l'écraser ! Que voulez-vous qu'il se passe alors ? Le fait que l'utilisateur de ce module gère ces questions à l'avance en ouvrant des filehandles pour GnuPG permet à l'utilisateur de savoir exactement ce qui va se passer dans ces circonstances, et rend le module moins sujet aux
erreurs.
Lorsque GnuPG traite un message volumineux, il reste parfois
bloqué.
Votre problème peut être dû à des questions de tampon (buffering) ; lorsque GnuPG lit/écrit dans des filehandles non directs (ceux qui sont envoyés vers des filehandles que vous lisez en mémoire
, et non ceux qui accèdent au disque), des problèmes
de tampon peuvent tout gâcher. Je recommande
de consulter « options » dans GnuPG::Handles.
