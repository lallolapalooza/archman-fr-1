RÉSUM

É

Ce module fournit un accès perl à GLib et aux bibliothèques GObject de GLib. GLib est une bibliothèque de portabilité et d'utilitaires ; GO

bject fournit un système de types générique avec héritage et un puissant système de signaux. Ensemble, ces bibliothèques sont utilisées com
me fondement pour de nombreuses bibliothèques qui composent l'environnement Gnome, et sont utilisées dans de nombreux projets sans rapport.

DESCRIPTIO

N

Cet emballage tente de fournir une interface perl tout en restant aussi fidèle que possible à l'API C sous-jacente, afin que toute documentation de référence que

vous pouvez trouver sur l'utilisation de GLib puisse encore s'appliquer à l'utilisation des bibliothèques depuis perl. Ce module fournit également des outils pou
r créer des emballages pour d'autres bibliothèques basées sur GObject. La section « VOIR AUSSI » contient des pointeurs vers toutes sortes d'informations utiles.

PERL CONTRE

C

GLib fournit aux programmes C bon nombre des mêmes fonctionnalités que Perl offre nativement. Lorsque la fonctionnalité de GLib chevauche celle de Perl, celle de Perl est privilégiée. Certains concepts ont été éliminés entièrement, car Perl est un langage de plus haut niveau que C. Dans d'autres cas, nous avons dû ajouter ou modifier des API pour qu'elles aient du sens en Perl. Voici un aperçu rapide

:

Perl le fait

déjà

Les types GLib GList (liste doublement chaînée), GSList (liste simplement chaînée), GHashTable, GArray, etc. ont tous été remplacés par des types de données Perl natifs. En fait, de nombreuses fonctions qui prennent des GList ou des tableaux acceptent simplement des liste

s sur la pile Perl. Dans la plupart des cas, les GIOChannels ne sont pas plus fonctionnels que les descripteurs de fichiers Perl, vous ne verrez donc aucun GIOChannel. Les GClosures ne sont pas visibles au niveau Perl, car les références de code Perl font la même chose. Pr
esque toute fonction prenant soit un pointeur de fonction C, soit un GClosure acceptera une référence de code en Perl. (En fait, vous pouvez probablement vous en tirer avec juste un nom de sous-programme à de nombreux endroits, à condition de ne pas utiliser strict subs.)

Ne vous en faites

pas

Certains concepts ont été éliminés ; vous n'avez jamais à vous soucier du comptage de références sur les GObjects ni à libérer les structures GBoxed.

Perl est un langage à ramasse-miettes, et nous avons beaucoup travaillé pour que les emballages s'occupent de la mémoire pour vous d'une manière qui s
emble naturelle à un développeur Perl. Vous ne verrez pas de GValues en Perl (ce n'est de toute façon qu'une structure C envieuse des scalaires Perl).

Oh, et nous avons créé un type GBoxed pour les scalaires Perl afin que vous puissiez utiliser des scalaires là où n'importe quel type boxed serait autorisé (par exemple les colonnes GtkTreeModel)

Les fonctions qui peuvent renvoyer faux et définir un GError en C lèvent une exception en Perl, en utilisant un objet d'exception basé sur le GError pour $@ ; voir Glib::Error. Attraper les exceptions dans les signaux est un problème délicat, elles ont donc leur propre section ; voir

EXCEPTIONS.

Les énumérations et les drapeaux sont traités comme des chaînes et des tableaux de chaînes, respectivement. GLib fournit un moyen d'enregistrer des surnoms pour les valeurs d'énumération, et les emballages Perl utilisent ces surnoms pour les vraies valeurs, afin que nous n'ayons jamais à traiter de nombres en Perl. Cela peut devenir un peu lourd pour les champs de bits, mais c'est très pratique quand vous oubliez une valeur de drapeau, car les emballages vous diront quelles valeurs sont acceptées lorsque vous passez quelque chose d'invalide. De plus, les emballages considèrent les caractères - et _ comme équivalents, afin que les noms de signaux et de propriétés puissent être correctement convertis en chaînes par l'opérateur =>. Par exemple, ce qui suit est équivalent

: 
# propriété foo-matic de type FooType, utilisant la
# valeur FOO_SOMETHING_COOL. son surnom serait
# 'something-cool'. vous pouvez utiliser soit le nom complet
# soit le surnom lorsque vous fournissez des valeurs à perl.
$object->set ('foo-matic', 'FOO_SOMETHING_COOL');
$object->set ('foo_matic', 'something_cool');
$object->set (foo_matic => 'something-cool')
;

Attention, Perl vous renverra toujours la forme du surnom, avec le

tiret.

Les drapeaux ont quelques capacités magiques supplémentaires sous la forme d'opérateurs surchargés

: 
+ ou |   union de deux ensembles de drapeaux ("add")
-        différence de deux ensembles de drapeaux ("sub", "remove")
* ou &   intersection de deux ensembles de bits ("and")
/ ou ^   différence symétrique ("xor", vous en aurez rarement besoin)
>=       opérateur de contenance ("l'ensemble de gauche est-il un surensemble de l'ensemble de droite ?")
==
égalité

De plus, les drapeaux en contexte booléen indiquent s'ils sont vides ou non, ce qui vous permet d'écrire des opérations courantes de manière naturelle

: 
$widget->set_events ($widget->get_events - "motion_notify_mask");
$widget->set_events ($widget->get_events - ["motion_notify_mask",
                                            "button_press_mask"]);
# touche Maj enfoncée (les deux fonctionnent, c'est une question de goût)
if ($event->state >= "shift-mask") { ...
if ($event->state * "shift-mask") { ...
# soit Maj SOIT Ctrl enfoncée ?
if ($event->state * ["shift-mask", "control-mask"]) { ...
# Maj ET Ctrl enfoncées ?
if ($event->state >= ["shift-mask", "control-mask"]) { ..
.

En général, "+" et "-" fonctionnent comme prévu pour ajouter ou supprimer des drapeaux. Pour tester si des bits sont définis dans un masque, vous utilisez "$mask * ...", et pour tester si tous les bits sont définis dans un masque, vous utilisez "$mask >=

...".

Lorsqu'il est déréférencé comme un tableau @$flags ou "$flags->[...]", vous pouvez accéder aux valeurs des drapeaux directement sous forme de chaînes (mais vous n'êtes pas autorisé à modifier le tableau), et lorsqu'il est converti en chaîne "$flags", une valeur de drapeaux produira un

NOMS DE FICHIERS, URIS ET

ENCODAGES

Perl connaît deux types de données, le texte unicode et les octets binaires. Les noms de fichiers sur un système qui n'utilise pas une locale utf-8 sont souvent stockés dans un encodage local ("octets binaires"). Gtk+ et ses descendants, cependant, travaillent en unicode la plupart du temps, donc lorsque vous fournissez un nom de fichier à une fonction GLib/Gtk+ qui attend un nom de fichier, vous devez d'abord le convertir de l'encodage local à

unicode.

Cela implique une certaine devinette élaborée, que perl évite actuellement, mais que GLib et Gtk+ font. Par exception, certaines fonctions Gtk+ veulent un nom de fichier en encodage local, mais l'interface perl contourne généralement cela en le convertissant automatiquement pour

vous.

En bref : Tout devrait être en unicode au niveau

perl.

EXCEPTION

S

Le langage C ne supporte pas les exceptions ; GLib est une bibliothèque C, et bien sûr ne supporte pas les exceptions non plus. En Perl, nous utilisons die et eval pour lever et attraper des exceptions, ce qui est une pratique plutôt courante. Donc, les bindings doivent faire un peu de magie noire en coulisses pour empêcher GLib d'exploser lorsque le programme Perl utilise des exceptions. Malheureusement, un peu de cette magie doit fuiter jusqu'à ce que vous puissiez la voir au niveau

Perl.

Les gestionnaires de signaux et d'événements sont exécutés dans un contexte eval ; si une exception se produit dans un tel gestionnaire et que vous ne l'attrapez pas, Perl signalera qu'une erreur s'est produite, puis continuera son travail comme si rien ne s'était

passé.

Vous pouvez enregistrer des sous-routines comme gestionnaires d'exceptions, pour être appelées lorsqu'une telle exception est attrapée. Une autre fonction les supprime pour

vous. 
$tag = Glib->install_exception_handler (\&my_handler);
Glib->remove_exception_handler ($tag)
;

Le gestionnaire d'exceptions recevra une copie fraîche du $@ de l'exception fautive sur la pile d'arguments, et doit retourner une valeur non nulle si le gestionnaire doit rester installé. S'il retourne faux, le gestionnaire sera

supprimé. 
sub my_handler {
    if ($_[0] =~ m/ftang quisinart/) {
         clean_up_after_ftang ();
    }
    1; # vivre pour se battre un autre jour
}

Vous pouvez enregistrer autant de gestionnaires que vous le souhaitez ; ils s'exécuteront tous

indépendamment.

Une chose importante à retenir est que les exceptions ne traversent pas les boucles principales. En fait, les exceptions sont complètement dis

tinctes des boucles principales. Si vous devez quitter une boucle principale lorsqu'une exception se produit, installez un gestionnaire qui qu
itte la boucle principale, mais demandez-vous aussi si vous utilisez les exceptions pour le contrôle de flux ou pour le traitement des exceptions.

ENTIERS SUR 64

BITS

Puisque le type de données entier de perl ne peut contenir que des valeurs sur 32 bits sur toutes les machines 32 bits et même sur certaines machines 64 bits, Glib convertit les entiers sur 64 bits vers et depuis des chaînes si nécessaire. Ces chaînes peuvent ensuite être utilisées pour alimenter l'un des divers modules d'entiers de grande taille. Assurez-vous de ne pas laisser vos chaînes entrer dans un contexte numérique avant de les passer à une fonction Glib, car dans ce cas, perl convertira le nombre en notation scientifique que, à ce stade, n'est pas comprise par les convertisseurs de

GLib.

Voici un aperçu des modules d'entiers de grande taille disponibles. Tout d'abord, il y a Math::BigInt. Il a tout ce dont vous aurez jamais besoin, mais son implémentation pure Perl est aussi plutôt lente. Il existe cependant plusieurs moyens de contourner

cela.
Math::BigInt::
FastCalc
Math::BigInt::FastCalc peut aider à éviter la vitesse glaciaire de Math::BigInt::Calc standard. Les versions récentes de Math::BigInt utiliseront automatiquement Math::BigInt::FastCalc à la place de Math::BigInt::Calc lorsqu'il est disponible. D'autres options incluent Math::BigInt::GMP ou Math::BigInt::Pari, qui ont cependant des dépendances beaucoup plus
importantes.
Math::BigInt::
Lite
Ensuite, il y a Math::BigInt::Lite, qui utilise les opérations natives sur les entiers Perl tant que les entiers Perl ont une plage suffisante, et se met à niveau vers Math::BigInt lorsque les entiers Perl déborderaient. Cela doit être utilisé à la place de Math::
