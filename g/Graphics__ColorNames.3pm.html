Graphics::ColorNames(3) Documentation Perl contribuée par les utilisateurs Graphics::ColorNames(3)

NOM

Graphics::ColorNames - définit les valeurs RGB pour les noms de couleurs courants

VERSION

version v3.5.0

SYNOPSIS

use Graphics::ColorNames;
use Graphics::ColorNames::WWW;
$pal = Graphics::ColorNames->new( qw[ X WWW ] );
$rgb = $pal->hex('green');          # renvoie '00ff00'
$rgb = $pal->hex('green', '0x');    # renvoie '0x00ff00'
$rgb = $pal->hex('green', '#');     # renvoie '#00ff00'
$rgb = $pal->rgb('green');          # renvoie '0,255,0'
@rgb = $pal->rgb('green');          # renvoie (0, 255, 0)

DESCRIPTION

Ce module fournit une interface commune pour obtenir les valeurs RGB des couleurs par leurs noms standard. L'intention est de (1) fournir un module commun que les auteurs peuvent utiliser avec d'autres modules pour spécifier des couleurs par leur nom ; et (2) libérer les auteurs de modules de la nécessité de « réinventer la roue » chaque fois qu'ils décident de donner aux utilisateurs l'option de spécifier une couleur par son nom plutôt que par sa valeur RGB.

MÉTHODES

"new"

Le constructeur est le suivant :

my $pal = Graphics::ColorNames->new( @schemes );

où @schemes est un tableau de schémas de couleurs (palettes, dictionnaires).

Un schéma de couleurs valide peut être le nom d'un schéma de couleurs (tel que "X" ou un nom de module complet tel que "Graphics::ColorNames::X"), une référence vers un hash ou une sous-routine de schéma de couleurs, ou vers le chemin ou le descripteur de fichier ouvert pour un fichier rgb.txt .

Si aucun n'est spécifié, il utilise le schéma de couleurs par défaut "X" , qui correspond aux couleurs X-Windows rgb.txt . Pour la plupart des usages, c'est suffisant. Depuis la version 3.2.0, il a été mis à jour pour utiliser les couleurs du 2014-07-06, incluant donc aussi les couleurs CSS standard.

D'autres schémas de couleurs sont disponibles sur CPAN, par exemple Graphics::ColorNames::WWW.

Depuis la version 2.1002, les dictionnaires Color::Library peuvent également être utilisés :

my $pal = Graphics::ColorNames->new( 'Color::Library::Dictionary::HTML' );

"rgb"

@rgb = $pal->rgb($name);
$rgb = $pal->rgb($name, $separator);

Si appelé dans un contexte de liste, renvoie un triplet.

Si appelé dans un contexte scalaire, renvoie une chaîne séparée par un séparateur optionnel (qui vaut par défaut une virgule). Par exemple,

@rgb = $pal->rgb('blue');      # renvoie (0, 0, 255)
$rgb = $pal->rgb('blue', ','); # renvoie "0,0,255"

Les noms de couleurs inconnus renvoient des listes ou des chaînes vides, selon le contexte.

Les noms de couleurs ne sont pas sensibles à la casse, et les espaces ou la ponctuation sont ignorés. Ainsi "Alice Blue" renvoie la même valeur que "aliceblue", "ALICE-BLUE" et "a*lICEbl-ue". (Si vous utilisez des noms de couleurs basés sur une saisie utilisateur, vous devriez ajouter une validation supplémentaire des noms de couleurs.)

La valeur renvoyée est au format hexadécimal à six chiffres utilisé en HTML et CSS (sans le '#' initial). Pour la convertir en valeurs séparées de rouge, vert et bleu (entre 0 et 255), utilisez la fonction "hex2tuple".

Vous pouvez également spécifier un nom de fichier absolu comme schéma de couleurs, si le fichier est au même format que le fichier standard rgb.txt .

"hex"

$hex = $pal->hex($name, $prefix);

Renvoie un code RGB hexadécimal à 6 chiffres pour la couleur. Si un préfixe optionnel est spécifié, il préfixera le code avec cette chaîne. Par exemple,

$hex = $pal->hex('blue', '#'); # renvoie "#0000ff"

Si la couleur n'existe pas, il renverra une chaîne vide.

Une valeur RGB hexadécimale de la forme "#RRGGBB", "0xRRGGBB" ou "RRGGBB" renverra la valeur elle-même :

$color = $pal->hex('#123abc');         # renvoie '123abc'

méthodes de nom de couleur chargées automatiquement

Les méthodes de nom de couleur chargées automatiquement ont été supprimées en v3.4.0.

"load_scheme"

$pal->load_scheme( $scheme );

Cela charge dynamiquement un schéma de couleurs, qui peut être soit une référence vers un hash, soit une référence vers du code.

EXPORTS

"all_schemes"

my @schemes = all_schemes();

Renvoie une liste de tous les schémas de couleurs disponibles installés sur la machine dans l'espace de noms Graphics::ColorNames .

L'ordre n'a aucune signification.

"hex2tuple"

Convertit une chaîne hexadécimale en un tuple.

"tuple2hex"

Convertit un tuple en une chaîne hexadécimale.

INTERFACE LIÉE

L'interface standard (avant la version 0.40) se faisait via un hash lié :

tie %pal, 'Graphics::ColorNames', qw[ X WWW ];

Cette interface est dépréciée et sera déplacée vers un module séparé dans le futur.

SCHÉMAS DE COULEURS PERSONNALISÉS

Vous pouvez ajouter des fichiers de schéma de noms en créant un module Perl dont le nom est "Graphics::ColorNames::SCHEMENAME" qui a une sous-routine nommée "NamesRgbTable" qui renvoie un hash de noms de couleurs et de valeurs RGB. (Les schémas avec un espace de noms de base différent nécessiteront que l'espace de noms complet soit donné.)

Les noms de couleurs doivent être en minuscules, et les valeurs RGB doivent être des nombres sur 24 bits contenant les valeurs de rouge, vert et bleu dans l'ordre du byte le plus significatif au moins significatif.

Un exemple de schéma de noms est ci-dessous :

package Graphics::ColorNames::Metallic;
sub NamesRgbTable() {
  use integer;
  return {
    copper => 0xb87333,
    gold   => 0xcd7f32,
    silver => 0xe6e8fa,
  };
}

Vous utiliseriez le schéma ci-dessus comme suit :

tie %colors, 'Graphics::ColorNames', 'Metallic';

Le comportement de la spécification de plusieurs clés avec le même nom est indéterminé quant à laquelle prend le dessus.

Depuis la version 2.10, la casse, les espaces et la ponctuation sont ignorés dans les noms de couleurs. Ainsi un nom comme "Willy's Favorite Shade-of-Blue" est traité de la même manière que "willysfavoroteshadeofblue". (Si votre schéma n'inclut pas d'entrées en double avec espaces et ponctuation, alors la version minimale de Graphics::ColorNames devrait être 2.10 dans vos exigences.)

Un exemple de module supplémentaire est le module Graphics::ColorNames::Mozilla.

Depuis la version 1.03, "NamesRgbTable" peut également renvoyer une référence vers du code :

package Graphics::ColorNames::Orange;
sub NamesRgbTable() {
  return sub {
    my $name = shift;
    return 0xffa500;
  };
}

Voir Graphics::ColorNames::GrayScale pour un exemple.

FEUILLE DE ROUTE

Les changements suivants sont prévus pour le futur :

  • L'interface liée sera supprimée, mais implémentée dans un module séparé pour les utilisateurs qui souhaitent l'utiliser.
  • L'espace de noms pour les schémas de couleurs sera déplacé vers "Graphics::ColorNames::Schemes" mais des options seront ajoutées pour utiliser le schéma existant.

    Cela permettra de nommer des modules comme "Graphics::ColorNames::Tied" sans être confondu avec des schémas de couleurs.

  • Ce module sera réécrit pour être une classe basée sur Moo.

VOIR AUSSI

Color::Library fournit une bibliothèque étendue de schémas de couleurs. Une différence notable est qu'elle prend en charge des schémas plus complexes qui contiennent des informations supplémentaires sur les couleurs individuelles et associent plusieurs couleurs à un seul nom.

Color::Rgb a une fonction similaire à celle de ce module, mais analyse un fichier rgb.txt.

Graphics::ColorObject peut convertir entre RGB et d'autres types d'espaces colorimétriques.

Graphics::ColorUtils peut également convertir entre RGB et d'autres types d'espaces colorimétriques, et prend en charge le RGB à partir de noms dans divers schémas de couleurs.

Acme::AutoColor fournit des sous-routines correspondant aux noms de couleurs.
