N

Les opérations ioctl(2) suivantes, spécifiques à Linux, sont prises en charge pour les terminaux console et les consoles virtuelles. ioctl(2) operations are supported for console terminals and virtual consoles.

KDSETL
ED
Définir les LED. Les LED sont définies pour correspondre aux trois bits de poids faible de l'entier unsigned long dans argp. Cependant, si un bit de poids fort est défini, les LED reprennent leur comportement normal : afficher l
'état des fonctions clavier verrouillage majuscules
, verrouillage numérique et verrouillage défilement.

Avant Linux 1.1.54, les LED reflétaient simplement l'état des indicateurs de clavier correspondants, et KDGETLED/KDSETLED changeaient également les indicateurs de clavier. Depuis Linux 1.1.54, les LED peuvent afficher des informations arbitraires, mais par défaut elles affichent les indicateurs de clavier. Les deux ioctls suivants sont utilisés pour accéder aux indicateurs de

clavier.
KDGKBL
ED
Obtenir les indicateurs de clavier CapsLock, NumLock, ScrollLock (pas les lumières). argp pointe vers un char qui est défini à l'état des indicateurs. Les trois bits de poids faible (masque 0x7) contiennent l'état actuel des indicateurs, et les bits de poids faible du nibble suivant (masque 0x70) contiennent l'état par défaut des indicateurs. (Depuis Linux 1.1.
54.)
KDSKBL
ED
Définir les indicateurs de clavier CapsLock, NumLock, ScrollLock (pas les lumières). argp est un entier unsigned long contenant l'état d'indicateur souhaité. Les trois bits de poids faible (masque 0x7) contiennent l'état des indicateurs, et les bits de poids faible du nibble suivant (masque 0x70) contiennent l'état par défaut des indicateurs. (Depuis Linux 1.1.
54.)

KDMKTO
NE
Générer un ton de durée spécifiée. Les 16 bits de poids faible de l'entier unsigned long dans argp spécifient la période en cycles d'horloge, et les 16 bits de poids fort donnent la durée en msec. Si la durée est zéro, le son est coupé. Le contrôle revient immédiatement. Par exemple, argp = (125<<16) + 0x637 spécifierait le bip normalement associé à un ctrl-G. (Ainsi, depuis Linux 0.99pl1 ; cassé dans Linux 2.1.49-50.
)
KIOCSOU
ND
Démarrer ou arrêter la génération de son. Les 16 bits de poids faible de argp spécifient la période en cycles d'horloge (c'est-à-dire argp = 1193180/fréquence). argp = 0 coupe le son. Dans les deux cas, le contrôle revient
immédiatement.
GIO_CM
AP
Obtenir la table de couleurs par défaut actuelle du noyau. argp pointe vers un tableau de 48 octets. (Depuis Linux 1.3.
3.)
PIO_CM
AP
Modifier la table de couleurs par défaut en mode texte. argp pointe vers un tableau de 48 octets contenant, dans l'ordre, les valeurs Rouge, Vert et Bleu pour les 16 couleurs d'écran disponibles : 0 est éteint, et 255 est l'intensité maximale. Les couleurs par défaut sont, dans l'ordre : noir, rouge foncé, vert foncé, brun, bleu foncé, violet foncé, cyan foncé, gris clair, gris foncé, rouge vif, vert vif, jaune, bleu vif, violet vif, cyan vif et blanc. (Depuis Linux 1.3.
3.)
GIO_FO
NT
Récupère la police d'écran de 256 caractères sous forme étendue. argp pointe vers un tableau de 8192 octets. Échoue avec le code d'erreur EINVAL si la police actuellement chargée est une police de 512 caractères, ou si la console n'est pas en mode
texte.
GIO_FON
TX
Récupère la police d'écran et les informations associées. argp pointe vers une struct consolefontdesc (voir PIO_FONTX). À l'appel, le champ charcount devrait être défini au nombre maximal de caractères qui tiendrait dans le buffer pointé par chardata. Au retour, les champs charcount et charheight sont remplis avec les données respectives pour la police actuellement chargée, et le tableau chardata contient les données de la police si la valeur initiale de charcount indiquait qu'il y avait suffisamment d'espace ; sinon, le buffer reste intact et errno est défini à ENOMEM. (Depuis Linux 1.3.
1.)
PIO_FO
NT
Définit la police d'écran de 256 caractères. Charge la police dans le générateur de caractères EGA/VGA. argp pointe vers une table de 8192 octets, avec 32 octets par caractère. Seuls les premiers N d'entre eux sont utilisés pour une police 8xN (0 < N <= 32). Cet appel invalide également le mappage
Unicode.

GIO_SCRNM
AP
Obtenir le mappage d'écran du noyau. argp pointe vers une zone de taille E_TABSZ, qui est chargée avec les positions de police utilisées pour afficher chaque caractère. Cet appel est susceptible de renvoyer des informations inutiles si la police actuellement chargée a plus de 256
caractères.
GIO_UNISCRNM
AP
Obtenir le mappage d'écran Unicode complet du noyau. argp pointe vers une zone de taille E_TABSZ*sizeof(unsigned short), qui est chargée avec les Unicodes que chaque caractère représente. Un ensemble spécial d'Unicodes, commençant à U+F000, est utilisé pour représenter les mappages "direct vers la police". (Depuis Linux 1.3.
1.)

E_TABSZ. ISCRNMAP">PIO_UNISCRNMAP

Des Unicodes spéciaux commençant à U+F000 peuvent être utilisés pour faire correspondre directement aux symboles de la police. (Depuis Linux 1.
