NOM

GooCanvas2::CairoTypes - Pont entre GooCanvas2 et les types Cairo

SYNOPSIS

use GooCanvas2;
use GooCanvas2::CairoTypes;
my $pattern = Cairo::SolidPattern->create_rgba(0, 0, 0, 0);
my $rect = GooCanvas2::CanvasRect->new(
        ...,
        'fill-pattern' => $pattern,  # échoue sans CairoTypes, fonctionne juste avec
);
# Parfois (mais pas toujours, aucune idée pourquoi) cela échoue :
$rect->get('fill-pattern')->set_filter('linear);
# Voici la solution :
GooCanvas2::CairoTypes::cairoize_pattern($rect->get('fill-pattern'))
        ->set_filter('linear);

DESCRIPTION

Il existe un problème dans l'interaction entre GooCanvas, GObject Introspection, Cairo et leurs liaisons Perl, qui rend certaines fonctionnalités inutilisables du côté Perl. Ceci est mieux décrit ici https://stackoverflow.com/questions/64625955/cairosolidpattern-is-not-of-type-goocanvas2cairopattern, et une tentative https://gitlab.gnome.org/GNOME/goocanvas/-/merge_requests/9 a été faite pour la corriger en amont. Jusqu'à ce qu'elle soit corrigée, cela peut servir de solution de contournement.

Actuellement, ce module ne fait que « corriger » l'interopérabilité de "Cairo::Pattern/GooCanvas2::CairoPattern". Pour certains appels, cela fonctionne simplement si ce module a été inclus ; pour d'autres appels, vous devez explicitement convertir le type.

Si vous avez une idée sur la façon de corriger ces cas pour qu'ils ne nécessitent pas un tel appel, ou si vous avez besoin de faire le pont entre plus de types, les requêtes de fusion https://github.com/DarthGandalf/GooCanvas2-CairoTypes sont les bienvenues !
