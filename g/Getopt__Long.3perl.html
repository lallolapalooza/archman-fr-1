DESCRIPTIO

N

Le module Getopt::Long implémente une fonction getopt étendue appelée GetOptions(). Elle analyse la ligne de commande depuis @ARGV, reconnaît et supprime les options spécifiées et leurs valeurs

possibles.

Cette fonction respecte la syntaxe POSIX pour les options de ligne de commande, avec des extensions GNU. En général, cela signifie que les opti

ons ont des noms longs au lieu de lettres uniques, et sont introduites par un double tiret "--". Le support pour le regroupement des options d
e ligne de commande, comme c'était le cas avec l'approche plus traditionnelle des lettres uniques, est fourni mais n'est pas activé par défaut.

Options de Ligne de Commande, une

Introduction

Les programmes opérés par ligne de commande prennent traditionnellement leurs arguments de la ligne de commande, par exemple des noms de fichiers ou d'autres informations dont le programme a besoin. En plus des arguments, ces programmes prennent souvent des options de ligne de commande. Les options ne sont pas nécessaires pour que le programme fonctionne, d'où le nom 'option', mais elles sont utilisées pour modifier son comportement par défaut. Par exemple, un programme pourrait faire son travail silencieusement, mais avec une option appropriée, il pourrait fournir des informations détaillées sur ce qu'il a

fait.

Les options de ligne de commande viennent en plusieurs formes. Historiquement, elles sont précédées d'un tiret unique "-", et consistent en une seule

lettre. 
-l -a
-c

Habituellement, ces options à caractère unique peuvent être regroupées

: 
-la
c

Les options peuvent avoir des valeurs, la valeur est placée après le caractère de l'option. Parfois avec un espace blanc entre les deux, parfois non

: 
-s 24
-s24

En raison de la nature très cryptique de ces options, un autre style a été développé qui utilisait des noms longs. Ainsi, au lieu d'un cryptique "-l", on pouvait utiliser le plus descriptif "--long". Pour distinguer un regroupement d'options à caractère unique d'une option longue, deux tirets sont utilisés pour précéder le nom de l'option. Les premières implémentations des options longues utilisaient un plus "+" à la place. De plus, les valeurs d'options pouvaient être spécifiées soit

comme 
--size=2
4

soi

t 
--size
24

La forme "+" est maintenant obsolète e

t fortement
déconseillée.

Prise en Main de Getopt::

Long

Getopt::Long est le successeur Perl5 de "newgetopt.pl". C'était le premier module Perl qui fournissait le support pour la gestion du nouveau style d'options de ligne de commande, en particulier les noms d'options longs, d'où le nom Perl5 Getopt::Long. Ce module supporte également les options à caractère unique et le

regroupement.

Pour utiliser Getopt::Long depuis un programme Perl, vous devez inclure la ligne suivante dans votre programme Perl

: 
use Getopt::
Long;

Cela chargera le noyau du module Getopt::Long et préparera votre programme pour l'utiliser. La plupart du code réel de Getopt::Long n'est pas chargé jusqu'à ce que vous appeliez réellement l'une de ses

fonctions.

Dans la configuration par défaut, les noms d'options peuvent être abrégés jusqu'à ce qu'ils soient uniques, la casse n'a pas d'importance, et un tiret unique est suffisant, même pour les noms d'options longues. De plus, les options peuvent être placées entre des arguments non-options. Voir "Configuring Getopt::Long" pour plus de détails sur la façon de configurer Getopt::

Long.

Options

Simples

Les options les plus simples sont celles qui ne prennent aucune valeur. Leur simple présence sur la ligne de commande active l'option. Des exemples populaires sont

: 
--all --verbose --quiet
--debug

Gérer les options simples est simple

: 
my $verbose = '';   # variable d'option avec valeur par défaut (faux)
my $all = '';       # variable d'option avec valeur par défaut (faux)
GetOptions ('verbose' => \$verbose, 'all' => \$all)
;

L'appel à GetOptions() analyse les arguments de la ligne de commande présents dans @ARGV et définit la variable d'option à la valeur 1 si l'option est apparue sur la ligne de commande. Sinon, la variable d'option n'est pas touchée. Définir la valeur de l'option à vrai est souvent appelé activer l'o

ption.

Le nom d'option tel que spécifié à la fonction GetOptions() est appelé la spécification d' option. Plus tard, nous verrons que cette spécification peut contenir plus que simplement le nom de l'option. La référence à la variable est appelée la destination de l'opti

on.

GetOptions() renverra une valeur vraie si la ligne de commande a pu être traitée avec succès. Sinon, elle écrira des messages d'erreur en utilisant die() et warn(), et renverr

a un résul
tat faux.

Des Options Un Peu Moins

Simples

Getopt::Long supporte deux variantes utiles des options simples : les options négables et les options incré

mentales.

Une option négable est spécifiée avec un point d'exclamation "!" après le nom de l'option

: 
my $verbose = '';   # variable d'option avec valeur par défaut (faux)
GetOptions ('verbose!' => \$verbose)
;

Maintenant, l'utilisation de "--verbose" sur la ligne de commande activera $verbose, comme prévu. Mais il est également permis d'utiliser "--noverbose", ce qui désactivera $verbose en définissant sa valeur à 0. En utilisant une valeur par défaut appropriée, le programme peut savoir si $verbose est faux par défaut, ou désactivé en utilisant "--noverbose"

.

(Si à la fois "--verbose" et "--noverbose" sont donnés, celui qui est donné en dernier prend le dessus.

)

Une option incrémentale est spécifiée avec un plus "+" après le nom de l'option

: 
my $verbose = '';   # variable d'option avec valeur par défaut (faux)
GetOptions ('verbose+' => \$verbose)
;

L'utilisation de "--verbose" sur la ligne de commande incrémentera la valeur de $verbose. De cette façon, le programme peut garder une trace du nombre de fois où l'option est apparue sur la ligne de commande. Par exemple, chaque occurrence de "--verbose" pourrait augmenter le ni

Mélanger les Options de Ligne de Commande avec d'Autres

Arguments

Habituellement, les programmes prennent des options de ligne de commande ainsi que d'autres arguments, par exemple des noms de fichiers. Il est de bonne pratique de toujours spécifier les options en premier, et les autres arguments en dernier. Getopt::Long permettra cependant que les options et les arguments soient mélangés, et 'filtrera' toutes les options avant de passer le reste des arguments au programme. Pour arrêter Getopt::Long de traiter plus d'arguments, insérez un double tiret "--" sur la ligne de commande

: 
--size 24 --
--all

Dans cet exemple, "--all" ne sera pas traité comme une option, mais passé au programme intact, dans @AR

Options avec

Valeurs

Pour les options qui prennent des valeurs, il doit être spécifié si la valeur de l'option est requise ou non, et quel type de valeur l'option

attend.

Trois types de valeurs sont supportés : les nombres entiers, les nombres à virgule flottante et les chaînes de

caractères.

Si la valeur de l'option est requise, Getopt::Long prendra l'argument de la ligne de commande qui suit l'option et l'assignera à la variable d'option. Si, cependant, la valeur de l'option est spécifiée comme optionnelle, cela ne sera fait que si cette valeur ne ressemble pas à une option de ligne de commande valide

elle-même. 
my $tag = '';       # variable d'option variable with default value
GetOptions ('tag=s' => \$tag)
;

Dans la spécification d'option, le nom de l'option est suivi d'un signe égal "=" et de la lettre "s". Le signe égal indique que cette option nécessite une valeur. La lettre "s" indique que cette valeur est une chaîne arbitraire. Les autres types de valeurs possibles sont "i" pour les valeurs entières, et "f" pour les valeurs en virgule flottante. L'utilisation d'un deux-points ":" à la place du signe égal indique que la valeur de l'option est facultative. Dans ce cas, si aucune valeur appropriée n'est fournie, les options de type chaîne reçoivent une chaîne vide '' assignée, tandis que les options numériques sont définies à 0

.

(Si la même option apparaît plus d'une fois sur la ligne de

commande, la dernière valeur fournie est utilisée. Si vou
s souhaitez prendre toutes les valeurs, voir ci-dessous.)

Options avec plusieurs

valeurs

Les options prennent parfois plusieurs valeurs. Par exemple, un programme pourrait utiliser plusieurs répertoires pour rechercher des fichiers de bibliothèque

: 
--library lib/stdlib --library
lib/extlib

Pour obtenir ce comportement, indiquez simplement une référence de tableau comme destination pour l'option

: 
GetOptions ("library=s" => \@libfiles)
;

Alternativement, vous pouvez indiquer que l'option peut avoir plusieurs valeurs en ajoutant un "@", et passer une référence à un scalaire comme destination

: 
GetOptions ("library=s@" => \$libfiles)
;

Utilisé avec l'exemple ci-dessus, @libfiles c.q. @$libfiles contiendrait deux chaînes à la fin de l'exécution : "lib/stdlib" et "lib/extlib", dans cet ordre. Il est également possible d'indiquer que seuls les nombres entiers ou en virgule flottante sont des valeurs

acceptables.

Il est souvent utile d'autoriser des listes de valeurs séparées par des virgules ainsi que des occurrences multiples des options. Cela est facile à faire avec les opérateurs Perl split() et join()

: 
GetOptions ("library=s" => \@libfiles);
@libfiles = split(/,/,join(',',@libfiles))
;

Bien sûr, il est important de choisir la chaîne séparatrice appropriée pour chaque

objectif.

Avertissement : ce qui suit est une fonctionnalité

expérimentale.

Les options peuvent prendre plusieurs valeurs à la fois, par

--coordinates 52.2 16.4 --rgbcolor 255 255

Cela peut être accompli en ajoutant un spécificateur de répétition à la spécification de l'option. Les spécificateurs de répétition sont très similaires aux spécificateurs "{...}" de répétition qui peuvent être utilisés avec des motifs d'expression régulière. Par exemple, la ligne de commande ci-dessus serait traitée comme suit

GetOptions('coordinates=f{2}' => \@coor, 'rgbcolor=i{3}' => \@color)

La destination de l'option doit être un tableau ou une référence de

tableau.

Il est également possible d'indiquer le nombre minimal et maximal d'arguments qu'une option prend. "foo=s{2,4}" indique une option qui prend au moins deux et au plus 4 arguments. "foo=s{1,}" indique une ou plusieurs valeurs ; "foo:s{,}" indique zéro ou pl

usieurs valeurs

Sous-routines définies par l'utilisateur pour traiter les

options

Le contrôle ultime sur ce qui doit être fait lorsque (en fait : chaque fois) une option est rencontrée sur la ligne de commande peut être obtenu en désignant une référence à une sous-routine (ou une sous-routine anonyme) comme destination de l'option. Lorsque GetOptions() rencontre l'option, il appellera la sous-routine avec deux ou trois arguments. Le premier argument est le nom de l'option. (En fait, c'est un objet qui se convertit en chaîne en le nom de l'option.) Pour une destination scalaire ou tableau, le deuxième argument est la valeur à stocker. Pour une destination hachage, le deuxième argument est la clé du hachage, et le troisième argument la valeur à stocker. Il appartient à la sous-routine de stocker la valeur, ou de faire ce qu'elle juge

approprié.

Une application triviale de ce mécanisme est d'implémenter des options qui sont liées les unes aux autres. Par exemple

: 
my $verbose = '';   # option variable with default value (false)
GetOptions ('verbose' => \$verbose,
            'quiet'   => sub { $verbose = 0 })
;

Ici "--verbose" et "--quiet" contrôlent la même variable $verbose, mais avec des valeurs

opposées.

Si la sous-routine doit signaler une erreur, elle doit appeler die() avec le message d'erreur souhaité comme argument. GetOptions() interceptera le die(), émettra le message d'erreur, et enregistrera qu'un résultat d'erreur doit être retourné à la fin de

l'exécution.

Si le texte du message d'erreur commence par un point d'exclamation "!", il est interprété spécialement par GetOptions(). Il y a actuellement une commande spéciale implémentée : die("!FINISH") fera que GetOptions() arrête le traitement des options, comme s'il avait rencontré un double tiret "--"

.

Voici un exemple de la manière d'accéder au nom et à la valeur de l'option depuis l'intérieur d'une sous-routine

: 
GetOptions ('opt=i' => \&handler);
sub handler {
    my ($opt_name, $opt_value) = @_;
    print("Option name is $opt_name and value is $opt_value\n");
}

Analyse des options à partir d'un tableau

arbitraire

Par défaut, GetOptions analyse les options présentes dans le tableau global @ARGV. Une entrée spéciale "GetOptionsFromArray" peut être utilisée pour analyser les options à partir d'un tableau

arbitraire. 
use Getopt::Long qw(GetOptionsFromArray);
$ret = GetOptionsFromArray(\@myopts, ...)
;

Utilisé de cette manière, les options et leurs valeurs possibles sont retirées de @myopts, le global @ARGV n'est pas touché du

tout.

Les deux appels suivants se comportent de manière identique

: 
$ret = GetOptions( ... );
$ret = GetOptionsFromArray(\@ARGV, ... )
;

Cela signifie également qu'une référence de hash en premier argument devient maintenant le deuxième argument

: 
$ret = GetOptions(\%opts, ... );
$ret = GetOptionsFromArray(\@ARGV, \%opts, ...
)
;

Analyse des options à partir d'une chaîne

arbitraire

Une entrée spéciale "GetOptionsFromString" peut être utilisée pour analyser les options à partir d'une chaîne

arbitraire. 
use Getopt::Long qw(GetOptionsFromString);
$ret = GetOptionsFromString($string, ...)
;

Le contenu de la chaîne est divisé en arguments à l'aide d'un appel à "Text::ParseWords::shellwords". Comme avec "GetOptionsFromArray", le global @ARGV n'est pas

touché.

Il est possible qu'à la fin, tous les arguments de la chaîne n'aient pas été traités. "GetOptionsFromString" renverra, lorsqu'il est appelé en contexte liste, à la fois le statut de retour et une référence de tableau vers les arguments restants

: 
($ret, $args) = GetOptionsFromString($string, ... )
;

S'il reste des arguments, et que "GetOptionsFromString" n'a pas été appelé en contexte liste, un message sera donné et "GetOptionsFromString" renverra un

échec.

Comme avec GetOptionsFromArray, une référence de

hash en premier argument devient maintenant
le deuxième argument. Voir la section suivante.

Stockage des valeurs d'options dans un

hash

Parfois, par exemple lorsqu'il y a beaucoup d'options, avoir une variable distincte pour chacune d'elles peut être fastidieux. GetOptions() prend en charge, comme mécanisme alternatif, le stockage des valeurs d'options dans un

hash.

Pour obtenir cela, une référence vers un hash doit être passée comme premier argument à GetOptions(). Pour chaque option spécifiée sur la ligne de commande, la valeur de l'option sera stockée dans le hash avec le nom de l'option comme clé. Les options qui ne sont pas réellement utilisées sur la ligne de commande ne seront pas mises dans le hash, en d'autres termes, exists($h{option}) (ou defined()) peut être utilisé pour tester si une option a été utilisée. L'inconvénient est que des avertissements seront émis si le programme s'exécute sous "use strict" et utilise $h{option} sans tester avec exists() ou defined() d'

abord. 
my %h = ();
GetOptions (\%h, 'length=i');       # will store in
$h{length}

Pour les options qui prennent des valeurs de liste ou de hash, il est nécessaire d'indiquer cela en ajoutant un "@" ou un "%" après le type

: 
GetOptions (\%h, 'colours=s@');     # will push to @{$h{colours}
}

Pour rendre les choses plus compliquées, le hash peut contenir des références vers les destinations réelles, par exemple

: 
my $len = 0;
my %h = ('length' => \$len);
GetOptions (\%h, 'length=i');       # will store in
$len

Cet exemple est entièrement équivalent à

: 
my $len = 0;
GetOptions ('length=i' => \$len);   # will store in
$len

Tout mélange est possible. Par exemple, les options les plus fréquemment utilisées pourraient être stockées dans des variables tandis que toutes les autres options sont stockées dans le hash

: 
my $verbose = 0;                    # frequently referred
my $debug = 0;                      # frequently referred
my %h = ('verbose' => \$verbose, 'debug' => \$debug);
GetOptions (\%h, 'verbose', 'debug', 'filter', 'size=i');
if ( $verbose ) { ... }
if ( exists $h{filter} ) { ... option 'filter' was specified ...
}

Astuces et

Pousser plusieurs valeurs dans une option

hachage

AinsiParfois, vous souhaitez combiner le meilleur des hachages et des tableaux. Par exemple, la ligne de commande : 

--list add=first --list add=second --list add=third
où chaque option 'list add' successive ajoutera la valeur de 'add' au tableau de référence $list->{'add'}. Le résultat serait : 
$list->{add} = [qw(first second third)];
Cela peut être accompli avec une routine de destination : 
GetOptions('list=s%' =>
             sub { push(@{$list{$_[1]}}, $_[2]) });

Dépannage

GetOptions ne renvoie pas un résultat faux lorsqu'une option n'est pas fournie

C'est pourquoi elles s'appellent des 'options'.

GetOptions ne divise pas la ligne de commande correctement

La ligne de commande n'est pas divisée par GetOptions, mais par l'interpréteur de ligne de commande (CLI). Sous Unix, c'est le shell. Sous Windows, c'est COMMAND.COM ou CMD.EXE. D'autres systèmes d'exploitation ont d'autres CLI.

Il est important de savoir que ces CLI peuvent se comporter différemment lorsque la ligne de commande contient des caractères spéciaux, en particulier des guillemets ou des barres obliques inverses. Par exemple, avec les shells Unix, vous pouvez utiliser des apostrophes ("'") et des guillemets (""") pour regrouper des mots. Les alternatives suivantes sont équivalentes sous Unix :

"deux mots"
'deux mots'
deux\ mots

En cas de doute, insérez l'instruction suivante avant votre programme Perl :

print STDERR (join("|",@ARGV),"\n");

pour vérifier comment votre CLI transmet les arguments au programme.

use GetOpt::Long;

Comment puis-je placer une option "-?" dans un Getopt::Long ?

Vous ne pouvez obtenir cela qu'en utilisant un alias, et Getopt::Long version 2.13 au minimum.

use Getopt::Long;
GetOptions("help|?");    # -help et -? définiront tous deux $opt_help

D'autres caractères qui ne peuvent pas apparaître dans les identificateurs Perl sont également pris en charge dans les alias avec Getopt::Long à partir de la version 2.39. Notez que les caractères "!", "|", "+", "=" et ":" ne peuvent apparaître qu'en premier (ou seul) caractère d'un alias.

À partir de la version 2.32, Getopt::Long fournit l'aide automatique, un moyen rapide et facile d'ajouter les options --help et -? à votre programme, et de les gérer.

Voir "auto_help" dans la section « Configuration de Getopt::Long ».
