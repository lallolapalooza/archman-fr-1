Glib::GenPod(3) Documentation Perl fournie par l'utilisateur Glib::GenPod(3)

NOM

Glib::GenPod - Utilitaires de génération de POD pour les modules basés sur Glib

SYNOPSIS

use Glib::GenPod;
# utiliser les valeurs par défaut :
xsdoc2pod ($fichier_sortie_xsdocparse, $répertoire_destination);
# ou prendre les choses en main
require $fichier_sortie_xsdocparse;
foreach my $package (sort keys %$data) {
    print "=head1 NAME\n\n$package\n\n";
    print "=head1 METHODS\n\n" . podify_methods ($package) . "\n\n";
}

DESCRIPTION

Ce module inclut plusieurs utilitaires pour créer de la documentation POD pour les modules Perl basés sur XS qui s'appuient sur les fondations du module Glib. Les éléments les plus importants sont la logique pour convertir les structures de données créées par xsdocparse.pl pour décrire les xsubs et les POD en documentation de méthode, avec les signatures d'appel et les descriptions d'arguments, et la conversion des noms de types C en noms de types Perl. Le reste du module est principalement du code standard pour formater et imprimer proprement les informations qui peuvent être interrogées à partir du système de types Glib.

Pour faciliter la vie des mainteneurs de modules, nous incluons également une fonction tout-en-un, xsdoc2pod(), qui fait pratiquement tout pour vous. Tous les éléments qu'elle utilise sont utilisables publiquement, vous pouvez donc faire ce que vous voulez si la sortie par défaut ne vous convient pas.

DOCUMENTATION DES FICHIERS XS

Toutes les informations utilisées comme entrée pour les méthodes incluses ici proviennent des fichiers XS de votre projet, et sont extraites par la fonction xsdocparse de Glib::ParseXSDoc. Cette fonction crée un fichier contenant du code Perl qui peut être évalué ou requis pour recréer les structures de données analysées, qui sont une liste de POD provenant de la partie C littérale du fichier XS (la documentation API XS), et une table (hash) des données restantes, indexée par nom de package, et incluant les POD et les xsubs lus à partir du reste de chaque fichier XS après la première ligne MODULE.

Plusieurs directives POD personnalisées sont reconnues dans la section XSubs. Notez que chacune est recherchée comme début de paragraphe et doit suivre une directive "=cut".

=for object Nom::Du::Package
Toutes les xsubs et POD à partir d'ici jusqu'à la prochaine directive object ou ligne MODULE seront placées sous la clé 'Nom::Du::Package' dans la structure de données de xsdocparse. Tout ce qui va de cette ligne jusqu'à la prochaine directive "=cut" est inclus comme POD de description.
=for object Nom::Du::Package (Autre::Nom::Du::Package)
Générer la documentation POD dans Nom::Du::Package mais pour le package Autre::Nom::Du::Package. Ceci est utile si vous souhaitez que la documentation POD apparaisse dans un autre espace de noms mais que vous vouliez toujours la hiérarchie générée automatiquement, les signaux et la liste des propriétés, etc. de l'espace de noms d'origine. Par exemple : 
=for object Gnome2::PanelApplet::main (Gnome2::PanelApplet)
=cut

Cela créera Gnome2/PanelApplet/main.pod contenant la documentation générée automatiquement pour Gnome2::PanelApplet (hiérarchie, signaux, etc.) plus la liste des méthodes du fichier XS actuel.

=for enum Nom::Du::Package
=for flags Nom::Du::Package
Cela amène xsdoc2pod à appeler "podify_values" sur Nom::Du::Package lors de l'écriture du POD pour le package actuel (défini par une directive object ou une ligne MODULE). Tout texte dans ce paragraphe, jusqu'à la prochaine directive "=cut", est inclus dans cette section.
=for deprecated_by Nom::Du::Package
Utilisé pour ajouter un avertissement de dépréciation, indiquant Nom::Du::Package comme moyen alternatif d'obtenir la même fonctionnalité. Il peut y avoir plusieurs de ces directives dans chaque package.
=for see_also chose_quelque_chose_a_voir
Utilisé pour ajouter des sections "voir aussi" supplémentaires à la fin des parents, s'il y en a, pour un objet donné. Tout ce qui suit l'espace après see_also jusqu'à la fin de la ligne sera ajouté à la liste des "voir aussi". Il peut y avoir plusieurs de ces directives dans chaque package.
=for apidoc
=for apidoc Nom::Complet::Symbole
Les paragraphes de ce type documentent les xsubs, et sont associés aux xsubs par xsdocparse.pl. Si le nom complet du symbole n'est pas inclus, le paragraphe doit être attaché à la déclaration de la xsub (pas de lignes vides entre "=cut" et la xsub).

Dans les POD apidoc, nous reconnaissons quelques directives spéciales (la partie "for\s+" est facultative sur celles-ci) :

=for signature ...
Remplace la signature d'appel générée par le texte ... . Si vous incluez plusieurs directives de signature, elles seront toutes utilisées. C'est pratique lorsque vous souhaitez modifier le type de retour ou lister différentes façons d'invoquer une méthode surchargée, comme ceci : 
=for apidoc
=signature bool Class->foo
=signature ($thing, @other) = $object->foo ($it, $something)
Le texte ici est inclus dans la documentation générée.
Vous pouvez en fait inclure des directives de signature et d'argument
à tout moment dans ce POD ; elles sont supprimées ensuite.
En fait, tout POD est valide ici, jusqu'à =cut.
=cut
void foo (...)
    PPCODE:
       /* du code fou suit */
=for arg nom (type) description
=for arg nom description
La directive d'argument ajoute ou remplace une description d'argument. La description est facultative, tout comme la spécification du type (la partie entre parenthèses). Si vous souhaitez masquer un argument, spécifiez "__hide__" comme type. Le nom de l'argument n'a *pas* besoin d'inclure un sigil, car des signes dollar seront ajoutés. MISE À JOUR : Qu'en est-il de @ pour les listes ?

De plus, nous honorons quelques "modificateurs" sur la ligne =for apidoc, après le nom du symbole, s'ils sont présents :

- __hide__
Ne pas documenter cette xsub. C'est pratique dans certaines situations, par exemple pour les fonctions privées. DESTROY a toujours cette option activée, par exemple.
- __gerror__
Cette fonction ou méthode peut générer une exception Glib::Error.
- __function__
Générer une signature de style fonction pour cette xsub. Par défaut, la génération est de style méthode.
- __deprecated__
Cette fonction ou méthode est dépréciée et ne devrait pas être utilisée dans le code nouvellement écrit.

(Ceux-ci sont en fait gérés par Glib::ParseXSDoc, mais nous les listons ici car, eh bien, ils constituent une partie importante de la façon dont vous documentez les fichiers XS.)

FONCTIONS

xsdoc2pod ($fichier_données, $répertoire_sortie='blib/lib', index=undef)
Étant donné un $fichier_données contenant la sortie de xsdocparse.pl, crée dans $répertoire_sortie un fichier POD pour chaque package, contenant tout ce que nous pouvons imaginer pour ce module. La sortie est contrôlée par les directives "=for object" et similaires dans le code source.

Si vous ne voulez pas que chaque package crée un fichier POD séparé, utilisez le code de cette fonction comme point de départ pour votre propre programme d'impression.

add_types (@noms_fichiers)
Analyse les @noms_fichiers donnés pour trouver les entrées à ajouter à la table %basic_types utilisée pour les correspondances de noms C vers noms de package Perl des types qui ne sont pas enregistrés auprès du système de types Glib. Le format du fichier est très simple : les lignes vides sont ignorées ; /#.*$/ est supprimé de chaque ligne comme commentaire ; le premier jeton sur chaque ligne est considéré comme un nom de type C, et les jetons restants sont la description de ce type. Par exemple, un fichier valide peut ressembler à ceci : 
# quelques types spéciaux
FooBar      Foo::Bar
Frob        frobnicateur localisé

Les décorations de type C telles que "const" et "*" sont implicites (ne les incluez pas), et la variante _ornull est gérée pour vous.

$string = podify_properties ($nom_package)
Imprime proprement les propriétés d'objet appartenant au dérivé Glib::Object $nom_package et retourne le texte sous forme de chaîne. Retourne undef s'il n'y a pas de propriétés ou si $package n'est pas un Glib::Object.

Imprime proprement les propriétés enfants appartenant au dérivé Gtk2::Container $nom_package et retourne le texte sous forme de chaîne. Retourne undef s'il n'y a pas de propriétés enfants.

Fonction d'aide permettant de placer du pod générique à des emplacements spécifiques dans les pages générées automatiquement.
