NOM

Type::Tiny::Manual::UsingWithMite - comment utiliser Type::Tiny avec Mite

MANUEL

Mite adopte une approche peu orthodoxe du code orienté objet. Lorsque vous démarrez un projet avec Mite (que nous supposerons s'appeler Your::Project), Mite crée un module nommé Your::Project::Mite pour vous.

Ensuite, toutes vos classes utilisent un code comme ceci :

package Your::Project::Widget;

use Your::Project::Mite -all;

has name => (
   is => ro,
   isa => 'Str',
);

has id => (
   is => ro,
   isa => 'PositiveInt',
);

signature_for warble => (
   named => [
      foo   => 'Int',
      bar   => 'ArrayRef',
   ],
);

sub warble {
   my ( $self, $arg ) = @_;
   printf( "%s: %d\n", $self->name, $arg->foo );
   return;
}

1;

Après avoir écrit ou modifié chaque classe ou rôle, vous exécutez la commande "mite compile" et Mite génère une collection de classes Perl compilées qui n'ont aucune dépendance externe (sur Perl 5.14+. Il y a quelques dépendances externes sur les versions plus anciennes de Perl.)

Les options de l'attribut "isa" sont des contraintes de type Type::Tiny exprimées sous forme de chaînes. Mite les recherche lors de la compilation en utilisant "dwim_type" de Type::Utils, et précharge Types::Standard, Types::Common::String et Types::Common::Numeric pour vous.

Le mot-clé "signature_for" est similaire à la fonction correspondante dans Type::Params. Encore une fois, notez que les types sont exprimés sous forme de chaînes et recherchés en utilisant "dwim_type".

Tous les types qui sont inlineables devraient fonctionner. En cas d'utilisation de coercition, toutes les coercitions qui sont inlineables devraient fonctionner.

Types personnalisés dans Mite

Vous pouvez définir votre propre bibliothèque de types (disons, Your::Project::Types) en utilisant Type::Library comme d'habitude :

package Your::Project::Types;

use Type::Library
   -extends => [ 'Types::Standard', 'Types::Common::Numeric' ];

__PACKAGE__->add_type(
   name    => 'Widget',
   parent  => InstanceOf['Your::Project::Widget'],
)->coercion->add_type_coercions(
   HashRef, q{Your::Project::Widget->new($_)},
);

__PACKAGE__->make_immutable;

1;

Maintenant, si vos classes chargent Your::Project::Types, elles auront soudainement une dépendance sur Type::Library, donc vous ne ressentirez pas cette agréable sensation de zéro dépendance. Mais vous pouvez ajouter ceci à votre fichier ".mite/config" :

types: Your::Project::Types

Maintenant, Mite saura qu'il doit charger cette bibliothèque de types au moment de la compilation, et rendra ces types disponibles sous forme de types textuels partout.

Bibliothèques de types compilées

Il est très appréciable de ne pas avoir à citer ses contraintes de type :

has name => (
   is   => ro,
   isa  => Str,
);

Une solution pour cela est Type::Library::Compiler.

Supposons que vous ayez créé la bibliothèque de types personnalisée ci-dessus, vous pouvez utiliser Type::Library::Compiler pour la compiler dans un module nommé Your::Project::Types::Compiled, qui utilise simplement Exporter et ne dépend pas de Type::Library ou de toute autre partie de Type::Tiny.

Alors votre classe Widget peut l'utiliser :

package Your::Project::Widget;

use Your::Project::Mite -all;
use Your::Project::Types::Compiled -types;

has name => (
   is   => ro,
   isa  => Str,
);

has id => (
   is   => ro,
   isa  => PositiveInt,
);

signature_for warble => (
   named => [
      foo   => Int,
      bar   => ArrayRef,
   ],
);

sub warble {
   my ( $self, $arg ) = @_;
   printf( "%s: %d\n", $self->name, $arg->foo );
   return;
}

1;

Les bibliothèques de types compilées sont plus limitées que les vraies bibliothèques de types. Vous ne pouvez pas, par exemple, faire de types paramétrés avec elles. Cependant, elles offrent toujours des fonctionnalités intéressantes comme :

Foo->check( $value )     # quelques méthodes basiques comme celle-ci
is_Foo( $value )         # vérifications booléennes
assert_Foo( $value )     # assertions qui meurent
Foo | Bar                # unions !

De cette façon, vous pouvez écrire un projet avec l'orienté objet, les rôles, les modificateurs de méthodes, les attributs typés, les signatures typées, et même la coercition, sans aucune dépendance externe ! (Les outils comme Mite et Type::Library::Compiler ne sont nécessaires que pour le développeur, pas pour l'utilisateur final.)
