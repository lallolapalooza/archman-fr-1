NOM

Type::Tiny::Manual::UsingWithClassTiny - utilisation de Type::Tiny avec Class::Tiny

MANUEL

Class::Tiny est un constructeur de classes encore plus petit que Moo.

Traduisons la classe Horse classique de Moo en Class::Tiny.

Moo :

package Horse {
  use Moo;
  use Types::Standard qw( Str Num ArrayRef );
  use namespace::autoclean;

  has name       => ( is => 'ro', isa => Str, required => 1 );
  has gender     => ( is => 'ro', isa => Str );
  has age        => ( is => 'rw', isa => Num );
  has children   => (
    is       => 'ro',
    isa      => ArrayRef,
    default  => sub { return [] },
  );
}

Class::Tiny :

package Horse {
  use Class::Tiny qw( gender age ), {
    name     => sub { die "name is required"; },
    children => sub { return [] },
  };
  use Types::Standard qw( Str Num ArrayRef Dict Optional Slurpy Any Object );
  use Type::Params qw( signature_for );
  use namespace::autoclean;

  # vérifications de type
  signature_for BUILD => (
    method => Object,
    named  => [
      name       => Str,
      gender     => Optional[Str],
      age        => Optional[Num],
      children   => Optional[ArrayRef],
      ()         => Slurpy[Any],
    ],
    fallback => 1,
  );
  signature_for [ 'name', 'gender', 'children' ] => (
    method     => Object,
    positional => [],
  );
  signature_for age => (
    method     => Object,
    positional => [ Optional[Num] ],
  );
}

Que se passe-t-il ici ?

Eh bien, Class::Tiny, après avoir construit un nouvel objet, fait ceci :

$self->BUILD($args);

(Techniquement, il appelle "BUILD" non seulement pour la classe actuelle, mais aussi pour toutes les classes parentes.) Nous pouvons nous accrocher à cela afin de vérifier les contraintes de type pour le constructeur.

Nous utilisons "signature_for" de Type::Params pour envelopper la méthode "BUILD" originale (qui n'existe pas, donc "fallback => 1" supposera simplement une sous-routine vide) avec une vérification de type pour ses arguments. La vérification de type est simplement un Dict qui vérifie les attributs requis et optionnels de la classe et inclut Slurpy[Any] à la fin pour être flexible aux sous-classes ajoutant de nouveaux attributs.

Ensuite, nous enveloppons les méthodes "name", "gender" et "children" avec des vérifications pour s'assurer qu'elles ne sont appelées qu'en tant que getters, et nous enveloppons "age", lui permettant d'être appelé en tant que setter avec un Num.

Il existe également quelques modules CPAN qui peuvent vous aider.

Class::Tiny::ConstrainedAccessor

Class::Tiny::ConstrainedAccessor crée un "BUILD" et des accesseurs qui appliquent les contraintes de Type::Tiny. Les types d'attributs sont passés à Class::Tiny::ConstrainedAccessor ; les valeurs par défaut des attributs sont passées à Class::Tiny.

package Horse {
  use Types::Standard qw( Str Num ArrayRef );
  use Class::Tiny::ConstrainedAccessor {
    name     => Str,
    gender   => Str,
    age      => Num,
    children => ArrayRef,
  };
  use Class::Tiny qw( gender age ), {
    name     => sub { die "name is required"; },
    children => sub { return [] },
  };
}

Class::Tiny::Antlers

Class::Tiny::Antlers fournit une syntaxe de type Moose pour Class::Tiny, y compris le support de "isa". Vous n'avez pas non plus besoin d'utiliser Class::Tiny lui-même.

package Horse {
  use Class::Tiny::Antlers qw(has);
  use Types::Standard qw( Str Num ArrayRef );
  use namespace::autoclean;

  has name       => (
    is        => 'ro',
    isa       => Str,
    default   => sub { die "name is required" },
  );
  has gender     => ( is => 'ro',    isa => Str );
  has age        => ( is => 'rw',    isa => Num );
  has children   => (
    is        => 'ro',
    isa       => ArrayRef,
    default   => sub { return [] },
  );
}
