Types::Standard(3) Documentation Perl contribuée par les utilisateurs Types::Standard(3)

NOM

Types::Standard - ensemble groupé de types intégrés pour Type::Tiny

SYNOPSIS

use v5.36;

package Horse {
  use Moo;
  use Types::Standard qw( Str Int Enum ArrayRef Object );
  use Type::Params qw( signature_for );
  use namespace::autoclean;

  has name => (
    is       => 'ro',
    isa      => Str,
    required => 1,
  );

  has gender => (
    is       => 'ro',
    isa      => Enum[qw( f m )],
  );

  has age => (
    is       => 'rw',
    isa      => Int->where( '$_ >= 0' ),
  );

  has children => (
    is       => 'ro',
    isa      => ArrayRef[Object],
    default  => sub { return [] },
  );

  # signature de méthode
  signature_for add_child => (
    method     => Object,
    positional => [ Object ],
  );

  sub add_child ( $self, $child ) {
    push $self->children->@*, $child;
    return $self;
  }
}

package main;

my $boldruler = Horse->new(
  name    => "Bold Ruler",
  gender  => 'm',
  age     => 16,
);

my $secretariat = Horse->new(
  name    => "Secretariat",
  gender  => 'm',
  age     => 0,
);

$boldruler->add_child( $secretariat );

use Types::Standard qw( is_Object assert_Object );

# is_Object($thing) retourne un booléen
my $is_it_an_object = is_Object $boldruler;

# assert_Object($thing) retourne $thing ou meurt
say assert_Object($boldruler)->name;  # affiche "Bold Ruler"

STATUT

Ce module est couvert par la politique de stabilité de Type-Tiny.

DESCRIPTION

Ceci documente les détails de la bibliothèque de types Types::Standard. Type::Tiny::Manual est un meilleur point de départ si vous êtes novice.

Type::Tiny regroupe quelques types qui semblent utiles.

Similaire à Moose

Les types suivants sont similaires à ceux décrits dans Moose::Util::TypeConstraints.

  • Any

    Absolument n'importe quelle valeur réussit cette contrainte de type (même undef).

  • Item

    Essentiellement la même chose que Any. Toutes les autres contraintes de type dans cette bibliothèque héritent directement ou indirectement de Item.

  • Bool

    Les valeurs qui sont des booléens raisonnables. Accepte 1, 0, la chaîne vide et undef.

    D'autres clients ont également acheté : BoolLike de Types::TypeTiny.

  • Maybe[`a]

    Étant donné une autre contrainte de type, accepte également undef. Par exemple, Maybe[Int] accepte tous les entiers plus undef.

  • Undef

    Seul undef réussit cette contrainte de type.

  • Defined

    Seul undef échoue à cette contrainte de type.

  • Value

    Toute valeur définie, non-référence.

  • Str

    Toute chaîne de caractères.

    (La seule différence entre Value et Str est que la première accepte les typeglobs et les vstrings.)

    D'autres clients ont également acheté : StringLike de Types::TypeTiny.

  • Num

    Voir LaxNum et StrictNum ci-dessous.

  • Int

    Un entier ; c'est-à-dire une chaîne de chiffres de 0 à 9, éventuellement précédée d'un signe moins.

    Attendez-vous à des résultats incohérents pour les dualvars, et pour les nombres trop grands (ou les nombres négatifs trop bas) pour que Perl puisse les représenter en toute sécurité comme des entiers.

  • ClassName

    Le nom d'un paquet chargé. Le paquet doit avoir @ISA ou $VERSION défini, ou doit définir au moins une sous-routine pour être considéré comme un paquet chargé.

  • RoleName

    Comme ClassName, mais le paquet ne doit *pas* définir une méthode appelée "new". Ceci est subtilement différent de la contrainte de type du même nom de Moose ; faites-moi savoir si cela vous pose des problèmes. (Je ne peux pas promettre de changer quoi que ce soit, cependant.)

  • Ref[`a]

    Toute valeur de référence définie, y compris les objets "blessés".

    Contrairement à Moose, Ref est un type paramétré, permettant des vérifications Scalar::Util::reftype, comme

    Ref["HASH"]  # références de hachage, y compris les références de hachage "blessées"
  • ScalarRef[`a]

    Une valeur pour laquelle "ref($value) eq "SCALAR" ou ref($value) eq "REF"".

    Si paramétrée, la valeur référencée doit satisfaire la contrainte supplémentaire. Par exemple, ScalarRef[Int] doit être une référence à un scalaire qui contient une valeur entière.

  • ArrayRef[`a]

    Une valeur pour laquelle "ref($value) eq "ARRAY"".

    Si paramétrée, les éléments du tableau doivent satisfaire la contrainte supplémentaire. Par exemple, ArrayRef[Num] doit être une référence à un tableau de nombres.

    En tant qu'extension du type ArrayRef de Moose, une longueur minimale et maximale de tableau peut être donnée :

    ArrayRef[CodeRef, 1]        # ArrayRef d'au moins un CodeRef
ArrayRef[FileHandle, 0, 2]  # ArrayRef jusqu'à deux FileHandles
ArrayRef[Any, 0, 100]       # ArrayRef jusqu'à 100 éléments

    D'autres clients ont également acheté : ArrayLike de Types::TypeTiny.

  • HashRef[`a]

    Une valeur pour laquelle "ref($value) eq "HASH"".

    Si paramétrée, les valeurs du hachage doivent satisfaire la contrainte supplémentaire. Par exemple, HashRef[Num] doit être une référence à un hachage où les valeurs sont des nombres. Les clés du hachage ne sont pas contraintes, mais Perl les limite aux chaînes de caractères ; voir Map ci-dessous si vous avez besoin de contraindre davantage les valeurs du hachage.

    D'autres clients ont également acheté : HashLike de Types::TypeTiny.

  • CodeRef

    Une valeur pour laquelle "ref($value) eq "CODE"".

    D'autres clients ont également acheté : CodeLike de Types::TypeTiny.

  • RegexpRef

    Une référence pour laquelle re::is_regexp($value) est vraie, ou une référence "blessée" pour laquelle "$value->isa("Regexp")" est vraie.

  • GlobRef

    Une valeur pour laquelle "ref($value) eq "GLOB"".

  • FileHandle

    Un descripteur de fichier.

  • Object

    Un objet "blessé".

    (Ceci accepte également les références d'expressions régulières.)

Structuré

Ok, j'ai piqué quelques idées à MooseX::Types::Structured.

  • Map[`k, `v]

    Similaire à HashRef mais paramétré avec des contraintes de type pour la clé et la valeur. La contrainte pour les clés serait typiquement un sous-type de Str.

  • Tuple[...]

    Sous-type de ArrayRef, acceptant une liste de contraintes de type pour chaque emplacement du tableau.

    Tuple[Int, HashRef] correspondrait à "[1, {}]" mais pas à "[{}, 1]".

  • Dict[...]

    Sous-type de HashRef, acceptant une liste de contraintes de type pour chaque emplacement du hachage.

    Par exemple, Dict[name => Str, id => Int] autorise "{ name => "Bob", id => 42 }".

  • Optional[`a]

    Utilisé en conjonction avec Dict et Tuple pour spécifier des emplacements optionnels qui peuvent être omis (mais pas nécessairement définis sur undef explicite).

    Dict[name => Str, id => Optional[Int]] autorise "{ name => "Bob" }" mais pas "{ name => "Bob", id => "BOB" }".

    Notez que toute utilisation de Optional[`a] en dehors du contexte des contraintes de type paramétrées Dict et Tuple a peu de sens, et son comportement est indéfini. (Une exception : elle est utilisée par Type::Params dans un but similaire à son utilisation dans Tuple.)

Ce module exporte également un type paramétré Slurpy, qui peut être utilisé comme suit.

peut provoquer l'inclusion de valeurs finales supplémentaires dans un Tuple et leur validation. Par exemple, l'inclusion dans un arrayref :

my $type = Tuple[ Str, Slurpy[ ArrayRef[Int] ] ];

$type->( ["Hello"] );                # ok
$type->( ["Hello", 1, 2, 3] );       # ok
$type->( ["Hello", [1, 2, 3]] );     # pas ok

Ou dans un hashref :

my $type2 = Tuple[ Str, Slurpy[ Map[Int, RegexpRef] ] ];

$type2->( ["Hello"] );                               # ok
$type2->( ["Hello", 1, qr/one/i, 2, qr/two/] );      # ok

Cela peut provoquer l'inclusion de valeurs supplémentaires dans un Dict dans un hashref et leur validation :

my $type3 = Dict[ values => ArrayRef, Slurpy[ HashRef[Str] ] ];

$type3->( { values => [] } );                        # ok
$type3->( { values => [], name => "Foo" } );         # ok
$type3->( { values => [], name => [] } );            # pas ok

Dans un Tuple ou un Dict, Slurpy[Any] peut être utilisé pour indiquer que des valeurs supplémentaires sont acceptables, mais ne doivent pas être contraintes de quelque manière que ce soit.

Slurpy[Any] est un chemin de code optimisé. Bien que les vérifications suivantes soient essentiellement équivalentes, la première devrait s'exécuter beaucoup plus rapidement :

Tuple[ Int, Slurpy[Any] ]
Tuple[ Int, Slurpy[ArrayRef] ]

Une fonction slurpy($type) est également exportée, ce qui était historiquement la façon de créer des types slurpy.

En dehors de Dict et Tuple, Slurpy[Foo] devrait agir de la même manière que Foo. Mais ne faites pas cela.

Objets

D'accord, j'ai volé quelques idées à MooX::Types::MooseLike::Base.

  • InstanceOf[`a]

    Raccourci pour une union de contraintes Type::Tiny::Class.

    InstanceOf["Foo", "Bar"] autorise les objets bénis dans les classes "Foo" ou "Bar", ou leurs sous-classes.

    En l'absence de paramètres, équivalent à Object.

  • ConsumerOf[`a]

    Raccourci pour une intersection de contraintes Type::Tiny::Role.

    ConsumerOf["Foo", "Bar"] autorise les objets pour lesquels "$o->DOES("Foo")" et "$o->DOES("Bar")" retournent tous deux true.

    En l'absence de paramètres, équivalent à Object.

  • HasMethods[`a]

    Raccourci pour une contrainte Type::Tiny::Duck.

    HasMethods["foo", "bar"] autorise les objets pour lesquels "$o->can("foo")" et "$o->can("bar")" retournent tous deux true.

    En l'absence de paramètres, équivalent à Object.

Plus

Il existe quelques autres types exportés par ce module :

  • Overload[`a]

    Sans paramètres, vérifie que la valeur est un objet surchargé. Peut être doté d'un ou plusieurs paramètres de chaîne de caractères, qui sont des opérations spécifiques à vérifier pour qu'elles soient surchargées. Par exemple, ce qui suit vérifie les objets qui surchargent l'addition et la soustraction.

    Overload["+", "-"]
  • Tied[`a]

    Une référence vers un scalaire, un tableau ou un hash lié (tied).

    Peut être paramétré avec une contrainte de type qui sera appliquée à l'objet retourné par la fonction tied(). Par commodité, peut également être paramétré avec une chaîne de caractères, qui sera développée en une Type::Tiny::Class.

    use Types::Standard qw(Tied);
use Type::Utils qw(class_type);

my $My_Package = class_type { class => "My::Package" };

tie my %h, "My::Package";
\%h ~~ Tied;                   # vrai
\%h ~~ Tied[ $My_Package ];    # vrai
\%h ~~ Tied["My::Package"];    # vrai

tie my $s, "Other::Package";
\$s ~~ Tied;                   # vrai
$s  ~~ Tied;                   # faux !!

    Si vous avez besoin de vérifier que quelque chose est spécifiquement une référence vers un hash lié, utilisez une intersection :

    use Types::Standard qw( Tied HashRef );

my $TiedHash = (Tied) & (HashRef);

tie my %h, "My::Package";
tie my $s, "Other::Package";

\%h ~~ $TiedHash;     # vrai
\$s ~~ $TiedHash;     # faux
  • StrMatch[`a]

    Une chaîne qui correspond à une expression régulière :

    declare "Distance",
   as StrMatch[ qr{^([0-9]+)\s*(mm|cm|m|km)$} ];

    Vous pouvez éventuellement fournir une contrainte de type pour le tableau de sous-expressions :

    declare "Distance",
   as StrMatch[
      qr{^([0-9]+)\s*(.+)$},
      Tuple[
         Int,
         enum(DistanceUnit => [qw/ mm cm m km /]),
      ],
   ];

    Voici un exemple utilisant Regexp::Common :

    package Local::Host {
   use Moose;
   use Regexp::Common;
   has ip_address => (
      is         => 'ro',
      required   => 1,
      isa        => StrMatch[qr/^$RE{net}{IPv4}$/],
      default    => '127.0.0.1',
   );
}

    Sur certaines versions de Perl, les contraintes de type des formes StrMatch[qr/../ et StrMatch[qr/\A..\z/ avec n'importe quel nombre de points intermédiaires peuvent être optimisées en simples vérifications de longueur.

  • Enum[`a]

    Comme dans MooX::Types::MooseLike::Base :

    has size => (
   is     => "ro",
   isa    => Enum[qw( S M L XL XXL )],
);

    Vous pouvez activer la coercition en passant "\1" avant la liste des valeurs.

    has size => (
   is     => "ro",
   isa    => Enum[ \1, qw( S M L XL XXL ) ],
   coerce => 1,
);

    Cela utilisera la méthode "closest_match" de Type::Tiny::Enum pour coercir des chaînes de caractères qui correspondent étroitement.

  • OptList

    Un arrayref d'arrayrefs dans le style de la sortie de Data::OptList.

  • LaxNum, StrictNum

    Dans Moose 2.09, l'implémentation de la contrainte de type Num est passée d'un wrapper autour de la fonction "looks_like_number" de Scalar::Util à une expression régulière plus stricte (qui interdit des choses comme "-Inf" et "Nan").

    Types::Standard fournit les deux implémentations. LaxNum est mesurable plus rapide.

    La contrainte de type Num est actuellement un alias pour LaxNum à moins que vous ne définissiez la variable d'environnement "PERL_TYPES_STANDARD_STRICTNUM" à true avant de charger Types::Standard, auquel cas elle devient un alias pour StrictNum. La constante "Types::Standard::STRICTNUM" peut être utilisée pour vérifier si Num est strict.

    La plupart des gens devraient probablement utiliser Num ou StrictNum. N'utilisez pas explicitement LaxNum à moins que vous n'ayez spécifiquement besoin d'un attribut qui accepte des choses comme "Inf".

  • CycleTuple[`a]

    Similaire à Tuple, mais cyclique.

    CycleTuple[Int, HashRef]

    autorisera "[1,{}]" et "[1,{},2,{}]" mais interdira "[1,{},2]" et "[1,{},2,"pas un hashref"]".

    Je pense que vous comprenez déjà CycleTuple.

    Actuellement, les paramètres Optional et Slurpy sont interdits. Leurs cas d'utilisation sont assez limités et on ne sait pas exactement ce qu'ils devraient signifier.

    Ce qui suit est un moyen efficace de vérifier un arrayref de taille paire :

    CycleTuple[Any, Any]

    Ce qui suit est un arrayref qui serait approprié pour être converti en un hashref :

    CycleTuple[Str, Any]

    Tous les exemples jusqu'à présent ont utilisé deux paramètres, mais ce qui suit est également un CycleTuple possible :

    CycleTuple[Str, Int, HashRef]

    Ce sera un arrayref où les valeurs d'index 0, 3, 6, etc. sont des chaînes, les valeurs d'index 1, 4, 7, etc. sont des entiers, et les valeurs d'index 2, 5, 8, etc. sont des hashrefs.

Coercions

La plupart des types de cette bibliothèque de types n'ont pas de coercions. L'exception est Bool depuis Types::Standard 1.003_003, qui se convertit depuis Any via "!!$_".

Certaines coercions autonomes peuvent être exportées. Celles-ci peuvent être combinées avec des contraintes de type en utilisant la méthode "plus_coercions".

  • MkOpt

    Une coercion de ArrayRef, HashRef ou Undef vers OptList. Exemple d'utilisation dans un attribut Moose :

    use Types::Standard qw( OptList MkOpt );

has options => (
   is     => "ro",
   isa    => OptList->plus_coercions( MkOpt ),
   coerce => 1,
);
  • Split[`a]

    Divise une chaîne selon une expression régulière.

    use Types::Standard qw( ArrayRef Str Split );

has name => (
   is     => "ro",
   isa    => ArrayRef->of(Str)->plus_coercions(Split[qr/\s/]),
   coerce => 1,
);
  • Join[`a]

    Joint un tableau de chaînes avec un délimiteur.

SYNOPSIS

  use Types::Standard qw( Int );
  sub foo ( $x ) { ... }
  foo( 5 ); # OK
  foo( 5.0 ); # Type::Tiny::Error
  
  use Types::Standard qw( Scalar );
  sub bar ( $x ) { ... }
  bar( 5 );
  bar( 5.0 );
  bar( "hello" );
  bar( "hello" => 5 );
  bar( undef );
  bar( [] );
  bar( {} );
  
  use Types::Standard qw( Undef );
  sub baz ( $x ) { ... }
  baz( undef ); # OK
  baz( 5 ); # Type::Tiny::Error

DESCRIPTION

This module exports a number of type constraints that are intended to be useful in the vast majority of Perl programs.

These type constraints are exported by default when you use Type::Tiny.

The type constraints provided by this module are:

Boolean
Matches true values (1, "1", "yes", "true", etc.) and false values (0, "0", "no", "false", etc.).
Char
Matches a single character string.
CodeRef
Matches any code reference.
Defined
Matches anything except undef.
HashRef
Matches any hash reference.
Int
Matches any integer.
NonEmptyStr
Matches any string that is not empty.
Num
Matches any number (integer or floating-point).
Object
Matches any blessed reference (and so any object).
PackageName
Matches any string that looks like a package name.
PositiveInt
Matches any integer greater than zero.
Ref
Matches any reference.
Scalar
Matches any scalar value (including undef).
Str
Matches any string.
Undef
Matches only undef.
Word
Matches any string consisting only of alphanumeric characters and underscores.
xs_verbose
Set this environment variable to a true value to make Type::Tiny produce more verbose error messages. For example:
  $ PERL5OPT=-MType::Tiny=XS_DEBUG=1 perl your_script.pl

This is useful for debugging, but you probably don't want to do this in production.

Set this environment variable to a true value to suppress XS usage similarly. (Several other CPAN distributions also pay attention to this environment variable.)
