Type::Coercion(3) Documentation Perl fournie par l'utilisateur Type::Coercion(3)

NOM

Type::Coercion - un ensemble de coercions vers une contrainte de type particulière

STATUT

Ce module est couvert par la politique de stabilité de Type-Tiny.

DESCRIPTION

Constructeurs

new(%attributs)
Fonction constructeur style Moose.
"add($c1, $c2)"
Crée un Type::Coercion à partir de deux objets Type::Coercion existants.

Attributs

Les attributs sont des valeurs nommées qui peuvent être passées au constructeur. Pour chaque attribut, il existe une méthode de lecture correspondante. Par exemple :

my $c = Type::Coercion->new( type_constraint => Int );
my $t = $c->type_constraint;  # Int

Attributs importants

Ce sont les attributs que vous serez le plus susceptible de fournir lors de la création de vos propres coercions de type, et ceux que vous lirez le plus souvent lors du traitement des objets de coercition.

"type_constraint"
Référence faible vers la contrainte de type cible (c'est-à-dire la contrainte de type à laquelle la sortie des coderefs de coercition est censée se conformer).
"type_coercion_map"
Tableau de paires source-type/code.
"frozen"
Booléen ; par défaut faux. Une coercion gelée ne peut pas avoir la méthode "add_type_coercions" appelée sur elle.
"name"
Un nom pour la coercition. Ceux-ci doivent être conformes à certaines règles de nommage (ils doivent commencer par une lettre majuscule et continuer à utiliser uniquement des lettres, des chiffres 0-9 et des underscores).

Optionnel ; s'il n'est pas fourni, ce sera une coercition anonyme.

"display_name"
Un nom à afficher pour la coercition lorsqu'elle est convertie en chaîne. Ceux-ci n'ont pas besoin de respecter de règles de nommage. Optionnel ; un nom par défaut sera calculé à partir du "name".
"library"
Le nom du paquet de la bibliothèque de types à laquelle cette coercition est associée. Optionnel. Uniquement informatif : la définition de cet attribut n'installe pas la coercition dans le paquet.

Attributs liés aux coercions paramétrables et paramétrées

Les attributs suivants sont utilisés pour les coercions paramétrées, mais ne sont pas entièrement documentés car ils pourraient changer dans un avenir proche :

"coercion_generator"
"parameters"
"parameterized_from"

Attributs générés paresseusement

Les attributs suivants ne devraient généralement pas être passés au constructeur ; sauf si vous faites quelque chose de particulièrement inhabituel, vous devriez vous fier aux valeurs de retour par défaut construites paresseusement.

"compiled_coercion"
Coderef pour contraindre une valeur ($_[0]).

Le but général de cet attribut est que vous ne devriez pas le définir, mais vous fier au défaut généré paresseusement. Type::Coercion générera généralement un coderef assez rapide, en insérant toutes les vérifications de contrainte de type, etc.

"moose_coercion"
Un objet Moose::Meta::TypeCoercion équivalent. Ne définissez pas cela manuellement ; fiez-vous à celui généré par défaut.

Méthodes

Méthodes prédicat

Ces méthodes retournent des booléens indiquant des informations sur la coercition. Elles sont étroitement associées à un attribut particulier. (Voir "Attributs".)

"has_type_constraint", "has_library"
Méthodes prédicat simples style Moose indiquant la présence ou l'absence d'un attribut.
"is_anon"
Retourne vrai si et seulement si la coercition n'a pas de "name".

Les prédicat suivants sont utilisés pour les coercions paramétrées, mais ne sont pas entièrement documentés car ils pourraient changer dans un avenir proche :

"has_coercion_generator"
"has_parameters"
"is_parameterizable"
"is_parameterized"

Coercition

Les méthodes suivantes sont utilisées pour contraindre des valeurs vers une contrainte de type :

coerce($valeur)
Contraindre la valeur vers le type cible.

Retourne la valeur contrainte, ou la valeur d'origine si aucune coercition n'a été possible.

assert_coerce($valeur)
Contraindre la valeur vers le type cible, et lancer une exception si le résultat ne valide pas contre la contrainte de type cible.

Retourne la valeur contrainte.

Méthodes de définition de code de coercition

Toutes ces méthodes retournent $self afin qu'elles soient adaptées au chaînage.

"add_type_coercions($type1, $code1, ...)"
Prend une ou plusieurs paires de contraintes Type::Tiny et codes de coercition, créant une liste ordonnée de types sources et de codes de coercition.

Les codes de coercition peuvent être exprimés soit comme une chaîne de code Perl (cela inclut les objets qui surchargent la stringification), soit comme un coderef (ou un objet qui surcharge la coderefication). Dans les deux cas, la valeur à contraindre est $_.

add_type_coercions($objet_coercition) fonctionne également, et peut être utilisé pour copier des coercions d'une autre contrainte de type :

$type->coercion->add_type_coercions($othertype->coercion)->freeze;
"freeze"
Définit l'attribut "frozen" à vrai. Appelé automatiquement par Type::Tiny parfois.
"i_really_want_to_unfreeze"
Si vous voulez vraiment dégeler une coercition, appelez cette méthode.

N'appelez pas cette méthode. Cela pourrait potentiellement entraîner des bugs subtils.

Cette méthode est considérée comme instable ; les futures versions de Type::Tiny pourraient modifier son comportement (par exemple, lancer une exception si il a été détecté que le dégèlement de cette coercition particulière causera des bugs).

Paramétrisation

La méthode suivante est utilisée pour les coercions paramétrées, mais n'est pas entièrement documentée car elle pourrait changer dans un avenir proche :

parameterize(@paramètres)

Méthodes d'introspection de coercition de type

Ces méthodes vous permettent de déterminer la relation d'une coercition avec les contraintes de type :

has_coercion_for_type($type_source)
Retourne vrai si et seulement si cette coercition a une coercition à partir du type source.

Retourne la chaîne spéciale "0 but true" si aucune coercition ne devrait réellement être nécessaire pour ce type. (Par exemple, si une coercition contraint vers un type théorique "Number", il n'y a probablement pas de coercition nécessaire pour les valeurs qui se conforment déjà au type "Integer".)

has_coercion_for_value($valeur)
Retourne vrai si et seulement si la valeur pourrait être contrainte par cette coercition.

Retourne la chaîne spéciale "0 but true" si aucune coercition ne serait réellement nécessaire pour cette valeur (car elle satisfait déjà la contrainte de type cible).

L'attribut "type_constraint" fournit un objet de contrainte de type pour la contrainte de type cible de la coercition. Voir "Attributs".

Méthodes d'inlining

Les méthodes suivantes sont utilisées pour générer des chaînes de code Perl qui peuvent être collées dans des subs "eval"uées pour effectuer des coercitions de type :

"can_be_inlined"
Retourne vrai si et seulement si la coercition peut être inlinée.
inline_coercion($nom_var)
Tout comme "inline_coerce" de Type::Tiny.

Autres méthodes

"qualified_name"
Pour les coercions non anonymes qui ont une bibliothèque, retourne un nom qualifié du genre "MyLib::MyCoercion". Sinon, retourne la même chose que "name".
isa($class), can($method), AUTOLOAD(@args)
Si Moose est chargé, alors la combinaison de ces méthodes est utilisée pour simuler un Moose::Meta::TypeCoercion.

Les méthodes suivantes existent pour la compatibilité Moose/Mouse, mais n'ont aucune utilité.

"compile_type_coercion"
"meta"

Surcharge

  • La booléanisation est surchargée pour retourner toujours vrai.
  • La transformation en code de fonction (coderefification) est surchargée pour appeler "coerce".
  • Sur Perl 5.10.1 et supérieur, la comparaison intelligente (smart match) est surchargée pour appeler "has_coercion_for_value".

Les versions précédentes de Type::Coercion surchargeaient l'opérateur "+" pour appeler "add". Le support pour cela a été abandonné après 0.040.

DIAGNOSTICS

Tentative d'ajout de code de coercition à un Type::Coercion qui a été figé
Les contraintes de type de Type::Tiny sont conçues comme des objets immuables. Une fois que vous avez créé une contrainte, plutôt que de la modifier, vous créez généralement des contraintes enfants pour faire ce que vous voulez.

Les objets Type::Coercion, en revanche, sont mutables. Les routines de coercition peuvent être ajoutées à tout moment pendant la durée de vie de l'objet.

Parfois, Type::Tiny a besoin de figer un objet Type::Coercion pour l'empêcher. Dans le code Moose et Mouse, cela se produira probablement dès que vous utiliserez une contrainte de type dans un attribut.

Solutions de contournement :

  • Définissez autant de vos coercions que possible au sein des bibliothèques de types, et non au sein du code qui utilise les bibliothèques de types. La bibliothèque de types sera évaluée relativement tôt, probablement avant qu'il y ait une raison de figer une coercition.
  • Si vous avez besoin d'ajouter des coercions à un type dans du code d'application en dehors de la bibliothèque de types, créez plutôt un subtype et ajoutez-y des coercions. La méthode "plus_coercions" fournie par Type::Tiny devrait simplifier cela.
