NOM

Type::Tiny::Manual::NonOO - Type::Tiny dans du code non orienté objet

MANUEL

Bien que Type::Tiny ait été conçu dans une optique de programmation orientée objet, en particulier pour les classes et rôles de type Moose, il peut être utilisé dans une programmation procédurale et impérative.

Si vous avez lu Type::Tiny::Manual::UsingWithMoo, vous devriez comprendre comment Type::Params peut être utilisé pour valider les paramètres de méthodes. Cette même technique peut être appliquée aux sous-routines normales. Plus d'informations sur la vérification des paramètres sont disponibles dans Type::Tiny::Manual::Params.

Les fonctions "is_*" et "assert_*" exportées par les bibliothèques de types peuvent également être utiles dans du code non orienté objet. Voir Type::Tiny::Manual::UsingWithMoo3.

Type::Tiny et la comparaison intelligente

Perl 5.10 a introduit l'opérateur de comparaison intelligente "~~", qui a depuis été déprécié car, bien que l'idée générale soit assez saine, les détails étaient un peu complexes.

Néanmoins, Type::Tiny prend en charge la comparaison intelligente et je la documente ici car il n'y a pas de meilleur endroit pour la placer.

Ce qui suit peut être utilisé pour vérifier si une valeur passe une contrainte de type :

$valeur ~~ UnCertainType

Là où ça devient étrange, c'est si $valeur est un objet et surcharge "~~". Quelle surcharge de "~~" gagne ? Je ne sais pas.

Mieux vaut utiliser :

UnCertainType->check( $valeur )   # plus fiable, probablement plus rapide
is_UnCertainType($valeur)         # plus fiable, certainement plus rapide

Il est également possible de faire :

$valeur ~~ UnCertainType->coercion

Cela vérifie si $valeur correspond à un type qui peut être contraint pour devenir UnCertainType.

Mais mieux vaut utiliser :

UnCertainType->coercion->has_coercion_for_value( $valeur )

"given" et "when"

Lié à l'opérateur de comparaison intelligente, il y a la syntaxe "given"/"when".

Ceci ne fera pas ce que vous attendez :

use Types::Standard qw( Str Int );

given ( $valeur ) {
  when ( Int ) { ... }
  when ( Str ) { ... }
}

Ceci fera ce que vous vouliez :

use Types::Standard qw( is_Str is_Int );

given ( $valeur ) {
  when ( \&is_Int ) { ... }
  when ( \&is_Str ) { ... }
}

Désolé, c'est juste comme ça que Perl fonctionne.

Mieux encore :

use Types::Standard qw( Str Int );
use Type::Utils qw( match_on_type );

match_on_type $valeur => (
  Str, sub { ... },
  Int, sub { ... },
);

Si cela fait partie d'une boucle ou d'un autre bloc de code fréquemment appelé, vous pouvez compiler les vérifications une fois et les utiliser de nombreuses fois :

use Types::Standard qw( Str Int );
use Type::Utils qw( compile_match_on_type );

my $table_dispatch = compile_match_on_type(
  Str, sub { ... },
  Int, sub { ... },
);

$table_dispatch->($_) for @beaucoup_de_valeurs;

Comme pour la plupart des choses dans Type::Tiny, ces références de sous-programmes peuvent être remplacées par des chaînes de code Perl.
