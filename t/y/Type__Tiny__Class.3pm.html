Type::Tiny::Class(3) Documentation Perl Contribuée par l'Utilisateur Type::Tiny::Class(3)

NOM

Type::Tiny::Class - contraintes de type basées sur la méthode "isa"

SYNOPSIS

Utilisation via Types::Standard :

package Local::Horse {
  use Moo;
  use Types::Standard qw( Str InstanceOf );

  has name => (
    is       => 'ro',
    isa      => Str,
  );

  has owner => (
    is       => 'ro',
    isa      => InstanceOf[ 'Local::Person' ],
    default  => sub { Local::Person->new },
  );
}

Utilisation de la fonction d'exportation de Type::Tiny::Class :

package Local::Horse {
  use Moo;
  use Types::Standard qw( Str );
  use Type::Tiny::Class 'Local::Person';

  has name => (
    is       => 'ro',
    isa      => Str,
  );

  has owner => (
    is       => 'ro',
    isa      => LocalPerson,
    default  => sub { LocalPerson->new },
  );
}

Utilisation de l'interface orientée objet de Type::Tiny::Class :

package Local::Horse {
  use Moo;
  use Types::Standard qw( Str );
  use Type::Tiny::Class;

  my $Person = Type::Tiny::Class->new( class => 'Local::Person' );

  has name => (
    is       => 'ro',
    isa      => Str,
  );

  has owner => (
    is       => 'ro',
    isa      => $Person,
    default  => sub { $Person->new },
  );
}

Utilisation de l'interface fonctionnelle de Type::Utils :

package Local::Horse {
  use Moo;
  use Types::Standard qw( Str );
  use Type::Utils;

  my $Person = class_type 'Local::Person';

  has name => (
    is       => 'ro',
    isa      => Str,
  );

  has owner => (
    is       => 'ro',
    isa      => $Person,
    default  => sub { $Person->new },
  );
}

STATUT

Ce module est couvert par la politique de stabilité de Type-Tiny.

DESCRIPTION

Contraintes de type de la forme générale "{ $_->isa("Some::Class") }".

Ce package hérite de Type::Tiny ; voir celui-ci pour la plupart de la documentation. Les principales différences sont listées ci-dessous :

Constructeur

"new"
Lorsque le constructeur est appelé sur une instance de Type::Tiny::Class, il transmet l'appel au constructeur de la classe pour la contrainte. Ainsi, par exemple : 
my $type = Type::Tiny::Class->new(class => "Foo::Bar");
my $obj  = $type->new(hello => "World");
say ref($obj);   # affiche "Foo::Bar"

Ce petit bout de « fait ce que vous voulez » a été emprunté à MooseX::Types::TypeDecorator, mais Type::Tiny ne pousse pas l'idée aussi loin.

Attributs

"class"
La classe pour la contrainte.
"constraint"
Contrairement à Type::Tiny, vous ne pouvez pas passer un coderef de contrainte au constructeur. Fiez-vous plutôt à la valeur par défaut.
"inlined"
Contrairement à Type::Tiny, vous ne pouvez pas passer un coderef d'imbrication au constructeur. Fiez-vous plutôt à la valeur par défaut.
"parent"
Le parent est calculé automatiquement et ne peut pas être passé au constructeur.

Méthodes

"plus_constructors($source, $method_name)"
Très similaire à "plus_coercions" mais ajoute des coercitions qui passent par un constructeur. (En fait, ceci est implémenté comme un wrapper pour "plus_coercions".)

Exemple :

package MyApp::Minion;

use Moose; extends "MyApp::Person";

use Types::Standard qw( HashRef Str );
use Type::Utils qw( class_type );

my $Person = class_type({ class => "MyApp::Person" });

has boss => (
   is     => "ro",
   isa    => $Person->plus_constructors(
      HashRef,     "new",
      Str,         "_new_from_name",
   ),
   coerce => 1,
);

package main;

MyApp::Minion->new(
   ...,
   boss => "Bob",  ## via MyApp::Person->_new_from_name
);

MyApp::Minion->new(
   ...,
   boss => { name => "Bob" },  ## via MyApp::Person->new
);

Comme la coercition de "HashRef" via constructeur est un désir courant, si vous appelez "plus_constructors" sans arguments du tout, c'est la valeur par défaut.

$classtype->plus_constructors(HashRef, "new")
$classtype->plus_constructors()  ## identique à ci-dessus

Ceci est pratique pour les classes basées sur Moose/Mouse/Moo.

stringifies_to($constraint)
Voir Type::Tiny::ConstrainedObject.
numifies_to($constraint)
Voir Type::Tiny::ConstrainedObject.
"with_attribute_values($attr1 => $constraint1, ...)"
Voir Type::Tiny::ConstrainedObject.

Exportations

Type::Tiny::Class peut être utilisé comme exportateur.

use Type::Tiny::Class 'HTTP::Tiny';

Ceci exportera les fonctions suivantes dans votre espace de noms :

"HTTPTiny"
is_HTTPTiny( $value )
assert_HTTPTiny( $value )
to_HTTPTiny( $value )

Vous pourrez également utiliser "HTTPTiny->new(...)" comme raccourci pour "HTTP::Tiny->new(...)".

Plusieurs types peuvent être exportés simultanément :

use Type::Tiny::Class qw( HTTP::Tiny LWP::UserAgent );

Type::Tiny::Class(3pm)

NOM

Type::Tiny::Class - une classe de base pour les classes qui utilisent Type::Tiny pour leurs contraintes de type.

SYNOPIS


package My::Class;

use base 'Type::Tiny::Class';

# Définir des contraintes de type personnalisées
sub My::Class::is_foo {
    my ($self, $arg) = @_;
    return $arg eq 'foo';
}

# Utiliser Type::Tiny pour les contraintes de type
use Type::Tiny;

my $Integer = type &is_integer;
my $String = type &is_string;
my $Foo = type &is_foo;

__PACKAGE__->type_constraint(
    'bar', $Integer,
    'baz', $String,
    'qux', $Foo,
);

# Accesseurs automatiques
sub bar {
    my $self = shift;
    if (@_) {
        my $value = shift;
        $self->{bar} = $self->check('bar', $value);
    }
    return $self->{bar};
}

sub baz {
    my $self = shift;
    if (@_) {
        my $value = shift;
        $self->{baz} = $self->check('baz', $value);
    }
    return $self->{baz};
}

sub qux {
    my $self = shift;
    if (@_) {
        my $value = shift;
        $self->{qux} = $self->check('qux', $value);
    }
    return $self->{qux};
}

# Utiliser les contraintes dans les méthodes
sub new {
    my $class = shift;
    my %args = @_;
    return bless {
        bar => $class->check('bar', $args{bar}),
        baz => $class->check('baz', $args{baz}),
        qux => $class->check('qux', $args{qux}),
    }, $class;
}

1;

STATUT

Ce module est considéré comme stable.

DESCRIPTION

Type::Tiny::Class est une classe de base pour les classes Perl qui souhaitent utiliser les puissantes fonctionnalités de contraintes de type de Type::Tiny.

En héritant de Type::Tiny::Class, votre classe obtient automatiquement:

  • Une méthode type_constraint pour définir des contraintes de type pour les attributs de votre classe.
  • Une méthode check pour vérifier si une valeur donnée correspond à une contrainte de type définie.
  • Des accesseurs automatiques pour les attributs définis avec type_constraint. Ces accesseurs vérifient la valeur fournie avant de l'affecter.

Vous pouvez également définir vos propres fonctions de validation de type personnalisées et les utiliser avec Type::Tiny.
