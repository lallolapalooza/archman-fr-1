Type::Tiny::Manual::UsingWithMoo2 - utilisation avancée de Type::Tiny avec Moo

MANUEL

Qu'est-ce qu'un Type ?

Jusqu'à présent, tous les exemples vous ont montré comment travailler avec des types, mais nous n'avons pas regardé ce qu'est réellement un type.

use Types::Standard qw( Int );
my $type = Int;

"Int" dans le code ci-dessus n'est qu'une fonction appelée avec zéro argument qui renvoie un objet Perl béni. C'est cet objet qui définit ce qu'est le type Int et est responsable de vérifier que les valeurs respectent sa définition.

use Types::Standard qw( HashRef Int );
my $type = HashRef[Int];

La fonction "HashRef", si elle est appelée sans paramètre, renvoie l'objet définissant le type HashRef, tout comme la fonction "Int" l'a fait précédemment. Mais la différence ici est qu'elle est appelée avec un paramètre, un tableau de référence contenant l'objet de type Int. Elle l'utilise pour créer le type HashRef[Int] et le renvoie.

Comme tout objet, vous pouvez appeler des méthodes dessus. Les méthodes les plus importantes à connaître sont :

# vérifier la valeur et renvoyer un booléen
#
$type->check($value);

# renvoyer un message d'erreur concernant l'échec de la vérification de type de $value
# mais ne pas vraiment vérifier la valeur
#
$type->get_message($value);

# coercer la valeur
#
my $coerced = $type->coerce($value);

Nous avons déjà vu d'autres méthodes plus tôt dans le tutoriel.

# créer un nouveau type, identique à l'ancien type, mais qui a des coercions
#
my $new_type = $type->plus_coercions( ... );

# syntaxe différente pour les types paramétrés
#
my $href = HashRef;
my $int = Int;
my $href_of_int = $href->of($int);

Vous devriez maintenant comprendre ceci :

use Types::Standard qw( ArrayRef Dict Optional );
use Types::Common::Numeric qw( PositiveInt );
use Types::Common::String qw( NonEmptyStr );

my $RaceInfo = Dict[
  year    => PositiveInt,
  race    => NonEmptyStr,
  jockey  => Optional[NonEmptyStr],
];

has latest_event  => ( is => 'rw', isa => $RaceInfo );
has wins          => ( is => 'rw', isa => ArrayRef[$RaceInfo] );
has losses        => ( is => 'rw', isa => ArrayRef[$RaceInfo] );

Cela peut vous aider à éviter les répétitions si vous avez un type paramétré complexe que vous devez réutiliser plusieurs fois.

"where"

L'une des méthodes les plus utiles que vous puissiez appeler sur un objet de type est "where".

use Types::Standard qw( Int );

has lucky_number => (
  is   => 'ro',
  isa  => Int->where(sub { $_ != 13 }),
);

Je pense que vous comprenez déjà ce que cela fait. Cela crée une nouvelle contrainte de type à la volée, restreignant le type d'origine.

Comme pour les coercions, ces restrictions peuvent être exprimées sous forme de coderef ou sous forme de chaîne de code Perl, opérant sur la variable $_. Et comme pour les coercions, utiliser une chaîne de code entraînera de meilleures performances.

use Types::Standard qw( Int );

has lucky_number => (
  is   => 'ro',
  isa  => Int->where(q{ $_ != 13 }),
);

Coercissons un hashref de chaînes à partir d'un tableau de référence de chaînes de taille paire :

use Types::Standard qw( HashRef ArrayRef Str );

has stringhash => (
  is   => 'ro',
  isa  => HashRef->of(Str)->plus_coercions(
    ArrayRef->of(Str)->where(q{ @$_ % 2 == 0 }), q{
      my %h = @$_;
      \%h;
    },
  ),
  coerce => 1,  # n'oubliez jamais !
);

Si vous comprenez cela, vous êtes vraiment dans la classe avancée. Félicitations !

Unions

Parfois, vous voulez accepter une chose ou une autre. C'est assez facile avec Type::Tiny.

use Types::Standard qw( HashRef ArrayRef Str );

has strings => (
  is    => 'ro',
  isa   => ArrayRef[Str] | HashRef[Str],
);

Type::Tiny surcharge l'opérateur OU bit à bit, donc des choses comme celle-ci devraient "simplement fonctionner".

Cela dit, maintenant tout code qui appelle "$self->strings" devra probablement vérifier si la valeur est un tableau de référence ou un hash de référence avant de faire quoi que ce soit avec. Il peut donc être plus simple globalement de choisir l'une des options et de coerçer l'autre.

Intersections

Semblable à une union est une intersection.

package MyAPI::Client {
  use Moo;
  use Types::Standard qw( HasMethods InstanceOf );

  has ua => (
    is    => 'ro',
    isa   => (InstanceOf["MyUA"]) & (HasMethods["store_cookie"]),
  );
}

Ici, nous vérifions que l'UA est une instance de la classe MyUA et offre également la méthode "store_cookie". Peut-être que "store_cookie" n'est pas fournie par la classe MyUA elle-même, mais plusieurs sous-classes de MyUA la fournissent.

Les intersections ne sont pas aussi utiles que les unions. C'est parce qu'elles n'ont souvent pas de sens. "(ArrayRef) & (HashRef)" serait une référence qui pointerait simultanément vers un tableau et un hash, ce qui est impossible.

Notez que lors de l'utilisation d'intersections, il est de bonne pratique de placer des parenthèses autour de chaque type. Ceci est pour désambiguïser la signification de "&" pour Perl, car Perl l'utilise comme opérateur ET bit à bit mais aussi comme sigil pour les subs.

Compléments

Pour tout type Foo, il existe un type complémentaire ~Foo (prononcé "non Foo").

package My::Class {
  use Moo;
  use Types::Standard qw( ArrayRef CodeRef );

  has things => ( is => 'ro', isa => ArrayRef[~CodeRef] );
}

L'attribut "things" est maintenant un tableau de référence de tout sauf des références de code.

Si vous avez besoin d'un nombre qui n'est pas un entier :

Num & ~Int

Types::Standard inclut deux types qui sont complémentaires l'un de l'autre : Undef et Defined.

NegativeInt pourrait sembler être le complément de PositiveOrZeroInt mais quand on y pense, ce n'est pas le cas. Il existe des valeurs qui n'entrent dans aucune des catégories, comme les non-entiers, les chaînes non numériques, les références, undef, etc.

"stringifies_to" et "numifies_to"

Le type de contrainte Object fournit les méthodes "stringifies_to" et "numifies_to" qui sont probablement mieux expliquées par des exemples.

"Object->numifies_to(Int)" signifie tout objet pour lequel "0 + $object" est un entier.

"Object->stringifies_to(StrMatch[$re])" signifie tout objet pour lequel "$object" correspond à l'expression régulière.

"Object->stringifies_to($re)" fonctionne également comme un raccourci.

"Object->numifies_to($coderef)" et "Object->stringifies_to($coderef)" fonctionnent également, où le coderef vérifie $_ et renvoie un booléen.

D'autres types qui sont également logiquement des objets, tels que les types paramétrés HasMethods, InstanceOf, et ConsumerOf devraient également fournir les méthodes "stringifies_to" et "numifies_to".

"stringifies_to" et "numifies_to" fonctionnent sur les unions si toutes les contraintes de type de l'union offrent la méthode.

"stringifies_to" et "numifies_to" fonctionnent sur les intersections si au moins une des contraintes de type de l'intersection offre la méthode.

NOM

Type::Tiny::Manual::UsingWithMoo2 - Utiliser Type::Tiny avec Moo

MANUEL

Ce manuel couvre l'utilisation de Type::Tiny avec Moo. Il existe plusieurs façons d'intégrer les deux bibliothèques.

Attributs à valeurs spécifiques

Voici un exemple de la façon de restreindre la valeur d'un attribut à un type spécifique qui peut être une sous-classe d'un autre type, mais qui a également des valeurs spécifiques pour ses propres attributs.

package Horse;
use strict;
use warnings;
use Moo;
use Types::Standard qw( Enum Object );
use namespace::autoclean;

our $VERSION = '0.000001';

has gender  => (
  is  => 'ro',
  isa => Enum['m', 'f'],
);
has father  => (
  is  => 'ro',
  isa => Object->with_attribute_values(gender => Enum['m']),
);
has mother  => (
  is  => 'ro',
  isa => Object->with_attribute_values(gender => Enum['f']),
);

Dans cet exemple, lorsque vous définissez le père d'un cheval, cela appellera "$father->gender" et vérifiera qu'il correspond à Enum['m'].

Cette méthode appartient à la même famille que "stringifies_as" et "numifies_as", donc, comme elles, elle ne s'applique qu'à Object et aux contraintes de type similaires, peut fonctionner sur les unions/intersections dans les mêmes circonstances, et acceptera également des coderefs et des regex.

has father  => (
  is  => 'ro',
  isa => Object->with_attribute_values(gender => sub { $_ eq 'm' }),
);
has mother  => (
  is  => 'ro',
  isa => Object->with_attribute_values(gender => qr/^f/i),
);

Toutes les méthodes "stringifies_as", "numifies_as", et "with_attributes_as" sont en réalité des wrappers autour de "where". Les deux suivantes sont approximativement équivalentes :

my $type1 = Object->with_attribute_values(foo => Int, bar => Num);

my $type2 = Object->where(sub {
  Int->check( $_->foo ) and Num->check( $_->bar )
});

La première produira un code plus performant cependant.

Variables Tiedes

Il est possible de lier des variables à une contrainte de type.

use Types::Standard qw( Int );

tie my $n, Int, 4;

print "$n\n";   # affiche "4"
$n = 5;         # ok
$n = "foo";     # plante

Vous pouvez également lier des tableaux :

tie my @numbers, Int;
push @numbers, 1 .. 10;

Et des hachages :

tie my %numbers, Int;
$numbers{lucky}   = 7;
$numbers{unlucky} = 13;

Plus tôt dans le manuel, il a été mentionné qu'il y avait un problème avec du code comme celui-ci :

push $horse->children->@*, $non_horse;

Cela peut être résolu en utilisant des variables tiedes.

tie $horse->children->@*, InstanceOf["Horse"];

Voici un exemple plus long utilisant des builders et des triggers.

package Horse {
  use Moo;
  use Types::Standard qw( Str Num ArrayRef InstanceOf );
  use Type::Params qw( signature_for );
  use namespace::autoclean;

  my $ThisClass = InstanceOf[ __PACKAGE__ ];

  has name       => ( is => 'ro',    isa => Str );
  has gender     => ( is => 'ro',    isa => Str );
  has age        => ( is => 'rw',    isa => Num );
  has children   => (
    is        => 'rw',
    isa       => ArrayRef[$ThisClass],
    builder   => "_build_children",
    trigger   => sub { shift->_trigger_children(@_) },
  );

  # lie un tableau par défaut
  sub _build_children ( $self ) {
    tie my @kids, $ThisClass;
    \@kids;
  }

  # cette méthode liera un tableau fourni par l'appelant
  sub _trigger_children ( $self, $new ) {
    tie $new->@*, $ThisClass;
  }

  signature_for add_child => (
    method     => $ThisClass,
    positional => [ $ThisClass ],
  );

  sub add_child ( $self, $kid ) {
    push $self->children->@*, $kid;
    return $self;
  }
}

Il est maintenant pratiquement impossible pour l'appelant de faire une erreur en ajoutant un non-cheval comme enfant.

(Notez qu'il existe un module Types::Self sur CPAN qui définira un type Self signifiant InstanceOf[ __PACKAGE__ ] pour vous !)
