Type::Utils(3) Documentation Perl fournie par l'utilisateur Type::Utils(3)

NOM

Type::Utils - fonctions utilitaires pour faciliter la définition et l'utilisation des contraintes de type

SYNOPSIS

package Types::Mine;

use Type::Library -base;
use Type::Utils -all;

BEGIN { extends "Types::Standard" };

declare "AllCaps",
   as "Str",
   where { uc($_) eq $_ },
   inline_as { my $varname = $_[1]; "uc($varname) eq $varname" };

coerce "AllCaps",
   from "Str", via { uc($_) };

STATUT

Ce module est couvert par la politique de stabilité de Type-Tiny.

DESCRIPTION

Ce module fournit des fonctions utilitaires pour faciliter la définition et l'utilisation des contraintes de type.

Fonctions de déclaration de type

Beaucoup des fonctions suivantes sont similaires aux fonctions portant le même nom décrites dans Moose::Util::TypeConstraints.

"declare $name, %options"
"declare %options"
Déclare une contrainte de type nommée ou anonyme. Utilise "as" et "where" pour spécifier le type parent (le cas échéant) et (éventuellement) affiner sa définition. 
declare EvenInt, as Int, where { $_ % 2 == 0 };
my $EvenInt = declare as Int, where { $_ % 2 == 0 };

NOTE : Les types nommés seront automatiquement ajoutés au registre de types de l'appelant. (Voir Type::Registry.) Si le paquet appelant hérite de Type::Library, les types nommés seront également automatiquement installés dans la bibliothèque et rendus disponibles en tant qu'exportations.

Gemme cachée : si vous héritez d'une contrainte de type qui inclut des coercitions, vous pouvez inclure "coercion => 1" dans la table de hachage %options pour hériter des coercions.

"subtype $name, %options"
"subtype %options"
Déclare une contrainte de type nommée ou anonyme qui descend d'une contrainte de type existante. Utilise "as" et "where" pour spécifier le type parent et affiner sa définition.

En fait, vous devriez utiliser "declare" à la place ; ceci n'est qu'un alias.

Cette fonction n'est pas exportée par défaut.

"type $name, %options"
"type %options"
Déclare une contrainte de type nommée ou anonyme qui ne descend pas d'une contrainte de type existante. Utilise "where" pour fournir un coderef qui contraint les valeurs.

En fait, vous devriez utiliser "declare" à la place ; ceci n'est qu'un alias.

Cette fonction n'est pas exportée par défaut.

"as $parent"
Utilisé avec "declare" pour spécifier une contrainte de type parent : 
declare EvenInt, as Int, where { $_ % 2 == 0 };
"where { BLOC }"
Utilisé avec "declare" pour fournir le coderef de contrainte : 
declare EvenInt, as Int, where { $_ % 2 == 0 };

Le coderef opère sur $_, qui est la valeur testée.

"message { BLOC }"
Génère un message d'erreur personnalisé lorsqu'une valeur échoue à la validation. 
declare EvenInt,
   as Int,
   where { $_ % 2 == 0 },
   message {
      Int->validate($_) or "$_ n'est pas divisible par deux";
   };

Sans message personnalisé, les messages générés par Type::Tiny sont du genre La valeur "33" n'a pas réussi la contrainte de type "EvenInt", ce qui est généralement raisonnable.

"inline_as { BLOC }"
Génère une chaîne de code Perl qui peut être utilisée pour intégrer la vérification de type dans d'autres fonctions. Si votre vérification de type est utilisée dans des méthodes de constructeur ou d'accesseur Moose ou Moo, ou utilisée par Type::Params, cela peut entraîner des améliorations de performance significatives. 
declare EvenInt,
   as Int,
   where { $_ % 2 == 0 },
   inline_as {
      my ($constraint, $varname) = @_;
      my $perlcode = 
         $constraint->parent->inline_check($varname)
         . "&& ($varname % 2 == 0)";
      return $perlcode;
   };

warn EvenInt->inline_check('$xxx');  # démonstration

Votre bloc "inline_as" peut retourner une liste, auquel cas celles-ci seront fusionnées avec "&&". Le premier élément de la liste peut être undef, auquel cas undef sera remplacé par la contrainte de type parente intégrée. (Et lèvera une exception s'il n'y a pas de parent.)

declare EvenInt,
   as Int,
   where { $_ % 2 == 0 },
   inline_as {
      return (undef, "($_ % 2 == 0)");
   };
"class_type $name, { class => $package, %options }"
"class_type { class => $package, %options }"
"class_type $name"
Raccourci pour déclarer une contrainte de type Type::Tiny::Class.

Si $package est omis, il est supposé être le même que $name. Si $name contient "::" (ce qui serait un nom invalide pour Type::Tiny), celui-ci sera supprimé.

Ainsi, par exemple, class_type("Foo::Bar") déclare une contrainte de type Type::Tiny::Class nommée "FooBar" qui contraint les valeurs à être des objets bénis dans le paquet "Foo::Bar".

"role_type $name, { role => $package, %options }"
"role_type { role => $package, %options }"
"role_type $name"
Raccourci pour déclarer une contrainte de type Type::Tiny::Role.

Si $package est omis, il est supposé être le même que $name. Si $name contient "::" (ce qui serait un nom invalide pour Type::Tiny), celui-ci sera supprimé.

"duck_type $name, \@methods"
"duck_type \@methods"
Raccourci pour déclarer une contrainte de type Type::Tiny::Duck.
"union $name, \@constraints"
"union \@constraints"
Raccourci pour déclarer une contrainte de type Type::Tiny::Union.
"enum $name, \@values"
"enum \@values"
Raccourci pour déclarer une contrainte de type Type::Tiny::Enum.
"intersection $name, \@constraints"
"intersection \@constraints"
Raccourci pour déclarer une contrainte de type Type::Tiny::Intersection.

Fonctions de déclaration de coercition

Beaucoup des fonctions suivantes sont similaires aux fonctions portant le même nom décrites dans Moose::Util::TypeConstraints.

"coerce $target, @coercions"
Ajoute des coercions à la contrainte de type cible. La liste des coercions est une liste de paires contrainte de type, code de conversion. Le code de conversion peut être soit une chaîne de code Perl soit un coderef ; dans les deux cas, la valeur à convertir est $_.
"from $source"
Sucre pour spécifier une contrainte de type dans une liste de coercions : 
coerce EvenInt, from Int, via { $_ * 2 };  # Comme coderef...
coerce EvenInt, from Int, q { $_ * 2 };    # ou comme chaîne !
"via { BLOC }"
Sucre pour spécifier un coderef dans une liste de coercions.
"declare_coercion $name, \%opts, $type1, $code1, ..."
"declare_coercion \%opts, $type1, $code1, ..."
Déclare une coercition qui n'est pas explicitement attachée à un type de la bibliothèque. Par exemple : 
declare_coercion "ArrayRefFromAny", from "Any", via { [$_] };

Cette coercition pourra être exportée de la bibliothèque sous forme d'objet Type::Coercion, mais le type ArrayRef exporté par la bibliothèque ne l'utilisera pas automatiquement.

Les coercitions déclarées de cette manière sont immuables (gelées).

"to_type $type"
Utilisé avec "declare_coercion" pour déclarer la contrainte de type cible d'une coercition, mais toujours w

sans attacher explicitement la coercition à la contrainte de type : 
declare_coercion "ArrayRefFromAny",
   to_type "ArrayRef",
   from "Any", via { [$_] };

Vous devriez presque toujours utiliser ceci lors de la déclaration d'une coercition non attachée car elle est extrêmement utile pour une coercition de type de savoir à quoi elle va se coercez - cela lui permet de sauter la coercition lorsqu'aucune coercition n'est nécessaire (par exemple, éviter de coercez "[]" en "[ [] ]") et permet à "assert_coerce" de fonctionner correctement.

Gestion de bibliothèques de types

"extends @libraries"
Indique que cette bibliothèque de types étend d'autres bibliothèques de types, en important leurs contraintes de type.

Devrait généralement être exécuté dans un bloc "BEGIN".

Ceci n'est pas exporté par défaut car il n'est pas agréable de l'exporter vers les classes Moo, Moose ou Mouse ! "use Type::Utils -all" peut être utilisé pour l'importer dans votre bibliothèque de types.

Autre

"match_on_type $value => ($type => \&action, ..., \&default?)"
Quelque chose comme une construction "switch"/"case" ou "given"/"when". Distribue selon différents chemins de code en fonction du type de la valeur entrante. Exemple manifestement volé de la documentation Moose : 
sub to_json
{
   my $value = shift;

   return match_on_type $value => (
      HashRef() => sub {
         my $hash = shift;
         '{ '
            . (
            join ", " =>
            map { '"' . $_ . '" : ' . to_json( $hash->{$_} ) }
            sort keys %$hash
         ) . ' }';
      },
      ArrayRef() => sub {
         my $array = shift;
         '[ '.( join ", " => map { to_json($_) } @$array ).' ]';
      },
      Num()   => q {$_},
      Str()   => q { '"' . $_ . '"' },
      Undef() => q {'null'},
      => sub { die "$_ n'est pas un type json acceptable" },
   );
}

Notez que contrairement à Moose, le code peut être spécifié sous forme de chaîne au lieu d'un coderef. (par exemple pour "Num", "Str" et "Undef" ci-dessus.)

Pour des performances améliorées, essayez "compile_match_on_type".

Cette fonction n'est pas exportée par défaut.

"my $coderef = compile_match_on_type($type => \&action, ..., \&default?)"
Compile un bloc "match_on_type" en un coderef. Le convertisseur JSON suivant est environ deux ordres de grandeur plus rapide que l'exemple précédent : 
sub to_json;
*to_json = compile_match_on_type(
   HashRef() => sub {
      my $hash = shift;
      '{ '
         . (
         join ", " =>
         map { '"' . $_ . '" : ' . to_json( $hash->{$_} ) }
         sort keys %$hash
      ) . ' }';
   },
   ArrayRef() => sub {
      my $array = shift;
      '[ '.( join ", " => map { to_json($_) } @$array ).' ]';
   },
   Num()   => q {$_},
   Str()   => q { '"' . $_ . '"' },
   Undef() => q {'null'},
   => sub { die "$_ n'est pas un type json acceptable" },
);

N'oubliez pas de stocker le coderef quelque part de suffisamment permanent afin de ne pas le compiler encore et encore. Les variables "state" (dans Perl >= 5.10) sont idéales pour cela. (Même idée que Type::Params.)

Cette fonction n'est pas exportée par défaut.

"my $coderef = classifier(@types)"
Retourne un coderef qui peut être utilisé pour classifier des valeurs selon leur contrainte de type. Le coderef, lorsqu'il reçoit une valeur, retourne une contrainte de type satisfaite par la valeur. 
use feature qw( say );
use Type::Utils qw( classifier );
use Types::Standard qw( Int Num Str Any );

my $classifier = classifier(Str, Int, Num, Any);

say $classifier->( "42"  )->name;   # Int
say $classifier->( "4.2" )->name;   # Num
say $classifier->( []    )->name;   # Any

Notez que, par exemple, "42" satisfait Int, mais il satisferait également les contraintes de type Num, Str et Any. Dans ce cas, le classificateur a choisi la contrainte de type la plus spécifique que "42" satisfait.

Si aucune contrainte de type n'est satisfaite par la valeur, le classificateur retournera undef.

"dwim_type($string, %options)"
Étant donné une chaîne comme "ArrayRef[Int|CodeRef]", la transforme en un objet de contrainte de type, en essayant de faire ce que vous voulez.

Il utilise la syntaxe de Type::Parser. Tout d'abord, le registre de types (Type::Registry) du package appelant est consulté ; si celui-ci n'a pas de correspondance, Types::Standard est consulté pour les noms de contraintes de type standard.

Si aucune des méthodes ci-dessus ne donne une contrainte de type, et que la classe appelante est une classe basée sur Moose, alors "dwim_type" tente de rechercher la contrainte de type dans le registre de types Moose. S'il s'agit d'une classe basée sur Mouse, le registre de types Mouse est utilisé à la place.

Si aucune contrainte de type ne peut être trouvée par ces méthodes normales, plusieurs solutions de repli sont disponibles :

"lookup_via_moose"
Recherche dans le registre Moose même si l'appelant est une classe non-Moose.
"lookup_via_mouse"
Recherche dans le registre Mouse même si l'appelant est une classe non-Mouse.
"make_class_type"
Crée une nouvelle contrainte Type::Tiny::Class.
"make_role_type"
Crée une nouvelle contrainte Type::Tiny::Role.

Vous pouvez modifier celles qui doivent être tentées, et dans quel ordre, en passant une option à "dwim_type" :

my $type = Type::Utils::dwim_type(
   "ArrayRef[Int]",
   fallback      => [ "lookup_via_mouse" , "make_role_type" ],
);

Pour des raisons historiques, par défaut les solutions de repli tentées sont :

lookup_via_moose, lookup_via_mouse, make_class_type

Vous pouvez définir "fallback" à un tableau vide (arrayref) pour éviter d'utiliser ces solutions de repli.

Vous pouvez spécifier une alternative pour l'appelant en utilisant l'option "for".

my $type = dwim_type("ArrayRef", for => "Moose::Object");

Bien qu'il soit probablement préférable d'utiliser l'interface Type::Registry appropriée pour résoudre les chaînes de contraintes de type, cette fonction fait souvent ce que vous voulez.

Elle ne devrait jamais mourir si elle ne parvient pas à trouver une contrainte de type (mais peut mourir si la chaîne de contrainte de type est syntaxiquement malformée), préférant retourner undef.

Cette fonction n'est pas exportée par défaut.

"is($type, $value)"
Raccourci pour "$type->check($value)" mais aussi si $type est une chaîne, la recherchera via "dwim_type".

Cette fonction n'est pas exportée par défaut. Cette fonction n'est même pas exportée par "use Type::Utils -all". Vous devez la demander explicitement.

use Type::Utils "is";

Attention à l'utiliser dans les scripts de test car elle porte le même nom qu'une fonction exportée par Test::More. Notez que vous pouvez renommer cette fonction si "is" provoque des conflits :

use Type::Utils "is" => { -as => "isntnt" };
"assert($type, $value)"
Similaire à "is" mais au lieu de retourner un booléen, retourne $value et meurt si la valeur échoue à la vérification de type.

Cette fonction n'est pas exportée par défaut, mais elle est exportée par "use Type::Utils -all".

"english_list(\$conjunction, @items)"
Joint les éléments avec des virgules, plaçant une conjonction avant le dernier élément. La conjonction est facultative, avec par défaut "and". 
english_list(qw/foo bar baz/);       # "foo, bar, et baz"
english_list(\"or", qw/quux quuux/); # "quux ou quuux"

Cette fonction n'est pas exportée par défaut.

EXPORT

Par défaut, toutes les fonctions documentées ci-dessus sont exportées, à l'exception de "subtype" et "type" (préférez "declare" à la place), "extends", "dwim_type", "match_on_type"/"compile_match_on_type", "classifier", et "english_list".

Ce module utilise Exporter::Tiny ; consultez la documentation de ce module pour des astuces et conseils d'importation depuis Type::Utils.
