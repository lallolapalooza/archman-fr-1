NOM

Type::Tiny::Manual::Installation - comment installer Type::Tiny

MANUEL

L'installation de Type-Tiny devrait être simple.

Installation avec cpanminus

Si vous avez cpanm, vous n'avez besoin que d'une ligne :

% cpanm Type::Tiny

Si vous installez dans un répertoire système, vous devrez peut-être passer l'indicateur "-S" à cpanm, qui utilise sudo pour installer le module :

% cpanm -S Type::Tiny

Installation avec le Shell CPAN

Alternativement, si votre shell CPAN est configuré, vous devriez simplement pouvoir faire :

% cpan Type::Tiny

Installation manuelle

En dernier recours, vous pouvez l'installer manuellement. Téléchargez la tarball et décompressez-la.

Consultez le fichier META.json pour une liste des prérequis. Installez-les d'abord.

Pour construire Type-Tiny :

% perl Makefile.PL
% make && make test

Installez-le ensuite :

% make install

Si vous installez dans un répertoire système, vous devrez peut-être exécuter :

% sudo make install

Dépendances

Type::Tiny nécessite au moins Perl 5.8.1, bien que certaines fonctionnalités liées à Unicode (par exemple, les noms de contraintes de type non ASCII) puissent mieux fonctionner dans les versions plus récentes de Perl.

Type::Tiny nécessite Exporter::Tiny, un module qui était auparavant inclus dans cette distribution, mais qui a depuis été séparé en une distribution distincte. Ne vous inquiétez pas - il est rapide et facile à installer.

À l'exécution, Type::Tiny nécessite également les modules Perl suivants : B, B::Deparse, Carp, Data::Dumper, Scalar::Util, Text::Balanced, overload, strict et warnings. Tous ceux-ci sont inclus avec Perl lui-même.

Certaines fonctionnalités nécessitent des modules supplémentaires. Les traces de pile sur les exceptions nécessitent Devel::StackTrace. Le plugin Reply::Plugin::TypeTiny pour Reply nécessite Reply (évidemment).

Type::Tiny::XS n'est pas requis, mais s'il est disponible, il offre un gain de vitesse pour certaines vérifications de type. (Définir la variable d'environnement "PERL_TYPE_TINY_XS" à faux, ou définir "PERL_ONLY" à vrai supprimera l'utilisation de Type::Tiny::XS, même s'il est disponible.)

La suite de tests nécessite en outre Test::More, Test::Fatal et Test::Requires. Test::More est inclus avec Perl, mais si vous utilisez une version de Perl antérieure à 5.14, vous devrez mettre à niveau vers au moins Test::More version 0.96. Test::Requires et Test::Fatal (ainsi que Try::Tiny dont Test::Fatal dépend) sont inclus avec Type::Tiny dans le répertoire "inc", vous n'avez donc pas besoin de les installer séparément.

Si vous utilisez Type::Tiny conjointement avec Moo, alors au moins Moo 1.006000 est recommandé. Si vous utilisez Type::Tiny avec Moose, alors au moins Moose 2.0000 est recommandé. Si vous utilisez Type::Tiny avec Mouse, alors au moins Mouse 1.00 est recommandé. Type::Tiny est principalement non testé avec des versions plus anciennes de ces paquets.

Type::Tiny et cperl

cperl http://perl11.org/cperl/ est une version étendue de Perl avec divers changements incompatibles par rapport aux versions officielles de Perl 5.

Depuis Type::Tiny 1.010001, cperl est une plateforme prise en charge pour Type::Tiny avec quelques mises en garde. Au moment de la rédaction, Moose ne s'installe pas sur les dernières versions de cperl, donc l'utilisation de Type::Tiny avec Moose sur cperl n'est pas testée. Moo peut être forcé à s'installer, et Type::Tiny est vérifié pour fonctionner avec Moo sur cperl. cperl active non seulement une nouvelle catégorie d'avertissements appelée "shadow" (ce qui est bien ; ils sont potentiellement utiles) mais active les avertissements d'ombre par défaut (ce qui est ennuyeux). Type::Tiny ne tentera pas (et ne tentera probablement jamais) de contourner ces avertissements. Si les avertissements vous dérangent, vous devriez pouvoir les intercepter en utilisant $SIG{__WARN__}. Certaines fonctionnalités d'Eval::TypeTiny sont cassées sous cperl, mais on ne pense pas qu'elles aient d'effet pratique sur Type::Tiny ou ses autres modules inclus.
