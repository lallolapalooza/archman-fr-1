NOM

Type::Tiny::Union - contraintes de type union

SYNTAXE

Utilisation via la surcharge de l'opérateur "|" :

package Local::Stash {
  use Moo;
  use Types::Common qw( ArrayRef HashRef );

  has data => (
    is   => 'ro',
    isa  => HashRef | ArrayRef,
  );
}

my $x = Local::Stash->new( data => {} );  # ok
my $y = Local::Stash->new( data => [] );  # ok

Utilisation de l'interface orientée objet de Type::Tiny::Union :

package Local::Stash {
  use Moo;
  use Types::Common qw( ArrayRef HashRef );
  use Type::Tiny::Union;

  my $AnyData = Type::Tiny::Union->new(
    name             => 'AnyData',
    type_constraints => [ HashRef, ArrayRef ],
  );

  has data => (
    is   => 'ro',
    isa  => $AnyData,
  );
}

Utilisation de l'interface fonctionnelle de Type::Utils :

package Local::Stash {
  use Moo;
  use Types::Common qw( ArrayRef HashRef );
  use Type::Utils;

  my $AnyData = union AnyData => [ HashRef, ArrayRef ];

  has data => (
    is   => 'ro',
    isa  => $AnyData,
  );
}

STATUT

Ce module est couvert par la politique de stabilité de Type-Tiny.

DESCRIPTION

Contraintes de type union.

Ce paquet hérite de Type::Tiny ; consultez-le pour la plupart de la documentation. Les principales différences sont listées ci-dessous :

Constructeur

Le constructeur "new" de Type::Tiny fonctionne toujours, bien sûr. Mais il y a aussi :

new_by_overload(%attributs)
Comme le constructeur "new", mais retournera parfois une autre contrainte de type qui n'est pas strictement une instance de Type::Tiny::Union, mais qui encapsule la même signification. Ce constructeur est utilisé par la surcharge de l'opérateur "|" par Type::Tiny.

Attributs

"type_constraints"
Arrayref de contraintes de type.

Lorsqu'elles sont passées au constructeur, si l'une des contraintes de type de l'union est elle-même une contrainte de type union, elle est "décompressée" dans la nouvelle union.

"constraint"
Contrairement à Type::Tiny, vous ne pouvez PAS passer de coderef de contrainte au constructeur. Fiez-vous plutôt à la valeur par défaut.
"inlined"
Contrairement à Type::Tiny, vous ne pouvez PAS passer de coderef d'inlining au constructeur. Fiez-vous plutôt à la valeur par défaut.
"parent"
Contrairement à Type::Tiny, vous ne pouvez PAS passer de coderef d'inlining au constructeur. Un parent sera plutôt calculé automatiquement.
"coercion"
Vous ne passerez probablement pas cela au constructeur. (Ce n'est pas encore interdit, car il pourrait y avoir une utilité à laquelle je n'ai pas pensé.)

La valeur par défaut générée automatiquement sera un objet Type::Coercion::Union.

Méthodes

find_type_for($valeur)
Retourne la première contrainte de type individuelle dans l'union que $valeur réussit.
stringifies_to($contrainte)
Voir Type::Tiny::ConstrainedObject.
numifies_to($contrainte)
Voir Type::Tiny::ConstrainedObject.
"with_attribute_values($attr1 => $contrainte1, ...)"
Voir Type::Tiny::ConstrainedObject.

Surcharge d'opérateurs

•
La conversion en arrayref appelle "type_constraints".
