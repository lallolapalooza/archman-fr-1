NOM

Type::Tiny::Manual::UsingWithMoose - comment utiliser Type::Tiny avec Moose

MANUEL

Lisez d'abord Type::Tiny::Manual::UsingWithMoo, Type::Tiny::Manual::UsingWithMoo2 et Type::Tiny::Manual::UsingWithMoo3. Tout ce qui se trouve dans ces parties du manuel devrait fonctionner exactement de la même manière dans Moose.

Cette partie du manuel se concentrera sur les spécificités de Moose.

Pourquoi utiliser Type::Tiny en fait ?

Moose possède un système de contraintes de type intégré qui est assez pratique à utiliser, mais il y a plusieurs raisons pour lesquelles vous devriez envisager d'utiliser Type::Tiny à la place.

  • Les contraintes de type Type::Tiny seront généralement plus rapides que les intégrées de Moose. Même sans Type::Tiny::XS installé, Type::Tiny produit généralement du code inline plus efficace que Moose. Les coercitions seront généralement beaucoup plus rapides.
  • Type::Tiny fournit des méthodes utiles comme "where" et "plus_coercions" qui permettent de modifier facilement les contraintes de type et les coercitions au niveau de chaque attribut.

    Quelque chose comme ceci est beaucoup plus difficile à faire avec des types Moose simples :

    has name => (
  is      => "ro",
  isa     => Str->plus_coercions(
    ArrayRef[Str], sub { join " ", @$_ },
  ),
  coerce  => 1,
);

    Moose a tendance à encourager la définition globale des coercitions, donc si vous vouliez qu'un attribut Str puisse être converti à partir de ArrayRef[Str], alors *tous* les attributs Str seraient convertis à partir de ArrayRef[Str], et ils le feraient tous de la même manière. (Même s'il peut être judicieux de joindre par un espace dans certains endroits, une virgule dans d'autres, et un saut de ligne dans d'autres encore !)

  • Type::Tiny fournit des coercions profondes automatiques, donc si le type Xyz a une coercion, ce qui suit devrait « simplement fonctionner » : 
    has xyzlist => ( is => 'ro', isa => ArrayRef[Xyz], coerce => 1 );
  • Type::Tiny offre une sélection plus large de types intégrés.
  • En utilisant Type::Tiny, vous pouvez utiliser les mêmes contraintes de type et coercitions pour les attributs et les paramètres de méthodes, dans du code Moose et non-Moose.

Type::Utils

Si vous avez utilisé Moose::Util::TypeConstraints, vous êtes peut-être habitué à utiliser un DSL pour déclarer des contraintes de type :

use Moose::Util::TypeConstraints;

subtype 'Natural',
  as 'Int',
  where { $_ > 0 };

Il existe un module appelé Type::Utils qui fournit un DSL très similaire pour déclarer des types dans des bibliothèques de types basées sur Type::Library.

package My::Types {
  use Type::Library -base;
  use Type::Utils;
  use Types::Standard qw( Int );

  declare 'Natural',
    as Int,
    where { $_ > 0 };
}

Personnellement, je préfère cependant la manière plus orientée objet de déclarer des types.

Depuis Type::Library 1.012, un raccourci est disponible pour importer Type::Library et Type::Utils en même temps :

package MyType {
  use Type::Library -base, -utils;

  ...;
}

Dans Moose, vous pourriez également déclarer des types comme ceci à l'intérieur des classes et des rôles. Contrairement à Moose, Type::Tiny ne conserve pas les types dans un seul espace de noms plat global, donc cela ne fonctionne pas exactement de la même manière avec Type::Utils. Il crée toujours le type, mais il ne le stocke dans aucune bibliothèque de types ; le type est retourné.

package My::Class {
  use Moose;
  use Type::Utils;
  use Types::Standard qw( Int );

  my $Natural =          # stocker le type dans une variable
    declare 'Natural',
    as Int,
    where { $_ > 0 };

  has number => ( is => 'ro', isa => $Natural );
}

Mais vraiment, la manière orientée objet n'est-elle pas plus propre ?

package My::Class {
  use Moose;
  use Types::Standard qw( Int );

  has number => (
    is   => 'ro',
    isa  => Int->where('$_ > 0'),
  );
}

Type::Tiny et MooseX::Types

Types::Standard devrait être un remplacement direct pour MooseX::Types. Et Types::Common::Numeric et Types::Common::String devraient facilement remplacer MooseX::Types::Common::Numeric et MooseX::Types::Common::String.

Cela dit, si vous souhaitez utiliser un mélange de Type::Tiny et MooseX::Types, ils devraient s'intégrer de manière transparente.

use Types::Standard qw( ArrayRef );
use MooseX::Types::Common::Numeric qw( PositiveInt );

# cela devrait simplement fonctionner
my $list_of_nums = ArrayRef[PositiveInt];

# et ceci
my $list_or_num = ArrayRef | PositiveInt;

Paramètre d'importation « -moose »

Si vous avez lu jusqu'ici dans le manuel, vous saurez que c'est la manière habituelle d'importer des contraintes de type :

use Types::Standard qw( Int );

Et le "Int" qui est importé est une fonction qui ne prend aucun argument et retourne la contrainte de type Int, qui est un objet béni dans la classe Type::Tiny.

Type::Tiny imite l'API Moose::Meta::TypeConstraint si bien que la plupart des codes Moose et MooseX ne pourront pas faire la différence.

Mais que faire si vous avez besoin d'un véritable objet Moose::Meta::TypeConstraint ?

use Types::Standard -moose, qw( Int );

Maintenant, la fonction "Int" importée retournera une véritable contrainte de type native Moose.

Ce drapeau est principalement un vestige de l'époque où les objets natifs de Type::Tiny ne fonctionnaient *pas* directement dans Moose. Dans 99,9 % des cas, il n'y a aucune raison de l'utiliser et de nombreuses raisons de ne pas le faire. (Les contraintes de type natives de Moose n'offrent pas de méthodes utiles comme "plus_coercions" et "where".)

Méthode « moose_type »

Une autre façon rapide d'obtenir un objet de contrainte de type Moose natif à partir d'un objet Type::Tiny est d'appeler la méthode "moose_type" :

use Types::Standard qw( Int );

my $tiny_type   = Int;
my $moose_type  = $tiny_type->moose_type;

En interne, c'est ce que fait le drapeau "-moose" lors de l'importation de fonctions.
