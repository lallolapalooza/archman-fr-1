Type::Tiny::Duck(3) Documentation Perl fournie par l'utilisateur Type::Tiny::Duck(3)

NOM

Type::Tiny::Duck - contraintes de type basées sur la méthode "can"

SYNOPSIS

Utilisation via Types::Standard :

package Logger {
  use Moo;
  use Types::Standard qw( HasMethods Bool );

  has debugging => ( is => 'rw', isa => Bool, default => 0 );
  has output    => ( is => 'ro', isa => HasMethods[ 'print' ] );

  sub warn {
    my ( $self, $message ) = @_;
    $self->output->print( "[WARNING] $message\n" );
  }

  sub debug {
    my ( $self, $message ) = @_;
    $self->output->print( "[DEBUG] $message\n" ) if $self->debugging;
  }
}

Utilisation de la fonctionnalité d'export de Type::Tiny::Duck :

package Logger {
  use Moo;
  use Types::Standard qw( Bool );
  use Type::Tiny::Duck Printable => [ 'print' ];

  has debugging => ( is => 'rw', isa => Bool, default => 0 );
  has output    => ( is => 'ro', isa => Printable );

  sub warn {
    my ( $self, $message ) = @_;
    $self->output->print( "[WARNING] $message\n" );
  }

  sub debug {
    my ( $self, $message ) = @_;
    $self->output->print( "[DEBUG] $message\n" ) if $self->debugging;
  }
}

Utilisation de l'interface orientée objet de Type::Tiny::Duck :

package Logger {
  use Moo;
  use Types::Standard qw( Bool );
  use Type::Tiny::Duck;

  my $Printable = Type::Type::Duck->new(
    name    => 'Printable',
    methods => [ 'print' ],
  );

  has debugging => ( is => 'rw', isa => Bool, default => 0 );
  has output    => ( is => 'ro', isa => $Printable );

  sub warn {
    my ( $self, $message ) = @_;
    $self->output->print( "[WARNING] $message\n" );
  }

  sub debug {
    my ( $self, $message ) = @_;
    $self->output->print( "[DEBUG] $message\n" ) if $self->debugging;
  }
}

STATUT

Ce module est couvert par la politique de stabilité de Type-Tiny.

DESCRIPTION

Contraintes de type de la forme générale "{ $_->can("méthode") }".

Le nom fait référence au dicton : "Si ça ressemble à un canard, nage comme un canard et fait coin-coin comme un canard, alors c'est probablement un canard". Le "duck typing" (typage canard) peut être une manière plus flexible de tester des objets que de se fier à "isa", car il permet aux utilisateurs de substituer facilement des objets mockés.

Ce paquet hérite de Type::Tiny ; consultez celui-ci pour la plupart des documentations. Les différences majeures sont listées ci-dessous :

Constructeurs

Le constructeur "new" de Type::Tiny fonctionne toujours, bien sûr. Mais il existe aussi :

"new_intersection( type_constraints => \@canards, %opts )"
Crée une nouvelle contrainte de type canard qui est l'intersection de contraintes de type canard existantes. Cela permet à l'intersection de "HasMethods['read']" et "HasMethods['write']" d'être simplement "HasMethods['read', 'write']" au lieu d'une contrainte de type union complexe avec deux contraintes de type canard comme enfants.

Attributs

"methods"
Un tableau de noms de méthodes.
"constraint"
Contrairement à Type::Tiny, vous *ne pouvez pas* passer un code de contrainte au constructeur. Utilisez plutôt la valeur par défaut.
"inlined"
Contrairement à Type::Tiny, vous *ne pouvez pas* passer un code d'inline au constructeur. Utilisez plutôt la valeur par défaut.
"parent"
Le parent est toujours Types::Standard::Object, et ne peut pas être passé au constructeur.

Méthodes

stringifies_to($constraint)
Voir Type::Tiny::ConstrainedObject.
numifies_to($constraint)
Voir Type::Tiny::ConstrainedObject.
"with_attribute_values($attr1 => $constraint1, ...)"
Voir Type::Tiny::ConstrainedObject.

Exports

Type::Tiny::Duck peut être utilisé comme exportateur.

use Type::Tiny::Duck HttpClient => [ 'get', 'post' ];

Cela exportera les fonctions suivantes dans votre espace de noms :

"HttpClient"
is_HttpClient( $valeur )
assert_HttpClient( $valeur )
to_HttpClient( $valeur )

Plusieurs types peuvent être exportés en une seule fois :

use Type::Tiny::Duck (
  HttpClient   => [ 'get', 'post' ],
  FtpClient    => [ 'upload', 'download' ],
);
