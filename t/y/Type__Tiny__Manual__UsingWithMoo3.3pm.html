NOM

Type::Tiny::Manual::UsingWithMoo3 - utilisation alternative de Type::Tiny avec Moo

MANUEL

Registres de types

Dans tous les exemples jusqu'à présent, nous avons importé une collection de contraintes de type dans chaque classe :

package Horse {
  use Moo;
  use Types::Standard qw( Str ArrayRef HashRef Int Any InstanceOf );
  use Types::Common::Numeric qw( PositiveInt );
  use Types::Common::String qw( NonEmptyStr );

  has name    => ( is => 'ro', isa => Str );
  has father  => ( is => 'ro', isa => InstanceOf["Horse"] );
  ...;
}

Cela crée un tas de sous-routines dans l'espace de noms Horse, une pour chaque type. Nous avons utilisé namespace::autoclean pour les nettoyer plus tard.

Mais il est également possible d'éviter de charger tout cela dans l'espace de noms Horse. Au lieu de cela, nous utiliserons un registre de types :

package Horse {
  use Moo;
  use Type::Registry qw( t );

  t->add_types('-Standard');
  t->add_types('-Common::String');
  t->add_types('-Common::Numeric');

  t->alias_type('InstanceOf["Horse"]' => 'Horsey');

  has name     => ( is => 'ro', isa => t('Str') );
  has father   => ( is => 'ro', isa => t('Horsey') );
  has mother   => ( is => 'ro', isa => t('Horsey') );
  has children => ( is => 'ro', isa => t('ArrayRef[Horsey]') );
  ...;
}

Vous n'avez même pas besoin d'importer la fonction t(). Type::Registry peut être utilisé de manière entièrement orientée objet.

package Horse {
  use Moo;
  use Type::Registry;

  my $reg = Type::Registry->for_me;

  $reg->add_types('-Standard');
  $reg->add_types('-Common::String');
  $reg->add_types('-Common::Numeric');

  $reg->alias_type('InstanceOf["Horse"]' => 'Horsey');

  has name => ( is => 'ro', isa => $reg->lookup('Str') );
  ...;
}

Vous pourriez créer deux registres avec des définitions entièrement différentes pour le même type nommé.

my $dracula = Aristocrat->new(name => 'Dracula');

package AristocracyTracker {
  use Type::Registry;

  my $reg1 = Type::Registry->new;
  $reg1->add_types('-Common::Numeric');
  $reg1->alias_type('PositiveInt' => 'Count');

  my $reg2 = Type::Registry->new;
  $reg2->add_types('-Standard');
  $reg2->alias_type('InstanceOf["Aristocrat"]' => 'Count');

  $reg1->lookup("Count")->assert_valid("1");
  $reg2->lookup("Count")->assert_valid($dracula);
}

Type::Registry utilise "AUTOLOAD", donc des choses comme celles-ci fonctionnent :

$reg->ArrayRef->of( $reg->Int );

Bien que vous puissiez créer autant de registres que vous le souhaitez, Type::Registry créera un registre par défaut pour chaque paquet.

# Créer un nouveau registre vide.
# 
my $reg = Type::Registry->new;

# Obtenir le registre par défaut pour mon paquet.
# Il sera pré-rempli avec tous les types que nous avons importés en utilisant `use`.
#
my $reg = Type::Registry->for_me;

# Obtenir le registre par défaut pour un autre paquet.
#
my $reg = Type::Registry->for_class("Horse");

Les registres de types sont un endroit pratique pour stocker un tas de types sans polluer votre espace de noms. Ils ne sont cependant pas la même chose que les bibliothèques de types. Types::Standard, Types::Common::String et Types::Common::Numeric sont des bibliothèques de types ; des paquets qui exportent des types pour que d'autres les utilisent. Nous verrons comment en créer une plus tard.

Pour l'instant, voici la meilleure façon de penser à la différence :

  • Registre de types

    Organiser une collection de types à utiliser ici dans cette classe. Cette collection est un détail d'implémentation.

  • Bibliothèque de types

    Exporter une collection de types à utiliser dans plusieurs classes. Cette collection fait partie de votre API.

Importation de fonctions

Nous avons vu comment, par exemple, Types::Standard exporte une sous-routine appelée "Int" qui renvoie l'objet de type Int.

use Types::Standard qw( Int );

my $type = Int;
$type->check($value) or die $type->get_message($value);

Les bibliothèques de types sont également capables d'exporter d'autres fonctions de commodité.

"is_*"

C'est un raccourci pour vérifier si une valeur satisfait une contrainte de type :

use Types::Standard qw( is_Int );

if ( is_Int $value ) {
  ...;
}

Appeler is_Int($value) sera souvent marginalement plus rapide que d'appeler "Int->check($value)" car cela évite un appel de méthode. (Les appels de méthodes en Perl finissent par être plus lents que les appels de fonctions normaux.)

Utiliser des choses comme "is_ArrayRef" dans votre code pourrait être préférable à "ref($value) eq "ARRAY"" car c'est plus propre, conduit à une vérification de type plus cohérente, et pourrait même être plus rapide. (Type::Tiny peut être assez rapide ; il est parfois capable d'exporter ces fonctions sous forme de sous-routines XS.)

Si vous vérifiez des contraintes de type comme "is_ArrayRef" ou "is_InstanceOf", il n'y a aucun moyen de passer un paramètre. "is_ArrayRef[Int]($value)" ne fonctionne pas, pas plus que "is_ArrayRef(Int, $value)" ni "is_ArrayRef($value, Int)". Pour certains types comme "is_InstanceOf", cela les rend assez inutiles ; sans pouvoir donner un nom de classe, cela agit simplement comme "is_Object". Voir "Exportation de types paramétrés" pour une solution. Regardez aussi isa.

Il existe également une fonction générique "is".

use Types::Standard qw( ArrayRef Int );
use Type::Utils qw( is );

if ( is ArrayRef[Int], \@numbers ) {
  ...;
}

"assert_*"

Alors que is_Int($value) renvoie un booléen, assert_Int($value) lèvera une erreur si la valeur ne satisfait pas la contrainte, et renverra la valeur sinon. Vous pouvez donc faire :

my $sum = assert_Int($x) + assert_Int($y);

Et vous obtiendrez la somme des entiers $x et $y, et une explosion si l'un d'eux n'est pas un entier !

Assert est utile pour des vérifications rapides de paramètres si vous évitez Type::Params pour une raison étrange :

sub add_numbers {
  my $x = assert_Num(shift);
  my $y = assert_Num(shift);
  return $x + $y;
}

Vous pouvez également utiliser une fonction générique "assert".

use Type::Utils qw( assert );

sub add_numbers {
  my $x = assert Num, shift;
  my $y = assert Num, shift;
  return $x + $y;
}

"to_*"

C'est un raccourci pour la coercition :

my $truthy = to_Bool($value);

Cela fait confiance que la coercition a fonctionné correctement. Vous pouvez la combiner avec une assertion si vous voulez être sûr.

my $truthy = assert_Bool(to_Bool($value));

Raccourcis pour exporter des fonctions

C'est un peu verbeux :

use Types::Standard qw( Bool is_Bool assert_Bool to_Bool );

N'est-ce pas un peu plus agréable ?

use Types::Standard qw( +Bool );

Le signe plus indique à une bibliothèque de types d'exporter non seulement le type lui-même, mais aussi toutes les fonctions de commodité.

Vous pouvez également utiliser :

use Types::Standard -types;   # exporte Int, Bool, etc
use Types::Standard -is;      # exporte is_Int, is_Bool, etc
use Types::Standard -assert;  # exporte assert_Int, assert_Bool, etc
use Types::Standard -to;      # exporte to_Bool, etc
use Types::Standard -all;     # juste exporte tout !!!

Donc, si vous imaginez que les fonctions exportées par Types::Standard sont comme ceci :

qw(
  Str             is_Str          assert_Str
  Num             is_Num          assert_Num
  Int             is_Int          assert_Int
  Bool            is_Bool         assert_Bool     to_Bool
  ArrayRef        is_ArrayRef     assert_ArrayRef
);
# ... et plus

Alors "+" exporte un groupe horizontal de ceux-ci, et "-" exporte un groupe vertical.

Exportation de types paramétrés

Il est possible d'exporter des types paramétrables comme ArrayRef, mais il est également possible d'exporter des types *paramétrés*.

use Types::Standard qw( ArrayRef Int );
use Types::Stan

Type::Tiny::Manual::UsingWithMoo 3 - perl

NAME

Type::Tiny::Manual::UsingWithMoo - How to use Type::Tiny with Moose/Moo

MANUAL

This manual page explains how to use Type::Tiny with Moo and Moose.

Types provided by Types::Standard

Types::Standard provides a number of useful type constraints. You can import them directly, or you can import them into your own namespace. This is useful if you want to avoid name collisions.

use Types::Standard -types; # imports all types into the current namespace

# Or, if you want to avoid name collisions:
package MyTypes;
use Types::Standard -types;
our @ISA = qw( Types::Standard ); # Make sure all of Types::Standard types are available
1;

package main;
use MyTypes qw( PositiveInt Str );
assert_PositiveInt( $foo );
assert_Str( $bar );

The -types option is equivalent to -normalize. This means that any type constraints that are imported will be normalized. This means that any type constraints that are parameterized will be parameterized with their default values. For example, if you import ArrayRef, it will be imported as ArrayRef[Any].

If you want to import a type constraint with a specific parameterization, you can do so like this:

use Types::Standard qw( IntList );

# Then, you can use IntList as a type constraint.
# Note that this is equivalent to:
# use Types::Standard -types; # makes 'IntList' available
# our $IntList = ArrayRef->of(Int);

The -types option is only available since Type::Tiny 2.0. If you are using an older version of Type::Tiny, you will need to import the types manually.

Since Type::Tiny 2.0, you can define your own parameterized types like this:

use Type::Tiny;
use Type::Tiny::Enum;

my $IntList = Type::Tiny::ArrayRef->of(Int);
my $is_IntList = $IntList->compile;

# ... and then use $is_IntList wherever you need a type checker for an
# array reference of integers.

You can also export your own parameterized types:

use Type::Tiny;

package MyTypes;
use Type::Tiny -types; # Make sure all of Type::Tiny's types are available

our $IntList = Type::Tiny::ArrayRef->of(Int);
our $StrList = Type::Tiny::ArrayRef->of(Str);

1;

package main;
use MyTypes qw( IntList StrList );

my $list = [1, 2, 3];
assert_IntList($list); # OK

my $other_list = ["a", "b", "c"];
assert_StrList($other_list); # OK

When you export parameterized types, you can also specify a name for the exported type. This is useful if you want to use a different name for the type than the one that is generated by Type::Tiny.

use Type::Tiny;

package MyTypes;
use Type::Tiny -types;

our 'IntList' => ( of => Int );

1;

package main;
use MyTypes qw( IntList );

my $list = [1, 2, 3];
assert_IntList($list); # OK

Using is_IntList($value) should be significantly faster than "ArrayRef->of(Int)->check($value)".

This trick only works for parameterized types that have a single parameter, like ArrayRef, HashRef, InstanceOf, etc. (Sorry, "Dict" and "Tuple"!)

Since Type::Tiny 2.8.0 there has been experimental support for a different way of exporting parameterized versions of certain parameterizable type constraints.

use Types::Standard -types;
use Types::Standard::ArrayRef (
  IntList         => { of => Int },
  StrList         => { of => Str },
  NonEmptyStrList => { of => Str->where( sub { length($_) > 0 } ) },
  StrNonEmptyList => { of => Str, where => sub { @$_ > 0 } },
  NEStrNEList     => {
    of    => Str->where( sub { length($_) > 0 } ),
    where => sub { @$_ > 0 },
  },
);

assert_IntList [ 1.. 5 ];                      # doesn't die

is_NonEmptyStrList [ "foo", "bar" ];           # ==> true
is_NonEmptyStrList [ "foo", "" ];              # ==> false
is_NonEmptyStrList [];                         # ==> true

is_StrNonEmptyList [ "foo", "bar" ];           # ==> true
is_StrNonEmptyList [ "foo", "" ];              # ==> true
is_StrNonEmptyList [];                         # ==> false

is_NEStrNEList [ "foo", "bar" ];               # ==> true
is_NEStrNEList [ "foo", "" ];                  # ==> false
is_NEStrNEList [];                             # ==> false

And of course "where" also accepts a string of Perl code.

Lexical imports

Type::Tiny 2.0 combined with Perl 5.37.2+ allows lexically scoped imports. So:

my $is_ok = do {
  use Types::Standard -lexical, qw( Str ArrayRef );
  ArrayRef->of( Str )->check( \@things );
};

# The Str and ArrayRef types aren't defined here.

Do What I Mean!

use Type::Utils qw( dwim_type );

my $type = dwim_type("ArrayRef[Int]");

"dwim_type" will look up a type constraint from a string and attempt to guess what you meant.

If it's a type constraint that you seem to have imported with "use", then it should find it. Otherwise, if you're using Moose or Mouse, it'll try asking those. Or if it's in Types::Standard, it'll look there. And if it still has no idea, then it will assume dwim_type("Foo") means dwim_type("InstanceOf['Foo']").

It just does a big old bunch of guessing.

The "is" function will use "dwim_type" if you pass it a string as a type.

use Type::Utils qw( is );

if ( is "ArrayRef[Int]", \@numbers ) {
  ...;
}

Types::Common

Notice that in a lot of examples we're importing one or two functions each from a few different modules:

use Types::Common::Numeric qw( PositiveInt );
use Types::Common::String qw( NonEmptyStr );
use Types::Standard qw( ArrayRef Slurpy );
use Type::Params qw( signature_for );

A module called Types::Common exists which acts as a single place you can use for importing most of Type::Tiny's commonly used types and functions.

use Types::Common qw(
  PositiveInt NonEmptyStr ArrayRef Slurpy
  signature_for
);

Types::Common provides:

  • All the types from Types::Standard.
  • All the types from Types::Common::Numeric and Types::Common::String.
  • All the types from Types::TypeTiny.
  • The "-sigs" tag from Type::Params.
  • The t() function from Type::Registry.
