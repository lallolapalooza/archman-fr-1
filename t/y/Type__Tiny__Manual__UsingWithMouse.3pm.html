NOM

Type::Tiny::Manual::UsingWithMouse - comment utiliser Type::Tiny avec Mouse

MANUEL

Lisez d'abord Type::Tiny::Manual::UsingWithMoo, Type::Tiny::Manual::UsingWithMoo2, et Type::Tiny::Manual::UsingWithMoo3. Tout ce qui se trouve dans ces parties du manuel devrait fonctionner exactement de la même manière avec Mouse.

Cette partie du manuel se concentrera sur les spécificités de Mouse.

Globalement, Type::Tiny est moins bien testé avec Mouse qu'avec Moose et Moo, mais il existe tout de même un bon nombre de cas de test pour l'utilisation de Type::Tiny avec Mouse, et il n'y a pas de problèmes majeurs connus avec le support de Type::Tiny pour Mouse.

Pourquoi utiliser Type::Tiny en général ?

Mouse dispose d'un système de contraintes de type intégré qui est assez pratique à utiliser, mais il y a plusieurs raisons pour lesquelles vous devriez envisager d'utiliser Type::Tiny à la place.

  • Type::Tiny fournit des méthodes utiles comme "where" et "plus_coercions" qui permettent d'ajuster facilement les contraintes de type et les coercions sur une base par attribut.

    Quelque chose comme ceci est beaucoup plus difficile à faire avec des types Mouse purs :

    has name => (
  is      => "ro",
  isa     => Str->plus_coercions(
    ArrayRef[Str], sub { join " " x @$_ },
  ),
  coerce  => 1,
);

    Mouse tend à encourager la définition des coercions globalement, donc si vous vouliez qu'un attribut Str puisse être cohérit de ArrayRef[Str], alors tous les attributs Str seraient cohérit de ArrayRef[Str], et ils le feraient tous de la même manière. (Même si cela pourrait avoir du sens de joindre par un espace dans certains endroits, une virgule dans d'autres, et un saut de ligne dans d'autres encore !)

  • Type::Tiny fournit des coercions profondes automatiques, donc si le type Xyz a une coercion, le suivant devrait "simplement fonctionner" : 
    has xyzlist => ( is => 'ro', isa => ArrayRef[Xyz], coerce => 1 );
  • Type::Tiny offre une plus large sélection de types intégrés.
  • En utilisant Type::Tiny, vous pouvez utiliser les mêmes contraintes de type et coercions pour les attributs et les paramètres de méthode, dans du code Mouse et non-Mouse.

Type::Utils

Si vous avez utilisé Mouse::Util::TypeConstraints, vous êtes peut-être habitué à utiliser un DSL pour déclarer les contraintes de type :

use Mouse::Util::TypeConstraints;

subtype 'Natural',
  as 'Int',
  where { $_ > 0 };

Il existe un module appelé Type::Utils qui fournit un DSL très similaire pour déclarer des types dans des bibliothèques de types basées sur Type::Library.

package My::Types {
  use Type::Library -base;
  use Type::Utils;
  use Types::Standard qw( Int );

  declare 'Natural',
    as Int,
    where { $_ > 0 };
}

Personnellement, je préfère cependant la manière plus orientée objet de déclarer des types.

Dans Mouse, vous pourriez également déclarer des types comme ceci dans des classes et des rôles. Contrairement à Mouse, Type::Tiny ne conserve pas les types dans un seul espace de noms global plat, donc cela ne fonctionne pas exactement de la même manière avec Type::Utils. Cela crée toujours le type, mais ne le stocke dans aucune bibliothèque de types ; le type est retourné.

package My::Class {
  use Mouse;
  use Type::Utils;
  use Types::Standard qw( Int );

  my $Natural =          # stocker le type dans une variable
    declare 'Natural',
    as Int,
    where { $_ > 0 };

  has number => ( is => 'ro', isa => $Natural );
}

Mais vraiment, la manière orientée objet n'est-elle pas plus propre ?

package My::Class {
  use Mouse;
  use Types::Standard qw( Int );

  has number => (
    is   => 'ro',
    isa  => Int->where('$_ > 0'),
  );
}

Type::Tiny et MouseX::Types

Types::Standard devrait être un remplacement direct pour MooseX::Types. Et Types::Common::Numeric et Types::Common::String devraient facilement remplacer MouseX::Types::Common::Numeric et MouseX::Types::Common::String.

Cela dit, si vous souhaitez utiliser un mélange de Type::Tiny et de MouseX::Types, ils devraient s'intégrer de manière assez transparente.

use Types::Standard qw( ArrayRef );
use MouseX::Types::Mouse qw( Int );

# cela devrait simplement fonctionner
my $list_of_nums = ArrayRef[Int];

# et ceci
my $list_or_num = ArrayRef | Int;

Paramètre d'importation "-mouse"

Si vous avez lu jusqu'ici dans le manuel, vous saurez que c'est la manière habituelle d'importer des contraintes de type :

use Types::Standard qw( Int );

Et le "Int" qui est importé est une fonction qui ne prend aucun argument et renvoie la contrainte de type Int, qui est un objet béni dans la classe Type::Tiny.

Type::Tiny simule l'API de Mouse::Meta::TypeConstraint si bien que la plupart du code Mouse et MouseX ne pourront pas faire la différence.

Mais et si vous avez besoin d'un vrai objet Mouse::Meta::TypeConstraint ?

use Types::Standard -mouse, qw( Int );

Maintenant, la fonction "Int" importée renverra une véritable contrainte de type Mouse native.

Ce drapeau est principalement un vestige de l'époque où les objets natifs de Type::Tiny ne fonctionnaient pas directement dans Mouse. Dans 99,9 % des cas, il n'y a aucune raison de l'utiliser et de nombreuses raisons de ne pas le faire. (Les contraintes de type natif de Mouse n'offrent pas de méthodes utiles comme "plus_coercions" et "where".)

"mouse_type" Méthode

Une autre façon rapide d'obtenir un objet contrainte de type Mouse natif à partir d'un objet Type::Tiny est d'appeler la méthode "mouse_type" :

use Types::Standard qw( Int );

my $tiny_type   = Int;
my $mouse_type  = $tiny_type->mouse_type;

En interne, c'est ce que fait le drapeau "-mouse" lors de l'importation des fonctions.

Performance de Type::Tiny

Type::Tiny devrait s'exécuter à peu près aussi vite que les types Mouse. C'est parce que, lorsque c'est possible, il utilisera les implémentations XS de Mouse pour les vérifications de type afin d'effectuer le travail le plus lourd.

Il existe quelques contraintes de type pour lesquelles Type::Tiny préfère faire les choses sans l'aide de Mouse, pour des raisons de cohérence et d'exactitude. Par exemple, l'implémentation XS de Mouse pour Bool est... étrange... elle accepte les objets bénis qui surchargent "bool", mais seulement s'ils renvoient false. S'ils renvoient true, c'est une erreur de contrainte de type.

Utiliser Type::Tiny au lieu des contraintes de type de Mouse ne devrait pas faire de différence significative dans les performances de votre code.
