Type::Tiny::Bitfield(3) Documentation Perl fournie par l'utilisateur Type::Tiny::Bitfield(3)

NOM

Type::Tiny::Bitfield - contraintes de type bitfield/bitflag

SYNOPIS

Utilisation de la fonctionnalité d'exportation de Type::Tiny::Bitfield :

package LightSource {
  use Moo;

  use Type::Tiny::Bitfield LedSet => {
    RED   => 1,
    GREEN => 2,
    BLUE  => 4,
  };

  has leds => ( is => 'ro', isa => LedSet, default => 0, coerce => 1 );

  sub new_red {
    my $class = shift;
    return $class->new( leds => LEDSET_RED );
  }

  sub new_green {
    my $class = shift;
    return $class->new( leds => LEDSET_GREEN );
  }

  sub new_yellow {
    my $class = shift;
    return $class->new( leds => LEDSET_RED | LEDSET_GREEN );
  }
}

Utilisation de l'interface orientée objet de Type::Tiny::Bitfield :

package LightSource {
  use Moo;
  use Type::Tiny::Bitfield;

  my $LedSet = Type::Tiny::Bitfield->new(
    name   => 'LedSet',
    values => {
      RED   => 1,
      GREEN => 2,
      BLUE  => 4,
    },
    coercion => 1,
  );

  has leds => ( is => 'ro', isa => $LedSet, default => 0, coerce => 1 );

  sub new_red {
    my $class = shift;
    return $class->new( leds => $LedSet->RED );
  }

  sub new_green {
    my $class = shift;
    return $class->new( leds => $LedSet->GREEN );
  }

  sub new_yellow {
    my $class = shift;
    return $class->new( leds => $LedSet->coerce('red|green') );
  }
}

STATUT

Ce module est couvert par la politique de stabilité de Type-Tiny.

DESCRIPTION

Contraintes de type Bitfield.

Ce paquet hérite de Type::Tiny ; consultez celui-ci pour la plupart de la documentation. Les différences majeures sont listées ci-dessous :

Attributs

"values"
Tableau haché des bits autorisés dans le bitfield. Les clés doivent être des chaînes en majuscules (UPPER_SNAKE_CASE). Les valeurs doivent être des entiers positifs qui sont des puissances de deux. Le même nombre ne peut pas être utilisé plusieurs fois.
"constraint"
Contrairement à Type::Tiny, vous ne pouvez *pas* passer une référence de fonction de contrainte au constructeur. Fiez-vous plutôt à la valeur par défaut.
"inlined"
Contrairement à Type::Tiny, vous ne pouvez *pas* passer une référence de fonction d'intégration (inlining) au constructeur. Fiez-vous plutôt à la valeur par défaut.
"parent"
Le parent est toujours Types::Common::Numeric::PositiveOrZeroInt et ne peut pas être passé au constructeur.
"coercion"
Si "coercion => 1" est passé au constructeur, le type aura une coercition automatique depuis Str. Les types construits par la méthode "import" auront toujours "coercion => 1".

Dans l'exemple SYNOPSIS, la coercition depuis Str acceptera des chaînes telles que :

"RED"
"red"
"Red Green"
"Red+Blue"
"blue | GREEN"
"LEDSET_RED + LeDsEt_green"

Méthodes

Cette classe utilise "AUTOLOAD" pour permettre aux noms de chaque bit dans le bitfield d'être utilisés comme méthodes. Ces noms de méthodes seront toujours en majuscules (UPPER_SNAKE_CASE).

Par exemple, dans la synopsis, "LedSet->GREEN" retournerait 2.

Autres méthodes fournies :

from_string( $str )
Fournit la coercition standard à partir d'une chaîne, même si ce type de contrainte n'a pas de coercition.
to_string( $int )
Effectue la coercition inverse.
constant_names()
C'est une commodité pour permettre : 
use base 'Exporter::Tiny';
push our @EXPORT_OK, LineStyle->constant_names;

Exportations

Type::Tiny::Bitfield peut être utilisé comme exportateur.

use Type::Tiny::Bitfield LedSet => {
  RED    => 1,
  GREEN  => 2,
  BLUE   => 4,
};

Ceci exportera les fonctions suivantes dans votre espace de noms :

"LedSet"
is_LedSet( $value )
assert_LedSet( $value )
to_LedSet( $string )
LedSet_to_Str( $value )
"LEDSET_RED"
"LEDSET_GREEN"
"LEDSET_BLUE"

Plusieurs types bitfield peuvent être exportés en même temps :

use Type::Tiny::Enum (
  LedSet     => { RED => 1, GREEN => 2, BLUE => 4 },
  LedPattern => { FLASHING => 1 },
);

Surcharge d'opérateurs

Il est possible de combiner deux types Bitfield en utilisant l'opérateur "+".

use Type::Tiny::Enum (
  LedSet     => { RED => 1, GREEN => 2, BLUE => 4 },
  LedPattern => { FLASHING => 8 },
);

has leds => (
  is      => 'ro',
  isa     => LedSet + LedPattern,
  default => 0,
  coerce  => 1
);

Ceci autorisera des valeurs comme "11" (LEDSET_RED|LEDSET_GREEN|LEDPATTERN_FLASHING).

Une exception sera levée si certains des noms dans les deux types combinés entrent en conflit.
