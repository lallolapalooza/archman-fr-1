NOM

Type::Tiny::Manual::UsingWithTestMore - Type::Tiny pour les suites de tests

MANUEL

Test::TypeTiny

C'est un module pour tester que les types que vous avez définis acceptent et rejettent les valeurs que vous pensez qu'ils devraient.

should_pass($valeur, $type);
should_fail($autre_valeur, $type);

Facile. (Mais oui, j'oublie toujours si le type va en premier ou en second !)

Il existe également une fonction pour tester que les relations de sous-type/super-type fonctionnent correctement.

ok_subtype($type, @sous_types);

Bien sûr, vous pouvez simplement vérifier un type comme ceci :

ok( $type->check($valeur) );

Mais l'avantage de "should_pass" est que si la variable d'environnement "EXTENDED_TESTING" est définie sur vraie, "should_pass" effectuera également une vérification stricte de la valeur, ce qui implique de remonter l'arbre d'héritage du type (son parent, le parent de son parent, etc.) pour s'assurer que la valeur respecte toutes leurs contraintes.

Si une vérification normale et une vérification stricte diffèrent, c'est généralement un problème quelque part dans le code d'inlining.

Voir Test::TypeTiny pour plus d'informations.

Type::Tiny comme remplacement pour Test::Deep

Voici l'un des exemples de la documentation Test::Deep :

my $name_re = re('^(Mr|Mrs|Miss) \w+ \w+$');
cmp_deeply(
  $person,
  {
    Name       => $name_re,
    Phone      => re('^0d{6}$'),
    ChildNames => array_each($name_re)
  },
  "personne ok"
);

Il est assez facile de réécrire cela pour utiliser Types::Standard :

my $name = StrMatch[ qr/^(Mr|Mrs|Miss) \w+ \w+$/ ];
should_pass(
  $person,
  Dict[
    Name         => $name,
    Phone        => StrMatch[ qr/^0d{6}$/ ],
    ChildNames   => ArrayRef[$name]
  ]
);

Il n'y a rien de particulièrement mal avec Test::Deep, mais si vous connaissez déjà les types intégrés de Type::Tiny et que vous avez peut-être également écrit vos propres bibliothèques de types, cela vous évitera d'avoir à passer d'un système de vérification à deux systèmes distincts.
