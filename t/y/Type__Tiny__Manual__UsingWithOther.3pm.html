NOM

Type::Tiny::Manual::UsingWithOther - utiliser Type::Tiny avec Class::InsideOut, Params::Check et Object::Accessor.

MANUEL

L'équipe des antlers n'est pas la seule à proposer des boîtes à outils de programmation orientée objet en Perl. Bien que Type::Tiny ait peut-être été conçu avec Moose, Mouse et Moo à l'esprit, il peut être utilisé avec d'autres boîtes à outils.

Ces boîtes à outils sont... eh bien... hmm... d'accord... elles existent.

Si vous démarrez un nouveau projet, il y a très peu de raisons de ne pas utiliser Class::Tiny, Moo ou Moose. Vous pouvez donc probablement sauter cette partie de la documentation et passer directement à Type::Tiny::Manual::UsingWithTestMore.

Class::InsideOut

Vous avez besoin de Class::InsideOut 1.13 ou supérieur, qui prend en charge les objets bénis et surchargés (y compris les contraintes de type Type::Tiny) pour les options "get_hook" et "set_hook".

package Person {
  use Class::InsideOut qw( public );
  use Types::Standard qw( Str Int );
  use Types::Common::Numeric qw( PositiveInt );
  use Type::Params qw( signature_for );

  # Les vérifications de type sont très faciles.
  # Fournissez simplement le type comme hook de définition.
  public name => my %_name, {
    set_hook => Str,
  };

  # Définir un type qui convertit silencieusement les valeurs négatives
  # en valeurs positives. C'est bête, mais ça fonctionne comme exemple !
  my $Years = PositiveInt->plus_coercions(Int, q{ abs($_) });

  # Les coercitions sont plus ennuyeuses, mais possibles.
  public age => my %_age, {
    set_hook => sub { $_ = $Years->assert_coerce($_) },
  };

  # La vérification des paramètres pour les méthodes est conforme aux attentes.
  signature_for get_older => ( method => 1, positional => [ $Years ] );

  sub get_older ( $self, $years ) {
    $self->_set_age( $self->age + $years );
  }
}

Params::Check et Object::Accessor

La fonction allow() de Params::Check, l'option "allow" de la fonction check() de Params::Check, et le mécanisme de validation des entrées pour Object::Accessor fonctionnent tous de la même manière, qui est essentiellement une implémentation limitée en pur Perl de l'opérateur de correspondance intelligente (smart match). Bien que cela ne prenne pas en charge directement les contraintes de type Type::Tiny, cela prend en charge les coderefs. Vous pouvez utiliser la méthode "compiled_check" de Type::Tiny pour obtenir un coderef approprié.

Exemple Param::Check :

my $tmpl = {
  name => { allow => Str->compiled_check },
  age  => { allow => Int->compiled_check },
};
check($tmpl, { name => "Bob", age => 32 })
  or die Params::Check::last_error();

Exemple Object::Accessor :

my $obj = Object::Accessor->new;
$obj->mk_accessors(
  { name => Str->compiled_check },
  { age  => Int->compiled_check },
);

Mise en garde : Object::Accessor ne déclenche pas d'erreur lorsqu'une valeur ne respecte pas sa contrainte de type ; il affiche plutôt un avertissement sur STDERR. Ce comportement peut être modifié en réglant "$Object::Accessor::FATAL = 1".

Class::Struct

C'est une preuve de concept sur la façon dont Type::Tiny peut être utilisé pour contraindre les attributs de Class::Struct. Il n'est probablement pas bon d'utiliser cela en production car cela ralentit "UNIVERSAL::isa" globalement.

use Types::Standard -types;
use Class::Struct;
{
  my %MAP;
  my $orig_isa = \&UNIVERSAL::isa;
  *UNIVERSAL::isa = sub {
    return $MAP{$1}->check($_[0])
      if $_[1] =~ /^CLASSSTRUCT::TYPETINY::(.+)$/ && exists $MAP{$1};
    goto $orig;
  };
  my $orig_dn = \&Type::Tiny::display_name;
  *Type::Tiny::display_name = sub {
    if (caller(1) eq 'Class::Struct') {
      $MAP{$_[0]{uniq}} = $_[0];
      return "CLASSSTRUCT::TYPETINY::".$_[0]{uniq};
    }
    goto $orig_dn;
  };
}
struct Person => [ name => Str, age => Int ];
my $bob = Person->new(
  name => "Bob",
  age  => 21,
);
$bob->name("Robert");   # OK
$bob->name([]);         # Échoue

Class::Plain

Il n'y a actuellement pas de haut niveau d'intégration, mais voici un exemple rapide de vérification des types des attributs dans le constructeur.

Si certains de vos accesseurs sont ":rw", vous devrez également y ajouter des vérifications de type.

use Class::Plain;

class Point {
  use Types::Common -types, -sigs;

  field x :reader;
  field y :reader;

  signature_for new => (
    method => !!1,
    bless  => !!0,
    named  => [
      x => Int,
      y => Int,
    ],
  );

  method as_arrayref () {
    return [ $self->x, $self->y ];
  }
}

La signature suivante pourrait également intéresser :

signature_for new => (
  method   => !!1,
  multiple => [
    {
      named => [
        x => Int,
        y => Int,
      ],
      bless => !!0,
    },
    {
      positional => [ Int, Int ],
      goto_next  => sub {
        my ( $class, $x, $y ) = @_;
        return ( $class, { x => $x, y => $y } ),
      },
    },
  ],
);

Cela permettrait à votre classe d'être instanciée en utilisant l'une des méthodes suivantes :

my $point11 = Point->new( { x => 1, y => 1 } );
my $point22 = Point->new(   x => 2, y => 2   );
my $point33 = Point->new( 3, 3 );
