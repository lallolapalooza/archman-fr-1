NOM

Type::Tiny::Manual::Optimization - tirer le meilleur parti de votre processeur

MANUEL

Type::Tiny est écrit en gardant à l'esprit l'efficacité, mais il existe des techniques que vous pouvez utiliser pour obtenir les meilleures performances.

XS

La chose la plus simple que vous puissiez faire pour augmenter les performances de nombreuses contraintes de type intégrées est d'installer Type::Tiny::XS, un ensemble de vérifications de contraintes de type ultra-rapides implémentées en C.

Type::Tiny tentera de charger Type::Tiny::XS et d'utiliser ses vérifications de type. Si Type::Tiny::XS n'est pas disponible, il essaiera alors d'utiliser Mouse *s'il est déjà chargé*, mais Type::Tiny ne tentera pas de charger Mouse pour vous.

Certaines contraintes de type peuvent également être accélérées si vous avez Ref::Util::XS installé.

Types qui peuvent être accélérés par Type::Tiny::XS

Les contraintes de type simples suivantes de Types::Standard seront accélérées par Type::Tiny::XS : Any, ArrayRef, Bool, ClassName, CodeRef, Defined, FileHandle, GlobRef, HashRef, Int, Item, Object, Map, Ref, ScalarRef, Str, Tuple, Undef, et Value. (Notez que Num et RegexpRef ne sont *pas* sur cette liste.)

La forme paramétrée de Ref ne peut pas être accélérée.

Les formes paramétrées de ArrayRef, HashRef, et Map ne peuvent être accélérées que si leurs paramètres le sont.

La forme paramétrée de Tuple peut être accélérée si ses paramètres le sont, si elle n'a pas de composants Optional, et si elle n'utilise pas Slurpy.

Certaines contraintes de type peuvent bénéficier partiellement de Type::Tiny::XS. Par exemple, RoleName hérite de ClassName, donc une partie de la vérification du type sera effectuée par Type::Tiny::XS.

Les contraintes de type paramétrées InstanceOf, HasMethods, et Enum seront accélérées. Il en sera de même pour les objets Type::Tiny::Class, Type::Tiny::Duck, et Type::Tiny::Enum.

Les contraintes de type PositiveInt et PositiveOrZeroInt de Types::Common::Numeric seront accélérées, tout comme la contrainte de type NonEmptyStr de Types::Common::String.

Les types StringLike, CodeLike, HashLike, et ArrayLike de Types::TypeTiny seront accélérés, y compris les versions paramétrées de HashLike et ArrayLike.

Type::Tiny::Union et Type::Tiny::Intersection seront également accélérés si leurs contraintes de type constitutives le sont.

Types qui peuvent être accélérés par Mouse

Les contraintes de type simples suivantes de Types::Standard seront accélérées par Type::Tiny::XS : Any, ArrayRef, Bool, ClassName, CodeRef, Defined, FileHandle, GlobRef, HashRef, Ref, ScalarRef, Str, Undef, et Value. (Notez que Item, Num, Int, Object, et RegexpRef ne sont *pas* sur cette liste.)

La forme paramétrée de Ref ne peut pas être accélérée.

Les formes paramétrées de ArrayRef et HashRef ne peuvent être accélérées que si leurs paramètres le sont.

Certaines contraintes de type peuvent bénéficier partiellement de Mouse. Par exemple, RoleName hérite de ClassName, donc une partie de la vérification du type sera effectuée par Mouse.

Les contraintes de type paramétrées InstanceOf et HasMethods seront accélérées. Il en sera de même pour les objets Type::Tiny::Class et Type::Tiny::Duck.

Inlining des Contraintes de Type

Dans le cas d'une contrainte de type comme celle-ci :

my $type = Int->where( sub { $_ >= 0 } );

Type::Tiny devra appeler une sous-routine pour vérifier qu'une valeur respecte la contrainte de type Int, et votre sous-routine pour vérifier que la valeur est supérieure à zéro.

Les appels de sous-routines en Perl sont relativement coûteux en termes d'utilisation de mémoire et de processeur, il serait donc bon de pouvoir tout faire en un seul appel de sous-routine.

La contrainte de type Int sait comment créer une chaîne de code Perl qui vérifie un entier. C'est quelque chose comme ce qui suit. (C'est en fait plus compliqué, mais c'est assez proche comme exemple.)

$_ =~ /^-?[0-9]+$/

Si vous fournissez votre vérification sous forme de chaîne au lieu d'une sous-routine, comme ceci :

my $type = Int->where( q{ $_ >= 0 } );

Alors Type::Tiny pourra les combiner en une seule chaîne :

( $_ =~ /^-?[0-9]+$/ ) && ( $_ >= 0 )

Ainsi, Type::Tiny pourra vérifier les valeurs en un seul appel de sous-routine. Fournir des contraintes sous forme de chaînes est un moyen très simple et facile d'optimiser les vérifications de type.

Mais cela peut être encore plus efficace. Type::Tiny doit localiser $_ et y copier la valeur pour la vérification ci-dessus. Si vous vérifiez ArrayRef[$type], cela sera fait pour chaque élément du tableau. Les choses pourraient être rendues plus efficaces si Type::Tiny était capable de vérifier directement :

( $arrayref->[$i] =~ /^-?[0-9]+$/ ) && ( $arrayref->[$i] >= 0 )

Cela peut être fait en fournissant une sous-routine d'inlining. La sous-routine reçoit un nom de variable et peut l'utiliser dans la chaîne de code qu'elle génère.

my $type = Type::Tiny->new(
  parent  => Int,
  inlined => sub ( $self, $varname ) {
    return sprintf(
      '(%s) && ( %s >= 0 )',
      $self->parent->inline_check( $varname ),
      $varname,
    );
  }
);

Parce qu'il est assez courant de vouloir appeler la vérification d'inlining du parent et d'y ajouter sa propre chaîne avec un "&&", Type::Tiny fournit un raccourci pour cela. Retournez simplement une liste de chaînes à fusionner avec "&&", et si la première est "undef", Type::Tiny remplira le vide avec la vérification de type parente.

my $type = Type::Tiny->new(
  parent  => Int,
  inlined => sub ( $self, $varname ) {
    return ( undef, sprintf( '%s >= 0', $varname ) );
  },
);

Il existe une optimisation supplémentaire qui peut être appliquée dans ce cas particulier. Vous noterez que nous vérifions que la chaîne correspond à "/^-?[0-9+]$/" puis que nous vérifions qu'elle est supérieure ou égale à zéro. Mais un entier non négatif ne commencera jamais par un signe moins, nous pourrions donc inliner la vérification pour quelque chose comme :

$_ =~ /^[0-9]+$/

Bien qu'une vérification d'inlining *puisse* appeler la vérification de type parente, elle n'est pas obligée de le faire.

my $type = Type::Tiny->new(
  parent  => Int,
  inlined => sub ( $self, $varname ) {
    return sprintf( '%s =~ /^[0-9]+$/', $varname );
  }
);

Si vous choisissez de ne pas appeler la vérification de type parente, vous devez vous assurer que votre propre vérification est au moins aussi rigoureuse.

Inlining des Coercitions

Moo est le seul toolkit de programmation orienté objet qui prend en charge pleinement l'inlining des coercitions, mais même pour Moose et Mouse, fournir des coercitions sous forme de chaînes peut aider Type::Tiny à optimiser ses fonctionnalités de coercition.

Pour Moo, si vous souhaitez que votre coercition soit inlinable, tous les types à partir desquels et vers lesquels vous effectuez la coercition doivent être inlinables, et la coercition doit être fournie sous forme de chaîne de code Perl.

Bon Sens

La contrainte de type HashRef[ArrayRef] peut probablement être vérifiée plus rapidement que HashRef[ArrayRef[Num]]. Si vous vous retrouvez à utiliser des contraintes de type très complexes et lentes, vous devriez envisager de passer à des contraintes plus simples et plus rapides. (Bien que cela signifie que vous devez faire un peu plus confiance à votre appelant pour ne pas vous fournir de mauvaises données.)

(Une exception contre-intuitive à cela : même si Int est plus restrictif que Num, dans la plupart des circonstances, les vérifications Int s'exécuteront plus rapidement.)

Devel::StrictMode

Une possibilité est d'utiliser des vérifications de type strictes lors de l'exécution de vos tests de production, et des vérifications de type plus rapides et plus permissives à d'autres moments. Devel::StrictMode peut faciliter cela.

Cela fournit une constante "STRICT" qui indique si votre code fonctionne en mode "strict" en fonction de certaines variables d'environnement.

Attributs

use Types::Standard qw( ArrayRef Num );
use Devel::StrictMode qw( STRICT );

NOM

Type::Tiny::Manual::Optimization - Optimiser les vérifications de type

MANUEL

Ce manuel décrit comment optimiser l'utilisation de Type::Tiny. Il existe plusieurs façons d'optimiser les vérifications de type, en fonction de vos besoins et de votre environnement.

Utilisation de Devel::StrictMode

Devel::StrictMode est un module qui permet de désactiver les vérifications de type lorsque le mode strict est désactivé. Cela peut considérablement accélérer votre code dans un environnement de production où les erreurs de type sont moins susceptibles de se produire.

Voici un exemple de la façon d'utiliser Devel::StrictMode avec Type::Tiny:

use strict;
use warnings;

use Type::Tiny;
use Devel::StrictMode qw( STRICT );

my $foo = Type::Tiny->new(
    is      => 'ro',
    isa     => STRICT ? Int : Any,
    default => sub { 0 },
);

Dans cet exemple, l'attribut is sera vérifié comme étant un Int en mode strict, mais comme étant n'importe quoi (Any) en mode non strict. La valeur par défaut sera toujours 0.

Il est déconseillé de faire cela sur des attributs qui ont des coercions car cela peut conduire à un comportement incohérent et imprévisible.

Type::Params

Une méthode très efficace qui évite de compiler la signature du tout si "STRICT" est faux :

use Types::Standard qw( Num Object );
use Type::Params qw( signature );
use Devel::StrictMode qw( STRICT );

sub add_number {
  state $check;
  STRICT and $check //= signature(
    method     => 1,
    positional => [ Num ],
  );

  my ( $self, $num ) = STRICT ? &$check : @_;

  push @{ $self->numbers }, $num;
  return $self;
}

Encore une fois, vous devez veiller à assurer un comportement cohérent si vous utilisez des coercions, des valeurs par défaut, des slurpies, etc.

Une méthode moins efficace, mais plus déclarative et suffisamment intelligente pour désactiver uniquement les vérifications qui peuvent être désactivées en toute sécurité (ou presque), tandis que les coercions, les valeurs par défaut et les slurpies continueront de fonctionner :

use Types::Standard qw( Num Object );
use Type::Params qw( signature_for );
use Devel::StrictMode qw( STRICT );

 signature_for add_number => (
   strictness => STRICT,
   method     => 1,
   positional => [ Num ],
 );

 sub add_number ( $self, $num ) {
   push @{ $self->numbers }, $num;
   return $self;
 }

Vérifications de type Ad-Hoc

...;
my $x = get_some_number();
assert_Int $x if STRICT;
return $x + 1;
...;

L'opérateur Slash

Type::Tiny possède une partie de la même logique que Devel::StrictMode intégrée. En particulier, il surcharge l'opérateur slash (division) de sorte que TypeA/TypeB soit évalué à TypeB normalement, mais à TypeA en mode strict.

Un exemple utilisant cette fonctionnalité :

use Types::Standard -types;

has numbers => (
  is      => 'ro',
  isa     => ArrayRef[ Num / Any ],
  default => sub { [] },
);

En mode strict, cet attribut vérifierait que sa valeur est un tableau de nombres (ce qui peut être lent s'il contient beaucoup de nombres). Normalement, cependant, il vérifiera simplement que la valeur est un tableau.
