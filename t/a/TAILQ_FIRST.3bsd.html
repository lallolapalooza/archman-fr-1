TAILQ_HEAD

The macros TAILQ_CONCAT, TAILQ_ENTRY, TAILQ_FIRST, TAILQ_FOREACH, TAILQ_FOREACH_FROM, TAILQ_FOREACH_SAFE, TAILQ_FOREACH_FROM_SAFE, TAILQ_HEAD, TAILQ_HEAD_INITIALIZER, TAILQ_INIT, TAILQ_INSERT_AFTER, TAILQ_INSERT_BEFORE, TAILQ_INSERT_HEAD, TAILQ_INSERT_TAIL, TAILQ_LAST, TAILQ_NEXT, TAILQ_PREV, TAILQ_REMOVE, and TAILQ_SWAP are provided to operate on tail queues. A tail queue is a singly-linked list where pointers are maintained to both the head and tail of the list. This allows for O(1) insertion at either end of the list, but requires an extra pointer per element.

The general syntax for the operations is:

TAILQ_CONCAT(TAILQ_HEAD *head1, TAILQ_HEAD *head2, TYPE *temp_var);
Concatenates the tail queue pointed to by head2 onto the end of the tail queue pointed to by head1. The temp_var argument is needed to allow for concatenation of a tail queue onto itself. After the concatenation, head2 is left empty.
TAILQ_ENTRY(TYPE, NAME);
Declares a structure that links the elements in the tail queue. TYPE is the name of the user defined structure, and NAME is the name of the entry field in the TYPE structure.
TAILQ_FIRST(TAILQ_HEAD *head);
Returns the first element in the tail queue, or NULL if the queue is empty.
TAILQ_FOREACH(TYPE *var, TAILQ_HEAD *head);
Traverses the tail queue referenced by head in the forward direction, assigning each element in turn to var.
TAILQ_FOREACH_FROM(TYPE *var, TAILQ_HEAD *head);
Behaves identically to TAILQ_FOREACH when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.
TAILQ_FOREACH_SAFE(TYPE *var, TAILQ_HEAD *head, TYPE *nextvar);
Traverses the tail queue referenced by head in the forward direction, assigning each element in turn to var. However, unlike TAILQ_FOREACH, it is permitted to both remove var as well as free it from within the loop safely without interfering with the traversal.
TAILQ_FOREACH_FROM_SAFE(TYPE *var, TAILQ_HEAD *head, TYPE *nextvar);
Behaves identically to TAILQ_FOREACH_SAFE when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.
TAILQ_HEAD(HEADNAME, TYPE);
Declares a tail queue head named HEADNAME. TYPE is the name of the user defined structure.
TAILQ_HEAD_INITIALIZER(TAILQ_HEAD head);
Evaluates to an initializer for the tail queue head. This macro can be used to initialize a tail queue statically.
TAILQ_INIT(TAILQ_HEAD *head);
Initializes the tail queue referenced by head.
TAILQ_INSERT_AFTER(TAILQ_HEAD *head, TYPE *listelm, TYPE *elm, TAILQ_ENTRY NAME);
Inserts the new element elm after the element listelm in the tail queue referenced by head. The NAME argument is the name of the entry field within the structure defined by TYPE.
TAILQ_INSERT_BEFORE(TYPE *listelm, TYPE *elm, TAILQ_ENTRY NAME);
Inserts the new element elm before the element listelm in the tail queue. The NAME argument is the name of the entry field within the structure defined by TYPE. This macro can only be used on doubly linked lists and tail queues.
TAILQ_INSERT_HEAD(TAILQ_HEAD *head, TYPE *elm, TAILQ_ENTRY NAME);
Inserts the new element elm at the head of the tail queue referenced by head. The NAME argument is the name of the entry field within the structure defined by TYPE.
TAILQ_INSERT_TAIL(TAILQ_HEAD *head, TYPE *elm, TAILQ_ENTRY NAME);
Inserts the new element elm at the tail of the tail queue referenced by head. The NAME argument is the name of the entry field within the structure defined by TYPE.
TAILQ_LAST(TAILQ_HEAD *head, HEADNAME);
Returns the last element in the tail queue, or NULL if the queue is empty. HEADNAME is the name of the tail queue head structure.
TAILQ_NEXT(TYPE *elm, TAILQ_ENTRY NAME);
Returns the next element in the tail queue after the element elm, or NULL if elm is the last element. The NAME argument is the name of the entry field within the structure defined by TYPE.
TAILQ_PREV(TYPE *elm, HEADNAME, TAILQ_ENTRY NAME);
Returns the previous element in the tail queue before the element elm, or NULL if elm is the first element. HEADNAME is the name of the tail queue head structure. The NAME argument is the name of the entry field within the structure defined by TYPE. This macro can only be used on doubly linked lists and tail queues.
TAILQ_REMOVE(TAILQ_HEAD *head, TYPE *elm, TAILQ_ENTRY NAME);
Removes the element elm from the tail queue referenced by head. The NAME argument is the name of the entry field within the structure defined by TYPE.
TAILQ_SWAP(TAILQ_HEAD *head1, TAILQ_HEAD *head2, TYPE, TAILQ_ENTRY NAME);
Swaps the contents of the tail queues referenced by head1 and head2. The TYPE and NAME arguments are used to ensure type compatibility.

DESCRIPTION

These macros define and operate on four types of data structures which can be used in both C and C++ source code:

  1. Lists
  2. Singly-linked lists
  3. Singly-linked tail queues
  4. Tail queues
All four structures support the following functionality:
  1. Insertion of a new entry at the head of the list.
  2. Insertion of a new entry after any element in the list.
  3. O(1) removal of an entry from the head of the list.
  4. Forward traversal through the list.
  5. Swapping the contents of two lists.

Singly-linked lists are the simplest of the four data structures and support only the above functionality. Singly-linked lists are ideal for applications with large datasets and few or no removals, or for implementing a LIFO queue. Singly-linked lists add the following functionality:

  1. O(n) removal of any entry in the list.
  2. O(n) concatenation of two lists.

Singly-linked tail queues add the following functionality:

  1. Entries can be added at the end of a list.
  2. O(n) removal of any entry in the list.
  3. They may be concatenated.
However:
  1. All list insertions must specify the head of the list.
  2. Each head entry requires two pointers rather than one.
  3. Code size is about 15% greater and operations run about 20% slower than singly-linked lists.

Singly-linked tail queues are ideal for applications with large datasets and few or no removals, or for implementing a FIFO queue.

All doubly linked types of data structures (lists and tail queues) additionally allow:

  1. Insertion of a new entry before any element in the list.
  2. O(1) removal of any entry in the list.
However:
  1. Each element requires two pointers rather than one.
  2. Code size and execution time of operations (except for removal) is about twice that of the singly-linked data-structures.

Linked lists are the simplest of the doubly linked data structures. They add the following functionality over the above:

  1. O(n) concatenation of two lists.
  2. They may be traversed backwards.
However:
  1. To traverse backwards, an entry to begin the traversal and the list in which it is contained must be specified.

Tail queues add the following functionality:

  1. Entries can be added at the end of a list.
  2. They may be traversed backwards, from tail to head.
  3. They may be concatenated.
However:
  1. All list insertions and removals must specify the head of the list.
  2. Each head entry requires two pointers rather than one.
  3. Code size is about 15% greater and operations run about 20% slower than singly-linked lists.

In the macro definitions, TYPE is the name of a user defined structure. The structure must contain a field called NAME which is of type SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY, or TAILQ_ENTRY. In the macro definitions, CLASSTYPE is the name of a user defined class. The class must contain a field called NAME which is of type SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY, or TAILQ_CLASS_ENTRY. The argument HEADNAME is the name of a user defined structure that must be declared using the macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD, or TAILQ_CLASS_HEAD. See the examples below for further explanation of how these macros are used.

SINGLY-LINKED LISTS

A singly-linked list is headed by a structure defined by the SLIST_HEAD macro. This structure contains a single pointer to the first element on the list. The elements are singly linked for minimum space and pointer manipulation overhead at the expense of O(n) removal for arbitrary elements. New elements can be added to the list after an existing element or at the head of the list. An SLIST_HEAD structure is declared as follows:

SLIST_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the list. A pointer to the head of the list can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro SLIST_HEAD_INITIALIZER evaluates to an initializer for the list head.

The macro SLIST_CONCAT concatenates the list headed by head2 onto the end of the one headed by head1 removing all entries from the former. Use of this macro should be avoided as it traverses the entirety of the head1 list. A singly-linked tail queue should be used if this macro is needed in high-usage code paths or to operate on long lists.

The macro SLIST_EMPTY evaluates to true if there are no elements in the list.

The macro SLIST_ENTRY declares a structure that connects the elements in the list.

The macro SLIST_FIRST returns the first element in the list or NULL if the list is empty.

The macro SLIST_FOREACH traverses the list referenced by head in the forward direction, assigning each element in turn to var.

The macro SLIST_FOREACH_FROM behaves identically to SLIST_FOREACH when var is NULL, else it treats var as a previously found SLIST element and begins the loop at var instead of the first element in the SLIST referenced by head.

The macro SLIST_FOREACH_SAFE traverses the list referenced by head in the forward direction, assigning each element in turn to var. However, unlike SLIST_FOREACH() here it is permitted to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro SLIST_FOREACH_FROM_SAFE behaves identically to SLIST_FOREACH_SAFE when var is NULL, else it treats var as a previously found SLIST element and begins the loop at var instead of the first element in the SLIST referenced by head.

The macro SLIST_INIT initializes the list referenced by head.

The macro SLIST_INSERT_HEAD inserts the new element elm at the head of the list.

The macro SLIST_INSERT_AFTER inserts the new element elm after the element listelm in the singly-linked list referenced by head. The NAME argument is the name of the entry field within the structure defined by TYPE.

The macro SLIST_NEXT returns the next element in the singly-linked list after the element elm, or NULL if elm is the last element. The NAME argument is the name of the entry field within the structure defined by TYPE.

The macro SLIST_REMOVE removes the element elm from the singly-linked list referenced by head. The NAME argument is the name of the entry field within the structure defined by TYPE.

The macro SLIST_SWAP swaps the contents of the singly-linked lists referenced by head1 and head2. The TYPE and NAME arguments are used to ensure type compatibility.

EXAMPLE

The following example demonstrates the use of tail queues to maintain a list of struct file structures:

struct file {
        int             f_flags;
        struct fdlink   f_link;         /* list link */
};

TAILQ_HEAD(filelist, file) file_head;
struct file *fp;
struct file *nextfp;

TAILQ_INIT(&file_head);

/* Create and insert new file structures */
fp = malloc(sizeof(*fp));
fp->f_flags = O_RDONLY;
TAILQ_INSERT_TAIL(&file_head, fp, f_link);

fp = malloc(sizeof(*fp));
fp->f_flags = O_WRONLY;
TAILQ_INSERT_TAIL(&file_head, fp, f_link);

/* Traverse the list */
TAILQ_FOREACH(fp, &file_head) {
        printf("File flags: %d\n", fp->f_flags);
}

/* Remove an element from the list */
TAILQ_REMOVE(&file_head, fp, f_link);
free(fp);

/* Traverse the list backwards */
TAILQ_FOREACH_REVERSE(fp, &file_head, filelist) {
        printf("File flags: %d\n", fp->f_flags);
}

/* Remove element safely during traversal */
TAILQ_FOREACH_SAFE(fp, &file_head, nextfp, f_link) {
        if (fp->f_flags & O_RDONLY) {
                TAILQ_REMOVE(&file_head, fp, f_link);
                free(fp);
        }
}

BUGS

TAILQ_CONCAT has linear complexity because it requires traversing the entire first list. In addition, it can not be used to concatenate a tail queue onto itself. A singly-linked tail queue should be used if this macro is needed in high-usage code paths or to operate on long lists.

TAILQ_FOREACH_FROM and TAILQ_FOREACH_FROM_SAFE can not be used to iterate backwards through the list.

FILES D'ATTENTE À QUEUE SIMPLEMENT CHAÎNÉE

Une file d'attente à queue simplement chaînée est dirigée par une structure définie par la macro STAILQ_HEAD. Cette structure contient une paire de pointeurs, l'un vers le premier élément de la file d'attente à queue et l'autre vers le dernier élément de la file d'attente à queue. Les éléments sont simplement chaînés pour un minimum d'espace et de manipulation de pointeurs, au détriment d'une suppression en O(n) pour les éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la file d'attente à queue après un élément existant, à la tête de la file d'attente à queue, ou à la fin de la file d'attente à queue. Une structure STAILQ_HEAD est déclarée comme suit :

STAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la file d'attente à queue. Un pointeur vers la tête de la file d'attente à queue peut ensuite être déclaré comme :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro STAILQ_HEAD_INITIALIZER évalue à un initialiseur pour la file d'attente à queue head.

La macro STAILQ_CONCAT concatène la file d'attente à queue dirigée par head2 à la fin de celle dirigée par head1, en supprimant toutes les entrées de la première.

La macro STAILQ_EMPTY évalue à vrai s'il n'y a pas d'éléments dans la file d'attente à queue.

La macro STAILQ_ENTRY déclare une structure qui relie les éléments de la file d'attente à queue.

La macro STAILQ_FIRST retourne le premier élément de la file d'attente à queue ou NULL si la file d'attente à queue est vide.

La macro STAILQ_FOREACH parcourt la file d'attente à queue référencée par head dans le sens avant, assignant chaque élément tour à tour à var.

La macro STAILQ_FOREACH_FROM se comporte identiquement à STAILQ_FOREACH lorsque var est NULL, sinon elle traite var comme un élément STAILQ précédemment trouvé et commence la boucle à var au lieu du premier élément dans la STAILQ référencée par head.

La macro STAILQ_FOREACH_SAFE parcourt la file d'attente à queue référencée par head dans le sens avant, assignant chaque élément tour à tour à var. Cependant, contrairement à STAILQ_FOREACH(), il est permis ici de supprimer var ainsi que de le libérer depuis l'intérieur de la boucle en toute sécurité sans interférer avec le parcours.

La macro STAILQ_FOREACH_FROM_SAFE se comporte identiquement à STAILQ_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément STAILQ précédemment trouvé et commence la boucle à var au lieu du premier élément dans la STAILQ référencée par head.

La macro STAILQ_INIT initialise la file d'attente à queue référencée par head.

La macro STAILQ_INSERT_HEAD insère le nouveau élément elm à la tête de la file d'attente à queue.

La macro STAILQ_INSERT_TAIL insère le nouveau élément elm à la fin de la file d'attente à queue.

La macro STAILQ_INSERT_AFTER insère le nouveau élément elm après l'élément listelm.

La macro STAILQ_LAST retourne le dernier élément de la file d'attente à queue. Si la file d'attente à queue est vide, la valeur retournée est NULL.

La macro STAILQ_NEXT retourne le prochain élément de la file d'attente à queue, ou NULL si cet élément est le dernier.

La macro STAILQ_REMOVE_AFTER supprime l'élément qui suit elm de la file d'attente à queue. Contrairement à STAILQ_REMOVE, cette macro ne parcourt pas toute la file d'attente à queue.

La macro STAILQ_REMOVE_HEAD supprime l'élément à la tête de la file d'attente à queue. Pour une efficacité optimale, les éléments à supprimer de la tête de la file d'attente à queue devraient utiliser cette macro explicitement plutôt que la macro générique STAILQ_REMOVE.

La macro STAILQ_REMOVE supprime l'élément elm de la file d'attente à queue. L'utilisation de cette macro doit être évitée car elle parcourt toute la liste. Une file d'attente à queue doublement chaînée devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues files d'attente à queue.

La macro STAILQ_SWAP échange le contenu de head1 et head2.

EXEMPLE DE FILE D'ATTENTE À QUEUE SIMPLEMENT CHAÎNÉE

STAILQ_HEAD(stailhead, entry) head =
    STAILQ_HEAD_INITIALIZER(head);
struct stailhead *headp;		/* Tête de file d'attente à queue simplement chaînée. */
struct entry {
	...
	STAILQ_ENTRY(entry) entries;	/* File d'attente à queue. */
	...
} *n1, *n2, *n3, *np;

STAILQ_INIT(&head);			/* Initialiser la file d'attente. */

n1 = malloc(sizeof(struct entry));	/* Insérer à la tête. */
STAILQ_INSERT_HEAD(&head, n1, entries);

n1 = malloc(sizeof(struct entry));	/* Insérer à la fin. */
STAILQ_INSERT_TAIL(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
STAILQ_INSERT_AFTER(&head, n1, n2, entries);
					/* Suppression. */
STAILQ_REMOVE(&head, n2, entry, entries);
free(n2);
					/* Suppression de la tête. */
n3 = STAILQ_FIRST(&head);
STAILQ_REMOVE_HEAD(&head, entries);
free(n3);
					/* Parcours avant. */
STAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sûr. */
STAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	STAILQ_REMOVE(&head, np, entry, entries);
	free(np);
}
					/* Suppression de la File d'attente à Queue. */
while (!STAILQ_EMPTY(&head)) {
	n1 = STAILQ_FIRST(&head);
	STAILQ_REMOVE_HEAD(&head, entries);
	free(n1);
}
					/* Suppression plus rapide de la File d'attente à Queue. */
n1 = STAILQ_FIRST(&head);
while (n1 != NULL) {
	n2 = STAILQ_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
STAILQ_INIT(&head);

LISTES

Une liste est dirigée par une structure définie par la macro LIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont doublement chaînés de manière à ce qu'un élément arbitraire puisse être supprimé sans parcourir la liste. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant, avant un élément existant, ou à la tête de la liste. Une structure LIST_HEAD est déclarée comme suit :

LIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la liste. Un pointeur vers la tête de la liste peut ensuite être déclaré comme :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro LIST_HEAD_INITIALIZER évalue à un initialiseur pour la liste head.

La macro LIST_CONCAT concatène la liste dirigée par head2 à la fin de celle dirigée par head1, en supprimant toutes les entrées de la première. L'utilisation de cette macro doit être évitée car elle parcourt la totalité de la liste head1. Une file d'attente à queue doublement chaînée devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro LIST_EMPTY évalue à vrai s'il n'y a aucun élément dans la liste.

La macro LIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro LIST_FIRST retourne le premier élément de la liste ou NULL si la liste est vide.

La macro LIST_FOREACH parcourt la liste référencée par hea

LISTS

A singly linked list is headed by a structure defined by the LIST_HEAD macro. This structure contains a pointer to the first element in the list. The elements are singly linked so that an arbitrary element may be removed without traversing the list. New elements can be added to the list before or after an existing element, or the new element can be added to the head of the list. A LIST_HEAD structure is declared as follows:

LIST_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the list. A pointer to the head of the list can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro LIST_HEAD_INITIALIZER evaluates to an initializer for the list head.

The macro LIST_EMPTY evaluates to true if there are no items on the list.

The macro LIST_ENTRY declares a structure that connects the elements in the list.

The macro LIST_FIRST returns the first item on the list or NULL if the list is empty.

The macro LIST_FOREACH traverses the list referenced by head in the forward direction, assigning each element in turn to var.

The macro LIST_FOREACH_FROM behaves identically to LIST_FOREACH when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_FOREACH_SAFE traverses the list referenced by head in the forward direction, assigning each element in turn to var. However, unlike LIST_FOREACH() here it is permitted to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro LIST_FOREACH_FROM_SAFE behaves identically to LIST_FOREACH_SAFE when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_INIT initializes the list referenced by head.

The macro LIST_INSERT_HEAD inserts the new element elm at the head of the list.

The macro LIST_INSERT_AFTER inserts the new element elm after the element listelm.

The macro LIST_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro LIST_NEXT returns the next element in the list, or NULL if this is the last.

The macro LIST_PREV returns the previous element in the list, or NULL if this is the first. List head must contain element elm.

The macro LIST_REMOVE removes the element elm from the list.

The macro LIST_SWAP swaps the contents of head1 and head2.

LIST EXAMPLE

LIST_HEAD(listhead, entry) head =
    LIST_HEAD_INITIALIZER(head);
struct listhead *headp;			/* List head. */
struct entry {
	...
	LIST_ENTRY(entry) entries;	/* List. */
	...
} *n1, *n2, *n3, *np, *np_temp;

LIST_INIT(&head);			/* Initialize the list. */

n1 = malloc(sizeof(struct entry));	/* Insert at the head. */
LIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insert after. */
LIST_INSERT_AFTER(n1, n2, entries);

n3 = malloc(sizeof(struct entry));	/* Insert before. */
LIST_INSERT_BEFORE(n2, n3, entries);

LIST_REMOVE(n2, entries);		/* Deletion. */
free(n2);
					/* Forward traversal. */
LIST_FOREACH(np, &head, entries)
	np-> ...

					/* Safe forward traversal. */
LIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	LIST_REMOVE(np, entries);
	free(np);
}

while (!LIST_EMPTY(&head)) {		/* List Deletion. */
	n1 = LIST_FIRST(&head);
	LIST_REMOVE(n1, entries);
	free(n1);
}

n1 = LIST_FIRST(&head);			/* Faster List Deletion. */
while (n1 != NULL) {
	n2 = LIST_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
LIST_INIT(&head);

TAIL QUEUES

A tail queue is headed by a structure defined by the TAILQ_HEAD macro. This structure contains a pair of pointers, one to the first element in the tail queue and the other to the last element in the tail queue. The elements are doubly linked so that an arbitrary element can be removed without traversing the tail queue. New elements can be added to the tail queue after an existing element, before an existing element, at the head of the tail queue, or at the end of the tail queue. A TAILQ_HEAD structure is declared as follows:

TAILQ_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the tail queue. A pointer to the head of the tail queue can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro TAILQ_HEAD_INITIALIZER evaluates to an initializer for the tail queue head.

The macro TAILQ_CONCAT concatenates the tail queue headed by head2 onto the end of the one headed by head1 removing all entries from the former.

The macro TAILQ_EMPTY evaluates to true if there are no items on the tail queue.

The macro TAILQ_ENTRY declares a structure that connects the elements in the tail queue.

The macro TAILQ_FIRST returns the first item on the tail queue or NULL if the tail queue is empty.

The macro TAILQ_FOREACH traverses the tail queue referenced by head in the forward direction, assigning each element in turn to var. var is set to NULL if the loop completes normally, or if there were no elements.

The macro TAILQ_FOREACH_FROM behaves identically to TAILQ_FOREACH when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.

The macro TAILQ_FOREACH_REVERSE traverses the tail queue referenced by head in the reverse direction, assigning each element in turn to var.

The macro TAILQ_FOREACH_REVERSE_FROM behaves identically to TAILQ_FOREACH_REVERSE when var is NULL, else it treats var as a previously found TAILQ element and begins the reverse loop at var instead of the last element in the TAILQ referenced by head.

The macros TAILQ_FOREACH_SAFE and TAILQ_FOREACH_REVERSE_SAFE traverse the list referenced by head in the forward or reverse direction respectively, assigning each element in turn to var. However, unlike their unsafe counterparts, TAILQ_FOREACH and TAILQ_FOREACH_REVERSE make it possible to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro TAILQ_FOREACH_FROM_SAFE behaves identically to TAILQ_FOREACH_SAFE when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.

The macro TAILQ_FOREACH_REVERSE_FROM_SAFE behaves identically to TAILQ_FOREACH_REVERSE_SAFE when var is NULL, else it treats var as a previously found TAILQ element and begins the reverse loop at var instead of the last element in the TAILQ referenced by head.

The macro TAILQ_INIT initializes the tail queue referenced by head.

The macro TAILQ_INSERT_HEAD inserts the new element elm at the head of the tail queue.

The macro TAILQ_INSERT_TAIL inserts the new element elm at the end of the tail queue.

The macro TAILQ_INSERT_AFTER inserts the new element elm after the element listelm.

The macro TAILQ_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro TAILQ_LAST returns the last item on the tail queue. If the tail queue is empty the return value is NULL.

The macro TAILQ_NEXT returns the next item on the tail queue, or NULL if this item is the last.

The macro TAILQ_PREV returns the previous item on the tail queue, or NULL if this item is the first.

The macro TAILQ_REMOVE removes the element elm from the tail queue.

The macro TAILQ_SWAP swaps the contents of head1 and head2.

TAIL QUEUE EXAMPLE

TAILQ_HEAD(tailhead, entry) head =
    TAILQ_HEAD_INITIALIZER(head);
struct tailhead *headp;			/* Tail queue head. */
struct entry {
	...
	TAILQ_ENTRY(entry) entries;	/* Tail queue. */
	...
} *n1, *n2, *n3, *np;

TAILQ_INIT(&head);			/* Initialize the queue. */

n1 = malloc(sizeof(struct entry));	/* Insert at the tail. */

n3 = malloc(sizeof(struct entry));	/* Insert before. */
TAILQ_INSERT_BEFORE(n2, n3, entries);

TAILQ_REMOVE(&head, n2, entries);	/* Deletion. */
free(n2);
					/* Forward traversal. */
TAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* Safe forward traversal. */
TAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	TAILQ_REMOVE(&head, np, entries);
	free(np);
}
					/* Reverse traversal. */
TAILQ_FOREACH_REVERSE(np, &head, tailhead, entries)
	np-> ...
					/* TailQ Deletion. */
while (!TAILQ_EMPTY(&head)) {
	n1 = TAILQ_FIRST(&head);
	TAILQ_REMOVE(&head, n1, entries);
	free(n1);
}
					/* Faster TailQ Deletion. */
n1 = TAILQ_FIRST(&head);
while (n1 != NULL) {

	n1 = n2;

DIAGNOSTICS

Lors du débogage de queue(3), il peut être utile de suivre les changements de file d'attente. Pour activer le traçage, définissez la macro QUEUE_MACRO_DEBUG_TRACE au moment de la compilation.

Il peut également être utile de corrompre les pointeurs qui ont été désenchaînés d'une file d'attente, pour détecter une utilisation après suppression. Pour activer la corruption des pointeurs, définissez la macro QUEUE_MACRO_DEBUG_TRASH au moment de la compilation. La macro QMD_IS_TRASHED(void *ptr) renvoie vrai si ptr a été corrompu par l'option QUEUE_MACRO_DEBUG_TRASH.
