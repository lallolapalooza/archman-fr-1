TAP::Parser::IteratorFactory(3perl) Guide de référence du programmeur Perl TAP::Parser::IteratorFactory(3perl)

NOM

TAP::Parser::IteratorFactory - Détermine quels objets SourceHandler utiliser pour une Source donnée

VERSION

Version 3.50

SYNOPSIS

use TAP::Parser::IteratorFactory;
my $factory = TAP::Parser::IteratorFactory->new({ %config });
my $iterator  = $factory->make_iterator( $filename );

DESCRIPTION

Ceci est une classe usine qui prend une TAP::Parser::Source et la passe à tous les TAP::Parser::SourceHandlers enregistrés pour voir lequel devrait gérer la source.

Si vous êtes un auteur de plugin, vous serez intéressé par la façon d'"enregistrer_gestionnaire" (register_handler), par le fonctionnement de "détecter_source" (detect_source).

MÉTHODES

Méthodes de classe

"new"

Crée une nouvelle classe usine :

my $sf = TAP::Parser::IteratorFactory->new( $config );

$config est optionnel. S'il est fourni, il définit "config" et appelle "load_handlers".

"register_handler"

Enregistre un nouveau TAP::Parser::SourceHandler avec cette usine.

__PACKAGE__->register_handler( $handler_class );

"handlers"

Liste des gestionnaires qui ont été enregistrés.

Méthodes d'instance

"config"

my $cfg = $sf->config;
$sf->config({ Perl => { %config } });

Accesseur/mutateur en chaîne pour la configuration des gestionnaires de source disponibles. Il s'agit d'un hashref indexé par la classe du gestionnaire dont les valeurs contiennent la configuration à passer aux gestionnaires lors de la détection et de la création. Les noms de classe peuvent être complètement qualifiés ou abrégés, par ex. :

# ceux-ci sont équivalents
$sf->config({ 'TAP::Parser::SourceHandler::Perl' => { %config } });
$sf->config({ 'Perl' => { %config } });

"load_handlers"

$sf->load_handlers;

Charge les classes de gestionnaires définies dans "config". Par exemple, étant donné une configuration :

$sf->config({
  MySourceHandler => { some => 'config' },
});

"load_handlers" tentera de charger la classe "MySourceHandler" en la recherchant dans @INC dans cet ordre :

TAP::Parser::SourceHandler::MySourceHandler
MySourceHandler

La méthode "croak" est appelée en cas d'erreur.

"make_iterator"

my $iterator = $src_factory->make_iterator( $source );

Étant donné une TAP::Parser::Source, trouve le TAP::Parser::SourceHandler le plus approprié à utiliser pour créer un TAP::Parser::Iterator (voir "detect_source"). S'arrête en cas d'erreur.

"detect_source"

Étant donné une TAP::Parser::Source, détecte quel type de source c'est et renvoie *un* TAP::Parser::SourceHandler (celui qui est le plus confiant). S'arrête en cas d'erreur.

L'algorithme de détection fonctionne à peu près comme suit :

for (@registered_handlers) {
  # on leur demande à quel point ils sont confiants pour gérer cette source
  $confidence{$handler} = $handler->can_handle( $source )
}
# choisir le gestionnaire le plus confiant

Les égalités sont gérées en choisissant le premier gestionnaire.

SOUS-CLASSEMENT

Veuillez consulter "SUBCLASSING" dans TAP::Parser pour un aperçu du sous-classement.

Exemple

Si nous avons bien fait les choses, vous voudrez probablement écrire une nouvelle source, plutôt que de sous-classer celle-ci (voir TAP::Parser::SourceHandler pour cela).

Mais au cas où vous en trouveriez le besoin...

package MyIteratorFactory;
use strict;
use base 'TAP::Parser::IteratorFactory';
# remplacer l'algorithme de détection de source
sub detect_source {
  my ($self, $raw_source_ref, $meta) = @_;
  # faire le travail de détective, en utilisant $meta et tout le reste...
}
1;
