DESCRIPTION

Ces macros définissent et opèrent sur quatre types de structures de données qui peuvent être utilisées dans du code source C et C++ :

  1. Listes
  2. Listes chaînées simplement
  3. Files à queue chaînées simplement
  4. Files à queue
Les quatre structures prennent en charge la fonctionnalité suivante :
  1. Insertion d'une nouvelle entrée en tête de liste.
  2. Insertion d'une nouvelle entrée après un élément quelconque de la liste.
  3. Suppression en O(1) d'une entrée en tête de liste.
  4. Parcours avant dans la liste.
  5. Échange du contenu de deux listes.

Les listes chaînées simplement sont les plus simples des quatre structures de données et ne prennent en charge que la fonctionnalité ci-dessus. Les listes chaînées simplement sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une file LIFO. Les listes chaînées simplement ajoutent la fonctionnalité suivante :

  1. Suppression en O(n) de n'importe quelle entrée dans la liste.
  2. Concaténation en O(n) de deux listes.

Les files à queue chaînées simplement ajoutent la fonctionnalité suivante :

  1. Des entrées peuvent être ajoutées à la fin d'une liste.
  2. Suppression en O(n) de n'importe quelle entrée dans la liste.
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions de liste doivent spécifier la tête de la liste.
  2. Chaque entrée de tête nécessite deux pointeurs plutôt qu'un seul.
  3. La taille du code est environ 15% plus grande et les opérations sont environ 20% plus lentes que pour les listes chaînées simplement.

Les files à queue chaînées simplement sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une file FIFO.

Tous les types de structures de données doublement chaînées (listes et files à queue) permettent en plus :

  1. Insertion d'une nouvelle entrée avant n'importe quel élément de la liste.
  2. Suppression en O(1) de n'importe quelle entrée de la liste.
Cependant :
  1. Chaque élément nécessite deux pointeurs au lieu d'un seul.
  2. La taille du code et le temps d'exécution des opérations (sauf la suppression) sont environ le double de ceux des structures de données chaînées simplement.

Les listes chaînées sont les plus simples des structures de données doublement chaînées. Elles ajoutent la fonctionnalité suivante par rapport à ce qui précède :

  1. Concaténation en O(n) de deux listes.
  2. Elles peuvent être parcourues en arrière.
Cependant :
  1. Pour parcourir en arrière, une entrée pour commencer le parcours et la liste dans laquelle elle est contenue doivent être spécifiées.

Les files à queue ajoutent la fonctionnalité suivante :

  1. Des entrées peuvent être ajoutées à la fin d'une liste.
  2. Elles peuvent être parcourues en arrière, de la queue à la tête.
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions et suppressions de liste doivent spécifier la tête de la liste.
  2. Chaque entrée de tête nécessite deux pointeurs plutôt qu'un seul.
  3. La taille du code est environ 15% plus grande et les opérations sont environ 20% plus lentes que pour les listes chaînées simplement.

Dans les définitions de macros, TYPE est le nom d'une structure définie par l'utilisateur. La structure doit contenir un champ appelé NAME qui est de type SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY, ou TAILQ_ENTRY. Dans les définitions de macros, CLASSTYPE est le nom d'une classe définie par l'utilisateur. La classe doit contenir un champ appelé NAME qui est de type SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY, ou TAILQ_CLASS_ENTRY. L'argument HEADNAME est le nom d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD, ou TAILQ_CLASS_HEAD. Voir les exemples ci-dessous pour plus d'explications sur l'utilisation de ces macros.

LISTES CHAÎNÉES SIMPLEMENT

Une liste chaînée simplement est dirigée par une structure définie par la macro SLIST_HEAD. Cette structure contient un unique pointeur vers le premier élément de la liste. Les éléments sont chaînés simplement pour une minimisation de l'espace et des frais généraux de manipulation des pointeurs, au détriment d'une suppression en O(n) pour les éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant ou en tête de liste. Une structure SLIST_HEAD est déclarée comme suit :

SLIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la liste. Un pointeur vers la tête de la liste peut ensuite être déclaré comme :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro SLIST_HEAD_INITIALIZER évalue à un initialiseur pour la liste head.

La macro SLIST_CONCAT concatène la liste dirigée par head2 à la fin de celle dirigée par head1, supprimant toutes les entrées de la première. L'utilisation de cette macro doit être évitée car elle parcourt la totalité de la liste head1. Une file à queue chaînée simplement devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro SLIST_EMPTY évalue à vrai s'il n'y a aucun élément dans la liste.

La macro SLIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro SLIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro SLIST_FOREACH parcourt la liste référencée par head dans le sens avant, attribuant chaque élément tour à tour à var.

La macro SLIST_FOREACH_FROM se comporte identiquement à SLIST_FOREACH lorsque var est NULL, sinon elle traite var comme un élément SLIST précédemment trouvé et commence la boucle à var au lieu du premier élément de la SLIST référencée par head.

La macro SLIST_FOREACH_SAFE parcourt la liste référencée par head dans le sens avant, attribuant chaque élément tour à tour à var. Cependant, contrairement à SLIST_FOREACH(), il est permis de supprimer var ainsi que de le libérer depuis l'intérieur de la boucle en toute sécurité sans interférer avec le parcours.

La macro SLIST_FOREACH_FROM_SAFE se comporte identiquement à SLIST_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément SLIST précédemment trouvé et commence la boucle à var au lieu du premier élément de la SLIST référencée par head.

La macro SLIST_INIT initialise la liste référencée par head.

La macro SLIST_INSERT_HEAD insère le nouvel élément elm en tête de liste.

La macro SLIST_INSERT_AFTER insère le nouvel élément elm après l'élément

var class="Fa">listelm.

La macro SLIST_NEXT renvoie le nœud suivant de la liste.

La macro SLIST_REMOVE_AFTER supprime le nœud qui suit elm de la liste. Contrairement à SLIST_REMOVE, cette macro ne parcourt pas toute la liste.

La macro SLIST_REMOVE_HEAD supprime le nœud elm du début de la liste. Pour des raisons d'optimisation, les nœuds à supprimer du début de la liste doivent utiliser explicitement cette macro plutôt que la macro générique SLIST_REMOVE.

La macro SLIST_REMOVE supprime le nœud elm de la liste. L'utilisation de cette macro doit être évitée car elle parcourt toute la liste. Les listes doublement chaînées doivent être utilisées si cette macro doit être employée dans des chemins de code à utilisation intensive ou pour opérer sur de longues listes.

La macro SLIST_SWAP échange le contenu de head1 et head2.

SINGLY-LINKED LIST EXAMPLE

SLIST_HEAD(slisthead, entry) head =
    SLIST_HEAD_INITIALIZER(head);
struct slisthead *headp;		/* Tête de liste chaînée simple. */
struct entry {
	...
	SLIST_ENTRY(entry) entries;	/* Liste chaînée simple. */
	...
} *n1, *n2, *n3, *np;

SLIST_INIT(&head);			/* Initialisation de la liste. */

n1 = malloc(sizeof(struct entry));	/* Insertion en tête. */
SLIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insertion après. */
SLIST_INSERT_AFTER(n1, n2, entries);

SLIST_REMOVE(&head, n2, entry, entries);/* Suppression. */
free(n2);

n3 = SLIST_FIRST(&head);
SLIST_REMOVE_HEAD(&head, entries);	/* Suppression depuis la tête. */
free(n3);
					/* Parcours avant. */
SLIST_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sécurisé. */
SLIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	SLIST_REMOVE(&head, np, entry, entries);
	free(np);
}

while (!SLIST_EMPTY(&head)) {		/* Suppression de liste. */
	n1 = SLIST_FIRST(&head);
	SLIST_REMOVE_HEAD(&head, entries);
	free(n1);
}

SINGLY-LINKED TAIL QUEUES

Une queue chaînée simple est dirigée par une structure définie à l'aide de la macro STAILQ_HEAD. Cette structure contient une paire de pointeurs, l'un vers le premier élément de la queue, et l'autre vers le dernier élément de la queue. Les éléments sont chaînés de manière à minimiser la surcharge d'espace et la manipulation des pointeurs, au détriment d'une suppression d'éléments arbitraires en O(n). De nouveaux éléments peuvent être ajoutés à la queue après un élément existant, au début de la queue, ou à la fin de la queue. Une structure STAILQ_HEAD est déclarée comme suit :

STAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments de la queue. Un pointeur vers la tête de la queue peut être déclaré ultérieurement comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont choisis par l'utilisateur.)

La macro STAILQ_HEAD_INITIALIZER est le résultat d'un initialiseur pour la queue head.

La macro STAILQ_CONCAT concatène la queue dirigée par head2 à la fin de la queue dirigée par head1, vidant ainsi la première.

La macro STAILQ_EMPTY est évaluée à vrai si la queue ne contient aucun élément.

La macro STAILQ_ENTRY déclare une structure qui relie les éléments de la queue.

La macro STAILQ_FIRST renvoie le premier élément de la queue, ou NULL si la queue est vide.

La macro STAILQ_FOREACH parcourt la queue dirigée par head dans le sens avant, assignant chaque élément à var.

La macro STAILQ_FOREACH_FROM se comporte de manière similaire à STAILQ_FOREACH lorsque var est NULL ; sinon, elle traite var comme un élément précédemment trouvé dans la queue et commence la boucle à partir de var au lieu du premier élément de la queue dirigée par head.

La macro STAILQ_FOREACH_SAFE parcourt la queue dirigée par head dans le sens avant, assignant chaque élément à var. Cependant, contrairement à STAILQ_FOREACH(), il est permis de supprimer var et de le libérer en toute sécurité dans la boucle sans interférer avec le parcours.

La macro STAILQ_FOREACH_FROM_SAFE se comporte de manière similaire à STAILQ_FOREACH_SAFE lorsque var est NULL ; sinon, elle traite var comme un élément précédemment trouvé dans la queue et commence la boucle à partir de var au lieu du premier élément de la queue dirigée par head.

La macro STAILQ_INIT initialise la queue dirigée par head.

La macro STAILQ_INSERT_HEAD insère le nouveau nœud elm au début de la queue.

La macro STAILQ_INSERT_TAIL insère le nouveau nœud elm à la fin de la queue.

La macro STAILQ_INSERT_AFTER insère le nouveau nœud elm après le nœud listelm.

La macro STAILQ_LAST renvoie le dernier élément de la queue. Si la queue est vide, la valeur renvoyée est NULL.

La macro STAILQ_NEXT renvoie le nœud suivant de la queue, ou NULL s'il s'agit du dernier.

La macro STAILQ_REMOVE_AFTER supprime le nœud qui suit elm de la queue. Contrairement à STAILQ_REMOVE, cette macro ne parcourt pas toute la queue.

La macro STAILQ_REMOVE_HEAD supprime le nœud au début de la queue. Pour optimiser l'efficacité, les nœuds à supprimer du début de la queue doivent explicitement utiliser cette macro plutôt que la macro générique STAILQ_REMOVE.

La macro STAILQ_REMOVE supprime le nœud elm de la queue. L'utilisation de cette macro doit être évitée car elle parcourt toute la liste. Les queues doublement chaînées doivent être utilisées si cette macro doit être utilisée dans des chemins de code à utilisation intensive ou pour opérer sur de longues queues.

La macro STAILQ_SWAP échange le contenu de head1 et head2.

SINGLY-LINKED TAIL QUEUE EXAMPLE

STAILQ_HEAD(stailhead, entry) head =
    STAILQ_HEAD_INITIALIZER(head);
struct stailhead *headp;		/* Tête de queue chaînée simple. */
struct entry {
	...
	STAILQ_ENTRY(entry) entries;	/* Queue chaînée. */
	...
} *n1, *n2, *n3, *np;

STAILQ_INIT(&head);			/* Initialisation de la queue. */

n1 = malloc(sizeof(struct entry));	/* Insertion en tête. */
STAILQ_INSERT_HEAD(&head, n1, entries);

n1 = malloc(sizeof(struct entry));	/* Insertion en fin. */
STAILQ_INSERT_TAIL(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insertion après. */
STAILQ_INSERT_AFTER(&head, n1, n2, entries);
					/* Suppression. */
STAILQ_REMOVE(&head, n2, entry, entries);
free(n2);
					/* Suppression depuis la tête. */
n3 = STAILQ_FIRST(&head);
STAILQ_REMOVE_HEAD(&head, entries);
free(n3);
					/* Parcours avant. */
STAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sécurisé. */
STAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	STAILQ_REMOVE(&head, np, entry, entries);
	free(np);
}
					/* Suppression de queue. */
while (!STAILQ_EMPTY(&head)) {
	n1 = STAILQ_FIRST(&head);
	STAILQ_REMOVE_HEAD(&head, entries);
	free(n1);
}
					/* Suppression plus rapide de queue. */
n1 = STAILQ_FIRST(&head);
while (n1 != NULL) {
	n2 = STAILQ_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
STAILQ_INIT(&head);

LISTS

Une liste est dirigée par une structure définie à l'aide de la macro LIST_HEAD. Cette structure contient un pointeur unique vers le premier élément de la liste. Les éléments sont doublement chaînés afin qu'un élément arbitraire puisse être supprimé sans parcourir toute la liste. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant, avant un élément existant, ou au début de la liste. Une structure LIST_HEAD est déclarée comme suit :

LIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments de la liste. Un pointeur vers la tête de la liste peut être déclaré ultérieurement comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont choisis par l'utilisateur.)

La macro LIST_HEAD_INITIALIZER est le résultat d'un initialiseur pour la liste head.

La macro LIST_CONCAT concatène la liste dirigée par head2 à la fin de la liste dirigée par head1, vidant ainsi la première. L'utilisation de cette macro doit être évitée car elle parcourt toute la liste dirigée par head1. Une queue doit être utilisée si cette macro doit être utilisée dans des chemins de code à utilisation intensive ou pour opérer sur de longues listes.

La macro LIST_EMPTY est évaluée à vrai si la liste ne contient aucun élément.

La macro LIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro LIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro LIST_FOREACH parcourt la liste dirigée par F

LISTS

A singly linked list is headed by a structure defined by the LIST_HEAD macro. This structure contains a pointer to the first element in the list. The elements are singly linked so that an arbitrary element can be removed only by traversing the list starting from the first element. New elements can be added to the list before an existing element, or at the head of the list. A LIST_HEAD structure is declared as follows:

LIST_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the list. A pointer to the head of the list can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro LIST_HEAD_INITIALIZER evaluates to an initializer for the list head.

The macro LIST_EMPTY evaluates to true if there are no items on the list.

The macro LIST_ENTRY declares a structure that connects the elements in the list.

The macro LIST_FIRST returns the first item on the list or NULL if the list is empty.

The macro LIST_FOREACH traverses the list referenced by head in the forward direction, assigning each element in turn to var.

The macro LIST_FOREACH_FROM behaves identically to LIST_FOREACH when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_FOREACH_SAFE traverses the list referenced by head in the forward direction, assigning each element in turn to var. However, unlike LIST_FOREACH() here it is permitted to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro LIST_FOREACH_FROM_SAFE behaves identically to LIST_FOREACH_SAFE when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_INIT initializes the list referenced by head.

The macro LIST_INSERT_HEAD inserts the new element elm at the head of the list.

The macro LIST_INSERT_AFTER inserts the new element elm after the element listelm.

The macro LIST_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro LIST_NEXT returns the next element in the list, or NULL if this is the last.

The macro LIST_PREV returns the previous element in the list, or NULL if this is the first. List head must contain element elm.

The macro LIST_REMOVE removes the element elm from the list.

The macro LIST_SWAP swaps the contents of head1 and head2.

LIST EXAMPLE

LIST_HEAD(listhead, entry) head =
    LIST_HEAD_INITIALIZER(head);
struct listhead *headp;			/* List head. */
struct entry {
	...
	LIST_ENTRY(entry) entries;	/* List. */
	...
} *n1, *n2, *n3, *np, *np_temp;

LIST_INIT(&head);			/* Initialize the list. */

n1 = malloc(sizeof(struct entry));	/* Insert at the head. */
LIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insert after. */
LIST_INSERT_AFTER(n1, n2, entries);

n3 = malloc(sizeof(struct entry));	/* Insert before. */
LIST_INSERT_BEFORE(n2, n3, entries);

LIST_REMOVE(n2, entries);		/* Deletion. */
free(n2);
					/* Forward traversal. */
LIST_FOREACH(np, &head, entries)
	np-> ...

					/* Safe forward traversal. */
LIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	LIST_REMOVE(np, entries);
	free(np);
}

while (!LIST_EMPTY(&head)) {		/* List Deletion. */
	n1 = LIST_FIRST(&head);
	LIST_REMOVE(n1, entries);
	free(n1);
}

n1 = LIST_FIRST(&head);			/* Faster List Deletion. */
while (n1 != NULL) {
	n2 = LIST_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
LIST_INIT(&head);

TAIL QUEUES

A tail queue is headed by a structure defined by the TAILQ_HEAD macro. This structure contains a pair of pointers, one to the first element in the tail queue and the other to the last element in the tail queue. The elements are doubly linked so that an arbitrary element can be removed without traversing the tail queue. New elements can be added to the tail queue after an existing element, before an existing element, at the head of the tail queue, or at the end of the tail queue. A TAILQ_HEAD structure is declared as follows:

TAILQ_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the tail queue. A pointer to the head of the tail queue can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro TAILQ_HEAD_INITIALIZER evaluates to an initializer for the tail queue head.

The macro TAILQ_CONCAT concatenates the tail queue headed by head2 onto the end of the one headed by head1 removing all entries from the former.

The macro TAILQ_EMPTY evaluates to true if there are no items on the tail queue.

The macro TAILQ_ENTRY declares a structure that connects the elements in the tail queue.

The macro TAILQ_FIRST returns the first item on the tail queue or NULL if the tail queue is empty.

The macro TAILQ_FOREACH traverses the tail queue referenced by head in the forward direction, assigning each element in turn to var. var is set to NULL if the loop completes normally, or if there were no elements.

The macro TAILQ_FOREACH_FROM behaves identically to TAILQ_FOREACH when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.

The macro TAILQ_FOREACH_REVERSE traverses the tail queue referenced by head in the reverse direction, assigning each element in turn to var.

The macro TAILQ_FOREACH_REVERSE_FROM behaves identically to TAILQ_FOREACH_REVERSE when var is NULL, else it treats var as a previously found TAILQ element and begins the reverse loop at var instead of the last element in the TAILQ referenced by head.

The macros TAILQ_FOREACH_SAFE and TAILQ_FOREACH_REVERSE_SAFE traverse the list referenced by head in the forward or reverse direction respectively, assigning each element in turn to var. However, unlike their unsafe counterparts, TAILQ_FOREACH and TAILQ_FOREACH_REVERSE make it possible to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro TAILQ_FOREACH_FROM_SAFE behaves identically to TAILQ_FOREACH_SAFE when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.

The macro TAILQ_FOREACH_REVERSE_FROM_SAFE behaves identically to TAILQ_FOREACH_REVERSE_SAFE when var is NULL, else it treats var as a previously found TAILQ element and begins the reverse loop at var instead of the last element in the TAILQ referenced by head.

The macro TAILQ_INIT initializes the tail queue referenced by head.

The macro TAILQ_INSERT_HEAD inserts the new element elm at the head of the tail queue.

The macro TAILQ_INSERT_TAIL inserts the new element elm at the end of the tail queue.

The macro TAILQ_INSERT_AFTER inserts the new element elm after the element listelm.

The macro TAILQ_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro TAILQ_LAST returns the last item on the tail queue. If the tail queue is empty the return value is NULL.

The macro TAILQ_NEXT returns the next item on the tail queue, or NULL if this item is the last.

The macro TAILQ_PREV returns the previous item on the tail queue, or NULL if this item is the first.

The macro TAILQ_REMOVE removes the element elm from the tail queue.

The macro TAILQ_SWAP swaps the contents of head1 and head2.

DIAGNOSTICS

Lorsque le débogage de queue(3) est nécessaire, il peut être utile de tracer les changements de file d'attente. Pour activer le traçage, définissez la macro QUEUE_MACRO_DEBUG_TRACE au moment de la compilation.

Il peut également être utile de corrompre les pointeurs qui ont été retirés d'une file d'attente, afin de détecter une utilisation après suppression. Pour activer la corruption des pointeurs, définissez la macro QUEUE_MACRO_DEBUG_TRASH au moment de la compilation. La macro QMD_IS_TRASHED(void *ptr) retourne vrai si ptr a été corrompu par l'option QUEUE_MACRO_DEBUG_TRASH.
