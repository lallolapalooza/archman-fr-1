TAP::Parser::Scheduler(3perl) Guide de référence des programmeurs Perl TAP::Parser::Scheduler(3perl)

NOM

TAP::Parser::Scheduler - Planifie les tests lors des tests parallèles

VERSION

Version 3.50

SYNOPIS

use TAP::Parser::Scheduler;

DESCRIPTION

MÉTHODES

Méthodes de classe

"new"

my $sched = TAP::Parser::Scheduler->new(tests => \@tests);
my $sched = TAP::Parser::Scheduler->new(
    tests => [ ['t/nom_test.t','Description du Test'], ... ],
    rules => \%rules,
);

Étant donné 'tests' et des 'rules' optionnelles en entrée, retourne un nouvel objet "TAP::Parser::Scheduler". Chaque membre de @tests doit être soit le nom d'un fichier de test, soit un tableau à deux éléments, où le premier élément est un nom de fichier de test et le second élément est une description du test. Par défaut, nous utiliserons le nom du test comme description.

L'attribut optionnel "rules" fournit des indications sur les tests qui doivent être exécutés en parallèle et ceux qui doivent être exécutés séquentiellement. Si aucune structure de données de règles n'est fournie, une structure de données par défaut est utilisée qui rend chaque test éligible à être exécuté en parallèle :

{ par => '**' },

La structure de données des règles est documentée plus en détail dans la section suivante.

Structure de données des règles

La structure de données ""rules"" est le cœur du planificateur. Elle vous permet d'exprimer des règles simples comme "exécuter tous les tests en séquence" ou "exécuter tous les tests en parallèle sauf ces cinq tests". Cependant, la structure des règles prend également en charge la mise en correspondance de motifs de type glob et les définitions récursives, vous pouvez donc également exprimer des motifs arbitrairement complexes.

La règle doit avoir une seule clé de niveau supérieur : soit 'par' pour "parallèle", soit 'seq' pour "séquence".

Les valeurs doivent être des chaînes de caractères avec une mise en correspondance possible de type glob, ou des tableaux de chaînes de caractères ou des hachages qui suivent ce motif de manière récursive.

Chaque élément d'un tableau directement sous une clé 'par' est éligible pour être exécuté en parallèle, tandis que les valeurs directement sous une clé 'seq' doivent être exécutées en séquence.

Exemples de règles

Voici quelques exemples :

# Tous les tests doivent être exécutés en parallèle (la règle par défaut)
{ par => '**' },
# Exécuter tous les tests en séquence, sauf ceux commençant par "p"
{ par => 't/p*.t' },
# Exécuter tous les tests en parallèle, sauf ceux commençant par "p"
{
    seq => [
              { seq => 't/p*.t' },
              { par => '**'     },
           ],
}
# Exécuter certains tests de démarrage en séquence, puis certains tests parallèles, puis certains
# tests de nettoyage en séquence.
{
    seq => [
        { seq => 't/startup/*.t' },
        { par => ['t/a/*.t','t/b/*.t','t/c/*.t'], }
        { seq => 't/shutdown/*.t' },
    ],
},

Résolution des règles

  • Par défaut, tous les tests sont éligibles pour être exécutés en parallèle. La spécification de vos propres règles supprime celle-ci.
  • "La première correspondance est gagnante". La première règle qui correspond à un test est celle qui s'applique.
  • Tout test qui ne correspond à aucune règle sera exécuté en séquence à la fin de l'exécution.
  • L'existence d'une règle n'implique pas la sélection d'un test. Vous devez toujours spécifier les tests à exécuter.
  • Spécifier une règle pour permettre l'exécution des tests en parallèle ne les fait pas exécuter en parallèle. Vous devez toujours spécifier le nombre de "jobs" parallèles dans votre objet Harness.

Correspondance de motifs de type glob pour les règles

Nous implémentons notre propre correspondance de motifs de type glob. Voici les motifs qu'il prend en charge :

** représente n'importe quel nombre de caractères, y compris /, dans un chemin
* représente zéro ou plusieurs caractères dans un nom de fichier/répertoire
? représente exactement un caractère dans un nom de fichier/répertoire
{foo,bar,baz} représente n'importe lequel de foo, bar ou baz.
\ est un caractère d'échappement

Méthodes d'instance

"get_all"

Obtenir une liste de tous les tests restants.

"get_job"

Retourne le prochain travail disponible sous forme d'objet TAP::Parser::Scheduler::Job ou "undef" si aucun n'est disponible. Retourne un TAP::Parser::Scheduler::Spinner si le planificateur a encore des travaux en attente mais qu'aucun n'est disponible pour être exécuté pour le moment.

"as_string"

Retourne une représentation lisible par l'homme de l'arbre de planification. Par exemple :

my @tests = (qw{
    t/startup/foo.t 
    t/shutdown/foo.t

    t/a/foo.t t/b/foo.t t/c/foo.t t/d/foo.t
});
my $sched = TAP::Parser::Scheduler->new(
    tests => \@tests,
    rules => {
        seq => [
            { seq => 't/startup/*.t' },
            { par => ['t/a/*.t','t/b/*.t','t/c/*.t'] },
            { seq => 't/shutdown/*.t' },
        ],
    },
);

Produit :

par:
  seq:
    par:
      seq:
        par:
          seq:
            't/startup/foo.t'
        par:
          seq:
            't/a/foo.t'
          seq:
            't/b/foo.t'
          seq:
            't/c/foo.t'
        par:
          seq:
            't/shutdown/foo.t'
    't/d/foo.t'
