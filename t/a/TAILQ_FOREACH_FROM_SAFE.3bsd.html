DESCRIPTION

Ces macros définissent et opèrent sur quatre types de structures de données qui peuvent être utilisées dans le code source C et C++ :

  1. Listes
  2. Listes chaînées simples
  3. Files de liste chaînées simples (tail queues)
  4. Files de liste chaînées (tail queues)
Les quatre structures prennent en charge la fonctionnalité suivante :
  1. Insertion d'une nouvelle entrée en tête de liste.
  2. Insertion d'une nouvelle entrée après un élément existant dans la liste.
  3. Suppression en O(1) d'une entrée en tête de liste.
  4. Parcours avant dans la liste.
  5. Échange du contenu de deux listes.

Les listes chaînées simples sont les plus simples des quatre structures de données et ne prennent en charge que la fonctionnalité ci-dessus. Les listes chaînées simples sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une pile (LIFO). Les listes chaînées simples ajoutent la fonctionnalité suivante :

  1. Suppression en O(n) de n'importe quelle entrée dans la liste.
  2. Concaténation en O(n) de deux listes.

Les files de liste chaînées simples (tail queues) ajoutent la fonctionnalité suivante :

  1. Les entrées peuvent être ajoutées à la fin d'une liste.
  2. Suppression en O(n) de n'importe quelle entrée dans la liste.
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions de liste doivent spécifier la tête de la liste.
  2. Chaque entrée de tête nécessite deux pointeurs au lieu d'un seul.
  3. La taille du code est environ 15% plus grande et les opérations sont environ 20% plus lentes que pour les listes chaînées simples.

Les files de liste chaînées simples (tail queues) sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une file d'attente (FIFO).

Tous les types de structures de données doublement chaînées (listes et files de liste chaînées) autorisent en outre :

  1. Insertion d'une nouvelle entrée avant un élément de la liste.
  2. Suppression en O(1) de n'importe quelle entrée dans la liste.
Cependant :
  1. Chaque élément nécessite deux pointeurs au lieu d'un seul.
  2. La taille du code et le temps d'exécution des opérations (sauf pour la suppression) sont environ le double de ceux des structures de données simplement chaînées.

Les listes chaînées sont les plus simples des structures de données doublement chaînées. Elles ajoutent la fonctionnalité suivante par rapport à ce qui précède :

  1. Concaténation en O(n) de deux listes.
  2. Elles peuvent être parcourues en arrière.
Cependant :
  1. Pour parcourir en arrière, une entrée pour commencer le parcours et la liste dans laquelle elle est contenue doivent être spécifiées.

Les files de liste chaînées (tail queues) ajoutent la fonctionnalité suivante :

  1. Les entrées peuvent être ajoutées à la fin d'une liste.
  2. Elles peuvent être parcourues en arrière, de la fin vers le début.
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions et suppressions de liste doivent spécifier la tête de la liste.
  2. Chaque entrée de tête nécessite deux pointeurs au lieu d'un seul.
  3. La taille du code est environ 15% plus grande et les opérations sont environ 20% plus lentes que pour les listes chaînées simples.

Dans les définitions de macros, TYPE est le nom d'une structure définie par l'utilisateur. La structure doit contenir un champ appelé NAME qui est de type SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY, ou TAILQ_ENTRY. Dans les définitions de macros, CLASSTYPE est le nom d'une classe définie par l'utilisateur. La classe doit contenir un champ appelé NAME qui est de type SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY, ou TAILQ_CLASS_ENTRY. L'argument HEADNAME est le nom d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD, ou TAILQ_CLASS_HEAD. Voir les exemples ci-dessous pour plus d'explications sur la façon dont ces macros sont utilisées.

LISTES CHAÎNÉES SIMPLES

Une liste chaînée simple est dirigée par une structure définie par la macro SLIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont chaînés simplement pour une occupation mémoire et une manipulation de pointeurs minimales, au détriment d'une suppression en O(n) pour les éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant ou en tête de liste. Une structure SLIST_HEAD est déclarée comme suit :

SLIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la liste. Un pointeur vers la tête de la liste peut ensuite être déclaré comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro SLIST_HEAD_INITIALIZER évalue à un initialiseur pour la liste head.

La macro SLIST_CONCAT concatène la liste dirigée par head2 à la fin de celle dirigée par head1, en supprimant toutes les entrées de la première. L'utilisation de cette macro doit être évitée car elle parcourt la totalité de la liste head1. Une file de liste chaînée simple (tail queue) devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro SLIST_EMPTY évalue à vrai s'il n'y a aucun élément dans la liste.

La macro SLIST_ENTRY déclare une structure qui connecte les éléments de la liste.

La macro SLIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro SLIST_FOREACH parcourt la liste référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var.

La macro SLIST_FOREACH_FROM se comporte identiquement à SLIST_FOREACH lorsque var est NULL, sinon elle traite var comme un élément SLIST trouvé précédemment et commence la boucle à var au lieu du premier élément de la SLIST référencée par head.

La macro SLIST_FOREACH_SAFE parcourt la liste référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var. Cependant, contrairement à SLIST_FOREACH(), ici il est permis de supprimer var ainsi que de le libérer depuis l'intérieur de la boucle en toute sécurité sans interférer avec le parcours.

La macro SLIST_FOREACH_FROM_SAFE se comporte identiquement à SLIST_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément SLIST trouvé précédemment et commence la boucle à var au lieu du premier élément de la SLIST référencée par head.

La macro SLIST_INIT initialise la liste référencée par head.

La macro SLIST_INSERT_HEAD insère le nouvel élément elm en tête de la liste.

La macro SLIST_INSERT_AFTER insère le nouvel élément elm après l'élément

listelm.

La macro SLIST_NEXT renvoie l'élément suivant dans la liste.

La macro SLIST_REMOVE_AFTER supprime l'élément qui suit elm de la liste. Contrairement à SLIST_REMOVE, cette macro ne parcourt pas toute la liste.

La macro SLIST_REMOVE_HEAD supprime l'élément elm de la tête de la liste. Pour une efficacité optimale, les éléments supprimés de la tête de la liste devraient utiliser explicitement cette macro plutôt que la macro générique SLIST_REMOVE.

La macro SLIST_REMOVE supprime l'élément elm de la liste. L'utilisation de cette macro doit être évitée car elle parcourt toute la liste. Une liste doublement chaînée devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro SLIST_SWAP échange le contenu de head1 et head2.

EXEMPLE DE LISTE SIMPLEMENT CHAÎNÉE

SLIST_HEAD(slisthead, entry) head =
    SLIST_HEAD_INITIALIZER(head);
struct slisthead *headp;		/* Tête de liste simplement chaînée. */
struct entry {
	...
	SLIST_ENTRY(entry) entries;	/* Liste simplement chaînée. */
	...
} *n1, *n2, *n3, *np;

SLIST_INIT(&head);			/* Initialiser la liste. */

n1 = malloc(sizeof(struct entry));	/* Insérer à la tête. */
SLIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
SLIST_INSERT_AFTER(n1, n2, entries);

SLIST_REMOVE(&head, n2, entry, entries);/* Suppression. */
free(n2);

n3 = SLIST_FIRST(&head);
SLIST_REMOVE_HEAD(&head, entries);	/* Suppression de la tête. */
free(n3);
					/* Parcours avant. */
SLIST_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sécurisé. */
SLIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	SLIST_REMOVE(&head, np, entry, entries);
	free(np);
}

while (!SLIST_EMPTY(&head)) {		/* Suppression de la liste. */
	n1 = SLIST_FIRST(&head);
	SLIST_REMOVE_HEAD(&head, entries);
	free(n1);
}

FILES D'ATTENTE SIMPLEMENT CHAÎNÉES AVEC QUEUE

Une file d'attente simplement chaînée avec queue est dirigée par une structure définie par la macro STAILQ_HEAD. Cette structure contient une paire de pointeurs, l'un vers le premier élément de la file d'attente et l'autre vers le dernier élément de la file d'attente. Les éléments sont chaînés simplement pour un minimum d'espace et d'opérations sur les pointeurs, au prix d'une suppression en O(n) pour les éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la file d'attente après un élément existant, à la tête de la file d'attente ou à la fin de la file d'attente. Une structure STAILQ_HEAD est déclarée comme suit :

STAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la file d'attente. Un pointeur vers la tête de la file d'attente peut être déclaré plus tard comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro STAILQ_HEAD_INITIALIZER s'évalue à un initialiseur pour la file d'attente head.

La macro STAILQ_CONCAT concatène la file d'attente dirigée par head2 à la fin de celle dirigée par head1, supprimant toutes les entrées de la première.

La macro STAILQ_EMPTY s'évalue à vrai s'il n'y a pas d'éléments dans la file d'attente.

La macro STAILQ_ENTRY déclare une structure qui relie les éléments de la file d'attente.

La macro STAILQ_FIRST renvoie le premier élément de la file d'attente ou NULL si la file d'attente est vide.

La macro STAILQ_FOREACH parcourt la file d'attente référencée par head dans le sens avant, assignant chaque élément successivement à var.

La macro STAILQ_FOREACH_FROM se comporte identiquement à STAILQ_FOREACH lorsque var est NULL, sinon elle traite var comme un élément STAILQ trouvé précédemment et commence la boucle à var au lieu du premier élément de la STAILQ référencée par head.

La macro STAILQ_FOREACH_SAFE parcourt la file d'attente référencée par head dans le sens avant, assignant chaque élément successivement à var. Cependant, contrairement à STAILQ_FOREACH(), il est permis de supprimer var ainsi que de le libérer depuis l'intérieur de la boucle en toute sécurité sans interférer avec le parcours.

La macro STAILQ_FOREACH_FROM_SAFE se comporte identiquement à STAILQ_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément STAILQ trouvé précédemment et commence la boucle à var au lieu du premier élément de la STAILQ référencée par head.

La macro STAILQ_INIT initialise la file d'attente référencée par head.

La macro STAILQ_INSERT_HEAD insère le nouvel élément elm à la tête de la file d'attente.

La macro STAILQ_INSERT_TAIL insère le nouvel élément elm à la fin de la file d'attente.

La macro STAILQ_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro STAILQ_LAST renvoie le dernier élément de la file d'attente. Si la file d'attente est vide, la valeur retournée est NULL.

La macro STAILQ_NEXT renvoie l'élément suivant de la file d'attente, ou NULL si cet élément est le dernier.

La macro STAILQ_REMOVE_AFTER supprime l'élément qui suit elm de la file d'attente. Contrairement à STAILQ_REMOVE, cette macro ne parcourt pas toute la file d'attente.

La macro STAILQ_REMOVE_HEAD supprime l'élément à la tête de la file d'attente. Pour une efficacité optimale, les éléments supprimés de la tête de la file d'attente devraient utiliser cette macro explicitement plutôt que la macro générique STAILQ_REMOVE.

La macro STAILQ_REMOVE supprime l'élément elm de la file d'attente. L'utilisation de cette macro doit être évitée car elle parcourt toute la liste. Une file d'attente doublement chaînée devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues files d'attente.

La macro STAILQ_SWAP échange le contenu de head1 et head2.

EXEMPLE DE FILE D'ATTENTE SIMPLEMENT CHAÎNÉE AVEC QUEUE

STAILQ_HEAD(stailhead, entry) head =
    STAILQ_HEAD_INITIALIZER(head);
struct stailhead *headp;		/* Tête de file d'attente simplement chaînée. */
struct entry {
	...
	STAILQ_ENTRY(entry) entries;	/* File d'attente. */
	...
} *n1, *n2, *n3, *np;

STAILQ_INIT(&head);			/* Initialiser la file. */

n1 = malloc(sizeof(struct entry));	/* Insérer à la tête. */
STAILQ_INSERT_HEAD(&head, n1, entries);

n1 = malloc(sizeof(struct entry));	/* Insérer à la fin. */
STAILQ_INSERT_TAIL(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
STAILQ_INSERT_AFTER(&head, n1, n2, entries);
					/* Suppression. */
STAILQ_REMOVE(&head, n2, entry, entries);
free(n2);
					/* Suppression de la tête. */
n3 = STAILQ_FIRST(&head);
STAILQ_REMOVE_HEAD(&head, entries);
free(n3);
					/* Parcours avant. */
STAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sécurisé. */
STAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	STAILQ_REMOVE(&head, np, entry, entries);
	free(np);
}
					/* Suppression de la file d'attente. */
while (!STAILQ_EMPTY(&head)) {
	n1 = STAILQ_FIRST(&head);
	STAILQ_REMOVE_HEAD(&head, entries);
	free(n1);
}
					/* Suppression plus rapide de la file d'attente. */
n1 = STAILQ_FIRST(&head);
while (n1 != NULL) {
	n2 = STAILQ_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
STAILQ_INIT(&head);

LISTES

Une liste est dirigée par une structure définie par la macro LIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont chaînés doublement de sorte qu'un élément arbitraire puisse être supprimé sans parcourir la liste. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant, avant un élément existant, ou à la tête de la liste. Une structure LIST_HEAD est déclarée comme suit :

LIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la liste. Un pointeur vers la tête de la liste peut être déclaré plus tard comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro LIST_HEAD_INITIALIZER s'évalue à un initialiseur pour la liste head.

La macro LIST_CONCAT concatène la liste dirigée par head2 à la fin de celle dirigée par head1, supprimant toutes les entrées de la première. L'utilisation de cette macro doit être évitée car elle parcourt toute la liste head1. Une file d'attente devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro LIST_EMPTY s'évalue à vrai s'il n'y a pas d'éléments dans la liste.

La macro LIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro LIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro LIST_FOREACH parcourt la liste référencée par

LISTS

A singly linked list is headed by a structure defined by the LIST_HEAD macro. This structure contains a pointer to the first element in the list. The elements are singly linked so that an arbitrary element can be removed only if the previous element is known. New elements can be added to the list before an arbitrary element, or at the head of the list. A LIST_HEAD structure is declared as follows:

LIST_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the list. A pointer to the head of the list can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro LIST_HEAD_INITIALIZER evaluates to an initializer for the list head.

The macro LIST_EMPTY evaluates to true if there are no items on the list.

The macro LIST_ENTRY declares a structure that connects the elements in the list.

The macro LIST_FIRST returns the first item on the list or NULL if the list is empty.

The macro LIST_FOREACH traverses the list referenced by head in the forward direction, assigning each element in turn to var.

The macro LIST_FOREACH_FROM behaves identically to LIST_FOREACH when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_FOREACH_SAFE traverses the list referenced by head in the forward direction, assigning each element in turn to var. However, unlike LIST_FOREACH() here it is permitted to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro LIST_FOREACH_FROM_SAFE behaves identically to LIST_FOREACH_SAFE when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_INIT initializes the list referenced by head.

The macro LIST_INSERT_HEAD inserts the new element elm at the head of the list.

The macro LIST_INSERT_AFTER inserts the new element elm after the element listelm.

The macro LIST_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro LIST_NEXT returns the next element in the list, or NULL if this is the last.

The macro LIST_PREV returns the previous element in the list, or NULL if this is the first. List head must contain element elm.

The macro LIST_REMOVE removes the element elm from the list.

The macro LIST_SWAP swaps the contents of head1 and head2.

LIST EXAMPLE

LIST_HEAD(listhead, entry) head =
    LIST_HEAD_INITIALIZER(head);
struct listhead *headp;			/* List head. */
struct entry {
	...
	LIST_ENTRY(entry) entries;	/* List. */
	...
} *n1, *n2, *n3, *np, *np_temp;

LIST_INIT(&head);			/* Initialize the list. */

n1 = malloc(sizeof(struct entry));	/* Insert at the head. */
LIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insert after. */
LIST_INSERT_AFTER(n1, n2, entries);

n3 = malloc(sizeof(struct entry));	/* Insert before. */
LIST_INSERT_BEFORE(n2, n3, entries);

LIST_REMOVE(n2, entries);		/* Deletion. */
free(n2);
					/* Forward traversal. */
LIST_FOREACH(np, &head, entries)
	np-> ...

					/* Safe forward traversal. */
LIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	LIST_REMOVE(np, entries);
	free(np);
}

while (!LIST_EMPTY(&head)) {		/* List Deletion. */
	n1 = LIST_FIRST(&head);
	LIST_REMOVE(n1, entries);
	free(n1);
}

n1 = LIST_FIRST(&head);			/* Faster List Deletion. */
while (n1 != NULL) {
	n2 = LIST_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
LIST_INIT(&head);

TAIL QUEUES

A tail queue is headed by a structure defined by the TAILQ_HEAD macro. This structure contains a pair of pointers, one to the first element in the tail queue and the other to the last element in the tail queue. The elements are doubly linked so that an arbitrary element can be removed without traversing the tail queue. New elements can be added to the tail queue after an existing element, before an existing element, at the head of the tail queue, or at the end of the tail queue. A TAILQ_HEAD structure is declared as follows:

TAILQ_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the tail queue. A pointer to the head of the tail queue can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro TAILQ_HEAD_INITIALIZER evaluates to an initializer for the tail queue head.

The macro TAILQ_CONCAT concatenates the tail queue headed by head2 onto the end of the one headed by head1 removing all entries from the former.

The macro TAILQ_EMPTY evaluates to true if there are no items on the tail queue.

The macro TAILQ_ENTRY declares a structure that connects the elements in the tail queue.

The macro TAILQ_FIRST returns the first item on the tail queue or NULL if the tail queue is empty.

The macro TAILQ_FOREACH traverses the tail queue referenced by head in the forward direction, assigning each element in turn to var. var is set to NULL if the loop completes normally, or if there were no elements.

The macro TAILQ_FOREACH_FROM behaves identically to TAILQ_FOREACH when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.

The macro TAILQ_FOREACH_REVERSE traverses the tail queue referenced by head in the reverse direction, assigning each element in turn to var.

The macro TAILQ_FOREACH_REVERSE_FROM behaves identically to TAILQ_FOREACH_REVERSE when var is NULL, else it treats var as a previously found TAILQ element and begins the reverse loop at var instead of the last element in the TAILQ referenced by head.

The macros TAILQ_FOREACH_SAFE and TAILQ_FOREACH_REVERSE_SAFE traverse the list referenced by head in the forward or reverse direction respectively, assigning each element in turn to var. However, unlike their unsafe counterparts, TAILQ_FOREACH and TAILQ_FOREACH_REVERSE make it possible to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro TAILQ_FOREACH_FROM_SAFE behaves identically to TAILQ_FOREACH_SAFE when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.

The macro TAILQ_FOREACH_REVERSE_FROM_SAFE behaves identically to TAILQ_FOREACH_REVERSE_SAFE when var is NULL, else it treats var as a previously found TAILQ element and begins the reverse loop at var instead of the last element in the TAILQ referenced by head.

The macro TAILQ_INIT initializes the tail queue referenced by head.

The macro TAILQ_INSERT_HEAD inserts the new element elm at the head of the tail queue.

The macro TAILQ_INSERT_TAIL inserts the new element elm at the end of the tail queue.

The macro TAILQ_INSERT_AFTER inserts the new element elm after the element listelm.

The macro TAILQ_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro TAILQ_LAST returns the last item on the tail queue. If the tail queue is empty the return value is NULL.

The macro TAILQ_NEXT returns the next item on the tail queue, or NULL if this item is the last.

The macro TAILQ_PREV returns the previous item on the tail queue, or NULL if this item is the first.

The macro TAILQ_REMOVE removes the element elm from the tail queue.

The macro TAILQ_SWAP swaps the contents of head1 and head2.

TAIL QUEUE EXAMPLE

TAILQ_HEAD(tailhead, entry) head =
    TAILQ_HEAD_INITIALIZER(head);
struct tailhead *headp;			/* Tail queue head. */
struct entry {
	...
	TAILQ_ENTRY(entry) entries;	/* Tail queue. */
	...
} *n1, *n2, *n3, *np;

TAILQ_INIT(&head);			/* Initialize the queue. */

n1 = malloc(sizeof(struct entry));	/* Insert at the head. */
TAILQ_INSERT_HEAD(&head, n1, entries);

n1 = malloc(sizeof(struct entry));	/* Insert at the tail. */
TAILQ_INSERT_TAIL(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insert after. */
TAILQ_INSERT_AFTER(&head, n1, n2, entries);

n3 = malloc(sizeof(struct entry));	/* Insert before. */
TAILQ_INSERT_BEFORE(n2, n3, entries);

TAILQ_REMOVE(&head, n2, entries);	/* Deletion. */
free(n2);
					/* Forward traversal. */
TAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* Safe forward traversal. */
TAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	TAILQ_REMOVE(&head, np, entries);
	free(np);
}
					/* Reverse traversal. */
TAILQ_FOREACH_REVERSE(np, &head, tailhead, entries)
	np-> ...
					/* TailQ Deletion. */
while (!TAILQ_EMPTY(&head)) {
	n1 = TAILQ_FIRST(&head);
	TAILQ_REMOVE(&head, n1, entries);
	free(n1);
}
					/* Faster TailQ Deletion. */
n1 = TAILQ_FIRST(&head);
while (n1 != NULL) {
	n2 = TAILQ_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
TAILQ_INIT(&head);
TAILQ_FOREACH_FROM_SAFE(3bsd) — Arch manual pages

NAME

TAILQ_FOREACH_FROM_SAFE, TAILQ_FOREACH_FROM — iterate over a tail queue

LIBRARY

libbsd

SYNOPSIS

#include <bsd/sys/queue.h>

#define TAILQ_FOREACH_FROM_SAFE(var, head, first, next, var_backup) \
    for ((var) = TAILQ_FIRST((head)); \
        (var) != NULL; \
        (var_backup) = (var), (var) = TAILQ_NEXT((var_backup), (next))) \
        /* empty */
#define TAILQ_FOREACH_FROM(var, head, next) \
    for ((var) = TAILQ_FIRST((head)); \
        (var) != NULL; \
        (var) = TAILQ_NEXT((var), (next))) \
        /* empty */

DESCRIPTION

The TAILQ_FOREACH_FROM_SAFE macro iterates over the elements of a tail queue starting from an arbitrary element. The iteration is safe in the sense that it is possible to remove the current element from the queue during the iteration. The iteration stops when the end of the queue is reached.

The elements are traversed from the element first to the end of the queue. The macro TAILQ_FOREACH_FROM_SAFE requires two additional temporary variables, var_backup and next, to be declared in the scope where the loop is expanded. These temporary variables must be of the same type as var and a pointer to the entry type respectively. The loop variable var must be a pointer to a structure type. The macro TAILQ_FOREACH_FROM is a non-safe version of the same construct.

The macro takes the following arguments:

var
A pointer to the loop variable that will hold the current element.
head
The head of the tail queue.
first
The first element from which to start the iteration.
var_backup
A temporary variable that must be declared and of the same type as var. It stores the current element, which is needed to advance the loop.
next
A pointer to the entry type of the queue, used to access the link field.

The macro TAILQ_FOREACH_FROM is similar to TAILQ_FOREACH_FROM_SAFE, but it does not provide the safety net of var_backup. Modifying the queue during the iteration using TAILQ_FOREACH_FROM can lead to undefined behavior.

DIAGNOSTICS

When debugging queue(3), it can be useful to trace queue changes. To enable tracing, define the macro QUEUE_MACRO_DEBUG_TRACE at compile time.

It can also be useful to trash pointers that have been unlinked from a queue, to detect use after removal. To enable pointer trashing, define the macro QUEUE_MACRO_DEBUG_TRASH at compile time. The macro QMD_IS_TRASHED(void *ptr) returns true if ptr has been trashed by the QUEUE_MACRO_DEBUG_TRASH option.
