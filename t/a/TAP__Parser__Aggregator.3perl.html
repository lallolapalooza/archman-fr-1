TAP::Parser::Aggregator(3perl) Guide du programmeur Perl TAP::Parser::Aggregator(3perl)

NOM

TAP::Parser::Aggregator - Agrège les résultats de TAP::Parser

VERSION

Version 3.50

SYNOPIS

use TAP::Parser::Aggregator;
my $aggregate = TAP::Parser::Aggregator->new;
$aggregate->add( 't/00-load.t', $load_parser );
$aggregate->add( 't/10-lex.t',  $lex_parser  );
my $summary = <<'END_SUMMARY';
Passés :  %s
Échoués :  %s
Succès inattendus : %s
END_SUMMARY
printf $summary,
       scalar $aggregate->passed,
       scalar $aggregate->failed,
       scalar $aggregate->todo_passed;

DESCRIPTION

"TAP::Parser::Aggregator" collecte des objets parseurs et permet de signaler/interroger leurs résultats agrégés.

METHODES

Méthodes de classe

"new"

my $aggregate = TAP::Parser::Aggregator->new;

Retourne un nouvel objet "TAP::Parser::Aggregator".

Méthodes d'instance

"add"

$aggregate->add( $description => $parser );

La $description est généralement le nom d'un fichier de test (mais seulement par convention). Elle est utilisée comme identifiant unique (voir par exemple "parsers"). Réutiliser une description est une erreur fatale.

La $parser est un objet TAP::Parser.

"parsers"

my $count   = $aggregate->parsers;
my @parsers = $aggregate->parsers;
my @parsers = $aggregate->parsers(@descriptions);

En contexte scalaire sans arguments, cette méthode retourne le nombre de parseurs agrégés. En contexte liste sans arguments, retourne les parseurs dans l'ordre où ils ont été ajoutés.

Si @descriptions est donné, ceux-ci correspondent aux clés utilisées dans chaque appel à la méthode add(). Retourne un tableau des parseurs demandés (dans l'ordre demandé) en contexte liste ou une référence de tableau en contexte scalaire.

Demander un identifiant inconnu est une erreur fatale.

"descriptions"

Obtient un tableau de descriptions dans l'ordre où elles ont été ajoutées à l'agrégateur.

"start"

Appelez "start" immédiatement avant d'ajouter des résultats à l'agrégateur. Entre autres, cela enregistre l'heure de début de l'exécution des tests.

"stop"

Appelez "stop" immédiatement après avoir ajouté tous les résultats de test à l'agrégateur.

"elapsed"

elapsed retourne un objet Benchmark qui représente le temps d'exécution des tests agrégés. Pour que "elapsed" soit valide, vous devez appeler "start" avant d'exécuter les tests et "stop" immédiatement après.

"elapsed_timestr"

Retourne une chaîne formatée représentant le temps d'exécution retourné par elapsed(). Cela évite au programmeur de se soucier de Benchmark.

"all_passed"

Retourne vrai si tous les tests ont réussi et qu'aucune erreur de parsing n'a été détectée.

"get_status"

Obtient un mot unique décrivant le statut des tests agrégés. Selon le résultat des tests, retourne 'PASS', 'FAIL' ou 'NOTESTS'. Ce jeton est compris par CPAN::Reporter.

Méthodes de résumé

Chacune des méthodes suivantes retournera le nombre total de tests correspondants si appelée en contexte scalaire. Si appelée en contexte liste, retourne les descriptions des parseurs qui contiennent les tests correspondants (voir "add" pour une explication de la description.

  • failed
  • parse_errors
  • passed
  • planned
  • skipped
  • todo
  • todo_passed
  • wait
  • exit

Par exemple, pour savoir combien de tests ont réussi de manière inattendue (tests TODO qui ont réussi alors qu'ils n'auraient pas dû) :

my $count        = $aggregate->todo_passed;
my @descriptions = $aggregate->todo_passed;

Notez que "wait" et "exit" sont les totaux des statuts d'attente et de sortie de chacun des tests. Ces valeurs sont totalisées uniquement pour fournir une valeur vraie si l'un d'entre eux est non nul.

"total"

my $tests_run = $aggregate->total;

Retourne le nombre total de tests exécutés.

"has_problems"

if ( $parser->has_problems ) {
    ...
}

Identique à "has_errors", mais retourne également vrai si des tests TODO ont réussi de manière inattendue. Ceci s'apparente davantage à des "avertissements".

"has_errors"

if ( $parser->has_errors ) {
    ...
}

Retourne vrai si l'un des parseurs a échoué. Cela inclut :

  • Tests échoués
  • Erreurs de parsing
  • Statut de sortie ou d'attente incorrect

"todo_failed"

# déprécié en faveur de 'todo_passed'. Cette méthode avait un nom horrible.

C'était une méthode au nom horriblement mal choisi. Elle indique quels tests TODO ont réussi de manière inattendue. Émettra maintenant un avertissement et appellera "todo_passed".
