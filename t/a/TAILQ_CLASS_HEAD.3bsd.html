DESCRIPTION

These macros define and operate on four types of data structures which can be used in both C and C++ source code:

  1. Lists
  2. Singly-linked lists
  3. Singly-linked tail queues
  4. Tail queues
All four structures support the following functionality:
  1. Insertion of a new entry at the head of the list.
  2. Insertion of a new entry after any element in the list.
  3. O(1) removal of an entry from the head of the list.
  4. Forward traversal through the list.
  5. Swapping the contents of two lists.

Singly-linked lists are the simplest of the four data structures and support only the above functionality. Singly-linked lists are ideal for applications with large datasets and few or no removals, or for implementing a LIFO queue. Singly-linked lists add the following functionality:

  1. O(n) removal of any entry in the list.
  2. O(n) concatenation of two lists.

Singly-linked tail queues add the following functionality:

  1. Entries can be added at the end of a list.
  2. O(n) removal of any entry in the list.
  3. They may be concatenated.
However:
  1. All list insertions must specify the head of the list.
  2. Each head entry requires two pointers rather than one.
  3. Code size is about 15% greater and operations run about 20% slower than singly-linked lists.

Singly-linked tail queues are ideal for applications with large datasets and few or no removals, or for implementing a FIFO queue.

All doubly linked types of data structures (lists and tail queues) additionally allow:

  1. Insertion of a new entry before any element in the list.
  2. O(1) removal of any entry in the list.
However:
  1. Each element requires two pointers rather than one.
  2. Code size and execution time of operations (except for removal) is about twice that of the singly-linked data-structures.

Linked lists are the simplest of the doubly linked data structures. They add the following functionality over the above:

  1. O(n) concatenation of two lists.
  2. They may be traversed backwards.
However:
  1. To traverse backwards, an entry to begin the traversal and the list in which it is contained must be specified.

Tail queues add the following functionality:

  1. Entries can be added at the end of a list.
  2. They may be traversed backwards, from tail to head.
  3. They may be concatenated.
However:
  1. All list insertions and removals must specify the head of the list.
  2. Each head entry requires two pointers rather than one.
  3. Code size is about 15% greater and operations run about 20% slower than singly-linked lists.

In the macro definitions, TYPE is the name of a user defined structure. The structure must contain a field called NAME which is of type SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY, or TAILQ_ENTRY. In the macro definitions, CLASSTYPE is the name of a user defined class. The class must contain a field called NAME which is of type SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY, or TAILQ_CLASS_ENTRY. The argument HEADNAME is the name of a user defined structure that must be declared using the macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD, or TAILQ_CLASS_HEAD. See the examples below for further explanation of how these macros are used.

SINGLY-LINKED LISTS

A singly-linked list is headed by a structure defined by the SLIST_HEAD macro. This structure contains a single pointer to the first element on the list. The elements are singly linked for minimum space and pointer manipulation overhead at the expense of O(n) removal for arbitrary elements. New elements can be added to the list after an existing element or at the head of the list. An SLIST_HEAD structure is declared as follows:

SLIST_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the list. A pointer to the head of the list can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro SLIST_HEAD_INITIALIZER evaluates to an initializer for the list head.

The macro SLIST_CONCAT concatenates the list headed by head2 onto the end of the one headed by head1 removing all entries from the former. Use of this macro should be avoided as it traverses the entirety of the head1 list. A singly-linked tail queue should be used if this macro is needed in high-usage code paths or to operate on long lists.

The macro SLIST_EMPTY evaluates to true if there are no elements in the list.

The macro SLIST_ENTRY declares a structure that connects the elements in the list.

The macro SLIST_FIRST returns the first element in the list or NULL if the list is empty.

The macro SLIST_FOREACH traverses the list referenced by head in the forward direction, assigning each element in turn to var.

The macro SLIST_FOREACH_FROM behaves identically to SLIST_FOREACH when var is NULL, else it treats var as a previously found SLIST element and begins the loop at var instead of the first element in the SLIST referenced by head.

The macro SLIST_FOREACH_SAFE traverses the list referenced by head in the forward direction, assigning each element in turn to var. However, unlike SLIST_FOREACH() here it is permitted to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro SLIST_FOREACH_FROM_SAFE behaves identically to SLIST_FOREACH_SAFE when var is NULL, else it treats var as a previously found SLIST element and begins the loop at var instead of the first element in the SLIST referenced by head.

The macro SLIST_INIT initializes the list referenced by head.

The macro SLIST_INSERT_HEAD inserts the new element elm at the head of the list.

The macro SLIST_INSERT_AFTER inserts the new element elm after the element listelm.

The macro SLIST_REMOVE removes the element elm from the list.

The macro SLIST_SWAP swaps the contents of the two lists headed by head1 and head2.

SINGLY-LINKED TAIL QUEUES

Singly-linked tail queues are similar to singly-linked lists, but they support O(1) insertion at the tail of the queue, as well as O(1) insertion at the head. They are implemented using the STAILQ_HEAD and STAILQ_ENTRY macros. The structure is declared as follows:

STAILQ_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the queue. A pointer to the head of the queue can later be declared as:

struct HEADNAME *headp;

The macro STAILQ_HEAD_INITIALIZER evaluates to an initializer for the queue head.

The macro STAILQ_CONCAT concatenates the queue headed by head2 onto the end of the one headed by head1 removing all entries from the former. Use of this macro should be avoided as it traverses the entirety of the head1 queue. A singly-linked tail queue should be used if this macro is needed in high-usage code paths or to operate on long queues.

The macro STAILQ_EMPTY evaluates to true if there are no elements in the queue.

The macro STAILQ_ENTRY declares a structure that connects the elements in the queue.

The macro STAILQ_FIRST returns the first element in the queue or NULL if the queue is empty.

The macro STAILQ_LAST returns the last element in the queue or NULL if the queue is empty.

The macro STAILQ_NEXT returns the next element in the queue after elm, or NULL if elm is the last element.

The macro STAILQ_FOREACH traverses the queue referenced by head in the forward direction, assigning each element in turn to var.

The macro STAILQ_FOREACH_FROM behaves identically to STAILQ_FOREACH when var is NULL, else it treats var as a previously found STAILQ element and begins the loop at var instead of the first element in the STAILQ referenced by head.

The macro STAILQ_FOREACH_SAFE traverses the queue referenced by head in the forward direction, assigning each element in turn to var. However, unlike STAILQ_FOREACH() here it is permitted to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro STAILQ_FOREACH_FROM_SAFE behaves identically to STAILQ_FOREACH_SAFE when var is NULL, else it treats var as a previously found STAILQ element and begins the loop at var instead of the first element in the STAILQ referenced by head.

The macro STAILQ_INIT initializes the queue referenced by head.

The macro STAILQ_INSERT_HEAD inserts the new element elm at the head of the queue.

The macro STAILQ_INSERT_TAIL inserts the new element elm at the tail of the queue.

The macro STAILQ_INSERT_AFTER inserts the new element elm after the element listelm.

The macro STAILQ_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro STAILQ_REMOVE removes the element elm from the queue.

FILES D'ATTENTE À EXTRÉMITÉ SIMPLEMENT CHAÎNÉES

Une file d'attente à extrémité simplement chaînée est dirigée par une structure définie par la macro STAILQ_HEAD. Cette structure contient une paire de pointeurs, l'un vers le premier élément de la file d'attente et l'autre vers le dernier élément de la file d'attente. Les éléments sont chaînés de manière simplement chaînée pour une surcharge minimale d'espace et de manipulation de pointeurs, au détriment d'une suppression en O(n) pour les éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la file d'attente après un élément existant, en tête de la file d'attente, ou à la fin de la file d'attente. Une structure STAILQ_HEAD est déclarée comme suit :

STAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à chaîner dans la file d'attente. Un pointeur vers la tête de la file d'attente peut ensuite être déclaré comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro STAILQ_HEAD_INITIALIZER évalue un initialiseur pour la file d'attente head.

La macro STAILQ_CONCAT concatène la file d'attente dirigée par head2 à la fin de celle dirigée par head1, supprimant toutes les entrées de la première.

La macro STAILQ_EMPTY évalue à vrai s'il n'y a pas d'éléments dans la file d'attente.

La macro STAILQ_ENTRY déclare une structure qui relie les éléments de la file d'attente.

La macro STAILQ_FIRST retourne le premier élément de la file d'attente ou NULL si la file d'attente est vide.

La macro STAILQ_FOREACH parcourt la file d'attente référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var.

La macro STAILQ_FOREACH_FROM se comporte de manière identique à STAILQ_FOREACH lorsque var est NULL, sinon elle traite var comme un élément STAILQ précédemment trouvé et commence la boucle à var au lieu du premier élément de la STAILQ référencée par head.

La macro STAILQ_FOREACH_SAFE parcourt la file d'attente référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var. Cependant, contrairement à STAILQ_FOREACH(), il est permis de supprimer var ainsi que de le libérer depuis la boucle en toute sécurité sans interférer avec le parcours.

La macro STAILQ_FOREACH_FROM_SAFE se comporte de manière identique à STAILQ_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément STAILQ précédemment trouvé et commence la boucle à var au lieu du premier élément de la STAILQ référencée par head.

La macro STAILQ_INIT initialise la file d'attente référencée par head.

La macro STAILQ_INSERT_HEAD insère le nouvel élément elm en tête de la file d'attente.

La macro STAILQ_INSERT_TAIL insère le nouvel élément elm à la fin de la file d'attente.

La macro STAILQ_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro STAILQ_LAST retourne le dernier élément de la file d'attente. Si la file d'attente est vide, la valeur de retour est NULL.

La macro STAILQ_NEXT retourne le prochain élément de la file d'attente, ou NULL si cet élément est le dernier.

La macro STAILQ_REMOVE_AFTER supprime l'élément suivant elm de la file d'attente. Contrairement à STAILQ_REMOVE, cette macro ne parcourt pas toute la file d'attente.

La macro STAILQ_REMOVE_HEAD supprime l'élément en tête de la file d'attente. Pour une efficacité optimale, les éléments supprimés de la tête de la file d'attente devraient utiliser explicitement cette macro plutôt que la macro générique STAILQ_REMOVE.

La macro STAILQ_REMOVE supprime l'élément elm de la file d'attente. L'utilisation de cette macro doit être évitée car elle parcourt toute la liste. Une file d'attente doublement chaînée devrait être utilisée si cette macro est nécessaire dans des chemins de code à usage intensif ou pour opérer sur de longues files d'attente.

La macro STAILQ_SWAP échange le contenu de head1 et head2.

EXEMPLE DE FILE D'ATTENTE À EXTRÉMITÉ SIMPLEMENT CHAÎNÉE

STAILQ_HEAD(stailhead, entry) head =
    STAILQ_HEAD_INITIALIZER(head);
struct stailhead *headp;		/* Tête de file d'attente à extrémité simplement chaînée. */
struct entry {
	...
	STAILQ_ENTRY(entry) entries;	/* File d'attente. */
	...
} *n1, *n2, *n3, *np;

STAILQ_INIT(&head);			/* Initialise la file. */

n1 = malloc(sizeof(struct entry));	/* Insertion en tête. */
STAILQ_INSERT_HEAD(&head, n1, entries);

n1 = malloc(sizeof(struct entry));	/* Insertion à la fin. */
STAILQ_INSERT_TAIL(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insertion après. */
STAILQ_INSERT_AFTER(&head, n1, n2, entries);
					/* Suppression. */
STAILQ_REMOVE(&head, n2, entry, entries);
free(n2);
					/* Suppression de la tête. */
n3 = STAILQ_FIRST(&head);
STAILQ_REMOVE_HEAD(&head, entries);
free(n3);
					/* Parcours avant. */
STAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sécurisé. */
STAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	STAILQ_REMOVE(&head, np, entry, entries);
	free(np);
}
					/* Suppression de la TailQ. */
while (!STAILQ_EMPTY(&head)) {
	n1 = STAILQ_FIRST(&head);
	STAILQ_REMOVE_HEAD(&head, entries);
	free(n1);
}
					/* Suppression plus rapide de la TailQ. */
n1 = STAILQ_FIRST(&head);
while (n1 != NULL) {
	n2 = STAILQ_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
STAILQ_INIT(&head);

LISTES

Une liste est dirigée par une structure définie par la macro LIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont doublement chaînés de sorte qu'un élément arbitraire puisse être supprimé sans parcourir la liste. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant, avant un élément existant, ou en tête de la liste. Une structure LIST_HEAD est déclarée comme suit :

LIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à chaîner dans la liste. Un pointeur vers la tête de la liste peut ensuite être déclaré comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro LIST_HEAD_INITIALIZER évalue un initialiseur pour la liste head.

La macro LIST_CONCAT concatène la liste dirigée par head2 à la fin de celle dirigée par head1, supprimant toutes les entrées de la première. L'utilisation de cette macro doit être évitée car elle parcourt la totalité de la liste head1. Une file d'attente à extrémité devrait être utilisée si cette macro est nécessaire dans des chemins de code à usage intensif ou pour opérer sur de longues listes.

La macro LIST_EMPTY évalue à vrai s'il n'y a aucun élément dans la liste.

La macro LIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro LIST_FIRST retourne le premier élément de la liste ou NULL si la liste est vide.

La macro LIST_FOREACH parcourt la liste référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var.

La macro LIST_FOREACH_FROM se comporte de manière identique à LIST_FOREACH lorsque var est NULL, sinon elle traite var comme un élément de liste précédemment trouvé et commence la boucle à var au lieu du premier élément de la liste référencée par head.

La macro LIST_FOREACH_SAFE parcourt la liste référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var. Cependant, contrairement à LIST_FOREACH(), il est permis de supprimer var ainsi que de le libérer depuis la boucle en toute sécurité sans interférer avec le parcours.

QUEUES À QUEUE

Une queue à queue est dirigée par une structure définie par la macro TAILQ_HEAD. Cette structure contient une paire de pointeurs, l'un vers le premier élément de la queue à queue et l'autre vers le dernier élément de la queue à queue. Les éléments sont doublement chaînés de sorte qu'un élément arbitraire puisse être retiré sans parcourir la queue à queue. De nouveaux éléments peuvent être ajoutés à la queue à queue après un élément existant, avant un élément existant, en tête de la queue à queue, ou à la fin de la queue à queue. Une structure TAILQ_HEAD est déclarée comme suit :

TAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la queue à queue. Un pointeur vers la tête de la queue à queue peut ensuite être déclaré comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro TAILQ_HEAD_INITIALIZER évalue à un initialiseur pour la queue à queue head.

La macro TAILQ_CONCAT concatène la queue à queue dirigée par head2 à la fin de celle dirigée par head1, retirant toutes les entrées de la première.

La macro TAILQ_EMPTY évalue à vrai s'il n'y a pas d'éléments dans la queue à queue.

La macro TAILQ_ENTRY déclare une structure qui relie les éléments de la queue à queue.

La macro TAILQ_FIRST retourne le premier élément de la queue à queue ou NULL si la queue à queue est vide.

La macro TAILQ_FOREACH parcourt la queue à queue référencée par head dans le sens avant, attribuant chaque élément tour à tour à var. var est mis à NULL si la boucle se termine normalement, ou s'il n'y avait aucun élément.

La macro TAILQ_FOREACH_FROM se comporte identiquement à TAILQ_FOREACH lorsque var est NULL, sinon elle traite var comme un élément TAILQ trouvé précédemment et commence la boucle à var au lieu du premier élément de la TAILQ référencée par head.

La macro TAILQ_FOREACH_REVERSE parcourt la queue à queue référencée par head dans le sens inverse, attribuant chaque élément tour à tour à var.

La macro TAILQ_FOREACH_REVERSE_FROM se comporte identiquement à TAILQ_FOREACH_REVERSE lorsque var est NULL, sinon elle traite var comme un élément TAILQ trouvé précédemment et commence la boucle inverse à var au lieu du dernier élément de la TAILQ référencée par head.

Les macros TAILQ_FOREACH_SAFE et TAILQ_FOREACH_REVERSE_SAFE parcourent la liste référencée par head dans le sens avant ou inverse respectivement, attribuant chaque élément tour à tour à var. Cependant, contrairement à leurs homologues non sécurisés, TAILQ_FOREACH et TAILQ_FOREACH_REVERSE permettent de retirer var ainsi que de le libérer depuis la boucle en toute sécurité sans interférer avec le parcours.

La macro TAILQ_FOREACH_FROM_SAFE se comporte identiquement à TAILQ_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément TAILQ trouvé précédemment et commence la boucle à var au lieu du premier élément de la TAILQ référencée par head.

La macro TAILQ_FOREACH_REVERSE_FROM_SAFE se comporte identiquement à TAILQ_FOREACH_REVERSE_SAFE lorsque var est NULL, sinon elle traite var comme un élément TAILQ trouvé précédemment et commence la boucle inverse à var au lieu du dernier élément de la TAILQ référencée par head.

La macro TAILQ_INIT initialise la queue à queue référencée par head.

La macro TAILQ_INSERT_HEAD insère le nouvel élément elm à la tête de la queue à queue.

La macro TAILQ_INSERT_TAIL insère le nouvel élément elm à la fin de la queue à queue.

La macro TAILQ_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro TAILQ_INSERT_BEFORE insère le nouvel élément elm avant l'élément listelm.

La macro TAILQ_LAST retourne le dernier élément de la queue à queue. Si la queue à queue est vide, la valeur de retour est NULL.

La macro TAILQ_NEXT retourne l'élément suivant de la queue à queue, ou NULL si cet élément est le dernier.

La macro TAILQ_PREV retourne l'élément précédent de la queue à queue, ou NULL si cet élément est le premier.

La macro TAILQ_REMOVE retire l'élément elm de la queue à queue.

La macro TAILQ_SWAP échange le contenu de head1 et head2.

DIAGNOSTICS

Lors du débogage de queue(3), il peut être utile de suivre les modifications de la file d'attente. Pour activer le suivi, définissez la macro QUEUE_MACRO_DEBUG_TRACE au moment de la compilation.

Il peut également être utile de mettre au rebut les pointeurs qui ont été détachés d'une file d'attente, pour détecter une utilisation après retrait. Pour activer la mise au rebut des pointeurs, définissez la macro QUEUE_MACRO_DEBUG_TRASH au moment de la compilation. La macro QMD_IS_TRASHED(void *ptr) renvoie vrai si ptr a été mis au rebut par l'option QUEUE_MACRO_DEBUG_TRASH.
