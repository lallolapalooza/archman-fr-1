TAP::Parser::ResultFactory(3perl) Guide du programmeur Perl TAP::Parser::ResultFactory(3perl)

NOM

TAP::Parser::ResultFactory - Fabrique pour la création d'objets de sortie TAP::Parser

SYNTAXE

use TAP::Parser::ResultFactory;
my $token   = {...};
my $factory = TAP::Parser::ResultFactory->new;
my $result  = $factory->make_result( $token );

VERSION

Version 3.50

DESCRIPTION

Ceci est une classe fabrique simple qui retourne une sous-classe de TAP::Parser::Result représentant le morceau de données de test actuel du TAP (généralement une seule ligne). Elle est principalement utilisée par TAP::Parser::Grammar. Sauf si vous créez une sous-classe, vous n'aurez probablement pas besoin d'utiliser ce module directement.

MÉTHODES

Méthodes de classe

"new"

Crée une nouvelle classe fabrique. Note : Vous n'avez actuellement pas besoin d'instancier une fabrique pour l'utiliser.

"make_result"

Retourne une instance de la classe appropriée pour le jeton de test passé en argument.

my $result = TAP::Parser::ResultFactory->make_result($token);

Peut également être appelée comme méthode d'instance.

"class_for"

Prend un argument : $type. Retourne la classe pour ce $type, ou émet une erreur avec "croak".

"register_type"

Prend deux arguments : $type, $class

Cela vous permet de remplacer un type existant par votre propre type personnalisé, ou d'enregistrer un type entièrement nouveau, par exemple :

# créer un type de résultat personnalisé :
package MyResult;
use strict;
use base 'TAP::Parser::Result';
# enregistrer avec la fabrique :
TAP::Parser::ResultFactory->register_type( 'my_type' => __PACKAGE__ );
# l'utiliser :
my $r = TAP::Parser::ResultFactory->( { type => 'my_type' } );

Votre type personnalisé devrait alors être automatiquement pris en compte par TAP::Parser.

SOUSCLASSEMENT

Veuillez consulter "SOUSCLASSEMENT" dans TAP::Parser pour un aperçu du sous-classement.

Il y a quelques points à garder à l'esprit lors de la création de votre propre "ResultFactory" :

1.
La fabrique elle-même n'est jamais instanciée (cela pourrait changer à l'avenir). Cela signifie que "_initialize" n'est jamais appelée.
2.
"TAP::Parser::Result->new" n'est jamais appelé, les $tokens sont reblessés. Cela changera dans une future version !
3.
Les sous-classes de TAP::Parser::Result s'enregistreront directement auprès de TAP::Parser::ResultFactory : 
package MyFooResult;
TAP::Parser::ResultFactory->register_type( foo => __PACKAGE__ );

Bien sûr, il vous appartient de décider si vous voulez les ignorer ou non.

Exemple

package MyResultFactory;
use strict;
use MyResult;
use base 'TAP::Parser::ResultFactory';
# forcer tous les résultats à être 'MyResult'
sub class_for {
  return 'MyResult';
}
1;
