TAP::Formatter::Base(3perl) Guide de référence du programmeur Perl TAP::Formatter::Base(3perl)

NOM

TAP::Formatter::Base - Classe de base pour les délégués de sortie de harness

VERSION

Version 3.50

DESCRIPTION

Ceci fournit un formatage de sortie orienté console pour TAP::Harness.

SYNOPIS

use TAP::Formatter::Console;
my $harness = TAP::Formatter::Console->new( \%args );

METHODES

Méthodes de classe

"new"

my %args = (
   verbose => 1,
)
my $harness = TAP::Formatter::Console->new( \%args );

Le constructeur retourne un nouvel objet "TAP::Formatter::Console". Si un TAP::Harness est créé sans "formatter", un "TAP::Formatter::Console" est automatiquement créé. Si l'une des options suivantes a été donnée à TAP::Harness->new, elle sera passée à ce constructeur qui accepte un hashref optionnel dont les clés autorisées sont :

  • "verbosity"

    Définit le niveau de verbosité.

  • "verbose"

    Affiche les résultats de tests individuels sur STDOUT.

  • "timer"

    Ajoute le temps d'exécution de chaque test à la sortie. Utilise Time::HiRes si disponible.

  • "failures"

    Affiche les échecs de tests (c'est une opération nulle si "verbose" est sélectionné).

  • "comments"

    Affiche les commentaires de tests (c'est une opération nulle si "verbose" est sélectionné).

  • "quiet"

    Supprime une partie de la sortie des tests (principalement les échecs pendant que les tests sont en cours d'exécution).

  • "really_quiet"

    Supprime tout sauf le résumé des tests.

  • "silent"

    Supprime toute sortie.

  • "errors"

    Si des erreurs d'analyse sont trouvées dans la sortie TAP, une note en sera faite dans le rapport récapitulatif. Pour voir toutes les erreurs d'analyse, définissez cet argument à vrai :

    errors => 1
  • "directives"

    Si défini à une valeur vraie, seuls les résultats de tests avec des directives seront affichés. Ceci remplace d'autres paramètres tels que "verbose", "failures", ou "comments".

  • "stdout"

    Un descripteur de fichier pour capturer la sortie standard.

  • "color"

    Si défini, spécifie si une sortie en couleur est souhaitée. Si "color" n'est pas défini, il utilisera par défaut la sortie en couleur si le support des couleurs est disponible sur la plateforme actuelle et que la sortie n'est pas redirigée.

  • "jobs"

    Le nombre de jobs concurrents que ce formateur gérera.

  • "show_count"

    Valeur booléenne. Si faux, désactive le compteur de tests "X/Y" qui apparaît pendant l'exécution des tests.

Toutes les clés pour lesquelles la valeur est "undef" seront ignorées.

"prepare"

Appelée par Test::Harness avant que toute sortie de test ne soit générée.

Ceci est consultatif et peut ne pas être appelé si les tests sont fournis à Test::Harness par un itérateur.

"open_test"

Appelée pour créer une nouvelle session de test. Une session de test ressemble à ceci :

my $session = $formatter->open_test( $test, $parser );
while ( defined( my $result = $parser->next ) ) {
    $session->result($result);
    exit 1 if $result->is_bailout;
}
$session->close_test;

"summary"

$harness->summary( $aggregate );

"summary" imprime le rapport récapitulatif après l'exécution de tous les tests. Le premier argument est un agrégat à résumer. Un second argument optionnel peut être défini à une valeur vraie pour indiquer que le résumé est la sortie d'une exécution de test interrompue.
