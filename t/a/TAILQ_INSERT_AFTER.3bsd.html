DESCRIPTION

These macros implement several types of singly and doubly linked lists, and queues.

A list is a data structure where each element is linked to the next element. This can be achieved using singly linked lists, doubly linked lists, or tail- queus. A tail- queue is a doubly linked list that also maintains a pointer to the tail element, allowing for efficient insertion and removal at both the head and the tail.

The following macros are provided for manipulating these data structures:

SLIST_CLASS_ENTRY(CLASSTYPE);
Declares a structure that is used as an entry in a singly linked list. The CLASSTYPE parameter is the name of the structure that will contain the list entry.
SLIST_CLASS_HEAD(HEADNAME, CLASSTYPE);
Declares a structure that is used as the head of a singly linked list. The HEADNAME parameter is the name of the structure that will contain the list head, and CLASSTYPE is the name of the structure that will contain the list entry.
SLIST_CONCAT(head1, head2, TYPE, SLIST_ENTRY NAME);
Concatenates the list pointed to by head2 onto the end of the list pointed to by head1. The TYPE and SLIST_ENTRY NAME parameters are used to access the list entry within the list elements.
SLIST_EMPTY(head);
Returns true if the list pointed to by head is empty, false otherwise.
SLIST_ENTRY(TYPE);
Declares a structure that is used as an entry in a singly linked list. The TYPE parameter is the name of the structure that will contain the list entry.
SLIST_FIRST(head);
Returns a pointer to the first element in the list pointed to by head, or NULL if the list is empty.
SLIST_FOREACH(var, head, SLIST_ENTRY NAME);
Iterates over the elements in the list pointed to by head. The var parameter is a pointer to the current element, and SLIST_ENTRY NAME is the name of the list entry within the list elements.
SLIST_FOREACH_FROM(var, head, SLIST_ENTRY NAME);
Similar to SLIST_FOREACH, but starts iterating from the element pointed to by var.
SLIST_FOREACH_FROM_SAFE(var, head, SLIST_ENTRY NAME, temp_var);
A safe version of SLIST_FOREACH_FROM that can be used when modifying the list during iteration. The temp_var parameter is used to store a temporary pointer to the next element.
SLIST_FOREACH_SAFE(var, head, SLIST_ENTRY NAME, temp_var);
A safe version of SLIST_FOREACH that can be used when modifying the list during iteration. The temp_var parameter is used to store a temporary pointer to the next element.
SLIST_HEAD(HEADNAME, TYPE);
Declares a structure that is used as the head of a singly linked list. The HEADNAME parameter is the name of the structure that will contain the list head, and TYPE is the name of the structure that will contain the list entry.
SLIST_HEAD_INITIALIZER(head);
Initializes a singly linked list head.
SLIST_INIT(head);
Initializes the singly linked list pointed to by head.
SLIST_INSERT_AFTER(listelm, elm, SLIST_ENTRY NAME);
Inserts the element pointed to by elm after the element pointed to by listelm in the list. The SLIST_ENTRY NAME parameter is used to access the list entry within the list elements.
SLIST_INSERT_HEAD(head, elm, SLIST_ENTRY NAME);
Inserts the element pointed to by elm at the head of the list pointed to by head. The SLIST_ENTRY NAME parameter is used to access the list entry within the list elements.
SLIST_NEXT(elm, SLIST_ENTRY NAME);
Returns a pointer to the next element in the list after the element pointed to by elm. The SLIST_ENTRY NAME parameter is used to access the list entry within the list elements.
SLIST_REMOVE(head, elm, TYPE, SLIST_ENTRY NAME);
Removes the element pointed to by elm from the list pointed to by head. The TYPE and SLIST_ENTRY NAME parameters are used to access the list entry within the list elements.
SLIST_REMOVE_AFTER(elm, SLIST_ENTRY NAME);
Removes the element immediately following the element pointed to by elm from the list. The SLIST_ENTRY NAME parameter is used to access the list entry within the list elements.
SLIST_REMOVE_HEAD(head, SLIST_ENTRY NAME);
Removes the first element from the list pointed to by head. The SLIST_ENTRY NAME parameter is used to access the list entry within the list elements.
SLIST_SWAP(head1, head2, TYPE);
Swaps the contents of the two lists pointed to by head1 and head2. The TYPE parameter is used to access the list entry within the list elements.
STAILQ_CLASS_ENTRY(CLASSTYPE);

STAILQ_CLASS_HEAD(HEADNAME, CLASSTYPE);

STAILQ_LAST(head, STAILQ_ENTRY NAME);
Returns a pointer to the last element in the queue pointed to by head, or NULL if the queue is empty. The STAILQ_ENTRY NAME parameter is used to access the queue entry within the queue elements.
STAILQ_NEXT(elm, STAILQ_ENTRY NAME);
Returns a pointer to the next element in the queue after the element pointed to by elm. The STAILQ_ENTRY NAME parameter is used to access the queue entry within the queue elements.
STAILQ_PREV(elm, STAILQ_ENTRY NAME);
Returns a pointer to the previous element in the queue before the element pointed to by elm. The STAILQ_ENTRY NAME parameter is used to access the queue entry within the queue elements.
STAILQ_REMOVE(head, elm, STAILQ_ENTRY NAME);

DESCRIPTION

Ces macros définissent et opèrent sur quatre types de structures de données qui peuvent être utilisées dans le code source C et C++ :

  1. Listes
  2. Listes chaînées simples
  3. Files de listes chaînées simples
  4. Files de listes chaînées
Les quatre structures supportent la fonctionnalité suivante :
  1. Insertion d'une nouvelle entrée en tête de la liste.
  2. Insertion d'une nouvelle entrée après n'importe quel élément de la liste.
  3. Suppression en O(1) d'une entrée de la tête de la liste.
  4. Parcours avant dans la liste.
  5. Échange du contenu de deux listes.

Les listes chaînées simples sont les plus simples des quatre structures de données et ne supportent que la fonctionnalité ci-dessus. Les listes chaînées simples sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une pile (LIFO). Les listes chaînées simples ajoutent la fonctionnalité suivante :

  1. Suppression en O(n) de n'importe quelle entrée dans la liste.
  2. Concaténation en O(n) de deux listes.

Les files de listes chaînées simples ajoutent la fonctionnalité suivante :

  1. Les entrées peuvent être ajoutées à la fin d'une liste.
  2. Suppression en O(n) de n'importe quelle entrée dans la liste.
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions de liste doivent spécifier la tête de la liste.
  2. Chaque entrée de tête nécessite deux pointeurs au lieu d'un.
  3. La taille du code est environ 15% plus grande et les opérations sont environ 20% plus lentes que celles des listes chaînées simples.

Les files de listes chaînées simples sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une file d'attente (FIFO).

Toutes les structures de données de type doublement chaînées (listes et files de listes chaînées) permettent en outre :

  1. Insertion d'une nouvelle entrée avant n'importe quel élément de la liste.
  2. Suppression en O(1) de n'importe quelle entrée dans la liste.
Cependant :
  1. Chaque élément nécessite deux pointeurs au lieu d'un.
  2. La taille du code et le temps d'exécution des opérations (sauf la suppression) sont environ le double de ceux des structures de données simplement chaînées.

Les listes chaînées sont les plus simples des structures de données doublement chaînées. Elles ajoutent la fonctionnalité suivante par rapport à ce qui précède :

  1. Concaténation en O(n) de deux listes.
  2. Elles peuvent être parcourues en arrière.
Cependant :
  1. Pour parcourir en arrière, une entrée pour commencer le parcours et la liste dans laquelle elle se trouve doivent être spécifiées.

Les files de listes chaînées ajoutent la fonctionnalité suivante :

  1. Les entrées peuvent être ajoutées à la fin d'une liste.
  2. Elles peuvent être parcourues en arrière, de la fin vers le début.
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions et suppressions de liste doivent spécifier la tête de la liste.
  2. Chaque entrée de tête nécessite deux pointeurs au lieu d'un.
  3. La taille du code est environ 15% plus grande et les opérations sont environ 20% plus lentes que celles des listes chaînées simples.

Dans les définitions de macros, TYPE est le nom d'une structure définie par l'utilisateur. La structure doit contenir un champ appelé NOM qui est de type SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY, ou TAILQ_ENTRY. Dans les définitions de macros, CLASSTYPE est le nom d'une classe définie par l'utilisateur. La classe doit contenir un champ appelé NOM qui est de type SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY, ou TAILQ_CLASS_ENTRY. L'argument NOMTETE est le nom d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD, ou TAILQ_CLASS_HEAD. Voir les exemples ci-dessous pour plus d'explications sur la façon dont ces macros sont utilisées.

LISTES CHAÎNÉES SIMPLES

Une liste chaînée simple est dirigée par une structure définie par la macro SLIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont chaînés simplement pour un minimum d'espace et de manipulation de pointeurs, au prix d'une suppression en O(n) pour les éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant ou en tête de la liste. Une structure SLIST_HEAD est déclarée comme suit :

SLIST_HEAD(NOMTETE, TYPE) tête;

où NOMTETE est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la liste. Un pointeur vers la tête de la liste peut plus tard être déclaré comme suit :

struct NOMTETE *tête_p;

(Les noms tête et tête_p sont sélectionnables par l'utilisateur.)

La macro SLIST_HEAD_INITIALIZER évalue à un initialiseur pour la liste tête.

La macro SLIST_CONCAT concatène la liste dirigée par tête2 à la fin de celle dirigée par tête1, supprimant toutes les entrées de la première. L'utilisation de cette macro doit être évitée car elle parcourt la totalité de la liste tête1. Une file de listes chaînées simples doit être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro SLIST_EMPTY évalue à vrai s'il n'y a aucun élément dans la liste.

La macro SLIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro SLIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro SLIST_FOREACH parcourt la liste référencée par tête dans la direction avant, assignant chaque élément en tour à var.

La macro SLIST_FOREACH_FROM se comporte identiquement à SLIST_FOREACH lorsque var est NULL, sinon elle traite var comme un élément SLIST précédemment trouvé et commence la boucle à var au lieu du premier élément de la SLIST référencée par tête.

La macro SLIST_FOREACH_SAFE parcourt la liste référencée par tête dans la direction avant, assignant chaque élément en tour à var. Cependant, contrairement à SLIST_FOREACH(), ici il est permis de supprimer var ainsi que de le libérer depuis l'intérieur de la boucle en toute sécurité sans interférer avec le parcours.

La macro SLIST_FOREACH_FROM_SAFE se comporte identiquement à SLIST_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément SLIST précédemment trouvé et commence la boucle à var au lieu du premier élément de la SLIST référencée par tête.

La macro SLIST_INIT initialise la liste référencée par tête.

La macro SLIST_INSERT_HEAD insère le nouvel élément elm en tête de la liste.

La macro SLIST_INSERT_AFTER insère le nouvel élément elm après l'élémentlistelm.

La macro SLIST_NEXT renvoie l'élément suivant de la liste.

La macro SLIST_REMOVE_AFTER supprime l'élément qui suit elm de la liste. Contrairement à SLIST_REMOVE, cette macro ne parcourt pas toute la liste.

La macro SLIST_REMOVE_HEAD supprime l'élément elm de la tête de la liste. Pour une efficacité optimale, les éléments supprimés de la tête de la liste devraient utiliser explicitement cette macro plutôt que la macro générique SLIST_REMOVE.

La macro SLIST_REMOVE supprime l'élément elm de la liste. L'utilisation de cette macro doit être évitée car elle parcourt toute la liste. Une liste doublement chaînée devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro SLIST_SWAP échange le contenu de head1 et head2.

FILES D'ATTENTE À QUEUE SIMPLEMENT CHAÎNEES

Une file d'attente à queue simplement chaînée est dirigée par une structure définie par la macro STAILQ_HEAD. Cette structure contient une paire de pointeurs, l'un vers le premier élément de la file d'attente et l'autre vers le dernier élément de la file d'attente. Les éléments sont simplement chaînés pour un minimum d'espace et de surcharge de manipulation de pointeurs, au détriment d'une suppression en O(n) pour les éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la file d'attente après un élément existant, en tête de la file d'attente, ou à la fin de la file d'attente. Une structure STAILQ_HEAD est déclarée comme suit :

STAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à chaîner dans la file d'attente. Un pointeur vers la tête de la file d'attente peut être déclaré ultérieurement comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro STAILQ_HEAD_INITIALIZER évalue une initialisation pour la file d'attente head.

La macro STAILQ_CONCAT concatène la file d'attente dirigée par head2 à la fin de celle dirigée par head1, supprimant toutes les entrées de la première.

La macro STAILQ_EMPTY évalue à vrai s'il n'y a pas d'éléments dans la file d'attente.

La macro STAILQ_ENTRY déclare une structure qui connecte les éléments de la file d'attente.

La macro STAILQ_FIRST renvoie le premier élément de la file d'attente ou NULL si la file d'attente est vide.

La macro STAILQ_FOREACH parcourt la file d'attente référencée par head dans la direction avant, assignant chaque élément à tour de rôle à var.

La macro STAILQ_FOREACH_FROM se comporte identiquement à STAILQ_FOREACH lorsque var est NULL, sinon elle traite var comme un élément STAILQ trouvé précédemment et commence la boucle à var au lieu du premier élément de la STAILQ référencée par head.

La macro STAILQ_FOREACH_SAFE parcourt la file d'attente référencée par head dans la direction avant, assignant chaque élément à tour de rôle à var. Cependant, contrairement à STAILQ_FOREACH(), il est permis ici de supprimer var ainsi que de le libérer depuis la boucle en toute sécurité sans interférer avec le parcours.

La macro STAILQ_FOREACH_FROM_SAFE se comporte identiquement à STAILQ_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément STAILQ trouvé précédemment et commence la boucle à var au lieu du premier élément de la STAILQ référencée par head.

La macro STAILQ_INIT initialise la file d'attente référencée par head.

La macro STAILQ_INSERT_HEAD insère le nouvel élément elm en tête de la file d'attente.

La macro STAILQ_INSERT_TAIL insère le nouvel élément elm à la fin de la file d'attente.

La macro STAILQ_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro STAILQ_LAST renvoie le dernier élément de la file d'attente. Si la file d'attente est vide, la valeur de retour est NULL.

La macro STAILQ_NEXT renvoie le prochain élément de la file d'attente, ou NULL si cet élément est le dernier.

La macro STAILQ_REMOVE_AFTER supprime l'élément qui suit elm de la file d'attente. Contrairement à STAILQ_REMOVE, cette macro ne parcourt pas toute la file d'attente.

La macro STAILQ_REMOVE_HEAD supprime l'élément en tête de la file d'attente. Pour une efficacité optimale, les éléments supprimés de la tête de la file d'attente devraient utiliser explicitement cette macro plutôt que la macro générique STAILQ_REMOVE.

La macro STAILQ_REMOVE supprime l'élément elm de la file d'attente. L'utilisation de cette macro doit être évitée car elle parcourt toute la liste. Une file d'attente doublement chaînée devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues files d'attente.

La macro STAILQ_SWAP échange le contenu de head1 et head2.

n1 = malloc(sizeof(struct entry));	/* Insérer à la queue. */
STAILQ_INSERT_TAIL(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
STAILQ_INSERT_AFTER(&head, n1, n2, entries);
					/* Suppression. */
STAILQ_REMOVE(&head, n2, entry, entries);
free(n2);
					/* Suppression de la tête. */
n3 = STAILQ_FIRST(&head);
STAILQ_REMOVE_HEAD(&head, entries);
free(n3);
					/* Parcours avant. */
STAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sécurisé. */
STAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	STAILQ_REMOVE(&head, np, entry, entries);
	free(np);
}
					/* Suppression de la TailQ. */
while (!STAILQ_EMPTY(&head)) {
	n1 = STAILQ_FIRST(&head);
	STAILQ_REMOVE_HEAD(&head, entries);
	free(n1);
}
					/* Suppression plus rapide de la TailQ. */
n1 = STAILQ_FIRST(&head);
while (n1 != NULL) {
	n2 = STAILQ_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
STAILQ_INIT(&head);

LISTES

Une liste est dirigée par une structure définie par la macro LIST_HEAD. Cette structure contient un unique pointeur vers le premier élément de la liste. Les éléments sont doublement chaînés de sorte qu'un élément arbitraire puisse être supprimé sans parcourir la liste. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant, avant un élément existant, ou en tête de liste. Une structure LIST_HEAD est déclarée comme suit :

LIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à chaîner dans la liste. Un pointeur vers la tête de la liste peut être déclaré ultérieurement comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro LIST_HEAD_INITIALIZER évalue une initialisation pour la liste head.

La macro LIST_CONCAT concatène la liste dirigée par head2 à la fin de celle dirigée par head1, supprimant toutes les entrées de la première. L'usage de cette macro doit être évité car elle parcourt la totalité de la liste head1. Une file d'attente à queue devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro LIST_EMPTY évalue à vrai s'il n'y a aucun élément dans la liste.

La macro LIST_ENTRY déclare une structure qui connecte les éléments de la liste.

La macro LIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro LIST_FOREACH parcourt la liste référencée par head en, assignant chaque élément à tour de rôle à var.

LIST EXAMPLE

LIST_HEAD(listhead, entry) head =
    LIST_HEAD_INITIALIZER(head);
struct listhead *headp;			/* List head. */
struct entry {
	...
	LIST_ENTRY(entry) entries;	/* List. */
	...
} *n1, *n2, *n3, *np, *np_temp;

LIST_INIT(&head);			/* Initialize the list. */

n1 = malloc(sizeof(struct entry));	/* Insert at the head. */
LIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insert after. */
LIST_INSERT_AFTER(n1, n2, entries);

n3 = malloc(sizeof(struct entry));	/* Insert before. */
LIST_INSERT_BEFORE(n2, n3, entries);

LIST_REMOVE(n2, entries);		/* Deletion. */
free(n2);
					/* Forward traversal. */
LIST_FOREACH(np, &head, entries)
	np-> ...

					/* Safe forward traversal. */
LIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	LIST_REMOVE(np, entries);
	free(np);
}

while (!LIST_EMPTY(&head)) {		/* List Deletion. */
	n1 = LIST_FIRST(&head);
	LIST_REMOVE(n1, entries);
	free(n1);
}

n1 = LIST_FIRST(&head);			/* Faster List Deletion. */
while (n1 != NULL) {
	n2 = LIST_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
LIST_INIT(&head);

TAIL QUEUES

Une queue de liste chaînée est dirigée par une structure définie par la macro TAILQ_HEAD. Cette structure contient une paire de pointeurs, un vers le premier élément de la queue de liste chaînée et l'autre vers le dernier élément. Les éléments sont doublement chaînés de sorte qu'un élément arbitraire puisse être supprimé sans parcourir la queue de liste chaînée. De nouveaux éléments peuvent être ajoutés à la queue de liste chaînée après un élément existant, avant un élément existant, en tête de la queue de liste chaînée ou à la fin de la queue de liste chaînée. Une structure TAILQ_HEAD est déclarée comme suit :

TAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à relier dans la queue de liste chaînée. Un pointeur vers la tête de la queue de liste chaînée peut plus tard être déclaré comme :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro TAILQ_HEAD_INITIALIZER s'évalue comme un initialiseur pour la queue de liste chaînée head.

La macro TAILQ_CONCAT concatène la queue de liste chaînée dirigée par head2 à la fin de celle dirigée par head1, supprimant toutes les entrées de la première.

La macro TAILQ_EMPTY s'évalue à vrai s'il n'y a aucun élément dans la queue de liste chaînée.

La macro TAILQ_ENTRY déclare une structure qui relie les éléments de la queue de liste chaînée.

La macro TAILQ_FIRST retourne le premier élément de la queue de liste chaînée ou NULL si la queue est vide.

La macro TAILQ_FOREACH parcourt la queue de liste chaînée référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var. var est mis à NULL si la boucle se termine normalement, ou s'il n'y avait aucun élément.

La macro TAILQ_FOREACH_FROM se comporte de manière identique à TAILQ_FOREACH lorsque var est NULL, sinon elle traite var comme un élément TAILQ trouvé précédemment et commence la boucle à var au lieu du premier élément de la TAILQ référencée par head.

La macro TAILQ_FOREACH_REVERSE parcourt la queue de liste chaînée référencée par head dans le sens inverse, assignant chaque élément à tour de rôle à var.

La macro TAILQ_FOREACH_REVERSE_FROM se comporte de manière identique à TAILQ_FOREACH_REVERSE lorsque var est NULL, sinon elle traite var comme un élément TAILQ trouvé précédemment et commence la boucle inverse à var au lieu du dernier élément de la TAILQ référencée par head.

Les macros TAILQ_FOREACH_SAFE et TAILQ_FOREACH_REVERSE_SAFE parcourent la liste référencée par head dans le sens avant ou inverse respectivement, assignant chaque élément à tour de rôle à var. Cependant, contrairement à leurs homologues non sécurisés, TAILQ_FOREACH et TAILQ_FOREACH_REVERSE permettent de supprimer var ainsi que de le libérer de la boucle en toute sécurité sans interférer avec le parcours.

La macro TAILQ_FOREACH_FROM_SAFE se comporte de manière identique à TAILQ_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément TAILQ trouvé précédemment et commence la boucle à var au lieu du premier élément de la TAILQ référencée par head.

La macro TAILQ_FOREACH_REVERSE_FROM_SAFE se comporte de manière identique à TAILQ_FOREACH_REVERSE_SAFE lorsque var est NULL, sinon elle traite var comme un élément TAILQ trouvé précédemment et commence la boucle inverse à var au lieu du dernier élément de la TAILQ référencée par head.

La macro TAILQ_INIT initialise la queue de liste chaînée référencée par head.

La macro TAILQ_INSERT_HEAD insère le nouvel élément elm en tête de la queue de liste chaînée.

La macro TAILQ_INSERT_TAIL insère le nouvel élément elm à la fin de la queue de liste chaînée.

La macro TAILQ_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro TAILQ_INSERT_BEFORE insère le nouvel élément elm avant l'élément listelm.

La macro TAILQ_LAST retourne le dernier élément de la queue de liste chaînée. Si la queue est vide, la valeur de retour est NULL.

La macro TAILQ_NEXT retourne l'élément suivant de la queue de liste chaînée, ou NULL si cet élément est le dernier.

La macro TAILQ_PREV retourne l'élément précédent de la queue de liste chaînée, ou NULL si cet élément est le premier.

La macro TAILQ_REMOVE supprime l'élément elm de la queue de liste chaînée.

La macro TAILQ_SWAP échange le contenu de head1 et head2.

DIAGNOSTICS

Lors du débogage de queue(3), il peut être utile de tracer les changements de file d'attente. Pour activer le traçage, définissez la macro QUEUE_MACRO_DEBUG_TRACE au moment de la compilation.

Il peut également être utile de "corrompre" les pointeurs qui ont été désolidarisés d'une file d'attente, pour détecter une utilisation après suppression. Pour activer la corruption de pointeurs, définissez la macro QUEUE_MACRO_DEBUG_TRASH au moment de la compilation. La macro QMD_IS_TRASHED(void *ptr) retourne vrai si ptr a été corrompu par l'option QUEUE_MACRO_DEBUG_TRASH.
