ARGUMENTS

Tcl_Condition *condPtr (entrée)
Une variable de condition, qui doit être associée à un verrou mutex.
Tcl_Mutex *mutexPtr (entrée)
Un verrou mutex.
const Tcl_Time *timePtr (entrée)
Une limite de temps pour l'attente de la condition. NULL pour attendre indéfiniment. Notez qu'une valeur de polling de 0 seconde n'a pas beaucoup de sens.
Tcl_ThreadDataKey *keyPtr (entrée)
Identifie un bloc de stockage local au thread. La clé doit être statique et propre à l'ensemble du processus, et pourtant chaque thread finira par associer un bloc de stockage différent à cette clé.
int *size (entrée)
La taille du bloc de stockage local au thread. Cette quantité de données est allouée et initialisée à zéro lors du premier appel à Tcl_GetThreadData par chaque thread.
Tcl_ThreadId *idPtr (sortie)
Le stockage référencé contiendra l'identifiant du nouveau thread tel que retourné par le système d'exploitation.
Tcl_ThreadId id (entrée)
Identifiant du thread attendu.
Tcl_ThreadCreateProc *proc (entrée)
Cette procédure agira comme le main() du nouveau thread. Le clientData spécifié sera son seul argument.
ClientData clientData (entrée)
Informations arbitraires. Passées comme seul argument à la procédure proc.
int stackSize (entrée)
La taille de la pile allouée au nouveau thread.
int flags (entrée)
Masque de bits contenant des indicateurs permettant à l'appelant de modifier le comportement du nouveau thread.
int *result (sortie)
Le stockage référencé est utilisé pour y placer le code de sortie du thread attendu.

INTRODUCTION

Depuis la sortie 8.1, le cœur de Tcl est thread-safe, ce qui vous permet d'intégrer Tcl dans des applications multithreadées sans personnalisation du cœur de Tcl. Depuis la sortie 8.6, le support multithreading de Tcl est activé par défaut. Pour désactiver le support multithreading de Tcl, vous devez inclure l'option --disable-threads dans configure lors de la configuration et de la compilation de votre cœur Tcl.

Une contrainte importante de l'implémentation des threads Tcl est que seul le thread qui a créé un interpréteur Tcl peut utiliser cet interpréteur. En d'autres termes, plusieurs threads ne peuvent pas accéder au même interpréteur Tcl. (Cependant, un seul thread peut créer et utiliser plusieurs interpréteurs en toute sécurité.)

DESCRIPTION

Tcl fournit Tcl_CreateThread pour la création de threads. L'appelant peut déterminer la taille de la pile allouée au nouveau thread et modifier son comportement via les flags fournis. La valeur TCL_THREAD_STACK_DEFAULT pour stackSize indique que la taille par défaut spécifiée par le système d'exploitation doit être utilisée pour le nouveau thread. Quant aux drapeaux, seules les valeurs TCL_THREAD_NOFLAGS et TCL_THREAD_JOINABLE sont actuellement définies. La première d'entre elles active le comportement par défaut sans réglages spéciaux. L'utilisation de la seconde valeur marque le nouveau thread comme joinable. Cela signifie qu'un autre thread peut attendre la sortie d'un tel thread marqué et le rejoindre.

Restrictions : Sur certains systèmes UNIX, la bibliothèque pthread ne contient pas la fonctionnalité permettant de spécifier la taille de la pile d'un thread. La valeur spécifiée pour la taille de la pile est ignorée sur ces systèmes. Windows ne prend actuellement pas en charge les threads joinables. Cette valeur de drapeau est donc ignorée sur cette plateforme.

Tcl fournit les fonctions Tcl_ExitThread et Tcl_FinalizeThread pour terminer les threads et invoquer des gestionnaires de sortie facultatifs par thread. Voir la page Tcl_Exit pour plus d'informations sur ces procédures.

La fonction Tcl_JoinThread est fournie pour permettre aux threads d'attendre la sortie d'un autre thread, qui doit avoir été marqué comme joinable via l'utilisation du drapeau TCL_THREAD_JOINABLE lors de sa création via Tcl_CreateThread.

Tenter d'attendre la sortie d'un thread non joinable ou d'un thread déjà attendu entraînera une erreur. Attendre un thread joinable qui est déjà sorti est possible, le système conservera les informations nécessaires jusqu'après l'appel à Tcl_JoinThread. Cela signifie que ne pas appeler Tcl_JoinThread pour un thread joinable provoquera une fuite de mémoire.

L'appel Tcl_GetThreadData renvoie un pointeur vers un bloc de données privées au thread. Son argument est une clé partagée par tous les threads et une taille pour le bloc de stockage. Le stockage est automatiquement alloué et initialisé à zéro lors de la première demande par chaque thread. Le stockage est automatiquement désalloué par Tcl_FinalizeThread.

SYNCHRONISATION ET COMMUNICATION

Tcl fournit Tcl_ThreadQueueEvent et Tcl_ThreadAlert pour gérer la mise en file d'attente des événements dans les applications multithreadées. Voir la page du manuel Notifier pour plus d'informations sur ces procédures.

Un mutex est un verrou utilisé pour sérialiser tous les threads à travers un morceau de code en appelant Tcl_MutexLock et Tcl_MutexUnlock. Si un thread détient un mutex, tout autre thread appelant Tcl_MutexLock sera bloqué jusqu'à ce que Tcl_MutexUnlock soit appelé. Un mutex peut être détruit après son utilisation en appelant Tcl_MutexFinalize. Le résultat du verrouillage d'un mutex deux fois par le même thread est indéfini. Sur certaines plateformes, cela entraînera un interblocage. Les procédures Tcl_MutexLock, Tcl_MutexUnlock et Tcl_MutexFinalize sont définies comme des macros vides si les threads ne sont pas activés lors de la compilation. Pour la déclaration des mutex, la macro TCL_DECLARE_MUTEX doit être utilisée. Cette macro assure une gestion correcte des mutex même lorsque le cœur est compilé sans support des threads.

Une variable de condition est utilisée comme mécanisme de signalisation : un thread peut verrouiller un mutex puis attendre sur une variable de condition avec Tcl_ConditionWait. Ceci libère atomiquement le verrou du mutex et bloque le thread en attente jusqu'à ce qu'un autre thread appelle Tcl_ConditionNotify. L'appelant de Tcl_ConditionNotify doit détenir le mutex associé en ayant précédemment appelé Tcl_MutexLock, mais cela n'est pas imposé. La notification de la variable de condition débloque tous les threads en attente sur la variable de condition, mais ils ne continuent pas tant que le mutex n'est pas libéré avec Tcl_MutexUnlock. L'implémentation de Tcl_ConditionWait verrouille automatiquement le mutex avant de retourner.

L'appelant de Tcl_ConditionWait doit être préparé aux notifications parasites en appelant Tcl_ConditionWait dans une boucle while qui teste un invariant.

Une variable de condition peut être détruite après son utilisation en appelant Tcl_ConditionFinalize.

Les procédures Tcl_ConditionNotify, Tcl_ConditionWait et Tcl_ConditionFinalize sont définies comme des macros vides si les threads ne sont pas activés lors de la compilation.

INITIALISATION

Tous ces objets de synchronisation sont auto-initialisants. Ils sont implémentés comme des pointeurs opaques qui doivent être NULL lors de leur première utilisation. Les mutex et les variables de condition sont soit nettoyés par des gestionnaires de sortie de processus (s'ils vivent assez longtemps), soit explicitement par des appels à Tcl_MutexFinalize ou Tcl_ConditionFinalize. Le stockage local aux threads est récupéré lors de Tcl_FinalizeThread.

NOM

TCL_THREAD_CREATE_PROC, TCL_THREAD_CREATE_TYPE

SYNOPIS

Pour créer un thread avec du code portable, sa fonction d'implémentation doit être déclarée comme suit :

static Tcl_ThreadCreateProc MonFonctionImplmentationThread;

Elle devrait ensuite être définie comme dans cet exemple, qui se contente de compter jusqu'à une valeur donnée puis se termine.

static Tcl_ThreadCreateType
MonFonctionImplmentationThread(
    ClientData clientData)
{
    int i, limite = (int) clientData;
    for (i=0 ; i<limite ; i++) {
        /* ne fait rien du tout ici */
    }
    TCL_THREAD_CREATE_RETURN;
}

Pour créer le thread ci-dessus, le faire exécuter et attendre qu'il se termine, nous ferions ceci :

int limite = 1000000000;
ClientData donneesLimite = (void*)((intptr_t) limite);
Tcl_ThreadId id;    /* contient l'identifiant du thread créé */
int resultat;
if (Tcl_CreateThread(&id, MonFonctionImplmentationThread, donneesLimite,
        TCL_THREAD_STACK_DEFAULT,
        TCL_THREAD_JOINABLE) != TCL_OK) {
    /* Le thread n'a pas été créé correctement */
    return;
}
/* Faire autre chose pendant un moment ici */
if (Tcl_JoinThread(id, &resultat) != TCL_OK) {
    /* Le thread ne s'est pas terminé correctement */
    return;
}
/* Tout est proprement nettoyé */

ARGUMENTS

Les arguments suivants sont utilisés :

ClientData clientData

Ce sont les données client passées à la fonction du thread.

TCL_THREAD_STACK_DEFAULT

C'est la taille de pile par défaut pour le thread.

TCL_THREAD_JOINABLE

Cela indique que le thread peut être joint.
