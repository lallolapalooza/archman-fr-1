DESCRIPTION

Ces fonctions sont conçues pour accéder à plusieurs interpréteurs depuis des programmes C. Elles permettent de gérer plusieurs interpréteurs dans une relation hiérarchique, ainsi que la gestion des alias, des commandes qui, lorsqu'elles sont invoquées dans un interpréteur, sont exécutées dans un autre. La valeur de retour des fonctions qui renvoient un entier est soit TCL_OK, soit TCL_ERROR. Si TCL_ERROR est retourné, alors le résultat de l'interpréteur contient un message d'erreur.

Tcl_CreateSlave crée un nouvel interpréteur comme enfant de interp. Il crée également une commande enfant nommée childName dans interp, qui permet à interp de manipuler le nouvel enfant. Si isSafe est zéro, la commande crée un enfant fiable dans lequel le code Tcl a accès à toutes les commandes Tcl. Si c'est 1, la commande crée un enfant "sûr" dans lequel le code Tcl n'a accès qu'à un ensemble de commandes Tcl définies comme "Safe Tcl" ; voir l'entrée du manuel de la commande Tcl interp pour plus de détails. Si la création du nouvel interpréteur enfant échoue, NULL est retourné.

Tcl_CreateChild est un synonyme de Tcl_CreateSlave.

Tcl_IsSafe retourne 1 si interp est "sûr" (créé avec le flag TCL_SAFE_INTERPRETER spécifié), 0 sinon.

Tcl_MakeSafe marque interp comme "sûr", de sorte que les futurs appels à Tcl_IsSafe retournent 1. Il supprime également de interp toute fonctionnalité connue qui pourrait être dangereuse (commandes et variables). Cependant, il ne peut pas savoir quelles parties d'une extension ou d'une application sont sûres et ne fait aucune tentative pour supprimer ces parties, de sorte que la sécurité n'est pas garantie après l'appel à Tcl_MakeSafe. Les utilisateurs doivent être prudents lors de l'utilisation de Tcl_MakeSafe pour éviter de fausses affirmations de sécurité. Dans de nombreux cas, Tcl_CreateSlave peut être un meilleur choix, car il crée des interpréteurs dans un état sûr connu.

Tcl_GetSlave retourne un pointeur vers un interpréteur enfant de interp. L'interpréteur enfant est identifié par childName. Si un tel interpréteur enfant n'existe pas, NULL est retourné.

Tcl_GetChild est un synonyme de Tcl_GetSlave.

Tcl_GetMaster retourne un pointeur vers l'interpréteur maître de interp. Si interp n'a pas de maître (c'est-à-dire, c'est un interpréteur de niveau supérieur), NULL est retourné.

Tcl_GetParent est un synonyme de Tcl_GetMaster.

Tcl_GetInterpPath stocke dans le résultat de interp le chemin relatif entre interp et childInterp ; childInterp doit être un enfant de interp. Si le calcul du chemin relatif réussit, TCL_OK est retourné, sinon TCL_ERROR et un message d'erreur est stocké comme résultat de interp.

Tcl_CreateAlias crée une commande nommée childCmd dans childInterp qui, lorsqu'elle est invoquée, provoquera l'exécution de la commande targetCmd dans targetInterp. Les arguments spécifiés par les chaînes dans argv sont toujours ajoutés aux arguments fournis lors de l'invocation de childCmd et passés à targetCmd. Cette opération retourne TCL_OK si elle réussit, sinon TCL_ERROR et un message d'erreur est stocké dans la valeur de résultat de childInterp. Remarque : il n'y a pas de restriction sur la relation d'héritage entre childInterp et targetInterp (telle que créée par Tcl_CreateSlave). Deux interpréteurs quelconques peuvent être utilisés sans restriction sur la manière dont ils sont liés.

Tcl_CreateAliasObj est similaire à Tcl_CreateAlias, sauf qu'il prend un tableau de valeurs à passer comme arguments supplémentaires au lieu d'un tableau de chaînes.

Tcl_GetAliasObj retourne des informations sous la forme d'un pointeur vers un tableau de structures Tcl_Obj sur un alias aliasName dans interp. N'importe lequel des champs de résultat peut être NULL, auquel cas les données correspondantes ne sont pas retournées. Si un champ de résultat n'est pas NULL, l'adresse indiquée est définie sur la donnée correspondante. Par exemple, si targetCmdPtr n'est pas NULL, il est défini sur un pointeur vers la chaîne contenant le nom de la commande cible.

Tcl_GetAlias est similaire à Tcl_GetAliasObj, sauf qu'il retourne un pointeur vers un tableau de chaînes de caractères au lieu d'un tableau de structures Tcl_Obj. Tcl_GetAlias est obsolète

Tcl_CreateSlave

SYNOPSIS

#include <tcl.h>

Tcl_Interp *
Tcl_CreateSlave(
    Tcl_Interp *interp,
    const char *slaveName,
    int isPrivate
);

void
Tcl_MakeWindowPackageSlave(
    Tcl_Interp *interp,
    const char *slaveName
);

void
Tcl_DeleteSlave(
    Tcl_Interp *interp,
    const char *slaveName
);

ARGUMENTS

Tcl_Interp *interp (in)
The interpreter in which to create the new slave interpreter.
const char *slaveName (in)
The name for the new slave interpreter. This name is entered in the master interpreter’s namespace.
int isPrivate (in)
Non-zero means the slave interpreter should be created as a private slave. Zero means it should be created as a public slave.

DESCRIPTION

These functions are used to create, control, and destroy Tcl interpreters that are slaves of other interpreters.

Tcl_CreateSlave creates a new Tcl interpreter which is a slave to the interpreter given by interp. The new interpreter is created with the name specified by slaveName. This name is added to the global namespace of the master interpreter, interp. The name must not contain namespace qualifiers (e.g., {::foo}) or have global namespace qualifiers (e.g., {::bar}). If slaveName is null or empty, no name is created in the master interpreter’s namespace.

The isPrivate argument determines whether the slave interpreter is public or private. A public slave interpreter (isPrivate is 0) can be invoked directly by name from the master interpreter. A private slave interpreter (isPrivate is non-zero) can only be invoked via the interp command. In addition, commands invoked in a private slave will not create new global variables in the master interpreter.

If the creation is successful, Tcl_CreateSlave returns a pointer to the new slave interpreter. If an interpreter already exists with the name slaveName in the master interpreter’s global namespace, or if memory allocation fails, Tcl_CreateSlave returns NULL.

Tcl_MakeWindowPackageSlave is a convenience procedure that calls Tcl_CreateSlave to create a private slave interpreter named slaveName. It then makes sure that the windowing package is loaded into the new slave interpreter.

Tcl_DeleteSlave destroys the slave interpreter named slaveName. The name slaveName must be the name of an existing slave interpreter that is accessible from the master interpreter given by interp. If slaveName does not refer to an existing slave interpreter, or if the slave interpreter is not actually a slave (e.g., it was created with Tcl_CreateInterp), this procedure does nothing.

For a description of the Tcl interface to multiple interpreters, see interp(n).
