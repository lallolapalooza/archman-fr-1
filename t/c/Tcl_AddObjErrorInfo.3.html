ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur dans lequel enregistrer les informations.

int code Le code retourné par l'évaluation du script.
Tcl_Obj *options Un dictionnaire d'options de retour.

const char *message (in)
Pour Tcl_AddErrorInfo, il s'agit d'une chaîne C conventionnelle à ajouter à l'option de retour -errorinfo. Pour Tcl_AddObjErrorInfo, il pointe vers le premier octet d'un tableau de length octets contenant une chaîne à ajouter à l'option de retour -errorinfo. Ce tableau d'octets peut contenir des octets nuls intégrés, sauf si length est négatif.
Tcl_Obj *objPtr (in)
Un message à ajouter à l'option de retour -errorinfo sous la forme d'une valeur Tcl_Obj.
int length (in)
Le nombre d'octets à copier depuis message lors de l'ajout à l'option de retour -errorinfo. Si négatif, tous les octets jusqu'au premier octet nul sont utilisés.
Tcl_Obj *errorObjPtr (in)
L'option de retour -errorcode sera définie sur cette valeur.
const char *element (in)
Chaîne à enregistrer comme un élément de l'option de retour -errorcode. Le dernier argument element doit être (char *)NULL.
va_list argList (in)
Une liste d'arguments qui doit avoir été initialisée avec va_start, et effacée avec va_end.

int lineNum Le numéro de ligne d'un script où une erreur s'est produite.
const char *script (in)
Pointeur vers le premier caractère du script contenant la commande (doit être <= command)
const char *command (in)
Pointeur vers le premier caractère de la commande qui a généré l'erreur
int commandLength (in)
Nombre d'octets dans la commande ; -1 signifie utiliser tous les octets jusqu'au premier octet nul

DESCRIPTION

Les routines Tcl_SetReturnOptions et Tcl_GetReturnOptions exposent les mêmes capacités que les commandes return et catch, respectivement, sous la forme d'une interface C.

Tcl_GetReturnOptions récupère le dictionnaire des options de retour d'un interpréteur après l'évaluation d'un script. Des routines telles que Tcl_Eval sont appelées pour évaluer un script dans un interpréteur. Ces routines retournent un code de complétion entier. Ces routines laissent également dans l'interpréteur à la fois un résultat et un dictionnaire d'options de retour généré par l'évaluation du script. Tout comme Tcl_GetObjResult récupère le résultat, Tcl_GetReturnOptions récupère le dictionnaire des options de retour. Le code de complétion entier doit être passé comme argument code à Tcl_GetReturnOptions afin que toutes les options requises soient présentes dans le dictionnaire. Spécifiquement, une valeur de code de TCL_ERROR garantira que les entrées pour les clés -errorinfo, -errorcode et -errorline apparaîtront dans le dictionnaire. De plus, les entrées pour les clés -code et -level seront ajustées si nécessaire pour correspondre à la valeur de code. Le (Tcl_Obj *) retourné par Tcl_GetReturnOptions pointe vers un Tcl_Obj non partagé avec un compteur de référence de zéro. Le dictionnaire peut être modifié, soit en ajoutant, supprimant ou écrasant des entrées, sans avoir besoin de vérifier une valeur partagée. Comme avec tout Tcl_Obj avec un compteur de référence de zéro, il appartient à l'appelant d'organiser sa suppression avec Tcl_DecrRefCount ou de référencer celui-ci via Tcl_IncrRefCount (ou l'une des nombreuses fonctions qui l'appellent, notamment Tcl_SetObjResult et Tcl_SetVar2Ex).

Une utilisation typique pour Tcl_GetReturnOptions est de récupérer la trace de la pile lorsqu'une évaluation de script retourne TCL_ERROR, comme suit :

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* Faire quelque chose avec stackTrace */
    Tcl_DecrRefCount(options);
}

Tcl_SetReturnOptions définit les options de retour de interp à être options. Si options contient une valeur invalide pour une clé, TCL_ERROR sera retourné, et le résultat de l'interpréteur sera défini sur un message d'erreur approprié. Sinon, un code de complétion en accord avec les clés -code et -level dans options sera retourné.

Par exemple, la commande return de Tcl elle-même pourrait être implémentée en utilisant Tcl_SetReturnOptions comme suit :

if ((objc % 2) == 0) { /* argument de résultat explicite */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(Ce n'est pas vraiment implémenté de cette façon. Les privilèges d'accès internes permettent une alternative plus efficace qui s'intègre mieux avec le compilateur de bytecode.)

Notez qu'un Tcl_Obj nouvellement créé peut être passé comme argument options sans qu'il soit nécessaire de gérer le comptage de référence. Ceci est analogue à Tcl_SetObjResult.

Alors que Tcl_SetReturnOptions fournit une interface générale pour définir toute collection d'options de retour, il existe une poignée d'options de retour qui sont très fréquemment utilisées. Notamment, les options de retour -errorinfo et -errorcode doivent être correctement définies lorsque la procédure de commande d'une commande retourne TCL_ERROR. L'option de retour -errorline est également lue par les commandes qui évaluent des scripts et souhaitent fournir des informations détaillées sur l'emplacement de l'erreur dans le texte de la trace de la pile qu'elles ajoutent à l'option -errorinfo. Tcl fournit plusieurs interfaces plus simples pour définir plus directement ces options de retour.

L'option -errorinfo contient une trace de la pile des opérations qui étaient en cours lorsqu'une erreur s'est produite, et est destinée à être lisible par l'homme. L'option -errorcode contient une liste Tcl d'éléments destinés à être lisibles par machine. Le premier élément de la valeur -errorcode identifie la classe d'erreur qui s'est produite (par exemple, POSIX signifie qu'une erreur s'est produite dans un appel système POSIX) et des éléments supplémentaires contiennent des informations supplémentaires qui dépendent de la classe. Voir la page de manuel sur la variable errorCode pour des détails sur les différents formats de l'option -errorcode utilisés par les commandes intégrées de Tcl.

La valeur de l'option -errorinfo est progressivement construite au fur et à mesure qu'une erreur remonte les opérations imbriquées. Chaque fois qu'un code d'erreur est retourné à Tcl_Eval, ou à l'une des routines qui effectue l'évaluation de script, la procédure Tcl_AddErrorInfo est appelée pour ajouter du texte supplémentaire à la valeur -errorinfo décrivant la commande qui était en cours d'exécution lorsque l'erreur s'est produite. Au moment où l'erreur est entièrement renvoyée à l'application, elle contiendra une trace complète de l'activité en cours lorsque l'erreur s'est produite.

Il est parfois utile d'ajouter des informations supplémentaires à la valeur -errorinfo au-delà de ce qui peut être fourni automatiquement par les routines d'évaluation de script. Tcl_AddErrorInfo peut être utilisé à cet effet : son argument message est une chaîne supplémentaire à ajouter à l'option -errorinfo. Par exemple, lorsqu'une erreur survient pendant la commande source, la procédure Tcl_AddErrorInfo est appelée pour enregistrer le nom du fichier en cours de traitement et le numéro de ligne sur lequel l'erreur s'est produite. ARGUMENTS

Invocations de Tcl_AddErrorInfo, Tcl_AppendObjToErrorInfo, Tcl_AddObjErrorInfo, Tcl_LogCommandInfo:

L'interprète Tcl à modifier est interp, qui doit être un pointeur vers une structure Tcl_Interp valide.

Pour Tcl_AddErrorInfo, message est un pointeur vers une chaîne de caractères se terminant par un caractère nul qui sera ajoutée à la valeur de l'option de retour -errorinfo.

Pour Tcl_AppendObjToErrorInfo, objPtr est un pointeur vers une structure Tcl_Obj dont la valeur de chaîne sera ajoutée à la valeur de l'option de retour -errorinfo.

Pour Tcl_AddObjErrorInfo, message est un pointeur vers une chaîne de caractères et length est la longueur de la chaîne. Si length est négatif, la longueur est déterminée par le caractère nul terminateur.

Pour Tcl_LogCommandInfo, commandName est le nom de la commande en cours d'exécution et lineNum est le numéro de ligne de cette commande dans le script source.

Invocations de Tcl_SetObjErrorCode, Tcl_SetErrorCode, Tcl_SetErrorCodeVA:

L'interprète Tcl à modifier est interp.

Pour Tcl_SetObjErrorCode, errorObjPtr est un pointeur vers une structure Tcl_Obj dont la valeur sera définie comme l'option de retour -errorcode.

Pour Tcl_SetErrorCode, les arguments restants sont une liste de chaînes de caractères se terminant par un caractère nul qui seront utilisés pour construire la valeur de l'option de retour -errorcode. Par exemple, Tcl_SetErrorCode(interp, "POSIX", errno, (char *) NULL);

Pour Tcl_SetErrorCodeVA, argList est une liste d'arguments contenant les mêmes informations que les arguments de Tcl_SetErrorCode.

Invocations de Tcl_GetErrorLine, Tcl_SetErrorLine:

L'interprète Tcl est interp.

Pour Tcl_SetErrorLine, line est la valeur entière à définir pour l'option de retour -errorline.

Invocation de Tcl_PosixError:

L'interprète Tcl est interp.

Invocation de Tcl_ResetResult:

L'interprète Tcl est interp.

DESCRIPTION

Ces procédures sont utilisées pour gérer les informations d'erreur associées à un interpréteur Tcl. Elles permettent de définir ou d'interroger les options de retour d'erreur telles que -errorinfo et -errorcode.

Tcl_AddErrorInfo ajoute une chaîne de caractères à la fin de la valeur de l'option de retour -errorinfo. Cette option contient une trace de la pile des appels de procédure et le numéro de ligne où l'erreur s'est produite. Le moment idéal pour appeler Tcl_AddErrorInfo est juste après qu'une routine d'évaluation de script ait retourné TCL_ERROR. La valeur de l'option de retour -errorline (récupérée via un appel à Tcl_GetReturnOptions) constitue souvent une partie utile du message passé à Tcl_AddErrorInfo.

Tcl_AppendObjToErrorInfo est une interface alternative offrant la même fonctionnalité que Tcl_AddErrorInfo. Tcl_AppendObjToErrorInfo est appelée lorsque la valeur de chaîne à ajouter à l'option -errorinfo est disponible sous forme de Tcl_Obj au lieu d'un tableau char.

Tcl_AddObjErrorInfo est presque identique à Tcl_AddErrorInfo, à l'exception d'un argument length supplémentaire. Cela permet à la chaîne message de contenir des octets nuls incorporés. Ce n'est pratiquement jamais une bonne idée. Si le message doit contenir le caractère nul U+0000, les règles de codage internes habituelles de Tcl doivent être utilisées pour éviter d'avoir besoin d'un octet nul. Si l'interface Tcl_AddObjErrorInfo est utilisée, elle doit l'être avec une valeur length négative.

La procédure Tcl_SetObjErrorCode est utilisée pour définir l'option de retour -errorcode avec la valeur de liste errorObjPtr construite par l'appelant. Tcl_SetObjErrorCode est généralement appelée juste avant de retourner une erreur. Si une erreur est retournée sans appeler Tcl_SetObjErrorCode ou Tcl_SetErrorCode, l'interpréteur Tcl définit automatiquement l'option de retour -errorcode à NONE.

La procédure Tcl_SetErrorCode est également utilisée pour définir l'option de retour -errorcode. Cependant, elle prend une ou plusieurs chaînes à enregistrer au lieu d'une seule valeur. Sinon, son comportement est similaire à celui de Tcl_SetObjErrorCode.

Tcl_SetErrorCodeVA est identique à Tcl_SetErrorCode, sauf qu'au lieu de prendre un nombre variable d'arguments, elle prend une liste d'arguments.

La procédure Tcl_GetErrorLine est utilisée pour lire la valeur entière de l'option de retour -errorline sans la surcharge d'un appel complet à Tcl_GetReturnOptions. De même, Tcl_SetErrorLine définit la valeur de l'option de retour -errorline.

Tcl_PosixError définit la variable -errorcode après une erreur dans un appel noyau POSIX. Elle lit la valeur de la variable C errno et appelle Tcl_SetErrorCode pour définir l'option de retour -errorcode au format POSIX. L'appelant doit avoir précédemment appelé Tcl_SetErrno pour définir errno ; ceci est nécessaire sur certaines plateformes (par exemple, Windows) où Tcl est lié dans une application en tant que bibliothèque partagée, ou lorsque l'erreur se produit dans une extension chargée dynamiquement. Voir la page de manuel de Tcl_SetErrno pour plus d'informations.

Tcl_PosixError retourne un message de diagnostic lisible par l'homme pour l'erreur (c'est la même valeur qui apparaîtra comme troisième élément de la valeur -errorcode). Il peut être pratique d'inclure cette chaîne dans le message d'erreur retourné à l'application dans le résultat de l'interpréteur.

Tcl_LogCommandInfo est appelée après qu'une erreur se produise dans un interpréteur. Elle ajoute des informations sur la commande qui était en cours d'exécution lorsque l'erreur s'est produite à la valeur -errorinfo, et le numéro de ligne stocké en interne dans l'interpréteur est défini.

Dans les anciennes versions de Tcl, il n'existait pas de routine Tcl_GetReturnOptions. À la place, les variables globales Tcl errorInfo et errorCode étaient le seul endroit pour récupérer les informations d'erreur. De nombreux codes existants écrits pour d'anciennes versions de Tcl accèdent encore à ces informations via ces variables globales.

Il est important de comprendre que, bien que la lecture de ces variables globales reste une manière prise en charge d'accéder à ces valeurs d'options de retour, il est important de ne pas supposer que l'écriture dans ces variables globales définira correctement les options de retour correspondantes. Il a longtemps été souligné dans cette page de manuel qu'il est important d'appeler les procédures décrites ici plutôt que de définir errorInfo ou errorCode directement avec Tcl_ObjSetVar2.

Si la procédure Tcl_ResetResult est appelée, elle efface tout l'état de l'interpréteur associé à l'évaluation du script, y compris l'ensemble du dictionnaire des options de retour. En particulier, les options -errorinfo et -errorcode sont réinitialisées. Si une erreur s'était produite, l'appel à Tcl_ResetResult effacera l'état d'erreur pour donner l'impression qu'aucune erreur ne s'est produite après tout. Les variables globales errorInfo et errorCode ne sont pas modifiées par Tcl_ResetResult, elles continuent donc de contenir un enregistrement des informations sur la dernière erreur rencontrée dans un interpréteur.
