ARGUMENTS

Tcl_Interp *interp (en entrée)
Utilisé pour le rapport d'erreurs et pour rechercher un canal enregistré dedans.
const char *fileName (en entrée)
Le nom d'un fichier local ou réseau.
const char *mode (en entrée)
Spécifie comment le fichier doit être accédé. Peut avoir l'une des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (en entrée)
Indicateurs de permission de style POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront appliquées au fichier créé.
int argc (en entrée)
Le nombre d'éléments dans argv.
const char **argv (en entrée)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans option de la commande Tcl exec.
int flags (en entrée)
Spécifie la disposition des descripteurs standard dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, l'entrée standard du premier processus enfant dans le pipe est le canal pipe, sinon elle est la même que l'entrée standard du processus appelant ; idem pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, alors le pipe peut rediriger les descripteurs standard pour outrepasser les descripteurs standard pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, de telles redirections entraînent une erreur.
ClientData handle (en entrée)
Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, il s'agit d'un descripteur de fichier, pour Windows, d'un HANDLE.
int readOrWrite (en entrée)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (en entrée)
Le nom du canal.
int *modePtr (en sortie)
Pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (en entrée)
Le motif à faire correspondre, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (en entrée)
Un canal Tcl pour l'entrée ou la sortie. Doit avoir été la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (en entrée/sortie)
Un pointeur vers une valeur Tcl dans laquelle stocker les caractères lus à partir du canal.
int charsToRead (en entrée)
Le nombre de caractères à lire du canal. Si le codage du canal est binary, cela équivaut au nombre d'octets à lire du canal.
int appendFlag (en entrée)
Si non nul, les données lues du canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (en sortie)
Un tampon dans lequel stocker les octets lus du canal.
int bytesToRead (en entrée)
Le nombre d'octets à lire du canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (en entrée/sortie)
Un pointeur vers une valeur Tcl dans laquelle stocker la ligne lue du canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (en entrée/sortie)
Un pointeur vers une chaîne dynamique Tcl dans laquelle stocker la ligne lue du canal. Doit avoir été initialisé par l'appelant. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne dynamique.
const char *input (en entrée)
L'entrée à ajouter à un tampon de canal.
int inputLen (en entrée)
Longueur de l'entrée
int addAtEnd (en entrée)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon du canal.
Tcl_Obj *writeObjPtr (en entrée)
Un pointeur vers une valeur Tcl dont le contenu sera envoyé en sortie sur le canal.
const char *charBuf (en entrée)
Un tampon contenant les caractères à envoyer en sortie sur le canal.
const char *byteBuf (en entrée)
Un tampon contenant les octets à envoyer en sortie sur le canal.
int bytesToWrite (en entrée)
Le nombre d'octets à consommer de charBuf ou byteBuf et à envoyer sur le canal.
Tcl_WideInt offset (en entrée)
À quelle distance déplacer le point d'accès dans le canal sur lequel la prochaine opération d'entrée ou de sortie sera appliquée, mesuré en octets par rapport à la position donnée par seekMode. Peut être positif ou négatif.
int seekMode (en entrée)
Par rapport à quel point chercher ; utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs légales sont SEEK_SET, SEEK_CUR, et SEEK_END.
Tcl_WideInt length (en entrée)
La longueur (non négative) à laquelle tronquer le canal.
const char *optionName (en entrée)

Tcl_DString *optionValue (en entrée)

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des appareils et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie tamponnées sur une variété de types de fichiers, de sockets et d'appareils. Le mécanisme de canaux est extensible aux nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée de manuel de Tcl_CreateChannel. Le mécanisme de canaux fournit un schéma de tamponnage inspiré des E/S standard Unix, et il permet également les E/S non bloquantes sur les canaux.

Les procédures décrites dans cette entrée de manuel comprennent les API C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canaux et comment implémenter des pilotes de canaux pour de nouveaux types de canaux, voir l'entrée de manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et renvoie un descripteur de canal qui peut être utilisé pour effectuer des entrées et sorties sur le fichier. Cette API est calquée sur la procédure fopen de la bibliothèque d'entrée/sortie standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur la valeur Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel chaque fois que possible.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, la création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Elle crée une séquence de sous-processus spécifiés par les arguments argv et argc et renvoie un canal qui peut être utilisé pour communiquer avec ces sous-processus. L'argument flags indique quel type de communication existera avec le pipeline de commandes.

Si le drapeau TCL_STDIN est défini, l'entrée standard du premier sous-processus sera liée au canal : écrire dans le canal fournira l'entrée au sous-processus. Si TCL_STDIN n'est pas défini, l'entrée standard du premier sous-processus sera la même que celle de cette application. Si TCL_STDOUT est défini, la sortie standard du dernier sous-processus pourra être lue depuis le canal ; sinon, elle sera envoyée à la sortie standard de cette application. Si TCL_STDERR est défini, la sortie d'erreur standard de tous les sous-processus est renvoyée au canal et entraîne une erreur lors de la fermeture du canal ; sinon, elle est envoyée à l'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas défini, alors argc et argv peuvent rediriger les descripteurs stdio pour outrepasser TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, alors il est une erreur que argc et argv outrepassent les canaux stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, la création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un descripteur de fichier existant et spécifique à la plateforme. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, la création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel renvoie un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur Tcl dans interp. Si un canal portant ce nom n'est pas enregistré dans cet interpréteur, la procédure renvoie NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms selon le pattern. Si pattern est NULL, alors aucun filtrage ne sera effectué. La valeur de retour est TCL_OK si aucune erreur ne s'est produite lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur pourront se référer au canal dans les opérations d'entrée ou de sortie en utilisant le nom donné lors de l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur Tcl peut appeler Tcl_RegisterChannel avec interp comme NULL, pour indiquer qu'il souhaite détenir une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et ne sera fermé que lorsque le nombre correspondant d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code exécuté en dehors de tout interpréteur de détenir en toute sécurité une référence à un canal qui est également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code gérant les canaux standards. Si aucun canal standard n'a été initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un traité général sur les canaux standards et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Si cette opération a supprimé le dernier enregistrement du canal dans un interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur Tcl peut appeler Tcl_UnregisterChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. Si c'est la dernière référence au canal, il sera alors fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel sauf qu'il fermera également le canal si aucune autre référence à celui-ci n'existe.

TCL_DETACHCHANNEL

Tcl_DetachChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Au-delà de cela, cette commande n'a aucun autre effet. Elle ne peut pas être utilisée sur les canaux standards (stdout, stderr, stdin), et renverra TCL_ERROR si on lui passe l'un de ces canaux.

Le code non associé à un interpréteur Tcl peut appeler Tcl_DetachChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. Si c'est la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standards, stdin, stdout ou stderr. Si c'est le cas, il renvoie 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standards sont initialisés ou valides autrement.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur quelconque lors de l'appel à Tcl_Close. Les sorties en tampon sont vidées vers le périphérique de sortie du canal avant la destruction du canal, et toute entrée en tampon est rejetée. S'il s'agit d'un canal bloquant, l'appel ne retourne pas tant que toutes les données en tampon n'ont pas été envoyées avec succès au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a des sorties en tampon qui ne peuvent pas être écrites sans bloquer, l'appel retourne immédiatement ; la sortie est vidée en arrière-plan et le canal sera fermé une fois que toutes les données en tampon auront été sorties. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close renvoie TCL_OK. Si une erreur se produit, Tcl_Close renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré en utilisant Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour les détails. Si le canal a déjà été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez plutôt utiliser Tcl_UnregisterChannel, qui appellera Tcl_Close en interne lorsque tous les appels à Tcl_RegisterChannel auront été mis en correspondance par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, convertit les octets en UTF-8 en se basant sur le codage du canal et stocke les données produites dans la représentation chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit pendant la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Définir char

TCL_READCHARS, TCL_READ, ET AL.

Définir sToRead à -1 fera en sorte que la commande lise tous les caractères actuellement disponibles (mode non bloquant) ou tout jusqu'à l'eof (mode bloquant).

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé étaient disponibles. Ceci est appelé une lecture courte. En mode bloquant, cela ne peut se produire qu'à la fin de fichier. En mode non bloquant, une lecture courte peut également se produire s'il n'y a pas assez d'entrée actuellement disponible : Tcl_ReadChars renvoie un compte court plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour savoir laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les différentes représentations de fin de ligne en la représentation interne canonique \n selon le mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les différents modes spécifiques à la plateforme sont décrits dans l'entrée du manuel de la commande Tcl fconfigure.

Par optimisation des performances, lors de la lecture d'un canal avec l'encodage binary, les octets ne sont pas convertis en UTF-8 lors de leur lecture. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr sous forme de tableau d'octets. La représentation en chaîne de cette valeur ne sera construite que si elle est nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette façon, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans avoir à payer le coût de conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'il n'effectue pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Il consomme des octets du channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par un caractère nul. Son contenu est valide à partir de la position zéro jusqu'à, mais sans inclure, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas l'empilement. Alors que Tcl_Read (et les autres fonctions de l'API) obtient toujours ses données du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_ReadRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données du canal inférieur vers la transformation.

TCL_GETSOBJ AND TCL_GETS

Tcl_GetsObj consomme des octets du channel, convertit les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée ait été vue. Si l'encodage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception des caractères de fin de ligne terminaux, sont ajoutés à la représentation en chaîne de lineObjPtr. Les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_GetsObj renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj renvoie également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 s'il n'y avait pas de données disponibles ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est renvoyé, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité de l'entrée.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique donnée par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, à la tête ou à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées à la tête de la file. Si le channel a un EOF "collant" défini, aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets renvoie inputLen ou -1 si une erreur se produit.

TCL_WRITECHARS, TCL_WRITEOBJ, AND TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données caractères à charBuf. Les caractères UTF-8 dans le tampon sont convertis vers l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par un caractère nul et il sort tout jusqu'au caractère nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal à none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un compte du nombre d'octets acceptés pour la sortie vers le canal. Il s'agit soit d'un nombre supérieur à zéro pour indiquer le succès, soit de -1 pour indiquer qu'une erreur s'est produite. Si une erreur se produit, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme selon l'option -translation pour le canal. Ceci est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'il accepte une valeur Tcl dont le contenu sera sorti vers le canal. Les caractères UTF-8 dans la représentation en chaîne de writeObjPtr sont convertis vers l'encodage du canal et mis en file d'attente pour la sortie vers channel. Par optimisation des performances, lors de l'écriture sur un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lorsqu'ils sont écrits. Au lieu de cela, les octets dans la représentation interne de writeObjPtr sous forme de tableau d'octets sont écrits dans le canal. La représentation en tableau d'octets de la valeur sera construite si elle est nécessaire. De cette façon, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans avoir à payer le coût de conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'il n'effectue pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par un caractère nul et il sort tout jusqu'au caractère nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée vers le canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation vers le canal inférieur.

TCL_FLUSH

Tcl_Flush force toutes les données de sortie mises en mémoire tampon pour channel à être écrites dans son fichier ou appareil sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne revient pas tant que toutes les données mises en mémoire tampon n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel revient immédiatement si le canal est non bloquant ; il démarre une mise en mémoire tampon en arrière-plan qui écrira les données mises en mémoire tampon vers le canal éventuellement, aussi rapidement que le canal est capable de les absorber.

La valeur de retour est normalement TCL_OK. Si une erreur se produit, Tcl_Flush renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans le channel où les données ultérieures seront lues ou écrites. La sortie mise en mémoire tampon est vidée vers le canal et l'entrée mise en mémoire tampon est ignorée, avant l'opération de recherche.

Tcl_Seek renvoie normalement le nouveau point d'accès. Si une erreur se produit, Tcl_Seek renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut ou peut ne pas avoir été déplacé.

TCL_TELL

Tcl_Tell renvoie le point d'accès actuel pour un canal. La valeur renvoyée est -1 si le canal ne prend pas en charge la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent du channel à une longueur donnée de length octets. Il renvoie TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, c'est le nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl dénommée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue.

DESCRIPTION

These functions provide a low-level interface for accessing Tcl channels. They are intended for use by channel drivers and other Tcl extensions that need to manipulate channels directly.

TCL_OPENFILECHANNEL

Opens a file named path with the given mode and permissions, and returns a Tcl channel for it. If interp is non-NULL, an error message is left in the interpreter's result if an error occurs. The return value is the new channel or NULL if an error occurred.

The mode string is the same as used by the Tcl open command. The permissions argument is used only if the file is created (e.g. mode is "w" or "a"). It is ignored if the file already exists.

After the channel is created, it is automatically registered with the interpreter.

TCL_OPENCOMMANDCHANNEL

Opens a channel by executing the command specified by cmdargv. The command is expected to create a channel and return its name. If interp is non-NULL, an error message is left in the interpreter's result if an error occurs. The return value is the new channel or NULL if an error occurred.

After the channel is created, it is automatically registered with the interpreter.

TCL_MAKEFILECHANNEL

Creates a Tcl channel from an existing low-level file descriptor or handle, fileHandle. The channel is associated with the given Tcl interpreter, interp. It is the caller's responsibility to ensure that the fileHandle is valid and that it is not closed by other means after this call. If interp is non-NULL, an error message is left in the interpreter's result if an error occurs. The return value is the new channel or NULL if an error occurred.

After the channel is created, it is automatically registered with the interpreter.

TCL_GETCHANNEL

Returns the Tcl channel corresponding to the name given by channelName. If interp is non-NULL, an error message is left in the interpreter's result if the channel doesn't exist or is not accessible. Returns NULL if no such channel exists. Note that the returned channel is a copy of the internal channel structure; modifying it will not affect the original channel.

TCL_REGISTERCHANNEL

Registers a new channel channel with the interpreter interp. The channel is associated with the channel driver described by driverVector. If interp is non-NULL, an error message is left in the interpreter's result if an error occurs. Returns TCL_OK or TCL_ERROR.

TCL_UNREGISTERCHANNEL

Unregisters the channel channel from the interpreter interp. The channel should not be used after this call. If interp is non-NULL, an error message is left in the interpreter's result if an error occurs. Returns TCL_OK or TCL_ERROR.

TCL_DETACHCHANNEL

Detaches the channel channel from the interpreter. The channel structure is returned, but it is no longer associated with the interpreter. The caller is responsible for managing the channel after this call (e.g., closing it). Returns the detached channel structure or NULL if an error occurs.

TCL_ISSTANDARDCHANNEL

Returns true if channel is one of the standard Tcl channels (input, output, or error). Returns false otherwise.

TCL_CLOSE

Closes the channel channel. This flushes any buffered output and releases any associated resources. If interp is non-NULL, an error message is left in the interpreter's result if an error occurs. Returns TCL_OK or TCL_ERROR.

TCL_READCHARS AND TCL_READ

Tcl_ReadChars reads up to numChars characters from the channel into the buffer pointed to by buf. If nonBlocking is true, the call will not block; if data is not available, it returns immediately. If a character-based read is requested (e.g., reading until a newline), it reads that character as well. Returns the number of characters actually read, or -1 if an error occurred. If interp is non-NULL, an error message is left in the interpreter's result.

Tcl_ReadObj reads data from the channel using the channel's registered read procedure. The read procedure is called with the provided readProc and clientData. This is typically used for reading objects.

Tcl_Gets reads a line from the channel, including the terminating newline character, if present. The line is stored in the Tcl object line. Returns the number of characters read, or -1 if an error occurred. If end-of-file is reached before any characters are read, it returns 0.

Tcl_Ungets pushes the string chars back onto the channel's input buffer. Subsequent reads will return these characters first. Returns TCL_OK on success, TCL_ERROR on failure.

TCL_GETSOBJ AND TCL_GETS

Tcl_GetsObj reads a line from the channel, including the terminating newline character, if present. The line is returned as a Tcl object. Returns the new Tcl object, or NULL if an error occurred. If end-of-file is reached before any characters are read, it returns an empty Tcl object.

TCL_UNGETS

Pushes the string chars back onto the channel's input buffer. Subsequent reads will return these characters first. Returns TCL_OK on success, TCL_ERROR on failure.

TCL_WRITECHARS, TCL_WRITEOBJ, AND TCL_WRITE

Tcl_WriteChars writes the characters in chars to the channel. It attempts to write all numChars characters. Returns the number of characters actually written, or -1 if an error occurred. If interp is non-NULL, an error message is left in the interpreter's result.

Tcl_WriteObj writes the contents of the Tcl object objPtr to the channel.

Tcl_Write writes numBytes bytes from the buffer buf to the channel.

TCL_FLUSH

Flushes any buffered output for the channel channel. If interp is non-NULL, an error message is left in the interpreter's result if an error occurs. Returns TCL_OK or TCL_ERROR.

TCL_SEEK

Sets the current position in the channel channel to offset bytes from the beginning (SEEK_SET), current position (SEEK_CUR), or end (SEEK_END>) of the channel. Returns the new offset in bytes from the beginning of the channel, or -1 if an error occurred. If interp is non-NULL, an error message is left in the interpreter's result.

This operation is only supported for seekable channels (e.g., files).

TCL_TELL

Returns the current offset in bytes from the beginning of the channel channel. Returns -1 if an error occurred or if the channel is not seekable. If interp is non-NULL, an error message is left in the interpreter's result.

TCL_TRUNCATECHANNEL

Truncates the channel channel at the specified length. If the current position is greater than length, it is moved to length. Returns TCL_OK on success, TCL_ERROR on failure. If interp is non-NULL, an error message is left in the interpreter's result.

This operation is only supported for seekable channels that are open for writing.

TCL_GETCHANNELOPTION

Gets the value of the channel option optionName for the channel channel and stores it in the Tcl object value. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and, if interp is non-NULL, leaves an error message in the interpreter's result.

The possible option names and values are described in the manual entry for the Tcl fconfigure command. Additional channel-type specific options may also be available.

TCL_SETCHANNELOPTION

Sets the value of the channel option optionName for the channel channel to newValue. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and, if interp is non-NULL, leaves an error message in the interpreter's result.

The possible option names and values are described in the manual entry for the Tcl fconfigure command. Additional channel-type specific options may also be available.

TCL_EOF

Returns a non-zero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Returns a non-zero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
