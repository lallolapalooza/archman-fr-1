ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour le rapport d'erreurs et pour rechercher un canal enregistré en lui.
const char *fileName (in)
Le nom d'un fichier local ou réseau.
const char *mode (in)
Spécifie comment le fichier doit être accédé. Peut avoir toutes les valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (in)
Indicateurs de permission de style POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront appliquées au fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont le même sens que les arguments sans option de la commande Tcl exec.
int flags (in)
Spécifie la disposition des descripteurs standard dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, l'entrée standard du premier enfant dans le pipeline est le canal du pipeline, sinon elle est identique à l'entrée standard du processus appelant ; idem pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, alors le pipeline peut rediriger les descripteurs standard pour outrepasser les descripteurs standard pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, alors de telles redirections provoquent une erreur.
ClientData handle (in)
Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, il s'agit d'un descripteur de fichier, pour Windows, d'un HANDLE.
int readOrWrite (in)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (in)
Le motif à faire correspondre, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl pour l'entrée ou la sortie. Doit avoir été la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker les caractères lus du canal.
int charsToRead (in)
Le nombre de caractères à lire du canal. Si l'encodage du canal est binaire, cela équivaut au nombre d'octets à lire du canal.
int appendFlag (in)
Si différent de zéro, les données lues du canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (out)
Un tampon dans lequel stocker les octets lus du canal.
int bytesToRead (in)
Le nombre d'octets à lire du canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker la ligne lue du canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne dynamique Tcl dans laquelle stocker la ligne lue du canal. Doit avoir été initialisé par l'appelant. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne dynamique.
const char *input (in)
L'entrée à ajouter à un tampon de canal.
int inputLen (in)
Longueur de l'entrée.
int addAtEnd (in)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon de canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera envoyé en sortie vers le canal.
const char *charBuf (in)
Un tampon contenant les caractères à envoyer en sortie vers le canal.
const char *byteBuf (in)
Un tampon contenant les octets à envoyer en sortie vers le canal.
int bytesToWrite (in)
Le nombre d'octets à consommer de charBuf ou byteBuf et à envoyer en sortie vers le canal.
Tcl_WideInt offset (in)
Distance à parcourir dans le canal à partir du point spécifié par seekMode pour déplacer le point d'accès des futures opérations d'entrée ou de sortie. Peut être positif ou négatif.
int seekMode (in)
Point de référence pour le déplacement ; utilisé avec offset pour calculer le nouveau point d'accès du canal. Les valeurs légales sont SEEK_SET, SEEK_CUR, et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) à laquelle tronquer le canal.
const char *optionName (in)
Le nom d'une option applicable à ce canal, telle que -blocking. Peut avoir toutes les valeurs acceptées par la commande fconfigure.
Tcl_DString *optionValue (in)
Où stocker la valeur d'une option ou une liste de toutes les options et leurs valeurs. Doit avoir été initialisé par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des périphériques et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie en tampon sur une variété de types de fichiers, de sockets et de périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée de manuel de Tcl_CreateChannel. Le mécanisme de canaux fournit un schéma de mise en tampon modélisé d'après les E/S standard d'Unix, et il permet également des E/S non bloquantes sur les canaux.

Les procédures décrites dans cette entrée de manuel comprennent les API C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canaux et de la manière d'implémenter des pilotes de canaux pour de nouveaux types de canaux, consultez l'entrée de manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Ouvre un fichier nommé fileName en utilisant le mode spécifié et le retourne sous forme de canal Tcl. Si permissions est non nul, il est utilisé pour définir les permissions du fichier si celui-ci est créé.

Le mode est une chaîne de caractères qui peut avoir n'importe laquelle des valeurs autorisées pour l'argument mode de la commande Tcl open.

Les modes possibles sont :

r
Ouverture en lecture seule.
w
Ouverture en écriture seule. Le fichier est tronqué s'il existe.
a
Ouverture en écriture seule. Tous les écrits sont ajoutés à la fin du fichier.
r+
Ouverture en lecture et écriture. Le fichier doit exister.
w+
Ouverture en lecture et écriture. Le fichier est tronqué s'il existe.
a+
Ouverture en lecture et écriture. Tous les écrits sont ajoutés à la fin du fichier.

Le mode peut aussi inclure un b pour indiquer que le fichier doit être ouvert en mode binaire (par défaut, Tcl suppose le mode texte et tente de gérer les fins de ligne universelles et les encodages).

Si un nouveau fichier est créé, ses permissions sont déterminées par la valeur de permissions combinée avec le umask du processus. Si permissions est 0, alors le masque d'autorisation par défaut du processus est utilisé.

La valeur retournée est un canal Tcl ou NULL si une erreur se produit. Dans ce dernier cas, un message d'erreur est écrit dans interp.

TCL_OPENCOMMANDCHANNEL

Crée un pipeline de commandes en utilisant le système d'exploitation. La commande spécifiée par argv[0] est exécutée, avec les arguments fournis dans argv[1]...argv[argc-1]. Le comportement des descripteurs d'entrée standard (stdin), sortie standard (stdout) et erreur standard (stderr) de la commande enfant est contrôlé par flags.

La valeur retournée est un canal Tcl représentant le pipeline, ou NULL s'il y a une erreur.

TCL_MAKEFILECHANNEL

Crée un canal Tcl à partir d'un descripteur de fichier existant (par exemple, un descripteur retourné par l'appel système `open`). Le descripteur de fichier est spécifié par handle et les opérations autorisées sont indiquées par readOrWrite. Le canal résultant sera géré par Tcl.

Notez que si le canal est fermé, le descripteur de fichier sous-jacent ne sera pas fermé par Tcl. Si vous souhaitez que Tcl ferme le descripteur de fichier lorsque le canal est fermé, vous devez appeler Tcl_RegisterChannel pour que le canal soit géré par l'interpréteur Tcl.

TCL_GETCHANNEL

Retourne le canal Tcl correspondant à channelName. Si modePtr est non nul, il pointe vers un entier qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et/ou en écriture.

La valeur retournée est un canal Tcl ou NULL si aucun canal de ce nom n'existe.

TCL_GETCHANNELNAMES

Ajoute une liste de tous les noms de canaux actuellement enregistrés dans l'interpréteur interp à l'option -result de l'interpréteur. Retourne 0 en cas de succès, ou -1 en cas d'erreur.

La valeur retournée est un canal Tcl ou NULL si aucun canal de ce nom n'existe.

TCL_GETCHANNELNAMESEX

Similaire à Tcl_GetChannelNames, mais ne retourne que les noms de canaux qui correspondent au motif pattern. Le motif est un motif de correspondance de chaînes standard Tcl (voir Tcl_StringMatch). Si pattern est NULL, tous les noms de canaux sont retournés.

TCL_REGISTERCHANNEL

Enregistre le canal channel dans l'interpréteur interp sous le nom associé au canal. Après l'enregistrement, le canal peut être accédé par son nom via des commandes Tcl ou d'autres API de canaux Tcl.

TCL_UNREGISTERCHANNEL

Désenregistre le canal channel de l'interpréteur interp. Le canal ne sera plus accessible par son nom. Si le canal n'est pas déjà fermé, il ne sera pas fermé par cette procédure. Le canal sera désenregistré mais son descripteur sous-jacent restera ouvert.

Retourne 0 en cas de succès, ou -1 en cas d'erreur.

TCL_DETACHCHANNEL

Détache le canal channel de l'interpréteur interp. Cette procédure est appelée lorsque le canal est fermé par l'utilisateur ou par une commande Tcl. Elle désenregistre le canal et libère toutes les ressources associées. Si le canal est du type fichier, son descripteur sous-jacent sera fermé.

Retourne 0 en cas de succès, ou -1 en cas d'erreur.

TCL_ISTANDARDCHANNEL

Retourne vrai (1) si le canal channel est l'un des canaux standard (stdin, stdout, stderr) du processus, faux (0) sinon.

TCL_CLOSE

Ferme le canal channel. Tous les tampons en attente sont vidés avant la fermeture. Si le canal a été créé avec Tcl_CreateChannel, le pilote de canal est responsable de la fermeture du descripteur de fichier sous-jacent.

Retourne 0 en cas de succès, ou -1 en cas d'erreur.

TCL_READCHARS

Lit jusqu'à charsToRead caractères du canal channel et les stocke dans la valeur Tcl pointée par readObjPtr. Si appendFlag est vrai, les caractères lus sont ajoutés à la valeur existante ; sinon, la valeur existante est remplacée. Le canal doit être ouvert en lecture.

Retourne le nombre de caractères réellement lus, ou -1 en cas d'erreur. Si le nombre de caractères lus est inférieur à charsToRead, cela peut signifier que la fin du fichier a été atteinte ou que le canal n'est pas en mode blocage et qu'aucun caractère n'était disponible pour la lecture.

TCL_READ

Lit jusqu'à bytesToRead octets du canal channel et les stocke dans le tampon readBuf. Le canal doit être ouvert en lecture.

Retourne le nombre d'octets réellement lus, ou -1 en cas d'erreur. Si le nombre d'octets lus est inférieur à bytesToRead, cela peut signifier que la fin du fichier a été atteinte ou que le canal n'est pas en mode blocage et qu'aucun octet n'était disponible pour la lecture.

TCL_GETSOBJ

Lit une ligne entière depuis le canal channel, jusqu'au prochain caractère de nouvelle ligne, et stocke le résultat dans la valeur Tcl pointée par lineObjPtr. La nouvelle ligne n'est pas incluse dans le résultat. Le canal doit être ouvert en lecture.

Retourne le nombre de caractères lus, ou -1 en cas d'erreur. Si la fin du fichier est atteinte avant la lecture d'un caractère de nouvelle ligne, la ligne entière est retournée. Si la fin du fichier est atteinte immédiatement, 0 est retourné.

TCL_GETS

Similaire à Tcl_GetsObj, mais stocke la ligne lue dans une chaîne dynamique Tcl pointée par lineRead.

TCL_UNGETS

Ajoute la chaîne input de longueur inputLen au tampon d'entrée du canal channel. Si addAtEnd est vrai, l'entrée est ajoutée à la fin du tampon ; sinon, elle est ajoutée au début. Cette procédure est utile pour réintroduire des données dans un canal après les avoir lues.

Retourne 0 en cas de succès, ou -1 en cas d'erreur.

TCL_WRITEOBJ

Écrit le contenu de la valeur Tcl pointée par writeObjPtr vers le canal channel. Le canal doit être ouvert en écriture.

Retourne le nombre d'octets réellement écrits, ou -1 en cas d'erreur. Si le nombre d'octets écrits est inférieur au nombre total d'octets dans la valeur, cela peut signifier que le canal n'est pas en mode blocage et que le tampon d'écriture est plein.

TCL_WRITECHARS

Écrit au plus bytesToWrite caractères du tampon charBuf vers le canal channel. Le canal doit être ouvert en écriture.

Retourne le nombre d'octets réellement écrits, ou -1 en cas d'erreur. Si le nombre d'octets écrits est inférieur à bytesToWrite, cela peut signifier que le canal n'est pas en mode blocage et que le tampon d'écriture est plein.

TCL_WRITE

Écrit au plus bytesToWrite octets du tampon byteBuf vers le canal channel. Le canal doit être ouvert en écriture.

Retourne le nombre d'octets réellement écrits, ou -1 en cas d'erreur. Si le nombre d'octets écrits est inférieur à bytesToWrite, cela peut signifier que le canal n'est pas en mode blocage et que le tampon d'écriture est plein.

TCL_READRAW

Similaire à Tcl_Read, mais lit les données brutes du canal sans aucune conversion d'encodage ou de fin de ligne.

TCL_WRITERAW

Similaire à Tcl_Write, mais écrit les données brutes vers le canal sans aucune conversion d'encodage ou de fin de ligne.

TCL_EOF

Retourne vrai (1) si la fin du fichier a été atteinte pour le canal channel, faux (0) sinon.

TCL_FLUSH

Force l'écriture de toutes les données en attente dans les tampons de sortie du canal channel vers le périphérique sous-jacent. Retourne 0 en cas de succès, ou -1 en cas d'erreur.

TCL_INPUTBLOCKED

Retourne vrai (1) si une opération de lecture sur le canal channel bloquerait l'exécution (par exemple, si le canal est en mode non bloquant et qu'aucune donnée n'est disponible), faux (0) sinon.

TCL_INPUTBUFFERED

Retourne le nombre d'octets actuellement en attente dans le tampon d'entrée du canal channel.

TCL_OUTPUTBUFFERED

Retourne le nombre d'octets actuellement en attente dans le tampon de sortie du canal channel.

TCL_SEEK

Modifie le point d'accès actuel du canal channel. Le nouveau point d'accès est calculé en ajoutant offset (qui peut être positif ou négatif) au point de référence spécifié par seekMode. Les valeurs légales pour seekMode sont SEEK_SET (début du fichier), SEEK_CUR (position actuelle) et SEEK_END (fin du fichier). La procédure retourne la nouvelle position du point d'accès en octets, ou -1 en cas d'erreur.

Cette opération n'est généralement valide que pour les canaux de type fichier.

TCL_TELL

Retourne la position actuelle du point d'accès dans le canal channel, en octets depuis le début du fichier. Retourne -1 en cas d'erreur.

Cette opération n'est généralement valide que pour les canaux de type fichier.

TCL_TRUNCATECHANNEL

Tronque le canal channel à la longueur spécifiée par length. Si la longueur spécifiée est supérieure à la taille actuelle du canal, le canal est étendu et le contenu ajouté est constitué de zéros. Cette opération n'est généralement valide que pour les canaux de type fichier ouverts en écriture.

Retourne 0 en cas de succès, ou -1 en cas d'erreur.

TCL_GETCHANNELOPTION

Récupère la valeur de l'option optionName pour le canal channel et la stocke dans la chaîne dynamique pointée par optionValue. Les noms d'options sont les mêmes que ceux utilisés avec la commande Tcl fconfigure, tels que -blocking, -buffering, -encoding, etc. La chaîne dynamique optionValue doit avoir été initialisée avant l'appel.

Retourne 0 en cas de succès, ou -1 en cas d'erreur.

TCL_SETCHANNELOPTION

Définit la valeur de l'option optionName pour le canal channel à newValue. Les noms d'options sont les mêmes que ceux utilisés avec la commande Tcl fconfigure. La valeur newValue est une chaîne de caractères.

Retourne 0 en cas de succès, ou -1 en cas d'erreur.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et renvoie un descripteur de canal qui peut être utilisé pour effectuer des entrées et sorties sur le fichier. Cette API est basée sur la procédure fopen de la bibliothèque d'E/S standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat d'interp après toute erreur. Depuis Tcl 8.4, l'API basée sur la valeur Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel chaque fois que possible.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'attribue également comme remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Elle crée une séquence de sous-processus spécifiés par les arguments argv et argc et renvoie un canal qui peut être utilisé pour communiquer avec ces sous-processus. L'argument flags indique quel type de communication existera avec le pipeline de commandes.

Si l'indicateur TCL_STDIN est défini, l'entrée standard du premier sous-processus sera liée au canal : écrire dans le canal fournira des données au sous-processus. Si TCL_STDIN n'est pas défini, l'entrée standard du premier sous-processus sera la même que l'entrée standard de cette application. Si TCL_STDOUT est défini, la sortie standard du dernier sous-processus peut être lue à partir du canal ; sinon, elle va vers la sortie standard de cette application. Si TCL_STDERR est défini, la sortie d'erreur standard de tous les sous-processus est renvoyée au canal et entraîne une erreur lors de la fermeture du canal ; sinon, elle va vers la sortie d'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas défini, alors argc et argv peuvent rediriger les descripteurs stdio pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, alors c'est une erreur pour argc et argv de remplacer les canaux stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'attribue également comme remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un descripteur de fichier existant et spécifique à la plateforme. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'attribue également comme remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel renvoie un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur Tcl dans interp. Si un canal portant ce nom n'est pas enregistré dans cet interpréteur, la procédure renvoie NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms en fonction du pattern. Si pattern est NULL, il n'effectuera aucun filtrage. La valeur de retour est TCL_OK si aucune erreur ne s'est produite lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur peuvent faire référence au canal dans les opérations d'entrée ou de sortie en utilisant le nom donné lors de l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur Tcl peut appeler Tcl_RegisterChannel avec interp comme NULL, pour indiquer qu'il souhaite conserver une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et ne sera fermé que lorsque le nombre correspondant d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code exécuté en dehors de tout interpréteur de conserver en toute sécurité une référence à un canal également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code qui gère les canaux standards. Si aucun canal standard n'a été initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un exposé général sur les canaux standards et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel supprime un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Si cette opération a supprimé la dernière inscription du canal dans un interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur Tcl peut appeler Tcl_UnregisterChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, celui-ci sera maintenant fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel sauf qu'il fermera également le canal si aucune référence supplémentaire n'existe pour celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel supprime un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Au-delà de cela, cette commande n'a aucun autre effet. Elle ne peut pas être utilisée sur les canaux standards (stdout, stderr, stdin), et renverra TCL_ERROR si elle est passée à l'un de ces canaux.

Le code non associé à un interpréteur Tcl peut appeler Tcl_DetachChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standards, stdin, stdout ou stderr. Si c'est le cas, il renvoie 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standards sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lorsque Tcl_Close est appelé. Les sorties en mémoire tampon sont vidées vers le périphérique de sortie du canal avant de détruire le canal, et toute entrée en mémoire tampon est rejetée. S'il s'agit d'un canal bloquant, l'appel ne retourne pas tant que toutes les données en mémoire tampon n'ont pas été envoyées avec succès vers le périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a des sorties en mémoire tampon qui ne peuvent pas être écrites sans bloquer, l'appel retourne immédiatement ; la sortie est vidée en arrière-plan et le canal sera fermé une fois que toutes les données en mémoire tampon auront été sorties. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close renvoie TCL_OK. Si une erreur se produit, Tcl_Close renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré en utilisant Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour les détails. Si le canal a déjà été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez plutôt utiliser Tcl_UnregisterChannel, qui appellera intérieurement Tcl_Close lorsque tous les appels à Tcl_RegisterChannel auront été égalés par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, convertissant les octets en UTF-8 en fonction de l'encodage du canal et stockant les données produites dans la représentation sous forme de chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, convertissant les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée ait été vue. Si l'encodage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception du ou des caractères de fin de ligne, sont ajoutés à la représentation de chaîne de lineObjPtr. Le ou les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_GetsObj renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj renvoie également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est renvoyé, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité des entrées.

Tcl_Gets est identique à Tcl_GetsObj, à l'exception que les caractères résultants sont ajoutés à la chaîne dynamique donnée par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, soit à la tête, soit à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées à la tête de la file. Si channel a un indicateur EOF "collant" (sticky), aucune donnée ne sera ajoutée à la file d'entrée. Tcl_Ungets renvoie inputLen ou -1 si une erreur se produit.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données de caractères à charBuf. Les caractères UTF-8 du tampon sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars attend que charBuf soit terminé par un caractère nul et qu'il envoie tout jusqu'au caractère nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal sur none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un compteur du nombre d'octets qui ont été acceptés pour la sortie vers le canal. Il s'agit soit d'un nombre supérieur à zéro pour indiquer le succès, soit de -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme conformément à l'option -translation du canal. Cela est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars, sauf qu'il accepte une valeur Tcl dont le contenu sera sorti sur le canal. Les caractères UTF-8 de la représentation de chaîne de writeObjPtr sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. À des fins d'optimisation des performances, lors de l'écriture sur un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets de la représentation interne de writeObjPtr en tant que valeur de tableau d'octets sont écrits sur le canal. La représentation de tableau d'octets de la valeur sera construite si elle est nécessaire. De cette manière, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et des fonctions associées, puis écrites sur un canal sans avoir à les convertir depuis ou vers UTF-8.

Tcl_Write est similaire à Tcl_WriteChars, sauf qu'il n'effectue pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour des raisons de compatibilité ascendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write attend que byteBuf soit terminé par un caractère nul et qu'il envoie tout jusqu'au caractère nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas le chaînage. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leurs entrées dans le canal le plus haut de la pile dont le canal fourni fait partie, Tcl_WriteRaw ne le fait pas. Par conséquent, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation vers le canal situé en dessous.

TCL_FLUSH

Tcl_Flush provoque l'écriture de toutes les données de sortie mises en mémoire tampon pour channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données mises en mémoire tampon n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal est non bloquant ; il démarre une opération de vidage en arrière-plan qui écrira les données mises en mémoire tampon sur le canal éventuellement, aussi rapidement que le canal est capable de les absorber.

La valeur de retour est normalement TCL_OK. En cas d'erreur, Tcl_Flush renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données ultérieures seront lues ou écrites. Les sorties mises en mémoire tampon sont vidées dans le canal et les entrées mises en mémoire tampon sont ignorées avant l'opération de recherche.

Tcl_Seek renvoie normalement le nouveau point d'accès. En cas d'erreur, Tcl_Seek renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut avoir été déplacé ou non.

TCL_TELL

Tcl_Tell renvoie le point d'accès actuel pour un canal. La valeur renvoyée est -1 si le canal ne supporte pas la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent de channel à une longueur donnée de length octets. Il renvoie TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et de leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, il s'agit du nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption retrieves the value of an option optionName for a channel channel. If interp is non-NULL, the value is stored in the interpreter's result, which is managed using a series of calls to Tcl_DStringAppendElement. The various preexisting options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and calls Tcl_SetErrno to store an appropriate POSIX error code.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
