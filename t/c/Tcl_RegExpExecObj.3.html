Tcl_RegExpMatch, Tcl_RegExpCompile, Tcl_RegExpExec, Tcl_RegExpRange, Tcl_GetRegExpFromObj, Tcl_RegExpMatchObj, Tcl_RegExpExecObj, Tcl_RegExpGetInfo - Correspondance de motifs avec des expressions régulières

int
Tcl_RegExpMatch(interp, text, pattern)

Tcl_RegExp
Tcl_RegExpCompile(interp, pattern)

int
Tcl_RegExpExec(interp, regexp, text, start)

void
Tcl_RegExpRange(regexp, index, startPtr, endPtr)

Tcl_RegExp
Tcl_GetRegExpFromObj(interp, patObj, cflags)

int
Tcl_RegExpExecObj(interp, regexp, textObj, offset, nmatches, eflags)

void
Tcl_RegExpGetInfo(regexp, infoPtr)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur Tcl à utiliser pour le rapport d'erreurs. L'interpréteur peut être NULL si aucun rapport d'erreur n'est souhaité.
Tcl_Obj *textObj (in/out)
Se réfère à la valeur à partir de laquelle obtenir le texte à rechercher. La représentation interne de la valeur peut être convertie dans un format qui peut être recherché efficacement.
Tcl_Obj *patObj (in/out)
Se réfère à la valeur à partir de laquelle obtenir une expression régulière. L'expression régulière compilée est mise en cache dans la valeur.
const char *text (in)
Texte à rechercher pour une correspondance avec une expression régulière.
const char *pattern (in)
Chaîne sous la forme d'un motif d'expression régulière.
Tcl_RegExp regexp (in)
Expression régulière compilée. Doit avoir été retournée précédemment par Tcl_GetRegExpFromObj ou Tcl_RegExpCompile.
const char *start (in)
Si text n'est qu'une partie d'une autre chaîne, cet argument identifie le début de la chaîne plus grande. S'il n'est pas le même que text, alors aucune correspondance “^” ne sera autorisée.
int index (in)
Spécifie quelle plage est souhaitée : 0 signifie la plage de la correspondance entière, 1 ou plus signifie la plage qui correspondait à une sous-expression entre parenthèses.
const char **startPtr (out)
L'adresse du premier caractère de la plage est stockée ici, ou NULL s'il n'y a pas de telle plage.
const char **endPtr (out)
L'adresse du caractère juste après le dernier caractère de la plage est stockée ici, ou NULL s'il n'y a pas de telle plage.
int cflags (in)
Combinaison par OU de bits des indicateurs de compilation TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, TCL_REG_EXPANDED, TCL_REG_QUOTE, TCL_REG_NOCASE, TCL_REG_NEWLINE, TCL_REG_NLSTOP, TCL_REG_NLANCH, TCL_REG_NOSUB, et TCL_REG_CANMATCH. Voir ci-dessous pour plus d'informations.
int offset (in)
Le décalage de caractères dans le texte où la recherche de correspondance doit commencer. La valeur du décalage n'a aucun impact sur les correspondances ^. Ce comportement est contrôlé par eflags.
int nmatches (in)
Le nombre de sous-expressions correspondantes qui doivent être mémorisées pour une utilisation ultérieure. Si cette valeur est 0, aucune information de correspondance de sous-expression ne sera calculée. Si la valeur est -1, toutes les sous-expressions correspondantes seront mémorisées. Toute autre valeur sera interprétée comme le nombre maximum de sous-expressions à mémoriser.
int eflags (in)
Combinaison par OU de bits des indicateurs d'exécution TCL_REG_NOTBOL et TCL_REG_NOTEOL. Voir ci-dessous pour plus d'informations.
Tcl_RegExpInfo *infoPtr (out)
L'adresse de l'emplacement où les informations sur une correspondance précédente doivent être stockées par Tcl_RegExpGetInfo.

DESCRIPTION

Tcl_RegExpMatch détermine si son argument pattern correspond à regexp, où regexp est interprété comme une expression régulière en utilisant les règles de la page de référence re_syntax. S'il y a une correspondance, Tcl_RegExpMatch retourne 1. S'il n'y a pas de correspondance, Tcl_RegExpMatch retourne 0. Si une erreur se produit pendant le processus de correspondance (par exemple, pattern n'est pas une expression régulière valide), Tcl_RegExpMatch retourne -1 et laisse un message d'erreur dans le résultat de l'interpréteur. Tcl_RegExpMatchObj est similaire à Tcl_RegExpMatch, sauf qu'elle opère sur les valeurs Tcl textObj et patObj au lieu de chaînes UTF. Tcl_RegExpMatchObj est généralement plus efficace que Tcl_RegExpMatch, c'est donc l'interface préférée.

Tcl_RegExpCompile, Tcl_RegExpExec, et Tcl_RegExpRange fournissent un accès de plus bas niveau au moteur de correspondance d'expressions régulières. Tcl_RegExpCompile compile une chaîne d'expression régulière dans la forme interne utilisée pour une correspondance de motif efficace. La valeur de retour est un jeton pour cette forme compilée, qui peut être utilisée dans des appels ultérieurs à Tcl_RegExpExec ou Tcl_RegExpRange. Si une erreur se produit lors de la compilation de l'expression régulière, Tcl_RegExpCompile retourne NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Notez : la valeur de retour de Tcl_RegExpCompile n'est valide que jusqu'au prochain appel à Tcl_RegExpCompile ; il n'est pas sûr de conserver ces valeurs pendant de longues périodes.

Tcl_RegExpExec exécute le moteur de correspondance d'expressions régulières. Il retourne 1 si text contient une plage de caractères qui correspond à regexp, 0 si aucune correspondance n'est trouvée, et -1 si une erreur se produit. En cas d'erreur, Tcl_RegExpExec laisse un message d'erreur dans le résultat de l'interpréteur. Lors de la recherche d'une chaîne pour plusieurs correspondances d'un motif, il est important de distinguer le début de la chaîne d'origine et le début de la recherche actuelle. Par exemple, lors de la recherche de la deuxième occurrence d'une correspondance, l'argument text peut pointer vers le caractère juste après la première correspondance ; cependant, il est important que le moteur de correspondance sache que ce n'est pas le début de toute la chaîne, afin qu'il n'autorise pas les atomes “^” dans le motif à correspondre. L'argument start fournit cette information en pointant vers le début de la chaîne globale contenant text. Start sera inférieur ou égal à text ; s'il est inférieur à text, aucune correspondance ^ ne sera autorisée.

Tcl_RegExpRange peut être appelée après le retour de Tcl_RegExpExec ; elle fournit des informations détaillées sur les plages de la chaîne qui correspondent à quelles parties du motif. Tcl_RegExpRange retourne une paire de pointeurs dans *startPtr et *endPtr qui identifient une plage de caractères dans la chaîne source pour l'appel le plus récent à Tcl_RegExpExec. Index indique quelle parmi plusieurs plages est souhaitée : si index est 0, des informations sont retournées sur la plage globale de caractères qui a correspondu au motif entier ; sinon, des informations sont retournées sur la plage de caractères qui a correspondu à la index-ième sous-expression entre parenthèses dans le motif. S'il n'y a pas de plage correspondant à index, alors NULL est stocké dans *startPtr et *endPtr.

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj, et Tcl_RegExpGetInfo sont des interfaces de valeur qui fournissent le contrôle le plus direct de la bibliothèque d'expressions régulières de Henry Spencer. Pour les utilisateurs qui ont besoin de modifier directement les options de compilation et d'exécution, il est recommandé d'utiliser ces interfaces au lieu d'appeler les fonctions internes d'expressions régulières. Ces interfaces gèrent les détails des traductions UTF vers Unicode ainsi que fournissent des performances améliorées grâce à la mise en cache dans les valeurs de motif et de chaîne.

Tcl_GetRegExpFromObj tente de retourner une expression régulière compilée à partir de patObj. Si la valeur ne contient pas déjà une expression régulière compilée, elle tentera d'en créer une à partir de la chaîne dans la valeur et de l'attribuer à la représentation interne de patObj. La valeur de retour de cette fonction est de type Tcl_RegExp. La valeur de retour est un jeton pour cette forme compilée, qui peut être utilisée dans des appels ultérieurs à Tcl_RegExpExecObj ou Tcl_RegExpGetInfo. Si une erreur se produit lors de la compilation de l'expression régulière, Tcl_GetRegExpFromObj retourne NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Le jeton d'expression régulière peut être utilisé tant que la représentation interne de patObj fait référence à la forme compilée. L'argument cflags est un OU de bits de zéro ou plusieurs des indicateurs suivants qui contrôlent la compilation de patObj :

TCL_REG_ADVANCED
Utilise le moteur d'expressions régulières avancé de Henry Spencer.
TCL_REG_EXTENDED
Interprète le motif en utilisant la syntaxe des expressions régulières étendues POSIX.
TCL_REG_BASIC
Interprète le motif en utilisant la syntaxe des expressions régulières de base POSIX.
TCL_REG_EXPANDED
Le motif est écrit en lignes, avec des espaces blancs ignorés et des commentaires commençant par “#”. Les espaces blancs et les commentaires peuvent être inclus dans le motif en les échappant avec une barre oblique inverse ou en les plaçant dans une classe de caractères.
TCL_REG_QUOTE
Toutes les métacaractères dans le motif sont traités comme des caractères littéraux. Cela est utile si vous voulez faire correspondre une chaîne qui pourrait contenir des métacaractères d'expressions régulières sans qu'ils soient interprétés.
TCL_REG_NOCASE
La correspondance ne tient pas compte de la casse des lettres.
TCL_REG_NEWLINE
Le caractère de nouvelle ligne sera traité comme un caractère d'espace blanc normal par “.” et “[^…]”. Autrement, “.” ne correspondra pas aux nouvelles lignes.
TCL_REG_NLSTOP
Les caractères de nouvelle ligne arrêtent les correspondances pour les ancres “\b”, “\B”, “\w”, et “\W”.
TCL_REG_NLANCH
Les caractères de nouvelle ligne sont traités comme des ancres de début/fin de ligne. Autrement, seul le début/la fin de la chaîne entière sont considérés comme des ancres.
TCL_REG_NOSUB
Les informations sur les sous-expressions correspondantes ne sont pas calculées. Ceci peut être utilisé pour accélérer la recherche lorsque ces informations ne sont pas nécessaires.
TCL_REG_CANMATCH
Indique que la fonction Tcl_RegExpExecObj doit retourner 1 si le motif peut correspondre *n'importe où* dans la chaîne, et non seulement au début de la chaîne. Cela est utile pour vérifier si une chaîne est susceptible de correspondre à un motif, sans avoir à spécifier de décalage.

Tcl_RegExpExecObj exécute une expression régulière compilée, regexp, sur la chaîne représentée par textObj. La recherche commence au caractère décalé de offset dans la chaîne. L'argument nmatches spécifie le nombre maximal de sous-expressions qui doivent être conservées ; s'il est égal à 0, aucune information sur les sous-expressions n'est calculée ; s'il est égal à -1, toutes les sous-expressions sont conservées. Les indicateurs eflags contrôlent le comportement des ancres de début et de fin de ligne :

TCL_REG_NOTBOL
Empêche l'ancre “^” de correspondre au début de la chaîne.
TCL_REG_NOTEOL
Empêche l'ancre “$” de correspondre à la fin de la chaîne.

Tcl_RegExpExecObj retourne 1 si une correspondance est trouvée, 0 sinon, et -1 en cas d'erreur. L'information sur la correspondance est stockée dans l'objet regexp (si regexp a été obtenu via Tcl_GetRegExpFromObj) ou peut être récupérée via Tcl_RegExpGetInfo.

Tcl_RegExpGetInfo remplit la structure Tcl_RegExpInfo pointée par infoPtr avec des informations sur la dernière correspondance effectuée par Tcl_RegExpExecObj. La structure Tcl_RegExpInfo a la forme suivante :

typedef struct Tcl_RegExpInfo {
    int nmatches;
    int *starts;
    int *lengths;
} Tcl_RegExpInfo;

nmatches sera le nombre de sous-expressions correspondantes (y compris la correspondance globale). starts sera un tableau de pointeurs vers le début de chaque partie correspondante de la chaîne. lengths sera un tableau de longueurs de chaque partie correspondante. La mémoire pour ces tableaux est allouée par le système d'expressions régulières et doit être libérée par l'appelant en utilisant Tcl_Free.

Les fonctions de bas niveau retournent des pointeurs dans la chaîne d'entrée originale. Les fonctions orientées objet retournent des décalages et des longueurs sous forme d'entiers. Les décalages sont toujours des décalages en octets dans la représentation UTF-8 de la chaîne. Les longueurs sont également en octets.

Tcl_RegExpCompile et Tcl_RegExpExec sont les fonctions plus anciennes et moins flexibles. Il est recommandé d'utiliser Tcl_GetRegExpFromObj et Tcl_RegExpExecObj à la place, car elles gèrent mieux les chaînes Unicode et offrent des fonctionnalités supplémentaires.

UTILISATION ET EFFETS DE BORD

Les expressions régulières sont très puissantes mais peuvent aussi être lentes. Le moteur d'expressions régulières Tcl est relativement rapide, mais des motifs mal conçus peuvent entraîner des performances très médiocres.

La compilation d'une expression régulière peut prendre du temps. Si vous utilisez le même motif à plusieurs reprises, compilez-le une fois et réutilisez le résultat. Les fonctions orientées objet (Tcl_GetRegExpFromObj, Tcl_RegExpExecObj) mettent en cache les expressions régulières compilées dans les objets Tcl, ce qui permet de les réutiliser automatiquement.

Les fonctions de correspondance d'expressions régulières peuvent allouer de la mémoire. Si vous utilisez beaucoup d'expressions régulières, assurez-vous de libérer la mémoire inutilisée pour éviter les fuites de mémoire.

Les options TCL_REG_NEWLINE, TCL_REG_NLSTOP et TCL_REG_NLANCH affectent la façon dont les caractères de nouvelle ligne sont traités. Comprendre ces options est crucial pour une correspondance correcte sur plusieurs lignes.

EXEMPLES

Correspondance simple :

int result = Tcl_RegExpMatch(interp, "Hello world", "world"); // result sera 1
result = Tcl_RegExpMatch(interp, "Hello world", "planet");  // result sera 0

Compilation et exécution :

Tcl_RegExp regexp = Tcl_RegExpCompile(interp, "[0-9]+");
if (regexp) {
    int result = Tcl_RegExpExec(interp, regexp, "There are 123 apples", NULL);
    // result sera 1
    Tcl_RegExpFree(regexp); // Assurez-vous de libérer la mémoire
}

Utilisation des objets Tcl :

Tcl_Obj *textObj = Tcl_NewStringObj("The quick brown fox", -1);
Tcl_Obj *patObj = Tcl_NewStringObj("quick.*fox", -1);
Tcl_GetObjInternalRep(patObj, TCL_RE_OBJ_TYPE); // Pour activer la mise en cache

int result = Tcl_RegExpMatchObj(interp, textObj, patObj); // result sera 1

Obtention des plages correspondantes :

Tcl_RegExp regexp = Tcl_RegExpCompile(interp, "(quick) (brown) (fox)");
if (regexp) {
    Tcl_RegExpExecObj(interp, regexp, "The quick brown fox", 0, -1, 0);
    
    const char *startPtr, *endPtr;
    Tcl_RegExpRange(regexp, 0, &startPtr, &endPtr); // Correspondance globale
    // startPtr pointe vers 'q' de "quick", endPtr pointe juste après 'x' de "fox"

    Tcl_RegExpRange(regexp, 1, &startPtr, &endPtr); // Première sous-expression
    // startPtr pointe vers 'q' de "quick", endPtr pointe juste après 'k' de "quick"

    Tcl_RegExpRange(regexp, 2, &startPtr, &endPtr); // Deuxième sous-expression
    // startPtr pointe vers 'b' de "brown", endPtr pointe juste après 'n' de "brown"

    Tcl_RegExpFree(regexp);
}

NOM

Tcl_RegExpExecObj, Tcl_RegExpCompileObj, Tcl_RegExpGetInfo, Tcl_RegExpIndices, Tcl_RegExpInfo - chercher des sous-chaînes dans une chaîne en utilisant une expression régulière

SYNTAXE

#include <tcl.h>

int
Tcl_RegExpCompileObj(interp, objPtr, errCodePtr)
Tcl_Interp *interp;
Tcl_Obj *objPtr;
int *errCodePtr;
char **errorMsg;

int
Tcl_RegExpExecObj(interp, regexpObjPtr, stringObjPtr, nmatches, offset, eflags)
Tcl_Interp *interp;
Tcl_Obj *regexpObjPtr;
Tcl_Obj *stringObjPtr;
int nmatches;
int offset;
int eflags;

void
Tcl_RegExpGetInfo(regexpObjPtr, infoPtr)
Tcl_Obj *regexpObjPtr;
Tcl_RegExpInfo *infoPtr;

ARGUMENTS

Toutes les fonctions ci-dessus traitent les expressions régulières compilées comme des objets Tcl, ce qui permet de les stocker dans des variables et de les passer à plusieurs commandes. Notez que les objets expr réguliers ne peuvent pas être modifiés après leur création, et doivent donc être compilés à l'aide de Tcl_RegExpCompileObj avant d'être utilisés avec Tcl_RegExpExecObj.

interp (Tcl_Interp *)
Interpréteur Tcl à utiliser pour le traitement des erreurs.
objPtr (Tcl_Obj *)
Pointeur vers l'objet à compiler ou à exécuter.
errCodePtr (int *)
Pointeur vers un entier pour stocker le code d'erreur.
errorMsg (char **)
Pointeur vers une chaîne pour stocker le message d'erreur.
regexpObjPtr (Tcl_Obj *)
Pointeur vers un objet représentant l'expression régulière compilée.
stringObjPtr (Tcl_Obj *)
Pointeur vers l'objet représentant la chaîne dans laquelle chercher.
nmatches (int)
Le nombre de sous-expressions à enregistrer.
offset (int)
L'index de caractère Unicode où commencer la recherche.
eflags (int)
Un OR bit à bit des drapeaux spécifiant le comportement de la recherche.
infoPtr (Tcl_RegExpInfo *)
Pointeur vers une structure pour stocker les informations sur la correspondance.

DESCRIPTION

Ces fonctions fournissent une interface de bas niveau pour la recherche d'expressions régulières dans Tcl. Elles permettent une plus grande flexibilité et des optimisations potentielles par rapport à l'utilisation des commandes regexp et regsub de Tcl.

Tcl_RegExpCompileObj compile l'objet objPtr en une forme compilée utilisable par les autres fonctions. Les drapeaux suivants peuvent être utilisés pour modifier le comportement de la compilation :

TCL_REG_ADVANCED
Compile des expressions régulières avancées (« ARE »). Ce mode correspond à la syntaxe normale des expressions régulières acceptée par les commandes Tcl regexp et regsub.
TCL_REG_EXTENDED
Compile des expressions régulières étendues (« ERE »). Ce mode correspond à la syntaxe des expressions régulières reconnue par Tcl 8.0 et les versions antérieures.
TCL_REG_BASIC
Compile des expressions régulières de base (« BRE »). Ce mode correspond à la syntaxe des expressions régulières reconnue par les utilitaires Unix courants comme sed et grep. C'est le mode par défaut si aucun drapeau n'est spécifié.
TCL_REG_EXPANDED
Compile l'expression régulière (de base, étendue ou avancée) en utilisant une syntaxe étendue qui autorise les commentaires et les espaces blancs. Ce mode fait que les espaces blancs non échappés et non contenus dans des expressions entre crochets, ainsi que les commentaires de type # jusqu'à la fin de la ligne, sont ignorés.
TCL_REG_QUOTE
Compile une chaîne littérale, tous les caractères étant traités comme des caractères ordinaires.
TCL_REG_NOCASE
Compile pour une correspondance qui ignore les distinctions majuscules/minuscules.
TCL_REG_NEWLINE
Compile pour une correspondance sensible aux sauts de ligne. Par défaut, le saut de ligne est un caractère complètement ordinaire sans signification spéciale dans les expressions régulières ou les chaînes. Avec ce drapeau, les expressions entre crochets ([^]) et le caractère « . » ne correspondent jamais au saut de ligne, « ^ » correspond à une chaîne vide après n'importe quel saut de ligne en plus de sa fonction normale, et « $ » correspond à une chaîne vide avant n'importe quel saut de ligne en plus de sa fonction normale. REG_NEWLINE est l'OR bit à bit de REG_NLSTOP et REG_NLANCH.
TCL_REG_NLSTOP
Compile pour une correspondance partielle sensible aux sauts de ligne, le comportement des expressions entre crochets ([^]) et du caractère « . » étant affecté, mais pas le comportement de « ^ » et « $ ». Dans ce mode, les expressions entre crochets ([^]) et le caractère « . » ne correspondent jamais au saut de ligne.
TCL_REG_NLANCH
Compile pour une correspondance inverse partielle sensible aux sauts de ligne, le comportement de « ^ » et « $ » (les « ancres ») étant affecté, mais pas le comportement des expressions entre crochets ([^]) et du caractère « . ». Dans ce mode, « ^ » correspond à une chaîne vide après n'importe quel saut de ligne en plus de sa fonction normale, et « $ » correspond à une chaîne vide avant n'importe quel saut de ligne en plus de sa fonction normale.
TCL_REG_NOSUB
Compile pour une correspondance qui ne signale que le succès ou l'échec, pas ce qui a été trouvé. Cela réduit les frais de compilation et peut améliorer les performances. Les appels ultérieurs à Tcl_RegExpGetInfo ou Tcl_RegExpRange ne signaleront aucune information de correspondance.
TCL_REG_CANMATCH
Compile pour une correspondance qui signale la possibilité de compléter une correspondance partielle étant donné plus de texte (voir ci-dessous).

Un seul des drapeaux TCL_REG_EXTENDED, TCL_REG_ADVANCED, TCL_REG_BASIC et TCL_REG_QUOTE peut être spécifié.

Tcl_RegExpExecObj exécute le moteur de correspondance d'expressions régulières. Il renvoie 1 si objPtr contient une plage de caractères qui correspond à regexp, 0 si aucune correspondance n'est trouvée, et -1 si une erreur se produit. En cas d'erreur, Tcl_RegExpExecObj laisse un message d'erreur dans le résultat de l'interpréteur. La valeur nmatches indique au moteur de correspondance combien de sous-expressions sont d'intérêt. Si nmatches est 0, alors aucune information de correspondance de sous-expression n'est enregistrée, ce qui peut permettre au moteur d'effectuer diverses optimisations. Si la valeur est -1, alors toutes les sous-expressions du motif sont conservées. Si la valeur est un entier positif, alors seul ce nombre de sous-expressions sera conservé. La recherche commence à l'index de caractère Unicode spécifié par offset. Contrairement à Tcl_RegExpExec, le comportement des ancres n'est pas affecté par la valeur de l'offset. Au lieu de cela, le comportement des ancres est explicitement contrôlé par l'argument eflags, qui est un OR bit à bit de zéro ou plusieurs des drapeaux suivants :

TCL_REG_NOTBOL
Le caractère de départ ne sera pas traité comme le début d'une ligne ou le début de la chaîne, donc « ^ » ne correspondra pas là. Notez que ce drapeau n'a aucun effet sur la façon dont « \A » correspond.
TCL_REG_NOTEOL
Le dernier caractère de la chaîne ne sera pas traité comme la fin d'une ligne ou la fin de la chaîne, donc « $ » ne correspondra pas là. Notez que ce drapeau n'a aucun effet sur la façon dont « \Z » correspond.

Tcl_RegExpGetInfo récupère les informations sur la dernière correspondance effectuée avec une expression régulière regexp donnée. L'argument infoPtr contient un pointeur vers une structure définie comme suit :

typedef struct Tcl_RegExpInfo {
    int nsubs;
    Tcl_RegExpIndices *matches;
    long extendStart;
} Tcl_RegExpInfo;

Le champ nsubs contient un décompte du nombre de sous-expressions entre parenthèses dans l'expression régulière. Si TCL_REG_NOSUB a été utilisé, cette valeur sera zéro. Le champ matches pointe vers un tableau de nsubs+1 valeurs qui indiquent les bornes de chaque sous-expression trouvée. Le premier élément du tableau fait référence à la plage correspondant à l'expression régulière entière, et les éléments suivants font référence aux sous-expressions entre parenthèses dans l'ordre où elles apparaissent dans le motif. Chaque élément est une structure définie comme suit :

typedef struct Tcl_RegExpIndices {
    long start;
    long end;
} Tcl_RegExpIndices;

Les valeurs start et end sont des indices de caractères Unicode relatifs à l'emplacement de l'offset dans objPtr où la recherche a commencé. L'indice start identifie le premier caractère de la sous-expression correspondante. L'indice end identifie le premier caractère après la sous-expression correspondante. Si la sous-expression a correspondu à une chaîne vide, alors start et end seront égaux. Si la sous-expression n'a pas participé à la correspondance, alors start et end seront définis à -1.

Le champ extendStart dans Tcl_RegExpInfo n'est défini que si le drapeau TCL_REG_CANMATCH a été utilisé. Il indique le premier caractère de la chaîne où une correspondance pourrait se produire. Si une correspondance a été trouvée, ce sera le même que le début de la correspondance actuelle. Si aucune correspondance n'a été trouvée, il indique le point le plus précoce où une correspondance pourrait se produire si du texte supplémentaire était ajouté à la chaîne. S'il est impossible de trouver une correspondance, même avec du texte supplémentaire, ce champ sera défini à -1.
