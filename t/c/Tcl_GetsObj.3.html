ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour le rapport d'erreurs et pour rechercher un canal enregistré dans celui-ci.
const char *fileName (in)
Le nom d'un fichier local ou réseau.
const char *mode (in)
Indique comment le fichier est accédé. Peut avoir n'importe quelle valeur autorisée pour l'argument mode de la commande open de Tcl.
int permissions (in)
Flags de permissions POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront définies sur le fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour construire un pipeline de commandes. Ces valeurs ont la même signification que les arguments non -- dans la commande exec de Tcl.
int flags (in)
Indique la disposition des canaux standards dans le pipeline: combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, le stdin du premier enfant dans le pipeline est le canal de pipeline, sinon il est le même que le stdin du processus appelant; de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, le pipeline peut rediriger les canaux standards pour outrepasser les canaux standards qui ont TCL_STDIN, TCL_STDOUT et TCL_STDERR définis. S'il est défini, alors les redirections provoquent une erreur.
ClientData handle (in)
Le handle opérationnel spécifique pour les E/S vers un fichier. Pour Unix, c'est un descripteur de fichier, pour Windows c'est un HANDLE.
int readOrWrite (in)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (in)
Le motif à rechercher, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl d'entrée ou de sortie. Il doit avoir été la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle seront stockés les caractères lus du canal.
int charsToRead (in)
Le nombre de caractères à lire du canal. Si le codage du canal est binary, cela équivaut au nombre d'octets à lire du canal.
int appendFlag (in)
Si non nul, les données lues du canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (out)
Un tampon dans lequel seront stockés les octets lus du canal.
int bytesToRead (in)
Le nombre d'octets à lire du canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle sera stockée la ligne lue du canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne dynamique dans laquelle sera stockée la ligne lue du canal. Elle doit avoir été initialisée par l'appelant. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne dynamique.
const char *input (in)
L'entrée à ajouter à un tampon de canal.
int inputLen (in)
Longueur de l'entrée.
int addAtEnd (in)
Flag indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon du canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera écrit dans le canal.
const char *charBuf (in)
Un tampon contenant les caractères à écrire dans le canal.
const char *byteBuf (in)
Un tampon contenant les octets à écrire dans le canal.
int bytesToWrite (in)
Le nombre d'octets à consommer de charBuf ou byteBuf et à écrire dans le canal.
Tcl_WideInt offset (in)
De combien le point d'accès dans le canal sera déplacé lors de la prochaine opération d'entrée ou de sortie, mesuré en octets à partir du point donné par seekMode. Peut être positif ou négatif.
int seekMode (in)
Par rapport à quel point effectuer la recherche; utilisé avec offset pour calculer le nouveau point d'accès du canal. Les valeurs légales sont SEEK_SET, SEEK_CUR et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) à laquelle le canal sera tronqué.
const char *optionName (in)
Le nom d'une option applicable à ce canal, comme -blocking. Peut avoir toute valeur acceptée par la commande fconfigure.
Tcl_DString *optionValue (in)
Où la valeur d'une option ou une liste de toutes les options et leurs valeurs sera stockée. Doit avoir été initialisé par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canal de Tcl fournit un mécanisme indépendant du périphérique et de la plateforme pour effectuer des opérations d'entrée et de sortie bufferisées sur un certain nombre de types de fichiers, de sockets et de périphériques. Le mécanisme de canal est extensible à de nouveaux types de canaux en fournissant un pilote de canal de bas niveau pour le nouveau type; l'interface du pilote de canal est décrite dans la page de manuel de Tcl_CreateChannel. Le mécanisme de canal fournit un schéma de bufferisation calqué sur les E/S standard d'Unix, et permet également les E/S non bloquantes sur les canaux.

Les procédures décrites dans ce manuel correspondent aux API du niveau général de l'architecture de canal. Pour une description de l'architecture du pilote de canal et comment implémenter des pilotes de canal pour de nouveaux types de canaux, consultez la page de manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

La procédure Tcl_OpenFileChannel ouvre un fichier nommé par fileName et retourne un handle de canal Tcl qui peut être utilisé pour lire et/ou écrire dans le fichier. Le mode d'accès au fichier est spécifié par mode, qui a la même sémantique que l'argument mode pour la commande open de Tcl. Les valeurs typiques pour mode sont "r" (lecture), "w" (écriture, tronquant le fichier s'il existe), "a" (ajout à la fin), "rb" (lecture binaire), "wb" (écriture binaire, tronquant le fichier s'il existe), "ab" (ajout binaire à la fin), etc. Les permissions spécifient les permissions POSIX à utiliser si le fichier est créé. Les valeurs typiques sont 0644 pour les fichiers réguliers. La procédure retourne un handle de canal Tcl, ou NULL si une erreur survient. Dans ce dernier cas, un message d'erreur est stocké dans la variable d'interprétation interp.

TCL_OPENCOMMANDCHANNEL

La procédure Tcl_OpenCommandChannel est similaire à la commande exec de Tcl. Elle crée un pipeline de processus. argv contient les arguments de commande pour chaque processus du pipeline, et argc est le nombre d'arguments. La procédure crée un pipeline de processus en utilisant les commandes spécifiées dans argv. Les canaux standards (stdin, stdout, stderr) de ces processus sont connectés pour former un pipeline. Les canaux standards du processus de premier plan sont retournés par la procédure. Le flag flags contrôle comment les canaux standards du processus appelant sont connectés au pipeline. Par défaut, le stdin du premier processus est le stdin du processus appelant, et le stdout et le stderr du dernier processus sont le stdout et le stderr du processus appelant, respectivement. Si TCL_STDIN est spécifié, le stdin du premier processus est remplacé par le stdin du processus appelant. De même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE est défini, toute tentative de redirection des canaux standards spécifiés dans flags provoquera une erreur.

TCL_MAKEFILECHANNEL

La procédure Tcl_MakeFileChannel prend un handle opérationnel existant et le transforme en un canal Tcl. Cela est utile pour intégrer des canaux de fichiers existants (par exemple, ceux ouverts par l'appel système open) dans le système de canaux Tcl. handle est le handle opérationnel (un descripteur de fichier sous Unix, un HANDLE sous Windows). readOrWrite est une combinaison OR des flags TCL_READABLE et TCL_WRITABLE indiquant si le handle peut être lu et/ou écrit. La procédure retourne un nouveau handle de canal Tcl, ou NULL en cas d'erreur.

TCL_GETCHANNEL

La procédure Tcl_GetChannel recherche un canal nommé par channelName dans l'interprète interp. Si modePtr n'est pas NULL, il pointe vers une variable entière qui sera définie pour indiquer si le canal est ouvert pour lecture (TCL_READABLE) et/ou écriture (TCL_WRITABLE). La procédure retourne un pointeur vers le canal Tcl, ou NULL si le canal n'est pas trouvé ou si une erreur survient.

TCL_GETCHANNELNAMES

La procédure Tcl_GetChannelNames retourne une liste de tous les noms de canaux actuellement enregistrés dans l'interprète interp. La liste est retournée sous forme d'une valeur Tcl (généralement un objet de type liste) stockée dans la variable interp->result. La procédure retourne une valeur entière indiquant le succès (0) ou l'échec (un code d'erreur Tcl).

TCL_GETCHANNELNAMESEX

Similaire à Tcl_GetChannelNames, mais Tcl_GetChannelNamesEx ne retourne que les noms de canaux qui correspondent au pattern spécifié. Le motif est évalué en utilisant la sémantique de Tcl_StringMatch. Si pattern est NULL, elle se comporte comme Tcl_GetChannelNames.

TCL_REGISTERCHANNEL

La procédure Tcl_RegisterChannel enregistre un canal Tcl channel dans l'interprète interp. Une fois enregistré, le canal peut être référencé par son nom dans les commandes Tcl.

TCL_UNREGISTERCHANNEL

La procédure Tcl_UnregisterChannel désenregistre le canal channel de l'interprète interp. Cela empêche le canal d'être référencé par son nom dans les commandes Tcl. Le canal lui-même est toujours valide et peut être utilisé tant qu'il n'est pas explicitement fermé.

TCL_DETACHCHANNEL

La procédure Tcl_DetachChannel détache le canal channel de l'interprète interp. Cela signifie que le canal n'est plus géré par le système de canaux Tcl, mais le descripteur de fichier sous-jacent reste ouvert. Ceci est utile lorsque vous souhaitez utiliser le descripteur de fichier brut en dehors de Tcl, par exemple pour le passer à un autre processus via fork/exec. La procédure retourne une valeur entière: 0 en cas de succès, et un code d'erreur Tcl en cas d'échec.

TCL_ISSTANDARDCHANNEL

La procédure Tcl_IsStandardChannel retourne une valeur non nulle si channel est l'un des canaux standards (stdin, stdout, stderr) de l'interprète Tcl, et zéro sinon.

TCL_CLOSE

La procédure Tcl_Close ferme le canal channel. Toutes les opérations d'entrée ou de sortie sur le canal sont terminées. Si le canal était ouvert en écriture, tous les tampons d'écriture sont vidés avant la fermeture. La procédure retourne 0 en cas de succès, et une valeur d'erreur Tcl en cas d'échec.

TCL_READCHARS

La procédure Tcl_ReadChars lit jusqu'à charsToRead caractères du canal channel et les stocke dans l'objet Tcl pointé par readObjPtr. Si appendFlag est non nul, les caractères lus sont ajoutés à la fin du contenu existant de l'objet; sinon, l'objet est réinitialisé avant d'y ajouter les caractères lus. Si le canal est configuré en mode blocage et que le nombre de caractères demandé n'est pas disponible, la procédure bloquera jusqu'à ce que le nombre spécifié de caractères soit disponible ou que la fin du fichier soit atteinte. La procédure retourne le nombre de caractères réellement lus, ou -1 en cas d'erreur. Si le canal est configuré en mode non bloquant et que les caractères demandés ne sont pas disponibles immédiatement, elle retourne 0.

TCL_READ

La procédure Tcl_Read lit jusqu'à bytesToRead octets du canal channel et les place dans le tampon readBuf. Le tampon readBuf doit être suffisamment grand pour contenir bytesToRead octets. La procédure retourne le nombre d'octets réellement lus, ou -1 en cas d'erreur. Si le canal est configuré en mode non bloquant et que les octets demandés ne sont pas disponibles immédiatement, elle retourne 0.

TCL_GETSOBJ

La procédure Tcl_GetsObj lit une ligne complète du canal channel (jusqu'au prochain caractère de nouvelle ligne) et la stocke dans l'objet Tcl pointé par lineObjPtr. Si la fin du fichier est atteinte avant qu'un caractère de nouvelle ligne ne soit rencontré, la ligne restante est retournée. Le caractère de nouvelle ligne est consommé mais n'est pas inclus dans la valeur retournée. Si le canal est configuré en mode blocage et qu'une ligne complète n'est pas disponible, la procédure bloquera jusqu'à ce qu'une ligne soit disponible ou que la fin du fichier soit atteinte. La procédure retourne le nombre d'octets lus, ou -1 en cas d'erreur. Si le canal est configuré en mode non bloquant et qu'une ligne n'est pas disponible immédiatement, elle retourne 0.

TCL_GETS

Similaire à Tcl_GetsObj, mais lit la ligne dans un tampon de chaîne dynamique lineRead. La procédure retourne le nombre d'octets lus, ou -1 en cas d'erreur.

TCL_UNGETS

La procédure Tcl_Ungets préfixe une chaîne input de longueur inputLen au buffer d'entrée du canal channel. Si addAtEnd est non nul, l'entrée est ajoutée à la fin du buffer existant; sinon, elle est ajoutée au début. Ceci est utile pour implémenter des analyseurs qui ont besoin de réinsérer des données dans le flux d'entrée.

TCL_WRITEOBJ

La procédure Tcl_WriteObj écrit le contenu de l'objet Tcl pointé par writeObjPtr dans le canal channel. Si le canal est configuré en mode blocage et que le tampon de sortie est plein, la procédure bloquera jusqu'à ce que tout le contenu soit écrit. La procédure retourne le nombre d'octets réellement écrits, ou -1 en cas d'erreur. Si le canal est configuré en mode non bloquant et que le tampon de sortie est plein, elle retourne 0.

TCL_WRITECHARS

La procédure Tcl_WriteChars écrit les caractères du tampon charBuf dans le canal channel. Elle essaie d'écrire bytesToWrite caractères. La sémantique est similaire à Tcl_WriteObj, mais utilise un tampon de caractères C au lieu d'un objet Tcl.

TCL_WRITE

Similaire à Tcl_WriteChars, mais opère sur des octets bruts dans byteBuf.

TCL_READRAW

La procédure Tcl_ReadRaw lit jusqu'à bytesToRead octets du canal channel et les place dans le tampon readBuf. Cette procédure est similaire à Tcl_Read, mais elle ne fait aucune conversion de fin de ligne ou de jeu de caractères; elle lit les octets exactement tels qu'ils sont dans le canal.

TCL_WRITERAW

La procédure Tcl_WriteRaw écrit les octets du tampon byteBuf dans le canal channel. Elle essaie d'écrire bytesToWrite octets. Cette procédure est similaire à Tcl_Write, mais elle n'effectue aucune conversion; elle écrit les octets exactement tels qu'ils sont dans le tampon.

TCL_EOF

La procédure Tcl_Eof retourne une valeur non nulle si la fin du fichier a été atteinte sur le canal channel, et zéro sinon. Elle ne consomme pas de données.

TCL_FLUSH

La procédure Tcl_Flush force l'écriture de toutes les données tamponnées en sortie du canal channel. Ceci est utile pour s'assurer que les données sont envoyées immédiatement, par exemple, avant d'attendre une réponse d'un processus distant.

TCL_INPUTBLOCKED

La procédure Tcl_InputBlocked retourne une valeur non nulle si le canal channel est en mode blocage et qu'une opération de lecture sur ce canal bloquerait, et zéro sinon. Ceci est utile pour vérifier si une lecture peut être effectuée sans bloquer.

TCL_INPUTBUFFERED

La procédure Tcl_InputBuffered retourne le nombre d'octets actuellement dans le tampon d'entrée du canal channel. Cela peut être utilisé pour déterminer combien de données sont disponibles pour la lecture sans bloquer.

TCL_OUTPUTBUFFERED

La procédure Tcl_OutputBuffered retourne le nombre d'octets actuellement dans le tampon de sortie du canal channel. Cela peut être utilisé pour déterminer combien de données doivent encore être écrites.

TCL_SEEK

La procédure Tcl_Seek modifie la position actuelle du curseur dans le canal channel. offset spécifie la quantité de déplacement, et seekMode spécifie le point de référence (SEEK_SET pour le début, SEEK_CUR pour la position actuelle, SEEK_END pour la fin). La procédure retourne la nouvelle position du curseur en octets, ou -1 en cas d'erreur.

TCL_TELL

La procédure Tcl_Tell retourne la position actuelle du curseur dans le canal channel en octets, ou -1 en cas d'erreur.

TCL_TRUNCATECHANNEL

La procédure Tcl_TruncateChannel tronque le canal channel à la longueur spécifiée par length. Cela signifie que toutes les données après l'octet length sont supprimées. Cette opération n'est valide que pour les canaux qui prennent en charge le déplacement (seekable). La procédure retourne 0 en cas de succès, ou une valeur d'erreur Tcl en cas d'échec.

TCL_GETCHANNELOPTION

La procédure Tcl_GetChannelOption récupère la valeur de l'option optionName pour le canal channel et la stocke dans la chaîne dynamique optionValue. La procédure retourne 0 en cas de succès, ou une valeur d'erreur Tcl en cas d'échec.

TCL_SETCHANNELOPTION

La procédure Tcl_SetChannelOption définit la valeur de l'option optionName pour le canal channel à la nouvelle valeur newValue. La procédure retourne 0 en cas de succès, ou une valeur d'erreur Tcl en cas d'échec.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et renvoie un descripteur de canal pouvant être utilisé pour effectuer des entrées et sorties vers le fichier. Cette API est modelée sur la fonction fopen de la bibliothèque d'entrée/sortie standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles de la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas nul, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. À partir de Tcl 8.4, l'API basée sur les valeurs Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel dans tous les cas.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en tant que remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Il crée un pipeline de processus séquentiels spécifiés par les arguments argv et argc et renvoie un canal qui peut être utilisé pour communiquer avec ces processus séquentiels. L'argument flags indique le type de communication que vous aurez avec le pipeline de commandes.

Si le drapeau TCL_STDIN est défini, l'entrée standard du premier processus séquentiel sera liée au canal : écrire dans le canal fournira l'entrée au processus séquentiel. Si le drapeau TCL_STDIN n'est pas défini, l'entrée standard du premier processus séquentiel sera la même que l'entrée standard de cette application. Si le drapeau TCL_STDOUT est défini, la sortie standard du dernier processus séquentiel peut être lue à partir du canal ; sinon, elle va à la sortie standard de cette application. Si le drapeau TCL_STDERR est défini, la sortie d'erreur standard de tous les processus séquentiels est renvoyée au canal et génère une erreur lorsque le canal est fermé ; sinon, elle va à la sortie d'erreur standard de cette application. Si le drapeau TCL_ENFORCE_MODE n'est pas défini, les arguments argc et argv peuvent rediriger les descripteurs standard pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, c'est une erreur pour argc et argv de rediriger les canaux standard pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être nul.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en tant que remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un descripteur de fichier existant et spécifique à la plateforme. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en tant que remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel renvoie un canal donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur dans interp. Si aucun canal enregistré dans cet interpréteur avec ce nom n'existe, il renvoie NULL. Si l'argument modePtr n'est pas nul, il pointe vers un entier qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtre ces noms selon le pattern. Si pattern est nul, il ne filtre rien. La valeur renvoyée est TCL_OK s'il n'y a pas d'erreur lors de l'écriture dans le résultat, sinon TCL_ERROR, et le message d'erreur reste dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à la collection de canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur peuvent faire référence au canal en utilisant le nom donné dans l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal est automatiquement fermé lorsqu'il est désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur peut appeler Tcl_RegisterChannel avec interp à NULL, indiquant qu'il souhaite conserver une référence à ce canal. Ultérieurement, le canal peut être enregistré dans un interpréteur Tcl et ne sera fermé que lorsque le même nombre d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code s'exécutant en dehors de tout interpréteur de conserver en toute sécurité une référence à un canal qui est également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code qui gère les canaux standard. Si aucun canal standard n'est initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour une discussion générale sur les canaux standard et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel supprime un canal de la collection de canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Si cette opération a supprimé le dernier enregistrement du canal dans n'importe quel interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur peut appeler Tcl_UnregisterChannel avec interp à NULL, indiquant à Tcl qu'il n'a plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel, sauf qu'il ferme également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel supprime un canal de la collection de canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Par conséquent, cette commande n'a aucun effet supplémentaire. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin), et renvoie TCL_ERROR si l'un de ces canaux est passé.

Le code non associé à un interpréteur peut appeler Tcl_DetachChannel avec interp à NULL, indiquant à Tcl qu'il n'a plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel vérifie si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. Si c'est le cas, il renvoie 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lorsque Tcl_Close est appelé. Le tampon de sortie est vidé avant que le canal ne soit détruit, et tout tampon d'entrée est jeté. S'il s'agit d'un canal bloquant, l'appel ne renvoie pas tant que tout le tampon n'a pas été correctement envoyé au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a un tampon de sortie qui ne peut pas être écrit sans blocage, l'appel renvoie immédiatement ; la sortie est vidée en arrière-plan et le canal est fermé une fois que tout le tampon a été écrit. Dans ce cas, les erreurs survenues pendant le vidage sont signalées, mais pas les erreurs survenues lors de la fermeture elle-même.

Si le canal a été fermé correctement, Tcl_Close renvoie TCL_OK. Si une erreur se produit, Tcl_Close renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas nul, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré avec Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour les détails. Si le canal a été donné comme chan dans un appel à Tcl_RegisterChannel, vous devez utiliser Tcl_UnregisterChannel, qui appelle Tcl_Close en interne lorsque tous les appels à Tcl_RegisterChannel ont été mis en correspondance par des appels à Tcl_UnregisterChannel.

TCL_READCHARS AND TCL_READ

Tcl_ReadChars consomme des octets du channel, les convertit en UTF-8 selon le codage du canal et stocke les données produites dans la représentation de readObjPtr. La valeur renvoyée par Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit pendant la lecture, la valeur renvoyée est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Le mot charsToRead doit être utilisé avec précaution, car si une valeur supérieure au nombre d'octets disponibles dans le canal est passée, une erreur se produira.

/i> à -1 entraînera la commande à lire tous les caractères actuellement disponibles (non bloquant) ou tout jusqu'à eof (mode bloquant).

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé étaient disponibles. Ceci est appelé une lecture courte. En mode bloquant, cela ne peut se produire qu'à la fin du fichier. En mode non bloquant, une lecture courte peut également se produire s'il n'y a pas assez d'entrée actuellement disponible : Tcl_ReadChars retourne un compte court plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour déterminer laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les diverses représentations de fin de ligne en la représentation interne canonique \n selon le mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les divers modes spécifiques à la plateforme sont décrits dans l'entrée manuelle de la commande Tcl fconfigure.

En tant qu'optimisation des performances, lors de la lecture à partir d'un canal avec le codage binary, les octets ne sont pas convertis en UTF-8 lors de leur lecture. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr comme une valeur de tableau d'octets. La représentation sous forme de chaîne de cette valeur ne sera construite que si elle est nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette façon, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans les frais de conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'il ne fait pas de conversions d'encodage, quel que soit le codage du canal. Il est déprécié et existe pour des raisons de compatibilité ascendante avec les extensions Tcl non internationalisées. Il consomme des octets du channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par un zéro. Son contenu est valide à partir de la position zéro jusqu'à, mais sans inclure, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas l'empilement. Tandis que Tcl_Read (et les autres fonctions de l'API) obtient toujours ses données du canal supérieur dans la pile dont le canal fourni fait partie, Tcl_ReadRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canal transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données du canal inférieur dans la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, en convertissant les octets en UTF-8 en fonction du codage du canal, jusqu'à ce qu'une ligne complète d'entrée ait été vue. Si le codage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception du(des) caractère(s) de fin de ligne terminant, sont ajoutés à la représentation sous forme de chaîne de lineObjPtr. Le(s) caractère(s) de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_GetsObj retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj retourne également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est retourné, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité de l'entrée.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique fournie par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, soit à la tête, soit à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si channel a un EOF « collant » défini, aucune donnée ne sera ajoutée à la file d'entrée. Tcl_Ungets retourne inputLen ou -1 en cas d'erreur.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données de caractères à charBuf. Les caractères UTF-8 du tampon sont convertis vers le codage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par un zéro et il sort tout jusqu'au zéro.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal à none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un compte du nombre d'octets acceptés pour la sortie vers le canal. Il s'agit soit d'un nombre supérieur à zéro pour indiquer le succès, soit de -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme selon l'option -translation pour le canal. Ceci est fait même si le canal n'a pas de codage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'il accepte une valeur Tcl dont le contenu sera sorti vers le canal. Les caractères UTF-8 de la représentation sous forme de chaîne de writeObjPtr sont convertis vers le codage du canal et mis en file d'attente pour la sortie vers channel. En tant qu'optimisation des performances, lors de l'écriture sur un canal avec le codage binary, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets dans la représentation interne de writeObjPtr en tant que valeur de tableau d'octets sont écrits dans le canal. La représentation de tableau d'octets de la valeur sera construite si nécessaire. De cette façon, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans les frais de conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'il ne fait pas de conversions d'encodage, quel que soit le codage du canal. Il est déprécié et existe pour des raisons de compatibilité ascendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par un zéro et il sort tout jusqu'au zéro.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas l'empilement. Tandis que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée dans le canal supérieur de la pile dont le canal fourni fait partie, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canal transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation dans le canal inférieur.

TCL_FLUSH

Tcl_Flush provoque l'écriture de toutes les données de sortie mises en mémoire tampon pour channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données mises en mémoire tampon n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal est non bloquant ; il démarre une vidange en arrière-plan qui écrira les données mises en mémoire tampon vers le canal éventuellement, aussi vite que le canal est capable de les absorber.

La valeur de retour est normalement TCL_OK. En cas d'erreur, Tcl_Flush retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données ultérieures seront lues ou écrites. La sortie mise en mémoire tampon est vidée vers le canal et l'entrée mise en mémoire tampon est ignorée, avant l'opération de recherche.

Tcl_Seek retourne normalement le nouveau point d'accès. En cas d'erreur, Tcl_Seek retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut ou peut ne pas avoir été déplacé.

TCL_TELL

Tcl_Tell retourne le point d'accès actuel pour un canal. La valeur retournée est -1 si le canal ne prend pas en charge la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent de channel à une longueur donnée de length octets. Il retourne TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION
