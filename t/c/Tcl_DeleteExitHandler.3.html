Tcl_DeleteExitHandler(3)

Paquet: tcl

Licences: TCL

Tcl_Exit(3) Procédures de la bibliothèque Tcl Tcl_Exit(3)

NOM

Tcl_Exit, Tcl_Finalize, Tcl_CreateExitHandler, Tcl_DeleteExitHandler, Tcl_ExitThread, Tcl_FinalizeThread, Tcl_CreateThreadExitHandler, Tcl_DeleteThreadExitHandler, Tcl_SetExitProc - terminer l'application ou le fil d'exécution (et appeler les gestionnaires de sortie)

SYNTAXE

#include <tcl.h>

Tcl_Exit(status)

Tcl_Finalize()

Tcl_CreateExitHandler(proc, clientData)

Tcl_DeleteExitHandler(proc, clientData)

Tcl_ExitThread(status)

Tcl_FinalizeThread()

Tcl_CreateThreadExitHandler(proc, clientData)

Tcl_DeleteThreadExitHandler(proc, clientData)

Tcl_ExitProc *
Tcl_SetExitProc(proc)

ARGUMENTS

int status (entrée)
Fournit des informations sur la raison de la sortie de l'application ou du fil d'exécution. La signification exacte peut être spécifique à la plateforme. 0 signifie généralement une sortie normale, toute valeur non nulle signifie généralement qu'une erreur s'est produite.
Tcl_ExitProc *proc (entrée)
Procédure à appeler avant de quitter l'application, ou (pour Tcl_SetExitProc) NULL pour désinstaller la procédure de sortie d'application actuelle.
ClientData clientData (entrée)
Valeur arbitraire d'un mot à passer à proc.

DESCRIPTION

Les procédures décrites ici fournissent un mécanisme de sortie gracieux pour terminer l'exécution d'une application Tcl. Les gestionnaires de sortie sont appelés pour nettoyer l'état de l'application avant de terminer l'exécution du code Tcl.

Appelez Tcl_Exit pour terminer une application Tcl et sortir du processus courant. Cette procédure est appelée par la commande exit et peut être appelée n'importe où ailleurs pour terminer l'application. Personne ne devrait jamais appeler la procédure système exit directement ; appelez toujours Tcl_Exit à la place, afin qu'elle puisse appeler les gestionnaires de sortie. Notez que si un autre code appelle la procédure système exit directement, ou provoque autrement la terminaison de l'application sans appeler Tcl_Exit, les gestionnaires de sortie ne seront pas exécutés. Tcl_Exit appelle en interne l'appel système exit, elle ne retourne donc jamais le contrôle à son appelant. Si un gestionnaire de sortie d'application a été installé (voir Tcl_SetExitProc), ce gestionnaire est appelé avec un argument consistant en le statut de sortie (converti en ClientData) ; le gestionnaire de sortie d'application ne doit pas retourner le contrôle à Tcl.

Tcl_Finalize est similaire à Tcl_Exit sauf qu'elle ne quitte pas le processus courant. Elle est utile pour le nettoyage lorsqu'un processus a fini d'utiliser Tcl mais souhaite continuer à s'exécuter, et lorsque Tcl est utilisé dans une extension chargée dynamiquement qui est sur le point d'être déchargée. Votre code doit toujours appeler Tcl_Finalize lorsque Tcl est déchargé, pour assurer un nettoyage approprié. Tcl_Finalize peut être appelée plusieurs fois en toute sécurité.

Tcl_ExitThread est utilisée pour terminer le fil d'exécution courant et appeler les gestionnaires de sortie par fil d'exécution. Cette finalisation est effectuée par Tcl_FinalizeThread, que vous pouvez appeler si vous souhaitez simplement nettoyer l'état spécifique au fil d'exécution et appeler les gestionnaires de sortie du fil d'exécution. Tcl_Finalize appelle automatiquement Tcl_FinalizeThread pour le fil d'exécution courant.

Tcl_CreateExitHandler organise l'appel de proc par Tcl_Finalize et Tcl_Exit. Tcl_CreateThreadExitHandler organise l'appel de proc par Tcl_FinalizeThread et Tcl_ExitThread. Cela fournit un point d'ancrage pour les opérations de nettoyage telles que la mise en mémoire tampon de vidage et la libération de la mémoire globale. Proc doit correspondre au type Tcl_ExitProc :

typedef void Tcl_ExitProc(
        ClientData clientData);

Le paramètre clientData de proc est une copie de l'argument clientData donné à Tcl_CreateExitHandler ou Tcl_CreateThreadExitHandler lors de la création du rappel. Typiquement, clientData pointe vers une structure de données contenant des informations spécifiques à l'application sur ce qu'il faut faire dans proc.

Tcl_DeleteExitHandler et Tcl_DeleteThreadExitHandler peuvent être appelés pour supprimer un gestionnaire de sortie précédemment créé. Ils suppriment le gestionnaire indiqué par proc et clientData afin qu'aucun appel à proc ne soit effectué. S'il n'existe pas de tel gestionnaire, alors Tcl_DeleteExitHandler ou Tcl_DeleteThreadExitHandler ne fait rien.

Tcl_Finalize et Tcl_Exit exécutent tous les gestionnaires de sortie enregistrés, dans l'ordre inverse de celui dans lequel ils ont été enregistrés. Cela correspond à l'ordre naturel dans lequel les extensions sont chargées et déchargées ; si l'extension A charge l'extension B, elle décharge généralement B avant d'être elle-même déchargée. Si l'extension A enregistre ses gestionnaires de sortie avant de charger l'extension B, cela garantit que tous les gestionnaires de sortie pour B seront exécutés avant les gestionnaires de sortie pour A.

Tcl_Finalize et Tcl_Exit appellent Tcl_FinalizeThread et les gestionnaires de sortie de fil d'exécution *après* les gestionnaires de sortie de processus. C'est parce que la finalisation de fil d'exécution arrête le système de canaux d'E/S, de sorte que toute tentative d'E/S par les gestionnaires de sortie globaux disparaîtra dans le néant.

Tcl_SetExitProc installe un gestionnaire de sortie d'application, renvoyant le gestionnaire de sortie d'application précédemment installé ou NULL si aucun gestionnaire d'application n'était installé. Si un gestionnaire de sortie d'application est installé, ce gestionnaire prend la responsabilité complète de la finalisation des sous-systèmes Tcl via Tcl_Finalize à un moment approprié. L'argument passé à proc lorsqu'il est appelé sera le code de statut de sortie (tel que passé à Tcl_Exit) converti en une valeur ClientData.
