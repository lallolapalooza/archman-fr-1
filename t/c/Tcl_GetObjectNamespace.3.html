ARGUMENTS

Tcl_Interp *interp (entrée/sortie)
Interpréteur fournissant le contexte pour rechercher ou créer un objet, et dans lequel les messages d'erreur seront écrits en cas d'échec.

Le nom de l'objet à rechercher.

Référence à l'objet sur lequel opérer.
Tcl_Class class (entrée)
Référence à la classe sur laquelle opérer.
const char *name (entrée)
Le nom de l'objet à créer, ou NULL si un nouveau nom inutilisé doit être sélectionné automatiquement.
const char *nsName (entrée)
Le nom de l'espace de noms à créer pour l'usage privé de l'objet, ou NULL si un nouveau nom inutilisé doit être sélectionné automatiquement. L'espace de noms ne doit pas exister au préalable.
int objc (entrée)
Le nombre d'éléments dans le tableau objv.
Tcl_Obj *const *objv (entrée)
Les arguments de la commande pour créer l'instance de la classe.
int skip (entrée)
Le nombre d'arguments au début du tableau d'arguments, objv, qui ne sont pas des arguments pour des constructeurs. Ceci permet la génération de messages d'erreur corrects même lorsque des schémas d'appel compliqués sont utilisés (par exemple, via la commande next).
Tcl_ObjectMetadataType *metaTypePtr (entrée)
Le type de metadata qui est défini avec Tcl_ClassSetMetadata ou récupéré avec Tcl_ClassGetMetadata.
ClientData metadata (entrée)
Un élément de métadonnées à attacher à la classe, ou NULL pour supprimer les métadonnées associées à un metaTypePtr particulier.
Tcl_ObjectMapMethodNameProc methodNameMapper (entrée)
Un pointeur vers une fonction à appeler pour ajuster le mappage des objets et des noms de méthodes aux implémentations, ou NULL lorsqu'aucun tel mappage n'est requis.

DESCRIPTION

Les objets sont des entités typées qui ont un ensemble d'opérations ("méthodes") qui leur sont associées. Les classes sont des objets qui peuvent fabriquer des objets. Chaque classe peut être considérée comme un objet en soi ; la vue objet peut être récupérée à l'aide de Tcl_GetClassAsObject qui retourne toujours l'objet lorsqu'elle est appliquée à une classe non détruite, et un objet peut être vu comme une classe à l'aide de Tcl_GetObjectAsClass (qui retourne soit la classe, soit NULL si l'objet n'est pas une classe). Un objet peut être recherché à l'aide de la fonction Tcl_GetObjectFromObj, qui retourne soit un objet, soit NULL (avec un message d'erreur dans le résultat de l'interpréteur) si l'objet ne peut être trouvé. La manière correcte de rechercher une classe par son nom est de rechercher l'objet portant ce nom, puis d'utiliser Tcl_GetObjectAsClass.

Chaque objet a sa propre commande et son propre espace de noms qui lui sont associés. La commande peut être récupérée à l'aide de la fonction Tcl_GetObjectCommand, le nom de l'objet (et donc le nom de la commande) avec Tcl_GetObjectName, et l'espace de noms peut être récupéré à l'aide de la fonction Tcl_GetObjectNamespace. Notez que la référence Tcl_Obj retournée par Tcl_GetObjectName est une référence partagée. Vous pouvez également savoir si l'objet a été marqué pour suppression avec Tcl_ObjectDeleted (il retourne vrai si la suppression de l'objet a commencé) ; ceci peut être utile lors du traitement des méthodes.

Les instances de classes sont créées à l'aide de Tcl_NewObjectInstance, qui crée un objet à partir de n'importe quelle classe (et qui est appelée en interne par les méthodes create et new de la classe oo::class). Elle prend des paramètres qui donnent optionnellement le nom de l'objet et de l'espace de noms à créer, et qui décrivent les arguments à passer au constructeur de la classe (s'il y en a). Le résultat de la fonction sera soit une référence au nouvel objet créé, soit NULL si la création a échoué (un message d'erreur sera alors laissé dans le résultat de l'interpréteur). De plus, les objets peuvent être copiés en utilisant Tcl_CopyObjectInstance qui crée une copie d'un objet sans exécuter de constructeurs.

Notez que la gestion du cycle de vie des objets est gérée en interne par TclOO, et n'utilise pas Tcl_Preserve. Il n'est pas sûr de placer une référence Tcl_Object dans une structure C dont la durée de vie est différente de celle de l'objet ; vous devriez utiliser le nom de la commande de l'objet (tel qu'obtenu avec Tcl_GetObjectName) à la place. Il est sûr d'utiliser une référence Tcl_Object pendant la durée d'appel d'une méthode sur cet objet ; les références ne deviennent pas invalides tant qu'il y a un appel en cours sur leur objet (même si la seule opération garantie d'être sûre sur elles est Tcl_ObjectDeleted ; les autres opérations ne sont garanties de fonctionner que sur des objets non détruits).

MÉTADONNÉES OBJET ET CLASSE

Chaque objet et chaque classe peuvent avoir une quantité arbitraire de métadonnées qui leur sont attachées, pour lesquelles l'objet ou la classe n'attache aucune signification au-delà de ce qui est décrit dans une instance de structure Tcl_ObjectMetadataType. Les métadonnées à attacher sont décrites par le type des métadonnées (donné dans l'argument metaTypePtr) et un pointeur arbitraire (l'argument metadata) qui sont donnés à Tcl_ObjectSetMetadata et Tcl_ClassSetMetadata, et une pièce de métadonnées particulière peut être récupérée en donnant son type avec Tcl_ObjectGetMetadata et Tcl_ClassGetMetadata. Si le paramètre metadata de Tcl_ObjectSetMetadata ou Tcl_ClassSetMetadata est NULL, les métadonnées sont supprimées si elles étaient attachées, et les résultats de Tcl_ObjectGetMetadata et Tcl_ClassGetMetadata sont NULL si le type de métadonnées donné n'était pas attaché. Il n'est pas considéré comme une erreur de demander ou de supprimer une pièce de métadonnées qui n'était pas attachée.

STRUCTURE TCL_OBJECTMETADATATYPE

Le contenu de la structure Tcl_ObjectMetadataType est le suivant :

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

Le champ version permet des extensions futures de la structure, et doit toujours être déclaré égal à TCL_OO_METADATA_VERSION_CURRENT. Le champ name fournit un nom lisible par l'homme pour le type, et est réservé au débogage.

Le champ deleteProc donne une fonction de type Tcl_ObjectMetadataDeleteProc qui est utilisée pour supprimer une pièce de métadonnées particulière, et qui est appelée lorsque les métadonnées attachées sont remplacées ou supprimées ; le champ ne doit pas être NULL.

Le champ cloneProc donne une fonction qui est utilisée pour copier une pièce de métadonnées (utilisée lorsqu'une copie d'objet est créée en utilisant Tcl_CopyObjectInstance) ; si NULL, les métadonnées seront simplement copiées directement.

SIGNATURE FONCTION TCL_OBJECTMETADATADELETEPROC

Les fonctions correspondant à cette signature sont utilisées pour supprimer les métadonnées associées à une classe ou à un objet.

typedef void Tcl_ObjectMetadataDeleteProc(ClientData clientData);

SIGNATURE FONCTION TCL_CLONEPROC

Les fonctions correspondant à cette signature sont utilisées pour cloner les métadonnées associées à une classe ou à un objet.

typedef ClientData Tcl_CloneProc(ClientData clientData);

SIGNATURE FONCTION TCL_OBJECTMAPMETHODNAMEPROC

Les fonctions correspondant à cette signature sont utilisées pour mapper un nom de méthode donné à un nom de méthode différent, utilisé pour trouver le code d'implémentation de la méthode.

typedef const char * Tcl_ObjectMapMethodNameProc(Tcl_Object object,
        const char *methodName);

AVERTISSEMENTS

Les objets TclOO sont des objets Tcl standards, et ne doivent pas être considérés comme des primitives d'une valeur simple, et en particulier comme des objets que vous pouvez stocker en toute sécurité dans une structure C avec une durée de vie différente de celle de l'objet.

L'utilisation de pointeurs Tcl_Object en dehors de la portée de la méthode appelée est déconseillée et peut entraîner un comportement indéfini.
