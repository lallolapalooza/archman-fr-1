ARGUMENTS

Interpréteur contenant la variable.
const char *name1 (in)
Nom d'une variable de tableau (si name2 n'est pas NULL) ou (si name2 est NULL) nom d'une variable scalaire ou nom complet incluant le nom de la variable et l'indice. Peut inclure :: pour spécifier une variable dans un espace de noms particulier.
const char *name2 (in)
S'il n'est pas NULL, nom de l'élément dans le tableau ; dans ce cas, name1 doit faire référence à une variable de tableau.
Tcl_Obj *newValuePtr (in)
Pointeur vers une valeur Tcl contenant la nouvelle valeur de la variable.
int flags (in)
OU bit à bit fournissant des informations supplémentaires. Voir ci-dessous pour les valeurs valides.
const char *varName (in)
Nom de la variable. Peut inclure :: pour spécifier une variable dans un espace de noms particulier. Peut faire référence à une variable scalaire ou à un élément de tableau.
const char *newValue (in)
Nouvelle valeur de la variable, spécifiée sous forme de chaîne terminée par un caractère nul. Une copie de cette valeur est stockée dans la variable.
Tcl_Obj *part1Ptr (in)
Pointeur vers une valeur Tcl contenant le nom de la variable. Le nom peut inclure une série de :: pour spécifier une variable dans un espace de noms particulier. Peut faire référence à une variable scalaire ou à un élément d'une variable de tableau.
Tcl_Obj *part2Ptr (in)
S'il n'est pas NULL, pointe vers une valeur contenant le nom d'un élément dans un tableau et part1Ptr doit faire référence à une variable de tableau.

DESCRIPTION

Ces procédures sont utilisées pour créer, modifier, lire et supprimer des variables Tcl à partir du code C.

Tcl_SetVar2Ex, Tcl_SetVar, Tcl_SetVar2 et Tcl_ObjSetVar2 créeront une nouvelle variable ou modifieront une variable existante. Ces procédures définiront la valeur donnée par newValuePtr ou newValue dans la variable donnée et retourneront un pointeur vers sa nouvelle valeur, qui est stockée dans la structure de variable de Tcl. Tcl_SetVar2Ex et Tcl_ObjSetVar2 reçoivent la nouvelle valeur sous forme de Tcl_Obj et retournent un pointeur vers un Tcl_Obj. Tcl_SetVar et Tcl_SetVar2 reçoivent la nouvelle valeur sous forme de chaîne et retournent une chaîne ; elles sont généralement moins efficaces que Tcl_ObjSetVar2. Notez que la valeur retournée peut être différente de l'argument newValuePtr ou newValue, en raison des modifications apportées par les traceurs d'écriture. Si une erreur se produit lors de la définition de la variable (par exemple, une référence à un tableau sans spécifier d'indice dans le tableau), NULL est retourné et un message d'erreur est laissé dans le résultat de interp si le bit TCL_LEAVE_ERR_MSG est actif.

Tcl_GetVar2Ex, Tcl_GetVar, Tcl_GetVar2 et Tcl_ObjGetVar2 retournent la valeur actuelle d'une variable. Les arguments de ces procédures sont traités de la même manière que les arguments des procédures décrites ci-dessus. Normalement, la valeur retournée est un pointeur vers la valeur de la variable. Pour Tcl_GetVar2Ex et Tcl_ObjGetVar2, la valeur est retournée sous forme de pointeur vers un Tcl_Obj. Pour Tcl_GetVar et Tcl_GetVar2, la valeur est retournée sous forme de chaîne ; c'est généralement moins efficace, Tcl_GetVar2Ex ou Tcl_ObjGetVar2 sont donc préférables. Si une erreur se produit lors de la lecture de la variable (par exemple, la variable n'existe pas ou un élément de tableau est spécifié pour une variable scalaire), NULL est retourné et un message d'erreur est laissé dans le résultat de interp si le bit TCL_LEAVE_ERR_MSG est actif.

Tcl_UnsetVar et Tcl_UnsetVar2 peuvent être utilisés pour supprimer une variable, ce qui fait que les tentatives futures de lecture de celle-ci renvoient une erreur. Les arguments de ces procédures sont traités de la même manière que les arguments des procédures précédentes. Si la variable est supprimée avec succès, TCL_OK est retourné. Si la variable ne peut pas être supprimée car elle n'existe pas, TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de interp si le bit TCL_LEAVE_ERR_MSG est actif. Si un élément de tableau est spécifié, l'élément donné est supprimé mais le tableau reste. Si un nom de tableau sans indice est spécifié, le tableau entier est supprimé.

Le nom d'une variable peut être spécifié à ces procédures de quatre manières :

[1]
Si Tcl_SetVar, Tcl_GetVar ou Tcl_UnsetVar est appelé, le nom de la variable est donné sous forme d'une seule chaîne, varName. Si varName contient une parenthèse ouvrante et se termine par une parenthèse fermante, la valeur entre les parenthèses est considérée comme un indice (toute valeur de chaîne) et les caractères avant la première parenthèse sont considérés comme le nom d'une variable de tableau. Si varName ne contient pas de parenthèses comme décrit ci-dessus, l'ensemble complet est considéré comme le nom d'une variable scalaire.
[2]
Si name1 et name2 sont spécifiés et que name2 n'est pas NULL, un élément de tableau est spécifié et le nom du tableau et l'indice ont déjà été séparés par l'appelant : name1 contient le nom et name2 contient l'indice. Une erreur est générée si name1 contient une parenthèse ouvrante et se termine par une parenthèse fermante (élément de tableau) et name2 n'est pas NULL.
[3]
Si name2 est NULL, name1 est traité comme varName dans le cas [1] (il peut s'agir d'une variable scalaire ou d'une variable de tableau).

L'argument flags peut être utilisé pour spécifier l'une des plusieurs options mentionnées. Il est constitué d'un OU des bits suivants :

TCL_GLOBAL_ONLY
Normalement, les procédures recherchent les variables comme suit. S'il y a un appel de procédure actif dans interp, la variable est recherchée au niveau d'appel de procédure actuel. Sinon, elle est recherchée d'abord dans l'espace de noms actuel, puis dans l'espace de noms global. Cependant, si ce bit est actif dans flags, la variable n'est recherchée que dans l'espace de noms global, même s'il y a un appel de procédure actif dans interp. Si TCL_GLOBAL_ONLY et TCL_NAMESPACE_ONLY sont tous deux spécifiés, TCL_GLOBAL_ONLY est ignoré.
TCL_NAMESPACE_ONLY
Si ce bit est actif dans flags, la variable n'est recherchée que dans l'espace de noms actuel ; s'il y a un appel de procédure actif, ses variables sont ignorées, et l'espace de noms global est également ignoré, à moins qu'il ne s'agisse de l'espace de noms actuel.
TCL_LEAVE_ERR_MSG
Si une erreur est retournée et que ce bit est actif dans flags, un message d'erreur est laissé dans le résultat de interp, où il peut être récupéré avec Tcl_GetObjResult ou Tcl_GetStringResult. Si ce bit n'est pas actif, aucun message d'erreur n'est laissé et le résultat de interp n'est pas modifié.
TCL_APPEND_VALUE
Si ce bit est actif, newValuePtr ou newValue est ajouté à la valeur actuelle au lieu de la remplacer. Si la variable est actuellement indéfinie, le bit est ignoré. Ce bit n'est utilisé que par les procédures Tcl_Set*.
TCL_LIST_ELEMENT
Si ce bit est actif, newValue est converti en un élément de liste Tcl valide avant de définir (ou d'ajouter à) la variable. Un espace de séparation est ajouté avant le nouvel élément de liste. Un séparateur d'espace est ajouté avant le nouvel élément de liste.

ARGUMENTS

-

Le répertoire de variables qui va être utilisé pour stocker et récupérer les variables. Le champ varTable de la structure Tcl_Interp est généralement utilisé.

Le nom de la variable à modifier ou à lire. Pour les tableaux, le nom est divisé en deux chaînes par Tcl_SetVar2 et Tcl_GetVar2 : la première chaîne est le nom du tableau et la deuxième est l'indice de l'élément. Pour Tcl_SetVar et Tcl_GetVar, le nom est une seule chaîne, qui peut contenir des caractères `(` pour les indices de tableau (par exemple, array(index)).

La nouvelle valeur à donner à la variable. Si le bit TCL_LIST_ELEMENT est défini dans le drapeau, alors le comportement diffère. La nouvelle valeur est ajoutée comme dernier élément d'une liste. Le comportement est le même que celui de la commande Tcl lappend.

Un masque de bits contenant un ou plusieurs des indicateurs suivants :

TCL_GLOBAL_ONLY
Ne recherche la variable que dans la portée globale ; ignore les portées locales ou les cadres de pile.
TCL_APPEND_VALUE
Ajoute la nouvelle valeur à la fin de la valeur existante de la variable, au lieu de la remplacer. Si la variable n'existe pas, elle est créée avec la nouvelle valeur. Si l'opération d'ajout échoue (par exemple, si la valeur existante n'est pas une chaîne valide ou si l'opération tente d'ajouter un élément à une liste qui n'est pas elle-même une liste), alors une erreur est retournée.
TCL_LIST_ELEMENT
Traite la variable comme une liste et ajoute la nouvelle valeur comme dernier élément de cette liste. La variable est traitée comme une liste uniquement si la variable n'est pas le premier élément d'une liste ou d'une sous-liste (c'est-à-dire si la valeur actuelle de la variable est vide, ne contient que le caractère '{' ou se termine par ' }'). Lors de l'ajout, la valeur d'origine de la variable doit également être une liste valide, de sorte que l'opération consiste à ajouter un nouvel élément de liste à une liste.
TCL_LEAVE_ERR_MSG
Ne formate pas le message d'erreur. Si une erreur se produit, le message d'erreur se trouve dans le champ result de la structure Tcl_Interp. Si ce bit n'est pas défini, Tcl formatera le message d'erreur.

DESCRIPTION

Les procédures Tcl_SetVar et Tcl_SetVar2 définissent la valeur d'une variable dans l'interpréteur Tcl spécifié. Les arguments name et name1/name2 spécifient la variable. Si la variable n'existe pas, elle est créée. Le comportement est le même que celui des commandes Tcl set et array set. La valeur est définie à la chaîne spécifiée par l'argument value. Si l'un des indicateurs TCL_APPEND_VALUE ou TCL_LIST_ELEMENT est défini dans flags, le comportement est modifié comme décrit ci-dessus pour l'argument flags.

Si la variable est définie avec succès, alors TCL_OK est retourné. Si une erreur se produit (par exemple, une tentative de définir un élément de tableau pour une variable scalaire ou une mauvaise utilisation des indicateurs), alors TCL_ERROR est retourné et le champ result de la structure Tcl_Interp contiendra un message d'erreur.

Il est important de noter que lorsque l'indicateur TCL_LIST_ELEMENT est utilisé, Tcl essaie de conserver la valeur de la variable sous forme de liste. Si la valeur existante de la variable n'est pas une liste valide, le comportement est le même que s'il s'agissait d'une simple concaténation de chaînes. Cela se produit lorsque la valeur actuelle de la variable est vide, ne contient que le caractère '{' ou se termine par ' }'. Lorsque vous ajoutez, la valeur d'origine de la variable doit également être une liste valide, de sorte que l'opération consiste à ajouter un nouvel élément de liste à une liste.

Tcl_GetVar et Tcl_GetVar2 retournent la valeur actuelle d'une variable. Les arguments de ces procédures sont traités de la même manière que les arguments de Tcl_SetVar et Tcl_SetVar2. Dans des circonstances normales, la valeur de retour est un pointeur vers la valeur de la variable (qui est stockée dans la structure de variable de Tcl et ne changera pas avant le prochain appel à Tcl_SetVar ou Tcl_SetVar2). Tcl_GetVar et Tcl_GetVar2 utilisent les bits d'indicateurs TCL_GLOBAL_ONLY et TCL_LEAVE_ERR_MSG, qui ont tous deux la même signification que pour Tcl_SetVar. Si une erreur se produit lors de la lecture de la variable (par exemple, la variable n'existe pas ou un élément de tableau est spécifié pour une variable scalaire), alors NULL est retourné.

Tcl_UnsetVar et Tcl_UnsetVar2 peuvent être utilisés pour supprimer une variable, de sorte que les appels futurs à Tcl_GetVar ou Tcl_GetVar2 pour la variable retourneront une erreur. Les arguments de ces procédures sont traités de la même manière que les arguments de Tcl_GetVar et Tcl_GetVar2. Si la variable est supprimée avec succès, alors TCL_OK est retourné. Si la variable ne peut pas être supprimée car elle n'existe pas, alors TCL_ERROR est retourné. Si un élément de tableau est spécifié, l'élément donné est supprimé mais le tableau reste. Si un nom de tableau est spécifié sans indice, alors le tableau entier est supprimé.
