Tcl_Main(3) Procédures de bibliothèque Tcl Tcl_Main(3)

NOM

Tcl_Main, Tcl_MainEx, Tcl_MainExW, Tcl_SetStartupScript, Tcl_GetStartupScript, Tcl_SetMainLoop - programme principal, script de démarrage et définition de la boucle d'événements pour les applications basées sur Tcl

SYNOPSIS

#include <tcl.h>

Tcl_Main(argc, argv, appInitProc)

Tcl_MainEx(argc, charargv, appInitProc, interp)

Tcl_MainExW(argc, wideargv, appInitProc, interp)

Tcl_SetStartupScript(path, encoding)

Tcl_Obj *
Tcl_GetStartupScript(encodingPtr)

Tcl_SetMainLoop(mainLoopProc)

ARGUMENTS

int argc (entrée)
Nombre d'éléments dans argv.
char *argv[] (entrée)
Tableau de chaînes contenant les arguments de la ligne de commande. Sous Windows, lorsqu'on utilise -DUNICODE, le type du paramètre change en wchar_t *.
char *charargv[] (entrée)
Comme argv, mais ne change pas de type en wchar_t.
char *wideargv[] (entrée)
Comme argv, mais le type est toujours wchar_t.
Tcl_AppInitProc *appInitProc (entrée)
Adresse d'une procédure d'initialisation spécifique à l'application. La valeur pour ce paramètre est généralement Tcl_AppInit.
Tcl_Obj *path (entrée)
Nom du fichier à utiliser comme script de démarrage, ou NULL.
const char *encoding (entrée)
Encodage du fichier à utiliser comme script de démarrage, ou NULL.
const char **encodingPtr (sortie)
Si non NULL, emplacement pour écrire une copie du pointeur (const char *) vers le nom de l'encodage.
Tcl_MainLoopProc *mainLoopProc (entrée)
Adresse d'une procédure de boucle d'événements spécifique à l'application.
Tcl_Interp *interp (entrée)
Interpréteur Tcl déjà créé.

DESCRIPTION

Tcl_Main peut servir de programme principal pour les applications de type shell Tcl. Un “shell application” est un programme comme tclsh ou wish qui supporte à la fois l'interprétation interactive de Tcl et l'évaluation d'un script contenu dans un fichier donné comme argument de ligne de commande. Tcl_Main est offert comme une commodité aux développeurs de shells applications, afin qu'ils n'aient pas à reproduire tout le code pour l'initialisation correcte de la bibliothèque Tcl et le fonctionnement du shell interactif. D'autres styles d'intégration de Tcl dans une application ne sont pas supportés par Tcl_Main. Ceux-ci doivent être réalisés en appelant directement des fonctions de niveau inférieur de la bibliothèque Tcl.

La fonction Tcl_Main est offerte par la bibliothèque Tcl depuis la version Tcl 7.4. Dans les versions antérieures de Tcl, la bibliothèque Tcl elle-même définissait une fonction main, mais cela manque de flexibilité quant au style d'intégration et avoir une fonction main dans une bibliothèque (particulièrement une bibliothèque partagée) cause des problèmes sur de nombreux systèmes. Avoir main dans la bibliothèque Tcl rendrait également difficile l'utilisation de Tcl dans des programmes C++, puisque les programmes C++ doivent avoir des fonctions main spéciales C++.

Normalement, chaque application shell contient une petite fonction main qui ne fait que d'invoquer Tcl_Main. Tcl_Main fait alors tout le travail de création et d'exécution d'une application de type tclsh.

Tcl_Main n'est pas fournie par l'interface publique de la bibliothèque de stubs de Tcl. Les programmes qui appellent Tcl_Main doivent être liés à la bibliothèque Tcl standard. Les extensions (avec ou sans stubs) ne sont pas censées appeler Tcl_Main.

Tcl_Main n'est pas thread-safe. Elle ne devrait être appelée que par un seul thread principal d'une application multithread. Cette restriction n'est pas un problème dans l'utilisation normale décrite ci-dessus.

Tcl_Main et donc toutes les applications basées sur elle, comme tclsh, utilisent Tcl_GetStdChannel pour initialiser les canaux standards à leurs valeurs par défaut. Voir Tcl_StandardChannels pour plus d'informations.

Tcl_Main supporte deux modes de fonctionnement, selon que le nom de fichier et l'encodage d'un script de démarrage ont été établis ou non. Les routines Tcl_SetStartupScript et Tcl_GetStartupScript sont les outils pour contrôler cette configuration de Tcl_Main.

Tcl_SetStartupScript enregistre la valeur path comme nom du fichier que Tcl_Main doit évaluer comme son script de démarrage. La valeur encoding est le nom Tcl de l'encodage utilisé pour stocker le texte dans ce fichier. Une valeur de NULL pour encoding est un signal pour utiliser l'encodage système. Une valeur de NULL pour path efface tout enregistrement existant afin que Tcl_Main n'évalue aucun script de démarrage.

Tcl_GetStartupScript interroge le nom de fichier et l'encodage enregistrés par le dernier appel à Tcl_SetStartupScript dans le même thread. Le nom de fichier stocké est retourné, et le nom d'encodage stocké est écrit à l'emplacement pointé par encodingPtr, lorsque celui-ci n'est pas NULL.

Les valeurs de nom de fichier et d'encodage gérées par les routines Tcl_SetStartupScript et Tcl_GetStartupScript sont stockées par thread. Bien que les fonctions de stockage et de récupération de ces routines fonctionnent dans n'importe quel thread, seuls les appels dans le même thread principal que Tcl_Main peuvent avoir une influence sur celui-ci.

L'appelant de Tcl_Main peut appeler Tcl_SetStartupScript au préalable pour établir son script de démarrage souhaité. Si Tcl_Main constate qu'aucun script de démarrage de ce type n'a été établi, il consulte les premiers arguments de argv. S'ils correspondent à ?-encoding name? fileName, où fileName ne commence pas par le caractère -, alors fileName est considéré comme le nom d'un fichier contenant un script de démarrage, et name est considéré comme le nom de l'encodage du contenu de ce fichier. Tcl_Main appelle alors Tcl_SetStartupScript avec ces valeurs.

Tcl_Main définit ensuite dans son interpréteur principal les variables Tcl argc, argv, argv0, et tcl_interactive, comme décrit dans la documentation de tclsh.

Une fois son propre initialisation terminée, mais avant de traiter les commandes, Tcl_Main appelle la procédure donnée par l'argument appInitProc. Cette procédure fournit un “hook” pour que l'application effectue sa propre initialisation de l'interpréteur créé par Tcl_Main, telle que la définition de commandes spécifiques à l'application. La routine d'initialisation de l'application peut également appeler Tcl_SetStartupScript pour (re)définir le fichier et l'encodage à utiliser comme script de démarrage. La procédure doit avoir une interface qui correspond au type Tcl_AppInitProc :

typedef int Tcl_AppInitProc(
        Tcl_Interp *interp);

AppInitProc est presque toujours un pointeur vers Tcl_AppInit ; pour plus de détails sur cette procédure, voir la documentation de Tcl_AppInit.

Lorsque appInitProc est terminée, Tcl_Main appelle Tcl_GetStartupScript pour déterminer quel script de démarrage a été demandé, le cas échéant. Si un script de démarrage a été fourni, Tcl_Main tente de l'évaluer. Sinon, le mode interactif commence par l'examen de la variable tcl_rcFileName dans l'interpréteur principal. Si cette variable existe et contient le nom d'un fichier lisible, le contenu de ce fichier est évalué dans l'interpréteur principal. Ensuite, les opérations interactives commencent, avec les invites et les résultats d'évaluation des commandes écrits sur le canal de sortie standard, et les commandes lues depuis le canal d'entrée standard puis évaluées. Les invites écrites sur le canal de sortie standard peuvent être personnalisées en définissant les variables Tcl tcl_prompt1 et tcl_prompt2 comme décrit dans la documentation de tclsh. Les invites et les résultats d'évaluation des commandes sont écrits sur le canal de sortie standard uniquement si la variable Tcl tcl_interactive dans l'interpréteur principal contient une valeur entière non nulle.

Tcl_SetMainLoop permet de définir une procédure de boucle d'événements à exécuter. Cela permet, par exemple, à Tk d'être chargé dynamiquement et de définir sa boucle d'événements. La boucle d'événements s'exécutera après le script de démarrage. Si vous êtes en mode interactif, définir la procédure de boucle principale fera que l'invite deviendra basée sur fileevent, puis la procédure de boucle sera appelée. Lorsque la procédure de boucle retourne en mode interactif, l'opération interactive se poursuivra. La procédure de boucle principale doit avoir une interface qui correspond au type Tcl_MainLoopProc :

typedef void Tcl_MainLoopProc(void);

Tcl_Main ne retourne pas. Normalement, un programme basé sur Tcl_Main se terminera lorsque la commande exit sera évaluée. En mode interactif, si un EOF ou une erreur de canal est rencontré sur le canal d'entrée standard, alors Tcl_Main évaluera elle-même la commande exit.

Tcl_MainExW(3) — Tcl — archlinux.fr

NAME

Tcl_MainExW — main application procedure for Tcl applications

SYNOPSIS

#include <tcl.h>

int
Tcl_MainExW(int argc, wchar_t **argv, Tcl_AppInitProc *appInitProc, Tcl_Interp *interp);

ARGUMENTS

argc (in):
Number of arguments in argv.
argv (in):
Array of arguments.
appInitProc (in):
Procedure to call to perform application-specific initialization.
interp (in):
The interpreter to use for the application. If this is NULL, then a new interpreter will be created.

DESCRIPTION

Tcl_MainExW is the main entry point for Tcl applications. It performs several initialization steps, processes command-line arguments, and then enters the Tcl event loop.

The appInitProc procedure is called to perform application-specific initialization. This procedure should initialize any Tcl packages that the application needs and perform any other setup required.

Command-line arguments are processed as follows:

  • If the -encoding option is present, it specifies the encoding of the startup script.
  • If the -path option is present, it adds directories to the auto_path variable.
  • If the - option is present, it specifies the startup script to evaluate.

After processing command-line arguments, Tcl_MainExW enters the Tcl event loop by calling Tcl_DoOneEvent. This loop continues until an event occurs that causes the application to exit.

In interactive mode, after the main loop procedure (if any) returns. In non-interactive mode, after Tcl_MainExW evaluates the startup script, and the main loop procedure (if any) returns, Tcl_MainExW will also evaluate the exit command.

SEE ALSO

tclsh(1), Tcl_GetStdChannel(3), Tcl_StandardChannels(3), Tcl_AppInit(3), exit(n), encoding(n)

KEYWORDS
