ARGUMENTS

Tcl_Interp *interp (in)
L'interpréteur où les données compressées ou décompressées seront stockées. C'est également là que les messages d'erreur seront écrits. Pour Tcl_ZlibStreamInit, ceci peut être NULL pour créer un flux qui n'est pas associé à une commande.
int format (in)
Quel format de données compressées vous souhaitez utiliser. Doit être l'un des suivants : TCL_ZLIB_FORMAT_ZLIB pour les données zlib, TCL_ZLIB_FORMAT_GZIP pour les données gzip, ou TCL_ZLIB_FORMAT_RAW pour les données compressées brutes. De plus, pour la compression uniquement, vous pouvez également choisir TCL_ZLIB_FORMAT_AUTO, qui peut détecter automatiquement si les données compressées étaient au format zlib ou gzip.
Tcl_Obj *dataObj (in/out)
Une valeur de type tableau d'octets contenant les données à compresser ou décompresser, ou celles qui seront ajoutées aux données extraites du flux lorsqu'elles sont passées à Tcl_ZlibStreamGet.
int level (in)
Quel niveau de compression vous souhaitez utiliser. Doit être un nombre de 0 à 9 ou l'un des suivants : TCL_ZLIB_COMPRESS_NONE sans compression, TCL_ZLIB_COMPRESS_FAST pour une compression rapide mais inefficace, TCL_ZLIB_COMPRESS_BEST pour une compression lente mais maximale, ou TCL_ZLIB_COMPRESS_DEFAULT pour le niveau recommandé par la bibliothèque zlib.
Tcl_Obj *dictObj (in/out)
Un dictionnaire qui contient, ou sera mis à jour pour contenir, une description de l'en-tête gzip associé aux données compressées. N'est utile que lorsque le format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Si NULL est passé, un en-tête par défaut sera utilisé pour la compression et l'en-tête sera ignoré (sauf pour les vérifications d'intégrité) lors de la décompression. Pour plus de détails sur le contenu de ce dictionnaire, voir la section GZIP OPTIONS DICTIONARY.
unsigned int initValue (in)
La valeur initiale pour l'algorithme de checksum.
int bufferSize (in)
Un indicateur de la taille du tampon à utiliser pour recevoir les données. Utilisez 0 pour utiliser une estimation basée sur les données d'entrée.
unsigned char *bytes (in)
Un tableau d'octets pour exécuter l'algorithme de checksum, ou NULL pour obtenir la valeur initiale recommandée pour l'algorithme de checksum.
int length (in)
Le nombre d'octets dans le tableau.
int mode (in)
Dans quel mode le flux va opérer. Doit être TCL_ZLIB_STREAM_DEFLATE pour un flux de compression ou TCL_ZLIB_STREAM_INFLATE pour un flux de décompression.
Tcl_ZlibStream *zshandlePtr (out)
Un pointeur vers une variable dans laquelle le jeton abstrait du flux sera écrit en cas de succès lors de sa création.
Tcl_ZlibStream zshandle (in)
Le jeton abstrait du flux sur lequel opérer.
int flush (in)
Et comment le flux sera vidé après y avoir écrit des données. Doit être l'un des suivants : TCL_ZLIB_NO_FLUSH si aucune vidange ne doit être effectuée, TCL_ZLIB_FLUSH si les données compressées actuelles doivent être rendues disponibles pour être accessibles via Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si le flux doit être mis dans un état où le décompresseur peut récupérer d'une corruption, ou TCL_ZLIB_FINALIZE pour s'assurer que le flux est terminé et que toute terminaison demandée par le format est écrite.
int count (in)
Le nombre maximum d'octets à obtenir du flux, ou -1 pour obtenir tous les octets restants des tampons du flux.
Tcl_Obj *compDict (in)
Une valeur de type tableau d'octets qui est le dictionnaire de compression à utiliser avec le flux. Il convient de noter qu'il ne s'agit pas d'un dictionnaire Tcl, et il est recommandé de ne l'utiliser qu'avec les flux qui ont été créés avec leur format défini sur TCL_ZLIB_FORMAT_ZLIB, car les autres formats n'ont aucun mécanisme pour indiquer si un dictionnaire de compression a été fourni, sauf en échouant à la décompression.

DESCRIPTION

Ces fonctions sont l'interface du langage Tcl à la bibliothèque Zlib de Jean-loup Gailly et Mark Adler.

Tcl_ZlibDeflate et Tcl_ZlibInflate compressent et décompressent les données contenues dans l'argument dataObj, selon l'argument format et, pour la compression, l'argument level. Le dictionnaire de l'argument dictObj est utilisé pour passer des informations supplémentaires sur les données compressées lorsque le format de compression le prend en charge ; actuellement, le dictionnaire n'est utilisé que lorsque l'argument format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Pour plus de détails sur le contenu du dictionnaire, voir la section GZIP OPTIONS DICTIONARY. Une fois réussies, les deux fonctions laissent les données compressées ou décompressées dans une valeur de type tableau d'octets qui est le résultat de l'interpréteur Tcl ; la valeur renvoyée est un code de résultat Tcl standard.

Tcl_ZlibAdler32 et Tcl_ZlibCRC32 calculent des checksums sur des tableaux d'octets, renvoyant le checksum calculé. Les checksums sont calculés de manière incrémentielle, ce qui permet de traiter les données bloc par bloc, mais cela nécessite que l'appelant conserve la valeur actuelle du checksum et la passe comme paramètre initValue ; la valeur initiale pour cela peut être obtenue en utilisant NULL comme paramètre bytes au lieu d'un pointeur vers un tableau d'octets pour calculer le checksum. Par conséquent, l'utilisation typique sur un bloc de données unique est la suivante :

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Remarque : l'algorithme Adler-32 n'est pas un véritable checksum, mais un type de hachage connexe qui fonctionne mieux sur de longues données.

FLUX ZLIB

Tcl_ZlibStreamInit crée un flux de compression ou de décompression lié à une commande Tcl, selon ses arguments, et fournit un jeton abstrait pour le flux et renvoie un code de résultat normal ; Tcl_ZlibStreamGetCommandName renvoie le nom de cette commande étant donné le jeton du flux, ou NULL si le flux n'a pas de commande. Les flux ne sont pas conçus pour être sûrs multi-plateformes ; chaque flux ne doit être utilisé qu'à partir du thread qui l'a créé. Lors de l'utilisation de flux gzip, un dictionnaire (champs tels que dans la section GZIP OPTIONS DICTIONARY) peut être fourni par le paramètre dictObj, ce qui permet de contrôler les en-têtes générés lors de la compression, et lors de la décompression permet de découvrir les en-têtes existants. Il est à noter que le dictionnaire sera écrit lors de la décompression une fois que suffisamment de données auront été lues pour avoir un en-tête complet. Cela signifie que le dictionnaire doit être une valeur non partagée dans ce cas ; il est suggéré d'utiliser une valeur vide créée avec Tcl_NewObj.

Une fois qu'un flux est construit, Tcl_ZlibStreamPut est utilisé pour ajouter des données au flux et Tcl_ZlibStreamGet est utilisé pour obtenir des données du flux après son traitement. Les deux renvoient des codes de résultat normaux de Tcl et laissent un message d'erreur dans le résultat de l'interpréteur auquel le flux est enregistré en cas d'erreur (si un tel enregistrement a été effectué). Avec Tcl_ZlibStreamPut, la valeur du tampon de données qui lui est passé ne doit pas être modifiée par la suite. Avec Tcl_ZlibStreamGet, la valeur du tampon de données qui lui est passé aura les octets de données ajoutés. Interne au flux, les données sont maintenues compressées pour minimiser le coût de l'espace tampon.

Tcl_ZlibStreamChecksum renvoie le checksum calculé sur les données non compressées selon le format, et Tcl_ZlibStreamGet est celui utilisé pour obtenir le checksum du flux.

Tcl_ZlibStreamInit(3) — Tcl

NAME

Tcl_ZlibStreamInit, Tcl_ZlibStreamPut, Tcl_ZlibStreamGet, Tcl_ZlibStreamEof, Tcl_ZlibStreamSetCompressionDictionary, Tcl_ZlibStreamReset, Tcl_ZlibStreamClose — Interface to the zlib compression library

SYNOPSIS

#include <tcl.h>

Tcl_ObjCmdProc *
Tcl_ZlibStreamInit(interp, argc, objv)
Tcl_ObjCmdProc *
Tcl_ZlibStreamPut(interp, stream, dataObj, flush)
Tcl_ObjCmdProc *
Tcl_ZlibStreamGet(interp, stream, size)
Tcl_ObjCmdProc *
Tcl_ZlibStreamEof(stream)
Tcl_ObjCmdProc *
Tcl_ZlibStreamSetCompressionDictionary(stream, dictObj)
Tcl_ObjCmdProc *
Tcl_ZlibStreamReset(stream)
Tcl_ObjCmdProc *
Tcl_ZlibStreamClose(stream)

ARGUMENTS

interp (Tcl_Interp*)
Tcl interpreter to use for error reporting and for creating the stream command.
argc (int)
Number of arguments in objv.
objv (Tcl_Obj* const [])
Array of arguments. The first argument is the name of the command to create.
stream (Tcl_ZlibStream*)
Opaque pointer to a zlib stream state.
dataObj (Tcl_Obj*)
An object containing the data to write to the stream.
flush (int)
How to flush the stream. One of Z_NO_FLUSH, Z_SYNC_FLUSH, Z_FULL_FLUSH, Z_FINISH.
size (int)
The maximum number of bytes to read from the stream.
dictObj (Tcl_Obj*)
A Tcl object containing the compression dictionary.

DESCRIPTION

These functions provide an interface to the zlib compression library. The primary function is Tcl_ZlibStreamInit which initializes and returns a new zlib stream object, and registers a Tcl command with the interpreter to control the stream. The command is created with the name given by the first element of objv. The remaining elements of objv are arguments to the command, and are interpreted as follows:

init name compressionLevel ?options?
Initializes a new zlib stream. The name argument is the name of the Tcl command to create for this stream. compressionLevel must be an integer between -1 and 9, or 0 for no compression. The following options are understood:
-type type
Specifies the type of compression. Must be one of zlib, gzip, or raw. The default is zlib.
-dictionary dictObj
Specifies a compression dictionary. See Tcl_ZlibStreamSetCompressionDictionary below.
-level level
Same as the positional argument compressionLevel.
put data ?flush?
Writes the given data to the stream, optionally flushing the stream according to flush. Returns the number of bytes written.
get size
Reads up to size bytes from the stream and returns them as a byte array object. If an error occurs, the command returns an empty string and sets the Tcl result to an error message.
eof
Returns a boolean value indicating whether the end of the uncompressed data has been reached.
setdictionary dictionary
Sets the compression dictionary for the stream. See Tcl_ZlibStreamSetCompressionDictionary below.
reset
Resets the stream for reuse. See Tcl_ZlibStreamReset below.
close
Closes the stream and deletes the associated command. See Tcl_ZlibStreamClose below.

Tcl_ZlibStreamPut writes data to the stream. The flush argument specifies how the stream should be flushed. The values are defined in the zlib library, and include:

Z_NO_FLUSH
Don't flush; allow more output to be buffered.
Z_SYNC_FLUSH
Flush as much as possible, but don't necessarily finish the current block or function call. data is guaranteed to be available to the caller. If the compression level is greater than 1, the compressed output is guaranteed to be written. (The zlib manual says that only data up to the last full input block is written. This function is useful for input when you might be reading from a file and want to allow the compressed file to be read from the beginning before the end of the compressed file is reached.)
Z_FULL_FLUSH
Flush all output available. A useful compression function is guaranteed to be completely finished. This function is useful in all circumstances. If the compression level is set to Z_BEST_SPEED, this option is the same as Z_SYNC_FLUSH. Otherwise, data is flushed and the compressed output is guaranteed to be written.
Z_FINISH
Stream the computations tothe end of the compressed file. Tcl_ZlibStreamPut will return a normal Tcl result code, but the stream will no longer accept data.

Tcl_ZlibStreamGet reads data from the stream. The size argument specifies the maximum number of bytes to read. Returns the data as a Tcl byte array object. If the end of the stream is reached, it returns an empty string.

Tcl_ZlibStreamEof returns a boolean value indicating whether the end of the uncompressed data has been reached.

Tcl_ZlibStreamSetCompressionDictionary is used to control the compression dictionary used with the stream, a compression dictionary being an array of bytes (such as might be created with Tcl_NewByteArrayObj) that is used to initialize the compression engine rather than leaving it to create it on the fly from the data being compressed. Setting a compression dictionary allows for more efficient compression in the case where the start of the data is highly regular, but it does require both the compressor and the decompressor to agree on the value to use. Compression dictionaries are only fully supported for zlib-format data; on compression, they must be set before any data is sent in with Tcl_ZlibStreamPut, and on decompression they should be set when Tcl_ZlibStreamGet produces an error with its -errorcode set to “ZLIB NEED_DICT code”; the code will be the Adler-32 checksum (see Tcl_ZlibAdler32) of the compression dictionary sought. (Note that this is only true for zlib-format streams; gzip streams ignore compression dictionaries as the format specification doesn't permit them, and raw streams just produce a data error if the compression dictionary is missing or incorrect.)

If you wish to clear a stream and reuse it for a new compression or decompression action, Tcl_ZlibStreamReset will do this and return a normal Tcl result code to indicate whether it was successful; if the stream is registered with an interpreter, an error message will be left in the interpreter result when this function returns TCL_ERROR. Finally, Tcl_ZlibStreamClose will clean up the stream and delete the associated command: using Tcl_DeleteCommand on the stream's command is equivalent (when such a command exists).

GZIP OPTIONS DICTIONARY

The dictObj parameter to Tcl_ZlibDeflate, Tcl_ZlibInflate and Tcl_ZlibStreamInit is used to pass a dictionary of options about that is used to describe the gzip header in the compressed data. When creating compressed data, the dictionary is read and when unpacking compressed data the dictionary is written (in which case the dictObj parameter must refer to an unshared dictionary value).

The following fields in the dictionary value are understood. All other fields are ignored. No field is required when creating a gzip-format stream.

comment
This holds the comment field of the header, if present. If absent, no comment was supplied (on decompression) or will be created (on compression).
crc
A boolean value describing whether a CRC of the header is computed. Note that the gzip program does not use or allow a CRC on the header.
filename
The name of the file that held the uncompressed data. This should not contain any directory separators, and should be sanitized before use on decompression with file tail.
os
The operating system type code field from the header (if not the “unknown” value). See RFC 1952 for the meaning of these codes. On compression, if this is absent then the field will be set to the “unknown” value.
size
The size of the uncompressed data. This is ignored on compression; the size of the data compressed depends on how much data is supplied to the compression engine.
time
The time field from the header if non-zero, expected to be the time that the file named by the filename field was modified. Suitable for use with clock format. On creation, the right value to use is that from clock seconds or file mtime.
type
The type of the uncompressed data (either binary or text) if known.

PORTABILITY NOTES

These functions will fail gracefully if Tcl is not linked with the zlib library.
