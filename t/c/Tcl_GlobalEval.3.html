Tcl_Eval(3) Procédures de la bibliothèque Tcl Tcl_Eval(3)

NOM

Tcl_EvalObjEx, Tcl_EvalFile, Tcl_EvalObjv, Tcl_Eval, Tcl_EvalEx, Tcl_GlobalEval, Tcl_GlobalEvalObj, Tcl_VarEval, Tcl_VarEvalVA - exécuter des scripts Tcl

SYNTAXE

#include <tcl.h>

int
Tcl_EvalObjEx(interp, objPtr, flags)

int
Tcl_EvalFile(interp, fileName)

int
Tcl_EvalObjv(interp, objc, objv, flags)

int
Tcl_Eval(interp, script)

int
Tcl_EvalEx(interp, script, numBytes, flags)

int
Tcl_GlobalEval(interp, script)

int
Tcl_GlobalEvalObj(interp, objPtr)

int
Tcl_VarEval(interp, part, part, ... (char *)NULL)

int
Tcl_VarEvalVA(interp, argList)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur dans lequel exécuter le script. Le résultat de l'interpréteur est modifié pour contenir le résultat ou le message d'erreur du script.
Tcl_Obj *objPtr (entrée)
Une valeur Tcl contenant le script à exécuter.
int flags (entrée)
Combinaison OU de bits d'indicateurs qui spécifient des options supplémentaires. TCL_EVAL_GLOBAL et TCL_EVAL_DIRECT sont actuellement pris en charge.
const char *fileName (entrée)
Nom d'un fichier contenant un script Tcl.
int objc (entrée)
Le nombre de valeurs dans le tableau pointé par objv ; c'est aussi le nombre de mots dans la commande.
Tcl_Obj **objv (entrée)
Pointe vers un tableau de pointeurs vers des valeurs ; chaque valeur contient la valeur d'un seul mot dans la commande à exécuter.
int numBytes (entrée)
Le nombre d'octets dans script, sans inclure de caractère nul de fin. Si c'est -1, alors tous les caractères jusqu'au premier octet nul sont utilisés.
const char *script (entrée)
Pointe vers le premier octet du script à exécuter (terminé par un octet nul et encodé en UTF-8).
const char *part (entrée)
Chaîne formant une partie d'un script Tcl.
va_list argList (entrée)
Une liste d'arguments qui doit avoir été initialisée avec va_start et effacée avec va_end.

DESCRIPTION

Les procédures décrites ici sont appelées pour exécuter des scripts Tcl sous diverses formes. Tcl_EvalObjEx est la procédure centrale et est utilisée par beaucoup des autres. Elle exécute les commandes dans le script stocké dans objPtr jusqu'à ce qu'une erreur se produise ou que la fin du script soit atteinte. Si c'est la première fois que objPtr est exécuté, ses commandes sont compilées en instructions bytecode qui sont ensuite exécutées. Les bytecodes sont sauvegardés dans objPtr afin que l'étape de compilation puisse être ignorée si la valeur est évaluée à nouveau plus tard.

La valeur de retour de Tcl_EvalObjEx (et de toutes les autres procédures décrites ici) est un code de complétion Tcl avec l'une des valeurs TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK, ou TCL_CONTINUE, ou potentiellement une autre valeur entière provenant d'une extension. De plus, une valeur de résultat ou un message d'erreur est laissé dans le résultat de interp ; il peut être récupéré en utilisant Tcl_GetObjResult.

Tcl_EvalFile lit le fichier donné par fileName et évalue son contenu comme un script Tcl. Elle retourne les mêmes informations que Tcl_EvalObjEx. Si le fichier n'a pas pu être lu, une erreur Tcl est retournée pour décrire pourquoi le fichier n'a pas pu être lu. Le caractère de fin de fichier pour les fichiers est “\32” (^Z) pour toutes les plateformes. Si vous avez besoin d'un “^Z” dans le code pour la comparaison de chaînes, vous pouvez utiliser “\032” ou “\u001a”, qui seront en toute sécurité substitués par l'interpréteur Tcl en “^Z”.

Tcl_EvalObjv exécute une seule commande pré-analysée au lieu d'un script. Les arguments objc et objv contiennent les valeurs des mots de la commande Tcl, un mot dans chaque valeur de objv. Tcl_EvalObjv évalue la commande et retourne un code de complétion et un résultat, tout comme Tcl_EvalObjEx. L'appelant de Tcl_EvalObjv doit gérer le compteur de références des éléments de objv, en s'assurant que les valeurs sont valides jusqu'à ce que Tcl_EvalObjv retourne.

Tcl_Eval est similaire à Tcl_EvalObjEx sauf que le script à exécuter est fourni sous forme de chaîne au lieu d'une valeur et aucune compilation n'a lieu. La chaîne doit être une chaîne UTF-8 correcte, telle que convertie par Tcl_ExternalToUtfDString ou Tcl_ExternalToUtf lorsqu'il est connu qu'elle pourrait contenir des caractères ASCII supérieurs dont les combinaisons possibles pourraient être un code spécial UTF-8. La chaîne est analysée et exécutée directement (en utilisant Tcl_EvalObjv) au lieu d'être compilée et d'exécuter les bytecodes. Dans les situations où l'on sait que le script ne sera jamais exécuté à nouveau, Tcl_Eval peut être plus rapide que Tcl_EvalObjEx.
Tcl_Eval retourne un code de complétion et un résultat, tout comme Tcl_EvalObjEx. Note : pour la compatibilité ascendante avec les versions antérieures à Tcl 8.0, Tcl_Eval copie le résultat de la valeur dans interp vers interp->result (son utilisation est déconseillée) où il peut être accédé directement.
Cela rend Tcl_Eval quelque peu plus lent que Tcl_EvalEx, qui ne fait pas la copie.

Tcl_EvalEx est une version étendue de Tcl_Eval qui prend des arguments supplémentaires numBytes et flags. Pour la raison d'efficacité donnée ci-dessus, Tcl_EvalEx est généralement préférée à Tcl_Eval.

Tcl_GlobalEval et Tcl_GlobalEvalObj sont des procédures plus anciennes qui sont maintenant déconseillées. Elles sont similaires à Tcl_EvalEx et Tcl_EvalObjEx sauf que le script est évalué dans l'espace de noms global et que son contexte de variables se compose uniquement de variables globales (il ignore toutes les procédures Tcl actives). Ces fonctions sont équivalentes à l'utilisation de l'indicateur TCL_EVAL_GLOBAL (voir ci-dessous).

Tcl_VarEval prend n'importe quel nombre d'arguments de chaîne de n'importe quelle longueur, les concatène en une seule chaîne, puis appelle Tcl_Eval pour exécuter cette chaîne comme une commande Tcl. Elle retourne le résultat de la commande et modifie également interp->result de la même manière que Tcl_Eval. Le dernier argument de Tcl_VarEval doit être (char *)NULL pour indiquer la fin des arguments.

Tcl_VarEvalVA est identique à Tcl_VarEval sauf que au lieu de prendre un nombre variable d'arguments, elle prend une liste d'arguments. Tcl_VarEvalVA est maintenant déconseillée.

BITS D'INDICATEURS

Toute combinaison OU (OR) des valeurs suivantes peut être utilisée pour l'argument flags des procédures telles que Tcl_EvalObjEx :

TCL_EVAL_DIRECT
Cet indicateur est uniquement utilisé par Tcl_EvalObjEx ; il est ignoré par les autres procédures. Si ce bit d'indicateur est défini, le script n'est pas compilé en bytecodes ; il est exécuté directement, comme le fait Tcl_EvalEx. L'indicateur TCL_EVAL_DIRECT est utile dans les situations où le contenu d'une valeur va changer immédiatement, de sorte que les bytecodes ne seront pas réutilisés lors d'une exécution future. Dans ce cas, il est plus rapide d'exécuter le script directement.
TCL_EVAL_GLOBAL
Si cet indicateur est défini, le script est évalué dans l'espace de noms global au lieu de l'espace de noms actuel et son contexte de variables se compose uniquement de variables globales (il ignore toutes les procédures Tcl actives).

DETAILS DIVERS

Pendant le traitement d'une commande Tcl, il est légal d'effectuer des appels imbriqués pour évaluer d'autres commandes (c'est ainsi que les procédures et certaines structures de contrôle sont implémentées). Si un code autre que TCL_OK est retourné par une invocation imbriquée de Tcl_EvalObjEx, l'appelant doit normalement retourner immédiatement, en passant ce même code de retour à son appelant, et ainsi de suite jusqu'à ce que l'application de haut niveau soit atteinte. Quelques commandes, comme for, vérifient certains codes de retour, comme TCL_BREAK et TCL_CONTINUE, et les traitent spécialement sans retourner.

Tcl_EvalObjEx garde une trace du nombre d'invocations Tcl_EvalObjEx imbriquées en cours pour interp. Tcl_GlobalEval(3) - Tcl Commands

NAME

Tcl_GlobalEval - evaluate Tcl script in a context where global variables are accessible

SYNOPSIS

#include <tcl.h>

int
Tcl_GlobalEval(interp, script);

ARGUMENTS

Tcl_Interp *interp
Interpreter in which to evaluate the script.
const char *script
String containing Tcl commands to evaluate.

DESCRIPTION

The function Tcl_GlobalEval evaluates the Tcl commands in the string script within the interpreter specified by interp. The commands are executed in the global scope of the interpreter, meaning that they have access to and can modify any global variables.

The return value from Tcl_GlobalEval is the same as the return value from the Tcl command that was executed last in the script. If the script completes successfully, the return value is TCL_OK. If an error occurs during execution, the return value is TCL_ERROR. If the script is interrupted (e.g., by a call to error or by the user), the return value is TCL_BREAK or TCL_CONTINUE, although these return codes should only be seen when implementing Tcl commands within C. Top-level applications should never see a return code from Tcl_GlobalEval other than TCL_OK or TCL_ERROR.

The result of the script is stored in the interpreter's result widget using Tcl_SetResult. It can be retrieved using Tcl_GetStringResult.

FLAG BITS

No flag bits are relevant to this function.

MISCELLANEOUS DETAILS

The Tcl_GlobalEval function is generally only useful for implementing Tcl commands that need to evaluate scripts in the global context. Most applications should use Tcl_EvalObjEx instead, which provides more control over the evaluation context and object-based scripting.

It is important to note that if the script being evaluated contains a command like break or continue, and this command is invoked in an inappropriate place, it will result in a TCL_BREAK or TCL_CONTINUE return code. This situation should generally not occur in typical use cases. Top-level applications should never see a return code from Tcl_EvalObjEx other than TCL_OK or TCL_ERROR.

execute, file, global, result, script, value
