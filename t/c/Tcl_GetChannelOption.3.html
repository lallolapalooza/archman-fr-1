ARGUMENTS

Tcl_Interp *interp (en)
Utilisé pour le rapport d'erreurs et pour rechercher un canal enregistré en son sein.
const char *fileName (en)
Le nom d'un fichier local ou réseau.
const char *mode (en)
Spécifie comment le fichier doit être accédé. Peut avoir toutes les valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (en)
Indicateurs de permission de style POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront appliquées au fichier créé.
int argc (en)
Le nombre d'éléments dans argv.
const char **argv (en)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans commutateur de la commande Tcl exec.
int flags (en)
Spécifie la disposition des descripteurs stdin, stdout, stderr dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, stdin du premier enfant du pipeline est le canal de pipe, sinon il est identique à l'entrée standard du processus appelant ; de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, le pipe peut rediriger les descripteurs stdio pour outrepasser les descripteurs stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, de telles redirections provoquent une erreur.

Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, il s'agit d'un descripteur de fichier, pour Windows, il s'agit d'un HANDLE.

Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (en)
Le nom du canal.

Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon de canal.

Un tampon contenant les caractères à envoyer en sortie vers le canal.

Un tampon contenant les octets à envoyer en sortie vers le canal.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des périphériques et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie en mémoire tampon sur une variété de types de fichiers, de sockets et de périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée du manuel pour Tcl_CreateChannel. Le mécanisme de canaux fournit un schéma de mise en mémoire tampon calqué sur les E/S standard d'Unix, et il permet également les E/S non bloquantes sur les canaux.

Les procédures décrites dans cette entrée du manuel comprennent les API C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canal et comment implémenter des pilotes de canal pour de nouveaux types de canaux, voir l'entrée du manuel pour Tcl_CreateChannel.

TCL_OPENFILECHANNEL

La procédure Tcl_OpenFileChannel ouvre un fichier nommé fileName. Le comportement est similaire à la commande Tcl open ; mode spécifie comment le fichier est ouvert (par exemple, r pour la lecture, w pour l'écriture, a pour l'ajout, rb pour la lecture binaire, etc.). permissions est utilisé uniquement si le fichier est créé (par exemple, s'il est ouvert en mode écriture ou ajout) et spécifie les permissions POSIX du nouveau fichier. La procédure renvoie un handle de canal Tcl. Si une erreur se produit, le canal renvoyé est NULL et une description de l'erreur est laissée dans le champ d'information d'erreur de l'interpréteur.

TCL_OPENCOMMANDCHANNEL

La procédure Tcl_OpenCommandChannel crée un pipeline de processus dans lequel le premier processus exécute la commande spécifiée par argv. Les descripteurs d'E/S standard du premier processus peuvent être redirigés pour utiliser le nouveau canal retourné, ou pour être les mêmes que les descripteurs d'E/S standard du processus appelant, selon les bits définis dans flags. Les bits TCL_STDIN, TCL_STDOUT, et TCL_STDERR spécifient respectivement si l'entrée standard, la sortie standard et la sortie d'erreur du premier processus doivent être connectées au pipeline. Si TCL_ENFORCE_MODE est spécifié, toute tentative de redirection supplémentaire des descripteurs d'E/S standard provoque une erreur.

Le canal retourné peut ensuite être utilisé pour communiquer avec le pipeline. L'utilisation des bits TCL_STDIN, TCL_STDOUT et TCL_STDERR dans flags détermine quels descripteurs d'E/S du processus appelant sont utilisés ; si un bit n'est pas défini, le descripteur d'E/S correspondant pour le premier processus du pipeline est le même que celui du processus appelant. Par exemple, si TCL_STDIN est défini, mais pas TCL_STDOUT, l'entrée standard du premier processus proviendra d'un pipe, tandis que sa sortie standard sera le même descripteur que la sortie standard du processus Tcl.

TCL_MAKEFILECHANNEL

La procédure Tcl_MakeFileChannel crée un nouveau canal Tcl à partir d'un descripteur de fichier ou d'un handle d'E/S existant. Le paramètre handle est le descripteur de fichier (sur Unix) ou le handle d'E/S (sur Windows) à encapsuler. Le paramètre readOrWrite est une combinaison OR des drapeaux TCL_READABLE et TCL_WRITABLE pour indiquer si le descripteur est disponible en lecture et/ou en écriture. Le canal est initialisé en utilisant le pilote de canal de fichier générique, qui gère les opérations par défaut des fichiers. Si le handle est un descripteur de fichier valide, le canal retourné sera responsable de la fermeture du descripteur de fichier lorsqu'il sera fermé, sauf si le drapeau TCL_CLOSE_READS ou TCL_CLOSE_WRITES est utilisé pour désactiver ce comportement.

TCL_GETCHANNEL

La procédure Tcl_GetChannel renvoie le canal Tcl associé au nom de canal channelName dans l'interpréteur interp. Le champ modePtr recevra une combinaison OR des drapeaux TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert pour lecture et/ou écriture. Si le canal n'existe pas ou n'est pas accessible dans le mode spécifié, NULL est renvoyé et une erreur est générée.

TCL_GETCHANNELNAMES

La procédure Tcl_GetChannelNames renvoie une liste de tous les noms de canaux actuellement enregistrés dans l'interpréteur interp sous forme de chaîne Tcl (en utilisant Tcl_Obj). La liste est séparée par des espaces. La procédure retourne TCL_OK en cas de succès et TCL_ERROR en cas d'échec (par exemple, si l'interpréteur est nul).

TCL_GETCHANNELNAMESEX

La procédure Tcl_GetChannelNamesEx est similaire à Tcl_GetChannelNames, mais elle ne renvoie que les noms de canaux qui correspondent au modèle spécifié par pattern. Le modèle est évalué à l'aide de Tcl_StringMatch. Si pattern est NULL, elle se comporte comme Tcl_GetChannelNames.

TCL_REGISTERCHANNEL

La procédure Tcl_RegisterChannel enregistre un canal Tcl créé par une autre procédure (par exemple, Tcl_CreateChannel) dans l'interpréteur interp. Après l'enregistrement, le canal peut être référencé par son nom dans les commandes Tcl.

TCL_UNREGISTERCHANNEL

La procédure Tcl_UnregisterChannel désenregistre un canal de l'interpréteur interp. Cela empêche de nouvelles références au canal par son nom, mais n'affecte pas les opérations en cours sur le canal. Le canal doit d'abord être fermé avec Tcl_Close avant d'être désenregistré pour éviter les fuites de ressources.

La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR si le canal n'est pas trouvé ou si une erreur se produit.

TCL_DETACHCHANNEL

La procédure Tcl_DetachChannel supprime un canal enregistré de l'interpréteur interp. Contrairement à Tcl_UnregisterChannel, cette opération libère toutes les ressources associées au canal, y compris la fermeture du descripteur sous-jacent. La procédure ne doit être appelée que pour les canaux qui ne sont plus nécessaires et qui n'ont pas été explicitement fermés avec Tcl_Close.

La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR si le canal n'est pas trouvé ou si une erreur se produit.

TCL_ISSTANDARDCHANNEL

La procédure Tcl_IsStandardChannel renvoie 1 si le canal fourni est l'un des canaux standard (stdin, stdout ou stderr) pour l'interpréteur, et 0 sinon.

TCL_CLOSE

La procédure Tcl_Close ferme le canal channel. Toutes les écritures en attente dans le tampon de sortie du canal sont d'abord vidées. Si le canal a été créé avec Tcl_OpenFileChannel ou Tcl_MakeFileChannel, cela fermera également le descripteur de fichier ou le handle sous-jacent.

La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR si une erreur se produit pendant le vidage ou la fermeture. Si le canal était déjà fermé, un code d'erreur peut être généré.

TCL_READCHARS

La procédure Tcl_ReadChars lit jusqu'à charsToRead caractères depuis le canal channel et les stocke dans la valeur Tcl référencée par readObjPtr. Si appendFlag est vrai, les caractères lus sont ajoutés à la fin de la valeur existante ; sinon, la valeur est remplacée. La lecture se poursuit jusqu'à ce que le nombre demandé de caractères soit lu, ou jusqu'à ce que la fin du fichier soit atteinte, ou jusqu'à ce qu'une erreur se produise. La procédure renvoie le nombre réel de caractères lus. Elle renvoie -1 en cas d'erreur ou si le canal est bloqué en attente d'entrée (dans le cas d'E/S non bloquantes).

TCL_READ

La procédure Tcl_Read lit jusqu'à bytesToRead octets depuis le canal channel et les place dans le tampon fourni par readBuf. Le tampon doit être suffisamment grand pour contenir le nombre d'octets spécifié. La procédure renvoie le nombre réel d'octets lus. Elle renvoie -1 en cas d'erreur ou si le canal est bloqué en attente d'entrée (dans le cas d'E/S non bloquantes).

TCL_GETSOBJ

La procédure Tcl_GetsObj lit une ligne depuis le canal channel et la stocke dans la valeur Tcl référencée par lineObjPtr. Une ligne est définie comme une séquence de caractères se terminant par un caractère de nouvelle ligne ('\n'). Le caractère de nouvelle ligne est lu mais n'est pas stocké dans la valeur Tcl. Si la fin du fichier est atteinte avant qu'un caractère de nouvelle ligne ne soit rencontré, la ligne lue jusqu'à ce point est renvoyée. La procédure renvoie le nombre d'octets lus (qui peut être 0 s'il n'y a rien à lire ou s'il s'agit d'une ligne vide suivie d'une nouvelle ligne). Elle renvoie -1 en cas d'erreur ou si le canal est bloqué en attente d'entrée.

La valeur Tcl référencée par lineObjPtr est remplacée par la ligne lue. Si vous souhaitez ajouter la ligne à une valeur existante, vous devez d'abord la dupliquer ou utiliser la commande Tcl gets.

TCL_GETS

La procédure Tcl_Gets lit une ligne depuis le canal channel et l'ajoute à la chaîne dynamique lineRead. Le comportement est identique à Tcl_GetsObj, sauf que la sortie est stockée dans une Tcl_DString.

La procédure renvoie le nombre d'octets lus (qui peut être 0), ou -1 en cas d'erreur ou si le canal est bloqué.

TCL_UNGETS

La procédure Tcl_Ungets renvoie les données spécifiées par input et inputLen au canal channel pour être lues plus tard. Si addAtEnd est vrai, les données sont ajoutées à la fin du tampon d'entrée du canal ; sinon, elles sont ajoutées au début. Cela permet de simuler la lecture de données qui n'étaient pas présentes lors de la lecture initiale.

La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

TCL_WRITEOBJ

La procédure Tcl_WriteObj écrit le contenu de la valeur Tcl référencée par writeObjPtr dans le canal channel. La procédure tentera d'écrire tous les octets, mais peut renvoyer un nombre inférieur si le tampon de sortie est plein (dans le cas d'E/S non bloquantes) ou si une erreur se produit. La procédure renvoie le nombre d'octets écrits.

TCL_WRITECHARS

La procédure Tcl_WriteChars écrit jusqu'à bytesToWrite caractères depuis le tampon charBuf dans le canal channel. Elle renvoie le nombre d'octets effectivement écrits.

TCL_WRITE

La procédure Tcl_Write écrit jusqu'à bytesToWrite octets depuis le tampon byteBuf dans le canal channel. Elle renvoie le nombre d'octets effectivement écrits.

TCL_READRAW

La procédure Tcl_ReadRaw lit des données brutes (sans traitement d'encodage/décodage) depuis le canal channel dans le tampon readBuf. Le nombre d'octets à lire est spécifié par bytesToRead. Elle renvoie le nombre d'octets lus.

TCL_WRITERAW

La procédure Tcl_WriteRaw écrit des données brutes (sans traitement d'encodage/décodage) depuis le tampon byteBuf dans le canal channel. Le nombre d'octets à écrire est spécifié par bytesToWrite. Elle renvoie le nombre d'octets écrits.

TCL_EOF

La procédure Tcl_Eof renvoie 1 si la fin du fichier a été atteinte sur le canal channel pour la lecture, et 0 sinon.

TCL_FLUSH

La procédure Tcl_Flush vide tous les tampons en attente pour le canal channel. Cela garantit que toutes les données écrites ont été envoyées au système d'exploitation sous-jacent. Elle renvoie TCL_OK en cas de succès, et TCL_ERROR si une erreur se produit.

TCL_INPUTBLOCKED

La procédure Tcl_InputBlocked renvoie 1 si une tentative de lecture sur le canal channel échouerait immédiatement parce qu'il n'y a pas de données disponibles (c'est-à-dire que le canal est bloqué en attente d'entrée), et 0 sinon. Ceci est utile pour les opérations non bloquantes.

TCL_INPUTBUFFERED

La procédure Tcl_InputBuffered renvoie le nombre d'octets actuellement disponibles dans le tampon d'entrée du canal channel. Ces données sont en attente d'être lues par l'application.

TCL_OUTPUTBUFFERED

La procédure Tcl_OutputBuffered renvoie le nombre d'octets attendant d'être écrits dans le tampon de sortie du canal channel. Ces données n'ont pas encore été transmises au système sous-jacent.

TCL_SEEK

La procédure Tcl_Seek modifie la position actuelle du curseur dans le canal channel. Le nouveau curseur est déterminé par le décalage offset et le mode de recherche seekMode. seekMode peut être SEEK_SET (le décalage est relatif au début du fichier), SEEK_CUR (le décalage est relatif à la position actuelle) ou SEEK_END (le décalage est relatif à la fin du fichier). La procédure renvoie la nouvelle position du curseur en octets, ou -1 en cas d'erreur.

TCL_TELL

La procédure Tcl_Tell renvoie la position actuelle du curseur dans le canal channel en octets, mesurée à partir du début du fichier. Elle renvoie -1 en cas d'erreur.

TCL_TRUNCATECHANNEL

La procédure Tcl_TruncateChannel tronque le canal channel à la longueur spécifiée par length. Si la longueur actuelle du canal est inférieure à length, il est étendu avec des zéros. Cette opération n'est valide que pour les canaux qui supportent les opérations de taille de fichier. La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

TCL_GETCHANNELOPTION

La procédure Tcl_GetChannelOption renvoie la valeur de l'option spécifiée par optionName pour le canal channel. La valeur est stockée dans la chaîne dynamique optionValue. Les noms d'options valides sont les mêmes que ceux acceptés par la commande Tcl fconfigure (par exemple, -blocking, -buffering, -encoding, -translation).

Elle renvoie TCL_OK en cas de succès, et TCL_ERROR si l'option n'est pas valide ou si une erreur se produit.

TCL_SETCHANNELOPTION

La procédure Tcl_SetChannelOption définit l'option spécifiée par optionName sur la nouvelle valeur newValue pour le canal channel. Les noms et valeurs d'options valides sont les mêmes que ceux acceptés par la commande Tcl fconfigure.

Elle renvoie TCL_OK en cas de succès, et TCL_ERROR si l'option n'est pas valide, si la valeur n'est pas valide, ou si une erreur se produit.

PENFILECHANNEL'>Tcl_OpenFileChannel

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et renvoie un descripteur de canal qui peut être utilisé pour effectuer des entrées et sorties sur le fichier. Cette API est calquée sur la procédure fopen de la bibliothèque d'E/S standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur survient lors de l'ouverture du canal, Tcl_OpenFileChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur la valeur Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel chaque fois que possible.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Elle crée une séquence de sous-processus spécifiés par les arguments argv et argc et renvoie un canal qui peut être utilisé pour communiquer avec ces sous-processus. L'argument flags indique le type de communication qui existera avec le pipeline de commandes.

Si l'indicateur TCL_STDIN est défini, l'entrée standard du premier sous-processus sera liée au canal : écrire dans le canal fournira une entrée au sous-processus. Si TCL_STDIN n'est pas défini, alors l'entrée standard du premier sous-processus sera la même que l'entrée standard de cette application. Si TCL_STDOUT est défini, la sortie standard du dernier sous-processus peut être lue à partir du canal ; sinon, elle va vers la sortie standard de cette application. Si TCL_STDERR est défini, la sortie de l'erreur standard pour tous les sous-processus est renvoyée au canal et résulte en une erreur lors de la fermeture du canal ; sinon, elle va vers la sortie d'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas défini, alors argc et argv peuvent rediriger les descripteurs stdio pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, alors c'est une erreur pour argc et argv de remplacer les canaux stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur survient lors de l'ouverture du canal, Tcl_OpenCommandChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un descripteur de fichier existant et spécifique à la plateforme. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel renvoie un canal donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur Tcl dans interp. Si aucun canal de ce nom n'est enregistré dans cet interpréteur, la procédure renvoie NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms selon le pattern. Si pattern est NULL, alors aucun filtrage ne sera effectué. La valeur de retour est TCL_OK si aucune erreur ne s'est produite lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur pourront se référer au canal dans les opérations d'entrée ou de sortie en utilisant le nom donné lors de l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour ce canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code s'exécutant en dehors de tout interpréteur Tcl peut appeler Tcl_RegisterChannel avec interp comme NULL, pour indiquer qu'il souhaite conserver une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et il ne sera fermé que lorsque le nombre correspondant d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code s'exécutant en dehors de tout interpréteur de conserver en toute sécurité une référence à un canal qui est également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code gérant les canaux standard. Si aucun canal standard n'a été initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un exposé général sur les canaux standard et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel supprime un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour se référer au canal dans cet interpréteur. Si cette opération a supprimé le dernier enregistrement du canal dans un quelconque interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur Tcl peut appeler Tcl_UnregisterChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera alors fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel sauf qu'il fermera également le canal si aucune référence supplémentaire à celui-ci n'existe.

TCL_DETACHCHANNEL

Tcl_DetachChannel supprime un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour se référer au canal dans cet interpréteur. Au-delà de cela, cette commande n'a aucun autre effet. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin), et renverra TCL_ERROR si un de ces canaux lui est passé.

Le code non associé à un interpréteur Tcl peut appeler Tcl_DetachChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. Si c'est le cas, il renvoie 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou valides autrement.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lorsque Tcl_Close est appelé. Les sorties tamponnées sont vidées vers le périphérique de sortie du canal avant la destruction du canal, et toute entrée tamponnée est rejetée. S'il s'agit d'un canal bloquant, l'appel ne renvoie pas tant que toutes les données tamponnées n'ont pas été envoyées avec succès au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a une sortie tamponnée qui ne peut pas être écrite sans bloquer, l'appel renvoie immédiatement ; la sortie est vidée en arrière-plan et le canal sera fermé une fois que toutes les données tamponnées auront été sorties. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close renvoie TCL_OK. Si une erreur survient, Tcl_Close renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur survient lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré à l'aide de Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a jamais été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez plutôt utiliser Tcl_UnregisterChannel, qui appellera Tcl_Close en interne lorsque tous les appels à Tcl_RegisterChannel auront été équilibrés par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, convertit les octets en UTF-8 en se basant sur l'encodage du canal et stocke les données produites dans la représentation chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur survient pendant la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Définir cha

TCL_READCHARS, TCL_READOBJ, TCL_READ, ET TCL_READRAW

Tcl_ReadChars lit des caractères du canal channel dans l'objet Tcl readObjPtr. Le nombre maximal de caractères à lire est spécifié par charsToRead. Si charsToRead est négatif, le canal sera lu en mode non bloquant, c'est-à-dire que tous les caractères actuellement disponibles seront lus sans attente.

La valeur de retour peut être inférieure à la valeur demandée, indiquant que moins de données que demandé étaient disponibles. C'est ce qu'on appelle une lecture courte. En mode bloquant, cela ne peut se produire qu'à la fin du fichier. En mode non bloquant, une lecture courte peut aussi se produire s'il n'y a pas assez d'entrées actuellement disponibles : Tcl_ReadChars renvoie un décompte court plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour savoir quelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les différentes représentations de fin de ligne en la représentation interne canonique \n selon le mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les différents modes spécifiques à la plateforme sont décrits dans l'entrée de manuel de la commande Tcl fconfigure.

Par optimisation des performances, lors de la lecture d'un canal avec le codage binary, les octets ne sont pas convertis en UTF-8 lors de leur lecture. Ils sont plutôt stockés dans la représentation interne de readObjPtr comme une valeur de tableau d'octets. La représentation de chaîne de cette valeur ne sera construite que si elle est nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette manière, les données orientées octets peuvent être lues d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans la dépense de conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'il ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour des raisons de compatibilité ascendante avec les extensions Tcl non internationalisées. Il consomme des octets du channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par un caractère nul. Son contenu est valide à partir de la position zéro jusqu'à, mais sans inclure, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas l'empilement. Alors que Tcl_Read (et les autres fonctions de l'API) obtient toujours ses données du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_ReadRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer des données du canal inférieur vers la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, convertissant les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée ait été vue. Si l'encodage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception des caractères de fin de ligne terminaux, sont ajoutés à la représentation de chaîne de lineObjPtr. Les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_GetsObj renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj renvoie également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est renvoyé, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité de l'entrée.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique donnée par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, soit à la tête, soit à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur des données à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si le channel a un indicateur EOF "collant" défini, aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets renvoie inputLen ou -1 si une erreur se produit.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données caractères à charBuf. Les caractères UTF-8 du tampon sont convertis dans l'encodage du canal et mis en file d'attente pour sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par un caractère nul et il envoie tout jusqu'au caractère nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal à none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un décompte du nombre d'octets qui ont été acceptés pour la sortie vers le canal. Il s'agit soit d'un nombre supérieur à zéro pour indiquer le succès, soit de -1 pour indiquer qu'une erreur s'est produite. Si une erreur se produit, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme selon l'option -translation pour le canal. Ceci est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'il accepte une valeur Tcl dont le contenu sera envoyé au canal. Les caractères UTF-8 de la représentation de chaîne de writeObjPtr sont convertis dans l'encodage du canal et mis en file d'attente pour sortie vers channel. Par optimisation des performances, lors de l'écriture dans un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets dans la représentation interne de writeObjPtr en tant que valeur de tableau d'octets sont écrits dans le canal. La représentation de tableau d'octets de la valeur sera construite si nécessaire. De cette manière, les données orientées octets peuvent être lues d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans la dépense de conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'il ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour des raisons de compatibilité ascendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par un caractère nul et il envoie tout jusqu'au caractère nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) envoie toujours son entrée au canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer des données de la transformation vers le canal inférieur.

TCL_FLUSH

Tcl_Flush provoque l'écriture de toutes les données de sortie en mémoire tampon pour channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne revient que lorsque toutes les données mises en mémoire tampon ont été envoyées au canal ou qu'une erreur s'est produite. L'appel revient immédiatement si le canal est non bloquant ; il démarre une opération de vidage en arrière-plan qui écrira les données mises en mémoire tampon vers le canal éventuellement, aussi rapidement que le canal est capable de les absorber.

La valeur de retour est normalement TCL_OK. Si une erreur se produit, Tcl_Flush renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données ultérieures seront lues ou écrites. La sortie mise en mémoire tampon est vidée vers le canal et l'entrée mise en mémoire tampon est ignorée, avant l'opération de recherche.

Tcl_Seek renvoie normalement le nouveau point d'accès. Si une erreur se produit, Tcl_Seek renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut ou peut ne pas avoir été déplacé.

TCL_TELL

Tcl_Tell renvoie le point d'accès actuel pour un canal. La valeur renvoyée est -1 si le canal ne prend pas en charge la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent de channel à une longueur donnée de length octets. Il renvoie TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, il s'agit du nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue.

, en utilisant une série d'appels à Tcl_DStringAppendElement. Les diverses options préexistantes et leurs valeurs possibles sont décrites dans l'entrée de manuel de la commande Tcl fconfigure. D'autres options peuvent être ajoutées par chaque type de canal. Ces options spécifiques au type de canal sont décrites dans l'entrée de manuel de la commande Tcl qui crée un canal de ce type ; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans l'entrée de manuel de la commande Tcl socket. La procédure renvoie normalement TCL_OK. Si une erreur se produit, elle renvoie TCL_ERROR et appelle Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit une nouvelle valeur newValue pour une option optionName sur le channel. La procédure renvoie normalement TCL_OK. Si une erreur se produit, elle renvoie TCL_ERROR ; en outre, si interp est différent de NULL, Tcl_SetChannelOption laisse un message d'erreur dans le résultat de l'interpréteur.

TCL_EOF

Tcl_Eof renvoie une valeur non nulle si channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked renvoie une valeur non nulle si channel est en mode non bloquant et que la dernière opération d'entrée a renvoyé moins de données que demandé parce qu'il n'y avait pas suffisamment de données disponibles. L'appel renvoie toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered renvoie le nombre d'octets d'entrée actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en lecture, cette fonction renvoie toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered renvoie le nombre d'octets de sortie actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en écriture, cette fonction renvoie toujours zéro.

PROBLÈMES DE PLATEFORME

Les descripteurs renvoyés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que renvoyé par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel, ou Tcl_MakeFileChannel. D'autres types de canaux peuvent renvoyer un type de descripteur différent sur les plateformes Windows.
