Tcl_RegExpMatch, Tcl_RegExpCompile, Tcl_RegExpExec, Tcl_RegExpRange, Tcl_GetRegExpFromObj, Tcl_RegExpMatchObj, Tcl_RegExpExecObj, Tcl_RegExpGetInfo - Correspondance de motifs avec des expressions régulières

SYNOPIS

#include <tcl.h>

int
Tcl_RegExpMatchObj(interp, textObj, patObj)

int
Tcl_RegExpMatch(interp, text, pattern)

Tcl_RegExp
Tcl_RegExpCompile(interp, pattern)

int
Tcl_RegExpExec(interp, regexp, text, start)

void
Tcl_RegExpRange(regexp, index, startPtr, endPtr)

Tcl_RegExp
Tcl_GetRegExpFromObj(interp, patObj, cflags)

int
Tcl_RegExpExecObj(interp, regexp, textObj, offset, nmatches, eflags)

void
Tcl_RegExpGetInfo(regexp, infoPtr)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur Tcl à utiliser pour signaler les erreurs. L'interpréteur peut être NULL si aucun rapport d'erreur n'est souhaité.
Tcl_Obj *textObj (entrée/sortie)
Fait référence à la valeur à partir de laquelle obtenir le texte à rechercher. La représentation interne de la valeur peut être convertie dans une forme qui peut être efficacement recherchée.
Tcl_Obj *patObj (entrée/sortie)
Fait référence à la valeur à partir de laquelle obtenir une expression régulière. L'expression régulière compilée est mise en cache dans la valeur.
const char *text (entrée)
Texte dans lequel rechercher une correspondance avec une expression régulière.
const char *pattern (entrée)
Chaîne sous la forme d'un motif d'expression régulière.
Tcl_RegExp regexp (entrée)
Expression régulière compilée. Doit avoir été retournée précédemment par Tcl_GetRegExpFromObj ou Tcl_RegExpCompile.
const char *start (entrée)
Si text n'est qu'une partie d'une autre chaîne, cet argument identifie le début de la chaîne plus grande. S'il n'est pas le même que text, alors aucun motif «“^”» ne sera autorisé.
int index (entrée)
Spécifie quelle plage est souhaitée : 0 signifie la plage de la correspondance entière, 1 ou plus signifie la plage qui correspondait à une sous-expression entre parenthèses.
const char **startPtr (sortie)
L'adresse du premier caractère de la plage est stockée ici, ou NULL s'il n'y a pas de telle plage.
const char **endPtr (sortie)
L'adresse du caractère juste après le dernier caractère de la plage est stockée ici, ou NULL s'il n'y a pas de telle plage.
int cflags (entrée)
Combinaison OU des indicateurs de compilation TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, TCL_REG_EXPANDED, TCL_REG_QUOTE, TCL_REG_NOCASE, TCL_REG_NEWLINE, TCL_REG_NLSTOP, TCL_REG_NLANCH, TCL_REG_NOSUB, et TCL_REG_CANMATCH. Voir ci-dessous pour plus d'informations.
int offset (entrée)
Le décalage de caractère dans le texte où la correspondance doit commencer. La valeur du décalage n'a aucun impact sur les correspondances ^. Ce comportement est contrôlé par eflags.
int nmatches (entrée)
Le nombre de sous-expressions correspondantes qui doivent être mémorisées pour une utilisation ultérieure. Si cette valeur est 0, alors aucune information de correspondance de sous-expression ne sera calculée. Si la valeur est -1, alors toutes les sous-expressions correspondantes seront mémorisées. Toute autre valeur sera considérée comme le nombre maximum de sous-expressions à mémoriser.
int eflags (entrée)
Combinaison OU des indicateurs d'exécution TCL_REG_NOTBOL et TCL_REG_NOTEOL. Voir ci-dessous pour plus d'informations.
Tcl_RegExpInfo *infoPtr (sortie)
L'adresse de l'emplacement où les informations sur une correspondance précédente doivent être stockées par Tcl_RegExpGetInfo.

DESCRIPTION

Tcl_RegExpMatch détermine si son argument pattern correspond à regexp, où regexp est interprété comme une expression régulière selon les règles de la page de référence re_syntax. S'il y a une correspondance, Tcl_RegExpMatch renvoie 1. S'il n'y a pas de correspondance, Tcl_RegExpMatch renvoie 0. Si une erreur se produit dans le processus de correspondance (par exemple, pattern n'est pas une expression régulière valide), Tcl_RegExpMatch renvoie -1 et laisse un message d'erreur dans le résultat de l'interpréteur. Tcl_RegExpMatchObj est similaire à Tcl_RegExpMatch sauf qu'elle opère sur les valeurs Tcl textObj et patObj au lieu des chaînes UTF. Tcl_RegExpMatchObj est généralement plus efficace que Tcl_RegExpMatch, c'est donc l'interface préférée.

Tcl_RegExpCompile, Tcl_RegExpExec, et Tcl_RegExpRange fournissent un accès de plus bas niveau au moteur de correspondance de motifs d'expression régulière. Tcl_RegExpCompile compile une chaîne d'expression régulière dans la forme interne utilisée pour une correspondance de motifs efficace. La valeur de retour est un jeton pour cette forme compilée, qui peut être utilisée dans des appels ultérieurs à Tcl_RegExpExec ou Tcl_RegExpRange. Si une erreur se produit lors de la compilation de l'expression régulière, Tcl_RegExpCompile renvoie NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Remarque : la valeur de retour de Tcl_RegExpCompile n'est valide que jusqu'au prochain appel à Tcl_RegExpCompile ; il n'est pas sûr de conserver ces valeurs pendant de longues périodes.

Tcl_RegExpExec exécute le moteur de correspondance de motifs d'expression régulière. Il renvoie 1 si text contient une plage de caractères qui correspond à regexp, 0 s'il n'y a pas de correspondance, et -1 si une erreur se produit. En cas d'erreur, Tcl_RegExpExec laisse un message d'erreur dans le résultat de l'interpréteur. Lors de la recherche d'une chaîne pour plusieurs correspondances d'un motif, il est important de faire la distinction entre le début de la chaîne d'origine et le début de la recherche en cours. Par exemple, lors de la recherche de la deuxième occurrence d'une correspondance, l'argument text peut pointer vers le caractère juste après la première correspondance ; cependant, il est important que le moteur de motif sache qu'il ne s'agit pas du début de la chaîne entière, de sorte qu'il n'autorise pas les atomes «“^”» dans le motif à correspondre. L'argument start fournit cette information en pointant vers le début de la chaîne globale contenant text. Start sera inférieur ou égal à text ; s'il est inférieur à text, alors aucune correspondance ^ ne sera autorisée.

Tcl_RegExpRange peut être appelé après que Tcl_RegExpExec ait renvoyé ; il fournit des informations détaillées sur les plages de la chaîne qui correspondent à quelles parties du motif. Tcl_RegExpRange renvoie une paire de pointeurs dans *startPtr et *endPtr qui identifient une plage de caractères dans la chaîne source pour l'appel le plus récent à Tcl_RegExpExec. Index indique quelle plage parmi plusieurs est souhaitée : si index est 0, les informations sont renvoyées sur la plage globale de caractères qui correspondait au motif entier ; sinon, les informations sont renvoyées sur la plage de caractères qui correspondait à la index-ième sous-expression entre parenthèses dans le motif. S'il n'y a pas de plage correspondant à index, alors NULL est stocké dans *startPtr et *endPtr.

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj, et Tcl_RegExpGetInfo sont des interfaces de valeur qui fournissent le contrôle le plus direct de la bibliothèque d'expressions régulières de Henry Spencer. Pour les utilisateurs qui ont besoin de modifier directement les options de compilation et d'exécution, il est recommandé d'utiliser ces interfaces plutôt que d'appeler les fonctions internes d'expressions régulières. Ces interfaces gèrent les détails des traductions UTF vers Unicode ainsi que l'amélioration des performances grâce à la mise en cache dans les valeurs de motif et de chaîne.

Tcl_GetRegExpFromObj tente de renvoyer une expression régulière compilée à partir de patObj. Si la valeur ne contient pas déjà une expression régulière compilée, elle tentera d'en créer une à partir de la chaîne dans la valeur et de l'assigner à la représentation interne de patObj. La valeur de retour de cette fonction est de type Tcl_RegExp. La valeur de retour est un jeton pour cette forme compilée, qui peut être utilisée dans des appels ultérieurs à Tcl_RegExpExecObj ou Tcl_RegExpGetInfo. Si une erreur se produit lors de la compilation de l'expression régulière, Tcl_GetRegExpFromObj renvoie NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Le jeton d'expression régulière peut être utilisé tant que la représentation interne de patObj fait référence à la forme compilée. L'argument cflags est un OU binaire de zéro ou plusieurs des indicateurs suivants qui contrôlent la compilation de patObj :

NAME

Tcl_RegExpCompile, Tcl_RegExpExecObj, Tcl_RegExpGetInfo, Tcl_RegExpIndices, Tcl_RegExpInfo - compile and execute regular expressions

SYNOPSIS

#include <tcl.h>
Tcl_RegExp CompileTcl_RegExpCompile(interp, pattern, flags)
Tcl_RegExp CompileTcl_RegExpExecObj(interp, regexp, objPtr,
        nmatches, offset, eflags)
int
Tcl_RegExpGetInfo(interp, regexp, infoPtr)
Tcl_RegExpIndices *
Tcl_RegExpIndices(nsubs, matches)
long
Tcl_RegExpInfo(nsubs, matches, extendStart)

ARGUMENTS

Tcl_Interp *interp
Interpreter to use for error reporting.
const char *pattern
Regular expression pattern string.
int flags
Bit-wise OR of zero or more of the following flags, plus at most one of TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, or TCL_REG_QUOTE. See below.
Tcl_Obj *objPtr
The string to match against.
int nmatches
Number of subexpressions to record match information for.
long offset
Unicode character offset to start matching from.
int eflags
Bit-wise OR of zero or more of the following flags. See below.
Tcl_RegExp regexp
Opaque handle returned by Tcl_RegExpCompile.
Tcl_RegExpInfo *infoPtr
Pointer to a structure to fill with match information.

DESCRIPTION

The function Tcl_RegExpCompile compiles the regular expression specified by pattern. The flags argument is a bit-wise OR of zero or more of the flags described below, plus exactly one of the flags TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, or TCL_REG_QUOTE. The function returns an opaque handle that can be used in subsequent calls to Tcl_RegExpExecObj and Tcl_RegExpGetInfo. If an error occurs during compilation, the handle is NULL and an error message is left in the interpreter result. The compiled regular expression should be freed when no longer needed by calling Tcl_RegExpFree.

TCL_REG_ADVANCED
Compile advanced regular expressions (“ARE”s). This mode corresponds to the normal regular expression syntax accepted by the Tcl regexp and regsub commands.
TCL_REG_EXTENDED
Compile extended regular expressions (“ERE”s). This mode corresponds to the regular expression syntax recognized by Tcl 8.0 and earlier versions.
TCL_REG_BASIC
Compile basic regular expressions (“BRE”s). This mode corresponds to the regular expression syntax recognized by common Unix utilities like sed and grep. This is the default if no flags are specified.
TCL_REG_EXPANDED
Compile the regular expression (basic, extended, or advanced) using an expanded syntax that allows comments and whitespace. This mode causes non-backslashed non-bracket-expression white space and #-to-end-of-line comments to be ignored.
TCL_REG_QUOTE
Compile a literal string, with all characters treated as ordinary characters.
TCL_REG_NOCASE
Compile for matching that ignores upper/lower case distinctions.
TCL_REG_NEWLINE
Compile for newline-sensitive matching. By default, newline is a completely ordinary character with no special meaning in either regular expressions or strings. With this flag, “[^” bracket expressions and “.” never match newline, “^” matches an empty string after any newline in addition to its normal function, and “$ ” matches an empty string before any newline in addition to its normal function. REG_NEWLINE is the bit-wise OR of REG_NLSTOP and REG_NLANCH.
TCL_REG_NLSTOP
Compile for partial newline-sensitive matching, with the behavior of “[^” bracket expressions and “.” affected, but not the behavior of “^” and “$ ”. In this mode, “[^” bracket expressions and “.” never match newline.
TCL_REG_NLANCH
Compile for inverse partial newline-sensitive matching, with the behavior of “^” and “$ ” (the “anchors”) affected, but not the behavior of “[^” bracket expressions and “.”. In this mode “^” matches an empty string after any newline in addition to its normal function, and “$ ” matches an empty string before any newline in addition to its normal function.
TCL_REG_NOSUB
Compile for matching that reports only success or failure, not what was matched. This reduces compile overhead and may improve performance. Subsequent calls to Tcl_RegExpGetInfo or Tcl_RegExpRange will not report any match information.
TCL_REG_CANMATCH
Compile for matching that reports the potential to complete a partial match given more text (see below).

Only one of TCL_REG_EXTENDED, TCL_REG_ADVANCED, TCL_REG_BASIC, and TCL_REG_QUOTE may be specified.

Tcl_RegExpExecObj executes the regular expression pattern matcher. It returns 1 if objPtr contains a range of characters that match regexp, 0 if no match is found, and -1 if an error occurs. In the case of an error, Tcl_RegExpExecObj leaves an error message in the interpreter result. The nmatches value indicates to the matcher how many subexpressions are of interest. If nmatches is 0, then no subexpression match information is recorded, which may allow the matcher to make various optimizations. If the value is -1, then all of the subexpressions in the pattern are remembered. If the value is a positive integer, then only that number of subexpressions will be remembered. Matching begins at the specified Unicode character index given by offset. Unlike Tcl_RegExpExec, the behavior of anchors is not affected by the offset value. Instead the behavior of the anchors is explicitly controlled by the eflags argument, which is a bit-wise OR of zero or more of the following flags:

TCL_REG_NOTBOL
The starting character will not be treated as the beginning of a line or the beginning of the string, so “^” will not match there. Note that this flag has no effect on how “\A” matches.
TCL_REG_NOTEOL
The last character in the string will not be treated as the end of a line or the end of the string, so “$ ” will not match there. Note that this flag has no effect on how “\Z” matches.

Tcl_RegExpGetInfo retrieves information about the last match performed with a given regular expression regexp. The infoPtr argument contains a pointer to a structure that is defined as follows:

typedef struct Tcl_RegExpInfo {
    int nsubs;
    Tcl_RegExpIndices *matches;
    long extendStart;
} Tcl_RegExpInfo;

The nsubs field contains a count of the number of parenthesized subexpressions within the regular expression. If the TCL_REG_NOSUB was used, then this value will be zero. The matches field points to an array of nsubs+1 values that indicate the bounds of each subexpression matched. The first element in the array refers to the range matched by the entire regular expression, and subsequent elements refer to the parenthesized subexpressions in the order that they appear in the pattern. Each element is a structure that is defined as follows:

typedef struct Tcl_RegExpIndices {
    long start;
    long end;
} Tcl_RegExpIndices;

The start and end values are Unicode character indices relative to the offset location within objPtr where matching began. The start index identifies the first character of the matched subexpression. The end index identifies the first character after the matched subexpression. If the subexpression matched the empty string, then start and end will be equal. If the subexpression did not participate in the match, then start and end will be set to -1.

The extendStart field in Tcl_RegExpInfo is only set if the TCL_REG_CANMATCH flag was used. It indicates the first character in the string where a match could occur. If a match was found, this will be the same as the beginning of the current match. If no match was found, then it indicates the earliest point at which a match might occur if additional text is appended to the string. If it is no match is possible even with further text, this field will be set to -1.
