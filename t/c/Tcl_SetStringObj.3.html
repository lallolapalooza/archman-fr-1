ARGUMENTS

const char *bytes (in)
Pointe vers le premier octet d'un tableau d'octets UTF-8 utilisé pour définir ou ajouter une valeur de chaîne. Ce tableau d'octets peut contenir des caractères nuls incorporés, sauf si numChars est négatif. (Les applications qui ont besoin de caractères nuls doivent les représenter sous forme de séquence de deux octets \300\200, utiliser Tcl_ExternalToUtf pour convertir, ou utiliser Tcl_NewByteArrayObj si la chaîne est une collection d'octets non interprétés.)

Le nombre d'octets à copier de bytes lors de l'initialisation, de la définition ou de l'ajout d'une valeur de chaîne. S'il est négatif, tous les octets jusqu'au premier caractère nul sont utilisés.

DESCRIPTION

Les procédures décrites dans ce manuel permettent de manipuler des valeurs Tcl sous forme de valeurs de chaîne. Elles utilisent la représentation interne de la valeur pour stocker des informations supplémentaires, ce qui rend les opérations de manipulation de chaînes plus efficaces. En particulier, les procédures optimisent les opérations d'ajout en allouant de l'espace supplémentaire pour la chaîne, évitant ainsi des copies répétées pour chaque ajout. De plus, les opérations d'indexation et de longueur sont optimisées car la représentation Unicode de la chaîne est calculée et mise en cache si nécessaire. Lorsque vous utilisez les procédures de la famille Tcl_Append* où le résultat de l'interpréteur est la valeur à ajouter, il est important d'appeler d'abord Tcl_ResetResult pour vous assurer que vous n'ajoutez pas accidentellement des données existantes à la valeur de résultat.

Tcl_NewStringObj et Tcl_SetStringObj créent une nouvelle valeur ou modifient une valeur existante pour stocker une copie de la chaîne fournie par bytes et length. Tcl_NewUnicodeObj et Tcl_SetUnicodeObj créent une nouvelle valeur ou modifient une valeur existante pour stocker une copie de la chaîne Unicode fournie par unicode et numChars. Tcl_NewStringObj et Tcl_NewUnicodeObj retournent un pointeur vers une nouvelle valeur avec un compteur de références de zéro. Les quatre procédures définissent la valeur pour stocker une copie de la chaîne spécifiée. Tcl_SetStringObj et Tcl_SetUnicodeObj libèrent toute ancienne représentation de chaîne et interne de la valeur.

Tcl_GetStringFromObj et Tcl_GetString retournent la représentation sous forme de chaîne d'une valeur. Celle-ci est donnée par le pointeur d'octet retourné et (pour Tcl_GetStringFromObj) la longueur, qui est stockée dans lengthPtr si celui-ci n'est pas NULL. Si la représentation UTF de la chaîne de la valeur est invalide (son pointeur d'octet est NULL), la représentation de chaîne est régénérée à partir de la représentation interne de la valeur. La mémoire référencée par le pointeur d'octet retourné appartient au gestionnaire de valeurs. Elle est retournée en tant que pointeur modifiable, permettant aux auteurs de types Tcl_ObjType de modifier la représentation de chaîne dans le Tcl_UpdateStringProc de leur Tcl_ObjType. Sauf pour ce but limité, le pointeur retourné par Tcl_GetStringFromObj ou Tcl_GetString doit être traité comme en lecture seule. Il est recommandé d'assigner ce pointeur à une variable de type const char *, même dans les situations limitées où l'écriture sur ce pointeur est acceptée, les principes de copie en écriture de Tcl_Obj doivent être respectés, en utilisant les appels appropriés à Tcl_IsShared et Tcl_DuplicateObj avant toute modification de la représentation de chaîne. La procédure Tcl_GetString est utilisée dans la situation courante où l'appelant n'a pas besoin de la longueur de la représentation de chaîne.

Tcl_GetUnicodeFromObj et Tcl_GetUnicode retournent la valeur d'une valeur sous forme de chaîne Unicode. Celle-ci est donnée par le pointeur retourné et (pour Tcl_GetUnicodeFromObj) la longueur, qui est stockée dans lengthPtr si celui-ci n'est pas NULL. La mémoire référencée par le pointeur d'octet retourné appartient au gestionnaire de valeurs et ne doit pas être modifiée par l'appelant. La procédure Tcl_GetUnicode est utilisée dans la situation courante où l'appelant n'a pas besoin de la longueur de la représentation de chaîne Unicode.

Tcl_GetUniChar retourne le index-ième caractère dans la représentation Unicode de la valeur. L'index est supposé être dans la plage valide.

Tcl_GetRange retourne une nouvelle valeur composée des caractères entre first et last (inclus) dans la représentation Unicode de la valeur. Si la représentation Unicode de la valeur est invalide, la représentation Unicode de la valeur est régénérée à partir de la représentation de chaîne de la valeur. Si first < 0, la chaîne retournée commence au début de la valeur. Si last < 0, la chaîne retournée se termine à la fin de la valeur.

Package `vim-lsp-settings`

Configuration des paramètres de LSP pour Vim

Description du package

Ce package fournit un moyen simple de configurer les paramètres pour les serveurs de langage (LSP) utilisés avec le plugin vim-lsp (ou d'autres plugins LSP compatibles). Il permet de définir des options spécifiques pour chaque serveur de langage, telles que les chemins d'accès aux exécutables, les arguments de ligne de commande, les gestionnaires de formatage, et plus encore.

L'objectif est de centraliser et de simplifier la gestion de ces configurations, permettant aux utilisateurs de personnaliser leur expérience LSP sans avoir à modifier directement des fichiers de configuration complexes.

Utilisation

Une fois le package installé, vous pouvez configurer vos serveurs LSP en créant ou en modifiant le fichier de configuration spécifié par le plugin vim-lsp (généralement dans votre ~/.vim/lsp_settings.json ou ~/.config/nvim/lsp_settings.json pour Neovim).

Le format de ce fichier de configuration est généralement JSON et ressemble à ceci : 

{
  "languages": {
    "python": {
      "command": ["pylsp"],
      "settings": {
        "pylsp": {
          "plugins": {
            "pylint": {
              "enabled": true,
              "args": ["--rcfile=.pylintrc"]
            },
            "flake8": {
              "enabled": true
            }
          }
        }
      },
      "root_pattern": ["pyproject.toml", ".git", "setup.py"]
    },
    "javascript": {
      "command": ["typescript-language-server"],
      "args": ["--stdio"],
      "settings": {
        "tsserver": {
          "npmPath": "/usr/share/npm",
          "useWorkspaceTsdk": true
        }
      },
      "root_pattern": ["package.json", ".git"]
    }
    // ... autres configurations de langages
  }
}

Vous pouvez trouver des exemples détaillés et la documentation complète dans le dépôt du projet (lien ci-dessous).
