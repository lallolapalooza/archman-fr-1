DESCRIPTION

Ces fonctions sont destinées à accéder à la fonctionnalité de multiples interpréteurs Tcl depuis des programmes C. Elles permettent de gérer de multiples interpréteurs dans une relation hiérarchique et la gestion des alias, des commandes qui, lorsqu'elles sont invoquées dans un interpréteur, exécutent une commande dans un autre interpréteur. La valeur retournée par les fonctions qui retournent un int est TCL_OK ou TCL_ERROR. Si TCL_ERROR est retourné, alors le résultat de l'interpréteur contient un message d'erreur.

Tcl_CreateSlave crée un nouvel interpréteur en tant qu'enfant de interp. Elle crée également une commande enfant nommée childName dans interp, ce qui permet à interp de manipuler le nouvel enfant. Si isSafe est zéro, la commande crée un enfant fiable dans lequel le code Tcl a accès à toutes les commandes Tcl. Si c'est 1, la commande crée un enfant "sûr" dans lequel le code Tcl a accès uniquement à un ensemble de commandes Tcl définies comme "Safe Tcl" ; voir l'entrée du manuel pour la commande Tcl_interp pour plus de détails. Si la création du nouvel interpréteur enfant échoue, NULL est retourné.

Tcl_CreateChild est un synonyme de Tcl_CreateSlave.

Tcl_IsSafe retourne 1 si interp est "sûr" (créé avec le drapeau TCL_SAFE_INTERPRETER spécifié), 0 sinon.

Tcl_MakeSafe marque interp comme "sûr", de sorte que les futurs appels à Tcl_IsSafe retourneront 1. Elle supprime également de interp toute fonctionnalité connue qui pourrait être potentiellement dangereuse (commandes et variables). Cependant, elle ne peut pas savoir quelles parties d'une extension ou d'une application sont sûres et n'essaie pas de les supprimer, donc la sécurité n'est pas garantie après l'appel à Tcl_MakeSafe. Les utilisateurs doivent être prudents quant à l'utilisation de Tcl_MakeSafe pour éviter de fausses affirmations de sécurité. Pour de nombreux cas, Tcl_CreateSlave peut être un meilleur choix, car elle crée des interpréteurs dans un état sûr connu.

Tcl_GetSlave retourne un pointeur vers un interpréteur enfant de interp. L'interpréteur enfant est identifié par childName. Si un tel enfant n'existe pas, NULL est retourné.

Tcl_GetChild est un synonyme de Tcl_GetSlave.

Tcl_GetMaster retourne un pointeur vers l'interpréteur maître de interp. Si interp n'a pas de maître (c'est-à-dire, c'est un interpréteur de niveau supérieur), NULL est retourné.

Tcl_GetParent est un synonyme de Tcl_GetMaster.

Tcl_GetInterpPath stocke dans le résultat de interp le chemin relatif entre interp et childInterp; childInterp doit être un enfant de interp. Si le calcul du chemin relatif réussit, TCL_OK est retourné, sinon TCL_ERROR est retourné et un message d'erreur est stocké dans le résultat de interp.

Tcl_CreateAlias crée une commande nommée childCmd dans childInterp qui, lorsqu'elle est invoquée, provoquera l'exécution de la commande targetCmd dans targetInterp. Les arguments spécifiés par les chaînes de caractères dans argv sont toujours ajoutés à l'ensemble des arguments fournis lors de l'invocation de childCmd et sont passés à targetCmd. Cette opération retourne TCL_OK si elle réussit, ou TCL_ERROR en cas d'échec ; dans ce cas, un message d'erreur est laissé dans la valeur résultat de childInterp. Remarque : il n'y a pas de restriction sur la relation ancestrale (créée par Tcl_CreateSlave) entre childInterp et targetInterp. Deux interpréteurs quelconques peuvent être utilisés sans restriction sur la manière dont ils sont liés.

Tcl_CreateAliasObj est similaire à Tcl_CreateAlias sauf qu'elle prend un tableau de valeurs à passer en tant qu'arguments supplémentaires au lieu d'un tableau de chaînes de caractères.

Tcl_GetAliasObj retourne des informations sous forme de pointeur vers un tableau de structures Tcl_Obj sur un alias aliasName dans interp. Chacun des champs de résultat peut être NULL, auquel cas la donnée correspondante n'est pas retournée. Si un champ de résultat n'est pas NULL, le pointeur spécifié est défini à la donnée correspondante. Par exemple, si targetCmdPtr n'est pas NULL, il est défini à un pointeur vers la chaîne contenant le nom de la commande cible.

Tcl_GetAlias est similaire à Tcl_GetAliasObj sauf qu'elle retourne un pointeur vers un tableau de chaînes de caractères au lieu d'un tableau de structures Tcl_Obj. Tcl_GetAlias est obsolète

ARGUMENTS

Tcl_Interp *interp
Interpréteur Tcl.
Tcl_Interp *master
Le nouvel interpréteur maître.
const char *slaveName
Le nom de l'esclave à créer ou à trouver.
int setSynch
Si vrai, l'esclave est configuré pour fonctionner en mode synchrone.
Tcl_Interp *masterInterp
L'interpréteur maître.

DESCRIPTION

Ces procédures gèrent le mécanisme des interpréteurs maîtres et esclaves de Tcl. Un interpréteur peut avoir un seul interpréteur maître, mais un interpréteur maître peut avoir plusieurs interpréteurs esclaves. Le mécanisme est utilisé pour créer des hiérarchies d'interpréteurs et pour contrôler l'exécution de scripts dans différents interpréteurs.

Tcl_GetMaster renvoie un pointeur vers l'interpréteur maître de l'interpréteur donné, ou NULL s'il n'y a pas de maître.

Tcl_SetMaster configure le nouvel interpréteur maître pour l'interpréteur donné. L'interpréteur donné devient alors un esclave du nouveau maître. La fonction renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'échec (par exemple, si l'interpréteur a déjà un maître ou s'il tente de s'établir comme maître de lui-même).

Tcl_BecomeMaster fait de l'interpréteur donné le maître de tous les interpréteurs qui étaient auparavant ses maîtres. Cela peut avoir des effets secondaires imprévus si d'autres interpréteurs sont des esclaves de l'interpréteur donné. La fonction renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

Tcl_DissociateSubInterp supprime la relation maître-esclave de l'interpréteur donné et de son maître. L'interpréteur devient alors un interpréteur autonome. La fonction renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

Tcl_CreateSlave crée un nouvel interpréteur esclave nommé slaveName sous l'autorité de masterInterp. Si setSynch est vrai, l'esclave fonctionnera en mode synchrone, ce qui signifie que les commandes exécutées dans l'esclave seront bloquantes jusqu'à ce qu'elles soient terminées. Sinon, l'esclave fonctionnera en mode asynchrone. La fonction renvoie un pointeur vers le nouvel interpréteur esclave en cas de succès, ou NULL en cas d'échec.

Tcl_GetSlave renvoie un pointeur vers l'interpréteur esclave nommé slaveName sous l'autorité de masterInterp, ou NULL s'il n'existe pas.

Tcl_ForgetSlave supprime l'interpréteur esclave nommé slaveName de l'autorité de masterInterp. La fonction renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

Pour une description de l'interface Tcl pour plusieurs interpréteurs, voir interp(n).
