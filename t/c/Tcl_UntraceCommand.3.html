Tcl_TraceCommand(3) Procédures de la bibliothèque Tcl Tcl_TraceCommand(3)

NOM

Tcl_CommandTraceInfo, Tcl_TraceCommand, Tcl_UntraceCommand - surveiller les renommages et suppressions d'une commande

SYNTAXE

#include <tcl.h>

ClientData
Tcl_CommandTraceInfo(interp, cmdName, flags, proc, prevClientData)

int
Tcl_TraceCommand(interp, cmdName, flags, proc, clientData)

void
Tcl_UntraceCommand(interp, cmdName, flags, proc, clientData)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur contenant la commande.
const char *cmdName (in)
Nom de la commande.
int flags (in)
Collection OR des valeurs TCL_TRACE_RENAME et TCL_TRACE_DELETE.
Tcl_CommandTraceProc *proc (in)
Procédure à appeler lorsque les opérations spécifiées se produisent sur cmdName.
ClientData clientData (in)
Argument arbitraire à passer à proc.
ClientData prevClientData (in)
Si non NULL, donne la dernière valeur retournée par Tcl_CommandTraceInfo, donc cet appel retournera des informations sur le prochain trace. Si NULL, cet appel retournera des informations sur le premier trace.

DESCRIPTION

Tcl_TraceCommand permet à une procédure C de surveiller les opérations effectuées sur une commande Tcl, de sorte que la procédure C soit invoquée chaque fois que la commande est renommée ou supprimée. Si le trace est créé avec succès, Tcl_TraceCommand retourne TCL_OK. Si une erreur s'est produite (par exemple, cmdName spécifie une commande inexistante), TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de l'interpréteur.

L'argument flags de Tcl_TraceCommand indique quand la procédure de trace doit être invoquée. Il consiste en une combinaison OR de toutes les valeurs suivantes:

TCL_TRACE_RENAME
Invoque proc chaque fois que la commande est renommée.
TCL_TRACE_DELETE
Invoque proc lorsque la commande est supprimée.

Chaque fois que l'une des opérations spécifiées est effectuée sur la commande, proc sera invoquée. Elle doit avoir des arguments et un résultat correspondant au type Tcl_CommandTraceProc:

typedef void Tcl_CommandTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *oldName,
        const char *newName,
        int flags);

Les paramètres clientData et interp auront les mêmes valeurs que celles passées à Tcl_TraceCommand lors de la création du trace. ClientData pointe typiquement vers une structure de données spécifique à l'application qui décrit quoi faire lorsque proc est invoquée. OldName donne le nom de la commande en cours de renommage, et newName donne le nouveau nom de la commande (ou NULL lors de la suppression de la commande). Flags est une combinaison OR de bits fournissant potentiellement plusieurs informations. Un des bits TCL_TRACE_RENAME et TCL_TRACE_DELETE sera défini dans flags pour indiquer quelle opération est effectuée sur la commande. Le bit TCL_TRACE_DESTROYED sera défini dans flags si le trace est sur le point d'être détruit ; cette information peut être utile à proc pour qu'elle puisse nettoyer ses propres structures de données internes (voir la section TCL_TRACE_DESTROYED ci-dessous pour plus de détails). Étant donné que la suppression de commandes peut avoir lieu dans le cadre de la suppression de l'interpréteur qui les contient, proc doit être prudent quant à ce qui peut être appelé dans interp. La routine Tcl_InterpDeleted est un outil important à cet égard. Lorsque Tcl_InterpDeleted retourne 1, proc ne sera pas en mesure d'invoquer des scripts dans interp. La fonction de proc dans ce cas est limitée au nettoyage de ses propres structures de données.

Tcl_UntraceCommand peut être utilisé pour supprimer un trace. Si la commande spécifiée par interp, cmdName et flags a un trace défini avec flags, proc et clientData, alors le trace correspondant est supprimé. Si aucun trace de ce type n'existe, alors l'appel à Tcl_UntraceCommand n'a aucun effet. Les mêmes bits sont valides pour flags que pour les appels à Tcl_TraceCommand.

Tcl_CommandTraceInfo peut être utilisé pour récupérer des informations sur les traces définis sur une commande donnée. La valeur de retour de Tcl_CommandTraceInfo est le clientData associé à un trace particulier. Le trace doit être sur la commande spécifiée par les arguments interp, cmdName et flags (notez que les flags sont actuellement ignorés ; flags doit être défini à 0 pour la compatibilité future) et sa procédure de trace doit être la même que l'argument proc. Si l'argument prevClientData est NULL, alors la valeur de retour correspond au premier trace correspondant (le plus récemment créé), ou NULL s'il n'y a pas de traces correspondants. Si l'argument prevClientData n'est pas NULL, alors il doit s'agir de la valeur de retour d'un appel précédent à Tcl_CommandTraceInfo. Dans ce cas, la nouvelle valeur de retour correspondra au prochain trace correspondant après celui dont le clientData correspond à prevClientData, ou NULL si aucun trace ne correspond à prevClientData ou s'il n'y a plus de traces correspondants après celui-ci. Ce mécanisme permet de parcourir tous les traces d'une commande donnée qui ont le même proc.

APPELER DES COMMANDES PENDANT LES TRACES

Lors des traces de renommage, la commande en cours de renommage est visible sous les deux noms simultanément, et la commande existe toujours pendant les traces de suppression, sauf si l'interpréteur qui la contient est en cours de suppression. Cependant, il n'y a aucun mécanisme pour signaler qu'une erreur s'est produite dans une procédure de trace, donc une grande attention doit être apportée pour que les erreurs ne soient pas perdues silencieusement.

MULTIPLES TRACES

Il est possible que plusieurs traces existent sur la même commande. Lorsque cela se produit, toutes les procédures de trace seront invoquées à chaque accès, dans l'ordre du plus récemment créé au moins récemment créé. Les tentatives de suppression de la commande pendant un trace de suppression échoueront silencieusement, car la commande est déjà programmée pour suppression. Si la commande en cours de renommage est renommée par l'un de ses traces de renommage, ce renommage prendra le pas sur celui qui a déclenché le trace et la collection de traces ne sera pas réexécutée ; si plusieurs traces renomment la commande, le dernier renommage prendra le pas.

FLAG TCL_TRACE_DESTROYED

Dans un rappel de suppression à proc, le bit TCL_TRACE_DESTROYED est défini dans flags.
