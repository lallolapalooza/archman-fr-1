Tcl_Interp *interp (en entrée)
Interpréteur à utiliser pour la signalisation d'erreur, ou NULL si aucune signalisation d'erreur n'est souhaitée.
const char *name (en entrée)
Nom de l'encodage à charger.
Tcl_Encoding encoding (en entrée)
L'encodage à interroger, libérer ou utiliser pour convertir du texte. Si encoding est NULL, l'encodage système actuel est utilisé.
Tcl_Obj *objPtr (en entrée)
Nom de l'encodage pour lequel obtenir un jeton.
Tcl_Encoding *encodingPtr (en sortie)
Pointe vers le stockage où le jeton d'encodage doit être écrit.
const char *src (en entrée)
Pour les fonctions Tcl_ExternalToUtf, un tableau d'octets dans l'encodage spécifié qui doit être converti en UTF-8. Pour les fonctions Tcl_UtfToExternal et Tcl_WinUtfToTChar, un tableau de caractères UTF-8 à convertir vers l'encodage spécifié.
const TCHAR *tsrc (en entrée)
Un tableau de caractères Windows TCHAR à convertir en UTF-8.
int srcLen (en entrée)
Longueur de src ou tsrc en octets. Si la longueur est négative, la longueur spécifique à l'encodage de la chaîne est utilisée.
Tcl_DString *dstPtr (en sortie)
Pointeur vers un Tcl_DString non initialisé ou libéré dans lequel le résultat converti sera stocké.
int flags (en entrée)
Divers bits de drapeau combinés par OU. TCL_ENCODING_START signifie que le tampon source est le premier bloc d'un flux d'entrée (potentiellement multi-blocs), indiquant à la routine de conversion de se réinitialiser à un état initial et d'effectuer toute initialisation nécessaire avant la conversion du premier octet. TCL_ENCODING_END signifie que le tampon source est le dernier bloc d'un flux d'entrée (potentiellement multi-blocs), indiquant à la routine de conversion d'effectuer toute finalisation nécessaire après la conversion du dernier octet, puis de se réinitialiser à un état initial. TCL_ENCODING_STOPONERROR signifie que la routine de conversion doit retourner immédiatement lors de la lecture d'un caractère source qui n'existe pas dans l'encodage cible ; sinon, un caractère de repli par défaut sera automatiquement substitué.
Tcl_EncodingState *statePtr (en entrée/sortie)
Utilisé lors de la conversion d'un flux d'octets (généralement long ou de longueur indéfinie) pièce par pièce. La routine de conversion stocke son état actuel dans *statePtr après la conversion de src (le tampon contenant la pièce actuelle) ; ces informations d'état doivent être renvoyées lors de la conversion de la pièce suivante du flux afin que la routine de conversion sache dans quel état elle se trouvait à la fin de la pièce précédente. Peut être NULL, auquel cas la valeur spécifiée pour flags est ignorée et le tampon source est supposé contenir la chaîne complète à convertir.
char *dst (en sortie)
Tampon dans lequel le résultat converti sera stocké. Pas plus de dstLen octets seront stockés dans dst.
int dstLen (en entrée)
La longueur maximale du tampon de sortie dst en octets.
int *srcReadPtr (en sortie)
Rempli avec le nombre d'octets de src qui ont été réellement convertis. Cela peut être inférieur à la longueur source d'origine s'il y a eu un problème lors de la conversion de certains caractères source. Peut être NULL.
int *dstWrotePtr (en sortie)
Rempli avec le nombre d'octets qui ont été réellement stockés dans le tampon de sortie à la suite de la conversion. Peut être NULL.
int *dstCharsPtr (en sortie)
Rempli avec le nombre de caractères correspondant au nombre d'octets stockés dans le tampon de sortie. Peut être NULL.
Tcl_DString *bufPtr (en sortie)
Stockage pour le nom d'encodage système prescrit.
const Tcl_EncodingType *typePtr (en entrée)
Structure qui définit un nouveau type d'encodage.
Tcl_Obj *searchPath (en entrée)
Liste de répertoires du système de fichiers dans lesquels rechercher les fichiers de données d'encodage.
const char *path (en entrée)
Un chemin vers l'emplacement du fichier d'encodage.

INTRODUCTION

Ces routines convertissent entre la représentation interne des caractères de Tcl, UTF-8, et les représentations de caractères utilisées par divers systèmes d'exploitation ou systèmes de fichiers, tels que Unicode, ASCII ou Shift-JIS. Lors de l'opération sur des chaînes, comme l'obtention des noms de fichiers ou l'affichage de caractères à l'aide de polices internationales, les chaînes doivent être traduites dans un ou plusieurs formats que les différents appels système peuvent utiliser. Par exemple, sur un poste de travail Unix japonais, un utilisateur pourrait obtenir un nom de fichier représenté dans l'encodage de fichier EUC-JP, puis traduire les caractères vers l'encodage de police jisx0208 afin d'afficher le nom du fichier dans un widget Tk. Le but du paquet d'encodage est d'aider à combler le fossé de traduction. UTF-8 fournit une base intermédiaire pour tous les différents encodages. Dans l'exemple ci-dessus, le texte serait traduit en UTF-8 à partir de l'encodage de fichier que le système d'exploitation utilise. Ensuite, il serait traduit de UTF-8 vers l'encodage de police requis par les routines d'affichage.

Certains encodages de base sont intégrés à Tcl. D'autres peuvent être définis par l'utilisateur ou chargés dynamiquement à partir de fichiers d'encodage d'une manière indépendante de la plateforme.

DESCRIPTION

Tcl_GetEncoding trouve un encodage en fonction de son nom. Le nom peut faire référence à un encodage Tcl intégré, à un encodage défini par l'utilisateur enregistré en appelant Tcl_CreateEncoding, ou à un fichier d'encodage chargeable dynamiquement. La valeur de retour est un jeton qui représente l'encodage et peut être utilisé dans des appels ultérieurs à des procédures telles que Tcl_GetEncodingName, Tcl_FreeEncoding et Tcl_UtfToExternal. Si le nom ne fait référence à aucun encodage connu ou chargeable, NULL est retourné et un message d'erreur est renvoyé dans interp.

Le paquet d'encodage maintient une base de données de tous les encodages actuellement en cours d'utilisation. La première fois que name est rencontré, Tcl_GetEncoding retourne un encodage avec un compteur de références de 1. Si le même nom est demandé plusieurs fois, le compteur de références pour cet encodage est incrémenté sans les frais généraux d'allocation d'un nouvel encodage et de toutes ses structures de données associées.

Lorsqu'un encoding n'est plus nécessaire, Tcl_FreeEncoding doit être appelé pour le libérer. Lorsqu'un encoding n'est plus utilisé nulle part (c'est-à-dire qu'il a été libéré autant de fois qu'il a été obtenu), Tcl_FreeEncoding libérera tout le stockage utilisé par l'encodage et le supprimera de la base de données.

Tcl_GetEncodingFromObj traite la représentation sous forme de chaîne de objPtr comme un nom d'encodage, et trouve un encodage avec ce nom, tout comme le fait Tcl_GetEncoding. Lorsqu'un encodage est trouvé, il est mis en cache dans la valeur objPtr pour référence future, le jeton Tcl_Encoding est écrit dans le stockage pointe

d par encodingPtr, et la valeur TCL_OK est retournée. Si aucun encodage de ce type n'est trouvé, la valeur TCL_ERROR est retournée, et aucune écriture sur *encodingPtr n'a lieu. Tout comme avec Tcl_GetEncoding, l'appelant doit appeler Tcl_FreeEncoding sur le jeton d'encodage résultant lorsqu'il ne sera plus utilisé.

Tcl_ExternalToUtfDString convertit un tampon source src de l'encoding spécifié en UTF-8. Les octets convertis sont stockés dans dstPtr, qui est ensuite terminé par un caractère nul. L'appelant doit éventuellement appeler Tcl_DStringFree pour libérer toute information stockée dans dstPtr. Lors de la conversion, si l'un des caractères du tampon source ne peut pas être représenté dans l'encodage cible, un caractère de remplacement par défaut sera utilisé. La valeur de retour est un pointeur vers la valeur stockée dans la DString.

Tcl_ExternalToUtf convertit un tampon source src de l'encoding spécifié en UTF-8. Jusqu'à srcLen octets sont convertis depuis le tampon source et jusqu'à dstLen octets convertis sont stockés dans dst. Dans tous les cas, *srcReadPtr est rempli avec le nombre d'octets qui ont été convertis avec succès depuis src et *dstWrotePtr est rempli avec le nombre correspondant d'octets qui ont été stockés dans dst. La valeur de retour est l'une des suivantes :

TCL_OK
Tous les octets de src ont été convertis.
TCL_CONVERT_NOSPACE
Le tampon de destination n'était pas assez grand pour toutes les données converties ; autant de caractères que possible ont été convertis.
TCL_CONVERT_MULTIBYTE
Les derniers octets du tampon source étaient le début d'une séquence multi-octets, mais des octets supplémentaires étaient nécessaires pour compléter cette séquence. Un appel ultérieur à la routine de conversion doit passer un tampon contenant les octets non convertis qui restaient dans src plus quelques octets supplémentaires du flux source pour convertir correctement la séquence multi-octets précédemment divisée.
TCL_CONVERT_SYNTAX
Le tampon source contenait une séquence de caractères invalide. Cela peut se produire si le flux d'entrée a été corrompu ou si la méthode d'encodage d'entrée a été mal identifiée.
TCL_CONVERT_UNKNOWN
Le tampon source contenait un caractère qui ne pouvait pas être représenté dans l'encodage cible et TCL_ENCODING_STOPONERROR a été spécifié.

Tcl_UtfToExternalDString convertit un tampon source src de l'UTF-8 vers l'encoding spécifié. Les octets convertis sont stockés dans dstPtr, qui est ensuite terminé par le caractère nul approprié à l'encodage. L'appelant doit éventuellement appeler Tcl_DStringFree pour libérer toute information stockée dans dstPtr. Lors de la conversion, si l'un des caractères du tampon source ne peut pas être représenté dans l'encodage cible, un caractère de remplacement par défaut sera utilisé. La valeur de retour est un pointeur vers la valeur stockée dans la DString.

Tcl_UtfToExternal convertit un tampon source src de l'UTF-8 vers l'encoding spécifié. Jusqu'à srcLen octets sont convertis depuis le tampon source et jusqu'à dstLen octets convertis sont stockés dans dst. Dans tous les cas, *srcReadPtr est rempli avec le nombre d'octets qui ont été convertis avec succès depuis src et *dstWrotePtr est rempli avec le nombre correspondant d'octets qui ont été stockés dans dst. Les valeurs de retour sont les mêmes que les valeurs de retour pour Tcl_ExternalToUtf.

Tcl_WinUtfToTChar et Tcl_WinTCharToUtf sont des fonctions utilitaires propres à Windows pour convertir entre UTF-8 et les chaînes Windows basées sur le type TCHAR qui est par convention un caractère Unicode sous Windows NT.

Tcl_GetEncodingName est approximativement l'inverse de Tcl_GetEncoding. Étant donné un encoding, la valeur de retour est l'argument name qui a été utilisé pour créer l'encodage. La chaîne retournée par Tcl_GetEncodingName n'est garantie de persister que jusqu'à ce que l'encoding soit supprimé. L'appelant ne doit pas modifier cette chaîne.

Tcl_SetSystemEncoding définit l'encodage par défaut qui doit être utilisé chaque fois que l'utilisateur passe une valeur NULL pour l'argument encoding à l'une des autres fonctions d'encodage. Si name est NULL, l'encodage système est réinitialisé à l'encodage système par défaut, binary. Si le nom ne fait pas référence à un encodage connu ou chargeable, TCL_ERROR est retourné et un message d'erreur est laissé dans interp. Sinon, cette procédure incrémente le compteur de références du nouvel encodage système, décrémente le compteur de références de l'ancien encodage système et retourne TCL_OK.

Tcl_GetEncodingNameFromEnvironment fournit un moyen pour la bibliothèque Tcl de signaler le nom d'encodage qu'elle estime être correct pour une utilisation en tant qu'encodage système, en se basant sur des appels système et l'examen de l'environnement adaptés à la plateforme. Elle accepte bufPtr, un pointeur vers une Tcl_DString non initialisée ou libérée, et y écrit le nom de l'encodage. La valeur Tcl_DStringValue est retournée.

Tcl_GetEncodingNames définit le résultat de l'interp en une liste composée des noms de tous les encodages actuellement définis ou qui peuvent être chargés dynamiquement, en recherchant dans le chemin d'encodage spécifié par Tcl_SetDefaultEncodingDir. Cette procédure ne garantit pas que les fichiers d'encodage chargeables dynamiquement contiennent des données valides, mais simplement qu'ils existent.

Tcl_CreateEncoding définit un nouvel encodage et enregistre les procédures C qui sont appelées en retour pour convertir entre l'encodage et l'UTF-8. Les encodages créés par Tcl_CreateEncoding sont ensuite visibles dans la base de données utilisée par Tcl_GetEncoding. Tout comme avec la procédure Tcl_GetEncoding, la valeur de retour est un jeton qui représente l'encodage et peut être utilisé dans des appels ultérieurs à d'autres fonctions d'encodage. Tcl_CreateEncoding retourne un encodage avec un compteur de références de 1. Si un encodage portant le nom spécifié existe déjà, son entrée dans la base de données est remplacée par le nouvel encodage ; le jeton de l'ancien encodage restera valide et continuera de se comporter comme avant, mais les utilisateurs du nouveau jeton appelleront désormais les nouvelles procédures d'encodage.

L'argument typePtr à Tcl_CreateEncoding contient des informations sur le nom de l'encodage et les procédures qui seront appelées pour convertir entre cet encodage et l'UTF-8. Il est défini comme suit :

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

L'encodingName fournit un nom de chaîne pour l'encodage, par lequel il peut être référencé dans d'autres procédures comme Tcl_GetEncoding. Le toUtfProc fait référence à une procédure de rappel à invoquer pour convertir du texte de cet encodage en UTF-8. Le fromUtfProc fait référence à une procédure de rappel à invoquer pour convertir du texte de l'UTF-8 vers cet encodage. Le freeProc fait référence à une procédure de rappel à invoquer lorsque cet encodage est supprimé. Le champ freeProc peut être NULL. Le clientData contient une valeur arbitraire d'un mot passée aux procédures toUtfProc, fromUtfProc et freeProc chaque fois qu'elles sont appelées. Typiquement, il s'agit d'un pointeur vers une structure de données contenant des informations spécifiques à l'encodage qui peuvent être utilisées par les procédures de rappel. Par exemple, deux encodages très similaires comme ascii et macRoman peuvent utiliser la même procédure de rappel, mais utiliser différentes valeurs de clientData pour contrôler son comportement. Le nullSize spécifie le nombre d'octets nuls qui signifient la fin de la chaîne dans cet encodage. Il doit être de 1 (pour les encodages mono-octet ou multi-octets comme ASCII ou Shift-JIS) ou de 2 (pour les encodages double-octet comme Unicode). Les encodages de taille constante avec 3 octets ou plus par caractère (comme CNS11643) ne sont pas acceptés.

Les procédures de rappel toUtfProc et fromUtfProc doivent correspondre au type Tcl_EncodingConvertProc :

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

Les procédures toUtfProc et fromUtfProc sont appelées par la famille de fonctions Tcl_ExternalToUtf ou Tcl_UtfToExternal pour effectuer la conversion réelle. Le paramètre clientData de ces procédures est le même que le champ clientData spécifié à Tcl_CreateEncoding lors de la création de l'encodage. Les arguments restants aux procédures de rappel sont les mêmes que les arguments, documentés en haut, à Tcl_ExternalToUtf ou Tcl_UtfToExternal, à l'exception suivante. Si l'argument srcLen d'une de ces fonctions de haut niveau est négatif, la valeur passée à la procédure de rappel sera la longueur de chaîne spécifique à l'encodage appropriée de src. Si l'un des arguments srcReadPtr, dstWrotePtr, ou dstCharsPtr d'une des fonctions de haut niveau est NULL, la valeur correspondante passée à la procédure de rappel sera un emplacement non NULL.

La procédure de rappel freeProc, si elle n'est pas NULL, doit correspondre au type Tcl_EncodingFreeProc :

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

Cette fonction freeProc est appelée lorsque l'encodage est supprimé. Le paramètre clientData est le même que le champ clientData spécifié à Tcl_CreateEncoding lors de la création de l'encodage.

Tcl_GetEncodingSearchPath et Tcl_SetEncodingSearchPath sont appelés pour accéder et définir la liste des répertoires du système de fichiers recherchés pour les fichiers de données d'encodage.

La valeur retournée par Tcl_GetEncodingSearchPath est la valeur stockée par le dernier appel réussi à Tcl_SetEncodingSearchPath. Si aucun appel à Tcl_SetEncodingSearchPath n'a eu lieu, Tcl calculera une valeur initiale basée sur l'environnement. Il existe un seul chemin de recherche d'encodage pour l'ensemble du processus, partagé par tous les threads du processus.
