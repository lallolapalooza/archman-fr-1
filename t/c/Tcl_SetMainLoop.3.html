Tcl_Main(3) Procédures de la bibliothèque Tcl Tcl_Main(3)

NOM

Tcl_Main, Tcl_MainEx, Tcl_MainExW, Tcl_SetStartupScript, Tcl_GetStartupScript, Tcl_SetMainLoop - programme principal, script de démarrage et boucle d'événements pour les applications Tcl

SYNOPIS

#include <tcl.h>

Tcl_Main(argc, argv, appInitProc)

Tcl_MainEx(argc, charargv, appInitProc, interp)

Tcl_MainExW(argc, wideargv, appInitProc, interp)

Tcl_SetStartupScript(path, encoding)

Tcl_Obj *
Tcl_GetStartupScript(encodingPtr)

Tcl_SetMainLoop(mainLoopProc)

ARGUMENTS

int argc (in)
Nombre d'éléments dans argv.
char *argv[] (in)
Tableau de chaînes contenant les arguments de la ligne de commande. Sous Windows, lorsque -DUNICODE est utilisé, le type du paramètre change en wchar_t *.
char *charargv[] (in)
Identique à argv, mais le type ne change pas en wchar_t.
char *wideargv[] (in)
Identique à argv, mais le type est toujours wchar_t.
Tcl_AppInitProc *appInitProc (in)
Adresse d'une procédure d'initialisation spécifique à l'application. La valeur de cet argument est généralement Tcl_AppInit.
Tcl_Obj *path (in)
Nom du fichier à utiliser comme script de démarrage, ou NULL.
const char *encoding (in)
Encodage du fichier à utiliser comme script de démarrage, ou NULL.
const char **encodingPtr (out)
Si non NULL, emplacement pour copier le (const char *) pointant vers le nom de l'encodage.
Tcl_MainLoopProc *mainLoopProc (in)
Adresse d'une procédure de boucle d'événements spécifique à l'application.
Tcl_Interp *interp (in)
Interpréteur Tcl déjà créé.

DESCRIPTION

Tcl_Main peut servir de programme principal pour les applications shell basées sur Tcl. Une application shell est un programme tel que tclsh ou wish qui prend en charge à la fois l'interprétation interactive de Tcl et l'évaluation d'un script contenu dans un fichier donné comme argument de ligne de commande. Tcl_Main est offert comme commodité aux développeurs d'applications shell, afin qu'ils n'aient pas à répéter tout le code pour une initialisation appropriée de la bibliothèque Tcl et pour le fonctionnement du shell interactif. D'autres styles d'intégration de Tcl dans une application ne sont pas pris en charge par Tcl_Main. Ceux-ci doivent être réalisés en appelant directement des fonctions de bas niveau de la bibliothèque Tcl.

La fonction Tcl_Main est disponible dans la bibliothèque Tcl depuis la version 7.4. Dans les versions précédentes de Tcl, la bibliothèque elle-même définissait une fonction main, mais celle-ci manquait de flexibilité dans le style d'intégration et avoir une fonction main dans une bibliothèque (en particulier dans une bibliothèque partagée) posait des problèmes sur de nombreux systèmes. Avoir main dans la bibliothèque Tcl rendrait également difficile l'utilisation de Tcl dans des programmes C++, car les programmes C++ doivent avoir des fonctions main spéciales pour C++.

Normalement, chaque application shell contient une petite fonction main qui appelle uniquement Tcl_Main. Tcl_Main effectue ensuite tout le travail de création et d'exécution d'une application similaire à tclsh.

Tcl_Main n'est pas disponible dans l'interface publique de la bibliothèque stub Tcl. Les programmes qui appellent Tcl_Main doivent être liés à la bibliothèque standard Tcl. Les extensions (même celles activées avec des stubs) ne sont pas conçues pour appeler Tcl_Main.

Tcl_Main n'est pas thread-safe. Il ne doit être appelé que par le thread principal unique d'une application multithread. Cette restriction n'est pas un problème dans l'utilisation normale décrite ci-dessus.

Tcl_Main et donc toutes les applications basées sur lui, telles que tclsh, utilisent Tcl_GetStdChannel pour initialiser les canaux standard à leurs valeurs par défaut. Voir Tcl_StandardChannels pour plus d'informations.

Tcl_Main prend en charge deux modes de fonctionnement, selon que le nom et l'encodage du script de démarrage ont été définis. Les routines Tcl_SetStartupScript et Tcl_GetStartupScript sont les outils permettant de contrôler cette configuration de Tcl_Main.

Tcl_SetStartupScript enregistre la valeur path comme nom de fichier à évaluer par Tcl_Main comme script de démarrage. La valeur encoding est le nom de l'encodage Tcl utilisé pour stocker le texte dans ce fichier. Une valeur NULL pour encoding indique d'utiliser l'encodage système. Une valeur NULL pour path supprime tout enregistrement existant, de sorte que Tcl_Main n'évaluera aucun script de démarrage.

Tcl_GetStartupScript interroge le nom de fichier et l'encodage enregistrés par le dernier appel à Tcl_SetStartupScript dans le même thread. Le nom de fichier stocké est renvoyé, et le nom de l'encodage stocké est écrit à l'emplacement pointé par encodingPtr, lorsque celui-ci n'est pas NULL.

Les valeurs de nom et d'encodage gérées par les routines Tcl_SetStartupScript et Tcl_GetStartupScript sont conservées par thread. Bien que les fonctions de stockage et de récupération de ces routines fonctionnent dans n'importe quel thread, seules celles appelées dans le même thread que Tcl_Main peuvent avoir une influence sur celui-ci.

L'appelant de Tcl_Main peut appeler Tcl_SetStartupScript en premier lieu pour définir son propre script de démarrage souhaité. Si Tcl_Main ne trouve aucun script de démarrage ainsi défini, il examine les premiers arguments de argv. S'ils correspondent à ?-encoding name? fileName, où fileName ne commence pas par le caractère -, alors fileName est considéré comme le nom d'un fichier contenant un script de démarrage, et name est considéré comme le nom de l'encodage du contenu de ce fichier. Tcl_Main appelle ensuite Tcl_SetStartupScript avec ces valeurs.

Après avoir défini les variables Tcl dans l'interpréteur principal de Tcl_Main, le script de démarrage est évalué dans l'interpréteur principal. Les variables argc, argv, argv0 et tcl_interactive sont définies comme décrit dans la documentation de tclsh.

Avant de traiter les commandes, une fois son propre travail d'initialisation terminé, Tcl_Main appelle la procédure fournie par l'argument appInitProc. Cette procédure permet à l'application de définir ses propres commandes dans l'interpréteur créé par Tcl_Main. La routine d'initialisation de l'application peut également appeler Tcl_SetStartupScript pour (re)définir le fichier et l'encodage comme script de démarrage. La procédure doit avoir une interface correspondant au type Tcl_AppInitProc :

typedef int Tcl_AppInitProc(
        Tcl_Interp *interp);

Le AppInitProc est presque toujours un pointeur vers Tcl_AppInit ; pour plus de détails sur cette procédure, voir la documentation de Tcl_AppInit.

Lorsque la procédure appInitProc se termine, Tcl_Main appelle Tcl_GetStartupScript pour déterminer quel script de démarrage a été demandé, le cas échéant. Si un script de démarrage a été fourni, Tcl_Main tente de l'évaluer. Sinon, le mode interactif commence par la recherche de la variable tcl_rcFileName dans l'interpréteur principal. Si cette variable existe et contient le nom d'un fichier lisible, le contenu du fichier est évalué dans l'interpréteur principal. Ensuite, l'opération interactive commence, avec les invites et les résultats d'évaluation des commandes écrits sur le canal de sortie standard, et les commandes lues à partir du canal d'entrée standard puis évaluées. Les invites écrites sur le canal de sortie standard peuvent être personnalisées en définissant les variables tcl_prompt1 et tcl_prompt2 comme décrit dans la documentation de tclsh. Les invites et les résultats d'évaluation des commandes ne sont écrits sur le canal de sortie standard que si la variable tcl_interactive dans l'interpréteur principal contient une valeur non nulle.

Tcl_SetMainLoop permet de définir une procédure de boucle d'événements à exécuter. Cela permet, par exemple, de charger dynamiquement Tk et de définir sa boucle d'événements. La boucle d'événements sera exécutée après le script de démarrage. Si vous êtes en mode interactif, la définition de la procédure de boucle d'événements entraînera la transformation de l'invite basée sur fileevent, puis l'appel de la procédure de boucle d'événements. Lorsque la procédure de boucle d'événements retourne en mode interactif, l'opération interactive se poursuit. La procédure de boucle d'événements doit avoir une interface correspondant au type Tcl_MainLoopProc :

typedef void Tcl_MainLoopProc(void);

Tcl_Main ne retourne pas. Normalement, un programme basé sur Tcl_Main se termine lorsque la commande exit est évaluée. En mode interactif, si un EOF ou une erreur est détecté sur le canal d'entrée standard, Tcl_Main évaluera lui-même la commande exit.

NOM

Tcl_SetMainLoop

SYNOPIS

Tcl_SetMainLoop(3)

ARGUMENTS

-t timeout -- délai d'attente pour la boucle principale

-d delay -- délai entre les itérations de la boucle

-s script -- script à exécuter lors de chaque itération de la boucle

-u user -- utilisateur sous lequel exécuter le script

-n name -- nom du script

-o output -- fichier de sortie pour le script

-a arg -- argument à passer au script

-e expr -- évaluer l'expression dans le script

-c cmd -- commande à exécuter dans le script

-v var -- variable à définir dans le script

-r repeat -- répéter le script

-l line -- ligne à exécuter dans le script

-f file -- fichier à lire

-i input -- entrée à lire

-b buffer -- tampon à utiliser

-p prefix -- préfixe à utiliser

-h help -- afficher le message d'aide

-V version -- afficher les informations de version

DESCRIPTION

Tcl_SetMainLoop est une commande qui définit la procédure de la boucle principale pour une application Tcl. La procédure de la boucle principale est la fonction qui est appelée de manière répétée par Tcl pour traiter les événements. Cette commande permet à l'application de spécifier quelle fonction doit être appelée de manière répétée, et elle peut également définir un délai d'attente ou un délai entre les itérations de la boucle.
