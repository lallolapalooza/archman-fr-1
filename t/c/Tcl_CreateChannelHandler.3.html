Tcl_CreateChannelHandler(3) Procédures de la bibliothèque Tcl Tcl_CreateChannelHandler(3)

NOM

Tcl_CreateChannelHandler, Tcl_DeleteChannelHandler - appeler une procédure lorsqu'un canal devient lisible ou inscriptible

SYNTAXE

#include <tcl.h>

void
Tcl_CreateChannelHandler(channel, mask, proc, clientData)

void
Tcl_DeleteChannelHandler(channel, proc, clientData)

ARGUMENTS

Tcl_Channel channel (entrée)
Canal Tcl tel que retourné par Tcl_CreateChannel.
int mask (entrée)
Conditions sous lesquelles proc doit être appelée : combinaison OU de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION. Spécifier une valeur zéro pour désactiver temporairement un gestionnaire existant.
Tcl_FileProc *proc (entrée)
Procédure à invoquer chaque fois que le canal indiqué par channel remplit les conditions spécifiées par mask.
ClientData clientData (entrée)
Valeur arbitraire d'un mot à passer à proc.

DESCRIPTION

Tcl_CreateChannelHandler organise l'appel de proc dans le futur chaque fois que l'entrée ou la sortie devient possible sur le canal identifié par channel, ou lorsqu'une condition exceptionnelle existe pour channel. Les conditions d'intérêt sous lesquelles proc sera invoquée sont spécifiées par l'argument mask. Voir l'entrée du manuel de fileevent pour une description précise de ce que signifie pour un canal d'être lisible ou inscriptible. Proc doit conformer au prototype suivant :

typedef void Tcl_ChannelProc(
        ClientData clientData,
        int mask);

L'argument clientData est la même valeur que celle passée à Tcl_CreateChannelHandler lors de la création du gestionnaire. Typiquement, clientData pointe vers une structure de données contenant des informations spécifiques à l'application concernant le canal. Mask est un masque entier indiquant quelles conditions demandées existent réellement pour le canal ; il contiendra un sous-ensemble des bits de l'argument mask passé à Tcl_CreateChannelHandler lors de la création du gestionnaire.

Chaque gestionnaire de canal est identifié par une combinaison unique de channel, proc et clientData. Il peut y avoir de nombreux gestionnaires pour un canal donné tant qu'ils n'ont pas le même channel, proc et clientData. Si Tcl_CreateChannelHandler est invoqué alors qu'il existe déjà un gestionnaire pour channel, proc et clientData, aucun nouveau gestionnaire n'est créé ; au lieu de cela, le mask est modifié pour le gestionnaire existant.

Tcl_DeleteChannelHandler supprime un gestionnaire de canal identifié par channel, proc et clientData ; si aucun gestionnaire de ce type n'existe, l'appel n'a aucun effet.

Les gestionnaires de canaux sont invoqués via le mécanisme d'événements Tcl, ils ne sont donc utiles que dans les applications pilotées par événements. Notez également que les conditions spécifiées dans l'argument mask passé à proc peuvent ne plus exister lorsque proc est invoqué : par exemple, s'il y a deux gestionnaires pour TCL_READABLE sur le même canal, le premier gestionnaire pourrait consommer toute l'entrée disponible de sorte que le canal ne soit plus lisible lorsque le second gestionnaire est invoqué. Pour cette raison, il peut être utile d'utiliser des E/S non bloquantes sur les canaux pour lesquels il existe des gestionnaires d'événements.
