Pointe vers une structure contenant les adresses des fonctions qui peuvent être appelées pour effectuer des opérations d'entrée/sortie et d'autres fonctions sur le canal.

Le nom de ce canal, comme file3 ; il ne doit pas être utilisé par un autre canal. Peut être NULL, auquel cas le canal est créé sans nom. Si le canal créé est affecté à l'un des canaux standard (stdin, stdout ou stderr), le nom attribué au canal sera le nom du canal standard.
ClientData donneesInstance (in)
Valeur arbitraire d'un seul mot associée à ce canal. Cette valeur est transmise aux fonctions de typePtr lorsqu'elles sont appelées.
int masque (in)
OR de TCL_READABLE et TCL_WRITABLE pour indiquer si un canal est lisible et/ou écrivable.
Tcl_Channel canal (in)
Le canal sur lequel opérer.
int direction (in)
TCL_READABLE signifie que vous voulez le handle d'entrée ; TCL_WRITABLE signifie que vous voulez le handle de sortie.
ClientData *handlePtr (out)
L'endroit où le handle souhaité du système d'exploitation sera stocké.
int taille (in)
La taille, en octets, des buffers à allouer sur ce canal.
int masque (in)
OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION indiquant les événements qui se sont produits sur ce canal.
Tcl_Interp *interp (in)
Interpréteur actuel. (Peut être NULL)
const char *nomOption (in)
Nom de l'option invalide.

Liste d'options spécifiques (mots séparés par des espaces, sans le -), à ajouter à la liste d'options standard. Peut être NULL pour les messages d'erreur d'options standard uniquement.

DESCRIPTION

Tcl utilise une architecture de canaux à deux niveaux. Elle fournit un niveau supérieur générique pour permettre aux programmes C et Tcl d'effectuer des entrées/sorties en utilisant les mêmes API pour divers fichiers, périphériques, sockets, etc. Les API C génériques sont décrites dans la page de manuel de Tcl_OpenFileChannel.

Le niveau inférieur fournit des pilotes de canaux spécifiques pour chaque type de périphérique pris en charge sur chaque plateforme. Cette page de manuel décrit les API C utilisées entre le niveau générique et les pilotes de canaux spécifiques. Elle explique également comment de nouveaux types de canaux peuvent être ajoutés en fournissant de nouveaux pilotes de canaux.

Les pilotes de canaux se composent de plusieurs éléments : Premièrement, chaque pilote de canal fournit une structure Tcl_ChannelType contenant des pointeurs vers les fonctions qui implémentent les opérations utilisées par le niveau générique pour communiquer avec le pilote de canal. La structure Tcl_ChannelType et les fonctions auxquelles elle fait référence sont décrites dans la section TCL_CHANNELTYPE, ci-dessous.

Deuxièmement, les pilotes de canaux fournissent généralement une commande Tcl pour créer des instances de ce type de canal. Par exemple, la commande Tcl open crée des canaux qui utilisent les pilotes de canaux de fichiers et de commandes, et la commande Tcl socket crée des canaux qui utilisent les protocoles réseau TCP.

Troisièmement, un pilote de canal fournit éventuellement une fonction C pour ouvrir des instances de ce type de canal. Par exemple, Tcl_OpenFileChannel ouvre un canal qui utilise le pilote de canal de fichier, et Tcl_OpenTcpClient ouvre un canal qui utilise le protocole réseau TCP. Ces fonctions d'ouverture utilisent normalement Tcl_CreerCanal en interne pour ouvrir le canal.

Pour ajouter un nouveau type de canal, vous devez implémenter une API C ou une commande Tcl qui ouvre un canal en appelant Tcl_CreerCanal. Lorsque votre pilote appelle Tcl_CreerCanal, il passe une structure Tcl_ChannelType décrivant les procédures d'entrée/sortie de votre pilote. Le niveau générique appellera les fonctions référencées dans cette structure pour effectuer des opérations sur le canal.

Tcl_CreerCanal ouvre un nouveau canal et lui associe typePtr et donneesInstance. Le canal est ouvert dans le mode indiqué par masque. Pour une discussion sur les pilotes de canaux, leurs opérations et la structure Tcl_ChannelType, voir la section TCL_CHANNELTYPE, ci-dessous.

Tcl_CreerCanal interagit avec le code qui gère les canaux standard. Une fois qu'un canal standard a été initialisé par un appel à Tcl_GetStdChannel ou Tcl_SetStdChannel, la fermeture de ce canal fera que le prochain appel à Tcl_CreerCanal utilisera également le nouveau canal comme nouveau canal standard. Voir Tcl_StandardChannels pour une discussion générale sur les canaux standard et le comportement de la bibliothèque Tcl à leur égard.

Tcl_GetChannelInstanceData renvoie les données d'instance associées au canal dans canal. Il s'agit de la même valeur que l'argument donneesInstance de l'appel à Tcl_CreerCanal qui a créé ce canal.

Tcl_GetChannelType renvoie un pointeur vers la structure Tcl_ChannelType utilisée par le canal dans l'argument canal. Il s'agit de la même valeur que l'argument typePtr de l'appel à Tcl_CreerCanal qui a créé ce canal.

Tcl_GetChannelName renvoie une chaîne contenant le nom associé au canal, ou NULL si l'argument nomCanal de Tcl_CreerCanal était NULL.

Tcl_GetChannelHandle place le handle du système d'exploitation associé à canal pour la direction donnée dans handlePtr.

EXEMPLE

L'exemple suivant montre comment créer un canal :

int main(int argc, char *argv[]) {
    Tcl_Channel *canal;
    int taille = 4096;
    int masque = TCL_READABLE | TCL_WRITABLE;

    canal = Tcl_CreerCanal(typePtr, "file3", donneesInstance, masque);
    Tcl_SetChannelBufferSize(canal, taille);
    Tcl_NotifyChannel(canal, masque);
}

Elle fournit un niveau supérieur générique pour permettre aux programmes C et Tcl d'effectuer des entrées/sorties en utilisant les mêmes API pour divers fichiers, périphériques, sockets, etc. Les API C génériques sont décrites dans la page de manuel de Tcl_OpenFileChannel.

Le niveau inférieur fournit des pilotes de canaux spécifiques pour chaque type de périphérique pris en charge sur chaque plateforme. Cette page de manuel décrit les API C utilisées entre le niveau générique et les pilotes de canaux spécifiques. Elle explique également comment de nouveaux types de canaux peuvent être ajoutés en fournissant de nouveaux pilotes de canaux.

Les pilotes de canaux se composent de plusieurs éléments : Premièrement, chaque pilote de canal fournit une structure Tcl_ChannelType contenant des pointeurs vers les fonctions qui implémentent les opérations utilisées par le niveau générique pour communiquer avec le pilote de canal. La structure Tcl_ChannelType et les fonctions auxquelles elle fait référence sont décrites dans la section TCL_CHANNELTYPE, ci-dessous.

Deuxièmement, les pilotes de canaux fournissent généralement une commande Tcl pour créer des instances de ce type de canal. Par exemple, la commande Tcl open crée des canaux qui utilisent les pilotes de canaux de fichiers et de commandes, et la commande Tcl socket crée des canaux qui utilisent les protocoles réseau TCP.

Troisièmement, un pilote de canal fournit éventuellement une fonction C pour ouvrir des instances de ce type de canal. Par exemple, Tcl_OpenFileChannel ouvre un canal qui utilise le pilote de canal de fichier, et Tcl_OpenTcpClient ouvre un canal qui utilise le protocole réseau TCP. Ces fonctions d'ouverture utilisent normalement Tcl_CreerCanal en interne pour ouvrir le canal.

Pour ajouter un nouveau type de canal, vous devez implémenter une API C ou une commande Tcl qui ouvre un canal en appelant Tcl_CreerCanal. Lorsque votre pilote appelle Tcl_CreerCanal, il passe une structure Tcl_ChannelType décrivant les procédures d'entrée/sortie de votre pilote. Le niveau générique appellera les fonctions référencées dans cette structure pour effectuer des opérations sur le canal.

Tcl_CreerCanal ouvre un nouveau canal et lui associe typePtr et donneesInstance. Le canal est ouvert dans le mode indiqué par masque. Pour une discussion sur les pilotes de canaux, leurs opérations et la structure Tcl_ChannelType, voir la section TCL_CHANNELTYPE, ci-dessous.

Tcl_CreerCanal interagit avec le code qui gère les canaux standard. Une fois qu'un canal standard a été initialisé par un appel à Tcl_GetStdChannel ou Tcl_SetStdChannel, la fermeture de ce canal fera que le prochain appel à Tcl_CreerCanal utilisera également le nouveau canal comme nouveau canal standard. Voir Tcl_StandardChannels pour une discussion générale sur les canaux standard et le comportement de la bibliothèque Tcl à leur égard.

Tcl_GetChannelInstanceData renvoie les données d'instance associées au canal dans canal. Il s'agit de la même valeur que l'argument donneesInstance de l'appel à Tcl_CreerCanal qui a créé ce canal.

Tcl_GetChannelType renvoie un pointeur vers la structure Tcl_ChannelType utilisée par le canal dans l'argument canal. Il s'agit de la même valeur que l'argument typePtr de l'appel à Tcl_CreerCanal qui a créé ce canal.

Tcl_GetChannelName renvoie une chaîne contenant le nom associé au canal, ou NULL si l'argument nomCanal de Tcl_CreerCanal était NULL.

Tcl_GetChannelHandle place le handle du système d'exploitation associé à canal pour la direction donnée dans handlePtr.

EXEMPLE

L'exemple suivant montre comment créer un canal :

int main(int argc, char *argv[]) {
    Tcl_Channel *canal;
    int taille = 4096;
    int masque = TCL_READABLE | TCL_WRITABLE;

    canal = Tcl_CreerCanal(typePtr, "file3", donneesInstance, masque);
    Tcl_SetChannelBufferSize(canal, taille);
    Tcl_NotifyChannel(canal, masque);
}

ARGUMENTS

const Tcl_ChannelType *typePtr (in)
Pointe vers une structure contenant les adresses des fonctions qui peuvent être appelées pour effectuer des opérations d'entrée/sortie et d'autres fonctions sur le canal.
const char *nomCanal (in)
Le nom de ce canal, comme file3 ; il ne doit pas être utilisé par un autre canal. Peut être NULL, auquel cas le canal est créé sans nom. Si le canal créé est affecté à l'un des canaux standard (stdin, stdout ou stderr), le nom attribué au canal sera le nom du canal standard.
ClientData donneesInstance (in)
Valeur arbitraire d'un seul mot associée à ce canal. Cette valeur est transmise aux fonctions de typePtr lorsqu'elles sont appelées.
int masque (in)
OR de TCL_READABLE et TCL_WRITABLE pour indiquer si un canal est lisible et/ou écrivable.
Tcl_Channel canal (in)
Le canal sur lequel opérer.
int direction (in)
TCL_READABLE signifie que vous voulez le handle d'entrée ; TCL_WRITABLE signifie que vous voulez le handle de sortie.
ClientData *handlePtr (out)
L'endroit où le handle souhaité du système d'exploitation sera stocké.
int taille (in)
La taille, en octets, des buffers à allouer sur ce canal.
int masque (in)
OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION indiquant les événements qui se sont produits sur ce canal.
Tcl_Interp *interp (in)
Interpréteur actuel. (Peut être NULL)
const char *nomOption (in)
Nom de l'option invalide.
const char *listeOption (in)
Liste d'options spécifiques (mots séparés par des espaces, sans le -), à ajouter à la liste d'options standard. Peut être NULL pour les messages d'erreur d'options standard uniquement.

Ces fonctions sont utilisées par les pilotes de canal pour gérer les canaux dans le système Tcl.

Tcl_GetChannelHandle renvoie le handle du périphérique spécifié par handlePtr et retourne TCL_OK. Tcl_GetChannelMode retourne une combinaison OR de TCL_READABLE et TCL_WRITABLE, indiquant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelBufferSize retourne la taille, en octets, des tampons alloués pour stocker les entrées ou sorties dans le channel. Si la valeur n'a pas été définie par un appel précédent à Tcl_SetChannelBufferSize, décrit ci-dessous, alors la valeur par défaut de 4096 est retournée.

Tcl_SetChannelBufferSize définit la taille, en octets, des tampons qui seront alloués lors des opérations ultérieures sur le canal pour stocker les entrées ou sorties. L'argument size doit être compris entre un et un million, permettant des tampons de un octet à un million d'octets. Si size est en dehors de cette plage, Tcl_SetChannelBufferSize définit la taille du tampon à 4096.

Les pilotes de canal sont responsables de l'invocation de cette fonction chaque fois que les gestionnaires de canal doivent être appelés pour le canal (ou que d'autres tâches en attente, comme la vidange d'une écriture, doivent être effectuées). Voir WATCHPROC ci-dessous pour plus de détails.

Tcl_BadChannelOption est appelé à partir de setOptionProc ou getOptionProc spécifiques au pilote pour générer un message d'erreur complet.

Tcl_ChannelBuffered retourne le nombre d'octets d'entrée actuellement mis en tampon dans le tampon interne (zone de rappel) du canal lui-même. Il ne rend pas compte des données dans les tampons globaux pour la pile de canaux dont fait partie le canal fourni.

Tcl_IsChannelShared vérifie le compteur de références du channel spécifié et retourne si le channel a été partagé entre plusieurs interpréteurs (résultat == 1) ou non (résultat == 0).

Tcl_IsChannelRegistered vérifie si le channel spécifié est enregistré dans l'interpréteur interp donné (résultat == 1) ou non (résultat == 0).

Tcl_IsChannelExisting vérifie si un canal avec le nom spécifié est enregistré dans la liste globale (du thread) de tous les canaux (résultat == 1) ou non (résultat == 0).

Tcl_CutChannel supprime le channel spécifié de la liste globale (du thread) de tous les canaux (du thread courant). L'application à un canal encore enregistré dans un interpréteur n'est pas autorisée. TCL_CHANNELTYPE

Un pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers des fonctions qui implémentent les diverses opérations sur un canal ; ces opérations sont appelées si nécessaire par la couche générique. La structure a été versionnée à partir de Tcl 8.3.2/8.4 pour corriger un problème avec les pilotes de canal empilés. Voir la section OLD CHANNEL TYPES ci-dessous pour plus de détails sur l'ancienne structure.

La structure Tcl_ChannelType contient les champs suivants :

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Il n'est pas nécessaire de fournir des implémentations pour toutes les opérations sur les canaux. Celles qui ne sont pas nécessaires peuvent être mises à NULL dans la structure : blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc, et close2Proc, en plus de flushProc, handlerProc, threadActionProc, et truncateProc. Les autres fonctions qui ne peuvent pas être implémentées de manière significative doivent retourner EINVAL lorsqu'elles sont appelées, pour indiquer que les opérations qu'elles représentent ne sont pas disponibles. Notez également que wideSeekProc peut être NULL si seekProc l'est.

L'utilisateur ne doit utiliser que la structure ci-dessus pour l'instanciation de Tcl_ChannelType. Lors de la référence aux champs d'une structure Tcl_ChannelType, les fonctions suivantes doivent être utilisées pour obtenir les valeurs : Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc, ou Tcl_ChannelHandlerProc.

La modification des structures a été faite de manière à ce que les types de canaux standard soient binaires compatibles. Cependant, les types de canaux qui utilisent des canaux empilés (c'est-à-dire TLS, Trf) ont de nouvelles versions pour correspondre au changement ci-dessus, car le code précédent pour les canaux empilés avait des problèmes.

TYPENAME

Le champ typeName contient une chaîne terminée par un caractère nul qui identifie le type de l'appareil implémenté par ce pilote, par exemple file ou socket.

Le champ blockModeProc contient l'adresse d'une fonction appelée par la couche générique pour définir le mode bloquant et non bloquant sur le périphérique. BlockModeProc doit correspondre au prototype suivant :

L'argument instanceData est le même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. CLOSEPROC ET CLOSE2PROC

Le champ closeProc contient l'adresse d'une fonction appelée par la couche générique pour fermer un canal. La procédure doit correspondre au prototype suivant :

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création du canal. La fonction doit libérer toutes les ressources associées au canal. Elle doit retourner zéro en cas de succès ; sinon, elle doit retourner un code d'erreur POSIX non nul. De plus, si une erreur se produit et que interp n'est pas NULL, la procédure doit stocker un message d'erreur dans le résultat de l'interpréteur.

Alternativement, les canaux qui permettent de fermer indépendamment les côtés lecture et écriture peuvent définir closeProc à TCL_CLOSE2PROC et close2Proc à l'adresse d'une fonction qui correspond au prototype suivant :

typedef int Tcl_DriverClose2Proc(
        ClientData instanceData,
        Tcl_Interp *interp,
        int flags);

close2Proc sera appelée avec flags défini comme une combinaison OR de TCL_CLOSE_READ ou TCL_CLOSE_WRITE pour indiquer que le pilote doit fermer le côté lecture et/ou écriture du canal. Le pilote de canal peut être appelé pour effectuer des opérations supplémentaires sur le canal après l'appel de close2Proc pour fermer un ou les deux côtés du canal. Si flags est 0 (zéro), le pilote doit fermer le canal de la manière décrite ci-dessus pour closeProc. Aucune autre opération ne sera appelée sur cette instance après l'appel de close2Proc avec tous les drapeaux effacés. Dans tous les cas, la fonction close2Proc doit retourner zéro si l'opération de fermeture a réussi ; sinon, elle doit retourner un code d'erreur POSIX non nul. De plus, si une erreur se produit et que interp n'est pas NULL, la procédure doit stocker un message d'erreur dans le résultat de l'interpréteur.

Les valeurs closeProc et close2Proc peuvent être récupérées avec Tcl_ChannelCloseProc ou Tcl_ChannelClose2Proc, qui retournent un pointeur vers la fonction respective.

INPUTPROC

Le champ inputProc contient l'adresse d'une fonction appelée par la couche générique pour lire des données depuis le fichier ou le périphérique et les stocker dans un tampon interne. InputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création du canal. L'argument buf pointe vers un tableau d'octets dans lequel stocker les données d'entrée du périphérique, et l'argument bufSize indique combien d'octets sont disponibles à buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique. Si une erreur se produit, la fonction doit définir la variable à un code d'erreur POSIX qui identifie l'erreur qui s'est produite.

La fonction doit lire les données depuis le périphérique d'entrée encapsulé par le canal et les stocker à buf. En cas de succès, la fonction doit retourner un entier non négatif indiquant combien d'octets ont été lus depuis le périphérique d'entrée et stockés à buf. En cas d'erreur, la fonction doit retourner -1. Si une erreur se produit après que certaines données ont été lues depuis le périphérique, ces données sont perdues.

Si inputProc peut déterminer que le périphérique d'entrée dispose de données disponibles mais moins que ce qui est demandé par l'argument bufSize, la fonction ne doit tenter de lire que la quantité de données disponible et retourner sans bloquer. Si le périphérique d'entrée ne dispose d'aucune donnée disponible et que le canal est en mode non bloquant, la fonction doit retourner une erreur EAGAIN. Si le périphérique d'entrée ne dispose d'aucune donnée disponible et que le canal est en mode bloquant, la fonction doit bloquer pendant la plus courte durée possible jusqu'à ce qu'au moins un octet de données puisse être lu depuis le périphérique ; ensuite, elle devrait retourner autant de données qu'elle peut lire sans bloquer.

Cette valeur peut être récupérée avec Tcl_ChannelInputProc, qui retourne un pointeur vers la fonction.

        int toWrite,
        int *errorCodePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création du canal. L'argument buf contient un tableau d'octets à écrire sur le périphérique, et l'argument toWrite indique combien d'octets doivent être écrits à partir de l'argument buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique. Si une erreur se produit, la fonction doit définir cette variable à un code d'erreur POSIX qui identifie l'erreur.

La fonction doit écrire les données à buf sur le périphérique de sortie encapsulé par le canal. En cas de succès, la fonction doit retourner un entier non négatif indiquant combien d'octets ont été écrits sur le périphérique de sortie. La valeur de retour est normalement la même que toWrite, mais peut être inférieure dans certains cas, par exemple si l'opération de sortie est interrompue par un signal. Si une erreur se produit, la fonction doit retourner -1. En cas d'erreur, certaines données peuvent avoir été écrites sur le périphérique.

Si le canal est non bloquant et que le périphérique de sortie ne peut absorber aucune donnée, la fonction doit retourner -1 avec une erreur EAGAIN sans écrire aucune donnée.

Cette valeur peut être récupérée avec Tcl_ChannelOutputProc, qui retourne un pointeur vers la fonction.

SEEKPROC ET WIDESEEKPROC

Le champ seekProc contient l'adresse d'une fonction appelée par la couche générique pour déplacer le point d'accès auquel les opérations d'entrée ou de sortie ultérieures seront appliquées. SeekProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

L'argument instanceData est la même valeur que celle donnée à Tcl_CreateChannel lors de la création de ce canal. Offset et seekMode ont la même signification que pour la procédure Tcl_Seek (décrite dans l'entrée de manuel de Tcl_OpenFileChannel).

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique pour retourner les valeurs errno de la fonction. La fonction doit définir cette variable à un code d'erreur POSIX si une erreur se produit. La fonction doit stocker un code d'erreur EINVAL si le type de canal n'implémente pas la recherche.

La valeur de retour est le nouveau point d'accès ou -1 en cas d'erreur. Si une erreur s'est produite, la fonction ne doit pas déplacer le point d'accès.

S'il existe un champ seekProc non NULL, le champ wideSeekProc peut contenir l'adresse d'une fonction alternative à utiliser qui gère les décalages larges (c'est-à-dire plus grands que 32 bits), permettant ainsi de rechercher dans des fichiers de plus de 2 Go. WideSeekProc sera appelée de préférence à seekProc, mais les deux doivent être définis si wideSeekProc est défini. WideSeekProc doit correspondre au prototype suivant :

typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

Les arguments et les valeurs de retour signifient la même chose qu'avec seekProc ci-dessus, à l'exception du type des décalages et du type de retour qui sont différents.

La valeur seekProc peut être récupérée avec Tcl_ChannelSeekProc, qui retourne un pointeur vers la fonction, et de même, wideSeekProc peut être récupérée avec Tcl_ChannelWideSeekProc.

SETOPTIONPROC

Le champ setOptionProc contient l'adresse d'une fonction appelée par la couche générique pour définir une option spécifique au type de canal sur un canal. setOptionProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

optionName est le nom d'une option à définir, et newValue est la nouvelle valeur de cette option, sous forme de chaîne. instanceData est la même valeur que celle donnée à Tcl_CreateChannel lors de la création de ce canal. La fonction doit effectuer toute action spécifique au type de canal requise pour implémenter la nouvelle valeur de l'option.

Certaines options sont gérées par le code générique et cette fonction n'est jamais appelée pour les définir, par exemple -blockmode. D'autres options sont spécifiques à chaque type de canal et la procédure setOptionProc du pilote de canal sera appelée pour les implémenter. Le champ setOptionProc peut être NULL, ce qui indique que ce type de canal ne prend en charge aucune option spécifique.

Si la valeur de l'option est modifiée avec succès vers la nouvelle valeur, la fonction retourne TCL_OK. Elle doit appeler Tcl_BadChannelOption qui retourne elle-même TCL_ERROR si optionName n'est pas reconnu. Si newValue spécifie une valeur pour l'option qui n'est pas prise en charge ou si une erreur d'appel système se produit, la fonction doit laisser un message d'erreur dans le résultat de interp si interp n'est pas NULL. La fonction doit également appeler Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

Cette valeur peut être récupérée avec Tcl_ChannelSetOptionProc, qui retourne un pointeur vers la fonction.
