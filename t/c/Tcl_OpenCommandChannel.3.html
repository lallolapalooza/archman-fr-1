ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour le rapport d'erreurs et pour rechercher un canal enregistré dedans.
const char *fileName (in)
Le nom d'un fichier local ou réseau.
const char *mode (in)
Spécifie comment le fichier doit être accédé. Peut avoir n'importe laquelle des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (in)
Indications de permissions de style POSIX comme 0644. Si un nouveau fichier est créé, ces permissions seront appliquées au fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour construire un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans option de la commande Tcl exec.
int flags (in)
Spécifie la disposition des descripteurs stdio dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, l'entrée standard du premier enfant dans le tuyau est le canal du tuyau, sinon elle est la même que l'entrée standard du processus appelant ; de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, alors le tuyau peut rediriger les descripteurs stdio pour remplacer les descripteurs stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, alors de telles redirections provoquent une erreur.
ClientData handle (in)
Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, c'est un descripteur de fichier, pour Windows c'est un HANDLE.
int readOrWrite (in)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (in)
Le motif à faire correspondre, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl pour l'entrée ou la sortie. Doit être la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker les caractères lus depuis le canal.
int charsToRead (in)
Le nombre de caractères à lire du canal. Si le codage du canal est binary, ceci est équivalent au nombre d'octets à lire du canal.
int appendFlag (in)
Si non nul, les données lues du canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (out)
Un tampon dans lequel stocker les octets lus depuis le canal.
int bytesToRead (in)
Le nombre d'octets à lire du canal. Le tampon readBuf doit être assez grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker la ligne lue du canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne dynamique Tcl dans laquelle stocker la ligne lue du canal. Doit avoir été initialisée par l'appelant. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne dynamique.
const char *input (in)
L'entrée à ajouter à un tampon de canal.
int inputLen (in)
Longueur de l'entrée
int addAtEnd (in)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon de canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera sorti sur le canal.
const char *charBuf (in)
Un tampon contenant les caractères à sortir sur le canal.
const char *byteBuf (in)
Un tampon contenant les octets à sortir sur le canal.
int bytesToWrite (in)
Le nombre d'octets à consommer de charBuf ou byteBuf et à sortir sur le canal.
Tcl_WideInt offset (in)
Décalage pour déplacer le point d'accès dans le canal auquel la prochaine opération d'entrée ou de sortie sera appliquée, mesuré en octets à partir de la position donnée par seekMode. Peut être positif ou négatif.
int seekMode (in)
Par rapport à quel point chercher ; utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs légales sont SEEK_SET, SEEK_CUR, et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) à laquelle tronquer le canal.
const char *optionName (in)
Le nom d'une option applicable à ce canal, telle que -blocking. Peut avoir n'importe laquelle des valeurs acceptées par la commande fconfigure.
Tcl_DString *optionValue (in)
Où stocker la valeur d'une option ou une liste de toutes les options et leurs valeurs. Doit avoir été initialisé par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des périphériques et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie en mémoire tampon sur une variété de types de fichiers, de sockets et de périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant une interface de pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée de manuel de Tcl_CreateChannel. Le mécanisme de canaux fournit un schéma de mise en mémoire tampon calqué sur les E/S standard d'Unix, et il permet également les E/S non bloquantes sur les canaux.

Les procédures décrites dans cette entrée de manuel comprennent les APIs C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canal et comment implémenter des pilotes de canal pour de nouveaux types de canaux, voir l'entrée de manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

La procédure Tcl_OpenFileChannel ouvre le fichier spécifié par fileName et le renvoie comme un canal Tcl. Le paramètre mode spécifie comment le fichier doit être ouvert ; il peut prendre les mêmes valeurs que l'argument mode pour la commande Tcl open. Le paramètre permissions spécifie les permissions POSIX à utiliser si le fichier est créé.

Si une erreur se produit, NULL est renvoyé et interp est utilisé pour stocker un message d'erreur.

TCL_OPENCOMMANDCHANNEL

La procédure Tcl_OpenCommandChannel crée un pipeline de commandes à partir d'un tableau de chaînes de caractères et le renvoie comme un canal Tcl. Les arguments argc et argv sont le nombre et le tableau des arguments de la commande. Les flags spécifient la disposition des descripteurs stdio dans le pipeline : TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE.

Si une erreur se produit, NULL est renvoyé et interp est utilisé pour stocker un message d'erreur.

TCL_MAKEFILECHANNEL

La procédure Tcl_MakeFileChannel prend un descripteur de fichier (sous Unix) ou un handle de fichier (sous Windows) et le convertit en un canal Tcl. Le paramètre readOrWrite est une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant quelles opérations sont valides sur le descripteur.

Si une erreur se produit, NULL est renvoyé.

TCL_GETCHANNEL

La procédure Tcl_GetChannel renvoie un canal Tcl correspondant au channelName donné, éventuellement en vérifiant qu'il est ouvert en lecture et/ou en écriture comme spécifié par modePtr. Si le canal n'est pas trouvé, NULL est renvoyé et un message d'erreur est stocké dans interp.

TCL_GETCHANNELNAMES

La procédure Tcl_GetChannelNames renvoie le nombre de canaux disponibles dans l'interpréteur interp. La liste des noms des canaux est stockée dans l'objet résultat de interp sous forme d'une liste Tcl.

La procédure Tcl_GetChannelNamesEx est similaire, mais ne renvoie que les canaux dont le nom correspond au pattern.

TCL_REGISTERCHANNEL

La procédure Tcl_RegisterChannel enregistre un canal Tcl dans l'interpréteur interp, le rendant disponible pour les commandes Tcl qui utilisent des noms de canaux.

TCL_UNREGISTERCHANNEL

La procédure Tcl_UnregisterChannel désenregistre un canal Tcl de l'interpréteur interp. Le canal doit être fermé avant d'être désenregistré.

Si le canal a été désenregistré avec succès, 0 est renvoyé, sinon 1 est renvoyé.

TCL_DETACHCHANNEL

La procédure Tcl_DetachChannel détache un canal de son interpréteur. Le canal sera toujours valide, mais ne pourra plus être accédé par son nom. Le canal doit être fermé manuellement plus tard.

Si le canal a été détaché avec succès, 0 est renvoyé, sinon 1 est renvoyé.

TCL_ISTANDARDCHANNEL

La procédure Tcl_IsStandardChannel renvoie vrai si le canal donné est l'un des canaux standard (entrée, sortie ou erreur).

TCL_CLOSE

La procédure Tcl_Close ferme le canal donné. Toutes les données en mémoire tampon sont vidées avant la fermeture.

Si la fermeture réussit, 0 est renvoyé, sinon Tcl_EWOULDBLOCK est renvoyé si l'opération a été bloquée et Tcl_IOError si une autre erreur s'est produite.

TCL_READCHARS

La procédure Tcl_ReadChars lit jusqu'à charsToRead caractères depuis le canal et les stocke dans la valeur Tcl pointée par readObjPtr. Si appendFlag est non nul, les caractères lus sont ajoutés à la valeur existante ; sinon, la valeur est remplacée. Si une erreur se produit ou si la fin du fichier est atteinte, le nombre de caractères lus est renvoyé. Sinon, le nombre de caractères demandés est renvoyé.

Si une erreur d'E/S se produit, Tcl_IOError est renvoyé. Si l'opération est bloquée, Tcl_EWOULDBLOCK est renvoyé.

TCL_READ

La procédure Tcl_Read lit jusqu'à bytesToRead octets depuis le canal et les stocke dans le tampon readBuf. Le tampon doit être suffisamment grand pour contenir ce nombre d'octets. La procédure renvoie le nombre d'octets réellement lus.

Si une erreur d'E/S se produit, Tcl_IOError est renvoyé. Si l'opération est bloquée, Tcl_EWOULDBLOCK est renvoyé.

TCL_GETSOBJ

La procédure Tcl_GetsObj lit une ligne depuis le canal, y compris le caractère de fin de ligne s'il est présent, et la stocke dans la valeur Tcl pointée par lineObjPtr. La ligne lue est ajoutée à la valeur existante. La procédure renvoie 1 si une ligne a été lue, 0 si la fin du fichier est atteinte sans lire de ligne, ou Tcl_IOError si une erreur d'E/S s'est produite.

Si l'opération est bloquée, Tcl_EWOULDBLOCK est renvoyé.

TCL_GETS

La procédure Tcl_Gets est similaire à Tcl_GetsObj, mais elle stocke la ligne lue dans une chaîne dynamique Tcl pointée par lineRead.

TCL_UNGETS

La procédure Tcl_Ungets renvoie la chaîne input (de longueur inputLen) dans le canal. Si addAtEnd est non nul, l'entrée est ajoutée à la fin du tampon ; sinon, elle est ajoutée au début.

Renvoie le nombre d'octets effectivement mis de côté, ou une valeur d'erreur.

TCL_WRITEOBJ

La procédure Tcl_WriteObj écrit le contenu de la valeur Tcl pointée par writeObjPtr sur le canal.

Renvoie le nombre d'octets écrits. Si une erreur d'E/S se produit, Tcl_IOError est renvoyé. Si l'opération est bloquée, Tcl_EWOULDBLOCK est renvoyé.

TCL_WRITECHARS

La procédure Tcl_WriteChars écrit les caractères du tampon charBuf (de longueur bytesToWrite) sur le canal.

Renvoie le nombre d'octets écrits. Si une erreur d'E/S se produit, Tcl_IOError est renvoyé. Si l'opération est bloquée, Tcl_EWOULDBLOCK est renvoyé.

TCL_WRITE

La procédure Tcl_Write est similaire à Tcl_WriteChars, mais elle écrit les octets du tampon byteBuf sur le canal.

TCL_READRAW

La procédure Tcl_ReadRaw lit bytesToRead octets du canal et les place dans le tampon readBuf. Contrairement à Tcl_Read, elle ne fait aucune conversion de jeu de caractères et fonctionne en mode binaire.

Renvoie le nombre d'octets lus. Si une erreur d'E/S se produit, Tcl_IOError est renvoyé. Si l'opération est bloquée, Tcl_EWOULDBLOCK est renvoyé.

TCL_WRITERAW

La procédure Tcl_WriteRaw écrit bytesToWrite octets du tampon byteBuf sur le canal. Contrairement à Tcl_Write, elle ne fait aucune conversion de jeu de caractères et fonctionne en mode binaire.

Renvoie le nombre d'octets écrits. Si une erreur d'E/S se produit, Tcl_IOError est renvoyé. Si l'opération est bloquée, Tcl_EWOULDBLOCK est renvoyé.

TCL_EOF

La procédure Tcl_Eof renvoie vrai si la fin du fichier a été atteinte sur le canal.

TCL_FLUSH

La procédure Tcl_Flush vide toutes les données en mémoire tampon du canal. Elle renvoie 0 en cas de succès, ou une valeur d'erreur en cas d'échec.

TCL_INPUTBLOCKED

La procédure Tcl_InputBlocked renvoie vrai si la dernière opération de lecture sur le canal a été bloquée.

TCL_INPUTBUFFERED

La procédure Tcl_InputBuffered renvoie le nombre d'octets actuellement en mémoire tampon d'entrée pour le canal.

TCL_OUTPUTBUFFERED

La procédure Tcl_OutputBuffered renvoie le nombre d'octets actuellement en mémoire tampon de sortie pour le canal.

TCL_SEEK

La procédure Tcl_Seek change le point d'accès du canal à la position spécifiée par offset par rapport à seekMode (SEEK_SET, SEEK_CUR ou SEEK_END). Elle renvoie la nouvelle position du pointeur d'accès en octets, ou -1 en cas d'erreur.

TCL_TELL

La procédure Tcl_Tell renvoie la position actuelle du pointeur d'accès du canal en octets, ou -1 en cas d'erreur.

TCL_TRUNCATECHANNEL

La procédure Tcl_TruncateChannel tronque le canal à la longueur spécifiée par length. Elle renvoie 0 en cas de succès, ou une valeur d'erreur en cas d'échec.

TCL_GETCHANNELOPTION

La procédure Tcl_GetChannelOption récupère la valeur de l'option spécifiée par optionName pour le canal donné et la stocke dans la chaîne dynamique pointée par optionValue. Si optionName est NULL, alors toutes les options du canal sont récupérées sous forme d'une liste Tcl (clé-valeur).

Renvoie 0 en cas de succès, ou Tcl_IOError en cas d'erreur.

TCL_SETCHANNELOPTION

La procédure Tcl_SetChannelOption définit l'option spécifiée par optionName du canal donné à la valeur newValue.

Renvoie 0 en cas de succès, ou Tcl_IOError en cas d'erreur.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et renvoie un handle de canal qui peut être utilisé pour effectuer des entrées et sorties sur le fichier. Cette API est calquée sur la fonction fopen de la bibliothèque d'E/S standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. À partir de Tcl 8.4, l'API basée sur les valeurs Tcl_FSOpenFileChannel devrait être préférée à Tcl_OpenFileChannel dans tous les cas.

Le canal nouvellement créé n'est pas enregistré auprès de l'interpréteur fourni ; pour l'enregistrer, il faut utiliser Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'affecte également en tant que remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface C de bas niveau aux fonctions des commandes exec et open. Il crée une séquence de processus subsidiaires spécifiés par les arguments argv et argc et renvoie un canal qui peut être utilisé pour communiquer avec ces processus subsidiaires. L'argument flags indique le type de communication que vous aurez avec la séquence de commandes.

Si le drapeau TCL_STDIN est défini, le stdin du premier processus subsidiaire est lié au canal : écrire dans le canal fournit une entrée au processus subsidiaire. Si le drapeau TCL_STDIN n'est pas défini, le stdin du premier processus subsidiaire sera le même que le stdin de cette application. Si le drapeau TCL_STDOUT est défini, la sortie standard du dernier processus subsidiaire peut être lue à partir du canal ; sinon, elle va à la sortie standard de cette application. Si le drapeau TCL_STDERR est défini, la sortie d'erreur standard de tous les processus subsidiaires est renvoyée au canal et génère une erreur lorsque le canal est fermé ; sinon, elle va à la sortie d'erreur standard de cette application. Si le drapeau TCL_ENFORCE_MODE n'est pas défini, argc et argv peuvent rediriger les handles standard pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, c'est une erreur pour argc et argv de rediriger les canaux standard pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le canal nouvellement créé n'est pas enregistré auprès de l'interpréteur fourni ; pour l'enregistrer, il faut utiliser Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'affecte également en tant que remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un handle de fichier existant, spécifique au système d'exploitation. Le canal nouvellement créé n'est pas enregistré auprès de l'interpréteur fourni ; pour l'enregistrer, il faut utiliser Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'affecte également en tant que remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel renvoie un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur dans interp. Si aucun canal enregistré dans cet interpréteur avec ce nom n'existe, la procédure renvoie NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtre ces noms en fonction du pattern. Si pattern est NULL, aucun filtrage n'est effectué. La valeur de retour est TCL_OK s'il n'y a pas eu d'erreurs lors de l'écriture dans le résultat, sinon TCL_ERROR et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal aux canaux accessibles dans interp. Après cet appel, les programmes exécutés dans cet interpréteur peuvent se référer au canal par le nom donné dans l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera automatiquement fermé lorsqu'il sera désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur peut appeler Tcl_RegisterChannel avec interp comme NULL, pour indiquer qu'il souhaite conserver une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur et ne sera fermé que lorsqu'un nombre d'appels à Tcl_UnregisterChannel égal au nombre d'appels à Tcl_RegisterChannel aura été effectué. Cela permet au code exécuté en dehors de tout interpréteur de conserver une référence sûre à un canal qui est également enregistré dans un interpréteur.

Cette procédure interagit avec le code qui gère les canaux standard. Si aucun canal standard n'est initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un aperçu des canaux standard et du comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel supprime un canal des canaux accessibles dans interp. Après cet appel, les programmes exécutés dans cet interpréteur ne pourront plus utiliser le nom du canal pour s'y référer dans cet interpréteur. Si cette opération supprime le dernier enregistrement du canal dans n'importe quel interpréteur, le canal sera également fermé et détruit.

Le code non associé à un interpréteur peut appeler Tcl_UnregisterChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne maintient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera maintenant fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel sauf qu'il ferme également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel supprime un canal des canaux accessibles dans interp. Après cet appel, les programmes exécutés dans cet interpréteur ne pourront plus utiliser le nom du canal pour s'y référer dans cet interpréteur. Au-delà de cela, cette commande n'a aucun effet supplémentaire. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin), et renverra TCL_ERROR si elle est appelée avec l'un de ces canaux.

Le code non associé à un interpréteur peut appeler Tcl_DetachChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne maintient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel vérifie si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. Si c'est le cas, il renvoie 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lors de l'appel à Tcl_Close. Les données de sortie mises en mémoire tampon sont envoyées au périphérique de sortie du canal avant la destruction du canal, et toutes les données d'entrée mises en mémoire tampon sont ignorées. S'il s'agit d'un canal bloquant, l'appel ne renvoie pas tant que toutes les données mises en mémoire tampon n'ont pas été envoyées au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a des données de sortie mises en mémoire tampon qui ne peuvent pas être écrites sans bloquer, l'appel renvoie immédiatement ; les données sont envoyées en arrière-plan et le canal sera fermé une fois que toutes les données mises en mémoire tampon auront été envoyées. Dans ce cas, les erreurs lors du nettoyage ne sont pas signalées.

Si le canal a été fermé correctement, Tcl_Close renvoie TCL_OK. Si une erreur se produit, Tcl_Close renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré à l'aide de Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devez utiliser Tcl_UnregisterChannel, qui appellera Tcl_Close en interne lorsque tous les appels à Tcl_RegisterChannel auront été mis en correspondance par des appels à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, les convertit en UTF-8 selon l'encodage du canal et stocke les données produites dans la représentation chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

L'instruction c

TCL_READCHARS, TCL_READOBJ, ET TCL_READ

Définir harsToRead sur -1 amènera la commande à lire tous les caractères actuellement disponibles (mode non bloquant) ou tout jusqu'à EOF (mode bloquant).

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé étaient disponibles. C'est ce qu'on appelle une lecture courte. En mode bloquant, cela ne peut se produire qu'à la fin du fichier. En mode non bloquant, une lecture courte peut également se produire s'il n'y a pas assez d'entrée actuellement disponible : Tcl_ReadChars renvoie un nombre limité plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour savoir laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les diverses représentations de fin de ligne en la représentation interne canonique \n selon le mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les divers modes spécifiques à la plateforme sont décrits dans l'entrée du manuel de la commande Tcl fconfigure.

Par optimisation des performances, lors de la lecture à partir d'un canal avec l'encodage binary, les octets ne sont pas convertis en UTF-8 lorsqu'ils sont lus. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr en tant que valeur de tableau d'octets. La représentation sous forme de chaîne de cette valeur ne sera construite que si nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette façon, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites vers un canal sans les frais de conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'il ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déconseillé et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Il consomme des octets du channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par un caractère nul. Son contenu est valide à partir de la position zéro jusqu'à, mais sans inclure, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas l'empilement. Alors que Tcl_Read (et les autres fonctions de l'API) obtiennent toujours leurs données du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_ReadRaw ne le fait pas. Par conséquent, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données du canal inférieur dans la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, convertissant les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée ait été vue. Si l'encodage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception des caractères de fin de ligne terminaux, sont ajoutés à la représentation de chaîne de lineObjPtr. Les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. En cas d'erreur, Tcl_GetsObj renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj renvoie également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 s'il n'y avait pas de données disponibles ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est renvoyé, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité des entrées.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique fournie par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, à la tête ou à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si channel a un EOF "collant" défini, aucune donnée ne sera ajoutée à la file d'entrée. Tcl_Ungets renvoie inputLen ou -1 en cas d'erreur.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données caractères à charBuf. Les caractères UTF-8 du tampon sont convertis selon l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par un caractère nul et il sortira tout jusqu'au caractère nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal sur none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est le nombre d'octets qui ont été acceptés pour la sortie vers le canal. Il s'agit soit d'un nombre supérieur à zéro pour indiquer le succès, soit de -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme selon l'option -translation pour le canal. Cela est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'il accepte une valeur Tcl dont le contenu sera sorti vers le canal. Les caractères UTF-8 de la représentation de chaîne de writeObjPtr sont convertis selon l'encodage du canal et mis en file d'attente pour la sortie vers channel. Par optimisation des performances, lors de l'écriture vers un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lorsqu'ils sont écrits. Au lieu de cela, les octets de la représentation interne de writeObjPtr en tant que valeur de tableau d'octets sont écrits sur le canal. La représentation de tableau d'octets de la valeur sera construite si elle est nécessaire. De cette façon, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites sur un canal sans les frais de conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'il ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déconseillé et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par un caractère nul et il sortira tout jusqu'au caractère nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_WriteRaw ne le fait pas. Par conséquent, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation dans le canal inférieur.

TCL_FLUSH

Tcl_Flush provoque l'écriture immédiate de toutes les données de sortie mises en tampon pour channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne revient pas tant que toutes les données mises en tampon n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel revient immédiatement si le canal n'est pas bloquant ; il démarre un vidage en arrière-plan qui écrira les données mises en tampon dans le canal éventuellement, aussi rapidement que le canal pourra les absorber.

La valeur de retour est normalement TCL_OK. En cas d'erreur, Tcl_Flush renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données ultérieures seront lues ou écrites. La sortie mise en tampon est vidée vers le canal et l'entrée mise en tampon est rejetée, avant l'opération de recherche.

Tcl_Seek renvoie normalement le nouveau point d'accès. En cas d'erreur, Tcl_Seek renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut ou peut ne pas avoir été déplacé.

TCL_TELL

Tcl_Tell renvoie le point d'accès actuel d'un canal. La valeur renvoyée est -1 si le canal ne prend pas en charge la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent de channel à une longueur donnée de length octets. Il renvoie TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, c'est le nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue

Tcl_OpenCommandChannel(3) — Tcl

NAME

Tcl_OpenCommandChannel — ouvre et configure un canal, et le rend disponible pour les commandes de bas niveau.

SYNOPSIS

#include <tcl.h>

Tcl_Channel
Tcl_OpenCommandChannel(interp, name, readCmd, writeCmd, deleteCmd)

ARGUMENTS

Tcl_Interp *interp
Interpréteur Tcl à utiliser pour les commandes.
const char *name
Nom du canal à créer.
const char *readCmd
Commande à exécuter pour lire à partir du canal.
const char *writeCmd
Commande à exécuter pour écrire dans le canal.
Tcl_CmdDeleteProc *deleteCmd
Procédure de suppression du gestionnaire de canal.

DESCRIPTION

La procédure Tcl_OpenCommandChannel crée un nouveau canal Tcl qui est implémenté à l'aide de commandes Tcl pour les opérations de lecture et d'écriture. Le canal est nommé name et est rendu disponible pour les commandes de bas niveau en utilisant les commandes spécifiées par readCmd et writeCmd. La procédure deleteCmd est appelée lorsque le canal est supprimé, afin de libérer les ressources associées.

Cette procédure est utile pour intégrer des systèmes externes qui utilisent des commandes pour les opérations d'entrée/sortie avec Tcl. Par exemple, un programme externe peut être lancé avec Tcl_CreateProcess, et un canal peut être créé pour communiquer avec les flux d'entrée et de sortie standard de ce processus en utilisant des commandes Tcl.

Une fois le canal créé, il peut être manipulé comme tout autre canal Tcl, en utilisant des commandes telles que Tcl_Read, Tcl_Write, Tcl_Close, etc.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier et renvoie un descripteur de canal Tcl. Le nom du fichier est spécifié par fileName et le mode d'accès par mode. Les modes d'accès sont similaires à ceux de la fonction C fopen (par exemple, "r", "w", "rb", "wb"). Si interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur en cas d'erreur.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel crée un canal utilisant des commandes Tcl pour les opérations d'E/S. Les commandes pour la lecture et l'écriture sont spécifiées par readCmd et writeCmd respectivement. Le canal est enregistré avec le nom name. deleteCmd est une procédure qui sera appelée lorsque le canal est supprimé.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un descripteur de canal Tcl à partir d'un descripteur de fichier existant (par exemple, un descripteur de fichier C ou un handle Windows). Le descripteur de fichier est spécifié par handle et le nom du canal par name. mask spécifie les opérations autorisées (lecture, écriture, ou les deux).

TCL_GETCHANNEL

Tcl_GetChannel renvoie le descripteur de canal Tcl correspondant au nom name dans l'interpréteur interp. Si aucun canal avec ce nom n'existe, NULL est renvoyé.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel enregistre un canal Tcl existant dans l'interpréteur interp sous le nom name. Ceci est utile pour rendre un canal créé en C disponible pour les commandes Tcl.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel supprime un canal enregistré de l'interpréteur interp. Le canal est également fermé.

TCL_DETACHCHANNEL

Tcl_DetachChannel détache un canal de l'interpréteur Tcl. Le canal n'est pas fermé, mais il n'est plus géré par Tcl. Ceci est utile lorsque vous voulez prendre le contrôle d'un canal Tcl et le gérer vous-même en C.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel renvoie vrai si le canal channel est l'un des canaux standards (stdin, stdout, stderr), faux sinon.

TCL_CLOSE

Tcl_Close ferme le canal channel. Toutes les données en attente dans les tampons de sortie sont vidées avant la fermeture. Si interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur en cas d'erreur.

TCL_READCHARS AND TCL_READ

Tcl_ReadChars lit jusqu'à numChars caractères du canal channel et les place dans le tampon buffer. Tcl_Read lit jusqu'à numBytes octets du canal channel et les place dans le tampon buffer. Ces fonctions gèrent le mode de blocage et non-blocage du canal, ainsi que les erreurs.

TCL_GETSOBJ AND TCL_GETS

Tcl_GetsObj lit une ligne complète du canal channel et la renvoie sous forme d'objet Tcl. Tcl_Gets lit une ligne complète du canal channel et la place dans le tampon buffer. Elles renvoient une valeur spéciale pour indiquer la fin de fichier.

TCL_UNGETS

Tcl_Ungets ajoute le contenu de la chaîne string au début du tampon d'entrée du canal channel. Ceci permet de réinsérer des données lues précédemment dans le flux d'entrée.

TCL_WRITECHARS, TCL_WRITEOBJ, AND TCL_WRITE

Tcl_WriteChars écrit les caractères de la chaîne string dans le canal channel. Tcl_WriteObj écrit le contenu d'un objet Tcl dans le canal channel. Tcl_Write écrit numBytes octets à partir du tampon byteConstPtr dans le canal channel. Ces fonctions gèrent les erreurs et le mode de blocage/non-blocage.

TCL_FLUSH

Tcl_Flush force l'écriture de toutes les données en attente dans les tampons de sortie du canal channel. Ceci est utile pour s'assurer que les données sont envoyées immédiatement au dispositif sous-jacent.

TCL_SEEK

Tcl_Seek modifie la position actuelle dans le canal channel. L'argument offset spécifie le nombre d'octets à déplacer, et mode indique si le déplacement est relatif au début du fichier (SEEK_SET), à la position actuelle (SEEK_CUR), ou à la fin du fichier (SEEK_END).

TCL_TELL

Tcl_Tell renvoie la position actuelle dans le canal channel.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier associé au canal channel à la position spécifiée par length.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère la valeur de l'option optionName pour le canal channel et la stocke dans le résultat de l'interpréteur interp. Si l'option n'existe pas ou si une erreur se produit, l'appel renvoie TCL_ERROR et un message d'erreur est laissé dans le résultat de l'interpréteur. Les options prédéfinies et leurs valeurs possibles sont décrites dans la page de manuel de la commande Tcl fconfigure. D'autres options peuvent être ajoutées par chaque type de canal. Ces options spécifiques au type de canal sont décrites dans la page de manuel de la commande Tcl qui crée un canal de ce type; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans la page de manuel de la commande Tcl socket. La procédure renvoie normalement TCL_OK. Si une erreur se produit, elle renvoie TCL_ERROR et appelle Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit une nouvelle valeur newValue pour une option optionName sur le canal channel. La procédure renvoie normalement TCL_OK. Si une erreur se produit, elle renvoie TCL_ERROR; de plus, si interp n'est pas NULL, Tcl_SetChannelOption laisse un message d'erreur dans le résultat de l'interpréteur.

TCL_EOF

Tcl_Eof renvoie une valeur non nulle si le canal channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked renvoie une valeur non nulle si le canal channel est en mode non bloquant et que la dernière opération d'entrée a renvoyé moins de données que demandé car il n'y avait pas suffisamment de données disponibles. L'appel renvoie toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered renvoie le nombre d'octets d'entrée actuellement mis en tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en lecture, cette fonction renvoie toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered renvoie le nombre d'octets de sortie actuellement mis en tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en écriture, cette fonction renvoie toujours zéro.

PROBLÈMES LIÉS À LA PLATEFORME

Les descripteurs renvoyés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que renvoyé par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel, ou Tcl_MakeFileChannel. D'autres types de canaux peuvent renvoyer un type de descripteur différent sur les plateformes Windows.
