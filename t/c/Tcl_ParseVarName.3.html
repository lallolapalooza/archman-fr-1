NOM

SYNOPIS

#include <tcl.h>

int
Tcl_ParseVarName(interp, start, numBytes, parsePtr, append)

const char *
Tcl_ParseVar(interp, start, termPtr)

Tcl_FreeParse(usedParsePtr)

Tcl_Obj *
Tcl_EvalTokens(interp, tokenPtr, numTokens)

int
Tcl_EvalTokensStandard(interp, tokenPtr, numTokens)

ARGUMENTS

Tcl_Interp *interp (out)
Pour les procédures autres que Tcl_FreeParse, Tcl_EvalTokens et Tcl_EvalTokensStandard, utilisé uniquement pour signaler les erreurs ; si NULL, alors aucun message d'erreur ne sera laissé après les erreurs. Pour Tcl_EvalTokens et Tcl_EvalTokensStandard, détermine le contexte pour évaluer le script et est également utilisé pour signaler les erreurs ; il ne doit pas être NULL.
const char *start (in)
Index du premier caractère dans la chaîne à analyser.
int numBytes (in)
Nombre d'octets dans la chaîne à analyser, sans inclure le caractère nul final. Si inférieur à 0, le script consiste en tous les caractères suivant start jusqu'au premier caractère nul.
int nested (in)
Si non nul, signifie que le script fait partie d'une substitution de commande, donc une accolade fermante non citée doit être traitée comme un terminateur de commande. Si nul, les accolades fermantes n'ont pas de signification spéciale.
int append (in)
Si non nul, signifie que *parsePtr contient déjà des jetons valides ; les nouveaux jetons doivent être ajoutés à ceux déjà présents. Si nul, signifie que *parsePtr est initialisé ; toute information qu'il contient est ignorée. Cet argument est normalement 0.
Tcl_Parse *parsePtr (out)
Pointe vers une structure qui sera remplie avec des informations sur la commande analysée, l'expression, le nom de variable, etc. Toute information précédente dans cette structure est ignorée, sauf si append est non nul dans un appel à Tcl_ParseBraces, Tcl_ParseQuotedString ou Tcl_ParseVarName.
const char **termPtr (out)
S'il n'est pas NULL, pointe vers un emplacement où Tcl_ParseBraces, Tcl_ParseQuotedString et Tcl_ParseVar stockeront un pointeur vers le caractère juste après le caractère de fin (l'accolade fermante, la fin du nom de variable ou la fin de la chaîne citée, respectivement) si l'analyse a réussi.
Tcl_Parse *usedParsePtr (in)
Pointe vers la structure qui a été remplie par un appel précédent à Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseVarName, etc.

DESCRIPTION

Ces procédures analysent des commandes Tcl ou des parties de commandes Tcl comme des expressions ou des références de variables. Chaque procédure prend un pointeur vers un script (ou une partie de celui-ci) et le remplit avec une collection de jetons décrivant les informations analysées. Les procédures renvoient normalement TCL_OK. Cependant, si une erreur se produit, elles renvoient TCL_ERROR, laissent un message d'erreur dans le résultat de interp (si interp n'est pas NULL) et ne laissent rien dans *parsePtr.

Tcl_ParseCommand est une procédure qui analyse des scripts Tcl. Étant donné un pointeur vers un script, elle analyse la première commande. Si la commande a été analysée avec succès, Tcl_ParseCommand renvoie TCL_OK et remplit avec des informations sur la structure de la commande (voir les détails ci-dessous). S'il y a eu une erreur d'analyse, elle renvoie TCL_ERROR, laisse un message d'erreur dans le résultat de interp et ne laisse rien dans *parsePtr.

Tcl_ParseExpr analyse des expressions Tcl. Étant donné un pointeur vers un script contenant une expression, Tcl_ParseExpr analyse l'expression. Si l'expression a été analysée avec succès, Tcl_ParseExpr renvoie TCL_OK et remplit avec des informations sur la structure de l'expression (voir les détails ci-dessous). S'il y a eu une erreur d'analyse, elle renvoie TCL_ERROR, laisse un message d'erreur dans le résultat de interp et ne laisse rien dans *parsePtr.

Tcl_ParseBraces analyse une chaîne ou un argument de commande entouré d'accolades, comme {bonjour} ou {chaîne \t avec \t tabulations}, à partir du début de son argument start. Le premier caractère de start doit être {. Si la chaîne entourée d'accolades a été analysée avec succès, Tcl_ParseBraces renvoie TCL_OK, remplit avec des informations sur la structure de la chaîne (voir les détails ci-dessous) et stocke un pointeur vers le caractère juste après l'accolade fermante à l'emplacement donné par *termPtr. Si une erreur se produit pendant l'analyse, elle renvoie TCL_ERROR, laisse un message d'erreur dans le résultat de interp et ne laisse rien dans *parsePtr ou *termPtr.

Tcl_ParseQuotedString analyse une chaîne entre guillemets doubles comme "la somme est [expr {$a+$b}]" à partir du début de l'argument start. Le premier caractère de start doit être ". Si la chaîne entre guillemets doubles a été analysée avec succès, Tcl_ParseQuotedString renvoie TCL_OK, remplit avec des informations sur la structure de la chaîne (voir les détails ci-dessous) et stocke un pointeur vers le caractère juste après le guillemet fermant à l'emplacement donné par *termPtr. Si une erreur se produit pendant l'analyse, elle renvoie TCL_ERROR, laisse un message d'erreur dans le résultat de interp et ne laisse rien dans *parsePtr ou *termPtr.

Tcl_ParseVarName analyse une référence de variable Tcl comme $abc ou $x([expr {$index + 1}]) à partir du début de l'argument start. Le premier caractère de start doit être $. Si la variable a été analysée avec succès, Tcl_ParseVarName renvoie TCL_OK et remplit avec des informations sur la structure du nom de variable (voir les détails ci-dessous). Si une erreur se produit pendant l'analyse, elle renvoie TCL_ERROR, laisse un message d'erreur dans le résultat de interp (si interp n'est pas NULL) et ne laisse rien dans *parsePtr.

Tcl_ParseVar analyse une référence de variable Tcl comme $abc ou $x([expr {$index + 1}]) à partir du début de l'argument start. Le premier caractère de start doit être $. Si la variable a été analysée avec succès, elle renvoie un pointeur vers la valeur de la variable. Si une erreur se produit pendant l'analyse, elle renvoie NULL et laisse un message d'erreur dans le résultat de interp.

Les informations dans *parsePtr de Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString et Tcl_ParseVarName peuvent inclure de la mémoire dynamique. Si ces cinq procédures d'analyse renvoient TCL_OK, l'appelant doit invoquer Tcl_FreeParse pour libérer la mémoire dans *parsePtr. Ces procédures ignorent toute information existante dans *parsePtr (sauf si append est non nul), donc si plusieurs appels sont effectués à l'une d'entre elles, Tcl_FreeParse doit être invoqué une fois après chaque appel.

Tcl_EvalTokensStandard évalue un ensemble de jetons analysés à partir d'une structure Tcl. Les jetons typiques consistent en tous les jetons d'un mot ou tous les jetons qui composent l'index d'une référence de variable de type tableau. Tcl_EvalTokensStandard effectue les substitutions requises par les jetons et concatène les valeurs résultantes. La valeur de retour de Tcl_EvalTokensStandard est un code d'achèvement Tcl avec l'une des valeurs TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK, TCL_CONTINUE, ou une valeur entière potentielle provenant d'une extension. De plus, une valeur de résultat ou un message d'erreur est laissé dans le résultat de interp ; il peut être récupéré en utilisant Tcl_GetObjResult.

Tcl_EvalTokens diffère de Tcl_EvalTokensStandard uniquement par sa valeur de retour.

STRUCTURE DE PARSE TCL

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, et Tcl_ParseVarName retournent des informations d'analyse dans deux structures de données, Tcl_Parse et Tcl_Token :

typedef struct Tcl_Parse {
    const char *commentStart;
    int commentSize;
    const char *commandStart;
    int commandSize;
    int numWords;
    Tcl_Token *tokenPtr;
    int numTokens;
    ...
} Tcl_Parse;
typedef struct Tcl_Token {
    int type;
    const char *start;
    int size;
    int numComponents;
} Tcl_Token;

Les cinq premiers champs d'une structure Tcl_Parse sont remplis uniquement par Tcl_ParseCommand. Ces champs ne sont pas utilisés par les autres procédures d'analyse.

Tcl_ParseCommand remplit une structure Tcl_Parse avec des informations qui décrivent une commande Tcl et tous les commentaires qui précèdent la commande. S'il y a des commentaires, le champ commentStart pointe vers le caractère # qui commence le premier commentaire et commentSize indique le nombre d'octets dans tous les commentaires précédant la commande, y compris le caractère de nouvelle ligne qui termine le dernier commentaire. Si la commande n'est pas précédée de commentaires, commentSize est égal à 0. Tcl_ParseCommand définit également le champ commandStart pour pointer vers le premier caractère du premier mot de la commande (en sautant les commentaires et les espaces de début) et commandSize donne le nombre total d'octets dans la commande, y compris le caractère pointé par commandStart jusqu'au caractère de nouvelle ligne, de crochet fermant ou de point-virgule qui termine la commande, inclus. Le champ numWords donne le nombre total de mots dans la commande.

Toutes les procédures d'analyse définissent les champs restants, tokenPtr et numTokens. Le champ tokenPtr pointe vers le début d'un tableau de structures Tcl_Token qui décrivent les composants de l'entité analysée. Le champ numTokens donne le nombre total de jetons présents dans le tableau. Chaque jeton contient quatre champs. Le champ type sélectionne l'un des plusieurs types de jetons décrits ci-dessous. Le champ start pointe vers le premier caractère du jeton et le champ size donne le nombre total de caractères dans le jeton. Certains types de jetons, tels que TCL_TOKEN_WORD et TCL_TOKEN_VARIABLE, sont constitués de plusieurs jetons composants, qui suivent immédiatement le jeton parent ; le champ numComponents décrit combien il y en a. Le champ type a l'une des valeurs suivantes :

TCL_TOKEN_WORD
Ce jeton décrit normalement un mot d'une commande, mais il peut aussi décrire une chaîne entre guillemets ou accolades dans une expression. Le jeton décrit un composant du script qui est le résultat de la concaténation d'une séquence de sous-composants, chacun décrit par un sous-jeton distinct. Le jeton commence par le premier caractère non blanc du composant (qui peut être un guillemet double ou une accolade ouvrante) et inclut tous les caractères du composant jusqu'au caractère d'espace, point-virgule, crochet fermant, guillemet fermant ou accolade fermante qui termine le composant, sans l'inclure. Le champ numComponents compte le nombre total de sous-jetons qui composent le mot, y compris les sous-jetons des jetons TCL_TOKEN_VARIABLE et TCL_TOKEN_BS.
TCL_TOKEN_SIMPLE_WORD
Ce jeton a la même signification que TCL_TOKEN_WORD, à la différence près que le mot est garanti de consister en un seul sous-jeton TCL_TOKEN_TEXT. Le champ numComponents est toujours 1.
TCL_TOKEN_EXPAND_WORD
Ce jeton a la même signification que TCL_TOKEN_WORD, à la différence près que l'analyseur de commandes note que ce mot a commencé par le préfixe d'expansion {*}, indiquant qu'après substitution, la valeur de liste de ce mot doit être étendue pour former plusieurs arguments lors de l'évaluation de la commande. Ce type de jeton ne peut être créé que par Tcl_ParseCommand.
TCL_TOKEN_TEXT
Le jeton décrit une plage de texte littéral faisant partie d'un mot. Le champ numComponents est toujours 0.
TCL_TOKEN_BS
Le jeton décrit une séquence d'échappement par barre oblique inverse telle que \n ou \0xA3. Le champ numComponents est toujours 0.
TCL_TOKEN_COMMAND
Le jeton décrit une commande dont le résultat doit être substitué dans le mot. Le jeton inclut les crochets qui entourent la commande. Le champ numComponents est toujours 0 (la commande imbriquée n'est pas analysée ; appelez Tcl_ParseCommand récursivement si vous souhaitez voir ses jetons).
TCL_TOKEN_VARIABLE
Le jeton décrit une substitution de variable, y compris le signe $, le nom de la variable et l'indice du tableau (s'il y en a un) jusqu'au parenthèse fermante qui termine l'indice. Ce jeton est suivi d'un ou plusieurs jetons supplémentaires qui décrivent le nom de la variable et l'indice du tableau. Si numComponents est égal à 1, la variable est un scalaire et le jeton suivant est un jeton TCL_TOKEN_TEXT qui donne le nom de la variable. Si numComponents est supérieur à 1, la variable est un tableau : le premier sous-jeton est un jeton TCL_TOKEN_TEXT donnant le nom du tableau et les sous-jetons restants sont des jetons TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND et TCL_TOKEN_VARIABLE qui doivent être concaténés pour produire l'indice du tableau. Le champ numComponents inclut les sous-jetons imbriqués faisant partie des jetons TCL_TOKEN_VARIABLE dans l'indice du tableau.
TCL_TOKEN_SUB_EXPR
Le jeton décrit une sous-expression d'une expression (ou une expression entière). Une sous-expression peut consister en une valeur telle qu'une constante entière, une substitution de variable ou une sous-expression entre parenthèses ; elle peut également consister en un opérateur et ses opérandes. Le jeton commence par le premier caractère non blanc de la sous-expression jusqu'au caractère d'espace, d'accolade, de parenthèse fermante ou de crochet fermant qui termine la sous-expression, sans l'inclure. Ce jeton est suivi d'un ou plusieurs jetons supplémentaires qui décrivent la sous-expression. Si le premier sous-jeton après le jeton TCL_TOKEN_SUB_EXPR est un jeton TCL_TOKEN_OPERATOR, la sous-expression consiste en un opérateur et ses opérandes en jetons. Si l'opérateur n'a pas d'opérandes, la sous-expression consiste uniquement en le jeton TCL_TOKEN_OPERATOR. Chaque opérande est décrit par un jeton TCL_TOKEN_SUB_EXPR. Sinon, la sous-expression est une valeur décrite par l'un des types de jetons TCL_TOKEN_WORD, TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, TCL_TOKEN_VARIABLE et TCL_TOKEN_SUB_EXPR. Le champ numComponents compte le nombre total de sous-jetons qui composent la sous-expression ; cela inclut les sous-jetons des jetons TCL_TOKEN_SUB_EXPR imbriqués.
TCL_TOKEN_OPERATOR
Le jeton décrit un opérateur d'une expression tel que && ou hypot. Un jeton TCL_TOKEN_OPERATOR est toujours précédé d'un jeton TCL_TOKEN_SUB_EXPR qui décrit l'opérateur et ses opérandes ; le champ numComponents du jeton TCL_TOKEN_SUB_EXPR peut être utilisé pour déterminer le nombre d'opérandes. Un opérateur binaire tel que * est suivi de deux jetons TCL_TOKEN_SUB_EXPR qui décrivent ses opérandes. Un opérateur unaire comme - est suivi d'un seul jeton TCL_TOKEN_SUB_EXPR pour son opérande. Si l'opérateur est une fonction mathématique telle que log10, le jeton TCL_TOKEN_OPERATOR donnera son nom et les jetons TCL_TOKEN_SUB_EXPR suivants décriront ses opérandes ; s'il n'y a pas d'opérandes (comme avec rand), aucun jeton TCL_TOKEN_SUB_EXPR ne suit. Il existe un opérateur ternaire, ?, qui apparaît dans les sous-expressions if-then-else telles que x?y:z ; dans ce cas, le jeton TCL_TOKEN_OPERATOR ? est suivi de trois jetons TCL_TOKEN_SUB_EXPR pour les opérandes x, y et z. Le champ numComponents pour un jeton TCL_TOKEN_OPERATOR est toujours 0.

Après le retour de Tcl_ParseCommand, le premier jeton pointé par le champ tokenPtr de la structure Tcl_Parse est toujours de type TCL_TOKEN_WORD ou TCL_TOKEN_SIMPLE_WORD ou TCL_TOKEN_EXPAND_WORD. Il est suivi des sous-jetons qui doivent être concaténés pour produire la valeur de ce mot. Le jeton suivant est le jeton TCL_TOKEN_WORD ou TCL_TOKEN_SIMPLE_WORD ou TCL_TOKEN_EXPAND_WORD du deuxième mot, suivi des sous-jetons pour ce mot, et ainsi de suite jusqu'à ce que les numWords aient été pris en compte.

Après le retour de Tcl_ParseExpr, le premier jeton pointé par le champ tokenPtr de la structure Tcl_Parse est toujours de type TCL_TOKEN_SUB_EXPR. Il est suivi des sous-jetons qui doivent être évalués pour produire la valeur de l'expression. Seules les informations de jetons dans la structure Tcl_Parse sont modifiées : les champs commentStart, commentSize, commandStart et commandSize ne sont pas modifiés par Tcl_ParseExpr.

Après le retour de Tcl_ParseBraces, le tableau de jetons pointé par le champ tokenPtr de la structure Tcl_Parse contiendra un seul jeton TCL_TOKEN_TEXT si la chaîne entre accolades ne contient aucun saut de ligne précédé d'une barre oblique inverse. Si la chaîne contient des sauts de ligne précédés d'une barre oblique inverse, le tableau de jetons contiendra un ou plusieurs sous-jetons TCL_TOKEN_TEXT ou TCL_TOKEN_BS qui doivent être concaténés pour produire la valeur de la chaîne. Si la chaîne entre accolades était simplement {} (c'est-à-dire que la chaîne était vide), le seul jeton TCL_TOKEN_TEXT aura un champ size contenant zéro ; cela garantit qu'au moins un jeton apparaît pour décrire la chaîne entre accolades. Tcl_ParseVarName(3) - Tcl

NAME

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, Tcl_ParseVarName - generic Tcl parser routines

SYNOPSIS

#include <tcl.h>

int
Tcl_ParseCommand(interp, start, end, parsePtr);
int
Tcl_ParseExpr(interp, start, end, parsePtr);
int
Tcl_ParseBraces(interp, start, end, parsePtr);
int
Tcl_ParseQuotedString(interp, start, end, parsePtr);
int
Tcl_ParseVarName(interp, start, end, parsePtr);

ARGUMENTS

in
Tcl_Interp *interp
Tcl_Token *tokenPtr (in Tcl_Parse structure)
in/out
char *start
char *end
Tcl_Parse *parsePtr

DESCRIPTION

These functions are low-level routines used internally by Tcl to parse commands, expressions, quoted strings, and variable names. They are not intended for use by application programmers, but they may be useful for implementing new Tcl commands or extensions that need to understand Tcl syntax.

The functions all take an interpreter (interp), a starting character pointer (start), and an ending character pointer (end) which delimit the characters to be parsed. They fill in the Tcl_Parse structure pointed to by parsePtr with information about the parsed structure. The Tcl_Parse structure is defined in <tcl.h> as:

typedef struct Tcl_Parse {
    Tcl_Interp *interp;       // Interpreter being used.
    char *bufferStart;        // Start of the string being parsed.
    char *bufferEnd;          // End of the string being parsed.
    int numTokens;            // Number of tokens in the token array.
    Tcl_Token *tokenPtr;      // Pointer to the first token in the array.
    // ... additional fields for private use ...
} Tcl_Parse;

The functions return an integer code: TCL_OK if the parsing was successful, or TCL_ERROR if there was a syntax error. If an error occurs, the interpreter's result will contain an error message.

The Tcl_Parse structure contains an array of Tcl_Token structures, starting at the tokenPtr field. This array describes the parsed structure in terms of sub-tokens. Each token is defined as:

typedef struct Tcl_Token {
    char *start;     // Pointer to the start of the token within the
                        // original string.
    int size;        // Length of the token.
    int type;        // Type of the token.
} Tcl_Token;

The possible token types are:

TCL_TOKEN_TEXT
A piece of plain text.
TCL_TOKEN_SPACE
Whitespace characters.
TCL_TOKEN_COMMAND
A command substitution (e.g., `command`).
TCL_TOKEN_VARIABLE
A variable substitution (e.g., $var or ${var}).
TCL_TOKEN_SUBST
A substitution that needs further processing (e.g., escape sequences).
TCL_TOKEN_ESCMARK
A character that was escaped with a backslash.
TCL_TOKEN_BS
A backslash character.
TCL_TOKEN_QUOTED
A double-quoted string.
TCL_TOKEN_BRACKETS
A braced string.
TCL_TOKEN_TERM
A terminating character (e.g., a newline or semicolon).

The exact set of token types generated depends on the function being called.

After Tcl_ParseCommand returns, the tokenPtr field points to an array of tokens describing the command. The first token is always a TCL_TOKEN_TEXT token representing the command name, followed by tokens describing the arguments. The numTokens field indicates the total number of tokens in the array.

After Tcl_ParseExpr returns, the tokenPtr field points to an array of tokens describing the expression. The tokens represent the components of the expression, such as operators, operands, and substitutions.

After Tcl_ParseBraces returns, the tokenPtr field points to an array of tokens describing the braced string. The array will consist of one or more TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, and TCL_TOKEN_VARIABLE sub-tokens. The array always contains at least one token; for example, if the argument start is empty, the array returned consists of a single TCL_TOKEN_TEXT token with a zero size field. Only the token information in the Tcl_Parse structure is modified: the commentStart, commentSize, commandStart, and commandSize fields are not modified by Tcl_ParseBraces.

After Tcl_ParseQuotedString returns, the array of tokens pointed to by the tokenPtr field of the Tcl_Parse structure depends on the contents of the quoted string. It will consist of one or more TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, and TCL_TOKEN_VARIABLE sub-tokens. The array always contains at least one token; for example, if the argument start is empty, the array returned consists of a single TCL_TOKEN_TEXT token with a zero size field. Only the token information in the Tcl_Parse structure is modified: the commentStart, commentSize, commandStart, and commandSize fields are not modified.

After Tcl_ParseVarName returns, the first token pointed to by the tokenPtr field of the Tcl_Parse structure always has type TCL_TOKEN_VARIABLE. It is followed by the sub-tokens that make up the variable name as described above. The total length of the variable name is contained in the size field of the first token. As in Tcl_ParseExpr, only the token information in the Tcl_Parse structure is modified by Tcl_ParseVarName: the commentStart, commentSize, commandStart, and commandSize fields are not modified.

All of the character pointers in the Tcl_Parse and Tcl_Token structures refer to characters in the start argument passed to Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, and Tcl_ParseVarName.

There are additional fields in the Tcl_Parse structure after the numTokens field, but these are for the private use of Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, and Tcl_ParseVarName; they should not be referenced by code outside of these procedures.

backslash substitution, braces, command, expression, parse, token, variable substitution
