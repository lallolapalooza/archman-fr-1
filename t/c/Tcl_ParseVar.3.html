Tcl_ParseCommand(3) Procédures de la bibliothèque Tcl Tcl_ParseCommand(3)

NOM

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, Tcl_ParseVarName, Tcl_ParseVar, Tcl_FreeParse, Tcl_EvalTokens, Tcl_EvalTokensStandard - analyse des scripts et expressions Tcl

SYNOPSIS

#include <tcl.h>

int
Tcl_ParseCommand(interp, start, numBytes, nested, parsePtr)

int
Tcl_ParseExpr(interp, start, numBytes, parsePtr)

int
Tcl_ParseBraces(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseQuotedString(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseVarName(interp, start, numBytes, parsePtr, append)

const char *
Tcl_ParseVar(interp, start, termPtr)

Tcl_FreeParse(usedParsePtr)

Tcl_Obj *
Tcl_EvalTokens(interp, tokenPtr, numTokens)

int
Tcl_EvalTokensStandard(interp, tokenPtr, numTokens)

ARGUMENTS

Tcl_Interp *interp (out)
Pour les procédures autres que Tcl_FreeParse, Tcl_EvalTokens et Tcl_EvalTokensStandard, utilisé uniquement pour la signalisation d'erreur ; si NULL, aucun message d'erreur n'est laissé après les erreurs. Pour Tcl_EvalTokens et Tcl_EvalTokensStandard, détermine le contexte pour l'évaluation du script et est également utilisé pour la signalisation d'erreur ; ne doit pas être NULL.
const char *start (in)
Pointeur vers le premier caractère de la chaîne à analyser.
int numBytes (in)
Nombre d'octets dans la chaîne à analyser, sans inclure le caractère nul de terminaison. S'il est inférieur à 0, le script se compose de tous les caractères suivant start jusqu'au premier caractère nul.
int nested (in)
Si différent de zéro, cela signifie que le script fait partie d'une substitution de commande, de sorte qu'une parenthèse fermante non citée doit être traitée comme un terminateur de commande. Si zéro, les parenthèses fermantes n'ont pas de signification spéciale.
int append (in)
Si différent de zéro, cela signifie que *parsePtr contient déjà des jetons valides ; les nouveaux jetons doivent être ajoutés à ceux déjà présents. Zéro signifie que *parsePtr n'est pas initialisé ; toute information qu'il contient est ignorée. Cet argument est normalement 0.
Tcl_Parse *parsePtr (out)
Pointe vers la structure à remplir avec des informations sur la commande analysée, l'expression, le nom de la variable, etc. Toute information précédente dans cette structure est ignorée, sauf si append est différent de zéro dans un appel à Tcl_ParseBraces, Tcl_ParseQuotedString ou Tcl_ParseVarName.
const char **termPtr (out)
S'il n'est pas NULL, pointe vers un emplacement où Tcl_ParseBraces, Tcl_ParseQuotedString et Tcl_ParseVar stockeront un pointeur vers le caractère juste après le caractère de terminaison (l'accolade fermante, le dernier caractère du nom de la variable ou la guillemet fermant (respectivement)) si l'analyse a réussi. S'il est NULL, le caractère de terminaison n'est pas renvoyé.
Tcl_Parse *usedParsePtr (in)
Pointe vers la structure qui a été remplie par un appel précédent à Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseVarName, etc.

DESCRIPTION

Ces procédures analysent les commandes Tcl ou des parties de commandes Tcl telles que des expressions ou des références à des variables. Chaque procédure prend un pointeur vers un script (ou une partie de celui-ci) et remplit la structure pointée par parsePtr avec une collection de jetons décrivant les informations qui ont été analysées. Les procédures renvoient normalement TCL_OK. Cependant, si une erreur se produit, elles renvoient TCL_ERROR, laissent un message d'erreur dans le résultat d'interp (si interp n'est pas NULL), et ne laissent rien dans parsePtr.

Tcl_ParseCommand est une procédure qui analyse les scripts Tcl. Étant donné un pointeur vers un script, elle analyse la première commande du script. Si la commande a été analysée avec succès, Tcl_ParseCommand renvoie TCL_OK et remplit la structure pointée par parsePtr avec des informations sur la structure de la commande (voir ci-dessous pour les détails). Si une erreur s'est produite lors de l'analyse de la commande, TCL_ERROR est renvoyé, un message d'erreur est laissé dans le résultat d'interp, et aucune information n'est laissée dans *parsePtr.

Tcl_ParseExpr analyse les expressions Tcl. Étant donné un pointeur vers un script contenant une expression, Tcl_ParseExpr analyse l'expression. Si l'expression a été analysée avec succès, Tcl_ParseExpr renvoie TCL_OK et remplit la structure pointée par parsePtr avec des informations sur la structure de l'expression (voir ci-dessous pour les détails). Si une erreur s'est produite lors de l'analyse de la commande, TCL_ERROR est renvoyé, un message d'erreur est laissé dans le résultat d'interp, et aucune information n'est laissée dans *parsePtr.

Tcl_ParseBraces analyse une chaîne ou un argument de commande entre accolades comme {bonjour} ou {chaîne \t avec \t tabulations} depuis le début de son argument start. Le premier caractère de start doit être {. Si la chaîne entre accolades a été analysée avec succès, Tcl_ParseBraces renvoie TCL_OK, remplit la structure pointée par parsePtr avec des informations sur la structure de la chaîne (voir ci-dessous pour les détails), et stocke un pointeur vers le caractère juste après le } de terminaison à l'emplacement indiqué par *termPtr. Si une erreur se produit lors de l'analyse de la chaîne, TCL_ERROR est renvoyé, un message d'erreur est laissé dans le résultat d'interp, et aucune information n'est laissée dans *parsePtr ou *termPtr.

Tcl_ParseQuotedString analyse une chaîne entre guillemets doubles comme "la somme est [expr {$a+$b}]" depuis le début de l'argument start. Le premier caractère de start doit être ". Si la chaîne entre guillemets doubles a été analysée avec succès, Tcl_ParseQuotedString renvoie TCL_OK, remplit la structure pointée par parsePtr avec des informations sur la structure de la chaîne (voir ci-dessous pour les détails), et stocke un pointeur vers le caractère juste après le " de terminaison à l'emplacement indiqué par *termPtr. Si une erreur se produit lors de l'analyse de la chaîne, TCL_ERROR est renvoyé, un message d'erreur est laissé dans le résultat d'interp, et aucune information n'est laissée dans *parsePtr ou *termPtr.

Tcl_ParseVarName analyse une référence de variable Tcl comme $abc ou $x([expr {$index + 1}]) depuis le début de son argument start. Le premier caractère de start doit être $. Si un nom de variable a été analysé avec succès, Tcl_ParseVarName renvoie TCL_OK et remplit la structure pointée par parsePtr avec des informations sur la structure du nom de la variable (voir ci-dessous pour les détails). Si une erreur se produit lors de l'analyse de la commande, TCL_ERROR est renvoyé, un message d'erreur est laissé dans le résultat d'interp (si interp n'est pas NULL), et aucune information n'est laissée dans *parsePtr.

Tcl_ParseVar analyse une référence de variable Tcl comme $abc ou $x([expr {$index + 1}]) depuis le début de son argument start. Le premier caractère de start doit être $. Si le nom de la variable est analysé avec succès, Tcl_ParseVar renvoie un pointeur vers la valeur chaîne de la variable. Si une erreur se produit lors de l'analyse, NULL est renvoyé et un message d'erreur est laissé dans le résultat d'interp.

Les informations laissées dans *parsePtr par Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString et Tcl_ParseVarName peuvent inclure de la mémoire allouée dynamiquement. Si ces cinq procédures d'analyse renvoient TCL_OK, l'appelant doit invoquer Tcl_FreeParse pour libérer le stockage dans *parsePtr. Ces procédures ignorent toute information existante dans *parsePtr (sauf si append est différent de zéro), donc si des appels répétés sont effectués à l'une d'entre elles, Tcl_FreeParse doit être invoqué une fois après chaque appel.

Tcl_EvalTokensStandard évalue une séquence de jetons d'analyse provenant d'une structure Tcl_Parse. Les jetons consistent typiquement en tous les jetons d'un mot ou tous les jetons qui composent l'indice d'une référence à une variable de tableau. Tcl_EvalTokensStandard effectue les substitutions demandées par les jetons et concatène les valeurs résultantes. La valeur de retour de Tcl_EvalTokensStandard est un code de complétion Tcl avec l'une des valeurs TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK, ou TCL_CONTINUE, ou potentiellement une autre valeur entière provenant d'une extension. De plus, une valeur de résultat ou un message d'erreur est laissé dans le résultat d'interp ; il peut être récupéré à l'aide de Tcl_GetObjResult.

Tcl_EvalTokens diffère de Tcl_EvalTokensStandard uniquement par la convention de retour

n utilisé : il renvoie le résultat dans un nouveau Tcl_Obj. Le compteur de références de la valeur retournée comme résultat a été incrémenté, donc l'appelant doit invoquer Tcl_DecrRefCount lorsqu'il a terminé avec la valeur. Si une erreur ou une autre exception se produit lors de l'évaluation des jetons (comme une référence à une variable inexistante), la valeur de retour est NULL et un message d'erreur est laissé dans le résultat de interp. L'utilisation de Tcl_EvalTokens est déconseillée.

STRUCTURE DE PARSE TCL

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, et Tcl_ParseVarName renvoient des informations de parse dans deux structures de données, Tcl_Parse et Tcl_Token :

typedef struct Tcl_Parse {
    const char *commentStart;
    int commentSize;
    const char *commandStart;
    int commandSize;
    int numWords;
    Tcl_Token *tokenPtr;
    int numTokens;
    ...
} Tcl_Parse;
typedef struct Tcl_Token {
    int type;
    const char *start;
    int size;
    int numComponents;
} Tcl_Token;

Les cinq premiers champs d'une structure Tcl_Parse sont remplis uniquement par Tcl_ParseCommand. Ces champs ne sont pas utilisés par les autres procédures de parse.

Tcl_ParseCommand remplit une structure Tcl_Parse avec des informations décrivant une commande Tcl et tout commentaire qui précède la commande. S'il y a des commentaires, le champ commentStart pointe vers le caractère # qui commence le premier commentaire et commentSize indique le nombre d'octets dans tous les commentaires précédant la commande, y compris le caractère de nouvelle ligne qui termine le dernier commentaire. Si la commande n'est précédée d'aucun commentaire, commentSize est 0. Tcl_ParseCommand définit également le champ commandStart pour pointer vers le premier caractère du premier mot de la commande (en ignorant les commentaires et les espaces blancs en début de ligne) et commandSize donne le nombre total d'octets dans la commande, y compris le caractère pointé par commandStart jusqu'au caractère de nouvelle ligne, de crochet fermant ou de point-virgule qui termine la commande. Le champ numWords donne le nombre total de mots dans la commande.

Toutes les procédures de parse définissent les champs restants, tokenPtr et numTokens. Le champ tokenPtr pointe vers le premier d'un tableau de structures Tcl_Token qui décrivent les composants de l'entité en cours de parse. Le champ numTokens donne le nombre total de jetons présents dans le tableau. Chaque jeton contient quatre champs. Le champ type sélectionne l'un des plusieurs types de jetons décrits ci-dessous. Le champ start pointe vers le premier caractère du jeton et le champ size donne le nombre total de caractères dans le jeton. Certains types de jetons, tels que TCL_TOKEN_WORD et TCL_TOKEN_VARIABLE, sont constitués de plusieurs jetons composants, qui suivent immédiatement le jeton parent ; le champ numComponents décrit combien il y en a. Le champ type a l'une des valeurs suivantes :

TCL_TOKEN_WORD
Ce jeton décrit normalement un mot d'une commande, mais il peut aussi décrire une chaîne de caractères entre guillemets ou accolades dans une expression. Le jeton décrit un composant du script qui est le résultat de la concaténation d'une séquence de sous-composants, chacun décrit par un sous-jeton séparé. Le jeton commence par le premier caractère non blanc du composant (qui peut être une double-quote ou une accolade ouvrante) et inclut tous les caractères du composant jusqu'au caractère qui termine le composant (espace, point-virgule, crochet fermant, guillemet fermant ou accolade fermante), mais sans l'inclure. Le champ numComponents compte le nombre total de sous-jetons qui constituent le mot, y compris les sous-jetons des jetons TCL_TOKEN_VARIABLE et TCL_TOKEN_BS.
TCL_TOKEN_SIMPLE_WORD
Ce jeton a la même signification que TCL_TOKEN_WORD, à l'exception que le mot est garanti de consister en un seul sous-jeton TCL_TOKEN_TEXT. Le champ numComponents est toujours 1.
TCL_TOKEN_EXPAND_WORD
Ce jeton a la même signification que TCL_TOKEN_WORD, à l'exception que le parseur de commande note que ce mot a commencé par le préfixe d'expansion {*}, indiquant qu'après substitution, la valeur de liste de ce mot doit être développée pour former plusieurs arguments lors de l'évaluation de la commande. Ce type de jeton ne peut être créé que par Tcl_ParseCommand.
TCL_TOKEN_TEXT
Le jeton décrit une plage de texte littéral qui fait partie d'un mot. Le champ numComponents est toujours 0.
TCL_TOKEN_BS
Le jeton décrit une séquence d'échappement par antislash comme \n ou \0xA3. Le champ numComponents est toujours 0.
TCL_TOKEN_COMMAND
Le jeton décrit une commande dont le résultat doit être substitué dans le mot. Le jeton inclut les crochets qui entourent la commande. Le champ numComponents est toujours 0 (la commande imbriquée n'est pas parsée ; appelez Tcl_ParseCommand récursivement si vous souhaitez voir ses jetons).
TCL_TOKEN_VARIABLE
Le jeton décrit une substitution de variable, y compris le $, le nom de la variable et l'index du tableau (s'il y en a un) jusqu'à la parenthèse fermante qui termine l'index. Ce jeton est suivi d'un ou plusieurs jetons supplémentaires qui décrivent le nom de la variable et l'index du tableau. Si numComponents est 1, la variable est scalaire et le jeton suivant est un jeton TCL_TOKEN_TEXT qui donne le nom de la variable. Si numComponents est supérieur à 1, la variable est un tableau : le premier sous-jeton est un jeton TCL_TOKEN_TEXT donnant le nom du tableau et les sous-jetons restants sont des jetons TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, et TCL_TOKEN_VARIABLE qui doivent être concaténés pour produire l'index du tableau. Le champ numComponents inclut les sous-jetons imbriqués faisant partie des jetons TCL_TOKEN_VARIABLE dans l'index du tableau.
TCL_TOKEN_SUB_EXPR
Le jeton décrit une sous-expression d'une expression (ou une expression entière). Une sous-expression peut consister en une valeur telle qu'une littérale entière, une substitution de variable, ou une sous-expression entre parenthèses ; elle peut aussi consister en un opérateur et ses opérandes. Le jeton commence par le premier caractère non blanc de la sous-expression jusqu'au caractère qui termine la sous-expression (espace, accolade, parenthèse fermante ou crochet) sans l'inclure. Ce jeton est suivi d'un ou plusieurs jetons supplémentaires qui décrivent la sous-expression. Si le premier sous-jeton après le jeton TCL_TOKEN_SUB_EXPR est un jeton TCL_TOKEN_OPERATOR, la sous-expression consiste en un opérateur et ses opérandes jetons. Si l'opérateur n'a pas d'opérandes, la sous-expression consiste uniquement en le jeton TCL_TOKEN_OPERATOR. Chaque opérande est décrit par un jeton TCL_TOKEN_SUB_EXPR. Sinon, la sous-expression est une valeur décrite par l'un des types de jetons TCL_TOKEN_WORD, TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, TCL_TOKEN_VARIABLE, et TCL_TOKEN_SUB_EXPR. Le champ numComponents compte le nombre total de sous-jetons qui constituent la sous-expression ; cela inclut les sous-jetons pour les jetons TCL_TOKEN_SUB_EXPR imbriqués.
TCL_TOKEN_OPERATOR
Le jeton décrit un opérateur d'expression tel que && ou hypot. Un jeton TCL_TOKEN_OPERATOR est toujours précédé d'un jeton TCL_TOKEN_SUB_EXPR qui décrit l'opérateur et ses opérandes ; le champ numComponents du jeton TCL_TOKEN_SUB_EXPR peut être utilisé pour déterminer le nombre d'opérandes. Un opérateur binaire comme * est suivi de deux jetons TCL_TOKEN_SUB_EXPR qui décrivent ses opérandes. Un opérateur unaire comme - est suivi d'un seul jeton TCL_TOKEN_SUB_EXPR pour son opérande. Si l'opérateur est une fonction mathématique comme log10, le jeton TCL_TOKEN_OPERATOR donnera son nom et les jetons TCL_TOKEN_SUB_EXPR suivants décriront ses opérandes ; s'il n'y a pas d'opérandes (comme avec rand), aucun jeton TCL_TOKEN_SUB_EXPR ne suit. Il y a un opérateur ternaire, ?, qui apparaît dans les sous-expressions if-then-else comme x?y:z ; dans ce cas, le jeton ? TCL_TOKEN_OPERATOR est suivi de trois jetons TCL_TOKEN_SUB_EXPR pour les opérandes x, y, et z. Le champ numComponents pour un jeton TCL_TOKEN_OPERATOR est toujours 0.

Après le retour de Tcl_ParseCommand, le premier jeton pointé par le champ tokenPtr de la structure Tcl_Parse est toujours de type TCL_TOKEN_WORD ou TCL_TOKEN_SIMPLE_WORD ou TCL_TOKEN_EXPAND_WORD. Il est suivi des sous-jetons qui doivent être concaténés pour produire la valeur de ce mot. Le jeton suivant est le jeton TCL_TOKEN_WORD ou TCL_TOKEN_SIMPLE_WORD ou TCL_TOKEN_EXPAND_WORD du deuxième mot, suivi des sous-jetons pour ce mot, et ainsi de suite jusqu'à ce que tous les numWords aient été comptabilisés.

Après le retour de Tcl_ParseExpr, le premier jeton pointé par le champ tokenPtr de la structure Tcl_Parse est toujours de type TCL_TOKEN_SUB_EXPR. Il est suivi des sous-jetons qui doivent être évalués pour produire la valeur de l'expression. Seules les informations de jeton dans la structure Tcl_Parse sont modifiées : les champs commentStart, commentSize, commandStart, et commandSize ne sont pas modifiés par Tcl_ParseExpr.

Après le retour de Tcl_ParseBraces, le tableau de jetons pointé par le champ tokenPtr de la structure Tcl_Parse contiendra un unique jeton TCL_TOKEN_TEXT si la chaîne entre accolades ne contient aucun caractère de nouvelle ligne échappé. Si la chaîne contient des caractères de nouvelle ligne échappés, le tableau de jetons contiendra un ou plusieurs sous-jetons TCL_TOKEN_TEXT ou TCL_TOKEN_BS qui doivent être concaténés pour produire la valeur de la chaîne. Si la chaîne entre accolades était juste {} (c'est-à-dire, la chaîne était vide), l'unique jeton TCL_TOKEN_TEXT aura un champ size contenant zéro ; cela garantit qu'au moins un jeton apparaît pour décrire la chaîne entre accolades. Seules les informations de jeton dans la structure Tcl_Parse sont modifiées : les champs commentStart,commentSize, commandStart et commandSize ne sont pas modifiés par Tcl_ParseBraces.

Après le retour de Tcl_ParseQuotedString, le tableau de jetons pointé par le champ tokenPtr de la structure Tcl_Parse dépend du contenu de la chaîne entre guillemets. Il sera constitué d'un ou plusieurs sous-jetons de type TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND et TCL_TOKEN_VARIABLE. Le tableau contient toujours au moins un jeton ; par exemple, si l'argument start est vide, le tableau retourné consiste en un seul jeton de type TCL_TOKEN_TEXT avec un champ size nul. Seules les informations de jeton dans la structure Tcl_Parse sont modifiées : les champs commentStart, commentSize, commandStart et commandSize ne sont pas modifiés.

Après le retour de Tcl_ParseVarName, le premier jeton pointé par le champ tokenPtr de la structure Tcl_Parse a toujours le type TCL_TOKEN_VARIABLE. Il est suivi des sous-jetons qui composent le nom de la variable, comme décrit ci-dessus. La longueur totale du nom de la variable est contenue dans le champ size du premier jeton. Comme dans Tcl_ParseExpr, seules les informations de jeton dans la structure Tcl_Parse sont modifiées par Tcl_ParseVarName : les champs commentStart, commentSize, commandStart et commandSize ne sont pas modifiés.

Tous les pointeurs de caractères dans les structures Tcl_Parse et Tcl_Token font référence à des caractères dans l'argument start passé à Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString et Tcl_ParseVarName.

Il y a des champs supplémentaires dans la structure Tcl_Parse après le champ numTokens, mais ceux-ci sont réservés à l'usage privé de Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString et Tcl_ParseVarName ; ils ne doivent pas être référencés par du code extérieur à ces procédures.
