ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour le rapport d'erreurs et pour rechercher un canal enregistré dedans.
const char *fileName (in)
Le nom d'un fichier local ou réseau.
const char *mode (in)
Spécifie comment le fichier doit être accédé. Peut avoir n'importe laquelle des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (in)
Indicateurs de permission de style POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront définies sur le fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans option de la commande Tcl exec.
int flags (in)
Spécifie la disposition des descripteurs stdio dans le pipeline : combinaison par OU de TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, l'entrée standard du premier processus enfant dans le pipeline est le canal du pipeline, sinon elle est identique à l'entrée standard du processus appelant ; de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, alors le pipeline peut rediriger les descripteurs stdio pour outrepasser les descripteurs stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, alors de telles redirections provoquent une erreur.
ClientData handle (in)
Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, il s'agit d'un descripteur de fichier, pour Windows, il s'agit d'un HANDLE.
int readOrWrite (in)
Combinaison par OU de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Pointe vers une variable entière qui recevra une combinaison par OU de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (in)
Le motif à faire correspondre, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl pour l'entrée ou la sortie. Doit avoir été la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker les caractères lus depuis le canal.
int charsToRead (in)
Le nombre de caractères à lire depuis le canal. Si l'encodage du canal est binaire, cela équivaut au nombre d'octets à lire depuis le canal.
int appendFlag (in)
Si non nul, les données lues depuis le canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (out)
Un tampon dans lequel stocker les octets lus depuis le canal.
int bytesToRead (in)
Le nombre d'octets à lire depuis le canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker la ligne lue depuis le canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne dynamique Tcl dans laquelle stocker la ligne lue depuis le canal. Doit avoir été initialisée par l'appelant. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne dynamique.
const char *input (in)
L'entrée à ajouter à un tampon de canal.
int inputLen (in)
Longueur de l'entrée.
int addAtEnd (in)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon de canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera envoyé en sortie vers le canal.
const char *charBuf (in)
Un tampon contenant les caractères à envoyer en sortie vers le canal.
const char *byteBuf (in)
Un tampon contenant les octets à envoyer en sortie vers le canal.
int bytesToWrite (in)
Le nombre d'octets à consommer de charBuf ou byteBuf et à envoyer en sortie vers le canal.
Tcl_WideInt offset (in)
De combien déplacer le point d'accès dans le canal où la prochaine opération d'entrée ou de sortie sera appliquée, mesuré en octets à partir de la position donnée par seekMode. Peut être positif ou négatif.
int seekMode (in)
Par rapport à quel point chercher ; utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs légales sont SEEK_SET, SEEK_CUR, et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) à laquelle tronquer le canal.
const char *optionName (in)
Le nom d'une option applicable à ce canal, telle que -blocking. Peut avoir n'importe laquelle des valeurs acceptées par la commande fconfigure.
Tcl_DString *optionValue (in)
Où stocker la valeur d'une option ou une liste de toutes les options et leurs valeurs. Doit avoir été initialisé par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des appareils et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie en tampon sur une variété de types de fichiers, de sockets et d'appareils. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée de man pour Tcl_CreateChannel. Le mécanisme de canaux fournit un système de mise en tampon inspiré des E/S standard d'Unix, et il permet également des E/S non bloquantes sur les canaux.

Les procédures décrites dans cette entrée de man comprennent les API C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canaux et comment implémenter des pilotes de canaux pour de nouveaux types de canaux, voir l'entrée de man pour Tcl_CreateChannel.

TCL_OPENFILECHANNEL

La procédure Tcl_OpenFileChannel ouvre un canal associé au nom de fichier fileName. Le fonctionnement du canal est déterminé par le mode et les permissions. Les valeurs et la signification de mode sont les mêmes que celles de l'argument mode de la commande Tcl open. La valeur permissions est utilisée si un nouveau fichier est créé ; elle est ignorée dans le cas contraire. Si le canal est créé avec succès, son nom de type sera file. Si une erreur se produit pendant l'ouverture du fichier, interp sera défini sur une erreur et NULL sera renvoyé.

TCL_OPENCOMMANDCHANNEL

La procédure Tcl_OpenCommandChannel crée un pipeline de commandes en exécutant la commande spécifiée par argv. Le fonctionnement du pipeline est déterminé par flags. Les descripteurs d'entrée, de sortie et d'erreur standard du premier processus enfant peuvent être redirigés en spécifiant les indicateurs TCL_STDIN, TCL_STDOUT, et TCL_STDERR respectivement. Si TCL_ENFORCE_MODE n'est pas spécifié, alors des redirections stdio peuvent outrepasser les réglages d'indicateurs. Les canaux retournés pour l'entrée et la sortie seront configurés pour être bloquants par défaut.

TCL_MAKEFILECHANNEL

La procédure Tcl_MakeFileChannel est une primitive de bas niveau qui crée un canal Tcl à partir d'un descripteur de fichier existant (par exemple, un descripteur de fichier ouvert via l'appel système open).

Le paramètre handle est un descripteur de fichier valide pour le système d'exploitation. Pour les systèmes Unix, il s'agit d'un entier représentant un descripteur de fichier ; pour les systèmes Windows, il s'agit d'un HANDLE de fichier.

Le paramètre readOrWrite est une combinaison par OU d'indicateurs qui spécifie si le canal doit être en lecture (TCL_READABLE) et/ou en écriture (TCL_WRITABLE). Les canaux créés de cette façon ne sont pas automatiquement enregistrés dans l'interpréteur Tcl. L'appelant est responsable de l'enregistrement du canal à l'aide de Tcl_RegisterChannel.

La valeur de retour est un Tcl_Channel qui représente le descripteur de fichier, ou NULL si une erreur s'est produite.

TCL_GETCHANNEL

La procédure Tcl_GetChannel recherche un canal enregistré dans l'interpréteur interp qui correspond à channelName. Si le canal est trouvé, un pointeur vers le canal est renvoyé. Si modePtr n'est pas NULL, il sera défini sur une combinaison par OU de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et/ou en écriture. Si aucun canal nommé channelName n'est trouvé, NULL est renvoyé et le champ result de l'interpréteur est défini sur une chaîne d'erreur.

TCL_GETCHANNELNAMES

La procédure Tcl_GetChannelNames renvoie une liste de tous les noms de canaux enregistrés dans l'interpréteur interp. La liste est stockée dans la variable résultat de l'interpréteur sous forme d'une liste Tcl. Le nombre d'éléments de la liste est renvoyé. Si une erreur se produit, -1 est renvoyé.

TCL_GETCHANNELNAMESEX

Similaire à Tcl_GetChannelNames, mais ne renvoie que les noms de canaux qui correspondent au pattern donné. Le pattern est évalué comme une chaîne de correspondance de modèle (voir Tcl_StringMatch). Si pattern est NULL, cela se comporte de la même manière que Tcl_GetChannelNames.

TCL_REGISTERCHANNEL

La procédure Tcl_RegisterChannel enregistre le canal donné par channel dans l'interpréteur interp. Le nom du canal est obtenu à partir des informations internes du canal. Une fois enregistré, le canal peut être référencé par son nom dans les commandes Tcl telles que puts et gets.

TCL_UNREGISTERCHANNEL

La procédure Tcl_UnregisterChannel désenregistre le canal donné par channel de l'interpréteur interp. Ceci est généralement appelé avant que le canal ne soit fermé. Le canal doit avoir été préalablement enregistré. La procédure renvoie 0 en cas de succès et -1 si le canal n'était pas enregistré.

TCL_DETACHCHANNEL

La procédure Tcl_DetachChannel est utilisée pour supprimer la gestion par Tcl des E/S pour un canal donné. Après un appel à Tcl_DetachChannel, le canal ne sera plus accessible via Tcl. L'appelant est responsable de la gestion du descripteur de fichier sous-jacent. Les appels à Tcl_Close, Tcl_Read, etc., sur un canal détaché peuvent échouer.

TCL_ISTANDARDCHANNEL

La procédure Tcl_IsStandardChannel renvoie vrai si le canal est l'un des canaux d'E/S standard de l'interpréteur (entrée, sortie ou erreur) et faux sinon.

TCL_CLOSE

La procédure Tcl_Close ferme le canal donné par channel. Elle vide d'abord tous les tampons de sortie en attente. Ensuite, elle libère toutes les ressources associées au canal. Si le canal a été créé avec Tcl_OpenFileChannel, le descripteur de fichier sous-jacent est également fermé. Si une erreur se produit pendant l'écriture des données en tampon ou pendant la fermeture du descripteur de fichier, interp sera défini sur une erreur et -1 sera renvoyé. Dans le cas contraire, 0 est renvoyé.

TCL_READCHARS

La procédure Tcl_ReadChars lit jusqu'à charsToRead caractères du canal channel et les place dans le tampon pointé par readObjPtr. Si appendFlag est non nul, les caractères sont ajoutés à la fin de la valeur existante de readObjPtr ; sinon, ils remplacent le contenu de readObjPtr. La lecture s'arrête si la fin du fichier est atteinte, si le nombre spécifié de caractères est lu, ou si une erreur se produit. Le nombre de caractères réellement lus est renvoyé. Si la fin du fichier est atteinte, le résultat peut être inférieur à charsToRead. Si une erreur se produit, -1 est renvoyé et interp est défini sur une erreur.

Le canal channel doit être ouvert en lecture.

TCL_READ

La procédure Tcl_Read lit jusqu'à bytesToRead octets du canal channel et les place dans le tampon readBuf. La lecture s'arrête si la fin du fichier est atteinte, si le nombre spécifié d'octets est lu, ou si une erreur se produit. Le nombre d'octets réellement lus est renvoyé. Si la fin du fichier est atteinte, le résultat peut être inférieur à bytesToRead. Si une erreur se produit, -1 est renvoyé et interp est défini sur une erreur.

Cette procédure est similaire à Tcl_ReadChars, mais elle lit des octets bruts et ne prend pas en compte le codage du canal. Le canal channel doit être ouvert en lecture.

TCL_GETSOBJ

La procédure Tcl_GetsObj lit des caractères du canal channel jusqu'à ce qu'un caractère de nouvelle ligne soit lu, qu'une fin de fichier soit rencontrée, ou qu'une erreur se produise. Les caractères lus, y compris le caractère de nouvelle ligne s'il a été lu, sont placés dans la valeur objet pointée par lineObjPtr. Les caractères sont ajoutés à la valeur existante de lineObjPtr. La procédure renvoie le nombre total d'octets lus dans lineObjPtr. Si une fin de fichier est atteinte avant la lecture de tout caractère, 0 est renvoyé. Si une erreur se produit, -1 est renvoyé et interp est défini sur une erreur.

Le canal channel doit être ouvert en lecture.

TCL_GETS

La procédure Tcl_Gets est similaire à Tcl_GetsObj, mais elle place la ligne lue dans la chaîne dynamique Tcl lineRead. Les caractères lus sont ajoutés à la chaîne dynamique existante. Le nombre total d'octets lus est renvoyé, ou 0 en cas de fin de fichier, ou -1 en cas d'erreur.

Le canal channel doit être ouvert en lecture.

TCL_UNGETS

La procédure Tcl_Ungets place les données fournies par input (de longueur inputLen) dans le tampon d'entrée du canal channel. Si addAtEnd est vrai, les données sont ajoutées à la fin des données existantes dans le tampon d'entrée ; sinon, elles sont ajoutées au début. Ceci est utile pour simuler la lecture de données qui ont déjà été traitées par une autre partie du programme. La procédure renvoie le nombre d'octets mis en tampon. En cas d'erreur, elle renvoie -1.

Le canal channel doit être ouvert en lecture.

TCL_WRITEBIENS

La procédure Tcl_WriteObj écrit le contenu de la valeur objet pointée par writeObjPtr dans le canal channel. La procédure tente d'écrire autant de données que possible. Le nombre d'octets réellement écrits est renvoyé. Si une erreur se produit, -1 est renvoyé et interp est défini sur une erreur.

Le canal channel doit être ouvert en écriture.

TCL_WRITECHARS

La procédure Tcl_WriteChars écrit jusqu'à bytesToWrite octets du tampon charBuf dans le canal channel. La procédure tente d'écrire autant de données que possible. Le nombre d'octets réellement écrits est renvoyé. Si une erreur se produit, -1 est renvoyé et interp est défini sur une erreur.

Le canal channel doit être ouvert en écriture.

TCL_WRITE

La procédure Tcl_Write est similaire à Tcl_WriteChars, mais elle écrit des octets bruts et ne prend pas en compte le codage du canal. Elle écrit jusqu'à bytesToWrite octets du tampon byteBuf dans le canal channel. Le nombre d'octets réellement écrits est renvoyé. Si une erreur se produit, -1 est renvoyé.

Le canal channel doit être ouvert en écriture.

TCL_READRAW

La procédure Tcl_ReadRaw est identique à Tcl_Read.

TCL_WRITERAW

La procédure Tcl_WriteRaw est identique à Tcl_Write.

TCL_EOF

La procédure Tcl_Eof renvoie vrai si la fin du fichier a été atteinte sur le canal channel, et faux sinon. La fin du fichier est atteinte lorsque toutes les données ont été lues du canal.

TCL_FLUSH

La procédure Tcl_Flush force l'écriture de toutes les données en attente dans le tampon de sortie du canal channel vers le périphérique sous-jacent. Si une erreur se produit pendant l'écriture, -1 est renvoyé et interp est défini sur une erreur. Sinon, 0 est renvoyé.

TCL_INPUTBLOCKED

La procédure Tcl_InputBlocked renvoie vrai si le canal channel est en mode bloquant et qu'une opération de lecture bloquerait l'exécution, et faux sinon. Ceci est utile pour déterminer si une tentative de lecture échouera à cause d'une attente de données d'entrée.

TCL_INPUTBUFFERED

La procédure Tcl_InputBuffered renvoie le nombre d'octets actuellement dans le tampon d'entrée du canal channel. Ces données sont disponibles pour la lecture sans avoir à interroger le périphérique sous-jacent.

TCL_OUTPUTBUFFERED

La procédure Tcl_OutputBuffered renvoie le nombre d'octets actuellement dans le tampon de sortie du canal channel. Ces données n'ont pas encore été écrites sur le périphérique sous-jacent. Vider le tampon peut être nécessaire pour s'assurer que ces données sont écrites.

TCL_SEEK

La procédure Tcl_Seek définit la position du flux d'E/S pour le canal channel. La nouvelle position est calculée en ajoutant offset à la position donnée par seekMode. Les valeurs possibles pour seekMode sont :

SEEK_SET
Le décalage est mesuré à partir du début du fichier.
SEEK_CUR
Le décalage est mesuré à partir de la position actuelle du flux.
SEEK_END
Le décalage est mesuré à partir de la fin du fichier.
La procédure renvoie la nouvelle position du flux en octets à partir du début du fichier. Si une erreur se produit, -1 est renvoyé et interp est défini sur une erreur.

Seuls les canaux capables de rechercher (par exemple, les fichiers) supportent cette opération.

TCL_TELL

La procédure Tcl_Tell renvoie la position actuelle du flux d'E/S pour le canal channel, mesurée en octets à partir du début du fichier. Si une erreur se produit, -1 est renvoyé et interp est défini sur une erreur.

Seuls les canaux capables de rechercher (par exemple, les fichiers) supportent cette opération.

TCL_TRUNCATECHANNEL

La procédure Tcl_TruncateChannel tronque le fichier associé au canal channel à la taille spécifiée par length. Les données au-delà de cette longueur sont perdues. Si une erreur se produit, -1 est renvoyé et interp est défini sur une erreur. Sinon, 0 est renvoyé.

Seuls les canaux qui sont des fichiers ouverts en écriture supportent cette opération.

TCL_GETCHANNELOPTION

La procédure Tcl_GetChannelOption récupère la valeur de l'option donnée par optionName pour le canal channel. La valeur est placée dans la chaîne dynamique Tcl optionValue. La liste des options valides est la même que celles acceptées par la commande Tcl fconfigure. Si l'option est reconnue, 0 est renvoyé. Sinon, -1 est renvoyé et interp est défini sur une erreur.

TCL_SETCHANNELOPTION

La procédure Tcl_SetChannelOption définit la valeur de l'option donnée par optionName pour le canal channel à la valeur donnée par newValue. La liste des options valides est la même que celles acceptées par la commande Tcl fconfigure. Si l'option est reconnue et que sa valeur est définie avec succès, 0 est renvoyé. Sinon, -1 est renvoyé et interp est défini sur une erreur.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et retourne un descripteur de canal qui peut être utilisé pour effectuer des entrées et sorties sur le fichier. Cette API est basée sur la procédure fopen de la bibliothèque d'E/S standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles du commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur les valeurs Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel chaque fois que possible.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, la création du nouveau canal lui assigne également en remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Elle crée une séquence de sous-processus spécifiés par les arguments argv et argc et retourne un canal qui peut être utilisé pour communiquer avec ces sous-processus. L'argument flags indique quel type de communication existera avec le pipeline de commandes.

Si le drapeau TCL_STDIN est défini, l'entrée standard du premier sous-processus sera liée au canal : écrire dans le canal fournira des entrées au sous-processus. Si TCL_STDIN n'est pas défini, l'entrée standard du premier sous-processus sera la même que l'entrée standard de cette application. Si TCL_STDOUT est défini, la sortie standard du dernier sous-processus peut être lue depuis le canal ; sinon, elle va à la sortie standard de cette application. Si TCL_STDERR est défini, la sortie d'erreur standard de tous les sous-processus est renvoyée au canal et entraîne une erreur lors de la fermeture du canal ; sinon, elle va à l'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas défini, alors argc et argv peuvent rediriger les descripteurs stdio pour annuler TCL_STDIN, TCL_STDOUT, et TCL_STDERR ; s'il est défini, alors c'est une erreur pour argc et argv de rediriger les canaux stdio pour lesquels TCL_STDIN, TCL_STDOUT, et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, la création du nouveau canal lui assigne également en remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un descripteur de fichier existant et spécifique à la plateforme. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, la création du nouveau canal lui assigne également en remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel retourne un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur Tcl dans interp. Si un canal portant ce nom n'est pas enregistré dans cet interpréteur, la procédure retourne NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms en fonction du pattern. Si pattern est NULL, alors aucun filtrage ne sera effectué. La valeur de retour est TCL_OK si aucune erreur ne s'est produite lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur pourront faire référence au canal dans les opérations d'entrée ou de sortie en utilisant le nom donné lors de l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour ce canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur Tcl peut appeler Tcl_RegisterChannel avec interp comme NULL, pour indiquer qu'il souhaite détenir une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et ne sera fermé que lorsque le nombre correspondant d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code exécuté en dehors de tout interpréteur de détenir en toute sécurité une référence à un canal également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code gérant les canaux standard. Si aucun canal standard n'a été initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un exposé général sur les canaux standard et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Si cette opération a supprimé la dernière inscription du canal dans un interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur Tcl peut appeler Tcl_UnregisterChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera maintenant fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel, sauf qu'il fermera également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Au-delà de cela, cette commande n'a aucun autre effet. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin), et retournera TCL_ERROR si elle est appelée avec l'un de ces canaux.

Le code non associé à un interpréteur Tcl peut appeler Tcl_DetachChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. Si c'est le cas, il retourne 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lorsque Tcl_Close est appelé. Les sorties tamponnées sont vidées vers le périphérique de sortie du canal avant la destruction du canal, et toute entrée tamponnée est discardée. S'il s'agit d'un canal bloquant, l'appel ne retourne pas tant que toutes les données tamponnées n'ont pas été envoyées avec succès au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a des sorties tamponnées qui ne peuvent pas être écrites sans bloquer, l'appel retourne immédiatement ; les sorties sont vidées en arrière-plan et le canal sera fermé une fois que toutes les données tamponnées auront été envoyées. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close retourne TCL_OK. Si une erreur se produit, Tcl_Close retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré en utilisant Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a déjà été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez plutôt utiliser Tcl_UnregisterChannel, qui appellera Tcl_Close en interne lorsque tous les appels à Tcl_RegisterChannel auront été égalés par les appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, convertissant les octets en UTF-8 en se basant sur l'encodage du canal et stockant les données produites dans la représentation sous forme de chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, les convertissant en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée ait été lue. Si l'encodage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception du ou des caractères de fin de ligne, sont ajoutés à la représentation sous forme de chaîne de lineObjPtr. Le ou les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_GetsObj renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj renvoie également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est renvoyé, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité des entrées.

Tcl_Gets est identique à Tcl_GetsObj, sauf que les caractères résultants sont ajoutés à la chaîne dynamique fournie par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, soit à la tête, soit à la queue de la file d'attente. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file d'attente ; sinon, elles seront ajoutées au début de la file d'attente. Si channel a un EOF "collant" défini, aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets renvoie inputLen ou -1 si une erreur se produit.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données de caractères à charBuf. Les caractères UTF-8 dans le tampon sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars attend que charBuf soit terminé par un caractère nul et il écrit tout jusqu'au caractère nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal à none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est le nombre d'octets qui ont été acceptés pour la sortie vers le canal. Il s'agit soit d'une valeur supérieure à zéro pour indiquer le succès, soit de -1 pour indiquer qu'une erreur s'est produite. Si une erreur se produit, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme, conformément à l'option -translation du canal. Cela est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars, sauf qu'il accepte une valeur Tcl dont le contenu sera envoyé au canal. Les caractères UTF-8 de la représentation sous forme de chaîne de writeObjPtr sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. Par optimisation des performances, lors de l'écriture dans un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets de la représentation interne de writeObjPtr en tant que valeur de tableau d'octets sont écrits dans le canal. La représentation en tableau d'octets de la valeur sera construite si elle est nécessaire. De cette manière, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de la conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars, sauf qu'il n'effectue pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour des raisons de compatibilité descendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write attend que byteBuf soit terminé par un caractère nul et il écrit tout jusqu'au caractère nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas la mise en pile. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée dans le canal le plus haut de la pile dont le canal fourni fait partie, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction n'est utilisable que pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation vers le canal situé en dessous.

TCL_FLUSH

Tcl_Flush force la sortie de toutes les données tamponnées pour channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données tamponnées n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal n'est pas bloquant ; il démarre une opération de vidage en arrière-plan qui écrira les données tamponnées dans le canal éventuellement, aussi vite que le canal sera capable de les absorber.

La valeur de retour est normalement TCL_OK. Si une erreur se produit, Tcl_Flush renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données suivantes seront lues ou écrites. La sortie tamponnée est vidée vers le canal et l'entrée tamponnée est rejetée, avant l'opération de recherche.

Tcl_Seek renvoie normalement le nouveau point d'accès. Si une erreur se produit, Tcl_Seek renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut avoir été déplacé ou non.

TCL_TELL

Tcl_Tell renvoie le point d'accès actuel d'un canal. La valeur renvoyée est -1 si le canal ne supporte pas la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent de channel à une longueur donnée de length octets. Il renvoie TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et de leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, c'est le nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue.

D'autres options peuvent être ajoutées par chaque type de canal. Ces options spécifiques au type de canal sont décrites dans l'entrée du manuel de la commande Tcl qui crée un canal de ce type ; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans l'entrée du manuel de la commande Tcl socket. La procédure retourne normalement TCL_OK. Si une erreur se produit, elle retourne TCL_ERROR et appelle Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit une nouvelle valeur newValue pour une option optionName sur le channel. La procédure retourne normalement TCL_OK. Si une erreur se produit, elle retourne TCL_ERROR ; de plus, si interp n'est pas NULL, Tcl_SetChannelOption laisse un message d'erreur dans le résultat de l'interpréteur.

TCL_EOF

Tcl_Eof retourne une valeur non nulle si channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked retourne une valeur non nulle si channel est en mode non bloquant et que la dernière opération d'entrée a retourné moins de données que demandé car il n'y avait pas suffisamment de données disponibles. L'appel retourne toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered retourne le nombre d'octets d'entrée actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en lecture, cette fonction retourne toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered retourne le nombre d'octets de sortie actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en écriture, cette fonction retourne toujours zéro.

PROBLÈMES DE PLATEFORME

Les descripteurs retournés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que retourné par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel, ou Tcl_MakeFileChannel. D'autres types de canaux peuvent retourner un type de descripteur différent sur les plateformes Windows.
