ARGUMENTS

Tcl_Interp *interp (in/out)
L'interpréteur contenant l'objet ou la classe pour laquelle créer ou mettre à jour une méthode.
Tcl_Object object (in)
L'objet auquel attacher la méthode.
Tcl_Class class (in)
La classe à laquelle attacher la méthode.
Tcl_Obj *nameObj (in)
Le nom de la méthode à créer. Ne doit pas être NULL lors de la création de constructeurs ou de destructeurs.
int isPublic (in)
Un indicateur indiquant la visibilité de la méthode. Les seules valeurs publiques supportées pour cet indicateur sont 0 pour une méthode non exportée et 1 pour une méthode exportée.
Tcl_MethodType *methodTypePtr (in)
Une description du type de la méthode à créer, ou le type de méthode à comparer.
ClientData clientData (in)
Un bloc de données transmis à l'implémentation de la méthode sans interprétation.
ClientData *clientDataPtr (out)
Un pointeur vers une variable dans laquelle écrire la valeur clientData fournie lors de la création de la méthode. Si NULL, la valeur clientData ne sera pas récupérée.
Tcl_Method method (in)
Une référence à une méthode à interroger.
Tcl_ObjectContext context (in)
Une référence à un contexte d'appel de méthode. Notez que le code client *ne doit pas* conserver de référence à un contexte.
int objc (in)
Le nombre d'arguments à passer à l'implémentation de la méthode.
Tcl_Obj *const *objv (in)
Un tableau d'arguments à passer à l'implémentation de la méthode.
int skip (in)
Le nombre d'arguments passés à l'implémentation de la méthode qui ne représentent pas des arguments "réels".

DESCRIPTION

Une méthode est une opération effectuée sur un objet et qui est associée à cet objet. Chaque méthode doit être attachée soit à un objet, soit à une classe ; les méthodes attachées à une classe sont associées à toutes les instances (directes et indirectes) de cette classe.

À partir d'une méthode, l'entité qui l'a déclarée peut être trouvée en utilisant Tcl_MethodDeclarerClass qui renvoie la classe à laquelle la méthode est attachée (ou NULL si la méthode n'est attachée à aucune classe) et Tcl_MethodDeclarerObject qui renvoie l'objet auquel la méthode est attachée (ou NULL si la méthode n'est attachée à aucun objet). Le nom de la méthode peut être récupéré avec Tcl_MethodName et si la méthode est exportée est récupéré avec Tcl_MethodIsPublic. Le type de la méthode peut également être introspecté dans une mesure limitée ; la fonction Tcl_MethodIsType indique si une méthode est d'un type particulier, en assignant le clientData par méthode à la variable pointée par clientDataPtr si (celui-ci n'est pas NULL) si le type est trouvé.

CRÉATION DE MÉTHODES

Les méthodes sont créées par Tcl_NewMethod et Tcl_NewInstanceMethod, qui créent une méthode attachée à une classe ou à un objet respectivement. Dans les deux cas, l'argument nameObj donne le nom de la méthode à créer, l'argument isPublic indique si la méthode doit être exportée initialement, l'argument methodTypePtr décrit l'implémentation de la méthode (voir la section TYPES DE MÉTHODES ci-dessous) et l'argument clientData donne des données spécifiques à l'implémentation qui sont transmises à l'implémentation de la méthode lorsqu'elle est appelée.

Lorsque l'argument nameObj de Tcl_NewMethod est NULL, une méthode sans nom est créée, qui est utilisée pour les constructeurs et les destructeurs. Les constructeurs doivent être installés dans leur classe en utilisant la fonction Tcl_ClassSetConstructor, et les destructeurs (qui ne doivent pas nécessiter d'arguments) doivent être installés dans leur classe en utilisant la fonction Tcl_ClassSetDestructor. Les méthodes sans nom ne doivent pas être utilisées à d'autres fins, et les méthodes nommées ne doivent pas être utilisées comme constructeurs ou destructeurs. Notez également qu'un methodTypePtr NULL est utilisé pour fournir une signalisation interne, et ne doit pas être utilisé dans le code client.

CONTEXTES D'APPEL DE MÉTHODE

Lorsqu'une méthode est appelée, une référence au contexte d'appel de méthode est passée comme l'un des arguments à la fonction d'implémentation. Ce contexte peut être inspecté pour fournir des informations sur l'appelant, mais ne doit pas être conservé au-delà du moment où l'appel de méthode se termine.

La méthode qui est appelée peut être récupérée du contexte en utilisant Tcl_ObjectContextMethod, et l'objet qui a provoqué l'invocation de la méthode peut être récupéré avec Tcl_ObjectContextObject. Le nombre d'arguments qui doivent être ignorés (par exemple, le nom de l'objet et le nom de la méthode dans un appel de méthode normal) est lu avec Tcl_ObjectContextSkippedArgs, et le contexte peut également indiquer s'il agit d'un filtre pour une autre méthode via Tcl_ObjectContextIsFiltering.

Pendant l'exécution d'une méthode, l'implémentation de la méthode peut choisir d'invoquer les étapes de la chaîne d'appels de méthode qui viennent après l'implémentation de la méthode actuelle. Ceci (le cœur de la commande next) est fait en utilisant Tcl_ObjectContextInvokeNext. Notez que cette fonction ne manipule pas la pile d'images d'appel, contrairement à la commande next ; si l'implémentation de la méthode a empilé une ou plusieurs images supplémentaires sur la pile dans le cadre de son implémentation, elle est également responsable de dépiler temporairement ces images pendant l'exécution de la fonction Tcl_ObjectContextInvokeNext. Notez également que le contexte d'appel de méthode n'est *jamais* supprimé pendant l'exécution de cette fonction.

TYPES DE MÉTHODES

Les types de méthodes sont décrits par un pointeur vers une structure Tcl_MethodType, définie comme suit :

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

Le champ version permet une extension future de la structure, et doit toujours être déclaré égal à TCL_OO_METHOD_VERSION_CURRENT. Le champ name fournit un nom lisible par l'homme pour le type, et est la valeur exposée via les commandes Tcl info class methodtype et info object methodtype.

Le champ callProc donne une fonction qui est appelée lorsque la méthode est invoquée ; il ne doit jamais être NULL.

Le champ deleteProc donne une fonction qui est utilisée pour supprimer une méthode particulière, et est appelée lorsque la méthode est remplacée ou supprimée ; si le champ est NULL, on suppose que le clientData de la méthode n'a pas besoin d'action spéciale pour être supprimé.

Le champ cloneProc est soit une fonction utilisée pour copier le clientData d'une méthode (dans le cadre de Tcl_CopyObjectInstance), soit NULL pour indiquer que le clientData peut simplement être copié directement.

SIGNATURE DE FONCTION Tcl_MethodCallProc

Une fonction de type Tcl_MethodCallProc a la signature suivante :

typedef int (*Tcl_MethodCallProc)(
    ClientData clientData,
    Tcl_Interp *interp,
    int objc,
    Tcl_Obj *const objv[]
);

Le champ clientData est la valeur associée à la méthode lors de sa création. L'interpréteur et les arguments sont ceux passés à la méthode.

NAME

Tcl_ObjectContextObject - object context manipulation

SYNOPSIS

#include <tclOO.h>
Tcl_ObjectContext
    Tcl_GetObjectContext(Tcl_Interp *interp);
void
    Tcl_DeleteObjectContext(Tcl_ObjectContext objectContext);
Tcl_Object
    Tcl_GetObjectContextObject(Tcl_ObjectContext objectContext);
Tcl_Object
    Tcl_GetObjectContextClass(Tcl_ObjectContext objectContext);
Tcl_Object
    Tcl_GetObjectContextConstructor(Tcl_ObjectContext objectContext);
Tcl_Object
    Tcl_GetObjectContextMethod(Tcl_ObjectContext objectContext);
void
    Tcl_SetObjectContextMethod(Tcl_ObjectContext objectContext,
            Tcl_Object method);
Tcl_Object
    Tcl_GetObjectContextSupercontext(Tcl_ObjectContext objectContext);
int
    Tcl_PushObjectContext(Tcl_Interp *interp,
            Tcl_ObjectContext objectContext);
void
    Tcl_PopObjectContext(Tcl_Interp *interp);

ARGUMENTS

Tcl_Interp *interp
Dans lequel le contexte de l'objet est récupéré ou inséré. Il peut aussi être utilisé pour signaler des erreurs si la manipulation du contexte échoue.
Tcl_ObjectContext objectContext
Le contexte de l'objet à manipuler.
Tcl_Object method
La méthode à définir dans le contexte de l'objet.

DESCRIPTION

Un contexte d'objet est un enregistrement de l'objet ou de la classe qui est en train d'être manipulé, que ce soit lors de la construction, de la destruction, de l'invocation de méthode, ou de la copie. Les fonctions suivantes sont disponibles pour manipuler les contextes d'objets.

Tcl_GetObjectContext récupère le contexte d'objet actif pour l'interpréteur interp. Si aucun contexte d'objet n'est actif (par exemple, si l'appel n'est pas fait à l'intérieur d'une méthode), alors NULL est retourné. Ce contexte peut ensuite être utilisé pour récupérer des informations sur l'objet, la classe, le constructeur ou la méthode courante en cours d'exécution.

Tcl_DeleteObjectContext libère la mémoire associée à objectContext. Ceci ne doit être appelé que sur des contextes d'objets qui n'ont pas été récupérés par Tcl_GetObjectContext ou qui ne sont plus nécessaires.

Tcl_GetObjectContextObject retourne l'objet, ou la classe si l'on est dans une classe, qui est associé à objectContext.

Tcl_GetObjectContextClass retourne la classe de l'objet qui est associé à objectContext.

Tcl_GetObjectContextConstructor retourne le constructeur de l'objet qui est associé à objectContext.

Tcl_GetObjectContextMethod retourne la méthode qui est associée à objectContext.

Tcl_SetObjectContextMethod définit la méthode qui est associée à objectContext.

Tcl_GetObjectContextSupercontext retourne le contexte d'objet parent (super-contexte) de objectContext.

Tcl_PushObjectContext pousse un nouveau contexte d'objet sur la pile des contextes de l'interpréteur interp. Ceci est utilisé pour créer un nouveau contexte dans lequel les méthodes peuvent être exécutées. La fonction retourne le contexte d'objet qui était actif avant que le nouveau contexte ne soit poussé. Si une erreur se produit, l'interpréteur sera dans un état d'erreur et NULL sera retourné.

Tcl_PopObjectContext retire le contexte d'objet du sommet de la pile des contextes de l'interpréteur interp. Ceci doit être appelé pour chaque appel réussi à Tcl_PushObjectContext afin de s'assurer que la pile des contextes reste cohérente.

METHOD TYPES

Les fonctions de rappel suivantes sont utilisées pour gérer les méthodes au sein de TclOO.

TCL_METHODCALLPROC FUNCTION SIGNATURE

Les fonctions correspondant à cette signature sont appelées lorsque la méthode est invoquée.

typedef int Tcl_MethodCallProc(
                    ClientData clientData,
                    Tcl_Interp *interp,
                    Tcl_ObjectContext objectContext,
                    int objc,
                    Tcl_Obj *const *objv);

L'argument clientData d'un Tcl_MethodCallProc est la valeur qui a été donnée lors de la création de la méthode, interp est un endroit pour exécuter des scripts et accéder à des variables ainsi que là où placer le résultat de la méthode, et les champs objc et objv fournissent les objets paramètres à la méthode. Le contexte d'appel de la méthode peut être découvert via l'argument objectContext, et la valeur de retour d'un Tcl_MethodCallProc est n'importe quel code de retour Tcl (par exemple, TCL_OK, TCL_ERROR).

TCL_METHODDELETEPROC FUNCTION SIGNATURE

Les fonctions correspondant à cette signature sont utilisées lorsqu'une méthode est supprimée, que ce soit par la création d'une nouvelle méthode ou parce que l'objet ou la classe est supprimé.

typedef void Tcl_MethodDeleteProc(
                    ClientData clientData);

L'argument clientData d'un Tcl_MethodDeleteProc sera la même valeur que celle passée à l'argument clientData de Tcl_NewMethod ou Tcl_NewInstanceMethod lors de la création de la méthode.

TCL_CLONEPROC FUNCTION SIGNATURE

Les fonctions correspondant à cette signature sont utilisées pour copier une méthode lorsque l'objet ou la classe est copié en utilisant Tcl_CopyObjectInstance (ou oo::copy).

typedef int Tcl_CloneProc(
                    Tcl_Interp *interp,
                    ClientData oldClientData,
                    ClientData *newClientDataPtr);

L'argument interp fournit un endroit pour écrire un message d'erreur lorsque la tentative de clonage de l'objet doit échouer, auquel cas la procédure de clonage doit également retourner TCL_ERROR ; elle doit sinon retourner TCL_OK. Le champ oldClientData d'un Tcl_CloneProc donne la valeur de la méthode en cours de copie, et le champ newClientDataPtr pointera vers une variable dans laquelle écrire la valeur pour la méthode en cours de copie.
