ARGUMENTS

Tcl_Interp *interp (entrée/sortie)
L'interpréteur contenant l'objet ou la classe pour créer ou mettre à jour une méthode.
Tcl_Object object (entrée)
L'objet sur lequel la méthode est créée.
Tcl_Class class (entrée)
La classe à laquelle la méthode est associée.
Tcl_Obj *nameObj (entrée)
Le nom de la méthode à créer. Ne doit pas être NULL, sauf lors de la création de constructeurs ou de destructeurs.
int isPublic (entrée)
Un drapeau indiquant la visibilité de la méthode. Les valeurs supportées pour ce drapeau sont 0 pour les méthodes non exportées et 1 pour les méthodes exportées.
Tcl_MethodType *methodTypePtr (entrée)
Une description du type de la méthode à créer, ou le type de méthode à comparer.
ClientData clientData (entrée)
Un bloc de données passé à l'implémentation de la méthode sans interprétation.
ClientData *clientDataPtr (sortie)
Un pointeur vers une variable dans laquelle la valeur clientData fournie lors de la création de la méthode est écrite. Si NULL, la valeur clientData n'est pas récupérée.
Tcl_Method method (entrée)
Une référence à une méthode à interroger.
Tcl_ObjectContext context (entrée)
Une référence à un contexte d'appel de méthode. Note : le code client ne doit pas conserver de référence à un contexte.
int objc (entrée)
Le nombre d'arguments passés à l'implémentation de la méthode.
Tcl_Obj *const *objv (entrée)
Un tableau d'arguments passés à l'implémentation de la méthode.
int skip (entrée)
Le nombre d'arguments passés à l'implémentation de la méthode qui ne représentent pas d'arguments réels.

DESCRIPTION

Une méthode est une opération effectuée sur un objet associé à l'objet. Chaque méthode doit être associée à un objet ou à une classe ; les méthodes associées à une classe sont associées à toutes les instances (directes et indirectes) de cette classe.

Étant donné une méthode, son déclarant peut être trouvé en utilisant Tcl_MethodDeclarerClass, qui renvoie la classe à laquelle la méthode est associée (ou NULL si la méthode n'est associée à aucune classe), et Tcl_MethodDeclarerObject, qui renvoie l'objet auquel la méthode est associée (ou NULL si la méthode n'est associée à aucun objet). Le nom de la méthode peut être récupéré avec Tcl_MethodName et si la méthode est exportée, cela peut être récupéré avec Tcl_MethodIsPublic. On peut également interroger le type de la méthode dans une mesure limitée ; la fonction Tcl_MethodIsType renvoie si une méthode est d'un type spécifique, en assignant la valeur clientData à la variable indiquée par clientDataPtr si (et seulement si) le type correspond.

CRÉATION DE MÉETHODES

Les méthodes sont créées via Tcl_NewMethod et Tcl_NewInstanceMethod, qui créent une méthode associée à une classe ou à un objet respectivement. Dans les deux cas, l'argument nameObj donne le nom de la méthode à créer, l'argument isPublic indique si la méthode doit être initialement exportée, l'argument methodTypePtr décrit l'implémentation de la méthode (voir la section TYPES DE MÉETHODES), et l'argument clientData fournit des données d'implémentation spécifiques qui sont passées à l'implémentation de la méthode lors de son appel.

Lorsque l'argument nameObj de Tcl_NewMethod est NULL, une méthode sans nom est créée, utilisée pour les constructeurs et les destructeurs. Les constructeurs doivent être installés dans leur classe en utilisant la fonction Tcl_ClassSetConstructor, et les destructeurs (qui ne nécessitent aucun argument) doivent être installés dans leur classe en utilisant Tcl_ClassSetDestructor. Les méthodes sans nom ne doivent pas être utilisées à d'autres fins, et les méthodes nommées ne doivent pas être utilisées comme constructeurs ni destructeurs. Il faut également noter qu'un NULL methodTypePtr est utilisé pour fournir des signaux internes, et ne doit pas être utilisé dans le code client.

CONTEXTES D'APPEL DE MÉETHODES

Lorsqu'une méthode est appelée, une référence à un contexte d'appel de méthode est passée comme l'un des arguments de la fonction d'implémentation. Ce contexte peut être inspecté pour fournir des informations sur l'appelant, mais ne doit pas être conservé au-delà du moment où l'appel de méthode se termine.

La méthode qui est appelée peut être récupérée en utilisant Tcl_ObjectContextMethod, et l'objet qui a causé l'invocation de la méthode peut être récupéré avec Tcl_ObjectContextObject. Le nombre d'arguments qui sont sautés (par exemple, le nom de l'objet et le nom de la méthode dans une invocation normale) est lu avec Tcl_ObjectContextSkippedArgs, et le contexte peut également signaler s'il travaille comme filtre pour une autre méthode avec Tcl_ObjectContextIsFiltering.

Pendant l'exécution d'une méthode, l'implémentation de la méthode peut choisir d'invoquer les étapes de la chaîne d'appel de méthode qui suivent l'implémentation actuelle de la méthode. Ceci (le cœur de la commande next) est réalisé avec Tcl_ObjectContextInvokeNext. Il faut noter que cette fonction ne modifie pas la pile d'appels, comme le fait la commande next ; si l'implémentation de la méthode a poussé une ou plusieurs frames supplémentaires sur la pile pendant son implémentation, elle doit également être responsable de dépiler ces frames pendant l'exécution de Tcl_ObjectContextInvokeNext. Il faut également noter que le contexte d'appel de méthode n'est jamais supprimé pendant l'exécution de cette fonction.

TYPES DE MÉETHODES

Les types de méthodes sont décrits par un pointeur vers une structure Tcl_MethodType, qui est définie comme suit :

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

Le champ version permet une extension future de la structure, et doit toujours être déclaré égal à TCL_OO_METHOD_VERSION_CURRENT. Le champ name fournit un nom lisible par l'homme pour le type, et est la valeur exposée par les commandes Tcl info class methodtype et info object methodtype.

Le champ callProc fournit une fonction qui est appelée lors de l'invocation de la méthode ; il ne doit jamais être NULL.

Le champ deleteProc fournit une fonction utilisée pour supprimer une méthode spécifique, et est appelée lorsque la méthode est remplacée ou supprimée ; si le champ est NULL, on suppose que le clientData de la méthode ne nécessite aucune action spéciale pour sa suppression.

Le champ cloneProc est une fonction utilisée pour copier le clientData de la méthode (dans le cadre de Tcl_CopyObjectInstance) ou NULL pour indiquer que le clientData peut être copié directement.

SIGNATURE DE FONCTION TCL_METHODCALLPROC

typedef int (*Tcl_MethodCallProc)(Tcl_Interp *interp,
    void *clientData, Tcl_ObjectContext context, int objc,
    Tcl_Obj *const objv[]);

NOM

TclOO

SYNTAXE

Les procédures correspondant à cette signature sont appelées lorsqu'une méthode est invoquée.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

L'argument clientData d'un Tcl_MethodCallProc est la valeur qui a été fournie lors de la création de la méthode, interp est un endroit où les scripts s'exécutent et accèdent aux variables, ainsi que l'endroit où le résultat de la méthode doit être placé, et les champs objc et objv indiquent les objets paramètres de la méthode. Le contexte d'appel de la méthode peut être découvert via l'argument objectContext, et la valeur de retour d'un Tcl_MethodCallProc est n'importe quel code de retour Tcl (par exemple, TCL_OK, TCL_ERROR).

SIGNATURE DE FONCTION TCL_METHODDELETEPROC

Les procédures correspondant à cette signature sont utilisées lorsqu'une méthode est supprimée, que ce soit par la création d'une nouvelle méthode ou en raison de la suppression de l'objet ou de la classe.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

L'argument clientData d'un Tcl_MethodDeleteProc sera le même que la valeur passée à l'argument clientData de Tcl_NewMethod ou Tcl_NewInstanceMethod lors de la création de la méthode.

SIGNATURE DE FONCTION TCL_CLONEPROC

Les procédures correspondant à cette signature sont utilisées pour copier une méthode lorsque l'objet ou la classe est copié à l'aide de Tcl_CopyObjectInstance (ou oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

L'argument interp d'un Tcl_CloneProc fournit un endroit pour écrire un message d'erreur si la copie de l'objet échoue, auquel cas la procédure de copie doit renvoyer TCL_ERROR ; elle doit renvoyer TCL_OK dans le cas contraire. Le champ oldClientData d'un Tcl_CloneProc fournit la valeur de la méthode en cours de copie, et le champ newClientDataPtr pointe vers une variable où la valeur de la méthode copiée est écrite.
