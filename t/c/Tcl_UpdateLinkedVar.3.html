Tcl_LinkVar(3) Procédures de la bibliothèque Tcl Tcl_LinkVar(3)

NOM

Tcl_LinkVar, Tcl_UnlinkVar, Tcl_UpdateLinkedVar - Lier une variable Tcl à une variable C

SYNOPHIS

#include <tcl.h>

int
Tcl_LinkVar(interp, varName, addr, type)

Tcl_UnlinkVar(interp, varName)

Tcl_UpdateLinkedVar(interp, varName)

ARGUMENTS

Tcl_Interp *interp (entrée)
L'interpréteur qui contient varName. Également utilisé par Tcl_LinkVar pour renvoyer des messages d'erreur.
const char *varName (entrée)
Le nom de la variable globale.
char *addr (entrée)
L'adresse de la variable C à lier à varName.
int type (entrée)
Le type de la variable C. Doit être l'un des éléments suivants : TCL_LINK_INT, TCL_LINK_UINT, TCL_LINK_CHAR, TCL_LINK_UCHAR, TCL_LINK_SHORT, TCL_LINK_USHORT, TCL_LINK_LONG, TCL_LINK_ULONG, TCL_LINK_WIDE_INT, TCL_LINK_WIDE_UINT, TCL_LINK_FLOAT, TCL_LINK_DOUBLE, TCL_LINK_BOOLEAN, ou TCL_LINK_STRING, éventuellement combiné avec TCL_LINK_READ_ONLY pour rendre la variable Tcl en lecture seule.

DESCRIPTION

Tcl_LinkVar utilise des traces de variables pour maintenir la variable Tcl nommée par varName synchronisée avec la variable C à l'adresse spécifiée par addr. Chaque fois que la variable Tcl est lue, la valeur de la variable C sera renvoyée, et chaque fois que la variable Tcl est écrite, la variable C sera mise à jour pour avoir la même valeur. Tcl_LinkVar renvoie normalement TCL_OK ; si une erreur se produit lors de l'établissement du lien (par exemple, parce que varName est le nom d'un tableau), TCL_ERROR est renvoyé et le résultat de l'interpréteur contient un message d'erreur.

L'argument type spécifie le type de la variable C et doit avoir l'une des valeurs suivantes, éventuellement combinée avec TCL_LINK_READ_ONLY :

TCL_LINK_INT
La variable C est de type int. Toute valeur écrite dans la variable Tcl doit avoir une forme entière correcte acceptable par Tcl_GetIntFromObj ; les tentatives d'écriture de valeurs non entières dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
TCL_LINK_UINT
La variable C est de type unsigned int. Toute valeur écrite dans la variable Tcl doit avoir une forme entière non signée correcte acceptable par Tcl_GetWideIntFromObj et être dans la plage définie par la plateforme pour le type unsigned int ; les tentatives d'écriture de valeurs non entières (ou de valeurs hors plage) dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
TCL_LINK_CHAR
La variable C est de type char. Toute valeur écrite dans la variable Tcl doit avoir une forme entière correcte acceptable par Tcl_GetIntFromObj et être dans la plage du type de données char ; les tentatives d'écriture de valeurs non entières ou hors plage dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
TCL_LINK_UCHAR
La variable C est de type unsigned char. Toute valeur écrite dans la variable Tcl doit avoir une forme entière non signée correcte acceptable par Tcl_GetIntFromObj et être dans la plage définie par la plateforme pour le type unsigned char ; les tentatives d'écriture de valeurs non entières (ou de valeurs hors plage) dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
TCL_LINK_SHORT
La variable C est de type short. Toute valeur écrite dans la variable Tcl doit avoir une forme entière correcte acceptable par Tcl_GetIntFromObj et être dans la plage du type de données short ; les tentatives d'écriture de valeurs non entières ou hors plage dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
TCL_LINK_USHORT
La variable C est de type unsigned short. Toute valeur écrite dans la variable Tcl doit avoir une forme entière non signée correcte acceptable par Tcl_GetIntFromObj et être dans la plage définie par la plateforme pour le type unsigned short ; les tentatives d'écriture de valeurs non entières (ou de valeurs hors plage) dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
TCL_LINK_LONG
La variable C est de type long. Toute valeur écrite dans la variable Tcl doit avoir une forme entière correcte acceptable par Tcl_GetLongFromObj ; les tentatives d'écriture de valeurs non entières ou hors plage dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
TCL_LINK_ULONG
La variable C est de type unsigned long. Toute valeur écrite dans la variable Tcl doit avoir une forme entière non signée correcte acceptable par Tcl_GetWideIntFromObj et être dans la plage définie par la plateforme pour le type unsigned long ; les tentatives d'écriture de valeurs non entières (ou de valeurs hors plage) dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
TCL_LINK_DOUBLE
La variable C est de type double. Toute valeur écrite dans la variable Tcl doit avoir une forme réelle correcte acceptable par Tcl_GetDoubleFromObj ; les tentatives d'écriture de valeurs non réelles dans varName seront rejetées avec des erreurs Tcl. Les représentations entières ou réelles incomplètes (comme la chaîne vide, '.', '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
TCL_LINK_FLOAT
La variable C est de type float. Toute valeur écrite dans la variable Tcl doit avoir une forme réelle correcte acceptable par Tcl_GetDoubleFromObj et être dans la plage acceptable pour un float ; les tentatives d'écriture de valeurs non réelles (ou de valeurs hors plage) dans varName seront rejetées avec des erreurs Tcl. Les représentations entières ou réelles incomplètes (comme la chaîne vide, '.', '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
TCL_LINK_WIDE_INT
La variable C est de type Tcl_WideInt (qui est un type entier d'au moins 64 bits sur toutes les plateformes qui peuvent le supporter.) Toute valeur écrite dans la variable Tcl doit avoir une forme entière correcte acceptable par Tcl_GetWideIntFromObj ; les tentatives d'écriture de valeurs non entières dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
TCL_LINK_WIDE_UINT
La variable C est de type Tcl_WideUInt (qui est un type entier non signé d'au moins 64 bits sur toutes les plateformes qui peuvent le supporter.) Toute valeur écrite dans la variable Tcl doit avoir une forme entière non signée correcte acceptable par Tcl_GetWideIntFromObj (elle sera convertie en non signé) ; les tentatives d'écriture de valeurs non entières dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
<
b>TCL_LINK_BOOLEAN
La variable C est de type int. Si sa valeur est nulle, elle sera lue depuis Tcl comme “0” ; sinon, elle sera lue depuis Tcl comme “1”. Chaque fois que varName est modifiée, la variable C sera définie à une valeur de 0 ou 1. Toute valeur écrite dans la variable Tcl doit avoir une forme booléenne appropriée acceptable par Tcl_GetBooleanFromObj ; les tentatives d'écriture de valeurs non booléennes dans varName seront rejetées avec des erreurs Tcl.
TCL_LINK_STRING
La variable C est de type char *. Si sa valeur n'est pas NULL, elle doit être un pointeur vers une chaîne allouée avec Tcl_Alloc ou ckalloc. Chaque fois que la variable Tcl est modifiée, la chaîne C actuelle sera libérée et une nouvelle mémoire sera allouée pour contenir une copie de la nouvelle valeur de la variable. Si la variable C contient un pointeur NULL, la variable Tcl sera lue comme “NULL”.

Si le drapeau TCL_LINK_READ_ONLY est présent dans type, la variable sera en lecture seule depuis Tcl, de sorte que sa valeur ne pourra être modifiée qu'en modifiant la variable C. Les tentatives d'écriture de la variable depuis Tcl seront rejetées avec des erreurs.

Tcl_UnlinkVar supprime le lien précédemment établi pour la variable donnée par varName. S'il n'existe pas de lien pour varName, la procédure n'a aucun effet.

Tcl_UpdateLinkedVar peut être appelée après que la variable C ait été modifiée pour forcer la mise à jour immédiate de la variable Tcl. Dans de nombreux cas, cette procédure n'est pas nécessaire, car toute tentative de lire la variable Tcl retournera la dernière valeur de la variable C. Cependant, si une trace a été définie sur la variable Tcl (par exemple, un widget Tk qui souhaite afficher la valeur de la variable), la trace ne sera pas déclenchée lorsque la variable C aura été modifiée. Tcl_UpdateLinkedVar garantit que toutes les traces sur la variable Tcl sont invoquées.

Notez que, comme pour tout appel à un interpréteur Tcl, Tcl_UpdateLinkedVar doit être appelé depuis le même thread qui a créé l'interpréteur. Le mécanisme le plus sûr consiste à s'assurer que la variable C n'est jamais mise à jour depuis un thread autre que celui qui a créé l'interpréteur (éventuellement en réponse à un événement posté avec Tcl_ThreadQueueEvent), mais lorsqu'il est nécessaire de mettre à jour la variable dans un thread séparé, il est conseillé d'utiliser Tcl_AsyncMark pour indiquer au thread hébergeant l'interpréteur qu'il est prêt à exécuter Tcl_UpdateLinkedVar.
