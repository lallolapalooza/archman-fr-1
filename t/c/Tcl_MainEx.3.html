Tcl_Main(3) Procédures de la bibliothèque Tcl Tcl_Main(3)

NOM

Tcl_Main, Tcl_MainEx, Tcl_MainExW, Tcl_SetStartupScript, Tcl_GetStartupScript, Tcl_SetMainLoop - programme principal, script de démarrage et boucle d'événements pour les applications Tcl

SYNOPIS

#include <tcl.h>

Tcl_Main(argc, argv, appInitProc)

Tcl_MainEx(argc, charargv, appInitProc, interp)

Tcl_MainExW(argc, wideargv, appInitProc, interp)

Tcl_SetStartupScript(path, encoding)

Tcl_Obj *
Tcl_GetStartupScript(encodingPtr)

Tcl_SetMainLoop(mainLoopProc)

ARGUMENTS

int argc (in)
Nombre d'éléments dans argv.
char *argv[] (in)
Tableau de chaînes contenant les arguments de la ligne de commande. Sous Windows, lorsque -DUNICODE est utilisé, le type devient wchar_t *.
char *charargv[] (in)
Comme argv, mais ne change pas le type en wchar_t.
char *wideargv[] (in)
Comme argv, mais le type est toujours wchar_t.
Tcl_AppInitProc *appInitProc (in)
Adresse d'une fonction d'initialisation spécifique à l'application. La valeur de cet argument est généralement Tcl_AppInit.
Tcl_Obj *path (in)
Nom du fichier à utiliser comme script de démarrage, ou NULL.
const char *encoding (in)
Encodage du fichier à utiliser comme script de démarrage, ou NULL.
const char **encodingPtr (out)
Si non NULL, emplacement pour copier le (const char *) pointant vers l'encodage du fichier.
Tcl_MainLoopProc *mainLoopProc (in)
Adresse d'une fonction de boucle d'événements pour l'application spécifique.
Tcl_Interp *interp (in)
Interpréteur Tcl déjà créé.

DESCRIPTION

Tcl_Main peut servir de programme principal pour les applications shell basées sur Tcl. Une "application shell" est un programme similaire à tclsh ou wish qui prend en charge à la fois l'interprétation interactive de Tcl et l'évaluation d'un script contenu dans un fichier donné en tant qu'argument de ligne de commande. Tcl_Main est offert comme commodité pour les développeurs d'applications shell, afin qu'ils n'aient pas à répéter tout le code pour l'initialisation appropriée de la bibliothèque Tcl et le fonctionnement du shell interactif. D'autres styles d'incorporation de Tcl dans une application ne sont pas pris en charge par Tcl_Main. Ceux-ci doivent être réalisés en appelant directement les fonctions de bas niveau de la bibliothèque Tcl.

La fonction Tcl_Main est proposée par la bibliothèque Tcl depuis la version 7.4. Dans les versions antérieures de Tcl, la bibliothèque elle-même définissait une fonction main, mais celle-ci n'avait pas la flexibilité du style d'incorporation et le fait d'avoir une fonction main dans une bibliothèque (en particulier dans une bibliothèque partagée) causait des problèmes sur de nombreux systèmes. Avoir main dans la bibliothèque Tcl rendrait également difficile l'utilisation de Tcl dans des programmes C++, car les programmes C++ doivent avoir des fonctions main C++ spéciales.

Normalement, chaque application shell contient une petite fonction main qui appelle Tcl_Main. Tcl_Main effectue ensuite tout le travail de création et d'exécution d'une application similaire à tclsh.

Tcl_Main n'est pas disponible dans l'interface publique de la bibliothèque de stubs Tcl. Les programmes qui appellent Tcl_Main doivent être liés à la bibliothèque Tcl standard. Les extensions (avec ou sans stubs) ne sont pas conçues pour appeler Tcl_Main.

Tcl_Main n'est pas sûr pour les threads. Il ne doit être appelé que par un seul thread principal d'une application multithread. Cette restriction n'est pas un problème dans l'utilisation normale décrite ci-dessus.

Tcl_Main et toute application basée sur celle-ci, comme tclsh, utilisent Tcl_GetStdChannel pour initialiser les canaux standard à leurs valeurs par défaut. Consultez Tcl_StandardChannels pour plus d'informations.

Tcl_Main prend en charge deux modes de fonctionnement, selon que le nom et l'encodage du script de démarrage ont été définis. Les routines Tcl_SetStartupScript et Tcl_GetStartupScript sont les instruments pour contrôler cette configuration de Tcl_Main.

Tcl_SetStartupScript enregistre la valeur path comme nom de fichier que Tcl_Main utilisera comme script de démarrage. La valeur encoding est le nom de l'encodage utilisé pour stocker le texte dans ce fichier. Une valeur NULL pour encoding indique que l'encodage du système sera utilisé. Une valeur NULL pour path supprime tout enregistrement précédent et Tcl_Main n'évaluera aucun script de démarrage.

Tcl_GetStartupScript interroge le nom et l'encodage enregistrés par le dernier appel à Tcl_SetStartupScript dans le même thread. Le nom du fichier stocké est renvoyé et le nom de l'encodage stocké est écrit à l'emplacement pointé par encodingPtr, lorsque celui-ci n'est pas NULL.

Les valeurs de nom et d'encodage gérées par les routines Tcl_SetStartupScript et Tcl_GetStartupScript sont stockées par thread. Bien que les fonctions de stockage et de récupération de ces routines fonctionnent dans n'importe quel thread, seuls les appels dans le même thread que Tcl_Main peuvent avoir une influence sur celui-ci.

L'appelant de Tcl_Main peut appeler Tcl_SetStartupScript en premier pour définir son script de démarrage souhaité. Si Tcl_Main constate qu'il n'y a pas de script de démarrage ainsi, il examine les premiers arguments de argv. Si ceux-ci correspondent à ?-encoding name?, fileName, où fileName ne commence pas par le caractère -, alors fileName est considéré comme le nom d'un fichier contenant un script de démarrage, et name est le nom de l'encodage des contenus de ce fichier. Tcl_Main appelle ensuite Tcl_SetStartupScript avec ces valeurs.

Tcl_Main définit ensuite dans son interpréteur principal les variables Tcl argc, argv, argv0 et tcl_interactive, comme décrit dans la documentation de tclsh.

Après sa propre initialisation, Tcl_Main appelle la procédure spécifiée par l'argument appInitProc. Cette procédure fournit un "point d'entrée" pour l'application afin qu'elle effectue sa propre initialisation de l'interprétation créée par Tcl_Main, comme la définition de commandes spécifiques à l'application. La routine d'initialisation de l'application peut également appeler Tcl_SetStartupScript pour (re)définir le fichier et l'encodage utilisés comme script de démarrage. La procédure doit avoir une interface correspondant au type Tcl_AppInitProc :

typedef int Tcl_AppInitProc(
        Tcl_Interp *interp);

AppInitProc est presque toujours un pointeur vers Tcl_AppInit ; pour plus de détails sur cette procédure, consultez la documentation de Tcl_AppInit.

Lorsque la procédure appInitProc est terminée, Tcl_Main appelle Tcl_GetStartupScript pour déterminer quel script de démarrage a été demandé, s'il y en a un. Si un script de démarrage a été fourni, Tcl_Main tente de l'évaluer. Sinon, il démarre le mode interactif en examinant la variable tcl_rcFileName dans l'interpréteur principal. Si cette variable existe et contient le nom d'un fichier lisible, le contenu de ce fichier est évalué dans l'interpréteur principal. Ensuite, le mode interactif est démarré, avec les invites et les résultats d'évaluation des commandes écrits sur le canal de sortie standard, et les commandes lues à partir du canal d'entrée standard et évaluées. Les invites écrites sur le canal de sortie standard peuvent être personnalisées en définissant les variables tcl_prompt1 et tcl_prompt2 comme décrit dans la documentation de tclsh. Les invites et les résultats d'évaluation des commandes sont écrits uniquement sur le canal de sortie standard si la variable tcl_interactive dans l'interpréteur principal contient une valeur non nulle.

Tcl_SetMainLoop permet de définir une procédure de boucle d'événements à exécuter. Cela permet, par exemple, de charger dynamiquement Tk et de définir sa boucle d'événements. La boucle d'événements s'exécutera après le script de démarrage. Si vous êtes en mode interactif, la définition de la procédure de boucle d'événements entraînera la définition de l'invite sur base de fileevent, puis l'appel de la procédure de boucle d'événements. Lorsque la procédure de boucle d'événements retourne en mode interactif, l'opération interactive se poursuit. La procédure de boucle d'événements principale doit avoir une interface correspondant au type Tcl_MainLoopProc :

typedef void Tcl_MainLoopProc(void);

Tcl_Main ne retourne pas. Normalement, une application basée sur Tcl_Main se terminera lorsque la commande de sortie exit sera évaluée. En mode interactif, si une fin de fichier (EOF) ou une erreur de canal est détectée sur le canal d'entrée standard, Tcl_Main évaluera lui-même la commande de sortie exit.
