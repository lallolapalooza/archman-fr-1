DESCRIPTION

Tcl utilise une architecture de canaux double. Il fournit une couche supérieure générique pour permettre aux programmes C et Tcl d'effectuer des entrées et sorties en utilisant les mêmes API pour une variété de fichiers, périphériques, sockets, etc. Les API C générales sont décrites dans le manuel de Tcl_OpenFileChannel.

La couche inférieure fournit des pilotes de canaux spécifiques pour chaque type de périphérique pris en charge sur chaque plateforme. Ce manuel décrit les API C qui communiquent entre la couche générique et les pilotes de canaux spécifiques. Il explique également comment de nouveaux types de canaux peuvent être ajoutés en fournissant de nouveaux pilotes de canaux.

Les pilotes de canaux se composent de plusieurs composants : Premièrement, chaque pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers les fonctions implémentées pour effectuer les diverses opérations utilisées par la couche générique pour communiquer avec le pilote de canal. La structure Tcl_ChannelType et les fonctions auxquelles elle fait référence sont décrites dans la section TCL_CHANNELTYPE, ci-dessous.

Deuxièmement, les pilotes de canaux fournissent généralement une commande Tcl pour créer des instances de ce type de canal. Par exemple, la commande Tcl open crée des canaux qui utilisent les pilotes de fichiers et de commandes, et la commande Tcl socket crée des canaux qui utilisent les protocoles réseau TCP pour la communication réseau.

Troisièmement, un pilote de canal fournit facultativement une fonction C pour ouvrir des instances de ce type de canal. Par exemple, Tcl_OpenFileChannel ouvre un canal utilisant le pilote de fichier, et Tcl_OpenTcpClient ouvre un canal utilisant le protocole réseau TCP. Ces fonctions d'ouverture utilisent généralement Tcl_CreateChannel en interne pour ouvrir le canal.

Pour ajouter un nouveau type de canal, vous devez implémenter une API C ou une commande Tcl qui ouvre un canal en appelant Tcl_CreateChannel. Lorsque votre pilote appelle Tcl_CreateChannel, il transmet une structure Tcl_ChannelType décrivant les procédures d'E/S de votre pilote. La couche générique appellera ensuite les fonctions référencées dans cette structure pour effectuer des opérations sur le canal.

Tcl_CreateChannel ouvre un nouveau canal et lui associe typePtr et instanceData. Le canal est ouvert dans le mode indiqué par mask. Pour une discussion sur les pilotes de canaux, leurs opérations et la structure Tcl_ChannelType, voir la section TCL_CHANNELTYPE, ci-dessous.

Tcl_CreateChannel interagit avec le code qui gère les canaux standard. Une fois qu'un canal standard a été initialisé, via un appel à Tcl_GetStdChannel ou un appel à Tcl_SetStdChannel, la fermeture de ce canal amènera le prochain appel à Tcl_CreateChannel à faire également du nouveau canal un canal standard. Voir Tcl_StandardChannels pour un traitement général des canaux standard et le comportement de la bibliothèque Tcl à leur égard.

Tcl_GetChannelInstanceData renvoie les données d'instanciation associées au canal dans channel. Il s'agit de la même valeur que l'argument instanceData dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelType renvoie un pointeur vers la structure Tcl_ChannelType utilisée par le canal dans l'argument channel. Il s'agit de la même valeur que l'argument typePtr dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelName renvoie une chaîne contenant le nom associé au canal, ou NULL si l'argument channelName à Tcl_CreateChannel était NULL.

Tcl_GetChannelHandle place le handle de périphérique spécifique au système d'exploitation associé à channel pour la direction donnée à l'emplacement spécifié par handlePtr.

TCL_CHANNELTYPE

Un pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers des fonctions qui implémentent les différentes opérations sur un canal ; ces opérations sont appelées au besoin par la couche générique. La structure a été versionnée à partir de Tcl 8.3.2/8.4 pour corriger un problème avec les pilotes de canaux bloqués. Voir la section TYPES DE CANAUX ANCIENS pour plus de détails sur l'ancienne structure.

La structure Tcl_ChannelType contient les champs suivants :

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Il n'est pas nécessaire de fournir des implémentations pour toutes les opérations de canal. Celles qui ne sont pas nécessaires peuvent être définies à NULL dans la structure : blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc et close2Proc, ainsi que flushProc, handlerProc, threadActionProc et truncateProc. Les autres fonctions qui ne peuvent pas être implémentées de manière significative doivent renvoyer EINVAL lorsqu'elles sont appelées, indiquant que les opérations représentées ne sont pas disponibles. Il est également important de noter que wideSeekProc peut être NULL si seekProc ne l'est pas.

L'utilisateur ne doit utiliser que la structure mentionnée pour l'instanciation de Tcl_ChannelType. Lorsqu'il fait référence aux champs d'une structure Tcl_ChannelType, les fonctions suivantes doivent être utilisées pour obtenir les valeurs : Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc ou Tcl_ChannelFlushProc.

La modification des structures a été apportée de manière à ce que les types de canaux standard soient binaires compatibles. Cependant, les types de canaux qui utilisent des canaux bloqués (c'est-à-dire TLS, Trf) ont de nouvelles versions pour correspondre à ce changement en raison des problèmes précédents dans le code des canaux bloqués.

TYPENAME

Le champ typeName contient une chaîne terminée par null qui identifie le type de périphérique implémenté par ce pilote, par exemple file ou socket.

Cette valeur peut être obtenue avec Tcl_ChannelName, qui renvoie un pointeur vers la chaîne.

VERSION

Le champ version doit être défini sur la version de la structure requise. TCL_CHANNEL_VERSION_2 est la version minimale recommandée. TCL_CHANNEL_VERSION_3 doit être défini pour spécifier le champ wideSeekProc. TCL_CHANNEL_VERSION_4 doit être défini pour spécifier le champ threadActionProc (inclut wideSeekProc). TCL_CHANNEL_VERSION_5 doit être défini pour spécifier les champs truncateProc (inclut wideSeekProc et threadActionProc). Si aucune de ces valeurs n'est définie, on suppose que le Tcl_ChannelType a la structure d'origine. Voir TYPES DE CANAUX ANCIENS pour plus de détails. Bien que Tcl reconnaisse et fonctionne avec toutes ces structures, les canaux bloqués doivent avoir au moins TCL_CHANNEL_VERSION_2 pour fonctionner correctement.

Cette valeur peut être obtenue avec Tcl_ChannelVersion, qui renvoie l'une des valeurs suivantes : TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 ou TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

Le champ blockModeProc contient l'adresse d'une fonction appelée par la couche générique pour définir le mode bloquant et non bloquant sur le périphérique. BlockModeProc doit correspondre au prototype suivant :

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

Le instanceData est le même que la valeur fournie à Tcl_CreateChannel lors de la création de ce canal. L'argument mode est soit TCL_MODE_BLOCKING soit TCL_MODE_NONBLOCKING pour définir le périphérique en mode bloquant ou non bloquant. La fonction doit renvoyer zéro si l'opération a réussi, ou un code d'erreur POSIX non nul si l'opération a échoué.

Si l'opération a réussi, la fonction peut modifier le instanceData fourni pour enregistrer que le canal est passé en mode bloquant ou non bloquant et pour implémenter le comportement correspondant. Pour certains types de périphériques, le comportement bloquant et non bloquant peut être implémenté par le système d'exploitation sous-jacent ; pour d'autres types de périphériques, le comportement doit être émulé dans le pilote de canal.

Cette valeur peut être obtenue avec Tcl_ChannelBlockModeProc, qui renvoie un pointeur vers la fonction.

Un pilote de canal qui ne fournit pas de blockModeProc doit être très prudent. Il doit indiquer exactement quel mode bloquant lui convient, et s'il le documente également pour l'utilisateur, alors le mode bloquant du canal ne sera pas modifié à une valeur inacceptable. Toute confusion ici peut entraîner un blocage (faux et difficile à trouver) de l'interpréteur.

DESCRIPTION

These procedures provide the Tcl interface for manipulating channels. Channels are Tcl objects that represent an I/O source or destination. Tcl supports channels for files, pipes, sockets, and serial ports.

A channel is implemented by a channel driver. A channel driver is a collection of C procedures that perform I/O operations for a particular type of channel. Tcl includes built-in channel drivers for files and sockets. Users can implement their own channel drivers for other types of I/O.

The channel driver is described by a Tcl_ChannelType structure, which contains pointers to procedures that perform operations on channels of that type. The structure is defined as follows:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverNotifyProc *normalizeProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGet

Le champ closeProc contient l'adresse d'une fonction appelée par la couche générique pour fermer un canal. La fonction closeProc doit correspondre au prototype suivant :




typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);




InstanceData est la même valeur que celle passée à
    Tcl_CreateChannel lors de la création du canal. La fonction doit effectuer
    les actions nécessaires pour fermer le canal. Si le canal est fermé avec succès,
    la fonction doit retourner 0 ; sinon, elle doit retourner un code d'erreur POSIX
    non nul. De plus, si une erreur se produit et que interp n'est pas NULL,
    la procédure doit stocker un message d'erreur dans le résultat de l'interpréteur.


Alternativement, les canaux qui prennent en charge la fermeture
    indépendante des côtés de lecture et d'écriture peuvent définir
    closeProc sur TCL_CLOSE2PROC et définir close2Proc sur
    l'adresse d'une fonction correspondant au prototype suivant :




typedef int Tcl_DriverClose2Proc(
        ClientData instanceData,
        Tcl_Interp *interp,
        int flags);




Le close2Proc sera appelé avec flags défini sur une
    combinaison OR de TCL_CLOSE_READ ou TCL_CLOSE_WRITE pour indiquer
    que le pilote doit fermer le côté lecture et/ou écriture du canal. Le pilote
    de canal peut être appelé pour effectuer des opérations supplémentaires sur le
    canal après que close2Proc ait été appelé pour fermer un ou les deux côtés
    du canal. Si flags est 0 (zéro), le pilote doit fermer le canal de la
    manière décrite ci-dessus pour closeProc. Aucune autre opération ne sera
    invoquée sur cette instance après que close2Proc ait été appelé avec
    tous les drapeaux effacés. Dans tous les cas, la fonction close2Proc doit
    retourner zéro si l'opération de fermeture a réussi ; sinon, elle doit retourner
    un code d'erreur POSIX non nul. De plus, si une erreur se produit et que
    interp n'est pas NULL, la procédure doit stocker un message d'erreur dans
    le résultat de l'interpréteur.


Les valeurs closeProc et close2Proc peuvent être récupérées
    avec Tcl_ChannelCloseProc ou Tcl_ChannelClose2Proc, qui retournent
    un pointeur vers la fonction respective.

INPUTPROC

Le champ inputProc contient l'adresse d'une fonction appelée par la couche générique pour lire des données du fichier ou de l'appareil et les stocker dans un tampon interne. InputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création du canal. L'argument buf pointe vers un tableau d'octets dans lequel stocker l'entrée de l'appareil, et l'argument bufSize indique combien d'octets sont disponibles à buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique. Si une erreur se produit, la fonction doit définir la variable sur un code d'erreur POSIX qui identifie l'erreur qui s'est produite.

La fonction doit lire les données de l'appareil d'entrée encapsulé par le canal et les stocker dans buf. En cas de succès, la fonction doit retourner un entier non négatif indiquant combien d'octets ont été lus à partir de l'appareil d'entrée et stockés dans buf. En cas d'erreur, la fonction doit retourner -1. Si une erreur se produit après que certaines données ont été lues à partir de l'appareil, ces données sont perdues.

Si inputProc peut déterminer que l'appareil d'entrée dispose de données disponibles mais moins que demandé par l'argument bufSize, la fonction ne doit tenter de lire que la quantité de données disponible et retourner sans bloquer. Si l'appareil d'entrée n'a aucune donnée disponible et que le canal est en mode non bloquant, la fonction doit retourner une erreur EAGAIN. Si l'appareil d'entrée n'a aucune donnée disponible et que le canal est en mode bloquant, la fonction doit bloquer pendant la durée la plus courte possible jusqu'à ce qu'au moins un octet de données puisse être lu à partir de l'appareil ; ensuite, elle doit retourner autant de données qu'elle peut lire sans bloquer.

Cette valeur peut être récupérée avec Tcl_ChannelInputProc, qui retourne un pointeur vers la fonction.

OUTPUTPROC

Le champ outputProc contient l'adresse d'une fonction appelée par la couche générique pour transférer des données d'un tampon interne vers l'appareil de sortie. OutputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création du canal. L'argument buf contient un tableau d'octets à écrire dans l'appareil, et l'argument toWrite indique combien d'octets doivent être écrits à partir de l'argument buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique. Si une erreur se produit, la fonction doit définir cette variable sur un code d'erreur POSIX qui identifie l'erreur.

La fonction doit écrire les données dans buf dans l'appareil de sortie encapsulé par le canal. En cas de succès, la fonction doit retourner un entier non négatif indiquant combien d'octets ont été écrits dans l'appareil de sortie. La valeur de retour est normalement la même que toWrite, mais peut être inférieure dans certains cas, par exemple si l'opération de sortie est interrompue par un signal. Si une erreur se produit, la fonction doit retourner -1. En cas d'erreur, certaines données peuvent avoir été écrites dans l'appareil.

Si le canal n'est pas bloquant et que l'appareil de sortie ne peut absorber aucune donnée, la fonction doit retourner -1 avec une erreur EAGAIN sans écrire aucune donnée.

Cette valeur peut être récupérée avec Tcl_ChannelOutputProc, qui retourne un pointeur vers la fonction.

SEEKPROC ET WIDESEEKPROC

Le champ seekProc contient l'adresse d'une fonction appelée par la couche générique pour déplacer le point d'accès auquel les opérations d'entrée ou de sortie ultérieures seront appliquées. SeekProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

L'argument instanceData est la même valeur que celle donnée à Tcl_CreateChannel lors de la création de ce canal. Offset et seekMode ont la même signification que pour la procédure Tcl_Seek (décrite dans l'entrée de manuel de Tcl_OpenFileChannel).

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique pour retourner les valeurs errno de la fonction. La fonction doit définir cette variable sur un code d'erreur POSIX si une erreur se produit. La fonction doit stocker un code d'erreur EINVAL si le type de canal n'implémente pas le déplacement.

La valeur de retour est le nouveau point d'accès ou -1 en cas d'erreur. Si une erreur s'est produite, la fonction ne doit pas déplacer le point d'accès.

S'il existe un champ seekProc non NULL, le champ wideSeekProc peut contenir l'adresse d'une fonction alternative à utiliser, qui gère les décalages larges (c'est-à-dire plus grands que 32 bits), permettant ainsi les déplacements dans des fichiers de plus de 2 Go. typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

Les arguments et les valeurs de retour signifient la même chose qu'avec seekProc ci-dessus, à l'exception du type des décalages et du type de retour qui sont différents.

La valeur seekProc peut être récupérée avec Tcl_ChannelSeekProc, qui retourne un pointeur vers la fonction, et de même, le wideSeekProc peut être récupéré avec Tcl_ChannelWideSeekProc.

SETOPTIONPROC

Le champ setOptionProc contient l'adresse d'une fonction appelée par la couche générique pour définir une option spécifique au type de canal sur un canal. setOptionProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

optionName est le nom d'une option à définir, et newValue est la nouvelle valeur de cette option, sous forme de chaîne. instanceData est la même valeur que celle donnée à Tcl_CreateChannel lors de la création de ce canal. La fonction doit effectuer l'action spécifique au type de canal requise pour implémenter la nouvelle valeur de l'option.

Certaines options sont gérées par le code générique et cette fonction n'est jamais appelée pour les définir, par exemple -blockmode. D'autres options sont spécifiques à chaque type de canal et la procédure setOptionProc du pilote de canal sera appelée pour les implémenter. Le champ setOptionProc peut être NULL, ce qui indique que ce type de canal ne prend en charge aucune option spécifique au type.

Si la valeur de l'option est modifiée avec succès vers la nouvelle valeur, la fonction retourne TCL_OK. Elle doit appeler Tcl_BadChannelOption qui elle-même retourne TCL_ERROR si optionName n'est pas reconnu. Si newValue spécifie une valeur pour l'option qui n'est pas prise en charge ou si une erreur d'appel système se produit, la fonction doit laisser un message d'erreur dans le résultat de interp si interp n'est pas NULL. La fonction doit également appeler Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

Cette valeur peut être récupérée avec Tcl_ChannelSetOptionProc, qui retourne un pointeur vers la fonction.

GETOPTIONPROC

Le champ getOptionProc contient l'adresse d'une fonction appelée par la couche générique pour obtenir la valeur d'une option spécifique au type de canal sur un canal. getOptionProc doit correspondre au prototype suivant :

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,

Si optionName est NULL, la fonction stocke dans optionValue une liste alternée de toutes les options prises en charge et de leurs valeurs actuelles. En cas de succès, la fonction retourne TCL_OK. Tcl_CreateChannelDriver

NOM

Tcl_CreateChannelDriver - enregistrer un nouveau type de canal

SYNOPIS

#include <tcl.h>

int
Tcl_CreateChannelDriver(
        const char *typeName,
        Tcl_ChannelType *typePtr);

DESCRIPTION

La procédure Tcl_CreateChannelDriver enregistre un nouveau type de canal avec Tcl. Les types de canaux sont utilisés pour implémenter différents types de canaux Tcl, tels que les fichiers, les pipes, les sockets et les canaux série. Chaque type de canal est implémenté par un ensemble de procédures appelées collectivement un pilote de canal. Le pilote décrit le comportement du type de canal, y compris comment lire et écrire des données, comment gérer les options et comment notifier Tcl des événements se produisant sur le canal.

Le premier argument, typeName, est une chaîne de caractères identifiant le nouveau type de canal. Il doit être unique. Le second argument, typePtr, est un pointeur vers une structure Tcl_ChannelType qui décrit les procédures du pilote de canal.

La structure Tcl_ChannelType contient les champs suivants :

typeName
Le nom du type de canal. Doit correspondre à l'argument typeName de Tcl_CreateChannelDriver.
blockModeProc
Pointeur vers une procédure qui sera appelée par la couche générique pour définir le mode bloquant du canal. Elle devrait correspondre au prototype suivant :
typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. Le mode est soit TCL_MODE_BLOCKING, soit TCL_MODE_NONBLOCKING. La procédure doit retourner 0 en cas de succès, ou un code d'erreur errno approprié (qui peut être utilisé avec Tcl_SetErrno) en cas d'échec.

Cette valeur peut être récupérée avec Tcl_ChannelBlockModeProc, qui retourne un pointeur vers la procédure.

closeProc
Pointeur vers une procédure appelée par la couche générique pour fermer le canal. Elle devrait correspondre au prototype suivant :
typedef int Tcl_DriverCloseProc(
        ClientData instanceData);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. La procédure doit effectuer toute opération de nettoyage nécessaire pour le canal, y compris la libération de toute mémoire allouée par le pilote de canal. Elle doit retourner 0 en cas de succès, ou un code d'erreur errno approprié en cas d'échec.

Cette valeur peut être récupérée avec Tcl_ChannelCloseProc, qui retourne un pointeur vers la procédure.

inputProc
Pointeur vers une procédure appelée par la couche générique pour lire des données du canal. Elle devrait correspondre au prototype suivant :
typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        Tcl_Errno *errorPtr);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. Le deuxième argument, buf, est un tampon dans lequel les données lues doivent être placées. Le troisième argument, bufSize, est la taille maximale du tampon. Le quatrième argument, errorPtr, est un pointeur vers une variable dans laquelle le code d'erreur POSIX doit être stocké en cas d'erreur. La procédure doit retourner le nombre d'octets lus, ou -1 en cas d'erreur. Si le canal est fermé pendant la lecture, elle doit retourner 0.

Cette valeur peut être récupérée avec Tcl_ChannelInputProc, qui retourne un pointeur vers la procédure.

outputProc
Pointeur vers une procédure appelée par la couche générique pour écrire des données sur le canal. Elle devrait correspondre au prototype suivant :
typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int numBytes,
        Tcl_Errno *errorPtr);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. Le deuxième argument, buf, est le tampon contenant les données à écrire. Le troisième argument, numBytes, est le nombre d'octets à écrire. Le quatrième argument, errorPtr, est un pointeur vers une variable dans laquelle le code d'erreur POSIX doit être stocké en cas d'erreur. La procédure doit retourner le nombre d'octets écrits, ou -1 en cas d'erreur. Si le canal est fermé pendant l'écriture, elle doit retourner 0.

Cette valeur peut être récupérée avec Tcl_ChannelOutputProc, qui retourne un pointeur vers la procédure.

seekProc
Pointeur vers une procédure appelée par la couche générique pour rechercher une position dans le canal. Elle devrait correspondre au prototype suivant :
typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        Tcl_SeekOffset offset,
        int seekMode);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. L'argument offset spécifie le décalage par rapport au point de référence. L'argument seekMode est soit SEEK_SET, SEEK_CUR, soit SEEK_END. La procédure doit retourner la nouvelle position de lecture/écriture dans le canal, ou -1 en cas d'erreur. Cette procédure n'est utilisée que pour les canaux qui prennent en charge la recherche.

Cette valeur peut être récupérée avec Tcl_ChannelSeekProc, qui retourne un pointeur vers la procédure.

setOptionProc
Pointeur vers une procédure appelée par la couche générique pour définir une option du canal. Elle devrait correspondre au prototype suivant :
typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        const char *optionName,
        const char *value,
        Tcl_Interp *interp);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. L'argument optionName est le nom de l'option à définir. L'argument value est la valeur de l'option. L'argument interp est l'interpréteur dans lequel l'option est définie. La procédure doit retourner TCL_OK en cas de succès, ou TCL_ERROR en cas d'échec. Si une option non reconnue est fournie, la procédure devrait générer une erreur dans l'interpréteur et retourner TCL_ERROR. Si une erreur de système se produit, la procédure devrait laisser un message d'erreur dans le résultat de interp si interp n'est pas NULL. La procédure devrait également appeler Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

Certaines options sont gérées par le code générique et cette procédure n'est jamais appelée pour récupérer leur valeur, par ex. -blockmode. D'autres options sont spécifiques à chaque type de canal et la procédure getOptionProc du pilote de canal sera appelée pour les implémenter. Le champ getOptionProc peut être NULL, ce qui indique que ce type de canal ne prend en charge aucune option spécifique au type.

Cette valeur peut être récupérée avec Tcl_ChannelSetOptionProc, qui retourne un pointeur vers la procédure.

Pointeur vers une procédure appelée par la couche générique pour récupérer la valeur d'une option du canal. Elle devrait correspondre au prototype suivant :
typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        const char *optionName,
        Tcl_Interp *interp);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. L'argument optionName est le nom de l'option à récupérer. L'argument interp est l'interpréteur dans lequel la valeur de l'option doit être stockée. La procédure doit retourner TCL_OK en cas de succès, ou TCL_ERROR en cas d'échec. Si une option non reconnue est fournie, la procédure devrait générer une erreur dans l'interpréteur et retourner TCL_ERROR. Si une erreur de système se produit, la procédure devrait laisser un message d'erreur dans le résultat de interp si interp n'est pas NULL. La procédure devrait également appeler Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

Certaines options sont gérées par le code générique et cette procédure n'est jamais appelée pour récupérer leur valeur, par ex. -blockmode. D'autres options sont spécifiques à chaque type de canal et cette procédure sera appelée pour les implémenter. Le champ getOptionProc peut être NULL, ce qui indique que ce type de canal ne prend en charge aucune option spécifique au type.

Cette valeur peut être récupérée avec Tcl_ChannelGetOptionProc, qui retourne un pointeur vers la procédure.

watchProc
Pointeur vers une procédure appelée par la couche générique pour initialiser le mécanisme de notification d'événements pour signaler les événements d'intérêt sur ce canal. WatchProc devrait correspondre au prototype suivant :
typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

Le instanceData est le même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. L'argument mask est une combinaison OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION ; il indique les événements dont l'appelant s'intéresse sur ce canal.

La procédure doit initialiser les mécanismes spécifiques au type de périphérique pour remarquer quand un événement d'intérêt est présent sur le canal. Lorsqu'un ou plusieurs des événements désignés se produisent sur le canal, le pilote de canal est responsable d'appeler Tcl_NotifyChannel pour informer le module générique de canal. Le pilote doit veiller à ne pas affamer d'autres pilotes de canal ou sources de rappels en invoquant Tcl_NotifyChannel trop fréquemment. L'équité peut être assurée en utilisant la file d'événements Tcl pour permettre la planification de l'événement de canal en séquence avec d'autres événements. Voir la description de Tcl_QueueEvent pour plus de détails sur la façon de mettre un événement en file d'attente.

Cette valeur peut être récupérée avec Tcl_ChannelWatchProc, qui retourne un pointeur vers la procédure.

getHandleProc
Pointeur vers une procédure appelée par la couche générique pour récupérer un handle spécifique au périphérique à partir du canal. GetHandleProc devrait correspondre au prototype suivant :
typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. L'argument direction est soit TCL_READABLE pour récupérer le handle utilisé pour l'entrée, soit TCL_WRITABLE pour récupérer le handle utilisé pour la sortie.

Si l'implémentation du canal a des handles spécifiques au périphérique, la procédure doit récupérer le handle approprié associé au canal, selon l'argument direction. Le handle doit être stocké dans l'emplacement référencé par handlePtr, et TCL_OK doit être retourné. Si le canal n'est pas ouvert pour la direction spécifiée, ou si l'implémentation du canal n'utilise pas de handles de périphérique, la procédure doit retourner TCL_ERROR.

Cette valeur peut être récupérée avec Tcl_ChannelGetHandleProc, qui retourne un pointeur vers la procédure.

flushProc
Le champ flushProc est actuellement réservé pour une utilisation future. Il doit être défini à NULL. FlushProc devrait correspondre au prototype suivant :
typedef int Tcl_DriverFlushProc(

TCL_BADCHANNELOPTION

Cette procédure génère un message d'erreur « mauvaise option » dans un interpréteur (optionnel). Elle est utilisée par les pilotes de canal lorsqu'une option Set/Get invalide est demandée. Son but est de concaténer la liste des options génériques à celles spécifiques et de factoriser la chaîne de message d'erreur des options génériques.

Elle retourne toujours TCL_ERROR

Un message d'erreur est généré dans la valeur de résultat de interp pour indiquer qu'une commande a été invoquée avec une mauvaise option. Le message a la forme

    mauvaise option "blah": devrait être l'un de
    <...options génériques...>+<...options spécifiques...>
donc vous obtenez par exemple : 
    mauvaise option "-blah": devrait être l'un de -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, ou -sockname
lorsque appelée avec optionList égal à « peername sockname »

« blah » est l'argument optionName et « <options spécifiques> » est une liste d'options spécifiques séparées par des espaces. La fonction prend soin d'insérer des signes moins avant chaque option, des virgules après, et un « ou » avant la dernière option.

Pointeur vers un emplacement mémoire dans lequel le handle sera stocké si la commande réussit. Le type exact du handle dépend du type de canal.

DESCRIPTION

Cette fonction est une fonction d'aide qui permet de récupérer le descripteur de fichier sous-jacent (ou une autre forme d'identifiant) pour un canal Tcl donné. Le canal est identifié par son nom, chanName.

Si le canal nommé chanName existe et est un canal pour lequel un handle peut être récupéré (par exemple, un canal de fichier ou un canal socket), la fonction stockera le handle dans l'emplacement mémoire pointé par handlePtr et retournera 1. Si le canal n'existe pas, ou s'il s'agit d'un type de canal pour lequel un handle ne peut pas être directement récupéré, la fonction retournera 0 et laissera une erreur dans l'interpréteur interp.

TCL_CHANNELTYPE

Les types de canaux Tcl sont définis par des structures Tcl_ChannelType. Chaque structure Tcl_ChannelType peut fournir une fonction getHandleProc qui sera appelée par Tcl_GetChannelHandle pour obtenir le handle sous-jacent. Si le getHandleProc du type de canal est NULL, Tcl_GetChannelHandle échouera.

TCL_BADCHANNELOPTION

L'erreur retournée par Tcl_GetChannelHandle lorsque le canal n'existe pas ou n'a pas de handle sous-jacent est généralement du type TCL_BADCHANNELOPTION.

TYPES DE CANAL ANTIGOS

Dans les anciennes versions de Tcl, il était possible d'enregistrer des types de canaux qui ne fournissaient pas explicitement un getHandleProc. Dans ce cas, Tcl_GetChannelHandle peut avoir tenté d'en déduire un, mais cela n'est plus supporté.
