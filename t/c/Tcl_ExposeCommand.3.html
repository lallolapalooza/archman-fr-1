DESCRIPTION

Ces procédures sont destinées à l'accès à la facilité des multiples interpréteurs depuis des programmes C. Elles permettent de gérer plusieurs interpréteurs dans une relation hiérarchique, et la gestion des alias, des commandes qui, lorsqu'elles sont invoquées dans un interpréteur, exécutent une commande dans un autre interpréteur. La valeur de retour pour celles des procédures qui retournent un int est soit TCL_OK, soit TCL_ERROR. Si TCL_ERROR est retourné, le résultat de l'interpréteur contient un message d'erreur.

Tcl_CreateSlave crée un nouvel interpréteur en tant qu'enfant de interp. Elle crée également une commande enfant nommée childName dans interp qui permet à interp de manipuler le nouvel enfant. Si isSafe est zéro, la commande crée un enfant fiable dans lequel le code Tcl a accès à toutes les commandes Tcl. Si c'est 1, la commande crée un enfant “sûr” dans lequel le code Tcl n'a accès qu'à un ensemble de commandes Tcl définies comme “Safe Tcl”; voir la notice de la commande Tcl interp pour plus de détails. Si la création du nouvel interpréteur enfant a échoué, NULL est retourné.

Tcl_CreateChild est un synonyme de Tcl_CreateSlave.

Tcl_IsSafe retourne 1 si interp est “sûr” (a été créé avec le drapeau TCL_SAFE_INTERPRETER spécifié), 0 sinon.

Tcl_MakeSafe marque interp comme “sûr”, de sorte que les appels futurs à Tcl_IsSafe retournent 1. Elle supprime également toutes les fonctionnalités de base potentiellement dangereuses connues (commandes et variables) de interp. Cependant, elle ne peut pas savoir quelles parties d'une extension ou d'une application sont sûres et ne fait aucune tentative pour supprimer ces parties, donc la sécurité n'est pas garantie après l'appel à Tcl_MakeSafe. Les appelants devront faire attention à leur utilisation de Tcl_MakeSafe pour éviter de fausses affirmations de sécurité. Pour de nombreuses situations, Tcl_CreateSlave peut être un meilleur choix, car elle crée des interpréteurs dans un état de sécurité connu.

Tcl_GetSlave retourne un pointeur vers un interpréteur enfant de interp. L'interpréteur enfant est identifié par childName. Si aucun interpréteur enfant de ce nom n'existe, NULL est retourné.

Tcl_GetChild est un synonyme de Tcl_GetSlave.

Tcl_GetMaster retourne un pointeur vers l'interpréteur maître de interp. Si interp n'a pas de maître (c'est un interpréteur de haut niveau) alors NULL est retourné.

Tcl_GetParent est un synonyme de Tcl_GetMaster.

Tcl_GetInterpPath stocke dans le résultat de interp le chemin relatif entre interp et childInterp; childInterp doit être un enfant de interp. Si le calcul du chemin relatif réussit, TCL_OK est retourné, sinon TCL_ERROR est retourné et un message d'erreur est stocké comme résultat de interp.

Tcl_CreateAlias crée une commande nommée childCmd dans childInterp qui, lorsqu'elle est invoquée, provoque l'invocation de la commande targetCmd dans targetInterp. Les arguments spécifiés par les chaînes contenues dans argv sont toujours ajoutés au début des arguments fournis lors de l'invocation de childCmd et passés à targetCmd. Cette opération retourne TCL_OK si elle réussit, ou TCL_ERROR si elle échoue; dans ce cas, un message d'erreur est laissé dans le résultat de valeur de childInterp. Notez qu'il n'y a aucune restriction sur la relation d'ascendance (telle que créée par Tcl_CreateSlave) entre childInterp et targetInterp. Deux interpréteurs quelconques peuvent être utilisés, sans aucune restriction sur la manière dont ils sont liés.

Tcl_CreateAliasObj est similaire à Tcl_CreateAlias sauf qu'elle prend un vecteur de valeurs à passer comme arguments supplémentaires au lieu d'un vecteur de chaînes de caractères.

Tcl_GetAliasObj retourne des informations sous forme de pointeur vers un vecteur de structures Tcl_Obj sur un alias aliasName dans interp. Chacun des champs de résultat peut être NULL, auquel cas la donnée correspondante n'est pas retournée. Si un champ de résultat n'est pas NULL, l'adresse indiquée est définie à la donnée correspondante. Par exemple, si targetCmdPtr n'est pas NULL, il est défini à un pointeur vers la chaîne contenant le nom de la commande cible.

Tcl_ExposeCommand(3) - Arch manual pages

NAME

Tcl_ExposeCommand, Tcl_HideCommand - make commands visible or invisible to scripts

SYNOPSIS

#include <tcl.h>

int
Tcl_ExposeCommand(interp, hiddenCmdName, cmdName)
    Tcl_Interp *interp;
    const char *hiddenCmdName;
    const char *cmdName;
int
Tcl_HideCommand(interp, cmdName, hiddenCmdName)
    Tcl_Interp *interp;
    const char *cmdName;
    const char *hiddenCmdName;

ARGUMENTS

Tcl_Interp *interp
Interpréteur Tcl à modifier.
const char *hiddenCmdName
Nom sous lequel la commande est connue en tant que commande cachée.
const char *cmdName
Nom sous lequel la commande est connue en tant que commande exposée.

DESCRIPTION

Ces routines sont utilisées pour contrôler la visibilité des commandes Tcl. Tcl gère deux ensembles de commandes : les commandes exposées et les commandes cachées. Les commandes exposées sont celles qui sont normalement disponibles pour être appelées à partir de scripts Tcl. Les commandes cachées ne sont pas directement disponibles pour les scripts et ne peuvent être utilisées que par le biais de commandes spéciales telles que interp alias ou par l'intermédiaire d'appels à des commandes dans un interpréteur parent depuis un interpréteur enfant. Les commandes cachées sont souvent utilisées pour implémenter des fonctionnalités de niveau inférieur ou pour restreindre l'accès à certaines fonctionnalités.

Tcl_ExposeCommand déplace la commande nommée hiddenCmdName de l'ensemble des commandes cachées vers l'ensemble des commandes exposées, en la plaçant sous le nom cmdName. HiddenCmdName doit être le nom d'une commande cachée existante, sinon l'opération retournera TCL_ERROR et laissera un message d'erreur comme résultat de interp. Si une commande exposée nommée cmdName existe déjà, l'opération retournera TCL_ERROR et laissera un message d'erreur comme résultat de interp. Si l'opération réussit, elle retournera TCL_OK. Après l'exécution de cette commande, les tentatives d'utilisation de cmdName dans tout mécanisme d'évaluation de script réussiront à nouveau.

Tcl_HideCommand déplace la commande nommée cmdName de l'ensemble des commandes exposées vers l'ensemble des commandes cachées, sous le nom hiddenCmdName. CmdName doit être le nom d'une commande exposée existante, sinon l'opération retournera TCL_ERROR et laissera un message d'erreur comme résultat de interp. Actuellement, ni cmdName ni hiddenCmdName ne doivent contenir de qualificateurs de namespace, sinon l'opération retournera TCL_ERROR et laissera un message d'erreur comme résultat de interp. CmdName sera recherché dans le namespace global, et non par rapport au namespace courant, même si le namespace courant n'est pas le global. Si une commande cachée dont le nom est hiddenCmdName existe déjà, l'opération retournera également TCL_ERROR et un message d'erreur sera laissé comme résultat de interp. Si l'opération réussit, elle retournera TCL_OK. Après l'exécution de cette commande, les tentatives d'utilisation de cmdName dans tout mécanisme d'évaluation de script échoueront.

Pour une description de l'interface Tcl vers plusieurs interpréteurs, voir interp(n).
