Tcl_Interp *interp (in)
Interpréteur à utiliser pour le rapport d'erreurs, ou NULL si aucun rapport d'erreurs n'est souhaité.
const char *name (in)
Nom de l'encodage à charger.
Tcl_Encoding encoding (in)
Encodage à interroger, libérer ou utiliser pour convertir du texte. Si encoding est NULL, l'encodage actuel du système est utilisé.
Tcl_Obj *objPtr (in)
Nom de l'encodage pour obtenir le jeton.
Tcl_Encoding *encodingPtr (out)
Le jeton de l'encodage est écrit à cet endroit.
const char *src (in)
Pour les fonctions Tcl_ExternalToUtf, un tableau d'octets dans l'encodage spécifié qui est converti en UTF-8. Pour les fonctions Tcl_UtfToExternal et Tcl_WinUtfToTChar, un tableau de caractères UTF-8 qui est converti dans l'encodage spécifié.
const TCHAR *tsrc (in)
Un tableau de caractères Windows TCHAR qui est converti en UTF-8.
int srcLen (in)
Longueur de src ou tsrc en octets. Si la longueur est négative, la longueur de la chaîne dans l'encodage spécifié est utilisée.
Tcl_DString *dstPtr (out)
Un DString non initialisé ou libéré dans lequel le résultat de la conversion est stocké.
int flags (in)
Bits OR-és de différentes options. TCL_ENCODING_START indique que le tampon d'entrée est le premier bloc d'un flux d'entrée (potentiellement multi-blocs), indiquant à la routine de conversion de réinitialiser à l'état initial et d'effectuer toute initialisation nécessaire avant de commencer à convertir les premiers octets. TCL_ENCODING_END indique que le tampon d'entrée est le dernier bloc d'un flux d'entrée (potentiellement multi-blocs), indiquant à la routine de conversion d'effectuer toute finalisation nécessaire après la conversion du dernier octet, puis de réinitialiser à l'état initial. TCL_ENCODING_STOPONERROR indique que la routine de conversion renvoie immédiatement lorsqu'elle lit un caractère qui n'existe pas dans l'encodage cible ; sinon, un caractère par défaut est automatiquement substitué.
Tcl_EncodingState *statePtr (in/out)
Utilisé lors de la conversion d'un flux d'octets (généralement long ou de longueur indéfinie) par morceaux. La routine de conversion stocke son état actuel dans *statePtr après que src (le tampon contenant le morceau actuel) a été converti ; les informations d'état doivent être transmises à nouveau lors de la conversion du morceau suivant du flux afin que la routine de conversion sache dans quel état elle se trouvait lorsqu'elle s'est arrêtée à la fin du dernier morceau. Peut être NULL, auquel cas la valeur spécifiée pour flags est ignorée et on suppose que le tampon d'entrée contient le texte complet à convertir.
char *dst (out)
Tampon dans lequel le résultat de la conversion est stocké. Pas plus de dstLen octets seront stockés dans dst.
int dstLen (in)
La longueur maximale du tampon de sortie dst en octets.
int *srcReadPtr (out)
Est rempli avec le nombre d'octets de src qui ont été réellement convertis. Peut être inférieur à la longueur d'origine des caractères d'entrée s'il y a eu un problème lors de la conversion de certains caractères d'entrée. Peut être NULL.
int *dstWrotePtr (out)
Est rempli avec le nombre d'octets qui ont été stockés dans le tampon de sortie en conséquence de la conversion. Peut être NULL.
int *dstCharsPtr (out)
Est rempli avec le nombre de caractères correspondant au nombre d'octets stockés dans le tampon de sortie. Peut être NULL.
Tcl_DString *bufPtr (out)
Stockage du nom de l'encodage du système spécifié.
const Tcl_EncodingType *typePtr (in)
Une structure définissant un nouveau type d'encodage.
Tcl_Obj *searchPath (in)
Liste des répertoires de fichiers dans lesquels rechercher les fichiers d'encodage.
const char *path (in)
Un chemin indiquant l'emplacement du fichier d'encodage.

INTRODUCTION

Ces routines convertissent entre la représentation interne des caractères de Tcl, UTF-8, et les représentations de caractères utilisées par divers systèmes d'exploitation ou systèmes de fichiers, tels qu'Unicode, ASCII, ou EUC-JP. Lors de l'opération avec des chaînes de caractères, comme l'obtention de noms de fichiers ou l'affichage de caractères à l'aide de polices internationales, les chaînes doivent être traduites dans un ou plusieurs formats que différents appels système peuvent utiliser. Par exemple, dans un travail japonais sous Unix, un utilisateur pourrait obtenir un nom de fichier représenté dans l'encodage EUC-JP, puis traduire les caractères dans l'encodage jisx0208 pour afficher le nom du fichier dans un widget Tk. Le but de l'encodage est d'aider à combler le fossé de traduction. UTF-8 fournit un pont de staging pour tous les encodages. Dans l'exemple ci-dessus, le texte serait traduit en UTF-8 à partir de l'encodage utilisé par le système d'exploitation, puis traduit de UTF-8 vers l'encodage requis par les routines d'affichage.

Certains encodages de base sont précompilés dans Tcl. D'autres peuvent être définis par l'utilisateur ou chargés dynamiquement à partir de fichiers d'encodage indépendants de la plateforme.

DESCRIPTION

Tcl_GetEncoding trouve un encodage étant donné son name. Le nom peut faire référence à un encodage prédéfini dans Tcl, à un encodage défini par l'utilisateur enregistré en appelant Tcl_CreateEncoding, ou à un encodage chargeable dynamiquement. La valeur retournée est un jeton représentant l'encodage et peut être utilisé dans des procédures ultérieures telles que Tcl_GetEncodingName, Tcl_FreeEncoding et Tcl_UtfToExternal. Si le nom ne fait référence à aucun encodage connu ou chargeable, NULL est retourné et un message d'erreur est rapporté dans interp.

L'encodage maintient une base de données de tous les encodages actuellement utilisés. Lorsqu'il est vu pour la première fois le name, Tcl_GetEncoding renvoie un encodage avec un compteur de références de 1. Si le même name est demandé à nouveau, le compteur de références de cet encodage est incrémenté sans le surcoût d'allocation d'un nouvel encodage et de ses structures associées.

Lorsqu'un encodage n'est plus utilisé, Tcl_FreeEncoding doit être appelé pour le libérer. Lorsqu'un encodage n'est plus utilisé nulle part (c'est-à-dire qu'il a été libéré autant de fois qu'il a été obtenu), Tcl_FreeEncoding libérera toutes les ressources utilisées par l'encodage et supprimera l'encodage de la base de données.

Tcl_GetEncodingFromObj traite la représentation textuelle de objPtr comme un nom d'encodage et trouve un encodage portant ce nom, tout comme Tcl_GetEncoding. Lorsqu'un encodage est trouvé, il est mis en cache dans la valeur de objPtr pour référence future, et le jeton Tcl_Encoding est écrit dans le stockage pointé par encodingPtr.

EXEMPLE

Tcl_ExternalToUtfDString convertit un tampon source src de l'encodage spécifié en UTF-8. Les octets convertis sont stockés dans dstPtr, qui est ensuite terminé par un caractère nul. L'appelant devra éventuellement appeler Tcl_DStringFree pour libérer toute information stockée dans dstPtr. Lors de la conversion, si certains des caractères dans le tampon source ne peuvent pas être représentés dans l'encodage cible, un caractère de repli par défaut sera utilisé. La valeur de retour est un pointeur vers la valeur stockée dans le DString.

Tcl_ExternalToUtf convertit un tampon source src de l'encodage spécifié en UTF-8. Jusqu'à srcLen octets sont convertis du tampon source et jusqu'à dstLen octets convertis sont stockés dans dst. Dans tous les cas, *srcReadPtr est rempli avec le nombre d'octets qui ont été convertis avec succès depuis src et *dstWrotePtr est rempli avec le nombre correspondant d'octets qui ont été stockés dans dst. La valeur de retour est l'une des suivantes :

TCL_OK
Tous les octets de src ont été convertis.
TCL_CONVERT_NOSPACE
Le tampon de destination n'était pas assez grand pour toutes les données converties ; autant de caractères que possible ont été convertis.
TCL_CONVERT_MULTIBYTE
Les derniers octets du tampon source étaient le début d'une séquence multi-octets, mais des octets supplémentaires étaient nécessaires pour compléter cette séquence. Un appel ultérieur à la routine de conversion devrait passer un tampon contenant les octets non convertis restants dans src ainsi que quelques octets supplémentaires du flux source pour convertir correctement la séquence multi-octets précédemment divisée.
TCL_CONVERT_SYNTAX
Le tampon source contenait une séquence de caractères invalide. Cela peut se produire si le flux d'entrée a été endommagé ou si la méthode d'encodage d'entrée a été mal identifiée.
TCL_CONVERT_UNKNOWN
Le tampon source contenait un caractère qui ne pouvait pas être représenté dans l'encodage cible et TCL_ENCODING_STOPONERROR a été spécifié.

Tcl_UtfToExternalDString convertit un tampon source src de l'UTF-8 vers l'encodage spécifié. Les octets convertis sont stockés dans dstPtr, qui est ensuite terminé par le caractère nul approprié à l'encodage. L'appelant devra éventuellement appeler Tcl_DStringFree pour libérer toute information stockée dans dstPtr. Lors de la conversion, si certains des caractères dans le tampon source ne peuvent pas être représentés dans l'encodage cible, un caractère de repli par défaut sera utilisé. La valeur de retour est un pointeur vers la valeur stockée dans le DString.

Tcl_UtfToExternal convertit un tampon source src de l'UTF-8 vers l'encodage spécifié. Jusqu'à srcLen octets sont convertis du tampon source et jusqu'à dstLen octets convertis sont stockés dans dst. Dans tous les cas, *srcReadPtr est rempli avec le nombre d'octets qui ont été convertis avec succès depuis src et *dstWrotePtr est rempli avec le nombre correspondant d'octets qui ont été stockés dans dst. Les valeurs de retour sont les mêmes que les valeurs de retour pour Tcl_ExternalToUtf.

Tcl_WinUtfToTChar et Tcl_WinTCharToUtf sont des fonctions utilitaires propres à Windows pour convertir entre UTF-8 et les chaînes Windows basées sur le type TCHAR qui est par convention un caractère Unicode sous Windows NT.

Tcl_GetEncodingName est à peu près l'inverse de Tcl_GetEncoding. Étant donné un encoding, la valeur de retour est l'argument name qui a été utilisé pour créer l'encodage. La chaîne retournée par Tcl_GetEncodingName n'est garantie de persister que jusqu'à ce que l'encoding soit supprimé. L'appelant ne doit pas modifier cette chaîne.

Tcl_SetSystemEncoding définit l'encodage par défaut qui doit être utilisé chaque fois que l'utilisateur passe une valeur NULL pour l'argument encoding à l'une des autres fonctions d'encodage. Si name est NULL, l'encodage système est réinitialisé à l'encodage système par défaut, binary. Si le nom ne fait pas référence à un encodage connu ou chargeable, TCL_ERROR est retourné et un message d'erreur est laissé dans interp. Sinon, cette procédure incrémente le compteur de références du nouvel encodage système, décrémente le compteur de références de l'ancien encodage système, et retourne TCL_OK.

Tcl_GetEncodingNameFromEnvironment fournit un moyen pour la bibliothèque Tcl de rapporter le nom d'encodage qu'elle considère comme le bon à utiliser comme encodage système, basé sur des appels système et l'examen de l'environnement adapté à la plateforme. Il accepte bufPtr, un pointeur vers un Tcl_DString non initialisé ou libéré et y écrit le nom de l'encodage. La valeur Tcl_DStringValue est retournée.

Tcl_GetEncodingNames définit le résultat de l'interp comme une liste comprenant les noms de tous les encodages qui sont actuellement définis ou qui peuvent être chargés dynamiquement, en parcourant le chemin des encodages spécifié par Tcl_SetDefaultEncodingDir. Cette procédure ne garantit pas que les fichiers d'encodage chargeables dynamiquement contiennent des données valides, mais simplement qu'ils existent.

Tcl_CreateEncoding définit un nouvel encodage et enregistre les procédures C qui sont appelées en retour pour convertir entre l'encodage et l'UTF-8. Les encodages créés par Tcl_CreateEncoding sont par la suite visibles dans la base de données utilisée par Tcl_GetEncoding. Comme avec la procédure Tcl_GetEncoding, la valeur de retour est un jeton qui représente l'encodage et peut être utilisé dans des appels ultérieurs à d'autres fonctions d'encodage. Tcl_CreateEncoding retourne un encodage avec un compteur de références de 1. Si un encodage avec le nom spécifié existe déjà, son entrée dans la base de données est remplacée par le nouvel encodage ; le jeton pour l'ancien encodage restera valide et continuera de se comporter comme avant, mais les utilisateurs du nouveau jeton appelleront maintenant les nouvelles procédures d'encodage.

L'argument typePtr à Tcl_CreateEncoding contient des informations sur le nom de l'encodage et les procédures qui seront appelées pour convertir entre cet encodage et l'UTF-8. Il est défini comme suit :

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

L'encodingName fournit un nom de chaîne pour l'encodage, par lequel il peut être référencé dans d'autres procédures comme Tcl_GetEncoding. Le toUtfProc fait référence à une procédure de rappel à invoquer pour convertir du texte de cet encodage en UTF-8. Le fromUtfProc fait référence à une procédure de rappel à invoquer pour convertir du texte de l'UTF-8 vers cet encodage. Le freeProc fait référence à une procédure de rappel à invoquer lorsque cet encodage est supprimé. Le champ freeProc peut être NULL. Le clientData contient une valeur arbitraire d'un mot passée aux procédures toUtfProc, fromUtfProc, et freeProc chaque fois qu'elles sont appelées. Typiquement, il s'agit d'un pointeur vers une structure de données contenant des informations spécifiques à l'encodage qui peuvent être utilisées par les procédures de rappel. Par exemple, deux encodages très similaires comme ascii et macRoman peuvent utiliser la même procédure de rappel, mais utiliser différentes valeurs de clientData pour contrôler son comportement. Le nullSize spécifie le nombre d'octets zéro qui signifient la fin de la chaîne dans cet encodage. Il doit être de 1 (pour les encodages mono-octet ou multi-octets comme ASCII ou Shift-JIS) ou 2 (pour les encodages double-octet comme Unicode). Les encodages de taille constante avec 3 octets ou plus par caractère (comme CNS11643) ne sont pas acceptés.

Les procédures de rappel toUtfProc et fromUtfProc doivent correspondre au type Tcl_EncodingConvertProc :

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

Les procédures toUtfProc et fromUtfProc sont appelées par la famille de fonctions Tcl_ExternalToUtf ou Tcl_UtfToExternal pour effectuer la conversion réelle. Le paramètre clientData à ces procédures est le même que le champ clientData spécifié à Tcl_CreateEncoding lors de la création de l'encodage. Les arguments restants aux procédures de rappel sont les mêmes que les arguments, documentés en haut, à Tcl_ExternalToUtf ou Tcl_UtfToExternal, avec les exceptions suivantes. Si l'argument srcLen à l'une de ces fonctions de haut niveau est négatif, la valeur passée à la procédure de rappel sera la longueur de chaîne spécifique à l'encodage appropriée de src. Si l'un des arguments srcReadPtr, dstWrotePtr, ou dstCharsPtr à l'une des fonctions de haut niveau est NULL, la valeur correspondante passée à la procédure de rappel sera un emplacement non-NULL.

La procédure de rappel freeProc, si elle n'est pas NULL, doit correspondre au type Tcl_EncodingFreeProc :

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

Cette fonction freeProc est appelée lorsque l'encodage est supprimé. Le paramètre clientData est le même que le champ clientData spécifié à Tcl_CreateEncoding lors de la création de l'encodage.

Tcl_GetEncodingSearchPath et Tcl_SetEncodingSearchPath sont appelés pour accéder et définir la liste des répertoires du système de fichiers recherchés pour les fichiers de données d'encodage.

La valeur retournée par Tcl_GetEncodingSearchPath est la valeur stockée par le dernier appel réussi à Tcl_SetEncodingSearchPath. Si aucun appel à Tcl_SetEncodingSearchPath n'a eu lieu, Tcl calculera une valeur initiale basée sur l'environnement. Il existe un chemin de recherche d'encodage pour l'ensemble du processus, partagé par tous les threads du processus.
