Tcl_Hash(3) Procédures de la bibliothèque Tcl Tcl_Hash(3)

NAME

Tcl_InitHashTable, Tcl_InitCustomHashTable, Tcl_InitObjHashTable, Tcl_DeleteHashTable, Tcl_CreateHashEntry, Tcl_DeleteHashEntry, Tcl_FindHashEntry, Tcl_GetHashValue, Tcl_SetHashValue, Tcl_GetHashKey, Tcl_FirstHashEntry, Tcl_NextHashEntry, Tcl_HashStats - procédures pour gérer les tables de hachage

Tcl_HashEntry *
Tcl_FindHashEntry(tablePtr, key)

ClientData
Tcl_GetHashValue(entryPtr)

Tcl_SetHashValue(entryPtr, value)

void *
Tcl_GetHashKey(tablePtr, entryPtr)

Tcl_FirstHashEntry(tablePtr, searchPtr)

ARGUMENTS

Tcl_HashTable *tablePtr (in)
Adresse de la structure de table de hachage (pour toutes les procédures sauf Tcl_InitHashTable, cette structure doit avoir été précédemment initialisée par un appel à Tcl_InitHashTable).
int keyType (in)
Types de clés à utiliser pour la table de hachage. Doit être l'un de TCL_STRING_KEYS, TCL_ONE_WORD_KEYS, TCL_CUSTOM_TYPE_KEYS, TCL_CUSTOM_PTR_KEYS, ou une valeur entière supérieure à 1.
Tcl_HashKeyType *typePtr (in)
Adresse de la structure qui définit le comportement de la table de hachage.
const void *key (in)
Clé à rechercher dans la table. La forme exacte dépend du keyType utilisé pour créer la table.
int *newPtr (out)
La valeur de *newPtr est définie sur 1 si une nouvelle entrée a été créée et sur 0 si une entrée avec la clé key existait déjà.
Tcl_HashEntry *entryPtr (in)
Pointeur vers une entrée de table de hachage.
ClientData value (in)
Nouvelle valeur à assigner à l'entrée de la table de hachage. Elle n'a pas besoin d'être de type ClientData, mais doit tenir dans l'espace même de ClientData.
Tcl_HashSearch *searchPtr (in)
Pointeur vers une structure utilisée pour suivre la progression lors de l'énumération de toutes les entrées d'une table de hachage.

DESCRIPTION

Une table de hachage consiste en zéro ou plusieurs entrées, chacune composée d'une clé et d'une valeur. Étant donné la clé d'une entrée, les routines de hachage peuvent localiser rapidement l'entrée, et par conséquent, sa valeur. Il ne peut y avoir qu'une seule entrée dans une table de hachage ayant la même clé, mais il peut y avoir plusieurs entrées ayant la même valeur. Les clés peuvent prendre l'une des quatre formes suivantes : chaînes de caractères, valeurs d'un seul mot, tableaux d'entiers ou clés personnalisées définies par une structure Tcl_HashKeyType (voir la section THE TCL_HASHKEYTYPE STRUCTURE ci-dessous). Toutes les clés d'une table ont la même forme, qui est spécifiée lors de l'initialisation de la table. La valeur d'une entrée de table de hachage peut être n'importe quoi qui tienne dans l'espace même d'un pointeur de chaîne. Les valeurs des entrées de table de hachage sont entièrement gérées par les clients, pas par le module de hachage. Généralement, chaque valeur d'entrée est un pointeur vers une structure gérée par le code client.

Les tables de hachage croissent en douceur lorsque le nombre d'entrées augmente, de sorte qu'il y a toujours moins de trois entrées par compartiment en moyenne. Cela permet des recherches rapides indépendamment du nombre d'entrées dans une table.

Le noyau fournit trois fonctions pour l'initialisation des tables de hachage : Tcl_InitHashTable, Tcl_InitObjHashTable et Tcl_InitCustomHashTable.

Tcl_InitHashTable initialise une structure qui décrit une nouvelle table de hachage. L'espace de la structure est fourni par le client, pas par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. Tous les types de clés décrits ci-dessous sont autorisés, sauf TCL_CUSTOM_TYPE_KEYS et TCL_CUSTOM_PTR_KEYS.

Tcl_InitObjHashTable est un wrapper pour Tcl_InitCustomHashTable et initialise une table de hachage dont les clés sont des Tcl_Obj *.

Tcl_InitCustomHashTable initialise une structure qui décrit une nouvelle table de hachage. L'espace de la structure est fourni par le client, pas par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. KeyType doit avoir l'une des valeurs suivantes :

TCL_STRING_KEYS
Les clés sont des chaînes terminées par un caractère nul. Elles sont passées aux routines de hachage en utilisant le pointeur vers le premier caractère de la chaîne.
TCL_ONE_WORD_KEYS
Les clés sont des valeurs d'un seul mot ; elles sont passées aux routines de hachage et stockées dans les entrées de table sous forme de valeurs char *. La valeur du pointeur est la clé ; il n'est pas nécessaire (et ce n'est généralement pas le cas) qu'elle pointe réellement vers une chaîne.
TCL_CUSTOM_TYPE_KEYS
Les clés sont de type arbitraire et sont stockées dans les entrées. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section THE TCL_HASHKEYTYPE STRUCTURE ci-dessous.
TCL_CUSTOM_PTR_KEYS
Les clés sont des pointeurs vers un type arbitraire et sont stockées dans les entrées. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section THE TCL_HASHKEYTYPE STRUCTURE ci-dessous.
other
Si keyType n'est pas l'un des précédents, il doit s'agir d'une valeur entière supérieure à 1. Dans ce cas, les clés seront des tableaux de valeurs int, où keyType indique le nombre d'int dans chaque clé. Cela permet l'utilisation de structures comme clés. Toutes les clés doivent avoir la même taille. Les clés de tableaux sont passées aux fonctions de hachage en utilisant le pointeur vers le premier int du tableau.

Tcl_DeleteHashTable supprime toutes les entrées d'une table de hachage et libère la mémoire associée au tableau de compartiments et aux entrées. Elle ne libère pas la structure de table elle-même (poutée par tablePtr), car cette mémoire est la responsabilité du client. Tcl_DeleteHashTable ne libère ni ne manipule non plus les valeurs des entrées de la table de hachage. Si les valeurs des entrées pointent vers une mémoire allouée dynamiquement, il est de la responsabilité du client de libérer ces structures avant de supprimer la table.

Tcl_CreateHashEntry localise l'entrée correspondant à une clé donnée, en créant une nouvelle entrée dans la table si aucune entrée avec la clé spécifiée n'existe. Si une entrée avec la clé spécifiée existe déjà, *newPtr est mis à 0. Si une nouvelle entrée a été créée, *newPtr est mis à une valeur non nulle et la valeur de la nouvelle entrée sera mise à 0. La valeur retournée par Tcl_CreateHashEntry est un pointeur vers l'entrée, qui peut être utilisé pour récupérer et modifier la valeur de l'entrée ou la supprimer de la table.

Tcl_DeleteHashEntry supprimera une entrée existante d'une table. La mémoire associée à l'entrée elle-même est libérée, mais le client est responsable de toute nettoyage associé à la valeur de l'entrée, tel que la libération d'une structure vers laquelle le client pointe.

Tcl_FindHashEntry est similaire à Tcl_CreateHashEntry sauf qu'elle ne crée pas de nouvelle entrée si la clé n'existe pas ; elle retourne plutôt NULL comme résultat.

Tcl_GetHashValue et Tcl_SetHashValue sont utilisées pour lire et écrire la valeur d'une entrée, respectivement. Les valeurs sont stockées et récupérées comme type ClientData, ce qui est suffisant pour contenir une valeur de pointeur. Dans presque tous les cas, cela suffit également pour contenir une valeur entière.

Tcl_GetHashKey retourne la clé d'une entrée de table de hachage donnée, soit sous forme de pointeur vers une chaîne, une clé d'un seul mot (char *), soit sous forme de pointeur vers le premier élément d'un tableau d'entiers, en fonction du keyType utilisé pour créer la table de hachage. Dans tous les cas, Tcl_GetHashKey retourne un résultat de type char *. Lorsque la clé est une chaîne ou un tableau, le résultat de Tcl_GetHashKey pointe vers des informations dans l'entrée de la table de hachage ; ces informations resteront valides jusqu'à ce que l'entrée soit supprimée ou que sa table soit supprimée.

Tcl_FirstHashEntry et Tcl_NextHashEntry peuvent être utilisées pour parcourir toutes les entrées d'une table de hachage.

Tcl_FirstHashEntry initialise le enregistrement de recherche et renvoie la première entrée de la table (ou NULL si la table est vide). Chaque appel subséquent à Tcl_NextHashEntry renvoie la entrée suivante dans la table ou NULL si la fin de la table a été atteinte. Un appel à Tcl_FirstHashEntry suivi d'appels à Tcl_NextHashEntry renverra chaque entrée de la table exactement une fois, dans un ordre arbitraire. Il est déconseillé de modifier la structure de la table, par exemple en créant ou en supprimant des entrées, pendant que la recherche est en cours, à l'exception de la suppression de l'entrée renvoyée par Tcl_FirstHashEntry ou Tcl_NextHashEntry.

Tcl_HashStats renvoie une chaîne allouée dynamiquement avec des informations globales sur une table de hachage, telles que le nombre d'entrées qu'elle contient, le nombre de compartiments dans son tableau de hachage, et l'utilisation des compartiments. Il incombe à l'appelant de libérer la chaîne de résultat en la passant à ckfree.

Le fichier d'en-tête tcl.h définit les structures de données réelles utilisées pour implémenter les tables de hachage. Ceci est nécessaire pour que les clients puissent allouer des structures Tcl_HashTable et pour que des macros puissent être utilisées pour lire et écrire les valeurs des entrées. Cependant, les utilisateurs des routines de hachage ne devraient jamais se référer directement à l'un des champs de l'une des structures de données relatives au hachage ; utilisez les procédures et les macros définies ici.

LA STRUCTURE TCL_HASHKEYTYPE

Les auteurs d'extensions peuvent définir de nouveaux types de clés de hachage en définissant quatre procédures, en initialisant une structure Tcl_HashKeyType pour décrire le type, et en appelant Tcl_InitCustomHashTable. La structure Tcl_HashKeyType est définie comme suit :

typedef struct Tcl_HashKeyType {
    int version;
    int flags;
    Tcl_HashKeyProc *hashKeyProc;
    Tcl_CompareHashKeysProc *compareKeysProc;
    Tcl_AllocHashEntryProc *allocEntryProc;
    Tcl_FreeHashEntryProc *freeEntryProc;
} Tcl_HashKeyType;

Le membre version est la version de la table. Si cette structure est étendue dans le futur, la version peut être utilisée pour distinguer différentes structures. Elle doit être définie à TCL_HASH_KEY_TYPE_VERSION.

Le membre flags est 0 ou une ou plusieurs des valeurs suivantes combinées par OU :

TCL_HASH_KEY_RANDOMIZE_HASH
Certaines choses, comme les pointeurs, ne se hachent pas bien car elles n'utilisent pas les bits inférieurs. Si cet indicateur est défini, la table de hachage tentera de rectifier cela en randomisant les bits, puis en utilisant les N bits supérieurs comme index dans la table.
TCL_HASH_KEY_SYSTEM_HASH
Cet indicateur force Tcl à utiliser les procédures d'allocation de mémoire fournies par le système d'exploitation lors de l'allocation et de la libération de la mémoire utilisée pour stocker les structures de données de la table de hachage, et non les routines d'allocation de mémoire personnalisées de Tcl. Ceci est important si la table de hachage doit être utilisée dans l'implémentation d'un ensemble personnalisé de routines d'allocation, ou de quelque chose dont un ensemble personnalisé de routines d'allocation pourrait dépendre, afin d'éviter toute dépendance circulaire.

Le membre hashKeyProc contient l'adresse d'une fonction appelée pour calculer une valeur de hachage pour la clé.

typedef unsigned int Tcl_HashKeyProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

Si ceci est NULL, alors keyPtr est utilisé et TCL_HASH_KEY_RANDOMIZE_HASH est supposé.

Le membre compareKeysProc contient l'adresse d'une fonction appelée pour comparer deux clés.

typedef int Tcl_CompareHashKeysProc(
        void *keyPtr,
        Tcl_HashEntry *hPtr);

Si ceci est NULL, alors les pointeurs keyPtr sont comparés. Si les clés ne correspondent pas, la fonction renvoie 0, sinon elle renvoie 1.

Le membre allocEntryProc contient l'adresse d'une fonction appelée pour allouer de l'espace pour une entrée et initialiser la clé et clientData.

typedef Tcl_HashEntry *Tcl_AllocHashEntryProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

Si ceci est NULL, alors Tcl_Alloc est utilisé pour allouer suffisamment d'espace pour une Tcl_HashEntry, le pointeur de clé est assigné à key.oneWordValue et clientData est défini à NULL. Les clés de chaîne et les clés de tableau utilisent cette fonction pour allouer suffisamment d'espace pour l'entrée et la clé dans un seul bloc, plutôt que de le faire en deux blocs. Cela permet d'économiser l'espace pour un pointeur vers la clé depuis l'entrée et une autre allocation mémoire. Les clés Tcl_Obj* utilisent cette fonction pour allouer suffisamment d'espace pour une entrée et incrémenter le compteur de références sur la valeur.

Le membre freeEntryProc contient l'adresse d'une fonction appelée pour libérer l'espace d'une entrée.

typedef void Tcl_FreeHashEntryProc(
        Tcl_HashEntry *hPtr);

Si ceci est NULL, alors Tcl_Free est utilisé pour libérer l'espace pour l'entrée. Les clés Tcl_Obj* utilisent cette fonction pour décrémenter le compteur de références sur la valeur.
