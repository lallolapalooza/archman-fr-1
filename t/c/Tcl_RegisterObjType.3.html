Tcl_RegisterObjType(3) Procédures de la bibliothèque Tcl Tcl_RegisterObjType(3)

NAME

Tcl_RegisterObjType, Tcl_GetObjType, Tcl_AppendAllObjTypes, Tcl_ConvertToType - manipuler les types de valeur Tcl

SYNOPSIS

#include <tcl.h>

Tcl_RegisterObjType(typePtr)

const Tcl_ObjType *
Tcl_GetObjType(typeName)

int
Tcl_AppendAllObjTypes(interp, objPtr)

int
Tcl_ConvertToType(interp, objPtr, typePtr)

ARGUMENTS

const Tcl_ObjType *typePtr (in)
Pointe vers la structure contenant les informations sur le type de valeur Tcl. Cette mémoire doit rester toujours active.
const char *typeName (in)
Nom d'un type de valeur Tcl que Tcl_GetObjType doit rechercher.
Tcl_Interp *interp (in)
Interpréteur à utiliser pour le reporting d'erreurs.
Tcl_Obj *objPtr (in)
Pour Tcl_AppendAllObjTypes, ceci pointe vers la valeur à laquelle le nom du type de valeur est ajouté comme élément de liste. Pour Tcl_ConvertToType, ceci pointe vers une valeur qui doit avoir été le résultat d'un appel précédent à Tcl_NewObj.

DESCRIPTION

Les fonctions de cette page de manuel gèrent les types de valeur Tcl (parfois appelés types d'objet ou Tcl_ObjType pour des raisons historiques). Elles sont utilisées pour enregistrer de nouveaux types de valeur, rechercher des types et forcer des conversions d'un type à un autre.

Tcl_RegisterObjType enregistre un nouveau type de valeur Tcl dans la table de tous les types de valeur que Tcl_GetObjType peut rechercher par nom. Il existe également d'autres types de valeur que Tcl prend en charge, qui ne sont pas enregistrés. Les extensions peuvent choisir d'enregistrer les types de valeur qu'elles créent ou non. L'argument typePtr pointe vers une structure Tcl_ObjType qui décrit le nouveau type, en donnant son nom et en fournissant des pointeurs vers quatre procédures qui implémentent le type. Si un type portant le même nom que celui de typePtr existe déjà, il sera remplacé par le nouveau type. La structure Tcl_ObjType est décrite dans la section LA STRUCTURE TCL_OBJTYPE ci-dessous.

Tcl_GetObjType renvoie un pointeur vers la structure enregistrée Tcl_ObjType portant le nom typeName. Elle renvoie NULL s'il n'existe pas de type enregistré portant ce nom.

Tcl_AppendAllObjTypes ajoute au nom de chaque type de valeur enregistré, en tant qu'élément de liste, à la valeur référencée par objPtr. La valeur de retour est TCL_OK, sauf s'il s'est produit une erreur lors de la conversion de objPtr en une valeur de liste ; dans ce cas, TCL_ERROR est renvoyé.

Tcl_ConvertToType convertit une valeur d'un type à un autre si cela est possible. Elle crée une représentation interne appropriée pour objPtr selon le type cible typePtr et définit son typePtr comme déterminé par la procédure typePtr->setFromAnyProc. Toute représentation interne ancienne de objPtr est libérée. Si une erreur se produit pendant la conversion, elle renvoie TCL_ERROR et laisse un message d'erreur dans la valeur de résultat pour interp (sauf si interp est NULL). Sinon, elle renvoie TCL_OK. Passer un interp nul permet d'utiliser cette fonction comme un test pour voir si la conversion peut être effectuée (et a effectivement été effectuée).

Dans de nombreux cas, la procédure typePtr->setFromAnyProc définira objPtr->typePtr sur la valeur de l'argument typePtr, mais cela n'est plus garanti. Le setFromAnyProc peut choisir d'utiliser une autre structure Tcl_ObjType connexe pour la représentation interne de objPtr s'il le souhaite.

LA STRUCTURE TCL_OBJTYPE

Les auteurs d'extensions peuvent définir de nouveaux types de valeur en définissant quatre procédures et en initialisant une structure Tcl_ObjType qui décrit le type. Les auteurs d'extensions peuvent passer un pointeur vers leur structure Tcl_ObjType à Tcl_RegisterObjType s'ils veulent permettre à d'autres auteurs d'extensions de rechercher leur structure Tcl_ObjType par nom en utilisant Tcl_GetObjType. La structure Tcl_ObjType est définie comme suit :

typedef struct Tcl_ObjType {
    const char *name;
    Tcl_FreeInternalRepProc *freeIntRepProc;
    Tcl_DupInternalRepProc *dupIntRepProc;
    Tcl_UpdateStringProc *updateStringProc;
    Tcl_SetFromAnyProc *setFromAnyProc;
} Tcl_ObjType;

CHAMP NAME

Le champ name décrit le nom du type, par exemple, int. Lorsqu'un type est enregistré, c'est le nom que les appelants de Tcl_GetObjType utilisent pour rechercher le type. Pour les types non enregistrés, le champ name est principalement utile pour le débogage. Les quatre champs restants sont des pointeurs vers des procédures que le code Tcl générique appelle :

CHAMP SETFROMANYPROC

Le champ setFromAnyProc contient l'adresse d'une fonction appelée pour créer une représentation interne valide à partir de la représentation string d'une valeur.

typedef int Tcl_SetFromAnyProc(
        Tcl_Interp *interp,
        Tcl_Obj *objPtr);

Si une représentation interne ne peut pas être créée à partir de la représentation string, elle renvoie TCL_ERROR et laisse un message d'erreur dans la valeur de résultat pour interp (sauf si interp est NULL). Si setFromAnyProc réussit, elle stocke la nouvelle représentation interne, définit le typePtr de objPtr sur la structure Tcl_ObjType correspondant au nouveau type de valeur, et renvoie TCL_OK. Avant de définir la nouvelle représentation interne, le setFromAnyProc doit libérer l'ancienne représentation interne de objPtr en appelant la procédure freeIntRepProc de l'ancien type si elle n'est pas NULL.

À titre d'exemple, le setFromAnyProc du type de valeur prédéfini liste Tcl obtient une représentation string mise à jour de objPtr en appelant Tcl_GetStringFromObj. Il analyse la chaîne pour vérifier qu'elle est dans un format de liste valide et pour obtenir chaque valeur d'élément de la liste, et, si cela réussit, stocke les éléments de liste dans la représentation interne de objPtr et définit le typePtr de objPtr sur la structure Tcl_ObjType du type liste.

Vous ne devez pas libérer l'ancienne représentation interne de objPtr, sauf si vous la remplacez par une nouvelle ou si vous réinitialisez le membre typePtr à NULL.

Le champ setFromAnyProc peut être mis à NULL, si les procédures qui utilisent la représentation interne n'ont pas besoin de la dériver d'une valeur string arbitraire. Cependant, dans ce cas, passer un pointeur vers la structure à Tcl_ConvertToType provoquera un crash, donc pour éviter ce cas, vous ne devriez pas enregistrer le type.

CHAMP UPDATESTRINGPROC

Le champ updateStringProc contient l'adresse d'une fonction appelée pour créer une représentation string valide à partir de la représentation interne d'une valeur.

typedef void Tcl_UpdateStringProc(
        Tcl_Obj *objPtr);

Le membre bytes de objPtr est toujours NULL lorsqu'il est appelé. Il doit toujours définir bytes à non NULL avant de retourner. Nous exigeons que le tableau d'octets de la représentation string ait un NULL après le dernier octet, à la position length, et qu'il n'y ait pas d'octet NULL avant celui-ci ; cela permet de traiter les représentations string comme des chaînes terminées par un NUL conventionnelles. Ces contraintes peuvent être facilement respectées en utilisant l'encodage UTF de Tcl pour la représentation string, de la même manière que pour d'autres routines Tcl acceptant des valeurs de chaîne comme arguments. La mémoire du tableau d'octets doit être allouée sur le tas en utilisant Tcl_Alloc ou ckalloc. Remarque : les updateStringProc doivent allouer suffisamment d'espace pour les octets de la chaîne et l'octet NUL final.

Le updateStringProc pour le type de valeur prédéfini double Tcl appelle Tcl_PrintDouble pour écrire dans un tampon de taille TCL_DOUBLE_SPACE, puis alloue et copie la représentation string pour un espace suffisant pour la contenir. Un pointeur vers l'espace alloué est stocké dans le membre bytes.

Le champ updateStringProc peut être mis à NULL, si les procédures qui utilisent la représentation interne sont écrites de telle manière que la représentation string n'est jamais invalide. Si la procédure échoue, un message d'erreur sera laissé dans la valeur de résultat pour interp (sauf si interp est NULL). Sinon, elle renvoie TCL_OK. Passer un interp nul permet d'utiliser cette fonction comme un test pour voir si la conversion peut être effectuée (et a effectivement été effectuée).

LE CHAMP DUPINTREPPROC

Le membre dupIntRepProc contient l'adresse d'une fonction appelée pour copier une représentation interne d'une valeur à une autre.

typedef void Tcl_DupInternalRepProc(
        Tcl_Obj *srcPtr,
        Tcl_Obj *dupPtr);

La représentation interne de dupPtr est une copie de la représentation interne de srcPtr. Avant l'appel, la représentation interne de srcPtr est valide et celle de dupPtr ne l'est pas. Le type de valeur de srcPtr détermine ce que signifie la copie de sa représentation interne.

Par exemple, le dupIntRepProc pour le type entier de Tcl copie simplement un entier. Le dupIntRepProc du type liste intégré utilise un schéma beaucoup plus sophistiqué pour continuer à partager le stockage autant que raisonnablement possible.

LE CHAMP FREEINTREPPROC

Le membre freeIntRepProc contient l'adresse d'une fonction qui est appelée lorsqu'une valeur est libérée.

typedef void Tcl_FreeInternalRepProc(
        Tcl_Obj *objPtr);

La fonction freeIntRepProc peut désallouer le stockage pour la représentation interne de la valeur et effectuer d'autres traitements spécifiques au type nécessaires lors de la libération d'une valeur.

Par exemple, le freeIntRepProc du type liste respecte le schéma de partage de stockage établi par le dupIntRepProc afin de ne libérer le stockage que lorsque la dernière valeur qui le partage est libérée.

Le membre freeIntRepProc peut être défini sur NULL pour indiquer que la représentation interne ne nécessite pas de libération. L'implémentation de freeIntRepProc ne doit pas accéder au membre bytes de la valeur, car Tcl utilise son propre usage interne de ce champ lors de la suppression de la valeur. Les tâches définies pour le freeIntRepProc n'ont pas besoin de consulter le membre bytes.
