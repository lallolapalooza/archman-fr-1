ARGUMENTS

Tcl_HashTable *tablePtr (entree)
Adresse de la structure de la table de hachage (pour toutes les procédures sauf Tcl_InitHashTable, celle-ci doit avoir été initialisée au préalable par l'appel à Tcl_InitHashTable).
int keyType (entree)
Types de clés utilisés pour la nouvelle table de hachage. Doit être l'un de TCL_STRING_KEYS, TCL_ONE_WORD_KEYS, TCL_CUSTOM_TYPE_KEYS, TCL_CUSTOM_PTR_KEYS, ou une valeur entière supérieure à 1.
Tcl_HashKeyType *typePtr (entree)
Adresse de la structure qui définit le comportement de la table de hachage.
const void *key (entree)
Clé utilisée pour interroger la table. La forme exacte dépend de keyType utilisé pour créer la table.
int *newPtr (sortie)
La valeur dans *newPtr est définie à 1 si une nouvelle entrée est créée et 0 si une entrée pour key existe déjà.
Tcl_HashEntry *entryPtr (entree)
Pointeur vers une entrée de la table de hachage.
ClientData value (entree)
Nouvelle valeur à assigner à une entrée de la table de hachage. Pas nécessaire d'avoir le type ClientData, mais doit occuper le même espace que le type ClientData.
Tcl_HashSearch *searchPtr (entree)
Pointeur vers une structure utilisé pour suivre la progression dans l'énumération de toutes les entrées d'une table de hachage.

DESCRIPTION

Une table de hachage se compose de zéro ou plusieurs entrées, chacune ayant une clé et une valeur. Compte tenu de la clé d'une entrée, les routines de hachage peuvent localiser rapidement l'entrée, et donc sa valeur. Il peut y avoir un maximum d'une entrée dans une table de hachage avec une clé spécifique, mais il peut y avoir de nombreuses entrées avec la même valeur. Les clés peuvent prendre l'une des quatre formes suivantes : chaînes, valeurs d'un seul mot, tableaux d'entiers, ou clés définies par une structure Tcl_HashKeyType (voir section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous). Toutes les clés dans une table de hachage ont la même forme, qui est spécifiée lors de l'initialisation de la table.

La valeur d'une entrée de table de hachage peut être n'importe quoi qui occupe le même espace qu'un pointeur vers une chaîne. Les valeurs des entrées de table de hachage sont entièrement gérées par les clients, pas par le module de hachage lui-même. En général, chaque valeur d'entrée est un pointeur vers un objet de données géré par le code client.

Les tables de hachage se développent en douceur à mesure que le nombre d'entrées augmente, de sorte qu'il y a toujours moins de trois entrées par compartiment en moyenne. Cela permet des requêtes rapides, quel que soit le nombre d'entrées dans une table.

Le noyau offre trois fonctions pour l'initialisation des tables de hachage : Tcl_InitHashTable, Tcl_InitObjHashTable et Tcl_InitCustomHashTable.

Tcl_InitHashTable initialise une structure décrivant une nouvelle table de hachage. L'espace pour la structure est fourni par le client, pas par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. Tous les types de clés décrits plus loin sont autorisés, à l'exception de TCL_CUSTOM_TYPE_KEYS et TCL_CUSTOM_PTR_KEYS.

Tcl_InitObjHashTable est un wrapper de Tcl_InitCustomHashTable et initialise une table de hachage dont les clés sont des Tcl_Obj *.

Tcl_InitCustomHashTable initialise une structure décrivant une nouvelle table de hachage. L'espace pour la structure est fourni par le client, pas par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. KeyType doit avoir l'une des valeurs suivantes :

TCL_STRING_KEYS
Les clés sont des chaînes terminées par un caractère nul. Elles sont passées aux routines de hachage en utilisant l'adresse du premier caractère de la chaîne.
TCL_ONE_WORD_KEYS
Les clés sont des valeurs d'un seul mot ; elles sont passées aux routines de hachage et stockées dans les entrées de la table comme des valeurs de char *. La valeur du pointeur est la clé ; il n'est pas nécessaire (et en général pas pertinent) qu'elle pointe réellement vers une chaîne.
TCL_CUSTOM_TYPE_KEYS
Les clés sont de type arbitraire et stockées dans les entrées. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous.
TCL_CUSTOM_PTR_KEYS
Les clés sont des pointeurs vers un type arbitraire et stockées dans les entrées. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous.
other
Si keyType n'est pas l'un des éléments précédents, il doit s'agir d'une valeur entière supérieure à 1. Dans ce cas, les clés seront des tableaux de valeurs de int, où keyType spécifie le nombre d'entiers dans chaque clé. Cela permet d'utiliser des structures comme clés. Toutes les clés doivent avoir la même taille. Les clés de tableau sont passées aux fonctions de hachage en utilisant l'adresse du premier entier du tableau.

Tcl_DeleteHashTable supprime toutes les entrées d'une table de hachage et libère l'espace associé au tableau de compartiments et aux entrées. Elle ne libère pas la structure de la table elle-même (pointée par tablePtr), car l'espace est supposé être géré par le client. Tcl_DeleteHashTable ne libère ni ne manipule les valeurs des entrées de la table de hachage. Si les valeurs des entrées pointent vers de la mémoire dynamique, la responsabilité de libérer ces structures incombe au client avant la suppression de la table.

Tcl_CreateHashEntry localise l'entrée correspondant à une clé donnée, créant une nouvelle entrée dans la table si aucune entrée avec la clé spécifiée n'existe. Si une entrée avec la même clé existe déjà, *newPtr est défini à 0. Si une nouvelle entrée est créée, *newPtr est défini à une valeur non nulle et la valeur de la nouvelle entrée sera définie à 0. La valeur retournée par Tcl_CreateHashEntry est un pointeur vers l'entrée, qui peut être utilisé pour obtenir et modifier la valeur de l'entrée ou pour la supprimer de la table.

Tcl_DeleteHashEntry supprimera une entrée existante d'une table. La mémoire associée à l'entrée elle-même est libérée, mais le client est responsable de toute nettoyage associé à la valeur de l'entrée, comme la libération d'un objet pointé.

Tcl_FindHashEntry est similaire à Tcl_CreateHashEntry sauf qu'elle ne crée pas de nouvelle entrée si la clé n'existe pas ; elle renvoie plutôt NULL en résultat.

Tcl_GetHashValue et Tcl_SetHashValue sont utilisés pour lire et écrire respectivement la valeur d'une entrée. Les valeurs sont stockées et récupérées en tant que type ClientData, ce qui est suffisant pour contenir une valeur de pointeur. Sur la quasi-totalité des machines, cela suffit également pour contenir une valeur entière.

Tcl_GetHashKey renvoie la clé d'une entrée de table de hachage donnée, soit sous forme de pointeur vers une chaîne, d'une clé d'un seul mot (char *), soit comme pointeur vers le premier mot d'un tableau d'entiers, en fonction du keyType utilisé pour créer la table de hachage. Dans tous les cas, Tcl_GetHashKey renvoie un résultat de type char *. Lorsque la clé est une chaîne ou un tableau, le résultat de Tcl_GetHashKey pointe vers des informations dans l'entrée de la table ; ces informations resteront valides jusqu'à ce que l'entrée soit supprimée ou que sa table soit supprimée.

Tcl_FirstHashEntry et Tcl_NextHashEntry peuvent être utilisés pour parcourir toutes les entrées d'une table de hachage.

Tcl_FirstHashEntry initialise l’enregistrement de recherche et renvoie la première entrée de la table (ou NULL si la table est vide). Chaque appel successif à Tcl_NextHashEntry renvoie l’entrée suivante dans la table ou NULL si la fin de la table a été atteinte. Un appel à Tcl_FirstHashEntry suivi d’appels à Tcl_NextHashEntry renverra chaque entrée de la table exactement une fois, dans un ordre arbitraire. Il est déconseillé de modifier la structure de la table, par exemple en créant ou en supprimant des entrées, pendant que la recherche est en cours, à l’exception de la suppression de l’entrée renvoyée par Tcl_FirstHashEntry ou Tcl_NextHashEntry.

Tcl_HashStats renvoie une chaîne allouée dynamiquement contenant des informations globales sur une table de hachage, telles que le nombre d’entrées qu’elle contient, le nombre de compartiments dans son tableau de hachage et l’utilisation des compartiments. Il incombe à l’appelant de libérer la chaîne de résultat en la passant à ckfree.

Le fichier d’en-tête tcl.h définit les structures de données réelles utilisées pour implémenter les tables de hachage. Ceci est nécessaire afin que les clients puissent allouer des structures Tcl_HashTable et afin que les macros puissent être utilisées pour lire et écrire les valeurs des entrées. Cependant, les utilisateurs des routines de hachage ne doivent jamais faire référence directement à l’un des champs des structures de données liées au hachage ; utilisez les procédures et macros définies ici.

LA STRUCTURE TCL_HASHKEYTYPE

Les écrivains d’extensions peuvent définir de nouveaux types de clés de hachage en définissant quatre procédures, en initialisant une structure Tcl_HashKeyType pour décrire le type, et en appelant Tcl_InitCustomHashTable. La structure Tcl_HashKeyType est définie comme suit :

typedef struct Tcl_HashKeyType {
    int version;
    int flags;
    Tcl_HashKeyProc *hashKeyProc;
    Tcl_CompareHashKeysProc *compareKeysProc;
    Tcl_AllocHashEntryProc *allocEntryProc;
    Tcl_FreeHashEntryProc *freeEntryProc;
} Tcl_HashKeyType;

Le membre version est la version de la table. Si cette structure est étendue à l’avenir, la version peut être utilisée pour distinguer différentes structures. Elle doit être définie à TCL_HASH_KEY_TYPE_VERSION.

Le membre flags est 0 ou une ou plusieurs des valeurs suivantes combinées par OR :

TCL_HASH_KEY_RANDOMIZE_HASH
Certains éléments, comme les pointeurs, ne hachant pas bien car ils n’utilisent pas les bits inférieurs. Si ce drapeau est défini, la table de hachage tentera de rectifier cela en randomisant les bits puis en utilisant les N bits supérieurs comme index dans la table.
TCL_HASH_KEY_SYSTEM_HASH
Ce drapeau force Tcl à utiliser les procédures d’allocation mémoire fournies par le système d’exploitation lors de l’allocation et de la libération de la mémoire utilisée pour stocker les structures de données de la table de hachage, et non les routines d’allocation mémoire personnalisées de Tcl. Ceci est important si la table de hachage doit être utilisée dans l’implémentation d’un ensemble personnalisé de routines d’allocation, ou quelque chose dont un ensemble personnalisé de routines d’allocation pourrait dépendre, afin d’éviter toute dépendance circulaire.

Le membre hashKeyProc contient l’adresse d’une fonction appelée pour calculer une valeur de hachage pour la clé.

typedef unsigned int Tcl_HashKeyProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

Si ceci est NULL, alors keyPtr est utilisé et TCL_HASH_KEY_RANDOMIZE_HASH est supposé.

Le membre compareKeysProc contient l’adresse d’une fonction appelée pour comparer deux clés.

typedef int Tcl_CompareHashKeysProc(
        void *keyPtr,
        Tcl_HashEntry *hPtr);

Si ceci est NULL, alors les pointeurs keyPtr sont comparés. Si les clés ne correspondent pas, la fonction renvoie 0, sinon elle renvoie 1.

Le membre allocEntryProc contient l’adresse d’une fonction appelée pour allouer de l’espace pour une entrée et initialiser la clé et clientData.

typedef Tcl_HashEntry *Tcl_AllocHashEntryProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

Si ceci est NULL, alors Tcl_Alloc est utilisé pour allouer suffisamment d’espace pour une Tcl_HashEntry, le pointeur de clé est assigné à key.oneWordValue et le clientData est défini à NULL. Les clés de type chaîne et les clés de type tableau utilisent cette fonction pour allouer suffisamment d’espace pour l’entrée et la clé en un seul bloc, plutôt qu’en deux blocs. Cela permet d’économiser l’espace pour un pointeur vers la clé depuis l’entrée et une autre allocation mémoire. Les clés de type Tcl_Obj* utilisent cette fonction pour allouer suffisamment d’espace pour une entrée et incrémenter le compteur de références sur la valeur.

Le membre freeEntryProc contient l’adresse d’une fonction appelée pour libérer l’espace d’une entrée.

typedef void Tcl_FreeHashEntryProc(
        Tcl_HashEntry *hPtr);

Si ceci est NULL, alors Tcl_Free est utilisé pour libérer l’espace de l’entrée. Les clés de type Tcl_Obj* utilisent cette fonction pour décrémenter le compteur de références sur la valeur.
