Tcl_RegExpRange(regexp, index, startPtr, endPtr)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur Tcl à utiliser pour le rapport d'erreur. L'interpréteur peut être NULL si aucun rapport d'erreur n'est souhaité.
Tcl_Obj *textObj (in/out)
Se réfère à la valeur à partir de laquelle obtenir le texte à rechercher. La représentation interne de la valeur peut être convertie dans une forme qui peut être recherchée efficacement.
Tcl_Obj *patObj (in/out)
Se réfère à la valeur à partir de laquelle obtenir une expression régulière. L'expression régulière compilée est mise en cache dans la valeur.
const char *text (in)
Texte à rechercher une correspondance avec une expression régulière.
const char *pattern (in)
Chaîne sous forme de motif d'expression régulière.
Tcl_RegExp regexp (in)
Expression régulière compilée. Doit avoir été retournée précédemment par Tcl_GetRegExpFromObj ou Tcl_RegExpCompile.
const char *start (in)
Si text n'est qu'une portion d'une autre chaîne, cet argument identifie le début de la chaîne plus grande. S'il n'est pas le même que text, alors aucun motif «“^” ne sera autorisé.
int index (in)
Spécifie quelle plage est souhaitée : 0 signifie la plage de la correspondance entière, 1 ou plus signifie la plage qui a correspondu à une sous-expression entre parenthèses.
const char **startPtr (out)
L'adresse du premier caractère de la plage est stockée ici, ou NULL s'il n'y a pas de telle plage.
const char **endPtr (out)
L'adresse du caractère juste après le dernier caractère de la plage est stockée ici, ou NULL s'il n'y a pas de telle plage.
int cflags (in)
Combinaison par OR des indicateurs de compilation TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, TCL_REG_EXPANDED, TCL_REG_QUOTE, TCL_REG_NOCASE, TCL_REG_NEWLINE, TCL_REG_NLSTOP, TCL_REG_NLANCH, TCL_REG_NOSUB, et TCL_REG_CANMATCH. Voir ci-dessous pour plus d'informations.
int offset (in)
Le décalage de caractère dans le texte où la correspondance doit commencer. La valeur du décalage n'a aucun impact sur les correspondances ^. Ce comportement est contrôlé par eflags.
int nmatches (in)
Le nombre de sous-expressions correspondantes qui doivent être mémorisées pour une utilisation ultérieure. Si cette valeur est 0, alors aucune information de correspondance de sous-expression ne sera calculée. Si la valeur est -1, alors toutes les sous-expressions correspondantes seront mémorisées. Toute autre valeur sera considérée comme le nombre maximum de sous-expressions à mémoriser.
int eflags (in)
Combinaison par OR des indicateurs d'exécution TCL_REG_NOTBOL et TCL_REG_NOTEOL. Voir ci-dessous pour plus d'informations.
Tcl_RegExpInfo *infoPtr (out)
L'adresse de l'emplacement où les informations sur une correspondance précédente doivent être stockées par Tcl_RegExpGetInfo.

DESCRIPTION

Tcl_RegExpMatch détermine si son argument pattern correspond à regexp, où regexp est interprété comme une expression régulière en utilisant les règles de la page de manuel re_syntax. S'il y a une correspondance, Tcl_RegExpMatch renvoie 1. S'il n'y a pas de correspondance, elle renvoie 0. Si une erreur se produit pendant le processus de correspondance (par exemple, pattern n'est pas une expression régulière valide), Tcl_RegExpMatch renvoie -1 et laisse un message d'erreur dans le résultat de l'interpréteur. Tcl_RegExpMatchObj est similaire à Tcl_RegExpMatch mais opère sur les valeurs Tcl textObj et patObj au lieu de chaînes UTF-8. Tcl_RegExpMatchObj est généralement plus efficace que Tcl_RegExpMatch, c'est donc l'interface préférée.

Tcl_RegExpCompile, Tcl_RegExpExec et Tcl_RegExpRange fournissent un accès de plus bas niveau au module de motif d'expression régulière. Tcl_RegExpCompile compile une chaîne d'expression régulière dans la forme interne utilisée pour une recherche efficace. La valeur retournée est un jeton pour cette forme compilée, qui peut être utilisé dans des appels ultérieurs à Tcl_RegExpExec ou Tcl_RegExpRange. Si une erreur se produit pendant la compilation de l'expression régulière, Tcl_RegExpCompile renvoie NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Notez : la valeur retournée par Tcl_RegExpCompile n'est valide que jusqu'au prochain appel à Tcl_RegExpCompile ; il n'est pas sûr de conserver ces valeurs pendant des périodes prolongées.

Tcl_RegExpExec exécute le module de motif d'expression régulière. Elle renvoie 1 si text contient une plage de caractères qui correspond à regexp, 0 s'il n'y a pas de correspondance, et -1 s'il se produit une erreur. En cas d'erreur, Tcl_RegExpExec laisse un message d'erreur dans le résultat de l'interpréteur. Lorsque vous recherchez un motif dans une chaîne pour plusieurs correspondances, il est important de faire la distinction entre le début de la chaîne d'origine et le début de la recherche actuelle. Par exemple, lors de la recherche de la deuxième correspondance, l'argument text pourrait pointer vers le caractère juste après la première correspondance ; cependant, il est important que le module de motif sache que ce n'est pas le début de la chaîne entière, de sorte que les correspondances de type ^ ne sont pas autorisées dans le motif. L'argument start fournit cette information en pointant vers le début de la chaîne entière contenant text. Start sera inférieur ou égal à text ; s'il est inférieur, les correspondances de type ^ ne seront pas autorisées.

Tcl_RegExpRange peut être appelée après que Tcl_RegExpExec a renvoyé ; elle fournit des informations détaillées sur les plages de la chaîne qui ont correspondu à quelles parties du motif. Tcl_RegExpRange renvoie une paire de pointeurs dans *startPtr et *endPtr qui identifient une plage de caractères dans la chaîne source pour l'appel le plus récent à Tcl_RegExpExec. Index indique quelle parmi plusieurs plages est souhaitée : si index est 0, des informations sur la plage générale de caractères qui ont correspondu au motif complet sont renvoyées ; sinon, des informations sur la plage de caractères qui ont correspondu à la sous-expression d'index index dans le motif sont renvoyées. S'il n'y a pas de plage correspondant à index, alors NULL sera stocké dans *startPtr et *endPtr.

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj et Tcl_RegExpGetInfo sont des interfaces d'objet qui fournissent le contrôle le plus direct sur la bibliothèque d'expressions régulières de Henry Spencer. Pour les utilisateurs qui ont besoin de modifier directement les options de compilation et d'exécution, il est conseillé d'utiliser ces interfaces au lieu d'appeler les fonctions internes de regexp. Ces interfaces gèrent les traductions de UTF vers Unicode et offrent de meilleures performances grâce à la mise en cache dans les objets de motif et de texte.

Tcl_GetRegExpFromObj tente de renvoyer une expression régulière compilée à partir de patObj. Si la valeur ne contient pas déjà une expression régulière compilée, elle tentera d'en créer une à partir de la chaîne dans la valeur et de l'attribuer à la représentation interne de patObj. La valeur retournée par cette fonction est de type Tcl_RegExp. La valeur retournée est un jeton pour cette forme compilée, qui peut être utilisé dans des appels ultérieurs à Tcl_RegExpExecObj ou Tcl_RegExpGetInfo. Si une erreur se produit pendant la compilation de l'expression régulière, Tcl_GetRegExpFromObj renvoie NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Le jeton d'expression régulière peut être utilisé tant que la représentation interne de patObj fait référence à la forme compilée. L'argument cflags est un OU de zéro ou plus des indicateurs suivants qui contrôlent la compilation de patObj :

TCL_REG_ADVANCED

NOM

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj, Tcl_RegExpGetInfo – compiler et exécuteur d'expressions régulières Tcl

SYNOPSIS

#include <tcl.h>

int
Tcl_GetRegExpFromObj(interp, objPtr, flags);

int
Tcl_RegExpExecObj(interp, regexpObjPtr, objPtr,
        nmatches, offset, eflags);

void
Tcl_RegExpGetInfo(regexpObjPtr, infoPtr);

ARGUMENTS

TCL_REG_ADVANCED
Compile des expressions régulières avancées ("ARE"s). Ce mode correspond à la syntaxe normale des expressions régulières acceptée par les commandes Tcl regexp et regsub.
TCL_REG_EXTENDED
Compile des expressions régulières étendues ("ERE"s). Ce mode correspond à la syntaxe des expressions régulières reconnue par Tcl 8.0 et les versions antérieures.
TCL_REG_BASIC
Compile des expressions régulières de base ("BRE"s). Ce mode correspond à la syntaxe des expressions régulières reconnue par les utilitaires Unix courants comme sed et grep. C'est le mode par défaut si aucun indicateur n'est spécifié.
TCL_REG_EXPANDED
Compile l'expression régulière (de base, étendue ou avancée) en utilisant une syntaxe étendue qui autorise les commentaires et les espaces blancs. Ce mode ignore les espaces blancs non protégés par une barre oblique inverse et ne faisant pas partie d'une expression entre crochets, ainsi que les commentaires du type #-jusqu'à la fin de la ligne.
TCL_REG_QUOTE
Compile une chaîne littérale, tous les caractères étant traités comme des caractères ordinaires.
TCL_REG_NOCASE
Compile pour une correspondance ignorant la distinction entre majuscules et minuscules.
TCL_REG_NEWLINE
Compile pour une correspondance sensible aux sauts de ligne. Par défaut, le saut de ligne est un caractère complètement ordinaire sans signification spéciale dans les expressions régulières ou les chaînes. Avec cet indicateur, les expressions entre crochets de type [^...] et le caractère "." ne correspondent jamais au saut de ligne, "^" correspond à une chaîne vide après tout saut de ligne en plus de sa fonction normale, et "$" correspond à une chaîne vide avant tout saut de ligne en plus de sa fonction normale. REG_NEWLINE est le OU bit à bit de REG_NLSTOP et REG_NLANCH.
TCL_REG_NLSTOP
Compile pour une correspondance partiellement sensible aux sauts de ligne, avec le comportement des expressions entre crochets [^...] et du caractère "." affecté, mais pas le comportement de "^" et "$". Dans ce mode, les expressions entre crochets [^...] et le caractère "." ne correspondent jamais au saut de ligne.
TCL_REG_NLANCH
Compile pour une correspondance inverse partiellement sensible aux sauts de ligne, avec le comportement de "^" et "$" (les "ancres") affecté, mais pas le comportement des expressions entre crochets [^...] et du caractère ".". Dans ce mode, "^" correspond à une chaîne vide après tout saut de ligne en plus de sa fonction normale, et "$" correspond à une chaîne vide avant tout saut de ligne en plus de sa fonction normale.
TCL_REG_NOSUB
Compile pour une correspondance qui ne signale que le succès ou l'échec, pas ce qui a été trouvé. Cela réduit les frais de compilation et peut améliorer les performances. Les appels ultérieurs à Tcl_RegExpGetInfo ou Tcl_RegExpRange ne signaleront aucune information de correspondance.
TCL_REG_CANMATCH
Compile pour une correspondance qui signale la possibilité de compléter une correspondance partielle étant donné plus de texte (voir ci-dessous).

Un seul parmi TCL_REG_EXTENDED, TCL_REG_ADVANCED, TCL_REG_BASIC et TCL_REG_QUOTE peut être spécifié.

Tcl_RegExpExecObj exécute le moteur de correspondance de motif d'expression régulière. Il renvoie 1 si objPtr contient une plage de caractères qui correspond à regexp, 0 si aucune correspondance n'est trouvée, et -1 si une erreur se produit. Dans le cas d'une erreur, Tcl_RegExpExecObj laisse un message d'erreur dans le résultat de l'interpréteur. La valeur nmatches indique au moteur combien de sous-expressions sont d'intérêt. Si nmatches est 0, alors aucune information de correspondance de sous-expression n'est enregistrée, ce qui peut permettre au moteur d'effectuer diverses optimisations. Si la valeur est -1, alors toutes les sous-expressions du motif sont conservées. Si la valeur est un entier positif, alors seulement ce nombre de sous-expressions sera conservé. La correspondance commence à l'index de caractère Unicode spécifié par offset. Contrairement à Tcl_RegExpExec, le comportement des ancres n'est pas affecté par la valeur de décalage. Au lieu de cela, le comportement des ancres est explicitement contrôlé par l'argument eflags, qui est un OU bit à bit de zéro ou plusieurs des indicateurs suivants :

TCL_REG_NOTBOL
Le caractère de départ ne sera pas traité comme le début d'une ligne ou le début de la chaîne, donc "^" ne correspondra pas là. Notez que cet indicateur n'a aucun effet sur la façon dont "\A" correspond.
TCL_REG_NOTEOL
Le dernier caractère de la chaîne ne sera pas traité comme la fin d'une ligne ou la fin de la chaîne, donc "$" ne correspondra pas là. Notez que cet indicateur n'a aucun effet sur la façon dont "\Z" correspond.

Tcl_RegExpGetInfo récupère des informations sur la dernière correspondance effectuée avec une expression régulière donnée regexp. L'argument infoPtr contient un pointeur vers une structure définie comme suit :

typedef struct Tcl_RegExpInfo {
    int nsubs;
    Tcl_RegExpIndices *matches;
    long extendStart;
} Tcl_RegExpInfo;

Le champ nsubs contient le nombre d'expressions parenthesisées dans l'expression régulière. Si TCL_REG_NOSUB a été utilisé, cette valeur sera zéro. Le champ matches pointe vers un tableau de nsubs+1 valeurs qui indiquent les limites de chaque sous-expression correspondante. Le premier élément du tableau fait référence à la plage correspondue par l'expression régulière entière, et les éléments suivants font référence aux sous-expressions parenthesées dans l'ordre où elles apparaissent dans le motif. Chaque élément est une structure définie comme suit :

typedef struct Tcl_RegExpIndices {
    long start;
    long end;
} Tcl_RegExpIndices;

Les valeurs start et end sont des indices de caractères Unicode relatifs à l'emplacement du décalage dans objPtr où la correspondance a commencé. L'indice start identifie le premier caractère de la sous-expression correspondante. L'indice end identifie le premier caractère après la sous-expression correspondante. Si la sous-expression correspond à la chaîne vide, alors start et end seront égaux. Si la sous-expression n'a pas participé à la correspondance, alors start et end seront définis à -1.

Le champ extendStart dans Tcl_RegExpInfo n'est défini que si l'indicateur TCL_REG_CANMATCH a été utilisé. Il indique le premier caractère de la chaîne où une correspondance pourrait se produire. Si une correspondance a été trouvée, ce sera la même que le début de la correspondance actuelle. Si aucune correspondance n'a été trouvée, il indiquera le point le plus précoce où une correspondance pourrait se produire si du texte supplémentaire est ajouté à la chaîne. S'il est impossible d'établir une correspondance même avec du texte supplémentaire, ce champ sera défini à -1.
