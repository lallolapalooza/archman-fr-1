Pour Tcl_AddObjErrorInfo, il pointe vers le premier octet d'un tableau de length octets contenant une chaîne à ajouter à la valeur de l'option -errorinfo. Tcl_Obj *errorObjPtr (in)
La valeur de l'option -errorcode sera définie sur cette valeur.

Une chaîne à enregistrer comme élément de l'option de retour -errorcode. Le dernier argument doit être (char *)NULL.

Une liste d'arguments qui doit avoir été initialisée avec va_start et terminée avec va_end.

Le pointeur vers le premier caractère du script contenant la commande (doit être <= la commande).

Le pointeur vers le premier caractère de la commande qui a généré l'erreur.

Le nombre d'octets dans la commande ; -1 signifie utiliser tous les octets jusqu'au premier octet nul.

DESCRIPTION

Les routines Tcl_SetReturnOptions et Tcl_GetReturnOptions exposent les mêmes capacités que les commandes return et catch respectivement sous forme d'interface C.

Tcl_GetReturnOptions récupère le dictionnaire des options de retour d'un interpréteur après l'évaluation d'un script. Des routines comme Tcl_Eval sont appelées pour évaluer un script dans un interpréteur. Ces routines retournent un code d'achèvement entier. Ces routines maintiennent également dans l'interpréteur à la fois un résultat et un dictionnaire d'options de retour générés par l'évaluation du script. Ainsi, de la même manière que Tcl_GetObjResult récupère le résultat, Tcl_GetReturnOptions récupère le dictionnaire des options de retour. Le code d'achèvement entier doit être passé comme argument code à Tcl_GetReturnOptions afin que toutes les exigences soient présentes dans le dictionnaire. Spécifiquement, une valeur de code de TCL_ERROR garantira que les entrées pour les clés -errorinfo, -errorcode et -errorline sont dans le dictionnaire. Les entrées pour les clés -code et -level seront également ajustées si nécessaire pour correspondre à la valeur de code. Le (Tcl_Obj *) retourné par Tcl_GetReturnOptions pointe vers un Tcl_Obj non partagé avec un compteur de références de zéro. Le dictionnaire peut être modifié, en ajoutant, supprimant ou remplaçant n'importe quelle entrée, sans avoir besoin de vérifier une valeur partagée. Comme tout Tcl_Obj avec un compteur de références de zéro, il incombe à l'utilisateur d'organiser sa disposition avec Tcl_DecrRefCount ou en le référençant via Tcl_IncrRefCount (ou l'une des nombreuses fonctions qui font cela, y compris Tcl_SetObjResult et Tcl_SetVar2Ex).

Une utilisation typique de Tcl_GetReturnOptions est de récupérer la pile d'appels lorsqu'une erreur de retour de script se produit, comme le montre l'exemple :

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* Faire quelque chose avec stackTrace */
    Tcl_DecrRefCount(options);
}

Tcl_SetReturnOptions définit les options de retour de interp comme options. Si options contient une valeur invalide pour une clé, TCL_ERROR est retourné et le résultat de l'interpréteur sera défini sur un message d'erreur approprié. Sinon, un code d'achèvement correspondant à la valeur des clés -code et -level dans options sera retourné.

Par exemple, la commande return de Tcl elle-même pourrait être implémentée en termes de Tcl_SetReturnOptions comme suit :

if ((objc % 2) == 0) { /* argument explicite */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(Elle n'est pas réellement implémentée ainsi. Les privilèges internes permettent une alternative plus efficace qui s'intègre mieux au compilateur de bytecode.)

Note : Un nouvel objet Tcl_Obj peut être passé comme argument options sans avoir besoin de gérer la comptabilité des références. Ceci est similaire à Tcl_SetObjResult.

Bien que Tcl_SetReturnOptions fournisse une interface générale pour définir n'importe quelle collection d'options de retour, il existe un nombre limité d'options de retour qui sont très fréquemment utilisées. Les plus notables sont les options -errorinfo et -errorcode. Elles doivent être correctement définies lorsque la procédure de commande retourne TCL_ERROR. L'option -errorline est également lue par les commandes qui évaluent des scripts et souhaitent fournir des informations de localisation détaillées dans le rapport d'erreur. Tcl fournit plusieurs interfaces plus simples pour définir directement ces options de retour.

La valeur de l'option -errorinfo contient une pile d'appels des opérations qui étaient en cours d'exécution lorsqu'une erreur s'est produite, et est destinée à être lisible par l'homme. La valeur de l'option -errorcode contient une liste d'éléments Tcl destinés à être lisibles par machine. Le premier élément de l'option -errorcode identifie le type d'erreur qui s'est produite (par exemple, POSIX signifie qu'une erreur s'est produite dans un appel système POSIX). Les éléments supplémentaires contiennent des informations supplémentaires qui dépendent du type d'erreur. Pour plus de détails sur les différents formats utilisés dans l'option -errorcode par les commandes internes de Tcl, consultez l'entrée de manuel de la variable errorCode.

La valeur de l'option -errorinfo est progressivement construite pendant que l'erreur est transmise par les opérations imbriquées. Chaque fois qu'un code d'erreur est renvoyé à Tcl_Eval, ou à toute routine qui effectue l'évaluation de scripts, la procédure Tcl_AddErrorInfo est appelée pour ajouter du texte supplémentaire à la valeur de l'option -errorinfo décrivant la commande qui était en cours d'exécution lorsque l'erreur s'est produite. Lorsque l'erreur a été entièrement transmise au programme, elle contiendra une trace complète de l'activité en cours d'exécution lorsque l'erreur s'est produite.

Il est parfois utile d'ajouter des informations supplémentaires à l'option -errorinfo au-delà de ce que peuvent fournir les routines d'évaluation de scripts. Tcl_AddErrorInfo peut être utilisé à cette fin : son argument message est une chaîne supplémentaire à ajouter à la valeur de l'option -errorinfo. Par exemple, lorsqu'une erreur se produit pendant la commande source, la procédure Tcl_AddErrorInfo est appelée pour enregistrer le nom du fichier traité et la ligne où l'erreur s'est produite. De même, lorsqu'une erreur se produit pendant l'évaluation d'un script...

Tcl_SetReturnOptions — Set the return options for the interpreter

DESCRIPTION

These procedures are used to control the return options of the interpreter, which are error information that is returned to the application when a Tcl script executes an error. The return options are accessed by the application using Tcl_GetReturnOptions.

The error information consists of several fields, including: -errorinfo, which contains a stack trace of Tcl procedures and line numbers, and -errorcode, which contains a Tcl list that describes the error in more detail. -errorline contains the line number where the error occurred.

Tcl_AddErrorInfo appends the string pointed to by message to the interpreter's -errorinfo return option. This is typically done when an error occurs within a Tcl script. The Tcl procedure names and line numbers within the procedure are recorded, and so on. The best time to invoke Tcl_AddErrorInfo is just after a script evaluation routine returns TCL_ERROR. The value of the -errorline option (retrieved by a call to Tcl_GetReturnOptions) often forms a useful part of the message passed to Tcl_AddErrorInfo.

Tcl_AppendObjToErrorInfo is an alternative interface to the same functionality as Tcl_AddErrorInfo. Tcl_AppendObjToErrorInfo is called when the value of the string to append to the -errorinfo option is available as a Tcl_Obj instead of as a char array.

Tcl_AddObjErrorInfo is almost identical to Tcl_AddErrorInfo, except that it has an additional argument length. This allows the message string to contain implicit null bytes. This is essentially never a good idea. If the message needs to contain a null byte U+0000, Tcl's internal encoding rules should be used to avoid the need for a null byte. If the Tcl_AddObjErrorInfo interface is used in any case, it should be used with a negative value for length.

The procedure Tcl_SetObjErrorCode is used to set the value of the -errorcode option to the list errorObjPtr constructed by the caller. Tcl_SetObjErrorCode is typically invoked just before returning an error. If an error is returned without invoking Tcl_SetObjErrorCode or Tcl_SetErrorCode, the Tcl interpreter automatically sets the value of the -errorcode option to NONE.

The procedure Tcl_SetErrorCode is also used to set the value of the -errorcode option. However, it takes one or more strings to record the value instead of a value. Otherwise, its behavior is similar to Tcl_SetObjErrorCode.

Tcl_SetErrorCodeVA is the same as Tcl_SetErrorCode, except that it takes a list argument instead of a variable number of arguments.

The procedure Tcl_GetErrorLine is used to read the integer value of the -errorline option without the overhead of a full call to Tcl_GetReturnOptions. Similarly, Tcl_SetErrorLine sets the value of the -errorline option.

Tcl_PosixError sets the value of the -errorcode variable after an error in a POSIX kernel call. It reads the value of the C variable errno and calls Tcl_SetErrorCode to set the value of the -errorcode option in the POSIX format. The caller must have previously called Tcl_SetErrno to set errno before this operation; this is necessary in some environments (e.g., on Windows) where Tcl is linked into an application as a shared library, or when the error occurs in a dynamically loaded extension. See the manual entry for Tcl_SetErrno for more information.

Tcl_PosixError returns a human-readable diagnostic message for the error (this is the same value that will appear as the third element in the -errorcode option's value). It may be convenient to include this string as part of the error message returned to the application in the interpretation result.

Tcl_LogCommandInfo is invoked after an error occurs in an interpretation environment. It adds information about the command that was being executed when the error occurred to the -errorinfo error evaluation, and the internally stored line number in the interpretation environment is set.

In older versions of Tcl, the Tcl_GetReturnOptions routine did not exist. Instead, the global variables errorInfo and errorCode were the only possible way to retrieve error information. Much existing code written for older versions of Tcl still accesses this information via those global variables.

It is important to recognize that although reading these global variables remains a supported way to access these return values, it is important not to assume that writing to these global variables will correctly set the corresponding return values. It has always been emphasized in this manual that it is important to invoke the procedures described here rather than directly setting errorInfo or errorCode with Tcl_ObjSetVar2.

If the procedure Tcl_ResetResult is called, it cleans up all state of the script evaluation environment, including the complete return options dictionary. In particular, the -errorinfo and -errorcode options are reset. If an error had occurred, the call to Tcl_ResetResult will clean up the error state so that it appears as if no error occurred after all. The global variables errorInfo and errorCode are not modified by Tcl_ResetResult and continue to hold information about the most recent error in an interpretation environment.
