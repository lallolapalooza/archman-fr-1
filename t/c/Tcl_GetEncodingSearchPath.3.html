Tcl_Interp *interp (in)
Interpréteur à utiliser pour le rapport d'erreurs, ou NULL si aucun rapport d'erreurs n'est souhaité.
const char *name (in)
Nom de l'encodage à charger.

L'encodage à interroger, libérer ou utiliser pour convertir du texte. Si encoding est NULL, l'encodage système actuel est utilisé.
Tcl_Obj *objPtr (in)
Nom de l'encodage pour lequel obtenir un jeton.
Tcl_Encoding *encodingPtr (out)
Pointe vers la zone mémoire où le jeton d'encodage doit être écrit.
const char *src (in)
Pour les fonctions Tcl_ExternalToUtf, un tableau d'octets dans l'encodage spécifié qui doit être converti en UTF-8. Pour les fonctions Tcl_UtfToExternal et Tcl_WinUtfToTChar, un tableau de caractères UTF-8 à convertir dans l'encodage spécifié.
const TCHAR *tsrc (in)
Un tableau de caractères Windows TCHAR à convertir en UTF-8.
int srcLen (in)
Longueur de src ou tsrc en octets. Si la longueur est négative, la longueur spécifique à l'encodage de la chaîne est utilisée.
Tcl_DString *dstPtr (out)
Pointeur vers une Tcl_DString non initialisée ou libérée dans laquelle le résultat converti sera stocké.
int flags (in)
Divers bits d'indicateurs combinés par OR. TCL_ENCODING_START signifie que le tampon source est le premier bloc d'un flux d'entrée (potentiellement multi-blocs), indiquant à la routine de conversion de revenir à un état initial et d'effectuer toute initialisation nécessaire avant la conversion du premier octet. TCL_ENCODING_END signifie que le tampon source est le dernier bloc d'un flux d'entrée (potentiellement multi-blocs), indiquant à la routine de conversion d'effectuer toute finalisation nécessaire après la conversion du dernier octet, puis de revenir à un état initial. TCL_ENCODING_STOPONERROR signifie que la routine de conversion doit retourner immédiatement à la lecture d'un caractère source qui n'existe pas dans l'encodage cible ; sinon, un caractère de remplacement par défaut sera automatiquement substitué.
Tcl_EncodingState *statePtr (in/out)
Utilisé lors de la conversion d'un flux d'octets (généralement long ou de longueur indéfinie) morceau par morceau. La routine de conversion stocke son état actuel dans *statePtr après que src (le tampon contenant le morceau actuel) ait été converti ; ces informations d'état doivent être retransmises lors de la conversion du morceau suivant du flux afin que la routine de conversion sache dans quel état elle s'est arrêtée à la fin du dernier morceau. Peut être NULL, auquel cas la valeur spécifiée pour flags est ignorée et le tampon source est supposé contenir la chaîne complète à convertir.
char *dst (out)
Tampon dans lequel le résultat converti sera stocké. Pas plus de dstLen octets seront stockés dans dst.
int dstLen (in)
La longueur maximale du tampon de sortie dst en octets.
int *srcReadPtr (out)
Rempli avec le nombre d'octets de src qui ont effectivement été convertis. Cela peut être inférieur à la longueur source originale s'il y a eu un problème lors de la conversion de certains caractères source. Peut être NULL.
int *dstWrotePtr (out)
Rempli avec le nombre d'octets qui ont effectivement été stockés dans le tampon de sortie suite à la conversion. Peut être NULL.
int *dstCharsPtr (out)
Rempli avec le nombre de caractères correspondant au nombre d'octets stockés dans le tampon de sortie. Peut être NULL.
Tcl_DString *bufPtr (out)
Zone mémoire pour le nom de l'encodage système prescrit.
const Tcl_EncodingType *typePtr (in)
Structure définissant un nouveau type d'encodage.

Un chemin vers l'emplacement du fichier d'encodage.

INTRODUCTION

Ces routines convertissent entre la représentation interne de caractères de Tcl, UTF-8, et les représentations de caractères utilisées par divers systèmes d'exploitation ou systèmes de fichiers, tels que Unicode, ASCII ou Shift-JIS. Lors de la manipulation de chaînes, par exemple pour obtenir les noms de fichiers ou afficher des caractères à l'aide de polices internationales, les chaînes doivent être traduites dans un ou potentiellement plusieurs formats que les divers appels système peuvent utiliser. Par exemple, sur un poste de travail Unix japonais, un utilisateur pourrait obtenir un nom de fichier représenté dans l'encodage de fichier EUC-JP, puis traduire les caractères dans l'encodage de police jisx0208 afin d'afficher le nom de fichier dans un widget Tk. Le but du paquet d'encodage est d'aider à combler l'écart de traduction. UTF-8 fournit un terrain d'étape intermédiaire pour tous les divers encodages. Dans l'exemple ci-dessus, le texte serait traduit en UTF-8 à partir de l'encodage de fichier que le système d'exploitation utilise. Ensuite, il serait traduit de UTF-8 vers l'encodage de police requis par les routines d'affichage.

Certains encodages de base sont compilés dans Tcl. D'autres peuvent être définis par l'utilisateur ou chargés dynamiquement à partir de fichiers d'encodage d'une manière indépendante de la plateforme.

DESCRIPTION

Tcl_GetEncoding recherche un encodage étant donné son name. Le nom peut faire référence à un encodage Tcl intégré, à un encodage défini par l'utilisateur enregistré en appelant Tcl_CreateEncoding, ou à un fichier d'encodage chargeable dynamiquement. La valeur de retour est un jeton qui représente l'encodage et peut être utilisé dans des appels ultérieurs à des procédures telles que Tcl_GetEncodingName, Tcl_FreeEncoding et Tcl_UtfToExternal. Si le nom ne fait référence à aucun encodage connu ou chargeable, NULL est retourné et un message d'erreur est retourné dans interp.

Le paquet d'encodage maintient une base de données de tous les encodages actuellement utilisés. La première fois que name est rencontré, Tcl_GetEncoding retourne un encodage avec un compteur de référence de 1. Si le même name est demandé plusieurs fois, le compteur de référence pour cet encodage est incrémenté sans le surcoût d'allocation d'un nouvel encodage et de toutes ses structures de données associées.

Lorsqu'un encoding n'est plus nécessaire, Tcl_FreeEncoding doit être appelé pour le libérer. Lorsqu'un encoding n'est plus utilisé nulle part (c'est-à-dire qu'il a été libéré autant de fois qu'il a été obtenu), Tcl_FreeEncoding libérera toute la mémoire utilisée par l'encodage et le supprimera de la base de données.

Tcl_GetEncodingFromObj traite la représentation sous forme de chaîne de objPtr comme un nom d'encodage, et trouve un encodage avec ce nom, tout comme le fait Tcl_GetEncoding. encodingPtr es el puntero que se apunta. Se devuelve el valor TCL_OK. Si no se encuentra dicha codificación, se devuelve el valor TCL_ERROR y no se escribe nada en *encodingPtr. Al igual que con Tcl_GetEncoding, el llamador debe llamar a Tcl_FreeEncoding sobre el token de codificación resultante cuando ese token ya no se necesite.

Tcl_ExternalToUtfDString convierte un búfer fuente src de la codificación especificada encoding a UTF-8. Los bytes convertidos se almacenan en dstPtr, que se termina con un carácter nulo específico de la codificación. El llamador eventualmente deberá llamar a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Cuando se realiza la conversión, si algún carácter de la fuente no se puede representar en la codificación de destino, se utiliza un carácter de reemplazo predeterminado. El valor devuelto es un puntero al valor almacenado en el DString.

Tcl_ExternalToUtf convierte un búfer fuente src de la codificación especificada encoding a UTF-8. Se convierten más de srcLen bytes de la fuente y se almacenan más de dstLen bytes en dst. En todos los casos, *srcReadPtr se rellena con el número de bytes que se convirtieron correctamente de src y *dstWrotePtr se rellena con el número de bytes correspondientes que se almacenaron en dst. El valor devuelto es uno de los siguientes:

TCL_OK
Todo el contenido de src se convirtió.
TCL_CONVERT_NOSPACE
El búfer de destino no es lo suficientemente grande para almacenar todos los datos convertidos; se convirtieron tantos caracteres como fue posible.
TCL_CONVERT_MULTIBYTE
Los últimos bytes de la fuente eran el inicio de una secuencia multibyte, pero se necesitaron más bytes para completar esta secuencia. Una llamada posterior a la rutina de conversión debe pasar un búfer que contenga los bytes no convertidos restantes en src y algunos más de la secuencia de entrada para convertir correctamente la secuencia de caracteres que se había dividido previamente.
TCL_CONVERT_SYNTAX
El búfer de entrada contenía una secuencia de caracteres inválida. Esto puede ocurrir si el flujo de entrada ha sido dañado o si el método de codificación de entrada fue identificado incorrectamente.
TCL_CONVERT_UNKNOWN
El búfer de entrada contenía un carácter que no se puede representar en la codificación de destino y se especificó TCL_ENCODING_STOPONERROR.

Tcl_UtfToExternalDString convierte un búfer de entrada src de UTF-8 a la codificación especificada encoding. Los bytes convertidos se almacenan en dstPtr, que se termina con el carácter nulo adecuado para la codificación. El llamador eventualmente deberá llamar a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Cuando se realiza la conversión, si algún carácter de la fuente no se puede representar en la codificación de destino, se utiliza un carácter de reemplazo predeterminado. El valor devuelto es un puntero al valor almacenado en el DString.

Tcl_UtfToExternal convierte un búfer de entrada src de UTF-8 a la codificación especificada encoding. Se convierten más de srcLen bytes de la fuente y se almacenan más de dstLen bytes en dst. En todos los casos, *srcReadPtr se rellena con el número de bytes que se convirtieron correctamente de src y *dstWrotePtr se rellena con el número de bytes correspondientes que se almacenaron en dst. Los valores devueltos son los mismos que los de Tcl_ExternalToUtf.

Tcl_WinUtfToTChar y Tcl_WinTCharToUtf son funciones de conveniencia para convertir entre UTF-8 y cadenas de Windows basadas en el tipo TCHAR, que por conveniencia es un carácter Unicode en Windows NT.

Tcl_GetEncodingName es aproximadamente la inversa de Tcl_GetEncoding. Dado un encoding, el valor devuelto es el argumento name que se utilizó para crear la codificación. Se garantiza que la cadena devuelta por Tcl_GetEncodingName solo persistirá hasta que se elimine el encoding. El llamador no debe modificar esta cadena.

Tcl_SetSystemEncoding establece la codificación predeterminada que se utilizará cuando el usuario pasa un valor nulo para el argumento encoding a cualquier otra función de codificación. Si name es nulo, la codificación del sistema se restablece a la codificación predeterminada, binary. Si el nombre no se refiere a una codificación conocida o cargable, se devuelve TCL_ERROR y se deja un mensaje de error en interp. De lo contrario, este procedimiento incrementa el contador de referencias de la nueva codificación del sistema, decrementa el contador de referencias de la codificación antigua del sistema y devuelve TCL_OK.

Tcl_GetEncodingNameFromEnvironment proporciona un medio para que la biblioteca Tcl informe el nombre de la codificación que cree que es el correcto para ser la codificación del sistema, basándose en llamadas al sistema y examen del entorno adecuado para la plataforma. Acepta bufPtr, un puntero a un Tcl_DString no inicializado o liberado, y escribe el nombre de la codificación en él. El valor devuelto es el Tcl_DStringValue.

Tcl_GetEncodingNames establece el resultado interp a una lista que consiste en los nombres de todas las codificaciones definidas o dinámicamente cargables, buscando en la carpeta de codificaciones especificada por Tcl_SetDefaultEncodingDir. Este procedimiento no garantiza que los archivos dinámicamente cargables contengan datos válidos, pero sí que existen.

Tcl_CreateEncoding define una nueva codificación y registra los procedimientos C que se invocan para convertir entre esta codificación y UTF-8. Las codificaciones creadas por Tcl_CreateEncoding son thereafter visibles en la base de datos utilizada por Tcl_GetEncoding. Al igual que con Tcl_GetEncoding, el valor devuelto es un token que representa la codificación y puede utilizarse en llamadas posteriores a otras funciones de codificación. Tcl_CreateEncoding devuelve una codificación con un contador de referencias de 1. Si ya existe una codificación con el nombre especificado name, su entrada en la base de datos se reemplaza con la nueva codificación; el token de la antigua codificación sigue siendo válido y continúa comportándose como antes, pero los usuarios del nuevo token llamarán ahora a los procedimientos de la nueva codificación.

El argumento typePtr de Tcl_CreateEncoding contiene información sobre el nombre de la codificación y los procedimientos que se invocan para convertir entre esta codificación y UTF-8. Se define como:

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

El encodingName proporciona un nombre para la codificación, por el cual se puede hacer referencia en otros procedimientos como Tcl_GetEncoding. El toUtfProc hace referencia a un procedimiento de devolución de llamada que se invocará para convertir texto de esta codificación a UTF-8. El fromUtfProc hace referencia a un procedimiento de devolución de llamada que se invocará para convertir texto de UTF-8 a esta codificación. El freeProc hace referencia a un procedimiento de devolución de llamada que se invocará cuando se elimine esta codificación. El campo freeProc puede ser nulo. El clientData contiene un valor de una palabra que se pasa a los procedimientos toUtfProc, fromUtfProc y freeProc cuando se invocan. Generalmente, este es un puntero a una estructura que contiene información específica de la codificación que puede ser utilizada por los procedimientos de devolución de llamada. Por ejemplo, dos codificaciones muy similares como ascii y macRoman pueden usar el mismo procedimiento de devolución de llamada, pero utilizan diferentes valores de clientData para controlar su comportamiento. El nullSize especifica el número de ceros que se utilizan para indicar el final de una cadena en esta codificación. Debe ser 1 (para codificaciones de un solo byte o multibyte como ASCII o Shift-JIS) o 2 (para codificaciones de dos bytes como Unicode). No se aceptan codificaciones constantes con 3 o más bytes por carácter (como CNS11643).

Los procedimientos de devolución de llamada toUtfProc y fromUtfProc deben corresponder al tipo Tcl_EncodingConvertProc:

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

Los procedimientos toUtfProc y fromUtfProc son invocados por Tcl_ExternalToUtf o Tcl_UtfToExternal para realizar la conversión real. El parámetro clientData de estos procedimientos es el mismo que el campo clientData especificado en Tcl_CreateEncoding cuando se creó la codificación. Los argumentos restantes de los procedimientos de devolución de llamada son los mismos que los argumentos, documentados anteriormente, para Tcl_ExternalToUtf o Tcl_UtfToExternal, con las siguientes excepciones. Si el argumento srcLen de una de estas funciones de nivel superior es negativo, el valor pasado al procedimiento de devolución de llamada será la longitud adecuada de la codificación fuente src. Si alguno de los argumentos srcReadPtr, dstWrotePtr o dstCharsPtr de una de estas funciones de nivel superior es NULL, el valor correspondiente pasado al procedimiento de devolución de llamada será una ubicación no NULL.

El procedimiento de devolución de llamada freeProc, si no es nulo, debe corresponder al tipo Tcl_EncodingFreeProc:

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

Este freeProc se llama cuando se elimina la codificación. El parámetro clientData es el mismo que el campo clientData especificado en Tcl_CreateEncoding cuando se creó la codificación.

Tcl_GetEncodingSearchPath y Tcl_SetEncodingSearchPath se llaman para acceder y configurar la lista de directorios de archivos de datos de codificación que se buscan en el sistema.

El valor devuelto por Tcl_GetEncodingSearchPath es el valor almacenado por la última llamada exitosa a Tcl_SetEncodingSearchPath. NAME

Tcl_GetEncodingSearchPath, Tcl_SetEncodingSearchPath, Tcl_GetDefaultEncodingDir, Tcl_SetDefaultEncodingDir — manage the search path for encoding files

SYNOPSIS

#include <tcl.h>

const char *
Tcl_GetEncodingSearchPath(interp);

int
Tcl_SetEncodingSearchPath(interp, path);

const char *
Tcl_GetDefaultEncodingDir(void);

void
Tcl_SetDefaultEncodingDir(dir);

ARGUMENTS

char *interp
Tcl interpreter.
const char *path
A string containing a Tcl list of directories.
const char *dir
A string containing a directory path.

DESCRIPTION

The Tcl encoding system allows arbitrary character encodings to be supported dynamically through the use of dynamically loadable encoding files. Tcl searches for these files in a list of directories specified by the encoding search path. The Tcl_GetEncodingSearchPath and Tcl_SetEncodingSearchPath functions provide C-level access to this search path.

Tcl_GetEncodingSearchPath returns the current encoding search path as a Tcl list of directories. This value is stored in the interpreter’s global variable named “::encoding::searchPath”.

Tcl_SetEncodingSearchPath sets the encoding search path to the value of path. path must be a string containing a Tcl list of directories. The directories in the list are used by Tcl in order when searching for encoding data files. If path is NULL, the search path is reset to its default value (typically just the Tcl library directory’s encoding subdirectory).

The directories specified in searchPath are not verified as existing readable filesystem directories. When searching for encoding data files takes place, and non-existent or non-readable filesystem directories on the searchPath are silently ignored.

Tcl_GetDefaultEncodingDir and Tcl_SetDefaultEncodingDir are obsolete interfaces best replaced with calls to Tcl_GetEncodingSearchPath and Tcl_SetEncodingSearchPath. They are called to access and set the first element of the searchPath list. Since Tcl searches searchPath for encoding data files in list order, these routines establish the “default” directory in which to find encoding data files.

ENCODING FILES

Space would prohibit precompiling into Tcl every possible encoding algorithm, so many encodings are stored on disk as dynamically-loadable encoding files. This behavior also allows the user to create additional encoding files that can be loaded using the same mechanism. These encoding files contain information about the tables and/or escape sequences used to map between an external encoding and Unicode. The external encoding may consist of single-byte, multi-byte, or double-byte characters.

Each dynamically-loadable encoding is represented as a text file. The initial line of the file, beginning with a “#” symbol, is a comment that provides a human-readable description of the file. The next line identifies the type of encoding file. It can be one of the following letters:

[1] S
A single-byte encoding, where one character is always one byte long in the encoding. An example is iso8859-1, used by many European languages.
[2] D
A double-byte encoding, where one character is always two bytes long in the encoding. An example is big5, used for Chinese text.
[3] M
A multi-byte encoding, where one character may be either one or two bytes long. Certain bytes are lead bytes, indicating that another byte must follow and that together the two bytes represent one character. Other bytes are not lead bytes and represent themselves. An example is shiftjis, used by many Japanese computers.
[4] E
An escape-sequence encoding, specifying that certain sequences of bytes do not represent characters, but commands that describe how following bytes should be interpreted.

The rest of the lines in the file depend on the type.

Cases [1], [2], and [3] are collectively referred to as table-based encoding files. The lines in a table-based encoding file are in the same format as this example taken from the shiftjis encoding (this is not the complete file):

The third line of the file is three numbers. The first number is the fallback character (in base 16) to use when converting from UTF-8 to this encoding. The second number is a 1 if this file represents the encoding for a symbol font, or 0 otherwise. The last number (in base 10) is how many pages of data follow.

Subsequent lines in the example above are pages that describe how to map from the encoding into 2-byte Unicode. The first line in a page identifies the page number. Following it are 256 double-byte numbers, arranged as 16 rows of 16 numbers. Given a character in the encoding, the high byte of that character is used to select which page, and the low byte of that character is used as an index to select one of the double-byte numbers in that page - the value obtained being the corresponding Unicode character. By examination of the example above, one can see that the characters 0x7E and 0x8163 in shiftjis map to 203E and 2026 in Unicode, respectively.

Following the first page will be all the other pages, each in the same format as the first: one number identifying the page followed by 256 double-byte Unicode characters. If a character in the encoding maps to the Unicode character 0000, it means that the character does not actually exist. If all characters on a page would map to 0000, that page can be omitted.

Case [4] is the escape-sequence encoding file. The lines in an this type of file are in the same format as this example taken from the iso2022-jp encoding:

# Encoding file: iso2022-jp, escape-driven
E
init		{}
final		{}
iso8859-1	\x1b(B
jis0201		\x1b(J
jis0208		\x1b$@
jis0208		\x1b$B
jis0212		\x1b$(D
gb2312		\x1b$A
ksc5601		\x1b$(C

In the file, the first column represents an option and the second column is the associated value. init is a string to emit or expect before the first character is converted, while final is a string to emit or expect after the last character. All other options are names of table-based encodings; the associated value is the escape-sequence that marks that encoding. Tcl syntax is used for the values; in the above example, for instance, “{}” represents the empty string and “\x1b” represents character 27.

When Tcl_GetEncoding encounters an encoding name that has not been loaded, it attempts to load an encoding file called name.enc from the encoding subdirectory of each directory that Tcl searches for its script library. If the encoding file exists, but is malformed, an error message will be left in interp.
