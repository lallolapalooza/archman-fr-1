ARGUMENTS

Tcl_Interp *interp (en entrée)
L'interpréteur dans lequel stocker les données compressées ou décompressées résultantes. C'est aussi là que les messages d'erreur sont écrits. Pour Tcl_ZlibStreamInit, cela peut être NULL pour créer un flux qui n'est pas lié à une commande.
int format (en entrée)
Quel format de données compressées utiliser. Doit être l'un des suivants : TCL_ZLIB_FORMAT_ZLIB pour les données au format zlib, TCL_ZLIB_FORMAT_GZIP pour les données au format gzip, ou TCL_ZLIB_FORMAT_RAW pour les données compressées brutes. De plus, pour la décompression uniquement, TCL_ZLIB_FORMAT_AUTO peut également être choisi, ce qui permet de détecter automatiquement si les données compressées étaient au format zlib ou gzip.
Tcl_Obj *dataObj (en entrée/sortie)
Une valeur de type tableau d'octets contenant les données à compresser ou décompresser, ou à laquelle les données extraites du flux sont ajoutées lorsqu'elles sont passées à Tcl_ZlibStreamGet.
int level (en entrée)
Quel niveau de compression utiliser. Doit être un nombre de 0 à 9 ou l'un des suivants : TCL_ZLIB_COMPRESS_NONE pour aucune compression, TCL_ZLIB_COMPRESS_FAST pour une compression rapide mais inefficace, TCL_ZLIB_COMPRESS_BEST pour une compression lente mais maximale, ou TCL_ZLIB_COMPRESS_DEFAULT pour le niveau recommandé par la bibliothèque zlib.
Tcl_Obj *dictObj (en entrée/sortie)
Un dictionnaire qui contient, ou qui sera mis à jour pour contenir, une description de l'en-tête gzip associé aux données compressées. Utile uniquement lorsque le paramètre format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Si NULL est passé, un en-tête par défaut sera utilisé lors de la compression et l'en-tête sera ignoré (outre les vérifications d'intégrité) lors de la décompression. Voir la section DICTIONNAIRE D'OPTIONS GZIP pour les détails sur le contenu de ce dictionnaire.
unsigned int initValue (en entrée)
La valeur initiale pour l'algorithme de checksum.
int bufferSize (en entrée)
Un indice concernant la taille du tampon à utiliser pour recevoir les données. Utilisez 0 pour utiliser une estimation générique basée sur les données d'entrée.
unsigned char *bytes (en entrée)
Un tableau d'octets sur lequel exécuter l'algorithme de checksum, ou NULL pour obtenir la valeur initiale recommandée pour l'algorithme de checksum.
int length (en entrée)
Le nombre d'octets dans le tableau.
int mode (en entrée)
Dans quel mode faire fonctionner le flux. Doit être soit TCL_ZLIB_STREAM_DEFLATE pour un flux de compression, soit TCL_ZLIB_STREAM_INFLATE pour un flux de décompression.
Tcl_ZlibStream *zshandlePtr (en sortie)
Un pointeur vers une variable dans laquelle écrire le jeton abstrait du flux en cas de création réussie.
Tcl_ZlibStream zshandle (en entrée)
Le jeton abstrait du flux sur lequel opérer.
int flush (en entrée)
Si et comment vider le flux après y avoir écrit les données. Doit être l'un des suivants : TCL_ZLIB_NO_FLUSH si aucun vidage n'est à faire, TCL_ZLIB_FLUSH si les données actuellement compressées doivent être rendues disponibles pour accès via Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si le flux doit être mis dans un état où le décompresseur peut récupérer en cas de corruption, ou TCL_ZLIB_FINALIZE pour s'assurer que le flux est terminé et que toute bande finale exigée par le format est écrite.
int count (en entrée)
Le nombre maximum d'octets à extraire du flux, ou -1 pour extraire tous les octets restants des tampons du flux.
Tcl_Obj *compDict (en entrée)
Une valeur de type tableau d'octets représentant le dictionnaire de compression à utiliser avec le flux. Notez qu'il ne s'agit *pas* d'un dictionnaire Tcl, et il est recommandé de ne l'utiliser qu'avec des flux qui ont été créés avec leur format défini sur TCL_ZLIB_FORMAT_ZLIB, car les autres formats n'ont aucun mécanisme pour indiquer si un dictionnaire de compression était présent, autre qu'échouer lors de la décompression.

DESCRIPTION

Ces fonctions forment l'interface de la bibliothèque Tcl à la bibliothèque Zlib de Jean-loup Gailly et Mark Adler.

Tcl_ZlibDeflate et Tcl_ZlibInflate compressent et décompressent respectivement les données contenues dans l'argument dataObj, conformément aux arguments format et, pour la compression, level. Le dictionnaire de l'argument dictObj est utilisé pour transmettre des informations d'en-tête supplémentaires sur les données compressées lorsque le format de compression le prend en charge ; actuellement, le dictionnaire n'est utilisé que lorsque le paramètre format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Pour les détails sur le contenu du dictionnaire, voir la section DICTIONNAIRE D'OPTIONS GZIP ci-dessous. En cas de succès, les deux fonctions laissent les données compressées ou décompressées résultantes dans une valeur de type tableau d'octets qui est le résultat de l'interpréteur Tcl ; la valeur retournée est un code de résultat Tcl standard.

Tcl_ZlibAdler32 et Tcl_ZlibCRC32 calculent des checksums sur des tableaux d'octets, retournant le checksum calculé. Les checksums sont calculés de manière incrémentale, permettant de traiter les données bloc par bloc, mais cela nécessite que l'appelant maintienne le checksum actuel et le passe comme paramètre initValue ; la valeur initiale à utiliser pour cela peut être obtenue en utilisant NULL pour le paramètre bytes au lieu d'un pointeur vers le tableau d'octets sur lequel calculer le checksum. Ainsi, une utilisation typique dans le cas d'un bloc de données unique est la suivante :

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Notez que l'algorithme Adler-32 n'est pas un vrai checksum, mais plutôt un type de hachage connexe qui fonctionne mieux sur de longues données.

FLUX ZLIB

Tcl_ZlibStreamInit crée un flux de compression ou de décompression qui est lié à une commande Tcl, conformément à ses arguments, et fournit un jeton abstrait pour le flux et retourne un code de résultat Tcl normal ; Tcl_ZlibStreamGetCommandName retourne le nom de cette commande étant donné le jeton du flux, ou NULL si le flux n'a pas de commande. Les flux ne sont pas conçus pour être thread-safe ; chaque flux ne devrait jamais être utilisé que depuis le thread qui l'a créé. Lors de l'utilisation de flux gzip, un dictionnaire (champs comme indiqué dans la section DICTIONNAIRE D'OPTIONS GZIP ci-dessous) peut être fourni via le paramètre dictObj, ce qui permet lors de la compression de contrôler les en-têtes générés, et lors de la décompression de découvrir les en-têtes existants. Notez que le dictionnaire sera écrit lors de la décompression une fois que suffisamment de données auront été lues pour avoir un en-tête complet. Cela signifie que le dictionnaire doit être une valeur non partagée dans ce cas ; une valeur vide créée avec Tcl_NewObj est suggérée.

Une fois qu'un flux a été construit, Tcl_ZlibStreamPut est utilisé pour ajouter des données au flux et Tcl_ZlibStreamGet est utilisé pour récupérer des données du flux après traitement. Les deux retournent des codes de résultat Tcl normaux et laissent un message d'erreur dans le résultat de l'interpréteur auquel le flux est enregistré en cas d'erreur (si une telle enregistrement a été effectuée). Avec Tcl_ZlibStreamPut, la valeur du tampon de données qui lui est passée ne doit pas être modifiée par la suite. Avec Tcl_ZlibStreamGet, la valeur du tampon de données qui lui est passée aura les octets de données ajoutés. Interne au flux, les données sont gardées compressées afin de minimiser le coût de l'espace tampon.

DESCRIPTION

Ces fonctions fournissent une interface de flux pour la bibliothèque zlib. Elles permettent de compresser et décompresser des données en continu, sans avoir à charger toutes les données en mémoire en même temps.

Tcl_ZlibStreamInit initialise un nouveau flux zlib. Il prend en paramètre l'interpréteur Tcl, le niveau de compression, le format des données (zlib, gzip ou raw), une fonction de rappel à appeler lors de la fermeture du flux, et des données spécifiques au client.

Tcl_ZlibStreamPut écrit des données dans le flux pour la compression. Le paramètre flush peut être utilisé pour contrôler quand les données compressées doivent être envoyées.

Tcl_ZlibStreamGet lit des données décompressées du flux. Elle renvoie le nombre d'octets lus dans le tampon fourni. Si une erreur se produit, elle renvoie -1 et définit l'interpréteur Tcl pour contenir un message d'erreur. Si la fin des données décompressées est atteinte, elle renvoie 0. Les valeurs de retour spéciales sont retournées lorsque les conditions suivantes sont remplies. Z_OK signifie que la sortie est disponible et que le flux est toujours opérationnel. Z_BUF_ERROR est retourné si aucun espace de sortie n'est disponible. Z_STREAM_END est retourné quand la fin de l'archive décompressée est atteinte.

Tcl_ZlibStreamEof retourne une valeur booléenne indiquant si la fin des données décompressées a été atteinte.

Tcl_ZlibStreamSetCompressionDictionary est utilisé pour contrôler le dictionnaire de compression utilisé avec le flux. Un dictionnaire de compression est un tableau d'octets (tel que pourrait être créé avec Tcl_NewByteArrayObj) qui est utilisé pour initialiser le moteur de compression plutôt que de le laisser le créer à la volée à partir des données compressées. La définition d'un dictionnaire de compression permet une compression plus efficace dans le cas où le début des données est très régulier, mais elle exige que le compresseur et le décompresseur se mettent d'accord sur la valeur à utiliser. Les dictionnaires de compression ne sont pleinement pris en charge que pour les données au format zlib ; lors de la compression, ils doivent être définis avant que toute donnée ne soit envoyée avec Tcl_ZlibStreamPut, et lors de la décompression, ils doivent être définis lorsque Tcl_ZlibStreamGet produit une erreur avec son -errorcode défini sur “ZLIB NEED_DICT code”; le code sera la somme de contrôle Adler-32 (voir Tcl_ZlibAdler32) du dictionnaire de compression recherché. (Notez que ce n'est vrai que pour les flux au format zlib ; les flux gzip ignorent les dictionnaires de compression car la spécification du format ne les autorise pas, et les flux bruts produisent simplement une erreur de données si le dictionnaire de compression est manquant ou incorrect.)

Si vous souhaitez effacer un flux et le réutiliser pour une nouvelle action de compression ou de décompression, Tcl_ZlibStreamReset s'en chargera et renverra un code de résultat Tcl normal pour indiquer s'il a réussi ; si le flux est enregistré auprès d'un interpréteur, un message d'erreur sera laissé dans le résultat de l'interpréteur lorsque cette fonction renverra TCL_ERROR. Enfin, Tcl_ZlibStreamClose nettoiera le flux et supprimera la commande associée : l'utilisation de Tcl_DeleteCommand sur la commande du flux est équivalente (lorsqu'une telle commande existe).

OPTIONS GZIP DICTIONNAIRE

Le paramètre dictObj à Tcl_ZlibDeflate, Tcl_ZlibInflate et Tcl_ZlibStreamInit est utilisé pour passer un dictionnaire d'options concernant l'en-tête gzip dans les données compressées. Lors de la création de données compressées, le dictionnaire est lu et lors du déballage de données compressées, le dictionnaire est écrit (auquel cas le paramètre dictObj doit faire référence à une valeur de dictionnaire non partagée).

Les champs suivants dans la valeur du dictionnaire sont compris. Tous les autres champs sont ignorés. Aucun champ n'est requis lors de la création d'un flux au format gzip.

comment
Contient le champ commentaire de l'en-tête, s'il est présent. S'il est absent, aucun commentaire n'a été fourni (lors de la décompression) ou ne sera créé (lors de la compression).
crc
Une valeur booléenne indiquant si une somme de contrôle CRC de l'en-tête est calculée. Notez que le programme gzip n'utilise pas et n'autorise pas de CRC sur l'en-tête.
filename
Le nom du fichier qui contenait les données non compressées. Il ne doit pas contenir de séparateurs de répertoire et doit être assaini avant utilisation lors de la décompression avec file tail.
os
Le champ code du type de système d'exploitation de l'en-tête (s'il n'est pas la valeur “unknown”). Voir RFC 1952 pour la signification de ces codes. Lors de la compression, si ce champ est absent, il sera défini sur la valeur “unknown”.
size
La taille des données non compressées. Ceci est ignoré lors de la compression ; la taille des données compressées dépend de la quantité de données fournie au moteur de compression.
time
Le champ temps de l'en-tête s'il est non nul, attendu comme étant le moment où le fichier nommé par le champ filename a été modifié. Convient pour être utilisé avec clock format. Lors de la création, la bonne valeur à utiliser est celle de clock seconds ou file mtime.
type
Le type des données non compressées (soit binary, soit text) si connu.

NOTES PORTABILITE

Ces fonctions échoueront gracieusement si Tcl n'est pas lié à la bibliothèque zlib.
