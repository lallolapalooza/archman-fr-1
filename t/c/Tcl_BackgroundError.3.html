Tcl_BackgroundError(3) Procédures de la bibliothèque Tcl Tcl_BackgroundError(3)

NOM

Tcl_BackgroundException, Tcl_BackgroundError - signaler une exception Tcl survenue lors d'un traitement en arrière-plan

SYNTAXE

#include <tcl.h>

Tcl_BackgroundException(interp, code)

Tcl_BackgroundError(interp)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur dans lequel l'exception est survenue.
int code (in)
Le code de retour exceptionnel à signaler.

DESCRIPTION

Cette procédure est généralement appelée lorsqu'une exception Tcl (tout code de retour autre que TCL_OK) survient lors d'un “traitement en arrière-plan” tel que l'exécution d'un gestionnaire d'événements. Lorsque une telle exception survient, la condition est signalée à Tcl ou à un widget ou à un autre code C, et il n'y a généralement aucun moyen évident pour ce code de signaler l'exception à l'utilisateur. Dans ces cas, le code appelle Tcl_BackgroundException avec un argument interp identifiant l'interpréteur dans lequel l'exception est survenue, et un argument code contenant la valeur du code de retour de l'exception. L'état de l'interpréteur, y compris tout message d'erreur dans le résultat de l'interpréteur, et les valeurs de toutes les entrées du dictionnaire d'options de retour, sont capturés et sauvegardés. Tcl_BackgroundException organise ensuite la boucle d'événements pour invoquer à un moment ultérieur la commande enregistrée dans cet interpréteur pour gérer les erreurs d'arrière-plan via la commande interp bgerror, en passant les valeurs capturées comme arguments. La commande gestionnaire enregistrée est censée signaler l'exception d'une manière spécifique à l'application. La commande gestionnaire reçoit deux arguments, le résultat de l'interpréteur, et les options de retour de l'interpréteur au moment où l'erreur s'est produite. Si l'application n'enregistre aucune commande gestionnaire, la commande gestionnaire par défaut tentera d'appeler bgerror pour signaler l'erreur. Si une condition d'erreur survient lors de l'appel de la commande gestionnaire, alors Tcl_BackgroundException signale elle-même l'erreur en affichant un message sur le fichier d'erreur standard.

Tcl_BackgroundException n'appelle pas la commande gestionnaire immédiatement car cela pourrait potentiellement interférer avec les scripts en cours au moment où l'erreur s'est produite. Au lieu de cela, elle appelle la commande gestionnaire plus tard sous forme de rappel inactif (idle callback).

Il est possible que de nombreuses exceptions d'arrière-plan s'accumulent avant que la commande gestionnaire ne soit appelée. Lorsque cela se produit, chacune des exceptions est traitée dans l'ordre. Cependant, si la commande gestionnaire renvoie une exception de type break, alors tous les rapports d'erreurs restants pour l'interpréteur sont ignorés.

La routine Tcl_BackgroundError est une interface plus ancienne et plus simple, utile lorsque le code d'exception signalé est TCL_ERROR. Elle est équivalente à :

Tcl_BackgroundException(interp, TCL_ERROR);

MOTS-CLÉS

arrière-plan, bgerror, erreur, interp
