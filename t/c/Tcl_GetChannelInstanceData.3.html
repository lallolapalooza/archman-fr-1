ARGUMENTS

const Tcl_ChannelType *typePtr (in)
Pointe vers une structure contenant les points d'accès aux fonctions qui peuvent être appelées pour effectuer des opérations d'entrée/sortie sur le canal.
const char *channelName (in)
Le nom du canal, par exemple, file3 ; il ne doit pas être utilisé par un autre canal. Il peut être NULL, auquel cas le canal est créé sans nom. Si le canal créé est affecté à l'un des canaux standard (stdin, stdout ou stderr), le nom affecté au canal sera le nom du canal standard.
ClientData instanceData (in)
Une valeur arbitraire d'un mot à associer à ce canal. Cette valeur est transmise aux fonctions dans typePtr lorsqu'elles sont appelées.
int mask (in)
OR de TCL_READABLE et TCL_WRITABLE pour indiquer si le canal est lisible et écrivable.
Tcl_Channel channel (in)
Le canal sur lequel opérer.
int direction (in)
TCL_READABLE signifie que le handle d'entrée est souhaité ; TCL_WRITABLE signifie que le handle de sortie est souhaité.
ClientData *handlePtr (out)
Le pointeur où le handle souhaité du système d'exploitation doit être stocké.
int size (in)
La quantité en octets de tampons à allouer sur ce canal.
int mask (in)
OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION indiquant les événements qui se sont produits sur ce canal.
Tcl_Interp *interp (in)
L'interpréteur actuel. (Peut être NULL)
const char *optionName (in)
Nom de l'option invalide.
const char *optionList (in)
Une liste d'options spécifiques (mots séparés par des espaces, sans le signe moins) à ajouter à la liste d'options standard. Peut être NULL uniquement pour les messages d'erreur standard.

DESCRIPTION

Tcl utilise une architecture de canaux à deux couches. Elle offre une couche de haut niveau pour permettre aux programmes C et Tcl d'effectuer des entrées et sorties en utilisant les mêmes API pour divers fichiers, périphériques, sockets, etc. Les API C générales sont décrites dans la page de manuel de Tcl_OpenFileChannel.

La couche inférieure fournit des pilotes de canal spécifiques pour chaque type de périphérique pris en charge sur chaque plateforme. Ce manuel décrit les API C qui communiquent entre la couche de haut niveau et les pilotes de canal spécifiques. Il explique également comment de nouveaux types de canaux peuvent être ajoutés en implémentant de nouveaux pilotes de canal.

Les pilotes de canal se composent de plusieurs composants : Premièrement, chaque pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers les fonctions qui implémentent les opérations utilisées par la couche de haut niveau pour communiquer avec le pilote de canal. La structure Tcl_ChannelType et les fonctions auxquelles elle fait référence sont décrites dans la section TCL_CHANNELTYPE, ci-dessous.

Deuxièmement, les pilotes de canal fournissent généralement une commande Tcl pour créer des instances de ce type de canal. Par exemple, la commande Tcl open crée des canaux qui utilisent les pilotes de canal de fichier et de commande, et la commande Tcl socket crée des canaux qui utilisent les protocoles réseau TCP.

Troisièmement, un pilote de canal fournit facultativement une fonction C pour créer des instances de ce type de canal. Par exemple, Tcl_OpenFileChannel ouvre un canal qui utilise le pilote de canal de fichier, et Tcl_OpenTcpClient ouvre un canal qui utilise le protocole réseau TCP. Ces fonctions de création utilisent généralement Tcl_CreateChannel en interne pour ouvrir le canal.

Pour ajouter un nouveau type de canal, vous devez implémenter une API C ou une commande Tcl qui ouvre un canal en appelant Tcl_CreateChannel. Lorsque votre pilote appelle Tcl_CreateChannel, il transmet un Tcl_ChannelType qui décrit les fonctions d'E/S de votre pilote. La couche de haut niveau invoque ensuite les fonctions référencées dans cette structure pour effectuer des opérations sur le canal.

Tcl_CreateChannel ouvre un nouveau canal et lui associe typePtr et instanceData. Le canal est ouvert dans le mode indiqué par mask. Pour une discussion sur les pilotes de canal, leurs opérations et la structure Tcl_ChannelType, voir la section TCL_CHANNELTYPE, ci-dessous.

Tcl_CreateChannel interagit avec le code qui gère les canaux standard. Une fois qu'un canal standard a été initialisé par un appel à Tcl_GetStdChannel ou un appel à Tcl_SetStdChannel, la fermeture de ce canal amènera le prochain appel à Tcl_CreateChannel à faire de ce nouveau canal un canal standard également. Voir Tcl_StandardChannels pour un aperçu des canaux standard et du comportement de la bibliothèque Tcl à leur égard.

Tcl_GetChannelInstanceData renvoie les données d'instance associées au canal dans channel. C'est la même chose que l'argument instanceData dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelType renvoie un pointeur vers la structure Tcl_ChannelType utilisée par le canal dans l'argument channel. C'est la même chose que l'argument typePtr dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelName renvoie une chaîne contenant le nom associé au canal, ou NULL si l'argument channelName de Tcl_CreateChannel était NULL.

Tcl_GetChannelHandle place le handle du système d'exploitation associé à channel pour la direction donnée dans handlePtr.

EXEMPLE

L'exemple suivant montre comment utiliser Tcl_CreateChannel pour créer un canal de fichier :

int main() {
    Tcl_Channel *channel = Tcl_CreateChannel("file3", NULL, NULL, 0);
    int size = 1024;
    Tcl_SetChannelBufferSize(channel, size);
    ...
}

TCL_CHANNELTYPE

Un pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers des fonctions implémentant les diverses opérations sur un canal ; ces opérations sont appelées selon les besoins par la couche générique. La structure a été versionnée à partir de Tcl 8.3.2/8.4 pour corriger un problème avec les pilotes de canaux bloqués. Voir la section OLD CHANNEL TYPES pour les détails sur l'ancienne structure.

La structure Tcl_ChannelType contient les champs suivants :

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Il n'est pas nécessaire de fournir des implémentations pour toutes les opérations de canal. Celles qui ne sont pas nécessaires peuvent être définies à NULL dans la structure : blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc, et close2Proc, ainsi que flushProc, handlerProc, threadActionProc, et truncateProc. Les autres fonctions qui ne peuvent pas être implémentées de manière significative doivent retourner EINVAL lorsqu'elles sont appelées, pour indiquer que les opérations qu'elles représentent ne sont pas disponibles. Il convient également de noter que wideSeekProc peut être NULL si seekProc ne l'est pas.

L'utilisateur ne doit utiliser que cette structure pour l'instanciation de Tcl_ChannelType. Lorsqu'il fait référence à des champs d'une structure Tcl_ChannelType, les fonctions suivantes doivent être utilisées pour obtenir les valeurs : Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc, ou Tcl_ChannelHandlerProc.

La modification des structures a été effectuée de manière à ce que les types de canaux standard soient binaires compatibles. Cependant, les types de canaux qui utilisent des canaux bloqués (c'est-à-dire TLS, Trf) ont de nouvelles versions pour correspondre au changement précédent, en raison de problèmes dans le code antérieur des canaux bloqués.

TYPENAME

Le champ typeName contient une chaîne terminée par null qui identifie le type de périphérique implémenté par ce pilote, par exemple, file ou socket.

Cette valeur peut être obtenue avec Tcl_ChannelName, qui renvoie un pointeur vers la chaîne.

VERSION

Le champ version doit être défini à la version de la structure requise. TCL_CHANNEL_VERSION_2 est le minimum recommandé. TCL_CHANNEL_VERSION_3 doit être défini pour spécifier le membre wideSeekProc. TCL_CHANNEL_VERSION_4 doit être défini pour spécifier le membre threadActionProc (inclut wideSeekProc). TCL_CHANNEL_VERSION_5 doit être défini pour spécifier les membres truncateProc (inclut wideSeekProc et threadActionProc). Si aucun de ces éléments n'est défini, on suppose que ce Tcl_ChannelType a la structure d'origine. Voir OLD CHANNEL TYPES pour plus de détails. Bien que Tcl reconnaisse et fonctionne avec toutes ces structures, les canaux bloqués doivent être au moins TCL_CHANNEL_VERSION_2 pour fonctionner correctement.

Cette valeur peut être obtenue avec Tcl_ChannelVersion, qui renvoie l'une des valeurs TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 ou TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

Le champ blockModeProc contient l'adresse d'une fonction appelée par la couche générique pour définir le mode bloquant et non bloquant du périphérique. BlockModeProc doit correspondre au prototype suivant :

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

Le instanceData est le même que la valeur fournie à Tcl_CreateChannel lors de la création de ce canal. L'argument mode est soit TCL_MODE_BLOCKING, soit TCL_MODE_NONBLOCKING pour définir le périphérique en mode bloquant ou non bloquant. La fonction doit retourner zéro si l'opération a réussi, ou un code d'erreur POSIX non nul si l'opération a échoué.

Si l'opération réussit, la fonction peut modifier la valeur fournie instanceData pour enregistrer que le canal est entré en mode bloquant ou non bloquant et implémenter le comportement bloquant ou non bloquant. Pour certains types de périphériques, le comportement bloquant et non bloquant peut être implémenté par le système d'exploitation sous-jacent ; pour d'autres types de périphériques, le comportement doit être émulé dans le pilote de canal.

Cette valeur peut être obtenue avec Tcl_ChannelBlockModeProc, qui renvoie un pointeur vers la fonction.

Un pilote de canal qui ne fournit pas de blockModeProc doit être très prudent. Il doit indiquer exactement quel mode bloquant lui convient, et il doit également le documenter pour l'utilisateur afin que le mode bloquant du canal ne change pas vers une valeur inacceptable. Toute confusion ici peut conduire l'interpréteur à un blocage (étrange et difficile à trouver).

CLOSEPROC ET CLOSE2PROC

Le champ closeProc contient l'adresse d'une fonction appelée par la couche générique pour nettoyer les informations du pilote lorsque le canal est fermé. CloseProc doit correspondre au prototype suivant :

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

L'argument instanceData est le même que la valeur fournie à Tcl_CreateChannel lors de la création du canal. La fonction doit libérer toute mémoire conservée par le pilote de canal pour ce canal, et fermer les périphériques d'entrée et de sortie encapsulés par ce canal. Avant d'appeler cette fonction, toutes les données de sortie en attente seront envoyées au périphérique. Aucune autre opération du pilote ne sera appelée après l'appel à closeProc. Si l'opération de fermeture réussit, la fonction sera appelée.

INPUTPROC

Le champ inputProc contient l'adresse d'une fonction appelée par la couche générale pour lire des données depuis le périphérique ou le fichier et les stocker dans un tampon interne. InputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création du canal. L'argument buf pointe vers un tableau d'octets dans lequel les données d'entrée du périphérique seront stockées, et l'argument bufSize indique combien d'octets sont disponibles dans buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générale. Si une erreur se produit, la fonction doit définir cette variable à un code d'erreur POSIX identifiant l'erreur.

La fonction doit lire les données du périphérique encapsulé par le canal et les stocker dans buf. En cas de succès, elle doit retourner un entier non négatif indiquant le nombre d'octets lus depuis le périphérique et stockés dans buf. En cas d'erreur, elle doit retourner -1. Si une erreur se produit après la lecture de certaines données depuis le périphérique, ces données seront perdues.

Si inputProc peut déterminer que le périphérique a des données disponibles mais moins que ce qui est demandé par l'argument bufSize, la fonction doit essayer de lire uniquement ce qui est disponible et retourner sans bloquer. Si le périphérique n'a pas de données disponibles et que le canal est en mode non bloquant, la fonction doit retourner une erreur EAGAIN. Si le périphérique n'a pas de données disponibles et que le canal est en mode bloquant, la fonction doit bloquer pendant la plus courte durée possible jusqu'à ce qu'au moins un octet puisse être lu depuis le périphérique, puis retourner toutes les données qui peuvent être lues sans bloquer.

Cette valeur peut être récupérée avec Tcl_ChannelInputProc, qui retourne l'adresse de la fonction.

OUTPUTPROC

Le champ outputProc contient l'adresse d'une fonction appelée par la couche générale pour transférer des données du tampon interne vers le périphérique de sortie. OutputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création du canal. L'argument buf contient un tableau d'octets à écrire dans le périphérique, et l'argument toWrite indique combien d'octets seront écrits depuis l'argument buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générale pour retourner les valeurs de errno de la fonction. La fonction doit définir cette variable à un code d'erreur POSIX si une erreur se produit. Si le type de canal n'implémente pas le déplacement de position, la fonction doit définir le code d'erreur EINVAL.

La fonction doit écrire les données dans buf dans le périphérique de sortie encapsulé par le canal. En cas de succès, elle doit retourner un entier non négatif indiquant le nombre d'octets écrits dans le périphérique de sortie. La valeur retournée est normalement la même que toWrite, mais peut être plus petite dans certains cas, comme lorsque l'opération de sortie est interrompue par un signal. Si une erreur se produit, la fonction doit retourner -1. En cas d'erreur, certaines données pourraient avoir été écrites dans le périphérique.

Si le canal est en mode non bloquant et que le périphérique de sortie ne peut absorber aucune donnée, la fonction doit retourner -1 avec une erreur EAGAIN sans écrire de données.

Cette valeur peut être récupérée avec Tcl_ChannelOutputProc, qui retourne l'adresse de la fonction.

SEEKPROC ET WIDESEEKPROC

Le champ seekProc contient l'adresse d'une fonction appelée par la couche générale pour déplacer le point d'accès auquel les opérations d'entrée ou de sortie ultérieures seront appliquées. SeekProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

L'argument instanceData est la même valeur que celle donnée à Tcl_CreateChannel lors de la création de ce canal. Offset et seekMode ont la même signification que dans la fonction Tcl_Seek (mentionnée dans le manuel de Tcl_OpenFileChannel).

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générale pour retourner les valeurs de errno de la fonction. La fonction doit définir cette variable à un code d'erreur POSIX si une erreur se produit. Si le type de canal n'implémente pas le déplacement de position, la fonction doit définir le code d'erreur EINVAL.

La valeur retournée est le nouveau point d'accès ou -1 en cas d'erreur. Si une erreur se produit, la fonction ne doit pas déplacer le point d'accès.

Si un seekProc non nul existe, le champ wideSeekProc peut contenir l'adresse d'une fonction alternative qui gère les décalages de position (c'est-à-dire supérieurs à 32 bits), permettant le déplacement dans des fichiers de plus de 2 Go. La fonction wideSeekProc est appelée de préférence à seekProc, mais les deux doivent être définis si wideSeekProc est défini. WideSeekProc doit correspondre au prototype suivant :

typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

Les arguments et les valeurs retournées sont les mêmes que pour seekProc, à l'exception du type de décalage et du type de retour qui sont différents.

Le champ seekProc peut être récupéré avec Tcl_ChannelSeekProc, qui retourne l'adresse de la fonction, et le champ wideSeekProc peut être récupéré avec Tcl_ChannelWideSeekProc.

SETOPTIONPROC

Le champ setOptionProc contient l'adresse d'une fonction appelée par la couche générale pour définir une option spécifique au type de canal sur un canal. setOptionProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

optionName est le nom d'une option à définir, et newValue est la nouvelle valeur pour cette option, sous forme de chaîne. L'instanceData est la même valeur que celle donnée à Tcl_CreateChannel lors de la création de ce canal. La fonction doit effectuer l'action spécifique pour implémenter la nouvelle valeur de l'option.

Certaines options sont gérées par le code général et cette fonction n'est jamais appelée pour les définir, par exemple -blockmode. D'autres options sont spécifiques à chaque type de canal et la fonction setOptionProc du pilote du canal est appelée pour les implémenter. Le champ setOptionProc peut être NULL, indiquant que ce type de canal ne prend pas en charge les options spécifiques.

Si la valeur de l'option est modifiée avec succès à la nouvelle valeur, la fonction retourne TCL_OK. Elle doit appeler Tcl_BadChannelOption, qui retourne TCL_ERROR si le optionName n'est pas reconnu. Si newValue spécifie une valeur non prise en charge ou si une erreur se produit lors d'un appel système, la fonction doit stocker un message d'erreur dans le résultat de interp si interp n'est pas NULL. La fonction doit également appeler Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

Cette valeur peut être récupérée avec Tcl_ChannelSetOptionProc, qui retourne l'adresse de la fonction.

GETOPTIONPROC

Le champ getOptionProc contient l'adresse d'une fonction appelée par la couche générale pour obtenir la valeur d'une option spécifique au type de canal sur un canal. getOptionProc doit correspondre au prototype suivant :

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        Tcl_DString *optionValue);

OptionName est le nom d'une option prise en charge par ce type de canal. Si le nom de l'option n'est pas NULL, la fonction stocke sa valeur actuelle, sous forme de chaîne, dans la chaîne dynamique Tcl optionValue. Si optionName est NULL, la fonction stocke dans optionValue une liste alternative de toutes les options prises en charge et de leurs valeurs actuelles. En cas de succès, la fonction retourne TCL_OK. Elle doit appeler Tcl_BadChannelOption, qui retourne TCL_ERROR si le optionName n'est pas reconnu. Si newValue spécifie une valeur non prise en charge ou si une erreur se produit lors d'un appel système, la fonction doit stocker un message d'erreur dans le résultat de interp si interp n'est pas NULL. La fonction doit également appeler Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

Cette valeur peut être récupérée avec Tcl_ChannelGetOptionProc, qui retourne l'adresse de la fonction.

optionName n'est pas reconnue. Si une erreur d'appel système se produit, la fonction doit laisser un message d'erreur dans le résultat de interp si interp n'est pas NULL. La fonction doit également appeler Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

Certaines options sont gérées par le code générique et cette fonction n'est jamais appelée pour récupérer leur valeur, par exemple -blockmode. D'autres options sont spécifiques à chaque type de canal et la procédure getOptionProc du pilote de canal sera appelée pour les implémenter. Le champ getOptionProc peut être NULL, ce qui indique que ce type de canal ne prend pas en charge d'options spécifiques au type.

Cette valeur peut être récupérée avec Tcl_ChannelGetOptionProc, qui renvoie un pointeur vers la fonction.

WATCHPROC

Le champ watchProc contient l'adresse d'une fonction appelée par la couche générique pour initialiser le mécanisme de notification d'événements afin de signaler les événements intéressants sur ce canal. WatchProc doit correspondre au prototype suivant :

typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. L'argument mask est une combinaison OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION ; il indique les événements que l'appelant souhaite signaler sur ce canal.

La fonction doit initialiser les mécanismes spécifiques au type de périphérique pour signaler lorsqu'un événement d'intérêt est présent sur le canal. Lorsque un ou plusieurs des événements désignés se produisent sur le canal, le pilote de canal est responsable d'appeler Tcl_NotifyChannel pour informer le module générique de canal. Le pilote doit veiller à ne pas affamer d'autres pilotes de canal ou sources de rappels en appelant Tcl_NotifyChannel trop fréquemment. L'équité peut être assurée en utilisant la file d'attente d'événements Tcl pour permettre à l'événement du canal d'être planifié en séquence avec d'autres événements. Voir la description de Tcl_QueueEvent pour plus de détails sur la façon de mettre un événement en file d'attente.

Cette valeur peut être récupérée avec Tcl_ChannelWatchProc, qui renvoie un pointeur vers la fonction.

GETHANDLEPROC

Le champ getHandleProc contient l'adresse d'une fonction appelée par la couche générique pour récupérer un handle spécifique au périphérique du canal. GetHandleProc doit correspondre au prototype suivant :

typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. L'argument direction est soit TCL_READABLE pour récupérer le handle utilisé pour l'entrée, soit TCL_WRITABLE pour récupérer le handle utilisé pour la sortie.

Si l'implémentation du canal a des handles spécifiques au périphérique, la fonction doit récupérer le handle approprié associé au canal, conformément à l'argument direction. Le handle doit être stocké à l'emplacement indiqué par handlePtr, et TCL_OK doit être renvoyé. Si le canal n'est pas ouvert pour la direction spécifiée, ou si l'implémentation du canal n'utilise pas de handles de périphérique, la fonction doit renvoyer TCL_ERROR.

Cette valeur peut être récupérée avec Tcl_ChannelGetHandleProc, qui renvoie un pointeur vers la fonction.

FLUSHPROC

Le champ flushProc est actuellement réservé pour une utilisation future. Il doit être défini à NULL. FlushProc doit correspondre au prototype suivant :

typedef int Tcl_DriverFlushProc(
        ClientData instanceData);

Cette valeur peut être récupérée avec Tcl_ChannelFlushProc, qui renvoie un pointeur vers la fonction.

HANDLERPROC

Le champ handlerProc contient l'adresse d'une fonction appelée par la couche générique pour notifier le canal qu'un événement s'est produit. Il doit être défini pour les pilotes de canaux empilés qui souhaitent être notifiés des événements se produisant sur le canal sous-jacent (empilé). HandlerProc doit correspondre au prototype suivant :

typedef int Tcl_DriverHandlerProc(
        ClientData instanceData,
        int interestMask);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. Le interestMask est une combinaison OR de TCL_READABLE ou TCL_WRITABLE ; il indique quel type d'événement s'est produit sur ce canal.

Cette valeur peut être récupérée avec Tcl_ChannelHandlerProc, qui renvoie un pointeur vers la fonction.

THREADACTIONPROC

Le champ threadActionProc contient l'adresse de la fonction appelée par la couche générique lorsqu'un canal est créé, fermé ou sur le point de passer à un autre thread, c'est-à-dire chaque fois que l'état du pilote spécifique au thread pourrait avoir besoin d'être initialisé ou mis à jour. Il peut être NULL. L'action TCL_CHANNEL_THREAD_REMOVE est utilisée pour notifier le pilote qu'il doit mettre à jour ou supprimer toute donnée spécifique au thread qu'il pourrait maintenir pour le canal.

L'action TCL_CHANNEL_THREAD_INSERT est utilisée pour notifier le pilote qu'il doit mettre à jour ou initialiser toute donnée spécifique au thread qu'il pourrait maintenir en utilisant le thread appelant comme associé. Voir Tcl_CutChannel et Tcl_SpliceChannel pour plus de détails.

typedef void Tcl_DriverThreadActionProc(
        ClientData instanceData,
        int action);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal.

Ces valeurs peuvent être récupérées avec Tcl_ChannelThreadActionProc, qui renvoie un pointeur vers la fonction.

TRUNCATEPROC

Le champ truncateProc contient l'adresse de la fonction appelée par la couche générique lorsqu'un canal est tronqué à une certaine longueur. Il peut être NULL.

typedef int Tcl_DriverTruncateProc(
        ClientData instanceData,
        Tcl_WideInt length);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal, et length est la nouvelle longueur du fichier sous-jacent, qui ne doit pas être négative. Le résultat doit être 0 en cas de succès ou un code errno (adapté à l'utilisation avec Tcl_SetErrno) en cas d'échec.

Ces valeurs peuvent être récupérées avec Tcl_ChannelTruncateProc, qui renvoie un pointeur vers la fonction.

TCL_BADCHANNELOPTION

Cette procédure génère un message d'erreur « option incorrecte » dans un interpréteur (optionnel). Elle est utilisée par les pilotes de canaux lorsqu'une option de définition/obtention invalide est demandée. Son but est de concaténer la liste générique des options aux options spécifiques et de factoriser la chaîne de message d'erreur des options génériques.

Elle renvoie toujours TCL_ERROR

Un message d'erreur est généré dans la valeur du résultat d'interp pour indiquer qu'une commande a été invoquée avec une mauvaise option. Le message a la forme

    mauvaise option "blah" : devrait être l'une des
    <...options génériques...>+<...options spécifiques...>
ainsi, par exemple, vous obtenez : 
    mauvaise option "-blah" : devrait être l'une des -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, ou -sockname
lorsqu'elle est appelée avec optionList égale à « peername sockname »

“blah” est l'argument optionName et « <options spécifiques> » est une liste d'options spécifiques séparées par des espaces. La fonction prend soin d'insérer des signes moins devant chaque option, des virgules après, et un « ou » avant la dernière option.

ANCIENS TYPES DE CANAUX

La structure Tcl_ChannelType originale (8.3.1 et versions antérieures) contient les champs suivants :

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
} Tcl_ChannelType;

Il est toujours possible de créer des canaux avec la structure ci-dessus. Le code interne du canal déterminera la version. Il est impératif d'utiliser la nouvelle structure Tcl_ChannelType si vous créez un pilote de canal empilé, en raison de problèmes avec l'implémentation précédente des canaux empilés (dans 8.2.0 à 8.3.1).

Avant la version 8.4.0 (c'est-à-dire lors des dernières versions de 8.3 et du début du cycle de développement de 8.4), la structure Tcl_ChannelType contenait les champs suivants :

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_ChannelTypeVersion version;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Lorsque la structure ci-dessus est enregistrée en tant que type de canal, le champ version doit toujours être TCL_CHANNEL_VERSION_2.
