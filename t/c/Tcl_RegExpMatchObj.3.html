Tcl_RegExpMatch(3) Procédures de la bibliothèque Tcl Tcl_RegExpMatch(3)

NOM

Tcl_RegExpMatch, Tcl_RegExpCompile, Tcl_RegExpExec, Tcl_RegExpRange, Tcl_GetRegExpFromObj, Tcl_RegExpMatchObj, Tcl_RegExpExecObj, Tcl_RegExpGetInfo - Correspondance de motifs avec expressions régulières

SYNOPSIS

#include <tcl.h>

int
Tcl_RegExpMatchObj(interp, textObj, patObj)

int
Tcl_RegExpMatch(interp, text, pattern)

Tcl_RegExp
Tcl_RegExpCompile(interp, pattern)

int
Tcl_RegExpExec(interp, regexp, text, start)

void
Tcl_RegExpRange(regexp, index, startPtr, endPtr)

Tcl_RegExp
Tcl_GetRegExpFromObj(interp, patObj, cflags)

int
Tcl_RegExpExecObj(interp, regexp, textObj, offset, nmatches, eflags)

void
Tcl_RegExpGetInfo(regexp, infoPtr)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur Tcl à utiliser pour le rapport d'erreurs. L'interpréteur peut être NULL si aucun rapport d'erreur n'est souhaité.
Tcl_Obj *textObj (in/out)
Référence à la valeur à partir de laquelle obtenir le texte à rechercher. La représentation interne de la valeur peut être convertie dans un format qui peut être efficacement recherché.
Tcl_Obj *patObj (in/out)
Référence à la valeur à partir de laquelle obtenir une expression régulière. L'expression régulière compilée est mise en cache dans la valeur.
const char *text (in)
Texte dans lequel rechercher une correspondance avec une expression régulière.
const char *pattern (in)
Chaîne sous forme de motif d'expression régulière.
Tcl_RegExp regexp (in)
Expression régulière compilée. Doit avoir été retournée précédemment par Tcl_GetRegExpFromObj ou Tcl_RegExpCompile.
const char *start (in)
Si text n'est qu'une partie d'une autre chaîne, cet argument identifie le début de la chaîne plus grande. S'il n'est pas identique à text, alors aucun “^” ne sera autorisé.
int index (in)
Spécifie quelle plage est souhaitée : 0 signifie la plage de la correspondance entière, 1 ou plus signifie la plage qui a correspondu à une sous-expression entre parenthèses.
const char **startPtr (out)
L'adresse du premier caractère de la plage y est stockée, ou NULL s'il n'y a pas de telle plage.
const char **endPtr (out)
L'adresse du caractère juste après le dernier de la plage y est stockée, ou NULL s'il n'y a pas de telle plage.
int cflags (in)
Combinaison OR des drapeaux de compilation TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, TCL_REG_EXPANDED, TCL_REG_QUOTE, TCL_REG_NOCASE, TCL_REG_NEWLINE, TCL_REG_NLSTOP, TCL_REG_NLANCH, TCL_REG_NOSUB, et TCL_REG_CANMATCH. Voir ci-dessous pour plus d'informations.
int offset (in)
Le décalage de caractère dans le texte où la correspondance doit commencer. La valeur du décalage n'a aucun impact sur les correspondances ^. Ce comportement est contrôlé par eflags.
int nmatches (in)
Le nombre de sous-expressions correspondantes qui doivent être mémorisées pour une utilisation ultérieure. Si cette valeur est 0, aucune information de correspondance de sous-expression ne sera calculée. Si la valeur est -1, alors toutes les sous-expressions correspondantes seront mémorisées. Toute autre valeur sera considérée comme le nombre maximum de sous-expressions à mémoriser.
int eflags (in)
Combinaison OR des drapeaux d'exécution TCL_REG_NOTBOL et TCL_REG_NOTEOL. Voir ci-dessous pour plus d'informations.
Tcl_RegExpInfo *infoPtr (out)
L'adresse de l'emplacement où les informations sur une correspondance précédente doivent être stockées par Tcl_RegExpGetInfo.

DESCRIPTION

Tcl_RegExpMatch détermine si son argument pattern correspond à regexp, où regexp est interprété comme une expression régulière en utilisant les règles de la page de référence re_syntax. S'il y a une correspondance, Tcl_RegExpMatch retourne 1. S'il n'y a pas de correspondance, Tcl_RegExpMatch retourne 0. Si une erreur survient dans le processus de correspondance (par exemple, pattern n'est pas une expression régulière valide), alors Tcl_RegExpMatch retourne -1 et laisse un message d'erreur dans le résultat de l'interpréteur. Tcl_RegExpMatchObj est similaire à Tcl_RegExpMatch sauf qu'elle opère sur les valeurs Tcl textObj et patObj au lieu de chaînes UTF. Tcl_RegExpMatchObj est généralement plus efficace que Tcl_RegExpMatch, c'est donc l'interface préférée.

Tcl_RegExpCompile, Tcl_RegExpExec, et Tcl_RegExpRange fournissent un accès de plus bas niveau au moteur de correspondance d'expressions régulières. Tcl_RegExpCompile compile une chaîne d'expression régulière dans la forme interne utilisée pour une correspondance de motif efficace. La valeur de retour est un jeton pour cette forme compilée, qui peut être utilisé dans des appels ultérieurs à Tcl_RegExpExec ou Tcl_RegExpRange. Si une erreur survient lors de la compilation de l'expression régulière, Tcl_RegExpCompile retourne NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Note : la valeur de retour de Tcl_RegExpCompile n'est valide que jusqu'au prochain appel à Tcl_RegExpCompile ; il n'est pas sûr de conserver ces valeurs pendant de longues périodes.

Tcl_RegExpExec exécute le moteur de correspondance d'expressions régulières. Il retourne 1 si text contient une plage de caractères qui correspond à regexp, 0 s'il n'y a pas de correspondance trouvée, et -1 si une erreur survient. En cas d'erreur, Tcl_RegExpExec laisse un message d'erreur dans le résultat de l'interpréteur. Lors de la recherche dans une chaîne pour plusieurs correspondances d'un motif, il est important de distinguer le début de la chaîne d'origine et le début de la recherche actuelle. Par exemple, lors de la recherche de la deuxième occurrence d'une correspondance, l'argument text pourrait pointer vers le caractère juste après la première correspondance ; cependant, il est important que le moteur de correspondance sache qu'il ne s'agit pas du début de la chaîne entière, afin qu'il n'autorise pas les atomes “^” dans le motif à correspondre. L'argument start fournit cette information en pointant vers le début de la chaîne globale contenant text. Start sera inférieur ou égal à text ; s'il est inférieur à text, aucune correspondance ^ ne sera autorisée.

Tcl_RegExpRange peut être appelée après que Tcl_RegExpExec ait retourné ; elle fournit des informations détaillées sur les plages de la chaîne qui ont correspondu à quelles parties du motif. Tcl_RegExpRange retourne une paire de pointeurs dans *startPtr et *endPtr qui identifient une plage de caractères dans la chaîne source pour l'appel le plus récent à Tcl_RegExpExec. Index indique quelle parmi plusieurs plages est souhaitée : si index est 0, les informations sont retournées sur la plage globale de caractères qui a correspondu à l'ensemble du motif ; sinon, les informations sont retournées sur la plage de caractères qui a correspondu à la index-ième sous-expression entre parenthèses dans le motif. S'il n'y a pas de plage correspondant à index, NULL est stocké dans *startPtr et *endPtr.

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj, et Tcl_RegExpGetInfo sont des interfaces de valeur qui fournissent le contrôle le plus direct de la bibliothèque d'expressions régulières de Henry Spencer. Pour les utilisateurs qui ont besoin de modifier directement les options de compilation et d'exécution, il est recommandé d'utiliser ces interfaces au lieu d'appeler les fonctions internes d'expression régulière. Ces interfaces gèrent les détails des traductions UTF vers Unicode ainsi que l'amélioration des performances grâce à la mise en cache dans les valeurs de motif et de chaîne.

Tcl_GetRegExpFromObj tente de retourner une expression régulière compilée à partir de patObj. Si la valeur ne contient pas déjà une expression régulière compilée, elle tentera d'en créer une à partir de la chaîne dans la valeur et de l'assigner à la représentation interne de patObj. La valeur de retour de cette fonction est de type Tcl_RegExp. La valeur de retour est un jeton pour cette forme compilée, qui peut être utilisé dans des appels ultérieurs à Tcl_RegExpExecObj ou Tcl_RegExpGetInfo. Si une erreur survient lors de la compilation de l'expression régulière, Tcl_GetRegExpFromObj retourne NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Le jeton d'expression régulière peut être utilisé tant que la représentation interne de patObj fait référence à la forme compilée. L'argument cflags est un OR bit-à-bit de zéro ou plusieurs des drapeaux suivants qui contrôlent la compilation de patObj :

TCL_REG_ADVANCED
Active les extensions avancées de style Perl aux expressions régulières.
TCL_REG_EXTENDED
Active les extensions de style POSIX aux expressions régulières.
TCL_REG_BASIC
Utilise la syntaxe des expressions régulières de base POSIX.
TCL_REG_EXPANDED
Permet la mise en forme des expressions régulières avec des espaces blancs et des commentaires.
TCL_REG_QUOTE
Traite toutes les métacaractères comme des caractères littéraux.
TCL_REG_NOCASE
Ignore la casse lors de la correspondance.
TCL_REG_NEWLINE
Les caractères de nouvelle ligne sont traités comme des correspondances avec '.' et '^' et '$'.
TCL_REG_NLSTOP
Les caractères de nouvelle ligne arrêtent les correspondances avec '.' et l'ancre '$'.
TCL_REG_NLANCH
Les caractères de nouvelle ligne sont traités comme des correspondances avec les ancres '^' et '$'.
TCL_REG_NOSUB
Aucune information sur les sous-correspondances n'est calculée.
TCL_REG_CANMATCH
Retourne une valeur appropriée pour la fonction Tcl_RegExpExecObj.

Les fonctions Tcl_RegExpExecObj et Tcl_RegExpGetInfo sont utilisées pour effectuer une correspondance d'expression régulière et obtenir des informations sur la correspondance. Regexp est un jeton d'expression régulière compilée, obtenu à partir de Tcl_GetRegExpFromObj. TextObj est la valeur Tcl contenant le texte à faire correspondre. Offset spécifie le décalage de caractère dans textObj où commencer la correspondance. Les ancres '^' et '$' sont affectées par cet argument, conformément à eflags. Nmatches spécifie le nombre maximum de sous-expressions à mémoriser. Une valeur de -1 signifie toutes les sous-expressions. Eflags est une combinaison OR des drapeaux d'exécution suivants :

TCL_REG_NOTBOL
Le début du texte n'est pas considéré comme le début d'une ligne (c'est-à-dire que '^' ne correspondra pas).
TCL_REG_NOTEOL
La fin du texte n'est pas considérée comme la fin d'une ligne (c'est-à-dire que '$' ne correspondra pas).

Tcl_RegExpExecObj retourne 1 si une correspondance est trouvée, 0 sinon, et -1 en cas d'erreur. Tcl_RegExpGetInfo remplit la structure Tcl_RegExpInfo pointée par infoPtr avec des informations sur la correspondance la plus récente. La structure Tcl_RegExpInfo est définie comme suit :

typedef struct {
    int numSubexprs;
    const char **subexpr;
    int length;
    const char *extendTo;
} Tcl_RegExpInfo;

Les champs de la structure sont les suivants :

numSubexprs
Le nombre de sous-expressions qui ont été capturées par la correspondance.
subexpr
Un tableau de pointeurs de chaînes, où subexpr[i] pointe vers le début de la i-ème sous-expression capturée. subexpr[0] pointe vers le début de la correspondance entière.
length
La longueur de la correspondance entière en caractères.
extendTo
Pointeur vers le caractère qui suit la fin de la correspondance entière.

NAME

Tcl_RegExpMatchObj - Compile, execute, and retrieve information about regular expression matches

SYNOPSIS

#include <tcl.h>
int
Tcl_RegExpMatchObj(interp, regexp, objPtr, nmatches, matchesp, offset, eflags);
int
Tcl_RegExpExec(interp, regexp, string, nmatches, matchesp, offset, eflags);
int
Tcl_RegExpGetInfo(interp, regexp, infoPtr);
typedef struct Tcl_RegExpInfo {
    int nsubs;
    Tcl_RegExpIndices *matches;
    long extendStart;
} Tcl_RegExpInfo;
typedef struct Tcl_RegExpIndices {
    long start;
    long end;
} Tcl_RegExpIndices;

ARGUMENTS

Tcl_Interp *interp (out)
Intérprete de Tcl en el que se va a realizar la operación. Si se encuentra un error, el mensaje de error se dejará en el resultado del intérprete.
Tcl_Obj *regexp (in)
Objeto Tcl que contiene la expresión regular a compilar.
Tcl_Obj *objPtr (in)
Objeto Tcl que contiene la cadena a buscar.
const char *regexp (in)
Cadena de caracteres que contiene la expresión regular a compilar.
const char *string (in)
Cadena de caracteres que contiene la cadena a buscar.
int nmatches (in)
Máximo número de subexpresiones que se registrarán. Si es 0, no se registra información de subexpresiones. Si es -1, se registran todas las subexpresiones. Si es positivo, se registran ese número de subexpresiones.
Tcl_RegExpIndices *matchesp (out)
Puntero a un array donde se almacenarán los índices de las subexpresiones que coinciden. El tamaño del array debe ser nmatches + 1.
long offset (in)
Índice de carácter a partir del cual comenzar la búsqueda.
int eflags (in)
Flags que modifican el comportamiento de la coincidencia. Ver más abajo.
Tcl_RegExpInfo *infoPtr (out)
Puntero a una estructura donde se almacenará la información de la coincidencia.

DESCRIPTION

Las funciones Tcl_RegExpMatchObj y Tcl_RegExpExec realizan coincidencias de expresiones regulares. Tcl_RegExpMatchObj opera sobre objetos Tcl, mientras que Tcl_RegExpExec opera sobre cadenas de caracteres C. Ambas funciones compilan la expresión regular y luego la ejecutan en la cadena o en el objeto de cadena especificado. La expresión regular se compila utilizando una combinación de flags que se pasan en el argumento eflags, que es una OR a nivel de bits de cero o más de las siguientes constantes:

TCL_REG_ADVANCED
Compilar expresiones regulares avanzadas (“ARE”s). Este modo corresponde a la sintaxis normal de expresiones regulares aceptada por los comandos Tcl regexp y regsub.
TCL_REG_EXTENDED
Compilar expresiones regulares extendidas (“ERE”s). Este modo corresponde a la sintaxis de expresiones regulares reconocida por Tcl 8.0 y versiones anteriores.
TCL_REG_BASIC
Compilar expresiones regulares básicas (“BRE”s). Este modo corresponde a la sintaxis de expresiones regulares reconocida por utilidades de Unix comunes como sed y grep. Esto es el modo predeterminado si no se especifican ningún parámetro.
TCL_REG_EXPANDED
Compilar la expresión regular (básica, extendida o avanzada) utilizando una sintaxis expandida que permite comentarios y espacios en blanco. Este modo ignora espacios en blanco no salidos de paréntesis y comentarios de tipo #-a-fin-de-línea.
TCL_REG_QUOTE
Compilar una cadena literal, tratando todos los caracteres como caracteres ordinarios.
TCL_REG_NOCASE
Compilar para que ignore diferencias de mayúsculas/minúsculas.
TCL_REG_NEWLINE
Compilar para coincidencias sensibles a la nueva línea. Por defecto, la nueva línea es un carácter completamente ordinario con ningún significado especial en expresiones regulares o strings. Con este flag, el bloque [^] no coincide con una nueva línea, el . nunca coincide con una nueva línea, ^ coincide con un cadena vacía después de una nueva línea además de su función normal, y $ coincide con un cadena vacía antes de una nueva línea además de su función normal. REG_NEWLINE es el OR bit a bit de REG_NLSTOP y REG_NLANCH.
TCL_REG_NLSTOP
Compilar para coincidencias sensibles a la nueva línea, con el comportamiento de [^] bloque afectado, pero no el comportamiento de ^ y $ . En este modo, [^] bloque nunca coincide con una nueva línea.
TCL_REG_NLANCH
Compilar para coincidencias inversas sensibles a la nueva línea, con el comportamiento de ^ y $ (los anchos) afectados, pero no el comportamiento de [^] bloque y . En este modo, ^ coincide con un cadena vacía después de una nueva línea además de su función normal, y $ coincide con un cadena vacía antes de una nueva línea además de su función normal.
TCL_REG_NOSUB
Compilar para coincidencias que reporten solo éxito o fallo, no el contenido que se matche. Esto reduce la carga de compilación y puede mejorar el rendimiento. Las llamadas posteriores a Tcl_RegExpGetInfo o Tcl_RegExpRange no reportarán información de coincidencia.
TCL_REG_CANMATCH
Compilar para coincidencias que reporten la posibilidad de completar una coincidencia parcial dada más texto (ver más abajo).

Solo uno de TCL_REG_EXTENDED, TCL_REG_ADVANCED, TCL_REG_BASIC y TCL_REG_QUOTE puede especificarse.

Tcl_RegExpExecObj ejecuta el compilador de patrones de expresiones regulares. Devuelve 1 si objPtr contiene un rango de caracteres que coincidan con regexp, 0 si no se encuentra ninguna coincidencia, y -1 en caso de error. En caso de error, Tcl_RegExpExecObj deja un mensaje de error en el resultado del interpretador. El valor de nmatches indica a la máscara cuántas subexpresiones son de interés. Si nmatches es 0, no se registra información de coincidencia de subexpresiones, lo que puede permitir al máscara hacer varios optimizaciones. Si el valor es -1, entonces todas las subexpresiones en el patrón son registradas. Si el valor es un número positivo, solo se registran ese número de subexpresiones. La coincidencia comienza en el índice de carácter Unicode dado por offset. Diferente de Tcl_RegExpExec, el comportamiento de los anchos no se afecta por el valor de offset. En lugar de eso, el comportamiento de los anchos se controla explícitamente mediante el argumento eflags, que es una OR bit a bit de cero o más de los siguientes flags:

TCL_REG_NOTBOL
El carácter inicial no se trata como el principio de una línea o el principio de la cadena, así que ^ no coincidirá allí. Nota: este flag no tiene efecto en cómo \A se usa.
TCL_REG_NOTEOL
El último carácter en la cadena no se trata como el final de una línea o el final de la cadena, así que $ no coincidirá allí. Nota: este flag no tiene efecto en cómo \Z se usa.

Tcl_RegExpGetInfo recupera información sobre la última coincidencia realizada con una expresión regular específica regexp. El argumento infoPtr contiene un puntero a un estructura definida como sigue:

typedef struct Tcl_RegExpInfo {
    int nsubs;
    Tcl_RegExpIndices *matches;
    long extendStart;
} Tcl_RegExpInfo;

El campo nsubs contiene el número de subexpresiones paréntesis dentro de la expresión regular. Si se usó el flag TCL_REG_NOSUB, este valor será cero. El campo matches apunta a un array de nsubs+1 valores que indican los límites de cada subexpresión coincidida. El primer elemento del array se refiere a la coincidencia de la expresión regular entera, y los elementos siguientes se refieren a las subexpresiones paréntesis en el orden en que aparecen en el patrón. Cada elemento es una estructura definida como sigue:

typedef struct Tcl_RegExpIndices {
    long start;
    long end;
} Tcl_RegExpIndices;

Los valores de start y end son índices de carácter Unicode relativos a la ubicación de objPtr donde se inició la coincidencia. Los valores de start identifican el primer carácter de la subexpresión coincidida. Los valores de end identifican el primer carácter después de la subexpresión coincidida. Si la subexpresión coincidió con un cadena vacía, start y end serán iguales. Si la subexpresión no participó en la coincidencia, start y end serán seteados a -1.

El campo extendStart en Tcl_RegExpInfo se establece solo si se usó el flag TCL_REG_CANMATCH. Indica el primer carácter en la cadena donde podría haber una coincidencia. Si se encontró una coincidencia, este será el mismo que el principio de la coincidencia actual. Si no se encontró una coincidencia, indica la posición más temprana en la que podría haber una coincidencia si se agregara más texto a la cadena. Si no hay coincidencia posible incluso con más texto, este campo será seteado a -1.
