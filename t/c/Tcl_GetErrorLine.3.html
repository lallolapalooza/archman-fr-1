DESCRIPTION

Les routines Tcl_SetReturnOptions et Tcl_GetReturnOptions exposent les mêmes capacités que les commandes return et catch, respectivement, sous la forme d'une interface C.

Tcl_GetReturnOptions récupère le dictionnaire des options de retour d'un interpréteur après l'évaluation d'un script. Des routines comme Tcl_Eval sont appelées pour évaluer un script dans un interpréteur. Ces routines retournent un code de complétion entier. Elles laissent également dans l'interpréteur un résultat et un dictionnaire d'options de retour générés par l'évaluation du script. Tout comme Tcl_GetObjResult récupère le résultat, Tcl_GetReturnOptions récupère le dictionnaire des options de retour. Le code de complétion entier doit être passé comme argument code à Tcl_GetReturnOptions afin que toutes les options requises soient présentes dans le dictionnaire. Plus précisément, une valeur code de TCL_ERROR garantira que les entrées pour les clés -errorinfo, -errorcode, et -errorline apparaîtront dans le dictionnaire. De plus, les entrées pour les clés -code et -level seront ajustées si nécessaire pour correspondre à la valeur de code. Le (Tcl_Obj *) retourné par Tcl_GetReturnOptions pointe vers un Tcl_Obj non partagé avec un compteur de références de zéro. Le dictionnaire peut être modifié, soit en ajoutant, supprimant ou écrasant des entrées, sans avoir besoin de vérifier une valeur partagée. Comme pour tout Tcl_Obj avec un compteur de références de zéro, il appartient à l'appelant de prendre en charge sa suppression avec Tcl_DecrRefCount ou de faire référence à celui-ci via Tcl_IncrRefCount (ou l'une des nombreuses fonctions qui l'appellent, notamment Tcl_SetObjResult et Tcl_SetVar2Ex).

Une utilisation typique de Tcl_GetReturnOptions consiste à récupérer la trace de la pile lorsque l'évaluation d'un script retourne TCL_ERROR, comme suit :

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* Faire quelque chose avec stackTrace */
    Tcl_DecrRefCount(options);
}

Tcl_SetReturnOptions définit les options de retour de interp à options. Si options contient une valeur invalide pour une clé, TCL_ERROR sera retourné, et le résultat de l'interpréteur sera défini sur un message d'erreur approprié. Sinon, un code de complétion conforme aux clés -code et -level dans options sera retourné.

Par exemple, la commande return de Tcl elle-même pourrait être implémentée en termes de Tcl_SetReturnOptions comme suit :

if ((objc % 2) == 0) { /* argument de résultat explicite */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(Ce n'est pas vraiment implémenté de cette façon. Les privilèges d'accès internes permettent une alternative plus efficace qui s'intègre mieux avec le compilateur de bytecode.)

Notez qu'un Tcl_Obj nouvellement créé peut être passé comme argument options sans avoir besoin de gérer de comptage de références. Ceci est analogue à Tcl_SetObjResult.

Bien que Tcl_SetReturnOptions fournisse une interface générale pour définir n'importe quelle collection d'options de retour, il existe une poignée d'options de retour très fréquemment utilisées. Notamment, les options de retour -errorinfo et -errorcode doivent être correctement définies lorsque la procédure de commande d'une commande retourne TCL_ERROR. L'option de retour -errorline est également lue par les commandes qui évaluent des scripts et souhaitent fournir des informations détaillées sur la localisation des erreurs dans le texte de la trace de la pile qu'elles ajoutent à l'option -errorinfo. Tcl fournit plusieurs interfaces plus simples pour définir plus directement ces options de retour.

L'option -errorinfo contient une trace de la pile des opérations en cours lors d'une erreur, et est destinée à être lisible par l'homme. L'option -errorcode contient une liste Tcl d'éléments destinés à être lisibles par machine. Le premier élément de la valeur -errorcode identifie la classe d'erreur qui s'est produite (par exemple, POSIX signifie qu'une erreur s'est produite dans un appel système POSIX) et les éléments supplémentaires contiennent des informations supplémentaires qui dépendent de la classe. Voir l'entrée man sur la variable errorCode pour plus de détails sur les différents formats de l'option -errorcode utilisés par les commandes intégrées de Tcl.

La valeur de l'option -errorinfo est progressivement construite au fur et à mesure qu'une erreur remonte les opérations imbriquées. Chaque fois qu'un code d'erreur est retourné à Tcl_Eval, ou à l'une des routines qui effectuent l'évaluation de scripts, la procédure Tcl_AddErrorInfo est appelée pour ajouter un texte supplémentaire à la valeur -errorinfo décrivant la commande qui était en cours d'exécution lorsque l'erreur s'est produite. Au moment où l'erreur est entièrement renvoyée à l'application, elle contiendra une trace complète de l'activité en cours au moment où l'erreur s'est produite.

Il est parfois utile d'ajouter des informations supplémentaires à la valeur -errorinfo au-delà de ce qui peut être fourni automatiquement par les routines d'évaluation de script. Tcl_AddErrorInfo peut être utilisé à cet effet : son argument message est une chaîne supplémentaire à ajouter à l'option -errorinfo. Par exemple, lorsqu'une erreur survient pendant la commande source, la procédure Tcl_AddErrorInfo est appelée pour enregistrer le nom du fichier en cours de traitement et le numéro de ligne sur lequel l'erreur s'est produite.
