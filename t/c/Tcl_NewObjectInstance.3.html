ARGUMENTS

Tcl_Interp *interp (entrée/sortie)
Interpréteur qui fournit le contexte pour rechercher ou créer un objet, et dans lequel les messages d'erreur seront écrits en cas d'échec.
Tcl_Obj *objPtr (entrée)
Nom de l'objet à rechercher.
Tcl_Object object (entrée)
Référence à l'objet sur lequel opérer.
Tcl_Class class (entrée)
Référence à la classe sur laquelle opérer.
const char *name (entrée)
Nom de l'objet à créer, ou NULL s'il faut sélectionner un nouveau nom automatiquement.
const char *nsName (entrée)
Nom de l'espace de noms à créer pour l'usage privé de l'objet, ou NULL s'il faut sélectionner un nouveau nom automatiquement. L'espace de noms doit exister.
int objc (entrée)
Le nombre d'éléments dans le tableau objv.
Tcl_Obj *const *objv (entrée)
Arguments pour la commande de création de l'objet de la classe.
int skip (entrée)
Le nombre d'arguments dans le tableau d'arguments, objv, qui ne sont pas des arguments du constructeur. Cela permet de générer des messages d'erreur corrects, même avec des modèles d'appel complexes (par exemple, avec la commande next).

Le type des metadata qui sont définis avec Tcl_ClassSetMetadata ou récupérés avec Tcl_ClassGetMetadata.

Un élément de métadonnées à joindre à la classe, ou NULL pour supprimer les métadonnées associées à un metaTypePtr.
Tcl_ObjectMapMethodNameProc methodNameMapper (entrée)
Un pointeur vers une fonction qui est appelée pour ajuster le mappage des objets et des noms de méthodes aux implémentations, ou NULL lorsqu'aucun mappage de ce type n'est requis.

DESCRIPTION

Les objets sont des entités de type qui ont un ensemble d'opérations (« méthodes ») qui leur sont associées. Les classes sont des objets qui peuvent créer d'autres objets. Chaque classe peut être considérée comme un objet en soi ; le mode objet d'une classe peut être obtenu avec Tcl_GetClassAsObject, qui renvoie toujours l'objet lorsqu'elle est appliquée à une classe non détruite, et un objet peut être vu comme une classe avec l'aide de Tcl_GetObjectAsClass (qui renvoie la classe, ou NULL si l'objet n'est pas une classe). Pour rechercher une classe par son nom, la méthode correcte consiste à rechercher l'objet portant ce nom, puis à utiliser Tcl_GetObjectAsClass.

Chaque objet possède sa propre commande et son propre espace de noms associés. La commande peut être obtenue avec Tcl_GetObjectCommand, le nom de l'objet (et donc le nom de la commande) avec Tcl_GetObjectName, et l'espace de noms peut être obtenu avec Tcl_GetObjectNamespace. Note : l'objet référencé par Tcl_GetObjectName est une référence partagée. Vous pouvez également savoir si l'objet a été marqué pour suppression avec Tcl_ObjectDeleted (renvoie vrai si la suppression de l'objet a commencé) ; cela peut être utile lors du traitement des méthodes.

Les objets de classe sont créés avec Tcl_NewObjectInstance, qui crée un objet de n'importe quelle classe (et qui est appelé en interne par les deux méthodes create et new de la classe oo::class). Des paramètres lui sont passés, qui fournissent éventuellement le nom de l'objet et l'espace de noms à créer, et qui décrivent les arguments à passer au constructeur de la classe (le cas échéant). Le résultat de la fonction sera une référence à l'objet créé, ou NULL si la création a échoué (auquel cas un message d'erreur sera laissé dans le résultat de l'interpréteur). De plus, les objets peuvent être copiés en utilisant Tcl_CopyObjectInstance, qui crée une copie d'un objet sans exécuter aucun constructeur.

Note : la gestion de la durée de vie des objets est gérée en interne dans TclOO et n'utilise pas Tcl_Preserve. Il n'est pas sûr de placer un Tcl_Object dans une structure C ayant une durée de vie différente de celle de l'objet ; vous devriez utiliser le nom de la commande de l'objet (obtenu avec Tcl_GetObjectName), plutôt qu'un handle vers Tcl_Object. Il est sûr d'utiliser un handle vers Tcl_Object pendant la durée d'un appel de méthode sur cet objet ; les handles ne sont pas invalidés tant qu'il y a un appel en attente sur leur objet (même si la seule opération sûre garantie sur eux est Tcl_ObjectDeleted ; les autres opérations ne sont garanties que pour les objets non détruits).

MÉTADONNÉES D'OBJET ET DE CLASSE

Chaque objet et chaque classe peuvent avoir un ensemble arbitraire de métadonnées qui leur sont associées, que l'objet ou la classe n'interprète que ce qui est décrit dans une structure Tcl_ObjectMetadataType. Les métadonnées à joindre sont décrites par le type des métadonnées (fourni dans l'argument metaTypePtr) et un pointeur arbitraire (l'argument metadata) qui sont passés à Tcl_ObjectSetMetadata et Tcl_ClassSetMetadata, et une donnée spécifique de métadonnées peut être obtenue par Tcl_ObjectGetMetadata et Tcl_ClassGetMetadata. Si le paramètre metadata de Tcl_ObjectSetMetadata ou Tcl_ClassSetMetadata est NULL, les métadonnées seront supprimées si elles étaient attachées, et les résultats de Tcl_ObjectGetMetadata et Tcl_ClassGetMetadata seront NULL si le type de métadonnées demandé n'était pas attaché. Ce n'est pas une erreur de demander ou de supprimer des métadonnées qui n'étaient pas attachées.

STRUCTURE TCL_OBJECTMETADATATYPE

Le contenu de la structure Tcl_ObjectMetadataType est le suivant :

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

Le champ version permet une extension future de la structure et doit toujours être déclaré égal à TCL_OO_METADATA_VERSION_CURRENT. Le champ name fournit un nom lisible par l'homme pour le type et est réservé au débogage.

Le champ deleteProc fournit une fonction de type Tcl_ObjectMetadataDeleteProc qui est utilisée pour supprimer un élément de métadonnées, et est appelée lorsque les métadonnées associées à une classe ou un objet sont remplacées ou supprimées ; le champ ne doit pas être NULL.

Le champ cloneProc fournit une fonction utilisée pour copier un élément de métadonnées (utilisé lors de la création d'une copie d'un objet avec Tcl_CopyObjectInstance) ; s'il est NULL, les métadonnées seront copiées directement.

SIGNATURE DE FONCTION Tcl_ObjectMetadataDeleteProc

Les fonctions correspondant à cette signature sont utilisées pour supprimer les métadonnées associées à une classe ou un objet.

typedef void Tcl_ObjectMetadataDeleteProc(
    ClientData clientData);

Le paramètre clientData est la valeur des métadonnées qui doivent être libérées.

SIGNATURE DE FONCTION Tcl_CloneProc

Les fonctions correspondant à cette signature sont utilisées pour copier les métadonnées associées à un objet lors de la copie de cet objet.

typedef ClientData Tcl_CloneProc(
    ClientData clientData);

Le paramètre clientData est la valeur des métadonnées qui doivent être copiées. La fonction doit renvoyer une nouvelle valeur de métadonnées qui est une copie de la valeur d'origine, ou NULL si le clonage échoue.

VOIR AUSSI

Tcl_CreateClass(3), Tcl_Object(3)

Tcl_ObjectDeleteProc(
        ClientData metadata);

L'argument metadata donne l'adresse des métadonnées à supprimer.

SIGNATURE DE FONCTION TCL_CLONEPROC

Les fonctions correspondant à cette signature sont utilisées pour créer des copies de métadonnées associées à une classe ou à un objet.

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData srcMetadata,
        ClientData *dstMetadataPtr);

L'argument interp fournit un endroit pour écrire un message d'erreur si la tentative de clonage de l'objet échoue, auquel cas la procédure de clonage doit également retourner TCL_ERROR ; elle doit retourner TCL_OK sinon. L'argument srcMetadata donne l'adresse des métadonnées à cloner, et les métadonnées clonées doivent être écrites dans la variable pointée par dstMetadataPtr ; NULL doit être écrit si les métadonnées ne doivent pas être clonées mais que l'opération globale de copie de l'objet doit quand même réussir.

ASSOCIATION DES NOMS DE MÉTHODES D'OBJETS

Il est possible de contrôler, par objet, quelles méthodes sont appelées lorsqu'une méthode particulière est invoquée. Normalement, cela se fait en recherchant le nom de la méthode dans l'objet puis dans la hiérarchie des classes, mais un contrôle fin de la valeur exacte utilisée pour effectuer la recherche est offert par la capacité de définir une fonction de rappel de mapping de noms de méthodes via Tcl_ObjectSetMethodNameMapper (et son homologue d'introspection, Tcl_ObjectGetMethodNameMapper, qui retourne le mapper actuel). Le mapper actuel (s'il en existe un) est appelé immédiatement avant de rechercher la chaîne d'implémentations de méthodes à utiliser.

SIGNATURE DE FONCTION TCL_OBJECTMAPMETHODNAMEPROC

La fonction de rappel Tcl_ObjectMapMethodNameProc est définie comme suit :

typedef int Tcl_ObjectMapMethodNameProc(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class *startClsPtr,
        Tcl_Obj *methodNameObj);

Si le résultat est TCL_OK, le remappage est supposé avoir été effectué. Si le résultat est TCL_ERROR, un message d'erreur aura été laissé dans interp et l'appel de méthode échouera. Si le résultat est TCL_BREAK, les règles de recherche de noms de méthodes standard seront utilisées ; le comportement des autres codes de résultat est actuellement indéfini. Le paramètre object indique quel objet est traité. Le paramètre startClsPtr pointe vers une variable qui contient la première classe fournissant une définition dans la chaîne de méthodes à traiter, ou NULL si toute la chaîne doit être traitée (l'argument lui-même n'est jamais NULL) ; cette variable peut être mise à jour par la fonction de rappel. Le paramètre methodNameObj donne un objet non partagé contenant le nom de la méthode invoquée, tel que fourni par l'utilisateur ; cet objet peut être mis à jour par la fonction de rappel.

Method(3), oo::class(n), oo::copy(n), oo::define(n), oo::object(n)
