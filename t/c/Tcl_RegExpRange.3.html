ARGUMENTS

Tcl_Interp *interp (entree)
Interpréteur Tcl à utiliser pour signaler les erreurs. L'interpréteur peut être NULL si aucun signalement d'erreur n'est souhaité.
Tcl_Obj *textObj (entree/sortie)
Référence à la valeur à partir de laquelle obtenir le texte à rechercher. La représentation interne de la valeur peut être convertie dans une forme qui peut être efficacement recherchée.
Tcl_Obj *patObj (entree/sortie)
Référence à la valeur à partir de laquelle obtenir une expression régulière. L'expression régulière compilée est mise en cache dans la valeur.
const char *text (entree)
Texte dans lequel rechercher une correspondance avec une expression régulière.
const char *pattern (entree)
Chaîne sous forme de motif d'expression régulière.
Tcl_RegExp regexp (entree)
Expression régulière compilée. Doit avoir été retournée précédemment par Tcl_GetRegExpFromObj ou Tcl_RegExpCompile.
const char *start (entree)
Si text n'est qu'une partie d'une autre chaîne, cet argument identifie le début de la chaîne plus grande. S'il n'est pas identique à text, alors aucune correspondance “^” ne sera permise.
int index (entree)
Spécifie quelle plage est désirée : 0 signifie la plage de la correspondance entière, 1 ou plus signifie la plage qui a correspondu à une sous-expression entre parenthèses.
const char **startPtr (sortie)
L'adresse du premier caractère de la plage y est stockée, ou NULL s'il n'y a pas de telle plage.
const char **endPtr (sortie)
L'adresse du caractère juste après le dernier caractère de la plage y est stockée, ou NULL s'il n'y a pas de telle plage.
int cflags (entree)
Combinaison OR des drapeaux de compilation TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, TCL_REG_EXPANDED, TCL_REG_QUOTE, TCL_REG_NOCASE, TCL_REG_NEWLINE, TCL_REG_NLSTOP, TCL_REG_NLANCH, TCL_REG_NOSUB, et TCL_REG_CANMATCH. Voir ci-dessous pour plus d'informations.
int offset (entree)
Le décalage de caractère dans le texte où la recherche doit commencer. La valeur du décalage n'a aucun impact sur les correspondances ^. Ce comportement est contrôlé par eflags.
int nmatches (entree)
Le nombre de sous-expressions correspondantes qui doivent être mémorisées pour une utilisation ultérieure. Si cette valeur est 0, alors aucune information de correspondance de sous-expression ne sera calculée. Si la valeur est -1, alors toutes les sous-expressions correspondantes seront mémorisées. Toute autre valeur sera considérée comme le nombre maximum de sous-expressions à mémoriser.
int eflags (entree)
Combinaison OR de zéro ou plusieurs des drapeaux d'exécution TCL_REG_NOTBOL et TCL_REG_NOTEOL. Voir ci-dessous pour plus d'informations.
Tcl_RegExpInfo *infoPtr (sortie)
L'adresse de l'emplacement où les informations sur une correspondance précédente doivent être stockées par Tcl_RegExpGetInfo.

DESCRIPTION

Tcl_RegExpMatch détermine si son argument pattern correspond à regexp, où regexp est interprété comme une expression régulière selon les règles de la page de référence re_syntax. S'il y a une correspondance, Tcl_RegExpMatch retourne 1. S'il n'y a pas de correspondance, Tcl_RegExpMatch retourne 0. Si une erreur se produit lors du processus de correspondance (par exemple, pattern n'est pas une expression régulière valide), alors Tcl_RegExpMatch retourne -1 et laisse un message d'erreur dans le résultat de l'interpréteur. Tcl_RegExpMatchObj est similaire à Tcl_RegExpMatch, sauf qu'elle opère sur les valeurs Tcl textObj et patObj plutôt que sur des chaînes UTF. Tcl_RegExpMatchObj est généralement plus efficace que Tcl_RegExpMatch, c'est donc l'interface préférée.

Tcl_RegExpCompile, Tcl_RegExpExec et Tcl_RegExpRange fournissent un accès de plus bas niveau au moteur de correspondance de motifs d'expressions régulières. Tcl_RegExpCompile compile une chaîne d'expression régulière dans la forme interne utilisée pour une correspondance de motif efficace. La valeur de retour est un jeton pour cette forme compilée, qui peut être utilisé dans des appels ultérieurs à Tcl_RegExpExec ou Tcl_RegExpRange. Si une erreur se produit lors de la compilation de l'expression régulière, Tcl_RegExpCompile retourne NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Remarque : la valeur de retour de Tcl_RegExpCompile n'est valide que jusqu'au prochain appel à Tcl_RegExpCompile ; il n'est pas sûr de conserver ces valeurs pendant de longues périodes.

Tcl_RegExpExec exécute le moteur de correspondance de motifs d'expressions régulières. Il retourne 1 si text contient une plage de caractères qui correspond à regexp, 0 si aucune correspondance n'est trouvée, et -1 si une erreur se produit. En cas d'erreur, Tcl_RegExpExec laisse un message d'erreur dans le résultat de l'interpréteur. Lors de la recherche dans une chaîne de plusieurs correspondances d'un motif, il est important de distinguer le début de la chaîne originale du début de la recherche en cours. Par exemple, lors de la recherche de la deuxième occurrence d'une correspondance, l'argument text peut pointer vers le caractère juste après la première correspondance ; cependant, il est important que le moteur de correspondance sache que ce n'est pas le début de la chaîne entière, afin qu'il n'autorise pas les atomes “^” dans le motif à correspondre. L'argument start fournit cette information en pointant vers le début de la chaîne globale contenant text. Start sera inférieur ou égal à text ; s'il est inférieur à text, aucune correspondance ^ ne sera autorisée.

Tcl_RegExpRange peut être appelée après le retour de Tcl_RegExpExec ; elle fournit des informations détaillées sur les plages de la chaîne qui ont correspondu à quelles parties du motif. Tcl_RegExpRange retourne une paire de pointeurs dans *startPtr et *endPtr qui identifient une plage de caractères dans la chaîne source pour l'appel le plus récent à Tcl_RegExpExec. Index indique quelle plage parmi plusieurs est désirée : si index est 0, des informations sont retournées sur la plage globale de caractères qui a correspondu au motif entier ; sinon, des informations sont retournées sur la plage de caractères qui a correspondu à la sous-expression entre parenthèses index-ième dans le motif. S'il n'y a pas de plage correspondant à index, NULL est stocké dans *startPtr et *endPtr.

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj et Tcl_RegExpGetInfo sont des interfaces de valeur qui fournissent le contrôle le plus direct de la bibliothèque d'expressions régulières de Henry Spencer. Pour les utilisateurs qui ont besoin de modifier directement les options de compilation et d'exécution, il est recommandé d'utiliser ces interfaces plutôt que d'appeler les fonctions internes d'expressions régulières. Ces interfaces gèrent les détails des traductions UTF vers Unicode, ainsi que l'amélioration des performances grâce à la mise en cache dans les valeurs de motif et de chaîne.

Tcl_GetRegExpFromObj tente de retourner une expression régulière compilée à partir de patObj. Si la valeur ne contient pas déjà une expression régulière compilée, elle tentera d'en créer une à partir de la chaîne dans la valeur et de l'assigner à la représentation interne de patObj. La valeur de retour de cette fonction est de type Tcl_RegExp. La valeur de retour est un jeton pour cette forme compilée, qui peut être utilisé dans des appels ultérieurs à Tcl_RegExpExecObj ou Tcl_RegExpGetInfo. Si une erreur se produit lors de la compilation de l'expression régulière, Tcl_GetRegExpFromObj retourne NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Le jeton d'expression régulière peut être utilisé tant que la représentation interne de patObj fait référence à la forme compilée. L'argument cflags est un OR bit à bit de zéro ou plusieurs des drapeaux suivants qui contrôlent la compilation de patObj :

TCL_REG_ADVANCED
Utilise la syntaxe avancée d'expressions régulières, qui est un sur-ensemble de la syntaxe étendue. Le jeu complet de fonctionnalités avancées est décrit dans la page de manuel re_syntax.
TCL_REG_EXTENDED
Utilise la syntaxe étendue d'expressions régulières (la syntaxe par défaut des commandes Tcl `regexp` et `regsub`). Le jeu complet de fonctionnalités étendues est décrit dans la page de manuel re_syntax.
TCL_REG_BASIC
Utilise la syntaxe d'expressions régulières de base POSIX. C'est un sous-ensemble de la syntaxe étendue, et il est décrit dans la page de manuel re_syntax.
TCL_REG_EXPANDED
Le motif d'expression régulière est formaté en mode étendu. Les espaces blancs sont ignorés, sauf lorsqu'ils sont protégés par une barre oblique inverse ou qu'ils font partie d'une classe de caractères. Les lignes qui ne contiennent que des commentaires (commençant par”#” et se terminant par un retour à la ligne) sont ignorées. Cela permet d'écrire des expressions régulières complexes sur plusieurs lignes et de les rendre plus lisibles. Le mode étendu est souvent utilisé avec le mode non casse (TCL_REG_NOCASE) pour une meilleure lisibilité des motifs.
TCL_REG_QUOTE
Traite toutes les barres obliques inverses littéralement et quotes le motif d'expression régulière. Ceci est utile lorsque vous souhaitez faire correspondre un motif d'expression régulière littéralement, mais que vous ne voulez pas avoir à vous soucier de la mise en échappement de caractères spéciaux d'expression régulière tels que `*`, `+`, `?`, `(`, `)`, `[`, etc.
TCL_REG_NOCASE
Ignore la casse lors de la comparaison des caractères. Par exemple, `a` correspondra à `A` et vice versa. Ce drapeau est souvent utilisé en combinaison avec le mode étendu (TCL_REG_EXPANDED) pour une meilleure lisibilité des motifs.
TCL_REG_NEWLINE
Les caractères newline (`\n`) sont traités comme des caractères de fin de ligne, tout comme les autres caractères de fin de ligne. Par défaut, `\n` ne correspond qu'à `\n`, et non à d'autres caractères de fin de ligne. Ce drapeau modifie ce comportement afin que `\n` corresponde également aux caractères de fin de ligne, et qu'il soit également traité comme un caractère de fin de ligne dans les ancres `^` et `$`, sauf si les drapeaux TCL_REG_NLSTOP ou TCL_REG_NLANCH sont spécifiés.
TCL_REG_NLSTOP
Les caractères newline (`\n`) sont traités comme des caractères de fin de ligne. Si ce drapeau est activé, alors le caractère `.` ne correspond pas aux caractères newline. S'il est désactivé (et que TCL_REG_NEWLINE est activé), alors `.` correspond aux caractères newline.
TCL_REG_NLANCH
Les caractères newline (`\n`) sont traités comme des caractères de fin de ligne. Si ce drapeau est activé, alors les ancres `^` et `$` correspondent au début et à la fin de chaque ligne dans la chaîne, et pas seulement au début et à la fin de la chaîne entière. Si ce drapeau est désactivé (et que TCL_REG_NEWLINE est activé), alors `^` et `$` ne correspondent qu'au début et à la fin de la chaîne entière.
TCL_REG_NOSUB
Indique que les informations de sous-correspondance ne doivent pas être calculées. Cela peut considérablement accélérer l'exécution des expressions régulières lorsque les informations sur les sous-correspondances ne sont pas nécessaires.
TCL_REG_CANMATCH
Indique que le motif ne fait qu'une vérification de correspondance. La fonction Tcl_RegExpExecObj retournera 1 si le motif correspond à une partie du texte, et 0 dans le cas contraire. Les informations sur la partie correspondante du texte ne seront pas calculées. Cela peut être utilisé pour une vérification de motif plus rapide et plus efficace.

L'argument eflags est une combinaison OR bit à bit de zéro ou plusieurs des drapeaux suivants qui contrôlent l'exécution de l'expression régulière :

TCL_REG_NOTBOL
Indique que la chaîne de texte ne commence pas au début d'une ligne. Par conséquent, l'ancre `^` ne devrait pas correspondre à une nouvelle ligne, même si le drapeau TCL_REG_NEWLINE est utilisé.
TCL_REG_NOTEOL
Indique que la chaîne de texte ne se termine pas à la fin d'une ligne. Par conséquent, l'ancre `$` ne devrait pas correspondre à une nouvelle ligne, même si le drapeau TCL_REG_NEWLINE est utilisé.

Tcl_RegExpExecObj exécute le moteur de correspondance de motifs d'expressions régulières compilé sur l'objet de texte textObj. Il retourne 1 si le motif correspond à une partie du texte, 0 s'il n'y a pas de correspondance, et -1 si une erreur se produit. En cas d'erreur, Tcl_RegExpExecObj laisse un message d'erreur dans le résultat de l'interpréteur. L'argument offset spécifie le décalage de caractère dans le texte où la recherche doit commencer. L'argument nmatches contrôle le nombre de sous-expressions correspondantes qui doivent être enregistrées. Si nmatches est 0, aucune sous-correspondance n'est enregistrée. Si nmatches est -1, toutes les sous-correspondances sont enregistrées. Sinon, au plus nmatches sous-correspondances sont enregistrées. L'argument eflags est une combinaison OR des drapeaux d'exécution mentionnés ci-dessus.

Tcl_RegExpGetInfo remplit la structure Tcl_RegExpInfo pointée par infoPtr avec des informations sur la correspondance la plus récente effectuée par Tcl_RegExpExecObj. La structure Tcl_RegExpInfo est définie comme suit :

typedef struct Tcl_RegExpInfo {
    int nmatches;
    const char **matches;
    Tcl_Obj **matchObjs;
    const char *full;
} Tcl_RegExpInfo;

Les champs de la structure sont les suivants :

nmatches
Le nombre de correspondances trouvées, y compris la correspondance globale. Ce nombre est inférieur ou égal à la valeur de l'argument nmatches passé à Tcl_RegExpExecObj.
matches
Un tableau de pointeurs de chaînes. L'élément à l'index 0 pointe vers le début de la correspondance globale, et les éléments suivants pointent vers le début des sous-correspondances correspondantes. La fin de chaque correspondance est indiquée par le caractère suivant le dernier caractère correspondant. Si une sous-correspondance n'a pas été trouvée, le pointeur correspondant est NULL.
matchObjs
Un tableau d'objets Tcl. Chaque élément contient la sous-chaîne qui correspond à la sous-correspondance correspondante. Ce tableau est valide uniquement si les chaînes Tcl sous-jacentes sont toujours valides et si la mise en cache d'objet est activée.
full
Pointe vers le début de la correspondance globale dans la chaîne de texte.

">TCL_REG_ADVANCED
Compile les expressions régulières avancées ("ARE"). Ce mode correspond à la syntaxe normale des expressions régulières acceptée par les commandes Tcl regexp et regsub.
TCL_REG_EXTENDED
Compile les expressions régulières étendues ("ERE"). Ce mode correspond à la syntaxe des expressions régulières reconnue par Tcl 8.0 et les versions antérieures.
TCL_REG_BASIC
Compile les expressions régulières de base ("BRE"). Ce mode correspond à la syntaxe des expressions régulières reconnue par les utilitaires Unix courants comme sed et grep. C'est le mode par défaut si aucun indicateur n'est spécifié.
TCL_REG_EXPANDED
Compile l'expression régulière (de base, étendue ou avancée) en utilisant une syntaxe étendue qui autorise les commentaires et les espaces blancs. Ce mode ignore les espaces blancs non échappés et non contenus dans des expressions de crochets, ainsi que les commentaires de type "# jusqu'à la fin de la ligne".
TCL_REG_QUOTE
Compile une chaîne littérale, tous les caractères étant traités comme des caractères ordinaires.
TCL_REG_NOCASE
Compile pour une correspondance ignorant la distinction majuscules/minuscules.
TCL_REG_NEWLINE
Compile pour une correspondance sensible aux sauts de ligne. Par défaut, le saut de ligne est un caractère entièrement ordinaire, sans signification spéciale dans les expressions régulières ou les chaînes. Avec cet indicateur, les expressions de crochets "[^...]" et le caractère "." ne correspondent jamais à un saut de ligne, "^" correspond à une chaîne vide après un saut de ligne en plus de sa fonction normale, et "$" correspond à une chaîne vide avant un saut de ligne en plus de sa fonction normale. REG_NEWLINE est le OU bit à bit de REG_NLSTOP et REG_NLANCH.
TCL_REG_NLSTOP
Compile pour une correspondance partiellement sensible aux sauts de ligne, avec le comportement des expressions de crochets "[^...]" et du caractère "." affecté, mais pas le comportement de "^" et "$". Dans ce mode, les expressions de crochets "[^...]" et le caractère "." ne correspondent jamais à un saut de ligne.
TCL_REG_NLANCH
Compile pour une correspondance inverse partiellement sensible aux sauts de ligne, avec le comportement de "^" et "$" (les "ancres") affecté, mais pas le comportement des expressions de crochets "[^...]" et du caractère ".". Dans ce mode, "^" correspond à une chaîne vide après un saut de ligne en plus de sa fonction normale, et "$" correspond à une chaîne vide avant un saut de ligne en plus de sa fonction normale.
TCL_REG_NOSUB
Compile pour une correspondance qui ne signale que le succès ou l'échec, pas ce qui a été trouvé. Cela réduit les frais de compilation et peut améliorer les performances. Les appels ultérieurs à Tcl_RegExpGetInfo ou Tcl_RegExpRange ne signaleront aucune information de correspondance.
TCL_REG_CANMATCH
Compile pour une correspondance qui signale la possibilité de compléter une correspondance partielle étant donné plus de texte (voir ci-dessous).

Un seul des indicateurs TCL_REG_EXTENDED, TCL_REG_ADVANCED, TCL_REG_BASIC, et TCL_REG_QUOTE peut être spécifié.

Tcl_RegExpExecObj exécute le moteur d'expression régulière. Il renvoie 1 si objPtr contient une plage de caractères qui correspond à regexp, 0 si aucune correspondance n'est trouvée, et -1 si une erreur se produit. En cas d'erreur, Tcl_RegExpExecObj laisse un message d'erreur dans le résultat de l'interpréteur. La valeur de nmatches indique au moteur le nombre de sous-expressions qui sont d'intérêt. Si nmatches est 0, alors aucune information de correspondance de sous-expression n'est enregistrée, ce qui peut permettre au moteur d'effectuer diverses optimisations. Si la valeur est -1, alors toutes les sous-expressions du motif sont mémorisées. Si la valeur est un entier positif, alors seul ce nombre de sous-expressions sera mémorisé. La recherche commence à l'index de caractère Unicode spécifié par offset. Contrairement à Tcl_RegExpExec, le comportement des ancres n'est pas affecté par la valeur de l'offset. Le comportement des ancres est explicitement contrôlé par l'argument eflags, qui est un OU bit à bit de zéro ou plusieurs des indicateurs suivants :

TCL_REG_NOTBOL
Le caractère de départ ne sera pas traité comme le début d'une ligne ou le début de la chaîne, donc "^" n'y correspondra pas. Notez que cet indicateur n'a aucun effet sur la façon dont "\A" correspond.
TCL_REG_NOTEOL
Le dernier caractère de la chaîne ne sera pas traité comme la fin d'une ligne ou la fin de la chaîne, donc "$" ne correspondra pas là. Notez que cet indicateur n'a aucun effet sur la façon dont "\Z" correspond.

Tcl_RegExpGetInfo récupère des informations sur la dernière correspondance effectuée avec une expression régulière donnée regexp. L'argument infoPtr contient un pointeur vers une structure définie comme suit :

typedef struct Tcl_RegExpInfo {
    int nsubs;
    Tcl_RegExpIndices *matches;
    long extendStart;
} Tcl_RegExpInfo;

Le champ nsubs contient le nombre de sous-expressions entre parenthèses dans l'expression régulière. Si TCL_REG_NOSUB a été utilisé, cette valeur sera zéro. Le champ matches pointe vers un tableau de nsubs+1 valeurs qui indiquent les limites de chaque sous-expression trouvée. Le premier élément du tableau fait référence à la plage trouvée par l'expression régulière entière, et les éléments suivants font référence aux sous-expressions entre parenthèses dans l'ordre où elles apparaissent dans le motif. Chaque élément est une structure définie comme suit :

typedef struct Tcl_RegExpIndices {
    long start;
    long end;
} Tcl_RegExpIndices;

Les valeurs start et end sont des indices de caractères Unicode par rapport à l'emplacement de l'offset dans objPtr où la recherche a commencé. L'indice start identifie le premier caractère de la sous-expression trouvée. L'indice end identifie le premier caractère après la sous-expression trouvée. Si la sous-expression a trouvé la chaîne vide, alors start et end seront égaux. Si la sous-expression n'a pas participé à la correspondance, alors start et end seront définis à -1.

Le champ extendStart dans Tcl_RegExpInfo n'est défini que si l'indicateur TCL_REG_CANMATCH a été utilisé. Il indique le premier caractère de la chaîne où une correspondance pourrait se produire. Si une correspondance a été trouvée, ce sera le même que le début de la correspondance actuelle. Si aucune correspondance n'a été trouvée, il indique le point le plus précoce où une correspondance pourrait se produire si du texte supplémentaire était ajouté à la chaîne. Si aucune correspondance n'est possible même avec du texte supplémentaire, ce champ sera défini à -1.
