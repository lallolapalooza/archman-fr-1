Tcl_CreateInterp(3) Procédures de la bibliothèque Tcl Tcl_CreateInterp(3)

NAME

Tcl_CreateInterp, Tcl_DeleteInterp, Tcl_InterpActive, Tcl_InterpDeleted - créer et supprimer un interpréteur de commandes Tcl

SYNOPSIS

#include <tcl.h>

Tcl_Interp *
Tcl_CreateInterp()
Tcl_DeleteInterp(interp)
int
Tcl_InterpDeleted(interp)
int
Tcl_InterpActive(interp)

ARGUMENTS

Tcl_Interp *interp (in)
Jeton pour l'interpréteur à détruire ou à interroger.

DESCRIPTION

Tcl_CreateInterp crée une nouvelle structure d'interpréteur et renvoie un jeton pour celle-ci. Le jeton est nécessaire pour les appels à d'autres procédures Tcl, telles que Tcl_CreateCommand, Tcl_Eval et Tcl_DeleteInterp. Le jeton renvoyé par Tcl_CreateInterp ne peut être passé qu'aux routines Tcl appelées depuis le même thread que l'appel original à Tcl_CreateInterp. Il n'est pas sûr de passer le même jeton aux routines Tcl depuis plusieurs threads. Le nouvel interpréteur est initialisé avec les commandes par défaut de la bibliothèque Tcl et les variables standard telles que tcl_platform et env. Pour lier des commandes supplémentaires, appelez Tcl_CreateCommand, et pour créer des variables supplémentaires, appelez Tcl_SetVar.

Tcl_DeleteInterp marque un interpréteur comme supprimé; l'interpréteur sera supprimé lorsque les appels à Tcl_Release correspondront aux derniers appels à Tcl_Preserve. À ce moment-là, toutes les ressources qui lui sont associées, y compris les variables, les procédures et les liaisons de commandes spécifiques à l'application, seront supprimées. Après le retour de Tcl_DeleteInterp, toute tentative d'utilisation de Tcl_Eval sur l'interpréteur échouera et renverra TCL_ERROR. Après l'appel à Tcl_DeleteInterp, il est sûr d'examiner le résultat de l'interpréteur, de consulter ou de définir des valeurs de variables, de définir, de supprimer ou de récupérer des procédures, et d'examiner la pile d'évaluation au moment de l'exécution. Voir plus de détails dans la section INTERPRETERS ET GESTION DE LA MÉMOIRE.

Tcl_InterpDeleted renvoie une valeur non nulle si Tcl_DeleteInterp a été appelé avec interp comme argument; cela indique que l'interpréteur sera supprimé lorsque le dernier appel à Tcl_Preserve sera mis en correspondance avec un appel à Tcl_Release. Si une valeur non nulle est renvoyée, tout appel à Tcl_Eval sur cet interpréteur renverra à nouveau TCL_ERROR.

Tcl_InterpDeleted est utile dans les rappels de suppression pour distinguer entre le moment où seule la mémoire dont le rappel est responsable de la suppression est supprimée et le moment où l'interpréteur lui-même est supprimé. Dans le premier cas, le rappel peut recréer les données en cours de suppression, mais cela pourrait entraîner une boucle infinie si l'interpréteur est en cours de suppression.

Tcl_InterpActive est utile pour déterminer s'il y a une exécution de script en cours dans un interpréteur, ce qui est une information utile lorsque Tcl est incorporé dans un environnement de garbage collection et qu'il est nécessaire de déterminer si l'interpréteur est un candidat à la suppression. La fonction renvoie une valeur vraie si l'interpréteur a au moins une exécution active en cours, et faux sinon.

INTERPRETERS ET GESTION DE LA MÉMOIRE

Tcl_DeleteInterp peut être appelé à tout moment sur un interpréteur qui peut être utilisé dans des évaluations imbriquées et dans du code C dans diverses extensions. Tcl implémente un mécanisme simple qui permet aux appelants d'utiliser des interpréteurs sans se soucier de leur suppression dans des appels imbriqués, et sans nécessiter de code spécial pour protéger l'interpréteur, dans la plupart des cas. Ce mécanisme garantit que les utilisations imbriquées d'un interpréteur peuvent continuer à l'utiliser même après l'appel à Tcl_DeleteInterp.

Le mécanisme repose sur la mise en correspondance des appels à Tcl_Preserve avec les appels à Tcl_Release. Ce n'est que lorsque le dernier appel à Tcl_Preserve est mis en correspondance avec un appel à Tcl_Release que l'interpréteur sera supprimé. Voir l'entrée man de Tcl_Preserve pour une description de ces fonctions.

Les règles concernant le moment où l'utilisateur d'un interpréteur doit appeler Tcl_Preserve et Tcl_Release sont simples:

Interpreters Passés en Arguments
Les fonctions qui reçoivent un interpréteur en argument peuvent utiliser l'interpréteur en toute sécurité sans protection spéciale. Ainsi, lorsque vous écrivez une extension avec de nouvelles commandes Tcl, vous n'aurez pas besoin de code spécial pour protéger les interpréteurs reçus en tant qu'arguments. Cela couvre la plupart des utilisations.
Création et Suppression d'Interpreters
Lorsque vous créez un nouvel interpréteur et que vous l'utilisez dans un appel à Tcl_Eval, Tcl_VarEval, Tcl_GlobalEval, Tcl_SetVar ou Tcl_GetVar, vous devez encapsuler toutes les utilisations de l'interpréteur par des appels à Tcl_Preserve et Tcl_Release. N'oubliez pas qu'il est dangereux d'utiliser l'interpréteur une fois que Tcl_Release a été appelé. Pour vous assurer que l'interpréteur est correctement supprimé lorsqu'il n'est plus nécessaire, appelez Tcl_InterpDeleted pour vérifier si un autre code a déjà appelé Tcl_DeleteInterp; sinon, appelez Tcl_DeleteInterp avant d'appeler Tcl_Release dans votre code.
Récupération d'un Interpréteur à partir de Données
Lorsqu'un interpréteur est récupéré à partir de données (par exemple, le client d'un rappel) pour être utilisé dans l'une des fonctions d'évaluation (Tcl_Eval, Tcl_VarEval, Tcl_GlobalEval, Tcl_EvalObjv, etc.) ou fonctions d'accès aux variables (Tcl_SetVar, Tcl_GetVar, Tcl_SetVar2Ex, etc.), vous devez encapsuler toutes les utilisations de l'interpréteur par des appels à Tcl_Preserve et Tcl_Release; il est dangereux de réutiliser l'interpréteur une fois que Tcl_Release a été appelé. Si l'interpréteur est stocké dans une structure de données de rappel, vous devez mettre en place un mécanisme de suppression approprié par le code qui crée la structure afin que l'interpréteur soit retiré de la structure (par exemple, en définissant le champ sur NULL) lorsque l'interpréteur est supprimé. Sinon, vous pourriez utiliser un interpréteur déjà libéré dont la mémoire pourrait déjà avoir été réutilisée.

Toutes les utilisations d'interpréteurs dans Tcl et Tk sont déjà protégées. Les auteurs d'extensions doivent s'assurer que leur code protège également tout interpréteur supplémentaire utilisé, comme décrit ci-dessus.

Remarque: les mécanismes de protection ne fonctionnent pas bien avec les systèmes de garbage collection conventionnels. Lorsque vous vous trouvez dans un tel environnement, Tcl_InterpActive doit être utilisé pour déterminer quand un interpréteur est un candidat à la suppression en raison de l'inactivité.

Tcl_CreateInterp - create a new Tcl interpreter

SYNOPSIS

#include <tcl.h>

Tcl_Interp *
Tcl_CreateInterp(void);

Description

The Tcl_CreateInterp procedure creates a new Tcl interpreter. An interpreter is the central data structure for Tcl; it holds the state for a Tcl application, including variables, procedures, and loaded extensions.

When an interpreter is created, it is initialized with the standard Tcl commands, procedures, and variables. The memory for the interpreter is dynamically allocated and managed by Tcl. The caller is responsible for freeing the interpreter when it is no longer needed by calling Tcl_DeleteInterp.

Return value

Returns a pointer to the newly created interpreter. If the interpreter cannot be created (e.g., due to insufficient memory), it returns NULL.

SEE ALSO

Tcl_DeleteInterp(3), Tcl_Eval(3), Tcl_Global(3), Tcl_SetVar(3)

KEYWORDS

create, interpreter, new, Tcl

Tcl_CreateInterp(3)

Tcl_CreateInterp - créer un nouvel interpréteur Tcl

Synopsis

#include <tcl.h>

Tcl_Interp *
Tcl_CreateInterp(void);

Description

La procédure Tcl_CreateInterp crée un nouvel interpréteur Tcl. Un interpréteur est la structure de données centrale de Tcl ; il détient l'état d'une application Tcl, y compris les variables, les procédures et les extensions chargées.

Lorsqu'un interpréteur est créé, il est initialisé avec les commandes, procédures et variables Tcl standard. La mémoire de l'interpréteur est allouée dynamiquement et gérée par Tcl. L'appelant est responsable de libérer l'interpréteur lorsqu'il n'est plus nécessaire en appelant Tcl_DeleteInterp.

Valeur de retour

Retourne un pointeur vers le nouvel interpréteur créé. Si l'interpréteur ne peut pas être créé (par exemple, en raison d'une mémoire insuffisante), il retourne NULL.
