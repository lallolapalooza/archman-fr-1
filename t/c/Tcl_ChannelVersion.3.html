DESCRIPTION

Tcl utilise une architecture de canaux à deux niveaux. Elle offre un niveau supérieur générique pour que les programmes C et Tcl puissent effectuer des entrées et sorties en utilisant les mêmes API pour une variété de fichiers, périphériques, sockets, etc. Les API C génériques sont décrites dans l'entrée de manuel pour Tcl_OpenFileChannel.

Le niveau inférieur fournit des pilotes de canal spécifiques pour chaque type de périphérique pris en charge sur chaque plateforme. Cette entrée de manuel décrit les API C qui communiquent entre le niveau générique et les pilotes de canal spécifiques. Elle explique également comment de nouveaux types de canaux peuvent être ajoutés en fournissant de nouveaux pilotes de canal.

Les pilotes de canal sont constitués de plusieurs composants : Premièrement, chaque pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers les procédures qui implémentent les diverses opérations utilisées par le niveau générique pour communiquer avec le pilote de canal. La structure Tcl_ChannelType et les procédures auxquelles elle fait référence sont décrites dans la section TCL_CHANNELTYPE ci-dessous.

Deuxièmement, les pilotes de canal fournissent généralement une commande Tcl pour créer des instances de ce type de canal. Par exemple, la commande Tcl open crée des canaux qui utilisent les pilotes de canal de fichier et de commande, et la commande Tcl socket crée des canaux qui utilisent des protocoles réseau TCP pour la communication réseau.

Troisièmement, un pilote de canal fournit éventuellement une fonction C pour ouvrir des instances de ce type de canal. Par exemple, Tcl_OpenFileChannel ouvre un canal qui utilise le pilote de canal de fichier, et Tcl_OpenTcpClient ouvre un canal qui utilise le protocole réseau TCP. Ces fonctions de création appellent généralement Tcl_CreateChannel en interne pour ouvrir le canal.

Pour ajouter un nouveau type de canal, vous devez implémenter une API C ou une commande Tcl qui ouvre un canal en appelant Tcl_CreateChannel. Lorsque votre pilote appelle Tcl_CreateChannel, il transmet une structure Tcl_ChannelType qui décrit les fonctions d'E/S de votre pilote. Le niveau générique appellera ensuite les procédures référencées dans cette structure pour effectuer des opérations sur le canal.

Tcl_CreateChannel ouvre un nouveau canal et lui associe typePtr et instanceData. Le canal est ouvert dans le mode indiqué par mask. Pour une discussion sur les pilotes de canal, leurs opérations et la structure Tcl_ChannelType, voir la section TCL_CHANNELTYPE ci-dessous.

Tcl_CreateChannel interagit avec le code qui gère les canaux standard. Une fois qu'un canal standard a été initialisé par un appel à Tcl_GetStdChannel ou Tcl_SetStdChannel, la fermeture de ce canal entraînera la prochaine invocation de Tcl_CreateChannel pour qu'il devienne le nouveau canal standard. Voir Tcl_StandardChannels pour un traitement général des canaux standard et du comportement de la bibliothèque Tcl à leur égard.

Tcl_GetChannelInstanceData renvoie les données d'instance associées au canal dans channel. Il s'agit de la même valeur que l'argument instanceData dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelType renvoie un pointeur vers la structure Tcl_ChannelType utilisée par le canal dans l'argument channel. Il s'agit de la même valeur que l'argument typePtr dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelName renvoie une chaîne contenant le nom associé au canal, ou NULL si l'argument channelName de Tcl_CreateChannel était NULL.

Tcl_GetChannelHandle place le handle du système d'exploitation associé à channel pour la direction donnée dans handlePtr.

Tcl_GetChannelThread retourne l'identifiant du thread gérant actuellement le canal spécifié. Ceci permet aux pilotes de canal d'envoyer leurs événements de fichier à la bonne file d'attente d'événements, même pour un cœur multi-thread.

Tcl_GetChannelMode retourne une combinaison OR de TCL_READABLE et TCL_WRITABLE, indiquant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelBufferSize retourne la taille, en octets, des tampons alloués pour stocker l'entrée ou la sortie dans le canal. Si la valeur n'a pas été définie par un appel précédent à Tcl_SetChannelBufferSize, décrit ci-dessous, alors la valeur par défaut de 4096 est retournée.

Tcl_SetChannelBufferSize définit la taille, en octets, des tampons qui seront alloués lors des opérations ultérieures sur le canal pour stocker l'entrée ou la sortie. L'argument size doit être compris entre un et un million, permettant des tampons d'un octet à un million d'octets. Si size est en dehors de cette plage, Tcl_SetChannelBufferSize définit la taille du tampon à 4096.

Tcl_NotifyChannel est appelé par un pilote de canal pour indiquer à la couche générique que les événements spécifiés par mask se sont produits sur le canal. Les pilotes de canal sont responsables de l'invocation de cette fonction chaque fois que les gestionnaires de canal doivent être appelés pour le canal (ou d'autres tâches en attente, comme une purge d'écriture, doivent être effectuées). Voir WATCHPROC ci-dessous pour plus de détails.

Tcl_BadChannelOption est appelé depuis le setOptionProc ou le getOptionProc spécifique au pilote pour générer un message d'erreur complet.

Tcl_ChannelBuffered retourne le nombre d'octets d'entrée actuellement mis en tampon dans le tampon interne (zone de retour en arrière) du canal lui-même. Il ne rend pas compte des données dans les tampons globaux de la pile de canaux dont fait partie le canal fourni.

Tcl_IsChannelShared vérifie le compteur de références du canal spécifié et retourne si le canal a été partagé entre plusieurs interpréteurs (résultat == 1) ou non (résultat == 0).

Tcl_IsChannelRegistered vérifie si le canal spécifié est enregistré dans l'interpréteur donné (résultat == 1) ou non (résultat == 0).

Tcl_IsChannelExisting vérifie si un canal portant le nom spécifié est enregistré dans la liste globale (par thread) de tous les canaux (résultat == 1) ou non (résultat == 0).

Tcl_CutChannel supprime le canal spécifié de la liste globale (par thread) de tous les canaux (du thread courant). L'application à un canal toujours enregistré dans un interpréteur n'est pas autorisée. Notifie également le pilote si la version Tcl_ChannelType est TCL_CHANNEL_VERSION_4 (ou supérieure), et Tcl_DriverThreadActionProc est définie pour celui-ci.

Tcl_SpliceChannel ajoute le canal spécifié à la liste globale (par thread) de tous les canaux (du thread courant). L'application à un canal enregistré dans un interpréteur n'est pas autorisée. Notifie également le pilote si la version Tcl_ChannelType est TCL_CHANNEL_VERSION_4 (ou supérieure), et Tcl_DriverThreadActionProc est définie pour celui-ci.

Tcl_ClearChannelHandlers supprime tous les gestionnaires de canal et scripts d'événements associés au canal spécifié, arrêtant ainsi tout traitement d'événements pour ce canal.

TCL_CHANNELTYPE

Un pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers des fonctions implémentant les différentes opérations sur un canal ; ces opérations sont invoquées au besoin par la couche générique. La structure a été versionnée à partir de Tcl 8.3.2/8.4 pour corriger un problème avec les pilotes de canal empilés. Voir la section OLD CHANNEL TYPES ci-dessous pour plus de détails sur l'ancienne structure.

La structure Tcl_ChannelType contient les champs suivants :

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Il n'est pas nécessaire de fournir des implémentations pour toutes les opérations de canal. Celles qui ne sont pas nécessaires peuvent être définies sur NULL dans la structure : blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc et close2Proc, en plus de flushProc, handlerProc, threadActionProc et truncateProc. D'autres fonctions qui ne peuvent pas être implémentées de manière significative devraient retourner EINVAL lorsqu'elles sont appelées, pour indiquer que les opérations qu'elles représentent ne sont pas disponibles. Notez également que wideSeekProc peut être NULL si seekProc l'est.

L'utilisateur ne doit utiliser que la structure ci-dessus pour l'instanciation de Tcl_ChannelType. Lors de la référence aux champs d'une structure Tcl_ChannelType, les fonctions suivantes doivent être utilisées pour obtenir les valeurs : Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc ou Tcl_ChannelHandlerProc.

La modification apportée aux structures a été faite de telle sorte que les types de canaux standard soient binaires compatibles. Cependant, les types de canaux qui utilisent des canaux empilés (c'est-à-dire TLS, Trf) ont de nouvelles versions pour correspondre au changement ci-dessus, car le code précédent pour les canaux empilés avait des problèmes.

TYPENAME

Le champ typeName contient une chaîne terminée par null qui identifie le type du périphérique implémenté par ce pilote, par exemple file ou socket.

Cette valeur peut être récupérée avec Tcl_ChannelName, qui retourne un pointeur vers la chaîne.

VERSION

Le champ version doit être défini sur la version de la structure dont vous avez besoin. TCL_CHANNEL_VERSION_2 est le minimum recommandé. TCL_CHANNEL_VERSION_3 doit être défini pour spécifier le membre wideSeekProc. TCL_CHANNEL_VERSION_4 doit être défini pour spécifier le membre threadActionProc (inclut wideSeekProc). TCL_CHANNEL_VERSION_5 doit être défini pour spécifier les membres truncateProc (inclut wideSeekProc et threadActionProc). S'il n'est défini sur aucune de ces valeurs, alors ce Tcl_ChannelType est supposé avoir la structure originale. Voir OLD CHANNEL TYPES pour plus de détails. Bien que Tcl reconnaisse et fonctionne avec les deux structures, les canaux empilés doivent être au moins de TCL_CHANNEL_VERSION_2 pour fonctionner correctement.

Cette valeur peut être récupérée avec Tcl_ChannelVersion, qui retourne l'une des valeurs TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 ou TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

Le champ blockModeProc contient l'adresse d'une fonction appelée par la couche générique pour définir le mode bloquant et non bloquant sur le périphérique. BlockModeProc doit correspondre au prototype suivant :

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

Le instanceData est le même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. L'argument mode est soit TCL_MODE_BLOCKING soit TCL_MODE_NONBLOCKING pour définir le périphérique en mode bloquant ou non bloquant. La fonction doit retourner zéro si l'opération a réussi, ou un code d'erreur POSIX non nul si l'opération a échoué.

Si l'opération réussit, la fonction peut modifier le instanceData fourni pour enregistrer que le canal est entré en mode bloquant ou non bloquant et pour implémenter le comportement bloquant ou non bloquant. Pour certains types de périphériques, le comportement bloquant et non bloquant peut être implémenté par le système d'exploitation sous-jacent ; pour d'autres types de périphériques, le comportement doit être émuler dans le pilote de canal.

Cette valeur peut être récupérée avec Tcl_ChannelBlockModeProc, qui retourne un pointeur vers la fonction.

Un pilote de canal ne fournissant pas de blockModeProc doit être très, très prudent. Il doit indiquer précisément à la couche générique quel mode bloquant lui convient, et doit également le documenter pour l'utilisateur afin que le mode bloquant du canal ne soit pas modifié à une valeur inacceptable. Toute confusion ici peut entraîner l'interpréteur dans une boucle infinie (imaginée et difficile à trouver).

CLOSEPROC ET CLOSE2PROC

Le champ closeProc contient l'adresse d'une fonction appelée par la couche générique pour nettoyer les informations relatives au pilote lors de la fermeture du canal. CloseProc doit correspondre au prototype suivant :

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

L'argument instanceData est le même que la valeur fournie à Tcl_CreateChannel lors de la création du canal. La fonction doit libérer toute mémoire maintenue par le pilote de canal pour ce canal, et fermer les périphériques d'entrée et de sortie encapsulés par ce canal. Toutes les sorties mises en file d'attente auront été purgées vers le périphérique avant que cette fonction ne soit appelée, et aucune autre opération de pilote ne sera invoquée sur cette instance après l'appel du closeProc. Si l'opération de fermeture réussit, la procédure s'exécute

DESCRIPTION

Tcl provides a generic channel driver interface that allows Tcl scripts to perform input and output operations on a wide variety of devices and files. This interface is implemented by a collection of Tcl procedures and by channel driver modules. Each channel driver module implements a Tcl_ChannelType structure which describes the operations that can be performed on channels of that type.

The Tcl_ChannelType structure has the following fields:

typeName
The name of the channel type (e.g., "file", "socket", "pipe"). This name is used to register and look up channel types.
closeProc
A pointer to a procedure that Tcl calls when a channel of this type is closed. The procedure should clean up any resources associated with the channel. See the description of Tcl_DriverCloseProc below for details.
inputProc
A pointer to a procedure that Tcl calls to read data from the channel. See the description of Tcl_DriverInputProc below for details.
outputProc
A pointer to a procedure that Tcl calls to write data to the channel. See the description of Tcl_DriverOutputProc below for details.
seekProc
A pointer to a procedure that Tcl calls to move the access point in a channel. See the description of Tcl_DriverSeekProc below for details. This field can be NULL if the channel type does not support seeking.
setOptionProc
A pointer to a procedure that Tcl calls to set a channel-type-specific option on a channel. See the description of Tcl_DriverSetOptionProc below for details. This field can be NULL if the channel type does not support any type-specific options.
getOptionProc
A pointer to a procedure that Tcl calls to get the value of a channel-type-specific option on a channel. See the description of Tcl_DriverGetOptionProc below for details. This field can be NULL if the channel type does not support any type-specific options.
watchProc
A pointer to a procedure that Tcl calls to register interest in input or output events on the channel. This is used by Tcl's event loop. See the Tcl_DriverWatchProc man page for details.
getUFileProc
A pointer to a procedure that Tcl calls to get the underlying Unix file descriptor for a channel. See Tcl_DriverGetFileProc for details. This field may be NULL.
setWaterMarkProc

A pointer to a procedure that Tcl calls when a channel is closed. This allows for independent closing of read and write sides of a channel. See the description of Tcl_DriverClose2Proc below for details.

CHANNEL DRIVER PROCEDURES

Channel drivers implement the following procedures:

CLOSEPROC

The closeProc field contains the address of a procedure that Tcl calls when a channel is closed. The procedure should perform any necessary cleanup for the channel's resources. It must match the following prototype:

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

InstanceData is the same value that was passed to Tcl_CreateChannel when the channel was created. The interp argument is the interpreter in which the channel is being closed. The function should return zero if the close operation was successful; otherwise it should return a nonzero POSIX error code. In addition, if an error occurs and interp is not NULL, the procedure should store an error message in the interpreter's result.

Alternatively, channels that support closing the read and write sides independently may set closeProc to TCL_CLOSE2PROC and set close2Proc to the address of a function that matches the following prototype:

typedef int Tcl_DriverClose2Proc(
        ClientData instanceData,
        Tcl_Interp *interp,
        int flags);

The close2Proc will be called with flags set to an OR'ed combination of TCL_CLOSE_READ or TCL_CLOSE_WRITE to indicate that the driver should close the read and/or write side of the channel. The channel driver may be invoked to perform additional operations on the channel after close2Proc is called to close one or both sides of the channel. If flags is 0 (zero), the driver should close the channel in the manner described above for closeProc. No further operations will be invoked on this instance after close2Proc is called with all flags cleared. In all cases, the close2Proc function should return zero if the close operation was successful; otherwise it should return a nonzero POSIX error code. In addition, if an error occurs and interp is not NULL, the procedure should store an error message in the interpreter's result.

The closeProc and close2Proc values can be retrieved with Tcl_ChannelCloseProc or Tcl_ChannelClose2Proc, which return a pointer to the respective function.

INPUTPROC

The inputProc field contains the address of a function called by the generic layer to read data from the file or device and store it in an internal buffer. InputProc must match the following prototype:

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

InstanceData is the same as the value passed to Tcl_CreateChannel when the channel was created. The buf argument points to an array of bytes in which to store input from the device, and the bufSize argument indicates how many bytes are available at buf.

The errorCodePtr argument points to an integer variable provided by the generic layer. If an error occurs, the function should set the variable to a POSIX error code that identifies the error that occurred.

The function should read data from the input device encapsulated by the channel and store it at buf. On success, the function should return a nonnegative integer indicating how many bytes were read from the input device and stored at buf. On error, the function should return -1. If an error occurs after some data has been read from the device, that data is lost.

If inputProc can determine that the input device has some data available but less than requested by the bufSize argument, the function should only attempt to read as much data as is available and return without blocking. If the input device has no data available whatsoever and the channel is in nonblocking mode, the function should return an EAGAIN error. If the input device has no data available whatsoever and the channel is in blocking mode, the function should block for the shortest possible time until at least one byte of data can be read from the device; then, it should return as much data as it can read without blocking.

This value can be retrieved with Tcl_ChannelInputProc, which returns a pointer to the function.

OUTPUTPROC

The outputProc field contains the address of a function called by the generic layer to transfer data from an internal buffer to the output device. OutputProc must match the following prototype:

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

InstanceData is the same as the value passed to Tcl_CreateChannel when the channel was created. The buf argument contains an array of bytes to be written to the device, and the toWrite argument indicates how many bytes are to be written from the buf argument.

The errorCodePtr argument points to an integer variable provided by the generic layer. If an error occurs, the function should set this variable to a POSIX error code that identifies the error.

The function should write the data at buf to the output device encapsulated by the channel. On success, the function should return a nonnegative integer indicating how many bytes were written to the output device. The return value is normally the same as toWrite, but may be less in some cases such as if the output operation is interrupted by a signal. If an error occurs the function should return -1. In case of error, some data may have been written to the device.

If the channel is nonblocking and the output device is unable to absorb any data whatsoever, the function should return -1 with an EAGAIN error without writing any data.

This value can be retrieved with Tcl_ChannelOutputProc, which returns a pointer to the function.

SEEKPROC AND WIDESEEKPROC

The seekProc field contains the address of a function called by the generic layer to move the access point at which subsequent input or output operations will be applied. SeekProc must match the following prototype:

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

The instanceData argument is the same as the value given to Tcl_CreateChannel when this channel was created. Offset and seekMode have the same meaning as for the Tcl_Seek procedure (described in the manual entry for Tcl_OpenFileChannel).

The errorCodePtr argument points to an integer variable provided by the generic layer for returning errno values from the function. The function should set this variable to a POSIX error code if an error occurs. The function should store an EINVAL error code if the channel type does not implement seeking.

The return value is the new access point or -1 in case of error. If an error occurred, the function should not move the access point.

If there is a non-NULL seekProc field, the wideSeekProc field may contain the address of an alternative function to use which handles wide (i.e. larger than 32-bit) offsets, so allowing seeks within files larger than 2GB. The wideSeekProc will be called in preference to the seekProc, but both must be defined if the wideSeekProc is defined. WideSeekProc must match the following prototype:

typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

The arguments and return values mean the same thing as with seekProc above, except that the type of offsets and the return type are different.

The seekProc value can be retrieved with Tcl_ChannelSeekProc, which returns a pointer to the function, and similarly the wideSeekProc can be retrieved with Tcl_ChannelWideSeekProc.

SETOPTIONPROC

The setOptionProc field contains the address of a function called by the generic layer to set a channel type specific option on a channel. setOptionProc must match the following prototype:

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

optionName is the name of an option to set, and newValue is the new value for that option, as a string. The instanceData is the same as the value given to Tcl_CreateChannel when this channel was created. The function should do whatever channel type specific action is required to implement the new value of the option.

Some options are handled by the generic code and this function is never called to set them, e.g. -blockmode. Other options are specific to each channel type and the setOptionProc procedure of the channel driver will get called to implement them. The setOptionProc field can be NULL, which indicates that this channel type supports no type specific options.

If the option value is successfully modified to the new value, the function returns TCL_OK. It should call Tcl_BadChannelOption which itself returns TCL_ERROR if the optionName is unrecognized. If newValue specifies a value for the option that is not supported or if a system call error occurs, the function should leave an error message in the result of interp if interp is not NULL. The function should also call Tcl_SetErrno to store an appropriate POSIX error code.

This value can be retrieved with Tcl_ChannelSetOptionProc, which returns a pointer to the function.

GETOPTIONPROC

The getOptionProc field contains the address of a function called by the generic layer to get the value of a channel type specific option on a channel. getOptionProc must match the following prototype:

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        Tcl_DString *optionValue);

OptionName is the name of an option supported by this type of channel. If the option name is not NULL, the function stores its current value, as a string, in the Tcl dynamic string optionValue. If optionName is NULL, the function stores in optionValue an alternating list of all supported options and their current values. On success, the function returns TCL_OK. It should call Tcl_BadChannelOption which itself returns TCL_ERROR if the optionNa

Certaines options sont gérées par le code générique et cette fonction n'est jamais appelée pour récupérer leur valeur, par exemple -blockmode. D'autres options sont spécifiques à chaque type de canal et la procédure getOptionProc du pilote de canal sera appelée pour les implémenter. Le champ getOptionProc peut être NULL, ce qui indique que ce type de canal ne prend en charge aucune option spécifique au type.

Cette valeur peut être récupérée avec Tcl_ChannelGetOptionProc, qui renvoie un pointeur vers la fonction.

WATCHPROC

Le champ watchProc contient l'adresse d'une fonction appelée par la couche générique pour initialiser le mécanisme de notification d'événements afin de détecter les événements d'intérêt sur ce canal. WatchProc doit correspondre au prototype suivant :

typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. L'argument mask est une combinaison OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION ; il indique les événements que l'appelant souhaite détecter sur ce canal.

La fonction doit initialiser les mécanismes spécifiques au type de périphérique pour détecter quand un événement d'intérêt est présent sur le canal. Lorsqu'un ou plusieurs des événements désignés se produisent sur le canal, le pilote de canal est responsable d'appeler Tcl_NotifyChannel pour informer le module de canal générique. Le pilote doit veiller à ne pas affamer d'autres pilotes de canal ou sources de rappels en appelant Tcl_NotifyChannel trop fréquemment. L'équité peut être assurée en utilisant la file d'attente d'événements Tcl pour permettre à l'événement de canal d'être planifié en séquence avec d'autres événements. Voir la description de Tcl_QueueEvent pour plus de détails sur la mise en file d'attente d'un événement.

Cette valeur peut être récupérée avec Tcl_ChannelWatchProc, qui renvoie un pointeur vers la fonction.

GETHANDLEPROC

Le champ getHandleProc contient l'adresse d'une fonction appelée par la couche générique pour récupérer un handle spécifique au périphérique à partir du canal. GetHandleProc doit correspondre au prototype suivant :

typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. L'argument direction est soit TCL_READABLE pour récupérer le handle utilisé pour l'entrée, soit TCL_WRITABLE pour récupérer le handle utilisé pour la sortie.

Si l'implémentation du canal possède des handles spécifiques au périphérique, la fonction doit récupérer le handle approprié associé au canal, en fonction de l'argument direction. Le handle doit être stocké à l'emplacement référencé par handlePtr, et TCL_OK doit être renvoyé. Si le canal n'est pas ouvert pour la direction spécifiée, ou si l'implémentation du canal n'utilise pas de handles de périphérique, la fonction doit renvoyer TCL_ERROR.

Cette valeur peut être récupérée avec Tcl_ChannelGetHandleProc, qui renvoie un pointeur vers la fonction.

FLUSHPROC

Le champ flushProc est actuellement réservé pour une utilisation future. Il doit être défini à NULL. FlushProc doit correspondre au prototype suivant :

typedef int Tcl_DriverFlushProc(
        ClientData instanceData);

Cette valeur peut être récupérée avec Tcl_ChannelFlushProc, qui renvoie un pointeur vers la fonction.

HANDLERPROC

Le champ handlerProc contient l'adresse d'une fonction appelée par la couche générique pour notifier le canal qu'un événement s'est produit. Il doit être défini pour les pilotes de canal empilés qui souhaitent être informés des événements qui se produisent sur le canal sous-jacent (empilé). HandlerProc doit correspondre au prototype suivant :

typedef int Tcl_DriverHandlerProc(
        ClientData instanceData,
        int interestMask);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. Le interestMask est une combinaison OR de TCL_READABLE ou TCL_WRITABLE ; il indique quel type d'événement s'est produit sur ce canal.

Cette valeur peut être récupérée avec Tcl_ChannelHandlerProc, qui renvoie un pointeur vers la fonction.

THREADACTIONPROC

Le champ threadActionProc contient l'adresse de la fonction appelée par la couche générique lorsqu'un canal est créé, fermé ou sur le point de passer à un autre thread, c'est-à-dire chaque fois que l'état du pilote spécifique au thread pourrait devoir être initialisé ou mis à jour. Il peut être NULL. L'action TCL_CHANNEL_THREAD_REMOVE est utilisée pour notifier au pilote qu'il doit mettre à jour ou supprimer toute donnée spécifique au thread qu'il pourrait maintenir pour le canal.

L'action TCL_CHANNEL_THREAD_INSERT est utilisée pour notifier au pilote qu'il doit mettre à jour ou initialiser toute donnée spécifique au thread qu'il pourrait maintenir en utilisant le thread appelant comme associé. Voir Tcl_CutChannel et Tcl_SpliceChannel pour plus de détails.

typedef void Tcl_DriverThreadActionProc(
        ClientData instanceData,
        int action);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal.

Ces valeurs peuvent être récupérées avec Tcl_ChannelThreadActionProc, qui renvoie un pointeur vers la fonction.

TRUNCATEPROC

Le champ truncateProc contient l'adresse de la fonction appelée par la couche générique lorsqu'un canal est tronqué à une certaine longueur. Il peut être NULL.

typedef int Tcl_DriverTruncateProc(
        ClientData instanceData,
        Tcl_WideInt length);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal, et length est la nouvelle longueur du fichier sous-jacent, qui ne doit pas être négative. Le résultat doit être 0 en cas de succès ou un code errno (adapté pour être utilisé avec Tcl_SetErrno) en cas d'échec.

Ces valeurs peuvent être récupérées avec Tcl_ChannelTruncateProc, qui renvoie un pointeur vers la fonction.

TCL_BADCHANNELOPTION

Cette procédure génère un message d'erreur "mauvaise option" dans un interpréteur (optionnel). Elle est utilisée par les pilotes de canal lorsqu'une option Set/Get invalide est demandée. Son but est de concaténer la liste générique des options à celles spécifiques et de factoriser la chaîne de message d'erreur des options génériques.

Elle renvoie toujours TCL_ERROR

Un message d'erreur est généré dans la valeur de résultat d'interp pour indiquer qu'une commande a été invoquée avec une mauvaise option. Le message a la forme

    mauvaise option "blah" : devrait être l'une des
    <...options génériques...>+<...options spécifiques...>
vous obtenez par exemple : 
    mauvaise option "-blah" : devrait être l'une des -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, ou -sockname
lorsqu'elle est appelée avec optionList égal à “peername sockname”

“blah” est l'argument optionName et “<options spécifiques>” est une liste d'options spécifiques séparées par des espaces. La fonction prend soin d'insérer des signes moins avant chaque option, des virgules après, et un “ou” avant la dernière option.

VIEILLES TYPES DE CANAUX

La structure Tcl_ChannelType originale (8.3.1 et versions antérieures) contient les champs suivants :

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
} Tcl_ChannelType;

Il est toujours possible de créer des canaux avec la structure ci-dessus. Le code interne des canaux déterminera la version. Il est impératif d'utiliser la nouvelle structure Tcl_ChannelType si vous créez un pilote de canal empilé, en raison de problèmes avec l'implémentation précédente des canaux empilés (dans les versions 8.2.0 à 8.3.1).

Avant la version 8.4.0 (c'est-à-dire lors des dernières versions de 8.3 et du début du cycle de développement de 8.4), la structure Tcl_ChannelType contenait les champs suivants :

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_ChannelTypeVersion version;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Lorsque la structure ci-dessus est enregistrée comme type de canal, le champ version doit toujours être TCL_CHANNEL_VERSION_2.

NAME

Tcl_ChannelVersion - returns version information about Tcl channel support

SYNOPSIS

#include <tcl.h>

const char *
Tcl_ChannelVersion(void);

ARGUMENTS

None.

DESCRIPTION

The Tcl_ChannelVersion procedure returns a string containing version information about the Tcl channel support code. The string is a human-readable description of the version and should not be parsed by programs.

TCL_CHANNELTYPE

The channel type structure used by Tcl channels is defined by the Tcl_ChannelType structure. This structure contains function pointers for operations on channels, such as reading, writing, and flushing.

The specific fields within the Tcl_ChannelType structure may vary depending on the Tcl version and the type of channel. However, the core functions related to I/O operations are generally present.

TCL_BADCHANNELOPTION

The constant TCL_BADCHANNELOPTION is a value used internally by Tcl to indicate an invalid channel option when setting or getting channel configurations.

OLD CHANNEL TYPES

In older versions of Tcl, channel handling might have been implemented differently. The current channel mechanism, based on the Tcl_ChannelType structure, was introduced to provide a more flexible and extensible way to manage I/O channels.

Applications using older Tcl versions might need to adapt their channel handling code to use the newer API for compatibility and to leverage advanced features.
