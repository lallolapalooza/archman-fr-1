Tcl_CreateFileHandler(3) Procédures de bibliothèque Tcl Tcl_CreateFileHandler(3)

NOM

Tcl_CreateFileHandler, Tcl_DeleteFileHandler - associer des rappels de procédure avec des fichiers ou des périphériques (Unix uniquement)

SYNOPSIS

#include <tcl.h>

Tcl_CreateFileHandler(fd, mask, proc, clientData)

Tcl_DeleteFileHandler(fd)

ARGUMENTS

int fd (en entrée)
Descripteur de fichier Unix pour un fichier ou un périphérique ouvert.
int mask (en entrée)
Conditions dans lesquelles proc doit être appelée : combinaison OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION. Peut être défini à 0 pour désactiver temporairement un gestionnaire.
Tcl_FileProc *proc (en entrée)
Procédure à invoquer chaque fois que le fichier ou le périphérique indiqué par file remplit les conditions spécifiées par mask.
ClientData clientData (en entrée)
Valeur arbitraire d'un mot à passer à proc.

DESCRIPTION

Tcl_CreateFileHandler organise l'invocation de proc à l'avenir chaque fois que des E/S deviennent possibles sur un fichier ou qu'une condition exceptionnelle existe pour le fichier. Le fichier est indiqué par fd, et les conditions d'intérêt sont indiquées par mask. Par exemple, si mask est TCL_READABLE, proc sera appelée lorsque le fichier sera lisible. Le rappel à proc est effectué par Tcl_DoOneEvent, donc Tcl_CreateFileHandler n'est utile que dans les programmes qui distribuent des événements via Tcl_DoOneEvent ou via des commandes Tcl telles que vwait.

Proc doit avoir des arguments et un résultat qui correspondent au type Tcl_FileProc :

typedef void Tcl_FileProc(
        ClientData clientData,
        int mask);

Le paramètre clientData de proc est une copie de l'argument clientData donné à Tcl_CreateFileHandler lors de la création du rappel. Typiquement, clientData pointe vers une structure de données contenant des informations spécifiques à l'application sur le fichier. Mask est un masque entier indiquant lesquelles des conditions demandées existent réellement pour le fichier ; il contiendra un sous-ensemble des bits du masque donné à Tcl_CreateFileHandler.

Il ne peut exister qu'un seul gestionnaire pour un fichier donné à un moment donné. Si Tcl_CreateFileHandler est appelé alors qu'un gestionnaire existe déjà pour fd, alors le nouveau rappel remplace les informations qui étaient précédemment enregistrées.

Tcl_DeleteFileHandler peut être appelé pour supprimer le gestionnaire de fichier pour fd ; si aucun gestionnaire n'existe pour le fichier donné par fd, alors la procédure n'a aucun effet.

Le but des gestionnaires de fichiers est de permettre à une application de répondre aux événements tout en attendant que les fichiers soient prêts pour les E/S. Pour que cela fonctionne correctement, l'application peut avoir besoin d'utiliser des opérations d'E/S non bloquantes sur les fichiers pour lesquels des gestionnaires sont déclarés. Sinon, l'application pourrait se bloquer si elle lit ou écrit trop de données ; en attendant que les E/S se terminent, l'application ne pourra pas traiter d'autres événements. Utilisez Tcl_SetChannelOption avec -blocking pour définir le canal en mode bloquant ou non bloquant selon les besoins.

Notez que ces interfaces ne sont prises en charge que par l'implémentation Unix du notifier Tcl.
