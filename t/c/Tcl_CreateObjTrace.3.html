Tcl_CreateObjTrace(3)

Paquet: tcl

Licences: TCL

Tcl_CreateTrace(3) Procédures de bibliothèque Tcl Tcl_CreateTrace(3)

NOM

Tcl_CreateTrace, Tcl_CreateObjTrace, Tcl_DeleteTrace - organiser le traçage de l'exécution des commandes

SYNOPIS

#include <tcl.h>

Tcl_Trace
Tcl_CreateTrace(interp, level, proc, clientData)

Tcl_Trace
Tcl_CreateObjTrace(interp, level, flags, objProc, clientData, deleteProc)

Tcl_DeleteTrace(interp, trace)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur contenant la commande à tracer ou à ne plus tracer.
int level (entrée)
Seules les commandes à ce niveau d'imbrication ou en dessous seront tracées, sauf si 0 est spécifié. 1 signifie commandes de premier niveau uniquement, 2 signifie commandes de premier niveau ou celles qui sont invoquées comme conséquences immédiates de l'exécution de commandes de premier niveau (corps de procédure, commandes entre crochets, etc.) et ainsi de suite. Une valeur de 0 signifie que les commandes à n'importe quel niveau sont tracées.
int flags (entrée)
Indicateurs régissant l'exécution du traçage. Voir ci-dessous pour les détails.
Tcl_CmdObjTraceProc *objProc (entrée)
Procédure à appeler pour chaque commande exécutée. Voir ci-dessous pour les détails de la séquence d'appel.
Tcl_CmdTraceProc *proc (entrée)
Procédure à appeler pour chaque commande exécutée. Voir ci-dessous pour les détails de la séquence d'appel.
ClientData clientData (entrée)
Valeur arbitraire d'un mot à passer à objProc ou proc.
Tcl_CmdObjTraceDeleteProc *deleteProc (entrée)
Procédure à appeler lors de la suppression du traçage. Voir ci-dessous pour les détails de la séquence d'appel. Un pointeur NULL est acceptable et n'entraîne aucun rappel lors de la suppression du traçage.
Tcl_Trace trace (entrée)
Jeton pour le traçage à supprimer (valeur de retour d'un appel précédent à Tcl_CreateTrace).

DESCRIPTION

Tcl_CreateObjTrace organise le traçage des commandes. Après son appel, objProc sera invoqué avant que l'interpréteur Tcl n'appelle toute procédure de commande lors de l'évaluation des commandes dans interp. La valeur de retour de Tcl_CreateObjTrace est un jeton pour le traçage, qui peut être passé à Tcl_DeleteTrace pour supprimer le traçage. Il peut y avoir plusieurs traçages en vigueur simultanément pour le même interpréteur.

objProc doit avoir des arguments et un résultat qui correspondent au type, Tcl_CmdObjTraceProc:

typedef int Tcl_CmdObjTraceProc(
        ClientData clientData,
        Tcl_Interp* interp,
        int level,
        const char *command,
        Tcl_Command commandToken,
        int objc,
        Tcl_Obj *const objv[]);

Les paramètres clientData et interp sont des copies des arguments correspondants fournis à Tcl_CreateTrace. ClientData pointe généralement vers une structure de données spécifique à l'application qui décrit ce qu'il faut faire lorsque objProc est invoqué. Le paramètre level donne le niveau d'imbrication de la commande (1 pour les commandes de premier niveau passées à Tcl_Eval par l'application, 2 pour les commandes de niveau supérieur passées à Tcl_Eval dans le cadre de l'analyse ou de l'interprétation des commandes de niveau 1, et ainsi de suite). Le paramètre command pointe vers une chaîne contenant le texte de la commande, avant toute substitution d'argument. Le paramètre commandToken est un jeton de commande Tcl qui identifie la commande à invoquer. Le jeton peut être passé à Tcl_GetCommandName, Tcl_GetCommandInfoFromToken, ou Tcl_SetCommandInfoFromToken pour manipuler la définition de la commande. Les paramètres objc et objv désignent le nombre final de paramètres et le vecteur de paramètres qui seront passés à la commande, et qui ont subi toutes les substitutions.

Le rappel objProc est censé retourner un code de retour de statut Tcl standard. Si ce code est TCL_OK (le cas normal), alors l'interpréteur Tcl invoquera la commande. Tout autre code de retour est traité comme si la commande avait retourné ce statut, et la commande n'est pas invoquée.

Le rappel objProc ne doit modifier objv en aucune façon.

Le traçage ne se produira que pour les commandes à un niveau d'imbrication inférieur ou égal au paramètre level (c'est-à-dire que le paramètre level pour objProc sera toujours inférieur ou égal au paramètre level pour Tcl_CreateTrace).

Le traçage a un impact significatif sur les performances d'exécution car il fait en sorte que le compilateur de bytecode s'abstienne de générer du code en ligne pour des commandes Tcl telles que if et while afin qu'elles puissent être tracées. Si les traçages pour les commandes intégrées ne sont pas requis, le paramètre flags peut être défini sur la valeur constante TCL_ALLOW_INLINE_COMPILATION. Dans ce cas, les traçages sur les commandes intégrées peuvent ou non entraîner des rappels de traçage, en fonction de l'état de l'interpréteur, mais les performances d'exécution seront considérablement améliorées. (Cette fonctionnalité est souhaitable, par exemple, lors de l'utilisation de Tcl_CreateObjTrace pour implémenter un profileur de temps d'exécution.)

Les appels à objProc seront effectués par l'analyseur Tcl immédiatement avant qu'il n'appelle la procédure de commande pour la commande (cmdProc). Cela se produit après l'analyse et la substitution des arguments, de sorte que le traçage des commandes substituées se produit avant le traçage des commandes contenant les substitutions. S'il y a une erreur de syntaxe dans une commande, ou s'il n'y a pas de procédure de commande associée à un nom de commande, aucun traçage ne se produira pour cette commande. Si une chaîne passée à Tcl_Eval contient plusieurs commandes (entre crochets, ou sur différentes lignes), plusieurs appels à objProc seront effectués, un pour chaque commande.

Tcl_DeleteTrace supprime un traçage, de sorte qu'aucun appel futur ne sera effectué à la procédure associée au traçage. Après le retour de Tcl_DeleteTrace, l'appelant ne doit plus jamais utiliser le jeton trace.

Lorsque Tcl_DeleteTrace est appelé, l'interpréteur invoque le deleteProc qui a été passé comme paramètre à Tcl_CreateObjTrace. Le deleteProc doit correspondre au type, Tcl_CmdObjTraceDeleteProc:

typedef void Tcl_CmdObjTraceDeleteProc(
        ClientData clientData);

Le paramètre clientData sera le même que le paramètre clientData qui a été initialement passé à Tcl_CreateObjTrace.

Tcl_CreateTrace est une interface alternative pour le traçage de commandes, non recommandée pour les nouvelles applications. Elle est fournie pour la compatibilité ascendante avec le code développé pour les anciennes versions de l'interpréteur Tcl. Elle est similaire à Tcl_CreateObjTrace, sauf que son paramètre proc doit avoir des arguments et un résultat qui correspondent au type Tcl_CmdTraceProc:

typedef void Tcl_CmdTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        int level,
        char *command,
        Tcl_CmdProc *cmdProc,
        ClientData cmdClientData,
        int argc,
        const char *argv[]);

Les paramètres du rappel proc sont similaires à ceux du rappel objProc ci-dessus. Le commandToken est remplacé par cmdProc, un pointeur vers la procédure de commande (basée sur des chaînes) qui sera invoquée ; et cmdClientData, les données client qui seront passées à la procédure. Le paramètre objc est remplacé par un paramètre argv, qui donne les arguments de la commande sous forme de chaînes de caractères. Proc ne doit pas modifier les chaînes command ou argv.

Si un traçage créé avec Tcl_CreateTrace est en vigueur, la compilation en ligne des commandes Tcl telles que if et while est toujours désactivée. Il n'y a pas de notification lorsqu'un traçage créé avec Tcl_CreateTrace est supprimé. Il n'y a aucun moyen d'être notifié lors de la suppression du traçage créé par Tcl_CreateTrace. Il n'y a aucun moyen pour le proc associé à un appel à Tcl_CreateTrace d'interrompre l'exécution de command.
