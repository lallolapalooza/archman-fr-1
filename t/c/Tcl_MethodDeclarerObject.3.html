ARGUMENTS

Tcl_Interp *interp (in/out)
L'interpréteur contenant l'objet ou la classe dans laquelle créer ou mettre à jour une méthode.
Tcl_Object object (in)
L'objet dans lequel créer la méthode.
Tcl_Class class (in)
La classe dans laquelle créer la méthode.
Tcl_Obj *nameObj (in)
Le nom de la méthode à créer. Ne doit pas être NULL sauf lors de la création de constructeurs ou de destructeurs.
int isPublic (in)
Un indicateur indiquant la visibilité de la méthode. Les seules valeurs publiques supportées pour cet indicateur sont 0 pour une méthode non exportée et 1 pour une méthode exportée.
Tcl_MethodType *methodTypePtr (in)
Une description du type de la méthode à créer, ou le type de méthode à comparer.
ClientData clientData (in)
Un bloc de données qui est passé à l'implémentation de la méthode sans interprétation.
ClientData *clientDataPtr (out)
Un pointeur vers une variable dans laquelle écrire la valeur clientData fournie lors de la création de la méthode. Si NULL, la valeur clientData ne sera pas récupérée.
Tcl_Method method (in)
Une référence à une méthode à interroger.
Tcl_ObjectContext context (in)
Une référence à un contexte d'appel de méthode. Notez que le code client ne doit pas conserver une référence à un contexte.
int objc (in)
Le nombre d'arguments à passer à l'implémentation de la méthode.
Tcl_Obj *const *objv (in)
Un tableau d'arguments à passer à l'implémentation de la méthode.
int skip (in)
Le nombre d'arguments passés à l'implémentation de la méthode qui ne représentent pas des arguments « réels ».

DESCRIPTION

Une méthode est une opération effectuée sur un objet associé à l'objet. Chaque méthode doit être associée à un objet ou à une classe ; les méthodes associées à une classe sont associées à toutes les instances (directes et indirectes) de cette classe.

Étant donné une méthode, l'entité qui l'a déclarée peut être trouvée en utilisant Tcl_MethodDeclarerClass qui renvoie la classe à laquelle la méthode est associée (ou NULL si la méthode n'est associée à aucune classe) et Tcl_MethodDeclarerObject qui renvoie l'objet auquel la méthode est associée (ou NULL si la méthode n'est associée à aucun objet). Le nom de la méthode peut être obtenu avec Tcl_MethodName et si la méthode est exportée peut être obtenu avec Tcl_MethodIsPublic. Le type de la méthode peut également être inspecté de manière limitée ; la fonction Tcl_MethodIsType renvoie si une méthode est d'un type particulier, en assignant la valeur clientData à la variable indiquée par clientDataPtr si (cela n'est pas nul) et si le type correspond.

CRÉATION DE MÉTHODES

Les méthodes sont créées avec Tcl_NewMethod et Tcl_NewInstanceMethod, qui créent une méthode associée à une classe ou à un objet respectivement. Dans les deux cas, l'argument nameObj donne le nom de la méthode à créer, l'argument isPublic indique si la méthode doit être exportée initialement, l'argument methodTypePtr décrit l'implémentation de la méthode (voir la section METHOD TYPES) et l'argument clientData fournit des données d'implémentation spécifiques qui sont passées à l'implémentation de la méthode lorsqu'elle est appelée.

Lorsque l'argument nameObj de Tcl_NewMethod est NULL, une méthode sans nom est créée, qui est utilisée pour les constructeurs et les destructeurs. Les constructeurs doivent être installés dans leur classe avec la fonction Tcl_ClassSetConstructor, et les destructeurs (qui ne requièrent pas d'arguments) doivent être installés dans leur classe avec la fonction Tcl_ClassSetDestructor. Les méthodes sans nom ne doivent pas être utilisées à d'autres fins que les constructeurs ou les destructeurs, et les méthodes nommées ne doivent pas être utilisées comme telles. Il faut également noter qu'un NULL methodTypePtr est utilisé pour fournir un signe interne et ne doit pas être utilisé dans le code client.

CONTEXTES D'APPEL DE MÉTHODES

Lorsqu'une méthode est appelée, une référence à un contexte d'appel de méthode est passée comme l'un des arguments de la fonction d'implémentation. Ce contexte peut être inspecté pour fournir des informations sur l'appelant, mais ne doit pas être conservé au-delà du moment où l'appel de méthode se termine.

La méthode qui est appelée peut être obtenue à partir du contexte via Tcl_ObjectContextMethod, et l'objet qui a causé l'appel de méthode peut être obtenu avec Tcl_ObjectContextObject. Le nombre d'arguments qui doivent être ignorés (par exemple, le nom de l'objet et le nom de la méthode dans un appel normal) est lu avec Tcl_ObjectContextSkippedArgs, et le contexte peut également signaler s'il travaille comme filtre pour une autre méthode via Tcl_ObjectContextIsFiltering.

Pendant l'exécution d'une méthode, l'implémentation de la méthode peut choisir d'invoquer les étapes de la chaîne d'appel de méthodes qui viennent après l'implémentation actuelle de la méthode. Ceci (le cœur de la commande next) est fait avec Tcl_ObjectContextInvokeNext. Il faut noter que cette fonction ne modifie pas la pile d'appels, contrairement à la commande next ; si l'implémentation de la méthode a placé une ou plusieurs piles supplémentaires sur la pile dans le cadre de son implémentation, elle doit également être responsable de vider ces piles d'appels pendant l'exécution de la fonction Tcl_ObjectContextInvokeNext. Il faut également noter que le contexte d'appel de méthode n'est jamais supprimé pendant l'exécution de cette fonction.

TYPES DE MÉTHODES

Les types de méthodes sont décrits par un pointeur vers une structure Tcl_MethodType, qui est définie comme suit :

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

Le champ version permet l'extension future de la structure, et doit toujours être déclaré égal à TCL_OO_METHOD_VERSION_CURRENT. Le champ name fournit un nom lisible par l'homme pour le type, et est la valeur qui est exposée via les commandes info class methodtype et info object methodtype. Le champ callProc fournit une fonction qui est appelée lorsque la méthode est invoquée ; elle ne doit jamais être NULL.

Le champ deleteProc fournit une fonction qui est utilisée pour supprimer une méthode spécifique, et est appelée lorsque la méthode est remplacée ou supprimée ; si le champ est NULL, on suppose qu'aucune action spéciale n'est nécessaire pour supprimer le clientData.

Le champ cloneProc est une fonction qui est utilisée pour copier le clientData de la méthode (dans le cadre de Tcl_CopyObjectInstance) ou est NULL pour indiquer que le clientData peut simplement être copié directement.

SIGNATURE DE FONCTION TCL_METHODCALLPROC

La fonction callProc a la signature suivante :

typedef int Tcl_MethodCallProc(
    ClientData clientData,
    Tcl_Interp *interp,
    int objc,
    Tcl_Obj *const objv[]);

Le paramètre clientData est le même que celui qui a été fourni à Tcl_NewMethod ou Tcl_NewInstanceMethod lors de la création de la méthode. Les paramètres interp, objc et objv sont les mêmes que ceux qui ont été passés à la commande oo::object call ou à la commande oo::class call, et reflètent également le nom de la méthode et le nom de l'objet comme arguments supplémentaires si les méthodes sont implémentées en C. L'implémentation de la méthode doit renvoyer TCL_OK en cas de succès, ou TCL_ERROR en cas d'échec.

Il est à noter que lors de l'invocation des méthodes de classe à partir d'une commande oo::class call, le premier argument passé à la fonction callProc est le nom de la classe, et le nom de la méthode est le deuxième argument.

Le champ cloneProc a la signature suivante :

typedef Tcl_CloneProc *Tcl_CloneProc(
    ClientData clientData);

Le champ deleteProc a la signature suivante :

typedef void Tcl_MethodDeleteProc(
    ClientData clientData);

NOM

TCL_METHODCALLPROC_FUNC_SIGNATURE

SYNTAXE

Les fonctions correspondant à cette signature sont appelées lorsqu'une méthode est invoquée.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

L'argument clientData d'un Tcl_MethodCallProc est la valeur qui a été transmise lors de la création de la méthode, interp est un endroit où les scripts sont exécutés et où les variables sont accessibles, et c'est aussi là que le résultat de la méthode est placé. Les champs objc et objv donnent les objets paramètres de la méthode. Le contexte d'appel de la méthode peut être découvert via l'argument objectContext, et la valeur de retour d'un Tcl_MethodCallProc est un code de retour Tcl quelconque (par exemple, TCL_OK, TCL_ERROR).

SIGNATURE DE FONCTION Tcl_MethodDeleteProc

Les fonctions correspondant à cette signature sont utilisées lorsqu'une méthode est supprimée, soit lors de la création d'une nouvelle méthode, soit lorsque l'objet ou la classe est supprimé.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

L'argument clientData d'un Tcl_MethodDeleteProc sera le même que la valeur qui a été transmise à l'argument clientData de Tcl_NewMethod ou Tcl_NewInstanceMethod lors de la création de la méthode.

SIGNATURE DE FONCTION Tcl_CloneProc

Les fonctions correspondant à cette signature sont utilisées pour copier une méthode lorsque l'objet ou la classe est copié en utilisant Tcl_CopyObjectInstance (ou oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

L'argument interp donne un endroit où écrire un message d'erreur lorsque l'on tente de cloner l'objet et que cela échoue, auquel cas la fonction de clonage doit retourner TCL_ERROR ; elle retourne TCL_OK sinon. Le champ oldClientData d'un Tcl_CloneProc donne la valeur de la méthode en cours de copie, et le champ newClientDataPtr pointe vers un endroit où écrire la valeur de la méthode en cours de copie.
