ARGUMENTS

Tcl_Interp *interp (entree)
Si une erreur se produit lors de la conversion d'une valeur en valeur de dictionnaire, un message d'erreur est laissé dans la valeur de résultat de l'interpréteur, sauf si interp est NULL.
Tcl_Obj *dictPtr (entree/sortie)
Pointe vers la valeur de dictionnaire à manipuler. Si dictPtr ne pointe pas déjà vers une valeur de dictionnaire, une tentative sera faite pour la convertir.
Tcl_Obj *keyPtr (entree)
Pointe vers la clé de la paire clé/valeur manipulée dans la valeur de dictionnaire.
Tcl_Obj **keyPtrPtr (sortie)
Pointe vers une variable à laquelle sera affectée la clé d'une paire clé/valeur. Peut être NULL pour indiquer que l'appelant ne s'intéresse pas à la clé.
Tcl_Obj *valuePtr (entree)
Pointe vers la valeur de la paire clé/valeur manipulée dans la valeur de dictionnaire (ou sous-valeur, dans le cas de Tcl_DictObjPutKeyList.)
Tcl_Obj **valuePtrPtr (sortie)
Pointe vers une variable à laquelle sera affectée la valeur d'une paire clé/valeur. Pour Tcl_DictObjFirst et Tcl_DictObjNext, cela peut être NULL pour indiquer que l'appelant ne s'intéresse pas à la valeur.
int *sizePtr (sortie)
Pointe vers une variable à laquelle sera affecté le nombre de paires clé/valeur contenues dans le dictionnaire.
Tcl_DictSearch *searchPtr (entree/sortie)
Pointeur vers une structure utilisée pour suivre la progression de l'énumération de toutes les paires clé/valeur d'un dictionnaire. Le contenu de la structure sera initialisé par l'appel à Tcl_DictObjFirst. Si l'énumération doit être interrompue avant que toutes les valeurs du dictionnaire n'aient été retournées, le pointeur de recherche doit être passé à Tcl_DictObjDone pour permettre la libération des verrous internes.
int *donePtr (sortie)
Pointe vers une variable à laquelle une valeur non nulle sera écrite lorsque l'énumération des paires clé/valeur d'un dictionnaire sera terminée, et zéro sinon.
int keyc (entree)
Indique le nombre de clés qui seront fournies dans le tableau keyv.
Tcl_Obj *const *keyv (entree)
Tableau de keyc pointeurs vers des valeurs que Tcl_DictObjPutKeyList et Tcl_DictObjRemoveKeyList utiliseront pour localiser la paire clé/valeur à manipuler dans les sous-dictionnaires de la valeur de dictionnaire principale qui leur est passée.

DESCRIPTION

Les valeurs de dictionnaire Tcl ont une représentation interne qui supporte un mappage efficace des clés aux valeurs et qui garantit que l'ordre particulier des clés dans le dictionnaire reste le même, modulo les clés supprimées (qui les retirent de l'ordre) ou ajoutées (qui les ajoutent à la fin de l'ordre). Si réinterprété comme une liste, les valeurs aux indices pairs dans la liste seront les clés du dictionnaire, et chacune sera suivie (à l'indice impair) de la valeur qui lui est associée.

Les procédures décrites dans cette page de manuel sont utilisées pour créer, modifier, indexer et itérer sur les valeurs de dictionnaire à partir du code C.

Tcl_NewDictObj crée une nouvelle valeur de dictionnaire vide. La représentation textuelle de la valeur sera invalide, et le compteur de références de la valeur sera zéro.

Tcl_DictObjGet recherche la clé donnée dans le dictionnaire donné et écrit un pointeur vers la valeur associée à cette clé dans la variable pointée par valuePtrPtr, ou NULL si la clé n'a pas de correspondance dans le dictionnaire. Le résultat de cette procédure est TCL_OK, ou TCL_ERROR si dictPtr ne peut pas être converti en dictionnaire.

Tcl_DictObjPut met à jour le dictionnaire donné de sorte que la clé donnée corresponde à la valeur donnée ; chaque clé peut exister au plus une fois dans un dictionnaire particulier. Le dictionnaire ne doit pas être partagé, mais la clé et la valeur peuvent l'être. Cette procédure peut incrémenter le compteur de références de la clé et de la valeur s'il s'avère nécessaire de les stocker. Ni la clé ni la valeur ne doivent être NULL. Le résultat de cette procédure est TCL_OK, ou TCL_ERROR si dictPtr ne peut pas être converti en dictionnaire.

Tcl_DictObjRemove met à jour le dictionnaire donné de sorte que la clé donnée n'ait pas de correspondance avec une valeur. Le dictionnaire ne doit pas être partagé, mais la clé peut l'être. La clé réellement stockée dans le dictionnaire verra son compteur de références décrémenté si elle était présente. Ce n'est pas une erreur si la clé n'existait pas auparavant. Le résultat de cette procédure est TCL_OK, ou TCL_ERROR si dictPtr ne peut pas être converti en dictionnaire.

Tcl_DictObjSize met à jour la variable donnée avec le nombre de paires clé/valeur actuellement dans le dictionnaire donné. Le résultat de cette procédure est TCL_OK, ou TCL_ERROR si dictPtr ne peut pas être converti en dictionnaire.

Tcl_DictObjFirst commence une itération sur toutes les paires clé/valeur du dictionnaire donné, plaçant la clé et la valeur dans les variables pointées par les arguments keyPtrPtr et valuePtrPtr (qui peuvent être NULL pour indiquer que l'appelant ne s'intéresse ni à la clé ni à la valeur respectivement.) La paire clé/valeur suivante dans le dictionnaire peut être récupérée avec Tcl_DictObjNext. Les mises à jour concurrentes de la représentation interne du dictionnaire ne modifieront pas le traitement de l'itération, sauf si le dictionnaire n'est pas partagé, auquel cas cela déclenchera une terminaison prématurée de l'itération (ce que les scripts Tcl ne peuvent pas déclencher via la commande dict.) L'argument searchPtr pointe vers un contexte utilisé pour identifier quelle itération particulière est effectuée, et est initialisé par l'appel à Tcl_DictObjFirst. L'argument donePtr pointe vers une variable qui est mise à jour à zéro s'il reste d'autres paires clé/valeur à itérer, ou à une valeur non nulle si l'itération est terminée. L'ordre d'itération n'est pas défini par l'implémentation. Si l'argument dictPtr ne peut pas être converti en dictionnaire, Tcl_DictObjFirst retourne TCL_ERROR et l'itération n'est pas commencée, sinon elle retourne TCL_OK.

Lorsque Tcl_DictObjFirst est appelé sur un dictionnaire, un verrou est placé sur le dictionnaire pour permettre à ce dictionnaire d'être itéré en toute sécurité sans tenir compte des modifications apportées au dictionnaire pendant l'itération. Pour cette raison, une fois que l'itération sur les clés d'un dictionnaire est terminée (soit parce que toutes les valeurs ont été itérées, comme indiqué par la variable pointée par l'argument donePtr étant mise à un, soit parce qu'aucune valeur supplémentaire n'est requise), la fonction Tcl_DictObjDone doit être appelée avec le même searchPtr que celui passé à Tcl_DictObjFirst afin que les verrous internes puissent être libérés. Une fois qu'un searchPtr particulier est passé à Tcl_DictObjDone, le passer à Tcl_DictObjNext (sans l'avoir d'abord initialisé avec Tcl_DictObjFirst) n'entraînera la production d'aucune valeur et la variable pointée par donePtr sera mise à un. Il est sûr d'appeler Tcl_DictObjDone plusieurs fois sur le même searchPtr pour chaque appel à Tcl_DictObjFirst.

Les procédures Tcl_DictObjPutKeyList et Tcl_DictObjRemoveKeyList sont les analogues proches de Tcl_DictObjPut et Tcl_DictObjRemove respectivement, sauf qu'au lieu de travailler avec un seul dictionnaire, elles sont conçues pour opérer sur un arbre imbriqué de dictionnaires, avec des dictionnaires internes stockés comme valeurs à l'intérieur de dictionnaires externes. Les arguments keyc et keyv spécifient une liste de clés (avec les clés les plus externes en premier) qui agit comme un chemin vers la paire clé/valeur à affecter. Notez qu'il n'existe pas d'opération correspondante pour lire une valeur

NOM

Tcl_DictObjPutKeyList

SYNOPIS

Tcl_DictObjPutKeyList(interp, objPtr, search, key, value, done)

ARGUMENTS

interp : Interpréteur Tcl

objPtr : Objet dictionnaire

search : Objet Tcl_DictSearch

key : Objet Tcl_Obj

value : Objet Tcl_Obj

done : Entier

DESCRIPTION

Conserva toute la structure du fichier. Avec une utilisation répétée de Tcl_DictObjGet, il est facile de construire un chemin comme celui-ci. Avec Tcl_DictObjPutKeyList, des dictionnaires imbriqués sont créés pour les clés non terminales où elles n'existent pas encore. Avec Tcl_DictObjRemoveKeyList, toutes les clés non terminales doivent exister et avoir une valeur de dictionnaire.

EXEMPLE

Utilisation de l'interface d'itération de dictionnaire pour rechercher si une clé qui correspond à elle-même existe :

Tcl_DictSearch search;
Tcl_Obj *key, *value;
int done;
/*
 * Supposons que interp et objPtr soient des paramètres. C'est la manière idiomatique de commencer une itération sur le dictionnaire ; il établit un verrou sur la représentation interne qui garantit qu'il n'y a pas de modifications concurrentes lorsque la gestion normale des références est également utilisée. Le verrou est automatiquement libéré à la fin de l'itération, mais il doit être libéré manuellement si l'itération se termine par une sortie exceptionnelle. Il est cependant sûr de tenter de libérer le verrou même si nous avons terminé l'itération.
 */
if (Tcl_DictObjFirst(interp, objPtr, &search,
        &key, &value, &done) != TCL_OK) {
    return TCL_ERROR;
}
for (; !done ; Tcl_DictObjNext(&search, &key, &value, &done)) {
    /*
     * Note : strcmp() n'est pas une bonne méthode pour comparer des valeurs et est utilisé ici uniquement à titre de démonstration.
     */
    if (!strcmp(Tcl_GetString(key), Tcl_GetString(value))) {
        break;
    }
}
Tcl_DictObjDone(&search);
Tcl_SetObjResult(interp, Tcl_NewBooleanObj(!done));
return TCL_OK;
