ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour le rapport d'erreur et pour rechercher dans l'interpréteur un canal enregistré.
const char *fileName (in)
Le nom d'un fichier local ou distant.
const char *mode (in)
Indique comment le fichier doit être ouvert. Peut avoir n'importe quelle valeur permise par l'argument mode de la commande Tcl open.
int permissions (in)
Indicateurs POSIX de permissions, tels que 0644. Si un nouveau fichier est créé, ces permissions seront définies sur le fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour construire une chaîne de commandes. Ces valeurs ont la même signification que les arguments non-switch de la commande exec.
int flags (in)
Indique le dépôt des canaux standards dans la chaîne de commandes : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE. Si TCL_STDIN est activé, le canal d'entrée standard du premier enfant de la chaîne est le canal de la chaîne, sinon il est identique à l'entrée standard du processus appelant ; il en va de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas activé, la chaîne peut rediriger les canaux standards pour outrepasser les canaux standards spécifiés avec TCL_STDIN, TCL_STDOUT et TCL_STDERR. S'il est activé, ces redirections provoquent une erreur.
ClientData handle (in)
Un handle spécifique aux E/S pour un fichier opérationnel. Pour Unix, c'est un descripteur de fichier ; pour Windows, c'est un HANDLE.
int readOrWrite (in)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Le pointeur vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (in)
Le motif à rechercher, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl pour l'entrée ou la sortie. Il doit avoir été la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle seront stockés les caractères lus du canal.
int charsToRead (in)
Le nombre de caractères à lire du canal. Si le canal est en mode d'encodage binary, ceci est équivalent au nombre d'octets à lire du canal.
int appendFlag (in)
Si différent de zéro, les données lues du canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (out)
Un tampon dans lequel seront stockés les octets lus du canal.
int bytesToRead (in)
Le nombre d'octets à lire du canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle sera stockée la ligne lue du canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne dynamique dans laquelle sera stockée la ligne lue du canal. Elle doit avoir été initialisée par l'appelant. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne dynamique.
const char *input (in)
L'entrée à ajouter à un tampon de canal.
int inputLen (in)
Longueur de l'entrée.
int addAtEnd (in)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon du canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera écrit sur le canal.
const char *charBuf (in)
Un tampon contenant les caractères à écrire sur le canal.
const char *byteBuf (in)
Un tampon contenant les octets à écrire sur le canal.
int bytesToWrite (in)
Le nombre d'octets à consommer de charBuf ou byteBuf et à écrire sur le canal.
Tcl_WideInt offset (in)
À quelle distance du point d'accès du canal l'opération suivante sera appliquée, mesurée en octets depuis le point donné par seekMode. Peut être positif ou négatif.
int seekMode (in)
Par rapport à quel point on cherche ; utilisé avec offset pour calculer le nouveau point d'accès du canal. Les valeurs valides sont SEEK_SET, SEEK_CUR et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) à laquelle le canal sera tronqué.
const char *optionName (in)
Le nom d'une option applicable au canal, telle que -blocking. Peut avoir n'importe quelle valeur acceptée par la commande fconfigure.
Tcl_DString *optionValue (in)
Où est stockée la valeur d'une option ou une liste de toutes les options et leurs valeurs. Il doit avoir été initialisé par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Les mécanismes de canal Tcl fournissent un mécanisme indépendant du périphérique et de la plateforme pour effectuer des opérations d'entrée/sortie bufferisées sur une variété de types de fichiers, de sockets et de périphériques. Le mécanisme de canal est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans la page de manuel de Tcl_CreateChannel. Le mécanisme de canal fournit un schéma de bufferisation inspiré des E/S standards d'Unix, et permet également des opérations non bloquantes sur les canaux.

Les procédures décrites dans ce manuel sont les API C du niveau d'architecture de canal générique. Pour une description de l'architecture des pilotes de canal et comment implémenter des pilotes de canal pour de nouveaux types de canaux, voir la page de manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Ouvre un fichier nommé par fileName et crée un nouveau canal Tcl pour accéder au fichier. L'argument mode spécifie la façon dont le fichier doit être ouvert (par exemple, "r" pour lecture, "w" pour écriture, "a" pour ajout, "r+" pour lecture et écriture, etc.). L'argument permissions spécifie les permissions POSIX pour le fichier s'il est créé. Si une erreur se produit, un message d'erreur est stocké dans l'interpréteur interp et la procédure retourne NULL.

TCL_OPENCOMMANDCHANNEL

Ouvre une chaîne de commandes spécifiée par argv. Cette procédure est utilisée pour créer des canaux Tcl qui représentent les flux d'entrée/sortie standard des processus exécutés par la commande Tcl exec. L'argument flags est une combinaison OR des indicateurs TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE pour contrôler la manière dont les canaux standards sont gérés.

TCL_MAKEFILECHANNEL

Crée un nouveau canal Tcl à partir d'un handle de fichier existant (descripteur de fichier Unix ou HANDLE Windows). L'argument readOrWrite est une combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer les opérations autorisées sur le canal.

TCL_GETCHANNEL

Retourne un pointeur vers le canal Tcl nommé par channelName enregistré dans l'interpréteur interp. Si l'argument modePtr n'est pas NULL, il sera défini sur une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant l'état d'ouverture du canal.

TCL_GETCHANNELNAMES

Crée une valeur Tcl contenant une liste de tous les noms de canaux actuellement enregistrés dans l'interpréteur interp. La valeur de retour est le nombre d'éléments dans la liste.

TCL_GETCHANNELNAMESEX

Similaire à Tcl_GetChannelNames, mais ne retourne que les noms de canaux qui correspondent au modèle pattern (utilisant la correspondance de chaînes Tcl).

TCL_REGISTERCHANNEL

Enregistre un canal Tcl avec l'interpréteur interp, le rendant accessible par son nom.

TCL_UNREGISTERCHANNEL

Désenregistre un canal Tcl de l'interpréteur interp, le rendant inaccessible par son nom. Le canal doit être fermé avant d'être désenregistré.

TCL_DETACHCHANNEL

Sépare un canal Tcl de l'interpréteur interp. Cela empêche la plupart des opérations sur le canal à partir de Tcl, mais le canal reste ouvert. Utile pour transférer la propriété d'un canal à un autre processus ou à une bibliothèque.

TCL_ISTANDARDCHANNEL

Retourne vrai si channel est l'un des canaux standards (stdin, stdout, stderr) du processus Tcl.

TCL_CLOSE

Ferme le canal channel. Toutes les données en attente dans les tampons de sortie sont vidées. Si une erreur se produit, un message d'erreur est stocké dans l'interpréteur interp et la procédure retourne un code d'erreur.

TCL_READCHARS

Lit jusqu'à charsToRead caractères du canal channel et les stocke dans le Tcl_Obj readObjPtr. Si appendFlag est différent de zéro, les caractères lus sont ajoutés à la valeur existante de readObjPtr ; sinon, readObjPtr est réinitialisé avant la lecture. La procédure retourne le nombre de caractères réellement lus.

TCL_READ

Lit jusqu'à bytesToRead octets du canal channel et les stocke dans le tampon readBuf. La procédure retourne le nombre d'octets réellement lus. Ceci est généralement utilisé pour la lecture binaire.

TCL_GETSOBJ

Lit une ligne du canal channel (jusqu'à un caractère de nouvelle ligne ou la fin du fichier) et stocke le résultat dans le Tcl_Obj lineObjPtr. Le caractère de nouvelle ligne est consommé mais non inclus dans le résultat. La procédure retourne 1 si une ligne a été lue, 0 s'il n'y avait rien à lire (fin de fichier) ou -1 en cas d'erreur.

TCL_GETS

Similaire à Tcl_GetsObj, mais lit la ligne dans un Tcl_DString lineRead déjà alloué. La ligne lue est ajoutée à la fin de la chaîne dynamique existante.

TCL_UNGETS

Prépare des données d'entrée à être lues à partir du canal à une date ultérieure. L'argument input contient les données à "rembobiner", inputLen est sa longueur, et addAtEnd indique si les données doivent être ajoutées au début (0) ou à la fin (non-zéro) du tampon de lecture existant du canal.

TCL_WRITEOBJ

Écrit le contenu du Tcl_Obj writeObjPtr sur le canal channel. La procédure retourne le nombre d'octets effectivement écrits, ou -1 en cas d'erreur.

TCL_WRITECHARS

Écrit les caractères du tampon charBuf sur le canal channel. La procédure consomme jusqu'à bytesToWrite caractères du tampon. Retourne le nombre d'octets réellement écrits, ou -1 en cas d'erreur.

TCL_WRITE

Écrit les octets du tampon byteBuf sur le canal channel. La procédure consomme jusqu'à bytesToWrite octets du tampon. Retourne le nombre d'octets réellement écrits, ou -1 en cas d'erreur. Ceci est généralement utilisé pour l'écriture binaire.

TCL_READRAW

Lit des octets bruts du canal channel dans readBuf. La procédure lit jusqu'à bytesToRead octets. Contrairement à Tcl_Read, cela ignore les conversions de fin de ligne et les traductions de fin de ligne.

TCL_WRITERAW

Écrit des octets bruts du tampon byteBuf sur le canal channel. La procédure écrit jusqu'à bytesToWrite octets. Contrairement à Tcl_Write, cela ignore les conversions de fin de ligne et les traductions de fin de ligne.

TCL_EOF

Retourne vrai si la fin du fichier a été atteinte sur le canal channel pour la lecture.

TCL_FLUSH

Force le vidage de tous les tampons de sortie pour le canal channel vers le périphérique sous-jacent. Utile pour s'assurer que toutes les données écrites sont effectivement envoyées.

TCL_INPUTBLOCKED

Retourne vrai si le dernier appel de lecture sur le canal channel a bloqué parce qu'aucune donnée n'était disponible.

TCL_INPUTBUFFERED

Retourne le nombre d'octets actuellement dans le tampon d'entrée du canal channel qui n'ont pas encore été lus par l'application.

TCL_OUTPUTBUFFERED

Retourne le nombre d'octets actuellement dans le tampon de sortie du canal channel qui n'ont pas encore été écrits sur le périphérique sous-jacent.

TCL_SEEK

Définit le point d'accès actuel pour le canal channel. L'argument offset est le décalage et seekMode spécifie le point de référence (SEEK_SET pour le début, SEEK_CUR pour la position actuelle, SEEK_END pour la fin). La procédure retourne la nouvelle position du point d'accès, ou -1 en cas d'erreur.

TCL_TELL

Retourne la position actuelle du point d'accès pour le canal channel. Retourne -1 en cas d'erreur.

TCL_TRUNCATECHANNEL

Tronque le fichier associé au canal channel à la longueur spécifiée par length. La longueur doit être non négative. Utile pour les fichiers ouverts en écriture.

TCL_GETCHANNELOPTION

Récupère la valeur de l'option spécifiée par optionName pour le canal channel et la stocke dans le Tcl_DString optionValue. Si optionName est NULL, toutes les options et leurs valeurs sont stockées.

TCL_SETCHANNELOPTION

Définit la valeur de l'option spécifiée par optionName pour le canal channel à newValue. Cette procédure est utilisée pour modifier le comportement du canal, par exemple, pour le rendre bloquant ou non bloquant.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et retourne un descripteur de canal qui peut être utilisé pour effectuer des entrées et sorties sur le fichier. Cette API est calquée sur la procédure fopen de la bibliothèque d'E/S standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur la valeur Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel chaque fois que possible.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Elle crée une séquence de sous-processus spécifiés par les arguments argv et argc et retourne un canal qui peut être utilisé pour communiquer avec ces sous-processus. L'argument flags indique quel type de communication existera avec le pipeline de commandes.

Si le drapeau TCL_STDIN est défini, l'entrée standard du premier sous-processus sera liée au canal : écrire dans le canal fournira des données au sous-processus. Si TCL_STDIN n'est pas défini, l'entrée standard du premier sous-processus sera la même que l'entrée standard de cette application. Si TCL_STDOUT est défini, la sortie standard du dernier sous-processus pourra être lue depuis le canal ; sinon, elle sera dirigée vers la sortie standard de cette application. Si TCL_STDERR est défini, la sortie d'erreur standard de tous les sous-processus sera renvoyée au canal et résultera en une erreur lors de la fermeture du canal ; sinon, elle sera dirigée vers la sortie d'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas défini, alors argc et argv peuvent rediriger les descripteurs stdio pour remplacer TCL_STDIN, TCL_STDOUT, et TCL_STDERR ; s'il est défini, alors c'est une erreur pour argc et argv de remplacer les canaux stdio pour lesquels TCL_STDIN, TCL_STDOUT, et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un descripteur de fichier existant et spécifique à la plateforme. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel retourne un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur Tcl dans interp. Si un canal portant ce nom n'est pas enregistré dans cet interpréteur, la procédure retourne NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms selon le pattern. Si pattern est NULL, aucun filtrage ne sera effectué. La valeur de retour est TCL_OK si aucune erreur ne s'est produite lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur peuvent faire référence au canal dans les opérations d'entrée ou de sortie en utilisant le nom donné dans l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur Tcl peut appeler Tcl_RegisterChannel avec interp comme NULL, pour indiquer qu'il souhaite conserver une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et il ne sera fermé que lorsque le nombre correspondant d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code exécuté en dehors de tout interpréteur de détenir en toute sécurité une référence à un canal qui est également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code gérant les canaux standards. Si aucun canal standard n'a été initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un exposé général sur les canaux standards et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel supprime un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Si cette opération a supprimé le dernier enregistrement du canal dans un interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur Tcl peut appeler Tcl_UnregisterChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera maintenant fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel sauf qu'il fermera également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel supprime un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Au-delà de cela, cette commande n'a pas d'autre effet. Elle ne peut pas être utilisée sur les canaux standards (stdout, stderr, stdin), et retournera TCL_ERROR si on lui passe l'un de ces canaux.

Le code non associé à un interpréteur Tcl peut appeler Tcl_DetachChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standards, stdin, stdout ou stderr. Si c'est le cas, il retourne 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standards sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lorsque Tcl_Close est appelé. Les sorties mises en tampon sont vidées sur le périphérique de sortie du canal avant la destruction du canal, et toute entrée mise en tampon est discardée. S'il s'agit d'un canal bloquant, l'appel ne retourne pas tant que toutes les données mises en tampon n'ont pas été envoyées avec succès au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a des sorties mises en tampon qui ne peuvent pas être écrites sans bloquer, l'appel retourne immédiatement ; la sortie est vidée en arrière-plan et le canal sera fermé une fois que toutes les données mises en tampon auront été sorties. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close retourne TCL_OK. Si une erreur se produit, Tcl_Close retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré en utilisant Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a déjà été passé comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez plutôt utiliser Tcl_UnregisterChannel, qui appellera en interne Tcl_Close lorsque tous les appels à Tcl_RegisterChannel auront été mis en correspondance par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, convertissant les octets en UTF-8 en se basant sur l'encodage du canal et stockant les données produites dans la représentation chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Définir charsToRe

TCL_READCHARS, TCL_READOBJS, ET TCL_READ

Une valeur de -1 pour bytesToRead déclenchera la lecture de tous les caractères actuellement disponibles (mode non bloquant) ou de tout jusqu'à EOF (mode bloquant).

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé étaient disponibles. C'est ce qu'on appelle une lecture courte. En mode bloquant, cela ne peut se produire qu'à la fin du fichier. En mode non bloquant, une lecture courte peut également se produire s'il n'y a pas assez d'entrée disponible actuellement : Tcl_ReadChars renvoie un compte court plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour déterminer laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les diverses représentations de fin de ligne en la représentation interne canonique \n selon le mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les différents modes spécifiques à la plateforme sont décrits dans l'entrée de manuel de la commande Tcl fconfigure.

Par optimisation des performances, lors de la lecture à partir d'un canal avec le codage binary, les octets ne sont pas convertis en UTF-8 lorsqu'ils sont lus. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr sous forme de tableau d'octets. La représentation textuelle de cette valeur ne sera construite que si elle est nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette façon, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions connexes, puis écrites dans un canal sans avoir à supporter le coût de la conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'elle n'effectue pas de conversions de codage, quel que soit le codage du canal. Elle est dépréciée et existe pour des raisons de compatibilité descendante avec les extensions Tcl non internationalisées. Elle consomme des octets du channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par un nul. Son contenu est valide à partir de la position zéro jusqu'à, mais sans inclure, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne tient pas compte de l'empilement. Alors que Tcl_Read (et les autres fonctions de l'API) obtiennent toujours leurs données du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_ReadRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données du canal inférieur vers la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, en convertissant les octets en UTF-8 en fonction du codage du canal, jusqu'à ce qu'une ligne complète d'entrée ait été vue. Si le codage du canal est binary, chaque octet lu à partir du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception des caractères de fin de ligne terminaux, sont ajoutés à la représentation textuelle de lineObjPtr. Les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_GetsObj renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj renvoie également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est renvoyé, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité d'une entrée.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique fournie par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, à la tête ou à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si le channel a un EOF "collant" défini, aucune donnée ne sera ajoutée à la file d'entrée. Tcl_Ungets renvoie inputLen ou -1 si une erreur se produit.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données caractères à charBuf. Les caractères UTF-8 du tampon sont convertis dans le codage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par un nul et affiche tout jusqu'au nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal à none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée en sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un compte du nombre d'octets acceptés pour la sortie vers le canal. Il s'agit soit d'une valeur supérieure à zéro pour indiquer le succès, soit de -1 pour indiquer qu'une erreur s'est produite. Si une erreur se produit, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme selon l'option -translation pour le canal. Cela est fait même si le canal n'a pas de codage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'elle accepte une valeur Tcl dont le contenu sera affiché sur le canal. Les caractères UTF-8 de la représentation textuelle de writeObjPtr sont convertis dans le codage du canal et mis en file d'attente pour la sortie vers channel. Par optimisation des performances, lors de l'écriture dans un canal avec le codage binary, les caractères UTF-8 ne sont pas convertis lorsqu'ils sont écrits. Au lieu de cela, les octets dans la représentation interne de writeObjPtr sous forme de tableau d'octets sont écrits dans le canal. La représentation en tableau d'octets de la valeur sera construite si elle est nécessaire. De cette façon, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions connexes, puis écrites dans un canal sans avoir à supporter le coût de la conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'elle n'effectue pas de conversions de codage, quel que soit le codage du canal. Elle est dépréciée et existe pour des raisons de compatibilité descendante avec les extensions Tcl non internationalisées. Elle accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par un nul et affiche tout jusqu'au nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne tient pas compte de l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée dans le canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation vers le canal inférieur.

TCL_FLUSH

Tcl_Flush provoque l'écriture de toutes les données de sortie tamponnées pour channel dans son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données tamponnées n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal est non bloquant ; il lance une opération de vidage en arrière-plan qui écrira les données tamponnées dans le canal éventuellement, aussi vite que le canal est capable de les absorber.

La valeur de retour est normalement TCL_OK. Si une erreur se produit, Tcl_Flush renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données ultérieures seront lues ou écrites. La sortie tamponnée est vidée vers le canal et l'entrée tamponnée est rejetée, avant l'opération de recherche.

Tcl_Seek renvoie normalement le nouveau point d'accès. Si une erreur se produit, Tcl_Seek renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut ou peut ne pas avoir été déplacé.

TCL_TELL

Tcl_Tell renvoie le point d'accès actuel pour un canal. La valeur retournée est -1 si le canal ne supporte pas la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent à channel à une longueur donnée de length octets. Il renvoie TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, c'est le nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl dénommée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue.

TCL_EOF

Tcl_Eof renvoie une valeur non nulle si le canal channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

Tcl_InputBlocked renvoie une valeur non nulle si le canal channel est en mode non bloquant et que la dernière opération d'entrée a renvoyé moins de données que demandé car il n'y avait pas suffisamment de données disponibles. L'appel renvoie toujours zéro si le canal est en mode bloquant.

PROBLÈMES DE PLATEFORME

Les descripteurs renvoyés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que renvoyé par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel ou Tcl_MakeFileChannel. D'autres types de canaux peuvent renvoyer un type de descripteur différent sur les plateformes Windows.
