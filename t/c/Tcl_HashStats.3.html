ARGUMENTS

Tcl_HashTable *tablePtr (entrant)
Adresse de la structure de table de hachage (pour toutes les procédures sauf Tcl_InitHashTable, cela doit avoir été initialisé par un appel précédent à Tcl_InitHashTable).
int keyType (entrant)
Type de clés à utiliser pour la nouvelle table de hachage. Doit être soit TCL_STRING_KEYS, TCL_ONE_WORD_KEYS, TCL_CUSTOM_TYPE_KEYS, TCL_CUSTOM_PTR_KEYS, soit une valeur entière supérieure à 1.
Tcl_HashKeyType *typePtr (entrant)
Adresse de la structure qui définit le comportement de la table de hachage.
const void *key (entrant)
Clé à utiliser pour la recherche dans la table. La forme exacte dépend du keyType utilisé pour créer la table.
int *newPtr (sortant)
Le mot à l'adresse *newPtr est défini à 1 si une nouvelle entrée a été créée et à 0 s'il existait déjà une entrée pour key.
Tcl_HashEntry *entryPtr (entrant)
Pointeur vers une entrée de table de hachage.
ClientData value (entrant)
Nouvelle valeur à assigner à l'entrée de la table de hachage. N'a pas besoin d'avoir le type ClientData, mais doit tenir dans le même espace que ClientData.
Tcl_HashSearch *searchPtr (entrant)
Pointeur vers l'enregistrement à utiliser pour suivre la progression lors de l'énumération de toutes les entrées d'une table de hachage.

DESCRIPTION

Une table de hachage se compose de zéro ou plusieurs entrées, chacune composée d'une clé et d'une valeur. Étant donné la clé d'une entrée, les routines de hachage peuvent localiser très rapidement l'entrée, et donc sa valeur. Il peut y avoir au plus une entrée dans une table de hachage avec une clé particulière, mais de nombreuses entrées peuvent avoir la même valeur. Les clés peuvent prendre l'une des quatre formes : chaînes de caractères, valeurs d'un mot, tableaux d'entiers, ou clés personnalisées définies par une structure Tcl_HashKeyType (voir la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous). Toutes les clés d'une table donnée ont la même forme, qui est spécifiée lors de l'initialisation de la table.

La valeur d'une entrée de table de hachage peut être n'importe quoi qui tient dans le même espace qu'un pointeur “char *”. Les valeurs des entrées de table de hachage sont gérées entièrement par les clients, pas par le module de hachage lui-même. Généralement, la valeur de chaque entrée est un pointeur vers une structure de données gérée par le code client.

Les tables de hachage grossissent de manière fluide à mesure que le nombre d'entrées augmente, de sorte qu'il y a toujours moins de trois entrées par compartiment de hachage, en moyenne. Cela permet des recherches rapides indépendamment du nombre d'entrées dans une table.

Le noyau fournit trois fonctions pour l'initialisation des tables de hachage : Tcl_InitHashTable, Tcl_InitObjHashTable et Tcl_InitCustomHashTable.

Tcl_InitHashTable initialise une structure qui décrit une nouvelle table de hachage. L'espace pour la structure est fourni par l'appelant, pas par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. Tous les types de clés décrits plus loin sont autorisés, à l'exception de TCL_CUSTOM_TYPE_KEYS et TCL_CUSTOM_PTR_KEYS.

Tcl_InitObjHashTable est un wrapper autour de Tcl_InitCustomHashTable et initialise une table de hachage dont les clés sont des Tcl_Obj *.

Tcl_InitCustomHashTable initialise une structure qui décrit une nouvelle table de hachage. L'espace pour la structure est fourni par l'appelant, pas par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. KeyType doit avoir l'une des valeurs suivantes :

TCL_STRING_KEYS
Les clés sont des chaînes terminées par un caractère nul. Elles sont passées aux routines de hachage en utilisant l'adresse du premier caractère de la chaîne.
TCL_ONE_WORD_KEYS
Les clés sont des valeurs d'un seul mot ; elles sont passées aux routines de hachage et stockées dans les entrées de la table de hachage en tant que valeurs “char *”. La valeur du pointeur est la clé ; elle n'a pas besoin (et généralement ne le fait pas) de pointer vers une chaîne de caractères.
TCL_CUSTOM_TYPE_KEYS
Les clés sont de type arbitraire et sont stockées dans l'entrée. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous.
TCL_CUSTOM_PTR_KEYS
Les clés sont des pointeurs vers un type arbitraire et sont stockées dans l'entrée. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous.
autre
Si keyType n'est pas l'une des options ci-dessus, il doit s'agir d'une valeur entière supérieure à 1. Dans ce cas, les clés seront des tableaux de valeurs “int”, où keyType donne le nombre d'entiers dans chaque clé. Cela permet d'utiliser des structures comme clés. Toutes les clés doivent avoir la même taille. Les clés de tableau sont passées aux fonctions de hachage en utilisant l'adresse du premier entier du tableau.

Tcl_DeleteHashTable supprime toutes les entrées d'une table de hachage et libère la mémoire associée au tableau de compartiments et aux entrées de la table. Elle ne libère pas la structure de table elle-même (pointée par tablePtr), car la mémoire est supposée être gérée par le client. Tcl_DeleteHashTable ne libère pas non plus et ne manipule pas les valeurs des entrées de la table de hachage. Si les valeurs des entrées pointent vers de la mémoire allouée dynamiquement, il est de la responsabilité du client de libérer ces structures avant de supprimer la table.

Tcl_CreateHashEntry localise l'entrée correspondant à une clé particulière, créant une nouvelle entrée dans la table s'il n'y en existait pas déjà avec la clé donnée. Si une entrée existait déjà avec la clé donnée, alors *newPtr est mis à zéro. Si une nouvelle entrée a été créée, alors *newPtr est mis à une valeur non nulle et la valeur de la nouvelle entrée sera mise à zéro. La valeur de retour de Tcl_CreateHashEntry est un pointeur vers l'entrée, qui peut être utilisé pour récupérer et modifier la valeur de l'entrée ou pour supprimer l'entrée de la table.

Tcl_DeleteHashEntry supprimera une entrée existante d'une table. La mémoire associée à l'entrée elle-même sera libérée, mais le client est responsable de tout nettoyage associé à la valeur de l'entrée, tel que la libération d'une structure à laquelle elle pointe.

Tcl_FindHashEntry est similaire à Tcl_CreateHashEntry sauf qu'elle ne crée pas de nouvelle entrée si la clé n'existe pas ; au lieu de cela, elle renvoie NULL comme résultat.

Tcl_GetHashValue et Tcl_SetHashValue sont utilisées pour lire et écrire la valeur d'une entrée, respectivement. Les valeurs sont stockées et récupérées sous le type “ClientData”, qui est assez grand pour contenir une valeur de pointeur. Sur presque toutes les machines, c'est aussi assez grand pour contenir une valeur entière.

Tcl_GetHashKey renvoie la clé d'une entrée de table de hachage donnée, soit comme un pointeur vers une chaîne, une clé d'un seul mot (“char *”), soit comme un pointeur vers le premier mot d'un tableau d'entiers, selon le keyType utilisé pour créer une table de hachage. Dans tous les cas, Tcl_GetHashKey renvoie un résultat de type “char *”. Lorsque la clé est une chaîne ou un tableau, le résultat de Tcl_GetHashKey pointe vers des informations dans l'entrée de la table ; ces informations resteront valides jusqu'à ce que l'entrée soit supprimée ou que sa table soit supprimée.

Tcl_FirstHashEntry et Tcl_NextHashEntry peuvent être utilisées pour parcourir toutes les entrées d'une table de hachage.

DESCRIPTION

Une structure de type "Tcl_HashSearch", fournie par le client, est utilisée pour suivre la progression dans la table. Tcl_FirstHashEntry initialise l'enregistrement de recherche et renvoie la première entrée de la table (ou NULL si la table est vide). Chaque appel ultérieur à Tcl_NextHashEntry renvoie l'entrée suivante dans la table ou NULL si la fin de la table a été atteinte. Un appel à Tcl_FirstHashEntry suivi d'appels à Tcl_NextHashEntry renverra chaque entrée de la table exactement une fois, dans un ordre arbitraire. Il est déconseillé de modifier la structure de la table, par exemple en créant ou en supprimant des entrées, pendant que la recherche est en cours, à l'exception de la suppression de l'entrée renvoyée par Tcl_FirstHashEntry ou Tcl_NextHashEntry.

Tcl_HashStats renvoie une chaîne allouée dynamiquement avec des informations globales sur une table de hachage, telles que le nombre d'entrées qu'elle contient, le nombre de compartiments dans son tableau de hachage et l'utilisation des compartiments. Il incombe à l'appelant de libérer la chaîne de résultats en la passant à ckfree.

Le fichier d'en-tête tcl.h définit les structures de données réelles utilisées pour implémenter les tables de hachage. Ceci est nécessaire pour que les clients puissent allouer des structures Tcl_HashTable et pour que des macros puissent être utilisées pour lire et écrire les valeurs des entrées. Cependant, les utilisateurs des routines de hachage ne doivent jamais se référer directement à aucun des champs d'aucune des structures de données liées au hachage ; utilisez les procédures et les macros définies ici.

LA STRUCTURE TCL_HASHKEYTYPE

Les extensions peuvent définir de nouveaux types de clés de hachage en définissant quatre procédures, en initialisant une structure Tcl_HashKeyType pour décrire le type et en appelant Tcl_InitCustomHashTable. La structure Tcl_HashKeyType est définie comme suit :

typedef struct Tcl_HashKeyType {
    int version;
    int flags;
    Tcl_HashKeyProc *hashKeyProc;
    Tcl_CompareHashKeysProc *compareKeysProc;
    Tcl_AllocHashEntryProc *allocEntryProc;
    Tcl_FreeHashEntryProc *freeEntryProc;
} Tcl_HashKeyType;

Le membre version est la version de la table. Si cette structure est étendue à l'avenir, la version peut être utilisée pour distinguer différentes structures. Elle doit être définie à TCL_HASH_KEY_TYPE_VERSION.

Le membre flags est 0 ou une ou plusieurs des valeurs suivantes combinées par OR :

TCL_HASH_KEY_RANDOMIZE_HASH
Certains éléments, comme les pointeurs, ne hachent pas bien car ils n'utilisent pas les bits de poids faible. Si ce drapeau est défini, la table de hachage tentera de rectifier cela en randomisant les bits, puis en utilisant les N bits de poids fort comme indice dans la table.
TCL_HASH_KEY_SYSTEM_HASH
Ce drapeau force Tcl à utiliser les procédures d'allocation de mémoire fournies par le système d'exploitation lors de l'allocation et de la libération de la mémoire utilisée pour stocker les structures de données de la table de hachage, et non les propres routines d'allocation de mémoire personnalisées de Tcl. Ceci est important si la table de hachage doit être utilisée dans l'implémentation d'un ensemble personnalisé de routines d'allocation, ou quelque chose dont un ensemble personnalisé de routines d'allocation pourrait dépendre, afin d'éviter toute dépendance circulaire.

Le membre hashKeyProc contient l'adresse d'une fonction appelée pour calculer une valeur de hachage pour la clé.

typedef unsigned int Tcl_HashKeyProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

Si ceci est NULL, alors keyPtr est utilisé et TCL_HASH_KEY_RANDOMIZE_HASH est supposé.

Le membre compareKeysProc contient l'adresse d'une fonction appelée pour comparer deux clés.

typedef int Tcl_CompareHashKeysProc(
        void *keyPtr,
        Tcl_HashEntry *hPtr);

Si ceci est NULL, alors les pointeurs keyPtr sont comparés. Si les clés ne correspondent pas, la fonction renvoie 0, sinon elle renvoie 1.

Le membre allocEntryProc contient l'adresse d'une fonction appelée pour allouer de l'espace pour une entrée et initialiser la clé et clientData.

typedef Tcl_HashEntry *Tcl_AllocHashEntryProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

Si ceci est NULL, alors Tcl_Alloc est utilisé pour allouer suffisamment d'espace pour un Tcl_HashEntry, le pointeur de clé est assigné à key.oneWordValue et clientData est défini à NULL. Les clés de type chaîne et les clés de tableau utilisent cette fonction pour allouer suffisamment d'espace pour l'entrée et la clé dans un seul bloc, au lieu de le faire en deux blocs. Cela permet d'économiser de l'espace pour un pointeur vers la clé depuis l'entrée et une autre allocation mémoire. Les clés Tcl_Obj* utilisent cette fonction pour allouer suffisamment d'espace pour une entrée et incrémenter le compteur de références sur la valeur.

Le membre freeEntryProc contient l'adresse d'une fonction appelée pour libérer de l'espace pour une entrée.

typedef void Tcl_FreeHashEntryProc(
        Tcl_HashEntry *hPtr);

Si ceci est NULL, alors Tcl_Free est utilisé pour libérer l'espace de l'entrée. Les clés Tcl_Obj* utilisent cette fonction pour décrémenter le compteur de références sur la valeur.
