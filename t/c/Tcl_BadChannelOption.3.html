DESCRIPTION

Tcl utilise une architecture de canaux à deux couches. Elle fournit une couche supérieure générique pour permettre aux programmes C et Tcl d'effectuer des entrées et sorties en utilisant les mêmes API pour une variété de fichiers, périphériques, sockets, etc. Les API C génériques sont décrites dans la page de manuel de Tcl_OpenFileChannel.

La couche inférieure fournit des pilotes de canaux spécifiques au type pour chaque type d'appareil pris en charge sur chaque plateforme. Cette page de manuel décrit les API C utilisées pour communiquer entre la couche générique et les pilotes de canaux spécifiques au type. Elle explique également comment de nouveaux types de canaux peuvent être ajoutés en fournissant de nouveaux pilotes de canaux.

Les pilotes de canaux se composent d'un certain nombre de composants : Premièrement, chaque pilote de canal fournit une structure Tcl_ChannelType contenant des pointeurs vers des fonctions implémentant les diverses opérations utilisées par la couche générique pour communiquer avec le pilote de canal. La structure Tcl_ChannelType et les fonctions auxquelles elle fait référence sont décrites dans la section TCL_CHANNELTYPE, ci-dessous.

Deuxièmement, les pilotes de canaux fournissent généralement une commande Tcl pour créer des instances de ce type de canal. Par exemple, la commande Tcl open crée des canaux qui utilisent les pilotes de canaux de fichier et de commande, et la commande Tcl socket crée des canaux qui utilisent des sockets TCP pour la communication réseau.

Troisièmement, un pilote de canal fournit facultativement une fonction C pour ouvrir des instances de canal de ce type. Par exemple, Tcl_OpenFileChannel ouvre un canal qui utilise le pilote de canal de fichier, et Tcl_OpenTcpClient ouvre un canal qui utilise le protocole réseau TCP. Ces fonctions de création utilisent généralement Tcl_CreateChannel en interne pour ouvrir le canal.

Pour ajouter un nouveau type de canal, vous devez implémenter une API C ou une commande Tcl qui ouvre un canal en appelant Tcl_CreateChannel. Lorsque votre pilote appelle Tcl_CreateChannel, il passe une structure Tcl_ChannelType décrivant les procédures d'E/S du pilote. La couche générique appellera alors les fonctions référencées dans cette structure pour effectuer des opérations sur le canal.

Tcl_CreateChannel ouvre un nouveau canal et y associe les typePtr et instanceData fournis. Le canal est ouvert dans le mode indiqué par mask. Pour une discussion sur les pilotes de canaux, leurs opérations et la structure Tcl_ChannelType, voir la section TCL_CHANNELTYPE, ci-dessous.

Tcl_CreateChannel interagit avec le code qui gère les canaux standard. Une fois qu'un canal standard a été initialisé soit par un appel à Tcl_GetStdChannel, soit par un appel à Tcl_SetStdChannel, la fermeture de ce canal standard fera que le prochain appel à Tcl_CreateChannel fera également du nouveau canal le nouveau canal standard. Voir Tcl_StandardChannels pour un traité général sur les canaux standard et le comportement de la bibliothèque Tcl à leur égard.

Tcl_GetChannelInstanceData retourne les données d'instance associées au canal dans channel. Ceci est identique à l'argument instanceData dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelType retourne un pointeur vers la structure Tcl_ChannelType utilisée par le canal dans l'argument channel. Ceci est identique à l'argument typePtr dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelName retourne une chaîne contenant le nom associé au canal, ou NULL si l'argument channelName de Tcl_CreateChannel était NULL.

FONCTIONS DE CANAL

Ces fonctions sont destinées à être utilisées par les pilotes de canal personnalisés pour gérer et interagir avec les canaux Tcl. Elles fournissent des opérations de bas niveau pour interroger et manipuler l'état et les descripteurs d'un canal.

Tcl_GetChannelHandle renvoie un descripteur de périphérique pour le canal spécifié et la direction donnée (entrée ou sortie). Ce descripteur est spécifique au pilote et peut être utilisé par le code du pilote pour interagir directement avec le périphérique sous-jacent. Si le canal n'a pas de descripteur de périphérique pour la direction spécifiée, la fonction renvoie la valeur spécifiée par handlePtr et renvoie TCL_OK. Si le canal n'a pas de descripteur de périphérique pour la direction spécifiée, alors TCL_ERROR est retourné à la place. Différents pilotes de canal retourneront différents types de descripteurs. Référez-vous aux entrées du manuel pour chaque pilote afin de déterminer le type de descripteur retourné.

Tcl_GetChannelThread renvoie l'identifiant du thread gérant actuellement le channel spécifié. Cela permet aux pilotes de canal d'envoyer leurs événements de fichier à la file d'événements correcte, même pour un cœur multi-thread.

Tcl_GetChannelMode renvoie une combinaison OR de TCL_READABLE et TCL_WRITABLE, indiquant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelBufferSize renvoie la taille, en octets, des tampons alloués pour stocker les entrées ou sorties dans le channel. Si la valeur n'a pas été définie par un appel précédent à Tcl_SetChannelBufferSize, décrit ci-dessous, alors la valeur par défaut de 4096 est renvoyée.

Tcl_SetChannelBufferSize définit la taille, en octets, des tampons qui seront alloués lors des opérations ultérieures sur le canal pour stocker les entrées ou sorties. L'argument size doit être compris entre un et un million, permettant des tampons de un octet à un million d'octets. Si size est en dehors de cette plage, Tcl_SetChannelBufferSize définit la taille du tampon à 4096.

Tcl_NotifyChannel est appelé par un pilote de canal pour indiquer à la couche générique que les événements spécifiés par mask se sont produits sur le canal. Les pilotes de canal sont responsables de l'invocation de cette fonction chaque fois que les gestionnaires de canal doivent être appelés pour le canal (ou que d'autres tâches en attente comme une purge d'écriture doivent être effectuées). Voir WATCHPROC ci-dessous pour plus de détails.

Tcl_BadChannelOption est appelé à partir du setOptionProc ou getOptionProc spécifique au pilote pour générer un message d'erreur complet.

Tcl_ChannelBuffered renvoie le nombre d'octets d'entrée actuellement mis en tampon dans le tampon interne (zone de retour en arrière) du canal lui-même. Il ne rapporte pas les données dans les tampons globaux pour la pile de canaux dont fait partie le canal fourni.

Tcl_IsChannelShared vérifie le compteur de références du channel spécifié et renvoie si le channel était partagé entre plusieurs interpréteurs (résultat == 1) ou non (résultat == 0).

Tcl_IsChannelRegistered vérifie si le channel spécifié est enregistré dans l'interpréteur interp donné (résultat == 1) ou non (résultat == 0).

Tcl_IsChannelExisting vérifie si un canal portant le nom spécifié est enregistré dans la liste globale (du thread) de tous les canaux (résultat == 1) ou non (résultat == 0).

Tcl_CutChannel retire le channel spécifié de la liste globale (du thread) de tous les canaux (du thread courant). L'application à un canal toujours enregistré dans un interpréteur n'est pas autorisée. Notifie également le pilote si la version de Tcl_ChannelType est TCL_CHANNEL_VERSION_4 (ou supérieure), et si Tcl_DriverThreadActionProc est défini pour celui-ci.

Tcl_SpliceChannel ajoute le channel spécifié à la liste globale (du thread) de tous les canaux (du thread courant). L'application à un canal enregistré dans un interpréteur n'est pas autorisée. Notifie également le pilote si la version de Tcl_ChannelType est TCL_CHANNEL_VERSION_4 (ou supérieure), et si Tcl_DriverThreadActionProc est défini pour celui-ci.

Tcl_ClearChannelHandlers supprime tous les gestionnaires de canal et les scripts d'événements associés au channel spécifié, interrompant ainsi tout traitement d'événements pour ce canal.

TCL_CHANNELTYPE

Un pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers des fonctions qui implémentent les diverses opérations sur un canal ; ces opérations sont invoquées au besoin par la couche générique. La structure a été versionnée à partir de Tcl 8.3.2/8.4 pour corriger un problème avec les pilotes de canal empilés. Voir la section OLD CHANNEL TYPES ci-dessous pour plus de détails sur l'ancienne structure.

La structure Tcl_ChannelType contient les champs suivants :

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Il n'est pas nécessaire de fournir des implémentations pour toutes les opérations de canal. Celles qui ne sont pas nécessaires peuvent être définies sur NULL dans la structure : blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc et close2Proc, en plus de flushProc, handlerProc, threadActionProc et truncateProc. Les autres fonctions qui ne peuvent pas être implémentées de manière significative devraient renvoyer EINVAL lorsqu'elles sont appelées, pour indiquer que les opérations qu'elles représentent ne sont pas disponibles. Notez également que wideSeekProc peut être NULL si seekProc l'est.

L'utilisateur ne doit utiliser que la structure ci-dessus pour l'instanciation de Tcl_ChannelType. Lors de la référence aux champs d'une structure Tcl_ChannelType, les fonctions suivantes doivent être utilisées pour obtenir les valeurs : Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc ou Tcl_ChannelHandlerProc.

La modification des structures a été effectuée de manière à ce que les types de canaux standard soient binaires compatibles. Cependant, les types de canaux qui utilisent des canaux empilés (c'est-à-dire TLS, Trf) ont de nouvelles versions pour correspondre au changement ci-dessus, car le code précédent pour les canaux empilés avait des problèmes.

TYPENAME

Le champ typeName contient une chaîne terminée par null qui identifie le type du périphérique implémenté par ce pilote, par exemple file ou socket.

Cette valeur peut être récupérée avec Tcl_ChannelName, qui renvoie un pointeur vers la chaîne.

VERSION

Le champ version doit être défini sur la version de la structure dont vous avez besoin. TCL_CHANNEL_VERSION_2 est le minimum recommandé. TCL_CHANNEL_VERSION_3 doit être défini pour spécifier le membre wideSeekProc. TCL_CHANNEL_VERSION_4 doit être défini pour spécifier le membre threadActionProc (inclut wideSeekProc). TCL_CHANNEL_VERSION_5 doit être défini pour spécifier le membre truncateProc (inclut wideSeekProc et threadActionProc). S'il n'est défini sur aucune de ces valeurs, on suppose que ce Tcl_ChannelType a la structure d'origine. Voir OLD CHANNEL TYPES pour plus de détails. Bien que Tcl reconnaisse et fonctionne avec les deux structures, les canaux empilés doivent être au moins de TCL_CHANNEL_VERSION_2 pour fonctionner correctement.

Cette valeur peut être récupérée avec Tcl_ChannelVersion, qui renvoie l'une des valeurs TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 ou TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

Le champ blockModeProc contient l'adresse d'une fonction appelée par la couche générique pour définir le mode bloquant et non bloquant sur le périphérique. BlockModeProc doit correspondre au prototype suivant :

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

L'argument instanceData est le même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. L'argument mode est soit TCL_MODE_BLOCKING, soit TCL_MODE_NONBLOCKING pour définir le périphérique en mode bloquant ou non bloquant. La fonction doit renvoyer zéro si l'opération a réussi, ou un code d'erreur POSIX non nul si l'opération a échoué.

Si l'opération réussit, la fonction peut modifier l' instanceData fourni pour enregistrer que le canal est entré en mode bloquant ou non bloquant et pour implémenter le comportement bloquant ou non bloquant. Pour certains types de périphériques, le comportement bloquant et non bloquant peut être implémenté par le système d'exploitation sous-jacent ; pour d'autres types de périphériques, le comportement doit être émulé dans le pilote de canal.

Cette valeur peut être récupérée avec Tcl_ChannelBlockModeProc, qui renvoie un pointeur vers la fonction.

Un pilote de canal ne fournissant **pas** de blockModeProc doit être très, très prudent. Il doit indiquer précisément à la couche générique quel mode de blocage lui convient, et cela doit également être documenté pour l'utilisateur afin que le mode de blocage du canal ne soit pas modifié à une valeur inacceptable. Toute confusion ici peut conduire l'interpréteur à une interbloquage (fausse et difficile à trouver).

CLOSEPROC ET CLOSE2PROC

Le champ closeProc contient l'adresse d'une fonction appelée par la couche générique pour nettoyer les informations relatives au pilote lorsque le canal est fermé. CloseProc doit correspondre au prototype suivant :

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

L'argument instanceData est le même que la valeur fournie à Tcl_CreateChannel lors de la création du canal. La fonction doit libérer toute mémoire conservée par le pilote de canal pour ce canal, et fermer les périphériques d'entrée et de sortie encapsulés par ce canal. Toutes les sorties mises en file d'attente auront été purgées vers le périphérique avant l'appel de cette fonction, et aucune autre opération du pilote ne sera invoquée sur cette instance après l'appel du closeProc. Si l'opération de fermeture réussit, la procédure

doit retourner zéro ; sinon, elle doit retourner un code d'erreur POSIX non nul. De plus, si une erreur se produit et que interp n'est pas NULL, la procédure doit stocker un message d'erreur dans le résultat de l'interpréteur.

Alternativement, les canaux qui permettent de fermer indépendamment les côtés lecture et écriture peuvent définir closeProc sur TCL_CLOSE2PROC et définir close2Proc à l'adresse d'une fonction correspondant au prototype suivant :

typedef int Tcl_DriverClose2Proc(
        ClientData instanceData,
        Tcl_Interp *interp,
        int flags);

Le close2Proc sera appelé avec flags défini comme une combinaison OR de TCL_CLOSE_READ ou TCL_CLOSE_WRITE pour indiquer au pilote de fermer le côté lecture et/ou écriture du canal. Le pilote de canal peut être invoqué pour effectuer des opérations supplémentaires sur le canal après l'appel de close2Proc pour fermer un ou les deux côtés du canal. Si flags est 0 (zéro), le pilote doit fermer le canal comme décrit ci-dessus pour closeProc. Aucune opération supplémentaire ne sera invoquée sur cette instance après l'appel de close2Proc avec tous les indicateurs effacés. Dans tous les cas, la fonction close2Proc doit retourner zéro si l'opération de fermeture a réussi ; sinon, elle doit retourner un code d'erreur POSIX non nul. De plus, si une erreur se produit et que interp n'est pas NULL, la procédure doit stocker un message d'erreur dans le résultat de l'interpréteur.

Les valeurs closeProc et close2Proc peuvent être récupérées avec Tcl_ChannelCloseProc ou Tcl_ChannelClose2Proc, qui retournent un pointeur vers la fonction respective.

INPUTPROC

Le champ inputProc contient l'adresse d'une fonction appelée par la couche générique pour lire les données du fichier ou de l'appareil et les stocker dans un tampon interne. InputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création du canal. L'argument buf pointe vers un tableau d'octets dans lequel stocker les entrées de l'appareil, et l'argument bufSize indique combien d'octets sont disponibles à buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique. En cas d'erreur, la fonction doit définir cette variable avec un code d'erreur POSIX identifiant l'erreur survenue.

La fonction doit lire les données de l'appareil d'entrée encapsulé par le canal et les stocker dans buf. En cas de succès, la fonction doit retourner un entier non négatif indiquant le nombre d'octets lus depuis l'appareil d'entrée et stockés dans buf. En cas d'erreur, la fonction doit retourner -1. En cas d'erreur après que certaines données ont été lues depuis l'appareil, ces données sont perdues.

Si inputProc peut déterminer que l'appareil d'entrée dispose de certaines données disponibles mais moins que demandé par l'argument bufSize, la fonction ne doit tenter de lire que la quantité de données disponible et retourner sans bloquer. Si l'appareil d'entrée ne dispose d'aucune donnée disponible et que le canal est en mode non bloquant, la fonction doit retourner une erreur EAGAIN. Si l'appareil d'entrée ne dispose d'aucune donnée disponible et que le canal est en mode bloquant, la fonction doit bloquer pendant le temps le plus court possible jusqu'à ce qu'au moins un octet de données puisse être lu depuis l'appareil ; ensuite, elle doit retourner autant de données qu'elle peut lire sans bloquer.

Cette valeur peut être récupérée avec Tcl_ChannelInputProc, qui retourne un pointeur vers la fonction.

OUTPUTPROC

Le champ outputProc contient l'adresse d'une fonction appelée par la couche générique pour transférer des données d'un tampon interne vers l'appareil de sortie. OutputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création du canal. L'argument buf contient un tableau d'octets à écrire dans l'appareil, et l'argument toWrite indique le nombre d'octets à écrire depuis l'argument buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique. En cas d'erreur, la fonction doit définir cette variable avec un code d'erreur POSIX identifiant l'erreur.

La fonction doit écrire les données à buf dans l'appareil de sortie encapsulé par le canal. En cas de succès, la fonction doit retourner un entier non négatif indiquant le nombre d'octets écrits dans l'appareil de sortie. La valeur de retour est normalement la même que toWrite, mais peut être inférieure dans certains cas, par exemple si l'opération de sortie est interrompue par un signal. En cas d'erreur, la fonction doit retourner -1. En cas d'erreur, certaines données peuvent avoir été écrites sur l'appareil.

Si le canal est non bloquant et que l'appareil de sortie ne peut absorber aucune donnée, la fonction doit retourner -1 avec une erreur EAGAIN sans écrire aucune donnée.

Cette valeur peut être récupérée avec Tcl_ChannelOutputProc, qui retourne un pointeur vers la fonction.

SEEKPROC ET WIDESEEKPROC

Le champ seekProc contient l'adresse d'une fonction appelée par la couche générique pour déplacer le point d'accès auquel les opérations d'entrée ou de sortie ultérieures seront appliquées. SeekProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

L'argument instanceData est la même valeur que celle donnée à Tcl_CreateChannel lors de la création de ce canal. Offset et seekMode ont la même signification que pour la procédure Tcl_Seek (décrite dans l'entrée de manuel de Tcl_OpenFileChannel).

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique pour retourner les valeurs errno de la fonction. La fonction doit définir cette variable avec un code d'erreur POSIX si une erreur se produit. La fonction doit stocker un code d'erreur EINVAL si le type de canal n'implémente pas le déplacement.

La valeur de retour est le nouveau point d'accès ou -1 en cas d'erreur. Si une erreur s'est produite, la fonction ne doit pas déplacer le point d'accès.

S'il existe un champ seekProc non NULL, le champ wideSeekProc peut contenir l'adresse d'une fonction alternative à utiliser qui gère les décalages larges (c'est-à-dire supérieurs à 32 bits), permettant ainsi les déplacements dans des fichiers de plus de 2 Go. Le wideSeekProc sera appelé de préférence au seekProc, mais les deux doivent être définis si le wideSeekProc est défini. WideSeekProc doit correspondre au prototype suivant :

typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

Les arguments et les valeurs de retour signifient la même chose qu'avec seekProc ci-dessus, sauf que le type des décalages et le type de retour sont différents.

La valeur seekProc peut être récupérée avec Tcl_ChannelSeekProc, qui retourne un pointeur vers la fonction, et de même, le wideSeekProc peut être récupéré avec Tcl_ChannelWideSeekProc.

SETOPTIONPROC

Le champ setOptionProc contient l'adresse d'une fonction appelée par la couche générique pour définir une option spécifique au type de canal sur un canal. setOptionProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

optionName est le nom d'une option à définir, et newValue est la nouvelle valeur pour cette option, sous forme de chaîne de caractères. instanceData est la même valeur que celle donnée à Tcl_CreateChannel lors de la création de ce canal. La fonction doit effectuer toute action spécifique au type de canal requise pour implémenter la nouvelle valeur de l'option.

Certaines options sont gérées par le code générique et cette fonction n'est jamais appelée pour les définir, par exemple -blockmode. D'autres options sont spécifiques à chaque type de canal et la procédure setOptionProc du pilote de canal sera appelée pour les implémenter. Le champ setOptionProc peut être NULL, ce qui indique que ce type de canal ne prend en charge aucune option spécifique au type.

Si la valeur de l'option est modifiée avec succès pour la nouvelle valeur, la fonction retourne TCL_OK. Elle doit appeler Tcl_BadChannelOption qui retourne elle-même TCL_ERROR si le optionName n'est pas reconnu. Si newValue spécifie une valeur pour l'option qui n'est pas prise en charge ou si une erreur d'appel système se produit, la fonction doit laisser un message d'erreur dans le résultat de interp si interp n'est pas NULL. La fonction doit également appeler Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

Cette valeur peut être récupérée avec Tcl_ChannelSetOptionProc, qui retourne un pointeur vers la fonction.

GETOPTIONPROC

Le champ getOptionProc contient l'adresse d'une fonction appelée par la couche générique pour obtenir la valeur d'une option spécifique au type de canal sur un canal. getOptionProc doit correspondre au prototype suivant :

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        Tcl_DString *optionValue);

OptionName est le nom d'une option prise en charge par ce type de canal. Si le nom de l'option n'est pas NULL, la fonction stocke sa valeur actuelle, sous forme de chaîne, dans la chaîne dynamique Tcl optionValue. Si optionName est NULL, la fonction stocke dans optionValue une liste alternée de toutes les options prises en charge et de leurs valeurs actuelles. En cas de succès, la fonction retourne TCL_OK. Elle doit appeler Tcl_BadChannelOption qui retourne elle-même TCL_ERROR si le option

Nom n'est pas reconnu. Si une erreur d'appel système se produit, la fonction doit laisser un message d'erreur dans le résultat de interp si interp n'est pas NULL. La fonction doit également appeler Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

Certaines options sont gérées par le code générique et cette fonction n'est jamais appelée pour récupérer leur valeur, par exemple -blockmode. D'autres options sont spécifiques à chaque type de canal et la procédure getOptionProc du pilote de canal sera appelée pour les implémenter. Le champ getOptionProc peut être NULL, ce qui indique que ce type de canal ne prend en charge aucune option spécifique au type.

Cette valeur peut être récupérée avec Tcl_ChannelGetOptionProc, qui renvoie un pointeur vers la fonction.

WATCHPROC

Le champ watchProc contient l'adresse d'une fonction appelée par la couche générique pour initialiser le mécanisme de notification d'événements afin de détecter les événements d'intérêt sur ce canal. WatchProc doit correspondre au prototype suivant :

typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

instanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. L'argument mask est une combinaison OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION ; il indique les événements que l'appelant souhaite détecter sur ce canal.

La fonction doit initialiser les mécanismes spécifiques au type de périphérique pour détecter lorsqu'un événement d'intérêt est présent sur le canal. Lorsque un ou plusieurs des événements désignés se produisent sur le canal, le pilote de canal est responsable d'appeler Tcl_NotifyChannel pour informer le module de canal générique. Le pilote doit veiller à ne pas affamer d'autres pilotes de canal ou sources de rappels en invoquant Tcl_NotifyChannel trop fréquemment. L'équité peut être assurée en utilisant la file d'attente d'événements Tcl pour permettre à l'événement du canal d'être planifié en séquence avec d'autres événements. Voir la description de Tcl_QueueEvent pour plus de détails sur la mise en file d'attente d'un événement.

Cette valeur peut être récupérée avec Tcl_ChannelWatchProc, qui renvoie un pointeur vers la fonction.

GETHANDLEPROC

Le champ getHandleProc contient l'adresse d'une fonction appelée par la couche générique pour récupérer un handle spécifique au périphérique du canal. GetHandleProc doit correspondre au prototype suivant :

typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

instanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. L'argument direction est soit TCL_READABLE pour récupérer le handle utilisé pour l'entrée, soit TCL_WRITABLE pour récupérer le handle utilisé pour la sortie.

Si l'implémentation du canal a des handles spécifiques au périphérique, la fonction doit récupérer le handle approprié associé au canal, selon l'argument direction. Le handle doit être stocké à l'emplacement référencé par handlePtr, et TCL_OK doit être renvoyé. Si le canal n'est pas ouvert pour la direction spécifiée, ou si l'implémentation du canal n'utilise pas de handles de périphérique, la fonction doit renvoyer TCL_ERROR.

Cette valeur peut être récupérée avec Tcl_ChannelGetHandleProc, qui renvoie un pointeur vers la fonction.

FLUSHPROC

Le champ flushProc est actuellement réservé pour une utilisation future. Il doit être défini sur NULL. FlushProc doit correspondre au prototype suivant :

typedef int Tcl_DriverFlushProc(
        ClientData instanceData);

Cette valeur peut être récupérée avec Tcl_ChannelFlushProc, qui renvoie un pointeur vers la fonction.

HANDLERPROC

Le champ handlerProc contient l'adresse d'une fonction appelée par la couche générique pour notifier le canal qu'un événement s'est produit. Il doit être défini pour les pilotes de canaux empilés qui souhaitent être notifiés des événements qui se produisent sur le canal sous-jacent (empilé). HandlerProc doit correspondre au prototype suivant :

typedef int Tcl_DriverHandlerProc(
        ClientData instanceData,
        int interestMask);

instanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. Le interestMask est une combinaison OR de TCL_READABLE ou TCL_WRITABLE ; il indique quel type d'événement s'est produit sur ce canal.

Cette valeur peut être récupérée avec Tcl_ChannelHandlerProc, qui renvoie un pointeur vers la fonction.

THREADACTIONPROC

Le champ threadActionProc contient l'adresse de la fonction appelée par la couche générique lorsqu'un canal est créé, fermé ou déplacé vers un autre thread, c'est-à-dire chaque fois que l'état du pilote spécifique au thread peut devoir être initialisé ou mis à jour. Il peut être NULL. L'action TCL_CHANNEL_THREAD_REMOVE est utilisée pour notifier le pilote qu'il doit mettre à jour ou supprimer toute donnée spécifique au thread qu'il pourrait maintenir pour le canal.

L'action TCL_CHANNEL_THREAD_INSERT est utilisée pour notifier le pilote qu'il doit mettre à jour ou initialiser toute donnée spécifique au thread qu'il pourrait maintenir en utilisant le thread appelant comme associé. Voir Tcl_CutChannel et Tcl_SpliceChannel pour plus de détails.

typedef void Tcl_DriverThreadActionProc(
        ClientData instanceData,
        int action);

instanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal.

Ces valeurs peuvent être récupérées avec Tcl_ChannelThreadActionProc, qui renvoie un pointeur vers la fonction.

TRUNCATEPROC

Le champ truncateProc contient l'adresse de la fonction appelée par la couche générique lorsqu'un canal est tronqué à une certaine longueur. Il peut être NULL.

typedef int Tcl_DriverTruncateProc(
        ClientData instanceData,
        Tcl_WideInt length);

instanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal, et length est la nouvelle longueur du fichier sous-jacent, qui ne doit pas être négative. Le résultat doit être 0 en cas de succès ou un code errno (approprié pour une utilisation avec Tcl_SetErrno) en cas d'échec.

Ces valeurs peuvent être récupérées avec Tcl_ChannelTruncateProc, qui renvoie un pointeur vers la fonction.

TCL_BADCHANNELOPTION

Cette procédure génère un message d'erreur “option incorrecte” dans un interpréteur (optionnel). Elle est utilisée par les pilotes de canaux lorsqu'une option Set/Get invalide est demandée. Son but est de concaténer la liste des options génériques aux options spécifiques et de factoriser la chaîne du message d'erreur des options génériques.

Elle renvoie toujours TCL_ERROR

Un message d'erreur est généré dans la valeur de résultat d'interp pour indiquer qu'une commande a été appelée avec une option incorrecte. Le message a la forme

    mauvaise option "blah" : devrait être l'une des
    <...options génériques...>+<...options spécifiques...>
donc vous obtenez par exemple : 
    mauvaise option "-blah" : devrait être l'une des -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, ou -sockname
lorsque appelée avec optionList égal à “peername sockname”

“blah” est l'argument optionName et “<options spécifiques>” est une liste d'options spécifiques séparées par des espaces. La fonction prend soin d'insérer des signes moins avant chaque option, des virgules après, et un “ou” avant la dernière option.

TYPES DE CANAUX OBSOLÈTES

La structure Tcl_ChannelType originale (8.3.1 et versions antérieures) contient les champs suivants :

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
} Tcl_ChannelType;

Il est toujours possible de créer des canaux avec la structure ci-dessus. Le code interne du canal déterminera la version. Il est impératif d'utiliser la nouvelle structure Tcl_ChannelType si vous créez un pilote de canal empilé, en raison de problèmes avec l'implémentation précédente des canaux empilés (dans les versions 8.2.0 à 8.3.1).

Avant la version 8.4.0 (c'est-à-dire lors des dernières versions de 8.3 et au début du cycle de développement de 8.4), la structure Tcl_ChannelType contenait les champs suivants :

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_ChannelTypeVersion version;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Lorsque la structure ci-dessus est enregistrée en tant que type de canal, le champ version doit toujours être TCL_CHANNEL_VERSION_2.

DESCRIPTION

The Tcl_BadChannelOption function is called by Tcl channel drivers when a user attempts to set or get an option that is not supported by that channel driver. It generates a Tcl error message indicating that the option is invalid for the given channel. The return value is always a Tcl object indicating an error.

TCL_CHANNELTYPE

The Tcl_ChannelType structure defines the interface between Tcl and a channel driver. It is a collection of function pointers that Tcl calls to perform operations on channels of that type. The structure contains the following fields:

typeName
A string containing the name of the channel type. This name is used to identify the channel type in Tcl commands.
driverProc
A pointer to the channel driver's main procedure. This procedure is called by Tcl to handle various channel-related operations, such as opening, closing, reading, and writing.
closeProc
A pointer to the channel driver's close procedure. This procedure is called by Tcl when the channel is closed.
inputProc
A pointer to the channel driver's input procedure. This procedure is called by Tcl to read data from the channel.
outputProc
A pointer to the channel driver's output procedure. This procedure is called by Tcl to write data to the channel.
seekProc
A pointer to the channel driver's seek procedure. This procedure is called by Tcl to reposition the channel's read/write pointer.
setNotifierProc
A pointer to the channel driver's set notifier procedure. This procedure is called by Tcl to set up a notifier for channel events.
threadActionProc
A pointer to the channel driver's thread action procedure. This procedure is called by Tcl when the channel is accessed from a different thread.
watchProc
A pointer to the channel driver's watch procedure. This procedure is called by Tcl to set up event monitoring for the channel.
notifyProc
A pointer to the channel driver's notify procedure. This procedure is called by Tcl when an event occurs on the channel.
getOptionProc
A pointer to the channel driver's get option procedure. This procedure is called by Tcl to retrieve the value of a channel option.
setOptionProc
A pointer to the channel driver's set option procedure. This procedure is called by Tcl to set the value of a channel option.
convertErrorProc
A pointer to the channel driver's convert error procedure. This procedure is called by Tcl to convert a system error code into a Tcl error message.
reconfigureChannelProc
A pointer to the channel driver's reconfigure channel procedure. This procedure is called by Tcl to reconfigure the channel.

TCL_BADCHANNELOPTION

The Tcl_BadChannelOption function is called by Tcl channel drivers when a user attempts to set or get an option that is not supported by that channel driver. It generates a Tcl error message indicating that the option is invalid for the given channel. The return value is always a Tcl object indicating an error.

OLD CHANNEL TYPES

The Tcl_ChannelType structure has been extended over time to include new fields. Older versions of Tcl may not support all of these fields. Channel drivers should be written to be compatible with older versions of Tcl by checking for the existence of these fields before using them.
