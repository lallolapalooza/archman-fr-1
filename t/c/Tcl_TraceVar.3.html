Tcl_TraceVar(3)

Tcl_TraceVar(3) Procédures de la Bibliothèque Tcl Tcl_TraceVar(3)

NOM

Tcl_TraceVar, Tcl_TraceVar2, Tcl_UntraceVar, Tcl_UntraceVar2, Tcl_VarTraceInfo, Tcl_VarTraceInfo2 - surveiller les accès aux variables

SYNTAXE

#include <tcl.h>

int
Tcl_TraceVar(interp, varName, flags, proc, clientData)

int
Tcl_TraceVar2(interp, name1, name2, flags, proc, clientData)

Tcl_UntraceVar(interp, varName, flags, proc, clientData)

Tcl_UntraceVar2(interp, name1, name2, flags, proc, clientData)

ClientData
Tcl_VarTraceInfo(interp, varName, flags, proc, prevClientData)

ClientData
Tcl_VarTraceInfo2(interp, name1, name2, flags, proc, prevClientData)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur contenant la variable.
const char *varName (in)
Nom de la variable. Peut faire référence à une variable scalaire, à une variable d'array sans indice, ou à une variable d'array avec un indice entre parenthèses.
int flags (in)
OU binaire des valeurs de TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS, TCL_TRACE_ARRAY, TCL_GLOBAL_ONLY, TCL_NAMESPACE_ONLY, TCL_TRACE_RESULT_DYNAMIC et TCL_TRACE_RESULT_OBJECT. Toutes les flags ne sont pas utilisées par toutes les procédures. Voir plus d'informations ci-dessous.
Tcl_VarTraceProc *proc (in)
Procédure à appeler lorsque l'une des opérations surveillées se produit.
ClientData clientData (in)
Valeur d'un mot à passer à proc.
const char *name1 (in)
Nom d'une variable scalaire ou d'un tableau (sans indice).
const char *name2 (in)
Pour une surveillance sur un élément d'un tableau, donne l'indice de l'élément. Pour les surveillances sur des variables scalaires ou des tableaux entiers, c'est NULL.
ClientData prevClientData (in)
S'il n'est pas NULL, donne la dernière valeur renvoyée par Tcl_VarTraceInfo ou Tcl_VarTraceInfo2, de sorte que cet appel renvoie des informations sur la prochaine surveillance. S'il est NULL, cet appel renvoie des informations sur la première surveillance.

DESCRIPTION

Tcl_TraceVar permet à une procédure C de surveiller et de contrôler l'accès à une variable Tcl, de sorte que la procédure C est appelée lorsqu'une variable est lue, écrite ou désinstallée. Si la surveillance est créée avec succès, Tcl_TraceVar renvoie TCL_OK. Si une erreur se produit (par exemple, varName spécifie un élément de tableau, mais la variable réelle n'est pas un tableau), TCL_ERROR est renvoyé et un message d'erreur est placé dans le résultat de l'interpréteur.

L'argument flags de Tcl_TraceVar indique quand la procédure de surveillance sera appelée et fournit des informations pour configurer la surveillance. Il est composé d'un OU binaire de n'importe quelle valeur parmi les suivantes :

TCL_GLOBAL_ONLY
Normalement, la variable est recherchée au niveau d'appel de procédure actuel ; si ce bit est défini, la variable est recherchée au niveau global, ignorant toute procédure active.
TCL_NAMESPACE_ONLY
Normalement, la variable est recherchée au niveau d'appel de procédure actuel ; si ce bit est défini, la variable est recherchée dans l'espace de noms actuel, ignorant toute procédure active.
TCL_TRACE_READS
proc est appelée lorsqu'une tentative de lecture de la variable est effectuée.
TCL_TRACE_WRITES
proc est appelée lorsqu'une tentative de modification de la variable est effectuée.
TCL_TRACE_UNSETS
proc est appelée lorsque la variable est désinstallée. Une variable peut être désinstallée explicitement avec une commande unset, ou implicitement lorsqu'une procédure retourne (ses variables locales sont automatiquement détruites) ou lorsque l'interpréteur est détruit (toutes les variables sont automatiquement détruites).
TCL_TRACE_ARRAY
proc est appelée lorsqu'une commande d'array est invoquée. Cela donne à la procédure de surveillance l'occasion de mettre à jour l'array avant que le nom d'array ou le get d'array ne soit invoqué. Note : ceci est appelé avant un set d'array, mais cela déclenche des surveillances d'écriture.
TCL_TRACE_RESULT_DYNAMIC
Le résultat de l'appel de proc est une chaîne dynamique qui sera libérée par la bibliothèque Tcl via un appel à ckfree. Ne doit pas être spécifié en même temps que TCL_TRACE_RESULT_OBJECT.
TCL_TRACE_RESULT_OBJECT
Le résultat de l'appel de proc est un Tcl_Obj* (converti en char*), avec un compteur de références d'au moins un. La propriété de cette référence est transmise au cœur de la bibliothèque Tcl pour être libérée (lorsque le cœur aura fini avec elle) par un appel à Tcl_DecrRefCount. Ne doit pas être spécifié en même temps que TCL_TRACE_RESULT_DYNAMIC.

Lorsqu'une des opérations spécifiées se produit sur la variable, proc est appelée. Elle doit avoir des arguments et des retours correspondant au type Tcl_VarTraceProc :

typedef char *Tcl_VarTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *name1,
        const char *name2,
        int flags);

Les paramètres clientData et interp auront les mêmes valeurs que celles passées à Tcl_TraceVar lors de la création de la surveillance. clientData pointe typiquement vers une structure de données spécifique à l'application qui décrit quoi faire lorsque proc est appelée. name1 et name2 donnent le nom de la variable surveillée sous la forme normale à deux parties (voir la description de Tcl_TraceVar2 pour plus de détails). flags est un OU binaire de bits fournissant diverses informations. L'un des bits TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_ARRAY ou TCL_TRACE_UNSETS sera défini dans flags pour indiquer quelle opération est effectuée sur la variable. Le bit TCL_GLOBAL_ONLY sera défini lorsque la variable accédée est globale et non accessible depuis le niveau d'appel de procédure actuel : la procédure de surveillance devra passer ce bit à des procédures associées comme Tcl_GetVar si elle tente d'accéder à la variable. Le bit TCL_NAMESPACE_ONLY sera défini lorsque la variable accédée est dans un espace de noms et non accessible depuis le niveau d'appel de procédure actuel : la procédure de surveillance devra passer ce bit à des procédures associées comme Tcl_GetVar si elle tente d'accéder à la variable. Le bit TCL_TRACE_DESTROYED sera défini dans flags si la surveillance est sur le point d'être détruite ; cette information peut être utile à proc pour nettoyer ses structures internes (voir la section TCL_TRACE_DESTROYED pour plus de détails). Enfin, le bit TCL_INTERP_DESTROYED sera défini si l'environnement complet de l'interpréteur est en cours de destruction. Lorsque ce bit est défini, proc doit être particulièrement prudent quant à ce qu'elle fait (voir la section TCL_INTERP_DESTROYED pour plus de détails). La valeur renvoyée par la procédure de surveillance doit normalement être NULL ; voir ERREURS RENVOYÉES pour plus d'informations sur d'autres valeurs possibles.

Tcl_UntraceVar peut être utilisé pour supprimer une surveillance. Si la variable spécifiée par interp, varName et flags a une surveillance avec flags, proc et clientData, alors la surveillance correspondante est supprimée. S'il n'existe pas de telle surveillance, l'appel à Tcl_UntraceVar n'a aucun effet. Les mêmes bits sont valides pour flags que pour les appels à Tcl_TraceVar.

Tcl_VarTraceInfo peut être utilisé pour récupérer des informations sur les surveillances définies pour une variable donnée. La valeur renvoyée par Tcl_VarTraceInfo est le clientData associé à une surveillance particulière. La surveillance doit être associée à la variable spécifiée par les arguments interp, varName et flags (seuls les bits TCL_GLOBAL_ONLY et TCL_NAMESPACE_ONLY de flags sont utilisés ; les autres bits sont ignorés) et sa procédure de surveillance doit être la même que l'argument proc. Si l'argument prevClientData est NULL, la valeur renvoyée correspond à la première (la plus récente) surveillance correspondante, ou NULL s'il n'y a pas de correspondance.

DESCRIPTION

The procedures Tcl_TraceVar, Tcl_UntraceVar, and Tcl_VarTraceInfo allow C code to monitor and control access to Tcl variables. Tcl_TraceVar installs a trace procedure, proc, which will be called whenever a variable named varName is accessed.

The flags argument specifies the types of accesses that should trigger the trace procedure. It is formed by OR-ing together zero or more of the following values:

TCL_TRACE_READ
Trace reads of the variable.
TCL_TRACE_WRITE
Trace writes to the variable.
TCL_TRACE_UNSET
Trace unsetting of the variable.
TCL_TRACE_ARRAY
Trace array operations (getting, setting, or unsetting elements).
TCL_TRACE_DELETE
Trace deletion of the variable (e.g., when the interpreter is destroyed).
TCL_TRACE_RENAME
Trace renaming of the variable.
TCL_TRACE_INTERACTIVE
Trace accesses that occur in an interactive setting (e.g., from the Tcl shell).
TCL_TRACE_KILL_SPECIFIC
If this flag is set, the trace is removed from the variable after it is invoked. This is useful for traces that should only be invoked once.
TCL_TRACE_RESULT_DYNAMIC
Indicates that the trace procedure returns a dynamically allocated string for error messages (to be freed with ckfree). This is mutually exclusive with TCL_TRACE_RESULT_OBJECT.
TCL_TRACE_RESULT_OBJECT
Indicates that the trace procedure returns a Tcl object for error messages (to be freed with Tcl_DecrRefCount). This is mutually exclusive with TCL_TRACE_RESULT_DYNAMIC.

The clientData argument is an arbitrary pointer that is passed to the trace procedure whenever it is invoked. It can be used to pass information to the trace procedure, such as a pointer to application-specific data.

The trace procedure should have the following prototype:

typedef int Tcl_TraceProc(clientData, interp, varName, elementPtr, flags);

Here, clientData is the same value passed to Tcl_TraceVar. interp is the interpreter in which the trace occurs. varName is the name of the variable being accessed. If the trace is for an array element, elementPtr points to the name of the element; otherwise, it is NULL. flags is a bitmask indicating the type of access that triggered the trace (see above for possible flag values).

The trace procedure should return 0 for normal completion, or non-zero to indicate an error. If an error occurs, the trace procedure should return a pointer to a static error message string (or a dynamically allocated string or Tcl_Obj* if TCL_TRACE_RESULT_DYNAMIC or TCL_TRACE_RESULT_OBJECT is set in flags). The access that triggered the trace will be aborted with the error message.

Tcl_UntraceVar removes a trace previously set by Tcl_TraceVar. It requires the same varName, proc, clientData, and flags arguments as Tcl_TraceVar to identify the trace to be removed.

Tcl_VarTraceInfo returns information about traces set on a variable. If prevClientData is NULL, it returns the clientData of the most recently added trace that matches varName and proc. If no such trace exists, it returns NULL. If prevClientData is not NULL, then it should be the return value from a previous call to Tcl_VarTraceInfo. In this case, the new return value will correspond to the next matching trace after the one whose clientData matches prevClientData, or NULL if no trace matches prevClientData or if there are no more matching traces after it. This mechanism makes it possible to step through all of the traces for a given variable that have the same proc.

TWO-PART NAMES

The procedures Tcl_TraceVar2, Tcl_UntraceVar2, and Tcl_VarTraceInfo2 are identical to Tcl_TraceVar, Tcl_UntraceVar, and Tcl_VarTraceInfo, respectively, except that the name of the variable consists of two parts. Name1 gives the name of a scalar variable or array, and name2 gives the name of an element within an array. When name2 is NULL, name1 may contain both an array and an element name: if the name contains an open parenthesis and ends with a close parenthesis, then the value between the parentheses is treated as an element name (which can have any string value) and the characters before the first open parenthesis are treated as the name of an array variable. If name2 is NULL and name1 does not refer to an array element it means that either the variable is a scalar or the trace is to be set on the entire array rather than an individual element (see WHOLE-ARRAY TRACES below for more information).

ACCESSING VARIABLES DURING TRACES

During read, write, and array traces, the trace procedure can read, write, or unset the traced variable using Tcl_GetVar2, Tcl_SetVar2, and other procedures. While proc is executing, traces are temporarily disabled for the variable, so that calls to Tcl_GetVar2 and Tcl_SetVar2 will not cause proc or other trace procedures to be invoked again. Disabling only occurs for the variable whose trace procedure is active; accesses to other variables will still be traced. However, if a variable is unset during a read or write trace then unset traces will be invoked.

During unset traces the variable has already been completely expunged. It is possible for the trace procedure to read or write the variable, but this will be a new version of the variable. Traces are not disabled during unset traces as they are for read and write traces, but existing traces have been removed from the variable before any trace procedures are invoked. If new traces are set by unset trace procedures, these traces will be invoked on accesses to the variable by the trace procedures.

CALLBACK TIMING

When read tracing has been specified for a variable, the trace procedure will be invoked whenever the variable's value is read. This includes set Tcl commands, $-notation in Tcl commands, and invocations of the Tcl_GetVar and Tcl_GetVar2 procedures. Proc is invoked just before the variable's value is returned. It may modify the value of the variable to affect what is returned by the traced access. If it unsets the variable then the access will return an error just as if the variable never existed.

When write tracing has been specified for a variable, the trace procedure will be invoked whenever the variable's value is modified. This includes set commands, commands that modify variables as side effects (such as catch and scan), and calls to the Tcl_SetVar and Tcl_SetVar2 procedures). Proc will be invoked after the variable's value has been modified, but before the new value of the variable has been returned. It may modify the value of the variable to override the change and to determine the value actually returned by the traced access. If it deletes the variable then the traced access will return an empty string.

When array tracing has been specified, the trace procedure will be invoked at the beginning of the array command implementation, before any of the operations like get, set, or names have been invoked. The trace procedure can modify the array elements with Tcl_SetVar and Tcl_SetVar2.

When unset tracing has been specified, the trace procedure will be invoked whenever the variable is destroyed. The traces will be called after the variable has been completely unset.

WHOLE-ARRAY TRACES

If a call to Tcl_TraceVar or Tcl_TraceVar2 specifies the name of an array variable without an index into the array, then the trace will be set on the array as a whole. This means that proc will be invoked whenever any element of the array is accessed in the ways specified by flags. When an array is unset, a whole-array trace will be invoked just once, with name1 equal to the name of the array and name2 NULL; it will not be invoked once for each element.

MULTIPLE TRACES

It is possible for multiple traces to exist on the same variable. When this happens, all of the trace procedures will be invoked on each access, in order from most-recently-created to least-recently-created. When there exist whole-array traces for an array as well as traces on individual elements, the whole-array traces are invoked before the individual-element traces. If a read or write trace unsets the variable then all of the unset traces will be invoked but the remainder of the read and write traces will be skipped.

ERROR RETURNS

Under normal conditions trace procedures should return NULL, indicating successful completion. If proc returns a non-NULL value it signifies that an error occurred. The return value must be a pointer to a static character string containing an error message, unless (exactly one of) the TCL_TRACE_RESULT_DYNAMIC and TCL_TRACE_RESULT_OBJECT flags is set, which specify that the result is either a dynamic string (to be released with ckfree) or a Tcl_Obj* (cast to char* and to be released with Tcl_DecrRefCount) containing the error message. If a trace procedure returns an error, no further traces are invoked for the access and the traced access aborts with the given message. Trace procedures can use this facility to make variables read-only, for example (but note that the value of the variable will already have been modified before the trace procedure is called, so the trace procedure will have to restore the correct value).

The return value from proc is only used during read and write tracing. During unset traces, the return value is ignored and all relevant trace procedures will always be invoked.

RESTRICTIONS

A trace procedure can be called at any time, even when there are partially formed results stored in the interpreter. If the trace procedure does anything that could damage this result (such as calling Tcl_Eval) then it must use the Tcl_SaveInterpState and related routines to save and restore the original state of the interpreter before it returns.

UNDEFINED VARIABLES

It is legal to set a trace on an undefined variable. The variable will still appear to be undefined until the first time its value is set. If an undefined variable is traced and then unset, the unset will fail with an error (“no such variable”), but the trace procedure will still be invoked.

TCL_TRACE_DESTROYED FLAG

In an unset callback to proc, the TCL_TRACE_DESTROYED bit is set in flags if the trace is being removed as part of the deletion. Traces on a variable are always removed whenever the variable is deleted; the only time TCL_TRACE_DESTROYED is not set is for a whole-array trace invoked when only a single element of an array is unset.

TCL_INTERP_DESTROYED

When an interpreter is destroyed, unset traces are called for all of its variables. The TCL_INTERP_DESTROYED bit will be set in the flags argument passed to the trace procedures. Trace procedures must be extremely careful in what they do if the TCL_INTERP_DESTROYED bit is set. It is not safe for the procedures to invoke any Tcl procedures on the interpreter, since its state is partially deleted. All that trace procedures should do under these circumstances is to clean up and free their own internal data structures.

BUGS

Tcl does not do any error checking to prevent trace procedures from misusing the interpreter during traces with TCL_INTERP_DESTROYED set.

Array traces are not yet integrated with the Tcl info exists command, nor is there Tcl-level access to array traces.
