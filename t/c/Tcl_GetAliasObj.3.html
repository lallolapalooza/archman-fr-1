DESCRIPTION

Ces procédures sont destinées à l'accès à la fonctionnalité des interpréteurs multiples depuis l'intérieur de programmes C. Elles permettent de gérer plusieurs interpréteurs dans une relation hiérarchique, et la gestion des alias, des commandes qui, lorsqu'elles sont invoquées dans un interpréteur, exécutent une commande dans un autre interpréteur. La valeur de retour pour les procédures qui retournent un int est soit TCL_OK, soit TCL_ERROR. Si TCL_ERROR est retourné, le résultat de l'interpréteur contient un message d'erreur.

Tcl_CreateSlave crée un nouvel interpréteur comme enfant de interp. Elle crée également une commande enfant nommée childName dans interp qui permet à interp de manipuler le nouvel enfant. Si isSafe est zéro, la commande crée un enfant fiable dans lequel le code Tcl a accès à toutes les commandes Tcl. S'il vaut 1, la commande crée un enfant «sûr» dans lequel le code Tcl n'a accès qu'à l'ensemble des commandes Tcl définies comme «Safe Tcl»; voir la page de manuel de la commande Tcl interp pour les détails. Si la création du nouvel interpréteur enfant a échoué, NULL est retourné.

Tcl_CreateChild est un synonyme de Tcl_CreateSlave.

Tcl_IsSafe retourne 1 si interp est «sûr» (a été créé avec le drapeau TCL_SAFE_INTERPRETER spécifié), 0 sinon.

Tcl_MakeSafe marque interp comme «sûr», de sorte que les appels futurs à Tcl_IsSafe retourneront 1. Elle supprime également toutes les fonctionnalités de base potentiellement dangereuses connues (commandes et variables) de interp. Cependant, elle ne peut pas connaître les parties d'une extension ou d'une application qui sont sûres et ne fait aucune tentative pour supprimer ces parties, donc la sécurité n'est pas garantie après avoir appelé Tcl_MakeSafe. Les appelants devront faire attention à leur utilisation de Tcl_MakeSafe pour éviter les fausses affirmations de sécurité. Pour de nombreuses situations, Tcl_CreateSlave peut être un meilleur choix, car elle crée des interpréteurs dans un état sûr connu.

Tcl_GetSlave retourne un pointeur vers un interpréteur enfant de interp. L'interpréteur enfant est identifié par childName. Si aucun interpréteur enfant de ce nom n'existe, NULL est retourné.

Tcl_GetChild est un synonyme de Tcl_GetSlave.

Tcl_GetMaster retourne un pointeur vers l'interpréteur maître de interp. Si interp n'a pas de maître (c'est un interpréteur de niveau supérieur), alors NULL est retourné.

Tcl_GetParent est un synonyme de Tcl_GetMaster.

Tcl_GetInterpPath stocke dans le résultat de interp le chemin relatif entre interp et childInterp; childInterp doit être un enfant de interp. Si le calcul du chemin relatif réussit, TCL_OK est retourné, sinon TCL_ERROR est retourné et un message d'erreur est stocké comme résultat de interp.

Tcl_CreateAlias crée une commande nommée childCmd dans childInterp qui, lors de son invocation, provoquera l'invocation de la commande targetCmd dans targetInterp. Les arguments spécifiés par les chaînes contenues dans argv sont toujours ajoutés au début des arguments fournis lors de l'invocation de childCmd et passés à targetCmd. Cette opération retourne TCL_OK si elle réussit, ou TCL_ERROR si elle échoue ; dans ce cas, un message d'erreur est laissé dans la valeur de résultat de childInterp. Notez qu'il n'y a aucune restriction sur la relation d'ascendance (telle que créée par Tcl_CreateSlave) entre childInterp et targetInterp. Deux interpréteurs quelconques peuvent être utilisés, sans aucune restriction sur la façon dont ils sont liés.

Tcl_CreateAliasObj est similaire à Tcl_CreateAlias sauf qu'elle prend un vecteur de valeurs à passer comme arguments supplémentaires au lieu d'un vecteur de chaînes.

Tcl_GetAliasObj retourne des informations sous la forme d'un pointeur vers un vecteur de structures Tcl_Obj concernant un alias aliasName dans interp. N'importe lequel des champs de résultat peut être NULL, auquel cas la donnée correspondante n'est pas retournée. Si un champ de résultat n'est pas NULL, l'adresse indiquée est définie à la donnée correspondante. Par exemple, si targetCmdPtr n'est pas NULL, il est défini à un pointeur vers la chaîne contenant le nom de la commande cible.

Tcl_GetAlias est similaire à Tcl_GetAliasObj sauf qu'elle retourne un pointeur vers un vecteur de chaînes au lieu d'un vecteur de structures Tcl_Obj. Tcl_GetAlias est obsolète.

Tcl_GetAliasObj(3) - Tcl C API

NAME

Tcl_GetAliasObj, Tcl_ExposeCommand, Tcl_HideCommand - manage aliases and hidden commands

SYNOPSIS

#include <tcl.h>

CONST char *
Tcl_GetAliasObj(interp, slaveInterp, cmdName, argNum)
Tcl_Command
Tcl_ExposeCommand(interp, hiddenCmdName, cmdName)
Tcl_Command
Tcl_HideCommand(interp, cmdName, hiddenCmdName)

ARGUMENTS

Tcl_Interp *interp (in)
Interpreter containing the command to alias or hide.
Tcl_Interp *slaveInterp (in)
Interpreter containing the command to be aliased. Can be the same as interp.
CONST char *cmdName (in)
Name of the command to alias or hide.
int argNum (in)
The argument number at which the aliased command should be invoked. For a simple alias, this is typically 1.
CONST char *hiddenCmdName (in)
Name of the command in the hidden command set.

DESCRIPTION

These functions are used to manage the mapping between exposed commands and hidden commands. Exposed commands are those which are visible and callable by users within a Tcl interpreter. Hidden commands are commands which are normally invisible to users but can be made visible (exposed) via these functions. An alias is created by exposing a command under a new name.

Tcl_GetAliasObj returns the name of the command that is currently aliased to cmdName in slaveInterp. If cmdName is not aliased, or if slaveInterp is invalid, it returns NULL. ArgNum is the argument number, and is currently unused and should be set to 1. The result is a dynamically allocated string that must be freed by the caller using Tcl_Free. This function is deprecated; use Tcl_GetAlias instead.

Tcl_ExposeCommand moves the command named hiddenCmdName from the set of hidden commands to the set of exposed commands, putting it under the name cmdName. HiddenCmdName must be the name of an existing hidden command, or the operation will return TCL_ERROR and leave an error message as the result of interp. If an exposed command named cmdName already exists, the operation returns TCL_ERROR and leaves an error message as the result of interp. If the operation succeeds, it returns TCL_OK. After executing this command, attempts to use cmdName in any script evaluation mechanism will again succeed.

Tcl_HideCommand moves the command named cmdName from the set of exposed commands to the set of hidden commands, under the name hiddenCmdName. CmdName must be the name of an existing exposed command, or the operation will return TCL_ERROR and leave an error message as the result of interp. Currently both cmdName and hiddenCmdName must not contain namespace qualifiers, or the operation will return TCL_ERROR and leave an error message as the result of interp. The CmdName will be looked up in the global namespace, and not relative to the current namespace, even if the current namespace is not the global one. If a hidden command whose name is hiddenCmdName already exists, the operation also returns TCL_ERROR and an error message is left as the result of interp. If the operation succeeds, it returns TCL_OK. After executing this command, attempts to use cmdName in any script evaluation mechanism will fail.

For a description of the Tcl interface to multiple interpreters, see interp(n).

NOM

Tcl_GetAliasObj, Tcl_ExposeCommand, Tcl_HideCommand - gérer les alias et les commandes cachées

SYNTAXE

#include <tcl.h>

CONST char *
Tcl_GetAliasObj(interp, slaveInterp, cmdName, argNum)
Tcl_Command
Tcl_ExposeCommand(interp, hiddenCmdName, cmdName)
Tcl_Command
Tcl_HideCommand(interp, cmdName, hiddenCmdName)

ARGUMENTS

Tcl_Interp *interp (en entrée)
Interpréteur contenant la commande à aliaser ou à cacher.
Tcl_Interp *slaveInterp (en entrée)
Interpréteur contenant la commande à aliaser. Peut être le même que interp.
CONST char *cmdName (en entrée)
Nom de la commande à aliaser ou à cacher.
int argNum (en entrée)
Le numéro d'argument auquel la commande aliasée doit être appelée. Pour un alias simple, c'est typiquement 1.
CONST char *hiddenCmdName (en entrée)
Nom de la commande dans l'ensemble des commandes cachées.

DESCRIPTION

Ces fonctions sont utilisées pour gérer le mappage entre les commandes exposées et les commandes cachées. Les commandes exposées sont celles qui sont visibles et appelables par les utilisateurs dans un interpréteur Tcl. Les commandes cachées sont des commandes qui sont normalement invisibles pour les utilisateurs mais qui peuvent être rendues visibles (exposées) via ces fonctions. Un alias est créé en exposant une commande sous un nouveau nom.

Tcl_GetAliasObj renvoie le nom de la commande qui est actuellement aliasée vers cmdName dans slaveInterp. Si cmdName n'est pas aliasée, ou si slaveInterp est invalide, elle renvoie NULL. ArgNum est le numéro d'argument et n'est actuellement pas utilisé ; il doit être défini à 1. Le résultat est une chaîne allouée dynamiquement qui doit être libérée par l'appelant à l'aide de Tcl_Free. Cette fonction est obsolète ; utilisez Tcl_GetAlias à la place.

Tcl_ExposeCommand déplace la commande nommée hiddenCmdName de l'ensemble des commandes cachées vers l'ensemble des commandes exposées, en la plaçant sous le nom cmdName. HiddenCmdName doit être le nom d'une commande cachée existante, sinon l'opération renverra TCL_ERROR et laissera un message d'erreur comme résultat de interp. Si une commande exposée nommée cmdName existe déjà, l'opération renvoie TCL_ERROR et laisse un message d'erreur comme résultat de interp. Si l'opération réussit, elle renvoie TCL_OK. Après l'exécution de cette commande, les tentatives d'utilisation de cmdName dans tout mécanisme d'évaluation de script réussiront à nouveau.

Tcl_HideCommand déplace la commande nommée cmdName de l'ensemble des commandes exposées vers l'ensemble des commandes cachées, sous le nom hiddenCmdName. CmdName doit être le nom d'une commande exposée existante, sinon l'opération renverra TCL_ERROR et laissera un message d'erreur comme résultat de interp. Actuellement, cmdName et hiddenCmdName ne doivent pas contenir de qualificateurs de namespace, sinon l'opération renverra TCL_ERROR et laissera un message d'erreur comme résultat de interp. CmdName sera recherché dans le namespace global, et non par rapport au namespace courant, même si le namespace courant n'est pas le global. Si une commande cachée dont le nom est hiddenCmdName existe déjà, l'opération renvoie également TCL_ERROR et un message d'erreur est laissé comme résultat de interp. Si l'opération réussit, elle renvoie TCL_OK. Après l'exécution de cette commande, les tentatives d'utilisation de cmdName dans tout mécanisme d'évaluation de script échoueront.

Pour une description de l'interface Tcl vers plusieurs interpréteurs, voir interp(n).
