DESCRIPTION

Tcl_CreateObjCommand définit une nouvelle commande dans interp et l'associe à la procédure proc de telle sorte que chaque fois que name est invoquée comme commande Tcl (par exemple, via un appel à Tcl_EvalObjEx) l'interpréteur appellera proc pour la traiter.

Tcl_CreateObjCommand supprime toute commande existante name déjà associée à l'interpréteur (bien qu'il existe une exception où la commande existante n'est pas supprimée). Elle renvoie un jeton qui peut être utilisé pour faire référence à la commande dans les appels ultérieurs à Tcl_GetCommandName. Si name contient des qualificatifs ::, la commande est ajoutée au namespace spécifié ; sinon, elle est ajoutée au namespace global. Si Tcl_CreateObjCommand est appelée pour un interpréteur en cours de suppression, aucune nouvelle commande n'est créée et NULL est renvoyé. proc doit avoir des arguments et un résultat correspondant au type Tcl_ObjCmdProc :

typedef int Tcl_ObjCmdProc(
        ClientData clientData,
        Tcl_Interp *interp,
        int objc,
        Tcl_Obj *const objv[]);

Lorsque proc est appelée, clientData et interp seront des copies des arguments passés à Tcl_CreateObjCommand. Généralement, clientData pointe vers une structure de données spécifique à l'application décrivant ce qui doit être fait lorsque la procédure de commande est invoquée. Objc et objv décrivent les arguments de la commande, objc donne le nombre de valeurs d'arguments (y compris le nom de la commande) et objv donne les valeurs des arguments. Le tableau objv contiendra objc valeurs, pointant vers les valeurs des arguments. Contrairement à argv[argv] dans une procédure basée sur des chaînes, objv[objc] ne contiendra pas de NULL.

De plus, lorsque proc est appelée, elle ne doit pas modifier le contenu de objv en modifiant les éléments du tableau (par exemple, objv[2] = NULL), car cela entraînerait des fuites de mémoire et une corruption de la pile d'exécution. La constante dans la déclaration de objv fera que les compilateurs ANSI signaleront toute tentative d'affectation comme une erreur. Cependant, il est acceptable de modifier la représentation interne de toute valeur individuelle. Par exemple, l'utilisateur peut appeler Tcl_GetIntFromObj sur objv[2] pour obtenir la représentation entière de cette valeur ; cet appel peut changer le type de la valeur vers laquelle objv[2] pointe, mais il ne changera pas l'endroit où objv[2] pointe.

Le proc doit renvoyer un code entier qui est TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK ou TCL_CONTINUE. Consultez la page de manuel Tcl pour plus de détails sur la signification de chaque code. Les commandes normales ne renverront que TCL_OK ou TCL_ERROR. De plus, si proc doit renvoyer un résultat non vide, il peut appeler Tcl_SetObjResult pour définir le résultat de l'interpréteur. Dans le cas d'un retour de TCL_OK, cela donne le résultat de la commande, et dans le cas d'un TCL_ERROR, cela donne un message d'erreur. Avant d'invoquer la procédure de commande, Tcl_EvalObjEx définit le résultat de l'interpréteur sur une valeur représentant une chaîne vide, de sorte que les commandes simples peuvent renvoyer un résultat vide en ne faisant rien.

Les valeurs dans le tableau objv appartiennent à Tcl et il n'est pas garanti qu'elles persistent une fois que proc est terminé : proc ne doit pas les modifier. Si vous souhaitez renvoyer quelque chose du tableau objv, appelez Tcl_SetObjResult.

Normalement, Tcl_CreateObjCommand supprime toute commande existante name déjà associée à l'interpréteur. Cependant, si la commande existante a été créée précédemment via un appel à Tcl_CreateCommand, Tcl_CreateObjCommand ne la supprime pas, mais planifie que l'interpréteur appelle le Tcl_ObjCmdProc proc à l'avenir. La procédure basée sur des chaînes plus ancienne Tcl_CmdProc associée à la commande est conservée et son adresse peut être obtenue via des appels ultérieurs à Tcl_GetCommandInfo. Ceci est fait pour la compatibilité ascendante.

DeleteProc est appelée lorsque (et si) name est supprimée. Cela peut se produire via des appels à Tcl_DeleteCommand, Tcl_DeleteCommandFromToken, ou Tcl_DeleteInterp, ou par le remplacement de name dans un autre appel à Tcl_CreateObjCommand. DeleteProc est appelée avant la suppression de la commande, donnant à l'application la possibilité de libérer toutes les structures associées à la commande. DeleteProc doit avoir des arguments et un résultat correspondant au type Tcl_CmdDeleteProc :

typedef void Tcl_CmdDeleteProc(
        ClientData clientData);

L'argument clientData sera le même que l'argument clientData passé à Tcl_CreateObjCommand.

Le clientData argument sera le même que l'argument clientData passé à Tcl_CreateObjCommand.

Tcl_DeleteCommand supprime une commande d'un interpréteur de commande. Une fois l'appel terminé, toute tentative d'invoquer cmdName dans interp entraînera des erreurs. Si cmdName n'est pas associée comme commande dans interp, Tcl_DeleteCommand ne fera rien et renverra -1 ; sinon, elle renvoie 0. Il n'y a aucune restriction sur cmdName : elle peut faire référence à une commande intégrée, une commande spécifique à l'application ou une procédure Tcl. Si name contient des qualificatifs ::, la commande est supprimée du namespace spécifié.

Étant donné un jeton renvoyé par Tcl_CreateObjCommand, Tcl_DeleteCommandFromToken supprime la commande d'un interpréteur de commande. Même si la commande a été renommée, elle sera toujours supprimée. Une fois l'appel terminé, toute tentative d'invoquer la commande dans interp entraînera des erreurs. Si la commande correspondant à token a déjà été supprimée de interp, Tcl_DeleteCommand ne fera rien et renverra -1 ; sinon, elle renvoie 0.

Tcl_GetCommandInfo vérifie si cmdName existe en tant que commande dans interp. cmdName peut inclure des qualificatifs :: pour identifier une commande dans un namespace spécifique. Si la commande n'est pas trouvée, elle renvoie 0. Sinon, elle place des informations sur la commande dans la structure Tcl_CmdInfo pointée par infoPtr et renvoie 1.
