Tcl_TraceVar(3) Procédures de bibliothèque Tcl Tcl_TraceVar(3)

NOM

Tcl_TraceVar, Tcl_TraceVar2, Tcl_UntraceVar, Tcl_UntraceVar2, Tcl_VarTraceInfo, Tcl_VarTraceInfo2 - suivre les accès à une variable

SYNOPSIS

#include <tcl.h>

int
Tcl_TraceVar(interp, varName, flags, proc, clientData)

int
Tcl_TraceVar2(interp, name1, name2, flags, proc, clientData)

Tcl_UntraceVar(interp, varName, flags, proc, clientData)

Tcl_UntraceVar2(interp, name1, name2, flags, proc, clientData)

ClientData
Tcl_VarTraceInfo(interp, varName, flags, proc, prevClientData)

ClientData
Tcl_VarTraceInfo2(interp, name1, name2, flags, proc, prevClientData)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur contenant la variable.
const char *varName (in)
Nom de la variable. Peut faire référence à une variable scalaire, à une variable tableau sans indice, ou à une variable tableau avec un indice entre parenthèses.
int flags (in)
OR des valeurs TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS, TCL_TRACE_ARRAY, TCL_GLOBAL_ONLY, TCL_NAMESPACE_ONLY, TCL_TRACE_RESULT_DYNAMIC et TCL_TRACE_RESULT_OBJECT. Tous les drapeaux ne sont pas utilisés dans toutes les procédures. Voir plus d'informations ci-dessous.
Tcl_VarTraceProc *proc (in)
Procédure à appeler lorsque l'une des opérations tracées se produit.
ClientData clientData (in)
Valeur arbitraire d'un mot à passer à proc.
const char *name1 (in)
Nom de la variable scalaire ou du tableau (sans indice de tableau).
const char *name2 (in)
Pour un suivi sur un élément de tableau, donne l'indice de l'élément. Pour les suivis sur des variables scalaires ou des tableaux entiers, est NULL.
ClientData prevClientData (in)
S'il n'est pas NULL, donne la dernière valeur retournée par Tcl_VarTraceInfo ou Tcl_VarTraceInfo2, de sorte que cet appel retournera des informations sur le suivi suivant. S'il est NULL, cet appel retournera des informations sur le premier suivi.

DESCRIPTION

Tcl_TraceVar permet à une procédure C de surveiller et de contrôler l'accès à une variable Tcl, de sorte que la procédure C soit appelée chaque fois qu'une variable est lue, écrite ou désunset. Si le suivi est créé correctement, Tcl_TraceVar retourne TCL_OK. Si une erreur se produit (par exemple, varName spécifie un élément de tableau, mais la variable réelle n'est pas un tableau), TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de l'interpréteur.

L'argument flags de Tcl_TraceVar indique quand la procédure de suivi doit être appelée et fournit des informations pour configurer le suivi. Il est formé par un OR de n'importe laquelle des valeurs suivantes :

TCL_GLOBAL_ONLY
Normalement, la variable est recherchée au niveau d'appel de procédure actuel ; si ce bit est défini, la variable est recherchée au niveau global, ignorant toute procédure active.
TCL_NAMESPACE_ONLY
Normalement, la variable est recherchée au niveau d'appel de procédure actuel ; si ce bit est défini, la variable est recherchée dans l'espace de noms actuel, ignorant toute procédure active.
TCL_TRACE_READS
Le proc est appelé chaque fois qu'une tentative est faite pour lire la variable.
TCL_TRACE_WRITES
Le proc est appelé chaque fois qu'une tentative est faite pour modifier la variable.
TCL_TRACE_UNSETS
Le proc est appelé chaque fois que la variable est désunset. Une variable peut être désunset explicitement avec la commande unset, ou implicitement lorsqu'une procédure retourne (ses variables locales sont automatiquement désunset), ou lorsque l'interpréteur est détruit (toutes les variables sont automatiquement désunset).
TCL_TRACE_ARRAY
Le proc est appelé chaque fois que la commande array est invoquée. Cela donne à la procédure de suivi la possibilité de mettre à jour le tableau avant que le nom du tableau ou le get du tableau ne soit appelé. Note : ceci est appelé avant un set de tableau, mais cela provoquera des suivis d'écriture.
TCL_TRACE_RESULT_DYNAMIC
Le résultat de l'appel du proc est une chaîne dynamique allouée par la bibliothèque Tcl, qui sera libérée par un appel à ckfree. Ne doit pas être spécifié simultanément avec TCL_TRACE_RESULT_OBJECT.
TCL_TRACE_RESULT_OBJECT
Le résultat de l'appel du proc est un Tcl_Obj* (converti en pointeur char), avec un compteur de références d'au moins un. La propriété de ce référencé sera transférée à la bibliothèque Tcl pour être libérée (lorsque la bibliothèque aura fini avec lui) par un appel à Tcl_DecrRefCount. Ne doit pas être spécifié simultanément avec TCL_TRACE_RESULT_DYNAMIC.

Lorsqu'une des opérations spécifiées se produit sur la variable, le proc est appelé. Il doit avoir des arguments et des retours correspondant au type Tcl_VarTraceProc :

typedef char *Tcl_VarTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *name1,
        const char *name2,
        int flags);

Les paramètres clientData et interp auront les mêmes valeurs que celles passées à Tcl_TraceVar lors de la création du suivi. clientData pointe généralement vers un ensemble de données d'application décrivant quoi faire lorsque proc est appelé. name1 et name2 donnent le nom de la variable suivie dans le format normal en deux parties (voir la description de Tcl_TraceVar2 pour les détails). flags est un OR de bits fournissant diverses informations. L'un des bits TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_ARRAY ou TCL_TRACE_UNSETS sera défini dans flags pour indiquer quelle opération est effectuée sur la variable. Le bit TCL_GLOBAL_ONLY sera défini lorsque la variable accédée est globale et ne peut pas être accédée depuis le niveau d'appel de procédure actuel : la procédure de suivi devra passer ce drapeau aux procédures de variable telles que Tcl_GetVar si elle tente d'accéder à la variable. Le bit TCL_NAMESPACE_ONLY sera défini lorsque la variable accédée est dans un espace de noms et ne peut pas être accédée depuis le niveau d'appel de procédure actuel : la procédure de suivi devra passer ce drapeau aux procédures de variable telles que Tcl_GetVar si elle tente d'accéder à la variable. Le bit TCL_TRACE_DESTROYED sera défini dans flags si le suivi doit être détruit ; ces informations peuvent être utiles pour que proc nettoie ses structures internes (voir la section TCL_TRACE_DESTROYED pour plus de détails). Enfin, le bit TCL_INTERP_DESTROYED sera défini si tout l'environnement de l'interpréteur est en cours de destruction. Lorsque ce bit est défini, proc doit être particulièrement prudent quant à ce qu'il fait (voir la section TCL_INTERP_DESTROYED pour plus de détails). La valeur de retour de la procédure de suivi doit normalement être NULL ; voir VALEURS DE RETOUR D'ERREUR pour des informations sur d'autres valeurs possibles.

Tcl_UntraceVar peut être utilisé pour supprimer un suivi. Si la variable spécifiée par interp, varName, et flags a un suivi avec les mêmes flags, proc, et clientData, alors le suivi correspondant est supprimé. S'il n'existe pas de tel suivi, l'appel à Tcl_UntraceVar n'a aucun effet. Les mêmes bits sont valides pour flags que pour les appels à Tcl_TraceVar.

Tcl_VarTraceInfo peut être utilisé pour récupérer des informations sur les suivis définis pour une variable donnée. La valeur retournée par Tcl_VarTraceInfo est le clientData associé à un suivi particulier. Le suivi doit se trouver dans la variable spécifiée par les arguments interp, varName, et flags (seuls les bits TCL_GLOBAL_ONLY et TCL_NAMESPACE_ONLY de flags sont utilisés ; les autres bits sont ignorés) et sa procédure de suivi doit être la même que l'argument proc. Si l'argument prevClientData est NULL, la valeur retournée correspond au premier (le plus récent) suivi correspondant, ou NULL s'il n'y a pas de correspondance.

NOMS EN DEUX PARTIES

Les procédures Tcl_TraceVar2, Tcl_UntraceVar2 et Tcl_VarTraceInfo2 sont identiques à Tcl_TraceVar, Tcl_UntraceVar et Tcl_VarTraceInfo, respectivement, à l'exception près que le nom de la variable se compose de deux parties. Nom1 donne le nom d'une variable scalaire ou d'un tableau, et nom2 donne le nom d'un élément d'un tableau. Lorsque nom2 est NULL, nom1 peut contenir à la fois le nom d'un tableau et d'un élément. Si le nom contient une parenthèse ouvrante et se termine par une parenthèse fermante, la valeur entre les parenthèses sera traitée comme le nom de l'élément (qui peut avoir n'importe quelle valeur de chaîne) et les caractères avant la première parenthèse seront traités comme le nom d'une variable tableau. Si nom2 est NULL et que nom1 ne fait pas référence à un élément de tableau, cela signifie que la variable est scalaire ou que le traçage est défini sur le tableau entier (voir TRAÇAGES DE TABLEAUX ENTIERS ci-dessous).

ACCÈS AUX VARIABLES PENDANT LES TRAÇAGES

Pendant les traçages en lecture, en écriture et de tableau, la procédure de traçage peut lire, écrire ou supprimer la variable tracée à l'aide de Tcl_GetVar2, Tcl_SetVar2 et d'autres procédures. Tant que proc est en cours d'exécution, les traçages sont temporairement désactivés pour la variable, de sorte que les appels à Tcl_GetVar2 et Tcl_SetVar2 ne provoquent pas l'invocation de proc ou d'autres procédures de traçage. Seul le traçage de la variable dont la procédure de traçage est active est désactivé ; les accès aux autres variables sont toujours tracés. Cependant, si la variable est supprimée pendant un traçage en lecture ou en écriture, les traçages de suppression sont invoqués.

Pendant les traçages de suppression, la variable a déjà été complètement supprimée. Il est possible que la procédure de traçage lise ou écrive la variable, mais ce sera une nouvelle version de la variable. Les traçages ne sont pas désactivés pendant les traçages de suppression, comme pour les traçages en lecture et en écriture, mais les traçages existants ont été supprimés de la variable avant que les procédures de traçage ne soient invoquées. Si de nouveaux traçages sont définis par des procédures de traçage de suppression, ceux-ci sont invoqués lorsque la variable est accédée par les procédures de traçage.

CALENDRIER DES RAPPELS DE TRAÇAGE

Lorsqu'un traçage en lecture est spécifié pour une variable, la procédure de traçage est invoquée chaque fois que la valeur de la variable est lue. Cela inclut les commandes Tcl telles que set, la notation $ dans les commandes Tcl, et les invocations des procédures Tcl_GetVar et Tcl_GetVar2. Proc est invoqué juste avant que la valeur de la variable ne soit renvoyée. Vous pouvez modifier la valeur de la variable pour affecter ce qui est renvoyé par l'accès tracé. Si vous supprimez la variable, l'accès renverra une erreur, comme si la variable n'existait jamais.

Lorsqu'un traçage en écriture est spécifié pour une variable, la procédure de traçage est invoquée chaque fois que la valeur de la variable est modifiée. Cela inclut les commandes Tcl telles que set, les commandes qui modifient les variables comme effet secondaire (telles que catch et scan), et les appels aux procédures Tcl_SetVar et Tcl_SetVar2. Proc est invoqué après que la valeur de la variable ait été modifiée, mais avant que la nouvelle valeur de la variable ne soit renvoyée. Vous pouvez modifier la valeur de la variable pour surcharger la modification et déterminer la valeur réellement renvoyée par l'accès tracé. Si vous supprimez la variable, l'accès tracé renverra une chaîne vide.

Lorsqu'un traçage de tableau est spécifié, la procédure de traçage est invoquée au début de l'exécution des commandes de tableau, avant que les opérations comme get, set ou nom ne soient invoquées. La procédure de traçage peut modifier les éléments du tableau avec Tcl_SetVar et Tcl_SetVar2.

Lorsqu'un traçage de suppression est spécifié, la procédure de traçage est invoquée chaque fois que la variable est supprimée. Les traçages sont invoqués après que la variable ait été complètement supprimée.

TRAÇAGES DE TABLEAUX ENTIERS

Si Tcl_TraceVar ou Tcl_TraceVar2 est appelé et que le nom d'une variable tableau est spécifié sans indice dans le tableau, le traçage sera défini sur le tableau entier. Cela signifie que proc sera invoqué chaque fois que n'importe quel élément du tableau est accédé de la manière spécifiée par flags. Lorsqu'un tableau est supprimé, un traçage de tableau entier sera invoqué une fois, avec nom1 égal au nom du tableau et nom2 NULL ; il ne sera pas invoqué une fois pour chaque élément.

TRAÇAGES MULTIPLES

Il est possible d'avoir plusieurs traçages sur la même variable. Lorsque cela se produit, toutes les procédures de traçage sont invoquées chaque fois que la variable est accédée, dans l'ordre du plus récent au moins récent. Lorsqu'il y a des traçages de tableau sur un tableau et des traçages individuels sur des éléments, les traçages de tableau entiers sont invoqués avant les traçages individuels. Si un traçage en lecture ou en écriture supprime la variable, tous les traçages de suppression sont invoqués, mais les traçages en lecture et en écriture restants sont ignorés.

RETOURS D'ERREUR

Dans des conditions normales, les procédures de traçage doivent renvoyer NULL, indiquant le succès. Si proc renvoie une valeur non NULL, cela signifie qu'une erreur s'est produite. La valeur renvoyée doit être un pointeur vers une chaîne statique contenant un message d'erreur, sauf si l'un des drapeaux TCL_TRACE_RESULT_DYNAMIC ou TCL_TRACE_RESULT_OBJECT est actif, qui spécifie que le résultat est une chaîne dynamique (à libérer avec ckfree) ou un Tcl_Obj* (converti en char* et à libérer avec Tcl_DecrRefCount), contenant le message d'erreur. Si une procédure de traçage renvoie une erreur, aucune autre procédure de traçage n'est invoquée pour cet accès, et l'accès tracé est abandonné avec le message donné. Les procédures de traçage peuvent utiliser cette fonctionnalité pour rendre les variables en lecture seule, par exemple (mais notez que la valeur de la variable a déjà été modifiée avant que la procédure de traçage ne s'exécute, de sorte que la procédure de traçage devra restaurer la valeur correcte).

La valeur renvoyée par proc n'est utilisée que pendant les traçages en lecture et en écriture. Pendant les traçages de suppression, la valeur est ignorée et toutes les procédures de traçage pertinentes sont toujours invoquées.

RESTRICTIONS

Une procédure de traçage peut être appelée à tout moment, même lorsqu'il existe des résultats partiellement formés stockés dans l'interpréteur. Si la procédure de traçage effectue une action qui pourrait endommager ce résultat (comme appeler Tcl_Eval), elle doit utiliser les routines Tcl_SaveInterpState et associées pour sauvegarder et restaurer l'état d'origine de l'interpréteur avant de renvoyer.

VARIABLES NON DÉFINIES

Il est légal de définir un traçage sur une variable non définie. La variable continuera d'apparaître comme non définie jusqu'à ce que sa valeur soit définie pour la première fois. Si une variable non définie est tracée puis supprimée, la suppression échouera avec une erreur ("no such variable"), mais la procédure de traçage sera toujours invoquée.

DRAPEAU TCL_TRACE_DESTROYED

Dans un rappel de suppression de traçage pour proc, le bit TCL_TRACE_DESTROYED est défini dans flags si le traçage est en cours de suppression dans le cadre du processus de suppression. Les traçages d'une variable sont toujours supprimés lorsque la variable est supprimée ; le seul moment où le bit TCL_TRACE_DESTROYED n'est pas défini est lorsqu'un traçage de tableau entier est exécuté lorsqu'un seul élément de tableau est supprimé.

BIT TCL_INTERP_DESTROYED

Lorsque l'interpréteur est supprimé, les traçages de suppression pour toutes ses variables sont invoqués. Le bit TCL_INTERP_DESTROYED est défini dans l'argument flags passé aux procédures de traçage. Les procédures de traçage doivent être extrêmement prudentes dans ce qu'elles font si le bit TCL_INTERP_DESTROYED est actif. Il n'est pas sûr d'invoquer une procédure Tcl dans l'interpréteur, car son état est partiellement supprimé. Dans de tels cas, les procédures de traçage doivent nettoyer et libérer leurs structures internes.

BOGUES

Tcl n'effectue aucune vérification d'erreurs pour empêcher les procédures de traçage d'utiliser l'interpréteur de manière incorrecte pendant les traçages lorsque le bit TCL_INTERP_DESTROYED est actif.

Les traçages de tableaux ne sont pas encore intégrés à la commande Tcl info exists, et il n'y a pas d'accès aux traçages de tableaux au niveau Tcl.
