Tcl_CreateInterp(3) Procédures de la bibliothèque Tcl Tcl_CreateInterp(3)

NOM

Tcl_CreateInterp, Tcl_DeleteInterp, Tcl_InterpActive, Tcl_InterpDeleted - créer et supprimer des interpréteurs de commandes Tcl

SYNOPIS

#include <tcl.h>

Tcl_Interp *
Tcl_CreateInterp()

Tcl_DeleteInterp(interp)

int
Tcl_InterpDeleted(interp)

int
Tcl_InterpActive(interp)

ARGUMENTS

Tcl_Interp *interp (en entrée)
Jeton pour l'interpréteur à détruire ou à interroger.

DESCRIPTION

Tcl_CreateInterp crée une nouvelle structure d'interpréteur et renvoie un jeton pour celle-ci. Le jeton est nécessaire pour les appels à la plupart des autres procédures Tcl, telles que Tcl_CreateCommand, Tcl_Eval et Tcl_DeleteInterp. Le jeton renvoyé par Tcl_CreateInterp ne peut être passé qu'aux routines Tcl appelées depuis le même thread que l'appel original à Tcl_CreateInterp. Il n'est pas sûr que plusieurs threads passent le même jeton aux routines de Tcl. Le nouvel interpréteur est initialisé avec les commandes Tcl intégrées et avec des variables standard comme tcl_platform et env. Pour intégrer des commandes supplémentaires, appelez Tcl_CreateCommand, et pour créer des variables supplémentaires, appelez Tcl_SetVar.

Tcl_DeleteInterp marque un interpréteur comme supprimé ; l'interpréteur sera éventuellement supprimé lorsque tous les appels à Tcl_Preserve pour celui-ci auront été mis en correspondance avec des appels à Tcl_Release. À ce moment-là, toutes les ressources qui lui sont associées, y compris les variables, les procédures et les liaisons de commandes spécifiques à l'application, seront supprimées. Après le retour de Tcl_DeleteInterp, toute tentative d'utilisation de Tcl_Eval sur l'interpréteur échouera et renverra TCL_ERROR. Après l'appel à Tcl_DeleteInterp, il est sûr d'examiner le résultat de l'interpréteur, d'interroger ou de définir les valeurs des variables, de définir, d'annuler la définition ou de récupérer des procédures, et d'examiner la pile d'évaluation d'exécution. Voir ci-dessous, dans la section INTERPRÉTEURS ET GESTION DE LA MÉMOIRE pour plus de détails.

Tcl_InterpDeleted renvoie une valeur non nulle si Tcl_DeleteInterp a été appelé avec interp comme argument ; cela indique que l'interpréteur sera éventuellement supprimé, lorsque le dernier appel à Tcl_Preserve pour celui-ci sera mis en correspondance avec un appel à Tcl_Release. Si une valeur non nulle est renvoyée, les appels ultérieurs à Tcl_Eval dans cet interpréteur renverront TCL_ERROR.

Tcl_InterpDeleted est utile dans les callbacks de suppression pour distinguer entre le moment où seule la mémoire dont le callback est responsable est en cours de suppression et le moment où l'interpréteur entier est en cours de suppression. Dans le premier cas, le callback peut recréer les données en cours de suppression, mais cela entraînerait une boucle infinie si l'interpréteur était en cours de suppression.

Tcl_InterpActive est utile pour déterminer s'il y a une exécution de scripts en cours dans un interpréteur, ce qui est une information utile lorsque Tcl est intégré dans un environnement à ramassage de miettes et qu'il devient nécessaire de déterminer si l'interpréteur est un candidat à la suppression. La fonction renvoie une valeur vraie si l'interpréteur a au moins une exécution active en cours d'exécution à l'intérieur, et une valeur fausse sinon.

INTERPRÉTEURS ET GESTION DE LA MÉMOIRE

Tcl_DeleteInterp peut être appelé à tout moment sur un interpréteur qui peut être utilisé par des évaluations imbriquées et du code C dans diverses extensions. Tcl implémente un mécanisme simple qui permet aux appelants d'utiliser des interpréteurs sans craindre que l'interpréteur ne soit supprimé dans un appel imbriqué, et sans nécessiter de code spécial pour protéger l'interpréteur, dans la plupart des cas. Ce mécanisme garantit que les utilisations imbriquées d'un interpréteur peuvent continuer à l'utiliser en toute sécurité même après que Tcl_DeleteInterp ait été appelé.

Le mécanisme repose sur la mise en correspondance des appels à Tcl_Preserve avec les appels à Tcl_Release. Si Tcl_DeleteInterp a été appelé, ce n'est que lorsque le dernier appel à Tcl_Preserve est mis en correspondance par un appel à Tcl_Release que l'interpréteur sera libéré. Voir la page de manuel de Tcl_Preserve pour une description de ces fonctions.

Les règles concernant le moment où l'utilisateur d'un interpréteur doit appeler Tcl_Preserve et Tcl_Release sont simples :

Interprèteurs Passés En Arguments
Les fonctions qui reçoivent un interpréteur en argument peuvent utiliser l'interpréteur en toute sécurité sans aucune protection spéciale. Ainsi, lorsque vous écrivez une extension composée de nouvelles commandes Tcl, aucun code spécial n'est nécessaire pour protéger les interpréteurs reçus en argument. Cela couvre la majorité de toutes les utilisations.
Création Et Suppression D'interpréteur
Lorsqu'un nouvel interpréteur est créé et utilisé dans un appel à Tcl_Eval, Tcl_VarEval, Tcl_GlobalEval, Tcl_SetVar ou Tcl_GetVar, une paire d'appels à Tcl_Preserve et Tcl_Release doit être encapsulée autour de toutes les utilisations de l'interpréteur. N'oubliez pas qu'il est dangereux d'utiliser l'interpréteur une fois que Tcl_Release a été appelé. Pour garantir que l'interpréteur est correctement supprimé lorsqu'il n'est plus nécessaire, appelez Tcl_InterpDeleted pour tester si un autre code a déjà appelé Tcl_DeleteInterp ; sinon, appelez Tcl_DeleteInterp avant d'appeler Tcl_Release dans votre propre code.
Récupération D'un Interpréteur D'une Structure De Données
Lorsqu'un interpréteur est récupéré d'une structure de données (par exemple, les données client d'un callback) pour être utilisé dans l'une des fonctions d'évaluation (Tcl_Eval, Tcl_VarEval, Tcl_GlobalEval, Tcl_EvalObjv, etc.) ou les fonctions d'accès aux variables (Tcl_SetVar, Tcl_GetVar, Tcl_SetVar2Ex, etc.), une paire d'appels à Tcl_Preserve et Tcl_Release doit être encapsulée autour de toutes les utilisations de l'interpréteur ; il est dangereux de réutiliser l'interpréteur une fois que Tcl_Release a été appelé. Si un interpréteur est stocké dans une structure de données de callback, un mécanisme de nettoyage de suppression approprié doit être configuré par le code qui crée la structure de données afin que l'interpréteur soit retiré de la structure de données (par exemple, en mettant le champ à NULL) lorsque l'interpréteur est supprimé. Sinon, vous pourriez utiliser un interpréteur qui a été libéré et dont la mémoire a peut-être déjà été réutilisée.

Toutes les utilisations des interpréteurs dans Tcl et Tk ont déjà été protégées. Les rédacteurs d'extensions doivent s'assurer que leur code protège également tous les interpréteurs supplémentaires utilisés, comme décrit ci-dessus.

Notez que les mécanismes de protection ne fonctionnent pas bien avec les systèmes de ramassage de miettes conventionnels. Dans un tel environnement géré, Tcl_InterpActive doit être utilisé pour déterminer quand un interpréteur est un candidat à la suppression en raison de l'inactivité.
