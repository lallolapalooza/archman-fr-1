Tcl_Interp(3) Procédures de bibliothèque Tcl Tcl_Interp(3)

NOM

Tcl_Interp - champs visibles par le client des structures d'interpréteur

SYNOPSIS

#include <tcl.h>

typedef struct {
    char *result;
    Tcl_FreeProc *freeProc;
    int errorLine;
} Tcl_Interp;
typedef void Tcl_FreeProc(
        char *blockPtr);

DESCRIPTION

La procédure Tcl_CreateInterp retourne un pointeur vers une structure Tcl_Interp. Les appelants de Tcl_CreateInterp doivent utiliser ce pointeur comme un jeton opaque, adapté à rien d'autre qu'à être passé à d'autres routines de l'interface Tcl. L'accès direct aux champs via le pointeur comme décrit ci-dessous n'est plus pris en charge. Les routines publiques prises en charge Tcl_SetResult, Tcl_GetResult, Tcl_SetErrorLine, Tcl_GetErrorLine doivent être utilisées à la place.

Pour les programmes existants et les extensions qui ne sont plus maintenus, les compilations contre les fichiers d'en-tête Tcl 8.6 ne sont possibles qu'avec les directives du compilateur

#define USE_INTERP_RESULT
et/ou 
#define USE_INTERP_ERRORLINE
selon les champs de la structure Tcl_Interp qui sont accédés. Ces directives peuvent être intégrées dans le code ou fournies via des options du compilateur.

Les champs result et freeProc sont utilisés pour retourner des résultats ou des messages d'erreur à partir des commandes. Ces informations sont retournées par les procédures de commande à Tcl_Eval, et par Tcl_Eval à ses appelants. Le champ result pointe vers la chaîne qui représente le résultat ou le message d'erreur, et le champ freeProc indique comment éliminer le stockage pour la chaîne lorsqu'elle n'est plus nécessaire. La manière la plus simple pour les procédures de commande de manipuler ces champs est d'appeler des procédures comme Tcl_SetResult ou Tcl_AppendResult ; elles masqueront tous les détails de gestion des champs. La description ci-dessous s'adresse à ceux qui manipulent directement les champs.

À chaque fois qu'une procédure de commande retourne, elle doit s'assurer que le champ result de son interpréteur pointe vers la chaîne retournée par la commande. Le champ result doit toujours pointer vers une chaîne valide. Si une commande souhaite ne retourner aucun résultat, alors interp->result doit pointer vers une chaîne vide. Normalement, les résultats sont supposés être alloués statiquement, ce qui signifie que le contenu ne changera pas avant la prochaine fois que Tcl_Eval sera appelée ou qu'une autre procédure de commande sera invoquée. Dans ce cas, le champ freeProc doit être nul. Alternativement, une procédure de commande peut allouer dynamiquement sa valeur de retour (par exemple, en utilisant Tcl_Alloc) et y stocker un pointeur dans interp->result. Dans ce cas, la procédure de commande doit également définir interp->freeProc à l'adresse d'une procédure qui peut libérer la valeur, ou à TCL_DYNAMIC si le stockage a été alloué directement par Tcl ou par un appel à Tcl_Alloc. Si interp->freeProc n'est pas nul, Tcl appellera freeProc pour libérer l'espace pointé par interp->result avant d'invoquer la commande suivante. Si une procédure cliente écrase interp->result alors que interp->freeProc n'est pas nul, elle est responsable de l'appel de freeProc pour libérer l'ancien interp->result (la macro Tcl_FreeResult doit être utilisée à cet effet).

FreeProc doit avoir des arguments et un résultat qui correspondent à la déclaration Tcl_FreeProc ci-dessus : elle reçoit un seul argument qui est un pointeur vers la valeur de résultat à libérer. Dans la plupart des applications, TCL_DYNAMIC est la seule valeur non nulle jamais utilisée pour freeProc. Cependant, une application peut stocker une adresse de procédure différente dans freeProc afin d'utiliser un allocateur de mémoire alternatif ou d'effectuer d'autres nettoyages lorsque la mémoire du résultat est libérée.

Dans le cadre du traitement de chaque commande, Tcl_Eval initialise interp->result et interp->freeProc juste avant d'appeler la procédure de commande pour cette commande. Le champ freeProc sera initialisé à zéro, et interp->result pointera vers une chaîne vide. Les commandes qui ne retournent aucune valeur peuvent simplement laisser les champs inchangés. De plus, la chaîne vide pointée par result fait en réalité partie d'un tableau de TCL_RESULT_SIZE caractères (environ 200). Si une commande souhaite retourner une courte chaîne, elle peut simplement la copier dans la zone pointée par interp->result. Ou, elle peut utiliser la procédure sprintf pour générer une courte chaîne de résultat à l'emplacement pointé par interp->result.

Il est de convention générale dans les applications basées sur Tcl que le résultat d'un interpréteur est normalement dans l'état initialisé décrit au paragraphe précédent. Les procédures qui manipulent le résultat d'un interpréteur (par exemple, en retournant une erreur) supposeront généralement que le résultat a été initialisé lors de l'appel de la procédure. Si une telle procédure doit être appelée après que le résultat ait été modifié, alors Tcl_ResetResult doit être appelée d'abord pour réinitialiser le résultat à son état initialisé. L'utilisation directe de interp->result est fortement déconseillée (voir Tcl_SetResult).

Le champ errorLine n'est valide qu'après que Tcl_Eval retourne un code de retour TCL_ERROR. Dans cette situation, le champ errorLine identifie le numéro de ligne de la commande en cours d'exécution lorsque l'erreur s'est produite. Les numéros de ligne sont relatifs à la commande en cours d'exécution : 1 signifie la première ligne de la commande passée à Tcl_Eval, 2 signifie la deuxième ligne, et ainsi de suite. Le champ errorLine est généralement utilisé en conjonction avec Tcl_AddErrorInfo pour signaler des informations sur l'endroit où une erreur s'est produite. ErrorLine ne doit normalement pas être modifié, sauf par Tcl_Eval.
