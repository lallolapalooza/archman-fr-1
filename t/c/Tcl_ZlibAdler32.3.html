ARGUMENTS

Tcl_Interp *interp (entree)
L'interpréteur dans lequel stocker les données compressées ou décompressées résultantes. Aussi là où les messages d'erreur sont écrits. Pour Tcl_ZlibStreamInit, cela peut être NULL pour créer un flux non lié à une commande.
int format (entree)
Quel format de données compressées manipuler. Doit être l'un des suivants : TCL_ZLIB_FORMAT_ZLIB pour les données au format zlib, TCL_ZLIB_FORMAT_GZIP pour les données au format gzip, ou TCL_ZLIB_FORMAT_RAW pour les données compressées brutes. De plus, pour la seule décompression, TCL_ZLIB_FORMAT_AUTO peut également être choisi, ce qui permet de détecter automatiquement si les données compressées étaient au format zlib ou gzip.
Tcl_Obj *dataObj (entree/sortie)
Une valeur de type tableau d'octets contenant les données à compresser ou décompresser, ou à laquelle les données extraites du flux sont ajoutées lorsqu'elles sont passées à Tcl_ZlibStreamGet.
int level (entree)
Quel niveau de compression utiliser. Doit être un nombre de 0 à 9 ou l'un des suivants : TCL_ZLIB_COMPRESS_NONE pour aucune compression, TCL_ZLIB_COMPRESS_FAST pour une compression rapide mais inefficace, TCL_ZLIB_COMPRESS_BEST pour une compression lente mais maximale, ou TCL_ZLIB_COMPRESS_DEFAULT pour le niveau recommandé par la bibliothèque zlib.
Tcl_Obj *dictObj (entree/sortie)
Un dictionnaire qui contient, ou sera mis à jour pour contenir, une description de l'en-tête gzip associé aux données compressées. Utile uniquement lorsque le paramètre format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Si NULL est passé, un en-tête par défaut sera utilisé lors de la compression et l'en-tête sera ignoré (hormis les vérifications d'intégrité) lors de la décompression. Voir la section DICTIONNAIRE DES OPTIONS GZIP pour les détails sur le contenu de ce dictionnaire.
unsigned int initValue (entree)
La valeur initiale pour l'algorithme de checksum.
int bufferSize (entree)
Un indice quant à la taille du tampon à utiliser pour recevoir les données. Utiliser 0 pour utiliser une estimation générique basée sur les données d'entrée.
unsigned char *bytes (entree)
Un tableau d'octets sur lequel exécuter l'algorithme de checksum, ou NULL pour obtenir la valeur initiale recommandée pour l'algorithme de checksum.
int length (entree)
Le nombre d'octets dans le tableau.
int mode (entree)
Quel mode utiliser pour le flux. Doit être soit TCL_ZLIB_STREAM_DEFLATE pour un flux de compression soit TCL_ZLIB_STREAM_INFLATE pour un flux de décompression.
Tcl_ZlibStream *zshandlePtr (sortie)
Un pointeur vers une variable dans laquelle écrire le jeton abstrait du flux en cas de création réussie.
Tcl_ZlibStream zshandle (entree)
Le jeton abstrait sur lequel opérer le flux.
int flush (entree)
Si et comment vider le flux après y avoir écrit les données. Doit être l'un des suivants : TCL_ZLIB_NO_FLUSH si aucun vidage n'est à effectuer, TCL_ZLIB_FLUSH si les données actuellement compressées doivent être mises à disposition en utilisant Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si le flux doit être mis dans un état où le décompresseur peut se rétablir en cas de corruption, ou TCL_ZLIB_FINALIZE pour s'assurer que le flux est terminé et que toute remorque exigée par le format est écrite.
int count (entree)
Le nombre maximum d'octets à obtenir du flux, ou -1 pour obtenir tous les octets restants des tampons du flux.
Tcl_Obj *compDict (entree)
Une valeur de type tableau d'octets qui est le dictionnaire de compression à utiliser avec le flux. Notez qu'il ne s'agit pas d'un dictionnaire Tcl, et il est recommandé que cela ne soit utilisé qu'avec des flux dont le format a été défini sur TCL_ZLIB_FORMAT_ZLIB car les autres formats n'ont aucun mécanisme pour indiquer si un dictionnaire de compression était présent, autre que l'échec lors de la décompression.

DESCRIPTION

Ces fonctions forment l'interface de la bibliothèque Tcl à la bibliothèque Zlib de Jean-loup Gailly et Mark Adler.

Tcl_ZlibDeflate et Tcl_ZlibInflate respectivement compressent et décompressent les données contenues dans l'argument dataObj, conformément aux arguments format et, pour la compression, level. Le dictionnaire de l'argument dictObj est utilisé pour transmettre des informations d'en-tête supplémentaires sur les données compressées lorsque le format de compression le supporte ; actuellement, le dictionnaire est seulement utilisé lorsque le paramètre format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Pour plus de détails sur le contenu du dictionnaire, voir la section DICTIONNAIRE DES OPTIONS GZIP ci-dessous. En cas de succès, les deux fonctions laissent les données compressées ou décompressées résultantes dans une valeur de type tableau d'octets qui est le résultat de l'interpréteur Tcl ; la valeur retournée est un code de résultat Tcl standard.

Tcl_ZlibAdler32 et Tcl_ZlibCRC32 calculent des checksums sur des tableaux d'octets, renvoyant le checksum calculé. Les checksums sont calculés de manière incrémentielle, permettant de traiter les données bloc par bloc, mais cela nécessite que l'appelant maintienne le checksum actuel et le passe comme paramètre initValue ; la valeur initiale à utiliser pour cela peut être obtenue en utilisant NULL pour le paramètre bytes au lieu d'un pointeur vers le tableau d'octets sur lequel calculer le checksum. Ainsi, une utilisation typique dans le cas d'un seul bloc de données ressemble à ceci :

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Notez que l'algorithme Adler-32 n'est pas un véritable checksum, mais plutôt un type de hachage connexe qui fonctionne mieux sur de grandes quantités de données.

FLUX ZLIB

Tcl_ZlibStreamInit crée un flux de compression ou de décompression qui est lié à une commande Tcl, selon ses arguments, et fournit un jeton abstrait pour le flux et retourne un code de résultat Tcl normal ; Tcl_ZlibStreamGetCommandName retourne le nom de cette commande étant donné le jeton du flux, ou NULL si le flux n'a pas de commande. Les flux ne sont pas conçus pour être thread-safe ; chaque flux ne devrait jamais être utilisé qu'à partir du thread qui l'a créé. Lors du travail avec des flux gzip, un dictionnaire (champs tels que donnés dans la section DICTIONNAIRE DES OPTIONS GZIP ci-dessous) peut être fourni via le paramètre dictObj qui, lors de la compression, permet de contrôler les en-têtes générés, et lors de la décompression, permet de découvrir les en-têtes existants. Notez que le dictionnaire sera écrit lors de la décompression une fois que suffisamment de données auront été lues pour avoir un en-tête complet. Cela signifie que le dictionnaire doit être une valeur non partagée dans ce cas ; une valeur vide créée avec Tcl_NewObj est suggérée.

Une fois qu'un flux a été construit, Tcl_ZlibStreamPut est utilisé pour ajouter des données au flux et Tcl_ZlibStreamGet est utilisé pour récupérer des données du flux après traitement. Les deux retournent des codes de résultat Tcl normaux et laissent un message d'erreur dans le résultat de l'interpréteur auquel le flux est enregistré en cas d'erreur (si une telle enregistrement a été effectué). Avec Tcl_ZlibStreamPut, le tableau de données passé ne doit pas être modifié par la suite. Avec Tcl_ZlibStreamGet, le tableau de données passé verra les octets de données ajoutés. Interne au flux, les données sont maintenues compressées afin de minimiser le coût de l'espace tampon.

NOM

TCL_ZLIB_STREAM_CLOSE

RÉSUMÉ

Tcl_ZlibStreamClose(stream)

ARGUMENTS

stream

DESCRIPTION

Tcl_ZlibStreamClose(stream) renvoie un code de résultat Tcl normal pour indiquer s'il a réussi ; si le flux est enregistré auprès d'un interpréteur, un message d'erreur sera laissé dans le résultat de l'interpréteur lorsque cette fonction renverra TCL_ERROR. Enfin, Tcl_ZlibStreamClose nettoiera le flux et supprimera la commande associée : utiliser Tcl_DeleteCommand sur la commande du flux est équivalent (lorsqu'une telle commande existe).

DICTIONNAIRE DES OPTIONS GZIP

Le paramètre dictObj à Tcl_ZlibDeflate, Tcl_ZlibInflate et Tcl_ZlibStreamInit est utilisé pour passer un dictionnaire d'options décrivant l'en-tête gzip dans les données compressées. Lors de la création de données compressées, le dictionnaire est lu et lors de la décompression des données compressées, le dictionnaire est écrit (dans ce cas, le paramètre dictObj doit faire référence à une valeur non partagée).

Les champs suivants dans la valeur du dictionnaire sont compris. Tous les autres champs sont ignorés. Aucun champ n'est nécessaire lors de la création d'un flux au format gzip.

comment
Ceci stocke le champ commentaire de l'en-tête, s'il est présent. S'il n'est pas présent, aucun commentaire n'a été fourni (en décompression) ou il sera créé (en compression).
crc
Une valeur booléenne indiquant si un CRC de l'en-tête est calculé. Note : le programme gzip n'utilise ni ne permet un CRC dans l'en-tête.
filename
Nom du fichier qui contenait les données non compressées. Vous devez éviter tout séparateur de répertoire et il doit être nettoyé avant d'être utilisé en décompression avec la commande file tail.
os
Valeur du champ type de système d'exploitation de l'en-tête (s'il ne s'agit pas de la valeur inconnue). Voir RFC 1952 pour la signification de ces codes. En compression, si cette valeur n'est pas présente, elle sera définie à inconnu.
size
Dimensions des données non compressées. Ce champ est ignoré en compression ; la taille des données compressées dépend de la quantité de données fournie au moteur de compression.
time
Valeur du champ de temps dans l'en-tête s'il n'est pas nul, attendu comme le moment où le fichier nommé par le champ filename a été modifié. Il convient pour une utilisation avec le format clock. En création, la valeur correcte à utiliser est celle de clock seconds ou file mtime.
type
Types des données non compressées (binaire ou texte) si connu.

NOTES DE PORTABILITÉ

Ces fonctions échoueront gracieusement si Tcl n'est pas lié à la bibliothèque zlib.
