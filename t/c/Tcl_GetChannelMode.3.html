DESCRIPTION

Tcl utilise une architecture de canaux à deux niveaux. Il fournit une couche supérieure générique pour permettre aux programmes C et Tcl d'effectuer des entrées et des sorties en utilisant les mêmes API pour une variété de fichiers, périphériques, sockets, etc. Les API C génériques sont décrites dans l'entrée de manuel de Tcl_OpenFileChannel.

La couche inférieure fournit des pilotes de canaux spécifiques au type pour chaque type de périphérique supporté sur chaque plateforme. Cette entrée de manuel décrit les API C utilisées pour communiquer entre la couche générique et les pilotes de canaux spécifiques au type. Elle explique également comment de nouveaux types de canaux peuvent être ajoutés en fournissant de nouveaux pilotes de canaux.

Les pilotes de canaux se composent de plusieurs composants : Premièrement, chaque pilote de canal fournit une structure Tcl_ChannelType contenant des pointeurs vers des fonctions implémentant les diverses opérations utilisées par la couche générique pour communiquer avec le pilote de canal. La structure Tcl_ChannelType et les fonctions auxquelles elle fait référence sont décrites dans la section TCL_CHANNELTYPE, ci-dessous.

Deuxièmement, les pilotes de canaux fournissent généralement une commande Tcl pour créer des instances de ce type de canal. Par exemple, la commande Tcl open crée des canaux qui utilisent les pilotes de canaux de fichier et de commande, et la commande Tcl socket crée des canaux qui utilisent des sockets TCP pour la communication réseau.

Troisièmement, un pilote de canal fournit facultativement une fonction C pour ouvrir des instances de canal de ce type. Par exemple, Tcl_OpenFileChannel ouvre un canal qui utilise le pilote de canal de fichier, et Tcl_OpenTcpClient ouvre un canal qui utilise le protocole réseau TCP. Ces fonctions de création utilisent généralement Tcl_CreateChannel en interne pour ouvrir le canal.

Pour ajouter un nouveau type de canal, vous devez implémenter une API C ou une commande Tcl qui ouvre un canal en invoquant Tcl_CreateChannel. Lorsque votre pilote appelle Tcl_CreateChannel, il lui transmet une structure Tcl_ChannelType décrivant les procédures d'E/S du pilote. La couche générique invoquera alors les fonctions référencées dans cette structure pour effectuer des opérations sur le canal.

Tcl_CreateChannel ouvre un nouveau canal et lui associe les paramètres typePtr et instanceData fournis. Le canal est ouvert dans le mode indiqué par mask. Pour une discussion sur les pilotes de canaux, leurs opérations et la structure Tcl_ChannelType, voir la section TCL_CHANNELTYPE, ci-dessous.

Tcl_CreateChannel interagit avec le code gérant les canaux standards. Une fois qu'un canal standard a été initialisé soit par un appel à Tcl_GetStdChannel, soit par un appel à Tcl_SetStdChannel, la fermeture de ce canal standard entraînera le fait que le prochain appel à Tcl_CreateChannel fera également du nouveau canal le nouveau canal standard. Voir Tcl_StandardChannels pour un traité général sur les canaux standards et le comportement de la bibliothèque Tcl à leur égard.

Tcl_GetChannelInstanceData renvoie les données d'instance associées au canal dans channel. Ceci est identique à l'argument instanceData de l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelType renvoie un pointeur vers la structure Tcl_ChannelType utilisée par le canal dans l'argument channel. Ceci est identique à l'argument typePtr de l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelName renvoie une chaîne contenant le nom associé au canal, ou NULL si l'argument channelName de Tcl_CreateChannel était NULL.

Tcl_GetChannelHandle place le handle de périphérique spécifique au système d'exploitation associé à channel pour la direction direction donnée dans le

location specified by handlePtr and returns TCL_OK. If the channel does not have a device handle for the specified direction, then TCL_ERROR is returned instead. Different channel drivers will return different types of handle. Refer to the manual entries for each driver to determine what type of handle is returned.

Tcl_GetChannelThread returns the id of the thread currently managing the specified channel. This allows channel drivers to send their file events to the correct event queue even for a multi-threaded core.

Tcl_GetChannelMode returns an OR-ed combination of TCL_READABLE and TCL_WRITABLE, indicating whether the channel is open for input and output.

Tcl_GetChannelBufferSize returns the size, in bytes, of buffers allocated to store input or output in channel. If the value was not set by a previous call to Tcl_SetChannelBufferSize, described below, then the default value of 4096 is returned.

Tcl_SetChannelBufferSize sets the size, in bytes, of buffers that will be allocated in subsequent operations on the channel to store input or output. The size argument should be between one and one million, allowing buffers of one byte to one million bytes. If size is outside this range, Tcl_SetChannelBufferSize sets the buffer size to 4096.

Tcl_NotifyChannel is called by a channel driver to indicate to the generic layer that the events specified by mask have occurred on the channel. Channel drivers are responsible for invoking this function whenever the channel handlers need to be called for the channel (or other pending tasks like a write flush should be performed). See WATCHPROC below for more details.

Tcl_BadChannelOption is called from driver specific setOptionProc or getOptionProc to generate a complete error message.

Tcl_ChannelBuffered returns the number of bytes of input currently buffered in the internal buffer (push back area) of the channel itself. It does not report about the data in the overall buffers for the stack of channels the supplied channel is part of.

Tcl_IsChannelShared checks the refcount of the specified channel and returns whether the channel was shared among multiple interpreters (result == 1) or not (result == 0).

Tcl_IsChannelRegistered checks whether the specified channel is registered in the given interpreter (result == 1) or not (result == 0).

Tcl_IsChannelExisting checks whether a channel with the specified name is registered in the (thread)-global list of all channels (result == 1) or not (result == 0).

Tcl_CutChannel removes the specified channel from the (thread)global list of all channels (of the current thread). Application to a channel still registered in some interpreter is not allowed. Also notifies the driver if the Tcl_ChannelType version is TCL_CHANNEL_VERSION_4 (or higher), and Tcl_DriverThreadActionProc is defined for it.

Tcl_SpliceChannel adds the specified channel to the (thread)global list of all channels (of the current thread). Application to a channel registered in some interpreter is not allowed. Also notifies the driver if the Tcl_ChannelType version is TCL_CHANNEL_VERSION_4 (or higher), and Tcl_DriverThreadActionProc is defined for it.

Tcl_ClearChannelHandlers removes all channel handlers and event scripts associated with the specified channel, thus shutting down all event processing for this channel.

TCL_CHANNELTYPE

Un pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers des fonctions implémentant les diverses opérations sur un canal ; ces opérations sont invoquées au besoin par la couche générique. La structure a été versionnée à partir de Tcl 8.3.2/8.4 pour corriger un problème avec les canaux empilés. Voir la section OLD CHANNEL TYPES ci-dessous pour plus de détails sur l'ancienne structure.

La structure Tcl_ChannelType contient les champs suivants :

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Il n'est pas nécessaire de fournir des implémentations pour toutes les opérations sur les canaux. Celles qui ne sont pas nécessaires peuvent être mises à NULL dans la structure : blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc, et close2Proc, en plus de flushProc, handlerProc, threadActionProc, et truncateProc. Les autres fonctions qui ne peuvent pas être implémentées de manière significative devraient retourner EINVAL lorsqu'elles sont appelées, pour indiquer que les opérations qu'elles représentent ne sont pas disponibles. Notez également que wideSeekProc peut être NULL si seekProc l'est.

L'utilisateur ne doit utiliser que la structure ci-dessus pour l'instanciation de Tcl_ChannelType. Lors de la référence aux champs d'une structure Tcl_ChannelType, les fonctions suivantes doivent être utilisées pour obtenir les valeurs : Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc, ou Tcl_ChannelHandlerProc.

La modification des structures a été faite de manière à ce que les types de canaux standard soient binaires compatibles. Cependant, les types de canaux qui utilisent des canaux empilés (c'est-à-dire TLS, Trf) ont de nouvelles versions pour correspondre au changement ci-dessus, car le code précédent pour les canaux empilés avait des problèmes.

TYPENAME

Le champ typeName contient une chaîne terminée par un nul qui identifie le type du périphérique implémenté par ce pilote, par exemple file ou socket.

Cette valeur peut être récupérée avec Tcl_ChannelName, qui renvoie un pointeur vers la chaîne.

VERSION

Le champ version doit être défini à la version de la structure dont vous avez besoin. TCL_CHANNEL_VERSION_2 est le minimum recommandé. TCL_CHANNEL_VERSION_3 doit être défini pour spécifier le membre wideSeekProc. TCL_CHANNEL_VERSION_4 doit être défini pour spécifier le membre threadActionProc (inclut wideSeekProc). TCL_CHANNEL_VERSION_5 doit être défini pour spécifier les membres truncateProc (inclut wideSeekProc et threadActionProc). S'il n'est défini à aucune de ces valeurs, alors ce Tcl_ChannelType est supposé avoir la structure d'origine. Voir OLD CHANNEL TYPES pour plus de détails. Bien que Tcl reconnaisse et fonctionne avec les deux structures, les canaux empilés doivent être d'au moins TCL_CHANNEL_VERSION_2 pour fonctionner correctement.

Cette valeur peut être récupérée avec Tcl_ChannelVersion, qui renvoie l'une des valeurs TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 ou TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

Le champ blockModeProc contient l'adresse d'une fonction appelée par la couche générique pour définir le mode bloquant et non bloquant sur le périphérique. BlockModeProc doit correspondre au prototype suivant :

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

instanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. L'argument mode est soit TCL_MODE_BLOCKING soit TCL_MODE_NONBLOCKING pour définir le périphérique en mode bloquant ou non bloquant. La fonction doit retourner zéro si l'opération a réussi, ou un code d'erreur POSIX non nul si l'opération a échoué.

Si l'opération réussit, la fonction peut modifier le instanceData fourni pour enregistrer que le canal est entré en mode bloquant ou non bloquant et pour implémenter le comportement bloquant ou non bloquant. Pour certains types de périphériques, le comportement bloquant et non bloquant peut être implémenté par le système d'exploitation sous-jacent ; pour d'autres types de périphériques, le comportement doit être émulé dans le pilote du canal.

Cette valeur peut être récupérée avec Tcl_ChannelBlockModeProc, qui renvoie un pointeur vers la fonction.

Un pilote de canal qui ne fournit pas de blockModeProc doit être très, très prudent. Il doit indiquer à la couche générique quel mode bloquant lui est acceptable, et cela doit également être documenté pour l'utilisateur afin que le mode bloquant du canal ne soit pas modifié à une valeur inacceptable. Toute confusion ici peut entraîner l'interpréteur dans une impasse (fantomatique et difficile à trouver).

Tcl_ChannelType

A structure of this type describes a channel driver. Channel drivers are used by Tcl to implement I/O channels. Tcl uses the information in the Tcl_ChannelType structure to invoke driver-specific routines to perform operations like reading, writing, closing, or seeking on a channel. Tcl channels are created using Tcl_CreateChannel, which takes a pointer to a Tcl_ChannelType structure describing the new channel.

The structure has the following fields:

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        ClientData driverData;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverWideSeekProc *wideSeekProc;
} Tcl_ChannelType;

The fields are:

typeName
Name of this channel type (e.g. "file", "socket", "pipe"). This is used primarily for internal Tcl use. It must be unique for each channel driver. This field may not be NULL.
closeProc
Procedure called to close the channel. May be NULL. See section CLOSEPROC for details.
inputProc
Procedure called to read data from the channel. May be NULL. See section INPUTPROC for details.
outputProc
Procedure called to write data to the channel. May be NULL. See section OUTPUTPROC for details.
seekProc
Procedure called to seek on the channel. May be NULL. See section SEEKPROC AND WIDESEEKPROC for details.
setOptionProc
Procedure called to set channel-specific options. May be NULL. See section SETOPTIONPROC for details.
getOptionProc
Procedure called to get channel-specific options. May be NULL. See section GETOPTIONPROC for details.
driverData
A value that should be passed as the instanceData argument to all other channel driver procedures for this channel type. This is used to hold global state for a channel type, such as file system information.
close2Proc
Procedure called to close the channel. May be NULL. See section CLOSEPROC for details. This field allows channels to support independent closing of the read and write sides of the channel.
wideSeekProc
Procedure called to seek on the channel, supporting offsets larger than 32 bits. May be NULL. See section SEEKPROC AND WIDESEEKPROC for details.

DESCRIPTION

A Tcl channel driver is defined by a Tcl_ChannelType structure. This structure contains pointers to functions that implement the various operations (read, write, close, seek, set/get options) for a channel. The Tcl library implements a generic channel layer that multiplexes I/O operations across different channel drivers. When a channel is created using Tcl_CreateChannel, the caller provides a pointer to a Tcl_ChannelType structure that describes the channel's behavior.

The fields in the Tcl_ChannelType structure are function pointers that the generic channel layer calls to perform operations on the channel. These functions are specific to the channel's underlying implementation (e.g., a file, a socket, a pipe). The field names correspond to the operations they perform.

CLOSEPROC

The closeProc field contains the address of a function called by the generic layer to close the channel. closeProc must match the following prototype:

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

InstanceData is the same value that was passed to Tcl_CreateChannel when the channel was created. The function should perform any necessary cleanup for the channel, such as closing file descriptors or freeing allocated memory. The function should return zero if the close operation was successful; otherwise it should return a nonzero POSIX error code. In addition, if an error occurs and interp is not NULL, the procedure should store an error message in the interpreter's result.

Alternatively, channels that support closing the read and write sides independently may set closeProc to TCL_CLOSE2PROC and set close2Proc to the address of a function that matches the following prototype:

typedef int Tcl_DriverClose2Proc(
        ClientData instanceData,
        Tcl_Interp *interp,
        int flags);

The close2Proc will be called with flags set to an OR'ed combination of TCL_CLOSE_READ or TCL_CLOSE_WRITE to indicate that the driver should close the read and/or write side of the channel. The channel driver may be invoked to perform additional operations on the channel after close2Proc is called to close one or both sides of the channel. If flags is 0 (zero), the driver should close the channel in the manner described above for closeProc. No further operations will be invoked on this instance after close2Proc is called with all flags cleared. In all cases, the close2Proc function should return zero if the close operation was successful; otherwise it should return a nonzero POSIX error code. In addition, if an error occurs and interp is not NULL, the procedure should store an error message in the interpreter's result.

The closeProc and close2Proc values can be retrieved with Tcl_ChannelCloseProc or Tcl_ChannelClose2Proc, which return a pointer to the respective function.

INPUTPROC

The inputProc field contains the address of a function called by the generic layer to read data from the file or device and store it in an internal buffer. InputProc must match the following prototype:

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

InstanceData is the same as the value passed to Tcl_CreateChannel when the channel was created. The buf argument points to an array of bytes in which to store input from the device, and the bufSize argument indicates how many bytes are available at buf.

The errorCodePtr argument points to an integer variable provided by the generic layer. If an error occurs, the function should set the variable to a POSIX error code that identifies the error that occurred.

The function should read data from the input device encapsulated by the channel and store it at buf. On success, the function should return a nonnegative integer indicating how many bytes were read from the input device and stored at buf. On error, the function should return -1. If an error occurs after some data has been read from the device, that data is lost.

If inputProc can determine that the input device has some data available but less than requested by the bufSize argument, the function should only attempt to read as much data as is available and return without blocking. If the input device has no data available whatsoever and the channel is in nonblocking mode, the function should return an EAGAIN error. If the input device has no data available whatsoever and the channel is in blocking mode, the function should block for the shortest possible time until at least one byte of data can be read from the device; then, it should return as much data as it can read without blocking.

This value can be retrieved with Tcl_ChannelInputProc, which returns a pointer to the function.

OUTPUTPROC

The outputProc field contains the address of a function called by the generic layer to transfer data from an internal buffer to the output device. OutputProc must match the following prototype:

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

InstanceData is the same as the value passed to Tcl_CreateChannel when the channel was created. The buf argument contains an array of bytes to be written to the device, and the toWrite argument indicates how many bytes are to be written from the buf argument.

The errorCodePtr argument points to an integer variable provided by the generic layer. If an error occurs, the function should set this variable to a POSIX error code that identifies the error.

The function should write the data at buf to the output device encapsulated by the channel. On success, the function should return a nonnegative integer indicating how many bytes were written to the output device. The return value is normally the same as toWrite, but may be less in some cases such as if the output operation is interrupted by a signal. If an error occurs the function should return -1. In case of error, some data may have been written to the device.

If the channel is nonblocking and the output device is unable to absorb any data whatsoever, the function should return -1 with an EAGAIN error without writing any data.

This value can be retrieved with Tcl_ChannelOutputProc, which returns a pointer to the function.

SEEKPROC AND WIDESEEKPROC

The seekProc field contains the address of a function called by the generic layer to move the access point at which subsequent input or output operations will be applied. SeekProc must match the following prototype:

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

The instanceData argument is the same as the value given to Tcl_CreateChannel when this channel was created. Offset and seekMode have the same meaning as for the Tcl_Seek procedure (described in the manual entry for Tcl_OpenFileChannel).

The errorCodePtr argument points to an integer variable provided by the generic layer for returning errno values from the function. The function should set this variable to a POSIX error code if an error occurs. The function should store an EINVAL error code if the channel type does not implement seeking.

The return value is the new access point or -1 in case of error. If an error occurred, the function should not move the access point.

If there is a non-NULL seekProc field, the wideSeekProc field may contain the address of an alternative function to use which handles wide (i.e. larger than 32-bit) offsets, so allowing seeks within files larger than 2GB. The wideSeekProc will be called in preference to the seekProc, but both must be defined if the wideSeekProc is defined. WideSeekProc must match the following prototype:

typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

The arguments and return values mean the same thing as with seekProc above, except that the type of offsets and the return type are different.

The seekProc value can be retrieved with Tcl_ChannelSeekProc, which returns a pointer to the function, and similarly the wideSeekProc can be retrieved with Tcl_ChannelWideSeekProc.

SETOPTIONPROC

The setOptionProc field contains the address of a function called by the generic layer to set a channel type specific option on a channel. setOptionProc must match the following prototype:

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

optionName is the name of an option to set, and newValue is the new value for that option, as a string. The instanceData is the same as the value given to Tcl_CreateChannel when this channel was created. The function should do whatever channel type specific action is required to implement the new value of the option.

Some options are handled by the generic code and this function is never called to set them, e.g. -blockmode. Other options are specific to each channel type and the setOptionProc procedure of the channel driver will get called to implement them. The setOptionProc field can be NULL, which indicates that this channel type supports no type specific options.

If the option value is successfully modified to the new value, the function returns TCL_OK. It should call Tcl_BadChannelOption which itself returns TCL_ERROR if the optionName is unrecognized. If newValue specifies a value for the option that is not supported or if a system call error occurs, the function should leave an error message in the result of interp if interp is not NULL. The function should also call Tcl_SetErrno to store an appropriate POSIX error code.

This value can be retrieved with Tcl_ChannelSetOptionProc, which returns a pointer to the function.

GETOPTIONPROC

The getOptionProc field contains the address of a function called by the generic layer to get the value of a channel type specific option on a channel. getOptionProc must match the following prototype:

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        Tcl_DString *optionValue);

OptionName is the name of an option supported by this type of channel. If the option name is not NULL, the function stores its current value, as a string, in the Tcl dynamic string optionValue. If optionName is NULL, the function stores in optionValue an alternating list of all supported options and their current values. On success, the function returns TCL_OK. It should call Tcl_BadChannelOption which itself returns TCL_ERROR if the optionNa

me est inconnu. Si une erreur d'appel système se produit, la fonction doit laisser un message d'erreur dans le résultat de interp si interp n'est pas NULL. La fonction doit également appeler Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

Certaines options sont gérées par le code générique et cette fonction n'est jamais appelée pour récupérer leur valeur, par exemple -blockmode. D'autres options sont spécifiques à chaque type de canal et la procédure getOptionProc du pilote de canal sera appelée pour les implémenter. Le champ getOptionProc peut être NULL, ce qui indique que ce type de canal ne prend en charge aucune option spécifique au type.

Cette valeur peut être récupérée avec Tcl_ChannelGetOptionProc, qui renvoie un pointeur vers la fonction.

WATCHPROC

Le champ watchProc contient l'adresse d'une fonction appelée par la couche générique pour initialiser le mécanisme de notification d'événements afin de détecter les événements d'intérêt sur ce canal. WatchProc doit correspondre au prototype suivant :

typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. L'argument mask est une combinaison OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION ; il indique les événements que l'appelant souhaite détecter sur ce canal.

La fonction doit initialiser les mécanismes spécifiques au type d'appareil pour détecter lorsqu'un événement d'intérêt est présent sur le canal. Lorsqu'un ou plusieurs des événements désignés se produisent sur le canal, le pilote du canal est responsable d'appeler Tcl_NotifyChannel pour informer le module de canal générique. Le pilote doit veiller à ne pas affamer les autres pilotes de canal ou sources de rappels en invoquant Tcl_NotifyChannel trop fréquemment. L'équité peut être assurée en utilisant la file d'attente d'événements Tcl pour permettre la planification de l'événement du canal en séquence avec d'autres événements. Voir la description de Tcl_QueueEvent pour plus de détails sur la mise en file d'attente d'un événement.

Cette valeur peut être récupérée avec Tcl_ChannelWatchProc, qui renvoie un pointeur vers la fonction.

GETHANDLEPROC

Le champ getHandleProc contient l'adresse d'une fonction appelée par la couche générique pour récupérer un descripteur spécifique à l'appareil à partir du canal. GetHandleProc doit correspondre au prototype suivant :

typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. L'argument direction est soit TCL_READABLE pour récupérer le descripteur utilisé pour l'entrée, soit TCL_WRITABLE pour récupérer le descripteur utilisé pour la sortie.

Si l'implémentation du canal possède des descripteurs spécifiques à l'appareil, la fonction doit récupérer le descripteur approprié associé au canal, selon l'argument direction. Le descripteur doit être stocké à l'emplacement référencé par handlePtr, et TCL_OK doit être renvoyé. Si le canal n'est pas ouvert pour la direction spécifiée, ou si l'implémentation du canal n'utilise pas de descripteurs d'appareil, la fonction doit renvoyer TCL_ERROR.

Cette valeur peut être récupérée avec Tcl_ChannelGetHandleProc, qui renvoie un pointeur vers la fonction.

FLUSHPROC

Le champ flushProc est actuellement réservé pour une utilisation future. Il doit être défini à NULL. FlushProc doit correspondre au prototype suivant :

typedef int Tcl_DriverFlushProc(
        ClientData instanceData);

Cette valeur peut être récupérée avec Tcl_ChannelFlushProc, qui renvoie un pointeur vers la fonction.

HANDLERPROC

Le champ handlerProc contient l'adresse d'une fonction appelée par la couche générique pour notifier le canal qu'un événement s'est produit. Il doit être défini pour les pilotes de canal empilés qui souhaitent être informés des événements qui se produisent sur le canal sous-jacent (empilé). HandlerProc doit correspondre au prototype suivant :

typedef int Tcl_DriverHandlerProc(
        ClientData instanceData,
        int interestMask);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. Le interestMask est une combinaison OR de TCL_READABLE ou TCL_WRITABLE ; il indique quel type d'événement s'est produit sur ce canal.

Cette valeur peut être récupérée avec Tcl_ChannelHandlerProc, qui renvoie un pointeur vers la fonction.

THREADACTIONPROC

Le champ threadActionProc contient l'adresse de la fonction appelée par la couche générique lorsqu'un canal est créé, fermé ou sur le point d'être déplacé vers un autre thread, c'est-à-dire chaque fois que l'état du pilote spécifique au thread pourrait devoir être initialisé ou mis à jour. Il peut être NULL. L'action TCL_CHANNEL_THREAD_REMOVE est utilisée pour notifier le pilote qu'il doit mettre à jour ou supprimer toute donnée spécifique au thread qu'il pourrait maintenir pour le canal.

L'action TCL_CHANNEL_THREAD_INSERT est utilisée pour notifier le pilote qu'il doit mettre à jour ou initialiser toute donnée spécifique au thread qu'il pourrait maintenir en utilisant le thread appelant comme associé. Voir Tcl_CutChannel et Tcl_SpliceChannel pour plus de détails.

typedef void Tcl_DriverThreadActionProc(
        ClientData instanceData,
        int action);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal.

Ces valeurs peuvent être récupérées avec Tcl_ChannelThreadActionProc, qui renvoie un pointeur vers la fonction.

TRUNCATEPROC

Le champ truncateProc contient l'adresse de la fonction appelée par la couche générique lorsqu'un canal est tronqué à une certaine longueur. Il peut être NULL.

typedef int Tcl_DriverTruncateProc(
        ClientData instanceData,
        Tcl_WideInt length);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal, et length est la nouvelle longueur du fichier sous-jacent, qui ne doit pas être négative. Le résultat doit être 0 en cas de succès ou un code errno (adapté à une utilisation avec Tcl_SetErrno) en cas d'échec.

Ces valeurs peuvent être récupérées avec Tcl_ChannelTruncateProc, qui renvoie un pointeur vers la fonction.

TCL_BADCHANNELOPTION

Cette procédure génère un message d'erreur « mauvaise option » dans un interpréteur (optionnel). Elle est utilisée par les pilotes de canal lorsqu'une option Set/Get invalide est demandée. Son but est de concaténer la liste des options génériques aux options spécifiques et de factoriser la chaîne de message d'erreur des options génériques.

Elle renvoie toujours TCL_ERROR

Un message d'erreur est généré dans la valeur de résultat d'interp pour indiquer qu'une commande a été invoquée avec une mauvaise option. Le message a la forme

    mauvaise option "blah" : doit être l'une des
    <...options génériques...>+<...options spécifiques...>
ainsi vous obtenez par exemple : 
    mauvaise option "-blah" : doit être l'une des -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, ou -sockname
lorsqu'elle est appelée avec optionList égal à « peername sockname »

“blah” est l'argument optionName et “<options spécifiques>” est une liste d'options spécifiques séparée par des espaces. La fonction prend grand soin d'insérer des signes moins avant chaque option, des virgules après, et un « ou » avant la dernière option.

La structure Tcl_ChannelType d'origine (8.3.1 et versions antérieures) contient les champs suivants :

typedef struct Tcl_ChannelType {

Il est toujours possible de créer des canaux avec la structure ci-dessus. Le code interne des canaux déterminera la version. Avant la version 8.4.0 (c'est-à-dire lors des dernières versions de 8.3 et du début du cycle de développement de 8.4), la structure Tcl_ChannelType contenait les champs suivants :

typedef struct Tcl_ChannelType {

DESCRIPTION

These functions provide an API for managing Tcl channels. Channels are Tcl's abstraction for input/output. They can be connected to files, sockets, pipes, or other devices. The Tcl channel driver mechanism is used to implement different types of channels, such as those for serial ports, network sockets, or pipes.

The functions allow you to get and set channel modes (blocking or nonblocking), buffer sizes, and options. You can also get information about a channel, such as its name and type, and check if it is a standard channel (stdin, stdout, stderr). The functions also provide ways to create, register, and find channel types, as well as to manage the underlying file handles associated with channels.

The `Tcl_MakeFile` and `Tcl_MakeIOChannel` functions are used to create Tcl channels from existing file handles or descriptors. `Tcl_GetOpenFile` allows you to get the underlying file descriptor for a Tcl channel. `Tcl_NewChannelType` is used to define a new channel type, and `Tcl_RegisterChannel` and `Tcl_UnregisterChannel` manage the registration of channel types within a Tcl interpreter.

The functions `Tcl_ChannelSetHandle`, `Tcl_ChannelHandle`, `Tcl_ChannelName`, `Tcl_ChannelVersion`, `Tcl_ChannelBlockMode`, `Tcl_ChannelOptions`, `Tcl_ChannelGetMode`, `Tcl_ChannelSetMode`, `Tcl_ChannelGetOption`, `Tcl_ChannelSetOption`, `Tcl_ChannelGetHandle`, `Tcl_ChannelSetHandle`, `Tcl_ChannelCloseHandle`, `Tcl_ChannelNames`, and `Tcl_ChannelTypes` provide more specific ways to interact with Tcl channels and their associated properties.

TCL_CHANNELTYPE

A `Tcl_ChannelType` structure defines the behavior of a particular type of Tcl channel. It contains pointers to functions that implement operations such as reading, writing, flushing, closing, and getting/setting options for that channel type.

TCL_BADCHANNELOPTION

This is an error code returned when an invalid option is specified for a channel operation.

OLD CHANNEL TYPES

Older versions of Tcl used a different channel driver interface. The functions documented here represent the modern API for channel management.
