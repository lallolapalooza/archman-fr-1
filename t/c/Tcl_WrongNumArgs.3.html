Tcl_WrongNumArgs(3) Procédures de bibliothèque Tcl Tcl_WrongNumArgs(3)

NOM

Tcl_WrongNumArgs - génère un message d'erreur standard pour un nombre incorrect d'arguments

SYNOPIS

#include <tcl.h>

Tcl_WrongNumArgs(interp, objc, objv, message)

ARGUMENTS

Tcl_Interp interp (entree)
Interpréteur dans lequel l'erreur sera signalée : le message d'erreur sera stocké dans son résultat.
int objc (entree)
Nombre d'arguments initiaux de objv à inclure dans le message d'erreur.
Tcl_Obj *const objv[] (entree)
Arguments de la commande qui avait le mauvais nombre d'arguments.
const char *message (entree)
Informations supplémentaires d'erreur à afficher après les arguments initiaux de objv. Ceci donne typiquement la syntaxe acceptable de la commande. Cet argument peut être NULL.

DESCRIPTION

Tcl_WrongNumArgs est une procédure utilitaire qui est appelée par les procédures de commande lorsqu'elles découvrent qu'elles ont reçu un nombre incorrect d'arguments. Tcl_WrongNumArgs génère un message d'erreur standard et le stocke dans le résultat de interp. Le message inclut les objc premiers éléments de objv plus message. Par exemple, si objv consiste en les valeurs foo et bar, objc est 1, et message est “fileName count” alors le résultat de interp sera défini sur la chaîne suivante :

mauvais # arguments : devrait être "foo fileName count"

Si objc est 2, le résultat sera défini sur la chaîne suivante :

mauvais # arguments : devrait être "foo bar fileName count"

Objc est généralement 1, mais peut être 2 ou plus pour des commandes comme string et les commandes de widget Tk, qui utilisent le premier argument comme sous-commande.

Certaines des valeurs dans le tableau objv peuvent être des abréviations pour une sous-commande. La commande Tcl_GetIndexFromObj convertira la valeur de chaîne abrégée en un indexObject. Si une erreur se produit lors de l'analyse de la sous-commande, nous aimerions utiliser le nom complet de la sous-commande plutôt que l'abréviation. En utilisant l'exemple ci-dessus, supposons que bar est en fait une abréviation pour barfly et que la valeur est maintenant un indexObject car elle a été passée à Tcl_GetIndexFromObj. Dans ce cas, le message d'erreur serait :

mauvais # arguments : devrait être "foo barfly fileName count"
