Utilisé pour le reporting d'erreurs et pour rechercher un canal enregistré en son sein.

Le nom d'un fichier local ou réseau.
const char *mode (en)
Spécifie comment le fichier doit être accédé. Peut avoir l'une des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (en)
Indicateurs de permission de style POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront définies sur le fichier créé.
int argc (en)
Le nombre d'éléments dans argv.
const char **argv (en)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont la même signification que les arguments non-options de la commande Tcl exec.

Spécifie la disposition des descripteurs stdio dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, le stdin du premier fils dans le pipe est le canal du pipe, sinon il est le même que l'entrée standard du processus appelant ; de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, le pipe peut rediriger les descripteurs stdio pour outrepasser les descripteurs stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, de telles redirections provoquent une erreur.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des périphériques et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie en mémoire tampon sur une variété de types de fichiers, de sockets et de périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée de la page man de Tcl_CreateChannel. Le mécanisme de canaux fournit un schéma de mise en mémoire tampon inspiré de l'E/S standard d'Unix, et il permet également des E/S non bloquantes sur les canaux.

Les procédures décrites dans cette page man constituent les API C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canaux et comment implémenter des pilotes de canaux pour de nouveaux types de canaux, consultez l'entrée de la page man de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Ouvre un canal pour le fichier nommé fileName. Le comportement d'ouverture est contrôlé par mode et permissions. Les valeurs de mode sont les mêmes que celles utilisées par la commande open de Tcl. Le champ permissions spécifie les permissions de fichier à utiliser si le fichier est créé. La valeur de retour est un handle de canal ou le canal NULL si une erreur se produit. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

Les valeurs de mode peuvent être n'importe quelle combinaison des lettres suivantes :

r
Ouverture en lecture seule.
w
Ouverture en écriture seule. Le fichier est tronqué s'il existe.
a
Ouverture en écriture seule. Le pointeur de fichier est positionné à la fin du fichier s'il existe.
r+
Ouverture pour lecture et écriture.
w+
Ouverture pour lecture et écriture. Le fichier est tronqué s'il existe.
a+
Ouverture pour lecture et écriture. Le pointeur de fichier est positionné à la fin du fichier s'il existe.

Les options suivantes peuvent également être ajoutées à ces modes:

b
Mode binaire. Les données sont lues et écrites telles quelles, sans aucune conversion de fin de ligne ou d'encodage.
c
Crée le fichier s'il n'existe pas. Une erreur se produit si le fichier existe déjà.
t
Mode texte. Les données sont converties en utilisant l'encodage de canal spécifié ou l'encodage par défaut du système.

Le comportement exact de r+, w+ et a+ dépend du système d'exploitation.

Si le nom du fichier est -, alors l'entrée ou la sortie standard de l'interpréteur sera utilisée.

Si le nom du fichier commence par |, le reste du nom de chaîne est interprété comme une commande à exécuter. L'entrée standard du processus sera connectée à l'entrée standard du processus appelant, et la sortie standard du processus sera connectée à la sortie standard du processus appelant.

Si le nom du fichier commence par | et est suivi d'un autre caractère |, le reste du nom de chaîne est interprété comme une commande à exécuter. L'entrée standard du processus sera connectée à la sortie standard du processus appelant, et la sortie standard du processus sera connectée à l'entrée standard du processus appelant.

Dans le cas des modes w et w+, si le fichier existe déjà, son contenu est tronqué. Si le fichier n'existe pas, il est créé.

Dans le cas des modes a et a+, si le fichier existe déjà, le pointeur de fichier est positionné à la fin du fichier. Si le fichier n'existe pas, il est créé.

Les permissions du fichier sont spécifiées par permissions, qui est un entier de style POSIX, par exemple 0644. Si le fichier est créé, ces permissions sont appliquées. Ces permissions sont ignorées si le fichier existe déjà.

Si fileName est un nom de fichier de périphérique et que le mode est w ou a, les opérations de retour arrière sur le périphérique sont désactivées.

TCL_OPENCOMMANDCHANNEL

Ouvre un canal en exécutant la commande spécifiée par argv. Les arguments de la commande sont spécifiés dans argc et argv. Les arguments de la commande sont les mêmes que ceux utilisés pour la commande exec de Tcl. Les indicateurs flags spécifient la disposition des descripteurs stdio dans le pipeline. TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE sont des combinaisons possibles d'indicateurs.

Si TCL_STDIN est défini, le stdin du premier fils dans le pipe sera le canal du pipe, sinon il sera le même que l'entrée standard du processus appelant. Les mêmes règles s'appliquent à TCL_STDOUT et TCL_STDERR.

Si TCL_ENFORCE_MODE n'est pas défini, alors le pipe peut rediriger les descripteurs stdio pour outrepasser les descripteurs stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, de telles redirections provoquent une erreur.

La valeur de retour est un handle de canal ou le canal NULL si une erreur se produit. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

TCL_MAKEFILECHANNEL

Crée un canal Tcl à partir d'un descripteur de fichier existant (sur Unix) ou d'un handle de système d'exploitation (sur Windows). Le descripteur ou handle est spécifié par handle. Les opérations autorisées sur le canal sont spécifiées par readOrWrite, qui est une combinaison OR de TCL_READABLE et TCL_WRITABLE.

Ce canal devient la propriété de Tcl, et il sera fermé lorsque le canal Tcl sera fermé (par exemple, par la commande close ou Tcl_Close). Le descripteur ou handle sous-jacent ne sera pas fermé automatiquement lorsque le canal Tcl sera fermé, à moins que l'option de canal -reuse ne soit définie sur une valeur fausse.

La valeur de retour est un handle de canal ou le canal NULL si une erreur se produit. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

TCL_GETCHANNEL

Retourne un handle pour le canal nommé channelName. Le canal doit avoir été précédemment enregistré dans l'interpréteur interp. Si modePtr n'est pas NULL, il pointe vers un entier qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et/ou en écriture.

La valeur de retour est un handle de canal ou le canal NULL si une erreur se produit. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

TCL_GETCHANNELNAMES

Retourne une liste de tous les noms de canaux actuellement enregistrés dans l'interpréteur interp sous forme d'une valeur Tcl retournée par la commande set. Le résultat est stocké dans l'élément result de l'interpréteur. La valeur de retour est le nombre d'éléments dans la liste, ou -1 en cas d'erreur.

TCL_GETCHANNELNAMESEX

Retourne une liste de tous les noms de canaux actuellement enregistrés dans l'interpréteur interp qui correspondent au pattern donné, sous forme d'une valeur Tcl retournée par la commande set. Le résultat est stocké dans l'élément result de l'interpréteur. Le pattern est évalué en utilisant Tcl_StringMatch. Si pattern est NULL, tous les noms de canaux sont retournés. La valeur de retour est le nombre d'éléments dans la liste, ou -1 en cas d'erreur.

TCL_REGISTERCHANNEL

Enregistre le channel donné dans l'interpréteur interp. Les canaux doivent être enregistrés avant de pouvoir être accessibles par leur nom. Si un canal portant le même nom est déjà enregistré, ce dernier est désenregistré et le nouveau canal est enregistré.

TCL_UNREGISTERCHANNEL

Désenregistre le channel donné de l'interpréteur interp. Si le canal est toujours ouvert, il n'est pas fermé. Le canal ne peut plus être accédé par son nom.

La valeur de retour est 0 en cas de succès, et -1 en cas d'erreur (par exemple, si le canal n'est pas enregistré dans cet interpréteur).

TCL_DETACHCHANNEL

Détache le channel donné de l'interpréteur interp. Le canal n'est plus géré par Tcl et sa fermeture ultérieure n'affecte pas le canal Tcl. Le canal reste ouvert et peut être utilisé par le système d'exploitation. Le descripteur ou handle sous-jacent n'est pas fermé.

La valeur de retour est 0 en cas de succès, et -1 en cas d'erreur (par exemple, si le canal n'est pas enregistré dans cet interpréteur).

TCL_ISTANDARDCHANNEL

Retourne vrai (1) si le canal donné est l'une des entrées/sorties standard (stdin, stdout, stderr), et faux (0) sinon.

TCL_CLOSE

Ferme le channel donné. Si le canal est toujours ouvert, toutes les données en mémoire tampon sont vidées, les ressources sont libérées et le canal est désenregistré de l'interpréteur. Les appels ultérieurs à Tcl_Read, Tcl_Write, ou autres fonctions liées aux canaux sur ce canal échoueront. La fermeture des canaux du système d'exploitation sous-jacents est gérée par le pilote de canal approprié. Pour les canaux de fichiers, le descripteur de fichier sous-jacent est fermé. Pour les canaux de sockets, la connexion est fermée.

La valeur de retour est 0 en cas de succès, et -1 en cas d'erreur (par exemple, si le canal est déjà fermé).

TCL_READCHARS

Lit jusqu'à charsToRead caractères du channel dans l'objet Tcl pointé par readObjPtr. Si appendFlag est non nul, les caractères lus sont ajoutés à la fin du contenu existant de l'objet. Sinon, le contenu existant de l'objet est effacé avant que les caractères lus ne soient ajoutés. Si le canal n'est pas dans un mode qui supporte les caractères (par exemple, le mode binaire), alors charsToRead spécifie le nombre d'octets à lire.

La valeur de retour est le nombre de caractères (ou d'octets) effectivement lus, ou -1 en cas d'erreur. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

TCL_READ

Lit jusqu'à bytesToRead octets du channel dans le tampon readBuf. Le tampon readBuf doit être assez grand pour contenir bytesToRead octets. Cette fonction est utilisée pour lire des données binaires brutes. Pour lire des données texte, utilisez Tcl_ReadChars.

La valeur de retour est le nombre d'octets effectivement lus, ou -1 en cas d'erreur. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

TCL_GETSOBJ

Lit une ligne du channel et la stocke dans l'objet Tcl pointé par lineObjPtr. Une ligne est définie comme une séquence de caractères se terminant par un caractère de nouvelle ligne (newline). Le caractère de nouvelle ligne n'est pas stocké dans l'objet. Si une fin de fichier est rencontrée avant un caractère de nouvelle ligne, la ligne restante est retournée. Les caractères lus sont ajoutés à la fin du contenu existant de l'objet.

La valeur de retour est le nombre de caractères lus, ou -1 en cas d'erreur. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

TCL_GETS

Lit une ligne du channel et la stocke dans la chaîne dynamique Tcl pointée par lineRead. Une ligne est définie comme une séquence de caractères se terminant par un caractère de nouvelle ligne (newline). Le caractère de nouvelle ligne n'est pas stocké dans la chaîne. Si une fin de fichier est rencontrée avant un caractère de nouvelle ligne, la ligne restante est retournée. Les caractères lus sont ajoutés à la fin des données déjà présentes dans la chaîne dynamique.

La valeur de retour est le nombre de caractères lus, ou -1 en cas d'erreur. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

TCL_UNGETS

Ajoute la chaîne input de longueur inputLen à un tampon pour le canal spécifié. Si addAtEnd est nul, l'entrée est ajoutée au début du tampon ; sinon, elle est ajoutée à la fin. Les données ajoutées seront lues lors des appels futurs à Tcl_Read ou Tcl_Gets.

La valeur de retour est le nombre de caractères ajoutés, ou -1 en cas d'erreur.

TCL_WRITEOBJ

Écrit le contenu de l'objet Tcl pointé par writeObjPtr dans le channel.

La valeur de retour est le nombre d'octets écrits, ou -1 en cas d'erreur. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

TCL_WRITECHARS

Écrit les caractères du tampon charBuf dans le channel. Le nombre d'octets à écrire est spécifié par bytesToWrite. Si le canal n'est pas dans un mode qui supporte les caractères (par exemple, le mode binaire), alors bytesToWrite spécifie le nombre d'octets à écrire.

La valeur de retour est le nombre d'octets effectivement écrits, ou -1 en cas d'erreur. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

TCL_WRITE

Écrit les octets du tampon byteBuf dans le channel. Le nombre d'octets à écrire est spécifié par bytesToWrite. Cette fonction est utilisée pour écrire des données binaires brutes. Pour écrire des données texte, utilisez Tcl_WriteChars.

La valeur de retour est le nombre d'octets effectivement écrits, ou -1 en cas d'erreur. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

TCL_READRAW

Lit jusqu'à bytesToRead octets du channel dans le tampon readBuf. Le tampon readBuf doit être assez grand pour contenir bytesToRead octets. Cette fonction est utilisée pour lire des données binaires brutes sans aucune conversion de fin de ligne ou d'encodage. Pour lire des données texte, utilisez Tcl_ReadChars.

La valeur de retour est le nombre d'octets effectivement lus, ou -1 en cas d'erreur. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

TCL_WRITERAW

Écrit les octets du tampon byteBuf dans le channel. Le nombre d'octets à écrire est spécifié par bytesToWrite. Cette fonction est utilisée pour écrire des données binaires brutes sans aucune conversion de fin de ligne ou d'encodage. Pour écrire des données texte, utilisez Tcl_WriteChars.

La valeur de retour est le nombre d'octets effectivement écrits, ou -1 en cas d'erreur. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

TCL_EOF

Retourne vrai (1) si la fin du fichier a été atteinte pour le channel donné, et faux (0) sinon. La fin du fichier est atteinte lorsque une tentative de lecture ne retourne aucun octet.

TCL_FLUSH

Force l'écriture de toutes les données en mémoire tampon dans le channel. Ceci est utile pour s'assurer que toutes les données écrites sont envoyées au périphérique sous-jacent. L'appel de Tcl_Flush sur un canal de sortie qui a déjà été fermé échoue.

La valeur de retour est 0 en cas de succès, et -1 en cas d'erreur.

TCL_INPUTBLOCKED

Retourne vrai (1) si le channel est actuellement bloqué en attente d'entrée, et faux (0) sinon. Un canal est considéré comme bloqué s'il n'y a pas de données disponibles pour la lecture et que la lecture bloquerait.

TCL_INPUTBUFFERED

Retourne le nombre d'octets de données actuellement en mémoire tampon pour la lecture sur le channel.

TCL_OUTPUTBUFFERED

Retourne le nombre d'octets de données actuellement en mémoire tampon pour l'écriture sur le channel.

TCL_SEEK

Modifie la position de lecture/écriture du channel. L'offset est spécifié par offset et le mode de recherche par seekMode. seekMode peut être SEEK_SET (début du fichier), SEEK_CUR (position actuelle) ou SEEK_END (fin du fichier). Les offsets peuvent être positifs ou négatifs.

La valeur de retour est la nouvelle position de lecture/écriture en octets à partir du début du fichier, ou -1 en cas d'erreur. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

Cette opération n'est valide que pour les canaux qui supportent la recherche (par exemple, les fichiers). Elle échouera pour les canaux qui ne supportent pas la recherche (par exemple, les sockets).

TCL_TELL

Retourne la position de lecture/écriture actuelle du channel en octets à partir du début du fichier.

La valeur de retour est la position actuelle, ou -1 en cas d'erreur. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

Cette opération n'est valide que pour les canaux qui supportent la recherche.

TCL_TRUNCATECHANNEL

Tronque le channel à la longueur spécifiée par length. La longueur doit être non négative. Si la longueur spécifiée est inférieure à la taille actuelle du fichier, les données au-delà de la nouvelle longueur sont perdues.

La valeur de retour est 0 en cas de succès, et -1 en cas d'erreur. Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

Cette opération n'est valide que pour les canaux qui supportent la troncature (par exemple, les fichiers).

TCL_GETCHANNELOPTION

Récupère la valeur de l'option spécifiée par optionName pour le channel donné. La valeur de l'option est stockée dans la chaîne dynamique Tcl pointée par optionValue. optionValue doit avoir été initialisée par l'appelant.

La valeur de retour est 0 en cas de succès, et -1 en cas d'erreur (par exemple, si l'option n'est pas valide pour ce canal). Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

TCL_SETCHANNELOPTION

Définit la valeur de l'option spécifiée par optionName pour le channel donné à newValue. Les options disponibles et leurs valeurs sont les mêmes que celles qui peuvent être définies à l'aide de la commande fconfigure.

La valeur de retour est 0 en cas de succès, et -1 en cas d'erreur (par exemple, si l'option n'est pas valide pour ce canal ou si la valeur fournie est invalide). Si une erreur se produit, un message d'erreur est stocké dans le champ result de l'interpréteur Tcl.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et retourne un descripteur de canal qui peut être utilisé pour effectuer des entrées et sorties sur le fichier. Cette API est inspirée de la procédure fopen de la bibliothèque d'E/S standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur les valeurs Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel chaque fois que possible.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, la création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Elle crée une séquence de sous-processus spécifiés par les arguments argv et argc et retourne un canal qui peut être utilisé pour communiquer avec ces sous-processus. L'argument flags indique le type de communication qui existera avec le pipeline de commandes.

Si l'indicateur TCL_STDIN est défini, l'entrée standard du premier sous-processus sera liée au canal : écrire dans le canal fournira des données au sous-processus. Si TCL_STDIN n'est pas défini, l'entrée standard du premier sous-processus sera la même que l'entrée standard de cette application. Si TCL_STDOUT est défini, la sortie standard du dernier sous-processus peut être lue à partir du canal ; sinon, elle va à la sortie standard de cette application. Si TCL_STDERR est défini, la sortie d'erreur standard de tous les sous-processus est retournée au canal et résulte en une erreur lors de la fermeture du canal ; sinon, elle va à l'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas défini, alors argc et argv peuvent rediriger les descripteurs stdio pour outrepasser TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, alors il est erroné que argc et argv outrepassent les canaux stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, la création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un descripteur de fichier existant et spécifique à la plateforme. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, la création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel retourne un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur Tcl dans interp. Si un canal portant ce nom n'est pas enregistré dans cet interpréteur, la procédure retourne NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms en fonction du pattern. Si pattern est NULL, alors aucun filtrage ne sera effectué. La valeur de retour est TCL_OK si aucune erreur ne s'est produite lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur pourront faire référence au canal dans les opérations d'entrée ou de sortie en utilisant le nom donné lors de l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur Tcl peut appeler Tcl_RegisterChannel avec interp comme NULL, pour indiquer qu'il souhaite conserver une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et ne sera fermé que lorsque le nombre correspondant d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code exécuté en dehors de tout interpréteur de détenir en toute sécurité une référence à un canal qui est également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code gérant les canaux standard. Si aucun canal standard n'a été initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un exposé général sur les canaux standard et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Si cette opération a supprimé la dernière inscription du canal dans un interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur Tcl peut appeler Tcl_UnregisterChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera alors fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel, sauf qu'elle fermera également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Au-delà de cela, cette commande n'a pas d'autre effet. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin), et retournera TCL_ERROR si elle reçoit l'un de ces canaux.

Le code non associé à un interpréteur Tcl peut appeler Tcl_DetachChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. Si c'est le cas, il retourne 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou autrement valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lors de l'appel à Tcl_Close. Les sorties tamponnées sont vidées vers le périphérique de sortie du canal avant la destruction du canal, et toute entrée tamponnée est écartée. S'il s'agit d'un canal bloquant, l'appel ne retourne pas tant que toutes les données tamponnées n'ont pas été envoyées avec succès au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a des sorties tamponnées qui ne peuvent pas être écrites sans bloquer, l'appel retourne immédiatement ; la sortie est vidée en arrière-plan et le canal sera fermé une fois que toutes les données tamponnées auront été sorties. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close retourne TCL_OK. Si une erreur se produit, Tcl_Close retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré à l'aide de Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a déjà été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez plutôt utiliser Tcl_UnregisterChannel, qui appellera Tcl_Close en interne lorsque tous les appels à Tcl_RegisterChannel auront été mis en correspondance par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, convertit les octets en UTF-8 en se basant sur le codage du canal et stocke les données produites dans la représentation chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

La définition de char

TCL_READCHARS, TCL_READOBJ, -1 ETCL_READ, ETCL_READRAW

La valeur Tcl_ReadChars à -1 provoquera la lecture par la commande de tous les caractères actuellement disponibles (mode non bloquant) ou de tout jusqu'à l'EOF (mode bloquant).

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé étaient disponibles. C'est ce qu'on appelle une lecture courte. En mode bloquant, cela ne peut se produire qu'à la fin du fichier. En mode non bloquant, une lecture courte peut également se produire s'il n'y a pas assez d'entrée actuellement disponible : Tcl_ReadChars retourne un décompte court plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour savoir laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les diverses représentations de fin de ligne en la représentation interne canonique \n selon le mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les divers modes spécifiques à la plateforme sont décrits dans l'entrée du manuel de la commande Tcl fconfigure.

En tant qu'optimisation des performances, lors de la lecture à partir d'un canal avec le codage binary, les octets ne sont pas convertis en UTF-8 lors de leur lecture. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr sous forme de valeur de tableau d'octets. La représentation sous forme de chaîne de cette valeur ne sera construite que si elle est nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette manière, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et des fonctions associées, puis écrites dans un canal sans avoir à supporter le coût de conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'elle n'effectue pas de conversions de codage, quel que soit le codage du canal. Elle est obsolète et existe pour des raisons de compatibilité ascendante avec les extensions Tcl non internationalisées. Elle consomme des octets du channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par un caractère nul. Son contenu est valide à partir de la position zéro jusqu'à, mais sans inclure, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas l'empilement. Alors que Tcl_Read (et les autres fonctions de l'API) obtient toujours ses données du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_ReadRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données du canal inférieur vers la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, en convertissant les octets en UTF-8 en fonction du codage du canal, jusqu'à ce qu'une ligne d'entrée complète soit vue. Si le codage du canal est binary, chaque octet lu à partir du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception des caractères de fin de ligne terminaux, sont ajoutés à la représentation sous forme de chaîne de lineObjPtr. Les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_GetsObj retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj retourne également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est retourné, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité de l'entrée.

Tcl_Gets est identique à Tcl_GetsObj, sauf que les caractères résultants sont ajoutés à la chaîne dynamique donnée par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, à la tête ou à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si channel a un EOF « collant » défini, aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets retourne inputLen ou -1 si une erreur se produit.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données de caractères à charBuf. Les caractères UTF-8 dans le tampon sont convertis dans le codage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par un caractère nul et il sort tout jusqu'au caractère nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal sur none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un décompte du nombre d'octets acceptés pour la sortie vers le canal. Il s'agit soit d'un nombre supérieur à zéro pour indiquer le succès, soit de -1 pour indiquer qu'une erreur s'est produite. Si une erreur se produit, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme selon l'option -translation pour le canal. Ceci est fait même si le canal n'a pas de codage.

Tcl_WriteObj est similaire à Tcl_WriteChars, sauf qu'il accepte une valeur Tcl dont le contenu sera sorti vers le canal. Les caractères UTF-8 de la représentation sous forme de chaîne de writeObjPtr sont convertis dans le codage du canal et mis en file d'attente pour la sortie vers channel. En tant qu'optimisation des performances, lors de l'écriture dans un canal avec le codage binary, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets de la représentation interne de writeObjPtr en tant que valeur de tableau d'octets sont écrits dans le canal. La représentation de tableau d'octets de la valeur sera construite si elle est nécessaire. De cette manière, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et des fonctions associées, puis écrites dans un canal sans avoir à supporter le coût de conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars, sauf qu'elle n'effectue pas de conversions de codage, quel que soit le codage du canal. Elle est obsolète et existe pour des raisons de compatibilité ascendante avec les extensions Tcl non internationalisées. Elle accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par un caractère nul et il sort tout jusqu'au caractère nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée dans le canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation vers le canal inférieur.

TCL_FLUSH

Tcl_Flush provoque l'écriture de toutes les données de sortie mises en mémoire tampon pour channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données mises en mémoire tampon n'ont pas été envoyées au canal ou qu'une erreur ne s'est pas produite. L'appel retourne immédiatement si le canal n'est pas bloquant ; il démarre une opération de vidage en arrière-plan qui écrira les données mises en mémoire tampon dans le canal éventuellement, aussi rapidement que le canal sera capable de les absorber.

La valeur de retour est normalement TCL_OK. Si une erreur se produit, Tcl_Flush retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données ultérieures seront lues ou écrites. La sortie mise en mémoire tampon est vidée vers le canal et l'entrée mise en mémoire tampon est supprimée, avant l'opération de recherche. Un décalage de 0, SEEK_CUR, SEEK_DATA, SEEK_END, SEEK_HOLE, ou SEEK_SET peut être utilisé comme origine.

Tcl_Seek retourne normalement le nouveau point d'accès. Si une erreur se produit, Tcl_Seek retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut ou peut ne pas avoir été déplacé.

TCL_TELL

Tcl_Tell retourne le point d'accès actuel pour un canal. La valeur retournée est -1 si le canal ne prend pas en charge la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent channel à une longueur donnée de length octets. Il retourne TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur de l'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, c'est le nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et leurs valeurs dans optionValue.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption lit la valeur de l'option optionName sur channel. La valeur est retournée sous forme de chaîne Tcl dans valuePtr. La procédure renvoie normalement TCL_OK. Si une erreur se produit, elle renvoie TCL_ERROR et laisse un message d'erreur dans le résultat de l'interpréteur. Les options préexistantes et leurs valeurs possibles sont décrites dans la page man de la commande Tcl fconfigure. D'autres options peuvent être ajoutées par chaque type de canal. Ces options spécifiques au type de canal sont décrites dans la page man de la commande Tcl qui crée un canal de ce type ; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans la page man de la commande Tcl socket.

Les valeurs des options sont retournées sous forme de chaînes Tcl. Si une option est booléenne (comme -blocking ou -buffering), la valeur retournée est "1" pour vrai et "0" pour faux. Si une option est une énumération, la valeur retournée est la chaîne qui représente la valeur actuelle. La procédure peut utiliser des appels séquentiels à Tcl_DStringAppendElement.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit une nouvelle valeur newValue pour une option optionName sur channel. La procédure renvoie normalement TCL_OK. Si une erreur se produit, elle renvoie TCL_ERROR ; de plus, si interp n'est pas NULL, Tcl_SetChannelOption laisse un message d'erreur dans le résultat de l'interpréteur.

TCL_EOF

Tcl_Eof renvoie une valeur non nulle si le channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked renvoie une valeur non nulle si le channel est en mode non bloquant et que la dernière opération d'entrée a retourné moins de données que demandé car il n'y avait pas assez de données disponibles. L'appel renvoie toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered renvoie le nombre d'octets d'entrée actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en lecture, cette fonction renvoie toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered renvoie le nombre d'octets de sortie actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en écriture, cette fonction renvoie toujours zéro.

PROBLÈMES DE PLATEFORME

Les descripteurs renvoyés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que renvoyé par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel ou Tcl_MakeFileChannel. D'autres types de canaux peuvent renvoyer un type de descripteur différent sur les plateformes Windows.
