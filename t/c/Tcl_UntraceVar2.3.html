Tcl_UntraceVar2(3) Procédures de la bibliothèque Tcl Tcl_UntraceVar2(3)

NOM

Tcl_UntraceVar2, Tcl_UntraceVar2, Tcl_VarTraceInfo, Tcl_VarTraceInfo2 - surveille les accès à une variable

SYNOPIS

#include <tcl.h>

int
Tcl_UntraceVar2(interp, name1, name2, flags, proc, clientData)

ClientData
Tcl_VarTraceInfo2(interp, name1, name2, flags, proc, prevClientData)

ClientData
Tcl_VarTraceInfo(interp, varName, flags, proc, prevClientData)

ClientData
Tcl_UntraceVar2(interp, name1, name2, flags, proc, clientData)

ClientData
Tcl_UntraceVar(interp, varName, flags, proc, clientData)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur contenant la variable.
const char *varName (entrée)
Nom de la variable. Peut référencer une variable scalaire, une variable de tableau sans indice, ou une variable de tableau avec un indice entre parenthèses.
int flags (entrée)
OU logique des valeurs TCL_GLOBAL_ONLY, TCL_NAMESPACE_ONLY, TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS, TCL_TRACE_ARRAY, TCL_TRACE_RESULT_DYNAMIC et TCL_TRACE_RESULT_OBJECT. Tous les indicateurs ne sont pas utilisés dans toutes les procédures. Voir ci-dessous pour plus d'informations.
Tcl_VarTraceProc *proc (entrée)
Procédure à appeler lorsqu'une des opérations tracées est effectuée.
ClientData clientData (entrée)
Valeur arbitraire d'un mot à passer à proc.
const char *name1 (entrée)
Nom d'une variable scalaire ou de tableau (sans indice de tableau).
const char *name2 (entrée)
Pour un trace sur un élément de tableau, donne l'indice de l'élément. Pour les traces sur des variables scalaires ou des tableaux entiers, c'est NULL.
ClientData prevClientData (entrée)
S'il n'est pas NULL, donne la valeur la plus récente renvoyée par Tcl_VarTraceInfo ou Tcl_VarTraceInfo2, donc cet appel renverra des informations sur le prochain trace. S'il est NULL, cet appel renverra des informations sur le premier trace.

DESCRIPTION

Tcl_UntraceVar2 permet à une procédure C de surveiller et de contrôler l'accès à une variable Tcl, de telle sorte que la procédure C est appelée lorsqu'elle est lue, écrite ou désactivée. Si le trace est créé avec succès, Tcl_UntraceVar2 renvoie TCL_OK. Si une erreur se produit (par exemple, varName spécifie un élément de tableau, mais la variable réelle n'est pas un tableau), TCL_ERROR est renvoyé et un message d'erreur est laissé dans le résultat de l'interpréteur.

L'argument flags de Tcl_UntraceVar2 indique quand la procédure de trace est appelée et fournit des informations pour configurer le trace. Il est constitué d'une combinaison OU de l'un des éléments suivants:

TCL_GLOBAL_ONLY
Normalement, la variable est recherchée au niveau de l'appel de procédure actuel ; si ce bit est défini, la variable est recherchée au niveau global, ignorant toute procédure active.
TCL_NAMESPACE_ONLY
Normalement, la variable est recherchée au niveau de l'appel de procédure actuel ; si ce bit est défini, la variable est recherchée dans l'espace de noms actuel, ignorant toute procédure active.
TCL_TRACE_READS
proc est appelé lorsqu'on tente de lire la variable.
TCL_TRACE_WRITES
proc est appelé lorsqu'on tente de modifier la variable.
TCL_TRACE_UNSETS
proc est appelé lorsqu'une variable est désactivée. Une variable peut être désactivée explicitement par une commande unset, ou implicitement lorsqu'une procédure renvoie (ses variables locales sont désactivées), ou lorsque l'interpréteur est détruit (toutes les variables sont désactivées).
TCL_TRACE_ARRAY
proc est appelé lorsqu'une commande de tableau est exécutée. Cela donne à la procédure de trace l'opportunité de mettre à jour le tableau avant que les noms de tableau ou les get de tableau ne soient appelés. Il doit être appelé avant un set de tableau, mais cela déclenchera des traces d'écriture.
TCL_TRACE_RESULT_DYNAMIC
Le résultat de l'appel de proc est une chaîne allouée dynamiquement qui sera libérée par un appel à ckfree de la bibliothèque Tcl. Vous ne pouvez pas spécifier TCL_TRACE_RESULT_OBJECT simultanément.
TCL_TRACE_RESULT_OBJECT
Le résultat de l'appel de proc est un Tcl_Obj* (casté en char*) avec un compteur de références d'au moins un. Le contrôle de référence de cet objet est passé au noyau Tcl pour libération (lorsque le noyau aura terminé avec lui) par un appel à Tcl_DecrRefCount. Vous ne pouvez pas spécifier TCL_TRACE_RESULT_DYNAMIC simultanément.

Lorsque l'une des opérations spécifiées se produit sur la variable, proc est appelé. Il doit avoir des arguments et un résultat qui correspondent au type Tcl_VarTraceProc :

typedef char *Tcl_VarTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *name1,
        const char *name2,
        int flags);

Les paramètres clientData et interp auront les mêmes valeurs qui ont été passées lors de la création du trace. clientData pointe typiquement vers une structure de données spécifique à l'application qui décrit quoi faire lorsque proc est appelé. name1 et name2 donnent le nom de la variable tracée dans la forme normale à deux parties (voir la description de Tcl_TraceVar2 pour plus de détails). flags est une combinaison OU de bits qui fournissent divers éléments d'information. Un des bits TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_ARRAY ou TCL_TRACE_UNSETS sera défini dans flags pour indiquer quelle opération est effectuée sur la variable. Le bit TCL_GLOBAL_ONLY sera défini lorsque la variable accédée est globale et n'est pas accessible depuis le niveau d'appel de procédure actuel : la procédure de trace devra passer cet indicateur aux procédures liées aux variables comme Tcl_GetVar si elle tente d'accéder à la variable. Le bit TCL_NAMESPACE_ONLY sera défini lorsque la variable accédée est un espace de noms et n'est pas accessible depuis le niveau d'appel de procédure actuel : la procédure de trace devra passer cet indicateur aux procédures liées aux variables comme Tcl_GetVar si elle tente d'accéder à la variable. Le bit TCL_TRACE_DESTROYED sera défini dans flags si le trace est sur le point d'être détruit ; ces informations peuvent être utiles à proc afin qu'il puisse nettoyer ses structures internes (voir la section TCL_TRACE_DESTROYED pour plus de détails). Enfin, le bit TCL_INTERP_DESTROYED sera défini si l'environnement d'interpréteur entier est en cours de destruction. Lorsque ce bit est défini, proc doit être particulièrement prudent quant à ce qu'il fait (voir la section TCL_INTERP_DESTROYED). La valeur renvoyée par la procédure de trace doit normalement être NULL ; voir ERREURS RENVOYÉES pour plus d'informations sur d'autres erreurs potentielles.

Tcl_UntraceVar peut être utilisé pour supprimer un trace. Si la variable spécifiée par interp, varName, et flags a un trace avec flags, proc, et clientData, alors le trace correspondant est supprimé. S'il n'existe pas de tel trace, l'appel à Tcl_UntraceVar n'a aucun effet. Les mêmes bits sont valides pour flags que pour les appels à Tcl_TraceVar.

Tcl_VarTraceInfo peut être utilisé pour récupérer des informations sur les traces définis pour une variable donnée. La valeur renvoyée par Tcl_VarTraceInfo est le clientData associé à un trace spécifique. Le trace doit être associé à la variable spécifiée par les arguments interp, varName, et flags (seuls les bits TCL_GLOBAL_ONLY et TCL_NAMESPACE_ONLY de flags sont utilisés ; les autres bits sont ignorés) et sa procédure de trace doit être identique à l'argument proc. Si l'argument prevClientData est NULL, la valeur renvoyée correspond au premier (le plus récent) trace correspondant, ou NULL s'il n'y a pas de correspondance.

NOMENCLATURE

Les procédures Tcl_TraceVar, Tcl_UntraceVar et Tcl_VarTraceInfo permettent de créer, de supprimer et d'interroger des « traces » sur les variables Tcl. Une trace est un mécanisme par lequel une procédure Tcl (appelée proc) est automatiquement appelée chaque fois qu'une variable est lue, écrite, ou mise à jour d'une autre manière. Le paramètre clientData est un pointeur opaque utilisé par le programmeur pour identifier la trace ; il est passé à proc chaque fois qu'elle est appelée. L'argument flags est un masque de bits qui spécifie le type de traces à établir. Il peut s'agir d'une combinaison des éléments suivants : TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS, et TCL_TRACE_ARRAYS. Si TCL_TRACE_ARRAYS est spécifié, alors la procédure est appelée pour toute opération sur la variable entière, que ce soit une lecture, une écriture ou une suppression. Si une combinaison d'indicateurs est spécifiée, la procédure est appelée pour toutes les opérations spécifiées.

La procédure Tcl_VarTraceInfo est utilisée pour obtenir des informations sur les traces existantes. Si le paramètre prevClientData est NULL, alors la procédure renvoie des informations sur la première trace correspondant aux flags spécifiés. Sinon, prevClientData doit être la valeur de retour d'un appel précédent à Tcl_VarTraceInfo. Dans ce cas, la nouvelle valeur de retour correspondra à la trace correspondante suivante après celle dont le clientData correspond à prevClientData, ou NULL s'il n'y a plus de traces correspondantes. Ce mécanisme permet de parcourir toutes les traces d'une variable donnée qui ont le même proc.

DEUX PARTIES NOMS

Les procédures Tcl_TraceVar2, Tcl_UntraceVar2 et Tcl_VarTraceInfo2 sont identiques à Tcl_TraceVar, Tcl_UntraceVar et Tcl_VarTraceInfo, respectivement, à la différence près que le nom de la variable est constitué de deux parties. Name1 donne le nom d'une variable scalaire ou d'un tableau, et name2 donne le nom d'un élément dans un tableau. Lorsque name2 est NULL, name1 peut contenir à la fois un nom de tableau et un nom d'élément : si le nom contient une parenthèse ouvrante et se termine par une parenthèse fermante, alors la valeur entre les parenthèses est traitée comme un nom d'élément (qui peut avoir n'importe quelle valeur de chaîne) et les caractères avant la première parenthèse ouvrante sont traités comme le nom d'une variable de tableau. Si name2 est NULL et que name1 ne fait pas référence à un élément de tableau, cela signifie que la variable est soit scalaire, soit que la trace doit être définie sur l'ensemble du tableau plutôt que sur un élément individuel (voir TRACES DE TABLEAU ENTIER ci-dessous pour plus d'informations).

ACCÈS AUX VARIABLES PENDANT LES TRACES

Pendant les traces de lecture, d'écriture et de tableau, la procédure de trace peut lire, écrire ou désinstaller la variable tracée en utilisant Tcl_GetVar2, Tcl_SetVar2 et d'autres procédures. Pendant que proc est en cours d'exécution, les traces sont temporairement désactivées pour la variable, de sorte que les appels à Tcl_GetVar2 et Tcl_SetVar2 ne provoquent pas la réinvocation de proc ou d'autres procédures de trace. La désactivation ne se produit que pour la variable dont la procédure de trace est active ; les accès aux autres variables seront toujours tracés. Cependant, si une variable est désinstallée pendant une trace de lecture ou d'écriture, les traces de désinstallation seront invoquées.

Pendant les traces de désinstallation, la variable a déjà été complètement supprimée. Il est possible pour la procédure de trace de lire ou d'écrire la variable, mais ce sera une nouvelle version de la variable. Les traces ne sont pas désactivées pendant les traces de désinstallation comme elles le sont pour les traces de lecture et d'écriture, mais les traces existantes ont été supprimées de la variable avant que toute procédure de trace ne soit invoquée. Si de nouvelles traces sont définies par les procédures de trace de désinstallation, ces traces seront invoquées lors des accès à la variable par les procédures de trace.

CALENDRIER DES RAPPELS

Lorsque le traçage de lecture a été spécifié pour une variable, la procédure de trace sera appelée chaque fois que la valeur de la variable est lue. Cela inclut les commandes Tcl set, la notation $ dans les commandes Tcl, et les invocations des procédures Tcl_GetVar et Tcl_GetVar2. Proc est appelée juste avant que la valeur de la variable ne soit retournée. Elle peut modifier la valeur de la variable pour affecter ce qui est retourné par l'accès tracé. Si elle désinstalle la variable, l'accès retournera une erreur comme si la variable n'avait jamais existé.

Lorsque le traçage d'écriture a été spécifié pour une variable, la procédure de trace sera appelée chaque fois que la valeur de la variable est modifiée. Cela inclut les commandes set, les commandes qui modifient les variables comme effets secondaires (telles que catch et scan), et les appels aux procédures Tcl_SetVar et Tcl_SetVar2). Proc sera appelée après que la valeur de la variable ait été modifiée, mais avant que la nouvelle valeur de la variable n'ait été retournée. Elle peut modifier la valeur de la variable pour remplacer le changement et déterminer la valeur réellement retournée par l'accès tracé. Si elle supprime la variable, l'accès tracé retournera une chaîne vide.

Lorsque le traçage de tableau a été spécifié, la procédure de trace sera appelée au début de l'implémentation de la commande de tableau, avant que les opérations telles que get, set ou names n'aient été invoquées. La procédure de trace peut modifier les éléments du tableau avec Tcl_SetVar et Tcl_SetVar2.

Lorsque le traçage de désinstallation a été spécifié, la procédure de trace sera appelée chaque fois que la variable est détruite. Les traces seront appelées après que la variable ait été complètement désinstallée.

TRACES DE TABLEAU ENTIER

Si un appel à Tcl_TraceVar ou Tcl_TraceVar2 spécifie le nom d'une variable de tableau sans index dans le tableau, alors la trace sera définie sur le tableau dans son ensemble. Cela signifie que proc sera appelée chaque fois qu'un élément du tableau est accédé de la manière spécifiée par flags. Lorsqu'un tableau est désinstallé, une trace de tableau entier sera appelée une seule fois, avec name1 égal au nom du tableau et name2 NULL ; elle ne sera pas appelée une fois pour chaque élément.

TRACES MULTIPLES

Il est possible que plusieurs traces existent sur la même variable. Lorsque cela se produit, toutes les procédures de trace seront appelées à chaque accès, dans l'ordre le plus récemment créé au moins récemment créé. Lorsqu'il existe des traces de tableau entier pour un tableau ainsi que des traces sur des éléments individuels, les traces de tableau entier sont appelées avant les traces d'éléments individuels. Si une trace de lecture ou d'écriture désinstalle la variable, alors toutes les traces de désinstallation seront appelées mais le reste des traces de lecture et d'écriture seront ignorées.

RETOURS D'ERREUR

Dans des conditions normales, les procédures de trace doivent retourner NULL, indiquant un achèvement réussi. Si proc retourne une valeur non-NULL, cela signifie qu'une erreur s'est produite. La valeur de retour doit être un pointeur vers une chaîne de caractères statique contenant un message d'erreur, sauf si (exactement un des) indicateurs TCL_TRACE_RESULT_DYNAMIC et TCL_TRACE_RESULT_OBJECT est défini, qui spécifient que le résultat est soit une chaîne dynamique (à libérer avec ckfree) soit un Tcl_Obj* (casté en char* et à libérer avec Tcl_DecrRefCount) contenant le message d'erreur. Si une procédure de trace retourne une erreur, aucune autre trace n'est appelée pour l'accès et l'accès tracé est annulé avec le message donné. Les procédures de trace peuvent utiliser cette fonctionnalité pour rendre les variables en lecture seule, par exemple (mais notez que la valeur de la variable aura déjà été modifiée avant que la procédure de trace ne soit appelée, donc la procédure de trace devra restaurer la valeur correcte).

La valeur de retour de proc n'est utilisée que pendant le traçage de lecture et d'écriture. Pendant les traces de désinstallation, la valeur de retour est ignorée et toutes les procédures de trace pertinentes seront toujours appelées.

RESTRICTIONS

Une procédure de trace peut être appelée à tout moment, même lorsqu'il existe des résultats partiellement formés stockés dans l'interpréteur. Si la procédure de trace fait quoi que ce soit qui pourrait endommager ce résultat (tel qu'appeler Tcl_Eval), alors elle doit utiliser les routines Tcl_SaveInterpState et associées pour enregistrer et restaurer l'état d'origine de l'interpréteur avant de retourner.

VARIABLES NON DÉFINIES

Il est légal de définir une trace sur une variable non définie. La variable apparaîtra toujours comme non définie jusqu'à la première fois que sa valeur est définie. Si une variable non définie est tracée puis désinstallée, la désinstallation échouera avec une erreur (« aucune variable de ce type »), mais la procédure de trace sera quand même appelée.

INDICATEUR TCL_TRACE_DESTROYED

Dans un rappel de désinstallation à proc, le bit TCL_TRACE_DESTROYED est défini dans flags si la trace est en cours de suppression dans le cadre de la suppression. Les traces d'une variable sont toujours supprimées chaque fois que la variable est supprimée ; la seule fois où TCL_TRACE_DESTROYED n'est pas défini est pour une trace de tableau entier appelée lorsque seul un seul élément d'un tableau est désinstallé.

TCL_INTERP_DESTROYED

Lorsqu'un interpréteur est détruit, les traces de désinstallation sont appelées pour toutes ses variables. Le bit TCL_INTERP_DESTROYED sera défini dans l'argument flags passé aux procédures de trace. Les procédures de trace doivent être extrêmement prudentes dans ce qu'elles font si le bit TCL_INTERP_DESTROYED est défini. Il n'est pas sûr que les procédures invoquent des procédures Tcl sur l'interpréteur, car son état est partiellement supprimé. Tout ce que les procédures de trace devraient faire dans ces circonstances est de nettoyer et de libérer leurs propres structures de données internes.

BOGUES

Tcl n'effectue aucune vérification d'erreurs pour empêcher les procédures de trace d'utiliser incorrectement l'interpréteur pendant les traces avec TCL_INTERP_DESTROYED défini.

Les traces de tableau ne sont pas encore intégrées à la commande Tcl info exists, et il n'y a pas d'accès au niveau Tcl aux traces de tableau.
