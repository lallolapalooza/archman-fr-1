ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur à utiliser pour le rapport d'erreurs, ou NULL si aucun rapport d'erreurs n'est souhaité.
const char *name (in)
Nom de l'encodage à charger.
Tcl_Encoding encoding (in)
L'encodage à interroger, libérer ou utiliser pour convertir du texte. Si encoding est NULL, l'encodage système actuel est utilisé.
Tcl_Obj *objPtr (in)
Nom de l'encodage pour lequel obtenir le jeton.
Tcl_Encoding *encodingPtr (out)
Pointe vers le stockage où le jeton d'encodage doit être écrit.
const char *src (in)
Pour les fonctions Tcl_ExternalToUtf, un tableau d'octets dans l'encodage spécifié qui doit être converti en UTF-8. Pour les fonctions Tcl_UtfToExternal et Tcl_WinUtfToTChar, un tableau de caractères UTF-8 à convertir vers l'encodage spécifié.
const TCHAR *tsrc (in)
Un tableau de caractères Windows TCHAR à convertir en UTF-8.
int srcLen (in)
Longueur de src ou tsrc en octets. Si la longueur est négative, la longueur spécifique à l'encodage de la chaîne est utilisée.
Tcl_DString *dstPtr (out)
Pointeur vers une Tcl_DString non initialisée ou libérée dans laquelle le résultat converti sera stocké.
int flags (in)
Divers bits de drapeaux mis en OR. TCL_ENCODING_START signifie que le tampon source est le premier bloc d'un flux d'entrée (potentiellement multi-blocs), indiquant à la routine de conversion de revenir à un état initial et d'effectuer toute initialisation nécessaire avant la conversion du premier octet. TCL_ENCODING_END signifie que le tampon source est le dernier bloc d'un flux d'entrée (potentiellement multi-blocs), indiquant à la routine de conversion d'effectuer toute finalisation nécessaire après la conversion du dernier octet, puis de revenir à un état initial. TCL_ENCODING_STOPONERROR signifie que la routine de conversion doit retourner immédiatement lors de la lecture d'un caractère source qui n'existe pas dans l'encodage cible ; sinon, un caractère de repli par défaut sera automatiquement substitué.
Tcl_EncodingState *statePtr (in/out)
Utilisé lors de la conversion d'un flux d'octets (généralement long ou de longueur indéfinie) pièce par pièce. La routine de conversion stocke son état actuel dans *statePtr après que src (le tampon contenant la pièce actuelle) a été converti ; ces informations d'état doivent être renvoyées lors de la conversion de la pièce suivante du flux afin que la routine de conversion sache dans quel état elle était lorsqu'elle s'est arrêtée à la fin de la pièce précédente. Peut être NULL, auquel cas la valeur spécifiée pour flags est ignorée et le tampon source est supposé contenir la chaîne complète à convertir.
char *dst (out)
Tampon dans lequel le résultat converti sera stocké. Pas plus de dstLen octets seront stockés dans dst.
int dstLen (in)
La longueur maximale du tampon de sortie dst en octets.
int *srcReadPtr (out)
Rempli avec le nombre d'octets de src qui ont été effectivement convertis. Cela peut être inférieur à la longueur source d'origine s'il y a eu un problème lors de la conversion de certains caractères source. Peut être NULL.
int *dstWrotePtr (out)
Rempli avec le nombre d'octets qui ont été effectivement stockés dans le tampon de sortie à la suite de la conversion. Peut être NULL.
int *dstCharsPtr (out)
Rempli avec le nombre de caractères qui correspondent au nombre d'octets stockés dans le tampon de sortie. Peut être NULL.
Tcl_DString *bufPtr (out)
Stockage pour le nom d'encodage système prescrit.
const Tcl_EncodingType *typePtr (in)
Structure qui définit un nouveau type d'encodage.
Tcl_Obj *searchPath (in)
Liste de répertoires de système de fichiers dans lesquels rechercher les fichiers de données d'encodage.
const char *path (in)
Un chemin vers l'emplacement du fichier d'encodage.

INTRODUCTION

Ces routines convertissent entre la représentation de caractères interne de Tcl, UTF-8, et les représentations de caractères utilisées par divers systèmes d'exploitation ou systèmes de fichiers, tels que Unicode, ASCII ou Shift-JIS. Lors de l'opération sur des chaînes, comme l'obtention des noms de fichiers ou l'affichage de caractères à l'aide de polices internationales, les chaînes doivent être traduites dans un ou plusieurs formats que les divers appels système peuvent utiliser. Par exemple, sur un poste de travail Unix japonais, un utilisateur pourrait obtenir un nom de fichier représenté dans l'encodage de fichier EUC-JP, puis traduire les caractères vers l'encodage de police jisx0208 afin d'afficher le nom de fichier dans un widget Tk. Le but du paquet d'encodage est d'aider à combler le fossé de traduction. UTF-8 fournit un terrain d'étape intermédiaire pour tous les différents encodages. Dans l'exemple ci-dessus, le texte serait traduit en UTF-8 depuis l'encodage de fichier quelconque que le système d'exploitation utilise. Ensuite, il serait traduit d'UTF-8 vers l'encodage de police requis par les routines d'affichage.

Certains encodages de base sont intégrés à Tcl. D'autres peuvent être définis par l'utilisateur ou chargés dynamiquement à partir de fichiers d'encodage d'une manière indépendante de la plateforme.

DESCRIPTION

Tcl_GetEncoding trouve un encodage à partir de son name. Le nom peut faire référence à un encodage Tcl intégré, à un encodage défini par l'utilisateur enregistré en appelant Tcl_CreateEncoding, ou à un fichier d'encodage chargeable dynamiquement. La valeur de retour est un jeton qui représente l'encodage et peut être utilisé dans des appels ultérieurs à des procédures telles que Tcl_GetEncodingName, Tcl_FreeEncoding et Tcl_UtfToExternal. Si le nom ne fait référence à aucun encodage connu ou chargeable, NULL est retourné et un message d'erreur est renvoyé dans interp.

Le paquet d'encodage maintient une base de données de tous les encodages actuellement en cours d'utilisation. La première fois que name est rencontré, Tcl_GetEncoding renvoie un encodage avec un compteur de références de 1. Si le même name est demandé plusieurs fois, le compteur de références pour cet encodage est incrémenté sans le surcoût d'allocation d'un nouvel encodage et de toutes ses structures de données associées.

Lorsqu'un encoding n'est plus nécessaire, Tcl_FreeEncoding doit être appelé pour le libérer. Lorsqu'un encoding n'est plus utilisé nulle part (c'est-à-dire qu'il a été libéré autant de fois qu'il a été obtenu), Tcl_FreeEncoding libérera tout le stockage utilisé par l'encodage et le supprimera de la base de données.

Tcl_GetEncodingFromObj traite la représentation textuelle de objPtr comme un nom d'encodage, et trouve un encodage portant ce nom, tout comme le fait Tcl_GetEncoding. Lorsqu'un encodage est trouvé, il est mis en cache dans la valeur de objPtr pour référence future, le jeton Tcl_Encoding est écrit dans le stockage

Tcl_ExternalToUtfDString convertit un buffer source src de l'encodage spécifié encoding en UTF-8. Les octets convertis sont stockés dans dstPtr, qui est ensuite terminé par un caractère nul approprié. L'appelant doit finalement appeler Tcl_DStringFree pour libérer toute information stockée dans dstPtr. Lors de la conversion, si un caractère dans le buffer source ne peut pas être représenté dans l'encodage cible, un caractère de remplacement par défaut sera utilisé. La valeur retournée est un pointeur vers la valeur stockée dans le DString.

Tcl_ExternalToUtf convertit un buffer source src de l'encodage spécifié encoding en UTF-8. Un maximum de srcLen octets est converti à partir du buffer source et un maximum de dstLen octets est stocké dans dst. Dans tous les cas, *srcReadPtr est rempli avec le nombre d'octets qui ont été convertis à partir de src et *dstWrotePtr est rempli avec le nombre correspondant d'octets qui ont été stockés dans dst. La valeur retournée est l'une des suivantes :

TCL_OK
Tous les octets de src ont été convertis.
TCL_CONVERT_NOSPACE
Le buffer de destination n'était pas assez grand pour toutes les données converties ; autant de caractères ont été convertis que possible.
TCL_CONVERT_MULTIBYTE
Les derniers octets du buffer source constituaient le début d'une séquence multi-octets, mais des octets supplémentaires étaient nécessaires pour compléter cette séquence. Un appel ultérieur à la fonction de conversion doit passer un buffer contenant les octets non convertis toujours présents dans src plus quelques octets supplémentaires du flux d'entrée afin de convertir correctement la séquence multi-octets qui avait été divisée.
TCL_CONVERT_SYNTAX
Le buffer source contenait une séquence de caractères invalide. Cela peut se produire si le flux d'entrée a été corrompu ou si la méthode d'encodage d'entrée a été mal identifiée.
TCL_CONVERT_UNKNOWN
Le buffer source contenait un caractère qui ne pouvait pas être représenté dans l'encodage cible et TCL_ENCODING_STOPONERROR a été spécifié.

Tcl_UtfToExternalDString convertit un buffer source src d'UTF-8 en l'encodage spécifié encoding. Les octets convertis sont stockés dans dstPtr, qui est ensuite terminé par un caractère nul approprié. L'appelant doit finalement appeler Tcl_DStringFree pour libérer toute information stockée dans dstPtr. Lors de la conversion, si un caractère dans le buffer source ne peut pas être représenté dans l'encodage cible, un caractère de remplacement par défaut sera utilisé. La valeur retournée est un pointeur vers la valeur stockée dans le DString.

Tcl_UtfToExternal convertit un buffer source src d'UTF-8 en l'encodage spécifié encoding. Un maximum de srcLen octets est converti à partir du buffer source et un maximum de dstLen octets est stocké dans dst. Dans tous les cas, *srcReadPtr est rempli avec le nombre d'octets qui ont été convertis à partir de src et *dstWrotePtr est rempli avec le nombre correspondant d'octets qui ont été stockés dans dst. Les valeurs retournées sont les mêmes que celles de Tcl_ExternalToUtf.

Tcl_WinUtfToTChar et Tcl_WinTCharToUtf sont des fonctions pratiques pour convertir entre UTF-8 et les chaînes Windows basées sur le type TCHAR, qui est en pratique une chaîne Unicode sous Windows NT.

Tcl_GetEncodingName est à peu près l'inverse de Tcl_GetEncoding. Étant donné un encoding, la valeur retournée est l'argument name qui a été utilisé pour créer l'encodage. La chaîne retournée par Tcl_GetEncodingName n'est garantie de persister que jusqu'à ce que l'encoding soit supprimé. L'appelant ne doit pas modifier cette chaîne.

Tcl_SetSystemEncoding définit l'encodage par défaut qui doit être utilisé lorsque l'utilisateur passe une valeur nulle pour l'argument encoding à toute fonction d'encodage. Si name est nul, l'encodage système est réinitialisé à l'encodage par défaut du système, binary. Si le nom ne fait référence à aucun encodage connu ou chargeable, TCL_ERROR est retourné et un message d'erreur est laissé dans interp. Sinon, cette procédure incrémente le compteur de références du nouvel encodage système, décrémente le compteur de références de l'ancien encodage système et retourne TCL_OK.

Tcl_GetEncodingNameFromEnvironment fournit un moyen à la bibliothèque Tcl de signaler le nom de l'encodage qu'elle suppose être approprié comme encodage système, basé sur des appels à des fonctions système et l'examen de l'environnement approprié à la plateforme. Il reçoit bufPtr, un pointeur vers un Tcl_DString initialisé ou libéré, et y écrit le nom de l'encodage. La valeur retournée est le Tcl_DStringValue.

Tcl_GetEncodingNames définit la valeur de interp à une liste contenant les noms de tous les encodages définis ou dynamiquement chargeables, en recherchant dans le répertoire d'encodages spécifié par Tcl_SetDefaultEncodingDir. Cette procédure ne garantit pas que les fichiers chargeables dynamiquement contiennent des données valides, mais assure seulement qu'ils existent.

Tcl_CreateEncoding définit un nouvel encodage et enregistre les fonctions de conversion qui sont appelées lors de la conversion entre cet encodage et l'UTF-8. Les encodages créés par Tcl_CreateEncoding sont ensuite visibles dans la base de données utilisée par Tcl_GetEncoding. Tout comme avec Tcl_GetEncoding, la valeur retournée est un jeton représentant l'encodage et peut être utilisé dans des appels ultérieurs à d'autres fonctions d'encodage. Tcl_CreateEncoding retourne un encodage avec un compteur de références de 1. Si un encodage avec le nom spécifié name existe déjà, son entrée dans la base de données est remplacée par le nouvel encodage ; le jeton de l'ancien encodage reste valide et continue de se comporter comme avant, mais les utilisateurs du nouveau jeton appelleront désormais les fonctions du nouvel encodage.

L'argument typePtr de Tcl_CreateEncoding contient des informations sur le nom de l'encodage et les fonctions de conversion qui seront appelées lors de la conversion entre cet encodage et l'UTF-8. Il est défini comme suit :

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

Le encodingName fournit un nom pour l'encodage, par lequel il peut être référencé dans d'autres fonctions comme Tcl_GetEncoding. Le toUtfProc fait référence à une fonction de rappel pour convertir du texte de cet encodage vers l'UTF-8. Le fromUtfProc fait référence à une fonction de rappel pour convertir du texte de l'UTF-8 vers cet encodage. Le freeProc fait référence à une fonction de rappel à invoquer lorsque cet encodage est supprimé. Le champ freeProc peut être nul. Le clientData contient une valeur d'un mot arbitraire passée à toUtfProc, fromUtfProc et freeProc lorsqu'ils sont invoqués. Généralement, il s'agit d'un pointeur vers une structure de données contenant des informations spécifiques à l'encodage, qui peuvent être utilisées par les fonctions de rappel. Par exemple, deux encodages très similaires comme ascii et macRoman peuvent utiliser la même fonction de rappel, mais utilisent des valeurs clientData différentes pour contrôler leur comportement. Le nullSize spécifie le nombre de zéros qui signalent la fin de chaîne dans cet encodage. Il doit être de 1 (pour les encodages à un octet ou multi-octets comme ASCII ou Shift-JIS) ou 2 (pour les encodages à deux octets comme Unicode). Les encodages constants avec 3 octets ou plus par caractère (comme CNS11643) ne sont pas acceptés.

Les fonctions de rappel toUtfProc et fromUtfProc doivent correspondre au type Tcl_EncodingConvertProc :

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

Les fonctions toUtfProc et fromUtfProc sont appelées par les fonctions de la famille Tcl_ExternalToUtf ou Tcl_UtfToExternal pour effectuer la conversion réelle. Le paramètre clientData de ces fonctions est le même que le champ clientData spécifié lors de la création de l'encodage avec Tcl_CreateEncoding. Les arguments restants des fonctions de rappel sont les mêmes que les arguments, documentés au début, de Tcl_ExternalToUtf ou Tcl_UtfToExternal, à l'exception suivante. Si l'argument srcLen de l'une de ces fonctions de haut niveau est négatif, la valeur passée à la fonction de rappel sera la longueur appropriée de src pour l'encodage spécifié. Si l'un des arguments srcReadPtr, dstWrotePtr ou dstCharsPtr de l'une de ces fonctions de haut niveau est NULL, la valeur correspondante passée à la fonction de rappel sera un emplacement non-NULL.

La fonction de rappel freeProc, si elle n'est pas nulle, doit correspondre au type Tcl_EncodingFreeProc :

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

Cette fonction freeProc est appelée lorsque l'encodage est supprimé. Le paramètre clientData est le même que le champ clientData spécifié lors de la création de l'encodage avec Tcl_CreateEncoding.

Tcl_GetEncodingSearchPath et Tcl_SetEncodingSearchPath sont appelés pour accéder et configurer la liste des répertoires des fichiers de données d'encodage. La valeur retournée par Tcl_GetEncodingSearchPath est la valeur stockée par le dernier appel réussi à Tcl_SetEncodingSearchPath. S'il n'y a pas eu d'appels à Tcl_SetEncodingSearchPath, Tcl calculera une valeur initiale basée sur l'environnement. Il existe un chemin de recherche d'encodages pour l'ensemble du processus, partagé par tous les threads du processus.
