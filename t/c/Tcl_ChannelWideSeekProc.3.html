ARGUMENTS

Pointe vers une structure contenant les pointeurs vers les fonctions qui peuvent être appelées pour effectuer des opérations d'E/S et d'autres processus sur le canal.

Le nom de ce canal, comme file3 ; il ne doit pas être utilisé par aucun autre canal. Peut être NULL, dans ce cas le canal est créé sans nom. Si le canal créé est assigné à l'un des canaux standard (stdin, stdout ou stderr), le nom du canal assigné sera le nom du canal standard.

Valeur arbitraire d'un seul octet associée à ce canal. Cette valeur est passée aux fonctions dans typePtr lorsqu'elles sont appelées.

TCL_READABLE signifie que vous voulez le handle d'entrée ; TCL_WRITABLE signifie que vous voulez le handle de sortie.

int size (in)
La taille, en octets, des tampons à allouer sur ce canal.

OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION qui indique les événements qui se sont produits sur ce canal.

const char *optionName (in)

Liste des options spécifiées (mots séparés par des espaces, sans -) à ajouter à la liste des options standard. Peut être NULL uniquement pour les messages d'erreur d'options standard.

DESCRIPTION

Tcl utilise une architecture de canaux à deux couches. Elle fournit une couche supérieure générique pour permettre aux programmes C et Tcl d'effectuer des entrées et des sorties en utilisant les mêmes API pour une variété de fichiers, périphériques, sockets, etc. Les API C génériques sont décrites dans la page de manuel d'entrée Tcl_OpenFileChannel.

La couche inférieure fournit des pilotes de canal spécifiques à chaque type de périphérique supporté sur chaque plateforme. Ce manuel décrit les API C qui communiquent entre la couche générique et les pilotes de canal spécifiques. Il explique également comment de nouveaux types de canaux peuvent être ajoutés en fournissant de nouveaux pilotes de canal.

Les pilotes de canal se composent de plusieurs composants : Premièrement, chaque pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers les fonctions qui implémentent les différentes opérations utilisées par la couche générique pour communiquer avec le pilote de canal. La structure Tcl_ChannelType et les fonctions auxquelles elle fait référence sont décrites dans la section TCL_CHANNELTYPE, ci-dessous.

Deuxièmement, les pilotes de canal fournissent généralement une commande Tcl pour créer des instances de ce type de canal. Par exemple, la commande Tcl open crée des canaux qui utilisent les pilotes et commandes de fichiers, et la commande Tcl socket crée des canaux qui utilisent les protocoles de socket TCP pour la communication réseau.

Troisièmement, un pilote de canal fournit éventuellement une fonction C pour ouvrir des instances de ce type de canal. Par exemple, Tcl_OpenFileChannel ouvre un canal qui utilise le pilote de canal de fichier, et Tcl_OpenTcpClient ouvre un canal qui utilise le protocole réseau TCP. Ces fonctions de création appellent généralement Tcl_CreateChannel en interne pour ouvrir le canal.

Pour ajouter un nouveau type de canal, vous devez implémenter une API C ou une commande Tcl qui ouvre un canal en appelant Tcl_CreateChannel. Lorsque votre pilote appelle Tcl_CreateChannel, il passe une structure Tcl_ChannelType qui décrit les procédures d'E/S de votre pilote. La couche générique invoquera ensuite les fonctions référencées dans cette structure pour effectuer des opérations sur le canal.

Tcl_CreateChannel ouvre un nouveau canal et y associe typePtr et instanceData. Le canal est ouvert dans le mode indiqué par mask. Pour une discussion sur les pilotes de canal, leurs opérations et la structure Tcl_ChannelType, voir la section TCL_CHANNELTYPE, ci-dessous.

Tcl_CreateChannel interagit avec le code qui gère les canaux standard. Une fois qu'un canal standard a été initialisé par un appel à Tcl_GetStdChannel ou un appel à Tcl_SetStdChannel, la fermeture de ce canal entraînera sa conversion en nouveau canal standard lors du prochain appel à Tcl_CreateChannel. Voir Tcl_StandardChannels pour une discussion générale sur les canaux standard et le comportement de la bibliothèque Tcl à leur égard.

Tcl_GetChannelInstanceData renvoie les données d'instanciation associées au canal dans channel. Il s'agit de la même valeur que l'argument instanceData dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelType renvoie un pointeur vers la structure Tcl_ChannelType utilisée par le canal dans l'argument channel. Il s'agit de la même valeur que l'argument typePtr dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelName renvoie une chaîne contenant le nom associé au canal, ou NULL si l'argument channelName de Tcl_CreateChannel était NULL.

Tcl_GetChannelHandle place le handle du périphérique du système d'exploitation associé à channel pour la direction donnée dans handlePtr.

FONCTIONS DE CANAL

Ces fonctions sont utilisées par les pilotes de canal pour interagir avec la couche générique de Tcl.

Tcl_GetChannelHandle renvoie un pointeur vers la poignée de périphérique spécifiée par handlePtr et retourne TCL_OK. Si le canal n'a pas de poignée de périphérique pour la direction spécifiée, alors TCL_ERROR est retourné à la place. Différents pilotes de canal renverront différents types de poignées. Référez-vous aux entrées du manuel pour chaque pilote afin de déterminer quel type de poignée est retourné.

Tcl_GetChannelThread renvoie l'identifiant du thread gérant actuellement le channel spécifié. Cela permet aux pilotes de canal d'envoyer leurs événements de fichier à la file d'attente d'événements correcte, même pour un noyau multi-thread.

Tcl_GetChannelMode renvoie une combinaison OR de TCL_READABLE et TCL_WRITABLE, indiquant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelBufferSize renvoie la taille, en octets, des tampons alloués pour stocker les entrées ou sorties dans le channel. Si la valeur n'a pas été définie par un appel précédent à Tcl_SetChannelBufferSize, décrit ci-dessous, alors la valeur par défaut de 4096 est retournée.

Tcl_SetChannelBufferSize définit la taille, en octets, des tampons qui seront alloués lors des opérations ultérieures sur le canal pour stocker les entrées ou sorties. L'argument size doit être compris entre un et un million, permettant des tampons de un octet à un million d'octets. Si size est en dehors de cette plage, Tcl_SetChannelBufferSize définit la taille du tampon à 4096.

Tcl_NotifyChannel est appelé par un pilote de canal pour indiquer à la couche générique que les événements spécifiés par mask se sont produits sur le canal. Les pilotes de canal sont responsables de l'invocation de cette fonction chaque fois que les gestionnaires de canal doivent être appelés pour le canal (ou d'autres tâches en attente, comme un vidage d'écriture, doivent être effectuées). Voir WATCHPROC ci-dessous pour plus de détails.

Tcl_BadChannelOption est appelé à partir du setOptionProc ou getOptionProc spécifique au pilote pour générer un message d'erreur complet.

Tcl_ChannelBuffered renvoie le nombre d'octets d'entrée actuellement mis en tampon dans le tampon interne (zone de retour en arrière) du canal lui-même. Il ne rapporte pas les données dans les tampons globaux pour la pile de canaux dont fait partie le canal fourni.

Tcl_IsChannelShared vérifie le compteur de références du channel spécifié et renvoie si le channel a été partagé entre plusieurs interpréteurs (résultat == 1) ou non (résultat == 0).

Tcl_IsChannelRegistered vérifie si le channel spécifié est enregistré dans l'interpréteur interp donné (résultat == 1) ou non (résultat == 0).

Tcl_IsChannelExisting vérifie si un canal portant le nom spécifié est enregistré dans la liste globale (du thread) de tous les canaux (résultat == 1) ou non (résultat == 0).

Tcl_CutChannel supprime le channel spécifié de la liste globale (du thread) de tous les canaux (du thread courant). L'application à un canal toujours enregistré dans un interpréteur n'est pas autorisée. Notifie également le pilote si la version de Tcl_ChannelType est TCL_CHANNEL_VERSION_4 (ou supérieure) et si Tcl_DriverThreadActionProc est définie pour celui-ci.

Tcl_SpliceChannel ajoute le channel spécifié à la liste globale (du thread) de tous les canaux (du thread courant). L'application à un canal enregistré dans un interpréteur n'est pas autorisée. Notifie également le pilote si la version de Tcl_ChannelType est TCL_CHANNEL_VERSION_4 (ou supérieure) et si Tcl_DriverThreadActionProc est définie pour celui-ci.

Tcl_ClearChannelHandlers supprime tous les gestionnaires de canal et les scripts d'événements associés au channel spécifié, arrêtant ainsi tout traitement d'événements pour ce canal.

TCL_CHANNELTYPE

Un pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers des fonctions implémentant les différentes opérations sur un canal ; ces opérations sont appelées au besoin par la couche générique. La structure a été versionnée à partir de Tcl 8.3.2/8.4 pour corriger un problème avec les pilotes de canal empilés. Voir la section OLD CHANNEL TYPES ci-dessous pour les détails sur l'ancienne structure.

La structure Tcl_ChannelType contient les champs suivants :

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Il n'est pas nécessaire de fournir des implémentations pour toutes les opérations de canal. Celles qui ne sont pas nécessaires peuvent être mises à NULL dans la structure : blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc, et close2Proc, en plus de flushProc, handlerProc, threadActionProc, et truncateProc. D'autres fonctions qui ne peuvent pas être implémentées de manière significative devraient retourner EINVAL lorsqu'elles sont appelées, pour indiquer que les opérations qu'elles représentent ne sont pas disponibles. Notez également que wideSeekProc peut être NULL si seekProc l'est.

L'utilisateur ne doit utiliser que la structure ci-dessus pour l'instanciation de Tcl_ChannelType. Lors de la référence aux champs d'une structure Tcl_ChannelType, les fonctions suivantes doivent être utilisées pour obtenir les valeurs : Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc, ou Tcl_ChannelHandlerProc.

La modification des structures a été effectuée de manière à ce que les types de canaux standard soient binaires compatibles. Cependant, les types de canaux qui utilisent des canaux empilés (c'est-à-dire TLS, Trf) ont de nouvelles versions pour correspondre au changement ci-dessus, car le code précédent pour les canaux empilés présentait des problèmes.

TYPENAME

Le champ typeName contient une chaîne terminée par null qui identifie le type du périphérique implémenté par ce pilote, par exemple file ou socket.

Cette valeur peut être récupérée avec Tcl_ChannelName, qui renvoie un pointeur vers la chaîne.

VERSION

Le champ version doit être défini sur la version de la structure dont vous avez besoin. TCL_CHANNEL_VERSION_2 est le minimum recommandé. TCL_CHANNEL_VERSION_3 doit être défini pour spécifier le membre wideSeekProc. TCL_CHANNEL_VERSION_4 doit être défini pour spécifier le membre threadActionProc (inclut wideSeekProc). TCL_CHANNEL_VERSION_5 doit être défini pour spécifier les membres truncateProc (inclut wideSeekProc et threadActionProc). S'il n'est défini sur aucun de ceux-ci, alors ce Tcl_ChannelType est supposé avoir la structure d'origine. Voir OLD CHANNEL TYPES pour plus de détails. Bien que Tcl reconnaisse et fonctionne avec les deux structures, les canaux empilés doivent être au moins de version TCL_CHANNEL_VERSION_2 pour fonctionner correctement.

Cette valeur peut être récupérée avec Tcl_ChannelVersion, qui renvoie l'une des valeurs suivantes : TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 ou TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

Le champ blockModeProc contient l'adresse d'une fonction appelée par la couche générique pour définir le mode bloquant et non bloquant sur le périphérique. BlockModeProc doit correspondre au prototype suivant :

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

Le instanceData est le même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. L'argument mode est soit TCL_MODE_BLOCKING, soit TCL_MODE_NONBLOCKING pour mettre le périphérique en mode bloquant ou non bloquant. La fonction doit renvoyer zéro si l'opération a réussi, ou un code d'erreur POSIX non nul si l'opération a échoué.

Si l'opération réussit, la fonction peut modifier le instanceData fourni pour enregistrer que le canal est entré en mode bloquant ou non bloquant et pour implémenter le comportement bloquant ou non bloquant. Pour certains types de périphériques, le comportement bloquant et non bloquant peut être implémenté par le système d'exploitation sous-jacent ; pour d'autres types de périphériques, le comportement doit être émulé dans le pilote de canal.

Cette valeur peut être récupérée avec Tcl_ChannelBlockModeProc, qui renvoie un pointeur vers la fonction.

Un pilote de canal qui **ne fournit pas** de blockModeProc doit être très, très prudent. Il doit indiquer à la couche générique quel mode bloquant lui convient, et doit également documenter cela pour l'utilisateur afin que le mode bloquant du canal ne soit pas changé en une valeur inacceptable. Toute confusion ici peut entraîner l'interpréteur dans un interblocage (factice et difficile à trouver).

CLOSEPROC ET CLOSE2PROC

Le champ closeProc contient l'adresse d'une fonction appelée par la couche générique pour nettoyer les informations relatives au pilote lors de la fermeture du canal. CloseProc doit correspondre au prototype suivant :

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

L'argument instanceData est le même que la valeur fournie à Tcl_CreateChannel lors de la création du canal. La fonction doit libérer toute mémoire maintenue par le pilote de canal pour ce canal, et fermer les périphériques d'entrée et de sortie encapsulés par ce canal. Toute sortie mise en file d'attente aura été vidée vers le périphérique avant que cette fonction ne soit appelée, et aucune autre opération de pilote ne sera invoquée sur cette instance après l'appel du closeProc. Si l'opération de fermeture réussit, la procédure

re doit retourner zéro ; sinon, il doit retourner un code d'erreur POSIX non nul. De plus, si une erreur se produit et que interp n'est pas NULL, la procédure doit stocker un message d'erreur dans le résultat de l'interpréteur.

Alternativement, les canaux qui supportent la fermeture indépendante des côtés lecture et écriture peuvent définir closeProc à TCL_CLOSE2PROC et définir close2Proc à l'adresse d'une fonction correspondant au prototype suivant :

typedef int Tcl_DriverClose2Proc(
        ClientData instanceData,
        Tcl_Interp *interp,
        int flags);

Le close2Proc sera appelé avec flags défini à une combinaison OR de TCL_CLOSE_READ ou TCL_CLOSE_WRITE pour indiquer que le pilote doit fermer le côté lecture et/ou écriture du canal. Le pilote de canal peut être appelé pour effectuer des opérations supplémentaires sur le canal après que close2Proc ait été appelé pour fermer un ou deux côtés du canal. Si flags est 0 (zéro), le pilote doit fermer le canal de la manière décrite ci-dessus pour closeProc. Aucune autre opération ne sera invoquée sur cette instance après l'appel de close2Proc avec tous les indicateurs effacés. Dans tous les cas, la fonction close2Proc doit retourner zéro si l'opération de fermeture a réussi ; sinon, elle doit retourner un code d'erreur POSIX non nul. De plus, si une erreur se produit et que interp n'est pas NULL, la procédure doit stocker un message d'erreur dans le résultat de l'interpréteur.

Les valeurs closeProc et close2Proc peuvent être récupérées avec Tcl_ChannelCloseProc ou Tcl_ChannelClose2Proc, qui retournent un pointeur vers la fonction respective.

INPUTPROC

Le champ inputProc contient l'adresse d'une fonction appelée par la couche générique pour lire des données depuis le fichier ou le périphérique et les stocker dans un tampon interne. InputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création du canal. L'argument buf pointe vers un tableau d'octets dans lequel stocker les entrées du périphérique, et l'argument bufSize indique le nombre d'octets disponibles dans buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique. Si une erreur se produit, la fonction doit définir la variable à un code d'erreur POSIX qui identifie l'erreur survenue.

La fonction doit lire les données du périphérique d'entrée encapsulé par le canal et les stocker dans buf. En cas de succès, la fonction doit retourner un entier non négatif indiquant le nombre d'octets lus depuis le périphérique d'entrée et stockés dans buf. En cas d'erreur, la fonction doit retourner -1. Si une erreur se produit après que des données aient été lues depuis le périphérique, ces données sont perdues.

Si inputProc peut déterminer que le périphérique d'entrée a des données disponibles, mais moins que ce qui est demandé par l'argument bufSize, la fonction ne doit tenter de lire que la quantité de données disponible et retourner sans bloquer. Si le périphérique d'entrée n'a aucune donnée disponible et que le canal est en mode non bloquant, la fonction doit retourner une erreur EAGAIN. Si le périphérique d'entrée n'a aucune donnée disponible et que le canal est en mode bloquant, la fonction doit bloquer le moins de temps possible jusqu'à ce qu'au moins un octet de données puisse être lu depuis le périphérique ; ensuite, elle doit retourner autant de données qu'elle peut lire sans bloquer.

Cette valeur peut être récupérée avec Tcl_ChannelInputProc, qui retourne un pointeur vers la fonction.

OUTPUTPROC

Le champ outputProc contient l'adresse d'une fonction appelée par la couche générique pour transférer des données d'un tampon interne vers le périphérique de sortie. OutputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création du canal. L'argument buf contient un tableau d'octets à écrire sur le périphérique, et l'argument toWrite indique le nombre d'octets à écrire depuis l'argument buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique. Si une erreur se produit, la fonction doit définir cette variable à un code d'erreur POSIX qui identifie l'erreur.

La fonction doit écrire les données de buf sur le périphérique de sortie encapsulé par le canal. En cas de succès, la fonction doit retourner un entier non négatif indiquant le nombre d'octets écrits sur le périphérique de sortie. La valeur de retour est normalement la même que toWrite, mais peut être inférieure dans certains cas, par exemple si l'opération de sortie est interrompue par un signal. En cas d'erreur, la fonction doit retourner -1. En cas d'erreur, certaines données peuvent avoir été écrites sur le périphérique.

Si le canal est non bloquant et que le périphérique de sortie ne peut absorber aucune donnée, la fonction doit retourner -1 avec une erreur EAGAIN sans écrire de données.

Cette valeur peut être récupérée avec Tcl_ChannelOutputProc, qui retourne un pointeur vers la fonction.

SEEKPROC ET WIDESEEKPROC

Le champ seekProc contient l'adresse d'une fonction appelée par la couche générique pour déplacer le point d'accès auquel les opérations d'entrée ou de sortie subséquentes seront appliquées. SeekProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

L'argument instanceData est la même valeur que celle donnée à Tcl_CreateChannel lors de la création de ce canal. Offset et seekMode ont la même signification que pour la procédure Tcl_Seek (décrite dans l'entrée de manuel de Tcl_OpenFileChannel).

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique pour retourner les valeurs errno de la fonction. La fonction doit définir cette variable à un code d'erreur POSIX si une erreur se produit. La fonction doit stocker un code d'erreur EINVAL si le type de canal n'implémente pas la recherche.

La valeur de retour est le nouveau point d'accès ou -1 en cas d'erreur. Si une erreur s'est produite, la fonction ne doit pas déplacer le point d'accès.

S'il existe un champ seekProc non NULL, le champ wideSeekProc peut contenir l'adresse d'une fonction alternative à utiliser qui gère les décalages larges (c'est-à-dire supérieurs à 32 bits), permettant ainsi les recherches dans des fichiers de plus de 2 Go. Le wideSeekProc sera appelé de préférence au seekProc, mais les deux doivent être définis si le wideSeekProc est défini. WideSeekProc doit correspondre au prototype suivant :

typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

Les arguments et les valeurs de retour ont la même signification qu'avec seekProc ci-dessus, à l'exception du type des décalages et du type de retour qui sont différents.

La valeur seekProc peut être récupérée avec Tcl_ChannelSeekProc, qui retourne un pointeur vers la fonction, et de même, le wideSeekProc peut être récupéré avec Tcl_ChannelWideSeekProc.

SETOPTIONPROC

Le champ setOptionProc contient l'adresse d'une fonction appelée par la couche générique pour définir une option spécifique au type de canal sur un canal. setOptionProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

optionName est le nom d'une option à définir, et newValue est la nouvelle valeur de cette option, sous forme de chaîne. instanceData est la même valeur que celle donnée à Tcl_CreateChannel lors de la création de ce canal. La fonction doit effectuer toute action spécifique au type de canal nécessaire pour implémenter la nouvelle valeur de l'option.

Certaines options sont gérées par le code générique et cette fonction n'est jamais appelée pour les définir, par exemple -blockmode. D'autres options sont spécifiques à chaque type de canal et la procédure setOptionProc du pilote de canal sera appelée pour les implémenter. Le champ setOptionProc peut être NULL, ce qui indique que ce type de canal ne prend en charge aucune option spécifique au type.

Si la valeur de l'option est modifiée avec succès vers la nouvelle valeur, la fonction retourne TCL_OK. Elle doit appeler Tcl_BadChannelOption qui retourne elle-même TCL_ERROR si le optionName n'est pas reconnu. Si newValue spécifie une valeur pour l'option qui n'est pas prise en charge ou si une erreur d'appel système se produit, la fonction doit laisser un message d'erreur dans le résultat de interp si interp n'est pas NULL. La fonction doit également appeler Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

Cette valeur peut être récupérée avec Tcl_ChannelSetOptionProc, qui retourne un pointeur vers la fonction.

Le champ getOptionProc contient l'adresse d'une fonction appelée par la couche générique pour obtenir la valeur d'une option spécifique au type de canal sur un canal. getOptionProc doit correspondre au prototype suivant :

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        Tcl_DString *optionValue);

OptionName est le nom d'une option prise en charge par ce type de canal. Si le nom de l'option n'est pas NULL, la fonction stocke sa valeur actuelle, sous forme de chaîne, dans la chaîne dynamique Tcl optionValue. Si optionName est NULL, la fonction stocke dans optionValue une liste alternée de toutes les options prises en charge et de leurs valeurs actuelles. En cas de succès, la fonction retourne TCL_OK. TCL_CHANNELTYPE

La structure Tcl_ChannelType contient des informations sur un type de canal particulier. Elle est utilisée par le code générique des canaux pour implémenter des opérations sur les canaux. Le code générique appelle les procédures de cette structure pour effectuer des opérations spécifiques au type de canal. Ces procédures sont souvent appelées pour des opérations de bas niveau qui ne peuvent pas être implémentées par du code générique.

La structure Tcl_ChannelType est définie comme suit :

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverThreadActionProc *threadActionProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Les champs de la structure sont les suivants :

TYPENAME

Le champ typeName contient le nom du type de canal. Ce nom est utilisé pour enregistrer le type de canal avec Tcl_RegisterChannel et pour faire référence au type de canal dans les commandes Tcl.

CLOSEPROC

Le champ closeProc contient l'adresse d'une procédure appelée par la couche générique lorsque le canal est fermé. Elle doit correspondre au prototype suivant :

typedef int Tcl_DriverCloseProc(
        ClientData instanceData);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. La procédure doit effectuer les actions de nettoyage nécessaires pour le canal, libérer les ressources allouées et retourner 0 en cas de succès, ou un code d'erreur approprié (par exemple, un code errno) en cas d'échec.

Cette valeur peut être récupérée avec Tcl_ChannelCloseProc, qui renvoie un pointeur vers la procédure.

INPUTPROC

Le champ inputProc contient l'adresse d'une procédure appelée par la couche générique pour lire des données du canal. Elle doit correspondre au prototype suivant :

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buffer,
        int space);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. Les arguments buffer et space spécifient la mémoire tampon dans laquelle les données lues doivent être placées et l'espace disponible dans ce tampon, respectivement. La procédure doit lire les données du canal et les placer dans buffer. Elle doit retourner le nombre d'octets effectivement lus. Si aucune donnée n'est disponible pour la lecture, elle doit retourner 0. Si une erreur se produit lors de la lecture, elle doit retourner -1 et définir le code d'erreur approprié à l'aide de Tcl_SetErrno.

Cette valeur peut être récupérée avec Tcl_ChannelInputProc, qui renvoie un pointeur vers la procédure.

OUTPUTPROC

Le champ outputProc contient l'adresse d'une procédure appelée par la couche générique pour écrire des données dans le canal. Elle doit correspondre au prototype suivant :

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buffer,
        int space);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. Les arguments buffer et space spécifient la mémoire tampon contenant les données à écrire et le nombre d'octets à écrire, respectivement. La procédure doit écrire les données du canal à partir de buffer. Elle doit retourner le nombre d'octets effectivement écrits. Si une erreur se produit lors de l'écriture, elle doit retourner -1 et définir le code d'erreur approprié à l'aide de Tcl_SetErrno.

Cette valeur peut être récupérée avec Tcl_ChannelOutputProc, qui renvoie un pointeur vers la procédure.

SEEKPROC

Le champ seekProc contient l'adresse d'une procédure appelée par la couche générique pour repositionner la position de lecture/écriture dans le canal. Elle doit correspondre au prototype suivant :

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. L'argument offset spécifie le déplacement par rapport au point de référence, et seekMode spécifie le point de référence (par exemple, SEEK_SET, SEEK_CUR, SEEK_END). La procédure doit repositionner la position de lecture/écriture et retourner la nouvelle position absolue à partir du début du fichier. Si une erreur se produit, elle doit retourner -1.

Cette valeur peut être récupérée avec Tcl_ChannelSeekProc, qui renvoie un pointeur vers la procédure.

SETOPTIONPROC

Le champ setOptionProc contient l'adresse d'une procédure appelée par la couche générique pour définir une option spécifique au canal. Elle doit correspondre au prototype suivant :

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        const char *optionName,
        const Tcl_Obj *optionValue,
        Tcl_Interp *interp);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. OptionName est le nom de l'option à définir, et optionValue est la valeur de l'option sous forme d'un objet Tcl. L'argument interp est l'interpréteur dans lequel la commande a été invoquée ; il peut être utilisé pour générer des messages d'erreur. La procédure doit tenter de définir l'option spécifiée. Si l'option est reconnue et définie avec succès, elle doit retourner TCL_OK. Si l'option n'est pas reconnue ou si une erreur se produit lors de la définition de l'option, elle doit générer un message d'erreur dans interp et retourner TCL_ERROR.

Cette valeur peut être récupérée avec Tcl_ChannelSetOptionProc, qui renvoie un pointeur vers la procédure.

GETOPTIONPROC

Le champ getOptionProc contient l'adresse d'une procédure appelée par la couche générique pour obtenir la valeur d'une option spécifique au canal. Elle doit correspondre au prototype suivant :

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        const char *optionName,
        Tcl_Interp *interp);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. OptionName est le nom de l'option dont on veut obtenir la valeur. L'argument interp est l'interpréteur dans lequel la commande a été invoquée ; il peut être utilisé pour définir le résultat de la commande. La procédure doit tenter de récupérer la valeur de l'option spécifiée. Si l'option est reconnue, elle doit définir le résultat de l'interpréteur avec la valeur de l'option (sous forme d'un objet Tcl) et retourner TCL_OK. Si l'option n'est pas reconnue, elle doit générer un message d'erreur dans interp si interp n'est pas NULL et retourner TCL_ERROR. Si une erreur système se produit, la fonction doit laisser un message d'erreur dans le résultat de interp si interp n'est pas NULL. La fonction doit également appeler Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

Certaines options sont gérées par le code générique et cette procédure n'est jamais appelée pour récupérer leur valeur, par exemple -blockmode. D'autres options sont spécifiques à chaque type de canal et la procédure getOptionProc du pilote de canal sera appelée pour les implémenter. Le champ getOptionProc peut être NULL, ce qui indique que ce type de canal ne prend en charge aucune option spécifique au type.

Cette valeur peut être récupérée avec Tcl_ChannelGetOptionProc, qui renvoie un pointeur vers la procédure.

WATCHPROC

Le champ watchProc contient l'adresse d'une procédure appelée par la couche générique pour initialiser le mécanisme de notification d'événements afin de détecter les événements d'intérêt sur ce canal. WatchProc doit correspondre au prototype suivant :

typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. L'argument mask est une combinaison OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION ; il indique les événements dont l'appelant souhaite être notifié sur ce canal.

La procédure doit initialiser les mécanismes spécifiques au type de périphérique pour détecter quand un événement d'intérêt se produit sur le canal. Lorsqu'un ou plusieurs des événements désignés se produisent sur le canal, le pilote de canal est responsable de l'appel de Tcl_NotifyChannel pour informer le module générique de canal. Le pilote doit veiller à ne pas affamer d'autres pilotes de canal ou sources de rappels en invoquant Tcl_NotifyChannel trop fréquemment. L'équité peut être assurée en utilisant la file d'attente d'événements Tcl pour permettre à l'événement de canal d'être planifié en séquence avec d'autres événements. Voir la description de Tcl_QueueEvent pour plus de détails sur la mise en file d'attente d'un événement.

Cette valeur peut être récupérée avec Tcl_ChannelWatchProc, qui renvoie un pointeur vers la procédure.

GETHANDLEPROC

Le champ getHandleProc contient l'adresse d'une procédure appelée par la couche générique pour récupérer un handle spécifique au périphérique du canal. GetHandleProc doit correspondre au prototype suivant :

typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. L'argument direction est soit TCL_READABLE pour récupérer le handle utilisé pour l'entrée, soit TCL_WRITABLE pour récupérer le handle utilisé pour la sortie.

Si l'implémentation du canal a des handles spécifiques au périphérique, la procédure doit récupérer le handle approprié associé au canal, conformément à l'argument direction. Le handle doit être stocké à l'emplacement référencé par handlePtr, et TCL_OK doit être retourné. Si le canal n'est pas ouvert pour la direction spécifiée, ou si l'implémentation du canal n'utilise pas de handles de périphérique, la procédure doit retourner TCL_ERROR.

Cette valeur peut être récupérée avec Tcl_ChannelGetHandleProc, qui renvoie un pointeur vers la procédure.

FLUSHPROC

Le champ flushProc est actuellement réservé pour une utilisation future. Il doit être défini à NULL. FlushProc doit correspondre au prototype suivant :

typedef int Tcl_DriverFlushProc(
        ClientData instanceData);

Cette valeur peut être récupérée avec Tcl_ChannelFlushProc, qui renvoie un pointeur vers la procédure.

HANDLERPROC

Le champ handlerProc contient l'adresse d'une procédure appelée par la couche générique pour notifier le canal qu'un événement s'est produit. Il doit être défini pour les pilotes de canal empilés qui souhaitent être notifiés des événements qui se produisent sur le canal sous-jacent (empilé). HandlerProc doit correspondre au prototype suivant :

typedef int Tcl_DriverHandlerProc(
        ClientData instanceData,
        int interestMask);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. Le interestMask est une combinaison OR de TCL_READABLE ou TCL_WRITABLE ; il indique quel type d'événement s'est produit sur ce canal.

Cette valeur peut être récupérée avec Tcl_ChannelHandlerProc, qui renvoie un pointeur vers la procédure.

THREADACTIONPROC

Le champ threadActionProc contient l'adresse de la procédure appelée par la couche générique lorsqu'un canal est créé, fermé, ou est sur le point de passer à un autre thread, c'est-à-dire chaque fois que l'état du pilote spécifique au thread pourrait devoir être initialisé ou mis à jour. Il peut être NULL. L'action TCL_CHANNEL_THREAD_REMOVE est utilisée pour notifier le pilote qu'il doit mettre à jour ou supprimer toute donnée spécifique au thread qu'il pourrait maintenir pour le canal.

L'action TCL_CHANNEL_THREAD_INSERT est utilisée pour notifier le pilote qu'il doit mettre à jour ou initialiser toute donnée spécifique au thread qu'il pourrait maintenir en utilisant le thread appelant comme associé. Voir Tcl_CutChannel et Tcl_SpliceChannel pour plus de détails.

typedef void Tcl_DriverThreadActionProc(
        ClientData instanceData,
        int action);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal.

Ces valeurs peuvent être récupérées avec Tcl_ChannelThreadActionProc, qui renvoie un pointeur vers la procédure.

TRUNCATEPROC

Le champ truncateProc contient l'adresse de la procédure appelée par la couche générique lorsqu'un canal est tronqué à une certaine longueur. Il peut être NULL.

typedef int Tcl_DriverTruncateProc(
        ClientData instanceData,
        Tcl_WideInt length);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal, et length est la nouvelle longueur du fichier sous-jacent, qui ne doit pas être négative. Le résultat doit être 0 en cas de succès ou un code errno (adapté à une utilisation avec Tcl_SetErrno) en cas d'échec.

Ces valeurs peuvent être récupérées avec Tcl_ChannelTruncateProc, qui renvoie un pointeur vers la procédure.

TCL_BADCHANNELOPTION

Cette procédure génère un message d'erreur de type « mauvaise option » dans un interpréteur (facultatif). Elle est utilisée par les pilotes de canal lorsqu'une option de définition/obtention invalide est demandée. Son but est de concaténer la liste des options génériques aux options spécifiques et de factoriser la chaîne de message d'erreur des options génériques.

Elle retourne toujours TCL_ERROR

Un message d'erreur est généré dans la valeur de résultat de interp pour indiquer qu'une commande a été invoquée avec une mauvaise option. Le message a la forme :

    mauvaise option "blah" : devrait être l'une de
    <...options génériques...>+<...options spécifiques...>
vous obtenez par exemple : 
    mauvaise option "-blah" : devrait être l'une de -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, ou -sockname
lorsque appelée avec optionList égal à « peername sockname »

« blah » est l'argument optionName et « <options spécifiques> » est une liste d'options spécifiques séparées par des espaces. La procédure prend soin d'insérer des signes moins avant chaque option, des virgules après, et un « ou » avant la dernière option.

VIEILLES TYPES DE CANAL

La structure Tcl_ChannelType d'origine (8.3.1 et versions antérieures) contient les champs suivants :

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
} Tcl_ChannelType;

Il est toujours possible de créer des canaux avec la structure ci-dessus. Le code interne des canaux déterminera la version. Il est impératif d'utiliser la nouvelle structure Tcl_ChannelType si vous créez un pilote de canal empilé, en raison de problèmes avec l'implémentation précédente des canaux empilés (dans 8.2.0 à 8.3.1).

Avant 8.4.0 (c'est-à-dire pendant les dernières versions de 8.3 et la première partie du cycle de développement de 8.4), la structure Tcl_ChannelType contenait les champs suivants :

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_ChannelTypeVersion version;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Lorsque la structure ci-dessus est enregistrée en tant que type de canal, le champ version doit toujours être TCL_CHANNEL_VERSION_2.
