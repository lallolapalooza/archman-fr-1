DESCRIPTION

Les routines Tcl_SetReturnOptions et Tcl_GetReturnOptions exposent les mêmes capacités que les commandes return et catch, respectivement, sous forme d'une interface C.

Tcl_GetReturnOptions récupère le dictionnaire des options de retour d'un interpréteur après l'évaluation d'un script. Des routines telles que Tcl_Eval sont appelées pour évaluer un script dans un interpréteur. Ces routines retournent un code de complétion entier. Elles laissent également dans l'interpréteur un résultat et un dictionnaire d'options de retour générés par l'évaluation du script. Tout comme Tcl_GetObjResult récupère le résultat, Tcl_GetReturnOptions récupère le dictionnaire des options de retour. Le code de complétion entier doit être passé comme argument code à Tcl_GetReturnOptions afin que toutes les options requises soient présentes dans le dictionnaire. Spécifiquement, une valeur de code de TCL_ERROR garantira que les entrées pour les clés -errorinfo, -errorcode, et -errorline apparaîtront dans le dictionnaire. De plus, les entrées pour les clés -code et -level seront ajustées si nécessaire pour correspondre à la valeur de code. Le (Tcl_Obj *) retourné par Tcl_GetReturnOptions pointe vers un Tcl_Obj non partagé avec un compteur de références de zéro. Le dictionnaire peut être modifié, soit en ajoutant, supprimant, ou écrasant des entrées, sans avoir besoin de vérifier une valeur partagée. Comme avec tout Tcl_Obj avec un compteur de référence de zéro, il appartient à l'appelant de s'occuper de sa suppression avec Tcl_DecrRefCount ou de faire une référence à celui-ci via Tcl_IncrRefCount (ou l'une des nombreuses fonctions qui appellent cela, notamment Tcl_SetObjResult et Tcl_SetVar2Ex).

Une utilisation typique pour Tcl_GetReturnOptions est de récupérer la trace de la pile lorsque l'évaluation d'un script retourne TCL_ERROR, comme ceci :

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* Faire quelque chose avec stackTrace */
    Tcl_DecrRefCount(options);
}

Tcl_SetReturnOptions définit les options de retour de interp sur options. Si options contient une valeur invalide pour une clé, TCL_ERROR sera retourné, et le résultat de l'interpréteur sera défini sur un message d'erreur approprié. Sinon, un code de complétion cohérent avec les clés -code et -level dans options sera retourné.

Par exemple, la commande return de Tcl elle-même pourrait être implémentée en utilisant Tcl_SetReturnOptions comme suit :

if ((objc % 2) == 0) { /* argument de résultat explicite */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(Elle n'est pas vraiment implémentée de cette manière. Les privilèges d'accès internes permettent une alternative plus efficace qui s'intègre mieux avec le compilateur de bytecode.)

Notez qu'un Tcl_Obj nouvellement créé peut être passé comme argument options sans avoir besoin de gérer le comptage de références. Ceci est analogue à Tcl_SetObjResult.

Bien que Tcl_SetReturnOptions fournisse une interface générale pour définir n'importe quelle collection d'options de retour, il existe une poignée d'options de retour qui sont très fréquemment utilisées. Le plus notablement, l'option -errorinfo et l'option -errorcode doivent être correctement définies lorsque la procédure de commande d'une commande retourne TCL_ERROR. L'option -errorline est également lue par les commandes qui évaluent des scripts et souhaitent fournir des informations détaillées sur la localisation de l'erreur dans le texte de la trace de la pile qu'elles ajoutent à l'option -errorinfo. Tcl fournit plusieurs interfaces plus simples pour définir plus directement ces options de retour.

L'option -errorinfo contient une trace de la pile des opérations qui étaient en cours lorsqu'une erreur s'est produite, et est destinée à être lisible par l'homme. L'option -errorcode contient une liste Tcl d'éléments destinés à être lisibles par machine. Le premier élément de la valeur de -errorcode identifie la classe de l'erreur qui s'est produite (par exemple, POSIX signifie qu'une erreur s'est produite dans un appel système POSIX) et les éléments supplémentaires contiennent des informations supplémentaires qui dépendent de la classe. Voir la page de manuel sur la variable errorCode pour les détails sur les différents formats pour l'option -errorcode utilisés par les commandes intégrées de Tcl.

La valeur de l'option -errorinfo est progressivement construite lorsqu'une erreur se déroule à travers les opérations imbriquées. Chaque fois qu'un code d'erreur est retourné à Tcl_Eval, ou à l'une des routines qui effectue l'évaluation de script, la procédure Tcl_AddErrorInfo est appelée pour ajouter du texte supplémentaire à la valeur -errorinfo décrivant la commande qui était en cours d'exécution lorsque l'erreur s'est produite. Au moment où l'erreur est revennue à l'application, elle contiendra une trace complète de l'activité en cours lorsque l'erreur s'est produite.

Il est parfois utile d'ajouter des informations supplémentaires à la valeur -errorinfo au-delà de ce qui peut être fourni automatiquement par les routines d'évaluation de script. Tcl_AddErrorInfo peut être utilisée à cet effet : son argument message est une chaîne supplémentaire à ajouter à l'option -errorinfo. Par exemple, lorsqu'une erreur survient pendant la commande source, la procédure Tcl_AddErrorInfo est appelée pour enregistrer le nom du fichier en cours de traitement et le numéro de ligne de l'erreur. DESCRIPTION

Les procédures Tcl, le nom de la procédure et le numéro de ligne dans la procédure sont enregistrés, et ainsi de suite. Le meilleur moment pour appeler Tcl_AddErrorInfo est juste après qu'une routine d'évaluation de script retourne TCL_ERROR. La valeur de retour de l'option -errorline (récupérée par un appel à Tcl_GetReturnOptions) est généralement une partie utile du message passé à Tcl_AddErrorInfo.

Tcl_AppendObjToErrorInfo est une interface alternative pour la même fonctionnalité que Tcl_AddErrorInfo. Tcl_AppendObjToErrorInfo est appelée lorsque la valeur à ajouter à -errorinfo est disponible en tant que Tcl_Obj au lieu d'un tableau de char.

Tcl_AddObjErrorInfo est presque identique à Tcl_AddErrorInfo, sauf qu'elle a un argument supplémentaire length. Cela permet à la chaîne message de contenir des octets nuls intégrés. Ce n'est pratiquement jamais une bonne idée. Si le message doit contenir le caractère nul U+0000, les règles internes de codage de errno doivent être utilisées pour éviter la nécessité d'un octet nul. Si l'interface Tcl_AddObjErrorInfo est utilisée, elle doit être utilisée avec une valeur négative de length.

La procédure Tcl_SetObjErrorCode est utilisée pour définir la valeur de retour de l'option -errorcode à la valeur errorObjPtr construite par l'appelant. Tcl_SetObjErrorCode est généralement invoquée juste avant de retourner une erreur. Si une erreur est retournée sans invoquer Tcl_SetObjErrorCode ou Tcl_SetErrorCode, l'interpréteur Tcl définit automatiquement la valeur de retour de l'option -errorcode à NONE.

La procédure Tcl_SetErrorCode est également utilisée pour définir la valeur de retour de l'option -errorcode. Cependant, elle prend une ou plusieurs chaînes à enregistrer au lieu d'une valeur. Sinon, son comportement est similaire à celui de Tcl_SetObjErrorCode.

Tcl_SetErrorCodeVA est identique à Tcl_SetErrorCode, sauf qu'elle prend un nombre variable d'arguments, au lieu d'une liste d'arguments.

La procédure Tcl_GetErrorLine est utilisée pour lire la valeur entière de l'option de retour -errorline sans le surcoût d'un appel complet à Tcl_GetReturnOptions. De même, Tcl_SetErrorLine définit la valeur de l'option de retour -errorline.

Tcl_PosixError définit la valeur de la variable -errorcode après une erreur dans un appel au noyau POSIX. Elle lit la valeur de la variable errno de C et appelle Tcl_SetErrorCode pour définir la valeur de l'option de retour -errorcode au format POSIX. L'appelant doit avoir précédemment appelé Tcl_SetErrno pour définir errno ; ceci est nécessaire sur certaines machines (par exemple, sous Windows) où Tcl est lié à une application en tant que bibliothèque partagée, ou lorsque l'erreur se produit dans une extension dynamique. Voir le manuel de Tcl_SetErrno pour plus d'informations.

Tcl_PosixError renvoie un message de diagnostic humain pour l'erreur (c'est la même valeur qui apparaîtra comme troisième élément dans la valeur de l'option -errorcode). Il est utile d'inclure cette chaîne dans le message d'erreur renvoyé à l'application dans le résultat de l'interprétation.

Tcl_LogCommandInfo est invoqué après qu'une erreur se produit dans un interpréteur. Il ajoute des informations sur la commande qui était en cours d'exécution lorsque l'erreur s'est produite à la valeur d'erreur -errorinfo, et le numéro de ligne stocké en interne dans l'interpréteur est défini.

Dans les anciennes versions de Tcl, la routine Tcl_GetReturnOptions n'existait pas. À la place, les variables globales errorInfo et errorCode étaient les seuls emplacements pour récupérer les informations d'erreur. De nombreux codes existants pour les anciennes versions de Tcl accèdent encore à ces informations via ces variables globales.

Il est important de reconnaître que bien que la lecture de ces variables globales reste une méthode prise en charge pour accéder aux valeurs de retour d'options, il est important de ne pas supposer que l'écriture dans ces variables globales définira correctement les valeurs de retour correspondantes. Il a toujours été souligné dans cette page de manuel qu'il est important d'invoquer les procédures décrites ici plutôt que de définir directement errorInfo ou errorCode avec Tcl_ObjSetVar2.

Si Tcl_ResetResult est appelée, elle nettoie tout l'état de l'interpréteur associé à l'évaluation de scripts, y compris le dictionnaire complet des options de retour. En particulier, les options -errorinfo et -errorcode sont réinitialisées. S'il y avait eu une erreur, l'appel à Tcl_ResetResult nettoiera l'état d'erreur de manière à ce qu'il apparaisse comme si aucune erreur ne s'était produite après tout. Les variables globales errorInfo et errorCode ne sont pas modifiées par Tcl_ResetResult et continuent de conserver un enregistrement des informations sur la dernière erreur dans un interpréteur.
