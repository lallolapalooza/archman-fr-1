Tcl_OpenTcpClient(3) Procédures de la bibliothèque Tcl Tcl_OpenTcpClient(3)

NAME

Tcl_OpenTcpClient, Tcl_MakeTcpClientChannel, Tcl_OpenTcpServer — procédures pour ouvrir des canaux utilisant des sockets TCP

SYNOPSIS

#include <tcl.h> 

Tcl_Channel
Tcl_OpenTcpClient(interp, port, host, myaddr, myport, async)

Tcl_Channel
Tcl_MakeTcpClientChannel(sock)

Tcl_Channel
Tcl_OpenTcpServer(interp, port, myaddr, proc, clientData)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur Tcl à utiliser pour le rapport d'erreurs. Si non NULL et qu'une erreur survient, un message d'erreur est laissé dans le résultat de l'interpréteur.
int port (in)
Un numéro de port pour se connecter en tant que client ou pour écouter en tant que serveur.
const char *host (in)
Une chaîne spécifiant un nom d'hôte ou une adresse pour l'extrémité distante de la connexion.
int myport (in)
Un numéro de port pour l'extrémité cliente du socket. Si 0, un numéro de port est alloué aléatoirement.
const char *myaddr (in)
Une chaîne spécifiant le nom d'hôte ou l'adresse de l'interface réseau à utiliser pour l'extrémité locale de la connexion. Si NULL, une interface par défaut est choisie.
int async (in)
Si non nul, le socket client est connecté de manière asynchrone au serveur.
ClientData sock (in)
Handle spécifique à la plateforme pour un socket TCP client.
Tcl_TcpAcceptProc *proc (in)
Pointeur vers une procédure à invoquer chaque fois qu'une nouvelle connexion est acceptée via le socket.
ClientData clientData (in)
Valeur arbitraire d'un mot à passer à proc.

DESCRIPTION

Ces fonctions sont des procédures de commodité pour créer des canaux qui communiquent via des sockets TCP. Les opérations sur un canal sont décrites dans la page de manuel de Tcl_OpenFileChannel.

TCL_OPENTCPCLIENT

Tcl_OpenTcpClient ouvre un socket TCP client connecté à un port spécifié sur un hôte particulier et renvoie un canal pouvant être utilisé pour communiquer avec le serveur. L'hôte auquel se connecter peut être spécifié comme un nom de domaine (par exemple, www.sunlabs.com) ou comme une chaîne contenant la représentation alphanumérique de son adresse de 4 octets (par exemple, 127.0.0.1). Utilisez la chaîne localhost pour vous connecter à un socket TCP sur l'hôte sur lequel la fonction s'exécute.

Les arguments myaddr et myport permettent à un client de spécifier une adresse pour le côté local de la connexion. Si myaddr est NULL, une interface est automatiquement choisie par le système d'exploitation. Si myport est 0, un numéro de port est choisi aléatoirement par le système d'exploitation.

Si async est 0, l'appel à Tcl_OpenTcpClient ne retourne qu'après que le socket client ait correctement connecté au serveur ou que la connexion ait échoué. Si async est différent de zéro, le socket est connecté de manière asynchrone et le canal retourné peut ne pas être encore connecté au serveur lorsque Tcl_OpenTcpClient est appelé. Si le canal est en mode bloquant et qu'une opération d'entrée/sortie y est effectuée avant que la connexion ne soit terminée ou n'ait échoué, cette opération attendra jusqu'à ce que la connexion se termine avec succès ou échoue. Si le canal est en mode non bloquant, l'opération d'entrée/sortie retournera immédiatement et un appel à Tcl_InputBlocked sur le canal retournera une valeur non nulle.

Le canal retourné est ouvert en lecture et en écriture. S'il y a une erreur lors de l'ouverture du socket, Tcl_OpenTcpClient retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas nul, un message d'erreur est laissé dans le résultat de l'interpréteur.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, vous devez utiliser Tcl_RegisterChannel. Si l'un des canaux standards, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'assigne également comme remplacement de ce canal standard.

TCL_MAKETCPCLIENTCHANNEL

Tcl_MakeTcpClientChannel crée un Tcl_Channel autour d'un handle existant, spécifique au système d'exploitation, pour un socket TCP client.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, vous devez utiliser Tcl_RegisterChannel. Si l'un des canaux standards, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'assigne également comme remplacement de ce canal standard.

TCL_OPENTCPSERVER

Tcl_OpenTcpServer ouvre un socket TCP sur l'hôte local sur un port spécifié et utilise le mécanisme d'événements Tcl pour accepter les connexions des clients. L'argument myaddr spécifie l'interface réseau. Si myaddr est NULL, l'adresse spéciale INADDR_ANY doit être utilisée pour permettre les connexions de n'importe quelle interface réseau. Chaque fois qu'un client se connecte à ce socket, Tcl crée un canal pour la nouvelle connexion et appelle proc avec des informations sur le canal. Proc doit correspondre au prototype suivant :

typedef void Tcl_TcpAcceptProc(
        ClientData clientData,
        Tcl_Channel channel,
        char *hostName,
        int port);

L'argument clientData sera le même que l'argument clientData de Tcl_OpenTcpServer, channel sera le handle du nouveau canal, hostName pointera vers une chaîne contenant le nom de l'hôte du client qui effectue la connexion, et port contiendra le numéro de port du client. Le nouveau canal est ouvert en entrée et en sortie. Si proc lève une erreur, la connexion est automatiquement fermée. Proc n'a pas de valeur de retour, mais si vous souhaitez refuser la connexion, vous pouvez fermer channel.

Tcl_OpenTcpServer renvoie normalement un pointeur vers un canal représentant le socket du serveur. Si une erreur survient, Tcl_OpenTcpServer retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si l'interpréteur n'est pas nul, un message d'erreur est laissé dans le résultat de l'interpréteur.

Le canal retourné par Tcl_OpenTcpServer ne peut pas être utilisé pour l'entrée ou la sortie. C'est simplement un handle pour le socket utilisé pour accepter les connexions. L'appelant peut fermer le canal pour arrêter le serveur et désactiver les futures connexions de nouveaux clients.

Les canaux de serveur TCP fonctionnent correctement uniquement dans les applications qui distribuent des événements via Tcl_DoOneEvent ou via des commandes Tcl telles que vwait ; sinon, Tcl ne notifiera jamais qu'une demande de connexion d'un client distant est en attente.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, vous devez utiliser Tcl_RegisterChannel. Si l'un des canaux standards, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'assigne également comme remplacement de ce canal standard.

PROBLÈMES DE PLATEFORME

Sur les plateformes Unix, le handle du socket est un descripteur de fichier Unix, tel que retourné par l'appel socket. Sur la plateforme Windows, le handle du socket est un SOCKET, tel que défini dans l'API WinSock.
