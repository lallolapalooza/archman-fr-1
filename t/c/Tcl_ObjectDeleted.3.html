DESCRIPTION

Les objets sont des entités typées qui ont un ensemble d'opérations ("méthodes") associées à elles. Les classes sont des objets qui peuvent fabriquer des objets. Chaque classe peut être vue comme un objet en soi ; la vue objet peut être récupérée à l'aide de Tcl_GetClassAsObject qui retourne toujours l'objet lorsqu'elle est appliquée à une classe non détruite, et un objet peut être vu comme une classe avec l'aide de Tcl_GetObjectAsClass (qui retourne soit la classe, soit NULL si l'objet n'est pas une classe). Un objet peut être recherché à l'aide de la fonction Tcl_GetObjectFromObj, qui retourne soit un objet, soit NULL (avec un message d'erreur dans le résultat de l'interpréteur) si l'objet ne peut être trouvé. La manière correcte de rechercher une classe par nom est de rechercher l'objet portant ce nom, puis d'utiliser Tcl_GetObjectAsClass.

Chaque objet a sa propre commande et son propre espace de noms associés. La commande peut être récupérée à l'aide de la fonction Tcl_GetObjectCommand, le nom de l'objet (et donc le nom de la commande) avec Tcl_GetObjectName, et l'espace de noms peut être récupéré à l'aide de la fonction Tcl_GetObjectNamespace. Notez que la référence Tcl_Obj retournée par Tcl_GetObjectName est une référence partagée. Vous pouvez également obtenir si l'objet a été marqué pour suppression avec Tcl_ObjectDeleted (il retourne vrai si la suppression de l'objet a commencé) ; cela peut être utile pendant le traitement des méthodes.

Les instances de classes sont créées à l'aide de Tcl_NewObjectInstance, qui crée un objet à partir de n'importe quelle classe (et qui est appelé en interne par les méthodes create et new de la classe oo::class). Elle prend des paramètres qui donnent éventuellement le nom de l'objet et de l'espace de noms à créer, et qui décrivent les arguments à passer au constructeur de la classe (le cas échéant). Le résultat de la fonction sera soit une référence au nouvel objet créé, soit NULL si la création a échoué (auquel cas un message d'erreur sera laissé dans le résultat de l'interpréteur). En outre, les objets peuvent être copiés en utilisant Tcl_CopyObjectInstance qui crée une copie d'un objet sans exécuter de constructeurs.

Notez que la gestion de la durée de vie des objets est gérée en interne dans TclOO, et n'utilise pas Tcl_Preserve. Il n'est pas sûr de placer une poignée Tcl_Object dans une structure C dont la durée de vie est différente de celle de l'objet ; vous devriez plutôt utiliser le nom de commande de l'objet (tel que récupéré avec Tcl_GetObjectName). Il est sûr d'utiliser une poignée Tcl_Object pendant la durée de vie d'un appel de méthode sur cet objet ; les poignées ne deviennent pas invalides tant qu'il y a un appel en cours sur leur objet (même si la seule opération garantie d'être sûre sur elles est Tcl_ObjectDeleted ; les autres opérations ne sont garanties de fonctionner que sur des objets non supprimés).

MÉTABONNÉES OBJET ET CLASSE

Chaque objet et chaque classe peuvent avoir des quantités arbitraires de métadonnées attachées à eux, auxquelles l'objet ou la classe n'attribue aucune signification au-delà de ce qui est décrit dans une instance de structure Tcl_ObjectMetadataType. Les métadonnées à attacher sont décrites par le type des métadonnées (fourni dans l'argument metaTypePtr) et un pointeur arbitraire (l'argument metadata) qui sont donnés à Tcl_ObjectSetMetadata et Tcl_ClassSetMetadata, et un élément particulier de métadonnées peut être récupéré en donnant son type à l'aide de Tcl_ObjectGetMetadata et Tcl_ClassGetMetadata. Si le paramètre metadata de Tcl_ObjectSetMetadata ou Tcl_ClassSetMetadata est NULL, les métadonnées sont supprimées si elles étaient attachées, et les résultats de Tcl_ObjectGetMetadata et Tcl_ClassGetMetadata sont NULL si le type de métadonnées donné n'était pas attaché. Il n'est pas une erreur de demander ou de supprimer une métadonnée qui n'était pas attachée.

STRUCTURE TCL_OBJECTMETADATATYPE

Le contenu de la structure Tcl_ObjectMetadataType est le suivant :

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

Le champ version permet une extension future de la structure, et doit toujours être déclaré égal à TCL_OO_METADATA_VERSION_CURRENT. Le champ name fournit un nom lisible par l'homme pour le type, et est réservé au débogage.

Le champ deleteProc donne une fonction de type Tcl_ObjectMetadataDeleteProc qui est utilisée pour supprimer une métadonnée particulière, et est appelée lorsque les métadonnées attachées sont remplacées ou supprimées ; le champ ne doit pas être NULL.

Le champ cloneProc donne une fonction qui est utilisée pour copier une métadonnée (utilisée lors de la création d'une copie d'objet à l'aide de Tcl_CopyObjectInstance) ; si NULL, les métadonnées seront copiées directement.

SIGNATURE FONCTION TCL_OBJECTMETADATADELETEPROC

Les fonctions correspondant à cette signature sont utilisées pour supprimer les métadonnées associées à une classe ou à un objet.

DESCRIPTION

The TclOO object system provides a number of functions for managing objects and their associated metadata. These functions allow you to control how objects are created, destroyed, copied, and how their methods are invoked.

OBJECT AND CLASS METADATA

Each TclOO object can have associated metadata, which is opaque data managed by the application. This metadata can be used to store custom information related to the object. The following functions provide access to this metadata:

Tcl_ObjectSetConstructor
Sets the constructor procedure for an object. The constructor is called when the object is created and is responsible for initializing the object's metadata.
Tcl_ObjectGetConstructor
Retrieves the constructor procedure for an object.
Tcl_ObjectSetDeleteProc
Sets the delete procedure for an object. The delete procedure is called when the object is destroyed and is responsible for cleaning up the object's metadata.
Tcl_ObjectGetDeleteProc
Retrieves the delete procedure for an object.
Tcl_ObjectSetCloneProc
Sets the clone procedure for an object. The clone procedure is called when the object is copied and is responsible for creating a copy of the object's metadata.
Tcl_ObjectGetCloneProc
Retrieves the clone procedure for an object.

The following functions provide information about the state of an object:

Tcl_ObjectDeleted
Checks if an object has been deleted. If the object has been deleted, this function returns TCL_OK, otherwise it returns TCL_ERROR. If an error occurs, the error message is written to the interpreter specified by interp.
Tcl_ObjectDestroyed
Checks if an object has been destroyed. This function returns 1 if the object has been destroyed, and 0 otherwise.
Tcl_ObjectIsDeleted
Checks if an object has been marked for deletion. This function returns 1 if the object is marked for deletion, and 0 otherwise.

The Tcl_ObjectConstructorProc callback is defined as follows:

typedef int Tcl_ObjectConstructorProc(
        Tcl_Interp *interp,
        Tcl_Object object,
        int objc,
        Tcl_Obj *const *objv);

The constructor procedure is called when an object is created. The interp argument is the interpreter in which the object is created. The object argument is the object being created. The objc and objv arguments describe the arguments passed to the constructor.

The Tcl_ObjectDeleteProc callback is defined as follows:

typedef int Tcl_ObjectDeleteProc(
        Tcl_Interp *interp,
        ClientData metadata);

The metadata argument gives the address of the metadata to be deleted.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to create copies of metadata associated with a class or object.

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData srcMetadata,
        ClientData *dstMetadataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The srcMetadata argument gives the address of the metadata to be cloned, and the cloned metadata should be written into the variable pointed to by dstMetadataPtr; a NULL should be written if the metadata is to not be cloned but the overall object copy operation is still to succeed.

OBJECT METHOD NAME MAPPING

It is possible to control, on a per-object basis, what methods are invoked when a particular method is invoked. Normally this is done by looking up the method name in the object and then in the class hierarchy, but fine control of exactly what the value used to perform the look up is afforded through the ability to set a method name mapper callback via Tcl_ObjectSetMethodNameMapper (and its introspection counterpart, Tcl_ObjectGetMethodNameMapper, which returns the current mapper). The current mapper (if any) is invoked immediately before looking up what chain of method implementations is to be used.

TCL_OBJECTMAPMETHODNAMEPROC FUNCTION SIGNATURE

The Tcl_ObjectMapMethodNameProc callback is defined as follows:

typedef int Tcl_ObjectMapMethodNameProc(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class *startClsPtr,
        Tcl_Obj *methodNameObj);

If the result is TCL_OK, the remapping is assumed to have been done. If the result is TCL_ERROR, an error message will have been left in interp and the method call will fail. If the result is TCL_BREAK, the standard method name lookup rules will be used; the behavior of other result codes is currently undefined. The object parameter says which object is being processed. The startClsPtr parameter points to a variable that contains the first class to provide a definition in the method chain to process, or NULL if the whole chain is to be processed (the argument itself is never NULL); this variable may be updated by the callback. The methodNameObj parameter gives an unshared object containing the name of the method being invoked, as provided by the user; this object may be updated by the callback.
