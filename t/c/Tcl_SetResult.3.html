DESCRIPTION

Les procédures décrites ici sont des utilitaires pour manipuler la valeur du résultat dans un interpréteur Tcl. Le résultat de l'interpréteur peut être une valeur Tcl ou une chaîne. Par exemple, Tcl_SetObjResult et Tcl_SetResult définissent le résultat pour, respectivement, une valeur et une chaîne. De plus, Tcl_GetObjResult et Tcl_GetStringResult retournent le résultat de l'interpréteur comme valeur et comme chaîne. Les procédures maintiennent toujours la cohérence entre le format de chaîne et de valeur du résultat de l'interpréteur. Par exemple, si Tcl_SetObjResult est appelé pour définir le résultat à une valeur, Tcl_GetStringResult retournera la représentation chaîne de la valeur.

Tcl_SetObjResult assure que objPtr est le résultat pour interp, remplaçant tout résultat existant. Le résultat pointe alors vers la valeur référencée par objPtr. Le compteur de références de objPtr est incrémenté car il y a maintenant une nouvelle référence à celui-ci depuis interp. Le compteur de références de l'ancienne valeur est décrémenté et elle est libérée s'il n'y a plus de références à celle-ci.

Tcl_GetObjResult retourne le résultat pour interp sous forme de valeur. Le compteur de références de la valeur n'est pas incrémenté ; si l'appelant a besoin de conserver un pointeur à long terme vers la valeur, il doit utiliser Tcl_IncrRefCount pour incrémenter son compteur de références afin d'éviter qu'elle ne soit libérée trop tôt ou modifiée accidentellement.

Tcl_SetResult assure que result est le résultat pour la commande Tcl actuelle dans interp, remplaçant tout résultat existant. L'argument freeProc spécifie comment gérer l'espace dans result ; il est discuté dans la section THE TCL_FREEPROC ARGUMENT TO TCL_SETRESULT ci-dessous. Si result est NULL, alors freeProc est ignoré et Tcl_SetResult réinitialise le résultat de interp à une chaîne vide.

Tcl_GetStringResult retourne le résultat pour interp sous forme de chaîne. Si le résultat a été défini par un appel à Tcl_SetObjResult, la représentation chaîne de la valeur sera convertie et retournée. Si la représentation chaîne de la valeur contient des octets nuls, cette conversion perdra des informations. Pour cette raison, il est recommandé aux programmeurs d'écrire leur code en utilisant les nouvelles API de valeur et d'appeler Tcl_GetObjResult à la place.

Tcl_ResetResult efface le résultat pour interp et laisse le résultat dans son état initial vide normal. Si le résultat est une valeur, son compteur de références est décrémenté et le résultat pointe vers une valeur non partagée représentant une chaîne vide. Si le résultat est une chaîne allouée dynamiquement, sa mémoire est libérée et le résultat devient une chaîne vide. Tcl_ResetResult efface également l'état d'erreur géré par Tcl_AddErrorInfo, Tcl_AddObjErrorInfo et Tcl_SetErrorCode.

Tcl_AppendResult facilite la construction de résultats Tcl en fragments. Elle prend chacun de ses arguments result et les ajoute en ordre au résultat actuel associé à interp. Si le résultat est dans son état initial vide (par exemple, une procédure de commande a été invoquée ou Tcl_ResetResult a été appelé), alors Tcl_AppendResult définit le résultat à la concaténation de ses arguments result. Tcl_AppendResult peut être appelée de manière répétée comme fragments supplémentaires de résultat. Tcl_AppendResult gère toutes les questions de gestion de mémoire associées à la gestion du résultat de interp, comme l'allocation d'une zone plus grande si nécessaire. Elle gère également la conversion vers et depuis le champ result de interp pour gérer la compatibilité avec les anciennes extensions. N'importe quel nombre d'arguments result peut être passé en un seul appel ; le dernier argument de la liste doit être (char *)NULL.

Tcl_AppendResultVA est identique à Tcl_AppendResult sauf qu'elle prend une liste d'arguments variable au lieu d'un nombre variable d'arguments.

Tcl_TransferResult transfère l'état de l'interpréteur de sourceInterp vers targetInterp. Les deux interpréteurs doivent avoir été créés dans le même thread. Si sourceInterp et targetInterp sont identiques, rien ne se passe. Sinon, Tcl_TransferResult déplace le résultat de sourceInterp vers targetInterp, et réinitialise le résultat dans sourceInterp. Elle déplace également le dictionnaire d'options de retour contrôlé par la valeur de retour code de la même manière que Tcl_GetReturnOptions.

INTERFACES DÉPRÉCIÉES

PROCÉDURES DE CHAÎNE ANCIENNES

L'utilisation des procédures suivantes est obsolète car elles manipulent le résultat de Tcl comme une chaîne. Les procédures comme Tcl_SetObjResult qui manipulent le résultat comme une valeur peuvent être significativement plus efficaces.

Tcl_AppendElement est similaire à Tcl_AppendResult car elle permet de construire des résultats en fragments. Cependant, Tcl_AppendElement ne prend qu'un seul argument element et l'ajoute au résultat actuel comme un élément de liste valide. Tcl_AppendElement ajoute des antislashs ou des crochets si nécessaire pour garantir que le résultat de interp puisse être analysé comme une liste et que element puisse être extrait comme un élément unique. Dans des conditions normales, Tcl_AppendElement ajoute un espace dans le résultat de interp juste avant d'ajouter le nouvel élément de liste, de sorte que les éléments de liste dans le résultat soient correctement séparés. Cependant, si le nouvel élément de liste est le premier d'une liste ou d'une sous-liste (c'est-à-dire que le résultat actuel de interp est vide, ou se compose uniquement du caractère '{', ou se termine par les caractères '{' ), alors aucun espace n'est ajouté.

Tcl_FreeResult effectue une partie du travail de Tcl_ResetResult. Elle libère l'espace associé au résultat de interp. Elle met également interp->freeProc à zéro, mais ne modifie pas interp->result ou n'efface pas l'état d'erreur.

Tcl_FreeResult est plus couramment utilisé lorsqu'une procédure est sur le point de remplacer une valeur de résultat par une autre.

ACCÈS DIRECT À INTERP->RESULT

Il était légal pour les programmes de lire et d'écrire directement interp->result pour manipuler le résultat de l'interpréteur. L'en-tête Tcl ne permet pas cet accès par défaut, et le code C qui le fait encore doit être mis à jour pour utiliser le nouveau mode.
