ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur auquel la limite gérée s'applique ou dont les limites seront vérifiées.
int type (in)
Le type de limite auquel l'opération se réfère. Ce doit être TCL_LIMIT_COMMANDS ou TCL_LIMIT_TIME.
int commandLimit (in)
Le nombre maximum de commandes (tel que rapporté par info cmdcount) qui peuvent être exécutées dans l'interpréteur.
Tcl_Time *timeLimitPtr (in/out)
Un pointeur vers une structure qui peut lire la nouvelle limite de temps (par Tcl_LimitSetTime) ou écrire la limite de temps actuelle (par Tcl_LimitGetTime).
int granularity (in)
Un diviseur qui indique tous les combien de points d'entrée (hooks) une vérification doit réellement avoir lieu. Doit être au moins 1.
Tcl_LimitHandlerProc *handlerProc (in)
Fonction à appeler lorsqu'une limite est dépassée. Si le handlerProc supprime ou augmente la limite pendant son exécution, l'interpréteur limité sera autorisé à continuer le traitement après le retour du gestionnaire. Plusieurs gestionnaires peuvent être associés à la même limite d'interpréteur ; leur ordre d'exécution n'est pas défini et ils doivent être identifiés par handlerProc et clientData lors de leur suppression.
ClientData clientData (in)
Une valeur de pointeur de données arbitraire utilisée pour passer le contexte à la fonction handlerProc.
Tcl_LimitHandlerDeleteProc *deleteProc (in)
Fonction à appeler lorsqu'un gestionnaire est supprimé. Peut être NULL si le clientData ne nécessite aucune suppression.

DESCRIPTION

Le système de limites de temps de Tcl permet un contrôle précis sur le temps d'exécution d'un script et est utile dans les cas où un programme est divisé en plusieurs parties dont certaines sont plus fiables que d'autres (par exemple, les serveurs d'applications web).

Chaque interpréteur peut avoir une limite sur son temps d'exécution et une limite sur le nombre de commandes qu'il peut exécuter. Étant donné que la vérification de ces limites peut être coûteuse (en particulier la limite de temps), chaque limite a également une politique de granularité, qui est un diviseur pour le nombre de points d'entrée (hooks) où une vérification peut avoir lieu (qui a lieu juste avant l'exécution d'une commande et à une fréquence non spécifiée entre les exécutions de commandes, ce qui peut se produire dans des boucles while vides).

La partie finale du moteur de limites est un schéma de rappels qui permet des notifications lorsqu'une limite est dépassée. Ces rappels peuvent fournir une journalisation ou peuvent allouer plus de ressources à l'interprétation pour lui permettre de traiter plus de temps.

Lorsqu'une limite est dépassée (et que les rappels ont été exécutés ; l'ordre d'exécution des rappels n'est pas défini), l'exécution dans l'interpréteur limité est arrêtée en générant une erreur et en définissant un indicateur qui empêche la commande catch dans cet interpréteur de traiter cette erreur. Il appartient au contexte qui a initié l'exécution dans cet interpréteur (normalement l'interpréteur principal) de gérer l'erreur.

API DE VÉRIFICATION DES LIMITES

Pour vérifier les limites d'un interpréteur, appelez Tcl_LimitCheck, qui renvoie TCL_OK si la limite n'a pas été dépassée (après traitement des rappels) et TCL_ERROR si la limite a été dépassée (dans ce cas, un message d'erreur est également placé dans le résultat de l'interpréteur). Cette fonction ne doit être appelée que lorsque Tcl_LimitReady renvoie une valeur non nulle afin que la politique de granularité soit appliquée. Cette API est conçue pour être similaire en utilisation à Tcl_AsyncReady et Tcl_AsyncInvoke.

Lorsque vous écrivez du code qui peut se comporter comme catch en termes d'erreurs, vous ne devez capturer une erreur que si Tcl_LimitExceeded renvoie zéro. S'il renvoie non zéro, l'interpréteur est dans un état de limite dépassée et les erreurs doivent se propager au contexte qui a appelé le code. Vous pouvez également vérifier si un type de limite spécifique a été dépassé en utilisant Tcl_LimitTypeExceeded.

CONFIGURATION DES LIMITES

Pour vérifier si une limite a été définie (mais pas encore vérifiée) dans un interpréteur, appelez Tcl_LimitTypeEnabled avec le type de limite que vous souhaitez vérifier. Pour activer une limite, appelez Tcl_LimitTypeSet, et pour désactiver une limite, appelez Tcl_LimitTypeReset.

Le niveau d'une limite de commandes peut être défini en utilisant Tcl_LimitSetCommands et récupéré en utilisant Tcl_LimitGetCommands. De même, pour une limite de temps, Tcl_LimitSetTime et Tcl_LimitGetTime sont utilisés, mais avec cette API, la limite de temps est copiée depuis et vers la structure Tcl_Time vers laquelle pointe l'argument timeLimitPtr.

La granularité de la limite spécifique peut être définie en utilisant Tcl_LimitSetGranularity et récupérée en utilisant Tcl_LimitGetGranularity. Vous devez noter que les granularités doivent être positives.

GESTIONNAIRES DE LIMITES

Pour ajouter un gestionnaire de rappel à invoquer lorsqu'une limite est dépassée, appelez Tcl_LimitAddHandler. L'argument handlerProc décrit la fonction à appeler ; il doit avoir le prototype suivant :

typedef void Tcl_LimitHandlerProc(
        ClientData clientData,
        Tcl_Interp *interp);

L'argument clientData de la fonction gestionnaire sera ce qui a été passé à l'argument clientData de Tcl_LimitAddHandler, et interp est l'interpréteur qui a dépassé la limite.

L'argument deleteProc de Tcl_LimitAddHandler est une fonction à appeler pour supprimer la valeur clientData. Il peut être TCL_STATIC ou NULL si aucune action de suppression n'est requise, ou TCL_DYNAMIC si seule la libération de la structure avec Tcl_Free est nécessaire. Sinon, il doit faire référence à une fonction avec le prototype suivant :

typedef void Tcl_LimitHandlerDeleteProc(
        ClientData clientData);

Un gestionnaire de limite peut être supprimé en utilisant Tcl_LimitRemoveHandler ; le gestionnaire supprimé sera le premier trouvé (parmi les gestionnaires ajoutés avec Tcl_LimitAddHandler) avec exactement les arguments type, handlerProc et clientData. Cette fonction invoque toujours le deleteProc sur le clientData (à moins que le deleteProc ne soit NULL ou TCL_STATIC).
