ARGUMENTS

Interpréteur dans lequel les informations seront enregistrées.

const char *message (entree)
Pour Tcl_AddErrorInfo, il s'agit d'une chaîne C conventionnelle à ajouter à l'option de retour -errorinfo. Pour Tcl_AddObjErrorInfo, cela pointe vers le premier octet d'un tableau de length octets contenant une chaîne à ajouter à l'option de retour -errorinfo. Ce tableau d'octets peut contenir des octets nuls si length est négatif.

L'option de retour -errorcode sera définie à cette valeur.

Chaîne à enregistrer comme l'un des éléments de l'option de retour -errorcode. Le dernier argument doit être (char *)NULL.

DESCRIPTION

Les routines Tcl_SetReturnOptions et Tcl_GetReturnOptions exposent les mêmes capacités que les routines return et catch respectivement sous la forme d'une interface C.

Tcl_GetReturnOptions récupère le dictionnaire d'options de retour d'un interpréteur après l'évaluation d'un script. Des routines comme Tcl_Eval sont appelées pour évaluer un script dans un interpréteur. Ces routines renvoient un code de complétion entier. Ces routines conservent également dans l'interpréteur à la fois un résultat et un dictionnaire d'options de retour générés par l'évaluation du script. De manière similaire à Tcl_GetObjResult, Tcl_GetReturnOptions récupère le dictionnaire d'options de retour. Le code de complétion entier doit être passé comme argument code à Tcl_GetReturnOptions afin que tous les éléments nécessaires soient présents dans le dictionnaire. Spécifiquement, une valeur de code de TCL_ERROR garantira que les entrées pour les clés -errorinfo, -errorcode et -errorline soient incluses dans le dictionnaire. Les entrées pour les clés -code et -level seront également ajustées si nécessaire pour correspondre à la valeur de code. Le (Tcl_Obj *) renvoyé par Tcl_GetReturnOptions pointe vers un Tcl_Obj non partagé avec un compteur de références nul. Le dictionnaire peut être modifié, en ajoutant, supprimant ou écrasant n'importe quelle entrée, sans avoir besoin de vérifier une valeur partagée. Comme tout Tcl_Obj avec un compteur de références nul, il incombe à l'appelant d'organiser sa disposition avec Tcl_DecrRefCount ou en le référençant via Tcl_IncrRefCount (ou l'une des nombreuses fonctions qui l'appellent, y compris notamment Tcl_SetObjResult et Tcl_SetVar2Ex).

Une utilisation typique de Tcl_GetReturnOptions est de récupérer la trace de la pile lorsque l'évaluation d'un script renvoie TCL_ERROR, comme suit :

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* Faire quelque chose avec stackTrace */
    Tcl_DecrRefCount(options);
}

Tcl_SetReturnOptions définit les options de retour de interp à options. Si options contient des valeurs invalides pour une clé, TCL_ERROR sera renvoyé et le résultat de l'interpréteur sera défini à un message d'erreur approprié. Sinon, un code de complétion sera renvoyé conformément au -code et -level dans options.

Par exemple, la commande return de Tcl elle-même pourrait être implémentée en termes de Tcl_SetReturnOptions comme suit :

if ((objc % 2) == 0) { /* argument résultat explicite */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(Elle n'est pas réellement implémentée ainsi. Les privilèges internes permettent une alternative plus efficace qui est mieux optimisée par le compilateur bytecode.)

Note : Un nouveau Tcl_Obj peut être passé comme argument options sans avoir besoin de gérer le comptage de références. Ceci est analogue à Tcl_SetObjResult.

Bien que Tcl_SetReturnOptions offre une interface générale pour définir n'importe quelle collection d'options de retour, il existe plusieurs types d'options de retour qui sont très fréquemment utilisés. Les plus notables sont -errorinfo et -errorcode qui doivent être correctement définis lorsque la procédure d'une commande renvoie TCL_ERROR. L'option de retour -errorline est également lue par les commandes qui évaluent des scripts et souhaitent fournir des informations de localisation détaillées sur la ligne de texte de la trace de la pile qui est ajoutée à l'option -errorinfo. Tcl offre plusieurs interfaces plus simples pour définir ces options de retour de manière plus directe.

La valeur de l'option -errorinfo contient une trace de la pile des opérations en cours lorsque une erreur s'est produite, et est destinée à être lue par des humains. La valeur de l'option -errorcode contient une liste d'éléments Tcl destinés à être lus par des machines. Le premier élément de l'option -errorcode identifie le type d'erreur qui s'est produit (par exemple, POSIX signifie qu'une erreur s'est produite dans un appel POSIX). Les éléments supplémentaires contiennent des informations supplémentaires qui dépendent du type d'erreur. Voir l'entrée du manuel de la variable errorCode pour des détails sur les différents formats utilisés dans les options de retour -errorcode par les commandes Tcl standard.

La valeur de l'option -errorinfo est progressivement construite au fur et à mesure que l'erreur est propagée à travers les opérations imbriquées. Chaque fois qu'un code d'erreur est renvoyé à Tcl_Eval, ou à l'une des routines qui effectuent l'évaluation de scripts, la procédure Tcl_AddErrorInfo est appelée pour ajouter un texte supplémentaire à l'option de retour -errorinfo décrivant la commande qui était en cours d'exécution lorsque l'erreur s'est produite. Au moment où l'erreur est renvoyée à l'application, elle contiendra une trace complète de l'activité en cours lorsque l'erreur s'est produite.

Il est parfois utile d'ajouter des informations supplémentaires à l'option de retour -errorinfo au-delà de ce qui peut être fourni automatiquement par les routines d'évaluation de scripts. Tcl_AddErrorInfo peut être utilisé à cette fin : son argument message est une chaîne supplémentaire à ajouter à l'option de retour -errorinfo. Par exemple, lorsqu'une erreur se produit pendant la commande source, la procédure Tcl_AddErrorInfo est appelée pour enregistrer le nom du fichier en cours de traitement et le numéro de ligne auquel l'erreur s'est produite. Le meilleur moment pour appeler Tcl_AddErrorInfo est juste après qu'une routine d'évaluation de script ait retourné TCL_ERROR. La valeur de l'option de retour -errorline (récupérée via un appel à Tcl_GetReturnOptions) constitue souvent une partie utile du message passé à Tcl_AddErrorInfo.

Tcl_AppendObjToErrorInfo est une interface alternative pour la même fonctionnalité que Tcl_AddErrorInfo. Tcl_AppendObjToErrorInfo est appelée lorsque la valeur de chaîne à ajouter à l'option -errorinfo est disponible sous forme de Tcl_Obj au lieu d'un tableau de char.

Tcl_AddObjErrorInfo est presque identique à Tcl_AddErrorInfo, à l'exception d'un argument length supplémentaire. Cela permet à la chaîne message de contenir des octets nuls incorporés. Ce n'est pratiquement jamais une bonne idée. Si le message doit contenir le caractère nul U+0000, les règles de codage habituelles de Tcl doivent être utilisées pour éviter le besoin d'un octet nul. Si l'interface Tcl_AddObjErrorInfo est utilisée, ce doit être avec une valeur length négative.

La procédure Tcl_SetObjErrorCode est utilisée pour définir l'option de retour -errorcode à la valeur de liste errorObjPtr construite par l'appelant. Tcl_SetObjErrorCode est généralement invoquée juste avant de retourner une erreur. Si une erreur est retournée sans appeler Tcl_SetObjErrorCode ou Tcl_SetErrorCode, l'interpréteur Tcl définit automatiquement l'option de retour -errorcode à NONE.

La procédure Tcl_SetErrorCode est également utilisée pour définir l'option de retour -errorcode. Cependant, elle prend une ou plusieurs chaînes à enregistrer au lieu d'une valeur. Sinon, elle est similaire à Tcl_SetObjErrorCode en termes de comportement.

Tcl_SetErrorCodeVA est identique à Tcl_SetErrorCode sauf qu'au lieu de prendre un nombre variable d'arguments, elle prend une liste d'arguments.

La procédure Tcl_GetErrorLine est utilisée pour lire la valeur entière de l'option de retour -errorline sans la surcharge d'un appel complet à Tcl_GetReturnOptions. De même, Tcl_SetErrorLine définit la valeur de l'option de retour -errorline.

Tcl_PosixError définit la variable -errorcode après une erreur dans un appel noyau POSIX. Elle lit la valeur de la variable C errno et appelle Tcl_SetErrorCode pour définir l'option de retour -errorcode au format POSIX. L'appelant doit avoir préalablement appelé Tcl_SetErrno pour définir errno ; ceci est nécessaire sur certaines plates-formes (par exemple, Windows) où Tcl est lié dans une application en tant que bibliothèque partagée, ou lorsque l'erreur se produit dans une extension chargée dynamiquement. Voir la page de manuel de Tcl_SetErrno pour plus d'informations.

Tcl_PosixError retourne un message de diagnostic lisible par l'homme pour l'erreur (c'est la même valeur qui apparaîtra comme troisième élément de la valeur -errorcode). Il peut être pratique d'inclure cette chaîne dans le message d'erreur retourné à l'application dans le résultat de l'interpréteur.

Tcl_LogCommandInfo est invoquée après qu'une erreur se produit dans un interpréteur. Elle ajoute des informations sur la commande qui était en cours d'exécution lorsque l'erreur s'est produite à la valeur -errorinfo, et le numéro de ligne stocké en interne dans l'interpréteur est défini.

Dans les versions antérieures de Tcl, il n'y avait pas de routine Tcl_GetReturnOptions. À sa place, les variables globales Tcl errorInfo et errorCode étaient le seul endroit pour récupérer les informations d'erreur. De nombreux codes existants écrits pour les anciennes versions de Tcl accèdent toujours à ces informations via ces variables globales.

Il est important de réaliser que, bien que la lecture de ces variables globales reste un moyen pris en charge pour accéder à ces valeurs d'options de retour, il est important de ne pas supposer que l'écriture dans ces variables globales définira correctement les options de retour correspondantes. Il a longtemps été souligné dans cette page de manuel qu'il est important d'appeler les procédures décrites ici plutôt que de définir directement errorInfo ou errorCode avec Tcl_ObjSetVar2.

Si la procédure Tcl_ResetResult est appelée, elle efface toutes les états de l'interpréteur associés à l'évaluation du script, y compris l'ensemble du dictionnaire des options de retour. En particulier, les options -errorinfo et -errorcode sont réinitialisées. Si une erreur s'était produite, l'appel Tcl_ResetResult effacera l'état d'erreur pour donner l'impression qu'aucune erreur ne s'est produite après tout. Les variables globales errorInfo et errorCode ne sont pas modifiées par Tcl_ResetResult, elles continuent donc de conserver un enregistrement des informations sur la dernière erreur vue dans un interpréteur.
