Tcl_Eval(3) Procédures de la bibliothèque Tcl Tcl_Eval(3)

NOM

Tcl_EvalObjEx, Tcl_EvalFile, Tcl_EvalObjv, Tcl_Eval, Tcl_EvalEx, Tcl_GlobalEval, Tcl_GlobalEvalObj, Tcl_VarEval, Tcl_VarEvalVA - exécuter des scripts Tcl

SYNOPSIS

#include <tcl.h>

int
Tcl_EvalObjEx(interp, objPtr, flags)

int
Tcl_EvalFile(interp, fileName)

int
Tcl_EvalObjv(interp, objc, objv, flags)

int
Tcl_Eval(interp, script)

int
Tcl_EvalEx(interp, script, numBytes, flags)

int
Tcl_GlobalEval(interp, script)

int
Tcl_GlobalEvalObj(interp, objPtr)

int
Tcl_VarEval(interp, part, part, ... (char *)NULL)

int
Tcl_VarEvalVA(interp, argList)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur dans lequel exécuter le script. Le résultat de l'interpréteur est modifié pour contenir le résultat ou le message d'erreur du script.
Tcl_Obj *objPtr (in)
Une valeur Tcl contenant le script à exécuter.
int flags (in)
Combinaison OU'ée de bits d'indicateurs qui spécifient des options supplémentaires. TCL_EVAL_GLOBAL et TCL_EVAL_DIRECT sont actuellement supportés.
const char *fileName (in)
Nom d'un fichier contenant un script Tcl.
int objc (in)
Le nombre de valeurs dans le tableau pointé par objv ; c'est aussi le nombre de mots dans la commande.
Tcl_Obj **objv (in)
Pointe vers un tableau de pointeurs vers des valeurs ; chaque valeur contient la valeur d'un seul mot dans la commande à exécuter.
int numBytes (in)
Le nombre d'octets dans script, sans inclure de caractère nul de terminaison. Si -1, alors tous les caractères jusqu'au premier octet nul sont utilisés.
const char *script (in)
Pointe vers le premier octet du script à exécuter (terminé par un nul et UTF-8).
const char *part (in)
Chaîne formant une partie d'un script Tcl.
va_list argList (in)
Une liste d'arguments qui doit avoir été initialisée avec va_start, et effacée avec va_end.

DESCRIPTION

Les procédures décrites ici sont appelées pour exécuter des scripts Tcl sous diverses formes. Tcl_EvalObjEx est la procédure principale et est utilisée par beaucoup d'autres. Elle exécute les commandes du script stocké dans objPtr jusqu'à ce qu'une erreur se produise ou que la fin du script soit atteinte. Si c'est la première fois que objPtr est exécuté, ses commandes sont compilées en instructions bytecode qui sont ensuite exécutées. Les bytecodes sont sauvegardés dans objPtr afin que l'étape de compilation puisse être ignorée si la valeur est évaluée à nouveau à l'avenir.

La valeur de retour de Tcl_EvalObjEx (et de toutes les autres procédures décrites ici) est un code de complétion Tcl avec l'une des valeurs TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK, ou TCL_CONTINUE, ou potentiellement une autre valeur entière provenant d'une extension. De plus, une valeur de résultat ou un message d'erreur est laissé dans le résultat de interp ; il peut être récupéré en utilisant Tcl_GetObjResult.

Tcl_EvalFile lit le fichier donné par fileName et évalue son contenu comme un script Tcl. Il retourne les mêmes informations que Tcl_EvalObjEx. Si le fichier n'a pas pu être lu, une erreur Tcl est retournée pour décrire pourquoi le fichier n'a pas pu être lu. Le caractère de fin de fichier pour les fichiers est “\32” (^Z) pour toutes les plateformes. Si vous avez besoin d'un “^Z” dans le code pour une comparaison de chaînes, vous pouvez utiliser “\032” ou “\u001a”, qui seront sûrement substitués par l'interpréteur Tcl en “^Z”.

Tcl_EvalObjv exécute une seule commande pré-analysée au lieu d'un script. Les arguments objc et objv contiennent les valeurs des mots pour la commande Tcl, un mot dans chaque valeur de objv. Tcl_EvalObjv évalue la commande et retourne un code de complétion et un résultat comme Tcl_EvalObjEx. L'appelant de Tcl_EvalObjv doit gérer le compteur de références des éléments de objv, s'assurant que les valeurs sont valides jusqu'à ce que Tcl_EvalObjv retourne.

Tcl_Eval est similaire à Tcl_EvalObjEx sauf que le script à exécuter est fourni sous forme de chaîne au lieu d'une valeur et qu'aucune compilation n'a lieu. La chaîne doit être une chaîne UTF-8 correcte telle que convertie par Tcl_ExternalToUtfDString ou Tcl_ExternalToUtf lorsqu'il est connu qu'elle pourrait contenir des caractères ASCII supérieurs dont les combinaisons possibles pourraient être un code spécial UTF-8. La chaîne est analysée et exécutée directement (en utilisant Tcl_EvalObjv) au lieu d'être compilée et d'exécuter les bytecodes. Dans les situations où l'on sait que le script ne sera jamais exécuté à nouveau, Tcl_Eval peut être plus rapide que Tcl_EvalObjEx.
Tcl_Eval retourne un code de complétion et un résultat comme Tcl_EvalObjEx. Note : pour la compatibilité avec les versions antérieures à Tcl 8.0, Tcl_Eval copie le résultat de la valeur dans interp vers interp->result (son utilisation est déconseillée) où il peut être accédé directement.
Cela rend Tcl_Eval un peu plus lent que Tcl_EvalEx, qui n'effectue pas la copie.

Tcl_EvalEx est une version étendue de Tcl_Eval qui prend des arguments supplémentaires numBytes et flags. Pour la raison d'efficacité donnée ci-dessus, Tcl_EvalEx est généralement préférée à Tcl_Eval.

Tcl_GlobalEval et Tcl_GlobalEvalObj sont des procédures plus anciennes qui sont maintenant dépréciées. Elles sont similaires à Tcl_EvalEx et Tcl_EvalObjEx sauf que le script est évalué dans l'espace de noms global et que son contexte de variables se compose uniquement de variables globales (il ignore les procédures Tcl actives). Ces fonctions sont équivalentes à l'utilisation de l'indicateur TCL_EVAL_GLOBAL (voir ci-dessous).

Tcl_VarEval prend un nombre quelconque d'arguments de chaîne de toute longueur, les concatène en une seule chaîne, puis appelle Tcl_Eval pour exécuter cette chaîne comme une commande Tcl. Elle retourne le résultat de la commande et modifie également interp->result de la même manière que Tcl_Eval. Le dernier argument de Tcl_VarEval doit être (char *)NULL pour indiquer la fin des arguments.

Tcl_VarEvalVA est identique à Tcl_VarEval sauf qu'au lieu de prendre un nombre variable d'arguments, elle prend une liste d'arguments. Tcl_VarEvalVA est maintenant dépréciée.

BITS DES INDICATEURS

Toute combinaison OU'ée des valeurs suivantes peut être utilisée pour l'argument flags des procédures telles que Tcl_EvalObjEx :

TCL_EVAL_DIRECT
Cet indicateur est uniquement utilisé par Tcl_EvalObjEx ; il est ignoré par les autres procédures. Si ce bit d'indicateur est défini, le script n'est pas compilé en bytecodes ; au lieu de cela, il est exécuté directement comme le fait Tcl_EvalEx. L'indicateur TCL_EVAL_DIRECT est utile dans les situations où le contenu d'une valeur va changer immédiatement, de sorte que les bytecodes ne seront pas réutilisés lors d'une exécution future. Dans ce cas, il est plus rapide d'exécuter le script directement.
TCL_EVAL_GLOBAL
Si cet indicateur est défini, le script est évalué dans l'espace de noms global au lieu de l'espace de noms actuel et son contexte de variables se compose uniquement de variables globales (il ignore les procédures Tcl actives).

DETAILS DIVERS

Pendant le traitement d'une commande Tcl, il est légal de faire des appels imbriqués pour évaluer d'autres commandes (c'est ainsi que les procédures et certaines structures de contrôle sont implémentées). Si un code autre que TCL_OK est retourné par une invocation imbriquée de Tcl_EvalObjEx, alors l'appelant doit normalement retourner immédiatement, passant ce même code de retour à son appelant, et ainsi de suite jusqu'à ce que l'application de niveau supérieur soit atteinte. Quelques commandes, comme for, vérifient certains codes de retour, comme TCL_BREAK et TCL_CONTINUE, et les traitent spécialement sans retourner.

Tcl_EvalObjEx suit le nombre d'invocations imbriquées de Tcl_EvalObjEx en cours pour interp. Si un code de TCL_RETURN, TCL_BREAK, ou TCL_CONTINUE est sur le point d'être retourné par l'invocation Tcl_EvalObjEx de plus haut niveau pour interp, il convertit le code de retour en TCL_ERROR et définit le résultat de interp sur un message d'erreur indiquant que la commande return, break

, ou la commande continue a été invoquée à un endroit inapproprié. Cela signifie que les applications de niveau supérieur ne devraient jamais voir un code de retour de Tcl_EvalObjEx autre que TCL_OK ou TCL_ERROR.
