Tcl_Interp *interp (entrée)
Utilisé pour le rapport d'erreurs et pour rechercher un canal enregistré en son sein.
const char *fileName (entrée)
Le nom d'un fichier local ou réseau.
const char *mode (entrée)
Spécifie comment le fichier doit être accédé. Peut avoir l'une des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (entrée)
Indicateurs de permission de style POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront appliquées au fichier créé.
int argc (entrée)
Le nombre d'éléments dans argv.
const char **argv (entrée)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans option de la commande Tcl exec.
int flags (entrée)
Spécifie la disposition des descripteurs stdio dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, stdin du premier enfant dans le pipe est le canal pipe, sinon il est identique à l'entrée standard du processus appelant ; il en va de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, le pipe peut rediriger les descripteurs stdio pour remplacer les descripteurs stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, de telles redirections provoquent une erreur.

Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, il s'agit d'un descripteur de fichier, pour Windows, il s'agit d'un HANDLE.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des périphériques et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie en mémoire tampon sur une variété de types de fichiers, de sockets et de périphériques. Le mécanisme de canaux est extensible aux nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée du manuel de Tcl_CreateChannel. Le mécanisme de canaux fournit un système de mise en mémoire tampon calqué sur les E/S standard d'Unix, et il permet également les E/S non bloquantes sur les canaux.

Les procédures décrites dans cette entrée de manuel constituent les APIs C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canaux et comment implémenter des pilotes de canaux pour de nouveaux types de canaux, voir l'entrée du manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

La procédure Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et crée un canal Tcl pour l'accès à ce fichier. Le canal retourné est de type ‐fichier‐ (a file channel). Les arguments mode et permissions sont utilisés pour spécifier comment le fichier est ouvert. Les valeurs possibles pour mode sont les mêmes que celles autorisées pour la commande Tcl open (par exemple, "r", "w", "a", "rb", "w+", etc.). Si le fichier n'existe pas et que le mode est tel qu'il doit être créé (par exemple, "w" ou "a"), il sera créé avec les permissions spécifiées par permissions. Les permissions sont un masque de bits POSIX tel que 0644, et elles sont masquées par la valeur umask du processus. Si une erreur se produit lors de l'ouverture du fichier, Tcl_OpenFileChannel retourne NULL et laisse un enregistrement d'erreur dans interp. Sinon, il retourne un handle de canal non nul.

TCL_OPENCOMMANDCHANNEL

La procédure Tcl_OpenCommandChannel crée un pipeline de processus en exécutant la commande spécifiée par argv. Les arguments pour la commande sont fournis dans argc et argv. La procédure crée un canal Tcl qui peut être utilisé pour lire la sortie standard du premier processus du pipeline et/ou écrire sur son entrée standard. Les arguments flags contrôlent la manière dont les flux standard (stdin, stdout, stderr) du nouveau processus sont mappés aux flux standard du processus parent. Voir la section ARGUMENTS pour une description des drapeaux.

TCL_MAKEFILECHANNEL

La procédure Tcl_MakeFileChannel prend un descripteur de fichier existant (un entier sur les systèmes Unix, un HANDLE de fichier sur Windows) et l'enveloppe dans un canal Tcl. Le descripteur de fichier est spécifié par handle. Le paramètre readOrWrite indique si le canal doit être ouvert en lecture (TCL_READABLE), en écriture (TCL_WRITABLE), ou les deux (TCL_READABLE | TCL_WRITABLE). Le canal retourné est de type ‐fichier‐. Si une erreur se produit, NULL est retourné.

Une fois qu'un canal a été créé avec Tcl_MakeFileChannel, il n'est pas automatiquement enregistré dans l'interpréteur. Il doit être enregistré explicitement en utilisant Tcl_RegisterChannel s'il doit être accessible par des commandes Tcl.

TCL_GETCHANNEL

La procédure Tcl_GetChannel renvoie un descripteur de canal pour le canal nommé channelName. Si modePtr n'est pas NULL, alors il doit pointer vers une variable entière qui recevra les modes de lecture/écriture du canal (une combinaison de TCL_READABLE et TCL_WRITABLE). Si Tcl_GetChannel est appelé avec modePtr non NULL, cela peut être utilisé pour tester si un canal est ouvert en lecture et/ou en écriture avant de tenter une opération. Si le canal n'existe pas ou s'il y a une erreur, NULL est retourné et un message d'erreur est placé dans l'interpréteur.

TCL_GETCHANNELNAMES

La procédure Tcl_GetChannelNames renvoie une liste de tous les noms de canaux actuellement enregistrés dans l'interpréteur interp. La liste est renvoyée sous forme d'un objet Tcl de type liste qui est défini dans interp sous le nom ::Tcl_ChannelNames. Si pattern est non NULL, alors seulement les noms de canaux qui correspondent au motif spécifié (selon Tcl_StringMatch) sont inclus dans la liste.

TCL_REGISTERCHANNEL

La procédure Tcl_RegisterChannel enregistre un canal channel dans l'interpréteur interp, le rendant accessible à partir du script Tcl en utilisant son nom. Le nom du canal est déterminé par le pilote de canal lorsque le canal est créé. Si le canal est déjà enregistré, son enregistrement précédent est retiré.

TCL_UNREGISTERCHANNEL

La procédure Tcl_UnregisterChannel retire un canal channel de l'interpréteur interp, le rendant inaccessible à partir du script Tcl. Cela n'a aucun effet sur le canal lui-même ; il peut toujours être utilisé par des appels de procédure C.

TCL_DETACHCHANNEL

La procédure Tcl_DetachChannel retire un canal channel de l'interpréteur interp, mais il est maintenant géré par l'appelant. Cela signifie qu'il ne sera pas automatiquement fermé lorsque l'interpréteur est détruit. Ceci est utile pour les canaux qui doivent survivre à la destruction de l'interpréteur, par exemple, les canaux utilisés par des threads ou des modules externes.

TCL_ISTANDARDCHANNEL

La procédure Tcl_IsStandardChannel renvoie vrai si le canal spécifié est l'un des canaux standards (stdin, stdout, stderr) de Tcl, faux sinon.

TCL_CLOSE

La procédure Tcl_Close ferme un canal channel. Cela libère toutes les ressources associées au canal, y compris les tampons de lecture et d'écriture. Si le canal a été ouvert en écriture, toutes les données en attente dans le tampon d'écriture sont vidées avant la fermeture du canal. Si une erreur se produit lors de la fermeture du canal, Tcl_Close renvoie -1 et laisse un enregistrement d'erreur dans interp. Sinon, elle renvoie 0.

TCL_READCHARS

La procédure Tcl_ReadChars lit jusqu'à charsToRead caractères du canal channel et les stocke dans la valeur Tcl pointée par readObjPtr. Si appendFlag est différent de zéro, les caractères lus sont ajoutés à la valeur existante de l'objet ; sinon, ils remplacent le contenu existant. La procédure essaiera de lire exactement charsToRead caractères, mais elle peut en lire moins si la fin du fichier est atteinte ou si le canal est temporairement bloqué en lecture (en mode non bloquant). Si une erreur se produit, Tcl_ReadChars renvoie -1 et laisse un enregistrement d'erreur dans interp. Sinon, elle renvoie le nombre de caractères lus.

TCL_READ

La procédure Tcl_Read lit jusqu'à bytesToRead octets du canal channel et les stocke dans le tampon d'octets spécifié par readBuf. La procédure essaiera de lire exactement bytesToRead octets, mais elle peut en lire moins si la fin du fichier est atteinte ou si le canal est temporairement bloqué en lecture (en mode non bloquant). Si une erreur se produit, Tcl_Read renvoie -1 et laisse un enregistrement d'erreur dans interp. Sinon, elle renvoie le nombre d'octets lus.

TCL_GETSOBJ

La procédure Tcl_GetsObj lit une ligne du canal channel, en incluant le caractère de fin de ligne s'il est présent. La ligne lue (sans le caractère de fin de ligne) est stockée dans la valeur Tcl pointée par lineObjPtr. La ligne lue est ajoutée à la valeur existante de l'objet. La procédure essaiera de lire jusqu'à ce qu'un caractère de fin de ligne soit rencontré, ou jusqu'à ce que la fin du fichier soit atteinte, ou que le canal soit temporairement bloqué en lecture (en mode non bloquant). Si une erreur se produit, Tcl_GetsObj renvoie -1 et laisse un enregistrement d'erreur dans interp. Sinon, elle renvoie le nombre de caractères lus (sans compter le caractère de fin de ligne). Si la fin du fichier est atteinte avant la lecture de tout caractère, la procédure renvoie 0.

TCL_GETS

La procédure Tcl_Gets lit une ligne du canal channel, en incluant le caractère de fin de ligne s'il est présent. La ligne lue est stockée dans la chaîne dynamique Tcl spécifiée par lineRead. La ligne lue est ajoutée à toute donnée déjà présente dans la chaîne dynamique. La procédure essaiera de lire jusqu'à ce qu'un caractère de fin de ligne soit rencontré, ou jusqu'à ce que la fin du fichier soit atteinte, ou que le canal soit temporairement bloqué en lecture (en mode non bloquant). Si une erreur se produit, Tcl_Gets renvoie -1 et laisse un enregistrement d'erreur dans interp. Sinon, elle renvoie le nombre de caractères lus. Si la fin du fichier est atteinte avant la lecture de tout caractère, la procédure renvoie 0.

TCL_UNGETS

La procédure Tcl_Ungets ajoute des données input de longueur inputLen à la mémoire tampon d'entrée du canal channel. Si addAtEnd est vrai, les données sont ajoutées à la fin de la mémoire tampon ; sinon, elles sont ajoutées au début. Cela peut être utilisé pour remettre des données dans le flux d'entrée, par exemple, après avoir lu un délimiteur qui n'était pas censé faire partie des données.

'TCL_WRITE'>TCL_WRITE

La procédure Tcl_WriteObj écrit le contenu de la valeur Tcl pointée par writeObjPtr sur le canal channel. La procédure essaiera d'écrire toutes les données, mais peut en écrire moins si le canal est plein (en mode non bloquant) ou si une erreur se produit. Si une erreur se produit, Tcl_WriteObj renvoie -1 et laisse un enregistrement d'erreur dans interp. Sinon, elle renvoie le nombre d'octets écrits.

La procédure Tcl_WriteChars écrit les caractères du tampon spécifié par charBuf sur le canal channel. Elle essaiera d'écrire exactement bytesToWrite octets. Si une erreur se produit, elle renvoie -1 et laisse un enregistrement d'erreur dans interp. Sinon, elle renvoie le nombre d'octets écrits.

La procédure Tcl_Write écrit les octets du tampon spécifié par byteBuf sur le canal channel. Elle essaiera d'écrire exactement bytesToWrite octets. Si une erreur se produit, elle renvoie -1 et laisse un enregistrement d'erreur dans interp. Sinon, elle renvoie le nombre d'octets écrits.

TCL_READRAW

Les procédures Tcl_ReadRaw et Tcl_WriteRaw sont similaires aux procédures Tcl_Read et Tcl_Write, respectivement, mais elles opèrent sur des données binaires brutes sans aucune conversion d'encodage ou de fin de ligne. Elles sont utiles pour travailler avec des canaux qui ne sont pas censés être interprétés comme du texte, tels que les sockets réseau ou les fichiers binaires.

TCL_EOF

La procédure Tcl_Eof renvoie vrai si la fin du fichier a été atteinte sur le canal channel, faux sinon. Notez que cela ne renvoie vrai que si une opération de lecture a tenté de lire au-delà de la fin du fichier.

TCL_FLUSH

La procédure Tcl_Flush force la vidange de toutes les données en attente dans le tampon d'écriture du canal channel vers le périphérique sous-jacent. Si une erreur se produit lors de la vidange, Tcl_Flush renvoie -1 et laisse un enregistrement d'erreur dans interp. Sinon, elle renvoie 0.

TCL_INPUTBLOCKED

La procédure Tcl_InputBlocked renvoie vrai si une opération de lecture sur le canal channel serait bloquée, faux sinon. Ceci est uniquement significatif pour les canaux ouverts en mode non bloquant.

TCL_INPUTBUFFERED

La procédure Tcl_InputBuffered renvoie le nombre d'octets qui sont actuellement dans le tampon d'entrée du canal channel et qui n'ont pas encore été lus par l'application.

TCL_OUTPUTBUFFERED

La procédure Tcl_OutputBuffered renvoie le nombre d'octets qui sont actuellement dans le tampon de sortie du canal channel et qui n'ont pas encore été écrits sur le périphérique sous-jacent.

TCL_SEEK

La procédure Tcl_Seek change le point d'accès courant du canal channel. Le nouvel emplacement est calculé en ajoutant offset octets au point de référence spécifié par seekMode. Les valeurs possibles pour seekMode sont SEEK_SET (début du canal), SEEK_CUR (position courante) et SEEK_END (fin du canal). offset peut être positif ou négatif. La procédure renvoie la nouvelle position du point d'accès en octets à partir du début du canal, ou -1 si une erreur se produit.

TCL_TELL

La procédure Tcl_Tell renvoie la position actuelle du point d'accès dans le canal channel, mesurée en octets à partir du début du canal. Si une erreur se produit, elle renvoie -1.

TCL_TRUNCATECHANNEL

La procédure Tcl_TruncateChannel tronque le fichier associé au canal channel à la longueur spécifiée par length. La longueur doit être non négative. Si une erreur se produit, elle renvoie -1 et laisse un enregistrement d'erreur dans interp. Sinon, elle renvoie 0.

TCL_GETCHANNELOPTION

La procédure Tcl_GetChannelOption récupère la valeur de l'option spécifiée par optionName pour le canal channel. La valeur est stockée dans la chaîne dynamique optionValue, qui doit avoir été initialisée par l'appelant. Si l'option n'existe pas ou si une erreur se produit, -1 est renvoyé et un enregistrement d'erreur est laissé dans interp. Sinon, 0 est renvoyé.

Les options disponibles sont les mêmes que celles acceptées par la commande Tcl fconfigure, y compris -blocking, -buffering, -encoding, -translation, et -eof.

TCL_SETCHANNELOPTION

La procédure Tcl_SetChannelOption définit la valeur de l'option spécifiée par optionName pour le canal channel à la nouvelle valeur newValue. Si une erreur se produit, -1 est renvoyé et un enregistrement d'erreur est laissé dans interp. Sinon, 0 est renvoyé.

Les options disponibles sont les mêmes que celles acceptées par la commande Tcl fconfigure, y compris -blocking, -buffering, -encoding, -translation, et -eof.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et renvoie un descripteur de canal qui peut être utilisé pour effectuer des entrées et sorties sur le fichier. Cette API est modélisée d'après la procédure fopen de la bibliothèque d'E/S standard d'Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur la valeur Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel chaque fois que possible.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr, a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Elle crée une séquence de sous-processus spécifiés par les arguments argv et argc et renvoie un canal qui peut être utilisé pour communiquer avec ces sous-processus. L'argument flags indique quel type de communication existera avec le pipeline de commandes.

Si le drapeau TCL_STDIN est activé, l'entrée standard du premier sous-processus sera liée au canal : écrire dans le canal fournira des données au sous-processus. Si TCL_STDIN n'est pas activé, l'entrée standard du premier sous-processus sera la même que l'entrée standard de cette application. Si TCL_STDOUT est activé, la sortie standard du dernier sous-processus pourra être lue à partir du canal ; sinon, elle sera envoyée à la sortie standard de cette application. Si TCL_STDERR est activé, la sortie d'erreur standard de tous les sous-processus sera renvoyée au canal et provoquera une erreur lors de la fermeture du canal ; sinon, elle sera envoyée à la sortie d'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas activé, alors argc et argv peuvent rediriger les descripteurs stdio pour outrepasser TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est activé, alors c'est une erreur que argc et argv outrepassent les canaux stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr, a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un descripteur de fichier existant et spécifique à la plateforme. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr, a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel renvoie un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur Tcl dans interp. Si un canal portant ce nom n'est pas enregistré dans cet interpréteur, la procédure renvoie NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms en fonction du pattern. Si pattern est NULL, alors aucun filtrage ne sera effectué. La valeur de retour est TCL_OK si aucune erreur ne s'est produite lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur pourront faire référence au canal dans les opérations d'entrée ou de sortie en utilisant le nom donné dans l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur Tcl peut appeler Tcl_RegisterChannel avec interp à NULL, pour indiquer qu'il souhaite conserver une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et ne sera fermé que lorsque le nombre correspondant d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code exécuté en dehors de tout interpréteur de conserver en toute sécurité une référence à un canal qui est également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code gérant les canaux standard. Si aucun canal standard n'a été initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un traité général sur les canaux standard et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel supprime un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Si cette opération a supprimé le dernier enregistrement du canal dans un interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur Tcl peut appeler Tcl_UnregisterChannel avec interp à NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera alors fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel sauf qu'elle fermera également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel supprime un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Au-delà de cela, cette commande n'a aucun autre effet. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin), et renverra TCL_ERROR si elle est appelée avec l'un de ces canaux.

Le code non associé à un interpréteur Tcl peut appeler Tcl_DetachChannel avec interp à NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. Si c'est le cas, elle renvoie 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou autrement valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lorsque Tcl_Close est appelé. La sortie mise en mémoire tampon est vidée vers le périphérique de sortie du canal avant la destruction du canal, et toute entrée mise en mémoire tampon est rejetée. S'il s'agit d'un canal bloquant, l'appel ne renvoie pas tant que toutes les données mises en mémoire tampon n'ont pas été envoyées avec succès au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a une sortie mise en mémoire tampon qui ne peut pas être écrite sans bloquer, l'appel renvoie immédiatement ; la sortie est vidée en arrière-plan et le canal sera fermé une fois que toutes les données mises en mémoire tampon auront été sorties. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close renvoie TCL_OK. Si une erreur se produit, Tcl_Close renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré en utilisant Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a déjà été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez plutôt utiliser Tcl_UnregisterChannel, qui appellera internement Tcl_Close lorsque tous les appels à Tcl_RegisterChannel auront été égalés par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, convertit les octets en UTF-8 en fonction de l'encodage du canal et stocke les données produites dans la représentation chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, les convertissant en UTF-8 en se basant sur l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée soit rencontrée. Si l'encodage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception des caractères de fin de ligne terminaux, sont ajoutés à la représentation sous forme de chaîne de lineObjPtr. Les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_GetsObj renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj renvoie également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est renvoyé, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité d'entrée.

Tcl_Gets est identique à Tcl_GetsObj, sauf que les caractères résultants sont ajoutés à la chaîne dynamique fournie par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, soit à la tête, soit à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si channel a un indicateur EOF "collant" (sticky), aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets renvoie inputLen ou -1 si une erreur se produit.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données de caractères à charBuf. Les caractères UTF-8 du tampon sont convertis vers l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par un caractère nul et il sort tout jusqu'au nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître sur le périphérique de sortie immédiatement, en raison de la mise en tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering du canal sur none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering du canal sur le mode line.

La valeur de retour de Tcl_WriteChars est le nombre d'octets qui ont été acceptés pour la sortie vers le canal. Il s'agit soit d'un nombre supérieur à zéro pour indiquer le succès, soit de -1 pour indiquer qu'une erreur s'est produite. Si une erreur se produit, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme, conformément à l'option -translation du canal. Ceci est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars, sauf qu'il accepte une valeur Tcl dont le contenu sera sorti vers le canal. Les caractères UTF-8 de la représentation de chaîne de writeObjPtr sont convertis vers l'encodage du canal et mis en file d'attente pour la sortie vers channel. Par optimisation des performances, lors de l'écriture dans un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets de la représentation interne de writeObjPtr en tant que valeur de tableau d'octets sont écrits dans le canal. La représentation de tableau d'octets de la valeur sera construite si nécessaire. De cette manière, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de conversion depuis ou vers UTF-8.

Tcl_Write est similaire à Tcl_WriteChars, sauf qu'il n'effectue pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour des raisons de compatibilité ascendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par un caractère nul et il sort tout jusqu'au nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée dans le canal le plus haut dans la pile dont le canal fourni fait partie, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation vers le canal inférieur.

TCL_FLUSH

Tcl_Flush force la sortie de toutes les données tamponnées pour channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données tamponnées n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal est non bloquant ; il démarre une purge en arrière-plan qui écrira les données tamponnées dans le canal éventuellement, aussi vite que le canal pourra les absorber.

La valeur de retour est normalement TCL_OK. Si une erreur se produit, Tcl_Flush renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les lectures ou écritures de données ultérieures auront lieu. La sortie tamponnée est vidée vers le canal et l'entrée tamponnée est ignorée avant l'opération de recherche.

Tcl_Seek renvoie normalement le nouveau point d'accès. Si une erreur se produit, Tcl_Seek renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut avoir été déplacé ou non.

TCL_TELL

Tcl_Tell renvoie le point d'accès actuel pour un canal. La valeur retournée est -1 si le canal ne supporte pas la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent de channel à une longueur donnée de length octets. Il renvoie TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et de leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, c'est le nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue, en utilisant

NOM

Tcl_DStringAppendElement séries d'appels à Tcl_DStringAppendElement. Les diverses options préexistantes et leurs valeurs possibles sont décrites dans l'entrée du manuel de la commande Tcl fconfigure. D'autres options peuvent être ajoutées par chaque type de canal. Ces options spécifiques au type de canal sont décrites dans l'entrée du manuel de la commande Tcl qui crée un canal de ce type ; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans l'entrée du manuel de la commande Tcl socket. La procédure retourne normalement TCL_OK. Si une erreur se produit, elle retourne TCL_ERROR et appelle Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit une nouvelle valeur newValue pour une option optionName sur channel. La procédure retourne normalement TCL_OK. Si une erreur se produit, elle retourne TCL_ERROR ; en outre, si interp n'est pas NULL, Tcl_SetChannelOption laisse un message d'erreur dans le résultat de l'interpréteur.

TCL_EOF

Tcl_Eof retourne une valeur non nulle si channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked retourne une valeur non nulle si channel est en mode non bloquant et que la dernière opération d'entrée a retourné moins de données que demandé car il y avait une quantité insuffisante de données disponibles. L'appel retourne toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered retourne le nombre d'octets d'entrée actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en lecture, cette fonction retourne toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered retourne le nombre d'octets de sortie actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en écriture, cette fonction retourne toujours zéro.

PROBLÈMES DE PLATEFORME

Les descripteurs retournés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que retourné par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel, ou Tcl_MakeFileChannel. D'autres types de canaux peuvent retourner un type de descripteur différent sur les plateformes Windows.
