ARGUMENTS

Tcl_Interp *interp (en entrée)
Utilisé pour le reporting d'erreurs et pour rechercher un canal enregistré dans celui-ci.
const char *fileName (en entrée)
Le nom d'un fichier local ou réseau.
const char *mode (en entrée)
Spécifie comment le fichier doit être accédé. Peut avoir n'importe laquelle des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (en entrée)
Indicateurs de permissions de style POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront définies sur le fichier créé.
int argc (en entrée)
Le nombre d'éléments dans argv.
const char **argv (en entrée)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans commutateur de la commande Tcl exec.
int flags (en entrée)
Spécifie la disposition des descripteurs stdio dans le pipeline : combinaison en OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, l'entrée standard du premier processus enfant du pipeline est le canal de tuyau, sinon elle est la même que l'entrée standard du processus appelant ; de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, alors le tuyau peut rediriger les descripteurs stdio pour outre-passer les descripteurs stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, de telles redirections provoquent une erreur.
ClientData handle (en entrée)
Descripteur spécifique au système d'exploitation pour l'E/S vers un fichier. Pour Unix, c'est un descripteur de fichier, pour Windows, c'est un HANDLE.
int readOrWrite (en entrée)
Combinaison en OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (en entrée)
Le nom du canal.
int *modePtr (en sortie)
Pointe vers une variable entière qui recevra une combinaison en OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (en entrée)
Le modèle à faire correspondre, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (en entrée)
Un canal Tcl pour l'entrée ou la sortie. Doit avoir été la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (en entrée/sortie)
Un pointeur vers une valeur Tcl dans laquelle stocker les caractères lus du canal.
int charsToRead (en entrée)
Le nombre de caractères à lire du canal. Si l'encodage du canal est binary, cela équivaut au nombre d'octets à lire du canal.
int appendFlag (en entrée)
Si non nul, les données lues du canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (en sortie)
Un tampon dans lequel stocker les octets lus du canal.
int bytesToRead (en entrée)
Le nombre d'octets à lire du canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (en entrée/sortie)
Un pointeur vers une valeur Tcl dans laquelle stocker la ligne lue du canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (en entrée/sortie)
Un pointeur vers une chaîne dynamique Tcl dans laquelle stocker la ligne lue du canal. Doit avoir été initialisée par l'appelant. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne dynamique.
const char *input (en entrée)
L'entrée à ajouter à un tampon de canal.
int inputLen (en entrée)
Longueur de l'entrée.
int addAtEnd (en entrée)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon de canal.
Tcl_Obj *writeObjPtr (en entrée)
Un pointeur vers une valeur Tcl dont le contenu sera envoyé en sortie vers le canal.
const char *charBuf (en entrée)
Un tampon contenant les caractères à envoyer en sortie vers le canal.
const char *byteBuf (en entrée)
Un tampon contenant les octets à envoyer en sortie vers le canal.
int bytesToWrite (en entrée)
Le nombre d'octets à consommer de charBuf ou byteBuf et à envoyer en sortie vers le canal.
Tcl_WideInt offset (en entrée)
Distance de déplacement du point d'accès dans le canal auquel la prochaine opération d'entrée ou de sortie sera appliquée, mesurée en octets à partir de la position donnée par seekMode. Peut être positif ou négatif.
int seekMode (en entrée)
Point de référence pour le déplacement ; utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs légales sont SEEK_SET, SEEK_CUR, et SEEK_END.
Tcl_WideInt length (en entrée)
La longueur (non négative) à laquelle tronquer le canal.
const char *optionName (en entrée)
Le nom d'une option applicable à ce canal, comme -blocking. Peut avoir n'importe laquelle des valeurs acceptées par la commande fconfigure.
Tcl_DString *optionValue (en entrée)
Emplacement pour stocker la valeur d'une option ou une liste de toutes les options et leurs valeurs. Doit avoir été initialisé par l'appelant.
const char *newValue (en entrée)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des périphériques et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie en tampon sur une variété de types de fichiers, de sockets et de périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée du manuel pour Tcl_CreateChannel. Le mécanisme de canaux fournit un schéma de mise en tampon calqué sur les E/S standard d'Unix, et il permet également les E/S non bloquantes sur les canaux.

Les procédures décrites dans cette entrée de manuel comprennent les API C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canaux et de la manière d'implémenter des pilotes de canaux pour de nouveaux types de canaux, consultez l'entrée du manuel pour Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Ouvre un fichier nommé fileName et renvoie un canal Tcl qui peut être utilisé pour accéder au fichier. Le fichier est ouvert en utilisant le mode spécifié par mode et les permissions spécifiées par permissions.

Mode doit être une chaîne de caractères qui spécifie comment le fichier doit être ouvert. Les valeurs possibles pour mode sont les mêmes que celles autorisées pour l'argument mode de la commande Tcl open.

Permissions est un entier qui spécifie les permissions pour le nouveau fichier s'il est créé. Si le fichier est ouvert en lecture seule ou en écriture seule, les permissions sont ignorées. Les permissions sont spécifiées dans le même format que les octal bits des permissions POSIX, par exemple, 0644.

Si une erreur se produit, Tcl_OpenFileChannel renvoie TCL_BAD_CHANNEL et l'interpréteur interp contient une chaîne d'erreur décrivant l'erreur. Sinon, il renvoie un handle de canal valide.

TCL_OPENCOMMANDCHANNEL

Crée un pipeline de processus et renvoie un canal Tcl qui représente l'entrée standard ou la sortie standard (ou les deux) du premier processus dans le pipeline. Le pipeline est construit en exécutant la commande spécifiée par argc et argv. La signification de argc et argv est la même que pour la commande Tcl exec.

Les bits de flags spécifient quelle entrée/sortie standard du pipeline doit être connectée au canal Tcl. Si TCL_STDIN est défini, l'entrée standard du premier processus est connectée au canal Tcl. Si TCL_STDOUT est défini, la sortie standard du dernier processus est connectée au canal Tcl. Si TCL_STDERR est défini, la sortie d'erreur standard du dernier processus est connectée au canal Tcl. Si aucun de ces bits n'est défini, alors le canal Tcl est connecté à la sortie standard du premier processus.

Si TCL_ENFORCE_MODE est défini dans flags, alors toute tentative de redirection des descripteurs stdio pour des canaux déjà ouverts par l'interpréteur provoquera une erreur. Sinon, de telles redirections sont autorisées.

Si une erreur se produit, Tcl_OpenCommandChannel renvoie TCL_BAD_CHANNEL et l'interpréteur interp contient une chaîne d'erreur décrivant l'erreur. Sinon, il renvoie un handle de canal valide.

TCL_MAKEFILECHANNEL

Crée un nouveau canal Tcl à partir d'un descripteur de fichier existant (ou d'un autre handle d'E/S système). handle est le descripteur de fichier ou le handle d'E/S du système d'exploitation. readOrWrite est une combinaison en OR des drapeaux TCL_READABLE et TCL_WRITABLE indiquant si le canal doit être ouvert en lecture ou en écriture.

Si une erreur se produit, Tcl_MakeFileChannel renvoie TCL_BAD_CHANNEL et l'interpréteur interp contient une chaîne d'erreur décrivant l'erreur. Sinon, il renvoie un handle de canal valide.

TCL_GETCHANNEL

Retourne le canal Tcl nommé channelName. Si modePtr n'est pas NULL, alors la variable entière à laquelle il pointe recevra une combinaison en OR des drapeaux TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.

Si le canal n'existe pas ou si une erreur se produit, Tcl_GetChannel renvoie TCL_BAD_CHANNEL et l'interpréteur interp contient une chaîne d'erreur décrivant l'erreur. Sinon, il renvoie le handle de canal.

TCL_GETCHANNELNAMES

Renvoie une liste de tous les noms de canaux actuellement enregistrés dans l'interpréteur interp. Les noms de canaux sont ajoutés comme éléments d'un objet liste qui est stocké dans l'emplacement d'interprète de nom de résultat (result name-space interpreter location). La commande renvoie TCL_OK en cas de succès, ou TCL_ERROR si une erreur se produit.

TCL_GETCHANNELNAMESEX

Renvoie une liste de tous les noms de canaux actuellement enregistrés dans l'interpréteur interp qui correspondent au modèle pattern. Le modèle est géré par Tcl_StringMatch. Si pattern est NULL, alors tous les noms de canaux sont renvoyés.

Les noms de canaux sont ajoutés comme éléments d'un objet liste qui est stocké dans l'emplacement d'interprète de nom de résultat. La commande renvoie TCL_OK en cas de succès, ou TCL_ERROR si une erreur se produit.

TCL_REGISTERCHANNEL

Enregistre le canal channel dans l'interpréteur interp. Une fois enregistré, le canal peut être référencé par son nom de canal, et il sera fermé lorsque l'interpréteur sera détruit.

TCL_UNREGISTERCHANNEL

Désenregistre le canal channel de l'interpréteur interp. Si le canal est déjà fermé, cela n'a aucun effet. La fonction renvoie TCL_OK en cas de succès, ou TCL_ERROR si le canal n'est pas enregistré dans l'interpréteur.

TCL_DETACHCHANNEL

Détache le canal channel de l'interpréteur interp. Une fois détaché, le canal ne sera plus fermé lorsque l'interpréteur sera détruit. Il incombe au programme appelant de fermer le canal.

La fonction renvoie TCL_OK en cas de succès, ou TCL_ERROR si le canal n'est pas enregistré dans l'interpréteur.

TCL_ISSTANDARDCHANNEL

Renvoie 1 si le canal channel est l'un des canaux standard (stdin, stdout, stderr), 0 sinon.

TCL_CLOSE

Ferme le canal channel. Toutes les opérations d'E/S sur le canal cessent d'être valides après l'appel à cette fonction. Si le canal est un canal d'entrée, toutes les données en attente dans le tampon d'entrée sont perdues. Si le canal est un canal de sortie, toutes les données en attente dans le tampon de sortie sont vidées vers le système avant que le canal ne soit fermé.

Si une erreur se produit lors de la fermeture du canal, la fonction renvoie TCL_ERROR et l'interpréteur interp contient une chaîne d'erreur décrivant l'erreur. Sinon, il renvoie TCL_OK.

TCL_READCHARS

Lit jusqu'à charsToRead caractères du canal channel et les stocke dans l'objet Tcl pointé par readObjPtr. Si appendFlag est non nul, les caractères lus sont ajoutés au contenu existant de l'objet Tcl. Sinon, l'objet Tcl est réinitialisé pour contenir uniquement les caractères lus.

Si une erreur se produit ou si la fin du fichier est atteinte avant la lecture du nombre de caractères spécifié, la fonction renvoie le nombre réel de caractères lus. Si une erreur se produit, la valeur renvoyée peut être négative, et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Si la fin du fichier est atteinte, la valeur renvoyée sera de 0 si aucun caractère n'a été lu, ou le nombre de caractères lus si certains caractères ont été lus avant la fin du fichier.

TCL_READ

Lit jusqu'à bytesToRead octets du canal channel et les stocke dans le tampon readBuf. Le tampon readBuf doit être suffisamment grand pour contenir bytesToRead octets.

Si une erreur se produit ou si la fin du fichier est atteinte avant la lecture du nombre d'octets spécifié, la fonction renvoie le nombre réel d'octets lus. Si une erreur se produit, la valeur renvoyée peut être négative, et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Si la fin du fichier est atteinte, la valeur renvoyée sera de 0 si aucun octet n'a été lu, ou le nombre d'octets lus si certains octets ont été lus avant la fin du fichier.

TCL_GETSOBJ

Lit une ligne du canal channel et la stocke dans l'objet Tcl pointé par lineObjPtr. Une ligne est définie comme une séquence de caractères se terminant par un caractère de saut de ligne ('\n'). Si la fin du fichier est atteinte avant la lecture d'un caractère de saut de ligne, la ligne lue sera tout le reste du fichier. Les caractères de saut de ligne sont consommés mais non inclus dans l'objet Tcl.

Si une erreur se produit, la fonction renvoie TCL_ERROR et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Si la fin du fichier est atteinte, la fonction renvoie TCL_EOF. Sinon, elle renvoie TCL_OK.

TCL_GETS

Lit une ligne du canal channel et la stocke dans la chaîne dynamique lineRead. Une ligne est définie comme une séquence de caractères se terminant par un caractère de saut de ligne ('\n'). Si la fin du fichier est atteinte avant la lecture d'un caractère de saut de ligne, la ligne lue sera tout le reste du fichier. Les caractères de saut de ligne sont consommés mais non ajoutés à la chaîne dynamique.

Si une erreur se produit, la fonction renvoie TCL_ERROR et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Si la fin du fichier est atteinte, la fonction renvoie TCL_EOF. Sinon, elle renvoie TCL_OK.

TCL_UNGETS

Ajoute la chaîne input de longueur inputLen au début ou à la fin du tampon d'entrée du canal channel, selon la valeur de addAtEnd. Si addAtEnd est vrai, l'entrée est ajoutée à la fin du tampon. Sinon, elle est ajoutée au début.

Si une erreur se produit, la fonction renvoie TCL_ERROR et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Sinon, elle renvoie TCL_OK.

TCL_WRITEOPT

Écrit le contenu de l'objet Tcl pointé par writeObjPtr dans le canal channel. Les données sont écrites sans mise en tampon.

Si une erreur se produit, la fonction renvoie TCL_ERROR et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Sinon, elle renvoie TCL_OK.

TCL_WRITECHARS

Écrit les caractères de charBuf dans le canal channel. Le nombre d'octets écrits est spécifié par bytesToWrite. Les données sont écrites sans mise en tampon.

Si une erreur se produit, la fonction renvoie TCL_ERROR et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Sinon, elle renvoie TCL_OK.

TCL_WRITE

Écrit les octets de byteBuf dans le canal channel. Le nombre d'octets écrits est spécifié par bytesToWrite. Les données sont écrites sans mise en tampon.

Si une erreur se produit, la fonction renvoie TCL_ERROR et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Sinon, elle renvoie TCL_OK.

TCL_READRAW

Lit jusqu'à bytesToRead octets du canal channel et les stocke dans le tampon readBuf. Le tampon readBuf doit être suffisamment grand pour contenir bytesToRead octets. Contrairement à Tcl_Read, cette procédure ne tente pas de décoder les données. Elle est utile pour lire des données binaires.

Si une erreur se produit ou si la fin du fichier est atteinte avant la lecture du nombre d'octets spécifié, la fonction renvoie le nombre réel d'octets lus. Si une erreur se produit, la valeur renvoyée peut être négative, et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Si la fin du fichier est atteinte, la valeur renvoyée sera de 0 si aucun octet n'a été lu, ou le nombre d'octets lus si certains octets ont été lus avant la fin du fichier.

TCL_WRITERAW

Écrit les octets de byteBuf dans le canal channel. Le nombre d'octets écrits est spécifié par bytesToWrite. Contrairement à Tcl_Write, cette procédure ne tente pas d'encoder les données. Elle est utile pour écrire des données binaires.

Si une erreur se produit, la fonction renvoie TCL_ERROR et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Sinon, elle renvoie TCL_OK.

TCL_EOF

Renvoie 1 si la fin du fichier a été atteinte sur le canal channel, 0 sinon.

TCL_FLUSH

Vide toutes les données mises en tampon dans le canal channel vers le système sous-jacent. Si une erreur se produit, la fonction renvoie TCL_ERROR et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Sinon, elle renvoie TCL_OK.

TCL_INPUTBLOCKED

Renvoie 1 si une opération de lecture sur le canal channel bloquerait l'exécution, 0 sinon. Cela est utile pour implémenter des E/S non bloquantes.

TCL_INPUTBUFFERED

Renvoie le nombre d'octets actuellement disponibles dans le tampon d'entrée du canal channel.

TCL_OUTPUTBUFFERED

Renvoie le nombre d'octets actuellement en attente dans le tampon de sortie du canal channel.

TCL_SEEK

Définit le point d'accès courant dans le canal channel à une nouvelle position. La nouvelle position est calculée en ajoutant offset à la position indiquée par seekMode. Les valeurs de seekMode sont : SEEK_SET (début du fichier), SEEK_CUR (position courante) et SEEK_END (fin du fichier).

Si une erreur se produit, la fonction renvoie -1 et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Sinon, elle renvoie la nouvelle position courante du canal en octets.

TCL_TELL

Renvoie la position courante du point d'accès dans le canal channel, mesurée en octets à partir du début du canal.

Si une erreur se produit, la fonction renvoie -1 et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Sinon, elle renvoie la position courante.

TCL_TRUNCATECHANNEL

Tronque le canal channel à la longueur spécifiée par length. Si la longueur spécifiée est supérieure à la longueur actuelle du canal, le canal est étend avec des octets nuls. Cette opération n'est valide que sur les canaux qui supportent le déplacement (seek).

Si une erreur se produit, la fonction renvoie TCL_ERROR et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Sinon, elle renvoie TCL_OK.

TCL_GETCHANNELOPTION

Récupère la valeur de l'option optionName pour le canal channel. La valeur est stockée dans la chaîne dynamique pointée par optionValue. L'ensemble des noms d'options valides est le même que celui accepté par la commande Tcl fconfigure.

Si une erreur se produit, la fonction renvoie TCL_ERROR et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Sinon, elle renvoie TCL_OK.

TCL_SETCHANNELOPTION

Définit la valeur de l'option optionName pour le canal channel à newValue. L'ensemble des noms d'options valides est le même que celui accepté par la commande Tcl fconfigure.

Si une erreur se produit, la fonction renvoie TCL_ERROR et l'interpréteur interp contiendra une chaîne d'erreur décrivant l'erreur. Sinon, elle renvoie TCL_OK.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et renvoie un handle de canal qui peut être utilisé pour lire et écrire dans le fichier. Cette API est calquée sur la fonction fopen de la bibliothèque d'E/S standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles de la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être obtenu avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur les valeurs Tcl_FSOpenFileChannel devrait être utilisée de préférence à Tcl_OpenFileChannel dans la mesure du possible.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, il faut utiliser Tcl_RegisterChannel, décrit plus loin. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'affecte également comme substitut des canaux standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface au niveau C des fonctions des commandes exec et open. Elle crée une séquence de processus subsidiaires spécifiée par les arguments argv et argc et renvoie un canal qui peut être utilisé pour communiquer avec ces processus subsidiaires. L'argument flags indique le type de communication à établir avec la séquence de commandes.

Si le bit TCL_STDIN est défini, l'entrée standard du premier processus subsidiaire est liée au canal : écrire dans le canal fournit l'entrée au processus subsidiaire. Si le bit TCL_STDIN n'est pas défini, l'entrée standard du premier processus subsidiaire sera la même que l'entrée standard de cette application. Si le bit TCL_STDOUT est défini, la sortie standard de la dernière sous-séquence peut être lue depuis le canal ; sinon, elle est envoyée à la sortie standard de cette application. Si le bit TCL_STDERR est défini, la sortie d'erreur standard de tous les processus subsidiaires est renvoyée au canal et génère une erreur lors de la fermeture du canal ; sinon, elle est envoyée à la sortie d'erreur standard de cette application. Si le bit TCL_ENFORCE_MODE n'est pas défini, les arguments argc et argv peuvent rediriger les handles standard pour outrepasser TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, il s'agit d'une erreur si argc et argv tentent d'outrepasser les canaux standard pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être obtenu avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de interp. interp ne peut pas être NULL.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, il faut utiliser Tcl_RegisterChannel, décrit plus loin. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'affecte également comme substitut des canaux standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un handle de fichier existant et spécifique à la plateforme. Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, il faut utiliser Tcl_RegisterChannel, décrit plus loin. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'affecte également comme substitut des canaux standard.

TCL_GETCHANNEL

Tcl_GetChannel renvoie un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur dans interp. Si le canal portant ce nom n'est pas trouvé dans l'interpréteur, il renvoie NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtre ces noms en fonction du pattern. Si pattern est NULL, aucun filtrage n'est effectué. La valeur de retour est TCL_OK si aucune erreur ne s'est produite lors de l'écriture dans le résultat, sinon TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à la collection de canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur pourront faire référence au canal par le nom donné lors de l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'utilisateur doit éviter d'appeler Tcl_Close pour le canal ; le canal est automatiquement fermé lorsqu'il est désenregistré de l'interpréteur.

Le code s'exécutant en dehors de tout interpréteur peut appeler Tcl_RegisterChannel avec interp comme NULL, pour indiquer qu'il souhaite conserver une référence à ce canal. Après cela, le canal peut être enregistré dans un interpréteur Tcl et ne sera fermé que lorsque les appels correspondants à Tcl_UnregisterChannel auront été effectués. Cela permet au code exécuté en dehors de tout interpréteur de conserver une référence sûre à un canal qui est également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code qui gère les canaux standard. Si aucun canal standard n'est initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un aperçu des canaux standard et du comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel retire un canal de la collection de canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Si cette opération supprime le dernier enregistrement du canal dans un quelconque interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur quelconque peut appeler Tcl_UnregisterChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne conserve plus de référence à ce canal. Si c'est la dernière référence au canal, il est fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel, sauf qu'il ferme également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel retire un canal de la collection de canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Au-delà de cela, cette commande n'a aucun autre effet. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin), et renvoie TCL_ERROR si on lui passe l'un de ces canaux.

Le code non associé à un interpréteur quelconque peut appeler Tcl_DetachChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne conserve plus de référence à ce canal. Si c'est la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il n'est pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel vérifie si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. Si c'est le cas, il renvoie 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un quelconque interpréteur lorsque Tcl_Close est appelé. Le tampon de sortie est écrit sur le périphérique de sortie du canal avant sa destruction, et tout tampon d'entrée est rejeté. S'il s'agit d'un canal bloquant, l'appel ne renvoie pas tant que toutes les données mises en tampon n'ont pas été correctement envoyées au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a des données mises en tampon qui ne peuvent pas être écrites sans blocage, l'appel renvoie immédiatement ; les données sont écrites en arrière-plan et le canal est fermé une fois que toutes les données mises en tampon ont été écrites. Dans ce cas, les erreurs lors de l'écriture ne sont pas signalées.

Si le canal a été fermé correctement, Tcl_Close renvoie TCL_OK. Si une erreur se produit, Tcl_Close renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être obtenu avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de interp.

Remarque : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré avec Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a été donné comme chan dans un appel à Tcl_RegisterChannel, vous devez utiliser Tcl_UnregisterChannel, qui appelle Tcl_Close en interne lorsque tous les appels à Tcl_RegisterChannel ont été compensés par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS AND TCL_READ

Tcl_ReadChars consomme des octets du channel, les convertit en UTF-8 selon l'encodage du canal et stocke les données produites dans la représentation de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être obtenu avec Tcl_GetErrno.

L'affectation de chars

TCL_READCHARS, TCL_READOBJ, ET AL. TCL_READ, ET AL.

Tcl_ReadChars lit tous les caractères du canal qui sont actuellement disponibles, jusqu'à un maximum de charsToRead caractères. Le résultat est stocké dans l'objet Tcl référencé par readObjPtr. Lire moins que le nombre de caractères demandés est possible. La valeur de retour est le nombre de caractères effectivement lus. La valeur à lire peut être -1, auquel cas Tcl_ReadChars lit tous les caractères actuellement disponibles (mode non bloquant) ou tout jusqu'à la fin du fichier (mode bloquant).

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé étaient disponibles. Ceci est appelé une lecture courte (short read). En mode bloquant, cela ne peut arriver qu'en fin de fichier. En mode non bloquant, une lecture courte peut également se produire s'il n'y a pas assez d'entrée actuellement disponible : Tcl_ReadChars renvoie un compte court plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour savoir laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les diverses représentations de fin de ligne en la représentation interne canonique \n selon le mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les divers modes spécifiques à la plateforme sont décrits dans l'entrée du manuel de la commande Tcl fconfigure.

Par optimisation de performance, lors de la lecture à partir d'un canal avec l'encodage binary, les octets ne sont pas convertis en UTF-8 lors de leur lecture. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr en tant que valeur de tableau d'octets. La représentation textuelle de cette valeur ne sera construite que si elle est nécessaire (par exemple, suite à un appel à Tcl_GetStringFromObj). De cette manière, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de la conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'elle n'effectue pas de conversions d'encodage, quel que soit l'encodage du canal. Elle est obsolète et existe pour des raisons de compatibilité descendante avec les extensions Tcl non internationalisées. Elle consomme des octets du canal et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par un zéro. Son contenu est valide à partir de la position zéro jusqu'à, mais non incluse, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas pour l'empilement. Alors que Tcl_Read (et les autres fonctions de l'API) obtiennent toujours leurs données du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_ReadRaw ne le fait pas. Ainsi, cette fonction est **uniquement** utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer des données du canal inférieur dans la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du canal, convertissant les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée ait été vue. Si l'encodage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception du ou des caractères de fin de ligne terminaux, sont ajoutés à la représentation textuelle de lineObjPtr. Le ou les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_GetsObj renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj renvoie également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est renvoyé, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité d'entrée.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique donnée par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, soit à la tête, soit à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si channel a un EOF "collant" (sticky) défini, aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets renvoie inputLen ou -1 si une erreur se produit.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données caractères à charBuf. Les caractères UTF-8 dans le tampon sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars attend que charBuf soit terminé par un zéro et il affiche tout jusqu'au zéro.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal à none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un compte du nombre d'octets qui ont été acceptés pour la sortie vers le canal. C'est soit un nombre supérieur à zéro pour indiquer le succès, soit -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme selon l'option -translation pour le canal. Ceci est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'il accepte une valeur Tcl dont le contenu sera affiché sur le canal. Les caractères UTF-8 dans la représentation textuelle de writeObjPtr sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. Par optimisation de performance, lors de l'écriture vers un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lorsqu'ils sont écrits. Au lieu de cela, les octets dans la représentation interne de writeObjPtr en tant que valeur de tableau d'octets sont écrits sur le canal. La représentation sous forme de tableau d'octets de la valeur sera construite si nécessaire. De cette manière, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de la conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'elle n'effectue pas de conversions d'encodage, quel que soit l'encodage du canal. Elle est obsolète et existe pour des raisons de compatibilité descendante avec les extensions Tcl non internationalisées. Elle accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write attend que byteBuf soit terminé par un zéro et il affiche tout jusqu'au zéro.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas pour l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée dans le canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction est **uniquement** utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer des données de la transformation dans le canal situé en dessous.

TCL_FLUSH

Tcl_Flush provoque l'écriture de toutes les données de sortie tamponnées pour le canal vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données tamponnées n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal est non bloquant ; il démarre une opération de vidage en arrière-plan qui écrira les données tamponnées dans le canal éventuellement, aussi rapidement que le canal est capable de les absorber.

La valeur de retour est normalement TCL_OK. En cas d'erreur, Tcl_Flush renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans le canal où les données ultérieures seront lues ou écrites. La sortie tamponnée est vidée vers le canal et l'entrée tamponnée est rejetée, avant l'opération de positionnement.

Tcl_Seek renvoie normalement le nouveau point d'accès. En cas d'erreur, Tcl_Seek renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut ou peut ne pas avoir été déplacé.

TCL_TELL

Tcl_Tell renvoie le point d'accès actuel pour un canal. La valeur renvoyée est -1 si le canal ne prend pas en charge le positionnement.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent du canal à une longueur donnée de length octets. Il renvoie TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et de leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, il s'agit du nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue.

Tcl_GetChannelOption, Tcl_SetChannelOption, Tcl_Eof, Tcl_InputBlocked, Tcl_InputBuffered, Tcl_OutputBuffered - Page de manuel Tcl

TCL_GETCHANNELOPTION

Tcl_GetChannelOption obtient la valeur de l'option optionName pour le canal channel. La valeur est stockée dans la chaîne de caractères retournée par Tcl_DStringAppendElement. Les options préexistantes et leurs valeurs possibles sont décrites dans la page de manuel de la commande Tcl fconfigure. D'autres options peuvent être ajoutées par chaque type de canal. Ces options spécifiques au type de canal sont décrites dans la page de manuel de la commande Tcl qui crée un canal de ce type ; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans la page de manuel de la commande Tcl socket. La procédure retourne normalement TCL_OK. Si une erreur se produit, elle retourne TCL_ERROR et appelle Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit une nouvelle valeur newValue pour une option optionName sur le channel. La procédure retourne normalement TCL_OK. Si une erreur se produit, elle retourne TCL_ERROR ; de plus, si interp n'est pas NULL, Tcl_SetChannelOption laisse un message d'erreur dans le résultat de l'interpréteur.

TCL_EOF

Tcl_Eof retourne une valeur non nulle si le channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked retourne une valeur non nulle si le channel est en mode non bloquant et que la dernière opération d'entrée a retourné moins de données que demandé car il n'y avait pas suffisamment de données disponibles. L'appel retourne toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered retourne le nombre d'octets d'entrée actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en lecture, cette fonction retourne toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered retourne le nombre d'octets de sortie actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en écriture, cette fonction retourne toujours zéro.

PROBLÈMES DE PLATEFORME

Les descripteurs retournés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que retourné par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel, ou Tcl_MakeFileChannel. D'autres types de canaux peuvent retourner un type différent de descripteur sur les plateformes Windows.
