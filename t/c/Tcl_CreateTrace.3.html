Paquet: tcl

Tcl_CreateTrace(3) Procédures de la bibliothèque Tcl Tcl_CreateTrace(3)

NOM

Tcl_CreateTrace, Tcl_CreateObjTrace, Tcl_DeleteTrace - organiser le suivi de l'exécution des commandes

SYNOPIS

#include <tcl.h>

Tcl_Trace
Tcl_CreateTrace(interp, level, proc, clientData)

Tcl_Trace
Tcl_CreateObjTrace(interp, level, flags, objProc, clientData, deleteProc)

Tcl_DeleteTrace(interp, trace)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur contenant la commande à suivre ou à ne plus suivre.
int level (entrée)
Seules les commandes à ce niveau d'imbrication ou en dessous seront suivies, sauf si 0 est spécifié. 1 signifie commandes de niveau supérieur uniquement, 2 signifie commandes de niveau supérieur ou celles qui sont appelées comme conséquences immédiates de l'exécution de commandes de niveau supérieur (corps de procédures, commandes entre crochets, etc.) et ainsi de suite. Une valeur de 0 signifie que les commandes à n'importe quel niveau sont suivies.
int flags (entrée)
Indicateurs régissant l'exécution du suivi. Voir ci-dessous pour les détails.
Tcl_CmdObjTraceProc *objProc (entrée)
Procédure à appeler pour chaque commande exécutée. Voir ci-dessous pour les détails de la séquence d'appel.
Tcl_CmdTraceProc *proc (entrée)
Procédure à appeler pour chaque commande exécutée. Voir ci-dessous pour les détails de la séquence d'appel.
ClientData clientData (entrée)
Valeur arbitraire d'un mot à passer à objProc ou proc.
Tcl_CmdObjTraceDeleteProc *deleteProc (entrée)
Procédure à appeler lorsque le suivi est supprimé. Voir ci-dessous pour les détails de la séquence d'appel. Un pointeur NULL est possible et n'entraîne aucun rappel lors de la suppression du suivi.
Tcl_Trace trace (entrée)
Jeton pour le suivi à supprimer (valeur de retour d'un appel précédent à Tcl_CreateTrace).

DESCRIPTION

Tcl_CreateObjTrace organise le suivi des commandes. Après son appel, objProc sera invoquée avant que l'interpréteur Tcl n'appelle une procédure de commande lors de l'évaluation des commandes dans interp. La valeur de retour de Tcl_CreateObjTrace est un jeton pour le suivi, qui peut être passé à Tcl_DeleteTrace pour supprimer le suivi. Il peut y avoir plusieurs suivis en vigueur simultanément pour le même interpréteur.

objProc doit avoir des arguments et un résultat qui correspondent au type, Tcl_CmdObjTraceProc :

typedef int Tcl_CmdObjTraceProc(
        ClientData clientData,
        Tcl_Interp* interp,
        int level,
        const char *command,
        Tcl_Command commandToken,
        int objc,
        Tcl_Obj *const objv[]);

Les paramètres clientData et interp sont des copies des paramètres correspondants donnés à Tcl_CreateTrace. ClientData pointe généralement vers une structure de données spécifique à l'application qui décrit quoi faire lorsque objProc est invoquée. Le paramètre level donne le niveau d'imbrication de la commande (1 pour les commandes de niveau supérieur passées à Tcl_Eval par l'application, 2 pour les commandes de niveau inférieur passées à Tcl_Eval dans le cadre de l'analyse ou de l'interprétation des commandes de niveau 1, et ainsi de suite). Le paramètre command pointe vers une chaîne contenant le texte de la commande, avant toute substitution d'argument. Le paramètre commandToken est un jeton de commande Tcl qui identifie la commande à invoquer. Le jeton peut être passé à Tcl_GetCommandName, Tcl_GetCommandInfoFromToken ou Tcl_SetCommandInfoFromToken pour manipuler la définition de la commande. Les paramètres objc et objv désignent le nombre final de paramètres et le vecteur de paramètres qui seront passés à la commande, et ont subi toutes les substitutions.

Le rappel objProc est censé retourner un code de retour de statut Tcl standard. Si ce code est TCL_OK (le cas normal), alors l'interpréteur Tcl invoquera la commande. Tout autre code de retour est traité comme si la commande avait retourné ce statut, et la commande n'est *pas* invoquée.

Le rappel objProc ne doit modifier objv d'aucune manière.

Le suivi ne se produira que pour les commandes dont le niveau d'imbrication est inférieur ou égal au paramètre level (c'est-à-dire que le paramètre level pour objProc sera toujours inférieur ou égal au paramètre level pour Tcl_CreateTrace).

Le suivi a un impact significatif sur les performances d'exécution car il fait en sorte que le compilateur de bytecode s'abstienne de générer du code en ligne pour les commandes Tcl telles que if et while afin qu'elles puissent être suivies. Si les suivis pour les commandes intégrées ne sont pas requis, le paramètre flags peut être défini à la valeur constante TCL_ALLOW_INLINE_COMPILATION. Dans ce cas, les suivis sur les commandes intégrées peuvent ou non entraîner des rappels de suivi, en fonction de l'état de l'interpréteur, mais les performances d'exécution seront considérablement améliorées. (Cette fonctionnalité est souhaitable, par exemple, lorsque l'on utilise Tcl_CreateObjTrace pour implémenter un profileur de temps d'exécution.)

Les appels à objProc seront effectués par l'analyseur Tcl immédiatement avant qu'il n'appelle la procédure de commande pour la commande (cmdProc). Cela se produit après l'analyse et la substitution des arguments, de sorte que le suivi des commandes substituées se produit avant le suivi des commandes contenant les substitutions. S'il y a une erreur de syntaxe dans une commande, ou s'il n'y a pas de procédure de commande associée à un nom de commande, aucun suivi ne se produira pour cette commande. Si une chaîne passée à Tcl_Eval contient plusieurs commandes (entre crochets, ou sur différentes lignes), plusieurs appels à objProc se produiront, un pour chaque commande.

Tcl_DeleteTrace supprime un suivi, de sorte qu'aucun appel futur ne sera effectué à la procédure associée au suivi. Après le retour de Tcl_DeleteTrace, l'appelant ne devrait plus jamais utiliser le jeton trace.

Lorsque Tcl_DeleteTrace est appelé, l'interpréteur invoque le deleteProc qui a été passé en paramètre à Tcl_CreateObjTrace. Le deleteProc doit correspondre au type, Tcl_CmdObjTraceDeleteProc :

typedef void Tcl_CmdObjTraceDeleteProc(
        ClientData clientData);

Le paramètre clientData sera le même que le paramètre clientData qui a été initialement passé à Tcl_CreateObjTrace.

Tcl_CreateTrace est une interface alternative pour le suivi des commandes, *non recommandée pour les nouvelles applications*. Elle est fournie pour la compatibilité descendante avec le code développé pour les anciennes versions de l'interpréteur Tcl. Elle est similaire à Tcl_CreateObjTrace, sauf que son paramètre proc doit avoir des arguments et un résultat qui correspondent au type Tcl_CmdTraceProc :

typedef void Tcl_CmdTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        int level,
        char *command,
        Tcl_CmdProc *cmdProc,
        ClientData cmdClientData,
        int argc,
        const char *argv[]);

Les paramètres du rappel proc sont similaires à ceux du rappel objProc ci-dessus. Le commandToken est remplacé par cmdProc, un pointeur vers la procédure de commande (basée sur des chaînes de caractères) qui sera invoquée ; et cmdClientData, les données client qui seront passées à la procédure. Le paramètre objc est remplacé par un paramètre argv, qui donne les arguments de la commande sous forme de chaînes de caractères. Proc ne doit pas modifier les chaînes command ou argv.

Si un suivi créé avec Tcl_CreateTrace est actif, la compilation en ligne des commandes Tcl telles que if et while est toujours désactivée. Il n'y a aucune notification lors de la suppression d'un suivi créé avec Tcl_CreateTrace. Il n'y a aucun moyen d'être informé lorsque le suivi créé par Tcl_CreateTrace est supprimé. Il n'y a aucun moyen pour le proc associé à un appel à Tcl_CreateTrace d'interrompre l'exécution de command.
