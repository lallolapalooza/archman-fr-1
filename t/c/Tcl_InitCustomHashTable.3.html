ARGUMENTS

Tcl_HashTable *tablePtr (in)
Adresse de la structure de table de hachage (pour toutes les procédures sauf Tcl_InitHashTable, celle-ci doit avoir été initialisée par un appel précédent à Tcl_InitHashTable).
int keyType (in)
Type de clés à utiliser pour la nouvelle table de hachage. Doit être TCL_STRING_KEYS, TCL_ONE_WORD_KEYS, TCL_CUSTOM_TYPE_KEYS, TCL_CUSTOM_PTR_KEYS, ou une valeur entière supérieure à 1.
Tcl_HashKeyType *typePtr (in)
Adresse de la structure qui définit le comportement de la table de hachage.
const void *key (in)
Clé à utiliser pour la recherche dans la table. La forme exacte dépend du keyType utilisé pour créer la table.
int *newPtr (out)
Le mot à l'adresse *newPtr est défini sur 1 si une nouvelle entrée a été créée et sur 0 s'il existait déjà une entrée pour key.
Tcl_HashEntry *entryPtr (in)
Pointeur vers une entrée de table de hachage.
ClientData value (in)
Nouvelle valeur à assigner à l'entrée de table de hachage. N'a pas besoin d'être de type ClientData, mais doit tenir dans le même espace que ClientData.
Tcl_HashSearch *searchPtr (in)
Pointeur vers un enregistrement à utiliser pour suivre la progression lors de l'énumération de toutes les entrées d'une table de hachage.

DESCRIPTION

Une table de hachage se compose de zéro ou plusieurs entrées, chacune constituée d'une clé et d'une valeur. Étant donnée la clé d'une entrée, les routines de hachage peuvent localiser très rapidement l'entrée, et donc sa valeur. Il peut y avoir au plus une entrée dans une table de hachage avec une clé particulière, mais plusieurs entrées peuvent avoir la même valeur. Les clés peuvent prendre l'une des quatre formes suivantes : chaînes de caractères, valeurs d'un seul mot, tableaux d'entiers, ou clés personnalisées définies par une structure Tcl_HashKeyType (voir la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous). Toutes les clés d'une table donnée ont la même forme, qui est spécifiée lors de l'initialisation de la table.

La valeur d'une entrée de table de hachage peut être n'importe quoi qui tient dans le même espace qu'un pointeur “char *”. Les valeurs des entrées de table de hachage sont entièrement gérées par les clients, et non par le module de hachage lui-même. Typiquement, la valeur de chaque entrée est un pointeur vers une structure de données gérée par le code client.

Les tables de hachage se développent de manière fluide à mesure que le nombre d'entrées augmente, de sorte qu'il y a toujours moins de trois entrées par compartiment de hachage, en moyenne. Cela permet des recherches rapides indépendamment du nombre d'entrées dans une table.

Le cœur fournit trois fonctions pour l'initialisation des tables de hachage : Tcl_InitHashTable, Tcl_InitObjHashTable et Tcl_InitCustomHashTable.

Tcl_InitHashTable initialise une structure qui décrit une nouvelle table de hachage. L'espace pour la structure est fourni par l'appelant, et non par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. Tous les types de clés décrits plus loin sont autorisés, à l'exception de TCL_CUSTOM_TYPE_KEYS et TCL_CUSTOM_PTR_KEYS.

Tcl_InitObjHashTable est un wrapper autour de Tcl_InitCustomHashTable et initialise une table de hachage dont les clés sont des Tcl_Obj *.

Tcl_InitCustomHashTable initialise une structure qui décrit une nouvelle table de hachage. L'espace pour la structure est fourni par l'appelant, et non par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. KeyType doit avoir l'une des valeurs suivantes :

TCL_STRING_KEYS
Les clés sont des chaînes de caractères terminées par un caractère nul. Elles sont passées aux routines de hachage en utilisant l'adresse du premier caractère de la chaîne.
TCL_ONE_WORD_KEYS
Les clés sont des valeurs d'un seul mot ; elles sont passées aux routines de hachage et stockées dans les entrées de table de hachage sous forme de valeurs “char *”. La valeur du pointeur est la clé ; elle n'a pas besoin (et ne le fait généralement pas) de pointer vers une chaîne de caractères.
TCL_CUSTOM_TYPE_KEYS
Les clés sont de type arbitraire et sont stockées dans l'entrée. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous.
TCL_CUSTOM_PTR_KEYS
Les clés sont des pointeurs vers un type arbitraire et sont stockées dans l'entrée. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous.
autre
Si keyType n'est pas l'une des options ci-dessus, alors il doit s'agir d'une valeur entière supérieure à 1. Dans ce cas, les clés seront des tableaux de valeurs “int”, où keyType donne le nombre d'entiers dans chaque clé. Cela permet d'utiliser des structures comme clés. Toutes les clés doivent avoir la même taille. Les clés de tableau sont passées aux fonctions de hachage en utilisant l'adresse du premier entier du tableau.

Tcl_DeleteHashTable supprime toutes les entrées d'une table de hachage et libère la mémoire associée au tableau de compartiments et aux entrées de la table. Elle ne libère pas la structure de table elle-même (pointée par tablePtr), car la mémoire est censée être gérée par le client. Tcl_DeleteHashTable ne libère pas non plus et ne manipule pas les valeurs des entrées de la table de hachage. Si les valeurs des entrées pointent vers une mémoire allouée dynamiquement, il incombe au client de libérer ces structures avant de supprimer la table.

Tcl_CreateHashEntry localise l'entrée correspondant à une clé particulière, en créant une nouvelle entrée dans la table s'il n'en existait pas déjà une avec la clé donnée. Si une entrée existait déjà avec la clé donnée, alors *newPtr est mis à zéro. Si une nouvelle entrée a été créée, alors *newPtr est mis à une valeur non nulle et la valeur de la nouvelle entrée sera mise à zéro. La valeur de retour de Tcl_CreateHashEntry est un pointeur vers l'entrée, qui peut être utilisé pour récupérer et modifier la valeur de l'entrée ou pour supprimer l'entrée de la table.

Tcl_DeleteHashEntry supprime une entrée existante d'une table. La mémoire associée à l'entrée elle-même sera libérée, mais le client est responsable de toute opération de nettoyage associée à la valeur de l'entrée, comme la libération d'une structure vers laquelle elle pointe.

Tcl_FindHashEntry est similaire à Tcl_CreateHashEntry sauf qu'elle ne crée pas de nouvelle entrée si la clé n'existe pas ; elle retourne plutôt NULL comme résultat.

Tcl_GetHashValue et Tcl_SetHashValue sont utilisées pour lire et écrire la valeur d'une entrée, respectivement. Les valeurs sont stockées et récupérées sous le type “ClientData”, qui est suffisamment grand pour contenir une valeur de pointeur. Sur presque toutes les machines, il est également suffisamment grand pour contenir une valeur entière.

Tcl_GetHashKey retourne la clé pour une entrée de table de hachage donnée, soit sous forme de pointeur vers une chaîne, une clé d'un seul mot (“char *”), soit comme pointeur vers le premier mot d'un tableau d'entiers, en fonction du keyType utilisé pour créer une table de hachage. Dans tous les cas, Tcl_GetHashKey retourne un résultat de type “char *”. Lorsque la clé est une chaîne ou un tableau, le résultat de Tcl_GetHashKey pointe vers les informations contenues dans l'entrée de la table ; ces informations resteront valides jusqu'à ce que l'entrée soit supprimée ou que sa table soit supprimée.

Tcl_FirstHashEntry et Tcl_NextHashEntry peuvent être utilisées pour parcourir toutes les entrées d'une table de hachage.

Tcl_HashStats retourne une chaîne de caractères (qui doit être libérée par le client avec Tcl_Free) contenant des statistiques sur la structure interne de la table de hachage.

LA STRUCTURE TCL_HASHKEYTYPE

Lorsque vous utilisez Tcl_InitCustomHashTable avec le type de clé TCL_CUSTOM_TYPE_KEYS ou TCL_CUSTOM_PTR_KEYS, vous devez fournir une structure Tcl_HashKeyType qui définit comment les clés de type personnalisé doivent être hachées et comparées. La structure Tcl_HashKeyType a la forme suivante :

typedef struct Tcl_HashKeyType {
    size_t (*hashKey)(char *key, int numBytes);
    int (*compareKeys)(char *key1, char *key2, int numBytes);
    void (*freeKey)(char *key);
} Tcl_HashKeyType;
hashKey
Un pointeur vers une fonction qui prend un pointeur vers une clé et sa taille en octets, et retourne un entier non signé représentant le hachage de la clé. Si le champ keyType était défini sur TCL_CUSTOM_PTR_KEYS, alors numBytes est la taille en octets du pointeur, et la fonction de hachage doit juste retourner la valeur du pointeur.
compareKeys
Un pointeur vers une fonction qui prend deux pointeurs vers des clés et leur taille en octets, et retourne 1 si les clés sont égales, et 0 sinon. Si le champ keyType était défini sur TCL_CUSTOM_PTR_KEYS, alors numBytes est la taille en octets du pointeur, et la fonction de comparaison doit juste comparer les deux pointeurs.
freeKey
Un pointeur vers une fonction qui prend un pointeur vers une clé et qui est appelé lorsque l'entrée est supprimée de la table. Cette fonction est responsable de la libération de toute mémoire allouée pour la clé. Si aucun nettoyage n'est nécessaire, ce champ peut être NULL.

La fonction de hachage hashKey est responsable de la génération d'un entier non signé à partir de la clé. La fonction de comparaison compareKeys est responsable de la comparaison de deux clés pour l'égalité. La fonction freeKey est responsable de la libération de toute mémoire allouée pour la clé. Lorsque le type de clé est TCL_CUSTOM_PTR_KEYS, la valeur numBytes passée aux fonctions hashKey et compareKeys sera la taille en octets d'un pointeur sur la plateforme actuelle.

Si vous utilisez un type de clé qui n'est pas une chaîne ou un mot, comme des tableaux d'entiers, vous spécifiez le nombre d'entiers dans chaque clé comme valeur de keyType (par exemple, 2 pour des tableaux de deux entiers). La structure Tcl_HashKeyType peut alors être omise, et Tcl utilisera des routines de hachage et de comparaison par défaut qui traitent les clés comme des tableaux d'entiers.

NAME

Tcl_InitCustomHashTable, Tcl_AllocHashEntry, Tcl_DeleteHashEntry, Tcl_FindHashEntry, Tcl_FirstHashEntry, Tcl_HashStats, Tcl_InitHashTable, Tcl_NextHashEntry - manipuler des tables de hachage personnalisées

SYNOPSIS

#include <tcl.h>

Tcl_HashTable *
Tcl_InitCustomHashTable(tablePtr, keyTypePtr);

Tcl_HashEntry *
Tcl_AllocHashEntry(tablePtr, keyPtr);

void
Tcl_DeleteHashEntry(tablePtr, hPtr);

Tcl_HashEntry *
Tcl_FindHashEntry(tablePtr, keyPtr);

Tcl_HashEntry *
Tcl_FirstHashEntry(tablePtr, searchPtr);

int
Tcl_HashStats(tablePtr, stringPtr);

Tcl_HashTable *
Tcl_InitHashTable(tablePtr, hashKeyType);

Tcl_HashEntry *
Tcl_NextHashEntry(tablePtr, searchPtr);

ARGUMENTS

tablePtr
Pointeur vers la table de hachage.
keyTypePtr
Pointeur vers une structure décrivant le type de clé.
keyPtr
Pointeur vers la clé.
hPtr
Pointeur vers une entrée de table de hachage.
searchPtr
Pointeur vers une structure de recherche.
stringPtr
Pointeur vers une chaîne de caractères pour les statistiques.
hashKeyType
Type de clé pour les tables de hachage standard.

DESCRIPTION

Les tables de hachage de Tcl sont des structures de données efficaces pour stocker des paires clé-valeur. Elles sont implémentées comme un tableau de listes chaînées (également appelées "buckets"). Les fonctions décrites ici permettent de créer, manipuler et interroger ces tables.

Tcl_InitHashTable initialise une table de hachage pour un type de clé spécifié. Le type de clé est représenté par une valeur entière qui spécifie le type de clé utilisé (par exemple, chaînes de caractères, entiers, pointeurs). Le membre numBuckets spécifie la taille initiale du tableau de hachage.

Tcl_InitCustomHashTable initialise une table de hachage avec un type de clé personnalisé, défini par une structure Tcl_HashKeyType. Cela permet une plus grande flexibilité dans la manière dont les clés sont traitées et comparées.

Tcl_AllocHashEntry alloue une nouvelle entrée dans la table de hachage pour une clé donnée. La clé est copiée dans l'entrée. Si une entrée avec cette clé existe déjà, elle est retournée. Sinon, une nouvelle entrée est allouée et initialisée.

Tcl_DeleteHashEntry supprime une entrée de la table de hachage. Le pointeur hPtr doit pointer vers une entrée valide retournée par l'une des fonctions de recherche de table de hachage.

Tcl_FindHashEntry recherche une entrée dans la table de hachage en utilisant la clé spécifiée. Si une entrée correspondante est trouvée, un pointeur vers cette entrée est retourné, sinon NULL est retourné.

Pour parcourir toutes les entrées d'une table de hachage, utilisez une structure Tcl_HashSearch pour garder une trace de la progression. Tcl_FirstHashEntry initialise l'enregistrement de recherche et retourne la première entrée de la table (ou NULL si la table est vide). Chaque appel ultérieur à Tcl_NextHashEntry retourne la prochaine entrée dans la table ou NULL si la fin de la table a été atteinte. Un appel à Tcl_FirstHashEntry suivi d'appels à Tcl_NextHashEntry retournera chaque entrée de la table exactement une fois, dans un ordre arbitraire. Il est déconseillé de modifier la structure de la table (par exemple, en créant ou en supprimant des entrées) pendant qu'une recherche est en cours, à l'exception de la suppression de l'entrée retournée par Tcl_FirstHashEntry ou Tcl_NextHashEntry.

Tcl_HashStats retourne une chaîne allouée dynamiquement avec des informations générales sur une table de hachage, telles que le nombre d'entrées qu'elle contient, le nombre de buckets dans son tableau de hachage et l'utilisation des buckets. Il est de la responsabilité de l'appelant de libérer la chaîne résultante en la passant à ckfree.

Le fichier d'en-tête tcl.h définit les structures de données réelles utilisées pour implémenter les tables de hachage. Ceci est nécessaire pour que les clients puissent allouer des structures Tcl_HashTable et pour que des macros puissent être utilisées pour lire et écrire les valeurs des entrées. Cependant, les utilisateurs des routines de hachage ne doivent jamais se référer directement à aucun des champs des structures de données liées au hachage ; utilisez les procédures et macros définies ici.

LA STRUCTURE TCL_HASHKEYTYPE

Les auteurs d'extensions peuvent définir de nouveaux types de clés de hachage en définissant quatre procédures, en initialisant une structure Tcl_HashKeyType pour décrire le type et en appelant Tcl_InitCustomHashTable. La structure Tcl_HashKeyType est définie comme suit :

typedef struct Tcl_HashKeyType {
    int version;
    int flags;
    Tcl_HashKeyProc *hashKeyProc;
    Tcl_CompareHashKeysProc *compareKeysProc;
    Tcl_AllocHashEntryProc *allocEntryProc;
    Tcl_FreeHashEntryProc *freeEntryProc;
} Tcl_HashKeyType;

Le membre version est la version de la table. Si cette structure est étendue à l'avenir, la version peut être utilisée pour distinguer différentes structures. Elle doit être définie à TCL_HASH_KEY_TYPE_VERSION.

Le membre flags est 0 ou une ou plusieurs des valeurs suivantes combinées par OU :

TCL_HASH_KEY_RANDOMIZE_HASH
Certaines choses, comme les pointeurs, ne hachent pas bien car elles n'utilisent pas les bits de poids faible. Si ce drapeau est défini, la table de hachage tentera de rectifier cela en randomisant les bits, puis en utilisant les N bits supérieurs comme indice dans la table.
TCL_HASH_KEY_SYSTEM_HASH
Ce drapeau force Tcl à utiliser les procédures d'allocation de mémoire fournies par le système d'exploitation lors de l'allocation et de la libération de mémoire utilisée pour stocker les structures de données de la table de hachage, et non l'une des routines d'allocation de mémoire personnalisées de Tcl. Ceci est important si la table de hachage doit être utilisée dans l'implémentation d'un ensemble personnalisé de routines d'allocation, ou de quelque chose dont un ensemble personnalisé de routines d'allocation pourrait dépendre, afin d'éviter toute dépendance circulaire.

Le membre hashKeyProc contient l'adresse d'une fonction appelée pour calculer une valeur de hachage pour la clé.

typedef unsigned int Tcl_HashKeyProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

Si ceci est NULL, alors keyPtr est utilisé et TCL_HASH_KEY_RANDOMIZE_HASH est supposé.

Le membre compareKeysProc contient l'adresse d'une fonction appelée pour comparer deux clés.

typedef int Tcl_CompareHashKeysProc(
        void *keyPtr,
        Tcl_HashEntry *hPtr);

Si ceci est NULL, alors les pointeurs keyPtr sont comparés. Si les clés ne correspondent pas, la fonction retourne 0, sinon elle retourne 1.

Le membre allocEntryProc contient l'adresse d'une fonction appelée pour allouer de l'espace pour une entrée et initialiser la clé et clientData.

typedef Tcl_HashEntry *Tcl_AllocHashEntryProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

Si ceci est NULL, alors Tcl_Alloc est utilisé pour allouer suffisamment d'espace pour une Tcl_HashEntry, le pointeur de clé est assigné à key.oneWordValue et clientData est mis à NULL. Les clés de type chaîne et les clés de tableau utilisent cette fonction pour allouer suffisamment d'espace pour l'entrée et la clé en un seul bloc, plutôt qu'en deux. Cela permet d'économiser de l'espace pour un pointeur vers la clé depuis l'entrée et une autre allocation mémoire. Les clés Tcl_Obj* utilisent cette fonction pour allouer suffisamment d'espace pour une entrée et incrémenter le compteur de références sur la valeur.

Le membre freeEntryProc contient l'adresse d'une fonction appelée pour libérer l'espace d'une entrée.

typedef void Tcl_FreeHashEntryProc(
        Tcl_HashEntry *hPtr);

Si ceci est NULL, alors Tcl_Free est utilisé pour libérer l'espace de l'entrée. Les clés Tcl_Obj* utilisent cette fonction pour décrémenter le compteur de références sur la valeur.
