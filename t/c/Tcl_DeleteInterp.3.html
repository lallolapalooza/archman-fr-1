Tcl_CreateInterp(3) Procédures de la bibliothèque Tcl Tcl_CreateInterp(3)

NOM

Tcl_CreateInterp, Tcl_DeleteInterp, Tcl_InterpActive, Tcl_InterpDeleted - créer et supprimer des interpréteurs de commandes Tcl

SYNOPIS

#include <tcl.h>

Tcl_Interp *
Tcl_CreateInterp()

Tcl_DeleteInterp(interp)

int
Tcl_InterpDeleted(interp)

int
Tcl_InterpActive(interp)

ARGUMENTS

Tcl_Interp *interp (entrée)
Jeton pour l'interpréteur à détruire ou interroger.

DESCRIPTION

Tcl_CreateInterp crée une nouvelle structure d'interpréteur et renvoie un jeton pour celle-ci. Le jeton est requis dans les appels à la plupart des autres procédures Tcl, telles que Tcl_CreateCommand, Tcl_Eval et Tcl_DeleteInterp. Le jeton renvoyé par Tcl_CreateInterp ne peut être passé qu'aux routines Tcl appelées depuis le même thread que l'appel original à Tcl_CreateInterp. Il n'est pas sûr que plusieurs threads passent le même jeton aux routines de Tcl. Le nouvel interpréteur est initialisé avec les commandes Tcl intégrées et avec des variables standard telles que tcl_platform et env. Pour lier des commandes supplémentaires, appelez Tcl_CreateCommand, et pour créer des variables supplémentaires, appelez Tcl_SetVar.

Tcl_DeleteInterp marque un interpréteur comme supprimé ; l'interpréteur sera éventuellement supprimé lorsque tous les appels à Tcl_Preserve pour celui-ci auront été mis en correspondance avec des appels à Tcl_Release. À ce moment-là, toutes les ressources qui lui sont associées, y compris les variables, les procédures et les liaisons de commandes spécifiques à l'application, seront supprimées. Après le retour de Tcl_DeleteInterp, toute tentative d'utilisation de Tcl_Eval sur l'interpréteur échouera et renverra TCL_ERROR. Après l'appel à Tcl_DeleteInterp, il est sûr d'examiner le résultat de l'interpréteur, d'interroger ou de définir les valeurs des variables, de définir, de supprimer ou de récupérer des procédures, et d'examiner la pile d'évaluation d'exécution. Voir ci-dessous, dans la section INTERPRETEURS ET GESTION DE LA MÉMOIRE pour plus de détails.

Tcl_InterpDeleted renvoie une valeur non nulle si Tcl_DeleteInterp a été appelé avec interp comme argument ; cela indique que l'interpréteur sera éventuellement supprimé, lorsque le dernier appel à Tcl_Preserve pour celui-ci sera mis en correspondance avec un appel à Tcl_Release. Si une valeur non nulle est renvoyée, les appels ultérieurs à Tcl_Eval dans cet interpréteur renverront TCL_ERROR.

Tcl_InterpDeleted est utile dans les rappels de suppression pour distinguer entre le moment où seule la mémoire dont le rappel est responsable est supprimée et le moment où l'interpréteur entier est supprimé. Dans le premier cas, le rappel peut recréer les données en cours de suppression, mais cela entraînerait une boucle infinie si l'interpréteur était en cours de suppression.

Tcl_InterpActive est utile pour déterminer si une exécution de scripts est en cours dans un interpréteur, ce qui est une information utile lorsque Tcl est intégré dans un environnement à garbage collection et qu'il devient nécessaire de déterminer si l'interpréteur est un candidat à la suppression. La fonction renvoie une valeur vraie si l'interpréteur a au moins une exécution active en cours, et une valeur fausse sinon.

INTERPRETEURS ET GESTION DE LA MÉMOIRE

Tcl_DeleteInterp peut être appelé à tout moment sur un interpréteur qui peut être utilisé par des évaluations imbriquées et du code C dans diverses extensions. Tcl implémente un mécanisme simple qui permet aux appelants d'utiliser des interpréteurs sans se soucier que l'interpréteur soit supprimé dans un appel imbriqué, et sans nécessiter de code spécial pour protéger l'interpréteur, dans la plupart des cas. Ce mécanisme garantit que les utilisations imbriquées d'un interpréteur peuvent continuer à l'utiliser en toute sécurité même après que Tcl_DeleteInterp ait été appelé.

Le mécanisme repose sur la mise en correspondance des appels à Tcl_Preserve avec les appels à Tcl_Release. Si Tcl_DeleteInterp a été appelé, l'interpréteur ne sera libéré que lorsque le dernier appel à Tcl_Preserve sera mis en correspondance par un appel à Tcl_Release. Voir l'entrée de manuel pour Tcl_Preserve pour une description de ces fonctions.

Les règles concernant le moment où l'utilisateur d'un interpréteur doit appeler Tcl_Preserve et Tcl_Release sont simples :

Interpréteurs Passés en Arguments
Les fonctions qui reçoivent un interpréteur en argument peuvent utiliser l'interpréteur en toute sécurité sans aucune protection spéciale. Ainsi, lorsque vous écrivez une extension composée de nouvelles commandes Tcl, aucun code spécial n'est nécessaire pour protéger les interpréteurs reçus en argument. Cela couvre la majorité des utilisations.
Création et Suppression d'Interpréteur
Lorsqu'un nouvel interpréteur est créé et utilisé dans un appel à Tcl_Eval, Tcl_VarEval, Tcl_GlobalEval, Tcl_SetVar, ou Tcl_GetVar, une paire d'appels à Tcl_Preserve et Tcl_Release doit encadrer toutes les utilisations de l'interpréteur. N'oubliez pas qu'il est dangereux d'utiliser l'interpréteur une fois que Tcl_Release a été appelé. Pour garantir que l'interpréteur est correctement supprimé lorsqu'il n'est plus nécessaire, appelez Tcl_InterpDeleted pour tester si un autre code a déjà appelé Tcl_DeleteInterp ; sinon, appelez Tcl_DeleteInterp avant d'appeler Tcl_Release dans votre propre code.
Récupération d'un Interpréteur d'une Structure de Données
Lorsqu'un interpréteur est récupéré d'une structure de données (par ex. les données client d'un rappel) pour être utilisé dans l'une des fonctions d'évaluation (Tcl_Eval, Tcl_VarEval, Tcl_GlobalEval, Tcl_EvalObjv, etc.) ou fonctions d'accès aux variables (Tcl_SetVar, Tcl_GetVar, Tcl_SetVar2Ex, etc.), une paire d'appels à Tcl_Preserve et Tcl_Release doit encadrer toutes les utilisations de l'interpréteur ; il est dangereux de réutiliser l'interpréteur une fois que Tcl_Release a été appelé. Si un interpréteur est stocké à l'intérieur d'une structure de données de rappel, un mécanisme de nettoyage de suppression approprié doit être mis en place par le code qui crée la structure de données afin que l'interpréteur soit retiré de la structure de données (par ex. en mettant le champ à NULL) lorsque l'interpréteur est supprimé. Sinon, vous pourriez utiliser un interpréteur qui a été libéré et dont la mémoire peut déjà avoir été réutilisée.

Toutes les utilisations d'interpréteurs dans Tcl et Tk ont déjà été protégées. Les rédacteurs d'extensions doivent s'assurer que leur code protège également tous les interpréteurs supplémentaires utilisés, comme décrit ci-dessus.

Notez que les mécanismes de protection ne fonctionnent pas bien avec les systèmes de garbage collection conventionnels. Dans un tel environnement géré, Tcl_InterpActive doit être utilisé pour déterminer quand un interpréteur est un candidat à la suppression en raison de son inactivité.

Tcl_DeleteInterp(3) - Linux man page

Tcl_DeleteInterp - destroy a Tcl interpreter.

SYNOPSIS

#include <tcl.h>

void
Tcl_DeleteInterp(interp)
    Tcl_Interp *interp;

ARGUMENTS

Name I/O Description
interp I Interpreter to destroy.

DESCRIPTION

The Tcl_DeleteInterp procedure destroys the Tcl interpreter specified by interp. It releases all memory and other resources associated with the interpreter, including all objects created within it, all event handlers, and all packages loaded into it. After this procedure returns, interp is no longer a valid interpreter, and it should not be used.

Tcl_DeleteInterp - détruit un interpréteur Tcl.

SYNTAXE

#include <tcl.h>

void
Tcl_DeleteInterp(interp)
    Tcl_Interp *interp;

ARGUMENTS

Nom E/S Description
interp E Interpréteur à détruire.

DESCRIPTION

La procédure Tcl_DeleteInterp détruit l'interpréteur Tcl spécifié par interp. Elle libère toute la mémoire et les autres ressources associées à l'interpréteur, y compris tous les objets créés à l'intérieur, tous les gestionnaires d'événements et tous les paquets chargés. Après le retour de cette procédure, interp n'est plus un interpréteur valide et ne doit pas être utilisé.
