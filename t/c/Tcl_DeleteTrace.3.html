Tcl_DeleteTrace(3)

Paquet: tcl

Licences: TCL

Tcl_DeleteTrace(3) Procédures de la bibliothèque Tcl Tcl_DeleteTrace(3)

NOM

Tcl_CreateTrace, Tcl_CreateObjTrace, Tcl_DeleteTrace - enregistrer l'exécution des commandes

SYNOPSIS

#include <tcl.h>

Tcl_Trace
Tcl_CreateTrace(interp, level, proc, clientData)

Tcl_Trace
Tcl_CreateObjTrace(interp, level, flags, objProc, clientData, deleteProc)

Tcl_DeleteTrace(interp, trace)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur contenant la commande à tracer ou à désenregistrer.
int level (in)
Les commandes d'un niveau de profondeur inférieur ou égal à ce niveau seront tracées, sauf si 0 est spécifié. 1 signifie uniquement les commandes de niveau supérieur, 2 signifie les commandes de niveau supérieur ou celles qui sont appelées comme conséquence immédiate de l'exécution des commandes de niveau supérieur (corps de procédure, commandes entre crochets, etc.) et ainsi de suite. Une valeur de 0 signifie que toutes les commandes sont tracées.
int flags (in)
Les indicateurs qui régissent l'exécution du traçage. Voir plus de détails ci-dessous.
Tcl_CmdObjTraceProc *objProc (in)
Procédure appelée lors de l'exécution d'une commande. Voir plus de détails sur la séquence d'appel.
Tcl_CmdTraceProc *proc (in)
Procédure appelée lors de l'exécution d'une commande. Voir plus de détails sur la séquence d'appel.
ClientData clientData (in)
Valeur arbitraire d'un seul mot passée à objProc ou proc.
Tcl_CmdObjTraceDeleteProc *deleteProc (in)
Procédure appelée lors de la suppression du traçage. Voir plus de détails sur la séquence d'appel. Un pointeur nul est autorisé et ne déclenche aucun appel lors de la suppression du traçage.
Tcl_Trace trace (in)
Jeton du traçage à supprimer (valeur retournée par un appel précédent à Tcl_CreateTrace).

DESCRIPTION

Tcl_CreateObjTrace enregistre l'exécution des commandes. Après son appel, objProc est appelé avant que l'interpréteur n'exécute une procédure de commande lors de l'évaluation de commandes dans interp. La valeur retournée par Tcl_CreateObjTrace est un jeton pour le traçage, qui peut être passé à Tcl_DeleteTrace pour supprimer le traçage. Plusieurs traçages peuvent être actifs simultanément pour le même interpréteur.

Le callback objProc doit avoir des arguments et un résultat qui correspondent au type Tcl_CmdObjTraceProc :

typedef int Tcl_CmdObjTraceProc(
        ClientData clientData,
        Tcl_Interp* interp,
        int level,
        const char *command,
        Tcl_Command commandToken,
        int objc,
        Tcl_Obj *const objv[]);

Les paramètres clientData et interp sont des copies des arguments correspondants passés à Tcl_CreateTrace. ClientData pointe généralement vers une structure de données spécifique à l'application qui décrit ce qu'il faut faire lorsque objProc est appelé. Le paramètre level donne le niveau de profondeur de la commande (1 pour les commandes de niveau supérieur passées à Tcl_Eval par l'application, 2 pour les commandes suivantes passées à Tcl_Eval lors de l'analyse ou de l'interprétation des commandes de niveau 1, et ainsi de suite). Le paramètre command pointe vers une chaîne contenant le texte de la commande, avant toute substitution d'arguments. Le paramètre commandToken est un jeton de commande Tcl qui identifie la commande à appeler. Le jeton peut être passé à Tcl_GetCommandName, Tcl_GetCommandInfoFromToken ou Tcl_SetCommandInfoFromToken pour modifier la définition de la commande. Les paramètres objc et objv désignent le nombre final de paramètres et le vecteur de paramètres qui seront passés à la commande, et toutes les substitutions ont été effectuées.

Le callback objProc doit retourner un code de retour Tcl standard. Si ce code est TCL_OK (cas normal), l'interpréteur appellera la commande. Tout autre code de retour sera traité comme si la commande retournait cet état, et la commande ne sera pas appelée.

Le callback objProc ne doit en aucun cas modifier objv.

Le traçage ne se produit que pour les commandes dont le niveau de profondeur est inférieur ou égal au level du paramètre (c'est-à-dire que le level du callback objProc sera toujours inférieur ou égal au level du paramètre de Tcl_CreateTrace).

Le traçage a un impact significatif sur les performances d'exécution, car il empêche le compilateur de bytecode de générer du code inline pour des commandes Tcl telles que if et while afin qu'elles puissent être tracées. Si le traçage des commandes de niveau standard n'est pas nécessaire, le paramètre flags peut être défini à la constante TCL_ALLOW_INLINE_COMPILATION. Dans ce cas, les traçages des commandes standard peuvent ou non générer des callbacks de traçage, en fonction de l'état de l'interpréteur, mais les performances d'exécution seront meilleures. (Cette fonctionnalité est souhaitable, par exemple, lors de l'utilisation de Tcl_CreateObjTrace pour implémenter un profileur d'exécution en temps réel.)

Les appels à objProc sont effectués immédiatement avant que l'analyseur Tcl n'appelle la procédure de commande pour la commande (cmdProc). Cela se produit après l'analyse et la substitution des arguments, de sorte que le traçage des commandes substituées se produit avant le traçage des commandes qui contiennent les substitutions. En cas d'erreur de syntaxe dans une commande ou si aucun procédure de commande n'est associée à un nom de commande, aucun traçage ne sera effectué pour cette commande. Si une chaîne passée à Tcl_Eval contient plusieurs commandes (entre crochets, ou sur des lignes distinctes), plusieurs appels à objProc seront effectués, un pour chaque commande.

Tcl_DeleteTrace supprime un traçage, de sorte qu'aucun appel futur ne sera effectué à la procédure associée au traçage. Après le retour de Tcl_DeleteTrace, l'appelant ne doit jamais utiliser le jeton trace.

Lorsque Tcl_DeleteTrace est appelé, l'interpréteur appelle le deleteProc qui a été passé comme argument à Tcl_CreateObjTrace. Le deleteProc doit correspondre au type Tcl_CmdObjTraceDeleteProc :

typedef void Tcl_CmdObjTraceDeleteProc(
        ClientData clientData);

Le paramètre clientData sera le même que le clientData initialement passé à Tcl_CreateObjTrace.

Tcl_CreateTrace est une interface alternative pour le traçage des commandes, et n'est pas recommandée pour les nouvelles applications. Elle est fournie pour des raisons de compatibilité avec le code développé dans les versions antérieures de l'interpréteur Tcl. Elle est similaire à Tcl_CreateObjTrace, sauf que son paramètre proc doit avoir des arguments et un résultat qui correspondent au type Tcl_CmdTraceProc :

typedef void Tcl_CmdTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        int level,
        char *command,
        Tcl_CmdProc *cmdProc,
        ClientData cmdClientData,
        int argc,
        const char *argv[]);

Les paramètres du callback proc sont similaires à ceux du callback objProc ci-dessus. Le commandToken est remplacé par cmdProc, un pointeur vers le procédure de commande (basée sur une chaîne) qui sera appelée ; et cmdClientData, les données client qui seront passées à la procédure. objc est remplacé par un paramètre argv, qui donne les arguments de la commande sous forme de chaînes de caractères. Proc ne doit pas modifier les chaînes command ou argv.

Si un traçage créé avec Tcl_CreateTrace est actif, la compilation inline des commandes Tcl telles que if et while est toujours désactivée. Aucune notification n'est donnée lorsqu'un traçage créé avec Tcl_CreateTrace est supprimé. Il n'y a aucun moyen d'être averti de la suppression du traçage créé avec Tcl_CreateTrace. Il n'y a aucun moyen d'interrompre l'exécution de command par la procédure associée à un appel à Tcl_CreateTrace.
