ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour la gestion des erreurs et pour rechercher un canal enregistré en son sein.
const char *fileName (in)
Le nom d'un fichier local ou réseau.
const char *mode (in)
Spécifie comment le fichier doit être accédé. Peut avoir l'une des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (in)
Indicateurs de permission de type POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront appliquées au fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans commutateur de la commande Tcl exec.
int flags (in)
Spécifie la disposition des descripteurs stdio dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, l'entrée standard du premier processus enfant du pipeline est le canal du pipeline, sinon elle est identique à l'entrée standard du processus appelant ; idem pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, alors le pipeline peut rediriger les descripteurs stdio pour outrepasser les descripteurs stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, ces redirections entraînent une erreur.
ClientData handle (in)
Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, il s'agit d'un descripteur de fichier, pour Windows, il s'agit d'un HANDLE.
int readOrWrite (in)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (in)
Le motif à faire correspondre, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl pour l'entrée ou la sortie. Doit être la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker les caractères lus depuis le canal.
int charsToRead (in)
Le nombre de caractères à lire depuis le canal. Si le codage du canal est binaire, cela équivaut au nombre d'octets à lire depuis le canal.
int appendFlag (in)
Si différent de zéro, les données lues du canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (out)
Un tampon dans lequel stocker les octets lus depuis le canal.
int bytesToRead (in)
Le nombre d'octets à lire depuis le canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker la ligne lue depuis le canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne dynamique Tcl dans laquelle stocker la ligne lue depuis le canal. Doit avoir été initialisé par l'appelant. La ligne lue sera ajoutée aux données déjà présentes dans la chaîne dynamique.
const char *input (in)
L'entrée à ajouter à un tampon de canal.
int inputLen (in)
Longueur de l'entrée
int addAtEnd (in)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon du canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera sorti vers le canal.
const char *charBuf (in)
Un tampon contenant les caractères à sortir vers le canal.
const char *byteBuf (in)
Un tampon contenant les octets à sortir vers le canal.
int bytesToWrite (in)
Le nombre d'octets à consommer de charBuf ou byteBuf et à sortir vers le canal.
Tcl_WideInt offset (in)
De combien déplacer le point d'accès dans le canal auquel la prochaine opération d'entrée ou de sortie sera appliquée, mesuré en octets depuis la position donnée par seekMode. Peut être positif ou négatif.
int seekMode (in)
Par rapport à quel point chercher ; utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs légales sont SEEK_SET, SEEK_CUR et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) à laquelle tronquer le canal.
const char *optionName (in)
Le nom d'une option applicable à ce canal, telle que -blocking. Peut avoir l'une des valeurs acceptées par la commande fconfigure.
Tcl_DString *optionValue (in)
Où stocker la valeur d'une option ou une liste de toutes les options et leurs valeurs. Doit avoir été initialisé par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des périphériques et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie mises en mémoire tampon sur une variété de types de fichiers, de sockets et de périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée du manuel de Tcl_CreateChannel. Le mécanisme de canaux fournit un schéma de mise en mémoire tampon calqué sur les E/S standard d'Unix, et il permet également les E/S non bloquantes sur les canaux.

Les procédures décrites dans cette entrée de manuel comprennent les API C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canaux et comment implémenter des pilotes de canaux pour de nouveaux types de canaux, voir l'entrée du manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Ouvre un canal pour un fichier nommé fileName avec le mode spécifié par mode et les permissions données par permissions. Le mode peut être r, w, a, r+, w+, ou a+, avec des suffixes optionnels comme b pour binaire ou t pour texte (ce dernier étant le mode par défaut). La valeur renvoyée est un handle de canal Tcl, ou NULL si une erreur s'est produite.

TCL_OPENCOMMANDCHANNEL

Ouvre un canal représentant un pipeline de commandes. Les arguments argc et argv spécifient la commande et ses arguments, qui sont exécutés via Tcl_Exec. Les flags spécifient comment les descripteurs stdio de la commande sont gérés.

TCL_MAKEFILECHANNEL

Crée un canal Tcl à partir d'un descripteur de fichier existant handle. L'argument readOrWrite spécifie si le canal est destiné à la lecture, à l'écriture, ou aux deux.

TCL_GETCHANNEL

Renvoie un handle de canal Tcl pour le canal nommé channelName enregistré dans l'interpréteur interp. Si modePtr n'est pas NULL, il est défini pour indiquer si le canal est lisible et/ou écrivable.

TCL_GETCHANNELNAMES

Renvoie une liste de tous les noms de canaux enregistrés dans l'interpréteur interp. Le résultat est stocké dans l'objet résultat de l'interpréteur.

TCL_GETCHANNELNAMESEX

Identique à Tcl_GetChannelNames, mais ne renvoie que les noms de canaux qui correspondent au pattern donné.

TCL_REGISTERCHANNEL

Enregistre un canal channel dans l'interpréteur interp, le rendant disponible pour être référencé par son nom.

TCL_UNREGISTERCHANNEL

Désenregistre un canal channel de l'interpréteur interp. Le canal sera fermé si le dernier handle de référence est supprimé.

TCL_DETACHCHANNEL

Détache le canal channel de l'interpréteur interp. Le canal n'est pas fermé, mais il ne sera plus connu de l'interpréteur. Cela est utile pour les pilotes de canaux qui gèrent la fermeture eux-mêmes.

TCL_ISTANDARDCHANNEL

Renvoie vrai si le canal channel est l'un des canaux standard (stdin, stdout, stderr).

TCL_CLOSE

Ferme le canal channel associé à l'interpréteur interp. Tous les tampons sont vidés avant la fermeture.

TCL_READCHARS

Lit jusqu'à charsToRead caractères depuis le canal channel et les stocke dans la valeur readObjPtr. Si appendFlag est vrai, les caractères lus sont ajoutés à la valeur existante ; sinon, la valeur est remplacée. Le nombre d'octets lus est renvoyé, ou -1 en cas d'erreur.

TCL_READ

Lit jusqu'à bytesToRead octets depuis le canal channel et les stocke dans le tampon readBuf. Le nombre d'octets lus est renvoyé, ou -1 en cas d'erreur.

TCL_GETSOBJ

Lit une ligne depuis le canal channel (jusqu'à un caractère de nouvelle ligne ou EOF) et la stocke dans la valeur lineObjPtr. La ligne lue est ajoutée à la valeur existante. Le nombre d'octets lus est renvoyé, ou -1 en cas d'erreur.

TCL_GETS

Lit une ligne depuis le canal channel et la stocke dans la chaîne dynamique lineRead. Le nombre d'octets lus est renvoyé, ou -1 en cas d'erreur.

TCL_UNGETS

Ajoute les données input de longueur inputLen dans le tampon d'entrée du canal channel. Si addAtEnd est vrai, les données sont ajoutées à la fin du tampon ; sinon, elles sont ajoutées au début. Renvoie 0 en cas de succès, -1 en cas d'erreur.

TCL_WRITEOBJ

Écrit le contenu de la valeur writeObjPtr vers le canal channel. Le nombre d'octets écrits est renvoyé, ou -1 en cas d'erreur.

TCL_WRITECHARS

Écrit les caractères du tampon charBuf (longueur bytesToWrite) vers le canal channel. Le nombre d'octets écrits est renvoyé, ou -1 en cas d'erreur.

TCL_WRITE

Écrit les octets du tampon byteBuf (longueur bytesToWrite) vers le canal channel. Le nombre d'octets écrits est renvoyé, ou -1 en cas d'erreur.

TCL_READRAW

Identique à Tcl_Read, mais ne procède à aucune conversion de caractères ou de fin de ligne.

TCL_WRITERAW

Identique à Tcl_Write, mais ne procède à aucune conversion de caractères ou de fin de ligne.

TCL_EOF

Renvoie vrai si la fin du fichier a été atteinte sur le canal channel.

TCL_FLUSH

Vide tous les tampons de sortie pour le canal channel. Renvoie 0 en cas de succès, -1 en cas d'erreur.

TCL_INPUTBLOCKED

Renvoie vrai si une opération de lecture sur le canal channel serait bloquante.

TCL_INPUTBUFFERED

Renvoie le nombre d'octets disponibles dans le tampon d'entrée du canal channel.

TCL_OUTPUTBUFFERED

Renvoie le nombre d'octets en attente dans le tampon de sortie du canal channel.

TCL_SEEK

Définit la position actuelle de lecture/écriture dans le canal channel à offset octets à partir du point spécifié par seekMode. Renvoie la nouvelle position en octets à partir du début du canal, ou -1 en cas d'erreur.

TCL_TELL

Renvoie la position actuelle de lecture/écriture dans le canal channel, en octets à partir du début du canal. Renvoie -1 en cas d'erreur.

TCL_TRUNCATECHANNEL

Tronque le fichier associé au canal channel à la longueur spécifiée par length. Renvoie 0 en cas de succès, -1 en cas d'erreur.

TCL_GETCHANNELOPTION

Récupère la valeur de l'option optionName pour le canal channel et la stocke dans la chaîne dynamique optionValue. Renvoie 0 en cas de succès, -1 en cas d'erreur.

TCL_SETCHANNELOPTION

Définit la valeur de l'option optionName pour le canal channel à newValue. Renvoie 0 en cas de succès, -1 en cas d'erreur.

EL'>TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et retourne un handle de canal qui peut être utilisé pour effectuer des entrées et sorties sur le fichier. Cette API est calquée sur la procédure fopen de la bibliothèque standard d'E/S d'Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur la valeur Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel dans la mesure du possible.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Elle crée une séquence de sous-processus spécifiés par les arguments argv et argc et retourne un canal qui peut être utilisé pour communiquer avec ces sous-processus. L'argument flags indique quel type de communication existera avec le pipeline de commandes.

Si le drapeau TCL_STDIN est défini, alors l'entrée standard du premier sous-processus sera liée au canal : écrire dans le canal fournira des données d'entrée au sous-processus. Si TCL_STDIN n'est pas défini, alors l'entrée standard du premier sous-processus sera la même que l'entrée standard de cette application. Si TCL_STDOUT est défini, alors la sortie standard du dernier sous-processus peut être lue depuis le canal ; sinon elle va à la sortie standard de cette application. Si TCL_STDERR est défini, la sortie d'erreur standard pour tous les sous-processus est renvoyée au canal et résulte en une erreur lors de la fermeture du canal ; sinon elle va à l'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas défini, alors argc et argv peuvent rediriger les descripteurs stdio pour remplacer TCL_STDIN, TCL_STDOUT, et TCL_STDERR ; s'il est défini, alors c'est une erreur pour argc et argv de remplacer les canaux stdio pour lesquels TCL_STDIN, TCL_STDOUT, et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un descripteur de fichier existant et spécifique à la plateforme. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel retourne un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur Tcl dans interp. Si un canal de ce nom n'est pas enregistré dans cet interpréteur, la procédure retourne NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OU de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms selon le pattern. Si pattern est NULL, alors il n'effectuera aucun filtrage. La valeur de retour est TCL_OK si aucune erreur ne s'est produite lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutant dans cet interpréteur peuvent faire référence au canal dans les opérations d'entrée ou de sortie en utilisant le nom donné lors de l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code exécutant en dehors de tout interpréteur Tcl peut appeler Tcl_RegisterChannel avec interp comme NULL, pour indiquer qu'il souhaite conserver une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et il ne sera fermé que lorsque le nombre correspondant d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code exécutant en dehors de tout interpréteur de conserver en toute sécurité une référence à un canal également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code gérant les canaux standards. Si aucun canal standard n'a été initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un exposé général sur les canaux standards et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Si cette opération a supprimé le dernier enregistrement du canal dans un interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur Tcl peut appeler Tcl_UnregisterChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera maintenant fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel sauf qu'il fermera également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Au-delà de cela, cette commande n'a aucun autre effet. Elle ne peut pas être utilisée sur les canaux standards (stdout, stderr, stdin), et retournera TCL_ERROR si on lui passe l'un de ces canaux.

Le code non associé à un interpréteur Tcl peut appeler Tcl_DetachChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standards, stdin, stdout ou stderr. Si c'est le cas, il retourne 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standards sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lors de l'appel à Tcl_Close. Les sorties mises en tampon sont vidées sur le périphérique de sortie du canal avant la destruction du canal, et toute entrée mise en tampon est rejetée. S'il s'agit d'un canal bloquant, l'appel ne retourne pas tant que toutes les données mises en tampon n'ont pas été envoyées avec succès au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a des sorties mises en tampon qui ne peuvent pas être écrites sans bloquer, l'appel retourne immédiatement ; la sortie est vidée en arrière-plan et le canal sera fermé une fois que toutes les données mises en tampon auront été sorties. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close retourne TCL_OK. Si une erreur se produit, Tcl_Close retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré en utilisant Tcl_RegisterChannel ; voir la documentation pour Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a déjà été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez plutôt utiliser Tcl_UnregisterChannel, qui appellera internement Tcl_Close lorsque tous les appels à Tcl_RegisterChannel auront été correspondus par des appels à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, convertissant les octets en UTF-8 en fonction de l'encodage du canal et stockant les données produites dans la représentation chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Définir charsToRead

pour causer que la commande lise tous les caractères actuellement disponibles (non bloquant) ou tout jusqu'à l'eof (mode bloquant).

La valeur de retour peut être plus petite que la valeur à lire, indiquant que moins de données que demandé étaient disponibles. Ceci est appelé une lecture courte. En mode bloquant, cela ne peut arriver qu'en fin de fichier. En mode non bloquant, une lecture courte peut aussi se produire s'il n'y a pas assez d'entrée actuellement disponible : Tcl_ReadChars retourne un compte court plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour savoir laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les diverses représentations de fin de ligne en la représentation interne canonique \n selon le mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les divers modes spécifiques à la plateforme sont décrits dans l'entrée du manuel de la commande Tcl fconfigure.

Comme optimisation des performances, lors de la lecture depuis un canal avec l'encodage binary, les octets ne sont pas convertis en UTF-8 lors de leur lecture. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr comme une valeur de tableau d'octets. La représentation textuelle de cette valeur ne sera construite que si elle est nécessaire (par exemple, suite à un appel à Tcl_GetStringFromObj). De cette façon, des données orientées octets peuvent être lues depuis un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites sur un canal sans le coût de conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'elle ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Elle est dépréciée et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Elle consomme des octets de channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par un caractère nul. Son contenu est valide à partir de la position zéro jusqu'à, et sans inclure, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas l'empilement. Tandis que Tcl_Read (et les autres fonctions de l'API) obtient toujours ses données du canal le plus haut dans la pile dont le canal fourni fait partie, Tcl_ReadRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer des données du canal inférieur dans la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, en convertissant les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée soit rencontrée. Si l'encodage du canal est binary, chaque octet lu depuis le canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception du ou des caractères de fin de ligne terminaux, sont ajoutés à la représentation textuelle de lineObjPtr. Le ou les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. En cas d'erreur, Tcl_GetsObj retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj retourne également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est retourné, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité d'entrée.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique fournie par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, à la tête ou à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si channel a un EOF "collant" réglé, aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets retourne inputLen ou -1 en cas d'erreur.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données textuelles à charBuf. Les caractères UTF-8 dans le tampon sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars attend que charBuf soit terminé par un caractère nul et sort tout jusqu'au caractère nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou réglez l'option -buffering sur le canal sur none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, réglez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un compte du nombre d'octets qui ont été acceptés pour la sortie vers le canal. Ceci est soit supérieur à zéro pour indiquer le succès, soit -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme selon l'option -translation du canal. Ceci est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'il accepte une valeur Tcl dont le contenu sera sorti vers le canal. Les caractères UTF-8 dans la représentation textuelle de writeObjPtr sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. Comme optimisation des performances, lors de l'écriture sur un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets dans la représentation interne de writeObjPtr en tant que valeur de tableau d'octets sont écrits sur le canal. La représentation en tableau d'octets de la valeur sera construite si elle est nécessaire. De cette façon, des données orientées octets peuvent être lues depuis un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites sur un canal sans le coût de conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'elle ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Elle est dépréciée et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Elle accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write attend que byteBuf soit terminé par un caractère nul et sort tout jusqu'au caractère nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas l'empilement. Tandis que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée dans le canal le plus haut dans la pile dont le canal fourni fait partie, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer des données de la transformation dans le canal inférieur.

TCL_FLUSH

Tcl_Flush force toutes les données de sortie tamponnées pour le channel à être écrites dans son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données tamponnées n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal n'est pas bloquant ; il démarre une opération de vidage en arrière-plan qui écrira les données tamponnées dans le canal éventuellement, aussi vite que le canal pourra les absorber.

La valeur de retour est normalement TCL_OK. En cas d'erreur, Tcl_Flush retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans le channel où les données ultérieures seront lues ou écrites. La sortie tamponnée est vidée vers le canal et l'entrée tamponnée est discardée, avant l'opération de recherche.

Tcl_Seek retourne normalement le nouveau point d'accès. En cas d'erreur, Tcl_Seek retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut ou peut ne pas avoir été déplacé.

TCL_TELL

Tcl_Tell retourne le point d'accès actuel d'un canal. La valeur retournée est -1 si le canal ne supporte pas la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent du channel à une longueur donnée de length octets. Il retourne TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, il s'agit du nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue, en utilisant

TCL_GETCHANNELOPTION

La procédure Tcl_GetChannelOption retourne la valeur de l'option optionName pour le canal channel. La valeur est stockée dans le champ valuePtr de la structure Tcl_ChannelType et est retournée sous forme de chaîne Tcl. Si optionName fait référence à une option de configuration générale, la valeur est retournée directement. Si l'option fait référence à une option spécifique à un type de canal, alors cette option est gérée par le pilote de canal du type de canal concerné. Les options spécifiques à un canal sont décrites dans la page de manuel de la commande Tcl qui crée un canal de ce type ; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans la page de manuel de la commande Tcl socket. La procédure retourne normalement TCL_OK. Si une erreur se produit, elle retourne TCL_ERROR et appelle Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

La procédure stocke la valeur de l'option dans le champ valuePtr de la structure Tcl_ChannelType, qui est une structure qui contient des pointeurs vers des procédures pour chaque type de canal. Ce champ est une chaîne Tcl, retournée par une série d'appels à Tcl_DStringAppendElement. Les diverses options préexistantes et leurs valeurs possibles sont décrites dans la page de manuel de la commande Tcl fconfigure. D'autres options peuvent être ajoutées par chaque type de canal. Ces options spécifiques au type de canal sont décrites dans la page de manuel de la commande Tcl qui crée un canal de ce type ; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans la page de manuel de la commande Tcl socket. La procédure retourne normalement TCL_OK. Si une erreur se produit, elle retourne TCL_ERROR et appelle Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit une nouvelle valeur newValue pour une option optionName sur le canal channel. La procédure retourne normalement TCL_OK. Si une erreur se produit, elle retourne TCL_ERROR ; de plus, si interp n'est pas NULL, Tcl_SetChannelOption laisse un message d'erreur dans le résultat de l'interpréteur.

TCL_EOF

Tcl_Eof retourne une valeur non nulle si le canal channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked retourne une valeur non nulle si le canal channel est en mode non bloquant et que la dernière opération d'entrée a retourné moins de données que demandé car il n'y avait pas suffisamment de données disponibles. L'appel retourne toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered retourne le nombre d'octets d'entrée actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en lecture, cette fonction retourne toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered retourne le nombre d'octets de sortie actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en écriture, cette fonction retourne toujours zéro.

PLATFORM ISSUES

Les descripteurs retournés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que retourné par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel, ou Tcl_MakeFileChannel. D'autres types de canaux peuvent retourner un type différent de descripteur sur les plateformes Windows.
