Tcl_Finalize(3)

Paquet: tcl

Licences: TCL

Tcl_Exit(3) Procédures de la bibliothèque Tcl Tcl_Exit(3)

NOM

Tcl_Exit, Tcl_Finalize, Tcl_CreateExitHandler, Tcl_DeleteExitHandler, Tcl_ExitThread, Tcl_FinalizeThread, Tcl_CreateThreadExitHandler, Tcl_DeleteThreadExitHandler, Tcl_SetExitProc - terminer l'application ou le thread (et invoquer les gestionnaires de sortie)

SYNOPSIS

#include <tcl.h>

Tcl_Exit(status)

Tcl_Finalize()

Tcl_CreateExitHandler(proc, clientData)

Tcl_DeleteExitHandler(proc, clientData)

Tcl_ExitThread(status)

Tcl_FinalizeThread()

Tcl_CreateThreadExitHandler(proc, clientData)

Tcl_DeleteThreadExitHandler(proc, clientData)

Tcl_ExitProc *
Tcl_SetExitProc(proc)

ARGUMENTS

int status (entrée)
Fournit des informations sur la raison de la sortie de l'application ou du thread. La signification exacte peut varier selon la plateforme. 0 signifie généralement une sortie normale, toute valeur non nulle signifie généralement qu'une erreur s'est produite.
Tcl_ExitProc *proc (entrée)
Procédure à invoquer avant la sortie de l'application, ou (pour Tcl_SetExitProc) NULL pour désinstaller la procédure de sortie d'application actuelle.
ClientData clientData (entrée)
Valeur arbitraire d'un mot à passer à proc.

DESCRIPTION

Les procédures décrites ici fournissent un mécanisme de sortie propre pour terminer l'exécution d'une application Tcl. Les gestionnaires de sortie sont invoqués pour nettoyer l'état de l'application avant de terminer l'exécution du code Tcl.

Invoquez Tcl_Exit pour terminer une application Tcl et quitter ce processus. Cette procédure est invoquée par la commande exit, et peut être invoquée n'importe où ailleurs pour terminer l'application. Personne ne devrait jamais invoquer la procédure système exit directement ; invoquez toujours Tcl_Exit à la place, afin qu'elle puisse invoquer les gestionnaires de sortie. Notez que si un autre code invoque directement la procédure système exit, ou cause autrement la terminaison de l'application sans appeler Tcl_Exit, les gestionnaires de sortie ne seront pas exécutés. Tcl_Exit invoque en interne l'appel système exit, donc elle ne retourne jamais le contrôle à son appelant. Si un gestionnaire de sortie d'application a été installé (voir Tcl_SetExitProc), ce gestionnaire est invoqué avec un argument constitué du code de sortie (cast en ClientData) ; le gestionnaire de sortie d'application ne doit pas retourner le contrôle à Tcl.

Tcl_Finalize est similaire à Tcl_Exit sauf qu'elle ne quitte pas le processus actuel. Elle est utile pour le nettoyage lorsqu'un processus a fini d'utiliser Tcl mais souhaite continuer son exécution, et lorsque Tcl est utilisé dans une extension chargée dynamiquement qui est sur le point d'être déchargée. Votre code doit toujours invoquer Tcl_Finalize lorsque Tcl est déchargé, pour assurer un nettoyage approprié. Tcl_Finalize peut être appelée plusieurs fois sans danger.

Tcl_ExitThread est utilisée pour terminer le thread courant et invoquer les gestionnaires de sortie par thread. Cette finalisation est effectuée par Tcl_FinalizeThread, que vous pouvez appeler si vous voulez seulement nettoyer l'état par thread et invoquer les gestionnaires de sortie de thread. Tcl_Finalize appelle Tcl_FinalizeThread pour le thread courant automatiquement.

Tcl_CreateExitHandler arrange pour que proc soit invoqué par Tcl_Finalize et Tcl_Exit. Tcl_CreateThreadExitHandler arrange pour que proc soit invoqué par Tcl_FinalizeThread et Tcl_ExitThread. Cela fournit un crochet pour les opérations de nettoyage telles que le vidage des tampons et la libération de la mémoire globale. Proc doit correspondre au type Tcl_ExitProc :

typedef void Tcl_ExitProc(
        ClientData clientData);

Le paramètre clientData de proc est une copie de l'argument clientData donné à Tcl_CreateExitHandler ou Tcl_CreateThreadExitHandler lors de la création du rappel. Typiquement, clientData pointe vers une structure de données contenant des informations spécifiques à l'application sur ce qu'il faut faire dans proc.

Tcl_DeleteExitHandler et Tcl_DeleteThreadExitHandler peuvent être appelés pour supprimer un gestionnaire de sortie précédemment créé. Ils suppriment le gestionnaire indiqué par proc et clientData afin qu'aucun appel à proc ne soit effectué. S'il n'existe aucun gestionnaire de ce type, Tcl_DeleteExitHandler ou Tcl_DeleteThreadExitHandler ne fait rien.

Tcl_Finalize et Tcl_Exit exécutent tous les gestionnaires de sortie enregistrés, dans l'ordre inverse de leur enregistrement. Cela correspond à l'ordre naturel dans lequel les extensions sont chargées et déchargées ; si l'extension A charge l'extension B, elle décharge généralement B avant d'être elle-même déchargée. Si l'extension A enregistre ses gestionnaires de sortie avant de charger l'extension B, cela garantit que tous les gestionnaires de sortie pour B seront exécutés avant les gestionnaires de sortie pour A.

Tcl_Finalize et Tcl_Exit appellent Tcl_FinalizeThread et les gestionnaires de sortie de thread après les gestionnaires de sortie globaux. C'est parce que la finalisation des threads arrête le système de canaux d'E/S, donc toute tentative d'E/S par les gestionnaires de sortie globaux sera perdue.

Tcl_SetExitProc installe un gestionnaire de sortie d'application, retournant le gestionnaire de sortie d'application précédemment installé ou NULL si aucun gestionnaire d'application n'était installé. Si un gestionnaire de sortie d'application est installé, ce gestionnaire prend la responsabilité complète de la finalisation des sous-systèmes de Tcl via Tcl_Finalize à un moment approprié. L'argument passé à proc lors de son invocation sera le code de statut de sortie (tel que passé à Tcl_Exit) casté en valeur ClientData.
