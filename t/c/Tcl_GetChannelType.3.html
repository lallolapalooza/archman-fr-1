DESCRIPTION

Tcl utilise une architecture de canaux à deux couches. Elle fournit une couche supérieure générique pour permettre aux programmes C et Tcl d'effectuer des entrées et sorties en utilisant les mêmes API pour une variété de fichiers, périphériques, sockets, etc. Les API C génériques sont décrites dans l'entrée man de Tcl_OpenFileChannel.

La couche inférieure fournit des pilotes de canaux spécifiques au type pour chaque type de périphérique supporté sur chaque plateforme. Cette entrée man décrit les API C utilisées pour communiquer entre la couche générique et les pilotes de canaux spécifiques au type. Elle explique également comment de nouveaux types de canaux peuvent être ajoutés en fournissant de nouveaux pilotes de canaux.

Les pilotes de canaux se composent d'un certain nombre de composants : Premièrement, chaque pilote de canal fournit une structure Tcl_ChannelType contenant des pointeurs vers des fonctions implémentant les diverses opérations utilisées par la couche générique pour communiquer avec le pilote de canal. La structure Tcl_ChannelType et les fonctions auxquelles elle fait référence sont décrites dans la section TCL_CHANNELTYPE, ci-dessous.

Deuxièmement, les pilotes de canaux fournissent généralement une commande Tcl pour créer des instances de ce type de canal. Par exemple, la commande Tcl open crée des canaux qui utilisent les pilotes de canaux de fichiers et de commandes, et la commande Tcl socket crée des canaux qui utilisent des sockets TCP pour la communication réseau.

Troisièmement, un pilote de canal fournit éventuellement une fonction C pour ouvrir des instances de canal de ce type. Par exemple, Tcl_OpenFileChannel ouvre un canal qui utilise le pilote de canal de fichier, et Tcl_OpenTcpClient ouvre un canal qui utilise le protocole réseau TCP. Ces fonctions de création utilisent généralement Tcl_CreateChannel en interne pour ouvrir le canal.

Pour ajouter un nouveau type de canal, vous devez implémenter une API C ou une commande Tcl qui ouvre un canal en appelant Tcl_CreateChannel. Lorsque votre pilote appelle Tcl_CreateChannel, il transmet une structure Tcl_ChannelType décrivant les procédures d'E/S du pilote. La couche générique invoquera alors les fonctions référencées dans cette structure pour effectuer des opérations sur le canal.

Tcl_CreateChannel ouvre un nouveau canal et lui associe le typePtr et le instanceData fournis. Le canal est ouvert dans le mode indiqué par mask. Pour une discussion sur les pilotes de canaux, leurs opérations et la structure Tcl_ChannelType, voir la section TCL_CHANNELTYPE, ci-dessous.

Tcl_CreateChannel interagit avec le code gérant les canaux standards. Une fois qu'un canal standard a été initialisé soit par un appel à Tcl_GetStdChannel, soit par un appel à Tcl_SetStdChannel, la fermeture de ce canal standard entraînera le fait que le prochain appel à Tcl_CreateChannel fera également du nouveau canal le nouveau canal standard. Voir Tcl_StandardChannels pour un traité général sur les canaux standards et le comportement de la bibliothèque Tcl à leur égard.

Tcl_GetChannelInstanceData renvoie les données d'instance associées au canal dans channel. C'est la même chose que l'argument instanceData dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelType renvoie un pointeur vers la structure Tcl_ChannelType utilisée par le canal dans l'argument channel. C'est la même chose que l'argument typePtr dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelName renvoie une chaîne contenant le nom associé au canal, ou NULL si l'argument channelName de Tcl_CreateChannel était NULL.

TCL_CHANNELTYPE

Un pilote de canal fournit une structure Tcl_ChannelType contenant des pointeurs vers des fonctions qui implémentent les diverses opérations sur un canal ; ces opérations sont appelées au besoin par la couche générale. La structure a été versionnée à partir de Tcl 8.3.2/8.4 pour corriger un problème avec les pilotes de canaux empilés. Voir la section OLD CHANNEL TYPES pour des détails sur l'ancienne structure.

La structure Tcl_ChannelType contient les champs suivants :

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Il n'est pas nécessaire de fournir des implémentations pour toutes les opérations de canal. Celles qui ne sont pas nécessaires peuvent être définies sur NULL dans la structure : blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc et close2Proc, en plus de flushProc, handlerProc, threadActionProc et truncateProc. Les autres fonctions qui ne peuvent pas être implémentées de manière significative doivent renvoyer EINVAL lorsqu'elles sont appelées, indiquant que les opérations qu'elles représentent ne sont pas disponibles. Il convient également de noter que wideSeekProc peut être NULL si seekProc ne l'est pas.

L'utilisateur ne doit utiliser que cette structure pour l'instanciation de Tcl_ChannelType. Lorsque vous faites référence aux champs d'une structure Tcl_ChannelType, vous devez utiliser les fonctions suivantes pour obtenir les valeurs : Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc, ou Tcl_ChannelHandlerProc.

Le changement dans les structures a été effectué de manière à ce que les types de canaux standard soient binaires compatibles. Cependant, les types de canaux qui utilisent des canaux empilés (c'est-à-dire TLS, Trf) ont de nouvelles versions correspondant au changement précédent en raison de problèmes dans le code précédent des canaux empilés.

TYPENAME

Le champ typeName contient une chaîne terminée par NULL qui identifie le type de périphérique implémenté par ce pilote, par exemple, file ou socket.

Cette valeur peut être obtenue avec Tcl_ChannelName, qui renvoie un pointeur vers la chaîne.

VERSION

Le champ version doit être défini à la version de la structure dont vous avez besoin. TCL_CHANNEL_VERSION_2 est le minimum recommandé. TCL_CHANNEL_VERSION_3 doit être défini pour spécifier le champ wideSeekProc. TCL_CHANNEL_VERSION_4 doit être défini pour spécifier le champ threadActionProc (inclut wideSeekProc). TCL_CHANNEL_VERSION_5 doit être défini pour spécifier les champs truncateProc (inclut wideSeekProc et threadActionProc). Si aucun de ceux-ci n'est défini, la structure originale est supposée pour Tcl_ChannelType. Voir OLD CHANNEL TYPES pour plus de détails. Bien que Tcl reconnaisse et fonctionne avec chacune de ces structures, les canaux empilés doivent avoir au moins TCL_CHANNEL_VERSION_2 pour fonctionner correctement.

Cette valeur peut être obtenue avec Tcl_ChannelVersion, qui renvoie l'une des valeurs TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 ou TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

Le champ blockModeProc contient l'adresse d'une fonction appelée par la couche générale pour définir le mode de blocage et de non-blocage du périphérique. BlockModeProc doit correspondre au prototype suivant :

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

instanceData est le même que la valeur passée à Tcl_CreateChannel lorsque ce canal a été créé. L'argument mode est soit TCL_MODE_BLOCKING, soit TCL_MODE_NONBLOCKING pour définir le périphérique en mode bloquant ou non bloquant. La fonction doit renvoyer zéro si l'opération a réussi, ou un code d'erreur POSIX non nul si l'opération a échoué.

Si l'opération a réussi, la fonction peut modifier le instanceData fourni pour enregistrer que le canal est entré en mode bloquant ou non bloquant et pour implémenter le comportement de blocage ou de non-blocage. Pour certains types de périphériques, le comportement de blocage et de non-blocage peut être implémenté par le système d'exploitation sous-jacent ; pour d'autres types de périphériques, le comportement doit être émulé dans le pilote de canal.

Cette valeur peut être obtenue avec Tcl_ChannelBlockModeProc, qui renvoie un pointeur vers la fonction.

Un pilote de canal qui ne fournit pas de blockModeProc doit être très prudent. Il doit indiquer exactement quel mode de blocage lui convient, et il doit le documenter pour l'utilisateur afin que le mode de blocage du canal ne soit pas modifié à une valeur inacceptable. Toute confusion ici pourrait conduire l'interpréteur à une collision (fantôme et difficile à trouver).

CLOSEPROC ET CLOSE2PROC

Le champ closeProc contient l'adresse d'une fonction appelée par la couche générale pour nettoyer les informations liées au pilote lorsque le canal est fermé. CloseProc doit correspondre au prototype suivant :

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

L'argument instanceData est le même que la valeur fournie à Tcl_CreateChannel lorsque ce canal a été créé. La fonction doit libérer toute mémoire conservée par le pilote de canal pour ce canal, et fermer les périphériques d'entrée et de sortie encapsulés par ce canal. Avant d'appeler cette fonction, toutes les sorties en file d'attente ont été vidées sur le périphérique. Aucune autre opération du pilote ne sera appelée après l'appel de closeProc. DESCRIPTION

A Tcl channel is an object that represents an open I/O channel, such as a file, pipe, or socket. This section describes the core channel management functions and the structure of channel drivers, which are implemented by Tcl extensions or applications.

A channel driver is a collection of C procedures that implement specific I/O operations for a channel. These procedures are registered with the Tcl core when a channel is created by calling Tcl_CreateChannel. The Tcl core then invokes these driver procedures as needed to perform I/O operations on the channel. A channel driver is represented by a Tcl_ChannelType structure, which contains pointers to the driver's procedures and other information:

typedef struct Tcl_ChannelType {
    const char *name;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetReadyProc *getReadyProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverThreadActionProc *threadActionProc;
    Tcl_DriverWideSeekProc *wideSeekProc;
    Tcl_DriverThreadActionProc *threadActionProc;
} Tcl_ChannelType;

The fields of this structure are described below:

NAME FIELD

The name field is a string that uniquely identifies the channel type. For example, "file", "socket", or "pipe".

CLOSEPROC AND CLOSE2PROC

The closeProc field contains the address of a function that is called by the generic layer to close the channel. CloseProc must match the following prototype:

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

The instanceData argument is the same value that was passed to Tcl_CreateChannel when the channel was created. The function should perform any necessary cleanup for the channel, such as releasing resources or closing underlying file descriptors. The function should return zero if the close operation was successful; otherwise it should return a nonzero POSIX error code. In addition, if an error occurs and interp is not NULL, the procedure should store an error message in the interpreter's result.

Alternatively, channels that support closing the read and write sides independently may set closeProc to TCL_CLOSE2PROC and set close2Proc to the address of a function that matches the following prototype:

typedef int Tcl_DriverClose2Proc(
        ClientData instanceData,
        Tcl_Interp *interp,
        int flags);

The close2Proc will be called with flags set to an OR'ed combination of TCL_CLOSE_READ or TCL_CLOSE_WRITE to indicate that the driver should close the read and/or write side of the channel. The channel driver may be invoked to perform additional operations on the channel after close2Proc is called to close one or both sides of the channel. If flags is 0 (zero), the driver should close the channel in the manner described above for closeProc. No further operations will be invoked on this instance after close2Proc is called with all flags cleared. In all cases, the close2Proc function should return zero if the close operation was successful; otherwise it should return a nonzero POSIX error code. In addition, if an error occurs and interp is not NULL, the procedure should store an error message in the interpreter's result.

The closeProc and close2Proc values can be retrieved with Tcl_ChannelCloseProc or Tcl_ChannelClose2Proc, which return a pointer to the respective function.

INPUTPROC

The inputProc field contains the address of a function called by the generic layer to read data from the file or device and store it in an internal buffer. InputProc must match the following prototype:

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

InstanceData is the same as the value passed to Tcl_CreateChannel when the channel was created. The buf argument points to an array of bytes in which to store input from the device, and the bufSize argument indicates how many bytes are available at buf.

The errorCodePtr argument points to an integer variable provided by the generic layer. If an error occurs, the function should set the variable to a POSIX error code that identifies the error that occurred.

The function should read data from the input device encapsulated by the channel and store it at buf. On success, the function should return a nonnegative integer indicating how many bytes were read from the input device and stored at buf. On error, the function should return -1. If an error occurs after some data has been read from the device, that data is lost.

If inputProc can determine that the input device has some data available but less than requested by the bufSize argument, the function should only attempt to read as much data as is available and return without blocking. If the input device has no data available whatsoever and the channel is in nonblocking mode, the function should return an EAGAIN error. If the input device has no data available whatsoever and the channel is in blocking mode, the function should block for the shortest possible time until at least one byte of data can be read from the device; then, it should return as much data as it can read without blocking.

This value can be retrieved with Tcl_ChannelInputProc, which returns a pointer to the function.

OUTPUTPROC

The outputProc field contains the address of a function called by the generic layer to transfer data from an internal buffer to the output device. OutputProc must match the following prototype:

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

InstanceData is the same as the value passed to Tcl_CreateChannel when the channel was created. The buf argument contains an array of bytes to be written to the device, and the toWrite argument indicates how many bytes are to be written from the buf argument.

The errorCodePtr argument points to an integer variable provided by the generic layer. If an error occurs, the function should set this variable to a POSIX error code that identifies the error.

The function should write the data at buf to the output device encapsulated by the channel. On success, the function should return a nonnegative integer indicating how many bytes were written to the output device. The return value is normally the same as toWrite, but may be less in some cases such as if the output operation is interrupted by a signal. If an error occurs the function should return -1. In case of error, some data may have been written to the device.

If the channel is nonblocking and the output device is unable to absorb any data whatsoever, the function should return -1 with an EAGAIN error without writing any data.

This value can be retrieved with Tcl_ChannelOutputProc, which returns a pointer to the function.

SEEKPROC AND WIDESEEKPROC

The seekProc field contains the address of a function called by the generic layer to move the access point at which subsequent input or output operations will be applied. SeekProc must match the following prototype:

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

The instanceData argument is the same as the value given to Tcl_CreateChannel when this channel was created. Offset and seekMode have the same meaning as for the Tcl_Seek procedure (described in the manual entry for Tcl_OpenFileChannel).

The errorCodePtr argument points to an integer variable provided by the generic layer for returning errno values from the function. The function should set this variable to a POSIX error code if an error occurs. The function should store an EINVAL error code if the channel type does not implement seeking.

The return value is the new access point or -1 in case of error. If an error occurred, the function should not move the access point.

If there is a non-NULL seekProc field, the wideSeekProc field may contain the address of an alternative function to use which handles wide (i.e. larger than 32-bit) offsets, so allowing seeks within files larger than 2GB. The wideSeekProc will be called in preference to the seekProc, but both must be defined if the wideSeekProc is defined. WideSeekProc must match the following prototype:

typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

The arguments and return values mean the same thing as with seekProc above, except that the type of offsets and the return type are different.

The seekProc value can be retrieved with Tcl_ChannelSeekProc, which returns a pointer to the function, and similarly the wideSeekProc can be retrieved with Tcl_ChannelWideSeekProc.

SETOPTIONPROC

The setOptionProc field contains the address of a function called by the generic layer to set a channel type specific option on a channel. setOptionProc must match the following prototype:

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

optionName is the name of an option to set, and newValue is the new value for that option, as a string. The instanceData is the same as the value given to Tcl_CreateChannel when this channel was created. The function should do whatever channel type specific action is required to implement the new value of the option.

Some options are handled by the generic code and this function is never called to set them, e.g. -blockmode. Other options are specific to each channel type and the setOptionProc procedure of the channel driver will get called to implement them. The setOptionProc field can be NULL, which indicates that this channel type supports no type specific options.

If the option value is successfully modified to the new value, the function returns TCL_OK. It should call Tcl_BadChannelOption which itself returns TCL_ERROR if the optionName is unrecognized. If newValue specifies a value for the option that is not supported or if a system call error occurs, the function should leave an error message in the result of interp if interp is not NULL. The function should also call Tcl_SetErrno to store an appropriate POSIX error code.

This value can be retrieved with Tcl_ChannelSetOptionProc, which returns a pointer to the function.

GETOPTIONPROC

The getOptionProc field contains the address of a function called by the generic layer to get the value of a channel type specific option on a channel. getOptionProc must match the following prototype:

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        Tcl_DString *optionValue);

OptionName is the name of an option supported by this type of channel. If the option name is not NULL, the function stores its current value, as a string, in the Tcl dynamic string optionValue. If optionName is NULL, the function stores in optionValue an alternating list of all supported options and their current values. On success, the function returns TCL_OK. It should call Tcl_BadChannelOption which itself returns TCL_ERROR if the optionNa

Mantener la estructura completa del archivo. Desconocido para mí. Si ocurre un error del sistema de llamadas, la función debe dejar un mensaje de error en el resultado de interp si interp no es NULL. La función también debe llamar a Tcl_SetErrno para almacenar un código de error POSIX apropiado. Algunas opciones son gestionadas por el código genérico y esta función nunca se llama para recuperar su valor, por ejemplo, -blockmode. Otros tipos de opciones son específicos de cada tipo de canal y la función getOptionProc del driver del canal se llama para implementarlas. El campo getOptionProc puede ser NULL, lo cual indica que este tipo de canal no soporta opciones específicas. Este valor puede ser recuperado mediante Tcl_ChannelGetOptionProc, que devuelve un puntero a la función.

WATCHPROC

El campo watchProc contiene la dirección de una función llamada por el nivel general para inicializar el mecanismo de notificación de eventos de interés en este canal. WatchProc debe corresponder al siguiente prototipo:

typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

El instanceData es el mismo que el valor pasado a Tcl_CreateChannel cuando este canal fue creado. El mask es una combinación OR de TCL_READABLE, TCL_WRITABLE y TCL_EXCEPTION; indica los eventos que el usuario quiere notificar en este canal.

La función debe inicializar mecanismos específicos de tipo de dispositivo para notificar cuando un evento de interés está presente en el canal. Cuando ocurre un evento de interés en el canal, el driver del canal debe llamar a Tcl_NotifyChannel para informar al modulo del canal general. El driver debe evitar que otros drivers de canal o fuentes de callbacks se bloqueen al invocar Tcl_NotifyChannel demasiado frecuentemente. La justicia puede asegurarse mediante el uso de la cola de eventos de Tcl para programar el evento del canal en secuencia con otros eventos. Vea la descripción de Tcl_QueueEvent para detalles de cómo programar un evento.

Este valor puede ser recuperado mediante Tcl_ChannelWatchProc, que devuelve un puntero a la función.

GETHANDLEPROC

El campo getHandleProc contiene la dirección de una función llamada por el nivel general para recuperar un handle específico del canal. GetHandleProc debe corresponder al siguiente prototipo:

typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

InstanceData es el mismo que el valor pasado a Tcl_CreateChannel cuando este canal fue creado. El direction es either TCL_READABLE para recuperar el handle utilizado para entrada, o TCL_WRITABLE para recuperar el handle utilizado para salida.

Si el implementación del canal tiene handles específicos, la función debe recuperar el handle adecuado según el argumento direction. El handle debe estar almacenado en el lugar referido por handlePtr, y TCL_OK debe devolverse. Si el canal no está abierto para la dirección especificada, o si la implementación del canal no usa handles específicos, la función debe devolver TCL_ERROR.

Este valor puede ser recuperado mediante Tcl_ChannelGetHandleProc, que devuelve un puntero a la función.

FLUSHPROC

El campo flushProc es actualmente reservado para el uso futuro. Debe ser establecido a NULL. FlushProc debe corresponder al siguiente prototipo:

typedef int Tcl_DriverFlushProc(
        ClientData instanceData);

Este valor puede ser recuperado mediante Tcl_ChannelFlushProc, que devuelve un puntero a la función.

HANDLERPROC

El campo handlerProc contiene la dirección de una función llamada por el nivel general para notificar al canal que un evento ocurrió. Debe ser definido para drivers de canal estackados que desean notificarse de eventos que ocurren en el canal subyacente (estackado). HandlerProc debe corresponder al siguiente prototipo:

typedef int Tcl_DriverHandlerProc(
        ClientData instanceData,
        int interestMask);

InstanceData es el mismo que el valor pasado a Tcl_CreateChannel cuando este canal fue creado. El interestMask es una combinación OR de TCL_READABLE o TCL_WRITABLE; indica el tipo de evento que ocurrió en este canal.

Este valor puede ser recuperado mediante Tcl_ChannelHandlerProc, que devuelve un puntero a la función.

THREADACTIONPROC

El campo threadActionProc contiene la dirección de la función llamada por el nivel general cuando un canal es creado, cerrado o se mueve a un otro hilo, es decir, cuando el estado de driver específico a la hora de ser inicializado o actualizado podría tener que ser inicializado o actualizado. Puede ser NULL. La acción TCL_CHANNEL_THREAD_REMOVE se usa para notificar al driver que debe actualizar o eliminar cualquier dato específico que podría mantener por el canal.

La acción TCL_CHANNEL_THREAD_INSERT se usa para notificar al driver que debe actualizar o inicializar cualquier dato específico que podría mantener utilizando el hilo actual como asociado. Vea Tcl_CutChannel y Tcl_SpliceChannel para más detalles.

typedef void Tcl_DriverThreadActionProc(
        ClientData instanceData,
        int action);

InstanceData es el mismo que el valor pasado a Tcl_CreateChannel cuando este canal fue creado.

Estos valores pueden ser recuperados mediante Tcl_ChannelThreadActionProc, que devuelve un puntero a la función.

TRUNCATEPROC

El campo truncateProc contiene la dirección de la función llamada por el nivel general cuando un canal es truncado a un largo específico. Puede ser NULL.

typedef int Tcl_DriverTruncateProc(
        ClientData instanceData,
        Tcl_WideInt length);

InstanceData es el mismo que el valor pasado a Tcl_CreateChannel cuando este canal fue creado, y length es el nuevo largo del archivo subyacente, que no debe ser negativo. El resultado debe ser 0 en éxito o un código de error (apropiado para el uso con Tcl_SetErrno) en el caso de fracaso.

Estos valores pueden ser recuperados mediante Tcl_ChannelTruncateProc, que devuelve un puntero a la función.

TCL_BADCHANNELOPTION

Este procedimiento genera un mensaje de error "bad option" en un (opcional) interprete. Se usa por los drivers de canal cuando se solicita una opción inválida. Su propósito es concatenar la lista de opciones generales al de las específicas y factorizar el mensaje de error de las opciones generales.

Siempre devuelve TCL_ERROR.

Un mensaje de error se genera en el valor de resultado de interp para indicar que se invocó una comandos con un opción inválida. El mensaje tiene la forma

    bad option "blah": should be one of
    <...generic options...>+<...specific options...>
así por ejemplo: 
    bad option "-blah": should be one of -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, or -sockname
cuando se llame con optionList igual a "peername sockname".

"blah" es el optionName argumento y <specific options> es una lista de palabras específicas separadas por espacios. La función se encarga de insertar guiones negativos antes de cada opción, comas después y un "or" antes de la última opción.

OLD CHANNEL TYPES

El estructura original (Tcl_ChannelType) de (8.3.1 y por debajo) contiene los siguientes campos:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
} Tcl_ChannelType;

A pesar de que aún se puede crear un canal con la estructura anterior, el código interno del canal determina la versión. Es esencial utilizar la nueva estructura Tcl_ChannelType cuando se crea un driver de canal estackado, debido a problemas en la implementación anterior de canales estackados (8.2.0 a 8.3.1).

Antes de 8.4.0 (es decir, durante las posteriorizaciones de 8.3 y el primer cuarto del desarrollo de 8.4) la estructura Tcl_ChannelType contenía los siguientes campos:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_ChannelTypeVersion version;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Cuando la estructura anterior es registrada como tipo de canal, el campo version debe siempre ser TCL_CHANNEL_VERSION_2.

NAME

Tcl_GetChannelType - retrieve information about a Tcl channel type

SYNOPSIS

#include <tcl.h>

const Tcl_ChannelType *
Tcl_GetChannelType(const char *typeName)

ARGUMENTS

char *typeName (in)
Name of the channel type to retrieve.

DESCRIPTION

The Tcl_GetChannelType function returns a pointer to the Tcl_ChannelType structure associated with the channel type named typeName. If no channel type with that name is registered, it returns NULL.

Channel types are registered using Tcl_CreateChannelType.

TCL_CHANNELTYPE

The Tcl_ChannelType structure is defined as follows:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockProc *blockProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverConvertHandleProc *convertHandleProc;
    int (TCL_HASH_SPECIAL_RETURN *flags);
} Tcl_ChannelType;

The fields are:

typeName
The name of the channel type. This is a static string that must not be modified.
blockProc
Procedure to call for blocking operations. May be NULL.
closeProc
Procedure to call for closing the channel. May be NULL.
inputProc
Procedure to call for input operations. May be NULL.
outputProc
Procedure to call for output operations. May be NULL.
seekProc
Procedure to call for seeking operations. May be NULL.
setOptionProc
Procedure to call for setting channel options. May be NULL.
getOptionProc
Procedure to call for getting channel options. May be NULL.
watchProc
Procedure to call for watching channel events. May be NULL.
getHandleProc
Procedure to call for getting the channel's underlying handle. May be NULL.
convertHandleProc
Procedure to call for converting the channel's underlying handle. May be NULL.
flags
A bitmask of flags that control the behavior of the channel type. Possible flags include TCL_CHANNEL_READABLE, TCL_CHANNEL_WRITABLE, TCL_CHANNEL_NONBLOCKING, etc. See the Tcl manual for a complete list.

TCL_BADCHANNELOPTION

If the channel type does not support a requested option, the setOptionProc or getOptionProc should return TCL_BADCHANNELOPTION.

OLD CHANNEL TYPES

Older versions of Tcl used a different structure for channel types. This function is compatible with both old and new channel types.
