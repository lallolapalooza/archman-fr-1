ARGUMENTS

Tcl_Interp *interp (en entrée)
Utilisé pour le reporting d'erreurs et pour rechercher un canal enregistré en son sein.
const char *fileName (en entrée)
Le nom d'un fichier local ou réseau.
const char *mode (en entrée)
Spécifie comment le fichier doit être accédé. Peut prendre l'une des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (en entrée)
Indicateurs de permissions de style POSIX, tels que 0644. Si un nouveau fichier est créé, ces permissions seront appliquées au fichier créé.
int argc (en entrée)
Le nombre d'éléments dans argv.
const char **argv (en entrée)
Arguments pour construire un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans option de la commande Tcl exec.
int flags (en entrée)
Spécifie la disposition des descripteurs standard dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, stdin pour le premier processus enfant dans le pipeline est le canal de tube, sinon il est identique à l'entrée standard du processus appelant ; de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, le tube peut rediriger les descripteurs standard pour outrepasser les descripteurs standard pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, de telles redirections entraînent une erreur.
ClientData handle (en entrée)
Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, il s'agit d'un descripteur de fichier, pour Windows, c'est un HANDLE.
int readOrWrite (en entrée)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (en entrée)
Le nom du canal.
int *modePtr (sortie)
Pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (en entrée)
Le motif à faire correspondre, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (en entrée)
Un canal Tcl pour l'entrée ou la sortie. Doit être la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (entrée/sortie)
Un pointeur vers une valeur Tcl dans laquelle stocker les caractères lus depuis le canal.
int charsToRead (en entrée)
Le nombre de caractères à lire depuis le canal. Si l'encodage du canal est binary, cela équivaut au nombre d'octets à lire depuis le canal.
int appendFlag (en entrée)
Si non nul, les données lues depuis le canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (sortie)
Un tampon dans lequel stocker les octets lus depuis le canal.
int bytesToRead (en entrée)
Le nombre d'octets à lire depuis le canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (entrée/sortie)
Un pointeur vers une valeur Tcl dans laquelle stocker la ligne lue depuis le canal. La ligne lue sera ajoutée à la valeur courante de la valeur.
Tcl_DString *lineRead (entrée/sortie)
Un pointeur vers une chaîne dynamique Tcl dans laquelle stocker la ligne lue depuis le canal. Doit avoir été initialisée par l'appelant. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne dynamique.
const char *input (en entrée)
L'entrée à ajouter à un tampon de canal.
int inputLen (en entrée)
Longueur de l'entrée
int addAtEnd (en entrée)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon de canal.
Tcl_Obj *writeObjPtr (en entrée)
Un pointeur vers une valeur Tcl dont le contenu sera envoyé en sortie vers le canal.
const char *charBuf (en entrée)
Un tampon contenant les caractères à envoyer en sortie vers le canal.
const char *byteBuf (en entrée)
Un tampon contenant les octets à envoyer en sortie vers le canal.
int bytesToWrite (en entrée)
Le nombre d'octets à consommer à partir de charBuf ou byteBuf et à envoyer en sortie vers le canal.
Tcl_WideInt offset (en entrée)
Décalage de la position d'accès dans le canal où la prochaine opération d'entrée ou de sortie sera appliquée, mesuré en octets à partir de la position indiquée par seekMode. Peut être positif ou négatif.
int seekMode (en entrée)
Point de référence pour le déplacement ; utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs valides sont SEEK_SET, SEEK_CUR, et SEEK_END.
Tcl_WideInt length (en entrée)
La longueur (non négative) à laquelle tronquer le canal.
const char *optionName (en entrée)
Le nom d'une option applicable à ce canal, telle que -blocking. Peut prendre l'une des valeurs acceptées par la commande fconfigure.
Tcl_DString *optionValue (en entrée)
Emplacement où stocker la valeur d'une option ou une liste de toutes les options et leurs valeurs. Doit avoir été initialisé par l'appelant.
const char *newValue (en entrée)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des périphériques et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie tamponnées sur une variété de types de fichiers, de sockets et de périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée man de Tcl_CreateChannel. Le mécanisme de canaux fournit un schéma de mise en tampon inspiré de l'E/S standard d'Unix, et il permet également les E/S non bloquantes sur les canaux.

Les procédures décrites dans cette entrée man constituent les API C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canaux et de la manière d'implémenter des pilotes de canaux pour de nouveaux types de canaux, voir l'entrée man de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Ouvre un canal vers le fichier nommé fileName en utilisant le mode spécifié par mode et les permissions permissions. Le mode spécifie comment le fichier doit être ouvert (par exemple, pour la lecture, l'écriture, ou les deux) et peut être combiné avec des options telles que b pour un mode binaire ou + pour ouvrir en lecture et écriture. Les permissions sont spécifiées en notation octale et s'appliquent uniquement si le fichier est créé.

Les valeurs possibles pour mode sont les mêmes que celles de la commande Tcl open : r, r+, w, w+, a, a+, rb, r+b, wb, w+b, ab, a+b, et leurs équivalents avec t au lieu de b pour le mode texte (c'est-à-dire le mode par défaut si ni b ni t ne sont spécifiés).

En cas de succès, cette procédure retourne un handle de canal. En cas d'échec, elle signale une erreur dans interp et retourne un pointeur NULL.

TCL_OPENCOMMANDCHANNEL

Crée un pipeline de processus en exécutant la commande spécifiée par argv. La procédure crée une série de canaux qui relient les descripteurs standard (stdin, stdout, stderr) des processus du pipeline aux canaux Tcl. Le comportement exact est déterminé par les bits définis dans flags. Les canaux de sortie de la commande (stdout et stderr) sont retournés en tant que canaux Tcl.

Si TCL_STDIN est défini dans flags, le canal retourné sera connecté à l'entrée standard du premier processus enfant. Sinon, le canal sera connecté à l'entrée standard du processus appelant.

De même, si TCL_STDOUT est défini, le canal retourné sera connecté à la sortie standard du dernier processus enfant. Si TCL_STDERR est défini, le canal retourné sera connecté à la sortie d'erreur standard du dernier processus enfant.

Si TCL_ENFORCE_MODE est défini, toute tentative de redirection des descripteurs standard des processus enfants entraînera une erreur. Sinon, la redirection des descripteurs standard est autorisée.

En cas de succès, cette procédure retourne un handle de canal pour la sortie de la commande (ou l'entrée si les indicateurs appropriés sont définis). En cas d'échec, elle signale une erreur dans interp et retourne un pointeur NULL.

TCL_MAKEFILECHANNEL

Crée un canal Tcl à partir d'un descripteur de fichier système existant (par exemple, un descripteur de fichier Unix ou un HANDLE Windows). L'argument readOrWrite indique si le canal sera utilisé pour la lecture, l'écriture, ou les deux.

En cas de succès, cette procédure retourne un handle de canal. En cas d'échec, elle signale une erreur dans interp et retourne un pointeur NULL.

TCL_GETCHANNEL

Retourne le handle de canal associé au nom de canal donné par channelName. Le pointeur modePtr sera défini pour indiquer si le canal est lisible et/ou accessible en écriture.

Si channelName fait référence à un canal qui n'est pas enregistré dans l'interpréteur interp, ou si le canal n'existe pas, une erreur sera signalée dans interp et NULL sera retourné.

TCL_GETCHANNELNAMES

Crée une valeur Tcl contenant une liste des noms de tous les canaux actuellement enregistrés dans l'interpréteur interp, et la stocke dans la variable d'objet à laquelle interp->result pointe. Retourne TCL_OK en cas de succès, ou TCL_ERROR en cas d'échec.

TCL_GETCHANNELNAMESEX

Crée une valeur Tcl contenant une liste des noms de tous les canaux actuellement enregistrés dans l'interpréteur interp qui correspondent au pattern spécifié, et la stocke dans la variable d'objet à laquelle interp->result pointe. Le pattern est évalué à l'aide de Tcl_StringMatch. Si pattern est NULL, tous les noms de canaux sont retournés. Retourne TCL_OK en cas de succès, ou TCL_ERROR en cas d'échec.

TCL_REGISTERCHANNEL

Enregistre le canal channel dans l'interpréteur interp sous le nom qui lui a été attribué lors de sa création. Après l'enregistrement, le canal peut être référencé par son nom par d'autres procédures Tcl, telles que fconfigure et close.

TCL_UNREGISTERCHANNEL

Annule l'enregistrement du canal channel de l'interpréteur interp. Après l'annulation de l'enregistrement, le canal ne peut plus être référencé par son nom. Cependant, le canal lui-même n'est pas fermé ; cela doit être fait séparément en appelant Tcl_Close.

Retourne TCL_OK si le canal a été trouvé et désenregistré, ou TCL_ERROR si le canal n'a pas été trouvé dans l'interpréteur.

TCL_DETACHCHANNEL

Détache le canal channel de l'interpréteur interp. Le canal est toujours valide et peut être utilisé par l'application appelante, mais il n'est plus géré par le mécanisme de canaux Tcl. Par exemple, il ne sera pas fermé automatiquement lorsque l'interpréteur sera détruit.

Retourne TCL_OK si le canal a été trouvé et détaché, ou TCL_ERROR si le canal n'a pas été trouvé dans l'interpréteur.

TCL_ISTANDARDCHANNEL

Retourne une valeur non nulle si le canal channel est l'un des canaux standard (entrée, sortie ou erreur standard), ou zéro sinon.

TCL_CLOSE

Ferme le canal channel. Toutes les écritures en attente sont vidées dans le canal, et toutes les ressources associées au canal sont libérées. Si le canal a été créé par Tcl_OpenFileChannel, le fichier sous-jacent est également fermé.

En cas de succès, retourne TCL_OK. En cas d'erreur (par exemple, une erreur lors de la vidange des données), elle signale une erreur dans interp et retourne TCL_ERROR.

TCL_READCHARS

Lit jusqu'à charsToRead caractères du canal channel et les stocke dans la valeur d'objet pointée par readObjPtr. Si appendFlag est non nul, les caractères lus sont ajoutés à la valeur existante de l'objet ; sinon, ils remplacent le contenu existant. La lecture s'arrête soit lorsque charsToRead caractères ont été lus, soit lorsque la fin du fichier est atteinte, soit lorsque la lecture est bloquée dans une opération non bloquante.

Retourne le nombre de caractères effectivement lus. Si une erreur se produit ou si le canal est bloqué et ne peut pas lire plus de caractères, elle retourne TCL_ERROR et signale l'erreur dans interp. Si la fin du fichier est atteinte et qu'aucun caractère n'a pu être lu, elle retourne 0.

TCL_READ

Lit jusqu'à bytesToRead octets du canal channel et les stocke dans le tampon readBuf. La lecture s'arrête soit lorsque bytesToRead octets ont été lus, soit lorsque la fin du fichier est atteinte, soit lorsque la lecture est bloquée dans une opération non bloquante.

Retourne le nombre d'octets effectivement lus. Si une erreur se produit ou si le canal est bloqué et ne peut pas lire plus d'octets, elle retourne TCL_ERROR et signale l'erreur dans interp. Si la fin du fichier est atteinte et qu'aucun octet n'a pu être lu, elle retourne 0.

TCL_GETSOBJ

Lit une ligne entière du canal channel (jusqu'au prochain caractère de nouvelle ligne, qui est lu mais non stocké) et la stocke dans la valeur d'objet pointée par lineObjPtr. La ligne lue est ajoutée à la valeur existante de l'objet. La lecture s'arrête soit lorsqu'une nouvelle ligne est rencontrée, soit lorsque la fin du fichier est atteinte, soit lorsque la lecture est bloquée dans une opération non bloquante.

Retourne TCL_OK en cas de succès (même si la fin du fichier est atteinte), ou TCL_ERROR en cas d'erreur d'E/S ou si le canal est bloqué et ne peut pas lire plus de caractères. Si la fin du fichier est atteinte et qu'aucun caractère n'a été lu avant elle, elle retourne 0.

TCL_GETS

Lit une ligne entière du canal channel et la stocke dans la chaîne dynamique Tcl lineRead. La ligne lue est ajoutée à toute donnée déjà présente dans la chaîne dynamique. La lecture s'arrête soit lorsqu'une nouvelle ligne est rencontrée, soit lorsque la fin du fichier est atteinte, soit lorsque la lecture est bloquée dans une opération non bloquante.

Retourne TCL_OK en cas de succès (même si la fin du fichier est atteinte), ou TCL_ERROR en cas d'erreur d'E/S ou si le canal est bloqué et ne peut pas lire plus de caractères. Si la fin du fichier est atteinte et qu'aucun caractère n'a été lu avant elle, elle retourne 0.

TCL_UNGETS

Remet les données spécifiées par input et inputLen dans le tampon d'entrée du canal channel. Si addAtEnd est non nul, les données sont ajoutées à la fin du tampon ; sinon, elles sont ajoutées au début. Ceci est utile pour implémenter des analyseurs d'entrée qui doivent lire au-delà du délimiteur souhaité et ensuite remettre le surplus dans le tampon d'entrée.

Retourne TCL_OK en cas de succès, ou TCL_ERROR en cas d'erreur (par exemple, si le canal n'a pas de tampon d'entrée).

TCL_WRITEOBJ

Écrit le contenu de la valeur d'objet pointée par writeObjPtr dans le canal channel. La procédure gère le codage et la conversion des types de données selon les options du canal. Les données sont écrites dans le tampon de sortie du canal. La procédure retourne lorsque le tampon est plein ou que toutes les données ont été écrites.

Retourne TCL_OK en cas de succès, ou TCL_ERROR en cas d'erreur d'E/S ou si le canal est bloqué et ne peut pas écrire plus de données. En cas d'erreur, elle signale l'erreur dans interp.

TCL_WRITECHARS

Écrit les caractères dans le tampon charBuf dans le canal channel. Le nombre d'octets à écrire est spécifié par bytesToWrite. Si le canal est ouvert en mode texte, les caractères de nouvelle ligne peuvent être convertis en séquences de fin de ligne spécifiques à la plateforme. Les données sont écrites dans le tampon de sortie du canal.

Retourne TCL_OK en cas de succès, ou TCL_ERROR en cas d'erreur d'E/S ou si le canal est bloqué et ne peut pas écrire plus de données. En cas d'erreur, elle signale l'erreur dans interp.

TCL_WRITE

Écrit les octets dans le tampon byteBuf dans le canal channel. Le nombre d'octets à écrire est spécifié par bytesToWrite. Cette procédure est destinée à l'écriture de données binaires brutes et n'effectue aucune conversion de fin de ligne ou d'encodage.

Retourne TCL_OK en cas de succès, ou TCL_ERROR en cas d'erreur d'E/S ou si le canal est bloqué et ne peut pas écrire plus de données. En cas d'erreur, elle signale l'erreur dans interp.

TCL_READRAW

Lit jusqu'à bytesToRead octets bruts (sans aucune conversion) du canal channel et les stocke dans le tampon readBuf. La lecture s'arrête soit lorsque bytesToRead octets ont été lus, soit lorsque la fin du fichier est atteinte, soit lorsque la lecture est bloquée dans une opération non bloquante.

Retourne le nombre d'octets effectivement lus. Si une erreur se produit ou si le canal est bloqué et ne peut pas lire plus d'octets, elle retourne TCL_ERROR et signale l'erreur dans interp. Si la fin du fichier est atteinte et qu'aucun octet n'a pu être lu, elle retourne 0.

TCL_WRITERAW

Écrit les octets bruts (sans aucune conversion) dans le tampon byteBuf dans le canal channel. Le nombre d'octets à écrire est spécifié par bytesToWrite. Cette procédure est destinée à l'écriture de données binaires brutes.

Retourne TCL_OK en cas de succès, ou TCL_ERROR en cas d'erreur d'E/S ou si le canal est bloqué et ne peut pas écrire plus de données. En cas d'erreur, elle signale l'erreur dans interp.

TCL_EOF

Retourne une valeur non nulle si la fin du fichier a été atteinte pour le canal channel, ou zéro sinon. La fin du fichier est atteinte lorsqu'une tentative de lecture sur le canal ne retourne plus de données.

TCL_FLUSH

Force le vidage de toutes les données en attente dans le tampon de sortie du canal channel vers le périphérique sous-jacent. Cela garantit que toutes les données écrites ont été effectivement envoyées.

Retourne TCL_OK en cas de succès, ou TCL_ERROR en cas d'erreur d'E/S. En cas d'erreur, elle signale l'erreur dans interp.

TCL_INPUTBLOCKED

Retourne une valeur non nulle si une opération de lecture sur le canal channel a été bloquée (c'est-à-dire qu'aucune donnée n'était disponible), ou zéro sinon. Ceci est utile dans les applications utilisant des opérations de canal non bloquantes.

TCL_INPUTBUFFERED

Retourne le nombre d'octets actuellement présents dans le tampon d'entrée du canal channel. Ceci est utile pour connaître la quantité de données disponibles pour la lecture sans avoir à effectuer une lecture réelle.

TCL_OUTPUTBUFFERED

Retourne le nombre d'octets actuellement présents dans le tampon de sortie du canal channel qui n'ont pas encore été écrits dans le périphérique sous-jacent. Ceci est utile pour savoir combien de données sont en attente d'être écrites.

TCL_SEEK

Définit le point d'accès actuel du canal channel. L'offset spécifié par offset est ajouté à la position donnée par seekMode (SEEK_SET pour le début du fichier, SEEK_CUR pour la position actuelle, SEEK_END pour la fin du fichier) pour calculer la nouvelle position. Les opérations futures de lecture ou d'écriture sur le canal commenceront à cette nouvelle position.

Retourne la nouvelle position du canal en octets à partir du début du fichier en cas de succès. En cas d'erreur (par exemple, tentative de se déplacer dans un canal non recherchable), elle retourne -1 et signale une erreur dans interp.

TCL_TELL

Retourne la position actuelle du canal channel en octets à partir du début du fichier. Ceci est utile pour enregistrer la position actuelle avant d'effectuer une opération de recherche, ou pour déterminer la taille d'un fichier.

En cas d'erreur (par exemple, si le canal n'a pas de position définie), elle retourne -1 et signale une erreur dans interp.

TCL_TRUNCATECHANNEL

Tronque le canal channel à la longueur spécifiée par length. Cela supprime toutes les données au-delà de cette longueur. Cette opération n'est valide que pour les canaux ouverts en écriture.

Retourne TCL_OK en cas de succès, ou TCL_ERROR en cas d'erreur (par exemple, si le canal n'est pas ouvert en écriture ou si l'opération de troncature échoue).

TCL_GETCHANNELOPTION

Récupère la valeur de l'option spécifiée par optionName pour le canal channel et la stocke dans la chaîne dynamique pointée par optionValue. Le nom de l'option doit être l'un des noms acceptés par la commande Tcl fconfigure (par exemple, -blocking, -buffering, -encoding, etc.).

Retourne TCL_OK en cas de succès, ou TCL_ERROR si l'option n'est pas valide ou si une erreur se produit lors de la récupération de la valeur. En cas d'erreur, elle signale l'erreur dans interp.

TCL_SETCHANNELOPTION

Définit la valeur de l'option spécifiée par optionName pour le canal channel à la nouvelle valeur donnée par newValue. Le nom de l'option et sa nouvelle valeur doivent être des valeurs acceptées par la commande Tcl fconfigure.

Retourne TCL_OK en cas de succès, ou TCL_ERROR si l'option n'est pas valide ou si une erreur se produit lors de la définition de la valeur. En cas d'erreur, elle signale l'erreur dans interp.

TCL_SEEK_SET, _CUR, _END

Ces constantes sont utilisées avec Tcl_Seek pour spécifier le point de référence à partir duquel l'offset est calculé.

SEEK_SET
Déplace l'accès au fichier au début du fichier plus l'offset.
SEEK_CUR
Déplace l'accès au fichier à la position actuelle plus l'offset.
SEEK_END
Déplace l'accès au fichier à la fin du fichier plus l'offset.

TCL_STDIN, _STDOUT, _STDERR, _ENFORCE_MODE

Ces constantes sont utilisées avec Tcl_OpenCommandChannel pour spécifier la manière dont les descripteurs standard des processus d'un pipeline doivent être gérés.

TCL_STDIN
Le canal retourné est connecté à l'entrée standard du premier processus enfant.
TCL_STDOUT
Le canal retourné est connecté à la sortie standard du dernier processus enfant.
TCL_STDERR
Le canal retourné est connecté à la sortie d'erreur standard du dernier processus enfant.
TCL_ENFORCE_MODE
Empêche la redirection des descripteurs standard des processus enfants. Toute tentative de redirection entraînera une erreur.

TCL_READABLE, _WRITABLE

Ces constantes sont utilisées avec Tcl_MakeFileChannel pour indiquer si le canal créé sera utilisé pour la lecture, l'écriture, ou les deux.

TCL_READABLE
Le canal est destiné à la lecture.
TCL_WRITABLE
Le canal est destiné à l'écriture.

TCL_OK, _ERROR

Ces constantes sont retournées par la plupart des procédures de canal pour indiquer le succès (TCL_OK) ou l'échec (TCL_ERROR). En cas d'échec, des informations supplémentaires sur l'erreur sont généralement disponibles dans le champ result de la structure Tcl_Interp.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et renvoie un descripteur de canal qui peut être utilisé pour lire et écrire dans le fichier. Cette API est calquée sur la fonction fopen de la bibliothèque standard d'E/S Unix. La syntaxe et la signification de tous les arguments sont similaires à celles de la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur les valeurs Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel lorsque cela est possible.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'affecte également comme remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface au niveau C des fonctions des commandes exec et open. Elle crée une séquence de processus enfants spécifiés par les arguments argv et argc et renvoie un canal qui peut être utilisé pour communiquer avec ces processus enfants. L'argument flags indique le type de communication que vous aurez avec la séquence de commandes.

Si le drapeau TCL_STDIN est défini, l'entrée standard du premier processus enfant sera connectée au canal : écrire dans le canal fournit l'entrée au processus enfant. Si le drapeau TCL_STDIN n'est pas défini, l'entrée standard du premier processus enfant sera la même que l'entrée standard de cette application. Si le drapeau TCL_STDOUT est défini, la sortie standard du dernier processus enfant pourra être lue depuis le canal ; sinon, elle sera dirigée vers la sortie standard de cette application. Si le drapeau TCL_STDERR est défini, la sortie d'erreur standard de tous les processus enfants sera renvoyée au canal et provoquera une erreur lors de la fermeture du canal ; sinon, elle sera dirigée vers la sortie d'erreur standard de cette application. Si le drapeau TCL_ENFORCE_MODE n'est pas défini, les valeurs argc et argv peuvent rediriger les descripteurs standards pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, il est erroné que argc et argv redirigent les canaux standards pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur interp. interp ne peut pas être NULL.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'affecte également comme remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un descripteur de fichier existant et spécifiquement pour le système d'exploitation. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'affecte également comme remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel renvoie un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers l'interpréteur dans interp. Si aucun canal enregistré dans cet interpréteur avec ce nom n'existe, il renvoie NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtre ces noms en fonction du pattern. Si pattern est NULL, aucun filtrage n'est effectué. La valeur de retour est TCL_OK s'il n'y a pas eu d'erreur lors de l'écriture dans le résultat, sinon TCL_ERROR et le message d'erreur reste dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal aux canaux accessibles dans interp. Après cet appel, les programmes Tcl qui s'exécutent dans cet interpréteur peuvent faire référence au canal par le nom donné lors de l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal est automatiquement fermé lorsqu'il est désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur peut appeler Tcl_RegisterChannel avec interp comme NULL, indiquant qu'il souhaite conserver une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et ne sera fermé que lorsque autant d'appels à Tcl_UnregisterChannel auront été effectués qu'il y ait eu d'appels correspondants. Cela permet au code exécuté en dehors de tout interpréteur de conserver une référence sûre à un canal qui est également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code qui gère les canaux standards. Si aucun canal standard n'est initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un aperçu des canaux standards et du comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel supprime un canal des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Si cette opération supprime le dernier enregistrement du canal dans un quelconque interpréteur, le canal sera également fermé et supprimé.

Le code non associé à un interpréteur peut appeler Tcl_UnregisterChannel avec interp comme NULL, indiquant à Tcl qu'il ne conserve plus de référence à ce canal. Si c'est la dernière référence au canal, il sera fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel, à la différence qu'il ferme également le canal si aucune référence restante n'est présente.

TCL_DETACHCHANNEL

Tcl_DetachChannel supprime un canal des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Par ailleurs, cette commande n'a pas d'autre effet. Elle ne peut pas être utilisée sur les canaux standards (stdout, stderr, stdin) et renverra TCL_ERROR si elle reçoit l'un de ces canaux en argument.

Le code non associé à un interpréteur peut appeler Tcl_DetachChannel avec interp comme NULL, indiquant à Tcl qu'il ne conserve plus de référence à ce canal. Si c'est la dernière référence au canal, il ne sera pas fermé, contrairement à Tcl_UnregisterChannel.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel vérifie si un canal est l'un des trois canaux standards, stdin, stdout ou stderr. S'il l'est, il renvoie 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standards sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lorsque Tcl_Close est appelé. Le tampon de sortie est vidé avant de détruire le canal, et tout tampon d'entrée est supprimé. Si ce canal est bloquant, l'appel ne renvoie pas tant que toutes les données tamponnées n'ont pas été envoyées au périphérique de sortie du canal. Si ce canal est non bloquant et qu'il y a des données d'entrée tamponnées qui ne peuvent pas être écrites sans blocage, l'appel renvoie immédiatement ; les données sont vidées en arrière-plan et le canal est fermé une fois que toutes les données tamponnées ont été envoyées. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close renvoie TCL_OK. Si une erreur se produit, Tcl_Close renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré avec Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devez utiliser Tcl_UnregisterChannel, qui appelle en interne Tcl_Close lorsque tous les appels à Tcl_RegisterChannel ont été mis en correspondance par des appels correspondants à Tcl_UnregisterChannel).

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, les convertit en UTF-8 selon l'encodage du canal et stocke les données produites dans la représentation de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit pendant la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Si charsToRead est défini

Le retour à -1 fera en sorte que la commande lise tous les caractères actuellement disponibles (sans blocage) ou tout jusqu'à l'eof (mode bloquant).

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé étaient disponibles. Ceci est appelé une lecture courte. En mode bloquant, cela ne peut arriver qu'à la fin du fichier. En mode non bloquant, une lecture courte peut également se produire s'il n'y a pas assez d'entrées actuellement disponibles : Tcl_ReadChars retourne un nombre réduit plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour savoir laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les diverses représentations de fin de ligne en la représentation interne canonique \n, conformément au mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les divers modes spécifiques à la plateforme sont décrits dans la page de manuel de la commande Tcl fconfigure.

En tant qu'optimisation des performances, lors de la lecture d'un canal avec le codage binary, les octets ne sont pas convertis en UTF-8 lorsqu'ils sont lus. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr sous forme de tableau d'octets. La représentation textuelle de cette valeur ne sera construite que si elle est nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette façon, les données orientées octets peuvent être lues depuis un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût d'une conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, à l'exception qu'il n'effectue pas de conversions de codage, quel que soit le codage du canal. Il est déprécié et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Il consomme des octets de channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par null. Son contenu est valide à partir de la position zéro jusqu'à, mais non comprise, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas l'empilement. Alors que Tcl_Read (et les autres fonctions de l'API) obtiennent toujours leurs données du canal le plus haut dans la pile dont le canal fourni fait partie, Tcl_ReadRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données du canal inférieur dans la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, en convertissant les octets en UTF-8 en fonction du codage du canal, jusqu'à ce qu'une ligne complète d'entrée soit vue. Si le codage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception du ou des caractères de fin de ligne terminating, sont ajoutés à la représentation textuelle de lineObjPtr. Le ou les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. En cas d'erreur, Tcl_GetsObj retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj retourne également -1 si la fin du fichier est atteinte; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 s'il n'y avait pas de données disponibles ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est retourné, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité de l'entrée.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique fournie par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, soit à la tête, soit à la queue. Le pointeur input pointe vers les données à ajouter. La longueur des données à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file d'attente; sinon, elles seront ajoutées à la tête de la file d'attente. Si channel a un EOF "collant" défini, aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets retourne inputLen ou -1 en cas d'erreur.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données caractères à charBuf. Les caractères UTF-8 dans le tampon sont convertis vers le codage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par null et il affiche tout jusqu'au null.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître sur le périphérique de sortie immédiatement, en raison de la mise en tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal à none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un compte du nombre d'octets acceptés pour la sortie vers le canal. C'est soit un nombre supérieur à zéro pour indiquer le succès, soit -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme conformément à l'option -translation pour le canal. Ceci est fait même si le canal n'a pas de codage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'il accepte une valeur Tcl dont le contenu sera affiché sur le canal. Les caractères UTF-8 de la représentation textuelle de writeObjPtr sont convertis vers le codage du canal et mis en file d'attente pour la sortie vers channel. En tant qu'optimisation des performances, lors de l'écriture sur un canal avec le codage binary, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets de la représentation interne de writeObjPtr sous forme de tableau d'octets sont écrits sur le canal. La représentation en tableau d'octets de la valeur sera construite si elle est nécessaire. De cette façon, les données orientées octets peuvent être lues depuis un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites sur un canal sans le coût d'une conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'il n'effectue pas de conversions de codage, quel que soit le codage du canal. Il est déprécié et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par null et il affiche tout jusqu'au null.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée dans le canal le plus haut dans la pile dont le canal fourni fait partie, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation dans le canal inférieur.

TCL_FLUSH

Tcl_Flush provoque l'écriture de toutes les données de sortie mises en tampon pour channel dans son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données mises en tampon n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal n'est pas bloquant; il démarre une opération de vidage en arrière-plan qui écrira les données mises en tampon dans le canal à terme, aussi rapidement que le canal pourra les absorber.

La valeur de retour est normalement TCL_OK. En cas d'erreur, Tcl_Flush retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données ultérieures seront lues ou écrites. La sortie mise en tampon est vidée vers le canal et l'entrée mise en tampon est rejetée, avant l'opération de déplacement.

Tcl_Seek retourne normalement le nouveau point d'accès. En cas d'erreur, Tcl_Seek retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut avoir été déplacé ou non.

TCL_TELL

Tcl_Tell retourne le point d'accès actuel pour un canal. La valeur retournée est -1 si le canal ne prend pas en charge le déplacement.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent de channel à une longueur donnée de length octets. Il retourne TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, c'est le nom de l'option à interroger; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue, en utilisant

  • un appel à Tcl_DStringAppendElement. Les diverses options préexistantes et leurs valeurs possibles sont décrites dans la page de manuel de la commande Tcl fconfigure. D'autres options peuvent être ajoutées par chaque type de canal. Ces options spécifiques au type de canal sont décrites dans la page de manuel de la commande Tcl qui crée un canal de ce type ; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans la page de manuel de la commande Tcl socket. La procédure renvoie normalement TCL_OK. En cas d'erreur, elle renvoie TCL_ERROR et appelle Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit une nouvelle valeur newValue pour une option optionName sur le canal channel. La procédure renvoie normalement TCL_OK. En cas d'erreur, elle renvoie TCL_ERROR ; de plus, si interp est non-NULL, Tcl_SetChannelOption laisse un message d'erreur dans le résultat de l'interpréteur.

TCL_EOF

Tcl_Eof renvoie une valeur non nulle si channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked renvoie une valeur non nulle si channel est en mode non bloquant et que la dernière opération d'entrée a retourné moins de données que demandé car il n'y avait pas suffisamment de données disponibles. L'appel renvoie toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered renvoie le nombre d'octets d'entrée actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en lecture, cette fonction renvoie toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered renvoie le nombre d'octets de sortie actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en écriture, cette fonction renvoie toujours zéro.

PLATFORM ISSUES

Les descripteurs renvoyés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que renvoyé par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel ou Tcl_MakeFileChannel. D'autres types de canaux peuvent renvoyer un type de descripteur différent sur les plateformes Windows.
