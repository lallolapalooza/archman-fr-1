ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour le rapport d'erreurs et pour rechercher un canal enregistré en son sein.
const char *fileName (in)
Le nom d'un fichier local ou réseau.
const char *mode (in)
Spécifie comment le fichier doit être accédé. Peut avoir n'importe laquelle des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (in)
Indicateurs de permission de style POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront appliquées au fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans commutateur de la commande Tcl exec.
int flags (in)
Spécifie la disposition des descripteurs stdio dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, stdin pour le premier enfant du pipe est le canal du pipe, sinon il est le même que l'entrée standard du processus appelant ; de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, alors le pipe peut rediriger les descripteurs stdio pour remplacer les descripteurs stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, de telles redirections provoquent une erreur.
ClientData handle (in)
Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, c'est un descripteur de fichier, pour Windows, c'est un HANDLE.
int readOrWrite (in)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (in)
Le modèle à faire correspondre, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl pour l'entrée ou la sortie. Doit être la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker les caractères lus depuis le canal.
int charsToRead (in)
Le nombre de caractères à lire depuis le canal. Si le codage du canal est binary, ceci est équivalent au nombre d'octets à lire depuis le canal.
int appendFlag (in)
Si différent de zéro, les données lues depuis le canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (out)
Un tampon dans lequel stocker les octets lus depuis le canal.
int bytesToRead (in)
Le nombre d'octets à lire depuis le canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker la ligne lue depuis le canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne dynamique Tcl dans laquelle stocker la ligne lue depuis le canal. Doit avoir été initialisé par l'appelant. La ligne lue sera ajoutée aux données déjà présentes dans la chaîne dynamique.
const char *input (in)
L'entrée à ajouter à un tampon de canal.
int inputLen (in)
Longueur de l'entrée
int addAtEnd (in)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon du canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera émis sur le canal.
const char *charBuf (in)
Un tampon contenant les caractères à émettre sur le canal.
const char *byteBuf (in)
Un tampon contenant les octets à émettre sur le canal.
int bytesToWrite (in)
Le nombre d'octets à consommer depuis charBuf ou byteBuf et à émettre sur le canal.
Tcl_WideInt offset (in)
Distance à laquelle déplacer le point d'accès dans le canal où la prochaine opération d'entrée ou de sortie sera appliquée, mesurée en octets par rapport à la position donnée par seekMode. Peut être positif ou négatif.
int seekMode (in)
Par rapport à quel point chercher ; utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs légales sont SEEK_SET, SEEK_CUR, et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) à laquelle tronquer le canal.
const char *optionName (in)
Le nom d'une option applicable à ce canal, telle que -blocking. Peut avoir n'importe laquelle des valeurs acceptées par la commande fconfigure.
Tcl_DString *optionValue (in)
Où stocker la valeur d'une option ou une liste de toutes les options et de leurs valeurs. Doit avoir été initialisé par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des périphériques et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie tamponnées sur une variété de types de fichiers, sockets et périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée de manuel de Tcl_CreateChannel. Le mécanisme de canaux fournit un schéma de mise en mémoire tampon calqué sur les E/S standard d'Unix, et il permet également les E/S non bloquantes sur les canaux.

Les procédures décrites dans cette entrée de manuel comprennent les APIs C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canaux et comment implémenter des pilotes de canaux pour de nouveaux types de canaux, voir l'entrée de manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Ouvre un nouveau canal Tcl associé au fichier spécifié par fileName. Les arguments mode et permissions ont la même signification que pour la commande Tcl open. Si un nouveau fichier est créé, il se verra attribuer les permissions spécifiées par permissions. La valeur de retour est un handle de canal Tcl, ou NULL s'il y a une erreur. L'interpréteur interp est utilisé pour signaler des erreurs.

TCL_OPENCOMMANDCHANNEL

Crée un nouveau canal Tcl représentant un pipeline de commandes. Argc et argv spécifient la commande et ses arguments, sous la forme utilisée par la commande Tcl exec. L'argument flags spécifie comment les descripteurs stdio du processus enfant doivent être reliés au pipeline. Voir la description de l'argument flags ci-dessus pour plus de détails. La valeur de retour est un handle de canal Tcl, ou NULL s'il y a une erreur.

TCL_MAKEFILECHANNEL

Crée un nouveau canal Tcl associé à un descripteur de fichier de bas niveau existant handle. Le champ readOrWrite indique quelles opérations (lecture, écriture ou les deux) sont valides sur le descripteur de fichier. La valeur de retour est un handle de canal Tcl, ou NULL s'il y a une erreur. Ce canal n'est pas automatiquement enregistré auprès de l'interpréteur ; utilisez Tcl_RegisterChannel pour ce faire.

TCL_GETCHANNEL

Récupère un handle de canal Tcl existant associé au nom de canal channelName. Si modePtr n'est pas NULL, il pointe vers un entier qui recevra une indication de lecture/écriture (ORed de TCL_READABLE et TCL_WRITABLE) pour le canal. Si le canal est un canal de sortie, il est renvoyé en lecture seule; sinon, il est renvoyé en en écriture seule. La valeur de retour est un handle de canal Tcl, ou NULL s'il y a une erreur.

TCL_GETCHANNELNAMES

Crée une liste des noms de tous les canaux actuellement enregistrés auprès de l'interpréteur interp et la stocke dans la variable Tcl nommée par interp->result. La valeur de retour est le nombre de canaux.

TCL_GETCHANNELNAMESEX

Crée une liste des noms de tous les canaux actuellement enregistrés auprès de l'interpréteur interp dont les noms correspondent au modèle pattern (voir Tcl_StringMatch) et la stocke dans la variable Tcl nommée par interp->result. Si pattern est NULL, cela se comporte comme Tcl_GetChannelNames. La valeur de retour est le nombre de canaux correspondants.

TCL_REGISTERCHANNEL

Enregistre le canal channel auprès de l'interpréteur interp. Le canal doit avoir un nom valide ; si ce n'est pas le cas, vous devriez utiliser Tcl_SetChannelName pour lui en donner un. Une fois enregistré, le canal peut être référencé par son nom dans les commandes Tcl.

TCL_UNREGISTERCHANNEL

Désenregistre le canal channel de l'interpréteur interp. Cela supprime le canal de la liste des canaux connus de l'interpréteur. Après désenregistrement, le canal ne peut plus être référencé par son nom, mais le canal lui-même reste ouvert jusqu'à ce que Tcl_Close soit appelé.

TCL_DETACHCHANNEL

Détache le canal channel de l'interpréteur interp. Cela désenregistre le canal et supprime le tampon du canal, le canal est ensuite passé au pilote de canal sous-jacent. L'appelant est responsable de la fermeture du canal sous-jacent lorsque celui-ci n'est plus nécessaire. Ceci est principalement utile pour les canaux qui ne sont pas censés être gérés par le mécanisme de canaux Tcl (par exemple, les canaux créés à l'aide de Tcl_MakeFileChannel qui doivent ensuite être gérés à un niveau inférieur par l'application).

TCL_ISTANDARDCHANNEL

Renvoie vrai si le canal channel est l'un des canaux standard (stdin, stdout ou stderr) et faux sinon.

TCL_CLOSE

Ferme le canal channel. Cela force l'écriture de toutes les données tamponnées en sortie, ferme le canal sous-jacent et libère toutes les ressources associées au canal. Si une erreur se produit lors de la fermeture, elle est signalée à l'interpréteur interp et un code d'erreur non nul est renvoyé.

TCL_READCHARS

Lit jusqu'à charsToRead caractères du canal channel et les stocke dans la valeur Tcl pointée par readObjPtr. Si appendFlag est non nul, les caractères lus sont ajoutés à la valeur existante ; sinon, ils la remplacent. Le nombre de caractères réellement lus est renvoyé. Une valeur de retour négative indique une erreur. Si le canal est ouvert en mode binaire, ce sera le nombre d'octets lus.

TCL_READ

Lit jusqu'à bytesToRead octets du canal channel et les stocke dans le tampon readBuf. readBuf doit être suffisamment grand pour contenir bytesToRead octets. Le nombre d'octets réellement lus est renvoyé. Une valeur de retour négative indique une erreur. Cette procédure est similaire à Tcl_ReadChars, mais opère au niveau des octets.

TCL_GETSOBJ

Lit une ligne entière depuis le canal channel et la stocke dans la valeur Tcl pointée par lineObjPtr. La ligne est lue jusqu'à ce qu'un caractère de nouvelle ligne soit rencontré ou que la fin du fichier soit atteinte. Le caractère de nouvelle ligne est consommé mais n'est pas inclus dans la valeur renvoyée. Les données existantes dans lineObjPtr sont écrasées. Le nombre de caractères lus est renvoyé, ou EOF si la fin du fichier est atteinte avant de lire tout caractère. Une valeur de retour négative indique une erreur.

TCL_GETS

Lit une ligne entière depuis le canal channel et l'ajoute à la chaîne dynamique lineRead. La ligne est lue jusqu'à ce qu'un caractère de nouvelle ligne soit rencontré ou que la fin du fichier soit atteinte. Le caractère de nouvelle ligne est consommé mais n'est pas inclus dans la chaîne dynamique. Les données existantes dans lineRead sont conservées. Le nombre de caractères lus est renvoyé, ou EOF si la fin du fichier est atteinte avant de lire tout caractère. Une valeur de retour négative indique une erreur.

TCL_UNGETS

Remet des données dans le tampon d'entrée d'un canal. Les données dans input, dont la longueur est inputLen, sont ajoutées au début (si addAtEnd est faux) ou à la fin (si addAtEnd est vrai) du tampon d'entrée du canal. Cela peut être utilisé pour implémenter des fonctionnalités telles que la recherche en arrière ou l'ajout de données avant la lecture effective.

TCL_WRITEOBJ

Écrit le contenu de la valeur Tcl pointée par writeObjPtr sur le canal channel. Le nombre d'octets réellement écrits est renvoyé. Une valeur de retour négative indique une erreur.

TCL_WRITECHARS

Écrit les caractères du tampon charBuf sur le canal channel. Le nombre d'octets à écrire est donné par bytesToWrite. Le nombre d'octets réellement écrits est renvoyé. Une valeur de retour négative indique une erreur.

TCL_WRITE

Écrit les octets du tampon byteBuf sur le canal channel. Le nombre d'octets à écrire est donné par bytesToWrite. Le nombre d'octets réellement écrits est renvoyé. Une valeur de retour négative indique une erreur. Cette procédure est similaire à Tcl_WriteChars, mais opère au niveau des octets.

TCL_READRAW

Similaire à Tcl_Read, mais lit directement les octets bruts depuis le canal, sans aucune conversion de codage ou de fin de ligne.

TCL_WRITERAW

Similaire à Tcl_Write, mais écrit directement les octets bruts sur le canal, sans aucune conversion de codage ou de fin de ligne.

TCL_EOF

Renvoie vrai si la fin du fichier a été atteinte sur le canal channel pour la lecture, et faux sinon. Ceci est utile après une opération de lecture qui renvoie moins de données que demandé.

TCL_FLUSH

Force l'écriture de toutes les données tamponnées en sortie vers le canal channel. Utile pour s'assurer que les données sont envoyées immédiatement, par exemple avant de lire une réponse.

TCL_INPUTBLOCKED

Renvoie vrai si une tentative de lecture sur le canal channel bloquerait, et faux sinon. Ceci est utile pour implémenter des E/S non bloquantes.

TCL_INPUTBUFFERED

Renvoie le nombre d'octets actuellement disponibles en lecture dans le tampon d'entrée du canal channel.

TCL_OUTPUTBUFFERED

Renvoie le nombre d'octets actuellement en attente d'écriture dans le tampon de sortie du canal channel.

TCL_SEEK

Modifie le point d'accès actuel dans le canal channel. L'argument offset spécifie de combien d'octets le point d'accès doit être déplacé, et seekMode spécifie le point de référence (début, fin ou position actuelle). La nouvelle position du point d'accès est renvoyée. Si une erreur se produit, -1 est renvoyé et l'interpréteur interp est mis à jour avec un message d'erreur.

TCL_TELL

Renvoie la position actuelle du point d'accès dans le canal channel. Si une erreur se produit, -1 est renvoyé et l'interpréteur interp est mis à jour avec un message d'erreur.

TCL_TRUNCATECHANNEL

Tronque le canal channel à la longueur spécifiée par length. Toutes les données au-delà de cette longueur sont perdues. La longueur doit être non négative. Si une erreur se produit, un code d'erreur non nul est renvoyé.

TCL_GETCHANNELOPTION

Récupère la valeur de l'option spécifiée par optionName pour le canal channel et la stocke dans la chaîne dynamique optionValue. Les noms d'options sont les mêmes que ceux utilisés par la commande Tcl fconfigure. Si optionName est NULL, toutes les options et leurs valeurs sont placées dans optionValue sous forme de liste Tcl.

TCL_SETCHANNELOPTION

Définit l'option spécifiée par optionName sur la nouvelle valeur newValue pour le canal channel. Les noms d'options sont les mêmes que ceux utilisés par la commande Tcl fconfigure. Si une erreur se produit, un code d'erreur non nul est renvoyé.

NEL'>TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et renvoie un handle de canal qui peut être utilisé pour effectuer des entrées et sorties sur le fichier. Cette API est calquée sur la procédure fopen de la bibliothèque Unix standard de lecture/écriture. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Dans le cadre de Tcl 8.4, la valeur basée sur l'API Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel lorsque cela est possible.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, il faut utiliser Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr était précédemment fermé, l'action de création du nouveau canal l'attribue également comme remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C pour les fonctionnalités des commandes exec et open. Elle crée une chaîne de processus séquentiels spécifiés par les arguments argv et argc et renvoie un canal qui peut être utilisé pour communiquer avec ces processus séquentiels. L'argument flags indique le type de communication qui aura lieu avec la chaîne de processus.

Si le drapeau TCL_STDIN est activé, l'entrée standard du premier processus séquentiel sera liée au canal : écrire dans le canal fournira une entrée audit processus. Si le drapeau TCL_STDIN n'est pas activé, l'entrée standard du premier processus séquentiel sera la même que l'entrée standard de cette application. Si le drapeau TCL_STDOUT est activé, la sortie standard du dernier processus séquentiel peut être lue depuis le canal ; sinon, elle va à la sortie standard de cette application. Si le drapeau TCL_STDERR est activé, la sortie d'erreur standard de tous les processus séquentiels est renvoyée au canal et provoque une erreur lors de la fermeture du canal ; sinon, elle va à la sortie d'erreur standard de cette application. Si le drapeau TCL_ENFORCE_MODE n'est pas activé, les arguments argc et argv peuvent rediriger les handles standards pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est activé, il s'agit d'une erreur si argc et argv tentent de remplacer les canaux standards pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, il faut utiliser Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr était précédemment fermé, l'action de création du nouveau canal l'attribue également comme remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un handle de fichier existant et spécifique à la plateforme. Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, il faut utiliser Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr était précédemment fermé, l'action de création du nouveau canal l'attribue également comme remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel renvoie un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur dans interp. Si le canal portant ce nom n'est pas trouvé dans l'interpréteur, la procédure renvoie NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms en fonction du pattern. Si pattern est NULL, aucun filtrage ne sera effectué. La valeur de retour est TCL_OK s'il n'y a pas eu d'erreurs lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur reste dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à la collection de canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur peuvent faire référence au canal en utilisant le nom donné dans l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal est automatiquement fermé lorsqu'il est désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur peut appeler Tcl_RegisterChannel avec interp comme NULL, indiquant qu'il souhaite conserver une référence à ce canal. Après cela, le canal peut être enregistré dans un interpréteur Tcl et ne sera fermé que lorsque le nombre d'appels à Tcl_UnregisterChannel correspondant aura été effectué. Cela permet au code exécuté en dehors de tout interpréteur de conserver une référence sécurisée à un canal enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code qui gère les canaux standards. Si aucun canal standard n'est initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un traitement général des canaux standards et du comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel retire un canal de la collection de canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Si cette opération retire le dernier enregistrement du canal dans un interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur peut appeler Tcl_UnregisterChannel avec interp comme NULL, indiquant à Tcl qu'il ne conserve plus de référence à ce canal. Si c'est la dernière référence au canal, il est maintenant fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel, sauf qu'il ferme également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel retire un canal de la collection de canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. De plus, cette commande n'a pas d'effet supplémentaire. Elle ne peut pas être utilisée sur les canaux standards (stdout, stderr, stdin), et renverra TCL_ERROR si l'un de ces canaux lui est passé.

Le code non associé à un interpréteur peut appeler Tcl_DetachChannel avec interp comme NULL, indiquant à Tcl qu'il ne conserve plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il n'est pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel vérifie si un canal est l'un des trois canaux standards, stdin, stdout ou stderr. Si c'est le cas, il renvoie 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standards sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lorsque Tcl_Close est appelé. Le tampon de sortie est vidé avant la destruction du canal, et tout tampon d'entrée est rejeté. S'il s'agit d'un canal bloquant, l'appel ne retourne pas tant que toutes les données mises en tampon n'ont pas été envoyées au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a des données mises en tampon qui ne peuvent pas être écrites sans blocage, l'appel retourne immédiatement ; la sortie est vidée en arrière-plan et le canal est fermé lorsque toutes les données mises en tampon ont été expédiées. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close renvoie TCL_OK. Si une erreur se produit, Tcl_Close renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré avec Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devez utiliser Tcl_UnregisterChannel, qui appelle Tcl_Close en interne lorsque tous les appels à Tcl_RegisterChannel ont été mis en correspondance par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, les convertissant en UTF-8 selon l'encodage du canal et stockant les données produites dans la représentation de readObjPtr. La valeur renvoyée par Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit pendant la lecture, la valeur renvoyée est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

La valeur de charsToRead

TCL_GETSOBJ_ET_TCL_GETS

Tcl_Getsobj consomme des octets de channel, convertissant les octets en UTF-8 en se basant sur l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée ait été vue. Si l'encodage du canal est binary, chaque octet lu depuis le canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception du ou des caractères de fin de ligne, sont ajoutés à la représentation en chaîne de caractères de lineObjPtr. Le ou les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_Getsobj retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_Getsobj retourne également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est retourné, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité des entrées.

Tcl_Get est identique à Tcl_Getsobj sauf que les caractères résultants sont ajoutés à la chaîne dynamique donnée par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, à la tête ou à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées à la tête de la file. Si channel a un indicateur "sticky" EOF défini, aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets retourne inputLen ou -1 si une erreur se produit.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données caractères à charBuf. Les caractères UTF-8 dans le tampon sont convertis selon l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par un caractère nul et il sortira tout jusqu'au caractère nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal sur none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est le nombre d'octets qui ont été acceptés pour la sortie vers le canal. Il s'agit soit d'un nombre supérieur à zéro pour indiquer le succès, soit de -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme selon l'option -translation du canal. Ceci est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars, sauf qu'il accepte une valeur Tcl dont le contenu sera sorti vers le canal. Les caractères UTF-8 dans la représentation en chaîne de writeObjPtr sont convertis selon l'encodage du canal et mis en file d'attente pour la sortie vers channel. Par optimisation de performance, lors de l'écriture dans un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lorsqu'ils sont écrits. Au lieu de cela, les octets de la représentation interne de writeObjPtr en tant que valeur de tableau d'octets sont écrits dans le canal. La représentation en tableau d'octets de la valeur sera construite si nécessaire. De cette manière, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans jamais avoir à les convertir depuis ou vers UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'il n'effectue pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par un caractère nul et il sortira tout jusqu'au caractère nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas le chaînage. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée dans le canal le plus haut dans la pile dont le canal fourni fait partie, Tcl_WriteRaw ne le fait pas. Par conséquent, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation vers le canal inférieur.

TCL_FLUSH

Tcl_Flush force la sortie de toutes les données mises en mémoire tampon pour channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données mises en mémoire tampon n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal est non bloquant ; il démarre une opération de vidage en arrière-plan qui écrira les données mises en mémoire tampon dans le canal éventuellement, aussi rapidement que le canal peut les absorber.

La valeur de retour est normalement TCL_OK. Si une erreur se produit, Tcl_Flush retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données ultérieures seront lues ou écrites. La sortie mise en mémoire tampon est vidée vers le canal et l'entrée mise en mémoire tampon est discardée, avant l'opération de recherche.

Tcl_Seek retourne normalement le nouveau point d'accès. Si une erreur se produit, Tcl_Seek retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut avoir été déplacé ou non.

TCL_TELL

Tcl_Tell retourne le point d'accès actuel pour un canal. La valeur retournée est -1 si le canal ne supporte pas la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent de channel à une longueur donnée de length octets. Il retourne TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et de leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, c'est le nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue, en utilisant

g une série d'appels à Tcl_DStringAppendElement. Les différentes options préexistantes et leurs valeurs possibles sont décrites dans la page de manuel de la commande Tcl fconfigure. D'autres options peuvent être ajoutées par chaque type de canal. Ces options spécifiques au type de canal sont décrites dans la page de manuel de la commande Tcl qui crée un canal de ce type ; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans la page de manuel de la commande Tcl socket. La procédure renvoie normalement TCL_OK. Si une erreur se produit, elle renvoie TCL_ERROR et appelle Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption attribue une nouvelle valeur newValue à une option optionName sur le canal channel. La procédure renvoie normalement TCL_OK. Si une erreur se produit, elle renvoie TCL_ERROR ; de plus, si interp n'est pas NULL, Tcl_SetChannelOption laisse un message d'erreur dans le résultat de l'interpréteur.

TCL_EOF

Tcl_Eof renvoie une valeur non nulle si le canal channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked renvoie une valeur non nulle si le canal channel est en mode non bloquant et que la dernière opération d'entrée a renvoyé moins de données que demandé car il n'y avait pas suffisamment de données disponibles. L'appel renvoie toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered renvoie le nombre d'octets d'entrée actuellement en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en lecture, cette fonction renvoie toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered renvoie le nombre d'octets de sortie actuellement en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en écriture, cette fonction renvoie toujours zéro.

PROBLÈMES DE PLATEFORME

Les descripteurs renvoyés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que renvoyé par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel ou Tcl_MakeFileChannel. D'autres types de canaux peuvent renvoyer un type de descripteur différent sur les plateformes Windows.
