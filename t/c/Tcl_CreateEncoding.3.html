const char *name (in)
Nom de l'encodage à charger.
Tcl_Encoding encoding (in)
Encodage à consulter, libérer ou utiliser pour convertir du texte. Si encoding est NULL, l'encodage du système actuel est utilisé.

Nom de l'encodage pour obtenir le jeton.
Tcl_Encoding *encodingPtr (out)
Le jeton d'encodage sera écrit ici.
const char *src (in)
Pour les fonctions Tcl_ExternalToUtf, un tableau d'octets dans l'encodage spécifié qui doit être converti en UTF-8. Pour les fonctions Tcl_UtfToExternal et Tcl_WinUtfToTChar, un tableau de caractères UTF-8 qui doit être converti dans l'encodage spécifié.
const TCHAR *tsrc (in)
Un tableau de caractères Windows TCHAR qui doit être converti en UTF-8.
int srcLen (in)
Longueur de src ou tsrc en octets. Si la longueur est négative, la longueur spécifiée par l'encodage est utilisée.
Tcl_DString *dstPtr (out)
Un pointeur vers une structure Tcl_DString non initialisée ou libérée dans laquelle le résultat converti sera stocké.
int flags (in)
Bites de drapeaux ORés. TCL_ENCODING_START indique que le tampon d'entrée est le premier bloc d'un flux d'entrée (potentiellement à plusieurs blocs), indiquant à la routine de conversion de se réinitialiser à son état initial et d'effectuer toute initialisation nécessaire avant la première conversion d'octet. TCL_ENCODING_END indique que le tampon d'entrée est le dernier bloc d'un flux d'entrée (potentiellement à plusieurs blocs), indiquant à la routine de conversion d'effectuer toute finalisation nécessaire après la dernière conversion d'octet, puis de se réinitialiser à son état initial. TCL_ENCODING_STOPONERROR indique que la routine de conversion retournera immédiatement si un caractère d'entrée est lu qui n'existe pas dans l'encodage cible ; sinon, un caractère de substitution par défaut sera automatiquement substitué.
Tcl_EncodingState *statePtr (in/out)
Utilisé lors de la conversion d'un flux d'octets (généralement long ou de longueur indéfinie) par morceaux. La routine de conversion stocke son état actuel dans *statePtr après que src (le tampon contenant le morceau actuel) a été converti ; les informations d'état doivent être renvoyées lors de la conversion du prochain morceau du flux afin que la routine de conversion sache dans quel état elle se trouvait lorsqu'elle a été interrompue à la fin du dernier morceau. Peut être NULL, auquel cas la valeur spécifiée pour flags est ignorée et on suppose que le tampon d'entrée contient la chaîne complète à convertir.
char *dst (out)
Tampon dans lequel le résultat de la conversion est stocké. Pas plus de dstLen octets ne seront stockés dans dst.
int dstLen (in)
Longueur maximale du tampon de sortie dst en octets.
int *srcReadPtr (out)
Rempli avec le nombre d'octets de src qui ont été convertis. Cela peut être inférieur à la longueur d'origine des caractères d'entrée s'il y a eu un problème lors de la conversion de certains caractères d'entrée. Peut être NULL.
int *dstWrotePtr (out)
Rempli avec le nombre d'octets qui ont été stockés dans le tampon de sortie à la suite de la conversion. Peut être NULL.
int *dstCharsPtr (out)
Rempli avec le nombre de caractères correspondant au nombre d'octets stockés dans le tampon de sortie. Peut être NULL.
Tcl_DString *bufPtr (out)
Stocke le nom du système d'encodage spécifié.
const Tcl_EncodingType *typePtr (in)
Structure définissant un nouveau type d'encodage.
Tcl_Obj *searchPath (in)
Liste des répertoires de fichiers dans lesquels rechercher les fichiers d'encodage.
const char *path (in)
Un chemin vers l'emplacement des fichiers d'encodage.

INTRODUCTION

Ces routines convertissent entre la représentation interne des caractères de Tcl, UTF-8, et les représentations de caractères utilisées par divers systèmes d'exploitation ou systèmes de fichiers, tels que Unicode, ASCII ou EUC-JP. Lors de la manipulation de chaînes, comme l'obtention du nom d'un fichier ou l'affichage de caractères à l'aide de polices internationales, les chaînes doivent être traduites dans un ou plusieurs formats que les différents appels système peuvent utiliser. Par exemple, dans un environnement Unix japonais, un utilisateur pourrait obtenir un nom de fichier représenté dans l'encodage EUC-JP, puis traduire les caractères dans l'encodage JISX0208 pour afficher le nom du fichier dans un widget Tk. Le but de l'encodage est d'aider à combler le fossé de traduction. UTF-8 fournit un pont de staging pour tous les différents encodages. Dans l'exemple précédent, le texte serait traduit de l'encodage utilisé par l'opération système vers UTF-8. Ensuite, il serait traduit de UTF-8 vers l'encodage requis par les routines d'affichage.

Certains encodages de base sont inclus dans Tcl. D'autres peuvent être définis par l'utilisateur ou chargés dynamiquement à partir de fichiers d'encodage autonomes.

DESCRIPTION

Tcl_GetEncoding recherche un encodage donné son name. Le nom peut faire référence à un encodage Tcl prédéfini, à un encodage défini par l'utilisateur enregistré en appelant Tcl_CreateEncoding, ou à un encodage chargeable dynamiquement. La valeur retournée est un jeton représentant l'encodage et peut être utilisé dans des appels ultérieurs à des procédures telles que Tcl_GetEncodingName, Tcl_FreeEncoding et Tcl_UtfToExternal. Si le nom ne fait référence à aucun encodage connu ou chargeable, NULL est retourné et un message d'erreur est retourné dans interp.

L'encodage maintient un pool d'encodages actuellement en cours d'utilisation. Lorsque name est demandé pour la première fois, Tcl_GetEncoding renvoie un encodage avec un compteur de références de 1. Si name est demandé plusieurs fois, le compteur de références de cet encodage est incrémenté sans les frais généraux d'allocation d'un nouvel encodage et de ses structures associées.

Lorsqu'un encodage n'est plus utilisé, Tcl_FreeEncoding doit être appelé pour le libérer. Lorsqu'un encodage n'est plus utilisé nulle part (c'est-à-dire qu'il a été libéré autant de fois qu'il a été obtenu), Tcl_FreeEncoding libérera toute la mémoire de l'encodage et le supprimera du pool.

Tcl_GetEncodingFromObj traite la représentation de chaîne de objPtr comme un nom d'encodage et recherche un encodage portant ce nom, de la même manière que Tcl_GetEncoding. Lorsqu'un encodage est trouvé, il est mis en cache dans la valeur objPtr pour référence future, et le jeton Tcl_Encoding est écrit dans l'emplacement spécifié par encodingPtr.

Mantenga toda la estructura del archivo. El valor TCL_OK se devuelve si el encodingPtr se encarga de la codificación especificada. Si no existe tal codificación, se devuelve TCL_ERROR y no se realiza ninguna escritura en *encodingPtr. Esto es similar al caso de Tcl_GetEncoding, y el usuario debe llamar a Tcl_FreeEncoding sobre el token de codificación resultante cuando ya no lo vaya a utilizar.

Tcl_ExternalToUtfDString convierte un búfer fuente src de la codificación especificada a UTF-8. Los bytes convertidos se almacenan en dstPtr, que luego se termina con un carácter nulo específico de la codificación. El usuario debe llamar eventualmente a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Cuando se realiza la conversión, si algún carácter de la fuente no puede representarse en la codificación de destino, se utiliza un carácter de reemplazo por defecto. El valor devuelto es un puntero al valor almacenado en el DString.

Tcl_ExternalToUtf convierte un búfer fuente src de la codificación especificada a UTF-8. Un máximo de srcLen bytes se convierten de la fuente y un máximo de dstLen bytes se almacenan en dst. En todos los casos, *srcReadPtr se llena con el número de bytes convertidos de src y *dstWrotePtr se llena con el número correspondiente de bytes almacenados en dst. El valor devuelto es uno de los siguientes:

TCL_OK
Todo el contenido de src se convirtió.
TCL_CONVERT_NOSPACE
El búfer de destino no era suficiente para todos los datos convertidos; se convirtieron tantos caracteres como fue posible.
TCL_CONVERT_MULTIBYTE
Los últimos bytes de la fuente eran el inicio de una secuencia multibyte, pero se necesitaban más bytes para completar esta secuencia. Una llamada posterior a la conversión debe pasar un búfer que contenga los bytes no convertidos restantes de src más algunos bytes adicionales de la fuente para convertir correctamente la secuencia multibyte que se dividió.
TCL_CONVERT_SYNTAX
El búfer fuente contenía una secuencia de caracteres inválida. Esto puede ocurrir si el flujo de entrada ha sido dañado o si el método de codificación especificado se identificó incorrectamente.
TCL_CONVERT_UNKNOWN
El búfer fuente contenía un carácter que no podía representarse en la codificación de destino y se especificó TCL_ENCODING_STOPONERROR.

Tcl_UtfToExternalDString convierte un búfer fuente src de UTF-8 a la codificación especificada. Los bytes convertidos se almacenan en dstPtr, que luego se termina con un carácter nulo específico de la codificación. El usuario debe llamar eventualmente a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Cuando se realiza la conversión, si algún carácter de la fuente no puede representarse en la codificación de destino, se utiliza un carácter de reemplazo por defecto. El valor devuelto es un puntero al valor almacenado en el DString.

Tcl_UtfToExternal convierte un búfer fuente src de UTF-8 a la codificación especificada. Un máximo de srcLen bytes se convierten de la fuente y un máximo de dstLen bytes se almacenan en dst. En todos los casos, *srcReadPtr se llena con el número de bytes convertidos de src y *dstWrotePtr se llena con el número correspondiente de bytes almacenados en dst. Los valores devueltos son los mismos que los de Tcl_ExternalToUtf.

Tcl_WinUtfToTChar y Tcl_WinTCharToUtf son funciones de conveniencia para convertir entre UTF-8 y cadenas de Windows basadas en el tipo TCHAR, que por convención es un carácter Unicode en Windows NT.

Tcl_GetEncodingName es aproximadamente el inverso de Tcl_GetEncoding. Dado un encoding, el valor devuelto es el name que se utilizó para crear la codificación. La cadena devuelta por Tcl_GetEncodingName solo se garantiza que persista hasta que el encoding sea eliminado. El usuario no debe modificar esta cadena.

Tcl_SetSystemEncoding establece la codificación predeterminada que se debe usar cuando el usuario pasa un valor nulo para el argumento encoding a cualquier función de codificación. Si name es nulo, la codificación del sistema se restablece a la codificación predeterminada del sistema, binary. Si el nombre no se refiere a ninguna codificación conocida o cargable, se devuelve TCL_ERROR y se deja un mensaje de error en interp. De lo contrario, este procedimiento incrementa el recuento de referencias de la nueva codificación del sistema, decrementa el recuento de referencias de la codificación antigua del sistema y devuelve TCL_OK.

Tcl_GetEncodingNameFromEnvironment proporciona una forma para que la librería Tcl informe el nombre de codificación que creemos que es correcto como codificación del sistema, basándose en llamadas al sistema y el examen del entorno apropiado para la plataforma. Acepta bufPtr, un puntero a un Tcl_DString no inicializado o liberado, y escribe el nombre de la codificación en él. El valor devuelto es el valor de Tcl_DStringValue.

Tcl_GetEncodingNames establece el resultado interp a una lista consistente de los nombres de todas las codificaciones definidas o dinámicamente cargables, buscando en la ruta de codificaciones especificada por Tcl_SetDefaultEncodingDir. Este procedimiento no asegura que los archivos cargables dinámicamente contengan datos válidos, sino que solo asegura que existan.

Tcl_CreateEncoding define una nueva codificación y registra los procedimientos C que se llaman para convertir entre esta codificación y UTF-8. Las codificaciones creadas por Tcl_CreateEncoding son posteriormente visibles en la base de datos utilizada por Tcl_GetEncoding. Al igual que con Tcl_GetEncoding, el valor devuelto es un token que representa la codificación y se puede utilizar en llamadas posteriores a otras funciones de codificación. Tcl_CreateEncoding devuelve una codificación con un contador de referencias de 1. Si ya existe una codificación con el nombre especificado, su entrada en la base de datos se reemplaza con la nueva codificación; el token de la codificación antigua sigue siendo válido y continúa comportándose como antes, pero los usuarios del nuevo token ahora llamarán los nuevos procedimientos de codificación.

El argumento typePtr de Tcl_CreateEncoding contiene información sobre el nombre de la codificación y los procedimientos que se llamarán para convertir entre esta codificación y UTF-8. Se define como sigue:

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

El encodingName proporciona un nombre de cadena para la codificación, por el cual se puede referir en otros procedimientos como Tcl_GetEncoding. El toUtfProc se refiere a un procedimiento de devolución de llamada para invocar para convertir texto de esta codificación a UTF-8. El fromUtfProc se refiere a un procedimiento de devolución de llamada para invocar para convertir texto de UTF-8 a esta codificación. El freeProc se refiere a un procedimiento de devolución de llamada para invocar cuando se elimina esta codificación. El campo freeProc puede ser nulo. El clientData contiene un valor arbitrario de tamaño de una palabra pasado a toUtfProc, fromUtfProc y freeProc cuando se llamen. Normalmente, este es un puntero a un conjunto de datos que contiene información específica de la codificación, que puede ser utilizada por los procedimientos de devolución de llamada. Por ejemplo, dos codificaciones muy similares como ascii y macRoman pueden utilizar el mismo procedimiento de devolución de llamada, pero utilizan diferentes valores de clientData para controlar su comportamiento. El nullSize especifica el número de bytes nulos que señalan el final de cadena en esta codificación. Debe ser 1 (para codificaciones de un solo byte o multibyte como ASCII o Shift-JIS) o 2 (para codificaciones de doble byte como Unicode). Las codificaciones constantes con 3 o más bytes por carácter (como CNS11643) no son aceptadas.

Los procedimientos de devolución de llamada toUtfProc y fromUtfProc deben coincidir con el tipo Tcl_EncodingConvertProc:

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

Los procedimientos toUtfProc y fromUtfProc son llamados por Tcl_ExternalToUtf o Tcl_UtfToExternal para realizar la conversión real. El parámetro clientData de estos procedimientos es el mismo que el clientData especificado en Tcl_CreateEncoding cuando se creó la codificación. Los argumentos restantes de los procedimientos de devolución de llamada son los mismos que los argumentos, documentados en la parte superior, de Tcl_ExternalToUtf o Tcl_UtfToExternal, con las siguientes excepciones. Si el argumento srcLen de una de estas funciones de nivel superior es negativo, el valor pasado al procedimiento de devolución de llamada será la longitud correcta de la codificación de src. Si alguno de los argumentos srcReadPtr, dstWrotePtr o dstCharsPtr de una de estas funciones de nivel superior es NULL, el valor correspondiente pasado al procedimiento de devolución de llamada será un lugar no nulo.

El procedimiento de devolución de llamada freeProc, si no es nulo, debe coincidir con el tipo Tcl_EncodingFreeProc:

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

Este freeProc se llama cuando se elimina la codificación. El parámetro clientData es el mismo que el clientData especificado en Tcl_CreateEncoding cuando se creó la codificación.

Tcl_GetEncodingSearchPath y Tcl_SetEncodingSearchPath se utilizan para acceder y configurar la lista de directorios de archivos del sistema que se buscan para archivos de codificación. El valor devuelto por Tcl_GetEncodingSearchPath es el valor almacenado por la última llamada exitosa a Tcl_SetEncodingSearchPath. Si no se han realizado llamadas a Tcl_SetEncodingSearchPath, Tcl calculará un valor inicial basado en el entorno. Hay una ruta de búsqueda de codificación para todo el proceso, compartida por todos los hilos del proceso.

INTRODUCTION

Tcl provides built-in support for Unicode, and can convert between Unicode and other character encodings. These conversions are performed by procedures and data structures described here. Tcl includes a basic set of common encodings, and can also load additional encodings from dynamically loadable encoding files.

DESCRIPTION

The procedure Tcl_CreateEncoding is used to register a new encoding with the Tcl interpreter. The encoding is identified by the name encodingName. The argument bytesPerChar should be non-zero for single-byte and double-byte encodings, and zero for multi-byte encodings. The arguments outputFacts and inputFacts point to structures that describe the number of characters that can be converted in a single call, the number of fallback characters, and whether the encoding is variable-length. The arguments encodeProc and decodeProc point to the procedures that perform the actual conversion between Unicode and the encoding. The argument freeProc is a procedure that will be called when the encoding is deleted, and clientData is arbitrary data to be passed to encodeProc, decodeProc, and freeProc. Tcl_CreateEncoding returns TCL_OK on success and TCL_ERROR on failure.

The procedures Tcl_GetEncodingSearchPath and Tcl_SetEncodingSearchPath are used to get and set the search path for encoding data files. The search path is a list of directories. Tcl searches these directories in order for encoding data files. Non-existent or non-readable filesystem directories on the searchPath are silently ignored.

Tcl_GetDefaultEncodingDir and Tcl_SetDefaultEncodingDir are obsolete interfaces best replaced with calls to Tcl_GetEncodingSearchPath and Tcl_SetEncodingSearchPath. They are called to access and set the first element of the searchPath list. Since Tcl searches searchPath for encoding data files in list order, these routines establish the “default” directory in which to find encoding data files.

ENCODING FILES

Space would prohibit precompiling into Tcl every possible encoding algorithm, so many encodings are stored on disk as dynamically-loadable encoding files. This behavior also allows the user to create additional encoding files that can be loaded using the same mechanism. These encoding files contain information about the tables and/or escape sequences used to map between an external encoding and Unicode. The external encoding may consist of single-byte, multi-byte, or double-byte characters.

Each dynamically-loadable encoding is represented as a text file. The initial line of the file, beginning with a “#” symbol, is a comment that provides a human-readable description of the file. The next line identifies the type of encoding file. It can be one of the following letters:

[1] S
A single-byte encoding, where one character is always one byte long in the encoding. An example is iso8859-1, used by many European languages.
[2] D
A double-byte encoding, where one character is always two bytes long in the encoding. An example is big5, used for Chinese text.
[3] M
A multi-byte encoding, where one character may be either one or two bytes long. Certain bytes are lead bytes, indicating that another byte must follow and that together the two bytes represent one character. Other bytes are not lead bytes and represent themselves. An example is shiftjis, used by many Japanese computers.
[4] E
An escape-sequence encoding, specifying that certain sequences of bytes do not represent characters, but commands that describe how following bytes should be interpreted.

The rest of the lines in the file depend on the type.

Cases [1], [2], and [3] are collectively referred to as table-based encoding files. The lines in a table-based encoding file are in the same format as this example taken from the shiftjis encoding (this is not the complete file):

The third line of the file is three numbers. The first number is the fallback character (in base 16) to use when converting from UTF-8 to this encoding. The second number is a 1 if this file represents the encoding for a symbol font, or 0 otherwise. The last number (in base 10) is how many pages of data follow.

Subsequent lines in the example above are pages that describe how to map from the encoding into 2-byte Unicode. The first line in a page identifies the page number. Following it are 256 double-byte numbers, arranged as 16 rows of 16 numbers. Given a character in the encoding, the high byte of that character is used to select which page, and the low byte of that character is used as an index to select one of the double-byte numbers in that page - the value obtained being the corresponding Unicode character. By examination of the example above, one can see that the characters 0x7E and 0x8163 in shiftjis map to 203E and 2026 in Unicode, respectively.

Following the first page will be all the other pages, each in the same format as the first: one number identifying the page followed by 256 double-byte Unicode characters. If a character in the encoding maps to the Unicode character 0000, it means that the character does not actually exist. If all characters on a page would map to 0000, that page can be omitted.

Case [4] is the escape-sequence encoding file. The lines in an this type of file are in the same format as this example taken from the iso2022-jp encoding:

# Encoding file: iso2022-jp, escape-driven
E
init		{}
final		{}
iso8859-1	\x1b(B
jis0201		\x1b(J
jis0208		\x1b$@
jis0208		\x1b$B
jis0212		\x1b$(D
gb2312		\x1b$A
ksc5601		\x1b$(C

In the file, the first column represents an option and the second column is the associated value. init is a string to emit or expect before the first character is converted, while final is a string to emit or expect after the last character. All other options are names of table-based encodings; the associated value is the escape-sequence that marks that encoding. Tcl syntax is used for the values; in the above example, for instance, “{}” represents the empty string and “\x1b” represents character 27.

When Tcl_GetEncoding encounters an encoding name that has not been loaded, it attempts to load an encoding file called name.enc from the encoding subdirectory of each directory that Tcl searches for its script library. If the encoding file exists, but is malformed, an error message will be left in interp.
