ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour la signalisation d'erreur et pour rechercher un canal enregistré dans l'interpréteur.
const char *fileName (in)
Le nom d'un fichier local ou réseau.
const char *mode (in)
Spécifie comment le fichier doit être accédé. Peut avoir l'une des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (in)
Indicateurs de permissions de style POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront appliquées au fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans options de la commande Tcl exec.
int flags (in)
Spécifie la disposition des descripteurs de fichiers stdio dans le pipeline : une combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, l'entrée standard du premier fils dans le pipeline est le canal du pipeline, sinon elle est identique à l'entrée standard du processus appelant ; de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, le pipeline peut rediriger les descripteurs de fichiers stdio pour outrepasser les descripteurs de fichiers stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, de telles redirections provoquent une erreur.
ClientData handle (in)
Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, il s'agit d'un descripteur de fichier, pour Windows, il s'agit d'un HANDLE.
int readOrWrite (in)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (in)
Le motif à faire correspondre, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl pour l'entrée ou la sortie. Doit être le résultat d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker les caractères lus depuis le canal.
int charsToRead (in)
Le nombre de caractères à lire depuis le canal. Si le codage du canal est binary, cela équivaut au nombre d'octets à lire depuis le canal.
int appendFlag (in)
Si non nul, les données lues depuis le canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (out)
Un tampon dans lequel stocker les octets lus depuis le canal.
int bytesToRead (in)
Le nombre d'octets à lire depuis le canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker la ligne lue depuis le canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne dynamique Tcl dans laquelle stocker la ligne lue depuis le canal. Doit avoir été initialisé par l'appelant. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne dynamique.
const char *input (in)
L'entrée à ajouter à un tampon de canal.
int inputLen (in)
Longueur de l'entrée
int addAtEnd (in)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon du canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera envoyé en sortie vers le canal.
const char *charBuf (in)
Un tampon contenant les caractères à envoyer en sortie vers le canal.
const char *byteBuf (in)
Un tampon contenant les octets à envoyer en sortie vers le canal.
int bytesToWrite (in)
Le nombre d'octets à consommer depuis charBuf ou byteBuf et à envoyer vers le canal.
Tcl_WideInt offset (in)
Jusqu'où déplacer le point d'accès dans le canal où la prochaine opération d'entrée ou de sortie sera appliquée, mesuré en octets depuis la position donnée par seekMode. Peut être positif ou négatif.
int seekMode (in)
Par rapport à quel point chercher ; utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs légales sont SEEK_SET, SEEK_CUR, et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) à laquelle tronquer le canal.
const char *optionName (in)
Le nom d'une option applicable à ce canal, tel que -blocking. Peut avoir l'une des valeurs acceptées par la commande fconfigure.
Tcl_DString *optionValue (in)
Où stocker la valeur d'une option ou une liste de toutes les options et leurs valeurs. Doit avoir été initialisé par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des périphériques et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie en tampon sur une variété de types de fichiers, de sockets et de périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée de manuel de Tcl_CreateChannel. Le mécanisme de canaux fournit un système de mise en tampon calqué sur les E/S standard d'Unix, et il permet également des E/S non bloquantes sur les canaux.

Les procédures décrites dans cette entrée de manuel comprennent les API C de la couche générique de l'architecture des canaux. Pour une description de l'architecture du pilote de canal et comment implémenter des pilotes de canal pour de nouveaux types de canaux, voir l'entrée de manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier nommé fileName, crée un nouveau canal Tcl associé au fichier, et le retourne. Le mode d'ouverture et les permissions sont spécifiés par mode et permissions, respectivement. Le paramètre mode peut avoir l'une des valeurs acceptées par la commande Tcl open (par exemple, "r", "w", "rb", "w+", etc.). Si un nouveau fichier est créé, il reçoit les permissions spécifiées par permissions. Le fichier est ouvert en utilisant les fonctionnalités d'E/S du système d'exploitation sous-jacent. Le canal retourné est initialement en mode bloquant. Si une erreur survient lors de l'ouverture du fichier, une erreur est signalée dans l'interpréteur interp et NULL est retourné.

Tcl_OpenFileChannel supporte les noms de fichiers réseau, à condition que le système d'exploitation sous-jacent le supporte.

Les options pour le canal créé peuvent être définies en appelant Tcl_SetChannelOption. Les options courantes incluent -blocking, -buffering, -encoding, -translation, et -eof.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel crée un pipeline de processus, en exécutant la commande spécifiée par argc et argv. Les descripteurs de fichiers stdio du premier processus du pipeline sont configurés selon les indicateurs spécifiés dans flags. Les canaux d'entrée et de sortie sont créés pour le pipeline et retournés par la procédure. Les descripteurs de fichiers stdio qui ne sont pas redirigés sont hérités du processus appelant.

Les valeurs possibles pour flags sont des combinaisons OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Les indicateurs TCL_STDIN, TCL_STDOUT, et TCL_STDERR spécifient si l'entrée standard, la sortie standard ou l'erreur standard du premier processus doivent être connectées au pipeline. Si TCL_ENFORCE_MODE est défini, toute tentative de redirection de ces descripteurs de fichiers par le programme appelé entraînera une erreur.

Si le pipeline est créé avec succès, un canal Tcl est retourné. Sinon, une erreur est signalée dans l'interpréteur interp et NULL est retourné.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel prend un descripteur de fichier système existant (par exemple, le résultat de l'appel à `open` ou `socket` au niveau du système d'exploitation) et l'enveloppe dans un canal Tcl. Le paramètre handle est le descripteur de fichier du système d'exploitation, et readOrWrite spécifie si le canal doit être lisible, écrivable, ou les deux (en utilisant une combinaison OR de TCL_READABLE et TCL_WRITABLE).

Le canal résultant est initialement en mode bloquant. Le canal retourné doit être explicitement enregistré dans l'interpréteur à l'aide de Tcl_RegisterChannel avant de pouvoir être utilisé.

Cette fonction est utile pour interagir avec des descripteurs de fichiers existants, tels que ceux associés aux canaux standard (stdin, stdout, stderr) ou ceux créés par des appels système de bas niveau.

TCL_GETCHANNEL

Tcl_GetChannel recherche un canal existant nommé channelName dans l'interpréteur interp. Si modePtr n'est pas NULL, il pointe vers un entier qui recevra une valeur indiquant si le canal est lisible et/ou écrivable (une combinaison OR de TCL_READABLE et TCL_WRITABLE).

Si le canal est trouvé, un pointeur vers celui-ci est retourné. Sinon, une erreur est signalée dans l'interpréteur interp et NULL est retourné.

TCL_GETCHANNELNAMES

Tcl_GetChannelNames crée une liste de tous les noms de canaux actuellement enregistrés dans l'interpréteur interp et la stocke dans la variable d'interpréteur nommée auto_channelNames. Elle retourne le nombre de canaux trouvés.

Tcl_GetChannelNamesEx fait de même, mais ne renvoie que les noms de canaux qui correspondent au modèle pattern spécifié en utilisant Tcl_StringMatch.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel enregistre le canal channel avec l'interpréteur interp, le rendant ainsi disponible pour utilisation par les commandes Tcl (comme puts, gets, etc.) et par d'autres procédures Tcl manipulant des canaux.

Le canal doit avoir été créé précédemment, par exemple par Tcl_OpenFileChannel ou Tcl_MakeFileChannel.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel désenregistre le canal channel de l'interpréteur interp. Cela empêche toute utilisation future du canal par les commandes Tcl. La procédure ne ferme pas le canal; il est de la responsabilité de l'appelant de fermer le canal en appelant Tcl_Close.

Elle retourne TCL_OK si le canal a été désenregistré avec succès, sinon elle retourne TCL_ERROR (par exemple, si le canal n'était pas enregistré).

TCL_DETACHCHANNEL

Tcl_DetachChannel détache un canal de son interpréteur associé. Après cette opération, le canal ne sera plus affecté par les opérations sur l'interpréteur (par exemple, la fermeture de l'interpréteur n'entraînera pas la fermeture du canal). Le canal reste valide et peut être utilisé jusqu'à ce qu'il soit fermé explicitement par Tcl_Close.

Elle retourne TCL_OK si le canal a été détaché avec succès, sinon elle retourne TCL_ERROR.

TCL_ISTANDARDCHANNEL

Tcl_IsStandardChannel retourne 1 si le canal channel est l'un des canaux standard (entrée, sortie ou erreur standard) de l'interpréteur Tcl, et 0 sinon.

TCL_CLOSE

Tcl_Close ferme le canal channel. Toutes les opérations d'E/S sur le canal sont terminées. S'il y a des données dans le tampon de sortie, elles sont vidées sur le périphérique sous-jacent. Le canal est ensuite désenregistré de l'interpréteur.

Elle retourne TCL_OK si le canal a été fermé avec succès, sinon elle retourne TCL_ERROR (par exemple, si une erreur s'est produite lors de la vidange des tampons).

TCL_READCHARS

Tcl_ReadChars tente de lire jusqu'à charsToRead caractères depuis le canal channel et de les placer dans le Tcl objet pointé par readObjPtr. Si appendFlag est non nul, les caractères lus sont ajoutés à la fin de la valeur actuelle de l'objet; sinon, ils remplacent le contenu existant de l'objet.

Si la lecture réussit, le nombre de caractères réellement lus est retourné. La valeur peut être inférieure à charsToRead si la fin du fichier est atteinte ou si le canal est en mode non bloquant et qu'aucune donnée n'est disponible. Si une erreur se produit, Tcl_ReadChars retourne -1 et une condition d'erreur est définie dans l'interpréteur interp.

Cette procédure gère le décodage des caractères selon le jeu de caractères spécifié pour le canal. Si le canal est ouvert en mode binaire, il lit des octets plutôt que des caractères.

TCL_READ

Tcl_Read tente de lire jusqu'à bytesToRead octets depuis le canal channel et de les placer dans le tampon readBuf. Le tampon doit être suffisamment grand pour contenir bytesToRead octets.

Si la lecture réussit, le nombre d'octets réellement lus est retourné. La valeur peut être inférieure à bytesToRead si la fin du fichier est atteinte ou si le canal est en mode non bloquant et qu'aucune donnée n'est disponible. Si une erreur se produit, Tcl_Read retourne -1 et une condition d'erreur est définie dans l'interpréteur interp.

Cette procédure lit des octets bruts, sans aucun décodage ni traduction.

TCL_GETSOBJ

Tcl_GetsObj lit des données depuis le canal channel jusqu'à ce qu'un caractère de nouvelle ligne soit rencontré, ou jusqu'à ce que la fin du fichier soit atteinte. La ligne lue (y compris le caractère de nouvelle ligne, s'il est rencontré) est stockée dans le Tcl objet pointé par lineObjPtr. La ligne lue est ajoutée à la valeur existante de l'objet.

Si une ligne est lue avec succès, 0 est retourné. Si la fin du fichier est atteinte avant la lecture d'une ligne complète, 1 est retourné et l'objet contient les données restantes (qui peuvent être vides). Si une erreur se produit, Tcl_GetsObj retourne -1 et une condition d'erreur est définie dans l'interpréteur interp.

Cette procédure gère le décodage des caractères selon le jeu de caractères spécifié pour le canal.

TCL_GETS

Tcl_Gets est similaire à Tcl_GetsObj, mais lit la ligne dans une chaîne dynamique Tcl (Tcl_DString) pointée par lineRead. La ligne lue (y compris le caractère de nouvelle ligne) est ajoutée à la chaîne dynamique.

Les valeurs de retour sont les mêmes que pour Tcl_GetsObj.

TCL_UNGETS

Tcl_Ungets place les données spécifiées par input et inputLen dans un tampon interne associé au canal channel. Ces données seront lues par des appels ultérieurs à Tcl_ReadChars ou Tcl_GetsObj.

Si addAtEnd est non nul, les données sont ajoutées à la fin des données déjà dans le tampon. Sinon, elles sont ajoutées au début.

Elle retourne TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

TCL_WRITEOBJ

Tcl_WriteObj écrit le contenu du Tcl objet pointé par writeObjPtr dans le canal channel. Les données sont d'abord encodées selon le jeu de caractères du canal.

Si l'écriture réussit, le nombre d'octets réellement écrits est retourné. La valeur peut être inférieure au nombre total d'octets dans l'objet si le canal est en mode non bloquant et que le tampon de sortie est plein. Si une erreur se produit, Tcl_WriteObj retourne -1 et une condition d'erreur est définie dans l'interpréteur interp.

TCL_WRITECHARS

Tcl_WriteChars écrit jusqu'à bytesToWrite octets depuis le tampon charBuf dans le canal channel. Les données sont d'abord encodées selon le jeu de caractères du canal.

Si l'écriture réussit, le nombre d'octets réellement écrits est retourné. La valeur peut être inférieure à bytesToWrite si le canal est en mode non bloquant et que le tampon de sortie est plein. Si une erreur se produit, Tcl_WriteChars retourne -1 et une condition d'erreur est définie dans l'interpréteur interp.

TCL_WRITE

Tcl_Write écrit jusqu'à bytesToWrite octets depuis le tampon byteBuf dans le canal channel. Les données sont écrites telles quelles, sans aucun encodage.

Si l'écriture réussit, le nombre d'octets réellement écrits est retourné. La valeur peut être inférieure à bytesToWrite si le canal est en mode non bloquant et que le tampon de sortie est plein. Si une erreur se produit, Tcl_Write retourne -1 et une condition d'erreur est définie dans l'interpréteur interp.

TCL_READRAW

Tcl_ReadRaw est similaire à Tcl_Read, mais elle lit toujours des octets bruts, indépendamment du codage du canal.

TCL_WRITERAW

Tcl_WriteRaw est similaire à Tcl_Write, mais elle écrit toujours des octets bruts, indépendamment du codage du canal.

TCL_EOF

Tcl_Eof retourne 1 si la fin du fichier a été atteinte pour le canal channel lors d'une opération de lecture précédente, et 0 sinon.

TCL_FLUSH

Tcl_Flush vide tous les tampons de sortie pour le canal channel sur le périphérique sous-jacent. Cela garantit que toutes les données écrites ont été effectivement transmises.

Elle retourne TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

TCL_INPUTBLOCKED

Tcl_InputBlocked retourne 1 si une tentative de lecture sur le canal channel bloquerait (c'est-à-dire, s'il n'y a pas de données disponibles dans le tampon de lecture et que le canal est en mode non bloquant), et 0 sinon.

TCL_INPUTBUFFERED

Tcl_InputBuffered retourne le nombre d'octets actuellement dans le tampon de lecture du canal channel qui n'ont pas encore été lus par l'application.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered retourne le nombre d'octets actuellement dans le tampon d'écriture du canal channel qui n'ont pas encore été écrits sur le périphérique sous-jacent.

TCL_SEEK

Tcl_Seek modifie le point d'accès courant du canal channel. L'argument offset spécifie le nombre d'octets à déplacer, et seekMode indique si le déplacement est relatif au début du fichier (SEEK_SET), à la position courante (SEEK_CUR), ou à la fin du fichier (SEEK_END).

Elle retourne la nouvelle position du pointeur de fichier sous forme de Tcl_WideInt en cas de succès. Si une erreur se produit, elle retourne -1 (TCL_WIDE_INT_MIN) et une condition d'erreur est définie dans l'interpréteur interp.

Cette opération n'est valide que pour les canaux qui supportent la recherche (par exemple, les fichiers).

TCL_TELL

Tcl_Tell retourne la position courante du pointeur de fichier dans le canal channel sous forme de Tcl_WideInt.

Si une erreur se produit, elle retourne -1 (TCL_WIDE_INT_MIN) et une condition d'erreur est définie dans l'interpréteur interp.

Cette opération n'est valide que pour les canaux qui supportent la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier associé au canal channel à la longueur spécifiée par length. Si la longueur spécifiée est supérieure à la taille actuelle du fichier, le fichier est étendu et rempli de zéros.

Elle retourne TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

Cette opération n'est valide que pour les canaux qui sont ouverts en écriture et qui représentent des fichiers.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère la valeur de l'option spécifiée par optionName pour le canal channel et la stocke dans la chaîne dynamique optionValue. La chaîne dynamique doit avoir été initialisée avant l'appel.

Les noms d'options valides sont les mêmes que ceux acceptés par la commande Tcl fconfigure, tels que -blocking, -buffering, -encoding, etc.

Elle retourne TCL_OK en cas de succès, et TCL_ERROR en cas d'échec (par exemple, si l'option n'est pas valide ou si le canal n'existe pas).

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit la valeur de l'option spécifiée par optionName pour le canal channel à la valeur donnée par newValue.

Les noms d'options valides et leurs valeurs acceptables sont les mêmes que ceux utilisés par la commande Tcl fconfigure.

Elle retourne TCL_OK en cas de succès, et TCL_ERROR en cas d'échec (par exemple, si l'option n'est pas valide, si la valeur n'est pas correcte, ou si le canal n'existe pas).

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et retourne un descripteur de canal qui peut être utilisé pour effectuer des entrées et des sorties sur le fichier. Cette API est calquée sur la procédure fopen de la bibliothèque d'entrées-sorties standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur les valeurs Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel dans la mesure du possible.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Elle crée une séquence de sous-processus spécifiés par les arguments argv et argc et retourne un canal qui peut être utilisé pour communiquer avec ces sous-processus. L'argument flags indique quel type de communication existera avec le pipeline de commandes.

Si l'indicateur TCL_STDIN est défini, alors l'entrée standard du premier sous-processus sera liée au canal : l'écriture dans le canal fournira l'entrée au sous-processus. Si TCL_STDIN n'est pas défini, alors l'entrée standard du premier sous-processus sera la même que l'entrée standard de cette application. Si TCL_STDOUT est défini, alors la sortie standard du dernier sous-processus pourra être lue à partir du canal ; sinon, elle ira à la sortie standard de cette application. Si TCL_STDERR est défini, la sortie d'erreur standard pour tous les sous-processus est renvoyée au canal et entraîne une erreur lors de la fermeture du canal ; sinon, elle va à la sortie d'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas défini, alors argc et argv peuvent rediriger les descripteurs stdio pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, alors c'est une erreur pour argc et argv de remplacer les canaux stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un descripteur de fichier existant, spécifique à la plateforme. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel retourne un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur Tcl dans interp. Si un canal portant ce nom n'est pas enregistré dans cet interpréteur, la procédure retourne NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms en fonction du pattern. Si pattern est NULL, alors il n'y aura pas de filtrage. La valeur de retour est TCL_OK si aucune erreur ne s'est produite lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl s'exécutant dans cet interpréteur peuvent faire référence au canal dans les opérations d'entrée ou de sortie en utilisant le nom donné dans l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code s'exécutant en dehors de tout interpréteur Tcl peut appeler Tcl_RegisterChannel avec interp comme NULL, pour indiquer qu'il souhaite détenir une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et il ne sera fermé que lorsque le nombre correspondant d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code s'exécutant en dehors de tout interpréteur de détenir en toute sécurité une référence à un canal qui est également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code qui gère les canaux standard. Si aucun canal standard n'a été initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un exposé général sur les canaux standard et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Si cette opération a retiré le dernier enregistrement du canal dans un interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur Tcl peut appeler Tcl_UnregisterChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera maintenant fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel sauf qu'il fermera également le canal si aucune référence supplémentaire n'existe.

TCL_DETACHCHANNEL

Tcl_DetachChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Au-delà de cela, cette commande n'a aucun autre effet. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin), et retournera TCL_ERROR si on lui passe l'un de ces canaux.

Le code non associé à un interpréteur Tcl peut appeler Tcl_DetachChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. Si c'est le cas, il retourne 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou autrement valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lors de l'appel à Tcl_Close. Les sorties en mémoire tampon sont vidées sur le périphérique de sortie du canal avant la destruction du canal, et toute entrée en mémoire tampon est ignorée. S'il s'agit d'un canal bloquant, l'appel ne retourne pas tant que toutes les données en mémoire tampon n'ont pas été envoyées avec succès au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a une sortie en mémoire tampon qui ne peut pas être écrite sans bloquer, l'appel retourne immédiatement ; la sortie est vidée en arrière-plan et le canal sera fermé une fois que toutes les données en mémoire tampon auront été transmises. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close retourne TCL_OK. Si une erreur se produit, Tcl_Close retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré en utilisant Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a déjà été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez plutôt utiliser Tcl_UnregisterChannel, qui appellera Tcl_Close en interne lorsque tous les appels à Tcl_RegisterChannel auront été mis en correspondance par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, convertit les octets en UTF-8 en fonction de l'encodage du canal et stocke les données produites dans la représentation de chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Définir charsToRead

TCL_READCHARS, TCL_READOBJ, AND TCL_READ

Tcl_ReadChars lit tous les caractères disponibles actuellement (mode non bloquant) ou tout jusqu'à la fin de fichier (mode bloquant) du canal spécifié dans channel et les stocke dans readObjPtr. Le nombre de caractères à lire est spécifié par bytesToRead. Si bytesToRead est négatif, l'appel lit tous les caractères actuellement disponibles (mode non bloquant) ou tout jusqu'à la fin de fichier (mode bloquant).

La valeur de retour peut être inférieure à la valeur demandée, indiquant que moins de données que demandé étaient disponibles. Ceci est appelé une lecture partielle. En mode bloquant, cela ne peut se produire qu'à la fin d'un fichier. En mode non bloquant, une lecture partielle peut aussi se produire s'il n'y a pas assez d'entrée actuellement disponible : Tcl_ReadChars renvoie un nombre réduit plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour savoir laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les diverses représentations de fin de ligne en la représentation interne canonique \n selon le mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les divers modes spécifiques à la plateforme sont décrits dans la page de manuel de la commande Tcl fconfigure.

Par optimisation de performance, lors de la lecture d'un canal avec l'encodage binary, les octets ne sont pas convertis en UTF-8 lors de la lecture. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr comme une valeur de tableau d'octets. La représentation chaîne de cette valeur ne sera construite que si elle est nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette manière, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'elle ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Elle est dépréciée et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Elle consomme des octets du channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par un caractère nul. Son contenu est valide à partir de la position zéro et jusqu'à, mais sans inclure, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas l'empilement. Alors que Tcl_Read (et les autres fonctions de l'API) obtiennent toujours leurs données du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_ReadRaw ne le fait pas. Par conséquent, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données du canal inférieur dans la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, en convertissant les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée soit vue. Si l'encodage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception des caractères de fin de ligne terminating, sont ajoutés à la représentation chaîne de lineObjPtr. Les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_GetsObj renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj renvoie également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est renvoyé, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité des entrées.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique donnée par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisée pour ajouter des données à la file d'attente d'entrée d'un canal, à la tête ou à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si channel a un indicateur EOF « collant » (sticky), aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets renvoie inputLen ou -1 en cas d'erreur.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données caractère à charBuf. Les caractères UTF-8 dans le tampon sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars attend que charBuf soit terminé par un caractère nul et écrit tout jusqu'au caractère nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering du canal sur none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering du canal sur le mode line.

La valeur de retour de Tcl_WriteChars est le nombre d'octets qui ont été acceptés pour la sortie vers le canal. C'est soit un nombre supérieur à zéro pour indiquer le succès, soit -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme selon l'option -translation du canal. Cela est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'elle accepte une valeur Tcl dont le contenu sera envoyé au canal. Les caractères UTF-8 de la représentation chaîne de writeObjPtr sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. Par optimisation de performance, lors de l'écriture dans un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lorsqu'ils sont écrits. Au lieu de cela, les octets de la représentation interne de writeObjPtr en tant que valeur de tableau d'octets sont écrits dans le canal. La représentation tableau d'octets de la valeur sera construite si elle est nécessaire. De cette manière, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'elle ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Elle est dépréciée et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Elle accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write attend que byteBuf soit terminé par un caractère nul et écrit tout jusqu'au caractère nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée vers le canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_WriteRaw ne le fait pas. Par conséquent, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation vers le canal inférieur.

TCL_FLUSH

Tcl_Flush provoque l'écriture de toutes les données de sortie en tampon du channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données en tampon n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal n'est pas bloquant ; il démarre une opération de vidage en arrière-plan qui écrira les données en tampon vers le canal éventuellement, aussi rapidement que le canal peut les absorber.

La valeur de retour est normalement TCL_OK. En cas d'erreur, Tcl_Flush retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans le channel où les données ultérieures seront lues ou écrites. La sortie en tampon est vidée vers le canal et l'entrée en tampon est discardée, avant l'opération de déplacement.

Tcl_Seek retourne normalement le nouveau point d'accès. En cas d'erreur, Tcl_Seek retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut avoir été déplacé ou non.

TCL_TELL

Tcl_Tell retourne le point d'accès actuel pour un canal. La valeur retournée est -1 si le canal ne supporte pas le déplacement.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent du channel à une longueur donnée d'octets. Il renvoie TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit une nouvelle valeur newValue pour une option optionName sur channel. La procédure retourne normalement TCL_OK. Si une erreur survient, elle retourne TCL_ERROR ; de plus, si interp n'est pas NULL, Tcl_SetChannelOption laisse un message d'erreur dans le résultat de l'interpréteur.

TCL_EOF

Tcl_Eof retourne une valeur non nulle si channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked retourne une valeur non nulle si channel est en mode non bloquant et que la dernière opération d'entrée a retourné moins de données que demandé car il n'y avait pas suffisamment de données disponibles. L'appel retourne toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered retourne le nombre d'octets d'entrée actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en lecture, cette fonction retourne toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered retourne le nombre d'octets de sortie actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en écriture, cette fonction retourne toujours zéro.

PROBLÈMES DE PLATEFORME

Les descripteurs retournés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que retourné par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel, ou Tcl_MakeFileChannel. D'autres types de canaux peuvent retourner un type de descripteur différent sur les plateformes Windows.
