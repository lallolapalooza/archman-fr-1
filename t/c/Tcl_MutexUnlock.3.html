ARGUMENTS

Tcl_Condition *condPtr (in)
Une variable de condition, qui doit être associée à un verrou mutex.
Tcl_Mutex *mutexPtr (in)
Un verrou mutex.
const Tcl_Time *timePtr (in)
Une limite de temps pour l'attente de condition. NULL pour attendre indéfiniment. Notez qu'une valeur de 0 seconde pour le polling n'a pas beaucoup de sens.
Tcl_ThreadDataKey *keyPtr (in)
Ceci identifie un bloc de stockage local au thread. La clé doit être statique et globale au processus, mais chaque thread finira par associer un bloc de stockage différent à cette clé.
int *size (in)
La taille du bloc de stockage local au thread. Cette quantité de données est allouée et initialisée à zéro la première fois que chaque thread appelle Tcl_GetThreadData.
Tcl_ThreadId *idPtr (out)
Le stockage référencé contiendra l'identifiant du nouveau thread tel que retourné par le système d'exploitation.
Tcl_ThreadId id (in)
Identifiant du thread attendu.
Tcl_ThreadCreateProc *proc (in)
Cette procédure agira comme le main() du nouveau thread. Le clientData spécifié sera son unique argument.
ClientData clientData (in)
Informations arbitraires. Passées comme unique argument à la proc.
int stackSize (in)
La taille de la pile allouée au nouveau thread.
int flags (in)
Masque de bits contenant des drapeaux permettant à l'appelant de modifier le comportement du nouveau thread.
int *result (out)
Le stockage référencé est utilisé pour y placer le code de sortie du thread attendu.

INTRODUCTION

À partir de la version 8.1, le noyau Tcl est thread-safe, ce qui vous permet d'intégrer Tcl dans des applications multithreadées sans personnaliser le noyau Tcl. À partir de la version 8.6, le support du multithreading Tcl est activé par défaut. Pour désactiver le support du multithreading Tcl, vous devez inclure l'option --disable-threads à configure lors de la configuration et de la compilation de votre noyau Tcl.

Une contrainte importante de l'implémentation des threads Tcl est que seul le thread qui a créé un interpréteur Tcl peut utiliser cet interpréteur. En d'autres termes, plusieurs threads ne peuvent pas accéder au même interpréteur Tcl. (Cependant, un seul thread peut créer et utiliser plusieurs interpréteurs en toute sécurité.)

DESCRIPTION

Tcl fournit Tcl_CreateThread pour la création de threads. L'appelant peut déterminer la taille de la pile allouée au nouveau thread et modifier le comportement via les flags fournis. La valeur TCL_THREAD_STACK_DEFAULT pour stackSize indique que la taille par défaut telle que spécifiée par le système d'exploitation doit être utilisée pour le nouveau thread. Quant aux drapeaux, actuellement seules les valeurs TCL_THREAD_NOFLAGS et TCL_THREAD_JOINABLE sont définies. La première d'entre elles invoque le comportement par défaut sans paramètres spéciaux. L'utilisation de la seconde valeur marque le nouveau thread comme joignable. Cela signifie qu'un autre thread peut attendre la sortie de ce thread marqué et le joindre.

Restrictions : Sur certains systèmes UNIX, la bibliothèque pthread ne contient pas la fonctionnalité permettant de spécifier la taille de la pile d'un thread. La valeur spécifiée pour la taille de la pile est ignorée sur ces systèmes. Windows ne prend pas en charge les threads joignables actuellement. Cette valeur de drapeau est donc ignorée sur cette plateforme.

Tcl fournit les fonctions Tcl_ExitThread et Tcl_FinalizeThread pour terminer les threads et invoquer les gestionnaires de sortie optionnels par thread. Voir la page Tcl_Exit pour plus d'informations sur ces procédures.

La fonction Tcl_JoinThread est fournie pour permettre aux threads d'attendre la sortie d'un autre thread, qui doit avoir été marqué comme joignable par l'utilisation du drapeau TCL_THREAD_JOINABLE lors de sa création via Tcl_CreateThread.

Tenter d'attendre la sortie d'un thread non joignable ou d'un thread qui est déjà attendu entraînera une erreur. Attendre un thread joignable qui est déjà sorti est possible, le système conservera les informations nécessaires jusqu'après l'appel à Tcl_JoinThread. Cela signifie que ne pas appeler Tcl_JoinThread pour un thread joignable entraînera une fuite de mémoire.

L'appel Tcl_GetThreadData renvoie un pointeur vers un bloc de données privées au thread. Son argument est une clé partagée par tous les threads et une taille pour le bloc de stockage. Le stockage est automatiquement alloué et initialisé à zéro la première fois que chaque thread le demande. Le stockage est automatiquement désalloué par Tcl_FinalizeThread.

SYNCHRONISATION ET COMMUNICATION

Tcl fournit Tcl_ThreadQueueEvent et Tcl_ThreadAlert pour la gestion de la mise en file d'attente d'événements dans les applications multithreadées. Voir la page de manuel Notifier pour plus d'informations sur ces procédures.

Un mutex est un verrou utilisé pour sérialiser tous les threads à travers un morceau de code en appelant Tcl_MutexLock et Tcl_MutexUnlock. Si un thread détient un mutex, tout autre thread appelant Tcl_MutexLock sera bloqué jusqu'à ce que Tcl_MutexUnlock soit appelé. Un mutex peut être détruit après son utilisation en appelant Tcl_MutexFinalize. Le résultat du verrouillage d'un mutex deux fois par le même thread est indéfini. Sur certaines plateformes, cela entraînera un interblocage. Les procédures Tcl_MutexLock, Tcl_MutexUnlock et Tcl_MutexFinalize sont définies comme des macros vides si elles ne sont pas compilées avec les threads activés. Pour la déclaration des mutex, la macro TCL_DECLARE_MUTEX doit être utilisée. Cette macro assure une gestion correcte des mutex même lorsque le noyau est compilé sans les threads activés.

Une variable de condition est utilisée comme mécanisme de signalisation : un thread peut verrouiller un mutex, puis attendre sur une variable de condition avec Tcl_ConditionWait. Ceci libère atomiquement le verrou mutex et bloque le thread en attente jusqu'à ce qu'un autre thread appelle Tcl_ConditionNotify. L'appelant de Tcl_ConditionNotify doit avoir le mutex associé verrouillé en appelant préalablement Tcl_MutexLock, mais ce n'est pas une obligation. La notification de la variable de condition débloque tous les threads en attente sur la variable de condition, mais ils ne progressent pas tant que le mutex n'est pas libéré avec Tcl_MutexUnlock. L'implémentation de Tcl_ConditionWait verrouille automatiquement le mutex avant de retourner.

L'appelant de Tcl_ConditionWait doit être préparé aux notifications erronées en appelant Tcl_ConditionWait dans une boucle while qui teste un invariant.

Une variable de condition peut être détruite après son utilisation en appelant Tcl_ConditionFinalize.

Les procédures Tcl_ConditionNotify, Tcl_ConditionWait et Tcl_ConditionFinalize sont définies comme des macros vides si elles ne sont pas compilées avec les threads activés.

INITIALISATION

Tous ces objets de synchronisation sont auto-initialisés. Ils sont implémentés comme des pointeurs opaques qui doivent être NULL lors de la première utilisation. Les mutex et les variables de condition sont soit nettoyés par les gestionnaires de sortie de processus (s'ils vivent assez longtemps), soit explicitement par des appels à Tcl_MutexFinalize ou Tcl_ConditionFinalize. Le stockage local aux threads est récupéré pendant Tcl_FinalizeThread.

SYNTHÈSE

Pour créer un thread avec du code portable, votre fonction d'implémentation doit être déclarée comme suit:

static Tcl_ThreadCreateProc MyThreadImplFunc;

Vous devriez ensuite la définir comme suit, qui compte juste jusqu'à une valeur donnée puis se termine.

static Tcl_ThreadCreateType
MyThreadImplFunc(
    ClientData clientData)
{
    int i, limit = (int) clientData;
    for (i=0 ; i<limit ; i++) {
        /* ne rien faire ici */
    }
    TCL_THREAD_CREATE_RETURN;
}

Pour créer le thread ci-dessus, le faire exécuter et attendre qu'il se termine, vous feriez ceci:

int limit = 1000000000;
ClientData limitData = (void*)((intptr_t) limit);
Tcl_ThreadId id;    /* stocke l'identifiant du thread créé */
int result;
if (Tcl_CreateThread(&id, MyThreadImplFunc, limitData,
        TCL_THREAD_STACK_DEFAULT,
        TCL_THREAD_JOINABLE) != TCL_OK) {
    /* le thread n'a pas été créé correctement */
    return;
}
/* faites quelque chose un moment ici */
if (Tcl_JoinThread(id, &result) != TCL_OK) {
    /* le thread ne s'est pas terminé correctement */
    return;
}
/* tout s'est bien nettoyé */
