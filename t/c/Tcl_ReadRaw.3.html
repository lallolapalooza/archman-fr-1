ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour le reporting d'erreurs et pour rechercher un canal enregistré en son sein.
const char *fileName (in)
Le nom d'un fichier local ou réseau.
const char *mode (in)
Spécifie comment le fichier doit être accédé. Peut avoir l'une des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (in)
Indicateurs de permission de style POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront définies sur le fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans option de la commande Tcl exec.
int flags (in)
Spécifie la disposition des descripteurs stdio dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, stdin pour le premier enfant dans le pipeline est le canal de pipe, sinon il est le même que l'entrée standard du processus appelant ; idem pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, alors le pipe peut rediriger les descripteurs stdio pour outrepasser les descripteurs stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, de telles redirections provoquent une erreur.
ClientData handle (in)
Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, c'est un descripteur de fichier, pour Windows, c'est un HANDLE.
int readOrWrite (in)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (in)
Le motif à faire correspondre, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl pour l'entrée ou la sortie. Doit avoir été la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker les caractères lus depuis le canal.
int charsToRead (in)
Le nombre de caractères à lire depuis le canal. Si le codage du canal est binary, cela équivaut au nombre d'octets à lire depuis le canal.
int appendFlag (in)
Si non nul, les données lues depuis le canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (out)
Un tampon dans lequel stocker les octets lus depuis le canal.
int bytesToRead (in)
Le nombre d'octets à lire depuis le canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker la ligne lue depuis le canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne dynamique Tcl dans laquelle stocker la ligne lue depuis le canal. Doit avoir été initialisée par l'appelant. La ligne lue sera ajoutée aux données déjà présentes dans la chaîne dynamique.
const char *input (in)
L'entrée à ajouter à un tampon de canal.
int inputLen (in)
Longueur de l'entrée
int addAtEnd (in)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon de canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera envoyé en sortie vers le canal.
const char *charBuf (in)
Un tampon contenant les caractères à envoyer en sortie vers le canal.
const char *byteBuf (in)
Un tampon contenant les octets à envoyer en sortie vers le canal.
int bytesToWrite (in)
Le nombre d'octets à consommer depuis charBuf ou byteBuf et à envoyer en sortie vers le canal.
Tcl_WideInt offset (in)
À quelle distance déplacer le point d'accès dans le canal auquel la prochaine opération d'entrée ou de sortie sera appliquée, mesuré en octets par rapport à la position donnée par seekMode. Peut être positif ou négatif.
int seekMode (in)
Par rapport à quel point chercher ; utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs légales sont SEEK_SET, SEEK_CUR, et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) à laquelle tronquer le canal.
const char *optionName (in)
Le nom d'une option applicable à ce canal, telle que -blocking. Peut avoir l'une des valeurs acceptées par la commande fconfigure.
Tcl_DString *optionValue (in)
Où stocker la valeur d'une option ou une liste de toutes les options et leurs valeurs. Doit avoir été initialisé par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des périphériques et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie en tampon sur une variété de types de fichiers, de sockets et de périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée de manuel de Tcl_CreateChannel. Le mécanisme de canaux fournit un schéma de mise en tampon inspiré des E/S standard Unix, et il permet également les E/S non bloquantes sur les canaux.

Les procédures décrites dans cette entrée de manuel constituent les API C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canaux et comment implémenter des pilotes de canaux pour de nouveaux types de canaux, voir l'entrée de manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

La procédure Tcl_OpenFileChannel ouvre le fichier nommé fileName et renvoie un canal Tcl qui peut être utilisé pour accéder au fichier. Le mode spécifie comment le fichier doit être ouvert (par exemple, pour la lecture, l'écriture, ou les deux) et peut avoir l'une des valeurs autorisées pour l'argument mode de la commande Tcl open. Si un nouveau fichier est créé, permissions spécifie les permissions POSIX du nouveau fichier.

Si un succès, Tcl_OpenFileChannel renvoie un handle de canal. Sinon, il laisse une entrée d'erreur dans interp et renvoie le pointeur NULL.

TCL_OPENCOMMANDCHANNEL

La procédure Tcl_OpenCommandChannel crée un pipeline de commandes Unix, spécifié par argv (une liste de chaînes de caractères qui représentent une commande et ses arguments), et renvoie un canal Tcl qui peut être utilisé pour communiquer avec le pipeline. Le canal peut être utilisé pour envoyer l'entrée standard au premier processus du pipeline et/ou pour lire sa sortie standard et/ou son flux d'erreurs standard.

Les arguments flags spécifient la disposition des descripteurs stdio pour le pipeline. Les options valides sont TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Ces options sont OR-ed ensemble pour former la valeur de flags.

Si TCL_STDIN est défini, le canal retourné est utilisé pour l'entrée standard du premier processus du pipeline. Sinon, le processus utilise l'entrée standard du processus appelant.

Si TCL_STDOUT est défini, un canal distinct est créé pour la sortie standard du dernier processus du pipeline. Si TCL_STDERR est défini, un canal distinct est créé pour le flux d'erreurs standard du dernier processus du pipeline. Sinon, ces flux sont ceux du processus appelant.

Si TCL_ENFORCE_MODE est défini, le programme d'appel ne peut pas avoir de descripteurs stdio qui se chevauchent avec ceux qui sont connectés au pipeline. Par exemple, si TCL_STDIN est défini, le programme d'appel ne peut pas avoir son stdin connecté au même descripteur de fichier.

La procédure renvoie le canal Tcl pour le pipeline. Si une erreur se produit, une entrée d'erreur est laissée dans interp et NULL est renvoyé.

TCL_MAKEFILECHANNEL

La procédure Tcl_MakeFileChannel prend un descripteur de fichier existant (handle) et crée un nouveau canal Tcl associé à ce descripteur. Le paramètre readOrWrite est un masque de bits qui indique si le canal doit être utilisable pour la lecture (TCL_READABLE) et/ou l'écriture (TCL_WRITABLE).

Cette procédure est généralement utilisée pour encapsuler des descripteurs de fichiers ou des handles de systèmes d'exploitation existants dans le système de canaux Tcl. Par exemple, elle est utilisée en interne par Tcl pour créer des canaux pour les descripteurs de fichiers standard (stdin, stdout, stderr) lors de l'initialisation.

La procédure renvoie le nouveau canal Tcl créé. Si une erreur se produit, NULL est renvoyé et une entrée d'erreur est laissée dans interp.

TCL_GETCHANNEL

La procédure Tcl_GetChannel recherche un canal existant par son nom (channelName) dans l'interpréteur interp. Si le canal est trouvé, son handle est renvoyé. Si modePtr n'est pas NULL, il pointe vers un entier qui recevra les modes du canal (combinaison OR de TCL_READABLE et TCL_WRITABLE).

Si le canal est trouvé, son handle est renvoyé. Sinon, NULL est renvoyé et une entrée d'erreur est laissée dans interp.

TCL_GETCHANNELNAMES

La procédure Tcl_GetChannelNames renvoie une liste de tous les noms de canaux actuellement enregistrés dans l'interpréteur interp. Les noms sont stockés sous forme de chaîne dans l'objet retourné par l'interpréteur (résultat de l'interpréteur).

Si un pattern est fourni, seuls les noms de canaux qui correspondent au motif sont renvoyés. Le motif est évalué en utilisant Tcl_StringMatch.

La procédure renvoie 1 en cas de succès, et 0 en cas d'erreur.

TCL_REGISTERCHANNEL

La procédure Tcl_RegisterChannel enregistre un canal channel dans l'interpréteur interp, le rendant disponible pour une utilisation par les commandes Tcl.

Si le canal est déjà enregistré, une erreur est générée.

TCL_UNREGISTERCHANNEL

La procédure Tcl_UnregisterChannel désenregistre le canal channel de l'interpréteur interp. Le canal est fermé s'il est encore ouvert. Si le canal n'est pas enregistré, une erreur est générée.

La procédure renvoie 1 en cas de succès, et 0 en cas d'erreur.

TCL_DETACHCHANNEL

La procédure Tcl_DetachChannel détache le canal channel de l'interpréteur interp, mais le laisse ouvert. Cela est utile pour transférer un canal à un autre processus ou pour conserver le canal ouvert après la sortie d'un interpréteur.

La procédure renvoie 1 en cas de succès, et 0 en cas d'erreur.

TCL_ISSTANDARDCHANNEL

La procédure Tcl_IsStandardChannel renvoie vrai (1) si le canal channel est l'un des canaux standard (stdin, stdout, ou stderr), et faux (0) sinon.

TCL_CLOSE

La procédure Tcl_Close ferme le canal channel. Toutes les données mises en tampon sont d'abord vidées vers le canal. Si une erreur se produit pendant la fermeture ou le vidage, une entrée d'erreur est laissée dans interp.

La procédure renvoie 1 en cas de succès, et 0 en cas d'erreur.

TCL_READCHARS

La procédure Tcl_ReadChars lit jusqu'à charsToRead caractères depuis le channel et les stocke dans la valeur Tcl pointée par readObjPtr. Si appendFlag est non nul, les caractères lus sont ajoutés à la fin de la valeur existante de readObjPtr. Sinon, ils remplacent le contenu existant.

Si une erreur se produit, une entrée d'erreur est laissée dans interp et 0 est renvoyé. En cas de succès, le nombre de caractères lus est renvoyé. Si la fin du fichier est atteinte avant que tous les caractères demandés ne soient lus, le nombre de caractères réellement lus est renvoyé.

TCL_READ

La procédure Tcl_Read lit jusqu'à bytesToRead octets depuis le channel et les stocke dans le tampon readBuf. Le tampon doit être suffisamment grand pour contenir bytesToRead octets.

Si une erreur se produit, une entrée d'erreur est laissée dans interp et -1 est renvoyé. En cas de succès, le nombre d'octets lus est renvoyé. Si la fin du fichier est atteinte avant que tous les octets demandés ne soient lus, le nombre d'octets réellement lus est renvoyé.

TCL_GETSOBJ

La procédure Tcl_GetsObj lit une ligne entière depuis le channel (jusqu'au prochain caractère de nouvelle ligne, inclus) et la stocke dans la valeur Tcl pointée par lineObjPtr. La ligne lue est ajoutée au contenu existant de lineObjPtr.

Si une erreur se produit, une entrée d'erreur est laissée dans interp et -1 est renvoyé. En cas de succès, 0 est renvoyé. Si la fin du fichier est atteinte avant la lecture d'une ligne entière, la ligne incomplète lue est renvoyée. Dans ce cas, si la ligne n'est pas vide, la procédure renvoie le nombre d'octets lus.

TCL_GETS

La procédure Tcl_Gets lit une ligne entière depuis le channel (jusqu'au prochain caractère de nouvelle ligne, inclus) et l'ajoute à la chaîne dynamique lineRead. Le caractère de nouvelle ligne est inclus dans la chaîne.

Si une erreur se produit, une entrée d'erreur est laissée dans interp et -1 est renvoyé. En cas de succès, 0 est renvoyé. Si la fin du fichier est atteinte avant la lecture d'une ligne entière, la ligne incomplète lue est ajoutée à lineRead. Dans ce cas, si la ligne n'est pas vide, la procédure renvoie le nombre d'octets lus.

TCL_UNGETS

La procédure Tcl_Ungets place la chaîne input de longueur inputLen dans le tampon d'entrée du canal channel. Si addAtEnd est nul, l'entrée est ajoutée au début du tampon. Sinon, elle est ajoutée à la fin.

Ceci est utile pour "défaire" une lecture, par exemple, pour permettre à une commande de relire des données qui ont déjà été lues.

La procédure renvoie 0 en cas de succès, et -1 en cas d'erreur.

TCL_WRITEOBJ

La procédure Tcl_WriteObj écrit le contenu de la valeur Tcl pointée par writeObjPtr vers le canal channel. L'encodage du canal est utilisé pour convertir les caractères Unicode en une séquence d'octets avant d'écrire.

Si une erreur se produit, une entrée d'erreur est laissée dans interp et -1 est renvoyé. En cas de succès, le nombre d'octets écrits est renvoyé.

TCL_WRITECHARS

La procédure Tcl_WriteChars écrit la chaîne de caractères charBuf de longueur bytesToWrite vers le canal channel. L'encodage du canal est utilisé pour convertir les caractères en une séquence d'octets avant d'écrire.

Si une erreur se produit, une entrée d'erreur est laissée dans interp et -1 est renvoyé. En cas de succès, le nombre d'octets écrits est renvoyé.

TCL_WRITE

La procédure Tcl_Write écrit bytesToWrite octets depuis le tampon byteBuf vers le canal channel. Aucune conversion d'encodage n'est effectuée ; les octets sont écrits tels quels.

Si une erreur se produit, une entrée d'erreur est laissée dans interp et -1 est renvoyé. En cas de succès, le nombre d'octets écrits est renvoyé.

TCL_READRAW

La procédure Tcl_ReadRaw lit jusqu'à bytesToRead octets depuis le channel et les stocke dans le tampon readBuf. Les octets sont lus tels quels, sans aucune conversion d'encodage.

Si une erreur se produit, une entrée d'erreur est laissée dans interp et -1 est renvoyé. En cas de succès, le nombre d'octets lus est renvoyé. Si la fin du fichier est atteinte avant que tous les octets demandés ne soient lus, le nombre d'octets réellement lus est renvoyé.

TCL_WRITERAW

La procédure Tcl_WriteRaw écrit bytesToWrite octets depuis le tampon byteBuf vers le canal channel. Les octets sont écrits tels quels, sans aucune conversion d'encodage.

Si une erreur se produit, une entrée d'erreur est laissée dans interp et -1 est renvoyé. En cas de succès, le nombre d'octets écrits est renvoyé.

TCL_EOF

La procédure Tcl_Eof renvoie vrai (1) si la fin du fichier a été atteinte sur le canal channel, et faux (0) sinon.

TCL_FLUSH

La procédure Tcl_Flush force l'écriture de toutes les données tamponnées vers le canal channel. Si une erreur se produit pendant le vidage, une entrée d'erreur est laissée dans interp.

La procédure renvoie 1 en cas de succès, et 0 en cas d'erreur.

TCL_INPUTBLOCKED

La procédure Tcl_InputBlocked renvoie vrai (1) si une lecture sur le canal channel bloquerait actuellement, et faux (0) sinon. Ceci est utile pour implémenter des E/S non bloquantes.

TCL_INPUTBUFFERED

La procédure Tcl_InputBuffered renvoie le nombre d'octets actuellement disponibles dans le tampon d'entrée du canal channel.

TCL_OUTPUTBUFFERED

La procédure Tcl_OutputBuffered renvoie le nombre d'octets actuellement en attente d'écriture dans le tampon de sortie du canal channel.

TCL_SEEK

La procédure Tcl_Seek modifie le point d'accès courant du canal channel. Le nouveau point d'accès est calculé en ajoutant offset octets au point de référence spécifié par seekMode. Les valeurs possibles pour seekMode sont SEEK_SET (début du fichier), SEEK_CUR (position actuelle), et SEEK_END (fin du fichier).

Si une erreur se produit, la procédure renvoie -1 et laisse une entrée d'erreur dans interp. Sinon, elle renvoie la nouvelle position du point d'accès, en octets, depuis le début du fichier.

TCL_TELL

La procédure Tcl_Tell renvoie la position actuelle du point d'accès dans le canal channel, en octets depuis le début du fichier.

Si une erreur se produit, la procédure renvoie -1 et laisse une entrée d'erreur dans interp.

TCL_TRUNCATECHANNEL

La procédure Tcl_TruncateChannel tronque le canal channel à la position spécifiée par length. Les données après cette position sont perdues.

La procédure renvoie 0 en cas de succès, et -1 en cas d'erreur.

TCL_GETCHANNELOPTION

La procédure Tcl_GetChannelOption récupère la valeur de l'option optionName pour le canal channel et la stocke dans la chaîne dynamique optionValue. Si optionName est NULL, toutes les options du canal sont récupérées sous forme d'une chaîne de la forme "-option1 valeur1 -option2 valeur2 ...".

La procédure renvoie 1 en cas de succès, et 0 en cas d'erreur.

TCL_SETCHANNELOPTION

La procédure Tcl_SetChannelOption définit la valeur de l'option optionName pour le canal channel sur la chaîne newValue.

La procédure renvoie 1 en cas de succès, et 0 en cas d'erreur.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et renvoie un descripteur de canal utilisable pour effectuer des opérations d'entrée/sortie sur le fichier. Cette API est basée sur la procédure fopen de la bibliothèque d'E/S standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles fournies dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur les valeurs Tcl_FSOpenFileChannel doit être préférée à Tcl_OpenFileChannel dans la mesure du possible.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standards, stdin, stdout ou stderr a été précédemment fermé, la création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Elle crée une séquence de sous-processus spécifiés par les arguments argv et argc et renvoie un canal utilisable pour communiquer avec ces sous-processus. L'argument flags indique le type de communication qui existera avec le pipeline de commandes.

Si le drapeau TCL_STDIN est défini, l'entrée standard du premier sous-processus sera liée au canal : écrire dans le canal fournira des données au sous-processus. Si TCL_STDIN n'est pas défini, alors l'entrée standard du premier sous-processus sera la même que l'entrée standard de cette application. Si TCL_STDOUT est défini, la sortie standard du dernier sous-processus peut être lue à partir du canal ; sinon, elle va à la sortie standard de cette application. Si TCL_STDERR est défini, la sortie d'erreur standard de tous les sous-processus est renvoyée au canal et entraîne une erreur lors de la fermeture du canal ; sinon, elle va à la sortie d'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas défini, alors argc et argv peuvent rediriger les descripteurs stdio pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, alors c'est une erreur que argc et argv redirectionnent des canaux stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standards, stdin, stdout ou stderr a été précédemment fermé, la création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un descripteur de fichier existant, spécifique à la plateforme. Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standards, stdin, stdout ou stderr a été précédemment fermé, la création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel renvoie un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur Tcl dans interp. Si un canal de ce nom n'est pas enregistré dans cet interpréteur, la procédure renvoie NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms selon le pattern. Si pattern est NULL, alors aucun filtrage ne sera effectué. La valeur de retour est TCL_OK si aucune erreur ne s'est produite lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutant dans cet interpréteur peuvent se référer au canal dans les opérations d'entrée ou de sortie en utilisant le nom donné dans l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code exécutant en dehors de tout interpréteur Tcl peut appeler Tcl_RegisterChannel avec interp comme NULL, pour indiquer qu'il souhaite conserver une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et il ne sera fermé que lorsque le nombre correspondant d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code exécutant en dehors de tout interpréteur de conserver en toute sécurité une référence à un canal qui est également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code qui gère les canaux standards. Si aucun canal standard n'a été initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour une discussion générale sur les canaux standards et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel supprime un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour se référer au canal dans cet interpréteur. Si cette opération a supprimé la dernière inscription du canal dans un interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur Tcl peut appeler Tcl_UnregisterChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera alors fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel sauf qu'il fermera également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel supprime un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour se référer au canal dans cet interpréteur. Au-delà de cela, cette commande n'a pas d'autre effet. Elle ne peut pas être utilisée sur les canaux standards (stdout, stderr, stdin), et renverra TCL_ERROR si on lui passe l'un de ces canaux.

Le code non associé à un interpréteur Tcl peut appeler Tcl_DetachChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standards, stdin, stdout ou stderr. Si c'est le cas, il renvoie 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standards sont initialisés ou autrement valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lors de l'appel à Tcl_Close. La sortie mise en mémoire tampon est vidée sur le périphérique de sortie du canal avant la destruction du canal, et toute entrée mise en mémoire tampon est rejetée. S'il s'agit d'un canal bloquant, l'appel ne retourne pas tant que toutes les données mises en mémoire tampon n'ont pas été envoyées avec succès sur le périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a une sortie mise en mémoire tampon qui ne peut pas être écrite sans bloquer, l'appel retourne immédiatement ; la sortie est vidée en arrière-plan et le canal sera fermé une fois que toutes les données mises en mémoire tampon auront été traitées. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close renvoie TCL_OK. Si une erreur se produit, Tcl_Close renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré en utilisant Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour les détails. Si le canal a déjà été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez plutôt utiliser Tcl_UnregisterChannel, qui appellera en interne Tcl_Close lorsque tous les appels à Tcl_RegisterChannel auront été égalés par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, convertit les octets en UTF-8 en fonction du codage du canal et stocke les données produites dans la représentation de chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Définir charsToRead<

/i> à -1 fera en sorte que la commande lise tous les caractères actuellement disponibles (sans blocage) ou tout jusqu'à eof (mode bloquant).

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé étaient disponibles. Ceci est appelé une lecture partielle. En mode bloquant, cela ne peut arriver qu'à la fin du fichier. En mode non bloquant, une lecture partielle peut également se produire s'il n'y a pas assez d'entrée actuellement disponible : Tcl_ReadChars renvoie un nombre réduit plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour déterminer laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les différentes représentations de fin de ligne en la représentation interne canonique \n selon le mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les différents modes spécifiques à la plate-forme sont décrits dans l'entrée du manuel de la commande Tcl fconfigure.

En tant qu'optimisation des performances, lors de la lecture d'un canal avec l'encodage binary, les octets ne sont pas convertis en UTF-8 lors de leur lecture. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr sous forme de tableau d'octets. La représentation sous forme de chaîne de cette valeur ne sera construite que si nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette façon, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'il ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour assurer la compatibilité descendante avec les extensions Tcl non internationalisées. Il consomme des octets du channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par un caractère nul. Son contenu est valide à partir de la position zéro jusqu'à, mais sans inclure, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas le chaînage. Alors que Tcl_Read (et les autres fonctions de l'API) obtiennent toujours leurs données du canal le plus haut dans la pile dont le canal fourni fait partie, Tcl_ReadRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données du canal inférieur vers la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, convertissant les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée ait été vue. Si l'encodage du canal est binary, chaque octet lu à partir du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception des caractères de fin de ligne terminaux, sont ajoutés à la représentation sous forme de chaîne de lineObjPtr. Les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_GetsObj renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj renvoie également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 s'il n'y avait pas de données disponibles ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est renvoyé, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité d'entrée.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique donnée par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, soit à la tête, soit à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si channel a un EOF "collant" défini, aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets renvoie inputLen ou -1 en cas d'erreur.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données de caractères à charBuf. Les caractères UTF-8 dans le tampon sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par un caractère nul et il affiche tout jusqu'au caractère nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal à none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un compte du nombre d'octets acceptés pour la sortie vers le canal. Il s'agit soit d'une valeur supérieure à zéro pour indiquer le succès, soit de -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plate-forme selon l'option -translation pour le canal. Ceci est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'il accepte une valeur Tcl dont le contenu sera affiché sur le canal. Les caractères UTF-8 dans la représentation sous forme de chaîne de writeObjPtr sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. En tant qu'optimisation des performances, lors de l'écriture sur un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets dans la représentation interne de writeObjPtr sous forme de tableau d'octets sont écrits sur le canal. La représentation sous forme de tableau d'octets de la valeur sera construite si nécessaire. De cette façon, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'il ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour assurer la compatibilité descendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par un caractère nul et il affiche tout jusqu'au caractère nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas le chaînage. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée du canal le plus haut dans la pile dont le canal fourni fait partie, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation vers le canal inférieur.

TCL_FLUSH

Tcl_Flush force la sortie de toutes les données tamponnées pour channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données tamponnées n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal est non bloquant ; il démarre une vidange en arrière-plan qui écrira les données tamponnées dans le canal éventuellement, aussi vite que le canal pourra les absorber.

La valeur de retour est normalement TCL_OK. En cas d'erreur, Tcl_Flush renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données ultérieures seront lues ou écrites. La sortie tamponnée est vidée vers le canal et l'entrée tamponnée est supprimée, avant l'opération de recherche.

Tcl_Seek renvoie normalement le nouveau point d'accès. En cas d'erreur, Tcl_Seek renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut ou peut ne pas avoir été déplacé.

TCL_TELL

Tcl_Tell renvoie le point d'accès actuel d'un canal. La valeur renvoyée est -1 si le canal ne prend pas en charge la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent de channel à une longueur donnée en octets. Il renvoie TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, c'est le nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue, utilis

TCL_GETCHANNELOPTION

Tcl_GetChannelOption retrieves the value of an option optionName on channel. The value is returned in the interpreter's result. The procedure returns TCL_OK if the option was found and its value retrieved, or TCL_ERROR if the option is not supported by the channel. If interp is non-NULL, Tcl_GetChannelOption leaves an error message in the interpreter's result if an error occurs.

The value is returned as a Tcl string, which may be constructed using a series of calls to Tcl_DStringAppendElement. The various preexisting options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and calls Tcl_SetErrno to store an appropriate POSIX error code.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
