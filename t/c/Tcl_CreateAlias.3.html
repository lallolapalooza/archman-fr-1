DESCRIPTION

Ces fonctions sont destinées à l'accès à la fonctionnalité de multiples interpréteurs Tcl depuis des programmes C. Elles permettent la gestion de multiples interpréteurs dans une relation hiérarchique et la gestion d'alias, des commandes qui, lorsqu'elles sont invoquées dans un interpréteur, s'exécutent dans un autre interpréteur. La valeur retournée par les procédures qui retournent un int est TCL_OK ou TCL_ERROR. Si TCL_ERROR est retourné, le résultat de l'interpréteur contient un message d'erreur.

Tcl_CreateSlave crée un nouvel interpréteur comme enfant de interp. Elle crée également une commande enfant nommée childName dans interp qui permet à interp de manipuler le nouvel enfant. Si isSafe est zéro, la commande crée un enfant fiable dans lequel le code Tcl a accès à toutes les commandes Tcl. Si isSafe est 1, la commande crée un enfant "sécurisé" dans lequel le code Tcl n'a accès qu'à un ensemble de commandes Tcl définies comme "Tcl sécurisé" ; voir la page de manuel de la commande Tcl interp pour plus de détails. Si la création du nouvel interpréteur enfant échoue, NULL est retourné.

Tcl_CreateChild est un synonyme de Tcl_CreateSlave.

Tcl_IsSafe retourne 1 si interp est "sécurisé" (créé avec le drapeau TCL_SAFE_INTERPRETER spécifié), 0 sinon.

Tcl_MakeSafe marque interp comme "sécurisé", de sorte que les futurs appels à Tcl_IsSafe retourneront 1. Elle supprime également de interp toute fonctionnalité connue qui pourrait être dangereuse (commandes et variables). Cependant, elle ne peut pas savoir quelles parties d'une extension ou d'une application sont sécurisées et n'essaie pas de supprimer ces parties, donc la sécurité n'est pas garantie après l'appel à Tcl_MakeSafe. Les utilisateurs doivent faire preuve de prudence lors de l'utilisation de Tcl_MakeSafe pour éviter les fausses affirmations de sécurité. Dans de nombreux cas, Tcl_CreateSlave peut être une meilleure option, car elle crée des interpréteurs dans un état sécurisé connu.

Tcl_GetSlave retourne un pointeur vers un interpréteur enfant de interp. L'interpréteur enfant est identifié par childName. Si un tel interpréteur enfant n'existe pas, NULL est retourné.

Tcl_GetChild est un synonyme de Tcl_GetSlave.

Tcl_GetMaster retourne un pointeur vers l'interpréteur parent de interp. Si interp n'a pas de parent (c'est-à-dire qu'il s'agit d'un interpréteur de niveau supérieur), NULL est retourné.

Tcl_GetParent est un synonyme de Tcl_GetMaster.

Tcl_GetInterpPath stocke dans le résultat de interp le chemin relatif entre interp et childInterp ; childInterp doit être un enfant de interp. Si le calcul du chemin relatif réussit, TCL_OK est retourné, sinon TCL_ERROR est retourné et un message d'erreur est stocké dans le résultat de interp.

Tcl_CreateAlias crée une commande nommée childCmd dans childInterp qui, lorsqu'elle est invoquée, provoquera l'exécution de la commande targetCmd dans targetInterp. Les arguments spécifiés par les chaînes contenues dans argv sont toujours préfixés à tous les arguments fournis lors de l'invocation de childCmd et sont passés à targetCmd. Cette opération retourne TCL_OK si elle réussit, ou TCL_ERROR en cas d'échec ; dans ce cas, un message d'erreur est stocké dans la valeur du résultat de childInterp. Remarque : il n'y a aucune restriction sur la relation parenté (créée par Tcl_CreateSlave) entre childInterp et targetInterp. Deux interpréteurs quelconques peuvent être utilisés sans restriction quant à leur relation.

Tcl_CreateAliasObj est similaire à Tcl_CreateAlias mais prend un tableau de valeurs comme arguments supplémentaires au lieu d'un tableau de chaînes.

Tcl_GetAliasObj retourne des informations sous la forme d'un pointeur vers un tableau de structures Tcl_Obj concernant un alias aliasName dans interp. Tout champ de résultat peut être NULL, auquel cas la donnée correspondante n'est pas retournée. Si un champ de résultat n'est pas NULL, le pointeur indiqué est défini sur la donnée correspondante. Par exemple, si targetCmdPtr n'est pas NULL, il est défini sur un pointeur vers la chaîne contenant le nom de la commande cible.

ARGUMENTS

In addition to the arguments named below, all functions use these:

Tcl_Interp *interp
Interpreter to create the alias in.
const char *cmdName
Name for the new command or alias.
int levelCount
Number of stack frames to search backwards to find the correct interpreter.
const char *levelPtr[]
Array of names for the stack frames to search backwards.
int argCount
Number of arguments in argVec.
Tcl_Obj *argVec[]
Array of arguments for the alias command.
const char *hiddenCmdName
Name of the command to hide or expose.

DESCRIPTION

Tcl_CreateAlias and Tcl_CreateAliasObj create a new Tcl command named cmdName in the interpreter interp. This new command is an "alias" which, when invoked, will cause the script represented by argCount and argVec to be executed. The script is executed in the interpreter in which the alias was created. The alias is created in the global namespace unless cmdName contains namespace qualifiers. The script is executed with the invocation name set to cmdName.

The script is executed by first searching backwards through the call stack for levelCount frames, as specified by levelPtr. This is the same mechanism used by the Tcl uplevel command. If the correct interpreter is found, the script is executed there. If the correct interpreter cannot be found, the script is executed in the interpreter specified by interp.

Tcl_CreateAlias takes the arguments for the alias as an array of strings. Tcl_CreateAliasObj takes the arguments as an array of Tcl objects. Tcl_CreateAliasObj is more efficient than Tcl_CreateAlias because it avoids unnecessary object conversions.

If a command named cmdName already exists in the interpreter interp, then the operation returns TCL_ERROR and leaves an error message in interp->result. Otherwise, it returns TCL_OK.

When an alias is created, its command script is evaluated in the context of the interpreter in which the alias was defined. The arguments provided to the alias are passed as arguments to the script. The command name used when evaluating the script will be the name of the alias, cmdName.

The functions Tcl_ExposeCommand and Tcl_HideCommand are used to control access to commands defined in the global namespace of an interpreter. Initially, all commands are "exposed". You can hide a command using Tcl_HideCommand, and then later make it visible again using Tcl_ExposeCommand. Hiding a command prevents it from being executed by scripts.

Tcl_ExposeCommand moves the command named hiddenCmdName from the set of hidden commands to the set of exposed commands, putting it under the name cmdName. HiddenCmdName must be the name of an existing hidden command, or the operation will return TCL_ERROR and leave an error message as the result of interp. If an exposed command named cmdName already exists, the operation returns TCL_ERROR and leaves an error message as the result of interp. If the operation succeeds, it returns TCL_OK. After executing this command, attempts to use cmdName in any script evaluation mechanism will again succeed.

Tcl_HideCommand moves the command named cmdName from the set of exposed commands to the set of hidden commands, under the name hiddenCmdName. CmdName must be the name of an existing exposed command, or the operation will return TCL_ERROR and leave an error message as the result of interp. Currently both cmdName and hiddenCmdName must not contain namespace qualifiers, or the operation will return TCL_ERROR and leave an error message as the result of interp. The CmdName will be looked up in the global namespace, and not relative to the current namespace, even if the current namespace is not the global one. If a hidden command whose name is hiddenCmdName already exists, the operation also returns TCL_ERROR and an error message is left as the result of interp. If the operation succeeds, it returns TCL_OK. After executing this command, attempts to use cmdName in any script evaluation mechanism will fail.

For a description of the Tcl interface to multiple interpreters, see interp(n).
