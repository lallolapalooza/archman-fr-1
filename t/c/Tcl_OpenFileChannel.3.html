ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour le rapport d'erreurs et pour rechercher un canal enregistré en son sein.
const char *fileName (in)
Le nom d'un fichier local ou réseau.
const char *mode (in)
Spécifie comment le fichier doit être accédé. Peut prendre l'une des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (in)
Indicateurs de permission de style POSIX, tels que 0644. Si un nouveau fichier est créé, ces permissions seront définies sur le fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans options de la commande Tcl exec.
int flags (in)
Spécifie la disposition des descripteurs standard dans le pipeline : combinaison OU de TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, l'entrée standard du premier processus enfant du pipeline est le canal de tuyau, sinon elle est identique à l'entrée standard du processus appelant ; idem pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, alors le tuyau peut rediriger les descripteurs standard pour outrepasser les descripteurs standard pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, de telles redirections provoquent une erreur.
ClientData handle (in)
Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, il s'agit d'un descripteur de fichier, pour Windows, il s'agit d'un HANDLE.
int readOrWrite (in)
Combinaison OU de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Pointe vers une variable entière qui recevra une combinaison OU de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (in)
Le motif à faire correspondre, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl pour l'entrée ou la sortie. Doit avoir été la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker les caractères lus depuis le canal.
int charsToRead (in)
Le nombre de caractères à lire depuis le canal. Si le codage du canal est binary, cela équivaut au nombre d'octets à lire depuis le canal.
int appendFlag (in)
Si non nul, les données lues depuis le canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (out)
Un tampon dans lequel stocker les octets lus depuis le canal.
int bytesToRead (in)
Le nombre d'octets à lire depuis le canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker la ligne lue depuis le canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne dynamique Tcl dans laquelle stocker la ligne lue depuis le canal. Doit avoir été initialisée par l'appelant. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne dynamique.
const char *input (in)
L'entrée à ajouter à un tampon de canal.
int inputLen (in)
Longueur de l'entrée.
int addAtEnd (in)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon de canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera envoyé en sortie vers le canal.
const char *charBuf (in)
Un tampon contenant les caractères à envoyer en sortie vers le canal.
const char *byteBuf (in)
Un tampon contenant les octets à envoyer en sortie vers le canal.
int bytesToWrite (in)
Le nombre d'octets à consommer depuis charBuf ou byteBuf et à envoyer en sortie vers le canal.
Tcl_WideInt offset (in)
Distance à laquelle déplacer le point d'accès dans le canal auquel la prochaine opération d'entrée ou de sortie sera appliquée, mesurée en octets depuis la position donnée par seekMode. Peut être positif ou négatif.
int seekMode (in)
Par rapport à quel point chercher ; utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs légales sont SEEK_SET, SEEK_CUR, et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) à laquelle tronquer le canal.
const char *optionName (in)
Le nom d'une option applicable à ce canal, telle que -blocking. Peut avoir l'une des valeurs acceptées par la commande fconfigure.
Tcl_DString *optionValue (in)
Où stocker la valeur d'une option ou une liste de toutes les options et leurs valeurs. Doit avoir été initialisé par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des périphériques et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie mises en tampon sur une variété de types de fichiers, de sockets et de périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant une interface de pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans la page man de Tcl_CreateChannel. Le mécanisme de canaux fournit un schéma de mise en tampon inspiré des E/S standard d'Unix, et il permet également des E/S non bloquantes sur les canaux.

Les procédures décrites dans cette page man comprennent les API C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canaux et comment implémenter des pilotes de canaux pour de nouveaux types de canaux, voir la page man de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Ouvre un canal de type fichier nommé fileName. Le mode d'ouverture est spécifié par mode et correspond aux modes de la commande Tcl open (par exemple, "r" pour lecture, "w" pour écriture, "r+" pour lecture et écriture, "a" pour ajout). Les permissions sont des drapeaux POSIX (par exemple, 0644) qui seront utilisés si le fichier est créé. La valeur de retour est un descripteur de canal ou NULL si une erreur se produit.

TCL_OPENCOMMANDCHANNEL

Crée un pipeline de processus. La commande à exécuter est spécifiée par argv et sa taille par argc. Les flags spécifient la manière dont les descripteurs standard des processus du pipeline sont gérés. Voir la description des arguments pour une explication détaillée des flags.

TCL_MAKEFILECHANNEL

Crée un canal Tcl à partir d'un descripteur de fichier existant (par exemple, un descripteur de fichier Unix ou un HANDLE Windows). L'argument handle est le descripteur du système d'exploitation, et readOrWrite indique si le canal est lisible et/ou écrivable.

TCL_GETCHANNEL

Retourne un canal Tcl existant enregistré dans l'interpréteur interp sous le nom channelName. Si modePtr n'est pas NULL, il pointe vers un entier qui recevra le mode du canal (lisible/écrivable).

TCL_GETCHANNELNAMES

Retourne une liste de tous les noms de canaux actuellement enregistrés dans l'interpréteur interp sous forme d'une valeur Tcl objet. Les noms des canaux sont stockés dans l'objet résultat de l'interpréteur.

TCL_GETCHANNELNAMESEX

Similaire à Tcl_GetChannelNames, mais ne renvoie que les noms de canaux correspondant au motif spécifié par pattern. Si pattern est NULL, tous les noms de canaux sont renvoyés.

TCL_REGISTERCHANNEL

Enregistre un canal channel dans l'interpréteur interp. Ceci rend le canal disponible pour être référencé par son nom dans les commandes Tcl.

TCL_UNREGISTERCHANNEL

Désenregistre un canal channel de l'interpréteur interp. Si le canal est toujours ouvert, il sera fermé automatiquement.

TCL_DETACHCHANNEL

Détache un canal de l'interpréteur interp. Le canal n'est plus géré par Tcl, mais il reste ouvert. Ceci est généralement utilisé pour transférer la propriété d'un canal à un autre processus ou une autre partie du programme.

TCL_ISSTANDARDCHANNEL

Retourne vrai si le canal channel est l'un des canaux standard (entrée, sortie ou erreur standard).

TCL_CLOSE

Ferme le canal channel. Toute sortie en attente est vidée avant la fermeture. Si une erreur se produit pendant le vidage ou la fermeture, un code d'erreur est retourné et un message d'erreur est placé dans l'objet résultat de l'interpréteur interp.

TCL_READCHARS

Lit jusqu'à charsToRead caractères depuis le canal channel et les stocke dans l'objet Tcl pointé par readObjPtr. Si appendFlag est vrai, les caractères lus sont ajoutés à la valeur existante de l'objet ; sinon, ils remplacent le contenu existant. Retourne le nombre de caractères lus, ou -1 en cas d'erreur.

TCL_READ

Lit jusqu'à bytesToRead octets depuis le canal channel et les stocke dans le tampon readBuf. Retourne le nombre d'octets lus, ou -1 en cas d'erreur.

TCL_GETSOBJ

Lit une ligne entière depuis le canal channel (jusqu'au prochain caractère de nouvelle ligne) et la stocke dans l'objet Tcl pointé par lineObjPtr. Le caractère de nouvelle ligne est consommé mais non inclus dans l'objet résultat. Si la fin de fichier est atteinte avant de lire une nouvelle ligne, la ligne partielle lue est retournée. Retourne le nombre d'octets lus, ou -1 en cas d'erreur ou de fin de fichier.

TCL_GETS

Similaire à Tcl_GetsObj, mais stocke la ligne lue dans une chaîne dynamique Tcl lineRead. La chaîne dynamique doit avoir été initialisée par l'appelant. Retourne le nombre d'octets lus, ou -1 en cas d'erreur ou de fin de fichier.

TCL_UNGETS

Remet l'entrée input de longueur inputLen dans le tampon d'entrée du canal channel. Si addAtEnd est vrai, l'entrée est ajoutée à la fin du tampon ; sinon, elle est ajoutée au début. Ceci est utile pour implémenter des analyseurs syntaxiques qui doivent revenir en arrière.

TCL_WRITEOBJ

Écrit le contenu de l'objet Tcl pointé par writeObjPtr dans le canal channel. Retourne le nombre d'octets écrits, ou -1 en cas d'erreur.

TCL_WRITECHARS

Écrit les caractères du tampon charBuf dans le canal channel. bytesToWrite spécifie le nombre de caractères à écrire. Retourne le nombre d'octets réellement écrits, ou -1 en cas d'erreur.

TCL_WRITE

Écrit les octets du tampon byteBuf dans le canal channel. bytesToWrite spécifie le nombre d'octets à écrire. Retourne le nombre d'octets réellement écrits, ou -1 en cas d'erreur.

TCL_READRAW

Lit jusqu'à bytesToRead octets depuis le canal channel et les stocke dans le tampon readBuf. Contrairement à Tcl_Read, cette fonction ignore le codage du canal et lit toujours des octets bruts.

TCL_WRITERAW

Écrit les octets du tampon byteBuf dans le canal channel. bytesToWrite spécifie le nombre d'octets à écrire. Contrairement à Tcl_Write, cette fonction ignore le codage du canal et écrit toujours des octets bruts.

TCL_EOF

Retourne vrai si la fin du fichier a été atteinte pour le canal channel lors de la dernière opération de lecture.

TCL_FLUSH

Force l'écriture de toutes les données mises en tampon dans le canal channel vers le périphérique sous-jacent. Retourne 0 en cas de succès, ou -1 en cas d'erreur.

TCL_INPUTBLOCKED

Retourne vrai si le canal channel est configuré pour être en mode non bloquant et qu'il n'y a actuellement aucune donnée disponible pour la lecture.

TCL_INPUTBUFFERED

Retourne le nombre d'octets actuellement en attente dans le tampon d'entrée du canal channel.

TCL_OUTPUTBUFFERED

Retourne le nombre d'octets actuellement en attente dans le tampon de sortie du canal channel.

TCL_SEEK

Définit le point d'accès du canal channel à la position donnée par offset par rapport au point de référence spécifié par seekMode. seekMode peut être SEEK_SET (début du fichier), SEEK_CUR (position actuelle) ou SEEK_END (fin du fichier). Retourne la nouvelle position du point d'accès en octets, ou -1 en cas d'erreur.

TCL_TELL

Retourne la position actuelle du point d'accès du canal channel en octets. Retourne -1 en cas d'erreur.

TCL_TRUNCATECHANNEL

Tronque le canal channel à la longueur spécifiée par length. La longueur doit être non négative. Ceci est similaire à la commande Tcl truncate.

TCL_GETCHANNELOPTION

Récupère la valeur de l'option spécifiée par optionName pour le canal channel et la stocke dans la chaîne dynamique pointée par optionValue. L'ensemble des options disponibles est le même que celui accepté par la commande Tcl fconfigure.

TCL_SETCHANNELOPTION

Définit la valeur de l'option spécifiée par optionName pour le canal channel à la valeur newValue. L'ensemble des options disponibles est le même que celui accepté par la commande Tcl fconfigure.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et retourne une poignée de canal qui peut être utilisée pour effectuer des entrées et sorties sur le fichier. Cette API est calquée sur la procédure fopen de la bibliothèque d'entrées/sorties standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur survient lors de l'ouverture du canal, Tcl_OpenFileChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur les valeurs Tcl_FSOpenFileChannel doit être préférée à Tcl_OpenFileChannel dans la mesure du possible.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Elle crée une séquence de sous-processus spécifiés par les arguments argv et argc et retourne un canal qui peut être utilisé pour communiquer avec ces sous-processus. L'argument flags indique quel type de communication existera avec le pipeline de commandes.

Si le drapeau TCL_STDIN est activé, l'entrée standard du premier sous-processus sera liée au canal : écrire dans le canal fournira des données au sous-processus. Si TCL_STDIN n'est pas activé, l'entrée standard du premier sous-processus sera la même que l'entrée standard de cette application. Si TCL_STDOUT est activé, la sortie standard du dernier sous-processus pourra être lue depuis le canal ; sinon, elle sera dirigée vers la sortie standard de cette application. Si TCL_STDERR est activé, la sortie d'erreur standard de tous les sous-processus sera retournée au canal et entraînera une erreur lors de la fermeture du canal ; sinon, elle sera dirigée vers la sortie d'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas activé, alors argc et argv peuvent rediriger les descripteurs stdio pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est activé, alors c'est une erreur pour argc et argv de remplacer les canaux stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur survient lors de l'ouverture du canal, Tcl_OpenCommandChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'une poignée de fichier existante et spécifique à la plateforme. Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel retourne un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur Tcl dans interp. Si un canal de ce nom n'est pas enregistré dans cet interpréteur, la procédure retourne NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms selon le pattern. Si pattern est NULL, aucun filtrage ne sera effectué. La valeur de retour est TCL_OK si aucune erreur n'est survenue lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur pourront faire référence au canal dans les opérations d'entrée ou de sortie en utilisant le nom donné dans l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur Tcl peut appeler Tcl_RegisterChannel avec interp à NULL, pour indiquer qu'il souhaite conserver une référence à ce canal. Par la suite, le canal pourra être enregistré dans un interpréteur Tcl et ne sera fermé que lorsque le nombre correspondant d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code exécuté en dehors de tout interpréteur de conserver en toute sécurité une référence à un canal également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code gérant les canaux standard. Si aucun canal standard n'a été initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un traité général sur les canaux standard et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Si cette opération a supprimé le dernier enregistrement du canal dans un interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur Tcl peut appeler Tcl_UnregisterChannel avec interp à NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera alors fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel sauf qu'il fermera également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Au-delà de cela, cette commande n'a aucun autre effet. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin) et retournera TCL_ERROR si elle reçoit l'un de ces canaux.

Le code non associé à un interpréteur Tcl peut appeler Tcl_DetachChannel avec interp à NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. Si c'est le cas, il retourne 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un quelconque interpréteur lors de l'appel à Tcl_Close. Les sorties mises en tampon sont vidées sur le périphérique de sortie du canal avant la destruction du canal, et toute entrée mise en tampon est rejetée. S'il s'agit d'un canal bloquant, l'appel ne retourne pas tant que toutes les données mises en tampon n'ont pas été envoyées avec succès au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a des sorties mises en tampon qui ne peuvent pas être écrites sans bloquer, l'appel retourne immédiatement ; la sortie est vidée en arrière-plan et le canal sera fermé une fois que toutes les données mises en tampon auront été envoyées. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close retourne TCL_OK. Si une erreur survient, Tcl_Close retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur survient lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré à l'aide de Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour les détails. Si le canal a déjà été passé comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez plutôt utiliser Tcl_UnregisterChannel, qui appellera en interne Tcl_Close lorsque tous les appels à Tcl_RegisterChannel auront été remplacés par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, convertissant les octets en UTF-8 en se basant sur le codage du canal et stockant les données produites dans la représentation chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur survient lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Définir char

TCL_READCHARS, TCL_READOBJ, ET TCL_READ

La définition de -1 pour toRead fait que la commande lit tous les caractères actuellement disponibles (mode non bloquant) ou tout jusqu'à l'eof (mode bloquant).

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé étaient disponibles. C'est ce qu'on appelle une lecture courte. En mode bloquant, cela ne peut se produire qu'à une fin de fichier. En mode non bloquant, une lecture courte peut aussi se produire s'il n'y a pas assez d'entrée disponible actuellement : Tcl_ReadChars renvoie un compte court plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour savoir laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les diverses représentations de fin de ligne en la représentation interne canonique \n conformément au mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les divers modes spécifiques à la plateforme sont décrits dans l'entrée du manuel pour la commande fconfigure de Tcl.

En guise d'optimisation des performances, lors de la lecture à partir d'un canal avec l'encodage binary, les octets ne sont pas convertis en UTF-8 lors de leur lecture. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr en tant que valeur de tableau d'octets. La représentation sous forme de chaîne de cette valeur ne sera construite que si elle est nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette façon, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans avoir à supporter le coût de la conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'il ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Il consomme des octets du channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par un zéro. Son contenu est valide à partir de la position zéro jusqu'à, mais sans inclure, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas pour l'empilement. Alors que Tcl_Read (et les autres fonctions de l'API) obtiennent toujours leurs données du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_ReadRaw ne le fait pas. Ainsi, cette fonction ne peut être utilisée que pour les pilotes de canal transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données du canal inférieur dans la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, en convertissant les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée ait été vue. Si l'encodage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception du ou des caractères de fin de ligne terminaux, sont ajoutés à la représentation de chaîne de lineObjPtr. Le ou les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_GetsObj renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj renvoie également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est renvoyé, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité des entrées.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique donnée par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, soit à la tête, soit à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur des données à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si le channel a un EOF « collant » défini, aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets renvoie inputLen ou -1 si une erreur se produit.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données de caractères à charBuf. Les caractères UTF-8 dans le tampon sont convertis vers l'encodage du canal et mis en file d'attente pour la sortie vers le channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par un zéro et il écrit tout jusqu'au zéro.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal à none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un compte du nombre d'octets acceptés pour la sortie vers le canal. C'est soit supérieur à zéro pour indiquer le succès, soit -1 pour indiquer qu'une erreur s'est produite. Si une erreur se produit, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme selon l'option -translation pour le canal. Cela est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'il accepte une valeur Tcl dont le contenu sera sorti vers le canal. Les caractères UTF-8 dans la représentation de chaîne de writeObjPtr sont convertis vers l'encodage du canal et mis en file d'attente pour la sortie vers le channel. En guise d'optimisation des performances, lors de l'écriture sur un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets dans la représentation interne de writeObjPtr sous forme de valeur de tableau d'octets sont écrits dans le canal. La représentation en tableau d'octets de la valeur sera construite si nécessaire. De cette façon, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans avoir à supporter le coût de la conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'il ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers le channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par un zéro et il écrit tout jusqu'au zéro.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas pour l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée vers le canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction ne peut être utilisée que pour les pilotes de canal transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation dans le canal situé en dessous.

TCL_FLUSH

Tcl_Flush provoque l'écriture de toutes les données de sortie tamponnées pour le channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données tamponnées n'ont pas été envoyées au canal ou qu'une erreur ne s'est pas produite. L'appel retourne immédiatement si le canal est non bloquant ; il démarre une opération de vidage en arrière-plan qui écrira les données tamponnées vers le canal éventuellement, aussi vite que le canal peut les absorber.

La valeur de retour est normalement TCL_OK. Si une erreur se produit, Tcl_Flush renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans le channel où les données ultérieures seront lues ou écrites. La sortie tamponnée est vidée vers le canal et l'entrée tamponnée est rejetée, avant l'opération de recherche.

Tcl_Seek renvoie normalement le nouveau point d'accès. Si une erreur se produit, Tcl_Seek renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut ou non avoir été déplacé.

TCL_TELL

Tcl_Tell renvoie le point d'accès actuel d'un canal. La valeur renvoyée est -1 si le canal ne prend pas en charge la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent du channel à une longueur donnée de length octets. Il renvoie TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, c'est le nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue,

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère la valeur de l’option optionName pour le canal channel. La valeur est placée dans le résultat de l’interpréteur interp. La procédure renvoie normalement TCL_OK. En cas d’erreur, elle renvoie TCL_ERROR et laisse un message d’erreur dans le résultat de l’interpréteur. Les options disponibles et leurs valeurs possibles sont décrites dans la page de manuel de la commande Tcl fconfigure. D'autres options peuvent être ajoutées par chaque type de canal. Ces options spécifiques au type de canal sont décrites dans la page de manuel de la commande Tcl qui crée un canal de ce type ; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans la page de manuel de la commande Tcl socket. La procédure utilise une série d'appels à Tcl_DStringAppendElement.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit une nouvelle valeur newValue pour une option optionName sur le canal channel. La procédure renvoie normalement TCL_OK. En cas d’erreur, elle renvoie TCL_ERROR ; de plus, si interp n’est pas NULL, Tcl_SetChannelOption laisse un message d’erreur dans le résultat de l’interpréteur.

TCL_EOF

Tcl_Eof renvoie une valeur non nulle si le canal channel a rencontré une fin de fichier lors de la dernière opération d’entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked renvoie une valeur non nulle si le canal channel est en mode non bloquant et que la dernière opération d’entrée a renvoyé moins de données que demandé parce qu’il n’y avait pas assez de données disponibles. L’appel renvoie toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered renvoie le nombre d’octets d’entrée actuellement mis en mémoire tampon dans les tampons internes d’un canal. Si le canal n’est pas ouvert en lecture, cette fonction renvoie toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered renvoie le nombre d’octets de sortie actuellement mis en mémoire tampon dans les tampons internes d’un canal. Si le canal n’est pas ouvert en écriture, cette fonction renvoie toujours zéro.

PROBLÈMES DE PLATEFORME

Les descripteurs renvoyés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que renvoyé par l’appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel ou Tcl_MakeFileChannel. D’autres types de canaux peuvent renvoyer un type de descripteur différent sur les plateformes Windows.
