ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour le rapport d'erreurs et pour rechercher un canal enregistré dans celui-ci.
const char *fileName (in)
Nom d'un fichier local ou réseau.
const char *mode (in)
C'est le mode dans lequel le fichier est accédé. Il peut avoir n'importe quelle valeur autorisée pour l'argument mode des commandes open de Tcl.
int permissions (in)
Flags de permissions POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront définies sur le fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour construire un pipeline de commandes. Ces valeurs ont la même signification que les arguments non-switch des commandes exec.
int flags (in)
C'est la disposition des descripteurs standard dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, le stdin du premier enfant dans le pipeline est le canal de pipeline, sinon il est le même que le stdin du processus appelant ; il en va de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, le pipeline peut rediriger les descripteurs standard pour remplacer les descripteurs standard pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, ces redirections entraînent une erreur.
ClientData handle (in)
Le handle du système d'exploitation pour les E/S vers un fichier. Pour Unix, c'est un descripteur de fichier ; pour Windows, c'est un HANDLE.
int readOrWrite (in)
La combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Le pointeur vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (in)
Le motif à rechercher, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl pour l'entrée ou la sortie. Il doit avoir été retourné par une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle les caractères lus du canal sont stockés.
int charsToRead (in)
Le nombre de caractères à lire du canal. Si l'encodage du canal est binary, ceci est équivalent au nombre d'octets à lire du canal.
int appendFlag (in)
Si différent de zéro, les données lues du canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (out)
Un tampon dans lequel les octets lus du canal seront stockés.
int bytesToRead (in)
Le nombre d'octets à lire du canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle la ligne lue du canal sera stockée. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne dynamique dans laquelle la ligne lue du canal sera stockée. Elle doit avoir été initialisée par l'appelant. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne dynamique.
const char *input (in)
L'entrée à ajouter à un tampon de canal.
int inputLen (in)
Longueur de l'entrée.
int addAtEnd (in)
Flag indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon de canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera écrit dans le canal.
const char *charBuf (in)
Un tampon contenant les caractères à écrire dans le canal.
const char *byteBuf (in)
Un tampon contenant les octets à écrire dans le canal.
int bytesToWrite (in)
Le nombre d'octets à consommer de charBuf ou byteBuf et à écrire dans le canal.
Tcl_WideInt offset (in)
De combien d'octets le pointeur d'accès sera déplacé pour effectuer la prochaine opération d'entrée ou de sortie ? Il est mesuré à partir de la position donnée par seekMode. Il peut être positif ou négatif.
int seekMode (in)
À quelle position d'accès faut-il chercher ? Utilisé avec offset pour calculer la nouvelle position d'accès du canal. Les valeurs légales sont SEEK_SET, SEEK_CUR et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) pour tronquer le canal.
const char *optionName (in)
Le nom d'une option applicable au canal, par exemple -blocking. Il peut avoir n'importe quelle valeur acceptée par la commande fconfigure.
Tcl_DString *optionValue (in)
Où la valeur d'une option ou une liste de toutes les options et leurs valeurs est stockée. Elle doit avoir été initialisée par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canal Tcl fournit un mécanisme indépendant du périphérique et de la plateforme pour effectuer des opérations d'entrée et de sortie bufferisées sur divers types de fichiers, sockets et périphériques. Le mécanisme de canal est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans le manuel de Tcl_CreateChannel. Le mécanisme de canal fournit un schéma de bufferisation similaire aux E/S standard d'Unix et permet également des opérations d'E/S non bloquantes sur les canaux.

Les procédures décrites dans ce manuel sont les API C du niveau générique de l'architecture de canal. Pour une description de l'architecture du pilote de canal et comment implémenter des pilotes de canal pour de nouveaux types de canaux, voir le manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

La procédure Tcl_OpenFileChannel ouvre un fichier et renvoie un descripteur de canal Tcl pour ce fichier. Le descripteur de canal est utilisé dans toutes les autres opérations sur le canal.

fileName est le nom du fichier à ouvrir. mode est une chaîne de caractères qui spécifie comment le fichier doit être ouvert (par exemple, "r" pour lire, "w" pour écrire, "a" pour ajouter, etc.). permissions spécifie les permissions du fichier si un nouveau fichier est créé. Si une erreur se produit, un message d'erreur est stocké dans interp->result et NULL est retourné. Sinon, la nouvelle valeur de canal est retournée.

TCL_OPENCOMMANDCHANNEL

La procédure Tcl_OpenCommandChannel crée un pipeline de commandes et renvoie un descripteur de canal Tcl pour le pipeline. La commande argv[0] est exécutée, et ses arguments sont argv[1]...argv[argc-1]. Les flux d'E/S standard de la commande sont reliés au pipeline. Les flags contrôlent la façon dont les flux d'E/S standard de la commande sont connectés. Si une erreur se produit, un message d'erreur est stocké dans interp->result et NULL est retourné. Sinon, la nouvelle valeur de canal est retournée.

TCL_MAKEFILECHANNEL

La procédure Tcl_MakeFileChannel prend une handle de fichier existante (par exemple, un descripteur de fichier Unix ou un HANDLE Windows) et la transforme en un canal Tcl. readOrWrite est une combinaison OR des indicateurs TCL_READABLE et TCL_WRITABLE pour indiquer si le canal doit être ouvert en lecture ou en écriture.

TCL_GETCHANNEL

La procédure Tcl_GetChannel renvoie un descripteur de canal Tcl pour le canal nommé channelName. Si modePtr n'est pas NULL, il est défini sur une combinaison OR des indicateurs TCL_READABLE et TCL_WRITABLE pour indiquer si le canal est ouvert en lecture et en écriture.

TCL_GETCHANNELNAMES

La procédure Tcl_GetChannelNames renvoie un nombre entier égal au nombre de canaux enregistrés dans interp. De plus, le nom de chaque canal est ajouté à la liste des résultats de l'interpréteur sous forme d'une liste Tcl.

La procédure Tcl_GetChannelNamesEx est identique à Tcl_GetChannelNames, sauf qu'elle ne renvoie que les noms de canaux qui correspondent au motif pattern.

TCL_REGISTERCHANNEL

La procédure Tcl_RegisterChannel enregistre un canal Tcl avec l'interpréteur interp. Une fois enregistré, le canal peut être référencé par son nom dans les commandes Tcl.

TCL_UNREGISTERCHANNEL

La procédure Tcl_UnregisterChannel désenregistre un canal Tcl de l'interpréteur interp. Le canal doit être fermé avant d'être désenregistré.

TCL_DETACHCHANNEL

La procédure Tcl_DetachChannel détache un canal de l'interpréteur interp. Le canal est toujours valide, mais il ne peut plus être référencé par son nom dans les commandes Tcl. Le canal doit être fermé explicitement plus tard.

TCL_ISTANDARDCHANNEL

La procédure Tcl_IsStandardChannel renvoie vrai si le canal channel est l'un des canaux standard stdin, stdout, ou stderr.

TCL_CLOSE

La procédure Tcl_Close ferme un canal Tcl. Tous les tampons sont vidés et les ressources associées au canal sont libérées.

TCL_READCHARS

La procédure Tcl_ReadChars lit jusqu'à charsToRead caractères du canal channel et les stocke dans l'objet Tcl référencé par readObjPtr. Si appendFlag est différent de zéro, les caractères lus sont ajoutés à la fin de l'objet existant. Sinon, ils remplacent le contenu de l'objet. La procédure renvoie le nombre de caractères réellement lus. S'il y a une erreur, un message d'erreur est stocké dans interp->result et -1 est retourné.

TCL_READ

La procédure Tcl_Read lit jusqu'à bytesToRead octets du canal channel et les stocke dans le tampon readBuf. La procédure renvoie le nombre d'octets réellement lus. S'il y a une erreur, un message d'erreur est stocké dans interp->result et -1 est retourné.

TCL_GETSOBJ

La procédure Tcl_GetsObj lit une ligne entière du canal channel (jusqu'à un caractère de nouvelle ligne inclus) et stocke la ligne résultante dans l'objet Tcl référencé par lineObjPtr. La ligne lue est ajoutée au contenu existant de l'objet. La procédure renvoie le nombre d'octets réellement lus. S'il y a une erreur, un message d'erreur est stocké dans interp->result et -1 est retourné. Si la fin du fichier est atteinte avant qu'un caractère de nouvelle ligne ne soit lu, la ligne sera retournée sans le caractère de nouvelle ligne.

TCL_GETS

La procédure Tcl_Gets est similaire à Tcl_GetsObj, mais elle stocke la ligne lue dans une chaîne dynamique lineRead. La chaîne dynamique doit avoir été initialisée par l'appelant.

TCL_UNGETS

La procédure Tcl_Ungets place les données input de longueur inputLen dans le tampon d'entrée du canal channel. Si addAtEnd est vrai, les données sont ajoutées à la fin du tampon d'entrée ; sinon, elles sont ajoutées au début. Ceci est utile pour implémenter des analyseurs qui doivent pouvoir "revenir en arrière" sur une partie de l'entrée.

TCL_WRITEOBJ

La procédure Tcl_WriteObj écrit le contenu de l'objet Tcl référencé par writeObjPtr dans le canal channel. La procédure renvoie le nombre d'octets réellement écrits. S'il y a une erreur, un message d'erreur est stocké dans interp->result et -1 est retourné.

TCL_WRITECHARS

La procédure Tcl_WriteChars écrit les caractères dans charBuf dans le canal channel. bytesToWrite spécifie le nombre de caractères à écrire. La procédure renvoie le nombre d'octets réellement écrits. S'il y a une erreur, un message d'erreur est stocké dans interp->result et -1 est retourné.

TCL_WRITE

La procédure Tcl_Write est similaire à Tcl_WriteChars, mais elle écrit les octets dans byteBuf dans le canal channel. bytesToWrite spécifie le nombre d'octets à écrire.

TCL_READRAW

La procédure Tcl_ReadRaw est identique à Tcl_Read, sauf qu'elle lit les octets directement du canal sans effectuer de conversion d'encodage.

TCL_WRITERAW

La procédure Tcl_WriteRaw est identique à Tcl_Write, sauf qu'elle écrit les octets directement dans le canal sans effectuer de conversion d'encodage.

TCL_EOF

La procédure Tcl_Eof renvoie vrai si la fin du fichier a été atteinte pour le canal channel.

TCL_FLUSH

La procédure Tcl_Flush force la vidange de tous les tampons de sortie pour le canal channel. Elle renvoie 0 en cas de succès, ou -1 en cas d'erreur.

TCL_INPUTBLOCKED

La procédure Tcl_InputBlocked renvoie vrai si une opération de lecture sur le canal channel bloquerait l'exécution.

TCL_INPUTBUFFERED

La procédure Tcl_InputBuffered renvoie le nombre d'octets disponibles dans le tampon d'entrée du canal channel.

TCL_OUTPUTBUFFERED

La procédure Tcl_OutputBuffered renvoie le nombre d'octets en attente dans le tampon de sortie du canal channel.

TCL_SEEK

La procédure Tcl_Seek ajuste la position actuelle du canal channel en déplaçant le pointeur d'accès de offset octets à partir de la position donnée par seekMode. seekMode peut être SEEK_SET (début du fichier), SEEK_CUR (position actuelle) ou SEEK_END (fin du fichier). La procédure renvoie la nouvelle position absolue dans le fichier, ou -1 en cas d'erreur.

TCL_TELL

La procédure Tcl_Tell renvoie la position actuelle du pointeur d'accès dans le canal channel.

TCL_TRUNCATECHANNEL

La procédure Tcl_TruncateChannel tronque le canal channel à la longueur spécifiée par length. Le canal doit avoir été ouvert en écriture.

TCL_GETCHANNELOPTION

La procédure Tcl_GetChannelOption renvoie la valeur de l'option spécifiée par optionName pour le canal channel. La valeur est stockée dans la chaîne dynamique optionValue. La procédure renvoie 0 en cas de succès, ou -1 en cas d'erreur.

TCL_SETCHANNELOPTION

La procédure Tcl_SetChannelOption définit la valeur de l'option spécifiée par optionName pour le canal channel à newValue. La procédure renvoie 0 en cas de succès, ou -1 en cas d'erreur.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et retourne un descripteur de canal qui peut être utilisé pour effectuer des opérations d'entrée et de sortie sur le fichier. Cette API est modélisée d'après la procédure fopen de la bibliothèque d'E/S standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur survient lors de l'ouverture du canal, Tcl_OpenFileChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur les valeurs Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel chaque fois que possible.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Elle crée une séquence de sous-processus spécifiés par les arguments argv et argc et retourne un canal qui peut être utilisé pour communiquer avec ces sous-processus. L'argument flags indique quel type de communication existera avec le pipeline de commandes.

Si l'indicateur TCL_STDIN est défini, l'entrée standard du premier sous-processus sera liée au canal : écrire dans le canal fournira l'entrée au sous-processus. Si TCL_STDIN n'est pas défini, alors l'entrée standard du premier sous-processus sera la même que l'entrée standard de cette application. Si TCL_STDOUT est défini, la sortie standard du dernier sous-processus peut être lue depuis le canal ; sinon, elle va à la sortie standard de cette application. Si TCL_STDERR est défini, la sortie d'erreur standard de tous les sous-processus est retournée au canal et entraîne une erreur lors de la fermeture du canal ; sinon, elle va à l'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas défini, alors argc et argv peuvent rediriger les descripteurs stdio pour outrepasser TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, alors il est une erreur pour argc et argv de rediriger les canaux stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur survient lors de l'ouverture du canal, Tcl_OpenCommandChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un descripteur de fichier existant et spécifique à la plateforme. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel retourne un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur Tcl dans interp. Si un canal portant ce nom n'est pas enregistré dans cet interpréteur, la procédure retourne NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms en fonction du pattern. Si pattern est NULL, alors il n'effectuera aucun filtrage. La valeur de retour est TCL_OK si aucune erreur ne s'est produite lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur peuvent se référer au canal dans les opérations d'entrée ou de sortie en utilisant le nom donné dans l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code s'exécutant en dehors de tout interpréteur Tcl peut appeler Tcl_RegisterChannel avec interp comme NULL, pour indiquer qu'il souhaite détenir une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et ne sera fermé que lorsque le nombre correspondant d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code s'exécutant en dehors de tout interpréteur de détenir en toute sécurité une référence à un canal qui est également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code qui gère les canaux standard. Si aucun canal standard n'a été initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un exposé général sur les canaux standard et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel supprime un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour se référer au canal dans cet interpréteur. Si cette opération a supprimé le dernier enregistrement du canal dans un interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur Tcl peut appeler Tcl_UnregisterChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera alors fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel sauf qu'elle fermera également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel supprime un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour se référer au canal dans cet interpréteur. Au-delà de cela, cette commande n'a pas d'autre effet. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin), et retournera TCL_ERROR si elle est appelée avec l'un de ces canaux.

Le code non associé à un interpréteur Tcl peut appeler Tcl_DetachChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. Si c'est le cas, il retourne 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou autrement valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lorsque Tcl_Close est appelé. La sortie mise en mémoire tampon est vidée sur le périphérique de sortie du canal avant la destruction du canal, et toute entrée mise en mémoire tampon est discardée. S'il s'agit d'un canal bloquant, l'appel ne retourne pas tant que toutes les données tamponnées n'ont pas été envoyées avec succès sur le périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a une sortie tamponnée qui ne peut pas être écrite sans bloquer, l'appel retourne immédiatement ; la sortie est vidée en arrière-plan et le canal sera fermé une fois que toutes les données tamponnées auront été sorties. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close retourne TCL_OK. Si une erreur survient, Tcl_Close retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur survient lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré en utilisant Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a déjà été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez plutôt utiliser Tcl_UnregisterChannel, qui appellera Tcl_Close en interne lorsque tous les appels à Tcl_RegisterChannel auront été remplacés par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, convertit les octets en UTF-8 en fonction du codage du canal et stocke les données produites dans la représentation chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur survient lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Définir charsToRead

to -1 provoquera la lecture de toutes les caractères actuellement disponibles (non bloquant) ou de tout jusqu'à l'eof (mode bloquant) par la commande.

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé étaient disponibles. Ceci est appelé une lecture courte. En mode bloquant, cela ne peut arriver qu'à une fin de fichier. En mode non bloquant, une lecture courte peut également se produire s'il n'y a pas assez d'entrée actuellement disponible : Tcl_ReadChars retourne un compte court plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour savoir laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les diverses représentations de fin de ligne en la représentation interne canonique de \n selon le mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les divers modes spécifiques à la plateforme sont décrits dans l'entrée du manuel de la commande Tcl fconfigure.

Par optimisation de performance, lors de la lecture à partir d'un canal avec l'encodage binary, les octets ne sont pas convertis en UTF-8 lorsqu'ils sont lus. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr sous forme de tableau d'octets. La représentation textuelle de cette valeur ne sera construite que si elle est nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette façon, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans la dépense de conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'il ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour la compatibilité descendante avec les extensions Tcl non internationalisées. Il consomme des octets de channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par null. Son contenu est valide à partir de la position zéro jusqu'à, et sans inclure, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas pour l'empilement. Alors que Tcl_Read (et les autres fonctions de l'API) obtiennent toujours leurs données du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_ReadRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données du canal inférieur vers la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, convertissant les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée ait été vue. Si l'encodage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception du(des) caractère(s) de fin de ligne terminateur(s), sont ajoutés à la représentation textuelle de lineObjPtr. Le(s) caractère(s) de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_GetsObj retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj retourne également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est retourné, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité des entrées.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique fournie par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, à la tête ou à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur des données à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées à la tête de la file. Si channel a un EOF "collant" défini, aucune donnée ne sera ajoutée à la file d'entrée. Tcl_Ungets retourne inputLen ou -1 en cas d'erreur.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données caractères à charBuf. Les caractères UTF-8 dans le tampon sont convertis vers l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par null et il sort tout jusqu'au null.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal à none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un compte du nombre d'octets acceptés pour la sortie vers le canal. C'est soit supérieur à zéro pour indiquer le succès, soit -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme selon l'option -translation pour le canal. Ceci est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'il accepte une valeur Tcl dont le contenu sera sorti vers le canal. Les caractères UTF-8 dans la représentation textuelle de writeObjPtr sont convertis vers l'encodage du canal et mis en file d'attente pour la sortie vers channel. Par optimisation de performance, lors de l'écriture dans un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lorsqu'ils sont écrits. Au lieu de cela, les octets dans la représentation interne de writeObjPtr sous forme de tableau d'octets sont écrits dans le canal. La représentation sous forme de tableau d'octets de la valeur sera construite si nécessaire. De cette façon, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans la dépense de conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'il ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour la compatibilité descendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par null et il sort tout jusqu'au null.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas pour l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leurs entrées dans le canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation vers le canal inférieur.

TCL_FLUSH

Tcl_Flush provoque l'écriture de toutes les données de sortie en mémoire tampon pour channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas avant que toutes les données en mémoire tampon n'aient été envoyées au canal ou qu'une erreur ne se soit produite. L'appel retourne immédiatement si le canal est non bloquant ; il démarre une opération de vidage en arrière-plan qui écrira les données en mémoire tampon dans le canal éventuellement, aussi rapidement que le canal est capable de les absorber.

La valeur de retour est normalement TCL_OK. En cas d'erreur, Tcl_Flush retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données suivantes seront lues ou écrites. La sortie en mémoire tampon est vidée vers le canal et l'entrée en mémoire tampon est discardée, avant l'opération de déplacement.

Tcl_Seek retourne normalement le nouveau point d'accès. En cas d'erreur, Tcl_Seek retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut avoir été déplacé ou non.

TCL_TELL

Tcl_Tell retourne le point d'accès actuel pour un canal. La valeur retournée est -1 si le canal ne supporte pas le déplacement.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent de channel à une longueur donnée de length octets. Il retourne TCL_OK si l'opération a réussi, et TCL_ERROR sinon.
