INTRODUCTION

À partir de la version 8.1, le noyau Tcl est thread-safe, ce qui vous permet d'intégrer Tcl dans des applications multithreadées sans personnaliser le noyau Tcl. À partir de la version 8.6, le support du multithreading Tcl est activé par défaut. Pour désactiver le support du multithreading Tcl, vous devez inclure l'option --disable-threads lors de la configuration et de la compilation de votre noyau Tcl.

Une contrainte importante de l'implémentation des threads Tcl est que seul le thread qui a créé un interpréteur Tcl peut utiliser cet interpréteur. En d'autres termes, plusieurs threads ne peuvent pas accéder au même interpréteur Tcl. (Cependant, un seul thread peut créer et utiliser plusieurs interpréteurs en toute sécurité.)

DESCRIPTION

Tcl fournit Tcl_CreateThread pour la création de threads. L'appelant peut déterminer la taille de la pile allouée au nouveau thread et modifier son comportement via les flags fournis. La valeur TCL_THREAD_STACK_DEFAULT pour stackSize indique que la taille par défaut spécifiée par le système d'exploitation doit être utilisée pour le nouveau thread. Quant aux indicateurs, seuls les valeurs TCL_THREAD_NOFLAGS et TCL_THREAD_JOINABLE sont actuellement définies. La première de ces valeurs appelle le comportement par défaut sans paramètres spéciaux. L'utilisation de la seconde valeur marque le nouveau thread comme joinable. Cela signifie qu'un autre thread peut attendre la sortie de ce thread marqué et le rejoindre.

Restrictions : Sur certains systèmes UNIX, la bibliothèque pthread ne contient pas la fonctionnalité permettant de spécifier la taille de la pile d'un thread. La valeur spécifiée pour la taille de la pile est ignorée sur ces systèmes. Windows ne prend actuellement pas en charge les threads joinables. Cette valeur d'indicateur est donc ignorée sur cette plateforme.

Tcl fournit les fonctions Tcl_ExitThread et Tcl_FinalizeThread pour terminer les threads et appeler des gestionnaires de sortie optionnels par thread. Voir la page Tcl_Exit pour plus d'informations sur ces procédures.

La fonction Tcl_JoinThread est fournie pour permettre aux threads d'attendre la sortie d'un autre thread, qui doit avoir été marqué comme joinable via l'utilisation de l'indicateur TCL_THREAD_JOINABLE lors de sa création via Tcl_CreateThread.

Tenter d'attendre la sortie d'un thread non joinable ou d'un thread sur lequel on attend déjà entraînera une erreur. Attendre un thread joinable qui est déjà sorti est possible, le système conservera les informations nécessaires jusqu'après l'appel à Tcl_JoinThread. Cela signifie que ne pas appeler Tcl_JoinThread pour un thread joinable provoquera une fuite de mémoire.

L'appel Tcl_GetThreadData renvoie un pointeur vers un bloc de données privées au thread. Son argument est une clé partagée par tous les threads et une taille pour le bloc de stockage. Le stockage est automatiquement alloué et initialisé à zéro lors de la première demande par chaque thread. Le stockage est automatiquement désalloué par Tcl_FinalizeThread.

SYNCHRONISATION ET COMMUNICATION

Tcl fournit Tcl_ThreadQueueEvent et Tcl_ThreadAlert pour la gestion de la mise en file d'attente d'événements dans les applications multithreadées. Voir la page man Notifier pour plus d'informations sur ces procédures.

Un mutex est un verrou utilisé pour sérialiser tous les threads à travers un morceau de code en appelant Tcl_MutexLock et Tcl_MutexUnlock. Si un thread détient un mutex, tout autre thread appelant Tcl_MutexLock sera bloqué jusqu'à ce que Tcl_MutexUnlock soit appelé. Un mutex peut être détruit après son utilisation en appelant Tcl_MutexFinalize. Le résultat du verrouillage d'un mutex deux fois depuis le même thread n'est pas défini. Sur certaines plateformes, cela entraînera un interblocage. Les procédures Tcl_MutexLock, Tcl_MutexUnlock et Tcl_MutexFinalize sont définies comme des macros vides si le compilateur n'est pas activé avec les threads. Pour la déclaration des mutex, la macro TCL_DECLARE_MUTEX doit être utilisée. Cette macro assure une gestion correcte des mutex, même lorsque le noyau est compilé sans prise en charge des threads.

Une variable de condition est utilisée comme mécanisme de signalisation : un thread peut verrouiller un mutex, puis attendre sur une variable de condition avec Tcl_ConditionWait. Cela libère atomiquement le verrou mutex et bloque le thread en attente jusqu'à ce qu'un autre thread appelle Tcl_ConditionNotify. L'appelant de Tcl_ConditionNotify devrait détenir le mutex associé en appelant précédemment Tcl_MutexLock, mais ce n'est pas imposé. La notification de la variable de condition débloque tous les threads en attente sur la variable de condition, mais ils ne progressent pas tant que le mutex n'est pas libéré avec Tcl_MutexUnlock. L'implémentation de Tcl_ConditionWait verrouille automatiquement le mutex avant de retourner.

L'appelant de Tcl_ConditionWait doit être préparé aux notifications parasites en appelant Tcl_ConditionWait dans une boucle `while` qui teste un invariant.

Une variable de condition peut être détruite après son utilisation en appelant Tcl_ConditionFinalize.

Les procédures Tcl_ConditionNotify, Tcl_ConditionWait et Tcl_ConditionFinalize sont définies comme des macros vides si le compilateur n'est pas activé avec les threads.

INITIALISATION

Tous ces objets de synchronisation sont auto-initialisants. Ils sont implémentés comme des pointeurs opaques qui devraient être NULL lors de la première utilisation. Les mutex et les variables de condition sont soit nettoyés par les gestionnaires de sortie de processus (s'ils vivent assez longtemps), soit explicitement par des appels à Tcl_MutexFinalize ou Tcl_ConditionFinalize. Le stockage local aux threads est récupéré pendant Tcl_FinalizeThread.

NOM

TCL_THREAD_CREATE_PROC, TCL_THREAD_CREATE_TYPE

SYNOPIS

static TCL_THREAD_CREATE_PROC MonFonctionImplmentationFil;

static TCL_THREAD_CREATE_TYPE MonFonctionImplmentationFil( ClientData donneesClient)

ARGUMENTS

donneesClient

INTRODUCTION

Le package Thread permet d'accéder aux threads depuis le niveau du script.

DESCRIPTION

Pour créer un fil avec du code portable, la fonction d'implémentation doit être déclarée comme ceci :

static TCL_THREAD_CREATE_PROC MonFonctionImplmentationFil;

Puis elle doit être définie comme ceci, qui compte simplement jusqu'à une valeur donnée puis se termine.

static TCL_THREAD_CREATE_TYPE
MonFonctionImplmentationFil(
    ClientData donneesClient)
{
    int i, limite = (int) donneesClient;
    for (i=0 ; i<limite ; i++) {
        /* ne fait rien ici */
    }
    TCL_THREAD_CREATE_RETURN;
}

Pour créer le fil ci-dessus, le faire s'exécuter et attendre sa fin, on ferait ceci :

int limite = 1000000000;
ClientData donneesLimite = (void*)((intptr_t) limite);
Tcl_ThreadId id;    /* stocke l'identifiant du fil créé */
int resultat;
if (Tcl_CreateThread(&id, MonFonctionImplmentationFil, donneesLimite,
        TCL_THREAD_STACK_DEFAULT,
        TCL_THREAD_JOINABLE) != TCL_OK) {
    /* le fil n'a pas été créé correctement */
    return;
}
/* fait quelque chose pendant un moment ici */
if (Tcl_JoinThread(id, &resultat) != TCL_OK) {
    /* le fil ne s'est pas terminé correctement */
    return;
}
/* tout s'est bien nettoyé */
