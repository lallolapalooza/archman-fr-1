Encodage à interroger, libérer ou utiliser pour convertir du texte. Si encoding est NULL, l'encodage du système courant est utilisé.

Le token d'encodage y est écrit.
const char *src (in)
Pour les fonctions Tcl_ExternalToUtf, un tableau d'octets dans l'encodage spécifié qui sont convertis en UTF-8. Pour les fonctions Tcl_UtfToExternal et Tcl_WinUtfToTChar, un tableau de caractères UTF-8 qui sont convertis dans l'encodage spécifié.
const TCHAR *tsrc (in)
Un tableau de caractères TCHAR de Windows qui sont convertis en UTF-8.
int srcLen (in)
Longueur de src ou tsrc en octets. Si la longueur est négative, la longueur spécifique à la chaîne dans l'encodage est utilisée.
Tcl_DString *dstPtr (out)
Un DString non initialisé ou libéré dans lequel le résultat converti est stocké.
int flags (in)
Bits de drapeaux ORés. TCL_ENCODING_START indique que le tampon d'entrée est le premier bloc d'un flux d'entrée (potentiellement multi-blocs), indiquant à la routine de conversion de réinitialiser à un état initial et d'effectuer toute initialisation nécessaire avant de convertir le premier octet. TCL_ENCODING_END indique que le tampon d'entrée est le dernier bloc d'un flux d'entrée (potentiellement multi-blocs), indiquant à la routine de conversion d'effectuer toute finalisation nécessaire après la conversion du dernier octet, puis de réinitialiser à un état initial. TCL_ENCODING_STOPONERROR indique que la routine de conversion doit retourner immédiatement si un caractère qui n'existe pas dans l'encodage cible est lu; sinon, un caractère par défaut est automatiquement substitué.
Tcl_EncodingState *statePtr (in/out)
Utilisé lors de la conversion d'un flux d'octets (généralement long ou de longueur indéterminée) par blocs. La routine de conversion stocke son état actuel dans statePtr après avoir converti le bloc actuel (src, le tampon contenant le bloc actuel). Ces informations d'état doivent être renvoyées lors de la conversion du bloc suivant du flux afin que la routine de conversion sache dans quel état elle se trouvait en laissant le dernier bloc. Peut être NULL, auquel cas la valeur spécifiée pour flags est ignorée et on suppose que le tampon src contient le texte complet à convertir.

La longueur maximale du tampon de sortie dst en octets.

Rempli avec le nombre d'octets de src qui ont été effectivement convertis. Cela peut être inférieur à la longueur d'origine de src s'il y a eu un problème lors de la conversion de certains caractères de src. Peut être NULL.
int *dstWrotePtr (out)
Rempli avec le nombre d'octets qui ont été stockés dans le tampon de sortie en conséquence de la conversion. Peut être NULL.
int *dstCharsPtr (out)
Rempli avec le nombre de caractères correspondant au nombre d'octets stockés dans le tampon de sortie. Peut être NULL.

INTRODUCTION

Ces routines convertissent entre la représentation interne de caractères de Tcl, UTF-8, et les représentations de caractères utilisées par divers systèmes d'exploitation ou systèmes de fichiers, tels que Unicode, ASCII ou EUC-JP. Lorsque vous travaillez avec des chaînes, comme l'obtention d'un nom de fichier ou l'affichage de caractères à l'aide de polices internationales, les chaînes doivent être converties dans un ou plusieurs formats que les différents appels système peuvent utiliser. Par exemple, dans un environnement Unix japonais, un utilisateur pourrait obtenir un nom de fichier représenté dans l'encodage EUC-JP, puis convertir les caractères dans l'encodage jisx0208 pour afficher le nom du fichier dans une fenêtre Tk. Le but de l'encodage est de combler le fossé de traduction. UTF-8 fournit un point intermédiaire pour tous les encodages. Dans l'exemple ci-dessus, le texte serait converti en UTF-8 depuis n'importe quel encodage utilisé par l'opération système. Ensuite, il serait converti de UTF-8 vers l'encodage de police requis par le système d'affichage.

Certains encodages de base sont précompilés dans Tcl. D'autres peuvent être définis par l'utilisateur ou chargés dynamiquement à partir de fichiers d'encodage indépendants de la plateforme.

DESCRIPTION

Tcl_GetEncoding trouve un encodage étant donné son nom. Le nom peut faire référence à un encodage intégré à Tcl, à un encodage défini par l'utilisateur enregistré via Tcl_CreateEncoding, ou à un encodage chargeable dynamiquement. La valeur renvoyée est un token représentant l'encodage et peut être utilisée dans des procédures ultérieures telles que Tcl_GetEncodingName, Tcl_FreeEncoding et Tcl_UtfToExternal. Si le nom ne fait référence à aucun encodage connu ou chargeable, NULL est renvoyé et un message d'erreur est renvoyé dans interp.

L'encodage maintient une banque d'encodages actuellement en cours d'utilisation. La première fois que name est rencontré, Tcl_GetEncoding renvoie un encodage avec un compteur de référence de 1. Si le même name est demandé à nouveau, le compteur de référence de cet encodage est incrémenté sans la surcharge de l'allocation d'un nouvel encodage et de ses structures associées.

Lorsqu'un encodage n'est plus nécessaire, Tcl_FreeEncoding doit être appelé pour le libérer. Lorsqu'un encodage n'est plus utilisé (c'est-à-dire qu'il a été libéré autant de fois qu'il a été obtenu), Tcl_FreeEncoding libérera toute la mémoire utilisée par l'encodage et le supprimera de la banque.

Tcl_GetEncodingFromObj traite la représentation de chaîne de l'objet objPtr comme un nom d'encodage et trouve un encodage portant ce nom, tout comme le fait Tcl_GetEncoding. Lorsqu'un encodage est trouvé, il est mis en cache dans la valeur de objPtr pour les références futures, et le token Tcl_Encoding est écrit dans encodingPtr.

Mantener toda la estructura del archivo. El puntero a la memoria de almacenamiento encodingPtr se refiere a un valor que se devuelve, y el valor TCL_OK se retorna. Si no se encuentra tal codificación, se retorna TCL_ERROR y no se realiza ninguna escritura en *encodingPtr. De manera similar a Tcl_GetEncoding, el usuario debe llamar a Tcl_FreeEncoding en el token de codificación resultante cuando ya no lo use.

Tcl_ExternalToUtfDString convierte un buffer de entrada src de la codificación especificada encoding en UTF-8. Los bytes convertidos se almacenan en dstPtr, que se termina con el carácter nulo adecuado. El usuario debe llamar a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Cuando se convierten los caracteres de la fuente, si alguno no puede representarse en la codificación objetivo, se utiliza un carácter de reemplazo por defecto. El valor devuelto es un puntero al valor almacenado en el DString.

Tcl_ExternalToUtf convierte un buffer de entrada src de la codificación especificada encoding en UTF-8. MÁS de srcLen bytes se convierten del buffer de entrada y hasta dstLen bytes se escriben en dst. En todos los casos, *srcReadPtr se llena con el número de bytes que se convirtieron correctamente desde src, y *dstWrotePtr se llena con el número de bytes que se escribieron en dst. El valor devuelto es uno de los siguientes:

TCL_OK
Todo el contenido de src se convirtió.
TCL_CONVERT_NOSPACE
El buffer de destino no fue suficientemente grande para contener todos los datos convertidos; se convertieron tantos caracteres como podían.
TCL_CONVERT_MULTIBYTE
Los últimos bytes de la fuente eran el inicio de una secuencia de múltiples bytes, pero se necesitaban más bytes para completar esta secuencia. Una llamada posterior al convertidor debe pasar un buffer que contenga los bytes no convertidos que quedan en src, más algunos bytes de la secuencia de entrada para completar la secuencia de múltiples bytes.
TCL_CONVERT_SYNTAX
El buffer de entrada contuvo una secuencia de caracteres inválida. Esto puede ocurrir si el flujo de entrada ha sido dañado o si el método de codificación fue mal identificado.
TCL_CONVERT_UNKNOWN
El buffer de entrada contuvo un carácter que no se puede representar en la codificación objetivo y TCL_ENCODING_STOPONERROR fue especificado.

Tcl_UtfToExternalDString convierte un buffer de entrada src de UTF-8 en la codificación especificada encoding. Los bytes convertidos se almacenan en dstPtr, que se termina con el carácter nulo adecuado. El usuario debe llamar a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Cuando se convierten los caracteres de la fuente, si alguno no puede representarse en la codificación objetivo, se utiliza un carácter de reemplazo por defecto. El valor devuelto es un puntero al valor almacenado en el DString.

Tcl_UtfToExternal convierte un buffer de entrada src de UTF-8 en la codificación especificada encoding. MÁS de srcLen bytes se convierten del buffer de entrada y hasta dstLen bytes se escriben en dst. En todos los casos, *srcReadPtr se llena con el número de bytes que se convirtieron correctamente desde src, y *dstWrotePtr se llena con el número de bytes que se escribieron en dst. Los valores devueltos son los mismos que en Tcl_ExternalToUtf.

Tcl_WinUtfToTChar y Tcl_WinTCharToUtf son funciones de soporte para convertir entre UTF-8 y cadenas de Windows, basadas en el tipo TCHAR, que por convenio es una caracter Unicode en Windows NT.

Tcl_GetEncodingName es aproximadamente la inversa de Tcl_GetEncoding. Dado un encoding, el valor devuelto es el argumento name que se usó para crear la codificación. El string devuelto por Tcl_GetEncodingName solo se garantiza que persista hasta que el encoding sea eliminado. El usuario debe no modificar este string.

Tcl_SetSystemEncoding establece la codificación por defecto que se utilizará cuando el usuario pasa un valor NULL para el argumento encoding a cualquier función de codificación. Si name es NULL, el encodificador por defecto se resetea a la codificación del sistema, binary. Si el nombre no refiere a ninguna codificación conocida o cargable, se devuelve TCL_ERROR y una mensaje de error se deja en interp. De otro modo, esta procedimiento incrementa el contador de referencias del nuevo encodificador por defecto, decrementa el contador de referencias del antiguo encodificador por defecto y devuelve TCL_OK.

Tcl_GetEncodingNameFromEnvironment proporciona una manera para que la biblioteca Tcl reporte el nombre de la codificación que cree creer que es la correcta para usar como encodificador del sistema, basado en llamadas del sistema y examinación del entorno adecuado al plataforma. Recibe bufPtr, un puntero a un Tcl_DString no inicializado o liberado, y escribe el nombre de la codificación en él. El valor devuelto es el valor de Tcl_DStringValue.

Tcl_GetEncodingNames establece el resultado interp a una lista que contiene los nombres de todas las codificaciones definidas o dinámicamente cargables, buscando en la ruta de codificaciones especificada por Tcl_SetDefaultEncodingDir. Este procedimiento no asegura que los archivos dinámicamente cargables contengan datos válidos, pero solo garantiza que existan.

Tcl_CreateEncoding define una nueva codificación y registra las procedimientos C que se llaman para convertir entre esta codificación y UTF-8. Las codificaciones creadas por Tcl_CreateEncoding son después visibles en la base de datos usada por Tcl_GetEncoding. De manera similar a Tcl_GetEncoding, el valor devuelto es un token que representa la codificación y puede usarse en llamadas posteriores a otras funciones de codificación. Tcl_CreateEncoding devuelve una codificación con un contador de referencias de 1. Si ya existe una codificación con el nombre especificado, su entrada en la base de datos se reemplaza con la nueva codificación; el token del antiguo encodificador permanece válido y sigue comportándose como antes, pero los usuarios de este token ahora llamarán las procedimientos de codificación nuevas.

El argumento typePtr de Tcl_CreateEncoding contiene información sobre el nombre de la codificación y los procedimientos que se llamarán para convertir entre esta codificación y UTF-8. Es definido así:

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

El encodingName proporciona un nombre para la codificación, por el cual se puede referir en otros procedimientos como Tcl_GetEncoding. El toUtfProc refiere a un procedimiento de callback para convertir texto de esta codificación a UTF-8. El fromUtfProc refiere a un procedimiento de callback para convertir texto de UTF-8 a esta codificación. El freeProc refiere a un procedimiento de callback para invocar cuando se elimina esta codificación. El campo freeProc puede ser NULL. El clientData contiene un valor de una palabra arbitraria pasado a toUtfProc, fromUtfProc y freeProc cuando se llamen. Generalmente, este es un puntero a un conjunto de datos que contiene información específica de la codificación que puede usarse por los procedimientos de callback. Por ejemplo, dos codificaciones muy similares como ascii y macRoman pueden usar el mismo procedimiento de callback, pero usan diferentes valores de clientData para controlar su comportamiento. El nullSize especifica el número de ceros que significan el fin de cadena en esta codificación. Debe ser 1 (para codificaciones de solo byte o multi-byte como ASCII o Shift-JIS) o 2 (para codificaciones de dos bytes como Unicode). Las codificaciones con tamaño fijo de 3 o más bytes por carácter (como CNS11643) no son aceptadas.

Los procedimientos de callback toUtfProc y fromUtfProc deben corresponder al tipo Tcl_EncodingConvertProc:

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

Los procedimientos de callback toUtfProc y fromUtfProc se llaman por Tcl_ExternalToUtf o Tcl_UtfToExternal para realizar la conversión real. El parámetro clientData de estos procedimientos es el mismo que el clientData especificado en Tcl_CreateEncoding cuando la codificación fue creada. Los argumentos restantes de las procedimientos de callback son los mismos que los argumentos, documentados arriba, de Tcl_ExternalToUtf o Tcl_UtfToExternal, con las siguientes excepciones. Si el argumento srcLen de una de estas funciones de alto nivel es negativo, el valor pasado al procedimiento de callback será la longitud adecuada de la codificación src. Si cualquiera de los argumentos srcReadPtr, dstWrotePtr, o dstCharsPtr de una de estas funciones de alto nivel es NULL, el valor correspondiente pasado al procedimiento de callback será una ubicación no nula.

El procedimiento de callback freeProc, si no es NULL, debe corresponder al tipo Tcl_EncodingFreeProc:

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

Este freeProc se llama cuando se elimina la codificación. El parámetro clientData es el mismo que el clientData especificado en Tcl_CreateEncoding cuando la codificación fue creada.

Tcl_GetEncodingSearchPath y Tcl_SetEncodingSearchPath se usan para acceder y establecer la lista de carpetas de directorios del sistema que se buscan para archivos de datos de codificación.

El valor devuelto por Tcl_GetEncodingSearchPath es el valor almacenado por la última llamada exitosa a Tcl_SetEncodingSearchPath. Si no se ha realizado ninguna llamada a Tcl_SetEncodingSearchPath, Tcl calculará un valor inicial basado en el entorno. Hay una ruta de búsqueda de codificación única para el proceso, compartida por todos los hilos del proceso.

FICHIERS ENCODAGE

L'espace empêcherait la précompilation de tous les algorithmes d'encodage possibles dans Tcl, donc de nombreux encodages sont stockés sur disque sous forme de fichiers d'encodage chargeables dynamiquement. Ce comportement permet également à l'utilisateur de créer des fichiers d'encodage supplémentaires qui peuvent être chargés en utilisant le même mécanisme. Ces fichiers d'encodage contiennent des informations sur les tables et/ou les séquences d'échappement utilisées pour mapper entre un encodage externe et Unicode. L'encodage externe peut se composer de caractères sur un seul octet, de plusieurs octets ou de deux octets.

Chaque encodage chargeable dynamiquement est représenté par un fichier texte. La première ligne du fichier, commençant par un symbole « # », est un commentaire qui fournit une description lisible par l'homme du fichier. La ligne suivante identifie le type de fichier d'encodage. Il peut s'agir de l'une des lettres suivantes :

[1] S
Un encodage sur un seul octet, où un caractère a toujours une longueur d'un octet dans l'encodage. Un exemple est iso8859-1, utilisé par de nombreuses langues européennes.
[2] D
Un encodage sur deux octets, où un caractère a toujours une longueur de deux octets dans l'encodage. Un exemple est big5, utilisé pour le texte chinois.
[3] M
Un encodage multi-octets, où un caractère peut être d'un ou deux octets. Certains octets sont des octets principaux, indiquant qu'un autre octet doit suivre et que les deux octets ensemble représentent un caractère. D'autres octets ne sont pas des octets principaux et se représentent eux-mêmes. Un exemple est shiftjis, utilisé par de nombreux ordinateurs japonais.
[4] E
Un encodage de séquence d'échappement, spécifiant que certaines séquences d'octets ne représentent pas des caractères, mais des commandes qui décrivent comment les octets suivants doivent être interprétés.

Le reste des lignes du fichier dépend du type.

Les cas [1], [2] et [3] sont collectivement appelés fichiers d'encodage basés sur des tables. Les lignes d'un fichier d'encodage basé sur des tables sont dans le même format que cet exemple tiré de l'encodage shiftjis (ce n'est pas le fichier complet) :

Les lignes suivantes dans l'exemple ci-dessus sont des pages qui décrivent comment mapper de l'encodage vers Unicode à 2 octets. La première ligne d'une page identifie le numéro de page. Après cela se trouvent 256 nombres à double octet, arrangés en 16 lignes de 16 nombres. Étant donné un caractère dans l'encodage, l'octet de poids fort de ce caractère est utilisé pour sélectionner la page, et l'octet de poids faible de ce caractère est utilisé comme index pour sélectionner l'un des nombres à double octet de cette page - la valeur obtenue étant le caractère Unicode correspondant. D'après l'examen de l'exemple ci-dessus, on peut voir que les caractères 0x7E et 0x8163 dans shiftjis correspondent respectivement à 203E et 2026 dans Unicode.

Après la première page viendront toutes les autres pages, chacune dans le même format que la première : un nombre identifiant la page suivi de 256 caractères Unicode à double octet. Si un caractère de l'encodage correspond au caractère Unicode 0000, cela signifie que le caractère n'existe pas réellement. Si tous les caractères d'une page correspondent à 0000, cette page peut être omise.

Le cas [4] est le fichier d'encodage de séquences d'échappement. Les lignes de ce type de fichier sont dans le même format que cet exemple tiré de l'encodage iso2022-jp :

# Fichier d'encodage : iso2022-jp, piloté par échappement
E
init		{}
final		{}
iso8859-1	\x1b(B
jis0201		\x1b(J
jis0208		\x1b$@
jis0208		\x1b$B
jis0212		\x1b$(D
gb2312		\x1b$A
ksc5601		\x1b$(C

Dans le fichier, la première colonne représente une option et la deuxième colonne est la valeur associée. init est une chaîne à émettre ou à attendre avant la conversion du premier caractère, tandis que final est une chaîne à émettre ou à attendre après le dernier caractère. Toutes les autres options sont des noms d'encodages basés sur des tables ; la valeur associée est la séquence d'échappement qui marque cet encodage. La syntaxe Tcl est utilisée pour les valeurs ; dans l'exemple ci-dessus, par exemple, « {} » représente la chaîne vide et « \x1b » représente le caractère 27.

Lorsque Tcl_GetEncoding rencontre un nom d'encodage qui n'a pas été chargé, il tente de charger un fichier d'encodage appelé nom.enc à partir du sous-répertoire encoding de chaque répertoire que Tcl utilise pour rechercher sa bibliothèque de scripts. Si le fichier d'encodage existe mais est mal formé, un message d'erreur sera laissé dans interp.
