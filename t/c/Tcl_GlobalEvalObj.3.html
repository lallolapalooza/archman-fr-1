Tcl_EvalObjEx(3) Procédures de la bibliothèque Tcl Tcl_EvalObjEx(3)

NAME

Tcl_EvalObjEx, Tcl_EvalFile, Tcl_EvalObjv, Tcl_Eval, Tcl_EvalEx, Tcl_GlobalEval, Tcl_GlobalEvalObj, Tcl_VarEval, Tcl_VarEvalVA - exécuter des scripts Tcl

SYNOPSIS

#include <tcl.h>

int
Tcl_EvalObjEx(interp, objPtr, flags)

int
Tcl_EvalFile(interp, fileName)

int
Tcl_EvalObjv(interp, objc, objv, flags)

int
Tcl_Eval(interp, script)

int
Tcl_EvalEx(interp, script, numBytes, flags)

int
Tcl_GlobalEval(interp, script)

int
Tcl_GlobalEvalObj(interp, objPtr)

int
Tcl_VarEval(interp, part, part, ... (char *)NULL)

int
Tcl_VarEvalVA(interp, argList)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur dans lequel le script sera exécuté. Le résultat de l'interpréteur est modifié pour stocker le résultat ou le message d'erreur du script.
Tcl_Obj *objPtr (in)
Valeur Tcl contenant le script à exécuter.
int flags (in)
Combinaison OR bit à bit de drapeaux spécifiant des options supplémentaires. TCL_EVAL_GLOBAL et TCL_EVAL_DIRECT sont actuellement pris en charge.
const char *fileName (in)
Nom d'un fichier contenant un script Tcl.
int objc (in)
Le nombre de valeurs dans le tableau pointé par objv ; c'est aussi le nombre de mots dans la commande.
Tcl_Obj **objv (in)
Pointe vers un tableau de pointeurs vers des valeurs ; chaque valeur contient la valeur d'un mot dans la commande à exécuter.
int numBytes (in)
Le nombre d'octets dans script, sans inclure de caractère nul de fin. Si -1, tous les caractères jusqu'au premier nul sont utilisés.
const char *script (in)
Le premier octet du script à exécuter (terminé par un nul et en UTF-8).
const char *part (in)
Une chaîne qui fait partie d'un script Tcl.
va_list argList (in)
Une liste d'arguments qui doit avoir été initialisée avec va_start et terminée avec va_end.

DESCRIPTION

Les procédures décrites ici sont appelées pour exécuter des scripts Tcl sous différentes formes. Tcl_EvalObjEx est la procédure principale et est utilisée par beaucoup d'autres. Elle exécute les commandes dans le script stocké dans objPtr jusqu'à ce qu'une erreur se produise ou que la fin du script soit atteinte. Si c'est la première fois que objPtr est exécuté, ses commandes sont compilées en instructions de bytecode qui sont ensuite exécutées. Les instructions de bytecode sont stockées dans objPtr de sorte que l'étape de compilation puisse être omise si la valeur est réévaluée à l'avenir.

La valeur de retour de Tcl_EvalObjEx (et de toutes les autres procédures décrites ici) est un code d'achèvement Tcl avec l'une des valeurs TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK, ou TCL_CONTINUE, ou toute valeur entière possible d'une extension. De plus, une valeur de résultat ou un message d'erreur est laissé dans le résultat de interp ; il peut être récupéré en utilisant Tcl_GetObjResult.

Tcl_EvalFile lit le fichier donné par fileName et évalue son contenu comme un script Tcl. Il renvoie les mêmes informations que Tcl_EvalObjEx. Si le fichier ne peut pas être lu, une erreur Tcl est renvoyée pour décrire pourquoi le fichier ne peut pas être lu. Le caractère de fin de fichier pour les fichiers est \32 ( ^Z ) pour tous les systèmes d'exploitation. Si vous avez besoin d'un \32 (^Z) dans le code pour des comparaisons de chaînes, vous pouvez utiliser \032 ou \u001a, qui seront très probablement remplacés par l'interpréteur Tcl comme ^Z.

Tcl_EvalObjv exécute une commande pré-assemblée au lieu d'un script. Les arguments objc et objv contiennent les valeurs des mots de la commande Tcl, un mot par valeur dans objv. Tcl_EvalObjv évalue la commande et renvoie un code d'achèvement et un résultat tels que Tcl_EvalObjEx. L'appelant de Tcl_EvalObjv doit gérer le compteur de références des éléments de objv, en s'assurant que les valeurs sont valides jusqu'à ce que Tcl_EvalObjv renvoie.

Tcl_Eval est similaire à Tcl_EvalObjEx sauf que le script à exécuter est fourni sous forme de chaîne plutôt que de valeur et qu'il n'y a pas de compilation. La chaîne doit être une chaîne UTF-8 valide, convertie par Tcl_ExternalToUtfDString ou Tcl_ExternalToUtf si l'on sait qu'elle pourrait contenir des caractères ASCII majuscules dont les combinaisons possibles peuvent être un code UTF-8 spécial. La chaîne est analysée et exécutée directement (en utilisant Tcl_EvalObjv) au lieu d'être compilée et exécutée en bytecode. Dans les situations où l'on sait que le script ne sera pas exécuté à nouveau, Tcl_Eval peut être plus rapide que Tcl_EvalObjEx.

Tcl_Eval renvoie un code d'achèvement et un résultat tels que Tcl_EvalObjEx. Remarque : pour la compatibilité avec les versions antérieures de Tcl avant 8.0, Tcl_Eval copie la valeur résultat dans interp vers interp->result (son utilisation est obsolète), où elle peut être directement accessible.

Cela rend Tcl_Eval légèrement plus lent que Tcl_EvalEx, qui ne fait pas la copie.

Tcl_EvalEx est une version étendue de Tcl_Eval qui prend des arguments supplémentaires numBytes et flags. Pour la raison d'efficacité mentionnée ci-dessus, Tcl_EvalEx est généralement préférable à Tcl_Eval.

Tcl_GlobalEval et Tcl_GlobalEvalObj sont des procédures obsolètes qui sont maintenant dépréciées. Elles sont similaires à Tcl_EvalEx et Tcl_EvalObjEx sauf que le script est évalué dans l'espace de noms global et son contexte de variables ne consiste qu'en variables globales (il ignore toute procédure Tcl active). Ces fonctions sont équivalentes à l'utilisation du drapeau TCL_EVAL_GLOBAL (voir ci-dessous).

Tcl_VarEval prend un nombre quelconque d'arguments de chaîne de n'importe quelle longueur, les concatène en une seule chaîne, puis appelle Tcl_Eval pour exécuter cette chaîne comme une commande Tcl. Elle renvoie le résultat de la commande et modifie également interp->result de la même manière que Tcl_Eval. Le dernier argument de Tcl_VarEval doit être (char *)NULL pour indiquer la fin des arguments.

Tcl_VarEvalVA est identique à Tcl_VarEval sauf qu'au lieu de prendre un nombre variable d'arguments, elle prend une liste d'arguments. Tcl_VarEvalVA est maintenant obsolète.

BITS DE DRAPEAU

Toute combinaison OR'ed des valeurs suivantes peut être utilisée comme argument flags pour des procédures telles que Tcl_EvalObjEx :

TCL_EVAL_DIRECT
Ce drapeau est uniquement utilisé par Tcl_EvalObjEx ; il est ignoré par les autres procédures. Si ce bit est défini, le script n'est pas compilé en bytecode ; il est exécuté directement comme le fait Tcl_EvalEx. Le drapeau TCL_EVAL_DIRECT est utile dans les situations où le contenu d'une valeur va changer immédiatement, de sorte que les instructions de bytecode ne seront pas réutilisées lors d'une exécution ultérieure. Dans ce cas, il est plus rapide d'exécuter le script directement.
TCL_EVAL_GLOBAL
Si ce drapeau est défini, le script est évalué dans l'espace de noms global au lieu de l'espace de noms actuel et son contexte de variables ne consiste qu'en variables globales (il ignore toute procédure Tcl active).

DÉTAILS DIVERS

Lors du traitement d'une commande Tcl, il est légal de faire des appels imbriqués pour évaluer d'autres commandes (c'est ainsi que les procédures et certaines structures de contrôle sont implémentées). Si un code différent de TCL_OK est renvoyé par un appel imbriqué à Tcl_EvalObjEx, l'appelant doit normalement renvoyer immédiatement, en passant le même code de retour à son appelant, et ainsi de suite jusqu'à ce que le niveau de l'application supérieure soit atteint. Certaines commandes, telles que for, vérifieront certains codes de retour, tels que TCL_BREAK et TCL_CONTINUE, et les traiteront spécialement sans les renvoyer.

Tcl_EvalObjEx maintient le nombre d'invocations imbriquées de Tcl_EvalObjEx en cours pour interp. Si un code de retour de TCL_RETURN, TCL_BREAK ou TCL_CONTINUE doit être renvoyé par l'invocation la plus externe de Tcl_EvalObjEx pour interp, le code de retour est converti en TCL_ERROR et le résultat de interp est défini sur un message d'erreur indiquant que le return, break ou continue a été exécuté.

Le TCL_EVAL_DIRECT est disponible pour être utilisé dans des situations où des copies directes des scripts sont nécessaires, et le TCL_EVAL_GLOBAL pour évaluer dans l'espace de noms global.

NOM

Tcl_GlobalEvalObj

 SYNOPIS

Tcl_GlobalEvalObj( [ -commande commande ] [ -arg arg ] ... )

 ARGUMENTS

-commande commande : string - Nom de la commande à exécuter. -arg arg : string - Argument à passer à la commande.

 DESCRIPTION

Cette commande exécute une commande dans le contexte de l'interpréteur Tcl global. Elle vous permet d'exécuter des commandes arbitraires et de capturer leur sortie.

 BITS_INDICATEUR

Les indicateurs suivants sont pris en charge :

  • -f : Force l'exécution de la commande même s'il ne s'agit pas d'un script.
  • -n : N'exécute pas la commande, mais renvoie le résultat.
  • -s : Exécution silencieuse, pas de sortie.
 DETAILS_DIVERS

Cette commande peut être utilisée dans divers contextes, notamment :

  • Applications de haut niveau : Assurez-vous que les codes de retour de Tcl_EvalObjEx ne sont que TCL_OK ou TCL_ERROR.
  • Exécution de scripts : Utilisez Tcl_GlobalEvalObj pour exécuter des commandes dans le contexte de l'interpréteur global.
  • Exécution de commandes : Passez des arguments à la commande en utilisant -arg.

-commande commande : string - Nom de la commande à exécuter. -arg arg : string - Argument à passer à la commande.

 DESCRIPTION

Cette commande exécute une commande dans le contexte de l'interpréteur Tcl global. Elle vous permet d'exécuter des commandes arbitraires et de capturer leur sortie.

 BITS_INDICATEUR

Les indicateurs suivants sont pris en charge :

  • -f : Force l'exécution de la commande même s'il ne s'agit pas d'un script.
  • -n : N'exécute pas la commande, mais renvoie le résultat.
  • -s : Exécution silencieuse, pas de sortie.
 DETAILS_DIVERS

Cette commande peut être utilisée dans divers contextes, notamment :

  • Applications de haut niveau : Assurez-vous que les codes de retour de Tcl_EvalObjEx ne sont que TCL_OK ou TCL_ERROR.
  • Exécution de scripts : Utilisez Tcl_GlobalEvalObj pour exécuter des commandes dans le contexte de l'interpréteur global.
  • Exécution de commandes : Passez des arguments à la commande en utilisant -arg.
