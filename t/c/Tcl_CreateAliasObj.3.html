DESCRIPTION

Ces procédures sont destinées à l'accès à la facilité multi-interpréteurs depuis l'intérieur de programmes C. Elles permettent de gérer plusieurs interpréteurs dans une relation hiérarchique, et la gestion des alias, des commandes qui, lorsqu'elles sont invoquées dans un interpréteur, exécutent une commande dans un autre interpréteur. La valeur de retour pour les procédures qui retournent un int est soit TCL_OK, soit TCL_ERROR. Si TCL_ERROR est retourné, le résultat de l'interpréteur contient un message d'erreur.

Tcl_CreateSlave crée un nouvel interpréteur comme enfant de interp. Elle crée également une commande enfant nommée childName dans interp qui permet à interp de manipuler le nouvel enfant. Si isSafe est nul, la commande crée un enfant fiable dans lequel le code Tcl a accès à toutes les commandes Tcl. Si c'est 1, la commande crée un enfant « sûr » dans lequel le code Tcl n'a accès qu'à un ensemble de commandes Tcl définies comme « Safe Tcl » ; voir l'entrée de manuel de la commande interp de Tcl pour les détails. Si la création du nouvel interpréteur enfant a échoué, NULL est retourné.

Tcl_CreateChild est un synonyme de Tcl_CreateSlave.

Tcl_IsSafe retourne 1 si interp est « sûr » (a été créé avec le drapeau TCL_SAFE_INTERPRETER spécifié), 0 sinon.

Tcl_MakeSafe marque interp comme « sûr », de sorte que les futurs appels à Tcl_IsSafe retourneront 1. Elle supprime également toutes les fonctionnalités de base potentiellement dangereuses connues (commandes et variables) de interp. Cependant, elle ne peut pas connaître les parties d'une extension ou d'une application qui sont sûres et ne fait aucune tentative pour supprimer ces parties, donc la sécurité n'est pas garantie après avoir appelé Tcl_MakeSafe. Les appelants devront faire attention à leur utilisation de Tcl_MakeSafe pour éviter des affirmations de sécurité fausses. Pour de nombreuses situations, Tcl_CreateSlave peut être un meilleur choix, car elle crée des interpréteurs dans un état connu pour être sûr.

Tcl_GetSlave retourne un pointeur vers un interpréteur enfant de interp. L'interpréteur enfant est identifié par childName. Si aucun interpréteur enfant de ce nom n'existe, NULL est retourné.

Tcl_GetChild est un synonyme de Tcl_GetSlave.

Tcl_GetMaster retourne un pointeur vers l'interpréteur maître de interp. Si interp n'a pas de maître (c'est un interpréteur de haut niveau) alors NULL est retourné.

Tcl_GetParent est un synonyme de Tcl_GetMaster.

Tcl_GetInterpPath stocke dans le résultat de interp le chemin relatif entre interp et childInterp ; childInterp doit être un enfant de interp. Si le calcul du chemin relatif réussit, TCL_OK est retourné, sinon TCL_ERROR est retourné et un message d'erreur est stocké comme résultat de interp.

Tcl_CreateAlias crée une commande nommée childCmd dans childInterp qui, lorsqu'elle est invoquée, provoquera l'invocation de la commande targetCmd dans targetInterp. Les arguments spécifiés par les chaînes contenues dans argv sont toujours ajoutés devant tous les arguments fournis lors de l'invocation de childCmd et passés à targetCmd. Cette opération retourne TCL_OK si elle réussit, ou TCL_ERROR si elle échoue ; dans ce cas, un message d'erreur est laissé dans le résultat de valeur de childInterp. Notez qu'il n'y a aucune restriction sur la relation d'ascendance (telle que créée par Tcl_CreateSlave) entre childInterp et targetInterp. Deux interpréteurs quelconques peuvent être utilisés, sans aucune restriction sur leur relation.

Tcl_CreateAliasObj est similaire à Tcl_CreateAlias sauf qu'elle prend un vecteur de valeurs à passer comme arguments supplémentaires au lieu d'un vecteur de chaînes.

Tcl_GetAliasObj retourne des informations sous la forme d'un pointeur vers un vecteur de structures Tcl_Obj concernant un alias aliasName dans interp. N'importe lequel des champs de résultat peut être NULL, auquel cas la donnée correspondante n'est pas retournée. Si un champ de résultat n'est pas NULL, l'adresse indiquée est définie à la donnée correspondante. Par exemple, si targetCmdPtr n'est pas NULL, il est défini à un pointeur vers la chaîne contenant le nom de la commande cible.

Tcl_ExposeCommand déplace la commande nommée hiddenCmdName de l'ensemble des commandes masquées vers l'ensemble des commandes exposées, en la plaçant sous le nom cmdName. HiddenCmdName doit être le nom d'une commande masquée existante, sinon l'opération retournera TCL_ERROR et laissera un message d'erreur comme résultat de interp. Si une commande exposée nommée cmdName existe déjà, l'opération retournera TCL_ERROR et laissera un message d'erreur comme résultat de interp. Si l'opération réussit, elle retournera TCL_OK. Après l'exécution de cette commande, les tentatives d'utilisation de cmdName dans tout mécanisme d'évaluation de script réussiront à nouveau.

Tcl_HideCommand déplace la commande nommée cmdName de l'ensemble des commandes exposées vers l'ensemble des commandes masquées, sous le nom hiddenCmdName. CmdName doit être le nom d'une commande exposée existante, sinon l'opération retournera TCL_ERROR et laissera un message d'erreur comme résultat de interp. Actuellement, ni cmdName ni hiddenCmdName ne doivent contenir de qualificateurs d'espace de noms, sinon l'opération retournera TCL_ERROR et laissera un message d'erreur comme résultat de interp. CmdName sera recherché dans l'espace de noms global, et non par rapport à l'espace de noms courant, même si l'espace de noms courant n'est pas le global. Si une commande masquée dont le nom est hiddenCmdName existe déjà, l'opération retournera également TCL_ERROR et un message d'erreur sera laissé comme résultat de interp. Si l'opération réussit, elle retournera TCL_OK. Après l'exécution de cette commande, les tentatives d'utilisation de cmdName dans tout mécanisme d'évaluation de script échoueront.

Pour une description de l'interface Tcl pour plusieurs interpréteurs, voir interp(n).
