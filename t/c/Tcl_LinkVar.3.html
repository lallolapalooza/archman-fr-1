Tcl_LinkVar(3) Procédures de bibliothèque Tcl Tcl_LinkVar(3)

NOM

Tcl_LinkVar, Tcl_UnlinkVar, Tcl_UpdateLinkedVar - lier une variable Tcl à une variable C

SYNTAXE

#include <tcl.h>

int
Tcl_LinkVar(interp, varName, addr, type)

Tcl_UnlinkVar(interp, varName)

Tcl_UpdateLinkedVar(interp, varName)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur contenant varName. Utilisé également par Tcl_LinkVar pour renvoyer des messages d'erreur.
const char *varName (in)
Nom de la variable globale.
char *addr (in)
Adresse de la variable C qui doit être liée à varName.
int type (in)
Type de la variable C. Doit être l'un des suivants : TCL_LINK_INT, TCL_LINK_UINT, TCL_LINK_CHAR, TCL_LINK_UCHAR, TCL_LINK_SHORT, TCL_LINK_USHORT, TCL_LINK_LONG, TCL_LINK_ULONG, TCL_LINK_WIDE_INT, TCL_LINK_WIDE_UINT, TCL_LINK_FLOAT, TCL_LINK_DOUBLE, TCL_LINK_BOOLEAN, ou TCL_LINK_STRING, éventuellement combiné avec TCL_LINK_READ_ONLY pour rendre la variable Tcl en lecture seule.

DESCRIPTION

Tcl_LinkVar utilise des traces de variables pour maintenir la variable Tcl nommée par varName synchronisée avec la variable C à l'adresse donnée par addr. Chaque fois que la variable Tcl est lue, la valeur de la variable C sera renvoyée, et chaque fois que la variable Tcl est écrite, la variable C sera mise à jour pour avoir la même valeur. Tcl_LinkVar renvoie normalement TCL_OK ; si une erreur se produit lors de la mise en place du lien (par exemple, parce que varName est le nom d'un tableau), alors TCL_ERROR est renvoyé et le résultat de l'interpréteur contient un message d'erreur.

L'argument type spécifie le type de la variable C et doit avoir l'une des valeurs suivantes, éventuellement combinée avec TCL_LINK_READ_ONLY :

TCL_LINK_INT
La variable C est de type int. Toute valeur écrite dans la variable Tcl doit avoir une forme entière valide acceptable par Tcl_GetIntFromObj ; les tentatives d'écriture de valeurs non entières dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont acceptées comme valides.
TCL_LINK_UINT
La variable C est de type unsigned int. Toute valeur écrite dans la variable Tcl doit avoir une forme entière non signée valide acceptable par Tcl_GetWideIntFromObj et être dans la plage définie pour le type unsigned int sur la plateforme ; les tentatives d'écriture de valeurs non entières (ou de valeurs hors plage) dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont acceptées comme valides.
TCL_LINK_CHAR
La variable C est de type char. Toute valeur écrite dans la variable Tcl doit avoir une forme entière valide acceptable par Tcl_GetIntFromObj et être dans la plage du type de données char ; les tentatives d'écriture de valeurs non entières ou hors plage dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont acceptées comme valides.
TCL_LINK_UCHAR
La variable C est de type unsigned char. Toute valeur écrite dans la variable Tcl doit avoir une forme entière non signée valide acceptable par Tcl_GetIntFromObj et être dans la plage définie pour le type unsigned char sur la plateforme ; les tentatives d'écriture de valeurs non entières (ou de valeurs hors plage) dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont acceptées comme valides.
TCL_LINK_SHORT
La variable C est de type short. Toute valeur écrite dans la variable Tcl doit avoir une forme entière valide acceptable par Tcl_GetIntFromObj et être dans la plage du type de données short ; les tentatives d'écriture de valeurs non entières ou hors plage dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont acceptées comme valides.
TCL_LINK_USHORT
La variable C est de type unsigned short. Toute valeur écrite dans la variable Tcl doit avoir une forme entière non signée valide acceptable par Tcl_GetIntFromObj et être dans la plage définie pour le type unsigned short sur la plateforme ; les tentatives d'écriture de valeurs non entières (ou de valeurs hors plage) dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont acceptées comme valides.
TCL_LINK_LONG
La variable C est de type long. Toute valeur écrite dans la variable Tcl doit avoir une forme entière valide acceptable par Tcl_GetLongFromObj ; les tentatives d'écriture de valeurs non entières ou hors plage dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont acceptées comme valides.
TCL_LINK_ULONG
La variable C est de type unsigned long. Toute valeur écrite dans la variable Tcl doit avoir une forme entière non signée valide acceptable par Tcl_GetWideIntFromObj et être dans la plage définie pour le type unsigned long sur la plateforme ; les tentatives d'écriture de valeurs non entières (ou de valeurs hors plage) dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont acceptées comme valides.
TCL_LINK_DOUBLE
La variable C est de type double. Toute valeur écrite dans la variable Tcl doit avoir une forme réelle valide acceptable par Tcl_GetDoubleFromObj ; les tentatives d'écriture de valeurs non réelles dans varName seront rejetées avec des erreurs Tcl. Les représentations entières ou réelles incomplètes (comme la chaîne vide, '.', '+', '-' ou le préfixe hexadécimal/octal/binaire) sont acceptées comme valides.
TCL_LINK_FLOAT
La variable C est de type float. Toute valeur écrite dans la variable Tcl doit avoir une forme réelle valide acceptable par Tcl_GetDoubleFromObj et doit être dans la plage acceptable pour un float ; les tentatives d'écriture de valeurs non réelles (ou de valeurs hors plage) dans varName seront rejetées avec des erreurs Tcl. Les représentations entières ou réelles incomplètes (comme la chaîne vide, '.', '+', '-' ou le préfixe hexadécimal/octal/binaire) sont acceptées comme valides.
TCL_LINK_WIDE_INT
La variable C est de type Tcl_WideInt (qui est un type entier d'au moins 64 bits sur toutes les plateformes qui peuvent le supporter.) Toute valeur écrite dans la variable Tcl doit avoir une forme entière valide acceptable par Tcl_GetWideIntFromObj ; les tentatives d'écriture de valeurs non entières dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont acceptées comme valides.
TCL_LINK_WIDE_UINT
La variable C est de type Tcl_WideUInt (qui est un type entier non signé d'au moins 64 bits sur toutes les plateformes qui peuvent le supporter.) Toute valeur écrite dans la variable Tcl doit avoir une forme entière non signée valide acceptable par Tcl_GetWideIntFromObj (elle sera convertie en non signée) ; les tentatives d'écriture de valeurs non entières dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont acceptées comme valides.
TCL_LINK_BOOLEAN
La variable C est de type int. Toute valeur écrite dans la variable Tcl doit être une forme booléenne valide acceptable par Tcl_GetBooleanFromObj ; les tentatives d'écriture de valeurs non booléennes dans varName seront rejetées avec des erreurs Tcl.
TCL_LINK_STRING
La variable C est un pointeur vers une chaîne de caractères, c'est-à-dire char *. Toute valeur écrite dans la variable Tcl doit être une chaîne de caractères valide ; la mémoire pour la nouvelle chaîne sera allouée par Tcl_LinkVar. Le code C appelant est responsable de la libération de cette mémoire lorsqu'elle n'est plus nécessaire, par exemple lorsque le lien est rompu. Le pointeur C original sera perdu. Si le pointeur C pointe vers une chaîne qui doit survivre, elle doit être copiée. Les valeurs nulles sont acceptées pour addr, ce qui signifie que la variable Tcl sera liée à un pointeur NULL. Si le lien est établi avec une chaîne, lorsque le lien est rompu, la chaîne sera libérée.
TCL_LINK_READ_ONLY
Option combinable avec un des types ci-dessus. Rend la variable Tcl associée en lecture seule. Les tentatives d'écriture seront rejetées avec une erreur Tcl.

Tcl_UnlinkVar supprime le lien entre la variable Tcl nommée par varName et la variable C correspondante. Si le lien a été créé avec TCL_LINK_STRING, la mémoire allouée pour la chaîne sera libérée.

Tcl_UpdateLinkedVar peut être appelée depuis C pour forcer la mise à jour de la variable C liée à partir de la valeur de la variable Tcl. Ceci est nécessaire si la variable C peut être modifiée d'une manière qui n'est pas déclenchée par une mise à jour de la variable Tcl.

Tcl_LinkVar et Tcl_UnlinkVar sont généralement utilisées pour créer des liens entre des variables Tcl et des variables globales C. Ils ne fonctionnent pas avec les variables locales C. Les variables tableaux Tcl ne peuvent pas être directement liées à des variables C. La création d'un lien vers une variable de type chaîne de caractères alloue de la mémoire qui doit être libérée par le code C appelant.

MODIFICATIONS

Si une variable Tcl est liée à une variable C et que le type est TCL_LINK_STRING, l'appelant est responsable de la gestion de la mémoire de la chaîne liée. Le pointeur de chaîne original sera perdu. Si le pointeur pointait vers une chaîne statique ou une chaîne qui doit survivre, elle doit être copiée avant que le lien ne soit établi.

MÉMOIRE

Pour les liens de type TCL_LINK_STRING, Tcl_LinkVar alloue de la mémoire pour la chaîne à l'aide de Tcl_Alloc. Cette mémoire doit être libérée par le code C appelant en utilisant Tcl_Free lorsque le lien est rompu ou lorsque la chaîne n'est plus nécessaire. Si le lien est rompu par Tcl_UnlinkVar, la mémoire sera libérée automatiquement.

RENDEMENT

Tcl_LinkVar renvoie TCL_OK en cas de succès, et TCL_ERROR si une erreur se produit. Dans le cas d'une erreur, le champ result de l'interpréteur contiendra un message d'erreur.

NK_BOOLEAN
La variable C est de type int. Si sa valeur est zéro, elle sera lue depuis Tcl comme “0”; sinon, elle sera lue depuis Tcl comme “1”. Chaque fois que varName est modifié, la variable C sera définie à une valeur 0 ou 1. Toute valeur écrite dans la variable Tcl doit avoir une forme booléenne appropriée acceptable par Tcl_GetBooleanFromObj ; toute tentative d'écriture de valeurs non booléennes dans varName sera rejetée avec des erreurs Tcl.
TCL_LINK_STRING
La variable C est de type char *. Si sa valeur n'est pas NULL, elle doit être un pointeur vers une chaîne allouée avec Tcl_Alloc ou ckalloc. Chaque fois que la variable Tcl est modifiée, la chaîne C actuelle sera libérée et une nouvelle mémoire sera allouée pour contenir une copie de la nouvelle valeur de la variable. Si la variable C contient un pointeur NULL, la variable Tcl sera lue comme “NULL”.

Si le drapeau TCL_LINK_READ_ONLY est présent dans type, la variable sera en lecture seule depuis Tcl, de sorte que sa valeur ne pourra être modifiée qu'en modifiant la variable C. Toute tentative d'écriture de la variable depuis Tcl sera rejetée avec des erreurs.

Tcl_UnlinkVar supprime le lien précédemment établi pour la variable donnée par varName. S'il n'existe pas de lien pour varName, la procédure n'a aucun effet.

Tcl_UpdateLinkedVar peut être invoqué après que la variable C a changé pour forcer la mise à jour immédiate de la variable Tcl. Dans de nombreux cas, cette procédure n'est pas nécessaire, car toute tentative de lecture de la variable Tcl retournera la dernière valeur de la variable C. Cependant, si une trace a été définie sur la variable Tcl (par exemple, un widget Tk qui souhaite afficher la valeur de la variable), la trace ne se déclenchera pas lorsque la variable C aura changé. Tcl_UpdateLinkedVar garantit que toutes les traces sur la variable Tcl seront invoquées.

Notez que, comme pour tout appel à un interpréteur Tcl, Tcl_UpdateLinkedVar doit être appelé depuis le même thread qui a créé l'interpréteur. Le mécanisme le plus sûr est de s'assurer que la variable C est toujours mise à jour depuis le même thread qui a créé l'interpréteur (éventuellement en réponse à un événement posté avec Tcl_ThreadQueueEvent), mais lorsqu'il est nécessaire de mettre à jour la variable dans un thread séparé, il est conseillé d'utiliser Tcl_AsyncMark pour indiquer au thread hébergeant l'interpréteur qu'il est prêt à exécuter Tcl_UpdateLinkedVar.
