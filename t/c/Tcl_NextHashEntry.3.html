ARGUMENTS

Tcl_HashTable *tablePtr (entrée)
Adresse de la structure de la table de hachage (pour toutes les procédures sauf Tcl_InitHashTable, elle doit avoir été initialisée par un appel précédent à Tcl_InitHashTable).
int keyType (entrée)
Type des clés à utiliser pour la nouvelle table de hachage. Doit être soit TCL_STRING_KEYS, TCL_ONE_WORD_KEYS, TCL_CUSTOM_TYPE_KEYS, TCL_CUSTOM_PTR_KEYS, ou une valeur entière supérieure à 1.
Tcl_HashKeyType *typePtr (entrée)
Adresse de la structure qui définit le comportement de la table de hachage.
const void *key (entrée)
Clé à utiliser pour la recherche dans la table. Le format exact dépend du keyType utilisé pour créer la table.
int *newPtr (sortie)
La valeur à l'adresse *newPtr est définie à 1 si une nouvelle entrée a été créée et à 0 s'il existait déjà une entrée pour key.
Tcl_HashEntry *entryPtr (entrée)
Pointeur vers une entrée de la table de hachage.
ClientData value (entrée)
Nouvelle valeur à assigner à l'entrée de la table de hachage. N'a pas besoin d'être de type ClientData, mais doit tenir dans le même espace que ClientData.
Tcl_HashSearch *searchPtr (entrée)
Pointeur vers un enregistrement à utiliser pour suivre la progression lors de l'énumération de toutes les entrées d'une table de hachage.

DESCRIPTION

Une table de hachage se compose de zéro ou plusieurs entrées, chacune constituée d'une clé et d'une valeur. Étant donné la clé d'une entrée, les routines de hachage peuvent localiser très rapidement l'entrée, et par conséquent sa valeur. Il peut y avoir au plus une entrée dans une table de hachage pour une clé donnée, mais plusieurs entrées peuvent avoir la même valeur. Les clés peuvent prendre l'une des quatre formes suivantes : chaînes de caractères, valeurs d'un seul mot, tableaux d'entiers, ou clés personnalisées définies par une structure Tcl_HashKeyType (voir la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous). Toutes les clés d'une table donnée ont la même forme, qui est spécifiée lors de l'initialisation de la table.

La valeur d'une entrée de table de hachage peut être n'importe quoi qui tient dans le même espace qu'un pointeur “char *”. Les valeurs des entrées de table de hachage sont entièrement gérées par les clients, pas par le module de hachage lui-même. Généralement, la valeur de chaque entrée est un pointeur vers une structure de données gérée par le code client.

Les tables de hachage se développent de manière fluide à mesure que le nombre d'entrées augmente, de sorte qu'il y ait toujours moins de trois entrées par compartiment de hachage, en moyenne. Cela permet des recherches rapides quelle que soit le nombre d'entrées dans une table.

Le noyau fournit trois fonctions pour l'initialisation des tables de hachage : Tcl_InitHashTable, Tcl_InitObjHashTable et Tcl_InitCustomHashTable.

Tcl_InitHashTable initialise une structure qui décrit une nouvelle table de hachage. L'espace pour la structure est fourni par l'appelant, pas par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. Tous les types de clés décrits plus tard sont autorisés, à l'exception de TCL_CUSTOM_TYPE_KEYS et TCL_CUSTOM_PTR_KEYS.

Tcl_InitObjHashTable est un wrapper autour de Tcl_InitCustomHashTable et initialise une table de hachage dont les clés sont des Tcl_Obj *.

Tcl_InitCustomHashTable initialise une structure qui décrit une nouvelle table de hachage. L'espace pour la structure est fourni par l'appelant, pas par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. KeyType doit avoir l'une des valeurs suivantes :

TCL_STRING_KEYS
Les clés sont des chaînes de caractères terminées par un caractère nul. Elles sont passées aux routines de hachage en utilisant l'adresse du premier caractère de la chaîne.
TCL_ONE_WORD_KEYS
Les clés sont des valeurs d'un seul mot ; elles sont passées aux routines de hachage et stockées dans les entrées de la table de hachage sous forme de valeurs “char *”. La valeur du pointeur est la clé ; elle n'a pas besoin (et n'a généralement pas) de pointer vers une chaîne de caractères.
TCL_CUSTOM_TYPE_KEYS
Les clés sont de type arbitraire et sont stockées dans l'entrée. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous.
TCL_CUSTOM_PTR_KEYS
Les clés sont des pointeurs vers un type arbitraire et sont stockées dans l'entrée. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous.
autre
Si keyType n'est pas l'une des options ci-dessus, il doit s'agir d'une valeur entière supérieure à 1. Dans ce cas, les clés seront des tableaux de valeurs “int”, où keyType donne le nombre d'entiers dans chaque clé. Cela permet d'utiliser des structures comme clés. Toutes les clés doivent avoir la même taille. Les clés de tableau sont passées aux fonctions de hachage en utilisant l'adresse du premier entier du tableau.

Tcl_DeleteHashTable supprime toutes les entrées d'une table de hachage et libère la mémoire associée au tableau de compartiments et aux entrées de la table. Elle ne libère pas la structure de table elle-même (pointée par tablePtr), car on suppose que cette mémoire est gérée par le client. Tcl_DeleteHashTable ne libère pas non plus et ne manipule pas les valeurs des entrées de la table de hachage. Si les valeurs des entrées pointent vers de la mémoire allouée dynamiquement, il est de la responsabilité du client de libérer ces structures avant de supprimer la table.

Tcl_CreateHashEntry localise l'entrée correspondant à une clé particulière, en créant une nouvelle entrée dans la table s'il n'y en avait pas déjà une avec la clé donnée. Si une entrée existait déjà avec la clé donnée, *newPtr est mis à zéro. Si une nouvelle entrée a été créée, *newPtr est mis à une valeur non nulle et la valeur de la nouvelle entrée sera mise à zéro. La valeur de retour de Tcl_CreateHashEntry est un pointeur vers l'entrée, qui peut être utilisé pour récupérer et modifier la valeur de l'entrée ou pour supprimer l'entrée de la table.

Tcl_DeleteHashEntry supprime une entrée existante d'une table. La mémoire associée à l'entrée elle-même sera libérée, mais le client est responsable de tout nettoyage associé à la valeur de l'entrée, tel que la libération d'une structure qu'elle pointe.

Tcl_FindHashEntry est similaire à Tcl_CreateHashEntry sauf qu'elle ne crée pas de nouvelle entrée si la clé n'existe pas ; au lieu de cela, elle retourne NULL comme résultat.

Tcl_GetHashValue et Tcl_SetHashValue sont utilisées pour lire et écrire la valeur d'une entrée, respectivement. Les valeurs sont stockées et récupérées comme type “ClientData”, ce qui est suffisamment grand pour contenir une valeur de pointeur. Sur presque toutes les machines, c'est aussi suffisamment grand pour contenir une valeur entière.

Tcl_GetHashKey retourne la clé pour une entrée de table de hachage donnée, soit sous forme de pointeur vers une chaîne, une clé d'un seul mot (“char *”), soit comme pointeur vers le premier mot d'un tableau d'entiers, en fonction du keyType utilisé pour créer la table de hachage. Dans tous les cas, Tcl_GetHashKey retourne un résultat de type “char *”. Lorsque la clé est une chaîne ou un tableau, le résultat de Tcl_GetHashKey pointe vers des informations contenues dans l'entrée de la table ; ces informations resteront valides jusqu'à ce que l'entrée soit supprimée ou que sa table soit supprimée.

Tcl_FirstHashEntry et Tcl_NextHashEntry peuvent être utilisées pour parcourir toutes les entrées d'une table de hachage.

LA STRUCTURE TCL_HASHKEYTYPE

Pour utiliser des clés personnalisées (type TCL_CUSTOM_TYPE_KEYS ou TCL_CUSTOM_PTR_KEYS), un pointeur vers une structure Tcl_HashKeyType doit être passé à Tcl_InitCustomHashTable. La structure Tcl_HashKeyType est définie comme suit :

typedef struct {
    int spaceAvl;
    void (*freeProc)(char *keyPtr);
    int (*dupProc)(char *keyPtr, char *resultPtr);
    int (*compareProc)(char *key1Ptr, char *key2Ptr);
    void (*hashProc)(Tcl_HashEntry *hPtr);
} Tcl_HashKeyType;
spaceAvl
Espace (en octets) réservé pour chaque clé dans la table de hachage. Si cet argument est 0, alors les clés ne sont pas stockées dans la table de hachage.
freeProc
Procédure appelée pour libérer la mémoire d'une clé lorsque l'entrée correspondante est supprimée de la table. Doit être NULL si spaceAvl est 0 ou si les clés n'ont pas besoin d'être libérées spécifiquement.
dupProc
Procédure appelée pour dupliquer une clé lors de la création d'une nouvelle entrée dans la table. Elle est appelée pour copier la clé fournie par l'appelant dans l'espace alloué pour la clé dans la table. Doit être NULL si spaceAvl est 0. Le pointeur résultant de la copie doit être renvoyé.
compareProc
Procédure appelée pour comparer deux clés. Elle doit retourner 0 si les clés sont identiques et une valeur non nulle si elles sont différentes. Doit être NULL si les clés sont des chaînes simples (c'est-à-dire si keyType est TCL_STRING_KEYS).
hashProc
Procédure appelée pour calculer la valeur de hachage d'une clé. Elle doit stocker la valeur de hachage calculée dans le champ hash d'une structure Tcl_HashEntry. Doit être NULL si la clé est une chaîne simple (c'est-à-dire si keyType est TCL_STRING_KEYS).

Si keyType est TCL_CUSTOM_TYPE_KEYS, alors la clé elle-même est passée à hashProc et compareProc. Si keyType est TCL_CUSTOM_PTR_KEYS, alors la clé est traitée comme un pointeur vers une structure personnalisée et c'est ce pointeur qui est passé à hashProc et compareProc.

TCL_HASHSTATS

Tcl_HashStats retourne une chaîne formatée contenant des informations statistiques sur l'utilisation de la table de hachage. Les informations retournées incluent le nombre total d'entrées dans la table, le nombre de compartiments alloués, le nombre de compartiments actuellement utilisés, et les statistiques sur la distribution des entrées dans les compartiments. Ces informations peuvent être utiles pour le débogage et l'optimisation des performances. La chaîne retournée est allouée par Tcl et doit être libérée par l'appelant avec Tcl_Free.

DESCRIPTION

Tcl provides a general-purpose hash table implementation for use by extensions. The structure of a hash table is given by Tcl_HashTable, and the structure of an entry within a hash table is given by Tcl_HashEntry. These structures should not be accessed directly; use the procedures defined here.

Tcl_InitHashTable initializes the hash table structure pointed to by tablePtr to be empty. The typePtr argument describes the type of keys that will be used in the table. Standard key types are available for string keys (see Tcl_GetIndex), integer keys, and pointer keys. It is also possible to define custom key types by means of the Tcl_InitCustomHashTable procedure.

Tcl_CreateHashTable is like Tcl_InitHashTable, but it also allocates space for the table itself. The space should be freed using Tcl_DeleteHashTable.

Tcl_DeleteHashTable frees all storage associated with the hash table and any entries it contains.

Tcl_CreateHashEntry creates a new entry in the hash table tablePtr. It uses keyPtr to compute the hash value and to identify the entry. If an entry with this key already exists, it returns a pointer to the existing entry. If the entry does not exist, it creates a new entry, inserts it in the table, and returns a pointer to the new entry. If the newValuePtr argument is not NULL, then the integer it points to is set to non-zero if a new entry was created, or zero if an entry already existed.

Tcl_FindHashEntry searches the hash table tablePtr for an entry with the key keyPtr. If an entry is found, it returns a pointer to the entry; otherwise, it returns NULL.

Tcl_DeleteHashEntry deletes the entry pointed to by hPtr from its hash table. The storage for the entry is freed.

Tcl_GetHashKey returns a pointer to the key for the hash entry hPtr. The key is returned in the same format as it was passed to Tcl_CreateHashEntry or Tcl_FindHashEntry.

Tcl_GetHashValue returns the integer value associated with the hash entry hPtr. This value is set by Tcl_SetHashValue.

Tcl_SetHashValue sets the integer value associated with the hash entry hPtr to value.

The procedures Tcl_FirstHashEntry and Tcl_NextHashEntry can be used to iterate through all the entries in a hash table. A structure of type Tcl_HashSearch, provided by the client, is used to keep track of progress through the table. Tcl_FirstHashEntry initializes the search record and returns the first entry in the table (or NULL if the table is empty). Each subsequent call to Tcl_NextHashEntry returns the next entry in the table or NULL if the end of the table has been reached. A call to Tcl_FirstHashEntry followed by calls to Tcl_NextHashEntry will return each of the entries in the table exactly once, in an arbitrary order. It is inadvisable to modify the structure of the table, e.g. by creating or deleting entries, while the search is in progress, with the exception of deleting the entry returned by Tcl_FirstHashEntry or Tcl_NextHashEntry.

Tcl_HashStats returns a dynamically-allocated string with overall information about a hash table, such as the number of entries it contains, the number of buckets in its hash array, and the utilization of the buckets. It is the caller's responsibility to free the result string by passing it to ckfree.

The header file tcl.h defines the actual data structures used to implement hash tables. This is necessary so that clients can allocate Tcl_HashTable structures and so that macros can be used to read and write the values of entries. However, users of the hashing routines should never refer directly to any of the fields of any of the hash-related data structures; use the procedures and macros defined here.

THE TCL_HASHKEYTYPE STRUCTURE

Extension writers can define new hash key types by defining four procedures, initializing a Tcl_HashKeyType structure to describe the type, and calling Tcl_InitCustomHashTable. The Tcl_HashKeyType structure is defined as follows:

typedef struct Tcl_HashKeyType {
    int version;
    int flags;
    Tcl_HashKeyProc *hashKeyProc;
    Tcl_CompareHashKeysProc *compareKeysProc;
    Tcl_AllocHashEntryProc *allocEntryProc;
    Tcl_FreeHashEntryProc *freeEntryProc;
} Tcl_HashKeyType;

The version member is the version of the table. If this structure is extended in future then the version can be used to distinguish between different structures. It should be set to TCL_HASH_KEY_TYPE_VERSION.

The flags member is 0 or one or more of the following values OR'ed together:

TCL_HASH_KEY_RANDOMIZE_HASH
There are some things, pointers for example which do not hash well because they do not use the lower bits. If this flag is set then the hash table will attempt to rectify this by randomizing the bits and then using the upper N bits as the index into the table.
TCL_HASH_KEY_SYSTEM_HASH
This flag forces Tcl to use the memory allocation procedures provided by the operating system when allocating and freeing memory used to store the hash table data structures, and not any of Tcl's own customized memory allocation routines. This is important if the hash table is to be used in the implementation of a custom set of allocation routines, or something that a custom set of allocation routines might depend on, in order to avoid any circular dependency.

The hashKeyProc member contains the address of a function called to calculate a hash value for the key.

typedef unsigned int Tcl_HashKeyProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

If this is NULL then keyPtr is used and TCL_HASH_KEY_RANDOMIZE_HASH is assumed.

The compareKeysProc member contains the address of a function called to compare two keys.

typedef int Tcl_CompareHashKeysProc(
        void *keyPtr,
        Tcl_HashEntry *hPtr);

If this is NULL then the keyPtr pointers are compared. If the keys do not match then the function returns 0, otherwise it returns 1.

The allocEntryProc member contains the address of a function called to allocate space for an entry and initialize the key and clientData.

typedef Tcl_HashEntry *Tcl_AllocHashEntryProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

If this is NULL then Tcl_Alloc is used to allocate enough space for a Tcl_HashEntry, the key pointer is assigned to key.oneWordValue and the clientData is set to NULL. String keys and array keys use this function to allocate enough space for the entry and the key in one block, rather than doing it in two blocks. This saves space for a pointer to the key from the entry and another memory allocation. Tcl_Obj* keys use this function to allocate enough space for an entry and increment the reference count on the value.

The freeEntryProc member contains the address of a function called to free space for an entry.

typedef void Tcl_FreeHashEntryProc(
        Tcl_HashEntry *hPtr);

If this is NULL then Tcl_Free is used to free the space for the entry. Tcl_Obj* keys use this function to decrement the reference count on the value.
