ARGUMENTS

const Tcl_ChannelType *typePtr (in)
Pointe vers une structure contenant les adresses des procédures qui peuvent être appelées pour effectuer des opérations d'E/S et autres sur le canal.
const char *channelName (in)
Le nom de ce canal, par exemple file3 ; il ne doit être utilisé par aucun autre canal. Peut être NULL, dans ce cas le canal est créé sans nom. Si le canal créé est assigné à l'un des canaux standards (stdin, stdout ou stderr), le nom du canal assigné sera le nom du canal standard.
ClientData instanceData (in)
Valeur arbitraire d'un mot à associer à ce canal. Cette valeur est passée aux procédures dans typePtr lorsqu'elles sont invoquées.

Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer si un canal est lisible et/ou accessible en écriture.

Le canal à manipuler.
int direction (in)
TCL_READABLE signifie que le handle d'entrée est demandé ; TCL_WRITABLE signifie que le handle de sortie est demandé.

Pointe vers l'emplacement où le handle spécifique au système d'exploitation souhaité doit être stocké.
int size (in)
La taille, en octets, des tampons à allouer dans ce canal.
int mask (in)
Une combinaison OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION qui indique les événements qui se sont produits sur ce canal.

Interpréteur actuel. (peut être NULL)

DESCRIPTION

Tcl utilise une architecture de canaux à deux couches. Il fournit une couche supérieure générique pour permettre aux programmes C et Tcl d'effectuer des entrées et sorties en utilisant les mêmes API pour une variété de fichiers, périphériques, sockets, etc. Les API C génériques sont décrites dans l'entrée de manuel de Tcl_OpenFileChannel.

La couche inférieure fournit des pilotes de canaux spécifiques au type pour chaque type de périphérique supporté sur chaque plateforme. Cette entrée de manuel décrit les API C utilisées pour communiquer entre la couche générique et les pilotes de canaux spécifiques au type. Elle explique également comment de nouveaux types de canaux peuvent être ajoutés en fournissant de nouveaux pilotes de canaux.

Les pilotes de canaux se composent d'un certain nombre de composants : Premièrement, chaque pilote de canal fournit une structure Tcl_ChannelType contenant des pointeurs vers des fonctions implémentant les diverses opérations utilisées par la couche générique pour communiquer avec le pilote de canal. La structure Tcl_ChannelType et les fonctions qu'elle référence sont décrites dans la section TCL_CHANNELTYPE, ci-dessous.

Deuxièmement, les pilotes de canaux fournissent généralement une commande Tcl pour créer des instances de ce type de canal. Par exemple, la commande Tcl open crée des canaux qui utilisent les pilotes de canaux de fichiers et de commandes, et la commande Tcl socket crée des canaux qui utilisent des sockets TCP pour la communication réseau.

Troisièmement, un pilote de canal fournit optionnellement une fonction C pour ouvrir des instances de canaux de ce type. Par exemple, Tcl_OpenFileChannel ouvre un canal qui utilise le pilote de canal de fichier, et Tcl_OpenTcpClient ouvre un canal qui utilise le protocole réseau TCP. Ces fonctions de création utilisent généralement Tcl_CreateChannel en interne pour ouvrir le canal.

Pour ajouter un nouveau type de canal, vous devez implémenter une API C ou une commande Tcl qui ouvre un canal en appelant Tcl_CreateChannel. Lorsque votre pilote appelle Tcl_CreateChannel, il lui transmet une structure Tcl_ChannelType décrivant les procédures d'E/S du pilote. La couche générique invoquera alors les fonctions référencées dans cette structure pour effectuer des opérations sur le canal.

Tcl_CreateChannel ouvre un nouveau canal et lui associe les paramètres typePtr et instanceData fournis. Le canal est ouvert dans le mode indiqué par mask. Pour une discussion sur les pilotes de canaux, leurs opérations et la structure Tcl_ChannelType, voir la section TCL_CHANNELTYPE, ci-dessous.

Tcl_CreateChannel interagit avec le code qui gère les canaux standards. Une fois qu'un canal standard a été initialisé soit par un appel à Tcl_GetStdChannel, soit par un appel à Tcl_SetStdChannel, la fermeture de ce canal standard entraînera l'affectation du nouveau canal comme nouveau canal standard lors du prochain appel à Tcl_CreateChannel. Voir Tcl_StandardChannels pour un exposé général sur les canaux standards et le comportement de la bibliothèque Tcl à leur égard.

Tcl_GetChannelInstanceData retourne les données d'instance associées au canal dans channel. Il s'agit de la même valeur que l'argument instanceData lors de l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelType retourne un pointeur vers la structure Tcl_ChannelType utilisée par le canal dans l'argument channel. Il s'agit de la même valeur que l'argument typePtr lors de l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelName retourne une chaîne contenant le nom associé au canal, ou NULL si l'argument channelName de Tcl_CreateChannel était NULL.

Tcl_GetChannelHandle place le handle de périphérique spécifique au système d'exploitation associé à channel pour la direction donnée dans le

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Le lieu spécifié par handlePtr renvoie TCL_OK. Si le canal n'a pas de handle pour l'adresse spécifiée, il renvoie TCL_ERROR à la place. Différents pilotes de canal renvoient différents types de handles. Consultez les pages de manuel de chaque pilote pour déterminer le type de handle renvoyé.

Tcl_GetChannelThread renvoie l'identifiant du thread qui gère le canal spécifié. Cela permet aux pilotes de canal d'envoyer leurs événements de fichier à la bonne file d'événements, même dans un noyau multithread.

Tcl_GetChannelMode renvoie une combinaison OR de TCL_READABLE et TCL_WRITABLE, indiquant si le canal est ouvert en lecture et/ou en écriture.

Tcl_GetChannelBufferSize renvoie la taille, en octets, des tampons alloués pour stocker les entrées ou les sorties sur le canal channel. Si la valeur n'a pas été définie précédemment par un appel à Tcl_SetChannelBufferSize, elle renvoie la valeur par défaut de 4096.

Tcl_SetChannelBufferSize définit la taille, en octets, des tampons qui seront alloués lors des opérations ultérieures sur le canal pour stocker les entrées ou les sorties. L'argument size doit être compris entre 1 et 1 million, permettant des tampons de 1 octet à 1 million d'octets. Si size est en dehors de cette plage, Tcl_SetChannelBufferSize définit la taille du tampon à 4096.

Tcl_NotifyChannel est appelée par un pilote de canal pour indiquer à la couche générale que les événements spécifiés par mask se sont produits sur le canal. Les pilotes de canal sont responsables de l'invocation de cette fonction lorsque les gestionnaires de canal doivent être appelés (ou lorsque des tâches telles qu'un vidage d'écriture doivent être effectuées). Voir WATCHPROC pour plus de détails.

Tcl_BadChannelOption est appelée à partir des procédures spécifiques des pilotes setOptionProc ou getOptionProc pour générer un message d'erreur complet.

Tcl_ChannelBuffered renvoie le nombre d'octets d'entrée actuellement mis en mémoire tampon dans le tampon interne (zone de retour) du canal lui-même. Il ne signale pas les données dans les tampons globaux des canaux dont le canal spécifié fait partie.

Tcl_IsChannelShared vérifie le compteur de références du canal spécifié et renvoie si le canal a été partagé entre plusieurs interpréteurs (résultat == 1) ou non (résultat == 0).

Tcl_IsChannelRegistered vérifie si le canal spécifié est enregistré dans l'interpréteur (interp) donné (résultat == 1) ou non (résultat == 0).

Tcl_IsChannelExisting vérifie si un canal portant le nom spécifié est enregistré dans la liste globale (de threads) de tous les canaux (résultat == 1) ou non (résultat == 0).

Tcl_CutChannel supprime le canal spécifié de la liste globale (des threads) de tous les canaux (du thread actuel). L'application à un canal enregistré dans un interpréteur n'est pas autorisée. Elle notifie également le pilote si la version de Tcl_ChannelType est TCL_CHANNEL_VERSION_4 (ou supérieure) et que Tcl_DriverThreadActionProc est défini pour celui-ci.

Tcl_SpliceChannel ajoute le canal spécifié à la liste globale (des threads) de tous les canaux (du thread actuel). L'application à un canal enregistré dans un interpréteur n'est pas autorisée. Elle notifie également le pilote si la version de Tcl_ChannelType est TCL_CHANNEL_VERSION_4 (ou supérieure) et que Tcl_DriverThreadActionProc est défini pour celui-ci.

Tcl_ClearChannelHandlers supprime tous les gestionnaires de canaux et scripts d'événements associés au canal spécifié, ainsi que l'exécution de tous les processus d'événements pour ce canal.

TCL_CHANNELTYPE

Un pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers des fonctions implémentant les diverses opérations sur un canal ; ces opérations sont invoquées au besoin par la couche générale. La structure a été versionnée à partir de Tcl 8.3.2/8.4 pour corriger un problème avec les canaux bloqués. Voir la section ANCIENS TYPES DE CANAUX pour plus de détails sur l'ancienne structure.

La structure Tcl_ChannelType contient les champs suivants :

typedef struct Tcl_ChannelType {
                    const char *typeName;
                    Tcl_ChannelTypeVersion version;
                    Tcl_DriverCloseProc *closeProc;
                    Tcl_DriverInputProc *inputProc;
                    Tcl_DriverOutputProc *outputProc;
                    Tcl_DriverSeekProc *seekProc;
                    Tcl_DriverSetOptionProc *setOptionProc;
                    Tcl_DriverGetOptionProc *getOptionProc;
                    Tcl_DriverWatchProc *watchProc;
                    Tcl_DriverGetHandleProc *getHandleProc;
                    Tcl_DriverClose2Proc *close2Proc;
                    Tcl_DriverBlockModeProc *blockModeProc;
                    Tcl_DriverFlushProc *flushProc;
                    Tcl_DriverHandlerProc *handlerProc;
                    Tcl_DriverWideSeekProc *wideSeekProc;
                    Tcl_DriverThreadActionProc *threadActionProc;
                    Tcl_DriverTruncateProc *truncateProc;
                } Tcl_ChannelType;

Il n'est pas nécessaire de fournir des implémentations pour toutes les opérations de canal. Celles qui ne sont pas nécessaires peuvent être mises à NULL dans la structure : blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc et close2Proc, en plus de flushProc, handlerProc, threadActionProc et truncateProc. Les fonctions qui ne peuvent pas être implémentées de manière significative doivent renvoyer EINVAL lorsqu'elles sont appelées, indiquant que les opérations représentées ne sont pas disponibles. Il convient également de noter que wideSeekProc peut être NULL si seekProc l'est.

L'utilisateur ne doit utiliser cette structure que pour l'instanciation de Tcl_ChannelType. Lors de la référence aux champs d'une structure Tcl_ChannelType, les fonctions suivantes doivent être utilisées pour obtenir les valeurs : Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc, ou Tcl_ChannelHandlerProc.

La modification des structures a été faite de manière à ce que les types de canaux standard soient compatibles au niveau binaire. Cependant, les types de canaux qui utilisent des canaux bloqués (c'est-à-dire TLS, Trf) ont de nouvelles versions correspondant à ce changement en raison des problèmes dans l'ancien code des canaux bloqués.

TYPENAME

Le champ typeName contient une chaîne terminée par null qui identifie le type de périphérique implémenté par ce pilote, par exemple, file ou socket.

Cette valeur peut être obtenue avec Tcl_ChannelName, qui renvoie un pointeur vers la chaîne.

VERSION

Le champ version doit être défini à la version de la structure requise. TCL_CHANNEL_VERSION_2 est le minimum recommandé. TCL_CHANNEL_VERSION_3 doit être défini pour spécifier le membre wideSeekProc. TCL_CHANNEL_VERSION_4 doit être défini pour spécifier le membre threadActionProc (il inclut wideSeekProc). TCL_CHANNEL_VERSION_5 doit être défini pour spécifier les membres truncateProc (il inclut wideSeekProc et threadActionProc). S'il n'est pas défini à l'une de ces valeurs, on suppose que ce Tcl_ChannelType a la structure originale. Voir ANCIENS TYPES DE CANAUX pour plus de détails. Bien que Tcl reconnaisse et fonctionne avec chacune de ces structures, les canaux bloqués doivent être au moins de version TCL_CHANNEL_VERSION_2 pour fonctionner correctement.

Cette valeur peut être obtenue avec Tcl_ChannelVersion, qui renvoie l'une des valeurs TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 ou TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

Le champ blockModeProc contient l'adresse d'une fonction appelée par la couche générale pour définir le mode bloquant et non bloquant du périphérique. BlockModeProc doit correspondre au prototype suivant :

typedef int Tcl_DriverBlockModeProc(
                        ClientData instanceData,
                        int mode);

Le instanceData est la même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. L'argument mode est soit TCL_MODE_BLOCKING, soit TCL_MODE_NONBLOCKING pour définir le périphérique en mode bloquant ou non bloquant. La fonction doit renvoyer zéro si l'opération a réussi, ou un code d'erreur POSIX non nul si l'opération a échoué.

Si l'opération réussit, la fonction peut modifier le instanceData fourni pour enregistrer que le canal est passé en mode bloquant ou non bloquant et implémenter le comportement correspondant. Pour certains types de périphériques, le comportement bloquant et non bloquant peut être implémenté par le système d'exploitation sous-jacent ; pour d'autres types de périphériques, le comportement doit être émulé dans le pilote de canal.

Cette valeur peut être obtenue avec Tcl_ChannelBlockModeProc, qui renvoie un pointeur vers la fonction.

Un pilote de canal qui ne fournit pas de blockModeProc doit être très prudent. Il doit indiquer exactement quel mode de blocage lui est acceptable, et il doit également documenter à l'utilisateur que le mode de blocage du canal ne doit pas être changé à une valeur inacceptable. Toute confusion à ce sujet peut entraîner un interblocage (illusoire et difficile à trouver) de l'interpréteur.

CLOSEPROC ET CLOSE2PROC

Le champ closeProc contient l'adresse d'une fonction appelée par la couche générale pour nettoyer les informations relatives au pilote lorsque le canal est fermé. CloseProc doit correspondre au prototype suivant :

typedef int Tcl_DriverCloseProc(
                        ClientData instanceData,
                        Tcl_Interp *interp);

L'argument instanceData est le même que la valeur fournie à Tcl_CreateChannel lors de la création du canal. La fonction doit libérer tout stockage détenu par le pilote de canal pour ce canal, et fermer les descripteurs de fichiers d'entrée et de sortie encapsulés par ce canal. Toutes les sorties mises en file d'attente ont déjà été envoyées au périphérique avant l'invocation de cette fonction, et aucune opération de pilote ne sera invoquée après l'invocation de closeProc.

Cette valeur peut être obtenue avec Tcl_ChannelCloseProc, qui renvoie un pointeur vers la fonction.

L'utilisateur ne doit utiliser cette structure que pour l'instanciation de Tcl_ChannelType. Lors de la référence aux champs d'une structure Tcl_ChannelType, les fonctions suivantes doivent être utilisées pour obtenir les valeurs : Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc, ou Tcl_ChannelHandlerProc.

La modification des structures a été faite de manière à ce que les types de canaux standard soient compatibles au niveau binaire. Cependant, les types de canaux qui utilisent des canaux bloqués (c'est-à-dire TLS, Trf) ont de nouvelles versions correspondant à ce changement en raison des problèmes dans l'ancien code des canaux bloqués.

Alternativement, les canaux qui prennent en charge la fermeture indépendante des côtés lecture et écriture peuvent définir closeProc sur TCL_CLOSE2PROC et définir close2Proc sur l'adresse d'une fonction correspondant au prototype suivant :

typedef int Tcl_DriverClose2Proc(
        ClientData instanceData,
        Tcl_Interp *interp,

Le close2Proc sera appelé avec flags défini sur une combinaison OU de TCL_CLOSE_READ ou TCL_CLOSE_WRITE pour indiquer que le pilote doit fermer le côté lecture et/ou écriture du canal. Le pilote de canal peut être invoqué pour effectuer des opérations supplémentaires sur le canal après que close2Proc soit appelé pour fermer un ou les deux côtés du canal. Si flags est 0 (zéro), le pilote doit fermer le canal de la manière décrite ci-dessus pour closeProc. Aucune autre opération ne sera invoquée sur cette instance après que close2Proc soit appelé avec tous les drapeaux effacés. Dans tous les cas, la fonction close2Proc doit retourner zéro si l'opération de fermeture a réussi ; sinon, elle doit retourner un code d'erreur POSIX non nul. De plus, si une erreur se produit et que interp n'est pas NULL, la procédure doit stocker un message d'erreur dans le résultat de l'interpréteur.

Les valeurs closeProc et close2Proc peuvent être récupérées avec Tcl_ChannelCloseProc ou Tcl_ChannelClose2Proc, qui retournent un pointeur vers la fonction respective.

INPUTPROC

Le champ inputProc contient l'adresse d'une fonction appelée par la couche générique pour lire des données depuis le fichier ou le périphérique et les stocker dans un tampon interne. InputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

InstanceData est le même que la valeur passée à Tcl_CreateChannel lors de la création du canal. L'argument buf pointe vers un tableau d'octets dans lequel stocker les entrées du périphérique, et l'argument bufSize indique combien d'octets sont disponibles à buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique. En cas d'erreur, la fonction doit définir la variable à un code d'erreur POSIX qui identifie l'erreur qui est survenue.

La fonction doit lire les données du périphérique d'entrée encapsulé par le canal et les stocker à buf. En cas de succès, la fonction doit retourner un entier non négatif indiquant combien d'octets ont été lus depuis le périphérique d'entrée et stockés à buf. En cas d'erreur, la fonction doit retourner -1. Si une erreur se produit après que des données aient été lues depuis le périphérique, ces données sont perdues.

Si inputProc peut déterminer que le périphérique d'entrée a des données disponibles mais moins que ce qui est demandé par l'argument bufSize, la fonction ne doit tenter de lire que la quantité de données disponible et retourner sans bloquer. Si le périphérique d'entrée n'a aucune donnée disponible et que le canal est en mode non bloquant, la fonction doit retourner une erreur EAGAIN. Si le périphérique d'entrée n'a aucune donnée disponible et que le canal est en mode bloquant, la fonction doit bloquer pendant le moins de temps possible jusqu'à ce qu'au moins un octet de données puisse être lu depuis le périphérique ; ensuite, elle doit retourner autant de données qu'elle peut lire sans bloquer.

Cette valeur peut être récupérée avec Tcl_ChannelInputProc, qui retourne un pointeur vers la fonction.

OUTPUTPROC

Le champ outputProc contient l'adresse d'une fonction appelée par la couche générique pour transférer des données d'un tampon interne vers le périphérique de sortie. OutputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

InstanceData est le même que la valeur passée à Tcl_CreateChannel lors de la création du canal. L'argument buf contient un tableau d'octets à écrire sur le périphérique, et l'argument toWrite indique combien d'octets doivent être écrits depuis l'argument buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique. En cas d'erreur, la fonction doit définir cette variable à un code d'erreur POSIX qui identifie l'erreur.

La fonction doit écrire les données à buf sur le périphérique de sortie encapsulé par le canal. En cas de succès, la fonction doit retourner un entier non négatif indiquant combien d'octets ont été écrits sur le périphérique de sortie. La valeur de retour est normalement la même que toWrite, mais peut être inférieure dans certains cas, par exemple si l'opération de sortie est interrompue par un signal. En cas d'erreur, la fonction doit retourner -1. En cas d'erreur, certaines données peuvent avoir été écrites sur le périphérique.

Si le canal est non bloquant et que le périphérique de sortie ne peut absorber aucune donnée, la fonction doit retourner -1 avec une erreur EAGAIN sans écrire aucune donnée.

Cette valeur peut être récupérée avec Tcl_ChannelOutputProc, qui retourne un pointeur vers la fonction.

SEEKPROC ET WIDESEEKPROC

Le champ seekProc contient l'adresse d'une fonction appelée par la couche générique pour déplacer le point d'accès auquel les opérations d'entrée ou de sortie ultérieures seront appliquées. SeekProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

L'argument instanceData est le même que la valeur donnée à Tcl_CreateChannel lors de la création de ce canal. Offset et seekMode ont la même signification que pour la procédure Tcl_Seek (décrite dans l'entrée de manuel de Tcl_OpenFileChannel).

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique pour retourner les valeurs errno de la fonction. La fonction doit définir cette variable à un code d'erreur POSIX si une erreur se produit. La fonction doit stocker un code d'erreur EINVAL si le type de canal n'implémente pas le repositionnement.

La valeur de retour est le nouveau point d'accès ou -1 en cas d'erreur. Si une erreur s'est produite, la fonction ne doit pas déplacer le point d'accès.

S'il existe un champ seekProc non NULL, le champ wideSeekProc peut contenir l'adresse d'une fonction alternative à utiliser qui gère les décalages larges (c'est-à-dire supérieurs à 32 bits), permettant ainsi le repositionnement dans des fichiers de plus de 2 Go. Le wideSeekProc sera appelé de préférence au seekProc, mais les deux doivent être définis si le wideSeekProc est défini. WideSeekProc doit correspondre au prototype suivant :

typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

Les arguments et les valeurs de retour signifient la même chose qu'avec seekProc ci-dessus, à l'exception du type des décalages et du type de retour qui sont différents.

La valeur seekProc peut être récupérée avec Tcl_ChannelSeekProc, qui retourne un pointeur vers la fonction, et de même, le wideSeekProc peut être récupéré avec Tcl_ChannelWideSeekProc.

SETOPTIONPROC

Le champ setOptionProc contient l'adresse d'une fonction appelée par la couche générique pour définir une option spécifique au type de canal sur un canal. setOptionProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

optionName est le nom d'une option à définir, et newValue est la nouvelle valeur de cette option, sous forme de chaîne de caractères. L'instanceData est la même que la valeur donnée à Tcl_CreateChannel lors de la création de ce canal. La fonction doit effectuer toute action spécifique au type de canal requise pour implémenter la nouvelle valeur de l'option.

Certaines options sont gérées par le code générique et cette fonction n'est jamais appelée pour les définir, par exemple -blockmode. D'autres options sont spécifiques à chaque type de canal et la procédure setOptionProc du pilote de canal sera appelée pour les implémenter. Le champ setOptionProc peut être NULL, ce qui indique que ce type de canal ne prend en charge aucune option spécifique au type.

Si la valeur de l'option est modifiée avec succès à la nouvelle valeur, la fonction retourne TCL_OK. Elle doit appeler Tcl_BadChannelOption qui retourne elle-même TCL_ERROR si le optionName n'est pas reconnu. Si newValue spécifie une valeur pour l'option qui n'est pas prise en charge ou si une erreur d'appel système se produit, la fonction doit laisser un message d'erreur dans le résultat de interp si interp n'est pas NULL. La fonction doit également appeler Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

Cette valeur peut être récupérée avec Tcl_ChannelSetOptionProc, qui retourne un pointeur vers la fonction.

TCL_CHANNELTYPE

The Tcl_ChannelType structure is used to describe the operations that can be performed on a channel. Each channel registered with Tcl is associated with a Tcl_ChannelType structure. The structure describes the channel's name, and pointers to procedures that implement various channel operations. The structure is defined as follows:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverThreadActionProc *threadActionProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

The fields of the structure are described below:

TYPENAME

The typeName field contains the name of the channel type. This name is used to look up the channel type when a channel is created.

CLOSEPROC

The closeProc field contains the address of a procedure called by the generic layer to close the channel. CloseProc should match the following prototype:

typedef int Tcl_DriverCloseProc(
        ClientData instanceData);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The procedure should perform any necessary cleanup for the channel and return 0 on success or an errno code (suitable for use with Tcl_SetErrno) on failure.

This value can be retrieved with Tcl_ChannelCloseProc, which returns a pointer to the function.

INPUTPROC

The inputProc field contains the address of a procedure called by the generic layer to read data from the channel. InputProc should match the following prototype:

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        Tcl_ErrorSeverity severity);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The procedure should read up to bufSize bytes of data from the channel into the buffer pointed to by buf. It should return the number of bytes read, or return -1 if an error occurred. If an error occurs, the procedure should set an appropriate POSIX error code using Tcl_SetErrno and, if severity is not TCL_LEAVE_ERRNO, it should also leave an error message in the interpreter's result if interp is not NULL.

This value can be retrieved with Tcl_ChannelInputProc, which returns a pointer to the function.

OUTPUTPROC

The outputProc field contains the address of a procedure called by the generic layer to write data to the channel. OutputProc should match the following prototype:

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int numBytes,
        Tcl_ErrorSeverity severity);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The procedure should write numBytes bytes from the buffer pointed to by buf to the channel. It should return the number of bytes written, or return -1 if an error occurred. If an error occurs, the procedure should set an appropriate POSIX error code using Tcl_SetErrno and, if severity is not TCL_LEAVE_ERRNO, it should also leave an error message in the interpreter's result if interp is not NULL.

This value can be retrieved with Tcl_ChannelOutputProc, which returns a pointer to the function.

SEEKPROC

The seekProc field contains the address of a procedure called by the generic layer to seek on the channel. SeekProc should match the following prototype:

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The procedure should seek to the position specified by offset in the direction specified by seekMode (which can be SEEK_SET, SEEK_CUR, or SEEK_END). It should return the new absolute offset from the beginning of the file, or -1 if an error occurred. If an error occurs, the procedure should set an appropriate POSIX error code using Tcl_SetErrno.

This value can be retrieved with Tcl_ChannelSeekProc, which returns a pointer to the function.

SETOPTIONPROC

The setOptionProc field contains the address of a procedure called by the generic layer to set the options for the channel. SetOptionProc should match the following prototype:

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        const char *optionName,
        const Tcl_Obj *valuePtr);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The procedure should set the option specified by optionName to the value specified by valuePtr. The procedure should return TCL_OK on success or TCL_ERROR on failure. If an error occurs, the procedure should leave an error message in the interpreter's result.

This value can be retrieved with Tcl_ChannelSetOptionProc, which returns a pointer to the function.

GETOPTIONPROC

The getOptionProc field contains the address of a procedure called by the generic layer to get the value of an option for the channel. GetOptionProc should match the following prototype:

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        const char *optionName,
        Tcl_Interp *interp);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The procedure should get the value of the option specified by optionName and set it in the interpreter's result. The procedure should return TCL_OK on success or TCL_ERROR on failure. If an error occurs, the procedure should leave an error message in the interpreter's result.

Some options are handled by the generic code and this function is never called to retrieve their value, e.g. -blockmode. Other options are specific to each channel type and the getOptionProc procedure of the channel driver will get called to implement them. The getOptionProc field can be NULL, which indicates that this channel type supports no type specific options.

This value can be retrieved with Tcl_ChannelGetOptionProc, which returns a pointer to the function.

WATCHPROC

The watchProc field contains the address of a function called by the generic layer to initialize the event notification mechanism to notice events of interest on this channel. WatchProc should match the following prototype:

typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

The instanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The mask argument is an OR-ed combination of TCL_READABLE, TCL_WRITABLE and TCL_EXCEPTION; it indicates events the caller is interested in noticing on this channel.

The function should initialize device type specific mechanisms to notice when an event of interest is present on the channel. When one or more of the designated events occurs on the channel, the channel driver is responsible for calling Tcl_NotifyChannel to inform the generic channel module. The driver should take care not to starve other channel drivers or sources of callbacks by invoking Tcl_NotifyChannel too frequently. Fairness can be insured by using the Tcl event queue to allow the channel event to be scheduled in sequence with other events. See the description of Tcl_QueueEvent for details on how to queue an event.

This value can be retrieved with Tcl_ChannelWatchProc, which returns a pointer to the function.

GETHANDLEPROC

The getHandleProc field contains the address of a function called by the generic layer to retrieve a device-specific handle from the channel. GetHandleProc should match the following prototype:

typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The direction argument is either TCL_READABLE to retrieve the handle used for input, or TCL_WRITABLE to retrieve the handle used for output.

If the channel implementation has device-specific handles, the function should retrieve the appropriate handle associated with the channel, according the direction argument. The handle should be stored in the location referred to by handlePtr, and TCL_OK should be returned. If the channel is not open for the specified direction, or if the channel implementation does not use device handles, the function should return TCL_ERROR.

This value can be retrieved with Tcl_ChannelGetHandleProc, which returns a pointer to the function.

CLOSE2PROC

The close2Proc field contains the address of a procedure called by the generic layer to close the channel. It is called after the closeProc has been called. Close2Proc should match the following prototype:

typedef int Tcl_DriverClose2Proc(
        ClientData instanceData,
        Tcl_Interp *interp);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The procedure should perform any necessary cleanup for the channel and return 0 on success or an errno code (suitable for use with Tcl_SetErrno) on failure. If an error occurs, it should leave an error message in the interpreter's result.

This value can be retrieved with Tcl_ChannelClose2Proc, which returns a pointer to the function.

BLOCKMODEPROC

The blockModeProc field contains the address of a procedure called by the generic layer to set the blocking mode of the channel. BlockModeProc should match the following prototype:

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The mode argument is either TCL_BLOCKING or TCL_NONBLOCKING.

The procedure should set the blocking mode of the channel accordingly and return 0 on success or an errno code (suitable for use with Tcl_SetErrno) on failure.

This value can be retrieved with Tcl_ChannelBlockModeProc, which returns a pointer to the function.

FLUSHPROC

The flushProc field contains the address of a procedure called by the generic layer to flush the channel's output buffer. FlushProc should match the following prototype:

typedef int Tcl_DriverFlushProc(
        ClientData instanceData);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The procedure should write any buffered output data to the channel. It should return 0 on success or an errno code (suitable for use with Tcl_SetErrno) on failure.

This value can be retrieved with Tcl_ChannelFlushProc, which returns a pointer to the function.

HANDLERPROC

The handlerProc field contains the address of a function called by the generic layer to notify the channel that an event occurred. It should be defined for stacked channel drivers that wish to be notified of events that occur on the underlying (stacked) channel. HandlerProc should match the following prototype:

typedef int Tcl_DriverHandlerProc(
        ClientData instanceData,
        int interestMask);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The interestMask is an OR-ed combination of TCL_READABLE or TCL_WRITABLE; it indicates what type of event occurred on this channel.

This value can be retrieved with Tcl_ChannelHandlerProc, which returns a pointer to the function.

THREADACTIONPROC

The threadActionProc field contains the address of the function called by the generic layer when a channel is created, closed, or going to move to a different thread, i.e. whenever thread-specific driver state might have to initialized or updated. It can be NULL. The action TCL_CHANNEL_THREAD_REMOVE is used to notify the driver that it should update or remove any thread-specific data it might be maintaining for the channel.

The action TCL_CHANNEL_THREAD_INSERT is used to notify the driver that it should update or initialize any thread-specific data it might be maintaining using the calling thread as the associate. See Tcl_CutChannel and Tcl_SpliceChannel for more detail.

typedef void Tcl_DriverThreadActionProc(
        ClientData instanceData,
        int action);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created.

These values can be retrieved with Tcl_ChannelThreadActionProc, which returns a pointer to the function.

TRUNCATEPROC

The truncateProc field contains the address of the function called by the generic layer when a channel is truncated to some length. It can be NULL.

typedef int Tcl_DriverTruncateProc(
        ClientData instanceData,
        Tcl_WideInt length);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created, and length is the new length of the underlying file, which should not be negative. The result should be 0 on success or an errno code (suitable for use with Tcl_SetErrno) on failure.

These values can be retrieved with Tcl_ChannelTruncateProc, which returns a pointer to the function.

TCL_BADCHANNELOPTION

This procedure generates a “bad option” error message in an (optional) interpreter. It is used by channel drivers when an invalid Set/Get option is requested. Its purpose is to concatenate the generic options list to the specific ones and factorize the generic options error message string.

It always returns TCL_ERROR

An error message is generated in interp's result value to indicate that a command was invoked with a bad option. The message has the form

    bad option "blah": should be one of
    <...generic options...>+<...specific options...>
so you get for instance: 
    bad option "-blah": should be one of -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, or -sockname
when called with optionList equal to “peername sockname”

“blah” is the optionName argument and “<specific options>” is a space separated list of specific option words. The function takes good care of inserting minus signs before each option, commas after, and an “or” before the last option.

OLD CHANNEL TYPES

The original (8.3.1 and below) Tcl_ChannelType structure contains the following fields:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
} Tcl_ChannelType;

It is still possible to create channel with the above structure. The internal channel code will determine the version. It is imperative to use the new Tcl_ChannelType structure if you are creating a stacked channel driver, due to problems with the earlier stacked channel implementation (in 8.2.0 to 8.3.1).

Prior to 8.4.0 (i.e. during the later releases of 8.3 and early part of the 8.4 development cycle) the Tcl_ChannelType structure contained the following fields:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_ChannelTypeVersion version;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

When the above structure is registered as a channel type, the version field should always be TCL_CHANNEL_VERSION_2.
