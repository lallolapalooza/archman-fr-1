DESCRIPTION

Les objets sont des entités typées qui ont un ensemble d'opérations ("méthodes") associées. Les classes sont des objets qui peuvent fabriquer des objets. Chaque classe peut être vue comme un objet ; la vue objet peut être obtenue via Tcl_GetClassAsObject, qui renvoie toujours l'objet lorsqu'elle est appliquée à une classe non détruite, et un objet peut être vu comme une classe avec l'aide de Tcl_GetObjectAsClass (qui renvoie la classe, ou NULL si l'objet n'est pas une classe). Un objet peut être recherché via la fonction Tcl_GetObjectFromObj, qui renvoie un objet ou NULL (avec un message d'erreur dans le résultat de l'interpréteur) si l'objet ne peut être trouvé. La manière correcte de rechercher une classe par son nom est de rechercher l'objet portant ce nom, puis d'utiliser Tcl_GetObjectAsClass.

Chaque objet a sa propre commande et son propre espace de noms associés. La commande peut être obtenue via la fonction Tcl_GetObjectCommand, le nom de l'objet (et donc le nom de la commande) via Tcl_GetObjectName, et l'espace de noms peut être obtenu via la fonction Tcl_GetObjectNamespace. Note : la référence d'objet renvoyée par Tcl_GetObjectName est une référence partagée. Vous pouvez également vérifier si l'objet a été marqué pour suppression avec Tcl_ObjectDeleted (renvoie vrai si la suppression de l'objet a commencé) ; cela peut être utile pendant le traitement des méthodes.

Les instances de classes sont créées via Tcl_NewObjectInstance, qui crée un objet de n'importe quelle classe (et qui est appelée en interne par les méthodes create et new de la classe oo::class). Des paramètres sont donnés pour spécifier éventuellement le nom de l'objet et l'espace de noms à créer, et qui décrivent les arguments à passer au constructeur de la classe (s'il y en a un). Le résultat de la fonction sera une référence à la nouvelle instance d'objet, ou NULL si la création a échoué (auquel cas un message d'erreur sera laissé dans le résultat de l'interpréteur). De plus, les objets peuvent être copiés via Tcl_CopyObjectInstance, qui crée une copie de l'objet sans exécuter de constructeur.

Note : la gestion de la durée de vie des objets est gérée en interne par TclOO et n'utilise pas Tcl_Preserve. Il n'est pas sûr de placer un Tcl_Object dans une structure C dont la durée de vie est différente de celle de l'objet ; vous devriez utiliser le nom de commande de l'objet (tel qu'obtenu via Tcl_GetObjectName) à la place d'un pointeur vers Tcl_Object. Il est sûr d'utiliser un pointeur vers Tcl_Object pendant la durée d'un appel de méthode sur cet objet ; les pointeurs ne deviennent pas invalides tant qu'un appel de méthode est en cours sur leur objet (bien que la seule opération garantie sûre sur ceux-ci soit Tcl_ObjectDeleted ; les autres opérations garantissent seulement qu'elles fonctionnent sur des objets non détruits).

MÉTADONNÉES D'OBJET ET DE CLASSE

Chaque objet et chaque classe peuvent avoir un nombre arbitraire de métadonnées associées, dont l'objet ou la classe ne se soucie pas, sauf ce qui est décrit dans un instanciateur Tcl_ObjectMetadataType. Les métadonnées à ajouter sont décrites par le type des métadonnées (fourni dans l'argument metaTypePtr) et un pointeur arbitraire (l'argument metadata) qui sont passés à Tcl_ObjectSetMetadata et Tcl_ClassSetMetadata, et un certain fragment de métadonnées peut être récupéré étant donné son type via Tcl_ObjectGetMetadata et Tcl_ClassGetMetadata. Si le paramètre metadata de Tcl_ObjectSetMetadata ou Tcl_ClassSetMetadata est NULL, les métadonnées sont supprimées si elles étaient associées, et les résultats de Tcl_ObjectGetMetadata et Tcl_ClassGetMetadata seront NULL si le type de métadonnées donné n'était pas associé. Ce n'est pas une erreur de demander ou de supprimer un fragment de métadonnées qui n'est pas associé.

STRUCTURE TCL_OBJECTMETADATATYPE

Le contenu de la structure Tcl_ObjectMetadataType est le suivant :

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

Le champ version permet une extension future de la structure, et doit toujours être déclaré égal à TCL_OO_METADATA_VERSION_CURRENT. Le champ name fournit un nom lisible par l'homme pour le type, et est réservé à la débogage.

Le champ deleteProc donne un procédure de type Tcl_ObjectMetadataDeleteProc qui est utilisée pour supprimer un fragment de métadonnées, et est appelée lorsque les métadonnées associées sont remplacées ou supprimées ; le champ ne doit pas être NULL.

Le champ cloneProc donne une procédure qui est utilisée pour copier un fragment de métadonnées (utilisé lors de la création d'une copie d'un objet via Tcl_CopyObjectInstance) ; si NULL, les métadonnées seront simplement copiées directement.

Signature de fonction TCL_OBJECTMETADATADELETEPROC

Les fonctions correspondant à cette syntaxe sont utilisées pour supprimer les métadonnées associées à une classe ou un objet.

typedef void Tcl_ObjectMetadataDeleteProc(ClientData clientData);

L'argument clientData est le pointeur vers les métadonnées à supprimer.

Signature de fonction TCL_CLONEPROC

Les fonctions correspondant à cette syntaxe sont utilisées pour cloner des métadonnées lorsqu'un objet est copié.

typedef ClientData Tcl_CloneProc(ClientData clientData);

L'argument clientData est le pointeur vers les métadonnées à cloner. La fonction doit renvoyer un pointeur vers les métadonnées clonées, ou NULL si le clonage a échoué.

OBJET METHODE NOM MAPPING

Il est possible de contrôler, sur une base par objet, quelles méthodes sont appelées lorsqu'une méthode particulière est appelée. Normalement, cela se fait en recherchant le nom de la méthode dans l'objet, puis dans la hiérarchie des classes, mais un contrôle fin de la valeur exacte utilisée pour effectuer la recherche est offert grâce à la possibilité de définir une fonction de rappel de mappage de noms de méthodes via Tcl_ObjectSetMethodNameMapper (et son homologue d'introspection, Tcl_ObjectGetMethodNameMapper, qui renvoie le mappeur actuel). Le mappeur actuel (s'il y en a un) est appelé immédiatement avant de rechercher quelle chaîne d'implémentations de méthodes doit être utilisée.

SIGNATURE FONCTION TCL_OBJECTMAPMETHODNAMEPROC

La fonction de rappel Tcl_ObjectMapMethodNameProc est définie comme suit :

typedef int Tcl_ObjectMapMethodNameProc(
                        Tcl_Interp *interp,
                        Tcl_Object object,
                        Tcl_Class *startClsPtr,
                        Tcl_Obj *methodNameObj);

Si le résultat est TCL_OK, le remappage est supposé avoir été effectué. Si le résultat est TCL_ERROR, un message d'erreur aura été laissé dans interp et l'appel de méthode échouera. Si le résultat est TCL_BREAK, les règles de recherche de noms de méthodes standard seront utilisées ; le comportement des autres codes de résultat est actuellement indéfini. Le paramètre object indique quel objet est traité. Le paramètre startClsPtr pointe vers une variable contenant la première classe à fournir une définition dans la chaîne de méthodes à traiter, ou NULL si toute la chaîne doit être traitée (l'argument lui-même n'est jamais NULL) ; cette variable peut être mise à jour par la fonction de rappel. Le paramètre methodNameObj donne un objet non partagé contenant le nom de la méthode invoquée, tel que fourni par l'utilisateur ; cet objet peut être mis à jour par la fonction de rappel.
