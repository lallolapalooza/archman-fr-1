ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour le rapport d'erreurs et pour trouver un canal enregistré dans lui.
const char *fileName (in)
Le nom d'un fichier local ou distant.
const char *mode (in)
Indique comment le fichier est accédé. Peut prendre n'importe quelle valeur permise pour l'argument mode de la commande open de Tcl.
int permissions (in)
Flags de permissions POSIX comme 0644. Si un nouveau fichier est créé, ces permissions seront définies sur le fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour construire un pipeline de commandes. Ces valeurs ont la même signification que les arguments non --switch pour la commande exec de Tcl.
int flags (in)
Indique la disposition des handles standards dans le pipeline: combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE. Si TCL_STDIN est établi, le stdin du premier fils dans le pipeline est le canal de pipe, sinon c'est le même que le stdin du processus appelant; ainsi de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas établi, le pipeline peut rediriger les handles standards pour remplacer les handles standards ayant TCL_STDIN, TCL_STDOUT et TCL_STDERR établis. S'il est établi, alors une telle redirection provoque une erreur.
ClientData handle (in)
Un handle opérationnel spécifique à l'E/S vers un fichier. Pour Unix, c'est un descripteur de fichier, pour Windows c'est un HANDLE.
int readOrWrite (in)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Le pointeur vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et/ou en écriture.
const char *pattern (in)
Le motif à rechercher, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl pour l'entrée ou la sortie. Doit avoir été retourné par une procédure comme Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle seront stockés les caractères lus du canal. Si appendFlag est non nul, les données lues seront ajoutées à la valeur, sinon elles remplaceront le contenu existant.
int charsToRead (in)
Le nombre de caractères à lire du canal. Si le canal a un encodage binary, ceci est équivalent au nombre d'octets à lire du canal.
int appendFlag (in)
Si différent de zéro, les données lues du canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (out)
Un buffer dans lequel seront stockés les octets lus du canal.
int bytesToRead (in)
Le nombre d'octets à lire du canal. Le buffer readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle sera stockée la ligne lue du canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne Tcl dynamique dans laquelle sera stockée la ligne lue du canal. Elle doit avoir été initialisée par l'appelant. La ligne lue sera ajoutée aux données déjà présentes dans la chaîne.
const char *input (in)
L'entrée à ajouter à un buffer de canal.
int inputLen (in)
Longueur de l'entrée.
int addAtEnd (in)
Flag indiquant si l'entrée doit être ajoutée à la fin ou au début du buffer du canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera envoyé au canal.
const char *charBuf (in)
Un buffer contenant les caractères à envoyer au canal.
const char *byteBuf (in)
Un buffer contenant les octets à envoyer au canal.
int bytesToWrite (in)
Le nombre d'octets à consommer de charBuf ou byteBuf et à envoyer au canal.
Tcl_WideInt offset (in)
À quelle distance du point d'accès dans le canal la prochaine opération d'entrée ou de sortie sera appliquée, mesurée en octets à partir du point donné par seekMode. Peut être positif ou négatif.
int seekMode (in)
À quel point d'accès effectuer la recherche; utilisé avec offset pour calculer le nouveau point d'accès du canal. Les valeurs légales sont SEEK_SET, SEEK_CUR et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) à laquelle le canal sera tronqué.
const char *optionName (in)
Le nom d'une option applicable à ce canal, tel que -blocking. Peut prendre n'importe quelle valeur acceptée par la commande fconfigure.
Tcl_DString *optionValue (in)
Où la valeur d'une option ou une liste de toutes les options et leurs valeurs seront stockées. Doit avoir été initialisé par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canal de Tcl fournit un mécanisme indépendant de la plate-forme et des périphériques pour effectuer des opérations d'entrée/sortie bufferisées sur divers types de fichiers, sockets et périphériques. Le mécanisme de canal est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type; l'interface du pilote de canal est décrite dans la page de manuel de Tcl_CreateChannel. Le mécanisme de canal fournit une stratégie de bufferisation inspirée des E/S standards d'Unix, et permet également des opérations d'E/S non bloquantes sur les canaux.

Les procédures décrites dans cette page de manuel constituent les APIs de la couche générique capable de l'architecture de canal. Pour une description de l'architecture du pilote de canal et de la manière d'implémenter des pilotes de canal pour de nouveaux types de canaux, voir la page de manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

La procédure Tcl_OpenFileChannel ouvre un fichier indiqué par fileName en utilisant le mode spécifié par mode et les permissions spécifiées par permissions. Le champ mode est une chaîne de caractères qui peut avoir n'importe quelle valeur admise par la commande open de Tcl (par exemple, "r", "w", "a", "rb", "wb+", etc.). Le champ permissions est utilisé seulement quand un nouveau fichier est créé; il est ignoré sinon. La procédure retourne un handle de canal opaque utilisé pour accéder au fichier. Si une erreur se produit, Tcl_OpenFileChannel enregistre un message d'erreur dans l'interpréteur interp et retourne un canal NULL. Le handle de canal retourné peut être utilisé avec la plupart des autres procédures de canal de Tcl.

TCL_OPENCOMMANDCHANNEL

La procédure Tcl_OpenCommandChannel ouvre un pipeline de commandes. Les arguments argc et argv spécifient la commande et ses arguments, comme ils seraient spécifiés à la commande exec de Tcl. Le drapeau flags spécifie la disposition des handles standards dans le pipeline. Les options valides pour flags sont une combinaison OR des drapeaux TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE. Si TCL_STDIN est établi, le stdin du premier fils dans le pipeline est le canal de pipe retourné; sinon, c'est le même que le stdin du processus appelant. De même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas établi, le pipeline peut rediriger les handles standards pour remplacer les handles standards ayant TCL_STDIN, TCL_STDOUT et TCL_STDERR établis. Si TCL_ENFORCE_MODE est établi, alors une telle redirection provoque une erreur. La procédure retourne un handle de canal opaque utilisé pour accéder au pipeline. Si une erreur se produit, Tcl_OpenCommandChannel enregistre un message d'erreur dans l'interpréteur interp et retourne un canal NULL.

TCL_MAKEFILECHANNEL

La procédure Tcl_MakeFileChannel prend un handle de fichier existant (par exemple, un descripteur de fichier Unix ou un HANDLE Windows) et le transforme en un canal Tcl. Le paramètre readOrWrite est une combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont permises sur le handle. La procédure retourne un handle de canal opaque qui peut être utilisé avec les autres procédures de canal Tcl.

TCL_GETCHANNEL

La procédure Tcl_GetChannel retourne un handle de canal Tcl correspondant au nom channelName. Si modePtr est non NULL, il est défini sur une combinaison OR des drapeaux TCL_READABLE et TCL_WRITABLE pour indiquer si le canal est ouvert en lecture et/ou en écriture. Si une erreur se produit, un message d'erreur est enregistré dans l'interpréteur interp et la procédure retourne NULL.

TCL_GETCHANNELNAMES

La procédure Tcl_GetChannelNames retourne une liste de tous les noms de canaux actuellement enregistrés dans l'interpréteur interp sous forme de chaîne Tcl. La liste est stockée dans la variable résultat de l'interpréteur. Si un motif pattern est fourni à Tcl_GetChannelNamesEx, seules les noms de canaux correspondant au motif sont retournés.

TCL_REGISTERCHANNEL

La procédure Tcl_RegisterChannel enregistre un canal donné avec l'interpréteur interp. Le canal doit avoir été créé précédemment par une procédure comme Tcl_OpenFileChannel ou Tcl_MakeFileChannel. Une fois enregistré, le canal peut être référencé par son nom dans les commandes Tcl.

TCL_UNREGISTERCHANNEL

La procédure Tcl_UnregisterChannel désenregistre un canal donné de l'interpréteur interp. Le canal doit avoir été précédemment enregistré. Après désenregistrement, le canal ne peut plus être référencé par son nom. La procédure retourne 1 en cas de succès, et 0 en cas d'erreur (par exemple, si le canal n'était pas enregistré).

TCL_DETACHCHANNEL

La procédure Tcl_DetachChannel sépare le canal donné de l'interpréteur interp. Cela supprime le nom du canal de la table des noms de canaux de l'interpréteur, mais le canal lui-même n'est pas fermé. Le canal peut toujours être utilisé par son handle Tcl. Cela est utile lorsque vous voulez passer un canal à un autre processus Tcl ou à un autre thread sans avoir à le recréer.

TCL_ISTANDARDCHANNEL

La procédure Tcl_IsStandardChannel retourne 1 si le canal donné est l'un des canaux standards (stdin, stdout, stderr) du processus Tcl, et 0 sinon.

TCL_CLOSE

La procédure Tcl_Close ferme le canal donné. Toutes les données bufferisées en attente sont écrites, et les ressources associées au canal sont libérées. La procédure retourne 1 en cas de succès, et 0 en cas d'erreur.

TCL_READCHARS

La procédure Tcl_ReadChars lit jusqu'à charsToRead caractères du canal channel et les stocke dans l'objet Tcl pointé par readObjPtr. Si appendFlag est non nul, les caractères lus sont ajoutés à la fin de l'objet; sinon, ils remplacent le contenu existant de l'objet. La procédure retourne le nombre de caractères réellement lus. Si une erreur se produit ou si la fin du fichier est atteinte, la procédure retourne un code d'erreur ou le nombre de caractères lus jusqu'à ce point.

TCL_READ

La procédure Tcl_Read lit jusqu'à bytesToRead octets du canal channel et les stocke dans le buffer readBuf. La procédure retourne le nombre d'octets réellement lus. Si une erreur se produit ou si la fin du fichier est atteinte, la procédure retourne un code d'erreur ou le nombre d'octets lus jusqu'à ce point.

TCL_GETSOBJ

La procédure Tcl_GetsObj lit une ligne entière du canal channel (jusqu'à un caractère de nouvelle ligne, qui est inclus dans la ligne lue) et la stocke dans l'objet Tcl pointé par lineObjPtr. La ligne lue est ajoutée à la valeur actuelle de l'objet. La procédure retourne le nombre de caractères lus. Si la fin du fichier est atteinte avant la lecture d'une ligne complète, la procédure retourne un code d'erreur ou le nombre de caractères lus jusqu'à ce point.

TCL_GETS

La procédure Tcl_Gets lit une ligne entière du canal channel (jusqu'à un caractère de nouvelle ligne, qui est inclus dans la ligne lue) et l'ajoute à la chaîne Tcl dynamique pointée par lineRead. La procédure retourne le nombre de caractères lus. Si la fin du fichier est atteinte avant la lecture d'une ligne complète, la procédure retourne un code d'erreur ou le nombre de caractères lus jusqu'à ce point.

TCL_UNGETS

La procédure Tcl_Ungets place les données spécifiées par input et inputLen dans le buffer d'entrée du canal channel. Si addAtEnd est non nul, les données sont ajoutées à la fin du buffer d'entrée; sinon, elles sont ajoutées au début. Cela est utile pour réintroduire des données qui ont été lues mais qui devraient être traitées plus tard.

TCL_WRITEOBJ

La procédure Tcl_WriteObj écrit le contenu de l'objet Tcl pointé par writeObjPtr dans le canal channel. La procédure retourne le nombre d'octets réellement écrits. Si une erreur se produit, la procédure retourne un code d'erreur ou le nombre d'octets écrits jusqu'à ce point.

TCL_WRITECHARS

La procédure Tcl_WriteChars écrit les caractères du buffer charBuf dans le canal channel. Le nombre d'octets à écrire est spécifié par bytesToWrite. La procédure retourne le nombre d'octets réellement écrits. Si une erreur se produit, la procédure retourne un code d'erreur ou le nombre d'octets écrits jusqu'à ce point.

TCL_WRITE

La procédure Tcl_Write écrit les octets du buffer byteBuf dans le canal channel. Le nombre d'octets à écrire est spécifié par bytesToWrite. La procédure retourne le nombre d'octets réellement écrits. Si une erreur se produit, la procédure retourne un code d'erreur ou le nombre d'octets écrits jusqu'à ce point.

TCL_READRAW

La procédure Tcl_ReadRaw est identique à Tcl_Read, sauf qu'elle lit des octets bruts sans aucune conversion d'encodage. Elle est utile pour lire des données binaires.

TCL_WRITERAW

La procédure Tcl_WriteRaw est identique à Tcl_Write, sauf qu'elle écrit des octets bruts sans aucune conversion d'encodage. Elle est utile pour écrire des données binaires.

TCL_EOF

La procédure Tcl_Eof retourne 1 si la fin du fichier a été atteinte sur le canal donné, et 0 sinon.

TCL_FLUSH

La procédure Tcl_Flush force l'écriture de toutes les données bufferisées en attente dans le canal donné. C'est utile pour s'assurer que les données sont envoyées immédiatement, par exemple avant de fermer un canal ou d'attendre une réponse d'un autre processus.

TCL_INPUTBLOCKED

La procédure Tcl_InputBlocked retourne 1 si le canal donné est en mode blocage et qu'une tentative de lecture échouerait immédiatement (c'est-à-dire, s'il n'y a pas de données disponibles), et 0 sinon. Pour les canaux non bloquants, cela retourne toujours 0.

TCL_INPUTBUFFERED

La procédure Tcl_InputBuffered retourne le nombre d'octets qui sont actuellement dans le buffer d'entrée du canal donné et qui n'ont pas encore été lus par l'application.

TCL_OUTPUTBUFFERED

La procédure Tcl_OutputBuffered retourne le nombre d'octets qui sont actuellement dans le buffer de sortie du canal donné et qui n'ont pas encore été écrits sur le périphérique sous-jacent.

TCL_SEEK

La procédure Tcl_Seek change la position actuelle du canal donné. Le nouveau décalage est calculé en ajoutant offset octets au point d'accès spécifié par seekMode. seekMode peut être SEEK_SET (décalage par rapport au début du fichier), SEEK_CUR (décalage par rapport à la position actuelle) ou SEEK_END (décalage par rapport à la fin du fichier). La procédure retourne le nouveau décalage du canal, ou -1 en cas d'erreur.

TCL_TELL

La procédure Tcl_Tell retourne la position actuelle du canal donné, mesurée en octets à partir du début du fichier.

TCL_TRUNCATECHANNEL

La procédure Tcl_TruncateChannel tronque le canal donné à la longueur spécifiée par length. Si le canal est plus long que length, les données excédentaires sont supprimées. Si le canal est plus court que length, il est étendu avec des zéros (ou des caractères nuls). La procédure retourne 0 en cas de succès, et -1 en cas d'erreur.

TCL_GETCHANNELOPTION

La procédure Tcl_GetChannelOption obtient la valeur de l'option spécifiée par optionName pour le canal donné. La valeur est stockée dans la chaîne Tcl dynamique pointée par optionValue. Si optionName est NULL, toutes les options et leurs valeurs sont retournées sous forme de liste de paires clé-valeur.

TCL_SETCHANNELOPTION

La procédure Tcl_SetChannelOption définit la valeur de l'option spécifiée par optionName pour le canal donné à la nouvelle valeur newValue. Les options disponibles sont les mêmes que celles acceptées par la commande fconfigure.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et renvoie un handle de canal qui peut être utilisé pour lire et écrire dans le fichier. Cette API est calquée sur la fonction fopen de la bibliothèque d'entrée/sortie standard Unix. La syntaxe et la signification de tous les arguments sont similaires à ceux donnés dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel renvoie et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas , Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. À partir de Tcl 8.4, l'API basée sur les valeurs Tcl_FSOpenFileChannel doit être préférée à Tcl_OpenFileChannel lorsque cela est possible.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, il faut utiliser Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplaçant du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Elle crée une séquence de processus subsidiaires spécifiés par les arguments argv et argc et renvoie un canal qui peut être utilisé pour communiquer avec ces processus subsidiaires. L'argument flags indique le type de communication que vous aurez avec la séquence de commandes.

Si le drapeau TCL_STDIN est défini, le canal d'entrée standard du premier processus subsidiaire est lié au canal : écrire dans le canal fournit une entrée au processus subsidiaire. Si TCL_STDIN n'est pas défini, le canal d'entrée standard du premier processus subsidiaire sera le même que le canal d'entrée de cette application. Si TCL_STDOUT est défini, la sortie standard de la dernière sous-séquence peut être lue depuis le canal ; sinon, elle est dirigée vers la sortie standard de cette application. Si TCL_STDERR est défini, la sortie d'erreur standard de tous les processus subsidiaires est renvoyée au canal et génère une erreur lors de sa fermeture ; sinon, elle est dirigée vers la sortie d'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas défini, argc et argv peuvent rediriger les descripteurs standards pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, c'est une erreur pour argc et argv de rediriger les canaux standards pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel renvoie et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être .

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, il faut utiliser Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplaçant du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un handle de fichier existant et spécifique à la plateforme. Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, il faut utiliser Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplaçant du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel renvoie un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur dans interp. S'il n'y a pas de canal enregistré sous ce nom dans l'interpréteur, la procédure renvoie . Si l'argument modePtr n'est pas , il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms selon le pattern. Si pattern est , aucun filtrage ne sera effectué. La valeur de retour est TCL_OK s'il n'y a pas d'erreur lors de l'écriture dans le résultat, sinon TCL_ERROR et le message d'erreur reste dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal aux canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur pourront faire référence au canal en utilisant le nom donné dans l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera automatiquement fermé lorsqu'il sera déconnecté de l'interpréteur.

Le code exécuté en dehors de tout interpréteur peut appeler Tcl_RegisterChannel avec interp comme , indiquant qu'il souhaite conserver une référence à ce canal. Ultérieurement, le canal peut être enregistré dans un interpréteur et ne sera fermé que lorsque autant d'appels à Tcl_UnregisterChannel que nécessaire auront été effectués. Cela permet au code non associé à un interpréteur de conserver une référence sûre à un canal qui est également enregistré dans un interpréteur.

Cette procédure interagit avec le code qui gère les canaux standards. Si aucun canal standard n'est initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un aperçu des canaux standards et du comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel supprime un canal des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Si cette opération supprime le dernier enregistrement du canal dans un interpréteur, le canal sera également fermé et détruit.

Le code non associé à un interpréteur peut appeler Tcl_UnregisterChannel avec interp comme , indiquant à Tcl qu'il n'a plus de références à ce canal. S'il s'agit de la dernière référence, il sera fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel, sauf qu'il fermera également le canal s'il n'y a plus de références restantes.

TCL_DETACHCHANNEL

Tcl_DetachChannel supprime un canal des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour y faire référence dans cet interpréteur. Au-delà de cela, cette commande n'a pas d'effet supplémentaire. Elle ne peut pas être utilisée sur les canaux standards (stdout, stderr, stdin) et renverra TCL_ERROR si elle est appelée avec l'un d'eux.

Le code non associé à un interpréteur peut appeler Tcl_DetachChannel avec interp comme , indiquant à Tcl qu'il n'a plus de références à ce canal. S'il s'agit de la dernière référence, comme dans Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel vérifie si un canal est l'un des trois canaux standards, stdin, stdout ou stderr. Si c'est le cas, il renvoie 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standards sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit faire référence à un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lorsque Tcl_Close est appelé. Le buffer de sortie est vidé avant de détruire le canal, et toute entrée mise en tampon est rejetée. Si ce canal est bloquant, l'appel ne retourne pas tant que toutes les données mises en tampon n'ont pas été envoyées au périphérique de sortie du canal. Si ce canal est non bloquant et qu'il y a des données mises en tampon qui ne peuvent pas être écrites sans bloquer, l'appel retourne immédiatement ; les données sont envoyées en arrière-plan et le canal est fermé lorsque toutes les données mises en tampon ont été envoyées. Dans ce cas, les erreurs lors du vidage ne sont pas rapportées.

Si le canal a été fermé avec succès, Tcl_Close renvoie TCL_OK. Si une erreur se produit, Tcl_Close renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas , un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré avec Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez utiliser Tcl_UnregisterChannel, qui appelle Tcl_Close en interne lorsque tous les appels à Tcl_RegisterChannel ont été correspondus par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS AND TCL_READ

Tcl_ReadChars consomme des octets du channel, les convertissant en UTF-8 selon l'encodage du canal et stocke les données produites dans la représentation de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit pendant la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_READCHARS, TCL_READOBJ, AND TCL_READ

Tcl_ReadChars lee hasta charsToRead caracteres de entrada del canal especificado por channel y los almacena en la representación de cadena del objeto Tcl denotado por readObjPtr. Si charsToRead es un valor negativo, esto se interpreta como un valor de Tcl_EvalFile(3). -1 hará que el comando lea todos los caracteres actualmente disponibles (modo no bloqueante) o todos hasta el eof (modo bloqueante).

El valor de retorno puede ser menor que el valor a leer, indicando que menos datos de los solicitados estuvieron disponibles. Esto se llama una lectura corta. En modo bloqueante, esto solo puede ocurrir al final del archivo. En modo no bloqueante, una lectura corta también puede ocurrir si no hay entrada actual: Tcl_ReadChars devuelve un conteo corto en lugar de esperar más datos.

Si el canal está en modo bloqueante, un valor de retorno de cero indica una condición de fin de archivo. Si el canal está en modo no bloqueante, un valor de retorno de cero indica que no hay entrada actual o una condición de fin de archivo. Use Tcl_Eof y Tcl_InputBlocked para determinar cuál de estas condiciones realmente ocurrió.

Tcl_ReadChars traduce las diversas representaciones de fin de línea a la representación canónica interna \n según el modo actual de reconocimiento de fin de línea. El reconocimiento de fin de línea y los diversos modos específicos de plataforma se describen en el manual de la instrucción Tcl fconfigure.

Como optimización de rendimiento, al leer de un canal con la codificación binary, los bytes no se convierten a UTF-8 al leerse. En su lugar, se almacenan en la representación interna de readObjPtr como un valor de array de bytes. La representación de cadena de este valor solo se construye si es necesaria (por ejemplo, debido a una llamada a Tcl_GetStringFromObj). De esta manera, los datos orientados a bytes se pueden leer de un canal, manipular con Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribir en un canal sin el costo de convertir a o desde UTF-8.

Tcl_Read es similar a Tcl_ReadChars, excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para la compatibilidad con extensiones de Tcl no internacionalizadas. Consumió bytes de channel y los almacenó en readBuf, realizando traducciones de fin de línea en el camino. El valor de retorno de Tcl_Read es el número de bytes, hasta bytesToRead, escritos en readBuf. El búfer producido por Tcl_Read no está terminado en nulo. Sus contenidos son válidos desde la posición cero hasta, y excluyendo, la posición indicada por el valor de retorno.

Tcl_ReadRaw es lo mismo que Tcl_Read pero no compensa el puro. Aunque Tcl_Read (y otras funciones de la API) obtienen sus datos del canal superior en la pila de canales, Tcl_ReadRaw no lo hace. Por lo tanto, esta función solo es utilizable para drivers de canal transformadores, es decir, los drivers utilizados en medio de una pila de canales para mover datos del canal inferior hacia el transformador.

TCL_GETSOBJ Y TCL_GETS

Tcl_GetsObj consume bytes del channel, convirtiéndolos a UTF-8 según la codificación del canal, hasta que se haya visto una línea completa de entrada. Si la codificación del canal es binary, cada byte leído del canal se trata como un carácter Unicode individual. Todos los caracteres de la línea excepto los caracteres de fin de línea finales se agregan a la representación de cadena de lineObjPtr. Los caracteres de fin de línea se leen y descartan.

Si se leyó una línea con éxito, el valor de retorno es mayor o igual a cero e indica el número de bytes almacenados en lineObjPtr. Si ocurre un error, Tcl_GetsObj devuelve -1 y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Tcl_GetsObj también devuelve -1 si se ha alcanzado el final del archivo; el procedimiento Tcl_Eof puede usarse para diferenciar un error de una condición de fin de archivo.

Si el canal está en modo no bloqueante, el valor de retorno también puede ser -1 si no hay datos disponibles o si los datos disponibles no contienen un carácter de fin de línea. Cuando se devuelve -1, el procedimiento Tcl_InputBlocked puede invocarse para determinar si el canal está bloqueado debido a la ausencia de entrada.

Tcl_Gets es lo mismo que Tcl_GetsObj excepto que los caracteres resultantes se agregan a la cadena dinámica dada por lineRead en lugar de a un valor Tcl.

TCL_UNGETS

Tcl_Ungets se utiliza para agregar datos a la cola de entrada de un canal, al principio o al final de la cola. El puntero input apunta a los datos a agregar. El tamaño de los datos a agregar se indica con inputLen. Un valor distinto de cero de addAtEnd indica que los datos se agregarán al final de la cola; de lo contrario, se agregarán al principio de la cola. Si channel tiene un EOF pegajoso establecido, no se agregarán datos a la cola de entrada. Tcl_Ungets devuelve inputLen o -1 si ocurre un error.

TCL_WRITECHARS, TCL_WRITEOBJ, Y TCL_WRITE

Tcl_WriteChars acepta bytesToWrite bytes de datos de caracteres en charBuf. Los caracteres UTF-8 en el búfer se convierten a la codificación del canal y se ponen en cola para su salida al channel. Si bytesToWrite es negativo, Tcl_WriteChars espera que charBuf termine en nulo y emite todo hasta el nulo.

Los datos puestos en cola para su salida pueden no aparecer inmediatamente en el dispositivo de salida debido al almacenamiento en búfer interno. Si los datos deben aparecer inmediatamente, use Tcl_Flush después de llamar a Tcl_WriteChars, o establezca la opción -buffering en none en el canal. Si desea que los datos aparezcan tan pronto como se acepte una línea completa para la salida, establezca la opción -buffering en modo line.

El valor de retorno de Tcl_WriteChars es el número de bytes aceptados para la salida al canal. Esto es mayor que cero para indicar éxito o -1 para indicar un error. Si ocurre un error, Tcl_WriteChars registra un código de error POSIX que se puede recuperar con Tcl_GetErrno.

Los caracteres de nueva línea en los datos de salida se traducen a secuencias de fin de línea específicas de la plataforma según la opción -translation del canal. Esto se hace incluso si el canal no tiene codificación.

Tcl_WriteObj es similar a Tcl_WriteChars, excepto que acepta un valor Tcl cuyo contenido se emite al canal. Los caracteres UTF-8 en la representación de cadena de writeObjPtr se convierten a la codificación del canal y se ponen en cola para su salida al channel. Como optimización de rendimiento, al escribir en un canal con la codificación binary, los caracteres UTF-8 no se convierten al escribir. En su lugar, los bytes en la representación interna de writeObjPtr como un valor de array de bytes se escriben al canal. La representación de array de bytes del valor se construye si es necesario. De esta manera, los datos orientados a bytes se pueden leer de un canal, manipular con Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribir en un canal sin el costo de convertir a o desde UTF-8.

Tcl_Write es similar a Tcl_WriteChars, excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para la compatibilidad con extensiones de Tcl no internacionalizadas. Acepta bytesToWrite bytes de datos en byteBuf y los pone en cola para su salida al channel. Si bytesToWrite es negativo, Tcl_Write espera que byteBuf termine en nulo y emite todo hasta el nulo.

Tcl_WriteRaw es lo mismo que Tcl_Write, pero no compensa el puro. Aunque Tcl_Write (y otras funciones de la API) envían sus datos al canal superior en la pila de canales, Tcl_WriteRaw no lo hace. Por lo tanto, esta función solo es utilizable para drivers de canal transformadores, es decir, los drivers utilizados en medio de una pila de canales para mover datos del canal inferior hacia el transformador.

TCL_FLUSH

Tcl_Flush hace que todos los datos de salida almacenados en búfer para channel se escriban en su dispositivo o archivo subyacente lo antes posible. Si el canal está en modo bloqueante, la llamada no retorna hasta que todos los datos en búfer se hayan enviado al canal o ocurra un error. La llamada retorna inmediatamente si el canal está en modo no bloqueante; inicia un vaciado en segundo plano que escribirá los datos en búfer al canal eventualmente, tan rápido como el canal pueda absorberlos.

El valor de retorno es normalmente TCL_OK. Si ocurre un error, Tcl_Flush devuelve TCL_ERROR y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno.

TCL_SEEK

Tcl_Seek mueve el punto de acceso en channel donde se leerán o escribirán los próximos datos. Los datos de salida en búfer se escriben al canal y los datos de entrada en búfer se descartan antes de la operación de búsqueda.

Tcl_Seek normalmente devuelve el nuevo punto de acceso. Si ocurre un error, Tcl_Seek devuelve -1 y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Después de un error, el punto de acceso puede o no haber sido movido.

TCL_TELL

Tcl_Tell devuelve el punto de acceso actual para un canal. El valor devuelto es -1 si el canal no admite la búsqueda.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel trunca el archivo subyacente de channel a una longitud dada en bytes. Devuelve TCL_OK si la operación fue exitosa, y TCL_ERROR de lo contrario.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption retrieves the value of an option optionName for a channel channel. The value is returned as a Tcl string in the interpreter's result. The channel driver is responsible for converting the internal option value to a string. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and leaves an error message in the interpreter's result.

The various preexisting options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and calls Tcl_SetErrno to store an appropriate POSIX error code.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
