ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour le rapport d'erreurs et pour rechercher un canal enregistré dans celui-ci.
const char *fileName (in)
Le nom d'un fichier local ou en réseau.
const char *mode (in)
Indique comment le fichier est accédé. Peut avoir n'importe quelle valeur autorisée pour l'argument mode de la commande open de Tcl.
int permissions (in)
Flags de permissions POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront définies sur le fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour construire un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans switch de la commande exec de Tcl.
int flags (in)
Indique la disposition des handles standards dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, le stdin du premier enfant dans le pipeline est le canal du pipeline, sinon il est le même que le stdin du processus appelant ; de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, le pipeline peut rediriger les handles standards pour écraser les handles standards pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, de telles redirections provoquent une erreur.
ClientData handle (in)
Le handle opérationnel spécifique pour les E/S vers un fichier. Pour Unix c'est un descripteur de fichier, pour Windows c'est un HANDLE.
int readOrWrite (in)
OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Le pointeur vers une valeur entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (in)
Le motif à rechercher, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl pour l'entrée ou la sortie. Il doit avoir été la valeur de retour d'une procédure comme Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle seront stockés les caractères lus du canal.
int charsToRead (in)
Le nombre de caractères à lire du canal. Si l'en-tête du canal est en mode binary, c'est équivalent au nombre d'octets à lire du canal.
int appendFlag (in)
Si non nul, les données lues du canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (out)
Un buffer dans lequel seront stockés les octets lus du canal.
int bytesToRead (in)
Le nombre d'octets à lire du canal. Le buffer readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle sera stockée la ligne lue du canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne dynamique Tcl dans laquelle sera stockée la ligne lue du canal. Elle doit avoir été initialisée par l'appelant. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne dynamique.
const char *input (in)
L'entrée à ajouter à un buffer de canal.
int inputLen (in)
Longueur de l'entrée.
int addAtEnd (in)
Flag indiquant si l'entrée est ajoutée à la fin ou au début du buffer de canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera écrit dans le canal.
const char *charBuf (in)
Un buffer contenant les caractères à écrire dans le canal.
const char *byteBuf (in)
Un buffer contenant les octets à écrire dans le canal.
int bytesToWrite (in)
Le nombre d'octets à consommer de charBuf ou byteBuf et à écrire dans le canal.
Tcl_WideInt offset (in)
De combien d'octets le point d'accès dans le canal est-il déplacé pour la prochaine opération d'entrée ou de sortie ? Il est mesuré à partir de la position donnée par seekMode. Il peut être positif ou négatif.
int seekMode (in)
À partir d'où chercher ? Utilisé avec offset pour calculer le nouveau point d'accès du canal. Les valeurs valides sont SEEK_SET, SEEK_CUR et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) à laquelle le canal doit être tronqué.
const char *optionName (in)
Le nom d'une option applicable à ce canal, tel que -blocking. Peut avoir toute valeur acceptée par la commande fconfigure.
Tcl_DString *optionValue (in)
Où stocker la valeur d'une option ou une liste de toutes les options et leurs valeurs. Doit avoir été initialisé par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un moyen indépendant du périphérique et de la plateforme pour effectuer des opérations d'entrée/sortie bufferisées sur divers types de fichiers, sockets et périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux en fournissant un pilote de canal pour le nouveau type ; l'interface du pilote de canal est décrite dans la page de manuel de Tcl_CreateChannel. Le mécanisme de canaux fournit un schéma de bufferisation similaire aux E/S standards d'Unix et permet également des opérations d'E/S non bloquantes sur les canaux.

Les procédures décrites dans ce manuel constituent l'API C du niveau général de l'architecture des canaux. Pour une description de l'architecture des pilotes de canal et de la manière d'implémenter des pilotes de canal pour de nouveaux types de canaux, consultez la page de manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Ouvre un canal de type fichier et le retourne. Le canal est créé en utilisant le nom de fichier fileName, le mode mode et les permissions permissions. Les valeurs de mode et permissions ont la même signification que les arguments du même nom de la commande Tcl open. La procédure retourne un nouveau handle de canal Tcl ou NULL si une erreur se produit. L'erreur est signalée dans le champ result de l'interpréteur Tcl.

TCL_OPENCOMMANDCHANNEL

Crée un pipeline de processus. La commande argv est exécutée et la connexion entre le processus appelant et le pipeline est établie via les handles standards spécifiés dans flags. Les handles standards sont stdin, stdout, stderr. Il peut y avoir jusqu'à trois canaux retournés, un pour stdin, un pour stdout et un pour stderr, qui sont enregistrés dans l'interpréteur. Si une erreur se produit, NULL est retourné et l'erreur est signalée dans l'interpréteur.

TCL_MAKEFILECHANNEL

Crée un canal Tcl à partir d'un handle de fichier existant. Le handle de fichier handle est soit un descripteur de fichier Unix, soit un HANDLE Windows. L'argument readOrWrite est un OR bit à bit des drapeaux TCL_READABLE et TCL_WRITABLE pour indiquer si le canal doit être ouvert pour la lecture et/ou l'écriture.

TCL_GETCHANNEL

Retourne un handle vers le canal nommé channelName enregistré dans l'interpréteur interp. Si modePtr n'est pas NULL, il est défini sur une combinaison OR des drapeaux TCL_READABLE et TCL_WRITABLE pour indiquer si le canal est ouvert en lecture et/ou en écriture.

TCL_GETCHANNELNAMES

Remplit le champ result de l'interpréteur interp avec une liste de tous les noms de canaux enregistrés dans l'interpréteur. Les canaux standards (stdin, stdout, stderr) sont inclus.

TCL_GETCHANNELNAMESEX

Remplit le champ result de l'interpréteur interp avec une liste de tous les noms de canaux enregistrés dans l'interpréteur qui correspondent au pattern spécifié. Si pattern est NULL, cela fonctionne comme Tcl_GetChannelNames.

TCL_REGISTERCHANNEL

Enregistre le canal channel avec l'interpréteur interp. Le nom du canal est obtenu à partir des informations d'en-tête du canal. Une fois enregistré, le canal peut être référencé par son nom dans les commandes Tcl.

TCL_UNREGISTERCHANNEL

Désenregistre le canal channel de l'interpréteur interp. Le canal sera également fermé s'il n'a pas été détaché. Si le canal a été ouvert par Tcl_OpenFileChannel, cette procédure le fermera automatiquement, libérant ainsi toutes les ressources associées. Si le canal a été créé à l'aide de Tcl_MakeFileChannel, cette procédure ne fera que le désenregistrer ; le descripteur de fichier sous-jacent ne sera pas fermé.

TCL_DETACHCHANNEL

Détache le canal channel de l'interpréteur interp. Cela empêche Tcl_UnregisterChannel de fermer le canal. Il est ainsi possible de gérer le handle de fichier sous-jacent séparément.

TCL_ISTANDARDCHANNEL

Retourne 1 si le canal channel est un des canaux standards (stdin, stdout, stderr), 0 sinon.

TCL_CLOSE

Ferme le canal channel associé à l'interpréteur interp. Si le canal est associé à un descripteur de fichier ou à un handle de système d'exploitation, ces ressources sont également libérées. Si une erreur se produit, la procédure retourne EOF (-1).

TCL_READCHARS

Lit jusqu'à charsToRead caractères du canal channel et les stocke dans le buffer associé à readObjPtr. Si appendFlag est non nul, les caractères sont ajoutés à la fin de la valeur existante ; sinon, ils la remplacent. La procédure retourne le nombre de caractères lus, ou un code d'erreur en cas d'échec.

TCL_READ

Lit jusqu'à bytesToRead octets du canal channel et les stocke dans le buffer readBuf. La procédure retourne le nombre d'octets lus, ou un code d'erreur en cas d'échec.

TCL_GETSOBJ

Lit une ligne du canal channel (jusqu'à un caractère de nouvelle ligne, qui est consommé mais non stocké) et stocke la ligne dans l'objet lineObjPtr. La ligne est ajoutée à la valeur existante de l'objet. La procédure retourne le nombre d'octets lus, ou un code d'erreur en cas d'échec.

TCL_GETS

Lit une ligne du canal channel (jusqu'à un caractère de nouvelle ligne, qui est consommé mais non stocké) et la stocke dans le buffer lineRead. La ligne est ajoutée à toute donnée déjà présente dans lineRead. La procédure retourne le nombre d'octets lus, ou un code d'erreur en cas d'échec.

TCL_UNGETS

Insère les données input de longueur inputLen dans le buffer d'entrée du canal channel. Si addAtEnd est nul, l'entrée est insérée au début du buffer; sinon, elle est ajoutée à la fin.

TCL_WRITEOBJ

Écrit le contenu de l'objet writeObjPtr dans le canal channel. La procédure retourne le nombre d'octets écrits, ou un code d'erreur en cas d'échec.

TCL_WRITECHARS

Écrit les caractères du buffer charBuf dans le canal channel. Le nombre d'octets à écrire est spécifié par bytesToWrite. La procédure retourne le nombre d'octets écrits, ou un code d'erreur en cas d'échec.

TCL_WRITE

Écrit les octets du buffer byteBuf dans le canal channel. Le nombre d'octets à écrire est spécifié par bytesToWrite. La procédure retourne le nombre d'octets écrits, ou un code d'erreur en cas d'échec.

TCL_READRAW

Lit jusqu'à bytesToRead octets du canal channel et les stocke dans le buffer readBuf. Contrairement à Tcl_Read, cette procédure ne fait aucune conversion de fin de ligne et lit les données exactement telles qu'elles sont fournies par le système d'exploitation. La procédure retourne le nombre d'octets lus, ou un code d'erreur en cas d'échec.

TCL_WRITERAW

Écrit les octets du buffer byteBuf dans le canal channel. Contrairement à Tcl_Write, cette procédure n'effectue aucune conversion de fin de ligne et écrit les données telles quelles dans le système d'exploitation. Le nombre d'octets à écrire est spécifié par bytesToWrite. La procédure retourne le nombre d'octets écrits, ou un code d'erreur en cas d'échec.

TCL_EOF

Retourne 1 si la fin du fichier a été atteinte pour le canal channel, 0 sinon.

TCL_FLUSH

Force l'écriture de toutes les données bufferisées dans le canal channel. Ceci est utile pour s'assurer que toutes les données sont envoyées au périphérique sous-jacent, par exemple avant de fermer le canal ou d'attendre une réponse d'un processus externe.

TCL_INPUTBLOCKED

Retourne 1 si la dernière opération de lecture sur le canal channel a été bloquée (c'est-à-dire qu'aucune donnée n'était disponible), 0 sinon. Ceci est principalement utile pour les canaux configurés en mode non bloquant.

TCL_INPUTBUFFERED

Retourne le nombre d'octets actuellement en attente dans le buffer d'entrée du canal channel.

TCL_OUTPUTBUFFERED

Retourne le nombre d'octets actuellement en attente dans le buffer de sortie du canal channel.

TCL_SEEK

Change la position actuelle du canal channel. Le décalage est donné par offset et seekMode spécifie le point de départ du décalage. Les valeurs valides pour seekMode sont SEEK_SET (début du fichier), SEEK_CUR (position actuelle) et SEEK_END (fin du fichier). La procédure retourne la nouvelle position du canal en octets, ou -1 en cas d'erreur.

TCL_TELL

Retourne la position actuelle du canal channel en octets.

TCL_TRUNCATECHANNEL

Tronque le canal channel à la longueur spécifiée par length. Si length est plus petit que la taille actuelle du canal, les données excédentaires sont perdues. Si length est plus grand, le comportement dépend du système d'exploitation, mais généralement, le canal est rempli de zéros.

TCL_GETCHANNELOPTION

Récupère la valeur de l'option optionName pour le canal channel et la stocke dans le DString optionValue. L'argument interp est utilisé pour signaler les erreurs.

TCL_SETCHANNELOPTION

Définit la valeur de l'option optionName pour le canal channel à newValue. L'argument interp est utilisé pour signaler les erreurs.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et renvoie un descripteur de canal pouvant être utilisé pour lire et écrire dans le fichier. Cette API est calquée sur la procédure fopen de la bibliothèque d'entrée/sortie standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel renvoie et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. À partir de Tcl 8.4, l'API basée sur les valeurs Tcl_FSOpenFileChannel doit être préférée à Tcl_OpenFileChannel dans tous les cas.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'assigne également comme substitut du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Il crée une chaîne de processus séquentiels spécifiés par les arguments argv et argc et renvoie un canal qui peut être utilisé pour communiquer avec ces processus séquentiels. L'argument flags indique quel type de communication aura lieu avec la chaîne de commandes.

Si l'indicateur TCL_STDIN est défini, le canal d'entrée standard du premier processus séquentiel sera lié au canal : écrire dans le canal fournira l'entrée au processus séquentiel. Si l'indicateur TCL_STDIN n'est pas défini, le canal d'entrée standard du premier processus séquentiel sera le même que le canal d'entrée standard de cette application. Si l'indicateur TCL_STDOUT est défini, la sortie standard de la dernière sous-séquence peut être lue depuis le canal ; sinon, elle est envoyée à la sortie standard de cette application. Si l'indicateur TCL_STDERR est défini, la sortie d'erreur standard de tous les processus séquentiels est renvoyée au canal et provoque une erreur lors de la fermeture du canal ; sinon, elle est envoyée à la sortie d'erreur standard de cette application. Si l'indicateur TCL_ENFORCE_MODE n'est pas défini, argc et argv peuvent rediriger les descripteurs d'entrée/sortie standard pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, il est erroné que argc et argv puissent rediriger les canaux d'entrée/sortie standard pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel renvoie et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'assigne également comme substitut du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un descripteur de fichier existant, spécifiquement du système d'exploitation. Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'assigne également comme substitut du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel renvoie un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur dans interp. Si aucun canal enregistré dans cet interpréteur avec ce nom n'existe, la procédure renvoie NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE, indiquant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtre ces noms selon le pattern. Si pattern est NULL, aucun filtrage n'est effectué. La valeur de retour est TCL_OK s'il n'y a eu aucune erreur lors de l'écriture dans le résultat, sinon c'est TCL_ERROR et le message d'erreur est conservé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à la liste des canaux accessibles dans interp. Après cet appel, les programmes exécutant dans cet interpréteur peuvent faire référence au canal par le nom donné dans l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur et l'utilisateur ne doit pas appeler Tcl_Close pour le canal ; le canal est automatiquement fermé lorsqu'il est désenregistré de l'interpréteur.

Le code exécutant en dehors de tout interpréteur peut appeler Tcl_RegisterChannel avec interp comme NULL, indiquant qu'il souhaite conserver une référence à ce canal. Après cela, le canal peut être enregistré dans un interpréteur et ne sera fermé que lorsqu'un nombre d'appels à Tcl_UnregisterChannel correspondant aura été effectué. Cela permet au code exécutant en dehors de tout interpréteur de conserver une référence sûre à un canal qui est également enregistré dans un interpréteur.

Cette procédure interagit avec le code qui gère les canaux standard. Si aucun canal standard n'est initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés avec cet appel. Voir Tcl_StandardChannels pour un aperçu des canaux standard et du comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel supprime un canal de la liste des canaux accessibles dans interp. Après cet appel, les programmes ne pourront plus faire référence au canal par son nom dans cet interpréteur. Si cette opération a supprimé la dernière inscription du canal dans un interpréteur, le canal sera également fermé et détruit.

Le code non associé à un interpréteur peut appeler Tcl_UnregisterChannel avec interp comme NULL, indiquant à Tcl qu'il ne conserve plus de référence à ce canal. S'il s'agit de la dernière référence à ce canal, il sera fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel, sauf qu'il ferme également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel supprime un canal de la liste des canaux accessibles dans interp. Après cet appel, les programmes ne pourront plus faire référence au canal par son nom dans cet interpréteur. En attendant, cette commande n'a aucun autre effet. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin) et renverra TCL_ERROR si elle est appelée avec l'un de ces canaux.

Le code non associé à un interpréteur peut appeler Tcl_DetachChannel avec interp comme NULL, indiquant à Tcl qu'il ne conserve plus de référence à ce canal. S'il s'agit de la dernière référence à ce canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel vérifie si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. S'il l'est, il renvoie 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit représenter un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lors de l'appel à Tcl_Close. Les données de sortie tamponnées sont évacuées vers le périphérique de sortie du canal avant d'être détruites, et toutes les données d'entrée tamponnées sont ignorées. Si le canal est bloquant, l'appel ne renvoie pas tant que toutes les données tamponnées n'ont pas été correctement envoyées au périphérique de sortie du canal. Si le canal n'est pas bloquant et qu'il y a des données de sortie tamponnées qui ne peuvent pas être écrites sans blocage, l'appel renvoie immédiatement ; les données sont envoyées en arrière-plan et le canal est fermé lorsque toutes les données tamponnées ont été envoyées. Dans ce cas, les erreurs lors du nettoyage ne sont pas signalées.

Si le canal est fermé avec succès, Tcl_Close renvoie TCL_OK. Si une erreur se produit, Tcl_Close renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est conservé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré en utilisant Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devez utiliser Tcl_UnregisterChannel, qui appelle en interne Tcl_Close lorsque tous les appels à Tcl_RegisterChannel ont été mis en correspondance par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, les convertit en UTF-8 selon l'encodage du canal et stocke les données produites dans la représentation de readObjPtr. La valeur renvoyée par Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit lors de la lecture, la valeur renvoyée est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

La valeur de charsToRe

TCL_READCHARS

La spécification d'une valeur de -1 pour bytesToRead amènera la commande à lire tous les caractères actuellement disponibles (mode non bloquant) ou tout jusqu'à la fin du fichier (mode bloquant).

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé était disponible. Ceci est appelé une lecture courte. En mode bloquant, cela ne peut se produire qu'à la fin du fichier. En mode non bloquant, une lecture courte peut également se produire s'il n'y a pas suffisamment d'entrée actuellement disponible : Tcl_ReadChars renvoie un nombre réduit plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour déterminer laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les diverses représentations de fin de ligne en la représentation interne canonique \n conformément au mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les divers modes spécifiques à la plateforme sont décrits dans la page de manuel de la commande Tcl fconfigure.

En guise d'optimisation des performances, lors de la lecture d'un canal avec le codage binary, les octets ne sont pas convertis en UTF-8 lorsqu'ils sont lus. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr sous forme de tableau d'octets. La représentation en chaîne de caractères de cette valeur ne sera construite que si elle est nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette manière, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de la conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'il n'effectue pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour des raisons de compatibilité ascendante avec les extensions Tcl non internationalisées. Il consomme des octets du channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par un caractère nul. Son contenu est valide à partir de la position zéro jusqu'à, mais sans inclure, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas l'empilement. Alors que Tcl_Read (et les autres fonctions de l'API) obtiennent toujours leurs données du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_ReadRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données du canal inférieur dans la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, en convertissant les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée soit vue. Si l'encodage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception des caractères de fin de ligne terminaux, sont ajoutés à la représentation en chaîne de caractères de lineObjPtr. Les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. En cas d'erreur, Tcl_GetsObj renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj renvoie également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est renvoyé, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité de l'entrée.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique donnée par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, à la tête ou à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si channel a un indicateur EOF “collant” défini, aucune donnée ne sera ajoutée à la file d'entrée. Tcl_Ungets renvoie inputLen ou -1 si une erreur se produit.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données de caractères à charBuf. Les caractères UTF-8 dans le tampon sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par un caractère nul et il sort tout jusqu'au nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal à none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un nombre indiquant combien d'octets ont été acceptés pour la sortie vers le canal. Il s'agit soit d'une valeur supérieure à zéro pour indiquer le succès, soit de -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme conformément à l'option -translation pour le canal. Ceci est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'il accepte une valeur Tcl dont le contenu sera sorti vers le canal. Les caractères UTF-8 dans la représentation en chaîne de caractères de writeObjPtr sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. En tant qu'optimisation des performances, lors de l'écriture dans un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets dans la représentation interne de writeObjPtr sous forme de tableau d'octets sont écrits dans le canal. La représentation en tableau d'octets de la valeur sera construite si nécessaire. De cette manière, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de la conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'il n'effectue pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour des raisons de compatibilité ascendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par un caractère nul et il sort tout jusqu'au nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée dans le canal le plus haut de la pile dont fait partie le canal fourni, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation dans le canal inférieur.

TCL_FLUSH

Tcl_Flush provoque l'écriture de toutes les données de sortie tamponnées pour channel dans son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données tamponnées n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal est en mode non bloquant ; il démarre une purge en arrière-plan qui écrira les données tamponnées dans le canal éventuellement, aussi rapidement que le canal est capable de les absorber.

La valeur de retour est normalement TCL_OK. En cas d'erreur, Tcl_Flush renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données ultérieures seront lues ou écrites. La sortie tamponnée est vidée vers le canal et l'entrée tamponnée est rejetée, avant l'opération de recherche.

Tcl_Seek renvoie normalement le nouveau point d'accès. En cas d'erreur, Tcl_Seek renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut avoir été déplacé ou non.

TCL_TELL

Tcl_Tell renvoie le point d'accès actuel pour un canal. La valeur renvoyée est -1 si le canal ne prend pas en charge la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent de channel à une longueur donnée de length octets. Il renvoie TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, c'est le nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue.

en utilisant une série d'appels à Tcl_DStringAppendElement. Les différentes options préexistantes et leurs valeurs possibles sont décrites dans la page de manuel de la commande Tcl fconfigure. D'autres options peuvent être ajoutées par chaque type de canal. Ces options spécifiques au type de canal sont décrites dans la page de manuel de la commande Tcl qui crée un canal de ce type ; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans la page de manuel de la commande Tcl socket. La procédure renvoie normalement TCL_OK. Si une erreur se produit, elle renvoie TCL_ERROR et appelle Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit une nouvelle valeur newValue pour une option optionName sur channel. La procédure renvoie normalement TCL_OK. Si une erreur se produit, elle renvoie TCL_ERROR ; de plus, si interp est non NULL, Tcl_SetChannelOption laisse un message d'erreur dans le résultat de l'interpréteur.

TCL_EOF

Tcl_Eof renvoie une valeur non nulle si channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked renvoie une valeur non nulle si channel est en mode non bloquant et que la dernière opération d'entrée a renvoyé moins de données que demandé car il n'y avait pas assez de données disponibles. L'appel renvoie toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered renvoie le nombre d'octets d'entrée actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en lecture, cette fonction renvoie toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered renvoie le nombre d'octets de sortie actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en écriture, cette fonction renvoie toujours zéro.

PROBLÈMES DE PLATEFORME

Les descripteurs renvoyés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que renvoyé par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel, ou Tcl_MakeFileChannel. D'autres types de canaux peuvent renvoyer un type différent de descripteur sur les plateformes Windows.
