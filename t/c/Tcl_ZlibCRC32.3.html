ARGUMENTS

Tcl_Interp *interp (entree)
L'interpréteur dans lequel stocker les données compressées ou décompressées résultantes. C'est aussi là que les messages d'erreur sont écrits. Pour Tcl_ZlibStreamInit, cela peut être NULL pour créer un flux qui n'est pas lié à une commande.
int format (entree)
Quel format de données compressées traiter. Doit être l'un des TCL_ZLIB_FORMAT_ZLIB pour les données au format zlib, TCL_ZLIB_FORMAT_GZIP pour les données au format gzip, ou TCL_ZLIB_FORMAT_RAW pour les données compressées brutes. De plus, pour la décompression uniquement, TCL_ZLIB_FORMAT_AUTO peut également être choisi, ce qui permet de détecter automatiquement si les données compressées étaient au format zlib ou gzip.
Tcl_Obj *dataObj (entree/sortie)
Une valeur de tableau d'octets contenant les données à compresser ou décompresser, ou à laquelle les données extraites du flux sont ajoutées lors du passage à Tcl_ZlibStreamGet.
int level (entree)
Quel niveau de compression utiliser. Doit être un nombre de 0 à 9 ou l'un des suivants : TCL_ZLIB_COMPRESS_NONE pour aucune compression, TCL_ZLIB_COMPRESS_FAST pour une compression rapide mais inefficace, TCL_ZLIB_COMPRESS_BEST pour une compression lente mais maximale, ou TCL_ZLIB_COMPRESS_DEFAULT pour le niveau recommandé par la bibliothèque zlib.
Tcl_Obj *dictObj (entree/sortie)
Un dictionnaire qui contient, ou qui sera mis à jour pour contenir, une description de l'en-tête gzip associé aux données compressées. Utile uniquement lorsque le paramètre format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Si NULL est passé, un en-tête par défaut sera utilisé lors de la compression et l'en-tête sera ignoré (hormis les vérifications d'intégrité) lors de la décompression. Voir la section DICTIONNAIRE DES OPTIONS GZIP pour plus de détails sur le contenu de ce dictionnaire.
unsigned int initValue (entree)
La valeur initiale pour l'algorithme de somme de contrôle.
int bufferSize (entree)
Un indice quant à la taille du tampon à utiliser pour recevoir les données. Utilisez 0 pour utiliser une estimation générique basée sur les données d'entrée.
unsigned char *bytes (entree)
Un tableau d'octets sur lequel exécuter l'algorithme de somme de contrôle, ou NULL pour obtenir la valeur initiale recommandée pour l'algorithme de somme de contrôle.
int length (entree)
Le nombre d'octets dans le tableau.
int mode (entree)
Quel mode utiliser pour le flux. Doit être soit TCL_ZLIB_STREAM_DEFLATE pour un flux de compression, soit TCL_ZLIB_STREAM_INFLATE pour un flux de décompression.
Tcl_ZlibStream *zshandlePtr (sortie)
Un pointeur vers une variable dans laquelle écrire le jeton abstrait du flux en cas de succès de création.
Tcl_ZlibStream zshandle (entree)
Le jeton abstrait du flux à opérer.
int flush (entree)
Si et comment vider le flux après y avoir écrit les données. Doit être l'un des : TCL_ZLIB_NO_FLUSH si aucun vidage ne doit être effectué, TCL_ZLIB_FLUSH si les données actuellement compressées doivent être rendues disponibles pour un accès via Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si le flux doit être mis dans un état tel que le décompresseur puisse récupérer en cas de corruption, ou TCL_ZLIB_FINALIZE pour s'assurer que le flux est terminé et que toute bande-annonce demandée par le format est écrite.
int count (entree)
Le nombre maximum d'octets à obtenir du flux, ou -1 pour obtenir tous les octets restants des tampons du flux.
Tcl_Obj *compDict (entree)
Une valeur de tableau d'octets représentant le dictionnaire de compression à utiliser avec le flux. Notez qu'il ne s'agit *pas d'un dictionnaire Tcl*, et il est recommandé de ne l'utiliser qu'avec des flux dont le format est défini sur TCL_ZLIB_FORMAT_ZLIB, car les autres formats n'ont aucun mécanisme pour indiquer si un dictionnaire de compression était présent, sauf en échouant lors de la décompression.

DESCRIPTION

Ces fonctions constituent l'interface de la bibliothèque Tcl à la bibliothèque Zlib de Jean-loup Gailly et Mark Adler.

Tcl_ZlibDeflate et Tcl_ZlibInflate respectivement compressent et décompressent les données contenues dans l'argument dataObj, conformément aux arguments format et, pour la compression, level. Le dictionnaire dans le paramètre dictObj est utilisé pour transmettre des informations d'en-tête supplémentaires sur les données compressées lorsque le format de compression le prend en charge ; actuellement, le dictionnaire n'est utilisé que lorsque le paramètre format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Pour plus de détails sur le contenu du dictionnaire, voir la section DICTIONNAIRE DES OPTIONS GZIP ci-dessous. En cas de succès, les deux fonctions laissent les données compressées ou décompressées résultantes dans une valeur de tableau d'octets qui est le résultat de l'interpréteur Tcl ; la valeur retournée est un code de résultat Tcl standard.

Tcl_ZlibAdler32 et Tcl_ZlibCRC32 calculent des sommes de contrôle sur des tableaux d'octets, retournant la somme de contrôle calculée. Les sommes de contrôle sont calculées de manière incrémentale, permettant de traiter les données bloc par bloc, mais cela nécessite à l'appelant de maintenir la somme de contrôle actuelle et de la passer comme paramètre initValue ; la valeur initiale à utiliser pour cela peut être obtenue en utilisant NULL pour le paramètre bytes au lieu d'un pointeur vers le tableau d'octets sur lequel calculer la somme de contrôle. Ainsi, l'utilisation typique dans le cas d'un seul bloc de données ressemble à ceci :

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Notez que l'algorithme Adler-32 n'est pas une véritable somme de contrôle, mais plutôt un type de hachage apparenté qui fonctionne mieux sur des données plus longues.

FLUX ZLIB

Tcl_ZlibStreamInit crée un flux de compression ou de décompression qui est lié à une commande Tcl, conformément à ses arguments, et fournit un jeton abstrait pour le flux et retourne un code de résultat Tcl normal ; Tcl_ZlibStreamGetCommandName retourne le nom de cette commande étant donné le jeton du flux, ou NULL si le flux n'a pas de commande. Les flux ne sont pas conçus pour être thread-safe ; chaque flux ne devrait jamais être utilisé qu'à partir du thread qui l'a créé. Lors de l'utilisation de flux gzip, un dictionnaire (champs tels que donnés dans la section DICTIONNAIRE DES OPTIONS GZIP ci-dessous) peut être fourni via le paramètre dictObj qui, lors de la compression, permet de contrôler les en-têtes générés, et lors de la décompression, permet la découverte des en-têtes existants. Notez que le dictionnaire sera écrit lors de la décompression une fois que suffisamment de données auront été lues pour avoir un en-tête complet. Cela signifie que le dictionnaire doit être une valeur non partagée dans ce cas ; une valeur vide créée avec Tcl_NewObj est suggérée.

Une fois qu'un flux a été construit, Tcl_ZlibStreamPut est utilisé pour ajouter des données au flux et Tcl_ZlibStreamGet est utilisé pour récupérer des données du flux après traitement. Les deux retournent des codes de résultat Tcl normaux et laissent un message d'erreur dans le résultat de l'interpréteur auquel le flux est enregistré en cas d'erreur (si une telle enregistrement a été effectuée). Avec Tcl_ZlibStreamPut, la valeur du tampon de données qui lui est passé ne doit pas être modifiée par la suite. Avec Tcl_ZlibStreamGet, la valeur du tampon de données qui lui est passé aura les octets de données ajoutés. Interne au flux, les données sont conservées compressées afin de minimiser le coût de l'espace tampon.

DESCRIPTION

OPTIONS GZIP DICTIONNAIRE

Le paramètre dictObj de Tcl_ZlibDeflate, Tcl_ZlibInflate et Tcl_ZlibStreamInit est utilisé pour passer un dictionnaire d'options qui est utilisé pour décrire l'en-tête gzip dans les données compressées. Lors de la création des données compressées, le dictionnaire est lu et lors de la décompression des données compressées, le dictionnaire est écrit (dans ce cas, le paramètre dictObj doit faire référence à une valeur non partagée).

Les champs suivants dans la valeur du dictionnaire sont compris. Tous les autres champs sont ignorés. Aucun champ n'est requis lors de la création d'un flux au format gzip.

comment
Ce champ stocke le commentaire de l'en-tête, s'il est présent. S'il n'est pas présent, aucun commentaire n'a été fourni (en décompression) ou il sera créé (en compression).
crc
Une valeur booléenne décrivant si un CRC de l'en-tête est calculé. Note : le programme gzip n'utilise ni ne permet un CRC dans l'en-tête.
filename
Le nom du fichier qui contenait les données non compressées. Celui-ci ne doit pas contenir de séparateurs de répertoire et doit être nettoyé avant d'être utilisé en décompression avec file tail.
os
Le code du type de système d'exploitation de l'en-tête (s'il ne s'agit pas de la valeur inconnue). Voir RFC 1952 pour la signification de ces codes. En compression, s'il n'est pas présent, le champ sera défini sur la valeur inconnue.
size
La taille des données non compressées. Ceci est ignoré en compression ; la taille des données compressées dépend du volume de données fourni au moteur de compression.
time
Le champ de temps de l'en-tête s'il n'est pas nul, attendu pour être le moment où le fichier nommé par le champ filename a été modifié. Il convient de l'utiliser avec le format clock. Lors de la création, la valeur correcte à utiliser est celle de clock seconds ou file mtime.
type
Le type des données non compressées (c'est-à-dire binary ou text) si il est connu.

NOTES DE PORTABILITÉ

Ces fonctions se comporteront gracieusement si Tcl n'est pas lié à la bibliothèque zlib.
