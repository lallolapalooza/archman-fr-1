ARGUMENTS

const char *bytes (in)
Pointe vers le premier octet d'un tableau d'octets encodés en UTF-8 utilisé pour définir ou ajouter à une valeur de chaîne de caractères. Ce tableau d'octets peut contenir des caractères nuls intégrés, sauf si numChars est négatif. (Les applications ayant besoin de caractères nuls devraient les représenter comme la séquence de deux octets \300\200, utiliser Tcl_ExternalToUtf pour la conversion, ou Tcl_NewByteArrayObj si la chaîne est une collection d'octets non interprétés.)
int length (in)
Le nombre d'octets à copier de bytes lors de l'initialisation, de la définition ou de l'ajout à une valeur de chaîne de caractères. Si négatif, tous les octets jusqu'au premier caractère nul sont utilisés.
const Tcl_UniChar *unicode (in)
Pointe vers le premier octet d'un tableau de caractères Unicode utilisé pour définir ou ajouter à une valeur de chaîne de caractères. Ce tableau d'octets peut contenir des caractères nuls intégrés, sauf si numChars est négatif.
int numChars (in)
Le nombre de caractères Unicode à copier de unicode lors de l'initialisation, de la définition ou de l'ajout à une valeur de chaîne de caractères. Si négatif, tous les caractères jusqu'au premier caractère nul sont utilisés.
int index (in)
L'index du caractère Unicode à retourner.
int first (in)
L'index du premier caractère Unicode dans la plage Unicode à retourner sous forme de nouvelle valeur.
int last (in)
L'index du dernier caractère Unicode dans la plage Unicode à retourner sous forme de nouvelle valeur.
Tcl_Obj *objPtr (in/out)
Pointe vers une valeur à manipuler.
Tcl_Obj *appendObjPtr (in)
La valeur à ajouter à objPtr dans Tcl_AppendObjToObj.
int *lengthPtr (out)
Si non NULL, l'emplacement où Tcl_GetStringFromObj stockera la longueur de la représentation en chaîne de caractères de la valeur.
const char *string (in)
Valeur de chaîne de caractères terminée par un caractère nul à ajouter à objPtr.
va_list argList (in)
Une liste d'arguments qui doit avoir été initialisée à l'aide de va_start, et effacée à l'aide de va_end.
int limit (in)
Nombre maximum d'octets à ajouter.

Suffixe à ajouter lorsque la limite entraîne une troncature de la chaîne. Si NULL est passé, le suffixe “...” est utilisé.

DESCRIPTION

Les procédures décrites dans cette entrée de manuel permettent de manipuler les valeurs Tcl comme des chaînes de caractères. Elles utilisent la représentation interne de la valeur pour stocker des informations supplémentaires afin de rendre les manipulations de chaînes de caractères plus efficaces. En particulier, elles rendent efficaces une série d'opérations d'ajout en allouant un espace de stockage supplémentaire pour la chaîne afin qu'elle n'ait pas à être copiée à chaque ajout. De plus, les calculs d'indexation et de longueur sont optimisés car la représentation en chaîne Unicode est calculée et mise en cache au besoin. Lors de l'utilisation de la famille de fonctions Tcl_Append* où le résultat de l'interpréteur est la valeur à laquelle on ajoute, il est important d'appeler d'abord Tcl_ResetResult pour s'assurer que vous n'ajoutez pas involontairement à des données existantes dans la valeur résultante.

Tcl_NewStringObj et Tcl_SetStringObj créent une nouvelle valeur ou modifient une valeur existante pour contenir une copie de la chaîne fournie par bytes et length. Tcl_NewUnicodeObj et Tcl_SetUnicodeObj créent une nouvelle valeur ou modifient une valeur existante pour contenir une copie de la chaîne Unicode fournie par unicode et numChars. Tcl_NewStringObj et Tcl_NewUnicodeObj retournent un pointeur vers une valeur nouvellement créée avec un compteur de références à zéro. Les quatre procédures définissent la valeur pour contenir une copie de la chaîne spécifiée. Tcl_SetStringObj et Tcl_SetUnicodeObj libèrent toute ancienne représentation de chaîne ainsi que toute ancienne représentation interne de la valeur.

Tcl_GetStringFromObj et Tcl_GetString retournent la représentation en chaîne d'une valeur. Ceci est fourni par le pointeur retourné et (pour Tcl_GetStringFromObj) la longueur, qui est stockée dans lengthPtr si celui-ci n'est pas NULL. Si la représentation en chaîne UTF de la valeur est invalide (son pointeur d'octets est NULL), la représentation en chaîne est régénérée à partir de la représentation interne de la valeur. Le stockage référencé par le pointeur retourné appartient au gestionnaire de valeur. Il est transmis comme un pointeur modifiable afin que l'auteur d'extension créant son propre Tcl_ObjType puisse modifier la représentation en chaîne dans le cadre de Tcl_UpdateStringProc de son Tcl_ObjType. Sauf pour ce but limité, le pointeur retourné par Tcl_GetStringFromObj ou Tcl_GetString doit être traité comme en lecture seule. Il est recommandé que ce pointeur soit assigné à une variable (const char *). Même dans les situations limitées où la modification de ce pointeur est acceptable, il faut prendre soin de respecter les sémantiques de copie sur écriture requises par Tcl_Obj, avec des appels appropriés à Tcl_IsShared et Tcl_DuplicateObj avant toute modification en place de la représentation en chaîne. La procédure Tcl_GetString est utilisée dans le cas courant où l'appelant n'a pas besoin de la longueur de la représentation en chaîne.

Tcl_GetUnicodeFromObj et Tcl_GetUnicode retournent la valeur d'une valeur sous forme de chaîne Unicode. Ceci est fourni par le pointeur retourné et (pour Tcl_GetUnicodeFromObj) la longueur, qui est stockée dans lengthPtr si celui-ci n'est pas NULL. Le stockage référencé par le pointeur retourné appartient au gestionnaire de valeur et ne doit pas être modifié par l'appelant. La procédure Tcl_GetUnicode est utilisée dans le cas courant où l'appelant n'a pas besoin de la longueur de la représentation en chaîne unicode.

Tcl_GetUniChar retourne le caractère d'index index dans la représentation Unicode de la valeur. L'index est supposé être dans la plage appropriée.

Tcl_GetRange retourne une valeur nouvellement créée composée des caractères entre first et last (inclus) dans la représentation Unicode de la valeur. Si la représentation Unicode de la valeur est invalide, la représentation Unicode est régénérée à partir de la représentation en chaîne de la valeur. Si first < 0, alors la chaîne retournée commence au début de la valeur. Si last < 0, alors la chaîne retournée se termine à la fin de la valeur.

DESCRIPTION

The Tcl object system provides a way to store values in memory using different internal representations. It is the responsibility of the Tcl interpreter to manage the creation and destruction of these objects and to provide mechanisms for converting between representations. This document describes the procedures which are used to create and manipulate objects.

Tcl_NewStringObj creates a new Tcl object whose internal representation is a string. If string is not NULL, the object is initialized with a copy of the string. If length is "-1", then the length of the string is computed using strlen. Otherwise, length specifies the number of bytes in string to copy. The object is returned with a reference count of zero.

Tcl_NewUnicodeObj creates a new Tcl object whose internal representation is Unicode. The object is initialized with a copy of the Unicode string given by unicode and numChars. The object is returned with a reference count of zero.

Tcl_NewByteArrayObj creates a new Tcl object whose internal representation is a byte array. The object is initialized with a copy of the bytes given by bytes and length. The object is returned with a reference count of zero.

Tcl_NewBooleanObj creates a new Tcl object whose internal representation is a boolean. The object is initialized to boolValue.

Tcl_NewDoubleObj creates a new Tcl object whose internal representation is a double-precision floating-point number. The object is initialized to doubleValue.

Tcl_NewIntObj creates a new Tcl object whose internal representation is a signed 32-bit integer. The object is initialized to intValue.

Tcl_NewLongObj creates a new Tcl object whose internal representation is a signed 64-bit integer. The object is initialized to longValue.

Tcl_NewObj creates a new Tcl object with no internal representation. Such objects typically are used as temporary storage during the construction of other objects, or as placeholders for object values that have not yet been computed.

Tcl_DuplicateObj creates a new Tcl object that is a copy of the object specified by objPtr. The new object has a reference count of zero.

Tcl_FreeObj decrements the reference count for objPtr. If the reference count becomes zero, the memory associated with the object is freed.

Tcl_InvalidateStringRep discards the string representation for objPtr. This forces the string representation to be regenerated the next time it is needed.

Tcl_StringCaseMatch returns 1 if string1 matches string2 using case-insensitive matching, and 0 otherwise. This is the same matching rule as used by the Tcl string match command when the comparison is case-insensitive.

Tcl_GetBooleanFromObj attempts to convert the value in objPtr to a boolean value (0 or 1). If successful, the value is stored in the location pointed to by boolPtr and the function returns TCL_OK. Otherwise, an error message is left in interp and the function returns TCL_ERROR. The value may be any of the following case-insensitive values: true, false, yes, no, on, off, 1, or 0.

Tcl_GetByteArrayFromObj converts the value in objPtr to a byte array representation. If the conversion is successful, the function returns a pointer to the first byte of the array and stores the number of bytes in the array at the location pointed to by lengthPtr. If the object does not have a byte array representation, the string representation of the object is converted to bytes and used as the byte array. If the conversion fails, an error message is left in interp and the function returns NULL.

Tcl_GetDoubleFromObj attempts to convert the value in objPtr to a double-precision floating-point number. If successful, the value is stored in the location pointed to by doublePtr and the function returns TCL_OK. Otherwise, an error message is left in interp and the function returns TCL_ERROR.

Tcl_GetIntFromObj attempts to convert the value in objPtr to a signed 32-bit integer. If successful, the value is stored in the location pointed to by intPtr and the function returns TCL_OK. Otherwise, an error message is left in interp and the function returns TCL_ERROR.

Tcl_GetLongFromObj attempts to convert the value in objPtr to a signed 64-bit integer. If successful, the value is stored in the location pointed to by longPtr and the function returns TCL_OK. Otherwise, an error message is left in interp and the function returns TCL_ERROR.

Tcl_GetString returns a pointer to the string representation of objPtr. The caller must not modify the contents of the returned string. The string representation is guaranteed to be valid only until objPtr is next modified. If the object does not currently have a string representation, one will be created. Note that this function returns the length of the string as a side effect.

Tcl_GetStringFromObj returns a pointer to the string representation of objPtr and stores the length of the string in the location pointed to by lengthPtr. The caller must not modify the contents of the returned string. The string representation is guaranteed to be valid only until objPtr is next modified. If the object does not currently have a string representation, one will be created.

Tcl_GetObjType returns a pointer to the type information for the object objPtr, or NULL if the object has no type.

Tcl_SetObjLength changes the length of the string representation of objPtr to newLength. If newLength is greater than the allocated space for the string, the space is reallocated and the old value is copied to the new space. The bytes between the old length and newLength may contain arbitrary values. If newLength is less than the current length of the string, the string length is reduced without reallocating the space. In all cases, a null character is placed at the end of the new string.

Tcl_AppendToObj appends the data given by bytes and length to the string representation of the value specified by objPtr. If the value has an invalid string representation, then an attempt is made to convert bytes to the Unicode format. If the conversion is successful, then the converted form of bytes is appended to the value's Unicode representation. Otherwise, the value's Unicode representation is invalidated and converted to the UTF format, and bytes is appended to the value's new string representation. Eventually buffer growth is done by large allocations to optimize multiple calls.

Tcl_AppendUnicodeToObj appends the Unicode string given by unicode and numChars to the value specified by objPtr. If the value has an invalid Unicode representation, then unicode is converted to the UTF format and appended to the value's string representation. Appends are optimized to handle repeated appends relatively efficiently (it over-allocates the string or Unicode space to avoid repeated reallocations and copies of value's string value).

Tcl_AppendObjToObj is similar to Tcl_AppendToObj, but it appends the string or Unicode value (whichever exists and is best suited to be appended to objPtr) of appendObjPtr to objPtr.

Tcl_AppendStringsToObj is similar to Tcl_AppendToObj except that it can be passed more than one value to append and each value must be a null-terminated string (i.e. none of the values may contain internal null characters). Any number of string arguments may be provided, but the last argument must be (char *)NULL to indicate the end of the list.

Tcl_AppendStringsToObjVA is the same as Tcl_AppendStringsToObj except that instead of taking a variable number of arguments it takes an argument list.

Tcl_AppendLimitedToObj is similar to Tcl_AppendToObj except that it imposes a limit on how many bytes are appended. This can be handy when the string to be appended might be very large, but the value being constructed should not be allowed to grow without bound. A common usage is when constructing an error message, where the end result should be kept short enough to be read. Bytes from bytes are appended to objPtr, but no more than limit bytes total are to be appended. If the limit prevents all length bytes that are available from being appended, then the appending is done so that the last bytes appended are from the string ellipsis. This allows for an indication of the truncation to be left in the string. When length is -1, all bytes up to the first zero byte are appended, subject to the limit. When ellipsis is NULL, the default string ... is used. When ellipsis is non-NULL, it must point to a zero-byte-terminated string in Tcl's internal UTF encoding. The number of bytes appended can be less than the lesser of length and limit when appending fewer bytes is necessary to append only whole multi-byte characters.

Tcl_Format is the C-level interface to the engine of the format command. The actual command procedure for format is little more than

Tcl_Format(interp, Tcl_GetString(objv[1]), objc-2, objv+2);

The objc Tcl_Obj values in objv are formatted into a string according to the conversion specification in format argument, following the documentation for the format command. The resulting formatted string is converted to a new Tcl_Obj with refcount of zero and returned. If some error happens during production of the formatted string, NULL is returned, and an error message is recorded in interp, if interp is non-NULL.

Tcl_AppendFormatToObj is an appending alternative form of Tcl_Format with functionality equivalent to:

Tcl_Obj *newPtr = Tcl_Format(interp, format, objc, objv);
if (newPtr == NULL) return TCL_ERROR;
Tcl_AppendObjToObj(objPtr, newPtr);
Tcl_DecrRefCount(newPtr);
return TCL_OK;

but with greater convenience and efficiency when the appending functionality is needed.

Tcl_ObjPrintf serves as a replacement for the common sequence

char buf[SOME_SUITABLE_LENGTH];
sprintf(buf, format, ...);
Tcl_NewStringObj(buf, -1);

but with greater convenience and no need to determine SOME_SUITABLE_LENGTH. The formatting is done with the same core formatting engine used by Tcl_Format. This means the set of supported conversion specifiers is that of the format command but the behavior is as similar as possible to sprintf. Format specifiers which were added by C99 (like "hh", "ll", "j", "z", "t", "L") are not supported. When a conversion specifier passed to Tcl_ObjPrintf includes a precision, the value is taken as a number of bytes, as sprintf does, and not as a number of characters, as format does. This is done on the assumption that C code is more likely to know how many bytes it is passing around than the number of encoded characters those bytes happen to represent. The variable number of arguments passed in should be of the types that would be suitable for passing to sprintf. Note in this example usage, x is of type int.

int x = 5;
Tcl_Obj *objPtr = Tcl_ObjPrintf("Value is %d", x);

If the value of format contains internal inconsistencies or invalid specifier formats, the formatted string result produced by Tcl_ObjPrintf will be an error message describing the error. It is impossible however to provide runtime protection against mismatches between the format and any subsequent arguments. Compile-time protection may be provided by some compilers.

Tcl_AppendPrintfToObj is an appending alternative form of Tcl_ObjPrintf with functionality equivalent to

Tcl_Obj *newPtr = Tcl_ObjPrintf(format, ...);
Tcl_AppendObjToObj(objPtr, newPtr);
Tcl_DecrRefCount(newPtr);

but with greater convenience and efficiency when the appending functionality is needed.

The Tcl_SetObjLength procedure changes the length of the string value of its objPtr argument. If the newLength argument is greater than the space allocated for the value's string, then the string space is reallocated and the old value is copied to the new space; the bytes between the old length of the string and the new length may have arbitrary values. If the newLength argument is less than the current length of the value's string, with objPtr->length is reduced without reallocating the string space; the original allocated size for the string is recorded in the value, so that the string length can be enlarged in a subsequent call to Tcl_SetObjLength without reallocating storage. In all cases Tcl_SetObjLength leaves a null character at objPtr->bytes[newLength].

Tcl_AttemptSetObjLength is identical in function to Tcl_SetObjLength except that if sufficient memory to satisfy the request cannot be allocated, it does not cause the Tcl interpreter to panic. Thus, if newLength is greater than the space allocated for the value's string, and there is not enough memory available to satisfy the request, Tcl_AttemptSetObjLength will take no action and return 0 to indicate failure. If there is enough memory to satisfy the request, Tcl_AttemptSetObjLength behaves just like Tcl_SetObjLength and returns 1 to indicate success.

The Tcl_ConcatObj function returns a new string value whose value is the space-separated concatenation of the string representations of all of the values in the objv array. Tcl_ConcatObj eliminates leading and trailing white space as it copies the string representations of the objv array to the result. If an element of the objv array consists of nothing but white space, then that value is ignored entirely. This white-space removal was added to make the output of the concat command cleaner-looking. Tcl_ConcatObj returns a pointer to a newly-created value whose ref count is zero.
