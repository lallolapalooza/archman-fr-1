NAME

Tcl_InitHashTable, Tcl_InitCustomHashTable, Tcl_InitObjHashTable, Tcl_DeleteHashTable, Tcl_CreateHashEntry, Tcl_DeleteHashEntry, Tcl_FindHashEntry, Tcl_GetHashValue, Tcl_SetHashValue, Tcl_GetHashKey, Tcl_FirstHashEntry, Tcl_NextHashEntry, Tcl_HashStats - procédures pour gérer des tables de hachage

SYNOPSIS

#include <tcl.h>

Tcl_InitHashTable(tablePtr, keyType)

Tcl_InitCustomHashTable(tablePtr, keyType, typePtr)

Tcl_InitObjHashTable(tablePtr)

Tcl_DeleteHashTable(tablePtr)

Tcl_HashEntry *
Tcl_CreateHashEntry(tablePtr, key, newPtr)

Tcl_DeleteHashEntry(entryPtr)

Tcl_HashEntry *
Tcl_FindHashEntry(tablePtr, key)

ClientData
Tcl_GetHashValue(entryPtr)

Tcl_SetHashValue(entryPtr, value)

void *
Tcl_GetHashKey(tablePtr, entryPtr)

Tcl_HashEntry *
Tcl_FirstHashEntry(tablePtr, searchPtr)

Tcl_HashEntry *
Tcl_NextHashEntry(searchPtr)

char *
Tcl_HashStats(tablePtr)

ARGUMENTS

Tcl_HashTable *tablePtr (in)
Adresse de la structure de la table de hachage (pour toutes les procédures sauf Tcl_InitHashTable, celle-ci doit avoir été préalablement initialisée par l'appel à Tcl_InitHashTable).
int keyType (in)
Types de clés pour la nouvelle table de hachage. Doit être l'un de TCL_STRING_KEYS, TCL_ONE_WORD_KEYS, TCL_CUSTOM_TYPE_KEYS, TCL_CUSTOM_PTR_KEYS, ou une valeur entière supérieure à 1.
Tcl_HashKeyType *typePtr (in)
Adresse de la structure qui définit le comportement de la table de hachage.
const void *key (in)
Clé pour la recherche dans la table. La forme exacte dépend du keyType utilisé pour créer la table.
int *newPtr (out)
La valeur de *newPtr est définie à 1 si une nouvelle entrée a été créée et à 0 s'il existait déjà une entrée avec la clé key.
Tcl_HashEntry *entryPtr (in)
Pointeur vers une entrée de la table de hachage.
ClientData value (in)
Nouvelle valeur à assigner à l'entrée de la table de hachage. Elle n'a pas besoin d'être de type ClientData, mais doit occuper le même espace que le type ClientData.
Tcl_HashSearch *searchPtr (in)
Pointeur vers une structure utilisée pour enregistrer la progression dans l'énumération de toutes les entrées d'une table de hachage.

DESCRIPTION

Une table de hachage consiste en zéro ou plusieurs entrées, chacune avec une clé et une valeur. Étant donné la clé d'une entrée, les fonctions de hachage peuvent rapidement localiser l'entrée et sa valeur. Il peut y avoir au maximum une entrée avec une clé spécifique dans une table de hachage, mais il peut y avoir de nombreuses entrées avec la même valeur. Les clés peuvent prendre l'une des quatre formes suivantes : chaînes de caractères, valeurs d'un seul mot, tableaux d'entiers ou clés définies par une structure Tcl_HashKeyType (voir la section THE TCL_HASHKEYTYPE STRUCTURE ci-dessous). Toutes les valeurs d'une table de hachage ont la même forme, qui est spécifiée lors de l'initialisation de la table.

La valeur d'une entrée de table de hachage peut être tout ce qui tient dans le même espace qu'un pointeur vers un entier. Les valeurs des entrées de table de hachage sont entièrement gérées par les clients, pas par le module de hachage. En général, la valeur de chaque entrée peut être trouvée comme un pointeur vers une structure gérée par le code client.

Les tables de hachage s'agrandissent progressivement lorsque le nombre d'entrées augmente, permettant toujours moins de trois entrées par compartiment en moyenne. Cela permet des recherches rapides quelle que soit le nombre d'entrées dans une table.

Le noyau fournit trois fonctions pour l'initialisation des tables de hachage : Tcl_InitHashTable, Tcl_InitObjHashTable et Tcl_InitCustomHashTable.

Tcl_InitHashTable initialise une structure décrivant une nouvelle table de hachage. L'espace de la structure est fourni par le client, pas par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. Tous les types de clés décrits plus loin sont autorisés, à l'exception de TCL_CUSTOM_TYPE_KEYS et TCL_CUSTOM_PTR_KEYS.

Tcl_InitObjHashTable est un wrapper de Tcl_InitCustomHashTable qui initialise une table de hachage dont les clés sont des Tcl_Obj *.

Tcl_InitCustomHashTable initialise une structure décrivant une nouvelle table de hachage. L'espace de la structure est fourni par le client, pas par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. KeyType doit avoir l'une des valeurs suivantes :

TCL_STRING_KEYS
Les clés sont des chaînes de caractères terminées par un caractère nul. Elles sont passées aux fonctions de hachage en utilisant l'adresse du premier caractère de la chaîne.
TCL_ONE_WORD_KEYS
Les clés sont des valeurs d'un seul mot ; elles sont passées aux fonctions de hachage et stockées dans les entrées de la table en tant que valeurs char *. La valeur du pointeur est la clé ; elle ne doit pas (et ne doit pas) pointer vers une chaîne de caractères.
TCL_CUSTOM_TYPE_KEYS
Les clés sont de type arbitraire et stockées dans l'entrée. Le hachage et la comparaison sont basés sur typePtr. La structure Tcl_HashKeyType est décrite dans la section THE TCL_HASHKEYTYPE STRUCTURE ci-dessous.
TCL_CUSTOM_PTR_KEYS
Les clés sont des pointeurs vers un type arbitraire et stockées dans l'entrée. Le hachage et la comparaison sont basés sur typePtr. La structure Tcl_HashKeyType est décrite dans la section THE TCL_HASHKEYTYPE STRUCTURE ci-dessous.
other
Si keyType n'est pas l'un des précédents, il doit s'agir d'une valeur entière supérieure à 1. Dans ce cas, les clés seront des tableaux de valeurs entières, où keyType indique le nombre d'entiers dans chaque clé. Cela permet d'utiliser des structures comme clés. Toutes les clés doivent avoir la même taille. Les clés de tableaux sont passées aux fonctions de hachage en utilisant l'adresse du premier entier du tableau.

Tcl_DeleteHashTable supprime toutes les entrées d'une table de hachage et libère l'espace associé au tableau de compartiments et aux entrées. Elle ne libère pas la structure de la table elle-même (pointée par tablePtr), car cet espace est supposé être géré par le client. Tcl_DeleteHashTable ne libère ni ne manipule non plus les valeurs des entrées de la table de hachage. Si les valeurs des entrées pointent vers de la mémoire allouée dynamiquement, il incombe au client de libérer ces structures avant de supprimer la table.

Tcl_CreateHashEntry localise l'entrée correspondant à une clé donnée, en créant une nouvelle entrée dans la table si elle n'existe pas déjà avec cette clé. S'il existe déjà une entrée avec la même clé, *newPtr est défini à 0. Si une nouvelle entrée est créée, *newPtr est défini à une valeur non nulle et la valeur de la nouvelle entrée est définie à 0. La valeur retournée par Tcl_CreateHashEntry est un pointeur vers l'entrée, qui peut être utilisé pour obtenir et modifier la valeur de l'entrée ou pour la supprimer de la table.

Tcl_DeleteHashEntry supprimera une entrée existante d'une table. La mémoire associée à l'entrée elle-même est libérée, mais le client est responsable de tout nettoyage associé à la valeur de l'entrée, comme la libération d'une structure qui y pointe.

Tcl_FindHashEntry est similaire à Tcl_CreateHashEntry, sauf qu'il ne crée pas de nouvelle entrée si la clé n'existe pas ; il renvoie plutôt NULL en résultat.

Tcl_GetHashValue et Tcl_SetHashValue sont utilisés pour lire et écrire respectivement la valeur d'une entrée. Les valeurs sont stockées et récupérées en tant que type ClientData, qui est suffisamment grand pour stocker une valeur de pointeur. Sur la plupart des systèmes, cela est suffisant pour stocker également une valeur entière.

Tcl_GetHashKey renvoie la clé d'une entrée de table de hachage, que ce soit sous la forme d'un pointeur vers une chaîne, d'une clé d'un seul mot (char *) ou d'un pointeur vers le premier mot d'un tableau d'entiers, selon le keyType utilisé pour créer la table de hachage. Dans tous les cas, Tcl_GetHashKey renvoie un résultat de type char *. Lorsque la clé est une chaîne ou un tableau, le résultat de Tcl_GetHashKey pointe vers des informations dans l'entrée de la table ; ces informations seront valides jusqu'à ce que l'entrée soit supprimée ou que sa table soit supprimée.

Tcl_FirstHashEntry et Tcl_NextHashEntry peuvent être utilisés pour parcourir toutes les entrées d'une table de hachage.

ARGUMENTS

DESCRIPTION

Les tables de hachage sont utilisées pour stocker des données qui peuvent être rapidement récupérées à l'aide d'une clé. Tcl fournit un ensemble de routines pour créer, manipuler et rechercher dans des tables de hachage.

Tcl_InitHashTable initialise une table de hachage. TablePtr pointe vers une structure Tcl_HashTable fournie par l'appelant. TypePtr pointe vers une structure Tcl_HashKeyType qui décrit comment les clés doivent être gérées pour cette table. La première fois qu'une table est initialisée, il est recommandé d'utiliser Tcl_InitCustomHashTable au lieu de Tcl_InitHashTable afin de pouvoir spécifier des fonctions personnalisées pour la gestion des clés.

Tcl_DeleteHashTable détruit une table de hachage et libère toutes les ressources associées. Toutes les entrées de la table sont supprimées.

Tcl_CreateHashEntry crée une nouvelle entrée dans la table de hachage tablePtr avec la clé spécifiée par keyPtr. Si une entrée avec cette clé existe déjà, elle est renvoyée. Sinon, une nouvelle entrée est créée, initialisée et renvoyée. Le hachage calculé est stocké à l'emplacement indiqué par hashPtr.

Tcl_FindHashEntry recherche une entrée dans la table de hachage tablePtr correspondant à la clé keyPtr. Si une entrée est trouvée, un pointeur vers celle-ci est renvoyé. Sinon, NULL est renvoyé.

Une structure de type Tcl_HashSearch, fournie par le client, est utilisée pour suivre la progression dans la table. Tcl_FirstHashEntry initialise l'enregistrement de recherche et renvoie la première entrée de la table (ou NULL si la table est vide). Chaque appel ultérieur à Tcl_NextHashEntry renvoie l'entrée suivante dans la table ou NULL si la fin de la table a été atteinte. Un appel à Tcl_FirstHashEntry suivi d'appels à Tcl_NextHashEntry renverra chaque entrée de la table exactement une fois, dans un ordre arbitraire. Il est déconseillé de modifier la structure de la table, par exemple en créant ou en supprimant des entrées, pendant que la recherche est en cours, à l'exception de la suppression de l'entrée renvoyée par Tcl_FirstHashEntry ou Tcl_NextHashEntry.

Tcl_HashStats renvoie une chaîne allouée dynamiquement avec des informations générales sur une table de hachage, telles que le nombre d'entrées qu'elle contient, le nombre de buckets dans son tableau de hachage et l'utilisation des buckets. Il est de la responsabilité de l'appelant de libérer la chaîne résultante en la passant à ckfree.

Le fichier d'en-tête tcl.h définit les structures de données réelles utilisées pour implémenter les tables de hachage. Ceci est nécessaire pour que les clients puissent allouer des structures Tcl_HashTable et pour que des macros puissent être utilisées pour lire et écrire les valeurs des entrées. Cependant, les utilisateurs des routines de hachage ne doivent jamais se référer directement à aucun des champs d'aucune des structures de données liées au hachage ; utilisez les procédures et les macros définies ici.

LA STRUCTURE TCL_HASHKEYTYPE

Les développeurs d'extensions peuvent définir de nouveaux types de clés de hachage en définissant quatre procédures, en initialisant une structure Tcl_HashKeyType pour décrire le type et en appelant Tcl_InitCustomHashTable. La structure Tcl_HashKeyType est définie comme suit :

typedef struct Tcl_HashKeyType {
    int version;
    int flags;
    Tcl_HashKeyProc *hashKeyProc;
    Tcl_CompareHashKeysProc *compareKeysProc;
    Tcl_AllocHashEntryProc *allocEntryProc;
    Tcl_FreeHashEntryProc *freeEntryProc;
} Tcl_HashKeyType;

Le membre version est la version de la table. Si cette structure est étendue à l'avenir, la version peut être utilisée pour distinguer différentes structures. Elle doit être définie à TCL_HASH_KEY_TYPE_VERSION.

Le membre flags est 0 ou une ou plusieurs des valeurs suivantes ORées ensemble :

TCL_HASH_KEY_RANDOMIZE_HASH
Certaines choses, comme les pointeurs, ne se hachent pas bien car elles n'utilisent pas les bits de poids faible. Si ce drapeau est défini, la table de hachage tentera de remédier à cela en randomisant les bits puis en utilisant les N bits supérieurs comme indice dans la table.
TCL_HASH_KEY_SYSTEM_HASH
Ce drapeau force Tcl à utiliser les procédures d'allocation mémoire fournies par le système d'exploitation lors de l'allocation et de la libération de la mémoire utilisée pour stocker les structures de données de la table de hachage, et non les propres routines d'allocation mémoire personnalisées de Tcl. Ceci est important si la table de hachage doit être utilisée dans l'implémentation d'un ensemble personnalisé de routines d'allocation, ou de quelque chose dont un ensemble personnalisé de routines d'allocation pourrait dépendre, afin d'éviter toute dépendance circulaire.

Le membre hashKeyProc contient l'adresse d'une fonction appelée pour calculer une valeur de hachage pour la clé.

typedef unsigned int Tcl_HashKeyProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

Si ceci est NULL, alors keyPtr est utilisé et TCL_HASH_KEY_RANDOMIZE_HASH est supposé.

Le membre compareKeysProc contient l'adresse d'une fonction appelée pour comparer deux clés.

typedef int Tcl_CompareHashKeysProc(
        void *keyPtr,
        Tcl_HashEntry *hPtr);

Si ceci est NULL, alors les pointeurs keyPtr sont comparés. Si les clés ne correspondent pas, la fonction renvoie 0, sinon elle renvoie 1.

Le membre allocEntryProc contient l'adresse d'une fonction appelée pour allouer de l'espace pour une entrée et initialiser la clé et clientData.

typedef Tcl_HashEntry *Tcl_AllocHashEntryProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

Si ceci est NULL, alors Tcl_Alloc est utilisé pour allouer suffisamment d'espace pour une Tcl_HashEntry, le pointeur de clé est assigné à key.oneWordValue et clientData est défini à NULL. Les clés de type chaîne et les clés de tableau utilisent cette fonction pour allouer suffisamment d'espace pour l'entrée et la clé dans un seul bloc, plutôt que de le faire en deux blocs. Cela permet d'économiser l'espace pour un pointeur vers la clé de l'entrée et une autre allocation mémoire. Les clés Tcl_Obj* utilisent cette fonction pour allouer suffisamment d'espace pour une entrée et incrémenter le compteur de références sur la valeur.

Le membre freeEntryProc contient l'adresse d'une fonction appelée pour libérer l'espace d'une entrée.

typedef void Tcl_FreeHashEntryProc(
        Tcl_HashEntry *hPtr);

Si ceci est NULL, alors Tcl_Free est utilisé pour libérer l'espace de l'entrée. Les clés Tcl_Obj* utilisent cette fonction pour décrémenter le compteur de références sur la valeur.
