Tcl_LinkVar(3) Procédures de la bibliothèque Tcl Tcl_LinkVar(3)

NOM

Tcl_LinkVar, Tcl_UnlinkVar, Tcl_UpdateLinkedVar - Lier une variable Tcl à une variable C

SYNOPSIS

#include <tcl.h>

int
Tcl_LinkVar(interp, varName, addr, type)

Tcl_UnlinkVar(interp, varName)

Tcl_UpdateLinkedVar(interp, varName)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur contenant varName. Utilisé également par Tcl_LinkVar pour renvoyer des messages d'erreur.
const char *varName (in)
Nom de la variable globale.
char *addr (in)
Adresse de la variable C qui doit être liée à varName.
int type (in)
Type de la variable C. Doit être l'un des suivants : TCL_LINK_INT, TCL_LINK_UINT, TCL_LINK_CHAR, TCL_LINK_UCHAR, TCL_LINK_SHORT, TCL_LINK_USHORT, TCL_LINK_LONG, TCL_LINK_ULONG, TCL_LINK_WIDE_INT, TCL_LINK_WIDE_UINT, TCL_LINK_FLOAT, TCL_LINK_DOUBLE, TCL_LINK_BOOLEAN, ou TCL_LINK_STRING, éventuellement combiné avec TCL_LINK_READ_ONLY pour rendre la variable Tcl en lecture seule.

DESCRIPTION

Tcl_LinkVar utilise des traces de variables pour maintenir la variable Tcl nommée par varName synchronisée avec la variable C à l'adresse indiquée par addr. Chaque fois que la variable Tcl est lue, la valeur de la variable C sera retournée, et chaque fois que la variable Tcl est écrite, la variable C sera mise à jour pour avoir la même valeur. Tcl_LinkVar retourne normalement TCL_OK ; si une erreur survient lors de la mise en place du lien (par exemple, parce que varName est le nom d'un tableau), TCL_ERROR est retourné et le résultat de l'interpréteur contient un message d'erreur.

L'argument type spécifie le type de la variable C et doit avoir l'une des valeurs suivantes, éventuellement combinée avec TCL_LINK_READ_ONLY :

TCL_LINK_INT
La variable C est de type int. Toute valeur écrite dans la variable Tcl doit avoir une forme entière correcte acceptable par Tcl_GetIntFromObj ; les tentatives d'écriture de valeurs non entières dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
TCL_LINK_UINT
La variable C est de type unsigned int. Toute valeur écrite dans la variable Tcl doit avoir une forme entière non signée correcte acceptable par Tcl_GetWideIntFromObj et être dans la plage définie par la plateforme pour le type unsigned int ; les tentatives d'écriture de valeurs non entières (ou de valeurs hors plage) dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
TCL_LINK_CHAR
La variable C est de type char. Toute valeur écrite dans la variable Tcl doit avoir une forme entière correcte acceptable par Tcl_GetIntFromObj et être dans la plage du type char ; les tentatives d'écriture de valeurs non entières ou hors plage dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
TCL_LINK_UCHAR
La variable C est de type unsigned char. Toute valeur écrite dans la variable Tcl doit avoir une forme entière non signée correcte acceptable par Tcl_GetIntFromObj et être dans la plage définie par la plateforme pour le type unsigned char ; les tentatives d'écriture de valeurs non entières (ou de valeurs hors plage) dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.
TCL_LINK_SHORT
La variable C est de type short. Toute valeur écrite dans la variable Tcl doit avoir une forme entière correcte acceptable par Tcl_GetIntFromObj et être dans la plage du type short ; les tentatives d'écriture de valeurs non entières ou hors plage dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.

Toute valeur écrite dans la variable Tcl doit avoir une forme entière non signée correcte acceptable par Tcl_GetIntFromObj et être dans la plage définie par la plateforme pour le type unsigned short ; les tentatives d'écriture de valeurs non entières (ou de valeurs hors plage) dans varName seront rejetées avec des erreurs Tcl. Les représentations entières incomplètes (comme la chaîne vide, '+', '-' ou le préfixe hexadécimal/octal/binaire) sont également acceptées comme valides.

LIEN

Tcl_LinkVar lie une variable C à une variable Tcl.

SYNTAXE

int
Tcl_LinkVar(interp, varName, partieC, flags)
Tcl_Interp *interp;
const char *varName;
char *partieC;
int flags;

ARGUMENTS

``interp— Objet d'interprète Tcl.
``varName— Nom de la variable Tcl à lier.
``partieC— Pointeur vers la variable C à lier.
``flags— Indicateurs spécifiant le type de lien.

DESCRIPTION

La procédure Tcl_LinkVar établit un lien entre une variable C et une variable Tcl. Si un lien existe déjà pour varName, il sera remplacé. Si le lien ne peut pas être créé, par exemple en raison de permissions, une erreur Tcl sera générée et 0 sera retourné. Dans le cas contraire, 1 sera retourné.

Les valeurs possibles pour flags sont les suivantes :

``TCL_LINK_INT
La variable C est de type int. Les valeurs entières sont transférées entre Tcl et C. Les valeurs positives sont lues par Tcl comme une chaîne de caractères représentant l'entier ; les valeurs nulles sont lues comme "0" ; les valeurs négatives sont lues comme une chaîne de caractères négative.
``TCL_LINK_BOOLEAN
La variable C est de type int. Si sa valeur est nulle, elle sera lue par Tcl comme "0" ; sinon, elle sera lue par Tcl comme "1". Chaque fois que varName est modifié, la variable C sera définie à 0 ou 1. Toute valeur écrite dans la variable Tcl doit avoir une forme booléenne correcte acceptable par Tcl_GetBooleanFromObj ; toute tentative d'écriture de valeurs non booléennes dans varName sera rejetée avec des erreurs Tcl.
TCL_LINK_STRING
La variable C est de type char *. Si sa valeur n'est pas NULL, elle doit pointer vers une chaîne allouée avec Tcl_Alloc ou ckalloc. Chaque fois que la variable Tcl est modifiée, la chaîne C courante sera libérée et une nouvelle mémoire sera allouée pour contenir une copie de la nouvelle valeur de la variable. Si la variable C contient un pointeur NULL, la variable Tcl sera lue comme "NULL".

Si le drapeau TCL_LINK_READ_ONLY est présent dans type, la variable sera en lecture seule depuis Tcl, de sorte que sa valeur ne pourra être modifiée qu'en modifiant la variable C. Toute tentative d'écriture de la variable depuis Tcl sera rejetée avec des erreurs.

Tcl_UnlinkVar supprime le lien précédemment établi pour la variable donnée par varName. S'il n'existe pas de lien pour varName, la procédure n'a aucun effet.

Tcl_UpdateLinkedVar peut être appelée après que la variable C a changé pour forcer la mise à jour immédiate de la variable Tcl. Dans de nombreux cas, cette procédure n'est pas nécessaire, car toute tentative de lecture de la variable Tcl retournera la dernière valeur de la variable C. Cependant, si une trace a été définie sur la variable Tcl (par exemple, un widget Tk souhaitant afficher la valeur de la variable), la trace ne se déclenchera pas lorsque la variable C aura changé. Tcl_UpdateLinkedVar garantit que toutes les traces sur la variable Tcl sont invoquées.

Notez que, comme pour tout appel à un interpréteur Tcl, Tcl_UpdateLinkedVar doit être appelé depuis le même thread qui a créé l'interpréteur. Le mécanisme le plus sûr est de s'assurer que la variable C n'est jamais mise à jour que depuis le même thread qui a créé l'interpréteur (éventuellement en réponse à un événement posté avec Tcl_ThreadQueueEvent), mais lorsqu'il est nécessaire de mettre à jour la variable dans un thread séparé, il est conseillé d'utiliser Tcl_AsyncMark pour indiquer au thread hébergeant l'interpréteur qu'il est prêt à exécuter Tcl_UpdateLinkedVar.
