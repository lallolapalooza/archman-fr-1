NOM

Tcl_RegisterObjType, Tcl_GetObjType, Tcl_AppendAllObjTypes, Tcl_ConvertToType - manipuler les types de valeurs Tcl

SYNOPIS

#include <tcl.h>

Tcl_RegisterObjType(typePtr)

const Tcl_ObjType *
Tcl_GetObjType(typeName)

int
Tcl_AppendAllObjTypes(interp, objPtr)

int
Tcl_ConvertToType(interp, objPtr, typePtr)

ARGUMENTS

const Tcl_ObjType *typePtr (in)
Pointe vers la structure contenant les informations sur le type de valeur Tcl. Cet espace de stockage doit exister pour toujours, typiquement en étant alloué statiquement.
const char *typeName (in)
Le nom d'un type de valeur Tcl que Tcl_GetObjType doit rechercher.
Tcl_Interp *interp (in)
Interpréteur à utiliser pour le rapport d'erreurs.
Tcl_Obj *objPtr (in)
Pour Tcl_AppendAllObjTypes, pointe vers la valeur sur laquelle il ajoute le nom de chaque type de valeur comme élément de liste. Pour Tcl_ConvertToType, pointe vers une valeur qui doit avoir été le résultat d'un appel précédent à Tcl_NewObj.

DESCRIPTION

Les procédures de cette page de manuel gèrent les types de valeurs Tcl (parfois appelés types d'objets ou Tcl_ObjType pour des raisons historiques). Elles sont utilisées pour enregistrer de nouveaux types de valeurs, rechercher des types et forcer des conversions d'un type à un autre.

Tcl_RegisterObjType enregistre un nouveau type de valeur Tcl dans la table de tous les types de valeurs que Tcl_GetObjType peut rechercher par nom. Il existe d'autres types de valeurs pris en charge par Tcl également, que Tcl choisit de ne pas enregistrer. Les extensions peuvent de même choisir d'enregistrer les types de valeurs qu'elles créent ou non. L'argument typePtr pointe vers une structure Tcl_ObjType qui décrit le nouveau type en donnant son nom et en fournissant des pointeurs vers quatre procédures qui implémentent le type. Si la table des types contient déjà un type portant le même nom que dans typePtr, il est remplacé par le nouveau type. La structure Tcl_ObjType est décrite dans la section LA STRUCTURE TCL_OBJTYPE ci-dessous.

Tcl_GetObjType retourne un pointeur vers le Tcl_ObjType enregistré portant le nom typeName. Il retourne NULL si aucun type avec ce nom n'est enregistré.

Tcl_AppendAllObjTypes ajoute le nom de chaque type de valeur enregistré comme un élément de liste à la valeur Tcl référencée par objPtr. La valeur de retour est TCL_OK à moins qu'il n'y ait eu une erreur lors de la conversion de objPtr en une valeur de liste ; dans ce cas, TCL_ERROR est retourné.

Tcl_ConvertToType convertit une valeur d'un type à un autre si possible. Elle crée une nouvelle représentation interne pour objPtr appropriée au type cible typePtr et définit son membre typePtr tel que déterminé par l'appel de la routine typePtr->setFromAnyProc. Toute représentation interne du type précédent de objPtr est libérée. Si une erreur survient pendant la conversion, elle retourne TCL_ERROR et laisse un message d'erreur dans la valeur de résultat pour interp à moins que interp ne soit NULL. Sinon, elle retourne TCL_OK. Passer un interp NULL permet à cette procédure d'être utilisée comme test pour savoir si la conversion peut être effectuée (et effectivement a été effectuée).

Dans de nombreux cas, la routine typePtr->setFromAnyProc définira objPtr->typePtr à la valeur de l'argument typePtr, mais cela n'est plus garanti. Le setFromAnyProc est libre de définir la représentation interne pour objPtr afin d'utiliser un autre Tcl_ObjType lié, s'il le juge approprié.

LA STRUCTURE TCL_OBJTYPE

Les développeurs d'extensions peuvent définir de nouveaux types de valeurs en définissant quatre procédures et en initialisant une structure Tcl_ObjType pour décrire le type. Les développeurs d'extensions peuvent également passer un pointeur vers leur structure Tcl_ObjType à Tcl_RegisterObjType s'ils souhaitent permettre à d'autres extensions de rechercher leur Tcl_ObjType par nom avec la routine Tcl_GetObjType. La structure Tcl_ObjType est définie comme suit :

typedef struct Tcl_ObjType {
    const char *name;
    Tcl_FreeInternalRepProc *freeIntRepProc;
    Tcl_DupInternalRepProc *dupIntRepProc;
    Tcl_UpdateStringProc *updateStringProc;
    Tcl_SetFromAnyProc *setFromAnyProc;
} Tcl_ObjType;

LE CHAMP NAME

Le membre name décrit le nom du type, par exemple int. Lorsqu'un type est enregistré, c'est le nom utilisé par les appelants de Tcl_GetObjType pour rechercher le type. Pour les types non enregistrés, le champ name est principalement utile pour le débogage. Les quatre membres restants sont des pointeurs vers des procédures appelées par le code générique des valeurs Tcl :

LE CHAMP SETFROMANYPROC

Le membre setFromAnyProc contient l'adresse d'une fonction appelée pour créer une représentation interne valide à partir de la représentation textuelle d'une valeur.

typedef int Tcl_SetFromAnyProc(
        Tcl_Interp *interp,
        Tcl_Obj *objPtr);

Si une représentation interne ne peut pas être créée à partir du texte, elle retourne TCL_ERROR et place un message décrivant l'erreur dans la valeur de résultat pour interp à moins que interp ne soit NULL. Si setFromAnyProc réussit, elle stocke la nouvelle représentation interne, définit le membre typePtr de objPtr pour pointer vers la structure Tcl_ObjType correspondant à la nouvelle représentation interne, et retourne TCL_OK. Avant de définir la nouvelle représentation interne, le setFromAnyProc doit libérer toute représentation interne de l'ancien type de objPtr ; il le fait en appelant le freeIntRepProc de l'ancien type s'il n'est pas NULL.

Par exemple, le setFromAnyProc du type liste Tcl intégré obtient une représentation textuelle à jour pour objPtr en appelant Tcl_GetStringFromObj. Il analyse le texte pour vérifier qu'il est dans un format de liste valide et pour obtenir chaque valeur élément dans la liste, et, si cela réussit, stocke les éléments de la liste dans la représentation interne de objPtr et définit le membre typePtr de objPtr pour pointer vers la structure Tcl_ObjType du type liste.

Ne libérez pas la représentation interne précédente de objPtr à moins que vous ne la remplaciez par une nouvelle ou que vous ne réinitialisiez le membre typePtr à NULL.

Le membre setFromAnyProc peut être défini à NULL, si les procédures utilisant la représentation interne n'ont pas besoin de dériver cette représentation interne à partir d'une valeur textuelle arbitraire. Cependant, dans ce cas, passer un pointeur vers le type à Tcl_ConvertToType entraînera une panique, donc pour éviter cette possibilité, le type ne devrait PAS être enregistré.

LE CHAMP UPDATESTRINGPROC

Le membre updateStringProc contient l'adresse d'une fonction appelée pour créer une représentation textuelle valide à partir de la représentation interne d'une valeur.

typedef void Tcl_UpdateStringProc(
        Tcl_Obj *objPtr);

Le membre bytes de objPtr est toujours NULL lorsqu'il est appelé. Il doit toujours définir bytes non NULL avant de retourner. Nous exigeons que le tableau d'octets de la représentation textuelle ait un null après le dernier octet, à l'offset length, et qu'il n'y ait aucun octet null avant cela ; cela permet de traiter les représentations textuelles comme des chaînes C conventionnelles terminées par null. Ces restrictions sont facilement satisfaites en utilisant le codage interne UTF de Tcl pour la représentation textuelle, de la même manière que l'on ferait pour d'autres procédures Tcl acceptant des valeurs textuelles en arguments. L'espace pour le tableau d'octets doit être alloué sur le tas par Tcl_Alloc ou ckalloc. Notez que les updateStringProc doivent allouer suffisamment d'espace pour les octets de la chaîne et l'octet null terminateur.

Le updateStringProc pour le type double intégré de Tcl, par exemple, appelle Tcl_PrintDouble pour écrire dans un tampon de taille TCL_DOUBLE_SPACE, puis alloue et copie la représentation textuelle dans juste assez d'espace pour la contenir. Un pointeur vers l'espace alloué est stocké dans le membre bytes.
