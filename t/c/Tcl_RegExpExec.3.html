Tcl_RegExpMatch, Tcl_RegExpCompile, Tcl_RegExpExec, Tcl_RegExpRange, Tcl_GetRegExpFromObj, Tcl_RegExpMatchObj, Tcl_RegExpExecObj, Tcl_RegExpGetInfo - Correspondance de motifs avec des expressions régulières

#include <tcl.h>

int
Tcl_RegExpMatchObj(interp, textObj, patObj)

int
Tcl_RegExpMatch(interp, text, pattern)

Tcl_RegExp
Tcl_RegExpCompile(interp, pattern)

int
Tcl_RegExpExec(interp, regexp, text, start)

void
Tcl_RegExpRange(regexp, index, startPtr, endPtr)

Tcl_RegExp
Tcl_GetRegExpFromObj(interp, patObj, cflags)

int
Tcl_RegExpExecObj(interp, regexp, textObj, offset, nmatches, eflags)

void
Tcl_RegExpGetInfo(regexp, infoPtr)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur Tcl à utiliser pour le rapport d'erreurs. L'interpréteur peut être NULL si aucun rapport d'erreur n'est souhaité.
Tcl_Obj *textObj (in/out)
Fait référence à la valeur à partir de laquelle obtenir le texte à rechercher. La représentation interne de la valeur peut être convertie dans un format qui peut être recherché efficacement.
Tcl_Obj *patObj (in/out)
Fait référence à la valeur à partir de laquelle obtenir une expression régulière. L'expression régulière compilée est mise en cache dans la valeur.
const char *text (in)
Texte à rechercher une correspondance avec une expression régulière.
const char *pattern (in)
Chaîne sous la forme d'un motif d'expression régulière.
Tcl_RegExp regexp (in)
Expression régulière compilée. Doit avoir été retournée précédemment par Tcl_GetRegExpFromObj ou Tcl_RegExpCompile.
const char *start (in)
Si text n'est qu'une partie d'une autre chaîne, cet argument identifie le début de la chaîne plus grande. S'il n'est pas le même que text, alors aucun motif “^” ne sera permis.
int index (in)
Spécifie quelle plage est souhaitée : 0 signifie la plage de la correspondance entière, 1 ou plus signifie la plage qui correspondait à une sous-expression entre parenthèses.
const char **startPtr (out)
L'adresse du premier caractère de la plage est stockée ici, ou NULL s'il n'y a pas de telle plage.
const char **endPtr (out)
L'adresse du caractère juste après le dernier caractère de la plage est stockée ici, ou NULL s'il n'y a pas de telle plage.
int cflags (in)
Combinaison OR des indicateurs de compilation TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, TCL_REG_EXPANDED, TCL_REG_QUOTE, TCL_REG_NOCASE, TCL_REG_NEWLINE, TCL_REG_NLSTOP, TCL_REG_NLANCH, TCL_REG_NOSUB, et TCL_REG_CANMATCH. Voir ci-dessous pour plus d'informations.
int offset (in)
Le décalage de caractères dans le texte où la recherche de correspondance doit commencer. La valeur du décalage n'a aucun impact sur les correspondances ^. Ce comportement est contrôlé par eflags.
int nmatches (in)
Le nombre de sous-expressions correspondantes qui doivent être mémorisées pour une utilisation ultérieure. Si cette valeur est 0, alors aucune information de correspondance de sous-expression ne sera calculée. Si la valeur est -1, alors toutes les sous-expressions correspondantes seront mémorisées. Toute autre valeur sera considérée comme le nombre maximum de sous-expressions à mémoriser.
int eflags (in)
Combinaison OR des indicateurs d'exécution TCL_REG_NOTBOL et TCL_REG_NOTEOL. Voir ci-dessous pour plus d'informations.
Tcl_RegExpInfo *infoPtr (out)
L'adresse de l'emplacement où les informations sur une correspondance précédente doivent être stockées par Tcl_RegExpGetInfo.

DESCRIPTION

Tcl_RegExpMatch détermine si son argument pattern correspond à regexp, où regexp est interprété comme une expression régulière selon les règles de la page de référence re_syntax. S'il y a une correspondance, Tcl_RegExpMatch retourne 1. S'il n'y a pas de correspondance, Tcl_RegExpMatch retourne 0. Si une erreur se produit pendant le processus de correspondance (par exemple, pattern n'est pas une expression régulière valide), alors Tcl_RegExpMatch retourne -1 et laisse un message d'erreur dans le résultat de l'interpréteur. Tcl_RegExpMatchObj est similaire à Tcl_RegExpMatch sauf qu'elle opère sur les valeurs Tcl textObj et patObj au lieu de chaînes UTF. Tcl_RegExpMatchObj est généralement plus efficace que Tcl_RegExpMatch, c'est donc l'interface préférée.

Tcl_RegExpCompile, Tcl_RegExpExec, et Tcl_RegExpRange fournissent un accès de plus bas niveau au moteur d'expressions régulières. Tcl_RegExpCompile compile une chaîne d'expression régulière dans la forme interne utilisée pour une correspondance efficace. La valeur de retour est un jeton pour cette forme compilée, qui peut être utilisé dans des appels ultérieurs à Tcl_RegExpExec ou Tcl_RegExpRange. Si une erreur se produit lors de la compilation de l'expression régulière, Tcl_RegExpCompile retourne NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Remarque : la valeur de retour de Tcl_RegExpCompile n'est valide que jusqu'au prochain appel à Tcl_RegExpCompile ; il n'est pas sûr de conserver ces valeurs pendant de longues périodes.

Tcl_RegExpExec exécute le moteur d'expressions régulières. Il retourne 1 si text contient une plage de caractères qui correspond à regexp, 0 si aucune correspondance n'est trouvée, et -1 si une erreur se produit. En cas d'erreur, Tcl_RegExpExec laisse un message d'erreur dans le résultat de l'interpréteur. Lors de la recherche dans une chaîne pour plusieurs correspondances d'un motif, il est important de distinguer entre le début de la chaîne d'origine et le début de la recherche en cours. Par exemple, lors de la recherche de la deuxième occurrence d'une correspondance, l'argument text peut pointer vers le caractère suivant la première correspondance ; cependant, il est important que le moteur d'expressions régulières sache que ce n'est pas le début de toute la chaîne, afin qu'il ne permette pas aux atomes “^” du motif de correspondre. L'argument start fournit cette information en pointant vers le début de la chaîne globale contenant text. Start sera inférieur ou égal à text ; s'il est inférieur à text, aucune correspondance ^ ne sera autorisée.

Tcl_RegExpRange peut être invoqué après que Tcl_RegExpExec ait retourné ; il fournit des informations détaillées sur quelles plages de la chaîne ont correspondu à quelles parties du motif. Tcl_RegExpRange retourne une paire de pointeurs dans *startPtr et *endPtr qui identifient une plage de caractères dans la chaîne source pour l'appel le plus récent à Tcl_RegExpExec. Index indique quelle plage parmi plusieurs est souhaitée : si index est 0, des informations sont retournées sur la plage globale de caractères qui a correspondé à l'ensemble du motif ; sinon, des informations sont retournées sur la plage de caractères qui a correspondu à la index-ième sous-expression entre parenthèses dans le motif. S'il n'y a pas de plage correspondant à index, NULL est stocké dans *startPtr et *endPtr.

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj, et Tcl_RegExpGetInfo sont des interfaces orientées valeurs qui fournissent le contrôle le plus direct de la bibliothèque d'expressions régulières de Henry Spencer. Pour les utilisateurs qui ont besoin de modifier directement les options de compilation et d'exécution, il est recommandé d'utiliser ces interfaces plutôt que d'appeler les fonctions internes d'expressions régulières. Ces interfaces gèrent les détails des traductions UTF vers Unicode ainsi que l'amélioration des performances grâce à la mise en cache dans les valeurs de motif et de chaîne.

Tcl_GetRegExpFromObj tente de retourner une expression régulière compilée à partir de patObj. Si la valeur ne contient pas déjà une expression régulière compilée, elle tentera d'en créer une à partir de la chaîne dans la valeur et de l'assigner à la représentation interne de patObj. La valeur de retour de cette fonction est de type Tcl_RegExp. La valeur de retour est un jeton pour cette forme compilée, qui peut être utilisé dans des appels ultérieurs à Tcl_RegExpExecObj ou Tcl_RegExpGetInfo. Si une erreur se produit lors de la compilation de l'expression régulière, Tcl_GetRegExpFromObj retourne NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Le jeton d'expression régulière peut être utilisé tant que la représentation interne de patObj fait référence à la forme compilée. NAME

Tcl_RegExpExec, Tcl_RegExpExecObj, Tcl_RegExpGetInfo, Tcl_RegExpMatchObj, Tcl_RegExpCompileObj, Tcl_RegExpFree \- Tcl regular expression matching

SYNOPSIS

#include <tcl.h>

int
Tcl_RegExpCompileObj(
    Tcl_Interp *interp,
    Tcl_Obj *regexpObj,
    int flags
);

int
Tcl_RegExpExec(
    Tcl_Interp *interp,
    Tcl_RegExp regexp,
    const char *string,
    const char *end,
    int nmatches,
    long offset,
    int eflags
);

int
Tcl_RegExpExecObj(
    Tcl_Interp *interp,
    Tcl_RegExp regexp,
    Tcl_Obj *objPtr,
    int nmatches,
    long offset,
    int eflags
);

int
Tcl_RegExpGetInfo(
    Tcl_Interp *interp,
    Tcl_RegExp regexp,
    Tcl_RegExpInfo *infoPtr
);

int
Tcl_RegExpMatchObj(
    Tcl_Interp *interp,
    Tcl_Obj *regexpObj,
    Tcl_Obj *objPtr
);

void
Tcl_RegExpFree(
    Tcl_RegExp regexp
);

ARGUMENTS

interp (in)
Tcl interpreter to use for error reporting.
regexpObj (in)
Object containing the regular expression string.
flags (in)
Bitwise OR of options for compiling the regular expression. See description below.
regexp (in)
Compiled regular expression, as returned by Tcl_RegExpCompileObj or Tcl_RegExpMatchObj.
string (in)
Null-terminated string to match against. Can be NULL if end is not NULL.
end (in)
Pointer to character after the end of the string. If string is not NULL, then this points one character past the end of the string. If string is NULL, this argument points to the end of the string to be searched.
objPtr (in)
Object containing the string to match against.
nmatches (in)
Maximum number of subexpressions to remember. If 0, no information about subexpressions is recorded. If -1, all subexpressions are recorded. Otherwise, at most nmatches subexpressions are recorded.
offset (in)
Index in string or objPtr at which to begin matching. Indices are 0-based.
eflags (in)
Bitwise OR of flags that modify matching behavior. See description below.
infoPtr (out)
Pointer to structure to receive match information.

DESCRIPTION

These functions provide an interface to the Tcl regular expression engine. The functions fall into three categories: compiling regular expressions, executing regular expressions, and retrieving information about matches.

Tcl_RegExpCompileObj compiles the regular expression in regexpObj according to the options specified by flags. It returns a handle of type Tcl_RegExp which can be used in subsequent calls to Tcl_RegExpExec, Tcl_RegExpExecObj, and Tcl_RegExpGetInfo. The compiled regular expression should be freed with Tcl_RegExpFree when it is no longer needed. If an error occurs during compilation, Tcl_RegExpCompileObj returns NULL and leaves an error message in the interpreter result.

The flags argument is a bit-wise OR of zero or more of the following bits:

TCL_REG_ADVANCED
Compile advanced regular expressions (“ARE”s). This mode corresponds to the normal regular expression syntax accepted by the Tcl regexp and regsub commands.
TCL_REG_EXTENDED
Compile extended regular expressions (“ERE”s). This mode corresponds to the regular expression syntax recognized by Tcl 8.0 and earlier versions.
TCL_REG_BASIC
Compile basic regular expressions (“BRE”s). This mode corresponds to the regular expression syntax recognized by common Unix utilities like sed and grep. This is the default if no flags are specified.
TCL_REG_EXPANDED
Compile the regular expression (basic, extended, or advanced) using an expanded syntax that allows comments and whitespace. This mode causes non-backslashed non-bracket-expression white space and #-to-end-of-line comments to be ignored.
TCL_REG_QUOTE
Compile a literal string, with all characters treated as ordinary characters.
TCL_REG_NOCASE
Compile for matching that ignores upper/lower case distinctions.
TCL_REG_NEWLINE
Compile for newline-sensitive matching. By default, newline is a completely ordinary character with no special meaning in either regular expressions or strings. With this flag, “[^” bracket expressions and “.” never match newline, “^” matches an empty string after any newline in addition to its normal function, and “$” matches an empty string before any newline in addition to its normal function. REG_NEWLINE is the bit-wise OR of REG_NLSTOP and REG_NLANCH.
TCL_REG_NLSTOP
Compile for partial newline-sensitive matching, with the behavior of “[^” bracket expressions and “.” affected, but not the behavior of “^” and “$”. In this mode, “[^” bracket expressions and “.” never match newline.
TCL_REG_NLANCH
Compile for inverse partial newline-sensitive matching, with the behavior of “^” and “$” (the “anchors”) affected, but not the behavior of “[^” bracket expressions and “.”. In this mode “^” matches an empty string after any newline in addition to its normal function, and “$” matches an empty string before any newline in addition to its normal function.
TCL_REG_NOSUB
Compile for matching that reports only success or failure, not what was matched. This reduces compile overhead and may improve performance. Subsequent calls to Tcl_RegExpGetInfo or Tcl_RegExpRange will not report any match information.
TCL_REG_CANMATCH
Compile for matching that reports the potential to complete a partial match given more text (see below).

Only one of TCL_REG_EXTENDED, TCL_REG_ADVANCED, TCL_REG_BASIC, and TCL_REG_QUOTE may be specified.

Tcl_RegExpExecObj executes the regular expression pattern matcher. It returns 1 if objPtr contains a range of characters that match regexp, 0 if no match is found, and -1 if an error occurs. In the case of an error, Tcl_RegExpExecObj leaves an error message in the interpreter result. The nmatches value indicates to the matcher how many subexpressions are of interest. If nmatches is 0, then no subexpression match information is recorded, which may allow the matcher to make various optimizations. If the value is -1, then all of the subexpressions in the pattern are remembered. If the value is a positive integer, then only that number of subexpressions will be remembered. Matching begins at the specified Unicode character index given by offset. Unlike Tcl_RegExpExec, the behavior of anchors is not affected by the offset value. Instead the behavior of the anchors is explicitly controlled by the eflags argument, which is a bit-wise OR of zero or more of the following flags:

TCL_REG_NOTBOL
The starting character will not be treated as the beginning of a line or the beginning of the string, so “^” will not match there. Note that this flag has no effect on how “\A” matches.
TCL_REG_NOTEOL
The last character in the string will not be treated as the end of a line or the end of the string, so “$” will not match there. Note that this flag has no effect on how “\Z” matches.

Tcl_RegExpGetInfo retrieves information about the last match performed with a given regular expression regexp. The infoPtr argument contains a pointer to a structure that is defined as follows:

typedef struct Tcl_RegExpInfo {
    int nsubs;
    Tcl_RegExpIndices *matches;
    long extendStart;
} Tcl_RegExpInfo;

The nsubs field contains a count of the number of parenthesized subexpressions within the regular expression. If the TCL_REG_NOSUB was used, then this value will be zero. The matches field points to an array of nsubs+1 values that indicate the bounds of each subexpression matched. The first element in the array refers to the range matched by the entire regular expression, and subsequent elements refer to the parenthesized subexpressions in the order that they appear in the pattern. Each element is a structure that is defined as follows:

typedef struct Tcl_RegExpIndices {
    long start;
    long end;
} Tcl_RegExpIndices;

The start and end values are Unicode character indices relative to the offset location within objPtr where matching began. The start index identifies the first character of the matched subexpression. The end index identifies the first character after the matched subexpression. If the subexpression matched the empty string, then start and end will be equal. If the subexpression did not participate in the match, then start and end will be set to -1.

The extendStart field in Tcl_RegExpInfo is only set if the TCL_REG_CANMATCH flag was used. It indicates the first character in the string where a match could occur. If a match was found, this will be the same as the beginning of the current match. If no match was found, then it indicates the earliest point at which a match might occur if additional text is appended to the string. If it is no match is possible even with further text, this field will be set to -1.
