Tcl_Main(3) Procédures de la Bibliothèque Tcl Tcl_Main(3)

NOM

Tcl_Main, Tcl_MainEx, Tcl_MainExW, Tcl_SetStartupScript, Tcl_GetStartupScript, Tcl_SetMainLoop - programme principal, script de démarrage et boucle d'événements pour les applications Tcl

SYNOPSIS

#include <tcl.h>

Tcl_Main(argc, argv, appInitProc)

Tcl_MainEx(argc, charargv, appInitProc, interp)

Tcl_MainExW(argc, wideargv, appInitProc, interp)

Tcl_SetStartupScript(path, encoding)

Tcl_Obj *
Tcl_GetStartupScript(encodingPtr)

Tcl_SetMainLoop(mainLoopProc)

ARGUMENTS

int argc (in)
Nombre d'éléments dans argv.
char *argv[] (in)
Tableau de chaînes contenant les arguments de ligne de commande. Sous Windows, lorsque -DUNICODE est utilisé, le type du paramètre change en wchar_t *.
char *charargv[] (in)
Comme argv, mais le type ne change pas en wchar_t.
char *wideargv[] (in)
Comme argv, mais le type est toujours wchar_t.
Tcl_AppInitProc *appInitProc (in)
Adresse d'une procédure d'initialisation spécifique à l'application. La valeur de cet argument est généralement Tcl_AppInit.
Tcl_Obj *path (in)
Nom du fichier à utiliser comme script de démarrage, ou NULL.
const char *encoding (in)
Nom de l'encodage utilisé pour le fichier de script de démarrage, ou NULL.
const char **encodingPtr (out)
Si ce n'est pas NULL, l'emplacement pour copier un pointeur vers const char vers le nom de l'encodage.
Tcl_MainLoopProc *mainLoopProc (in)
Adresse d'une procédure de boucle d'événements spécifique à l'application.
Tcl_Interp *interp (in)
Interpréteur Tcl déjà créé.

DESCRIPTION

Tcl_Main peut servir de programme principal pour les applications de type shell Tcl. Une application de type shell est un programme tel que tclsh ou wish qui prend en charge à la fois l'interprétation interactive de Tcl et l'évaluation d'un script contenu dans un fichier donné comme argument de ligne de commande. Tcl_Main est offert comme une commodité pour les développeurs d'applications de type shell, afin qu'ils n'aient pas à reproduire tout le code nécessaire à l'initialisation de la bibliothèque Tcl et au fonctionnement du shell interactif. D'autres styles d'intégration de Tcl dans une application ne sont pas pris en charge par Tcl_Main. Ceux-ci doivent être réalisés en appelant directement des fonctions de bas niveau de la bibliothèque Tcl.

La fonction Tcl_Main est proposée par la bibliothèque Tcl depuis la version 7.4. Dans les versions précédentes de Tcl, la bibliothèque elle-même définissait une fonction main, mais celle-ci n'offrait pas de flexibilité en matière de style d'intégration et le fait d'avoir une fonction main dans une bibliothèque (en particulier dans une bibliothèque partagée) pose des problèmes sur de nombreux systèmes. Avoir main dans la bibliothèque Tcl rendrait également difficile l'utilisation de Tcl dans des programmes C++, car les programmes C++ doivent avoir des fonctions main spéciales spécifiques à C++.

Normalement, chaque application de type shell contient une petite fonction main qui appelle Tcl_Main. Tcl_Main effectue ensuite tout le travail de création et d'exécution d'une application similaire à tclsh.

Tcl_Main n'est pas disponible dans l'interface publique de la bibliothèque de stubs Tcl. Les programmes qui appellent Tcl_Main doivent être liés à la bibliothèque Tcl standard. Les extensions (y compris celles activées par les stubs) ne sont pas destinées à appeler Tcl_Main.

Tcl_Main n'est pas thread-safe. Il ne doit être appelé que par un seul thread du processus principal d'une application multithread. Cette restriction n'est pas un problème avec l'utilisation normale décrite ci-dessus.

Tcl_Main et par conséquent toutes les applications basées sur lui, comme tclsh, utilisent Tcl_GetStdChannel pour initialiser les canaux standard à leurs valeurs par défaut. Voir Tcl_StandardChannels pour plus d'informations.

Tcl_Main prend en charge deux modes de fonctionnement, selon que le nom et l'encodage d'un script de démarrage ont été définis. Les routines Tcl_SetStartupScript et Tcl_GetStartupScript sont les outils pour contrôler cette configuration de Tcl_Main.

Tcl_SetStartupScript enregistre path comme nom de fichier que Tcl_Main doit évaluer comme script de démarrage. La valeur encoding est le nom de l'encodage utilisé pour stocker le texte dans ce fichier. Une valeur NULL pour encoding est un signal pour utiliser l'encodage du système. Une valeur NULL pour path supprime tout enregistrement existant afin que Tcl_Main n'évalue aucun script de démarrage.

Tcl_GetStartupScript interroge le nom du fichier et l'encodage enregistrés par le dernier appel à Tcl_SetStartupScript dans le même thread. Le nom du fichier stocké est renvoyé, et le nom de l'encodage stocké est écrit dans l'espace pointé par encodingPtr, lorsque celui-ci n'est pas NULL.

Les valeurs de nom et d'encodage gérées par les routines Tcl_SetStartupScript et Tcl_GetStartupScript sont stockées par thread. Bien que les fonctions de stockage et de récupération de ces routines fonctionnent dans n'importe quel thread, seuls les appels dans le même thread que Tcl_Main peuvent avoir une influence sur celui-ci.

L'appelant de Tcl_Main peut d'abord appeler Tcl_SetStartupScript pour définir son propre script de démarrage souhaité. Si Tcl_Main constate qu'aucun script de démarrage n'est défini, il examinera les premiers arguments de argv. S'ils correspondent à ?-encoding name?, fileName, où fileName ne commence pas par le caractère -, alors fileName est pris comme nom d'un fichier contenant un script de démarrage, et name est pris comme nom de l'encodage du contenu de ce fichier. Tcl_Main appelle alors Tcl_SetStartupScript avec ces valeurs.

Tcl_Main définit ensuite dans son interpréteur principal les variables Tcl argc, argv, argv0 et tcl_interactive, comme décrit dans la documentation de tclsh.

Une fois son propre initialisation terminée, mais avant de traiter les commandes, Tcl_Main appelle la procédure spécifiée par l'argument appInitProc. Cette procédure fournit un "hook" pour que l'application effectue sa propre initialisation de l'interpréteur créé par Tcl_Main, comme la définition de commandes spécifiques à l'application. Le processus d'initialisation de l'application peut également appeler Tcl_SetStartupScript pour (ré)définir le fichier et l'encodage à utiliser comme script de démarrage. La procédure doit avoir une interface correspondant au type Tcl_AppInitProc:

typedef int Tcl_AppInitProc(
        Tcl_Interp *interp);

AppInitProc est presque toujours un pointeur vers Tcl_AppInit ; pour plus de détails sur cette procédure, voir la documentation de Tcl_AppInit.

Une fois la procédure appInitProc terminée, Tcl_Main appelle Tcl_GetStartupScript pour déterminer quel script de démarrage a été demandé, le cas échéant. Si un script de démarrage a été fourni, Tcl_Main tente de l'évaluer. Sinon, le mode interactif commence par examiner la variable tcl_rcFileName dans l'interpréteur principal. Si cette variable existe et contient le nom d'un fichier lisible, les instructions de ce fichier sont évaluées dans l'interpréteur principal. Ensuite, le mode interactif démarre, avec des invites et les résultats de l'évaluation des commandes écrits sur la sortie standard, et les commandes lues depuis le canal standard et évaluées. Les invites écrites sur la sortie standard peuvent être personnalisées en définissant les variables Tcl tcl_prompt1 et tcl_prompt2 comme décrit dans la documentation de tclsh. Les invites et les résultats de l'évaluation des commandes ne sont écrits sur le canal standard que si la variable Tcl tcl_interactive dans l'interpréteur principal a une valeur non nulle.

Tcl_SetMainLoop permet de définir une procédure de boucle d'événements à exécuter. Cela permet, par exemple, de charger dynamiquement Tk et de définir sa boucle d'événements. La boucle d'événements s'exécutera après le script de démarrage. Si vous êtes en mode interactif, la définition de la procédure de boucle d'événements entraînera le fait que l'invite sera basée sur fileevent, puis la procédure de boucle sera appelée. Lorsque la procédure de boucle d'événements renvoie en mode interactif, le fonctionnement interactif se poursuivra. La procédure de boucle d'événements doit avoir une interface correspondant au type Tcl_MainLoopProc:

typedef void Tcl_MainLoopProc(void);

Tcl_Main ne retourne pas. Normalement, un programme basé sur Tcl_Main se terminera lorsque la commande exit sera évaluée. En mode interactif, si un EOF ou une erreur est détecté sur le canal d'entrée standard, Tcl_Main évaluera lui-même la commande exit pour terminer.

Tcl_SetStartupScript(3) - Tcl

NAME

Tcl_SetStartupScript - specify a script to be evaluated by Tcl_Main

SYNOPSIS

#include <tcl.h>
const char *
Tcl_SetStartupScript(
  interp,
  script,
  fileName
);

ARGUMENTS

--> Var
Interp *interp (input): Interpreter to associate the script with.
--> Var
const char *script (input): The script string to be evaluated.
--> Var
const char *fileName (input): The name of the file associated with the script. This is often set to “”.

DESCRIPTION

The Tcl_SetStartupScript procedure allows the caller to specify a Tcl script to be evaluated by the Tcl_Main procedure. Tcl_Main is the default main program for Tcl applications that do not provide their own.

The script is evaluated after any Tcl application-specific initialization (provided by Tcl_AppInit) and before the main event loop is entered. If the application is running in non-interactive mode, the script is evaluated after the main event loop has terminated.

The script argument is a string containing the Tcl commands to be evaluated. The fileName argument is a string naming the file from which the script was loaded. This name is used in error messages and for managing the script’s namespace. It is often set to “” when the script is not loaded from a file.

If the procedure is successful, it returns a pointer to a static string containing the name of the startup script file. This is typically the same value as the fileName argument.

If an error occurs during the setup of the startup script, Tcl_SetStartupScript will return NULL. The error message will be left in the interpreter’s result.

The Tcl_Main procedure is typically called from the main function of a Tcl application. It handles command-line arguments, calls Tcl_AppInit (if provided), and then enters the Tcl event loop. The startup script specified by Tcl_SetStartupScript is evaluated after Tcl_AppInit and before the event loop begins. The script is executed using Tcl_EvalFile.

In interactive mode, the startup script is evaluated before the main event loop is entered. In non-interactive mode, after the main event loop terminates, the exit command is evaluated.

The startup script is executed in the global namespace.

The Tcl_Main procedure may use the startup script in either interactive or non-interactive mode. In non-interactive mode, the startup script is evaluated *after* the main event loop has terminated and before the exit command is evaluated. This allows the script to perform any necessary cleanup operations or finalizations.

The command evaluated after the main loop procedure (if any) returns. In non-interactive mode, after Tcl_Main evaluates the startup script, and the main loop procedure (if any) returns, Tcl_Main will also evaluate the exit command.
