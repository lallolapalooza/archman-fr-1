ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour le rapport d'erreurs et pour rechercher un canal enregistré en son sein.
const char *fileName (in)
Le nom d'un fichier local ou réseau.
const char *mode (in)
Spécifie comment le fichier doit être accédé. Peut prendre n'importe laquelle des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (in)
Indicateurs de permissions de style POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront appliquées au fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans option de la commande Tcl exec.
int flags (in)
Spécifie la disposition des descripteurs stdio dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, l'entrée standard du premier processus enfant du pipe est le canal du pipe, sinon elle est identique à l'entrée standard du processus appelant ; idem pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, alors le pipe peut rediriger les descripteurs stdio pour remplacer les descripteurs stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, de telles redirections provoquent une erreur.
ClientData handle (in)
Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, il s'agit d'un descripteur de fichier, pour Windows, il s'agit d'un HANDLE.
int readOrWrite (in)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (in)
Le motif à faire correspondre, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl pour l'entrée ou la sortie. Doit avoir été la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker les caractères lus depuis le canal. Si l'encodage du canal est binary, cela équivaut au nombre d'octets à lire depuis le canal.
int charsToRead (in)
Le nombre de caractères à lire depuis le canal. Si l'encodage du canal est binary, cela équivaut au nombre d'octets à lire depuis le canal.
int appendFlag (in)
Si différent de zéro, les données lues depuis le canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (out)
Un tampon dans lequel stocker les octets lus depuis le canal.
int bytesToRead (in)
Le nombre d'octets à lire depuis le canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker la ligne lue depuis le canal. La ligne lue sera ajoutée à la valeur courante de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne dynamique Tcl dans laquelle stocker la ligne lue depuis le canal. Doit avoir été initialisé par l'appelant. La ligne lue sera ajoutée à toutes les données déjà présentes dans la chaîne dynamique.
const char *input (in)
L'entrée à ajouter à un tampon de canal.
int inputLen (in)
Longueur de l'entrée.
int addAtEnd (in)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon de canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera sorti vers le canal.
const char *charBuf (in)
Un tampon contenant les caractères à sortir vers le canal.
const char *byteBuf (in)
Un tampon contenant les octets à sortir vers le canal.
int bytesToWrite (in)
Le nombre d'octets à consommer de charBuf ou byteBuf et à sortir vers le canal.
Tcl_WideInt offset (in)
Distance à laquelle déplacer le point d'accès dans le canal où la prochaine opération d'entrée ou de sortie sera appliquée, mesurée en octets à partir de la position donnée par seekMode. Peut être positif ou négatif.
int seekMode (in)
Par rapport à quel point chercher ; utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs légales sont SEEK_SET, SEEK_CUR, et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) à laquelle tronquer le canal.
const char *optionName (in)
Le nom d'une option applicable à ce canal, telle que -blocking. Peut avoir n'importe laquelle des valeurs acceptées par la commande fconfigure.
Tcl_DString *optionValue (in)
Où stocker la valeur d'une option ou une liste de toutes les options et leurs valeurs. Doit avoir été initialisé par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des périphériques et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie mises en tampon sur une variété de types de fichiers, de sockets et de périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée du manuel pour Tcl_CreateChannel. Le mécanisme de canaux fournit un système de mise en tampon calqué sur les E/S standard d'Unix, et il permet également les E/S non bloquantes sur les canaux.

Les procédures décrites dans cette entrée de manuel comprennent les API C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canaux et de la manière d'implémenter des pilotes de canaux pour de nouveaux types de canaux, consultez l'entrée du manuel pour Tcl_CreateChannel.

TCL_OPENFILECHANNEL

La procédure Tcl_OpenFileChannel ouvre un fichier nommé par fileName et lui associe un canal Tcl. Le comportement est similaire à celui de la commande Tcl open. Les arguments mode et permissions sont les mêmes que ceux de la commande open. Si le fichier est ouvert avec succès, un nouveau canal est renvoyé, sinon NULL est renvoyé et interp->result contient une description de l'erreur.

TCL_OPENCOMMANDCHANNEL

La procédure Tcl_OpenCommandChannel crée un pipeline de commandes et retourne un canal Tcl qui peut être utilisé pour communiquer avec le pipeline. L'argument argv est une liste de chaînes de caractères qui sont le nom de la commande suivie de ses arguments. Le comportement est similaire à celui de la commande Tcl exec.

L'argument flags spécifie la disposition des descripteurs standard pour le premier processus enfant du pipeline. Les indicateurs possibles sont TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE.

Si le canal est créé avec succès, un nouveau canal est renvoyé, sinon NULL est renvoyé et interp->result contient une description de l'erreur.

TCL_MAKEFILECHANNEL

La procédure Tcl_MakeFileChannel crée un nouveau canal Tcl à partir d'un descripteur de fichier existant handle. Les readOrWrite peuvent être une combinaison de TCL_READABLE et TCL_WRITABLE pour indiquer ce qui est valide pour le canal. La procédure renvoie le nouveau canal Tcl.

Sur Unix, handle est un descripteur de fichier entier. Sur Windows, handle est un HANDLE de type HANDLE.

TCL_GETCHANNEL

La procédure Tcl_GetChannel retourne un pointeur vers le canal Tcl nommé channelName. Si modePtr est non NULL, alors il sera déréférencé et se verra attribuer une combinaison OR des indicateurs TCL_READABLE et TCL_WRITABLE pour indiquer si le canal est ouvert en lecture et/ou en écriture. Si le canal nommé ne peut être trouvé ou est fermé, NULL est renvoyé et interp->result est défini pour décrire l'erreur.

TCL_GETCHANNELNAMES

La procédure Tcl_GetChannelNames retourne une liste de tous les canaux Tcl actuellement enregistrés dans l'interpréteur interp. La liste est retournée comme une chaîne de caractères dans interp->result. Chaque nom de canal est séparé par un espace. Si aucun canal n'est enregistré, la chaîne vide est retournée.

TCL_GETCHANNELNAMESEX

La procédure Tcl_GetChannelNamesEx retourne une liste de tous les canaux Tcl actuellement enregistrés dans l'interpréteur interp qui correspondent au pattern spécifié. Le motif est comparé à chaque nom de canal à l'aide de Tcl_StringMatch. La liste est retournée comme une chaîne de caractères dans interp->result. Chaque nom de canal est séparé par un espace. Si aucun canal ne correspond, la chaîne vide est retournée. Si pattern est NULL, cela se comporte comme Tcl_GetChannelNames.

TCL_REGISTERCHANNEL

La procédure Tcl_RegisterChannel enregistre un canal Tcl existant channel dans l'interpréteur interp. Cela rend le canal disponible pour les commandes Tcl telles que fconfigure et close, en utilisant le nom de canal qui a été donné lors de la création du canal (par exemple, par Tcl_OpenFileChannel).

TCL_UNREGISTERCHANNEL

La procédure Tcl_UnregisterChannel désenregistre un canal Tcl existant channel de l'interpréteur interp. Après cette opération, le canal n'est plus accessible via les commandes Tcl. La procédure renvoie 0 en cas de succès, et 1 en cas d'échec (par exemple, si le canal n'est pas enregistré).

TCL_DETACHCHANNEL

La procédure Tcl_DetachChannel dissocie un canal Tcl de l'interpréteur interp. Le canal n'est plus accessible par les commandes Tcl après cette opération. Le descripteur de fichier sous-jacent n'est pas fermé. La procédure renvoie 0 en cas de succès, et 1 en cas d'échec.

TCL_ISTANDARDCHANNEL

La procédure Tcl_IsStandardChannel renvoie 1 si le canal spécifié est l'un des canaux standard (entrée, sortie ou erreur standard) créés par Tcl, et 0 sinon.

TCL_CLOSE

La procédure Tcl_Close ferme un canal Tcl. Elle libère toutes les ressources associées au canal et invalide toute référence future au canal. Si le canal est déjà fermé, cette procédure ne fait rien. La procédure renvoie 0 en cas de succès, et 1 en cas d'échec (par exemple, si une erreur survient lors de la fermeture du descripteur de fichier sous-jacent).

TCL_READCHARS

La procédure Tcl_ReadChars lit jusqu'à charsToRead caractères depuis le canal spécifié et les place dans la valeur Tcl pointée par readObjPtr. Si appendFlag est différent de zéro, les données lues sont ajoutées à la valeur existante ; sinon, elles remplacent la valeur existante. La procédure renvoie le nombre de caractères réellement lus. Une valeur de retour négative indique une erreur.

TCL_READ

La procédure Tcl_Read lit jusqu'à bytesToRead octets depuis le canal spécifié et les place dans le tampon readBuf. Le tampon doit être suffisamment grand pour contenir le nombre d'octets spécifié. La procédure renvoie le nombre d'octets réellement lus. Une valeur de retour négative indique une erreur.

TCL_GETSOBJ

La procédure Tcl_GetsObj lit des caractères depuis le canal jusqu'à ce qu'un caractère de nouvelle ligne soit rencontré, ou que la fin du fichier soit atteinte. La ligne lue (sans le caractère de nouvelle ligne) est placée dans la valeur Tcl pointée par lineObjPtr. La procédure renvoie le nombre de caractères réellement lus (sans compter le caractère de nouvelle ligne). Une valeur de retour négative indique une erreur.

TCL_GETS

La procédure Tcl_Gets lit des caractères depuis le canal jus- qu'à ce qu'un caractère de nouvelle ligne soit rencontré, ou que la fin du fichier soit atteinte. La ligne lue (sans le caractère de nouvelle ligne) est copiée dans la chaîne dynamique lineRead. La procédure renvoie le nom- bre de caractères réellement lus (sans compter le caractère de nouvelle ligne). Une valeur de retour négative indique une erreur.

TCL_UNGETS

La procédure Tcl_Ungets ajoute la chaîne input de lon- gueur inputLen au début ou à la fin du tampon d'entrée du canal. Si addAtEnd est différent de zéro, l'entrée est ajoutée à la fin ; sinon, elle est ajoutée au début. La procédure renvoie le nombre de caractè- res ajoutés. Une valeur de retour négative indique une erreur.

TCL_WRITEOBJ

La procédure Tcl_WriteObj écrit le contenu de la valeur Tcl pointée par writeObjPtr dans le canal spécifié. La procédure renvoie le nombre d'octets réellement écrits. Une valeur de retour négative indique une erreur.

TCL_WRITECHARS

La procédure Tcl_WriteChars écrit jusqu'à bytesToWrite caractères de la mémoire tampon charBuf dans le canal spécifié. La procédure renvoie le nombre d'octets réellement écrits. Une valeur de retour négative indique une erreur.

TCL_WRITE

La procédure Tcl_Write écrit jusqu'à bytesToWrite octets de la mémoire tampon byteBuf dans le canal spécifié. La procédure renvoie le nombre d'octets réellement écrits. Une valeur de retour négative indique une erreur.

TCL_READRAW

La procédure Tcl_ReadRaw lit jusqu'à bytesToRead octets depuis le canal spécifié et les place dans le tampon readBuf. Contrairement à Tcl_Read, cette procédure ne prend pas en compte l'encodage du canal et lit les octets bruts.

TCL_WRITERAW

La procédure Tcl_WriteRaw écrit jusqu'à bytesToWrite octets de la mémoire tampon byteBuf dans le canal spécifié. Contrairement à Tcl_Write, cette procédure ne prend pas en compte l'encodage du canal et écrit les octets bruts.

TCL_EOF

La procédure Tcl_Eof renvoie 1 si la fin du fichier a été atteinte sur le canal spécifié, et 0 sinon. Si une erreur s'est produite lors de la lecture, la procédure renvoie -1.

TCL_FLUSH

La procédure Tcl_Flush force l'écriture de toutes les données mises en tampon dans le canal spécifié. La procédure renvoie 0 en cas de succès, et 1 en cas d'échec.

TCL_INPUTBLOCKED

La procédure Tcl_InputBlocked renvoie 1 si une tentative de lecture sur le canal spécifié bloquerait, et 0 sinon. Ceci est utile pour les opérations d'E/S non bloquantes.

TCL_INPUTBUFFERED

La procédure Tcl_InputBuffered renvoie le nombre d'octets en attente dans le tampon d'entrée du canal spécifié.

TCL_OUTPUTBUFFERED

La procédure Tcl_OutputBuffered renvoie le nombre d'octets en attente dans le tampon de sortie du canal spécifié.

TCL_SEEK

La procédure Tcl_Seek modifie le point d'accès courant du canal spécifié. L'argument offset spécifie le nombre d'octets à déplacer, et seekMode spécifie par rapport à quel point le déplacement est effectué (SEEK_SET pour le début du fichier, SEEK_CUR pour la position courante, SEEK_END pour la fin du fichier). La procédure renvoie la nouvelle position d'accès en octets depuis le début du fichier. Une valeur de retour négative indique une erreur.

TCL_TELL

La procédure Tcl_Tell renvoie la position d'accès courante du canal spécifié en octets depuis le début du fichier. Une valeur de retour négative indique une erreur.

TCL_TRUNCATECHANNEL

La procédure Tcl_TruncateChannel tronque le canal spécifié à la longueur donnée par length. Seules les opérations sur les fichiers qui supportent la troncature peuvent utiliser cette procédure. La procédure renvoie 0 en cas de succès, et 1 en cas d'échec.

TCL_GETCHANNELOPTION

La procédure Tcl_GetChannelOption récupère la valeur de l'option nommée optionName pour le canal spécifié. La valeur est stockée dans la chaîne dynamique optionValue. La procédure renvoie 0 en cas de succès, et 1 en cas d'échec.

TCL_SETCHANNELOPTION

La procédure Tcl_SetChannelOption définit la valeur de l'option nommée optionName pour le canal spécifié à la nouvelle valeur newValue. La procédure renvoie 0 en cas de succès, et 1 en cas d'échec.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et renvoie un handle de canal qui peut être utilisé pour effectuer des entrées et sorties sur le fichier. Cette API est calquée sur la fonction fopen de la bibliothèque standard Unix de lecture/écriture. La syntaxe et la signification de tous les arguments sont similaires à celles de la commande Tcl open lorsqu'elle ouvre un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. À partir de Tcl 8.4, l'API basée sur des valeurs Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel partout où cela est possible.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'affecte également en tant que remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctionnalités des commandes exec et open. Elle crée une séquence de processus subsidiaires spécifiés par les arguments argv et argc et renvoie un canal qui peut être utilisé pour communiquer avec ces processus subsidiaires. L'argument flags indique le type de communication qui existe avec la séquence de commandes.

Si TCL_STDIN est activé, le canal d'entrée standard du premier processus subsidiaire est lié au canal : écrire dans le canal fournit l'entrée au processus subsidiaire. Si TCL_STDIN n'est pas activé, le canal d'entrée standard du premier processus subsidiaire sera le même que l'entrée standard de cette application. Si TCL_STDOUT est activé, la sortie standard du dernier processus subsidiaire peut être lue depuis le canal ; sinon, elle va à la sortie standard de cette application. Si TCL_STDERR est activé, la sortie d'erreur standard de tous les processus subsidiaires est renvoyée au canal et génère une erreur lors de la fermeture du canal ; sinon, elle va à la sortie d'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas activé, argc et argv peuvent rediriger les handles d'entrée/sortie standard pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est activé, c'est une erreur pour argc et argv de rediriger les canaux d'entrée/sortie standard lorsque TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel renvoie NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'affecte également en tant que remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un handle de fichier existant et spécifique au système. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'affecte également en tant que remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel renvoie un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur dans interp. S'il n'existe aucun canal enregistré sous ce nom dans l'interpréteur, il renvoie NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent le nom des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms en fonction du pattern. Si pattern est NULL, aucun filtrage ne sera effectué. La valeur de retour est TCL_OK s'il n'y a eu aucune erreur lors de l'écriture dans le résultat, sinon TCL_ERROR, et le message d'erreur reste dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal aux canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur peuvent faire référence au canal par le nom donné lors de l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close sur le canal ; le canal est automatiquement fermé lorsqu'il est désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur peut appeler Tcl_RegisterChannel avec interp comme NULL, indiquant qu'il souhaite conserver une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et ne sera fermé que lorsqu'un nombre d'appels à Tcl_UnregisterChannel correspondant aura été effectué. Cela permet au code exécuté en dehors de tout interpréteur de conserver une référence sûre à un canal qui est également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code qui gère les canaux standard. Si les canaux standard n'ont pas été initialisés avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un aperçu des canaux standard et du comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel supprime un canal des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Si cette opération supprime la dernière inscription du canal dans un interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur peut appeler Tcl_UnregisterChannel avec interp comme NULL, indiquant à Tcl qu'il ne conserve plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il est fermé maintenant. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel sauf qu'il ferme également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel supprime un canal des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Au-delà de cela, cette commande n'a pas d'autre effet. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin), et renverra TCL_ERROR si on lui passe l'un de ces canaux.

Le code non associé à un interpréteur peut appeler Tcl_DetachChannel avec interp comme NULL, indiquant à Tcl qu'il ne conserve plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il n'est pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel vérifie si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. Si c'est le cas, il renvoie 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou validés de quelque manière que ce soit.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lorsque Tcl_Close est appelé. Le tampon de sortie est vidé avant la destruction du canal, et tout tampon d'entrée est ignoré. S'il s'agit d'un canal bloquant, l'appel ne renvoie pas tant que toutes les données tamponnées n'ont pas été envoyées au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a des données tamponnées qui ne peuvent pas être écrites sans blocage, l'appel renvoie immédiatement ; la sortie est vidée en arrière-plan et le canal est fermé lorsque toutes les données tamponnées ont été traitées. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé correctement, Tcl_Close renvoie TCL_OK. Si une erreur se produit, il renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : Il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré avec Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour les détails. Si le canal a été donné comme chan dans un appel à Tcl_RegisterChannel, vous devriez utiliser Tcl_UnregisterChannel, qui appelle Tcl_Close en interne lorsque tous les appels à Tcl_RegisterChannel ont été mis en correspondance par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, les convertit en UTF-8 selon l'encodage du canal et stocke les données produites dans la représentation de readObjPtr. La valeur renvoyée par Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit pendant la lecture, la valeur renvoyée est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_READCHARS, TCL_READOBJ, ET TCL_READ

Tcl_ReadChars lit charsToRead caractères du canal channel et les stocke dans l'objet Tcl readObjPtr. Si charsToRead est égal à -1, la commande lit tous les caractères actuellement disponibles (mode non bloquant) ou tout jusqu'à eof (mode bloquant).

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé étaient disponibles. C'est ce qu'on appelle une lecture courte. En mode bloquant, cela ne peut se produire qu'à la fin du fichier. En mode non bloquant, une lecture courte peut également se produire s'il n'y a pas assez d'entrées actuellement disponibles : Tcl_ReadChars retourne un compte réduit plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour savoir laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les diverses représentations de fin de ligne en la représentation interne canonique \n conformément au mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les divers modes spécifiques à la plateforme sont décrits dans l'entrée de manuel de la commande Tcl fconfigure.

Par optimisation des performances, lors de la lecture d'un canal avec le codage binary, les octets ne sont pas convertis en UTF-8 lors de leur lecture. Ils sont plutôt stockés dans la représentation interne de readObjPtr sous forme de tableau d'octets. La représentation sous forme de chaîne de cette valeur ne sera construite que si nécessaire (par exemple, suite à un appel à Tcl_GetStringFromObj). De cette façon, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de la conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'elle n'effectue pas de conversions d'encodage, quel que soit l'encodage du canal. Elle est dépréciée et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Elle consomme des octets du channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par un octet nul. Son contenu est valide à partir de la position zéro jusqu'à, et sans inclure, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas l'empilement. Alors que Tcl_Read (et les autres fonctions de l'API) obtiennent toujours leurs données du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_ReadRaw ne le fait pas. Cette fonction est donc uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données du canal inférieur dans la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, en convertissant les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée ait été vue. Si l'encodage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception du ou des caractères de fin de ligne terminaux, sont ajoutés à la représentation sous forme de chaîne de lineObjPtr. Le ou les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. En cas d'erreur, Tcl_GetsObj retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj retourne également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenant pas de caractère de fin de ligne. Lorsque -1 est retourné, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité de l'entrée.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique donnée par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, soit à la tête, soit à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si channel a un indicateur d'EOF « collant » défini, aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets retourne inputLen ou -1 en cas d'erreur.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données caractères à charBuf. Les caractères UTF-8 du tampon sont convertis vers l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars attend que charBuf soit terminé par un octet nul et sort tout jusqu'à l'octet nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal à none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un compte du nombre d'octets qui ont été acceptés pour la sortie vers le canal. C'est soit un nombre positif pour indiquer le succès, soit -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme conformément à l'option -translation du canal. Ceci est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'il accepte une valeur Tcl dont le contenu sera sorti vers le canal. Les caractères UTF-8 de la représentation sous forme de chaîne de writeObjPtr sont convertis vers l'encodage du canal et mis en file d'attente pour la sortie vers channel. Par optimisation des performances, lors de l'écriture dans un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lorsqu'ils sont écrits. Au lieu de cela, les octets de la représentation interne de writeObjPtr sous forme de tableau d'octets sont écrits dans le canal. La représentation sous forme de tableau d'octets de la valeur sera construite si elle est nécessaire. De cette façon, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de la conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'elle n'effectue pas de conversions d'encodage, quel que soit l'encodage du canal. Elle est dépréciée et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Elle accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write attend que byteBuf soit terminé par un octet nul et sort tout jusqu'à l'octet nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée vers le canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_WriteRaw ne le fait pas. Cette fonction est donc uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation dans le canal inférieur.

TCL_FLUSH

Tcl_Flush provoque l'écriture de toutes les données de sortie tamponnées pour le channel dans son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données tamponnées n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal est non bloquant ; il démarre une opération de vidage en arrière-plan qui écrira les données tamponnées vers le canal éventuellement, aussi vite que le canal peut les absorber.

La valeur de retour est normalement TCL_OK. En cas d'erreur, Tcl_Flush retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données ultérieures seront lues ou écrites. La sortie tamponnée est vidée vers le canal et l'entrée tamponnée est rejetée, avant l'opération de déplacement.

Tcl_Seek retourne normalement le nouveau point d'accès. En cas d'erreur, Tcl_Seek retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut avoir été déplacé ou non.

TCL_TELL

Tcl_Tell retourne le point d'accès actuel pour un canal. La valeur retournée est -1 si le canal ne prend pas en charge le déplacement.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent de channel à une longueur donnée de length octets. Il retourne TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, c'est le nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue.

D'autres options peuvent être ajoutées par chaque type de canal. Ces options spécifiques au type de canal sont décrites dans l'entrée du manuel pour la commande Tcl qui crée un canal de ce type ; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans l'entrée du manuel pour la commande Tcl socket. La procédure retourne normalement TCL_OK. Si une erreur se produit, elle retourne TCL_ERROR et appelle Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit une nouvelle valeur newValue pour une option optionName sur channel. La procédure retourne normalement TCL_OK. Si une erreur se produit, elle retourne TCL_ERROR ; de plus, si interp n'est pas NULL, Tcl_SetChannelOption laisse un message d'erreur dans le résultat de l'interpréteur.

TCL_EOF

Tcl_Eof retourne une valeur non nulle si channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked retourne une valeur non nulle si channel est en mode non bloquant et que la dernière opération d'entrée a retourné moins de données que demandé car il n'y avait pas suffisamment de données disponibles. L'appel retourne toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered retourne le nombre d'octets d'entrée actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en lecture, cette fonction retourne toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered retourne le nombre d'octets de sortie actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en écriture, cette fonction retourne toujours zéro.

PROBLÈMES DE PLATEFORME

Les descripteurs retournés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que retourné par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel, ou Tcl_MakeFileChannel. D'autres types de canaux peuvent retourner un type de descripteur différent sur les plateformes Windows.
