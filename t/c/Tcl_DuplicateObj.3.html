INTRODUCTION

Cette page de manuel présente un aperçu des valeurs Tcl (appelées Tcl_Obj pour des raisons historiques) et de leur utilisation. Elle décrit également les procédures génériques de gestion des valeurs Tcl. Ces procédures sont utilisées pour créer et copier des valeurs, ainsi que pour incrémenter et décrémenter le nombre de références (pointeurs) vers ces valeurs. Les procédures sont utilisées en conjonction avec celles qui opèrent sur des types de valeurs spécifiques tels que Tcl_GetIntFromObj et Tcl_ListObjAppendElement. Les procédures individuelles sont décrites avec les structures de données qu'elles manipulent.

Les valeurs dual-ported de Tcl fournissent un mécanisme à usage général pour stocker et échanger des valeurs Tcl. Elles remplacent largement l'utilisation de chaînes de caractères dans Tcl. Par exemple, elles sont utilisées pour stocker les valeurs des variables, les arguments de commande, les résultats de commande et les scripts. Les valeurs Tcl se comportent comme des chaînes de caractères mais conservent également une représentation interne qui peut être manipulée plus efficacement. Par exemple, une liste Tcl est maintenant représentée comme une valeur qui contient la représentation sous forme de chaîne de caractères de la liste ainsi qu'un tableau de pointeurs vers les valeurs de chaque élément de la liste. Les valeurs dual-ported évitent la plupart des conversions de type à l'exécution. Elles améliorent également la vitesse de nombreuses opérations car une représentation appropriée est immédiatement disponible. Le compilateur lui-même utilise des valeurs Tcl pour mettre en cache les bytecodes résultant de la compilation des scripts.

Les deux représentations sont des caches l'une de l'autre et sont calculées à la demande. C'est-à-dire que chaque représentation n'est calculée que lorsque nécessaire, elle est calculée à partir de l'autre représentation et, une fois calculée, elle est enregistrée. De plus, un changement dans une représentation invalide l'autre. Par exemple, un programme Tcl effectuant des calculs entiers peut opérer directement sur la représentation entière machine interne d'une variable sans avoir à convertir constamment entre entiers et chaînes de caractères. Ce n'est que lorsqu'il a besoin d'une chaîne de caractères représentant la valeur de la variable, par exemple pour l'imprimer, que le programme régénérera la représentation sous forme de chaîne à partir de l'entier. Bien que les valeurs contiennent une représentation interne, leurs sémantiques sont définies en termes de chaînes de caractères : une chaîne de caractères à jour peut toujours être obtenue, et tout changement apporté à la valeur sera reflété dans cette chaîne lorsque la représentation sous forme de chaîne de caractères de la valeur sera récupérée. En raison de cette invalidation et régénération de la représentation, il est dangereux pour les développeurs d'extensions d'accéder directement aux champs de Tcl_Obj. Il est préférable d'accéder aux informations de Tcl_Obj en utilisant des procédures telles que Tcl_GetStringFromObj et Tcl_GetString.

Les valeurs sont allouées sur le tas et sont référencées à l'aide d'un pointeur vers leur structure Tcl_Obj. Les valeurs sont partagées autant que possible. Cela réduit considérablement les besoins en stockage car certaines valeurs, comme les longues listes, sont très volumineuses. De plus, la plupart des valeurs Tcl ne sont que lues et jamais modifiées. C'est particulièrement vrai pour les arguments de procédure, qui peuvent être partagés entre l'appelant et la procédure appelée. L'affectation et la liaison des arguments se font simplement en affectant un pointeur vers la valeur. Le comptage de références est utilisé pour déterminer quand il est sûr de récupérer le stockage d'une valeur.

Les valeurs Tcl sont typées. La représentation interne d'une valeur est contrôlée par son type. Plusieurs types sont prédéfinis dans le noyau Tcl, y compris les entiers, les flottants, les listes et les bytecodes. Les développeurs d'extensions peuvent étendre l'ensemble des types en définissant leurs propres structures Tcl_ObjType.

LA STRUCTURE TCL_OBJ

Chaque valeur Tcl est représentée par une structure Tcl_Obj qui est définie comme suit.

typedef struct Tcl_Obj {
    int refCount;
    char *bytes;
    int length;
    const Tcl_ObjType *typePtr;
    union {
        long longValue;
        double doubleValue;
        void *otherValuePtr;
        Tcl_WideInt wideValue;
        struct {
            void *ptr1;
            void *ptr2;
        } twoPtrValue;
        struct {
            void *ptr;
            unsigned long value;
        } ptrAndLongRep;
    } internalRep;
} Tcl_Obj;

Les membres bytes et length ensemble contiennent la représentation sous forme de chaîne UTF-8 d'une valeur, qui est une chaîne comptée ne contenant pas d'octets nuls (les caractères nuls UTF-8 doivent être encodés sous forme d'une séquence de deux octets : 192, 128.) bytes pointe vers le premier octet de la représentation sous forme de chaîne. Le membre length donne le nombre d'octets. Le tableau d'octets doit toujours avoir un octet nul après le dernier octet de données, à l'offset length ; cela permet de traiter les représentations sous forme de chaîne comme des chaînes C classiques terminées par un caractère nul. Les programmes C utilisent Tcl_GetStringFromObj et Tcl_GetString pour obtenir la représentation sous forme de chaîne d'une valeur. Si bytes est NULL, la représentation sous forme de chaîne est invalide.

Le type d'une valeur gère sa représentation interne. Le membre typePtr pointe vers la structure Tcl_ObjType qui décrit le type. Si typePtr est NULL, la représentation interne est invalide.

Le membre de l'union internalRep contient la représentation interne d'une valeur. Il s'agit soit d'un entier (long), d'un nombre à virgule flottante de précision double, d'un pointeur vers une valeur contenant des informations supplémentaires nécessaires au type de la valeur pour représenter la valeur, d'un entier Tcl_WideInt, de deux pointeurs arbitraires, ou d'une paire composée d'un entier unsigned long et d'un pointeur.

Le membre refCount est utilisé pour savoir quand il est sûr de libérer le stockage d'une valeur. Il contient le nombre de références actives vers la valeur. Le maintien du bon comptage de références est une responsabilité clé des développeurs d'extensions. Le comptage de références est discuté plus bas dans la section GESTION DU STOCKAGE DES VALEURS.

Bien que les développeurs d'extensions puissent accéder directement aux membres d'une structure Tcl_Obj, il est beaucoup préférable d'utiliser les procédures et macros appropriées. Par exemple, les développeurs d'extensions ne devraient jamais lire ou mettre à jour refCount directement ; ils devraient utiliser des macros telles que Tcl_IncrRefCount et Tcl_IsShared à la place.

Une propriété clé des valeurs Tcl est qu'elles détiennent deux représentations. Une valeur commence généralement par ne contenir qu'une représentation sous forme de chaîne : elle n'a pas de type et a un typePtr NULL. Une valeur contenant une chaîne vide ou une copie d'une chaîne spécifiée est créée à l'aide de Tcl_NewObj ou Tcl_NewStringObj respectivement. La valeur sous forme de chaîne d'une valeur est obtenue avec Tcl_GetStringFromObj ou Tcl_GetString et modifiée avec Tcl_SetStringObj. Si la valeur est ensuite passée à une procédure comme Tcl_GetIntFromObj qui nécessite une représentation interne spécifique, la procédure en créera une et définira le typePtr de la valeur. La représentation interne est calculée à partir de la représentation sous forme de chaîne. Les deux représentations d'une valeur sont des duales l'une de l'autre : les changements apportés à l'une sont reflétés dans l'autre. Par exemple, Tcl_ListObjReplace modifiera la représentation interne d'une valeur et le prochain appel à Tcl_GetStringFromObj ou Tcl_GetString reflètera ce changement.

Les représentations sont recalculées à la demande pour des raisons d'efficacité. Un changement apporté à une représentation par une procédure telle que Tcl_ListObjReplace n'est pas immédiatement reflété dans l'autre représentation. Au lieu de cela, l'autre représentation est marquée comme invalide afin qu'elle ne soit régénérée que si elle est nécessaire plus tard. La plupart des programmeurs C n'ont jamais à se soucier de la façon dont cela est fait et utilisent simplement des procédures telles que Tcl_GetBooleanFromObj ou Tcl_ListObjIndex. Les programmeurs qui implémentent leurs propres types de valeurs doivent vérifier les représentations invalides et marquer les représentations comme invalides lorsque nécessaire. La procédure Tcl_InvalidateStringRep est utilisée pour marquer la représentation sous forme de chaîne d'une valeur comme invalide et pour libérer tout stockage associé à l'ancienne représentation sous forme de chaîne.

Une valeur nouvellement créée par Tcl_NewObj ou Tcl_NewStringObj a un refCount de 0. La macro Tcl_IncrRefCount incrémente le compteur de références lorsqu'une nouvelle référence à la valeur est créée. La macro Tcl_DecrRefCount décrémente le compteur lorsqu'une référence n'est plus nécessaire et, si le compteur de références de la valeur tombe à zéro, libère son stockage. Une valeur partagée par différents codes ou structures de données a un refCount supérieur à 1. EXEMPLE DU CYCLE DE VIE DUNE VALEUR

À titre d'exemple du cycle de vie d'une valeur, considérons la séquence de commandes suivante :

set x 123

Cela attribue à x une valeur non typée dont le membre bytes pointe vers 123 et le membre length contient 3. Le membre typePtr de la valeur est NULL.

puts "x est $x"

La représentation sous forme de chaîne de x est valide (puisque bytes n'est pas NULL) et est récupérée pour la commande.

incr x

La commande incr récupère d'abord un entier de la valeur de x en appelant Tcl_GetIntFromObj. Cette procédure vérifie si la valeur est déjà une valeur entière. Comme ce n'est pas le cas, elle convertit la valeur en définissant la représentation interne de la valeur à l'entier 123 et en faisant pointer le membre typePtr de la valeur vers la structure Tcl_ObjType entière. Les deux représentations sont maintenant valides. incr incrémente la représentation entière interne de la valeur, puis invalide sa représentation sous forme de chaîne (en appelant Tcl_InvalidateStringRep) car la représentation sous forme de chaîne ne correspond plus à la représentation interne.

puts "x est maintenant $x"

La représentation sous forme de chaîne de la valeur de x est nécessaire et est recalculée. La représentation sous forme de chaîne est maintenant 124 et les deux représentations sont à nouveau valides.

GESTION DU STOCKAGE DES VALEURS

Les valeurs Tcl sont allouées sur le tas et sont partagées autant que possible pour réduire les exigences de stockage. Le comptage de références est utilisé pour déterminer quand une valeur n'est plus nécessaire et peut être libérée en toute sécurité. Une valeur nouvellement créée par Tcl_NewObj ou Tcl_NewStringObj a un refCount de 0. La macro Tcl_IncrRefCount incrémente le compteur de références lorsqu'une nouvelle référence à la valeur est créée. La macro Tcl_DecrRefCount décrémente le compteur lorsqu'une référence n'est plus nécessaire et, si le compteur de références de la valeur tombe à zéro, libère son stockage. Une valeur partagée par différents codes ou structures de données a un refCount supérieur à 1. L'incrémentation du compteur de références d'une valeur garantit qu'elle ne sera pas libérée trop tôt ou que sa valeur ne sera pas modifiée accidentellement.

Par exemple, l'interpréteur de bytecode partage les valeurs d'arguments entre les procédures Tcl appelantes et appelées pour éviter d'avoir à copier les valeurs. Il attribue les valeurs des arguments de l'appel aux variables de paramètres formels de la procédure. Ce faisant, il appelle Tcl_IncrRefCount pour incrémenter le compteur de références de chaque argument, car il y a maintenant une nouvelle référence à celui-ci à partir du paramètre formel. Lorsque la procédure appelée retourne, l'interpréteur appelle Tcl_DecrRefCount pour décrémenter le compteur de références de chaque argument. Lorsque le compteur de références d'une valeur tombe à zéro ou moins, Tcl_DecrRefCount récupère son stockage. La plupart des procédures de commande n'ont pas à se soucier du comptage de références, car elles utilisent la valeur d'une valeur immédiatement et ne conservent pas de pointeur vers la valeur après leur retour. Cependant, si elles conservent un pointeur vers une valeur dans une structure de données, elles doivent veiller à incrémenter son compteur de références, car le pointeur conservé est une nouvelle référence.

Les procédures de commande qui modifient directement les valeurs, comme celles pour lappend et linsert, doivent veiller à copier une valeur partagée avant de la modifier. Elles doivent d'abord vérifier si la valeur est partagée en appelant Tcl_IsShared. Si la valeur est partagée, elles doivent copier la valeur en utilisant Tcl_DuplicateObj ; cela renvoie un nouveau duplicata de la valeur d'origine qui a un refCount de 0. Si la valeur n'est pas partagée, la procédure de commande possède la valeur et peut la modifier en toute sécurité directement. Par exemple, le code suivant apparaît dans la procédure de commande qui implémente linsert. Cette procédure modifie la valeur de liste qui lui est passée dans objv[1] en insérant objc-3 nouveaux éléments avant index.

listPtr = objv[1];
if (Tcl_IsShared(listPtr)) {
    listPtr = Tcl_DuplicateObj(listPtr);
} 
result = Tcl_ListObjReplace(interp, listPtr, index, 0,
( objc-3), &(objv[3]));
