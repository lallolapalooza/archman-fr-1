ARGUMENTS

Tcl_Interp *interp (entrée)
L'interpréteur dans lequel stocker les données compressées ou décompressées résultantes. Y sont également écrits les messages d'erreur. Pour Tcl_ZlibStreamInit, ceci peut être NULL pour créer un flux qui n'est pas lié à une commande.
int format (entrée)
Quel format de données compressées manipuler. Doit être l'un des suivants : TCL_ZLIB_FORMAT_ZLIB pour les données au format zlib, TCL_ZLIB_FORMAT_GZIP pour les données au format gzip, ou TCL_ZLIB_FORMAT_RAW pour les données compressées brutes. De plus, pour la décompression uniquement, TCL_ZLIB_FORMAT_AUTO peut également être choisi, ce qui permet de détecter automatiquement si les données compressées étaient au format zlib ou gzip.
Tcl_Obj *dataObj (entrée/sortie)
Une valeur de type tableau d'octets contenant les données à compresser ou décompresser, ou à laquelle les données extraites du flux sont ajoutées lorsqu'elles sont passées à Tcl_ZlibStreamGet.
int level (entrée)
Quel niveau de compression utiliser. Doit être un nombre de 0 à 9 ou l'une des valeurs suivantes : TCL_ZLIB_COMPRESS_NONE pour aucune compression, TCL_ZLIB_COMPRESS_FAST pour une compression rapide mais inefficace, TCL_ZLIB_COMPRESS_BEST pour une compression lente mais maximale, ou TCL_ZLIB_COMPRESS_DEFAULT pour le niveau recommandé par la bibliothèque zlib.
Tcl_Obj *dictObj (entrée/sortie)
Un dictionnaire qui contient, ou qui sera mis à jour pour contenir, une description de l'en-tête gzip associé aux données compressées. Utile uniquement lorsque le paramètre format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Si NULL est passé, un en-tête par défaut sera utilisé lors de la compression et l'en-tête sera ignoré (hormis les vérifications d'intégrité) lors de la décompression. Voir la section DICTIONNAIRE DES OPTIONS GZIP pour les détails sur le contenu de ce dictionnaire.
unsigned int initValue (entrée)
La valeur initiale pour l'algorithme de checksum.
int bufferSize (entrée)
Une indication sur la taille du tampon à utiliser pour recevoir les données. Utilisez 0 pour utiliser une estimation générique basée sur les données d'entrée.
unsigned char *bytes (entrée)
Un tableau d'octets sur lequel exécuter l'algorithme de checksum, ou NULL pour obtenir la valeur initiale recommandée pour l'algorithme de checksum.
int length (entrée)
Le nombre d'octets dans le tableau.
int mode (entrée)
Dans quel mode faire fonctionner le flux. Doit être soit TCL_ZLIB_STREAM_DEFLATE pour un flux de compression, soit TCL_ZLIB_STREAM_INFLATE pour un flux de décompression.
Tcl_ZlibStream *zshandlePtr (sortie)
Un pointeur vers une variable dans laquelle écrire le jeton abstrait pour le flux en cas de création réussie.
Tcl_ZlibStream zshandle (entrée)
Le jeton abstrait pour le flux à manipuler.
int flush (entrée)
Si et comment vider le flux après y avoir écrit les données. Doit être l'une des valeurs suivantes : TCL_ZLIB_NO_FLUSH si aucune vidange n'est à effectuer, TCL_ZLIB_FLUSH si les données actuellement compressées doivent être rendues disponibles pour accès à l'aide de Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si le flux doit être mis dans un état où le décompresseur peut récupérer en cas de corruption, ou TCL_ZLIB_FINALIZE pour s'assurer que le flux est terminé et que toute bande finale requise par le format est écrite.
int count (entrée)
Le nombre maximum d'octets à obtenir du flux, ou -1 pour obtenir tous les octets restants des tampons du flux.
Tcl_Obj *compDict (entrée)
Une valeur de type tableau d'octets représentant le dictionnaire de compression à utiliser avec le flux. Notez qu'il ne s'agit **pas** d'un dictionnaire Tcl, et il est recommandé de ne l'utiliser qu'avec des flux créés avec leur format défini à TCL_ZLIB_FORMAT_ZLIB, car les autres formats n'ont aucun mécanisme pour indiquer si un dictionnaire de compression était présent autre que l'échec lors de la décompression.

DESCRIPTION

Ces fonctions constituent l'interface entre la bibliothèque Tcl et la bibliothèque Zlib de Jean-loup Gailly et Mark Adler.

Tcl_ZlibDeflate et Tcl_ZlibInflate compressent et décompressent respectivement les données contenues dans l'argument dataObj, conformément aux arguments format et, pour la compression, level. Le dictionnaire dans le paramètre dictObj est utilisé pour transmettre des informations d'en-tête supplémentaires sur les données compressées lorsque le format de compression le prend en charge ; actuellement, le dictionnaire n'est utilisé que lorsque le paramètre format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Pour les détails du contenu du dictionnaire, voir la section DICTIONNAIRE DES OPTIONS GZIP ci-dessous. En cas de succès, les deux fonctions laissent les données compressées ou décompressées résultantes dans une valeur de type tableau d'octets qui est le résultat de l'interpréteur Tcl ; la valeur renvoyée est un code de résultat Tcl standard.

Tcl_ZlibAdler32 et Tcl_ZlibCRC32 calculent des checksums sur des tableaux d'octets, renvoyant le checksum calculé. Les checksums sont calculés de manière incrémentielle, permettant de traiter les données bloc par bloc, mais cela oblige l'appelant à maintenir le checksum actuel et à le passer comme paramètre initValue ; la valeur initiale à utiliser pour cela peut être obtenue en utilisant NULL pour le paramètre bytes au lieu d'un pointeur vers le tableau d'octets sur lequel calculer le checksum. Ainsi, l'utilisation typique dans le cas d'un bloc de données unique est la suivante :

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Notez que l'algorithme Adler-32 n'est pas un véritable checksum, mais plutôt un type de hachage connexe qui fonctionne mieux sur de longues données.

FLUX ZLIB

Tcl_ZlibStreamInit crée un flux de compression ou de décompression qui est lié à une commande Tcl, conformément à ses arguments, et fournit un jeton abstrait pour le flux et renvoie un code de résultat Tcl normal ; Tcl_ZlibStreamGetCommandName renvoie le nom de cette commande étant donné le jeton de flux, ou NULL si le flux n'a pas de commande. Les flux ne sont pas conçus pour être thread-safe ; chaque flux ne devrait jamais être utilisé qu'à partir du thread qui l'a créé. Lors de l'utilisation de flux gzip, un dictionnaire (champs tels que donnés dans la section DICTIONNAIRE DES OPTIONS GZIP ci-dessous) peut être fourni via le paramètre dictObj qui, lors de la compression, permet de contrôler les en-têtes générés, et lors de la décompression, permet de découvrir les en-têtes existants. Notez que le dictionnaire sera écrit lors de la décompression une fois que suffisamment de données auront été lues pour avoir un en-tête complet. Cela signifie que le dictionnaire doit être une valeur non partagée dans ce cas ; une valeur vide créée avec Tcl_NewObj est suggérée.

Une fois qu'un flux a été construit, Tcl_ZlibStreamPut est utilisé pour ajouter des données au flux et Tcl_ZlibStreamGet est utilisé pour récupérer des données du flux après traitement. Les deux renvoient des codes de résultat Tcl normaux et laissent un message d'erreur dans le résultat de l'interpréteur auquel le flux est enregistré en cas d'erreur (si une telle enregistrement a été effectuée). Avec Tcl_ZlibStreamPut, la valeur du tampon de données qui lui est passée ne doit pas être modifiée par la suite. Avec Tcl_ZlibStreamGet, la valeur du tampon de données qui lui est passée aura les octets de données ajoutés. Interne au flux, les données restent compressées afin de minimiser le coût de l'espace tampon.

Tcl_ZlibStreamEof renvoie une valeur booléenne indiquant si la fin des données décompressées a été atteinte.

Tcl_ZlibStreamSetCompressionDictionary est utilisé pour contrôler le dictionnaire de compression utilisé avec le flux, un dictionnaire de compression étant un tableau d'octets (comme pourrait être créé avec Tcl_NewByteArrayObj) qui est utilisé pour initialiser le moteur de compression au lieu de le laisser le créer au moment de la compression. La définition d'un dictionnaire de compression permet une compression plus efficace dans le cas où les données commencent régulièrement, mais nécessite que le compresseur et le décompresseur correspondent à la valeur à utiliser. Les dictionnaires de compression ne sont entièrement pris en charge que pour les données au format zlib ; lors de la compression, ils doivent être définis avant d'envoyer des données avec Tcl_ZlibStreamPut, et lors de la décompression, ils doivent être définis lorsque Tcl_ZlibStreamGet produit une erreur avec son -errorcode défini sur ZLIB NEED_DICT ; le code sera la somme de contrôle Adler-32 (voir Tcl_ZlibAdler32) du dictionnaire de compression recherché. (Notez que cela n'est valide que pour les flux au format zlib ; les flux gzip ignorent les dictionnaires de compression car la spécification du format ne les autorise pas, et les flux bruts ne génèrent une erreur de données que si le dictionnaire de compression est absent ou incorrect.)

Si vous souhaitez nettoyer un flux et le réutiliser pour une nouvelle action de compression ou de décompression, Tcl_ZlibStreamReset le fera et renverra un code Tcl normal pour indiquer s'il a réussi ; si le flux est enregistré avec un interpréteur, un message d'erreur sera laissé dans le résultat de l'interpréteur lorsque cette fonction renverra TCL_ERROR. Enfin, Tcl_ZlibStreamClose nettoiera le flux et supprimera la commande associée : utiliser Tcl_DeleteCommand sur la commande du flux est équivalent (lorsqu'une telle commande existe).

GZIP OPTIONS DICTIONARY

Le paramètre dictObj de Tcl_ZlibDeflate, Tcl_ZlibInflate et Tcl_ZlibStreamInit est utilisé pour passer un dictionnaire d'options sur lequel est décrit l'en-tête gzip dans les données compressées. Lors de la création des données compressées, le dictionnaire est lu et lors de la décompression des données compressées, le dictionnaire est écrit (dans ce cas, le paramètre dictObj doit faire référence à une valeur non partagée).

Les champs suivants dans la valeur du dictionnaire sont compris. Tous les autres champs sont ignorés. Aucun champ n'est requis lors de la création d'un flux au format gzip.

comment
Ceci stocke le champ commentaire de l'en-tête, s'il est présent. S'il n'est pas présent, aucun commentaire n'a été fourni (en décompression) ou un sera créé (en compression).
crc
Une valeur booléenne décrivant si une somme de contrôle CRC est calculée pour l'en-tête. Note : le programme gzip n'utilise ni n'autorise un CRC dans l'en-tête.
filename
Le nom du fichier qui a stocké les données non compressées. Celui-ci ne doit pas contenir de séparateurs de répertoire et doit être nettoyé avant d'être utilisé lors de la décompression avec file tail.
os
Le code du champ système d'exploitation de l'en-tête (s'il n'est pas la valeur inconnue). Voir RFC 1952 pour la signification de ces codes. En compression, si cette valeur n'est pas présente, le champ sera défini sur la valeur inconnue.
size
La taille des données non compressées. Ceci est ignoré en compression ; la taille des données compressées dépend de la quantité de données fournie au moteur de compression.
time
Le champ de temps de l'en-tête s'il n'est pas nul, attendu comme étant le moment où le fichier nommé par le champ filename a été modifié. Il convient de l'utiliser avec clock format. Lors de la création, la valeur correcte à utiliser est celle de clock seconds ou file mtime.
type
Le type des données non compressées (soit binary, soit text) si connu.

NOTES DE PORTABILITÉ

Ces fonctions se comporteront gracieusement si Tcl n'est pas lié à la bibliothèque zlib.
