ARGUMENTS

Tcl_Interp *interp (entrée)
Utilisé pour le rapport d'erreurs et pour rechercher un canal enregistré en lui.
const char *fileName (entrée)
Le nom d'un fichier local ou distant.
const char *mode (entrée)
Comment le fichier est-il accédé ? Peut avoir toute valeur permise pour l'argument mode de la commande open de Tcl.
int permissions (entrée)
Les drapeaux de permissions POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront définies sur le fichier créé.
int argc (entrée)
Le nombre d'éléments dans argv.
const char **argv (entrée)
Arguments pour construire un pipeline de commandes. Ces valeurs ont la même signification que les arguments non-switch dans la commande exec de Tcl.
int flags (entrée)
Comment les descripteurs standard se comportent dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, le stdin du premier enfant dans le pipeline est le canal de pipe, sinon c'est le même que le stdin du processus appelant ; il en va de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, le pipeline peut rediriger les descripteurs standard pour outrepasser les descripteurs standard pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, ces redirections provoquent une erreur.
ClientData handle (entrée)
Le descripteur spécifique à l'opération pour l'E/S vers un fichier. Pour Unix, c'est un descripteur de fichier, pour Windows, c'est un HANDLE.
int readOrWrite (entrée)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (entrée)
Le nom du canal.
int *modePtr (sortie)
Pointeur vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et/ou en écriture.
const char *pattern (entrée)
Le motif à rechercher, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (entrée)
Un canal Tcl pour l'entrée ou la sortie. Il doit avoir été le retour de la procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (entrée/sortie)
Un pointeur vers une valeur Tcl dans laquelle seront stockés les caractères lus du canal.
int charsToRead (entrée)
Le nombre de caractères à lire du canal. Si l'encodage du canal est binary, ceci est équivalent à la quantité d'octets à lire du canal.
int appendFlag (entrée)
Si différent de zéro, les données lues du canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu actuel de la valeur.
char *readBuf (sortie)
Un tampon dans lequel seront stockés les octets lus du canal.
int bytesToRead (entrée)
Le nombre d'octets à lire du canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (entrée/sortie)
Un pointeur vers une valeur Tcl dans laquelle sera stockée la ligne lue du canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (entrée/sortie)
Un pointeur vers une chaîne dynamique Tcl dans laquelle sera stockée la ligne lue du canal. Elle doit avoir été initialisée par l'utilisateur. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne.
const char *input (entrée)
L'entrée à ajouter au tampon du canal.
int inputLen (entrée)
Longueur de l'entrée.
int addAtEnd (entrée)
Drapeau indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon du canal.
Tcl_Obj *writeObjPtr (entrée)
Un pointeur vers une valeur Tcl dont le contenu sera envoyé au canal.
const char *charBuf (entrée)
Un tampon contenant les caractères à envoyer au canal.
const char *byteBuf (entrée)
Un tampon contenant les octets à envoyer au canal.
int bytesToWrite (entrée)
Le nombre d'octets à consommer de charBuf ou byteBuf et à envoyer au canal.
Tcl_WideInt offset (entrée)
À quelle distance déplacer le point d'accès dans le canal pour appliquer la prochaine opération d'entrée ou de sortie, mesurée en octets à partir du point donné par seekMode. Peut être positif ou négatif.
int seekMode (entrée)
Par rapport à quel point effectuer la recherche, utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs valides sont SEEK_SET, SEEK_CUR et SEEK_END.
Tcl_WideInt length (entrée)
La longueur (non négative) à laquelle le canal sera tronqué.
const char *optionName (entrée)
Le nom d'une option applicable au canal, comme -blocking. Peut avoir toute valeur acceptée par la commande fconfigure.
Tcl_DString *optionValue (entrée)
Où la valeur d'une option ou une liste de toutes les options et leurs valeurs est stockée. Doit avoir été initialisé par l'utilisateur.
const char *newValue (entrée)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canal de Tcl fournit un mécanisme indépendant des périphériques et de la plateforme pour effectuer des opérations d'E/S bufferisées sur divers types de fichiers, sockets et périphériques. Le mécanisme de canal est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans la page de manuel de Tcl_CreateChannel. Le mécanisme de canal fournit un schéma de mise en tampon inspiré des E/S standard d'Unix, et permet également des opérations non bloquantes sur les canaux.

Les procédures décrites dans ce manuel sont les API C du niveau général de l'architecture de canal. Pour une description de l'architecture du pilote de canal et comment implémenter des pilotes de canal pour de nouveaux types de canaux, voir la page de manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Ouvre un fichier dont le nom est fileName en utilisant le mode spécifié par mode et renvoie un nouveau canal Tcl.

Mode a le même format que l'argument mode pour la commande open de Tcl (par exemple, "r", "w", "rb", "r+", "w+", etc.). Les caractères encodés par le canal sont déterminés par l'option -translation du canal.

Permissions spécifie les permissions POSIX pour le fichier si un nouveau fichier est créé. Si le fichier existe déjà, permissions est ignoré. Le mode de fichier est déterminé par le mode d'ouverture, mais le comportement par défaut pour un mode d'ouverture où le fichier n'existe pas est de le créer. Les valeurs typiques sont 0644 pour les fichiers texte et 0600 pour les fichiers binaires.

Si fileName ne commence pas par 

//
(sur Windows) ou 
/
(sur Unix), ou s'il ne contient pas de :
//
, Tcl essaie d'ouvrir le fichier dans le répertoire de travail courant.

Si un fichier est ouvert en mode binary (c'est-à-dire sans la traduction de fin de ligne), Tcl_OpenFileChannel renvoie un canal qui lit et écrit des octets bruts. Sinon, il renvoie un canal qui lit et écrit des caractères. Les caractères sont encodés/décodés en utilisant l'encodage spécifié par l'option -encoding du canal (qui est "utf-8" par défaut).

Le canal retourné est automatiquement enregistré avec l'interpréteur interp et est géré par le système de gestion des canaux de Tcl. Les appels à Tcl_Close peuvent être utilisés pour fermer le canal et libérer ses ressources.

En cas d'erreur, Tcl_OpenFileChannel renvoie NULL et laisse un message d'erreur dans interp.

Sur les systèmes de type Unix, Tcl_OpenFileChannel peut ouvrir des fichiers spéciaux comme des pipes, des périphériques de terminaux, etc.

Sur Windows, Tcl_OpenFileChannel peut ouvrir des fichiers nommés, des périphériques (comme CON:, PRN:) et des tubes nommés.

La fonction Tcl_OpenCommandChannel est une forme spécialisée de Tcl_OpenFileChannel qui ouvre des canaux pour la communication avec des processus enfants dans un pipeline de commandes. L'argument flags contrôle la manière dont les canaux standard (stdin, stdout, stderr) du processus enfant sont liés aux canaux standard du processus parent.

La fonction Tcl_MakeFileChannel est utilisée pour créer un canal Tcl à partir d'un descripteur de fichier ou d'un handle de fichier existant. Elle prend un descripteur de fichier handle et un entier readOrWrite indiquant si le canal doit être lisible (TCL_READABLE) et/ou inscriptible (TCL_WRITABLE). Elle renvoie un nouveau canal Tcl qui encapsule le descripteur de fichier donné. Le canal retourné est enregistré automatiquement avec l'interpréteur interp.

La fonction Tcl_GetChannel est utilisée pour obtenir un pointeur vers la structure de canal associée à channelName dans l'interpréteur interp. L'argument modePtr est un pointeur vers un entier qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE, indiquant si le canal est ouvert en lecture et/ou en écriture. Si channelName n'est pas trouvé ou si le mode demandé n'est pas valide, la fonction renvoie NULL et laisse un message d'erreur dans interp.

La fonction Tcl_GetChannelNames renvoie une liste de tous les noms de canaux actuellement enregistrés dans l'interpréteur interp, stockée dans la variable résultante de l'interpréteur. Si pattern n'est pas NULL, seules les chaînes qui correspondent au pattern (en utilisant Tcl_StringMatch) sont renvoyées.

La fonction Tcl_RegisterChannel enregistre un canal Tcl nouvellement créé avec un interpréteur. Les canaux enregistrés sont accessibles par leur nom et sont automatiquement fermés lorsque l'interpréteur est détruit.

La fonction Tcl_UnregisterChannel supprime un canal de l'enregistrement de l'interpréteur. Le canal doit toujours être fermé explicitement avec Tcl_Close.

La fonction Tcl_DetachChannel détache un canal de l'interpréteur. Le canal n'est plus géré par Tcl et doit être géré (y compris sa fermeture) manuellement.

La fonction Tcl_IsStandardChannel renvoie vrai (1) si le canal channel est l'un des canaux standard (stdin, stdout, ou stderr) pour l'interpréteur, faux (0) sinon.

La fonction Tcl_Close ferme un canal Tcl. Si le canal a été ouvert avec Tcl_OpenFileChannel ou Tcl_OpenCommandChannel, cette fonction libère également les ressources associées au canal, y compris le descripteur de fichier sous-jacent. Si le canal a été créé avec Tcl_MakeFileChannel, il ne ferme pas le descripteur de fichier sous-jacent, mais le libère pour une utilisation ultérieure. Si le canal a été détaché avec Tcl_DetachChannel, il ne fait rien.

Les fonctions Tcl_ReadChars et Tcl_Read lisent des données du canal. Tcl_ReadChars lit jusqu'à charsToRead caractères (ou octets si le canal est binaire) et les stocke dans readObjPtr. Si appendFlag est non nul, les données lues sont ajoutées à la valeur existante de readObjPtr ; sinon, elles la remplacent. Tcl_Read lit jusqu'à bytesToRead octets et les stocke dans readBuf. Les deux fonctions renvoient le nombre d'octets réellement lus, ou -1 en cas d'erreur.

Les fonctions Tcl_GetsObj et Tcl_Gets lisent une ligne du canal (jusqu'au prochain caractère de nouvelle ligne). Tcl_GetsObj stocke la ligne (sans le caractère de nouvelle ligne final) dans lineObjPtr, ajoutant la ligne à la valeur existante. Tcl_Gets stocke la ligne (sans le caractère de nouvelle ligne final) dans lineRead, l'ajoutant à la chaîne existante. Les deux fonctions renvoient le nombre d'octets lus, ou -1 en cas d'erreur ou de fin de fichier.

La fonction Tcl_Ungets pousse inputLen octets de input dans le tampon d'entrée du canal. Si addAtEnd est non nul, l'input est ajouté à la fin du tampon ; sinon, il est ajouté au début.

Les fonctions Tcl_WriteObj, Tcl_WriteChars et Tcl_Write écrivent des données dans le canal. Tcl_WriteObj écrit le contenu de writeObjPtr. Tcl_WriteChars écrit les bytesToWrite premiers octets de charBuf. Tcl_Write écrit les bytesToWrite premiers octets de byteBuf. Toutes ces fonctions renvoient le nombre d'octets réellement écrits, ou -1 en cas d'erreur.

Les fonctions Tcl_ReadRaw et Tcl_WriteRaw sont similaires à Tcl_Read et Tcl_Write, mais elles effectuent des E/S binaires sans aucune traduction ou conversion d'encodage.

La fonction Tcl_Eof renvoie vrai (1) si la fin du fichier a été atteinte pour le canal channel, faux (0) sinon.

La fonction Tcl_Flush vide le tampon de sortie du canal channel. Elle garantit que toutes les données mises en tampon sont écrites dans le périphérique sous-jacent.

La fonction Tcl_InputBlocked renvoie vrai (1) si le canal d'entrée channel est bloqué (c'est-à-dire qu'aucune donnée n'est disponible pour la lecture sans bloquer), faux (0) sinon.

Les fonctions Tcl_InputBuffered et Tcl_OutputBuffered renvoient le nombre d'octets actuellement dans les tampons d'entrée et de sortie du canal channel, respectivement.

La fonction Tcl_Seek repositionne le point d'accès pour le canal channel à un décalage spécifié par offset par rapport au point spécifié par seekMode. Les valeurs possibles pour seekMode sont SEEK_SET (début du fichier), SEEK_CUR (position actuelle) et SEEK_END (fin du fichier). La fonction renvoie la nouvelle position d'accès en octets depuis le début du fichier, ou -1 en cas d'erreur.

La fonction Tcl_Tell renvoie la position actuelle du point d'accès du canal channel en octets depuis le début du fichier, ou -1 en cas d'erreur.

La fonction Tcl_TruncateChannel tronque le canal channel à la longueur spécifiée par length. Ceci n'est applicable qu'aux canaux qui prennent en charge la mise à zéro (par exemple, les fichiers).

La fonction Tcl_GetChannelOption récupère la valeur de l'option optionName pour le canal channel et la stocke dans optionValue. Si optionName est NULL, elle récupère une liste de toutes les options et leurs valeurs.

La fonction Tcl_SetChannelOption définit la valeur de l'option optionName pour le canal channel à newValue.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et retourne un descripteur de canal qui peut être utilisé pour effectuer des entrées et sorties sur le fichier. Cette API est calquée sur la procédure fopen de la bibliothèque d'entrées/sorties standard d'Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur la valeur Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel dans la mesure du possible.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standards, stdin, stdout ou stderr a été précédemment fermé, la création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface C aux fonctions des commandes exec et open. Elle crée une séquence de sous-processus spécifiés par les arguments argv et argc et retourne un canal qui peut être utilisé pour communiquer avec ces sous-processus. L'argument flags indique le type de communication qui existera avec le pipeline de commandes.

Si le drapeau TCL_STDIN est défini, alors l'entrée standard du premier sous-processus sera liée au canal : écrire dans le canal fournira des données au sous-processus. Si TCL_STDIN n'est pas défini, alors l'entrée standard du premier sous-processus sera la même que l'entrée standard de cette application. Si TCL_STDOUT est défini, alors la sortie standard du dernier sous-processus peut être lue depuis le canal ; sinon, elle va vers la sortie standard de cette application. Si TCL_STDERR est défini, la sortie d'erreur standard de tous les sous-processus est renvoyée au canal et entraîne une erreur lors de la fermeture du canal ; sinon, elle va vers la sortie d'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas défini, alors argc et argv peuvent rediriger les descripteurs stdio pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, alors c'est une erreur que argc et argv redirigent les canaux stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standards, stdin, stdout ou stderr a été précédemment fermé, la création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un descripteur de fichier existant et spécifique à la plateforme. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standards, stdin, stdout ou stderr a été précédemment fermé, la création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel retourne un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur Tcl dans interp. Si un canal portant ce nom n'est pas enregistré dans cet interpréteur, la procédure retourne NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms en fonction du pattern. Si pattern est NULL, alors aucun filtrage ne sera effectué. La valeur de retour est TCL_OK si aucune erreur ne s'est produite lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur peuvent se référer au canal dans les opérations d'entrée ou de sortie en utilisant le nom donné lors de l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour ce canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur Tcl peut appeler Tcl_RegisterChannel avec interp comme NULL, pour indiquer qu'il souhaite conserver une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et il ne sera fermé que lorsque le nombre correspondant d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code exécuté en dehors de tout interpréteur de conserver en toute sécurité une référence à un canal également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code gérant les canaux standards. Si aucun canal standard n'a été initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un exposé général sur les canaux standards et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour se référer au canal dans cet interpréteur. Si cette opération a supprimé le dernier enregistrement du canal dans un quelconque interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur Tcl peut appeler Tcl_UnregisterChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera alors fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel à ceci près qu'il fermera également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour se référer au canal dans cet interpréteur. Au-delà de cela, cette commande n'a aucun autre effet. Elle ne peut pas être utilisée sur les canaux standards (stdout, stderr, stdin) et retournera TCL_ERROR si elle reçoit l'un de ces canaux en argument.

Le code non associé à un interpréteur Tcl peut appeler Tcl_DetachChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standards, stdin, stdout ou stderr. Si c'est le cas, il retourne 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standards sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un quelconque interpréteur lorsque Tcl_Close est appelé. La sortie tamponnée est vidée vers le périphérique de sortie du canal avant la destruction du canal, et toute entrée tamponnée est rejetée. S'il s'agit d'un canal bloquant, l'appel ne retourne pas tant que toutes les données tamponnées n'ont pas été envoyées avec succès vers le périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a une sortie tamponnée qui ne peut pas être écrite sans bloquer, l'appel retourne immédiatement ; la sortie est vidée en arrière-plan et le canal sera fermé une fois que toutes les données tamponnées auront été transmises. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close retourne TCL_OK. Si une erreur se produit, Tcl_Close retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré en utilisant Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour les détails. Si le canal a déjà été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez plutôt utiliser Tcl_UnregisterChannel, qui appellera en interne Tcl_Close lorsque tous les appels à Tcl_RegisterChannel auront été mis en correspondance par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, convertissant les octets en UTF-8 en se basant sur l'encodage du canal et stockant les données produites dans la représentation chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Définir ch

arsToRead à -1 entraînera la lecture par la commande de tous les caractères actuellement disponibles (mode non bloquant) ou de tout jusqu'à EOF (mode bloquant).

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé étaient disponibles. Ceci est appelé une lecture courte. En mode bloquant, cela ne peut se produire qu'en fin de fichier. En mode non bloquant, une lecture courte peut également se produire s'il n'y a pas assez d'entrée disponible : Tcl_ReadChars renvoie un nombre réduit plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour savoir laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les diverses représentations de fin de ligne en la représentation interne canonique \n selon le mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les différents modes spécifiques à la plateforme sont décrits dans l'entrée du manuel de la commande Tcl fconfigure.

Par optimisation des performances, lors de la lecture d'un canal avec le codage binary, les octets ne sont pas convertis en UTF-8 lors de leur lecture. Ils sont stockés dans la représentation interne de readObjPtr sous forme de tableau d'octets. La représentation sous forme de chaîne de cette valeur ne sera construite que si elle est nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette manière, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de la conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, à l'exception qu'elle n'effectue pas de conversions de codage, quel que soit le codage du canal. Elle est dépréciée et existe pour des raisons de compatibilité ascendante avec les extensions Tcl non internationalisées. Elle consomme des octets du channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par null. Son contenu est valide à partir de la position zéro jusqu'à la position indiquée par la valeur de retour, sans l'inclure.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas le chaînage. Alors que Tcl_Read (et les autres fonctions de l'API) obtiennent toujours leurs données du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_ReadRaw ne le fait pas. Cette fonction est donc uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données du canal inférieur dans la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, convertissant les octets en UTF-8 en fonction du codage du canal, jusqu'à ce qu'une ligne complète d'entrée soit vue. Si le codage du canal est binary, chaque octet lu à partir du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception des caractères de fin de ligne terminaux, sont ajoutés à la représentation sous forme de chaîne de lineObjPtr. Les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_GetsObj renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj renvoie également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est renvoyé, la procédure Tcl_InputBlocked peut être invoquée pour déterminer si le canal est bloqué en raison de l'indisponibilité de l'entrée.

Tcl_Gets est identique à Tcl_GetsObj, sauf que les caractères résultants sont ajoutés à la chaîne dynamique donnée par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, à la tête ou à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si le canal a un indicateur EOF "collant" activé, aucune donnée ne sera ajoutée à la file d'entrée. Tcl_Ungets renvoie inputLen ou -1 si une erreur se produit.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données de caractères à charBuf. Les caractères UTF-8 dans le tampon sont convertis dans le codage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par null et il sort tout jusqu'au null.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering du canal à none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering du canal en mode line.

La valeur de retour de Tcl_WriteChars est un compte du nombre d'octets qui ont été acceptés pour la sortie vers le canal. C'est soit supérieur à zéro pour indiquer le succès, soit -1 pour indiquer qu'une erreur s'est produite. Si une erreur se produit, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme conformément à l'option -translation pour le canal. Ceci est fait même si le canal n'a pas de codage.

Tcl_WriteObj est similaire à Tcl_WriteChars, sauf qu'il accepte une valeur Tcl dont le contenu sera sorti vers le canal. Les caractères UTF-8 de la représentation sous forme de chaîne de writeObjPtr sont convertis dans le codage du canal et mis en file d'attente pour la sortie vers channel. Par optimisation des performances, lors de l'écriture dans un canal avec le codage binary, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets dans la représentation interne de writeObjPtr en tant que valeur de tableau d'octets sont écrits dans le canal. La représentation de tableau d'octets de la valeur sera construite si nécessaire. De cette manière, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de la conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars, sauf qu'elle n'effectue pas de conversions de codage, quel que soit le codage du canal. Elle est dépréciée et existe pour des raisons de compatibilité ascendante avec les extensions Tcl non internationalisées. Elle accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par null et il sort tout jusqu'au null.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas le chaînage. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée dans le canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_WriteRaw ne le fait pas. Cette fonction est donc uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation dans le canal inférieur.

TCL_FLUSH

Tcl_Flush force l'écriture de toutes les données de sortie mises en mémoire tampon pour channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données mises en mémoire tampon n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal est non bloquant ; il démarre une synchronisation en arrière-plan qui écrira les données mises en mémoire tampon dans le canal éventuellement, aussi rapidement que le canal est capable de les absorber.

La valeur de retour est normalement TCL_OK. Si une erreur se produit, Tcl_Flush retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données ultérieures seront lues ou écrites. La sortie mise en mémoire tampon est vidée vers le canal et l'entrée mise en mémoire tampon est ignorée, avant l'opération de recherche.

Tcl_Seek renvoie normalement le nouveau point d'accès. Si une erreur se produit, Tcl_Seek renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut avoir été déplacé ou non.

TCL_TELL

Tcl_Tell renvoie le point d'accès actuel pour un canal. La valeur retournée est -1 si le canal ne prend pas en charge la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent à channel à une longueur donnée de length octets. Il renvoie TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, c'est le nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue >, en utilisant une série d'appels à Tcl_DStringAppendElement. Les diverses options préexistantes et leurs valeurs possibles sont décrites dans l'entrée du manuel de la commande Tcl fconfigure. D'autres options peuvent être ajoutées par chaque type de canal. Ces options spécifiques au type de canal sont décrites dans l'entrée du manuel de la commande Tcl qui crée un canal de ce type ; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans l'entrée du manuel de la commande Tcl socket. La procédure renvoie normalement TCL_OK. En cas d'erreur, elle renvoie TCL_ERROR et appelle Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit une nouvelle valeur newValue pour une option optionName sur channel. La procédure renvoie normalement TCL_OK. En cas d'erreur, elle renvoie TCL_ERROR ; de plus, si interp n'est pas NULL, Tcl_SetChannelOption laisse un message d'erreur dans le résultat de l'interpréteur.

TCL_EOF

Tcl_Eof renvoie une valeur non nulle si channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked renvoie une valeur non nulle si channel est en mode non bloquant et que la dernière opération d'entrée a renvoyé moins de données que demandé car il n'y avait pas suffisamment de données disponibles. L'appel renvoie toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered renvoie le nombre d'octets d'entrée actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en lecture, cette fonction renvoie toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered renvoie le nombre d'octets de sortie actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en écriture, cette fonction renvoie toujours zéro.

PROBLÈMES DE PLATEFORME

Les descripteurs renvoyés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que renvoyé par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel, ou Tcl_MakeFileChannel. D'autres types de canaux peuvent renvoyer un type de descripteur différent sur les plateformes Windows.
