NAME

Tcl_TraceVar, Tcl_TraceVar2, Tcl_UntraceVar, Tcl_UntraceVar2, Tcl_VarTraceInfo, Tcl_VarTraceInfo2 - surveiller les accès à une variable

SYNOPSIS

#include <tcl.h>

int
Tcl_TraceVar(interp, varName, flags, proc, clientData)

int
Tcl_TraceVar2(interp, name1, name2, flags, proc, clientData)

Tcl_UntraceVar(interp, varName, flags, proc, clientData)

Tcl_UntraceVar2(interp, name1, name2, flags, proc, clientData)

ClientData
Tcl_VarTraceInfo(interp, varName, flags, proc, prevClientData)

ClientData
Tcl_VarTraceInfo2(interp, name1, name2, flags, proc, prevClientData)

ARGUMENTOS

Tcl_Interp *interp (in)
Interpréteur contenant la variable.
const char *varName (in)
Nom de la variable. Peut faire référence à une variable scalaire, une variable tableau sans indice, ou une variable tableau avec un indice entre parenthèses.
int flags (in)
OR bit à bit des valeurs suivantes : TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS, TCL_TRACE_ARRAY, TCL_GLOBAL_ONLY, TCL_NAMESPACE_ONLY, TCL_TRACE_RESULT_DYNAMIC et TCL_TRACE_RESULT_OBJECT. Tous les flags ne sont pas utilisés par toutes les procédures. Voir plus d'informations ci-dessous.
Tcl_VarTraceProc *proc (in)
Procédure à appeler lorsqu'une des opérations suivies se produit.
ClientData clientData (in)
Valeur d'une donnée d'un seul mot transmise à proc.
const char *name1 (in)
Nom d'une variable scalaire ou tableau (sans indice de tableau).
const char *name2 (in)
Pour un suivi d'élément de tableau, donne l'indice de l'élément. Pour un suivi de variable scalaire ou de tableau entier, est NULL.
ClientData prevClientData (in)
S'il n'est pas NULL, donne la valeur retournée la plus récente par Tcl_VarTraceInfo ou Tcl_VarTraceInfo2, de sorte que cet appel retournera des informations sur le prochain suivi. S'il est NULL, cet appel retournera des informations sur le premier suivi.

DESCRIPCIÓN

Tcl_TraceVar permet à une procédure C de surveiller et de contrôler l'accès à une variable Tcl, afin que la procédure C soit appelée lorsqu'une variable est lue, écrite ou désactivée. Si le suivi est créé avec succès, Tcl_TraceVar renvoie TCL_OK. Si une erreur se produit (par exemple, varName spécifie un élément de tableau, mais la variable réelle n'est pas un tableau), TCL_ERROR est renvoyé et un message d'erreur est placé dans le résultat de l'interpréteur.

L'argument flags de Tcl_TraceVar indique quand la procédure de suivi est appelée et fournit des informations pour configurer le suivi. Il consiste en une combinaison OR de n'importe laquelle des valeurs suivantes :

TCL_GLOBAL_ONLY
Normalement, la variable est recherchée au niveau d'appel de procédure actuel ; si ce bit est défini, la variable est recherchée au niveau global, ignorant toute procédure active.
TCL_NAMESPACE_ONLY
Normalement, la variable est recherchée au niveau d'appel de procédure actuel ; si ce bit est défini, la variable est recherchée dans l'espace de noms actuel, ignorant toute procédure active.
TCL_TRACE_READS
proc est appelée lorsqu'une tentative de lecture de la variable est effectuée.
TCL_TRACE_WRITES
proc est appelée lorsqu'une tentative de modification de la variable est effectuée.
TCL_TRACE_UNSETS
proc est appelée lorsque la variable est désactivée. Une variable peut être désactivée explicitement à l'aide d'une commande unset, ou implicitement lorsqu'une procédure retourne (ses variables locales sont automatiquement désactivées), ou lorsque l'interpréteur est détruit (toutes les variables sont automatiquement désactivées).
TCL_TRACE_ARRAY
proc est appelée lorsque la commande array est appelée. Cela donne à la procédure de suivi la possibilité de mettre à jour le tableau avant que le nom du tableau ou la récupération du tableau ne soit appelée. Remarque : ceci est appelé avant que la définition du tableau ne soit appelée, mais cela déclenchera les suivis d'écriture.
TCL_TRACE_RESULT_DYNAMIC
Le résultat de l'appel de proc est une chaîne dynamique qui sera libérée par la bibliothèque Tcl via un appel à ckfree. Il ne doit pas être spécifié simultanément avec TCL_TRACE_RESULT_OBJECT.
TCL_TRACE_RESULT_OBJECT
Le résultat de l'appel de proc est un Tcl_Obj* (converti en pointeur char*) avec un compteur de références d'au moins un. Le propriétaire de cette référence est passé à la bibliothèque Tcl pour être libéré (lorsque la bibliothèque Tcl a fini de l'utiliser) via un appel à Tcl_DecrRefCount. Il ne doit pas être spécifié simultanément avec TCL_TRACE_RESULT_DYNAMIC.

Lorsqu'une des opérations spécifiées se produit sur la variable, proc est appelée. Elle doit avoir des arguments et un type de retour correspondant à Tcl_VarTraceProc :

typedef char *Tcl_VarTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *name1,
        const char *name2,
        int flags);

Les paramètres clientData et interp auront les mêmes valeurs qui ont été passées à Tcl_TraceVar lors de la création du suivi. clientData pointe généralement vers un ensemble de données spécifique à l'application décrivant ce qu'il faut faire lorsque proc est appelée. name1 et name2 donnent le nom de la variable suivie dans la forme à deux parties normale (voir la description de Tcl_TraceVar2 pour plus de détails). flags est une combinaison OR de bits qui fournissent divers éléments d'information. L'un des bits TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_ARRAY ou TCL_TRACE_UNSETS sera défini dans flags pour indiquer quelle opération est effectuée sur la variable. Le bit TCL_GLOBAL_ONLY sera défini lorsque la variable accédée est globale et non accessible depuis le niveau d'appel de procédure actuel : la procédure de suivi devra passer ce flag aux procédures liées aux variables telles que Tcl_GetVar si elle tente d'accéder à la variable. Le bit TCL_NAMESPACE_ONLY sera défini lorsque la variable accédée est dans un espace de noms et non accessible depuis le niveau d'appel de procédure actuel : la procédure de suivi devra passer ce flag aux procédures liées aux variables telles que Tcl_GetVar si elle tente d'accéder à la variable. Le bit TCL_TRACE_DESTROYED sera défini dans flags si le suivi doit être détruit ; ces informations peuvent être utiles à proc pour qu'elle puisse nettoyer ses structures internes (voir la section TCL_TRACE_DESTROYED pour plus de détails). Enfin, le bit TCL_INTERP_DESTROYED sera défini si l'ensemble de l'interpréteur est détruit. Lorsque ce bit est défini, proc doit être particulièrement prudent dans ce qu'il fait (voir la section TCL_INTERP_DESTROYED pour plus de détails). La valeur de retour de la procédure de suivi devrait normalement être NULL ; voir ERROR RETURNS pour plus d'informations sur les autres valeurs possibles.

Tcl_UntraceVar peut être utilisé pour supprimer un suivi. Si la variable spécifiée par interp, varName et flags a un suivi avec flags, proc et clientData, le suivi correspondant est supprimé. S'il n'existe pas de tel suivi, l'appel à Tcl_UntraceVar n'a aucun effet. Les mêmes bits sont valides pour flags que pour les appels à Tcl_TraceVar.

Tcl_VarTraceInfo peut être utilisé pour récupérer des informations sur les suivis définis sur une variable donnée. La valeur de retour de Tcl_VarTraceInfo est le clientData associé à un suivi spécifique. Le suivi doit être associé à la variable spécifiée par les arguments interp, varName et flags (seuls les bits TCL_GLOBAL_ONLY et TCL_NAMESPACE_ONLY de flags sont utilisés ; les autres bits sont ignorés) et sa procédure de suivi doit être la même que l'argument proc. Si l'argument prevClientData est NULL, la valeur retournée correspond au premier (le plus récent) suivi correspondant, ou NULL s'il n'y a pas de correspondance.

NOM DE LA PROCÉDURE

Tcl_VarTraceInfo, Tcl_VarTraceInfo2 - interroger les informations sur les traces de variables Tcl

SYNTAXE

#include <tcl.h>

const char *
Tcl_VarTraceInfo(interp, varName, prevTraceInfo)
void
Tcl_TraceVar2(interp, name1, name2, mask, proc, clientData)
void
Tcl_UntraceVar2(interp, name1, name2, mask, proc, clientData)
const char *
Tcl_VarTraceInfo2(interp, name1, name2, prevTraceInfo)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur Tcl dans lequel effectuer l'opération.
const char *varName (entrée)
Nom de la variable à tracer (pour Tcl_VarTraceInfo).
const char *prevTraceInfo (entrée)
Information de trace précédente (pour Tcl_VarTraceInfo).
const char *name1 (entrée)
Nom de la première partie du nom de la variable (pour Tcl_TraceVar2, Tcl_UntraceVar2, Tcl_VarTraceInfo2).
const char *name2 (entrée)
Nom de la seconde partie du nom de la variable (pour Tcl_TraceVar2, Tcl_UntraceVar2, Tcl_VarTraceInfo2).
int mask (entrée)
Masque de bits spécifiant les types d'accès à tracer. Les valeurs possibles sont TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_ARRAY_WRITES, et TCL_TRACE_UNSETS. Les valeurs peuvent être combinées à l'aide de l'opérateur OU binaire.
Tcl_VarTraceProc *proc (entrée)
Pointeur vers la procédure de trace à appeler.
ClientData clientData (entrée)
Données fournies par l'utilisateur, à passer à la procédure de trace.

DESCRIPTION

Les procédures Tcl_TraceVar et Tcl_VarTraceInfo sont utilisées pour créer et interroger des traces de variables. Une trace de variable est un mécanisme qui permet d'exécuter une procédure spécifiée chaque fois qu'une variable est lue, écrite, qu'un tableau est modifié, ou que la variable est désactivée.

Tcl_TraceVar enregistre la procédure proc pour être appelée lorsque la variable nommée varName est accédée d'une manière spécifiée par mask. L'argument clientData est passé à proc chaque fois qu'elle est appelée ; il est généralement utilisé pour identifier la trace ou pour stocker des données associées à la trace.

Tcl_UntraceVar supprime une trace de variable précédemment enregistrée. Les arguments proc et clientData doivent correspondre à ceux utilisés lors de l'appel à Tcl_TraceVar pour que la bonne trace soit supprimée.

Tcl_VarTraceInfo permet d'obtenir des informations sur les traces existantes pour une variable donnée. Si prevClientData est NULL, la procédure renvoie les informations sur la première trace trouvée pour la variable spécifiée. Sinon, si prevClientData n'est pas NULL, il doit s'agir de la valeur de retour d'un appel précédent à Tcl_VarTraceInfo. Dans ce cas, la nouvelle valeur de retour correspondra à la trace correspondante suivante après celle dont clientData correspond à prevClientData, ou NULL s'il n'y a plus de traces correspondantes. Ce mécanisme permet de parcourir toutes les traces d'une variable donnée qui ont le même proc.

DEUX NOMS PARTIES

Les procédures Tcl_TraceVar2, Tcl_UntraceVar2, et Tcl_VarTraceInfo2 sont identiques à Tcl_TraceVar, Tcl_UntraceVar, et Tcl_VarTraceInfo, respectivement, sauf que le nom de la variable se compose de deux parties. Name1 donne le nom d'une variable scalaire ou d'un tableau, et name2 donne le nom d'un élément dans un tableau. Lorsque name2 est NULL, name1 peut contenir à la fois un nom de tableau et un nom d'élément : si le nom contient une parenthèse ouvrante et se termine par une parenthèse fermante, alors la valeur entre les parenthèses est traitée comme un nom d'élément (qui peut avoir n'importe quelle valeur de chaîne) et les caractères avant la première parenthèse ouvrante sont traités comme le nom d'une variable de tableau. Si name2 est NULL et name1 ne fait pas référence à un élément de tableau, cela signifie que la variable est scalaire ou que la trace doit être définie sur l'ensemble du tableau plutôt que sur un élément individuel (voir TRACES DE TABLEAU ENTIER ci-dessous pour plus d'informations).

ACCÈS AUX VARIABLES PENDANT LES TRACES

Pendant les traces de lecture, d'écriture et de tableau, la procédure de trace peut lire, écrire ou désactiver la variable tracée en utilisant Tcl_GetVar2, Tcl_SetVar2 et d'autres procédures. Pendant que proc est en cours d'exécution, les traces sont temporairement désactivées pour la variable, de sorte que les appels à Tcl_GetVar2 et Tcl_SetVar2 ne provoqueront pas l'invocation répétée de proc ou d'autres procédures de trace. La désactivation ne se produit que pour la variable dont la procédure de trace est active ; les accès aux autres variables seront toujours tracés. Cependant, si une variable est désactivée pendant une trace de lecture ou d'écriture, les traces de désactivation seront invoquées.

Pendant les traces de désactivation, la variable a déjà été complètement expurgée. Il est possible pour la procédure de trace de lire ou d'écrire la variable, mais ce sera une nouvelle version de la variable. Les traces ne sont pas désactivées pendant les traces de désactivation, contrairement aux traces de lecture et d'écriture, mais les traces existantes ont été supprimées de la variable avant que toute procédure de trace ne soit appelée. Si de nouvelles traces sont définies par les procédures de trace de désactivation, ces traces seront invoquées lors des accès à la variable par les procédures de trace.

CALENDRIER DES RAPPELS

Lorsqu'un traçage de lecture a été spécifié pour une variable, la procédure de trace sera appelée chaque fois que la valeur de la variable est lue. Cela inclut les commandes Tcl set, la notation $ dans les commandes Tcl, et les invocations des procédures Tcl_GetVar et Tcl_GetVar2. Proc est appelée juste avant que la valeur de la variable ne soit renvoyée. Elle peut modifier la valeur de la variable pour affecter ce qui est renvoyé par l'accès tracé. Si elle désactive la variable, l'accès renverra une erreur comme si la variable n'avait jamais existé.

Lorsqu'un traçage d'écriture a été spécifié pour une variable, la procédure de trace sera appelée chaque fois que la valeur de la variable est modifiée. Cela inclut les commandes set, les commandes qui modifient les variables comme effets secondaires (telles que catch et scan), et les appels aux procédures Tcl_SetVar et Tcl_SetVar2). Proc sera appelée après que la valeur de la variable ait été modifiée, mais avant que la nouvelle valeur de la variable n'ait été renvoyée. Elle peut modifier la valeur de la variable pour outrepasser le changement et pour déterminer la valeur réellement renvoyée par l'accès tracé. Si elle supprime la variable, l'accès tracé renverra une chaîne vide.

Lorsqu'un traçage de tableau a été spécifié, la procédure de trace sera appelée au début de l'implémentation de la commande de tableau, avant que les opérations telles que get, set ou names n'aient été invoquées. La procédure de trace peut modifier les éléments du tableau avec Tcl_SetVar et Tcl_SetVar2.

Lorsqu'un traçage de désactivation a été spécifié, la procédure de trace sera appelée chaque fois que la variable est détruite. Les traces seront appelées après que la variable ait été complètement désactivée.

TRACES DE TABLEAU ENTIER

Si un appel à Tcl_TraceVar ou Tcl_TraceVar2 spécifie le nom d'une variable de tableau sans indice dans le tableau, alors la trace sera définie sur le tableau dans son ensemble. Cela signifie que proc sera appelée chaque fois que tout élément du tableau est accédé de la manière spécifiée par flags. Lorsqu'un tableau est désactivé, une trace de tableau entier sera appelée une seule fois, avec name1 égal au nom du tableau et name2 NULL ; elle ne sera pas appelée une fois pour chaque élément.

TRACES MULTIPLES

Il est possible que plusieurs traces existent sur la même variable. Lorsque cela se produit, toutes les procédures de trace seront appelées à chaque accès, dans l'ordre, de la plus récemment créée à la moins récemment créée. Lorsqu'il existe des traces de tableau entier pour un tableau ainsi que des traces sur des éléments individuels, les traces de tableau entier sont appelées avant les traces d'éléments individuels. Si une trace de lecture ou d'écriture désactive la variable, alors toutes les traces de désactivation seront appelées, mais le reste des traces de lecture et d'écriture sera ignoré.

RETOURS D'ERREUR

Dans des conditions normales, les procédures de trace doivent renvoyer NULL, indiquant une complétion réussie. Si proc renvoie une valeur non-NULL, cela signifie qu'une erreur s'est produite. La valeur de retour doit être un pointeur vers une chaîne de caractères statique contenant un message d'erreur, sauf si (un seul et unique) des indicateurs TCL_TRACE_RESULT_DYNAMIC et TCL_TRACE_RESULT_OBJECT est défini, qui spécifient que le résultat est soit une chaîne dynamique (à libérer avec ckfree) soit un Tcl_Obj* (casté en char* et à libérer avec Tcl_DecrRefCount) contenant le message d'erreur. Si une procédure de trace renvoie une erreur, aucune autre trace n'est appelée pour l'accès et l'accès tracé est abandonné avec le message donné. Les procédures de trace peuvent utiliser cette fonctionnalité pour rendre les variables en lecture seule, par exemple (mais notez que la valeur de la variable aura déjà été modifiée avant que la procédure de trace ne soit appelée, donc la procédure de trace devra restaurer la valeur correcte).

La valeur de retour de proc n'est utilisée que lors des traçages de lecture et d'écriture. Pendant les traçages de désactivation, la valeur de retour est ignorée et toutes les procédures de trace pertinentes seront toujours appelées.

RESTRICTIONS

Une procédure de trace peut être appelée à tout moment, même lorsqu'il y a des résultats partiellement formés stockés dans l'interpréteur. Si la procédure de trace fait quelque chose qui pourrait endommager ce résultat (comme appeler Tcl_Eval), elle doit utiliser la routine Tcl_SaveInterpState et les routines associées pour sauvegarder et restaurer l'état original de l'interpréteur avant de retourner.

VARIABLES NON DÉFINIES

Il est légal de définir une trace sur une variable non définie. La variable semblera toujours non définie jusqu'à la première fois où sa valeur est définie. Si une variable non définie est tracée puis désactivée, la désactivation échouera avec une erreur ("pas de telle variable"), mais la procédure de trace sera toujours appelée.

INDICATEUR TCL_TRACE_DESTROYED

Dans un rappel de désactivation à proc, le bit TCL_TRACE_DESTROYED est défini dans flags si la trace est en cours de suppression dans le cadre de la suppression. Les traces sur une variable sont toujours supprimées lorsque la variable est supprimée ; la seule fois où TCL_TRACE_DESTROYED n'est pas défini est pour une trace de tableau entier invoquée lorsque seul un seul élément d'un tableau est désactivé.

TCL_INTERP_DESTROYED

Lorsqu'un interpréteur est détruit, les traces de désactivation sont appelées pour toutes ses variables. Le bit TCL_INTERP_DESTROYED sera défini dans l'argument flags passé aux procédures de trace. Les procédures de trace doivent être extrêmement prudentes dans ce qu'elles font si le bit TCL_INTERP_DESTROYED est défini. Il n'est pas sûr pour les procédures d'invoquer des procédures Tcl sur l'interpréteur, car son état est partiellement supprimé. Tout ce que les procédures de trace devraient faire dans ces circonstances est de nettoyer et de libérer leurs propres structures de données internes.

BOGUES

Tcl ne fait aucune vérification d'erreur pour empêcher les procédures de trace d'utiliser abusivement l'interpréteur pendant les traces avec TCL_INTERP_DESTROYED défini.

Les traces de tableaux ne sont pas encore intégrées à la commande Tcl info exists, et il n'y a pas d'accès au niveau Tcl aux traces de tableaux.
