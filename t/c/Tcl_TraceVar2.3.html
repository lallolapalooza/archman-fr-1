Tcl_TraceVar(3) Procédures de bibliothèque Tcl Tcl_TraceVar(3)

NOM

Tcl_TraceVar, Tcl_TraceVar2, Tcl_UntraceVar, Tcl_UntraceVar2, Tcl_VarTraceInfo, Tcl_VarTraceInfo2 - surveiller les accès à une variable

SYNOPIS

#include <tcl.h>

int
Tcl_TraceVar(interp, varName, flags, proc, clientData)

int
Tcl_TraceVar2(interp, name1, name2, flags, proc, clientData)

Tcl_UntraceVar(interp, varName, flags, proc, clientData)

Tcl_UntraceVar2(interp, name1, name2, flags, proc, clientData)

ClientData
Tcl_VarTraceInfo(interp, varName, flags, proc, prevClientData)

ClientData
Tcl_VarTraceInfo2(interp, name1, name2, flags, proc, prevClientData)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur contenant la variable.
const char *varName (entrée)
Nom de la variable. Peut faire référence à une variable scalaire, à une variable de tableau sans indice, ou à une variable de tableau avec un indice entre parenthèses.
int flags (entrée)
Combinaison OR des valeurs TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS, TCL_TRACE_ARRAY, TCL_GLOBAL_ONLY, TCL_NAMESPACE_ONLY, TCL_TRACE_RESULT_DYNAMIC et TCL_TRACE_RESULT_OBJECT. Tous les indicateurs ne sont pas utilisés par toutes les procédures. Voir ci-dessous pour plus d'informations.
Tcl_VarTraceProc *proc (entrée)
Procédure à appeler chaque fois qu'une des opérations tracées se produit.
ClientData clientData (entrée)
Valeur arbitraire d'un mot à passer à proc.
const char *name1 (entrée)
Nom de la variable scalaire ou du tableau (sans l'indice du tableau).
const char *name2 (entrée)
Pour un trace sur un élément d'un tableau, donne l'indice de l'élément. Pour les traces sur des variables scalaires ou des tableaux entiers, est NULL.
ClientData prevClientData (entrée)
Si non NULL, donne la dernière valeur retournée par Tcl_VarTraceInfo ou Tcl_VarTraceInfo2, donc cet appel retournera des informations sur le trace suivant. Si NULL, cet appel retournera des informations sur le premier trace.

DESCRIPTION

Tcl_TraceVar permet à une procédure C de surveiller et de contrôler l'accès à une variable Tcl, de sorte que la procédure C soit appelée chaque fois que la variable est lue, écrite ou désunset. Si le trace est créé avec succès, Tcl_TraceVar retourne TCL_OK. Si une erreur se produit (par exemple, varName spécifie un élément d'un tableau, mais la variable réelle n'est pas un tableau), alors TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de l'interpréteur.

L'argument flags de Tcl_TraceVar indique quand la procédure de trace doit être appelée et fournit des informations pour configurer le trace. Il se compose d'une combinaison OR de n'importe laquelle des valeurs suivantes :

TCL_GLOBAL_ONLY
Normalement, la variable sera recherchée au niveau actuel de l'appel de procédure ; si ce bit est défini, la variable sera recherchée au niveau global, ignorant toute procédure active.
TCL_NAMESPACE_ONLY
Normalement, la variable sera recherchée au niveau actuel de l'appel de procédure ; si ce bit est défini, la variable sera recherchée dans le namespace actuel, ignorant toute procédure active.
TCL_TRACE_READS
Appeler proc chaque fois qu'une tentative de lecture de la variable est effectuée.
TCL_TRACE_WRITES
Appeler proc chaque fois qu'une tentative de modification de la variable est effectuée.
TCL_TRACE_UNSETS
Appeler proc chaque fois que la variable est désunset. Une variable peut être désunset explicitement par une commande unset, ou implicitement lorsqu'une procédure retourne (ses variables locales sont automatiquement désunset) ou lorsque l'interpréteur est supprimé (toutes les variables sont automatiquement désunset).
TCL_TRACE_ARRAY
Appeler proc chaque fois que la commande array est invoquée. Cela donne à la procédure de trace une chance de mettre à jour le tableau avant que array names ou array get ne soient appelés. Notez que cela est appelé avant un array set, mais cela déclenchera des traces d'écriture.
TCL_TRACE_RESULT_DYNAMIC
Le résultat de l'appel de proc est une chaîne allouée dynamiquement qui sera libérée par la bibliothèque Tcl via un appel à ckfree. Ne doit pas être spécifié en même temps que TCL_TRACE_RESULT_OBJECT.
TCL_TRACE_RESULT_OBJECT
Le résultat de l'appel de proc est un Tcl_Obj* (converti en char*) avec un compteur de références d'au moins un. La propriété de cette référence sera transférée au noyau Tcl pour être libérée (lorsque le noyau aura fini avec) via un appel à Tcl_DecrRefCount. Ne doit pas être spécifié en même temps que TCL_TRACE_RESULT_DYNAMIC.

Chaque fois qu'une des opérations spécifiées se produit sur la variable, proc sera appelée. Elle devrait avoir des arguments et un résultat qui correspondent au type Tcl_VarTraceProc :

typedef char *Tcl_VarTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *name1,
        const char *name2,
        int flags);

Les paramètres clientData et interp auront les mêmes valeurs que ceux passés à Tcl_TraceVar lors de la création du trace. ClientData pointe généralement vers une structure de données spécifique à l'application qui décrit quoi faire lorsque proc est appelée. Name1 et name2 donnent le nom de la variable tracée dans la forme habituelle en deux parties (voir la description de Tcl_TraceVar2 ci-dessous pour les détails). Flags est une combinaison OR de bits fournissant plusieurs informations. Un des bits TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_ARRAY, ou TCL_TRACE_UNSETS sera défini dans flags pour indiquer quelle opération est effectuée sur la variable. Le bit TCL_GLOBAL_ONLY sera défini chaque fois que la variable accédée est une variable globale non accessible depuis le niveau actuel de procédure : la procédure de trace devra repasser ce flag aux procédures liées aux variables comme Tcl_GetVar si elle tente d'accéder à la variable. Le bit TCL_NAMESPACE_ONLY sera défini chaque fois que la variable accédée est une variable de namespace non accessible depuis le niveau actuel de procédure : la procédure de trace devra repasser ce flag aux procédures liées aux variables comme Tcl_GetVar si elle tente d'accéder à la variable. Le bit TCL_TRACE_DESTROYED sera défini dans flags si le trace est sur le point d'être détruit ; cette information peut être utile à proc pour qu'elle puisse nettoyer ses propres structures de données internes (voir la section TCL_TRACE_DESTROYED ci-dessous pour plus de détails). Enfin, le bit TCL_INTERP_DESTROYED sera défini si l'interpréteur entier est en cours de destruction. Lorsque ce bit est défini, proc doit être particulièrement prudent dans les actions qu'elle entreprend (voir la section TCL_INTERP_DESTROYED ci-dessous). La valeur de retour de la procédure de trace devrait normalement être NULL ; voir RETOURS D'ERREUR ci-dessous pour des informations sur d'autres possibilités.

Tcl_UntraceVar peut être utilisé pour supprimer un trace. Si la variable spécifiée par interp, varName, et flags a un trace défini avec flags, proc, et clientData, alors le trace correspondant est supprimé. Si aucun trace de ce type n'existe, l'appel à Tcl_UntraceVar n'a aucun effet. Les mêmes bits sont valides pour flags que pour les appels à Tcl_TraceVar.

Tcl_VarTraceInfo peut être utilisé pour récupérer des informations sur les traces définis sur une variable donnée. La valeur de retour de Tcl_VarTraceInfo est le clientData associé à un trace particulier. Le trace doit porter sur la variable spécifiée par les arguments interp, varName, et flags (seuls les bits TCL_GLOBAL_ONLY et TCL_NAMESPACE_ONLY de flags sont utilisés ; les autres bits sont ignorés) et sa procédure de trace doit être la même que l'argument proc. Si l'argument prevClientData est NULL, alors la valeur de retour correspond au premier trace correspondant (le plus récemment créé), ou NULL s'il n'y a pas de correspondance.

Notez que le nom de la variable peut être spécifié sous la forme habituelle à deux composants de Tcl, à savoir name1 et name2. Dans ce cas, si name2 est NULL, alors le trace porte sur la variable scalaire nommée par name1. Si name2 n'est pas NULL, alors il spécifie l'indice de l'élément de tableau nommé par name1. Les appels à Tcl_TraceVar2 et Tcl_UntraceVar2 utilisent cette forme à deux composants pour spécifier le nom de la variable.

Les appels à Tcl_VarTraceInfo2 et Tcl_UntraceVar2 utilisent également cette forme à deux composants.

Le résultat de Tcl_VarTraceInfo et Tcl_VarTraceInfo2 est le clientData du trace demandé. S'il n'y a pas de trace correspondant à ces critères, NULL est retourné. Si plusieurs traces correspondent, le premier rencontré sera retourné. Pour obtenir les autres traces correspondants, appelez à nouveau la procédure avec la valeur de retour de l'appel précédent comme nouvelle valeur pour prevClientData.

RETOURS DES PROCÉDURES DE TRACE

Si une procédure de trace retourne une chaîne non NULL, celle-ci remplace la valeur résultant de l'opération qui a déclenché le trace. Si la procédure de trace retourne NULL, l'opération se poursuit normalement. Les indicateurs TCL_TRACE_RESULT_DYNAMIC et TCL_TRACE_RESULT_OBJECT peuvent être utilisés pour spécifier la manière dont le résultat doit être géré par Tcl.

RETOURS DES FONCTIONS API

Tcl_TraceVar et Tcl_TraceVar2 retournent TCL_OK en cas de succès, ou TCL_ERROR en cas d'échec (par exemple, si varName ou name1/name2 ne correspondent pas à une variable existante ou si les flags sont invalides). Dans le cas d'une erreur, un message d'erreur est placé dans le résultat de l'interpréteur.

Tcl_UntraceVar et Tcl_UntraceVar2 ne retournent rien.

Tcl_VarTraceInfo et Tcl_VarTraceInfo2 retournent le clientData du trace trouvé, ou NULL s'il n'y en a pas.

EXEMPLE

Pour créer un trace qui sera déclenché lors de la lecture ou de l'écriture de la variable globale `myVar` :

int result = Tcl_TraceVar(interp, "myVar", TCL_TRACE_READS | TCL_TRACE_WRITES,
                          myTraceProc, (ClientData)NULL);
if (result != TCL_OK) {
    fprintf(stderr, "%s\n", Tcl_GetStringResult(interp));
}

Pour supprimer le trace ci-dessus :

Tcl_UntraceVar(interp, "myVar", TCL_TRACE_READS | TCL_TRACE_WRITES,
               myTraceProc, (ClientData)NULL);

Pour trouver le clientData du trace le plus récent de lecture/écriture sur `myVar` :

ClientData cd = Tcl_VarTraceInfo(interp, "myVar",
                                TCL_TRACE_READS | TCL_TRACE_WRITES,
                                myTraceProc, NULL);

VOIR AUSSI

Tcl_SetVar(3), Tcl_GetVar(3), Tcl_SetAssocData(3), Tcl_VarEval(3)

TCL_TRACE_DESTROYED ET TCL_INTERP_DESTROYED

Lorsque le bit TCL_TRACE_DESTROYED est défini dans l'argument flags passé à la procédure de trace proc, cela signifie que le trace lui-même est sur le point d'être supprimé. Ceci est typiquement causé par un appel à Tcl_UntraceVar ou Tcl_UntraceVar2. La procédure de trace devrait utiliser cette information pour effectuer tout nettoyage nécessaire de ses propres structures de données associées à ce trace avant qu'il ne soit effectivement supprimé.

Lorsque le bit TCL_INTERP_DESTROYED est défini dans l'argument flags passé à la procédure de trace proc, cela signifie que l'interpréteur entier est en cours de destruction. Dans ce cas, la procédure de trace doit être particulièrement prudente quant aux opérations qu'elle effectue. En particulier, elle ne doit pas essayer d'appeler de procédures Tcl qui pourraient elles-mêmes déclencher des traces ou des callbacks qui pourraient accéder à des ressources qui ne sont plus valides. Les procédures Tcl standard qui manipulent des variables (comme Tcl_GetVar) sont généralement sûres, mais des appels plus complexes peuvent être problématiques. Si la procédure de trace gère des ressources externes (par exemple, des descripteurs de fichiers ou des blocs de mémoire alloués par l'application), c'est le moment idéal pour les libérer.

NOMS EN DEUX PARTIES

Les procédures Tcl_TraceVar2, Tcl_UntraceVar2 et Tcl_VarTraceInfo2 sont identiques à Tcl_TraceVar, Tcl_UntraceVar et Tcl_VarTraceInfo, respectivement, à la seule différence que le nom de la variable se compose de deux parties. Name1 donne le nom d'une variable scalaire ou d'un tableau, et name2 donne le nom d'un élément dans un tableau. Lorsque name2 est NULL, name1 peut contenir à la fois un nom de tableau et un nom d'élément : si le nom contient une parenthèse ouvrante et se termine par une parenthèse fermante, alors la valeur entre les parenthèses est traitée comme un nom d'élément (qui peut avoir n'importe quelle valeur de chaîne) et les caractères avant la première parenthèse ouvrante sont traités comme le nom d'une variable de tableau. Si name2 est NULL et que name1 ne fait pas référence à un élément de tableau, cela signifie soit que la variable est scalaire, soit que la trace doit être définie sur le tableau entier plutôt que sur un élément individuel (voir TRACES DE TABLEAU ENTIER ci-dessous pour plus d' informations).

ACCES AUX VARIABLES PENDANT LES TRACES

Pendant les traces de lecture, d'écriture et de tableau, la procédure de trace peut lire, écrire ou désinstaller la variable tracée en utilisant Tcl_GetVar2, Tcl_SetVar2 et d'autres procédures. Pendant que proc est en cours d'exécution, les traces sont temporairement désactivées pour la variable, de sorte que les appels à Tcl_GetVar2 et Tcl_SetVar2 ne provoquent pas la réinvocation de proc ou d'autres procédures de trace. La désactivation n'a lieu que pour la variable dont la procédure de trace est active ; les accès aux autres variables seront toujours tracés. Cependant, si une variable est désinstallée pendant une trace de lecture ou d'écriture, les traces de désinstallation seront invoquées.

Pendant les traces de désinstallation, la variable a déjà été complètement expurgée. Il est possible pour la procédure de trace de lire ou d'écrire la variable, mais ce sera une nouvelle version de la variable. Les traces ne sont pas désactivées pendant les traces de désinstallation, comme elles le sont pour les traces de lecture et d'écriture, mais les traces existantes ont été supprimées de la variable avant que les procédures de trace ne soient invoquées. Si de nouvelles traces sont définies par les procédures de trace de désinstallation, ces traces seront invoquées lors des accès à la variable par les procédures de trace.

CALENDRIER DES APPELS

Lorsqu'un traçage de lecture a été spécifié pour une variable, la procédure de trace sera invoquée chaque fois que la valeur de la variable sera lue. Cela inclut les commandes Tcl set, la notation $ dans les commandes Tcl, et les invocations des procédures Tcl_GetVar et Tcl_GetVar2. Proc est invoquée juste avant que la valeur de la variable ne soit retournée. Elle peut modifier la valeur de la variable pour affecter ce qui est retourné par l'accès tracé. Si elle désinstalle la variable, alors l'accès retournera une erreur, comme si la variable n'avait jamais existé.

Lorsqu'un traçage d'écriture a été spécifié pour une variable, la procédure de trace sera invoquée chaque fois que la valeur de la variable sera modifiée. Cela inclut les commandes set, les commandes qui modifient les variables comme effets secondaires (telles que catch et scan), et les appels aux procédures Tcl_SetVar et Tcl_SetVar2). Proc sera invoquée après que la valeur de la variable ait été modifiée, mais avant que la nouvelle valeur de la variable n'ait été retournée. Elle peut modifier la valeur de la variable pour outrepasser le changement et pour déterminer la valeur effectivement retournée par l'accès tracé. Si elle supprime la variable, alors l'accès tracé retournera une chaîne vide.

Lorsqu'un traçage de tableau a été spécifié, la procédure de trace sera invoquée au début de l'implémentation de la commande de tableau, avant que toutes les opérations comme get, set ou names n'aient été invoquées. La procédure de trace peut modifier les éléments du tableau avec Tcl_SetVar et Tcl_SetVar2.

Lorsqu'un traçage de désinstallation a été spécifié, la procédure de trace sera invoquée chaque fois que la variable sera détruite. Les traces seront appelées après que la variable ait été complètement désinstallée.

TRACES DE TABLEAU ENTIER

Si un appel à Tcl_TraceVar ou Tcl_TraceVar2 spécifie le nom d'une variable de tableau sans index dans le tableau, alors la trace sera définie sur le tableau dans son ensemble. Cela signifie que proc sera invoquée chaque fois qu'un élément du tableau sera accédé de la manière spécifiée par flags. Lorsqu'un tableau est désinstallé, une trace de tableau entier sera invoquée une seule fois, avec name1 égal au nom du tableau et name2 NULL ; elle ne sera pas invoquée une fois pour chaque élément.

TRACES MULTIPLES

Il est possible que plusieurs traces existent sur la même variable. Lorsque cela se produit, toutes les procédures de trace seront invoquées à chaque accès, dans l'ordre de la plus récemment créée à la moins récemment créée. Lorsqu'il existe des traces de tableau entier pour un tableau ainsi que des traces sur des éléments individuels, les traces de tableau entier sont invoquées avant les traces d'éléments individuels. Si une trace de lecture ou d'écriture désinstalle la variable, alors toutes les traces de désinstallation seront invoquées, mais les traces de lecture et d'écriture restantes seront ignorées.

RETOURS D'ERREUR

Dans des conditions normales, les procédures de trace doivent retourner NULL, indiquant un achèvement réussi. Si proc retourne une valeur non NULL, cela signifie qu'une erreur s'est produite. La valeur de retour doit être un pointeur vers une chaîne de caractères statique contenant un message d'erreur, sauf si (exactement un des) les drapeaux TCL_TRACE_RESULT_DYNAMIC et TCL_TRACE_RESULT_OBJECT est défini, qui spécifient que le résultat est soit une chaîne dynamique (à libérer avec ckfree) soit un Tcl_Obj* (converti en char* et à libérer avec Tcl_DecrRefCount) contenant le message d'erreur. Si une procédure de trace retourne une erreur, aucune autre trace n'est invoquée pour l'accès et l'accès tracé est avorté avec le message donné. Les procédures de trace peuvent utiliser cette fonctionnalité pour rendre les variables en lecture seule, par exemple (mais notez que la valeur de la variable aura déjà été modifiée avant que la procédure de trace ne soit appelée, donc la procédure de trace devra restaurer la valeur correcte).

La valeur de retour de proc n'est utilisée que pendant les traces de lecture et d'écriture. Pendant les traces de désinstallation, la valeur de retour est ignorée et toutes les procédures de trace pertinentes seront toujours invoquées.

RESTRICTIONS

Une procédure de trace peut être appelée à tout moment, même lorsqu'il existe des résultats partiellement formés stockés dans l'interpréteur. Si la procédure de trace fait quoi que ce soit qui pourrait endommager ce résultat (comme appeler Tcl_Eval), elle doit utiliser Tcl_SaveInterpState et les routines associées pour sauvegarder et restaurer l'état d'origine de l'interpréteur avant de retourner.

VARIABLES NON DÉFINIES

Il est légal de définir une trace sur une variable non définie. La variable semblera toujours non définie jusqu'à la première fois où sa valeur sera définie. Si une variable non définie est tracée puis désinstallée, la désinstallation échouera avec une erreur (« pas de telle variable »), mais la procédure de trace sera quand même invoquée.

DRAPEAU TCL_TRACE_DESTROYED

Dans un rappel de désinstallation à proc, le bit TCL_TRACE_DESTROYED est défini dans flags si la trace est supprimée dans le cadre de la suppression. Les traces sur une variable sont toujours supprimées lorsque la variable est supprimée ; la seule fois où TCL_TRACE_DESTROYED n'est pas défini est pour une trace de tableau entier invoquée lorsque seul un seul élément d'un tableau est désinstallé.

TCL_INTERP_DESTROYED

Lorsqu'un interpréteur est détruit, les traces de désinstallation sont appelées pour toutes ses variables. Le bit TCL_INTERP_DESTROYED sera défini dans l'argument flags passé aux procédures de trace. Les procédures de trace doivent être extrêmement prudentes dans ce qu'elles font si le bit TCL_INTERP_DESTROYED est défini. Il n'est pas sûr pour les procédures d'invoquer des procédures Tcl sur l'interpréteur, car son état est partiellement supprimé. Tout ce que les procédures de trace devraient faire dans ces circonstances est de nettoyer et de libérer leurs propres structures de données internes.

BOGUES

Tcl n'effectue aucune vérification d'erreur pour empêcher les procédures de trace d'utiliser mal l'interpréteur pendant les traces avec TCL_INTERP_DESTROYED défini.

Les traces de tableaux ne sont pas encore intégrées à la commande Tcl info exists, et il n'y a pas non plus d'accès au niveau Tcl aux traces de tableaux.
