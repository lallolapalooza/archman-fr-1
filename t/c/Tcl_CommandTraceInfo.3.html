Paquet: tcl

Licences: TCL

Tcl_TraceCommand(3) Procédures de la bibliothèque Tcl Tcl_TraceCommand(3)

NOM

Tcl_CommandTraceInfo, Tcl_TraceCommand, Tcl_UntraceCommand - surveiller les renommages et suppressions d'une commande

SYNOPIS

#include <tcl.h>

ClientData
Tcl_CommandTraceInfo(interp, cmdName, flags, proc, prevClientData)

int
Tcl_TraceCommand(interp, cmdName, flags, proc, clientData)

void
Tcl_UntraceCommand(interp, cmdName, flags, proc, clientData)

ARGUMENTS

Tcl_Interp *interp (en entrée)
Interpréteur contenant la commande.
const char *cmdName (en entrée)
Nom de la commande.
int flags (en entrée)
Combinaison OR des valeurs TCL_TRACE_RENAME et TCL_TRACE_DELETE.
Tcl_CommandTraceProc *proc (en entrée)
Procédure à appeler lorsque les opérations spécifiées sont effectuées sur cmdName.
ClientData clientData (en entrée)
Argument arbitraire à passer à proc.
ClientData prevClientData (en entrée)
Si non NULL, donne la dernière valeur retournée par Tcl_CommandTraceInfo, de sorte que cet appel retournera des informations sur le trace suivant. Si NULL, cet appel retournera des informations sur le premier trace.

DESCRIPTION

Tcl_TraceCommand permet à une procédure C de surveiller les opérations effectuées sur une commande Tcl, de telle sorte que la procédure C soit appelée chaque fois que la commande est renommée ou supprimée. Si le trace est créé avec succès, Tcl_TraceCommand retourne TCL_OK. Si une erreur s'est produite (par exemple, cmdName spécifie une commande inexistante), TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de l'interpréteur.

L'argument flags de Tcl_TraceCommand indique quand la procédure de trace doit être appelée. Il se compose d'une combinaison OR de n'importe lesquelles des valeurs suivantes :

TCL_TRACE_RENAME
Appeler proc chaque fois que la commande est renommée.
TCL_TRACE_DELETE
Appeler proc lorsque la commande est supprimée.

Chaque fois qu'une des opérations spécifiées est effectuée sur la commande, proc sera appelée. Elle doit avoir des arguments et un résultat correspondant au type Tcl_CommandTraceProc :

typedef void Tcl_CommandTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *oldName,
        const char *newName,
        int flags);

Les paramètres clientData et interp auront les mêmes valeurs que celles passées à Tcl_TraceCommand lors de la création du trace. ClientData pointe généralement vers une structure de données spécifique à l'application qui décrit ce qu'il faut faire lorsque proc est appelée. OldName donne le nom de la commande en cours de renommage, et newName donne le nom auquel la commande est renommée (ou NULL lorsque la commande est supprimée.) Flags est une combinaison OR de bits fournissant potentiellement plusieurs informations. L'un des bits TCL_TRACE_RENAME et TCL_TRACE_DELETE sera défini dans flags pour indiquer quelle opération est effectuée sur la commande. Le bit TCL_TRACE_DESTROYED sera défini dans flags si le trace est sur le point d'être détruit ; cette information peut être utile à proc pour qu'elle puisse nettoyer ses propres structures de données internes (voir la section TCL_TRACE_DESTROYED ci-dessous pour plus de détails). Étant donné que la suppression des commandes peut avoir lieu dans le cadre de la suppression de l'interpréteur qui les contient, proc doit être prudent en vérifiant sur quoi la valeur passée interp peut être appelée. La fonction Tcl_InterpDeleted est un outil important à cet égard. Lorsque Tcl_InterpDeleted retourne 1, proc ne pourra invoquer aucun script dans interp. La fonction de proc dans ce cas est limitée au nettoyage de ses propres structures de données.

Tcl_UntraceCommand peut être utilisé pour supprimer un trace. Si la commande spécifiée par interp, cmdName et flags a un trace défini avec flags, proc et clientData, alors le trace correspondant est supprimé. S'il n'existe aucun trace de ce type, l'appel à Tcl_UntraceCommand n'a aucun effet. Les mêmes bits sont valides pour flags que pour les appels à Tcl_TraceCommand.

Tcl_CommandTraceInfo peut être utilisé pour récupérer des informations sur les traces définis pour une commande donnée. La valeur de retour de Tcl_CommandTraceInfo est le clientData associé à un trace particulier. Le trace doit être sur la commande spécifiée par les arguments interp, cmdName et flags (notez que les flags sont actuellement ignorés ; flags doit être défini à 0 pour la compatibilité future) et sa procédure de trace doit être la même que l'argument proc. Si l'argument prevClientData est NULL, alors la valeur de retour correspond au premier trace correspondant (le plus récemment créé), ou NULL s'il n'y a pas de traces correspondants. Si l'argument prevClientData n'est pas NULL, alors il doit s'agir de la valeur de retour d'un appel précédent à Tcl_CommandTraceInfo. Dans ce cas, la nouvelle valeur de retour correspondra au prochain trace correspondant après celui dont le clientData correspond à prevClientData, ou NULL s'il n'y a pas de trace correspondant à prevClientData ou s'il n'y a plus de traces correspondants après lui. Ce mécanisme permet de parcourir tous les traces d'une commande donnée qui ont le même proc.

APPEL DES COMMANDES PENDANT LES TRACES

Pendant les traces de renommage, la commande en cours de renommage est visible avec les deux noms simultanément, et la commande existe toujours pendant les traces de suppression, à moins que l'interpréteur qui la contient ne soit en cours de suppression. Cependant, il n'y a aucun mécanisme pour signaler qu'une erreur s'est produite dans une procédure de trace, donc une grande prudence doit être prise pour que les erreurs ne soient pas perdues silencieusement.

MULTIPLE TRACES

Il est possible que plusieurs traces existent sur la même commande. Lorsque cela se produit, toutes les procédures de trace seront appelées à chaque accès, dans l'ordre du plus récemment créé au moins récemment créé. Les tentatives de supprimer la commande pendant une trace de suppression échoueront silencieusement, car la commande est déjà programmée pour suppression. Si la commande en cours de renommage est renommée par l'une de ses traces de renommage, ce renommage prend la priorité sur celui qui a déclenché le trace et l'ensemble des traces ne sera pas réexécuté ; si plusieurs traces renomment la commande, le dernier renommage prend la priorité.

FLAG TCL_TRACE_DESTROYED

Dans une callback de suppression à proc, le bit TCL_TRACE_DESTROYED est défini dans flags.
