INTRODUCTION

À partir de la version 8.1, le noyau Tcl est thread-safe, ce qui vous permet d'intégrer Tcl dans des applications multithreadées sans personnaliser le noyau Tcl. À partir de la version 8.6, le support du multithreading Tcl est activé par défaut. Pour désactiver le support du multithreading Tcl, vous devez inclure l'option --disable-threads à configure lors de la configuration et de la compilation de votre noyau Tcl.

Une contrainte importante de l'implémentation des threads Tcl est que seul le thread qui a créé un interpréteur Tcl peut utiliser cet interpréteur. En d'autres termes, plusieurs threads ne peuvent pas accéder au même interpréteur Tcl. (Cependant, un seul thread peut créer et utiliser plusieurs interpréteurs en toute sécurité.)

DESCRIPTION

Tcl fournit Tcl_CreateThread pour la création de threads. L'appelant peut déterminer la taille de la pile donnée au nouveau thread et modifier son comportement via les flags fournis. La valeur TCL_THREAD_STACK_DEFAULT pour stackSize indique que la taille par défaut spécifiée par le système d'exploitation doit être utilisée pour le nouveau thread. Quant aux indicateurs, actuellement seules les valeurs TCL_THREAD_NOFLAGS et TCL_THREAD_JOINABLE sont définies. La première d'entre elles invoque le comportement par défaut sans réglages spéciaux. L'utilisation de la seconde valeur marque le nouveau thread comme joignable. Cela signifie qu'un autre thread peut attendre la sortie d'un tel thread marqué et le joindre.

Restrictions : Sur certains systèmes UNIX, la bibliothèque pthread ne contient pas la fonctionnalité pour spécifier la taille de la pile d'un thread. La valeur spécifiée pour la taille de la pile est ignorée sur ces systèmes. Windows ne prend actuellement pas en charge les threads joignables. Cette valeur d'indicateur est donc ignorée sur cette plateforme.

Tcl fournit les fonctions Tcl_ExitThread et Tcl_FinalizeThread pour terminer les threads et invoquer des gestionnaires de sortie optionnels par thread. Voir la page Tcl_Exit pour plus d'informations sur ces procédures.

La fonction Tcl_JoinThread est fournie pour permettre aux threads d'attendre la sortie d'un autre thread, qui doit avoir été marqué comme joignable via l'utilisation de l'indicateur TCL_THREAD_JOINABLE lors de sa création via Tcl_CreateThread.

Tenter d'attendre la sortie d'un thread non joignable ou d'un thread déjà attendu entraînera une erreur. Attendre un thread joignable qui est déjà sorti est possible, le système conservera les informations nécessaires jusqu'après l'appel à Tcl_JoinThread. Cela signifie que ne pas appeler Tcl_JoinThread pour un thread joignable causera une fuite de mémoire.

L'appel Tcl_GetThreadData retourne un pointeur vers un bloc de données privées au thread. Son argument est une clé partagée par tous les threads et une taille pour le bloc de stockage. Le stockage est automatiquement alloué et initialisé à zéro lors de la première demande par chaque thread. Le stockage est automatiquement désalloué par Tcl_FinalizeThread.

SYNCHRONISATION ET COMMUNICATION

Tcl fournit Tcl_ThreadQueueEvent et Tcl_ThreadAlert pour la gestion de la mise en file d'attente des événements dans les applications multithreadées. Voir la page de manuel Notifier pour plus d'informations sur ces procédures.

Un mutex est un verrou utilisé pour sérialiser tous les threads à travers un morceau de code en appelant Tcl_MutexLock et Tcl_MutexUnlock. Si un thread détient un mutex, tout autre thread appelant Tcl_MutexLock sera bloqué jusqu'à ce que Tcl_MutexUnlock soit appelé. Un mutex peut être détruit après son utilisation en appelant Tcl_MutexFinalize. Le résultat du verrouillage d'un mutex deux fois par le même thread est indéfini. Sur certaines plateformes, cela entraînera un interblocage. Les procédures Tcl_MutexLock, Tcl_MutexUnlock et Tcl_MutexFinalize sont définies comme des macros vides si elles ne sont pas compilées avec les threads activés. Pour la déclaration des mutex, la macro TCL_DECLARE_MUTEX doit être utilisée. Cette macro assure une gestion correcte des mutex même lorsque le noyau est compilé sans support des threads activé.

Une variable de condition est utilisée comme mécanisme de signalisation : un thread peut verrouiller un mutex puis attendre sur une variable de condition avec Tcl_ConditionWait. Cela libère atomiquement le verrou mutex et bloque le thread en attente jusqu'à ce qu'un autre thread appelle Tcl_ConditionNotify. L'appelant de Tcl_ConditionNotify doit détenir le mutex associé en ayant précédemment appelé Tcl_MutexLock, mais cela n'est pas imposé. La notification de la variable de condition débloque tous les threads en attente sur la variable de condition, mais ils ne progressent pas tant que le mutex n'est pas libéré avec Tcl_MutexUnlock. L'implémentation de Tcl_ConditionWait verrouille automatiquement le mutex avant de retourner.

L'appelant de Tcl_ConditionWait doit être préparé aux notifications impromptues en appelant Tcl_ConditionWait dans une boucle while qui teste un invariant.

Une variable de condition peut être détruite après son utilisation en appelant Tcl_ConditionFinalize.

Les procédures Tcl_ConditionNotify, Tcl_ConditionWait et Tcl_ConditionFinalize sont définies comme des macros vides si elles ne sont pas compilées avec les threads activés.

INITIALISATION

Tous ces objets de synchronisation sont auto-initialisés. Ils sont implémentés comme des pointeurs opaques qui devraient être NULL lors de leur première utilisation. Les mutex et les variables de condition sont soit nettoyés par les gestionnaires de sortie de processus (s'ils vivent aussi longtemps), soit explicitement par des appels à Tcl_MutexFinalize ou Tcl_ConditionFinalize. Le stockage local aux threads est récupéré lors de Tcl_FinalizeThread.

INTRODUCTION

Le package Thread fournit une interface pour créer et gérer des threads sous Tcl. Les threads sont une manière d'exécuter plusieurs parties de votre programme simultanément. Ce package peut être utilisé pour créer des applications multithreadées qui peuvent bénéficier du parallélisme.

DESCRIPTION

Les fonctions fournies par le package Thread vous permettent de créer de nouveaux threads, d'attendre leur achèvement, de gérer la sortie des threads, de mettre en file d'attente des événements pour des threads spécifiques et d'alerter des threads pour qu'ils traitent des événements.

La création de threads est effectuée par la procédure Tcl_CreateThread. Elle prend un pointeur vers un Tcl_ThreadId, une procédure de démarrage, des données client, une taille de pile et un indicateur de jointure. La procédure de démarrage est celle qui sera exécutée par le nouveau thread.

Tcl_JoinThread est utilisé pour attendre qu'un thread se termine. Elle prend l'ID du thread à rejoindre et un pointeur vers un int qui recevra le statut de sortie du thread.

Tcl_ExitThread termine le thread courant avec un statut de sortie spécifié. Tcl_FinalizeThread nettoie les ressources associées au thread courant.

Tcl_GetCurrentThread renvoie l'ID du thread courant. Tcl_IsMainThread vérifie si le thread courant est le thread principal de l'application.

Tcl_ThreadQueueEvent met en file d'attente un événement pour un thread spécifique, et Tcl_ThreadAlert alerte un thread pour qu'il traite les événements en attente.

Tcl_CreateThreadExitHandler enregistre un gestionnaire à appeler avant la sortie d'un thread, et Tcl_DeleteThreadExitHandler supprime un gestionnaire enregistré.

ACCÈS AUX THREADS AU NIVEAU DU SCRIPT

Bien que les fonctions ci-dessus fournissent une API C pour la gestion des threads, Tcl offre également un accès au niveau du script à certaines de ces fonctionnalités via des commandes Tcl intégrées ou des extensions de package. L'une de ces extensions est le package Thread.

EXEMPLE

Pour créer un thread avec du code portable, sa fonction d'implémentation doit être déclarée comme suit:

static Tcl_ThreadCreateProc MyThreadImplFunc;

Elle devrait ensuite être définie comme cet exemple, qui compte simplement jusqu'à une valeur donnée puis se termine.

static Tcl_ThreadCreateType
MyThreadImplFunc(
    ClientData clientData)
{
    int i, limit = (int) clientData;
    for (i=0 ; i<limit ; i++) {
        /* ne fait rien du tout ici */
    }
    TCL_THREAD_CREATE_RETURN;
}

Pour créer le thread ci-dessus, le faire exécuter et attendre sa fin, nous ferions ceci:

int limit = 1000000000;
ClientData limitData = (void*)((intptr_t) limit);
Tcl_ThreadId id;    /* contient l'identité du thread créé */
int result;
if (Tcl_CreateThread(&id, MyThreadImplFunc, limitData,
        TCL_THREAD_STACK_DEFAULT,
        TCL_THREAD_JOINABLE) != TCL_OK) {
    /* Le thread n'a pas été créé correctement */
    return;
}
/* Faire autre chose pendant un moment ici */
if (Tcl_JoinThread(id, &result) != TCL_OK) {
    /* Le thread ne s'est pas terminé correctement */
    return;
}
/* Tout est bien nettoyé */
