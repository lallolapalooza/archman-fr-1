ARGUMENTS

Tcl_HashTable *tablePtr (entrée)
Adresse de la structure de table de hachage (pour toutes les procédures sauf Tcl_InitHashTable, celle-ci doit avoir été initialisée par un appel précédent à Tcl_InitHashTable).
int keyType (entrée)
Type de clés à utiliser pour la nouvelle table de hachage. Doit être soit TCL_STRING_KEYS, TCL_ONE_WORD_KEYS, TCL_CUSTOM_TYPE_KEYS, TCL_CUSTOM_PTR_KEYS, ou une valeur entière supérieure à 1.
Tcl_HashKeyType *typePtr (entrée)
Adresse de la structure qui définit le comportement de la table de hachage.
const void *key (entrée)
Clé à utiliser pour sonder la table. La forme exacte dépend de keyType utilisé pour créer la table.
int *newPtr (sortie)
Le mot à l'adresse *newPtr est défini à 1 si une nouvelle entrée a été créée et 0 s'il existait déjà une entrée pour key.
Tcl_HashEntry *entryPtr (entrée)
Pointeur vers une entrée de table de hachage.
ClientData value (entrée)
Nouvelle valeur à assigner à l'entrée de la table de hachage. N'a pas besoin d'avoir le type ClientData, mais doit tenir dans le même espace que ClientData.
Tcl_HashSearch *searchPtr (entrée)
Pointeur vers l'enregistrement à utiliser pour suivre la progression lors de l'énumération de toutes les entrées d'une table de hachage.

DESCRIPTION

Une table de hachage se compose de zéro ou plusieurs entrées, chacune constituée d'une clé et d'une valeur. Étant donné la clé d'une entrée, les routines de hachage peuvent localiser très rapidement l'entrée, et donc sa valeur. Il peut y avoir au plus une entrée dans une table de hachage avec une clé particulière, mais de nombreuses entrées peuvent avoir la même valeur. Les clés peuvent prendre l'une des quatre formes suivantes : chaînes de caractères, valeurs d'un seul mot, tableaux d'entiers, ou clés personnalisées définies par une structure Tcl_HashKeyType (voir la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous). Toutes les clés d'une table donnée ont la même forme, qui est spécifiée lors de l'initialisation de la table.

La valeur d'une entrée de table de hachage peut être n'importe quoi qui tient dans le même espace qu'un pointeur “char *”. Les valeurs des entrées de table de hachage sont gérées entièrement par les clients, et non par le module de hachage lui-même. Typiquement, la valeur de chaque entrée est un pointeur vers une structure de données gérée par le code client.

Les tables de hachage se développent de manière fluide à mesure que le nombre d'entrées augmente, de sorte qu'il y ait toujours moins de trois entrées par compartiment de hachage, en moyenne. Cela permet des recherches rapides, quel que soit le nombre d'entrées dans une table.

Le cœur fournit trois fonctions pour l'initialisation des tables de hachage : Tcl_InitHashTable, Tcl_InitObjHashTable et Tcl_InitCustomHashTable.

Tcl_InitHashTable initialise une structure décrivant une nouvelle table de hachage. L'espace pour la structure est fourni par l'appelant, pas par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. Tous les types de clés décrits plus tard sont autorisés, à l'exception de TCL_CUSTOM_TYPE_KEYS et TCL_CUSTOM_PTR_KEYS.

Tcl_InitObjHashTable est un wrapper autour de Tcl_InitCustomHashTable et initialise une table de hachage dont les clés sont des Tcl_Obj *.

Tcl_InitCustomHashTable initialise une structure décrivant une nouvelle table de hachage. L'espace pour la structure est fourni par l'appelant, pas par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. KeyType doit avoir l'une des valeurs suivantes :

TCL_STRING_KEYS
Les clés sont des chaînes de caractères terminées par un caractère nul. Elles sont passées aux routines de hachage en utilisant l'adresse du premier caractère de la chaîne.
TCL_ONE_WORD_KEYS
Les clés sont des valeurs d'un seul mot ; elles sont passées aux routines de hachage et stockées dans les entrées de la table de hachage comme des valeurs “char *”. La valeur du pointeur est la clé ; elle n'a pas besoin (et ne pointe généralement pas) vers une chaîne de caractères.
TCL_CUSTOM_TYPE_KEYS
Les clés sont de type arbitraire et sont stockées dans l'entrée. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous.
TCL_CUSTOM_PTR_KEYS
Les clés sont des pointeurs vers un type arbitraire et sont stockées dans l'entrée. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous.
autre
Si keyType n'est pas l'un des éléments ci-dessus, il doit s'agir d'une valeur entière supérieure à 1. Dans ce cas, les clés seront des tableaux de valeurs “int”, où keyType donne le nombre d'entiers dans chaque clé. Cela permet d'utiliser des structures comme clés. Toutes les clés doivent avoir la même taille. Les clés de tableau sont passées aux fonctions de hachage en utilisant l'adresse du premier entier du tableau.

Tcl_DeleteHashTable supprime toutes les entrées d'une table de hachage et libère la mémoire associée au tableau de compartiments de la table et aux entrées. Elle ne libère pas la structure de table elle-même (pointée par tablePtr), car cette mémoire est supposée être gérée par le client. Tcl_DeleteHashTable ne libère pas non plus et ne manipule pas autrement les valeurs des entrées de la table de hachage. Si les valeurs des entrées pointent vers de la mémoire allouée dynamiquement, il incombe au client de libérer ces structures avant de supprimer la table.

Tcl_CreateHashEntry localise l'entrée correspondant à une clé particulière, en créant une nouvelle entrée dans la table s'il n'y en avait pas déjà une avec la clé donnée. Si une entrée existait déjà avec la clé donnée, alors *newPtr est mis à zéro. Si une nouvelle entrée a été créée, alors *newPtr est mis à une valeur non nulle et la valeur de la nouvelle entrée sera mise à zéro. La valeur de retour de Tcl_CreateHashEntry est un pointeur vers l'entrée, qui peut être utilisé pour récupérer et modifier la valeur de l'entrée ou pour supprimer l'entrée de la table.

Tcl_DeleteHashEntry supprimera une entrée existante d'une table. La mémoire associée à l'entrée elle-même sera libérée, mais le client est responsable de tout nettoyage associé à la valeur de l'entrée, tel que la libération d'une structure à laquelle elle pointe.

Tcl_FindHashEntry est similaire à Tcl_CreateHashEntry sauf qu'il ne crée pas de nouvelle entrée si la clé n'existe pas ; il renvoie NULL comme résultat.

Tcl_GetHashValue et Tcl_SetHashValue sont utilisés pour lire et écrire la valeur d'une entrée, respectivement. Les valeurs sont stockées et récupérées comme type “ClientData”, qui est suffisamment grand pour contenir une valeur de pointeur. Sur presque toutes les machines, cela suffit également pour contenir une valeur entière.

Tcl_GetHashKey renvoie la clé d'une entrée de table de hachage donnée, soit sous forme de pointeur vers une chaîne, une clé d'un seul mot (“char *”), soit sous forme de pointeur vers le premier mot d'un tableau d'entiers, en fonction du keyType utilisé pour créer la table de hachage. Dans tous les cas, Tcl_GetHashKey renvoie un résultat de type “char *”. Lorsque la clé est une chaîne ou un tableau, le résultat de Tcl_GetHashKey pointe vers des informations dans l'entrée de la table ; ces informations resteront valides jusqu'à ce que l'entrée soit supprimée ou que sa table soit supprimée.

Tcl_FirstHashEntry et Tcl_NextHashEntry peuvent être utilisés pour parcourir toutes les entrées d'une table de hachage

LA STRUCTURE TCL_HASHKEYTYPE

Les programmeurs d'extensions peuvent définir de nouveaux types de clés de hachage en définissant quatre procédures, en initialisant une structure Tcl_HashKeyType pour décrire le type, et en appelant Tcl_InitCustomHashTable. La structure Tcl_HashKeyType est définie comme suit :

typedef struct Tcl_HashKeyType {
    int version;
    int flags;
    Tcl_HashKeyProc *hashKeyProc;
    Tcl_CompareHashKeysProc *compareKeysProc;
    Tcl_AllocHashEntryProc *allocEntryProc;
    Tcl_FreeHashEntryProc *freeEntryProc;
} Tcl_HashKeyType;

Le membre version est la version de la table. Si cette structure est étendue dans le futur, la version peut être utilisée pour distinguer différentes structures. Il doit être défini à TCL_HASH_KEY_TYPE_VERSION.

Le membre flags est 0 ou une ou plusieurs des valeurs suivantes combinées par OR :

TCL_HASH_KEY_RANDOMIZE_HASH
Certains éléments, comme les pointeurs, ne sont pas bien hachés car ils n'utilisent pas les bits de poids faible. Si ce drapeau est défini, la table de hachage tentera de corriger cela en randomisant les bits, puis en utilisant les N bits supérieurs comme index dans la table.
TCL_HASH_KEY_SYSTEM_HASH
Ce drapeau force Tcl à utiliser les procédures d'allocation mémoire fournies par le système d'exploitation lors de l'allocation et de la libération de la mémoire utilisée pour stocker les structures de données de la table de hachage, et non les routines d'allocation mémoire personnalisées de Tcl. Ceci est important si la table de hachage doit être utilisée dans l'implémentation d'un ensemble personnalisé de routines d'allocation, ou de quelque chose dont un ensemble personnalisé de routines d'allocation pourrait dépendre, afin d'éviter toute dépendance circulaire.

Le membre hashKeyProc contient l'adresse d'une fonction appelée pour calculer une valeur de hachage pour la clé.

typedef unsigned int Tcl_HashKeyProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

Si ceci est NULL, keyPtr est utilisé et TCL_HASH_KEY_RANDOMIZE_HASH est supposé.

Le membre compareKeysProc contient l'adresse d'une fonction appelée pour comparer deux clés.

typedef int Tcl_CompareHashKeysProc(
        void *keyPtr,
        Tcl_HashEntry *hPtr);

Si ceci est NULL, les pointeurs keyPtr sont comparés. Si les clés ne correspondent pas, la fonction renvoie 0, sinon elle renvoie 1.

Le membre allocEntryProc contient l'adresse d'une fonction appelée pour allouer de l'espace pour une entrée et initialiser la clé et clientData.

typedef Tcl_HashEntry *Tcl_AllocHashEntryProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

Si ceci est NULL, Tcl_Alloc est utilisé pour allouer suffisamment d'espace pour une Tcl_HashEntry, le pointeur de clé est assigné à key.oneWordValue et clientData est défini à NULL. Les clés de chaîne et les clés de tableau utilisent cette fonction pour allouer suffisamment d'espace pour l'entrée et la clé dans un seul bloc, plutôt que de le faire en deux blocs. Cela économise de l'espace pour un pointeur vers la clé depuis l'entrée et une autre allocation mémoire. Les clés Tcl_Obj* utilisent cette fonction pour allouer suffisamment d'espace pour une entrée et incrémenter le compteur de références sur la valeur.

Le membre freeEntryProc contient l'adresse d'une fonction appelée pour libérer l'espace d'une entrée.

typedef void Tcl_FreeHashEntryProc(
        Tcl_HashEntry *hPtr);

Si ceci est NULL, Tcl_Free est utilisé pour libérer l'espace de l'entrée. Les clés Tcl_Obj* utilisent cette fonction pour décrémenter le compteur de références sur la valeur.
