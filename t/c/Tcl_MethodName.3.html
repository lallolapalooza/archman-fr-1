ARGUMENTS

Tcl_Interp *interp (in/out)
L'interpréteur contenant l'objet ou la classe pour créer ou mettre à jour une méthode.
Tcl_Object object (in)
L'objet sur lequel la méthode sera créée.
Tcl_Class class (in)
La classe sur laquelle la méthode sera créée.
Tcl_Obj *nameObj (in)
Le nom de la méthode à créer. Ne doit pas être NULL si un constructeur ou un destructeur est créé.
int isPublic (in)
Un indicateur indiquant la visibilité de la méthode. Les valeurs supportées pour cet indicateur sont 0 pour une méthode non exportée et 1 pour une méthode exportée.
Tcl_MethodType *methodTypePtr (in)
Une description du type de la méthode à créer, ou le type de méthode à comparer.
ClientData clientData (in)
Un morceau de données passé à l'implémentation de la méthode sans interprétation.
ClientData *clientDataPtr (out)
Un pointeur vers une variable dans laquelle écrire la valeur de clientData fournie lors de la création de la méthode. S'il est NULL, la valeur de clientData ne sera pas récupérée.
Tcl_Method method (in)
Une référence à une méthode à interroger.
Tcl_ObjectContext context (in)
Une référence à un contexte d'appel de méthode. Note : le code client ne doit pas conserver de référence à un contexte.
int objc (in)
Le nombre d'arguments passés à l'implémentation de la méthode.
Tcl_Obj *const *objv (in)
Un tableau d'arguments passés à l'implémentation de la méthode.
int skip (in)
Le nombre d'arguments passés à l'implémentation de la méthode qui ne représentent pas d'arguments « réels ».

DESCRIPTION

Une méthode est une opération effectuée sur un objet associé à l'objet. Chaque méthode doit être associée à un objet ou à une classe ; les méthodes associées à une classe sont associées à toutes les instances (directes et indirectes) de cette classe.

Étant donné une méthode, l'entité qui l'a déclarée peut être trouvée à l'aide de Tcl_MethodDeclarerClass, qui renvoie la classe à laquelle la méthode est associée (ou NULL si la méthode n'est associée à aucune classe), et Tcl_MethodDeclarerObject, qui renvoie l'objet auquel la méthode est associée (ou NULL si la méthode n'est associée à aucun objet). Le nom de la méthode peut être récupéré avec Tcl_MethodName et si elle est exportée, elle peut être récupérée avec Tcl_MethodIsPublic. On peut également inspecter le type de la méthode de manière limitée ; la fonction Tcl_MethodIsType renvoie si une méthode est d'un type spécifique, en assignant la valeur de clientData à la variable pointée par clientDataPtr si (c'est-à-dire non NULL) le type correspond.

CRÉATION DE MÉTHODES

Les méthodes sont créées avec Tcl_NewMethod et Tcl_NewInstanceMethod, qui créent une méthode associée à une classe ou à un objet respectivement. Dans les deux cas, l'argument nameObj donne le nom de la méthode à créer, l'argument isPublic indique si la méthode doit être exportée initialement, l'argument methodTypePtr décrit l'implémentation de la méthode (voir la section TYPES DE MÉTHODES ci-dessous) et l'argument clientData donne des données spécifiques à l'implémentation qui sont passées à l'implémentation de la méthode lors de son appel.

Lorsque l'argument nameObj de Tcl_NewMethod est NULL, une méthode sans nom est créée, qui est utilisée pour les constructeurs et les destructeurs. Les constructeurs doivent être installés dans leur classe avec la fonction Tcl_ClassSetConstructor, et les destructeurs (qui ne nécessitent pas d'arguments) doivent être installés dans leur classe avec la fonction Tcl_ClassSetDestructor. Les méthodes sans nom ne doivent pas être utilisées à d'autres fins que les constructeurs ou les destructeurs, et les méthodes nommées ne doivent pas être utilisées comme constructeurs ou destructeurs. Il convient également de noter qu'un NULL methodTypePtr est utilisé pour fournir un signal interne et ne doit pas être utilisé dans le code client.

CONTEXTES D'APPEL DE MÉTHODES

Lorsqu'une méthode est appelée, un pointeur de contexte d'appel de méthode est passé comme l'un des arguments de la fonction d'implémentation. Ce contexte peut être inspecté pour fournir des informations sur l'appelant, mais ne doit pas être conservé au-delà de la fin de l'appel de méthode.

La méthode en cours d'appel peut être récupérée avec Tcl_ObjectContextMethod, et l'objet qui a provoqué l'invocation de la méthode peut être récupéré avec Tcl_ObjectContextObject. Le nombre d'arguments passés comme « non réels » (par exemple, le nom de l'objet et le nom de la méthode dans un appel normal) peut être lu avec Tcl_ObjectContextSkippedArgs, et le contexte peut également indiquer s'il fonctionne comme un filtre pour une autre méthode avec Tcl_ObjectContextIsFiltering.

Pendant l'exécution d'une méthode, l'implémentation de la méthode peut choisir d'invoquer les étapes de la chaîne d'appel de méthodes qui suivent cette implémentation actuelle. Cela (le cœur de la commande next) est exécuté avec Tcl_ObjectContextInvokeNext. La notification que le contexte d'appel de méthode doit être manipulé est que la pile d'appel n'est pas manipulée, contrairement à la commande next ; si l'implémentation de la méthode a introduit un ou plusieurs autres cadres supplémentaires dans la pile, elle doit également être responsable de les supprimer de la pile lors de l'exécution de Tcl_ObjectContextInvokeNext. Il convient également de noter que le contexte d'appel de méthode n'est jamais supprimé pendant l'exécution de cette fonction.

TYPES DE MÉTHODES

Les types de méthodes sont décrits par un pointeur vers une structure Tcl_MethodType, qui est définie comme suit :

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

Le champ version permet une expansion future de la structure et doit toujours être égal à TCL_OO_METHOD_VERSION_CURRENT. Le champ name fournit un nom lisible par l'homme pour le type, et est la valeur exposée par les commandes Tcl info class methodtype et info object methodtype.

Le champ callProc fournit une fonction qui est appelée lorsque la méthode est invoquée ; il ne doit jamais être NULL.

Le champ deleteProc fournit une fonction qui est utilisée pour supprimer une méthode spécifique, et est appelée lorsque la méthode est remplacée ou supprimée ; si le champ est NULL, on suppose que le clientData de la méthode ne nécessite aucune action spéciale pour sa suppression.

Le champ cloneProc est une fonction utilisée pour copier le clientData d'une méthode (dans le cadre de Tcl_CopyObjectInstance) ou NULL pour indiquer que le clientData peut être copié directement.

SIGNATURE DE FONCTION Tcl_MethodCallProc

La signature de la fonction Tcl_MethodCallProc est définie comme suit :

typedef Tcl_MethodCallProc Tcl_MethodCallProc(Tcl_Obj *obj, Tcl_Obj *const *objv, int argc, int skip);

La fonction Tcl_MethodCallProc est appelée lorsque la méthode est invoquée. Le paramètre obj représente l'objet qui est invoqué, le paramètre objv est un tableau d'arguments passés à l'implémentation de la méthode, et les paramètres argc et skip indiquent le nombre d'arguments passés et le nombre d'arguments qui ne représentent pas d'arguments réels, respectivement.

NOM

Tcl_MethodName

SYNOPSIS

Les fonctions qui correspondent à cette signature sont appelées lorsque la méthode est invoquée.

typedef int Tcl_MethodNameProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

L'argument clientData d'une Tcl_MethodNameProc est la valeur qui lui a été transmise lors de la création de la méthode, l'interp est un emplacement où les scripts sont exécutés et les variables sont consultées, et c'est également là que le résultat de l'invocation sera placé. Les champs objc et objv indiquent les objets d'entrée de la méthode. Le contexte d'appel de la méthode peut être découvert via l'argument objectContext, et la valeur de retour d'une Tcl_MethodNameProc est tout code de retour Tcl (par exemple, TCL_OK, TCL_ERROR).
