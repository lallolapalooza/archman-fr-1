Tcl_SplitPath(3) Procédures de la bibliothèque Tcl Tcl_SplitPath(3)

NOM

Tcl_SplitPath, Tcl_JoinPath, Tcl_GetPathType - manipuler des chemins de fichiers spécifiques à la plateforme

SYNOPSIS

#include <tcl.h>

Tcl_SplitPath(path, argcPtr, argvPtr)

char *
Tcl_JoinPath(argc, argv, resultPtr)

Tcl_PathType
Tcl_GetPathType(path)

ARGUMENTS

const char *path (entrée)
Chemin de fichier sous une forme appropriée pour la plateforme actuelle (voir l'entrée de manuel filename pour les formes acceptables pour les noms de chemin).
int *argcPtr (sortie)
Rempli avec le nombre d'éléments de chemin dans path.
const char ***argvPtr (sortie)
*argvPtr sera rempli avec l'adresse d'un tableau de pointeurs vers les chaînes qui sont les éléments extraits de path. Il y aura *argcPtr entrées valides dans le tableau, suivies d'une entrée NULL.
int argc (entrée)
Nombre d'éléments dans argv.
const char *const *argv (entrée)
Tableau d'éléments de chemin à fusionner en un seul chemin.
Tcl_DString *resultPtr (entrée/sortie)
Un pointeur vers un Tcl_DString initialisé auquel le résultat de Tcl_JoinPath sera ajouté.

DESCRIPTION

Ces procédures ont été remplacées par les procédures conscientes des valeurs Tcl dans la page de manuel FileSystem, qui sont plus efficaces.

Ces procédures peuvent être utilisées pour désassembler et réassembler les chemins de fichiers de manière indépendante de la plateforme : elles fournissent un accès au niveau C aux mêmes fonctionnalités que les commandes file split, file join et file pathtype.

Tcl_SplitPath divise un chemin en ses éléments constitutifs, renvoyant un tableau de pointeurs vers les éléments à l'aide de argcPtr et argvPtr. La zone mémoire pointée par *argvPtr est allouée dynamiquement ; en plus du tableau de pointeurs, elle contient également des copies de tous les éléments du chemin. Il est de la responsabilité de l'appelant de libérer tout ce stockage. Par exemple, supposons que vous ayez appelé Tcl_SplitPath avec le code suivant :

int argc;
char *path;
char **argv;
...
Tcl_SplitPath(string, &argc, &argv);

Alors vous devriez éventuellement libérer le stockage avec un appel similaire à celui-ci :

Tcl_Free((char *) argv);

Tcl_JoinPath est l'inverse de Tcl_SplitPath : elle prend une collection d'éléments de chemin donnée par argc et argv et génère une chaîne de résultat qui est un chemin correctement construit. La chaîne de résultat est ajoutée à resultPtr. ResultPtr doit faire référence à un Tcl_DString initialisé.

Si le résultat de Tcl_SplitPath est passé à Tcl_JoinPath, le résultat fera référence au même emplacement, mais peut ne pas être sous la même forme. En effet, Tcl_SplitPath et Tcl_JoinPath éliminent les séparateurs de chemin dupliqués et renvoient une forme normalisée pour chaque plateforme.

Tcl_GetPathType renvoie le type du path spécifié, où Tcl_PathType est l'un de TCL_PATH_ABSOLUTE, TCL_PATH_RELATIVE ou TCL_PATH_VOLUME_RELATIVE. Voir l'entrée de manuel filename pour une description des types de chemin pour chaque plateforme.
