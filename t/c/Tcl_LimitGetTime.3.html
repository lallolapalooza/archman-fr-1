ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur auquel s'applique la limite gérée ou dont les limites seront vérifiées.
int type (in)
Le type de limite auquel l'opération se réfère. Doit être soit TCL_LIMIT_COMMANDS, soit TCL_LIMIT_TIME.
int commandLimit (in)
Le nombre maximum de commandes (tel que rapporté par info cmdcount) qui peuvent être exécutées dans l'interpréteur.
Tcl_Time *timeLimitPtr (in/out)
Un pointeur vers une structure qui contiendra soit la nouvelle limite de temps lue (Tcl_LimitSetTime), soit la limite de temps actuelle écrite (Tcl_LimitGetTime).
int granularity (in)
Diviseur indiquant à quelle fréquence une limite particulière doit réellement être vérifiée. Doit être au moins 1.
Tcl_LimitHandlerProc *handlerProc (in)
Fonction à appeler lorsqu'une limite particulière est dépassée. Si le handlerProc supprime ou augmente la limite pendant son traitement, l'interpréteur limité sera autorisé à continuer son traitement après le retour du gestionnaire. Plusieurs gestionnaires peuvent être attachés à la même limite d'interpréteur ; leur ordre d'exécution n'est pas défini, et ils doivent être identifiés par handlerProc et clientData lors de leur suppression.
ClientData clientData (in)
Mot arbitraire de la taille d'un pointeur utilisé pour passer un contexte à la fonction handlerProc.
Tcl_LimitHandlerDeleteProc *deleteProc (in)
Fonction à appeler chaque fois qu'un gestionnaire est supprimé. Peut être NULL si clientData ne nécessite aucune suppression.

DESCRIPTION

Le sous-système de limite de ressources des interpréteurs Tcl permet un contrôle précis du temps de calcul qu'un script peut utiliser, et est utile pour les cas où un programme est divisé en plusieurs parties, dont certaines sont plus fiables que d'autres (par exemple, les serveurs d'applications web).

Chaque interpréteur peut avoir une limite sur le temps réel d'exécution, et une limite sur le nombre de commandes que l'interpréteur peut exécuter. Étant donné que la vérification de ces limites peut être coûteuse (en particulier la limite de temps), chaque limite a également une granularité de vérification, qui est un diviseur pour un décompte interne du nombre de points dans le cœur où une vérification peut être effectuée (ce qui se produit juste avant l'exécution d'une commande et à une fréquence non spécifiée entre l'exécution des commandes, qui peut se produire dans des boucles while à corps vide).

Le composant final du moteur de limites est un schéma de rappel qui permet d'être notifié lorsque qu'une limite a été dépassée. Ces rappels peuvent simplement fournir une journalisation, ou peuvent allouer plus de ressources à l'interpréteur pour lui permettre de continuer à traiter plus longtemps.

Lorsqu'une limite est dépassée (et que les rappels ont été exécutés ; l'ordre d'exécution des rappels n'est pas spécifié), l'exécution dans l'interpréteur limité est arrêtée en levant une erreur et en définissant un drapeau qui empêche la commande catch de cet interpréteur de piéger cette erreur. C'est au contexte qui a initié l'exécution dans cet interpréteur (généralement l'interpréteur principal) de gérer l'erreur.

API DE VÉRIFICATION DES LIMITES

Pour vérifier les limites de ressources d'un interpréteur, appelez Tcl_LimitCheck, qui renvoie TCL_OK si la limite n'a pas été dépassée (après traitement des rappels) et TCL_ERROR si la limite a été dépassée (auquel cas un message d'erreur est également placé dans le résultat de l'interpréteur). Cette fonction ne devrait être appelée que lorsque Tcl_LimitReady renvoie une valeur non nulle afin que la politique de granularité soit appliquée. Cette API est conçue pour être similaire en utilisation à Tcl_AsyncReady et Tcl_AsyncInvoke.

Lorsque vous écrivez du code qui peut se comporter comme catch par rapport aux erreurs, vous ne devez piéger une erreur que si Tcl_LimitExceeded renvoie zéro. Si elle renvoie une valeur non nulle, l'interpréteur est dans un état de limite dépassée et les erreurs doivent être autorisées à se propager au contexte appelant. Vous pouvez également vérifier si un type de limite particulier a été dépassé en utilisant Tcl_LimitTypeExceeded.

CONFIGURATION DES LIMITES

Pour vérifier si une limite est définie (mais pas si elle a réellement été dépassée) sur un interpréteur, appelez Tcl_LimitTypeEnabled avec le type de limite que vous souhaitez vérifier. Pour activer une limite particulière, appelez Tcl_LimitTypeSet, et pour désactiver une limite, appelez Tcl_LimitTypeReset.

Le niveau d'une limite de commande peut être défini à l'aide de Tcl_LimitSetCommands, et récupéré à l'aide de Tcl_LimitGetCommands. De même pour une limite de temps avec Tcl_LimitSetTime et Tcl_LimitGetTime respectivement, mais avec cette API, la limite de temps est copiée depuis et vers la structure Tcl_Time vers laquelle pointe l'argument timeLimitPtr.

La granularité de vérification d'une limite particulière peut être définie à l'aide de Tcl_LimitSetGranularity et récupérée à l'aide de Tcl_LimitGetGranularity. Notez que les granularités doivent toujours être positives.

RAPPELS DE LIMITES

Pour ajouter un rappel de gestionnaire à invoquer lorsqu'une limite est dépassée, appelez Tcl_LimitAddHandler. L'argument handlerProc décrit la fonction qui sera effectivement appelée ; elle doit avoir le prototype suivant :

typedef void Tcl_LimitHandlerProc(
        ClientData clientData,
        Tcl_Interp *interp);

L'argument clientData du gestionnaire sera ce qui est passé à l'argument clientData de Tcl_LimitAddHandler, et interp est l'interpréteur dont la limite a été dépassée.

L'argument deleteProc de Tcl_LimitAddHandler est une fonction à appeler pour supprimer la valeur clientData. Il peut s'agir de TCL_STATIC ou NULL si aucune action de suppression n'est nécessaire, ou de TCL_DYNAMIC si tout ce qui est nécessaire est de libérer la structure avec Tcl_Free. Sinon, il doit faire référence à une fonction ayant le prototype suivant :

typedef void Tcl_LimitHandlerDeleteProc(
        ClientData clientData);

Un gestionnaire de limites peut être supprimé à l'aide de Tcl_LimitRemoveHandler ; le gestionnaire supprimé sera le premier trouvé (parmi les gestionnaires ajoutés avec Tcl_LimitAddHandler) avec des arguments type, handlerProc et clientData exactement correspondants. Cette fonction invoque toujours le deleteProc sur le clientData (sauf si le deleteProc était NULL ou TCL_STATIC).

NOM

Tcl_LimitGetTime, Tcl_LimitSetTime, Tcl_Limit time — obtenir et définir des limites de temps d'exécution

SYNTAXE

#include <tcl.h>

int
Tcl_LimitGetTime(limitPtr, resultPtr)
Tcl_Limit *limitPtr;
int *resultPtr;

int
Tcl_LimitSetTime(limitPtr, value)
Tcl_Limit *limitPtr;
int value;

ARGUMENTS

$
Pointeur vers une structure Tcl_Limit contenant les informations de la limite de temps. Elle est retournée par Tcl_NewLimit.
$
Pointeur vers un entier où la valeur actuelle de la limite de temps sera stockée.
$
La nouvelle valeur entière de la limite de temps.

DESCRIPTION

La fonction Tcl_LimitGetTime renvoie la valeur entière actuelle de la limite de temps pointée par limitPtr dans la variable vers laquelle pointe resultPtr. La valeur est généralement un nombre de millisecondes. Si la limite n'est pas une limite de temps, la fonction renvoie TCL_ERROR et une erreur est déclenchée. Dans le cas contraire, elle renvoie TCL_OK.

La fonction Tcl_LimitSetTime définit la valeur entière de la limite de temps pointée par limitPtr à la valeur spécifiée par value. La valeur est généralement un nombre de millisecondes. Si la limite n'est pas une limite de temps, la fonction renvoie TCL_ERROR et une erreur est déclenchée. Dans le cas contraire, elle renvoie TCL_OK.

API DE VÉRIFICATION DES LIMITES

Les fonctions suivantes sont disponibles pour travailler avec les limites :

Tcl_NewLimit(typePtr)
Crée une nouvelle structure Tcl_Limit du type spécifié par typePtr et la renvoie. typePtr est un pointeur vers une structure Tcl_LimitType. Il existe plusieurs types de limites prédéfinis pour le temps, la mémoire, le nombre d'appels, etc.
Tcl_LimitCheck(limitPtr)
Vérifie si la limite spécifiée par limitPtr a été dépassée. Renvoie 1 si elle a été dépassée, 0 sinon.
Tcl_LimitReady(limitPtr)
Renvoie 1 si la limite spécifiée par limitPtr est prête à être vérifiée (par exemple, si la limite de temps actuelle est atteinte). Renvoie 0 sinon.
Tcl_LimitExpired(limitPtr)
Renvoie 1 si la limite spécifiée par limitPtr a expiré. Renvoie 0 sinon.
Tcl_LimitFree(limitPtr)
Libère la mémoire associée à la structure Tcl_Limit.

CONFIGURATION DES LIMITES

Les limites peuvent être configurées à l'aide des commandes Tcl suivantes :

limit
Commande principale pour gérer les limites.
limit options ?arg ...?
Configure et interroge les limites.
limit new <type> ?args?
Crée une nouvelle limite du type spécifié.
limit config <limit> ?options?
Configure une limite existante.
limit delete <limit>
Supprime une limite.
limit get <limit>
Renvoie la valeur actuelle d'une limite.
limit set <limit> <value>
Définit la valeur d'une limite.
limit check <limit>
Vérifie si une limite a été dépassée.
limit expired <limit>
Vérifie si une limite a expiré.

Les types de limites prédéfinis incluent :

  • time : limite de temps d'exécution en millisecondes.
  • memory : limite de mémoire en octets.
  • calls : limite du nombre d'appels.
