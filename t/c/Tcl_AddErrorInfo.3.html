Tcl_Obj *errorObjPtr (in)
La valeur de -errorcode sera définie sur cette valeur.
const char *element (in)
La chaîne à enregistrer comme élément de l'option de retour -errorcode. Le dernier argument doit être (char *)NULL.
va_list argList (in)
Une liste d'arguments qui doit avoir été initialisée avec va_start et nettoyée avec va_end.

int commandLength (in)
Le nombre d'octets dans la commande ; -1 signifie utiliser tous les octets jusqu'au premier octet nul

DESCRIPTION

Les routines Tcl_SetReturnOptions et Tcl_GetReturnOptions exposent les mêmes capacités que les commandes return et catch sous la forme d'une interface C.

Tcl_GetReturnOptions récupère le dictionnaire d'options de retour d'un interpréteur après l'évaluation d'un script. Les routines telles que Tcl_Eval sont appelées pour évaluer un script dans un interpréteur. Ces routines renvoient un code d'achèvement entier. Ces routines maintiennent également dans l'interpréteur à la fois un résultat et un dictionnaire d'options de retour générés par l'évaluation du script. Tout comme Tcl_GetObjResult récupère le résultat, Tcl_GetReturnOptions récupère le dictionnaire d'options de retour. Le code d'achèvement entier doit être passé comme argument code à Tcl_GetReturnOptions afin que toutes les exigences soient présentes dans le dictionnaire. Plus précisément, une valeur de code de TCL_ERROR garantira que les éléments pour les clés -errorinfo, -errorcode et -errorline sont inclus dans le dictionnaire. Les éléments pour les clés -code et -level seront également ajustés si nécessaire pour correspondre à la valeur de code. Le (Tcl_Obj *) renvoyé par Tcl_GetReturnOptions pointe vers un objet Tcl_Obj non partagé avec un compteur de références de zéro. Le dictionnaire peut être modifié, en ajoutant, en supprimant ou en remplaçant n'importe quelle entrée, sans qu'il soit nécessaire de vérifier une valeur partagée. Comme pour tout Tcl_Obj avec un compteur de références de zéro, il incombe à l'utilisateur d'organiser sa disposition avec Tcl_DecrRefCount ou de le référencer avec Tcl_IncrRefCount (ou l'une des nombreuses fonctions qui l'appellent, telles que Tcl_SetObjResult et Tcl_SetVar2Ex).

Une utilisation typique de Tcl_GetReturnOptions consiste à récupérer la pile d'appels lorsque le script renvoie TCL_ERROR, comme illustré ci-dessous :

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* Faire quelque chose avec stackTrace */
    Tcl_DecrRefCount(options);
}

Tcl_SetReturnOptions définit les options de retour de interp à options. Si options contient une valeur invalide pour une clé quelconque, TCL_ERROR est renvoyé et le résultat de l'interpréteur est défini sur un message d'erreur approprié. Sinon, un code d'achèvement correspondant aux valeurs des clés -code et -level dans options est renvoyé.

Par exemple, la commande Tcl return peut être implémentée en utilisant Tcl_SetReturnOptions comme suit :

if ((objc % 2) == 0) { /* argument de résultat explicite */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(Ceci n'est pas réellement implémenté ainsi. Les privilèges internes permettent une alternative plus efficace qui s'aligne mieux avec le compilateur bytecode.)

Remarque : Un objet Tcl_Obj nouvellement créé peut être passé comme argument options sans qu'il soit nécessaire de gérer le compteur de références. Ceci est analogue à Tcl_SetObjResult.

Bien que Tcl_SetReturnOptions fournisse une interface générale pour définir n'importe quelle collection d'options de retour, il existe un nombre limité d'options de retour très fréquemment utilisées. Les plus notables sont les options -errorinfo et -errorcode qui doivent être correctement définies lorsque la procédure de commande renvoie TCL_ERROR. L'option -errorline est également lue par les commandes qui évaluent des scripts et souhaitent fournir des informations d'emplacement d'erreur dans la trace textuelle.

Tcl fournit plusieurs interfaces plus simples pour définir directement ces options de retour.

L'option -errorinfo contient une pile d'appels des opérations qui étaient en cours lorsque s'est produite une erreur, et est intentionnellement lisible par l'homme. L'option -errorcode contient une liste d'éléments Tcl qui sont intentionnellement lisibles par machine. Le premier élément de la valeur -errorcode identifie le type d'erreur qui s'est produite (par exemple, POSIX signifie qu'une erreur s'est produite lors d'un appel POSIX). Les éléments supplémentaires contiennent des informations supplémentaires qui dépendent du type d'erreur. Pour plus de détails sur les différents formats utilisés dans l'option -errorcode par les commandes internes Tcl, voir l'entrée de manuel sur la variable errorCode.

L'option -errorinfo est construite progressivement à mesure que l'erreur se dénoue à travers les opérations imbriquées. Chaque fois qu'un code d'erreur est renvoyé à Tcl_Eval ou à toute routine effectuant l'évaluation d'un script, la procédure Tcl_AddErrorInfo est appelée pour ajouter du texte supplémentaire à l'option -errorinfo décrivant la commande qui était en cours d'exécution lorsque l'erreur s'est produite. Une fois que l'erreur a été entièrement transmise à l'application, elle contiendra une trace complète de l'activité en cours lorsque l'erreur s'est produite.

Il est parfois utile d'ajouter des informations supplémentaires à l'option -errorinfo au-delà de ce qui peut être fourni automatiquement par les routines d'évaluation de script. Tcl_AddErrorInfo peut être utilisé à cette fin : son argument message est une chaîne supplémentaire à ajouter à l'option -errorinfo. Par exemple, lorsqu'une erreur se produit lors de la commande source, la procédure Tcl_AddErrorInfo est appelée pour enregistrer le nom du fichier en cours de traitement et la ligne où l'erreur s'est produite. De même, lorsqu'une erreur se produit lors de l'évaluation d'un script, Tcl_AddErrorInfo est utilisé pour enregistrer des informations supplémentaires.
