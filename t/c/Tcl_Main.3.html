Tcl_Main(3) Procédures de la bibliothèque Tcl Tcl_Main(3)

NOM

Tcl_Main, Tcl_MainEx, Tcl_MainExW, Tcl_SetStartupScript, Tcl_GetStartupScript, Tcl_SetMainLoop - programme principal, script de démarrage et définition de la boucle d'événements pour les applications basées sur Tcl

SYNOPIS

#include <tcl.h>

Tcl_Main(argc, argv, appInitProc)

Tcl_MainEx(argc, charargv, appInitProc, interp)

Tcl_MainExW(argc, wideargv, appInitProc, interp)

Tcl_SetStartupScript(path, encoding)

Tcl_Obj *
Tcl_GetStartupScript(encodingPtr)

Tcl_SetMainLoop(mainLoopProc)

ARGUMENTS

int argc (entrée)
Nombre d'éléments dans argv.
char *argv[] (entrée)
Tableau de chaînes contenant les arguments de la ligne de commande. Sous Windows, lorsque -DUNICODE est utilisé, le type du paramètre change en wchar_t *.
char *charargv[] (entrée)
Comme argv, mais ne change pas de type en wchar_t.
char *wideargv[] (entrée)
Comme argv, mais le type est toujours wchar_t.
Tcl_AppInitProc *appInitProc (entrée)
Adresse d'une procédure d'initialisation spécifique à l'application. La valeur pour cet argument est généralement Tcl_AppInit.
Tcl_Obj *path (entrée)
Nom du fichier à utiliser comme script de démarrage, ou NULL.
const char *encoding (entrée)
Encodage du fichier à utiliser comme script de démarrage, ou NULL.
const char **encodingPtr (sortie)
Si non NULL, emplacement pour écrire une copie de (const char *) pointant vers le nom de l'encodage.
Tcl_MainLoopProc *mainLoopProc (entrée)
Adresse d'une procédure de boucle d'événements spécifique à l'application.
Tcl_Interp *interp (entrée)
Interpréteur Tcl déjà créé.

DESCRIPTION

Tcl_Main peut servir de programme principal pour les applications de type shell basées sur Tcl. Une « application de shell » est un programme comme tclsh ou wish qui prend en charge à la fois l'interprétation interactive de Tcl et l'évaluation d'un script contenu dans un fichier donné comme argument de ligne de commande. Tcl_Main est proposé comme une commodité aux développeurs d'applications de shell, afin qu'ils n'aient pas à reproduire tout le code nécessaire à l'initialisation correcte de la bibliothèque Tcl et au fonctionnement du shell interactif. D'autres styles d'intégration de Tcl dans une application ne sont pas pris en charge par Tcl_Main. Ceux-ci doivent être réalisés en appelant directement des fonctions de niveau inférieur de la bibliothèque Tcl.

La fonction Tcl_Main est proposée par la bibliothèque Tcl depuis la version Tcl 7.4. Dans les versions antérieures de Tcl, la bibliothèque Tcl elle-même définissait une fonction main, mais celle-ci manquait de flexibilité quant au style d'intégration et le fait d'avoir une fonction main dans une bibliothèque (en particulier une bibliothèque partagée) pose des problèmes sur de nombreux systèmes. Avoir main dans la bibliothèque Tcl rendrait également difficile l'utilisation de Tcl dans des programmes C++, car les programmes C++ doivent avoir des fonctions main spéciales en C++.

Normalement, chaque application de shell contient une petite fonction main qui ne fait rien d'autre qu'appeler Tcl_Main. Tcl_Main effectue ensuite tout le travail de création et d'exécution d'une application de type tclsh.

Tcl_Main n'est pas fournie par l'interface publique de la bibliothèque stub de Tcl. Les programmes qui appellent Tcl_Main doivent être liés à la bibliothèque Tcl standard. Les extensions (avec ou sans stub) ne sont pas censées appeler Tcl_Main.

Tcl_Main n'est pas thread-safe. Elle ne doit être appelée que par le thread principal d'une application multithreadée. Cette restriction n'est pas un problème dans l'utilisation normale décrite ci-dessus.

Tcl_Main et donc toutes les applications basées sur elle, comme tclsh, utilisent Tcl_GetStdChannel pour initialiser les canaux standard à leurs valeurs par défaut. Voir Tcl_StandardChannels pour plus d'informations.

Tcl_Main prend en charge deux modes de fonctionnement, en fonction de la présence ou non du nom de fichier et de l'encodage d'un script de démarrage. Les routines Tcl_SetStartupScript et Tcl_GetStartupScript sont les outils pour contrôler cette configuration de Tcl_Main.

Tcl_SetStartupScript enregistre la valeur path comme nom du fichier que Tcl_Main doit évaluer comme script de démarrage. La valeur encoding est le nom Tcl de l'encodage utilisé pour stocker le texte dans ce fichier. Une valeur NULL pour encoding signale d'utiliser l'encodage système. Une valeur NULL pour path efface tout enregistrement existant afin que Tcl_Main n'évalue aucun script de démarrage.

Tcl_GetStartupScript interroge le nom de fichier et l'encodage enregistrés, définis par le dernier appel à Tcl_SetStartupScript dans le même thread. Le nom de fichier stocké est renvoyé, et le nom de l'encodage stocké est écrit à l'emplacement pointé par encodingPtr, lorsque celui-ci n'est pas NULL.

Les valeurs de nom de fichier et d'encodage gérées par les routines Tcl_SetStartupScript et Tcl_GetStartupScript sont stockées par thread. Bien que les fonctions de stockage et de récupération de ces routines fonctionnent dans n'importe quel thread, seuls les appels effectués dans le même thread principal que Tcl_Main peuvent avoir une influence sur celui-ci.

L'appelant de Tcl_Main peut d'abord appeler Tcl_SetStartupScript pour définir son script de démarrage souhaité. Si Tcl_Main constate qu'aucun script de démarrage n'a été défini, elle consulte les premiers arguments de argv. S'ils correspondent à ?-encoding name? fileName, où fileName ne commence pas par le caractère -, alors fileName est considéré comme le nom d'un fichier contenant un script de démarrage, et name est considéré comme le nom de l'encodage du contenu de ce fichier. Tcl_Main appelle alors Tcl_SetStartupScript avec ces valeurs.

Tcl_Main définit ensuite dans son interpréteur principal les variables Tcl argc, argv, argv0 et tcl_interactive, comme décrit dans la documentation de tclsh.

Une fois son initialisation terminée, mais avant de traiter les commandes, Tcl_Main appelle la procédure fournie par l'argument appInitProc. Cette procédure fournit un « hook » pour que l'application effectue sa propre initialisation de l'interpréteur créé par Tcl_Main, comme la définition de commandes spécifiques à l'application. La routine d'initialisation de l'application peut également appeler Tcl_SetStartupScript pour (ré)définir le fichier et l'encodage à utiliser comme script de démarrage. La procédure doit avoir une interface qui correspond au type Tcl_AppInitProc :

typedef int Tcl_AppInitProc(
        Tcl_Interp *interp);

AppInitProc est presque toujours un pointeur vers Tcl_AppInit ; pour plus de détails sur cette procédure, voir la documentation de Tcl_AppInit.

Lorsque appInitProc est terminé, Tcl_Main appelle Tcl_GetStartupScript pour déterminer quel script de démarrage a été demandé, le cas échéant. Si un script de démarrage a été fourni, Tcl_Main tente de l'évaluer. Sinon, le mode interactif commence par l'examen de la variable tcl_rcFileName dans l'interpréteur principal. Si cette variable existe et contient le nom d'un fichier lisible, le contenu de ce fichier est évalué dans l'interpréteur principal. Ensuite, les opérations interactives commencent, avec des invites et les résultats de l'évaluation des commandes écrits sur le canal de sortie standard, et les commandes lues à partir du canal d'entrée standard puis évaluées. Les invites écrites sur le canal de sortie standard peuvent être personnalisées en définissant les variables Tcl tcl_prompt1 et tcl_prompt2 comme décrit dans la documentation de tclsh. Les invites et les résultats de l'évaluation des commandes sont écrits sur le canal de sortie standard uniquement si la variable Tcl tcl_interactive dans l'interpréteur principal contient une valeur entière non nulle.

Tcl_SetMainLoop permet de définir une procédure de boucle d'événements à exécuter. Cela permet, par exemple, de charger dynamiquement Tk et de définir sa boucle d'événements. La boucle d'événements s'exécutera après le script de démarrage. Si vous êtes en mode interactif, la définition de la procédure de boucle principale fera en sorte que l'invite soit basée sur les événements de fichier, puis la procédure de boucle sera appelée. Lorsque la procédure de boucle retourne en mode interactif, l'opération interactive se poursuivra. La procédure de boucle principale doit avoir une interface qui correspond au type Tcl_MainLoopProc :

typedef void Tcl_MainLoopProc(void);

Tcl_Main ne retourne pas. Normalement, un programme basé sur Tcl_Main se terminera lorsque la commande exit sera évaluée. En mode interactif, si une fin de fichier (EOF) ou une erreur de canal est rencontrée sur le canal d'entrée standard, alors Tcl_Main elle-même évaluera la commande exit.
