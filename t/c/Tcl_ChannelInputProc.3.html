DESCRIPTION

Tcl utilise une architecture de canaux à deux niveaux. Il offre une couche supérieure générique pour permettre aux programmes C et Tcl d'effectuer des entrées et sorties en utilisant les mêmes API pour une variété de fichiers, périphériques, sockets, etc. Les API C génériques sont décrites dans la page de manuel Tcl_OpenFileChannel.

La couche inférieure fournit des pilotes de canal spécifiques pour chaque type de périphérique pris en charge sur chaque plateforme. Ce document décrit les API C qui communiquent entre la couche générique et les pilotes de canal spécifiques. Il explique également comment de nouveaux types de canaux peuvent être ajoutés en implémentant de nouveaux pilotes de canal.

Les pilotes de canal se composent de plusieurs éléments : Premièrement, chaque pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers les procédures qui implémentent les opérations utilisées par la couche générique pour communiquer avec le pilote de canal. La structure Tcl_ChannelType et les procédures auxquelles elle fait référence sont décrites dans la section TCL_CHANNELTYPE, ci-dessous.

Deuxièmement, les pilotes de canal fournissent généralement une commande Tcl pour créer des instances de ce type de canal. Par exemple, la commande Tcl open crée des canaux qui utilisent les pilotes de canal de fichier et de commande, et la commande Tcl socket crée des canaux qui utilisent les protocoles réseau TCP.

Troisièmement, un pilote de canal fournit éventuellement une fonction C pour ouvrir des instances de ce type de canal. Par exemple, Tcl_OpenFileChannel ouvre un canal qui utilise le pilote de canal de fichier, et Tcl_OpenTcpClient ouvre un canal qui utilise le protocole réseau TCP. Ces fonctions de création utilisent généralement Tcl_CreateChannel en interne pour ouvrir le canal.

Pour ajouter un nouveau type de canal, vous devez implémenter une API C ou une commande Tcl qui ouvre un canal en appelant Tcl_CreateChannel. Lorsque votre pilote appelle Tcl_CreateChannel, il transmet une structure Tcl_ChannelType qui décrit les procédures d'entrée et de sortie de votre pilote. La couche générique appellera alors les procédures référencées dans cette structure pour effectuer des opérations sur le canal.

Tcl_CreateChannel ouvre un nouveau canal et lui associe typePtr et instanceData. Le canal est ouvert dans le mode indiqué par mask. Pour une discussion sur les pilotes de canal, leurs opérations et la structure Tcl_ChannelType, voir la section TCL_CHANNELTYPE.

Tcl_CreateChannel interagit avec le code qui gère les canaux standard. Une fois qu'un canal standard a été initialisé par un appel à Tcl_GetStdChannel ou Tcl_SetStdChannel, sa fermeture entraînera la conversion du prochain appel à Tcl_CreateChannel en nouveau canal standard. Voir Tcl_StandardChannels pour une vue d'ensemble des canaux standard et du comportement de la bibliothèque Tcl à leur égard.

Tcl_GetChannelInstanceData renvoie les données d'instance associées au canal dans channel. Il s'agit de la même valeur que l'argument instanceData dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelType renvoie un pointeur vers la structure Tcl_ChannelType utilisée par le canal dans l'argument channel. Il s'agit de la même valeur que l'argument typePtr dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelName renvoie une chaîne contenant le nom associé au canal, ou NULL si l'argument channelName de Tcl_CreateChannel était NULL.

Tcl_GetChannelHandle place le handle du système d'exploitation associé à channel pour la direction donnée dans handlePtr.

Tcl_GetChannelType renvoie un pointeur vers la structure Tcl_ChannelType utilisée par le canal dans l'argument channel. Il s'agit de la même valeur que l'argument typePtr dans l'appel

l'emplacement spécifié par handlePtr et retourne TCL_OK. Si le canal n'a pas de descripteur de périphérique pour la direction spécifiée, alors TCL_ERROR est retourné à la place. Différents pilotes de canal retourneront différents types de descripteurs. Référez-vous aux entrées manuelles pour chaque pilote afin de déterminer quel type de descripteur est retourné.

Tcl_GetChannelThread retourne l'identifiant du thread qui gère actuellement le canal spécifié. Cela permet aux pilotes de canal d'envoyer leurs événements de fichier à la bonne file d'attente d'événements, même pour un noyau multithread.

Tcl_GetChannelMode retourne une combinaison OR de TCL_READABLE et TCL_WRITABLE, indiquant si le canal est ouvert pour l'entrée et la sortie.

Tcl_GetChannelBufferSize retourne la taille, en octets, des mémoires tampons allouées pour stocker l'entrée ou la sortie dans le canal. Si la valeur n'a pas été définie par un appel précédent à Tcl_SetChannelBufferSize, décrit ci-dessous, alors la valeur par défaut de 4096 est retournée.

Tcl_SetChannelBufferSize définit la taille, en octets, des mémoires tampons qui seront allouées lors des opérations ultérieures sur le canal pour stocker l'entrée ou la sortie. L'argument size doit être compris entre un et un million, permettant des tampons de un octet à un million d'octets. Si size est en dehors de cette plage, Tcl_SetChannelBufferSize définit la taille du tampon à 4096.

Tcl_NotifyChannel est appelé par un pilote de canal pour indiquer à la couche générique que les événements spécifiés par mask se sont produits sur le canal. Les pilotes de canal sont responsables de l'invocation de cette fonction chaque fois que les gestionnaires de canal doivent être appelés pour le canal (ou que d'autres tâches en attente, comme une purge d'écriture, doivent être effectuées). Voir WATCHPROC ci-dessous pour plus de détails.

Tcl_BadChannelOption est appelé à partir du setOptionProc ou getOptionProc spécifique au pilote pour générer un message d'erreur complet.

Tcl_ChannelBuffered retourne le nombre d'octets d'entrée actuellement mis en mémoire tampon dans la mémoire tampon interne (zone de retour arrière) du canal lui-même. Il ne rend pas compte des données dans les tampons globaux de la pile de canaux dont fait partie le canal fourni.

Tcl_IsChannelShared vérifie le compteur de références du canal spécifié et retourne si le canal a été partagé entre plusieurs interpréteurs (résultat == 1) ou non (résultat == 0).

Tcl_IsChannelRegistered vérifie si le canal spécifié est enregistré dans le interpréteur donné (résultat == 1) ou non (résultat == 0).

Tcl_IsChannelExisting vérifie si un canal avec le nom spécifié est enregistré dans la liste globale (thread) de tous les canaux (résultat == 1) ou non (résultat == 0).

Tcl_CutChannel retire le canal spécifié de la liste globale (thread) de tous les canaux (du thread actuel). L'application à un canal toujours enregistré dans un interpréteur n'est pas autorisée. Notifie également le pilote si la version Tcl_ChannelType est TCL_CHANNEL_VERSION_4 (ou supérieure), et si Tcl_DriverThreadActionProc est défini pour celui-ci.

Tcl_SpliceChannel ajoute le canal spécifié à la liste globale (thread) de tous les canaux (du thread actuel). L'application à un canal enregistré dans un interpréteur n'est pas autorisée. Notifie également le pilote si la version Tcl_ChannelType est TCL_CHANNEL_VERSION_4 (ou supérieure), et si Tcl_DriverThreadActionProc est défini pour celui-ci.

Tcl_ClearChannelHandlers supprime tous les gestionnaires de canal et scripts d'événements associés au canal spécifié, arrêtant ainsi tout traitement d'événements pour ce canal.

TCL_CHANNELTYPE

Un pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers les fonctions qui implémentent les différentes opérations sur un canal ; ces opérations sont appelées au besoin par la couche générique. La structure a été versionnée à partir de Tcl 8.3.2/8.4 pour corriger un problème avec les pilotes de canal empilés. Voir la section OLD CHANNEL TYPES ci-dessous pour plus de détails sur l'ancienne structure.

La structure Tcl_ChannelType contient les champs suivants :

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Il n'est pas nécessaire de fournir des implémentations pour toutes les opérations de canal. Celles qui ne sont pas nécessaires peuvent être définies à NULL dans la structure : blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc, et close2Proc, en plus de flushProc, handlerProc, threadActionProc, et truncateProc. D'autres fonctions qui ne peuvent pas être implémentées de manière significative devraient retourner EINVAL lorsqu'elles sont appelées, pour indiquer que les opérations qu'elles représentent ne sont pas disponibles. Notez également que wideSeekProc peut être NULL si seekProc l'est.

L'utilisateur ne doit utiliser que la structure ci-dessus pour l'instanciation Tcl_ChannelType. Lors de la référence aux champs d'une structure Tcl_ChannelType, les fonctions suivantes doivent être utilisées pour obtenir les valeurs : Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc, ou Tcl_ChannelHandlerProc.

La modification des structures a été apportée de telle manière que les types de canaux standard sont binaires compatibles. Cependant, les types de canaux qui utilisent des canaux empilés (c'est-à-dire TLS, Trf) ont de nouvelles versions pour correspondre au changement ci-dessus, car le code précédent pour les canaux empilés présentait des problèmes.

TYPENAME

Le champ typeName contient une chaîne terminée par null qui identifie le type du périphérique implémenté par ce pilote, par exemple file ou socket.

Cette valeur peut être récupérée avec Tcl_ChannelName, qui retourne un pointeur vers la chaîne.

VERSION

Le champ version doit être défini sur la version de la structure dont vous avez besoin. TCL_CHANNEL_VERSION_2 est le minimum recommandé. TCL_CHANNEL_VERSION_3 doit être défini pour spécifier le membre wideSeekProc. TCL_CHANNEL_VERSION_4 doit être défini pour spécifier le membre threadActionProc (inclut wideSeekProc). TCL_CHANNEL_VERSION_5 doit être défini pour spécifier le membre truncateProc (inclut wideSeekProc et threadActionProc). S'il n'est défini sur aucune de ces valeurs, alors ce Tcl_ChannelType est supposé avoir la structure d'origine. Voir OLD CHANNEL TYPES pour plus de détails. Bien que Tcl reconnaisse et fonctionne avec les deux structures, les canaux empilés doivent être au moins de TCL_CHANNEL_VERSION_2 pour fonctionner correctement.

Cette valeur peut être récupérée avec Tcl_ChannelVersion, qui retourne l'une des valeurs TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 ou TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

Le champ blockModeProc contient l'adresse d'une fonction appelée par la couche générique pour définir le mode bloquant et non bloquant sur le périphérique. BlockModeProc doit correspondre au prototype suivant :

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

Le instanceData est le même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. L'argument mode est soit TCL_MODE_BLOCKING soit TCL_MODE_NONBLOCKING pour définir le périphérique en mode bloquant ou non bloquant. La fonction doit retourner zéro si l'opération a réussi, ou un code d'erreur POSIX non nul si l'opération a échoué.

Si l'opération réussit, la fonction peut modifier le instanceData fourni pour enregistrer que le canal est entré en mode bloquant ou non bloquant et pour implémenter le comportement bloquant ou non bloquant. Pour certains types de périphériques, le comportement bloquant et non bloquant peut être implémenté par le système d'exploitation sous-jacent ; pour d'autres types de périphériques, le comportement doit être émule dans le pilote de canal.

Cette valeur peut être récupérée avec Tcl_ChannelBlockModeProc, qui retourne un pointeur vers la fonction.

Un pilote de canal qui ne fournit pas de blockModeProc doit être très, très prudent. Il doit indiquer à la couche générique quel mode de blocage lui convient, et cela doit également être documenté pour l'utilisateur afin que le mode de blocage du canal ne soit pas modifié à une valeur inacceptable. Toute confusion ici peut entraîner l'interpréteur dans un interblocage (sporadique et difficile à trouver).

La fonction doit libérer toute mémoire maintenue par le pilote de canal pour ce canal, et fermer les périphériques d'entrée et de sortie encapsulés par ce canal. CLOSEPROC

Le champ closeProc contient l'adresse d'une fonction appelée par la couche générique lorsque le canal est fermé. closeProc doit correspondre au prototype suivant :

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

InstanceData est le même que la valeur transmise à Tcl_CreateChannel lors de la création du canal. La fonction doit effectuer toutes les opérations de nettoyage nécessaires pour libérer les ressources associées au canal. Si une erreur se produit, la fonction doit renvoyer un code d'erreur POSIX non nul ; sinon, elle doit renvoyer zéro. En outre, si une erreur se produit et que interp n'est pas NULL, la procédure doit stocker un message d'erreur dans le résultat de l'interpréteur.

Alternativement, les canaux qui prennent en charge la fermeture indépendante des côtés lecture et écriture peuvent définir closeProc sur TCL_CLOSE2PROC et close2Proc sur l'adresse d'une fonction correspondant au prototype suivant :

typedef int Tcl_DriverClose2Proc(
        ClientData instanceData,
        Tcl_Interp *interp,
        int flags);

close2Proc sera appelée avec flags défini sur une combinaison OR de TCL_CLOSE_READ ou TCL_CLOSE_WRITE pour indiquer que le pilote doit fermer le côté lecture et/ou écriture du canal. Le pilote de canal peut être appelé pour effectuer des opérations supplémentaires sur le canal après l'appel de close2Proc pour fermer un ou les deux côtés du canal. Si flags est 0 (zéro), le pilote doit fermer le canal de la manière décrite ci-dessus pour closeProc. Aucune opération supplémentaire ne sera effectuée sur cette instance après l'appel de close2Proc avec tous les indicateurs effacés. Dans tous les cas, la fonction close2Proc doit renvoyer zéro si l'opération de fermeture a réussi ; sinon, elle doit renvoyer un code d'erreur POSIX non nul. En outre, si une erreur se produit et que interp n'est pas NULL, la procédure doit stocker un message d'erreur dans le résultat de l'interpréteur.

Les valeurs closeProc et close2Proc peuvent être récupérées avec Tcl_ChannelCloseProc ou Tcl_ChannelClose2Proc, qui renvoient un pointeur vers la fonction respective.

INPUTPROC

Le champ inputProc contient l'adresse d'une fonction appelée par la couche générique pour lire des données du fichier ou de l'appareil et les stocker dans un tampon interne. InputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

InstanceData est le même que la valeur transmise à Tcl_CreateChannel lors de la création du canal. L'argument buf pointe vers un tableau d'octets dans lequel stocker les données entrantes de l'appareil, et l'argument bufSize indique combien d'octets sont disponibles à buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique. Si une erreur se produit, la fonction doit définir la variable sur un code d'erreur POSIX qui identifie l'erreur survenue.

La fonction doit lire les données de l'appareil d'entrée encapsulé par le canal et les stocker dans buf. En cas de succès, la fonction doit renvoyer un entier non négatif indiquant combien d'octets ont été lus de l'appareil d'entrée et stockés dans buf. En cas d'erreur, la fonction doit renvoyer -1. Si une erreur se produit après que certaines données ont été lues de l'appareil, ces données sont perdues.

Si inputProc peut déterminer que l'appareil d'entrée a des données disponibles mais moins que ce qui est demandé par l'argument bufSize, la fonction ne doit tenter de lire que la quantité de données disponibles et renvoyer sans bloquer. Si l'appareil d'entrée n'a aucune donnée disponible et que le canal est en mode non bloquant, la fonction doit renvoyer une erreur EAGAIN. Si l'appareil d'entrée n'a aucune donnée disponible et que le canal est en mode bloquant, la fonction doit bloquer pendant la durée la plus courte possible jusqu'à ce qu'au moins un octet de données puisse être lu de l'appareil ; ensuite, elle doit renvoyer autant de données qu'elle peut en lire sans bloquer.

Cette valeur peut être récupérée avec Tcl_ChannelInputProc, qui renvoie un pointeur vers la fonction.

OUTPUTPROC

Le champ outputProc contient l'adresse d'une fonction appelée par la couche générique pour transférer des données d'un tampon interne vers l'appareil de sortie. OutputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

InstanceData est le même que la valeur transmise à Tcl_CreateChannel lors de la création du canal. L'argument buf contient un tableau d'octets à écrire sur l'appareil, et l'argument toWrite indique combien d'octets doivent être écrits à partir de l'argument buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique. Si une erreur se produit, la fonction doit définir cette variable sur un code d'erreur POSIX qui identifie l'erreur.

La fonction doit écrire les données situées dans buf sur l'appareil de sortie encapsulé par le canal. En cas de succès, la fonction doit renvoyer un entier non négatif indiquant combien d'octets ont été écrits sur l'appareil de sortie. La valeur de retour est normalement la même que toWrite, mais peut être inférieure dans certains cas, par exemple si l'opération de sortie est interrompue par un signal. Si une erreur se produit, la fonction doit renvoyer -1. En cas d'erreur, certaines données peuvent avoir été écrites sur l'appareil.

Si le canal est non bloquant et que l'appareil de sortie ne peut absorber aucune donnée, la fonction doit renvoyer -1 avec une erreur EAGAIN sans écrire aucune donnée.

Cette valeur peut être récupérée avec Tcl_ChannelOutputProc, qui renvoie un pointeur vers la fonction.

SEEKPROC ET WIDESEEKPROC

Le champ seekProc contient l'adresse d'une fonction appelée par la couche générique pour déplacer le point d'accès auquel les opérations d'entrée ou de sortie ultérieures seront appliquées. SeekProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

L'argument instanceData est le même que la valeur transmise à Tcl_CreateChannel lors de la création de ce canal. Offset et seekMode ont la même signification que pour la procédure Tcl_Seek (décrite dans l'entrée de manuel de Tcl_OpenFileChannel).

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique pour renvoyer les valeurs errno de la fonction. La fonction doit définir cette variable sur un code d'erreur POSIX si une erreur se produit. La fonction doit stocker un code d'erreur EINVAL si le type de canal n'implémente pas le déplacement.

La valeur de retour est le nouveau point d'accès ou -1 en cas d'erreur. Si une erreur s'est produite, la fonction ne doit pas déplacer le point d'accès.

S'il existe un champ seekProc non NULL, le champ wideSeekProc peut contenir l'adresse d'une fonction alternative à utiliser, qui gère les décalages larges (c'est-à-dire supérieurs à 32 bits), permettant ainsi les déplacements dans des fichiers de plus de 2 Go. WideSeekProc sera appelé de préférence à seekProc, mais les deux doivent être définis si wideSeekProc est défini. WideSeekProc doit correspondre au prototype suivant :

typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

Les arguments et les valeurs de retour signifient la même chose qu'avec seekProc ci-dessus, sauf que le type des décalages et le type de retour sont différents.

La valeur seekProc peut être récupérée avec Tcl_ChannelSeekProc, qui renvoie un pointeur vers la fonction, et de manière similaire wideSeekProc peut être récupéré avec Tcl_ChannelWideSeekProc.

SETOPTIONPROC

Le champ setOptionProc contient l'adresse d'une fonction appelée par la couche générique pour définir une option spécifique au type de canal sur un canal. setOptionProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

optionName est le nom d'une option à définir, et newValue est la nouvelle valeur de cette option, sous forme de chaîne. instanceData est le même que la valeur transmise à Tcl_CreateChannel lors de la création de ce canal. La fonction doit effectuer toute action spécifique au type de canal requise pour implémenter la nouvelle valeur de l'option.

Certaines options sont gérées par le code générique et cette fonction n'est jamais appelée pour les définir, par exemple -blockmode. D'autres options sont spécifiques à chaque type de canal et la procédure setOptionProc du pilote de canal sera appelée pour les implémenter. Le champ setOptionProc peut être NULL, ce qui indique que ce type de canal ne prend en charge aucune option spécifique au type.

Si la valeur de l'option est modifiée avec succès pour la nouvelle valeur, la fonction renvoie TCL_OK. Elle doit appeler Tcl_BadChannelOption qui renvoie elle-même TCL_ERROR si optionName n'est pas reconnu. Si newValue spécifie une valeur pour l'option qui n'est pas prise en charge ou si une erreur d'appel système se produit, la fonction doit laisser un message d'erreur dans le résultat de interp si interp n'est pas NULL. La fonction doit également appeler Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

Cette valeur peut être récupérée avec Tcl_ChannelSetOptionProc, qui renvoie un pointeur vers la fonction.

WATCHPROC

Le champ watchProc contient l'adresse d'une fonction appelée par le niveau général pour initialiser le mécanisme de notification des événements d'intérêt sur ce canal. WatchProc doit correspondre au prototype suivant :

typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lorsque ce canal a été créé. L'argument mask est une combinaison OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION ; il indique les événements pour lesquels l'appelant souhaite être notifié sur ce canal.

La fonction doit initialiser les mécanismes spécifiques au type de périphérique pour notifier lorsqu'un événement d'intérêt est présent sur le canal. Lorsqu'un événement d'intérêt se produit sur le canal, le pilote de canal est responsable de l'appel de Tcl_NotifyChannel pour informer le module de canal général. Le pilote doit éviter de faire échouer les autres pilotes de canal ou sources de rappels en appelant Tcl_NotifyChannel trop fréquemment. L'équité peut être assurée en mettant en file d'attente l'événement Tcl pour permettre à l'événement de canal d'être planifié séquentiellement avec d'autres événements. Voir la description de Tcl_QueueEvent pour plus de détails sur la planification d'un événement.

Cette valeur peut être récupérée avec Tcl_ChannelWatchProc, qui renvoie l'adresse de la fonction.

GETHANDLEPROC

Le champ getHandleProc contient l'adresse d'une fonction appelée par le niveau général pour récupérer un handle spécifique au canal. GetHandleProc doit correspondre au prototype suivant :

typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

InstanceData est la même que la valeur passée à Tcl_CreateChannel lorsque ce canal a été créé. L'argument direction est TCL_READABLE pour récupérer le handle utilisé pour l'entrée, ou TCL_WRITABLE pour récupérer le handle utilisé pour la sortie.

Si l'implémentation du canal a des handles spécifiques, la fonction doit récupérer le handle approprié en fonction de l'argument direction. Le handle doit être stocké à l'emplacement référencé par handlePtr, et TCL_OK doit être renvoyé. Si le canal n'est pas ouvert pour la direction spécifiée, ou si l'implémentation du canal n'utilise pas de handles spécifiques, la fonction doit renvoyer TCL_ERROR.

Cette valeur peut être récupérée avec Tcl_ChannelGetHandleProc, qui renvoie l'adresse de la fonction.

typedef int Tcl_DriverTruncateProc(

TCL_BADCHANNELOPTION

Cette procédure génère un message d'erreur "mauvaise option" dans un interpréteur (optionnel). Elle est utilisée par les pilotes de canal lorsqu'une option invalide de Set/Get est demandée. Son but est de concaténer la liste des options génériques à celles spécifiques et de factoriser le message d'erreur des options génériques.

Renvoie toujours TCL_ERROR.

Un message d'erreur est généré dans la valeur de résultat de interp pour indiquer qu'une commande a été invoquée avec une option mal formée. Le message est formaté comme suit :

    mauvaise option "blah" : doit être l'une des suivantes
    <...options génériques...>+<...options spécifiques...>
ce qui donne par exemple : 
    mauvaise option "-blah" : doit être l'une des suivantes -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, ou -sockname
lorsqu'elle est appelée avec optionList égal à "peername sockname".

"blah" est l'argument optionName et <options spécifiques> est une liste de mots spécifiques séparés par des espaces. La fonction se charge d'insérer des traits d'union avant chaque option, des virgules après et un "ou" avant la dernière option.

ANCIENS TYPES DE CANAUX

La structure Tcl_ChannelType originale (8.3.1 et versions antérieures) contenait les champs suivants :

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
} Tcl_ChannelType;

Bien qu'il soit possible de créer des canaux avec la structure ci-dessus, le code interne du canal déterminera la version. Il est essentiel d'utiliser la nouvelle structure Tcl_ChannelType si vous créez un pilote de canal empilé en raison de problèmes dans l'implémentation précédente des canaux empilés (8.2.0 à 8.3.1).

Avant 8.4.0 (c'est-à-dire pendant les dernières versions de 8.3 et une partie du début du cycle de développement de 8.4), la structure Tcl_ChannelType contenait les champs suivants :

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_ChannelTypeVersion version;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Lorsque la structure ci-dessus est enregistrée comme type de canal, le champ version doit toujours être TCL_CHANNEL_VERSION_2.
