Tcl_OpenTcpClient(3) Procédures de la bibliothèque Tcl Tcl_OpenTcpClient(3)

NOM

Tcl_OpenTcpClient, Tcl_MakeTcpClientChannel, Tcl_OpenTcpServer - procédures pour ouvrir des canaux utilisant des sockets TCP

SYNOPSIS

#include <tcl.h> 

Tcl_Channel
Tcl_OpenTcpClient(interp, port, host, myaddr, myport, async)

Tcl_Channel
Tcl_MakeTcpClientChannel(sock)

Tcl_Channel
Tcl_OpenTcpServer(interp, port, myaddr, proc, clientData)

ARGUMENTS

Tcl_Interp *interp (entree)
Interpréteur Tcl à utiliser pour le rapport d'erreurs. Si non NULL et qu'une erreur se produit, un message d'erreur est laissé dans le résultat de l'interpréteur.
int port (entree)
Un numéro de port auquel se connecter en tant que client ou sur lequel écouter en tant que serveur.
const char *host (entree)
Une chaîne spécifiant un nom d'hôte ou une adresse pour l'extrémité distante de la connexion.
int myport (entree)
Un numéro de port pour l'extrémité client du socket. Si 0, un numéro de port est alloué aléatoirement.
const char *myaddr (entree)
Une chaîne spécifiant le nom d'hôte ou l'adresse de l'interface réseau à utiliser pour l'extrémité locale de la connexion. Si NULL, une interface par défaut est choisie.
int async (entree)
Si non nul, le socket client est connecté de manière asynchrone au serveur.
ClientData sock (entree)
Handle spécifique à la plateforme pour le socket TCP client.
Tcl_TcpAcceptProc *proc (entree)
Pointeur vers une procédure à appeler chaque fois qu'une nouvelle connexion est acceptée via le socket.
ClientData clientData (entree)
Valeur arbitraire d'un mot à passer à proc.

DESCRIPTION

Ces fonctions sont des procédures de commodité pour créer des canaux qui communiquent via des sockets TCP. Les opérations sur un canal sont décrites dans l'entrée de manuel de Tcl_OpenFileChannel.

TCL_OPENTCPCLIENT

Tcl_OpenTcpClient ouvre un socket TCP client connecté à un port sur un host spécifique, et retourne un canal qui peut être utilisé pour communiquer avec le serveur. L'hôte auquel se connecter peut être spécifié soit comme un nom de style nom de domaine (par exemple, www.sunlabs.com), soit comme une chaîne contenant la représentation alphanumérique de son adresse de quatre octets (par exemple, 127.0.0.1). Utilisez la chaîne localhost pour vous connecter à un socket TCP sur l'hôte sur lequel la fonction est appelée.

Les arguments myaddr et myport permettent à un client de spécifier une adresse pour l'extrémité locale de la connexion. Si myaddr est NULL, une interface est choisie automatiquement par le système d'exploitation. Si myport est 0, un numéro de port est choisi aléatoirement par le système d'exploitation.

Si async est nul, l'appel à Tcl_OpenTcpClient ne retourne qu'après que le socket client se soit connecté avec succès au serveur, ou que la connexion tentée ait échoué. Si async est non nul, le socket est connecté de manière asynchrone et le canal retourné peut ne pas encore être connecté au serveur lorsque l'appel à Tcl_OpenTcpClient retourne. Si le canal est en mode bloquant et qu'une opération d'entrée ou de sortie est effectuée sur le canal avant que la connexion ne soit terminée ou échouée, cette opération attendra jusqu'à ce que la connexion se termine avec succès ou échoue. Si le canal est en mode non bloquant, l'opération d'entrée ou de sortie retournera immédiatement et un appel ultérieur à Tcl_InputBlocked sur le canal retournera non nul.

Le canal retourné est ouvert pour la lecture et l'écriture. Si une erreur se produit lors de l'ouverture du socket, Tcl_OpenTcpClient retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_MAKETCPCLIENTCHANNEL

Tcl_MakeTcpClientChannel crée un Tcl_Channel autour d'un handle existant, spécifique à la plateforme, pour un socket TCP client.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_OPENTCPSERVER

Tcl_OpenTcpServer ouvre un socket TCP sur l'hôte local sur un port spécifié et utilise le mécanisme d'événements Tcl pour accepter les requêtes des clients souhaitant s'y connecter. L'argument myaddr spécifie l'interface réseau. Si myaddr est NULL, l'adresse spéciale INADDR_ANY doit être utilisée pour autoriser les connexions depuis n'importe quelle interface réseau. Chaque fois qu'un client se connecte à ce socket, Tcl crée un canal pour la nouvelle connexion et appelle proc avec des informations sur le canal. Proc doit correspondre au prototype suivant :

typedef void Tcl_TcpAcceptProc(
        ClientData clientData,
        Tcl_Channel channel,
        char *hostName,
        int port);

L'argument clientData sera le même que l'argument clientData à Tcl_OpenTcpServer, channel sera le handle pour le nouveau canal, hostName pointera vers une chaîne contenant le nom de l'hôte client effectuant la connexion, et port contiendra le numéro de port du client. Le nouveau canal est ouvert pour l'entrée et la sortie. Si proc lève une erreur, la connexion est automatiquement fermée. Proc n'a pas de valeur de retour, mais s'il souhaite rejeter la connexion, il peut fermer channel.

Tcl_OpenTcpServer retourne normalement un pointeur vers un canal représentant le socket serveur. Si une erreur se produit, Tcl_OpenTcpServer retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si l'interpréteur n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Le canal retourné par Tcl_OpenTcpServer ne peut être utilisé ni pour l'entrée ni pour la sortie. C'est simplement un handle pour le socket utilisé pour accepter les connexions. L'appelant peut fermer le canal pour arrêter le serveur et interdire les connexions ultérieures de nouveaux clients.

Les canaux serveur TCP fonctionnent correctement uniquement dans les applications qui traitent les événements via Tcl_DoOneEvent ou via des commandes Tcl telles que vwait ; sinon, Tcl ne remarquera jamais qu'une demande de connexion d'un client distant est en attente.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en remplacement du canal standard.

PROBLEMES DE PLATEFORME

Sur les plateformes Unix, le handle de socket est un descripteur de fichier Unix tel que retourné par l'appel système socket. Sur la plateforme Windows, le handle de socket est un SOCKET tel que défini dans l'API WinSock.
