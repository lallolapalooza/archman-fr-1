DESCRIPTION

Les objets sont des entités typées qui ont un ensemble d'opérations ("méthodes") qui leur sont associées. Les classes sont des objets qui peuvent fabriquer des objets. Chaque classe peut être vue comme un objet; la vue d'objet peut être obtenue en utilisant Tcl_GetClaseAsObject, qui retourne toujours l'objet lorsqu'il est appliqué à une classe non détruite, et un objet peut être vu comme une classe avec l'aide de Tcl_GetObjectAsClase (qui retourne la classe, ou NULL si l'objet n'est pas une classe). Pour trouver une classe par son nom, il est correct de rechercher d'abord l'objet de ce nom et ensuite d'utiliser Tcl_GetObjectAsClase.

Chaque objet a sa propre commande et son propre espace de noms associés. La commande peut être obtenue en utilisant Tcl_GetObjectCommand, le nom de l'objet (et donc le nom de la commande) avec Tcl_GetObjectName, et l'espace de noms peut être obtenu en utilisant Tcl_GetObjectNamespace. Notez que la référence retournée par Tcl_GetObjectName est une référence partagée. Vous pouvez également savoir si l'objet a été marqué pour suppression en utilisant Tcl_ObjectDeleted (retourne vrai si la suppression de l'objet a commencé); ceci peut être utile lors du traitement des méthodes.

Les instances de classes sont créées en utilisant Tcl_NewObjectInstance, qui crée un objet à partir de n'importe quelle classe (et qui est appelée en interne par les méthodes create et new de la classe oo::class). Des paramètres peuvent être passés qui donnent optionnellement le nom de l'objet et l'espace de noms à créer, et qui décrivent les arguments à passer au constructeur de la classe (s'il y en a). Le résultat de la fonction sera soit une référence à l'objet créé, soit NULL si la création a échoué (auquel cas un message d'erreur sera laissé dans le résultat de l'interpréteur). De plus, les objets peuvent être copiés en utilisant Tcl_CopyObjectInstance, qui crée une copie d'un objet sans exécuter de constructeur.

Note: la gestion de la durée de vie des objets est gérée en interne par TclOO et n'utilise pas Tcl_Preserve. Il n'est pas sûr de placer un Tcl_Object dans une structure C dont la durée de vie est différente de celle de l'objet; vous devez utiliser le nom de la commande de l'objet (obtenu via Tcl_GetObjectName) à la place d'un pointeur vers Tcl_Object. Il est sûr d'utiliser un pointeur vers Tcl_Object pendant la durée d'un appel de méthode sur cet objet; les pointeurs ne deviennent pas invalides tant qu'il y a un appel de méthode sur leur objet (même si la seule opération garantie sûre sur eux est Tcl_ObjectDeleted; les autres opérations ne sont garanties de fonctionner qu'avec des objets non détruits).

METADONNEES OBJET ET CLASSE

Chaque objet et chaque classe peuvent avoir un certain volume de métadonnées associées, que l'objet ou la classe n'interprète pas au-delà de ce qui est décrit dans un Tcl_ObjectMetadataType instancié. Les métadonnées qui sont attachées sont décrites par le type de métadonnées (donné dans l'argument metaTypePtr) et un pointeur arbitraire (l'argument metadata) qui sont passés à Tcl_ObjectSetMetadata et Tcl_ClaseSetMetadata, et un certain morceau de métadonnées peut être obtenu étant donné son type via Tcl_ObjectGetMetadata et Tcl_ClaseGetMetadata. Si le paramètre metadata à Tcl_ObjectSetMetadata ou Tcl_ClaseSetMetadata est NULL, les métadonnées sont supprimées si elles étaient attachées, et les résultats de Tcl_ObjectGetMetadata et Tcl_ClaseGetMetadata sont NULL si le type de métadonnées spécifié n'était pas attaché. Il n'est pas une erreur de demander ou de supprimer un morceau de métadonnées qui n'était pas attaché.

STRUCTURE TCL_OBJECTMETADATATYPE

Le contenu de la structure Tcl_ObjectMetadataType est le suivant:

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

Le champ version permet l'expansion future de la structure, et doit toujours être déclaré égal à TCL_OO_METADATA_VERSION_CURRENT. Le champ name fournit un nom lisible par l'homme pour le type, et est réservé au débogage.

Le champ deleteProc donne un procédure de type Tcl_ObjectMetadataDeleteProc qui est utilisée pour supprimer un morceau de métadonnées, et est appelée lorsque les métadonnées attachées sont remplacées ou supprimées; le champ ne doit pas être NULL.

Le champ cloneProc donne une procédure qui est utilisée pour copier un morceau de métadonnées (utilisé lors de la création d'une copie d'un objet via Tcl_CopyObjectInstance); si NULL, les métadonnées seront simplement copiées directement.

Les fonctions qui correspondent à cette signature sont utilisées pour supprimer les métadonnées associées à une classe ou à un objet.

ARGUMENTS

The functions manipulate the metadata associated with an object or class. The metadata is stored as a void pointer, which is managed by TclOO. The user may optionally associate a destructor function with the metadata. This destructor function is called whenever the object or class is destroyed, or when the metadata is explicitly freed using Tcl_ObjectFreeMetadata.

DESCRIPTION

These functions provide a C API for interacting with TclOO objects and classes. They allow you to get and set constructors, delete procedures, method name mappers, and metadata associated with objects and classes.

TCL_GETOBJECTCOMMAND FUNCTION SIGNATURE

The Tcl_GetObjectCommand function returns the Tcl_Command associated with the object named name in the interpreter interp.

CONSTRUCTOR FUNCTIONS

Tcl_ObjectSetConstructor sets the constructor for the given class cls to proc. The freeProcData argument is client data that will be passed to the constructor when it is called. Tcl_ObjectGetConstructor returns the current constructor for the class.

typedef int (*Tcl_ObjectConstructor)(Tcl_Interp *interp, Tcl_Object obj, int objc, Tcl_Obj *const *objv);

The constructor is called when a new object is created using the class.

DELETE PROCEDURES

Tcl_ObjectSetDeleteProc associates a delete procedure proc with the metadata of the given object or class objOrClass. The clientData argument is the data to be passed to the delete procedure. Tcl_ObjectGetDeleteProc returns the current delete procedure for the object or class.

typedef void (*Tcl_ObjectDeleteProc)(ClientData metadata);

The delete procedure is called when the object or class is destroyed, or when the metadata is explicitly freed using Tcl_ObjectFreeMetadata.

OBJECT AND CLASS METADATA

TclOO allows associating arbitrary data, called metadata, with objects and classes. This metadata can be retrieved, set, and freed using the following functions:

Tcl_ObjectSetMetadata
Sets the metadata for the given object or class object to clientData. If a delete procedure deleteProc is provided, it will be called when the metadata is no longer needed. If deleteProc is NULL, the metadata is simply discarded.
Tcl_ObjectGetMetadata
Returns the metadata associated with the given object or class object.
Tcl_ObjectFreeMetadata
Frees the metadata associated with the given object or class object. If a delete procedure was associated with the metadata, it will be called.
Tcl_ObjectCloneMetadata
Clones the metadata from one object to another. The cloneProc argument is a procedure that TclOO will call to perform the actual cloning of the metadata. The srcMetadata argument is the metadata to be cloned.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to create copies of metadata associated with a class or object.

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData srcMetadata,
        ClientData *dstMetadataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The srcMetadata argument gives the address of the metadata to be cloned, and the cloned metadata should be written into the variable pointed to by dstMetadataPtr; a NULL should be written if the metadata is to not be cloned but the overall object copy operation is still to succeed.

OBJECT METHOD NAME MAPPING

It is possible to control, on a per-object basis, what methods are invoked when a particular method is invoked. Normally this is done by looking up the method name in the object and then in the class hierarchy, but fine control of exactly what the value used to perform the look up is afforded through the ability to set a method name mapper callback via Tcl_ObjectSetMethodNameMapper (and its introspection counterpart, Tcl_ObjectGetMethodNameMapper, which returns the current mapper). The current mapper (if any) is invoked immediately before looking up what chain of method implementations is to be used.

TCL_OBJECTMAPMETHODNAMEPROC FUNCTION SIGNATURE

The Tcl_ObjectMapMethodNameProc callback is defined as follows:

typedef int Tcl_ObjectMapMethodNameProc(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class **startClsPtr,
        Tcl_Obj **methodNameObjPtr);

If the result is TCL_OK, the remapping is assumed to have been done. If the result is TCL_ERROR, an error message will have been left in interp and the method call will fail. If the result is TCL_BREAK, the standard method name lookup rules will be used; the behavior of other result codes is currently undefined. The object parameter says which object is being processed. The startClsPtr parameter points to a variable that contains the first class to provide a definition in the method chain to process, or NULL if the whole chain is to be processed (the argument itself is never NULL); this variable may be updated by the callback. The methodNameObjPtr parameter gives a pointer to an object containing the name of the method being invoked, as provided by the user; this object may be updated by the callback.
