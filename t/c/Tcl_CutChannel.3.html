DESCRIPTION

Tcl utilise une architecture de canaux à deux couches. Elle fournit une couche supérieure générique pour permettre aux programmes C et Tcl d'effectuer des entrées et sorties en utilisant les mêmes API pour une variété de fichiers, périphériques, sockets, etc. Les API C génériques sont décrites dans la page de manuel de Tcl_OpenFileChannel.

La couche inférieure fournit des pilotes de canaux spécifiques au type pour chaque type de périphérique supporté sur chaque plateforme. Cette page de manuel décrit les API C utilisées pour communiquer entre la couche générique et les pilotes de canaux spécifiques au type. Elle explique également comment de nouveaux types de canaux peuvent être ajoutés en fournissant de nouveaux pilotes de canaux.

Les pilotes de canaux se composent d'un certain nombre de composants : Premièrement, chaque pilote de canal fournit une structure Tcl_ChannelType contenant des pointeurs vers les fonctions implémentant les diverses opérations utilisées par la couche générique pour communiquer avec le pilote de canal. La structure Tcl_ChannelType et les fonctions qu'elle référence sont décrites dans la section TCL_CHANNELTYPE, ci-dessous.

Deuxièmement, les pilotes de canaux fournissent généralement une commande Tcl pour créer des instances de ce type de canal. Par exemple, la commande Tcl open crée des canaux qui utilisent les pilotes de canaux de fichier et de commande, et la commande Tcl socket crée des canaux qui utilisent des sockets TCP pour la communication réseau.

Troisièmement, un pilote de canal fournit facultativement une fonction C pour ouvrir des instances de canal de ce type. Par exemple, Tcl_OpenFileChannel ouvre un canal qui utilise le pilote de canal de fichier, et Tcl_OpenTcpClient ouvre un canal qui utilise le protocole réseau TCP. Ces fonctions de création utilisent typiquement Tcl_CreateChannel en interne pour ouvrir le canal.

Pour ajouter un nouveau type de canal, vous devez implémenter une API C ou une commande Tcl qui ouvre un canal en appelant Tcl_CreateChannel. Lorsque votre pilote appelle Tcl_CreateChannel, il lui transmet une structure Tcl_ChannelType décrivant les procédures d'E/S du pilote. La couche générique invoquera alors les fonctions référencées dans cette structure pour effectuer des opérations sur le canal.

Tcl_CreateChannel ouvre un nouveau canal et lui associe le typePtr et instanceData fournis. Le canal est ouvert dans le mode indiqué par mask. Pour une discussion sur les pilotes de canaux, leurs opérations et la structure Tcl_ChannelType, voir la section TCL_CHANNELTYPE, ci-dessous.

Tcl_CreateChannel interagit avec le code gérant les canaux standards. Une fois qu'un canal standard a été initialisé soit par un appel à Tcl_GetStdChannel, soit par un appel à Tcl_SetStdChannel, la fermeture de ce canal standard provoquera lors du prochain appel à Tcl_CreateChannel la création du nouveau canal en tant que nouveau canal standard également. Voir Tcl_StandardChannels pour un traité général sur les canaux standards et le comportement de la bibliothèque Tcl à leur égard.

Tcl_GetChannelInstanceData retourne les données d'instance associées au canal dans channel. Il s'agit de la même valeur que l'argument instanceData dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelType retourne un pointeur vers la structure Tcl_ChannelType utilisée par le canal dans l'argument channel. Il s'agit de la même valeur que l'argument typePtr dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelName retourne une chaîne contenant le nom associé au canal, ou NULL si l'argument channelName de Tcl_CreateChannel était NULL.

Tcl_GetChannelHandle place la poignée de périphérique spécifique au système d'exploitation associée à channel pour la direction donnée à l'emplacement indiqué par handlePtr.

Tcl_GetChannelThread retourne l'ID du thread qui possède le canal.

Tcl_GetChannelMode retourne le mode d'ouverture actuel du canal sous forme d'une combinaison OR des drapeaux TCL_READABLE et TCL_WRITABLE.

Tcl_GetChannelBufferSize retourne la taille actuelle du tampon pour les opérations de lecture et d'écriture sur le canal.

Tcl_SetChannelBufferSize configure la taille du tampon pour les opérations de lecture et d'écriture sur le canal.

Tcl_NotifyChannel est appelé par le pilote de canal pour informer la couche générique que certains événements se sont produits sur le canal. Le masque d'événements est une combinaison OR des drapeaux TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION.

Tcl_BadChannelOption est une procédure utilitaire pour générer une erreur indiquant que l'option spécifiée n'est pas valide pour le canal courant. Si interp n'est pas NULL, elle génère un message d'erreur dans l'interpréteur.

Tcl_IsChannelShared retourne vrai si le canal est partagé entre plusieurs interpréteurs.

Tcl_IsChannelRegistered retourne vrai si le canal est actuellement enregistré dans l'interpréteur spécifié.

Tcl_IsChannelExisting retourne vrai si un canal nommé channelName existe dans l'interpréteur courant.

Tcl_CutChannel détache un canal de son pilote de bas niveau, le rendant inutilisable pour les opérations d'E/S ultérieures. Le canal est cependant toujours accessible à partir de Tcl jusqu'à ce qu'il soit explicitement fermé.

Tcl_SpliceChannel est l'inverse de Tcl_CutChannel. Elle reconnecte un canal précédemment découpé à un pilote de bas niveau.

Tcl_ClearChannelHandlers supprime tous les gestionnaires d'événements associés au canal.

Tcl_ChannelBuffered retourne le nombre d'octets actuellement dans le tampon de sortie du canal.

Les fonctions Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc, et Tcl_ChannelHandlerProc sont des fonctions d'accès aux membres de la structure Tcl_ChannelType.

TCL_CHANNELTYPE

Un pilote de canal implémenté en C doit fournir une structure Tcl_ChannelType qui contient des informations sur le type de canal et des pointeurs vers les procédures qui implémentent les opérations d'E/S et d'autres fonctionnalités pour ce type de canal. La structure Tcl_ChannelType est définie comme suit :

typedef struct Tcl_ChannelType {
    const char *name;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverThreadActionProc *threadActionProc;
    Tcl_DriverTruncateProc *truncateProc;
    Tcl_DriverWideSeekProc *wideSeekProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_ChannelTypeVersion version;
} Tcl_ChannelType;

Les membres de la structure Tcl_ChannelType sont les suivants :

name
Nom du type de canal, utilisé par exemple dans la commande fconfigure pour identifier les options spécifiques au type.
blockModeProc
Pointeur vers une procédure qui configure le mode bloquant ou non-bloquant du canal. Voir Tcl_SetChannelOption.
closeProc
Pointeur vers une procédure qui effectue les opérations de fermeture du canal. Elle est appelée lorsque le canal est fermé. Si elle est NULL, Tcl_Close ne fera rien.
inputProc
Pointeur vers une procédure qui lit des données à partir du canal. Voir Tcl_Read.
outputProc
Pointeur vers une procédure qui écrit des données dans le canal. Voir Tcl_Write.
seekProc
Pointeur vers une procédure qui repositionne la position de lecture/écriture dans le canal. Voir Tcl_Seek.
setOptionProc
Pointeur vers une procédure qui définit une option pour le canal. Voir Tcl_SetChannelOption.
getOptionProc
Pointeur vers une procédure qui obtient la valeur d'une option pour le canal. Voir Tcl_GetChannelOption.
watchProc
Pointeur vers une procédure appelée lorsque des événements sont attendus sur le canal. Permet au pilote d'enregistrer des descripteurs de fichiers auprès du mécanisme de surveillance d'événements de Tcl.
getHandleProc
Pointeur vers une procédure qui retourne le handle OS spécifique au canal pour une direction donnée.
flushProc
Pointeur vers une procédure qui vide le tampon du canal.
handlerProc
Pointeur vers une procédure qui gère les événements sur le canal.
threadActionProc
Pointeur vers une procédure qui gère les actions du thread sur le canal.
truncateProc
Pointeur vers une procédure qui tronque le canal à une position donnée. Voir Tcl_TruncateChannel.
wideSeekProc
Pointeur vers une procédure qui repositionne la position de lecture/écriture dans le canal en utilisant des entiers 64 bits. Voir Tcl_Seek.
close2Proc
Pointeur vers une procédure qui effectue les opérations de fermeture du canal, en recevant un drapeau d'arrêt. Elle est appelée lorsque le canal est fermé. Si elle est NULL, Tcl_Close2 appelle closeProc.
version
La version de l'interface du pilote de canal. Doit être TCL_CHANNEL_VERSION_1.

Si un pilote de canal ne prend pas en charge une opération particulière, le pointeur correspondant dans la structure Tcl_ChannelType doit être NULL.

TCL_CHANNELTYPE

Un pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers des fonctions implémentant les diverses opérations sur un canal ; ces opérations sont appelées au besoin par la couche générique. Cette structure a été versionnée à partir de Tcl 8.3.2/8.4 pour corriger un problème avec les pilotes de canaux empilés. Voir la section OLD CHANNEL TYPES pour plus de détails sur l'ancienne structure.

La structure Tcl_ChannelType contient les champs suivants :

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Il n'est pas nécessaire de fournir des implémentations pour toutes les opérations de canal. Celles qui ne sont pas nécessaires peuvent être définies sur NULL dans la structure : blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc, et close2Proc, en plus de flushProc, handlerProc, threadActionProc, et truncateProc. Les fonctions qui ne peuvent pas être implémentées de manière significative doivent renvoyer EINVAL lorsqu'elles sont appelées, pour indiquer que les opérations représentées ne sont pas disponibles. Il faut également noter que wideSeekProc peut être NULL si seekProc ne l'est pas.

L'utilisateur ne doit utiliser que cette structure pour l'instanciation de Tcl_ChannelType. Lors de la référence aux champs d'une structure Tcl_ChannelType, les fonctions suivantes doivent être utilisées pour obtenir les valeurs : Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc, ou Tcl_ChannelHandlerProc.

La modification des structures a été effectuée de manière à ce que les types de canaux standard soient binaires compatibles. Cependant, les types de canaux qui utilisent des canaux empilés (c'est-à-dire TLS, Trf) ont de nouvelles versions correspondant à cette modification en raison de problèmes dans l'ancien code des canaux empilés.

TYPENAME

Le champ typeName contient une chaîne terminée par un caractère nul qui identifie le type de périphérique implémenté par ce pilote, par exemple, file ou socket.

Cette valeur peut être obtenue avec Tcl_ChannelName, qui renvoie un pointeur vers la chaîne.

VERSION

Le champ version doit être défini à la version de la structure requise. TCL_CHANNEL_VERSION_2 est la version minimale recommandée. TCL_CHANNEL_VERSION_3 doit être défini pour spécifier le membre wideSeekProc. TCL_CHANNEL_VERSION_4 doit être défini pour spécifier le membre threadActionProc (inclut wideSeekProc). TCL_CHANNEL_VERSION_5 doit être défini pour spécifier les membres truncateProc (inclut wideSeekProc et threadActionProc). Si elle n'est définie sur aucune de ces valeurs, Tcl_ChannelType supposera la structure d'origine. Voir OLD CHANNEL TYPES pour plus de détails. Bien que Tcl reconnaisse et fonctionne avec chacune de ces structures, les canaux empilés doivent être au moins TCL_CHANNEL_VERSION_2 pour fonctionner correctement.

Cette valeur peut être obtenue avec Tcl_ChannelVersion, qui renvoie l'une des valeurs TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 ou TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

Le champ blockModeProc contient l'adresse d'une fonction appelée par la couche générique pour définir le mode bloquant et non bloquant sur le périphérique. BlockModeProc doit correspondre au prototype suivant :

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

instanceData est la même valeur que celle fournie à Tcl_CreateChannel lorsque ce canal a été créé. L'argument mode doit être TCL_MODE_BLOCKING ou TCL_MODE_NONBLOCKING pour définir le périphérique en mode bloquant ou non bloquant. La fonction doit renvoyer zéro si l'opération a réussi, ou un code d'erreur POSIX non nul si l'opération a échoué.

Si l'opération réussit, la fonction peut modifier le instanceData fourni pour enregistrer que le canal est entré en mode bloquant ou non bloquant et pour implémenter le comportement bloquant ou non bloquant. Pour certains types de périphériques, le comportement bloquant et non bloquant peut être implémenté par le système d'exploitation sous-jacent ; pour d'autres types de périphériques, le comportement doit être émulé dans le pilote de canal.

Cette valeur peut être obtenue avec Tcl_ChannelBlockModeProc, qui renvoie un pointeur vers la fonction.

Un pilote de canal qui ne fournit pas de blockModeProc doit être très prudent. Il doit indiquer exactement quel mode bloquant lui convient, et il doit également le documenter pour l'utilisateur, afin que le mode bloquant du canal ne soit pas modifié à une valeur inacceptable. Des confusions peuvent survenir ici et entraîner un interblocage (faux et difficile à trouver) de l'interpréteur.

CLOSEPROC ET CLOSE2PROC

Le champ closeProc contient l'adresse d'une fonction appelée par la couche générique pour nettoyer les informations relatives au pilote lorsque le canal est fermé. closeProc doit correspondre au prototype suivant :

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

L'argument instanceData est la même valeur que celle fournie à Tcl_CreateChannel lorsque le canal a été créé. La fonction doit libérer tout stockage conservé par le pilote de canal pour ce canal et fermer les périphériques d'entrée et de sortie encapsulés par ce canal. Toutes les données de sortie accumulées auront déjà été vidées avant que cette fonction ne soit exécutée, et aucune opération de pilote ne sera appelée après l'appel de closeProc. CLOSEPROC ET CLOSE2PROC

Le champ closeProc contient l'adresse d'une fonction appelée par la couche générique pour fermer un canal. Le pilote de canal peut être appelé plusieurs fois pour fermer un canal, mais seulement une fois pour une opération de fermeture complète. La fonction closeProc doit correspondre au prototype suivant :

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

InstanceData est la même valeur que celle transmise à Tcl_CreateChannel lors de la création du canal. La fonction closeProc doit libérer toutes les ressources associées au canal et fermer le descripteur de fichier sous-jacent. Si une erreur se produit, la fonction doit renvoyer un code d'erreur POSIX non nul. En outre, si une erreur se produit et que interp n'est pas NULL, la procédure doit stocker un message d'erreur dans le résultat de l'interpréteur.

Alternativement, les canaux qui prennent en charge la fermeture indépendante des côtés lecture et écriture peuvent définir closeProc sur TCL_CLOSE2PROC et définir close2Proc sur l'adresse d'une fonction correspondant au prototype suivant :

typedef int Tcl_DriverClose2Proc(
        ClientData instanceData,
        Tcl_Interp *interp,
        int flags);

La fonction close2Proc sera appelée avec flags défini sur une combinaison OU de TCL_CLOSE_READ ou TCL_CLOSE_WRITE pour indiquer que le pilote doit fermer le côté lecture et/ou écriture du canal. Le pilote de canal peut être appelé pour effectuer des opérations supplémentaires sur le canal après l'appel de close2Proc pour fermer un ou deux côtés du canal. Si flags est 0 (zéro), le pilote doit fermer le canal de la manière décrite ci-dessus pour closeProc. Aucune autre opération ne sera invoquée sur cette instance après l'appel de close2Proc avec tous les indicateurs effacés. Dans tous les cas, la fonction close2Proc doit renvoyer zéro si l'opération de fermeture a réussi ; sinon, elle doit renvoyer un code d'erreur POSIX non nul. De plus, si une erreur se produit et que interp n'est pas NULL, la procédure doit stocker un message d'erreur dans le résultat de l'interpréteur.

Les valeurs closeProc et close2Proc peuvent être récupérées avec Tcl_ChannelCloseProc ou Tcl_ChannelClose2Proc, qui renvoient un pointeur vers la fonction respective.

INPUTPROC

Le champ inputProc contient l'adresse d'une fonction appelée par la couche générique pour lire des données du fichier ou de l'appareil et les stocker dans un tampon interne. InputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

InstanceData est la même valeur que celle transmise à Tcl_CreateChannel lors de la création du canal. L'argument buf pointe vers un tableau d'octets dans lequel stocker les entrées de l'appareil, et l'argument bufSize indique le nombre d'octets disponibles dans buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique. En cas d'erreur, la fonction doit définir la variable sur un code d'erreur POSIX qui identifie l'erreur qui s'est produite.

La fonction doit lire les données de l'appareil d'entrée encapsulé par le canal et les stocker dans buf. En cas de succès, la fonction doit renvoyer un entier non négatif indiquant le nombre d'octets lus à partir de l'appareil d'entrée et stockés dans buf. En cas d'erreur, la fonction doit renvoyer -1. Si une erreur se produit après que certaines données ont été lues à partir de l'appareil, ces données sont perdues.

Si inputProc peut déterminer que l'appareil d'entrée dispose de données disponibles mais moins que ce qui est demandé par l'argument bufSize, la fonction ne doit tenter de lire que la quantité de données disponible et renvoyer sans bloquer. Si l'appareil d'entrée ne dispose d'aucune donnée disponible et que le canal est en mode non bloquant, la fonction doit renvoyer une erreur EAGAIN. Si l'appareil d'entrée ne dispose d'aucune donnée disponible et que le canal est en mode bloquant, la fonction doit bloquer pendant la durée la plus courte possible jusqu'à ce qu'au moins un octet de données puisse être lu à partir de l'appareil ; ensuite, elle doit renvoyer autant de données qu'elle peut lire sans bloquer.

Cette valeur peut être récupérée avec Tcl_ChannelInputProc, qui renvoie un pointeur vers la fonction.

OUTPUTPROC

Le champ outputProc contient l'adresse d'une fonction appelée par la couche générique pour transférer des données d'un tampon interne vers l'appareil de sortie. OutputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

InstanceData est la même valeur que celle transmise à Tcl_CreateChannel lors de la création du canal. L'argument buf contient un tableau d'octets à écrire sur l'appareil, et l'argument toWrite indique le nombre d'octets à écrire à partir de l'argument buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique. En cas d'erreur, la fonction doit définir cette variable sur un code d'erreur POSIX qui identifie l'erreur.

La fonction doit écrire les données dans buf sur l'appareil de sortie encapsulé par le canal. En cas de succès, la fonction doit renvoyer un entier non négatif indiquant le nombre d'octets écrits sur l'appareil de sortie. La valeur de retour est normalement identique à toWrite, mais peut être inférieure dans certains cas, par exemple si l'opération de sortie est interrompue par un signal. En cas d'erreur, la fonction doit renvoyer -1. En cas d'erreur, certaines données peuvent avoir été écrites sur l'appareil.

Si le canal est non bloquant et que l'appareil de sortie ne peut absorber aucune donnée, la fonction doit renvoyer -1 avec une erreur EAGAIN sans écrire de données.

Cette valeur peut être récupérée avec Tcl_ChannelOutputProc, qui renvoie un pointeur vers la fonction.

SEEKPROC ET WIDESEEKPROC

Le champ seekProc contient l'adresse d'une fonction appelée par la couche générique pour déplacer le point d'accès auquel les opérations d'entrée ou de sortie ultérieures seront appliquées. SeekProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

L'argument instanceData est la même valeur que celle donnée à Tcl_CreateChannel lors de la création de ce canal. Offset et seekMode ont la même signification que pour la procédure Tcl_Seek (décrite dans l'entrée du manuel de Tcl_OpenFileChannel).

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générique pour renvoyer les valeurs errno de la fonction. La fonction doit définir cette variable sur un code d'erreur POSIX si une erreur se produit. La fonction doit stocker un code d'erreur EINVAL si le type de canal n'implémente pas le déplacement.

La valeur de retour est le nouveau point d'accès ou -1 en cas d'erreur. Si une erreur s'est produite, la fonction ne doit pas déplacer le point d'accès.

S'il existe un champ seekProc non NULL, le champ wideSeekProc peut contenir l'adresse d'une fonction alternative à utiliser qui gère les décalages larges (c'est-à-dire supérieurs à 32 bits), permettant ainsi les déplacements dans des fichiers de plus de 2 Go. WideSeekProc sera appelé de préférence à seekProc, mais les deux doivent être définis si wideSeekProc est défini. WideSeekProc doit correspondre au prototype suivant :

typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

Les arguments et les valeurs de retour signifient la même chose qu'avec seekProc ci-dessus, à l'exception du type des décalages et du type de retour qui sont différents.

La valeur seekProc peut être récupérée avec Tcl_ChannelSeekProc, qui renvoie un pointeur vers la fonction, et de même wideSeekProc peut être récupéré avec Tcl_ChannelWideSeekProc.

SETOPTIONPROC

Le champ setOptionProc contient l'adresse d'une fonction appelée par la couche générique pour définir une option spécifique au type de canal sur un canal. setOptionProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

optionName est le nom d'une option à définir, et newValue est la nouvelle valeur de cette option, sous forme de chaîne. instanceData est la même valeur que celle donnée à Tcl_CreateChannel lors de la création de ce canal. La fonction doit effectuer toute action spécifique au type de canal nécessaire pour implémenter la nouvelle valeur de l'option.

Certaines options sont gérées par le code générique et cette fonction n'est jamais appelée pour les définir, par exemple -blockmode. D'autres options sont spécifiques à chaque type de canal et la procédure setOptionProc du pilote de canal sera appelée pour les implémenter. Le champ setOptionProc peut être NULL, ce qui indique que ce type de canal ne prend en charge aucune option spécifique au type.

Si la valeur de l'option est modifiée avec succès vers la nouvelle valeur, la fonction renvoie TCL_OK. Elle doit appeler Tcl_BadChannelOption qui renvoie elle-même TCL_ERROR si optionName n'est pas reconnu. Si newValue spécifie une valeur pour l'option qui n'est pas prise en charge ou si une erreur d'appel système se produit, la fonction doit laisser un message d'erreur dans le résultat de interp si interp n'est pas NULL. La fonction doit également appeler Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

Cette valeur peut être récupérée avec Tcl_ChannelSetOptionProc, qui renvoie un pointeur vers la fonction.

GETOPTIONPROC

Le champ getOptionProc contient l'adresse d'une fonction appelée par la couche générique pour obtenir la valeur d'une option spécifique au type de canal sur un canal. getOptionProc doit correspondre au prototype suivant :

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        Tcl_DString *optionValue);

OptionName est le nom d'une option prise en charge par ce type de canal. Si le nom de l'option n'est pas NULL, la fonction stocke sa valeur actuelle, sous forme de chaîne, dans la chaîne dynamique Tcl optionValue. Si optionName est NULL, la fonction stocke dans optionValue une liste alternée de toutes les options prises en charge et de leurs valeurs actuelles. En cas de succès, la fonction renvoie TCL_OK. Elle doit appeler Tcl_BadChannelOption qui renvoie elle-même TCL_ERROR si optionName

WATCHPROC

Le champ watchProc contient l'adresse d'une fonction appelée par la couche générale pour initialiser le mécanisme de notification des événements qui intéressent ce canal. WatchProc doit correspondre au prototype suivant :

typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lorsque ce canal a été créé. L'argument mask est une combinaison OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION ; il indique les événements qui intéressent l'utilisateur pour ce canal.

La fonction doit initialiser les mécanismes spécifiques au type de périphérique pour qu'ils signalent lorsqu'un événement intéressant se produit sur le canal. Lorsqu'un événement intéressant se produit sur le canal, le pilote du canal doit appeler Tcl_NotifyChannel pour informer le module de canal générique. Le pilote doit veiller à ne pas surcharger les autres pilotes de canal ou les sources de rappels en appelant Tcl_NotifyChannel trop fréquemment. L'équité peut être assurée en appelant la file d'attente d'événements Tcl pour permettre à l'événement de canal d'être programmé séquentiellement avec d'autres événements. Voir la description de Tcl_QueueEvent pour plus de détails sur la façon de programmer un événement.

Cette valeur peut être récupérée avec Tcl_ChannelWatchProc, qui renvoie l'adresse de la fonction.

GETHANDLEPROC

Le champ getHandleProc contient l'adresse d'une fonction appelée par la couche générale pour récupérer un handle spécifique au canal. GetHandleProc doit correspondre au prototype suivant :

typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lorsque ce canal a été créé. L'argument direction est soit TCL_READABLE pour récupérer le handle utilisé pour l'entrée, soit TCL_WRITABLE pour récupérer le handle utilisé pour la sortie.

Si l'implémentation du canal a des handles spécifiques, la fonction doit récupérer le handle approprié en fonction de l'argument direction. Le handle doit être stocké à l'emplacement référencé par handlePtr, et TCL_OK doit être renvoyé. Si le canal n'est pas ouvert dans la direction spécifiée, ou si l'implémentation du canal n'utilise pas de handles spécifiques, la fonction doit renvoyer TCL_ERROR.

Cette valeur peut être récupérée avec Tcl_ChannelGetHandleProc, qui renvoie l'adresse de la fonction.

FLUSHPROC

Le champ flushProc est actuellement réservé pour une utilisation future. Il doit être défini sur NULL. FlushProc doit correspondre au prototype suivant :

typedef int Tcl_DriverFlushProc(
        ClientData instanceData);

Cette valeur peut être récupérée avec Tcl_ChannelFlushProc, qui renvoie l'adresse de la fonction.

HANDLERPROC

Le champ handlerProc contient l'adresse d'une fonction appelée par la couche générale pour notifier le canal qu'un événement s'est produit. Il doit être défini pour les pilotes de canaux empilés qui souhaitent être notifiés des événements se produisant sur le canal sous-jacent (empilé). HandlerProc doit correspondre au prototype suivant :

typedef int Tcl_DriverHandlerProc(
        ClientData instanceData,
        int interestMask);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lorsque ce canal a été créé. L'interestMask est une combinaison OR de TCL_READABLE ou TCL_WRITABLE ; elle indique le type d'événement qui s'est produit sur ce canal.

Cette valeur peut être récupérée avec Tcl_ChannelHandlerProc, qui renvoie l'adresse de la fonction.

THREADACTIONPROC

Le champ threadActionProc contient l'adresse de la fonction appelée par la couche générale lorsqu'un canal est créé, fermé ou doit être déplacé vers un thread différent, c'est-à-dire lorsque l'état spécifique au thread du pilote peut devoir être initialisé ou mis à jour. Il peut être NULL. L'action TCL_CHANNEL_THREAD_REMOVE est utilisée pour notifier le pilote qu'il doit mettre à jour ou supprimer toute donnée d'état spécifique au thread qu'il pourrait détenir pour le canal.

L'action TCL_CHANNEL_THREAD_INSERT est utilisée pour notifier le pilote qu'il doit mettre à jour ou initialiser toute donnée d'état spécifique au thread qu'il pourrait détenir en utilisant le thread actuel comme associé. Voir Tcl_CutChannel et Tcl_SpliceChannel pour plus de détails.

typedef void Tcl_DriverThreadActionProc(
        ClientData instanceData,
        int action);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lorsque ce canal a été créé.

Ces valeurs peuvent être récupérées avec Tcl_ChannelThreadActionProc, qui renvoie l'adresse de la fonction.

TRUNCATEPROC

Le champ truncateProc contient l'adresse de la fonction appelée par la couche générale lorsqu'un canal est tronqué à une longueur spécifiée. Il peut être NULL.

typedef int Tcl_DriverTruncateProc(
        ClientData instanceData,
        Tcl_WideInt length);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lorsque ce canal a été créé, et length est la nouvelle longueur du fichier sous-jacent, qui ne doit pas être négative. Le résultat doit être 0 en cas de succès ou un code d'erreur (qui peut être utilisé avec Tcl_SetErrno) en cas d'échec.

Ces valeurs peuvent être récupérées avec Tcl_ChannelTruncateProc, qui renvoie l'adresse de la fonction.

TCL_BADCHANNELOPTION

Cette procédure génère un message d'erreur « option invalide » dans un interpréteur (optionnel). Elle est utilisée par les pilotes de canaux lorsqu'une option Set/Get invalide est demandée. Son but est de concaténer la liste des options génériques à la liste spécifique et de factoriser le message d'erreur des options génériques.

Retourne toujours TCL_ERROR.

Un message d'erreur est généré dans la valeur de résultat de interp pour indiquer qu'une commande a été appelée avec une option invalide. Le message est de la forme :

    bad option "blah": should be one of
    <...generic options...>+<...specific options...>
par exemple : 
    bad option "-blah": should be one of -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, or -sockname
lorsqu'elle est appelée avec optionList égal à "peername sockname".

"blah" est l'argument optionName et "<options spécifiques>" est une liste de mots séparés par des espaces. La fonction gère correctement l'insertion de traits d'union devant chaque option, de virgules après et d'un "ou" avant la dernière option.

ANCIENS TYPES DE CANAUX

Le Tcl_ChannelType original (8.3.1 et versions antérieures) contient les champs suivants :

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
} Tcl_ChannelType;

Bien qu'il soit possible de créer des canaux avec la structure ci-dessus, le code interne du canal déterminera la version. Il est essentiel d'utiliser la nouvelle structure Tcl_ChannelType si vous créez un pilote de canal empilé en raison de problèmes dans l'implémentation précédente des canaux empilés (8.2.0 à 8.3.1).

Avant 8.4.0 (c'est-à-dire, pendant les dernières versions de 8.3 et une partie du cycle de développement de 8.4), la structure Tcl_ChannelType contenait les champs suivants :

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_ChannelTypeVersion version;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Lorsque la structure ci-dessus est enregistrée comme type de canal, le champ version doit toujours être TCL_CHANNEL_VERSION_2.

Tcl_CutChannel(3)

NAME

Tcl_CutChannel - coupes un canal du pilote de canal Tcl

SYNOPSIS

#include <tcl.h>

int
Tcl_CutChannel(interp, channel);
Tcl_Interp *interp;
Tcl_Channel channel;

ARGUMENTS

Tcl_Interp *interp (in): Interpréteur Tcl à utiliser pour les messages d'erreur.

Tcl_Channel channel (in): Canal à couper.

DESCRIPTION

La procédure Tcl_CutChannel est utilisée pour désenregistrer un canal du système de canaux Tcl. Cela libère toutes les ressources associées au canal, y compris le tampon d'entrée/sortie, et empêche toute utilisation future du canal. La plupart des applications utilisant Tcl n'auront pas besoin d'appeler cette procédure, car Tcl le fera automatiquement lorsque l'objet channel sera détruit. Elle est principalement destinée à être utilisée par les implémentations de pilotes de canal personnalisés.

Lorsque vous coupez un canal, Tcl recherche et libère le descripteur de fichier sous-jacent. Si le canal est bloquant, le descripteur de fichier est fermé. Si le canal est non bloquant, le descripteur de fichier n'est pas fermé, mais il est retiré de la liste des descripteurs de fichier surveillés par le gestionnaire d'événements Tcl. Cela empêche les événements futurs sur le descripteur de fichier de déclencher des rappels Tcl.

La procédure renvoie TCL_OK si le canal a été coupé avec succès, et TCL_ERROR s'il y a eu une erreur (par exemple, si le canal n'est pas valide ou s'il a déjà été coupé).

TCL_CHANNELTYPE

La structure Tcl_ChannelType est utilisée pour définir le comportement d'un type de canal particulier. Elle contient un ensemble de pointeurs de fonction qui gèrent diverses opérations sur le canal, telles que la lecture, l'écriture, la fermeture, etc.

TCL_BADCHANNELOPTION

Indique une option de canal invalide lors de l'appel de Tcl_SetChannelOption ou Tcl_GetChannelOption.

OLD CHANNEL TYPES

Les anciens types de canaux étaient moins flexibles et manquaient de certaines des fonctionnalités des types de canaux modernes.
