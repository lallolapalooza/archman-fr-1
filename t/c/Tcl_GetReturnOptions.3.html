DESCRIPTION

Les procédures Tcl_SetReturnOptions et Tcl_GetReturnOptions exposent les mêmes capacités que les commandes return et catch sous la forme d'une interface C.

La procédure Tcl_GetReturnOptions récupère le dictionnaire des options de retour de l'interpréteur après l'évaluation d'un script. Les procédures comme Tcl_Eval sont appelées pour évaluer un script dans un interpréteur. Ces procédures retournent un code de complétion entier. Ces procédures conservent également dans l'interpréteur le résultat et le dictionnaire des options de retour générés par l'évaluation du script. Semblablement à Tcl_GetObjResult, Tcl_GetReturnOptions récupère le dictionnaire des options de retour. Le code de complétion entier devrait être passé comme argument code à Tcl_GetReturnOptions afin que tous les arguments nécessaires soient présents dans le dictionnaire. Spécifiquement, une valeur de code de TCL_ERROR garantira que les entrées pour les clés -errorinfo, -errorcode et -errorline sont présentes dans le dictionnaire. Elle ajustera également les entrées pour les clés -code et -level si nécessaire pour qu'elles correspondent à la valeur de code. Le (Tcl_Obj *) retourné par Tcl_GetReturnOptions pointe vers un Tcl_Obj non partagé avec un compteur de références de zéro. Le dictionnaire peut être modifié, en ajoutant, supprimant ou en écrasant n'importe quelle entrée, sans avoir à vérifier une valeur partagée. Comme pour tout Tcl_Obj avec un compteur de références de zéro, l'utilisateur doit gérer sa disposition avec Tcl_DecrRefCount ou en le référençant avec Tcl_IncrRefCount (ou une des nombreuses procédures qui l'appellent, comme Tcl_SetObjResult et Tcl_SetVar2Ex).

Une utilisation typique de Tcl_GetReturnOptions est de récupérer la pile d'appels lorsque le retour du script est TCL_ERROR, comme illustré ci-dessous :

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* Faire quelque chose avec stackTrace */
    Tcl_DecrRefCount(options);
}

La procédure Tcl_SetReturnOptions définit les options de retour de l'interpréteur à options. Si options contient une valeur invalide pour une clé, TCL_ERROR sera retourné et le résultat de l'interpréteur sera défini à un message d'erreur approprié. Sinon, un code de complétion sera retourné conformément aux valeurs des clés -code et -level dans options.

À titre d'exemple, la commande return de Tcl pourrait être implémentée en termes de Tcl_SetReturnOptions comme suit :

if ((objc % 2) == 0) { /* argument explicite */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(Ce n'est pas réellement implémenté ainsi. Les privilèges internes permettent une alternative plus efficace qui s'aligne mieux avec le compilateur bytecode.)

Note : Un objet Tcl_Obj nouvellement créé peut être passé comme argument options sans avoir besoin de gérer de compteur de références. Ceci est analogue à Tcl_SetObjResult.

Bien que Tcl_SetReturnOptions fournisse une interface générale pour définir n'importe quel ensemble d'options de retour, il existe un petit nombre d'options de retour qui sont très fréquemment utilisées. Les plus notables sont les options -errorinfo et -errorcode qui doivent être définies correctement lorsque la procédure d'une commande retourne TCL_ERROR. L'option -errorline est également lue par les commandes qui évaluent des scripts et souhaitent fournir des informations détaillées sur la localisation dans la pile d'appels qu'elles ajoutent à l'option -errorinfo. Tcl fournit plusieurs interfaces plus simples pour définir ces options de retour plus directement.

L'option -errorinfo contient une pile d'appels des opérations qui ont été exécutées lorsqu'une erreur s'est produite, et elle est intentionnellement lisible par l'utilisateur. L'option -errorcode contient une liste d'éléments Tcl qui sont intentionnellement lisibles sous forme de machine. Le premier élément de l'option -errorcode identifie le type d'erreur qui s'est produite (par exemple, POSIX signifie qu'une erreur s'est produite dans un appel système POSIX). Les éléments supplémentaires contiennent des informations supplémentaires dépendant du type d'erreur. Voir l'entrée de manuel sur la variable errorCode pour plus de détails sur les différents formats utilisés dans l'option -errorcode par les commandes Tcl internes.

L'option -errorinfo est progressivement construite lors de la remontée des erreurs à travers les opérations imbriquées. Chaque fois qu'un code d'erreur est retourné à Tcl_Eval ou à toute procédure qui effectue l'évaluation de scripts, la procédure Tcl_AddErrorInfo est appelée pour ajouter plus de texte à l'option -errorinfo décrivant l'instruction de commande qui était en cours d'exécution lorsque l'erreur s'est produite. Lorsque l'erreur a été retournée à l'application, le suivi complet des activités au moment où l'erreur s'est produite contiendra une pile complète.

Il est parfois utile d'ajouter des informations supplémentaires à l'option -errorinfo au-delà de ce que les procédures d'évaluation de scripts peuvent fournir. La procédure Tcl_AddErrorInfo peut être utilisée à cette fin : son argument message est une chaîne supplémentaire à ajouter à l'option -errorinfo. Par exemple, lorsqu'une erreur est générée pendant l'exécution de la commande source, la procédure Tcl_AddErrorInfo est appelée pour enregistrer le nom du fichier en cours de traitement et la ligne à laquelle l'erreur s'est produite. De même, lorsqu'une erreur est générée pendant l'évaluation d'une commande, la procédure Tcl_AddErrorInfo est appelée pour enregistrer les informations du fichier et de la ligne d'erreur.

La procédure Tcl_AppendObjToErrorInfo et Tcl_AddObjErrorInfo fournissent des interfaces pour ajouter des données sous forme d'objets Tcl à l'option -errorinfo. Cela est utile lorsque des informations complexes ou formatées sont à ajouter, et que l'on souhaite s'assurer que les représentations sous forme de chaîne de ces objets sont correctement formatées et ajoutées à la pile d'erreurs.

La procédure Tcl_SetObjErrorCode et Tcl_SetErrorCode sont utilisées pour définir l'option -errorcode. Comme mentionné précédemment, cette option est destinée à contenir des informations structurées sur l'erreur. Tcl_SetObjErrorCode accepte un objet Tcl qui deviendra la nouvelle valeur de l'option -errorcode. Tcl_SetErrorCode permet de construire l'option -errorcode en spécifiant une série de chaînes qui seront transformées en une liste d'objets Tcl. Le dernier argument doit être un pointeur NULL pour marquer la fin de la liste des éléments.

Tcl_SetErrorCodeVA est une variante de Tcl_SetErrorCode qui utilise une liste d'arguments de type va_list. Ceci est utile dans les situations où la liste des éléments d'erreur est déjà construite ou générée de manière dynamique.

La procédure Tcl_GetErrorLine récupère le numéro de ligne associé à la dernière erreur dans l'interpréteur. Ceci est souvent utilisé conjointement avec l'option -errorinfo pour fournir des informations de débogage plus précises. La procédure Tcl_SetErrorLine permet de définir explicitement ce numéro de ligne.

La procédure Tcl_PosixError est une fonction utilitaire qui prend un interpréteur et retourne un pointeur vers une chaîne décrivant l'erreur POSIX la plus récente qui s'est produite dans l'interpréteur. Si aucune erreur POSIX ne s'est produite, elle retourne NULL. Cette fonction est particulièrement utile lors de l'interfaçage avec des appels système POSIX.

La procédure Tcl_LogCommandInfo est utilisée pour enregistrer des informations sur une instruction qui est en cours d'exécution, dans le but d'être utilisé lors de la génération d'informations d'erreur. Les arguments script, command et commandLength spécifient la portée du script, l'instruction elle-même et sa longueur. Ces informations peuvent ensuite être utilisées par les mécanismes de gestion d'erreurs de Tcl pour construire des traces d'appels plus informatives.

DESCRIPTION

These procedures provide access to the return options of a Tcl interpreter. Return options are values that are returned by Tcl commands, and they can be retrieved by the caller of Tcl command procedures. The most common return option is the result of the command, but there are other options as well. The most important return options are -errorinfo and -errorcode. These options are used to provide detailed error information when a Tcl script encounters an error.

Tcl_GetReturnOptions returns a Tcl object containing a dictionary of all available return options. The keys of the dictionary are the option names (e.g., "-errorinfo", "-errorcode", "-errorline"), and the values are the corresponding option values. The result argument should be a pointer to a Tcl object that holds the result of the last command executed in the interpreter. This object is often obtained from the return value of a call to Tcl_EvalObj or Tcl_Eval.

Tcl_SetReturnOptions sets the return options for the interpreter. The options argument is a Tcl object containing a dictionary of option names and values. This procedure is typically called by Tcl built-in commands that need to set complex return options.

Tcl_AddErrorInfo adds a string to the interpreter's -errorinfo return option. This option typically contains a stack trace of Tcl procedures that were called. When an error occurs, the current procedure name and line number are added to the stack trace. The best time to call Tcl_AddErrorInfo is just after a script evaluation routine returns TCL_ERROR. The return option -errorline (retrieved by calling Tcl_GetReturnOptions) often forms a useful part of the message passed to Tcl_AddErrorInfo.

Tcl_AppendObjToErrorInfo is an alternative interface for the same functionality as Tcl_AddErrorInfo. Tcl_AppendObjToErrorInfo is called when the string value to append to the -errorinfo option is available as a Tcl_Obj instead of a C char array.

Tcl_AddObjErrorInfo is almost identical to Tcl_AddErrorInfo, except that it has an additional argument length. This allows the message string to contain embedded null bytes. This is essentially never a good idea. If the message needs to contain the null character U+0000, then the internal Tcl encoding rules should be used to avoid the need for a null character. If the Tcl_AddObjErrorInfo interface is used in any case, a negative value should be used for length.

The procedure Tcl_SetObjErrorCode is used to set the value of the -errorcode return option to the value errorObjPtr constructed by the caller. Tcl_SetObjErrorCode is generally invoked just before returning an error. If an error is returned without calling Tcl_SetObjErrorCode or Tcl_SetErrorCode, the Tcl interpreter automatically sets the value of the -errorcode return option to NONE.

The procedure Tcl_SetErrorCode is also used to set the value of the -errorcode return option. However, it takes one or more strings to log the value instead of a value. Otherwise, its behavior is similar to Tcl_SetObjErrorCode.

Tcl_SetErrorCodeVA is the same as Tcl_SetErrorCode except that it takes an argument list instead of a variable number of arguments.

The procedure Tcl_GetErrorLine is used to read the integer value of the -errorline return option without the overhead of a full call to Tcl_GetReturnOptions. Similarly, Tcl_SetErrorLine sets the value of the -errorline return option.

Tcl_PosixError sets the value of the -errorcode variable after a call to a POSIX system function. It writes the value of the C language errno variable and calls Tcl_SetErrorCode to set the value of the -errorcode return option to the POSIX format. The caller must have previously called Tcl_SetErrno to set errno; this is necessary on some operating systems (e.g., Windows) where Tcl is linked to a shared library as part of an application, or when the error occurs in a dynamically loaded extension. See the Tcl_SetErrno manual entry for more information.

Tcl_PosixError returns a human-readable diagnostic message for the error (this is the same value that will appear as the third element in the -errorcode option value). It may be convenient to include this string as part of the error message returned to the application in the interpreter's result.

Tcl_LogCommandInfo is invoked after an error in the interpreter. It adds information about the command that was executing when the error occurred to the -errorinfo option value, and the line number internally stored in the interpreter is set.

In older versions of Tcl, the Tcl_GetReturnOptions routine did not exist. Instead, the global variables errorInfo and errorCode were the only places where error information could be retrieved. Much existing code written for older versions of Tcl still accesses this information through these global variables.

It is important to recognize that although reading these global variables is still a supported method for accessing these return option values, it is important not to assume that writing to these global variables will correctly set the corresponding option values. It has long been emphasized in this manual page that it is important to call the procedures described here instead of directly setting errorInfo or errorCode with Tcl_ObjSetVar2.

If the procedure Tcl_ResetResult is called, it clears all interpreter state associated with script evaluation, including the entire dictionary of return options. In particular, the -errorinfo and -errorcode options are reset. If an error had occurred, the call to Tcl_ResetResult will remove the error state so that it appears as if no error had occurred after all. The global variables errorInfo and errorCode are not modified by Tcl_ResetResult and continue to hold a record of information about the most recent error in the interpreter.

DESCRIPTION

Ces procédures fournissent l'accès aux options de retour d'un interpréteur Tcl. Les options de retour sont des valeurs qui sont retournées par les commandes Tcl, et elles peuvent être récupérées par l'appelant des procédures de commande Tcl. L'option de retour la plus courante est le résultat de la commande, mais il existe d'autres options. Les options de retour les plus importantes sont -errorinfo et -errorcode. Ces options sont utilisées pour fournir des informations d'erreur détaillées lorsqu'un script Tcl rencontre une erreur.

Tcl_GetReturnOptions retourne un objet Tcl contenant un dictionnaire de toutes les options de retour disponibles. Les clés du dictionnaire sont les noms des options (par exemple, "-errorinfo", "-errorcode", "-errorline"), et les valeurs sont les valeurs correspondantes des options. L'argument result doit être un pointeur vers un objet Tcl qui contient le résultat de la dernière commande exécutée dans l'interpréteur. Cet objet est souvent obtenu à partir de la valeur de retour d'un appel à Tcl_EvalObj ou Tcl_Eval.

Tcl_SetReturnOptions définit les options de retour pour l'interpréteur. L'argument options est un objet Tcl contenant un dictionnaire de noms et de valeurs d'options. Cette procédure est généralement appelée par les commandes intégrées Tcl qui ont besoin de définir des options de retour complexes.

Tcl_AddErrorInfo ajoute une chaîne à l'option de retour -errorinfo de l'interpréteur. Cette option contient généralement une trace de la pile des procédures Tcl qui ont été appelées. Lorsqu'une erreur se produit, le nom de la procédure actuelle et le numéro de ligne sont ajoutés à la trace de la pile. Le meilleur moment pour appeler Tcl_AddErrorInfo est juste après qu'une routine d'évaluation de script retourne TCL_ERROR. La valeur de retour de l'option -errorline (récupérée en appelant Tcl_GetReturnOptions) forme souvent une partie utile du message passé à Tcl_AddErrorInfo.

Tcl_AppendObjToErrorInfo est une interface alternative pour la même fonctionnalité que Tcl_AddErrorInfo. Tcl_AppendObjToErrorInfo est appelée lorsque la valeur de chaîne à ajouter à l'option -errorinfo est disponible sous forme de Tcl_Obj au lieu d'un tableau char C.

Tcl_AddObjErrorInfo est presque identique à Tcl_AddErrorInfo, sauf qu'elle a un argument supplémentaire length. Cela permet à la chaîne message de contenir des octets nuls intégrés. Ce n'est pratiquement jamais une bonne idée. Si le message doit contenir le caractère nul U+0000, alors les règles de codage internes de Tcl doivent être utilisées pour éviter le besoin d'un caractère nul. Si l'interface Tcl_AddObjErrorInfo est utilisée dans tous les cas, une valeur négative doit être utilisée pour length.

La procédure Tcl_SetObjErrorCode est utilisée pour définir la valeur de l'option de retour -errorcode à la valeur errorObjPtr construite par l'appelant. Tcl_SetObjErrorCode est généralement invoquée juste avant de retourner une erreur. Si une erreur est retournée sans appeler Tcl_SetObjErrorCode ou Tcl_SetErrorCode, l'interpréteur Tcl définit automatiquement la valeur de l'option de retour -errorcode sur NONE.

La procédure Tcl_SetErrorCode est également utilisée pour définir la valeur de l'option de retour -errorcode. Cependant, elle prend une ou plusieurs chaînes pour enregistrer la valeur au lieu d'une valeur. Sinon, son comportement est similaire à celui de Tcl_SetObjErrorCode.

Tcl_SetErrorCodeVA est identique à Tcl_SetErrorCode sauf qu'elle prend une liste d'arguments au lieu d'un nombre variable d'arguments.

La procédure Tcl_GetErrorLine est utilisée pour lire la valeur entière de l'option de retour -errorline sans la surcharge d'un appel complet à Tcl_GetReturnOptions. De même, Tcl_SetErrorLine définit la valeur de l'option de retour -errorline.

Tcl_PosixError définit la valeur de la variable -errorcode après un appel à une fonction système POSIX. Elle écrit la valeur de la variable errno du langage C et appelle Tcl_SetErrorCode pour définir la valeur de l'option de retour -errorcode au format POSIX. L'appelant doit avoir précédemment appelé Tcl_SetErrno pour définir errno ; ceci est nécessaire sur certains systèmes d'exploitation (par exemple, Windows) où Tcl est lié à une bibliothèque partagée dans le cadre d'une application, ou lorsque l'erreur se produit dans une extension chargée dynamiquement. Voir l'entrée du manuel de Tcl_SetErrno pour plus d'informations.

Tcl_PosixError retourne un message de diagnostic lisible par l'homme pour l'erreur (c'est la même valeur qui apparaîtra comme troisième élément dans la valeur de l'option -errorcode). Il peut être pratique d'inclure cette chaîne comme partie du message d'erreur retourné à l'application dans le résultat de l'interpréteur.

Tcl_LogCommandInfo est invoqué après une erreur dans l'interpréteur. Il ajoute des informations sur la commande qui était en cours d'exécution lorsque l'erreur s'est produite à la valeur de l'option -errorinfo, et le numéro de ligne stocké en interne dans l'interpréteur est défini.

Dans les anciennes versions de Tcl, la routine Tcl_GetReturnOptions n'existait pas. Au lieu de cela, les variables globales errorInfo et errorCode étaient les seuls endroits où les informations d'erreur pouvaient être récupérées. De nombreux codes existants écrits pour d'anciennes versions de Tcl accèdent encore à ces informations via ces variables globales.

Il est important de reconnaître que bien que la lecture de ces variables globales soit toujours une méthode prise en charge pour accéder à ces valeurs d'options de retour, il est important de ne pas supposer que l'écriture dans ces variables globales définira correctement les valeurs d'options correspondantes. Il a longtemps été souligné dans cette page de manuel qu'il est important d'appeler les procédures décrites ici au lieu de définir directement errorInfo ou errorCode avec Tcl_ObjSetVar2.

Si la procédure Tcl_ResetResult est appelée, elle efface tout l'état de l'interpréteur associé à l'évaluation de scripts, y compris le dictionnaire complet des options de retour. En particulier, les options -errorinfo et -errorcode sont réinitialisées. Si une erreur s'était produite, l'appel à Tcl_ResetResult supprimera l'état d'erreur de sorte qu'il apparaisse comme si aucune erreur ne s'était produite après tout. Les variables globales errorInfo et errorCode ne sont pas modifiées par Tcl_ResetResult et continuent de conserver un enregistrement des informations sur la dernière erreur dans l'interpréteur.
