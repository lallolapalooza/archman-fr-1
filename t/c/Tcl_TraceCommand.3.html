NOM

Tcl_CommandTraceInfo, Tcl_TraceCommand, Tcl_UntraceCommand - surveiller les renommages et suppressions d'une commande

SYNTAXE

#include <tcl.h>

ClientData
Tcl_CommandTraceInfo(interp, cmdName, flags, proc, prevClientData)

int
Tcl_TraceCommand(interp, cmdName, flags, proc, clientData)

void
Tcl_UntraceCommand(interp, cmdName, flags, proc, clientData)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur contenant la commande.
const char *cmdName (entrée)
Nom de la commande.
int flags (entrée)
Collection OR des valeurs TCL_TRACE_RENAME et TCL_TRACE_DELETE.
Tcl_CommandTraceProc *proc (entrée)
Procédure à appeler lorsque les opérations spécifiées se produisent sur cmdName.
ClientData clientData (entrée)
Argument arbitraire à passer à proc.
ClientData prevClientData (entrée)
Si non NULL, donne la dernière valeur retournée par Tcl_CommandTraceInfo, donc cet appel retournera des informations sur le prochain trace. Si NULL, cet appel retournera des informations sur le premier trace.

DESCRIPTION

Tcl_TraceCommand permet à une procédure C de surveiller les opérations effectuées sur une commande Tcl, de sorte que la procédure C soit invoquée chaque fois que la commande est renommée ou supprimée. Si le trace est créé avec succès, Tcl_TraceCommand retourne TCL_OK. Si une erreur se produit (par exemple, cmdName spécifie une commande inexistante), TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de l'interpréteur.

L'argument flags de Tcl_TraceCommand indique quand la procédure de trace doit être invoquée. Il se compose d'une combinaison OR de n'importe laquelle des valeurs suivantes :

TCL_TRACE_RENAME
Invoque proc chaque fois que la commande est renommée.
TCL_TRACE_DELETE
Invoque proc lorsque la commande est supprimée.

Chaque fois qu'une des opérations spécifiées se produit sur la commande, proc sera invoqué. Elle doit avoir des arguments et un résultat qui correspondent au type Tcl_CommandTraceProc :

typedef void Tcl_CommandTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *oldName,
        const char *newName,
        int flags);

Les paramètres clientData et interp auront les mêmes valeurs que celles passées à Tcl_TraceCommand lors de la création du trace. ClientData pointe généralement vers une structure de données spécifique à l'application qui décrit ce qu'il faut faire lorsque proc est invoqué. OldName donne le nom de la commande en cours de renommage, et newName donne le nom auquel la commande est renommée (ou NULL lors de la suppression de la commande). Flags est une combinaison OR de bits fournissant potentiellement plusieurs informations. Un des bits TCL_TRACE_RENAME et TCL_TRACE_DELETE sera défini dans flags pour indiquer quelle opération est effectuée sur la commande. Le bit TCL_TRACE_DESTROYED sera défini dans flags si le trace est sur le point d'être détruit ; cette information peut être utile à proc pour qu'elle puisse nettoyer ses propres structures de données internes (voir la section TCL_TRACE_DESTROYED ci-dessous pour plus de détails). Étant donné que la suppression des commandes peut avoir lieu dans le cadre de la suppression de l'interpréteur qui les contient, proc doit faire attention à vérifier ce que la valeur interp passée peut être appelée à faire. La routine Tcl_InterpDeleted est un outil important à cet égard. Lorsque Tcl_InterpDeleted retourne 1, proc ne pourra pas invoquer de scripts dans interp. La fonction de proc dans ce cas est limitée au nettoyage de ses propres structures de données.

Tcl_UntraceCommand peut être utilisé pour supprimer un trace. Si la commande spécifiée par interp, cmdName, et flags a un trace défini avec flags, proc, et clientData, alors le trace correspondant est supprimé. Si aucun trace de ce type n'existe, alors l'appel à Tcl_UntraceCommand n'a aucun effet. Les mêmes bits sont valides pour flags que pour les appels à Tcl_TraceCommand.

Tcl_CommandTraceInfo peut être utilisé pour récupérer des informations sur les traces définis sur une commande donnée. La valeur de retour de Tcl_CommandTraceInfo est le clientData associé à un trace particulier. Le trace doit être sur la commande spécifiée par les arguments interp, cmdName, et flags (notez que les flags sont actuellement ignorés ; flags doit être défini à 0 pour la compatibilité future) et sa procédure de trace doit être identique à l'argument proc. Si l'argument prevClientData est NULL, alors la valeur de retour correspond au premier trace correspondant (le plus récemment créé), ou NULL s'il n'y a pas de traces correspondants. Si l'argument prevClientData n'est pas NULL, alors il doit s'agir de la valeur de retour d'un appel précédent à Tcl_CommandTraceInfo. Dans ce cas, la nouvelle valeur de retour correspondra au prochain trace correspondant après celui dont clientData correspond à prevClientData, ou NULL si aucun trace ne correspond à prevClientData ou s'il n'y a plus de traces correspondants après lui. Ce mécanisme permet de parcourir tous les traces d'une commande donnée qui ont le même proc.

APPEL DES COMMANDES PENDANT LES TRACES

Pendant les traces de renommage, la commande renommée est visible avec les deux noms simultanément, et la commande existe toujours pendant les traces de suppression, sauf si l'interpréteur qui la contient est en cours de suppression. Cependant, il n'existe aucun mécanisme pour signaler qu'une erreur s'est produite dans une procédure de trace, donc une grande prudence doit être exercée pour que les erreurs ne soient pas perdues silencieusement.

MULTIPLE TRACES

Il est possible que plusieurs traces existent sur la même commande. Lorsque cela se produit, toutes les procédures de trace seront invoquées à chaque accès, dans l'ordre du plus récemment créé au moins récemment créé. Les tentatives de suppression de la commande pendant un trace de suppression échoueront silencieusement, car la commande est déjà prévue pour être supprimée de toute façon. Si la commande renommée est renommée par l'un de ses traces de renommage, ce renommage a la priorité sur celui qui a déclenché le trace et l'ensemble des traces ne sera pas réexécuté ; si plusieurs traces renomment la commande, le dernier renommage a la priorité.

FLAG TCL_TRACE_DESTROYED

Dans un rappel de suppression à proc, le bit TCL_TRACE_DESTROYED est défini dans flags.

MOTS CLÉS

clientData, trace, commande

NAME

Tcl_TraceCommand - establish a trace on a Tcl command

SYNOPSIS

#include <tcl.h>
int
Tcl_TraceCommand(interp, script, level, traceProc, clientData);

DESCRIPTION

Tcl_TraceCommand establishes a trace on the command named script. A trace is a callback mechanism that allows code to be executed whenever a command is invoked or destroyed. This can be useful for debugging, profiling, or implementing command wrappers.

When the command named script is invoked, the procedure traceProc will be called. The traceProc will receive the clientData associated with the trace and the interpreter interp. The level argument specifies the nesting level at which the trace should be active. A level of 0 means the trace is always active. Higher levels correspond to nested evaluations (e.g., within procedure calls).

When the command named script is destroyed (e.g., if the procedure defining it is deleted), the traceProc will be called with a special flag indicating that the command is being destroyed. This allows for cleanup of any associated resources.

ARGUMENTS

  • Tcl_Interp *interp: The interpreter in which to establish the trace.
  • const char *script: The name of the command to trace.
  • int level: The nesting level at which the trace should be active. 0 for always active.
  • Tcl_TraceProc *traceProc: The procedure to call when the command is invoked or destroyed.
  • ClientData clientData: Arbitrary data to pass to traceProc.

TCL_TRACE_DESTROYED FLAG

When the command is destroyed, the traceProc is called with a special value for the level argument, indicating that the trace is being removed because the command is being destroyed. This value is TCL_TRACE_DESTROYED.

KEYWORDS

trace, command, callback, debug

NOM

Tcl_TraceCommand - établir une trace sur une commande Tcl

SYNOPSIS

#include <tcl.h>
int
Tcl_TraceCommand(interp, script, level, traceProc, clientData);

DESCRIPTION

Tcl_TraceCommand établit une trace sur la commande nommée script. Une trace est un mécanisme de rappel qui permet d'exécuter du code chaque fois qu'une commande est invoquée ou détruite. Cela peut être utile pour le débogage, le profilage ou l'implémentation d'enveloppes de commande.

Lorsque la commande nommée script est invoquée, la procédure traceProc sera appelée. La traceProc recevra les clientData associés à la trace et l'interpréteur interp. L'argument level spécifie le niveau d'imbrication auquel la trace doit être active. Un niveau de 0 signifie que la trace est toujours active. Les niveaux supérieurs correspondent aux évaluations imbriquées (par exemple, dans les appels de procédure).

Lorsque la commande nommée script est détruite (par exemple, si la procédure qui la définit est supprimée), la traceProc sera appelée avec un indicateur spécial indiquant que la commande est en cours de destruction. Cela permet le nettoyage de toutes les ressources associées.

ARGUMENTS

  • Tcl_Interp *interp: L'interpréteur dans lequel établir la trace.
  • const char *script: Le nom de la commande à tracer.
  • int level: Le niveau d'imbrication auquel la trace doit être active. 0 pour toujours actif.
  • Tcl_TraceProc *traceProc: La procédure à appeler lorsque la commande est invoquée ou détruite.
  • ClientData clientData: Données arbitraires à passer à traceProc.

FLAG TCL_TRACE_DESTROYED

Lorsque la commande est détruite, la traceProc est appelée avec une valeur spéciale pour l'argument level, indiquant que la trace est supprimée car la commande est détruite. Cette valeur est TCL_TRACE_DESTROYED.

MOTS-CLÉS

trace, commande, rappel, débogage
