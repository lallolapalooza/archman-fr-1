Longueur de src ou tsrc en octets. Si la longueur est négative, la longueur spécifique à l'encodage de la chaîne est utilisée.
Tcl_DString *dstPtr (out)
Pointeur vers une Tcl_DString non initialisée ou libérée dans laquelle le résultat converti sera stocké.
int flags (in)
Divers bits de drapeau mis en OR. TCL_ENCODING_START signifie que le tampon source est le premier bloc d'un flux d'entrée (potentiellement en plusieurs blocs), indiquant à la routine de conversion de revenir à un état initial et d'effectuer toute initialisation nécessaire avant la conversion du premier octet. TCL_ENCODING_END signifie que le tampon source est le dernier bloc d'un flux d'entrée (potentiellement en plusieurs blocs), indiquant à la routine de conversion d'effectuer toute finalisation nécessaire après la conversion du dernier octet, puis de revenir à un état initial. TCL_ENCODING_STOPONERROR signifie que la routine de conversion doit retourner immédiatement après avoir lu un caractère source qui n'existe pas dans l'encodage cible ; sinon, un caractère de substitution par défaut sera automatiquement substitué.
Tcl_EncodingState *statePtr (in/out)
Utilisé lors de la conversion d'un flux d'octets (généralement long ou de longueur indéfinie) pièce par pièce. La routine de conversion stocke son état actuel dans *statePtr après la conversion de src (le tampon contenant la pièce actuelle) ; ces informations d'état doivent être renvoyées lors de la conversion de la pièce suivante du flux afin que la routine de conversion sache dans quel état elle s'est arrêtée à la fin de la dernière pièce. Peut être NULL, auquel cas la valeur spécifiée pour flags est ignorée et le tampon source est supposé contenir la chaîne complète à convertir.

Tampon dans lequel le résultat converti sera stocké. Pas plus de dstLen octets seront stockés dans dst.
int dstLen (in)
La longueur maximale du tampon de sortie dst en octets.

Rempli avec le nombre d'octets de src qui ont été réellement convertis. Cela peut être inférieur à la longueur source d'origine s'il y a eu un problème de conversion de certains caractères sources. Peut être NULL.

Rempli avec le nombre d'octets qui ont été réellement stockés dans le tampon de sortie à la suite de la conversion. Peut être NULL.

INTRODUCTION

Ces routines convertissent entre la représentation interne des caractères de Tcl, UTF-8, et les représentations de caractères utilisées par divers systèmes d'exploitation ou systèmes de fichiers, tels que Unicode, ASCII ou Shift-JIS. Lors de l'opération sur des chaînes, comme l'obtention des noms de fichiers ou l'affichage de caractères à l'aide de polices internationales, les chaînes doivent être traduites dans un ou potentiellement plusieurs formats que les différents appels système peuvent utiliser. Par exemple, sur une station de travail Unix japonaise, un utilisateur pourrait obtenir un nom de fichier représenté dans l'encodage de fichier EUC-JP, puis traduire les caractères dans l'encodage de police jisx0208 afin d'afficher le nom de fichier dans un widget Tk. Le but du package d'encodage est d'aider à combler l'écart de traduction. UTF-8 fournit une zone de transit intermédiaire pour tous les différents encodages. Dans l'exemple ci-dessus, le texte serait traduit en UTF-8 à partir de l'encodage de fichier que le système d'exploitation utilise. Ensuite, il serait traduit de l'UTF-8 vers l'encodage de police requis par les routines d'affichage.

Certains encodages de base sont intégrés à Tcl. D'autres peuvent être définis par l'utilisateur ou chargés dynamiquement à partir de fichiers d'encodage d'une manière indépendante de la plateforme.

DESCRIPTION

Tcl_GetEncoding trouve un encodage donné par son name. Le nom peut faire référence à un encodage Tcl intégré, à un encodage défini par l'utilisateur enregistré en appelant Tcl_CreateEncoding, ou à un fichier d'encodage chargeable dynamiquement. La valeur de retour est un jeton qui représente l'encodage et peut être utilisé dans des appels ultérieurs à des procédures telles que Tcl_GetEncodingName, Tcl_FreeEncoding et Tcl_UtfToExternal. Si le nom ne fait référence à aucun encodage connu ou chargeable, NULL est retourné et un message d'erreur est retourné dans interp.

Le package d'encodage maintient une base de données de tous les encodages actuellement en cours d'utilisation. La première fois que name est vu, Tcl_GetEncoding retourne un encodage avec un compteur de références de 1. Si le même name est demandé plusieurs fois, le compteur de références pour cet encodage est incrémenté sans la surcharge de l'allocation d'un nouvel encodage et de toutes ses structures de données associées.

Lorsqu'un encoding n'est plus nécessaire, Tcl_FreeEncoding doit être appelé pour le libérer. Lorsqu'un encoding n'est plus utilisé nulle part (c'est-à-dire qu'il a été libéré autant de fois qu'il a été obtenu), Tcl_FreeEncoding libérera tout l'espace utilisé par l'encodage et le supprimera de la base de données.

Tcl_GetEncodingFromObj traite la représentation sous forme de chaîne de objPtr comme un nom d'encodage, et trouve un encodage avec ce nom, tout comme le fait Tcl_GetEncoding. Tcl_ExternalToUtfDString convertit un tampon source src de l'encodage spécifié encoding en UTF-8. Les octets convertis sont stockés dans dstPtr, qui est terminé par un caractère nul. L'appelant doit éventuellement appeler Tcl_DStringFree pour libérer toute information stockée dans dstPtr. Lors de la conversion, si un des caractères du tampon source ne peut être représenté dans l'encodage cible, un caractère de remplacement par défaut sera utilisé. La valeur de retour est un pointeur vers la valeur stockée dans le DString.

Tcl_ExternalToUtf convertit un tampon source src de l'encodage spécifié encoding en UTF-8. Plus de srcLen octets sont convertis à partir du tampon source et stockés jusqu'à dstLen octets dans dst. Dans tous les cas, *srcReadPtr est rempli avec le nombre d'octets qui ont été convertis à partir de src et *dstWrotePtr est rempli avec le nombre correspondant d'octets stockés dans dst. La valeur de retour est l'un des éléments suivants :

TCL_OK
Tout le contenu de src a été converti.
TCL_CONVERT_NOSPACE
Le tampon de destination n'était pas assez grand pour toutes les données converties ; autant de caractères que possible ont été convertis.
TCL_CONVERT_MULTIBYTE
Les derniers octets du tampon source étaient le début d'une séquence multi-octets, mais plus d'octets étaient nécessaires pour compléter cette séquence. Un appel ultérieur à la routine de conversion doit passer un tampon contenant les octets non convertis restants de src plus quelques octets supplémentaires de la source pour convertir correctement la séquence multi-octets qui a été coupée.
TCL_CONVERT_SYNTAX
Le tampon source contenait une séquence de caractères invalide. Cela peut se produire si le flux d'entrée a été corrompu ou si la méthode d'encodage de l'entrée a été mal identifiée.
TCL_CONVERT_UNKNOWN
Le tampon source contenait un caractère qui ne pouvait pas être représenté dans l'encodage cible et TCL_ENCODING_STOPONERROR a été spécifié.

Tcl_UtfToExternalDString convertit un tampon source src d'UTF-8 en l'encodage spécifié encoding. Les octets convertis sont stockés dans dstPtr, qui est terminé par le caractère nul spécifique à l'encodage. L'appelant doit éventuellement appeler Tcl_DStringFree pour libérer toute information stockée dans dstPtr. Lors de la conversion, si un des caractères du tampon source ne peut être représenté dans l'encodage cible, un caractère de remplacement par défaut sera utilisé. La valeur de retour est un pointeur vers la valeur stockée dans le DString.

Tcl_UtfToExternal convertit un tampon source src d'UTF-8 en l'encodage spécifié encoding. Plus de srcLen octets sont convertis à partir du tampon source et stockés jusqu'à dstLen octets dans dst. Dans tous les cas, *srcReadPtr est rempli avec le nombre d'octets qui ont été convertis à partir de src et *dstWrotePtr est rempli avec le nombre correspondant d'octets stockés dans dst. Les valeurs de retour sont les mêmes que celles de Tcl_ExternalToUtf.

Tcl_WinUtfToTChar et Tcl_WinTCharToUtf sont des fonctions de commodité pour convertir entre UTF-8 et des chaînes Windows basées sur le type TCHAR, qui par convention est un caractère Unicode sous Windows NT.

Tcl_GetEncodingName est approximativement l'inverse de Tcl_GetEncoding. Étant donné un encoding, la valeur renvoyée est l'argument name qui a été utilisé pour créer l'encodage. La chaîne renvoyée par Tcl_GetEncodingName n'est garantie de persister que jusqu'à ce que l'encoding soit supprimé. L'appelant ne doit pas modifier cette chaîne.

Tcl_SetSystemEncoding définit l'encodage par défaut qui doit être utilisé lorsque l'utilisateur passe une valeur nulle pour l'argument encoding à toute fonction d'encodage. Si name est nulle, l'encodage système est réinitialisé à l'encodage par défaut du système, binary. Si le nom ne fait pas référence à un encodage connu ou chargeable, TCL_ERROR est renvoyé et un message d'erreur est laissé dans interp. Sinon, cette procédure incrémente le compteur de références du nouveau système d'encodage, décrémente le compteur de références de l'ancien système d'encodage et renvoie TCL_OK.

Tcl_GetEncodingNameFromEnvironment fournit un moyen pour la bibliothèque Tcl de rapporter le nom de l'encodage qu'elle pense être correct pour être l'encodage système, basé sur des appels système et un examen de l'environnement approprié à la plateforme. Elle accepte bufPtr, un pointeur vers un tampon Tcl_DString initialisé ou libéré, et y écrit le nom de l'encodage. La valeur renvoyée est Tcl_DStringValue.

Tcl_GetEncodingNames définit le résultat interp en une liste contenant les noms de tous les encodages définis ou chargeables dynamiquement, en recherchant dans le répertoire d'encodage spécifié par Tcl_SetDefaultEncodingDir. Cette procédure ne garantit pas que les fichiers chargeables dynamiquement contiennent des données valides, mais seulement qu'ils existent.

Tcl_CreateEncoding définit un nouvel encodage et enregistre les procédures C qui sont appelées pour convertir entre cet encodage et UTF-8. Les encodages créés par Tcl_CreateEncoding sont ensuite visibles dans le répertoire utilisé par Tcl_GetEncoding. Comme avec Tcl_GetEncoding, la valeur renvoyée est un jeton représentant l'encodage et peut être utilisée dans des appels ultérieurs à d'autres fonctions d'encodage. Tcl_CreateEncoding renvoie un encodage avec un compteur de références de 1. Si un encodage avec le nom spécifié existe déjà, son enregistrement dans le répertoire est remplacé par le nouvel encodage ; le jeton de l'ancien restera valide et continuera à se comporter comme avant, mais les utilisateurs du nouveau jeton appelleront désormais les procédures du nouvel encodage.

L'argument typePtr de Tcl_CreateEncoding contient des informations sur le nom de l'encodage et les procédures qui seront appelées pour convertir entre cet encodage et UTF-8. Il est défini comme suit :

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

Le champ encodingName fournit un nom pour l'encodage, par lequel il peut être référencé dans des procédures telles que Tcl_GetEncoding. Le champ toUtfProc fait référence à une procédure de rappel à invoquer pour convertir du texte de cet encodage en UTF-8. Le champ fromUtfProc fait référence à une procédure de rappel à invoquer pour convertir du texte d'UTF-8 en cet encodage. Le champ freeProc fait référence à une procédure de rappel à invoquer lorsque cet encodage est supprimé. Le champ freeProc peut être nul. Le champ clientData contient une valeur arbitraire d'un mot qui est passée à toUtfProc, fromUtfProc et freeProc lorsqu'elles sont appelées. Généralement, il s'agit d'un pointeur vers une structure contenant des informations spécifiques à l'encodage qui peuvent être utilisées par les procédures de rappel. Par exemple, deux encodages très similaires comme ascii et macRoman peuvent utiliser la même procédure de rappel, mais utilisent différentes valeurs de clientData pour contrôler leur comportement. Le champ nullSize spécifie le nombre d'octets nuls qui signifient la fin de chaîne dans cet encodage. Il doit être de 1 (pour les encodages d'un ou plusieurs octets comme ASCII ou Shift-JIS) ou 2 (pour les encodages à deux octets comme Unicode). Les encodages constants avec 3 octets ou plus par caractère (comme CNS11643) ne sont pas acceptés.

Les procédures de rappel toUtfProc et fromUtfProc doivent correspondre au type Tcl_EncodingConvertProc :

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

Les procédures de rappel toUtfProc et fromUtfProc sont appelées par Tcl_ExternalToUtf ou Tcl_UtfToExternal pour effectuer la conversion réelle. Le paramètre clientData de ces procédures est le même que le clientData spécifié dans Tcl_CreateEncoding lors de la création de l'encodage. Les arguments restants aux procédures de rappel sont les mêmes que les arguments, documentés ci-dessus, de Tcl_ExternalToUtf ou Tcl_UtfToExternal, avec les exceptions suivantes. Si l'argument srcLen de l'une de ces fonctions de haut niveau est négatif, la valeur transmise à la procédure de rappel sera la longueur appropriée de l'encodage de src. Si l'un des arguments srcReadPtr, dstWrotePtr ou dstCharsPtr de l'une de ces fonctions de haut niveau est nul, la valeur correspondante transmise à la procédure de rappel sera un emplacement non nul.

La procédure de rappel freeProc, si elle n'est pas nulle, doit correspondre au type Tcl_EncodingFreeProc :

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

Cette fonction freeProc est appelée lorsque l'encodage est supprimé. Le paramètre clientData est le même que le clientData spécifié dans Tcl_CreateEncoding lors de la création de l'encodage.

Tcl_GetEncodingSearchPath et Tcl_SetEncodingSearchPath sont appelés pour accéder et configurer la liste des répertoires de fichiers de données d'encodage. La valeur renvoyée par Tcl_GetEncodingSearchPath est la valeur stockée par le dernier appel réussi à Tcl_SetEncodingSearchPath. Si aucun appel à Tcl_SetEncodingSearchPath n'a été effectué, Tcl calculera une valeur initiale basée sur l'environnement. Il existe un chemin de recherche d'encodage pour l'ensemble du processus, partagé par tous les threads du processus.

INTRODUCTION

Tcl has built-in support for a number of different character encodings. This manual page describes the C API for accessing and managing these encodings.

DESCRIPTION

Tcl_GetEncodingNames returns a table of strings containing the names of all encodings that are currently available for loading. The list is NULL-terminated. The names may be used as arguments to Tcl_GetEncoding.

Tcl_GetEncoding loads and returns a handle for the encoding named name. The name is case-insensitive. If the encoding is not already loaded, Tcl will attempt to load it by looking for a file named name.enc in the directories specified by the Tcl_GetEncodingSearchPath and Tcl_GetDefaultEncodingDir mechanisms. If the encoding cannot be loaded, Tcl_GetEncoding returns NULL and leaves an error message in interp.

Tcl_FreeEncoding releases the handle encoding. It is important to call this function when an encoding handle is no longer needed, to free up resources.

Tcl_GetEncodingSearchPath returns the current search path for encoding files. This is a NULL-terminated array of strings, where each string is the name of a directory. The caller should not modify the returned value; if modifications are needed, the caller should copy the list and use Tcl_SetEncodingSearchPath.

Tcl_SetEncodingSearchPath sets the search path for encoding files to path. This is a NULL-terminated array of strings. Tcl makes its own copy of the path, so the caller does not need to preserve the path argument after the call returns. The path may contain directories that do not exist or are not readable; these will be silently ignored by Tcl when searching for encoding files. It is recommended that the search path should end with a directory that holds the core Tcl encodings, and then be followed by user-defined encoding directories.

The following are obsolete interfaces:

Tcl_GetDefaultEncodingDir and Tcl_SetDefaultEncodingDir are obsolete interfaces best replaced with calls to Tcl_GetEncodingSearchPath and Tcl_SetEncodingSearchPath. They are called to access and set the first element of the searchPath list. Since Tcl searches searchPath for encoding data files in list order, these routines establish the “default” directory in which to find encoding data files.

ENCODING FILES

Space would prohibit precompiling into Tcl every possible encoding algorithm, so many encodings are stored on disk as dynamically-loadable encoding files. This behavior also allows the user to create additional encoding files that can be loaded using the same mechanism. These encoding files contain information about the tables and/or escape sequences used to map between an external encoding and Unicode. The external encoding may consist of single-byte, multi-byte, or double-byte characters.

Each dynamically-loadable encoding is represented as a text file. The initial line of the file, beginning with a “#” symbol, is a comment that provides a human-readable description of the file. The next line identifies the type of encoding file. It can be one of the following letters:

[1] S
A single-byte encoding, where one character is always one byte long in the encoding. An example is iso8859-1, used by many European languages.
[2] D
A double-byte encoding, where one character is always two bytes long in the encoding. An example is big5, used for Chinese text.
[3] M
A multi-byte encoding, where one character may be either one or two bytes long. Certain bytes are lead bytes, indicating that another byte must follow and that together the two bytes represent one character. Other bytes are not lead bytes and represent themselves. An example is shiftjis, used by many Japanese computers.
[4] E
An escape-sequence encoding, specifying that certain sequences of bytes do not represent characters, but commands that describe how following bytes should be interpreted.

The rest of the lines in the file depend on the type.

The third line of the file is three numbers. The first number is the fallback character (in base 16) to use when converting from UTF-8 to this encoding. The second number is a 1 if this file represents the encoding for a symbol font, or 0 otherwise. The last number (in base 10) is how many pages of data follow.

Subsequent lines in the example above are pages that describe how to map from the encoding into 2-byte Unicode. The first line in a page identifies the page number. Following it are 256 double-byte numbers, arranged as 16 rows of 16 numbers. Given a character in the encoding, the high byte of that character is used to select which page, and the low byte of that character is used as an index to select one of the double-byte numbers in that page - the value obtained being the corresponding Unicode character. By examination of the example above, one can see that the characters 0x7E and 0x8163 in shiftjis map to 203E and 2026 in Unicode, respectively.

Following the first page will be all the other pages, each in the same format as the first: one number identifying the page followed by 256 double-byte Unicode characters. If a character in the encoding maps to the Unicode character 0000, it means that the character does not actually exist. If all characters on a page would map to 0000, that page can be omitted.

Case [4] is the escape-sequence encoding file. The lines in an this type of file are in the same format as this example taken from the iso2022-jp encoding:

# Encoding file: iso2022-jp, escape-driven
E
init		{}
final		{}
iso8859-1	\x1b(B
jis0201		\x1b(J
jis0208		\x1b$@
jis0208		\x1b$B
jis0212		\x1b$(D
gb2312		\x1b$A
ksc5601		\x1b$(C

In the file, the first column represents an option and the second column is the associated value. init is a string to emit or expect before the first character is converted, while final is a string to emit or expect after the last character. All other options are names of table-based encodings; the associated value is the escape-sequence that marks that encoding. Tcl syntax is used for the values; in the above example, for instance, “{}” represents the empty string and “\x1b” represents character 27.

When Tcl_GetEncoding encounters an encoding name that has not been loaded, it attempts to load an encoding file called name.enc from the encoding subdirectory of each directory that Tcl searches for its script library. If the encoding file exists, but is malformed, an error message will be left in interp.
