ARGUMENTS

Tcl_Interp *interp (en)
Utilisé pour le rapport d'erreurs et pour rechercher un canal enregistré dans celui-ci.
const char *fileName (en)
Le nom d'un fichier local ou réseau.
const char *mode (en)
Spécifie comment le fichier doit être accédé. Peut avoir l'une des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (en)
Indicateurs de permission de style POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront définies sur le fichier créé.
int argc (en)
Le nombre d'éléments dans argv.
const char **argv (en)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans commutateur de la commande Tcl exec.
int flags (en)
Spécifie la disposition des descripteurs stdio dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, l'entrée standard du premier processus enfant du pipeline est le canal de tuyau, sinon elle est identique à l'entrée standard du processus appelant ; idem pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, alors le tuyau peut rediriger les descripteurs stdio pour outrepasser les descripteurs stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, de telles redirections provoquent une erreur.
ClientData handle (en)
Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, il s'agit d'un descripteur de fichier, pour Windows, il s'agit d'un HANDLE.
int readOrWrite (en)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (en)
Le nom du canal.

Un pointeur vers une valeur Tcl dans laquelle stocker les caractères lus du canal.
int charsToRead (en)
Le nombre de caractères à lire du canal. Si l'encodage du canal est binary, ceci est équivalent au nombre d'octets à lire du canal.

Le nombre d'octets à lire du canal. Le tampon readBuf doit être assez grand pour contenir ce nombre d'octets.

Un pointeur vers une chaîne dynamique Tcl dans laquelle stocker la ligne lue du canal. Doit avoir été initialisé par l'appelant. La ligne lue sera ajoutée à toutes les données déjà présentes dans la chaîne dynamique.
const char *input (en)
L'entrée à ajouter à un tampon de canal.
int inputLen (en)
Longueur de l'entrée.
int addAtEnd (en)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon de canal.
Tcl_Obj *writeObjPtr (en)
Un pointeur vers une valeur Tcl dont le contenu sera envoyé au canal.
const char *charBuf (en)
Un tampon contenant les caractères à envoyer au canal.
const char *byteBuf (en)
Un tampon contenant les octets à envoyer au canal.
int bytesToWrite (en)
Le nombre d'octets à consommer de charBuf ou byteBuf et à envoyer au canal.

À quelle distance déplacer le point d'accès dans le canal où la prochaine opération d'entrée ou de sortie sera appliquée, mesuré en octets à partir de la position indiquée par seekMode. Peut être positif ou négatif.

Par rapport à quel point chercher ; utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs légales sont SEEK_SET, SEEK_CUR et SEEK_END.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un moyen indépendant de la plateforme et des périphériques pour effectuer des opérations d'E/S bufferisées sur divers types de fichiers, sockets et périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans la page de manuel de Tcl_CreateChannel. Le mécanisme de canaux fournit un schéma de bufferisation similaire aux E/S standard de Unix, et permet également d'effectuer des E/S non bloquantes sur des canaux.

Les procédures décrites dans ce manuel constituent les API de la couche de haut niveau de l'architecture des canaux. Pour une description de l'architecture des pilotes de canaux et comment implémenter des pilotes de canaux pour de nouveaux types de canaux, consultez la page de manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

La procédure Tcl_OpenFileChannel ouvre un fichier dont le nom est fileName et renvoie un nouveau canal Tcl représentant ce fichier. Le fichier est ouvert avec le mode spécifié par mode, qui peut avoir les mêmes valeurs que l'argument mode de la commande Tcl open (par exemple, "r", "w", "r+", "w+", "a"). Les permissions POSIX sont utilisées pour définir les permissions du fichier s'il est créé. Les valeurs possibles pour mode incluent également "b" pour le mode binaire (qui est le mode par défaut si aucun autre mode n'est spécifié) et "t" pour le mode texte.

Si une erreur se produit pendant l'ouverture du fichier, Tcl_OpenFileChannel renvoie NULL et laisse un message d'erreur dans la chaîne d'erreurs de l'interpréteur interp. Sinon, elle renvoie un handle de canal valide.

TCL_OPENCOMMANDCHANNEL

La procédure Tcl_OpenCommandChannel crée un pipeline de processus et renvoie un canal Tcl représentant le pipeline. argc et argv spécifient la commande et ses arguments. L'option flags est une combinaison OR des indicateurs suivants : TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, l'entrée standard du premier processus enfant est le canal du pipeline, sinon elle est identique à l'entrée standard du processus appelant.

TCL_MAKEFILECHANNEL

La procédure Tcl_MakeFileChannel enveloppe un descripteur de fichier de système d'exploitation existant (par exemple, un descripteur de fichier Unix ou un HANDLE Windows) dans un canal Tcl. Le paramètre handle est le descripteur de fichier et readOrWrite est une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le descripteur de fichier est ouvert en lecture et/ou en écriture.

TCL_GETCHANNEL

La procédure Tcl_GetChannel recherche un canal existant par son nom, channelName. Si modePtr n'est pas NULL, il pointe vers un entier qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.

TCL_GETCHANNELNAMES

La procédure Tcl_GetChannelNames renvoie une liste de tous les noms de canaux actuellement enregistrés dans l'interpréteur interp sous forme d'une valeur Tcl object. Le résultat est stocké dans l'objet Tcl spécifié par interp->result.

TCL_GETCHANNELNAMESEX

La procédure Tcl_GetChannelNamesEx est similaire à Tcl_GetChannelNames, mais elle ne renvoie que les noms de canaux qui correspondent au pattern spécifié. Le motif est géré de la même manière que dans la commande Tcl string match.

TCL_REGISTERCHANNEL

La procédure Tcl_RegisterChannel enregistre un canal channel avec l'interpréteur interp, le rendant disponible pour utilisation par les commandes Tcl. Le canal doit avoir été créé précédemment par une autre procédure Tcl_Channel.

TCL_UNREGISTERCHANNEL

La procédure Tcl_UnregisterChannel désenregistre un canal channel de l'interpréteur interp. Le canal doit avoir été précédemment enregistré avec Tcl_RegisterChannel. Après désenregistrement, le canal ne peut plus être utilisé par les commandes Tcl.

TCL_DETACHCHANNEL

La procédure Tcl_DetachChannel détache un canal channel de l'interpréteur interp. Cela signifie que le canal ne sera plus géré par Tcl, mais le descripteur de fichier sous-jacent reste ouvert. Cela est utile lorsque vous souhaitez transférer la propriété d'un canal à un autre processus ou le gérer manuellement.

TCL_ISTANDARDCHANNEL

La procédure Tcl_IsStandardChannel renvoie 1 si le canal channel est un canal standard (stdin, stdout ou stderr), et 0 sinon.

TCL_CLOSE

La procédure Tcl_Close ferme le canal channel. Toutes les données bufferisées en attente d'écriture sont d'abord vidées. Si une erreur se produit lors de la fermeture, la procédure renvoie TCL_ERROR et laisse un message d'erreur dans l'interpréteur interp. Sinon, elle renvoie TCL_OK.

TCL_READCHARS

La procédure Tcl_ReadChars lit jusqu'à charsToRead caractères du canal channel et les place dans la valeur Tcl pointée par readObjPtr. Si appendFlag est non nul, les caractères lus sont ajoutés à la valeur existante ; sinon, ils remplacent le contenu existant. Si le canal est en mode binaire, charsToRead est interprété comme un nombre d'octets.

La procédure renvoie le nombre de caractères réellement lus. Si une erreur se produit, elle renvoie -1 et laisse un message d'erreur dans l'interpréteur.

TCL_READ

La procédure Tcl_Read lit jusqu'à bytesToRead octets du canal channel et les place dans le tampon readBuf. Le tampon doit être assez grand pour contenir bytesToRead octets.

La procédure renvoie le nombre d'octets réellement lus. Si une erreur se produit, elle renvoie -1 et laisse un message d'erreur dans l'interpréteur.

TCL_GETSOBJ

La procédure Tcl_GetsObj lit une ligne du canal channel (jusqu'au prochain caractère de nouvelle ligne) et la stocke dans la valeur Tcl pointée par lineObjPtr. La ligne lue est ajoutée au contenu existant de la valeur.

La procédure renvoie le nombre d'octets réellement lus. Si une erreur se produit, elle renvoie -1 et laisse un message d'erreur dans l'interpréteur. Si la fin du fichier est atteinte avant la lecture d'une ligne, elle renvoie 0.

TCL_GETS

La procédure Tcl_Gets lit une ligne du canal channel (jusqu'au prochain caractère de nouvelle ligne) et l'ajoute à la chaîne dynamique lineRead. Le délimiteur de nouvelle ligne est inclus dans la chaîne.

La procédure renvoie le nombre d'octets réellement lus. Si une erreur se produit, elle renvoie -1 et laisse un message d'erreur dans l'interpréteur. Si la fin du fichier est atteinte avant la lecture d'une ligne, elle renvoie 0.

TCL_UNGETS

La procédure Tcl_Ungets ajoute la chaîne input de longueur inputLen au tampon d'entrée du canal channel. Si addAtEnd est non nul, l'entrée est ajoutée à la fin du tampon ; sinon, elle est ajoutée au début.

TCL_WRITEOBJ

La procédure Tcl_WriteObj écrit le contenu de la valeur Tcl pointée par writeObjPtr dans le canal channel.

La procédure renvoie le nombre d'octets réellement écrits. Si une erreur se produit, elle renvoie -1 et laisse un message d'erreur dans l'interpréteur.

TCL_WRITECHARS

La procédure Tcl_WriteChars écrit les caractères du tampon charBuf (longueur bytesToWrite) dans le canal channel. L'encodage du canal est utilisé pour convertir les caractères en octets si nécessaire.

La procédure renvoie le nombre d'octets réellement écrits. Si une erreur se produit, elle renvoie -1 et laisse un message d'erreur dans l'interpréteur.

TCL_WRITE

La procédure Tcl_Write écrit les octets du tampon byteBuf (longueur bytesToWrite) dans le canal channel. Cette procédure est utilisée pour écrire des données binaires brutes.

La procédure renvoie le nombre d'octets réellement écrits. Si une erreur se produit, elle renvoie -1 et laisse un message d'erreur dans l'interpréteur.

TCL_READRAW

La procédure Tcl_ReadRaw est similaire à Tcl_Read, mais elle lit des données brutes sans tenir compte de l'encodage du canal.

TCL_WRITERAW

La procédure Tcl_WriteRaw est similaire à Tcl_Write, mais elle écrit des données brutes sans tenir compte de l'encodage du canal.

TCL_EOF

La procédure Tcl_Eof renvoie 1 si la fin du fichier a été atteinte pour le canal channel, et 0 sinon.

TCL_FLUSH

La procédure Tcl_Flush vide tous les tampons d'écriture pour le canal channel. Cela garantit que toutes les données écrites sont envoyées au périphérique sous-jacent.

La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'erreur.

TCL_INPUTBLOCKED

La procédure Tcl_InputBlocked renvoie 1 si une tentative de lecture sur le canal channel bloquerait actuellement l'exécution, et 0 sinon. Ceci est utile pour la gestion des E/S non bloquantes.

TCL_INPUTBUFFERED

La procédure Tcl_InputBuffered renvoie le nombre d'octets actuellement présents dans le tampon d'entrée du canal channel.

TCL_OUTPUTBUFFERED

La procédure Tcl_OutputBuffered renvoie le nombre d'octets actuellement présents dans le tampon de sortie du canal channel qui n'ont pas encore été écrits sur le périphérique sous-jacent.

TCL_SEEK

La procédure Tcl_Seek repositionne le marqueur de position courant du canal channel. L'offset spécifie le nombre d'octets à déplacer, et seekMode spécifie le point de référence (SEEK_SET pour le début, SEEK_CUR pour la position courante, SEEK_END pour la fin).

La procédure renvoie la nouvelle position du marqueur de position courant en octets par rapport au début du canal. En cas d'erreur, elle renvoie -1 et laisse un message d'erreur dans l'interpréteur.

TCL_TELL

La procédure Tcl_Tell renvoie la position courante du marqueur de position dans le canal channel, en octets depuis le début du canal.

En cas d'erreur, elle renvoie -1 et laisse un message d'erreur dans l'interpréteur.

TCL_TRUNCATECHANNEL

La procédure Tcl_TruncateChannel tronque le canal channel à la length spécifiée. Cela signifie que toutes les données au-delà de cette longueur sont supprimées.

La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'erreur.

TCL_GETCHANNELOPTION

La procédure Tcl_GetChannelOption récupère la valeur de l'option optionName pour le canal channel et la stocke dans la chaîne dynamique optionValue. Les noms d'options sont les mêmes que ceux acceptés par la commande Tcl fconfigure.

La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'erreur (par exemple, si le nom de l'option n'est pas valide).

TCL_SETCHANNELOPTION

La procédure Tcl_SetChannelOption définit la valeur de l'option optionName pour le canal channel à newValue. Les noms d'options sont les mêmes que ceux acceptés par la commande Tcl fconfigure.

La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'erreur (par exemple, si le nom de l'option ou sa valeur n'est pas valide).

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et retourne un handle de canal pouvant être utilisé pour effectuer des entrées et sorties sur le fichier. Cette API est modelée d'après la procédure fopen de la bibliothèque d'entrée/sortie standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans les commandes Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel retourne NULL et enregistre un code d'erreur POSIX pouvant être obtenu avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. À partir de Tcl 8.4, la valeur basée sur l'API Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel dans tous les cas.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Il crée une chaîne de processus subsidiaires spécifiée par les arguments argv et argc et retourne un canal pouvant être utilisé pour communiquer avec ces processus subsidiaires. L'argument flags indique quel type de communication aura lieu avec la chaîne de commandes.

Si le drapeau TCL_STDIN est défini, le canal d'entrée standard du premier processus subsidiaire est lié au canal : écrire dans le canal fournit l'entrée au processus subsidiaire. Si le drapeau TCL_STDIN n'est pas défini, le canal d'entrée standard du premier processus subsidiaire sera le même que le canal d'entrée de cette application. Si le drapeau TCL_STDOUT est défini, la sortie standard du dernier processus subsidiaire peut être lue depuis le canal ; sinon, elle va à la sortie standard de cette application. Si le drapeau TCL_STDERR est défini, la sortie d'erreur standard de tous les processus subsidiaires est retournée au canal et provoque une erreur à la fermeture du canal ; sinon, elle va à la sortie d'erreur standard de cette application. Si le drapeau TCL_ENFORCE_MODE n'est pas défini, les arguments argc et argv peuvent rediriger les handles standard pour outrepasser TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, c'est une erreur pour argc et argv de rediriger les canaux standard pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel retourne NULL et enregistre un code d'erreur POSIX pouvant être obtenu avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un handle de fichier existant et spécifique à la plateforme. Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'action de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel retourne un canal donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur dans interp. Si aucun canal enregistré dans cet interpréteur avec ce nom n'existe, la procédure retourne NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtre ces noms en fonction du pattern. Si pattern est NULL, aucun filtrage n'est effectué. La valeur de retour est TCL_OK s'il n'y a pas eu d'erreurs lors de l'écriture dans le résultat, sinon c'est TCL_ERROR et le message d'erreur est conservé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à la collection de canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur peuvent faire référence au canal en utilisant le nom donné lors de l'appel à Tcl_CreateChannel pour les opérations d'entrée et de sortie. Après cet appel, le canal devient la propriété de l'interpréteur et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code s'exécutant en dehors de tout interpréteur peut appeler Tcl_RegisterChannel avec interp comme NULL, indiquant qu'il souhaite conserver une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et ne sera fermé que lorsque les appels correspondants à Tcl_UnregisterChannel auront été effectués. Cela permet au code s'exécutant en dehors de tout interpréteur de conserver une référence sécurisée à un canal qui est également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code qui gère les canaux standard. Si aucun canal standard n'est initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Consultez Tcl_StandardChannels pour une généralisation sur les canaux standard et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel supprime un canal de la collection de canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Si cette opération supprime le dernier enregistrement du canal dans un interpréteur, le canal sera également fermé et détruit.

Le code non associé à un interpréteur peut appeler Tcl_UnregisterChannel avec interp comme NULL, indiquant à Tcl qu'il ne conserve plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera fermé maintenant. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel, sauf qu'il ferme également le canal s'il n'y a plus de références restantes.

TCL_DETACHCHANNEL

Tcl_DetachChannel supprime un canal de la collection de canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Là, cette commande n'a aucun effet supplémentaire. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin), et retournera TCL_ERROR si on lui passe l'un de ces canaux.

Le code non associé à un interpréteur peut appeler Tcl_DetachChannel avec interp comme NULL, indiquant à Tcl qu'il ne conserve plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel vérifie si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. Si c'est le cas, il retourne 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou autrement valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lorsque Tcl_Close est appelé. Le tampon de sortie est vidé avant de détruire le canal, et tout tampon d'entrée est rejeté. S'il s'agit d'un canal bloquant, l'appel ne retourne pas tant que toutes les données mises en tampon n'ont pas été envoyées au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a des données mises en tampon qui ne peuvent pas être écrites sans blocage, l'appel retourne immédiatement ; la sortie est envoyée en arrière-plan et le canal est fermé lorsque toutes les données mises en tampon ont été traitées. Dans ce cas, les erreurs lors de l'envoi ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close retourne TCL_OK. Si une erreur se produit, Tcl_Close retourne TCL_ERROR et enregistre un code d'erreur POSIX pouvant être obtenu avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture et que interp n'est pas NULL, un message d'erreur est conservé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré avec Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel pour plus de détails. Si le canal a été donné comme chan dans un appel à Tcl_RegisterChannel, vous devez utiliser Tcl_UnregisterChannel, qui appelle en interne Tcl_Close lorsque tous les appels à Tcl_RegisterChannel ont été mis en correspondance par des appels à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, convertis en UTF-8 selon l'encodage du canal, et stocke les données résultantes dans la représentation de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit pendant la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX pouvant être obtenu avec Tcl_GetErrno.

La valeur de charsToRead

TCL_READCHARS, TCL_READOBJ, AND TCL_READ

La valeur -1 amènera la commande à lire tous les caractères actuellement disponibles (non bloquants) ou tout jusqu'à EOF (mode bloquant).

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé étaient disponibles. Ceci est appelé une lecture courte. En mode bloquant, cela ne peut se produire qu'à une fin de fichier. En mode non bloquant, une lecture courte peut également se produire s'il n'y a pas assez d'entrées actuellement disponibles : Tcl_ReadChars renvoie un nombre réduit plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour savoir laquelle de ces conditions s'est effectivement produite.

Tcl_ReadChars traduit les diverses représentations de fin de ligne en la représentation interne canonique \n selon le mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les divers modes spécifiques à la plateforme sont décrits dans l'entrée de manuel de la commande Tcl fconfigure.

Par optimisation de performance, lors de la lecture d'un canal avec l'encodage binary, les octets ne sont pas convertis en UTF-8 lors de leur lecture. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr sous forme de tableau d'octets. La représentation sous forme de chaîne de cette valeur ne sera construite que si nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette manière, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans les frais de conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'il n'effectue pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour des raisons de compatibilité ascendante avec les extensions Tcl non internationalisées. Il consomme des octets du channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par un zéro. Son contenu est valide à partir de la position zéro jusqu'à, mais sans inclure, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas pour l'empilement. Alors que Tcl_Read (et les autres fonctions de l'API) obtiennent toujours leurs données du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_ReadRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données du canal inférieur dans la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, convertit les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée ait été vue. Si l'encodage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception des caractères de fin de ligne terminaux, sont ajoutés à la représentation de chaîne de lineObjPtr. Les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. En cas d'erreur, Tcl_GetsObj renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj renvoie également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut aussi être -1 si aucune donnée n'était disponible ou si les données disponibles ne contiennent pas de caractère de fin de ligne. Lorsque -1 est renvoyé, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité de l'entrée.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique donnée par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, soit à la tête, soit à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur des données à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si channel a un indicateur EOF “collant” défini, aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets renvoie inputLen ou -1 en cas d'erreur.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données caractères à charBuf. Les caractères UTF-8 du tampon sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par un zéro et il sort tout jusqu'au zéro.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal à none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un compteur du nombre d'octets qui ont été acceptés pour la sortie vers le canal. C'est soit supérieur à zéro pour indiquer le succès, soit -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme selon l'option -translation du canal. Ceci est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'il accepte une valeur Tcl dont le contenu sera sorti vers le canal. Les caractères UTF-8 de la représentation de chaîne de writeObjPtr sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. Par optimisation de performance, lors de l'écriture dans un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets dans la représentation interne de writeObjPtr sous forme de tableau d'octets sont écrits dans le canal. La représentation en tableau d'octets de la valeur sera construite si elle est nécessaire. De cette manière, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans les frais de conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'il n'effectue pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour des raisons de compatibilité ascendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par un zéro et il sort tout jusqu'au zéro.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas pour l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation dans le canal situé en dessous.

TCL_FLUSH

Tcl_Flush force la sortie de toutes les données mises en mémoire tampon pour channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données mises en mémoire tampon n'ont pas été envoyées au canal ou qu'une erreur ne s'est pas produite. L'appel retourne immédiatement si le canal est non bloquant ; il démarre une purge en arrière-plan qui écrira les données mises en mémoire tampon dans le canal éventuellement, aussi rapidement que le canal est capable de les absorber.

La valeur de retour est normalement TCL_OK. En cas d'erreur, Tcl_Flush renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données suivantes seront lues ou écrites. La sortie mise en mémoire tampon est vidée vers le canal et l'entrée mise en mémoire tampon est rejetée, avant l'opération de recherche. L'appelant doit s'assurer que le canal est positionnable avant d'appeler Tcl_Seek.

Tcl_Seek renvoie normalement le nouveau point d'accès. En cas d'erreur, Tcl_Seek renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut avoir été déplacé ou non.

TCL_TELL

Tcl_Tell renvoie le point d'accès actuel pour un canal. La valeur renvoyée est -1 si le canal ne prend pas en charge le déplacement.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent de channel à une longueur donnée de length octets. Il renvoie TCL_OK si l'opération a réussi, et TCL_ERROR sinon.
