NOM

Tcl_InitHashTable, Tcl_InitCustomHashTable, Tcl_InitObjHashTable, Tcl_DeleteHashTable, Tcl_CreateHashEntry, Tcl_DeleteHashEntry, Tcl_FindHashEntry, Tcl_GetHashValue, Tcl_SetHashValue, Tcl_GetHashKey, Tcl_FirstHashEntry, Tcl_NextHashEntry, Tcl_HashStats - procédures pour gérer les tables de hachage

SYNOPSIS

#include <tcl.h>

Tcl_InitHashTable(tablePtr, keyType)

Tcl_InitCustomHashTable(tablePtr, keyType, typePtr)

Tcl_InitObjHashTable(tablePtr)

Tcl_DeleteHashTable(tablePtr)

Tcl_HashEntry *
Tcl_CreateHashEntry(tablePtr, key, newPtr)

Tcl_DeleteHashEntry(entryPtr)

Tcl_HashEntry *
Tcl_FindHashEntry(tablePtr, key)

ClientData
Tcl_GetHashValue(entryPtr)

Tcl_SetHashValue(entryPtr, value)

void *
Tcl_GetHashKey(tablePtr, entryPtr)

Tcl_HashEntry *
Tcl_FirstHashEntry(tablePtr, searchPtr)

Tcl_HashEntry *
Tcl_NextHashEntry(searchPtr)

char *
Tcl_HashStats(tablePtr)

ARGUMENTS

Tcl_HashTable *tablePtr (entrée)
Adresse de la structure de table de hachage (pour toutes les procédures sauf Tcl_InitHashTable, celle-ci doit avoir été initialisée par un appel précédent à Tcl_InitHashTable).
int keyType (entrée)
Type de clés à utiliser pour la nouvelle table de hachage. Doit être soit TCL_STRING_KEYS, TCL_ONE_WORD_KEYS, TCL_CUSTOM_TYPE_KEYS, TCL_CUSTOM_PTR_KEYS, soit une valeur entière supérieure à 1.
Tcl_HashKeyType *typePtr (entrée)
Adresse de la structure qui définit le comportement de la table de hachage.
const void *key (entrée)
Clé à utiliser pour sonder la table. La forme exacte dépend de keyType utilisé pour créer la table.
int *newPtr (sortie)
Le mot à l'adresse *newPtr est mis à 1 si une nouvelle entrée a été créée et à 0 s'il existait déjà une entrée pour key.
Tcl_HashEntry *entryPtr (entrée)
Pointeur vers une entrée de table de hachage.
ClientData value (entrée)
Nouvelle valeur à attribuer à l'entrée de la table de hachage. N'a pas besoin d'avoir le type ClientData, mais doit tenir dans le même espace que ClientData.
Tcl_HashSearch *searchPtr (entrée)
Pointeur vers l'enregistrement à utiliser pour suivre la progression lors de l'énumération de toutes les entrées d'une table de hachage.

DESCRIPTION

Une table de hachage se compose de zéro ou plusieurs entrées, chacune constituée d'une clé et d'une valeur. Étant donné la clé d'une entrée, les routines de hachage peuvent localiser très rapidement l'entrée, et donc sa valeur. Il ne peut y avoir qu'une seule entrée dans une table de hachage pour une clé donnée, mais plusieurs entrées peuvent avoir la même valeur. Les clés peuvent prendre l'une des quatre formes suivantes : chaînes de caractères, valeurs d'un seul mot, tableaux d'entiers, ou clés personnalisées définies par une structure Tcl_HashKeyType (Voir la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous). Toutes les clés d'une table donnée ont la même forme, qui est spécifiée lors de l'initialisation de la table.

La valeur d'une entrée de table de hachage peut être n'importe quoi qui tienne dans le même espace qu'un pointeur “char *”. Les valeurs des entrées de table de hachage sont gérées entièrement par les clients, et non par le module de hachage lui-même. Typiquement, la valeur de chaque entrée est un pointeur vers une structure de données gérée par le code client.

Les tables de hachage augmentent de manière fluide à mesure que le nombre d'entrées augmente, de sorte qu'il y ait toujours moins de trois entrées par compartiment de hachage, en moyenne. Cela permet des recherches rapides quel que soit le nombre d'entrées dans une table.

Le noyau fournit trois fonctions pour l'initialisation des tables de hachage : Tcl_InitHashTable, Tcl_InitObjHashTable et Tcl_InitCustomHashTable.

Tcl_InitHashTable initialise une structure qui décrit une nouvelle table de hachage. L'espace pour la structure est fourni par l'appelant, et non par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. Tous les types de clés décrits plus loin sont autorisés, à l'exception de TCL_CUSTOM_TYPE_KEYS et TCL_CUSTOM_PTR_KEYS.

Tcl_InitObjHashTable est une enveloppe autour de Tcl_InitCustomHashTable et initialise une table de hachage dont les clés sont des Tcl_Obj *.

Tcl_InitCustomHashTable initialise une structure qui décrit une nouvelle table de hachage. L'espace pour la structure est fourni par l'appelant, et non par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. KeyType doit avoir l'une des valeurs suivantes :

TCL_STRING_KEYS
Les clés sont des chaînes de caractères terminées par un octet nul. Elles sont passées aux routines de hachage en utilisant l'adresse du premier caractère de la chaîne.
TCL_ONE_WORD_KEYS
Les clés sont des valeurs d'un seul mot ; elles sont passées aux routines de hachage et stockées dans les entrées de la table de hachage sous forme de valeurs “char *”. La valeur du pointeur est la clé ; elle n'a pas besoin (et ne le fait généralement pas) de pointer vers une chaîne.
TCL_CUSTOM_TYPE_KEYS
Les clés sont de type arbitraire et sont stockées dans l'entrée. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous.
TCL_CUSTOM_PTR_KEYS
Les clés sont des pointeurs vers un type arbitraire et sont stockées dans l'entrée. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section LA STRUCTURE TCL_HASHKEYTYPE ci-dessous.
autre
Si keyType n'est pas l'un des éléments ci-dessus, il doit s'agir d'une valeur entière supérieure à 1. Dans ce cas, les clés seront des tableaux de valeurs “int”, où keyType donne le nombre d'entiers dans chaque clé. Cela permet d'utiliser des structures comme clés. Toutes les clés doivent avoir la même taille. Les clés de tableau sont passées aux fonctions de hachage en utilisant l'adresse du premier entier du tableau.

Tcl_DeleteHashTable supprime toutes les entrées d'une table de hachage et libère la mémoire associée au tableau de compartiments et aux entrées de la table. Elle ne libère pas la structure de table elle-même (pointée par tablePtr), car on suppose que cette mémoire est gérée par le client. Tcl_DeleteHashTable ne libère pas non plus et ne manipule pas les valeurs des entrées de la table de hachage. Si les valeurs des entrées pointent vers de la mémoire allouée dynamiquement, il est de la responsabilité du client de libérer ces structures avant de supprimer la table.

Tcl_CreateHashEntry localise l'entrée correspondant à une clé particulière, créant une nouvelle entrée dans la table s'il n'y en avait pas déjà une avec la clé donnée. Si une entrée existait déjà avec la clé donnée, alors *newPtr est mis à zéro. Si une nouvelle entrée a été créée, alors *newPtr est mis à une valeur non nulle et la valeur de la nouvelle entrée sera mise à zéro. La valeur de retour de Tcl_CreateHashEntry est un pointeur vers l'entrée, qui peut être utilisé pour récupérer et modifier la valeur de l'entrée ou pour supprimer l'entrée de la table.

Tcl_DeleteHashEntry supprimera une entrée existante d'une table. La mémoire associée à l'entrée elle-même sera libérée, mais le client est responsable de tout nettoyage associé à la valeur de l'entrée, tel que la libération d'une structure vers laquelle elle pointe.

Tcl_FindHashEntry est similaire à Tcl_CreateHashEntry sauf qu'elle ne crée pas une nouvelle entrée si la clé n'existe pas ; au lieu de cela, elle retourne NULL comme résultat.

Tcl_GetHashValue et Tcl_SetHashValue sont utilisés pour lire et écrire la valeur d'une entrée, respectivement. Les valeurs sont stockées et récupérées comme type “ClientData”, ce qui est suffisamment grand pour contenir une valeur de pointeur. Sur presque toutes les machines, cela est suffisant pour contenir également une valeur entière.

Tcl_GetHashKey retourne la clé d'une entrée de table de hachage donnée, soit sous forme de pointeur vers une chaîne, une clé d'un seul mot (“char *”), soit sous forme de pointeur vers le premier mot d'un tableau d'entiers, en fonction du keyType utilisé pour créer une table de hachage. Dans tous les cas, Tcl_GetHashKey retourne un résultat de type “char *”. Lorsque la clé est une chaîne ou un tableau, le résultat de Tcl_GetHashKey pointe vers des informations dans l'entrée de la table ; ces informations resteront valides jusqu'à ce que l'entrée soit supprimée ou que sa table soit supprimée.

Tcl_FirstHashEntry et Tcl_NextHashEntry peuvent être utilisés pour parcourir toutes les entrées d'une table de hachage.

Tcl_DeleteHashEntry(3) - Arch manual pages

NAME

Tcl_CreateHashEntry, Tcl_DeleteHashEntry, Tcl_FindHashEntry, Tcl_FirstHashEntry, Tcl_HashStats, Tcl_InitHashTable, Tcl_NextHashEntry

SYNOPSIS

#include <tcl.h>

Tcl_HashTable *
Tcl_InitHashTable(tablePtr, typePtr);

Tcl_HashEntry *
Tcl_FindHashEntry(tablePtr, keyPtr);

Tcl_HashEntry *
Tcl_CreateHashEntry(tablePtr, keyPtr, &newEntryPtr);

void
Tcl_DeleteHashEntry(tablePtr, entryPtr);

Tcl_HashEntry *
Tcl_FirstHashEntry(tablePtr, searchPtr);

Tcl_HashEntry *
Tcl_NextHashEntry(tablePtr, searchPtr);

char *
Tcl_HashStats(tablePtr);

ARGUMENTS

tablePtr
Pointer to the hash table to operate on. For use with Tcl_InitHashTable, this points to a Tcl_HashTable structure that is being initialized.
typePtr
Pointer to a structure describing the key type for the hash table. See section below for details.
keyPtr
Pointer to the key to search for or insert. The interpretation of this pointer depends on the key type. For example, for string keys, it is a pointer to a null-terminated string. For integer keys, it is a pointer to an integer. For Tcl objects, it is a pointer to a Tcl_Obj structure.
newEntryPtr
Pointer to a Tcl_HashEntry pointer. If the entry is newly created by Tcl_CreateHashEntry then the new entry is stored here.
entryPtr
Pointer to the hash entry to delete.
searchPtr
Pointer to a Tcl_HashSearch structure that is used to keep track of progress through the table.

DESCRIPTION

These procedures provide a general-purpose hash table implementation. A hash table is a structure that stores key-value pairs. It allows for efficient lookup, insertion, and deletion of entries based on their keys.

Tcl_InitHashTable initializes a hash table. It takes a pointer to a Tcl_HashTable structure and a pointer to a Tcl_HashKeyType structure describing the type of keys to be stored in the table. The typePtr argument can be one of the built-in types (e.g., string, integer, Tcl object) or a custom type defined by the extension writer. The initial size of the hash table (number of buckets) is determined by the typePtr argument. The function returns a pointer to the initialized hash table.

Tcl_FindHashEntry searches for an entry in the hash table using the provided key. If an entry with the matching key is found, a pointer to the Tcl_HashEntry structure is returned. Otherwise, NULL is returned.

Tcl_CreateHashEntry inserts a new entry into the hash table with the given key. If an entry with the same key already exists, it is returned. If the entry is newly created, the pointer to the new entry is stored in the location pointed to by newEntryPtr. This procedure returns a pointer to the existing or newly created entry.

Tcl_DeleteHashEntry deletes the specified entry from the hash table. The entryPtr argument should be a pointer to a valid hash entry previously returned by Tcl_FindHashEntry or Tcl_CreateHashEntry.

The functions Tcl_FirstHashEntry and Tcl_NextHashEntry are used to iterate through all the entries in a hash table. A structure of type Tcl_HashSearch, provided by the client, is used to keep track of progress through the table. Tcl_FirstHashEntry initializes the search record and returns the first entry in the table (or NULL if the table is empty). Each subsequent call to Tcl_NextHashEntry returns the next entry in the table or NULL if the end of the table has been reached. A call to Tcl_FirstHashEntry followed by calls to Tcl_NextHashEntry will return each of the entries in the table exactly once, in an arbitrary order. It is inadvisable to modify the structure of the table, e.g. by creating or deleting entries, while the search is in progress, with the exception of deleting the entry returned by Tcl_FirstHashEntry or Tcl_NextHashEntry.

Tcl_HashStats returns a dynamically-allocated string with overall information about a hash table, such as the number of entries it contains, the number of buckets in its hash array, and the utilization of the buckets. It is the caller's responsibility to free the result string by passing it to ckfree.

The header file tcl.h defines the actual data structures used to implement hash tables. This is necessary so that clients can allocate Tcl_HashTable structures and so that macros can be used to read and write the values of entries. However, users of the hashing routines should never refer directly to any of the fields of any of the hash-related data structures; use the procedures and macros defined here.

THE TCL_HASHKEYTYPE STRUCTURE

Extension writers can define new hash key types by defining four procedures, initializing a Tcl_HashKeyType structure to describe the type, and calling Tcl_InitCustomHashTable. The Tcl_HashKeyType structure is defined as follows:

typedef struct Tcl_HashKeyType {
    int version;
    int flags;
    Tcl_HashKeyProc *hashKeyProc;
    Tcl_CompareHashKeysProc *compareKeysProc;
    Tcl_AllocHashEntryProc *allocEntryProc;
    Tcl_FreeHashEntryProc *freeEntryProc;
} Tcl_HashKeyType;

The version member is the version of the table. If this structure is extended in future then the version can be used to distinguish between different structures. It should be set to TCL_HASH_KEY_TYPE_VERSION.

The flags member is 0 or one or more of the following values OR'ed together:

TCL_HASH_KEY_RANDOMIZE_HASH
There are some things, pointers for example which do not hash well because they do not use the lower bits. If this flag is set then the hash table will attempt to rectify this by randomizing the bits and then using the upper N bits as the index into the table.
TCL_HASH_KEY_SYSTEM_HASH
This flag forces Tcl to use the memory allocation procedures provided by the operating system when allocating and freeing memory used to store the hash table data structures, and not any of Tcl's own customized memory allocation routines. This is important if the hash table is to be used in the implementation of a custom set of allocation routines, or something that a custom set of allocation routines might depend on, in order to avoid any circular dependency.

The hashKeyProc member contains the address of a function called to calculate a hash value for the key.

typedef unsigned int Tcl_HashKeyProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

If this is NULL then keyPtr is used and TCL_HASH_KEY_RANDOMIZE_HASH is assumed.

The compareKeysProc member contains the address of a function called to compare two keys.

typedef int Tcl_CompareHashKeysProc(
        void *keyPtr,
        Tcl_HashEntry *hPtr);

If this is NULL then the keyPtr pointers are compared. If the keys do not match then the function returns 0, otherwise it returns 1.

The allocEntryProc member contains the address of a function called to allocate space for an entry and initialize the key and clientData.

typedef Tcl_HashEntry *Tcl_AllocHashEntryProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

If this is NULL then Tcl_Alloc is used to allocate enough space for a Tcl_HashEntry, the key pointer is assigned to key.oneWordValue and the clientData is set to NULL. String keys and array keys use this function to allocate enough space for the entry and the key in one block, rather than doing it in two blocks. This saves space for a pointer to the key from the entry and another memory allocation. Tcl_Obj* keys use this function to allocate enough space for an entry and increment the reference count on the value.

The freeEntryProc member contains the address of a function called to free space for an entry.

typedef void Tcl_FreeHashEntryProc(
        Tcl_HashEntry *hPtr);

If this is NULL then Tcl_Free is used to free the space for the entry. Tcl_Obj* keys use this function to decrement the reference count on the value.

hash table, key, lookup, search, value
