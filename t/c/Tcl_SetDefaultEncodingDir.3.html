ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur à utiliser pour le rapport d'erreurs, ou NULL si aucun rapport d'erreurs n'est souhaité.
const char *name (in)
Nom de l'encodage à charger.
Tcl_Encoding encoding (in)
Encodage à interroger, libérer ou utiliser pour convertir du texte. Si encoding est NULL, l'encodage du système courant est utilisé.
Tcl_Obj *objPtr (in)
Nom de l'encodage pour obtenir le jeton.
Tcl_Encoding encodingPtr (out)
Stocke le jeton de l'encodage demandé.
const char *src (in)
Pour les fonctions Tcl_ExternalToUtf, un tableau d'octets dans l'encodage spécifié à convertir en UTF-8. Pour les fonctions Tcl_UtfToExternal et Tcl_WinUtfToTChar, un tableau de caractères UTF-8 à convertir dans l'encodage spécifié.
const TCHAR *tsrc (in)
Un tableau de caractères Windows TCHAR à convertir en UTF-8.
int srcLen (in)
Longueur de src ou tsrc en octets. Si la longueur est négative, la longueur de chaîne spécifique à l'encodage est utilisée.
Tcl_DString *dstPtr (out)
Un DString non initialisé ou libéré dans lequel le résultat converti sera stocké.
int flags (in)
Bits de drapeau ORés. TCL_ENCODING_START indique que le tampon source est le premier bloc d'un flux d'entrée (potentiellement multi-blocs), indiquant à la routine de conversion de réinitialiser à l'état initial et d'effectuer toute initialisation requise avant de convertir le premier octet. TCL_ENCODING_END indique que le tampon source est le dernier bloc d'un flux d'entrée (potentiellement multi-blocs), indiquant à la routine de conversion d'effectuer toute finalisation requise après la conversion du dernier octet, puis de réinitialiser à l'état initial. TCL_ENCODING_STOPONERROR indique que la routine de conversion doit retourner immédiatement lorsqu'elle lit un caractère source qui n'est pas présent dans l'encodage cible ; sinon, un caractère par défaut sera automatiquement substitué.
Tcl_EncodingState *statePtr (in/out)
Utilisé lors de la conversion d'un flux d'octets (généralement long ou de longueur indéfinie) par morceaux. La routine de conversion stocke son état actuel dans statePtr après avoir converti le tampon src (le tampon contenant le morceau actuel). Ces informations d'état doivent être renvoyées lors du traitement du morceau suivant du flux afin que la routine de conversion sache dans quel état elle s'est trouvée lorsqu'elle a mis de côté le dernier morceau. Peut être NULL, auquel cas la valeur spécifiée pour flags est ignorée et il est supposé que le tampon source contient la chaîne complète à convertir.
char *dst (out)
Tampon dans lequel le résultat de la conversion sera stocké. Pas plus de dstLen octets ne seront stockés dans dst.
int dstLen (in)
Longueur maximale du tampon de sortie dst en octets.
int *srcReadPtr (out)
Contient le nombre d'octets de src qui ont été convertis. Cela peut être inférieur à la longueur d'origine de src s'il y a eu un problème lors de la conversion de certains caractères source. Peut être NULL.
int *dstWrotePtr (out)
Contient le nombre d'octets qui ont été stockés dans le tampon de sortie en conséquence de la conversion. Peut être NULL.
int *dstCharsPtr (out)
Contient le nombre de caractères correspondant au nombre d'octets stockés dans le tampon de sortie. Peut être NULL.
Tcl_DString *bufPtr (out)
Stocke le nom du système d'encodage spécifié.
const Tcl_EncodingType *typePtr (in)
Structure définissant un nouveau type d'encodage.
Tcl_Obj *searchPath (in)
Liste des répertoires de fichiers dans lesquels rechercher les fichiers d'encodage.
const char *path (in)
Emplacement du fichier d'encodage.

INTRODUCTION

Ces routines convertissent entre la représentation interne des caractères de Tcl, UTF-8, et les représentations de caractères utilisées par divers systèmes d'exploitation ou répertoires de fichiers, tels que Unicode, ASCII ou EUC-JP. Lors du travail avec des chaînes de caractères, comme l'obtention du nom de fichier ou l'affichage de caractères avec des polices internationales, les chaînes doivent être traduites dans une ou plusieurs formes qui peuvent être utilisées par les différents appels système. Par exemple, sur un poste de travail Unix japonais, un utilisateur pourrait obtenir un nom de fichier représenté dans l'encodage EUC-JP, puis traduire les caractères dans l'encodage jisx0208 pour afficher le nom du fichier dans un widget Tk. Le but du paquet d'encodage est d'aider à combler le fossé de traduction. UTF-8 fournit un pont de staging pour tous les encodages. Dans l'exemple ci-dessus, le texte serait traduit en UTF-8 à partir de l'encodage utilisé par le système d'exploitation, puis traduit dans l'encodage requis par les routines d'affichage.

Certains encodages de base sont inclus dans Tcl. D'autres peuvent être définis par l'utilisateur ou chargés dynamiquement à partir de fichiers d'encodage d'une manière indépendante de la plateforme.

DESCRIPTION

Tcl_GetEncoding trouve un encodage étant donné son nom. Le nom peut faire référence à un encodage prédéfini dans Tcl, à un encodage défini par l'utilisateur enregistré avec Tcl_CreateEncoding, ou à un encodage chargeable dynamiquement. La valeur renvoyée est un jeton représentant l'encodage et peut être utilisé dans des procédures telles que Tcl_GetEncodingName, Tcl_FreeEncoding et Tcl_UtfToExternal. Si le nom ne fait référence à aucun encodage connu ou chargeable, NULL est renvoyé et un message d'erreur est renvoyé dans interp.

Le paquet d'encodage maintient une banque d'encodages actuellement en cours d'utilisation. La première fois que name est vu, Tcl_GetEncoding renvoie un encodage avec un compteur de références de 1. Si le même name est demandé à nouveau, le compteur de références de cet encodage est incrémenté sans la surcharge d'allocation d'un nouvel encodage et de ses structures associées.

Lorsqu'un encodage n'est plus utilisé, Tcl_FreeEncoding doit être appelé pour le libérer. Lorsqu'un encodage n'est plus utilisé (c'est-à-dire qu'il a été libéré autant de fois qu'il a été obtenu), Tcl_FreeEncoding libérera toute la mémoire utilisée par cet encodage et supprimera l'encodage de la base de données.

Tcl_GetEncodingFromObj traite la représentation de chaîne de objPtr comme un nom d'encodage et trouve un encodage portant ce nom, de la même manière que Tcl_GetEncoding. Lorsqu'un encodage est trouvé, il est chargé dans la valeur objPtr comme un jeton pour référence future, et le jeton Tcl_Encoding est écrit dans le stockage. Le jeton est écrit dans le stockage de objPtr lorsqu'un encodage est trouvé.

pointé par encodingPtr, et la valeur TCL_OK est retournée. Si aucun encodage de ce type n'est trouvé, la valeur TCL_ERROR est retournée, et aucune écriture sur *encodingPtr n'a lieu. Tout comme avec Tcl_GetEncoding, l'appelant doit appeler Tcl_FreeEncoding sur le jeton d'encodage résultant lorsque ce jeton ne sera plus utilisé.

Tcl_ExternalToUtfDString convertit un tampon source src de l'encodage spécifié encoding en UTF-8. Les octets convertis sont stockés dans dstPtr, qui est ensuite terminé par un caractère nul. L'appelant devra éventuellement appeler Tcl_DStringFree pour libérer toute information stockée dans dstPtr. Lors de la conversion, si l'un des caractères du tampon source ne peut pas être représenté dans l'encodage cible, un caractère de remplacement par défaut sera utilisé. La valeur de retour est un pointeur vers la valeur stockée dans la DString.

Tcl_ExternalToUtf convertit un tampon source src de l'encodage spécifié encoding en UTF-8. Jusqu'à srcLen octets sont convertis à partir du tampon source et jusqu'à dstLen octets convertis sont stockés dans dst. Dans tous les cas, *srcReadPtr est rempli avec le nombre d'octets qui ont été convertis avec succès à partir de src et *dstWrotePtr est rempli avec le nombre correspondant d'octets qui ont été stockés dans dst. La valeur de retour est l'une des suivantes:

TCL_OK
Tous les octets de src ont été convertis.
TCL_CONVERT_NOSPACE
Le tampon de destination n'était pas assez grand pour toutes les données converties ; cependant, autant de caractères que possible ont été convertis.
TCL_CONVERT_MULTIBYTE
Les derniers octets du tampon source étaient le début d'une séquence multibyte, mais plus d'octets étaient nécessaires pour compléter cette séquence. Un appel ultérieur à la routine de conversion devrait passer un tampon contenant les octets non convertis qui restaient dans src plus quelques octets supplémentaires du flux source pour convertir correctement la séquence multibyte précédemment divisée.
TCL_CONVERT_SYNTAX
Le tampon source contenait une séquence de caractères invalide. Cela peut se produire si le flux d'entrée a été corrompu ou si la méthode d'encodage d'entrée a été mal identifiée.
TCL_CONVERT_UNKNOWN
Le tampon source contenait un caractère qui ne pouvait pas être représenté dans l'encodage cible et TCL_ENCODING_STOPONERROR a été spécifié.

Tcl_UtfToExternalDString convertit un tampon source src de UTF-8 vers l'encodage spécifié encoding. Les octets convertis sont stockés dans dstPtr, qui est ensuite terminé par le caractère nul approprié à l'encodage. L'appelant devra éventuellement appeler Tcl_DStringFree pour libérer toute information stockée dans dstPtr. Lors de la conversion, si l'un des caractères du tampon source ne peut pas être représenté dans l'encodage cible, un caractère de remplacement par défaut sera utilisé. La valeur de retour est un pointeur vers la valeur stockée dans la DString.

Tcl_UtfToExternal convertit un tampon source src de UTF-8 vers l'encodage spécifié encoding. Jusqu'à srcLen octets sont convertis à partir du tampon source et jusqu'à dstLen octets convertis sont stockés dans dst. Dans tous les cas, *srcReadPtr est rempli avec le nombre d'octets qui ont été convertis avec succès à partir de src et *dstWrotePtr est rempli avec le nombre correspondant d'octets qui ont été stockés dans dst. Les valeurs de retour sont les mêmes que les valeurs de retour pour Tcl_ExternalToUtf.

Tcl_WinUtfToTChar et Tcl_WinTCharToUtf sont des fonctions utilitaires spécifiques à Windows pour convertir entre UTF-8 et les chaînes Windows basées sur le type TCHAR, qui est par convention un caractère Unicode sous Windows NT.

Tcl_GetEncodingName est à peu près l'inverse de Tcl_GetEncoding. Étant donné un encoding, la valeur de retour est l'argument name qui a été utilisé pour créer l'encodage. La chaîne retournée par Tcl_GetEncodingName n'est garantie de persister que jusqu'à ce que l'encoding soit supprimé. L'appelant ne doit pas modifier cette chaîne.

Tcl_SetSystemEncoding définit l'encodage par défaut qui doit être utilisé chaque fois que l'utilisateur passe une valeur NULL pour l'argument encoding à l'une des autres fonctions d'encodage. Si name est NULL, l'encodage système est réinitialisé à l'encodage système par défaut, binary. Si le nom ne fait référence à aucun encodage connu ou chargeable, TCL_ERROR est retourné et un message d'erreur est laissé dans interp. Sinon, cette procédure incrémente le compteur de références du nouvel encodage système, décrémente le compteur de références de l'ancien encodage système et retourne TCL_OK.

Tcl_GetEncodingNameFromEnvironment fournit un moyen pour la bibliothèque Tcl de rapporter le nom d'encodage qu'elle estime être le bon à utiliser comme encodage système, basé sur des appels système et l'examen de l'environnement adapté à la plateforme. Il accepte bufPtr, un pointeur vers une Tcl_DString non initialisée ou libérée et y écrit le nom de l'encodage. La valeur Tcl_DStringValue est retournée.

Tcl_GetEncodingNames définit le résultat interp sur une liste constituée des noms de tous les encodages qui sont actuellement définis ou qui peuvent être chargés dynamiquement, en recherchant dans le chemin d'encodage spécifié par Tcl_SetDefaultEncodingDir. Cette procédure ne garantit pas que les fichiers d'encodage chargeables dynamiquement contiennent des données valides, mais seulement qu'ils existent.

Tcl_CreateEncoding définit un nouvel encodage et enregistre les procédures C qui sont appelées en retour pour convertir entre l'encodage et UTF-8. Les encodages créés par Tcl_CreateEncoding sont par la suite visibles dans la base de données utilisée par Tcl_GetEncoding. Tout comme avec la procédure Tcl_GetEncoding, la valeur de retour est un jeton qui représente l'encodage et peut être utilisé dans les appels ultérieurs à d'autres fonctions d'encodage. Tcl_CreateEncoding retourne un encodage avec un compteur de références de 1. Si un encodage avec le nom spécifié name existe déjà, son entrée dans la base de données est remplacée par le nouvel encodage ; le jeton de l'ancien encodage restera valide et continuera de se comporter comme avant, mais les utilisateurs du nouveau jeton appelleront désormais les nouvelles procédures d'encodage.

L'argument typePtr de Tcl_CreateEncoding contient des informations sur le nom de l'encodage et les procédures qui seront appelées pour convertir entre cet encodage et UTF-8. Il est défini comme suit :

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

L'élément encodingName fournit un nom sous forme de chaîne pour l'encodage, par lequel il peut être référencé dans d'autres procédures telles que Tcl_GetEncoding. L'élément toUtfProc fait référence à une procédure de rappel à invoquer pour convertir du texte de cet encodage en UTF-8. L'élément fromUtfProc fait référence à une procédure de rappel à invoquer pour convertir du texte d'UTF-8 vers cet encodage. L'élément freeProc fait référence à une procédure de rappel à invoquer lorsque cet encodage est supprimé. Le champ freeProc peut être NULL. L'élément clientData contient une valeur arbitraire d'un mot passée à toUtfProc, fromUtfProc et freeProc chaque fois qu'ils sont appelés. Typiquement, il s'agit d'un pointeur vers une structure de données contenant des informations spécifiques à l'encodage qui peuvent être utilisées par les procédures de rappel. Par exemple, deux encodages très similaires tels que ascii et macRoman peuvent utiliser la même procédure de rappel, mais utiliser différentes valeurs de clientData pour contrôler son comportement. L'élément nullSize spécifie le nombre d'octets zéro qui signifient la fin de la chaîne dans cet encodage. Il doit être de 1 (pour les encodages à un octet ou à plusieurs octets comme ASCII ou Shift-JIS) ou de 2 (pour les encodages à deux octets comme Unicode). Les encodages de taille constante avec 3 octets ou plus par caractère (comme CNS11643) ne sont pas acceptés.

Les procédures de rappel toUtfProc et fromUtfProc doivent correspondre au type Tcl_EncodingConvertProc :

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

Les procédures toUtfProc et fromUtfProc sont appelées par la famille de fonctions Tcl_ExternalToUtf ou Tcl_UtfToExternal pour effectuer la conversion réelle. Le paramètre clientData de ces procédures est le même que le champ clientData spécifié à Tcl_CreateEncoding lors de la création de l'encodage. Les autres arguments des procédures de rappel sont les mêmes que les arguments, documentés en haut, de Tcl_ExternalToUtf ou Tcl_UtfToExternal, avec les exceptions suivantes. Si l'argument srcLen de l'une de ces fonctions de haut niveau est négatif, la valeur passée à la procédure de rappel sera la longueur de chaîne spécifique à l'encodage appropriée de src. Si l'un des arguments srcReadPtr, dstWrotePtr ou dstCharsPtr de l'une des fonctions de haut niveau est NULL, la valeur correspondante passée à la procédure de rappel sera un emplacement non NULL.

La procédure de rappel freeProc, si elle n'est pas NULL, doit correspondre au type Tcl_EncodingFreeProc :

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

Cette fonction freeProc est appelée lorsque l'encodage est supprimé. Le paramètre clientData est le même que le champ clientData spécifié à Tcl_CreateEncoding lors de la création de l'encodage.

Tcl_GetEncodingSearchPath et Tcl_SetEncodingSearchPath sont appelés pour accéder et définir la liste des répertoires du système de fichiers recherchés pour les fichiers de données d'encodage.

La valeur retournée par Tcl_GetEncodingSearchPath est la valeur stockée par le dernier appel réussi à Tcl_SetEncodingSearchPath. Si aucun appel à Tcl_SetEncodingSearchPath n'a eu lieu, Tcl calculera une valeur initiale basée sur l'environnement. Il existe un seul chemin de recherche d'encodage pour l'ensemble du processus, partagé par tous les threads du processus.
