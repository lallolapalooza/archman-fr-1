ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour la signalisation d'erreur et pour rechercher un canal enregistré dans celui-ci.
const char *fileName (in)
Le nom d'un fichier local ou réseau.
const char *mode (in)
Spécifie comment le fichier doit être accédé. Peut avoir n'importe laquelle des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (in)
Indicateurs de permission de type POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront définies sur le fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans commutateur de la commande Tcl exec.
int flags (in)
Spécifie la disposition des descripteurs stdio dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, l'entrée standard du premier processus enfant du pipeline est le canal du pipeline, sinon elle est identique à l'entrée standard du processus appelant ; idem pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, alors le pipeline peut rediriger les descripteurs stdio pour remplacer les descripteurs stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, alors de telles redirections provoquent une erreur.
ClientData handle (in)
Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, il s'agit d'un descripteur de fichier, pour Windows, d'un HANDLE.
int readOrWrite (in)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (in)
Le motif à faire correspondre, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl pour l'entrée ou la sortie. Doit être la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker les caractères lus du canal.
int charsToRead (in)
Le nombre de caractères à lire du canal. Si le codage du canal est binary, ceci est équivalent au nombre d'octets à lire du canal.
int appendFlag (in)
Si différent de zéro, les données lues du canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (out)
Un tampon dans lequel stocker les octets lus du canal.
int bytesToRead (in)
Le nombre d'octets à lire du canal. Le tampon readBuf doit être assez grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle stocker la ligne lue du canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne dynamique Tcl dans laquelle stocker la ligne lue du canal. Doit avoir été initialisé par l'appelant. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne dynamique.
const char *input (in)
L'entrée à ajouter à un tampon de canal.
int inputLen (in)
Longueur de l'entrée.
int addAtEnd (in)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon du canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera envoyé en sortie vers le canal.
const char *charBuf (in)
Un tampon contenant les caractères à envoyer en sortie vers le canal.
const char *byteBuf (in)
Un tampon contenant les octets à envoyer en sortie vers le canal.
int bytesToWrite (in)
Le nombre d'octets à consommer de charBuf ou byteBuf et à envoyer en sortie vers le canal.
Tcl_WideInt offset (in)
Distance à parcourir dans le canal où la prochaine opération d'entrée ou de sortie sera appliquée, mesurée en octets à partir de la position donnée par seekMode. Peut être positif ou négatif.
int seekMode (in)
Par rapport à quel point effectuer la recherche ; utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs légales sont SEEK_SET, SEEK_CUR, et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) à laquelle tronquer le canal.
const char *optionName (in)
Le nom d'une option applicable à ce canal, telle que -blocking. Peut avoir n'importe laquelle des valeurs acceptées par la commande fconfigure.
Tcl_DString *optionValue (in)
Où stocker la valeur d'une option ou une liste de toutes les options et leurs valeurs. Doit avoir été initialisé par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des périphériques et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie mises en mémoire tampon sur une variété de types de fichiers, de sockets et de périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant une interface de pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée du manuel pour Tcl_CreateChannel. Le mécanisme de canaux fournit un schéma de mise en mémoire tampon inspiré de l'E/S standard d'Unix, et il permet également les E/S non bloquantes sur les canaux.

Les procédures décrites dans cette entrée du manuel comprennent les API C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canal et de la manière d'implémenter des pilotes de canal pour de nouveaux types de canaux, voir l'entrée du manuel pour Tcl_CreateChannel.

TCL_OPENFILECHANNEL

La procédure Tcl_OpenFileChannel ouvre un fichier nommé fileName et lui associe un canal Tcl. Le comportement de l'ouverture est contrôlé par mode et permissions. L'argument mode est une chaîne de caractères qui peut avoir n'importe quelle valeur valide pour l'argument mode de la commande Tcl open (par exemple, "r", "w", "rb+"). L'argument permissions spécifie les permissions POSIX à utiliser si un nouveau fichier est créé ; il est ignoré si le fichier existe déjà. La valeur de retour est un handle de canal Tcl, ou NULL si une erreur se produit (auquel cas un message d'erreur est écrit dans interp).

TCL_OPENCOMMANDCHANNEL

La procédure Tcl_OpenCommandChannel crée un pipeline de processus. Elle prend en argument une liste de commandes à exécuter en pipeline. Le premier argument est la commande la plus à gauche, le deuxième est la commande suivante, etc. Les arguments argc et argv sont un tableau de chaînes de caractères contenant les noms des commandes et leurs arguments. Les arguments flags contrôlent la manière dont les canaux standard (stdin, stdout, stderr) des processus enfants sont gérés. Si le drapeau TCL_STDIN est défini, l'entrée standard du premier processus est le nouveau canal créé. Si TCL_STDOUT est défini, la sortie standard du dernier processus est le nouveau canal créé. Si TCL_STDERR est défini, la sortie d'erreur standard du dernier processus est le nouveau canal créé. Le canal retourné par cette fonction est le canal de la sortie standard du dernier processus. Si une erreur se produit, NULL est retourné et un message d'erreur est écrit dans interp.

TCL_MAKEFILECHANNEL

La procédure Tcl_MakeFileChannel enregistre un descripteur de fichier (ou un handle de système d'exploitation équivalent) existant en tant que canal Tcl. L'argument handle est le descripteur de fichier ou le handle, et readOrWrite spécifie s'il s'agit d'un canal de lecture, d'écriture ou des deux (combinaison OR de TCL_READABLE et TCL_WRITABLE). La valeur de retour est un handle de canal Tcl, ou NULL en cas d'erreur.

TCL_GETCHANNEL

La procédure Tcl_GetChannel recherche un canal par son nom. channelName est le nom du canal à rechercher (par exemple, "file0"). Si modePtr est non NULL, il pointe vers un entier qui recevra une valeur indiquant si le canal est lisible et/ou écrivable (TCL_READABLE, TCL_WRITABLE).

TCL_GETCHANNELNAMES

La procédure Tcl_GetChannelNames renvoie une liste de tous les noms de canaux actuellement ouverts dans l'interpréteur interp. Les noms sont stockés sous forme d'une valeur Tcl object dans l'interpréteur, à la clé "::TclChannels::channelNames". La valeur retournée est 0 en cas de succès, -1 en cas d'erreur.

TCL_GETCHANNELNAMESEX

La procédure Tcl_GetChannelNamesEx est similaire à Tcl_GetChannelNames, mais elle ne renvoie que les noms de canaux qui correspondent au motif spécifié par pattern. Le motif est évalué en utilisant la procédure Tcl_StringMatch. Si pattern est NULL, tous les canaux sont retournés.

TCL_REGISTERCHANNEL

La procédure Tcl_RegisterChannel enregistre un canal donné dans l'interpréteur interp sous le nom qui lui a été attribué lors de sa création. Après l'enregistrement, le canal peut être accédé par son nom à l'aide de procédures telles que Tcl_GetChannel.

TCL_UNREGISTERCHANNEL

La procédure Tcl_UnregisterChannel supprime un canal de l'interpréteur interp. Après la désinscription, le canal ne peut plus être accédé par son nom. Cette procédure ne ferme pas le canal ; elle supprime simplement son nom de la table des canaux de l'interpréteur. La valeur retournée est 0 en cas de succès, -1 en cas d'erreur.

TCL_DETACHCHANNEL

La procédure Tcl_DetachChannel sépare un canal de l'interpréteur interp. Le canal est rendu inutilisable par la suite, mais il n'est pas automatiquement fermé. Le descripteur de fichier sous-jacent est retourné. Cette procédure est utile pour transférer des canaux à d'autres processus ou pour des utilisations spéciales. La valeur retournée est le descripteur de fichier sous-jacent, ou un handle d'exploitation du système, ou -1 en cas d'erreur.

TCL_ISTANDARDCHANNEL

La procédure Tcl_IsStandardChannel renvoie 1 si le canal spécifié est l'un des canaux standards (stdin, stdout ou stderr) du processus Tcl, et 0 sinon.

TCL_CLOSE

La procédure Tcl_Close ferme un canal Tcl. Toutes les données en attente dans les tampons de sortie sont vidées avant la fermeture. Si une erreur se produit lors de la fermeture, un message d'erreur est écrit dans interp. La valeur retournée est 0 en cas de succès, -1 en cas d'erreur.

TCL_READCHARS

La procédure Tcl_ReadChars lit au plus charsToRead caractères depuis le canal channel et les stocke dans la valeur Tcl pointée par readObjPtr. Si appendFlag est non nul, les caractères lus sont ajoutés à la fin de la valeur existante ; sinon, ils la remplacent. Si le canal est en mode blocage et qu'il n'y a pas assez de données à lire, la procédure attendra que des données soient disponibles. Si une erreur se produit, ou si la fin du fichier est atteinte, la procédure renvoie le nombre de caractères effectivement lus (qui peut être inférieur à charsToRead). Si une erreur se produit, un message d'erreur est écrit dans interp et la valeur retournée est -1.

TCL_READ

La procédure Tcl_Read lit au plus bytesToRead octets depuis le canal channel et les stocke dans le tampon readBuf. Cette procédure est conçue pour être utilisée avec des canaux ouverts en mode binaire. Si le canal est en mode blocage et qu'il n'y a pas assez de données à lire, la procédure attendra que des données soient disponibles. Elle renvoie le nombre d'octets effectivement lus, qui peut être inférieur à bytesToRead. Si une erreur se produit, un message d'erreur est écrit dans interp et la valeur retournée est -1.

TCL_GETSOBJ

La procédure Tcl_GetsObj lit une ligne complète depuis le canal channel (jusqu'à un caractère de nouvelle ligne inclus) et stocke le résultat dans la valeur Tcl pointée par lineObjPtr. La ligne lue est ajoutée à la valeur existante de lineObjPtr. Si un caractère de nouvelle ligne est lu, il est inclus dans le résultat. Si la fin du fichier est atteinte avant la lecture d'une nouvelle ligne, la procédure renvoie le contenu restant du tampon de lecture. Si une erreur se produit, -1 est retourné et un message d'erreur est écrit dans interp. Sinon, 0 est retourné.

TCL_GETS

La procédure Tcl_Gets est similaire à Tcl_GetsObj, mais elle stocke la ligne lue dans la chaîne dynamique Tcl pointée par lineRead. La ligne lue est ajoutée à la chaîne dynamique existante. La procédure renvoie le nombre d'octets effectivement lus. Si la fin du fichier est atteinte, la valeur retournée peut être inférieure au nombre d'octets précédemment lus. Si une erreur se produit, -1 est retourné et un message d'erreur est écrit dans interp.

TCL_UNGETS

La procédure Tcl_Ungets ajoute une chaîne de caractères input de longueur inputLen à un canal. Si addAtEnd est non nul, l'entrée est ajoutée à la fin du tampon d'entrée du canal (ce qui la rend disponible pour de futures lectures). Si addAtEnd est nul, l'entrée est ajoutée au début du tampon d'entrée du canal, ce qui lui donne la priorité sur les données déjà présentes dans le tampon. Cette procédure est utile pour simuler des entrées qui n'ont pas encore été réellement lues depuis la source. La valeur retournée est le nombre d'octets ajoutés au tampon, ou -1 en cas d'erreur.

TCL_WRITEOBJ

La procédure Tcl_WriteObj écrit le contenu de la valeur Tcl pointée par writeObjPtr en sortie vers le canal channel. Les données sont écrites dans les tampons de sortie et peuvent ne pas être immédiatement transférées vers le périphérique sous-jacent. Si une erreur se produit pendant l'écriture, un message d'erreur est écrit dans interp et la valeur retournée est -1. Sinon, la valeur retournée est le nombre d'octets effectivement écrits.

TCL_WRITECHARS

La procédure Tcl_WriteChars écrit bytesToWrite caractères du tampon charBuf en sortie vers le canal channel. Si le canal est en mode blocage et que le tampon de sortie est plein, la procédure attendra que de l'espace soit disponible. Si une erreur se produit, un message d'erreur est écrit dans interp et la valeur retournée est -1. Sinon, la valeur retournée est le nombre d'octets effectivement écrits.

TCL_WRITE

La procédure Tcl_Write est similaire à Tcl_WriteChars, mais elle écrit bytesToWrite octets du tampon byteBuf en sortie vers le canal channel. Elle est conçue pour être utilisée avec des canaux ouverts en mode binaire.

TCL_READRAW

La procédure Tcl_ReadRaw lit au plus bytesToRead octets depuis le canal channel et les stocke dans le tampon readBuf. Contrairement à Tcl_Read, cette procédure ne prend pas en compte le codage du canal et lit les données telles quelles. Elle est utile pour lire des données binaires brutes.

TCL_WRITERAW

La procédure Tcl_WriteRaw écrit bytesToWrite octets du tampon byteBuf en sortie vers le canal channel. Contrairement à Tcl_Write, cette procédure n'effectue aucune conversion de codage et écrit les données telles quelles. Elle est utile pour écrire des données binaires brutes.

TCL_EOF

La procédure Tcl_Eof renvoie 1 si la fin du fichier a été atteinte pour le canal channel, et 0 sinon. Elle ne renvoie 1 que si une tentative de lecture a échoué parce que la fin du fichier a été atteinte.

TCL_FLUSH

La procédure Tcl_Flush force le vidage de tous les tampons de sortie associés au canal channel. Les données sont écrites dans le périphérique sous-jacent. La valeur retournée est 0 en cas de succès, -1 en cas d'erreur.

TCL_INPUTBLOCKED

La procédure Tcl_InputBlocked renvoie 1 si le canal channel est actuellement bloqué en lecture (c'est-à-dire qu'une lecture ne retournerait pas immédiatement, même s'il n'y a pas de données disponibles), et 0 sinon. Ceci est utile pour déterminer si une opération de lecture non bloquante échouera.

TCL_INPUTBUFFERED

La procédure Tcl_InputBuffered renvoie le nombre d'octets actuellement présents dans le tampon d'entrée du canal channel.

TCL_OUTPUTBUFFERED

La procédure Tcl_OutputBuffered renvoie le nombre d'octets actuellement présents dans le tampon de sortie du canal channel qui n'ont pas encore été écrits sur le périphérique sous-jacent.

TCL_SEEK

La procédure Tcl_Seek ajuste la position de lecture/écriture du canal channel. L'argument offset spécifie la distance en octets à déplacer. L'argument seekMode détermine par rapport à quel point le déplacement est effectué : SEEK_SET (début du fichier), SEEK_CUR (position actuelle) ou SEEK_END (fin du fichier). La procédure renvoie la nouvelle position du canal en octets à partir du début du fichier, ou -1 en cas d'erreur.

TCL_TELL

La procédure Tcl_Tell renvoie la position actuelle de lecture/écriture du canal channel en octets à partir du début du fichier. Elle renvoie -1 en cas d'erreur.

TCL_TRUNCATECHANNEL

La procédure Tcl_TruncateChannel tronque le fichier associé au canal channel à la longueur spécifiée par length. Si la longueur actuelle du fichier est inférieure à length, le fichier est étendu. La valeur retournée est 0 en cas de succès, -1 en cas d'erreur.

TCL_GETCHANNELOPTION

La procédure Tcl_GetChannelOption récupère la valeur de l'option spécifiée par optionName pour le canal channel. La valeur est stockée dans la chaîne dynamique pointée par optionValue. Les noms d'options possibles sont les mêmes que ceux acceptés par la commande Tcl fconfigure (par exemple, -blocking, -buffering, -encoding). La valeur retournée est 0 en cas de succès, -1 en cas d'erreur.

TCL_SETCHANNELOPTION

La procédure Tcl_SetChannelOption définit la valeur de l'option spécifiée par optionName pour le canal channel sur la valeur newValue. Les noms et valeurs d'options possibles sont les mêmes que ceux acceptés par la commande Tcl fconfigure. La valeur retournée est 0 en cas de succès, -1 en cas d'erreur.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et retourne une poignée de canal qui peut être utilisée pour effectuer des entrées et sorties sur le fichier. Cette API est calquée sur la procédure fopen de la bibliothèque d'E/S standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur la valeur Tcl_FSOpenFileChannel doit être préférée à Tcl_OpenFileChannel chaque fois que possible.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'attribue également comme remplacement pour le canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Elle crée une séquence de sous-processus spécifiés par les arguments argv et argc et retourne un canal qui peut être utilisé pour communiquer avec ces sous-processus. L'argument flags indique quel type de communication existera avec le pipeline de commandes.

Si le drapeau TCL_STDIN est défini, l'entrée standard du premier sous-processus sera liée au canal : écrire dans le canal fournira des données au sous-processus. Si TCL_STDIN n'est pas défini, alors l'entrée standard du premier sous-processus sera la même que l'entrée standard de cette application. Si TCL_STDOUT est défini, la sortie standard du dernier sous-processus pourra être lue à partir du canal ; sinon, elle ira à la sortie standard de cette application. Si TCL_STDERR est défini, la sortie d'erreur standard de tous les sous-processus sera renvoyée au canal et entraînera une erreur lors de la fermeture du canal ; sinon, elle ira à la sortie d'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas défini, alors argc et argv peuvent rediriger les descripteurs stdio pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, alors c'est une erreur pour argc et argv de remplacer les canaux stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'attribue également comme remplacement pour le canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'une poignée de fichier existante, spécifique à la plateforme. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'attribue également comme remplacement pour le canal standard.

TCL_GETCHANNEL

Tcl_GetChannel retourne un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur Tcl dans interp. Si un canal portant ce nom n'est pas enregistré dans cet interpréteur, la procédure retourne NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms selon le pattern. Si pattern est NULL, alors il n'effectuera aucun filtrage. La valeur de retour est TCL_OK si aucune erreur ne s'est produite lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur peuvent faire référence au canal dans les opérations d'entrée ou de sortie en utilisant le nom donné lors de l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur Tcl peut appeler Tcl_RegisterChannel avec interp comme NULL, pour indiquer qu'il souhaite conserver une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et il ne sera fermé que lorsque le nombre correspondant d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code exécuté en dehors de tout interpréteur de conserver en toute sécurité une référence à un canal qui est également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code gérant les canaux standard. Si aucun canal standard n'a été initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un exposé général sur les canaux standard et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Si cette opération a supprimé la dernière inscription du canal dans un interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur Tcl peut appeler Tcl_UnregisterChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera alors fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel, sauf qu'il fermera également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Au-delà de cela, cette commande n'a aucun autre effet. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin), et retournera TCL_ERROR si on lui passe l'un de ces canaux.

Le code non associé à un interpréteur Tcl peut appeler Tcl_DetachChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. Si c'est le cas, il retourne 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lors de l'appel à Tcl_Close. Les sorties tamponnées sont vidées vers le périphérique de sortie du canal avant la destruction du canal, et toute entrée tamponnée est discardée. S'il s'agit d'un canal bloquant, l'appel ne revient pas tant que toutes les données tamponnées n'ont pas été envoyées avec succès au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a des sorties tamponnées qui ne peuvent pas être écrites sans bloquer, l'appel retourne immédiatement ; la sortie est vidée en arrière-plan et le canal sera fermé une fois que toutes les données tamponnées auront été sorties. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close retourne TCL_OK. Si une erreur se produit, Tcl_Close retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré à l'aide de Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a déjà été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez plutôt utiliser Tcl_UnregisterChannel, qui appellera en interne Tcl_Close lorsque tous les appels à Tcl_RegisterChannel auront été correspondus par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, en convertissant les octets en UTF-8 en fonction de l'encodage du canal et en stockant les données produites dans la représentation chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Définir charsToRead

TCL_READCHARS, TCL_READOBJ, ET TCL_READ

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé étaient disponibles. Ceci est appelé une lecture courte. En mode bloquant, cela ne peut arriver qu'à la fin du fichier. En mode non bloquant, une lecture courte peut également se produire s'il n'y a pas assez d'entrées actuellement disponibles : Tcl_ReadChars renvoie un compte court plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode non bloquant, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour savoir laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les diverses représentations de fin de ligne en la représentation interne canonique \n selon le mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les divers modes spécifiques à la plateforme sont décrits dans l'entrée de manuel de la commande Tcl fconfigure.

En tant qu'optimisation de performance, lors de la lecture depuis un canal avec l'encodage binary, les octets ne sont pas convertis en UTF-8 lors de leur lecture. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr sous forme de tableau d'octets. La représentation de chaîne de cette valeur ne sera construite que si elle est nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette manière, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de la conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'il ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Il consomme des octets de channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par un caractère nul. Son contenu est valide à partir de la position zéro jusqu'à, mais sans inclure, la position indiquée par la valeur de retour.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas l'empilement. Alors que Tcl_Read (et les autres fonctions de l'API) obtiennent toujours leurs données du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_ReadRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer des données du canal inférieur vers la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, convertissant les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée soit vue. Si l'encodage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception des caractères de fin de ligne terminating, sont ajoutés à la représentation de chaîne de lineObjPtr. Les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. Si une erreur se produit, Tcl_GetsObj renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj renvoie également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est renvoyé, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité de l'entrée.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique donnée par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, soit à la tête, soit à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur des données à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si channel a un indicateur EOF « collant » défini, aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets renvoie inputLen ou -1 en cas d'erreur.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données caractère à charBuf. Les caractères UTF-8 dans le tampon sont convertis en l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par un caractère nul et il sort tout jusqu'au nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal sur none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est un compte du nombre d'octets qui ont été acceptés pour la sortie vers le canal. C'est soit un nombre supérieur à zéro pour indiquer le succès, soit -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme conformément à l'option -translation pour le canal. Ceci est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'il accepte une valeur Tcl dont le contenu sera sorti vers le canal. Les caractères UTF-8 dans la représentation de chaîne de writeObjPtr sont convertis en l'encodage du canal et mis en file d'attente pour la sortie vers channel. En tant qu'optimisation de performance, lors de l'écriture dans un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets dans la représentation interne de writeObjPtr sous forme de tableau d'octets sont écrits dans le canal. La représentation de tableau d'octets de la valeur sera construite si elle est nécessaire. De cette manière, des données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de la conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'il ne fait pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour la compatibilité ascendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par un caractère nul et il sort tout jusqu'au nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer des données de la transformation dans le canal inférieur.

TCL_FLUSH

Tcl_Flush provoque l'écriture de toutes les données de sortie mises en mémoire tampon pour channel dans son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne que lorsque toutes les données mises en mémoire tampon ont été envoyées au canal ou qu'une erreur s'est produite. L'appel retourne immédiatement si le canal est non bloquant ; il démarre une opération de vidage en arrière-plan qui écrira les données mises en mémoire tampon dans le canal éventuellement, aussi rapidement que le canal est capable de les absorber.

La valeur de retour est normalement TCL_OK. En cas d'erreur, Tcl_Flush renvoie TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données subséquentes seront lues ou écrites. La sortie mise en mémoire tampon est vidée vers le canal et l'entrée mise en mémoire tampon est discardée, avant l'opération de recherche.

Tcl_Seek renvoie normalement le nouveau point d'accès. En cas d'erreur, Tcl_Seek renvoie -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut ou non avoir été déplacé.

TCL_TELL

Tcl_Tell renvoie le point d'accès actuel d'un canal. La valeur renvoyée est -1 si le canal ne prend pas en charge la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent à channel à une longueur donnée de length octets. Il renvoie TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, c'est le nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue, uti

ng a series of calls to Tcl_DStringAppendElement. Les différentes options préexistantes et leurs valeurs possibles sont décrites dans la page de manuel de la commande Tcl fconfigure. D'autres options peuvent être ajoutées par chaque type de canal. Ces options spécifiques au type de canal sont décrites dans la page de manuel de la commande Tcl qui crée un canal de ce type ; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans la page de manuel de la commande Tcl socket. La procédure retourne normalement TCL_OK. Si une erreur se produit, elle retourne TCL_ERROR et appelle Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit une nouvelle valeur newValue pour une option optionName sur le channel. La procédure retourne normalement TCL_OK. Si une erreur se produit, elle retourne TCL_ERROR ; de plus, si interp n'est pas NULL, Tcl_SetChannelOption laisse un message d'erreur dans le résultat de l'interpréteur.

TCL_EOF

Tcl_Eof retourne une valeur non nulle si le channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked retourne une valeur non nulle si le channel est en mode non bloquant et que la dernière opération d'entrée a retourné moins de données que demandé parce qu'il n'y avait pas suffisamment de données disponibles. L'appel retourne toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered retourne le nombre d'octets d'entrée actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en lecture, cette fonction retourne toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered retourne le nombre d'octets de sortie actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en écriture, cette fonction retourne toujours zéro.

PROBLÈMES DE PLATEFORME

Les descripteurs retournés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que retourné par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel ou Tcl_MakeFileChannel. D'autres types de canaux peuvent retourner un type différent de descripteur sur les plateformes Windows.
