L'interpréteur contenant l'objet ou la classe à laquelle créer ou mettre à jour une méthode.

L'objet auquel attacher la méthode.

La classe à laquelle attacher la méthode.

Le nombre d'arguments passés à l'implémentation de la méthode qui ne représentent pas d'arguments "réels".

DESCRIPTION

Une méthode est une opération effectuée sur un objet et associée à cet objet. Chaque méthode doit être attachée soit à un objet, soit à une classe ; les méthodes attachées à une classe sont associées à toutes les instances (directes et indirectes) de cette classe.

À partir d'une méthode, l'entité qui l'a déclarée peut être trouvée à l'aide de Tcl_MethodDeclarerClass qui renvoie la classe à laquelle la méthode est attachée (ou NULL si la méthode n'est attachée à aucune classe), et Tcl_MethodDeclarerObject qui renvoie l'objet auquel la méthode est attachée (ou NULL si la méthode n'est pas attachée à un objet). Le nom de la méthode peut être récupéré avec Tcl_MethodName et si la méthode est exportée ou non est récupéré avec Tcl_MethodIsPublic. Le type de la méthode peut également être introspecté dans une mesure limitée ; la fonction Tcl_MethodIsType renvoie si une méthode est d'un type particulier, en assignant le clientData par méthode à la variable pointée par clientDataPtr si (celui-ci est non NULL) si le type correspond.

CREATION DE MÉTHODE

Les méthodes sont créées par Tcl_NewMethod et Tcl_NewInstanceMethod, qui créent une méthode attachée à une classe ou à un objet respectivement. Dans les deux cas, l'argument nameObj donne le nom de la méthode à créer, l'argument isPublic indique si la méthode doit être exportée initialement, l'argument methodTypePtr décrit l'implémentation de la méthode (voir la section TYPES DE MÉTHODES ci-dessous) et l'argument clientData donne des données spécifiques à l'implémentation qui sont transmises à l'implémentation de la méthode lorsqu'elle est appelée.

Lorsque l'argument nameObj de Tcl_NewMethod est NULL, une méthode sans nom est créée, qui est utilisée pour les constructeurs et les destructeurs. Les constructeurs doivent être installés dans leur classe à l'aide de la fonction Tcl_ClassSetConstructor, et les destructeurs (qui ne doivent nécessiter aucun argument) doivent être installés dans leur classe à l'aide de la fonction Tcl_ClassSetDestructor. Les méthodes sans nom ne doivent pas être utilisées à d'autres fins, et les méthodes nommées ne doivent pas être utilisées comme constructeurs ou destructeurs. Notez également qu'un methodTypePtr NULL est utilisé pour fournir un signal interne et ne doit pas être utilisé dans le code client.

CONTEXTES D'APPEL DE MÉTHODE

Lorsqu'une méthode est appelée, une référence de contexte d'appel de méthode est passée comme l'un des arguments à la fonction d'implémentation. Ce contexte peut être inspecté pour fournir des informations sur l'appelant, mais ne doit pas être conservé au-delà du moment où l'appel de méthode se termine.

La méthode qui est appelée peut être récupérée du contexte en utilisant Tcl_ObjectContextMethod, et l'objet qui a provoqué l'invocation de la méthode peut être récupéré avec Tcl_ObjectContextObject. Le nombre d'arguments qui doivent être ignorés (par exemple, le nom de l'objet et le nom de la méthode dans un appel de méthode normal) est lu avec Tcl_ObjectContextSkippedArgs, et le contexte peut également signaler s'il fonctionne comme un filtre pour une autre méthode via Tcl_ObjectContextIsFiltering.

Pendant l'exécution d'une méthode, l'implémentation de la méthode peut choisir d'invoquer les étapes de la chaîne d'appel de méthode qui viennent après l'implémentation de la méthode actuelle. Ceci (le cœur de la commande next) est fait à l'aide de Tcl_ObjectContextInvokeNext. Notez que cette fonction ne manipule pas la pile des cadres d'appel, contrairement à la commande next ; si l'implémentation de la méthode a poussé un ou plusieurs cadres supplémentaires sur la pile dans le cadre de son implémentation, elle est également responsable de dépiler temporairement ces cadres pendant l'exécution de la fonction Tcl_ObjectContextInvokeNext. Notez également que le contexte d'appel de méthode n'est *jamais* supprimé pendant l'exécution de cette fonction.

TYPES DE MÉTHODES

Les types de méthodes sont décrits par un pointeur vers une structure Tcl_MethodType, qui est définie comme suit :

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

Le champ version permet une expansion future de la structure et doit toujours être déclaré égal à TCL_OO_METHOD_VERSION_CURRENT. Le champ name fournit un nom lisible par l'homme pour le type, et est la valeur exposée via les commandes Tcl info class methodtype et info object methodtype.

Le champ callProc fournit une fonction qui est appelée lorsque la méthode est invoquée ; il ne doit jamais être NULL.

Le champ deleteProc fournit une fonction qui est utilisée pour supprimer une méthode particulière, et est appelée lorsque la méthode est remplacée ou supprimée ; si le champ est NULL, on suppose que le clientData de la méthode ne nécessite aucune action spéciale pour être supprimé.

Le champ cloneProc est soit une fonction utilisée pour copier le clientData d'une méthode (dans le cadre de Tcl_CopyObjectInstance), soit NULL pour indiquer que le clientData peut simplement être copié directement.

SIGNATURE DE FONCTION TCL_METHODCALLPROC

La signature de la fonction callProc est la suivante :

typedef int (*Tcl_MethodCallProc)(
    ClientData clientData,
    Tcl_Interp *interp,
    int objc,
    Tcl_Obj *const *objv);

    DESCRIPTION

    Ces fonctions fournissent une interface pour gérer les méthodes dans le système d'objets TclOO. Elles permettent de déclarer, créer, supprimer, rechercher et appeler des méthodes associées à des classes et des objets TclOO.

    Les fonctions clés incluent:

    Tcl_NewMethod et Tcl_NewInstanceMethod:
    Créent de nouvelles méthodes pour une classe donnée. Tcl_NewMethod crée une méthode de classe, tandis que Tcl_NewInstanceMethod crée une méthode d'instance.
    Tcl_MethodCallProc:
    La signature de type pour les procédures de rappel qui implémentent la logique d'une méthode.
    Tcl_MethodDeleteProc:
    La signature de type pour les procédures de rappel qui nettoient les ressources associées à une méthode lorsqu'elle est supprimée.
    Tcl_CloneProc:
    La signature de type pour les procédures de rappel utilisées pour copier les données d'une méthode lors du clonage d'un objet.
    Tcl_MethodLookup et Tcl_MethodLookupSuper:
    Recherchent une méthode dans une classe et ses superclasses.
    Tcl_MethodCall et Tcl_MethodCallSuper:
    Appellent une méthode sur un objet donné, en tenant compte de la chaîne d'héritage.

    TYPES DE MÉTHODES

    Le système TclOO prend en charge plusieurs types de méthodes, chacun ayant un comportement et un objectif spécifique:

    SIGNATURE DE FONCTION TCL_METHODCALLPROC

    Les fonctions correspondant à cette signature sont appelées lorsque la méthode est invoquée.

    typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

    L'argument clientData d'un Tcl_MethodCallProc est la valeur qui a été donnée lors de la création de la méthode, interp est un endroit pour exécuter des scripts et accéder aux variables, ainsi que pour placer le résultat de la méthode, et les champs objc et objv donnent les objets paramètres à la méthode. Le contexte d'appel de la méthode peut être découvert via l'argument objectContext, et la valeur de retour d'un Tcl_MethodCallProc est n'importe quel code de retour Tcl (par exemple, TCL_OK, TCL_ERROR).

    SIGNATURE DE FONCTION TCL_METHODDELETEPROC

    Les fonctions correspondant à cette signature sont utilisées lors de la suppression d'une méthode, que ce soit par la création d'une nouvelle méthode ou parce que l'objet ou la classe est supprimé.

    typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

    L'argument clientData d'un Tcl_MethodDeleteProc sera la même que la valeur passée à l'argument clientData de Tcl_NewMethod ou Tcl_NewInstanceMethod lors de la création de la méthode.

    SIGNATURE DE FONCTION TCL_CLONEPROC

    Les fonctions correspondant à cette signature sont utilisées pour copier une méthode lorsque l'objet ou la classe est copié en utilisant Tcl_CopyObjectInstance (ou oo::copy).

    typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

    L'argument interp fournit un endroit pour écrire un message d'erreur lorsque la tentative de clonage de l'objet échoue, auquel cas la procédure de clonage doit également retourner TCL_ERROR ; elle doit retourner TCL_OK sinon. Le champ oldClientData d'un Tcl_CloneProc donne la valeur de la méthode en cours de copie, et le champ newClientDataPtr pointra vers une variable dans laquelle écrire la valeur pour la méthode en cours de copie.
