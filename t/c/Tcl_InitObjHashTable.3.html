Tcl_Hash(3) Procédures de la bibliothèque Tcl Tcl_Hash(3)

NAME

Tcl_InitHashTable, Tcl_InitCustomHashTable, Tcl_InitObjHashTable, Tcl_DeleteHashTable, Tcl_CreateHashEntry, Tcl_DeleteHashEntry, Tcl_FindHashEntry, Tcl_GetHashValue, Tcl_SetHashValue, Tcl_GetHashKey, Tcl_FirstHashEntry, Tcl_NextHashEntry, Tcl_HashStats - procédures pour gérer les tables de hachage

SYNOPSIS

#include <tcl.h>

Tcl_InitHashTable(tablePtr, keyType)

Tcl_InitCustomHashTable(tablePtr, keyType, typePtr)

Tcl_InitObjHashTable(tablePtr)

Tcl_DeleteHashTable(tablePtr)

Tcl_HashEntry *
Tcl_CreateHashEntry(tablePtr, key, newPtr)

Tcl_DeleteHashEntry(entryPtr)

Tcl_HashEntry *
Tcl_FindHashEntry(tablePtr, key)

ClientData
Tcl_GetHashValue(entryPtr)

Tcl_SetHashValue(entryPtr, value)

void *
Tcl_GetHashKey(tablePtr, entryPtr)

Tcl_HashEntry *
Tcl_FirstHashEntry(tablePtr, searchPtr)

Tcl_HashEntry *
Tcl_NextHashEntry(searchPtr)

char *
Tcl_HashStats(tablePtr)

ARGUMENTS

Tcl_HashTable *tablePtr (entrée)
Adresse d'une structure décrivant la table de hachage (pour toutes les procédures sauf Tcl_InitHashTable, cette structure doit avoir été précédemment initialisée par un appel à Tcl_InitHashTable).
int keyType (entrée)
Type de clés à utiliser pour la table de hachage. Doit être l'une des valeurs suivantes : TCL_STRING_KEYS, TCL_ONE_WORD_KEYS, TCL_CUSTOM_TYPE_KEYS, TCL_CUSTOM_PTR_KEYS, ou une valeur entière supérieure à 1.
Tcl_HashKeyType *typePtr (entrée)
Adresse de la structure définissant le comportement de la table de hachage.
const void *key (entrée)
Clé à utiliser pour la recherche dans la table. La forme exacte dépend du keyType utilisé pour créer la table.
int *newPtr (sortie)
La valeur de *newPtr est définie sur 1 si une nouvelle entrée a été créée et sur 0 s'il existait déjà une entrée pour la key.
Tcl_HashEntry *entryPtr (entrée)
Adresse d'une entrée de table de hachage.
ClientData value (entrée)
Nouvelle valeur à assigner à l'entrée de la table de hachage. Il n'est pas nécessaire qu'elle soit de type ClientData, mais elle doit s'ajuster dans le même espace que le type ClientData.
Tcl_HashSearch *searchPtr (entrée)
Adresse de la structure à utiliser pour suivre la progression dans l'énumération de toutes les entrées de la table de hachage.

DESCRIPTION

Une table de hachage se compose de zéro entrée ou plus, chacune étant constituée d'une clé et d'une valeur. Étant donné la clé d'une entrée, les routines de hachage peuvent rapidement localiser l'entrée, et donc sa valeur. Il ne peut y avoir qu'une seule entrée dans une table de hachage ayant une clé spécifique, mais il peut y avoir plusieurs entrées ayant la même valeur. Les clés peuvent prendre l'une des quatre formes suivantes : chaînes de caractères, valeurs d'un seul mot, tableaux d'entiers ou clés personnalisées définies par une structure Tcl_HashKeyType (voir la section THE TCL_HASHKEYTYPE STRUCTURE ci-dessous). Toutes les clés d'une table donnée ont la même forme, qui est spécifiée lors de l'initialisation de la table.

La valeur d'une entrée de table de hachage peut être n'importe quoi qui tient dans l'espace occupé par un pointeur de chaîne. Les valeurs des entrées de table de hachage sont entièrement gérées par les clients, et non par le module de hachage lui-même. Généralement, chaque valeur d'entrée pointe vers un objet géré par le code client.

Les tables de hachage croissent de manière fluide en fonction du nombre d'entrées, ce qui permet d'avoir toujours moins de trois entrées par compartiment en moyenne. Cela permet des requêtes rapides, quel que soit le nombre d'entrées dans une table.

Le noyau fournit trois procédures pour l'initialisation des tables de hachage : Tcl_InitHashTable, Tcl_InitObjHashTable et Tcl_InitCustomHashTable.

Tcl_InitHashTable initialise une structure décrivant une nouvelle table de hachage. L'espace pour la structure est fourni par le client, et non par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. Tous les types de clés mentionnés ci-après sont autorisés, à l'exception de TCL_CUSTOM_TYPE_KEYS et TCL_CUSTOM_PTR_KEYS.

Tcl_InitObjHashTable est un wrapper de Tcl_InitCustomHashTable et initialise une table de hachage dont les clés sont des Tcl_Obj *.

Tcl_InitCustomHashTable initialise une structure décrivant une nouvelle table de hachage. L'espace pour la structure est fourni par le client, et non par le module de hachage. La valeur de keyType indique quels types de clés seront utilisés pour toutes les entrées de la table. KeyType doit avoir l'une des valeurs suivantes :

TCL_STRING_KEYS
Les clés sont des chaînes de caractères terminées par null. Elles sont passées aux routines de hachage en utilisant le pointeur vers le premier caractère de la chaîne.
TCL_ONE_WORD_KEYS
Les clés sont des valeurs d'un seul mot ; elles sont passées aux routines de hachage et stockées dans les entrées de la table sous forme de valeurs de type char *. La valeur du pointeur est la clé ; elle ne doit pas (et ne doit pas le faire) pointer vers une chaîne.
TCL_CUSTOM_TYPE_KEYS
Les clés sont de type arbitraire et sont stockées dans l'entrée. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section THE TCL_HASHKEYTYPE STRUCTURE ci-dessous.
TCL_CUSTOM_PTR_KEYS
Les clés sont des pointeurs vers un type arbitraire et sont stockées dans l'entrée. Le hachage et la comparaison sont déterminés par typePtr. La structure Tcl_HashKeyType est décrite dans la section THE TCL_HASHKEYTYPE STRUCTURE ci-dessous.
autre
Si keyType n'est pas l'une des options ci-dessus, il doit s'agir d'une valeur entière supérieure à 1. Dans ce cas, les clés seront des tableaux de valeurs int, où keyType indique le nombre d'entiers dans chaque clé. Cela permet d'utiliser des structures comme clés. Toutes les clés doivent avoir la même taille. Les clés de tableaux sont passées aux fonctions de hachage en utilisant le pointeur vers le premier int du tableau.

Tcl_DeleteHashTable supprime toutes les entrées d'une table de hachage et libère l'espace associé au tableau des compartiments et aux entrées. Elle ne libère pas la structure de la table elle-même (pointée par tablePtr), car l'espace est supposé appartenir au client. Tcl_DeleteHashTable ne libère ni ne manipule non plus les valeurs des entrées de la table de hachage. Si les valeurs des entrées pointent vers de la mémoire allouée dynamiquement, il incombe au client de libérer ces structures avant de supprimer la table.

Tcl_CreateHashEntry localise l'entrée correspondant à une clé spécifique, créant une nouvelle entrée dans la table si elle n'existe pas déjà. Si une entrée existe déjà avec la même clé, *newPtr est défini sur 0. Si une nouvelle entrée est créée, *newPtr est défini sur une valeur non nulle et la valeur de la nouvelle entrée sera définie sur 0. La valeur retournée par Tcl_CreateHashEntry est un pointeur vers l'entrée, qui peut être utilisé pour récupérer et modifier la valeur de l'entrée ou pour la supprimer de la table.

Tcl_DeleteHashEntry supprimera une entrée existante d'une table. La mémoire associée à l'entrée elle-même sera libérée, mais le client est responsable de tout nettoyage lié à la valeur de l'entrée, comme la libération d'un objet vers lequel elle pointe.

Tcl_FindHashEntry est similaire à Tcl_CreateHashEntry, sauf qu'elle ne crée pas de nouvelle entrée si la clé n'existe pas ; elle retourne plutôt NULL en résultat.

Tcl_GetHashValue et Tcl_SetHashValue sont utilisés pour lire et écrire la valeur d'une entrée, respectivement. Les valeurs sont stockées et récupérées en tant que type ClientData, ce qui est suffisant pour stocker une valeur de pointeur. Dans presque tous les systèmes, cela suffit également pour stocker une valeur entière.

Tcl_GetHashKey renvoie la clé d'une entrée de table de hachage, soit sous forme de pointeur vers une chaîne, d'une clé d'un seul mot (char *), soit comme pointeur vers le premier élément d'un tableau d'entiers, en fonction du keyType utilisé pour créer la table. Dans tous les cas, Tcl_GetHashKey renvoie un résultat de type char *. Lorsque la clé est une chaîne ou un tableau, le résultat de Tcl_GetHashKey pointe vers des informations contenues dans l'entrée de la table de hachage ; ces informations seront valides jusqu'à ce que l'entrée soit supprimée ou que sa table soit supprimée.

Tcl_FirstHashEntry et Tcl_NextHashEntry peuvent être utilisés pour parcourir toutes les entrées d'une table de hachage.

ARGUMENTS

Tcl_HashTable *tablePtr
In: Pointer to the hash table structure to initialize or use. In: Pointer to the hash table structure to use.
const Tcl_HashKeyType *typePtr
In: Pointer to a structure describing the type of keys used in the hash table.
Tcl_HashSearch *searchPtr
In: Pointer to a structure to keep track of the search state.
Tcl_HashEntry *entryPtr
In: Pointer to the hash entry to delete or set the key for.
Tcl_HashKey key
In: The key to find or create. The key is a structure that can hold an integer, a string pointer, or a pointer to arbitrary data.
int *newPtr
Out: If non-NULL, then `*newPtr` is set to 1 if a new entry was created, or 0 if an entry with the given key already existed.

DESCRIPTION

Tcl provides a generic hash table implementation that can be used to store arbitrary key-value pairs. The hash table routines are optimized for speed and are used extensively within Tcl itself for implementing associative arrays, variable lookups, and other dictionary-like data structures. A hash table is managed by a Tcl_HashTable structure. The routines described here allow clients to create, delete, and manipulate hash tables.

The constants TCL_HASH_KEY_RANDOMIZE_HASH and TCL_HASH_KEY_SYSTEM_HASH are also defined in tcl.h.

Tcl_InitHashTable initializes a hash table structure pointed to by tablePtr. The typePtr argument points to a Tcl_HashKeyType structure that describes the type of keys to be used in the hash table. This allows for customization of hashing, comparison, allocation and deallocation of keys. Tcl_InitCustomHashTable does the same, but the `typePtr` is mandatory. If typePtr is NULL, then the default hash table type is used. The default hash table type uses pointers as keys and does not randomize the hash. See section THE TCL_HASHKEYTYPE STRUCTURE below for details on the Tcl_HashKeyType structure.

Tcl_CreateHashTable initializes a hash table structure pointed to by tablePtr using the default hash table type. The default hash table type uses pointers as keys, and does not randomize the hash. This is equivalent to calling Tcl_InitHashTable with typePtr set to NULL.

Tcl_InitObjHashTable initializes a hash table structure pointed to by tablePtr using Tcl objects as keys. This is the most common type of hash table.

Tcl_InitStringHashTable initializes a hash table structure pointed to by tablePtr using null-terminated strings as keys.

Tcl_InitIntHashTable initializes a hash table structure pointed to by tablePtr using integers as keys.

Tcl_DeleteHashTable destroys the hash table pointed to by tablePtr, freeing all entries and associated storage.

Tcl_FindHashEntry searches the hash table for an entry with the given key. It returns a pointer to the entry if found, or NULL otherwise.

Tcl_CreateHashEntry searches the hash table for an entry with the given key. If an entry is found, it returns a pointer to it. If no entry is found, a new entry is created, initialized, and its pointer is returned. If newPtr is not NULL, then `*newPtr` is set to 1 if a new entry was created, or 0 if an entry with the given key already existed.

Tcl_DeleteHashEntry deletes the entry pointed to by entryPtr from the hash table pointed to by tablePtr.

Tcl_SetHashKey sets the key for the hash entry pointed to by entryPtr to the given key. This is normally only used when creating a custom hash table type.

Tcl_GetHashKey returns the key associated with the hash entry pointed to by entryPtr.

The procedures Tcl_FirstHashEntry, Tcl_NextHashEntry, and Tcl_HashStats can be used to iterate over the entries in a hash table. A structure of type "Tcl_HashSearch", provided by the client, is used to keep track of progress through the table. Tcl_FirstHashEntry initializes the search record and returns the first entry in the table (or NULL if the table is empty). Each subsequent call to Tcl_NextHashEntry returns the next entry in the table or NULL if the end of the table has been reached. A call to Tcl_FirstHashEntry followed by calls to Tcl_NextHashEntry will return each of the entries in the table exactly once, in an arbitrary order. It is inadvisable to modify the structure of the table, e.g. by creating or deleting entries, while the search is in progress, with the exception of deleting the entry returned by Tcl_FirstHashEntry or Tcl_NextHashEntry.

Tcl_HashStats returns a dynamically-allocated string with overall information about a hash table, such as the number of entries it contains, the number of buckets in its hash array, and the utilization of the buckets. It is the caller's responsibility to free the result string by passing it to ckfree.

The header file tcl.h defines the actual data structures used to implement hash tables. This is necessary so that clients can allocate Tcl_HashTable structures and so that macros can be used to read and write the values of entries. However, users of the hashing routines should never refer directly to any of the fields of any of the hash-related data structures; use the procedures and macros defined here.

THE TCL_HASHKEYTYPE STRUCTURE

Extension writers can define new hash key types by defining four procedures, initializing a Tcl_HashKeyType structure to describe the type, and calling Tcl_InitCustomHashTable. The Tcl_HashKeyType structure is defined as follows:

typedef struct Tcl_HashKeyType {
    int version;
    int flags;
    Tcl_HashKeyProc *hashKeyProc;
    Tcl_CompareHashKeysProc *compareKeysProc;
    Tcl_AllocHashEntryProc *allocEntryProc;
    Tcl_FreeHashEntryProc *freeEntryProc;
} Tcl_HashKeyType;

The version member is the version of the table. If this structure is extended in future then the version can be used to distinguish between different structures. It should be set to TCL_HASH_KEY_TYPE_VERSION.

The flags member is 0 or one or more of the following values OR'ed together:

TCL_HASH_KEY_RANDOMIZE_HASH
There are some things, pointers for example which do not hash well because they do not use the lower bits. If this flag is set then the hash table will attempt to rectify this by randomizing the bits and then using the upper N bits as the index into the table.
TCL_HASH_KEY_SYSTEM_HASH
This flag forces Tcl to use the memory allocation procedures provided by the operating system when allocating and freeing memory used to store the hash table data structures, and not any of Tcl's own customized memory allocation routines. This is important if the hash table is to be used in the implementation of a custom set of allocation routines, or something that a custom set of allocation routines might depend on, in order to avoid any circular dependency.

The hashKeyProc member contains the address of a function called to calculate a hash value for the key.

typedef unsigned int Tcl_HashKeyProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

If this is NULL then keyPtr is used and TCL_HASH_KEY_RANDOMIZE_HASH is assumed.

The compareKeysProc member contains the address of a function called to compare two keys.

typedef int Tcl_CompareHashKeysProc(
        void *keyPtr,
        Tcl_HashEntry *hPtr);

If this is NULL then the keyPtr pointers are compared. If the keys do not match then the function returns 0, otherwise it returns 1.

The allocEntryProc member contains the address of a function called to allocate space for an entry and initialize the key and clientData.

typedef Tcl_HashEntry *Tcl_AllocHashEntryProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

If this is NULL then Tcl_Alloc is used to allocate enough space for a Tcl_HashEntry, the key pointer is assigned to key.oneWordValue and the clientData is set to NULL. String keys and array keys use this function to allocate enough space for the entry and the key in one block, rather than doing it in two blocks. This saves space for a pointer to the key from the entry and another memory allocation. Tcl_Obj* keys use this function to allocate enough space for an entry and increment the reference count on the value.

The freeEntryProc member contains the address of a function called to free space for an entry.

typedef void Tcl_FreeHashEntryProc(
        Tcl_HashEntry *hPtr);

If this is NULL then Tcl_Free is used to free the space for the entry. Tcl_Obj* keys use this function to decrement the reference count on the value.
