Tcl_SetAssocData(3) Procédures de bibliothèque Tcl Tcl_SetAssocData(3)

NOM

Tcl_GetAssocData, Tcl_SetAssocData, Tcl_DeleteAssocData - gérer les associations de clés de chaînes et de données spécifiées par l'utilisateur avec des interpréteurs Tcl

SYNOPIS

#include <tcl.h>

ClientData
Tcl_GetAssocData(interp, key, delProcPtr)

Tcl_SetAssocData(interp, key, delProc, clientData)

Tcl_DeleteAssocData(interp, key)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur dans lequel exécuter la commande spécifiée.
const char *key (in)
Clé pour l'association avec laquelle stocker des données ou à partir de laquelle supprimer ou récupérer des données. Généralement le préfixe du module pour un paquet.
Tcl_InterpDeleteProc *delProc (in)
Procédure à appeler lorsque interp est supprimé.
Tcl_InterpDeleteProc **delProcPtr (in)
Pointeur vers l'emplacement dans lequel stocker l'adresse de la procédure de suppression actuelle pour l'association. Ignoré si NULL.
ClientData clientData (in)
Valeur arbitraire d'un mot associée à la clé donnée dans cet interpréteur. Ces données sont la propriété de l'appelant.

DESCRIPTION

Ces procédures permettent aux extensions d'associer leurs propres données à un interpréteur Tcl. Une association se compose d'une clé de chaîne, généralement le nom de l'extension, et d'une valeur d'un mot, qui est généralement un pointeur vers une structure de données contenant des données spécifiques à l'extension. Tcl n'interprète ni la clé ni la valeur d'une association.

La gestion du stockage est facilitée par le stockage, avec chaque association, d'une procédure à appeler lorsque l'interpréteur est supprimé. Cette procédure peut disposer du stockage occupé par les données du client comme bon lui semble.

Tcl_SetAssocData crée une association entre une clé de chaîne et une donnée spécifiée par l'utilisateur dans l'interpréteur donné. S'il existe déjà une association avec la clé key, Tcl_SetAssocData la remplace par les nouvelles informations. Il appartient aux appelants d'organiser leur utilisation des noms pour éviter les conflits, par exemple, en utilisant les noms de paquets comme clés. Si l'argument deleteProc n'est pas NULL, il spécifie l'adresse d'une procédure à invoquer si l'interpréteur est supprimé avant que l'association ne soit supprimée. DeleteProc doit avoir des arguments et un résultat qui correspondent au type Tcl_InterpDeleteProc :

typedef void Tcl_InterpDeleteProc(
        ClientData clientData,
        Tcl_Interp *interp);

Lorsque deleteProc est invoqué, les arguments clientData et interp seront les mêmes que les arguments correspondants passés à Tcl_SetAssocData. La procédure de suppression ne sera pas invoquée si l'association est supprimée avant que l'interpréteur ne soit supprimé.

Tcl_GetAssocData renvoie la donnée stockée dans l'association avec la clé spécifiée dans l'interpréteur donné, et si le champ delProcPtr n'est pas NULL, l'adresse indiquée par celui-ci reçoit l'adresse de la procédure de suppression stockée avec cette association. Si aucune association avec la clé spécifiée n'existe dans l'interpréteur donné, Tcl_GetAssocData renvoie NULL.

Tcl_DeleteAssocData supprime une association avec une clé spécifiée dans l'interpréteur donné. Ensuite, elle appelle la procédure de suppression.

MOTS-CLÉS

association, données, procédure de suppression, interpréteur, clé
