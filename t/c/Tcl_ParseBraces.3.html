Tcl_ParseCommand(3) Procédures de bibliothèque Tcl Tcl_ParseCommand(3)

NOM

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, Tcl_ParseVarName, Tcl_ParseVar, Tcl_FreeParse, Tcl_EvalTokens, Tcl_EvalTokensStandard - analyse les scripts et expressions Tcl

SYNTAXE

#include <tcl.h>

int
Tcl_ParseCommand(interp, start, numBytes, nested, parsePtr)

int
Tcl_ParseExpr(interp, start, numBytes, parsePtr)

int
Tcl_ParseBraces(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseQuotedString(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseVarName(interp, start, numBytes, parsePtr, append)

const char *
Tcl_ParseVar(interp, start, termPtr)

Tcl_FreeParse(usedParsePtr)

Tcl_Obj *
Tcl_EvalTokens(interp, tokenPtr, numTokens)

int
Tcl_EvalTokensStandard(interp, tokenPtr, numTokens)

ARGUMENTS

Tcl_Interp *interp (out)
Pour les procédures autres que Tcl_FreeParse, Tcl_EvalTokens et Tcl_EvalTokensStandard, utilisé uniquement pour signaler les erreurs ; si NULL, aucun message d'erreur n'est laissé après les erreurs. Pour Tcl_EvalTokens et Tcl_EvalTokensStandard, détermine le contexte d'évaluation du script et est également utilisé pour signaler les erreurs ; ne doit pas être NULL.
const char *start (in)
Pointeur vers le premier caractère de la chaîne à analyser.
int numBytes (in)
Nombre d'octets dans la chaîne à analyser, sans inclure le caractère nul de terminaison. Si inférieur à 0, le script comprend tous les caractères suivant start jusqu'au premier caractère nul.
int nested (in)
Non-zéro signifie que le script fait partie d'une substitution de commande, donc une parenthèse fermante non citée doit être traitée comme un terminateur de commande. Si zéro, les parenthèses fermantes n'ont pas de signification spéciale.
int append (in)
Non-zéro signifie que *parsePtr contient déjà des jetons valides ; les nouveaux jetons doivent être ajoutés à ceux déjà présents. Zéro signifie que *parsePtr n'est pas initialisé ; toute information qu'il contient est ignorée. Cet argument est normalement 0.
Tcl_Parse *parsePtr (out)
Pointe vers la structure à remplir avec des informations sur la commande analysée, l'expression, le nom de variable, etc. Toute information précédente dans cette structure est ignorée, sauf si append n'est pas zéro dans un appel à Tcl_ParseBraces, Tcl_ParseQuotedString, ou Tcl_ParseVarName.
const char **termPtr (out)
Si non NULL, pointe vers un emplacement où Tcl_ParseBraces, Tcl_ParseQuotedString, et Tcl_ParseVar stockeront un pointeur vers le caractère juste après le caractère de terminaison (la parenthèse fermante, le dernier caractère du nom de variable, ou la guillemet fermant (respectivement)) si l'analyse a réussi.
Tcl_Parse *usedParsePtr (in)
Pointe vers la structure qui a été remplie par un appel précédent à Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseVarName, etc.

DESCRIPTION

Ces procédures analysent les commandes Tcl ou des parties de commandes Tcl telles que des expressions ou des références à des variables. Chaque procédure prend un pointeur vers un script (ou une partie de celui-ci) et remplit la structure pointée par parsePtr avec une collection de jetons décrivant les informations qui ont été analysées. Les procédures retournent normalement TCL_OK. Cependant, si une erreur se produit, elles retournent TCL_ERROR, laissent un message d'erreur dans le résultat de interp (si interp n'est pas NULL), et ne laissent rien dans parsePtr.

Tcl_ParseCommand est une procédure qui analyse les scripts Tcl. Étant donné un pointeur vers un script, elle analyse la première commande du script. Si la commande a été analysée avec succès, Tcl_ParseCommand retourne TCL_OK et remplit la structure pointée par parsePtr avec des informations sur la structure de la commande (voir ci-dessous pour les détails). Si une erreur s'est produite lors de l'analyse de la commande, TCL_ERROR est retournée, un message d'erreur est laissé dans le résultat de interp, et aucune information n'est laissée à *parsePtr.

Tcl_ParseExpr analyse les expressions Tcl. Étant donné un pointeur vers un script contenant une expression, Tcl_ParseExpr analyse l'expression. Si l'expression a été analysée avec succès, Tcl_ParseExpr retourne TCL_OK et remplit la structure pointée par parsePtr avec des informations sur la structure de l'expression (voir ci-dessous pour les détails). Si une erreur s'est produite lors de l'analyse de la commande, TCL_ERROR est retournée, un message d'erreur est laissé dans le résultat de interp, et aucune information n'est laissée à *parsePtr.

Tcl_ParseBraces analyse une chaîne ou un argument de commande entouré d'accolades tel que {hello} ou {string \t avec \t tabulations} depuis le début de son argument start. Le premier caractère de start doit être {. Si la chaîne entre accolades a été analysée avec succès, Tcl_ParseBraces retourne TCL_OK, remplit la structure pointée par parsePtr avec des informations sur la structure de la chaîne (voir ci-dessous pour les détails), et stocke un pointeur vers le caractère juste après l'accolade fermante } à l'emplacement indiqué par *termPtr. Si une erreur se produit lors de l'analyse de la chaîne, TCL_ERROR est retournée, un message d'erreur est laissé dans le résultat de interp, et aucune information n'est laissée à *parsePtr ou *termPtr.

Tcl_ParseQuotedString analyse une chaîne entre guillemets doubles telle que "la somme est [expr {$a+$b}]" depuis le début de l'argument start. Le premier caractère de start doit être ". Si la chaîne entre guillemets doubles a été analysée avec succès, Tcl_ParseQuotedString retourne TCL_OK, remplit la structure pointée par parsePtr avec des informations sur la structure de la chaîne (voir ci-dessous pour les détails), et stocke un pointeur vers le caractère juste après la guillemet fermante " à l'emplacement indiqué par *termPtr. Si une erreur se produit lors de l'analyse de la chaîne, TCL_ERROR est retournée, un message d'erreur est laissé dans le résultat de interp, et aucune information n'est laissée à *parsePtr ou *termPtr.

Tcl_ParseVarName analyse une référence de variable Tcl telle que $abc ou $x([expr {$index + 1}]) depuis le début de son argument start. Le premier caractère de start doit être $. Si un nom de variable a été analysé avec succès, Tcl_ParseVarName retourne TCL_OK et remplit la structure pointée par parsePtr avec des informations sur la structure du nom de variable (voir ci-dessous pour les détails). Si une erreur se produit lors de l'analyse de la commande, TCL_ERROR est retournée, un message d'erreur est laissé dans le résultat de interp (si interp n'est pas NULL), et aucune information n'est laissée à *parsePtr.

Tcl_ParseVar analyse une référence de variable Tcl telle que $abc ou $x([expr {$index + 1}]) depuis le début de son argument start. Le premier caractère de start doit être $. Si le nom de variable est analysé avec succès, Tcl_ParseVar retourne un pointeur vers la valeur chaîne de la variable. En cas d'erreur lors de l'analyse, NULL est retourné et un message d'erreur est laissé dans le résultat de interp.

Les informations laissées à *parsePtr par Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, et Tcl_ParseVarName peuvent inclure de la mémoire allouée dynamiquement. Si ces cinq procédures d'analyse retournent TCL_OK, l'appelant doit invoquer Tcl_FreeParse pour libérer l'espace mémoire à *parsePtr. Ces procédures ignorent toute information existante dans *parsePtr (sauf si append n'est pas zéro), donc si des appels répétés sont faits à l'une d'entre elles, Tcl_FreeParse doit être invoquée une fois après chaque appel.

Tcl_EvalTokensStandard évalue une séquence de jetons d'analyse provenant d'une structure Tcl_Parse. Les jetons consistent typiquement en tous les jetons d'un mot ou tous les jetons qui constituent l'index d'une référence à une variable tableau. Tcl_EvalTokensStandard effectue les substitutions demandées par les jetons et concatène les valeurs résultantes. La valeur de retour de Tcl_EvalTokensStandard est un code de complétion Tcl avec l'une des valeurs TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK, ou TCL_CONTINUE, ou potentiellement une autre valeur entière provenant d'une extension. De plus, une valeur de résultat ou un message d'erreur est laissé dans le résultat de interp ; il peut être récupéré en utilisant Tcl_GetObjResult.

Tcl_EvalTokens diffère de Tcl_EvalTokensStandard uniquement par la convention de retour

STRUCTURE PARSE TCL

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, et Tcl_ParseVarName renvoient des informations d'analyse dans deux structures, Tcl_Parse et Tcl_Token :

typedef struct Tcl_Parse {
    const char *commentStart;
    int commentSize;
    const char *commandStart;
    int commandSize;
    int numWords;
    Tcl_Token *tokenPtr;
    int numTokens;
    ...
} Tcl_Parse;
typedef struct Tcl_Token {
    int type;
    const char *start;
    int size;
    int numComponents;
} Tcl_Token;

Les cinq premiers champs d'une structure Tcl_Parse sont remplis uniquement par Tcl_ParseCommand. Ces champs ne sont pas utilisés par d'autres procédures d'analyse.

Tcl_ParseCommand remplit une structure Tcl_Parse avec des informations décrivant une commande Tcl et tout commentaire précédant la commande. S'il y a des commentaires, le champ commentStart pointe vers le caractère # qui commence le premier commentaire et commentSize indique le nombre d'octets dans tous les commentaires précédant la commande, y compris le caractère de fin de ligne qui termine le dernier commentaire. Si la commande n'est pas précédée de commentaires, commentSize est de 0. Tcl_ParseCommand définit également le champ commandStart pour pointer vers le premier caractère du premier mot de la commande (après tout commentaire et espace en tête), et commandSize donne le nombre total d'octets dans la commande, y compris le caractère pointé par commandStart jusqu'à la fin de la commande, y compris le caractère de fermeture de crochet, ou le point-virgule. Le champ numWords donne le nombre total de mots dans la commande.

Toutes les procédures d'analyse définissent les champs restants, tokenPtr et numTokens. Le champ tokenPtr pointe vers le premier d'un tableau de structures Tcl_Token qui décrivent les composants de l'entité en cours d'analyse. Le champ numTokens donne le nombre total de tokens présents dans le tableau. Chaque token contient quatre champs. Le champ type sélectionne l'un des types de token décrits ci-dessous. Le champ start pointe vers le premier caractère du token et le champ size donne le nombre total de caractères dans le token. Certains types de token, tels que TCL_TOKEN_WORD et TCL_TOKEN_VARIABLE, se composent de plusieurs tokens composants, qui suivent immédiatement le token parent ; le champ numComponents décrit combien il y en a. Le champ type a l'une des valeurs suivantes :

TCL_TOKEN_WORD
Ce token décrit généralement un mot d'une commande, mais peut également décrire une chaîne entre guillemets ou entre accolades dans une expression. Le token décrit un composant du script qui est le résultat de la concaténation d'une séquence de sous-composants, chacun décrit par un sous-token séparé. Le token commence par le premier caractère non blanc du composant (qui peut être un guillemet double ou une accolade ouvrante) et inclut tous les caractères du composant jusqu'à l'espace, le point-virgule, l'accolade fermante, le guillemet fermant ou le crochet fermant, sans les inclure. Le champ numComponents compte le nombre total de sous-tokens formant le mot, y compris les sous-tokens des tokens TCL_TOKEN_VARIABLE et TCL_TOKEN_BS.
TCL_TOKEN_SIMPLE_WORD
Ce token a la même signification que TCL_TOKEN_WORD, sauf que le mot est garanti de se composer d'un seul sous-token TCL_TOKEN_TEXT. Le champ numComponents est toujours 1.
TCL_TOKEN_EXPAND_WORD
Ce token a la même signification que TCL_TOKEN_WORD, sauf que l'analyseur de commande a noté que ce mot a commencé avec le préfixe d'expansion {*}, indiquant qu'après substitution, la valeur de liste de ce mot doit être étendue pour former plusieurs arguments lors de l'évaluation de la commande. Ce type de token ne peut être créé que par Tcl_ParseCommand.
TCL_TOKEN_TEXT
Le token décrit une plage de texte littéral faisant partie d'un mot. Le champ numComponents est toujours 0.
TCL_TOKEN_BS
Le token décrit une séquence de caractères échappés par une barre oblique inverse comme \n ou \0xA3. Le champ numComponents est toujours 0.
TCL_TOKEN_COMMAND
Le token décrit une commande dont le résultat doit être substitué dans le mot. Le token inclut les accolades entourant la commande. Le champ numComponents est toujours 0 (la commande imbriquée n'est pas analysée ; utilisez Tcl_ParseCommand récursivement si vous souhaitez voir ses tokens).
TCL_TOKEN_VARIABLE
Le token décrit une substitution de variable, y compris le $, le nom de la variable et l'indice du tableau (le cas échéant) jusqu'à l'accolade fermante qui termine l'indice. Ce token est suivi d'un ou plusieurs tokens décrivant le nom de la variable et l'indice du tableau. Si numComponents est de 1, alors la variable est scalaire et le token suivant est un TCL_TOKEN_TEXT donnant le nom de la variable. Si numComponents est supérieur à 1, alors la variable est un tableau : le premier sous-token est un TCL_TOKEN_TEXT donnant le nom du tableau et les sous-tokens restants sont des TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND et TCL_TOKEN_VARIABLE qui doivent être concaténés pour produire l'indice du tableau. Le champ numComponents inclut les sous-tokens de TCL_TOKEN_VARIABLE dans l'indice du tableau.
TCL_TOKEN_SUB_EXPR
Le token décrit une sous-expression d'une expression (ou une expression entière). Une sous-expression peut se composer d'une valeur telle qu'un entier littéral, une substitution de variable ou une sous-expression entre parenthèses ; elle peut également se composer d'un opérateur et de ses opérandes. Le token commence au premier caractère non blanc de la sous-expression jusqu'à l'espace, le crochet, la parenthèse fermante ou l'accolade fermante qui termine la sous-expression, sans les inclure. Ce token est suivi d'un ou plusieurs tokens décrivant la sous-expression. Si le premier sous-token après le TCL_TOKEN_SUB_EXPR est un TCL_TOKEN_OPERATOR, alors la sous-expression se compose d'un opérateur et de ses opérandes. Si l'opérateur n'a pas d'opérandes, la sous-expression se compose uniquement du token TCL_TOKEN_OPERATOR. Chaque opérande est décrit par un token TCL_TOKEN_SUB_EXPR. Sinon, la sous-expression est une valeur décrite par l'un des types de token TCL_TOKEN_WORD, TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, TCL_TOKEN_VARIABLE et TCL_TOKEN_SUB_EXPR. Le champ numComponents compte le nombre total de sous-tokens formant la sous-expression ; il inclut les sous-tokens de tout TCL_TOKEN_SUB_EXPR imbriqué.
TCL_TOKEN_OPERATOR
Le token décrit un opérateur d'une expression tel que && ou hypot. Un token TCL_TOKEN_OPERATOR est toujours précédé d'un token TCL_TOKEN_SUB_EXPR décrivant l'opérateur et ses opérandes ; le champ numComponents du token TCL_TOKEN_SUB_EXPR peut être utilisé pour déterminer le nombre d'opérandes. Un opérateur binaire tel que * est suivi de deux tokens TCL_TOKEN_SUB_EXPR décrivant ses opérandes. Un opérateur unaire tel que - est suivi d'un seul token TCL_TOKEN_SUB_EXPR pour son opérande. Si l'opérateur est une fonction mathématique comme log10, le token TCL_TOKEN_OPERATOR donnera son nom et les tokens TCL_TOKEN_SUB_EXPR suivants décriront ses opérandes ; s'il n'y a pas d'opérandes (comme avec rand), aucun token TCL_TOKEN_SUB_EXPR ne suivra. Il existe un opérateur ternaire, ?, qui apparaît dans les sous-expressions if-then-else comme x?y:z ; dans ce cas, le token TCL_TOKEN_OPERATOR ? est suivi de trois tokens TCL_TOKEN_SUB_EXPR pour les opérandes x, y et z. Le champ numComponents du token TCL_TOKEN_OPERATOR est toujours 0.

Après le retour de Tcl_ParseCommand, le premier token pointé par le champ tokenPtr de la structure Tcl_Parse est toujours de type TCL_TOKEN_WORD ou TCL_TOKEN_SIMPLE_WORD ou TCL_TOKEN_EXPAND_WORD. Il est suivi par les sous-tokens qui doivent être concaténés pour produire la valeur de ce mot. Le token suivant est le TCL_TOKEN_WORD ou TCL_TOKEN_SIMPLE_WORD du token TCL_TOKEN_EXPAND_WORD pour le deuxième mot, suivi par les sous-tokens de ce mot, et ainsi de suite jusqu'à ce que tous les numWords aient été traités.

Après le retour de Tcl_ParseExpr, le premier token pointé par le champ tokenPtr de la structure Tcl_Parse est toujours de type TCL_TOKEN_SUB_EXPR. Il est suivi par les sous-tokens qui doivent être évalués pour produire la valeur de l'expression. Seules les informations de token dans la structure Tcl_Parse sont modifiées : les champs commentStart, commentSize, commandStart et commandSize ne sont pas modifiés par Tcl_ParseExpr.

Après le retour de Tcl_ParseBraces, le tableau de tokens pointé par le champ tokenPtr de la structure Tcl_Parse contiendra un seul token TCL_TOKEN_TEXT si la chaîne ne contient aucune séquence de caractères échappés par une barre oblique inverse. Si la chaîne contient des séquences de caractères échappés par une barre oblique inverse, le tableau de tokens contiendra un ou plusieurs sous-tokens TCL_TOKEN_TEXT ou TCL_TOKEN_BS qui doivent être concaténés pour produire la valeur de la chaîne. Si la chaîne était seulement {} (c'est-à-dire que la chaîne était vide), le token TCL_TOKEN_TEXT unique aura un champ size de zéro ; cela garantit qu'au moins un token apparaît pour décrire la chaîne entre accolades.
