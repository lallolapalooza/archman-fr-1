DESCRIPTION

Les objets sont des entités typées qui ont un ensemble d'opérations ("méthodes") associées. Les classes sont des objets qui peuvent fabriquer des objets. Chaque classe peut être vue comme un objet en soi ; la vue objet peut être récupérée en utilisant Tcl_GetClassAsObject qui retourne toujours l'objet lorsqu'elle est appliquée à une classe non détruite, et un objet peut être vu comme une classe avec l'aide de Tcl_GetObjectAsClass (qui retourne soit la classe, soit NULL si l'objet n'est pas une classe). Un objet peut être recherché en utilisant la fonction Tcl_GetObjectFromObj, qui retourne soit un objet, soit NULL (avec un message d'erreur dans le résultat de l'interpréteur) si l'objet ne peut pas être trouvé. La manière correcte de rechercher une classe par son nom est de rechercher l'objet portant ce nom, puis d'utiliser Tcl_GetObjectAsClass.

Chaque objet a sa propre commande et son propre espace de noms associés. La commande peut être récupérée en utilisant la fonction Tcl_GetObjectCommand, le nom de l'objet (et donc le nom de la commande) avec Tcl_GetObjectName, et l'espace de noms peut être récupéré en utilisant la fonction Tcl_GetObjectNamespace. Notez que la référence Tcl_Obj retournée par Tcl_GetObjectName est une référence partagée. Vous pouvez également obtenir si l'objet a été marqué pour suppression avec Tcl_ObjectDeleted (elle retourne vrai si la suppression de l'objet a commencé) ; ceci peut être utile pendant le traitement des méthodes.

Les instances de classes sont créées en utilisant Tcl_NewObjectInstance, qui crée un objet à partir de n'importe quelle classe (et qui est appelé en interne par les méthodes create et new de la classe oo::class). Elle prend des paramètres qui donnent optionnellement le nom de l'objet et de l'espace de noms à créer, et qui décrivent les arguments à passer au constructeur de la classe (s'il y en a un). Le résultat de la fonction sera soit une référence au nouvel objet créé, soit NULL si la création a échoué (auquel cas un message d'erreur sera laissé dans le résultat de l'interpréteur). De plus, les objets peuvent être copiés en utilisant Tcl_CopyObjectInstance qui crée une copie d'un objet sans exécuter de constructeurs.

Notez que la gestion du cycle de vie des objets est gérée en interne au sein de TclOO, et n'utilise pas Tcl_Preserve. Il n'est pas sûr de placer une poignée Tcl_Object dans une structure C dont la durée de vie est différente de celle de l'objet ; vous devriez utiliser le nom de la commande de l'objet (tel qu'obtenu avec Tcl_GetObjectName) à la place. Il est sûr d'utiliser une poignée Tcl_Object pendant la durée d'un appel de méthode sur cet objet ; les poignées ne deviennent pas invalides tant qu'il y a un appel en cours sur leur objet (même si la seule opération garantie comme sûre sur elles est Tcl_ObjectDeleted ; les autres opérations ne sont garanties de fonctionner que sur des objets non supprimés).

MÉTADONNÉES OBJET ET CLASSE

Chaque objet et chaque classe peuvent avoir une quantité arbitraire de métadonnées attachées, auxquelles l'objet ou la classe n'attribue aucune signification au-delà de ce qui est décrit dans une instance de structure Tcl_ObjectMetadataType. Les métadonnées à attacher sont décrites par le type des métadonnées (donné dans l'argument metaTypePtr) et un pointeur arbitraire (l'argument metadata) qui sont passés à Tcl_ObjectSetMetadata et Tcl_ClassSetMetadata, et un élément particulier de métadonnées peut être récupéré en connaissant son type à l'aide de Tcl_ObjectGetMetadata et Tcl_ClassGetMetadata. Si le paramètre metadata passé à Tcl_ObjectSetMetadata ou Tcl_ClassSetMetadata est NULL, les métadonnées sont supprimées si elles étaient attachées, et les résultats de Tcl_ObjectGetMetadata et Tcl_ClassGetMetadata sont NULL si le type de métadonnées donné n'était pas attaché. Il n'est pas une erreur de demander ou de supprimer un élément de métadonnées qui n'était pas attaché.

STRUCTURE TCL_OBJECTMETADATATYPE

Le contenu de la structure Tcl_ObjectMetadataType est le suivant :

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

Le champ version permet une expansion future de la structure, et doit toujours être déclaré égal à TCL_OO_METADATA_VERSION_CURRENT. Le champ name fournit un nom lisible par l'homme pour le type, et est réservé au débogage.

Le champ deleteProc donne une fonction de type Tcl_ObjectMetadataDeleteProc qui est utilisée pour supprimer un élément particulier de métadonnées, et est appelée lorsque les métadonnées attachées sont remplacées ou supprimées ; le champ ne doit pas être NULL.

Le champ cloneProc donne une fonction qui est utilisée pour copier un élément de métadonnées (utilisé lorsqu'une copie d'un objet est créée à l'aide de Tcl_CopyObjectInstance) ; si NULL, les métadonnées seront simplement copiées directement.

DESCRIPTION


Ces fonctions fournissent une API de bas niveau pour la création, la
    manipulation et la destruction d'objets et de classes dans le système TclOO.
    Elles permettent de gérer les noms d'objets, les commandes associées, les
    méthodes (constructeurs, méthodes ordinaires, mappers de noms de méthodes),
    le clonage et la destruction.

TCL_CLONEPROC FUNCTION SIGNATURE


Les fonctions correspondant à cette signature sont utilisées pour
    créer des copies de métadonnées associées à une classe ou à un objet.




typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData srcMetadata,
        ClientData *dstMetadataPtr);




L'argument interp fournit un emplacement pour écrire un
    message d'erreur lorsque la tentative de clonage de l'objet échoue ; dans ce
    cas, la procédure de clonage doit également retourner TCL_ERROR ; elle doit
    sinon retourner TCL_OK. L'argument srcMetadata donne l'adresse des
    métadonnées à cloner, et les métadonnées clonées doivent être écrites dans la
    variable pointée par dstMetadataPtr ; une valeur NULL doit y être
    écrite si les métadonnées ne doivent pas être clonées mais que l'opération
    globale de copie de l'objet doit réussir.








OBJET MÉTHODE NOM MAPPING


Il est possible de contrôler, sur une base par objet, quelles méthodes
    sont appelées lorsqu'une méthode particulière est invoquée. Normalement, cela
    se fait en recherchant le nom de la méthode dans l'objet, puis dans la
    hiérarchie des classes, mais un contrôle fin de la valeur exacte utilisée pour
    effectuer la recherche est offert par la possibilité de définir une fonction
    de rappel (callback) pour le mappage des noms de méthodes via
    Tcl_ObjectSetMethodNameMapper (et son homologue d'introspection,
    Tcl_ObjectGetMethodNameMapper, qui retourne le mapper actuel). Le mapper
    actuel (s'il y en a un) est appelé immédiatement avant de rechercher la chaîne
    d'implémentations de méthodes à utiliser.




TCL_OBJECTMAPMETHODNAMEPROC FUNCTION SIGNATURE


Le callback Tcl_ObjectMapMethodNameProc est défini comme suit
    :




typedef int Tcl_ObjectMapMethodNameProc(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class *startClsPtr,
        Tcl_Obj *methodNameObj);




Si le résultat est TCL_OK, le remappage est supposé avoir été effectué.
    Si le résultat est TCL_ERROR, un message d'erreur aura été laissé dans
    interp et l'appel de méthode échouera. Si le résultat est TCL_BREAK, les
    règles standard de recherche de nom de méthode seront utilisées ; le
    comportement des autres codes de résultat est actuellement indéfini. Le paramètre
    object indique quel objet est en cours de traitement. Le paramètre
    startClsPtr pointe vers une variable qui contient la première classe à
    fournir une définition dans la chaîne de méthodes à traiter, ou NULL si toute
    la chaîne doit être traitée (l'argument lui-même n'est jamais NULL) ; cette
    variable peut être mise à jour par le callback. Le paramètre
    methodNameObj donne un objet non partagé contenant le nom de la méthode
    invoquée, tel que fourni par l'utilisateur ; cet objet peut être mis à jour
    par le callback.
