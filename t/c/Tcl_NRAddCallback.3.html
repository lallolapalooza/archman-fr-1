Tcl_NRAddCallback(3)

Paquet: tcl

Licences: TCL

NRE(3) Procédures de bibliothèque Tcl NRE(3)

NOM

Tcl_NRCreateCommand, Tcl_NRCallObjProc, Tcl_NREvalObj, Tcl_NREvalObjv, Tcl_NRCmdSwap, Tcl_NRExprObj, Tcl_NRAddCallback - Évaluation non récursive (sans pile) de scripts Tcl.

SYNTAXE

#include <tcl.h>

Tcl_Command
Tcl_NRCreateCommand(interp, cmdName, proc, nreProc, clientData,
                    deleteProc)

int
Tcl_NRCallObjProc(interp, nreProc, clientData, objc, objv)

int
Tcl_NREvalObj(interp, objPtr, flags)

int
Tcl_NREvalObjv(interp, objc, objv, flags)

int
Tcl_NRCmdSwap(interp, cmd, objc, objv, flags)

int
Tcl_NRExprObj(interp, objPtr, resultPtr)

void
Tcl_NRAddCallback(interp, postProcPtr, data0, data1, data2, data3)

ARGUMENTS

Tcl_Interp *interp (in)
L'interpréteur pertinent.
const char *cmdName (in)
Nom de la commande à créer.
Tcl_ObjCmdProc *proc (in)
Est appelée pour évaluer une commande. Généralement, juste un petit wrapper qui utilise Tcl_NRCallObjProc pour appeler nreProc avec un nouveau trampoline. Se comporte de manière similaire à la proc de Tcl_CreateObjCommand(3) (voir).
Tcl_ObjCmdProc *nreProc (in)
Est appelée à la place de proc lorsqu'un trampoline est déjà en cours d'utilisation.
ClientData clientData (in)
Valeur arbitraire de taille unique, transmise à proc, nreProc, deleteProc et objProc.
Tcl_CmdDeleteProc *deleteProc (in/out)
Est appelée avant que cmdName ne soit supprimé de l'interpréteur, permettant un nettoyage spécifique à la commande. Peut être NULL.
int objc (in)
Nombre d'éléments dans objv.
Tcl_Obj **objv (in)
Mots de la commande.
Tcl_Obj *objPtr (in)
Un script ou une expression à évaluer.
int flags (in)
Comme décrit pour Tcl_EvalObjv.
Tcl_Command cmd (in)
Jeton à utiliser à la place de celui dérivé du premier élément de objv pour évaluer une commande.
Tcl_Obj *resultPtr (out)
Un objet Tcl non partagé où le résultat de l'évaluation est stocké si le code de retour est TCL_OK.
Tcl_NRPostProc *postProcPtr (in)
Une fonction à ajouter.
ClientData data0 (in)
ClientData data1 (in)
ClientData data2 (in)
ClientData data3 (in)
data0 à data3 sont quatre valeurs de taille unique transmises à la fonction désignée par postProcPtr lorsqu'elle est invoquée.

DESCRIPTION

Ces fonctions offrent une interface à la pile de fonctions qu'un interpréteur parcourt pour évaluer des commandes. La fonction qui implémente une commande est implémentée par une fonction initiale et toute autre fonction que la routine place sur la pile au fur et à mesure. L'interpréteur lui-même place des fonctions sur la pile pour réagir à la fin d'une routine et pour exercer d'autres types de contrôle, tels que le passage d'une pile en cours ou l'évaluation de scripts à des niveaux supplémentaires sans ajouter d'image à la pile C. Pour exécuter une routine, la fonction initiale de la routine est d'abord appelée, puis un petit bout de code appelé trampoline qui prend itérativement des fonctions de la pile et les appelle, en utilisant la valeur du dernier appel comme valeur de la routine.

Tcl_NRCallObjProc appelle nreProc avec un nouveau trampoline.

Tcl_NRCreateCommand, une alternative à Tcl_CreateObjCommand, résout cmdName, qui peut contenir des qualificateurs d'espace, par rapport à l'espace actuel, crée une commande pour ce nom et retourne un jeton pour la commande qui peut être utilisé dans des appels ultérieurs à Tcl_GetCommandName. Sauf dans certains cas mentionnés ci-dessous, toute commande existante du même nom est d'abord supprimée. Si interp est en cours de suppression, Tcl_NRCreateCommand ne crée aucune commande, ne supprime aucune commande et retourne NULL.

Tcl_NREvalObj pousse une fonction similaire à Tcl_EvalObjEx mais qui ne consomme pas d'espace sur la pile C.

Tcl_NREvalObjv pousse une fonction similaire à Tcl_EvalObjv mais qui ne consomme pas d'espace sur la pile C.

Tcl_NRCmdSwap est similaire à Tcl_NREvalObjv, mais utilise cmd, un jeton précédemment retourné par Tcl_CreateObjCommand ou Tcl_GetCommandFromObj, au lieu de résoudre le premier élément de objv.

Tcl_NRExprObj pousse une fonction qui évalue objPtr comme une expression de la même manière que Tcl_ExprObj, mais qui ne consomme pas d'espace sur la pile C.

Toutes les fonctions retournent TCL_OK si l'évaluation du script, de la commande ou de l'expression a été planifiée avec succès. Sinon (par exemple, si le nom de la commande ne peut pas être résolu), elles retournent TCL_ERROR et stockent un message comme résultat de l'interpréteur.

Tcl_NRAddCallback pousse postProcPtr. La signature de Tcl_NRPostProc est :

typedef int
Tcl_NRPostProc(
        ClientData data[],
        Tcl_Interp *interp,
        int result);

data est un pointeur vers un tableau contenant data0 à data3. result est la valeur de retour de la fonction précédente implémentant une partie de la routine.

EXEMPLE

La commande suivante utilise Tcl_EvalObjEx, qui consomme de l'espace sur la pile C, pour évaluer un script :

int
TheCmdOldObjProc(
    ClientData clientData,
    Tcl_Interp *interp,
    int objc,
    Tcl_Obj *const objv[])
{
    int result;
    Tcl_Obj *objPtr;
    ... préparation ...
    result = Tcl_EvalObjEx(interp, objPtr, 0);
    ... post-traitement ...
    return result;
}
Tcl_CreateObjCommand(interp, "theCommand",
        TheCmdOldObjProc, clientData, TheCmdDeleteProc);

Pour éviter de consommer de l'espace sur la pile C, TheCmdOldObjProc est renommée en TheCmdNRObjProc et le passage de post-traitement est divisé en une fonction distincte, TheCmdPostProc, qui est placée sur la pile de fonctions. Tcl_EvalObjEx est remplacée par Tcl_NREvalObj, qui utilise un trampoline au lieu de consommer de l'espace sur la pile C. Une nouvelle version de TheCmdOldObjProc est simplement un wrapper qui utilise Tcl_NRCallObjProc pour appeler TheCmdNRObjProc :

int
TheCmdOldObjProc(
    ClientData clientData,
    Tcl_Interp *interp,
    int objc,
    Tcl_Obj *const objv[])
{
    return Tcl_NRCallObjProc(interp, TheCmdNRObjProc,
            clientData, objc, objv);
}
int
TheCmdNRObjProc
    ClientData clientData,
    Tcl_Interp *interp,
    int objc,
    Tcl_Obj *const objv[])
{
    Tcl_Obj *objPtr;
    ... préparation ...
    Tcl_NRAddCallback(interp, TheCmdPostProc,
            data0, data1, data2, data3);
    /* data0 .. data3 sont jusqu'à quatre valeurs de taille unique passées à la fonction de post-traitement */
    return Tcl_NREvalObj(interp, objPtr, 0);
}
int
TheCmdNRPostProc(
    ClientData data[],
    Tcl_Interp *interp,
    int result)
{
    /* data[0] .. data[3] sont les quatre éléments de données passés à Tcl_NRAddCallback */
    ... post-traitement ...
    return result;
}

Toute fonction qui met en forme une routine peut pousser d'autres fonctions, ce qui permet de mettre en œuvre des structures de contrôle telles que des boucles et des séquences à l'aide de la pile de fonctions.
