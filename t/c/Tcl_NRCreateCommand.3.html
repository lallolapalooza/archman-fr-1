Tcl_NRCreateCommand(3)

Paquet: tcl

Licences: TCL

NRE(3) Procédures de bibliothèque Tcl NRE(3)

NOM

Tcl_NRCreateCommand, Tcl_NRCallObjProc, Tcl_NREvalObj, Tcl_NREvalObjv, Tcl_NRCmdSwap, Tcl_NRExprObj, Tcl_NRAddCallback - Évaluation non récursive (sans pile) de scripts Tcl.

SYNOPIS

#include <tcl.h>

Tcl_Command
Tcl_NRCreateCommand(interp, cmdName, proc, nreProc, clientData,
                    deleteProc)

int
Tcl_NRCallObjProc(interp, nreProc, clientData, objc, objv)

int
Tcl_NREvalObj(interp, objPtr, flags)

int
Tcl_NREvalObjv(interp, objc, objv, flags)

int
Tcl_NRCmdSwap(interp, cmd, objc, objv, flags)

int
Tcl_NRExprObj(interp, objPtr, resultPtr)

void
Tcl_NRAddCallback(interp, postProcPtr, data0, data1, data2, data3)

ARGUMENTS

Tcl_Interp *interp (en entrée)
L'Interpréteur concerné.
const char *cmdName (en entrée)
Nom de la commande à créer.
Tcl_ObjCmdProc *proc (en entrée)
Appelé afin d'évaluer une commande. C'est souvent juste un petit wrapper qui utilise Tcl_NRCallObjProc pour appeler nreProc en utilisant un nouveau trampoline. Se comporte de la même manière que l'argument proc de Tcl_CreateObjCommand(3) (cf.).
Tcl_ObjCmdProc *nreProc (en entrée)
Appelé à la place de proc lorsqu'un trampoline est déjà utilisé.
ClientData clientData (en entrée)
Valeur arbitraire d'un mot passé à proc, nreProc, deleteProc et objProc.
Tcl_CmdDeleteProc *deleteProc (en entrée/sortie)
Appelé avant que cmdName ne soit supprimé de l'interpréteur, permettant un nettoyage spécifique à la commande. Peut être NULL.
int objc (en entrée)
Nombre d'éléments dans objv.
Tcl_Obj **objv (en entrée)
Mots de la commande.
Tcl_Obj *objPtr (en entrée)
Un script ou une expression à évaluer.
int flags (en entrée)
Comme décrit pour Tcl_EvalObjv.
Tcl_Command cmd (en entrée)
Jeton à utiliser à la place de celui dérivé du premier mot de objv pour évaluer une commande.
Tcl_Obj *resultPtr (en sortie)
Pointeur vers un Tcl_Obj non partagé où le résultat de l'évaluation est stocké si le code de retour est TCL_OK.
Tcl_NRPostProc *postProcPtr (en entrée)
Une fonction à pousser.
ClientData data0 (en entrée)
ClientData data1 (en entrée)
ClientData data2 (en entrée)
ClientData data3 (en entrée)
data0 à data3 sont quatre valeurs d'un mot qui seront passées à la fonction désignée par postProcPtr lorsqu'elle sera invoquée.

DESCRIPTION

Ces fonctions fournissent une interface à la pile de fonctions que l'interpréteur parcourt pour évaluer les commandes. La routine derrière une commande est implémentée par une fonction initiale et toute fonction supplémentaire que la routine pousse sur la pile au fur et à mesure de sa progression. L'interpréteur lui-même pousse des fonctions sur la pile pour réagir à la fin d'une routine et pour exercer d'autres formes de contrôle, telles que le passage entre les piles en cours d'exécution et l'évaluation d'autres scripts à des niveaux supplémentaires sans ajouter de cadres à la pile C. Pour exécuter une routine, la fonction initiale de la routine est appelée, puis un petit morceau de code appelé trampoline prend itérativement les fonctions de la pile et les appelle, en utilisant la valeur du dernier appel comme valeur de la routine.

Tcl_NRCallObjProc appelle nreProc en utilisant un nouveau trampoline.

Tcl_NRCreateCommand, une alternative à Tcl_CreateObjCommand, résout cmdName, qui peut contenir des qualificatifs de namespace, par rapport au namespace courant, crée une commande sous ce nom, et retourne un jeton pour la commande qui peut être utilisé dans des appels ultérieurs à Tcl_GetCommandName. Sauf quelques cas notés ci-dessous, toute commande existante portant le même nom est d'abord supprimée. Si interp est en cours de suppression, Tcl_NRCreateCommand ne crée aucune commande, ne supprime aucune commande et retourne NULL.

Tcl_NREvalObj pousse une fonction qui est similaire à Tcl_EvalObjEx mais ne consomme pas d'espace sur la pile C.

Tcl_NREvalObjv pousse une fonction qui est similaire à Tcl_EvalObjv mais ne consomme pas d'espace sur la pile C.

Tcl_NRCmdSwap est similaire à Tcl_NREvalObjv, mais utilise cmd, un jeton précédemment retourné par Tcl_CreateObjCommand ou Tcl_GetCommandFromObj, au lieu de résoudre le premier mot de objv.

Tcl_NRExprObj pousse une fonction qui évalue objPtr comme une expression de la même manière que Tcl_ExprObj mais sans consommer d'espace sur la pile C.

Toutes les fonctions retournent TCL_OK si l'évaluation du script, de la commande ou de l'expression a été planifiée avec succès. Sinon (par exemple si le nom de la commande ne peut pas être résolu), elles retournent TCL_ERROR et stockent un message comme résultat de l'interpréteur.

Tcl_NRAddCallback pousse postProcPtr. La signature pour Tcl_NRPostProc est :

typedef int
Tcl_NRPostProc(
        ClientData data[],
        Tcl_Interp *interp,
        int result);

data est un pointeur vers un tableau contenant data0 à data3. result est la valeur retournée par la fonction précédente implémentant une partie de la routine.

EXEMPLE

La commande suivante utilise Tcl_EvalObjEx, qui consomme de l'espace sur la pile C, pour évaluer un script :

int
TheCmdOldObjProc(
    ClientData clientData,
    Tcl_Interp *interp,
    int objc,
    Tcl_Obj *const objv[])
{
    int result;
    Tcl_Obj *objPtr;
    ... préparation ...
    result = Tcl_EvalObjEx(interp, objPtr, 0);
    ... post-traitement ...
    return result;
}
Tcl_CreateObjCommand(interp, "theCommand",
        TheCmdOldObjProc, clientData, TheCmdDeleteProc);

Pour éviter de consommer de l'espace sur la pile C, TheCmdOldObjProc est renommée en TheCmdNRObjProc et l'étape de post-traitement est divisée en une fonction séparée, TheCmdPostProc, qui est poussée sur la pile de fonctions. Tcl_EvalObjEx est remplacé par Tcl_NREvalObj, qui utilise un trampoline au lieu de consommer de l'espace sur la pile C. Une nouvelle version de TheCmdOldObjProc est juste un wrapper qui utilise Tcl_NRCallObjProc pour appeler TheCmdNRObjProc :

int
TheCmdOldObjProc(
    ClientData clientData,
    Tcl_Interp *interp,
    int objc,
    Tcl_Obj *const objv[])
{
    return Tcl_NRCallObjProc(interp, TheCmdNRObjProc,
            clientData, objc, objv);
}
int
TheCmdNRObjProc
    ClientData clientData,
    Tcl_Interp *interp,
    int objc,
    Tcl_Obj *const objv[])
{
    Tcl_Obj *objPtr;
    ... préparation ...
    Tcl_NRAddCallback(interp, TheCmdPostProc,
            data0, data1, data2, data3);
    /* data0 .. data3 sont jusqu'à quatre éléments d'un mot à
     * passer à la procédure de post-traitement */
    return Tcl_NREvalObj(interp, objPtr, 0);
}
int
TheCmdNRPostProc(
    ClientData data[],
    Tcl_Interp *interp,
    int result)
{
    /* data[0] .. data[3] sont les quatre mots de données
     * passés à Tcl_NRAddCallback */
    ... post-traitement ...
    return result;
}

Toute fonction composant une routine peut pousser d'autres fonctions, permettant d'implémenter des constructions de boucles et de séquencement en utilisant la pile de fonctions.
