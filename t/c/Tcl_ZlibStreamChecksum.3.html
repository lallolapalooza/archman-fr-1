ARGUMENTS

Tcl_Interp *interp (in)
L'interpréteur auquel le résultat des données compressées ou décompressées est stocké. C'est également là que les messages d'erreur sont écrits. Pour Tcl_ZlibStreamInit, ceci peut être NULL pour créer un flux qui n'est pas lié à une commande.
int format (in)
Quel format de données compressées utiliser. Doit être l'un des suivants : TCL_ZLIB_FORMAT_ZLIB pour des données au format zlib, TCL_ZLIB_FORMAT_GZIP pour des données au format gzip, ou TCL_ZLIB_FORMAT_RAW pour des données compressées au format brut. De plus, pour la décompression uniquement, on peut aussi choisir TCL_ZLIB_FORMAT_AUTO qui peut détecter automatiquement si les données compressées étaient au format zlib ou gzip.
Tcl_Obj *dataObj (in/out)
Une valeur de type tableau d'octets contenant les données à compresser ou décompresser, ou qui est ajoutée aux données extraites d'un flux lors de son passage à Tcl_ZlibStreamGet.
int level (in)
Quel niveau de compression utiliser. Doit être un nombre de 0 à 9 ou l'un des suivants : TCL_ZLIB_COMPRESS_NONE pour aucune compression, TCL_ZLIB_COMPRESS_FAST pour une compression rapide mais inefficace, TCL_ZLIB_COMPRESS_BEST pour une compression lente mais maximale, ou TCL_ZLIB_COMPRESS_DEFAULT pour le niveau recommandé par la bibliothèque zlib.
Tcl_Obj *dictObj (in/out)
Un dictionnaire contenant, ou qui sera mis à jour pour contenir, une description de l'en-tête gzip associé aux données compressées. Ceci n'est utile que lorsque le format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Si un NULL est passé, un en-tête par défaut sera utilisé lors de la compression et l'en-tête sera ignoré (sauf pour les vérifications d'intégrité). Voir la section GZIP OPTIONS DICTIONARY pour les détails sur le contenu de ce dictionnaire.
unsigned int initValue (in)
La valeur initiale pour l'algorithme de somme de contrôle.
int bufferSize (in)
Un indicateur de la taille du tampon à utiliser pour recevoir les données. Utilisez 0 pour utiliser une estimation basée sur les données d'entrée.
unsigned char *bytes (in)
Un tableau d'octets pour exécuter l'algorithme de somme de contrôle, ou NULL pour obtenir la valeur initiale recommandée pour l'algorithme de somme de contrôle.
int length (in)
Le nombre d'octets dans le tableau.
int mode (in)
Quel mode utiliser pour le flux. Doit être l'un des suivants : TCL_ZLIB_STREAM_DEFLATE pour un flux de compression ou TCL_ZLIB_STREAM_INFLATE pour un flux de décompression.
Tcl_ZlibStream *zshandlePtr (out)
Un pointeur vers une variable dans laquelle le jeton abstrait pour le flux est écrit lors de sa création réussie.
Tcl_ZlibStream zshandle (in)
Le jeton abstrait du flux sur lequel opérer.
int flush (in)
Comment le flux doit être vidé après l'écriture des données. Doit être l'un des suivants : TCL_ZLIB_NO_FLUSH si aucune vidange ne doit être effectuée, TCL_ZLIB_FLUSH si les données compressées actuelles doivent être disponibles pour être lues via Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si le flux doit être placé dans un état où le décompresseur peut se rétablir d'une corruption, ou TCL_ZLIB_FINALIZE pour s'assurer que le flux est terminé et que toute fin de fichier souhaitée par le format est écrite.
int count (in)
Le nombre maximum d'octets à obtenir du flux, ou -1 pour obtenir tous les octets restants des tampons du flux.
Tcl_Obj *compDict (in)
Une valeur de type tableau d'octets représentant le dictionnaire de compression à utiliser avec le flux. Il est à noter qu'il ne s'agit pas d'un dictionnaire Tcl, et il est recommandé de ne l'utiliser qu'avec des flux dont le format est défini sur TCL_ZLIB_FORMAT_ZLIB, car les autres formats n'ont pas de mécanisme pour indiquer si un dictionnaire de compression était présent, sauf en échouant lors de la décompression.

DESCRIPTION

Ces fonctions constituent l'interface de la bibliothèque Tcl vers la bibliothèque Zlib de Jean-loup Gailly et Mark Adler.

Tcl_ZlibDeflate et Tcl_ZlibInflate compressent et décompressent respectivement les données contenues dans l'argument dataObj, en fonction du format et, pour la compression, du niveau d'argument level. Le dictionnaire dans dictObj est utilisé pour transmettre des informations supplémentaires sur les données compressées lorsque le format de compression le prend en charge ; actuellement, le dictionnaire n'est utilisé que lorsque le format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Pour plus de détails sur le contenu du dictionnaire, voir la section GZIP OPTIONS DICTIONARY. En cas de succès, les deux fonctions laissent les données compressées ou décompressées dans une valeur de type tableau d'octets qui est le résultat de l'interpréteur Tcl ; la valeur retournée est un code de résultat Tcl standard.

Tcl_Adler32 et Tcl_ZlibCRC32 calculent des sommes de contrôle sur des tableaux d'octets, retournant la somme de contrôle calculée. Les sommes de contrôle sont calculées de manière incrémentale, permettant de traiter les données par morceaux, mais cela nécessite de conserver la valeur actuelle de la somme de contrôle et de la passer comme paramètre initValue de l'appel ; la valeur initiale pour cela peut être obtenue en utilisant NULL comme paramètre pour bytes au lieu d'un pointeur vers un tableau d'octets pour calculer la somme de contrôle sur. Par conséquent, l'utilisation typique dans le cas d'un seul bloc de données est la suivante :

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Note : L'algorithme Adler-32 n'est pas une somme de contrôle réelle, mais un type de hachage apparenté qui fonctionne mieux sur des données plus longues.

STREAMS ZLIB

Tcl_ZlibStreamInit crée un flux de compression ou de décompression lié à une commande Tcl, selon ses arguments, et fournit un jeton abstrait pour le flux et renvoie un code de résultat normal ; Tcl_ZlibStreamGetCommandName renvoie le nom de cette commande étant donné le jeton du flux, ou NULL si le flux n'a pas de commande. Les flux ne sont pas conçus pour être thread-safe ; chaque flux ne doit être utilisé que par le thread qui l'a créé. Lors de l'utilisation de flux gzip, un dictionnaire (valeurs telles que celles données dans la section GZIP OPTIONS DICTIONARY) peut être fourni par le paramètre dictObj qui permet de contrôler les en-têtes générés lors de la compression, et lors de la décompression permet de découvrir les en-têtes existants. Notez que le dictionnaire sera écrit au moment où il aura été suffisamment lu pour avoir un en-tête complet. Cela signifie que le dictionnaire doit être une valeur non partagée dans ce cas ; il est suggéré d'utiliser une valeur vide créée avec Tcl_NewObj.

Une fois qu'un flux est construit, Tcl_ZlibStreamPut est utilisé pour ajouter des données au flux et Tcl_ZlibStreamGet pour obtenir des données du flux après traitement. Les deux renvoient des codes de résultat Tcl normaux et laissent un message d'erreur dans le résultat de l'interpréteur auquel le flux est enregistré en cas d'erreur (si un tel enregistrement a été effectué). Avec Tcl_ZlibStreamPut, la valeur du tampon qui lui est passée ne doit pas être modifiée par la suite. Avec Tcl_ZlibStreamGet, la valeur du tampon qui lui est passée aura les octets de données ajoutés. Interne au flux, les données sont conservées compressées pour minimiser le coût de l'espace de tampon.

bStreamEof renvoie une valeur booléenne indiquant si la fin des données décompressées a été atteinte.

Tcl_ZlibStreamSetCompressionDictionary est utilisé pour contrôler le dictionnaire de compression utilisé avec le flux, un dictionnaire de compression étant un tableau d'octets (tel que pourrait être créé avec Tcl_NewByteArrayObj) qui est utilisé pour initialiser le moteur de compression au lieu de le laisser le créer à la volée à partir des données compressées. La définition d'un dictionnaire de compression permet une compression plus efficace dans le cas où le début des données est très régulier, mais cela nécessite que le compresseur et le décompresseur s'accordent sur la valeur à utiliser. Les dictionnaires de compression ne sont entièrement pris en charge que pour les données au format zlib ; lors de la compression, ils doivent être définis avant que toute donnée ne soit envoyée avec Tcl_ZlibStreamPut, et lors de la décompression, ils doivent être définis lorsque Tcl_ZlibStreamGet produit une erreur avec son -errorcode défini sur “ZLIB NEED_DICT code”; le code sera la somme de contrôle Adler-32 (voir Tcl_ZlibAdler32) du dictionnaire de compression recherché. (Notez que ce n'est vrai que pour les flux au format zlib ; les flux gzip ignorent les dictionnaires de compression car la spécification du format ne les autorise pas, et les flux bruts produisent simplement une erreur de données si le dictionnaire de compression est manquant ou incorrect.)

Si vous souhaitez effacer un flux et le réutiliser pour une nouvelle action de compression ou de décompression, Tcl_ZlibStreamReset le fera et renverra un code de résultat Tcl normal pour indiquer s'il a réussi ; si le flux est enregistré auprès d'un interpréteur, un message d'erreur sera laissé dans le résultat de l'interpréteur lorsque cette fonction renverra TCL_ERROR. Enfin, Tcl_ZlibStreamClose nettoiera le flux et supprimera la commande associée : utiliser Tcl_DeleteCommand sur la commande du flux est équivalent (lorsqu'une telle commande existe).

OPTIONS GZIP DICTIONNAIRE

Le paramètre dictObj à Tcl_ZlibDeflate, Tcl_ZlibInflate et Tcl_ZlibStreamInit est utilisé pour passer un dictionnaire d'options décrivant l'en-tête gzip dans les données compressées. Lors de la création de données compressées, le dictionnaire est lu et lors du dépaquetage de données compressées, le dictionnaire est écrit (auquel cas le paramètre dictObj doit faire référence à une valeur de dictionnaire non partagée).

Les champs suivants du dictionnaire sont compris. Tous les autres champs sont ignorés. Aucun champ n'est requis lors de la création d'un flux au format gzip.

comment
Contient le champ commentaire de l'en-tête, s'il est présent. S'il est absent, aucun commentaire n'a été fourni (lors de la décompression) ou ne sera créé (lors de la compression).
crc
Une valeur booléenne indiquant si une somme de contrôle CRC de l'en-tête est calculée. Notez que le programme gzip n'utilise *pas* et n'autorise pas de CRC sur l'en-tête.
filename
Le nom du fichier qui contenait les données décompressées. Il ne doit pas contenir de séparateurs de répertoire et doit être nettoyé avant utilisation lors de la décompression avec file tail.
os
Le champ du code du type de système d'exploitation de l'en-tête (s'il n'est pas la valeur “inconnu”). Voir RFC 1952 pour la signification de ces codes. Lors de la compression, si ce champ est absent, il sera défini sur la valeur “inconnu”.
size
La taille des données décompressées. Ceci est ignoré lors de la compression ; la taille des données compressées dépend de la quantité de données fournie au moteur de compression.
time
Le champ de temps de l'en-tête s'il est non nul, censé représenter le moment où le fichier nommé par le champ filename a été modifié. Convient pour une utilisation avec clock format. Lors de la création, la valeur appropriée à utiliser est celle de clock seconds ou file mtime.
type
Le type des données décompressées (soit binary, soit text) si connu.

NOTES DE PORTABILITÉ

Ces fonctions échoueront gracieusement si Tcl n'est pas lié à la bibliothèque zlib.
