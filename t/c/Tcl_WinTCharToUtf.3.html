L'encodage à interroger, libérer ou utiliser pour convertir du texte. Si encoding est NULL, l'encodage système courant est utilisé.
Tcl_Obj *objPtr (en entrée)
Nom de l'encodage pour lequel obtenir le jeton.
Tcl_Encoding *encodingPtr (en sortie)
Pointe vers l'emplacement où le jeton d'encodage doit être écrit.
const char *src (en entrée)
Pour les fonctions Tcl_ExternalToUtf, un tableau d'octets dans l'encodage spécifié qui doit être converti en UTF-8. Pour les fonctions Tcl_UtfToExternal et Tcl_WinUtfToTChar, un tableau de caractères UTF-8 à convertir vers l'encodage spécifié.

Un tableau de caractères TCHAR Windows à convertir en UTF-8.
int srcLen (en entrée)
Longueur de src ou tsrc en octets. Si la longueur est négative, la longueur spécifique à l'encodage de la chaîne est utilisée.
Tcl_DString *dstPtr (en sortie)
Pointeur vers une Tcl_DString non initialisée ou libérée dans laquelle le résultat converti sera stocké.
int flags (en entrée)
Divers bits d'indicateur combinés par OR. TCL_ENCODING_START indique que le tampon source est le premier bloc d'un flux d'entrée (potentiellement multi-blocs), informant la routine de conversion de réinitialiser son état initial et d'effectuer toute initialisation nécessaire avant la conversion du premier octet. TCL_ENCODING_END indique que le tampon source est le dernier bloc d'un flux d'entrée (potentiellement multi-blocs), informant la routine de conversion d'effectuer toute finalisation nécessaire après la conversion du dernier octet, puis de réinitialiser son état initial. TCL_ENCODING_STOPONERROR indique que la routine de conversion doit retourner immédiatement lors de la lecture d'un caractère source inexistant dans l'encodage cible ; sinon, un caractère de remplacement par défaut sera automatiquement substitué.
Tcl_EncodingState *statePtr (en entrée/sortie)
Utilisé lors de la conversion d'un flux d'octets (généralement long ou de longueur indéfinie) de manière fragmentée. La routine de conversion stocke son état courant dans *statePtr après la conversion de src (le tampon contenant le fragment courant) ; ces informations d'état doivent être renvoyées lors de la conversion du fragment suivant du flux, afin que la routine de conversion sache dans quel état elle s'est arrêtée à la fin du dernier fragment. Peut être NULL, auquel cas la valeur spécifiée pour flags est ignorée et le tampon source est supposé contenir la chaîne complète à convertir.
char *dst (en sortie)
Tampon dans lequel le résultat converti sera stocké. Pas plus de dstLen octets seront stockés dans dst.
int dstLen (en entrée)
La longueur maximale du tampon de sortie dst en octets.
int *srcReadPtr (en sortie)
Rempli avec le nombre d'octets de src qui ont été effectivement convertis. Cela peut être inférieur à la longueur source originale s'il y a eu un problème lors de la conversion de certains caractères source. Peut être NULL.
int *dstWrotePtr (en sortie)
Rempli avec le nombre d'octets qui ont été effectivement stockés dans le tampon de sortie à la suite de la conversion. Peut être NULL.
int *dstCharsPtr (en sortie)
Rempli avec le nombre de caractères qui correspondent au nombre d'octets stockés dans le tampon de sortie. Peut être NULL.
Tcl_DString *bufPtr (en sortie)

INTRODUCTION

Ces routines convertissent entre la représentation interne des caractères de Tcl, UTF-8, et les représentations de caractères utilisées par divers systèmes d'exploitation ou systèmes de fichiers, tels qu'Unicode, ASCII, ou Shift-JIS. Lors de l'opération sur des chaînes, comme l'obtention des noms de fichiers ou l'affichage de caractères à l'aide de polices internationales, les chaînes doivent être traduites dans un ou potentiellement plusieurs formats que les divers appels système peuvent utiliser. Par exemple, sur un poste de travail Unix japonais, un utilisateur pourrait obtenir un nom de fichier représenté dans l'encodage de fichier EUC-JP, puis traduire les caractères vers l'encodage de police jisx0208 afin d'afficher le nom de fichier dans un widget Tk. Le but du package d'encodage est d'aider à combler le fossé de traduction. UTF-8 fournit un terrain d'étape intermédiaire pour tous les divers encodages. Dans l'exemple ci-dessus, le texte serait traduit en UTF-8 à partir de l'encodage de fichier utilisé par le système d'exploitation. Ensuite, il serait traduit de UTF-8 vers l'encodage de police requis par les routines d'affichage.

Certains encodages de base sont compilés dans Tcl. D'autres peuvent être définis par l'utilisateur ou chargés dynamiquement à partir de fichiers d'encodage d'une manière indépendante de la plateforme.

DESCRIPTION

Tcl_GetEncoding recherche un encodage à partir de son name. Le nom peut faire référence à un encodage Tcl intégré, à un encodage défini par l'utilisateur enregistré en appelant Tcl_CreateEncoding, ou à un fichier d'encodage chargeable dynamiquement. La valeur de retour est un jeton qui représente l'encodage et peut être utilisé dans des appels ultérieurs à des procédures telles que Tcl_GetEncodingName, Tcl_FreeEncoding et Tcl_UtfToExternal. Si le nom ne fait référence à aucun encodage connu ou chargeable, NULL est retourné et un message d'erreur est retourné dans interp.

Le package d'encodage maintient une base de données de tous les encodages actuellement en cours d'utilisation. La première fois que name est rencontré, Tcl_GetEncoding retourne un encodage avec un compteur de références de 1. Si le même name est demandé plusieurs fois, alors le compteur de références pour cet encodage est incrémenté sans la surcharge liée à l'allocation d'un nouvel encodage et de toutes ses structures de données associées.

Lorsqu'un encoding n'est plus nécessaire, Tcl_FreeEncoding doit être appelé pour le libérer. Lorsqu'un encoding n'est plus utilisé nulle part (c'est-à-dire qu'il a été libéré autant de fois qu'il a été obtenu), Tcl_FreeEncoding libérera tout le stockage utilisé par l'encodage et le supprimera de la base de données.

Tcl_GetEncodingFromObj traite la représentation sous forme de chaîne de objPtr comme un nom d'encodage, et recherche un encodage avec ce nom, tout comme le fait Tcl_GetEncoding. Lorsqu'un encodage est trouvé, il est mis en cache dans la valeur de objPtr pour une référence future, le jeton Tcl_Encoding est écrit dans le stockage pointe

Mantener toda la estructura del archivo. El valor TCL_OK se devuelve cuando se pasa encodingPtr. Si no se encuentra ningún tipo de codificación, se devuelve el valor TCL_ERROR y no se realiza ninguna escritura en *encodingPtr. Es similar a Tcl_GetEncoding, el usuario debe llamar a Tcl_FreeEncoding sobre el token de codificación resultante cuando ya no lo use.

Tcl_ExternoAUTF8DString convierte un buffer fuente src de la codificación especificada encoding a UTF-8. Los bytes convertidos se almacenan en dstPtr, que luego se termina con un cero de la codificación específica. El usuario debe llamar eventualmente a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Cuando se convierte, si alguno de los caracteres en el buffer fuente no puede representarse en la codificación de destino, se usa un carácter de reemplazo por defecto. El valor devuelto es un puntero al valor almacenado en el DString.

Tcl_ExternoAUTF8 convierte un buffer fuente src de la codificación especificada encoding a UTF-8. MÁS de srcLen bytes se convierten del buffer fuente y se almacenan hasta dstLen bytes en dst. En todos los casos, *srcReadPtr se llena con el número de bytes convertidos de src y *dstWrotePtr con el número correspondiente de bytes almacenados en dst. El valor devuelto es uno de los siguientes:

TCL_OK
Todo el contenido de src se ha convertido.
TCL_CONVERT_NOSPACE
El buffer de destino no es suficiente para almacenar todos los datos convertidos; se convierten tantos caracteres como sea posible.
TCL_CONVERT_MULTIBYTE
Los últimos bytes de la fuente eran el inicio de una secuencia multibyte, pero se necesitaban más bytes para completarla. Una llamada posterior a la rutina de conversión debe pasar un buffer con los bytes no convertidos que aún estén en src más algunos bytes de la fuente de origen para completar la secuencia.
TCL_CONVERT_SYNTAX
El buffer fuente contiene una secuencia de caracteres inválida. Esto puede ocurrir si el flujo de entrada ha sido dañado o si el método de codificación especificado fue mal identificado.
TCL_CONVERT_UNKNOWN
El buffer fuente contiene un carácter que no puede representarse en la codificación de destino y TCL_ENCODING_STOPONERROR fue especificado.

Tcl_AUTF8AExternoDString convierte un buffer fuente src de UTF-8 a la codificación especificada encoding. Los bytes convertidos se almacenan en dstPtr, que luego se termina con el cero adecuado de la codificación específica. El usuario debe llamar eventualmente a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Cuando se convierte, si alguno de los caracteres en el buffer fuente no puede representarse en la codificación de destino, se usa un carácter de reemplazo por defecto. El valor devuelto es un puntero al valor almacenado en el DString.

Tcl_AUTF8AExterno convierte un buffer fuente src de UTF-8 a la codificación especificada encoding. MÁS de srcLen bytes se convierten del buffer fuente y se almacenan hasta dstLen bytes en dst. En todos los casos, *srcReadPtr se llena con el número de bytes convertidos de src y *dstWrotePtr con el número correspondiente de bytes almacenados en dst. Los valores devueltos son los mismos que en Tcl_ExternoAUTF8.

Tcl_WinUTF8ATChar y Tcl_WinTCharAUTF8 son funciones de conveniencia solo para Windows para convertir entre UTF-8 y cadenas de Windows basadas en el tipo TCHAR, que por convención es un carácter Unicode en Windows NT.

Tcl_GetEncodingName es aproximadamente la inversa de Tcl_GetEncoding. Dada una codificación encoding, el valor devuelto es el argumento name utilizado para crear la codificación. La cadena devuelta por Tcl_GetEncodingName solo se garantiza que persista hasta que la codificación encoding sea eliminada. El usuario no debe modificar esta cadena.

Tcl_SetSystemEncoding establece la codificación predeterminada que se debe usar cuando el usuario pasa un valor nulo para el argumento encoding a cualquier otra función de codificación. Si name es nulo, la codificación del sistema se restablece a la codificación predeterminada binary. Si el nombre no se refiere a ninguna codificación conocida o cargable, se devuelve TCL_ERROR y un mensaje de error se deja en interp. De lo contrario, este procedimiento incrementa la referencia del nuevo sistema de codificación, decrementa la referencia del antiguo sistema de codificación y devuelve TCL_OK.

Tcl_GetEncodingNameFromEnvironment proporciona una manera para que la biblioteca Tcl reporte el nombre de la codificación que cree que es adecuada para el sistema de codificación, basándose en llamadas al sistema y el examen del entorno adecuado para la plataforma. Recibe bufPtr, un puntero a un Tcl_DString inicialmente no inicializado o liberado, y escribe el nombre de la codificación en él. El valor devuelto es el Tcl_DStringValue.

Tcl_GetEncodingNames establece el resultado interp a una lista de nombres de todas las codificaciones definidas o dinámicamente cargables, buscando en la ruta de codificaciones especificada por Tcl_SetDefaultEncodingDir. Este procedimiento no asegura que los archivos dinámicamente cargables contengan datos válidos, pero solo asegura que existen.

Tcl_CreateEncoding define una nueva codificación y registra los procedimientos C que se llaman para convertir entre esta codificación y UTF-8. Las codificaciones creadas mediante Tcl_CreateEncoding son después visibles en la base de datos utilizada por Tcl_GetEncoding. De manera similar a Tcl_GetEncoding, el valor devuelto es un token que representa la codificación y se puede usar en llamadas posteriores a otras funciones de codificación. Tcl_CreateEncoding devuelve una codificación con un contador de referencias de 1. Si ya existe una codificación con el nombre especificado, su entrada en la base de datos se reemplaza con la nueva codificación; el token de la codificación antigua permanece válido y sigue comportándose como antes, pero los usuarios que utilicen el nuevo token ahora llamarán a los procedimientos de la nueva codificación.

El argumento typePtr de Tcl_CreateEncoding contiene información sobre el nombre de la codificación y los procedimientos que se llaman para convertir entre esta codificación y UTF-8. Se define como:

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

El encodingName proporciona un nombre para la codificación, por el cual se puede referir en otros procedimientos como Tcl_GetEncoding. El toUtfProc se refiere a un procedimiento de devolución de llamada para convertir texto de esta codificación a UTF-8. El fromUtfProc se refiere a un procedimiento de devolución de llamada para convertir texto de UTF-8 a esta codificación. El freeProc se refiere a un procedimiento de devolución de llamada para invocar cuando se elimina esta codificación. El campo freeProc puede ser nulo. El clientData contiene un valor arbitrario de una palabra, pasado a toUtfProc, fromUtfProc y freeProc cuando se llamen. Generalmente, esto es un puntero a un conjunto de datos que contiene información específica de la codificación, que es utilizada por los procedimientos de devolución de llamada. Por ejemplo, dos codificaciones muy similares como ascii y macRoman pueden usar el mismo procedimiento de devolución de llamada, pero usan diferentes valores de clientData para controlar su comportamiento. El nullSize especifica el número de ceros que indican el fin de cadena en esta codificación. Debe ser 1 (para codificaciones de un solo byte o multibyte como ASCII o Shift-JIS) o 2 (para codificaciones de dos bytes como Unicode). Las codificaciones con tamaño fijo de 3 o más bytes por carácter (como CNS11643) no se aceptan.

Los procedimientos de devolución de llamada toUtfProc y fromUtfProc deben corresponder al tipo Tcl_EncodingConvertProc:

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

Los procedimientos toUtfProc y fromUtfProc son llamados por Tcl_ExternoAUTF8 o Tcl_AUTF8AExterno para realizar la conversión real. El parámetro clientData de estos procedimientos es el mismo que el clientData especificado en Tcl_CreateEncoding cuando se creó la codificación. Los argumentos restantes de los procedimientos de devolución de llamada son los mismos que los argumentos, documentados al principio, de Tcl_ExternoAUTF8 o Tcl_AUTF8AExterno, con la siguiente excepción. Si el argumento srcLen de una de estas funciones de alto nivel es negativo, el valor pasado al procedimiento de devolución de llamada será la longitud adecuada de la codificación de origen src. Si alguno de los argumentos srcReadPtr, dstWrotePtr o dstCharsPtr de una de estas funciones de alto nivel es NULL, el valor correspondiente pasado al procedimiento de devolución de llamada será una ubicación no NULL.

El procedimiento de devolución de llamada freeProc, si no es NULL, debe corresponder al tipo Tcl_EncodingFreeProc:

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

Este procedimiento freeProc se llama cuando se elimina la codificación. El parámetro clientData es el mismo que el clientData especificado en Tcl_CreateEncoding cuando se creó la codificación.

Tcl_GetEncodingSearchPath y Tcl_SetEncodingSearchPath se llaman para acceder y establecer la lista de carpetas de directorios del sistema de archivos que se buscan para archivos de codificación.

El valor devuelto por Tcl_GetEncodingSearchPath es el valor almacenado por la última llamada exitosa a Tcl_SetEncodingSearchPath. Si no se han realizado llamadas a Tcl_SetEncodingSearchPath, Tcl calculará un valor inicial basado en el entorno. Existe una ruta de búsqueda de codificación para el proceso completo, compartida entre todos los hilos del proceso.

INTRODUCTION

Les fichiers d'encodage Tcl ne sont pas vérifiés comme existant en tant que répertoires lisibles du système de fichiers. Lors de la recherche de fichiers de données d'encodage, les répertoires du système de fichiers inexistants ou non lisibles sur le searchPath sont ignorés silencieusement.

DESCRIPTION

L'espace empêcherait de précompiler dans Tcl tous les algorithmes d'encodage possibles, de sorte que de nombreux encodages sont stockés sur disque sous forme de fichiers d'encodage chargeables dynamiquement. Ce comportement permet également à l'utilisateur de créer des fichiers d'encodage supplémentaires qui peuvent être chargés en utilisant le même mécanisme. Ces fichiers d'encodage contiennent des informations sur les tables et/ou les séquences d'échappement utilisées pour mapper entre un encodage externe et Unicode. L'encodage externe peut se composer de caractères d'un octet, de plusieurs octets ou de deux octets.

FICHIERS ENCODAGE

Chaque encodage chargeable dynamiquement est représenté par un fichier texte. La ligne initiale du fichier, commençant par un symbole “#”, est un commentaire qui fournit une description lisible par l'homme du fichier. La ligne suivante identifie le type de fichier d'encodage. Il peut s'agir de l'une des lettres suivantes :

[1] S
Un encodage à un octet, où un caractère est toujours d'un octet dans l'encodage. Un exemple est iso8859-1, utilisé par de nombreuses langues européennes.
[2] D
Un encodage à double octet, où un caractère est toujours de deux octets dans l'encodage. Un exemple est big5, utilisé pour le texte chinois.
[3] M
Un encodage multi-octets, où un caractère peut être d'un ou deux octets. Certains octets sont des octets de tête, indiquant qu'un autre octet doit suivre et que les deux octets ensemble représentent un caractère. D'autres octets ne sont pas des octets de tête et se représentent eux-mêmes. Un exemple est shiftjis, utilisé par de nombreux ordinateurs japonais.
[4] E
Un fichier d'encodage à séquence d'échappement, spécifiant que certaines séquences d'octets ne représentent pas des caractères, mais des commandes qui décrivent comment les octets suivants doivent être interprétés.

Le reste des lignes du fichier dépend du type.

Les cas [1], [2] et [3] sont collectivement appelés fichiers d'encodage basés sur des tables. Les lignes d'un fichier d'encodage basé sur des tables sont dans le même format que cet exemple tiré de l'encodage shiftjis (ce n'est pas le fichier complet) :

La troisième ligne du fichier contient trois nombres. Le premier nombre est le caractère de remplacement (en base 16) à utiliser lors de la conversion de UTF-8 vers cet encodage. Le second nombre est un 1 si ce fichier représente l'encodage d'une police de symboles, ou 0 sinon. Le dernier nombre (en base 10) indique combien de pages de données suivent.

Les lignes suivantes dans l'exemple ci-dessus sont des pages qui décrivent comment mapper depuis l'encodage vers Unicode à 2 octets. La première ligne d'une page identifie le numéro de la page. Elle est suivie de 256 nombres de deux octets, arrangés en 16 lignes de 16 nombres. Étant donné un caractère dans l'encodage, l'octet de tête de ce caractère est utilisé pour sélectionner la page, et l'octet de queue de ce caractère est utilisé comme index pour sélectionner l'un des nombres de deux octets dans cette page - la valeur obtenue étant le caractère Unicode correspondant. Par examen de l'exemple ci-dessus, on peut voir que les caractères 0x7E et 0x8163 en shiftjis correspondent à 203E et 2026 dans Unicode, respectivement.

Suite à la première page se trouveront toutes les autres pages, chacune dans le même format que la première : un nombre identifiant la page suivi de 256 caractères Unicode de deux octets. Si un caractère de l'encodage correspond au caractère Unicode 0000, cela signifie que le caractère n'existe pas réellement. Si tous les caractères d'une page correspondent à 0000, cette page peut être omise.

Le cas [4] est le fichier d'encodage à séquence d'échappement. Les lignes de ce type de fichier sont dans le même format que cet exemple tiré de l'encodage iso2022-jp :

# Fichier d'encodage : iso2022-jp, piloté par échappement
E
init		{}
final		{}
iso8859-1	\x1b(B
jis0201		\x1b(J
jis0208		\x1b$@
jis0208		\x1b$B
jis0212		\x1b$(D
gb2312		\x1b$A
ksc5601		\x1b$(C

Dans le fichier, la première colonne représente une option et la seconde colonne est la valeur associée. init est une chaîne à émettre ou à attendre avant que le premier caractère ne soit converti, tandis que final est une chaîne à émettre ou à attendre après le dernier caractère. Toutes les autres options sont des noms d'encodages basés sur des tables ; la valeur associée est la séquence d'échappement qui marque cet encodage. La syntaxe Tcl est utilisée pour les valeurs ; dans l'exemple ci-dessus, par exemple, “{}” représente la chaîne vide et “\x1b” représente le caractère 27.

Lorsque Tcl_GetEncoding rencontre un nom d'encodage qui n'a pas été chargé, il tente de charger un fichier d'encodage nommé name.enc à partir du sous-répertoire encoding de chaque répertoire dans lequel Tcl recherche sa bibliothèque de scripts. Si le fichier d'encodage existe, mais est malformé, un message d'erreur sera laissé dans interp.
