ARGUMENTS

Interpréteur dans lequel enregistrer les informations.

int code Le code de retour de l'évaluation du script.
Tcl_Obj *options Un dictionnaire d'options de retour.

const char *message (entrée)
Pour Tcl_AddErrorInfo, il s'agit d'une chaîne C conventionnelle à ajouter à la valeur de l'option de retour -errorinfo>. Pour Tcl_AddObjErrorInfo, il pointe vers le premier octet d'un tableau de length octets contenant une chaîne à ajouter à la valeur de l'option de retour -errorinfo>. Ce tableau d'octets peut contenir des octets nuls si length est négatif.
Tcl_Obj *objPtr (entrée)
Un message à ajouter à la valeur de l'option de retour -errorinfo> sous la forme d'une valeur Tcl_Obj.
int length (entrée)
Le nombre d'octets à copier de message lors de l'ajout à la valeur de l'option de retour -errorinfo>. S'il est négatif, tous les octets jusqu'au premier octet nul sont utilisés.
Tcl_Obj *errorObjPtr (entrée)
La valeur de l'option de retour -errorcode> sera définie à cette valeur.
const char *element (entrée)
Chaîne à enregistrer comme élément de l'option de retour -errorcode>. Le dernier argument doit être (char *)NULL.
va_list argList (entrée)
Une liste d'arguments qui doit avoir été initialisée avec va_start et nettoyée avec va_end.

int lineNum Le numéro de ligne d'un script où une erreur s'est produite.
const char *script (entrée)
Le pointeur vers le premier caractère du script contenant l'instruction (doit être <= command).
const char *command (entrée)
Le pointeur vers le premier caractère de l'instruction qui a généré l'erreur.
int commandLength (entrée)
Le nombre d'octets dans l'instruction ; -1 signifie utiliser tous les octets jusqu'au premier octet nul.

DESCRIPTION

Les routines Tcl_SetReturnOptions et Tcl_GetReturnOptions exposent les mêmes capacités que les routines return et catch sous la forme d'une interface C.

Tcl_GetReturnOptions récupère le dictionnaire d'options de retour d'un interpréteur après l'évaluation d'un script. Les routines telles que Tcl_Eval sont appelées pour évaluer un script dans un interpréteur. Ces routines renvoient un code d'achèvement entier. Ces routines maintiennent également dans l'interpréteur le résultat et le dictionnaire d'options de retour générés par l'évaluation du script. De manière similaire à Tcl_GetObjResult, Tcl_GetReturnOptions récupère le dictionnaire d'options de retour. Le code d'achèvement entier doit être passé comme argument code à Tcl_GetReturnOptions afin que toutes les options requises soient présentes dans le dictionnaire. Plus précisément, une valeur code de TCL_ERROR garantira que les entrées pour les clés -errorinfo, -errorcode et -errorline sont incluses dans le dictionnaire. Les entrées pour les clés -code et -level seront également ajustées si nécessaire pour correspondre à la valeur de code. Le (Tcl_Obj *) renvoyé par Tcl_GetReturnOptions pointe vers un Tcl_Obj non partagé avec un compteur de références de zéro. Le dictionnaire peut être modifié, en ajoutant, supprimant ou écrasant n'importe quelle entrée, sans avoir à vérifier une valeur partagée. Comme pour tout Tcl_Obj avec un compteur de références de zéro, il est de la responsabilité de l'utilisateur d'organiser sa disposition avec Tcl_DecrRefCount ou de le référencer via Tcl_IncrRefCount (ou l'une des nombreuses fonctions qui l'appellent, par exemple Tcl_SetObjResult et Tcl_SetVar2Ex).

Une utilisation typique de Tcl_GetReturnOptions est de récupérer la pile d'appels lorsqu'un script renvoie TCL_ERROR, comme suit :

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* Faire quelque chose avec stackTrace */
    Tcl_DecrRefCount(options);
}

Tcl_SetReturnOptions définit les options de retour de l'interpréteur à options. Si options contient des valeurs invalides pour l'une des clés, TCL_ERROR sera renvoyé et le résultat de l'interpréteur sera défini sur un message d'erreur approprié. Sinon, un code d'achèvement correspondant aux clés -code et -level dans options sera renvoyé.

Par exemple, la commande return de Tcl peut être implémentée en termes de Tcl_SetReturnOptions comme suit :

if ((objc % 2) == 0) { /* argument explicite */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(Ce n'est pas réellement implémenté ainsi. Les privilèges internes permettent une alternative plus efficace qui s'aligne mieux avec le compilateur de bytecode.)

Remarque : un nouveau Tcl_Obj peut être passé comme argument options sans avoir besoin de gérer le compteur de références. Ceci est analogue à Tcl_SetObjResult).

Bien que Tcl_SetReturnOptions fournisse une interface générale pour définir n'importe quelle collection d'options de retour, il existe un nombre limité d'options de retour qui sont très fréquemment utilisées. Les plus remarquables sont les options -errorinfo et -errorcode, qui doivent être correctement définies lorsque la procédure de commande renvoie TCL_ERROR. L'option -errorline est également lue par les commandes qui évaluent des scripts et souhaitent fournir des informations de localisation détaillées dans le texte de la pile d'appels. Tcl offre plusieurs interfaces plus simples pour définir directement ces options de retour.

La valeur de l'option -errorinfo contient une pile d'appels des opérations qui ont été exécutées lorsqu'une erreur s'est produite, et est destinée à être lisible par l'homme. La valeur de l'option -errorcode contient une liste d'éléments Tcl qui est censée être lisible par machine. Le premier élément de la valeur de l'option -errorcode identifie le type d'erreur qui s'est produite (par exemple, POSIX signifie qu'une erreur s'est produite dans un appel système POSIX). Les éléments supplémentaires contiennent des informations supplémentaires dépendant du type d'erreur. Pour plus de détails sur les divers formats de l'option -errorcode utilisés par les commandes intégrées de Tcl, voir l'entrée de manuel de la variable errorCode).

La valeur de l'option -errorinfo est progressivement construite au fur et à mesure que l'erreur remonte les opérations imbriquées. Chaque fois qu'un code d'erreur est renvoyé à Tcl_Eval, ou à toute routine qui effectue l'évaluation de scripts, la procédure Tcl_AddErrorInfo est appelée pour ajouter du texte supplémentaire à la valeur de l'option -errorinfo> décrivant l'instruction en cours d'exécution lorsque l'erreur s'est produite. Lorsque l'erreur a été entièrement transmise à l'application, elle contiendra une trace complète de l'activité en cours lorsque l'erreur s'est produite.

Il est parfois utile d'ajouter des informations supplémentaires à l'option -errorinfo> au-delà de ce qui peut être automatiquement fourni par les routines d'évaluation de scripts. Tcl_AddErrorInfo peut être utilisé à cette fin : son argument message est une chaîne supplémentaire à ajouter à la valeur de l'option de retour -errorinfo>. Par exemple, lorsqu'une erreur se produit pendant l'exécution de la commande source, la procédure Tcl_AddErrorInfo est appelée pour enregistrer le nom du fichier traité et le numéro de ligne auquel l'erreur s'est produite. De même, lorsqu'une erreur se produit pendant l'évaluation d'une commande, Tcl_AddErrorInfo est appelée pour enregistrer les informations nécessaires.

NOM

Tcl_LogCommandInfo

SYNTAXE

Tcl_LogCommandInfo(3)

ARGUMENTS

Aucun

DESCRIPTION

La procédure Tcl_LogCommandInfo est appelée après qu'une erreur se produit dans un interpréteur. Elle ajoute des informations sur la commande qui était en cours d'exécution lorsque l'erreur s'est produite à la valeur de -errorinfo, et le numéro de ligne stocké en interne dans l'interpréteur est défini.
