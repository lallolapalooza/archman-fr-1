Tcl_RegExpExec(interp, regexp, text, start)

void
Tcl_RegExpRange(regexp, index, startPtr, endPtr)

Tcl_RegExp
Tcl_GetRegExpFromObj(interp, patObj, cflags)

Tcl_RegExpExecObj(interp, regexp, textObj, offset, nmatches, eflags)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur Tcl à utiliser pour le rapport d'erreurs. L'interpréteur peut être NULL si aucun rapport d'erreur n'est souhaité.
Tcl_Obj *textObj (entrée/sortie)
Fait référence à la valeur à partir de laquelle obtenir le texte à rechercher. La représentation interne de la valeur peut être convertie dans un format qui peut être recherché efficacement.
Tcl_Obj *patObj (entrée/sortie)
Fait référence à la valeur à partir de laquelle obtenir une expression régulière. L'expression régulière compilée est mise en cache dans la valeur.
const char *text (entrée)
Texte dans lequel rechercher une correspondance avec une expression régulière.
const char *pattern (entrée)
Chaîne de caractères sous forme de motif d'expression régulière.
Tcl_RegExp regexp (entrée)
Expression régulière compilée. Doit avoir été retournée précédemment par Tcl_GetRegExpFromObj ou Tcl_RegExpCompile.
const char *start (entrée)
Si text n'est qu'une partie d'une autre chaîne, cet argument identifie le début de la chaîne plus grande. S'il n'est pas le même que text, alors aucun match “^” ne sera autorisé.
int index (entrée)
Spécifie quelle plage est souhaitée : 0 signifie la plage de la correspondance entière, 1 ou plus signifie la plage qui a correspondu à une sous-expression entre parenthèses.
const char **startPtr (sortie)
L'adresse du premier caractère de la plage est stockée ici, ou NULL s'il n'y a pas de telle plage.
const char **endPtr (sortie)
L'adresse du caractère juste après le dernier caractère de la plage est stockée ici, ou NULL s'il n'y a pas de telle plage.
int cflags (entrée)
Combinaison par OR des drapeaux de compilation TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, TCL_REG_EXPANDED, TCL_REG_QUOTE, TCL_REG_NOCASE, TCL_REG_NEWLINE, TCL_REG_NLSTOP, TCL_REG_NLANCH, TCL_REG_NOSUB, et TCL_REG_CANMATCH. Voir ci-dessous pour plus d'informations.
int offset (entrée)
Le décalage de caractères dans le texte où la recherche de correspondance doit commencer. La valeur du décalage n'a aucun impact sur les correspondances ^. Ce comportement est contrôlé par eflags.
int nmatches (entrée)
Le nombre de sous-expressions correspondantes qui doivent être mémorisées pour une utilisation ultérieure. Si cette valeur est 0, aucune information de correspondance de sous-expression ne sera calculée. Si la valeur est -1, toutes les sous-expressions correspondantes seront mémorisées. Toute autre valeur sera considérée comme le nombre maximum de sous-expressions à mémoriser.
int eflags (entrée)
Combinaison par OR des drapeaux d'exécution TCL_REG_NOTBOL et TCL_REG_NOTEOL. Voir ci-dessous pour plus d'informations.
Tcl_RegExpInfo *infoPtr (sortie)
L'adresse de l'emplacement où les informations sur une correspondance précédente doivent être stockées par Tcl_RegExpGetInfo.

DESCRIPTION

Tcl_RegExpMatch détermine si son argument pattern correspond à regexp, où regexp est interprété comme une expression régulière en utilisant les règles de la page de référence re_syntax. S'il y a une correspondance, Tcl_RegExpMatch retourne 1. S'il n'y a pas de correspondance, Tcl_RegExpMatch retourne 0. Si une erreur survient pendant le processus de correspondance (par exemple, pattern n'est pas une expression régulière valide), Tcl_RegExpMatch retourne -1 et laisse un message d'erreur dans le résultat de l'interpréteur. Tcl_RegExpMatchObj est similaire à Tcl_RegExpMatch, sauf qu'elle opère sur les valeurs Tcl textObj et patObj au lieu de chaînes UTF. Tcl_RegExpMatchObj est généralement plus efficace que Tcl_RegExpMatch, c'est donc l'interface préférée.

Tcl_RegExpCompile, Tcl_RegExpExec, et Tcl_RegExpRange fournissent un accès de plus bas niveau au moteur de correspondance de motifs d'expressions régulières. Tcl_RegExpCompile compile une chaîne d'expression régulière dans la forme interne utilisée pour une correspondance de motif efficace. La valeur de retour est un jeton pour cette forme compilée, qui peut être utilisée dans des appels ultérieurs à Tcl_RegExpExec ou Tcl_RegExpRange. Si une erreur survient lors de la compilation de l'expression régulière, Tcl_RegExpCompile retourne NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Remarque : la valeur de retour de Tcl_RegExpCompile n'est valide que jusqu'au prochain appel à Tcl_RegExpCompile ; il n'est pas sûr de conserver ces valeurs pendant de longues périodes.

Tcl_RegExpExec exécute le moteur de correspondance de motifs d'expressions régulières. Il retourne 1 si text contient une plage de caractères qui correspond à regexp, 0 si aucune correspondance n'est trouvée, et -1 si une erreur survient. En cas d'erreur, Tcl_RegExpExec laisse un message d'erreur dans le résultat de l'interpréteur. Lors de la recherche dans une chaîne pour plusieurs correspondances d'un motif, il est important de distinguer le début de la chaîne d'origine du début de la recherche actuelle. Par exemple, lors de la recherche de la deuxième occurrence d'une correspondance, l'argument text peut pointer vers le caractère juste après la première correspondance ; cependant, il est important que le moteur de correspondance sache que ce n'est pas le début de la chaîne entière, afin qu'il n'autorise pas les atomes “^” du motif à correspondre. L'argument start fournit cette information en pointant vers le début de la chaîne globale contenant text. Start sera inférieur ou égal à text ; s'il est inférieur à text, aucun match ^ ne sera autorisé.

Tcl_RegExpRange peut être invoqué après que Tcl_RegExpExec ait retourné ; il fournit des informations détaillées sur les plages de la chaîne qui ont correspondu à quelles parties du motif. Tcl_RegExpRange retourne une paire de pointeurs dans *startPtr et *endPtr qui identifient une plage de caractères dans la chaîne source pour l'appel le plus récent à Tcl_RegExpExec. Index indique quelle parmi plusieurs plages est souhaitée : si index est 0, les informations sont retournées sur la plage globale de caractères qui a correspondu à l'ensemble du motif ; sinon, les informations sont retournées sur la plage de caractères qui a correspondu à la index-ième sous-expression entre parenthèses dans le motif. S'il n'y a pas de plage correspondant à index, NULL est stocké dans *startPtr et *endPtr.

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj, et Tcl_RegExpGetInfo sont des interfaces de valeurs qui fournissent le contrôle le plus direct de la bibliothèque d'expressions régulières de Henry Spencer. Pour les utilisateurs qui ont besoin de modifier directement les options de compilation et d'exécution, il est recommandé d'utiliser ces interfaces au lieu d'appeler les fonctions internes d'expressions régulières. Ces interfaces gèrent les détails des traductions UTF vers Unicode ainsi que des améliorations de performance grâce à la mise en cache dans les valeurs de motif et de chaîne.

Tcl_GetRegExpFromObj tente de retourner une expression régulière compilée à partir de patObj. Si la valeur ne contient pas déjà une expression régulière compilée, elle tentera d'en créer une à partir de la chaîne dans la valeur et de l'attribuer à la représentation interne de patObj. La valeur de retour de cette fonction est de type Tcl_RegExp. La valeur de retour est un jeton pour cette forme compilée, qui peut être utilisée dans des appels ultérieurs à Tcl_RegExpExecObj ou Tcl_RegExpGetInfo. Si une erreur survient lors de la compilation de l'expression régulière, Tcl_GetRegExpFromObj retourne NULL et laisse un message d'erreur dans le résultat de l'interpréteur. Le jeton d'expression régulière peut être utilisé tant que la représentation interne de patObj fait référence à la forme compilée. L'argument cflags est un OR bit-à-bit de zéro ou plusieurs des drapeaux suivants qui contrôlent la compilation de patObj :

TCL_REG_ADVANCED
Active le mode avancé d'expressions régulières de Tcl. Ce mode inclut des constructions telles que `(?i)` pour la casse insensible, `(?x)` pour l'expansion des espaces, `(?m)` pour le mode multi-lignes, `(?s)` pour permettre au `.` de correspondre aux nouvelles lignes, et des groupes de non-capture `(?:...)`. Voir la documentation de Tcl sur les expressions régulières pour une description complète.
TCL_REG_EXTENDED
Utilise la syntaxe d'expressions régulières étendue (style Perl/POSIX). Ceci est le mode par défaut pour la commande Tcl `regexp`.
TCL_REG_BASIC
Utilise la syntaxe d'expressions régulières de base (style `egrep`).
TCL_REG_EXPANDED
Permet aux espaces blancs dans le motif d'être ignorés et aux `#` d'indiquer des commentaires. Cette option est utile pour rendre les motifs complexes plus lisibles.
TCL_REG_QUOTE
Traite tous les caractères du motif comme des littéraux, sauf les caractères d'échappement `\` qui conservent leur signification. Utile pour faire une correspondance exacte avec une chaîne qui pourrait contenir des caractères spéciaux d'expression régulière.
TCL_REG_NOCASE
Rend la correspondance insensible à la casse.
TCL_REG_NEWLINE
Les caractères de nouvelle ligne `\n` sont traités comme des caractères normaux et ne provoquent pas le début d'une nouvelle ligne. Le caractère `^` ne correspondra au début de la chaîne que si l'option `TCL_REG_NLANCH` n'est pas utilisée. Le caractère `$` ne correspondra à la fin de la chaîne que si l'option `TCL_REG_NLSTOP` n'est pas utilisée.
TCL_REG_NLSTOP
Les caractères de nouvelle ligne `\n` dans le texte provoquent la fin d'une ligne. Le caractère `$` correspondra à la fin de la chaîne ou juste avant un caractère de nouvelle ligne.
TCL_REG_NLANCH
Les caractères de nouvelle ligne `\n` dans le texte provoquent le début d'une nouvelle ligne. Le caractère `^` correspondra au début de la chaîne ou juste après un caractère de nouvelle ligne.
TCL_REG_NOSUB
Si cette option est définie, les sous-expressions correspondantes ne seront pas calculées. Cela peut légèrement améliorer les performances si vous n'avez besoin que de savoir s'il y a une correspondance, et non de ce qui a correspondu.
TCL_REG_CANMATCH
Indique que le motif est utilisé uniquement pour voir s'il peut correspondre au texte, et non pour obtenir les informations sur les plages de correspondance. Cela peut être utilisé pour des optimisations dans certaines situations.

Tcl_RegExpExecObj exécute une expression régulière compilée contre un objet texte. Elle retourne 1 s'il y a une correspondance, 0 s'il n'y en a pas, et -1 en cas d'erreur. Les arguments offset et eflags contrôlent le début de la recherche et le comportement des ancres de début/fin de ligne. Les arguments nmatches et eflags dans Tcl_RegExpExecObj sont similaires à leurs homologues dans la commande Tcl `regexp`.

Tcl_RegExpGetInfo remplit la structure pointée par infoPtr avec des informations sur la dernière correspondance effectuée par l'expression régulière compilée regexp. La structure Tcl_RegExpInfo est définie comme suit :

typedef struct {
    int numMatches;
    const char **matches;
    int *lengths;
    int numTags;
    const char **tags;
    int *lengths;
} Tcl_RegExpInfo;

Le membre numMatches contiendra le nombre de correspondances qui ont été enregistrées (y compris la correspondance globale).

Le membre matches contiendra un tableau de pointeurs vers le début des correspondances enregistrées dans la chaîne de caractères d'origine. Le premier élément (index 0) pointera vers la correspondance globale. Les éléments suivants pointeront vers les correspondances des sous-expressions entre parenthèses dans le motif, dans l'ordre où elles apparaissent.

Le membre lengths contiendra un tableau de longueurs correspondant au tableau matches. Chaque élément sera la longueur en caractères de la correspondance correspondante.

Le membre numTags contiendra le nombre de groupes entre parenthèses dans le motif.

Le membre tags contiendra un tableau de pointeurs vers le début des sous-expressions entre parenthèses qui ont effectivement correspondu.

Le membre lengths (qui apparaît deux fois dans la définition ci-dessus, ce qui est probablement une erreur de frappe dans la documentation d'origine et devrait probablement être le même tableau que le précédent) contiendra un tableau de longueurs correspondant au tableau tags.

Les informations retournées par Tcl_RegExpGetInfo sont valides jusqu'à ce que l'expression régulière compilée soit libérée ou qu'une autre opération sur l'expression régulière soit effectuée.

Tcl_RegExpGetInfo(3)

NOM

Tcl_RegExpGetInfo

SYNTAXIS

Tcl_RegExpGetInfo(regexp, infoPtr)

ARGUMENTOS

regexp : Chaîne, pointeur vers un modèle d'expression régulière Tcl.
infoPtr : Pointeur vers une structure contenant les informations sur la dernière correspondance.

DESCRIPTION

Tcl_RegExpGetInfo récupère des informations sur la dernière correspondance effectuée avec une expression régulière regexp donnée. L'argument infoPtr contient un pointeur vers une structure définie comme suit :

typedef struct Tcl_RegExpInfo {
    int nsubs;
    Tcl_RegExpIndices *matches;
    long extendStart;
} Tcl_RegExpInfo;

Le champ nsubs contient le nombre d'expressions régulières secondaires entre parenthèses dans l'expression régulière. Si TCL_REG_NOSUB a été utilisé, cette valeur sera zéro. Le champ matches pointe vers un tableau de nsubs+1 valeurs indiquant les limites de chaque expression régulière secondaire correspondante. Le premier élément du tableau fait référence à la plage correspondant à l'ensemble de l'expression régulière, et les éléments suivants font référence aux expressions régulières secondaires entre parenthèses dans l'ordre où elles apparaissent dans le modèle. Chaque élément est une structure définie comme suit :

typedef struct Tcl_RegExpIndices {
    long start;
    long end;
} Tcl_RegExpIndices;

Les valeurs start et end sont des indices de caractères Unicode relatifs à l'emplacement de décalage dans objPtr où la correspondance a commencé. L'indice start identifie le premier caractère de l'expression régulière secondaire correspondante. L'indice end identifie le premier caractère après l'expression régulière secondaire correspondante. Si l'expression régulière secondaire a correspondu à une chaîne vide, alors start et end seront égaux. Si l'expression régulière secondaire n'a pas participé à la correspondance, alors start et end seront définis à -1.

Le champ extendStart dans Tcl_RegExpInfo n'est défini que si le drapeau TCL_REG_CANMATCH a été utilisé. Il indique le premier caractère de la chaîne où une correspondance peut se produire. Si une correspondance a été trouvée, ce sera le même que le début de la correspondance actuelle. Si aucune correspondance n'a été trouvée, il indique le point le plus précoce auquel une correspondance pourrait se produire si du texte supplémentaire est ajouté à la chaîne. Si aucune correspondance n'est possible, même avec du texte supplémentaire, ce champ sera défini à -1.
