DESCRIPTION

Les objets sont des entités typées qui ont un ensemble d'opérations ("méthodes") associées. Les classes sont des objets qui peuvent fabriquer d'autres objets. Chaque classe peut être considérée comme un objet en soi ; la vue objet peut être récupérée en utilisant Tcl_GetClassAsObject qui renvoie toujours l'objet lorsqu'elle est appliquée à une classe non détruite, et un objet peut être vu comme une classe avec l'aide de Tcl_GetObjectAsClass (qui renvoie soit la classe, soit NULL si l'objet n'est pas une classe). Un objet peut être recherché en utilisant la fonction Tcl_GetObjectFromObj, qui renvoie soit un objet, soit NULL (avec un message d'erreur dans le résultat de l'interpréteur) si l'objet ne peut être trouvé. La manière correcte de rechercher une classe par son nom est de rechercher l'objet portant ce nom, puis d'utiliser Tcl_GetObjectAsClass.

Chaque objet a sa propre commande et son propre espace de noms associés. La commande peut être récupérée en utilisant la fonction Tcl_GetObjectCommand, le nom de l'objet (et donc le nom de la commande) avec Tcl_GetObjectName, et l'espace de noms peut être récupéré en utilisant la fonction Tcl_GetObjectNamespace. Notez que la référence Tcl_Obj retournée par Tcl_GetObjectName est une référence partagée. Vous pouvez également savoir si l'objet a été marqué pour suppression avec Tcl_ObjectDeleted (il renvoie vrai si la suppression de l'objet a commencé) ; cela peut être utile lors du traitement des méthodes.

Les instances de classes sont créées en utilisant Tcl_NewObjectInstance, qui crée un objet à partir de n'importe quelle classe (et qui est appelé en interne par les méthodes create et new de la classe oo::class). Il prend des paramètres qui donnent optionnellement le nom de l'objet et de l'espace de noms à créer, et qui décrivent les arguments à passer au constructeur de la classe (le cas échéant). Le résultat de la fonction sera soit une référence au nouvel objet créé, soit NULL si la création a échoué (un message d'erreur sera alors laissé dans le résultat de l'interpréteur). De plus, les objets peuvent être copiés en utilisant Tcl_CopyObjectInstance qui crée une copie d'un objet sans exécuter de constructeurs.

Notez que la gestion du cycle de vie des objets est gérée en interne dans TclOO, et n'utilise pas Tcl_Preserve. Il n'est pas sûr de placer une poignée Tcl_Object dans une structure C dont la durée de vie est différente de celle de l'objet ; vous devriez plutôt utiliser le nom de la commande de l'objet (tel qu'obtenu avec Tcl_GetObjectName). Il est sûr d'utiliser une poignée Tcl_Object pendant la durée de vie d'un appel de méthode sur cet objet ; les poignées ne deviennent pas invalides tant qu'il y a un appel en cours sur leur objet (même si la seule opération garantie d'être sûre sur elles est Tcl_ObjectDeleted ; les autres opérations ne sont garanties de fonctionner que sur les objets non supprimés).

MÉTADONNÉES OBJET ET CLASSE

Chaque objet et chaque classe peuvent avoir des quantités arbitraires de métadonnées attachées, auxquelles l'objet ou la classe n'attribue aucune signification au-delà de ce qui est décrit dans une instance de structure Tcl_ObjectMetadataType. Les métadonnées à attacher sont décrites par le type des métadonnées (donné dans l'argument metaTypePtr) et un pointeur arbitraire (l'argument metadata) qui sont donnés à Tcl_ObjectSetMetadata et Tcl_ClassSetMetadata, et un élément de métadonnées particulier peut être récupéré en donnant son type avec Tcl_ObjectGetMetadata et Tcl_ClassGetMetadata. Si le paramètre metadata de Tcl_ObjectSetMetadata ou Tcl_ClassSetMetadata est NULL, les métadonnées sont supprimées si elles étaient attachées, et les résultats de Tcl_ObjectGetMetadata et Tcl_ClassGetMetadata sont NULL si le type de métadonnées donné n'était pas attaché. Il n'y a pas d'erreur à demander ou supprimer un élément de métadonnées qui n'était pas attaché.

STRUCTURE TCL_OBJECTMETADATATYPE

Le contenu de la structure Tcl_ObjectMetadataType est le suivant :

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

Le champ version permet une expansion future de la structure, et doit toujours être déclaré égal à TCL_OO_METADATA_VERSION_CURRENT. Le champ name fournit un nom lisible par l'homme pour le type, et est réservé au débogage.

Le champ deleteProc donne une fonction de type Tcl_ObjectMetadataDeleteProc qui est utilisée pour supprimer un élément de métadonnées particulier, et est appelée lorsque les métadonnées attachées sont remplacées ou supprimées ; le champ ne doit pas être NULL.

Le champ cloneProc donne une fonction qui est utilisée pour copier un élément de métadonnées (utilisé lorsqu'une copie d'un objet est créée en utilisant Tcl_CopyObjectInstance) ; s'il est NULL, les métadonnées seront simplement copiées directement.

Tcl_ObjectSetMetadata(3) TclOO Commands Tcl_ObjectSetMetadata(3) NAME Tcl_ObjectSetMetadata, Tcl_ObjectGetMetadata, Tcl_ObjectDeleteMetadata, Tcl_CloneProc, Tcl_ObjectMapMethodNameProc - manipulate object metadata SYNOPSIS #include int Tcl_ObjectSetMetadata(Tcl_Interp *interp, Tcl_Object object, const char *key, Tcl_Obj *value); Tcl_Obj * Tcl_ObjectGetMetadata(Tcl_Interp *interp, Tcl_Object object, const char *key); int Tcl_ObjectDeleteMetadata(Tcl_Interp *interp, Tcl_Object object, const char *key); typedef int Tcl_CloneProc(Tcl_Interp *interp, ClientData srcMetadata, ClientData *dstMetadataPtr); typedef int Tcl_ObjectMapMethodNameProc(Tcl_Interp *interp, Tcl_Object object, Tcl_Class *startClsPtr, Tcl_Obj *methodNameObj); ARGUMENTS Tcl_Interp *interp (in) Interpreter to use for error reporting. Tcl_Object object (in) The object whose metadata is to be manipulated. const char *key (in) The name of the metadata key. Tcl_Obj *value (in) The value of the metadata to associate with the key. ClientData metadata (in) The metadata to be deleted. ClientData srcMetadata (in) The metadata to be cloned. ClientData *dstMetadataPtr (out) Pointer to the location where the cloned metadata should be stored. Tcl_Class *startClsPtr (in/out) The class from which to start searching for a method definition. Tcl_Obj *methodNameObj (in) The name of the method being invoked. DESCRIPTION TclOO provides a mechanism for associating arbitrary data with TclOO objects and classes. This data is referred to as "metadata". It is organized as a collection of key/value pairs. The keys are strings, and the values are Tcl objects. The functions described here allow the manipulation of object metadata. Class metadata can be manipulated similarly via the Tcl commands oo::class metadata and oo::class metadata delete. Tcl_ObjectSetMetadata associates the given object value with the given object key for the specified object. If a value is already associated with the key, it is overwritten. Tcl_ObjectGetMetadata returns the value associated with the given key for the specified object. If no value is associated with the key, NULL is returned. The returned Tcl object is not duplicated; the caller must not modify it unless it is explicitly duplicated first. Tcl_ObjectDeleteMetadata removes the association between the given key and the specified object. If no association exists, the call is ignored. OBJECT AND CLASS METADATA The metadata mechanism is extensible via the TclOO core. When an object is created or duplicated, its metadata may be copied. The mechanism for this is via the Tcl_CloneProc callback. It is invoked when an object is duplicated, or when a class is duplicated. The metadata pointer passed to the callback is the same as would be passed to the other metadata manipulation functions. A NULL value for the pointer indicates that no metadata is present for the object/class in question. If the metadata needs to be duplicated, a new value should be allocated and stored via the dstMetadataPtr. If the metadata does not need to be duplicated, the dstMetadataPtr should be set to NULL. Otherwise, the callback should return TCL_OK. If the operation fails, an error message should be written to the interpreter and TCL_ERROR should be returned. Tcl_ObjectDeleteMetadata gives the address of the metadata to be deleted. TCL_CLONEPROC FUNCTION SIGNATURE Functions matching this signature are used to create copies of metadata associated with a class or object. typedef int Tcl_CloneProc( Tcl_Interp *interp, ClientData srcMetadata, ClientData *dstMetadataPtr); The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The srcMetadata argument gives the address of the metadata to be cloned, and the cloned metadata should be written into the variable pointed to by dstMetadataPtr; a NULL should be written if the metadata is to not be cloned but the overall object copy operation is still to succeed. OBJECT METHOD NAME MAPPING It is possible to control, on a per-object basis, what methods are invoked when a particular method is invoked. Normally this is done by looking up the method name in the object and then in the class hierarchy, but fine control of exactly what the value used to perform the look up is afforded through the ability to set a method name mapper callback via Tcl_ObjectSetMethodNameMapper (and its introspection counterpart, Tcl_ObjectGetMethodNameMapper, which returns the current mapper). The current mapper (if any) is invoked immediately before looking up what chain of method implementations is to be used. TCL_OBJECTMAPMETHODNAMEPROC FUNCTION SIGNATURE The Tcl_ObjectMapMethodNameProc callback is defined as follows: typedef int Tcl_ObjectMapMethodNameProc( Tcl_Interp *interp, Tcl_Object object, Tcl_Class *startClsPtr, Tcl_Obj *methodNameObj); If the result is TCL_OK, the remapping is assumed to have been done. If the result is TCL_ERROR, an error message will have been left in interp and the method call will fail. If the result is TCL_BREAK, the standard method name lookup rules will be used; the behavior of other result codes is currently undefined. The object parameter says which object is being processed. The startClsPtr parameter points to a variable that contains the first class to provide a definition in the method chain to process, or NULL if the whole chain is to be processed (the argument itself is never NULL); this variable may be updated by the callback. The methodNameObj parameter gives an unshared object containing the name of the method being invoked, as provided by the user; this object may be updated by the callback.
