ARGUMENTS

const Tcl_ChannelType *typePtr (in)
Indique l'adresse d'une structure contenant les pointeurs vers les fonctions qui peuvent être appelées pour effectuer des opérations d'E/S et d'autres fonctionnalités sur le canal.
const char *channelName (in)
Le nom de ce canal, par exemple, file3 ; il ne doit pas être utilisé par aucun autre canal. Peut être NULL, dans ce cas le canal est créé sans nom. Si le canal créé est assigné à l'un des canaux standards (stdin, stdout ou stderr), le nom assigné au canal sera le nom du canal standard.
ClientData instanceData (in)
Valeur arbitraire d'un octet unique associée à ce canal. Cette valeur est passée aux fonctions dans typePtr lorsqu'elles sont invoquées.
int mask (in)
Une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est lisible et écriturable.
Tcl_Channel channel (in)
Le canal sur lequel opérer.
int direction (in)
TCL_READABLE signifie que le handle d'entrée est désiré ; TCL_WRITABLE signifie que le handle de sortie est désiré.
ClientData *handlePtr (out)
Indique l'emplacement où le handle souhaité du système d'exploitation doit être stocké.
int size (in)
La taille, en octets, des tampons à allouer sur ce canal.
int mask (in)
Une combinaison OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION indiquant les événements qui se sont produits sur ce canal.
Tcl_Interp *interp (in)
Interpréteur actuel. (Peut être NULL)
const char *optionName (in)
Nom de l'option invalide.
const char *optionList (in)
Liste d'options spécifiques (mots séparés par des espaces, sans le symbole -) qui sont ajoutés à la liste d'options génériques. Peut être NULL uniquement pour les messages d'erreur d'options génériques.

DESCRIPTION

Tcl utilise une architecture de canaux à deux couches. Elle offre un niveau supérieur générique pour permettre aux programmes C et Tcl d'effectuer des entrées et sorties en utilisant les mêmes API pour divers fichiers, périphériques, sockets, etc. Les API C génériques sont décrites dans la page de manuel Tcl_OpenFileChannel.

La couche inférieure fournit des pilotes de canaux spécifiques à chaque type de périphérique supporté sur chaque plateforme. Ce manuel décrit les API C qui communiquent entre la couche générique et les pilotes de canaux spécifiques. Il explique également comment de nouveaux types de canaux peuvent être ajoutés en fournissant de nouveaux pilotes de canaux.

Les pilotes de canaux se composent de plusieurs composants : Premièrement, chaque pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers les fonctions qui implémentent les différentes opérations utilisées par la couche générique pour communiquer avec le pilote de canal. La structure Tcl_ChannelType et les fonctions référencées par elle sont décrites dans la section TCL_CHANNELTYPE, ci-dessous.

Deuxièmement, les pilotes de canaux fournissent généralement une commande Tcl pour créer des instances de ce type de canal. Par exemple, la commande Tcl open crée des canaux qui utilisent les pilotes de canaux de fichiers et de commandes, et la commande Tcl socket crée des canaux qui utilisent des protocoles réseau TCP.

Troisièmement, un pilote de canal fournit facultativement une fonction C pour ouvrir des instances de ce type de canal. Par exemple, Tcl_OpenFileChannel ouvre un canal qui utilise le pilote de canal de fichiers, et Tcl_OpenTcpClient ouvre un canal qui utilise le protocole réseau TCP. Ces fonctions de création utilisent généralement Tcl_CreateChannel en interne pour ouvrir le canal.

Pour ajouter un nouveau type de canal, vous devez implémenter une API C ou une commande Tcl qui ouvre un canal en invoquant Tcl_CreateChannel. Lorsque votre pilote appelle Tcl_CreateChannel, il passe une structure Tcl_ChannelType qui décrit les procédures d'E/S de votre pilote. La couche générique invoque ensuite les fonctions référencées dans cette structure pour effectuer des opérations sur le canal.

Tcl_CreateChannel ouvre un nouveau canal et associe typePtr et instanceData à celui-ci. Le canal est ouvert dans le mode indiqué par mask. Pour une discussion sur les pilotes de canaux, leurs opérations et la structure Tcl_ChannelType, voir la section TCL_CHANNELTYPE, ci-dessous.

Tcl_CreateChannel interagit avec le code qui gère les canaux standards. Une fois qu'un canal standard a été initialisé par un appel à Tcl_GetStdChannel ou un appel à Tcl_SetStdChannel, la fermeture de ce canal provoquera la prochaine invocation de Tcl_CreateChannel pour créer un nouveau canal comme canal standard également. Consultez Tcl_StandardChannels pour une discussion générale sur les canaux standards et le comportement de la bibliothèque Tcl à leur égard.

Tcl_GetChannelInstanceData renvoie les données d'instance associées au canal dans channel. Ceci est identique à l'argument instanceData dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelType renvoie un pointeur vers la structure Tcl_ChannelType utilisée par le canal dans l'argument channel. Ceci est identique à l'argument typePtr dans l'appel à Tcl_CreateChannel qui a créé ce canal.

Tcl_GetChannelName renvoie une chaîne avec le nom associé au canal, ou NULL si l'argument channelName de Tcl_CreateChannel était NULL.

Tcl_GetChannelHandle place le handle du périphérique opérationnel associé à channel pour la direction donnée dans handlePtr.

FONCTIONS DE CANAL

Les fonctions suivantes sont disponibles pour la gestion des canaux.

Tcl_GetChannel renvoie un identifiant interne pour le canal spécifié par canalName. Si un canal portant ce nom n'est pas enregistré, elle renvoie NULL.

Tcl_GetChannelName renvoie le nom du canal spécifié par canal. Le nom est retourné sous forme de chaîne de caractères C.

Tcl_GetChannelInstanceData renvoie les données d'instance pour le canal spécifié par canal. Ces données sont celles qui ont été fournies lors de la création du canal.

Tcl_GetChannelType renvoie un pointeur vers la structure Tcl_ChannelType associée au canal spécifié par canal. Cela permet aux pilotes de canaux d'accéder à leurs propres fonctions de traitement.

Tcl_GetChannelHandle renvoie le descripteur de périphérique sous-jacent pour le canal spécifié par canal et pour la direction spécifiée par direction. La valeur renvoyée est stockée dans l'emplacement spécifié par handlePtr et la fonction renvoie TCL_OK. Si le canal n'a pas de descripteur de périphérique pour la direction spécifiée, alors TCL_ERROR est renvoyé à la place. Différents pilotes de canaux renverront différents types de descripteurs. Référez-vous aux entrées de manuel de chaque pilote pour déterminer le type de descripteur renvoyé.

Tcl_GetChannelThread renvoie l'identifiant du thread gérant actuellement le canal spécifié. Cela permet aux pilotes de canaux d'envoyer leurs événements de fichier à la bonne file d'attente d'événements, même pour un noyau multi-thread.

Tcl_GetChannelMode renvoie une combinaison OR de TCL_READABLE et TCL_WRITABLE, indiquant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelBufferSize renvoie la taille, en octets, des tampons alloués pour stocker l'entrée ou la sortie dans canal. Si la valeur n'a pas été définie par un appel précédent à Tcl_SetChannelBufferSize, décrit ci-dessous, alors la valeur par défaut de 4096 est renvoyée.

Tcl_SetChannelBufferSize définit la taille, en octets, des tampons qui seront alloués lors des opérations ultérieures sur le canal pour stocker l'entrée ou la sortie. L'argument size doit être compris entre un et un million, permettant des tampons d'un octet à un million d'octets. Si size est en dehors de cette plage, Tcl_SetChannelBufferSize définit la taille du tampon à 4096.

Tcl_NotifyChannel est appelé par un pilote de canal pour indiquer à la couche générique que les événements spécifiés par mask se sont produits sur le canal. Les pilotes de canaux sont responsables de l'invocation de cette fonction chaque fois que les gestionnaires de canaux doivent être appelés pour le canal (ou d'autres tâches en attente comme la vidange d'une écriture doivent être effectuées). Voir WATCHPROC ci-dessous pour plus de détails.

Tcl_BadChannelOption est appelé à partir de setOptionProc ou getOptionProc spécifiques au pilote pour générer un message d'erreur complet.

Tcl_ChannelBuffered renvoie le nombre d'octets d'entrée actuellement mis en mémoire tampon dans le tampon interne (zone de rappel) du canal lui-même. Il ne rend pas compte des données dans les tampons globaux de la pile de canaux dont fait partie le canal fourni.

Tcl_IsChannelShared vérifie le compteur de références du canal spécifié et renvoie si le canal a été partagé entre plusieurs interpréteurs (résultat == 1) ou non (résultat == 0).

Tcl_IsChannelRegistered vérifie si le canal spécifié est enregistré dans l'interprète interp donné (résultat == 1) ou non (résultat == 0).

Tcl_IsChannelExisting vérifie si un canal portant le nom spécifié est enregistré dans la liste globale (de fil de discussion) de tous les canaux (résultat == 1) ou non (résultat == 0).

Tcl_CutChannel supprime le canal spécifié de la liste globale (de fil de discussion) de tous les canaux (du thread courant). L'application à un canal toujours enregistré dans un interpréteur n'est pas autorisée. Notifie également le pilote si la version de Tcl_ChannelType est TCL_CHANNEL_VERSION_4 (ou supérieure) et si Tcl_DriverThreadActionProc est définie pour celui-ci.

Tcl_SpliceChannel ajoute le canal spécifié à la liste globale (de fil de discussion) de tous les canaux (du thread courant). L'application à un canal enregistré dans un interpréteur n'est pas autorisée. Notifie également le pilote si la version de Tcl_ChannelType est TCL_CHANNEL_VERSION_4 (ou supérieure) et si Tcl_DriverThreadActionProc est définie pour celui-ci.

Tcl_ClearChannelHandlers supprime tous les gestionnaires de canaux et scripts d'événements associés au canal spécifié, interrompant ainsi tout traitement d'événements pour ce canal.

TCL_CHANNELTYPE

Un pilote de canal fournit une structure Tcl_ChannelType qui contient des pointeurs vers des fonctions qui implémentent les diverses opérations sur un canal ; ces opérations sont appelées selon les besoins par la couche générique. La structure a été versionnée à partir de Tcl 8.3.2/8.4 pour corriger un problème avec les canaux empilés. Voir la section OLD CHANNEL TYPES ci-dessous pour plus de détails sur l'ancienne structure.

La structure Tcl_ChannelType contient les champs suivants :

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Il n'est pas nécessaire de fournir des implémentations pour toutes les opérations de canal. Celles qui ne sont pas nécessaires peuvent être définies sur NULL dans la structure : blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc et close2Proc, en plus de flushProc, handlerProc, threadActionProc et truncateProc. Les autres fonctions qui ne peuvent pas être implémentées de manière significative doivent renvoyer EINVAL lorsqu'elles sont appelées, pour indiquer que les opérations qu'elles représentent ne sont pas disponibles. Notez également que wideSeekProc peut être NULL si seekProc l'est.

L'utilisateur ne doit utiliser que la structure ci-dessus pour l'instanciation de Tcl_ChannelType. Lors de la référence des champs dans une structure Tcl_ChannelType, les fonctions suivantes doivent être utilisées pour obtenir les valeurs : Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc, ou Tcl_ChannelHandlerProc.

La modification apportée aux structures a été effectuée de telle sorte que les types de canaux standard sont binaires compatibles. Cependant, les types de canaux qui utilisent des canaux empilés (c'est-à-dire TLS, Trf) ont de nouvelles versions pour correspondre au changement ci-dessus, car le code précédent pour les canaux empilés avait des problèmes.

TYPENAME

Le champ typeName contient une chaîne terminée par un caractère nul qui identifie le type de périphérique implémenté par ce pilote, par exemple file ou socket.

Cette valeur peut être récupérée avec Tcl_ChannelName, qui renvoie un pointeur vers la chaîne.

VERSION

Le champ version doit être défini sur la version de la structure dont vous avez besoin. TCL_CHANNEL_VERSION_2 est le minimum recommandé. TCL_CHANNEL_VERSION_3 doit être défini pour spécifier le membre wideSeekProc. TCL_CHANNEL_VERSION_4 doit être défini pour spécifier le membre threadActionProc (inclut wideSeekProc). TCL_CHANNEL_VERSION_5 doit être défini pour spécifier les membres truncateProc (inclut wideSeekProc et threadActionProc). S'il n'est défini sur aucune de ces valeurs, alors ce Tcl_ChannelType est supposé avoir la structure d'origine. Voir OLD CHANNEL TYPES pour plus de détails. Bien que Tcl reconnaisse et fonctionne avec les deux structures, les canaux empilés doivent être au moins de la version TCL_CHANNEL_VERSION_2 pour fonctionner correctement.

Cette valeur peut être récupérée avec Tcl_ChannelVersion, qui renvoie l'une des valeurs TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 ou TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

Le champ blockModeProc contient l'adresse d'une fonction appelée par la couche générique pour définir le mode bloquant et non bloquant sur le périphérique. BlockModeProc doit correspondre au prototype suivant :

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

Le instanceData est le même que la valeur passée à Tcl_CreateChannel lors de la création de ce canal. L'argument mode est soit TCL_MODE_BLOCKING, soit TCL_MODE_NONBLOCKING pour définir le périphérique en mode bloquant ou non bloquant. La fonction doit renvoyer zéro si l'opération a réussi, ou un code d'erreur POSIX non nul si l'opération a échoué.

Si l'opération réussit, la fonction peut modifier le instanceData fourni pour enregistrer que le canal est entré en mode bloquant ou non bloquant et pour implémenter le comportement bloquant ou non bloquant. Pour certains types de périphériques, le comportement bloquant et non bloquant peut être implémenté par le système d'exploitation sous-jacent ; pour d'autres types de périphériques, le comportement doit être émulé dans le pilote de canal.

Cette valeur peut être récupérée avec Tcl_ChannelBlockModeProc, qui renvoie un pointeur vers la fonction.

Un pilote de canal qui ne fournit pas de blockModeProc doit être très, très prudent. Il doit indiquer à la couche générique quel mode de blocage lui convient, et cela doit également être documenté pour l'utilisateur afin que le mode de blocage du canal ne soit pas modifié à une valeur inacceptable. Toute confusion ici peut entraîner l'interpréteur dans une impasse (sans objet et difficile à trouver).

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,

La fonction doit libérer toute mémoire conservée par le pilote de canal pour ce canal, et fermer les périphériques d'entrée et de sortie encapsulés par ce canal. Toute sortie mise en file d'attente aura été vidée vers le périphérique avant que cette fonction ne soit appelée, et aucune autre opération de pilote ne sera invoquée sur cette instance après l'appel de closeProc. INPUTPROC

Le champ inputProc contient l'adresse d'une fonction appelée par la couche générale pour lire des données à partir d'un périphérique ou d'un fichier et les stocker dans un tampon interne. InputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création du canal. L'argument buf pointe vers un tableau d'octets dans lequel les données d'entrée du périphérique seront stockées, et l'argument bufSize indique combien d'octets sont disponibles dans buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générale. Si une erreur se produit, la fonction doit définir cette valeur sur un code POSIX identifiant l'erreur.

La fonction doit lire les données du périphérique encapsulé par le canal et les stocker dans buf. En cas de succès, la fonction doit retourner un nombre non négatif indiquant le nombre d'octets lus à partir du périphérique et stockés dans buf. En cas d'erreur, la fonction doit retourner -1. Si une erreur se produit après la lecture de certaines données du périphérique, ces données sont perdues.

Si inputProc peut déterminer que des données sont disponibles sur le périphérique mais moins que ce qui est demandé par l'argument bufSize, la fonction doit essayer de lire uniquement la quantité de données disponible et retourner sans bloquer. Si le périphérique n'a pas de données disponibles et que le canal est en mode non bloquant, la fonction doit retourner une erreur EAGAIN. Si le périphérique n'a pas de données disponibles et que le canal est en mode bloquant, la fonction doit bloquer pendant la plus courte durée possible jusqu'à ce qu'au moins un octet soit lu à partir du périphérique, puis retourner le nombre maximum de données qui peuvent être lues sans bloquer.

Cette valeur peut être obtenue à l'aide de Tcl_ChannelInputProc, qui renvoie un pointeur vers la fonction.

OUTPUTPROC

Le champ outputProc contient l'adresse d'une fonction appelée par la couche générale pour transférer des données d'un tampon interne vers le périphérique de sortie. OutputProc doit correspondre au prototype suivant :

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création du canal. L'argument buf contient un tableau d'octets qui sera écrit sur le périphérique, et l'argument toWrite indique combien d'octets seront écrits à partir de l'argument buf.

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générale pour retourner les valeurs de errno de la fonction. Si une erreur se produit, la fonction doit définir cette valeur sur un code POSIX identifiant l'erreur.

La fonction doit écrire les données dans buf sur le périphérique de sortie encapsulé par le canal. En cas de succès, la fonction doit retourner un nombre non négatif indiquant le nombre d'octets écrits sur le périphérique de sortie. La valeur de retour est normalement la même que toWrite, mais peut être inférieure dans certains cas, comme lorsque l'opération de sortie est interrompue par un signal. Si une erreur se produit, la fonction doit retourner -1. En cas d'erreur, certaines données peuvent avoir été écrites sur le périphérique.

Si le canal est en mode non bloquant et que le périphérique de sortie ne peut pas absorber toutes les données, la fonction doit retourner -1 avec une erreur EAGAIN sans écrire aucune donnée.

Cette valeur peut être obtenue à l'aide de Tcl_ChannelOutputProc, qui renvoie un pointeur vers la fonction.

SEEKPROC ET WIDESEEKPROC

Le champ seekProc contient l'adresse d'une fonction appelée par la couche générale pour déplacer le point d'accès auquel les opérations d'entrée ou de sortie ultérieures s'appliqueront. SeekProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

L'argument instanceData est la même valeur que celle reçue lors de la création du canal avec Tcl_CreateChannel. Offset et seekMode ont la même signification que dans la procédure Tcl_Seek (mentionnée dans le manuel de Tcl_OpenFileChannel).

L'argument errorCodePtr pointe vers une variable entière fournie par la couche générale pour retourner les valeurs de errno de la fonction. Si une erreur se produit, la fonction doit définir cette valeur sur un code POSIX identifiant l'erreur. La fonction doit définir le code EINVAL si le type de canal n'implémente pas le déplacement.

La valeur de retour est le nouveau point d'accès ou -1 en cas d'erreur. Si une erreur se produit, la fonction ne doit pas déplacer le point d'accès.

S'il existe un champ seekProc non nul, le champ wideSeekProc peut contenir l'adresse d'une fonction alternative gérant les déplacements de grande taille (c'est-à-dire supérieurs à 32 bits), permettant ainsi les déplacements dans des fichiers de plus de 2 Go. La fonction wideSeekProc sera appelée de préférence à seekProc, mais les deux doivent être définis si wideSeekProc est défini. WideSeekProc doit correspondre au prototype suivant :

typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

Les arguments et les valeurs de retour sont les mêmes qu'avec seekProc, à l'exception du type de déplacement et du type de retour qui sont différents.

La valeur de seekProc peut être obtenue à l'aide de Tcl_ChannelSeekProc, qui renvoie un pointeur vers la fonction, et de manière similaire, la valeur de wideSeekProc peut être obtenue à l'aide de Tcl_ChannelWideSeekProc.

SETOPTIONPROC

Le champ setOptionProc contient l'adresse d'une fonction appelée par la couche générale pour définir une option spécifique au type de canal sur un canal. setOptionProc doit correspondre au prototype suivant :

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

optionName est le nom d'une option à définir, et newValue est la nouvelle valeur de cette option, sous forme de chaîne. InstanceData est la même valeur que celle reçue lors de la création du canal avec Tcl_CreateChannel. La fonction doit effectuer l'action spécifique au type de canal pour implémenter la nouvelle valeur de l'option.

Certaines options sont gérées par le code général et cette fonction n'est jamais appelée pour les définir, par exemple -blockmode. D'autres options sont spécifiques à chaque type de canal et la fonction setOptionProc du pilote du canal est appelée pour les implémenter. Le champ setOptionProc peut être nul, indiquant que ce type de canal ne prend pas en charge d'options spécifiques.

Si la valeur de l'option est correctement modifiée à sa nouvelle valeur, la fonction retourne TCL_OK. Elle doit appeler Tcl_BadChannelOption, qui retourne TCL_ERROR si optionName n'est pas reconnu. Si newValue spécifie une valeur non prise en charge ou si une erreur se produit lors d'un appel système, la fonction doit laisser un message d'erreur dans le résultat de interp si interp n'est pas nul. La fonction doit également appeler Tcl_SetErrno pour stocker un code POSIX approprié.

Cette valeur peut être obtenue à l'aide de Tcl_ChannelSetOptionProc, qui renvoie un pointeur vers la fonction.

GETOPTIONPROC

Le champ getOptionProc contient l'adresse d'une fonction appelée par la couche générale pour obtenir la valeur d'une option spécifique au type de canal sur un canal. getOptionProc doit correspondre au prototype suivant :

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        Tcl_DString *optionValue);

OptionName est le nom d'une option prise en charge par ce type de canal. Si le nom de l'option n'est pas NULL, la fonction stocke sa valeur actuelle, sous forme de chaîne, dans la chaîne Tcl dynamique optionValue. Si optionName est NULL, la fonction stocke dans optionValue une liste alternative de toutes les options prises en charge et de leurs valeurs actuelles. En cas de succès, la fonction retourne TCL_OK. Elle doit appeler Tcl_BadChannelOption, qui retourne TCL_ERROR si optionName n'est pas reconnu. Si newValue spécifie une valeur non prise en charge ou si une erreur se produit lors d'un appel système, la fonction doit laisser un message d'erreur dans le résultat de interp si interp n'est pas nul. La fonction doit également appeler Tcl_SetErrno pour stocker un code POSIX approprié.

Cette valeur peut être obtenue à l'aide de Tcl_ChannelGetOptionProc, qui renvoie un pointeur vers la fonction.

Certaines options sont gérées par le code générique et cette fonction n'est jamais appelée pour récupérer leur valeur, par exemple -blockmode. Cette valeur peut être récupérée avec Tcl_ChannelGetOptionProc, qui renvoie un pointeur vers la fonction.

WATCHPROC

Le champ watchProc contient l'adresse d'une fonction appelée par la couche générique pour initialiser le mécanisme de notification d'événements afin de détecter les événements d'intérêt sur ce canal. WatchProc doit correspondre au prototype suivant :

typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. L'argument mask est une combinaison OR de TCL_READABLE, TCL_WRITABLE et TCL_EXCEPTION ; il indique les événements que l'appelant souhaite détecter sur ce canal.

La fonction doit initialiser les mécanismes spécifiques au type de périphérique pour détecter lorsqu'un événement d'intérêt est présent sur le canal. Lorsqu'un ou plusieurs des événements désignés se produisent sur le canal, le pilote de canal est responsable d'appeler Tcl_NotifyChannel pour informer le module de canal générique. Le pilote doit veiller à ne pas affamer d'autres pilotes de canal ou sources de rappels en appelant Tcl_NotifyChannel trop fréquemment. L'équité peut être assurée en utilisant la file d'attente d'événements de Tcl pour permettre à l'événement de canal d'être planifié en séquence avec d'autres événements. Voir la description de Tcl_QueueEvent pour plus de détails sur la façon de mettre en file d'attente un événement.

Cette valeur peut être récupérée avec Tcl_ChannelWatchProc, qui renvoie un pointeur vers la fonction.

GETHANDLEPROC

Le champ getHandleProc contient l'adresse d'une fonction appelée par la couche générique pour récupérer un descripteur spécifique au périphérique à partir du canal. GetHandleProc doit correspondre au prototype suivant :

typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. L'argument direction est soit TCL_READABLE pour récupérer le descripteur utilisé pour l'entrée, soit TCL_WRITABLE pour récupérer le descripteur utilisé pour la sortie.

Si l'implémentation du canal possède des descripteurs spécifiques au périphérique, la fonction doit récupérer le descripteur approprié associé au canal, conformément à l'argument direction. Le descripteur doit être stocké dans l'emplacement référencé par handlePtr, et TCL_OK doit être retourné. Si le canal n'est pas ouvert pour la direction spécifiée, ou si l'implémentation du canal n'utilise pas de descripteurs de périphérique, la fonction doit retourner TCL_ERROR.

Cette valeur peut être récupérée avec Tcl_ChannelGetHandleProc, qui renvoie un pointeur vers la fonction.

FLUSHPROC

Le champ flushProc est actuellement réservé pour une utilisation future. Il doit être défini à NULL. FlushProc doit correspondre au prototype suivant :

typedef int Tcl_DriverFlushProc(
        ClientData instanceData);

Cette valeur peut être récupérée avec Tcl_ChannelFlushProc, qui renvoie un pointeur vers la fonction.

HANDLERPROC

Le champ handlerProc contient l'adresse d'une fonction appelée par la couche générique pour notifier le canal qu'un événement s'est produit. Il doit être défini pour les pilotes de canal empilés qui souhaitent être notifiés des événements qui se produisent sur le canal sous-jacent (empilé). HandlerProc doit correspondre au prototype suivant :

typedef int Tcl_DriverHandlerProc(
        ClientData instanceData,
        int interestMask);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal. Le interestMask est une combinaison OR de TCL_READABLE ou TCL_WRITABLE ; il indique quel type d'événement s'est produit sur ce canal.

Cette valeur peut être récupérée avec Tcl_ChannelHandlerProc, qui renvoie un pointeur vers la fonction.

THREADACTIONPROC

Le champ threadActionProc contient l'adresse de la fonction appelée par la couche générique lorsqu'un canal est créé, fermé, ou va être déplacé vers un autre thread, c'est-à-dire chaque fois que l'état du pilote spécifique au thread pourrait avoir besoin d'être initialisé ou mis à jour. Il peut être NULL. L'action TCL_CHANNEL_THREAD_REMOVE est utilisée pour notifier le pilote qu'il doit mettre à jour ou supprimer toute donnée spécifique au thread qu'il pourrait maintenir pour le canal.

L'action TCL_CHANNEL_THREAD_INSERT est utilisée pour notifier le pilote qu'il doit mettre à jour ou initialiser toute donnée spécifique au thread qu'il pourrait maintenir en utilisant le thread appelant comme associé. Voir Tcl_CutChannel et Tcl_SpliceChannel pour plus de détails.

typedef void Tcl_DriverThreadActionProc(
        ClientData instanceData,
        int action);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal.

Ces valeurs peuvent être récupérées avec Tcl_ChannelThreadActionProc, qui renvoie un pointeur vers la fonction.

TRUNCATEPROC

Le champ truncateProc contient l'adresse de la fonction appelée par la couche générique lorsqu'un canal est tronqué à une certaine longueur. Il peut être NULL.

typedef int Tcl_DriverTruncateProc(
        ClientData instanceData,
        Tcl_WideInt length);

InstanceData est la même valeur que celle passée à Tcl_CreateChannel lors de la création de ce canal, et length est la nouvelle longueur du fichier sous-jacent, qui ne doit pas être négative. Le résultat doit être 0 en cas de succès ou un code errno (adapté à une utilisation avec Tcl_SetErrno) en cas d'échec.

Ces valeurs peuvent être récupérées avec Tcl_ChannelTruncateProc, qui renvoie un pointeur vers la fonction.

TCL_BADCHANNELOPTION

Cette procédure génère un message d'erreur “option invalide” dans un interpréteur (optionnel). Elle est utilisée par les pilotes de canal lorsqu'une option de définition/obtention invalide est demandée. Son but est de concaténer la liste des options génériques aux options spécifiques et de factoriser la chaîne de message d'erreur des options génériques.

Elle retourne toujours TCL_ERROR

Un message d'erreur est généré dans la valeur de résultat d'interp pour indiquer qu'une commande a été invoquée avec une option invalide. Le message a la forme

    mauvaise option "blah" : devrait être l'une des
    <...options génériques...>+<...options spécifiques...>
vous obtenez par exemple : 
    mauvaise option "-blah" : devrait être l'une des -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, ou -sockname
lorsqu'elle est appelée avec optionList égal à “peername sockname”

“blah” est l'argument optionName et “<options spécifiques>” est une liste d'options spécifiques séparées par des espaces. La fonction prend grand soin d'insérer des signes moins avant chaque option, des virgules après, et un “ou” avant la dernière option.

TYPES DE CANAUX ANCIENS

La structure Tcl_ChannelType originale (8.3.1 et versions inférieures) contient les champs suivants :

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
} Tcl_ChannelType;

Il est toujours possible de créer des canaux avec la structure ci-dessus. Le code de canal interne déterminera la version. Il est impératif d'utiliser la nouvelle structure Tcl_ChannelType si vous créez un pilote de canal empilé, en raison de problèmes avec l'implémentation précédente des canaux empilés (dans les versions 8.2.0 à 8.3.1).

Avant la version 8.4.0 (c'est-à-dire lors des dernières versions de 8.3 et au début du cycle de développement de 8.4), la structure Tcl_ChannelType contenait les champs suivants :

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_ChannelTypeVersion version;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

Lorsque la structure ci-dessus est enregistrée comme type de canal, le champ version doit toujours être TCL_CHANNEL_VERSION_2.
