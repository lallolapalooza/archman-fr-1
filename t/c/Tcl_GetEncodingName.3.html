Un tableau de caractères Windows TCHAR à convertir en UTF-8.
int srcLen (en entrée)
Longueur de src ou tsrc en octets. Si la longueur est négative, la longueur spécifique à l'encodage de la chaîne est utilisée.
Tcl_DString *dstPtr (en sortie)
Pointeur vers une Tcl_DString non initialisée ou libérée dans laquelle le résultat converti sera stocké.
int flags (en entrée)
Divers bits de drapeau combinés par OR. TCL_ENCODING_START signifie que le tampon source est le premier bloc d'un flux d'entrée (potentiellement multi-blocs), indiquant à la routine de conversion de réinitialiser à un état initial et d'effectuer toute initialisation nécessaire avant la conversion du premier octet. TCL_ENCODING_END signifie que le tampon source est le dernier bloc d'un flux d'entrée (potentiellement multi-blocs), indiquant à la routine de conversion d'effectuer toute finalisation nécessaire après la conversion du dernier octet, puis de réinitialiser à un état initial. TCL_ENCODING_STOPONERROR signifie que la routine de conversion doit retourner immédiatement à la lecture d'un caractère source qui n'existe pas dans l'encodage cible ; sinon, un caractère de remplacement par défaut sera automatiquement substitué.
Tcl_EncodingState *statePtr (en entrée/sortie)
Utilisé lors de la conversion d'un flux d'octets (généralement long ou de longueur indéfinie) morceau par morceau. La routine de conversion stocke son état actuel dans *statePtr après que src (le tampon contenant le morceau actuel) a été converti ; ces informations d'état doivent être renvoyées lors de la conversion du prochain morceau du flux afin que la routine de conversion sache dans quel état elle s'est arrêtée à la fin du dernier morceau. Peut être NULL, auquel cas la valeur spécifiée pour flags est ignorée et le tampon source est supposé contenir la chaîne complète à convertir.

Tampon dans lequel le résultat converti sera stocké. Pas plus de dstLen octets seront stockés dans dst.

La longueur maximale du tampon de sortie dst en octets.
int *srcReadPtr (en sortie)
Rempli avec le nombre d'octets de src qui ont été effectivement convertis. Cela peut être inférieur à la longueur source d'origine s'il y a eu un problème lors de la conversion de certains caractères source. Peut être NULL.

Rempli avec le nombre d'octets qui ont été effectivement stockés dans le tampon de sortie en résultat de la conversion. Peut être NULL.
int *dstCharsPtr (en sortie)

INTRODUCTION

Ces routines convertissent entre la représentation interne des caractères de Tcl, UTF-8, et les représentations de caractères utilisées par divers systèmes d'exploitation ou systèmes de fichiers, tels que Unicode, ASCII ou Shift-JIS. Lors du traitement de chaînes de caractères, comme pour obtenir les noms de fichiers ou afficher des caractères à l'aide de polices internationales, les chaînes doivent être traduites dans un ou plusieurs formats que les divers appels système peuvent utiliser. Par exemple, sur un poste de travail Unix japonais, un utilisateur pourrait obtenir un nom de fichier représenté dans l'encodage de fichier EUC-JP, puis traduire les caractères vers l'encodage de police jisx0208 afin d'afficher le nom de fichier dans un widget Tk. Le but du paquet d'encodage est d'aider à combler le fossé de traduction. UTF-8 fournit un terrain d'entente intermédiaire pour tous les différents encodages. Dans l'exemple ci-dessus, le texte serait traduit en UTF-8 à partir de l'encodage de fichier utilisé par le système d'exploitation. Ensuite, il serait traduit de UTF-8 vers l'encodage de police requis par les routines d'affichage.

Certains encodages de base sont intégrés à Tcl. D'autres peuvent être définis par l'utilisateur ou chargés dynamiquement à partir de fichiers d'encodage d'une manière indépendante de la plateforme.

DESCRIPTION

Tcl_GetEncoding recherche un encodage à partir de son name. Le nom peut faire référence à un encodage Tcl intégré, à un encodage défini par l'utilisateur enregistré en appelant Tcl_CreateEncoding, ou à un fichier d'encodage chargeable dynamiquement. La valeur de retour est un jeton qui représente l'encodage et peut être utilisé dans des appels ultérieurs à des procédures telles que Tcl_GetEncodingName, Tcl_FreeEncoding et Tcl_UtfToExternal. Si le nom ne faisait référence à aucun encodage connu ou chargeable, NULL est retourné et un message d'erreur est retourné dans interp.

Le paquet d'encodage maintient une base de données de tous les encodages actuellement en cours d'utilisation. La première fois que name est rencontré, Tcl_GetEncoding retourne un encodage avec un compteur de références de 1. Si le même name est demandé ultérieurement, le compteur de références pour cet encodage est incrémenté sans le surcoût de l'allocation d'un nouvel encodage et de toutes ses structures de données associées.

Lorsqu'un encoding n'est plus nécessaire, Tcl_FreeEncoding doit être appelé pour le libérer. Lorsqu'un encoding n'est plus utilisé (c'est-à-dire qu'il a été libéré autant de fois qu'il a été obtenu), Tcl_FreeEncoding libérera tout le stockage utilisé par l'encodage et le supprimera de la base de données.

Tcl_GetEncodingFromObj traite la représentation sous forme de chaîne de objPtr comme un nom d'encodage, et recherche un encodage avec ce nom, tout comme le fait Tcl_GetEncoding. Lorsqu'un encodage est trouvé, il est mis en cache dans la valeur objPtr pour une référence future, le jeton Tcl_Encoding est écrit dans le stockage pointé

transmis par encodingPtr, et la valeur TCL_OK est retournée. Si aucun encodage de ce type n'est trouvé, la valeur TCL_ERROR est retournée et aucune écriture dans *encodingPtr n'a lieu. Tout comme avec Tcl_GetEncoding, l'appelant doit appeler Tcl_FreeEncoding sur le jeton d'encodage résultant lorsque ce jeton ne sera plus utilisé.

Tcl_ExternalToUtfDString convertit un tampon source src de l'encodage spécifié encoding en UTF-8. Les octets convertis sont stockés dans dstPtr, qui est ensuite terminé par un caractère nul. L'appelant doit éventuellement appeler Tcl_DStringFree pour libérer toute information stockée dans dstPtr. Lors de la conversion, si l'un des caractères du tampon source ne peut pas être représenté dans l'encodage cible, un caractère de remplacement par défaut sera utilisé. La valeur de retour est un pointeur vers la valeur stockée dans le DString.

Tcl_ExternalToUtf convertit un tampon source src de l'encodage spécifié encoding en UTF-8. Jusqu'à srcLen octets sont convertis à partir du tampon source et jusqu'à dstLen octets convertis sont stockés dans dst. Dans tous les cas, *srcReadPtr est rempli avec le nombre d'octets qui ont été convertis avec succès à partir de src et *dstWrotePtr est rempli avec le nombre correspondant d'octets qui ont été stockés dans dst. La valeur de retour est l'une des suivantes :

TCL_OK
Tous les octets de src ont été convertis.
TCL_CONVERT_NOSPACE
Le tampon de destination n'était pas assez grand pour toutes les données converties ; cependant, autant de caractères que possible ont été convertis.
TCL_CONVERT_MULTIBYTE
Les derniers octets du tampon source étaient le début d'une séquence multibyte, mais des octets supplémentaires étaient nécessaires pour compléter cette séquence. Un appel ultérieur à la routine de conversion devrait passer un tampon contenant les octets non convertis qui restaient dans src plus quelques octets supplémentaires du flux source pour convertir correctement la séquence multibyte précédemment divisée.
TCL_CONVERT_SYNTAX
Le tampon source contenait une séquence de caractères invalide. Cela peut se produire si le flux d'entrée a été endommagé ou si la méthode d'encodage d'entrée a été mal identifiée.
TCL_CONVERT_UNKNOWN
Le tampon source contenait un caractère qui ne pouvait pas être représenté dans l'encodage cible et TCL_ENCODING_STOPONERROR a été spécifié.

Tcl_UtfToExternalDString convertit un tampon source src de l'UTF-8 vers l'encodage spécifié encoding. Les octets convertis sont stockés dans dstPtr, qui est ensuite terminé par le caractère nul approprié à l'encodage. L'appelant doit éventuellement appeler Tcl_DStringFree pour libérer toute information stockée dans dstPtr. Lors de la conversion, si l'un des caractères du tampon source ne peut pas être représenté dans l'encodage cible, un caractère de remplacement par défaut sera utilisé. La valeur de retour est un pointeur vers la valeur stockée dans le DString.

Tcl_UtfToExternal convertit un tampon source src de l'UTF-8 vers l'encodage spécifié encoding. Jusqu'à srcLen octets sont convertis à partir du tampon source et jusqu'à dstLen octets convertis sont stockés dans dst. Dans tous les cas, *srcReadPtr est rempli avec le nombre d'octets qui ont été convertis avec succès à partir de src et *dstWrotePtr est rempli avec le nombre correspondant d'octets qui ont été stockés dans dst. Les valeurs de retour sont les mêmes que les valeurs de retour pour Tcl_ExternalToUtf.

Tcl_WinUtfToTChar et Tcl_WinTCharToUtf sont des fonctions utilitaires propres à Windows pour convertir entre UTF-8 et les chaînes Windows basées sur le type TCHAR, qui est par convention un caractère Unicode sous Windows NT.

Tcl_GetEncodingName est approximativement l'inverse de Tcl_GetEncoding. Étant donné un encoding, la valeur de retour est l'argument name qui a été utilisé pour créer l'encodage. La chaîne retournée par Tcl_GetEncodingName n'est garantie de persister que jusqu'à ce que l'encoding soit supprimé. L'appelant ne doit pas modifier cette chaîne.

Tcl_SetSystemEncoding définit l'encodage par défaut qui doit être utilisé chaque fois que l'utilisateur passe une valeur NULL pour l'argument encoding à l'une des autres fonctions d'encodage. Si name est NULL, l'encodage système est réinitialisé à l'encodage système par défaut, binary. Si le nom ne fait référence à aucun encodage connu ou chargeable, TCL_ERROR est retourné et un message d'erreur est laissé dans interp. Sinon, cette procédure incrémente le compteur de références du nouvel encodage système, décrémente le compteur de références de l'ancien encodage système et retourne TCL_OK.

Tcl_GetEncodingNameFromEnvironment fournit un moyen pour la bibliothèque Tcl de signaler le nom d'encodage qu'elle considère comme correct à utiliser comme encodage système, en se basant sur des appels système et un examen de l'environnement approprié pour la plateforme. Elle accepte bufPtr, un pointeur vers un Tcl_DString non initialisé ou libéré, et y écrit le nom de l'encodage. Tcl_DStringValue est retourné.

Tcl_GetEncodingNames définit le résultat de l'interp sur une liste composée des noms de tous les encodages actuellement définis ou qui peuvent être chargés dynamiquement, en recherchant dans le chemin d'encodage spécifié par Tcl_SetDefaultEncodingDir. Cette procédure ne garantit pas que les fichiers d'encodage chargeables dynamiquement contiennent des données valides, mais simplement qu'ils existent.

Tcl_CreateEncoding définit un nouvel encodage et enregistre les procédures C qui sont appelées pour convertir entre l'encodage et l'UTF-8. Les encodages créés par Tcl_CreateEncoding sont ensuite visibles dans la base de données utilisée par Tcl_GetEncoding. Tout comme avec la procédure Tcl_GetEncoding, la valeur de retour est un jeton qui représente l'encodage et peut être utilisé dans des appels ultérieurs à d'autres fonctions d'encodage. Tcl_CreateEncoding retourne un encodage avec un compteur de références de 1. Si un encodage avec le nom spécifié name existe déjà, son entrée dans la base de données est remplacée par le nouvel encodage ; le jeton de l'ancien encodage restera valide et continuera de se comporter comme auparavant, mais les utilisateurs du nouveau jeton appelleront désormais les nouvelles procédures d'encodage.

L'argument typePtr à Tcl_CreateEncoding contient des informations sur le nom de l'encodage et les procédures qui seront appelées pour convertir entre cet encodage et l'UTF-8. Il est défini comme suit :

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

L'encodingName fournit un nom chaîne pour l'encodage, par lequel il peut être référencé dans d'autres procédures telles que Tcl_GetEncoding. Le toUtfProc fait référence à une procédure de rappel à invoquer pour convertir le texte de cet encodage en UTF-8. Le fromUtfProc fait référence à une procédure de rappel à invoquer pour convertir le texte de l'UTF-8 vers cet encodage. Le freeProc fait référence à une procédure de rappel à invoquer lorsque cet encodage est supprimé. Le champ freeProc peut être NULL. Le clientData contient une valeur arbitraire d'un mot passée aux procédures toUtfProc, fromUtfProc et freeProc chaque fois qu'elles sont appelées. Typiquement, il s'agit d'un pointeur vers une structure de données contenant des informations spécifiques à l'encodage qui peuvent être utilisées par les procédures de rappel. Par exemple, deux encodages très similaires tels que ascii et macRoman peuvent utiliser la même procédure de rappel, mais utiliser différentes valeurs de clientData pour contrôler son comportement. Le nullSize spécifie le nombre d'octets nuls qui signifient la fin de la chaîne dans cet encodage. Il doit être 1 (pour les encodages à octet unique ou multi-octets comme ASCII ou Shift-JIS) ou 2 (pour les encodages à double octet comme Unicode). Les encodages de taille constante avec 3 octets ou plus par caractère (comme CNS11643) ne sont pas acceptés.

Les procédures de rappel toUtfProc et fromUtfProc doivent correspondre au type Tcl_EncodingConvertProc :

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

Les procédures toUtfProc et fromUtfProc sont appelées par la famille de fonctions Tcl_ExternalToUtf ou Tcl_UtfToExternal pour effectuer la conversion réelle. Le paramètre clientData de ces procédures est le même que le champ clientData spécifié à Tcl_CreateEncoding lors de la création de l'encodage. Les arguments restants aux procédures de rappel sont les mêmes que les arguments, documentés en haut, à Tcl_ExternalToUtf ou Tcl_UtfToExternal, à l'exception des points suivants. Si l'argument srcLen de l'une de ces fonctions de haut niveau est négatif, la valeur passée à la procédure de rappel sera la longueur de chaîne appropriée spécifique à l'encodage de src. Si l'un des arguments srcReadPtr, dstWrotePtr, ou dstCharsPtr de l'une des fonctions de haut niveau est NULL, la valeur correspondante passée à la procédure de rappel sera un emplacement non NULL.

La procédure de rappel freeProc, si elle n'est pas NULL, doit correspondre au type Tcl_EncodingFreeProc :

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

Cette fonction freeProc est appelée lorsque l'encodage est supprimé. Le paramètre clientData est le même que le champ clientData spécifié à Tcl_CreateEncoding lors de la création de l'encodage.

Tcl_GetEncodingSearchPath et Tcl_SetEncodingSearchPath sont appelés pour accéder et définir la liste des répertoires du système de fichiers recherchés pour les fichiers de données d'encodage.

La valeur retournée par Tcl_GetEncodingSearchPath est la valeur stockée par le dernier appel réussi à Tcl_SetEncodingSearchPath. Si aucun appel à Tcl_SetEncodingSearchPath n'a eu lieu, Tcl calculera une valeur initiale basée sur l'environnement. Il existe un chemin de recherche d'encodage pour l'ensemble du processus, partagé par tous les threads du processus.

NOM

Tcl_GetEncodingName

SYNTHSE

Tcl_GetEncodingName(interp, name)

ARGUMENTS

interp requis Interpréteur Tcl name requis Chaîne

INTRODUCTION

Tcl_GetEncodingName est une commande Tcl qui récupère le nom de l'encodage utilisé par le script. Ce nom est généralement spécifié dans le fichier d'encodage, qui est un fichier texte contenant des informations sur l'encodage et ses séquences d'échappement associées.

DESCRIPTION

Tcl_GetEncodingName renvoie le nom du fichier d'encodage actuellement utilisé par le script. Le nom est déterminé par le fichier d'encodage utilisé, qui est spécifié par le paramètre name. Si aucun fichier d'encodage n'est spécifié, le fichier d'encodage par défaut est utilisé.

FICHIERS ENCODAGE

L'espace interdirait la pré-compilation de tous les algorithmes d'encodage possibles dans Tcl, donc de nombreux encodages sont stockés sur disque sous forme de fichiers d'encodage chargeables dynamiquement. Ce comportement permet également à l'utilisateur de créer des fichiers d'encodage supplémentaires qui peuvent être chargés en utilisant le même mécanisme. Ces fichiers d'encodage contiennent des informations sur les tables et/ou les séquences d'échappement utilisées pour mapper entre un encodage externe et Unicode. L'encodage externe peut se composer de caractères sur un seul octet, plusieurs octets ou deux octets.

Chaque encodage chargeable dynamiquement est représenté sous forme de fichier texte. La première ligne du fichier, commençant par un symbole “#”, est un commentaire qui fournit une description lisible par l'homme du fichier. La ligne suivante identifie le type de fichier d'encodage. Il peut s'agir de l'une des lettres suivantes :

[1] S
Un encodage sur un octet, où un caractère est toujours d'une longueur d'un octet dans l'encodage. Un exemple est iso8859-1, utilisé par de nombreuses langues européennes.
[2] D
Un encodage sur deux octets, où un caractère est toujours d'une longueur de deux octets dans l'encodage. Un exemple est big5, utilisé pour le texte chinois.
[3] M
Un encodage multi-octets, où un caractère peut être d'une longueur d'un ou deux octets. Certains octets sont des octets principaux, indiquant qu'un autre octet doit suivre et que les deux octets ensemble représentent un caractère. D'autres octets ne sont pas des octets principaux et se représentent eux-mêmes. Un exemple est shiftjis, utilisé par de nombreux ordinateurs japonais.
[4] E
Un encodage par séquence d'échappement, spécifiant que certaines séquences d'octets ne représentent pas des caractères, mais des commandes qui décrivent comment les octets suivants doivent être interprétés.

Le reste des lignes du fichier dépend du type.

Les cas [1], [2] et [3] sont collectivement appelés fichiers d'encodage basés sur des tables. Les lignes d'un fichier d'encodage basé sur des tables sont dans le même format que cet exemple tiré de l'encodage shiftjis (ce n'est pas le fichier complet) :

La troisième ligne du fichier contient trois nombres. Le premier nombre est le caractère de repli (en base 16) à utiliser lors de la conversion de UTF-8 vers cet encodage. Le deuxième nombre est 1 si ce fichier représente l'encodage d'une police de symboles, ou 0 sinon. Le dernier nombre (en base 10) indique le nombre de pages de données qui suivent.

Les lignes suivantes dans l'exemple ci-dessus sont des pages qui décrivent comment mapper de l'encodage vers Unicode sur 2 octets. La première ligne d'une page identifie le numéro de page. Elle est suivie de 256 nombres sur deux octets, organisés en 16 lignes de 16 nombres. Étant donné un caractère dans l'encodage, l'octet de poids fort de ce caractère est utilisé pour sélectionner la page, et l'octet de poids faible de ce caractère est utilisé comme index pour sélectionner l'un des nombres sur deux octets de cette page - la valeur obtenue étant le caractère Unicode correspondant. Par examen de l'exemple ci-dessus, on peut voir que les caractères 0x7E et 0x8163 en shiftjis correspondent respectivement à 203E et 2026 en Unicode.

Après la première page se trouvent toutes les autres pages, chacune dans le même format que la première : un nombre identifiant la page suivi de 256 caractères Unicode sur deux octets. Si un caractère de l'encodage correspond au caractère Unicode 0000, cela signifie que le caractère n'existe pas réellement. Si tous les caractères d'une page correspondent à 0000, cette page peut être omise.

Le cas [4] est le fichier d'encodage par séquence d'échappement. Les lignes de ce type de fichier sont dans le même format que cet exemple tiré de l'encodage iso2022-jp :

# Fichier d'encodage : iso2022-jp, piloté par échappement
E
init		{}
final		{}
iso8859-1	\x1b(B
jis0201		\x1b(J
jis0208		\x1b$@
jis0208		\x1b$B
jis0212		\x1b$(D
gb2312		\x1b$A
ksc5601		\x1b$(C

Dans le fichier, la première colonne représente une option et la deuxième colonne est la valeur associée. init est une chaîne à émettre ou à attendre avant la conversion du premier caractère, tandis que final est une chaîne à émettre ou à attendre après le dernier caractère. Toutes les autres options sont des noms d'encodages basés sur des tables ; la valeur associée est la séquence d'échappement qui marque cet encodage. La syntaxe Tcl est utilisée pour les valeurs ; dans l'exemple ci-dessus, par exemple, “{}” représente la chaîne vide et “\x1b” représente le caractère 27.

Lorsque Tcl_GetEncoding rencontre un nom d'encodage qui n'a pas été chargé, il tente de charger un fichier d'encodage appelé name.enc depuis le sous-répertoire encoding de chaque répertoire que Tcl recherche pour sa bibliothèque de scripts. Si le fichier d'encodage existe, mais est malformé, un message d'erreur sera laissé dans interp.
