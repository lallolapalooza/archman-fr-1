DESCRIPTION

Les routines Tcl_SetReturnOptions et Tcl_GetReturnOptions exposent les mêmes capacités que les commandes return et catch, respectivement, sous la forme d'une interface C.

Tcl_GetReturnOptions récupère le dictionnaire des options de retour d'un interpréteur après une évaluation de script. Des routines telles que Tcl_Eval sont appelées pour évaluer un script dans un interpréteur. Ces routines retournent un code de complétion entier. Ces routines laissent également dans l'interpréteur à la fois un résultat et un dictionnaire d'options de retour généré par l'évaluation du script. Tout comme Tcl_GetObjResult récupère le résultat, Tcl_GetReturnOptions récupère le dictionnaire des options de retour. Le code de complétion entier doit être passé comme argument code à Tcl_GetReturnOptions afin que toutes les options requises soient présentes dans le dictionnaire. Spécifiquement, une valeur code de TCL_ERROR garantira que les entrées pour les clés -errorinfo, -errorcode et -errorline apparaîtront dans le dictionnaire. De plus, les entrées pour les clés -code et -level seront ajustées si nécessaire pour correspondre à la valeur de code. Le (Tcl_Obj *) retourné par Tcl_GetReturnOptions pointe vers un Tcl_Obj non partagé avec un compteur de références de zéro. Le dictionnaire peut être écrit, soit en ajoutant, supprimant ou écrasant des entrées, sans avoir besoin de vérifier une valeur partagée. Comme pour tout Tcl_Obj avec un compteur de références de zéro, il incombe à l'appelant d'organiser son élimination avec Tcl_DecrRefCount ou de conserver une référence à celui-ci via Tcl_IncrRefCount (ou l'une des nombreuses fonctions qui appellent ceci, notamment Tcl_SetObjResult et Tcl_SetVar2Ex).

Une utilisation typique de Tcl_GetReturnOptions est de récupérer la trace de la pile lorsque l'évaluation du script retourne TCL_ERROR, comme suit :

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* Faire quelque chose avec stackTrace */
    Tcl_DecrRefCount(options);
}

Tcl_SetReturnOptions définit les options de retour de interp à options. Si options contient une valeur invalide pour une clé, TCL_ERROR sera retourné, et le résultat de l'interpréteur sera défini à un message d'erreur approprié. Sinon, un code de complétion en accord avec les clés -code et -level dans options sera retourné.

À titre d'exemple, la commande return de Tcl elle-même pourrait être implémentée en utilisant Tcl_SetReturnOptions comme suit :

if ((objc % 2) == 0) { /* argument de résultat explicite */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(Ce n'est pas vraiment implémenté de cette façon. Les privilèges d'accès internes permettent une alternative plus efficace qui s'intègre mieux avec le compilateur de bytecode.)

Notez qu'un Tcl_Obj nouvellement créé peut être passé comme argument options sans avoir besoin de gérer le comptage de références. Ceci est analogue à Tcl_SetObjResult.

Alors que Tcl_SetReturnOptions fournit une interface générale pour définir n'importe quelle collection d'options de retour, il existe une poignée d'options de retour qui sont très fréquemment utilisées. Notamment, les options -errorinfo et -errorcode doivent être correctement définies lorsque la procédure de commande d'une commande retourne TCL_ERROR. L'option -errorline est également lue par les commandes qui évaluent des scripts et souhaitent fournir des informations détaillées sur la localisation de l'erreur dans le texte de la trace de pile qu'elles ajoutent à l'option -errorinfo. Tcl fournit plusieurs interfaces plus simples pour définir plus directement ces options de retour.

L'option -errorinfo contient une trace de la pile des opérations en cours au moment où une erreur s'est produite, et est destinée à être lisible par l'homme. L'option -errorcode contient une liste Tcl d'éléments destinés à être lisibles par la machine. Le premier élément de la valeur -errorcode identifie la classe de l'erreur qui s'est produite (par exemple, POSIX signifie qu'une erreur s'est produite dans un appel système POSIX) et des éléments supplémentaires contiennent des informations supplémentaires qui dépendent de la classe. Voir la page de manuel sur la variable errorCode pour plus de détails sur les différents formats pour l'option -errorcode utilisés par les commandes intégrées de Tcl.

La valeur de l'option -errorinfo est progressivement construite au fur et à mesure qu'une erreur se dénoue à travers les opérations imbriquées. Chaque fois qu'un code d'erreur est retourné à Tcl_Eval, ou à l'une des routines qui effectuent l'évaluation de script, la procédure Tcl_AddErrorInfo est appelée pour ajouter du texte supplémentaire à la valeur -errorinfo décrivant la commande qui était en cours d'exécution lorsque l'erreur s'est produite. Au moment où l'erreur est entièrement renvoyée à l'application, elle contiendra une trace complète de l'activité en cours au moment où l'erreur s'est produite.

Il est parfois utile d'ajouter des informations supplémentaires à la valeur -errorinfo au-delà de ce qui peut être fourni automatiquement par les routines d'évaluation de script. Tcl_AddErrorInfo peut être utilisé à cet effet : son argument message est une chaîne supplémentaire à ajouter à l'option -errorinfo. Par exemple, lorsqu'une erreur survient pendant la commande source, la procédure Tcl_AddErrorInfo est appelée pour enregistrer le nom du fichier en cours de traitement et le numéro de ligne où l'erreur s'est produite. DESCRIPTION

Ces procédures fournissent des interfaces pour manipuler les informations d'erreur Tcl et les options de retour d'erreur.

Tcl_AddErrorInfo ajoute une chaîne de caractères message à la valeur de l'option de retour -errorinfo de l'interpréteur interp. Cela est généralement appelé juste après qu'une routine d'évaluation de script ait renvoyé TCL_ERROR. L'information d'erreur est stockée sous forme de pile de traces, et lorsque Tcl_AddErrorInfo est appelée, le nom de la procédure Tcl appelante, le nom de fichier et le numéro de ligne dans la procédure sont enregistrés. Le moment idéal pour appeler Tcl_AddErrorInfo est juste après qu'une routine d'évaluation de script ait retourné TCL_ERROR. La valeur de l'option de retour -errorline (récupérée via un appel à Tcl_GetReturnOptions) constitue souvent une partie utile du message passé à Tcl_AddErrorInfo.

Tcl_AppendObjToErrorInfo est une interface alternative à la même fonctionnalité que Tcl_AddErrorInfo. Tcl_AppendObjToErrorInfo est appelée lorsque la valeur de la chaîne à ajouter à l'option -errorinfo est disponible sous forme de Tcl_Obj au lieu d'un tableau de char.

Tcl_AddObjErrorInfo est presque identique à Tcl_AddErrorInfo, à l'exception qu'elle a un argument supplémentaire length. Cela permet à la chaîne message de contenir des octets nuls intégrés. Ce n'est pratiquement jamais une bonne idée. Si le message doit contenir le caractère nul U+0000, les règles d'encodage internes habituelles de Tcl devraient être utilisées pour éviter le besoin d'un octet nul. Si l'interface Tcl_AddObjErrorInfo est utilisée, ce devrait être avec une valeur length négative.

La procédure Tcl_SetObjErrorCode est utilisée pour définir l'option de retour -errorcode à la valeur de liste errorObjPtr construite par l'appelant. Tcl_SetObjErrorCode est généralement invoquée juste avant de renvoyer une erreur. Si une erreur est renvoyée sans appeler Tcl_SetObjErrorCode ou Tcl_SetErrorCode, l'interpréteur Tcl définit automatiquement l'option de retour -errorcode à NONE.

La procédure Tcl_SetErrorCode est également utilisée pour définir l'option de retour -errorcode. Cependant, elle prend une ou plusieurs chaînes de caractères à enregistrer au lieu d'une valeur. Sinon, elle est similaire à Tcl_SetObjErrorCode en termes de comportement.

Tcl_SetErrorCodeVA est identique à Tcl_SetErrorCode à l'exception qu'au lieu de prendre un nombre variable d'arguments, elle prend une liste d'arguments.

La procédure Tcl_GetErrorLine est utilisée pour lire la valeur entière de l'option de retour -errorline sans la surcharge d'un appel complet à Tcl_GetReturnOptions. De même, Tcl_SetErrorLine définit la valeur de l'option de retour -errorline.

Tcl_PosixError définit la variable -errorcode après une erreur dans un appel noyau POSIX. Elle lit la valeur de la variable C errno et appelle Tcl_SetErrorCode pour définir l'option de retour -errorcode au format POSIX. L'appelant doit avoir précédemment appelé Tcl_SetErrno pour définir errno ; ceci est nécessaire sur certaines plates-formes (par exemple, Windows) où Tcl est lié à une application en tant que bibliothèque partagée, ou lorsque l'erreur se produit dans une extension chargée dynamiquement. Voir l'entrée du manuel pour Tcl_SetErrno pour plus d'informations.

Tcl_PosixError renvoie un message de diagnostic lisible par l'homme pour l'erreur (c'est la même valeur qui apparaîtra comme troisième élément de la valeur -errorcode). Il peut être pratique d'inclure cette chaîne de caractères dans le message d'erreur renvoyé à l'application dans le résultat de l'interpréteur.

Tcl_LogCommandInfo est invoquée après une erreur dans un interpréteur. Elle ajoute des informations sur la commande qui était en cours d'exécution lorsque l'erreur s'est produite à la valeur -errorinfo, et le numéro de ligne stocké en interne dans l'interpréteur est défini.

Dans les anciennes versions de Tcl, il n'y avait pas de routine Tcl_GetReturnOptions. À sa place, les variables globales Tcl errorInfo et errorCode étaient le seul endroit pour récupérer les informations d'erreur. De nombreux codes existants écrits pour d'anciennes versions de Tcl accèdent encore à ces informations via ces variables globales.

Il est important de réaliser que, bien que la lecture de ces variables globales reste une méthode prise en charge pour accéder à ces valeurs d'option de retour, il est important de ne pas supposer que l'écriture dans ces variables globales définira correctement les options de retour correspondantes. Il a longtemps été souligné dans cette page de manuel qu'il est important d'appeler les procédures décrites ici plutôt que de définir directement errorInfo ou errorCode avec Tcl_ObjSetVar2.

Si la procédure Tcl_ResetResult est appelée, elle efface tout l'état de l'interpréteur associé à l'évaluation de script, y compris l'ensemble du dictionnaire d'options de retour. En particulier, les options -errorinfo et -errorcode sont réinitialisées. Si une erreur s'était produite, l'appel Tcl_ResetResult effacera l'état d'erreur pour qu'il apparaisse comme si aucune erreur ne s'était produite après tout. Les variables globales errorInfo et errorCode ne sont pas modifiées par Tcl_ResetResult, elles continuent donc de conserver un enregistrement des informations sur la dernière erreur rencontrée dans un interpréteur.
