ARGUMENTS

Tcl_Interp *interp (in)
Utilisé pour le rapport d'erreur et pour rechercher un canal enregistré dans celui-ci.
const char *fileName (in)
Le nom d'un fichier local ou réseau.
const char *mode (in)
Indique comment le fichier est accédé. Peut avoir n'importe quelle valeur autorisée pour l'argument mode de la commande open de Tcl.
int permissions (in)
Indicateurs de permissions POSIX comme 0644. Si un nouveau fichier est créé, ces permissions seront appliquées au fichier créé.
int argc (in)
Le nombre d'éléments dans argv.
const char **argv (in)
Arguments pour construire un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans options dans la commande exec de Tcl.
int flags (in)
Indique le comportement des handles standard dans le pipeline : combinaison OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, le stdin du premier enfant dans le pipeline est le canal du pipeline, sinon il est le même que le stdin du processus appelant ; il en va de même pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, le pipeline peut rediriger les handles standard pour outrepasser les handles standard pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, les redirections provoquent une erreur.
handle (in)
Un handle opérationnel spécifique pour les E/S vers un fichier. Pour Unix, c'est un descripteur de fichier, pour Windows c'est un HANDLE.
int readOrWrite (in)
Combinaison OR de TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (in)
Le nom du canal.
int *modePtr (out)
Pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (in)
Le motif à rechercher, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (in)
Un canal Tcl pour l'entrée ou la sortie. Il doit avoir été la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle seront stockés les caractères lus du canal.
int charsToRead (in)
Le nombre de caractères à lire du canal. Si l'en-tête d'encodage du canal est binary, cela équivaut au nombre d'octets à lire du canal.
int appendFlag (in)
Si différent de zéro, les données lues du canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu actuel de la valeur.
char *readBuf (out)
Un buffer dans lequel seront stockés les octets lus du canal.
int bytesToRead (in)
Le nombre d'octets à lire du canal. Le buffer readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (in/out)
Un pointeur vers une valeur Tcl dans laquelle sera stockée la ligne lue du canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (in/out)
Un pointeur vers une chaîne dynamique Tcl dans laquelle sera stockée la ligne lue du canal. Elle doit avoir été initialisée par l'appelant. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne dynamique.
const char *input (in)
L'entrée à ajouter à un buffer de canal.
int inputLen (in)
Longueur de l'entrée.
int addAtEnd (in)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du buffer du canal.
Tcl_Obj *writeObjPtr (in)
Un pointeur vers une valeur Tcl dont le contenu sera envoyé au canal.
const char *charBuf (in)
Un buffer contenant les caractères à envoyer au canal.
const char *byteBuf (in)
Un buffer contenant les octets à envoyer au canal.
int bytesToWrite (in)
Le nombre d'octets à consommer de charBuf ou byteBuf et à envoyer au canal.
Tcl_WideInt offset (in)
De combien d'octets le point d'accès dans le canal doit-il être déplacé pour appliquer la prochaine opération d'entrée ou de sortie, mesuré à partir du point donné par seekMode ? Il peut être positif ou négatif.
int seekMode (in)
À quel point rechercher ; utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs légales sont SEEK_SET, SEEK_CUR et SEEK_END.
Tcl_WideInt length (in)
La longueur (non négative) à laquelle tronquer le canal.
const char *optionName (in)
Le nom d'une option applicable au canal, tel que -blocking. Peut avoir n'importe quelle valeur acceptée par la commande fconfigure.
Tcl_DString *optionValue (in)
Où est stockée la valeur d'une option ou une liste de toutes les options et de leurs valeurs. Doit avoir été initialisé par l'appelant.
const char *newValue (in)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canal de Tcl fournit un mécanisme indépendant du périphérique et du système d'exploitation pour effectuer des opérations d'entrée/sortie bufferisées sur divers types de fichiers, sockets et périphériques. Le mécanisme de canal est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans le manuel de Tcl_CreateChannel. Le mécanisme de canal fournit un schéma de bufferisation similaire aux E/S standard Unix, et permet également des opérations non bloquantes sur les canaux.

Les procédures décrites dans cette page de manuel font partie des API C de niveau général de l'architecture des canaux. Pour une description de l'architecture du pilote de canal et comment implémenter des pilotes de canal pour de nouveaux types de canaux, voir le manuel de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Ouvre un canal pour le fichier spécifié par fileName, puis renvoie un handle de canal Tcl pour ce fichier. Le mode d'accès au fichier est spécifié par mode, et les permissions du nouveau fichier sont spécifiées par permissions. Si une erreur se produit pendant l'ouverture du fichier, une erreur Tcl est signalée et un canal NULL est renvoyé.

TCL_OPENCOMMANDCHANNEL

Crée un pipeline de processus et renvoie un canal Tcl qui peut être utilisé pour communiquer avec ce pipeline. Le pipeline est construit à partir des commandes dans argv. Les handles standard stdin, stdout et stderr du premier processus du pipeline peuvent être liés aux handles standard du processus Tcl appelant en utilisant les indicateurs flags. Les autres options de flags sont décrites dans la section ARGUMENTS.

Si une erreur se produit pendant la création du pipeline, une erreur Tcl est signalée et un canal NULL est renvoyé.

TCL_MAKEFILECHANNEL

Enveloppe un descripteur de fichier Unix ou un handle Windows existant dans un canal Tcl. Le handle handle est le descripteur de fichier ou le handle Windows. readOrWrite doit être une combinaison OR des indicateurs TCL_READABLE et TCL_WRITABLE pour indiquer si le handle doit être utilisé pour la lecture et/ou l'écriture.

Cette procédure est utile pour intégrer des descripteurs de fichiers ou des handles existants dans le système de canaux Tcl. Le canal Tcl créé est propriétaire du descripteur de fichier ou du handle, et le fermera lorsqu'il sera lui-même fermé.

TCL_GETCHANNEL

Renvoie un handle de canal Tcl pour le canal nommé channelName. Le mode d'ouverture du canal est spécifié par modePtr, qui est un pointeur vers un entier où seront stockés des indicateurs TCL_READABLE et/ou TCL_WRITABLE. Si channelName n'est pas un canal valide, ou si le mode d'ouverture demandé n'est pas autorisé, une erreur Tcl est signalée et un canal NULL est renvoyé.

TCL_GETCHANNELNAMES

Récupère une liste de tous les noms de canaux actuellement ouverts dans l'interpréteur interp. Les noms des canaux sont stockés sous forme d'une valeur Tcl listée dans l'objet d'interpréteur nommé result. Les noms des canaux sont renvoyés sous forme d'une liste Tcl de chaînes, où chaque chaîne est un nom de canal. Si une erreur se produit, une erreur Tcl est signalée et la valeur de l'objet result est effacée.

TCL_GETCHANNELNAMESEX

Similaire à Tcl_GetChannelNames, mais ne renvoie que les noms des canaux qui correspondent au pattern spécifié. Le motif est appliqué en utilisant Tcl_StringMatch. Si pattern est NULL, alors tous les noms de canaux sont renvoyés, comme avec Tcl_GetChannelNames.

TCL_REGISTERCHANNEL

Enregistre le canal channel donné dans l'interpréteur interp. Après l'enregistrement, le canal peut être référencé par son nom dans les commandes Tcl. Le canal doit avoir un nom valide assigné avant d'être enregistré; voir Tcl_CreateChannel pour de plus amples informations.

TCL_UNREGISTERCHANNEL

Désenregistre le canal channel donné de l'interpréteur interp. Après le désenregistrement, le canal ne peut plus être référencé par son nom. Le canal doit être fermé explicitement par un appel à Tcl_Close avant ou après le désenregistrement pour libérer les ressources associées.

Renvoie 0 en cas de succès, ou -1 si le canal n'était pas enregistré dans l'interpréteur.

TCL_DETACHCHANNEL

Détache le canal channel de l'interpréteur interp. Le canal reste ouvert, mais il n'est plus associé à un nom dans l'interpréteur. Les opérations futures sur le canal doivent être effectuées en utilisant le handle de canal retourné par des appels précédents à des fonctions comme Tcl_OpenFileChannel.

Cette fonction est utile lorsque vous souhaitez transférer la propriété d'un canal à une autre partie de votre application sans le fermer. Après avoir détaché un canal, le système de canaux Tcl ne le fermera plus automatiquement lorsqu'il sera désenregistré ou que l'interpréteur sera détruit.

Renvoie 0 en cas de succès, ou -1 si une erreur se produit.

TCL_ISSTANDARDCHANNEL

Renvoie vrai (1) si le canal channel est l'un des canaux standard (stdin, stdout, stderr), faux (0) sinon.

TCL_CLOSE

Ferme le canal channel donné, libérant toutes les ressources associées. Si une erreur se produit pendant la fermeture, une erreur Tcl est signalée.

Renvoie 0 en cas de succès, ou -1 si une erreur se produit.

TCL_READCHARS

Tente de lire charsToRead caractères du channel et de les stocker dans le Tcl_Obj readObjPtr. Si appendFlag est vrai, les caractères lus sont ajoutés à la valeur existante de readObjPtr ; sinon, ils remplacent la valeur existante. La procédure renvoie le nombre de caractères effectivement lus. Si une erreur se produit ou si la fin du fichier est atteinte avant que le nombre demandé de caractères n'ait été lu, un nombre plus petit peut être renvoyé.

TCL_READ

Tente de lire bytesToRead octets du channel et de les stocker dans le buffer readBuf. La procédure renvoie le nombre d'octets effectivement lus. Si une erreur se produit ou si la fin du fichier est atteinte avant que le nombre demandé d'octets n'ait été lu, un nombre plus petit peut être renvoyé.

TCL_GETSOBJ

Lit une ligne depuis le channel et la stocke dans le Tcl_Obj lineObjPtr. Une ligne est définie comme une séquence de caractères se terminant par un caractère de nouvelle ligne. Le caractère de nouvelle ligne est lu mais n'est pas inclus dans le résultat. Si la fin du fichier est atteinte avant la lecture d'une nouvelle ligne, la ligne restante est renvoyée. Si une erreur se produit, une erreur Tcl est signalée.

La procédure renvoie le nombre de caractères effectivement lus. Si une erreur se produit ou si la fin du fichier est atteinte, un nombre plus petit peut être renvoyé.

TCL_GETS

Similaire à Tcl_GetsObj, mais lit la ligne dans une chaîne dynamique Tcl lineRead. Le buffer lineRead doit avoir été initialisé par l'appelant avec Tcl_DStringInit. La ligne lue est ajoutée à la chaîne dynamique.

La procédure renvoie le nombre de caractères effectivement lus.

TCL_UNGETS

Retourne un tampon d'entrée pour le canal spécifié. Les données dans input (de longueur inputLen) sont ajoutées au buffer d'entrée du canal. Si addAtEnd est vrai, l'entrée est ajoutée à la fin du buffer; sinon, elle est ajoutée au début. Ceci est utile pour implémenter des analyseurs qui doivent « défaire » quelques caractères d'entrée.

La procédure renvoie le nombre d'octets effectivement ajoutés au buffer d'entrée.

TCL_WRITEOBJ

Écrit le contenu du Tcl_Obj writeObjPtr dans le channel. La procédure renvoie le nombre d'octets effectivement écrits.

TCL_WRITECHARS

Écrit les caractères du buffer charBuf dans le channel. bytesToWrite spécifie le nombre d'octets à écrire.

La procédure renvoie le nombre d'octets effectivement écrits.

TCL_WRITE

Écrit les octets du buffer byteBuf dans le channel. bytesToWrite spécifie le nombre d'octets à écrire.

La procédure renvoie le nombre d'octets effectivement écrits.

TCL_READRAW

Similaire à Tcl_Read, mais lit les données directement dans le buffer sans aucune conversion de fin de ligne ou de jeu de caractères.

TCL_WRITERAW

Similaire à Tcl_Write, mais écrit les données directement depuis le buffer sans aucune conversion de fin de ligne ou de jeu de caractères.

TCL_EOF

Renvoie vrai (1) si la fin du fichier a été atteinte sur le channel, faux (0) sinon.

TCL_FLUSH

Force l'écriture de toutes les données bufferisées dans le channel. Ceci est utile pour s'assurer que toutes les données écrites sont envoyées au périphérique sous-jacent.

Renvoie 0 en cas de succès, ou -1 si une erreur se produit.

TCL_INPUTBLOCKED

Renvoie vrai (1) si une tentative de lecture sur le channel bloquerait le processus appelant (par exemple, parce qu'il n'y a pas de données disponibles et que le canal n'est pas en mode non bloquant), faux (0) sinon.

TCL_INPUTBUFFERED

Renvoie le nombre d'octets de données actuellement dans le buffer d'entrée du channel qui n'ont pas encore été lus par l'application.

TCL_OUTPUTBUFFERED

Renvoie le nombre d'octets de données actuellement dans le buffer de sortie du channel qui n'ont pas encore été écrits sur le périphérique sous-jacent.

TCL_SEEK

Définit le point d'accès courant pour les opérations de lecture ou d'écriture sur le channel. Le nouveau point d'accès est calculé en ajoutant offset au point donné par seekMode. seekMode doit être l'une des valeurs SEEK_SET, SEEK_CUR ou SEEK_END. La procédure renvoie la nouvelle position du point d'accès, ou -1 sur une erreur.

Note: Le positionnement n'est pris en charge que pour les canaux qui prennent en charge le positionnement, tels que les fichiers ordinaires. Tenter de se positionner sur un canal qui ne prend pas en charge le positionnement (par exemple, un socket réseau) entraînera une erreur.

TCL_TELL

Renvoie la position actuelle du point d'accès pour le channel. Si le canal ne prend pas en charge le positionnement, une erreur est signalée. Renvoie la position actuelle ou -1 sur une erreur.

TCL_TRUNCATECHANNEL

Tronque le channel à la longueur spécifiée par length. La longueur doit être non négative. Si le canal est plus long que la longueur spécifiée, les données après la longueur spécifiée sont supprimées. Si le canal est plus court que la longueur spécifiée, il est étendu avec des octets nuls.

Cette opération n'est prise en charge que pour les canaux qui prennent en charge le positionnement et l'écriture. Tenter de tronquer un canal qui ne prend pas en charge ces opérations entraînera une erreur.

Renvoie 0 en cas de succès, ou -1 si une erreur se produit.

TCL_GETCHANNELOPTION

Récupère la valeur de l'option spécifiée par optionName pour le canal channel. La valeur de l'option est stockée dans le Tcl_DString optionValue. Si optionName est NULL, alors tous les noms d'options et leurs valeurs sont stockés dans optionValue sous forme d'une seule chaîne.

Renvoie 0 en cas de succès, ou -1 si une erreur se produit (par exemple, si l'option n'est pas valide ou si le canal n'existe pas).

TCL_SETCHANNELOPTION

Définit la valeur de l'option spécifiée par optionName pour le canal channel à newValue. Les options disponibles dépendent du type de canal. Les options courantes incluent -blocking, -buffering, -translation et -encoding.

Renvoie 0 en cas de succès, ou -1 si une erreur se produit (par exemple, si l'option n'est pas valide ou si la nouvelle valeur n'est pas valide).

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et retourne un handle de canal qui peut être utilisé pour effectuer des entrées et des sorties sur le fichier. Cette API est un modèle de la fonction fopen de la bibliothèque d'E/S standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. À partir de Tcl 8.4, l'API basée sur les valeurs Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel dans la mesure du possible.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr, a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface de niveau C aux fonctions des commandes exec et open. Il crée une chaîne de sous-processus spécifiés par les arguments argv et argc et retourne un canal qui peut être utilisé pour communiquer avec ces sous-processus. L'argument flags indique quel type de communication aura lieu avec la chaîne de commandes.

Si le flag TCL_STDIN est défini, le stdin du premier sous-processus est lié au canal : écrire dans le canal fournit l'entrée au sous-processus. Si le flag TCL_STDIN n'est pas défini, le stdin du premier sous-processus sera le même que le stdin de cette application. Si le flag TCL_STDOUT est défini, la sortie du dernier sous-processus peut être lue à partir du canal ; sinon, elle est dirigée vers la sortie standard de cette application. Si le flag TCL_STDERR est défini, la sortie d'erreur de tous les sous-processus est retournée au canal et provoque une erreur lors de la fermeture du canal ; sinon, elle est dirigée vers la sortie d'erreur standard de cette application. Si le flag TCL_ENFORCE_MODE n'est pas défini, argc et argv peuvent rediriger les handles standard pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, c'est une erreur si argc et argv tentent de remplacer les canaux standard pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr, a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'un handle de fichier existant, spécifique au système d'exploitation. Le nouveau canal créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr, a été précédemment fermé, l'acte de création du nouveau canal l'assigne également comme remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel retourne un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers l'interpréteur dans interp. S'il n'y a pas de canal enregistré sous ce nom dans l'interpréteur, il retourne NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OR de TCL_READABLE et TCL_WRITABLE, décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtre ces noms en fonction du pattern. Si pattern est NULL, aucune filtration n'est effectuée. La valeur de retour est TCL_OK s'il n'y a pas d'erreur lors de l'écriture dans le résultat, sinon TCL_ERROR et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à la liste des canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur pourront faire référence au canal par le nom fourni dans l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur peut appeler Tcl_RegisterChannel avec interp comme NULL, indiquant qu'il souhaite conserver une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et ne sera fermé que lorsque les appels correspondants à Tcl_UnregisterChannel auront été effectués. Cela permet au code exécuté en dehors de tout interpréteur de conserver en toute sécurité une référence à un canal qui est également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code gérant les canaux standard. Si aucun canal standard n'est initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour une généralisation sur les canaux standard et le comportement de la bibliothèque Tcl.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel supprime un canal de la liste des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Si cette opération a supprimé la dernière inscription du canal dans un interpréteur, le canal sera également fermé et détruit.

Le code non associé à un interpréteur peut appeler Tcl_UnregisterChannel avec interp comme NULL, indiquant à Tcl qu'il ne conserve plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera fermé maintenant. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel, sauf qu'il ferme également le canal s'il n'y a plus de références à celui-ci.

TCL_DETACHCHANNEL

Tcl_DetachChannel supprime un canal de la liste des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. De plus, cette commande n'a aucun effet supplémentaire. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin), et retournera TCL_ERROR si elle est appelée avec l'un de ces canaux.

Le code non associé à un interpréteur peut appeler Tcl_DetachChannel avec interp comme NULL, indiquant à Tcl qu'il ne conserve plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. Si c'est le cas, il retourne 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lors de l'appel à Tcl_Close. Le tampon de sortie est vidé du canal avant la destruction du canal, et tout tampon d'entrée est rejeté. Si le canal est bloquant, l'appel ne retourne pas tant que toutes les données bufferisées n'ont pas été envoyées au périphérique de sortie du canal. Si le canal est non bloquant et qu'il y a des données bufferisées qui ne peuvent pas être écrites sans bloquer, l'appel retourne immédiatement ; les données sont vidées en arrière-plan et le canal est fermé lorsque toutes les données bufferisées ont été émises. Dans ce cas, les erreurs lors du vidage ne sont pas rapportées.

Si le canal a été fermé avec succès, Tcl_Close retourne TCL_OK. Si une erreur se produit, Tcl_Close retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit pendant la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Remarque : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré avec Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour plus de détails. Si le canal a été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devez utiliser Tcl_UnregisterChannel, qui appelle Tcl_Close en interne lorsque tous les appels à Tcl_RegisterChannel ont été correspondus par des appels à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, les convertit en UTF-8 selon l'encodage du canal et stocke les données produites dans la représentation de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit pendant la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

L'encodage de char n'est pas vérifié ; le canal donné ou les canaux standard sont supposés être initialisés et valides.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du canal channel, en convertissant les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée ait été rencontrée. Si l'encodage du canal est binaire, chaque octet lu depuis le canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception des caractères de fin de ligne, sont ajoutés à la représentation textuelle de lineObjPtr. Les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. En cas d'erreur, Tcl_GetsObj retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj retourne également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode non bloquant, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est retourné, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité des entrées.

Tcl_Gets est identique à Tcl_GetsObj, à la différence que les caractères résultants sont ajoutés à la chaîne dynamique fournie par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, à la tête ou à la queue de la file. Le pointeur input pointe vers les données à ajouter. La longueur des données à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file d'attente ; sinon, elles seront ajoutées au début de la file. Si channel a un indicateur EOF "collant", aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets retourne inputLen ou -1 en cas d'erreur.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données textuelles à charBuf. Les caractères UTF-8 dans le tampon sont convertis à l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars attend que charBuf soit terminé par un caractère nul et affiche tout jusqu'au caractère nul.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering sur le canal à none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering sur le canal en mode line.

La valeur de retour de Tcl_WriteChars est le nombre d'octets qui ont été acceptés pour la sortie vers le canal. C'est soit un nombre supérieur à zéro pour indiquer le succès, soit -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme, conformément à l'option -translation du canal. Ceci est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars, sauf qu'il accepte une valeur Tcl dont le contenu sera affiché sur le canal. Les caractères UTF-8 de la représentation textuelle de writeObjPtr sont convertis à l'encodage du canal et mis en file d'attente pour la sortie vers channel. Par optimisation des performances, lors de l'écriture sur un canal avec l'encodage binaire, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets de la représentation interne de writeObjPtr en tant que valeur de tableau d'octets sont écrits sur le canal. La représentation en tableau d'octets de la valeur sera construite si nécessaire. De cette façon, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites sur un canal sans avoir à payer le coût de la conversion depuis ou vers UTF-8.

Tcl_Write est similaire à Tcl_WriteChars, sauf qu'il n'effectue pas de conversions d'encodage, quel que soit l'encodage du canal. Il est déprécié et existe pour des raisons de compatibilité descendante avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write attend que byteBuf soit terminé par un caractère nul et affiche tout jusqu'au caractère nul.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas la mise en pile. Alors que Tcl_Write (et les autres fonctions de l'API) alimentent toujours leur entrée dans le canal le plus haut de la pile dont le canal fourni fait partie, Tcl_WriteRaw ne le fait pas. Par conséquent, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer les données de la transformation vers le canal inférieur.

TCL_FLUSH

Tcl_Flush provoque l'écriture de toutes les données de sortie mises en mémoire tampon pour channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données mises en mémoire tampon n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal n'est pas bloquant ; il démarre une opération de vidage en arrière-plan qui écrira les données mises en mémoire tampon sur le canal éventuellement, aussi rapidement que le canal est capable de les absorber.

La valeur de retour est normalement TCL_OK. En cas d'erreur, Tcl_Flush retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données ultérieures seront lues ou écrites. La sortie mise en mémoire tampon est vidée vers le canal et l'entrée mise en mémoire tampon est discardée, avant l'opération de recherche.

Tcl_Seek retourne normalement le nouveau point d'accès. En cas d'erreur, Tcl_Seek retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut avoir été déplacé ou non.

TCL_TELL

Tcl_Tell retourne le point d'accès actuel pour un canal. La valeur retournée est -1 si le canal ne prend pas en charge la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent de channel à une longueur donnée de length octets. Il retourne TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et de leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, il s'agit du nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption returns the current value for an option optionName on channel. The value is returned as a value in the interpreter's result. If interp is non-NULL, Tcl_GetChannelOption may also set interpreter-specific channel options, for example, by using a series of calls to Tcl_DStringAppendElement. The various preexisting options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and calls Tcl_SetErrno to store an appropriate POSIX error code.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
