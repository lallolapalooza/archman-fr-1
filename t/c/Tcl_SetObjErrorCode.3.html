DESCRIPTION

Les routines Tcl_SetReturnOptions et Tcl_GetReturnOptions exposent les mêmes capacités que les commandes return et catch, respectivement, sous la forme d'une interface C.

Tcl_GetReturnOptions récupère le dictionnaire des options de retour d'un interpréteur suite à l'évaluation d'un script. Des routines telles que Tcl_Eval sont utilisées pour évaluer un script dans un interpréteur. Ces routines retournent un code de complétion entier. Ces routines laissent également dans l'interpréteur à la fois un résultat et un dictionnaire d'options de retour généré par l'évaluation du script. Tout comme Tcl_GetObjResult récupère le résultat, Tcl_GetReturnOptions récupère le dictionnaire des options de retour. Le code de complétion entier devrait être passé comme argument code à Tcl_GetReturnOptions afin que toutes les options requises soient présentes dans le dictionnaire. Spécifiquement, une valeur code de TCL_ERROR garantira que les entrées pour les clés -errorinfo, -errorcode et -errorline apparaîtront dans le dictionnaire. De plus, les entrées pour les clés -code et -level seront ajustées si nécessaire pour correspondre à la valeur de code. Le (Tcl_Obj *) retourné par Tcl_GetReturnOptions pointe vers un Tcl_Obj non partagé avec un compteur de références de zéro. Le dictionnaire peut être modifié, en ajoutant, supprimant ou écrasant n'importe quelle entrée, sans avoir besoin de vérifier une valeur partagée. Comme pour tout Tcl_Obj avec un compteur de références de zéro, il appartient à l'appelant de s'organiser pour sa suppression avec Tcl_DecrRefCount ou pour obtenir une référence à celui-ci via Tcl_IncrRefCount (ou l'une des nombreuses fonctions qui appellent cela, notamment Tcl_SetObjResult et Tcl_SetVar2Ex).

Une utilisation typique pour Tcl_GetReturnOptions est de récupérer la trace de la pile lors de l'évaluation d'un script retournant TCL_ERROR, comme suit :

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* Faire quelque chose avec stackTrace */
    Tcl_DecrRefCount(options);
}

Tcl_SetReturnOptions définit les options de retour de interp à être options. Si options contient une valeur invalide pour une clé, TCL_ERROR sera retourné, et le résultat de l'interpréteur sera défini à un message d'erreur approprié. Sinon, un code de complétion en accord avec les clés -code et -level dans options sera retourné.

Par exemple, la commande return de Tcl elle-même pourrait être implémentée en utilisant Tcl_SetReturnOptions comme suit :

if ((objc % 2) == 0) { /* argument de résultat explicite */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(Ce n'est pas vraiment implémenté ainsi. Les privilèges d'accès internes permettent une alternative plus efficace qui s'intègre mieux avec le compilateur de bytecode.)

Notez qu'un Tcl_Obj nouvellement créé peut être passé comme argument options sans avoir besoin de gérer le comptage de références. Ceci est analogue à Tcl_SetObjResult.

Alors que Tcl_SetReturnOptions fournit une interface générale pour définir toute collection d'options de retour, il existe une poignée d'options de retour très fréquemment utilisées. Notamment les options de retour -errorinfo et -errorcode doivent être correctement définies lorsque la procédure de commande d'une commande retourne TCL_ERROR. L'option de retour -errorline est également lue par les commandes qui évaluent des scripts et souhaitent fournir des informations détaillées sur la localisation de l'erreur dans le texte de la trace de la pile qu'elles ajoutent à l'option -errorinfo. Tcl fournit plusieurs interfaces plus simples pour définir plus directement ces options de retour.

L'option -errorinfo contient une trace de la pile des opérations en cours lorsqu'une erreur s'est produite, et est destinée à être lisible par l'homme. L'option -errorcode contient une liste Tcl d'éléments destinés à être lisibles par la machine. Le premier élément de la valeur -errorcode identifie la classe d'erreur qui s'est produite (par exemple, POSIX signifie qu'une erreur s'est produite dans un appel système POSIX) et des éléments supplémentaires contiennent des informations supplémentaires qui dépendent de la classe. Voir la page de manuel sur la variable errorCode pour les détails sur les différents formats de l'option -errorcode utilisés par les commandes intégrées de Tcl.

La valeur de l'option -errorinfo est progressivement construite lorsqu'une erreur se déroule à travers les opérations imbriquées. Chaque fois qu'un code d'erreur est retourné à Tcl_Eval, ou à l'une des routines qui effectuent l'évaluation de script, la procédure Tcl_AddErrorInfo est appelée pour ajouter un texte supplémentaire à la valeur -errorinfo décrivant la commande en cours d'exécution lorsque l'erreur s'est produite. Au moment où l'erreur est entièrement renvoyée à l'application, elle contiendra une trace complète de l'activité en cours lorsque l'erreur s'est produite.

Il est parfois utile d'ajouter des informations supplémentaires à la valeur -errorinfo au-delà de ce qui peut être fourni automatiquement par les routines d'évaluation de script. Tcl_AddErrorInfo peut être utilisé à cette fin : son argument message est une chaîne supplémentaire à ajouter à l'option -errorinfo. Par exemple, lorsqu'une erreur survient pendant la commande source, la procédure Tcl_AddErrorInfo est appelée pour enregistrer le nom du fichier en cours de traitement et le numéro de ligne de l'erreur. DESCRIPTION

These procedures are used to manipulate the error information maintained by a Tcl interpreter. The error information is returned to the caller of a script evaluation routine (like Tcl_Eval or Tcl_EvalObj) as return options. The most important return options are -errorinfo and -errorcode. The -errorinfo option contains a description of the error, including a stack trace, and the -errorcode option contains a structured error code.

Tcl_SetObjErrorCode is used to set the -errorcode return option to the list value errorObjPtr built up by the caller. Tcl_SetObjErrorCode is typically invoked just before returning an error. If an error is returned without calling Tcl_SetObjErrorCode or Tcl_SetErrorCode the Tcl interpreter automatically sets the -errorcode return option to NONE.

The procedure Tcl_SetErrorCode is also used to set the -errorcode return option. However, it takes one or more strings to record instead of a value. Otherwise, it is similar to Tcl_SetObjErrorCode in behavior.

Tcl_SetErrorCodeVA is the same as Tcl_SetErrorCode except that instead of taking a variable number of arguments it takes an argument list.

The procedure Tcl_AddErrorInfo appends the given message string to the -errorinfo return option. Tcl_AddErrorInfo is usually called when an error has occurred within a Tcl procedure, and the procedure wants to add information to the error message. Tcl procedures, the procedure name and line number within the procedure are recorded, and so on. The best time to call Tcl_AddErrorInfo is just after a script evaluation routine has returned TCL_ERROR. The value of the -errorline return option (retrieved via a call to Tcl_GetReturnOptions) often makes up a useful part of the message passed to Tcl_AddErrorInfo.

Tcl_AppendObjToErrorInfo is an alternative interface to the same functionality as Tcl_AddErrorInfo. Tcl_AppendObjToErrorInfo is called when the string value to be appended to the -errorinfo option is available as a Tcl_Obj instead of as a char array.

Tcl_AddObjErrorInfo is nearly identical to Tcl_AddErrorInfo, except that it has an additional length argument. This allows the message string to contain embedded null bytes. This is essentially never a good idea. If the message needs to contain the null character U+0000, Tcl's usual internal encoding rules should be used to avoid the need for a null byte. If the Tcl_AddObjErrorInfo interface is used at all, it should be with a negative length value.

The procedure Tcl_GetErrorLine is used to read the integer value of the -errorline return option without the overhead of a full call to Tcl_GetReturnOptions. Likewise, Tcl_SetErrorLine sets the -errorline return option value.

Tcl_PosixError sets the -errorcode variable after an error in a POSIX kernel call. It reads the value of the errno C variable and calls Tcl_SetErrorCode to set the -errorcode return option in the POSIX format. The caller must previously have called Tcl_SetErrno to set errno; this is necessary on some platforms (e.g. Windows) where Tcl is linked into an application as a shared library, or when the error occurs in a dynamically loaded extension. See the manual entry for Tcl_SetErrno for more information.

Tcl_PosixError returns a human-readable diagnostic message for the error (this is the same value that will appear as the third element in the -errorcode value). It may be convenient to include this string as part of the error message returned to the application in the interpreter's result.

Tcl_LogCommandInfo is invoked after an error occurs in an interpreter. It adds information about the command that was being executed when the error occurred to the -errorinfo value, and the line number stored internally in the interpreter is set.

In older releases of Tcl, there was no Tcl_GetReturnOptions routine. In its place, the global Tcl variables errorInfo and errorCode were the only place to retrieve the error information. Much existing code written for older Tcl releases still access this information via those global variables.

It is important to realize that while reading from those global variables remains a supported way to access these return option values, it is important not to assume that writing to those global variables will properly set the corresponding return options. It has long been emphasized in this manual page that it is important to call the procedures described here rather than setting errorInfo or errorCode directly with Tcl_ObjSetVar2.

If the procedure Tcl_ResetResult is called, it clears all of the state of the interpreter associated with script evaluation, including the entire return options dictionary. In particular, the -errorinfo and -errorcode options are reset. If an error had occurred, the Tcl_ResetResult call will clear the error state to make it appear as if no error had occurred after all. The global variables errorInfo and errorCode are not modified by Tcl_ResetResult so they continue to hold a record of information about the most recent error seen in an interpreter.
