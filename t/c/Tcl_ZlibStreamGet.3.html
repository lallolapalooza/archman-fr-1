ARGUMENTS

Tcl_Interp *interp (in)
L'interpréteur où sont stockées les données compressées ou non compressées. C'est aussi là que les messages d'erreur sont écrits. Pour Tcl_ZlibStreamInit, ceci peut être NULL pour créer un flux qui n'est pas lié à une commande.
int format (in)
Quel format de données compressées manipuler. Doit être l'un des suivants : TCL_ZLIB_FORMAT_ZLIB pour des données compressées au format zlib, TCL_ZLIB_FORMAT_GZIP pour des données compressées au format gzip, ou TCL_ZLIB_FORMAT_RAW pour des données compressées au format brut. Additionnellement, pour la compression uniquement, TCL_ZLIB_FORMAT_AUTO peut être sélectionné, qui peut automatiquement détecter si les données compressées étaient au format zlib ou gzip.
Tcl_Obj *dataObj (in/out)
Une valeur de type tableau d'octets contenant les données à compresser ou décompresser, ou à laquelle les données extraites du flux sont ajoutées lors du passage à Tcl_ZlibStreamGet.
int level (in)
Quel niveau de compression utiliser. Doit être un nombre de 0 à 9 ou l'un des suivants : TCL_ZLIB_COMPRESS_NONE pour aucune compression, TCL_ZLIB_COMPRESS_FAST pour une compression rapide mais inefficace, TCL_ZLIB_COMPRESS_BEST pour une compression lente mais maximale, ou TCL_ZLIB_COMPRESS_DEFAULT pour le niveau recommandé par la bibliothèque zlib.
Tcl_Obj *dictObj (in/out)
Un dictionnaire contenant, ou qui sera mis à jour pour contenir, une description de l'en-tête gzip associée aux données compressées. Ceci est utile uniquement lorsque le format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Si NULL est passé, un en-tête par défaut sera utilisé lors de la compression et l'en-tête sera ignoré (sauf si des vérifications d'intégrité sont effectuées) lors de la décompression. Pour plus de détails sur le contenu de ce dictionnaire, voir la section DICTIONNAIRE DES OPTIONS GZIP.
unsigned int initValue (in)
Valeur initiale pour l'algorithme de vérification de somme de contrôle.
int bufferSize (in)
Quelle est la taille approximative du tampon à utiliser pour recevoir les données. Utilisez 0 pour utiliser une estimation basée sur les données d'entrée.
unsigned char *bytes (in)
Un tableau d'octets pour exécuter l'algorithme de vérification de somme de contrôle, ou NULL pour obtenir la valeur initiale recommandée pour l'algorithme de vérification de somme de contrôle.
int length (in)
Le nombre d'octets dans le tableau.
int mode (in)
Quel mode opérer pour le flux. Doit être l'un des suivants : TCL_ZLIB_STREAM_DEFLATE pour un flux de compression ou TCL_ZLIB_STREAM_INFLATE pour un flux de décompression.
Tcl_ZlibStream *zshandlePtr (out)
Un pointeur vers une variable dans laquelle le jeton abstrait du flux sera écrit après sa création.
Tcl_ZlibStream zshandle (in)
Le jeton abstrait du flux sur lequel opérer.
int flush (in)
Et comment doit-on vider le flux après y avoir écrit des données. Doit être l'un des suivants : TCL_ZLIB_NO_FLUSH s'il n'y a pas de vidage à effectuer, TCL_ZLIB_FLUSH si les données compressées actuelles doivent être accessibles via Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si le flux doit être dans un état où le décompresseur peut se remettre d'une corruption, ou TCL_ZLIB_FINALIZE pour s'assurer que le flux est terminé et que tout bloc final requis par le format est écrit.
int count (in)
Le nombre maximum d'octets à obtenir du flux, ou -1 pour obtenir tous les octets restants des tampons du flux.
Tcl_Obj *compDict (in)
Une valeur de type tableau d'octets qui sera utilisée comme dictionnaire de compression pour le flux. Il convient de noter qu'il ne s'agit pas d'un dictionnaire Tcl, et il est recommandé de l'utiliser uniquement avec les flux qui ont été créés avec leur format défini sur TCL_ZLIB_FORMAT_ZLIB, car les autres formats n'ont pas de mécanisme pour indiquer si un dictionnaire de compression était présent, à l'exception de l'échec de la décompression.

DESCRIPTION

Ces fonctions constituent l'interface de la bibliothèque Tcl à la bibliothèque Zlib de Jean-loup Gailly et Mark Adler.

Tcl_ZlibDeflate et Tcl_ZlibInflate compressent et décompressent respectivement les données contenues dans l'argument dataObj, selon l'argument format et, pour la compression, level. Le dictionnaire dans l'argument dictObj est utilisé pour transmettre des informations supplémentaires sur les données compressées lorsque le format de compression le prend en charge ; actuellement, le dictionnaire n'est utilisé que lorsque l'argument format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Pour plus de détails sur le contenu du dictionnaire, voir la section DICTIONNAIRE DES OPTIONS GZIP. En cas de succès, les deux fonctions laisseront les données compressées ou décompressées dans une valeur de type tableau d'octets qui est le résultat de l'interpréteur Tcl ; la valeur retournée est un code de résultat standard de Tcl.

Tcl_ZlibAdler32 et Tcl_ZlibCRC32 calculent des sommes de contrôle sur des tableaux d'octets, retournant la somme de contrôle calculée. Les sommes de contrôle sont calculées de manière incrémentielle, permettant de traiter les données bloc par bloc, mais cela nécessite que l'appelant conserve la valeur actuelle de la somme de contrôle et la transmette comme paramètre initValue ; la valeur initiale pour cela peut être obtenue en utilisant NULL pour le paramètre bytes au lieu d'un pointeur vers un tableau d'octets pour calculer la somme de contrôle. Par conséquent, l'utilisation typique dans le cas d'un seul bloc de données est la suivante :

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Remarque : L'algorithme Adler-32 n'est pas une véritable somme de contrôle, mais une forme de hachage apparentée qui fonctionne mieux sur de longues séquences de données.

FLUX ZLIB

Tcl_ZlibStreamInit crée un flux de compression ou de décompression lié à une commande Tcl, selon ses arguments, et fournit un jeton abstrait pour le flux, retournant un code de résultat standard de Tcl ; Tcl_ZlibStreamGetCommandName retourne le nom de la commande étant donné le jeton du flux, ou NULL si le flux n'a pas de commande. Les flux ne sont pas conçus pour être thread-safe ; chaque flux ne doit être utilisé que par le thread qui l'a créé. Lors de la manipulation de flux gzip, un dictionnaire (tel que décrit dans la section DICTIONNAIRE DES OPTIONS GZIP) peut être fourni par le paramètre dictObj, qui permet le contrôle des en-têtes générés lors de la compression et la découverte des en-têtes existants lors de la décompression. Notez que le dictionnaire sera écrit dans le cas de la décompression une fois que suffisamment de données auront été lues pour obtenir un en-tête complet. Cela signifie que le dictionnaire doit être une valeur non partagée dans ce cas ; il est suggéré d'utiliser une valeur vide créée avec Tcl_NewObj.

Une fois qu'un flux est construit, Tcl_ZlibStreamPut est utilisé pour ajouter des données au flux et Tcl_ZlibStreamGet est utilisé pour obtenir des données du flux après traitement. Les deux retournent des codes de résultat standard de Tcl et laissent un message d'erreur dans le résultat de l'interpréteur auquel le flux est enregistré en cas d'erreur (si un tel enregistrement a été effectué). Avec Tcl_ZlibStreamPut, la valeur du tampon de données qui lui est passée ne doit pas être modifiée par la suite. Avec Tcl_ZlibStreamGet, la valeur du tampon de données qui lui est passée aura les octets de données ajoutés. Interne au flux, les données sont conservées compressées pour minimiser le coût de l'espace tampon.

NOM

Tcl_ZlibStreamGet, Tcl_ZlibStreamPut, Tcl_ZlibStreamSetCompressionDictionary, Tcl_ZlibStreamReset, Tcl_ZlibStreamClose, Tcl_ZlibStreamGetError - gestion de flux de compression zlib

Tcl_ZlibStreamSetCompressionDictionary(
    Tcl_Interp *interp,

int
Tcl_ZlibStreamReset(
    Tcl_Interp *interp,
    Tcl_Obj *streamPtr

void
Tcl_ZlibStreamClose(
    Tcl_Interp *interp,
    Tcl_Obj *streamPtr

Tcl_ZlibStreamGetError(

ARGUMENTS

Tcl_Interp *interp
Interpréteur Tcl courant.
Tcl_Obj *streamPtr
Pointeur vers l'objet Tcl représentant le flux zlib.
Tcl_Obj **resultPtr
Pointeur vers un pointeur vers un objet Tcl, où le résultat décompressé sera stocké. Cet objet sera une nouvelle chaîne Tcl.
Tcl_Obj *dataPtr
Pointeur vers l'objet Tcl contenant les données à compresser.
Tcl_Obj *dictPtr
Pointeur vers l'objet Tcl représentant le dictionnaire de compression.

DESCRIPTION

Ces fonctions fournissent une interface de bas niveau pour la gestion des flux de compression et décompression zlib. Elles permettent de compresser ou décompresser des données de manière incrémentale, ce qui est utile pour traiter de gros fichiers ou des données provenant de sources réseau.

Tcl_ZlibStreamGet tente de récupérer des données décompressées du flux. Si des données sont disponibles, elles sont stockées dans l'objet pointé par *resultPtr et la fonction retourne TCL_OK. Si le flux est vide et qu'aucune donnée n'est encore disponible, la fonction retourne TCL_OK mais *resultPtr sera un objet chaîne vide. Si une erreur se produit pendant la décompression, la fonction retourne TCL_ERROR et un message d'erreur est laissé dans le résultat de l'interpréteur. Si la fin des données compressées est atteinte, la fonction retourne TCL_OK et *resultPtr contiendra toutes les données décompressées disponibles jusqu'à présent. La fonction `amEof` (non documentée ici, mais implicitement utilisée par `Tcl_ZlibStreamGet`) renvoie une valeur booléenne indiquant si la fin des données décompressées a été atteinte.

Tcl_ZlibStreamPut envoie des données à compresser dans le flux. L'objet `dataPtr` doit contenir les données à compresser. La fonction retourne TCL_OK en cas de succès et TCL_ERROR en cas d'erreur.

Tcl_ZlibStreamSetCompressionDictionary est utilisé pour contrôler le dictionnaire de compression utilisé avec le flux. Un dictionnaire de compression est un tableau d'octets (tel que pourrait être créé avec Tcl_NewByteArrayObj) utilisé pour initialiser le moteur de compression plutôt que de le laisser le créer à la volée à partir des données compressées. La définition d'un dictionnaire de compression permet une compression plus efficace lorsque le début des données est très régulier, mais cela nécessite que le compresseur et le décompresseur s'accordent sur la valeur à utiliser. Les dictionnaires de compression ne sont entièrement pris en charge que pour les données au format zlib. Lors de la compression, ils doivent être définis avant que toute donnée ne soit envoyée avec Tcl_ZlibStreamPut, et lors de la décompression, ils doivent être définis lorsque Tcl_ZlibStreamGet produit une erreur avec son -errorcode défini sur « ZLIB NEED_DICT code » ; le code sera la somme de contrôle Adler-32 (voir Tcl_ZlibAdler32) du dictionnaire de compression recherché. (Notez que ce n'est vrai que pour les flux au format zlib ; les flux gzip ignorent les dictionnaires de compression car la spécification du format ne les autorise pas, et les flux bruts produisent simplement une erreur de données si le dictionnaire de compression est manquant ou incorrect.)

Si vous souhaitez réinitialiser un flux et le réutiliser pour une nouvelle action de compression ou de décompression, Tcl_ZlibStreamReset s'en chargera et retournera un code de résultat Tcl normal pour indiquer si cela a réussi ; si le flux est enregistré auprès d'un interpréteur, un message d'erreur sera laissé dans le résultat de l'interpréteur lorsque cette fonction retournera TCL_ERROR. Enfin, Tcl_ZlibStreamClose nettoiera le flux et supprimera la commande associée : l'utilisation de Tcl_DeleteCommand sur la commande du flux est équivalente (lorsqu'une telle commande existe).

OPTIONS GZIP DICTIONNAIRE

Le paramètre dictObj pour Tcl_ZlibDeflate, Tcl_ZlibInflate et Tcl_ZlibStreamInit est utilisé pour passer un dictionnaire d'options décrivant l'en-tête gzip dans les données compressées. Lors de la création de données compressées, le dictionnaire est lu et lors du dépaquetage de données compressées, le dictionnaire est écrit (auquel cas le paramètre dictObj doit faire référence à une valeur de dictionnaire non partagée).

Les champs suivants de la valeur du dictionnaire sont compris. Tous les autres champs sont ignorés. Aucun champ n'est requis lors de la création d'un flux au format gzip.

comment
Contient le champ commentaire de l'en-tête, s'il est présent. S'il est absent, aucun commentaire n'a été fourni (lors de la décompression) ou ne sera créé (lors de la compression).
crc
Une valeur booléenne indiquant si une somme de contrôle CRC de l'en-tête est calculée. Notez que le programme gzip n'utilise pas et n'autorise pas une somme de contrôle CRC sur l'en-tête.
filename
Le nom du fichier qui contenait les données non compressées. Il ne doit pas contenir de séparateurs de répertoire et doit être assaini avant utilisation lors de la décompression avec file tail.
os
Le champ code de type du système d'exploitation de l'en-tête (s'il n'est pas la valeur « unknown »). Voir RFC 1952 pour la signification de ces codes. Lors de la compression, si ce champ est absent, il sera défini sur la valeur « unknown ».
size
La taille des données non compressées. Ce champ est ignoré lors de la compression ; la taille des données compressées dépend de la quantité de données fournie au moteur de compression.
time
Le champ heure de l'en-tête s'il est non nul, supposé être l'heure de modification du fichier nommé par le champ filename. Convient pour une utilisation avec clock format. Lors de la création, la valeur appropriée à utiliser est celle de clock seconds ou file mtime.
type
Le type des données non compressées (soit binary soit text) si connu.

NOTES DE PORTABILITÉ

Ces fonctions échoueront gracieusement si Tcl n'est pas lié à la bibliothèque zlib.
