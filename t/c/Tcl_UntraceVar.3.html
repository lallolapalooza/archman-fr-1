Tcl_TraceVar(3) Procédures de la bibliothèque Tcl Tcl_TraceVar(3)

NOM

Tcl_TraceVar, Tcl_TraceVar2, Tcl_UntraceVar, Tcl_UntraceVar2, Tcl_VarTraceInfo, Tcl_VarTraceInfo2 - surveiller les accès à une variable

SYNOPSIS

#include <tcl.h>

int
Tcl_TraceVar(interp, varName, flags, proc, clientData)

int
Tcl_TraceVar2(interp, name1, name2, flags, proc, clientData)

Tcl_UntraceVar(interp, varName, flags, proc, clientData)

Tcl_UntraceVar2(interp, name1, name2, flags, proc, clientData)

ClientData
Tcl_VarTraceInfo(interp, varName, flags, proc, prevClientData)

ClientData
Tcl_VarTraceInfo2(interp, name1, name2, flags, proc, prevClientData)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur contenant la variable.
const char *varName (in)
Nom de la variable. Peut faire référence à une variable scalaire, à une variable de tableau sans index, ou à une variable de tableau avec un index parentésé.
int flags (in)
Combinaison OU des valeurs TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS, TCL_TRACE_ARRAY, TCL_GLOBAL_ONLY, TCL_NAMESPACE_ONLY, TCL_TRACE_RESULT_DYNAMIC et TCL_TRACE_RESULT_OBJECT. Tous les indicateurs ne sont pas utilisés par toutes les procédures. Voir ci-dessous pour plus d'informations.
Tcl_VarTraceProc *proc (in)
Procédure à appeler chaque fois qu'une des opérations tracées se produit.
ClientData clientData (in)
Valeur arbitraire d'un mot à passer à proc.
const char *name1 (in)
Nom de la variable scalaire ou de tableau (sans index de tableau).
const char *name2 (in)
Pour un trace sur un élément d'un tableau, donne l'index de l'élément. Pour les traces sur des variables scalaires ou sur des tableaux entiers, est NULL.
ClientData prevClientData (in)
Si non-NULL, donne la dernière valeur retournée par Tcl_VarTraceInfo ou Tcl_VarTraceInfo2, donc cet appel retournera des informations sur le trace suivant. Si NULL, cet appel retournera des informations sur le premier trace.

DESCRIPTION

Tcl_TraceVar permet à une procédure C de surveiller et de contrôler l'accès à une variable Tcl, de sorte que la procédure C soit appelée chaque fois que la variable est lue, écrite ou désinstallée. Si le trace est créé avec succès, Tcl_TraceVar retourne TCL_OK. Si une erreur s'est produite (par exemple, varName spécifie un élément d'un tableau, mais la variable réelle n'est pas un tableau), alors TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de l'interpréteur.

L'argument flags pour Tcl_TraceVar indique quand la procédure de trace doit être appelée et fournit des informations pour la configuration du trace. Il se compose d'une combinaison OU de n'importe lequel des valeurs suivantes :

TCL_GLOBAL_ONLY
Normalement, la variable sera recherchée au niveau actuel de l'appel de procédure ; si ce bit est défini, la variable sera recherchée au niveau global, ignorant toutes les procédures actives.
TCL_NAMESPACE_ONLY
Normalement, la variable sera recherchée au niveau actuel de l'appel de procédure ; si ce bit est défini, la variable sera recherchée dans l'espace de noms actuel, ignorant toutes les procédures actives.
TCL_TRACE_READS
Appeler proc chaque fois qu'une tentative de lecture de la variable est effectuée.
TCL_TRACE_WRITES
Appeler proc chaque fois qu'une tentative de modification de la variable est effectuée.
TCL_TRACE_UNSETS
Appeler proc chaque fois que la variable est désinstallée. Une variable peut être désinstallée explicitement par une commande unset, ou implicitement lorsqu'une procédure retourne (ses variables locales sont automatiquement désinstallées) ou lorsque l'interpréteur est supprimé (toutes les variables sont automatiquement désinstallées).
TCL_TRACE_ARRAY
Appeler proc chaque fois que la commande array est invoquée. Cela donne à la procédure de trace une chance de mettre à jour le tableau avant que array names ou array get ne soient appelés. Notez que cela est appelé avant un array set, mais cela déclenchera des traces d'écriture.
TCL_TRACE_RESULT_DYNAMIC
Le résultat de l'appel de proc est une chaîne allouée dynamiquement qui sera libérée par la bibliothèque Tcl via un appel à ckfree. Ne doit pas être spécifié en même temps que TCL_TRACE_RESULT_OBJECT.
TCL_TRACE_RESULT_OBJECT
Le résultat de l'appel de proc est un Tcl_Obj* (casté en char*) avec un compteur de références d'au moins un. La propriété de cette référence sera transférée au cœur Tcl pour être libérée (une fois que le cœur aura fini avec) via un appel à Tcl_DecrRefCount. Ne doit pas être spécifié en même temps que TCL_TRACE_RESULT_DYNAMIC.

Chaque fois qu'une des opérations spécifiées se produit sur la variable, proc sera appelée. Elle doit avoir des arguments et un résultat qui correspondent au type Tcl_VarTraceProc :

typedef char *Tcl_VarTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *name1,
        const char *name2,
        int flags);

Les paramètres clientData et interp auront les mêmes valeurs que celles passées à Tcl_TraceVar lors de la création du trace. ClientData pointe généralement vers une structure de données spécifique à l'application qui décrit quoi faire lorsque proc est appelée. Name1 et name2 donnent le nom de la variable tracée sous la forme normale en deux parties (voir la description de Tcl_TraceVar2 ci-dessous pour plus de détails). Flags est une combinaison OU de bits fournissant plusieurs informations. L'un des bits TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_ARRAY, ou TCL_TRACE_UNSETS sera défini dans flags pour indiquer quelle opération est effectuée sur la variable. Le bit TCL_GLOBAL_ONLY sera défini chaque fois que la variable accédée est une variable globale non accessible depuis le niveau actuel de l'appel de procédure : la procédure de trace devra repasser ce bit aux procédures liées aux variables comme Tcl_GetVar si elle tente d'accéder à la variable. Le bit TCL_NAMESPACE_ONLY sera défini chaque fois que la variable accédée est une variable d'espace de noms non accessible depuis le niveau actuel de l'appel de procédure : la procédure de trace devra repasser ce bit aux procédures liées aux variables comme Tcl_GetVar si elle tente d'accéder à la variable. Le bit TCL_TRACE_DESTROYED sera défini dans flags si le trace est sur le point d'être détruit ; cette information peut être utile à proc pour qu'elle puisse nettoyer ses propres structures de données internes (voir la section TCL_TRACE_DESTROYED ci-dessous pour plus de détails). Enfin, le bit TCL_INTERP_DESTROYED sera défini si l'interpréteur entier est détruit. Lorsque ce bit est défini, proc doit être particulièrement prudente dans les actions qu'elle effectue (voir la section TCL_INTERP_DESTROYED ci-dessous). La valeur de retour de la procédure de trace doit normalement être NULL ; voir RETOURS D'ERREURS ci-dessous pour des informations sur d'autres possibilités.

Tcl_UntraceVar peut être utilisé pour supprimer un trace. Si la variable spécifiée par interp, varName et flags a un trace défini avec flags, proc et clientData, alors le trace correspondant est supprimé. Si aucun trace de ce type n'existe, alors l'appel à Tcl_UntraceVar n'a aucun effet. Les mêmes bits sont valides pour flags que pour les appels à Tcl_TraceVar.

Tcl_VarTraceInfo peut être utilisé pour récupérer des informations sur les traces définis sur une variable donnée. La valeur de retour de Tcl_VarTraceInfo est le clientData associé à un trace particulier. Le trace doit être sur la variable spécifiée par les arguments interp, varName et flags (seuls les bits TCL_GLOBAL_ONLY et TCL_NAMESPACE_ONLY de flags sont utilisés ; les autres bits sont ignorés) et sa procédure de trace doit être la même que l'argument proc. Si l'argument prevClientData est NULL, alors la valeur de retour correspond au premier trace correspondant (le plus récemment créé), ou NULL s'il n'y a pas de correspondance.

ng traces. Si l'argument prevClientData n'est pas NULL, alors il doit s'agir de la valeur de retour d'un appel précédent à Tcl_VarTraceInfo. Dans ce cas, la nouvelle valeur de retour correspondra à la trace correspondante suivante après celle dont le clientData correspond à prevClientData, ou NULL s'il n'y a pas de trace correspondant à prevClientData ou s'il n'y en a pas d'autre après. Ce mécanisme permet de parcourir toutes les traces d'une variable donnée qui ont le même proc.

NOMS EN DEUX PARTIES

Les procédures Tcl_TraceVar2, Tcl_UntraceVar2 et Tcl_VarTraceInfo2 sont identiques à Tcl_TraceVar, Tcl_UntraceVar et Tcl_VarTraceInfo, respectivement, à la différence près que le nom de la variable est composé de deux parties. Name1 donne le nom d'une variable scalaire ou d'un tableau, et name2 donne le nom d'un élément dans un tableau. Lorsque name2 est NULL, name1 peut contenir à la fois un nom de tableau et un nom d'élément : si le nom contient une parenthèse ouvrante et se termine par une parenthèse fermante, alors la valeur entre les parenthèses est traitée comme un nom d'élément (qui peut avoir n'importe quelle valeur de chaîne) et les caractères avant la première parenthèse ouvrante sont traités comme le nom d'une variable de tableau. Si name2 est NULL et que name1 ne fait pas référence à un élément de tableau, cela signifie que la variable est scalaire ou que la trace doit être définie sur l'ensemble du tableau plutôt que sur un élément individuel (voir TRACES DE TABLEAU ENTIER ci-dessous pour plus d'informations).

ACCÈS AUX VARIABLES PENDANT LES TRACES

Lors des traces de lecture, d'écriture et de tableau, la procédure de trace peut lire, écrire ou désinstaller la variable tracée en utilisant Tcl_GetVar2, Tcl_SetVar2 et d'autres procédures. Pendant que proc s'exécute, les traces sont temporairement désactivées pour la variable, de sorte que les appels à Tcl_GetVar2 et Tcl_SetVar2 ne déclenchent pas l'invocation répétée de proc ou d'autres procédures de trace. La désactivation ne se produit que pour la variable dont la procédure de trace est active ; les accès à d'autres variables seront toujours tracés. Cependant, si une variable est désinstallée pendant une trace de lecture ou d'écriture, les traces de désinstallation seront invoquées.

Pendant les traces de désinstallation, la variable a déjà été complètement supprimée. Il est possible pour la procédure de trace de lire ou d'écrire la variable, mais il s'agira d'une nouvelle version de la variable. Les traces ne sont pas désactivées pendant les traces de désinstallation comme elles le sont pour les traces de lecture et d'écriture, mais les traces existantes ont été supprimées de la variable avant que toute procédure de trace ne soit invoquée. Si de nouvelles traces sont définies par des procédures de trace de désinstallation, ces traces seront invoquées lors des accès à la variable par les procédures de trace.

CALENDRIER DES APPELS DE RETOUR

Lorsque le traçage de lecture a été spécifié pour une variable, la procédure de trace sera invoquée chaque fois que la valeur de la variable sera lue. Cela inclut les commandes Tcl set, la notation en $-notation dans les commandes Tcl et les invocations des procédures Tcl_GetVar et Tcl_GetVar2. Proc est invoquée juste avant que la valeur de la variable ne soit retournée. Elle peut modifier la valeur de la variable pour affecter ce qui est retourné par l'accès tracé. Si elle désinstalle la variable, l'accès retournera une erreur comme si la variable n'avait jamais existé.

Lorsque le traçage d'écriture a été spécifié pour une variable, la procédure de trace sera invoquée chaque fois que la valeur de la variable sera modifiée. Cela inclut les commandes set, les commandes qui modifient les variables comme effets secondaires (telles que catch et scan), et les appels aux procédures Tcl_SetVar et Tcl_SetVar2. Proc sera invoquée après que la valeur de la variable ait été modifiée, mais avant que la nouvelle valeur de la variable n'ait été retournée. Elle peut modifier la valeur de la variable pour remplacer le changement et déterminer la valeur réellement retournée par l'accès tracé. Si elle supprime la variable, l'accès tracé retournera une chaîne vide.

Lorsque le traçage de tableau a été spécifié, la procédure de trace sera invoquée au début de l'implémentation de la commande de tableau, avant que les opérations telles que get, set ou names n'aient été invoquées. La procédure de trace peut modifier les éléments du tableau avec Tcl_SetVar et Tcl_SetVar2.

Lorsque le traçage de désinstallation a été spécifié, la procédure de trace sera invoquée chaque fois que la variable est détruite. Les traces seront appelées après que la variable ait été complètement désinstallée.

TRACES DE TABLEAU ENTIER

Si un appel à Tcl_TraceVar ou Tcl_TraceVar2 spécifie le nom d'une variable de tableau sans index dans le tableau, la trace sera définie sur le tableau dans son ensemble. Cela signifie que proc sera invoquée chaque fois qu'un élément du tableau sera accédé de la manière spécifiée par flags. Lorsqu'un tableau est désinstallé, une trace de tableau entier sera invoquée une seule fois, avec name1 égal au nom du tableau et name2 NULL ; elle ne sera pas invoquée une fois pour chaque élément.

TRACES MULTIPLES

Il est possible que plusieurs traces existent sur la même variable. Lorsque cela se produit, toutes les procédures de trace seront invoquées à chaque accès, dans l'ordre de la plus récemment créée à la moins récemment créée. Lorsqu'il existe des traces de tableau entier pour un tableau ainsi que des traces sur des éléments individuels, les traces de tableau entier sont invoquées avant les traces d'éléments individuels. Si une trace de lecture ou d'écriture désinstalle la variable, toutes les traces de désinstallation seront invoquées, mais les autres traces de lecture et d'écriture seront ignorées.

RETOURS D'ERREUR

Dans des conditions normales, les procédures de trace doivent retourner NULL, indiquant une achèvement réussie. Si proc retourne une valeur non-NULL, cela signifie qu'une erreur s'est produite. La valeur de retour doit être un pointeur vers une chaîne de caractères statique contenant un message d'erreur, sauf si (exactement l'un des) drapeaux TCL_TRACE_RESULT_DYNAMIC et TCL_TRACE_RESULT_OBJECT est défini, qui spécifient que le résultat est soit une chaîne dynamique (à libérer avec ckfree), soit un Tcl_Obj* (converti en char* et à libérer avec Tcl_DecrRefCount) contenant le message d'erreur. Si une procédure de trace retourne une erreur, aucune trace supplémentaire n'est invoquée pour l'accès et l'accès tracé est abandonné avec le message donné. Les procédures de trace peuvent utiliser cette installation pour rendre les variables non modifiables, par exemple (mais notez que la valeur de la variable aura déjà été modifiée avant que la procédure de trace ne soit appelée, donc la procédure de trace devra restaurer la valeur correcte).

La valeur de retour de proc n'est utilisée que lors des traces de lecture et d'écriture. Pendant les traces de désinstallation, la valeur de retour est ignorée et toutes les procédures de trace pertinentes seront toujours invoquées.

RESTRICTIONS

Une procédure de trace peut être appelée à tout moment, même lorsqu'il existe des résultats partiellement formés stockés dans l'interpréteur. Si la procédure de trace fait quelque chose qui pourrait endommager ce résultat (comme appeler Tcl_Eval), elle doit utiliser les routines Tcl_SaveInterpState et les routines associées pour sauvegarder et restaurer l'état original de l'interpréteur avant de retourner.

VARIABLES NON DÉFINIES

Il est légal de définir une trace sur une variable non définie. La variable apparaîtra toujours comme non définie jusqu'à la première fois où sa valeur est définie. Si une variable non définie est tracée puis désinstallée, la désinstallation échouera avec une erreur (« aucune telle variable »), mais la procédure de trace sera toujours invoquée.

LE DRAPEAU TCL_TRACE_DESTROYED

Dans un rappel de désinstallation à proc, le bit TCL_TRACE_DESTROYED est défini dans flags si la trace est en cours de suppression dans le cadre de la suppression. Les traces d'une variable sont toujours supprimées chaque fois que la variable est supprimée ; la seule fois où TCL_TRACE_DESTROYED n'est pas défini, c'est pour une trace de tableau entier invoquée lorsque seul un seul élément d'un tableau est désinstallé.

TCL_INTERP_DESTROYED

Lorsqu'un interpréteur est détruit, les traces de désinstallation sont appelées pour toutes ses variables. Le bit TCL_INTERP_DESTROYED sera défini dans l'argument flags passé aux procédures de trace. Les procédures de trace doivent être extrêmement prudentes dans ce qu'elles font si le bit TCL_INTERP_DESTROYED est défini. Il n'est pas sûr pour les procédures d'invoquer des procédures Tcl sur l'interpréteur, car son état est partiellement supprimé. Tout ce que les procédures de trace devraient faire dans ces circonstances est de nettoyer et de libérer leurs propres structures de données internes.

BOGUES

Tcl n'effectue aucune vérification d'erreur pour empêcher les procédures de trace d'utiliser incorrectement l'interpréteur pendant les traces avec TCL_INTERP_DESTROYED défini.

Les traces de tableaux ne sont pas encore intégrées à la commande Tcl info exists, et il n'y a pas d'accès au niveau Tcl aux traces de tableaux.

    Tcl_UntraceVar

    NOM

    Tcl_UntraceVar - Supprime une trace de variable

    SYNTAXE

    #include <tcl.h>

void
Tcl_UntraceVar(
    Tcl_Interp *iPtr,
    const char *varName,
    int mask,
    Tcl_VarTraceProc *traceProc,
    ClientData clientData)

    ARGUMENTS

    iPtr (in)
    Pointeur vers l'interpréteur Tcl.
    varName (in)
    Nom de la variable à désinscire de la trace.
    mask (in)
    Masque d'accès spécifiant le type de trace à supprimer (par exemple, TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS).
    traceProc (in)
    Pointeur vers la procédure de trace à supprimer.
    clientData (in)
    Données client associées à la trace à supprimer.

    DESCRIPTION

    La procédure Tcl_UntraceVar supprime une trace de variable précédemment enregistrée à l'aide de Tcl_TraceVar ou Tcl_TraceVar2. La trace à supprimer est identifiée par le nom de la variable (varName), le masque d'accès (mask), le pointeur vers la procédure de trace (traceProc) et les données client (clientData). Tous ces arguments doivent correspondre exactement aux valeurs fournies lors de l'enregistrement de la trace.

    NOMS EN DEUX PARTIES

    Si varName fait référence à un tableau Tcl, varName peut être de la forme nomTableau(indice). Dans ce cas, la trace n'est supprimée que pour l'élément de tableau spécifié. Si seul le nom du tableau est fourni (par exemple, nomTableau), la trace est supprimée pour toutes les entrées du tableau.

    ACCÈS AUX VARIABLES PENDANT LES TRACES

    Lorsqu'une procédure de trace est appelée, elle peut accéder aux valeurs actuelles de la variable qui a déclenché la trace, ainsi qu'aux variables liées à celle-ci. Les détails spécifiques dépendent du type de trace et des fonctions Tcl utilisées pour manipuler les variables.

    TEMPORISATION DES RAPPELS

    Les procédures de trace sont appelées avant que la modification de la variable ne soit réellement effectuée (pour les traces de lecture et d'écriture) ou avant que la variable ne soit détruite (pour les traces de désaffectation). Cela permet à la procédure de trace de consulter ou de modifier la valeur avant l'opération, ou d'annuler l'opération.

    TRACES DE TABLEAUX ENTIERS

    Une trace peut être définie sur un tableau entier. Dans ce cas, la procédure de trace sera appelée chaque fois qu'un élément du tableau est lu, écrit ou désaffecté. Le nom de la variable passé à la procédure de trace sera le nom de l'élément spécifique, et les données client permettront d'identifier le tableau d'origine.

    TRACES MULTIPLES

    Il est possible d'enregistrer plusieurs traces pour la même variable (ou le même élément de tableau) avec des masques d'accès, des procédures de trace ou des données client différents. Tcl_UntraceVar supprimera uniquement la trace spécifiée. Les autres traces resteront actives.

    VALEURS DE RETOUR D'ERREUR

    Tcl_UntraceVar ne retourne aucune valeur d'erreur. Si la trace spécifiée n'existe pas, la procédure ne fait rien.

    RESTRICTIONS

    Aucune restriction spécifique n'est mentionnée.

    VARIABLES NON DÉFINIES

    Si une trace est définie sur une variable qui n'existe pas encore, la trace sera activée dès que la variable sera créée. Si la variable est désaffectée avant d'être créée, la trace de désaffectation ne sera jamais appelée.

    DRAPEAU TCL_TRACE_DESTROYED

    Si une trace est déclenchée par la destruction de la variable ou de l'interpréteur, le drapeau TCL_TRACE_DESTROYED peut être défini dans le masque.

    TCL_INTERP_DESTROYED

    Lors de la destruction de l'interpréteur, toutes les traces associées sont automatiquement supprimées.

    BOGUES

    Aucun bogues mentionné.
