ARGUMENTS

Tcl_Interp *interp (entrée)
Utilisé pour signaler les erreurs et pour rechercher un canal enregistré dans celui-ci.
const char *fileName (entrée)
Le nom d'un fichier local ou réseau.
const char *mode (entrée)
Spécifie comment le fichier doit être accédé. Peut avoir n'importe laquelle des valeurs autorisées pour l'argument mode de la commande Tcl open.
int permissions (entrée)
Indicateurs de permission de type POSIX tels que 0644. Si un nouveau fichier est créé, ces permissions seront appliquées au fichier créé.
int argc (entrée)
Le nombre d'éléments dans argv.
const char **argv (entrée)
Arguments pour la construction d'un pipeline de commandes. Ces valeurs ont la même signification que les arguments sans option de la commande Tcl exec.
int flags (entrée)
Spécifie la disposition des descripteurs stdio dans le pipeline : combinaison des bits TCL_STDIN, TCL_STDOUT, TCL_STDERR, et TCL_ENFORCE_MODE. Si TCL_STDIN est défini, l'entrée standard du premier processus enfant du pipeline est le canal du pipe, sinon elle est la même que l'entrée standard du processus appelant ; idem pour TCL_STDOUT et TCL_STDERR. Si TCL_ENFORCE_MODE n'est pas défini, alors le pipe peut rediriger les descripteurs stdio pour outrepasser les descripteurs stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis. S'il est défini, de telles redirections provoquent une erreur.
ClientData handle (entrée)
Descripteur spécifique au système d'exploitation pour les E/S vers un fichier. Pour Unix, c'est un descripteur de fichier, pour Windows, c'est un HANDLE.
int readOrWrite (entrée)
Combinaison des bits TCL_READABLE et TCL_WRITABLE pour indiquer quelles opérations sont valides sur handle.
const char *channelName (entrée)
Le nom du canal.
int *modePtr (sortie)
Pointe vers une variable entière qui recevra une combinaison des bits TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et en écriture.
const char *pattern (entrée)
Le motif à faire correspondre, passé à Tcl_StringMatch, ou NULL.
Tcl_Channel channel (entrée)
Un canal Tcl pour l'entrée ou la sortie. Doit avoir été la valeur de retour d'une procédure telle que Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (entrée/sortie)
Un pointeur vers une valeur Tcl dans laquelle stocker les caractères lus du canal.
int charsToRead (entrée)
Le nombre de caractères à lire du canal. Si l'encodage du canal est binary, cela équivaut au nombre d'octets à lire du canal.
int appendFlag (entrée)
Si non nul, les données lues du canal seront ajoutées à la valeur. Sinon, les données remplaceront le contenu existant de la valeur.
char *readBuf (sortie)
Un tampon dans lequel stocker les octets lus du canal.
int bytesToRead (entrée)
Le nombre d'octets à lire du canal. Le tampon readBuf doit être suffisamment grand pour contenir ce nombre d'octets.
Tcl_Obj *lineObjPtr (entrée/sortie)
Un pointeur vers une valeur Tcl dans laquelle stocker la ligne lue du canal. La ligne lue sera ajoutée à la valeur actuelle de la valeur.
Tcl_DString *lineRead (entrée/sortie)
Un pointeur vers une chaîne dynamique Tcl dans laquelle stocker la ligne lue du canal. Doit avoir été initialisé par l'appelant. La ligne lue sera ajoutée à toute donnée déjà présente dans la chaîne dynamique.
const char *input (entrée)
L'entrée à ajouter à un tampon de canal.
int inputLen (entrée)
Longueur de l'entrée.
int addAtEnd (entrée)
Indicateur indiquant si l'entrée doit être ajoutée à la fin ou au début du tampon du canal.
Tcl_Obj *writeObjPtr (entrée)
Un pointeur vers une valeur Tcl dont le contenu sera envoyé au canal.
const char *charBuf (entrée)
Un tampon contenant les caractères à envoyer au canal.
const char *byteBuf (entrée)
Un tampon contenant les octets à envoyer au canal.
int bytesToWrite (entrée)
Le nombre d'octets à consommer de charBuf ou byteBuf et à envoyer au canal.
Tcl_WideInt offset (entrée)
À quelle distance déplacer le point d'accès dans le canal où la prochaine opération d'entrée ou de sortie sera appliquée, mesurée en octets à partir de la position donnée par seekMode. Peut être positif ou négatif.
int seekMode (entrée)
Par rapport à quel point rechercher ; utilisé avec offset pour calculer le nouveau point d'accès pour le canal. Les valeurs légales sont SEEK_SET, SEEK_CUR, et SEEK_END.
Tcl_WideInt length (entrée)
La longueur (non négative) à laquelle tronquer le canal.
const char *optionName (entrée)
Le nom d'une option applicable à ce canal, tel que -blocking. Peut avoir n'importe laquelle des valeurs acceptées par la commande fconfigure.
Tcl_DString *optionValue (entrée)
Où stocker la valeur d'une option ou une liste de toutes les options et leurs valeurs. Doit avoir été initialisé par l'appelant.
const char *newValue (entrée)
Nouvelle valeur pour l'option donnée par optionName.

DESCRIPTION

Le mécanisme de canaux Tcl fournit un mécanisme indépendant des périphériques et indépendant de la plateforme pour effectuer des opérations d'entrée et de sortie avec tampon sur une variété de types de fichiers, de sockets et de périphériques. Le mécanisme de canaux est extensible à de nouveaux types de canaux, en fournissant un pilote de canal de bas niveau pour le nouveau type ; l'interface du pilote de canal est décrite dans l'entrée man de Tcl_CreateChannel. Le mécanisme de canaux fournit un schéma de mise en tampon calqué sur les E/S standard Unix, et il permet également les E/S non bloquantes sur les canaux.

Les procédures décrites dans cette entrée man constituent les API C de la couche générique de l'architecture des canaux. Pour une description de l'architecture des pilotes de canaux et comment implémenter des pilotes de canaux pour de nouveaux types de canaux, voir l'entrée man de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

La procédure Tcl_OpenFileChannel ouvre un fichier nommé fileName en fonction du mode et des permissions spécifiés, et renvoie un canal Tcl représentant ce fichier.

Les valeurs possibles pour mode sont les mêmes que celles autorisées pour la commande Tcl open, c'est-à-dire :

r
Ouvre le fichier pour lecture.
w
Ouvre le fichier pour écriture. Si le fichier existe déjà, son contenu est tronqué. Sinon, un nouveau fichier est créé.
a
Ouvre le fichier pour écriture. Les données sont toujours écrites à la fin du fichier.
r+
Ouvre le fichier pour lecture et écriture. Le fichier doit exister.
w+
Ouvre le fichier pour lecture et écriture. Si le fichier existe déjà, son contenu est tronqué. Sinon, un nouveau fichier est créé.
a+
Ouvre le fichier pour lecture et écriture. Toutes les écritures sont effectuées à la fin du fichier. Si le fichier n'existe pas, il est créé.

Les modes b (binaire) et t (texte) sont également pris en charge, comme dans la commande Tcl open. S'ils ne sont pas spécifiés, la valeur par défaut est le mode texte.

Les permissions sont des indicateurs de style POSIX. Si le mode spécifie la création d'un nouveau fichier, ces permissions sont utilisées pour définir les permissions du nouveau fichier (masquées par le umask du processus).

Si le fichier est ouvert avec succès, Tcl_OpenFileChannel renvoie un handle de canal Tcl. Sinon, il signale une condition d'erreur en utilisant interp et renvoie le canal NULL.

TCL_OPENCOMMANDCHANNEL

La procédure Tcl_OpenCommandChannel crée un pipeline de processus en exécutant la commande spécifiée par argv. Les E/S du pipeline peuvent être gérées par le biais du canal Tcl renvoyé. La commande est exécutée dans un sous-shell. argc est le nombre d'arguments dans argv.

Les flags spécifient la disposition des descripteurs standard (stdin, stdout, stderr) du nouveau processus. Les combinaisons possibles sont:

TCL_STDIN
Le canal du pipe est utilisé comme entrée standard du premier processus enfant.
TCL_STDOUT
Le canal du pipe est utilisé comme sortie standard du dernier processus enfant.
TCL_STDERR
Le canal du pipe est utilisé comme sortie d'erreur standard du dernier processus enfant.
TCL_ENFORCE_MODE
Si ce drapeau est défini, toute tentative de redirection des descripteurs standard des processus enfants qui diffère de celle spécifiée par les autres drapeaux provoquera une erreur. Par exemple, si TCL_STDIN est spécifié, mais que la commande elle-même tente de rediriger son entrée standard d'une autre manière, cela provoquera une erreur.

Si TCL_STDIN, TCL_STDOUT ou TCL_STDERR ne sont pas spécifiés, les descripteurs standard du processus enfant seront les mêmes que ceux du processus parent.

La procédure renvoie un canal Tcl représentant le pipeline.

TCL_MAKEFILECHANNEL

La procédure Tcl_MakeFileChannel crée un canal Tcl à partir d'un descripteur de fichier existant (par exemple, un descripteur de fichier renvoyé par la fonction open ou socket du C). handle est le descripteur de fichier, et readOrWrite indique si le descripteur de fichier est disponible pour la lecture et/ou l'écriture.

La procédure renvoie un handle de canal Tcl.

TCL_GETCHANNEL

La procédure Tcl_GetChannel renvoie un canal Tcl nommé channelName qui est actuellement enregistré dans l'interpréteur interp. Si modePtr n'est pas NULL, il pointe vers un entier qui recevra une combinaison des bits TCL_READABLE et TCL_WRITABLE indiquant si le canal est ouvert en lecture et/ou en écriture.

La procédure renvoie un handle de canal Tcl s'il est trouvé, sinon elle renvoie NULL.

TCL_GETCHANNELNAMES

La procédure Tcl_GetChannelNames renvoie une liste de tous les noms de canaux actuellement enregistrés dans l'interpréteur interp. La liste est stockée dans l'objet résultat de l'interpréteur et renvoyée sous forme de chaîne.

Si pattern n'est pas NULL, seuls les noms de canaux qui correspondent au motif spécifié (en utilisant Tcl_StringMatch) sont renvoyés.

La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

TCL_REGISTERCHANNEL

La procédure Tcl_RegisterChannel enregistre le canal donné channel dans l'interpréteur interp sous le nom du canal.

TCL_UNREGISTERCHANNEL

La procédure Tcl_UnregisterChannel désenregistre le canal donné channel de l'interpréteur interp. Le canal est ensuite fermé automatiquement.

La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

TCL_DETACHCHANNEL

La procédure Tcl_DetachChannel sépare le canal channel de l'interpréteur interp. Le canal n'est plus géré par Tcl et doit être géré manuellement par l'appelant (par exemple, fermé). Il est courant d'utiliser cette procédure pour reprendre la propriété d'un descripteur de fichier bas level après qu'il a été créé via Tcl_OpenFileChannel.

La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

TCL_ISTANDARDCHANNEL

La procédure Tcl_IsStandardChannel renvoie vrai si le canal channel est l'un des canaux d'entrée, sortie ou erreur standard, et faux sinon.

TCL_CLOSE

La procédure Tcl_Close ferme le canal channel. Toutes les écritures en attente sont vidées avant la fermeture. Si le canal a été ouvert avec Tcl_OpenFileChannel, le descripteur de fichier sous-jacent est également fermé. La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

TCL_READCHARS

La procédure Tcl_ReadChars lit jusqu'à charsToRead caractères du canal channel et les stocke dans le Tcl_Obj pointé par readObjPtr. Si appendFlag est non nul, les caractères lus sont ajoutés à la valeur existante de l'objet ; sinon, ils remplacent la valeur existante.

La procédure renvoie le nombre de caractères réellement lus. Une valeur de retour négative indique une erreur.

TCL_READ

La procédure Tcl_Read lit jusqu'à bytesToRead octets du canal channel et les stocke dans le tampon readBuf. Le tampon doit être suffisamment grand pour contenir bytesToRead octets.

La procédure renvoie le nombre d'octets réellement lus. Une valeur de retour négative indique une erreur.

TCL_GETSOBJ

La procédure Tcl_GetsObj lit des caractères du canal channel jusqu'à ce qu'un caractère de nouvelle ligne soit rencontré, ou jusqu'à la fin du fichier. La ligne lue (sans le caractère de nouvelle ligne) est stockée dans le Tcl_Obj pointé par lineObjPtr. Si le canal est en mode binaire, cette fonction se comporte de manière identique à Tcl_Read.

La procédure renvoie 1 si une ligne a été lue avec succès, 0 si la fin du fichier a été atteinte avant la lecture de toute ligne, et une valeur négative en cas d'erreur.

TCL_GETS

La procédure Tcl_Gets lit des caractères du canal channel jusqu'à ce qu'un caractère de nouvelle ligne soit rencontré, ou jusqu'à la fin du fichier. La ligne lue (sans le caractère de nouvelle ligne) est stockée dans la chaîne dynamique Tcl lineRead. Le contenu précédent de lineRead est effacé avant la lecture.

La procédure renvoie 1 si une ligne a été lue avec succès, 0 si la fin du fichier a été atteinte avant la lecture de toute ligne, et une valeur négative en cas d'erreur.

TCL_UNGETS

La procédure Tcl_Ungets ajoute la chaîne input de longueur inputLen au tampon d'entrée du canal channel. Si addAtEnd est faux, l'entrée est ajoutée au début du tampon, simulant l'insertion de données qui n'ont pas été lues. Si addAtEnd est vrai, l'entrée est ajoutée à la fin du tampon.

La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

TCL_WRITEOBJ

La procédure Tcl_WriteObj écrit le contenu du Tcl_Obj pointé par writeObjPtr sur le canal channel.

La procédure renvoie le nombre d'octets réellement écrits. Une valeur de retour négative indique une erreur.

TCL_WRITECHARS

La procédure Tcl_WriteChars écrit les caractères du tampon charBuf sur le canal channel. La procédure essaiera d'écrire bytesToWrite caractères.

La procédure renvoie le nombre d'octets réellement écrits. Une valeur de retour négative indique une erreur.

TCL_WRITE

La procédure Tcl_Write écrit les octets du tampon byteBuf sur le canal channel. La procédure essaiera d'écrire bytesToWrite octets.

La procédure renvoie le nombre d'octets réellement écrits. Une valeur de retour négative indique une erreur.

TCL_READRAW

La procédure Tcl_ReadRaw lit jusqu'à bytesToRead octets du canal channel et les stocke dans le tampon readBuf. Cette procédure ne fait aucune conversion d'encodage et lit les données brutes du canal.

La procédure renvoie le nombre d'octets réellement lus. Une valeur de retour négative indique une erreur.

TCL_WRITERAW

La procédure Tcl_WriteRaw écrit les octets du tampon byteBuf sur le canal channel. Cette procédure n'effectue aucune conversion d'encodage et écrit les données brutes sur le canal.

La procédure renvoie le nombre d'octets réellement écrits. Une valeur de retour négative indique une erreur.

TCL_EOF

La procédure Tcl_Eof renvoie vrai si la fin du fichier a été atteinte sur le canal channel, et faux sinon.

TCL_FLUSH

La procédure Tcl_Flush vide tous les tampons de sortie pour le canal channel. La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

TCL_INPUTBLOCKED

La procédure Tcl_InputBlocked renvoie vrai si une tentative de lecture sur le canal channel bloquerait l'exécution, et faux sinon. Ceci est utile pour implémenter des E/S non bloquantes.

TCL_INPUTBUFFERED

La procédure Tcl_InputBuffered renvoie le nombre d'octets attendant dans le tampon d'entrée du canal channel.

TCL_OUTPUTBUFFERED

La procédure Tcl_OutputBuffered renvoie le nombre d'octets en attente dans le tampon de sortie du canal channel.

TCL_SEEK

La procédure Tcl_Seek repositionne le point d'accès du canal channel. L'offset est donné par offset, et le point de départ est donné par seekMode. Les valeurs possibles pour seekMode sont SEEK_SET (début du fichier), SEEK_CUR (position actuelle) et SEEK_END (fin du fichier). La procédure renvoie la nouvelle position du point d'accès en octets à partir du début du fichier, ou une valeur négative en cas d'erreur.

Cette opération n'est disponible que pour les canaux qui prennent en charge la recherche (par exemple, les fichiers).

TCL_TELL

La procédure Tcl_Tell renvoie la position actuelle du point d'accès du canal channel, mesurée en octets à partir du début du fichier. La procédure renvoie une valeur négative en cas d'erreur.

Cette opération n'est disponible que pour les canaux qui prennent en charge la recherche (par exemple, les fichiers).

TCL_TRUNCATECHANNEL

La procédure Tcl_TruncateChannel tronque le canal channel à la longueur spécifiée par length. Les données après cette longueur sont supprimées. La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

Cette opération n'est disponible que pour les canaux qui prennent en charge la troncature (par exemple, les fichiers).

TCL_GETCHANNELOPTION

La procédure Tcl_GetChannelOption renvoie la valeur de l'option spécifiée par optionName pour le canal channel. La valeur est stockée dans la chaîne dynamique optionValue. La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

Les options disponibles dépendent du type de canal. Pour les canaux de fichiers, les options sont les mêmes que pour la commande fconfigure.

TCL_SETCHANNELOPTION

La procédure Tcl_SetChannelOption définit la valeur de l'option spécifiée par optionName pour le canal channel à newValue. La procédure renvoie TCL_OK en cas de succès, et TCL_ERROR en cas d'échec.

Les options disponibles dépendent du type de canal. Pour les canaux de fichiers, les options sont les mêmes que pour la commande fconfigure.

Les options courantes incluent:

-blocking
Définit si les opérations de lecture/écriture sur le canal doivent être bloquantes ou non bloquantes. Une valeur de 0 signifie non bloquant, une valeur de 1 signifie bloquant.
-buffering
Contrôle la mise en tampon du canal. Les valeurs possibles sont none, line et full.
-translation
Contrôle la traduction des fins de ligne lors de la lecture/écriture. Les valeurs possibles sont binary, cr, lf, crlf.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel ouvre un fichier spécifié par fileName et retourne une poignée de canal qui peut être utilisée pour effectuer des entrées et sorties sur le fichier. Cette API est basée sur la procédure fopen de la bibliothèque d'entrée/sortie standard Unix. La syntaxe et la signification de tous les arguments sont similaires à celles données dans la commande Tcl open lors de l'ouverture d'un fichier. Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenFileChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, si interp n'est pas NULL, Tcl_OpenFileChannel laisse un message d'erreur dans le résultat de interp après toute erreur. Depuis Tcl 8.4, l'API basée sur la valeur Tcl_FSOpenFileChannel doit être utilisée de préférence à Tcl_OpenFileChannel dans la mesure du possible.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel fournit une interface C aux fonctions des commandes exec et open. Elle crée une séquence de sous-processus spécifiés par les arguments argv et argc et retourne un canal qui peut être utilisé pour communiquer avec ces sous-processus. L'argument flags indique le type de communication qui existera avec le pipeline de commandes.

Si l'indicateur TCL_STDIN est défini, l'entrée standard du premier sous-processus sera liée au canal : écrire dans le canal fournira des données au sous-processus. Si TCL_STDIN n'est pas défini, l'entrée standard du premier sous-processus sera la même que l'entrée standard de cette application. Si TCL_STDOUT est défini, la sortie standard du dernier sous-processus peut être lue à partir du canal ; sinon, elle va vers la sortie standard de cette application. Si TCL_STDERR est défini, la sortie d'erreur standard pour tous les sous-processus est renvoyée au canal et entraîne une erreur lors de la fermeture du canal ; sinon, elle va vers la sortie d'erreur standard de cette application. Si TCL_ENFORCE_MODE n'est pas défini, alors argc et argv peuvent rediriger les descripteurs stdio pour remplacer TCL_STDIN, TCL_STDOUT et TCL_STDERR ; s'il est défini, alors c'est une erreur pour argc et argv de remplacer les canaux stdio pour lesquels TCL_STDIN, TCL_STDOUT et TCL_STDERR ont été définis.

Si une erreur se produit lors de l'ouverture du canal, Tcl_OpenCommandChannel retourne NULL et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. De plus, Tcl_OpenCommandChannel laisse un message d'erreur dans le résultat de l'interpréteur. interp ne peut pas être NULL.

Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crée un Tcl_Channel à partir d'une poignée de fichier existante et spécifique à la plateforme. Le canal nouvellement créé n'est pas enregistré dans l'interpréteur fourni ; pour l'enregistrer, utilisez Tcl_RegisterChannel, décrit ci-dessous. Si l'un des canaux standard, stdin, stdout ou stderr a été précédemment fermé, l'acte de création du nouveau canal l'assigne également en remplacement du canal standard.

TCL_GETCHANNEL

Tcl_GetChannel retourne un canal étant donné le channelName utilisé pour le créer avec Tcl_CreateChannel et un pointeur vers un interpréteur Tcl dans interp. Si un canal portant ce nom n'est pas enregistré dans cet interpréteur, la procédure retourne NULL. Si l'argument modePtr n'est pas NULL, il pointe vers une variable entière qui recevra une combinaison OU de TCL_READABLE et TCL_WRITABLE décrivant si le canal est ouvert en lecture et en écriture.

Tcl_GetChannelNames et Tcl_GetChannelNamesEx écrivent les noms des canaux enregistrés dans le résultat de l'interpréteur sous forme de liste. Tcl_GetChannelNamesEx filtrera ces noms en fonction du pattern. Si pattern est NULL, alors aucun filtrage ne sera effectué. La valeur de retour est TCL_OK si aucune erreur ne s'est produite lors de l'écriture dans le résultat, sinon c'est TCL_ERROR, et le message d'erreur est laissé dans le résultat de l'interpréteur.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel ajoute un canal à l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl exécutés dans cet interpréteur pourront faire référence au canal dans les opérations d'entrée ou de sortie en utilisant le nom donné lors de l'appel à Tcl_CreateChannel. Après cet appel, le canal devient la propriété de l'interpréteur, et l'appelant ne doit pas appeler Tcl_Close pour le canal ; le canal sera fermé automatiquement lorsqu'il sera désenregistré de l'interpréteur.

Le code exécuté en dehors de tout interpréteur Tcl peut appeler Tcl_RegisterChannel avec interp comme NULL, pour indiquer qu'il souhaite conserver une référence à ce canal. Par la suite, le canal peut être enregistré dans un interpréteur Tcl et ne sera fermé que lorsque le nombre correspondant d'appels à Tcl_UnregisterChannel aura été effectué. Cela permet au code exécuté en dehors de tout interpréteur de conserver en toute sécurité une référence à un canal également enregistré dans un interpréteur Tcl.

Cette procédure interagit avec le code qui gère les canaux standard. Si aucun canal standard n'a été initialisé avant le premier appel à Tcl_RegisterChannel, ils seront initialisés par cet appel. Voir Tcl_StandardChannels pour un traité général sur les canaux standard et le comportement de la bibliothèque Tcl à leur égard.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Si cette opération a retiré le dernier enregistrement du canal dans un interpréteur, le canal est également fermé et détruit.

Le code non associé à un interpréteur Tcl peut appeler Tcl_UnregisterChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, il sera alors fermé. Tcl_UnregisterChannel est très similaire à Tcl_DetachChannel sauf qu'elle fermera également le canal s'il n'existe plus de références.

TCL_DETACHCHANNEL

Tcl_DetachChannel retire un canal de l'ensemble des canaux accessibles dans interp. Après cet appel, les programmes Tcl ne pourront plus utiliser le nom du canal pour faire référence au canal dans cet interpréteur. Au-delà de cela, cette commande n'a aucun autre effet. Elle ne peut pas être utilisée sur les canaux standard (stdout, stderr, stdin) et retournera TCL_ERROR si elle reçoit l'un de ces canaux.

Le code non associé à un interpréteur Tcl peut appeler Tcl_DetachChannel avec interp comme NULL, pour indiquer à Tcl qu'il ne détient plus de référence à ce canal. S'il s'agit de la dernière référence au canal, contrairement à Tcl_UnregisterChannel, il ne sera pas fermé.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel teste si un canal est l'un des trois canaux standard, stdin, stdout ou stderr. Si c'est le cas, il retourne 1, sinon 0.

Aucune tentative n'est faite pour vérifier si le canal donné ou les canaux standard sont initialisés ou valides.

TCL_CLOSE

Tcl_Close détruit le canal channel, qui doit désigner un canal actuellement ouvert. Le canal ne doit pas être enregistré dans un interpréteur lors de l'appel à Tcl_Close. Les sorties mises en mémoire tampon sont vidées vers le périphérique de sortie du canal avant de détruire le canal, et toute entrée mise en mémoire tampon est supprimée. S'il s'agit d'un canal bloquant, l'appel ne retourne pas tant que toutes les données mises en mémoire tampon n'ont pas été envoyées avec succès au périphérique de sortie du canal. S'il s'agit d'un canal non bloquant et qu'il y a des sorties mises en mémoire tampon qui ne peuvent pas être écrites sans bloquer, l'appel retourne immédiatement ; les sorties sont vidées en arrière-plan et le canal sera fermé une fois que toutes les données mises en mémoire tampon auront été produites. Dans ce cas, les erreurs lors du vidage ne sont pas signalées.

Si le canal a été fermé avec succès, Tcl_Close retourne TCL_OK. Si une erreur se produit, Tcl_Close retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Si le canal est fermé de manière synchrone et qu'une erreur se produit lors de la fermeture du canal et que interp n'est pas NULL, un message d'erreur est laissé dans le résultat de l'interpréteur.

Note : il n'est pas sûr d'appeler Tcl_Close sur un canal qui a été enregistré à l'aide de Tcl_RegisterChannel ; voir la documentation de Tcl_RegisterChannel, ci-dessus, pour les détails. Si le canal a déjà été donné comme argument chan dans un appel à Tcl_RegisterChannel, vous devriez plutôt utiliser Tcl_UnregisterChannel, qui appellera en interne Tcl_Close lorsque tous les appels à Tcl_RegisterChannel auront été mis en correspondance par des appels correspondants à Tcl_UnregisterChannel.

TCL_READCHARS ET TCL_READ

Tcl_ReadChars consomme des octets du channel, convertit les octets en UTF-8 en se basant sur le codage du canal et stocke les données produites dans la représentation chaîne de readObjPtr. La valeur de retour de Tcl_ReadChars est le nombre de caractères, jusqu'à charsToRead, qui ont été stockés dans readObjPtr. Si une erreur se produit lors de la lecture, la valeur de retour est -1 et Tcl_ReadChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Définir charsToRea

d à -1 fera en sorte que la commande lise tous les caractères actuellement disponibles (sans blocage) ou tout jusqu'à l'eof (mode bloquant).

La valeur de retour peut être inférieure à la valeur à lire, indiquant que moins de données que demandé étaient disponibles. Ceci est appelé une lecture courte. En mode bloquant, cela ne peut se produire qu'à la fin du fichier. En mode sans blocage, une lecture courte peut également se produire s'il n'y a pas assez d'entrée actuellement disponible : Tcl_ReadChars retourne un nombre réduit plutôt que d'attendre plus de données.

Si le canal est en mode bloquant, une valeur de retour de zéro indique une condition de fin de fichier. Si le canal est en mode sans blocage, une valeur de retour de zéro indique soit qu'aucune entrée n'est actuellement disponible, soit une condition de fin de fichier. Utilisez Tcl_Eof et Tcl_InputBlocked pour savoir laquelle de ces conditions s'est réellement produite.

Tcl_ReadChars traduit les différentes représentations de fin de ligne en la représentation interne canonique \n selon le mode de reconnaissance de fin de ligne actuel. La reconnaissance de fin de ligne et les différents modes spécifiques à la plateforme sont décrits dans l'entrée manuelle de la commande Tcl fconfigure.

En tant qu'optimisation des performances, lors de la lecture d'un canal avec l'encodage binary, les octets ne sont pas convertis en UTF-8 lors de leur lecture. Au lieu de cela, ils sont stockés dans la représentation interne de readObjPtr en tant que valeur de tableau d'octets. La représentation sous forme de chaîne de cette valeur ne sera construite que si elle est nécessaire (par exemple, en raison d'un appel à Tcl_GetStringFromObj). De cette façon, les données orientées octets peuvent être lues depuis un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de conversion vers ou depuis UTF-8.

Tcl_Read est similaire à Tcl_ReadChars, sauf qu'il ne fait pas de conversions d'encodage, indépendamment de l'encodage du canal. Il est obsolète et existe pour assurer la compatibilité avec les extensions Tcl non internationalisées. Il consomme des octets de channel et les stocke dans readBuf, en effectuant des traductions de fin de ligne en cours de route. La valeur de retour de Tcl_Read est le nombre d'octets, jusqu'à bytesToRead, écrits dans readBuf. Le tampon produit par Tcl_Read n'est pas terminé par null. Son contenu est valide à partir de la position zéro jusqu'à la position indiquée par la valeur de retour, non comprise.

Tcl_ReadRaw est identique à Tcl_Read mais ne compense pas l'empilement. Alors que Tcl_Read (et les autres fonctions de l'API) obtient toujours ses données du canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_ReadRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer des données du canal inférieur vers la transformation.

TCL_GETSOBJ ET TCL_GETS

Tcl_GetsObj consomme des octets du channel, en convertissant les octets en UTF-8 en fonction de l'encodage du canal, jusqu'à ce qu'une ligne complète d'entrée soit vue. Si l'encodage du canal est binary, chaque octet lu du canal est traité comme un caractère Unicode individuel. Tous les caractères de la ligne, à l'exception des caractères de fin de ligne terminaux, sont ajoutés à la représentation sous forme de chaîne de lineObjPtr. Les caractères de fin de ligne sont lus et ignorés.

Si une ligne a été lue avec succès, la valeur de retour est supérieure ou égale à zéro et indique le nombre d'octets stockés dans lineObjPtr. En cas d'erreur, Tcl_GetsObj retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Tcl_GetsObj retourne également -1 si la fin du fichier est atteinte ; la procédure Tcl_Eof peut être utilisée pour distinguer une erreur d'une condition de fin de fichier.

Si le canal est en mode sans blocage, la valeur de retour peut également être -1 si aucune donnée n'était disponible ou si les données disponibles ne contenaient pas de caractère de fin de ligne. Lorsque -1 est retourné, la procédure Tcl_InputBlocked peut être appelée pour déterminer si le canal est bloqué en raison de l'indisponibilité des entrées.

Tcl_Gets est identique à Tcl_GetsObj sauf que les caractères résultants sont ajoutés à la chaîne dynamique donnée par lineRead plutôt qu'à une valeur Tcl.

TCL_UNGETS

Tcl_Ungets est utilisé pour ajouter des données à la file d'attente d'entrée d'un canal, soit à la tête, soit à la queue. Le pointeur input pointe vers les données à ajouter. La longueur de l'entrée à ajouter est donnée par inputLen. Une valeur non nulle de addAtEnd indique que les données doivent être ajoutées à la fin de la file ; sinon, elles seront ajoutées au début de la file. Si channel a un EOF "collant" défini, aucune donnée ne sera ajoutée à la file d'attente d'entrée. Tcl_Ungets retourne inputLen ou -1 en cas d'erreur.

TCL_WRITECHARS, TCL_WRITEOBJ, ET TCL_WRITE

Tcl_WriteChars accepte bytesToWrite octets de données de caractères à charBuf. Les caractères UTF-8 du tampon sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_WriteChars s'attend à ce que charBuf soit terminé par null et il sort tout jusqu'au null.

Les données mises en file d'attente pour la sortie peuvent ne pas apparaître immédiatement sur le périphérique de sortie, en raison de la mise en mémoire tampon interne. Si les données doivent apparaître immédiatement, appelez Tcl_Flush après l'appel à Tcl_WriteChars, ou définissez l'option -buffering du canal sur none. Si vous souhaitez que les données apparaissent dès qu'une ligne complète est acceptée pour la sortie, définissez l'option -buffering du canal en mode line.

La valeur de retour de Tcl_WriteChars est un compteur indiquant le nombre d'octets acceptés pour la sortie vers le canal. Il s'agit soit d'une valeur supérieure à zéro pour indiquer le succès, soit de -1 pour indiquer qu'une erreur s'est produite. En cas d'erreur, Tcl_WriteChars enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

Les caractères de nouvelle ligne dans les données de sortie sont traduits en séquences de fin de ligne spécifiques à la plateforme selon l'option -translation du canal. Ceci est fait même si le canal n'a pas d'encodage.

Tcl_WriteObj est similaire à Tcl_WriteChars sauf qu'il accepte une valeur Tcl dont le contenu sera sorti vers le canal. Les caractères UTF-8 de la représentation de chaîne de writeObjPtr sont convertis dans l'encodage du canal et mis en file d'attente pour la sortie vers channel. En tant qu'optimisation des performances, lors de l'écriture dans un canal avec l'encodage binary, les caractères UTF-8 ne sont pas convertis lors de leur écriture. Au lieu de cela, les octets dans la représentation interne de writeObjPtr sous forme de tableau d'octets sont écrits dans le canal. La représentation sous forme de tableau d'octets de la valeur sera construite si nécessaire. De cette façon, les données orientées octets peuvent être lues à partir d'un canal, manipulées en appelant Tcl_GetByteArrayFromObj et les fonctions associées, puis écrites dans un canal sans le coût de conversion vers ou depuis UTF-8.

Tcl_Write est similaire à Tcl_WriteChars sauf qu'il ne fait pas de conversions d'encodage, indépendamment de l'encodage du canal. Il est obsolète et existe pour assurer la compatibilité avec les extensions Tcl non internationalisées. Il accepte bytesToWrite octets de données à byteBuf et les met en file d'attente pour la sortie vers channel. Si bytesToWrite est négatif, Tcl_Write s'attend à ce que byteBuf soit terminé par null et il sort tout jusqu'au null.

Tcl_WriteRaw est identique à Tcl_Write mais ne compense pas l'empilement. Alors que Tcl_Write (et les autres fonctions de l'API) envoient toujours leur entrée au canal le plus haut dans la pile dont fait partie le canal fourni, Tcl_WriteRaw ne le fait pas. Ainsi, cette fonction est uniquement utilisable pour les pilotes de canaux transformationnels, c'est-à-dire les pilotes utilisés au milieu d'une pile de canaux, pour déplacer des données de la transformation vers le canal situé en dessous.

TCL_FLUSH

Tcl_Flush force la sortie de toutes les données tamponnées pour channel vers son fichier ou périphérique sous-jacent dès que possible. Si le canal est en mode bloquant, l'appel ne retourne pas tant que toutes les données tamponnées n'ont pas été envoyées au canal ou qu'une erreur ne s'est produite. L'appel retourne immédiatement si le canal est sans blocage ; il démarre une vidange en arrière-plan qui écrira les données tamponnées dans le canal éventuellement, aussi vite que le canal sera capable de les absorber.

La valeur de retour est normalement TCL_OK. En cas d'erreur, Tcl_Flush retourne TCL_ERROR et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno.

TCL_SEEK

Tcl_Seek déplace le point d'accès dans channel où les données ultérieures seront lues ou écrites. La sortie tamponnée est vidée vers le canal et l'entrée tamponnée est rejetée, avant l'opération de recherche.

Tcl_Seek retourne normalement le nouveau point d'accès. En cas d'erreur, Tcl_Seek retourne -1 et enregistre un code d'erreur POSIX qui peut être récupéré avec Tcl_GetErrno. Après une erreur, le point d'accès peut ou peut ne pas avoir été déplacé.

TCL_TELL

Tcl_Tell retourne le point d'accès actuel d'un canal. La valeur retournée est -1 si le canal ne prend pas en charge la recherche.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel tronque le fichier sous-jacent de channel à une longueur donnée de length octets. Il retourne TCL_OK si l'opération a réussi, et TCL_ERROR sinon.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption récupère, dans optionValue, la valeur d'une des options actuellement en vigueur pour un canal, ou une liste de toutes les options et leurs valeurs. L'argument channel identifie le canal pour lequel interroger une option ou récupérer toutes les options et leurs valeurs. Si optionName n'est pas NULL, il s'agit du nom de l'option à interroger ; la valeur de l'option est copiée dans la chaîne dynamique Tcl désignée par optionValue. Si optionName est NULL, la fonction stocke une liste alternée de noms d'options et de leurs valeurs dans optionValue,

en utilisant une série d'appels à Tcl_DStringAppendElement. Les diverses options préexistantes et leurs valeurs possibles sont décrites dans l'entrée du manuel de la commande Tcl fconfigure. D'autres options peuvent être ajoutées par chaque type de canal. Ces options spécifiques au type de canal sont décrites dans l'entrée du manuel de la commande Tcl qui crée un canal de ce type ; par exemple, les options supplémentaires pour les canaux basés sur TCP sont décrites dans l'entrée du manuel de la commande Tcl socket. La procédure retourne normalement TCL_OK. En cas d'erreur, elle retourne TCL_ERROR et appelle Tcl_SetErrno pour stocker un code d'erreur POSIX approprié.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption définit une nouvelle valeur newValue pour une option optionName sur le channel. La procédure retourne normalement TCL_OK. En cas d'erreur, elle retourne TCL_ERROR ; de plus, si interp n'est pas NULL, Tcl_SetChannelOption laisse un message d'erreur dans le résultat de l'interpréteur.

TCL_EOF

Tcl_Eof retourne une valeur non nulle si le channel a rencontré une fin de fichier lors de la dernière opération d'entrée.

TCL_INPUTBLOCKED

Tcl_InputBlocked retourne une valeur non nulle si le channel est en mode non bloquant et que la dernière opération d'entrée a retourné moins de données que demandé car il n'y avait pas suffisamment de données disponibles. L'appel retourne toujours zéro si le canal est en mode bloquant.

TCL_INPUTBUFFERED

Tcl_InputBuffered retourne le nombre d'octets d'entrée actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en lecture, cette fonction retourne toujours zéro.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered retourne le nombre d'octets de sortie actuellement mis en mémoire tampon dans les tampons internes d'un canal. Si le canal n'est pas ouvert en écriture, cette fonction retourne toujours zéro.

PROBLÈMES_DE_PLATEFORME

Les descripteurs retournés par Tcl_GetChannelHandle dépendent de la plateforme et du type de canal. Sur les plateformes Unix, le descripteur est toujours un descripteur de fichier Unix tel que retourné par l'appel système open. Sur les plateformes Windows, le descripteur est un HANDLE de fichier lorsque le canal a été créé avec Tcl_OpenFileChannel, Tcl_OpenCommandChannel, ou Tcl_MakeFileChannel. D'autres types de canaux peuvent retourner un type de descripteur différent sur les plateformes Windows.
