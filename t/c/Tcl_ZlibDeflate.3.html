ARGUMENTS

Tcl_Interp *interp (in)
L'interpréteur dans lequel stocker les données compressées ou décompressées résultantes. C'est également là que les messages d'erreur sont écrits. Pour Tcl_ZlibStreamInit, cela peut être NULL pour créer un flux qui n'est pas lié à une commande.
int format (in)
Quel format de données compressées utiliser. Doit être l'un des suivants : TCL_ZLIB_FORMAT_ZLIB pour les données au format zlib, TCL_ZLIB_FORMAT_GZIP pour les données au format gzip, ou TCL_ZLIB_FORMAT_RAW pour les données compressées brutes. De plus, pour la décompression uniquement, TCL_ZLIB_FORMAT_AUTO peut également être choisi, ce qui peut détecter automatiquement si les données compressées étaient au format zlib ou gzip.
Tcl_Obj *dataObj (in/out)
Une valeur de type tableau d'octets contenant les données à compresser ou décompresser, ou à laquelle les données extraites du flux sont ajoutées lorsqu'elles sont passées à Tcl_ZlibStreamGet.
int level (in)
Quel niveau de compression utiliser. Doit être un nombre de 0 à 9 ou l'un des suivants : TCL_ZLIB_COMPRESS_NONE pour aucune compression, TCL_ZLIB_COMPRESS_FAST pour une compression rapide mais inefficace, TCL_ZLIB_COMPRESS_BEST pour une compression lente mais maximale, ou TCL_ZLIB_COMPRESS_DEFAULT pour le niveau recommandé par la bibliothèque zlib.
Tcl_Obj *dictObj (in/out)
Un dictionnaire qui contient, ou qui sera mis à jour pour contenir, une description de l'en-tête gzip associé aux données compressées. Uniquement utile lorsque le paramètre format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Si NULL est passé, un en-tête par défaut sera utilisé lors de la compression et l'en-tête sera ignoré (hormis les vérifications d'intégrité) lors de la décompression. Voir la section DICTIONNAIRE DES OPTIONS GZIP pour plus de détails sur le contenu de ce dictionnaire.
unsigned int initValue (in)
La valeur initiale pour l'algorithme de somme de contrôle.
int bufferSize (in)
Une indication de la taille du tampon à utiliser pour recevoir les données. Utilisez 0 pour utiliser une estimation générique basée sur les données d'entrée.
unsigned char *bytes (in)
Un tableau d'octets sur lequel exécuter l'algorithme de somme de contrôle, ou NULL pour obtenir la valeur initiale recommandée pour l'algorithme de somme de contrôle.
int length (in)
Le nombre d'octets dans le tableau.
int mode (in)
Dans quel mode faire fonctionner le flux. Doit être soit TCL_ZLIB_STREAM_DEFLATE pour un flux de compression, soit TCL_ZLIB_STREAM_INFLATE pour un flux de décompression.
Tcl_ZlibStream *zshandlePtr (out)
Un pointeur vers une variable dans laquelle écrire le jeton abstrait du flux en cas de création réussie.
Tcl_ZlibStream zshandle (in)
Le jeton abstrait du flux sur lequel opérer.
int flush (in)
Si et comment vider le flux après y avoir écrit les données. Doit être l'une des valeurs suivantes : TCL_ZLIB_NO_FLUSH si aucun vidage n'est à effectuer, TCL_ZLIB_FLUSH si les données actuellement compressées doivent être rendues disponibles pour accès via Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si le flux doit être mis dans un état où le décompresseur peut récupérer en cas de corruption, ou TCL_ZLIB_FINALIZE pour s'assurer que le flux est terminé et que toute bande-annonce exigée par le format est écrite.
int count (in)
Le nombre maximum d'octets à obtenir du flux, ou -1 pour obtenir tous les octets restants des tampons du flux.
Tcl_Obj *compDict (in)
Une valeur de type tableau d'octets qui est le dictionnaire de compression à utiliser avec le flux. Notez qu'il ne s'agit *pas d'un dictionnaire Tcl*, et il est recommandé de ne l'utiliser qu'avec des flux dont le format est défini sur TCL_ZLIB_FORMAT_ZLIB, car les autres formats n'ont aucun mécanisme pour indiquer si un dictionnaire de compression était présent, si ce n'est échouer lors de la décompression.

DESCRIPTION

Ces fonctions constituent l'interface de la bibliothèque Tcl à la bibliothèque Zlib de Jean-loup Gailly et Mark Adler.

Tcl_ZlibDeflate et Tcl_ZlibInflate compressent et décompressent respectivement les données contenues dans l'argument dataObj, conformément aux arguments format et, pour la compression, level. Le dictionnaire de l'argument dictObj est utilisé pour transmettre des informations d'en-tête supplémentaires sur les données compressées lorsque le format de compression le prend en charge ; actuellement, le dictionnaire n'est utilisé que lorsque le paramètre format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Pour plus de détails sur le contenu du dictionnaire, voir la section DICTIONNAIRE DES OPTIONS GZIP ci-dessous. En cas de succès, les deux fonctions laissent les données compressées ou décompressées résultantes dans une valeur de type tableau d'octets qui est le résultat de l'interpréteur Tcl ; la valeur retournée est un code de résultat Tcl standard.

Tcl_ZlibAdler32 et Tcl_ZlibCRC32 calculent des sommes de contrôle sur des tableaux d'octets, retournant la somme de contrôle calculée. Les sommes de contrôle sont calculées de manière incrémentale, permettant de traiter les données bloc par bloc, mais cela nécessite que l'appelant maintienne la somme de contrôle actuelle et la passe comme paramètre initValue ; la valeur initiale à utiliser pour cela peut être obtenue en utilisant NULL pour le paramètre bytes au lieu d'un pointeur vers le tableau d'octets sur lequel calculer la somme de contrôle. Ainsi, l'utilisation typique dans le cas d'un seul bloc de données est la suivante :

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Notez que l'algorithme Adler-32 n'est pas une véritable somme de contrôle, mais plutôt un type de hachage apparenté qui fonctionne mieux sur des données longues.

FLUX ZLIB

Tcl_ZlibStreamInit crée un flux de compression ou de décompression qui est lié à une commande Tcl, conformément à ses arguments, et fournit un jeton abstrait pour le flux et renvoie un code de résultat Tcl normal ; Tcl_ZlibStreamGetCommandName renvoie le nom de cette commande étant donné le jeton du flux, ou NULL si le flux n'a pas de commande. Les flux ne sont pas conçus pour être thread-safe ; chaque flux ne devrait jamais être utilisé que depuis le thread qui l'a créé. Lors de l'utilisation de flux gzip, un dictionnaire (champs tels que donnés dans la section DICTIONNAIRE DES OPTIONS GZIP ci-dessous) peut être fourni via le paramètre dictObj qui, lors de la compression, permet de contrôler les en-têtes générés, et lors de la décompression, permet de découvrir les en-têtes existants. Notez que le dictionnaire sera écrit lors de la décompression une fois que suffisamment de données auront été lues pour avoir un en-tête complet. Cela signifie que le dictionnaire doit être une valeur non partagée dans ce cas ; une valeur vide créée avec Tcl_NewObj est suggérée.

Une fois qu'un flux a été construit, Tcl_ZlibStreamPut est utilisé pour ajouter des données au flux et Tcl_ZlibStreamGet est utilisé pour récupérer des données du flux après traitement. Les deux renvoient des codes de résultat Tcl normaux et laissent un message d'erreur dans le résultat de l'interpréteur auquel le flux est enregistré en cas d'erreur (si un tel enregistrement a été effectué). Avec Tcl_ZlibStreamPut, la valeur du tampon de données qui lui est passée ne doit pas être modifiée par la suite. Avec Tcl_ZlibStreamGet, la valeur du tampon de données qui lui est passée aura les octets de données ajoutés. Internement au flux, les données sont gardées compressées afin de minimiser le coût de l'espace tampon.

Eof renvoie une valeur booléenne indiquant si la fin des données non compressées a été atteinte.

Tcl_ZlibStreamSetCompressionDictionary est utilisé pour contrôler le dictionnaire de compression utilisé avec le flux, un dictionnaire de compression étant un tableau d'octets (tel qu'il pourrait être créé avec Tcl_NewByteArrayObj) utilisé pour initialiser le moteur de compression, au lieu de le laisser le créer au moment de la compression. La définition d'un dictionnaire de compression permet une compression plus efficace dans le cas de données qui commencent de manière régulière, bien que cela nécessite que le compresseur et le décompresseur s'accordent sur la valeur à utiliser. Les dictionnaires de compression ne sont entièrement compatibles qu'avec les données au format zlib ; avant d'envoyer des données avec Tcl_ZlibStreamPut, les dictionnaires de compression doivent être définis en premier, et lors de la décompression, ils doivent être définis lorsque Tcl_ZlibStreamGet produit une erreur avec son -errorcode défini sur ZLIB NEED_DICT ; le code sera le checksum Adler-32 (voir Tcl_ZlibAdler32) du dictionnaire de compression recherché. (Notez que ceci n'est valable que pour les flux de compression au format zlib ; les flux gzip ignorent les dictionnaires de compression car le format ne les permet pas, et les flux bruts ne produisent une erreur de données que si le dictionnaire de compression est absent ou incorrect.)

Si vous souhaitez nettoyer un flux et le réutiliser pour une nouvelle action de compression ou de décompression, Tcl_ZlibStreamReset le fera et renverra un code de résultat normal pour indiquer si cela a réussi ; si le flux est enregistré auprès d'un interpréteur, un message d'erreur sera laissé dans le résultat de l'interpréteur lorsque cette fonction renverra TCL_ERROR. Enfin, Tcl_ZlibStreamClose nettoiera le flux et supprimera la commande associée : utiliser Tcl_DeleteCommand sur la commande du flux est équivalent (lorsqu'une telle commande existe).

GZIP OPTIONS DICTIONARY

Le paramètre dictObj à Tcl_ZlibDeflate, Tcl_ZlibInflate et Tcl_ZlibStreamInit est utilisé pour passer un dictionnaire d'options qui est utilisé pour décrire l'en-tête gzip dans les données compressées. Lors de la création de données compressées, le dictionnaire est lu et lors de la décompression de données compressées, il est écrit (dans ce cas, dictObj doit faire référence à une valeur de dictionnaire non partagée).

Les champs suivants dans la valeur du dictionnaire sont compris. Tous les autres champs sont ignorés. Aucun champ n'est obligatoire lors de la création d'un flux de format gzip.

comment
Ce champ stocke le champ de commentaire de l'en-tête, s'il est présent. S'il n'est pas présent, aucun commentaire n'a été fourni (en décompression) ou sera créé (en compression).
crc
Valeur booléenne décrivant si un CRC de l'en-tête a été calculé. Notez que le programme gzip n'utilise ni ne permet un CRC dans l'en-tête.
filename
Nom du fichier qui a stocké les données non compressées. Il doit éviter tout séparateur de répertoire et doit être assaini avant utilisation en décompression avec file tail.
os
Code de type de système d'exploitation de l'en-tête (s'il n'est pas la valeur inconnue). Voir RFC 1952 pour la signification de ces codes. En compression, si cette valeur est absente, elle sera définie sur la valeur inconnue.
size
Taille des données non compressées. Ce champ est ignoré en compression ; la taille des données compressées dépend du volume de données envoyées au moteur de compression.
time
Valeur du champ de temps de l'en-tête s'il n'est pas zéro, qui est censé être le moment où le fichier nommé par le champ filename a été modifié. Utile avec clock format. En création, la valeur correcte à utiliser est celle de clock seconds ou file mtime.
type
type de données non compressées (soit binary, soit text) si connu.

PORTABILITY NOTES

Ces fonctions se comporteront gracieusement si Tcl n'est pas lié à la bibliothèque zlib.
