ARGUMENTS

Tcl_Interp *interp (entrée)
L'interpréteur dans lequel stocker les données compressées ou décompressées résultantes. C'est également là que sont écrits les éventuels messages d'erreur. Pour Tcl_ZlibStreamInit, cela peut être NULL pour créer un flux qui n'est pas lié à une commande.
int format (entrée)
Quel format de données compressées manipuler. Doit être l'un des suivants : TCL_ZLIB_FORMAT_ZLIB pour les données au format zlib, TCL_ZLIB_FORMAT_GZIP pour les données au format gzip, ou TCL_ZLIB_FORMAT_RAW pour les données compressées brutes. De plus, pour la décompression uniquement, TCL_ZLIB_FORMAT_AUTO peut également être choisi, ce qui permet de détecter automatiquement si les données compressées étaient au format zlib ou gzip.
Tcl_Obj *dataObj (entrée/sortie)
Une valeur de type tableau d'octets contenant les données à compresser ou décompresser, ou à laquelle les données extraites du flux sont ajoutées lors du passage à Tcl_ZlibStreamGet.
int level (entrée)
Quel niveau de compression utiliser. Doit être un nombre de 0 à 9 ou l'une des options suivantes : TCL_ZLIB_COMPRESS_NONE pour aucune compression, TCL_ZLIB_COMPRESS_FAST pour une compression rapide mais inefficace, TCL_ZLIB_COMPRESS_BEST pour une compression lente mais maximale, ou TCL_ZLIB_COMPRESS_DEFAULT pour le niveau recommandé par la bibliothèque zlib.
Tcl_Obj *dictObj (entrée/sortie)
Un dictionnaire qui contient, ou qui contiendra, une description de l'en-tête gzip associé aux données compressées. Uniquement utile lorsque le paramètre format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Si NULL est passé, un en-tête par défaut sera utilisé lors de la compression et l'en-tête sera ignoré (hormis les vérifications d'intégrité) lors de la décompression. Voir la section DICTIONNAIRE D'OPTIONS GZIP pour les détails sur le contenu de ce dictionnaire.
unsigned int initValue (entrée)
La valeur initiale pour l'algorithme de checksum.
int bufferSize (entrée)
Une indication de la taille du tampon à utiliser pour recevoir les données. Utilisez 0 pour utiliser une estimation générique basée sur les données d'entrée.
unsigned char *bytes (entrée)
Un tableau d'octets sur lequel exécuter l'algorithme de checksum, ou NULL pour obtenir la valeur initiale recommandée pour l'algorithme de checksum.
int length (entrée)
Le nombre d'octets dans le tableau.
int mode (entrée)
Quel mode utiliser pour le flux. Doit être soit TCL_ZLIB_STREAM_DEFLATE pour un flux de compression, soit TCL_ZLIB_STREAM_INFLATE pour un flux de décompression.
Tcl_ZlibStream *zshandlePtr (sortie)
Un pointeur vers une variable dans laquelle écrire le jeton abstrait du flux en cas de création réussie.
Tcl_ZlibStream zshandle (entrée)
Le jeton abstrait du flux à manipuler.
int flush (entrée)
Si et comment vider le flux après y avoir écrit les données. Doit être l'une des options suivantes : TCL_ZLIB_NO_FLUSH si aucun vidage n'est à effectuer, TCL_ZLIB_FLUSH si les données actuellement compressées doivent être rendues accessibles via Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si le flux doit être mis dans un état où le décompresseur peut récupérer en cas de corruption, ou TCL_ZLIB_FINALIZE pour s'assurer que le flux est terminé et que toute remorque demandée par le format est écrite.
int count (entrée)
Le nombre maximum d'octets à obtenir du flux, ou -1 pour obtenir tous les octets restants des tampons du flux.
Tcl_Obj *compDict (entrée)
Une valeur de type tableau d'octets représentant le dictionnaire de compression à utiliser avec le flux. Notez qu'il ne s'agit PAS d'un dictionnaire Tcl, et il est recommandé de ne l'utiliser qu'avec des flux dont le format est défini sur TCL_ZLIB_FORMAT_ZLIB, car les autres formats n'ont aucun mécanisme pour indiquer si un dictionnaire de compression était présent, autre que d'échouer lors de la décompression.

DESCRIPTION

Ces fonctions constituent l'interface de la bibliothèque Tcl à la bibliothèque Zlib de Jean-loup Gailly et Mark Adler.

Tcl_ZlibDeflate et Tcl_ZlibInflate compressent et décompressent respectivement les données contenues dans l'argument dataObj, conformément aux arguments format et, pour la compression, level. Le dictionnaire de l'argument dictObj est utilisé pour transmettre des informations d'en-tête supplémentaires sur les données compressées lorsque le format de compression le supporte ; actuellement, le dictionnaire n'est utilisé que lorsque le paramètre format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Pour les détails sur le contenu du dictionnaire, voir la section DICTIONNAIRE D'OPTIONS GZIP ci-dessous. En cas de succès, les deux fonctions laissent les données compressées ou décompressées résultantes dans une valeur de tableau d'octets qui est le résultat de l'interpréteur Tcl ; la valeur renvoyée est un code de résultat Tcl standard.

Tcl_ZlibAdler32 et Tcl_ZlibCRC32 calculent des checksums sur des tableaux d'octets, renvoyant le checksum calculé. Les checksums sont calculés de manière incrémentielle, permettant de traiter les données bloc par bloc, mais cela nécessite que l'appelant conserve le checksum courant et le passe comme paramètre initValue ; la valeur initiale à utiliser pour cela peut être obtenue en utilisant NULL pour le paramètre bytes au lieu d'un pointeur vers le tableau d'octets sur lequel calculer le checksum. Ainsi, l'utilisation typique dans le cas d'un seul bloc de données ressemble à ceci :

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Notez que l'algorithme Adler-32 n'est pas un vrai checksum, mais une sorte de hachage apparenté qui fonctionne mieux sur de grandes quantités de données.

FLUX ZLIB

Tcl_ZlibStreamInit crée un flux de compression ou de décompression qui est lié à une commande Tcl, conformément à ses arguments, et fournit un jeton abstrait pour le flux et renvoie un code de résultat Tcl normal ; Tcl_ZlibStreamGetCommandName renvoie le nom de cette commande étant donné le jeton du flux, ou NULL si le flux n'a pas de commande. Les flux ne sont pas conçus pour être thread-safe ; chaque flux ne devrait jamais être utilisé qu'à partir du thread qui l'a créé. Lors de la manipulation de flux gzip, un dictionnaire (champs tels que donnés dans la section DICTIONNAIRE D'OPTIONS GZIP ci-dessous) peut être fourni via le paramètre dictObj qui, lors de la compression, permet de contrôler les en-têtes générés, et lors de la décompression, permet de découvrir les en-têtes existants. Notez que le dictionnaire sera écrit lors de la décompression une fois que suffisamment de données auront été lues pour avoir un en-tête complet. Cela signifie que le dictionnaire doit être une valeur non partagée dans ce cas ; une valeur vide créée avec Tcl_NewObj est suggérée.

Une fois qu'un flux a été construit, Tcl_ZlibStreamPut est utilisé pour ajouter des données au flux et Tcl_ZlibStreamGet est utilisé pour récupérer des données du flux après traitement. Les deux renvoient des codes de résultat Tcl normaux et laissent un message d'erreur dans le résultat de l'interpréteur auquel le flux est enregistré (si une telle enregistrement a été effectué). Avec Tcl_ZlibStreamPut, le tableau de données passé à celui-ci ne doit pas être modifié par la suite. Avec Tcl_ZlibStreamGet, le tableau de données passé à celui-ci aura les octets de données ajoutés. Interne au flux, les données sont conservées compressées afin de minimiser le coût de l'espace de tampon.

Tcl_ZlibStreamChecksum renvoie le checksum calculé sur les données décompressées conformément au format, et Tcl_ZlibStreamEof renvoie 1 si le flux est terminé, sinon 0.Tcl_ZlibStreamClose ferme le flux, libère les ressources associées et renvoie un code de résultat Tcl normal.Tcl_ZlibStreamReset réinitialise le flux à son état initial, mais conserve le nom de commande et le dictionnaire associés (s'il y en a). Tcl_ZlibStreamSetCompressionDictionary attache un dictionnaire de compression spécifié à un flux existant.

DICTIONNAIRE D'OPTIONS GZIP

Lorsque le paramètre format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO, le paramètre dictObj peut être utilisé pour spécifier les options du commentaire de l'en-tête gzip, ou pour lire le commentaire de l'en-tête à partir de données existantes.

Lors de la compression, le dictionnaire peut contenir les options suivantes :

text (booléen)
Si défini sur vrai, le fichier est considéré comme un fichier texte, et donc la stratégie de compression par défaut sera utilisée. Le paramètre textuel est utilisé par le programme pour savoir qu'il peut faire des optimisations spéciales (telles que la reconnaissance de fins de lignes).
modtime (entier)
L'estampille temporelle de modification du fichier. Si elle n'est pas spécifiée, elle sera remplacée par la date et l'heure actuelles.
name (chaîne)
Le nom du fichier d'origine. Le nom sera stocké dans l'en-tête gzip. Si non spécifié, le nom sera ignoré.
comment (chaîne)
Un commentaire sur le fichier. Le commentaire sera stocké dans l'en-tête gzip. Si non spécifié, le commentaire sera ignoré.
os (entier)
Le type du système d'exploitation pour lequel le fichier a été compressé. La valeur par défaut est 0x03 (UNIX).

Lors de la décompression, les options suivantes peuvent être lues à partir du dictionnaire (le dictionnaire doit être créé avec Tcl_NewObj avant d'être passé à la fonction de décompression) :

text (booléen)
Vrai si le fichier est considéré comme un fichier texte.
modtime (entier)
L'estampille temporelle de modification du fichier.
name (chaîne)
Le nom du fichier d'origine.
comment (chaîne)
Un commentaire sur le fichier.
os (entier)
Le type du système d'exploitation pour lequel le fichier a été compressé.

EXEMPLES

La commande Tcl zlib implémente cette interface. Par exemple, pour compresser une chaîne de caractères en utilisant gzip et la décompresser :

set data {Ceci est un exemple de données.}
set compressed [zlib::compress $data -level 9 -format gzip]
set decompressed [zlib::decompress $compressed -format gzip]
puts $decompressed ;# Affiche : Ceci est un exemple de données.

La bibliothèque Zlib fournit un support pour les flux de compression/décompression. Voici un exemple d'utilisation :

set myStream [zlib::newStream deflate -level 9]
set compressed [zlib::streamPut $myStream "Données à compresser"]
set compressed [zlib::streamPut $myStream "Autres données"]
set compressed [zlib::streamFinalize $myStream]
puts $compressed

set myStream [zlib::newStream inflate]
set decompressed [zlib::streamGet $myStream $compressed]
puts $decompressed

CODE DE RETOUR

Tcl_ZlibDeflate, Tcl_ZlibInflate, Tcl_ZlibStreamInit, Tcl_ZlibStreamPut et Tcl_ZlibStreamGet renvoient TCL_OK en cas de succès, ou TCL_ERROR en cas d'erreur.

Tcl_ZlibStreamEof renvoie 1 si le flux est terminé, 0 sinon.

Tcl_ZlibStreamChecksum renvoie le checksum calculé.

Tcl_ZlibStreamClose renvoie TCL_OK en cas de succès, ou TCL_ERROR en cas d'erreur.

Tcl_ZlibStreamReset renvoie TCL_OK en cas de succès, ou TCL_ERROR en cas d'erreur.

Tcl_ZlibStreamSetCompressionDictionary renvoie TCL_OK en cas de succès, ou TCL_ERROR en cas d'erreur.

Tcl_ZlibCRC32 et Tcl_ZlibAdler32 renvoient le checksum calculé. Si un pointeur NULL est passé pour bytes, ils renvoient la valeur initiale recommandée pour le checksum.

cl_ZlibStreamEof renvoie une valeur booléenne indiquant si la fin des données décompressées a été atteinte.

Tcl_ZlibStreamSetCompressionDictionary est utilisé pour contrôler le dictionnaire de compression utilisé avec le flux. Un dictionnaire de compression est un tableau d'octets (tel que pourrait être créé avec Tcl_NewByteArrayObj) qui est utilisé pour initialiser le moteur de compression plutôt que de le laisser le créer à la volée à partir des données compressées. La définition d'un dictionnaire de compression permet une compression plus efficace lorsque le début des données est très régulier, mais cela nécessite que le compresseur et le décompresseur s'accordent sur la valeur à utiliser. Les dictionnaires de compression ne sont entièrement pris en charge que pour les données au format zlib ; lors de la compression, ils doivent être définis avant que toute donnée ne soit envoyée avec Tcl_ZlibStreamPut, et lors de la décompression, ils doivent être définis lorsque Tcl_ZlibStreamGet produit une erreur avec son -errorcode défini sur « ZLIB NEED_DICT code » ; le code sera la somme de contrôle Adler-32 (voir Tcl_ZlibAdler32) du dictionnaire de compression recherché. (Notez que ce n'est vrai que pour les flux au format zlib ; les flux gzip ignorent les dictionnaires de compression car la spécification du format ne les autorise pas, et les flux bruts produisent simplement une erreur de données si le dictionnaire de compression est manquant ou incorrect.)

Si vous souhaitez réinitialiser un flux et le réutiliser pour une nouvelle action de compression ou de décompression, Tcl_ZlibStreamReset le fera et renverra un code de résultat Tcl normal pour indiquer s'il a réussi ; si le flux est enregistré auprès d'un interpréteur, un message d'erreur sera laissé dans le résultat de l'interpréteur lorsque cette fonction renverra TCL_ERROR. Enfin, Tcl_ZlibStreamClose nettoiera le flux et supprimera la commande associée : utiliser Tcl_DeleteCommand sur la commande du flux est équivalent (lorsqu'une telle commande existe).

OPTIONS GZIP DICTIONNAIRE

Le paramètre dictObj pour Tcl_ZlibDeflate, Tcl_ZlibInflate et Tcl_ZlibStreamInit est utilisé pour passer un dictionnaire d'options décrivant l'en-tête gzip dans les données compressées. Lors de la création de données compressées, le dictionnaire est lu et lors du déballage de données compressées, le dictionnaire est écrit (auquel cas le paramètre dictObj doit faire référence à une valeur de dictionnaire non partagée).

Les champs suivants du dictionnaire sont compris. Tous les autres champs sont ignorés. Aucun champ n'est requis lors de la création d'un flux au format gzip.

comment
Contient le champ commentaire de l'en-tête, s'il est présent. S'il est absent, aucun commentaire n'a été fourni (lors de la décompression) ou ne sera créé (lors de la compression).
crc
Une valeur booléenne indiquant si une somme de contrôle CRC de l'en-tête est calculée. Notez que le programme gzip n'utilise *pas* de CRC sur l'en-tête et ne l'autorise pas.
filename
Le nom du fichier qui contenait les données décompressées. Il ne doit contenir aucun séparateur de répertoire et doit être nettoyé avant utilisation lors de la décompression avec file tail.
os
Le champ du type de système d'exploitation de l'en-tête (s'il n'est pas la valeur « unknown »). Voir RFC 1952 pour la signification de ces codes. Lors de la compression, si ce champ est absent, il sera défini sur la valeur « unknown ».
size
La taille des données décompressées. Ceci est ignoré lors de la compression ; la taille des données compressées dépend de la quantité de données fournie au moteur de compression.
time
Le champ heure de l'en-tête s'il est non nul, supposé être l'heure de modification du fichier nommé par le champ filename. Convient pour une utilisation avec clock format. Lors de la création, la valeur appropriée à utiliser est celle de clock seconds ou file mtime.
type
Le type des données décompressées (soit binary, soit text) si connu.

NOTES DE PORTABILITÉ

Ces fonctions échoueront gracieusement si Tcl n'est pas lié à la bibliothèque zlib.
