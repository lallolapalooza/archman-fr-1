Tcl_ParseCommand(3) Procédures de la bibliothèque Tcl Tcl_ParseCommand(3)

NOM

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, Tcl_ParseVarName, Tcl_ParseVar, Tcl_FreeParse, Tcl_EvalTokens, Tcl_EvalTokensStandard - analyser des scripts Tcl et des expressions

SYN。
OPSIS

#include <tcl.h>

int
Tcl_ParseCommand(interp, start, numBytes, nested, parsePtr)

int
Tcl_ParseExpr(interp, start, numBytes, parsePtr)

int
Tcl_ParseBraces(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseQuotedString(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseVarName(interp, start, numBytes, parsePtr, append)

const char *
Tcl_ParseVar(interp, start, termPtr)

Tcl_FreeParse(usedParsePtr)

Tcl_Obj *
Tcl_EvalTokens(interp, tokenPtr, numTokens)

int
Tcl_EvalTokensStandard(interp, tokenPtr, numTokens)

ARGUMENTS

Tcl_Interp *interp (sortie)
Pour les procédures autres que Tcl_FreeParse, Tcl_EvalTokens et Tcl_EvalTokensStandard, utilisé uniquement pour signaler les erreurs ; s'il est NULL, aucun message d'erreur ne sera laissé après les erreurs. Pour Tcl_EvalTokens et Tcl_EvalTokensStandard, il détermine le contexte d'évaluation du script et est également utilisé pour signaler les erreurs ; il ne peut pas être NULL.
const char *start (entrée)
Pointeur vers le premier caractère de la chaîne à analyser.
int numBytes (entrée)
Nombre d'octets dans la chaîne à analyser, sans inclure le caractère nul de fin. S'il est inférieur à 0, le script consiste en tous les caractères suivant start jusqu'au premier caractère nul.
int nested (entrée)
Une valeur non nulle signifie que le script fait partie d'une substitution de commande, donc une accolade fermante ne doit pas être traitée comme un terminateur de commande. Si elle est nulle, les accolades fermantes n'ont pas de signification particulière.
int append (entrée)
Une valeur non nulle signifie que *parsePtr contient déjà des jetons valides ; les nouveaux jetons doivent être ajoutés à ceux existants. Zéro signifie que *parsePtr est initialisé ; toute information qu'il contient est ignorée. Cet argument est généralement 0.
Tcl_Parse *parsePtr (sortie)
Pointeur vers une structure qui sera remplie d'informations sur la commande analysée, l'expression, le nom de variable, etc. Toute information précédente dans cette structure est ignorée, sauf si append est non nulle dans un appel à Tcl_ParseBraces, Tcl_ParseQuotedString ou Tcl_ParseVarName.
const char **termPtr (sortie)
S'il n'est pas NULL, il pointe vers un emplacement où Tcl_ParseBraces, Tcl_ParseQuotedString et Tcl_ParseVar stockeront un pointeur vers le caractère suivant le terminateur (l'accolade fermante, le dernier caractère du nom de variable, ou la guillemet fermant, respectivement) si l'analyse a réussi.
Tcl_Parse *usedParsePtr (entrée)
Pointeur vers la structure qui a été remplie par un appel précédent à Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseVarName, etc.

DESCRIPTION

Ces procédures analysent des commandes Tcl ou des fragments de commandes Tcl, tels que des expressions ou des références de variables. Chaque procédure prend un pointeur vers un script (ou une partie de celui-ci) et remplit des informations sur les jetons décrivant les informations analysées. Normalement, ces procédures retournent TCL_OK. Cependant, si une erreur se produit, elles retournent TCL_ERROR, laissant un message d'erreur dans le résultat de interp (si interp n'est pas NULL) et ne laissant rien dans *parsePtr.

Tcl_ParseCommand est une procédure qui analyse les scripts Tcl. Étant donné un pointeur vers un script, elle analyse la première commande du script. Si la commande a été analysée avec succès, Tcl_ParseCommand retourne TCL_OK et remplit des informations sur la structure de la commande (voir les détails ci-dessous). Si une erreur s'est produite lors de l'analyse de la commande, elle retourne TCL_ERROR, laisse un message d'erreur dans le résultat de interp et ne laisse rien dans *parsePtr.

Tcl_ParseExpr analyse les expressions Tcl. Étant donné un pointeur vers un script contenant une expression, Tcl_ParseExpr analyse l'expression. Si l'expression a été analysée avec succès, Tcl_ParseExpr retourne TCL_OK et remplit des informations sur la structure de l'expression (voir les détails ci-dessous). Si une erreur s'est produite lors de l'analyse de l'expression, elle retourne TCL_ERROR, laisse un message d'erreur dans le résultat de interp et ne laisse rien dans *parsePtr.

Tcl_ParseBraces analyse une chaîne ou un argument de commande entouré d'accolades, tel que {hello} ou {string \t with \t tabs}, à partir du début de son argument start. Le premier caractère de start doit être {. Si la chaîne entre accolades a été analysée avec succès, Tcl_ParseBraces retourne TCL_OK, remplit des informations sur la structure de la chaîne (voir les détails ci-dessous) et stocke un pointeur vers le caractère suivant le terminateur } à l'emplacement donné par *termPtr. Si une erreur se produit lors de l'analyse de la chaîne, elle retourne TCL_ERROR, laisse un message d'erreur dans le résultat de interp et ne laisse rien dans *parsePtr ou *termPtr.

Tcl_ParseQuotedString analyse une chaîne entre guillemets doubles, telle que "sum is [expr {$a+$b}]", à partir du début de son argument start. Le premier caractère de start doit être ". Si la chaîne entre guillemets doubles a été analysée avec succès, Tcl_ParseQuotedString retourne TCL_OK, remplit des informations sur la structure de la chaîne (voir les détails ci-dessous) et stocke un pointeur vers le caractère suivant le terminateur " à l'emplacement donné par *termPtr. Si une erreur se produit lors de l'analyse de la chaîne, elle retourne TCL_ERROR, laisse un message d'erreur dans le résultat de interp et ne laisse rien dans *parsePtr ou *termPtr.

Tcl_ParseVarName analyse une référence à une variable Tcl, telle que $abc ou $x([expr {$index + 1}]), à partir du début de son argument start. Le premier caractère de start doit être $. Si la variable a été analysée avec succès, Tcl_ParseVarName retourne TCL_OK et remplit des informations sur la structure du nom de variable (voir les détails ci-dessous). Si une erreur s'est produite lors de l'analyse de la commande, elle retourne TCL_ERROR, laisse un message d'erreur dans le résultat de interp (si interp n'est pas NULL) et ne laisse rien dans *parsePtr.

Tcl_ParseVar analyse une référence à une variable Tcl, telle que $abc ou $x([expr {$index + 1}]), à partir du début de son argument start. Le premier caractère de start doit être $. Si la variable a été analysée avec succès, Tcl_ParseVar retourne un pointeur vers la valeur de la variable. Si une erreur se produit lors de l'analyse, elle retourne NULL et laisse un message d'erreur dans le résultat de interp.

Les informations dans *parsePtr laissées par Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString et Tcl_ParseVarName peuvent inclure de la mémoire allouée dynamiquement. Si ces cinq procédures d'analyse retournent TCL_OK, l'appelant doit appeler Tcl_FreeParse pour libérer la mémoire dans *parsePtr. Ces procédures ignorent toute information existante dans *parsePtr (sauf si append est non nulle), donc si plusieurs appels sont effectués à l'une d'elles, Tcl_FreeParse doit être appelé une fois après chaque appel.

Tcl_EvalTokensStandard évalue une séquence de jetons analysés à partir d'une structure Tcl. Les jetons typiques consistent en tous les jetons d'un mot ou tous les jetons composant l'index d'une référence à une variable de tableau. Tcl_EvalTokensStandard effectue les substitutions demandées par les jetons et concatène les valeurs résultantes. La valeur de retour de Tcl_EvalTokensStandard est un code d'achèvement Tcl avec l'une des valeurs TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK, TCL_CONTINUE, ou une valeur entière potentielle provenant d'une extension. De plus, une valeur de résultat ou un message d'erreur est laissé dans le résultat de interp ; il peut être récupéré en utilisant Tcl_GetObjResult.

Tcl_EvalTokens diffère de Tcl_EvalTokensStandard uniquement par la convention de retour.

TCL_PARSE STRUCTURE

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString et Tcl_ParseVarName retournent des informations d'analyse dans deux structures, Tcl_Parse et Tcl_Token :

typedef struct Tcl_Parse {
    const char *commentStart;
    int commentSize;
    const char *commandStart;
    int commandSize;
    int numWords;
    Tcl_Token *tokenPtr;
    int numTokens;
    ...
} Tcl_Parse;
typedef struct Tcl_Token {
    int type;
    const char *start;
    int size;
    int numComponents;
} Tcl_Token;

Les cinq premiers champs d'une structure Tcl_Parse sont remplis uniquement par Tcl_ParseCommand. Ces champs ne sont pas utilisés par les autres procédures d'analyse.

Tcl_ParseCommand remplit une structure Tcl_Parse avec des informations décrivant une commande Tcl et tout commentaire précédant la commande. S'il y a des commentaires, commentStart pointe vers le caractère # qui commence le premier commentaire et commentSize indique le nombre d'octets dans tous les commentaires précédant la commande, y compris le caractère de nouvelle ligne terminant le dernier commentaire. Si la commande n'est pas précédée de commentaires, commentSize est 0. Tcl_ParseCommand définit également commandStart pour pointer vers le premier caractère du premier mot de la commande (en sautant tout commentaire et espace de début) et commandSize donne le nombre total d'octets dans la commande, y compris le caractère pointé par commandStart jusqu'à et en incluant le caractère de fin de nouvelle ligne, de fermeture d'accolade ou de point final. Le champ numWords donne le nombre total de mots dans la commande.

Toutes les procédures d'analyse définissent les champs restants, tokenPtr et numTokens. Le champ tokenPtr pointe vers le premier d'un tableau de structures Tcl_Token décrivant les composants de l'entité analysée. Le champ numTokens donne le nombre total de jetons présents dans le tableau. Chaque jeton contient quatre champs. Le champ type sélectionne l'un des plusieurs types de jetons décrits ci-dessous. Le champ start pointe vers le premier caractère du jeton et le champ size donne le nombre total de caractères du jeton. Certains types de jetons, tels que TCL_TOKEN_WORD et TCL_TOKEN_VARIABLE, consistent en plusieurs composants de jetons, qui suivent immédiatement le jeton parent ; le champ numComponents décrit combien il y en a. Le champ type a l'une des valeurs suivantes :

TCL_TOKEN_WORD
Ce jeton décrit généralement un mot d'une commande mais peut également décrire une chaîne entre guillemets ou entre accolades dans une expression. Le jeton décrit un composant du script qui est le résultat de la concaténation d'une séquence de sous-composants, chacun décrit par un sous-jeton séparé. Le jeton commence par le premier caractère non-espace du composant (qui peut être une guillemet double ou une accolade ouvrante) et inclut tous les caractères du composant jusqu'à, mais non inclus, l'espace, le point final, l'accolade fermante, la guillemet fermante ou le crochet fermant qui termine le composant. Le champ numComponents compte le nombre total de sous-jetons qui forment le mot, y compris les sous-jetons TCL_TOKEN_VARIABLE et TCL_TOKEN_BS.
TCL_TOKEN_SIMPLE_WORD
Ce jeton a la même signification que TCL_TOKEN_WORD, sauf que le mot est garanti de consister en un seul sous-jeton TCL_TOKEN_TEXT. Le champ numComponents est toujours 1.
TCL_TOKEN_EXPAND_WORD
Ce jeton a la même signification que TCL_TOKEN_WORD, sauf que l'analyseur de commande note que ce mot a commencé avec le préfixe d'expansion {*}, indiquant qu'après la substitution, la valeur de liste de ce mot doit être développée pour former plusieurs arguments lors de l'évaluation de la commande. Ce type de jeton ne peut être créé que par Tcl_ParseCommand.
TCL_TOKEN_TEXT
Le jeton décrit une plage de texte littéral qui fait partie d'un mot. Le champ numComponents est toujours 0.
TCL_TOKEN_BS
Le jeton décrit une séquence de guillemets inversés telle que \n ou \0xA3. Le champ numComponents est toujours 0.
TCL_TOKEN_COMMAND
Le jeton décrit une commande dont le résultat doit être substitué dans le mot. Le jeton inclut les accolades entourant la commande. Le champ numComponents est toujours 0 (la commande imbriquée n'est pas analysée ; utilisez Tcl_ParseCommand récursivement si vous voulez voir ses jetons).
TCL_TOKEN_VARIABLE
Le jeton décrit une substitution de variable, y compris le $, le nom de la variable et l'index de tableau (le cas échéant) jusqu'à la parenthèse fermante qui termine l'index. Ce jeton est suivi d'un ou plusieurs jetons supplémentaires qui décrivent le nom de la variable et l'index du tableau. Si numComponents est 1, la variable est scalaire et le jeton suivant est un TCL_TOKEN_TEXT donnant le nom de la variable. Si numComponents est supérieur à 1, la variable est un tableau : le premier sous-jeton est un TCL_TOKEN_TEXT donnant le nom du tableau et les sous-jetons restants sont des TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND et TCL_TOKEN_VARIABLE qui doivent être concaténés pour produire l'index du tableau. Le champ numComponents inclut les sous-jetons imbriqués qui font partie des jetons TCL_TOKEN_VARIABLE dans l'index du tableau.
TCL_TOKEN_SUB_EXPR
Le jeton décrit une sous-expression d'une expression (ou toute l'expression). Une sous-expression peut consister en une valeur telle qu'un littéral entier, une substitution de variable ou une sous-expression entre parenthèses ; elle peut également consister en un opérateur et ses opérandes. Le jeton commence par le premier caractère non-espace de la sous-expression jusqu'à, mais non inclus, l'espace, l'accolade ouvrante, la parenthèse fermante ou l'accolade fermante qui termine la sous-expression. Ce jeton est suivi d'un ou plusieurs jetons supplémentaires décrivant la sous-expression. Si le premier sous-jeton après le jeton TCL_TOKEN_SUB_EXPR est un jeton TCL_TOKEN_OPERATOR, la sous-expression consiste en un opérateur et ses opérandes. Si l'opérateur n'a pas d'opérandes, la sous-expression consiste uniquement en le jeton TCL_TOKEN_OPERATOR. Chaque opérande est décrit par un jeton TCL_TOKEN_SUB_EXPR. Sinon, la sous-expression est une valeur décrite par l'un des types de jetons TCL_TOKEN_WORD, TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, TCL_TOKEN_VARIABLE ou TCL_TOKEN_SUB_EXPR. Le champ numComponents compte le nombre total de sous-jetons formant la sous-expression ; cela inclut les sous-jetons de tout TCL_TOKEN_SUB_EXPR imbriqué.
TCL_TOKEN_OPERATOR
Le jeton décrit un opérateur d'une expression tel que && ou hypot. Un jeton TCL_TOKEN_OPERATOR est toujours précédé d'un jeton TCL_TOKEN_SUB_EXPR décrivant l'opérateur et ses opérandes ; le champ numComponents du jeton TCL_TOKEN_SUB_EXPR peut être utilisé pour déterminer le nombre d'opérandes. Un opérateur binaire tel que * est suivi de deux jetons TCL_TOKEN_SUB_EXPR décrivant ses opérandes. Un opérateur unaire tel que - est suivi d'un seul jeton TCL_TOKEN_SUB_EXPR décrivant son opérande. Si l'opérateur est une fonction mathématique telle que log10, le jeton TCL_TOKEN_OPERATOR donnera son nom et les jetons TCL_TOKEN_SUB_EXPR suivants décriront ses opérandes ; s'il n'y a pas d'opérandes (comme avec rand), il n'y a pas de jetons TCL_TOKEN_SUB_EXPR suivants. Il existe un opérateur ternaire, ?, qui apparaît dans les expressions if-then-else comme x?y:z ; dans ce cas, le jeton ? TCL_TOKEN_OPERATOR est suivi de trois jetons TCL_TOKEN_SUB_EXPR pour les opérandes x, y et z. Le champ numComponents du jeton TCL_TOKEN_OPERATOR est toujours 0.

Après le retour de Tcl_ParseCommand, le premier jeton pointé par le champ tokenPtr de la structure Tcl_Parse est toujours de type TCL_TOKEN_WORD, TCL_TOKEN_SIMPLE_WORD ou TCL_TOKEN_EXPAND_WORD. Il est suivi par les sous-jetons qui doivent être concaténés pour produire la valeur de ce mot. Le jeton suivant est le mot TCL_TOKEN_WORD, TCL_TOKEN_SIMPLE_WORD ou TCL_TOKEN_EXPAND_WORD pour le deuxième mot, suivi de ses sous-jetons, et ainsi de suite jusqu'à ce que tous les numWords aient été comptés.

Après le retour de Tcl_ParseExpr, le premier jeton pointé par le champ tokenPtr de la structure Tcl_Parse est toujours de type TCL_TOKEN_SUB_EXPR. Il est suivi des sous-jetons qui doivent être évalués pour produire la valeur de l'expression. Seules les informations de jeton dans la structure Tcl_Parse sont modifiées : les champs commentStart, commentSize, commandStart et commandSize ne sont pas modifiés par Tcl_ParseExpr.

Après le retour de Tcl_ParseBraces, le tableau de jetons pointé par le champ tokenPtr de la structure Tcl_Parse contiendra un seul jeton TCL_TOKEN_TEXT si la chaîne entre accolades ne contient aucune séquence de guillemets inversés. Si la chaîne contient des séquences de guillemets inversés, le tableau de jetons contiendra un ou plusieurs sous-jetons TCL_TOKEN_TEXT ou TCL_TOKEN_BS qui doivent être concaténés pour produire la valeur de la chaîne. Si la chaîne entre accolades était seulement {} (c'est-à-dire que la chaîne était vide), le seul sous-jeton TCL_TOKEN_TEXT aura un champ size de valeur 0 ; cela garantit qu'au moins un jeton apparaît pour décrire la chaîne entre accolades. Seules les informations de jeton dans la structure Tcl_Parse sont modifiées : les champs commentStart, commentSize, commandStart et commandSize ne sont pas modifiés par Tcl_ParseExpr.

NOM

TCL_PARSE_STRUCTURE

SYNOPIS

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, Tcl_ParseVarName

ARGUMENTS

start, end, tokenPtr, size, commentStart, commentSize, commandStart, commandSize

DESCRIPTION

La structure Tcl_Parse contient les champs suivants :

Le champ commentSize n'est pas modifié par Tcl_ParseBraces.

Après le retour de Tcl_ParseQuotedString, le tableau de jetons pointé par le champ tokenPtr de la structure Tcl_Parse dépend du contenu de la chaîne citée. Il sera composé d'un ou plusieurs sous-jetons TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND et TCL_TOKEN_VARIABLE. Le tableau contient toujours au moins un jeton ; par exemple, si l'argument start est vide, le tableau retourné consiste en un unique jeton TCL_TOKEN_TEXT avec un champ size de zéro. Seules les informations de jeton dans la structure Tcl_Parse sont modifiées : les champs commentStart, commentSize, commandStart et commandSize ne sont pas modifiés.

Après le retour de Tcl_ParseVarName, le premier jeton pointé par le champ tokenPtr de la structure Tcl_Parse a toujours le type TCL_TOKEN_VARIABLE. Il est suivi des sous-jetons qui composent le nom de la variable comme décrit ci-dessus. La longueur totale du nom de la variable est contenue dans le champ size du premier jeton. Comme dans Tcl_ParseExpr, seules les informations de jeton dans la structure Tcl_Parse sont modifiées par Tcl_ParseVarName : les champs commentStart, commentSize, commandStart et commandSize ne sont pas modifiés.

Tous les pointeurs de caractères dans les structures Tcl_Parse et Tcl_Token font référence à des caractères dans l'argument start passé à Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString et Tcl_ParseVarName.

Il y a des champs supplémentaires dans la structure Tcl_Parse après le champ numTokens, mais ceux-ci sont réservés à l'usage privé de Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString et Tcl_ParseVarName ; ils ne doivent pas être référencés par du code extérieur à ces procédures.
