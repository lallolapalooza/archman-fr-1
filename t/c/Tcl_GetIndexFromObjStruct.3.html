Tcl_GetIndexFromObj(3) Procédures de bibliothèque Tcl Tcl_GetIndexFromObj(3)

NOM

Tcl_GetIndexFromObj, Tcl_GetIndexFromObjStruct - recherche une chaîne dans une table de mots-clés

SYNTAXE

#include <tcl.h>

int
Tcl_GetIndexFromObj(interp, objPtr, tablePtr, msg, flags,
indexPtr)

int
Tcl_GetIndexFromObjStruct(interp, objPtr, structTablePtr, offset,
                          msg, flags, indexPtr)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur à utiliser pour la signalisation d'erreurs ; si NULL, aucun message n'est fourni en cas d'erreur.
Tcl_Obj *objPtr (in/out)
La valeur sous forme de chaîne de cette valeur est utilisée pour rechercher dans tablePtr. La représentation interne est modifiée pour contenir l'indice de l'entrée de table correspondante.
const char *const *tablePtr (in)
Un tableau de chaînes terminées par un caractère nul. La fin du tableau est marquée par un pointeur de chaîne NULL. Notez que des références à tablePtr peuvent être conservées dans la représentation interne de objPtr, cela doit donc représenter l'adresse d'un tableau alloué statiquement.
const void *structTablePtr (in)
Un tableau de type arbitraire, généralement d'un type struct. Le premier membre de la structure doit être une chaîne terminée par un caractère nul. La taille de la structure est donnée par offset. Notez que des références à structTablePtr peuvent être conservées dans la représentation interne de objPtr, cela doit donc représenter l'adresse d'un tableau de structures alloué statiquement.
int offset (in)
Le décalage à ajouter à structTablePtr pour accéder à l'entrée suivante. La fin du tableau est marquée par un pointeur de chaîne NULL.
const char *msg (in)
Chaîne terminée par un caractère nul décrivant ce qui est recherché, tel que option. Cette chaîne est incluse dans les messages d'erreur.
int flags (in)
Combinaison OR-ée de bits fournissant des informations supplémentaires pour l'opération. Le seul bit actuellement défini est TCL_EXACT.
int *indexPtr (out)
L'indice de la chaîne dans tablePtr qui correspond à la valeur de objPtr est renvoyé ici.

DESCRIPTION

Ces procédures offrent un moyen efficace de rechercher des mots-clés, des noms de commutation, des noms d'options et des éléments similaires où la valeur littérale d'une valeur Tcl doit être choisie parmi un ensemble prédéfini. Tcl_GetIndexFromObj compare objPtr avec chacune des chaînes de tablePtr pour trouver une correspondance. Une correspondance se produit si la valeur de la chaîne de objPtr est identique à l'une des chaînes de tablePtr, ou si elle est une abréviation unique et non vide pour exactement une des chaînes de tablePtr et que le drapeau TCL_EXACT n'a pas été spécifié ; dans les deux cas, l'indice de l'entrée correspondante est stocké à *indexPtr et TCL_OK est renvoyé.

En l'absence d'entrée correspondante, TCL_ERROR est renvoyé et un message d'erreur est laissé dans le résultat de interp si interp n'est pas NULL. Msg est inclus dans le message d'erreur pour indiquer ce qui était recherché. Par exemple, si msg est option, le message d'erreur aura la forme “mauvaise option “firt” : doit être first, second, ou third”.

Si Tcl_GetIndexFromObj s'exécute avec succès, elle modifie la représentation interne de objPtr pour contenir l'adresse de la table et l'indice de l'entrée correspondante. Si Tcl_GetIndexFromObj est invoquée à nouveau avec les mêmes arguments objPtr et tablePtr (par exemple, lors d'une réinvocation d'une commande Tcl), elle renvoie immédiatement l'indice correspondant sans avoir à refaire l'opération de recherche. Notez : Tcl_GetIndexFromObj suppose que les entrées de tablePtr sont statiques : elles ne doivent pas changer entre les invocations. Si la valeur de objPtr est la chaîne vide, Tcl_GetIndexFromObj la traitera comme une valeur non correspondante et renverra TCL_ERROR.

Tcl_GetIndexFromObjStruct fonctionne comme Tcl_GetIndexFromObj, sauf qu'au lieu de traiter tablePtr comme un tableau de pointeurs de chaînes, elle le traite comme un pointeur vers la première chaîne dans une série de chaînes qui ont offset octets entre elles (c'est-à-dire qu'il y a un pointeur vers le premier tableau de caractères à tablePtr, un pointeur vers le deuxième tableau de caractères à tablePtr + offset octets, etc.) Ceci est particulièrement utile lors du traitement de choses comme Tk_ConfigurationSpec, dont les clés de chaîne se trouvent au même endroit dans chacun de plusieurs éléments de tableau.
