Tcl_Access(3) Procédures de bibliothèque Tcl Tcl_Access(3)

NOM

Tcl_Access, Tcl_Stat - vérifier les autorisations de fichier et d'autres attributs

SYNTAXE

#include <tcl.h>

int
Tcl_Access(path, mode)

int
Tcl_Stat(path, statPtr)

ARGUMENTS

const char *path (in)
Nom natif du fichier dont les attributs doivent être vérifiés.
int mode (in)
Masque composé d'une ou plusieurs des valeurs suivantes : R_OK, W_OK, X_OK et F_OK. R_OK, W_OK et X_OK demandent de vérifier si le fichier existe et possède les autorisations de lecture, d'écriture et d'exécution, respectivement. F_OK demande simplement de vérifier l'existence du fichier.
struct stat *statPtr (out)
La structure qui contient le résultat.

DESCRIPTION

Depuis Tcl 8.4, les API basées sur les objets Tcl_FSAccess et Tcl_FSStat doivent être utilisées de préférence à Tcl_Access et Tcl_Stat, chaque fois que possible. Ces fonctions prennent également en charge la couche de système de fichiers virtuel de Tcl, ce que celles-ci ne font pas.

FONCTIONS OBSOLÈTES

Il y a deux raisons d'appeler Tcl_Access et Tcl_Stat plutôt que d'appeler directement les fonctions de niveau système access et stat. Premièrement, l'implémentation sous Windows des deux fonctions corrige certains bugs dans les appels de niveau système. Deuxièmement, Tcl_Access et Tcl_Stat (ainsi que Tcl_OpenFileChannelProc) s'accrochent à une liste chaînée de fonctions. Cela permet la possibilité de rediriger l'accès aux fichiers vers des supports ou des méthodes d'accès alternatifs.

Tcl_Access vérifie si le processus serait autorisé à lire, écrire ou tester l'existence du fichier (ou d'un autre objet du système de fichiers) dont le nom est path. Si path est un lien symbolique sur Unix, les autorisations du fichier auquel ce lien symbolique fait référence sont testées.

En cas de succès (toutes les autorisations demandées accordées), zéro est retourné. En cas d'erreur (au moins un bit dans mode demandait une autorisation qui est refusée, ou une autre erreur s'est produite), -1 est retourné.

Tcl_Stat remplit la structure stat statPtr avec des informations sur le fichier spécifié. Vous n'avez besoin d'aucun droit d'accès au fichier pour obtenir ces informations, mais vous avez besoin de droits de recherche sur tous les répertoires nommés dans le chemin menant au fichier. La structure stat inclut des informations concernant le périphérique, l'inode (toujours 0 sous Windows), le mode de privilège, le nombre de liens (toujours 1 sous Windows), l'ID utilisateur (toujours 0 sous Windows), l'ID de groupe (toujours 0 sous Windows), rdev (identique au périphérique sous Windows), la taille, l'heure du dernier accès, l'heure de la dernière modification et l'heure de création.

Si path existe, Tcl_Stat retourne 0 et la structure stat est remplie de données. Sinon, -1 est retourné, et aucune information de stat n'est fournie.
