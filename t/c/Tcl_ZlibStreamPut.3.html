ARGUMENTS

Tcl_Interp *interp (in)
L'interpréteur pour stocker les données compressées ou décompressées résultantes. C'est également là que les messages d'erreur sont écrits. Pour Tcl_ZlibStreamInit, cela peut être NULL pour créer un flux non lié à une commande.
int format (in)
Quel format de données compressées utiliser. Doit être l'un des suivants : TCL_ZLIB_FORMAT_ZLIB pour les données compressées au format zlib, TCL_ZLIB_FORMAT_GZIP pour les données compressées au format gzip, ou TCL_ZLIB_FORMAT_RAW pour les données compressées au format brut. De plus, pour la compression uniquement, TCL_ZLIB_FORMAT_AUTO peut également être choisi, qui peut détecter automatiquement si les données compressées étaient au format zlib ou gzip.
Tcl_Obj *dataObj (in/out)
Une valeur de type tableau d'octets contenant les données à compresser ou décompresser, ou auxquelles les données extraites du flux sont ajoutées lors de l'appel à Tcl_ZlibStreamGet.
int level (in)
Quel niveau de compression utiliser. Doit être un nombre de 0 à 9 ou l'un des suivants : TCL_ZLIB_COMPRESS_NONE pour aucune compression, TCL_ZLIB_COMPRESS_FAST pour une compression rapide mais inefficace, TCL_ZLIB_COMPRESS_BEST pour une compression lente mais maximale, ou TCL_ZLIB_COMPRESS_DEFAULT pour le niveau recommandé par la bibliothèque zlib.
Tcl_Obj *dictObj (in/out)
Un dictionnaire qui contient, ou sera mis à jour pour contenir, une description de l'en-tête gzip associé aux données compressées. Utile uniquement lorsque le format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Si NULL est passé, un en-tête par défaut sera utilisé lors de la compression et l'en-tête sera ignoré (sauf pour la vérification de l'intégrité) lors de la décompression. Voir la section DICTIONNAIRE DES OPTIONS GZIP pour les détails sur le contenu du dictionnaire.
unsigned int initValue (in)
Valeur initiale pour l'algorithme de somme de contrôle.
int bufferSize (in)
Une estimation de la taille du tampon à utiliser pour recevoir les données. Utilisez 0 pour une estimation basée sur les données d'entrée.
unsigned char *bytes (in)
Un tableau d'octets sur lequel appliquer l'algorithme de somme de contrôle, ou NULL pour obtenir la valeur initiale recommandée pour l'algorithme de somme de contrôle.
int length (in)
Le nombre d'octets dans le tableau.
int mode (in)
Dans quel mode le flux doit opérer. Doit être TCL_ZLIB_STREAM_DEFLATE pour un flux de compression ou TCL_ZLIB_STREAM_INFLATE pour un flux de décompression.
Tcl_ZlibStream *zshandlePtr (out)
Un pointeur vers une variable dans laquelle le jeton abstrait pour le flux sera écrit après sa création.
Tcl_ZlibStream zshandle (in)
Le jeton abstrait du flux sur lequel opérer.
int flush (in)
Comment vider le flux après y avoir écrit des données. Doit être l'un des éléments suivants : TCL_ZLIB_NO_FLUSH si aucune vidange n'est effectuée, TCL_ZLIB_FLUSH si les données compressées actuelles doivent être disponibles pour être récupérées via Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si le flux doit être mis dans un état où le décompresseur peut récupérer après une corruption, ou TCL_ZLIB_FINALIZE pour s'assurer que le flux est terminé et que toute terminaison requise par le format est écrite.
int count (in)
Le nombre maximum d'octets à obtenir du flux, ou -1 pour obtenir tous les octets restants des tampons du flux.
Tcl_Obj *compDict (in)
Une valeur de tableau d'octets représentant le dictionnaire de compression à utiliser avec le flux. Notez qu'il ne s'agit pas d'un dictionnaire Tcl, et il est recommandé de ne l'utiliser qu'avec des flux créés avec son format défini sur TCL_ZLIB_FORMAT_ZLIB car les autres formats n'ont pas de mécanisme pour indiquer si un dictionnaire de compression était présent, sauf en échouant lors de la décompression.

DESCRIPTION

Ces fonctions fournissent l'interface de la bibliothèque Tcl à la bibliothèque Zlib de Jean-loup Gailly et Mark Adler.

Tcl_ZlibDeflate et Tcl_ZlibInflate respectivement compressent et décompressent les données contenues dans l'argument dataObj, selon l'argument format et, pour la compression, level. Le dictionnaire dans l'argument dictObj est utilisé pour transmettre des informations supplémentaires sur les données compressées lorsque le format de compression le prend en charge ; actuellement, le dictionnaire n'est utilisé que lorsque l'argument format est TCL_ZLIB_FORMAT_GZIP ou TCL_ZLIB_FORMAT_AUTO. Pour plus de détails sur le contenu du dictionnaire, voir la section DICTIONNAIRE DES OPTIONS GZIP. Après succès, les deux fonctions laissent les données compressées ou décompressées dans une valeur de tableau d'octets qui est le résultat de l'interpréteur Tcl ; la valeur retournée est un code de résultat Tcl standard.

Tcl_ZlibAdler32 et Tcl_ZlibCRC32 calculent des sommes de contrôle sur des tableaux d'octets, retournant la somme calculée. Les sommes de contrôle sont calculées de manière incrémentale, permettant de traiter les données bloc par bloc, mais cela nécessite de conserver la valeur actuelle de la somme et de la passer comme paramètre initValue de l'appel ; la valeur initiale à utiliser peut être obtenue en utilisant NULL pour le paramètre bytes au lieu d'un pointeur vers le tableau d'octets pour calculer la somme. Ainsi, l'utilisation typique dans le cas d'un seul bloc de données est la suivante :

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Note : l'algorithme Adler-32 n'est pas une somme de contrôle réelle, mais une variété de hachage qui fonctionne mieux avec des données plus longues.

STREAMS ZLIB

Tcl_ZlibStreamInit crée un flux de compression ou de décompression lié à une commande Tcl, selon ses arguments, et fournit un jeton abstrait pour le flux et retourne un code de résultat normal ; Tcl_ZlibStreamGetCommandName retourne le nom de cette commande étant donné le jeton du flux, ou NULL si le flux n'a pas de commande. Les flux ne sont pas conçus pour être thread-safe ; chaque flux ne doit être utilisé que dans le thread qui l'a créé. Lors de l'utilisation de flux gzip, un dictionnaire (champs comme dans la section DICTIONNAIRE DES OPTIONS GZIP) peut être passé via le paramètre dictObj qui permet de contrôler les en-têtes générés lors de la compression et de découvrir les en-têtes existants lors de la décompression. Notez que le dictionnaire sera mis à jour lors de la décompression une fois que suffisamment de données auront été lues pour avoir un en-tête complet. Cela signifie que le dictionnaire doit être une valeur non partagée dans ce cas ; il est suggéré d'utiliser une valeur vide créée avec Tcl_NewObj.

Une fois le flux construit, Tcl_ZlibStreamPut est utilisé pour ajouter des données au flux et Tcl_ZlibStreamGet est utilisé pour obtenir des données du flux après traitement. Tous deux retournent des codes de résultat Tcl normaux et laissent un message d'erreur dans le résultat de l'interpréteur avec lequel le flux est enregistré en cas d'erreur (si un tel enregistrement a été effectué). Avec Tcl_ZlibStreamPut, la valeur du tampon de données qui lui est passée ne doit pas être modifiée par la suite. Avec Tcl_ZlibStreamGet, la valeur du tampon de données qui lui est passée aura les octets de données ajoutés. En interne dans le flux, les données sont conservées compressées pour minimiser le coût de l'espace tampon.

Tcl_ZlibStreamPut(3) - Tcl

NAME

Tcl_ZlibStreamPut, Tcl_ZlibStreamGet, Tcl_ZlibStreamEof, Tcl_ZlibStreamSetCompressionDictionary, Tcl_ZlibStreamReset, Tcl_ZlibStreamClose - manage Tcl zlib streams

SYNOPSIS

#include <tcl.h>

int
Tcl_ZlibStreamPut(zStreamPtr, in, inLen, out, outLen);
int
Tcl_ZlibStreamGet(zStreamPtr, out, outLen, in, inLen);
int
Tcl_ZlibStreamEof(zStreamPtr);
int
Tcl_ZlibStreamSetCompressionDictionary(zStreamPtr, dictObj);
int
Tcl_ZlibStreamReset(zStreamPtr);
int
Tcl_ZlibStreamClose(zStreamPtr);

ARGUMENTS

Tcl_Interp *interp (in)–
Tcl interpreter to use for error reporting.
Tcl_ZlibStream *zStreamPtr (in)–
Pointer to the zlib stream structure.
const unsigned char *in (in)–
Input buffer.
int inLen (in)–
Length of input buffer.
unsigned char *out (out)–
Output buffer.
int outLen (out)–
Maximum length of output buffer.
Tcl_Obj *dictObj (in)–
A Tcl object holding compression dictionary data.

DESCRIPTION

These functions provide a low-level interface to Tcl's zlib compression and decompression streams. The zStreamPtr is a pointer to a Tcl_ZlibStream structure obtained from a call to Tcl_ZlibStreamInit.

Tcl_ZlibStreamPut is used to feed data into the stream for compression. The data is taken from the buffer pointed to by in and placed into the stream. Some or all of this data may be compressed and written to the buffer pointed to by out. The number of bytes written to the output buffer is returned. If the number of bytes written is less than outLen, then the caller should try again to write more data, possibly after flushing any remaining compressed data from the stream using Tcl_ZlibStreamGet.

Tcl_ZlibStreamGet is used to retrieve compressed data from the stream. On decompression, this call retrieves decompressed data. The data is placed into the buffer pointed to by out. The number of bytes written to the output buffer is returned. If the number of bytes written is less than outLen, then the caller should try again to write more data, possibly after feeding more compressed data into the stream using Tcl_ZlibStreamPut. If the call returns an error, the error code will be set in the interp's result.

Tcl_ZlibStreamEof returns a boolean value indicating whether the end of the uncompressed data has been reached.

Tcl_ZlibStreamSetCompressionDictionary is used to control the compression dictionary used with the stream, a compression dictionary being an array of bytes (such as might be created with Tcl_NewByteArrayObj) that is used to initialize the compression engine rather than leaving it to create it on the fly from the data being compressed. Setting a compression dictionary allows for more efficient compression in the case where the start of the data is highly regular, but it does require both the compressor and the decompressor to agreee on the value to use. Compression dictionaries are only fully supported for zlib-format data; on compression, they must be set before any data is sent in with Tcl_ZlibStreamPut, and on decompression they should be set when Tcl_ZlibStreamGet produces an error with its -errorcode set to “ZLIB NEED_DICT code”; the code will be the Adler-32 checksum (see Tcl_ZlibAdler32) of the compression dictionary sought. (Note that this is only true for zlib-format streams; gzip streams ignore compression dictionaries as the format specification doesn't permit them, and raw streams just produce a data error if the compression dictionary is missing or incorrect.)

If you wish to clear a stream and reuse it for a new compression or decompression action, Tcl_ZlibStreamReset will do this and return a normal Tcl result code to indicate whether it was successful; if the stream is registered with an interpreter, an error message will be left in the interpreter result when this function returns TCL_ERROR. Finally, Tcl_ZlibStreamClose will clean up the stream and delete the associated command: using Tcl_DeleteCommand on the stream's command is equivalent (when such a command exists).

GZIP OPTIONS DICTIONARY

The dictObj parameter to Tcl_ZlibDeflate, Tcl_ZlibInflate and Tcl_ZlibStreamInit is used to pass a dictionary of options about that is used to describe the gzip header in the compressed data. When creating compressed data, the dictionary is read and when unpacking compressed data the dictionary is written (in which case the dictObj parameter must refer to an unshared dictionary value).

The following fields in the dictionary value are understood. All other fields are ignored. No field is required when creating a gzip-format stream.

comment
This holds the comment field of the header, if present. If absent, no comment was supplied (on decompression) or will be created (on compression).
crc
A boolean value describing whether a CRC of the header is computed. Note that the gzip program does not use or allow a CRC on the header.
filename
The name of the file that held the uncompressed data. This should not contain any directory separators, and should be sanitized before use on decompression with file tail.
os
The operating system type code field from the header (if not the “unknown” value). See RFC 1952 for the meaning of these codes. On compression, if this is absent then the field will be set to the “unknown” value.
size
The size of the uncompressed data. This is ignored on compression; the size of the data compressed depends on how much data is supplied to the compression engine.
time
The time field from the header if non-zero, expected to be the time that the file named by the filename field was modified. Suitable for use with clock format. On creation, the right value to use is that from clock seconds or file mtime.
type
The type of the uncompressed data (either binary or text) if known.

PORTABILITY NOTES

These functions will fail gracefully if Tcl is not linked with the zlib library.
