Tcl_RegistrarObjTipo(3) Procédures de la bibliothèque Tcl Tcl_RegistrarObjTipo(3)

NOM

Tcl_RegistrarObjTipo, Tcl_GetObjTipo, Tcl_AppendAllObjTipos, Tcl_ConvertirALoTipo - manipuler les types de valeurs Tcl

SYNOPSIS

#include <tcl.h>

Tcl_RegistrarObjTipo(typePtr)

const Tcl_ObjTipo *
Tcl_GetObjTipo(typeNom)

int
Tcl_AppendAllObjTipos(interprete, objPtr)

int
Tcl_ConvertirALoTipo(interprete, objPtr, typePtr)

ARGUMENTS

const Tcl_ObjTipo * typePtr (en)
Pointe vers la structure décrivant les informations sur le type de valeur Tcl. Ce stockage doit toujours exister, typiquement par un stockage alloué statiquement.
const char * typeNom (en)
Le nom d'un type de valeur Tcl que Tcl_GetObjTipo doit rechercher.
Tcl_Interp interprete (en)
Interpréteur à utiliser pour le rapport d'erreurs.
Tcl_Obj objPtr (en)
Pour Tcl_AppendAllObjTipos, ceci pointe vers la valeur à laquelle le nom de chaque type de valeur est ajouté en tant qu'élément de liste. Pour Tcl_ConvertirALoTipo, ceci pointe vers une valeur qui doit avoir été le résultat d'un appel préalable à Tcl_NewObj.

DESCRIPTION

Les procédures de cette page de manuel gèrent les types de valeurs Tcl (parfois appelés types d'objets ou Tcl_ObjTipo pour des raisons historiques). Elles sont utilisées pour enregistrer de nouveaux types de valeurs, rechercher des types et forcer des conversions d'un type à un autre.

Tcl_RegistrarObjTipo enregistre un nouveau type de valeur Tcl dans la table de tous les types de valeurs que Tcl_GetObjTipo peut rechercher par nom. Il existe également d'autres types de valeurs pris en charge par Tcl, que Tcl n'enregistre pas. Les extensions peuvent également être libres d'enregistrer les types de valeurs qu'elles créent. L'argument typePtr pointe vers une structure Tcl_ObjTipo décrivant le nouveau type, étant donné son nom et fournissant des pointeurs vers quatre procédures qui implémentent le type. Si le type contient déjà un type portant le même nom que dans typePtr, il est remplacé par le nouveau type. La structure Tcl_ObjTipo est décrite dans la section suivante LA STRUCTURE TCL_OBJTYPE.

Tcl_GetObjTipo renvoie un pointeur vers le type de valeur enregistré sous le nom typeNom. Il renvoie NULL s'il n'y a pas de type enregistré portant ce nom.

Tcl_AppendAllObjTipos ajoute le nom de chaque type de valeur enregistré en tant qu'élément de liste à la valeur Tcl référencée par objPtr. La valeur renvoyée est TCL_OK sauf s'il y a eu une erreur lors de la conversion de objPtr en une valeur de liste ; dans ce cas, TCL_ERROR est renvoyé.

Tcl_ConvertirALoTipo convertit une valeur d'un type à un autre si possible. Elle crée une représentation interne appropriée pour objPtr selon le type cible typePtr et définit son membre typePtr comme déterminé par la routine typePtr->setFromAnyProc. Toute représentation interne de objPtr de son ancien type est libérée. Si une erreur se produit pendant la conversion, elle renvoie TCL_ERROR et laisse un message d'erreur dans la valeur résultat pour interprete, à moins que interprete ne soit NULL. Sinon, elle renvoie TCL_OK. Passer un interprete nul permet d'utiliser cette procédure comme test pour déterminer si la conversion peut être effectuée (et a effectivement été effectuée).

Dans de nombreux cas, la routine typePtr->setFromAnyProc définira objPtr->typePtr sur la valeur de l'argument typePtr, mais cela n'est plus garanti. La routine setFromAnyProc est libre de définir la représentation interne de objPtr pour utiliser une autre structure connexe de Tcl_ObjTipo, si elle le souhaite.

LA STRUCTURE TCL_OBJTYPE

Les auteurs d'extensions peuvent définir de nouveaux types de valeurs en définissant quatre procédures et en initialisant une structure Tcl_ObjTipo pour décrire le type. Les auteurs d'extensions peuvent également passer un pointeur vers leur structure Tcl_ObjTipo à Tcl_RegistrarObjTipo s'ils veulent permettre à d'autres auteurs d'extensions de rechercher leur Tcl_ObjTipo par nom via Tcl_GetObjTipo. La structure Tcl_ObjTipo est définie comme suit :

typedef struct Tcl_ObjTipo {
    const char *nom;
    Tcl_FreeInternalRepProc *freeIntRepProc;
    Tcl_DupInternalRepProc *dupIntRepProc;
    Tcl_UpdateStringProc *updateStringProc;
    Tcl_SetFromAnyProc *setFromAnyProc;
} Tcl_ObjTipo;

LE CHAMP NOM

Le membre nom décrit le nom du type, par exemple, int. Lorsqu'un type est enregistré, c'est le nom utilisé par les appelants de Tcl_GetObjTipo pour rechercher le type. Pour les types non enregistrés, le membre nom est principalement utile pour le débogage. Les quatre membres restants sont des pointeurs vers des procédures appelées par le code général de valeur de Tcl :

LE CHAMP SETFROMANYPROC

Le membre setFromAnyProc contient l'adresse d'une fonction appelée pour créer une représentation interne valide à partir de la représentation chaîne d'une valeur.

typedef int Tcl_SetFromAnyProc(
        Tcl_Interp *interprete,
        Tcl_Obj *objPtr);

Si une représentation interne ne peut pas être créée à partir de la chaîne, elle renvoie TCL_ERROR et place un message décrivant l'erreur dans la valeur résultat pour interprete, sauf si interprete est NULL. Si setFromAnyProc réussit, elle stocke la nouvelle représentation interne, définit le membre typePtr de objPtr pour pointer vers la structure Tcl_ObjTipo correspondant à la nouvelle représentation interne, et renvoie TCL_OK. Avant de définir la nouvelle représentation interne, le setFromAnyProc doit libérer toute représentation interne du type ancien de objPtr ; il le fait en appelant la procédure freeIntRepProc de l'ancien type s'il n'est pas NULL.

À titre d'exemple, le setFromAnyProc du type de liste prédéfini de Tcl obtient une représentation mise à jour de objPtr en appelant Tcl_GetStringFromObj. Il analyse la chaîne pour vérifier qu'elle est dans un format de liste valide et obtient chaque valeur d'élément dans la liste, et, si cela réussit, stocke les éléments de la liste dans la représentation interne de objPtr et définit le membre typePtr de objPtr pour pointer vers la structure de type de liste de Tcl_ObjTipo.

Vous ne devez pas libérer la représentation interne de l'ancien type de objPtr, sauf si vous remplacez cette représentation ou réinitialisez le membre typePtr à NULL.

Le membre setFromAnyProc peut être défini à NULL, si les routines utilisant la représentation interne n'ont pas besoin de dériver cette représentation interne à partir d'une valeur chaîne arbitraire. Cependant, dans ce cas, passer un pointeur vers votre type à Tcl_ConvertirALoTipo provoquera une erreur, donc pour éviter ce cas, le type ne doit pas être enregistré.

LE CHAMP UPDATESTRINGPROC

Le membre updateStringProc contient l'adresse d'une fonction appelée pour créer une représentation chaîne valide à partir de la représentation interne d'une valeur.

typedef void Tcl_UpdateStringProc(
        Tcl_Obj *objPtr);

Le membre bytes de objPtr est toujours NULL lorsqu'il est appelé. Il doit toujours définir bytes à non NULL avant de retourner. Nous exigeons que le tableau d'octets de la représentation chaîne ait un zéro après le dernier octet, à la position length, et n'ait aucun octet nul avant cela ; cela permet de traiter les représentations chaîne comme des chaînes terminées par un zéro C normales. Ces contraintes sont facilement satisfaites en utilisant le codage interne de Tcl pour la représentation chaîne, de la même manière que l'on ferait pour d'autres routines Tcl qui acceptent des valeurs chaîne comme arguments. La mémoire du tableau d'octets doit être réservée dans le tas via Tcl_Alloc ou ckalloc. Remarque : les updateStringProc doivent réserver suffisamment de mémoire pour les octets de la chaîne et l'octet nul de terminaison.

Le updateStringProc du type double prédéfini de Tcl, par exemple, appelle Tcl_PrintDouble pour écrire dans un tampon de taille TCL_DOUBLE_SPACE, puis réserve et copie la représentation chaîne dans un espace suffisant pour la stocker. Un pointeur vers cet espace réservé est stocké dans le membre bytes de objPtr.

Le membre updateStringProc peut être défini à NULL, si les routines utilisant la représentation interne sont écrites de telle sorte que la représentation chaîne ne soit jamais invalidée. L'échec de la validation de la représentation chaîne ne doit pas... (suite dans le texte original).

LE CHAMP DUPINTREPPROC

Le membre dupIntRepProc contient l'adresse d'une fonction appelée lors de la copie de la représentation interne d'une valeur vers une autre.

typedef void Tcl_DupInternalRepProc(
        Tcl_Obj *srcPtr,
        Tcl_Obj *dupPtr);

La représentation interne de dupPtr est faite pour être une copie de la représentation interne de srcPtr. Avant l'appel, la représentation interne de srcPtr est valide et celle de dupPtr ne l'est pas. Le type de valeur de srcPtr détermine ce que signifie copier sa représentation interne.

Par exemple, le dupIntRepProc pour le type entier de Tcl copie simplement un entier. Le dupIntRepProc du type liste des listes intégrées utilise un schéma plus sophistiqué pour continuer à partager le stockage autant que possible.

LE CHAMP FREEINTREPPROC

Le membre freeIntRepProc contient l'adresse d'une fonction qui est appelée lors de la libération d'une valeur.

typedef void Tcl_FreeInternalRepProc(
        Tcl_Obj *objPtr);

La fonction freeIntRepProc peut libérer le stockage pour la représentation interne de la valeur et effectuer d'autres tâches spécifiques au type lors de la libération d'une valeur.

Par exemple, le freeIntRepProc du type liste respectera le schéma de partage de stockage établi par le dupIntRepProc pour ne libérer le stockage que lorsque la dernière valeur partageant ce stockage est libérée.

Le freeIntRepProc peut être défini à NULL pour indiquer que la représentation interne n'a pas besoin d'être libérée. L'implémentation de freeIntRepProc ne doit pas accéder au membre bytes de la valeur, car Tcl utilise ses propres usages internes du champ bytes lors de la suppression de la valeur. Les tâches définies pour le freeIntRepProc n'ont pas besoin de consulter le membre bytes.
