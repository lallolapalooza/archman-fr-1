TPMLIB_SetProfile(3) TPMLIB_SetProfile(3)

NOM

TPMLIB_SetProfile - Définir un profil pour un TPM 2

BIBLIOTHÈQUE

Bibliothèque TPM (libtpms, -ltpms)

SYNOPSIS

#include <libtpms/tpm_types.h>

#include <libtpms/tpm_library.h>

#include <libtpms/tpm_error.h>

TPM_RESULT TPMLIB_SetProfile(const char *profile);

DESCRIPTION

TPMLIB_SetProfile() est utilisé pour appliquer l'un des profils fournis par libtpms à un TPM 2 lors de son premier démarrage. TPMLIB_SetProfile() doit être appelé après TPMLIB_ChooseTPMVersion() et avant TPMLIB_MainInit(). Un profil ne peut être appliqué qu'à un TPM 2 et échouera toujours pour un TPM 1.2.

Une fois qu'un profil a été défini, il sera utilisé par le TPM 2 à partir de ce moment-là et le profil sera conservé avec l'état du TPM 2 si l'état du TPM 2 a été écrit en utilisant la fonction de rappel enregistrée avec TPMLIB_RegisterCallbacks(). Les tentatives ultérieures de définir un profil différent pour la même instance de TPM 2 en utilisant cet appel API n'auront aucun effet.

Libtpms v0.10 et versions ultérieures prennent en charge plusieurs profils intégrés. Le profil 'null' assure la compatibilité descendante avec libtpms v0.9 et n'active que les algorithmes et commandes disponibles dans cette version de libtpms. Le profil par défaut active toutes les commandes et tous les algorithmes actuellement disponibles. Aucun de ces profils ne permet de modifications par l'utilisateur. Le profil 'custom' est le seul que l'utilisateur peut modifier et où l'utilisateur peut désactiver toutes les commandes et/ou algorithmes qui peuvent être désactivés.

Si un pointeur NULL est fourni comme profil, le profil 'null' sera utilisé et seules les commandes et algorithmes de libtpms v0.9 seront activés. L'état d'une telle instance de TPM 2 sera lisible par la version actuelle de libtpms ainsi que par les versions ultérieures de libtpms et permettra de rétrograder libtpms vers la version 0.9 à partir d'une version ultérieure.

Les profils avec le préfixe 'default' activent autant d'algorithmes et de commandes que possible. Le profil 'default-v1', introduit avec libtpms v0.10, permet de fonctionner avec libtpms v0.10 et versions ultérieures, mais ne permettra pas de rétrograder vers des versions antérieures de libtpms, telles que v0.9.

Un profil est une carte JSON au format chaîne de caractères. Il doit contenir le champ 'Name' avec le nom d'un profil connu. Il peut contenir un champ 'Algorithms' qui contient une liste d'algorithmes (verbes) séparés par des virgules à activer ou le champ 'Commands' qui contient une liste de plages de codes de commande séparés par des virgules à activer.

Voici des exemples de profils TPM 2 :

{"Name":"default-v1"}
{
 "Name":"custom",
 "Algorithms":"rsa,rsa-min-size=1024,tdes-min-size=128,hmac,aes,\
               aes-min-size=128,mgf1,keyedhash,xor,sha256,sha384,\
               sha512,null,rsassa,rsaes,rsapss,oaep,ecdsa,ecdh,ecdaa,\
               sm2,ecschnorr,ecmqv,kdf1-sp800-56a,kdf2,kdf1-sp800-108,\
               ecc,ecc-min-size=192,ecc-nist,ecc-nb,symcipher,camellia,\
               camellia-min-size=128,cmac,ctr,ofb,cbc,cfb,ecb",
 "StateFormatLevel":2
}

Le premier profil sélectionne le profil par défaut actuel ainsi que toutes les commandes et tous les algorithmes disponibles. Le second profil sélectionne le profil custom mais restreint l'ensemble des algorithmes fournis par le TPM 2 à ceux qui sont listés. Comme 'sha1' et 'tdes' sont absents de la liste, cela désactive ces algorithmes. Notez que le profil custom est le seul profil qui autorise des personnalisations des Algorithmes, Commandes et Attributs activés (non présentés ici).

Seul un sous-ensemble des algorithmes implémentés peut être désactivé. Pour déterminer la liste des algorithmes qui peuvent être désactivés, utilisez la liste des algorithmes renvoyée par TPMLIB_GetInfo(TPMLIB_INFO_RUNTIME_ALGORITHMS) dans le champ 'CanBeDisabled'. De même, seul un sous-ensemble des commandes implémentées peut être désactivé et TPMLIB_GetInfo(TPMLIB_INFO_RUNTIME_COMMANDS) peut être utilisé pour déterminer la liste des commandes 'CanBeDisabled'. Aucun attribut n'est activé par défaut, ils peuvent donc tous être désactivés. Pour voir quels attributs sont implémentés et peuvent être activés, utilisez TPMLIB_GetInfo(TPMLIB_INFO_RUNTIME_ATTRIBUTES).

Comme il est possible de désactiver des algorithmes obligatoires pour le TPM 2 Client PC, on peut créer une instance de TPM 2 qui provoquera l'échec des applications. Par conséquent, il est nécessaire de sélectionner soigneusement les algorithmes à désactiver en suivant les exigences des applications qui seront utilisées. En même temps, le choix des commandes activées est important afin que les algorithmes activés puissent effectivement être utilisés avec l'ensemble des commandes activées et que les applications ne tombent pas en panne de manière inattendue en raison de commandes désactivées. Par conséquent, la détermination de la liste des algorithmes et des commandes à activer et désactiver est laissée à l'utilisateur.

StateFormatLevel

Le champ StateFormatLevel existe dans chaque profil transporté par l'état d'un TPM 2. Le StateFormatLevel est un entier qui est incrémenté chaque fois que de nouvelles commandes ou de nouveaux algorithmes TPM 2 sont activés pour les profils. L'effet de ce paramètre est qu'un profil avec StateFormatLevel 'n' ne sera pas accepté par une version de libtpms qui n'implémente pas au moins StateFormatLevel 'n'. Cela empêche les applications qui pourraient avoir utilisé de nouveaux algorithmes ou commandes activés de tomber en panne parce qu'elles essaient de les utiliser à nouveau avec un TPM 2 d'une version de libtpms qui ne les prend pas en charge.

Lorsque ce qui précède est appliqué à un environnement de machine virtuelle, cela signifie que la migration de l'état d'un TPM 2 n'est possible que vers une version de libtpms qui implémente au moins le même StateFormatLevel. Par conséquent, il faut faire attention au profil choisi afin que le StateFormatLevel du profil ne devienne pas un obstacle à la migration de l'état du TPM entre différentes versions de libtpms. Cela signifie à son tour que dans un environnement où existent des versions plus anciennes de libtpms, qui peuvent être une cible de migration, le profil supporté par la plus ancienne version de libtpms devrait être choisi. Si libtpms v0.9 existe, il devrait s'agir du profil 'null', pour libtpms v0.10, il peut s'agir du profil 'default-v1'.

La liste suivante décrit la signification des StateFormatLevels :

1 : (depuis v0.10)
Ce StateFormatLevel est réservé au profil null. Seuls les algorithmes et commandes supportés par libtpms v0.9 sont activés. Pour rester compatible avec le format d'état de libtpms v0.9, le profil null ne sera pas écrit dans le cadre de l'état.
2 : (depuis v0.10)
Ce StateFormatLevel a permis l'écriture du profil dans le cadre de l'état.
3 : (depuis v0.10)
Ce StateFormatLevel a activé les commandes TPM 2 ECC_Encrypt (0x199) et ECC_Decrypt (0x19a).
4 : (depuis v0.10)
Ce StateFormatLevel :
  • a activé Camellia-192 et AES-192.
  • a activé la définition du drapeau d'attribut de session interne du TPM 2 isNameHashDefined qui a été ajouté ; il peut légèrement modifier le comportement des sessions lorsqu'elles sont, par exemple, utilisées par le profil default-v1 par rapport au profil null (libtpms v0.9).
5 : (depuis v0.10)
Ce StateFormatLevel a activé les commandes TPM 2 PolicyCapability (0x19b) et PolicyParameters (0x19c).
6 : (depuis v0.10)
Ce StateFormatLevel a apporté des modifications internes au code de mise en forme et de déformalisation d'un OBJET. Seuls les OBJETs de clé RSA ont leur exposant privé mis en forme et la hiérarchie est également toujours mise en forme maintenant. Les OBJETs de clé RSA peuvent être plus grands de 4 octets tandis que les autres sont plus petits maintenant.
7 : (depuis v0.10)
Ce StateFormatLevel a activé les attributs de profil suivants :
  • no-unpadded-encryption
  • no-sha1-signing
  • no-sha1-verification
  • no-sha1-hmac-creation
  • no-sha1-hmac-verification
  • no-sha1-hmac
  • fips-host
  • drbg-continous-test
  • pct
  • no-ecc-key-derivation

Un utilisateur peut spécifier le StateFormatLevel lors de l'utilisation du profil custom. Dans ce cas, le StateFormatLevel donné sert de StateFormatLevel maximum que les algorithmes et commandes donnés peuvent nécessiter (par exemple, '2' ne permettrait pas d'activer la commande ECC_Encrypt, qui nécessite '3') ou permet d'activer des tailles de clé, telles que AES-192, lorsque par exemple StateFormatLevel '4' est donné. Si StateFormatLevel '3' est donné, alors AES-192 ne sera pas activé.

Attributs

Les attributs décrits ci-dessous sont implémentés par le module TPM 2.

no-unpadded-encryption
Ceci désactive l'encodage non rembourré, qui est utilisé pour les clés symétriques.
no-sha1-signing
Ceci désactive la création de signatures SHA-1.
no-sha1-verification
Ceci désactive la vérification de signatures SHA-1.
no-sha1-hmac-creation
Ceci désactive la création de HMAC SHA-1.
no-sha1-hmac-verification
Ceci désactive la vérification de HMAC SHA-1.
no-sha1-hmac
Ceci désactive toutes les opérations HMAC SHA-1.
fips-host
Ce profil assure que les exigences FIPS pour les hôtes sont remplies.
drbg-continous-test
Ce profil permet de définir le drapeau 'drbg-continous-test'. Lorsque ce drapeau est défini, le générateur de nombres aléatoires TPM 2 continuera à générer de nouveaux nombres aléatoires en permanence et ne reviendra jamais à l'état précédent.
pct
Ce profil active les commandes TPM 2 avec l'identifiant 0x00000132.
no-ecc-key-derivation
Ce profil désactive la dérivation de clé ECC.

Ceci n'est qu'une partie des attributs qui peuvent être définis.

VALEUR DE RETOUR

En cas de succès, TPM_SUCCESS est renvoyé. Sinon, un code d'erreur TPM est renvoyé.

VOIR AUSSI

TPMLIB_ChooseTPMVersion(3), TPMLIB_MainInit(3), TPMLIB_GetInfo(3).

TPMLIB_SetProfile(3) — libtpms

NOM

TPMLIB_SetProfile - Configurer le profil TPM.

BIBLIOTHÈQUE

libtpms

SYNOPSIS

#include <libtpms/tpm_library.h>
TPM_RESULT
TPMLIB_SetProfile(const char *profile_name);

DESCRIPTION

La fonction TPMLIB_SetProfile configure le profil TPM. Le profil est un ensemble d'attributs qui définissent comment le TPM doit se comporter. Les profils sont généralement spécifiés dans des fichiers de configuration ou sur la ligne de commande. Le profil par défaut est utilisé si aucun profil n'est spécifié.

Niveau de format d'état

Le profil peut inclure la clé StateFormatLevel qui est un entier.

0
Désactive la sérialisation d'état.
1
Active la sérialisation d'état avec des structures C simples.
2
Active la sérialisation d'état avec des structures JSON.

Attributs

Un profil peut avoir la clé Attributes, similaire à Algorithms ou Commands. La liste suivante est une liste de verbes pris en charge :

no-unpadded-encryption: (depuis v0.10)
•
Empêche le chiffrement et le déchiffrement RSA sans remplissage (brut)
no-sha1-signing: (depuis v0.10)
•
Empêche la génération de signatures avec les algorithmes SHA1 et RSA ou ECC
no-sha1-verification: (depuis v0.10)
•
Empêche la vérification de signatures avec un digest SHA1 et les algorithmes RSA ou ECC
no-sha1-hmac-creation: (depuis v0.10)
•
Empêche la création de HMAC avec SHA1
no-sha1-hmac-verification: (depuis v0.10)
•
Empêche la vérification de HMAC avec SHA1
no-sha1-hmac: (depuis v0.10)
•
Empêche la création et la vérification de HMAC avec SHA1
fips-host: (depuis v0.10)
  • Empêche le chiffrement et le déchiffrement RSA sans remplissage (brut)
  • Empêche la génération de signatures avec les algorithmes SHA1 et RSA ou ECC
  • Empêche la vérification de signatures avec un digest SHA1 et les algorithmes RSA ou ECC

En ajoutant ces verbes à Attributes, un TPM 2 peut s'exécuter sur un hôte FIPS activé où la bibliothèque OpenSSL peut limiter les algorithmes de chiffrement, comme indiqué ci-dessus (référence : RHEL 9.4+, mais varie selon la distribution). Note : l'utilisation de ce verbe ne rend pas une instance TPM 2 conforme FIPS-140. Vous pouvez également consulter la section sur le 'Mode FIPS sur l'hôte'.

drbg-continous-test: (depuis v0.10)
•
Active le test continu du DRBG
pct: (depuis v0.10)
•
Active le test de cohérence partielle (pct) pour les clés RSA et EC
no-ecc-key-derivation: (depuis v0.10)
•
Empêche la dérivation de clés ECC

Mode FIPS sur l'hôte

Si le mode FIPS est activé sur un hôte (référence : RHEL 9.4+) alors la bibliothèque OpenSSL ne sera pas en mesure d'utiliser certains algorithmes. Dans ce cas, la liste suivante de verbes doit être omise d'un profil pour éviter les échecs de test ou la désactivation du mode FIPS sur l'instance OpenSSL.

  • camellia, camellia-min-size
  • tdes, tdes-min-size
  • rsaes
  • ecc-nist-p192
  • ecc-bn, ecc-bn-p256, ecc-bn-p638
  • ecc-sm2-p256

Un profil doit inclure les verbes suivants pour les tailles de clés minimales :

  • rsa-min-size=2048
  • ecc-min-size=224

ERREURS

TPM_SUCCESS
La fonction s'est terminée avec succès.
TPM_FAIL
Une erreur s'est produite. Cela peut être dû à un profil JSON mal formé, à un champ manquant dans le profil JSON, à un verbe JSON inconnu ou à une erreur de mémoire. Le fichier journal peut indiquer la raison de l'erreur.

Un TPM 1.2 ne peut pas avoir de profil appliqué et répondra toujours avec ce code d'erreur.

Pour une liste complète des codes d'erreur TPM, veuillez consulter le fichier d'inclusion libtpms/tpm_error.h

EXEMPLE

#include <stdio.h>
#include <libtpms/tpm_types.h>
#include <libtpms/tpm_library.h>
#include <libtpms/tpm_error.h>
int main(void) {
    TPM_RESULT res;
    unsigned char *respbuffer = NULL;
    uint32_t resp_size = 0;
    uint32_t respbufsize = 0;
    unsigned char *command;
    uint32_t command_size;
    [...]
    if (TPMLIB_ChooseTPMVersion(TPMLIB_TPM_VERSION_2) != TPM_SUCCESS) {
        fprintf(stderr, "Impossible de choisir TPM 2.\n");
        return 1;
    }
    if (TPMLIB_SetProfile(NULL) != TPM_SUCCESS) {
        fprintf(stderr, "Impossible de définir le profil.\n");
        return 1;
    }
    if (TPMLIB_MainInit() != TPM_SUCCESS) {
        fprintf(stderr, "Impossible d'initialiser le TPM.\n");
        return 1;
    }
    [...]
    /* construire la commande TPM */
    [...]
    res = TPMLIB_Process(&respbuffer, &resp_size,
                         &respbufsize,
                         command, command_size);
    [...]
    TPMLIB_Terminate();
    return 0;
}
