Paquet: libtpms

TPMLIB_RegisterCallbacks(3) TPMLIB_RegisterCallbacks(3)

NOM

TPMLIB_RegisterCallbacks - Enregistrer des fonctions de rappel pour implémenter un comportement personnalisé de certaines fonctions

BIBLIOTHÈQUE

TPM library (libtpms, -ltpms)

SYNTAXE

#include <libtpms/tpm_types.h>

#include <libtpms/tpm_library.h>

#include <libtpms/tpm_error.h>

TPM_RESULT TPMLIB_RegisterCallbacks(struct tpmlibrary_callbacks *callbacks);

DESCRIPTION

La fonction TPMLIB_RegisterCallbacks() permet d'enregistrer plusieurs fonctions de rappel avec libtpms, ce qui permet à l'utilisateur d'implémenter un comportement personnalisé de plusieurs fonctions internes à la bibliothèque. Cette fonctionnalité sera généralement utilisée si le comportement des fonctions internes fournies n'est pas celui requis. Un exemple serait que libtpms écrive toutes les données dans des fichiers avec certains noms. Si, cependant, les données doivent être écrites dans un type de stockage spécial, l'utilisateur enregistrera des fonctions de rappel avec la bibliothèque qui seront appelées lorsque le TPM doit lire, écrire ou supprimer des données du stockage, et l'utilisateur pourra alors implémenter un comportement personnalisé dans ces fonctions.

Ce qui suit montre la structure de données utilisée pour enregistrer les fonctions de rappel.

struct libtpms_callbacks {  
        int sizeOfStruct;
        TPM_RESULT (*tpm_nvram_init)(void);
        TPM_RESULT (*tpm_nvram_loaddata)(unsigned char **data,
                                         uint32_t *length,
                                         uint32_t tpm_number,
                                         const char *name);
        TPM_RESULT (*tpm_nvram_storedata)(const unsigned char *data,
                                          uint32_t length,
                                          uint32_t tpm_number,
                                          const char *name);
        TPM_RESULT (*tpm_nvram_deletename)(uint32_t tpm_number,
                                           const char *name,
                                           TPM_BOOL mustExist);
        TPM_RESULT (*tpm_io_init)(void);
        TPM_RESULT (*tpm_io_getlocality)(TPM_MODIFIER_INDICATOR *localityModifer,
                                         uint32_t tpm_number);
        TPM_RESULT (*tpm_io_getphysicalpresence)(TPM_BOOL *physicalPresence,
                                                 uint32_t tpm_number);
};

Actuellement, 7 fonctions de rappel sont prises en charge. Si un pointeur de fonction de rappel dans la structure ci-dessus est défini sur NULL, l'implémentation interne par défaut de cette fonction sera utilisée.

Si l'une des fonctions de rappel du groupe tpm_nvram ou tpm_io est définie, alors toutes les fonctions de rappel du groupe respectif doivent être implémentées.

tpm_nvram_init
Cette fonction est appelée avant toute opération sur le stockage persistant. Elle permet à l'utilisateur d'initialiser l'accès au stockage persistant.

En cas de succès, cette fonction doit retourner TPM_SUCCESS, un code d'échec sinon.

L'implémentation par défaut exige que la variable d'environnement TPM_PATH soit définie et pointe vers un répertoire où l'état du TPM peut être écrit. Si la variable n'est pas définie, elle retournera TPM_FAIL et l'initialisation du TPM dans TPMLIB_MainInit() échouera.

tpm_nvram_loaddata
Cette fonction est appelée lorsque le TPM souhaite charger son état depuis le stockage persistant. La fonction implémentée doit allouer un tampon (data) et le retourner au TPM avec la longueur du tampon (length). Le tpm_number est toujours 0 et peut être ignoré. Le paramètre name est soit TPM_SAVESTATE_NAME, TPM_VOLATILESTATE_NAME, soit TPM_PERMANENT_ALL_NAME et indique quel type d'état parmi les 3 doit être chargé.

En cas de succès, cette fonction doit retourner TPM_SUCCESS, un code d'échec sinon.

L'implémentation par défaut écrit l'état du TPM dans des fichiers d'un répertoire vers lequel la variable d'environnement TPM_PATH pointait lors de l'exécution de TPMLIB_MainInit(). L'échec de l'écriture de l'état du TPM dans les fichiers placera le TPM en mode échec.

Si cette fonction n'est pas définie (NULL), le fichier NVChip d'origine sera lu lors de l'utilisation d'un TPM 2. Ce fichier contient un vidage mémoire des structures de données internes et n'est ni portable entre les différentes endianness ou architectures de tailles différentes (32 bits, 64 bits), ni ne permettra de gérer les extensions de ces structures de données internes qu'il contient par des ajouts dans le code du TPM 2. Dans le pire des cas, cela peut entraîner des erreurs d'accès mémoire par les fonctions internes et provoquer des plantages. Il est donc recommandé de définir cette fonction et de gérer l'écriture de l'état du TPM.

tpm_nvram_storedata
Cette fonction est appelée lorsque le TPM souhaite stocker son état dans le stockage persistant. Les paramètres data et length fournissent les données à stocker et leur nombre d'octets. La fonction implémentée ne doit pas libérer le tampon data. Le tpm_number est toujours 0 et peut être ignoré. Le paramètre name est soit TPM_SAVESTATE_NAME, TPM_VOLATILESTATE_NAME, soit TPM_PERMANENT_ALL_NAME et indique quel type d'état parmi les 3 doit être stocké.

En cas de succès, cette fonction doit retourner TPM_SUCCESS, un code d'échec sinon.

L'implémentation par défaut lit l'état du TPM à partir de fichiers dans un répertoire vers lequel la variable d'environnement TPM_PATH pointait lors de l'exécution de TPMLIB_MainInit(). L'échec de la lecture de l'état du TPM à partir des fichiers peut placer le TPM en mode échec.

Si cette fonction n'est pas définie (NULL), le vidage mémoire sera écrit dans le fichier NVChip (TPM 2) et les mêmes commentaires s'appliquent que lorsque la fonction d'interface tpm_nvram_loaddata n'est pas définie.

tpm_nvram_deletename
Cette fonction est appelée lorsque le TPM souhaite supprimer l'état du stockage persistant. Le tpm_number est toujours 0 et peut être ignoré. Le paramètre name est soit TPM_SAVESTATE_NAME, TPM_VOLATILESTATE_NAME, soit TPM_PERMANENT_ALL_NAME et indique quel type d'état parmi les 3 doit être supprimé. Le paramètre mustExist indique si les données fournies doivent exister et la fonction implémentée doit retourner TPM_FAIL si les données n'existaient pas.

En cas de succès, cette fonction doit retourner TPM_SUCCESS, un code d'échec sinon.

L'implémentation par défaut supprime les fichiers d'état du TPM dans un répertoire vers lequel la variable d'environnement TPM_PATH pointait lors de l'exécution de TPMLIB_MainInit(). L'échec de la suppression des fichiers d'état du TPM peut placer le TPM en mode échec.

tpm_io_init
Cette fonction est appelée pour initialiser le sous-système d'entrée/sortie du TPM.

En cas de succès, cette fonction doit retourner TPM_SUCCESS, un code d'échec sinon.

L'implémentation par défaut retourne simplement TPM_SUCCESS.

tpm_io_getlocality
Cette fonction est appelée lorsque le TPM doit déterminer la localité sous laquelle une commande doit être exécutée. La fonction implémentée doit retourner le numéro de la localité en l'écrivant dans le pointeur localityModifier.

Cette fonction est censée retourner TPM_SUCCESS ainsi qu'un numéro de localité valide. Le programme implémentant la fonction appelée est censé gérer correctement les numéros de localité.

L'implémentation par défaut retourne 0 comme localité.

tpm_io_getphysicalpresence
Cette fonction est appelée lorsque le TPM doit déterminer si la présence physique a été confirmée. La fonction implémentée doit écrire TRUE ou FALSE dans le pointeur physicalPresence.

En cas de succès, cette fonction doit retourner TPM_SUCCESS, un code d'échec sinon.

L'implémentation par défaut retourne FALSE pour la présence physique.

VALEUR DE RETOUR

La fonction TPMLIB_RegisterCallbacks() retourne TPM_SUCCESS en cas de succès ou un code d'erreur TPM en cas d'échec.

VOIR AUSSI

TPMLIB_MainInit(3), TPMLIB_MainShutdown(3)

nk' href='#RETURN_VALUE'>VALEUR DE RETOUR

En cas de succès, TPMLIB_MainInit() retourne TPM_SUCCESS, une valeur d'erreur sinon.

ERREURS

TPM_SUCCESS
La fonction s'est terminée avec succès.
TPM_FAIL
Échec général.

Pour une liste complète des codes d'erreur TPM, veuillez consulter le fichier d'inclusion libtpms/tpm_error.h

EXEMPLE

#include <libtpms/tpm_types.h>
#include <libtpms/tpm_library.h>
#include <libtpms/tpm_error.h>
static TPM_MODIFIER_INDICATOR locality;
static TPM_RESULT mytpm_io_init(void)
{
       return TPM_SUCCESS;
}
static TPM_RESULT mytpm_io_getlocality(TPM_MODIFIER_INDICATOR *locModif,
                                       uint32_t tpm_number)
{
       *locModif = locality;
       return TPM_SUCCESS:
}
static TPM_RESULT mytpm_io_getphysicalpresence(TPM_BOOL *physicalPresence,
                                               uint32_t tpm_number)
{
       *physicalPresence = FALSE;
       return TPM_SUCCESS;
}
int main(void) {
    TPM_RESULT res;
    unsigned char *respbuffer;
    uint32_t resp_size;
    uint32_t respbufsize;
    unsigned char *command;
    uint32_t command_size;
    struct libtpms_callbacks cbs = {
        .sizeOfStruct               = sizeof(struct libtpms_callbacks),
        .tpm_nvram_init             = NULL,
        .tpm_nvram_loaddata         = NULL,
        .tpm_nvram_storedata        = NULL,
        .tpm_nvram_deletename       = NULL,
        .tpm_io_init                = mytpm_io_init,
        .tpm_io_getlocality         = mytpm_io_getlocality,
        .tpm_io_getphysicalpresence = mytpm_io_getphysicalpresence,
    };
    [...]
    if (TPMLIB_RegisterCallbacks(&cbs) != TPM_SUCCESS) {
        fprintf(stderr, "Could not register the callbacks.\n");
        return 1;
    }
    if (TPMLIB_MainInit()) != TPM_SUCCESS) {
        fprintf(stderr, "Could not start the TPM.\n");
        return 1;
    }
    [...]
    /* build TPM command */
    [...]
    res = TPMLIB_Process(&respbuffer, &resp_size,
                         &respbufsize,
                         command, command_size);
    [...]
    TPMLIB_Terminate();
    return 0;
}
