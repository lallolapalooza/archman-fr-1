NOM

TS_VERIFY_CTX, TS_VERIFY_CTX_new, TS_VERIFY_CTX_init, TS_VERIFY_CTX_free, TS_VERIFY_CTX_cleanup, TS_VERIFY_CTX_set_flags, TS_VERIFY_CTX_add_flags, TS_VERIFY_CTX_set0_data, TS_VERIFY_CTX_set0_imprint, TS_VERIFY_CTX_set0_store, TS_VERIFY_CTX_set0_certs, TS_VERIFY_CTX_set_certs, TS_VERIFY_CTS_set_certs, TS_VERIFY_CTX_set_data, TS_VERIFY_CTX_set_imprint, TS_VERIFY_CTX_set_store - gérer le contexte de vérification de la réponse TS

#include <openssl/ts.h>
typedef struct TS_verify_ctx TS_VERIFY_CTX;
TS_VERIFY_CTX *TS_VERIFY_CTX_new(void);
void TS_VERIFY_CTX_init(TS_VERIFY_CTX *ctx);
void TS_VERIFY_CTX_free(TS_VERIFY_CTX *ctx);
void TS_VERIFY_CTX_cleanup(TS_VERIFY_CTX *ctx);
int TS_VERIFY_CTX_set_flags(TS_VERIFY_CTX *ctx, int f);
int TS_VERIFY_CTX_add_flags(TS_VERIFY_CTX *ctx, int f);
int TS_VERIFY_CTX_set0_data(TS_VERIFY_CTX *ctx, BIO *b);
int TS_VERIFY_CTX_set0_imprint(TS_VERIFY_CTX *ctx,
                               unsigned char *hexstr, long len);
int TS_VERIFY_CTX_set0_store(TS_VERIFY_CTX *ctx, X509_STORE *s);
int TS_VERIFY_CTX_set0_certs(TS_VERIFY_CTX *ctx, STACK_OF(X509) *certs);

Les fonctions suivantes sont dépréciées depuis OpenSSL 3.4 :

BIO *TS_VERIFY_CTX_set_data(TS_VERIFY_CTX *ctx, BIO *b);
unsigned char *TS_VERIFY_CTX_set_imprint(TS_VERIFY_CTX *ctx,

X509_STORE *TS_VERIFY_CTX_set_store(TS_VERIFY_CTX *ctx, X509_STORE *s);
STACK_OF(X509) *TS_VERIFY_CTX_set_certs(TS_VERIFY_CTX *ctx,
                                        STACK_OF(X509) *certs);

La fonction suivante est dépréciée depuis OpenSSL 3.0 :

STACK_OF(X509) *TS_VERIFY_CTS_set_certs(TS_VERIFY_CTX *ctx,
                                        STACK_OF(X509) *certs);

DESCRIPTION

Le Protocole d'Horodatage (TSP) est défini par la RFC 3161. TSP est un protocole utilisé pour fournir une preuve à long terme de l'existence de certaines données avant une heure donnée. TSP définit une Autorité d'Horodatage (TSA) et une entité qui fait des requêtes à la TSA. Habituellement, la TSA est appelée le côté serveur, et l'entité requérante est appelée le client.

Dans TSP, lorsqu'un serveur envoie une réponse à un client, le serveur doit normalement signer les données de réponse - le TimeStampToken (TST) - avec sa clé privée. Ensuite, le client vérifie le TST reçu à l'aide de la chaîne de certificats du serveur.

Pour toutes les méthodes suivantes, sauf indication contraire, ctx est le contexte de vérification créé au préalable.

TS_VERIFY_CTX_new() renvoie une structure TS_VERIFY_CTX allouée.

TS_VERIFY_CTX_init() initialise un contexte de vérification.

TS_VERIFY_CTX_free() libère un objet TS_VERIFY_CTX. ctx est le contexte de vérification à libérer. Si ctx est NULL, l'appel est ignoré.

TS_VERIFY_CTX_set_flags() définit les drapeaux dans le contexte de vérification. f représente les drapeaux à définir.

TS_VERIFY_CTX_add_flags() ajoute des drapeaux au contexte de vérification. f représente les drapeaux à ajouter (par un OU bit à bit).

TS_VERIFY_CTX_set0_data() définit les données à vérifier. b est le BIO contenant les données. Un BIO précédemment attribué est libéré.

TS_VERIFY_CTX_set0_imprint() définit l'empreinte du message. hexstr est l'empreinte du message à attribuer. Une empreinte précédemment attribuée est libérée.

TS_VERIFY_CTX_set0_store() définit le magasin pour le contexte de vérification. s est le magasin à attribuer. Un magasin précédemment attribué est libéré.

TS_VERIFY_CTX_set0_certs() est utilisé pour définir la chaîne de certificats du serveur lors de la vérification d'un TST. certs est une pile de certificats X509.

TS_VERIFY_CTX_cleanup() libère toutes les données associées à l'objet TS_VERIFY_CTX donné et l'initialise. ctx est le contexte de vérification créé au préalable. Si ctx est NULL, l'appel est ignoré.

Toutes les fonctions suivantes décrites sont dépréciées. Les applications devraient plutôt utiliser les fonctions TS_VERIFY_CTX_set0_data(3), TS_VERIFY_CTX_set0_imprint(3), TS_VERIFY_CTX_set0_store(3), TS_VERIFY_CTX_set0_certs(3).

TS_VERIFY_CTX_set_data() est utilisé pour définir le BIO contenant les données à vérifier. Un BIO précédemment attribué n'est pas libéré par cet appel. b est le BIO contenant les données à attribuer.

TS_VERIFY_CTX_set_imprint() est utilisé pour définir l'empreinte du message. Une empreinte précédemment attribuée est libérée par cet appel. hexstr est la chaîne contenant l'empreinte du message à attribuer.

TS_VERIFY_CTX_set_store() est utilisé pour définir le magasin de certificats. Un magasin précédemment attribué n'est pas libéré par cet appel. s est le magasin à attribuer.

TS_VERIFY_CTX_set_certs() est utilisé pour définir la chaîne de certificats du serveur. Une pile précédemment attribuée n'est pas libérée par cet appel. certs est une pile de certificats X509.

TS_VERIFY_CTS_set_certs() est une faute d'orthographe de TS_VERIFY_CTX_set_certs() qui prend les mêmes paramètres et renvoie le même résultat.

VALEURS DE RETOUR

TS_VERIFY_CTX_new() renvoie une structure TS_VERIFY_CTX allouée.

TS_VERIFY_CTX_set_flags() renvoie les drapeaux passés via le paramètre f.

TS_VERIFY_CTX_add_flags() renvoie les drapeaux du contexte après que ceux passés via le paramètre f y aient été ajoutés.

TS_VERIFY_CTX_set0_data(), TS_VERIFY_CTX_set0_imprint(), TS_VERIFY_CTX_set0_store(), et TS_VERIFY_CTX_set0_certs() renvoient 1 si la valeur a pu être définie avec succès et 0 en cas d'erreur.

Les fonctions dépréciées TS_VERIFY_CTX_set_data(), TS_VERIFY_CTX_set_imprint(), TS_VERIFY_CTX_set_store(), TS_VERIFY_CTX_set_certs() renvoient le paramètre que l'utilisateur passe via les paramètres bio, hexstr, s ou certs.

VOIR AUSSI

OSSL_ESS_check_signing_certs(3)

HISTORIQUE

TS_VERIFY_CTX_set0_data(), TS_VERIFY_CTX_set0_imprint(), TS_VERIFY_CTX_set0_store(), TS_VERIFY_CTX_set0_certs() remplacent les fonctions TS_VERIFY_CTX_set_data(), TS_VERIFY_CTX_set_imprint(), TS_VERIFY_CTX_set_store(), TS_VERIFY_CTX_set_certs() qui ont été dépréciées dans OpenSSL 3.4.0.

L'orthographe de TS_VERIFY_CTX_set_certs() a été corrigée dans OpenSSL 3.0.0. La version mal orthographiée TS_VERIFY_CTS_set_certs() a été conservée pour des raisons de compatibilité, mais elle est dépréciée dans OpenSSL 3.0.0.
