DESCRIPTION

Ces procédures sont appelées par les gestionnaires de type de canvas pour effectuer diverses fonctions utilitaires.

Tk_CanvasTkwin renvoie la Tk_Window associée à un canvas particulier.

Tk_CanvasGetCoord traduit une spécification textuelle d'une coordonnée (telle que 2p ou 1.6c) en une coordonnée de canvas en virgule flottante double précision. Si string est une description de coordonnée valide, Tk_CanvasGetCoord stocke la coordonnée de canvas correspondante dans *doublePtr et renvoie TCL_OK. Sinon, elle stocke un message d'erreur dans le résultat de l'interpréteur et renvoie TCL_ERROR.

Tk_CanvasDrawableCoords est appelée par les gestionnaires de type lors du redessin pour calculer où dessiner les éléments. Étant donné les coordonnées x et y dans l'espace du canvas, Tk_CanvasDrawableCoords calcule le pixel correspondant dans le dessinable actuellement utilisé pour le redessin ; elle renvoie ces coordonnées dans *drawableXPtr et *drawableYPtr. Cette procédure ne doit pas être invoquée sauf pendant le redessin.

Tk_CanvasSetStippleOrigin est également utilisé lors du redessin. Il définit l'origine du motif (stipple) dans gc de sorte que les motifs dessinés avec gc dans la pixmap hors écran actuelle s'alignent avec les motifs dessinés avec l'origine (0,0) dans la fenêtre réelle du canvas. Tk_CanvasSetStippleOrigin est nécessaire pour garantir que les motifs s'alignent correctement lorsque le canvas est redessiné par petites parties. Les redessins sont effectués de manière doublement tamponnée, où une partie du canvas est redessinée dans une pixmap hors écran puis copiée dans l'écran. Dans cette approche, les origines des motifs dans les contextes graphiques doivent être ajustées lors de chaque redessin pour compenser la position de la pixmap hors écran par rapport à la fenêtre. Si un élément est dessiné avec des motifs, son gestionnaire de type appelle généralement Tk_CanvasSetStippleOrigin juste avant d'utiliser gc pour dessiner quelque chose ; une fois le dessin terminé, le gestionnaire de type appelle XSetTSOrigin pour restaurer l'origine dans gc à (0,0) (la restauration est nécessaire car les contextes graphiques sont partagés, ils ne peuvent donc pas être modifiés de façon permanente).

Tk_CanvasWindowCoords est similaire à Tk_CanvasDrawableCoords, sauf qu'elle renvoie des coordonnées dans la fenêtre du canvas sur l'écran, au lieu de coordonnées dans une pixmap hors écran.

Tk_CanvasEventuallyRedraw peut être invoquée par un gestionnaire de type pour informer Tk qu'une portion d'un canvas doit être redessinée. Les arguments x1, y1, x2 et y2 spécifient la région qui doit être redessinée, en coordonnées de canvas. Les gestionnaires de type ont rarement besoin d'invoquer Tk_CanvasEventuallyRedraw, car Tk peut normalement déterminer quand un élément a changé et faire la demande de redessin en son nom (cela se produit, par exemple, chaque fois que Tk appelle une configureProc ou une scaleProc). La seule fois où un gestionnaire de type doit appeler Tk_CanvasEventuallyRedraw est si un élément a changé de lui-même sans être invoqué via l'une des procédures de son Tk_ItemType ; cela pourrait se produire, par exemple, dans un élément d'image si l'image est modifiée à l'aide de commandes d'image.

Tk_CanvasTagsParseProc et Tk_CanvasTagsPrintProc sont des procédures qui gèrent l'option -tags pour les éléments de canvas. Le code d'un gestionnaire de type de canvas n'appellera pas ces procédures directement, mais utilisera leurs adresses pour créer une structure Tk_CustomOption pour l'option -tags. Le code ressemble typiquement à ceci :

static const Tk_CustomOption tagsOption = {Tk_CanvasTagsParseProc,
    Tk_CanvasTagsPrintProc, NULL
};
static const Tk_ConfigSpec configSpecs[] = {
    ...
    {TK_CONFIG_CUSTOM, "-tags", NULL, NULL,
        NULL, 0, TK_CONFIG_NULL_OK, &tagsOption},
    ...
};
