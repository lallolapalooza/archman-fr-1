Le bord inférieur de la région nécessitant un redessin. Seuls les pixels au-dessus de cette coordonnée doivent être redessinés.

DESCRIPTION

Ces procédures sont appelées par les gestionnaires de types de canvas pour effectuer diverses fonctions utilitaires.

Tk_CanvasTkwin renvoie le Tk_Window associé à un widget canvas spécifique.

Tk_CanvasGetCoord convertit une description textuelle d'une coordonnée en une valeur double précision dans l'espace du canvas (comme 2p ou 1.6c). Si string est une description valide d'une coordonnée, Tk_CanvasGetCoord stocke la coordonnée correspondante dans *doublePtr et renvoie TCL_OK. Si string n'est pas valide, elle stocke un message d'erreur dans le résultat de l'interpréteur et renvoie TCL_ERROR.

Tk_CanvasDrawableCoords est appelée pendant le redessin d'un widget pour calculer où les éléments doivent être dessinés. Étant donné les coordonnées x et y dans l'espace du canvas, Tk_CanvasDrawableCoords calcule les coordonnées dans le dessin en cours utilisé pour le redessin du canvas ; elle renvoie ces coordonnées dans *drawableXPtr et *drawableYPtr. Cette procédure n'est pas invoquée sauf pendant le redessin.

Tk_CanvasSetStippleOrigin est également invoqué pendant le redessin. Il définit l'origine des motifs de tramage dans gc de sorte que les motifs de tramage dessinés avec gc dans le pixmap hors écran soient alignés avec les motifs de tramage dessinés avec une origine (0,0) dans la fenêtre du canvas. Tk_CanvasSetStippleOrigin est nécessaire pour garantir que les motifs de tramage s'alignent correctement lorsque le canvas est redessiné par morceaux. Les redessins sont effectués en double buffer, où une partie du canvas est dessinée dans un pixmap hors écran, puis copiée à l'écran. Dans cette approche, les origines de tramage dans les contextes graphiques doivent être ajustées pendant chaque redessin pour compenser la position du pixmap hors écran par rapport à la fenêtre. Si un élément est dessiné avec un tramage, son gestionnaire de type appelle typiquement Tk_CanvasSetStippleOrigin juste avant d'utiliser gc pour dessiner quelque chose ; après avoir terminé le dessin, le gestionnaire de type appelle XSetTSOrigin pour restaurer l'origine dans gc à (0,0) (la restauration est nécessaire car les contextes graphiques sont partagés et ne peuvent pas être modifiés de manière permanente).

Tk_CanvasWindowCoords est similaire à Tk_CanvasDrawableCoords, mais elle renvoie des coordonnées dans la fenêtre du canvas à l'écran, plutôt que dans le pixmap hors écran.

Tk_CanvasEventuallyRedraw peut être invoqué par un gestionnaire de type pour informer Tk qu'une partie du canvas doit être redessinée. Les arguments x1, y1, x2, et y2 spécifient la région qui doit être redessinée, en coordonnées de canvas. Les gestionnaires de type invoquent rarement Tk_CanvasEventuallyRedraw, car Tk peut normalement déterminer quand un élément a changé et faire la requête de redessin lui-même (cela se produit, par exemple, lorsque Tk appelle un configureProc ou un scaleProc). Le seul moment où un gestionnaire de type doit invoquer Tk_CanvasEventuallyRedraw est si un élément a changé de lui-même sans être invoqué via l'une des procédures de son type d'élément ; cela pourrait se produire, par exemple, si un élément image est modifié à l'aide de commandes d'image.

Tk_CanvasTagsParseProc et Tk_CanvasTagsPrintProc sont des procédures qui gèrent l'option -tags pour les éléments de canvas. Le code du gestionnaire de type de canvas n'appelle pas directement ces procédures, mais utilise leurs adresses pour créer une structure Tk_CustomOption pour l'option -tags. Le code ressemble généralement à ceci :

static const Tk_CustomOption tagsOption = {Tk_CanvasTagsParseProc,
    Tk_CanvasTagsPrintProc, NULL
};
static const Tk_ConfigSpec configSpecs[] = {
    ...
    {TK_CONFIG_CUSTOM, "-tags", NULL, NULL,
        NULL, 0, TK_CONFIG_NULL_OK, &tagsOption},
    ...
};
