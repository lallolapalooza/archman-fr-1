OPTIONS SPÉCIFIQUES AU WIDGET

Nom: height
Classe: Height
Commutateur: -height
Spécifie la hauteur souhaitée pour la fenêtre, en unités de caractères de la police spécifiée par l'option -font. Doit être au moins un.
Nom: spacing1
Classe: Spacing1
Commutateur: -spacing1
Demande un espace supplémentaire au-dessus de chaque ligne de texte dans le widget, en utilisant l'une des formes standard pour les distances d'écran. Si une ligne est coupée, cette option s'applique uniquement à la première ligne affichée. Cette option peut être remplacée par des options -spacing1 dans les balises.
Nom: spacing2
Classe: Spacing2
Commutateur: -spacing2
Pour les lignes coupées (de sorte qu'elles couvrent plusieurs lignes à l'écran), cette option spécifie l'espace supplémentaire à fournir entre les lignes d'affichage qui représentent une seule ligne de texte. La valeur peut avoir l'une des formes standard pour les distances d'écran. Cette option peut être remplacée par des options -spacing2 dans les balises.
Nom: spacing3
Classe: Spacing3
Commutateur: -spacing3
Demande un espace supplémentaire en dessous de chaque ligne de texte dans le widget, en utilisant l'une des formes standard pour les distances d'écran. Si une ligne est coupée, cette option s'applique uniquement à la dernière ligne affichée. Cette option peut être remplacée par des options -spacing3 dans les balises.
Nom: state
Classe: State
Commutateur: -state
Spécifie l'un des deux états du texte : normal ou disabled. Si le texte est désactivé, aucun caractère ne peut être inséré ou supprimé et aucun curseur d'insertion ne sera affiché, même si le focus d'entrée est dans le widget.
Nom: tabs
Classe: Tabs
Commutateur: -tabs
Spécifie un ensemble de tabulations pour la fenêtre. La valeur de l'option consiste en une liste de distances d'écran donnant les positions des tabulations. Chaque position peut éventuellement être suivie dans l'élément de liste suivant par l'un des mots-clés left, right, center ou numeric, qui spécifie comment justifier le texte par rapport à la tabulation. Left est la valeur par défaut ; elle fait en sorte que le texte suivant le caractère de tabulation soit positionné avec son bord gauche à la position de tabulation. Right signifie que le bord droit du texte suivant le caractère de tabulation est positionné à la position de tabulation, et center signifie que le texte est centré à la position de tabulation. Numeric signifie que le point décimal dans le texte est positionné à la position de tabulation ; s'il n'y a pas de point décimal, alors le chiffre le moins significatif du nombre est positionné juste à gauche de la position de tabulation ; s'il n'y a pas de nombre dans le texte, alors le texte est aligné à droite à la position de tabulation. Par exemple, -tabs => [qw/2c left 4c 6c center/] crée trois tabulations avec des intervalles de deux centimètres ; les deux premières utilisent un alignement à gauche et la troisième utilise un alignement centré. Si la liste des tabulations n'a pas suffisamment d'éléments pour couvrir toutes les tabulations d'une ligne de texte, alors Tk extrapole de nouvelles tabulations en utilisant l'espacement et l'alignement de la dernière tabulation de la liste. La valeur de l'option tabs peut être remplacée par des options -tabs dans les balises. Si aucune option -tabs n'est spécifiée, ou si elle est spécifiée comme une liste vide, alors Tk utilise des tabulations par défaut espacées tous les huit caractères (taille moyenne).
Nom: width
Classe: Width
Commutateur: -width
Spécifie la largeur souhaitée pour la fenêtre en unités de caractères de la police spécifiée par l'option -font. Si la police n'a pas de largeur uniforme, alors la largeur du caractère « 0 » est utilisée pour la traduction des unités de caractères en unités d'écran.
Nom: wrap
Classe: Wrap
Commutateur: -wrap
Spécifie comment gérer les lignes dans le texte qui sont trop longues pour être affichées sur une seule ligne dans la fenêtre du texte. La valeur doit être none ou char ou word. Un mode de coupure none signifie que chaque ligne de texte apparaît comme une seule ligne à l'écran ; les caractères supplémentaires qui ne rentrent pas à l'écran ne sont pas affichés. Dans les autres modes, chaque ligne de texte sera divisée en plusieurs lignes d'écran si nécessaire pour que tous les caractères restent visibles. En mode char, une coupure de ligne peut se produire après n'importe quel caractère ; en mode word, une coupure de ligne se fera uniquement aux limites de mots.

DESCRIPTION

La méthode Text crée une nouvelle fenêtre (donnée par l'argument $text) et en fait un widget texte. Des options supplémentaires, décrites ci-dessus, peuvent être spécifiées sur la ligne de commande ou dans la base de données d'options pour configurer des aspects du texte tels que sa couleur de fond par défaut et son relief. La commande text renvoie le nom de chemin de la nouvelle fenêtre.

Un widget texte affiche une ou plusieurs lignes de texte et permet de modifier ce texte. Les widgets texte prennent en charge quatre types d'annotations sur le texte, appelées balises, marques, fenêtres intégrées ou images intégrées. Les balises permettent d'afficher différentes parties du texte avec différentes polices et couleurs. De plus, des callbacks perl/Tk peuvent être associés aux balises afin que des scripts soient invoqués lorsque des actions particulières telles que des frappes au clavier et des pressions de boutons de souris se produisent dans des plages spécifiques du texte. Voir "BALISES" ci-dessous pour plus de détails.

La deuxième forme d'annotation consiste en des marques, qui sont des marqueurs flottants dans le texte. Les marques sont utilisées pour suivre diverses positions intéressantes dans le texte pendant qu'il est édité. Voir "MARQUES" ci-dessous pour plus de détails.

La troisième forme d'annotation permet d'intégrer des fenêtres arbitraires dans un widget texte. Voir "FENÊTRES INTÉGRÉES" ci-dessous pour plus de détails.

La quatrième forme d'annotation permet d'intégrer des images Tk dans un widget texte. Voir "IMAGES INTÉGRÉES" ci-dessous pour plus de détails.

Le widget Text de Perl/Tk ne prend pas en charge l'annulation/rétablissement (undo/redo), utilisez plutôt le widget TextUndo.

- compte chars
Ajuste l'indice en arrière de compte caractères, en passant aux lignes précédentes du texte si nécessaire. S'il y a moins de compte caractères dans le texte avant l'indice courant, alors l'indice est défini sur le premier caractère du texte. Les espaces de chaque côté de compte sont facultatifs.
+ compte lines
Ajuste l'indice en avant de compte lignes, en conservant la même position de caractère dans la ligne. Les espaces de chaque côté de compte sont facultatifs.
- compte lines
Ajuste l'indice en arrière de compte lignes, en conservant la même position de caractère dans la ligne. S'il y a moins de compte lignes avant la ligne contenant l'indice courant, alors l'indice est défini pour référencer la même position de caractère sur la première ligne du texte. Ensuite, si la ligne n'est pas assez longue pour contenir un caractère à la position de caractère indiquée, la position de caractère est ajustée pour référencer le dernier caractère de la ligne (la nouvelle ligne). Les espaces de chaque côté de compte sont facultatifs.
linestart
Ajuste l'indice pour référencer le premier caractère de la ligne.
lineend
Ajuste l'indice pour référencer le dernier caractère de la ligne (la nouvelle ligne).
wordstart
Ajuste l'indice pour référencer le premier caractère du mot contenant l'indice courant. Un mot est constitué d'un nombre quelconque de caractères adjacents qui sont des lettres, des chiffres ou des tirets bas, ou d'un seul caractère qui n'est pas l'un d'eux.

Ajuste l'indice pour référencer le caractère juste après le dernier du mot contenant l'indice courant. Si l'indice courant fait référence au dernier caractère du texte, il n'est pas modifié.

Si plusieurs modificateurs sont présents, ils sont appliqués dans l'ordre de gauche à droite. Par exemple, l'indice ``end - 1 chars'' fait référence à l'avant-dernier caractère du texte et ``insert wordstart - 1 c'' fait référence au caractère juste avant le premier caractère du mot contenant le curseur d'insertion.

TAGS

La première forme d'annotation dans les widgets texte est une étiquette (tag). Une étiquette est une chaîne de caractères associée à certains des caractères d'un texte. Les étiquettes peuvent contenir des caractères arbitraires, mais il est probablement préférable d'éviter d'utiliser les caractères `` '' (espace), + ou - : ces caractères ont une signification spéciale dans les indices, donc les étiquettes les contenant ne peuvent pas être utilisées comme indices. Il peut y avoir un nombre quelconque d'étiquettes associées aux caractères d'un texte. Chaque étiquette peut faire référence à un seul caractère, à une plage de caractères, ou à plusieurs plages de caractères. Un caractère individuel peut avoir un nombre quelconque d'étiquettes associées.

Un ordre de priorité est défini entre les étiquettes, et cet ordre est utilisé pour implémenter certaines des fonctions liées aux étiquettes décrites ci-dessous. Lorsqu'une étiquette est définie (en l'associant à des caractères ou en définissant ses options d'affichage ou en y liant des callbacks), elle se voit attribuer une priorité supérieure à toute étiquette existante. L'ordre de priorité des étiquettes peut être redéfini à l'aide des méthodes ``$text->tagRaise'' et ``$text->tagLower''.

Les étiquettes servent trois objectifs dans les widgets texte. Premièrement, elles contrôlent la manière dont les informations sont affichées à l'écran. Par défaut, les caractères sont affichés conformément aux options background, font et foreground du widget texte. Cependant, des options d'affichage peuvent être associées à des étiquettes individuelles à l'aide de la méthode ``$text->tagConfigure''. Si un caractère a été étiqueté, alors les options d'affichage associées à l'étiquette remplacent le style d'affichage par défaut. Les options suivantes sont actuellement prises en charge pour les étiquettes :

-background => couleur
Couleur spécifie la couleur d'arrière-plan à utiliser pour les caractères associés à l'étiquette. Elle peut avoir l'une des formes acceptées par Tk_GetColor.
-bgstipple => bitmap
Bitmap spécifie une bitmap utilisée comme motif de tramage pour l'arrière-plan. Elle peut avoir l'une des formes acceptées par Tk_GetBitmap. Si bitmap n'a pas été spécifié, ou s'il est spécifié comme une chaîne vide, alors un remplissage solide sera utilisé pour l'arrière-plan.
-borderwidth => pixels
Pixels spécifie la largeur d'une bordure 3D à dessiner autour de l'arrière-plan. Elle peut avoir l'une des formes acceptées par Tk_GetPixels. Cette option est utilisée conjointement avec l'option -relief pour donner une apparence 3D à l'arrière-plan des caractères ; elle est ignorée sauf si l'option -background a été définie pour l'étiquette.
-elide => booléen
Elide spécifie si les données doivent être éludées. Les données éludées ne sont pas affichées et ne prennent pas de place à l'écran, mais se comportent par la suite comme des données normales.
-data => valeur
Permet d'associer une valeur scalaire perl arbitraire valeur à l'étiquette.
-fgstipple => bitmap
Bitmap spécifie une bitmap utilisée comme motif de tramage lors du dessin de texte et d'autres informations de premier plan telles que les soulignements. Elle peut avoir l'une des formes acceptées par Tk_GetBitmap. Si bitmap n'a pas été spécifié, ou s'il est spécifié comme une chaîne vide, alors un remplissage solide sera utilisé.
-font => nomPolice
NomPolice est le nom d'une police à utiliser pour dessiner les caractères. Il peut avoir l'une des formes acceptées par Tk_GetFontStruct.
-foreground => couleur
Couleur spécifie la couleur à utiliser lors du dessin de texte et d'autres informations de premier plan telles que les soulignements. Elle peut avoir l'une des formes acceptées par Tk_GetColor.
-justify => justification
Si le premier caractère d'une ligne d'affichage a une étiquette pour laquelle cette option a été spécifiée, alors justification détermine comment justifier la ligne. Elle doit être l'un des mots clés left, right ou center. Si une ligne est retournée, la justification de chaque ligne affichée est déterminée par le premier caractère de cette ligne d'affichage.
-lmargin1 => pixels
Si le premier caractère d'une ligne de texte a une étiquette pour laquelle cette option a été spécifiée, alors pixels spécifie de combien la ligne doit être indentée par rapport au bord gauche de la fenêtre. Pixels peut avoir l'une des formes standard pour les distances d'écran. Si une ligne de texte est retournée, cette option ne s'applique qu'à la première ligne affichée ; l'option -lmargin2 contrôle l'indentation des lignes suivantes.

Pixels peut avoir l'une des formes standard pour les distances d'écran. Cette option n'est utilisée que lorsque le renvoi est activé, et elle ne s'applique qu'à la deuxième et aux lignes d'affichage suivantes pour une ligne de texte.

Pixels spécifie une quantité par laquelle la ligne de base du texte doit être décalée verticalement par rapport à la ligne de base de la ligne globale, en pixels. Spécifie s'il faut dessiner ou non une ligne horizontale au milieu des caractères. Booléen peut avoir l'une des formes acceptées par Tk_GetBoolean.
-relief => relief
Relief spécifie le relief 3D à utiliser pour dessiner les arrière-plans, dans l'une des formes acceptées par Tk_GetRelief. Pixels peut avoir l'une des formes standard pour les distances d'écran. Cette option n'est utilisée que lorsque le renvoi est activé. -spacing2 => pixels
Pour les lignes renvoyées, cette option spécifie l'espace supplémentaire à laisser entre les lignes d'affichage pour une seule ligne de texte. Pixels peut avoir l'une des formes standard pour les distances d'écran.
-spacing3 => pixels
Pixels spécifie l'espace supplémentaire à laisser en dessous de chaque ligne de texte, en utilisant l'une des formes standard pour les distances d'écran. Si une ligne est renvoyée, cette option ne s'applique qu'à la dernière ligne affichée.
-tabs => tabList
TabList spécifie un ensemble de tabulations dans la même forme que pour l'option -tabs du widget de texte. Booléen spécifie si une ligne doit être dessinée sous les caractères. Il peut prendre l'une des formes acceptées par Tk_GetBoolean.

Mode spécifie comment gérer les lignes plus larges que la fenêtre de texte. Il a les mêmes valeurs légales que l'option -wrap du widget de texte : none, char, ou word. Si cette option de balise est spécifiée, elle remplace l'option -wrap du widget de texte.

Si un caractère a plusieurs balises associées, et si leurs options d'affichage entrent en conflit, alors les options de la balise de priorité la plus élevée sont utilisées. Si une option d'affichage particulière n'a pas été spécifiée pour une balise particulière, ou si elle est spécifiée comme une chaîne vide, alors cette option ne sera jamais utilisée ; l'option de la balise de priorité la plus élevée sera utilisée à la place. Si aucune balise ne spécifie une option d'affichage particulière, alors le style par défaut du widget sera utilisé.

Le deuxième objectif des balises est les liaisons d'événements. Vous pouvez associer des liaisons à une balise de la même manière que vous pouvez associer des liaisons à une classe de widget : chaque fois que des événements X particuliers se produisent sur des caractères avec la balise donnée, un appel de procédure <perl/Tk callback|Tk::callbacks> donné sera exécuté. Les liaisons de balises peuvent être utilisées pour donner des comportements à des plages de caractères ; entre autres choses, cela permet d'implémenter des fonctionnalités de type hypertexte. Pour plus de détails, voir la description de la méthode de widget tagBind ci-dessous.

La troisième utilisation des balises est la gestion de la sélection. Voir "LA SÉLECTION" ci-dessous.

MARQUEURS

La deuxième forme d'annotation dans les widgets de texte est un marqueur. Les marqueurs sont utilisés pour mémoriser des endroits particuliers dans un texte. Ils sont un peu comme les balises, en ce sens qu'ils ont des noms et qu'ils font référence à des endroits dans le fichier, mais un marqueur n'est pas associé à des caractères particuliers. Au lieu de cela, un marqueur est associé à l'espace entre deux caractères. Une seule position peut être associée à un marqueur à un moment donné. Si les caractères autour d'un marqueur sont supprimés, le marqueur restera ; il aura simplement de nouveaux caractères voisins. En revanche, si les caractères contenant une balise sont supprimés, la balise n'aura plus d'association avec des caractères dans le fichier. Les marqueurs peuvent être manipulés avec la méthode de widget texte ``$text->mark'', et leurs emplacements actuels peuvent être déterminés en utilisant le nom du marqueur comme index dans les méthodes.

Chaque marqueur a également une gravité, qui est soit left (gauche) soit right (droite). La gravité d'un marqueur spécifie ce qui arrive au marqueur lorsque du texte est inséré à l'emplacement du marqueur. Si un marqueur a une gravité gauche, alors le marqueur est traité comme s'il était attaché au caractère à sa gauche, de sorte que le marqueur restera à gauche de tout texte inséré à la position du marqueur. Si le marqueur a une gravité droite, le nouveau texte inséré à la position du marqueur apparaîtra à droite du marqueur. La gravité d'un marqueur est par défaut right.

L'espace de noms pour les marqueurs est différent de celui des balises : le même nom peut être utilisé pour un marqueur et une balise, mais ils feront référence à des choses différentes.

Deux marqueurs ont une signification particulière. Premièrement, le marqueur insert est associé au curseur d'insertion, comme décrit dans la section "LE CURSEUR D'INSERTION" ci-dessous. Deuxièmement, le marqueur current est associé au caractère le plus proche de la souris et est ajusté automatiquement pour suivre la position de la souris et toute modification du texte dans le widget (une exception : current n'est pas mis à jour en réponse aux mouvements de la souris si un bouton de la souris est enfoncé ; la mise à jour sera différée jusqu'à ce que tous les boutons de la souris aient été relâchés). Aucun de ces marqueurs spéciaux ne peut être supprimé.

FENÊTRES INTÉGRÉES

La troisième forme d'annotation dans les widgets de texte est une fenêtre intégrée. Chaque annotation de fenêtre intégrée provoque l'affichage d'une fenêtre à un point particulier du texte. Il peut y avoir un nombre quelconque de fenêtres intégrées dans un widget de texte, et n'importe quel widget peut être utilisé comme fenêtre intégrée (sous réserve des règles habituelles de gestion de la géométrie, qui exigent que la fenêtre de texte soit le parent de la fenêtre intégrée ou un descendant de son parent). La position de la fenêtre intégrée sur l'écran sera mise à jour lorsque le texte sera modifié ou défilé, et elle sera mappée et démappée lorsqu'elle entrera et sortira de la zone visible du widget de texte. Chaque fenêtre intégrée occupe l'espace d'index d'un caractère dans le widget de texte, et elle peut être référencée soit par le nom de sa fenêtre intégrée, soit par sa position dans l'espace d'index du widget. Si la plage de texte contenant la fenêtre intégrée est supprimée, la fenêtre est détruite.

Lorsqu'une fenêtre intégrée est ajoutée à un widget de texte avec la méthode widgetCreate, plusieurs options de configuration peuvent lui être associées. Ces options peuvent être modifiées ultérieurement avec la méthode widgetConfigure. Les options suivantes sont actuellement prises en charge :

-align => where
Si la fenêtre n'a pas la même hauteur que la ligne dans laquelle elle est affichée, cette option détermine où la fenêtre est affichée dans la ligne. Where doit avoir l'une des valeurs top (aligner le haut de la fenêtre avec le haut de la ligne), center (centrer la fenêtre dans la plage de la ligne), bottom (aligner le bas de la fenêtre avec le bas de la zone de la ligne), ou baseline (aligner le bas de la fenêtre avec la ligne de base de la ligne).
-create => callback
Spécifie un rappel qui peut être évalué pour créer la fenêtre pour l'annotation. Si aucune option -window n'a été spécifiée pour l'annotation, ce callback sera évalué lorsque l'annotation est sur le point d'être affichée à l'écran. Callback doit créer une fenêtre pour l'annotation et retourner le nom de cette fenêtre comme résultat. Si la fenêtre de l'annotation devait jamais être supprimée, callback sera évalué à nouveau la prochaine fois que l'annotation sera affichée.
-padx => pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser de chaque côté de la fenêtre intégrée. Il peut avoir l'une des formes habituelles définies pour une distance d'écran (voir Tk_GetPixels).
-pady => pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser en haut et en bas de la fenêtre intégrée. Il peut avoir l'une des formes habituelles définies pour une distance d'écran (voir Tk_GetPixels).
-stretch => booléen
Si la hauteur demandée de la fenêtre intégrée est inférieure à la hauteur de la ligne dans laquelle elle est affichée, cette option peut être utilisée pour spécifier si la fenêtre doit être étirée verticalement pour remplir sa ligne. Si l'option -pady a également été spécifiée, alors le remplissage demandé sera conservé même si la fenêtre est étirée.
-window => windowName
Si cette option est spécifiée, elle doit être le nom d'une fenêtre Tk (soit une fenêtre de niveau supérieur, soit une fenêtre enfant d'un autre widget Tk). Cette fenêtre sera intégrée dans le widget de texte. Le nom de la fenêtre doit être spécifié sous forme de chaîne. Il n'y a pas de valeur par défaut ; si cette option est absente, alors soit l'option -create est utilisée, soit aucune fenêtre n'est intégrée.
-window => $widget
Est le nom d'une fenêtre à afficher dans l'annotation.

IMAGES INTÉGRÉES

La forme finale de l'annotation dans les widgets de texte est une image intégrée. Chaque annotation d'image intégrée provoque l'affichage d'une image à un endroit spécifique du texte. Il peut y avoir un nombre quelconque d'images intégrées dans un widget de texte, et une image particulière peut être intégrée à plusieurs endroits du même widget de texte. La position de l'image à l'écran sera mise à jour lorsque le texte sera modifié ou défilé. Chaque image intégrée occupe un espace d'index de caractère dans le widget de texte, et peut être référencée par sa position dans l'espace d'index du widget ou par le nom qui lui est assigné lors de l'insertion de l'image avec imageCreate. Si la plage de texte contenant l'image intégrée est supprimée, cette copie de l'image est supprimée de l'écran.

Lorsqu'une image intégrée est ajoutée à un widget de texte avec la méthode image create, un nom unique est retourné pour cette instance d'image. Ce nom peut ensuite être utilisé pour faire référence à cette instance d'image. Le nom est considéré comme la valeur de l'option -name (décrite ci-dessous). Si l'option -name n'est pas fournie, le nom -image est utilisé. Si le nom imageName est déjà utilisé dans le widget de texte, #nn est ajouté à la fin du nom, où nn est un nombre arbitraire. Cela garantit que le nom imageName est unique. Une fois ce nom attribué à cette instance d'image, il ne change pas, même si les valeurs de -image ou -name sont modifiées avec la méthode image configure).

Lorsqu'une image intégrée est ajoutée à un widget de texte avec la méthode imageCreate, plusieurs options de configuration peuvent lui être associées. Ces options peuvent être modifiées ultérieurement avec la méthode image configure. Les options suivantes sont actuellement prises en charge :

-align => où
Si l'image n'est pas aussi haute que la ligne sur laquelle elle est affichée, cette option détermine où l'image est affichée dans la ligne. Où doit avoir une valeur parmi les valeurs top (aligner le bord supérieur de l'image avec le bord supérieur de la ligne), center (centrer l'image dans la plage de la ligne), bottom (aligner le bord inférieur de l'image avec le bord inférieur de la zone de la ligne) ou baseline (aligner le bord inférieur de l'image avec la ligne de base de la ligne).
-image => image
Est le nom de l'image Tk à afficher dans l'annotation. Si image n'est pas une image Tk valide, une erreur est renvoyée.
-name => NomImage
Est le nom par lequel cette instance d'image peut être référencée dans le widget de texte. Si NomImage n'est pas fourni, le nom de l'image Tk est utilisé. Si le nom nomImage est déjà utilisé, #nn est ajouté à la fin du nom, comme décrit ci-dessus.
-padx => pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser de chaque côté de l'image intégrée. Il peut avoir l'une des formes habituelles définies pour une distance d'écran.
-pady => pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser en haut et en bas de l'image intégrée. Il peut avoir l'une des formes habituelles définies pour une distance d'écran.

LA SÉLECTION

La prise en charge de la sélection est implémentée à l'aide d'étiquettes. Si l'option exportSelection du widget de texte est vraie, l'étiquette sel sera associée à la sélection :

[1]
Lorsque des caractères sont étiquetés avec sel, le widget de texte revendiquera la propriété de la sélection.
[2]
Les tentatives de récupération de la sélection seront gérées par le widget de texte, renvoyant tous les caractères avec l'étiquette sel.
[3]
Si la sélection est revendiquée par une autre application ou par une autre fenêtre de cette application, l'étiquette sel sera supprimée de tous les caractères du texte.
[4]
Lorsque la plage d'étiquettes sel change, un événement virtuel <<Selection>> est généré.
L'étiquette sel est définie automatiquement lorsqu'un widget de texte est créé, et ne peut pas être supprimée avec la méthode $text->tagDelete. De plus, les options selectBackground, selectBorderWidth et selectForeground du widget de texte sont liées aux étiquettes -background, -borderwidth et -foreground de l'étiquette sel : les changements sur l'une d'elles se refléteront automatiquement sur l'autre.

LE CURSEUR D'INSERTION

Le marqueur nommé insert a une importance particulière dans les widgets de texte. Il est défini automatiquement lorsque le widget est créé et ne peut pas être supprimé avec la commande $text->markUnset. Le marqueur insert représente la position du curseur d'insertion, et le curseur d'insertion est automatiquement dessiné à cet endroit lorsque le widget de texte a le focus d'entrée.

LE DRAPEAU MODIFIÉ

Le widget de texte peut suivre les modifications apportées au contenu du widget à l'aide du drapeau de modification. L'insertion ou la suppression de texte définira ce drapeau. Le drapeau peut être consulté, défini et effacé par programme. Chaque fois que l'état du drapeau change, un événement virtuel <<Modified>> est généré. Consultez l'instruction edit modified widget pour plus de détails.

Les événements Enter et Leave peuvent se produire soit parce que la marque current s'est déplacée, soit parce que le caractère à cette position a changé. Si un événement virtuel est utilisé dans une liaison, cette liaison ne peut se déclencher que si l'événement virtuel est défini par un événement sous-jacent lié à la souris ou au clavier.

Il est possible que le caractère actuel ait plusieurs tags, et que chacun d'eux ait une liaison pour une séquence d'événements particulière. S'il y a plusieurs liaisons correspondantes pour un seul tag, alors la liaison la plus spécifique est choisie (voir la documentation de la commande bind pour les détails). Les commandes continue et break dans les scripts de liaison sont traitées de la même manière que pour les liaisons créées avec la commande bind.

Si des liaisons sont créées pour le widget dans son ensemble en utilisant la commande bind, alors ces liaisons compléteront les liaisons de tags. Les liaisons de tags seront invoquées en premier, suivies des liaisons pour la fenêtre dans son ensemble.

The behavior of texts can be changed by defining new bindings for individual widgets or by redefining the class bindings.

TIED INTERFACE

The Perl/Tk Text widget also has built-in TIEHANDLE methods for print and printf statements. This means you can print to file handles tied to a Text widget, and the tied methods automatically insert the print statement's arguments into the Text widget.

For example:

#!/usr/local/bin/perl -w
use POSIX 'acos';
use Tk;
use strict;
my $mw = MainWindow->new;
my $text = $mw->Text(qw/-width 40 -height 10/)->pack;
tie *STDOUT, ref $text, $text;
print "Hello Text World!\n";
printf "pi ~= %1.5f", acos(-1.0);
MainLoop;

To tie a scrolled Text widget, use the Subwidget method to get to the "real" widget:

my $text = $mw->Scrolled('Text')->pack;
tie *STDOUT, 'Tk::Text', $text->Subwidget('scrolled');

PERFORMANCE ISSUES

Text widgets should run efficiently under a variety of conditions. The text widget uses about 2-3 bytes of main memory for each byte of text, so texts containing a megabyte or more should be practical on most workstations. Text is represented internally with a modified B-tree structure that makes operations relatively efficient even with large texts. Tags are included in the B-tree structure in a way that allows tags to span large ranges or have many disjoint smaller ranges without loss of efficiency. Marks are also implemented in a way that allows large numbers of marks. In most cases it is fine to have large numbers of unique tags, or a tag that has many distinct ranges.

One performance problem can arise if you have hundreds or thousands of different tags that all have the following characteristics: the first and last ranges of each tag are near the beginning and end of the text, respectively, or a single tag range covers most of the text widget. The cost of adding and deleting tags like this is proportional to the number of other tags with the same properties. In contrast, there is no problem with having thousands of distinct tags if their overall ranges are localized and spread uniformly throughout the text.

Very long text lines can be expensive, especially if they have many marks and tags within them.

The display line with the insert cursor is redrawn each time the cursor blinks, which causes a steady stream of graphics traffic. Set the -insertofftime option to 0 avoid this.
