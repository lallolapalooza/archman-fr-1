SetResources - Tk::CmdLine::SetResources((\@resource | $resource) [, $priority])
Définit les ressources initiales. 
Tk::CmdLine::SetResources((\@resource | $resource) [, $priority])

Une ressource unique peut être spécifiée sous forme de chaîne de la forme '<pattern>:<value>'. Plusieurs ressources peuvent être spécifiées en passant une référence de tableau dont les éléments sont soit des chaînes de la forme ci-dessus, soit des références de tableaux anonymes de la forme [ <pattern>, <value> ]. L'argument optionnel second spécifie la priorité, telle que définie dans option, à associer aux ressources (par défaut : userDefault).

Notez que "SetResources"() appelle d'abord "SetArguments"() s'il n'a pas déjà été appelé.

LoadResources - Tk::CmdLine::LoadResources([%options])
Charge les ressources initiales à partir d'un ou plusieurs fichiers. 
Tk::CmdLine::LoadResources(
    [ -symbol   => $symbol     ]
    [ -file     => $fileSpec   ]
    [ -priority => $priority   ]
    [ -echo     => $fileHandle ] );

[ -symbol => $symbol ] spécifie le nom d'une variable d'environnement qui, si elle est définie, définit une liste d'un ou plusieurs répertoires et/ou modèles de fichiers (joints en utilisant le délimiteur de chemin dépendant du système d'exploitation, par exemple le deux-points sur UNIX). $"XUSERFILESEARCHPATH" est un cas spécial. Si $"XUSERFILESEARCHPATH" n'est pas défini, $"XAPPLRESDIR" est vérifié à la place. Si $"XAPPLRESDIR" n'est pas défini, $"HOME" est vérifié à la place.

Un élément est identifié comme un modèle de fichier s'il contient un ou plusieurs modèles /%[A-Za-z]/. Seuls les modèles %L, %T et %N sont actuellement reconnus. Tous les autres sont remplacés par la chaîne nulle. Le modèle %L est traduit en $"LANG". Le modèle %T est traduit en app-defaults. Le modèle %N est traduit en le nom de classe de l'application.

Chaque modèle de fichier, après application des substitutions, est supposé définir un FileSpec à examiner.

Lorsqu'un répertoire est spécifié, les FileSpecs <DIRECTORY>/<LANG>/<CLASS> et <DIRECTORY>/<CLASS> sont définis, dans cet ordre.

[ -file => $fileSpec ] spécifie un fichier de ressources à charger. Le fichier est ignoré silencieusement s'il n'existe pas, ou s'il n'est pas lisible.

[ -priority => $priority ] spécifie la priorité, telle que définie dans option, à associer aux ressources (par défaut : userDefault).

[ -echo => $fileHandle ] peut être utilisé pour spécifier qu'une ligne doit être imprimée dans le FileHandle correspondant (par défaut : \*STDOUT) chaque fois qu'un fichier est examiné / chargé.

Si aucune option -symbol ou -file n'est spécifiée, "LoadResources"() traite le symbole $"XFILESEARCHPATH" avec la priorité startupFile et $"XUSERFILESEARCHPATH" avec la priorité userDefault. (Notez que $"XFILESEARCHPATH" et $"XUSERFILESEARCHPATH" sont censés contenir uniquement des modèles. $"XAPPLRESDIR" et $"HOME" sont censés être un répertoire unique. "LoadResources"() ne vérifie/se soucie pas de savoir si c'est le cas.)

Pour chaque ensemble de FileSpecs, "LoadResources"() examine chaque FileSpec pour déterminer si le fichier existe et est lisible. Le premier fichier qui répond à ce critère est lu et "SetResources"() est invoqué.

Notez que "LoadResources"() appelle d'abord "SetArguments"() s'il n'a pas déjà été appelé.

NOTES

Ce module est un module orienté objet dont les méthodes peuvent être appelées comme méthodes d'objet, méthodes de classe ou fonctions régulières. Ceci est réalisé via une référence d'objet maintenue interne qui est créée si nécessaire, et qui pointe toujours vers le dernier objet utilisé. "SetArguments"(), "SetResources"() et "LoadResources"() retournent la référence d'objet.

EXEMPLES

1.
@ARGV est traité par Tk::CmdLine lors de la création de MainWindow. 
use Tk;
# <Traiter @ARGV - en ignorant toutes les options spécifiques à X11>
my $mw = MainWindow->new();
MainLoop();
2.
@ARGV est traité par Tk::CmdLine avant la création de MainWindow. Une valeur de @ARGV de (--geometry=100x100 -opt1 a b c -bg red) est égale à (-opt1 a b c) après l'invocation de "SetArguments"(). 
use Tk;
Tk::CmdLine::SetArguments(); # Tk::CmdLine->SetArguments() fonctionne aussi
# <Traiter @ARGV - sans se soucier des options spécifiques à X11>
my $mw = MainWindow->new();
MainLoop();
3.
Identique à 2) sauf que les arguments par défaut sont chargés en premier. 
use Tk;
Tk::CmdLine::SetArguments(qw(-name test -iconic));
Tk::CmdLine::SetArguments();
# <Traiter @ARGV - sans se soucier des options spécifiques à X11>
my $mw = MainWindow->new();
MainLoop();
4.
@ARGV est traité par Tk::CmdLine avant la création de MainWindow. Les fichiers de ressources standard sont chargés avant la création de MainWindow. 
use Tk;
Tk::CmdLine::SetArguments();
# <Traiter @ARGV - sans se soucier des options spécifiques à X11>
Tk::CmdLine::LoadResources();
my $mw = MainWindow->new();
MainLoop();
5.
@ARGV est traité par Tk::CmdLine avant la création de MainWindow. Les fichiers de ressources standard sont chargés avant la création de MainWindow en utilisant des priorités non par défaut. 
use Tk;
Tk::CmdLine::SetArguments();
# <Traiter @ARGV - sans se soucier des options spécifiques à X11>
Tk::CmdLine::LoadResources(-echo => \*STDOUT,
    -priority => 65, -symbol => 'XFILESEARCHPATH' );
Tk::CmdLine::LoadResources(-echo => \*STDOUT,
    -priority => 75, -symbol => 'XUSERFILESEARCHPATH' );
my $mw = MainWindow->new();
MainLoop();
6.
@ARGV est traité par Tk::CmdLine avant la création de MainWindow. Les fichiers de ressources standard sont chargés avant la création de MainWindow. Des ressources individuelles sont également chargées avant la création de MainWindow. 
use Tk;
Tk::CmdLine::SetArguments();
# <Traiter @ARGV - sans se soucier des options spécifiques à X11>
Tk::CmdLine::LoadResources();
Tk::CmdLine::SetResources( # définir une ressource unique
    '*Button*background: red',
    'widgetDefault' );
Tk::CmdLine::SetResources( # définir plusieurs ressources
    [ '*Button*background: red', '*Button*foreground: blue' ],
    'widgetDefault' );
my $mw = MainWindow->new();
MainLoop();

ENVIRONNEMENT

HOME (optionnel)
Répertoire personnel qui peut contenir les fichiers de configuration par défaut des applications utilisateur tels que $"HOME"/$"LANG"/<CLASS> ou $"HOME"/<CLASS>.
LANG (optionnel)
La langue actuelle (par défaut : C).
XFILESEARCHPATH (optionnel)
Liste de modèles de FileSpec (joints en utilisant le délimiteur de chemin dépendant du système d'exploitation, par exemple le deux-points sur UNIX) utilisés pour définir les fichiers de configuration par défaut des applications système.
XUSERFILESEARCHPATH (optionnel)
Liste de modèles de FileSpec (joints en utilisant le délimiteur de chemin dépendant du système d'exploitation, par exemple le deux-points sur UNIX) utilisés pour définir les fichiers de configuration par défaut des applications utilisateur.
XAPPLRESDIR (optionnel)
Répertoire contenant les fichiers de configuration par défaut des applications utilisateur tels que $"XAPPLRESDIR"/$"LANG"/<CLASS> ou $"XAPPLRESDIR"/<CLASS>.
