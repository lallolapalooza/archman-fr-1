NOM

Tk::DialogBox - créer et manipuler un écran de dialogue.

SYNTAXE

use Tk::DialogBox
...
$d = $top->DialogBox(-title => "Titre", -buttons => ["OK", "Annuler"]);
$w = $d->add(Widget, args)->pack;
...
$button = $d->Show;

DESCRIPTION

DialogBox est très similaire à Dialog, sauf qu'il permet n'importe quel widget dans le Frame supérieur. DialogBox crée deux Frames, top et bottom. Le Frame inférieur affiche tous les Boutons spécifiés, alignés de gauche à droite. Le Frame supérieur agit comme un conteneur pour tous les autres widgets qui peuvent être ajoutés avec la méthode add().

OPTIONS

Les options reconnues par DialogBox sont les suivantes :

-title
Spécifie le titre de la DialogBox. Si ce n'est pas défini, le nom du programme est utilisé.
-buttons
Les noms des boutons à afficher dans le Frame inférieur. C'est une référence à un tableau de chaînes contenant le texte à mettre sur chaque Bouton. Il n'y a pas de valeur par défaut. Si vous ne spécifiez aucun nom de bouton, aucun Bouton n'est affiché.
-default_button
Spécifie le Bouton par défaut qui est considéré comme invoqué lorsque l'utilisateur appuie sur <Retour> dans la DialogBox. Ce Bouton est mis en évidence. Si aucun bouton par défaut n'est spécifié, le premier élément du tableau dont la référence est passée à l'option -buttons est utilisé comme valeur par défaut.
-cancel_button
Spécifie le Bouton qui est considéré comme invoqué lorsque l'utilisateur ferme la DialogBox en utilisant le bouton de fermeture du gestionnaire de fenêtre. Si l'option -cancel_button n'est pas donnée, et s'il n'y a qu'un seul bouton configuré, alors ce bouton est également utilisé comme bouton d'annulation. Sinon, aucun bouton n'est considéré comme le bouton d'annulation ; dans ce cas, Show retourne simplement "undef" lorsque l'utilisateur ferme la DialogBox.
-command
Une fonction de rappel qui est exécutée après l'invocation d'une action pour fermer la DialogBox, mais avant de restaurer les informations de focus et de grab. Le bouton sélectionné est passé comme premier argument.
-focus
Spécifie le widget qui recevra le focus initial après avoir fait apparaître la DialogBox. Par défaut, le widget -default_button reçoit le focus initial.
-showcommand
Une fonction de rappel qui est exécutée avant d'afficher la DialogBox et d'attendre une entrée utilisateur. La DialogBox elle-même est passée comme premier argument.

MÉTHODES

DialogBox ne prend en charge que deux méthodes pour le moment :

add(widget, options)
Ajoute le widget indiqué par widget. Widget peut être le nom de n'importe quel widget Tk (standard ou contribué). options sont les options que le widget accepte. Le widget est annoncé comme un sous-widget de DialogBox. Le nom de widget est mis en minuscules et utilisé comme nom annoncé. Si plusieurs instances de widget sont créées dans la DialogBox, seule la dernière recevra le nom annoncé. add() n'effectue pas automatiquement le pack() ou le grid() de widget dans la DialogBox.
Show(?-global?)
Affiche le dialogue jusqu'à ce que l'utilisateur invoque l'un des Boutons dans le Frame inférieur. Si le type de grab -global est spécifié, alors Show utilise ce grab ; sinon, il utilise un grab local par défaut. Retourne le nom du Bouton invoqué.

Le dialogue réel est affiché en utilisant la méthode Popup. Toutes les autres options fournies à Show sont passées à Popup et peuvent être utilisées pour positionner le dialogue à l'écran. Veuillez lire Tk::Popup pour plus de détails.

Exit()
Ferme la boîte de dialogue, en émulant un clic sur le bouton par défaut.

WIDGETS ANN0NCÉS

top
La référence du sous-widget à la moitié supérieure du widget DialogBox, le Frame contenant les widgets ajoutés par la méthode add.
bottom
La référence du sous-widget à la moitié inférieure du widget DialogBox, le Frame contenant les widgets Bouton.
B_"texte-bouton"
Références individuelles aux sous-widgets des Boutons dans le widget DialogBox. Le nom du sous-widget est la chaîne B_ concaténée avec la valeur -text du Bouton.

BOGUES

Il n'y a aucun moyen de supprimer un widget une fois qu'il a été ajouté au Frame supérieur, sauf si vous accédez au sous-widget top et parcourez les widgets enfants.

Il n'y a aucun contrôle sur l'apparence des Boutons dans le Frame inférieur, ni aucun moyen de contrôler le placement des deux Frames l'un par rapport à l'autre.
