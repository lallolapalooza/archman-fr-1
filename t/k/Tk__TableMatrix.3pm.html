$table = $parent->TableMatrix(?options?);

Options spécifiques au widget

Commutateur: -autoclear
Nom: autoClear
Classe: AutoClear
Une valeur booléenne qui spécifie si la première pression de touche dans une cellule effacera le texte qui s'y trouvait auparavant. Par défaut à 0.
Commutateur: -bordercursor
Nom: borderCursor
Classe: Cursor
Spécifie le nom du curseur à afficher lorsque la souris survole les bordures, une indication visuelle que le redimensionnement interactif est autorisé (il est donc affecté par la valeur de -resizeborders). Par défaut à crosshair.
Commutateur: -borderwidth ou -bd
Nom: borderWidth
Classe: BorderWidth
Spécifie une valeur en pixels non négative ou une liste de valeurs indiquant la largeur de la bordure 3D à dessiner sur les cellules de tableau internes (si une telle bordure est dessinée ; l'option <Brelief> détermine généralement cela). Si une seule valeur est spécifiée, un rectangle de cette largeur sera dessiné. Si deux valeurs sont spécifiées, alors seuls les bords gauche et droit de la cellule auront des bordures. Si quatre valeurs sont spécifiées, alors les valeurs correspondent aux bords {gauche droite haut bas}. Ceci peut être remplacé par l'option borderwidth d'une balise. Il peut également être affecté par le -drawmode défini pour le tableau. Chaque valeur de la liste doit avoir l'une des formes acceptables par Tk_GetPixels.
Commutateur: -browsecommand ou -browsecmd

Classe: BrowseCommand

Nom: cache
Classe: Cache

Peut maintenir l'état lorsque -command et -variable sont tous deux vides. Le cache est automatiquement vidé lorsque la valeur de -cache ou -variable change, sinon vous devez explicitement appeler clear dessus. Par défaut à désactivé.
Commutateur: -colorigin

Classe: Origin
Spécifie quel indice de colonne doit être interprété comme la colonne la plus à gauche dans le tableau. Cette valeur est utilisée pour les indices utilisateurs dans le tableau. Par défaut à 0.
Commutateur: -cols
Nom: cols
Classe: Cols
Nombre de colonnes dans le tableau. Par défaut à 10.
Commutateur: -colseparator
Nom: colSeparator
Classe: Separator
Spécifie un caractère séparateur qui sera interprété comme le séparateur de colonne lors de la copie ou du collage de données dans un tableau. Par défaut, les colonnes sont séparées comme des éléments d'une liste tcl.
Commutateur: -colstretchmode
Nom: colStretchMode
Classe: StretchMode
Spécifie l'un des modes d'étirement suivants pour que les colonnes remplissent l'espace de fenêtre supplémentaire alloué :
aucun
Les colonnes ne s'étireront pas pour remplir l'espace de fenêtre alloué. Si les colonnes sont trop étroites, il y aura un espace vide à droite du tableau. C'est le mode par défaut.
non-défini
Seules les colonnes qui n'ont pas de largeur spécifique définie seront étirées.
tout
Toutes les colonnes seront étirées du même nombre de pixels pour remplir l'espace de fenêtre alloué au tableau. Ce mode peut interférer avec le redimensionnement interactif des bordures qui tente de forcer la largeur des colonnes.
dernier
La dernière colonne sera étirée pour remplir l'espace de fenêtre alloué au tableau.
remplir
(uniquement valide pour -rowstretch actuellement)

Le tableau gagnera ou perdra des colonnes en fonction de l'espace de fenêtre alloué au tableau. Ce mode présente de nombreux problèmes et pourrait disparaître à l'avenir.

Commutateur: -coltagcommand
Nom: colTagCommand
Classe: TagCommand
Fournit le nom d'une procédure qui sera évaluée par le widget pour déterminer la balise à utiliser pour une colonne donnée. Lors de l'affichage d'une cellule, le widget tableau vérifiera d'abord si une balise a été définie à l'aide de la méthode de widget tag col. Si aucune balise n'est trouvée, il évaluera la procédure nommée en passant le numéro de colonne concerné comme seul argument. La procédure est censée retourner le nom d'une balise à utiliser, ou une chaîne nulle. Les erreurs survenant lors de l'évaluation de la procédure, ou le retour d'un nom de balise invalide sont ignorés silencieusement.

Le numéro de colonne courant est passé en argument à la commande col.

Commutateur: -colwidth
Nom: colWidth
Classe: ColWidth
Largeur de colonne par défaut, interprétée en caractères dans la police par défaut lorsque le nombre est positif, ou en pixels s'il est négatif. Par défaut à 10.
Commutateur: -command
Nom: command
Classe: Command
Spécifie une commande à utiliser comme interface procédurale pour les valeurs des cellules. Si -usecommand est vrai, cette commande sera utilisée au lieu de toute référence au tableau associatif -variable. Lors de la récupération des valeurs des cellules, la valeur de retour de la commande est utilisée comme valeur pour la cellule.

Arguments passés à ce rappel : Le drapeau de définition (=1 si on définit, sinon si on récupère), la ligne courante, la colonne courante, la valeur de la cellule (si on définit).

Commutateur: -drawmode
Nom: drawMode
Classe: DrawMode
Définit le mode de dessin du tableau sur l'une des options suivantes :
lent
Le tableau est dessiné sur une pixmap hors écran en utilisant les fonctions de bordure de Tk (double-buffering). Cela signifie qu'il n'y aura pas de scintillement, mais ce mode est lent pour les grands tableaux.
compatible
Le tableau est dessiné directement à l'écran en utilisant les fonctions de bordure de Tk
ns. Il est plus rapide, mais l'écran peut clignoter lors de la mise à jour. C'est la valeur par défaut.
rapide
La table est dessinée directement à l'écran et les bordures sont réalisées avec des appels X rapides, elles sont donc toujours d'une seule largeur de pixel. En conséquence, cela restreint -borderwidth à une plage de 0 ou 1. Ce mode offre les meilleures performances pour les grandes tables, mais peut clignoter lors du redessin et n'est pas 100% compatible Tk concernant le mode de bordure.
simple
La table est dessinée à l'écran comme en mode rapide, mais seules des lignes d'un seul pixel sont dessinées (pas de bordures carrées).

DESCRIPTION

The TableMatrix command creates a 2-dimensional grid of cells. The table can use a Tcl array variable or Tcl command for data storage and retrieval. The widget has an active cell, the contents of which can be edited (when the state is normal). The widget supports a default style for the cells and also multiple tags, which can be used to change the style of a row, column or cell (see TAGS for details). A cell flash can be set up so that changed cells will change color for a specified amount of time ("blink").
Cells can have embedded images or windows, as described in Tags and "Embedded Windows" respectively.

One or more cells may be selected as described below.
If a table is exporting its selection (see -exportselection option), then it will observe the standard X11 protocols for handling the selection.
See "the Selection" for details. It is not necessary for all the cells to be displayed in the table window at once; commands described below may be used to change the view in the window. Tables allow scrolling in both directions using the standard -xscrollcommand and -yscrollcommand options.
They also support scanning, as described below.

In order to obtain good performance, the table widget supports multiple drawing modes, two of which are fully Tk compatible.

Indices

Many of the widget commands for tables take one or more indices as arguments. An index specifies a particular cell of the table, in any of the following ways:

number,number
Specifies the cell as a numerical index of row,col which corresponds to the index of the associated Perl Hash, where -roworigin,-colorigin corresponds to the first cell in the table (0,0 by default). The values for row and column will be constrained to actual values in the table, which means a valid cell is always found.
active
Indicates the cell that has the location cursor. It is specified with the activate widget command.
anchor
Indicates the anchor point for the selection, which is set with the selection anchor widget command.
bottomright
Indicates the bottom-rightmost cell visible in the table.
end
Indicates the bottom right cell of the table.
origin
Indicates the top-leftmost editable cell of the table, not necessarily in the display. This takes into account the user specified origin and title area.
topleft
Indicates the top-leftmost editable cell visible in the table (this excludes title cells).
@x,y
Indicates the cell that covers the point in the table window specified by x and y (in pixel coordinates). If no cell covers that point, then the closest cell to that point is used. In the widget command descriptions below, arguments named index, first, and last always contain text indices in one of the above forms.

Tags

A tag is a textual string that is associated with zero or more rows, columns or cells in a table. Tags may contain arbitrary characters, but it is probably best to avoid using names which look like indices to reduce coding confusion. There may be any number of tags in a table, but each row, column or cell can only have one tag associated with it at a time. There are several permanent tags in each table that can be configured by the user and will determine the attributes for special cells:

active
This tag is given to the active cell
flash
If flash mode is on, this tag is given to any recently edited cells.
sel
This tag is given to any selected cells.
title
This tag is given to any cells in the title rows and columns. This tag has -state disabled by default.

Tags control the way cells are displayed on the screen. Where appropriate, the default for displaying cells is determined by the options for the table widget. However, display options may be associated with individual tags using the tagConfigure method. If a cell, row or column has been tagged, then the display options associated with the tag override the default display style. The following options are currently supported for tags:

-anchor anchor
Anchor for item in the cell space.
-background or -bg color
Background color of the cell.
-borderwidth or -bd pixel
Borderwidth of the cell, of the same format for the table, but may also be empty to inherit the default table borderwidth value (the default).
-font fontName
Font for text in the cell.
-foreground or -fg color
Foreground color of the cell.
-justify justify
How to justify mu
lti-line text in a cell. It must be one of left, right, or center.
-image imageName
Une image à afficher dans la cellule au lieu du texte.
-multiline boolean
Indique s'il faut afficher le texte avec des sauts de ligne sur plusieurs lignes.
-relief
Le relief de la cellule. Peut être une chaîne vide pour que cette balise ne perturbe pas la valeur.
-showtext boolean
Indique s'il faut afficher le texte par-dessus une image.
-state state
L'état de la cellule, pour permettre la désactivation de certaines cellules. Ceci empêche la cellule d'être modifiée par les méthodes insert ou delete, mais une méthode set directe ne sera pas empêchée.
-wrap boolean
Indique si les caractères doivent passer à la ligne dans une cellule qui n'est pas assez large.

Un ordre de priorité est défini entre les balises en fonction de l'ordre de création (la première balise créée a la priorité la plus élevée par défaut), et cet ordre est utilisé pour implémenter certaines des fonctions liées aux balises décrites ci-dessous. Lorsqu'une cellule est affichée, ses propriétés sont déterminées par les balises qui lui sont attribuées. La priorité d'une balise peut être modifiée par les méthodes tagLower et tagRaise.

Si une cellule a plusieurs balises associées qui définissent les mêmes options d'affichage (par exemple, une cellule title avec des balises row et cell spécifiques), alors les options de la balise de priorité la plus élevée sont utilisées. Si une option d'affichage particulière n'a pas été spécifiée pour une balise particulière, ou si elle est spécifiée comme une chaîne vide, alors cette option ne sera pas utilisée ; l'option de la balise de priorité immédiatement inférieure sera utilisée à la place. Si aucune balise ne spécifie une option d'affichage particulière, le style par défaut du widget sera utilisé.

Les images sont utilisées uniquement à des fins d'affichage. La modification dans cette cellule restera activée et toute interrogation de la cellule montrera la valeur textuelle de la cellule, quel que soit le résultat de -showtext.

Note : Il ne peut y avoir qu'une seule balise pour un type de balise donné. (Types de balises = flash, active, sel, title, celltag rowtag, coltag.) Par exemple, vous ne pouvez pas appliquer deux balises de cellule à une seule cellule (ou deux balises de ligne à une seule ligne, etc.) et vous attendre à ce que les propriétés de la balise soient fusionnées. La dernière balise de type appliquée sera celle qui est utilisée.

Fenêtres intégrées

Il peut y avoir n'importe quel nombre de fenêtres intégrées dans un widget de table (une par cellule), et n'importe quel widget peut être utilisé comme fenêtre intégrée (sous réserve des règles habituelles de gestion de la géométrie, qui exigent que la fenêtre de la table soit le parent de la fenêtre intégrée ou un descendant de son parent). La position de la fenêtre intégrée sur l'écran sera mise à jour lorsque la table sera modifiée ou déplacée, et elle sera mappée et démappée lorsqu'elle entrera et sortira de la zone visible du widget de table. Chaque fenêtre intégrée occupe l'espace d'une cellule dans le widget de table, et elle est référencée par l'indice de la cellule dans la table. Les fenêtres associées au widget de table sont détruites lorsque le widget de table est détruit.

Les fenêtres sont utilisées uniquement à des fins d'affichage. Une valeur existe toujours pour cette cellule, mais ne sera pas affichée à moins que la fenêtre ne soit supprimée d'une manière ou d'une autre. Si la fenêtre est détruite ou perdue par le widget de table au profit d'un autre gestionnaire de géométrie, alors toute donnée qui lui est associée est perdue (la cellule qu'elle occupait n'apparaîtra plus dans les noms de fenêtres).

Lorsqu'une fenêtre intégrée est ajoutée à un widget de table avec la commande de configuration de widget de fenêtre, plusieurs options de configuration peuvent lui être associées. Ces options peuvent être modifiées par des appels ultérieurs à la commande de configuration de widget de fenêtre. Les options suivantes sont actuellement prises en charge :

-create callback
PAS ACTUELLEMENT PRIS EN CHARGE. Spécifie un script Tcl qui peut être évalué pour créer la fenêtre de l'annotation.
Si aucune option -window n'a été spécifiée pour cette cellule, ce script sera évalué lorsque la cellule sera sur le point d'être affichée à l'écran.

La sélection

Les sélections de table sont disponibles sous le type STRING. Par défaut, la valeur de la sélection sera les valeurs des cellules sélectionnées sous forme de liste Tcl imbriquée où chaque ligne est une liste et chaque colonne est un élément d'une liste de lignes. Vous pouvez modifier la façon dont cette valeur est interprétée en définissant les options -rowseparator et -colseparator.
Par exemple, le format Excel par défaut serait de définir -rowseparator à "\n" et -colseparator à "\t". La modification de ces valeurs affecte à la fois la façon dont la table envoie la sélection et lit les données collées, garantissant que la table devrait toujours être capable de se couper et de se coller à elle-même. Il est possible de modifier la façon dont les collages sont gérés en éditant la procédure de bibliothèque de table tk_tablePasteHandler . Cela peut être nécessaire si -selectioncommand est défini.

Chevauchement de lignes/colonnes

Des cellules individuelles peuvent chevaucher plusieurs lignes et/ou colonnes. Ceci est fait via la commande spans (voir ci-dessous pour les arguments exacts). Les cellules dans la zone de titre qui chevauchent ne sont pas autorisées à chevaucher au-delà de la zone de titre, et seront contraintes en conséquence. Si la zone de titre rétrécit lors d'une configuration, des vérifications de cohérence seront effectuées pour assurer ce qui précède. Vous pouvez définir des chevauchements sur des cellules régulières qui s'étendent au-delà de la zone de lignes/colonnes définie. Ces chevauchements ne seront pas contraints, de sorte que lorsque la zone de lignes/colonnes définie s'agrandira, le chevauchement s'agrandira avec elle.

Lors de la définition d'un chevauchement, des vérifications sont effectuées pour savoir si le chevauchement chevaucherait une cellule déjà chevauchante ou cachée. C'est une erreur et ce n'est pas autorisé. Les chevauchements peuvent affecter la vitesse globale du rendu de la table, bien que pas de manière significative. Si les chevauchements ne sont pas utilisés, il n'y a aucune perte de performance.

Les cellules cachées par des cellules qui chevauchent ont toujours des données valides. Cela sera vu lors des opérations de copier-coller impliquant des cellules cachées, ou par accès direct par une commande telle que get ou set.

Les propriétés d'affichage des cellules qui chevauchent s'appliquent uniquement à la zone visuelle de la cellule. Par exemple, si une cellule est centrée sur 5 colonnes, alors lors de la visualisation de toute partie de ces colonnes, elle apparaîtra centrée dans la zone visible. La zone de colonne non visible ne sera pas prise en compte dans les calculs de centrage.

Substitution de commande

Les diverses commandes basées sur les options que la table prend en charge prennent toutes en charge le modèle familier de substitution % de Tk (voir Tk::bind pour plus de détails).
Les séquences % suivantes sont reconnues et substituées par le widget de table :

%c
Pour SelectionCommand, il s'agit du nombre maximum de colonnes dans une ligne de la sélection. Sinon, c'est la colonne de la cellule déclenchée.
%C
Une substitution pratique pour %r,%c.
%i
Pour SelectionCommand, il s'agit du nombre total de cellules dans la sélection. Pour Command, c'est 0 pour une lecture (get) et 1 pour une écriture (set). Sinon, c'est la position actuelle du curseur dans la cellule.
%r
Pour SelectionCommand, il s'agit du nombre de lignes dans la sélection. Sinon, c'est la ligne de la cellule déclenchée.
%s
Pour ValidateCommand, il s'agit de la valeur actuelle de la cellule en cours de validation. Pour SelectionCommand, il s'agit de la valeur par défaut de la sélection. Pour BrowseCommand , il s'agit de l'indice de la dernière cellule active. Pour Command, elle est vide pour les lectures (get) et la valeur actuelle de la cellule pour les écritures (set).
%S
Pour ValidateCommand, il s'agit de la nouvelle valeur potentielle de la cellule en cours de validation. Pour BrowseCommand, il s'agit de l'indice de la nouvelle cellule active.
%W
Le chemin d'accès à la fenêtre pour laquelle la commande a été générée.

    -browsecmd  => \&browse_callback,
    -command    => \&data_callback,
    -selectmode => 'cell',
    -titlerows  => 1,
    -titlecols  => 1,

STANDARD OPTIONS

Tk::TableMatrix supports the standard Tk options -background, -borderwidth, -cursor, -exportselection, -font, -foreground, -height, -highlightbackground, -highlightcolor, -highlightthickness, -padx, -pady, -relief, -takefocus, -width.

Widget-specific Options

The following options are specific to the Tk::TableMatrix widget:

-browsecmd cmd
Command to execute when a cell is browsed (mouse pointer hovers over it). The command is called with the row and column number of the cell.
-cache boolean
If true, enables caching of cell values. This can significantly improve performance if the same cells are accessed frequently. Defaults to true.
-cellrows integer
Number of rows to display per cell. Defaults to 1.
-cellcolumns integer
Number of columns to display per cell. Defaults to 1.
-colorigin integer
The column index of the origin for coloring. Defaults to 0.
-command cmd
Command to execute when a cell value needs to be retrieved. The command is called with the row and column number of the cell and should return the cell's value. If this option is not set, cells are assumed to be empty by default.
-cursor cursorName
Specifies the cursor to be displayed when the mouse pointer is over the widget. Default is "".
-editcmd cmd
Command to execute when a cell is edited. The command is called with the row, column, and the new value of the cell.
-editfont fontName
Font to be used for editing text in a cell. Defaults to the widget's font.
-editpadx amount
Internal padding for the editing entry widget. Defaults to 0.
-editpady amount
Internal padding for the editing entry widget. Defaults to 0.
-fixedrows integer
Number of rows at the top that are fixed and do not scroll. Defaults to 0.
-fixedcols integer
Number of columns on the left that are fixed and do not scroll. Defaults to 0.
-height amount
Desired height of the widget in screen units. Default is 10 rows.
-insertofftime milliseconds
The time in milliseconds that the insert cursor is off. Default is 500.
-insertontime milliseconds
The time in milliseconds that the insert cursor is on. Default is 500.
-insertwidth amount
Width of the insert cursor. Defaults to 2 pixels.
-ipadx amount
Internal padding of the cell. Defaults to 0.
-ipady amount
Internal padding of the cell. Defaults to 0.
-label text
Text to display in the cell. If not specified, the cell is empty.
-labelvariable varName
Name of a scalar Tk variable. If this option is set, the variable is updated with the cell's text and changes to the variable are reflected in the cell.
-mode mode
Specifies the selection mode. Can be cell, row, column, or table. Default is cell.
-orient orientation
Specifies the orientation of the widget. Can be horizontal or vertical. Default is vertical.
-padx amount
External padding of the cell. Defaults to 0.
-pady amount
External padding of the cell. Defaults to 0.
-raised boolean
If true, the cell will be raised. Defaults to false.
-roworigin integer
The row index of the origin for coloring. Defaults to 0.
-rows integer
Number of rows in the table. Defaults to 10.
-resizeborders options
Specifies how borders can be resized. Can be none, rows, cols, or both. Defaults to none.
-selectbackground color

-selectborderwidth amount
Border width for selected cells. Defaults to 0.
-selectforeground color
Foreground color for selected cells. Defaults to system default.
-selectmode mode

-titlerows integer

-width amount
Desired width of the widget in screen units. Default is 10 columns.
-wrapmode mode
Specifies the wrapping mode for text in cells. Can be none, char, or word. Default is none.

DESCRIPTION

The Tk::TableMatrix widget displays a table of information. It is highly configurable and can be used for a variety of purposes, from simple data display to complex interactive forms.

The table is organized into rows and columns. Each cell in the table can contain text or other Tk widgets. The widget provides methods for accessing and modifying cell values, controlling scrolling, and handling user interactions.

The table can have title rows and columns, which are fixed at the top and left edges, respectively. These are often used for row and column headers.

The selection mode determines how users can select cells, rows, or columns. The widget also supports editing of cell values, either directly or through a command callback.

INDICES

Many of the methods below take indices to specify cells, rows, or columns. Indices can be given in several forms:

rowNum
A non-negative integer specifying the row number. Row 0 is the topmost row.
colNum
A non-negative integer specifying the column number. Column 0 is the leftmost column.
end
The index of the last row or column.
first
Synonym for 0.
rowNumj
The index of the last row that is greater than or equal to rowNum.
colNumj
The index of the last column that is greater than or equal to colNum.
rowNumlin
The index of the first row that is greater than or equal to rowNum.
colNumlin
The index of the first column that is greater than or equal to colNum.
rowNumc
The index of the first row that is greater than or equal to rowNum.
colNumc
The index of the first column that is greater than or equal to colNum.
active
The row or column containing the active cell.
anchor
The anchor row or column for a selection.
current
The current row or column (where the mouse is pointing).

Ranges of rows or columns can be specified using two indices separated by a colon, e.g., 5:10 for rows 5 through 10. If only one index is given, it refers to a single cell, row, or column depending on the context.

Tags

Cells can be tagged to apply specific configurations or actions to groups of cells. The following tags are supported:

-background color
Background color for the tagged cells.
-command cmd
Command to execute when a tagged cell is accessed.
-font fontName
Font for the tagged cells.
-foreground color
Foreground color for the tagged cells.
-height amount
Height of the tagged cells.
-justify justify
Justification of text in the tagged cells (left, center, right). Default is left.
-label text
Text to display in the tagged cells.
-relief relief
Relief style for the tagged cells (flat, raised, sunken, ridge, solid, groove).
-state state
State of the tagged cells (normal, disabled).
-width amount
Width of the tagged cells.

Tags can be applied to individual cells, rows, or columns. For example, to set the background color of row 5 to red:

 $table->tag('row', 5, -background => 'red')

To set the background color of all cells in column 3 to blue:

 $table->tag('column', 3, -background => 'blue')

To set the background color of cell (2, 4) to green:

 $table->tag('cell', 2, 4, -background => 'green')

Embedded Windows

Tk::TableMatrix allows embedding other Tk widgets within its cells. This is done using the -window option when configuring a cell.

my $button = $table->new_child(Tk::Button, -text => 'Click Me');
$table->window(2, 3, $button);

When a cell contains a widget, the widget's geometry is managed by the TableMatrix widget. The size of the cell will adjust to accommodate the embedded widget.

the Selection

The selection can be managed using the following methods:

$table->selectionClear(?firstItem ?lastItem?)
Clears the selection in the specified range. If no range is specified, the entire selection is cleared.
$table->selectionIncludes(item)
Returns true if the specified item is selected, false otherwise.
$table->selectionSet(firstItem ?lastItem?)
Selects the specified range of items. If lastItem is omitted, only firstItem is selected.

Row/Col Spanning

Cells can span multiple rows and columns using the span method.

$table->span(firstRow, firstCol, lastRow, lastCol)
Makes the cell at (firstRow, firstCol) span across the rectangle defined by (firstRow, firstCol) and (lastRow, lastCol).
$table->unspan(row, col)
Removes any row or column spanning from the cell at (row, col).

Command Substitution

Tk::TableMatrix uses command substitution to get and set cell values. When the -command option is set, it is called to retrieve the value of a cell when it needs to be displayed. When a cell is edited, the -editcmd is called with the new value.

Widget Methods

In addition to the standard Tk widget methods, Tk::TableMatrix supports the following:

$table->cell(row, col, ?option?, ?value?, ...)
Get or set options for a specific cell. If no options are provided, returns a list of current options for the cell.
$table->cellcget(row, col, option)
Returns the value of the specified option for the cell at (row, col).
$table->cellconfigure(row, col, ?option?, ?value?, ...)
Same as cell.
$table->cget(option)
Returns the value of the specified widget option.
$table->configure(?option?, ?value?, ...)
Set or get widget options. If no options are provided, returns a list of all options and their values.
$table->delete(firstRow, firstCol, lastRow, lastCol)
Deletes the specified cells.
$table->get(firstRow, firstCol, lastRow, lastCol)
Returns the values of the specified cells.
$table->insert(row, col, ?option?, ?value?, ...)
Inserts a new cell at the specified position with the given options.
$table->scan(cmd, ?args?)
Perform scanning operations. Supported commands include mark, dragto.
$table->see(row, col)
Ensures that the specified cell is visible within the widget's window.
$table->set(firstRow, firstCol, lastRow, lastCol, ?option?, ?value?, ...)
Sets the values and/or options for the specified cells.
$table->xview(?args?)
This command is used to query and change the horizontal position of the text in the widget's window. It can take any of the following forms:
$table->xview()
Returns a list containing two elements, both of which are real fractions between 0 and 1. The first element gives the position of the table element at the left edge of the window, relative to the table as a whole (0.6 means 60% of the table's text is off-screen to the left, the middle 40% is visible in the window, and 40% of the text is off-screen to the right. These are the same values passed to scrollbars via the -xscrollcommand option.
$table->xview(index)
Adjusts the view in the window so that the column given by index is displayed at the left edge of the window.
$table->xviewMoveto(fraction)
Adjusts the view in the window so that fraction of the total width of the table text is off-screen to the left. fraction must be a fraction between 0 and 1.
$table->xviewScroll(number, what)
This command shifts the view in the window left or right according to number and what. Number must be an integer. What must be either units or pages or an abbreviation of one of these. If what is units, the view adjusts left or right by number cells on the display; if it is pages then the view adjusts by number screenfuls. If number is negative then cells farther to the left become visible; if it is positive then cells farther to the right become visible.
$table->yview(?args?)
This command is used to query and change the vertical position of the text in the widget's window. It can take any of the following forms:
$table->yview()
Returns a list containing two elements, both of which are real fractions between 0 and 1. The first element gives the position of the table element at the top of the window, relative to the table as a whole (0.5 means it is halfway through the table, for example). The second element gives the position of the table element just after the last one in the window, relative to the table as a whole. These are the same values passed to scrollbars via the -yscrollcommand option.
$table->yview(index)
Adjusts the view in the window so that the row given by index is displayed at the top of the window.
$table->yviewMoveto(fraction)
Adjusts the view in the window so that the element given by fraction appears at the top of the window. Fraction is a fraction between 0 and 1; 0 indicates the first element in the table, 0.33 indicates the element one-third the way through the table, and so on.
$table->yviewscroll(number, what)
This command adjusts the view in the window up or down according to number and what. Number must be an integer. What must be either units or pages. If what is units, the view adjusts up or down by number cells; if it is pages then the view adjusts by number screenfuls. If number is negative then earlier elements become visible; if it is positive then later elements become visible.

Default Bindings

The initialization creates class bindings that give the following default behaviour:

[1]
Clicking Button-1 in a cell activates that cell. Clicking into an already active cell moves the insertion cursor to the character nearest the mouse.
[2]
Moving the mouse while Button-1 is pressed will stroke out a selection area. Exiting while Button-1 is pressed causing scanning to occur on the table along with selection.
[3]
Moving the mouse while Button-2 is pressed causes scanning to occur without any selection.
[4]
Home moves the table to have the origin in view.
[5]
End moves the table to have the end cell in view.
[6]
Control-Home moves the table to the origin and activates that cell.
[7]
Control-End moves the table to the end and activates that cell.
[8]
Shift-Control-Home extends the selection to the origin.
[9]
Shift-Control-End extends the selection to the end.
[10]
The left, right, up and down arrows move the active cell.
[11]
Shift-<arrow> extends the selection in that direction.
[12]
Control-leftarrow and Control-rightarrow move the insertion cursor within the cell.
[13]
Control-slash selects all the cells.
[14]
Control-backslash clears selection from all the cells.
[15]
Backspace deletes the character before the insertion cursor in the active cell.
[16]
Delete deletes the character after the insertion cursor in the active cell.
[17]
Escape rereads the value of the active cell from the specified data source, discarding any edits that have may been performed on the cell.
[18]
Control-a moves the insertion cursor to the beginning of the active cell.
[19]
Control-e moves the insertion cursor to the end of the active cell.
[20]
Control-minus and Control-equals decrease and increase the width of the column with the active cell in it.
[21]
Moving the mouse while Button-3 (the right button on Windows) is pressed while you are over a border will cause interactive resizing of that row and/or column to occur, based on the value of -resizeborders. Some bindings may have slightly different behavior dependent on the -selectionmode of the widget. If the widget is disabled using the -state option, then its view can still be adjusted and cells can still be selected, but no insertion cursor will be displayed and no cell modifications will take place. The behavior of tables can be changed by defining new bindings for individual widgets or by redefining the class bindings. The default bindings are either compiled in the TableMatrix.pm file

Performance Issues

The number of rows and columns or a table widget should not significantly affect the speed of redraw. Recalculation and redraw of table parameters and cells is restricted as much as possible. The display cell with the insert cursor is redrawn each time the cursor blinks, which causes a steady stream of graphics traffic. Set the -insertofftime option to 0 avoid this. The use of a -command with the table without a cache can cause significant slow-down, as the command is called once for each request of a cell value.

Examples

Set the topleft title area to be one spanning cell. This overestimates both row and column span by one, but the command does all the constraining for us. $table span [$table cget -roworigin],[$table cget -colorigin] [$table cget -titlerows],[$table cget -titlecols] Force a table window refresh (useful for the slight chance that a bug in the table is not causing proper refresh): $table configure -padx [$table cget -padx]
