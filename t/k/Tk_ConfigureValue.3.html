Tk_ConfigureWidget(3) Procédures de la bibliothèque Tk Tk_ConfigureWidget(3)

NOM

Tk_ConfigureWidget, Tk_ConfigureInfo, Tk_ConfigureValue, Tk_FreeOptions - traiter les options de configuration des widgets

SYNOPSIS

#include <tk.h>

int
Tk_ConfigureWidget(interp, tkwin, specs, argc, argv, widgRec, flags)

int
Tk_ConfigureInfo(interp, tkwin, specs, widgRec, argvName, flags)

int
Tk_ConfigureValue(interp, tkwin, specs, widgRec, argvName, flags)

Tk_FreeOptions(specs, widgRec, display, flags)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur à utiliser pour renvoyer les messages d'erreur.
Tk_Window tkwin (in)
Fenêtre utilisée pour représenter le widget (nécessaire pour configurer les ressources X).
const Tk_ConfigSpec *specs (in)
Pointeur vers la table spécifiant les options de configuration légales pour ce widget.
int argc (in)
Nombre d'arguments dans argv.
const char **argv (in)
Options de ligne de commande pour configurer le widget.
char *widgRec (in/out)
Pointe vers la structure d'enregistrement du widget. Les champs de cette structure sont modifiés par Tk_ConfigureWidget pour contenir les informations de configuration.
int flags (in)
Si différent de zéro, alors il spécifie une combinaison OR de drapeaux qui contrôlent le traitement des informations de configuration. TK_CONFIG_ARGV_ONLY ignore la base de données d'options et les valeurs par défaut, et les bits de drapeau TK_CONFIG_USER_BIT et supérieurs sont utilisés pour désactiver sélectivement les entrées dans specs.
type name type (in)
Le nom du type d'un enregistrement de widget.
field name field (in)
Le nom d'un champ dans les enregistrements de type type.
const char *argvName (in)
Le nom utilisé sur les lignes de commande Tcl pour faire référence à une option particulière (par exemple, lors de la création d'un widget ou de l'invocation de la commande configure du widget). Si non NULL, alors des informations sont renvoyées uniquement pour cette option. Si NULL, alors des informations sont renvoyées pour toutes les options disponibles.
Display *display (in)
Affichage contenant le widget dont l'enregistrement doit être libéré ; nécessaire pour libérer les ressources.

DESCRIPTION

Note : Tk_ConfigureWidget devrait être remplacé par la nouvelle API basée sur Tcl_Obj, Tk_SetOptions. L'ancienne interface est conservée pour des raisons de compatibilité ascendante.

Tk_ConfigureWidget est appelée pour configurer divers aspects d'un widget, tels que les couleurs, les polices, la largeur des bordures, etc. Elle est conçue comme une procédure utilitaire pour réduire la quantité de code qui doit être écrite dans les gestionnaires de widgets individuels pour gérer les informations de configuration. Elle est généralement invoquée lors de la création des widgets, et à nouveau lorsque la commande configure est invoquée pour un widget. Bien qu'elle soit principalement destinée aux widgets, Tk_ConfigureWidget peut être utilisée dans d'autres situations où les informations argc-argv doivent être utilisées pour remplir une structure d'enregistrement, comme la configuration d'éléments graphiques pour un widget canvas ou d'entrées d'un menu.

Tk_ConfigureWidget traite une table spécifiant les options de configuration supportées (specs) et un ensemble d'arguments de ligne de commande (argc et argv) pour remplir les champs d'un enregistrement (widgRec). Elle utilise la base de données d'options et les valeurs par défaut spécifiées dans specs pour remplir les champs de widgRec qui ne sont pas spécifiés dans argv. Tk_ConfigureWidget renvoie normalement la valeur TCL_OK ; dans ce cas, elle ne modifie pas interp. Si une erreur se produit, TCL_ERROR est renvoyé et Tk_ConfigureWidget laissera un message d'erreur dans le résultat de l'interpréteur interp, à la manière standard de Tcl. En cas de retour d'erreur, certains des champs de widgRec pourraient déjà avoir été définis, si les informations de configuration les concernant ont été traitées avec succès avant que l'erreur ne se produise. Les autres champs seront définis à des valeurs initiales raisonnables afin que Tk_FreeOptions puisse être appelée pour le nettoyage.

Le tableau specs spécifie les types d'options de configuration supportées par le widget. Chacune de ses entrées spécifie une option de configuration et a la structure suivante :

typedef struct {
    int type;
    const char *argvName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int offset;
    int specFlags;
    const Tk_CustomOption *customPtr;
} Tk_ConfigSpec;
Le champ type indique le type d'option de configuration (par exemple, TK_CONFIG_COLOR pour une valeur de couleur, ou TK_CONFIG_INT pour une valeur entière). Le champ type indique comment utiliser la valeur de l'option (plus à ce sujet ci-dessous). Le champ argvName est une chaîne telle que “-font” ou “-bg”, qui est comparée aux valeurs dans argv (si argvName est NULL, cela signifie qu'il s'agit d'une entrée groupée ; voir ENTRÉES GROUPÉES ci-dessous). Les champs dbName et dbClass sont utilisés pour rechercher une valeur pour cette option dans la base de données d'options. Le champ defValue spécifie une valeur par défaut pour cette option de configuration si aucune valeur n'est spécifiée dans argv ou dans la base de données d'options. Offset indique où dans widgRec stocker les informations sur cette option, et specFlags contient des informations supplémentaires pour contrôler le traitement de cette option de configuration (voir DRAPEAUX ci-dessous). Le dernier champ, customPtr, n'est utilisé que si type est TK_CONFIG_CUSTOM ; voir TYPES D'OPTIONS PERSONNALISÉES ci-dessous.

Tk_ConfigureWidget traite d'abord argv pour voir quelles options de configuration (le cas échéant) y sont spécifiées. Argv doit contenir un nombre pair de champs ; le premier de chaque paire de champs doit correspondre à argvName d'une entrée dans specs (des abréviations uniques sont acceptables), et le second champ de la paire contient la valeur pour cette option de configuration. S'il y a des entrées dans spec pour lesquelles il n'y avait pas d'entrées correspondantes dans argv, Tk_ConfigureWidget utilise les champs dbName et dbClass de l'entrée specs pour sonder la base de données d'options ; si une valeur est trouvée, elle est utilisée comme valeur pour l'option. Enfin, si aucune entrée n'est trouvée dans la base de données d'options, le champ defValue de l'entrée specs est utilisé comme valeur pour l'option de configuration. Si defValue est NULL, ou si le bit TK_CONFIG_DONT_SET_DEFAULT est défini dans flags, alors il n'y a pas de valeur par défaut et cette entrée specs sera ignorée si aucune valeur n'est spécifiée dans argv ou dans la base de données d'options.

Une fois qu'une valeur de chaîne a été déterminée pour une option de configuration, Tk_ConfigureWidget traduit la valeur de chaîne en une forme plus utile, telle qu'une couleur si type est TK_CONFIG_COLOR ou un entier si type est TK_CONFIG_INT. Cette valeur est ensuite stockée dans l'enregistrement pointé par widgRec. Cet enregistrement est supposé contenir des informations pertinentes pour le gestionnaire du widget ; son type exact est inconnu de Tk_ConfigureWidget. Le champ offset de chaque entrée specs indique où dans widgRec stocker les informations sur cette option de configuration. Vous devriez utiliser la macro Tk_Offset pour générer les valeurs offset (voir ci-dessous pour une description de Tk_Offset). L'emplacement indiqué par widgRec et offset sera appelé la “cible” dans les descriptions ci-dessous.

Le champ type de chaque entrée dans specs détermine ce qu'il faut faire avec la valeur de chaîne de cette option de configuration. Les valeurs légales pour type, et les actions correspondantes, sont :

TK_CONFIG_ACTIVE_CURSOR
La valeur doit être une chaîne ASCII identifiant un curseur dans une forme appropriée pour être passée à Tk_GetCursor. La valeur est convertie en un Tk_Cursor en appelant Tk_GetCursor et le résultat est stocké dans la cible. De plus, le curseur résultant est défini comme curseur actif pour tkwin en appelant XDefineCursor. Si TK_CONFIG_NULL_OK est spécifié dans specFlags, alors la valeur peut être une chaîne vide, auquel cas la cible et le curseur actif de tkwin seront définis sur None. Si la valeur précédente de la cible n'était pas None, alors elle est libérée en la passant à Tk_FreeCursor.
TK_CONFIG_ANCHOR
La valeur doit être une chaîne ASCII identifiant un point d'ancrage d'une des manières acceptées par Tk_GetAnchor. La chaîne est convertie en un Tk_Anchor

par appel de Tk_GetAnchor et le résultat est stocké dans la cible.
TK_CONFIG_BITMAP
La valeur doit être une chaîne de caractères ASCII identifiant une bitmap sous une forme appropriée pour être passée à Tk_GetBitmap. La valeur est convertie en Pixmap par appel de Tk_GetBitmap et le résultat est stocké dans la cible. Si TK_CONFIG_NULL_OK est spécifié dans specFlags alors la valeur peut être une chaîne de caractères vide, dans ce cas la cible est définie sur None. Si la valeur précédente de la cible n'était pas None, alors elle est libérée en la passant à Tk_FreeBitmap.
TK_CONFIG_BOOLEAN
La valeur doit être une chaîne de caractères ASCII spécifiant une valeur booléenne. N'importe laquelle des valeurs «true», «yes», «on», ou «1», ou une abréviation d'une de ces valeurs, signifie vrai ; n'importe laquelle des valeurs «false», «no», «off», ou «0», ou une abréviation d'une de ces valeurs, signifie faux. La cible est attendue comme un entier ; pour les valeurs vraies elle sera définie à 1 et pour les valeurs fausses elle sera définie à 0.
TK_CONFIG_BORDER
La valeur doit être une chaîne de caractères ASCII identifiant une couleur de bordure sous une forme appropriée pour être passée à Tk_Get3DBorder. La valeur est convertie en (Tk_3DBorder *) par appel de Tk_Get3DBorder et le résultat est stocké dans la cible. Si TK_CONFIG_NULL_OK est spécifié dans specFlags alors la valeur peut être une chaîne de caractères vide, dans ce cas la cible sera définie sur NULL. Si la valeur précédente de la cible n'était pas NULL, alors elle est libérée en la passant à Tk_Free3DBorder.
TK_CONFIG_CAP_STYLE
La valeur doit être une chaîne de caractères ASCII identifiant un style de terminaison (cap style) dans l'une des manières acceptées par Tk_GetCapStyle. La chaîne est convertie en une valeur entière correspondant au style de terminaison par appel de Tk_GetCapStyle et le résultat est stocké dans la cible.
TK_CONFIG_COLOR
La valeur doit être une chaîne de caractères ASCII identifiant une couleur sous une forme appropriée pour être passée à Tk_GetColor. La valeur est convertie en (XColor *) par appel de Tk_GetColor et le résultat est stocké dans la cible. Si TK_CONFIG_NULL_OK est spécifié dans specFlags alors la valeur peut être une chaîne de caractères vide, dans ce cas la cible sera définie sur None. Si la valeur précédente de la cible n'était pas NULL, alors elle est libérée en la passant à Tk_FreeColor.
TK_CONFIG_CURSOR
Cette option est identique à TK_CONFIG_ACTIVE_CURSOR sauf que le nouveau curseur n'est pas rendu actif pour tkwin.
TK_CONFIG_CUSTOM
Cette option permet aux applications de définir de nouveaux types d'options. Le champ customPtr des entrées pointe vers une structure définissant le nouveau type d'option. Voir la section TYPES D'OPTIONS PERSONNALISÉES ci-dessous pour les détails.
TK_CONFIG_DOUBLE
La valeur doit être un nombre à virgule flottante ASCII dans le format accepté par strtol. La chaîne est convertie en une valeur double, et la valeur est stockée dans la cible.
TK_CONFIG_END
Marque la fin de la table. La dernière entrée dans specs doit avoir ce type ; tous ses autres champs sont ignorés et elle ne correspondra jamais à aucun argument.
TK_CONFIG_FONT
La valeur doit être une chaîne de caractères ASCII identifiant une police sous une forme appropriée pour être passée à Tk_GetFont. La valeur est convertie en Tk_Font par appel de Tk_GetFont et le résultat est stocké dans la cible. Si TK_CONFIG_NULL_OK est spécifié dans specFlags alors la valeur peut être une chaîne de caractères vide, dans ce cas la cible sera définie sur NULL. Si la valeur précédente de la cible n'était pas NULL, alors elle est libérée en la passant à Tk_FreeFont.
TK_CONFIG_INT
La valeur doit être une chaîne entière ASCII dans le format accepté par strtol (par ex. les préfixes «0» et «0x» peuvent être utilisés pour spécifier des nombres octaux ou hexadécimaux, respectivement). La chaîne est convertie en une valeur entière et l'entier est stocké dans la cible.
TK_CONFIG_JOIN_STYLE
La valeur doit être une chaîne de caractères ASCII identifiant un style de jointure dans l'une des manières acceptées par Tk_GetJoinStyle. La chaîne est convertie en une valeur entière correspondant au style de jointure par appel de Tk_GetJoinStyle et le résultat est stocké dans la cible.
TK_CONFIG_JUSTIFY
La valeur doit être une chaîne de caractères ASCII identifiant une méthode de justification dans l'une des manières acceptées par Tk_GetJustify. La chaîne est convertie en une Tk_Justify par appel de Tk_GetJustify et le résultat est stocké dans la cible.
TK_CONFIG_MM
La valeur doit spécifier une distance à l'écran dans l'une des formes acceptables pour Tk_GetScreenMM. La chaîne est convertie en une distance en virgule flottante double précision en millimètres et la valeur est stockée dans la cible.
TK_CONFIG_PIXELS
La valeur doit spécifier des unités à l'écran dans l'une des formes acceptables pour Tk_GetPixels. La chaîne est convertie en une distance entière en pixels et la valeur est stockée dans la cible.
TK_CONFIG_RELIEF
La valeur doit être une chaîne de caractères ASCII identifiant un relief sous une forme appropriée pour être passée à Tk_GetRelief. La valeur est convertie en une valeur entière de relief par appel de Tk_GetRelief et le résultat est stocké dans la cible.
TK_CONFIG_STRING
Une copie de la valeur est faite en allouant de l'espace mémoire avec Tcl_Alloc et en copiant la valeur dans l'espace alloué dynamiquement. Un pointeur vers la nouvelle chaîne est stocké dans la cible. Si TK_CONFIG_NULL_OK est spécifié dans specFlags alors la valeur peut être une chaîne de caractères vide, dans ce cas la cible sera définie sur NULL. Si la valeur précédente de la cible n'était pas NULL, alors elle est libérée en la passant à Tcl_Free.
TK_CONFIG_SYNONYM
Cette valeur de type identifie des entrées spéciales dans specs qui sont des synonymes pour d'autres entrées. Si une valeur d'argv correspond à argvName d'une entrée TK_CONFIG_SYNONYM, l'entrée n'est pas utilisée directement. Au lieu de cela, Tk_ConfigureWidget recherche dans specs une autre entrée dont argvName est le même que le champ dbName dans l'entrée TK_CONFIG_SYNONYM ; cette nouvelle entrée est utilisée comme si son argvName avait correspondu à la valeur argv. Le mécanisme de synonyme permet à plusieurs valeurs argv d'être utilisées pour une seule option de configuration, telle que «-background» et «-bg».
TK_CONFIG_UID
La valeur est traduite en un Tk_Uid (en la passant à Tk_GetUid). La valeur résultante est stockée dans la cible. Si TK_CONFIG_NULL_OK est spécifié dans specFlags et que la valeur est une chaîne de caractères vide alors la cible sera définie sur NULL.
TK_CONFIG_WINDOW
La valeur doit être un nom de chemin de fenêtre. Elle est traduite en un jeton Tk_Window et le jeton est stocké dans la cible.

ENTRÉES GROUPÉES

Dans certains cas, il est utile de générer plusieurs ressources à partir d'une seule valeur de configuration. Par exemple, un nom de couleur pourrait être utilisé à la fois pour générer la couleur d'arrière-plan d'un widget (en utilisant TK_CONFIG_COLOR) et pour générer une bordure 3D à dessiner autour du widget (en utilisant TK_CONFIG_BORDER). Dans des cas comme celui-ci, il est possible de spécifier que plusieurs entrées consécutives dans specs doivent être traitées comme un groupe. La première entrée est utilisée pour déterminer une valeur (en utilisant ses champs argvName, dbName, dbClass et defValue). La valeur sera traitée plusieurs fois (une fois pour chaque entrée du groupe), générant ainsi plusieurs ressources différentes et modifiant plusieurs cibles au sein de widgRec. Chacune des entrées après la première doit avoir une valeur NULL dans son champ argvName ; cela indique que l'entrée doit être groupée avec l'entrée qui la précède. Seuls les champs type et offset sont utilisés à partir de ces entrées suivantes.

INDICATEURS

L'argument flags passé à Tk_ConfigureWidget est utilisé conjointement avec les champs specFlags dans les entrées de specs pour fournir un contrôle supplémentaire sur le traitement des options de configuration. Ces valeurs sont utilisées de trois manières différentes comme décrit ci-dessous.

Premièrement, si l'argument flags de Tk_ConfigureWidget a le bit TK_CONFIG_ARGV_ONLY défini (c'est-à-dire flags | TK_CONFIG_ARGV_ONLY != 0), alors la base de données d'options et les champs defValue ne sont pas utilisés. Dans ce cas, si une entrée dans specs ne correspond pas à un champ dans argv alors rien ne se passe : la cible correspondante n'est pas modifiée. Cette fonctionnalité est utile lorsque l'objectif est de modifier certaines options de configuration tout en laissant les autres dans leur état actuel, par exemple lors du traitement d'une commande de widget configure.

Deuxièmement, le champ specFlags d'une entrée dans specs peut être utilisé pour contrôler le traitement de cette entrée. Chaque champ specFlags peut être une combinaison OR-ée des valeurs suivantes :

TK_CONFIG_COLOR_ONLY
Si ce bit est défini, l'entrée ne sera considérée que si l'affichage pour tkwin a plus d'un plan de bits. Si l'affichage est monochromatique, alors cette entrée specs sera ignorée.
TK_CONFIG_MONO_ONLY
TK_CONFIG_NULL_OK
Ce bit n'est pertinent que pour certains types d'entrées (voir les descriptions des différents types d'entrées). Si ce bit est défini, il indique qu'une valeur vide pour le champ est acceptable et, le cas échéant, la cible doit être définie à NULL ou None, selon le type de la cible. Ce drapeau est généralement utilisé pour permettre à une fonctionnalité d'être complètement désactivée, par exemple, en définissant une valeur de pointeur de curseur à None afin qu'une fenêtre hérite simplement de son curseur parent. Si ce bit n'est pas défini, les valeurs vides sont traitées comme des chaînes de caractères, ce qui entraîne généralement une erreur.
TK_CONFIG_DONT_SET_DEFAULT
Si ce bit est actif, cela signifie que le champ defValue de l'entrée ne doit être utilisé que pour retourner la valeur par défaut dans Tk_ConfigureInfo. Dans les appels à Tk_ConfigureWidget, aucune valeur par défaut ne sera fournie pour les entrées avec ce bit actif ; on supposera que l'appelant a déjà fourni une valeur par défaut à l'emplacement de la cible. Ce drapeau offre une optimisation des performances lorsque le traitement de la valeur de chaîne par défaut est coûteux : le client peut calculer la valeur par défaut une fois, stocker la valeur et la fournir avant d'appeler Tk_ConfigureWidget.
TK_CONFIG_OPTION_SPECIFIED
Ce bit est obsolète. Auparavant, il était défini et effacé par Tk_ConfigureWidget afin que les appelants puissent détecter quelles entrées étaient spécifiées dans argv, mais il a été supprimé car il était intrinsèquement non sûr pour les threads. Le code qui souhaite détecter quelles options étaient spécifiées doit utiliser Tk_SetOptions à la place.

Les drapeaux TK_CONFIG_MONO_ONLY et TK_CONFIG_COLOR_ONLY sont généralement utilisés pour spécifier différentes valeurs par défaut pour les affichages monochromes et couleur. Ceci est accompli en créant deux entrées dans specs qui sont identiques sauf que leurs champs defValue et specFlags sont différents. L'un doit avoir la valeur TK_CONFIG_MONO_ONLY dans son champ specFlags et la valeur par défaut pour les affichages monochromes dans son champ defValue ; l'autre doit avoir la valeur TK_CONFIG_COLOR_ONLY dans son champ specFlags et la valeur correspondante defValue pour les affichages couleur.

Troisièmement, il est possible d'utiliser flags et specFlags ensemble pour désactiver sélectivement certaines entrées. Cette fonctionnalité n'est pas souvent nécessaire. Elle est utile dans les cas où plusieurs types de widgets similaires sont implémentés dans un seul endroit. Elle permet de créer une seule table specs avec toutes les options de configuration pour tous les types de widgets. Lors du traitement d'un type de widget spécifique, seules les entrées pertinentes pour ce type sont utilisées. Cet effet est obtenu en définissant les bits de poids fort (ceux aux positions égales ou supérieures à TK_CONFIG_USER_BIT) dans les valeurs de specFlags ou de flags. Pour qu'une entrée spécifique dans specs soit utilisée, ses bits de poids fort doivent correspondre exactement aux bits de poids fort de la valeur de flags passée à Tk_ConfigureWidget. Si une table specs est utilisée pour N types de widgets distincts, alors N des bits de poids fort seront utilisés. Chaque entrée specs aura un ou plusieurs de ces bits actifs dans son champ specFlags pour indiquer les types de widgets pour lesquels cette entrée est valide. Lors de l'appel à Tk_ConfigureWidget, flags aura un seul de ces bits actif pour sélectionner les entrées correspondant au type de widget désiré. Pour un exemple pratique de cette fonctionnalité, voir le code dans tkButton.c.

TK_OFFSET

La macro Tk_Offset est fournie comme méthode sûre pour générer les valeurs de offset pour les entrées dans les structures de Tk_ConfigSpec. Elle prend deux arguments : le nom d'un type de structure et le nom d'un champ dans cette structure. Elle renvoie la position en octets du champ nommé dans les structures du type donné.

TK_CONFIGUREINFO

La procédure Tk_ConfigureInfo peut être utilisée pour obtenir des informations sur les options d'un widget donné. Étant donné un handle de fenêtre (tkwin), une table décrivant les options de configuration d'un type de widget (specs), un pointeur vers une structure de widget contenant les informations actuelles pour un widget (widgRec) et un argument argvName nul, Tk_ConfigureInfo génère une chaîne décrivant toutes les options de configuration de la fenêtre. Cette chaîne est placée dans le résultat de l'interpréteur result. Elle renvoie normalement TCL_OK ; si une erreur se produit, elle renvoie TCL_ERROR et le résultat de l'interpréteur contient un message d'erreur.

Si argvName est nul, la valeur dans le résultat de l'interpréteur généré par Tk_ConfigureInfo consiste en une liste d'une ou plusieurs entrées, chacune décrivant une option de configuration (c'est-à-dire une entrée dans specs). Chaque entrée de la liste contiendra deux ou cinq valeurs. Si l'entrée correspondante dans specs est de type TK_CONFIG_SYNONYM, la liste contiendra deux valeurs : le argvName de l'entrée et le dbName (nom du synonyme). Sinon, la liste contiendra cinq valeurs : argvName, dbName, dbClass, defValue et la valeur actuelle. La valeur actuelle est calculée en appelant des procédures telles que Tk_NameOfColor à partir du champ correspondant de widgRec.

Si l'argument argvName de Tk_ConfigureInfo n'est pas nul, il indique une seule option et seules les informations relatives à cette option sont retournées. La chaîne placée dans le résultat de l'interpréteur sera une liste de deux ou cinq valeurs comme décrit ci-dessus ; ce sera identique à la sous-liste correspondante qui aurait été retournée si argvName était nul.

L'argument flags de Tk_ConfigureInfo est utilisé pour restreindre les entrées specs à considérer, tout comme pour Tk_ConfigureWidget.

TK_CONFIGUREVALUE

Tk_ConfigureValue prend des arguments similaires à Tk_ConfigureInfo ; au lieu de retourner une liste de valeurs, il retourne uniquement la valeur actuelle de l'option donnée par argvName (argvName ne doit pas être nul). La valeur est retournée dans le résultat de l'interpréteur result et TCL_OK est normalement retourné comme résultat de la procédure. Si une erreur se produit dans Tk_ConfigureValue (par exemple, argvName n'est pas un nom d'option valide), TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de l'interpréteur result. Cette procédure est généralement utilisée pour implémenter les commandes cget des widgets.

TK_FREEOPTIONS

La procédure Tk_FreeOptions peut être appelée lors de la destruction d'un widget pour libérer toutes les ressources associées aux options de configuration. Elle parcourt specs et libère les ressources dans la structure du widget pour chaque entrée correspondant à une ressource qui doit être explicitement libérée (par exemple, celles de type TK_CONFIG_COLOR). Si le champ de la structure du widget ne pointe pas vers une ressource (par exemple, il contient un pointeur nul), alors aucune ressource n'est libérée pour cette entrée. Après avoir libéré une ressource, Tk_FreeOptions met le champ correspondant de la structure du widget à null.

TYPES D'OPTIONS PERSONNALISÉES

Les applications peuvent étendre les types de configuration préinstallés avec des types supplémentaires en écrivant des procédures pour analyser et imprimer les options d'un type et en créant une structure qui pointe vers ces procédures :

typedef struct Tk_CustomOption {
    Tk_OptionParseProc *parseProc;
    Tk_OptionPrintProc *printProc;
    ClientData clientData;
} Tk_CustomOption;
typedef int Tk_OptionParseProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tk_Window tkwin,
        char *value,
        char *widgRec,
        int offset);
typedef const char *Tk_OptionPrintProc(
        ClientData clientData,
        Tk_Window tkwin,
        char *widgRec,
        int offset,
        Tcl_FreeProc **freeProcPtr);
La structure Tk_CustomOption contient trois champs, qui sont des pointeurs vers les deux procédures et une valeur clientData qui est passée à ces procédures lorsqu'elles sont appelées. La valeur clientData pointe généralement vers une structure contenant les informations nécessaires aux procédures lors de l'analyse et de l'impression des options. La procédure parseProc est appelée par Tk_ConfigureWidget pour analyser une chaîne et stocker la valeur résultante dans la structure du widget. L'argument clientData est une copie du champ clientData de la structure Tk_CustomOption. L'argument interp pointe vers un interpréteur Tcl utilisé pour le rapport d'erreurs. Tkwin est une copie de l'argument tkwin de Tk_ConfigureWidget. L'argument value est une chaîne décrivant la valeur de l'option ; elle pourrait avoir été spécifiée explicitement dans l'appel à Tk_ConfigureWidget ou provenir de la base de données d'options ou de la valeur par défaut. Value ne sera jamais un pointeur nul mais peut pointer vers une chaîne vide. RecordPtr est le même que l'argument widgRec de Tk_ConfigureWidget ; il pointe vers le début de la structure du widget à modifier. Le dernier argument, offset, donne la position en octets depuis le début de la structure du widget jusqu'à l'emplacement où la valeur de l'option doit être placée. La procédure doit traduire la chaîne dans sa forme appropriée pour l'option et stocker la valeur dans la structure du widget. Elle devrait normalement renvoyer TCL_OK, mais si une erreur se produit lors de la traduction de la chaîne en valeur, elle devrait renvoyer TCL_ERROR et stocker un message d'erreur dans le résultat de l'interpréteur result.

La procédure printProc est appelée par Tk_ConfigureInfo pour produire une chaîne de valeur décrivant une option existante. Ses arguments clientData, tkwin, widgRec et offset ont la même signification que pour les procédures Tk_OptionParseProc. La procédure printProc doit examiner l'option dont la valeur est stockée dans widgRec à la position offset, produire une chaîne décrivant cette option et renvoyer un pointeur vers la chaîne. Si la chaîne est stockée dans la mémoire dynamique, la procédure doit définir *freeProcPtr à l'adresse d'une procédure pour libérer la mémoire de la chaîne ; Tk_ConfigureInfo appellera cette procédure lorsque la libération de la mémoire sera nécessaire.

est terminé avec la chaîne de caractères. Si la chaîne résultante est stockée dans une mémoire statique, alors printProc n'a pas besoin de faire quoi que ce soit avec l'argument freeProcPtr.

Une fois que parseProc et printProc ont été définis et qu'une structure Tk_CustomOption a été créée pour eux, les options de ce nouveau type peuvent être manipulées avec des entrées Tk_ConfigSpec dont les champs type sont TK_CONFIG_CUSTOM et dont les champs customPtr pointent vers la structure Tk_CustomOption.

EXEMPLES

Bien que l'explication de Tk_ConfigureWidget soit assez compliquée, son utilisation réelle est assez simple. La manière la plus simple de commencer est de copier le code d'un widget existant. L'implémentation de la bibliothèque pour les cadres (tkFrame.c) a une table de configuration simple, et l'implémentation de la bibliothèque pour les boutons (tkButton.c) a une table beaucoup plus complexe qui utilise plusieurs des mécanismes sophistiqués de specFlags.
