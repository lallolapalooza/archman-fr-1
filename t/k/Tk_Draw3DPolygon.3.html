ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur à utiliser pour le signalement des erreurs.
Tk_Window tkwin (entrée)
Jeton pour la fenêtre (pour toutes les procédures sauf Tk_Get3DBorder, doit être la fenêtre pour laquelle la bordure a été allouée).
Tcl_Obj *objPtr (entrée)
Pointeur vers une valeur dont la valeur décrit la couleur correspondant au fond (zones plates). Les bords éclairés seront plus clairs que celle-ci et les bords ombrés seront plus sombres que celle-ci.
const char *colorName (entrée)
Identique à objPtr sauf que la valeur est fournie sous forme de chaîne plutôt que de valeur.
Drawable drawable (entrée)
Jeton X pour une fenêtre ou un pixmap ; indique où les graphiques doivent être dessinés. Doit être soit la fenêtre X de tkwin, soit un pixmap ayant le même écran et la même profondeur que tkwin.
Tk_3DBorder border (entrée)
Jeton pour une bordure précédemment allouée lors d'un appel à Tk_Get3DBorder.
int x (entrée)
Coordonnée X du coin supérieur gauche du rectangle décrivant la bordure ou le biseau, en pixels.
int y (entrée)
Coordonnée Y du coin supérieur gauche du rectangle décrivant la bordure ou le biseau, en pixels.
int width (entrée)
Largeur du rectangle décrivant la bordure ou le biseau, en pixels.
int height (entrée)
Hauteur du rectangle décrivant la bordure ou le biseau, en pixels.
int borderWidth (entrée)
Largeur de la bordure en pixels. Une valeur positive signifie que la bordure est à l'intérieur du rectangle donné par x, y, width, height, une valeur négative signifie que la bordure est à l'extérieur du rectangle.
int relief (entrée)
Indique la position 3D de l'intérieur de la valeur par rapport à l'extérieur ; doit être TK_RELIEF_RAISED, TK_RELIEF_SUNKEN, TK_RELIEF_GROOVE, TK_RELIEF_SOLID, ou TK_RELIEF_RIDGE (peut aussi être TK_RELIEF_FLAT pour Tk_Fill3DRectangle).
XPoint *pointPtr (entrée)
Pointeur vers un tableau de points décrivant l'ensemble des sommets d'un polygone. Le polygone n'a pas besoin d'être fermé (il sera fermé automatiquement s'il ne l'est pas).
int numPoints (entrée)
Nombre de points à *pointPtr.
int polyBorderWidth (entrée)
Largeur de la bordure en pixels. Si positive, la bordure est dessinée à gauche de la trajectoire donnée par pointPtr ; si négative, la bordure est dessinée à droite de la trajectoire. Si leftRelief est TK_RELIEF_GROOVE ou TK_RELIEF_RIDGE alors la bordure est centrée sur la trajectoire.
int leftRelief (entrée)
Hauteur du côté gauche du tracé du polygone par rapport au droit. TK_RELIEF_RAISED signifie que le côté gauche doit apparaître plus haut et TK_RELIEF_SUNKEN signifie que le côté droit doit apparaître plus haut ; TK_RELIEF_GROOVE et TK_RELIEF_RIDGE signifient les choses évidentes. Pour Tk_Fill3DPolygon, TK_RELIEF_FLAT peut aussi être spécifié pour indiquer aucune différence de hauteur.
int leftBevel (entrée)
Une valeur non nulle signifie que ce biseau forme le côté gauche de la valeur ; zéro signifie qu'il forme le côté droit.
int leftIn (entrée)
Une valeur non nulle signifie que le bord gauche du biseau horizontal s'incline vers l'intérieur, de sorte que le bas du bord est plus à droite que le haut. Zéro signifie que le bord s'incline vers l'extérieur, de sorte que le bas est plus à gauche que le haut.
int rightIn (entrée)
Une valeur non nulle signifie que le bord droit du biseau horizontal s'incline vers l'intérieur, de sorte que le bas du bord est plus à gauche que le haut. Zéro signifie que le bord s'incline vers l'extérieur, de sorte que le bas est plus à droite que le haut.
int topBevel (entrée)
Une valeur non nulle signifie que ce biseau forme le côté supérieur de la valeur ; zéro signifie qu'il forme le côté inférieur.
int which (entrée)
Spécifie lequel des contextes graphiques de la bordure est souhaité. Doit être TK_3D_FLAT_GC, TK_3D_LIGHT_GC, ou TK_3D_DARK_GC.

DESCRIPTION

Ces procédures fournissent des facilités pour dessiner des bordures de fenêtre d'une manière qui produit une apparence tridimensionnelle. Tk_Alloc3DBorderFromObj alloue les couleurs et les Pixmaps nécessaires pour dessiner une bordure dans la fenêtre donnée par l'argument tkwin. La valeur de objPtr est un nom de couleur Tk standard qui détermine les couleurs de la bordure. La couleur indiquée par objPtr ne sera pas réellement utilisée dans la bordure ; elle indique la couleur de fond de la fenêtre (c'est-à-dire une couleur pour les surfaces plates). Les portions éclairées de la bordure apparaîtront plus claires que ce qu'indique objPtr, et les portions ombrées de la bordure apparaîtront plus sombres que objPtr.

Tk_Alloc3DBorderFromObj renvoie un jeton qui peut être utilisé dans des appels ultérieurs à Tk_Draw3DRectangle. Si une erreur se produit lors de l'allocation des informations pour la bordure (par exemple un nom de couleur invalide a été donné) alors NULL est renvoyé et un message d'erreur est laissé comme résultat de l'interpréteur interp. Si elle réussit, Tk_Alloc3DBorderFromObj met en cache les informations sur la valeur de retour dans objPtr, ce qui accélère les appels futurs à Tk_Alloc3DBorderFromObj avec le même objPtr et tkwin.

Tk_Get3DBorder est identique à Tk_Alloc3DBorderFromObj sauf que la couleur est spécifiée avec une chaîne au lieu d'une valeur. Cela empêche Tk_Get3DBorder de mettre en cache la valeur de retour, donc Tk_Get3DBorder est moins efficace que Tk_Alloc3DBorderFromObj.

Tk_Get3DBorderFromObj renvoie le jeton pour une bordure existante, étant donné la fenêtre et le nom de couleur utilisés pour créer la bordure. Tk_Get3DBorderFromObj ne crée pas réellement la bordure ; elle doit déjà avoir été créée par un appel précédent à Tk_Alloc3DBorderFromObj ou Tk_Get3DBorder. La valeur de retour est mise en cache dans objPtr, ce qui accélère les appels futurs à Tk_Get3DBorderFromObj avec le même objPtr et tkwin.

Une fois qu'une structure de bordure a été créée, Tk_Draw3DRectangle peut être invoquée pour dessiner la bordure. L'argument tkwin spécifie la fenêtre pour laquelle la bordure a été allouée, et drawable spécifie une fenêtre ou un pixmap dans lequel la bordure doit être dessinée. Drawable n'a pas besoin de faire référence à la même fenêtre que tkwin, mais il doit faire référence à un pixmap ou une fenêtre compatible : un associé au même écran et avec la même profondeur que tkwin. Les arguments x, y, width, et height définissent la boîte englobante de la région de bordure dans drawable (généralement x et y sont zéro et width et height sont les dimensions de la fenêtre), et borderWidth spécifie le nombre de pixels réellement occupés par la bordure. L'argument relief indique lequel de plusieurs effets tridimensionnels est souhaité : TK_RELIEF_RAISED signifie que l'intérieur du rectangle doit apparaître en relief par rapport à l'extérieur du rectangle, et TK_RELIEF_SUNKEN signifie que l'intérieur doit apparaître en creux. TK_RELIEF_GROOVE et TK_RELIEF_RIDGE signifient qu'il doit apparaître une rainure ou une crête autour de l'extérieur du rectangle.

Tk_Fill3DRectangle est quelque peu similaire à Tk_Draw3DRectangle sauf

Tk_Draw3DPolygon(3)

NAME

Tk_Draw3DRectangle, Tk_Fill3DRectangle, Tk_Draw3DPolygon, Tk_Fill3DPolygon, Tk_3DVerticalBevel, Tk_3DHorizontalBevel, Tk_SetBackgroundFromBorder, Tk_NameOf3DBorder, Tk_3DBorderColor, Tk_3DBorderGC, Tk_Free3DBorderFromObj, Tk_Free3DBorder - drawing routines for 3-D borders

SYNOPSIS

#include <tk.h>

Tk_Draw3DRectangle(tkwin, drawable, border, x, y, width, height, borderWidth, relief);
Tk_Fill3DRectangle(tkwin, drawable, border, x, y, width, height, borderWidth, relief);
Tk_Draw3DPolygon(tkwin, drawable, border, pointPtr, numPoints, polyBorderWidth, leftRelief);
Tk_Fill3DPolygon(tkwin, drawable, border, pointPtr, numPoints, polyBorderWidth, leftRelief);
Tk_3DVerticalBevel(tkwin, drawable, border, x, y, width, height, borderWidth, leftBorder, topBorder, relief);
Tk_3DHorizontalBevel(tkwin, drawable, border, x, y, width, height, borderWidth, leftIn, rightIn, relief);
Tk_SetBackgroundFromBorder(tkwin, border);
Tk_NameOf3DBorder(border);
Tk_3DBorderColor(border);
Tk_3DBorderGC(border, which);
Tk_Free3DBorderFromObj(interp, borderObj);
Tk_Free3DBorder(border);

ARGUMENTS

tkwin Tk_Window token for the window in which to draw.
drawable X Drawable on which to draw.
border A token for a Tk_3DBorder structure, created by Tk_Alloc3DBorder or Tk_Get3DBorder.
x, y, width, height Coordinates and dimensions of the rectangular area to be drawn.
borderWidth The desired border width. If 0, no border is drawn.
relief Specifies the 3-D effect desired. See Tk_3DBorderColor documentation for a list of values.
pointPtr Pointer to an array of points defining the polygon. Tcl_Point structures.
numPoints Number of points in the array pointed to by pointPtr.
polyBorderWidth The desired border width. Must be positive; if 0 or negative, no border is drawn.
leftRelief The relief of the left side of the trajectory. See Tk_3DBorderColor documentation for a list of values.
leftBorder, topBorder Used by Tk_3DVerticalBevel and Tk_3DHorizontalBevel to indicate the position of the border relative to the “inside” of the value.
leftIn, rightIn Used by Tk_3DHorizontalBevel to describe the mitering at the corners.
which One of TK_3D_FLAT_GC, TK_3D_LIGHT_GC, or TK_3D_DARK_GC.
interp Current interpreter.
borderObj The object that holds the border information.

DESCRIPTION

The procedure Tk_Draw3DRectangle draws a rectangle with a three-dimensional appearance. It first fills the rectangular area with the background color (one corresponding to the color used to create border). Then it calls Tk_Draw3DRectangle to draw a border just inside the outer edge of the rectangular area. The argument relief indicates the desired effect (TK_RELIEF_FLAT means no border should be drawn; all that happens is to fill the rectangle with the background color).

The procedure Tk_Draw3DPolygon may be used to draw more complex shapes with a three-dimensional appearance. The pointPtr and numPoints arguments define a trajectory, polyBorderWidth indicates how wide the border should be (and on which side of the trajectory to draw it), and leftRelief indicates which side of the trajectory should appear raised. Tk_Draw3DPolygon draws a border around the given trajectory using the colors from border to produce a three-dimensional appearance. If the trajectory is non-self-intersecting, the appearance will be a raised or sunken polygon shape. The trajectory may be self-intersecting, although it's not clear how useful this is.

Tk_Fill3DPolygon is to Tk_Draw3DPolygon what Tk_Fill3DRectangle is to Tk_Draw3DRectangle: it fills the polygonal area with the background color from border, then calls Tk_Draw3DPolygon to draw a border around the area (unless leftRelief is TK_RELIEF_FLAT; in this case no border is drawn).

The procedures Tk_3DVerticalBevel and Tk_3DHorizontalBevel provide lower-level drawing primitives that are used by procedures such as Tk_Draw3DRectangle. These procedures are also useful in their own right for drawing rectilinear border shapes. Tk_3DVerticalBevel draws a vertical beveled edge, such as the left or right side of a rectangle, and Tk_3DHorizontalBevel draws a horizontal beveled edge, such as the top or bottom of a rectangle. Each procedure takes x, y, width, and height arguments that describe the rectangular area of the beveled edge (e.g., width is the border width for Tk_3DVerticalBevel). The leftBorder and topBorder arguments indicate the position of the border relative to the “inside” of the value, and relief indicates the relief of the inside of the value relative to the outside. Tk_3DVerticalBevel just draws a rectangular region. Tk_3DHorizontalBevel draws a trapezoidal region to generate mitered corners; it should be called after Tk_3DVerticalBevel (otherwise Tk_3DVerticalBevel will overwrite the mitering in the corner). The leftIn and rightIn arguments to Tk_3DHorizontalBevel describe the mitering at the corners; a value of 1 means that the bottom edge of the trapezoid will be shorter than the top, 0 means it will be longer. For example, to draw a rectangular border the top bevel should be drawn with 1 for both leftIn and rightIn, and the bottom bevel should be drawn with 0 for both arguments.

The procedure Tk_SetBackgroundFromBorder will modify the background pixel and/or pixmap of tkwin to produce a result compatible with border. For color displays, the resulting background will just be the color specified when border was created; for monochrome displays, the resulting background will be a light stipple pattern, in order to distinguish the background from the illuminated portion of the border.

Given a token for a border, the procedure Tk_NameOf3DBorder will return the color name that was used to create the border.

The procedure Tk_3DBorderColor returns the XColor structure that will be used for flat surfaces drawn for its border argument by procedures like Tk_Fill3DRectangle. The return value corresponds to the color name that was used to create the border. The XColor, and its associated pixel value, will remain allocated as long as border exists.

The procedure Tk_3DBorderGC returns one of the X graphics contexts that are used to draw the border. The argument which selects which one of the three possible GC's: TK_3D_FLAT_GC returns the context used for flat surfaces, TK_3D_LIGHT_GC returns the context for light shadows, and TK_3D_DARK_GC returns the context for dark shadows.

When a border is no longer needed, Tk_Free3DBorderFromObj or Tk_Free3DBorder should be called to release the resources associated with it. For Tk_Free3DBorderFromObj the border to release is specified with the window and color name used to create the border; for Tk_Free3DBorder the border to release is specified with the Tk_3DBorder token for the border. There should be exactly one call to Tk_Free3DBorderFromObj or Tk_Free3DBorder for each call to Tk_Alloc3DBorderFromObj or Tk_Get3DBorder.

KEYWORDS

3D, background, border, color, depressed, illumination, value, polygon, raised, shadow, three-dimensional effect
