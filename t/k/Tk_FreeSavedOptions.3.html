ARGUMENTS

Tcl_Interp *interp (entrée)
Un interpréteur Tcl. La plupart des procédures l'utilisent uniquement pour retourner des messages d'erreur ; s'il est NULL, aucun message d'erreur n'est retourné. Pour Tk_CreateOptionTable, la valeur ne peut pas être NULL ; elle indique l'interpréteur dans lequel la table d'options sera utilisée.
const Tk_OptionSpec *templatePtr (entrée)
Pointe vers un tableau d'informations statiques décrivant les options de configuration prises en charge. Utilisé pour construire une Tk_OptionTable. Les informations pointées par cet argument doivent exister pendant toute la durée de vie de la Tk_OptionTable.
Tk_OptionTable optionTable (entrée)
Jeton pour une table d'options. Doit avoir été retourné par un appel précédent à Tk_CreateOptionTable.
char *recordPtr (entrée/sortie)
Pointe vers une structure où les valeurs des options de configuration sont stockées ; les champs de cet enregistrement sont modifiés par des procédures telles que Tk_SetOptions et lus par des procédures telles que Tk_GetOptionValue.
Tk_Window tkwin (entrée)
Pour les options telles que TK_OPTION_COLOR, cet argument indique la fenêtre dans laquelle l'option sera utilisée. Si optionTable n'utilise aucune option dépendant de la fenêtre, alors une valeur NULL peut être fournie pour cet argument.
int objc (entrée)
Nombre de valeurs dans objv.
Tcl_Obj *const *objv (entrée)
Arguments de la ligne de commande pour définir les options de configuration.
Tk_SavedOptions *savePtr (sortie)
Si non NULL, la structure pointée par cet argument est remplie avec les anciennes valeurs de toutes les options qui ont été modifiées et les anciennes valeurs sont automatiquement restaurées si une erreur se produit dans Tk_SetOptions.
int *maskPtr (sortie)
Si non NULL, le mot pointé par maskPtr est rempli avec le OU bit à bit des champs typeMask pour les options qui ont été modifiées.

Pointe vers une structure précédemment remplie par Tk_SetOptions avec les anciennes valeurs des options modifiées.
Tcl_Obj *namePtr (entrée)
La valeur de cet objet est le nom d'une option particulière. Si NULL est passé à Tk_GetOptionInfo, les informations sont retournées pour toutes les options. Ne doit pas être NULL lorsque Tk_GetOptionValue est appelé.

Le nom du type d'un enregistrement.
nom de champ field (entrée)
Le nom d'un champ dans les enregistrements de type type.

DESCRIPTION

Ces procédures gèrent la plupart des détails de l'analyse des options de configuration telles que celles des widgets Tk. Étant donné une description des options prises en charge, ces procédures gèrent tous les détails de l'analyse des options et du stockage de leurs valeurs dans une structure C associée au widget ou à l'objet. Les procédures ont été conçues principalement pour les widgets dans Tk, mais elles peuvent également être utilisées pour d'autres types d'objets qui ont des options de configuration. Dans le reste de cette page de manuel, le terme "widget" sera utilisé pour désigner l'objet dont les options sont gérées ; en pratique, l'objet peut ne pas être effectivement un widget. Le terme "enregistrement de widget" est utilisé pour désigner la structure de niveau C dans laquelle sont stockées les informations relatives à un widget ou objet particulier.

Notez que le moyen le plus simple d'apprendre à utiliser ces procédures est de consulter un exemple fonctionnel. Dans Tk, l'exemple le plus simple est le code qui implémente la famille de widgets boutons, qui se trouve dans tkButton.c. D'autres exemples se trouvent dans tkSquare.c et tkMenu.c.

Pour utiliser ces procédures, le code qui implémente le widget doit contenir un tableau statique de structures Tk_OptionSpec. Il s'agit d'un modèle décrivant les différentes options prises en charge par cette classe de widget ; il existe un modèle distinct pour chaque type de widget. Le modèle contient des informations telles que le nom de chaque option, son type, sa valeur par défaut et l'emplacement où la valeur de l'option est stockée dans l'enregistrement du widget. Voir MODÈLES ci-dessous pour plus de détails.

Afin de traiter les options de configuration de manière efficace, le modèle statique doit être complété par des informations supplémentaires disponibles uniquement à l'exécution. La procédure Tk_CreateOptionTable crée ces informations dynamiques à partir du modèle et renvoie un jeton Tk_OptionTable décrivant les informations statiques et dynamiques. Toutes les autres procédures, telles que Tk_SetOptions, prennent un jeton Tk_OptionTable comme argument. Généralement, Tk_CreateOptionTable est appelé la première fois qu'un widget d'une classe particulière est créé et la Tk_OptionTable résultante est utilisée à l'avenir pour tous les widgets de cette classe. Une Tk_OptionTable ne peut être utilisée que dans un seul interpréteur, spécifié par l'argument interp à Tk_CreateOptionTable. Lorsqu'une table d'options n'est plus nécessaire, Tk_DeleteOptionTable doit être appelée pour libérer toutes ses ressources. Toutes les tables d'options d'un interpréteur Tcl sont libérées automatiquement si l'interpréteur est supprimé.

Tk_InitOptions est invoqué lors de la création d'un nouveau widget pour définir les valeurs par défaut. Tk_InitOptions reçoit un jeton pour une table d'options (optionTable) et un pointeur vers un enregistrement de widget (recordPtr), qui est la structure C stockant les informations sur ce widget. Tk_InitOptions utilise les informations de la table d'options pour choisir une valeur par défaut appropriée pour chaque option, puis stocke cette valeur par défaut directement dans l'enregistrement du widget, écrasant toute information déjà présente. Tk_InitOptions retourne normalement TCL_OK. Si une erreur s'est produite lors de la définition des valeurs par défaut (par exemple, parce qu'une valeur par défaut était erronée), alors TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat d'interp si interp n'est pas NULL. Pour toute option de configuration d'un widget ayant le drapeau TK_OPTION_DONT_SET_DEFAULT défini dans son champ flags, l'initialisation ci-dessus est complètement ignorée, voir ci-dessous.

Tk_SetOptions est invoqué pour modifier les options de configuration en fonction des informations spécifiées dans une commande Tcl. La commande peut être celle qui crée un nouveau widget, ou une commande qui modifie les options d'un widget existant. Les arguments objc et objv décrivent les valeurs des arguments de la commande Tcl. Objv doit contenir un nombre pair d'objets : le premier objet de chaque paire donne le nom d'une option et le second objet donne la nouvelle valeur pour cette option. Tk_SetOptions recherche chaque nom dans optionTable, vérifie que la nouvelle valeur de l'option est conforme au type spécifié dans optionTable, et stocke la valeur de l'option dans l'enregistrement du widget donné par recordPtr. Tk_SetOptions retourne normalement TCL_OK. Si une erreur s'est produite (telle qu'un nom d'option inconnu ou une valeur d'option illégale), alors TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat d'interp si interp n'est pas NULL.

Tk_SetOptions dispose de deux fonctionnalités supplémentaires. Premièrement, si l'argument maskPtr n'est pas NULL, il pointe vers une valeur entière qui est remplie avec des informations sur les options qui ont été modifiées. Pour chaque option du modèle passé à Tk_CreateOptionTable, il existe un champ typeMask. Les bits de ce champ sont définis par le code qui implémente le widget ; par exemple, chaque bit peut correspondre à une option de configuration particulière. Alternativement, les bits peuvent être utilisés fonctionnellement. Par exemple, un bit peut être utilisé pour le redessin : toutes les options qui affectent l'affichage du widget, de sorte que la modification de l'option nécessite le redessin du widget, pourraient avoir ce bit défini. Un autre bit pourrait indiquer que la géométrie du widget doit être recalculée, etc. Tk_SetOptions effectue un OU bit à bit des champs typeMask des

The second additional feature of Tk_SetOptions has to do with error recovery. If an error occurs while processing configuration options, this feature makes it possible to restore all the configuration options to their previous values. Errors can occur either while processing options in Tk_SetOptions or later in the caller. In many cases the caller does additional processing after Tk_SetOptions returns; for example, it might use an option value to set a trace on a variable and may detect an error if the variable is an array instead of a scalar. Error recovery is enabled by passing in a non-NULL value for the savePtr argument to Tk_SetOptions; this should be a pointer to an uninitialized Tk_SavedOptions structure on the caller's stack. Tk_SetOptions overwrites the structure pointed to by savePtr with information about the old values of any options modified by the procedure. If Tk_SetOptions returns successfully, the caller uses the structure in one of two ways. If the caller completes its processing of the new options without any errors, then it must pass the structure to Tk_FreeSavedOptions so that the old values can be freed. If the caller detects an error in its processing of the new options, then it should pass the structure to Tk_RestoreSavedOptions, which will copy the old values back into the widget record and free the new values. If Tk_SetOptions detects an error then it automatically restores any options that had already been modified and leaves *savePtr in an empty state: the caller need not call either Tk_FreeSavedOptions or Tk_RestoreSavedOptions. If the savePtr argument to Tk_SetOptions is NULL then Tk_SetOptions frees each old option value immediately when it sets a new value for the option. In this case, if an error occurs in the third option, the old values for the first two options cannot be restored.

Tk_GetOptionValue returns the current value of a configuration option for a particular widget. The namePtr argument contains the name of an option; Tk_GetOptionValue uses optionTable to lookup the option and extract its value from the widget record pointed to by recordPtr, then it returns an object containing that value. If an error occurs (e.g., because namePtr contains an unknown option name) then NULL is returned and an error message is left in interp's result unless interp is NULL.

Tk_GetOptionInfo returns information about configuration options in a form suitable for configure widget commands. If the namePtr argument is not NULL, it points to an object that gives the name of a configuration option; Tk_GetOptionInfo returns an object containing a list with five elements, which are the name of the option, the name and class used for the option in the option database, the default value for the option, and the current value for the option. If the namePtr argument is NULL, then Tk_GetOptionInfo returns information about all options in the form of a list of lists; each sublist describes one option. Synonym options are handled differently depending on whether namePtr is NULL: if namePtr is NULL then the sublist for each synonym option has only two elements, which are the name of the option and the name of the other option that it refers to; if namePtr is non-NULL and names a synonym option then the object returned is the five-element list for the other option that the synonym refers to. If an error occurs (e.g., because namePtr contains an unknown option name) then NULL is returned and an error message is left in interp's result unless interp is NULL.

Tk_FreeConfigOptions must be invoked when a widget is deleted. It frees all of the resources associated with any of the configuration options defined in recordPtr by optionTable.

The Tk_Offset macro is provided as a safe way of generating the objOffset and internalOffset values for entries in Tk_OptionSpec structures. It takes two arguments: the name of a type of record, and the name of a field in that record. It returns the byte offset of the named field in records of the given type.

TEMPLATES

The array of Tk_OptionSpec structures passed to Tk_CreateOptionTable via its templatePtr argument describes the configuration options supported by a particular class of widgets. Each structure specifies one configuration option and has the following fields:

typedef struct {
    Tk_OptionType type;
    const char *optionName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int objOffset;
    int internalOffset;
    int flags;
    const void *clientData;
    int typeMask;
} Tk_OptionSpec;
The type field indicates what kind of configuration option this is (e.g. TK_OPTION_COLOR for a color value, or TK_OPTION_INT for an integer value). Type determines how the value of the option is parsed (more on this below). The optionName field is a string such as -font or -bg; it is the name used for the option in Tcl commands and passed to procedures via the objc or namePtr arguments. The dbName and dbClass fields are used by Tk_InitOptions to look up a default value for this option in the option database; if dbName is NULL then the option database is not used by Tk_InitOptions for this option. The defValue field specifies a default value for this configuration option if no value is specified in the option database. The objOffset and internalOffset fields indicate where to store the value of this option in widget records (more on this below); values for the objOffset and internalOffset fields should always be generated with the Tk_Offset macro. The flags field contains additional information to control the processing of this configuration option (see below for details). ClientData provides additional type-specific data needed by certain types. For instance, for TK_OPTION_COLOR types, clientData is a string giving the default value to use on monochrome displays. See the descriptions of the different types below for details. The last field, typeMask, is used by Tk_SetOptions to return information about which options were modified; see the description of Tk_SetOptions above for details.

When Tk_InitOptions and Tk_SetOptions store the value of an option into the widget record, they can do it in either of two ways. If the objOffset field of the Tk_OptionSpec is greater than or equal to zero, then the value of the option is stored as a (Tcl_Obj *) at the location in the widget record given by objOffset. If the internalOffset field of the Tk_OptionSpec is greater than or equal to zero, then the value of the option is stored in a type-specific internal form at the location in the widget record given by internalOffset. For example, if the option's type is TK_OPTION_INT then the internal form is an integer. If the objOffset or internalOffset field is negative then the value is not stored in that form. At least one of the offsets must be greater than or equal to zero.

The flags field consists of one or more bits ORed together. The following flags are supported:

TK_OPTION_NULL_OK
If this bit is set for an option then an empty string will be accepted as the value for the option and the resulting internal form will be a NULL pointer, a zero value, or None, depending on the type of the option. If the flag is not set then empty strings will result in errors. TK_OPTION_NULL_OK is typically used to allow a feature to be turned off entirely, e.g. set a cursor value to None so that a window simply inherits its parent's cursor. Not all option types support the TK_OPTION_NULL_OK flag; for those that do, there is an explicit indication of that fact in the descriptions below.
TK_OPTION_DONT_SET_DEFAULT
If this bit is set for an option then no default value will be set in Tk_InitOptions for this option. Neither the option database, nor any system default value, nor optionTable are used to give a default value to this option. Instead it is assumed that the caller has already supplied a default value in the widget code.

The type field of each Tk_OptionSpec structure determines how to parse the value of that configuration option. The legal value for type, and the corresponding actions, are described below. If the type requires a tkwin value to be passed into procedures like Tk_SetOptions, or if it uses the clientData field of the Tk_OptionSpec, then it is indicated explicitly; if not mentioned, the type requires neither tkwin nor clientData.

TK_OPTION_ANCHOR
The value must be a standard anchor position such as ne or center. The internal form is a Tk_Anchor value like the ones returned by Tk_GetAnchorFromObj.
TK_OPTION_BITMAP
The value must be a standard Tk bitmap name. The internal form is a Pixmap token like the ones returned by Tk_AllocBitmapFromObj. This option type requires tkwin to be supplied to procedures such as Tk_SetOptions, and it supports the TK_OPTION_NULL_OK flag.
TK_OPTION_BOOLEAN
The value must be a standard boolean value such as true or no. The internal form is an integer with value 0 or 1. Note that if the objOffset field is not used, information about the original value of this option will be lost.
TK_OPTION_BORDER

TYPES D'OPTIONS

TK_OPTION_BOOLEAN
La valeur doit être true ou false. La forme interne est un entier C (0 ou 1).
TK_OPTION_BITMAP
La valeur doit être le nom d'un bitmap tel que spécifié dans la section BITGravity du manuel de X (par exemple, @foo ou /tmp/foo.xbm). La forme interne est un Pixmap de Tk. Cette option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et elle prend en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_COLOR
La valeur doit être un nom de couleur standard tel que red ou #ff8080. La forme interne est un jeton (XColor *) comme ceux renvoyés par Tk_AllocColorFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_CURSOR
La valeur doit être un nom de curseur standard tel que cross ou @foo. La forme interne est un jeton Tk_Cursor comme ceux renvoyés par Tk_AllocCursorFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et lorsque l'option est définie, le curseur de la fenêtre est modifié en appelant XDefineCursor. Ce type d'option prend également en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_CUSTOM
Cette option permet aux applications de définir de nouveaux types d'options. Le champ clientData des points d'entrée pointe vers une structure définissant le nouveau type d'option. Voir la section TYPES D'OPTIONS PERSONNALISÉES ci-dessous pour plus de détails.
TK_OPTION_DOUBLE
La valeur de chaîne doit être un nombre à virgule flottante au format accepté par strtod. La forme interne est une valeur C double. Ce type d'option prend en charge le drapeau TK_OPTION_NULL_OK; si une valeur NULL est définie, la représentation interne est mise à zéro.
TK_OPTION_END
Marque la fin du modèle. Il doit y avoir une structure Tk_OptionSpec avec type TK_OPTION_END à la fin de chaque modèle. Si le champ clientData de cette structure n'est pas NULL, alors il pointe vers un tableau supplémentaire de Tk_OptionSpec, qui est lui-même terminé par une autre entrée TK_OPTION_END. Les modèles peuvent être chaînés arbitrairement en profondeur. Cette fonctionnalité permet de partager des options communes entre plusieurs classes de widgets.
TK_OPTION_FONT
La valeur doit être un nom de police standard tel que Times 16. La forme interne est un handle Tk_Font comme ceux renvoyés par Tk_AllocFontFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_INT
La valeur de chaîne doit être un entier au format accepté par strtol (par exemple, les préfixes 0 et 0x peuvent être utilisés pour spécifier respectivement des nombres octaux ou hexadécimaux). La forme interne est une valeur C int.
TK_OPTION_JUSTIFY
La valeur doit être une valeur de justification standard telle que left. La forme interne est un Tk_Justify comme les valeurs renvoyées par Tk_GetJustifyFromObj.
TK_OPTION_PIXELS
La valeur doit spécifier une distance d'écran telle que 2i ou 6.4. La forme interne est une valeur entière donnant une distance en pixels, comme les valeurs renvoyées par Tk_GetPixelsFromObj. Notez que si le champ objOffset n'est pas utilisé, les informations sur la valeur d'origine de cette option seront perdues. Voir OBJOFFSET VS. INTERNALOFFSET ci-dessous pour plus de détails. Ce type d'option prend en charge le drapeau TK_OPTION_NULL_OK; si une valeur NULL est définie, la représentation interne est mise à INT_MIN.
TK_OPTION_RELIEF
La valeur doit être un relief standard tel que raised. La forme interne est une valeur de relief entière telle que TK_RELIEF_RAISED. Ce type d'option prend en charge le drapeau TK_OPTION_NULL_OK; si une valeur NULL est définie, la représentation interne est mise à TK_RELIEF_NULL.
TK_OPTION_STRING
La valeur peut être n'importe quelle chaîne. La forme interne est un pointeur (char *) qui pointe vers une copie allouée dynamiquement de la valeur. Ce type d'option prend en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_STRING_TABLE
Pour ce type, clientData est un pointeur vers un tableau de chaînes adapté à être passé à Tcl_GetIndexFromObj. La valeur doit être l'une des chaînes du tableau, ou une abréviation unique d'une des chaînes. La forme interne est un entier donnant l'indice dans le tableau de la chaîne correspondante, comme la valeur de retour de Tcl_GetStringFromObj. Ce type d'option prend en charge le drapeau TK_OPTION_NULL_OK; si une valeur NULL est définie, la représentation interne est mise à -1.
TK_OPTION_SYNONYM
Ce type est utilisé pour fournir des noms alternatifs à une option (par exemple, -bg est souvent utilisé comme synonyme de -background). Le champ clientData est une chaîne qui donne le nom d'une autre option dans le même tableau. Chaque fois que l'option synonyme est utilisée, les informations de l'autre option seront utilisées à la place.
TK_OPTION_WINDOW
La valeur doit être un nom de chemin de fenêtre. La forme interne est un jeton Tk_Window pour la fenêtre. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions (afin d'identifier l'application), et il prend en charge le drapeau TK_OPTION_NULL_OK.

PROBLÈMES DE GESTION DE STOCKAGE

Si un champ d'un enregistrement de widget a son décalage stocké dans le champ objOffset ou internalOffset d'une structure Tk_OptionSpec, alors les procédures décrites ici géreront toutes les allocations de stockage et les problèmes de gestion des ressources associés au champ. Lorsque la valeur d'une option est modifiée, Tk_SetOptions (ou Tk_FreeSavedOptions) libérera automatiquement toutes les ressources associées à l'ancienne valeur, telles que les Tk_Fonts pour les options TK_OPTION_FONT ou la mémoire allouée dynamiquement pour les options TK_OPTION_STRING. Pour une option stockée sous forme d'objet à l'aide du champ objOffset d'une structure Tk_OptionSpec, l'enregistrement du widget partage l'objet pointé par la valeur objv de l'appel à Tk_SetOptions. Le compteur de références de cet objet est incrémenté lorsqu'un pointeur vers celui-ci est stocké dans l'enregistrement du widget et décrémenté lorsque l'option est modifiée. Lorsque le widget est supprimé, Tk_FreeConfigOptions doit être appelé ; il libérera les ressources associées à toutes les options et décrémentera les compteurs de références pour tous les objets.

Cependant, le code du widget est responsable du stockage de NULL ou None dans tous les champs pointeurs et jetons avant d'appeler Tk_InitOptions. Ceci est nécessaire pour permettre un nettoyage correct dans le cas rare où une erreur se produit dans Tk_InitOptions.

OBJOFFSET VS. INTERNALOFFSET

Dans la plupart des cas, il est plus simple d'utiliser le champ internalOffset d'une structure Tk_OptionSpec et non le champ objOffset. Cela rend la forme interne de la valeur immédiatement disponible pour le code du widget afin que la valeur n'ait pas à être extraite d'un objet chaque fois qu'elle est utilisée. Cependant, il y a deux cas où le champ objOffset est utile. Le premier cas concerne les options TK_OPTION_PIXELS. Dans ce cas, la forme interne est une valeur entière en pixels qui n'est valide que pour un écran particulier. Si la valeur de l'option est récupérée, elle sera renvoyée comme un simple nombre. Par exemple, après la commande .b configure -borderwidth 2m, la commande .b configure -borderwidth pourrait renvoyer 7, qui est la valeur entière en pixels correspondant à 2m. Malheureusement, cela perd la valeur d'origine indépendante de l'écran. Ainsi, pour les options TK_OPTION_PIXELS, il est préférable d'utiliser le champ objOffset. Dans ce cas, la valeur d'origine de l'option est conservée dans l'objet et peut être renvoyée lorsque l'option est récupérée. Dans la plupart des cas, il est pratique d'utiliser également le champ internalOffset, de sorte que la valeur entière soit immédiatement disponible pour être utilisée dans le code du widget (alternativement, Tk_GetPixelsFromObj peut être utilisé pour extraire la valeur entière de l'objet chaque fois qu'elle est nécessaire). Notez que le problème de perte d'informations lors des récupérations n'existe que pour les options TK_OPTION_PIXELS.

La deuxième raison d'utiliser le champ objOffset est de pouvoir implémenter de nouveaux types d'options non pris en charge par ces procédures. Pour implémenter un nouveau type d'option, vous pouvez utiliser TK_OPTION_STRING comme type dans la structure Tk_OptionSpec et définir le champ objOffset mais pas le champ internalOffset. Ensuite, après avoir appelé Tk_SetOptions, convertissez l'objet en forme interne vous-même.

Les widgets Ttk ne prennent pas en charge le mécanisme internalOffset. Les valeurs d'options des widgets Ttk sont toujours stockées comme (Tcl_Obj *), ce qui signifie que le champ objOffset doit être utilisé.

TYPES D'OPTIONS PERSONNALISÉES

Les applications peuvent étendre les types de configuration intégrés avec des types de configuration supplémentaires en écrivant des procédures pour analyser, imprimer, libérer et restaurer des copies enregistrées du type et en créant une structure pointant vers ces procédures :

typedef struct Tk_ObjCustomOption {
    const char *name;
    Tk_CustomOptionSetProc *setProc;
    Tk_CustomOptionGetProc *getProc;
    Tk_CustomOptionRestoreProc *restoreProc;
    Tk_CustomOptionFreeProc *freeProc;
    ClientData clientData;
} Tk_ObjCustomOption;
typedef int Tk_CustomOptionSetProc(
    ClientData clientData,
    Tcl_Interp *interp,
    Tk_Window tkwin,
    Tcl_Obj **valuePtr,
    char *recordPtr,
    int internalOffset,
    char *saveInternalPtr,
    int flags);
typedef Tcl_Obj *Tk_CustomOptionGetProc(
    ClientData clientData,
    Tk_Window tkwin,
    char *recordPtr,
    int internalOffset);
typedef void Tk_CustomOptionRestoreProc(
    ClientData clientData,
    Tk_Window tkwin,
    char *internalPtr,
    char *saveInternalPtr);
typedef void Tk_CustomOptionFreeProc(
    ClientData clientData,
    Tk_Window tkwin,
    char *internalPtr);

La structure Tk_ObjCustomOption contient six champs : un nom pour le type d'option personnalisé ; des pointeurs vers les quatre procédures ; et une valeur clientData à passer à ces procédures lorsqu'elles sont appelées. La valeur clientData

ue pointe généralement vers une structure contenant les informations nécessaires aux procédures lors de l'analyse et de l'impression des options. RestoreProc et freeProc peuvent être NULL, indiquant qu'aucune fonction ne doit être appelée pour ces opérations.

La procédure setProc est appelée par Tk_SetOptions pour convertir un Tcl_Obj en une représentation interne et stocker la valeur résultante dans l'enregistrement du widget. Les arguments sont :

clientData
Une copie du champ clientData dans la structure Tk_ObjCustomOption.
interp
Un pointeur vers un interpréteur Tcl, utilisé pour le signalement d'erreurs.
Tkwin
Une copie de l'argument tkwin de Tk_SetOptions
valuePtr
Un pointeur vers une référence à un Tcl_Obj décrivant la nouvelle valeur de l'option ; elle pourrait avoir été spécifiée explicitement dans l'appel à Tk_SetOptions ou provenir de la base de données des options ou d'une valeur par défaut. Si l'objOffset de l'option est non négatif (la valeur de l'option est stockée en tant que (Tcl_Obj *) dans l'enregistrement du widget), le pointeur Tcl_Obj référencé par valuePtr est le pointeur qui sera stocké à l'objOffset pour l'option. SetProc peut modifier la valeur si nécessaire ; par exemple, setProc peut modifier la valeur en NULL pour prendre en charge le drapeau TK_OPTION_NULL_OK.
recordPtr
Un pointeur vers le début de l'enregistrement du widget à modifier.
internalOffset
Décalage en octets à partir du début de l'enregistrement du widget jusqu'à l'emplacement où la représentation interne de la valeur de l'option doit être placée.
saveInternalPtr
Un pointeur vers un espace alloué dans une structure Tk_SavedOptions pour la représentation interne de la valeur d'option d'origine. Avant de définir l'option à sa nouvelle valeur, setProc doit définir la valeur référencée par saveInternalPtr à la valeur d'origine de l'option afin de prendre en charge Tk_RestoreSavedOptions.
flags
Une copie du champ flags dans la structure Tk_OptionSpec pour l'option

SetProc renvoie un résultat Tcl standard : TCL_OK pour indiquer un traitement réussi, ou TCL_ERROR pour indiquer un échec de quelque nature que ce soit. Un message d'erreur peut être laissé dans l'interpréteur Tcl fourni par interp en cas d'erreur.

La procédure getProc est appelée par Tk_GetOptionValue et Tk_GetOptionInfo pour récupérer une représentation Tcl_Obj de la représentation interne d'une option. L'argument clientData est une copie du champ clientData dans la structure Tk_ObjCustomOption. Tkwin est une copie de l'argument tkwin de Tk_GetOptionValue ou Tk_GetOptionInfo. RecordPtr est un pointeur vers le début de l'enregistrement du widget à interroger. InternalOffset est le décalage en octets depuis le début de l'enregistrement du widget jusqu'à l'emplacement où la représentation interne de la valeur de l'option est stockée. GetProc doit renvoyer un pointeur vers un Tcl_Obj représentant la valeur de l'option.

La procédure restoreProc est appelée par Tk_RestoreSavedOptions pour restaurer une représentation interne précédemment sauvegardée d'une valeur d'option personnalisée. L'argument clientData est une copie du champ clientData dans la structure Tk_ObjCustomOption. Tkwin est une copie de l'argument tkwin de Tk_GetOptionValue ou Tk_GetOptionInfo. InternalPtr est un pointeur vers l'emplacement où la représentation interne de la valeur de l'option est stockée. SaveInternalPtr est un pointeur vers la valeur sauvegardée. RestoreProc doit copier la valeur de saveInternalPtr vers internalPtr pour restaurer la valeur. RestoreProc n'a pas besoin de libérer la mémoire associée à internalPtr ou saveInternalPtr ; freeProc sera appelé pour libérer cette mémoire si nécessaire. RestoreProc n'a pas de valeur de retour.

La procédure freeProc est appelée par Tk_SetOptions et Tk_FreeSavedOptions pour libérer toute mémoire allouée pour la représentation interne d'une option personnalisée. L'argument clientData est une copie du champ clientData dans la structure Tk_ObjCustomOption. Tkwin est une copie de l'argument tkwin de Tk_GetOptionValue ou Tk_GetOptionInfo. InternalPtr est un pointeur vers l'emplacement où la représentation interne de la valeur de l'option est stockée. Le freeProc doit libérer toute mémoire associée à l'option. FreeProc n'a pas de valeur de retour.
