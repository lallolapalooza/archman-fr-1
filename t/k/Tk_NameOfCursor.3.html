Notez que la chaîne retournée par Tk_NameOfCursor n'est garantie que jusqu'au prochain appel à Tk_NameOfCursor. De plus, cet appel n'est pas portable, sauf pour les curseurs retournés par Tk_GetCursor.

Lorsqu'un curseur retourné par Tk_AllocCursorFromObj, Tk_GetCursor ou Tk_GetCursorFromData n'est plus nécessaire, il convient d'appeler Tk_FreeCursorFromObj ou Tk_FreeCursor pour le libérer. Pour Tk_FreeCursorFromObj, le curseur à libérer est spécifié avec les mêmes informations utilisées pour le créer ; pour Tk_FreeCursor, le curseur à libérer est spécifié avec son jeton Tk_Cursor. Il devrait y avoir exactement un appel à Tk_FreeCursor pour chaque appel à Tk_AllocCursorFromObj, Tk_GetCursor ou Tk_GetCursorFromData.

BOGUES

Pour déterminer si un curseur existant peut satisfaire une nouvelle demande, Tk_AllocCursorFromObj, Tk_GetCursor et Tk_GetCursorFromData ne considèrent que les valeurs immédiates de leurs arguments. Par exemple, lorsqu'un nom de fichier est passé à Tk_GetCursor, Tk_GetCursor supposera qu'il est sûr de réutiliser un curseur existant créé à partir du même nom de fichier : il ne vérifiera pas si le fichier lui-même a changé, ou si le répertoire courant a changé, ce qui amènerait le nom à faire référence à un fichier différent. De même, Tk_GetCursorFromData suppose que si le même pointeur *source* est utilisé dans deux appels différents, alors les pointeurs font référence aux mêmes données ; il ne vérifie pas si les valeurs de données réelles ont changé.
