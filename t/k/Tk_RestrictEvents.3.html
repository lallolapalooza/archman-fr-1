Tk_RestrictEvents(3) Procédures de la bibliothèque Tk Tk_RestrictEvents(3)

NOM

Tk_RestrictEvents - filtre et retarde sélectivement les événements X

SYNTAXE

#include <tk.h>

Tk_RestrictProc *
Tk_RestrictEvents(proc, arg, prevArgPtr)

ARGUMENTS

Tk_RestrictProc *proc (entrée)
Procédure prédicat à appeler pour filtrer les événements X entrants. NULL signifie ne pas restreindre les événements du tout.
ClientData arg (entrée)
Argument arbitraire à passer à proc.
ClientData *prevArgPtr (sortie)
Pointeur vers l'emplacement où enregistrer l'argument de la procédure de restriction précédente.

DESCRIPTION

Cette procédure est utile dans certaines situations où les applications ne sont préparées qu'à recevoir certains événements X. Après l'appel de Tk_RestrictEvents, Tcl_DoOneEvent (et par conséquent Tk_MainLoop) filtrera les événements d'entrée X à travers proc. Proc indique si un événement donné doit être traité immédiatement, différé à un moment ultérieur (par exemple, lorsque la restriction d'événements est levée), ou ignoré. Proc est une procédure dont les arguments et le résultat correspondent au type Tk_RestrictProc :

typedef Tk_RestrictAction Tk_RestrictProc(
        ClientData arg,
        XEvent *eventPtr);
L'argument arg est une copie de l'argument arg passé à Tk_RestrictEvents ; il peut être utilisé pour fournir à proc les informations dont elle a besoin pour filtrer les événements. L'argument eventPtr pointe vers un événement en cours d'examen. Proc renvoie une action de restriction (type énuméré Tk_RestrictAction) qui indique ce que Tcl_DoOneEvent doit faire avec l'événement. Si la valeur de retour est TK_PROCESS_EVENT, l'événement sera traité immédiatement. Si la valeur de retour est TK_DEFER_EVENT, l'événement sera laissé dans la file d'attente des événements pour un traitement ultérieur. Si la valeur de retour est TK_DISCARD_EVENT, l'événement sera retiré de la file d'attente des événements et ignoré sans être traité.

Tk_RestrictEvents utilise sa valeur de retour et prevArgPtr pour renvoyer des informations sur la procédure de restriction d'événements actuelle (une valeur NULL signifie qu'il n'y a actuellement aucune restriction). Ces valeurs peuvent être utilisées pour restaurer l'état de restriction précédent lorsqu'il n'y a plus besoin de la restriction actuelle.

Il y a très peu d'endroits où Tk_RestrictEvents est nécessaire. Dans la plupart des cas, la meilleure façon de restreindre les événements est de modifier les liaisons avec la commande Tcl bind ou en appelant Tk_CreateEventHandler et Tk_DeleteEventHandler depuis C. L'endroit principal où Tk_RestrictEvents doit être utilisé est lors de l'exécution d'actions synchrones (par exemple, si vous devez attendre qu'un événement particulier se produise sur une fenêtre particulière mais que vous ne souhaitez pas invoquer de gestionnaires pour d'autres événements). La solution « évidente » dans ces situations est d'appeler XNextEvent ou XWindowEvent, mais ces procédures ne peuvent pas être utilisées car Tk conserve sa propre file d'attente d'événements, séparée de la file d'attente des événements X. Au lieu de cela, appelez Tk_RestrictEvents pour configurer un filtre, puis appelez Tcl_DoOneEvent pour récupérer les événements souhaités.
