NOM

Tk::Widget - Classe de base de tous les widgets

SYNTAXE

package Tk::Whatever;
require Tk::Widget;
@ISA = qw(Tk::Widget);
Construct Tk::Widget 'Whatever';
sub Tk_cmd { \&Tk::whatever }

   $widget->méthode(?arg, arg, ...?)

DESCRIPTION

Tk::Widget est une classe de base abstraite pour tous les widgets Tk.

Les méthodes génériques disponibles pour tous les widgets incluent les méthodes basées sur le mécanisme de base "winfo" et sont utilisées pour récupérer des informations sur les fenêtres gérées par Tk. Elles peuvent prendre différentes formes, en fonction de la méthode. Les formes valides sont :

$widget->appname?(newName)?
Si newName n'est pas spécifié, cette méthode renvoie le nom de l'application (le nom qui peut être utilisé dans les commandes send pour communiquer avec l'application). Si newName est spécifié, alors le nom de l'application est changé en newName. Si le nom donné est déjà utilisé, alors un suffixe de la forme `` #2'' ou `` #3'' est ajouté afin de rendre le nom unique. Le résultat de la méthode est le nom réellement choisi. newName ne doit pas commencer par une lettre majuscule. Cela interférera avec le traitement des options, car les noms commençant par des majuscules sont supposés être des classes ; par conséquent, Tk peut ne pas être en mesure de trouver certaines options pour l'application. Si les envois ont été désactivés en supprimant la commande send, cette commande les réactivera et recréera la commande send.
$widget->atom(name)
Renvoie une chaîne décimale donnant l'identifiant entier de l'atome dont le nom est name. Si aucun atome n'existe avec le nom name, un nouvel atome est créé.
$widget->atomname(id)
Renvoie le nom textuel de l'atome dont l'identifiant entier est id. Cette commande est l'inverse de la commande $widget->atom. Elle génère une erreur si aucun atome de ce type n'existe.
$widget->bell(?-nice?);
Cette commande fait sonner la cloche de l'écran pour $widget et renvoie une chaîne vide. La commande utilise les paramètres actuels liés à la cloche pour l'écran, qui peuvent être modifiés avec des programmes tels que xset.

Si -nice n'est pas spécifié, cette commande réinitialise également le protecteur d'écran. Certains protecteurs d'écran l'ignoreront, mais d'autres seront réinitialisés de sorte que l'écran redevienne visible.

$widget->bindDump
Cette commande renvoie une liste de chaînes appropriées pour l'impression, détaillant les informations de liaison pour un widget. Elle imprime les bindtags d'un widget. Pour chaque balise de liaison, elle imprime toutes les liaisons, composées du descripteur d'événement et du rappel. Les arguments du rappel sont imprimés et les objets Tk::Ev sont développés.
$widget->Busy?(?-recurse => 1?,-option => value?)?
Cette méthode configure une option -cursor pour $widget et (si -recurse = 1> est spécifié) tous ses descendants. Le curseur à définir peut être passé sous forme de -cursor = curseur> ou vaut 'watch' par défaut. Les options de configuration supplémentaires sont appliquées uniquement à $widget. Elle ajoute également une balise spéciale 'Busy' aux bindtags des widgets ainsi configurés, de sorte que les événements KeyPress, KeyRelease, ButtonPress et ButtonRelease soient ignorés (les événements de pression générant un appel à bell). Elle acquiert ensuite un grab local pour $widget. L'état des widgets et du grab est restauré par un appel à $widget->Unbusy.
$widget->caret(?-x => x?, ?-y => y?, ?-height => height?);
Définit et interroge l'emplacement du curseur pour l'affichage de la fenêtre Tk spécifiée. Le curseur est l'emplacement du curseur par écran utilisé pour indiquer le focus global (par exemple, pour se conformer aux directives d'accessibilité de Microsoft), ainsi que pour la localisation des fenêtres XIM (X Input Methods) ou IME de Windows. Si aucune option n'est spécifiée, les dernières valeurs utilisées pour définir le curseur sont renvoyées sous forme de paires option-valeur. -x et -y représentent des coordonnées relatives à la fenêtre, et -height est la hauteur de l'emplacement actuel du curseur, ou la hauteur de la fenêtre spécifiée si aucune n'est donnée.
$widget->cells
Renvoie une chaîne décimale donnant le nombre de cellules dans la palette de couleurs pour $widget.
$widget->children
$widget->children Renvoie une liste contenant tous les enfants de $widget. La liste est dans l'ordre d'empilement, avec la fenêtre la plus basse en premier. Les fenêtres de niveau supérieur sont renvoyées comme enfants de leurs parents logiques.
$widget->class
Renvoie le nom de classe pour $widget.
$widget->colormapfull
Renvoie 1 si la palette de couleurs pour $widget est connue pour être pleine, 0 sinon. La palette de couleurs d'une fenêtre est « connue » pour être pleine si la dernière tentative d'allocation d'une nouvelle couleur dans cette fenêtre a échoué et que cette application n'a libéré aucune couleur dans la palette depuis l'allocation échouée.
$widget->ConfigSpecs
Utilisé pour effectuer la configuration déléguée des options d'un méga-widget. Renvoie, en notation Tk::Derived::ConfigSpecs (voir Tk::ConfigSpecs), toutes les options possibles pour un widget. Par exemple, 
$s = $self->Scale;
$self->ConfigSpecs(
    $s->ConfigSpecs,
    .... plus de spécifications ConfigSpecs
);

renvoie une table de hachage de toutes les options Tk::Scale, déléguées à $s - par exemple, quelques exemples représentatifs :

-bigincrement => [$s, bigIncrement, BigIncrement, 0, 0]
-digits       => [$s, digits, Digits, 0, 0]
-sliderlength => [$s, sliderLength, SliderLength, 10m, 30]
-troughcolor  => [$s, troughColor, Background, #c3c3c3, #c3c3c3]

Cela fournit un moyen facile de peupler les ConfigSpecs d'un méga-widget avec des initialisateurs.

$widget->containing(rootX,rootY)
Renvoie la fenêtre contenant le point donné par rootX et rootY. RootX et rootY sont spécifiés en unités d'écran (c'est-à-dire toute forme acceptable par Tk_GetPixels) dans le système de coordonnées de la fenêtre racine (si un gestionnaire de fenêtres racine virtuelle est utilisé, alors le système de coordonnées de la fenêtre racine virtuelle est utilisé). Si aucune fenêtre dans cette application ne contient le point, une chaîne vide est renvoyée. Dans la sélection de la fenêtre contenant, les enfants ont une priorité plus élevée que les parents et parmi les frères et sœurs, le plus haut dans l'ordre d'empilement est choisi.
$widget->depth
Renvoie une chaîne décimale donnant la profondeur de $widget (nombre de bits par pixel).
$widget->destroy
Cette commande supprime la fenêtre liée à $widget, ainsi que tous ses descendants. Si toutes les MainWindows sont supprimées, l'application entière sera détruite.

L'objet perl $widget continue d'exister tant que des références à celui-ci existent, par exemple jusqu'à ce que la variable sorte de portée. Cependant, toute tentative d'utilisation de méthodes Tk sur l'objet échouera. Exists($widget) renverra faux pour de tels objets.

Notez cependant que pendant qu'une fenêtre existe pour $widget, l'objet perl est maintenu (en raison des « références » internes de perl/Tk) même si les variables originales sont sorties de portée. (Normalement, c'est intuitif.)

Exists($widget)
Renvoie 1 s'il existe une fenêtre pour $widget, 0 si aucune fenêtre de ce type n'existe.
$widget->font(option?, arg, arg, ...?)
Crée et inspecte les polices. Voir Tk::Font pour plus de détails.

$widget->scaling?(nombre)?
Définit et interroge le facteur de mise à l'échelle actuel utilisé par Tk pour convertir entre les unités physiques (par exemple, points, pouces ou millimètres) et les pixels. L'argument nombre est un nombre à virgule flottante qui spécifie le nombre de pixels par point sur l'affichage de $widget. Si l'argument nombre est omis, la valeur actuelle du facteur de mise à l'échelle est retournée.

Un « point » est une unité de mesure égale à 1/72 de pouce. Un facteur de mise à l'échelle de 1,0 correspond à 1 pixel par point, ce qui est équivalent à un moniteur standard de 72 dpi. Un facteur de mise à l'échelle de 1,25 signifierait 1,25 pixels par point, ce qui correspond au réglage d'un moniteur de 90 dpi ; régler le facteur de mise à l'échelle sur 1,25 sur un moniteur de 72 dpi ferait en sorte que tout dans l'application s'affiche 1,25 fois plus grand que la normale. La valeur initiale du facteur de mise à l'échelle est définie au démarrage de l'application, en fonction des propriétés du moniteur installé (telles que rapportées par le système de fenêtrage), mais elle peut être modifiée à tout moment. Les mesures effectuées après la modification du facteur de mise à l'échelle utiliseront le nouveau facteur, mais il n'est pas défini si les widgets existants se redimensionneront dynamiquement pour s'adapter au nouveau facteur.

$widget->screen
Retourne le nom de l'écran associé à $widget, sous la forme nomAffichage.indiceEcran.
$widget->screencells
Retourne une chaîne décimale donnant le nombre de cellules dans la palette de couleurs par défaut pour l'écran de $widget.
$widget->screendepth
Retourne une chaîne décimale donnant la profondeur de la fenêtre racine de l'écran de $widget (nombre de bits par pixel).
$widget->screenheight
Retourne une chaîne décimale donnant la hauteur de l'écran de $widget, en pixels.
$widget->screenmmheight
Retourne une chaîne décimale donnant la hauteur de l'écran de $widget, en millimètres.
$widget->screenmmwidth
Retourne une chaîne décimale donnant la largeur de l'écran de $widget, en millimètres.
$widget->screenvisual
Retourne l'une des chaînes suivantes pour indiquer la classe visuelle par défaut de l'écran de $widget : directcolor, grayscale, pseudocolor, staticcolor, staticgray ou truecolor.
$widget->screenwidth
Retourne une chaîne décimale donnant la largeur de l'écran de $widget, en pixels.
$widget->server
Retourne une chaîne contenant des informations sur le serveur pour l'affichage de $widget. Le format exact de cette chaîne peut varier d'une plateforme à l'autre. Pour les serveurs X, la chaîne a la forme ``XmajorRminor vendor vendorVersion'' où major et minor sont les numéros de version et de révision fournis par le serveur (par exemple, X11R5), vendor est le nom du fournisseur du serveur et vendorRelease est un numéro de version entier fourni par le serveur.
$widget->toplevel
Retourne la référence de la fenêtre de plus haut niveau contenant $widget.
$widget->Unbusy
Restaure l'état du widget après un appel à $widget->Busy.
$widget->UnmapWindow
Fait en sorte que $widget soit « démappé », c'est-à-dire retiré de l'affichage. Cela fait pour n'importe quel widget ce que
$widget->withdraw fait pour les widgets de plus haut niveau. Peut dérouter le gestionnaire de géométrie (pack, grid, place, ...) qui pense gérer le widget.
$widget->update
L'une des deux méthodes utilisées pour « mettre à jour » l'application en entrant dans la boucle d'événements de manière répétée jusqu'à ce que tous les événements en attente (y compris les rappels inactifs) aient été traités.

La méthode update est utile dans les scripts où vous effectuez un calcul de longue durée mais où vous souhaitez toujours que l'application réponde aux événements tels que les interactions utilisateur ; si vous appelez occasionnellement update, les entrées utilisateur seront traitées lors du prochain appel à update.

$widget->useinputmethods( ?booléen? )
Définit et interroge l'état de l'utilisation des méthodes d'entrée XIM (X Input Methods) par Tk pour filtrer les événements. L'état résultant est retourné. XIM est utilisé dans certaines localités (par exemple, japonais, coréen) pour gérer des périphériques d'entrée spéciaux. Cette fonctionnalité n'est significative que sur X. Si le support XIM n'est pas disponible, cela retournera toujours 0. Si l'argument booléen est omis, l'état actuel est retourné. Ceci est activé par défaut pour l'affichage principal.
$widget->viewable
Retourne 1 si $widget et tous ses ancêtres jusqu'à la fenêtre de plus haut niveau la plus proche sont mappés. Retourne 0 si l'une de ces fenêtres n'est pas mappée.
$widget->visual
Retourne l'une des chaînes suivantes pour indiquer la classe visuelle de $widget : directcolor, grayscale, pseudocolor, staticcolor, staticgray ou truecolor.
$widget->visualid
Retourne l'identifiant X du visuel pour $widget.
$widget->visualsavailable(?includeids?)
Retourne une liste dont les éléments décrivent les visuels disponibles pour l'écran de $widget. Chaque élément se compose d'une classe visuelle suivie d'une profondeur entière. La classe a la même forme que celle retournée par
$widget->visual. La profondeur donne le nombre de bits par pixel dans le visuel. De plus, si l'argument includeids est fourni, la profondeur est suivie de l'identifiant X du visuel.
$widget->vrootheight
Retourne la hauteur de la fenêtre racine virtuelle associée à $widget s'il y en a une ; sinon, retourne la hauteur de l'écran de $widget.
$widget->vrootwidth
Retourne la largeur de la fenêtre racine virtuelle associée à $widget s'il y en a une ; sinon, retourne la largeur de l'écran de $widget.
$widget->vrootx
Retourne le décalage x de la fenêtre racine virtuelle associée à $widget, par rapport à la fenêtre racine de son écran. Ceci est normalement soit zéro, soit négatif. Retourne 0 s'il n'y a pas de fenêtre racine virtuelle pour $widget.
$widget->vrooty
Retourne le décalage y de la fenêtre racine virtuelle associée à $widget, par rapport à la fenêtre racine de son écran. Ceci est normalement soit zéro, soit négatif. Retourne 0 s'il n'y a pas de fenêtre racine virtuelle pour $widget.
$widget->waitVariable(\$nom)
$widget->waitVisibility
$widget->waitWindow
Les méthodes tk wait attendent que l'une des choses suivantes se produise, puis elles retournent sans aucune autre action. La valeur de retour est toujours une chaîne vide. waitVariable attend une référence à une variable perl et la commande attend que cette variable soit modifiée. Cette forme est généralement utilisée pour attendre qu'un utilisateur ait fini d'interagir avec une boîte de dialogue qui définit la variable comme faisant partie (potentiellement finale) de l'interaction. waitVisibility attend un changement dans l'état de visibilité de $widget (tel qu'indiqué par l'arrivée d'un événement VisibilityNotify). Cette forme est généralement utilisée pour attendre qu'une fenêtre nouvellement créée apparaisse à l'écran avant d'effectuer une action. waitWindow attend que $widget soit détruit. Cette forme est généralement utilisée pour attendre qu'un utilisateur ait fini d'interagir avec une boîte de dialogue avant d'utiliser le résultat de cette interaction. Notez que créer et détruire la fenêtre à chaque fois qu'une boîte de dialogue est nécessaire rend le code modulaire mais impose une surcharge qui peut être évitée en retirant la fenêtre à la place et en utilisant waitVisibility.

Pendant que les méthodes tk wait attendent, elles traitent les événements normalement, de sorte que l'application continuera de répondre aux interactions utilisateur. Si un gestionnaire d'événements appelle à nouveau tkwait, l'appel imbriqué à tkwait doit se terminer avant que l'appel externe puisse se terminer.

$widget->Walk(proc?, arg, ...?)
Parcourt une hiérarchie de widgets à partir de $widget tout en exécutant la sous-routine proc pour chaque widget visité. Les arguments arg, ... sont fournis à la sous-routine.
$widget->Widget(pathname)
Retourne la référence du widget pour le nom de chemin Tk donné, ou "undef" si le nom de chemin ne correspond pas à un widget Tk. C'est l'inverse de la méthode "PathName". (Ceci est une importation de l'interface C.)
$widget->width
Retourne une chaîne décimale donnant la largeur de $widget en pixels. Lorsqu'une fenêtre est créée pour la première fois, sa largeur sera de 1 pixel ; la largeur sera éventuellement modifiée par un gestionnaire de géométrie pour répondre aux besoins de la fenêtre. Si vous avez besoin de la largeur réelle immédiatement après la création d'un widget, appelez update pour forcer le gestionnaire de géométrie à l'arranger, ou utilisez
$widget->reqwidth pour obtenir la largeur demandée de la fenêtre au lieu de sa largeur réelle.
$widget->windowingsystem
Retourne le système de fenêtrage Tk actuel, l'un des suivants : x11 (basé sur X11), win32 (MS Windows), classic (Mac OS Classic) ou aqua (Mac OS X Aqua).
$widget->x
Retourne une chaîne décimale donnant la coordonnée x, dans le parent de $widget, du coin supérieur gauche de $widget la bordure (ou $widget s'il n'a pas de bordure).
$widget->y
Retourne une chaîne décimale donnant la coordonnée y, dans le parent de $widget, du coin supérieur gauche de la bordure de $widget (ou $widget s'il n'a pas de bordure).
