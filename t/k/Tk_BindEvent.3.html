Tk_CreateBindingTable(3) Procédures de la Bibliothèque Tk Tk_CreateBindingTable(3)

NAME

Tk_CreateBindingTable, Tk_DeleteBindingTable, Tk_CreateBinding, Tk_DeleteBinding, Tk_GetBinding, Tk_GetAllBindings, Tk_DeleteAllBindings, Tk_BindEvent - invoquer des scripts en réponse à des événements X

SYNOPSIS

#include <tk.h>

Tk_BindingTable
Tk_CreateBindingTable(interp)

Tk_DeleteBindingTable(bindingTable)

unsigned long
Tk_CreateBinding(interp, bindingTable, object, eventString, script, append)

int
Tk_DeleteBinding(interp, bindingTable, object, eventString)

const char *
Tk_GetBinding(interp, bindingTable, object, eventString)

Tk_GetAllBindings(interp, bindingTable, object)

Tk_DeleteAllBindings(bindingTable, object)

Tk_BindEvent(bindingTable, eventPtr, tkwin, numObjects, objectPtr)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur à utiliser lors de l'appel des liaisons dans la table de liaisons. Utilisé également pour retourner les résultats et les erreurs des procédures de liaisons.
Tk_BindingTable bindingTable (entrée)
Jeton pour la table de liaisons ; doit avoir été retourné par un appel précédent à Tk_CreateBindingTable.
ClientData object (entrée)
Identifie l'objet auquel la liaison est associée.
const char *eventString (entrée)
Chaîne décrivant la séquence d'événements.
const char *script (entrée)
Script Tcl à invoquer lorsque la liaison est déclenchée.
int append (entrée)
Une valeur non nulle signifie ajouter script au script existant de la liaison, s'il existe ; zéro signifie remplacer le script existant par le nouveau.
XEvent *eventPtr (entrée)
Événement X à faire correspondre avec les liaisons dans bindingTable.
Tk_Window tkwin (entrée)
Identifiant de n'importe quelle fenêtre de l'écran où l'événement s'est produit. Utilisé pour trouver des informations relatives à l'écran, telles que les cartes de clavier.
int numObjects (entrée)
Nombre d'identifiants d'objet pointés par objectPtr.
ClientData *objectPtr (entrée)
Pointe vers un tableau d'identifiants d'objet : les liaisons sont examinées pour chacun de ces objets dans l'ordre, du premier au dernier.

DESCRIPTION

Ces fonctions fournissent un mécanisme général pour créer et invoquer des liaisons. Les liaisons sont organisées en termes de tables de liaisons. Une table de liaisons consiste en une collection de liaisons plus un historique des événements récents. Au sein d'une table de liaisons, les liaisons sont associées à des objets. La signification d'un objet est définie par les clients du package de liaisons. Par exemple, Tk utilise une table de liaisons pour stocker toutes les liaisons créées par la commande bind. Pour cette table, les objets sont des pointeurs vers des chaînes telles que des noms de fenêtres, des noms de classes ou d'autres tags de liaison comme all. Tk maintient également une table de liaisons distincte pour chaque widget de grille, qui gère les liaisons créées par la commande bind du widget de grille ; au sein de cette table, un objet est un pointeur vers la structure interne d'un élément de grille ou un Tk_Uid identifiant un tag.

La fonction Tk_CreateBindingTable crée une nouvelle table de liaisons et y associe interp (lorsque les liaisons de la table sont invoquées, les scripts seront évalués dans interp). Tk_CreateBindingTable retourne un jeton pour la table, qui doit être utilisé dans les appels à d'autres fonctions telles que Tk_CreateBinding ou Tk_BindEvent.

Tk_DeleteBindingTable libère tout état associé à une table de liaisons. Une fois qu'il est retourné, l'appelant ne doit plus utiliser le jeton bindingTable.

Tk_CreateBinding ajoute une nouvelle liaison à une table existante. L'argument object identifie l'objet auquel la liaison est associée et peut être n'importe quelle valeur d'un seul mot. Il s'agit souvent d'un pointeur vers une chaîne ou une structure de données. L'argument eventString identifie l'événement ou la séquence d'événements pour la liaison ; voir la documentation de la commande bind pour une description de son format. script est le script Tcl à évaluer lorsque la liaison est déclenchée. append indique quoi faire s'il existe déjà une liaison pour object et eventString : si append est zéro, script remplace le script existant ; si append est non nul, le nouveau script est ajouté au script existant. Tk_CreateBinding retourne un code d'événement X pour tous les événements associés aux liaisons. Ces informations peuvent être utiles pour appeler XSelectInput afin de sélectionner les événements pertinents, ou pour désactiver l'utilisation de certains événements dans les liaisons. Si une erreur se produit lors de la création de la liaison (par exemple, eventString fait référence à un événement inexistant), 0 est retourné et un message d'erreur est laissé comme résultat de l'interpréteur interp.

Tk_DeleteBinding supprime de bindingTable la liaison donnée par object et eventString, si une telle liaison existe. Tk_DeleteBinding retourne toujours TCL_OK. Dans certains cas, il peut réinitialiser le résultat de l'interpréteur à sa valeur par défaut.

Tk_GetBinding retourne un pointeur vers le script associé à eventString et object dans bindingTable. S'il n'existe pas de telle liaison, il retourne NULL et un message d'erreur est laissé comme résultat de l'interpréteur interp.

Tk_GetAllBindings retourne dans le résultat de interp une liste de toutes les chaînes d'événements pour lesquelles il existe des liaisons dans bindingTable associées à object. S'il n'y a pas de liaisons pour object, le résultat sera une chaîne vide.

Tk_DeleteAllBindings supprime toutes les liaisons dans bindingTable associées à object.

Tk_BindEvent est appelé pour traiter un événement. Il crée une copie de l'événement dans une liste interne d'événements associée à la table de liaisons, puis recherche les liaisons qui correspondent à l'événement. Tk_BindEvent traite chaque objet pointé par objectPtr dans l'ordre. Pour chaque objet, il trouve toutes les liaisons qui correspondent à l'historique des événements actuel, sélectionne la liaison la plus spécifique en utilisant le mécanisme de priorité décrit dans la documentation de la commande bind, et invoque le script pour cette liaison. S'il n'y a pas de liaisons correspondantes pour un objet, l'objet est ignoré. Tk_BindEvent continue à traiter tous les objets, en gérant les exceptions telles que les erreurs, break et continue conformément à la documentation de la commande bind.
