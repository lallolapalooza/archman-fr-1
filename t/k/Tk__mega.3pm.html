NOM

Tk::mega - Support Perl/Tk pour l'écriture de widgets en pur Perl

SYNOPSIS

Définir le nouveau nom de classe du widget :

    package Tk::MonNouveauWidget;

Pour les classes de widgets composites :

    use base qw/ Tk::container / ; # où container est Frame ou Toplevel

Pour les classes de widgets dérivés :

    use base qw/ Tk::Derived Tk::WidgetDerive / ;

Installer le nouveau widget dans l'espace de noms de Tk et établir les constructeurs de classe et d'instance.

    Construct Tk::Widget 'MonNouveauWidget' ;

    sub ClassInit { mon ($self, $args) = @_ ; ... }

    sub Populate { mon ($self, $args) = @_ ; ... }

DESCRIPTION

L'objectif du support des méga-widgets de Perl/Tk est de faciliter la création de méga-widgets qui suivent le même protocole et la même interface que les widgets du cœur de Tk. Pour des exemples de code de méga-widgets, veuillez exécuter le programme de démonstration widget et aller à la section Exemples de méga-widgets Perl.

Il existe deux types de méga-widgets :

  • Widgets Composites

    Un widget composite est composé d'un ou plusieurs widgets existants. Le widget composite apparaît à l'utilisateur comme un simple widget unique. Un exemple bien connu est la boîte de sélection de fichiers.

  • Widgets Dérivés

    Un widget dérivé ajoute/modifie/supprime des propriétés et des méthodes d'un seul widget (ce widget peut lui-même être un méga-widget).

SUPPORT DES MÉGA-WIDGETS

Advertise

Donner un nom symbolique à un sous-widget.

Utilisation :

    $self->Advertise(nom=>$widget) ;

Attribue au sous-widget $widget du méga-widget $self le nom nom. On peut récupérer la référence d'un sous-widget annoncé avec la méthode Subwidget.

Commentaire : Auteurs de méga-widgets : Veuillez vous assurer de documenter les widgets annoncés qui sont destinés à un usage public. S'il n'y en a aucun, documentez ce fait, par exemple :

=head1 WIDGETS ANNONCÉS
Aucun.

Callback

Invoquer une fonction de rappel spécifiée par une option.

Utilisation :

    $self->Callback(-option ?,arguments ...?) ;

Callback exécute la fonction de rappel définie avec $self->ConfigSpecs(-option, [CALLBACK, ...]) ; Si des arguments sont donnés, ils sont passés à la fonction de rappel. Si -option n'est pas défini, il ne fait rien.

ClassInit

Initialisation de la classe du méga-widget.

Utilisation :

    sub ClassInit { mon ($class, $mw) = @_ ; ... }

ClassInit est appelé une fois pour chaque MainWindow juste avant que la première instance de widget d'une classe ne soit créée dans l'arbre de widgets de MainWindow.

ClassInit est souvent utilisé pour définir des liaisons et/ou d'autres ressources partagées par toutes les instances, par exemple, des images.

Exemples :

$mw->bind($class,"<Tab>", sub { my $w = shift; $w->Insert("\t"); $w->focus; $w->break});
$mw->bind($class,"<Return>", ['Insert',"\n"]);
$mw->bind($class,"<Delete>",'Delete');

Notez que $class est le nom de la classe (par exemple, Tk::MonTexte) et $mw est la fenêtre principale.

N'oubliez pas d'appeler $class->SUPER::ClassInit($mw) dans ClassInit.

Component

Fonction pratique pour créer des sous-widgets.

Utilisation :

$cw->Component('Whatever', 'NomAnnonce',
    -delegate => ['methode1', 'methode2', ...],
    ... autres options de widget ...,
);

Component fait plusieurs choses pour vous en un seul appel :

o Crée le widget

o L'annonce avec un nom donné (annulé par l'option 'Name')

o Délègue un ensemble de méthodes à ce widget (facultatif)

Exemple :

$cw->Component('Button', 'boutonQuitter', -command => sub{$mw->'destroy'});

ConfigSpecs

Définit les options et leur traitement

Utilisation :

$cw->ConfigSpecs(
    -option => [ où, dbname, dbclass, défaut],
    ...,
    DEFAULT => [où],
);

Définit les options d'un méga-widget et quelles actions sont déclenchées par la configuration/récupération d'une option (voir Tk::ConfigSpecs et Tk::Derived pour les détails).

Construct

Rendre le nouveau méga-widget connu de Tk.

Utilisation :

    Construct classebase 'Nom';

Construct déclare la nouvelle classe de widget afin que votre méga-widget fonctionne comme les widgets Perl/Tk normaux.

Exemples :

    Construct Tk::Widget 'QuelqueChose' ;     Construct Tk::Menu 'MonItem' ;

Le premier exemple permet d'utiliser $widget->QuelqueChose pour créer un nouveau widget QuelqueChose.

Le second exemple restreint l'utilisation de la méthode constructeur MonItem aux widgets dérivés de Menu : $estunmenu->MonItem.

CreateArgs

Traiter les options avant la création de tout widget :

    sub CreateArgs { mon ($package, $parent, $args) = @_ ; ... ; return @nouveauxargs ; }

$package est le paquet du méga-widget (par exemple, Tk::MonTexte, $parent le parent du widget à créer et $args la référence de hachage vers les options spécifiées dans l'appel du constructeur de widget.

N'oubliez pas d'appeler $package->SUPER::CreateArgs($parent, $args) dans CreateArgs.

Delegates

Rediriger une méthode du méga-widget vers un sous-widget du widget composite

Utilisation :

$cw->Delegates(
    'methode1' => $souswidget1,
    'methode2' => 'nomAnnonce',
    ...,
    'Construct' => $souswidget2,
    'DEFAULT'   => $souswidget3,
);

La délégation 'Construct' a une signification particulière. Après que 'Construct' a été délégué, tous les constructeurs de Widget sont redirigés. Par exemple, après

    $self->Delegates('Construct'=>$sousframe) ;

un $self->Button fait réellement un $sousframe->Button, donc le bouton créé est un enfant de Tk::mega(3pm) — Documentation Perl

NOM

Tk::mega - Support des méga-widgets

SYNOPSIS

Toutes les méthodes de Tk::mega sont appelées via un widget Tk.

    my $mega_widget = $toplevel->MegaWidget(
        -option => value,
        ...
    );
    $mega_widget->method(args);

DESCRIPTION

La classe Tk::mega est une classe de base pour construire des widgets composites (appelés « méga-widgets »). Un méga-widget est une collection de widgets Tk standards qui ensemble se comportent comme un widget unique. Le méga-widget gère les options communes aux sous-widgets et fournit une interface publique unifiée.

Les méga-widgets sont généralement construits en créant une nouvelle classe qui hérite de Tk::Composite. Les méthodes principales fournies par Tk::mega sont utilisées pour définir la construction et l'interface du méga-widget.

SUPPORT DES MÉGA-WIDGETS

Advertise

Déclare un sous-widget comme faisant partie du méga-widget. Cela permet aux sous-widgets d'être créés automatiquement avec le méga-widget.

Usage:

    $mw->Advertise(name => widget_type, ...);

Où name est le nom par lequel le méga-widget référencera ce sous-widget (par exemple, dans la méthode Subwidget), et widget_type est la classe du widget Tk à créer (par exemple, 'button', 'label').

Comment : Ceci est généralement appelé dans la méthode Populate du méga-widget.

Composite

Crée un widget composite.

Usage:

    my $mw = $parent->Composite(
        -widgetName => 'name',
        -option     => value,
        ...
    );

Composite est généralement utilisé dans le constructeur de votre classe méga-widget. Il crée le widget de base du méga-widget.

ConfigSpecs

Définit les options de configuration pour le méga-widget.

Usage:

    my @specs = (
        [ -option1 => 'WidgetOption1', 'Tk::widget', 'option1' ],
        [ -option2 => 'WidgetOption2', 'Tk::widget', 'option2', value ],
        ...
    );
    $mw->ConfigSpecs(@specs);

Les spécifications de configuration indiquent comment les options du méga-widget sont mappées aux options des sous-widgets ou comment elles sont traitées.

Les éléments de chaque spécification sont :

-option
Le nom de l'option du méga-widget (doit commencer par un tiret).
WidgetOption
Le nom de l'option du sous-widget auquel l'option du méga-widget sera mappée.
Tk::widget
La classe du widget Tk de destination (par exemple, 'Tk::button'). Si elle est omise, l'option sera gérée par le méga-widget lui-même.
value
Une valeur par défaut optionnelle pour l'option.

Comment : Ceci est généralement appelé dans la méthode Populate du méga-widget.

Delegate

Délègue les appels de méthodes à un sous-widget.

Usage:

    $mw->Delegate(method_name => subwidget_name, ...);

Où method_name est le nom de la méthode à déléguer et subwidget_name est le nom du sous-widget (tel que défini dans Advertise) auquel la méthode sera déléguée.

Comment : Les délégations ne fonctionnent qu'avec les méthodes que $cw n'a pas lui-même.

InitObject

Note : cette méthode ne doit généralement pas être utilisée, car elle a été remplacée par Populate et la spécification de Tk::Derived comme l'une des classes de base.

Définit la construction et l'interface des widgets dérivés.

Usage:

sub InitObject {
    my ($derived, $args) = @_;
    ...
}

où $derived est la référence du widget de la classe de base déjà créée et $args est la référence vers un hash des paires -option-valeur.

InitObject est presque identique à la méthode Populate. Populate effectue des opérations « magiques » supplémentaires utiles pour les méga-widgets avec plusieurs widgets.

N'oubliez pas d'appeler $derived->SUPER::InitObject($args) dans InitObject.

OnDestroy

Définit un rappel appelé lorsque le méga-widget est détruit.

Usage:

    $widget->OnDestroy(callback);

OnDestroy installe un rappel qui est appelé lorsqu'un widget est sur le point d'être détruit. Utile pour des actions de nettoyage spéciales. Il diffère d'un destroy normal en ce que toutes les structures de données du widget sont encore intactes.

Comment : Cette méthode pourrait être utilisée avec n'importe quel widget, pas seulement avec les méga-widgets. Elle est listée ici en raison de son utilité.

Populate

Définit la construction et l'interface du widget composite.

Usage:

sub Populate {
    my ($self, $args) = @_;
    ...
}

où $self est la référence du widget de la classe de base déjà créée et $args est la référence vers un hash des paires -option-valeur.

La plupart des autres fonctions de support sont normalement utilisées à l'intérieur de la sous-routine Populate.

N'oubliez pas d'appeler $cw->SUPER::Populate($args) dans Populate.

privateData

Définit/obtient un hash privé d'un widget pour stocker les données internes du composite.

Usage:

    $hashref = $self->privateData();

    $another = $self->privateData(unique_key|package);

Subwidget

Obtient la référence du widget d'un sous-widget annoncé.

    @subwidget = $cw->Subwidget();

    $subwidget = $cw->Subwidget(name);

    @subwidget = $cw->Subwidget(name ?,...?);

Retourne la ou les références du widget du sous-widget connu sous le(s) nom(s) donné(s). Sans arguments, retourne tous les sous-widgets connus de $cw. Voir la méthode Advertise comment définir le nom d'un sous-widget.

Comment : Utilisateurs de méga-widgets : utilisez Subwidget pour obtenir uniquement les sous-widgets documentés.

PIÈGES

  • Nom de classe de la base de données de ressources

    Certaines options standard utilisent une base de données de ressources dont le nom de classe n'est pas égal au nom de la base de données des ressources. Par exemple :

    Switch:            Name:             Class:
-padx              padX              Pad
-activerelief      activeRelief      Relief
-activebackground  activeBackground  Foreground
-status            undef             undef

    Il faut faire de même lorsqu'on définit l'une de ces options via ConfigSpecs.

  • Délégation de méthode

    La redirection des méthodes vers un sous-widget avec Delegate ne peut fonctionner que si le widget de base lui-même possède une méthode de ce nom. Par conséquent, on ne peut pas « déléguer » les méthodes listées dans Tk::Widget. Une méthode problématique courante est bind. Dans ce cas, il faut explicitement rediriger la méthode.

    sub bind {
    my $self = shift;
    my $to = $self->privateData->{'my_bind_target'};
    $to->bind(@_);
}
  • privateData

    Graham Barr a écrit : ... C'est probablement plus privé que ce que la plupart des gens pensent. Tous les appels à privateData ne renverront pas la même référence HASH. La référence HASH retournée dépend du paquet à partir duquel elle a été appelée ; une référence HASH différente est renvoyée pour chaque paquet. Cela permet à un widget de conserver des données privées, mais si elle est sous-classée, la sous-classe recevra une référence HASH différente et ne causera donc pas de conflits de noms dupliqués.

    Mais privateData accepte un argument optionnel si vous souhaitez forcer la référence HASH à retourner.

  • Scrolled et Composite

    Le constructeur Scrolled(Kind,...) ne peut pas être utilisé avec Composite. Il faut utiliser $cw->Composite(ScrlKind => 'name', ...);

MANQUANT

Bien sûr, Perl/Tk ne fournit pas de fonctions de support pour toutes les nécessités. Voici une courte liste de choses que vous devez gérer vous-même :

  • Aucun support pour définir des options qui ne sont que pour la construction.
  • Aucun support pour supprimer une option déjà connue du widget de base.
  • Il est difficile de définir undef comme valeur de repli pour une option de widget qui n'est pas déjà undef.
  • Le Frame dans Perl/Tk transporte une magie et une surcharge non nécessaires pour la définition de la classe de widget composite.
  • Aucune méthode de support pour les liaisons (bindings) partagées entre tous les widgets d'un widget composite (cela a-t-il un sens ?).
