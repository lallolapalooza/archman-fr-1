Tk_ConfigureWidget(3) Procédures de la bibliothèque Tk Tk_ConfigureWidget(3)

NOM

Tk_ConfigureWidget, Tk_ConfigureInfo, Tk_ConfigureValue, Tk_FreeOptions - traiter les options de configuration pour les widgets

SYNOPSIS

#include <tk.h>

int
Tk_ConfigureWidget(interp, tkwin, specs, argc, argv, widgRec, flags)

int
Tk_ConfigureInfo(interp, tkwin, specs, widgRec, argvName, flags)

int
Tk_ConfigureValue(interp, tkwin, specs, widgRec, argvName, flags)

Tk_FreeOptions(specs, widgRec, display, flags)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur à utiliser pour retourner les messages d'erreur.
Tk_Window tkwin (entrée)
Fenêtre utilisée pour représenter le widget (nécessaire pour configurer les ressources X).
const Tk_ConfigSpec *specs (entrée)
Pointeur vers la table spécifiant les options de configuration légales pour ce widget.
int argc (entrée)
Nombre d'arguments dans argv.
const char **argv (entrée)
Options de la ligne de commande pour configurer le widget.
char *widgRec (entrée/sortie)
Pointe vers la structure d'enregistrement du widget. Les champs de cette structure sont modifiés par Tk_ConfigureWidget pour contenir les informations de configuration.
int flags (entrée)
Si non nul, il spécifie une combinaison ORée des indicateurs qui contrôlent le traitement des informations de configuration. TK_CONFIG_ARGV_ONLY fait ignorer la base de données d'options et les valeurs par défaut, et les bits d'indicateurs TK_CONFIG_USER_BIT et supérieurs sont utilisés pour désactiver sélectivement les entrées dans specs.
type name type (entrée)
Le nom du type d'un enregistrement de widget.
field name field (entrée)
Le nom d'un champ dans les enregistrements de type type.
const char *argvName (entrée)
Le nom utilisé dans les lignes de commande Tcl pour faire référence à une option particulière (par exemple, lors de la création d'un widget ou de l'invocation de la commande configure d'un widget). Si non NULL, les informations ne sont retournées que pour cette option. Si NULL, les informations sont retournées pour toutes les options disponibles.
Display *display (entrée)
Affichage contenant le widget dont l'enregistrement est libéré ; nécessaire pour libérer les ressources.

DESCRIPTION

Note : Tk_ConfigureWidget devrait être remplacé par la nouvelle API basée sur Tcl_Obj, Tk_SetOptions. L'ancienne interface est conservée pour des raisons de compatibilité ascendante.

Tk_ConfigureWidget est appelée pour configurer divers aspects d'un widget, tels que les couleurs, les polices, la largeur des bordures, etc. Elle est conçue comme une procédure de commodité pour réduire la quantité de code qui doit être écrite dans les gestionnaires de widgets individuels pour gérer les informations de configuration. Elle est généralement appelée lors de la création des widgets, et à nouveau lorsque la commande configure est invoquée pour un widget. Bien qu'elle soit principalement destinée aux widgets, Tk_ConfigureWidget peut être utilisée dans d'autres situations où les informations argc-argv doivent être utilisées pour remplir une structure d'enregistrement, telles que la configuration d'éléments graphiques pour un widget canvas ou d'entrées d'un menu.

Tk_ConfigureWidget traite une table spécifiant les options de configuration supportées (specs) et une collection d'arguments de ligne de commande (argc et argv) pour remplir les champs d'un enregistrement (widgRec). Elle utilise la base de données d'options et les valeurs par défaut spécifiées dans specs pour remplir les champs de widgRec qui ne sont pas spécifiés dans argv. Tk_ConfigureWidget retourne normalement la valeur TCL_OK ; dans ce cas, elle ne modifie pas interp. Si une erreur se produit, TCL_ERROR est retournée et Tk_ConfigureWidget laissera un message d'erreur dans le résultat de l'interpréteur interp de la manière standard de Tcl. En cas de retour d'erreur, certains des champs de widgRec pourraient déjà avoir été définis, si les informations de configuration les concernant ont été traitées avec succès avant que l'erreur ne se produise. Les autres champs seront définis avec des valeurs initiales raisonnables afin que Tk_FreeOptions puisse être appelée pour le nettoyage.

Le tableau specs spécifie les types d'options de configuration attendues par le widget. Chacune de ses entrées spécifie une option de configuration et a la structure suivante :

typedef struct {
    int type;
    const char *argvName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int offset;
    int specFlags;
    const Tk_CustomOption *customPtr;
} Tk_ConfigSpec;
Le champ type indique quel type d'option de configuration il s'agit (par exemple, TK_CONFIG_COLOR pour une valeur de couleur, ou TK_CONFIG_INT pour une valeur entière). Le champ type indique comment utiliser la valeur de l'option (plus à ce sujet ci-dessous). Le champ argvName est une chaîne telle que “-font” ou “-bg”, qui est comparée aux valeurs dans argv (si argvName est NULL, cela signifie qu'il s'agit d'une entrée groupée ; voir ENTRÉES GROUPÉES ci-dessous). Les champs dbName et dbClass sont utilisés pour rechercher une valeur pour cette option dans la base de données d'options. Le champ defValue spécifie une valeur par défaut pour cette option de configuration si aucune valeur n'est spécifiée dans argv ou dans la base de données d'options. Offset indique où dans widgRec stocker les informations sur cette option, et specFlags contient des informations supplémentaires pour contrôler le traitement de cette option de configuration (voir INDICATEURS ci-dessous). Le dernier champ, customPtr, n'est utilisé que si type est TK_CONFIG_CUSTOM ; voir TYPES D'OPTIONS PERSONNALISÉES ci-dessous.

Tk_ConfigureWidget traite d'abord argv pour voir quelles options de configuration (le cas échéant) y sont spécifiées. Argv doit contenir un nombre pair de champs ; le premier de chaque paire de champs doit correspondre à argvName d'une entrée dans specs (des abréviations uniques sont acceptables), et le second champ de la paire contient la valeur pour cette option de configuration. S'il y a des entrées dans spec pour lesquelles il n'y avait pas d'entrées correspondantes dans argv, Tk_ConfigureWidget utilise les champs dbName et dbClass de l'entrée specs pour sonder la base de données d'options ; si une valeur est trouvée, elle est utilisée comme valeur pour l'option. Enfin, si aucune entrée n'est trouvée dans la base de données d'options, le champ defValue de l'entrée specs est utilisé comme valeur pour l'option de configuration. Si defValue est NULL, ou si le bit TK_CONFIG_DONT_SET_DEFAULT est défini dans flags, alors il n'y a pas de valeur par défaut et cette entrée specs sera ignorée si aucune valeur n'est spécifiée dans argv ou dans la base de données d'options.

Une fois qu'une valeur de chaîne a été déterminée pour une option de configuration, Tk_ConfigureWidget traduit cette chaîne en une forme plus utile, telle qu'une couleur si type est TK_CONFIG_COLOR ou un entier si type est TK_CONFIG_INT. Cette valeur est ensuite stockée dans l'enregistrement pointé par widgRec. Cet enregistrement est supposé contenir des informations pertinentes pour le gestionnaire du widget ; son type exact est inconnu de Tk_ConfigureWidget. Le champ offset de chaque entrée specs indique où dans widgRec stocker les informations sur cette option de configuration. Vous devriez utiliser la macro Tk_Offset pour générer les valeurs d'offset (voir ci-dessous pour une description de Tk_Offset). L'emplacement indiqué par widgRec et offset sera désigné comme la « cible » dans les descriptions ci-dessous.

Le champ type de chaque entrée dans specs détermine quoi faire avec la valeur de chaîne de cette option de configuration. Les valeurs légales pour type, et les actions correspondantes, sont :

TK_CONFIG_ACTIVE_CURSOR
La valeur doit être une chaîne ASCII identifiant un curseur dans un format approprié pour être passé à Tk_GetCursor. La valeur est convertie en un Tk_Cursor en appelant Tk_GetCursor et le résultat est stocké dans la cible. De plus, le curseur résultant est défini comme le curseur actif pour tkwin en appelant XDefineCursor. Si TK_CONFIG_NULL_OK est spécifié dans specFlags, alors la valeur peut être une chaîne vide, auquel cas la cible et le curseur actif de tkwin seront définis sur None. Si la valeur précédente de la cible n'était pas None, elle est libérée en la passant à Tk_FreeCursor.
TK_CONFIG_ANCHOR
La valeur doit être une chaîne ASCII identifiant un point d'ancrage d'une des manières acceptées par Tk_GetAnchor. La chaîne est convertie en un Tk_Anchor en appelant Tk_GetAnchor et le résultat est stocké dans la cible.
TK_CONFIG_BITMAP
La valeur doit être une chaîne ASCII identifiant un bitmap dans un format approprié pour être passé à Tk_GetBitmap. La valeur est convertie en un Pixmap en appelant Tk_GetBitmap et le résultat est stocké dans la cible. Si le drapeau TK_CONFIG_NULL_OK est spécifié dans specFlags, la valeur peut être une chaîne vide, auquel cas la cible est définie à None. Si la valeur précédente de la cible n'est pas None, elle est libérée en la passant à Tk_FreeBitmap.
TK_CONFIG_BOOLEAN
La valeur doit être une chaîne ASCII spécifiant une valeur booléenne. Toute valeur parmi "true", "yes", "on", "1" ou une abréviation de l'une de ces valeurs indique vrai ; toute valeur parmi "false", "no", "off", "0" ou une abréviation de l'une de ces valeurs indique faux. La cible attendue est un entier ; pour les valeurs vraies, elle sera définie à 1 et pour les fausses, à 0.
TK_CONFIG_BORDER
La valeur doit être une chaîne ASCII identifiant une couleur de bordure dans un format approprié pour être passé à Tk_Get3DBorder. La valeur est convertie en un (Tk_3DBorder *) en appelant Tk_Get3DBorder et le résultat est stocké dans la cible. Si le drapeau TK_CONFIG_NULL_OK est spécifié dans specFlags, la valeur peut être une chaîne vide, auquel cas la cible sera définie à None. Si la valeur précédente de la cible n'est pas None, elle est libérée en la passant à Tk_Free3DBorder.
TK_CONFIG_CAP_STYLE
La valeur doit être une chaîne ASCII identifiant un style de capuchon dans l'un des styles acceptés par Tk_GetCapStyle. La chaîne est convertie en une valeur entière correspondant au style de capuchon en appelant Tk_GetCapStyle et le résultat est stocké dans la cible.
TK_CONFIG_COLOR
La valeur doit être une chaîne ASCII identifiant une couleur dans un format approprié pour être passé à Tk_GetColor. La valeur est convertie en un (XColor *) en appelant Tk_GetColor et le résultat est stocké dans la cible. Si le drapeau TK_CONFIG_NULL_OK est spécifié dans specFlags, la valeur peut être une chaîne vide, auquel cas la cible sera définie à None. Si la valeur précédente de la cible n'est pas None, elle est libérée en la passant à Tk_FreeColor.
TK_CONFIG_CURSOR
Cette option est identique à TK_CONFIG_ACTIVE_CURSOR, sauf que le nouveau curseur n'est pas défini comme curseur actif dans tkwin.
TK_CONFIG_CUSTOM
Cette option permet aux applications de définir de nouveaux types d'options. Le champ customPtr des entrées pointe vers une structure qui définit le nouveau type d'option. Voir la section CUSTOM OPTION TYPES pour plus de détails.
TK_CONFIG_DOUBLE
La valeur doit être un nombre à virgule flottante ASCII dans le format accepté par strtod. La chaîne est convertie en une valeur double et la valeur est stockée dans la cible.
TK_CONFIG_END
Marque la fin de la table. La dernière entrée dans specs doit avoir ce type ; tous les autres champs sont ignorés et ne correspondront jamais à des arguments.
TK_CONFIG_FONT
La valeur doit être une chaîne ASCII identifiant une police dans un format approprié pour être passé à Tk_GetFont. La valeur est convertie en un Tk_Font en appelant Tk_GetFont et le résultat est stocké dans la cible. Si le drapeau TK_CONFIG_NULL_OK est spécifié dans specFlags, la valeur peut être une chaîne vide, auquel cas la cible sera définie à None. Si la valeur précédente de la cible n'est pas None, elle est libérée en la passant à Tk_FreeFont.
TK_CONFIG_INT
La valeur doit être une chaîne ASCII spécifiant un entier dans le format accepté par strtol (par exemple, 0 et 0x... pour spécifier des nombres octaux ou hexadécimaux). La chaîne est convertie en une valeur entière et celle-ci est stockée dans la cible.
TK_CONFIG_JOIN_STYLE
La valeur doit être une chaîne ASCII identifiant un style de jointure dans l'un des styles acceptés par Tk_GetJoinStyle. La chaîne est convertie en une valeur entière correspondant au style de jointure en appelant Tk_GetJoinStyle et le résultat est stocké dans la cible.
TK_CONFIG_JUSTIFY
La valeur doit être une chaîne ASCII identifiant une méthode d'alignement dans l'une des méthodes acceptées par Tk_GetJustify. La chaîne est convertie en une valeur Tk_Justify en appelant Tk_GetJustify et le résultat est stocké dans la cible.
TK_CONFIG_MM
La valeur doit spécifier une distance d'écran dans l'un des formats acceptés par Tk_GetScreenMM. La chaîne est convertie en une distance double précision en millimètres et la valeur est stockée dans la cible.
TK_CONFIG_PIXELS
La valeur doit spécifier des unités d'écran dans l'un des formats acceptés par Tk_GetPixels. La chaîne est convertie en une distance entière en pixels et la valeur est stockée dans la cible.
TK_CONFIG_RELIEF
La valeur doit être une chaîne ASCII identifiant un relief dans un format approprié pour être passé à Tk_GetRelief. La valeur est convertie en une valeur entière de relief en appelant Tk_GetRelief et le résultat est stocké dans la cible.
TK_CONFIG_STRING
Une copie de la valeur est faite en allouant de la mémoire avec Tcl_Alloc et la valeur est copiée dans l'espace alloué. Un pointeur vers la nouvelle chaîne est stocké dans la cible. Si le drapeau TK_CONFIG_NULL_OK est spécifié dans specFlags et que la valeur est une chaîne vide, la cible sera définie à None. Si la valeur précédente de la cible n'est pas None, elle est libérée en la passant à Tcl_Free.
TK_CONFIG_SYNONYM
Cette valeur de type identifie les entrées spéciales dans specs qui sont des synonymes d'autres entrées. Si une valeur d'argv correspond au argvName d'une entrée TK_CONFIG_SYNONYM, cette entrée n'est pas utilisée directement. Au lieu de cela, Tk_ConfigureWidget recherche dans specs une entrée dont le argvName est le même que le dbName de l'entrée TK_CONFIG_SYNONYM ; cette nouvelle entrée est utilisée comme si son argvName avait correspondu à la valeur argv. Le mécanisme de synonyme permet d'utiliser plusieurs valeurs argv pour une seule option de configuration, telles que -background et -bg.
TK_CONFIG_UID
La valeur est traduite en un Tk_Uid (en passant la valeur à Tk_GetUid). Le résultat est stocké dans la cible. Si le drapeau TK_CONFIG_NULL_OK est spécifié dans specFlags et que la valeur est une chaîne vide, la cible sera définie à None.
TK_CONFIG_WINDOW
La valeur doit être un nom de chemin de fenêtre. Elle est traduite en un jeton Tk_Window et le jeton est stocké dans la cible.

GROUPED ENTRIES

Dans certains cas, il est utile de générer plusieurs ressources à partir d'une seule valeur de configuration. Par exemple, un nom de couleur pourrait être utilisé à la fois pour générer la couleur d'arrière-plan d'un widget (en utilisant TK_CONFIG_COLOR) et pour générer une bordure 3D à dessiner autour du widget (en utilisant TK_CONFIG_BORDER). Dans de tels cas, il est possible de spécifier que plusieurs entrées consécutives dans specs doivent être traitées comme un groupe. La première entrée est utilisée pour déterminer une valeur (en utilisant son argvName, dbName, dbClass et defValue). La valeur sera traitée plusieurs fois (une fois pour chaque entrée du groupe), générant ainsi plusieurs ressources distinctes et modifiant plusieurs cibles dans widgRec. Chaque entrée après la première doit avoir une valeur nulle dans son champ argvName ; cela indique que l'entrée est traitée comme faisant partie du groupe qui la précède. Seuls les champs type et offset de ces entrées suivantes sont utilisés.

FLAGS

L'argument flags passé à Tk_ConfigureWidget est utilisé conjointement avec les champs specFlags des entrées specs pour fournir un contrôle supplémentaire sur le traitement des options de configuration. Ces valeurs sont utilisées de trois manières différentes, comme décrit ci-dessous.

Premièrement, si l'argument flags de Tk_ConfigureWidget a le bit TK_CONFIG_ARGV_ONLY activé (c'est-à-dire, flags | TK_CONFIG_ARGV_ONLY != 0), alors les champs option base et defValue ne sont pas utilisés. Dans ce cas, si une entrée specs ne correspond pas à un champ argv, rien ne se passe : la cible correspondante n'est pas modifiée. Cette fonctionnalité est utile lorsque l'objectif est de modifier certaines options de configuration tandis que d'autres restent dans leur état actuel, comme lors du traitement d'une instruction de configuration de widget.

Deuxièmement, le champ specFlags d'une entrée specs peut être utilisé pour contrôler le traitement de cette entrée. Chaque champ specFlags peut consister en une combinaison OR des valeurs suivantes :

TK_CONFIG_COLOR_ONLY
Si ce bit est activé, l'entrée ne sera prise en compte que si l'écran de tkwin a plus d'un plan de couleur. Si l'écran est monochrome, cette entrée sera ignorée.
TK_CONFIG_MONO_ONLY

Si este bit está activado, el registro se considerará solo si la pantalla para tkwin tiene exactamente un plano de color. Si la pantalla no es monocromática, estas specs se ignorarán.

TK_CONFIG_NULL_OK
Este bit solo es relevante para algunos tipos de entradas (ver descripciones de los tipos de entradas diferentes arriba). Si este bit está activado, indica que un valor vacío para el campo es aceptable y si ocurre, el objetivo debe establecerse a NULL o None, dependiendo del tipo del objetivo. Este flag se usa típicamente para permitir que una función se deshabilite por completo, por ejemplo, establecer un valor del cursor a None para que una ventana simplemente herede el cursor de su padre. Si este bit no está activado, los valores vacíos se procesan como cadenas, lo que generalmente resulta en un error.
TK_CONFIG_DONT_SET_DEFAULT
Si este bit está activado, significa que el campo defValue de la entrada debe usarse solo para devolver el valor por defecto en Tk_ConfigureInfo. En las llamadas a Tk_ConfigureWidget, no se proporcionará ningún valor por defecto para las entradas con este bit activado; se asumirá que el llamante ya ha proporcionado un valor por defecto en el lugar del objetivo. Este flag proporciona una optimización de rendimiento donde es costoso procesar el valor por defecto: el cliente puede calcular el valor por defecto una vez, guardar el valor y proporcionarlo antes de llamar a Tk_ConfigureWidget.
TK_CONFIG_OPTION_SPECIFIED
Este bit ha sido descontinuado. Anteriormente, era activado y claramente borrado por Tk_ConfigureWidget para que los usuarios detectaran qué entradas estaban especificadas en argv, pero se eliminó porque era intrínsecamente inseguro en entornos multihilo. El código que desee detectar qué opciones estaban especificadas debería usar Tk_SetOptions en su lugar.

Los flags TK_CONFIG_MONO_ONLY y TK_CONFIG_COLOR_ONLY se utilizan típicamente para especificar valores por defecto diferentes para pantallas monocromáticas y a color. Esto se logra creando dos entradas en specs que son idénticas, salvo en sus campos defValue y specFlags. Una de las entradas debe tener el valor TK_CONFIG_MONO_ONLY en su campo specFlags y el valor por defecto para pantallas monocromáticas en su campo defValue; la otra debe tener el valor TK_CONFIG_COLOR_ONLY en su campo specFlags y el valor adecuado para pantallas a color.

En tercer lugar, es posible usar los campos flags y specFlags juntos para desactivar selectivamente algunas entradas. Esta característica no se necesita muy a menudo. Es útil en casos donde varios tipos de widgets similares se implementan en un solo lugar. Permite crear una única tabla specs con todas las opciones de configuración para todos los tipos de widgets. Cuando se procese un tipo de widget específico, solo se utilizarán las entradas relevantes. Este efecto se logra estableciendo los bits de orden superior (es decir, en las posiciones iguales o mayores que TK_CONFIG_USER_BIT) en los valores de specFlags o en flags. Para que una entrada en specs se utilice, sus bits de orden superior deben coincidir exactamente con los bits de orden superior del valor de flags pasado a Tk_ConfigureWidget. Si se está utilizando una tabla specs para N tipos de widgets distintos, entonces se usarán N de los bits de orden superior. Cada entrada en specs tendrá uno o más de estos bits activados en su campo specFlags para indicar qué tipos de widgets son válidos para esta entrada. Cuando se llama a Tk_ConfigureWidget, flags tendrá un solo uno de estos bits activado para seleccionar las entradas correspondientes al tipo de widget deseado. Para un ejemplo de esta característica, ver el código en tkButton.c.

TK_OFFSET

La macro Tk_Offset se proporciona como un método seguro de generar los valores de offset para las entradas en estructuras de Tk_ConfigSpec. Toma dos argumentos: el nombre de un tipo de registro y el nombre de una propiedad en ese registro. Devuelve la posición de byte de la propiedad nombrada en registros de tipo dado.

TK_CONFIGUREINFO

El procedimiento Tk_ConfigureInfo puede utilizarse para obtener información sobre las opciones de un widget dado. Dado un token para una ventana (tkwin), una tabla que describe las opciones de configuración para una clase de widgets (specs), un puntero a un registro de widget que contiene la información actual del widget (widgRec), y un argumento argvName nulo, Tk_ConfigureInfo genera una cadena que describe todas las opciones de configuración para la ventana. Esta cadena se coloca en el resultado del intérprete interp. En condiciones normales, devuelve TCL_OK; si ocurre un error, devuelve TCL_ERROR y el resultado del intérprete contendrá un mensaje de error.

Si argvName es nulo, entonces el valor en el resultado del intérprete interp generado por Tk_ConfigureInfo consiste en una lista de una o más entradas, cada una describiendo una opción de configuración (es decir, una entrada en specs). Cada entrada en la lista contendrá dos o cinco valores. Si la entrada correspondiente en specs tiene tipo TK_CONFIG_SYNONYM, la lista contendrá dos valores: el argvName de la entrada y el dbName (nombre del símbolo). De lo contrario, la lista contendrá cinco valores: argvName, dbName, dbClass, defValue, y el valor actual. El valor actual se calcula llamando a procedimientos como Tk_NameOfColor desde el campo adecuado de widgRec.

Si el argumento argvName de Tk_ConfigureInfo no es nulo, indica una sola opción y solo se devuelve información para esa opción. La cadena colocada en el resultado del intérprete interp será una lista de dos o cinco valores como se describió anteriormente; esto será idéntico a la sublista correspondiente que se habría devuelto si argvName fuera nulo.

El argumento flags de Tk_ConfigureInfo se usa para restringir las entradas specs a considerar, así como para Tk_ConfigureWidget.

TK_CONFIGUREVALUE

El procedimiento Tk_ConfigureValue toma argumentos similares a Tk_ConfigureInfo; en lugar de devolver una lista de valores, solo devuelve el valor actual de la opción dada por argvName (argvName no debe ser nulo). El valor se devuelve en el resultado del intérprete interp y TCL_OK se devuelve normalmente como resultado del procedimiento. Si ocurre un error en Tk_ConfigureValue (por ejemplo, argvName no es un nombre de opción válido), TCL_ERROR se devuelve y un mensaje de error se deja en el resultado del intérprete interp. Este procedimiento se usa típicamente para implementar los comandos cget de los widgets.

TK_FREEOPTIONS

El procedimiento Tk_FreeOptions puede invocarse durante la limpieza de widgets para liberar todos los recursos asociados a las opciones de configuración. Escanea a través de specs y libera los recursos en el registro de widget para cada entrada que corresponde a un recurso que debe ser liberado explícitamente (por ejemplo, aquellos con tipo TK_CONFIG_COLOR). Si el campo en el registro de widget no se refiere a un recurso (por ejemplo, contiene un puntero nulo), no se libera ningún recurso para esa entrada. Después de liberar un recurso, Tk_FreeOptions establece el campo correspondiente del registro de widget a null.

TIPOS DE OPCIONES PERSONALIZADAS

Las aplicaciones pueden extender los tipos de configuración predeterminados escribiendo procedimientos para analizar e imprimir opciones de un tipo específico, y creando una estructura que apunte a esos procedimientos:

typedef struct Tk_CustomOption {
    Tk_OptionParseProc *parseProc;
    Tk_OptionPrintProc *printProc;
    ClientData clientData;
} Tk_CustomOption;
typedef int Tk_OptionParseProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tk_Window tkwin,
        char *value,
        char *widgRec,
        int offset);
typedef const char *Tk_OptionPrintProc(
        ClientData clientData,
        Tk_Window tkwin,
        char *widgRec,
        int offset,
        Tcl_FreeProc **freeProcPtr);
La estructura Tk_CustomOption contiene tres campos, que son punteros a los dos procedimientos y un valor clientData que se pasa a esos procedimientos cuando se invocan. El valor clientData suele apuntar a una estructura que contiene la información necesaria para los procedimientos cuando se analizan y se imprimen las opciones.

El procedimiento parseProc es invocado por Tk_ConfigureWidget para analizar una cadena y almacenar el valor resultante en el registro de widget. El argumento clientData es una copia del campo clientData de la estructura Tk_CustomOption. El argumento interp apunta a un intérprete Tcl utilizado para informar de errores. Tkwin es una copia del argumento tkwin de Tk_ConfigureWidget. El argumento value es una cadena que describe el valor de la opción; podría haber sido especificado explícitamente en la llamada a Tk_ConfigureWidget o podría provenir de la base de datos de opciones o del valor por defecto. value nunca será un puntero nulo, pero puede apuntar a una cadena vacía. widgRec es el mismo que el argumento widgRec de Tk_ConfigureWidget; apunta al inicio del registro de widget a modificar. El último argumento, offset, indica la posición en bytes desde el inicio del registro de widget hasta el lugar donde se va a colocar el valor de la opción. El procedimiento debe convertir la cadena a la forma adecuada para la opción y almacenar el valor en el registro de widget. Debería devolver TCL_OK normalmente, pero si ocurre un error al convertir la cadena en un valor, debería devolver TCL_ERROR y almacenar un mensaje de error en el resultado del intérprete interp.

El procedimiento printProc es invocado por Tk_ConfigureInfo para producir una cadena de valor que describe una opción existente. Sus argumentos clientData, tkwin, widgRec, y offset tienen el mismo significado que en los procedimientos Tk_OptionParseProc. El procedimiento printProc debe examinar la opción cuyo valor se almacena en el registro de widget en la posición offset, producir una cadena que describa esa opción, y devolver un puntero a la cadena. Si el valor se almacena en memoria dinámica, el procedimiento debe establecer *freeProcPtr a la dirección de un procedimiento para liberar la memoria de la cadena; Tk_ConfigureInfo llamará a este procedimiento cuando se procese.

est terminé avec la chaîne de caractères. Si la chaîne résultante est stockée dans la mémoire statique, alors printProc n'a pas besoin de faire quoi que ce soit avec l'argument freeProcPtr.

Une fois que parseProc et printProc ont été définis et qu'une structure Tk_CustomOption a été créée pour eux, les options de ce nouveau type peuvent être manipulées avec des entrées Tk_ConfigSpec dont les champs type sont TK_CONFIG_CUSTOM et dont les champs customPtr pointent vers la structure Tk_CustomOption.

EXEMPLES

Bien que l'explication de Tk_ConfigureWidget soit assez compliquée, son utilisation réelle est assez simple. La façon la plus simple de commencer est de copier le code d'un widget existant. L'implémentation de la bibliothèque des cadres (tkFrame.c) a une table de configuration simple, et l'implémentation de la bibliothèque des boutons (tkButton.c) a une table beaucoup plus complexe qui utilise plusieurs des mécanismes sophistiqués de specFlags.
