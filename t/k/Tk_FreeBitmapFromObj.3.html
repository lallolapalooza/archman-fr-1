ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur à utiliser pour le rapport d'erreurs ; si NULL alors aucun message d'erreur n'est laissé après les erreurs.
Tk_Window tkwin (in)
Jeton pour la fenêtre dans laquelle la bitmap sera utilisée.
Tcl_Obj *objPtr (in/out)
La valeur de chaîne décrit la bitmap souhaitée ; la représentation interne sera modifiée pour mettre en cache le pointeur vers la Pixmap correspondante.
const char *info (in)
Identique à objPtr sauf que la description de la bitmap est passée sous forme de chaîne et que la Pixmap résultante n'est pas mise en cache.
const char *name (in)
Nom de la nouvelle bitmap à définir.
const void *source (in)
Données de la bitmap, au format bitmap standard. Doit être stocké dans une mémoire statique dont la valeur ne changera jamais.
int width (in)
Largeur de la bitmap.
int height (in)
Hauteur de la bitmap.
int *widthPtr (out)
Pointeur vers un mot à remplir avec la largeur de la bitmap.
int *heightPtr (out)
Pointeur vers un mot à remplir avec la hauteur de la bitmap.
Display *display (in)
Affichage pour lequel la bitmap a été allouée.
Pixmap bitmap (in)
Identifiant d'une bitmap allouée par Tk_AllocBitmapFromObj ou Tk_GetBitmap.

DESCRIPTION

Ces procédures gèrent une collection de bitmaps (pixmaps à plan unique) utilisées par une application. Les procédures permettent de réutiliser efficacement les bitmaps, évitant ainsi la surcharge du serveur, et permettent également de nommer les bitmaps avec des chaînes de caractères.

Tk_AllocBitmapFromObj renvoie un identifiant Pixmap pour une bitmap qui correspond à la description dans objPtr et qui convient à une utilisation dans tkwin. Elle réutilise une bitmap existante si possible et en crée une nouvelle sinon. La valeur de objPtr doit avoir l'une des formes suivantes :

@fileName
FileName doit être le nom d'un fichier contenant une description de bitmap au format standard X11.
name
Name doit être le nom d'une bitmap définie précédemment avec un appel à Tk_DefineBitmap. Les noms suivants sont prédéfinis par Tk :
error
Le symbole international “interdit” : un cercle avec une ligne diagonale.
gray75
Gris 75% : un motif à damier où trois bits sur quatre sont activés.
gray50
Gris 50% : un motif à damier où un bit sur deux est activé.
gray25
Gris 25% : un motif à damier où un bit sur quatre est activé.
gray12
Gris 12.5% : un motif où un huitième des bits sont activés, composé d'un pixel sur quatre dans une ligne sur deux.
hourglass
Un symbole de sablier.
info
Une grande lettre “i”.
questhead
La silhouette d'une tête humaine, avec un point d'interrogation à l'intérieur.
question
Un grand point d'interrogation.
warning
Un grand point d'exclamation.

De plus, les noms prédéfinis suivants sont disponibles uniquement sur la plateforme Macintosh :

document
Un document générique.
stationery
Papier à lettres pour document.
edition
Le symbole de l'édition.
application
Icône d'application générique.
accessory
Un accessoire de bureau.
folder
Icône de dossier générique.
pfolder
Un dossier verrouillé.
trash
Une poubelle.
floppy
Une disquette.
ramdisk
Une disquette avec une puce.
cdrom
Une icône de disque CD.
preferences
Un dossier avec le symbole des préférences.
querydoc
Une icône de document de base de données.
stop
Un panneau stop.
note
Un visage avec une bulle.
caution
Un triangle avec un point d'exclamation.

Dans des conditions normales, Tk_AllocBitmapFromObj renvoie un identifiant pour la bitmap demandée. Si une erreur survient lors de la création de la bitmap, par exemple si objPtr fait référence à un fichier inexistant, alors None est renvoyé et un message d'erreur est laissé dans le résultat de interp si interp n'est pas NULL. Tk_AllocBitmapFromObj met en cache les informations sur la valeur de retour dans objPtr, ce qui accélère les appels futurs à des procédures telles que Tk_AllocBitmapFromObj et Tk_GetBitmapFromObj.

Tk_GetBitmap est identique à Tk_AllocBitmapFromObj sauf que la description de la bitmap est spécifiée avec une chaîne au lieu d'un objet. Cela empêche Tk_GetBitmap de mettre en cache la valeur de retour, donc Tk_GetBitmap est moins efficace que Tk_AllocBitmapFromObj.

Tk_GetBitmapFromObj renvoie le jeton d'une bitmap existante, étant donné la fenêtre et la description utilisées pour créer la bitmap. Tk_GetBitmapFromObj ne crée pas réellement la bitmap ; la bitmap doit avoir déjà été créée par un appel précédent à Tk_AllocBitmapFromObj ou Tk_GetBitmap. La valeur de retour est mise en cache dans objPtr, ce qui accélère les appels futurs à Tk_GetBitmapFromObj avec le même objPtr et tkwin.

Tk_DefineBitmap associe un nom à des données de bitmap en mémoire afin que le nom puisse être utilisé dans des appels ultérieurs à Tk_AllocBitmapFromObj ou Tk_GetBitmap. L'argument nameId donne un nom à la bitmap ; il ne doit pas avoir été utilisé précédemment dans un appel à Tk_DefineBitmap. Les arguments source, width et height décrivent la bitmap. Tk_DefineBitmap renvoie normalement TCL_OK ; si une erreur se produit (par exemple, une bitmap nommée nameId a déjà été définie), alors TCL_ERROR est renvoyé et un message d'erreur est laissé dans le résultat de l'interpréteur interp. Tk_FreeBitmapFromObj, Tk_GetBitmap, Tk_AllocBitmapFromObj, Tk_NameOfBitmap, Tk_SizeOfBitmap, Tk_FreeBitmap - manipuler des bitmaps Tk

Fenêtre associée à la bitmap. Utilisée pour obtenir les informations sur le profondimètre.

DESCRIPTION

Ces procédures sont utilisées pour créer, manipuler et libérer des bitmaps dans Tk. Les bitmaps sont des représentations graphiques 1 bits utilisées pour remplir des zones d'une fenêtre, par exemple pour les motifs de tramage.

Une description de bitmap sous forme de chaîne peut être fournie à Tk_AllocBitmapFromObj ou Tk_GetBitmap de plusieurs façons. Si la chaîne commence par un caractère « @ », elle est traitée comme un nom de fichier. Tk lira le fichier et l'utilisera comme bitmap. Si la chaîne ne commence pas par « @ », elle est traitée comme un nom de bitmap pré-défini. Tk recherche alors une bitmap portant ce nom dans sa base de données interne.

La procédure Tk_DefineBitmap est utilisée pour enregistrer une bitmap avec un nom donné dans la base de données interne de Tk. Les données de la bitmap sont fournies sous forme de tableau d'entiers non signés (par exemple, provenant d'un fichier généré par le programme bitmap) et de dimensions.

Par exemple, supposons que vous ayez un fichier de bitmap nommé stip.bitmap qui a été créé par le programme bitmap et qui contient un motif de tramage. Le code suivant utilise Tk_DefineBitmap pour définir une nouvelle bitmap nommée foo :

Pixmap bitmap;
#include "stip.bitmap"
Tk_DefineBitmap(interp, "foo", stip_bits,
    stip_width, stip_height);
...
bitmap = Tk_GetBitmap(interp, tkwin, "foo");

Ce code provoque la lecture du fichier bitmap au moment de la compilation et intègre les informations de la bitmap dans l'image exécutable du programme. Le même fichier bitmap pourrait être lu au moment de l'exécution en utilisant Tk_GetBitmap :

Pixmap bitmap;
bitmap = Tk_GetBitmap(interp, tkwin, "@stip.bitmap");

La seconde forme est un peu plus flexible (le fichier pourrait être modifié après la compilation du programme, ou une chaîne différente pourrait être fournie pour lire un fichier différent), mais elle est un peu plus lente et nécessite que le fichier bitmap existe séparément du programme.

Tk maintient une base de données de toutes les bitmaps actuellement en cours d'utilisation. Dans la mesure du possible, il renverra une bitmap existante plutôt que d'en créer une nouvelle. Lorsqu'une bitmap n'est plus utilisée, Tk la libérera automatiquement. Cette approche peut réduire considérablement la charge du serveur, de sorte que Tk_AllocBitmapFromObj et Tk_GetBitmap devraient généralement être utilisés de préférence aux procédures Xlib comme XReadBitmapFile.

Les bitmaps renvoyées par Tk_AllocBitmapFromObj et Tk_GetBitmap sont partagées, les appelants ne doivent donc jamais les modifier. Si une bitmap doit être modifiée dynamiquement, elle doit être créée en appelant directement des procédures Xlib telles que XReadBitmapFile ou XCreatePixmap.

La procédure Tk_NameOfBitmap est à peu près l'inverse de Tk_GetBitmap. Étant donné un argument X Pixmap, elle renvoie la description textuelle qui a été passée à Tk_GetBitmap lors de la création de la bitmap. bitmap doit avoir été la valeur de retour d'un appel précédent à Tk_AllocBitmapFromObj ou Tk_GetBitmap.

Tk_SizeOfBitmap renvoie les dimensions de son argument bitmap dans les mots pointés par les arguments widthPtr et heightPtr. Comme avec Tk_NameOfBitmap, bitmap doit avoir été créé par Tk_AllocBitmapFromObj ou Tk_GetBitmap.

Lorsqu'une bitmap n'est plus nécessaire, Tk_FreeBitmapFromObj ou Tk_FreeBitmap doit être appelée pour la libérer. Pour Tk_FreeBitmapFromObj la bitmap à libérer est spécifiée avec les mêmes informations utilisées pour la créer ; pour Tk_FreeBitmap la bitmap à libérer est spécifiée avec son jeton Pixmap. Il doit y avoir exactement un appel à Tk_FreeBitmapFromObj ou Tk_FreeBitmap pour chaque appel à Tk_AllocBitmapFromObj ou Tk_GetBitmap.

BUGS

Lorsqu'il détermine si une bitmap existante peut être utilisée pour satisfaire une nouvelle demande, Tk_AllocBitmapFromObj et Tk_GetBitmap ne prennent en compte que la valeur immédiate de la description textuelle. Par exemple, lorsqu'un nom de fichier est passé à Tk_GetBitmap, Tk_GetBitmap supposera qu'il est sûr de réutiliser une bitmap existante créée à partir du même nom de fichier : il ne vérifiera pas si le fichier lui-même a changé, ou si le répertoire courant a changé, faisant ainsi pointer le nom vers un fichier différent.
