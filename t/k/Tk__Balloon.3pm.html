Paquet: perl-tk

Balloon(3) Documentation des contributeurs Perl Balloon(3)

NOM

Tk::Balloon - ballons d'aide.

SYNOPSIS

use Tk::Balloon;
...
$b = $top->Balloon(-statusbar => $status_bar_widget);
# Balloon normal :
$b->attach($widget,
           -balloonmsg => "Message d'aide",
           -statusmsg => "Message d'état");
# Balloon attaché à un widget de menu :
$b->attach($menu, -state => 'status',
                  -msg => ['premier élément de menu',
                           'deuxième élément de menu',
                           ...
                          ],
          );
# Balloon attaché à un élément individuel d'un widget canvas :
$b->attach($canvas, -balloonposition => 'mouse',
                    -msg => {'item1' => 'message1',
                             'tag2'  => 'message2',
                              ...
                            },
          );
# Balloon attaché à des éléments d'un widget listbox :
$b->attach($listbox, -balloonposition => 'mouse',
                     -msg => ['premier élément de liste',
                              'deuxième élément de liste',
                              ...
                             ],
          );

DESCRIPTION

Le Balloon fournit le cadre pour créer et attacher des ballons d'aide à divers widgets, ainsi que pour afficher un ballon lorsque la souris s'arrête sur le widget pendant une certaine durée.

Ballons et menus ou listes

Si le ballon est attaché à un widget menu ou listbox et que les arguments de message sont des références de tableau, alors chaque élément du tableau correspond à un message pour une entrée de menu ou un élément de liste. Le message du ballon sera affiché pour l'entrée sur laquelle la souris s'arrête. Sinon, le ballon est considéré comme étant attaché à l'ensemble du menu ou de la listbox. Vous pouvez avoir des messages d'état et des ballons séparés, comme pour les ballons normaux.

Ballons et canvas

Si le ballon est attaché à un widget canvas et que les arguments de message sont des références de hachage, alors chaque clé du hachage doit correspondre à un ID ou une étiquette d'un élément de canvas et la valeur associée correspond au message pour cet élément de canvas. Le message du ballon sera affiché pour l'élément courant (celui sous le curseur de la souris). Sinon, le ballon est considéré comme étant attaché à l'ensemble du canvas. Vous pouvez avoir des messages d'état et des ballons séparés, comme pour les ballons normaux.

Ballons et HLists

Si le ballon est attaché à un widget HList et que les arguments de message sont des références de hachage, alors chaque clé du hachage doit correspondre à un chemin HList et la valeur associée correspond au message pour cet élément HList. Le message du ballon sera affiché pour l'élément courant (celui sous le curseur de la souris). Sinon, le ballon est considéré comme étant attaché à l'ensemble du HList. Vous pouvez avoir des messages d'état et des ballons séparés, comme pour les ballons normaux.

Position du ballon

Par défaut, le ballon est affiché dans le coin inférieur droit du client. S'il devait dépasser la bordure inférieure de l'écran, il est déplacé dans le coin supérieur gauche. S'il devait dépasser la bordure droite, il est affiché dans le coin inférieur gauche du client. S'il devait dépasser les deux bordures, il est déplacé dans le coin supérieur gauche du client. Par conséquent, le petit pointeur pointe toujours vers le client auquel il est attaché.

Options

Balloon accepte toutes les options que le widget Frame accepte. De plus, les options suivantes sont également reconnues.

-initwait
Définit le temps d'attente sans activité avant d'afficher un ballon d'aide. Il est spécifié en millisecondes. La valeur par défaut est de 350 millisecondes. Ceci s'applique aussi bien au ballon affiché qu'au message d'état.
-state
Peut être l'une des valeurs 'balloon', 'status', 'both' ou 'none', indiquant si le ballon d'aide, le message d'état, les deux ou aucun ne doit être activé lorsque la souris s'arrête sur le widget. La valeur par défaut est 'both'.
-statusbar
Définit le widget à utiliser pour afficher le message d'état. Ce widget doit accepter l'option -text et est généralement un Label. Si le widget accepte l'option -textvariable et que cette option est définie, cette option sera utilisée à la place de -text.
-balloonposition
Peut être 'widget' ou 'mouse'. Contrôle la position où le ballon sera affiché. 'widget' fait afficher le ballon dans le coin inférieur droit du widget auquel il est attaché (valeur par défaut), et 'mouse' fait afficher le ballon sous et à droite de la position de la souris.
-postcommand
Cette option prend une référence à un CODE qui sera exécuté avant d'afficher le message du ballon et le message d'état, et doit retourner une valeur vraie ou fausse pour indiquer si vous souhaitez afficher le ballon d'aide ou non. Elle permet également de contrôler la position du ballon d'aide via la valeur de retour, qui doit être une valeur vraie ressemblant à X,Y (qui correspond à cette expression régulière : "/^(\d+),(\d+)$/"). Si la valeur de retour de postcommand correspond à ce modèle, ces coordonnées seront utilisées comme position pour afficher le ballon. Note : un nouveau ballon peut être affiché après l'intervalle -initwait, mais cela peut être contrôlé avec l'option -postcommand. Attention : cette sous-routine doit retourner rapidement, sinon la réponse du ballon d'aide apparaîtra lentement et consommera beaucoup de temps CPU (elle est exécutée chaque fois que la souris se déplace sur les widgets auxquels le ballon d'aide est attaché).
-cancelcommand
Cette option prend une référence à un CODE qui sera exécuté avant d'annuler le message du ballon et le message d'état, et doit retourner une valeur vraie ou fausse pour indiquer si vous souhaitez annuler le ballon d'aide ou non. Attention : cette sous-routine doit retourner rapidement, sinon la réponse du ballon d'aide apparaîtra lentement et consommera beaucoup de temps CPU (elle est exécutée chaque fois que la souris se déplace sur les widgets auxquels le ballon d'aide est attaché).
-motioncommand
Cette option prend une référence à un CODE qui sera exécuté pour tout événement de mouvement de souris et doit retourner une valeur vraie ou fausse pour indiquer si le ballon actuel doit être annulé (désactivé). S'il retourne vrai, le ballon sera certainement annulé ; s'il retourne faux, il peut être annulé selon les règles internes. Note : un nouveau ballon peut être affiché après l'intervalle -initwait, mais cela peut être contrôlé avec l'option -postcommand. Attention : la sous-routine doit être extrêmement rapide, sinon la réponse du ballon d'aide apparaîtra lentement et consommera beaucoup de temps CPU (elle est exécutée chaque fois que la souris se déplace sur les widgets auxquels le ballon d'aide est attaché).
-numscreens
Cette option accepte un entier de 1 ou plus. Cette option doit être utilisée pour éviter les ballons désalignés sur plusieurs écrans en mode écran unique (SLS). Cela ne fonctionne que dans la direction horizontale. Par exemple : si vous êtes en mode SLS avec deux écrans, définissez cette valeur sur 2. La valeur par défaut est 1.

MÉTHODES

Le widget Balloon ne prend en charge que trois méthodes non standard :

attach(widget, options)

Attache le widget spécifié par widget au système de ballons. Les options autorisées sont :

-statusmsg
L'argument est le message qui s'affiche dans le message d'état lorsque la souris s'arrête sur ce client. S'il n'est pas spécifié, mais que -msg est spécifié, le message affiché dans le message d'état est le même que l'argument pour -msg. Si vous lui donnez une référence à un scalaire, il sera déréférencé avant d'être affiché. Utile si vous utilisez -postcommand pour changer le message.
-balloonmsg
