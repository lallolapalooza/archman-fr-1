Tk_GetVisual(3) Procédures de la bibliothèque Tk Tk_GetVisual(3)

NOM

Tk_GetVisual - traduire une chaîne en visualisation

SYNTAXE

#include <tk.h>

Visual *
Tk_GetVisual(interp, tkwin, string, depthPtr, colormapPtr)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur à utiliser pour signaler les erreurs.
Tk_Window tkwin (entrée)
Jeton de la fenêtre dans laquelle la visualisation sera utilisée.
const char *string (entrée)
Chaîne qui identifie la visualisation souhaitée. Voir ci-dessous pour les formats valides.
int *depthPtr (sortie)
La profondeur de la visualisation retournée est stockée ici.
Colormap *colormapPtr (sortie)
Si non NULL, une palette de couleurs appropriée pour la visualisation est trouvée et son identifiant est stocké ici.

DESCRIPTION

Tk_GetVisual prend une description textuelle d'une visualisation et trouve une visualisation X appropriée à utiliser dans tkwin, s'il en existe une. Elle renvoie un pointeur vers la structure X Visual de la visualisation et stocke le nombre de bits par pixel pour celle-ci à *depthPtr. Si string est non reconnaissable ou si aucune visualisation appropriée n'a pu être trouvée, alors NULL est renvoyé et Tk_GetVisual laisse un message d'erreur dans le résultat de l'interpréteur interp. Si colormap n'est pas NULL, alors Tk_GetVisual localise également une palette de couleurs appropriée à utiliser avec la visualisation résultante et stocke son identifiant X à *colormapPtr.

L'argument string spécifie la visualisation souhaitée de l'une des manières suivantes :

classe profondeur
La chaîne consiste en un nom de classe suivi d'un entier de profondeur, avec n'importe quelle quantité d'espaces blancs (y compris aucun) entre les deux. classe sélectionne le type de visualisation souhaité et doit être l'un des suivants : directcolor, grayscale, greyscale, pseudocolor, staticcolor, staticgray, staticgrey, ou truecolor, ou une abréviation unique. profondeur spécifie combien de bits par pixel sont nécessaires pour la visualisation. Si possible, Tk_GetVisual renverra une visualisation avec cette profondeur ; s'il n'y a pas de visualisation de la profondeur désirée, alors Tk_GetVisual recherche d'abord une visualisation avec une profondeur plus grande, puis une avec une profondeur moindre.
défaut
Utilise la visualisation par défaut de l'écran de tkwin.
cheminNom
Utilise la visualisation de la fenêtre donnée par cheminNom. cheminNom doit être le nom d'une fenêtre sur le même écran que tkwin.
nombre
Utilise la visualisation dont l'identifiant X est nombre.
meilleur ?profondeur?
Choisit la “meilleure visualisation possible”, en utilisant les règles suivantes, par ordre de priorité décroissante :
(a)
une visualisation qui a exactement la profondeur désirée est la meilleure, suivie d'une visualisation avec une profondeur plus grande que celle demandée (mais le moins possible de surplus), suivie d'une visualisation avec une profondeur moindre que celle demandée (mais la profondeur la plus grande possible) ;
(b)
si aucune profondeur n'est spécifiée, alors la visualisation disponible la plus profonde est choisie ;
(c)
pseudocolor est meilleure que truecolor ou directcolor, qui sont meilleures que staticcolor, qui est meilleure que staticgray ou grayscale ;
(d)
la visualisation par défaut de l'écran est meilleure que toute autre visualisation.

CRÉDITS

L'idée de Tk_GetVisual, ainsi que sa première implémentation, provient de Paul Mackerras.
