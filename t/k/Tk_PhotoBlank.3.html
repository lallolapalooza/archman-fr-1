Tk_FindPhoto(3) Procédures de la bibliothèque Tk Tk_FindPhoto(3)

NOM

Tk_FindPhoto, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoGetImage, Tk_PhotoBlank, Tk_PhotoExpand, Tk_PhotoGetSize, Tk_PhotoSetSize - manipuler les données d'image stockées dans une image photo.

SYNTAXE

#include <tk.h>

Tk_PhotoHandle
Tk_FindPhoto(interp, imageName)

int
Tk_PhotoPutBlock(interp, handle, blockPtr, x, y, width, height,compRule)

int
Tk_PhotoPutZoomedBlock(interp, handle, blockPtr, x, y, width, height,zoomX, zoomY, subsampleX, subsampleY, compRule)

int
Tk_PhotoGetImage(handle, blockPtr)

void
Tk_PhotoBlank(handle)

int
Tk_PhotoExpand(interp, handle, width, height)

void
Tk_PhotoGetSize(handle, widthPtr, heightPtr)

int
Tk_PhotoSetSize(interp. handle, width, height)

ARGUMENTS

Tcl_Interp *interp (en entrée)
Interpréteur dans lequel l'image a été créée et dans lequel le rapport d'erreur doit être effectué.
const char *imageName (en entrée)
Nom de l'image photo.
Tk_PhotoHandle handle (en entrée)
Handle opaque identifiant l'image photo à affecter.
Tk_PhotoImageBlock *blockPtr (en entrée)
Spécifie l'adresse et la disposition de stockage des données d'image.
int x (en entrée)
Spécifie la coordonnée X où le coin supérieur gauche du bloc doit être placé dans l'image.
int y (en entrée)
Spécifie la coordonnée Y où le coin supérieur gauche du bloc doit être placé dans l'image.
int width (en entrée)
Spécifie la largeur de la zone d'image à affecter (pour Tk_PhotoPutBlock) ou la largeur d'image souhaitée (pour Tk_PhotoExpand et Tk_PhotoSetSize).
int compRule (en entrée)
Spécifie la règle de composition utilisée lors de la combinaison de pixels transparents dans un bloc de données avec une image photo. Doit être l'une des valeurs TK_PHOTO_COMPOSITE_OVERLAY (qui place le bloc de données par-dessus l'image photo existante, le contenu précédent étant visible dans les bits transparents) ou TK_PHOTO_COMPOSITE_SET (qui ignore complètement le contenu existant de l'image photo dans le rectangle couvert par le bloc de données).
int height (en entrée)
Spécifie la hauteur de la zone d'image à affecter (pour Tk_PhotoPutBlock) ou la hauteur d'image souhaitée (pour Tk_PhotoExpand et Tk_PhotoSetSize).
int *widthPtr (en sortie)
Pointeur vers l'emplacement où stocker la largeur de l'image.
int *heightPtr (en sortie)
Pointeur vers l'emplacement où stocker la hauteur de l'image.
int subsampleX (en entrée)
Spécifie le facteur de sous-échantillonnage dans la direction X pour les données d'image d'entrée.
int subsampleY (en entrée)
Spécifie le facteur de sous-échantillonnage dans la direction Y pour les données d'image d'entrée.
int zoomX (en entrée)
Spécifie le facteur de zoom à appliquer dans la direction X aux pixels écrits dans l'image photo.
int zoomY (en entrée)
Spécifie le facteur de zoom à appliquer dans la direction Y aux pixels écrits dans l'image photo.

DESCRIPTION

Tk_FindPhoto renvoie un handle opaque qui est utilisé pour identifier une image photo particulière aux autres procédures. Le paramètre est le nom de l'image, c'est-à-dire le nom spécifié à la commande image create photo, ou attribué par cette commande si aucun nom n'était spécifié. Si imageName n'existe pas ou n'est pas une image photo, Tk_FindPhoto renvoie NULL.

Tk_PhotoPutBlock est utilisée pour fournir des blocs de données d'image à afficher. L'appel affecte une zone de l'image de taille width x height pixels, avec son coin supérieur gauche aux coordonnées (x,y). Tous les paramètres width, height, x, et y doivent être non négatifs. Si une partie de cette zone se trouve en dehors des limites actuelles de l'image, l'image sera agrandie pour inclure la zone, sauf si l'utilisateur a spécifié une taille d'image explicite avec les options de configuration du widget -width et/ou -height (voir photo(n)) ; dans ce cas, la zone est silencieusement découpée aux limites de l'image.

Le paramètre block est un pointeur vers une structure Tk_PhotoImageBlock, définie comme suit :

typedef struct {
    unsigned char *pixelPtr;
    int width;
    int height;
    int pitch;
    int pixelSize;
    int offset[4];
} Tk_PhotoImageBlock;
Le champ pixelPtr pointe vers le premier pixel, c'est-à-dire le pixel en haut à gauche du bloc. Les champs width et height spécifient les dimensions du bloc de pixels. Le champ pixelSize spécifie la différence d'adresse entre deux pixels horizontalement adjacents. Il doit être de 4 pour les données d'image RVB et de 2 pour les données en niveaux de gris. D'autres valeurs sont possibles, si les décalages dans le tableau offset sont ajustés en conséquence (par exemple, pour les données rouges, vertes et bleues stockées dans des plans différents). Cependant, l'utilisation d'une telle disposition est fortement déconseillée. En raison d'un bug, cela pourrait ne pas fonctionner correctement si un canal alpha est fourni. (voir la section BUGS ci-dessous). Le champ pitch spécifie la différence d'adresse entre deux pixels verticalement adjacents. Le tableau offset contient les décalages depuis l'adresse d'un pixel vers les adresses des octets contenant les composantes rouge, verte, bleue et alpha (transparence). Si les décalages pour le rouge, le vert et le bleu sont égaux, l'image est interprétée comme étant en niveaux de gris. S'ils diffèrent, des données RVB sont supposées. Normalement, les décalages seront de 0, 1, 2, 3 pour les données RVB et de 0, 0, 0, 1 pour les niveaux de gris. Il est possible de fournir des données d'image sans canal alpha en définissant le décalage alpha sur une valeur négative et en ajustant le champ pixelSize en conséquence. Cependant, cette utilisation est déconseillée (voir la section BUGS ci-dessous).

Le paramètre compRule de Tk_PhotoPutBlock spécifie une règle de composition indiquant quoi faire des pixels transparents. La valeur TK_PHOTO_COMPOSITE_OVERLAY indique que le contenu précédent de l'image photo doit être visible, et la valeur TK_PHOTO_COMPOSITE_SET indique que le contenu précédent de l'image photo doit être complètement ignoré, et que les valeurs du bloc doivent être copiées directement. Le comportement dans Tk8.3 et versions antérieures était équivalent à avoir TK_PHOTO_COMPOSITE_OVERLAY comme règle de composition.

Les valeurs données pour les paramètres width et height de Tk_PhotoPutBlock ne correspondent pas nécessairement aux valeurs spécifiées dans block. Si elles sont plus petites, Tk_PhotoPutBlock extrait un sous-bloc des données d'image fournies. Si elles sont plus grandes, les données fournies sont répliquées (de manière répétitive) pour remplir la zone spécifiée. Ces règles s'appliquent indépendamment dans les directions horizontale et verticale.

Tk_PhotoPutBlock renvoie normalement TCL_OK, bien que si elle ne parvient pas à allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est renvoyé à la place et, si l'argument interp est non NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoPutZoomedBlock fonctionne comme Tk_PhotoPutBlock, sauf que l'image peut être réduite ou agrandie pour l'affichage. Les paramètres subsampleX et subsampleY permettent de réduire la taille de l'image par sous-échantillonnage. Tk_PhotoPutZoomedBlock n'utilisera que les pixels de l'image d'entrée dont les coordonnées X sont des multiples de subsampleX, et dont les coordonnées Y sont des multiples de subsampleY. Par exemple, une image de 512x512 pixels peut être réduite à 256x256 en définissant subsampleX et subsampleY à 2.

Les paramètres zoomX et zoomY permettent d'agrandir l'image par réplication de pixels. Chaque pixel de l'image d'entrée (éventuellement sous-échantillonnée) sera écrit dans un bloc de zoomX pixels de large et zoomY pixels de haut de l'image affichée. Le sous-échantillonnage et le zoom peuvent être utilisés ensemble pour des effets spéciaux.

Tk_PhotoGetImage peut être utilisée pour récupérer des données d'image d'une image photo. Tk_PhotoGetImage remplit la structure pointée par le paramètre blockPtr avec des valeurs décrivant l'adresse et la disposition des données d'image que l'image photo a stockées en interne. Les valeurs sont valides jusqu'à ce que l'image soit détruite ou que sa taille soit modifiée.

Il est possible de modifier une image en écrivant directement dans les données auxquelles pointe le champ pixelPtr. La taille de l'image ne peut cependant pas être modifiée de cette manière. De plus, les modifications apportées en écrivant directement dans pixelPtr ne seront pas immédiatement visibles, mais seulement après un appel à Tk_ImageChanged ou après un événement qui provoque le redessin des widgets intéressés. NAME

Tk_PhotoBlank, Tk_PhotoGetImage, Tk_PhotoGetSize, Tk_PhotoPutBlock, Tk_PhotoSetSize, Tk_PhotoExpand, Tk_PhotoPutZoomedBlock — manipuler des données d'image photo

SYNOPSIS

#include <tk.h>

    void
    Tk_PhotoBlank(tkphoto);
    int
    Tk_PhotoGetImage(tkphoto, interp);
    int
    Tk_PhotoGetSize(tkphoto, widthPtr, heightPtr);
    int
    Tk_PhotoPutBlock(tkphoto, blockPtr, offsetx, offsety, width, height, pixelSize);
    int
    Tk_PhotoPutZoomedBlock(tkphoto, blockPtr, offsetx, offsety, width, height,
        zoomMultiply, zoomDivide, pixelSize);
    int
    Tk_PhotoExpand(tkphoto, width, height);
    int
    Tk_PhotoSetSize(tkphoto, width, height);

ARGUMENTS

Tk_Photo_Image *tkphoto
Identifiant de l'image photo à manipuler.
Tcl_Interp *interp
Interpréteur Tcl à utiliser pour les rapports d'erreurs.
int *widthPtr
Pointeur vers un entier dans lequel la largeur de l'image sera écrite.
int *heightPtr
Pointeur vers un entier dans lequel la hauteur de l'image sera écrite.
unsigned char *blockPtr
Pointeur vers le début des données de pixels dans le bloc d'image.
int offsetx
Décalage horizontal (en pixels) à l'intérieur de l'image photo où le bloc sera écrit.
int offsety
Décalage vertical (en pixels) à l'intérieur de l'image photo où le bloc sera écrit.
int width
Largeur (en pixels) des données dans le bloc d'image.
int height
Hauteur (en pixels) des données dans le bloc d'image.
int pixelSize
Nombre d'octets par pixel dans les données du bloc. Par exemple, 3 pour RGB, 4 pour RGBA.
int zoomMultiply
Facteur multiplicateur pour le zoom.
int zoomDivide
Facteur diviseur pour le zoom.

DESCRIPTION

Les procédures décrites ici sont utilisées pour créer et manipuler des images de type photo Tk. Ces images sont utilisées par le widget image de Tk. Le type photo est une image bitmap à mémoire tampon, où les pixels sont stockés dans une mémoire tampon gérée par Tk. Les données d'image peuvent être fournies sous forme de blocs individuels. Tk maintient une image bitmap interne et met à jour les parties nécessaires en fonction des blocs fournis. Les coordonnées des pixels sont (0,0) dans le coin supérieur gauche. Les valeurs de couleur sont des entiers non signés compris entre 0 et 255. Les images photo sont initialement vides.

Tk_PhotoPutBlock et Tk_PhotoPutZoomedBlock écrivent une région rectangulaire de données de pixels dans l'image photo. Les données sont spécifiées par blockPtr, width, height et pixelSize. La région sera écrite dans l'image photo à partir des coordonnées (offsetx,offsety). Les dimensions de l'image photo seront automatiquement étendues si nécessaire pour s'adapter aux pixels écrits. Si le bloc contient des données alpha (transparence), elles seront utilisées pour composer l'image. Si une partie de l'image photo est au-delà de ses dimensions actuelles, elle sera créée avec des pixels transparents par défaut. Si vous fournissez des données de couleur en dehors de la plage spécifiée par pixelSize, le comportement n'est pas défini. Les valeurs de zoomMultiply et zoomDivide dans Tk_PhotoPutZoomedBlock sont utilisées pour mettre à l'échelle le bloc avant de l'écrire dans l'image photo. Les valeurs de zoomMultiply et zoomDivide doivent être positives. Par exemple, pour un zoom 2x, utilisez 2 et 1. Pour un zoom 1.5x, utilisez 3 et 2. Si zoomMultiply est égal à zoomDivide, il s'agit d'une écriture non zoomée.

Pour écrire des modifications dans une copie des données d'image et les réécrire avec Tk_PhotoPutBlock ou Tk_PhotoPutZoomedBlock.

Tk_PhotoGetImage renvoie 1 pour la compatibilité avec la procédure correspondante de l'ancien widget photo.

Tk_PhotoBlank efface toute la zone de l'image photo. Les zones vides d'une image photo sont transparentes.

Tk_PhotoExpand demande que l'image du widget soit étendue pour avoir au moins une taille de width x height pixels. La largeur et/ou la hauteur ne sont pas modifiées si l'utilisateur a spécifié une largeur ou une hauteur d'image explicite avec les options de configuration -width et/ou -height, respectivement. Si les données de l'image sont fournies en plusieurs petits blocs, il est plus efficace d'utiliser Tk_PhotoExpand ou Tk_PhotoSetSize au début plutôt que de laisser l'image s'étendre par petits incréments au fur et à mesure que les blocs d'image sont fournis.

Tk_PhotoExpand renvoie normalement TCL_OK, bien que s'il ne peut pas allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est renvoyé à la place et, si l'argument interp n'est pas NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoSetSize spécifie la taille de l'image, comme si l'utilisateur avait spécifié les valeurs width et height données aux options de configuration -width et -height. Une valeur de zéro pour width ou height ne modifie pas la largeur ou la hauteur de l'image, mais permet de modifier la largeur ou la hauteur par des appels ultérieurs à Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock ou Tk_PhotoExpand.

Tk_PhotoSetSize renvoie normalement TCL_OK, bien que s'il ne peut pas allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est renvoyé à la place et, si l'argument interp n'est pas NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoGetSize renvoie les dimensions de l'image dans *widthPtr et *heightPtr.

PORTABILITY

Dans Tk 8.3 et versions antérieures, Tk_PhotoPutBlock et Tk_PhotoPutZoomedBlock avaient des signatures différentes. Si vous souhaitez compiler du code utilisant l'ancienne interface contre 8.4 sans mettre à jour votre code, compilez-le avec le drapeau -DUSE_COMPOSITELESS_PHOTO_PUT_BLOCK. Le code lié à l'aide de Stubs contre des versions antérieures de Tk continuera de fonctionner.

Dans Tk 8.4, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoExpand et Tk_PhotoSetSize ne prenaient pas d'argument interp ni ne renvoyaient de code de résultat. Si une mémoire insuffisante était disponible pour une image, Tk paniquait. Ce comportement est toujours pris en charge si vous compilez votre extension avec le drapeau supplémentaire -DUSE_PANIC_ON_PHOTO_ALLOC_FAILURE. Le code lié à l'aide de Stubs contre des versions antérieures de Tk continuera de fonctionner.

BUGS

La structure Tk_PhotoImageBlock utilisée pour fournir des données d'image à Tk_PhotoPutBlock promet une grande flexibilité dans la disposition des données (par exemple, des plans séparés pour les canaux rouge, vert, bleu et alpha). Malheureusement, l'implémentation ne tient pas cette promesse. Le problème est que le champ pixelSize est utilisé (incorrectement) pour déterminer si l'image a un canal alpha. Actuellement, si le décalage du canal alpha est supérieur ou égal à pixelSize, tk_PhotoPutblock suppose qu'aucune donnée alpha n'est présente et rend l'image entièrement opaque. Cela signifie que pour les dispositions où les canaux sont séparés (ou toute autre disposition exotique où pixelSize doit être inférieur au décalage alpha), le canal alpha ne sera pas lu correctement. Afin d'être prudent si ce problème est corrigé dans une future version, il est fortement recommandé de toujours fournir des données alpha - même si l'image n'a pas de transparence - et d'utiliser uniquement la disposition "standard" avec un pixelSize de 2 pour les données de niveaux de gris et de 4 pour les données RVB avec des offsets de 0, 0, 0, 1 ou 0, 1, 2, 3 respectivement.
