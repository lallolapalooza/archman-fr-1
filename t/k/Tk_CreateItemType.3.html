Tk_CreateItemType(3) Procédures de la bibliothèque Tk Tk_CreateItemType(3)

NOM

Tk_CreateItemType, Tk_GetItemTypes - définir un nouveau type d'élément de canevas

SYNTAXE

#include <tk.h>

Tk_CreateItemType(typePtr)

Tk_ItemType *
Tk_GetItemTypes()

ARGUMENTS

Tk_ItemType *typePtr (entree)
Structure définissant le nouveau type d'élément de canevas.

INTRODUCTION

Tk_CreateItemType est appelée pour définir un nouveau type d'élément de canevas décrit par l'argument typePtr. Un type d'élément correspond à une valeur particulière de l'argument type de la commande de widget create pour les canevas, et le code qui implémente un type d'élément de canevas est appelé un gestionnaire de type. Tk définit plusieurs types d'éléments intégrés, tels que rectangle, text et image, mais Tk_CreateItemType permet de définir des types d'éléments supplémentaires. Une fois que Tk_CreateItemType est retournée, le nouveau type d'élément peut être utilisé dans des widgets de canevas nouveaux ou existants, tout comme les types d'éléments intégrés.

Tk_GetItemTypes renvoie un pointeur vers le premier élément de la liste de tous les types d'éléments actuellement définis pour les canevas. Les entrées de la liste sont liées entre elles par leurs champs nextPtr, la fin de la liste étant marquée par un nextPtr NULL.

Il peut vous être plus facile de comprendre le reste de cette page de manuel en consultant le code d'un type d'élément de canevas existant tel que bitmap (dans le fichier tkCanvBmap.c) ou text (tkCanvText.c). La façon la plus simple de créer un nouveau gestionnaire de type est de copier le code d'un type existant et de le modifier pour le nouveau type.

Tk fournit un certain nombre de procédures utilitaires pour l'utilisation des gestionnaires de types de canevas, telles que Tk_CanvasCoords et Tk_CanvasPsColor ; celles-ci sont décrites dans des entrées de manuel distinctes.

STRUCTURES DE DONNÉES

Un gestionnaire de type consiste en une collection de procédures qui fournissent un ensemble standard d'opérations sur les éléments de ce type. Le gestionnaire de type traite trois types de structures de données. La première structure de données est un Tk_ItemType ; elle contient des informations telles que le nom du type et des pointeurs vers les procédures standard implémentées par le gestionnaire de type :

typedef struct Tk_ItemType {
    const char *name;
    int itemSize;
    Tk_ItemCreateProc *createProc;
    const Tk_ConfigSpec *configSpecs;
    Tk_ItemConfigureProc *configProc;
    Tk_ItemCoordProc *coordProc;
    Tk_ItemDeleteProc *deleteProc;
    Tk_ItemDisplayProc *displayProc;
    int alwaysRedraw;
    Tk_ItemPointProc *pointProc;
    Tk_ItemAreaProc *areaProc;
    Tk_ItemPostscriptProc *postscriptProc;
    Tk_ItemScaleProc *scaleProc;
    Tk_ItemTranslateProc *translateProc;
    Tk_ItemIndexProc *indexProc;
    Tk_ItemCursorProc *icursorProc;
    Tk_ItemSelectionProc *selectionProc;
    Tk_ItemInsertProc *insertProc;
    Tk_ItemDCharsProc *dCharsProc;
    Tk_ItemType *nextPtr;
} Tk_ItemType;

Les champs d'une structure Tk_ItemType sont décrits plus en détail plus loin dans cette page de manuel. Lorsque Tk_CreateItemType est appelée, son argument typePtr doit pointer vers une structure avec tous les champs initialisés à l'exception de nextPtr, que Tk utilise pour lier tous les types ensemble en une liste. La structure doit être dans une mémoire permanente (soit allouée statiquement, soit allouée dynamiquement mais jamais libérée) ; Tk conserve un pointeur vers cette structure.

La deuxième structure de données manipulée par un gestionnaire de type est un enregistrement d'élément. Pour chaque élément d'un canevas, il existe un enregistrement d'élément. Tous les éléments d'un type donné ont généralement des enregistrements d'éléments de même structure, mais des types différents ont généralement des formats différents pour leurs enregistrements d'éléments. La première partie de chaque enregistrement d'élément est un en-tête avec une structure standard définie par Tk via le type Tk_Item ; le reste de l'enregistrement d'élément est défini par le gestionnaire de type. Un gestionnaire de type doit définir ses enregistrements d'éléments avec un Tk_Item comme premier champ. Par exemple, l'enregistrement d'élément pour les éléments bitmap est défini comme suit :

typedef struct BitmapItem {
    Tk_Item header;
    double x, y;
    Tk_Anchor anchor;
    Pixmap bitmap;
    XColor *fgColor;
    XColor *bgColor;
    GC gc;
} BitmapItem;

La sous-structure header contient des informations utilisées par Tk pour gérer l'élément, telles que son identifiant, ses balises, son type et sa boîte englobante. Les champs commençant par x appartiennent au gestionnaire de type : Tk ne les lira ni ne les écrira jamais. Le gestionnaire de type ne devrait pas avoir besoin de lire ni d'écrire dans aucun des champs de l'en-tête, à l'exception de quatre champs nommés x1, y1, x2 et y2. Ces champs donnent une boîte englobante pour les éléments en utilisant les coordonnées entières du canevas : l'élément ne doit couvrir aucun pixel dont la coordonnée x est inférieure à x1 ou dont la coordonnée y est inférieure à y1, ni aucun pixel dont la coordonnée x est supérieure ou égale à x2 ou dont la coordonnée y est supérieure ou égale à y2. Il appartient au gestionnaire de type de maintenir la boîte englobante à jour lorsque l'élément est déplacé et reconfiguré.

Chaque fois que Tk appelle une procédure d'un gestionnaire de type, elle lui passe un pointeur vers un enregistrement d'élément. L'argument est toujours passé sous forme de pointeur vers un Tk_Item ; le gestionnaire de type le convertit généralement en pointeur vers son propre type spécifique, comme BitmapItem.

La troisième structure de données utilisée par les gestionnaires de type a le type Tk_Canvas ; elle sert de handle opaque pour le widget canevas dans son ensemble. Les gestionnaires de type n'ont pas besoin de connaître le contenu de cette structure. Un handle Tk_Canvas est généralement passé aux procédures d'un gestionnaire de type, et le gestionnaire de type peut passer le handle à des procédures de la bibliothèque telles que Tk_CanvasTkwin pour récupérer des informations sur le canevas.

CHAMPS TK_ITEMTYPE

NOM

Cette section et celles qui suivent décrivent en détail chacun des champs d'une structure Tk_ItemType. Le champ name fournit un nom sous forme de chaîne de caractères pour le type d'élément. Une fois que Tk_CreateImageType est retournée, ce nom peut être utilisé dans les commandes de widget create pour créer des éléments du nouveau type. Si un type d'élément portant ce nom existait déjà, le nouveau type d'élément remplace l'ancien.

INDICATEURS (DANS ALWAYSREDRAW)

Le champ typePtr->alwaysRedraw (nommé ainsi pour des raisons historiques) contient une collection de bits indicateurs qui modifient la façon dont le noyau du canevas interagit avec l'élément. Les bits suivants sont définis :

1
Indique que l'élément doit toujours être redessiné lorsqu'une partie du canevas est redessinée, plutôt que seulement lorsque la boîte englobante de l'élément chevauche la zone en cours de redessin. Ceci est utilisé pour les éléments de fenêtre, par exemple, qui doivent désactiver les sous-fenêtres qui ne sont pas à l'écran.
TK_CONFIG_OBJS
Indique que les opérations qui prendraient autrement une chaîne (ou un tableau de chaînes) prennent en fait une référence Tcl_Obj (ou un tableau de telles références). Les opérations auxquelles cela s'applique sont configProc, coordProc, createProc, indexProc et insertProc.
TK_MOVABLE_POINTS
Indique que l'élément prend en charge les procédures dCharsProc, indexProc et insertProc avec la même sémantique que les types ligne et polygone intégrés de Tk, et que par conséquent des points coordonnés individuels peuvent être déplacés. Ne doit pas être défini si l'une des méthodes ci-dessus est NULL.

ITEMSIZE

typePtr->itemSize donne la taille en octets des enregistrements d'éléments de ce type, y compris l'en-tête Tk_Item. Tk utilise cette taille pour allouer de l'espace mémoire pour les éléments du type. Tous les enregistrements d'éléments d'un type donné doivent avoir la même taille. Si des champs de longueur variable sont nécessaires pour un élément (tel qu'une liste de points pour un polygone), le gestionnaire de type peut allouer un objet séparé de longueur variable et y conserver un pointeur dans l'enregistrement d'élément.

CREATEPROC

CONFIGSPECS

Chaque gestionnaire de type doit fournir une table standard décrivant ses options de configuration, dans un format approprié pour être utilisé avec Tk_ConfigureWidget. Cette table est généralement utilisée par typePtr->createProc et typePtr->configProc, mais Tk l'utilise également directement pour récupérer des informations sur les options dans les commandes de widget itemcget et itemconfigure. typePtr->configSpecs doit pointer vers la table de configuration de ce type. Remarque : Tk fournit un type d'option personnalisé tk_CanvasTagsOption pour implémenter l'option -tags ; consultez un gestionnaire de type existant pour un exemple d'utilisation dans configSpecs.

CONFIGPROC

typePtr->configProc est appelée par Tk lorsque la commande de widget itemconfigure est invoquée pour modifier les options de configuration d'un élément de canevas. Cette procédure doit correspondre au prototype suivant :

typedef int Tk_ItemConfigureProc(
        Tcl_Interp *interp,
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int objc,
        Tcl_Obj *const objv[],
        int flags);

L'argument interp identifie l'interpréteur dans lequel la commande de widget a été invoquée, canvas est un pointeur vers le widget canevas, et itemPtr est un pointeur vers l'élément en cours de configuration. objc et objv contiennent les options de configuration. Remarque : si TK_CONFIG_OBJS n'est pas défini dans le champ typePtr->alwaysRedraw, objv contiendra en fait un pointeur vers un tableau de chaînes constantes. Par exemple, si la commande de widget suivante est invoquée :

.c itemconfigure 2 -fill red -outline black

objc sera 4 et objv contiendra les objets chaîne de -fill à black. objc sera toujours une valeur paire. L'argument flags contient les drapeaux à passer à Tk_ConfigureWidget ; actuellement, cette valeur est toujours TK_CONFIG_ARGV_ONLY lorsque Tk appelle typePtr->configProc, mais la procédure du gestionnaire de type createProc appelle généralement configProc avec différentes valeurs de drapeaux.

typePtr->configProc renvoie un code de complétion Tcl standard et laisse un message d'erreur dans le résultat de l'interpréteur en cas d'erreur. Elle doit mettre à jour le cadre de délimitation de l'élément pour refléter les nouvelles options de configuration.

COORDPROC

typePtr->coordProc est appelée par Tk pour implémenter la commande de widget coords pour un élément. Elle doit correspondre au prototype suivant :

typedef int Tk_ItemCoordProc(
        Tcl_Interp *interp,
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int objc,
        Tcl_Obj *const objv[]);

Les arguments interp, canvas et itemPtr ont la signification standard, et objc et objv décrivent les arguments de coordonnées. Remarque : si TK_CONFIG_OBJS n'est pas défini dans le champ typePtr->alwaysRedraw, objv contiendra en fait un pointeur vers un tableau de chaînes constantes. Par exemple, si la commande de widget suivante est invoquée :

.c coords 2 30 90

objc sera 2 et objv contiendra les objets entier 30 et 90.

La procédure coordProc doit traiter les nouvelles coordonnées, mettre à jour l'élément en conséquence (par exemple, elle doit réinitialiser le cadre de délimitation dans l'en-tête de l'élément) et renvoyer un code de complétion Tcl standard. En cas d'erreur, coordProc doit laisser un message d'erreur dans le résultat de l'interpréteur.

DELETEPROC

typePtr->deleteProc est appelée par Tk pour supprimer un élément et libérer les ressources qui lui sont allouées. Elle doit correspondre au prototype suivant :

typedef void Tk_ItemDeleteProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        Display *display);

Les arguments canvas et itemPtr ont la signification standard. display identifie l'écran contenant le canevas. deleteProc doit libérer toutes les ressources allouées à l'élément, permettant à Tk de libérer le enregistrement de l'élément. deleteProc ne doit pas libérer directement le enregistrement de l'élément ; cela sera fait par Tk lorsque deleteProc retournera.

DISPLAYPROC

typePtr->displayProc est appelée par Tk pour redessiner un élément à l'écran. Elle doit correspondre au prototype suivant :

typedef void Tk_ItemDisplayProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        Display *display,
        Drawable dst,
        int x,
        int y,
        int width,
        int height);

Les arguments canvas et itemPtr ont la signification standard. display identifie l'écran contenant le canevas, et dst spécifie un drawable sur lequel l'élément doit être rendu ; typiquement, il s'agit d'une pixmap hors écran que Tk copie dans la fenêtre du canevas une fois que tous les éléments pertinents ont été dessinés. x, y, width et height spécifient une région rectangulaire en coordonnées de canevas, qui est la zone à redessiner ; seule la partie qui chevauche cette zone doit être redessinée. Tk n'appellera pas displayProc à moins que le cadre de l'élément ne chevauche la zone de redessin, mais le gestionnaire de type peut souhaiter utiliser la zone de redessin pour optimiser le redessin de l'élément.

Étant donné qu'il y a un défilement et l'utilisation de pixmaps hors écran pour le redessin en double tampon, les coordonnées de l'élément dans dst ne seront pas nécessairement les mêmes que celles de la fenêtre du canevas. displayProc doit appeler Tk_CanvasDrawableCoords pour transformer les coordonnées du canevas en celles de dst.

Normalement, le displayProc d'un élément n'est appelé que si l'élément chevauche la zone affichée. Cependant, si le bit zéro de typePtr->alwaysRedraw est 1 (c'est-à-dire typePtr->alwaysRedraw & 1 == 1), alors displayProc est appelé pendant chaque opération de redessin, même si l'élément ne chevauche pas la zone de redessin ; ceci est utile dans des cas comme les éléments de fenêtre, où la sous-fenêtre doit être démappée lorsqu'elle est hors écran.

POINTPROC

typePtr->pointProc est appelée par Tk pour déterminer la proximité d'un point donné avec un élément de canevas. Tk utilise cette procédure pour des tâches telles que trouver l'élément sous la souris ou localiser l'élément le plus proche d'un point donné. La procédure doit correspondre au prototype suivant :

typedef double Tk_ItemPointProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        double *pointPtr);

Les arguments canvas et itemPtr ont la signification standard. pointPtr pointe vers un tableau de deux nombres représentant les coordonnées x et y d'un point. pointProc doit renvoyer une valeur réelle représentant la distance du point à l'élément, ou 0 si le point est à l'intérieur de l'élément.

AREAPROC

typePtr->areaProc est appelée par Tk pour déterminer la relation entre un élément et une zone rectangulaire. Elle doit correspondre au prototype suivant :

typedef int Tk_ItemAreaProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        double *rectPtr);

Les arguments canvas et itemPtr ont la signification standard. rectPtr pointe vers un tableau de quatre nombres réels ; les deux premiers donnent les coordonnées x et y du coin supérieur gauche d'un rectangle, et les deux derniers donnent les coordonnées x et y du coin inférieur droit. areaProc doit renvoyer -1 si l'élément est complètement à l'extérieur de la zone donnée, 0 s'il est partiellement à l'intérieur et partiellement à l'extérieur, et 1 s'il est complètement à l'intérieur de la zone.

POSTSCRIPTPROC

typePtr->postscriptProc est appelée par Tk pour générer du postscript d'un élément lors de la commande de widget postscript. Si le gestionnaire de type ne peut pas générer de postscript, typePtr->postscriptProc doit être nul. La procédure doit correspondre au prototype suivant :

typedef int Tk_ItemPostscriptProc(
        Tcl_Interp *interp,
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int prepass);

Les arguments interp, canvas et itemPtr ont la signification standard. prepass est un argument qui doit être passé à Tk_Postscript.

standards; prepass sera décrit ci-dessous. Si postscriptProc se termine avec succès, il doit ajouter le Postscript pour l'élément aux informations dans le résultat de l'interpréteur (par exemple, en appelant Tcl_AppendResult, pas Tcl_SetResult) et renvoyer TCL_OK. Si une erreur se produit, postscriptProc doit effacer le résultat et remplacer son contenu par un message d'erreur ; il doit ensuite renvoyer TCL_ERROR.

Tk fournit une collection de procédures utilitaires pour simplifier postscriptProc. Par exemple, Tk_CanvasPsColor générera du Postscript pour définir la couleur actuelle à une couleur Tk donnée et Tk_CanvasPsFont configurera les informations de police. Lors de la génération de Postscript, le gestionnaire de type est libre de modifier l'état graphique de l'interpréteur Postscript, car Tk place les commandes gsave et grestore autour du Postscript de l'élément. Le gestionnaire de type peut utiliser directement les coordonnées x du canevas dans son Postscript, mais il doit appeler Tk_CanvasPsY pour convertir les coordonnées y de l'espace du canevas (où l'origine est en haut à gauche) vers l'espace Postscript (où l'origine est en bas à gauche).

Afin de générer du Postscript conforme aux conventions de structuration de documents Adobe, Tk génère en fait du Postscript en deux passes. Il appelle postscriptProc de chaque élément à chaque passe. Le seul but de la première passe est de collecter des informations de police (ce qui est fait par Tk_CanvasPsFont) ; le Postscript réel est supprimé. Tk définit l'argument prepass de postscriptProc à 1 pendant la première passe ; le gestionnaire de type peut utiliser prepass pour ignorer toute génération de Postscript, à l'exception des appels à Tk_CanvasPsFont. Pendant la seconde passe, prepass sera 0, donc le gestionnaire de type doit générer du Postscript complet.

SCALEPROC

typePtr->scaleProc est appelé par Tk pour redimensionner un élément du canevas lors de la commande de widget scale. La procédure doit correspondre au prototype suivant :

typedef void Tk_ItemScaleProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        double originX,
        double originY,
        double scaleX,
        double scaleY);

Les arguments canvas et itemPtr ont la signification habituelle. originX et originY spécifient une origine par rapport à laquelle l'élément doit être redimensionné, et scaleX et scaleY donnent les facteurs d'échelle x et y. L'élément doit ajuster ses coordonnées afin qu'un point de l'élément qui avait auparavant les coordonnées x et y ait de nouvelles coordonnées x′ et y′, où

x′ = originX + scaleX × (x − originX)
y′ = originY + scaleY × (y − originY)

scaleProc doit également mettre à jour la boîte englobante dans l'en-tête de l'élément.

TRANSLATEPROC

typePtr->translateProc est appelé par Tk pour translater un élément du canevas lors de la commande de widget move. La procédure doit correspondre au prototype suivant :

typedef void Tk_ItemTranslateProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        double deltaX,
        double deltaY);

Les arguments canvas et itemPtr ont la signification habituelle, et deltaX et deltaY donnent les montants à ajouter à chaque coordonnée x et y dans l'élément. Le gestionnaire de type doit ajuster les coordonnées de l'élément et mettre à jour la boîte englobante dans l'en-tête de l'élément.

INDEXPROC

typePtr->indexProc est appelé par Tk pour traduire une spécification d'indice textuelle en un indice numérique, par exemple lors de la commande de widget index. Il n'est pertinent que pour les types d'éléments qui prennent en charge du texte ou des coordonnées indexables ; typePtr->indexProc peut être spécifié comme NULL pour les types d'éléments non textuels s'ils ne prennent pas en charge l'adressage de coordonnées détaillé. La procédure doit correspondre au prototype suivant :

typedef int Tk_ItemIndexProc(
        Tcl_Interp *interp,
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        Tcl_Obj *indexObj,
        int *indexPtr);

Les arguments interp, canvas et itemPtr ont tous la signification habituelle. indexObj contient une description textuelle d'un indice, et indexPtr pointe vers une valeur entière qui doit être remplie avec un indice numérique. Notez que si TK_CONFIG_OBJS n'est pas défini dans le champ typePtr->alwaysRedraw, le paramètre indexObj contiendra en fait un pointeur vers une chaîne de caractères constante. Il appartient au gestionnaire de type de décider quelles formes d'indice sont prises en charge (par exemple, nombres, insert, sel.first, end, etc.). indexProc doit renvoyer un code d'achèvement Tcl et définir le résultat de l'interpréteur en cas d'erreur.

ICURSORPROC

typePtr->icursorProc est appelé par Tk lors de la commande de widget icursor pour définir la position du curseur d'insertion dans un élément textuel. Il n'est pertinent que pour les types d'éléments qui prennent en charge un curseur d'insertion ; typePtr->icursorProc peut être spécifié comme NULL pour les types d'éléments qui ne prennent pas en charge un curseur d'insertion. La procédure doit correspondre au prototype suivant :

typedef void Tk_ItemCursorProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int index);

canvas et itemPtr ont les significations habituelles, et index est un indice dans le texte de l'élément, tel que renvoyé par un appel précédent à typePtr->insertProc. Le gestionnaire de type doit positionner le curseur d'insertion dans l'élément juste avant le caractère donné par index. La décision d'afficher ou non le curseur d'insertion est déterminée par d'autres informations fournies par Tk_CanvasGetTextInfo.

SELECTIONPROC

typePtr->selectionProc est appelé par Tk lors de la récupération de sélections ; il doit renvoyer une partie ou la totalité du texte sélectionné dans l'élément (le cas échéant). Il n'est pertinent que pour les types d'éléments qui prennent en charge du texte ; typePtr->selectionProc peut être spécifié comme NULL pour les types d'éléments non textuels. La procédure doit correspondre au prototype suivant :

typedef int Tk_ItemSelectionProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int offset,
        char *buffer,
        int maxBytes);

canvas et itemPtr ont les significations habituelles. offset est un décalage en octets dans la sélection où 0 fait référence au premier octet de la sélection ; il identifie le premier caractère à renvoyer dans cet appel. buffer pointe vers une zone mémoire dans laquelle stocker les octets demandés, et maxBytes spécifie le nombre maximal d'octets à renvoyer. selectionProc doit extraire jusqu'à maxBytes caractères de la sélection et les copier dans maxBytes ; il doit renvoyer le nombre d'octets réellement copiés, qui peut être inférieur à maxBytes s'il n'y a pas offset+maxBytes octets dans la sélection.

INSERTPROC

typePtr->insertProc est appelé par Tk lors de la commande de widget insert pour insérer du nouveau texte ou de nouvelles coordonnées dans un élément du canevas. Il n'est pertinent que pour les types d'éléments qui prennent en charge la méthode insert ; typePtr->insertProc peut être spécifié comme NULL pour d'autres types d'éléments. La procédure doit correspondre au prototype suivant :

typedef void Tk_ItemInsertProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int index,
        Tcl_Obj *obj);

canvas et itemPtr ont les significations habituelles. index est un indice dans le texte de l'élément, tel que renvoyé par un appel précédent à typePtr->insertProc, et obj contient le nouveau texte à insérer juste avant le caractère donné par index. Notez que si TK_CONFIG_OBJS n'est pas défini dans le champ typePtr->alwaysRedraw, le paramètre obj contiendra en fait un pointeur vers une chaîne de caractères constante à insérer. DCHARSPROC

typePtr->dCharsProc est appelé par Tk lors de la commande de widget dchars pour supprimer une plage de texte d'un élément du canevas ou une plage de coordonnées d'un élément tracé. Il n'est pertinent que pour les types d'éléments qui prennent en charge du texte ; typePtr->dCharsProc peut être spécifié comme NULL pour les types d'éléments non textuels qui ne veulent pas prendre en charge la suppression de coordonnées. La procédure doit correspondre au prototype suivant :

typedef void Tk_ItemDCharsProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int first,
        int last);

canvas et itemPtr ont les significations habituelles. first et last donnent les indices des premier et dernier octets à supprimer, tels que renvoyés par des appels précédents à typePtr->indexProc. Le gestionnaire de type doit supprimer les caractères spécifiés et mettre à jour la boîte englobante dans l'en-tête de l'élément.
