NOM

Tk_AllocColorFromObj, Tk_GetColor, Tk_GetColorFromObj, Tk_GetColorByValue, Tk_NameOfColor, Tk_FreeColorFromObj, Tk_FreeColor - gestion d'une base de couleurs

SYNTAXE

#include <tk.h>

XColor *
Tk_AllocColorFromObj(interp, tkwin, objPtr)

XColor *
Tk_GetColor(interp, tkwin, name)

XColor *
Tk_GetColorFromObj(tkwin, objPtr)

XColor *
Tk_GetColorByValue(tkwin, prefPtr)

const char *
Tk_NameOfColor(colorPtr)

GC
Tk_GCForColor(colorPtr, drawable)

Tk_FreeColorFromObj(tkwin, objPtr)

Tk_FreeColor(colorPtr)

ARGUMENTS

Tcl_Interp *interp (entree)
Interpréteur pour le rapport d'erreurs.
Tk_Window tkwin (entree)
Jeton de la fenêtre dans laquelle la couleur sera utilisée.
Tcl_Obj *objPtr (entree/sortie)
Valeur texte décrivant la couleur souhaitée ; la représentation interne est modifiée pour stocker un pointeur vers (XColor *).
const char *name (entree)
Description de la couleur passée sous forme de chaîne, et le résultat (XColor *) n'est pas stocké.
XColor *prefPtr (entree)
Spécifie les niveaux de rouge, de vert et de bleu de la couleur souhaitée.
XColor *colorPtr (entree)
Pointeur vers les informations de couleur X. Il doit avoir été précédemment alloué par un appel à Tk_AllocColorFromObj, Tk_GetColor ou Tk_GetColorByValue, sauf lorsqu'il est passé à Tk_NameOfColor.
Drawable drawable (entree)
Dessinable sur lequel le contexte graphique résultant sera utilisé. Il doit avoir le même écran et la même profondeur que la fenêtre pour laquelle la couleur a été allouée.

DESCRIPTION

Ces procédures gèrent les couleurs utilisées par une application Tk. Elles permettent de partager les couleurs lorsque cela est possible, afin de préserver l'espace de la palette de couleurs, et de choisir les couleurs les plus proches lorsque l'espace de la palette est épuisé.

Étant donné une description textuelle d'une couleur, Tk_AllocColorFromObj localise une valeur de pixel qui peut être utilisée pour rendre la couleur dans une fenêtre spécifique. La couleur souhaitée est spécifiée par une valeur dont la valeur chaîne doit avoir l'une des formes suivantes :

nom_couleur
L'un des noms de couleur valides définis dans le fichier de base de couleurs du serveur, tel que red ou PeachPuff.
#RGB
#RRGGBB
#RRRGGGBBB
#RRRRGGGGBBBB
Une spécification numérique des niveaux de rouge, de vert et de bleu pour afficher la couleur. Chaque R, G ou B représente un chiffre hexadécimal. Les quatre formes permettent de spécifier des couleurs avec 4 bits, 8 bits, 12 bits ou 16 bits. Lorsqu'on fournit moins de 16 bits pour chaque couleur, ils représentent les bits les plus significatifs de la couleur, tandis que les bits bas non remplis sont répétés à partir des bits les plus hauts disponibles. Par exemple, #3a7 équivaut à #3333aaaa7777.

Tk_AllocColorFromObj renvoie un pointeur vers une structure XColor ; cette structure indique les niveaux exacts de la couleur allouée (qui peuvent différer légèrement de ceux demandés, selon les limitations de l'écran), et une valeur de pixel qui peut être utilisée pour dessiner avec la couleur sur tkwin. En cas d'erreur lors de l'appel à Tk_AllocColorFromObj (par exemple, nom de couleur inconnu), NULL est renvoyé et un message d'erreur est stocké dans le résultat de interp si interp n'est pas NULL. Si la palette de couleurs de tkwin est pleine, Tk_AllocColorFromObj utilisera la couleur la plus proche existante dans la palette. Tk_AllocColorFromObj met en cache les informations sur la valeur renvoyée dans objPtr, ce qui accélère les appels futurs aux procédures telles que Tk_AllocColorFromObj et Tk_GetColorFromObj.

Tk_GetColor est identique à Tk_AllocColorFromObj, sauf que la description de la couleur est spécifiée par une chaîne de caractères au lieu d'une valeur. Cela empêche Tk_GetColor de stocker la valeur renvoyée, rendant Tk_GetColor moins efficace que Tk_AllocColorFromObj.

Tk_GetColorFromObj renvoie le jeton d'une couleur existante, étant donné la fenêtre et la description utilisée pour créer la couleur. Tk_GetColorFromObj ne crée pas réellement la couleur ; la couleur doit avoir été précédemment créée avec un appel à Tk_AllocColorFromObj ou Tk_GetColor. La valeur renvoyée est stockée dans objPtr, ce qui accélère les appels futurs à Tk_GetColorFromObj avec le même objPtr et tkwin.

Tk_GetColorByValue est similaire à Tk_GetColor, sauf que la couleur souhaitée est spécifiée par les champs red, green et blue de la structure pointée par colorPtr.

Ce paquet maintient une base de données de toutes les couleurs actuellement utilisées. Si une couleur est demandée plusieurs fois à partir de Tk_GetColor ou Tk_AllocColorFromObj (par exemple, par différentes fenêtres), ou si les mêmes intensités sont demandées plusieurs fois à partir de Tk_GetColorByValue, les valeurs de pixels existantes seront réutilisées. La réutilisation d'une valeur de pixel évite toute interaction avec le serveur d'affichage, ce qui rend l'allocation beaucoup plus efficace. Ces procédures offrent également une interface portable qui fonctionne sur tous les systèmes d'exploitation. Pour cette raison, vous devriez généralement utiliser Tk_AllocColorFromObj, Tk_GetColor ou Tk_GetColorByValue plutôt que des procédures de plus bas niveau comme XAllocColor.

Étant donné que différents appels à ce paquet peuvent renvoyer la même valeur de pixel partagée, les appelants ne doivent jamais modifier la couleur d'un pixel renvoyé par les procédures. Si vous souhaitez modifier dynamiquement une valeur de couleur, vous devez utiliser XAllocColorCells pour allouer la valeur de pixel de la couleur.

La procédure Tk_NameOfColor est approximativement l'inverse de Tk_GetColor. Si son argument colorPtr a été créé par Tk_AllocColorFromObj ou Tk_GetColor, la valeur renvoyée est la chaîne qui a été utilisée pour créer la couleur. Si colorPtr a été créé par un appel à Tk_GetColorByValue ou par tout autre mécanisme, la valeur renvoyée est une chaîne qui pourrait être passée à Tk_GetColor pour renvoyer la même couleur. Remarque : la valeur renvoyée par Tk_NameOfColor n'est garantie que jusqu'au prochain appel à Tk_NameOfColor.

Tk_GCForColor renvoie un contexte graphique dont le champ foreground est le pixel alloué pour colorPtr et dont les autres champs ont des valeurs par défaut. Cela fournit un moyen facile de dessiner avec une couleur. Le contexte graphique est mis en cache avec la couleur et n'existera que tant que colorPtr existera ; il sera libéré lorsque la dernière référence à colorPtr sera libérée par un appel à Tk_FreeColor.

Lorsqu'une couleur n'est plus nécessaire, Tk_FreeColorFromObj ou Tk_FreeColor doit être appelé pour la libérer. Pour Tk_FreeColorFromObj, la couleur à libérer est spécifiée avec les mêmes informations que celles utilisées pour la créer ; pour Tk_FreeColor, la couleur à libérer est spécifiée avec un pointeur vers sa structure XColor. Il doit y avoir exactement un appel à Tk_FreeColorFromObj ou Tk_FreeColor pour chaque appel à Tk_AllocColorFromObj, Tk_GetColor ou Tk_GetColorByValue.

ARGUMENTS

tkwin, objPtr

DESCRIPTION

La procédure Tk_AllocColorFromObj est utilisée pour allouer un pixel couleur Tk_Color à partir d'un objet Tcl qui spécifie la couleur. La couleur est spécifiée par le biais de l'objet Tcl objPtr, qui peut avoir l'une des formes suivantes.

Si objPtr spécifie une couleur dans le format standard des noms de couleurs X, par exemple, "red", "blue", "#ff0000" ou "#f00", alors Tk_AllocColorFromObj tentera d'allouer la couleur correspondante. Sinon, la couleur sera allouée en utilisant le nom de couleur spécifié dans objPtr comme un nom de couleur X. Par exemple, si objPtr spécifie la chaîne "red", alors Tk_AllocColorFromObj essaiera d'allouer la couleur rouge.

La valeur de retour est un pointeur vers une structure Tk_Color, qui contient les composantes rouge, verte et bleue de la couleur allouée. La structure Tk_Color est stockée dans le cache de couleurs du widget Tk, et la valeur de retour peut être réutilisée tant que la couleur est toujours utilisée. Si la couleur n'est plus utilisée, elle est désallouée et le pointeur devient invalide.

La couleur est allouée dans le contexte du pseudo-graphe tkwin. Cela signifie que la couleur sera visible sur le pseudo-graphe auquel tkwin est associé. Si tkwin est NULL, la couleur sera allouée dans le contexte du pseudo-graphe par défaut.
