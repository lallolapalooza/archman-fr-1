Le code suivant utilise Tk_DefineBitmap pour définir un nouveau bitmap nommé foo :

Pixmap bitmap ;
#include "stip.bitmap"
Tk_DefineBitmap(interp, "foo", stip_bits,
    stip_width, stip_height) ;
...
bitmap = Tk_GetBitmap(interp, tkwin, "foo") ;
Ce code lit le fichier bitmap au moment de la compilation et intègre les informations du bitmap dans l'image exécutable du programme. Le même fichier bitmap pourrait être lu au moment de l'exécution en utilisant Tk_GetBitmap : 
Pixmap bitmap ;
bitmap = Tk_GetBitmap(interp, tkwin, "@stip.bitmap") ;
La deuxième forme est un peu plus flexible (le fichier pourrait être modifié après la compilation du programme, ou une chaîne différente pourrait être fournie pour lire un fichier différent), mais elle est un peu plus lente et nécessite que le fichier bitmap existe séparément du programme.

Tk maintient une base de données de tous les bitmaps actuellement en cours d'utilisation. Dans la mesure du possible, il renverra un bitmap existant plutôt que d'en créer un nouveau. Lorsqu'un bitmap n'est plus utilisé, Tk le libérera automatiquement. Cette approche peut réduire considérablement la charge du serveur, par conséquent Tk_AllocBitmapFromObj et Tk_GetBitmap devraient généralement être préférés aux procédures Xlib telles que XReadBitmapFile.

Les bitmaps renvoyés par Tk_AllocBitmapFromObj et Tk_GetBitmap sont partagés, de sorte que les appelants ne devraient jamais les modifier. Si un bitmap doit être modifié dynamiquement, il doit être créé en appelant directement des procédures Xlib telles que XReadBitmapFile ou XCreatePixmap.

La procédure Tk_NameOfBitmap est à peu près l'inverse de Tk_GetBitmap. Étant donné un argument X Pixmap, elle renvoie la description textuelle qui a été passée à Tk_GetBitmap lors de la création du bitmap. Bitmap doit avoir été le résultat d'un appel précédent à Tk_AllocBitmapFromObj ou Tk_GetBitmap.

Tk_SizeOfBitmap renvoie les dimensions de son argument bitmap dans les mots pointés par les arguments widthPtr et heightPtr. Comme avec Tk_NameOfBitmap, bitmap doit avoir été créé par Tk_AllocBitmapFromObj ou Tk_GetBitmap.

Lorsqu'un bitmap n'est plus nécessaire, Tk_FreeBitmapFromObj ou Tk_FreeBitmap doit être appelé pour le libérer. Pour Tk_FreeBitmapFromObj, le bitmap à libérer est spécifié avec les mêmes informations utilisées pour le créer ; pour Tk_FreeBitmap, le bitmap à libérer est spécifié avec son jeton Pixmap. Il devrait y avoir exactement un appel à Tk_FreeBitmapFromObj ou Tk_FreeBitmap pour chaque appel à Tk_AllocBitmapFromObj ou Tk_GetBitmap.

BUGS

Pour déterminer si un bitmap existant peut être utilisé pour répondre à une nouvelle demande, Tk_AllocBitmapFromObj et Tk_GetBitmap ne tiennent compte que de la valeur immédiate de la description textuelle. Par exemple, lorsqu'un nom de fichier est passé à Tk_GetBitmap, Tk_GetBitmap supposera qu'il est sûr de réutiliser un bitmap existant créé à partir du même nom de fichier : il ne vérifiera pas si le fichier lui-même a changé, ou si le répertoire courant a changé, faisant ainsi référence au nom à un fichier différent.
