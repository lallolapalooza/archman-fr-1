Tk_ConfigureWidget(3) Procédures de la librairie Tk Tk_ConfigureWidget(3)

NOM

Tk_ConfigureWidget, Tk_ConfigureInfo, Tk_ConfigureValue, Tk_FreeOptions - traiter les options de configuration pour les widgets

SYNOPSIS

#include <tk.h>

int
Tk_ConfigureWidget(interp, tkwin, specs, argc, argv, widgRec, flags)

int
Tk_ConfigureInfo(interp, tkwin, specs, widgRec, argvName, flags)

int
Tk_ConfigureValue(interp, tkwin, specs, widgRec, argvName, flags)

Tk_FreeOptions(specs, widgRec, display, flags)

ARGUMENTS

Tcl_Interp *interp (in)
Interpreteur à utiliser pour renvoyer les messages d'erreur.
Tk_Window tkwin (in)
Fenêtre représentant le widget (nécessaire pour configurer les ressources X).
const Tk_ConfigSpec *specs (in)
Pointeur vers le tableau spécifiant les options de configuration valides pour ce widget.
int argc (in)
Nombre d'arguments dans argv.
const char **argv (in)
Options de ligne de commande pour configurer le widget.
char *widgRec (in/out)
Pointe vers la structure d'enregistrement du widget. Les champs de cette structure sont modifiés par Tk_ConfigureWidget pour stocker les informations de configuration.
int flags (in)
Si non nul, spécifie une combinaison OU de drapeaux qui contrôlent le traitement des informations de configuration. TK_CONFIG_ARGV_ONLY ignore la base de données d'options et les valeurs par défaut, et les bits TK_CONFIG_USER_BIT et supérieurs sont utilisés pour désactiver les entrées dans specs.
type name type (in)
Nom du type d'enregistrement de widget.
field name field (in)
Nom d'une propriété de l'enregistrement de type type.
const char *argvName (in)
Nom utilisé dans les lignes de commande Tcl pour faire référence à une option spécifique (par exemple, lors de la création d'un widget ou de l'invocation de la commande configure). S'il est NULL, seules les informations relatives à cette option sont renvoyées. S'il est NULL, des informations pour toutes les options disponibles sont renvoyées.
Display *display (in)
Affichage contenant le widget dont l'enregistrement est libéré ; nécessaire pour libérer les ressources.

DESCRIPTION

Note : Tk_ConfigureWidget devrait être remplacé par la nouvelle API basée sur Tcl_Obj, Tk_SetOptions. L'ancienne interface est conservée pour des raisons de compatibilité.

Tk_ConfigureWidget est utilisé pour configurer divers aspects d'un widget, tels que les couleurs, les polices, la largeur des bordures, etc. C'est une commodité pour réduire la quantité de code qui doit être écrit dans les gestionnaires de widgets pour gérer les informations de configuration. Il est généralement appelé lors de la création de widgets, et à nouveau lors de l'invocation de la commande configure pour un widget. Bien que principalement conçu pour les widgets, Tk_ConfigureWidget peut être utilisé dans d'autres contextes où des informations de ligne de commande argc-argv sont utilisées pour remplir une structure d'enregistrement, comme la configuration d'éléments graphiques dans un widget canvas ou d'entrées de menu.

Tk_ConfigureWidget traite un tableau qui spécifie les options de configuration prises en charge (specs) et une collection d'arguments de ligne de commande (argc et argv) pour remplir les champs d'une structure d'enregistrement (widgRec). Il utilise la base de données d'options et les valeurs par défaut spécifiées dans specs pour remplir les champs de widgRec qui ne sont pas spécifiés dans argv. Tk_ConfigureWidget renvoie normalement TCL_OK ; dans ce cas, il ne modifie pas interp. Si une erreur se produit, il renvoie TCL_ERROR et laisse un message d'erreur dans interp dans le style Tcl standard. En cas de retour d'erreur, certains des champs de widgRec peuvent déjà avoir été définis, si les informations de configuration correspondantes ont été traitées correctement avant que l'erreur ne se produise. Les autres champs sont définis à des valeurs initiales raisonnables afin que Tk_FreeOptions puisse être appelé pour le nettoyage.

Le tableau specs spécifie les types d'options de configuration attendus par le widget. Chaque entrée de ce tableau spécifie une option de configuration et a la structure suivante :

typedef struct {
    int type;
    const char *argvName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int offset;
    int specFlags;
    const Tk_CustomOption *customPtr;
} Tk_ConfigSpec;
Le champ type indique le type d'option de configuration (par exemple, TK_CONFIG_COLOR pour une valeur de couleur, ou TK_CONFIG_INT pour une valeur entière). Le champ type indique comment utiliser la valeur de l'option (plus d'informations dans le paragraphe suivant). Le champ argvName est une chaîne telle que -font ou -bg, qui est comparée aux valeurs de argv (si argvName est NULL, cela signifie qu'il s'agit d'une entrée groupée ; voir GROUPED ENTRIES ci-dessous). Les champs dbName et dbClass sont utilisés pour rechercher une valeur pour cette option dans la base de données d'options. Le champ defValue spécifie une valeur par défaut pour cette option si aucune valeur n'est spécifiée dans argv ou dans la base de données d'options. Le champ offset indique où dans widgRec les informations relatives à cette option sont stockées, et specFlags contient des informations supplémentaires pour contrôler le traitement de cette option (voir FLAGS ci-dessous). Le dernier champ, customPtr, est utilisé uniquement si type est TK_CONFIG_CUSTOM ; voir CUSTOM OPTION TYPES ci-dessous.

Tk_ConfigureWidget traite d'abord les arguments argv pour voir lesquels (s'il y en a) sont les options de configuration spécifiées là. Argv doit contenir un nombre pair de champs ; le premier champ de chaque paire doit correspondre au argvName d'une entrée dans specs (les abréviations uniques sont acceptables), et le second champ de la paire contient la valeur de cette option de configuration. S'il existe des entrées dans spec qui n'ont pas de correspondance dans argv, Tk_ConfigureWidget utilise les champs dbName et dbClass de l'entrée specs pour interroger la base de données d'options ; si une valeur est trouvée, elle est utilisée comme valeur pour l'option. Enfin, si aucune entrée n'est trouvée dans la base de données d'options, le champ defValue de l'entrée specs est utilisé comme valeur pour l'option de configuration. Si defValue est NULL, ou si le bit TK_CONFIG_DONT_SET_DEFAULT est activé dans flags, aucune valeur par défaut n'est définie et cette entrée specs sera ignorée s'il n'y a pas de valeur spécifiée dans argv ou dans la base de données d'options.

Une fois qu'une valeur a été déterminée pour une option de configuration, Tk_ConfigureWidget convertit la valeur de chaîne en un format plus utile, par exemple, une couleur si type est TK_CONFIG_COLOR ou un entier si type est TK_CONFIG_INT. Cette valeur est stockée dans l'enregistrement de la structure widgRec. Cet enregistrement est supposé contenir des informations pertinentes pour le gestionnaire de widget ; son type exact n'est pas connu de Tk_ConfigureWidget. Le champ offset de chaque entrée specs indique où dans widgRec les informations relatives à cette option de configuration sont stockées. Vous devez utiliser la macro Tk_Offset pour générer les valeurs d'offset (voir la description de Tk_Offset ci-dessous). L'emplacement indiqué par widgRec et offset sera appelé la "cible" dans les descriptions suivantes.

Le champ type de chaque entrée dans specs détermine ce qu'il faut faire avec la valeur de chaîne de cette option de configuration. Les valeurs légales pour type, et les actions correspondantes, sont :

TK_CONFIG_ACTIVE_CURSOR
La valeur doit être une chaîne ASCII identifiant un curseur approprié à passer à Tk_GetCursor. La chaîne est convertie en Tk_Cursor en appelant Tk_GetCursor et le résultat est stocké dans la cible. De plus, le curseur résultant est défini comme le curseur actif de tkwin en appelant XDefineCursor. Si le bit TK_CONFIG_NULL_OK est activé dans specFlags, la valeur peut être une chaîne vide, auquel cas la cible et le curseur actif de tkwin sont définis à None. Si la valeur précédente de la cible n'était pas None, elle est libérée en passant la valeur à Tk_FreeCursor.
TK_CONFIG_ANCHOR
La valeur doit être une chaîne ASCII identifiant un point d'ancrage dans l'une des formes acceptées par Tk_GetAnchor. La chaîne est convertie en Tk_Anchor.

Tk_ConfigureWidget traite un tableau qui spécifie les options de configuration prises en charge (specs) et une collection d'arguments de ligne de commande (argc et argv) pour remplir les champs d'une structure d'enregistrement (widgRec). Il utilise la base de données d'options et les valeurs par défaut spécifiées dans specs pour remplir les champs de widgRec qui ne sont pas spécifiés dans argv. Tk_ConfigureWidget renvoie normalement TCL_OK ; dans ce cas, il ne modifie pas interp. Si une erreur se produit, il renvoie TCL_ERROR et laisse un message d'erreur dans interp dans le style Tcl standard. En cas de retour d'erreur, certains des champs de widgRec peuvent déjà avoir été définis, si les informations de configuration correspondantes ont été traitées correctement avant que l'erreur ne se produise. Les autres champs sont définis à des valeurs initiales raisonnables afin que Tk_FreeOptions puisse être appelé pour le nettoyage.

Le tableau specs spécifie les types d'options de configuration attendus par le widget. Chaque entrée de ce tableau spécifie une option de configuration et a la structure suivante :

typedef struct {
    int type;
    const char *argvName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int offset;
    int specFlags;
    const Tk_CustomOption *customPtr;
} Tk_ConfigSpec;
Le champ type indique le type d'option de configuration (par exemple, TK_CONFIG_COLOR pour une valeur de couleur, ou TK_CONFIG_INT pour une valeur entière). Le champ type indique comment utiliser la valeur de l'option (plus d'informations dans le paragraphe suivant). Le champ argvName est une chaîne telle que -font ou -bg, qui est comparée aux valeurs de argv (si argvName est NULL, cela signifie qu'il s'agit d'une entrée groupée ; voir GROUPED ENTRIES ci-dessous). Les champs dbName et dbClass sont utilisés pour rechercher une valeur pour cette option dans la base de données d'options. Le champ defValue spécifie une valeur par défaut pour cette option si aucune valeur n'est spécifiée dans argv ou dans la base de données d'options. Le champ offset indique où dans widgRec les informations relatives à cette option sont stockées, et specFlags contient des informations supplémentaires pour contrôler le traitement de cette option (voir FLAGS ci-dessous). Le dernier champ, customPtr, est utilisé uniquement si type est TK_CONFIG_CUSTOM ; voir CUSTOM OPTION TYPES ci-dessous.

Tk_ConfigureWidget traite d'abord les arguments argv pour voir lesquels (s'il y en a) sont les options de configuration spécifiées là. Argv doit contenir un nombre pair de champs ; le premier champ de chaque paire doit correspondre au argvName d'une entrée dans specs (les abréviations uniques sont acceptables), et le second champ de la paire contient la valeur de cette option de configuration. S'il existe des entrées dans spec qui n'ont pas de correspondance dans argv, Tk_ConfigureWidget utilise les champs dbName et dbClass de l'entrée specs pour interroger la base de données d'options ; si une valeur est trouvée, elle est utilisée comme valeur pour l'option. Enfin, si aucune entrée n'est trouvée dans la base de données d'options, le champ defValue de l'entrée specs est utilisé comme valeur pour l'option de configuration. Si defValue est NULL, ou si le bit TK_CONFIG_DONT_SET_DEFAULT est activé dans flags, aucune valeur par défaut n'est définie et cette entrée specs sera ignorée s'il n'y a pas de valeur spécifiée dans argv ou dans la base de données d'options.

Une fois qu'une valeur a été déterminée pour une option de configuration, Tk_ConfigureWidget convertit la valeur de chaîne en un format plus utile, par exemple, une couleur si type est TK_CONFIG_COLOR ou un entier si type est TK_CONFIG_INT. Cette valeur est stockée dans l'enregistrement de la structure widgRec. Cet enregistrement est supposé contenir des informations pertinentes pour le gestionnaire de widget ; son type exact n'est pas connu de Tk_ConfigureWidget. Le champ offset de chaque entrée specs indique où dans widgRec les informations relatives à cette option de configuration sont stockées. Vous devez utiliser la macro Tk_Offset pour générer les valeurs d'offset (voir la description de Tk_Offset ci-dessous). L'emplacement indiqué par widgRec et offset sera appelé la "cible" dans les descriptions suivantes.

Le champ type de chaque entrée dans specs détermine ce qu'il faut faire avec la valeur de chaîne de cette option de configuration. Les valeurs légales pour type, et les actions correspondantes, sont :

TK_CONFIG_ACTIVE_CURSOR
La valeur doit être une chaîne ASCII identifiant un curseur approprié à passer à Tk_GetCursor. La chaîne est convertie en Tk_Cursor en appelant Tk_GetCursor et le résultat est stocké dans la cible. De plus, le curseur résultant est défini comme le curseur actif de tkwin en appelant XDefineCursor. Si le bit TK_CONFIG_NULL_OK est activé dans specFlags, la valeur peut être une chaîne vide, auquel cas la cible et le curseur actif de tkwin sont définis à None. Si la valeur précédente de la cible n'était pas None, elle est libérée en passant la valeur à Tk_FreeCursor.
TK_CONFIG_ANCHOR
La valeur doit être une chaîne ASCII identifiant un point d'ancrage dans l'une des formes acceptées par Tk_GetAnchor. La chaîne est convertie en Tk_Anchor.

Enfin, si aucune entrée n'est trouvée dans la base de données d'options, le champ defValue de l'entrée specs est utilisé comme valeur pour l'option de configuration. Si defValue est NULL, ou si le bit TK_CONFIG_DONT_SET_DEFAULT est activé dans flags, aucune valeur par défaut n'est définie et cette entrée specs sera ignorée s'il n'y a pas de valeur spécifiée dans argv ou dans la base de données d'options.

Une fois qu'une valeur a été déterminée pour une option de configuration, Tk_ConfigureWidget convertit la valeur de chaîne en un format plus utile, par exemple, une couleur si type est TK_CONFIG_COLOR ou un entier si type est TK_CONFIG_INT. Cette valeur est stockée dans l'enregistrement de la structure widgRec. Cet enregistrement est supposé contenir des informations pertinentes pour le gestionnaire de widget ; son type exact n'est pas connu de Tk_ConfigureWidget. Le champ offset de chaque entrée specs indique où dans widgRec les informations relatives à cette option de configuration sont stockées. Vous devez utiliser la macro Tk_Offset pour générer les valeurs d'offset (voir la description de Tk_Offset ci-dessous). L'emplacement indiqué par widgRec et offset sera appelé la "cible" dans les descriptions suivantes.

Le champ type de chaque entrée dans specs détermine ce qu'il faut faire avec la valeur de chaîne de cette option de configuration. Les valeurs légales pour type, et les actions correspondantes, sont :

TK_CONFIG_ACTIVE_CURSOR
La valeur doit être une chaîne ASCII identifiant un curseur approprié à passer à Tk_GetCursor. La chaîne est convertie en Tk_Cursor en appelant Tk_GetCursor et le résultat est stocké dans la cible. De plus, le curseur résultant est défini comme le curseur actif de tkwin en appelant XDefineCursor. Si le bit TK_CONFIG_NULL_OK est activé dans specFlags, la valeur peut être une chaîne vide, auquel cas la cible et le curseur actif de tkwin sont définis à None. Si la valeur précédente de la cible n'était pas None, elle est libérée en passant la valeur à Tk_FreeCursor.
TK_CONFIG_ANCHOR
La valeur doit être une chaîne ASCII identifiant un point d'ancrage dans l'une des formes acceptées par Tk_GetAnchor. La chaîne est convertie en Tk_Anchor.

TK_CONFIG_NULL_OK
Ce bit n'est pertinent que pour certains types d'entrées (voir les descriptions des différents types d'entrées ci-dessus). Si ce bit est défini, il indique qu'une valeur de chaîne vide pour le champ est acceptable et si elle se produit, la cible doit être définie à NULL ou None, selon le type de la cible. Ce drapeau est généralement utilisé pour permettre de désactiver complètement une fonctionnalité, par exemple, définir la valeur d'un curseur à None afin qu'une fenêtre hérite simplement du curseur de son parent. Si ce bit n'est pas défini, les chaînes vides sont traitées comme des chaînes, ce qui entraîne généralement une erreur.
TK_CONFIG_DONT_SET_DEFAULT
Si ce bit est égal à un, cela signifie que le champ defValue de l'entrée ne doit être utilisé que pour retourner la valeur par défaut dans Tk_ConfigureInfo. Dans les appels à Tk_ConfigureWidget, aucune valeur par défaut ne sera fournie pour les entrées ayant ce drapeau défini ; on suppose que l'appelant a déjà fourni une valeur par défaut à l'emplacement cible. Ce drapeau fournit une optimisation de performance lorsque le traitement de la chaîne par défaut est coûteux : le client peut calculer la valeur par défaut une fois, sauvegarder la valeur et la fournir avant d'appeler Tk_ConfigureWidget.
TK_CONFIG_OPTION_SPECIFIED
Ce bit est obsolète. Il était autrefois défini et effacé par Tk_ConfigureWidget afin que les appelants puissent détecter quelles entrées étaient spécifiées dans argv, mais il a été supprimé car il était intrinsèquement non thread-safe. Le code qui souhaite détecter quelles options ont été spécifiées devrait utiliser Tk_SetOptions à la place.

Les drapeaux TK_CONFIG_MONO_ONLY et TK_CONFIG_COLOR_ONLY sont généralement utilisés pour spécifier différentes valeurs par défaut pour les écrans monochromes et couleur. Ceci est fait en créant deux entrées dans specs qui sont identiques sauf pour leurs champs defValue et specFlags. Une entrée devrait avoir la valeur TK_CONFIG_MONO_ONLY dans ses specFlags et la valeur par défaut pour les écrans monochromes dans son defValue ; l'autre entrée devrait avoir la valeur TK_CONFIG_COLOR_ONLY dans ses specFlags et la valeur defValue appropriée pour les écrans couleur.

Troisièmement, il est possible d'utiliser flags et specFlags ensemble pour désactiver sélectivement certaines entrées. Cette fonctionnalité n'est pas très souvent nécessaire. Elle est utile dans les cas où plusieurs types de widgets similaires sont implémentés au même endroit. Elle permet de créer une seule table specs avec toutes les options de configuration pour tous les types de widgets. Lors du traitement d'un type de widget particulier, seules les entrées pertinentes pour ce type seront utilisées. Cet effet est obtenu en définissant les bits de poids fort (ceux dont la position est égale ou supérieure à TK_CONFIG_USER_BIT) dans les valeurs specFlags ou dans flags. Pour qu'une entrée particulière dans specs soit utilisée, ses bits de poids fort doivent correspondre exactement aux bits de poids fort de la valeur flags passée à Tk_ConfigureWidget. Si une table specs est utilisée pour N types de widgets différents, alors N des bits de poids fort seront utilisés. Chaque entrée specs aura un ou plusieurs de ces bits définis dans son champ specFlags pour indiquer les types de widgets pour lesquels cette entrée est valide. Lors de l'appel à Tk_ConfigureWidget, flags aura un seul de ces bits défini pour sélectionner les entrées du type de widget souhaité. Pour un exemple de fonctionnement de cette fonctionnalité, voir le code dans tkButton.c.

TK_OFFSET

La macro Tk_Offset est fournie comme moyen sûr de générer les valeurs d'offset pour les entrées dans les structures Tk_ConfigSpec. Elle prend deux arguments : le nom d'un type d'enregistrement et le nom d'un champ dans cet enregistrement. Elle retourne le décalage en octets du champ nommé dans les enregistrements du type donné.

TK_CONFIGUREINFO

La procédure Tk_ConfigureInfo peut être utilisée pour obtenir des informations sur une ou toutes les options d'un widget donné. Étant donné un jeton pour une fenêtre (tkwin), une table décrivant les options de configuration pour une classe de widgets (specs), un pointeur vers un enregistrement de widget contenant les informations actuelles d'un widget (widgRec), et un argument argvName NULL, Tk_ConfigureInfo génère une chaîne décrivant toutes les options de configuration de la fenêtre. La chaîne est placée dans le résultat de l'interpréteur interp. Dans des circonstances normales, elle retourne TCL_OK ; si une erreur se produit, elle retourne TCL_ERROR et le résultat de l'interpréteur contiendra un message d'erreur.

Si argvName est NULL, alors la valeur laissée dans le résultat de l'interpréteur par Tk_ConfigureInfo consiste en une liste d'une ou plusieurs entrées, chacune décrivant une option de configuration (c'est-à-dire une entrée dans specs). Chaque entrée de la liste contiendra soit deux, soit cinq valeurs. Si l'entrée correspondante dans specs a le type TK_CONFIG_SYNONYM, alors la liste contiendra deux valeurs : le argvName de l'entrée et le dbName (nom synonyme). Sinon, la liste contiendra cinq valeurs : argvName, dbName, dbClass, defValue, et la valeur actuelle. La valeur actuelle est calculée à partir du champ approprié de widgRec en appelant des procédures comme Tk_NameOfColor.

Si l'argument argvName de Tk_ConfigureInfo n'est pas NULL, alors il indique une option unique, et des informations ne sont retournées que pour cette option. La chaîne placée dans le résultat de l'interpréteur sera une liste contenant deux ou cinq valeurs comme décrit ci-dessus ; ce sera identique à la sous-liste correspondante qui aurait été retournée si argvName avait été NULL.

L'argument flags de Tk_ConfigureInfo est utilisé pour restreindre les entrées specs à considérer, tout comme pour Tk_ConfigureWidget.

TK_CONFIGUREVALUE

Tk_ConfigureValue prend des arguments similaires à Tk_ConfigureInfo ; au lieu de retourner une liste de valeurs, elle retourne simplement la valeur actuelle de l'option donnée par argvName (argvName ne doit pas être NULL). La valeur est retournée dans le résultat de l'interpréteur interp et TCL_OK est normalement retourné comme résultat de la procédure. Si une erreur se produit dans Tk_ConfigureValue (par exemple, argvName n'est pas un nom d'option valide), TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de l'interpréteur. Cette procédure est généralement appelée pour implémenter les commandes de widget cget.

TK_FREEOPTIONS

La procédure Tk_FreeOptions peut être appelée lors du nettoyage du widget pour libérer toutes les ressources associées aux options de configuration. Elle parcourt specs et pour chaque entrée correspondant à une ressource qui doit être explicitement libérée (par exemple, celles de type TK_CONFIG_COLOR), elle libère la ressource dans l'enregistrement du widget. Si le champ de l'enregistrement du widget ne fait pas référence à une ressource (par exemple, il contient un pointeur nul), aucune ressource n'est libérée pour cette entrée. Après avoir libéré une ressource, Tk_FreeOptions met le champ correspondant de l'enregistrement du widget à NULL.

TYPES D'OPTIONS PERSONNALISÉES

Les applications peuvent étendre les types de configuration intégrés avec des types de configuration supplémentaires en écrivant des procédures pour analyser et imprimer des options d'un type et en créant une structure pointant vers ces procédures :

typedef struct Tk_CustomOption {
    Tk_OptionParseProc *parseProc;
    Tk_OptionPrintProc *printProc;
    ClientData clientData;
} Tk_CustomOption;
typedef int Tk_OptionParseProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tk_Window tkwin,
        char *value,
        char *widgRec,
        int offset);
typedef const char *Tk_OptionPrintProc(
        ClientData clientData,
        Tk_Window tkwin,
        char *widgRec,
        int offset,
        Tcl_FreeProc **freeProcPtr);
La structure Tk_CustomOption contient trois champs, qui sont des pointeurs vers les deux procédures et une valeur clientData à passer à ces procédures lorsqu'elles sont invoquées. La valeur clientData pointe généralement vers une structure contenant les informations nécessaires aux procédures lors de l'analyse et de l'impression des options.

La procédure parseProc est invoquée par Tk_ConfigureWidget pour analyser une chaîne et stocker la valeur résultante dans l'enregistrement du widget. L'argument clientData est une copie du champ clientData de la structure Tk_CustomOption. L'argument interp pointe vers un interpréteur Tcl utilisé pour signaler les erreurs. Tkwin est une copie de l'argument tkwin de Tk_ConfigureWidget. L'argument value est une chaîne décrivant la valeur de l'option ; elle pourrait avoir été spécifiée explicitement dans l'appel à Tk_ConfigureWidget ou provenir de la base de données d'options ou d'une valeur par défaut. Value ne sera jamais un pointeur NULL mais il peut pointer vers une chaîne vide. RecordPtr est le même que l'argument widgRec de Tk_ConfigureWidget ; il pointe vers le début de l'enregistrement du widget à modifier. Le dernier argument, offset, donne le décalage en octets à partir du début de l'enregistrement du widget jusqu'à l'emplacement où la valeur de l'option doit être placée. La procédure doit traduire la chaîne dans la forme appropriée pour l'option et stocker la valeur dans l'enregistrement du widget. Elle doit normalement retourner TCL_OK, mais si une erreur se produit dans la traduction de la chaîne en valeur, elle doit retourner TCL_ERROR et stocker un message d'erreur dans le résultat de l'interpréteur interp.

La procédure printProc est appelée par Tk_ConfigureInfo pour produire une chaîne de caractères décrivant une option existante. Ses arguments clientData, tkwin, widgRec, et offset ont tous la même signification que pour les procédures Tk_OptionParseProc.
