NOM

Tk::after - Exécuter une commande après un délai

SYNOPSIS

  $widget->after(ms)

  $id = $widget->after(ms?,callback?)

  $id = $widget->repeat(ms?,callback?)

  $widget->afterCancel($id)

  $id = $widget->afterIdle(callback)

  $widget->afterInfo?($id)?

  $id->time(?delay?)

DESCRIPTION

Cette méthode est utilisée pour retarder l'exécution du programme ou pour exécuter une fonction de rappel en arrière-plan à un moment donné dans le futur.

Dans perl/Tk, $widget->after est implémenté via la classe "Tk::After", et les fonctions de rappel sont associées à $widget, et sont automatiquement annulées lorsque le widget est détruit. Une interface presque identique, mais sans annulation automatique, et sans répétition est fournie via la méthode Tk::after.

Détails Internes

La classe interne Tk::After a la synopsie suivante :

$id = Tk::After->new($widget, tid, $time, 'once',   callback);
$id = Tk::After->new($widget, tid, $time, 'repeat', callback);
$id->cancel;
$id->time(?delay?);

$id est un objet Tk::After, un tableau de 5 éléments :

$widget est la référence du widget parent.

tid est l'identifiant interne du timer, une chaîne unique.

$time est la chaîne 'idle', représentant un timer de file d'attente inactive, ou une valeur entière en millisecondes.

once ou repeat spécifie si le timer est un événement after unique, ou un événement repeat répétitif.

callback spécifie un objet Tk::Callback de Perl/Tk.

Changer l'intervalle du timer repeat

Il est possible de changer la valeur de délai d'un timer repeat, ou même d'annuler n'importe quel timer, en utilisant la méthode time. Si delay est spécifié et non nul, un nouveau délai de timer est établi. Si delay est zéro, l'événement timer est annulé comme si $id->cancel avait été invoqué. Dans tous les cas, le délai du timer en millisecondes est retourné.

Note : le nouveau délai du timer prendra effet lors de l'événement timer *ultérieur* - cette commande n'annulera pas l'événement timer en attente et ne le réémettra pas avec le nouveau délai.

La méthode after() a plusieurs formes comme suit :

$widget->after(ms)
La valeur ms doit être un entier indiquant un temps en millisecondes. La commande dort pendant ms millisecondes puis retourne. Pendant que la commande dort, l'application ne répond pas aux événements.
$widget->after(ms,callback)
Dans cette forme, la commande retourne immédiatement, mais elle organise l'exécution de callback ms millisecondes plus tard en tant que gestionnaire d'événements. Le rappel sera exécuté exactement une fois, au moment donné. La commande sera exécutée dans le contexte de $widget. Si une erreur survient lors de l'exécution de la commande retardée, le mécanisme Tk::Error est utilisé pour signaler l'erreur. La commande after retourne un identifiant (un objet dans le cas de perl/Tk) qui peut être utilisé pour annuler la commande retardée en utilisant afterCancel.
$widget->repeat(ms,callback)
Dans cette forme, la commande retourne immédiatement, mais elle organise l'exécution de callback ms millisecondes plus tard en tant que gestionnaire d'événements. Après l'exécution de callback, il est replanifié, pour être exécuté dans un nouveau délai de ms, et ainsi de suite, jusqu'à ce qu'il soit annulé.
$widget->afterCancel($id)
$id->cancel
Annule l'exécution d'une commande retardée qui avait été précédemment planifiée. $id indique quelle commande doit être annulée ; il doit avoir été la valeur de retour d'un appel précédent à after. Si la commande donnée par $id a déjà été exécutée (et n'est pas planifiée pour être exécutée à nouveau), alors afterCancel n'a aucun effet.
$widget->afterCancel(callback)
Cette forme n'est pas robuste dans perl/Tk - son utilisation est déconseillée. Cette commande devrait également annuler l'exécution d'une commande retardée. L'argument callback est comparé aux rappels en attente, si une correspondance est trouvée, ce rappel est annulé et ne sera jamais exécuté ; si aucun rappel de ce type n'est en attente, alors afterCancel n'a aucun effet.
$widget->afterIdle(callback)
Organise l'évaluation de callback plus tard en tant que rappel inactif. Le script sera exécuté exactement une fois, la prochaine fois que la boucle d'événements sera entrée et qu'il n'y aura aucun événement à traiter. La commande retourne un identifiant qui peut être utilisé pour annuler la commande retardée en utilisant afterCancel. Si une erreur survient lors de l'exécution du script, le mécanisme Tk::Error est utilisé pour signaler l'erreur.
$widget->afterInfo?($id)?
Cette commande retourne des informations sur les gestionnaires d'événements existants. Si aucun argument $id n'est fourni, la commande retourne une liste des identifiants de tous les gestionnaires d'événements existants créés par les commandes after et repeat pour $widget. Si $id est fourni, il spécifie un gestionnaire existant ; $id doit avoir été la valeur de retour d'un appel précédent à after ou repeat et il ne doit pas encore s'être déclenché ou avoir été annulé. Dans ce cas, la commande retourne une liste de trois éléments. Le premier élément de la liste est le rappel associé à $id, le deuxième élément est soit idle, soit la valeur entière en millisecondes du timer pour indiquer de quel type de gestionnaire d'événements il s'agit, et le troisième est une chaîne once ou repeat pour différencier un événement after d'un événement repeat.

Les formes after(ms) et afterIdle de la commande supposent que l'application est pilotée par événements : les commandes retardées ne seront pas exécutées à moins que l'application n'entre dans la boucle d'événements. Dans les applications qui ne sont pas normalement pilotées par événements, la boucle d'événements peut être entrée avec les commandes vwait et update.
