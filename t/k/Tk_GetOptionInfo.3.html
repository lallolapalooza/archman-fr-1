ARGUMENTS

Tcl_Interp *interp (in)
Un interpréteur Tcl. La plupart des procédures n'utilisent ceci que pour retourner des messages d'erreur ; s'il est NULL, aucun message d'erreur n'est retourné. Pour Tk_CreateOptionTable, la valeur ne peut pas être NULL ; elle donne l'interpréteur dans lequel la table d'options sera utilisée.
const Tk_OptionSpec *templatePtr (in)
Pointe vers un tableau d'informations statiques décrivant les options de configuration prises en charge. Utilisé pour construire une Tk_OptionTable. Les informations pointées par cet argument doivent exister pendant toute la durée de vie de la Tk_OptionTable.
Tk_OptionTable optionTable (in)
Jeton pour une table d'options. Doit avoir été retourné par un appel précédent à Tk_CreateOptionTable.
char *recordPtr (in/out)
Pointe vers la structure où les valeurs des options de configuration sont stockées ; les champs de cet enregistrement sont modifiés par des procédures telles que Tk_SetOptions et lus par des procédures telles que Tk_GetOptionValue.
Tk_Window tkwin (in)
Pour des options telles que TK_OPTION_COLOR, cet argument indique la fenêtre dans laquelle l'option sera utilisée. Si optionTable n'utilise aucune option dépendant de la fenêtre, une valeur NULL peut être fournie pour cet argument.
int objc (in)
Nombre de valeurs dans objv.
Tcl_Obj *const *objv (in)
Arguments de la ligne de commande pour la définition des options de configuration.
Tk_SavedOptions *savePtr (out)
S'il n'est pas NULL, la structure pointée par cet argument est remplie avec les anciennes valeurs de toutes les options qui ont été modifiées et les anciennes valeurs sont restaurées automatiquement en cas d'erreur dans Tk_SetOptions.
int *maskPtr (out)
S'il n'est pas NULL, le mot pointé par maskPtr est rempli avec le OU bit à bit des champs typeMask des options qui ont été modifiées.
Tk_SavedOptions *savedPtr (in/out)
Pointe vers une structure précédemment remplie par Tk_SetOptions avec les anciennes valeurs des options modifiées.
Tcl_Obj *namePtr (in)
La valeur de cet objet est le nom d'une option particulière. Si NULL est passé à Tk_GetOptionInfo, des informations sont retournées pour toutes les options. Ne doit pas être NULL lors de l'appel à Tk_GetOptionValue.
type name type (in)
Le nom du type d'un enregistrement.
field name field (in)
Le nom d'un champ dans des enregistrements de type type.

DESCRIPTION

Ces procédures gèrent la plupart des détails du traitement des options de configuration telles que celles des widgets Tk. Étant donné une description des options prises en charge, ces procédures gèrent tous les détails de l'analyse des options et du stockage de leurs valeurs dans une structure C associée au widget ou à l'objet. Les procédures ont été conçues principalement pour les widgets dans Tk, mais elles peuvent également être utilisées pour d'autres types d'objets qui ont des options de configuration. Dans le reste de cette page de manuel, "widget" sera utilisé pour désigner l'objet dont les options sont gérées ; en pratique, l'objet peut ne pas être réellement un widget. Le terme "enregistrement de widget" est utilisé pour désigner la structure de niveau C dans laquelle sont stockées les informations relatives à un widget ou objet particulier.

Notez que la manière la plus simple d'apprendre à utiliser ces procédures est de regarder un exemple fonctionnel. Dans Tk, l'exemple le plus simple est le code qui implémente la famille des widgets bouton, qui se trouve dans tkButton.c. D'autres exemples se trouvent dans tkSquare.c et tkMenu.c.

Afin d'utiliser ces procédures, le code qui implémente le widget doit contenir un tableau statique de structures Tk_OptionSpec. Il s'agit d'un modèle qui décrit les différentes options prises en charge par cette classe de widget ; il existe un modèle distinct pour chaque type de widget. Le modèle contient des informations telles que le nom de chaque option, son type, sa valeur par défaut et l'emplacement où la valeur de l'option est stockée dans l'enregistrement du widget. Voir MODÈLES ci-dessous pour plus de détails.

Afin de traiter les options de configuration efficacement, le modèle statique doit être augmenté d'informations supplémentaires disponibles uniquement à l'exécution. La procédure Tk_CreateOptionTable crée ces informations dynamiques à partir du modèle et retourne un jeton Tk_OptionTable qui décrit les informations statiques et dynamiques. Toutes les autres procédures, telles que Tk_SetOptions, prennent un jeton Tk_OptionTable comme argument. Typiquement, Tk_CreateOptionTable est appelé la première fois qu'un widget d'une classe particulière est créé et la Tk_OptionTable résultante est utilisée à l'avenir pour tous les widgets de cette classe. Une Tk_OptionTable ne peut être utilisée que dans un seul interpréteur, indiqué par l'argument interp à Tk_CreateOptionTable. Lorsqu'une table d'options n'est plus nécessaire, Tk_DeleteOptionTable doit être appelée pour libérer toutes ses ressources. Toutes les tables d'options d'un interpréteur Tcl sont libérées automatiquement si l'interpréteur est supprimé.

Tk_InitOptions est appelée lors de la création d'un nouveau widget pour définir les valeurs par défaut. Tk_InitOptions reçoit un jeton pour une table d'options (optionTable) et un pointeur vers un enregistrement de widget (recordPtr), qui est la structure C contenant les informations sur ce widget. Tk_InitOptions utilise les informations de la table d'options pour choisir une valeur par défaut appropriée pour chaque option, puis stocke la valeur par défaut directement dans l'enregistrement du widget, écrasant toute information déjà présente. Tk_InitOptions retourne normalement TCL_OK. Si une erreur s'est produite lors de la définition des valeurs par défaut (par exemple, parce qu'une valeur par défaut était erronée), alors TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de interp si interp n'est pas NULL. Pour toute option de configuration d'un widget qui a TK_OPTION_DONT_SET_DEFAULT défini dans son champ flags, l'initialisation ci-dessus est entièrement ignorée, voir ci-dessous.

Tk_SetOptions est appelée pour modifier les options de configuration en fonction des informations spécifiées dans une commande Tcl. La commande peut être celle qui crée un nouveau widget, ou une commande qui modifie les options d'un widget existant. Les arguments objc et objv décrivent les valeurs des arguments de la commande Tcl. Objv doit contenir un nombre pair d'objets : le premier objet de chaque paire donne le nom d'une option et le second objet donne la nouvelle valeur pour cette option. Tk_SetOptions recherche chaque nom dans optionTable, vérifie que la nouvelle valeur de l'option est conforme au type dans optionTable, et stocke la valeur de l'option dans l'enregistrement du widget donné par recordPtr. Tk_SetOptions retourne normalement TCL_OK. Si une erreur s'est produite (comme un nom d'option inconnu ou une valeur d'option illégale), alors TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de interp si interp n'est pas NULL.

Tk_SetOptions a deux fonctionnalités supplémentaires. Premièrement, si l'argument maskPtr n'est pas NULL, il pointe vers une valeur entière qui est remplie avec des informations sur les options qui ont été modifiées. Pour chaque option dans le modèle passé à Tk_CreateOptionTable, il y a un champ typeMask. Les bits de ce champ sont définis par le code qui implémente le widget ; par exemple, chaque bit peut correspondre à une option de configuration particulière. Alternativement, les bits peuvent être utilisés fonctionnellement. Par exemple, un bit peut être utilisé pour le redessin : toutes les options qui affectent l'affichage du widget, de sorte que le changement de l'option nécessite que le widget soit redessiné, peuvent avoir ce bit défini. Un autre bit peut indiquer que la géométrie du widget doit être recalculée, etc. Tk_SetOptions effectue un OU bit à bit des champs typeMask des

Toute la structure du fichier est conservée. Les options qui ont été modifiées et sont renvoyées dans *maskPtr ; l'appelant peut utiliser ces informations pour s'optimiser lui-même, par exemple, en évitant de redessiner la fenêtre si les options modifiées n'affectent pas son apparence. La seconde fonctionnalité supplémentaire de Tk_SetOptions concerne la récupération d'erreurs. Si une erreur se produit lors du traitement des options de configuration, cette fonctionnalité permet de restaurer toutes les valeurs de configuration à leurs anciennes valeurs. Les erreurs peuvent se produire lors du traitement des options dans Tk_SetOptions ou ultérieurement chez l'appelant. Dans de nombreux cas, l'appelant effectue un traitement supplémentaire après le retour de Tk_SetOptions ; par exemple, il peut utiliser la valeur d'une option pour définir un suivi dans une variable et détecter une erreur si la variable est un tableau au lieu d'un scalaire. La récupération d'erreurs est activée en passant une valeur non nulle pour l'argument savePtr de Tk_SetOptions ; il doit s'agir d'un pointeur vers une structure Tk_SavedOptions non initialisée sur la pile de l'appelant. Tk_SetOptions écrase la structure pointée par savePtr avec les informations sur les anciennes valeurs de toutes les options modifiées par la procédure. Si Tk_SetOptions retourne avec succès, l'appelant utilise la structure de l'une des deux manières. Si l'appelant termine son traitement des nouvelles options sans erreur, il doit passer la structure à Tk_FreeSavedOptions pour libérer les anciennes valeurs. Si l'appelant détecte une erreur dans son traitement des nouvelles options, il doit passer la structure à Tk_RestoreSavedOptions, qui recopie les anciennes valeurs dans l'enregistrement de la fenêtre et libère les nouvelles valeurs. Si Tk_SetOptions détecte une erreur, il restaure automatiquement toutes les options qui avaient déjà été modifiées et laisse *savePtr dans un état vide : l'appelant n'a pas besoin d'appeler Tk_FreeSavedOptions ou Tk_RestoreSavedOptions. Si l'argument savePtr de Tk_SetOptions est NULL, Tk_SetOptions libère chaque ancienne valeur d'option immédiatement lorsqu'il définit une nouvelle valeur pour l'option. Dans ce cas, si une erreur se produit pour la troisième option, les anciennes valeurs des deux premières options ne peuvent pas être restaurées. Tk_GetOptionValue renvoie la valeur actuelle d'une option de configuration pour une fenêtre spécifique. L'argument namePtr contient le nom d'une option ; Tk_GetOptionValue utilise optionTable pour rechercher l'option et extraire sa valeur de l'enregistrement de la fenêtre pointé par recordPtr, puis renvoie un objet contenant cette valeur. Si une erreur se produit (par exemple, parce que namePtr contient un nom d'option inconnu), NULL est renvoyé et un message d'erreur est laissé dans le résultat de interp, à moins que interp ne soit NULL. Tk_GetOptionInfo renvoie des informations sur les options de configuration dans un format approprié pour les commandes de widget configure. Si l'argument namePtr n'est pas NULL, il pointe vers un objet qui donne le nom d'une option de configuration ; Tk_GetOptionInfo renvoie un objet contenant une liste de cinq éléments, qui sont le nom de l'option, le nom et la classe utilisés pour l'option dans la base de données d'options, la valeur par défaut de l'option et la valeur actuelle de l'option. Si l'argument namePtr est NULL, Tk_GetOptionInfo renvoie des informations sur toutes les options sous forme de liste de listes ; chaque sous-liste décrit une option. Les options synthétiques sont traitées différemment selon que namePtr est NULL ou non : si namePtr est NULL, la sous-liste pour chaque option synthétique a seulement deux éléments, qui sont le nom de l'option et le nom de l'autre option à laquelle elle se réfère ; si namePtr n'est pas NULL et pointe vers une option synthétique, l'objet renvoyé est la liste de cinq éléments pour l'autre option à laquelle la synthétique se réfère. Si une erreur se produit (par exemple, parce que namePtr contient un nom d'option inconnu), NULL est renvoyé et un message d'erreur est laissé dans le résultat de interp, à moins que interp ne soit NULL. Tk_FreeConfigOptions doit être invoqué lorsque la fenêtre est supprimée. Il libère toutes les ressources associées à toute option de configuration définie dans recordPtr par optionTable. La macro Tk_Offset fournit une méthode sûre pour générer les valeurs objOffset et internalOffset pour les entrées dans les structures Tk_OptionSpec. Elle prend deux arguments : le nom d'un type d'enregistrement et le nom d'un champ dans cet enregistrement. Elle renvoie le décalage en octets du champ spécifié dans les enregistrements du type donné. Le champ type indique quel type d'option de configuration il s'agit (par exemple, TK_OPTION_COLOR pour une valeur de couleur, ou TK_OPTION_INT pour une valeur entière). Le type détermine comment la valeur de l'option est analysée (plus de détails ci-dessous). Le champ optionName est une chaîne comme -font ou -bg ; c'est le nom utilisé dans les commandes Tcl et passé aux procédures par les arguments objc ou namePtr. Les champs dbName et dbClass sont utilisés par Tk_InitOptions pour rechercher une valeur par défaut pour cette option dans la base de données d'options ; si dbName est NULL, la base de données d'options n'est pas utilisée par Tk_InitOptions pour cette option. Le champ defValue spécifie une valeur par défaut pour cette option si aucune valeur n'est spécifiée dans la base de données d'options. Les champs objOffset et internalOffset indiquent où la valeur de cette option est stockée dans les enregistrements de la fenêtre (plus de détails ci-dessous) ; les valeurs des champs objOffset et internalOffset doivent toujours être générées avec la macro Tk_Offset. Le champ flags contient des informations supplémentaires pour contrôler le traitement de cette option de configuration (plus de détails dans la section suivante). Le champ clientData fournit des données spécifiques au type nécessaires pour certains types. Par exemple, pour le type TK_OPTION_COLOR, clientData est une chaîne donnant la valeur par défaut pour les monochromes. Pour plus de détails, on peut consulter les descriptions des différents types. Le dernier champ, typeMask, est utilisé par Tk_SetOptions pour renvoyer des informations sur les options modifiées ; on peut consulter la description de Tk_SetOptions pour plus de détails. Lorsque Tk_InitOptions et Tk_SetOptions sauvegardent la valeur d'une option dans l'enregistrement de la fenêtre, ils peuvent le faire de deux manières. Si le champ objOffset de Tk_OptionSpec est supérieur ou égal à zéro, la valeur de l'option est stockée sous forme de (Tcl_Obj *) à l'emplacement de l'enregistrement de la fenêtre donné par objOffset. Si le champ internalOffset de Tk_OptionSpec est supérieur ou égal à zéro, la valeur de l'option est stockée sous une forme interne spécifique au type à l'emplacement de l'enregistrement de la fenêtre donné par internalOffset. Par exemple, si le type d'option est TK_OPTION_INT, la forme interne est un entier. Si le champ objOffset ou internalOffset est négatif, la valeur n'est pas stockée sous cette forme. Au moins un des décalages doit être supérieur ou égal à zéro. Le champ flags consiste en un ou plusieurs bits ORés entre eux. Les flags suivants sont compatibles : - TK_OPTION_NULL_OK Si ce bit est défini pour une option, une chaîne vide est acceptée comme valeur de l'option et la forme interne sera un pointeur NULL, une valeur zéro ou None, selon le type d'option. Si le flag n'est pas défini, une erreur se produira lors de l'utilisation d'une chaîne vide. TK_OPTION_NULL_OK est couramment utilisé pour permettre à une fonctionnalité d'être complètement désactivée, par exemple, définir une valeur de curseur à None pour qu'une fenêtre hérite de son curseur du parent. Tous les types d'options ne supportent pas le flag TK_OPTION_NULL_OK ; pour ceux-ci, il y a une indication explicite dans les descriptions ci-dessous. - TK_OPTION_DONT_SET_DEFAULT Si ce bit est défini pour une option, aucune valeur par défaut ne sera définie par Tk_InitOptions pour cette option. Aucune base de données d'options, aucune valeur par défaut du système, ni optionTable ne seront utilisés pour attribuer une valeur par défaut à cette option. Au lieu de cela, on suppose que l'appelant a déjà fourni une valeur par défaut dans le code du widget. Le champ type de chaque structure Tk_OptionSpec détermine comment la valeur de cette option de configuration est analysée. Les valeurs légales pour type et les actions correspondantes sont décrites ci-dessous. Si le type nécessite une valeur tkwin à passer aux procédures comme Tk_SetOptions, ou s'il utilise le champ clientData de Tk_OptionSpec, c'est indiqué explicitement ; si ce n'est pas mentionné, le type ne nécessite ni tkwin ni clientData. - TK_OPTION_ANCHOR La valeur doit être une position d'ancrage standard comme ne ou center. La forme interne est une valeur Tk_Anchor comme celles renvoyées par Tk_GetAnchorFromObj. - TK_OPTION_BITMAP La valeur doit être un nom de bitmap Tk standard. La forme interne est un jeton Pixmap comme ceux renvoyés par Tk_AllocBitmapFromObj. Ce type d'option nécessite tkwin pour des procédures comme Tk_SetOptions, et supporte le flag TK_OPTION_NULL_OK. - TK_OPTION_BOOLEAN La valeur doit être une valeur booléenne standard comme true ou no. La forme interne est une valeur entière avec la valeur 0 ou 1. Note : si le champ objOffset n'est pas utilisé, l'information sur la valeur originale de cette option sera perdue. - TK_OPTION_BORDER La valeur doit être un nom de couleur standard comme red ou #ff8080. La forme interne est un jeton Tk_3DBorder comme ceux renvoyés par Tk_Alloc3DBorderFromObj. Ce type d'option nécessite tkwin pour des procédures comme Tk_SetOptions, et supporte le flag TK_OPTION_NULL_OK. - TK_OPTION_COLOR La valeur doit être un nom de couleur standard comme red ou #ff8080. standard name de couleur tel que red ou #ff8080. La forme interne est un jeton (XColor *) comme ceux retournés par Tk_AllocColorFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge l'indicateur TK_OPTION_NULL_OK.
TK_OPTION_CURSOR
La valeur doit être un nom de curseur standard tel que cross ou @foo. La forme interne est un jeton Tk_Cursor comme ceux retournés par Tk_AllocCursorFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et lorsque l'option est définie, le curseur de la fenêtre est modifié en appelant XDefineCursor. Ce type d'option prend également en charge l'indicateur TK_OPTION_NULL_OK.
TK_OPTION_CUSTOM
Cette option permet aux applications de définir de nouveaux types d'options. Le champ clientData des points d'entrée pointe vers une structure définissant le nouveau type d'option. Voir la section TYPES D'OPTIONS PERSONNALISÉES ci-dessous pour plus de détails.
TK_OPTION_DOUBLE
La valeur de chaîne doit être un nombre à virgule flottante au format accepté par strtol. La forme interne est une valeur C double. Ce type d'option prend en charge l'indicateur TK_OPTION_NULL_OK ; si une valeur NULL est définie, la représentation interne est définie à zéro.
TK_OPTION_END
Marque la fin du modèle. Il doit y avoir une structure Tk_OptionSpec avec type TK_OPTION_END à la fin de chaque modèle. Si le champ clientData de cette structure n'est pas NULL, il pointe vers un tableau supplémentaire de Tk_OptionSpec, qui est lui-même terminé par une autre entrée TK_OPTION_END. Les modèles peuvent être chaînés à n'importe quelle profondeur. Cette fonctionnalité permet de partager des options communes entre plusieurs classes de widgets.
TK_OPTION_FONT
La valeur doit être un nom de police standard tel que Times 16. La forme interne est un handle Tk_Font comme ceux retournés par Tk_AllocFontFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge l'indicateur TK_OPTION_NULL_OK.
TK_OPTION_INT
La valeur de chaîne doit être un entier au format accepté par strtol (par exemple, les préfixes 0 et 0x peuvent être utilisés pour spécifier respectivement les nombres octaux ou hexadécimaux). La forme interne est une valeur C int.
TK_OPTION_JUSTIFY
La valeur doit être une valeur de justification standard telle que left. La forme interne est un Tk_Justify comme les valeurs retournées par Tk_GetJustifyFromObj.
TK_OPTION_PIXELS
La valeur doit spécifier une distance d'écran telle que 2i ou 6.4. La forme interne est une valeur entière donnant une distance en pixels, comme les valeurs retournées par Tk_GetPixelsFromObj. Notez que si le champ objOffset n'est pas utilisé, les informations sur la valeur d'origine de cette option seront perdues. Voir OBJOFFSET VS. INTERNALOFFSET ci-dessous pour plus de détails. Ce type d'option prend en charge l'indicateur TK_OPTION_NULL_OK ; si une valeur NULL est définie, la représentation interne est définie à INT_MIN.
TK_OPTION_RELIEF
La valeur doit être une valeur de relief standard telle que raised. La forme interne est une valeur entière de relief telle que TK_RELIEF_RAISED. Ce type d'option prend en charge l'indicateur TK_OPTION_NULL_OK ; si une valeur NULL est définie, la représentation interne est définie à TK_RELIEF_NULL.
TK_OPTION_STRING
La valeur peut être n'importe quelle chaîne. La forme interne est un pointeur (char *) qui pointe vers une copie allouée dynamiquement de la valeur. Ce type d'option prend en charge l'indicateur TK_OPTION_NULL_OK.
TK_OPTION_STRING_TABLE
Pour ce type, clientData est un pointeur vers un tableau de chaînes adapté à être passé à Tcl_GetIndexFromObj. La valeur doit être l'une des chaînes du tableau, ou une abréviation unique d'une des chaînes. La forme interne est un entier donnant l'indice dans le tableau de la chaîne correspondante, comme la valeur de retour de Tcl_GetStringFromObj. Ce type d'option prend en charge l'indicateur TK_OPTION_NULL_OK ; si une valeur NULL est définie, la représentation interne est définie à -1.
TK_OPTION_SYNONYM
Ce type est utilisé pour fournir des noms alternatifs à une option (par exemple, -bg est souvent utilisé comme synonyme de -background). Le champ clientData est une chaîne qui donne le nom d'une autre option dans la même table. Chaque fois que l'option synonyme est utilisée, les informations de l'autre option seront utilisées à la place.
TK_OPTION_WINDOW
La valeur doit être un nom de chemin de fenêtre. La forme interne est un jeton Tk_Window pour la fenêtre. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions (afin d'identifier l'application), et il prend en charge l'indicateur TK_OPTION_NULL_OK.

PROBLÈMES DE GESTION DE LA MÉMOIRE

Si un champ d'un enregistrement de widget a son décalage stocké dans le champ objOffset ou internalOffset d'une structure Tk_OptionSpec, les procédures décrites ici géreront toutes les allocations de mémoire et les questions de gestion des ressources associées au champ. Lorsque la valeur d'une option est modifiée, Tk_SetOptions (ou Tk_FreeSavedOptions) libérera automatiquement toutes les ressources associées à l'ancienne valeur, telles que Tk_Fonts pour les options TK_OPTION_FONT ou la mémoire allouée dynamiquement pour les options TK_OPTION_STRING. Pour une option stockée sous forme d'objet à l'aide du champ objOffset d'une Tk_OptionSpec, l'enregistrement du widget partage l'objet pointé par la valeur objv de l'appel à Tk_SetOptions. Le compteur de références de cet objet est incrémenté lorsqu'un pointeur vers celui-ci est stocké dans l'enregistrement du widget et décrémenté lorsque l'option est modifiée. Lorsque le widget est supprimé, Tk_FreeConfigOptions doit être appelé ; il libérera les ressources associées à toutes les options et décrémentera les compteurs de références pour tous les objets.

Cependant, le code du widget est responsable du stockage de NULL ou None dans tous les champs de pointeur et de jeton avant d'appeler Tk_InitOptions. Ceci est nécessaire pour permettre un nettoyage correct dans le cas rare où une erreur se produit dans Tk_InitOptions.

OBJOFFSET VS. INTERNALOFFSET

Dans la plupart des cas, il est plus simple d'utiliser le champ internalOffset d'une structure Tk_OptionSpec et non le champ objOffset. Cela rend la forme interne de la valeur immédiatement disponible pour le code du widget, de sorte que la valeur n'a pas besoin d'être extraite d'un objet à chaque utilisation. Cependant, il existe deux cas où le champ objOffset est utile. Le premier cas concerne les options TK_OPTION_PIXELS. Dans ce cas, la forme interne est une valeur entière en pixels qui n'est valide que pour un écran particulier. Si la valeur de l'option est récupérée, elle sera retournée comme un simple nombre. Par exemple, après la commande .b configure -borderwidth 2m, la commande .b configure -borderwidth pourrait retourner 7, qui est la valeur entière en pixels correspondant à 2m. Malheureusement, cela perd la valeur originale indépendante de l'écran. Ainsi, pour les options TK_OPTION_PIXELS, il est préférable d'utiliser le champ objOffset. Dans ce cas, la valeur d'origine de l'option est conservée dans l'objet et peut être retournée lors de la récupération de l'option. Dans la plupart des cas, il est également pratique d'utiliser le champ internalOffset, afin que la valeur entière soit immédiatement disponible pour utilisation dans le code du widget (alternativement, Tk_GetPixelsFromObj peut être utilisé pour extraire la valeur entière de l'objet chaque fois qu'elle est nécessaire). Notez que le problème de perte d'informations lors des récupérations n'existe que pour les options TK_OPTION_PIXELS.

La deuxième raison d'utiliser le champ objOffset est de mettre en œuvre de nouveaux types d'options non pris en charge par ces procédures. Pour mettre en œuvre un nouveau type d'option, vous pouvez utiliser TK_OPTION_STRING comme type dans la structure Tk_OptionSpec et définir le champ objOffset mais pas le champ internalOffset. Ensuite, après avoir appelé Tk_SetOptions, convertissez l'objet en forme interne vous-même.

Les widgets Ttk ne prennent pas en charge le mécanisme internalOffset. Les valeurs d'options des widgets Ttk sont toujours stockées sous forme de (Tcl_Obj *), ce qui signifie que le champ objOffset doit être utilisé.

TYPES D'OPTIONS PERSONNALISÉES

Les applications peuvent étendre les types de configuration intégrés avec des types de configuration supplémentaires en écrivant des procédures pour analyser, imprimer, libérer et restaurer des copies sauvegardées du type et en créant une structure pointant vers ces procédures :

typedef struct Tk_ObjCustomOption {
    const char *name;
    Tk_CustomOptionSetProc *setProc;
    Tk_CustomOptionGetProc *getProc;
    Tk_CustomOptionRestoreProc *restoreProc;
    Tk_CustomOptionFreeProc *freeProc;
    ClientData clientData;
} Tk_ObjCustomOption;
typedef int Tk_CustomOptionSetProc(
    ClientData clientData,
    Tcl_Interp *interp,
    Tk_Window tkwin,
    Tcl_Obj **valuePtr,
    char *recordPtr,
    int internalOffset,
    char *saveInternalPtr,
    int flags);
typedef Tcl_Obj *Tk_CustomOptionGetProc(
    ClientData clientData,
    Tk_Window tkwin,
    char *recordPtr,
    int internalOffset);
typedef void Tk_CustomOptionRestoreProc(
    ClientData clientData,
    Tk_Window tkwin,
    char *internalPtr,
    char *saveInternalPtr);
typedef void Tk_CustomOptionFreeProc(
    ClientData clientData,
    Tk_Window tkwin,
    char *internalPtr);

La structure Tk_ObjCustomOption contient six champs : un nom pour le type d'option personnalisé ; des pointeurs vers les quatre procédures ; et une valeur clientData à passer à ces procédures lorsqu'elles sont appelées. La valeur clientData

typiquement pointe vers une structure contenant les informations nécessaires aux procédures lors de l'analyse et de l'impression des options. RestoreProc et freeProc peuvent être NULL, indiquant qu'aucune fonction ne doit être appelée pour ces opérations.

La procédure setProc est appelée par Tk_SetOptions pour convertir un Tcl_Obj en une représentation interne et stocker la valeur résultante dans l'enregistrement du widget. Les arguments sont :

clientData
Une copie du champ clientData dans la structure Tk_ObjCustomOption.
interp
Un pointeur vers un interpréteur Tcl, utilisé pour le signalement d'erreurs.
Tkwin
Une copie de l'argument tkwin à Tk_SetOptions
valuePtr
Un pointeur vers une référence à un Tcl_Obj décrivant la nouvelle valeur de l'option ; elle pourrait avoir été spécifiée explicitement dans l'appel à Tk_SetOptions ou provenir de la base de données des options ou d'une valeur par défaut. Si le objOffset pour l'option est non négatif (la valeur de l'option est stockée sous forme de (Tcl_Obj *) dans l'enregistrement du widget), le pointeur Tcl_Obj référencé par valuePtr est le pointeur qui sera stocké à l'objOffset pour l'option. SetProc peut modifier la valeur si nécessaire ; par exemple, setProc peut changer la valeur à NULL pour supporter le drapeau TK_OPTION_NULL_OK.
recordPtr
Un pointeur vers le début de l'enregistrement du widget à modifier.
internalOffset
Décalage en octets depuis le début de l'enregistrement du widget jusqu'à l'emplacement où la représentation interne de la valeur de l'option doit être placée.
saveInternalPtr
Un pointeur vers le stockage alloué dans une structure Tk_SavedOptions pour la représentation interne de la valeur de l'option d'origine. Avant de définir l'option à sa nouvelle valeur, setProc doit définir la valeur référencée par saveInternalPtr à la valeur d'origine de l'option afin de supporter Tk_RestoreSavedOptions.
flags
Une copie du champ flags dans la structure Tk_OptionSpec pour l'option.

SetProc renvoie un résultat Tcl standard : TCL_OK pour indiquer un traitement réussi, ou TCL_ERROR pour indiquer un échec de quelque nature que ce soit. Un message d'erreur peut être laissé dans l'interpréteur Tcl fourni par interp en cas d'erreur.

La procédure getProc est appelée par Tk_GetOptionValue et Tk_GetOptionInfo pour récupérer une représentation Tcl_Obj de la représentation interne d'une option. L'argument clientData est une copie du champ clientData dans la structure Tk_ObjCustomOption. Tkwin est une copie de l'argument tkwin à Tk_GetOptionValue ou Tk_GetOptionInfo. RecordPtr est un pointeur vers le début de l'enregistrement du widget à interroger. InternalOffset est le décalage en octets depuis le début de l'enregistrement du widget jusqu'à l'emplacement où la représentation interne de la valeur de l'option est stockée. GetProc doit renvoyer un pointeur vers un Tcl_Obj représentant la valeur de l'option.

La procédure restoreProc est appelée par Tk_RestoreSavedOptions pour restaurer une représentation interne précédemment sauvegardée d'une valeur d'option personnalisée. L'argument clientData est une copie du champ clientData dans la structure Tk_ObjCustomOption. Tkwin est une copie de l'argument tkwin à Tk_GetOptionValue ou Tk_GetOptionInfo. InternalPtr est un pointeur vers l'emplacement où la représentation interne de la valeur de l'option est stockée. SaveInternalPtr est un pointeur vers la valeur sauvegardée. RestoreProc doit copier la valeur de saveInternalPtr à internalPtr pour restaurer la valeur. RestoreProc n'a pas besoin de libérer de mémoire associée à internalPtr ou saveInternalPtr ; freeProc sera appelée pour libérer cette mémoire si nécessaire. RestoreProc n'a pas de valeur de retour.

La procédure freeProc est appelée par Tk_SetOptions et Tk_FreeSavedOptions pour libérer tout stockage alloué pour la représentation interne d'une option personnalisée. L'argument clientData est une copie du champ clientData dans la structure Tk_ObjCustomOption. Tkwin est une copie de l'argument tkwin à Tk_GetOptionValue ou Tk_GetOptionInfo. InternalPtr est un pointeur vers l'emplacement où la représentation interne de la valeur de l'option est stockée. Le freeProc doit libérer tout stockage associé à l'option. FreeProc n'a pas de valeur de retour.
