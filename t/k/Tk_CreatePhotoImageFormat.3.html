Tk_CreatePhotoImageFormat(3) Procédures de la bibliothèque Tk Tk_CreatePhotoImageFormat(3)

NOM

Tk_CreatePhotoImageFormat - définir un nouveau format de fichier pour les images photo

SYNOPIS

#include <tk.h>

Tk_CreatePhotoImageFormat(formatPtr)

ARGUMENTS

const Tk_PhotoImageFormat *formatPtr (entrée)
Structure définissant le nouveau format de fichier.

DESCRIPTION

Tk_CreatePhotoImageFormat est appelée pour définir un nouveau format de fichier pour les données d'image à utiliser avec les images photo. Le code qui implémente un format de fichier image est appelé un gestionnaire de format de fichier image, ou gestionnaire pour faire court. Le code de l'image photo maintient une liste de gestionnaires qui peuvent être utilisés pour lire et écrire des données depuis ou vers un fichier. Certains gestionnaires peuvent également prendre en charge la lecture de données d'image à partir d'une chaîne ou la conversion de données d'image vers un format de chaîne. L'utilisateur peut spécifier quel gestionnaire utiliser avec l'option de configuration d'image -format ou l'option -format des sous-commandes read et write de l'image photo.

Un gestionnaire de format de fichier image se compose d'une collection de procédures plus une structure Tk_PhotoImageFormat, qui contient le nom du format de fichier image et des pointeurs vers six procédures fournies par le gestionnaire pour traiter les fichiers et les chaînes dans ce format. La structure Tk_PhotoImageFormat contient les champs suivants :

typedef struct Tk_PhotoImageFormat {
    const char *name;
    Tk_ImageFileMatchProc *fileMatchProc;
    Tk_ImageStringMatchProc *stringMatchProc;
    Tk_ImageFileReadProc *fileReadProc;
    Tk_ImageStringReadProc *stringReadProc;
    Tk_ImageFileWriteProc *fileWriteProc;
    Tk_ImageStringWriteProc *stringWriteProc;
} Tk_PhotoImageFormat;

Le gestionnaire n'a pas besoin de fournir des implémentations des six procédures. Par exemple, les procédures qui gèrent les données de chaîne ne seraient pas fournies pour un format dans lequel les données d'image sont stockées en binaire, et pourraient donc contenir des caractères nuls. Si une procédure n'est pas implémentée, le pointeur correspondant dans la structure Tk_PhotoImageFormat doit être défini sur NULL. Le gestionnaire doit fournir la procédure fileMatchProc s'il fournit la procédure fileReadProc, et la procédure stringMatchProc s'il fournit la procédure stringReadProc.

NOM

formatPtr->name fournit un nom pour le type d'image. Une fois que Tk_CreatePhotoImageFormat est retournée, ce nom peut être utilisé dans l'option de configuration et de sous-commande d'image photo -format. La page de manuel de l'image photo (photo(n)) décrit comment les formats de fichiers image sont choisis en fonction de leurs noms et de la valeur donnée à l'option -format. Le premier caractère de formatPtr->name ne doit pas être une lettre majuscule de l'ensemble de caractères ASCII (c'est-à-dire l'un des caractères A-Z). De tels noms sont utilisés uniquement pour le support de l'interface héritée (voir ci-dessous).

FILEMATCHPROC

formatPtr->fileMatchProc fournit l'adresse d'une procédure que Tk appellera lorsqu'elle recherche un gestionnaire de format de fichier image approprié pour lire des données d'un fichier donné. formatPtr->fileMatchProc doit correspondre au prototype suivant :

typedef int Tk_ImageFileMatchProc(
        Tcl_Channel chan,
        const char *fileName,
        Tcl_Obj *format,
        int *widthPtr,
        int *heightPtr,
        Tcl_Interp *interp);
L'argument fileName est le nom du fichier contenant les données de l'image, qui est ouvert en lecture comme chan. L'argument format contient la valeur donnée pour l'option -format, ou NULL si l'option n'a pas été spécifiée. Si les données dans le fichier semblent être dans le format pris en charge par ce gestionnaire, la procédure formatPtr->fileMatchProc doit stocker la largeur et la hauteur de l'image dans *widthPtr et *heightPtr respectivement, et retourner 1. Sinon, elle doit retourner 0.

STRINGMATCHPROC

formatPtr->stringMatchProc fournit l'adresse d'une procédure que Tk appellera lorsqu'elle recherche un gestionnaire de format de fichier image approprié pour lire des données à partir d'une chaîne donnée. formatPtr->stringMatchProc doit correspondre au prototype suivant :

typedef int Tk_ImageStringMatchProc(
        Tcl_Obj *data,
        Tcl_Obj *format,
        int *widthPtr,
        int *heightPtr,
        Tcl_Interp *interp);
L'argument data pointe vers l'objet contenant les données de l'image. L'argument format contient la valeur donnée pour l'option -format, ou NULL si l'option n'a pas été spécifiée. Si les données dans la chaîne semblent être dans le format pris en charge par ce gestionnaire, la procédure formatPtr->stringMatchProc doit stocker la largeur et la hauteur de l'image dans *widthPtr et *heightPtr respectivement, et retourner 1. Sinon, elle doit retourner 0.

FILEREADPROC

formatPtr->fileReadProc fournit l'adresse d'une procédure que Tk appellera pour lire des données à partir d'un fichier image dans une image photo. formatPtr->fileReadProc doit correspondre au prototype suivant :

typedef int Tk_ImageFileReadProc(
        Tcl_Interp *interp,
        Tcl_Channel chan,
        const char *fileName,
        Tcl_Obj *format,
        PhotoHandle imageHandle,
        int destX, int destY,
        int width, int height,
        int srcX, int srcY);
L'argument interp est l'interpréteur dans lequel la commande a été invoquée pour lire l'image ; il doit être utilisé pour signaler les erreurs. Les données de l'image se trouvent dans le fichier nommé fileName, qui est ouvert en lecture comme chan. L'argument format contient la valeur donnée pour l'option -format, ou NULL si l'option n'a pas été spécifiée. Les données de l'image dans le fichier, ou une sous-image de celle-ci, doivent être lues dans l'image photo identifiée par le handle imageHandle. La sous-image des données dans le fichier a les dimensions width x height et a son coin supérieur gauche aux coordonnées (srcX,srcY). Elle doit être stockée dans l'image photo avec son coin supérieur gauche aux coordonnées (destX,destY) en utilisant la procédure Tk_PhotoPutBlock. La valeur de retour est une valeur de retour Tcl standard.

STRINGREADPROC

formatPtr->stringReadProc fournit l'adresse d'une procédure que Tk appellera pour lire des données à partir d'une chaîne dans une image photo. formatPtr->stringReadProc doit correspondre au prototype suivant :

typedef int Tk_ImageStringReadProc(
        Tcl_Interp *interp,
        Tcl_Obj *data,
        Tcl_Obj *format,
        PhotoHandle imageHandle,
        int destX, int destY,
        int width, int height,
        int srcX, int srcY);
L'argument interp est l'interpréteur dans lequel la commande a été invoquée pour lire l'image ; il doit être utilisé pour signaler les erreurs. L'argument data pointe vers les données de l'image sous forme d'objet. L'argument format contient la valeur donnée pour l'option -format, ou NULL si l'option n'a pas été spécifiée. Les données de l'image dans la chaîne, ou une sous-image de celle-ci, doivent être lues dans l'image photo identifiée par le handle imageHandle. La sous-image des données dans la chaîne a les dimensions width x height et a son coin supérieur gauche aux coordonnées (srcX,srcY). Elle doit être stockée dans l'image photo avec son coin supérieur gauche aux coordonnées (destX,destY) en utilisant la procédure Tk_PhotoPutBlock. La valeur de retour est une valeur de retour Tcl standard.

FILEWRITEPROC

formatPtr->fileWriteProc fournit l'adresse d'une procédure que Tk appellera pour écrire des données d'une image photo vers un fichier. formatPtr->fileWriteProc doit correspondre au prototype suivant :

typedef int Tk_ImageFileWriteProc(
        Tcl_Interp *interp,
        const char *fileName,
        Tcl_Obj *format,
        Tk_PhotoImageBlock *blockPtr);

Les données de l'image à écrire sont en mémoire et sont décrites par la structure Tk_PhotoImageBlock pointée par blockPtr ; voir la page man FindPhoto(3) pour plus de détails. STRINGWRITEPROC

formatPtr->stringWriteProc fournit l'adresse d'une procédure que Tk doit appeler pour traduire les données d'une image photo en une chaîne. formatPtr->stringWriteProc doit correspondre au prototype suivant :

typedef int Tk_ImageStringWriteProc(
        Tcl_Interp *interp,
        Tcl_Obj *format,
        Tk_PhotoImageBlock *blockPtr);
L'argument interp est l'interpréteur dans lequel la commande a été invoquée pour convertir l'image ; il doit être utilisé pour signaler les erreurs. Les données de l'image à convertir sont en mémoire et sont décrites par la structure Tk_PhotoImageBlock pointée par blockPtr ; voir la page man FindPhoto(3) pour plus de détails. Les données pour la chaîne doivent être placées dans le résultat de l'interpréteur interp. L'argument format contient la valeur donnée pour l'option -format, ou NULL si l'option n'a pas été spécifiée. La chaîne de format peut contenir des caractères supplémentaires après le nom du format. Si cela est approprié, la procédure formatPtr->stringWriteProc peut interpréter ces caractères pour spécifier des détails supplémentaires sur le fichier image. La valeur de retour est une valeur de retour Tcl standard.

SUPPORT DES INTERFACES OBSOLÈTES

Dans Tk 8.2 et versions antérieures, la définition de tous les types de pointeurs de fonction stockés dans les champs d'une structure Tk_PhotoImageFormat était incompatible. Les programmes et bibliothèques hérités de cette époque peuvent encore contenir du code qui définit des formats d'image photo Tk étendus en utilisant l'ancienne interface. Le fichier d'en-tête Tk supportera toujours cette ancienne interface si le code est compilé avec la macro USE_OLD_IMAGE définie. Alternativement, les anciennes interfaces sont utilisées si le premier caractère de formatPtr->name est une lettre ASCII majuscule (A-Z), et que des conversions explicites sont utilisées pour ignorer l'inadéquation de type. Par exemple,

static Tk_PhotoImageFormat myFormat = {
    "MyFormat",
    (Tk_ImageFileMatchProc *) FileMatch,
    NULL,
    (Tk_ImageFileReadProc *) FileRead,
    NULL,
    NULL,
    NULL
};
définirait un Tk_PhotoImageFormat minimal qui ne fournit que des capacités de lecture de fichiers, où FileMatch et FileRead sont écrits selon les anciennes interfaces de Tk 8.2 ou antérieures.

Toute extension activée par des stubs fournissant un format d'image photo étendu via l'ancienne interface activée par la macro USE_OLD_IMAGE qui est compilée avec les en-têtes Tk 8.5 et liée à la bibliothèque de stubs Tk 8.5 produira un fichier qui ne peut être chargé que dans des interpréteurs Tk 8.5 ou plus récents ; c'est-à-dire les règles normales de compatibilité des stubs. Si un développeur a besoin de générer à partir d'un tel code un fichier chargeable dans des interpréteurs Tk 8.4 ou antérieurs, il doit utiliser les en-têtes et les bibliothèques de stubs Tk 8.4 pour ce faire.

Tout nouveau code écrit aujourd'hui ne devrait pas utiliser les anciennes interfaces. Attendez-vous à ce que leur support disparaisse dans Tk 9.
