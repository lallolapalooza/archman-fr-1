NOM

Tk::palette - Modifier la palette de couleurs Tk

SYNTAXE

$widget->setPalette(couleur_fond)

$widget->setPalette(nom=>valeur?,nom=>valeur ...?)

$widget->bisque

DESCRIPTION

La méthode setPalette change le schéma de couleurs pour Tk. Elle fait cela en modifiant les couleurs des widgets existants et en changeant la base de données d'options afin que les futurs widgets utilisent le nouveau schéma de couleurs. Si setPalette est appelée avec un seul argument, l'argument est le nom d'une couleur à utiliser comme couleur de fond normale ; setPalette calculera une palette de couleurs complète à partir de cette couleur de fond. Alternativement, les arguments de setPalette peuvent consister en n'importe quel nombre de paires nom-valeur, où le premier argument de la paire est le nom d'une option dans la base de données d'options Tk et le second argument est la nouvelle valeur à utiliser pour cette option. Les noms de base de données suivants sont actuellement pris en charge :

activeBackground       foreground      selectColor
activeForeground       highlightBackground     selectBackground
background     highlightColor  selectForeground
disabledForeground     insertBackground        troughColor

setPalette essaie de calculer des valeurs par défaut raisonnables pour toutes les options que vous ne spécifiez pas. Vous pouvez spécifier des options autres que celles ci-dessus et Tk modifiera également ces options sur les widgets. Cette fonctionnalité peut être utile si vous utilisez des widgets personnalisés avec des options de couleur supplémentaires.

Une fois qu'elle a calculé la nouvelle valeur à utiliser pour chacune des options de couleur, setPalette parcourt la hiérarchie des widgets pour modifier les options de tous les widgets existants. Pour chaque widget, elle vérifie si l'une des options ci-dessus est définie pour le widget. Si c'est le cas, et si la valeur actuelle de l'option est la valeur par défaut, alors la valeur est changée ; si l'option a une valeur autre que la valeur par défaut, setPalette ne la modifiera pas. La valeur par défaut d'une option est celle fournie par le widget (($w->configure('option'))[3]) sauf si setPalette a été exécutée précédemment, auquel cas c'est la valeur spécifiée dans l'invocation précédente de setPalette.

Après avoir modifié tous les widgets de l'application, setPalette ajoute des options à la base de données d'options pour changer les valeurs par défaut des widgets créés à l'avenir. Les nouvelles options sont ajoutées à la priorité widgetDefault, de sorte qu'elles seront remplacées par les options du fichier .Xdefaults ou par les options spécifiées sur la ligne de commande qui crée un widget.

La méthode bisque est fournie pour la compatibilité ascendante : elle restaure les couleurs de l'application au schéma de couleurs brun clair (``bisque'') utilisé dans Tk 3.6 et les versions antérieures.

BOGUES

L'utilisation des noms de la base de données d'options plutôt que des noms de configuration est compréhensible compte tenu du mécanisme (copié de Tcl/Tk), mais est potentiellement déroutante.

L'interpolation de différentes 'teintes' de couleur utilisées pour les effets 3D dans l'espace 'RGB' peut entraîner des changements indésirables dans la 'teinte'. L'interpolation dans 'HSV' (telle qu'utilisée dans Tk::ColorEditor) serait plus robuste et le support des couleurs de X11R5 encore plus.
