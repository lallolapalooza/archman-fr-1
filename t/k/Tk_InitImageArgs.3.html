Tk_CreateImageType(3) Procédures de la bibliothèque Tk Tk_CreateImageType(3)

NOM

Tk_CreateImageType, Tk_GetImageMasterData, Tk_GetImageModelData, Tk_InitImageArgs - définir un nouveau type d'image

SYNTAXE

#include <tk.h>

Tk_CreateImageType(typePtr)

ClientData
Tk_GetImageMasterData(interp, name, typePtrPtr)

ClientData
Tk_GetImageModelData(interp, name, typePtrPtr)

Tk_InitImageArgs(interp, argc, argvPtr)

ARGUMENTS

const Tk_ImageType *typePtr (in)
Structure définissant le nouveau type d'image. Pour Tk 8.4 et versions antérieures, cela doit être statique : un pointeur vers cette structure est conservé par le code de l'image. Dans Tk 8.5, cette limitation a été assouplie.
Tcl_Interp *interp (in)
Interpréteur dans lequel l'image a été créée.
const char *name (in)
Nom de l'image existante.
Tk_ImageType **typePtrPtr (out)
Pointe vers un mot dans lequel stocker un pointeur vers les informations de type pour l'image donnée, si elle existe.
int argc (in)
Nombre d'arguments
char ***argvPtr (in/out)
Pointeur vers la liste d'arguments

DESCRIPTION

Tk_CreateImageType est appelée pour définir un nouveau type d'image. Un type d'image correspond à une valeur particulière de l'argument type pour la commande image create. Il peut exister un nombre quelconque de types d'images différents, et de nouveaux types peuvent être définis dynamiquement en appelant Tk_CreateImageType. Par exemple, il pourrait y avoir un type pour les bitmaps 2 couleurs, un autre pour les images multicolores, un autre pour les images tramées, un autre pour la vidéo, et ainsi de suite.

Le code qui implémente un nouveau type d'image est appelé un gestionnaire d'images. Il se compose d'une collection de procédures plus trois types différents de structures de données. La première structure de données est une structure Tk_ImageType, qui contient le nom du type d'image et des pointeurs vers cinq procédures fournies par le gestionnaire d'images pour gérer les images de ce type :

typedef struct Tk_ImageType {
    const char *name;
    Tk_ImageCreateProc *createProc;
    Tk_ImageGetProc *getProc;
    Tk_ImageDisplayProc *displayProc;
    Tk_ImageFreeProc *freeProc;
    Tk_ImageDeleteProc *deleteProc;
} Tk_ImageType;
Les champs de cette structure seront décrits dans des sous-sections ultérieures de cette entrée.

La deuxième structure de données majeure manipulée par un gestionnaire d'images est appelée un modèle d'image ; elle contient des informations globales sur une image particulière, telles que les valeurs des options de configuration spécifiées dans une commande image create. Il y aura généralement une de ces structures pour chaque invocation de la commande image create.

La troisième structure de données liée aux images est une instance d'image. Il y aura généralement une de ces structures pour chaque utilisation d'une image dans un widget particulier. Il est possible qu'une seule image apparaisse simultanément dans plusieurs widgets, voire plusieurs fois dans le même widget. De plus, différentes instances peuvent être sur des écrans ou des affichages différents. La structure de données de l'instance d'image décrit les éléments qui peuvent varier d'une instance à l'autre, tels que les couleurs et les contextes graphiques pour le redessin. Il y a généralement une structure d'instance pour chaque option -image spécifiée pour un widget ou un élément de canevas.

Les sous-sections suivantes décrivent plus en détail les champs d'une Tk_ImageType.

NOM

typePtr->name fournit un nom pour le type d'image. Une fois que Tk_CreateImageType est revenue, ce nom peut être utilisé dans les commandes image create pour créer des images du nouveau type. S'il existait déjà un type d'image portant ce nom, le nouveau type d'image remplace l'ancien.

CREATEPROC

typePtr->createProc fournit l'adresse d'une procédure que Tk appellera chaque fois que image create est invoquée pour créer une image du nouveau type. typePtr->createProc doit correspondre au prototype suivant :

typedef int Tk_ImageCreateProc(
        Tcl_Interp *interp,
        const char *name,
        int objc,
        Tcl_Obj *const objv[],
        const Tk_ImageType *typePtr,
        Tk_ImageMaster model,
        ClientData *modelDataPtr);
L'argument interp est l'interpréteur dans lequel la commande image a été invoquée, et name est le nom de la nouvelle image, qui a été soit spécifié explicitement dans la commande image, soit généré automatiquement par la commande image. Les arguments objc et objv décrivent toutes les options de configuration pour la nouvelle image (tout ce qui suit l'argument de nom de image). L'argument model est un jeton qui fait référence aux informations de Tk sur cette image ; le gestionnaire d'images doit renvoyer ce jeton à Tk lors de l'invocation de la procédure Tk_ImageChanged. Généralement, createProc analysera objc et objv et créera une structure de données modèle d'image pour la nouvelle image. createProc peut stocker une valeur arbitraire d'un seul mot à *modelDataPtr, qui sera renvoyée au gestionnaire d'images lors de l'invocation d'autres callbacks. Généralement, la valeur est un pointeur vers la structure de données modèle pour l'image.

Si createProc rencontre une erreur, elle doit laisser un message d'erreur dans le résultat de l'interpréteur et renvoyer TCL_ERROR ; sinon, elle doit renvoyer TCL_OK.

createProc doit appeler Tk_ImageChanged afin de définir la taille de l'image et de demander un redessin initial.

GETPROC

typePtr->getProc est appelée par Tk chaque fois qu'un widget appelle Tk_GetImage pour utiliser une image particulière. Cette procédure doit correspondre au prototype suivant :

typedef ClientData Tk_ImageGetProc(
        Tk_Window tkwin,
        ClientData modelData);
L'argument tkwin identifie la fenêtre dans laquelle l'image sera utilisée et modelData est la valeur renvoyée par createProc lors de la création du modèle d'image. getProc créera généralement une structure de données pour la nouvelle instance, y compris les ressources nécessaires pour afficher l'image dans la fenêtre donnée. getProc renvoie un jeton d'un mot pour l'instance, qui est généralement l'adresse de la structure de données d'instance. Tk renverra cette valeur au gestionnaire d'images lors de l'invocation de ses procédures displayProc et freeProc.

DISPLAYPROC

typePtr->displayProc est appelée par Tk chaque fois qu'une image doit être affichée (c'est-à-dire chaque fois qu'un widget appelle Tk_RedrawImage). displayProc doit correspondre au prototype suivant :

typedef void Tk_ImageDisplayProc(
        ClientData instanceData,
        Display *display,
        Drawable drawable,
        int imageX,
        int imageY,
        int width,
        int height,
        int drawableX,
        int drawableY);
L'argument instanceData sera identique à la valeur renvoyée par getProc lors de la création de l'instance. display et drawable indiquent où afficher l'image ; drawable peut être un pixmap plutôt que la fenêtre spécifiée à getProc (c'est généralement le cas, car la plupart des widgets utilisent le double buffering pour leurs redessins afin d'obtenir des effets visuels plus fluides). imageX, imageY, width et height identifient la région de l'image qui doit être redessinée. Cette région sera toujours dans les limites de la taille de l'image telle que spécifiée dans le dernier appel à Tk_ImageChanged. drawableX et drawableY indiquent où dans drawable l'image doit être affichée ; displayProc doit afficher la région donnée de l'image de manière à ce que le point (imageX, imageY) dans l'image apparaisse à (drawableX, drawableY) dans drawable.

FREEPROC

typePtr->freeProc contient l'adresse d'une procédure que Tk appellera lorsque l'instance d'une image sera libérée (c'est-à-dire lorsque Tk_FreeImage sera appelée). Cela peut se produire, par exemple, lorsqu'un widget est supprimé ou qu'un élément d'image dans un canevas est supprimé, ou lorsque l'image affichée dans un widget ou un élément de canevas est modifiée. freeProc doit correspondre au prototype suivant :

typedef void Tk_ImageFreeProc(
        ClientData instanceData,
        Display *display);
L'argument instanceData sera identique à la valeur renvoyée par getProc lors de la création de l'instance. display est l'affichage X sur lequel l'image était utilisée. La procédure freeProc est responsable de la libération de toutes les ressources spécifiques à l'instance qui ont été allouées par getProc ou par displayProc.

DELETEPROC

typePtr->deleteProc contient l'adresse d'une procédure que Tk appellera lorsque le modèle d'une image est supprimé (c'est-à-dire lorsque la commande image delete est invoquée ou lorsque l'interpréteur est détruit). deleteProc doit correspondre au prototype suivant :

typedef void Tk_ImageDeleteProc(
        Tcl_Interp *interp,
        ClientData modelData);
L'argument modelData est la valeur qui a été écrite dans *modelDataPtr par le createProc de ce type. La procédure deleteProc est responsable de la libération de toutes les ressources spécifiques au modèle qui ont été allouées par createProc.

TK_GETIMAGEMASTERDATA

Cette procédure est utilisée pour obtenir les données maître d'une image existante. Elle est généralement appelée par un gestionnaire d'images pour récupérer les informations sur une image lorsqu'elle est utilisée. Elle retourne les données maître de l'image ou NULL si l'image n'est pas trouvée. Elle remplit également typePtrPtr avec un pointeur vers la structure Tk_ImageType de l'image.

TK_GETIMAGEMODELDATA

Similaire à Tk_GetImageMasterData, mais récupère les données du modèle de l'image. Elle est généralement appelée par Tk pour obtenir des informations sur une image.

TK_INITIMAGEARGS

Cette procédure est un utilitaire pour aider les gestionnaires d'images à analyser les arguments passés à la commande image create. Elle effectue des analyses de base sur les arguments et peut être utilisée pour simplifier le traitement des options dans le createProc.

VOIR AUSSI

Tk_DefineImage(3), Tk_ImageChanged(3), Tk_GetImage(3), Tk_FreeImage(3)

MOTS-CLÉS

image, type d'image, gestionnaire d'images, Tk

pedef void Tk_ImageFreeProc( ClientData instanceData, Display *display); Le paramètre instanceData sera identique à la valeur retournée par getProc lors de la création de l'instance, et display est l'affichage contenant la fenêtre de l'instance. freeProc doit libérer toutes les ressources associées à l'instance de l'image, car l'instance ne sera plus jamais utilisée.

DELETEPROC

typePtr->deleteProc est une procédure que Tk invoque lorsqu'une image est supprimée (c'est-à-dire lorsque la commande image delete est invoquée). Avant d'invoquer deleteProc, Tk invoquera freeProc pour chacune des instances de l'image. deleteProc doit correspondre au prototype suivant :

typedef void Tk_ImageDeleteProc(
        ClientData modelData);
Le paramètre modelData sera identique à la valeur stockée dans *modelDataPtr par createProc lors de la création de l'image. deleteProc doit libérer toutes les ressources associées à l'image.

TK_GETIMAGEMODELDATA

La procédure Tk_GetImageMasterData peut être invoquée pour récupérer des informations sur une image. Par exemple, un gestionnaire d'images peut utiliser cette procédure pour localiser ses données de modèle d'image pour une image. S'il existe une image nommée name dans l'interpréteur donné par interp, alors *typePtrPtr est rempli avec les informations de type de l'image (la valeur typePtr passée à Tk_CreateImageType lors de l'enregistrement du type d'image) et la valeur de retour est la valeur ClientData retournée par createProc lors de la création de l'image (il s'agit généralement d'un pointeur vers la structure de données du modèle d'image). Si une telle image n'existe pas, NULL est retourné et NULL est stocké à *typePtrPtr.

Tk_GetImageModelData est un synonyme de Tk_GetImageMasterData.

LEGACY INTERFACE SUPPORT

Dans Tk 8.2 et versions antérieures, la définition de Tk_ImageCreateProc était incompatible, avec le prototype suivant :

typedef int Tk_ImageCreateProc(
        Tcl_Interp *interp,
        char *name,
        int argc,
        char **argv,
        Tk_ImageType *typePtr,
        Tk_ImageMaster model,
        ClientData *modelDataPtr);
Les programmes et bibliothèques hérités datant de cette époque peuvent encore contenir du code qui définit des types d'images Tk étendus en utilisant l'ancienne interface. Le fichier d'en-tête Tk supportera toujours cette interface héritée si le code est compilé avec le macro USE_OLD_IMAGE défini.

Tk_ImageModel est un synonyme de Tk_ImageMaster.

Lorsque le support hérité USE_OLD_IMAGE est activé, vous pouvez voir la routine Tk_InitImageArgs en cours d'utilisation. Il s'agissait d'un outil de migration utilisé pour créer des extensions prenant en charge les stubs qui pouvaient être chargées dans des interpréteurs contenant toutes les versions de Tk 8.1 et ultérieures. Tk 8.5 ne fournit plus cette routine, mais utilise une macro pour convertir toute tentative d'appel de cette routine en un commentaire vide. Toute extension prenant en charge les stubs fournissant un type d'image étendu via l'interface héritée, compilée avec les en-têtes Tk 8.5 et liée à la bibliothèque de stubs Tk 8.5, produira un fichier qui ne pourra être chargé que dans des interpréteurs avec Tk 8.5 ou ultérieur ; c'est-à-dire les règles normales de compatibilité des stubs. Si un développeur a besoin de générer à partir d'un tel code un fichier chargeable dans des interpréteurs avec Tk 8.4 ou antérieur, il doit utiliser les en-têtes et les bibliothèques de stubs Tk 8.4 pour ce faire.

Tout nouveau code écrit aujourd'hui ne devrait pas utiliser les interfaces héritées. Leur support devrait disparaître dans Tk 9.
