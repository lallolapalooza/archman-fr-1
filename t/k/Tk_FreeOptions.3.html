Tk_ConfigureWidget(3) Procédures de la bibliothèque Tk Tk_ConfigureWidget(3)

NOM

Tk_ConfigureWidget, Tk_ConfigureInfo, Tk_ConfigureValue, Tk_FreeOptions - traiter les options de configuration pour les widgets

SYNTAXE

#include <tk.h>

int
Tk_ConfigureWidget(interp, tkwin, specs, argc, argv, widgRec, flags)

int
Tk_ConfigureInfo(interp, tkwin, specs, widgRec, argvName, flags)

int
Tk_ConfigureValue(interp, tkwin, specs, widgRec, argvName, flags)

Tk_FreeOptions(specs, widgRec, display, flags)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur à utiliser pour retourner les messages d'erreur.
Tk_Window tkwin (in)
Fenêtre utilisée pour représenter le widget (nécessaire pour configurer les ressources X).
const Tk_ConfigSpec *specs (in)
Pointeur vers la table spécifiant les options de configuration légales pour ce widget.
int argc (in)
Nombre d'arguments dans argv.
const char **argv (in)
Options en ligne de commande pour configurer le widget.
char *widgRec (in/out)
Pointe vers la structure d'enregistrement du widget. Les champs de cette structure sont modifiés par Tk_ConfigureWidget pour contenir les informations de configuration.
int flags (in)
Si non nul, il spécifie une combinaison OR de drapeaux qui contrôlent le traitement des informations de configuration. TK_CONFIG_ARGV_ONLY fait ignorer la base de données d'options et les valeurs par défaut, et les bits de drapeau TK_CONFIG_USER_BIT et supérieurs sont utilisés pour désactiver sélectivement les entrées dans specs.
type name type (in)
Le nom du type d'un enregistrement de widget.
field name field (in)
Le nom d'un champ dans les enregistrements de type type.
const char *argvName (in)
Le nom utilisé sur les lignes de commande Tcl pour faire référence à une option particulière (par exemple lors de la création d'un widget ou de l'invocation de la commande configure d'un widget). Si non NULL, alors les informations sont retournées uniquement pour cette option. Si NULL, alors les informations sont retournées pour toutes les options disponibles.
Display *display (in)
Affichage contenant le widget dont l'enregistrement est libéré ; nécessaire pour libérer les ressources.

DESCRIPTION

Note : Tk_ConfigureWidget devrait être remplacé par la nouvelle API basée sur Tcl_Obj, Tk_SetOptions. L'ancienne interface est conservée pour des raisons de compatibilité ascendante.

Tk_ConfigureWidget est appelée pour configurer divers aspects d'un widget, tels que les couleurs, les polices, la largeur de bordure, etc. Elle est conçue comme une procédure de commodité pour réduire la quantité de code qui doit être écrite dans les gestionnaires de widgets individuels pour traiter les informations de configuration. Elle est généralement invoquée lors de la création des widgets, et à nouveau lorsque la commande configure est invoquée pour un widget. Bien qu'elle soit principalement destinée aux widgets, Tk_ConfigureWidget peut être utilisée dans d'autres situations où des informations argc-argv doivent être utilisées pour remplir une structure d'enregistrement, comme la configuration d'éléments graphiques pour un widget canvas ou d'entrées d'un menu.

Tk_ConfigureWidget traite une table spécifiant les options de configuration qui sont supportées (specs) et une collection d'arguments en ligne de commande (argc et argv) pour remplir les champs d'un enregistrement (widgRec). Elle utilise la base de données d'options et les valeurs par défaut spécifiées dans specs pour remplir les champs de widgRec qui ne sont pas spécifiés dans argv. Tk_ConfigureWidget retourne normalement la valeur TCL_OK ; dans ce cas, elle ne modifie pas interp. Si une erreur se produit, TCL_ERROR est retournée et Tk_ConfigureWidget laissera un message d'erreur dans le résultat de l'interpréteur interp de la manière standard de Tcl. En cas de retour d'erreur, certains des champs de widgRec pourraient déjà avoir été définis, si les informations de configuration les concernant ont été traitées avec succès avant que l'erreur ne se produise. Les autres champs seront définis à des valeurs initiales raisonnables afin que Tk_FreeOptions puisse être appelée pour le nettoyage.

Le tableau specs spécifie les types d'options de configuration attendues par le widget. Chacune de ses entrées spécifie une option de configuration et a la structure suivante :

typedef struct {
    int type;
    const char *argvName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int offset;
    int specFlags;
    const Tk_CustomOption *customPtr;
} Tk_ConfigSpec;
Le champ type indique de quel type d'option de configuration il s'agit (par exemple TK_CONFIG_COLOR pour une valeur de couleur, ou TK_CONFIG_INT pour une valeur entière). Le champ type indique comment utiliser la valeur de l'option (plus à ce sujet ci-dessous). Le champ argvName est une chaîne de caractères telle que “-font” ou “-bg”, qui est comparée aux valeurs dans argv (si argvName est NULL, cela signifie qu'il s'agit d'une entrée groupée ; voir ENTRÉES GROUPÉES ci-dessous). Les champs dbName et dbClass sont utilisés pour rechercher une valeur pour cette option dans la base de données d'options. Le champ defValue spécifie une valeur par défaut pour cette option de configuration si aucune valeur n'est spécifiée dans argv ou dans la base de données d'options. Offset indique où dans widgRec stocker les informations sur cette option, et specFlags contient des informations supplémentaires pour contrôler le traitement de cette option de configuration (voir DRAPEAUX ci-dessous). Le dernier champ, customPtr, n'est utilisé que si type est TK_CONFIG_CUSTOM ; voir TYPES D'OPTIONS PERSONNALISÉES ci-dessous.

Tk_ConfigureWidget traite d'abord argv pour voir quelles options de configuration (le cas échéant) y sont spécifiées. Argv doit contenir un nombre pair de champs ; le premier de chaque paire de champs doit correspondre au argvName d'une entrée dans specs (des abréviations uniques sont acceptables), et le second champ de la paire contient la valeur de cette option de configuration. S'il existe des entrées dans spec pour lesquelles il n'y avait pas d'entrées correspondantes dans argv, Tk_ConfigureWidget utilise les champs dbName et dbClass de l'entrée specs pour sonder la base de données d'options ; si une valeur est trouvée, elle est utilisée comme valeur pour l'option. Enfin, si aucune entrée n'est trouvée dans la base de données d'options, le champ defValue de l'entrée specs est utilisé comme valeur pour l'option de configuration. Si le defValue est NULL, ou si le bit TK_CONFIG_DONT_SET_DEFAULT est défini dans flags, alors il n'y a pas de valeur par défaut et cette entrée specs sera ignorée si aucune valeur n'est spécifiée dans argv ou dans la base de données d'options.

Une fois qu'une valeur sous forme de chaîne a été déterminée pour une option de configuration, Tk_ConfigureWidget traduit cette valeur en une forme plus utile, telle qu'une couleur si type est TK_CONFIG_COLOR ou un entier si type est TK_CONFIG_INT. Cette valeur est ensuite stockée dans l'enregistrement pointé par widgRec. Cet enregistrement est supposé contenir des informations pertinentes pour le gestionnaire du widget ; son type exact est inconnu de Tk_ConfigureWidget. Le champ offset de chaque entrée specs indique où dans widgRec stocker les informations sur cette option de configuration. Vous devriez utiliser la macro Tk_Offset pour générer les valeurs offset (voir ci-dessous pour une description de Tk_Offset). L'emplacement indiqué par widgRec et offset sera appelé la « cible » dans les descriptions ci-dessous.

Le champ type de chaque entrée dans specs détermine ce qu'il faut faire avec la valeur sous forme de chaîne de cette option de configuration. Les valeurs légales pour type, et les actions correspondantes, sont :

TK_CONFIG_ACTIVE_CURSOR
La valeur doit être une chaîne ASCII identifiant un curseur dans un format approprié pour être passé à Tk_GetCursor. La valeur est convertie en un Tk_Cursor en appelant Tk_GetCursor et le résultat est stocké dans la cible. De plus, le curseur résultant est défini comme curseur actif pour tkwin en appelant XDefineCursor. Si TK_CONFIG_NULL_OK est spécifié dans specFlags, alors la valeur peut être une chaîne vide, auquel cas la cible et le curseur actif de tkwin seront définis à None. Si la valeur précédente de la cible n'était pas None, elle est libérée en la passant à Tk_FreeCursor.
TK_CONFIG_ANCHOR
La valeur doit être une chaîne ASCII identifiant un point d'ancrage d'une des manières acceptées par Tk_GetAnchor. La chaîne est convertie en un Tk_Anchor par
calling Tk_GetAnchor et le résultat est stocké dans la cible.
TK_CONFIG_BITMAP
La valeur doit être une chaîne ASCII identifiant un bitmap d'une forme adaptée pour être passée à Tk_GetBitmap. La valeur est convertie en Pixmap en appelant Tk_GetBitmap et le résultat est stocké dans la cible. Si TK_CONFIG_NULL_OK est spécifié dans specFlags alors la valeur peut être une chaîne vide, dans ce cas la cible est mise à None. Si la valeur précédente de la cible n'était pas None, alors elle est libérée en la passant à Tk_FreeBitmap.
TK_CONFIG_BOOLEAN
La valeur doit être une chaîne ASCII spécifiant une valeur booléenne. N'importe laquelle des valeurs «true», «yes», «on», ou «1», ou une abréviation d'une de ces valeurs, signifie vrai ; n'importe laquelle des valeurs «false», «no», «off», ou «0», ou une abréviation d'une de ces valeurs, signifie faux. La cible est attendue comme un entier ; pour les valeurs vraies elle sera mise à 1 et pour les valeurs fausses elle sera mise à 0.
TK_CONFIG_BORDER
La valeur doit être une chaîne ASCII identifiant une couleur de bordure d'une forme adaptée pour être passée à Tk_Get3DBorder. La valeur est convertie en (Tk_3DBorder *) en appelant Tk_Get3DBorder et le résultat est stocké dans la cible. Si TK_CONFIG_NULL_OK est spécifié dans specFlags alors la valeur peut être une chaîne vide, dans ce cas la cible sera mise à NULL. Si la valeur précédente de la cible n'était pas NULL, alors elle est libérée en la passant à Tk_Free3DBorder.
TK_CONFIG_CAP_STYLE
La valeur doit être une chaîne ASCII identifiant un style de capuchon d'une des manières acceptées par Tk_GetCapStyle. La chaîne est convertie en une valeur entière correspondant au style de capuchon en appelant Tk_GetCapStyle et le résultat est stocké dans la cible.
TK_CONFIG_COLOR
La valeur doit être une chaîne ASCII identifiant une couleur d'une forme adaptée pour être passée à Tk_GetColor. La valeur est convertie en (XColor *) en appelant Tk_GetColor et le résultat est stocké dans la cible. Si TK_CONFIG_NULL_OK est spécifié dans specFlags alors la valeur peut être une chaîne vide, dans ce cas la cible sera mise à None. Si la valeur précédente de la cible n'était pas NULL, alors elle est libérée en la passant à Tk_FreeColor.
TK_CONFIG_CURSOR
Cette option est identique à TK_CONFIG_ACTIVE_CURSOR sauf que le nouveau curseur n'est pas rendu actif pour tkwin.
TK_CONFIG_CUSTOM
Cette option permet aux applications de définir de nouveaux types d'options. Le champ customPtr pointe vers une structure définissant le nouveau type d'option. Voir la section TYPES D'OPTIONS PERSONNALISÉES ci-dessous pour les détails.
TK_CONFIG_DOUBLE
La valeur doit être un nombre à virgule flottante ASCII dans le format accepté par strtol. La chaîne est convertie en une valeur double, et la valeur est stockée dans la cible.
TK_CONFIG_END
Marque la fin du tableau. La dernière entrée de specs doit avoir ce type ; tous ses autres champs sont ignorés et elle ne correspondra jamais à aucun argument.
TK_CONFIG_FONT
La valeur doit être une chaîne ASCII identifiant une police d'une forme adaptée pour être passée à Tk_GetFont. La valeur est convertie en Tk_Font en appelant Tk_GetFont et le résultat est stocké dans la cible. Si TK_CONFIG_NULL_OK est spécifié dans specFlags alors la valeur peut être une chaîne vide, dans ce cas la cible sera mise à NULL. Si la valeur précédente de la cible n'était pas NULL, alors elle est libérée en la passant à Tk_FreeFont.
TK_CONFIG_INT
La valeur doit être une chaîne entière ASCII dans le format accepté par strtol (par exemple, les préfixes «0» et «0x» peuvent être utilisés pour spécifier respectivement des nombres octaux ou hexadécimaux). La chaîne est convertie en une valeur entière et l'entier est stocké dans la cible.
TK_CONFIG_JOIN_STYLE
La valeur doit être une chaîne ASCII identifiant un style de jointure d'une des manières acceptées par Tk_GetJoinStyle. La chaîne est convertie en une valeur entière correspondant au style de jointure en appelant Tk_GetJoinStyle et le résultat est stocké dans la cible.
TK_CONFIG_JUSTIFY
La valeur doit être une chaîne ASCII identifiant une méthode de justification d'une des manières acceptées par Tk_GetJustify. La chaîne est convertie en un Tk_Justify en appelant Tk_GetJustify et le résultat est stocké dans la cible.
TK_CONFIG_MM
La valeur doit spécifier une distance à l'écran sous une des formes acceptables par Tk_GetScreenMM. La chaîne est convertie en une distance en virgule flottante double précision en millimètres et la valeur est stockée dans la cible.
TK_CONFIG_PIXELS
La valeur doit spécifier des unités d'écran sous une des formes acceptables par Tk_GetPixels. La chaîne est convertie en une distance entière en pixels et la valeur est stockée dans la cible.
TK_CONFIG_RELIEF
La valeur doit être une chaîne ASCII identifiant un relief d'une forme adaptée pour être passée à Tk_GetRelief. La valeur est convertie en une valeur entière de relief en appelant Tk_GetRelief et le résultat est stocké dans la cible.
TK_CONFIG_STRING
Une copie de la valeur est faite en allouant de l'espace mémoire avec Tcl_Alloc et en copiant la valeur dans l'espace alloué dynamiquement. Un pointeur vers la nouvelle chaîne est stocké dans la cible. Si TK_CONFIG_NULL_OK est spécifié dans specFlags alors la valeur peut être une chaîne vide, dans ce cas la cible sera mise à NULL. Si la valeur précédente de la cible n'était pas NULL, alors elle est libérée en la passant à Tcl_Free.
TK_CONFIG_SYNONYM
Cette valeur de type identifie des entrées spéciales dans specs qui sont des synonymes d'autres entrées. Si une valeur d'argv correspond à l'argvName d'une entrée TK_CONFIG_SYNONYM, l'entrée n'est pas utilisée directement. Au lieu de cela, Tk_ConfigureWidget recherche dans specs une autre entrée dont l'argvName est le même que le champ dbName dans l'entrée TK_CONFIG_SYNONYM ; cette nouvelle entrée est utilisée comme si son argvName avait correspondu à la valeur argv. Le mécanisme de synonyme permet à plusieurs valeurs d'argv d'être utilisées pour une seule option de configuration, telles que «-background» et «-bg».
TK_CONFIG_UID
La valeur est traduite en un Tk_Uid (en la passant à Tk_GetUid). La valeur résultante est stockée dans la cible. Si TK_CONFIG_NULL_OK est spécifié dans specFlags et que la valeur est une chaîne vide alors la cible sera mise à NULL.
TK_CONFIG_WINDOW
La valeur doit être un nom de chemin de fenêtre. Elle est traduite en un jeton Tk_Window et le jeton est stocké dans la cible.

ENTRÉES GROUPÉES

Dans certains cas, il est utile de générer plusieurs ressources à partir d'une seule valeur de configuration. Par exemple, un nom de couleur peut être utilisé à la fois pour générer la couleur d'arrière-plan d'un widget (en utilisant TK_CONFIG_COLOR) et pour générer une bordure 3D à dessiner autour du widget (en utilisant TK_CONFIG_BORDER). Dans des cas comme ceux-ci, il est possible de spécifier que plusieurs entrées consécutives dans specs doivent être traitées comme un groupe. La première entrée est utilisée pour déterminer une valeur (en utilisant ses champs argvName, dbName, dbClass et defValue). La valeur sera traitée plusieurs fois (une fois pour chaque entrée du groupe), générant plusieurs ressources différentes et modifiant plusieurs cibles dans widgRec. Chacune des entrées après la première doit avoir une valeur NULL dans son champ argvName ; cela indique que l'entrée doit être groupée avec l'entrée qui la précède. Seuls les champs type et offset sont utilisés à partir de ces entrées suivantes.

INDICATEURS

L'argument flags passé à Tk_ConfigureWidget est utilisé en conjonction avec les champs specFlags dans les entrées de specs pour fournir un contrôle supplémentaire sur le traitement des options de configuration. Ces valeurs sont utilisées de trois manières différentes, comme décrit ci-dessous.

Premièrement, si l'argument flags de Tk_ConfigureWidget a l'indicateur TK_CONFIG_ARGV_ONLY défini (c'est-à-dire, flags | TK_CONFIG_ARGV_ONLY != 0), alors la base de données d'options et les champs defValue ne sont pas utilisés. Dans ce cas, si une entrée dans specs ne correspond pas à un champ dans argv alors rien ne se passe : la cible correspondante n'est pas modifiée. Cette fonctionnalité est utile lorsque le but est de modifier certaines options de configuration tout en laissant les autres dans leur état actuel, comme lors du traitement d'une commande de widget configure.

Deuxièmement, le champ specFlags d'une entrée dans specs peut être utilisé pour contrôler le traitement de cette entrée. Chaque champ specFlags peut être une combinaison OR des valeurs suivantes :

TK_CONFIG_COLOR_ONLY
Si cet indicateur est défini, l'entrée ne sera considérée que si l'affichage de tkwin a plus d'un plan de bits. Si l'affichage est monochrome, cette entrée specs sera ignorée.
TK_CONFIG_MONO_ONLY
Si
Si ce bit est défini, l'entrée ne sera prise en compte que si l'affichage pour tkwin a un seul plan de bits. Si l'affichage n'est pas monochrome, cette entrée specs sera ignorée.
TK_CONFIG_NULL_OK
Ce bit n'est pertinent que pour certains types d'entrées (voir les descriptions des différents types d'entrées ci-dessus). Si ce bit est défini, il indique qu'une valeur de chaîne vide pour le champ est acceptable et si elle se produit, la cible doit être définie à NULL ou None, selon le type de la cible. Ce drapeau est généralement utilisé pour permettre la désactivation complète d'une fonctionnalité, par exemple, définir une valeur de curseur à None afin qu'une fenêtre hérite simplement du curseur de son parent. Si ce bit n'est pas défini, les chaînes vides sont traitées comme des chaînes, ce qui entraîne généralement une erreur.
TK_CONFIG_DONT_SET_DEFAULT
Si ce bit est à un, cela signifie que le champ defValue de l'entrée ne doit être utilisé que pour retourner la valeur par défaut dans Tk_ConfigureInfo. Dans les appels à Tk_ConfigureWidget, aucune valeur par défaut ne sera fournie pour les entrées avec ce drapeau défini ; il est supposé que l'appelant a déjà fourni une valeur par défaut à l'emplacement cible. Ce drapeau offre une optimisation des performances lorsque le traitement de la chaîne par défaut est coûteux : le client peut calculer la valeur par défaut une fois, enregistrer la valeur et la fournir avant d'appeler Tk_ConfigureWidget.
TK_CONFIG_OPTION_SPECIFIED
Ce bit est obsolète. Il était auparavant défini et effacé par Tk_ConfigureWidget afin que les appelants puissent détecter quelles entrées étaient spécifiées dans argv, mais il a été supprimé car il n'était intrinsèquement pas sûr pour les threads. Le code qui souhaite détecter quelles options ont été spécifiées doit utiliser Tk_SetOptions à la place.

Les indicateurs TK_CONFIG_MONO_ONLY et TK_CONFIG_COLOR_ONLY sont généralement utilisés pour spécifier différentes valeurs par défaut pour les écrans monochromes et couleur. Ceci est réalisé en créant deux entrées dans specs qui sont identiques à l'exception de leurs champs defValue et specFlags. Une entrée doit avoir la valeur TK_CONFIG_MONO_ONLY dans ses specFlags et la valeur par défaut pour les écrans monochromes dans son defValue ; l'autre entrée doit avoir la valeur TK_CONFIG_COLOR_ONLY dans ses specFlags et la valeur appropriée defValue pour les écrans couleur.

Troisièmement, il est possible d'utiliser flags et specFlags ensemble pour désactiver sélectivement certaines entrées. Cette fonctionnalité n'est pas très souvent nécessaire. Elle est utile dans les cas où plusieurs types de widgets similaires sont implémentés au même endroit. Elle permet de créer une seule table specs avec toutes les options de configuration pour tous les types de widgets. Lors du traitement d'un type de widget particulier, seules les entrées pertinentes pour ce type seront utilisées. Cet effet est obtenu en définissant les bits de poids fort (ceux dans les positions égales ou supérieures à TK_CONFIG_USER_BIT) dans specFlags ou dans flags. Pour qu'une entrée particulière dans specs soit utilisée, ses bits de poids fort doivent correspondre exactement aux bits de poids fort de la valeur flags passée à Tk_ConfigureWidget. Si une table specs est utilisée pour N types de widgets différents, alors N des bits de poids fort seront utilisés. Chaque entrée specs aura un ou plusieurs de ces bits définis dans son champ specFlags pour indiquer les types de widgets pour lesquels cette entrée est valide. Lors de l'appel à Tk_ConfigureWidget, flags aura un seul de ces bits défini pour sélectionner les entrées du type de widget désiré. Pour un exemple de fonctionnement de cette fonctionnalité, voir le code dans tkButton.c.

TK_OFFSET

La macro Tk_Offset est fournie comme moyen sûr de générer les valeurs offset pour les entrées dans les structures Tk_ConfigSpec. Elle prend deux arguments : le nom d'un type d'enregistrement, et le nom d'un champ dans cet enregistrement. Elle renvoie le décalage en octets du champ nommé dans les enregistrements du type donné.

TK_CONFIGUREINFO

La procédure Tk_ConfigureInfo peut être utilisée pour obtenir des informations sur une ou toutes les options d'un widget donné. Étant donné un jeton pour une fenêtre (tkwin), une table décrivant les options de configuration d'une classe de widgets (specs), un pointeur vers un enregistrement de widget contenant les informations actuelles pour un widget (widgRec), et un argument argvName NULL, Tk_ConfigureInfo génère une chaîne décrivant toutes les options de configuration de la fenêtre. La chaîne est placée dans le résultat de l'interpréteur interp. Dans des circonstances normales, elle renvoie TCL_OK ; si une erreur se produit, elle renvoie TCL_ERROR et le résultat de l'interpréteur contiendra un message d'erreur.

Si argvName est NULL, alors la valeur laissée dans le résultat de l'interpréteur par Tk_ConfigureInfo consiste en une liste d'une ou plusieurs entrées, chacune décrivant une option de configuration (c'est-à-dire une entrée dans specs). Chaque entrée de la liste contiendra deux ou cinq valeurs. Si l'entrée correspondante dans specs a le type TK_CONFIG_SYNONYM, alors la liste contiendra deux valeurs : le argvName de l'entrée et le dbName (nom synonyme). Sinon, la liste contiendra cinq valeurs : argvName, dbName, dbClass, defValue, et la valeur actuelle. La valeur actuelle est calculée à partir du champ approprié de widgRec en appelant des procédures comme Tk_NameOfColor.

Si l'argument argvName à Tk_ConfigureInfo n'est pas NULL, alors il indique une option unique, et des informations sont renvoyées uniquement pour cette option. La chaîne placée dans le résultat de l'interpréteur sera une liste contenant deux ou cinq valeurs comme décrit ci-dessus ; ce sera identique à la sous-liste correspondante qui aurait été renvoyée si argvName avait été NULL.

L'argument flags à Tk_ConfigureInfo est utilisé pour restreindre les entrées specs à considérer, tout comme pour Tk_ConfigureWidget.

TK_CONFIGUREVALUE

Tk_ConfigureValue prend des arguments similaires à Tk_ConfigureInfo ; au lieu de retourner une liste de valeurs, elle retourne simplement la valeur actuelle de l'option donnée par argvName (argvName ne doit pas être NULL). La valeur est retournée dans le résultat de l'interpréteur interp et TCL_OK est normalement retourné comme résultat de la procédure. Si une erreur se produit dans Tk_ConfigureValue (par exemple, argvName n'est pas un nom d'option valide), TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de l'interpréteur. Cette procédure est généralement appelée pour implémenter les commandes de widget cget.

TK_FREEOPTIONS

La procédure Tk_FreeOptions peut être appelée lors du nettoyage du widget pour libérer toutes les ressources associées aux options de configuration. Elle parcourt specs et pour chaque entrée correspondant à une ressource qui doit être explicitement libérée (par exemple, celles de type TK_CONFIG_COLOR), elle libère la ressource dans l'enregistrement du widget. Si le champ de l'enregistrement du widget ne fait pas référence à une ressource (par exemple, il contient un pointeur nul), alors aucune ressource n'est libérée pour cette entrée. Après avoir libéré une ressource, Tk_FreeOptions met le champ correspondant de l'enregistrement du widget à NULL.

TYPES D'OPTIONS PERSONNALISÉES

Les applications peuvent étendre les types de configuration intégrés avec des types de configuration supplémentaires en écrivant des procédures pour analyser et imprimer des options d'un type et en créant une structure pointant vers ces procédures :

typedef struct Tk_CustomOption {
    Tk_OptionParseProc *parseProc;
    Tk_OptionPrintProc *printProc;
    ClientData clientData;
} Tk_CustomOption;
typedef int Tk_OptionParseProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tk_Window tkwin,
        char *value,
        char *widgRec,
        int offset);
typedef const char *Tk_OptionPrintProc(
        ClientData clientData,
        Tk_Window tkwin,
        char *widgRec,
        int offset,
        Tcl_FreeProc **freeProcPtr);
La structure Tk_CustomOption contient trois champs, qui sont des pointeurs vers les deux procédures et une valeur clientData à passer à ces procédures lorsqu'elles sont invoquées. La valeur clientData pointe généralement vers une structure contenant des informations nécessaires aux procédures lors de l'analyse et de l'impression des options.

La procédure parseProc est appelée par Tk_ConfigureWidget pour analyser une chaîne et stocker la valeur résultante dans l'enregistrement du widget. L'argument clientData est une copie du champ clientData dans la structure Tk_CustomOption. L'argument interp pointe vers un interpréteur Tcl utilisé pour le rapport d'erreurs. Tkwin est une copie de l'argument tkwin à Tk_ConfigureWidget. L'argument value est une chaîne décrivant la valeur de l'option ; elle pourrait avoir été spécifiée explicitement dans l'appel à Tk_ConfigureWidget ou elle pourrait provenir de la base de données d'options ou d'une valeur par défaut. Value ne sera jamais un pointeur NULL mais il peut pointer vers une chaîne vide. RecordPtr est identique à l'argument widgRec à Tk_ConfigureWidget ; il pointe vers le début de l'enregistrement du widget à modifier. Le dernier argument, offset, donne le décalage en octets à partir du début de l'enregistrement du widget jusqu'à l'emplacement où la valeur de l'option doit être placée. La procédure doit traduire la chaîne dans la forme appropriée pour l'option et stocker la valeur dans l'enregistrement du widget. Elle doit normalement renvoyer TCL_OK, mais si une erreur se produit lors de la traduction de la chaîne en valeur, elle doit renvoyer TCL_ERROR et stocker un message d'erreur dans le résultat de l'interpréteur interp.

La procédure printProc est appelée par Tk_ConfigureInfo pour produire une chaîne de caractères décrivant une option existante. Ses arguments clientData, tkwin, widgRec, et offset ont tous la même signification que pour les procédures Tk_OptionParseProc. Tk_FreeOptions(3)

NAME

Tk_FreeOptions, Tk_ConfigureOptions, Tk_ConfigureWidget, Tk_GetOptions, Tk_InitOptions, Tk_SetOptions - configure Tk widgets

SYNOPSIS

#include <tk.h>
int
Tk_ConfigureWidget(interp, tkwin, configSpecs, recordPtr, size, flags)
int
Tk_ConfigureInfo(interp, tkwin, configSpecs, recordPtr, optionName, flags)
int
Tk_ConfigureValue(interp, tkwin, configSpecs, recordPtr, optionName, flags)
void
Tk_InitOptions(recordPtr, size)
int
Tk_GetOptions(interp, numOptions, options, recordPtr, flags)
int
Tk_SetOptions(interp, numOptions, options, recordPtr, flags)
void
Tk_FreeOptions(numOptions, options, recordPtr)

ARGUMENTS

Tk_ConfigSpec *configSpecs (input) Configuration specifications for the widget.

Tcl_Interp *interp (input) Interpreter to use for error reporting.

Tk_Window tkwin (input) Window whose options are being configured. This is used for translating screen distances and for looking up resource databases.

char *recordPtr (input) Pointer to the widget's instance data structure.

int size (input) Size of the instance data structure pointed to by recordPtr.

int flags (input) Various flags that control how options are handled. See the FLAGS section below.

const char *optionName (input) The name of the option to query. If this is NULL, then information about all options is returned.

int numOptions (input) Number of entries in the options array.

CONST Tk_Option *options (input) Array of option specifications. See the Tk_Option structure definition.

DESCRIPTION

The Tk_Configure... functions provide a general mechanism for implementing configuration options for Tk widgets. They allow you to define a set of configuration options, specify how they map to fields in a widget's instance data structure, and provide procedures for parsing and printing values for the options. This mechanism is used internally by Tk for all its standard widgets, and it can be used by application programmers as well.

The central data structure for this mechanism is Tk_ConfigSpec, which has the following structure:

typedef struct {
    int type;               /* Type of option. */
    const char *optionName; /* Name of option. */
    const char *dbName;     /* Name in resource database. */
    const char *dbClass;    /* Class in resource database. */
    union {
        XrmInitialValues initialValues; /* For TK_CONFIG_COLOR_STRING, etc. */
        struct {
            Tk_GetProc *getProc;
            Tk_SetProc *setProc;
            ClientData clientData;
        } custom;
        struct {
            Tk_ObjCmdProc *cmdPtr;
            ClientData clientData;
        } objCustom;
    } value;
    char *defString;        /* Default value string. */
    int offset;             /* Offset of field in instance record. */
    int specFlags;          /* Flags. */
    ... /* other fields for specialized types */
} Tk_ConfigSpec;

The fields are as follows:

  • type: Specifies the type of the option. Tk_ConfigSpec types are defined in <tk.h> and include options like TK_CONFIG_BOOLEAN, TK_CONFIG_INT, TK_CONFIG_DOUBLE, TK_CONFIG_STRING, TK_CONFIG_ Tk_Window, TK_CONFIG_FONT, TK_CONFIG_COLOR, TK_CONFIG_BITMAP, TK_CONFIG_RELIEF, TK_CONFIG_BORDER, TK_CONFIG_CAP_STYLE, TK_CONFIG_JOIN_STYLE, TK_CONFIG_JUSTIFY, TK_CONFIG_CURSOR, TK_CONFIG_UID, TK_CONFIG_MM, TK_CONFIG_PIXELS, TK_CONFIG_CUSTOM, TK_CONFIG_OBJ, TK_CONFIG_ONOFF, TK_CONFIG_ACTIVE, TK_CONFIG_ARRAY, TK_CONFIG_CODE, TK_CONFIG_COLOR_STRING, TK_CONFIG_SYNONYM, and others. A full list of types is available in the Tk manual pages.
  • optionName: The name of the option as it will appear on the command line (e.g., "-background"). This should be a standard Tk option name, beginning with a "-".
  • dbName: The name used for the option in the resource database. This is typically the same as optionName, but without the leading "-".
  • dbClass: The class name used for the option in the resource database. This is also typically the same as dbName, but without the leading "-".
  • value: This union contains information specific to the option type.
    • For simple types like booleans, integers, and strings, this field is unused.
    • For TK_CONFIG_CUSTOM and TK_CONFIG_OBJ_CUSTOM types, value.custom or value.objCustom contains pointers to procedures that parse and print values for the custom option type. These procedures are described in the CUSTOM OPTION TYPES section.
    • For certain other types like TK_CONFIG_COLOR_STRING, it may contain resource database initial values.
  • defString: A pointer to a string that specifies the default value for the option. This string will be parsed using the same rules as command-line arguments. If this is NULL, then the option has no default value (and is typically required).
  • offset: The byte offset from the beginning of the widget's instance data structure (pointed to by recordPtr) to the field where the option's value should be stored. This is typically calculated using the TK_OFFSET macro.
  • specFlags: A bitmask that specifies additional characteristics of the option. Possible flags include:
    • TK_CONFIG_NULL_OK: The option value may be NULL (e.g., for strings).
    • TK_CONFIG_COLOR_MONO: For color options, use the default foreground color if the specified color is not available on the monochrome screen.
    • TK_CONFIG_BAD_FILE: If the option value is a filename, return an error if the file doesn't exist.
    • TK_CONFIG_DIR: The option value is a directory name.
    • TK_CONFIG_DONT_SET_DEFAULT: Don't use this option's value as the default for other options.
    • TK_CONFIG_NODE_TRANSIENT: This option is used only when the widget is created, not for subsequent reconfiguration.
    • TK_CONFIG_OBJ: The option value is a Tk object.
    A full list of flags is available in the Tk manual pages.
  • other fields: Depending on the option type, there may be other fields in the Tk_ConfigSpec structure, such as fields for specifying the default values for color, font, or border options.

The various Tk_Configure... functions are used as follows:

Tk_ConfigureWidget
This is the main procedure for configuring a widget. It takes a list of Tk_ConfigSpec entries and a configuration string (such as would be passed to the widget's configure subcommand) and updates the widget's instance data structure accordingly. It returns a standard Tk error status (TCL_OK or TCL_ERROR).
Tk_ConfigureInfo
This procedure is used to retrieve information about a widget's configuration options. It takes a specific option name and returns information about that option (its current value, type, default value, etc.). If optionName is NULL, it returns information about all options.
Tk_ConfigureValue
Similar to Tk_ConfigureInfo, but it returns the actual parsed value of the option, rather than just information about it.
Tk_InitOptions
Initializes the widget's instance data structure to default values. This should be called before any configuration is done.
Tk_GetOptions
Takes an array of Tk_Option structures and configures the widget based on the values specified in the array. This is typically used internally by Tk for processing complex configuration requests.
Tk_SetOptions
Similar to Tk_GetOptions, but it applies a set of options to the widget. This is typically used internally by Tk for processing complex configuration requests.
Tk_FreeOptions
Frees any dynamically allocated memory associated with the widget's configuration options. This should be called when the widget is destroyed.

GROUPED ENTRIES

Configuration options can be grouped together so that they are treated as a single unit. This is useful for options that have related sub-options, such as a border which might have separate options for width, relief, and color.

To group options, you set the optionName field of the first option in the group to NULL. Subsequent options in the group will have their optionName fields set as usual, but they will be treated as part of the group defined by the first option. The defString field of the first option in the group is typically used to specify the default value for the entire group.

FLAGS

The flags argument to the Tk_Configure... functions can be used to control how options are processed. The most common flags are:

TK_CONFIG_ARGV_ONLY
Only process options specified on the command line. Do not consult the resource database.
TK_CONFIG_OBEY_BORDER
If the widget has a border, respect its settings when configuring options like background color.
TK_CONFIG_OBEY_MONOCHROME
If the screen is monochrome, use default colors where appropriate.

TK_OFFSET

The TK_OFFSET macro is used to calculate the byte offset of a field within a structure. It is typically used in the offset field of a Tk_ConfigSpec entry.

    TK_OFFSET(structPtr, field)

where structPtr is a pointer to an instance of the structure and field is the name of the field whose offset is desired. For example:

    configSpecs[i].offset = TK_OFFSET(&widgetRec, background);

TK_CONFIGUREINFO

The Tk_ConfigureInfo procedure can be used to retrieve information about a widget's configuration options. If optionName is NULL, then information about all options is returned. The information is returned as a Tcl list, where each element of the list describes one option. The format of each option description depends on the value of the flags argument.

TK_CONFIGUREVALUE

The Tk_ConfigureValue procedure is similar to Tk_ConfigureInfo, but it returns the actual parsed value of the option as a Tcl object, rather than just information about it. This is useful for retrieving the current value of an option.

TK_FREEOPTIONS

The Tk_FreeOptions procedure is called to free any memory that was dynamically allocated by the configuration system on behalf of the widget. This typically includes memory allocated for string values, colors, fonts, etc. It should be called whenever the widget is destroyed or when its configuration is being reset.

The numOptions and options arguments specify the array of Tk_Option structures that were used to configure the widget. The recordPtr argument points to the widget's instance data structure.

CUSTOM OPTION TYPES

Tk provides a mechanism for defining custom option types, which can be used when the built-in types are insufficient. To define a custom option type, you create a Tk_CustomOption structure:

typedef struct {
    Tk_OptionParseProc *parseProc;
    Tk_OptionPrintProc *printProc;
    ClientData deleteProc;
    ClientData clientData;
} Tk_CustomOption;

The fields are:

  • parseProc: A pointer to a procedure that will be called to parse string values for the custom option. This procedure should convert the string value into the appropriate internal representation and store it in the widget's instance data structure. It should return TCL_OK on success and TCL_ERROR on failure. The procedure has the following signature: 
            int (*parseProc)(ClientData clientData, Tcl_Interp *interp,
            Tk_Window tkwin, const char *value, char *recordPtr, int offset)
    The clientData argument is the same as the clientData field in the Tk_ConfigSpec structure. The value argument is the string value to be parsed. The recordPtr argument points to the widget's instance data structure, and offset is the offset within that structure where the parsed value should be stored.
  • printProc: A pointer to a procedure that will be called to convert the internal representation of the option's value back into a string. This procedure is used when querying the option's value using Tk_ConfigureInfo or Tk_ConfigureValue. It should return a dynamically allocated string containing the string representation of the value. The procedure has the following signature: 
            char *(*printProc)(ClientData clientData, Tk_Window tkwin,
            char *recordPtr, int offset, Tcl_FreeProc **freeProcPtr)
    The clientData argument is the same as the clientData field in the Tk_ConfigSpec structure. The recordPtr argument points to the widget's instance data structure, and offset is the offset within that structure where the value to be printed is stored. The procedure should return a pointer to the dynamically allocated string. If the string is stored in static memory, then printProc should set freeProcPtr to NULL.
  • deleteProc: A pointer to a procedure that will be called to free any dynamically allocated memory associated with the option's value when the widget is destroyed or the option is reconfigured. This argument is optional and can be NULL if no cleanup is needed.
  • clientData: Arbitrary client data that will be passed to the parseProc and printProc procedures. This can be used to pass additional context or data to these procedures.

Once parseProc and printProc have been defined and a Tk_CustomOption structure has been created for them, options of this new type may be manipulated with Tk_ConfigSpec entries whose type fields are TK_CONFIG_CUSTOM and whose customPtr fields point to the Tk_CustomOption structure.

EXAMPLES

Although the explanation of Tk_ConfigureWidget is fairly complicated, its actual use is pretty straightforward. The easiest way to get started is to copy the code from an existing widget. The library implementation of frames (tkFrame.c) has a simple configuration table, and the library implementation of buttons (tkButton.c) has a much more complex table that uses many of the fancy specFlags mechanisms.
