Tk_CreateEventHandler(3) Procédures de la bibliothèque Tk Tk_CreateEventHandler(3)

NOM

Tk_CreateEventHandler, Tk_DeleteEventHandler - associer une procédure de rappel à un événement X

SYNTAXE

#include <tk.h>

Tk_CreateEventHandler(tkwin, mask, proc, clientData)

Tk_DeleteEventHandler(tkwin, mask, proc, clientData)

ARGUMENTS

Tk_Window tkwin (entree)
Jeton pour la fenêtre dans laquelle les événements peuvent se produire.
unsigned long mask (entree)
Masque binaire d'événements (tel que ButtonPressMask) pour lesquels proc doit être appelé.
Tk_EventProc *proc (entree)
Procédure à invoquer chaque fois qu'un événement dans mask se produit dans la fenêtre donnée par tkwin.
ClientData clientData (entree)
Valeur arbitraire d'un mot à passer à proc.

DESCRIPTION

Tk_CreateEventHandler fait en sorte que proc soit invoqué à l'avenir chaque fois que l'un des types d'événements spécifiés par mask se produit dans la fenêtre spécifiée par tkwin. L'appel de rappel à proc sera effectué par Tk_HandleEvent ; ce mécanisme ne fonctionne que dans les programmes qui distribuent les événements via Tk_HandleEvent (ou via d'autres procédures Tk qui appellent Tk_HandleEvent, telles que Tcl_DoOneEvent ou Tk_MainLoop).

Proc doit avoir des arguments et un résultat qui correspondent au type Tk_EventProc :

typedef void Tk_EventProc(
        ClientData clientData,
        XEvent *eventPtr);
Le paramètre clientData de proc est une copie de l'argument clientData donné à Tk_CreateEventHandler lors de la création de l'appel de rappel. Typiquement, clientData pointe vers une structure de données contenant des informations spécifiques à l'application sur la fenêtre dans laquelle l'événement s'est produit. EventPtr est un pointeur vers l'événement X, qui sera l'un de ceux spécifiés dans l'argument mask de Tk_CreateEventHandler.

Tk_DeleteEventHandler peut être appelé pour supprimer un gestionnaire d'événements précédemment créé : il supprime le premier gestionnaire qu'il trouve et qui est associé à tkwin et correspond aux arguments mask, proc et clientData. Si aucun gestionnaire de ce type n'existe, Tk_HandleEvent retourne sans rien faire. Bien que Tk le prenne en charge, il est probablement déconseillé d'avoir plus d'un appel de rappel avec les mêmes arguments mask, proc et clientData. Lorsqu'une fenêtre est supprimée, tous ses gestionnaires sont supprimés automatiquement ; dans ce cas, il n'est pas nécessaire d'appeler Tk_DeleteEventHandler.

Si plusieurs gestionnaires sont déclarés pour le même type d'événement X sur la même fenêtre, les gestionnaires seront invoqués dans l'ordre où ils ont été créés.
