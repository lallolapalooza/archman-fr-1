NOM

Tk_AllocCursorFromObj, Tk_GetCursor, Tk_GetCursorFromObj, Tk_GetCursorFromData, Tk_NameOfCursor, Tk_FreeCursorFromObj, Tk_FreeCursor - maintenir une base de données de curseurs

Tk_Cursor

const char *

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur à utiliser pour le rapport d'erreurs.
Tk_Window tkwin (in)
Jeton pour la fenêtre dans laquelle le curseur sera utilisé.
Tcl_Obj *objPtr (in/out)
Description du curseur ; voir ci-dessous pour les valeurs possibles. La représentation interne sera modifiée pour mettre en cache un pointeur vers le Tk_Cursor correspondant.
const char *name (in)
Identique à objPtr sauf que la description du curseur est passée sous forme de chaîne et que le Tk_Cursor résultant n'est pas mis en cache.
const char *source (in)
Données pour le curseur, au format de curseur standard.
const char *mask (in)
Données pour le masque du curseur, au format de curseur standard.
int width (in)
Largeur de source et mask.
int height (in)
Hauteur de source et mask.
int xHot (in)
Position X du point chaud du curseur.
int yHot (in)
Position Y du point chaud du curseur.
Tk_Uid fg (in)
Description textuelle de la couleur de premier plan pour le curseur.
Tk_Uid bg (in)
Description textuelle de la couleur d'arrière-plan pour le curseur.
Display *display (in)
Affichage pour lequel cursor a été alloué.
Tk_Cursor cursor (in)
Identifiant Tk opaque pour le curseur. S'il est passé à Tk_FreeCursor, il doit avoir été retourné par un appel précédent à Tk_GetCursor ou Tk_GetCursorFromData.

DESCRIPTION

Ces procédures gèrent une collection de curseurs utilisés par une application. Les procédures permettent la réutilisation efficace des curseurs, évitant ainsi la surcharge du serveur, et permettent également de nommer les curseurs avec des chaînes de caractères.

Tk_AllocCursorFromObj prend en argument un objet décrivant un curseur, et retourne un identifiant Tk opaque pour un curseur correspondant à la description. Il réutilise un curseur existant si possible et en crée un nouveau sinon. Tk_AllocCursorFromObj met en cache les informations sur la valeur de retour dans objPtr, ce qui accélère les appels futurs aux procédures telles que Tk_AllocCursorFromObj et Tk_GetCursorFromObj. Si une erreur se produit lors de la création du curseur, par exemple lorsque objPtr fait référence à un fichier inexistant, alors None est retourné et un message d'erreur sera stocké dans le résultat de interp si interp n'est pas NULL. ObjPtr doit contenir une liste Tcl standard avec l'une des formes suivantes :

nom [fgColor [bgColor]]
Nom est le nom d'un curseur dans la bibliothèque de curseurs standard X, c'est-à-dire l'un des noms définis dans cursorcursor.h, sans le préfixe XC_. Quelques exemples de valeurs sont X_cursor, hand2, ou left_ptr. L'Annexe B de “The X Window System” par Scheifler & Gettys présente des illustrations montrant l'apparence de chacun de ces curseurs. Si fgColor et bgColor sont tous deux spécifiés, ils indiquent les couleurs de premier plan et d'arrière-plan à utiliser pour le curseur (toute forme acceptable par Tk_GetColor peut être utilisée). Si seul fgColor est spécifié, alors il n'y aura pas de couleur d'arrière-plan : l'arrière-plan sera transparent. Si aucune couleur n'est spécifiée, le curseur utilisera le noir pour sa couleur de premier plan et le blanc pour sa couleur d'arrière-plan.

La version Macintosh de Tk prend en charge tous les curseurs X et acceptera également tous les curseurs Mac standard, y compris ibeam, crosshair, watch, plus, et arrow. De plus, Tk chargera les ressources de curseurs Macintosh des types crsr (couleur) et CURS (noir et blanc) par le nom de la ressource. L'application et tous ses fichiers de ressources de bibliothèques dynamiques ouverts seront recherchés pour le curseur nommé. En cas de conflits, les curseurs couleur seront toujours chargés de préférence aux curseurs noir et blanc.

@sourceName maskName fgColor bgColor
Dans cette forme, sourceName et maskName sont les noms de fichiers décrivant les bits source du curseur et son masque. Chaque fichier doit être au format de curseur X11 standard. FgColor et bgColor indiquent les couleurs à utiliser pour le curseur, dans toute forme acceptable par Tk_GetColor. Cette forme de la commande ne fonctionnera pas sur les ordinateurs Macintosh ou Windows.
@sourceName fgColor
Cette forme est similaire à la précédente, à la différence que la source est également utilisée comme masque. Cela signifie que l'arrière-plan du curseur est transparent. Cette forme de la commande ne fonctionnera pas sur les ordinateurs Macintosh ou Windows.
@sourceName
Cette forme ne fonctionne que sous Windows et chargera un curseur système Windows (.ani ou .cur) à partir du fichier spécifié dans sourceName.

Tk_GetCursor est identique à Tk_AllocCursorFromObj sauf que la description du curseur est spécifiée avec une chaîne au lieu d'un objet. Cela empêche Tk_GetCursor de mettre en cache la valeur de retour, de sorte que Tk_GetCursor est moins efficace que Tk_AllocCursorFromObj.

Tk_GetCursorFromObj retourne le jeton d'un curseur existant, étant donné la fenêtre et la description utilisées pour créer le curseur. Tk_GetCursorFromObj ne crée pas réellement le curseur ; le curseur doit avoir déjà été créé par un appel précédent à Tk_AllocCursorFromObj ou Tk_GetCursor. La valeur de retour est mise en cache dans objPtr, ce qui accélère les appels futurs à Tk_GetCursorFromObj avec le même objPtr et tkwin.

Tk_GetCursorFromData permet de créer des curseurs à partir de descriptions en mémoire de leurs curseurs source et masque. Source pointe vers les données standard du curseur pour les bits source du curseur, et mask pointe vers les données standard du curseur décrivant quels pixels de source doivent être dessinés et lesquels doivent être considérés comme transparents. Width et height donnent les dimensions du curseur, xHot et yHot indiquent l'emplacement du point chaud du curseur (le point signalé lors d'un événement), et fg et bg décrivent les couleurs de premier plan et d'arrière-plan du curseur textuellement (toute forme adaptée à Tk_GetColor peut être utilisée). Typiquement, les arguments de Tk_GetCursorFromData sont créés en incluant un fichier de curseur directement dans le code source d'un programme, comme dans l'exemple suivant :

Tk_Cursor cursor;
#include "source.cursor"
#include "mask.cursor"
cursor = Tk_GetCursorFromData(interp, tkwin, source_bits,
    mask_bits, source_width, source_height, source_x_hot,
    source_y_hot, Tk_GetUid("red"), Tk_GetUid("blue"));

Dans des conditions normales, Tk_GetCursorFromData retournera un identifiant pour le curseur demandé. Si une erreur survient lors de la création du curseur, alors None est retourné et un message d'erreur sera stocké dans le résultat de interp.

Tk_AllocCursorFromObj, Tk_GetCursor et Tk_GetCursorFromData maintiennent une base de données de tous les curseurs qu'ils ont créés. Chaque fois que possible, un appel à Tk_AllocCursorFromObj, Tk_GetCursor, ou Tk_GetCursorFromData retournera un curseur existant plutôt que d'en créer un nouveau. Cette approche peut considérablement réduire la surcharge du serveur, donc les procédures Tk devraient généralement être utilisées de préférence aux procédures Xlib telles que XCreateFontCursor ou XCreatePixmapCursor, qui créent un nouveau curseur à chaque appel. Les procédures Tk sont également plus portables que les procédures de plus bas niveau d'X.

Notez que la chaîne renvoyée par Tk_NameOfCursor n'est garantie de persister que jusqu'au prochain appel à Tk_NameOfCursor. De plus, cet appel n'est pas portable, sauf pour les curseurs renvoyés par Tk_GetCursor.

Lorsqu'un curseur renvoyé par Tk_AllocCursorFromObj, Tk_GetCursor ou Tk_GetCursorFromData n'est plus nécessaire, il convient d'appeler Tk_FreeCursorFromObj ou Tk_FreeCursor pour le libérer. Pour Tk_FreeCursorFromObj, le curseur à libérer est spécifié avec les mêmes informations que celles utilisées pour le créer ; pour Tk_FreeCursor, le curseur à libérer est spécifié avec son jeton Tk_Cursor. Il doit y avoir exactement un appel à Tk_FreeCursor pour chaque appel à Tk_AllocCursorFromObj, Tk_GetCursor ou Tk_GetCursorFromData.

BUGS

Pour déterminer si un curseur existant peut satisfaire une nouvelle demande, Tk_AllocCursorFromObj, Tk_GetCursor et Tk_GetCursorFromData ne tiennent compte que des valeurs immédiates de leurs arguments. Par exemple, lorsqu'un nom de fichier est passé à Tk_GetCursor, Tk_GetCursor supposera qu'il est sûr de réutiliser un curseur existant créé à partir du même nom de fichier : il ne vérifiera pas si le fichier lui-même a changé, ou si le répertoire courant a changé, faisant ainsi que le nom référence un fichier différent. De même, Tk_GetCursorFromData suppose que si le même pointeur *source* est utilisé dans deux appels différents, alors les pointeurs référencent les mêmes données ; il ne vérifie pas si les valeurs réelles des données ont changé.
