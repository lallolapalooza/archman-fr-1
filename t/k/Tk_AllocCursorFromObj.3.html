NOM

Tk_AllocCursorFromObj, Tk_GetCursor, Tk_GetCursorFromObj, Tk_GetCursorFromData, Tk_NameOfCursor, Tk_FreeCursorFromObj, Tk_FreeCursor - maintenir une base de données de curseurs

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur pour signaler les erreurs.
Tk_Window tkwin (entrée)
Token pour la fenêtre dans laquelle le curseur sera utilisé.
Tcl_Obj *objPtr (entrée/sortie)
Description du curseur ; voir ci-dessous pour les valeurs possibles. La représentation interne sera modifiée pour stocker le pointeur correspondant à Tk_Cursor dans objPtr.
const char *name (entrée)
Ignore objPtr, décrit le curseur comme une chaîne de caractères et le Tk_Cursor n'est pas conservé.
const char *source (entrée)
Données du curseur, au format standard.
const char *mask (entrée)
Données du masque du curseur, au format standard.
int width (entrée)
Largeur de source et de masque.
int height (entrée)
Hauteur de source et de masque.
int xHot (entrée)
Position X du point chaud du curseur.
int yHot (entrée)
Position Y du point chaud du curseur.
Tk_Uid fg (entrée)
Description textuelle de la couleur de premier plan du curseur.
Tk_Uid bg (entrée)
Description textuelle de la couleur d'arrière-plan du curseur.
Display *display (entrée)
Affichage sur lequel le curseur a été alloué.
Tk_Cursor cursor (entrée)
Identifiant opaque de Tk pour le curseur. S'il est passé à Tk_FreeCursor, il doit avoir été renvoyé par un appel précédent à Tk_GetCursor ou Tk_GetCursorFromData.

DESCRIPTION

Ces procédures gèrent une collection de curseurs utilisés par une application. Les procédures permettent de réutiliser les curseurs efficacement, en évitant la surcharge du serveur, et permettent également de nommer les curseurs avec des chaînes de caractères.

Tk_AllocCursorFromObj prend en argument un objet décrivant un curseur et renvoie un identifiant opaque de Tk pour un curseur correspondant à la description. Si possible, il réutilise un curseur existant ; sinon, il en crée un nouveau. Tk_AllocCursorFromObj met en cache les informations sur la valeur renvoyée dans objPtr, ce qui accélère les appels ultérieurs à des procédures comme Tk_AllocCursorFromObj et Tk_GetCursorFromObj. En cas d'erreur lors de la création du curseur, par exemple lorsque objPtr fait référence à un fichier inexistant, None est renvoyé et un message d'erreur est stocké dans interp si interp n'est pas nul. objPtr doit contenir une liste Tcl standard de l'une des formes suivantes :

nom [fgColor [bgColor]]
Nom est le nom d'un curseur standard du système X, c'est-à-dire l'un des noms définis dans cursorcursor.h, sans le préfixe XC_. Quelques exemples sont X_cursor, hand2, ou left_ptr. L'annexe B de « Le Système X » de Scheifler & Gettys montre des illustrations de l'apparence de chacun de ces curseurs. Si fgColor et bgColor sont tous deux spécifiés, ils donnent la couleur de premier plan et d'arrière-plan du curseur (toute description acceptée par Tk_GetColor peut être utilisée). Si seule fgColor est spécifiée, il n'y aura pas de couleur d'arrière-plan : l'arrière-plan sera transparent. Si aucune couleur n'est spécifiée, le curseur utilisera le noir pour la couleur de premier plan et le blanc pour l'arrière-plan.

La version Macintosh de Tk prend en charge tous les curseurs standards du système X et accepte également tous les curseurs standards du système Mac, y compris ibeam, crosshair, watch, plus et arrow. De plus, Tk chargera des ressources de type crsr (couleur) et CURS (noir et blanc) par leur nom. L'application et tous ses fichiers de ressources de bibliothèques dynamiques ouverts utiliseront ces ressources. En cas de conflit, les curseurs couleur seront chargés avant les curseurs noir et blanc.

@sourceName maskName fgColor bgColor
Dans ce format, sourceName et maskName sont les noms de fichiers décrivant les bits de source et de masque du curseur. Chaque fichier doit être au format standard X11 de curseur. fgColor et bgColor indiquent les couleurs du curseur, dans n'importe quel format acceptable par Tk_GetColor. Ce format ne fonctionne pas sur Macintosh ou Windows.
@sourceName fgColor
Ce format est similaire au précédent, mais la source est utilisée comme masque. Cela signifie que l'arrière-plan du curseur est transparent. Ce format ne fonctionne pas sur Macintosh ou Windows.
@sourceName
Ce format ne fonctionne que sous Windows et chargera un curseur système Windows (.ani ou .cur) à partir du fichier spécifié dans sourceName.

Tk_GetCursor est identique à Tk_AllocCursorFromObj, sauf que la description du curseur est spécifiée par une chaîne de caractères au lieu d'un objet. Cela empêche Tk_GetCursor de mapper la valeur renvoyée, Tk_GetCursor est donc moins efficace que Tk_AllocCursorFromObj.

Tk_GetCursorFromObj renvoie le token d'un curseur existant, étant donné la fenêtre et la description utilisées pour créer le curseur. Tk_GetCursorFromObj ne crée pas le curseur directement ; le curseur doit avoir été créé précédemment par un appel à Tk_AllocCursorFromObj ou Tk_GetCursor. La valeur renvoyée est conservée dans objPtr, accélérant les appels futurs à Tk_GetCursorFromObj avec le même objPtr et tkwin.

Tk_GetCursorFromData permet de créer des curseurs à partir de descriptions en mémoire de leurs données de source et de masque. source pointe vers les données standard pour les bits de source du curseur, et mask pointe vers les données standard décrivant quels pixels de source doivent être dessinés et lesquels doivent être considérés comme transparents. width et height donnent les dimensions du curseur, xHot et yHot indiquent l'emplacement du point chaud du curseur (le point qui sera rapporté lorsque se produira un événement), et fg et bg décrivent les couleurs de premier plan et d'arrière-plan du curseur textuellement (n'importe quel format approprié pour Tk_GetColor peut être utilisé). Normalement, les arguments de Tk_GetCursorFromData sont créés en incluant un fichier de curseur directement dans le code source d'un programme, comme dans l'exemple suivant :

Tk_Cursor cursor;
#include "source.cursor"
#include "mask.cursor"
cursor = Tk_GetCursorFromData(interp, tkwin, source_bits,
    mask_bits, source_width, source_height, source_x_hot,
    source_y_hot, Tk_GetUid("red"), Tk_GetUid("blue"));

Dans des conditions normales, Tk_GetCursorFromData renverra un identifiant pour le curseur demandé. En cas d'erreur lors de la création du curseur, None est renvoyé et un message d'erreur est stocké dans le résultat d'interp.

Tk_AllocCursorFromObj, Tk_GetCursor et Tk_GetCursorFromData maintiennent une base de données de tous les curseurs qu'ils ont créés. Lorsque c'est possible, un appel à Tk_AllocCursorFromObj, Tk_GetCursor ou Tk_GetCursorFromData renverra un curseur existant au lieu d'en créer un nouveau. Cette approche peut réduire considérablement la surcharge du serveur, de sorte que les procédures Tk doivent généralement être préférées aux procédures Xlib telles que XCreateFontCursor ou XCreatePixmapCursor, qui créent un nouveau curseur chaque fois qu'elles sont appelées. Les procédures Tk sont également plus portables que les procédures Xlib de bas niveau.

NOM

L'appel à Tk_GetCursorFromData, ou par tout autre moyen, renvoie une valeur hexadécimale représentant l'identifiant X du curseur. Remarque : la valeur renvoyée par Tk_NameOfCursor n'est garantie de persister que jusqu'à ce que Tk_NameOfCursor soit appelée à nouveau. De plus, cet appel n'est pas portable, à l'exception des curseurs renvoyés par Tk_GetCursor.

Lorsqu'un curseur renvoyé par Tk_AllocCursorFromObj, Tk_GetCursor ou Tk_GetCursorFromData n'est plus nécessaire, Tk_FreeCursorFromObj ou Tk_FreeCursor doit être appelé pour le libérer. Pour Tk_FreeCursorFromObj, le curseur à libérer est spécifié avec les mêmes informations utilisées pour le créer ; pour Tk_FreeCursor, le curseur à libérer est spécifié avec son jeton Tk_Cursor. Il doit y avoir exactement un appel à Tk_FreeCursor pour chaque appel à Tk_AllocCursorFromObj, Tk_GetCursor ou Tk_GetCursorFromData.

BOGUES

Lorsqu'il détermine si un curseur existant peut être utilisé pour satisfaire une nouvelle demande, Tk_AllocCursorFromObj, Tk_GetCursor et Tk_GetCursorFromData ne considèrent que les valeurs immédiates de leurs arguments. Par exemple, lorsqu'un nom de fichier est passé à Tk_GetCursor, Tk_GetCursor suppose qu'il est sûr de réutiliser un curseur créé à partir du même nom de fichier : il ne vérifie pas si le fichier lui-même a changé ou si le répertoire courant a changé, de sorte que le nom peut faire référence à un fichier différent. De même, Tk_GetCursorFromData suppose que si le même pointeur source est utilisé dans deux appels différents, alors les pointeurs font référence aux mêmes données ; il ne vérifie pas si les valeurs réelles des données ont changé.
