Tk_CreateImageType, Tk_GetImageMasterData, Tk_GetImageModelData, Tk_InitImageArgs - définir un nouveau type d'image

Nom de l'image existante.

Pointe vers un mot dans lequel stocker un pointeur vers les informations de type pour l'image donnée, si elle existe.
int argc (entree)
Nombre d'arguments

DESCRIPTION

Tk_CreateImageType est appelée pour définir un nouveau type d'image. Un type d'image correspond à une valeur particulière de l'argument type pour la commande image create. Il peut exister un nombre quelconque de types d'images différents, et de nouveaux types peuvent être définis dynamiquement en appelant Tk_CreateImageType. Par exemple, il pourrait y avoir un type pour les bitmaps 2 couleurs, un autre pour les images multicolores, un autre pour les images tramées, un autre pour la vidéo, etc.

Le code qui implémente un nouveau type d'image est appelé un *gestionnaire d'image*. Il se compose d'une collection de procédures plus trois types différents de structures de données. La première structure de données est une structure Tk_ImageType, qui contient le nom du type d'image et des pointeurs vers cinq procédures fournies par le gestionnaire d'image pour gérer les images de ce type :

typedef struct Tk_ImageType {
    const char *name;
    Tk_ImageCreateProc *createProc;
    Tk_ImageGetProc *getProc;
    Tk_ImageDisplayProc *displayProc;
    Tk_ImageFreeProc *freeProc;
    Tk_ImageDeleteProc *deleteProc;
} Tk_ImageType;
Les champs de cette structure seront décrits dans des sous-sections ultérieures de cette entrée.

La deuxième structure de données majeure manipulée par un gestionnaire d'image est appelée un *modèle d'image* ; elle contient des informations générales sur une image particulière, telles que les valeurs des options de configuration spécifiées dans une commande image create. Il y aura généralement une de ces structures pour chaque invocation de la commande image create.

La troisième structure de données liée aux images est une *instance d'image*. Il y aura généralement une de ces structures pour chaque utilisation d'une image dans un widget particulier. Il est possible qu'une même image apparaisse simultanément dans plusieurs widgets, ou même plusieurs fois dans le même widget. De plus, différentes instances peuvent être sur différents écrans ou affichages. La structure de données d'instance d'image décrit les choses qui peuvent varier d'une instance à l'autre, telles que les couleurs et les contextes graphiques pour le redessin. Il y a généralement une structure d'instance pour chaque option -image spécifiée pour un widget ou un élément de canevas.

Les sous-sections suivantes décrivent plus en détail les champs d'une Tk_ImageType.

NOM

typePtr->name fournit un nom pour le type d'image. Une fois que Tk_CreateImageType est retourné, ce nom peut être utilisé dans les commandes image create pour créer des images du nouveau type. S'il existait déjà un type d'image portant ce nom, le nouveau type d'image remplace l'ancien.

CREATEPROC

typePtr->createProc fournit l'adresse d'une procédure que Tk appellera chaque fois que image create est invoqué pour créer une image du nouveau type. typePtr->createProc doit correspondre au prototype suivant :

typedef int Tk_ImageCreateProc(
        Tcl_Interp *interp,
        const char *name,
        int objc,
        Tcl_Obj *const objv[],
        const Tk_ImageType *typePtr,
        Tk_ImageMaster model,
        ClientData *modelDataPtr);
L'argument interp est l'interpréteur dans lequel la commande image a été invoquée, et name est le nom de la nouvelle image, qui a été soit spécifié explicitement dans la commande image, soit généré automatiquement par la commande image. Les arguments objc et objv décrivent toutes les options de configuration de la nouvelle image (tout ce qui suit l'argument de nom de image). L'argument model est un jeton qui fait référence aux informations de Tk sur cette image ; le gestionnaire d'image doit renvoyer ce jeton à Tk lors de l'appel de la procédure Tk_ImageChanged. Typiquement, createProc analysera objc et objv et créera une structure de données de modèle d'image pour la nouvelle image. createProc peut stocker une valeur arbitraire d'un mot à *modelDataPtr, qui sera renvoyée au gestionnaire d'image lors de l'invocation d'autres callbacks. Typiquement, la valeur est un pointeur vers la structure de données du modèle pour l'image.

Si createProc rencontre une erreur, il doit laisser un message d'erreur dans le résultat de l'interpréteur et retourner TCL_ERROR ; sinon, il doit retourner TCL_OK.

createProc doit appeler Tk_ImageChanged afin de définir la taille de l'image et demander un redessin initial.

GETPROC

typePtr->getProc est appelée par Tk chaque fois qu'un widget appelle Tk_GetImage pour utiliser une image particulière. Cette procédure doit correspondre au prototype suivant :

typedef ClientData Tk_ImageGetProc(
        Tk_Window tkwin,
        ClientData modelData);
L'argument tkwin identifie la fenêtre dans laquelle l'image sera utilisée et modelData est la valeur renvoyée par createProc lors de la création du modèle d'image. getProc créera généralement une structure de données pour la nouvelle instance, incluant des éléments tels que les ressources nécessaires pour afficher l'image dans la fenêtre donnée. getProc renvoie un jeton d'un mot pour l'instance, qui est généralement l'adresse de la structure de données de l'instance. Tk renverra cette valeur au gestionnaire d'image lors de l'invocation de ses procédures displayProc et freeProc.

DISPLAYPROC

typePtr->displayProc est appelée par Tk chaque fois qu'une image doit être affichée (c'est-à-dire chaque fois qu'un widget appelle Tk_RedrawImage). displayProc doit correspondre au prototype suivant :

typedef void Tk_ImageDisplayProc(
        ClientData instanceData,
        Display *display,
        Drawable drawable,
        int imageX,
        int imageY,
        int width,
        int height,
        int drawableX,
        int drawableY);
L'argument instanceData sera identique à la valeur renvoyée par getProc lors de la création de l'instance. display et drawable indiquent où afficher l'image ; drawable peut être un pixmap plutôt que la fenêtre spécifiée à getProc (c'est généralement le cas, car la plupart des widgets utilisent le double buffering pour leur redessin afin d'obtenir des effets visuels plus fluides). imageX, imageY, width et height identifient la région de l'image qui doit être redessinée. Cette région sera toujours dans les limites de la taille de l'image telle que spécifiée dans le dernier appel à Tk_ImageChanged. drawableX et drawableY indiquent où dans drawable l'image doit être affichée ; displayProc doit afficher la région donnée de l'image de sorte que le point (imageX, imageY) dans l'image apparaisse à (drawableX, drawableY) dans drawable.
