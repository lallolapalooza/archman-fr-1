NOM

Tk::event - Facilités d'événements divers : définir des événements virtuels et générer des événements

SYNOPSIS

$widget->eventAction(?arg, arg, ...?);

DESCRIPTION

Les méthodes eventAction fournissent plusieurs facilités pour traiter les événements du système de fenêtrage, tels que la définition d'événements virtuels et la synthèse d'événements. Les événements virtuels sont partagés par tous les widgets du même MainWindow. Différents MainWindows peuvent avoir des événements virtuels différents.

Les méthodes suivantes sont actuellement supportées :

$widget->eventAdd('<<virtuel>>', séquence ?,séquence, ...?)
Associe l'événement virtuel virtuel aux séquences d'événements physiques données par les arguments séquence, de sorte que l'événement virtuel se déclenche chaque fois que l'une des séquences se produit. Virtuel peut être n'importe quelle valeur de chaîne et séquence peut avoir l'une des valeurs autorisées pour l'argument séquence de la méthode bind. Si virtuel est déjà défini, les nouvelles séquences d'événements physiques s'ajoutent aux séquences existantes pour l'événement.
$widget->eventDelete('<<virtuel>>' ?,séquence, séquence, ...?)
Supprime chaque séquence de celles associées à l'événement virtuel donné par virtuel. Virtuel peut être n'importe quelle valeur de chaîne et séquence peut avoir l'une des valeurs autorisées pour l'argument séquence de la méthode bind. Toutes les séquences non actuellement associées à virtuel sont ignorées. Si aucun argument séquence n'est fourni, toutes les séquences d'événements physiques sont supprimées pour virtuel, de sorte que l'événement virtuel ne se déclenchera plus.
$widget->eventGenerate(événement ?,option => valeur, option => valeur, ...?)
Génère un événement de fenêtre et organise son traitement comme s'il provenait du système de fenêtrage. $fenêtre est une référence à la fenêtre pour laquelle l'événement sera généré. Événement fournit une description de base de l'événement, telle que <Shift-Button-2> ou <<Paste>>. Si Fenêtre est vide, l'écran entier est visé, et les coordonnées sont relatives à l'écran. Événement peut avoir l'une des formes permises pour l'argument séquence de la méthode bind, à condition qu'il s'agisse d'un seul modèle d'événement, et non d'une séquence. Les paires option-valeur peuvent être utilisées pour spécifier des attributs supplémentaires de l'événement, tels que la position de la souris x et y ; voir "CHAMPS D'ÉVÉNEMENT" ci-dessous. Si l'option -when n'est pas spécifiée, l'événement est traité immédiatement : tous les gestionnaires de l'événement se termineront avant que la méthode eventGenerate ne retourne. Si l'option -when est spécifiée, elle détermine quand l'événement est traité.
$widget->eventInfo(?'<<virtuel>>'?)
Retourne des informations sur les événements virtuels. Si l'argument <<virtuel>> est omis, la valeur de retour est une liste de tous les événements virtuels actuellement définis. Si <<virtuel>> est spécifié, la valeur de retour est une liste dont les éléments sont les séquences d'événements physiques actuellement définies pour l'événement virtuel donné ; si l'événement virtuel n'est pas défini, undef est retourné.

CHAMPS D'ÉVÉNEMENT

Les options suivantes sont supportées pour la méthode eventGenerate. Elles correspondent aux expansions ``%'' autorisées dans les scripts de rappel pour la méthode bind.

-above => fenêtre
Fenêtre spécifie le champ dessus pour l'événement, soit comme un nom de chemin de fenêtre, soit comme un ID de fenêtre entier. Valide pour les événements Configure. Correspond à la substitution %a pour les scripts de liaison.
-borderwidth => taille
Taille doit être une distance d'écran ; elle spécifie le champ border_width pour l'événement. Valide pour les événements Configure. Correspond à la substitution %B pour les scripts de liaison.
-button => nombre
Nombre doit être un entier ; il spécifie le champ detail pour un événement ButtonPress ou ButtonRelease, remplaçant tout numéro de bouton fourni dans l'argument événement de base. Correspond à la substitution %b pour les scripts de liaison.
-count => nombre
Nombre doit être un entier ; il spécifie le champ count pour l'événement. Valide pour les événements Expose. Correspond à la substitution %c pour les scripts de liaison.
-delta => nombre
nombre doit être un entier ; il spécifie le champ delta pour l'événement MouseWheel. Le delta fait référence à la direction et à l'amplitude de la rotation de la molette de la souris. Notez que la valeur n'est pas une distance d'écran, mais des unités de mouvement dans la molette de la souris. Généralement, ces valeurs sont des multiples de 120. Par exemple, 120 devrait faire défiler le widget texte vers le haut de 4 lignes et -240 ferait défiler le widget texte vers le bas de 8 lignes. Bien sûr, d'autres widgets peuvent définir des comportements différents pour le mouvement de la molette de la souris. Ce champ correspond à la substitution %D pour les scripts de liaison.
-detail => détail
Détail spécifie le champ detail pour l'événement et doit être l'une des valeurs suivantes :
NotifyAncestor         NotifyNonlinearVirtual
NotifyDetailNone       NotifyPointer
NotifyInferior         NotifyPointerRoot
NotifyNonlinear        NotifyVirtual

Valide pour les événements Enter, Leave, FocusIn et FocusOut. Correspond à la substitution %d pour les scripts de liaison.

-focus booléen
Booléen doit être une valeur booléenne ; il spécifie le champ focus pour l'événement. Valide pour les événements Enter et Leave. Correspond à la substitution %f pour les scripts de liaison.
-height taille
Taille doit être une distance d'écran ; elle spécifie le champ height pour l'événement. Valide pour les événements Configure. Correspond à la substitution %h pour les scripts de liaison.
-keycode nombre
Nombre doit être un entier ; il spécifie le champ keycode pour l'événement. Valide pour les événements KeyPress et KeyRelease. Correspond à la substitution %k pour les scripts de liaison.
-keysym nom
Nom doit être le nom d'un keysym valide, tel que g, space, ou Return ; sa valeur keycode correspondante est utilisée comme champ keycode pour l'événement, remplaçant tout détail spécifié dans l'argument événement de base. Valide pour les événements KeyPress et KeyRelease. Correspond à la substitution %K pour les scripts de liaison.
-mode notification
Notification spécifie le champ mode pour l'événement et doit être l'une des valeurs suivantes : NotifyNormal, NotifyGrab, NotifyUngrab, ou NotifyWhileGrabbed. Valide pour les événements Enter, Leave, FocusIn, et FocusOut. Correspond à la substitution %m pour les scripts de liaison.
-override booléen
Booléen doit être une valeur booléenne ; il spécifie le champ override_redirect pour l'événement. Valide pour les événements Map, Reparent, et Configure. Correspond à la substitution %o pour les scripts de liaison.
-place où

PARAMETRES DE L'EVENEMENT

Spécifie le champ place pour l'événement ; il doit être soit PlaceOnTop, soit PlaceOnBottom. Valide pour les événements Circulate. Correspond à la substitution %p pour les scripts de liaison.

-root fenêtre
Fenêtre doit être soit un nom de chemin de fenêtre, soit un identifiant de fenêtre entier ; il spécifie le champ root pour l'événement. Valide pour les événements KeyPress, KeyRelease, ButtonPress, ButtonRelease, Enter, Leave et Motion. Correspond à la substitution %R pour les scripts de liaison.
-rootx coordonnée
Coordonnée doit être une distance d'écran ; elle spécifie le champ x_root pour l'événement. Valide pour les événements KeyPress, KeyRelease, ButtonPress, ButtonRelease, Enter, Leave et Motion. Correspond à la substitution %X pour les scripts de liaison.
-rooty coordonnée
Coordonnée doit être une distance d'écran ; elle spécifie le champ y_root pour l'événement. Valide pour les événements KeyPress, KeyRelease, ButtonPress, ButtonRelease, Enter, Leave et Motion. Correspond à la substitution %Y pour les scripts de liaison.
-sendevent booléen
Booléen doit être une valeur booléenne ; il spécifie le champ send_event pour l'événement. Valide pour tous les événements. Correspond à la substitution %E pour les scripts de liaison.
-serial nombre
Nombre doit être un entier ; il spécifie le champ serial pour l'événement. Valide pour tous les événements. Correspond à la substitution %# pour les scripts de liaison.
-state état
État spécifie le champ state pour l'événement. Pour les événements KeyPress, KeyRelease, ButtonPress, ButtonRelease, Enter, Leave et Motion, il doit s'agir d'une valeur entière. Pour les événements Visibility, il doit s'agir de l'une des valeurs VisibilityUnobscured, VisibilityPartiallyObscured ou VisibilityFullyObscured. Cette option remplace tous les modificateurs tels que Meta ou Control spécifiés dans l'événement de base. Correspond à la substitution %s pour les scripts de liaison.
-subwindow fenêtre
Fenêtre spécifie le champ subwindow de l'événement, soit sous forme de nom de chemin pour un widget Tk, soit sous forme d'identifiant de fenêtre entier. Valide pour les événements KeyPress, KeyRelease, ButtonPress, ButtonRelease, Enter, Leave et Motion. Similaire à la substitution %S pour les scripts de liaison.
-time entier
Entier doit être une valeur entière ; il spécifie le champ time pour l'événement. Valide pour les événements KeyPress, KeyRelease, ButtonPress, ButtonRelease, Enter, Leave, Motion et Property. Correspond à la substitution %t pour les scripts de liaison.
-warp booléen
Booléen doit être une valeur booléenne ; il spécifie si le pointeur de l'écran doit également être déplacé. Valide pour les événements KeyPress, KeyRelease, ButtonPress, ButtonRelease et Motion.
-width taille
Taille doit être une distance d'écran ; elle spécifie le champ width pour l'événement. Valide pour les événements Configure. Correspond à la substitution %w pour les scripts de liaison.
-when quand
Quand détermine le moment où l'événement sera traité ; il doit avoir l'une des valeurs suivantes :
now
Traiter l'événement immédiatement, avant que la commande ne retourne. C'est également ce qui se passe si l'option -when est omise.
tail
Placer l'événement dans la file d'attente d'événements de perl/Tk derrière tous les événements déjà mis en file d'attente pour cette application.
head
Placer l'événement au début de la file d'attente d'événements de perl/Tk, afin qu'il soit traité avant tous les autres événements déjà mis en file d'attente.
mark
Placer l'événement au début de la file d'attente d'événements de perl/Tk, mais derrière tous les autres événements déjà mis en file d'attente avec -when mark. Cette option est utile lors de la génération d'une série d'événements qui doivent être traités dans l'ordre, mais au début de la file d'attente.
-x coordonnée
Coordonnée doit être une distance d'écran ; elle spécifie le champ x pour l'événement. Valide pour les événements KeyPress, KeyRelease, ButtonPress, ButtonRelease, Motion, Enter, Leave, Expose, Configure, Gravity et Reparent. Correspond à la substitution %x pour les scripts de liaison. Si Fenêtre est vide, la coordonnée est relative à l'écran, et cette option correspond à la substitution %X pour les scripts de liaison.
-y coordonnée
Coordonnée doit être une distance d'écran ; elle spécifie le champ y pour l'événement. Valide pour les événements KeyPress, KeyRelease, ButtonPress, ButtonRelease, Motion, Enter, Leave, Expose, Configure, Gravity et Reparent. Correspond à la substitution %y pour les scripts de liaison. Si Fenêtre est vide, la coordonnée est relative à l'écran, et cette option correspond à la substitution %Y pour les scripts de liaison.

Toutes les options qui ne sont pas spécifiées lors de la génération d'un événement sont remplies avec la valeur 0, à l'exception de serial, qui est remplie avec le prochain numéro de série d'événement X.

EXEMPLES D'EVENEMENT VIRTUEL

Pour qu'une liaison d'événement virtuel se déclenche, deux choses doivent se produire. Premièrement, l'événement virtuel doit être défini avec la méthode eventAdd. Deuxièmement, une liaison doit être créée pour l'événement virtuel avec la méthode bind. Considérons les définitions d'événements virtuels suivantes :

$widget->eventAdd('<<Paste>>' => '<Control-y>');
$widget->eventAdd('<<Paste>>' => '<Button-2>');
$widget->eventAdd('<<Save>>' => '<Control-X><Control-S>');
$widget->eventAdd('<<Save>>' => '<Shift-F12>');

Dans la méthode bind, un événement virtuel peut être lié comme tout autre type d'événement intégré, comme suit :

$entry->bind('Tk::Entry', '<<Paste>>' => sub {
               $entry->Insert($entry->selectionGet) });

Les doubles crochets sont utilisés pour spécifier qu'un événement virtuel est en cours de liaison. Si l'utilisateur tape Control-y ou appuie sur le bouton 2, ou si un événement virtuel <<Paste>> est synthétisé avec eventGenerate, alors la liaison <<Paste>> sera invoquée.

Si une liaison virtuelle a la même séquence qu'une liaison physique distincte, la liaison physique aura la priorité. Considérons l'exemple suivant :

$mw->eventAdd('<<Paste>>' => '<Control-y>','<Meta-Control-y>');
$mw->bind('Tk::Entry', '<Control-y>' => sub{print 'Control-y'});
$mw->bind('Tk::Entry', '<<Paste>>'   => sub{print 'Paste'});

Lorsque l'utilisateur tape Control-y, la liaison <Control-y> sera invoquée, car un événement physique est considéré comme plus spécifique qu'un événement virtuel, toutes choses égales par ailleurs. Cependant, lorsque l'utilisateur tape Meta-Control-y, la liaison <<Paste>> sera invoquée, car le modificateur Meta dans le motif physique associé à la liaison virtuelle est plus spécifique que la séquence <Control-y> pour l'événement physique.

Les liaisons sur un événement virtuel peuvent être créées avant que l'événement virtuel n'existe. En fait, l'événement virtuel n'a jamais réellement besoin d'être défini, par exemple sur des plateformes où l'événement virtuel serait dénué de sens ou impossible à générer.

Lorsqu'une définition d'événement virtuel change à l'exécution, toutes les fenêtres réagiront immédiatement à la nouvelle définition. En partant de l'exemple précédent, si le code suivant est exécuté :

$entry->bind(ref($entry), '<Control-y>' => undef);
$entry->eventAdd('<<Paste>>' => '<Key-F6>');

le comportement changera de deux manières. Premièrement, la liaison masquée <<Paste>> réapparaîtra. Taper Control-y n'invoquera plus la liaison <Control-y>, mais l'événement virtuel <<Paste>>. Deuxièmement, appuyer sur la touche F6 invoquera désormais également la liaison <<Paste>>.
