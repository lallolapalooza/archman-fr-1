ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur dans lequel l'image a été créée et dans lequel les rapports d'erreur doivent être effectués.
const char *imageName (entrée)
Nom de l'image photo.
Tk_PhotoHandle handle (entrée)
Handle opaque identifiant l'image photo à affecter.
Tk_PhotoImageBlock *blockPtr (entrée)
Spécifie l'adresse et la disposition de stockage des données d'image.
int x (entrée)
Spécifie la coordonnée X où le coin supérieur gauche du bloc doit être placé dans l'image.
int y (entrée)
Spécifie la coordonnée Y où le coin supérieur gauche du bloc doit être placé dans l'image.
int width (entrée)
Spécifie la largeur de la zone d'image à affecter (pour Tk_PhotoPutBlock) ou la largeur d'image souhaitée (pour Tk_PhotoExpand et Tk_PhotoSetSize).
int compRule (entrée)
Spécifie la règle de composition utilisée lors de la combinaison de pixels transparents dans un bloc de données avec une image photo. Doit être l'une des valeurs TK_PHOTO_COMPOSITE_OVERLAY (qui place le bloc de données par-dessus l'image photo existante, avec le contenu précédent visible à travers les bits transparents) ou TK_PHOTO_COMPOSITE_SET (qui ignore le contenu précédent de l'image photo dans le rectangle couvert par le bloc de données).
int height (entrée)
Spécifie la hauteur de la zone d'image à affecter (pour Tk_PhotoPutBlock) ou la hauteur d'image souhaitée (pour Tk_PhotoExpand et Tk_PhotoSetSize).
int *widthPtr (sortie)
Pointeur vers l'emplacement où stocker la largeur de l'image.
int *heightPtr (sortie)
Pointeur vers l'emplacement où stocker la hauteur de l'image.
int subsampleX (entrée)
Spécifie le facteur de sous-échantillonnage dans la direction X pour les données d'image d'entrée.
int subsampleY (entrée)
Spécifie le facteur de sous-échantillonnage dans la direction Y pour les données d'image d'entrée.
int zoomX (entrée)
Spécifie le facteur de zoom à appliquer dans la direction X aux pixels écrits dans l'image photo.
int zoomY (entrée)
Spécifie le facteur de zoom à appliquer dans la direction Y aux pixels écrits dans l'image photo.

DESCRIPTION

Tk_FindPhoto renvoie un handle opaque qui est utilisé pour identifier une image photo particulière aux autres procédures. Le paramètre est le nom de l'image, c'est-à-dire le nom spécifié à la commande image create photo, ou attribué par cette commande si aucun nom n'a été spécifié. Si imageName n'existe pas ou n'est pas une image photo, Tk_FindPhoto renvoie NULL.

Tk_PhotoPutBlock est utilisé pour fournir des blocs de données d'image à afficher. L'appel affecte une zone de l'image de taille width x height pixels, avec son coin supérieur gauche aux coordonnées (x,y). Toutes les valeurs de width, height, x, et y doivent être non négatives. Si une partie de cette zone se trouve en dehors des limites actuelles de l'image, l'image sera étendue pour inclure la zone, à moins que l'utilisateur n'ait spécifié une taille d'image explicite avec les options de configuration du widget -width et/ou -height (voir photo(n)) ; dans ce cas, la zone est silencieusement coupée aux limites de l'image.

Le paramètre block est un pointeur vers une structure Tk_PhotoImageBlock, définie comme suit :

typedef struct {
    unsigned char *pixelPtr;
    int width;
    int height;
    int pitch;
    int pixelSize;
    int offset[4];
} Tk_PhotoImageBlock;
Le champ pixelPtr pointe vers le premier pixel, c'est-à-dire le pixel supérieur gauche du bloc. Les champs width et height spécifient les dimensions du bloc de pixels. Le champ pixelSize spécifie la différence d'adresse entre deux pixels horizontalement adjacents. Il doit être de 4 pour les données d'image RVB et de 2 pour les données d'image en niveaux de gris. D'autres valeurs sont possibles, si les décalages dans le tableau offset sont ajustés en conséquence (par exemple, pour des données rouges, vertes et bleues stockées dans des plans différents). L'utilisation d'une telle disposition est fortement déconseillée, cependant. En raison d'un bug, cela pourrait ne pas fonctionner correctement si un canal alpha est fourni. (voir la section BUGS ci-dessous). Le champ pitch spécifie la différence d'adresse entre deux pixels verticalement adjacents. Le tableau offset contient les décalages depuis l'adresse d'un pixel vers les adresses des octets contenant les composantes rouge, verte, bleue et alpha (transparence). Si les décalages pour le rouge, le vert et le bleu sont égaux, l'image est interprétée comme étant en niveaux de gris. S'ils diffèrent, des données RVB sont supposées. Normalement, les décalages seront de 0, 1, 2, 3 pour les données RVB et 0, 0, 0, 1 pour les niveaux de gris. Il est possible de fournir des données d'image sans canal alpha en définissant le décalage alpha à une valeur négative et en ajustant le champ pixelSize en conséquence. Cette utilisation est toutefois déconseillée (voir la section BUGS ci-dessous).

Le paramètre compRule de Tk_PhotoPutBlock spécifie une règle de composition indiquant quoi faire avec les pixels transparents. La valeur TK_PHOTO_COMPOSITE_OVERLAY indique que le contenu précédent de l'image photo doit rester visible, et la valeur TK_PHOTO_COMPOSITE_SET indique que le contenu précédent de l'image photo doit être complètement ignoré, et que les valeurs du bloc doivent être copiées directement. Le comportement dans Tk8.3 et antérieur était équivalent à avoir TK_PHOTO_COMPOSITE_OVERLAY comme règle de composition.

Les valeurs fournies pour les paramètres width et height de Tk_PhotoPutBlock ne correspondent pas nécessairement aux valeurs spécifiées dans block. Si elles sont plus petites, Tk_PhotoPutBlock extrait un sous-bloc des données d'image fournies. Si elles sont plus grandes, les données fournies sont répliquées (de manière répétitive) pour remplir la zone spécifiée. Ces règles fonctionnent indépendamment dans les directions horizontale et verticale.

Tk_PhotoPutBlock renvoie normalement TCL_OK, bien que s'il ne peut pas allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est retourné à la place et, si l'argument interp n'est pas NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoPutZoomedBlock fonctionne comme Tk_PhotoPutBlock sauf que l'image peut être réduite ou agrandie pour l'affichage. Les paramètres subsampleX et subsampleY permettent de réduire la taille de l'image par sous-échantillonnage. Tk_PhotoPutZoomedBlock n'utilisera que les pixels de l'image d'entrée dont les coordonnées X sont des multiples de subsampleX, et dont les coordonnées Y sont des multiples de subsampleY. Par exemple, une image de 512x512 pixels peut être réduite à 256x256 en réglant subsampleX et subsampleY sur 2.

Les paramètres zoomX et zoomY permettent d'agrandir l'image par réplication de pixels. Chaque pixel de l'image d'entrée (éventuellement sous-échantillonnée) sera écrit dans un bloc de zoomX pixels de large et zoomY pixels de haut de l'image affichée. Le sous-échantillonnage et le zoom peuvent être utilisés ensemble pour des effets spéciaux.

Tk_PhotoGetImage peut être utilisé pour récupérer des données d'image d'une image photo. Tk_PhotoGetImage remplit la structure pointée par le paramètre blockPtr avec des valeurs décrivant l'adresse et la disposition des données d'image que l'image photo a stockées en interne. Les valeurs sont valides jusqu'à ce que l'image soit détruite ou que sa taille soit modifiée.

Il est possible de modifier une image en écrivant directement dans les données pointées par le champ pixelPtr. La taille de l'image ne peut cependant pas être modifiée de cette manière.
