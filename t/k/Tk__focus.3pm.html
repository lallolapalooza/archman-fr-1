NOM

Tk::focus - Gérer le focus d'entrée

SYNTAXE

   $widget->focus

   $widget->focusOption

   $widget->focusNext

   $widget->focusPrev

   $widget->focusFollowsMouse

DESCRIPTION

Les méthodes focus sont utilisées pour gérer le focus d'entrée Tk. À tout moment, une fenêtre sur chaque écran est désignée comme la fenêtre de *focus* ; toute pression ou relâchement de touche pour cet écran est envoyé à cette fenêtre. Normalement, c'est au gestionnaire de fenêtres de rediriger le focus entre les fenêtres de niveau supérieur d'un écran. Par exemple, certains gestionnaires de fenêtres définissent automatiquement le focus d'entrée sur une fenêtre de niveau supérieur lorsque la souris y entre ; d'autres redirigent le focus d'entrée uniquement lorsque l'utilisateur clique sur une fenêtre. Habituellement, le gestionnaire de fenêtres ne définit le focus que pour les fenêtres de niveau supérieur, laissant à l'application le soin de rediriger le focus entre les enfants de la fenêtre de niveau supérieur.

Tk se souvient d'une fenêtre de focus pour chaque fenêtre de niveau supérieur (le descendant le plus récent de cette fenêtre de niveau supérieur à recevoir le focus) ; lorsque le gestionnaire de fenêtres donne le focus à une fenêtre de niveau supérieur, Tk la redirige automatiquement vers la fenêtre mémorisée. Au sein d'une fenêtre Tk de niveau supérieur, Tk utilise par défaut un modèle de focus *explicite*. Déplacer la souris dans une fenêtre de niveau supérieur ne change normalement pas le focus ; le focus ne change que lorsqu'un widget décide explicitement de revendiquer le focus (par exemple, suite à un clic sur un bouton), ou lorsque l'utilisateur tape une touche comme Tab qui déplace le focus.

La méthode focusFollowsMouse peut être appelée pour créer un modèle de focus *implicite* : elle reconfigure Tk de sorte que le focus soit défini sur une fenêtre chaque fois que la souris y entre. Les méthodes focusNext et focusPrev implémentent un ordre de focus parmi les fenêtres d'une fenêtre de niveau supérieur ; elles sont utilisées dans les liaisons par défaut pour Tab et Shift-Tab, entre autres.

Les méthodes focus peuvent prendre l'une des formes suivantes :

$widget->focusCurrent
Retourne la fenêtre de focus sur l'écran contenant $widget, ou une chaîne vide si aucune fenêtre de cette application n'a le focus sur cet écran.
$widget->focus
Si l'application a actuellement le focus d'entrée sur l'écran de $widget, cette commande réinitialise le focus d'entrée pour l'écran de $widget à $widget et retourne une chaîne vide. Si l'application n'a pas actuellement le focus d'entrée sur l'écran de $widget, $widget sera mémorisé comme le focus pour sa fenêtre de niveau supérieur ; la prochaine fois que le focus arrivera à la fenêtre de niveau supérieur, Tk le redirigera vers $widget.
$widget->focusForce
Définit le focus de l'écran de $widget à $widget, même si l'application n'a pas actuellement le focus d'entrée pour l'écran. Cette commande doit être utilisée avec parcimonie, voire pas du tout. En usage normal, une application ne doit pas revendiquer le focus pour elle-même ; elle doit plutôt attendre que le gestionnaire de fenêtres lui donne le focus.
$widget->focusLastfor
Retourne le nom de la fenêtre la plus récente à avoir eu le focus d'entrée parmi toutes les fenêtres du même niveau supérieur que $widget. Si aucune fenêtre de ce niveau supérieur n'a jamais eu le focus d'entrée, ou si la fenêtre de focus la plus récente a été supprimée, alors la fenêtre de niveau supérieur est retournée. La valeur de retour est la fenêtre qui recevra le focus d'entrée la prochaine fois que le gestionnaire de fenêtres donnera le focus à la fenêtre de niveau supérieur.
$widget->focusNext
$widget->focusPrev
focusNext est une méthode utilitaire utilisée pour le déplacement au clavier, mais elle peut être utile dans d'autres contextes. Elle définit le focus sur la fenêtre ``suivante'' après $widget dans l'ordre de focus. L'ordre de focus est déterminé par l'ordre d'empilement des fenêtres et la structure de la hiérarchie des fenêtres. Parmi les frères et sœurs, l'ordre de focus est le même que l'ordre d'empilement, la fenêtre la plus basse étant la première. Si une fenêtre a des enfants, la fenêtre est visitée en premier, suivie de ses enfants (récursivement), suivie de son frère et sœur suivant. Les fenêtres de niveau supérieur autres que $widget sont ignorées, de sorte que focusNext ne retourne jamais une fenêtre dans un niveau supérieur différent de $widget.

Après avoir calculé la fenêtre suivante, focusNext examine l'option -takefocus de la fenêtre pour voir si elle doit être ignorée. Si c'est le cas, focusNext continue vers la fenêtre suivante dans l'ordre de focus, jusqu'à ce qu'elle trouve une fenêtre qui accepte le focus ou revienne à $widget.

focusPrev est similaire à focusNext sauf qu'elle définit le focus sur la fenêtre juste avant $widget dans l'ordre de focus.

$widget->focusFollowsMouse
focusFollowsMouse change le modèle de focus de l'application en un modèle implicite où la fenêtre sous la souris obtient le focus. Après l'appel de cette procédure, chaque fois que la souris entre dans une fenêtre, Tk lui donnera automatiquement le focus d'entrée. La commande focus peut être utilisée pour déplacer le focus vers une fenêtre autre que celle sous la souris, mais dès que la souris entre dans une nouvelle fenêtre, le focus sautera sur cette fenêtre. Remarque : il n'existe actuellement aucun support intégré pour ramener l'application à un modèle de focus explicite ; pour ce faire, vous devrez écrire un script qui supprime les liaisons créées par focusFollowsMouse.

QUIRKS

Lorsqu'une fenêtre interne reçoit le focus d'entrée, Tk ne définit pas réellement le focus X sur cette fenêtre ; en ce qui concerne X, le focus restera sur la fenêtre de niveau supérieur contenant la fenêtre avec le focus. Cependant, Tk génère des événements FocusIn et FocusOut comme si le focus X était sur la fenêtre interne. Cette approche évite un certain nombre de problèmes qui surviendraient si le focus X était réellement déplacé ; le fait que le focus X soit sur la fenêtre de niveau supérieur est invisible à moins que vous n'utilisiez du code C pour interroger directement le serveur X.

ATTENTION

Notez que pour le widget Canvas, l'appel à focus doit être entièrement qualifié. En effet, il existe déjà une méthode focus pour le widget Canvas, qui définit le focus sur des étiquettes individuelles du canvas.

    $canvas->Tk::focus

NAME

Tk::focus - Widget focus management

SYNOPSIS

use Tk;
use Tk::focus qw(tk_focusFollowsMouse tk_focusNextWindow tk_focusPrevWindow tk_setFocus);

# ... Tk initialization ...

# Example usage:
tk_focusFollowsMouse($toplevel);
my $widget = tk_focusNextWindow($current_widget);
tk_setFocus($new_focus_widget);

DESCRIPTION

The Tk::focus module provides functions for managing keyboard focus within a Tk application. Focus determines which widget receives keyboard events.

QUIRKS

  • Focus behavior can be complex and depend on the window manager and the specific Tk version.
  • Some widgets might not be focusable by default.

CAVEATS

  • Ensure that the widgets you are manipulating with focus functions actually exist and are visible.
  • Avoid setting focus programmatically in a way that conflicts with user interaction or the window manager's focus policies.

KEYWORDS

Tk, Perl, GUI, focus, keyboard, widget
