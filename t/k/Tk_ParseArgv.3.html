Tk_ParseArgv(3) Procédures de la bibliothèque Tk Tk_ParseArgv(3)

NOM

Tk_ParseArgv - traiter les options de la ligne de commande

SYNTAXE

#include <tk.h>

int
Tk_ParseArgv(interp, tkwin, argcPtr, argv, argTable, flags)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur à utiliser pour renvoyer les messages d'erreur.
Tk_Window tkwin (in)
Fenêtre à utiliser lorsque les arguments spécifient des options Tk. Si NULL, aucune option Tk ne sera traitée.
int argcPtr (in/out)
Pointeur vers le nombre d'arguments dans argv ; est modifié pour contenir le nombre d'arguments non traités restants après l'appel.
const char **argv (in/out)
Arguments de la ligne de commande passés au programme principal. Modifié pour contenir les arguments non traités restants après l'appel.
Tk_ArgvInfo *argTable (in)
Tableau de descripteurs d'arguments, terminé par un élément de type TK_ARGV_END.
int flags (in)
Si non nul, il spécifie un ou plusieurs indicateurs qui contrôlent l'analyse des arguments. Différents indicateurs peuvent être combinés avec un OU bit à bit. Les indicateurs actuellement définis sont TK_ARGV_DONT_SKIP_FIRST_ARG, TK_ARGV_NO_ABBREV, TK_ARGV_NO_LEFTOVERS, et TK_ARGV_NO_DEFAULTS.

DESCRIPTION

Tk_ParseArgv traite un tableau d'arguments de ligne de commande conformément à un tableau décrivant les types d'arguments attendus. Chacun des arguments de argv est traité tour à tour : s'il correspond à l'une des entrées de argTable, l'argument est traité selon cette entrée et écarté. Les arguments qui ne correspondent à rien dans argTable sont copiés au début de argv (en conservant leur ordre original) et renvoyés à l'appelant. À la fin de l'appel, Tk_ParseArgv positionne *argcPtr pour contenir le nombre d'arguments restants dans argv, et argv[*argcPtr] contiendra la valeur NULL. Normalement, Tk_ParseArgv suppose que argv[0] est un nom de commande, il est donc traité comme un argument ne correspondant pas à argTable et renvoyé à l'appelant ; cependant, si le bit TK_ARGV_DONT_SKIP_FIRST_ARG est défini dans flags, alors argv[0] sera traité comme les autres éléments de argv.

Tk_ParseArgv renvoie normalement la valeur TCL_OK. Si une erreur se produit lors de l'analyse des arguments, alors TCL_ERROR est renvoyé et Tk_ParseArgv laissera un message d'erreur dans le résultat de l'interpréteur interp de la manière standard de Tcl. En cas de retour d'erreur, *argvPtr n'aura pas été modifié, mais argv aurait pu être partiellement modifié. Les causes possibles d'erreurs sont expliquées ci-dessous.

Le tableau argTable spécifie les types d'arguments attendus ; chacune de ses entrées a la structure suivante :

typedef struct {
    const char *key;
    int type;
    char *src;
    char *dst;
    const char *help;
} Tk_ArgvInfo;
Le champ key est une chaîne de caractères telle que “-display” ou “-bg” qui est comparée aux valeurs de argv. Type indique comment traiter un argument qui correspond à key (plus à ce sujet ci-dessous). Src et dst sont des valeurs supplémentaires utilisées pour traiter l'argument. Leur utilisation exacte dépend de type, mais typiquement src indique une valeur et dst indique où stocker la valeur. Les déclarations char * pour src et dst sont des espaces réservés : les types réels peuvent être différents. Enfin, help est une chaîne donnant une brève description de cette option ; cette chaîne est imprimée lorsque les utilisateurs demandent de l'aide sur les options de la ligne de commande.

Lors du traitement d'un argument dans argv, Tk_ParseArgv compare l'argument à chacun des key de argTable. Tk_ParseArgv sélectionne le premier spécificateur dont le key correspond exactement à l'argument, s'il existe. Sinon, Tk_ParseArgv sélectionne un spécificateur pour lequel l'argument est une abréviation unique. Si l'argument est une abréviation unique pour plus d'un spécificateur, une erreur est renvoyée. S'il n'y a pas d'entrée correspondante dans argTable, l'argument est ignoré et renvoyé à l'appelant.

Une fois qu'un spécificateur d'argument correspondant est trouvé, Tk_ParseArgv traite l'argument selon le champ type du spécificateur. L'argument qui a correspondu à key est appelé “l'argument correspondant” dans les descriptions ci-dessous. Dans le cadre du traitement, Tk_ParseArgv peut également utiliser l'argument suivant dans argv après l'argument correspondant, appelé “l'argument suivant”. Les valeurs légales pour type, et le traitement qu'elles provoquent, sont les suivantes :

TK_ARGV_END
Marque la fin du tableau. La dernière entrée de argTable doit avoir ce type ; tous ses autres champs sont ignorés et elle ne correspondra jamais à aucun argument.
TK_ARGV_CONSTANT
Src est traité comme un entier et dst comme un pointeur vers un entier. Src est stocké dans *dst. L'argument correspondant est écarté.
TK_ARGV_INT
L'argument suivant doit contenir une chaîne représentant un entier dans le format accepté par strtol (par exemple, les préfixes “0” et “0x” peuvent être utilisés pour spécifier des nombres octaux ou hexadécimaux, respectivement). Dst est traité comme un pointeur vers un entier ; l'argument suivant est converti en une valeur entière et stocké dans *dst. Src est ignoré. Les arguments correspondant et suivant sont écartés de argv.
TK_ARGV_FLOAT
L'argument suivant doit contenir un nombre à virgule flottante dans le format accepté par strtol. Dst est traité comme l'adresse d'une valeur à virgule flottante double précision ; l'argument suivant est converti en une valeur double précision et stocké dans *dst. Les arguments correspondant et suivant sont écartés de argv.
TK_ARGV_STRING
Dans cette forme, dst est traité comme un pointeur vers un (char *); Tk_ParseArgv stocke dans *dst un pointeur vers l'argument suivant, et écarte les arguments correspondant et suivant de argv. Src est ignoré.
TK_ARGV_UID
Cette forme est similaire à TK_ARGV_STRING, sauf que l'argument est transformé en un Tk_Uid en appelant Tk_GetUid. Dst est traité comme un pointeur vers un Tk_Uid ; Tk_ParseArgv stocke dans *dst le Tk_Uid correspondant à l'argument suivant, et écarte les arguments correspondant et suivant de argv. Src est ignoré.
TK_ARGV_CONST_OPTION
Cette forme provoque la définition d'une option Tk (comme si la commande option avait été invoquée). Le champ src est traité comme un pointeur vers une chaîne donnant la valeur d'une option, et dst est traité comme un pointeur vers le nom de l'option. L'argument correspondant est écarté. Si tkwin est NULL, alors les spécificateurs d'arguments de ce type sont ignorés (comme s'ils n'existaient pas).
TK_ARGV_OPTION_VALUE
Cette forme est similaire à TK_ARGV_CONST_OPTION, sauf que la valeur de l'option est prise de l'argument suivant au lieu de src. Dst est utilisé comme nom de l'option. Src est ignoré. Les arguments correspondant et suivant sont écartés. Si tkwin est NULL, alors les spécificateurs d'arguments de ce type sont ignorés (comme s'ils n'existaient pas).
TK_ARGV_OPTION_NAME_VALUE
Dans ce cas, l'argument suivant est pris comme nom d'une option Tk et l'argument suivant est pris comme valeur pour cette option. Src et dst sont ignorés. Les trois arguments sont écartés de argv. Si tkwin est NULL, alors les spécificateurs d'arguments de ce type sont ignorés (comme s'ils n'existaient pas).
TK_ARGV_HELP

Tk_ParseArgv 3

NAME

Tk_ParseArgv - parse command-line options

SYNOPSIS

#include <tk.h>

int
Tk_ParseArgv(interp, tkwin, argcPtr, argv, argTable, flags)
    Tcl_Interp *interp;
    Tk_Window tkwin;
    int *argcPtr;
    char **argv;
    Tk_ArgvInfo argTable[];
    int flags;

ARGUMENTS

interp
Interpreter to use for reporting errors.
tkwin
Window to use for error messages.
argcPtr
Address of integer containing the number of arguments in argv. This value will be updated by the procedure to reflect the number of arguments that were not processed.
argv
Array of strings containing the command-line arguments to parse. Arguments that are processed are removed from this array, and the remaining arguments are compacted to the front of the array.
argTable
Array of Tk_ArgvInfo structures describing the options that should be recognized. The table is terminated by an entry with a NULL key.
flags
Bitfield of option flags. See the FLAGS section below.

DESCRIPTION

Tk_ParseArgv is a procedure that provides a general mechanism for parsing command-line options. It processes the arguments in the argv array, matching them against entries in the argTable array. For each matching argument, it performs an action specified by the type field of the corresponding Tk_ArgvInfo structure.

The Tk_ArgvInfo structure has the following form:

typedef struct {
    char *key;
    int type;
    char *src;
    char *dst;
    char *help;
} Tk_ArgvInfo;
TK_ARGV_CONSTANT
The argument is expected to have no value; its presence indicates that the integer value at *src should be stored in the integer location pointed to by dst. The src field is not used for this option type.
TK_ARGV_INT
The argument is expected to have an integer value. The integer value is converted from the argument string and stored in the integer location pointed to by dst.
TK_ARGV_STRING
The argument is expected to have a string value. The string value is copied into the string location pointed to by dst.
TK_ARGV_REST
This option is used by programs or commands that allow the last several of their options to be the name and/or options for some other program. If a TK_ARGV_REST argument is found, then Tk_ParseArgv does not process any of the remaining arguments; it returns them all at the beginning of argv (along with any other unprocessed arguments). In addition, Tk_ParseArgv treats dst as the address of an integer value, and stores at *dst the index of the first of the TK_ARGV_REST options in the returned argv. This allows the program to distinguish the TK_ARGV_REST options from other unprocessed options that preceded the TK_ARGV_REST.
TK_ARGV_HELP
If this option is encountered, Tk_ParseArgv formats a message describing all the valid arguments. The message is placed in interpreter interp's result and Tk_ParseArgv returns TCL_ERROR. When this happens, the caller normally prints the help message and aborts. If the key field of a TK_ARGV_HELP specifier is NULL, then the specifier will never match any arguments; in this case the specifier simply provides extra documentation, which will be included when some other TK_ARGV_HELP entry causes help information to be returned.
TK_ARGV_FUNC
For this kind of argument, src is treated as the address of a procedure, which is invoked to process the following argument. The procedure should have the following structure:
int
func(dst, key, nextArg)
    char *dst;
    char *key;
    char *nextArg;
{
}
The dst and key parameters will contain the corresponding fields from the argTable entry, and nextArg will point to the following argument from argv (or NULL if there are not any more arguments left in argv). If func uses nextArg (so that Tk_ParseArgv should discard it), then it should return 1. Otherwise it should return 0 and TkParseArgv will process the following argument in the normal fashion. In either event the matching argument is discarded.
TK_ARGV_GENFUNC
This form provides a more general procedural escape. It treats src as the address of a procedure, and passes that procedure all of the remaining arguments. The procedure should have the following form:
int
genfunc(dst, interp, key, argc, argv)
    char *dst;
    Tcl_Interp *interp;
    char *key;
    int argc;
    char **argv;
{
}
The dst and key parameters will contain the corresponding fields from the argTable entry. Interp will be the same as the interp argument to Tcl_ParseArgv. Argc and argv refer to all of the options after the matching one. Genfunc should behave in a fashion similar to Tk_ParseArgv: parse as many of the remaining arguments as it can, then return any that are left by compacting them to the beginning of argv (starting at argv[0]). Genfunc should return a count of how many arguments are left in argv; Tk_ParseArgv will process them. If genfunc encounters an error then it should leave an error message in interpreter interp's result, in the usual Tcl fashion, and return -1; when this happens Tk_ParseArgv will abort its processing and return TCL_ERROR.

FLAGS

TK_ARGV_DONT_SKIP_FIRST_ARG
Tk_ParseArgv normally treats argv[0] as a program or command name, and returns it to the caller just as if it had not matched argTable. If this flag is given, then argv[0] is not given special treatment.
TK_ARGV_NO_ABBREV
Normally, Tk_ParseArgv accepts unique abbreviations for key values in argTable. If this flag is given then only exact matches will be acceptable.
TK_ARGV_NO_LEFTOVERS
Normally, Tk_ParseArgv returns unrecognized arguments to the caller. If this bit is set in flags then Tk_ParseArgv will return an error if it encounters any argument that does not match argTable. The only exception to this rule is argv[0], which will be returned to the caller with no errors as long as TK_ARGV_DONT_SKIP_FIRST_ARG is not specified.
TK_ARGV_NO_DEFAULTS
Normally, Tk_ParseArgv searches an internal table of standard argument specifiers in addition to argTable. If this bit is set in flags, then Tk_ParseArgv will use only argTable and not its default table.

EXAMPLE

Here is an example definition of an argTable and some sample command lines that use the options. Note the effect on argc and argv; arguments processed by Tk_ParseArgv are eliminated from argv, and argc is updated to reflect reduced number of arguments.

/*
 * Define and set default values for globals.
 */
int debugFlag = 0;
int numReps = 100;
char defaultFileName[] = "out";
char *fileName = defaultFileName;
Boolean exec = FALSE;
/*
 * Define option descriptions.
 */
Tk_ArgvInfo argTable[] = {
    {"-X", TK_ARGV_CONSTANT, (char *) 1, (char *) &debugFlag,
        "Turn on debugging printfs"},
    {"-N", TK_ARGV_INT, NULL, (char *) &numReps,
        "Number of repetitions"},
    {"-of", TK_ARGV_STRING, NULL, (char *) &fileName,
        "Name of file for output"},
    {"x", TK_ARGV_REST, NULL, (char *) &exec,
        "File to exec, followed by any arguments (must be last argument)."},
    {NULL, TK_ARGV_END, NULL, NULL,
        NULL}
};
main(argc, argv)
    int argc;
    char *argv[];
{
    ...
    if (Tk_ParseArgv(interp, tkwin, &argc, argv, argTable, 0) != TCL_OK) {
        fprintf(stderr, "%s\n", Tcl_GetString(Tcl_GetObjResult(interp)));
        exit(1);
    }
    /*
     * Remainder of the program.
     */
}

Note that default values can be assigned to variables named in argTable: the variables will only be overwritten if the particular arguments are present in argv. Here are some example command lines and their effects.

prog -N 200 infile        # just sets the numReps variable to 200
prog -of out200 infile    # sets fileName to reference "out200"
prog -XN 10 infile        # sets the debug flag, also sets numReps
In all of the above examples, argc will be set by Tk_ParseArgv to 2, argv[0] will be “prog”, argv[1] will be “infile”, and argv[2] will be NULL.

KEYWORDS

arguments, command line, options
