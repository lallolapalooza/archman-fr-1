ARGUMENTS

Tcl_Interp *interp (entrée)
Un interpréteur Tcl. La plupart des procédures utilisent ceci uniquement pour retourner des messages d'erreur ; s'il est NULL, aucun message d'erreur n'est retourné. Pour Tk_CreateOptionTable, la valeur ne peut pas être NULL ; elle donne l'interpréteur dans lequel la table d'options sera utilisée.
const Tk_OptionSpec *templatePtr (entrée)
Pointe vers un tableau d'informations statiques décrivant les options de configuration prises en charge. Utilisé pour construire une Tk_OptionTable. Les informations pointées par cet argument doivent exister pendant la durée de vie de la Tk_OptionTable.
Tk_OptionTable optionTable (entrée)
Jeton pour une table d'options. Doit avoir été retourné par un appel précédent à Tk_CreateOptionTable.
char *recordPtr (entrée/sortie)
Pointe vers une structure où les valeurs des options de configuration sont stockées ; les champs de cet enregistrement sont modifiés par des procédures telles que Tk_SetOptions et lus par des procédures telles que Tk_GetOptionValue.
Tk_Window tkwin (entrée)
Pour les options telles que TK_OPTION_COLOR, cet argument indique la fenêtre dans laquelle l'option sera utilisée. Si optionTable n'utilise aucune option dépendante de la fenêtre, une valeur NULL peut être fournie pour cet argument.
int objc (entrée)
Nombre de valeurs dans objv.
Tcl_Obj *const *objv (entrée)
Arguments de la ligne de commande pour définir les options de configuration.
Tk_SavedOptions *savePtr (sortie)
S'il n'est pas NULL, la structure pointée par cet argument est remplie avec les anciennes valeurs de toutes les options qui ont été modifiées et les anciennes valeurs sont restaurées automatiquement si une erreur se produit dans Tk_SetOptions.
int *maskPtr (sortie)
S'il n'est pas NULL, le mot pointé par maskPtr est rempli avec le OU binaire des champs typeMask des options qui ont été modifiées.
Tk_SavedOptions *savedPtr (entrée/sortie)
Pointe vers une structure précédemment remplie par Tk_SetOptions avec les anciennes valeurs des options modifiées.
Tcl_Obj *namePtr (entrée)
La valeur de cet objet est le nom d'une option particulière. Si NULL est passé à Tk_GetOptionInfo, des informations sont retournées pour toutes les options. Ne doit pas être NULL lorsque Tk_GetOptionValue est appelé.
type name type (entrée)
Le nom du type d'un enregistrement.
field name field (entrée)
Le nom d'un champ dans les enregistrements de type type.

DESCRIPTION

Ces procédures gèrent la plupart des détails de l'analyse des options de configuration telles que celles des widgets Tk. Étant donné une description des options prises en charge, ces procédures gèrent tous les détails de l'analyse des options et du stockage de leurs valeurs dans une structure C associée au widget ou à l'objet. Les procédures ont été conçues principalement pour les widgets dans Tk, mais elles peuvent également être utilisées pour d'autres types d'objets qui ont des options de configuration. Dans le reste de cette page de manuel, « widget » sera utilisé pour désigner l'objet dont les options sont gérées ; en pratique, l'objet peut ne pas être réellement un widget. Le terme « enregistrement de widget » est utilisé pour désigner la structure au niveau C où sont stockées les informations sur un widget ou un objet particulier.

Notez que le moyen le plus simple d'apprendre à utiliser ces procédures est de regarder un exemple fonctionnel. Dans Tk, l'exemple le plus simple est le code qui implémente la famille de widgets bouton, qui se trouve dans tkButton.c. D'autres exemples se trouvent dans tkSquare.c et tkMenu.c.

Afin d'utiliser ces procédures, le code qui implémente le widget doit contenir un tableau statique de structures Tk_OptionSpec. Il s'agit d'un modèle décrivant les différentes options prises en charge par cette classe de widget ; il existe un modèle séparé pour chaque type de widget. Le modèle contient des informations telles que le nom de chaque option, son type, sa valeur par défaut et où la valeur de l'option est stockée dans l'enregistrement du widget. Voir MODÈLES ci-dessous pour plus de détails.

Afin de traiter les options de configuration efficacement, le modèle statique doit être augmenté d'informations supplémentaires disponibles uniquement à l'exécution. La procédure Tk_CreateOptionTable crée ces informations dynamiques à partir du modèle et renvoie un jeton Tk_OptionTable qui décrit les informations statiques et dynamiques. Toutes les autres procédures, telles que Tk_SetOptions, prennent un jeton Tk_OptionTable comme argument. Typiquement, Tk_CreateOptionTable est appelée la première fois qu'un widget d'une classe particulière est créé et la Tk_OptionTable résultante est utilisée à l'avenir pour tous les widgets de cette classe. Une Tk_OptionTable ne peut être utilisée que dans un seul interpréteur, fourni par l'argument interp à Tk_CreateOptionTable. Lorsqu'une table d'options n'est plus nécessaire, Tk_DeleteOptionTable doit être appelée pour libérer toutes ses ressources. Toutes les tables d'options d'un interpréteur Tcl sont libérées automatiquement si l'interpréteur est supprimé.

Tk_InitOptions est appelée lors de la création d'un nouveau widget pour définir les valeurs par défaut. Tk_InitOptions reçoit un jeton pour une table d'options (optionTable) et un pointeur vers un enregistrement de widget (recordPtr), qui est la structure C contenant les informations sur ce widget. Tk_InitOptions utilise les informations de la table d'options pour choisir une valeur par défaut appropriée pour chaque option, puis stocke la valeur par défaut directement dans l'enregistrement du widget, écrasant toute information déjà présente dans l'enregistrement du widget. Tk_InitOptions renvoie normalement TCL_OK. Si une erreur s'est produite lors de la définition des valeurs par défaut (par exemple, parce qu'une valeur par défaut était erronée), TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de interp si interp n'est pas NULL. Pour toute option de configuration d'un widget qui a TK_OPTION_DONT_SET_DEFAULT défini dans son champ flags, l'initialisation ci-dessus est complètement ignorée, voir ci-dessous.

Tk_SetOptions est appelée pour modifier les options de configuration en fonction des informations spécifiées dans une commande Tcl. La commande peut être celle qui crée un nouveau widget, ou une commande qui modifie les options sur un widget existant. Les arguments objc et objv décrivent les valeurs des arguments de la commande Tcl. Objv doit contenir un nombre pair d'objets : le premier objet de chaque paire donne le nom d'une option et le second objet donne la nouvelle valeur pour cette option. Tk_SetOptions recherche chaque nom dans optionTable, vérifie que la nouvelle valeur de l'option est conforme au type dans optionTable, et stocke la valeur de l'option dans l'enregistrement du widget donné par recordPtr. Tk_SetOptions renvoie normalement TCL_OK. Si une erreur s'est produite (comme un nom d'option inconnu ou une valeur d'option illégale), TCL_ERROR est renvoyé et un message d'erreur est laissé dans le résultat de interp si interp n'est pas NULL.

Tk_SetOptions possède deux fonctionnalités supplémentaires. Premièrement, si l'argument maskPtr n'est pas NULL, il pointe vers une valeur entière qui est remplie d'informations sur les options qui ont été modifiées. Pour chaque option dans le modèle passé à Tk_CreateOptionTable, il y a un champ typeMask. Les bits de ce champ sont définis par le code qui implémente le widget ; par exemple, chaque bit peut correspondre à une option de configuration particulière. Alternativement, les bits peuvent être utilisés fonctionnellement. Par exemple, un bit peut être utilisé pour le redessin : toutes les options qui affectent l'affichage du widget, telles que le changement d'option nécessite que le widget soit redessiné, pourraient avoir ce bit défini. Un autre bit pourrait indiquer que la géométrie du widget doit être recalculée, et ainsi de suite. Tk_SetOptions fait un OU bit à bit des champs typeMask des

La deuxième fonctionnalité supplémentaire de Tk_SetOptions concerne la récupération d'erreurs. Si une erreur survient lors du traitement des options de configuration, cette fonctionnalité permet de restaurer toutes les options de configuration à leurs valeurs précédentes. Des erreurs peuvent survenir soit lors du traitement des options dans Tk_SetOptions, soit plus tard chez l'appelant. Dans de nombreux cas, l'appelant effectue un traitement supplémentaire après le retour de Tk_SetOptions ; par exemple, il peut utiliser la valeur d'une option pour définir un traceur sur une variable et peut détecter une erreur si la variable est un tableau au lieu d'un scalaire. La récupération d'erreurs est activée en passant une valeur non NULL pour l'argument savePtr à Tk_SetOptions ; il doit s'agir d'un pointeur vers une structure Tk_SavedOptions non initialisée sur la pile de l'appelant. Tk_SetOptions écrase la structure pointée par savePtr avec des informations sur les anciennes valeurs de toutes les options modifiées par la procédure. Si Tk_SetOptions réussit, l'appelant utilise la structure de l'une des deux manières suivantes. Si l'appelant termine son traitement des nouvelles options sans aucune erreur, il doit passer la structure à Tk_FreeSavedOptions afin que les anciennes valeurs puissent être libérées. Si l'appelant détecte une erreur dans son traitement des nouvelles options, il doit passer la structure à Tk_RestoreSavedOptions, qui copiera les anciennes valeurs dans l'enregistrement du widget et libérera les nouvelles valeurs. Si Tk_SetOptions détecte une erreur, il restaure automatiquement toutes les options qui avaient déjà été modifiées et laisse *savePtr dans un état vide : l'appelant n'a besoin d'appeler ni Tk_FreeSavedOptions, ni Tk_RestoreSavedOptions. Si l'argument savePtr à Tk_SetOptions est NULL, alors Tk_SetOptions libère immédiatement chaque ancienne valeur d'option lorsqu'il définit une nouvelle valeur pour l'option. Dans ce cas, si une erreur survient dans la troisième option, les anciennes valeurs des deux premières options ne peuvent pas être restaurées.

Tk_GetOptionValue retourne la valeur actuelle d'une option de configuration pour un widget particulier. L'argument namePtr contient le nom d'une option ; Tk_GetOptionValue utilise optionTable pour rechercher l'option et extraire sa valeur de l'enregistrement du widget pointé par recordPtr, puis retourne un objet contenant cette valeur. Si une erreur survient (par exemple, parce que namePtr contient un nom d'option inconnu), NULL est retourné et un message d'erreur est laissé dans le résultat de interp, sauf si interp est NULL.

Tk_GetOptionInfo retourne des informations sur les options de configuration sous une forme appropriée pour les commandes de widget configure. Si l'argument namePtr n'est pas NULL, il pointe vers un objet qui donne le nom d'une option de configuration ; Tk_GetOptionInfo retourne un objet contenant une liste de cinq éléments, qui sont le nom de l'option, le nom et la classe utilisés pour l'option dans la base de données d'options, la valeur par défaut pour l'option, et la valeur actuelle pour l'option. Si l'argument namePtr est NULL, alors Tk_GetOptionInfo retourne des informations sur toutes les options sous la forme d'une liste de listes ; chaque sous-liste décrit une option. Les options synonymes sont traitées différemment selon que namePtr est NULL ou non : si namePtr est NULL, alors la sous-liste pour chaque option synonyme n'a que deux éléments, qui sont le nom de l'option et le nom de l'autre option à laquelle elle fait référence ; si namePtr n'est pas NULL et nomme une option synonyme, alors l'objet retourné est la liste de cinq éléments pour l'autre option à laquelle le synonyme fait référence. Si une erreur survient (par exemple, parce que namePtr contient un nom d'option inconnu), alors NULL est retourné et un message d'erreur est laissé dans le résultat de interp, sauf si interp est NULL.

Tk_FreeConfigOptions doit être invoqué lorsqu'un widget est supprimé. Il libère toutes les ressources associées à toutes les options de configuration définies dans recordPtr par optionTable.

La macro Tk_Offset est fournie comme moyen sûr de générer les valeurs objOffset et internalOffset pour les entrées dans les structures Tk_OptionSpec. Elle prend deux arguments : le nom d'un type d'enregistrement et le nom d'un champ dans cet enregistrement. Elle retourne le décalage en octets du champ nommé dans les enregistrements du type donné.

CALIBRAGES

Le tableau de structures Tk_OptionSpec passé à Tk_CreateOptionTable via son argument templatePtr décrit les options de configuration prises en charge par une classe particulière de widgets. Chaque structure spécifie une option de configuration et a les champs suivants :

typedef struct {
    Tk_OptionType type;
    const char *optionName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int objOffset;
    int internalOffset;
    int flags;
    const void *clientData;
    int typeMask;
} Tk_OptionSpec;
Le champ type indique le type d'option de configuration (par exemple, TK_OPTION_COLOR pour une valeur de couleur, ou TK_OPTION_INT pour une valeur entière). Type détermine comment la valeur de l'option est analysée (plus d'informations ci-dessous). Le champ optionName est une chaîne telle que -font ou -bg ; c'est le nom utilisé pour l'option dans les commandes Tcl et passé aux procédures via les arguments objc ou namePtr. Les champs dbName et dbClass sont utilisés par Tk_InitOptions pour rechercher une valeur par défaut pour cette option dans la base de données d'options ; si dbName est NULL, la base de données d'options n'est pas utilisée par Tk_InitOptions pour cette option. Le champ defValue spécifie une valeur par défaut pour cette option de configuration si aucune valeur n'est spécifiée dans la base de données d'options. Les champs objOffset et internalOffset indiquent où stocker la valeur de cette option dans les enregistrements de widget (plus d'informations ci-dessous) ; les valeurs des champs objOffset et internalOffset doivent toujours être générées avec la macro Tk_Offset. Le champ flags contient des informations supplémentaires pour contrôler le traitement de cette option de configuration (voir ci-dessous pour plus de détails). ClientData fournit des données supplémentaires spécifiques au type nécessaires pour certains types. Par exemple, pour les types TK_OPTION_COLOR, clientData est une chaîne indiquant la valeur par défaut à utiliser sur les écrans monochromes. Voir les descriptions des différents types ci-dessous pour plus de détails. Le dernier champ, typeMask, est utilisé par Tk_SetOptions pour retourner des informations sur les options qui ont été modifiées ; voir la description de Tk_SetOptions ci-dessus pour plus de détails.

Lorsque Tk_InitOptions et Tk_SetOptions stockent la valeur d'une option dans l'enregistrement du widget, ils peuvent le faire de deux manières. Si le champ objOffset du Tk_OptionSpec est supérieur ou égal à zéro, alors la valeur de l'option est stockée sous forme de (Tcl_Obj *) à l'emplacement dans l'enregistrement du widget donné par objOffset. Si le champ internalOffset du Tk_OptionSpec est supérieur ou égal à zéro, alors la valeur de l'option est stockée sous une forme interne spécifique au type à l'emplacement dans l'enregistrement du widget donné par internalOffset. Par exemple, si le type de l'option est TK_OPTION_INT, alors la forme interne est un entier. Si le champ objOffset ou internalOffset est négatif, la valeur n'est pas stockée sous cette forme. Au moins l'un des décalages doit être supérieur ou égal à zéro.

Le champ flags est constitué d'un ou plusieurs bits combinés par OU. Les indicateurs suivants sont pris en charge :

TK_OPTION_NULL_OK
Si ce bit est défini pour une option, une chaîne vide sera acceptée comme valeur pour l'option et la forme interne résultante sera un pointeur NULL, une valeur zéro ou None, en fonction du type de l'option. Si l'indicateur n'est pas défini, les chaînes vides entraîneront des erreurs. TK_OPTION_NULL_OK est généralement utilisé pour permettre à une fonctionnalité d'être désactivée complètement, par exemple définir une valeur de curseur sur None afin qu'une fenêtre hérite simplement du curseur de son parent. Tous les types d'options ne prennent pas en charge l'indicateur TK_OPTION_NULL_OK ; pour ceux qui le font, il y a une indication explicite de ce fait dans les descriptions ci-dessous.
TK_OPTION_DONT_SET_DEFAULT
Si ce bit est défini pour une option, aucune valeur par défaut ne sera définie dans Tk_InitOptions pour cette option. Ni la base de données d'options, ni aucune valeur par défaut système, ni optionTable ne seront utilisés pour donner une valeur par défaut à cette option. Il est plutôt supposé que l'appelant a déjà fourni une valeur par défaut dans le code du widget.

Le champ type de chaque structure Tk_OptionSpec détermine comment analyser la valeur de cette option de configuration. La valeur légale pour type, et les actions correspondantes, sont décrites ci-dessous. Si le type nécessite qu'une valeur tkwin soit passée aux procédures telles que Tk_SetOptions, ou s'il utilise le champ clientData du Tk_OptionSpec, alors il est indiqué explicitement ; sinon, le type ne nécessite ni tkwin ni clientData.

TK_OPTION_ANCHOR
La valeur doit être une position d'ancrage standard telle que ne ou center. La forme interne est une valeur Tk_Anchor comme celles retournées par Tk_GetAnchorFromObj.
TK_OPTION_BITMAP
La valeur doit être un nom de bitmap Tk standard. La forme interne est un jeton Pixmap comme ceux retournés par Tk_AllocBitmapFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge l'indicateur TK_OPTION_NULL_OK.
TK_OPTION_BOOLEAN
La valeur doit être une valeur booléenne standard telle que true ou no. La forme interne est un entier avec la valeur 0 ou 1. Notez que si le champ objOffset n'est pas utilisé, les informations sur la valeur d'origine de cette option seront perdues.
TK_OPTION_BORDER
La valeur doit être un nom de couleur standard tel que red ou #ff8080. La forme interne est un jeton Tk_3DBorder comme ceux retournés par Tk_Alloc3DBorderFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge l'indicateur TK_OPTION_NULL_OK.

Si un campo de un registro de widget tiene su desplazamiento almacenado en la propiedad objOffset o internalOffset de una estructura Tk_OptionSpec, entonces los procedimientos descritos aquí manejarán todos los problemas de asignación de almacenamiento y gestión de recursos asociados con ese campo. Cuando el valor de una opción se modifica, Tk_SetOptions (o Tk_FreeSavedOptions) liberará automáticamente cualquier recurso asociado con el valor antiguo, como Tk_Fonts para opciones TK_OPTION_FONT o memoria dinámica para opciones TK_OPTION_STRING. Para un valor almacenado como un objeto utilizando la propiedad objOffset de una estructura Tk_OptionSpec, el registro de widget comparte el objeto que se menciona en el valor de objv de la llamada a Tk_SetOptions. El contador de referencias de este objeto se incrementa cuando se almacena un puntero a él en el registro de widget y se decrementa cuando la opción se modifica. Cuando el widget es eliminado, debe llamarse Tk_FreeConfigOptions, que liberará los recursos asociados con todas las opciones y decrementará los contadores de referencias para cualquier objeto.

Sin embargo, el código del widget está responsable de almacenar NULL o None en todos los campos de puntero y token antes de invocar Tk_InitOptions. Esto es necesario para permitir la limpieza adecuada en el raro caso de que ocurra un error en Tk_InitOptions.

Sin embargo, hay dos casos donde es útil usar la propiedad objOffset. El primer caso es para opciones TK_OPTION_PIXELS. En este caso, el formulario interno es un valor entero de píxeles válido solo para un determinado monitor. Si el valor de la opción se recupera, se devolverá como un número simple. Por ejemplo, después de la instrucción .b configure -borderwidth 2m, la instrucción .b configure -borderwidth podría devolver 7, que es el valor entero de píxeles correspondiente a 2m. Sin embargo, esto pierde el valor original sin dependencia de pantalla. Por lo tanto, para opciones TK_OPTION_PIXELS, es mejor usar la propiedad objOffset. En este caso, el valor original de la opción se mantiene en el objeto y puede ser devuelto cuando se recupera la opción. En la mayoría de los casos es conveniente usar la propiedad internalOffset, ya que el valor entero se puede utilizar inmediatamente en el código de widget (alternativamente, se puede usar Tk_GetPixelsFromObj para extraer el valor entero de la objeto cuando se necesite). Nota que el problema de perder información durante las recuperaciones solo existe para opciones TK_OPTION_PIXELS.

La segunda razón para usar la propiedad objOffset es para implementar nuevos tipos de opciones no soportados por estos procedimientos. Para implementar un nuevo tipo de opción, se puede usar TK_OPTION_STRING como tipo en la estructura Tk_OptionSpec y configurar la propiedad objOffset pero no la propiedad internalOffset. Luego, después de invocar Tk_SetOptions, se puede convertir el objeto a forma interna uno mismo.

Los widgets Ttk no soportan el mecanismo internalOffset. Los valores de opciones de widgets Ttk siempre se almacenan como (Tcl_Obj *), lo que significa que debe usarse la propiedad objOffset.

DESCRIPTION

These procedures manage configuration options for Tk widgets. They are the core of Tk's configuration mechanism. The configuration mechanism allows users to query and modify widget options using a standard set of options (e.g., -background, -width, -height) and also allows widgets to define their own custom options.

The configuration mechanism is implemented using a table of structures, each of which describes a single option. The structure is called Tk_OptionSpec and it contains information about the option's name, database name, database class, and pointers to procedures that handle getting and setting the option's value. The table is typically passed to Tk_InitOptions when a widget is created.

The configuration mechanism uses several procedures:

Tk_GetOptionValue
This procedure is used to get the value of a single configuration option. It takes the option's name, database name, and database class as arguments, along with flags that control how the option is interpreted. It returns the option's value as a Tcl_Obj in the location pointed to by optionPtr. It returns a Tcl result, TCL_OK on success and TCL_ERROR on failure.
Tk_SetOptions
This procedure is used to set multiple configuration options at once. It takes an array of Tk_OptionSpec structures and an array of corresponding Tcl_Obj values. It iterates through the options, calling the appropriate setProc for each option to convert the Tcl_Obj value into the widget's internal representation. It returns a Tcl result, TCL_OK on success and TCL_ERROR on failure.
Tk_RestoreSavedOptions
This procedure is used to restore widget configuration options that were previously saved using Tk_SetOptions. It takes pointers to the widget's record and the saved options structure. It iterates through the options, calling the appropriate restoreProc for each option to restore its original value.
Tk_FreeSavedOptions
This procedure is used to free any memory that was allocated for saved widget configuration options. It takes the array of Tk_OptionSpec structures and the saved options structure as arguments. It iterates through the options, calling the appropriate freeProc for each option to free its associated memory.

TEMPLATES

The configuration mechanism uses several procedures that act as templates for handling custom option types. These procedures are specified in the Tk_OptionSpec structure and are called by the Tk core routines when needed.

The following procedures are used:

getProc
This procedure is invoked by Tk_GetOptionValue, Tk_GetOptionInfo, and Tk_OptionName to return a Tcl_Obj representation of the internal representation of an option. The arguments are:
clientData
A copy of the clientData field in the Tk_OptionSpec structure. This is usually a pointer to the location in the widget record where the option's value is stored.
interp
A pointer to a Tcl interpreter. This is used for error reporting.
Tkwin
A copy of the tkwin argument to Tk_GetOptionValue, Tk_GetOptionInfo, or Tk_OptionName.
optionPtr
A pointer to a Tcl_Obj pointer. getProc should allocate a new Tcl_Obj and store the option's value in it, then set optionPtr to point to the new object. The caller is responsible for managing the memory for the Tcl_Obj.

GetProc returns a standard Tcl result: TCL_OK to indicate successful processing, or TCL_ERROR to indicate a failure. An error message may be left in the Tcl interpreter given by interp in the case of an error.

The setProc procedure is invoked by Tk_SetOptions to convert a Tcl_Obj into an internal representation and store the resulting value in the widget record. The arguments are:

clientData
A copy of the clientData field in the Tk_OptionSpec structure. This is usually a pointer to the location in the widget record where the option's value is stored.
interp
A pointer to a Tcl interpreter, used for error reporting.
Tkwin
A copy of the tkwin argument to Tk_SetOptions
objPtr
A pointer to a Tcl_Obj describing the new value for the option. This value may have come from the option database or a default.
recordPtr
A pointer to the start of the widget record to modify.
internalOffset
Offset in bytes from the start of the widget record to the location where the internal representation of the option value is to be placed.
flags
A copy of the flags field in the Tk_OptionSpec structure for the option.

SetProc returns a standard Tcl result: TCL_OK to indicate successful processing, or TCL_ERROR to indicate a failure of any kind. An error message may be left in the Tcl interpreter given by interp in the case of an error.

The restoreProc procedure is invoked by Tk_RestoreSavedOptions to restore a previously saved internal representation of a custom option value. The clientData argument is a copy of the clientData field in the Tk_OptionSpec structure. Tkwin is a copy of the tkwin argument to Tk_RestoreSavedOptions. InternalPtr is a pointer to the location where internal representation of the option value is stored. SaveInternalPtr is a pointer to the saved value. RestoreProc must copy the value from saveInternalPtr to internalPtr to restore the value. RestoreProc need not free any memory associated with either internalPtr or saveInternalPtr; freeProc will be invoked to free that memory if necessary. RestoreProc has no return value.

The freeProc procedure is invoked by Tk_SetOptions and Tk_FreeSavedOptions to free any storage allocated for the internal representation of a custom option. The clientData argument is a copy of the clientData field in the Tk_OptionSpec structure. Tkwin is a copy of the tkwin argument to Tk_SetOptions or Tk_FreeSavedOptions. InternalPtr is a pointer to the location where the internal representation of the option value is stored. The freeProc must free any storage associated with the option. FreeProc has no return value.

STORAGE MANAGEMENT ISSUES

The Tk_OptionSpec structure contains pointers to procedures that handle the storage management of custom option types. These procedures are getProc, setProc, restoreProc, and freeProc.

The getProc procedure is responsible for returning the current value of an option as a Tcl_Obj. If the option's value is stored in dynamically allocated memory, getProc should create a new Tcl_Obj and copy the value into it. The caller is responsible for freeing the memory associated with the Tcl_Obj.

The setProc procedure is responsible for converting a Tcl_Obj value into the widget's internal representation and storing it in the widget record. If the Tcl_Obj represents a dynamically allocated value, setProc should allocate new memory and copy the value into it. The freeProc will be called later to free this memory.

The restoreProc procedure is used to restore a previously saved option value. It copies the saved value from saveInternalPtr to internalPtr. It does not need to free any memory.

The freeProc procedure is responsible for freeing any dynamically allocated memory associated with an option's internal representation. It is called by Tk_SetOptions when an option is reconfigured, and by Tk_FreeSavedOptions when the widget is destroyed or when saved options are being discarded.

Widgets should provide NULL for restoreProc and freeProc if no special memory management is required for an option.

OBJOFFSET VS. INTERNALOFFSET

The Tk_OptionSpec structure contains two offset fields: objOffset and internalOffset.

objOffset is used when the option's value is stored as a Tcl_Obj pointer directly in the widget record. This is useful for options whose values are complex or change frequently.

internalOffset is used when the option's value is stored in a more compact internal representation (e.g., an integer, a string, or a structure). This is more efficient for simple options or when memory usage is a concern.

Only one of these offsets should be non-negative for a given option. If objOffset is non-negative, the option's value is stored as a (Tcl_Obj *) at that offset. If internalOffset is non-negative, the option's value is stored internally at that offset, and the getProc, setProc, restoreProc, and freeProc procedures are used to manage the conversion between Tcl_Obj and the internal representation.

CUSTOM OPTION TYPES

Tk provides built-in handlers for many common option types, such as colors, fonts, booleans, integers, and screen distances. However, widgets can define their own custom option types by providing their own getProc and setProc procedures.

This is typically done by creating a structure that holds the internal representation of the custom option, and then defining getProc and setProc procedures that know how to convert between Tcl_Obj values and this internal representation. The clientData field in the Tk_OptionSpec structure is used to pass a pointer to this internal structure to the getProc and setProc procedures.

The restoreProc and freeProc procedures are also used for custom option types, particularly for managing dynamically allocated memory associated with the internal representation.

The following procedures are involved in custom option handling:

setProc
This procedure is invoked by Tk_SetOptions to convert a Tcl_Obj into an internal representation and store the resulting value in the widget record. The arguments are:
clientData
A copy of the clientData field in the Tk_ObjCustomOption structure. This typically points to a structure containing information that is needed by the procedures when they are parsing and printing options. RestoreProc and freeProc may be NULL, indicating that no function should be called for those operations.
interp
A pointer to a Tcl interpreter, used for error reporting.
Tkwin
A copy of the tkwin argument to Tk_SetOptions
valuePtr
A pointer to a reference to a Tcl_Obj describing the new value for the option; it could have been specified explicitly in the call to Tk_SetOptions or it could come from the option database or a default. If the objOffset for the option is non-negative (the option value is stored as a (Tcl_Obj *) in the widget record), the Tcl_Obj pointer referenced by valuePtr is the pointer that will be stored at the objOffset for the option. SetProc may modify the value if necessary; for example, setProc may change the value to NULL to support the TK_OPTION_NULL_OK flag.
recordPtr
A pointer to the start of the widget record to modify.
internalOffset
Offset in bytes from the start of the widget record to the location where the internal representation of the option value is to be placed.
saveInternalPtr
A pointer to storage allocated in a Tk_SavedOptions structure for the internal representation of the original option value. Before setting the option to its new value, setProc should set the value referenced by saveInternalPtr to the original value of the option in order to support Tk_RestoreSavedOptions.
flags
A copy of the flags field in the Tk_OptionSpec structure for the option

SetProc returns a standard Tcl result: TCL_OK to indicate successful processing, or TCL_ERROR to indicate a failure of any kind. An error message may be left in the Tcl interpreter given by interp in the case of an error.

The getProc procedure is invoked by Tk_GetOptionValue and Tk_GetOptionInfo to retrieve a Tcl_Obj representation of the internal representation of an option. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. RecordPtr is a pointer to the beginning of the widget record to query. InternalOffset is the offset in bytes from the beginning of the widget record to the location where the internal representation of the option value is stored. GetProc must return a pointer to a Tcl_Obj representing the value of the option.

The restoreProc procedure is invoked by Tk_RestoreSavedOptions to restore a previously saved internal representation of a custom option value. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. InternalPtr is a pointer to the location where internal representation of the option value is stored. SaveInternalPtr is a pointer to the saved value. RestoreProc must copy the value from saveInternalPtr to internalPtr to restore the value. RestoreProc need not free any memory associated with either internalPtr or saveInternalPtr; freeProc will be invoked to free that memory if necessary. RestoreProc has no return value.

The freeProc procedure is invoked by Tk_SetOptions and Tk_FreeSavedOptions to free any storage allocated for the internal representation of a custom option. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. InternalPtr is a pointer to the location where the internal representation of the option value is stored. The freeProc must free any storage associated with the option. FreeProc has no return value.
