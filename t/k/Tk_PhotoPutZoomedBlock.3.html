Tk_PhotoPutZoomedBlock(3)

Paquet: tk

Licences: TCL

Tk_PhotoPutZoomedBlock, Tk_PhotoPutBlock, Tk_PhotoGetImage, Tk_PhotoBlank, Tk_PhotoExpand, Tk_PhotoSetSize, Tk_PhotoGetSize - Manipuler des blocs de données d'image Tk.

ARGUMENTS

interp
Interpréteur Tcl à utiliser pour les opérations qui peuvent échouer et nécessitent un message d'erreur.
photo
Handle vers le handle de photo à manipuler. Ce handle est généralement retourné par Tcl_GetImage lors de la demande d'une image de type `photo`. La fonction d'encodage de cette image est un gestionnaire d'images pour le type `photo`.
blockPtr
Pointeur vers une structure Tk_PhotoImageBlock contenant les données de l'image à copier. La structure Tk_PhotoImageBlock est définie comme suit :
typedef struct Tk_PhotoImageBlock {
    char *pixelPtr;       /* Pointeur vers les données de pixel. Le format dépend des
                           * champs offset et pixelSize. */
    int width, height;    /* Dimensions du bloc d'image en pixels. */
    int pitch;            /* Nombre d'octets entre le début de deux lignes de pixels adjacentes. */
    char *errorPtr;       /* Pointeur vers une chaîne d'erreur pour une raison quelconque
                           * (par exemple, impossible de lire une partie du bloc). NULL si aucune erreur. */
    int offset[4];        /* Décalages en octets vers les canaux R, V, B et Alpha. */
    int pixelSize;        /* Taille en octets d'un pixel (par exemple, 4 pour RGBA). */
} Tk_PhotoImageBlock;

Les valeurs des champs offset et pixelSize sont utilisées pour déterminer comment interpréter les données dans pixelPtr. Les indices 0, 1, 2 et 3 dans offset correspondent respectivement aux canaux rouge, vert, bleu et alpha. Si l'offset du canal alpha est supérieur ou égal à pixelSize, le canal alpha est ignoré (l'image est supposée opaque). Les fonctions Tk_PhotoPutBlock et Tk_PhotoPutZoomedBlock copient les données spécifiées par blockPtr dans l'image photo. Les arguments srcX, srcY, srcWidth et srcHeight spécifient la région des données source à copier, et destX, destY spécifient le coin supérieur gauche de la zone dans laquelle les données doivent être copiées. Les valeurs dans destWidth et destHeight sont utilisées uniquement par Tk_PhotoPutZoomedBlock et indiquent la taille de la zone de destination dans l'image photo. Si Tk_PhotoPutBlock est utilisé, la taille de la région source est copiée dans la région de destination correspondante.

L'argument compRule spécifie la règle de composition à utiliser pour copier les données. Actuellement, seul COMPOP_SRC est pris en charge, ce qui signifie que les données source remplacent simplement les données existantes.

width
Largeur souhaitée pour l'image photo.
height
Hauteur souhaitée pour l'image photo.
widthPtr
Pointeur vers un entier dans lequel la largeur actuelle de l'image photo sera stockée.
heightPtr
Pointeur vers un entier dans lequel la hauteur actuelle de l'image photo sera stockée.

DESCRIPTION

Ces fonctions fournissent une interface pour créer et manipuler des images Tk de type `photo`. Les images de type `photo` sont des images bitmap qui peuvent être modifiées par programme. Elles sont souvent utilisées pour afficher des images chargées à partir de fichiers ou générées dynamiquement.

Les fonctions Tk_PhotoPutBlock et Tk_PhotoPutZoomedBlock copient des blocs de données d'image dans une image photo existante. Vous pouvez utiliser ces fonctions pour mettre à jour des parties d'une image ou pour construire une image pixel par pixel. Il est recommandé d'utiliser ces fonctions pour effectuer des modifications sur une copie des données d'image et de les réécrire avec Tk_PhotoPutBlock ou Tk_PhotoPutZoomedBlock.

Tk_PhotoGetImage renvoie 1 pour la compatibilité avec la procédure correspondante dans l'ancien widget photo.

Tk_PhotoBlank vide toute la zone de l'image photo. Les zones vides d'une image photo sont transparentes.

Tk_PhotoExpand demande que l'image du widget soit étendue pour avoir au moins width x height pixels de taille. La largeur et/ou la hauteur ne sont pas modifiées si l'utilisateur a spécifié une largeur ou une hauteur d'image explicite avec les options de configuration -width et/ou -height, respectivement. Si les données d'image sont fournies en plusieurs petits blocs, il est plus efficace d'utiliser Tk_PhotoExpand ou Tk_PhotoSetSize au début plutôt que de laisser l'image s'étendre par petits incréments successifs au fur et à mesure que les blocs d'image sont fournis.

Tk_PhotoExpand renvoie normalement TCL_OK, bien que si elle ne peut pas allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est renvoyé à la place et, si l'argument interp n'est pas NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoSetSize spécifie la taille de l'image, comme si l'utilisateur avait spécifié les valeurs width et height données aux options de configuration -width et -height. Une valeur de zéro pour width ou height ne modifie pas la largeur ou la hauteur de l'image, mais permet de modifier la largeur ou la hauteur par des appels ultérieurs à Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock ou Tk_PhotoExpand.

Tk_PhotoSetSize renvoie normalement TCL_OK, bien que si elle ne peut pas allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est renvoyé à la place et, si l'argument interp n'est pas NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoGetSize renvoie les dimensions de l'image dans *widthPtr et *heightPtr.

PORTABILITE

Dans Tk 8.3 et versions antérieures, Tk_PhotoPutBlock et Tk_PhotoPutZoomedBlock avaient des signatures différentes. Si vous souhaitez compiler du code utilisant l'ancienne interface avec 8.4 sans mettre à jour votre code, compilez-le avec le drapeau -DUSE_COMPOSITELESS_PHOTO_PUT_BLOCK. Le code lié à l'aide de Stubs à des versions plus anciennes de Tk continuera de fonctionner.

Dans Tk 8.4, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoExpand et Tk_PhotoSetSize ne prenaient pas d'argument interp ni ne renvoyaient de code de résultat. Si la mémoire insuffisante était disponible pour une image, Tk paniquait. Ce comportement est toujours pris en charge si vous compilez votre extension avec le drapeau supplémentaire -DUSE_PANIC_ON_PHOTO_ALLOC_FAILURE. Le code lié à l'aide de Stubs à des versions plus anciennes de Tk continuera de fonctionner.

BOGUES

La structure Tk_PhotoImageBlock utilisée pour fournir des données d'image à Tk_PhotoPutBlock promet une grande flexibilité dans la disposition des données (par exemple, des plans séparés pour les canaux rouge, vert, bleu et alpha). Malheureusement, l'implémentation ne tient pas cette promesse. Le problème est que le champ pixelSize est utilisé (incorrectement) pour déterminer si l'image a un canal alpha. Actuellement, si le décalage du canal alpha est supérieur ou égal à pixelSize, tk_PhotoPutblock suppose qu'aucune donnée alpha n'est présente et rend l'image complètement opaque. Cela signifie que pour les dispositions où les canaux sont séparés (ou toute autre disposition exotique où pixelSize doit être inférieur au décalage alpha), le canal alpha ne sera pas lu correctement. Afin d'être prudent si ce problème est corrigé dans une future version, il est fortement recommandé de toujours fournir des données alpha - même si l'image n'a pas de transparence - et d'utiliser uniquement la disposition « standard » avec un pixelSize de 2 pour les données en niveaux de gris et de 4 pour les données RVB avec des offsets de 0, 0, 0, 1 ou 0, 1, 2, 3 respectivement.
