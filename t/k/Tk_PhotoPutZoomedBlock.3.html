NOM

Tk_FindPhoto, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoGetImage, Tk_PhotoBlank, Tk_PhotoExpand, Tk_PhotoGetSize, Tk_PhotoSetSize - manipuler les données d'image stockées dans une image photo.

SYNOPSIS

Tk_PhotoHandle
Tk_FindPhoto(interp, imageName)

int

Tk_PhotoGetImage(handle, blockPtr)

void
Tk_PhotoBlank(handle)

int
Tk_PhotoExpand(interp, handle, width, height)

void
Tk_PhotoGetSize(handle, widthPtr, heightPtr)

int
Tk_PhotoSetSize(interp. handle, width, height)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur dans lequel l'image a été créée et dans lequel le rapport d'erreur doit être effectué.
const char *imageName (entrée)
Nom de l'image photo.
Tk_PhotoHandle handle (entrée)
Handle opaque identifiant l'image photo à affecter.
Tk_PhotoImageBlock *blockPtr (entrée)
Spécifie l'adresse et la disposition de stockage des données d'image.
int x (entrée)
Spécifie la coordonnée X où le coin supérieur gauche du bloc doit être placé dans l'image.
int y (entrée)
Spécifie la coordonnée Y où le coin supérieur gauche du bloc doit être placé dans l'image.
int width (entrée)
Spécifie la largeur de la zone d'image à affecter (pour Tk_PhotoPutBlock) ou la largeur d'image souhaitée (pour Tk_PhotoExpand et Tk_PhotoSetSize).
int compRule (entrée)
Spécifie la règle de composition utilisée lors de la combinaison de pixels transparents dans un bloc de données avec une image photo. Doit être l'une des valeurs TK_PHOTO_COMPOSITE_OVERLAY (qui place le bloc de données au-dessus de l'image photo existante, le contenu précédent apparaissant à travers les bits transparents) ou TK_PHOTO_COMPOSITE_SET (qui supprime le contenu existant de l'image photo dans le rectangle couvert par le bloc de données.)
int height (entrée)
Spécifie la hauteur de la zone d'image à affecter (pour Tk_PhotoPutBlock) ou la hauteur d'image souhaitée (pour Tk_PhotoExpand et Tk_PhotoSetSize).
int *widthPtr (sortie)
Pointeur vers l'emplacement où stocker la largeur de l'image.
int *heightPtr (sortie)
Pointeur vers l'emplacement où stocker la hauteur de l'image.
int subsampleX (entrée)
Spécifie le facteur de sous-échantillonnage dans la direction X pour les données d'image d'entrée.
int subsampleY (entrée)
Spécifie le facteur de sous-échantillonnage dans la direction Y pour les données d'image d'entrée.
int zoomX (entrée)
Spécifie le facteur de zoom à appliquer dans la direction X aux pixels écrits dans l'image photo.
int zoomY (entrée)
Spécifie le facteur de zoom à appliquer dans la direction Y aux pixels écrits dans l'image photo.

DESCRIPTION

Tk_FindPhoto renvoie un handle opaque utilisé pour identifier une image photo particulière auprès des autres procédures. Le paramètre est le nom de l'image, c'est-à-dire le nom spécifié à la commande image create photo, ou attribué par cette commande si aucun nom n'a été spécifié. Si imageName n'existe pas ou n'est pas une image photo, Tk_FindPhoto renvoie NULL.

Tk_PhotoPutBlock est utilisé pour fournir des blocs de données d'image à afficher. L'appel affecte une zone de l'image de taille width x height pixels, avec son coin supérieur gauche aux coordonnées (x,y). Tous les paramètres width, height, x et y doivent être non négatifs. Si une partie de cette zone se trouve en dehors des limites actuelles de l'image, l'image sera agrandie pour inclure la zone, sauf si l'utilisateur a spécifié une taille d'image explicite avec les options de configuration du widget -width et/ou -height (voir photo(n)) ; dans ce cas la zone est silencieusement découpée aux limites de l'image.

Le paramètre block est un pointeur vers une structure Tk_PhotoImageBlock, définie comme suit :

typedef struct {
    unsigned char *pixelPtr;
    int width;
    int height;
    int pitch;
    int pixelSize;
    int offset[4];
} Tk_PhotoImageBlock;
Le champ pixelPtr pointe vers le premier pixel, c'est-à-dire le pixel supérieur gauche du bloc. Les champs width et height spécifient les dimensions du bloc de pixels. Le champ pixelSize spécifie la différence d'adresse entre deux pixels horizontalement adjacents. Il devrait être de 4 pour RGB et de 2 pour les données d'image en niveaux de gris. D'autres valeurs sont possibles, si les décalages dans le tableau offset sont ajustés en conséquence (par exemple pour des données rouge, vert et bleu stockées dans des plans différents). L'utilisation d'une telle disposition est fortement déconseillée, cependant. En raison d'un bug, elle pourrait ne pas fonctionner correctement si un canal alpha est fourni. (voir la section BUGS ci-dessous). Le champ pitch spécifie la différence d'adresse entre deux pixels verticalement adjacents. Le tableau offset contient les décalages depuis l'adresse d'un pixel vers les adresses des octets contenant les composantes rouge, vert, bleu et alpha (transparence). Si les décalages pour le rouge, le vert et le bleu sont égaux, l'image est interprétée comme étant en niveaux de gris. S'ils diffèrent, des données RGB sont supposées. Normalement les décalages seront 0, 1, 2, 3 pour les données RGB et 0, 0, 0, 1 pour les niveaux de gris. Il est possible de fournir des données d'image sans canal alpha en réglant le décalage pour alpha à une valeur négative et en ajustant le champ pixelSize en conséquence. Cet usage est déconseillé, cependant (voir la section BUGS ci-dessous).

Le paramètre compRule de Tk_PhotoPutBlock spécifie une règle de composition qui indique quoi faire avec les pixels transparents. La valeur TK_PHOTO_COMPOSITE_OVERLAY indique que le contenu précédent de l'image photo doit apparaître à travers, et la valeur TK_PHOTO_COMPOSITE_SET indique que le contenu précédent de l'image photo doit être complètement ignoré, et que les valeurs du bloc doivent être copiées directement. Le comportement dans Tk8.3 et antérieur était équivalent à avoir TK_PHOTO_COMPOSITE_OVERLAY comme règle de composition.

La valeur donnée pour les paramètres width et height de Tk_PhotoPutBlock ne doit pas nécessairement correspondre aux valeurs spécifiées dans block. Si elles sont plus petites, Tk_PhotoPutBlock extrait un sous-bloc à partir des données d'image fournies. Si elles sont plus grandes, les données données sont répliquées (de manière carrelée) pour remplir la zone spécifiée. Ces règles fonctionnent indépendamment dans les directions horizontale et verticale.

Tk_PhotoPutBlock renvoie normalement TCL_OK, bien que si il ne peut pas allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est renvoyé à la place et, si l'argument interp est non-NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoPutZoomedBlock fonctionne comme Tk_PhotoPutBlock sauf que l'image peut être réduite ou agrandie pour l'affichage. Les paramètres subsampleX et subsampleY permettent de réduire la taille de l'image par sous-échantillonnage. Tk_PhotoPutZoomedBlock n'utilisera que les pixels de l'image d'entrée dont les coordonnées X sont des multiples de subsampleX, et dont les coordonnées Y sont des multiples de subsampleY. Par exemple, une image de 512x512 pixels peut être réduite à 256x256 en réglant subsampleX et subsampleY à 2.

Les paramètres zoomX et zoomY permettent d'agrandir l'image par réplication de pixels. Chaque pixel de l'image d'entrée (éventuellement sous-échantillonnée) sera écrit dans un bloc de zoomX pixels de large et zoomY pixels de haut de l'image affichée. Le sous-échantillonnage et le zoom peuvent être utilisés ensemble pour des effets spéciaux.

Tk_PhotoGetImage peut être utilisé pour récupérer les données d'image d'une image photo. Tk_PhotoGetImage remplit la structure pointée par le paramètre blockPtr avec des valeurs qui décrivent l'adresse et la disposition des données d'image que l'image photo a stockées en interne. Les valeurs sont valides jusqu'à ce que l'image soit détruite ou que sa taille soit modifiée.

Il est possible de modifier une image en écrivant directement dans les données vers lesquelles pointe le champ pixelPtr. La taille de l'image ne peut pas être modifiée de cette façon, cependant. De plus, les modifications effectuées en écrivant directement dans pixelPtr ne seront pas immédiatement visibles, mais seulement après un appel à Tk_ImageChanged ou après un événement qui amène les widgets intéressés à se redessiner. Pour ces raisons, il est généralement préférable de faire Tk_PhotoPutZoomedBlock - Manuel Arch Linux

ARGUMENTS

interp
Interpréteur Tcl à utiliser pour les opérations qui peuvent échouer et nécessitent un message d'erreur.
photo
Handle vers le handle de photo à manipuler. Ce handle est généralement retourné par Tcl_GetImage lors de la demande d'une image de type `photo`. La fonction d'encodage de cette image est un gestionnaire d'images pour le type `photo`.
blockPtr
Pointeur vers une structure Tk_PhotoImageBlock contenant les données de l'image à copier. La structure Tk_PhotoImageBlock est définie comme suit :
typedef struct Tk_PhotoImageBlock {
    char *pixelPtr;       /* Pointeur vers les données de pixel. Le format dépend des
                           * champs offset et pixelSize. */
    int width, height;    /* Dimensions du bloc d'image en pixels. */
    int pitch;            /* Nombre d'octets entre le début de deux lignes de pixels adjacentes. */
    char *errorPtr;       /* Pointeur vers une chaîne d'erreur pour une raison quelconque
                           * (par exemple, impossible de lire une partie du bloc). NULL si aucune erreur. */
    int offset[4];        /* Décalages en octets vers les canaux R, V, B et Alpha. */
    int pixelSize;        /* Taille en octets d'un pixel (par exemple, 4 pour RGBA). */
} Tk_PhotoImageBlock;

Les valeurs des champs offset et pixelSize sont utilisées pour déterminer comment interpréter les données dans pixelPtr. Les indices 0, 1, 2 et 3 dans offset correspondent respectivement aux canaux rouge, vert, bleu et alpha. Si l'offset du canal alpha est supérieur ou égal à pixelSize, le canal alpha est ignoré (l'image est supposée opaque). Les fonctions Tk_PhotoPutBlock et Tk_PhotoPutZoomedBlock copient les données spécifiées par blockPtr dans l'image photo. Les arguments srcX, srcY, srcWidth et srcHeight spécifient la région des données source à copier, et destX, destY spécifient le coin supérieur gauche de la zone dans laquelle les données doivent être copiées. Les valeurs dans destWidth et destHeight sont utilisées uniquement par Tk_PhotoPutZoomedBlock et indiquent la taille de la zone de destination dans l'image photo. Si Tk_PhotoPutBlock est utilisé, la taille de la région source est copiée dans la région de destination correspondante.

L'argument compRule spécifie la règle de composition à utiliser pour copier les données. Actuellement, seul COMPOP_SRC est pris en charge, ce qui signifie que les données source remplacent simplement les données existantes.

width
Largeur souhaitée pour l'image photo.
height
Hauteur souhaitée pour l'image photo.
widthPtr
Pointeur vers un entier dans lequel la largeur actuelle de l'image photo sera stockée.
heightPtr
Pointeur vers un entier dans lequel la hauteur actuelle de l'image photo sera stockée.

DESCRIPTION

Ces fonctions fournissent une interface pour créer et manipuler des images Tk de type `photo`. Les images de type `photo` sont des images bitmap qui peuvent être modifiées par programme. Elles sont souvent utilisées pour afficher des images chargées à partir de fichiers ou générées dynamiquement.

Les fonctions Tk_PhotoPutBlock et Tk_PhotoPutZoomedBlock copient des blocs de données d'image dans une image photo existante. Vous pouvez utiliser ces fonctions pour mettre à jour des parties d'une image ou pour construire une image pixel par pixel. Il est recommandé d'utiliser ces fonctions pour effectuer des modifications sur une copie des données d'image et de les réécrire avec Tk_PhotoPutBlock ou Tk_PhotoPutZoomedBlock.

Tk_PhotoGetImage renvoie 1 pour la compatibilité avec la procédure correspondante dans l'ancien widget photo.

Tk_PhotoBlank vide toute la zone de l'image photo. Les zones vides d'une image photo sont transparentes.

Tk_PhotoExpand demande que l'image du widget soit étendue pour avoir au moins width x height pixels de taille. La largeur et/ou la hauteur ne sont pas modifiées si l'utilisateur a spécifié une largeur ou une hauteur d'image explicite avec les options de configuration -width et/ou -height, respectivement. Si les données d'image sont fournies en plusieurs petits blocs, il est plus efficace d'utiliser Tk_PhotoExpand ou Tk_PhotoSetSize au début plutôt que de laisser l'image s'étendre par petits incréments successifs au fur et à mesure que les blocs d'image sont fournis.

Tk_PhotoExpand renvoie normalement TCL_OK, bien que si elle ne peut pas allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est renvoyé à la place et, si l'argument interp n'est pas NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoSetSize spécifie la taille de l'image, comme si l'utilisateur avait spécifié les valeurs width et height données aux options de configuration -width et -height. Une valeur de zéro pour width ou height ne modifie pas la largeur ou la hauteur de l'image, mais permet de modifier la largeur ou la hauteur par des appels ultérieurs à Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock ou Tk_PhotoExpand.

Tk_PhotoSetSize renvoie normalement TCL_OK, bien que si elle ne peut pas allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est renvoyé à la place et, si l'argument interp n'est pas NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoGetSize renvoie les dimensions de l'image dans *widthPtr et *heightPtr.

PORTABILITE

Dans Tk 8.3 et versions antérieures, Tk_PhotoPutBlock et Tk_PhotoPutZoomedBlock avaient des signatures différentes. Si vous souhaitez compiler du code utilisant l'ancienne interface avec 8.4 sans mettre à jour votre code, compilez-le avec le drapeau -DUSE_COMPOSITELESS_PHOTO_PUT_BLOCK. Le code lié à l'aide de Stubs à des versions plus anciennes de Tk continuera de fonctionner.

Dans Tk 8.4, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoExpand et Tk_PhotoSetSize ne prenaient pas d'argument interp ni ne renvoyaient de code de résultat. Si la mémoire insuffisante était disponible pour une image, Tk paniquait. Ce comportement est toujours pris en charge si vous compilez votre extension avec le drapeau supplémentaire -DUSE_PANIC_ON_PHOTO_ALLOC_FAILURE. Le code lié à l'aide de Stubs à des versions plus anciennes de Tk continuera de fonctionner.

BOGUES

La structure Tk_PhotoImageBlock utilisée pour fournir des données d'image à Tk_PhotoPutBlock promet une grande flexibilité dans la disposition des données (par exemple, des plans séparés pour les canaux rouge, vert, bleu et alpha). Malheureusement, l'implémentation ne tient pas cette promesse. Le problème est que le champ pixelSize est utilisé (incorrectement) pour déterminer si l'image a un canal alpha. Actuellement, si le décalage du canal alpha est supérieur ou égal à pixelSize, tk_PhotoPutblock suppose qu'aucune donnée alpha n'est présente et rend l'image complètement opaque. Cela signifie que pour les dispositions où les canaux sont séparés (ou toute autre disposition exotique où pixelSize doit être inférieur au décalage alpha), le canal alpha ne sera pas lu correctement. Afin d'être prudent si ce problème est corrigé dans une future version, il est fortement recommandé de toujours fournir des données alpha - même si l'image n'a pas de transparence - et d'utiliser uniquement la disposition « standard » avec un pixelSize de 2 pour les données en niveaux de gris et de 4 pour les données RVB avec des offsets de 0, 0, 0, 1 ou 0, 1, 2, 3 respectivement.
