Tk_PhotoGetImage devuelve 1 para compatibilidad con la correspondiente procedimiento en el antiguo widget de foto.

Tk_PhotoBlank deja completamente transparentes el área completa de la imagen de la foto. Las áreas transparentes de una imagen de foto son transparentes.

Tk_PhotoExpand solicita que la imagen del widget se expanda a al menos width x height píxeles de tamaño. Los anchos y/o alturas no se modifican si el usuario ha especificado un ancho o alto explícito con los opciones -width y/o -height, respectivamente. Si los datos de imagen se están proporcionando en muchos bloques pequeños, es más eficiente usar Tk_PhotoExpand o Tk_PhotoSetSize al principio que permitir que la imagen se expanda en muchos pequeños incrementos como los bloques se proporcionan.

Tk_PhotoExpand normalmente devuelve TCL_OK, aunque si no se puede asignar suficiente memoria para almacenar la imagen resultante, se devuelve TCL_ERROR y, si el argumento interp es no NULL, se coloca un mensaje de error en el resultado del interpretador.

Tk_PhotoSetSize especifica el tamaño de la imagen, como si el usuario hubiera especificado los valores dados width y height a los opciones -width y -height del configurador. Un valor de cero para width o height no cambia el ancho o alto de la imagen, pero permite cambiar el ancho o alto de la imagen con llamadas posteriores a Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock o Tk_PhotoExpand.

Tk_PhotoSetSize normalmente devuelve TCL_OK, aunque si no se puede asignar suficiente memoria para almacenar la imagen resultante, se devuelve TCL_ERROR y, si el argumento interp es no NULL, se coloca un mensaje de error en el resultado del interpretador.

Tk_PhotoGetSize devuelve las dimensiones de la imagen en *widthPtr y *heightPtr.

PORTABILITÉ

En Tk 8.3 y versiones anteriores, Tk_PhotoPutBlock y Tk_PhotoPutZoomedBlock tenían diferentes signatures. Si deseas compilar código que use la interfaz antigua para Tk 8.4 sin actualizar tu código, compila con el flag -DUSE_COMPOSITELESS_PHOTO_PUT_BLOCK. El código vinculado con pseudopuertos contra versiones antiguas de Tk seguirá funcionando.

En Tk 8.4, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoExpand y Tk_PhotoSetSize no tenían un argumento interp o devolvían ningún código de resultado. Si no se tenía suficiente memoria para una imagen, Tk panicearía. Esta comportamiento sigue siendo soportado si compiles tu extensión con el flag adicional -DUSE_PANIC_ON_PHOTO_ALLOC_FAILURE. El código vinculado con pseudopuertos contra versiones antiguas de Tk seguirá funcionando.

BOGUES

El Tk_PhotoImageBlock estructura utilizada para proporcionar datos de imagen a Tk_PhotoPutBlock promete gran flexibilidad en el diseño de los datos (por ejemplo, planos separados para los canales rojo, verde, azul y alfa). Sin embargo, la implementación falla en cumplir esta promesa. El problema es que el campo pixelSize se usa incorrectamente para determinar si la imagen tiene un canal alfa. Actualmente, si el desplazamiento para el canal alfa es mayor o igual que pixelSize, tk_PhotoPutblock asume que no hay datos alfa y hace la imagen totalmente opaca. Esto significa que en diseños donde los canales son separados (o en cualquier otro diseño exótico donde pixelSize tiene que ser menor que el desplazamiento del canal alfa), el canal alfa no se leerá correctamente. Para ser prudente, si este problema se corregirá en una versión futura, se recomienda siempre proporcionar datos alfa, incluso si la imagen no tiene transparencia, y usar el diseño estándar con pixelSize de 2 para grises y 4 para datos RGB con desplazamientos de 0, 0, 0, 1 o 0, 1, 2, 3 respectivamente.
