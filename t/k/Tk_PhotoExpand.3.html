NOM

Tk_FindPhoto, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoGetImage, Tk_PhotoBlank, Tk_PhotoExpand, Tk_PhotoGetSize, Tk_PhotoSetSize - manipulent les données d'image stockées dans une image photo.

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur dans lequel l'image a été créée et où l'erreur sera rapportée.
const char *imageName (entrée)
Nom de l'image photo.
Tk_PhotoHandle handle (entrée)
Handle opaque qui identifie l'image photo à affecter.
Tk_PhotoImageBlock *blockPtr (entrée)
Indique l'adresse et la disposition des données d'image.

Coordonnée X où le coin supérieur gauche du bloc sera placé dans l'image.
int y (entrée)
Coordonnée Y où le coin supérieur gauche du bloc sera placé dans l'image.

Largeur de la zone d'image à affecter (pour Tk_PhotoPutBlock) ou largeur désirée (pour Tk_PhotoExpand et Tk_PhotoSetSize).

Facteur de sous-échantillonnage dans la direction X pour les données d'image entrantes.
int subsampleY (entrée)
Facteur de sous-échantillonnage dans la direction Y pour les données d'image entrantes.
int zoomX (entrée)
Facteur de zoom à appliquer dans la direction X pour les pixels écrits dans l'image photo.
int zoomY (entrée)
Facteur de zoom à appliquer dans la direction Y pour les pixels écrits dans l'image photo.

DESCRIPTION

Tk_FindPhoto renvoie un handle opaque qui est utilisé pour identifier une image photo spécifique pour d'autres procédures. Le paramètre est le nom de l'image, c'est-à-dire le nom spécifié dans la commande image create photo ou assigné par cette commande si aucun nom n'est spécifié. Si imageName n'existe pas ou n'est pas une image photo, Tk_FindPhoto renvoie NULL.

Tk_PhotoPutBlock est utilisé pour fournir des blocs de données d'image à afficher. L'appel affecte une zone de l'image d'une taille de width x height pixels, avec son coin supérieur gauche aux coordonnées (x, y). Tous les width, height, x et y doivent être non négatifs. Si une partie de cette zone se trouve en dehors des limites actuelles de l'image, l'image est étendue pour l'inclure, à moins que l'utilisateur n'ait spécifié une taille d'image explicite avec les options de configuration du widget -width et/ou -height (voir photo(n)) ; dans ce cas, la zone est silencieusement rognée aux limites de l'image.

Le paramètre block est un pointeur vers une structure Tk_PhotoImageBlock, définie comme suit :

typedef struct {
    unsigned char *pixelPtr;
    int width;
    int height;
    int pitch;
    int pixelSize;
    int offset[4];
} Tk_PhotoImageBlock;
Le champ pixelPtr pointe vers le premier pixel, c'est-à-dire le pixel supérieur gauche du bloc. Les champs width et height spécifient les dimensions du bloc de pixels. Le champ pixelSize spécifie la différence d'adresse entre deux pixels consécutifs horizontalement. Il doit être de 4 pour les images RVB et de 2 pour les données en niveaux de gris. D'autres valeurs sont possibles, à condition que les index dans le champ offset soient ajustés de manière appropriée (par exemple, pour les données rouge, verte et bleue stockées dans des plans différents). L'utilisation de cette disposition est fortement déconseillée. En raison d'un bogue, elle peut ne pas fonctionner correctement si un canal de transparence est fourni. (voir la section BUGS ci-dessous). Le champ pitch spécifie la différence d'adresse entre deux pixels consécutifs verticalement. Le champ offset contient les index des adresses des octets qui contiennent les composantes rouge, verte, bleue et transparence (alpha) du pixel. Si les index rouge, vert et bleu sont identiques, l'image est interprétée comme étant en niveaux de gris. S'ils diffèrent, des données RVB sont supposées. Normalement, les index seront 0, 1, 2, 3 pour les données RVB et 0, 0, 0, 1 pour les données en niveaux de gris. Il est possible de fournir des données d'image sans canal de transparence en réglant le champ offset pour le canal de transparence à une valeur négative et en ajustant le champ pixelSize en conséquence. Cette utilisation est fortement déconseillée (voir la section BUGS ci-dessous).

Le paramètre compRule pour Tk_PhotoPutBlock spécifie une règle de composition indiquant quoi faire avec les pixels transparents. La valeur TK_PHOTO_COMPOSITE_OVERLAY indique que le contenu précédent de l'image photo doit être affiché à travers les bits transparents, et la valeur TK_PHOTO_COMPOSITE_SET indique que le contenu précédent de l'image photo doit être complètement ignoré et que les valeurs du bloc doivent être copiées directement. Le comportement dans Tk8.3 et les versions antérieures était équivalent à avoir TK_PHOTO_COMPOSITE_OVERLAY comme règle de composition.

Les valeurs données pour les paramètres width et height dans Tk_PhotoPutBlock ne correspondent pas nécessairement aux valeurs spécifiées dans block. Si elles sont plus petites, Tk_PhotoPutBlock extrait un sous-bloc de l'image de données fournie. Si elles sont plus grandes, les données fournies sont répétées (en mode répétition) pour remplir la zone spécifiée. Ces règles fonctionnent indépendamment dans les directions horizontale et verticale.

Tk_PhotoPutBlock renvoie normalement TCL_OK, bien que si suffisamment de mémoire ne peut être allouée pour stocker l'image résultante, il renvoie TCL_ERROR et, si l'argument interp n'est pas NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoPutZoomedBlock fonctionne comme Tk_PhotoPutBlock sauf que l'image peut être réduite ou agrandie pour l'affichage. Les paramètres subsampleX et subsampleY permettent de réduire la taille de l'image par sous-échantillonnage. Tk_PhotoPutZoomedBlock utilisera uniquement les pixels de l'image d'entrée dont les coordonnées X sont des multiples de subsampleX et dont les coordonnées Y sont des multiples de subsampleY. Par exemple, une image de 512x512 pixels peut être réduite à 256x256 en réglant subsampleX et subsampleY à 2.

Les paramètres zoomX et zoomY permettent d'agrandir l'image en répétant les pixels. Chaque pixel de l'image d'entrée (potentiellement sous-échantillonnée) est écrit dans un bloc de zoomX pixels de large et zoomY pixels de haut dans l'image affichée. Le sous-échantillonnage et le zoom peuvent être utilisés ensemble pour des effets spéciaux.

Tk_PhotoGetImage peut être utilisé pour récupérer des données d'image à partir d'une image photo. Tk_PhotoGetImage remplit les valeurs décrivant l'adresse et la disposition des données d'image que l'image photo a stockées en interne. Les valeurs sont valides jusqu'à ce que l'image soit détruite ou que sa taille soit modifiée.

Il est possible de modifier une image en écrivant directement dans les données pointées par le champ pixelPtr. Cependant, la taille de l'image ne peut pas être modifiée de cette manière. De plus, les modifications effectuées en écrivant directement dans pixelPtr ne sont pas immédiatement visibles, mais seulement après un appel à Tk_ImageChanged ou après un événement qui provoque le redessin des widgets intéressés. Pour cette raison, il est généralement préférable d'apporter des modifications avec l'aide de Tk_ImageChanged ou d'événements.

DESCRIPTION

Ces procédures manipulent les images du type photo, qui sont un format d'image flexible utilisé par le widget image Tk. Les images photo sont composées de plusieurs blocs de pixels, et peuvent être mises à jour de manière incrémentielle.

La procédure Tk_PhotoImageBlock initialise une structure TkPhotoImageBlock. Cette structure est ensuite utilisée pour passer des données d'image aux procédures Tk_PhotoPutBlock ou Tk_PhotoPutZoomedBlock. Les champs pixelSize, pitch, data, offsetRed, offsetGreen, offsetBlue et offsetAlpha décrivent le format et l'emplacement des données d'image. Les champs freeProc et clientData peuvent être utilisés pour spécifier une procédure de libération personnalisée pour les données d'image.

Tk_PhotoPutBlock copie les données du bloc d'image spécifié par blockPtr dans l'image photo à l'emplacement spécifié par offsetU et offsetV. Les pixels existants dans la zone couverte par le nouveau bloc sont remplacés. Si la zone couverte par le nouveau bloc dépasse les dimensions actuelles de l'image photo, l'image photo est agrandie pour s'adapter. La procédure renvoie TCL_OK si tout s'est bien passé, ou TCL_ERROR si une erreur s'est produite (par exemple, une allocation de mémoire insuffisante).

Tk_PhotoPutZoomedBlock est similaire à Tk_PhotoPutBlock, mais elle permet de mettre à l'échelle le bloc d'image lors de son insertion. Les arguments zoomU et zoomV spécifient les facteurs de mise à l'échelle horizontaux et verticaux, respectivement. Les arguments width et height spécifient la taille du bloc résultant après mise à l'échelle. Cela permet d'insérer des images plus petites ou plus grandes, ou d'effectuer des opérations de mise à l'échelle simples.

Tk_PhotoGetImage renvoie 1 pour la compatibilité avec la procédure correspondante dans l'ancien widget photo.

Tk_PhotoBlank efface toute la zone de l'image photo. Les zones vides d'une image photo sont transparentes.

Tk_PhotoExpand demande que l'image du widget soit étendue pour avoir au moins width x height pixels. La largeur et/ou la hauteur sont inchangées si l'utilisateur a spécifié une largeur ou une hauteur d'image explicite avec les options de configuration -width et/ou -height, respectivement. Si les données d'image sont fournies en plusieurs petits blocs, il est plus efficace d'utiliser Tk_PhotoExpand ou Tk_PhotoSetSize au début plutôt que de laisser l'image s'agrandir par petites incrémentations au fur et à mesure que les blocs d'image sont fournis.

Tk_PhotoExpand renvoie normalement TCL_OK, bien que s'il ne parvient pas à allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est renvoyé à la place et, si l'argument interp n'est pas NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoSetSize spécifie la taille de l'image, comme si l'utilisateur avait spécifié les valeurs width et height données aux options de configuration -width et -height. Une valeur de zéro pour width ou height ne change pas la largeur ou la hauteur de l'image, mais permet de changer la largeur ou la hauteur par des appels ultérieurs à Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock ou Tk_PhotoExpand.

Tk_PhotoSetSize renvoie normalement TCL_OK, bien que s'il ne parvient pas à allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est renvoyé à la place et, si l'argument interp n'est pas NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoGetSize renvoie les dimensions de l'image dans *widthPtr et *heightPtr.

PORTABILITÉ

Dans Tk 8.3 et versions antérieures, Tk_PhotoPutBlock et Tk_PhotoPutZoomedBlock avaient des signatures différentes. Si vous souhaitez compiler du code utilisant l'ancienne interface avec 8.4 sans mettre à jour votre code, compilez-le avec le flag -DUSE_COMPOSITELESS_PHOTO_PUT_BLOCK. Le code lié à l'aide de Stubs aux versions antérieures de Tk continuera de fonctionner.

Dans Tk 8.4, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoExpand et Tk_PhotoSetSize ne prenaient pas d'argument interp ni ne renvoyaient de code de résultat. Si une mémoire insuffisante était disponible pour une image, Tk paniquait. Ce comportement est toujours supporté si vous compilez votre extension avec le flag supplémentaire -DUSE_PANIC_ON_PHOTO_ALLOC_FAILURE. Le code lié à l'aide de Stubs aux versions antérieures de Tk continuera de fonctionner.

BOGUES

La structure Tk_PhotoImageBlock utilisée pour fournir des données d'image à Tk_PhotoPutBlock promet une grande flexibilité dans la disposition des données (par exemple, des plans séparés pour les canaux rouge, vert, bleu et alpha). Malheureusement, l'implémentation ne tient pas cette promesse. Le problème est que le champ pixelSize est utilisé (de manière incorrecte) pour déterminer si l'image a un canal alpha. Actuellement, si le décalage du canal alpha est supérieur ou égal à pixelSize, tk_PhotoPutblock suppose qu'il n'y a pas de données alpha et rend l'image complètement opaque. Cela signifie que pour les dispositions où les canaux sont séparés (ou toute autre disposition exotique où pixelSize doit être inférieur au décalage alpha), le canal alpha ne sera pas lu correctement. Afin d'être prudent si ce problème est corrigé dans une future version, il est fortement recommandé de toujours fournir des données alpha - même si l'image n'a pas de transparence - et d'utiliser uniquement la disposition "standard" avec un pixelSize de 2 pour les données en niveaux de gris et 4 pour les données RVB avec des offsets de 0, 0, 0, 1 ou 0, 1, 2, 3 respectivement.
