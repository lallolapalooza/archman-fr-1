NOM

Tk::overview - Un aperçu de l'extension Tk8 orientée objet pour perl5

SYNTAXE

"use Tk;"

"$main = MainWindow->new();"

"$widget = $main->Widget(...);"

"$widget->pack(...);"

...

"MainLoop;"

DESCRIPTION

En écrivant l'extension perl Tk, les objectifs étaient de fournir une interface complète à la dernière version de production de Tk de John Ousterhout, tout en fournissant une interface orientée objet au code perl.

CONTENU

Le paquet est composé de trois parties peu connectées :

pTk - Source Tk convertie
Le sous-répertoire pTk est une copie du code C de Tk8.x, modifié pour permettre son utilisation par des langages autres que Tcl d'origine. (On peut lire pTk comme 'perl' Tk ou 'portable' Tk, selon votre sensibilité.)
« Colle » Tk à Perl
Le répertoire de niveau supérieur fournit Tk.xs et tkGlue.c qui fournissent les interfaces appelables depuis perl à pTk.
Code Perl pour les Classes « Widget »
Le sous-répertoire Tk contient les divers modules perl qui composent les « Classes » visibles par les applications Tk.

Les « widgets majeurs » tels que Tk::Text se trouvent en fait dans des répertoires séparés au niveau supérieur (par exemple, Text/* pour Tk::Text) et sont chargés dynamiquement au besoin sur les plateformes qui supportent DynaLoader de perl5.

HIERARCHIE DES CLASSES

package Tk; - la « classe de base »
Tous les « noms de commandes » documentés dans Tcl/Tk sont conçus pour ressembler à des sous-routines perl et résident dans le paquet Tk. Leurs noms sont tous en minuscules. Il y a généralement très peu de commandes à ce niveau qui sont appelées directement par les applications.
package Tk::Widget; - la « classe Widget »
Il n'y a pas d'objets réels de la classe Tk::Widget ; cependant, tous les divers « widgets » de fenêtre Tk en héritent, et elle hérite à son tour de toutes les fonctions Tk de base de Tk.

Tk::Widget fournit diverses fonctions et interfaces qui sont communes à tous les Widgets.

Un widget est représenté en perl par une référence bénie vers une hash. Il y a certains membres de la hash qui sont privés à Tk et à son code tkGlue. Les clés commençant par '.' et de la forme /^_[A-Z][A-Za-z_]+_$/ (c'est-à-dire commençant et finissant par _ et avec le premier caractère après _ étant une majuscule) doivent être considérées comme réservées à Tk.

Tk::Button, Tk::Entry, Tk::Text ...
Il y a une classe pour chaque type d'élément « Tk » de widget. Certains, comme Tk::Frame, ne font pas grand-chose et n'existent réellement que pour pouvoir en hériter ou pour que le focus ou la navigation dans les menus puisse découvrir le « type » de fenêtre en cours de traitement.

D'autres classes, comme Tk::Text, fournissent de nombreuses méthodes utilisées avec « bind » de Tk pour fournir une interface riche au clavier/souris aux données des widgets.

Ces classes de widgets incluent également des conversions du code Tcl pour les liaisons d'événements, la navigation du focus clavier, les barres de menus et la navigation clavier dans les menus. Toutes les fonctions Tcl ont été converties, mais les noms ont changé (systématiquement) et ont été réparties entre les différentes classes de manière qui, je l'espère, est appropriée. Les changements de noms sont normalement : suppression du préfixe tk_ initial car la nature Tk est implicite dans le préfixe Tk::, et suppression similaire par exemple de Menu du nom s'il a été déplacé dans la classe Tk::Menu. Ainsi, 'proc tkMenuNextEntry' devient 'sub NextEntry' dans le paquet Tk::Menu.

Tk::Image
Ceci fait pour les « images » de Tk8.x ce que Tk::Widget fait pour les widgets. Les images sont nouvelles dans Tk8.x et la structure de classe n'est pas non plus mature.

Il y a trois sous-classes : Tk::Bitmap, Tk::Pixmap et Tk::Photo.

Il est possible de créer des types d'images dynamiques ou chargés automatiquement héritant de Tk::Image pour d'autres types d'images ou formats photo (par exemple, support du format TIFF).

Widgets Composites
Un composite est une sorte de « cadre » avec des sous-widgets qui lui donnent un comportement utile. Tk::Dialog est un exemple de classe de widget composite construite à partir des éléments de base Tk. L'intention est que le code utilisateur n'ait pas besoin de savoir qu'une classe particulière est un composite, et crée et configure de tels widgets de la même manière que n'importe quel autre type. Le mécanisme configure et les méthodes de la classe manipulent les sous-widgets selon les besoins.

Les widgets composites sont implémentés via Tk::Frame et l'héritage multiple. Les deux classes de base « cadre », Tk::Frame et Tk::Toplevel, incluent la classe supplémentaire Tk::Derived dans leur héritage. Tk::Derived fournit des méthodes pour permettre la définition d'options configure supplémentaires pour un widget.

Un widget composite est typiquement défini comme dérivé de Tk::Frame ou Tk::Toplevel (par exemple, Tk::Dialog).
