Quelques contexte

La programmation d'interface graphique Tk est événementielle. (Cela vous est peut-être déjà familier.) Dans les programmes événementiels, la boucle principale de l'interface graphique est extérieure au programme utilisateur et se trouve à l'intérieur de la bibliothèque graphique. Cette boucle - initiée en appelant MainLoop - surveille tous les événements intéressants et active les procédures de gestion appropriées pour traiter ces événements. Certaines de ces procédures de gestion peuvent être fournies par l'utilisateur ; d'autres feront partie de la bibliothèque.

Pour un programmeur, cela signifie que vous ne surveillez pas ce qui se passe ; au lieu de cela, vous êtes sollicité par la boîte à outils pour effectuer des actions chaque fois que nécessaire. Ainsi, vous ne surveillez pas les requêtes 'augmenter fenêtre / fermer fenêtre / redessiner fenêtre', mais vous indiquez à la boîte à outils quelle routine gérera de tels cas, et la boîte à outils appellera les procédures lorsque nécessaire. Ces procédures sont connues sous le nom de callbacks, et certaines d'entre elles sont écrites par vous.

Premières exigences

Les programmes Perl qui utilisent Tk doivent inclure "use Tk". Un programme doit également utiliser "use strict" et le commutateur -w pour s'assurer que le programme fonctionne sans erreurs courantes.

Toute application Perl/Tk commence par la création de la MainWindow de Tk. Vous créez ensuite des éléments à l'intérieur de la MainWindow, et/ou créez de nouvelles fenêtres appelées Toplevels qui contiennent également des éléments enfants, avant de démarrer la MainLoop, qui est la dernière instruction logique de votre programme. Vous pouvez également créer plus d'éléments et de fenêtres pendant l'exécution, en utilisant des callbacks. Les éléments ne sont affichés sur l'écran qu'après avoir été organisés par un gestionnaire de géométrie comme pack ; plus d'informations à ce sujet plus tard. MainLoop démarre l'interface graphique et gère tous les événements. C'est tout ! Un exemple trivial à fenêtre unique est montré ci-dessous :

#!/usr/bin/perl -w
use Tk;
use strict;
my $mw = MainWindow->new;
$mw->Label(-text => 'Bonjour, le monde !')->pack;
$mw->Button(
    -text    => 'Quitter',
    -command => sub { exit },
)->pack;
MainLoop;

Veuillez exécuter cet exemple. Il vous montre deux types de widgets, un Label et un Button, et comment ils sont empaquetés. Lorsqu'il est cliqué, le widget Button invoque le callback spécifié par l'option "-command". Enfin, notez le style typique de Tk utilisant des paires => .

Création de widget

Les fenêtres et les widgets Tk sont hiérarchiques, c'est-à-dire qu'une fenêtre inclut une ou plusieurs autres fenêtres. Vous créez la première fenêtre Tk en utilisant "MainWindow->new". Cela renvoie une poignée de fenêtre, assignée à $mw dans l'exemple ci-dessus. Gardez une trace de la poignée principale, communément appelée une référence de widget.

Vous pouvez utiliser n'importe quelle poignée Tk pour créer des widgets enfants à l'intérieur de la fenêtre (ou du widget). Ceci est fait en appelant la méthode du constructeur Tk sur la variable. Dans l'exemple ci-dessus, la méthode "Label" appelée depuis $mw crée un widget Label à l'intérieur de la MainWindow. Dans l'appel au constructeur, vous pouvez spécifier diverses options ; vous pouvez plus tard ajouter ou modifier des options pour n'importe quel widget en utilisant la méthode configure, qui prend les mêmes paramètres que le constructeur. La seule exception à la structure hiérarchique est le constructeur Toplevel, qui crée une nouvelle fenêtre de premier niveau.

Après avoir créé un widget (autre que la MainWindow ou les Toplevels, vous devez le rendre visible en appelant pack. (Ce n'est pas tout à fait vrai ; plus tard.) Si vous n'avez pas besoin de faire référence au widget après la construction et l'empaquetage, appelez pack sur les résultats du constructeur, comme montré pour le Label et le Button dans l'exemple ci-dessus. Notez que le résultat de l'appel composé est le résultat de pack, qui est une poignée Tk valide.

Les fenêtres et les widgets sont supprimés en appelant destroy sur eux ; cela supprimera et effacera le widget et tous ses enfants.

Variables et routines de rappel

La plupart des interfaces graphiques sont utilisées pour définir un ensemble de valeurs et de conditions, puis effectuer l'action appropriée. Le toolkit Tk diffère de votre système moyen basé sur des invites textuelles ou des menus, car vous ne collectez pas vous-même les paramètres et ne décidez pas d'une action basée sur un code d'entrée ; au lieu de cela, vous laissez ces valeurs à votre toolkit et ne les obtenez que lorsque l'action est effectuée.

Ainsi, là où un système traditionnel basé sur du texte ressemblerait à ceci :

#!/usr/bin/perl -w
use strict;
print "Veuillez taper un nom de police\n";
my $font = <>; chomp $font;
# Valider la police
print "Veuillez taper un nom de fichier\n";
my $filename = <>; chomp $filename;
# Valider le nom de fichier
print "Tapez <1> pour faxer, <2> pour imprimer\n";
my $option = <>; chomp $option;
if ($option eq 1) {
    print "Fax de $filename en police $font\n";
} elsif ($option eq 2) {
    print "Envoi maintenant de $filename à l'imprimante en police $font\n";
}

L'exemple légèrement plus grand ci-dessous montre comment faire cela en Tk. Notez l'utilisation des rappels. Notez également que Tk gère les valeurs, et la sous-routine utilise la méthode get pour accéder aux valeurs. Si un utilisateur change d'avis et veut changer de police à nouveau, l'application ne s'en rend jamais compte ; tout est géré par Tk.

#!/usr/bin/perl -w
use Tk;
use strict;
my $mw = MainWindow->new;
$mw->Label(-text => 'Nom du fichier')->pack;
my $filename = $mw->Entry(-width => 20);
$filename->pack;
$mw->Label(-text => 'Nom de la police')->pack;
my $font = $mw->Entry(-width => 10);
$font->pack;
$mw->Button(
    -text => 'Fax',
    -command => sub{do_fax($filename, $font)}
)->pack;
$mw->Button(
    -text => 'Imprimer',
    -command => sub{do_print($filename, $font)}
)->pack;
MainLoop;
sub do_fax {
    my ($file, $font) = @_;
    my $file_val = $file->get;
    my $font_val = $font->get;
    print "Envoi par fax de $file_val en police $font_val\n";
}
sub do_print {
    my ($file, $font) = @_;
    my $file_val = $file->get;
    my $font_val = $font->get;
    print "Envoi du fichier $file_val à l'imprimante en police $font_val\n";
}

Le packer - groupement avec les widgets Frame

Dans les exemples ci-dessus, vous avez dû remarquer les appels à pack. C'est l'une des parties les plus compliquées de Tk. L'idée de base est que toute fenêtre ou widget doit être soumis à un gestionnaire de géométrie Tk ; le packer est l'un des gestionnaires de placement, et grid est un autre.

Les actions du packer sont assez simples : lorsqu'il est appliqué à un widget, le packer positionne ce widget à la position indiquée dans l'espace restant de son parent. Par défaut, la position est en haut ; cela signifie que les éléments suivants seront placés en dessous. Vous pouvez également spécifier les positions gauche, droite ou bas. Spécifiez la position en utilisant -side => 'right'.

Des paramètres d'emballage supplémentaires spécifient le comportement du widget lorsqu'il reste de l'espace dans le Frame ou lorsque la taille de la fenêtre est augmentée. Si les widgets doivent conserver une taille fixe, ne spécifiez rien ; c'est le comportement par défaut. Pour les widgets que vous souhaitez faire remplir l'espace horizontal et/ou vertical actuel, spécifiez -fill => 'x', 'y', ou 'both' ; pour les widgets qui doivent grandir, spécifiez -expand => 1. Ces paramètres ne sont pas montrés dans l'exemple ci-dessous ; voir la démonstration widget.

Si vous souhaitez regrouper certains éléments dans une fenêtre qui ont un ordre d'emballage différent des autres, vous pouvez les inclure dans un Frame. Il s'agit d'un type de fenêtre inactif destiné à l'emballage ou au remplissage (et à jouer avec les bordures et les couleurs).

L'exemple ci-dessous montre l'utilisation de pack et de Frames :

#!/usr/bin/perl -w
use Tk;
use strict;
# Prendre le haut et le bas - maintenant le haut implicite est au milieu
my $mw = MainWindow->new;
$mw->title( 'La MainWindow' );
$mw->Label(-text => 'En haut (par défaut)')->pack;
$mw->Label(-text => 'En bas')->pack(-side => 'bottom');
$mw->Label(-text => 'Le milieu reste')->pack;
# Comme le gauche et le droite sont pris, le bas ne fonctionnera pas...
my $top1 = $mw->Toplevel;
$top1->title( 'Toplevel 1' );
$top1->Label(-text => 'Gauche')->pack(-side => 'left');
$top1->Label(-text => 'Droite')->pack(-side => 'right');
$top1->Label(-text => '?Bas?')->pack(-side => 'bottom');
# Mais quand vous utilisez des Frames, les choses fonctionnent très bien
my $top2 = $mw->Toplevel;
$top2->title( 'Toplevel 2' );
my $frame = $top2->Frame;
$frame->pack;
$frame->Label(-text => 'Gauche2')->pack(-side => 'left');
$frame->Label(-text => 'Droite2')->pack(-side => 'right');
$top2->Label(-text => 'Bas2')->pack(-side => 'bottom');
MainLoop;

Plus d'une fenêtre

La plupart des applications réelles nécessitent plus d'une fenêtre. Comme vous venez de le voir, vous pouvez créer d'autres fenêtres externes en utilisant un widget Toplevel. Chaque fenêtre est indépendante ; la destruction d'une fenêtre Toplevel n'affecte pas les autres tant qu'elles ne sont pas enfants de la Toplevel fermée. Cependant, la fermeture de la MainWindow détruira tous les widgets Toplevel restants et mettra fin à l'application. L'exemple ci-dessous montre une application triviale à trois fenêtres :

#!/usr/bin/perl -w
use Tk;
use strict;
my $mw = MainWindow->new;
fill_window($mw, 'Principal');
my $top1 = $mw->Toplevel;
fill_window($top1, 'Premier Toplevel');
my $top2 = $mw->Toplevel;
fill_window($top2, 'Second Toplevel');
MainLoop;
sub fill_window {
    my ($window, $header) = @_;
    $window->Label(-text => $header)->pack;
    $window->Button(
        -text    => 'fermer',
        -command => [$window => 'destroy']
    )->pack(-side => 'left');
    $window->Button(
        -text    => 'quitter',
        -command => [$mw => 'destroy']
    )->pack(-side => 'right');
}

Plus de rappels

Jusqu'à présent, toutes les routines de rappel montrées appelaient une procédure utilisateur. Vous pouvez également avoir une routine de rappel qui appelle une autre routine Tk. C'est ainsi que les barres de défilement sont implémentées : les barres de défilement peuvent appeler un élément Tk ou une procédure utilisateur, chaque fois que leur position a changé. L'élément Tk auquel une barre de défilement est attachée appelle la barre de défilement lorsque sa taille ou son décalage a changé. De cette façon, les éléments sont liés. Vous pouvez toujours demander la position d'une barre de défilement, ou la définir manuellement - mais les valeurs par défaut seront prises en charge.

L'exemple ci-dessous montre une Listbox avec une barre de défilement. Déplacer la barre de défilement déplace la Listbox. Balayer une Listbox (faire glisser un élément avec le bouton gauche de la souris) déplace la barre de défilement.

 #!/usr/bin/perl -w
 use Tk;
 use strict;
 my $mw = MainWindow->new;
 my $box = $mw->Listbox(
     -relief => 'sunken',
     -height  => 5,
     -setgrid => 1,
);
my @items = qw(Un Deux Trois Quatre Cinq Six Sept
               Huit Neuf Dix Onze Douze);
foreach (@items) {
   $box->insert('end', $_);
}
my $scroll = $mw->Scrollbar(-command => ['yview', $box]);
$box->configure(-yscrollcommand => ['set', $scroll]);
$box->pack(-side => 'left', -fill => 'both', -expand => 1);
$scroll->pack(-side => 'right', -fill => 'y');
MainLoop;

Notez qu'il existe une méthode pratique Scrolled qui aide à construire des widgets avec des barres de défilement automatiquement gérées.

Canevas et étiquettes

L'un des widgets les plus puissants de Tk est la fenêtre Canvas. Dans une fenêtre Canvas, vous pouvez dessiner des graphiques simples et inclure d'autres widgets. La zone du Canvas peut être plus grande que la fenêtre visible, et peut alors être défilée. Chaque élément que vous dessinez sur le canevas a son propre identifiant, et peut éventuellement avoir une ou plusieurs étiquettes. Vous pouvez faire référence à n'importe quel élément par son identifiant, et vous pouvez faire référence à n'importe quel groupe d'éléments par une étiquette commune ; vous pouvez déplacer, supprimer ou modifier des groupes d'éléments en utilisant ces étiquettes, et vous pouvez lier des actions à des étiquettes. Pour un Canvas correctement conçu (souvent structuré), vous pouvez spécifier des actions puissantes assez simplement.

Dans l'exemple ci-dessous, des actions sont liées aux cercles (clic simple) et aux éléments bleus (double-clic) ; évidemment, cela peut être étendu à n'importe quelle étiquette ou groupe d'étiquettes.

#!/usr/bin/perl -w
use Tk;
use strict;
# Créer la B<MainWindow> et le canevas
my $mw = MainWindow->new;
my $canvas = $mw->Canvas;
$canvas->pack(-expand => 1, -fill => 'both');
# Créer divers éléments
create_item($canvas, 1, 1, 'circle', 'blue', 'Jane');
create_item($canvas, 4, 4, 'circle', 'red', 'Peter');
create_item($canvas, 4, 1, 'square', 'blue', 'James');
create_item($canvas, 1, 4, 'square', 'red', 'Patricia');
# Cliquer une fois avec le bouton gauche sur un élément 'circle' déclenche une procédure
$canvas->bind('circle', '<1>' => sub {handle_circle($canvas)});
# Double-cliquer avec le bouton gauche sur un élément 'blue' déclenche une procédure
$canvas->bind('blue', '<Double-1>' => sub {handle_blue($canvas)});
MainLoop;
# Créer un élément ; utiliser les paramètres comme étiquettes (ce n'est pas un comportement par défaut !)
sub create_item {
    my ($can, $x, $y, $form, $color, $name) = @_;
    my $x2 = $x + 1;
    my $y2 = $y + 1;
    my $kind;
    $kind = 'oval' if ($form eq 'circle');
    $kind = 'rectangle' if ($form eq 'square');
    $can->create(
        ($kind, "$x" . 'c', "$y" . 'c',
        "$x2" . 'c', "$y2" . 'c'),
        -tags => [$form, $color, $name],
        -fill => $color);
}
# Ceci récupère le vrai nom (pas actuel, bleu/rouge, carré/cercle)
# Note : vous voudrez retourner une liste dans des situations réalistes...
sub get_name {
    my ($can) = @_;
    my $item = $can->find('withtag', 'current');
    my @taglist = $can->gettags($item);
    my $name;
    foreach (@taglist) {
        next if ($_ eq 'current');
        next if ($_ eq 'red' or $_ eq 'blue');
        next if ($_ eq 'square' or $_ eq 'circle');
        $name = $_;
        last;
    }
    return $name;
}
sub handle_circle {
    my ($can) = @_;
    my $name = get_name($can);
    print "Action sur le cercle $name...\n";
}
sub handle_blue {
    my ($can) = @_;
    my $name = get_name($can);
    print "Action sur l'élément bleu $name...\n";
}

Perl/Tk et Unicode

Perl/Tk suit le modèle de Perl pour la gestion d'Unicode. C'est-à-dire, si une chaîne est correctement marquée comme une chaîne de "caractères" au sens décrit dans "TERMINOLOGY" dans Encode, alors Perl/Tk affichera et gérera très probablement cette chaîne correctement.

Certaines informations de fond

QUELQUES INFORMATIONS DE FOND

Dans ce manuel, le système d'interface de Tk, qui peut être utilisé pour développer des applications en Perl, est décrit. L'encodage des caractères est un sujet important, et le système d'encodage est implémenté en utilisant la bibliothèque PerlIO. Il est décrit comment différents types d'encodages peuvent être utilisés dans le système d'E/S de Perl.

Premières exigences

EXIGENCES INITIALES

Le système d'encodage est essentiel au bon fonctionnement de Tk. Si aucun encodage n'est spécifié, il est supposé que les informations sont encodées en iso-8859-1. Dans ce cas, l'encodage doit être spécifié explicitement si le mode E/S est utilisé.

Création de widgets

CRÉATION DE WIDGETS

Tk est capable de gérer Unicode. Par conséquent, l'utilisateur doit être préparé à activer les méthodes d'entrée appropriées pour saisir des caractères non ASCII. Si un encodage qui ne couvre pas tous les codes Unicode est utilisé, un avertissement sera émis lors de l'écriture du fichier, comme indiqué :

\x{20ac} ne se mappe pas à iso-8859-1 dans /usr/local/lib/perl5/site_perl/5.8.8/mach/Tk.pm ligne 250.

Widgets Tk standard

WIDGETS TK STANDARD

Les widgets Tk sont conçus pour gérer différents types d'encodages. Pour les données provenant d'un fichier, l'encodage doit être spécifié, à moins que le contenu ne soit encodé en ASCII ou iso-8859-1 :

use Tk;
open my $FH, <:encoding(utf-8)>, "filename" or die $!;
# ou pour des données en utf-16 : open my $FH, <:encoding(utf-16)>, "filename" or die $!;
my $data = <$FH>;
tkinit->Label(-text => $data)->pack;
MainLoop;

Variables et routines de rappel

VARIABLES ET ROUTINES DE RAPPEL

Dans Tk, les variables peuvent être utilisées pour stocker des données et les routines de rappel pour exécuter des actions. Pour les données lues à partir de widgets Tk et écrites dans un fichier, l'encodage doit être spécifié explicitement, même s'il s'agit d'iso-8859-1 :

use Tk;
$mw = tkinit;
$mw->Entry(-textvariable => \$input)->pack;
$mw->Button(
    -text => "Write to file",
    -command => sub {
        open my $FH, ">:encoding(iso-8859-1)", "filename" or die $!;
        print $FH $input;
    },
)->pack;
MainLoop;

CANEVAS ET TAGS

Les canevas de Tk permettent de représenter des graphiques et d'autres éléments. Les tags d'un canevas peuvent être utilisés pour identifier des éléments spécifiques. Les tags peuvent être définis en utilisant l'encodage dans le système d'E/S de Perl.
