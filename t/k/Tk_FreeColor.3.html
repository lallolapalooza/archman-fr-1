NOM

Tk_AllocColorFromObj, Tk_GetColor, Tk_GetColorFromObj, Tk_GetColorByValue, Tk_NameOfColor, Tk_FreeColorFromObj, Tk_FreeColor - maintenir une base de données de couleurs

SYNTAXE

#include <tk.h>

XColor *
Tk_AllocColorFromObj(interp, tkwin, objPtr)

XColor *
Tk_GetColor(interp, tkwin, name)

XColor *
Tk_GetColorFromObj(tkwin, objPtr)

XColor *
Tk_GetColorByValue(tkwin, prefPtr)

const char *
Tk_NameOfColor(colorPtr)

GC
Tk_GCForColor(colorPtr, drawable)

Tk_FreeColorFromObj(tkwin, objPtr)

Tk_FreeColor(colorPtr)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur à utiliser pour le rapport d'erreurs.
Tk_Window tkwin (in)
Fenêtre dans laquelle la couleur sera utilisée.
Tcl_Obj *objPtr (in/out)
Valeur de texte décrivant la couleur souhaitée ; la représentation interne sera modifiée pour stocker un pointeur vers un (XColor *).
const char *name (in)
La description de la couleur est fournie sous forme de chaîne, et le résultat (XColor *) n'est pas stocké.
XColor *prefPtr (in)
Intensités de rouge, vert et bleu de la couleur souhaitée.
XColor *colorPtr (in)
Pointeur vers les informations de couleur X. Il doit avoir été précédemment alloué par un appel à Tk_AllocColorFromObj, Tk_GetColor ou Tk_GetColorByValue, sauf lorsqu'il est passé à Tk_NameOfColor.
Drawable drawable (in)
Drawable sur lequel le contexte graphique résultant sera utilisé. Il doit avoir le même écran et la même profondeur que la fenêtre pour laquelle la couleur a été allouée.

DESCRIPTION

Ces procédures gèrent les couleurs utilisées par une application Tk. Elles permettent de partager les couleurs lorsque cela est possible, afin de préserver l'espace de couleur de la carte mémoire, et choisissent les couleurs les plus proches lorsque l'espace de la carte mémoire est plein.

Étant donné une description textuelle d'une couleur, Tk_AllocColorFromObj localise une valeur de pixel qui peut être utilisée pour rendre la couleur dans une fenêtre spécifique. La couleur souhaitée est spécifiée par une valeur dont la valeur de chaîne doit avoir l'une des formes suivantes :

nomCouleur
N'importe lequel des noms valides d'une couleur définie dans le fichier de base de données des couleurs du serveur, tel que red ou PeachPuff.
#RGB
#RRGGBB
#RRRGGGBBB
#RRRRGGGGBBBB
Une spécification numérique des intensités de rouge, vert et bleu à utiliser pour afficher la couleur. Chaque R, G ou B représente un chiffre hexadécimal. Les quatre formes permettent de spécifier des couleurs avec 4 bits, 8 bits, 12 bits ou 16 bits. Lorsque moins de 16 bits sont fournis pour chaque couleur, ils représentent les bits de poids fort de la couleur, tandis que les bits de poids faible non remplis sont répétés à partir des bits de poids fort disponibles. Par exemple, #3a7 est identique à #3333aaaa7777.

Tk_AllocColorFromObj renvoie un pointeur vers une structure XColor ; cette structure indique les intensités exactes de la couleur allouée (qui peuvent différer légèrement de celles demandées, en fonction des limitations de l'écran) et une valeur de pixel qui peut être utilisée pour dessiner avec la couleur sur tkwin. Si une erreur se produit dans Tk_AllocColorFromObj (comme un nom de couleur inconnu), NULL est renvoyé et un message d'erreur est stocké dans le résultat de interp si interp n'est pas NULL. Si la carte mémoire de tkwin est pleine, Tk_AllocColorFromObj utilisera la couleur la plus proche existante dans la carte mémoire. Tk_AllocColorFromObj met en cache les informations sur la valeur retournée dans objPtr, ce qui accélère les appels ultérieurs aux procédures telles que Tk_AllocColorFromObj et Tk_GetColorFromObj.

Tk_GetColor est identique à Tk_AllocColorFromObj, à la différence près que la description de la couleur est spécifiée par une chaîne de caractères au lieu d'un objet. Cela empêche Tk_GetColor de stocker la valeur retournée, ce qui rend Tk_GetColor moins efficace que Tk_AllocColorFromObj.

Tk_GetColorFromObj renvoie le jeton d'une couleur existante, étant donné la fenêtre et la description utilisées pour créer la couleur. Tk_GetColorFromObj ne crée pas réellement la couleur ; la couleur doit avoir été créée précédemment par un appel à Tk_AllocColorFromObj ou Tk_GetColor. La valeur renvoyée est stockée dans objPtr, ce qui accélère les appels ultérieurs à Tk_GetColorFromObj avec le même objPtr et le même tkwin.

Tk_GetColorByValue est similaire à Tk_GetColor, à la différence près que la couleur souhaitée est spécifiée par les champs red, green et blue de la structure pointée par colorPtr.

Ce paquet maintient une base de données de toutes les couleurs actuellement utilisées. Si la même couleur est requise plusieurs fois par Tk_GetColor ou Tk_AllocColorFromObj (par exemple, par différentes fenêtres), ou si les mêmes intensités sont requises plusieurs fois par Tk_GetColorByValue, les valeurs de pixel existantes sont réutilisées. La réutilisation d'une valeur de pixel évite toute interaction avec le serveur d'affichage, ce qui rend l'allocation beaucoup plus efficace. Ces procédures offrent également une interface portable qui fonctionne sur tous les systèmes d'exploitation. Pour cette raison, vous devriez généralement utiliser Tk_AllocColorFromObj, Tk_GetColor ou Tk_GetColorByValue plutôt que des procédures de plus bas niveau comme XAllocColor.

Étant donné que différents appels à ce paquet peuvent renvoyer la même valeur de pixel partagée, les appelants ne doivent jamais modifier la couleur d'un pixel renvoyé par ces procédures. Si une valeur de couleur doit être modifiée dynamiquement, XAllocColorCells doit être utilisé pour allouer la valeur de pixel de la couleur.

La procédure Tk_NameOfColor est approximativement l'inverse de Tk_GetColor. Si votre colorPtr a été créé par Tk_AllocColorFromObj ou Tk_GetColor, la valeur renvoyée est la chaîne qui a été utilisée pour créer la couleur. Si colorPtr a été créé par un appel à Tk_GetColorByValue ou par tout autre mécanisme, la valeur renvoyée est une chaîne qui pourrait être passée à Tk_GetColor pour renvoyer la même couleur. Remarque : la valeur renvoyée par Tk_NameOfColor n'est garantie que jusqu'au prochain appel à Tk_NameOfColor.

Tk_GCForColor renvoie un contexte graphique dont le champ foreground est le pixel alloué pour colorPtr et dont les autres champs ont des valeurs par défaut. Cela fournit un moyen simple de dessiner avec une couleur. Le contexte graphique est mis en cache avec la couleur et n'existera que tant que colorPtr existera ; il sera libéré lorsque le dernier référent de colorPtr sera libéré en appelant Tk_FreeColor.

Lorsqu'une couleur n'est plus nécessaire, Tk_FreeColorFromObj ou Tk_FreeColor doit être appelé pour la libérer. Pour Tk_FreeColorFromObj, la couleur à libérer est spécifiée avec les mêmes informations qui ont été utilisées pour la créer ; pour Tk_FreeColor, la couleur à libérer est spécifiée par un pointeur vers sa structure XColor. Il doit y avoir exactement un appel à Tk_FreeColorFromObj ou Tk_FreeColor pour chaque appel à Tk_AllocColorFromObj, Tk_GetColor ou Tk_GetColorByValue.
