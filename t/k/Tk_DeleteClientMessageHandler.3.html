Tk_CreateClientMessageHandler(3) Procédures de la bibliothèque Tk Tk_CreateClientMessageHandler(3)

NOM

Tk_CreateClientMessageHandler, Tk_DeleteClientMessageHandler - associer une procédure de rappel aux événements X de type ClientMessage

SYNTAXE

#include <tk.h>

Tk_CreateClientMessageHandler(proc)

Tk_DeleteClientMessageHandler(proc)

ARGUMENTS

Tk_ClientMessageProc *proc (entree)
Procédure à appeler chaque fois qu'un événement X de type ClientMessage se produit sur n'importe quel écran.

DESCRIPTION

Tk_CreateClientMessageHandler fait en sorte que proc soit appelée à l'avenir chaque fois qu'un événement X de type ClientMessage se produit et qui n'est pas géré par WM_PROTOCOL. Tk_CreateClientMessageHandler est destiné à être utilisé par des applications qui doivent surveiller les événements X de type ClientMessage, tels que les applications de glisser-déposer.

Le rappel à proc sera effectué par Tk_HandleEvent ; ce mécanisme ne fonctionne que dans les programmes qui distribuent les événements via Tk_HandleEvent (ou via d'autres procédures Tk qui appellent Tk_HandleEvent, telles que Tcl_DoOneEvent ou Tk_MainLoop).

Proc doit avoir des arguments et un résultat qui correspondent au type Tk_ClientMessageProc :

typedef int Tk_ClientMessageProc(
        Tk_Window tkwin,
        XEvent *eventPtr);
Le paramètre tkwin de proc est la fenêtre Tk associée à cet événement. EventPtr est un pointeur vers l'événement X.

Chaque fois qu'un événement X de type ClientMessage est traité par Tk_HandleEvent, proc est appelé s'il n'a pas été traité comme un WM_PROTOCOL. La valeur de retour de proc est normalement 0. Une valeur de retour non nulle indique que l'événement ne doit pas être traité davantage ; c'est-à-dire que proc a effectué tout le traitement autorisé pour l'événement.

S'il existe plusieurs gestionnaires d'événements de type ClientMessage, chacun est appelé pour chaque événement, dans l'ordre où ils ont été établis.

Tk_DeleteClientMessageHandler peut être appelé pour supprimer un gestionnaire d'événements de type ClientMessage précédemment créé : il supprime chaque gestionnaire qu'il trouve qui correspond à l'argument proc. Si aucun gestionnaire de ce type n'existe, Tk_DeleteClientMessageHandler retourne sans rien faire. Bien que Tk le prenne en charge, il est probablement déconseillé d'avoir plus d'un rappel avec le même argument proc.
