NOM

Tk::DItem - Éléments d'affichage Tix

SYNOPSIS

DESCRIPTION

Les éléments d'affichage et les types d'éléments d'affichage de Tix sont conçus pour résoudre un problème général : de nombreux widgets Tix (existants et prévus) affichent de nombreux éléments de nombreux types simultanément.

Par exemple, un widget de liste hiérarchique (voir Tk::HList) peut afficher des éléments d'images, de texte brut et de sous-fenêtres sous forme de hiérarchie. Un autre widget, le widget de liste tabulaire (voir Tk::TList), affiche également des éléments des mêmes types, bien qu'il organise les éléments sous forme de tableau. Encore un autre widget, le widget tableur (voir Tk::TixGrid), affiche également des éléments de types similaires, mais dans un format encore différent.

Dans ces exemples, les éléments d'affichage dans différents widgets ne diffèrent que par la façon dont ils sont arrangés par le widget hôte. Dans Tix, les éléments d'affichage sont clairement séparés des widgets hôtes. L'avantage est double : premièrement, la création et la configuration des éléments d'affichage deviennent uniformes sur les différents widgets hôtes. Deuxièmement, de nouveaux types d'éléments d'affichage peuvent être ajoutés sans avoir à modifier les widgets hôtes existants.

D'une certaine manière, les éléments d'affichage Tix sont similaires aux éléments du widget canvas de Tk. Cependant, contrairement aux éléments du canvas de Tix, les éléments du canvas ne sont pas indépendants du widget canvas ; cela rend impossible l'utilisation des éléments du canvas dans d'autres types de widgets TK.

L'apparence d'un élément d'affichage est contrôlée par un ensemble d'attributs. On observe que chaque attribut appartient généralement à l'une des deux catégories : « individuel » ou « collectif ». Par exemple, les éléments textuels d'un widget HList peuvent afficher chacun une chaîne de caractères différente ; cependant, dans la plupart des cas, les éléments textuels partagent la même couleur, la même police et le même espacement. Au lieu de conserver une version dupliquée des mêmes attributs dans chaque élément d'affichage, il serait avantageux de placer les attributs collectifs dans un objet spécial appelé style d'affichage. Premièrement, il y a la question de l'espace : un widget hôte peut avoir des milliers d'éléments ; conserver des attributs dupliqués serait très coûteux. Deuxièmement, lorsqu'il devient nécessaire de modifier un attribut collectif, tel que le changement de la couleur de premier plan de tous les éléments textuels en rouge, il sera plus efficace de ne modifier que l'objet de style d'affichage plutôt que de modifier tous les éléments textuels un par un.

Les attributs d'un élément d'affichage sont donc stockés à deux endroits : il possède un ensemble d'options d'élément pour stocker ses attributs individuels. Chaque élément d'affichage est également associé à un style d'affichage, qui spécifie les attributs collectifs de tous les éléments qui lui sont associés.

La division entre les attributs individuels et collectifs est fixe et ne peut être modifiée. Ainsi, lorsqu'il devient nécessaire que certains éléments diffèrent dans leurs attributs collectifs, deux styles d'affichage ou plus peuvent être utilisés. Par exemple, supposez que vous souhaitiez afficher deux colonnes d'éléments textuels dans un widget HList, une colonne en rouge et l'autre en bleu. Vous pouvez créer un objet TextStyle appelé « $red » qui définit un premier plan rouge, et un autre appelé « $blue », qui définit un premier plan bleu. Vous pouvez ensuite associer tous les éléments textuels de la première colonne à « $red » et ceux de la deuxième colonne à « $blue ».

TYPES D'ÉLÉMENTS D'AFFICHAGE ET OPTIONS

Actuellement, il existe trois types d'éléments d'affichage : texte, imagetext et fenêtre.

ÉLÉMENTS IMAGETEXT

Les éléments d'affichage de type imagetext sont utilisés pour afficher une image ainsi qu'une chaîne de texte. Les éléments Imagetext prennent en charge les options suivantes :

Options d'élément Imagetext

Nom : bitmap
Classe : Bitmap
Commutateur : -bitmap
Spécifie le bitmap à afficher dans l'élément.
Nom : image
Classe : Image
Commutateur : -image
Spécifie l'image à afficher dans l'élément. Lorsque les options -bitmap et -image sont spécifiées, seule l'image sera affichée.
Nom : imageTextStyle
Classe : ImageTextStyle
Commutateur : -style
Spécifie le style d'affichage à utiliser pour cet élément. Doit être le nom d'un style d'affichage imagetext qui a déjà été créé avec ItemStyle.
Nom : showImage
Classe : ShowImage
Commutateur : -showimage
Une valeur booléenne qui spécifie si l'image/le bitmap doit être affiché(e).
Nom : showText
Classe : ShowText
Commutateur : -showtext
Une valeur booléenne qui spécifie si la chaîne de texte doit être affichée.
Nom : text
Classe : Text
Commutateur : -text
Spécifie la chaîne de texte à afficher dans l'élément.
Nom : underline
Classe : Underline
Commutateur : -underline
Spécifie l'index entier d'un caractère à souligner dans la chaîne de texte de l'élément. 0 correspond au premier caractère du texte affiché dans le widget, 1 au caractère suivant, et ainsi de suite.

Options de style Imagetext

Les informations de style des éléments imagetext sont stockées dans le style d'affichage imagetext. Les options suivantes sont prises en charge :

OPTIONS STANDARD

-activebackground -activeforeground -anchor -background -disabledbackground -disabledforeground -foreground -font -justify -padx -pady -selectbackground -selectforeground -wraplength

Voir Tk::options pour les détails des options standard.

OPTIONS SPÉCIFIQUES AU STYLE

Nom : gap
Classe : Gap
Commutateur : -gap
Spécifie la distance entre le bitmap/image et la chaîne de texte, en pixels.
Nom : textAnchor
Classe : TextAnchor
Commutateur : -textanchor
La position d'ancrage sur l'image à laquelle la partie texte est attachée. Ceci est une addition de perl/Tk. Par défaut, c'est e pour la compatibilité avec Tix standard. Les cas intéressants sont
n
Le texte est centré au-dessus de l'image.
s
Le texte est centré en dessous de l'image.
e
Le texte est centré à droite de l'image.
w
Le texte est centré à gauche de l'image.
c
Le texte est centré sur l'image.

Les options sw,

se, ne, y b<nw> los casos parecen verse.

Pour que les éléments s'alignent correctement, il faut souvent aussi spécifier -anchor. Par exemple, avec la valeur par défaut e, l'ancrage de l'élément en tant que tout w fera que les images s'alignent en haut, en bas, à gauche, le texte étant collé sur le côté droit.

Les éléments de type text sont utilisés pour afficher une chaîne de caractères dans un widget. Les éléments de type text supportent les options suivantes :

Options d'élément de texte

Nom : textStyle
Classe : TextStyle
Commutateur : -style
Spécifie le style d'affichage à utiliser pour cet élément de texte. Doit être le nom d'un style text déjà créé avec ItemStyle.
Nom : text
Classe : Text
Commutateur : -text
Spécifie la chaîne de caractères à afficher dans l'élément.
Nom : underline
Classe : Underline
Commutateur : -underline
Spécifie l'index du caractère à souligner dans l'élément. 0 correspond au premier caractère de la chaîne de caractères affichée dans le widget, 1 au suivant, et ainsi de suite.

Options de style de texte

OPTIONS STANDARD

-activebackground -activeforeground -anchor -background -disabledbackground -disabledforeground -foreground -font -justify -padx -pady -selectbackground -selectforeground -wraplength

Voir Tk::options pour les détails des options standard.

ÉLÉMENTS DE FENÊTRE

Les éléments de type window sont utilisés pour afficher une sous-fenêtre dans un widget. Les éléments Window supportent les options suivantes :

Options d'élément de fenêtre

Nom : windowStyle
Classe : WindowStyle
Commutateur : -style
Spécifie le style d'affichage à utiliser pour cet élément de fenêtre. Doit être le nom d'un style de fenêtre window déjà créé avec la méthode ItemStyle.
Nom : window
Classe : Window
Commutateur : -window
Alias : -widget
Spécifie la sous-fenêtre à afficher dans l'élément.

Options de style de fenêtre

OPTIONS DE STYLE STANDARD

-anchor -padx -pady

Voir Tk::options pour les détails des options standard.

CRÉATION D'ÉLÉMENTS D'AFFICHAGE

Les éléments d'affichage n'existent pas d'eux-mêmes et ne peuvent pas être créés indépendamment des widgets dans lesquels ils se trouvent. En général, les éléments d'affichage sont créés à l'aide de méthodes spéciales de leurs widgets « hôtes ». Par exemple, les widgets HList ont la méthode item pour créer de nouveaux éléments d'affichage. Le code suivant crée un nouvel élément de texte dans la troisième colonne de l'entrée foo dans un widget HList :

my $hlist = $parent->HList(-columns=>3);
$hlist->add('foo');
$hlist->itemCreate('foo', 2, -itemtype=>'text', -text=>'Hello');

La méthode itemCreate du widget HList accepte un nombre variable d'arguments. L'argument spécial -itemtype spécifie le type d'élément d'affichage à créer. Les options valides pour ce type d'élément peuvent être spécifiées à l'aide de paires d'options option-valeur.

Après la création de l'élément d'affichage, il peut être configuré ou supprimé à l'aide des méthodes fournies par le widget qui héberge l'élément. Par exemple, le widget HList a les méthodes itemConfigure, itemCget et itemDelete pour accéder aux éléments d'affichage.

CRÉATION ET MANIPULATION DE STYLES D'ÉLÉMENT

Les styles d'élément sont créés avec ItemStyle :

SYNTAXE

   $widget->ItemStyle(itemType ?,-stylename=>name? ?,-refwindow=>pathName? ?,option=>value, ...>?);

itemType doit être l'un des types d'éléments d'affichage existants, tels que text, imagetext, window ou tout nouveau type ajouté par l'utilisateur. Des arguments supplémentaires peuvent être fournis sous forme d'une ou plusieurs paires d'options option-valeur. option peut être l'une des options valides pour ce style d'élément ou l'une des suivantes :

-stylename => name
Spécifie un nom pour ce style. S'il n'est pas spécifié, un nom par défaut sera choisi pour ce style.
-refwindow => $otherwidget
Spécifie une fenêtre à utiliser comme valeur par défaut pour les styles d'éléments. Si elle n'est pas spécifiée, le $widget sera utilisé. Les valeurs par défaut pour les styles d'éléments peuvent être définies à l'aide des bases d'options. L'exemple suivant définit les options -disablebackground et -disabledforeground d'un style de texte à l'aide de la base d'options : 
$widget->optionAdd('*table.list*disabledForeground' => 'blue');
$widget->optionAdd('*table.list*disabledBackground' => 'darkgray');
$widget->ItemStyle('text', -refwindow => $table_list, -fg => 'red');

En utilisant la base d'options pour définir les options des styles d'éléments, nous pouvons éviter le codage en dur des valeurs d'options et permettre à l'utilisateur plus de flexibilité dans la personnalisation. Voir Tk::option pour une description détaillée de la base d'options.

MÉTHODES DE STYLE

La méthode ItemStyle crée un objet. Cet objet supporte les méthodes configure et cget décrites dans Tk::options, qui peuvent être utilisées pour interroger et modifier les options décrites ci-dessus.

Les méthodes supplémentaires suivantes sont disponibles pour les styles d'éléments :

$style->delete
Détruit cet objet de style d'élément.

EXEMPLE

L'exemple suivant crée deux colonnes de données dans un widget HList. La première colonne est en rouge et la seconde en bleu. Les couleurs des colonnes sont contrôlées par deux styles de texte différents. L'ancre et la police de la deuxième colonne sont également choisies de manière à ce que les données d'entrée s'alignent correctement.

use strict;
use Tk;
use Tk::HList;
use Tk::ItemStyle;
my $mw = MainWindow->new();
my $hlist = $mw->HList(-columns=>2)->pack;
my $red  = $hlist->ItemStyle('text', -foreground=>'#800000');
my $blue = $hlist->ItemStyle('text', -foreground=>'#000080', -anchor=>'e');
my $e;
foreach ([Joe => '$10,000'], [Peter => '$20,000'],
         [Raj => '$90,000'],  [Zinh => '$0']) {
    $e = $hlist->addchild("");
    $hlist->itemCreate($e, 0, -itemtype=>'text',
             -text=>$_->[0], -style=>$red );
    $hlist->itemCreate($e, 1, -itemtype=>'text',
             -text=>$_->[1], -style=>$blue);
}
Tk::MainLoop;
