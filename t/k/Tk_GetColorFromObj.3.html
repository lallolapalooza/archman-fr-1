Tk_AllocColorFromObj(3) Procédures de la bibliothèque Tk Tk_AllocColorFromObj(3)

NOM

Tk_AllocColorFromObj, Tk_GetColor, Tk_GetColorFromObj, Tk_GetColorByValue, Tk_NameOfColor, Tk_FreeColorFromObj, Tk_FreeColor - gérer la base de données des couleurs

SYNOPIS

#include <tk.h>

XColor *
Tk_AllocColorFromObj(interp, tkwin, objPtr)

XColor *
Tk_GetColor(interp, tkwin, name)

XColor *
Tk_GetColorFromObj(tkwin, objPtr)

XColor *
Tk_GetColorByValue(tkwin, prefPtr)

const char *
Tk_NameOfColor(colorPtr)

GC
Tk_GCForColor(colorPtr, drawable)

Tk_FreeColorFromObj(tkwin, objPtr)

Tk_FreeColor(colorPtr)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur à utiliser pour la signalisation des erreurs.
Tk_Window tkwin (entrée)
Jeton de la fenêtre dans laquelle la couleur sera utilisée.
Tcl_Obj *objPtr (entrée/sortie)
La valeur de chaîne décrit la couleur souhaitée ; la représentation interne sera modifiée pour mettre en cache le pointeur vers le (XColor *) correspondant.
const char *name (entrée)
Identique à objPtr sauf que la description de la couleur est passée sous forme de chaîne et que le (XColor *) résultant n'est pas mis en cache.
XColor *prefPtr (entrée)
Indique les intensités rouge, verte et bleue de la couleur souhaitée.
XColor *colorPtr (entrée)
Pointeur vers les informations de couleur X. Doit avoir été alloué par un appel précédent à Tk_AllocColorFromObj, Tk_GetColor ou Tk_GetColorByValue, sauf lorsqu'il est passé à Tk_NameOfColor.
Drawable drawable (entrée)
Dessinable dans lequel le contexte graphique résultant sera utilisé. Doit avoir le même écran et la même profondeur que la fenêtre pour laquelle la couleur a été allouée.

DESCRIPTION

Ces procédures gèrent les couleurs utilisées par une application Tk. Elles permettent de partager les couleurs lorsque cela est possible, afin de préserver l'espace de la palette de couleurs, et elles choisissent les couleurs disponibles les plus proches lorsque l'espace de la palette est épuisé.

Étant donné une description textuelle d'une couleur, Tk_AllocColorFromObj localise une valeur de pixel qui peut être utilisée pour rendre la couleur dans une fenêtre particulière. La couleur souhaitée est spécifiée avec une valeur dont la valeur de chaîne doit avoir l'une des formes suivantes :

nomcouleur
Tous les noms textuels valides pour une couleur définie dans le fichier de base de données des couleurs du serveur, tels que red ou PeachPuff.
#RGB
#RRGGBB
#RRRGGGBBB
#RRRRGGGGBBBB
Une spécification numérique des intensités rouge, verte et bleue à utiliser pour afficher la couleur. Chaque R, G ou B représente un seul chiffre hexadécimal. Les quatre formes permettent de spécifier des couleurs avec des valeurs de 4 bits, 8 bits, 12 bits ou 16 bits. Lorsque moins de 16 bits sont fournis pour chaque couleur, ils représentent les bits les plus significatifs de la couleur, tandis que les bits inférieurs non remplis seront répliqués de manière répétée à partir des bits supérieurs disponibles. Par exemple, #3a7 est identique à #3333aaaa7777.

Tk_AllocColorFromObj renvoie un pointeur vers une structure XColor ; la structure indique les intensités exactes de la couleur allouée (qui peuvent différer légèrement de celles demandées, en fonction des limitations de l'écran) et une valeur de pixel qui peut être utilisée pour dessiner avec la couleur dans tkwin. Si une erreur se produit dans Tk_AllocColorFromObj (comme un nom de couleur inconnu), NULL est renvoyé et un message d'erreur est stocké dans le résultat de interp si interp n'est pas NULL. Si la palette de couleurs de tkwin est pleine, Tk_AllocColorFromObj utilisera la couleur existante la plus proche dans la palette. Tk_AllocColorFromObj met en cache les informations sur la valeur de retour dans objPtr, ce qui accélère les appels futurs à des procédures telles que Tk_AllocColorFromObj et Tk_GetColorFromObj.

Tk_GetColor est identique à Tk_AllocColorFromObj sauf que la description de la couleur est spécifiée avec une chaîne au lieu d'une valeur. Cela empêche Tk_GetColor de mettre en cache la valeur de retour, donc Tk_GetColor est moins efficace que Tk_AllocColorFromObj.

Tk_GetColorFromObj renvoie le jeton d'une couleur existante, étant donné la fenêtre et la description utilisées pour créer la couleur. Tk_GetColorFromObj ne crée pas réellement la couleur ; la couleur doit déjà avoir été créée par un appel précédent à Tk_AllocColorFromObj ou Tk_GetColor. La valeur de retour est mise en cache dans objPtr, ce qui accélère les appels futurs à Tk_GetColorFromObj avec le même objPtr et tkwin.

Tk_GetColorByValue est similaire à Tk_GetColor sauf que la couleur souhaitée est indiquée avec les champs red, green et blue de la structure pointée par colorPtr.

Ce package maintient une base de données de toutes les couleurs actuellement utilisées. Si la même couleur est demandée plusieurs fois à partir de Tk_GetColor ou Tk_AllocColorFromObj (par exemple, par différentes fenêtres), ou si les mêmes intensités sont demandées plusieurs fois à partir de Tk_GetColorByValue, alors les valeurs de pixels existantes seront réutilisées. La réutilisation d'un pixel existant évite toute interaction avec le serveur d'affichage, ce qui rend l'allocation beaucoup plus efficace. Ces procédures fournissent également une interface portable qui fonctionne sur toutes les plateformes. Pour cette raison, vous devriez généralement utiliser Tk_AllocColorFromObj, Tk_GetColor ou Tk_GetColorByValue au lieu de procédures de plus bas niveau comme XAllocColor.

Étant donné que différents appels à ce package peuvent renvoyer la même valeur de pixel partagée, les appelants ne doivent jamais modifier la couleur d'un pixel renvoyé par les procédures. Si vous devez modifier une valeur de couleur dynamiquement, vous devez utiliser XAllocColorCells pour allouer la valeur de pixel pour la couleur.

La procédure Tk_NameOfColor est à peu près l'inverse de Tk_GetColor. Si son argument colorPtr a été créé par Tk_AllocColorFromObj ou Tk_GetColor, la valeur de retour est la chaîne qui a été utilisée pour créer la couleur. Si colorPtr a été créé par un appel à Tk_GetColorByValue, ou par tout autre mécanisme, alors la valeur de retour est une chaîne qui pourrait être passée à Tk_GetColor pour renvoyer la même couleur. Remarque : la chaîne renvoyée par Tk_NameOfColor n'est garantie de persister que jusqu'au prochain appel à Tk_NameOfColor.

Tk_GCForColor renvoie un contexte graphique dont le champ foreground est le pixel alloué pour colorPtr et dont les autres champs ont tous des valeurs par défaut. Cela fournit un moyen facile de faire des dessins de base avec une couleur. Le contexte graphique est mis en cache avec la couleur et existera uniquement tant que colorPtr existera ; il est libéré lorsque la dernière référence à colorPtr est libérée en appelant Tk_FreeColor.

Lorsqu'une couleur n'est plus nécessaire, Tk_FreeColorFromObj ou Tk_FreeColor doit être appelé pour la libérer. Pour Tk_FreeColorFromObj, la couleur à libérer est spécifiée avec les mêmes informations utilisées pour la créer ; pour Tk_FreeColor, la couleur à libérer est spécifiée avec un pointeur vers sa structure XColor. Il doit y avoir exactement un appel à Tk_FreeColorFromObj ou Tk_FreeColor pour chaque appel à Tk_AllocColorFromObj, Tk_GetColor ou Tk_GetColorByValue.

Tk_GetColorFromObj

Nom

Tk_GetColorFromObj - convertit une chaîne en une couleur

Syntaxe

#include <tk.h>

int
Tk_GetColorFromObj(interp, valuePtr, colorPtr)
Tcl_Interp *interp;
Tcl_Obj *valuePtr;
Pixel *colorPtr;

Description

La procédure Tk_GetColorFromObj est utilisée pour convertir une chaîne représentant une couleur en une représentation interne de cette couleur. La chaîne est fournie sous forme d'un Tcl_Obj, ce qui permet une gestion efficace des objets Tcl. Le résultat est stocké dans le champ Pixel pointé par colorPtr.

La chaîne peut représenter une couleur de plusieurs manières :

  • Un nom de couleur standard (par exemple, "red", "blue", "gray").
  • Un triplet RVB hexadécimal (par exemple, "#RRGGBB" ou "#RGB").

Si la conversion réussit, la procédure renvoie TCL_OK et le champ Pixel est rempli avec la couleur convertie. Sinon, elle renvoie TCL_ERROR et définit l'information d'erreur dans l'interpréteur interp.

Arguments

  • interp : Pointeur vers l'interpréteur Tcl où stocker les informations d'erreur en cas d'échec.
  • valuePtr : Pointeur vers le Tcl_Obj contenant la chaîne représentant la couleur.
  • colorPtr : Pointeur vers une variable de type Pixel où le résultat de la conversion sera stocké.

Valeur de retour

TCL_OK si la conversion réussit, TCL_ERROR sinon.
