NOM

Tk::Scrollbar - Créer et manipuler des widgets Scrollbar

SYNOPSIS

$scrollbar = $parent->Scrollbar(?options?);

OPTIONS STANDARDS

-activebackground -highlightbackground -orient -takefocus -background -highlightcolor -relief -troughcolor -borderwidth -highlightthickness -repeatdelay -cursor -jump -repeatinterval

Voir Tk::options pour les détails sur les options standards.

OPTIONS SPECIFIQUES AU WIDGET

Nom : activeRelief
Classe : ActiveRelief
Commutateur : -activerelief
Spécifie le relief à utiliser lors de l'affichage de l'élément actif, le cas échéant. Les éléments autres que l'élément actif sont toujours affichés avec un relief élevé.
Nom : command
Classe : Command
Commutateur : -command
Spécifie un callback à appeler pour changer la vue dans le widget associé au scrollbar. Lorsqu'un utilisateur demande un changement de vue en manipulant le scrollbar, le callback est appelé. Le callback reçoit des arguments supplémentaires comme décrit plus loin. Cette option a presque toujours une valeur telle que [xview => $widget] ou [yview => $widget], composée d'un objet widget et soit de xview (si le scrollbar est pour le défilement horizontal) soit de yview (pour le défilement vertical). Tous les widgets déroulables ont des méthodes xview et yview qui acceptent exactement les arguments supplémentaires ajoutés par le scrollbar, comme décrit dans "COMMANDES DE DÉFILEMENT" ci-dessous.
Nom : elementBorderWidth
Classe : BorderWidth
Commutateur : -elementborderwidth
Spécifie la largeur des bordures dessinées autour des éléments internes du scrollbar (les deux flèches et le curseur). La valeur peut avoir l'une des formes acceptées par Tk_GetPixels. Si cette valeur est inférieure à zéro, la valeur de l'option borderWidth est utilisée à la place.
Nom : width
Classe : Width
Commutateur : -width
Spécifie la dimension étroite souhaitée de la fenêtre du scrollbar, sans inclure la bordure 3D, le cas échéant. Pour les scrollbars verticaux, ce sera la largeur et pour les scrollbars horizontaux, ce sera la hauteur. La valeur peut avoir l'une des formes acceptées par Tk_GetPixels.

DESCRIPTION

La méthode Scrollbar crée une nouvelle fenêtre (donnée par l'argument $widget) et en fait un widget scrollbar. Des options supplémentaires, décrites ci-dessus, peuvent être spécifiées en ligne de commande ou dans la base d'options pour configurer certains aspects du scrollbar tels que ses couleurs, son orientation et son relief. La commande scrollbar renvoie son argument $widget. Au moment où cette commande est invoquée, aucune fenêtre nommée $widget ne doit exister, mais le parent de $widget doit exister.

Un scrollbar est un widget qui affiche deux flèches, une à chaque extrémité du scrollbar, et un *curseur* dans la partie centrale du scrollbar. Il fournit des informations sur ce qui est visible dans une *fenêtre associée* qui affiche un document quelconque (tel qu'un fichier en cours d'édition ou un dessin). La position et la taille du curseur indiquent quelle portion du document est visible dans la fenêtre associée. Par exemple, si le curseur d'un scrollbar vertical couvre le premier tiers de la zone entre les deux flèches, cela signifie que la fenêtre associée affiche le premier tiers de son document.

Les scrollbars peuvent être utilisés pour ajuster la vue dans la fenêtre associée en cliquant ou en faisant glisser la souris. Voir "LIENS" ci-dessous pour plus de détails.

ÉLÉMENTS

Un scrollbar affiche cinq éléments, auxquels on fait référence dans les méthodes du scrollbar :

flèche1
La flèche supérieure ou gauche du scrollbar.
gouttière1
La région entre le curseur et flèche1.
curseur
Le rectangle qui indique ce qui est visible dans le widget associé.
gouttière2
La région entre le curseur et flèche2.
flèche2
La flèche inférieure ou droite du scrollbar.

MÉTHODES DU WIDGET

La méthode Scrollbar crée un objet widget. Cet objet prend en charge les méthodes configure et cget décrites dans Tk::options, qui peuvent être utilisées pour interroger et modifier les options décrites ci-dessus. Le widget hérite également de toutes les méthodes fournies par la classe générique Tk::Widget.

Les méthodes supplémentaires suivantes sont disponibles pour les widgets scrollbar :

$scrollbar->activate(?element?)
Marque l'élément indiqué par element comme actif, ce qui le fait afficher comme spécifié par les options activeBackground et activeRelief. Les seules valeurs d'élément comprises par cette commande sont arrow1, slider, ou arrow2. Si toute autre valeur est spécifiée, aucun élément du scrollbar ne sera actif. Si element n'est pas spécifié, la commande renvoie le nom de l'élément qui est actuellement actif, ou une chaîne vide si aucun élément n'est actif.
$scrollbar->delta(deltaX, deltaY)
Renvoie un nombre réel indiquant le changement fractionnel du réglage du scrollbar correspondant à un changement donné de la position du curseur. Par exemple, si le scrollbar est horizontal, le résultat indique de combien le réglage du scrollbar doit changer pour déplacer le curseur de deltaX pixels vers la droite (deltaY est ignoré dans ce cas). Si le scrollbar est vertical, le résultat indique de combien le réglage du scrollbar doit changer pour déplacer le curseur de deltaY pixels vers le bas. Les arguments et le résultat peuvent être zéro ou négatifs.
$scrollbar->fraction(x, y)
Renvoie un nombre réel compris entre 0 et 1 indiquant où se situe le point donné par x et y dans la zone de la gouttière du scrollbar. La valeur 0 correspond au haut ou à gauche de la gouttière, la valeur 1 correspond au bas ou à droite, 0.5 correspond au milieu, etc. X et y doivent être des coordonnées en pixels relatives au widget scrollbar. Si x et y font référence à un point à l'extérieur de la gouttière, le point le plus proche dans la gouttière est utilisé.
$scrollbar->get
Renvoie les réglages du scrollbar sous la forme d'une liste dont les éléments sont les arguments de la méthode set la plus récente.
$scrollbar->identify(x, y)
Renvoie le nom de l'élément sous le point donné par x et y (tel que arrow1), ou une chaîne vide si le point ne se situe dans aucun élément du scrollbar. X et y doivent être des coordonnées en pixels relatives au widget scrollbar.

ELEMENTS

A scrollbar widget is composed of three elements: arrow1, the slider (also called slider or (none)), and arrow2. These elements correspond to the parts of the scrollbar that may be referred to using the -elementborderwidth and -relief options.

arrow1
The up-arrow for a vertical scrollbar, or the left-arrow for a horizontal scrollbar.
slider
The part of the scrollbar that the user can drag. Its size and position indicate the current view into the associated widget.
arrow2
The down-arrow for a vertical scrollbar, or the right-arrow for a horizontal scrollbar.

WIDGET METHODS

$scrollbar->get
Returns a list of two floating-point numbers. These numbers specify the first and last positions of the visible portion of the document in the associated widget. The positions are relative to the entire document, ranging from 0.0 (top or left edge) to 1.0 (bottom or right edge). For example, if the scrollbar is configured with the -command option, this method will typically return values like [0.2 0.4]. If the scrollbar is not associated with any widget, or if the widget hasn't been mapped yet, it returns an empty list. The values represent the range of the document that is visible in the associated widget. For instance, if first is 0.2 and last is 0.4, it means that the first part of the document visible in the window is 20% of the way through the document, and the last visible part is 40% of the way through.

COMMANDES DE DÉFILEMENT

Lorsque l'utilisateur interagit avec la barre de défilement, par exemple en faisant glisser le curseur, la barre de défilement notifie le widget associé qu'il doit changer sa vue. La barre de défilement effectue la notification en évaluant un rappel spécifié comme option -command de la barre de défilement. Le rappel peut prendre plusieurs formes. Dans chaque cas, les arguments initiaux transmis sont ceux spécifiés dans le rappel -command lui-même, qui a généralement une forme comme [yview => $widget]. (Ce qui appellera $widget->yview(...) où la partie ... est comme ci-dessous. Voir Tk::callbacks pour les détails.) Le rappel reçoit des arguments supplémentaires comme suit :

moveto,fraction
Fraction est un nombre réel compris entre 0 et 1. Le widget doit ajuster sa vue de sorte que le point donné par fraction apparaisse au début du widget. Si fraction est 0, il fait référence au début du document. 1.0 fait référence à la fin du document, 0.333 fait référence à un point un tiers du chemin à travers le document, et ainsi de suite.
scroll,nombre,unités
Le widget doit ajuster sa vue de nombre unités. Les unités sont définies de la manière qui a du sens pour le widget, comme des caractères ou des lignes dans un widget texte. Nombre est soit 1, ce qui signifie qu'une unité doit défiler hors du haut ou de la gauche de la fenêtre, soit -1, ce qui signifie qu'une unité doit défiler hors du bas ou de la droite de la fenêtre.
scroll,nombre,page
Le widget doit ajuster sa vue de nombre pages. Il appartient au widget de définir la signification d'une page ; généralement, c'est un peu moins que ce qui rentre dans la fenêtre, de sorte qu'il y ait un léger chevauchement entre l'ancienne et la nouvelle vue. Nombre est soit 1, ce qui signifie que la page suivante doit devenir visible, soit -1, ce qui signifie que la page précédente doit devenir visible.

ANCIENNE SYNTAXE DE COMMANDE

Dans les versions de Tk antérieures à 4.0, les commandes de widget set et get utilisaient une forme différente. Cette forme est toujours prise en charge pour la compatibilité descendante, mais elle est obsolète. Dans l'ancienne syntaxe de commande, la méthode set a la forme suivante :

$scrollbar->set(totalUnits, windowUnits, firstUnit, lastUnit)
Dans cette forme, les arguments sont tous des entiers. TotalUnits indique la taille totale de l'objet affiché dans le widget associé. La signification d'une unité dépend du widget associé ; par exemple, dans un éditeur de texte, les unités peuvent correspondre à des lignes de texte. WindowUnits indique le nombre total d'unités qui peuvent tenir dans la fenêtre associée à la fois. FirstUnit et lastUnit indiquent les indices de la première et de la dernière unité actuellement visibles dans la fenêtre associée (zéro correspond à la première unité de l'objet).

Sous l'ancienne syntaxe, la méthode get renvoie une liste de quatre entiers, comprenant les valeurs totalUnits, windowUnits, firstUnit et lastUnit de la dernière méthode set.

Les rappels générés par les barres de défilement ont également une forme différente lorsque l'ancienne syntaxe est utilisée. Le rappel reçoit un seul argument :

unité
Unité est un entier qui indique ce qui doit apparaître en haut ou à gauche de la fenêtre du widget associé. Il a la même signification que les arguments firstUnit et lastUnit de la méthode set.

La dernière méthode set détermine si l'ancienne syntaxe doit être utilisée ou non. Si elle reçoit deux arguments réels, la nouvelle syntaxe sera utilisée à l'avenir, et si elle reçoit quatre arguments entiers, l'ancienne syntaxe sera utilisée.

LIAISONS

Tk crée automatiquement des liaisons de classe pour les barres de défilement qui leur donnent le comportement par défaut suivant. Si le comportement est différent pour les barres de défilement verticales et horizontales, le comportement horizontal est décrit entre parenthèses.

[1]
Appuyer sur le bouton 1 sur arrow1 provoque le décalage de la vue dans le widget associé vers le haut (gauche) d'une unité, de sorte que le document semble descendre (monter) d'une unité. Si le bouton est maintenu enfoncé, l'action se répète automatiquement.
[2]
Appuyer sur le bouton 1 sur trough1 provoque le décalage de la vue dans le widget associé vers le haut (gauche) d'un écran complet, de sorte que le document semble descendre (monter) d'un écran complet. Si le bouton est maintenu enfoncé, l'action se répète automatiquement.
[3]
Appuyer sur le bouton 1 sur le curseur et le faire glisser provoque le défilement de la vue avec le curseur. Si l'option jump est vraie, alors la vue ne défile pas avec le curseur ; elle ne change que lorsque le bouton de la souris est relâché.
[4]
Appuyer sur le bouton 1 sur trough2 provoque le décalage de la vue dans le widget associé vers le bas (droite) d'un écran complet, de sorte que le document semble monter (descendre) d'un écran complet. Si le bouton est maintenu enfoncé, l'action se répète automatiquement.
[5]
Appuyer sur le bouton 1 sur arrow2 provoque le décalage de la vue dans le widget associé vers le bas (droite) d'une unité, de sorte que le document semble monter (descendre) d'une unité. Si le bouton est maintenu enfoncé, l'action se répète automatiquement.
[6]
Si le bouton 2 est pressé sur la gouttière ou sur le curseur, il positionne la vue en fonction de la position de la souris ; faire glisser la souris avec le bouton 2 enfoncé fait défiler la vue avec la souris. Si le bouton 2 est pressé sur l'une des flèches, cela provoque le même comportement que l'appui sur le bouton 1.
[7]
Si le bouton 1 est pressé avec la touche Contrôle enfoncée, alors si la souris est sur arrow1 ou trough1, la vue change pour aller tout en haut (à gauche) du document ; si la souris est sur arrow2 ou trough2, la vue change pour aller tout en bas (à droite) du document ; si la souris est ailleurs, l'appui sur le bouton n'a aucun effet.
[8]
Dans les barres de défilement verticales, les touches Haut et Bas ont le même comportement que les clics de souris sur arrow1 et arrow2, respectivement. Dans les barres de défilement horizontales, ces touches n'ont aucun effet.
[9]
Dans les barres de défilement verticales, Contrôle-Haut et Contrôle-Bas ont le même comportement que les clics de souris sur trough1 et trough2, respectivement. Dans les barres de défilement horizontales, ces touches n'ont aucun effet.
[10]
Dans les barres de défilement horizontales, les touches Haut et Bas ont le même comportement que les clics de souris sur arrow1 et arrow2, respectivement. Dans les barres de défilement verticales, ces touches n'ont aucun effet.
[11]
Dans les barres de défilement horizontales, Contrôle-Haut et Contrôle-Bas ont le même comportement que les clics de souris sur trough1 et trough2, respectivement. Dans les barres de défilement verticales, ces touches n'ont aucun effet.
[12]
Les touches Page Précédente et Page Suivante ont le même comportement que les clics de souris sur trough1 et trough2, respectivement.
[13]
La touche Début ajuste la vue en haut (bord gauche) du document.
[14]
La touche Fin ajuste la vue en bas (bord droit) du document.
