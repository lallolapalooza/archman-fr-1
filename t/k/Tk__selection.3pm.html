NAME

Tk::selection - Manipuler la sélection X

SYNOPSIS

$widget->SelectionOption?(args)?

DESCRIPTION

Cet utilitaire fournit une interface au mécanisme de sélection X et implémente la fonctionnalité complète de sélection décrite dans le Manuel des conventions de communication entre clients d'interface (ICC CM).

L'objet widget utilisé pour invoquer ces méthodes détermine quel écran est utilisé pour accéder à la sélection. Pour éviter des conflits avec les méthodes de sélection des classes de widgets (par exemple, Text), cet ensemble de méthodes utilise le préfixe Selection. Les méthodes suivantes sont actuellement prises en charge :

$widget->SelectionClear?(-selection=>selection)?
Si la selection existe sur un écran quelconque de $widget, elle est effacée de sorte qu'aucune fenêtre ne détient la sélection. Selection spécifie le nom de l'atome à effacer, et doit être un nom d'atome tel que PRIMARY ou CLIPBOARD ; consultez le Manuel des conventions de communication entre clients pour plus de détails. Selection par défaut sur PRIMARY. Renvoie une valeur vide.
$widget->SelectionGet?(?-selection=>selection?,?-type=>type?)?
Récupère la valeur de selection de n'importe quel écran de $widget et renvoie le résultat. Selection par défaut sur PRIMARY.

Type spécifie la façon dont la sélection est renvoyée (la "cible" souhaitée en termes de ICC CM), et doit être un nom d'atome tel que STRING ou FILE_NAME ; consultez le Manuel des conventions de communication entre clients pour plus de détails. Type par défaut sur STRING. La fenêtre qui détient la sélection peut choisir de renvoyer la sélection dans n'importe lequel des formats de représentation, tels que STRING, ATOM, INTEGER, etc. (ce format est différent du type de sélection ; consultez l'ICC CM pour des détails confus).

Si le format n'est pas STRING, les choses deviennent compliquées, la description suivante est tirée de la page man Tcl/Tk, pas encore traduite pour la version Perl - elle est confusément mal informée.

Si la sélection est renvoyée dans un format autre qu'une chaîne de caractères, comme INTEGER ou ATOM, SelectionGet la convertit en une liste de valeurs Perl : les atomes sont convertis en leurs noms textuels, et toute autre valeur est convertie en entier.

L'objectif du port Perl est de fournir une meilleure gestion des différents formats que Tcl/Tk, ce qui devrait être possible étant donné la large gamme de "types" Perl. Bien que quelques réflexions aient été consacrées à cela aux débuts de Perl/Tk, ce qui se passe exactement n'est pas encore complètement clair et est sujet à changement.

$widget->SelectionHandle(?-selection=>selection?,?-type=>type?,?-format=>format? callback)
Crée un gestionnaire pour les requêtes de sélection, de sorte que callback soit exécuté lorsque la sélection est détenue par $widget et que quelqu'un essaie de la récupérer dans le format donné par type (par exemple, type est spécifié dans la commande selection get). Selection par défaut sur PRIMARY, type par défaut sur STRING, et format par défaut sur STRING. Si callback est une chaîne vide, tout gestionnaire existant pour $widget, type et selection est supprimé.

Lorsqu'une sélection est demandée, $widget étant le propriétaire de la sélection, et type étant le type souhaité, callback sera exécuté avec deux arguments supplémentaires. Les deux arguments supplémentaires sont offset et maxBytes : offset spécifie la position de départ dans la sélection et maxBytes donne le nombre maximum d'octets à récupérer. La commande doit renvoyer une valeur contenant au moins maxBytes de la sélection, à partir de la position offset. Pour les sélections très volumineuses (plus grandes que maxBytes), la sélection sera récupérée par plusieurs appels à callback avec des valeurs de offset croissantes. Si callback renvoie une chaîne dont la longueur est inférieure à maxBytes, il est supposé qu'elle contient le reste de la sélection ; si la longueur du résultat de callback est égale à maxBytes, callback est appelé à nouveau jusqu'à ce qu'il renvoie un résultat plus court que maxBytes. La valeur de maxBytes sera toujours relativement grande (plusieurs milliers d'octets).

Si callback renvoie une erreur (par exemple, via die), alors la récupération de la sélection est refusée, comme si la sélection n'existait pas en premier lieu.

L'argument format spécifie le format qui sera utilisé pour transmettre la sélection au demandeur (deuxième colonne du tableau 2 de l'ICC CM), et par défaut sur STRING. Si format est STRING, la sélection est transmise sous forme de caractères ASCII 8 bits (c'est-à-dire dans le format renvoyé par command).

Si format n'est pas STRING, les choses deviennent compliquées, la description suivante est tirée de la page man Tcl/Tk, pas encore traduite pour la version Perl - elle est confusément mal informée.

Si format est ATOM, la valeur renvoyée par command est divisée en champs séparés par des espaces ; chaque champ est converti en sa valeur d'atome, et la valeur d'atome est transmise à la place du nom de l'atome. Pour tout autre format, la valeur renvoyée par command est divisée en champs séparés par des espaces et chaque champ est converti en un entier de 32 bits ; un tableau d'entiers est transmis au demandeur de sélection.

L'argument format n'est nécessaire que pour la compatibilité avec de nombreux demandeurs de sélection, à l'exception de Tcl/Tk. Si Tcl/Tk est utilisé pour récupérer la sélection, la valeur est reconvertie en une chaîne côté demandeur, donc format est sans importance.

L'objectif du port Perl est de fournir une meilleure gestion des différents formats que Tcl/Tk, ce qui devrait être possible étant donné la large gamme de "types" Perl. Bien que quelques réflexions aient été consacrées à cela aux débuts de Perl/Tk, ce qui se passe exactement n'est pas encore complètement clair et est sujet à changement.

$widget->SelectionOwner?(-selection=>selection)?
SelectionOwner renvoie la fenêtre de cette application qui détient la sélection sur l'écran où se trouve $widget, ou une chaîne vide si aucune fenêtre de cette application ne détient la sélection. Selection par défaut sur PRIMARY.
$widget->SelectionOwn?(?-command=>callback?,?-selection=>selection?)?
SelectionOwn fait de $widget le nouveau propriétaire de la sélection sur l'écran de $widget, renvoyant une chaîne vide en résultat. La fenêtre existante, le cas échéant, est informée qu'elle a perdu la sélection. Si callback est spécifié, il sera exécuté lorsqu'une autre fenêtre revendiquera la propriété de la sélection de $widget en dehors de celle-ci. Selection par défaut sur PRIMARY.
