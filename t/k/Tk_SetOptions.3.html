ARGUMENTS

Tcl_Interp *interp (entrée)
Un interpréteur Tcl. La plupart des procédures utilisent ceci uniquement pour retourner des messages d'erreur ; s'il est NULL, aucun message d'erreur n'est retourné. Pour Tk_CreateOptionTable, la valeur ne peut pas être NULL ; elle donne l'interpréteur dans lequel la table d'options sera utilisée.
const Tk_OptionSpec *templatePtr (entrée)
Pointe vers un tableau d'informations statiques qui décrit les options de configuration qui sont prises en charge. Utilisé pour construire une Tk_OptionTable. Les informations pointées par cet argument doivent exister pendant la durée de vie de la Tk_OptionTable.
Tk_OptionTable optionTable (entrée)
Jeton pour une table d'options. Doit avoir été retourné par un appel précédent à Tk_CreateOptionTable.
char *recordPtr (entrée/sortie)
Pointe vers une structure dans laquelle les valeurs des options de configuration sont stockées ; les champs de cet enregistrement sont modifiés par des procédures telles que Tk_SetOptions et lus par des procédures telles que Tk_GetOptionValue.
Tk_Window tkwin (entrée)
Pour les options telles que TK_OPTION_COLOR, cet argument indique la fenêtre dans laquelle l'option sera utilisée. Si optionTable n'utilise aucune option dépendante de la fenêtre, alors une valeur NULL peut être fournie pour cet argument.
int objc (entrée)
Nombre de valeurs dans objv.
Tcl_Obj *const *objv (entrée)
Arguments de ligne de commande pour définir les options de configuration.
Tk_SavedOptions *savePtr (sortie)
S'il n'est pas NULL, la structure pointée par cet argument est remplie avec les anciennes valeurs de toutes les options qui ont été modifiées et les anciennes valeurs sont restaurées automatiquement en cas d'erreur dans Tk_SetOptions.
int *maskPtr (sortie)
S'il n'est pas NULL, le mot pointé par maskPtr est rempli avec le OU bit à bit des champs typeMask pour les options qui ont été modifiées.
Tk_SavedOptions *savedPtr (entrée/sortie)
Pointe vers une structure précédemment remplie par Tk_SetOptions avec les anciennes valeurs des options modifiées.
Tcl_Obj *namePtr (entrée)
La valeur de cet objet est le nom d'une option particulière. Si NULL est passé à Tk_GetOptionInfo, des informations sont retournées pour toutes les options. Ne doit pas être NULL lors de l'appel à Tk_GetOptionValue.
type name type (entrée)
Le nom du type d'un enregistrement.
field name field (entrée)
Le nom d'un champ dans les enregistrements de type type.

DESCRIPTION

Ces procédures gèrent la plupart des détails du traitement des options de configuration telles que celles des widgets Tk. Étant donné une description des options prises en charge, ces procédures gèrent tous les détails de l'analyse des options et du stockage de leurs valeurs dans une structure C associée au widget ou à l'objet. Les procédures ont été conçues principalement pour les widgets dans Tk, mais elles peuvent également être utilisées pour d'autres types d'objets qui ont des options de configuration. Dans le reste de cette page de manuel, "widget" sera utilisé pour désigner l'objet dont les options sont gérées ; en pratique, l'objet peut ne pas être réellement un widget. Le terme "enregistrement de widget" est utilisé pour désigner la structure au niveau C dans laquelle les informations sur un widget ou un objet particulier sont stockées.

Notez que la manière la plus simple d'apprendre à utiliser ces procédures est de regarder un exemple fonctionnel. Dans Tk, l'exemple le plus simple est le code qui implémente la famille de widgets bouton, qui se trouve dans tkButton.c. D'autres exemples se trouvent dans tkSquare.c et tkMenu.c.

Pour utiliser ces procédures, le code qui implémente le widget doit contenir un tableau statique de structures Tk_OptionSpec. Il s'agit d'un modèle qui décrit les différentes options prises en charge par cette classe de widget ; il existe un modèle séparé pour chaque type de widget. Le modèle contient des informations telles que le nom de chaque option, son type, sa valeur par défaut et l'emplacement de stockage de la valeur de l'option dans l'enregistrement du widget. Voir MODÈLES ci-dessous pour plus de détails.

Afin de traiter les options de configuration efficacement, le modèle statique doit être complété par des informations supplémentaires disponibles uniquement au moment de l'exécution. La procédure Tk_CreateOptionTable crée ces informations dynamiques à partir du modèle et retourne un jeton Tk_OptionTable qui décrit les informations statiques et dynamiques. Toutes les autres procédures, telles que Tk_SetOptions, prennent un jeton Tk_OptionTable comme argument. Généralement, Tk_CreateOptionTable est appelé la première fois qu'un widget d'une classe particulière est créé et la Tk_OptionTable résultante est utilisée par la suite pour tous les widgets de cette classe. Une Tk_OptionTable ne peut être utilisée que dans un seul interpréteur, donné par l'argument interp à Tk_CreateOptionTable. Lorsqu'une table d'options n'est plus nécessaire, Tk_DeleteOptionTable doit être appelée pour libérer toutes ses ressources. Toutes les tables d'options d'un interpréteur Tcl sont libérées automatiquement si l'interpréteur est supprimé.

Tk_InitOptions est appelée lorsqu'un nouveau widget est créé pour définir les valeurs par défaut. Tk_InitOptions reçoit un jeton pour une table d'options (optionTable) et un pointeur vers un enregistrement de widget (recordPtr), qui est la structure C contenant les informations sur ce widget. Tk_InitOptions utilise les informations de la table d'options pour choisir une valeur par défaut appropriée pour chaque option, puis stocke la valeur par défaut directement dans l'enregistrement du widget, écrasant toute information déjà présente dans l'enregistrement du widget. Tk_InitOptions retourne normalement TCL_OK. Si une erreur s'est produite lors de la définition des valeurs par défaut (par exemple, parce qu'une valeur par défaut était erronée), TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de interp si interp n'est pas NULL. Pour toute option de configuration d'un widget dont le champ flags contient TK_OPTION_DONT_SET_DEFAULT, l'initialisation ci-dessus est complètement ignorée, voir ci-dessous.

Tk_SetOptions est appelée pour modifier les options de configuration en fonction des informations spécifiées dans une commande Tcl. La commande peut être celle qui crée un nouveau widget, ou une commande qui modifie les options d'un widget existant. Les arguments objc et objv décrivent les valeurs des arguments de la commande Tcl. Objv doit contenir un nombre pair d'objets : le premier objet de chaque paire donne le nom d'une option et le second objet donne la nouvelle valeur pour cette option. Tk_SetOptions recherche chaque nom dans optionTable, vérifie que la nouvelle valeur de l'option est conforme au type dans optionTable, et stocke la valeur de l'option dans l'enregistrement du widget donné par recordPtr. Tk_SetOptions retourne normalement TCL_OK. Si une erreur s'est produite (telle qu'un nom d'option inconnu ou une valeur d'option illégale), alors TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de interp si interp n'est pas NULL.

Tk_SetOptions a deux fonctionnalités supplémentaires. Premièrement, si l'argument maskPtr n'est pas NULL, il pointe vers une valeur entière qui est remplie avec des informations sur les options qui ont été modifiées. Pour chaque option dans le modèle passé à Tk_CreateOptionTable, il existe un champ typeMask. Les bits de ce champ sont définis par le code qui implémente le widget ; par exemple, chaque bit peut correspondre à une option de configuration particulière. Alternativement, les bits peuvent être utilisés fonctionnellement. Par exemple, un bit peut être utilisé pour le redessinage : toutes les options qui affectent l'affichage du widget, de sorte que la modification de l'option nécessite que le widget soit redessiné, peuvent avoir ce bit défini. Un autre bit peut indiquer que la géométrie du widget doit être recalculée, etc. Tk_SetOptions effectue un OU bit à bit des champs typeMask de toutes les options modifiées.

l le options qui ont été modifiées et renvoie cette valeur dans *maskPtr ; l'appelant peut alors utiliser ces informations pour s'optimiser, par exemple, pour ne pas réafficher le widget si les options modifiées n'affectent pas son apparence.

La deuxième caractéristique supplémentaire de Tk_SetOptions concerne la récupération des erreurs. Si une erreur se produit lors du traitement des options de configuration, cette fonctionnalité permet de restaurer toutes les options de configuration à leurs valeurs précédentes. Des erreurs peuvent survenir soit lors du traitement des options dans Tk_SetOptions, soit ultérieurement chez l'appelant. Dans de nombreux cas, l'appelant effectue un traitement supplémentaire après le retour de Tk_SetOptions ; par exemple, il peut utiliser la valeur d'une option pour définir un traceur sur une variable et peut détecter une erreur si la variable est un tableau au lieu d'un scalaire. La récupération des erreurs est activée en passant une valeur non NULL pour l'argument savePtr à Tk_SetOptions ; il doit s'agir d'un pointeur vers une structure Tk_SavedOptions non initialisée sur la pile de l'appelant. Tk_SetOptions écrase la structure pointée par savePtr avec des informations sur les anciennes valeurs de toutes les options modifiées par la procédure. Si Tk_SetOptions renvoie avec succès, l'appelant utilise la structure de l'une des deux manières suivantes. Si l'appelant termine son traitement des nouvelles options sans erreur, il doit passer la structure à Tk_FreeSavedOptions afin que les anciennes valeurs puissent être libérées. Si l'appelant détecte une erreur dans son traitement des nouvelles options, il doit passer la structure à Tk_RestoreSavedOptions, qui copiera les anciennes valeurs dans le enregistrement du widget et libérera les nouvelles valeurs. Si Tk_SetOptions détecte une erreur, il restaure automatiquement toutes les options qui avaient déjà été modifiées et laisse *savePtr dans un état vide : l'appelant n'a pas besoin d'appeler Tk_FreeSavedOptions ni Tk_RestoreSavedOptions. Si l'argument savePtr de Tk_SetOptions est NULL, alors Tk_SetOptions libère chaque ancienne valeur d'option immédiatement lorsqu'il définit une nouvelle valeur pour l'option. Dans ce cas, si une erreur se produit dans la troisième option, les anciennes valeurs pour les deux premières options ne peuvent pas être restaurées.

Tk_GetOptionValue renvoie la valeur actuelle d'une option de configuration pour un widget particulier. L'argument namePtr contient le nom d'une option ; Tk_GetOptionValue utilise optionTable pour rechercher l'option et extraire sa valeur de l'enregistrement du widget pointé par recordPtr, puis il renvoie un objet contenant cette valeur. Si une erreur se produit (par exemple, parce que namePtr contient un nom d'option inconnu), NULL est renvoyé et un message d'erreur est laissé dans le résultat de interp, sauf si interp est NULL.

Tk_GetOptionInfo renvoie des informations sur les options de configuration sous une forme adaptée aux commandes de widget configure. Si l'argument namePtr n'est pas NULL, il pointe vers un objet qui donne le nom d'une option de configuration ; Tk_GetOptionInfo renvoie un objet contenant une liste de cinq éléments, qui sont le nom de l'option, le nom et la classe utilisés pour l'option dans la base de données d'options, la valeur par défaut de l'option et la valeur actuelle de l'option. Si l'argument namePtr est NULL, alors Tk_GetOptionInfo renvoie des informations sur toutes les options sous la forme d'une liste de listes ; chaque sous-liste décrit une option. Les options synonymes sont traitées différemment selon que namePtr est NULL : si namePtr est NULL, alors la sous-liste pour chaque option synonyme a seulement deux éléments, qui sont le nom de l'option et le nom de l'autre option à laquelle elle fait référence ; si namePtr n'est pas NULL et nomme une option synonyme, alors l'objet renvoyé est la liste de cinq éléments pour l'autre option à laquelle le synonyme fait référence. Si une erreur se produit (par exemple, parce que namePtr contient un nom d'option inconnu), NULL est renvoyé et un message d'erreur est laissé dans le résultat de interp, sauf si interp est NULL.

Tk_FreeConfigOptions doit être appelé lors de la suppression d'un widget. Il libère toutes les ressources associées à toutes les options de configuration définies dans recordPtr par optionTable.

La macro Tk_Offset est fournie comme moyen sûr de générer les valeurs objOffset et internalOffset pour les entrées des structures Tk_OptionSpec. Elle prend deux arguments : le nom d'un type d'enregistrement et le nom d'un champ dans cet enregistrement. Elle renvoie le décalage en octets du champ nommé dans les enregistrements du type donné.

MODÈLES

Le tableau de structures Tk_OptionSpec passé à Tk_CreateOptionTable via son argument templatePtr décrit les options de configuration prises en charge par une classe particulière de widgets. Chaque structure spécifie une option de configuration et possède les champs suivants :

typedef struct {
    Tk_OptionType type;
    const char *optionName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int objOffset;
    int internalOffset;
    int flags;
    const void *clientData;
    int typeMask;
} Tk_OptionSpec;
Le champ type indique le type d'option de configuration (par exemple, TK_OPTION_COLOR pour une valeur de couleur, ou TK_OPTION_INT pour une valeur entière). Le type détermine comment la valeur de l'option est analysée (plus d'informations ci-dessous). Le champ optionName est une chaîne de caractères telle que -font ou -bg ; c'est le nom utilisé pour l'option dans les commandes Tcl et passé aux procédures via les arguments objc ou namePtr. Les champs dbName et dbClass sont utilisés par Tk_InitOptions pour rechercher une valeur par défaut pour cette option dans la base de données d'options ; si dbName est NULL, alors la base de données d'options n'est pas utilisée par Tk_InitOptions pour cette option. Le champ defValue spécifie une valeur par défaut pour cette option de configuration si aucune valeur n'est spécifiée dans la base de données d'options. Les champs objOffset et internalOffset indiquent où stocker la valeur de cette option dans les enregistrements de widgets (plus d'informations ci-dessous) ; les valeurs pour les champs objOffset et internalOffset doivent toujours être générées avec la macro Tk_Offset. Le champ flags contient des informations supplémentaires pour contrôler le traitement de cette option de configuration (voir ci-dessous pour les détails). ClientData fournit des données supplémentaires spécifiques au type nécessaires pour certains types. Par exemple, pour les types TK_OPTION_COLOR, clientData est une chaîne de caractères indiquant la valeur par défaut à utiliser sur les écrans monochromes. Voir les descriptions des différents types ci-dessous pour plus de détails. Le dernier champ, typeMask, est utilisé par Tk_SetOptions pour renvoyer des informations sur les options qui ont été modifiées ; voir la description de Tk_SetOptions ci-dessus pour plus de détails.

Lorsque Tk_InitOptions et Tk_SetOptions stockent la valeur d'une option dans l'enregistrement du widget, ils peuvent le faire de deux manières. Si le champ objOffset de Tk_OptionSpec est supérieur ou égal à zéro, alors la valeur de l'option est stockée sous forme de (Tcl_Obj *) à l'emplacement dans l'enregistrement du widget donné par objOffset. Si le champ internalOffset de Tk_OptionSpec est supérieur ou égal à zéro, alors la valeur de l'option est stockée sous une forme interne spécifique au type à l'emplacement dans l'enregistrement du widget donné par internalOffset. Par exemple, si le type de l'option est TK_OPTION_INT, alors la forme interne est un entier. Si le champ objOffset ou internalOffset est négatif, alors la valeur n'est pas stockée sous cette forme. Au moins un des décalages doit être supérieur ou égal à zéro.

Le champ flags est composé d'un ou plusieurs bits ORés ensemble. Les drapeaux suivants sont pris en charge :

TK_OPTION_NULL_OK
Si ce bit est défini pour une option, alors une chaîne vide sera acceptée comme valeur pour l'option et la forme interne résultante sera un pointeur NULL, une valeur zéro ou None, selon le type de l'option. Si le drapeau n'est pas défini, les chaînes vides entraîneront des erreurs. TK_OPTION_NULL_OK est généralement utilisé pour permettre de désactiver complètement une fonctionnalité, par exemple, définir une valeur de curseur sur None afin qu'une fenêtre hérite simplement du curseur de son parent. Tous les types d'options ne prennent pas en charge le drapeau TK_OPTION_NULL_OK ; pour ceux qui le font, il y a une indication explicite dans les descriptions ci-dessous.
TK_OPTION_DONT_SET_DEFAULT
Si ce bit est défini pour une option, aucune valeur par défaut ne sera définie dans Tk_InitOptions pour cette option. Ni la base de données d'options, ni aucune valeur par défaut système, ni optionTable ne sont utilisés pour donner une valeur par défaut à cette option. Il est plutôt supposé que l'appelant a déjà fourni une valeur par défaut dans le code du widget.

Le champ type de chaque structure Tk_OptionSpec détermine comment analyser la valeur de cette option de configuration. La valeur légale pour type, et les actions correspondantes, sont décrites ci-dessous. Si le type nécessite qu'une valeur tkwin soit passée aux procédures telles que Tk_SetOptions, ou s'il utilise le champ clientData de Tk_OptionSpec, alors il est indiqué explicitement ; s'il n'est pas mentionné, le type ne nécessite ni tkwin ni clientData.

TK_OPTION_ANCHOR
La valeur doit être une position d'ancrage standard telle que ne ou center. La forme interne est une valeur Tk_Anchor telle que celles renvoyées par Tk_GetAnchorFromObj.
TK_OPTION_BITMAP
La valeur doit être un nom de bitmap Tk standard. La forme interne est un jeton Pixmap tel que ceux renvoyés par Tk_AllocBitmapFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_BOOLEAN
La valeur doit être une valeur booléenne standard telle que true ou no. La forme interne est un entier avec la valeur 0 ou 1. Notez que si le champ objOffset n'est pas utilisé, les informations sur la valeur d'origine de cette option seront perdues.

OPTION TYPES

TK_OPTION_BOOLEAN
The value must be a standard boolean value such as true or false. The internal form is a C int value (0 or 1).
TK_OPTION_CAP_STYLE
The value must be a standard cap style such as butt. The internal form is an integer cap style value such as CAP_BUTT.
TK_OPTION_COLOR
The value must be a standard color name such as red or #ff8080. The internal form is an (XColor *) token like the ones returned by Tk_AllocColorFromObj. This option type requires tkwin to be supplied to procedures such as Tk_SetOptions, and it supports the TK_OPTION_NULL_OK flag.
TK_OPTION_CURSOR
The value must be a standard cursor name such as cross or @foo. The internal form is a Tk_Cursor token like the ones returned by Tk_AllocCursorFromObj. This option type requires tkwin to be supplied to procedures such as Tk_SetOptions, and when the option is set the cursor for the window is changed by calling XDefineCursor. This option type also supports the TK_OPTION_NULL_OK flag.
TK_OPTION_CUSTOM
This option allows applications to define new option types. The clientData field of the entry points to a structure defining the new option type. See the section CUSTOM OPTION TYPES below for details.
TK_OPTION_DOUBLE
The string value must be a floating-point number in the format accepted by strtol. The internal form is a C double value. This option type supports the TK_OPTION_NULL_OK flag; if a NULL value is set, the internal representation is set to zero.
TK_OPTION_END
Marks the end of the template. There must be a Tk_OptionSpec structure with type TK_OPTION_END at the end of each template. If the clientData field of this structure is not NULL, then it points to an additional array of Tk_OptionSpec's, which is itself terminated by another TK_OPTION_END entry. Templates may be chained arbitrarily deeply. This feature allows common options to be shared by several widget classes.
TK_OPTION_FONT
The value must be a standard font name such as Times 16. The internal form is a Tk_Font handle like the ones returned by Tk_AllocFontFromObj. This option type requires tkwin to be supplied to procedures such as Tk_SetOptions, and it supports the TK_OPTION_NULL_OK flag.
TK_OPTION_INT
The string value must be an integer in the format accepted by strtol (e.g. 0 and 0x prefixes may be used to specify octal or hexadecimal numbers, respectively). The internal form is a C int value.
TK_OPTION_JUSTIFY
The value must be a standard justification value such as left. The internal form is a Tk_Justify like the values returned by Tk_GetJustifyFromObj.
TK_OPTION_PIXELS
The value must specify a screen distance such as 2i or 6.4. The internal form is an integer value giving a distance in pixels, like the values returned by Tk_GetPixelsFromObj. Note that if the objOffset field is not used, information about the original value of this option will be lost. See OBJOFFSET VS. INTERNALOFFSET below for details. This option type supports the TK_OPTION_NULL_OK flag; if a NULL value is set, the internal representation is set to INT_MIN.
TK_OPTION_RELIEF
The value must be standard relief such as raised. The internal form is an integer relief value such as TK_RELIEF_RAISED. This option type supports the TK_OPTION_NULL_OK flag; if a NULL value is set, the internal representation is set to TK_RELIEF_NULL.
TK_OPTION_STRING
The value may be any string. The internal form is a (char *) pointer that points to a dynamically allocated copy of the value. This option type supports the TK_OPTION_NULL_OK flag.
TK_OPTION_STRING_TABLE
For this type, clientData is a pointer to an array of strings suitable for passing to Tcl_GetIndexFromObj. The value must be one of the strings in the table, or a unique abbreviation of one of the strings. The internal form is an integer giving the index into the table of the matching string, like the return value from Tcl_GetStringFromObj. This option type supports the TK_OPTION_NULL_OK flag; if a NULL value is set, the internal representation is set to -1.
TK_OPTION_SYNONYM
This type is used to provide alternative names for an option (for example, -bg is often used as a synonym for -background). The clientData field is a string that gives the name of another option in the same table. Whenever the synonym option is used, the information from the other option will be used instead.
TK_OPTION_WINDOW
The value must be a window path name. The internal form is a Tk_Window token for the window. This option type requires tkwin to be supplied to procedures such as Tk_SetOptions (in order to identify the application), and it supports the TK_OPTION_NULL_OK flag.

GESTION DES PROBLÈMES DE STOCKAGE

Si un champ d'un enregistrement de widget a son décalage stocké dans le champ objOffset ou internalOffset d'une structure Tk_OptionSpec, les procédures décrites ici géreront toutes les questions d'allocation de stockage et de gestion des ressources associées au champ. Lorsque la valeur d'une option est modifiée, Tk_SetOptions (ou Tk_FreeSavedOptions) libérera automatiquement toutes les ressources associées à l'ancienne valeur, telles que les Tk_Fonts pour les options TK_OPTION_FONT ou la mémoire dynamiquement allouée pour les options TK_OPTION_STRING. Pour une option stockée sous forme d'objet à l'aide du champ objOffset d'une Tk_OptionSpec, l'enregistrement du widget partage l'objet pointé par la valeur objv de l'appel à Tk_SetOptions. Le compteur de références de cet objet est incrémenté lorsqu'un pointeur vers celui-ci est stocké dans l'enregistrement du widget et décrémenté lorsque l'option est modifiée. Lorsque le widget est supprimé, Tk_FreeConfigOptions doit être invoqué ; il libérera les ressources associées à toutes les options et décrémentera les compteurs de références pour tous les objets.

Cependant, le code du widget est responsable du stockage de NULL ou None dans tous les champs pointeurs et jetons avant d'invoquer Tk_InitOptions. Ceci est nécessaire pour permettre un nettoyage correct dans le cas rare où une erreur se produit dans Tk_InitOptions.

OBJOFFSET VS. INTERNALOFFSET

Dans la plupart des cas, il est plus simple d'utiliser le champ internalOffset d'une structure Tk_OptionSpec et non le champ objOffset. Cela rend la forme interne de la valeur immédiatement disponible pour le code du widget, de sorte que la valeur n'a pas à être extraite d'un objet chaque fois qu'elle est utilisée. Cependant, il y a deux cas où le champ objOffset est utile. Le premier cas concerne les options TK_OPTION_PIXELS. Dans ce cas, la forme interne est une valeur entière en pixels qui n'est valide que pour un écran particulier. Si la valeur de l'option est récupérée, elle sera retournée sous forme de simple nombre. Par exemple, après la commande .b configure -borderwidth 2m, la commande .b configure -borderwidth pourrait retourner 7, qui est la valeur entière en pixels correspondant à 2m. Malheureusement, cela fait perdre la valeur d'origine indépendante de l'écran. Ainsi, pour les options TK_OPTION_PIXELS, il est préférable d'utiliser le champ objOffset. Dans ce cas, la valeur d'origine de l'option est conservée dans l'objet et peut être retournée lors de la récupération de l'option. Dans la plupart des cas, il est pratique d'utiliser également le champ internalOffset, afin que la valeur entière soit immédiatement disponible pour une utilisation dans le code du widget (alternativement, Tk_GetPixelsFromObj peut être utilisé pour extraire la valeur entière de l'objet chaque fois que nécessaire). Notez que le problème de perte d'informations lors des récupérations n'existe que pour les options TK_OPTION_PIXELS.

La deuxième raison d'utiliser le champ objOffset est de pouvoir implémenter de nouveaux types d'options non pris en charge par ces procédures. Pour implémenter un nouveau type d'option, vous pouvez utiliser TK_OPTION_STRING comme type dans la structure Tk_OptionSpec et définir le champ objOffset mais pas le champ internalOffset. Ensuite, après avoir appelé Tk_SetOptions, convertissez vous-même l'objet en forme interne.

Les widgets Ttk ne prennent pas en charge le mécanisme internalOffset. Les valeurs d'options des widgets Ttk sont toujours stockées en tant que (Tcl_Obj *), ce qui signifie que le champ objOffset doit être utilisé.

TYPES D'OPTIONS PERSONNALISÉES

Les applications peuvent étendre les types de configuration intégrés avec des types de configuration supplémentaires en écrivant des procédures pour analyser, imprimer, libérer et restaurer des copies sauvegardées du type et en créant une structure pointant vers ces procédures :

typedef struct Tk_ObjCustomOption {
    const char *name;
    Tk_CustomOptionSetProc *setProc;
    Tk_CustomOptionGetProc *getProc;
    Tk_CustomOptionRestoreProc *restoreProc;
    Tk_CustomOptionFreeProc *freeProc;
    ClientData clientData;
} Tk_ObjCustomOption;
typedef int Tk_CustomOptionSetProc(
    ClientData clientData,
    Tcl_Interp *interp,
    Tk_Window tkwin,
    Tcl_Obj **valuePtr,
    char *recordPtr,
    int internalOffset,
    char *saveInternalPtr,
    int flags);
typedef Tcl_Obj *Tk_CustomOptionGetProc(
    ClientData clientData,
    Tk_Window tkwin,
    char *recordPtr,
    int internalOffset);
typedef void Tk_CustomOptionRestoreProc(
    ClientData clientData,
    Tk_Window tkwin,
    char *internalPtr,
    char *saveInternalPtr);
typedef void Tk_CustomOptionFreeProc(
    ClientData clientData,
    Tk_Window tkwin,
    char *internalPtr);

La structure Tk_ObjCustomOption contient six champs : un nom pour le type d'option personnalisé ; des pointeurs vers les quatre procédures ; et une valeur clientData à passer à ces procédures lorsqu'elles sont appelées. La valeur clientData typ

pointe donc vers une structure contenant les informations nécessaires aux procédures lors de l'analyse et de l'impression des options. RestoreProc et freeProc peuvent être NULL, indiquant qu'aucune fonction ne doit être appelée pour ces opérations.

La procédure setProc est appelée par Tk_SetOptions pour convertir un Tcl_Obj en une représentation interne et stocker la valeur résultante dans l'enregistrement du widget. Les arguments sont :

clientData
Une copie du champ clientData dans la structure Tk_ObjCustomOption.
interp
Un pointeur vers un interpréteur Tcl, utilisé pour le rapport d'erreurs.
Tkwin
Une copie de l'argument tkwin à Tk_SetOptions
valuePtr
Un pointeur vers une référence à un Tcl_Obj décrivant la nouvelle valeur de l'option ; elle pourrait avoir été spécifiée explicitement dans l'appel à Tk_SetOptions ou provenir de la base de données des options ou d'une valeur par défaut. Si l'objOffset pour l'option est non négatif (la valeur de l'option est stockée comme un (Tcl_Obj *) dans l'enregistrement du widget), le pointeur Tcl_Obj référencé par valuePtr est le pointeur qui sera stocké à l'objOffset pour l'option. SetProc peut modifier la valeur si nécessaire ; par exemple, setProc peut changer la valeur à NULL pour supporter le drapeau TK_OPTION_NULL_OK.
recordPtr
Un pointeur vers le début de l'enregistrement du widget à modifier.
internalOffset
Décalage en octets depuis le début de l'enregistrement du widget vers l'emplacement où la représentation interne de la valeur de l'option doit être placée.
saveInternalPtr
Un pointeur vers le stockage alloué dans une structure Tk_SavedOptions pour la représentation interne de la valeur de l'option d'origine. Avant de définir l'option à sa nouvelle valeur, setProc doit définir la valeur référencée par saveInternalPtr à la valeur d'origine de l'option afin de supporter Tk_RestoreSavedOptions.
flags
Une copie du champ flags dans la structure Tk_OptionSpec pour l'option

SetProc renvoie un résultat Tcl standard : TCL_OK pour indiquer un traitement réussi, ou TCL_ERROR pour indiquer un échec quelconque. Un message d'erreur peut être laissé dans l'interpréteur Tcl donné par interp en cas d'erreur.

La procédure getProc est appelée par Tk_GetOptionValue et Tk_GetOptionInfo pour récupérer une représentation Tcl_Obj de la représentation interne d'une option. L'argument clientData est une copie du champ clientData dans la structure Tk_ObjCustomOption. Tkwin est une copie de l'argument tkwin à Tk_GetOptionValue ou Tk_GetOptionInfo. RecordPtr est un pointeur vers le début de l'enregistrement du widget à interroger. InternalOffset est le décalage en octets depuis le début de l'enregistrement du widget vers l'emplacement où la représentation interne de la valeur de l'option est stockée. GetProc doit renvoyer un pointeur vers un Tcl_Obj représentant la valeur de l'option.

La procédure restoreProc est appelée par Tk_RestoreSavedOptions pour restaurer une représentation interne précédemment sauvegardée d'une valeur d'option personnalisée. L'argument clientData est une copie du champ clientData dans la structure Tk_ObjCustomOption. Tkwin est une copie de l'argument tkwin à Tk_GetOptionValue ou Tk_GetOptionInfo. InternalPtr est un pointeur vers l'emplacement où la représentation interne de la valeur de l'option est stockée. SaveInternalPtr est un pointeur vers la valeur sauvegardée. RestoreProc doit copier la valeur de saveInternalPtr à internalPtr pour restaurer la valeur. RestoreProc n'a pas besoin de libérer de mémoire associée à internalPtr ou saveInternalPtr ; freeProc sera appelée pour libérer cette mémoire si nécessaire. RestoreProc n'a pas de valeur de retour.

La procédure freeProc est appelée par Tk_SetOptions et Tk_FreeSavedOptions pour libérer tout stockage alloué pour la représentation interne d'une option personnalisée. L'argument clientData est une copie du champ clientData dans la structure Tk_ObjCustomOption. Tkwin est une copie de l'argument tkwin à Tk_GetOptionValue ou Tk_GetOptionInfo. InternalPtr est un pointeur vers l'emplacement où la représentation interne de la valeur de l'option est stockée. Le freeProc doit libérer tout stockage associé à l'option. FreeProc n'a pas de valeur de retour.
