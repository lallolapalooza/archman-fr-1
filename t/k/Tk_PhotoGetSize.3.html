NOM

Tk_FindPhoto, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoGetImage, Tk_PhotoBlank, Tk_PhotoExpand, Tk_PhotoGetSize, Tk_PhotoSetSize - manipuler les données d'image stockées dans une image photo.

SYNOPSIS

Tk_FindPhoto(interp, imageName)

Tk_PhotoGetImage(handle, blockPtr)

void
Tk_PhotoBlank(handle)

int
Tk_PhotoExpand(interp, handle, width, height)

Tk_PhotoGetSize(handle, widthPtr, heightPtr)

int
Tk_PhotoSetSize(interp. handle, width, height)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur dans lequel l'image a été créée et dans lequel les rapports d'erreur doivent être effectués.
const char *imageName (in)
Nom de l'image photo.
Tk_PhotoHandle handle (in)
Handle opaque identifiant l'image photo à affecter.
Tk_PhotoImageBlock *blockPtr (in)
Spécifie l'adresse et la disposition de stockage des données de l'image.
int x (in)
Spécifie la coordonnée X où le coin supérieur gauche du bloc doit être placé dans l'image.
int y (in)
Spécifie la coordonnée Y où le coin supérieur gauche du bloc doit être placé dans l'image.
int width (in)
Spécifie la largeur de la zone d'image à affecter (pour Tk_PhotoPutBlock) ou la largeur d'image souhaitée (pour Tk_PhotoExpand et Tk_PhotoSetSize).
int compRule (in)
Spécifie la règle de composition utilisée lors de la combinaison de pixels transparents dans un bloc de données avec une image photo. Doit être l'une des valeurs TK_PHOTO_COMPOSITE_OVERLAY (qui place le bloc de données par-dessus l'image photo existante, le contenu précédent apparaissant à travers les bits transparents) ou TK_PHOTO_COMPOSITE_SET (qui ignore le contenu existant de l'image photo dans le rectangle couvert par le bloc de données).
int height (in)
Spécifie la hauteur de la zone d'image à affecter (pour Tk_PhotoPutBlock) ou la hauteur d'image souhaitée (pour Tk_PhotoExpand et Tk_PhotoSetSize).
int *widthPtr (out)
Pointeur vers l'emplacement où stocker la largeur de l'image.
int *heightPtr (out)
Pointeur vers l'emplacement où stocker la hauteur de l'image.
int subsampleX (in)
Spécifie le facteur de sous-échantillonnage dans la direction X pour les données d'image d'entrée.
int subsampleY (in)
Spécifie le facteur de sous-échantillonnage dans la direction Y pour les données d'image d'entrée.
int zoomX (in)
Spécifie le facteur de zoom à appliquer dans la direction X aux pixels écrits dans l'image photo.
int zoomY (in)
Spécifie le facteur de zoom à appliquer dans la direction Y aux pixels écrits dans l'image photo.

DESCRIPTION

Tk_FindPhoto renvoie un handle opaque qui est utilisé pour identifier une image photo particulière aux autres procédures. Le paramètre est le nom de l'image, c'est-à-dire le nom spécifié à la commande image create photo, ou assigné par cette commande si aucun nom n'a été spécifié. Si imageName n'existe pas ou n'est pas une image photo, Tk_FindPhoto renvoie NULL.

Tk_PhotoPutBlock est utilisé pour fournir des blocs de données d'image à afficher. L'appel affecte une zone de l'image de taille width x height pixels, avec son coin supérieur gauche aux coordonnées (x,y). Tous les width, height, x et y doivent être non négatifs. Si une partie de cette zone se trouve en dehors des limites actuelles de l'image, l'image sera agrandie pour inclure la zone, sauf si l'utilisateur a spécifié une taille d'image explicite avec les options de configuration du widget -width et/ou -height (voir photo(n)) ; dans ce cas, la zone sera silencieusement coupée aux limites de l'image.

Le paramètre block est un pointeur vers une structure Tk_PhotoImageBlock, définie comme suit :

typedef struct {
    unsigned char *pixelPtr;
    int width;
    int height;
    int pitch;
    int pixelSize;
    int offset[4];
} Tk_PhotoImageBlock;
Le champ pixelPtr pointe vers le premier pixel, c'est-à-dire le pixel supérieur gauche du bloc. Les champs width et height spécifient les dimensions du bloc de pixels. Le champ pixelSize spécifie la différence d'adresse entre deux pixels horizontalement adjacents. Il doit être de 4 pour les données d'image RVB et de 2 pour les données d'image en niveaux de gris. D'autres valeurs sont possibles, si les décalages dans le tableau offset sont ajustés en conséquence (par exemple, pour les données rouges, vertes et bleues stockées dans différents plans). L'utilisation d'une telle disposition est fortement déconseillée, cependant. En raison d'un bug, cela pourrait ne pas fonctionner correctement si un canal alpha est fourni. (voir la section BUGS ci-dessous). Le champ pitch spécifie la différence d'adresse entre deux pixels verticalement adjacents. Le tableau offset contient les décalages de l'adresse d'un pixel vers les adresses des octets contenant les composantes rouge, verte, bleue et alpha (transparence). Si les décalages pour le rouge, le vert et le bleu sont égaux, l'image est interprétée comme étant en niveaux de gris. S'ils diffèrent, des données RVB sont supposées. Normalement, les décalages seront de 0, 1, 2, 3 pour les données RVB et de 0, 0, 0, 1 pour les niveaux de gris. Il est possible de fournir des données d'image sans canal alpha en définissant le décalage de l'alpha sur une valeur négative et en ajustant le champ pixelSize en conséquence. Cette utilisation est cependant déconseillée (voir la section BUGS ci-dessous).

La valeur du paramètre compRule pour Tk_PhotoPutBlock spécifie une règle de composition indiquant quoi faire avec les pixels transparents. La valeur TK_PHOTO_COMPOSITE_OVERLAY indique que le contenu précédent de l'image photo doit être visible, et la valeur TK_PHOTO_COMPOSITE_SET indique que le contenu précédent de l'image photo doit être complètement ignoré, et que les valeurs du bloc doivent être copiées directement. Le comportement dans Tk8.3 et versions antérieures était équivalent à avoir TK_PHOTO_COMPOSITE_OVERLAY comme règle de composition.

Les valeurs spécifiées pour les paramètres width et height de Tk_PhotoPutBlock ne correspondent pas nécessairement aux valeurs spécifiées dans block. Si elles sont plus petites, Tk_PhotoPutBlock extrait un sous-bloc des données d'image fournies. Si elles sont plus grandes, les données fournies sont répétées (de manière pavée) pour remplir la zone spécifiée. Ces règles opèrent indépendamment dans les directions horizontale et verticale.

Tk_PhotoPutBlock renvoie normalement TCL_OK, bien que s'il ne peut pas allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est renvoyé à la place et, si l'argument interp est non NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoPutZoomedBlock fonctionne comme Tk_PhotoPutBlock à l'exception que l'image peut être réduite ou agrandie pour l'affichage. Les paramètres subsampleX et subsampleY permettent de réduire la taille de l'image par sous-échantillonnage. Tk_PhotoPutZoomedBlock utilisera uniquement les pixels de l'image d'entrée dont les coordonnées X sont des multiples de subsampleX, et dont les coordonnées Y sont des multiples de subsampleY. Par exemple, une image de 512x512 pixels peut être réduite à 256x256 en définissant subsampleX et subsampleY à 2.

Les paramètres zoomX et zoomY permettent d'agrandir l'image par réplication de pixels. Chaque pixel de l'image d'entrée (éventuellement sous-échantillonnée) sera écrit dans un bloc de zoomX pixels de large et zoomY pixels de haut de l'image affichée. Le sous-échantillonnage et le zoom peuvent être utilisés ensemble pour des effets spéciaux.

Tk_PhotoGetImage peut être utilisé pour récupérer les données d'image d'une image photo. Tk_PhotoGetImage remplit la structure pointée par le paramètre blockPtr avec des valeurs décrivant l'adresse et la disposition des données d'image que l'image photo a stockées en interne. Les valeurs sont valides jusqu'à ce que l'image soit détruite ou que sa taille soit modifiée.

Il est possible de modifier une image en écrivant directement dans les données auxquelles pointe le champ pixelPtr. La taille de l'image ne peut cependant pas être modifiée de cette manière. De plus, les modifications apportées en écrivant directement dans pixelPtr ne seront pas immédiatement visibles, mais seulement après un appel à Tk_ImageChanged ou après un événement qui provoque le redessin des widgets intéressés.
