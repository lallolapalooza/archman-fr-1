ARGUMENTS

Tcl_Interp *interp (entrée)
Un interpréteur Tcl. La plupart des procédures utilisent cela uniquement pour retourner des messages d'erreur ; s'il est NULL, aucun message d'erreur n'est retourné. Pour Tk_CreateOptionTable, la valeur ne peut pas être NULL ; elle donne l'interpréteur dans lequel la table d'options sera utilisée.
const Tk_OptionSpec *templatePtr (entrée)
Pointe vers un tableau d'informations statiques décrivant les options de configuration prises en charge. Utilisé pour construire une Tk_OptionTable. Les informations pointées par cet argument doivent exister pendant la durée de vie de la Tk_OptionTable.
Tk_OptionTable optionTable (entrée)
Jeton pour une table d'options. Doit avoir été retourné par un appel précédent à Tk_CreateOptionTable.
char *recordPtr (entrée/sortie)
Pointe vers la structure dans laquelle les valeurs des options de configuration sont stockées ; les champs de cet enregistrement sont modifiés par des procédures telles que Tk_SetOptions et lus par des procédures telles que Tk_GetOptionValue.
Tk_Window tkwin (entrée)
Pour les options telles que TK_OPTION_COLOR, cet argument indique la fenêtre dans laquelle l'option sera utilisée. Si optionTable n'utilise aucune option dépendante de la fenêtre, alors une valeur NULL peut être fournie pour cet argument.
int objc (entrée)
Nombre de valeurs dans objv.
Tcl_Obj *const *objv (entrée)
Arguments de ligne de commande pour définir les options de configuration.
Tk_SavedOptions *savePtr (sortie)
S'il n'est pas NULL, la structure pointée par cet argument est remplie avec les anciennes valeurs de toutes les options qui ont été modifiées et les anciennes valeurs sont restaurées automatiquement si une erreur survient dans Tk_SetOptions.
int *maskPtr (sortie)
S'il n'est pas NULL, le mot pointé par maskPtr est rempli avec le OU bit à bit des champs typeMask des options qui ont été modifiées.
Tk_SavedOptions *savedPtr (entrée/sortie)
Pointe vers une structure précédemment remplie par Tk_SetOptions avec les anciennes valeurs des options modifiées.
Tcl_Obj *namePtr (entrée)
La valeur de cet objet est le nom d'une option particulière. Si NULL est transmis à Tk_GetOptionInfo, les informations sont retournées pour toutes les options. Ne doit pas être NULL lors de l'appel de Tk_GetOptionValue.
type name type (entrée)
Le nom du type d'un enregistrement.
field name field (entrée)
Le nom d'un champ dans les enregistrements de type type.

DESCRIPTION

Ces procédures gèrent la plupart des détails du traitement des options de configuration telles que celles des widgets Tk. Compte tenu d'une description des options prises en charge, ces procédures gèrent tous les détails de l'analyse des options et du stockage de leurs valeurs dans une structure C associée au widget ou à l'objet. Les procédures ont été conçues principalement pour les widgets dans Tk, mais elles peuvent également être utilisées pour d'autres types d'objets qui ont des options de configuration. Dans le reste de cette page de manuel, « widget » sera utilisé pour désigner l'objet dont les options sont gérées ; en pratique, l'objet peut ne pas être réellement un widget. Le terme « enregistrement de widget » est utilisé pour désigner la structure de niveau C dans laquelle sont stockées les informations relatives à un widget ou objet particulier.

Notez que le moyen le plus simple d'apprendre à utiliser ces procédures est de regarder un exemple fonctionnel. Dans Tk, l'exemple le plus simple est le code qui implémente la famille de widgets de boutons, qui se trouve dans tkButton.c. D'autres exemples se trouvent dans tkSquare.c et tkMenu.c.

Pour utiliser ces procédures, le code qui implémente le widget doit contenir un tableau statique de structures Tk_OptionSpec. Il s'agit d'un modèle qui décrit les diverses options prises en charge par cette classe de widget ; il existe un modèle distinct pour chaque type de widget. Le modèle contient des informations telles que le nom de chaque option, son type, sa valeur par défaut et où la valeur de l'option est stockée dans l'enregistrement du widget. Voir MODÈLES ci-dessous pour plus de détails.

Afin de traiter les options de configuration efficacement, le modèle statique doit être augmenté d'informations supplémentaires disponibles uniquement au moment de l'exécution. La procédure Tk_CreateOptionTable crée ces informations dynamiques à partir du modèle et retourne un jeton Tk_OptionTable qui décrit les informations statiques et dynamiques. Toutes les autres procédures, telles que Tk_SetOptions, prennent un jeton Tk_OptionTable en argument. Typiquement, Tk_CreateOptionTable est appelé la première fois qu'un widget d'une classe particulière est créé et la Tk_OptionTable résultante est utilisée à l'avenir pour tous les widgets de cette classe. Une Tk_OptionTable ne peut être utilisée que dans un seul interpréteur, donné par l'argument interp à Tk_CreateOptionTable. Lorsqu'une table d'options n'est plus nécessaire, Tk_DeleteOptionTable doit être appelée pour libérer toutes ses ressources. Toutes les tables d'options d'un interpréteur Tcl sont automatiquement libérées si l'interpréteur est supprimé.

Tk_InitOptions est invoqué lors de la création d'un nouveau widget pour définir les valeurs par défaut. Tk_InitOptions reçoit un jeton pour une table d'options (optionTable) et un pointeur vers un enregistrement de widget (recordPtr), qui est la structure C contenant les informations sur ce widget. Tk_InitOptions utilise les informations de la table d'options pour choisir une valeur par défaut appropriée pour chaque option, puis stocke la valeur par défaut directement dans l'enregistrement du widget, en remplaçant toute information déjà présente dans l'enregistrement du widget. Tk_InitOptions retourne normalement TCL_OK. Si une erreur s'est produite lors de la définition des valeurs par défaut (par exemple, parce qu'une valeur par défaut était erronée), alors TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de interp si interp n'est pas NULL. Pour toute option de configuration d'un widget ayant TK_OPTION_DONT_SET_DEFAULT défini dans son champ flags, l'initialisation ci-dessus est complètement ignorée, voir ci-dessous.

Tk_SetOptions est invoqué pour modifier les options de configuration en fonction des informations spécifiées dans une commande Tcl. La commande peut être celle qui crée un nouveau widget, ou une commande qui modifie les options d'un widget existant. Les arguments objc et objv décrivent les valeurs des arguments de la commande Tcl. Objv doit contenir un nombre pair d'objets : le premier objet de chaque paire donne le nom d'une option et le second objet donne la nouvelle valeur pour cette option. Tk_SetOptions recherche chaque nom dans optionTable, vérifie que la nouvelle valeur de l'option est conforme au type dans optionTable, et stocke la valeur de l'option dans l'enregistrement du widget donné par recordPtr. Tk_SetOptions retourne normalement TCL_OK. Si une erreur s'est produite (comme un nom d'option inconnu ou une valeur d'option illégale), alors TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de interp si interp n'est pas NULL.

Tk_SetOptions a deux fonctionnalités supplémentaires. Premièrement, si l'argument maskPtr n'est pas NULL, il pointe vers une valeur entière qui est remplie avec des informations sur les options qui ont été modifiées. Pour chaque option du modèle passé à Tk_CreateOptionTable, il y a un champ typeMask. Les bits de ce champ sont définis par le code qui implémente le widget ; par exemple, chaque bit peut correspondre à une option de configuration particulière. Alternativement, les bits peuvent être utilisés fonctionnellement. Par exemple, un bit peut être utilisé pour le redessin : toutes les options qui affectent l'affichage du widget, de sorte que la modification de l'option nécessite que le widget soit redessiné, pourraient avoir ce bit défini. Un autre bit pourrait indiquer que la géométrie du widget doit être recalculée, et ainsi de suite. Tk_SetOptions effectue un OU bit à bit des champs typeMask de toutes les options modifiées.

Deuxièmement, si l'argument savePtr n'est pas NULL, il pointe vers une structure qui est remplie avec les anciennes valeurs des options qui ont été modifiées. Si une erreur se produit lors du traitement des options, toutes les modifications sont automatiquement annulées en restaurant les anciennes valeurs à partir de savePtr. Le programme appelant peut ensuite utiliser Tk_FreeSavedOptions pour libérer la mémoire allouée par Tk_SetOptions pour stocker les anciennes valeurs. S'il n'y a pas eu d'erreur, le programme appelant peut utiliser les anciennes valeurs stockées dans savePtr, par exemple, pour les stocker à nouveau pour une utilisation ultérieure, ou pour les utiliser pour déterminer s'il faut effectuer une action coûteuse. Les anciennes valeurs peuvent être restaurées à tout moment en appelant Tk_RestoreSavedOptions.

Tk_GetOptionValue est utilisé pour extraire la valeur d'une option particulière. Il recherche l'option nommée par namePtr dans la table d'options optionTable, puis renvoie sa valeur actuelle en tant qu'objet Tcl. Si l'option n'est pas trouvée, une erreur est signalée. L'appelant est responsable de la libération de la valeur d'objet retournée.

Tk_GetOptionInfo est utilisé pour obtenir des informations sur une option, telles que son nom canonique, son type, sa valeur par défaut et sa description. Si namePtr est NULL, les informations sur toutes les options sont retournées. Les informations sont retournées sous forme d'une liste d'objets Tcl. L'appelant est responsable de la libération de la valeur d'objet retournée.

Tk_FreeConfigOptions est utilisé pour libérer la mémoire allouée par Tk pour stocker les valeurs des options de configuration dans l'enregistrement recordPtr. Ceci est généralement appelé lors de la suppression d'un widget. Il itère sur toutes les options spécifiées dans optionTable et libère toutes les valeurs allouées pour chaque option dans recordPtr.

Tk_Offset est une macro qui calcule le décalage en octets d'un champ donné dans une structure C. Il prend le nom du type de la structure et le nom du champ en tant qu'arguments et retourne le décalage. Ceci est utile lors de la définition de modèles d'options, car il fournit le décalage correct pour que Tk puisse accéder aux champs de la structure.

Voici un exemple de l'utilisation de Tk_Offset dans un modèle :

static Tk_OptionSpec optionTable[] = {
    { "-borderwidth", "borderWidth", Tk_Offset(MyWidgetRec, borderWidth),
      TK_OPTION_INT, "1" },
    ...
};

Dans cet exemple, Tk_Offset calcule le décalage du champ borderWidth dans la structure MyWidgetRec. Tk utilisera ce décalage pour lire ou écrire la valeur de l'option -borderwidth dans la structure du widget.

MODÈLES

Chaque classe de widget qui utilise ces procédures doit fournir un tableau statique de structures Tk_OptionSpec. Ce tableau, appelé « modèle d'options », décrit toutes les options de configuration que le widget prend en charge. Chaque entrée du tableau décrit une seule option et a le format suivant :

typedef struct {
    const char *optionName;       /* Name of the option in Tcl commands, e.g., "-background".*/
    const char *dbName;           /* Name for database lookups, e.g., "background". NULL means same as optionName.*/
    int offset;                   /* Offset in bytes from start of widget record to field holding option's value.*/
    int type;                     /* Type of the option's value (see below).*/
    const char *defaultPtr;       /* Default value, as a string.*/
    Tcl_ObjType *objTypePtr;      /* Optional: For custom option types, pointer to Tcl_ObjType.*/
    int flags;                    /* Optional: Flags controlling option behavior (see below).*/
    int typeMask;                 /* Optional: Bits for option mask.*/
    const char *clientData;       /* Optional: Extra info for option processing.*/
} Tk_OptionSpec;

Champs :

optionName
Le nom de l'option tel qu'il apparaîtrait dans une commande Tcl (par exemple, « -background »). Il doit commencer par un « - » et être en minuscules. L'option spéciale « - » est utilisée pour indiquer la fin du tableau.
dbName
Le nom de l'option tel qu'il serait utilisé dans une recherche dans la base de données des options Tk (par exemple, « background »). S'il est NULL, la valeur de optionName est utilisée. Ce nom ne doit pas commencer par un « - ».
offset
Le décalage en octets depuis le début de l'enregistrement du widget jusqu'au champ contenant la valeur de l'option. La macro Tk_Offset est utilisée pour calculer cette valeur.
type
Le type de la valeur de l'option. Les types possibles sont définis dans tk.h et incluent :
TK_OPTION_BOOLEAN
Valeur booléenne (0 ou 1).
TK_OPTION_COLOR
Une couleur, spécifiée en nom de couleur ou en spécification RVB.
TK_OPTION_FONT
Une police.
TK_OPTION_INT
Un entier.
TK_OPTION_DOUBLE
Un nombre à virgule flottante.
TK_OPTION_STRING
Une chaîne de caractères.
TK_OPTION_STRING_TABLE
Une chaîne parmi une table prédéfinie de chaînes autorisées.
TK_OPTION_RELIEF
Un type de relief (par exemple, tkReliefRaised, tkReliefSunken).
TK_OPTION_BITMAP
Une image bitmap.
TK_OPTION_PIXMAP
Une image pixmap.
TK_OPTION_CURSOR
Un curseur.
TK_OPTION_ACTIVE_CURSOR
Un curseur pour les zones actives.
TK_OPTION_JUSTIFY
Alignement (tkJustifyLeft, tkJustifyCenter, tkJustifyRight).
TK_OPTION_ANCHOR
Ancrage (par exemple, tkAnchorN, tkAnchorNE).
TK_OPTION_LISTBOX
Option spécifique à la liste (par exemple, tkListbox).
TK_OPTION_SPECIAL
Indique un type d'option personnalisé défini par l'application.
TK_OPTION_CUSTOM
Indique un type d'option personnalisé défini par l'application, utilisant objTypePtr.
defaultPtr
Un pointeur vers une chaîne de caractères représentant la valeur par défaut de l'option. La chaîne doit être dans un format approprié pour le type spécifié.
objTypePtr
Si le type est TK_OPTION_CUSTOM, ce pointeur doit pointer vers une structure Tcl_ObjType définissant la façon de gérer l'objet personnalisé.
flags
Un masque de bits facultatif contrôlant le comportement de l'option. Les indicateurs possibles sont :
TK_OPTION_AUTO_SET
L'option sera définie automatiquement par Tk.
TK_OPTION_TRANSLATE_REST
Traduire le reste des arguments en une chaîne.
TK_OPTION_NULL_OK
L'option peut avoir une valeur NULL.
TK_OPTION_DIRTY
Indique que l'option doit être marquée comme « sale » lorsqu'elle est modifiée.
TK_OPTION_READ_ONLY
L'option ne peut être définie que lors de la création du widget.
TK_OPTION_SPECIFIED
L'option a été explicitement spécifiée par l'utilisateur.
TK_OPTION_DONT_SET_DEFAULT
Ne pas initialiser cette option avec sa valeur par défaut lors de l'appel de Tk_InitOptions.
typeMask
Un masque de bits facultatif utilisé pour suivre les options qui ont été modifiées. L'application définit la signification des bits.
clientData
Données facultatives spécifiques à l'application qui peuvent être utilisées par des gestionnaires d'options personnalisés.

Le tableau doit être terminé par une entrée où optionName est NULL.

La deuxième fonctionnalité supplémentaire de Tk_SetOptions concerne la récupération d'erreurs. Si une erreur se produit lors du traitement des options de configuration, cette fonctionnalité permet de restaurer toutes les options de configuration à leurs valeurs précédentes. Des erreurs peuvent survenir soit lors du traitement des options dans Tk_SetOptions, soit plus tard chez l'appelant. Dans de nombreux cas, l'appelant effectue un traitement supplémentaire après le retour de Tk_SetOptions ; par exemple, il peut utiliser la valeur d'une option pour définir un trace sur une variable et détecter une erreur si la variable est un tableau au lieu d'un scalaire. La récupération d'erreurs est activée en transmettant une valeur non NULL pour l'argument savePtr à Tk_SetOptions ; il doit s'agir d'un pointeur vers une structure Tk_SavedOptions non initialisée sur la pile de l'appelant. Tk_SetOptions écrase la structure pointée par savePtr avec des informations sur les anciennes valeurs de toutes les options modifiées par la procédure. Si Tk_SetOptions réussit, l'appelant utilise la structure de l'une des deux manières suivantes. Si l'appelant termine le traitement des nouvelles options sans aucune erreur, il doit passer la structure à Tk_FreeSavedOptions afin que les anciennes valeurs puissent être libérées. Si l'appelant détecte une erreur dans le traitement des nouvelles options, il doit passer la structure à Tk_RestoreSavedOptions, qui copiera les anciennes valeurs dans l'enregistrement du widget et libérera les nouvelles valeurs. Si Tk_SetOptions détecte une erreur, elle restaure automatiquement toutes les options qui avaient déjà été modifiées et laisse *savePtr dans un état vide : l'appelant n'a pas besoin d'appeler ni Tk_FreeSavedOptions ni Tk_RestoreSavedOptions. Si l'argument savePtr à Tk_SetOptions est NULL, alors Tk_SetOptions libère chaque ancienne valeur d'option immédiatement lorsqu'elle définit une nouvelle valeur pour l'option. Dans ce cas, si une erreur se produit dans la troisième option, les anciennes valeurs des deux premières options ne peuvent pas être restaurées.

Tk_GetOptionValue retourne la valeur actuelle d'une option de configuration pour un widget particulier. L'argument namePtr contient le nom d'une option ; Tk_GetOptionValue utilise optionTable pour rechercher l'option et extraire sa valeur de l'enregistrement du widget pointé par recordPtr, puis il retourne un objet contenant cette valeur. Si une erreur se produit (par exemple, parce que namePtr contient un nom d'option inconnu), NULL est retourné et un message d'erreur est laissé dans le résultat de interp sauf si interp est NULL.

Tk_GetOptionInfo retourne des informations sur les options de configuration sous une forme adaptée aux commandes de widget configure. Si l'argument namePtr n'est pas NULL, il pointe vers un objet qui donne le nom d'une option de configuration ; Tk_GetOptionInfo retourne un objet contenant une liste de cinq éléments, qui sont le nom de l'option, le nom et la classe utilisés pour l'option dans la base de données des options, la valeur par défaut de l'option et la valeur actuelle de l'option. Si l'argument namePtr est NULL, alors Tk_GetOptionInfo retourne des informations sur toutes les options sous la forme d'une liste de listes ; chaque sous-liste décrit une option. Les options synonymes sont traitées différemment selon que namePtr est NULL : si namePtr est NULL alors la sous-liste pour chaque option synonyme a seulement deux éléments, qui sont le nom de l'option et le nom de l'autre option à laquelle elle fait référence ; si namePtr n'est pas NULL et nomme une option synonyme, alors l'objet retourné est la liste de cinq éléments pour l'autre option à laquelle le synonyme fait référence. Si une erreur se produit (par exemple, parce que namePtr contient un nom d'option inconnu), NULL est retourné et un message d'erreur est laissé dans le résultat de interp sauf si interp est NULL.

Tk_FreeConfigOptions doit être appelée lorsqu'un widget est supprimé. Elle libère toutes les ressources associées à l'une des options de configuration définies dans recordPtr par optionTable.

La macro Tk_Offset est fournie comme moyen sûr de générer les valeurs objOffset et internalOffset pour les entrées dans les structures Tk_OptionSpec. Elle prend deux arguments : le nom d'un type d'enregistrement et le nom d'un champ dans cet enregistrement. Elle retourne le décalage en octets du champ nommé dans les enregistrements du type donné.

MODÈLES

Le tableau de structures Tk_OptionSpec passé à Tk_CreateOptionTable via son argument templatePtr décrit les options de configuration prises en charge par une classe particulière de widgets. Chaque structure spécifie une option de configuration et possède les champs suivants :

typedef struct {
    Tk_OptionType type;
    const char *optionName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int objOffset;
    int internalOffset;
    int flags;
    const void *clientData;
    int typeMask;
} Tk_OptionSpec;
Le champ type indique le type d'option de configuration (par exemple, TK_OPTION_COLOR pour une valeur de couleur, ou TK_OPTION_INT pour une valeur entière). Type détermine comment la valeur de l'option est analysée (plus d'informations ci-dessous). Le champ optionName est une chaîne telle que -font ou -bg ; c'est le nom utilisé pour l'option dans les commandes Tcl et passé aux procédures via les arguments objc ou namePtr. Les champs dbName et dbClass sont utilisés par Tk_InitOptions pour rechercher une valeur par défaut pour cette option dans la base de données des options ; si dbName est NULL, la base de données des options n'est pas utilisée par Tk_InitOptions pour cette option. Le champ defValue spécifie une valeur par défaut pour cette option de configuration si aucune valeur n'est spécifiée dans la base de données des options. Les champs objOffset et internalOffset indiquent où stocker la valeur de cette option dans les enregistrements de widget (plus d'informations ci-dessous) ; les valeurs des champs objOffset et internalOffset doivent toujours être générées avec la macro Tk_Offset. Le champ flags contient des informations supplémentaires pour contrôler le traitement de cette option de configuration (voir ci-dessous pour les détails). ClientData fournit des données supplémentaires spécifiques au type nécessaires pour certains types. Par exemple, pour les types TK_OPTION_COLOR, clientData est une chaîne donnant la valeur par défaut à utiliser sur les écrans monochromes. Voir les descriptions des différents types ci-dessous pour les détails. Le dernier champ, typeMask, est utilisé par Tk_SetOptions pour retourner des informations sur les options qui ont été modifiées ; voir la description de Tk_SetOptions ci-dessus pour les détails.

Lorsque Tk_InitOptions et Tk_SetOptions stockent la valeur d'une option dans l'enregistrement du widget, elles peuvent le faire de deux manières. Si le champ objOffset de Tk_OptionSpec est supérieur ou égal à zéro, alors la valeur de l'option est stockée en tant que (Tcl_Obj *) à l'emplacement dans l'enregistrement du widget donné par objOffset. Si le champ internalOffset de Tk_OptionSpec est supérieur ou égal à zéro, alors la valeur de l'option est stockée sous une forme interne spécifique au type à l'emplacement dans l'enregistrement du widget donné par internalOffset. Par exemple, si le type de l'option est TK_OPTION_INT, alors la forme interne est un entier. Si le champ objOffset ou internalOffset est négatif, la valeur n'est pas stockée sous cette forme. Au moins l'un des décalages doit être supérieur ou égal à zéro.

Le champ flags se compose d'un ou plusieurs bits combinés par OR. Les indicateurs suivants sont pris en charge :

TK_OPTION_NULL_OK
Si ce bit est défini pour une option, une chaîne vide sera acceptée comme valeur pour l'option et la forme interne résultante sera un pointeur NULL, une valeur zéro ou None, selon le type de l'option. Si l'indicateur n'est pas défini, les chaînes vides entraîneront des erreurs. TK_OPTION_NULL_OK est généralement utilisé pour permettre de désactiver complètement une fonctionnalité, par exemple définir une valeur de curseur sur None afin qu'une fenêtre hérite simplement du curseur de son parent. Tous les types d'options ne prennent pas en charge l'indicateur TK_OPTION_NULL_OK ; pour ceux qui le font, il y a une indication explicite dans les descriptions ci-dessous.
TK_OPTION_DONT_SET_DEFAULT
Si ce bit est défini pour une option, aucune valeur par défaut ne sera définie dans Tk_InitOptions pour cette option. Ni la base de données des options, ni aucune valeur par défaut système, ni optionTable ne sont utilisés pour donner une valeur par défaut à cette option. Au lieu de cela, il est supposé que l'appelant a déjà fourni une valeur par défaut dans le code du widget.

Le champ type de chaque structure Tk_OptionSpec détermine comment analyser la valeur de cette option de configuration. La valeur légale pour type, et les actions correspondantes, sont décrites ci-dessous. Si le type nécessite une valeur tkwin à passer aux procédures comme Tk_SetOptions, ou s'il utilise le champ clientData de Tk_OptionSpec, alors il est indiqué explicitement ; si ce n'est pas mentionné, le type ne nécessite ni tkwin ni clientData.

TK_OPTION_ANCHOR
La valeur doit être une position d'ancrage standard telle que ne ou center. La forme interne est une valeur Tk_Anchor comme celles retournées par Tk_GetAnchorFromObj.
TK_OPTION_BITMAP
La valeur doit être un nom de bitmap Tk standard. La forme interne est un jeton Pixmap comme ceux retournés par Tk_AllocBitmapFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge l'indicateur TK_OPTION_NULL_OK.
TK_OPTION_BOOLEAN
La valeur doit être une valeur booléenne standard telle que true ou no. La forme interne est un entier avec la valeur 0 ou 1. Notez que si le champ objOffset n'est pas utilisé, les informations sur la valeur d'origine de cette option seront perdues.
TK_OPTION_BORDER
La valeur doit être un nom de couleur standard tel que red ou #ff8080. La forme interne est un jeton Tk_3DBorder comme ceux retournés par Tk_Alloc3DBorderFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge l'indicateur TK_OPTION_NULL_OK.
TK_OPTION_COLOR
La valeur doit être une couleur standard
TK_OPTION_COLOR
La valeur doit être un nom de couleur standard tel que red ou #ff8080. La forme interne est un jeton (XColor *) tel que ceux renvoyés par Tk_AllocColorFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_CURSOR
La valeur doit être un nom de curseur standard tel que cross ou @foo. La forme interne est un jeton Tk_Cursor tel que ceux renvoyés par Tk_AllocCursorFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et lorsque l'option est définie, le curseur de la fenêtre est modifié en appelant XDefineCursor. Ce type d'option prend également en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_CUSTOM
Cette option permet aux applications de définir de nouveaux types d'options. Le champ clientData des entrées pointe vers une structure définissant le nouveau type d'option. Voir la section TYPES D'OPTIONS PERSONNALISÉES ci-dessous pour plus de détails.
TK_OPTION_DOUBLE
La valeur sous forme de chaîne doit être un nombre à virgule flottante au format accepté par strtol. La forme interne est une valeur C double. Ce type d'option prend en charge le drapeau TK_OPTION_NULL_OK ; si une valeur NULL est définie, la représentation interne est mise à zéro.
TK_OPTION_END
Marque la fin du modèle. Il doit y avoir une structure Tk_OptionSpec avec type TK_OPTION_END à la fin de chaque modèle. Si le champ clientData de cette structure n'est pas NULL, alors il pointe vers un tableau supplémentaire de Tk_OptionSpec, qui est lui-même terminé par une autre entrée TK_OPTION_END. Les modèles peuvent être chaînés de manière arbitrairement profonde. Cette fonctionnalité permet de partager des options communes entre plusieurs classes de widgets.
TK_OPTION_FONT
La valeur doit être un nom de police standard tel que Times 16. La forme interne est un handle Tk_Font tel que ceux renvoyés par Tk_AllocFontFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_INT
La valeur sous forme de chaîne doit être un entier au format accepté par strtol (par exemple, les préfixes 0 et 0x peuvent être utilisés pour spécifier respectivement des nombres octaux ou hexadécimaux). La forme interne est une valeur C int.
TK_OPTION_JUSTIFY
La valeur doit être une valeur de justification standard telle que left. La forme interne est une Tk_Justify telle que les valeurs renvoyées par Tk_GetJustifyFromObj.
TK_OPTION_PIXELS
La valeur doit spécifier une distance d'écran telle que 2i ou 6.4. La forme interne est une valeur entière donnant une distance en pixels, telle que les valeurs renvoyées par Tk_GetPixelsFromObj. Notez que si le champ objOffset n'est pas utilisé, les informations sur la valeur d'origine de cette option seront perdues. Voir OBJOFFSET VS. INTERNALOFFSET ci-dessous pour plus de détails. Ce type d'option prend en charge le drapeau TK_OPTION_NULL_OK ; si une valeur NULL est définie, la représentation interne est définie sur INT_MIN.
TK_OPTION_RELIEF
La valeur doit être un relief standard tel que raised. La forme interne est une valeur de relief entière telle que TK_RELIEF_RAISED. Ce type d'option prend en charge le drapeau TK_OPTION_NULL_OK ; si une valeur NULL est définie, la représentation interne est définie sur TK_RELIEF_NULL.
TK_OPTION_STRING
La valeur peut être n'importe quelle chaîne. La forme interne est un pointeur (char *) qui pointe vers une copie dynamiquement allouée de la valeur. Ce type d'option prend en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_STRING_TABLE
Pour ce type, clientData est un pointeur vers un tableau de chaînes adapté à être passé à Tcl_GetIndexFromObj. La valeur doit être l'une des chaînes du tableau, ou une abréviation unique d'une des chaînes. La forme interne est un entier donnant l'index dans le tableau de la chaîne correspondante, tel que la valeur de retour de Tcl_GetStringFromObj. Ce type d'option prend en charge le drapeau TK_OPTION_NULL_OK ; si une valeur NULL est définie, la représentation interne est définie sur -1.
TK_OPTION_SYNONYM
Ce type est utilisé pour fournir des noms alternatifs à une option (par exemple, -bg est souvent utilisé comme synonyme de -background). Le champ clientData est une chaîne qui donne le nom d'une autre option dans le même tableau. Chaque fois que l'option synonyme est utilisée, les informations de l'autre option seront utilisées à la place.
TK_OPTION_WINDOW
La valeur doit être un nom de chemin de fenêtre. La forme interne est un jeton Tk_Window pour la fenêtre. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions (afin d'identifier l'application), et il prend en charge le drapeau TK_OPTION_NULL_OK.

ISSUES DE GESTION DE STOCKAGE

Si un champ d'un enregistrement de widget a son décalage stocké dans le champ objOffset ou internalOffset d'une structure Tk_OptionSpec, alors les procédures décrites ici géreront toutes les allocations de stockage et les problèmes de gestion des ressources associés au champ. Lorsque la valeur d'une option est modifiée, Tk_SetOptions (ou Tk_FreeSavedOptions) libérera automatiquement toutes les ressources associées à l'ancienne valeur, telles que les Tk_Fonts pour les options TK_OPTION_FONT ou la mémoire allouée dynamiquement pour les options TK_OPTION_STRING. Pour une option stockée comme un objet en utilisant le champ objOffset d'une structure Tk_OptionSpec, l'enregistrement du widget partage l'objet pointé par la valeur objv de l'appel à Tk_SetOptions. Le compteur de références de cet objet est incrémenté lorsqu'un pointeur vers celui-ci est stocké dans l'enregistrement du widget et décrémenté lorsque l'option est modifiée. Lorsque le widget est supprimé, Tk_FreeConfigOptions doit être appelé ; il libérera les ressources associées à toutes les options et décrémentera les compteurs de références pour tous les objets.

Cependant, le code du widget est responsable du stockage de NULL ou None dans tous les champs de pointeur et de jeton avant d'appeler Tk_InitOptions. Ceci est nécessaire pour permettre un nettoyage approprié dans le cas rare où une erreur se produit dans Tk_InitOptions.

OBJOFFSET VS. INTERNALOFFSET

Dans la plupart des cas, il est plus simple d'utiliser le champ internalOffset d'une structure Tk_OptionSpec et non le champ objOffset. Cela rend la forme interne de la valeur immédiatement disponible pour le code du widget, de sorte que la valeur n'a pas à être extraite d'un objet chaque fois qu'elle est utilisée. Cependant, il existe deux cas où le champ objOffset est utile. Le premier cas concerne les options TK_OPTION_PIXELS. Dans ce cas, la forme interne est une valeur entière en pixels qui n'est valide que pour un écran particulier. Si la valeur de l'option est récupérée, elle sera renvoyée comme un simple nombre. Par exemple, après la commande .b configure -borderwidth 2m, la commande .b configure -borderwidth pourrait renvoyer 7, qui est la valeur entière en pixels correspondant à 2m. Malheureusement, cela perd la valeur indépendante de l'écran d'origine. Ainsi, pour les options TK_OPTION_PIXELS, il est préférable d'utiliser le champ objOffset. Dans ce cas, la valeur d'origine de l'option est conservée dans l'objet et peut être renvoyée lorsque l'option est récupérée. Dans la plupart des cas, il est pratique d'utiliser également le champ internalOffset, de sorte que la valeur entière soit immédiatement disponible pour une utilisation dans le code du widget (alternativement, Tk_GetPixelsFromObj peut être utilisé pour extraire la valeur entière de l'objet chaque fois qu'elle est nécessaire). Notez que le problème de perte d'informations lors des récupérations n'existe que pour les options TK_OPTION_PIXELS.

La deuxième raison d'utiliser le champ objOffset est de mettre en œuvre de nouveaux types d'options non pris en charge par ces procédures. Pour mettre en œuvre un nouveau type d'option, vous pouvez utiliser TK_OPTION_STRING comme type dans la structure Tk_OptionSpec et définir le champ objOffset mais pas le champ internalOffset. Ensuite, après avoir appelé Tk_SetOptions, convertissez vous-même l'objet en forme interne.

Les widgets Ttk ne prennent pas en charge le mécanisme internalOffset. Les valeurs d'options des widgets Ttk sont toujours stockées sous forme de (Tcl_Obj *), ce qui signifie que le champ objOffset doit être utilisé.

DESCRIPTION

The Tk option configuration facility provides a uniform mechanism for widgets to handle configuration options. The facility supports a wide range of option types, including strings, integers, floating-point numbers, colors, fonts, screen distances, booleans, bitmaps, cursors, relief styles, and justification styles. The facility also allows for custom option types to be defined using arbitrary C code.

The core of the option configuration facility is the Tk_OptionSpec structure, which describes a single widget option. Multiple Tk_OptionSpec structures can be grouped together to form a Tk_OptionTable, which represents all the configurable options for a widget. The following sections describe the various structures and procedures used by the option configuration facility.

TEMPLATES

The Tk_Option structure is used to hold information about a single option that is not a custom option. It contains the following fields:

offset
Offset in bytes from the start of the widget record to the location where the option's value is stored. This field is used for options whose values are stored directly in the widget record as C basic types (integers, booleans, etc.).
objOffset
Offset in bytes from the start of the widget record to the location where a pointer to the option's Tcl_Obj value is stored. This field is used for options whose values are stored as Tcl_Obj pointers. If this value is negative, it means that the option's value is not stored as a Tcl_Obj pointer.
internalOffset
Offset in bytes from the start of the widget record to the location where the option's internal representation is stored. This field is used for custom option types, where the internal representation may be different from the Tcl_Obj representation.
name
The name of the option (e.g., "background", "font").
defaultValue
A string representing the default value of the option. This is used only if the option is not specified in the configuration command or the option database.
objDefaultValuePtr
A pointer to a Tcl_Obj representing the default value of the option. This is used in preference to defaultValue if it is non-NULL.
flags
A bitmask containing flags that control the behavior of the option. Possible flags include:
TK_OPTION_NULL_OK
Indicates that the option can be set to NULL.
TK_OPTION_AUTOSLOW
Indicates that the option should be automatically reset if it is changed dynamically.
TK_OPTION_DIRTY
Indicates that the option affects the widget's layout.
TK_OPTION_JIGGLE
Indicates that the option should be jiggled.
TK_OPTION_READ_ONLY
Indicates that the option is read-only.
optionPtr
A pointer to the Tk_OptionSpec structure that describes this option.

The Tk_ObjCustomOption structure is used to hold information about a custom option type. It contains all the fields of the Tk_Option structure, plus the following additional fields:

clientData
An arbitrary value that will be passed to the custom option's procedures. This is typically used to store a pointer to widget-specific data.
setProc
A pointer to a procedure that converts a Tcl_Obj into the internal representation of the option and stores it in the widget record. This procedure is invoked by Tk_SetOptions.
getProc
A pointer to a procedure that converts the internal representation of the option into a Tcl_Obj and returns it. This procedure is invoked by Tk_GetOptionValue and Tk_GetOptionInfo.
restoreProc
A pointer to a procedure that restores a previously saved internal representation of the option. This procedure is invoked by Tk_RestoreSavedOptions.
freeProc
A pointer to a procedure that frees any storage allocated for the internal representation of the option. This procedure is invoked by Tk_SetOptions and Tk_FreeSavedOptions.

STORAGE MANAGEMENT ISSUES

The Tk_OptionSpec structure describes a single widget option. It contains the following fields:

type
Specifies the type of the option. This can be one of the standard Tk option types (e.g., TK_OPTION_STRING, TK_OPTION_INT, TK_OPTION_COLOR) or a pointer to a Tk_ObjCustomOption structure for custom option types.
option
A pointer to a Tk_Option structure that holds information about the option, such as its name, default value, and flags.
objCustomOptionPtr
If the type field specifies a custom option type, this field is a pointer to a Tk_ObjCustomOption structure that describes the custom option.

The Tk_OptionTable structure represents a collection of Tk_OptionSpec structures. It is typically allocated dynamically by Tk_InitOptions.

The Tk_InitOptions procedure initializes an option table. It takes an array of Tk_OptionSpec structures and the widget's class name as arguments, and returns a pointer to a newly created Tk_OptionTable.

The Tk_ConfigureWidget and Tk_ConfigureObject procedures are used to configure a widget's options. They take the widget's window, an interpreter, the option table, the number of arguments, an array of Tcl objects representing the option-value pairs, a pointer to the widget record, and flags as arguments. They process the option-value pairs, convert them to the appropriate internal representations, and store them in the widget record.

The Tk_ScaleWidget and Tk_ScaleObject procedures are similar to Tk_ConfigureWidget and Tk_ConfigureObject, but they also support scaling of certain option values (e.g., screen distances).

The Tk_SetOptions and Tk_SetObjectOptions procedures are used to set widget options from a list of name-value pairs. They take the widget's window, an interpreter, the option table, the number of arguments, an array of Tcl objects representing the option-value pairs, a pointer to the widget record, flags, and a pointer to a Tk_SavedOptions structure as arguments. They process the option-value pairs, convert them to the appropriate internal representations, store them in the widget record, and save the original values in the Tk_SavedOptions structure for later restoration.

The Tk_GetOptionValue procedure retrieves the value of a specific option. It takes the interpreter, option table, pointer to the widget record, offset of the option's internal representation, and the widget's window as arguments. It returns a Tcl object representing the option's value.

The Tk_GetOptionInfo procedure retrieves information about all configurable options for a widget. It takes the interpreter, option table, pointer to the widget record, and the widget's window as arguments. It returns a Tcl object containing a list of option specifications.

The Tk_RestoreSavedOptions and Tk_RestoreObjectSavedOptions procedures restore previously saved option values. They take the widget's window, option table, pointer to the widget record, and a pointer to a Tk_SavedOptions structure as arguments.

The Tk_FreeSavedOptions and Tk_FreeObjectSavedOptions procedures free any storage allocated for saving option values. They take a pointer to a Tk_SavedOptions structure as an argument.

OBJOFFSET VS. INTERNALOFFSET

The objOffset field is used when the option's value is stored directly as a pointer to a Tcl_Obj in the widget record. This is typically used for options whose values are complex or can change dynamically.

The internalOffset field is used when the option's value is stored in a custom internal representation within the widget record. This is typically used for options that have a specific C data type or structure that is different from a Tcl_Obj.

The offset field is used for simple options whose values are stored directly as C basic types (e.g., integers, booleans) in the widget record. This field is not used for custom options or options stored as Tcl_Obj pointers.

CUSTOM OPTION TYPES

Custom option types allow widgets to define their own way of handling option values. This is done by providing a set of procedures (setProc, getProc, restoreProc, freeProc) that operate on the custom data type.

The Tk_ObjCustomOption structure is used to define a custom option type. It contains a pointer to the widget record where the option is stored and a pointer to the custom option's procedures. The structure:

clientData
A copy of the clientData field in the Tk_ObjCustomOption structure.
interp
A pointer to a Tcl interpreter, used for error reporting.
Tkwin
A copy of the tkwin argument to Tk_SetOptions
valuePtr
A pointer to a reference to a Tcl_Obj describing the new value for the option; it could have been specified explicitly in the call to Tk_SetOptions or it could come from the option database or a default. If the objOffset for the option is non-negative (the option value is stored as a (Tcl_Obj *) in the widget record), the Tcl_Obj pointer referenced by valuePtr is the pointer that will be stored at the objOffset for the option. SetProc may modify the value if necessary; for example, setProc may change the value to NULL to support the TK_OPTION_NULL_OK flag.
recordPtr
A pointer to the start of the widget record to modify.
internalOffset
Offset in bytes from the start of the widget record to the location where the internal representation of the option value is to be placed.
saveInternalPtr
A pointer to storage allocated in a Tk_SavedOptions structure for the internal representation of the original option value. Before setting the option to its new value, setProc should set the value referenced by saveInternalPtr to the original value of the option in order to support Tk_RestoreSavedOptions.
flags
A copy of the flags field in the Tk_OptionSpec structure for the option

SetProc returns a standard Tcl result: TCL_OK to indicate successful processing, or TCL_ERROR to indicate a failure of any kind. An error message may be left in the Tcl interpreter given by interp in the case of an error.

The getProc procedure is invoked by Tk_GetOptionValue and Tk_GetOptionInfo to retrieve a Tcl_Obj representation of the internal representation of an option. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. RecordPtr is a pointer to the beginning of the widget record to query. InternalOffset is the offset in bytes from the beginning of the widget record to the location where the internal representation of the option value is stored. GetProc must return a pointer to a Tcl_Obj representing the value of the option.

The restoreProc procedure is invoked by Tk_RestoreSavedOptions to restore a previously saved internal representation of a custom option value. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. InternalPtr is a pointer to the location where internal representation of the option value is stored. SaveInternalPtr is a pointer to the saved value. RestoreProc must copy the value from saveInternalPtr to internalPtr to restore the value. RestoreProc need not free any memory associated with either internalPtr or saveInternalPtr; freeProc will be invoked to free that memory if necessary. RestoreProc has no return value.

The freeProc procedure is invoked by Tk_SetOptions and Tk_FreeSavedOptions to free any storage allocated for the internal representation of a custom option. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. InternalPtr is a pointer to the location where the internal representation of the option value is stored. The freeProc must free any storage associated with the option. FreeProc has no return value.
