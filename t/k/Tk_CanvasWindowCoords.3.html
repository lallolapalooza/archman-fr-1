DESCRIPTION

Ces procédures sont appelées par les gestionnaires de canvas pour effectuer diverses fonctions utilitaires.

Tk_CanvasTkwin renvoie le Tk_Window associé à un widget canvas particulier.

Tk_CanvasGetCoord traduit une description textuelle d'une coordonnée dans un canvas (comme 2p ou 1.6c) en une coordonnée à double précision du canvas. Si string est une description valide d'une coordonnée, Tk_CanvasGetCoord stocke la valeur correspondante dans *doublePtr et renvoie TCL_OK. Sinon, elle stocke un message d'erreur dans le résultat de l'interpréteur et renvoie TCL_ERROR.

Tk_CanvasDrawableCoords est appelée lors du redessin pour calculer où les éléments doivent être dessinés. Étant donné les coordonnées x et y dans l'espace du canvas, Tk_CanvasDrawableCoords calcule les coordonnées de pixel dans le drawable actuel utilisé pour le redessin du canvas ; elle renvoie ces valeurs dans *drawableXPtr et *drawableYPtr. Cette procédure ne doit pas être appelée sauf pendant le redessin.

Tk_CanvasSetStippleOrigin est également utilisée pendant le redessin. Elle définit l'origine des motifs de hachures dans gc de sorte que les motifs dessinés avec gc dans le pixmap hors écran soient alignés avec les motifs dessinés avec une origine (0,0) dans la fenêtre de canvas réelle. Tk_CanvasSetStippleOrigin est nécessaire pour garantir que les motifs de hachures s'alignent correctement lorsque le canvas est redessiné par petites portions. Les redessins sont effectués en double tampon, où une portion du canvas est dessinée dans un pixmap hors écran, puis copiée sur l'écran. Dans cette configuration, les origines des hachures dans les contextes graphiques doivent être ajustées lors de chaque redessin pour compenser la position du pixmap hors écran par rapport à la fenêtre. Si un élément est dessiné avec une hachure, son gestionnaire de type d'élément appelle généralement Tk_CanvasSetStippleOrigin juste avant d'utiliser gc pour dessiner quelque chose ; après avoir terminé le dessin, le gestionnaire de type d'élément appelle XSetTSOrigin pour restaurer l'origine dans gc à (0,0) (la restauration est nécessaire car les contextes graphiques sont partagés et ne peuvent pas être modifiés de manière permanente).

Tk_CanvasWindowCoords est similaire à Tk_CanvasDrawableCoords, mais renvoie les coordonnées dans la fenêtre du canvas dans l'espace de l'écran, plutôt que dans un pixmap hors écran.

Tk_CanvasEventuallyRedraw peut être appelée par un gestionnaire de type d'élément pour informer Tk qu'une partie d'un canvas doit être redessinée. Les arguments x1, y1, x2, et y2 spécifient la région à redessiner, en coordonnées de canvas. Les gestionnaires de type d'élément ont rarement besoin d'appeler Tk_CanvasEventuallyRedraw, car Tk peut généralement déterminer quand un élément a changé et faire la demande de redessin par lui-même (cela se produit, par exemple, lorsque Tk appelle un configureProc ou un scaleProc). La seule fois où un gestionnaire de type d'élément doit appeler Tk_CanvasEventuallyRedraw est si un élément a changé en lui-même sans être déclenché par l'une des procédures de son type d'élément ; cela pourrait se produire, par exemple, si une image est modifiée à l'aide de commandes d'image.

Tk_CanvasTagsParseProc et Tk_CanvasTagsPrintProc sont des procédures qui gèrent l'option -tags pour les éléments de canvas. Le code d'un gestionnaire de type d'élément n'appelle pas directement ces procédures, mais utilise leurs adresses pour créer une structure Tk_CustomOption pour l'option -tags. Le code ressemble généralement à ceci :

static const Tk_CustomOption tagsOption = {Tk_CanvasTagsParseProc,
    Tk_CanvasTagsPrintProc, NULL
};
static const Tk_ConfigSpec configSpecs[] = {
    ...
    {TK_CONFIG_CUSTOM, "-tags", NULL, NULL,
        NULL, 0, TK_CONFIG_NULL_OK, &tagsOption},
    ...
};
