NOM

Tk::Menubutton - Créer et manipuler des widgets Menubutton

SYNOPIS

$menubouton = $parent->Menubutton(?options?);

OPTIONS STANDARD

-activebackground -cursor -highlightthickness -takefocus -activeforeground -disabledforeground -image -text -anchor -font -justify -textvariable -background -foreground -padx -underline -bitmap -highlightbackground -pady -relief -borderwidth -highlightcolor -wraplength

Voir Tk::options pour les détails des options standard.

OPTIONS SPÉCIFIQUES AU WIDGET

Nom de ligne de commande : -compound
Nom de base de données : compound
Classe de base de données : Compound
Spécifie si le bouton doit afficher à la fois une image et du texte, et si oui, où l'image doit être placée par rapport au texte. Les valeurs valides pour cette option sont bottom, center, left, none, right et top. La valeur par défaut est none, ce qui signifie que le bouton affichera soit une image, soit du texte, en fonction des valeurs des options -image et -bitmap.
Nom : direction
Classe : Height
Commutateur : -direction
Spécifie où le menu sera affiché. above essaie d'afficher le menu au-dessus du menubutton. below essaie d'afficher le menu en dessous du menubutton. left essaie d'afficher le menu à gauche du menubutton. right essaie d'afficher le menu à droite du menubutton. flush affiche le menu directement par-dessus le menubutton.
Nom : height
Classe : Height
Commutateur : -height
Spécifie une hauteur souhaitée pour le menubutton. Si une image ou un bitmap est affiché dans le menubutton, la valeur est en unités d'écran (c'est-à-dire toute forme acceptable par Tk_GetPixels) ; pour le texte, elle est en lignes de texte. Si cette option n'est pas spécifiée, la hauteur souhaitée du menubutton est calculée à partir de la taille de l'image, du bitmap ou du texte affiché.
Nom : indicatorOn
Classe : IndicatorOn
Commutateur : -indicatoron
La valeur doit être une valeur booléenne valide. Si elle est vraie, un petit rectangle indicateur sera affiché sur le côté droit du menubutton et les liaisons par défaut traiteront cela comme un menubutton optionnel. Si faux, aucun indicateur ne sera affiché.
Nom : menu
Classe : MenuName
Commutateur : -menu
Spécifie le chemin du menu associé à ce menubutton. Le menu doit être un enfant du menubutton.
Nom : state
Classe : State
Commutateur : -state
Spécifie l'un des trois états du menubutton : normal, active, ou disabled. En état normal, le menubutton est affiché en utilisant les options foreground et background. L'état actif est généralement utilisé lorsque le curseur est sur le menubutton. En état actif, le menubutton est affiché en utilisant les options activeForeground et activeBackground. L'état désactivé signifie que le menubutton doit être inactif : les liaisons par défaut refuseront d'activer le widget et ignoreront les clics de souris. Dans cet état, les options disabledForeground et background déterminent comment le bouton est affiché.
Nom : width
Classe : Width
Commutateur : -width
Spécifie une largeur souhaitée pour le menubutton. Si une image ou un bitmap est affiché dans le menubutton, la valeur est en unités d'écran (c'est-à-dire toute forme acceptable par Tk_GetPixels) ; pour le texte, elle est en caractères. Si cette option n'est pas spécifiée, la largeur souhaitée du menubutton est calculée à partir de la taille de l'image, du bitmap ou du texte affiché.

DESCRIPTION

La méthode Menubutton crée une nouvelle fenêtre (fournie par l'argument $widget) et en fait un widget menubutton. Des options supplémentaires, décrites ci-dessus, peuvent être spécifiées sur la ligne de commande ou dans la base de données d'options pour configurer des aspects du menubutton tels que ses couleurs, sa police, son texte et son relief initial. La commande menubutton renvoie son argument $widget. Au moment où cette commande est invoquée, il ne doit pas exister de fenêtre nommée $widget, mais le parent de $widget doit exister.

Un menubutton est un widget qui affiche une chaîne de caractères, un bitmap ou une image et est associé à un widget menu. Si du texte est affiché, il doit être entièrement dans la même police, mais il peut occuper plusieurs lignes à l'écran (s'il contient des sauts de ligne ou si un retour à la ligne se produit en raison de l'option wrapLength) et l'un des caractères peut facultativement être souligné à l'aide de l'option underline. En usage normal, appuyer sur le bouton de souris 1 sur le menubutton provoque l'affichage du menu associé juste en dessous du menubutton. Si la souris est déplacée sur le menu avant de relâcher le bouton de la souris, la libération du bouton provoque l'invocation de l'entrée de menu sous-jacente. Lorsque le bouton est relâché, le menu est retiré.

Les menubuttons sont généralement organisés en groupes appelés barres de menu qui permettent le balayage : si le bouton de la souris est pressé sur un menubutton (provoquant l'affichage de son menu) et que la souris est déplacée sur un autre menubutton de la même barre de menu sans relâcher le bouton de la souris, le menu du premier menubutton est retiré et le menu du nouveau menubutton est affiché à la place.

Il existe plusieurs interactions entre les menubuttons et les menus ; voir l'entrée du manuel menu pour des informations sur diverses configurations de menu, telles que les menus déroulants et les menus d'options.

MÉTHODES DU WIDGET

La méthode Menubutton crée un objet widget. Cet objet prend en charge les méthodes configure et cget décrites dans Tk::options, qui peuvent être utilisées pour interroger et modifier les options décrites ci-dessus. La méthode menu renvoie le menu associé au widget. Le widget hérite également de toutes les méthodes fournies par la classe générique Tk::Widget.

LIAISONS PAR DÉFAUT

Tk crée automatiquement des liaisons de classe pour les menubuttons qui leur donnent le comportement par défaut suivant :

[1]
Un menubutton s'active lorsque la souris passe dessus et se désactive lorsque la souris le quitte.
[2]
Appuyer sur le bouton de souris 1 sur un menubutton affiche le menubutton : son relief change pour devenir relevé et son menu associé est affiché sous le menubutton. Tk::Menubutton

Perl Tk Menubutton widgetperl v5.42.0

NAME

Menubutton — create buttons that display menus

SYNOPSIS

    package MyWindow;
    use Tk;
    use Tk::Menubutton;

    my $mw = MainWindow->new;
    my $mb = $mw->Menubutton(
        -text    => 'File',
        -menuitems => [
            [ 'New', \&new_cb ],
            [ 'Open', \&open_cb ],
            [ 'Save', \&save_cb ],
            [ 'Separator' ],
            [ 'Exit', \&exit_cb ],
        ]
    )->pack;

    MainLoop;
    sub new_cb { print "New clicked!\n"; }
    sub open_cb { print "Open clicked!\n"; }
    sub save_cb { print "Save clicked!\n"; }
    sub exit_cb { exit; }

STANDARD OPTIONS

Menubutton supports the standard Tk widget options, including:

        -activebackground, -activeforeground, -anchor, -background, -bitmap,
        -borderwidth, -command, -cursor, -disabledforeground, -exportselection,
        -font, -foreground, -height, -highlightbackground, -highlightcolor,
        -highlightthickness, -image, -justify, -label, -padx, -pady, -relief,
        -repeatdelay, -repeatinterval, -state, -takefocus, -text, -textvariable,
        -underline, -width, -wraplength

See the Tk::options manual page for details on the standard options.

WIDGET-SPECIFIC OPTIONS

-menuitems
Specifies a list of menu items to be placed in the menu associated with the menubutton. The format of the list is described below in the DESCRIPTION section. This option is often used instead of the standard Tk -menu option.
-menu
Specifies the menu widget that is associated with the menubutton. If this option is specified, the -menuitems option is ignored. The menu widget must already exist when this option is set. The menubutton will automatically call the postcascade method on the menu widget when the menubutton is activated.

DESCRIPTION

A menubutton is a button that, when clicked, displays a menu. The menubutton widget itself displays a label, which can be text or a bitmap. The menu associated with the menubutton can be created either by specifying the -menuitems option, or by explicitly creating a menu widget and associating it with the menubutton using the -menu option.

The -menuitems option provides a convenient way to create a menu. It takes a reference to a list of menu items. Each menu item can be one of the following:

[string, callback]
A menu entry with the given string as its label. When the entry is selected, the callback procedure is invoked. The callback should be a reference to a subroutine or a method. Arguments can be passed to the callback by appending them after the callback reference.
[string, callback, arg1, arg2, ...]
Same as above, but with additional arguments passed to the callback.
[string]
A menu entry with the given string as its label. No callback is associated with this entry. This is typically used for disabled entries or entries that trigger some other action not handled directly by Perl.
['Separator']
Creates a separator line in the menu.
['Cascade', menu_label, menu_items_ref]
Creates a cascading menu. menu_label is the text that appears on the menubutton that will pop up the cascade. menu_items_ref is a reference to another list of menu items, defining the cascade menu.
['Cascade', menu_label, menu_items_ref, arg1, arg2, ...]
Same as above, but with additional arguments passed to the cascade callback.

The menubutton widget also supports standard Tk bindings for mouse and keyboard interaction. These bindings are described in the DEFAULT BINDINGS section.

WIDGET METHODS

The Menubutton widget does not support any additional methods beyond the standard Tk widget methods.

DEFAULT BINDINGS

[1]
If button 1 is pressed over a menubutton, the menubutton is highlighted, and its associated menu is posted. If the mouse cursor is moved off the menubutton while the button is still pressed, the menubutton is un-highlighted and the menu is unposted.
[2]
If button 1 is released over the menubutton after it has been pressed and its menu posted, the menu is unposted.
[3]
If button 1 is pressed over a menubutton, and then the mouse is moved over an entry in the associated menu and button 1 is released, the menu entry is invoked. Once a menu entry has been invoked, the menubutton unposts itself.
[4]
If button 1 is pressed over a menubutton and then dragged over some other menubutton, the original menubutton unposts itself and the new menubutton posts.
[5]
If button 1 is pressed over a menubutton and released outside any menubutton or menu, the menubutton unposts without invoking any menu entry.
[6]
When a menubutton is posted, its associated menu claims the input focus to allow keyboard traversal of the menu and its submenus. See the menu documentation for details on these bindings.
[7]
If the underline option has been specified for a menubutton then keyboard traversal may be used to post the menubutton: Alt+x, where x is the underlined character (or its lower-case or upper-case equivalent), may be typed in any window under the menubutton's toplevel to post the menubutton.
[8]
The F10 key may be typed in any window to post the first menubutton under its toplevel window that isn't disabled.
[9]
If a menubutton has the input focus, the space and return keys post the menubutton.

If the menubutton's state is disabled then none of the above actions occur: the menubutton is completely non-responsive.

The behavior of menubuttons can be changed by defining new bindings for individual widgets or by redefining the class bindings.

KEYWORDS

menubutton, widget
