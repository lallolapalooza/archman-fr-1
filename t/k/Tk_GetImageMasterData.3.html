DELETEPROC

typePtr->deleteProc est une procédure que Tk appelle lors de la suppression d'une image (c'est-à-dire lorsque la commande image delete est invoquée). Avant d'appeler deleteProc, Tk appellera freeProc pour chacune des instances de l'image. deleteProc doit correspondre au prototype suivant :

typedef void Tk_ImageDeleteProc(
        ClientData modelData);
L'argument modelData sera identique à la valeur stockée dans *modelDataPtr par createProc lors de la création de l'image. deleteProc doit libérer toutes les ressources associées à l'image.

TK_GETIMAGEMODELDATA

La procédure Tk_GetImageMasterData peut être appelée pour récupérer des informations sur une image. Par exemple, un gestionnaire d'images peut utiliser cette procédure pour localiser ses données de modèle d'image pour une image. S'il existe une image nommée name dans l'interpréteur fourni par interp, alors *typePtrPtr est rempli avec les informations de type pour l'image (la valeur typePtr passée à Tk_CreateImageType lors de l'enregistrement du type d'image) et la valeur de retour est la valeur ClientData retournée par createProc lors de la création de l'image (il s'agit généralement d'un pointeur vers la structure de données du modèle d'image). Si une telle image n'existe pas, NULL est retourné et NULL est stocké dans *typePtrPtr.

Tk_GetImageModelData est un synonyme de Tk_GetImageMasterData.

PRISE EN CHARGE DE L'INTERFACE HERITEE

Dans Tk 8.2 et versions antérieures, la définition de Tk_ImageCreateProc était incompatible, avec le prototype suivant :

typedef int Tk_ImageCreateProc(
        Tcl_Interp *interp,
        char *name,
        int argc,
        char **argv,
        Tk_ImageType *typePtr,
        Tk_ImageMaster model,
        ClientData *modelDataPtr);
Les programmes et bibliothèques hérités datant de cette époque peuvent encore contenir du code qui définit des types d'images Tk étendus en utilisant l'ancienne interface. Le fichier d'en-tête Tk supportera toujours cette interface héritée si le code est compilé avec le macro USE_OLD_IMAGE défini.

Tk_ImageModel est un synonyme de Tk_ImageMaster.

Lorsque le support hérité USE_OLD_IMAGE est activé, vous pourriez voir la routine Tk_InitImageArgs utilisée. Il s'agissait d'un outil de migration utilisé pour créer des extensions activées par des stubs qui pouvaient être chargées dans des interpréteurs contenant toutes les versions de Tk 8.1 et ultérieures. Tk 8.5 ne fournit plus cette routine, mais utilise une macro pour convertir toute tentative d'appel de cette routine en un commentaire vide. Toute extension activée par des stubs fournissant un type d'image étendu via l'interface héritée, compilée avec les en-têtes Tk 8.5 et liée à la bibliothèque de stubs Tk 8.5, produira un fichier qui ne pourra être chargé que dans des interpréteurs avec Tk 8.5 ou ultérieur ; c'est-à-dire les règles normales de compatibilité des stubs. Si un développeur souhaite générer à partir d'un tel code un fichier chargeable dans des interpréteurs avec Tk 8.4 ou antérieur, il doit utiliser les en-têtes et les bibliothèques de stubs Tk 8.4 pour ce faire.

Tout nouveau code écrit aujourd'hui ne devrait pas utiliser les interfaces héritées. Leur support devrait disparaître dans Tk 9.
