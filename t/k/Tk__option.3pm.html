NOM

Tk::option - Utilisation de la base de données d'options en Perl/Tk

SYNOPIS

    $widget->widgetClass(Name=>nom, -class=>classe);

    $widget->PathName;

    $widget->optionAdd(motif=>valeur ?,priorité?);

    $widget->optionClear;

    $widget->optionGet(nom, classe);

    $widget->optionReadfile(nomFichier ?,priorité?);

DESCRIPTION

La base de données d'options (également connue sous le nom de base de données de ressources ou de base de données des paramètres par défaut de l'application) est un ensemble de règles pour appliquer les options par défaut aux widgets. Les utilisateurs et les administrateurs système peuvent définir ces règles pour personnaliser l'apparence des applications sans modifier le code de l'application ; par exemple, un utilisateur peut définir ses propres couleurs de premier plan et d'arrière-plan, ou un site peut utiliser des polices associées à des préférences visuelles ou linguistiques. Différents gestionnaires de fenêtres (et leurs implémentations) ont implémenté la base de données différemment, mais la plupart des gestionnaires de fenêtres basés sur Xt utilisent le fichier .Xdefaults ou l'utilitaire xrdb pour gérer les préférences de l'utilisateur ; certains utilisent les deux, et/ou implémentent un ensemble plus complexe de bases de données de site, d'utilisateur et d'application. Consultez la documentation de votre site pour ces sujets ou la propriété RESOURCE_MANAGER de votre gestionnaire de fenêtre.

Être un bon citoyen

Pour la plupart des applications, la base de données d'options "fonctionne tout simplement". Les méthodes option... sont destinées aux applications qui ont besoin de faire quelque chose d'inhabituel, comme ajouter de nouvelles règles ou tester une option par défaut. Même dans de tels cas, l'application doit tenir compte des préférences de l'utilisateur. Ne codez pas en dur les options des widgets sans une très bonne raison. Tous les utilisateurs ont leurs propres goûts et ils sont tous différents. Ils choisissent une police spéciale dans une taille spéciale et ont souvent passé beaucoup de temps à trouver une palette de couleurs qu'ils aimeront jusqu'à la mort. Lorsque vous respectez leurs choix, ils apprécieront beaucoup plus de travailler avec vos applications. Ne détruisez pas l'apparence commune d'un bureau personnel.

Règles d'options et identification des widgets

Tous les widgets d'une application sont identifiés hiérarchiquement par leur nom de chemin, en partant de la MainWindow et en passant par chaque widget utilisé pour créer le point d'extrémité. Les éléments du chemin sont des noms de widgets, tout comme les éléments d'un chemin de fichier, du répertoire racine à un fichier. Les règles de la base de données d'options sont des motifs qui sont comparés au nom de chemin d'un widget pour déterminer quelles valeurs par défaut s'appliquent. Lorsqu'un widget est créé, l'option Name peut être utilisée pour attribuer un nom au widget et créer ainsi un chemin distinctif pour les widgets d'une application. Si l'option Name n'est pas fournie, Perl/Tk attribue un nom par défaut basé sur le type de widget ; le nom par défaut d'une MainWindow est le appname. Ces valeurs par défaut conviennent à la plupart des widgets, ne vous sentez donc pas obligé de trouver un nom significatif pour chaque widget que vous créez. Un widget doit avoir un nom distinctif pour permettre aux utilisateurs de personnaliser ses options indépendamment des autres widgets d'une application. Par exemple, pour créer un widget Text auquel des options spéciales seront attribuées, donnez-lui un nom tel que :

$text = $mw->Text(Name => 'importantText');

Vous pouvez ensuite personnaliser les attributs du widget avec une règle dans la base de données d'options telle que :

*importantText*foreground: red

La classe class identifie des groupes de widgets, généralement au sein d'une application, mais aussi pour regrouper des widgets similaires entre différentes applications. On attribue généralement une classe à une TopLevel ou à une Frame afin que la classe s'applique à tous les enfants de ce widget. Pour étendre l'exemple, nous pourrions être plus spécifiques concernant le widget importantText en donnant une classe à sa frame :

$frame = $mw->Frame(-class => 'Urgent');
$text = $frame->Text(Name => 'importantText');

Ensuite, le motif de ressource peut être spécifié comme suit :

*Urgent*importantText*foreground: red

De même, le motif "*Urgent*background: cyan" s'appliquerait à tous les widgets de la frame.

MÉTHODES

$widget->widgetClass(Name=>nom, -class=>classe);
Identifie un nouveau widget avec nom et/ou classe. Name spécifie l'élément de chemin pour le widget ; les noms commencent généralement par une lettre minuscule. -class spécifie la classe du widget et de ses enfants ; les classes commencent généralement par une lettre majuscule. Si elles ne sont pas spécifiées, Perl/Tk attribuera un nom par défaut unique à chaque widget. Seuls les widgets MainWindow ont une classe par défaut, créée en mettant en majuscule la première lettre du nom de l'application.
$widget->PathName;
La méthode PathName renvoie le nom de chemin du widget, qui identifie de manière unique le widget au sein de l'application.
$widget->optionAdd(motif=>valeur ?, priorité?);
La méthode optionAdd ajoute une nouvelle option à la base de données. Motif contient l'option spécifiée et se compose de noms et/ou de classes séparés par des astérisques ou des points, dans le format X habituel. Valeur contient une chaîne de caractères à associer à motif ; c'est la valeur qui sera renvoyée lors des appels à la méthode optionGet. Si priorité est spécifiée, elle indique le niveau de priorité pour cette option (voir ci-dessous pour les valeurs légales) ; elle vaut par défaut interactive. Cette méthode renvoie toujours une chaîne vide.
$widget->optionClear;
La méthode optionClear efface la base de données d'options. Les options par défaut (provenant de la propriété RESOURCE_MANAGER ou du fichier .Xdefaults) seront rechargées automatiquement la prochaine fois qu'une option sera ajoutée ou supprimée de la base de données. Cette méthode renvoie toujours une chaîne vide.
$widget->optionGet(nom,classe);
La méthode optionGet renvoie la valeur de l'option spécifiée pour $widget sous nom et classe. Pour rechercher l'option, optionGet compare les motifs de la base de données de ressources au nom de chemin de $widget ainsi qu'à la classe de $widget (ou à celle de son parent si $widget n'a pas de classe spécifiée). La classe et le nom du widget sont des options définies lors de la création du widget (sans rapport avec la classe au sens de bless) ; le nom de la MainWindow est l'appname et sa classe est (par défaut) dérivée du nom du script.

Si plusieurs entrées dans la base de données d'options correspondent au nom de chemin, au nom et à la classe de $widget, alors la méthode renvoie celle qui a été créée avec le niveau de priorité le plus élevé. S'il y a plusieurs entrées correspondantes au même niveau de priorité, alors elle renvoie l'entrée qui a été insérée le plus récemment dans la base de données d'options. S'il n'y a pas d'entrées correspondantes, alors la chaîne vide est renvoyée.

$widget->optionReadfile(nomFichier?,priorité?);
La méthode optionReadfile lit nomFichier, qui doit avoir le format standard d'une base de données de ressources X telle que .Xdefaults, et ajoute toutes les options spécifiées dans ce fichier à la base de données d'options. Si priorité est spécifiée, elle indique le niveau de priorité auquel entrer les options ; priorité vaut par défaut interactive.

Les arguments priorité aux méthodes option sont normalement spécifiés symboliquement en utilisant l'une des valeurs suivantes :

widgetDefault
Niveau 20. Utilisé pour les valeurs par défaut codées en dur dans les widgets.

NAME

Tk::option - Prioritize Tk options

SYNOPSIS

    use Tk::option;

DESCRIPTION

The Tk widget database provides a mechanism for associating option name-value pairs with widgets. The database is a hierarchical structure, and option lookups involve searching a hierarchy of resources. This module provides keywords to help you specify the priority of options as they are retrieved from the database.

When an option is specified in multiple places, Tk uses a priority scheme to determine which value to use. The higher the priority level, the more important the option specification. The following keywords are available:

startupFile
Niveau 40. Utilisé pour les options spécifiées dans les fichiers de démarrage spécifiques à l'application.
userDefault
Niveau 60. Utilisé pour les options spécifiées dans les fichiers de configuration spécifiques à l'utilisateur, tels que .Xdefaults, les bases de données de ressources chargées dans le serveur X, ou les fichiers de démarrage spécifiques à l'utilisateur.
interactive
Niveau 80. Utilisé pour les options spécifiées de manière interactive après le démarrage de l'application. Si priority n'est pas spécifiée, elle est par défaut à ce niveau.

N'importe lequel des mots-clés ci-dessus peut être abrégé. De plus, les priorités peuvent être spécifiées numériquement en utilisant des entiers entre 0 et 100, inclus. La forme numérique est probablement une mauvaise idée, sauf pour les nouveaux niveaux de priorité autres que ceux donnés ci-dessus.

BUGS

Le schéma de priorité utilisé par Tk de base n'est pas le même que celui utilisé par les routines Xlib normales. En particulier, il suppose que l'ordre des entrées est défini, mais des commandes utilisateur telles que xrdb -merge peuvent modifier l'ordre.
