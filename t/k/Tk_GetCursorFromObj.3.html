NOM

Tk_AllocCursorFromObj, Tk_GetCursor, Tk_GetCursorFromObj, Tk_GetCursorFromData, Tk_NameOfCursor, Tk_FreeCursorFromObj, Tk_FreeCursor - gérer la base de données des curseurs

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur à utiliser pour le rapport d'erreurs.
Tk_Window tkwin (in)
Jeton de la fenêtre dans laquelle le curseur sera utilisé.
Tcl_Obj *objPtr (in/out)
Description du curseur ; voir ci-dessous pour les valeurs possibles. La représentation interne sera modifiée pour mettre en cache le pointeur vers le Tk_Cursor correspondant.
const char *name (in)
Identique à objPtr, sauf que la description du curseur est passée sous forme de chaîne de caractères et que le Tk_Cursor résultant n'est pas mis en cache.
const char *source (in)
Données du curseur source, au format curseur standard.
const char *mask (in)
Données du masque du curseur, au format curseur standard.
int width (in)
Largeur de source et mask.
int height (in)
Hauteur de source et mask.
int xHot (in)
Position X du point chaud du curseur.
int yHot (in)
Position Y du point chaud du curseur.
Tk_Uid fg (in)
Description textuelle de la couleur de premier plan du curseur.
Tk_Uid bg (in)
Description textuelle de la couleur d'arrière-plan du curseur.
Display *display (in)
Affichage pour lequel cursor a été alloué.
Tk_Cursor cursor (in)
Identifiant Tk opaque pour le curseur. S'il est passé à Tk_FreeCursor, il doit avoir été retourné par un appel précédent à Tk_GetCursor ou Tk_GetCursorFromData.

DESCRIPTION

Ces procédures gèrent une collection de curseurs utilisés par une application. Les procédures permettent la réutilisation efficace des curseurs, évitant ainsi la surcharge du serveur, et permettent également de nommer les curseurs avec des chaînes de caractères.

Tk_AllocCursorFromObj prend en argument un objet décrivant un curseur, et renvoie un identifiant Tk opaque pour un curseur correspondant à la description. Il réutilise un curseur existant si possible et en crée un nouveau sinon. Tk_AllocCursorFromObj met en cache les informations sur la valeur de retour dans objPtr, ce qui accélère les appels futurs aux procédures telles que Tk_AllocCursorFromObj et Tk_GetCursorFromObj. Si une erreur se produit lors de la création du curseur, par exemple lorsque objPtr fait référence à un fichier inexistant, alors None est retourné et un message d'erreur sera stocké dans le résultat de interp si interp n'est pas NULL. ObjPtr doit contenir une liste Tcl standard avec l'une des formes suivantes :

nom [couleurFg [couleurBg]]
Nom est le nom d'un curseur au format curseur standard X, c'est-à-dire l'un des noms définis dans cursorcursor.h, sans le préfixe XC_. Quelques exemples de valeurs sont X_cursor, hand2, ou left_ptr. L'Annexe B de “The X Window System” par Scheifler & Gettys contient des illustrations montrant à quoi ressemble chacun de ces curseurs. Si couleurFg et couleurBg sont tous deux spécifiés, ils donnent les couleurs de premier plan et d'arrière-plan à utiliser pour le curseur (toute forme acceptable par Tk_GetColor peut être utilisée). Si seule couleurFg est spécifiée, alors il n'y aura pas de couleur d'arrière-plan : l'arrière-plan sera transparent. Si aucune couleur n'est spécifiée, le curseur utilisera le noir pour sa couleur de premier plan et le blanc pour sa couleur d'arrière-plan.

La version Macintosh de Tk prend en charge tous les curseurs X et acceptera également tous les curseurs Mac standard, y compris ibeam, crosshair, watch, plus, et arrow. De plus, Tk chargera les ressources de curseurs Macintosh des types crsr (couleur) et CURS (noir et blanc) par le nom de la ressource. L'application et tous les fichiers de ressources de ses bibliothèques dynamiques ouvertes seront recherchés pour le curseur nommé. En cas de conflits, les curseurs couleur seront toujours chargés de préférence aux curseurs noir et blanc.

@nomSource nomMasque couleurFg couleurBg
Dans cette forme, nomSource et nomMasque sont les noms de fichiers décrivant les curseurs pour les bits source et le masque du curseur. Chaque fichier doit être au format curseur standard X11. CouleurFg et couleurBg indiquent les couleurs à utiliser pour le curseur, sous toutes les formes acceptables par Tk_GetColor. Cette forme de la commande ne fonctionnera pas sur Macintosh ou Windows.
@nomSource couleurFg
Cette forme est similaire à la précédente, à la différence que la source est également utilisée comme masque. Cela signifie que l'arrière-plan du curseur est transparent. Cette forme de la commande ne fonctionnera pas sur Macintosh ou Windows.
@nomSource
Cette forme ne fonctionne que sous Windows et chargera un curseur système Windows (.ani ou .cur) à partir du fichier spécifié dans nomSource.

Tk_GetCursor est identique à Tk_AllocCursorFromObj, sauf que la description du curseur est spécifiée avec une chaîne de caractères au lieu d'un objet. Cela empêche Tk_GetCursor de mettre en cache la valeur de retour, Tk_GetCursor est donc moins efficace que Tk_AllocCursorFromObj.

Tk_GetCursorFromObj renvoie le jeton d'un curseur existant, étant donné la fenêtre et la description utilisées pour créer le curseur. Tk_GetCursorFromObj ne crée pas réellement le curseur ; le curseur doit déjà avoir été créé par un appel précédent à Tk_AllocCursorFromObj ou Tk_GetCursor. La valeur de retour est mise en cache dans objPtr, ce qui accélère les appels futurs à Tk_GetCursorFromObj avec le même objPtr et tkwin.

Tk_GetCursorFromData permet de créer des curseurs à partir de descriptions en mémoire de leurs curseurs source et masque. Source pointe vers les données de curseur standard pour les bits source du curseur, et mask pointe vers les données de curseur standard décrivant quels pixels de source doivent être dessinés et lesquels doivent être considérés comme transparents. Width et height donnent les dimensions du curseur, xHot et yHot indiquent l'emplacement du point chaud du curseur (le point qui est rapporté lorsqu'un événement se produit), et fg et bg décrivent les couleurs du premier plan et de l'arrière-plan du curseur textuellement (toutes les formes appropriées pour Tk_GetColor peuvent être utilisées). Typiquement, les arguments de Tk_GetCursorFromData sont créés en incluant un fichier curseur directement dans le code source d'un programme, comme dans l'exemple suivant :

Tk_Cursor curseur;
#include "source.cursor"
#include "mask.cursor"
curseur = Tk_GetCursorFromData(interp, tkwin, source_bits,
    mask_bits, source_width, source_height, source_x_hot,
    source_y_hot, Tk_GetUid("red"), Tk_GetUid("blue"));

Dans des conditions normales, Tk_GetCursorFromData renverra un identifiant pour le curseur demandé. Si une erreur se produit lors de la création du curseur, alors None est retourné et un message d'erreur sera stocké dans le résultat de interp.

Tk_AllocCursorFromObj, Tk_GetCursor, et Tk_GetCursorFromData maintiennent une base de données de tous les curseurs qu'ils ont créés. Chaque fois que possible, un appel à Tk_AllocCursorFromObj, Tk_GetCursor, ou Tk_GetCursorFromData renverra un curseur existant plutôt qu'un nouveau. Cette approche peut réduire considérablement la surcharge du serveur, donc les procédures Tk devraient généralement être préférées aux procédures Xlib comme XCreateFontCursor ou XCreatePixmapCursor, qui créent un nouveau curseur à chaque appel. Les procédures Tk sont également plus portables que les procédures de plus bas niveau X.

Notez que la chaîne renvoyée par Tk_NameOfCursor n'est garantie que jusqu'au prochain appel à Tk_NameOfCursor. Lorsqu'un curseur renvoyé par Tk_AllocCursorFromObj, Tk_GetCursor ou Tk_GetCursorFromData n'est plus nécessaire, Tk_FreeCursorFromObj ou Tk_FreeCursor doit être appelé pour le libérer. Pour Tk_FreeCursorFromObj, le curseur à libérer est spécifié avec les mêmes informations utilisées pour le créer ; pour Tk_FreeCursor, le curseur à libérer est spécifié avec son jeton Tk_Cursor. Il doit y avoir exactement un appel à Tk_FreeCursor pour chaque appel à Tk_AllocCursorFromObj, Tk_GetCursor ou Tk_GetCursorFromData.

BUGS

Pour déterminer si un curseur existant peut être utilisé pour satisfaire une nouvelle demande, Tk_AllocCursorFromObj, Tk_GetCursor et Tk_GetCursorFromData ne considèrent que les valeurs immédiates de leurs arguments. Par exemple, lorsqu'un nom de fichier est passé à Tk_GetCursor, Tk_GetCursor supposera qu'il est sûr de réutiliser un curseur existant créé à partir du même nom de fichier : il ne vérifiera pas si le fichier lui-même a changé, ni si le répertoire courant a changé, faisant ainsi que le nom fasse référence à un fichier différent. De même, Tk_GetCursorFromData suppose que si le même pointeur *source* est utilisé dans deux appels différents, alors les pointeurs font référence aux mêmes données ; il ne vérifie pas si les valeurs de données réelles ont changé.
