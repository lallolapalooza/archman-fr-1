Tk_AllocBitmapFromObj(3) Procédures de la bibliothèque Tk Tk_AllocBitmapFromObj(3)

NOM

Tk_AllocBitmapFromObj, Tk_GetBitmap, Tk_GetBitmapFromObj, Tk_DefineBitmap, Tk_NameOfBitmap, Tk_SizeOfBitmap, Tk_FreeBitmapFromObj, Tk_FreeBitmap - maintenir la base de données de pixmaps à un seul plan

SYNOPIS

#include <tk.h>

Pixmap
Tk_AllocBitmapFromObj(interp, tkwin, objPtr)

Pixmap
Tk_GetBitmap(interp, tkwin, info)

Pixmap
Tk_GetBitmapFromObj(tkwin, objPtr)

int
Tk_DefineBitmap(interp, name, source, width, height)

const char *
Tk_NameOfBitmap(display, bitmap)

Tk_SizeOfBitmap(display, bitmap, widthPtr, heightPtr)

Tk_FreeBitmapFromObj(tkwin, objPtr)

Tk_FreeBitmap(display, bitmap)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur à utiliser pour signaler les erreurs ; si NULL, aucun message d'erreur n'est laissé après les erreurs.
Tk_Window tkwin (in)
Jeton de la fenêtre dans laquelle la bitmap sera utilisée.
Tcl_Obj *objPtr (in/out)
La valeur de type chaîne décrit la bitmap souhaitée ; la représentation interne sera modifiée pour mettre en cache le pointeur vers la Pixmap correspondante.
const char *info (in)
Identique à objPtr, sauf que la description de la bitmap est transmise sous forme de chaîne et que la Pixmap résultante n'est pas mise en cache.
const char *name (in)
Nom de la nouvelle bitmap à définir.
const void *source (in)
Données de la bitmap, au format bitmap standard. Doit être stocké dans une mémoire statique dont la valeur ne changera jamais.
int width (in)
Largeur de la bitmap.
int height (in)
Hauteur de la bitmap.
int *widthPtr (out)
Pointeur vers un mot à remplir avec la largeur de bitmap.
int *heightPtr (out)
Pointeur vers un mot à remplir avec la hauteur de bitmap.
Display *display (in)
Affichage pour lequel bitmap a été allouée.
Pixmap bitmap (in)
Identifiant d'une bitmap allouée par Tk_AllocBitmapFromObj ou Tk_GetBitmap.

DESCRIPTION

Ces procédures gèrent une collection de bitmaps (pixmaps à un seul plan) utilisées par une application. Les procédures permettent de réutiliser les bitmaps efficacement, évitant ainsi les surcoûts du serveur, et permettent également de nommer les bitmaps avec des chaînes de caractères.

Tk_AllocBitmapFromObj retourne un identifiant Pixmap pour une bitmap qui correspond à la description dans objPtr et qui est adaptée à une utilisation dans tkwin. Elle réutilise une bitmap existante, si possible, et en crée une nouvelle sinon. La valeur de objPtr doit avoir l'une des formes suivantes :

@fileName
FileName doit être le nom d'un fichier contenant une description de bitmap au format X11 standard.
name
Name doit être le nom d'une bitmap définie précédemment avec un appel à Tk_DefineBitmap. Les noms suivants sont prédéfinis par Tk :
error
Le symbole international “interdit” : un cercle avec une ligne diagonale le traversant.
gray75
Gris 75% : un motif en damier où trois bits sur quatre sont activés.
gray50
Gris 50% : un motif en damier où un bit sur deux est activé.
gray25
Gris 25% : un motif en damier où un bit sur quatre est activé.
gray12
Gris 12.5% : un motif où un huitième des bits sont activés, composé d'un pixel sur quatre dans une ligne sur deux.
hourglass
Un symbole de sablier.
info
Une grande lettre “i”.
questhead
La silhouette d'une tête humaine, avec un point d'interrogation dedans.
question
Un grand point d'interrogation.
warning
Un grand point d'exclamation.

En outre, les noms prédéfinis suivants sont disponibles uniquement sur la plateforme Macintosh :

document
Un document générique.
stationery
Papier à lettre pour document.
edition
Le symbole d'édition.
application
Icône générique d'application.
accessory
Un accessoire de bureau.
folder
Icône générique de dossier.
pfolder
Un dossier verrouillé.
trash
Une poubelle.
floppy
Une disquette.
ramdisk
Une disquette avec une puce.
cdrom
Une icône de disque CD.
preferences
Un dossier avec un symbole de préférences.
querydoc
Une icône de document de base de données.
stop
Un panneau stop.
note
Un visage avec des bulles de dialogue.
caution
Un triangle avec un point d'exclamation.

Dans des conditions normales, Tk_AllocBitmapFromObj retourne un identifiant pour la bitmap demandée. Si une erreur survient lors de la création de la bitmap, par exemple lorsque objPtr fait référence à un fichier inexistant, alors None est retourné et un message d'erreur est laissé dans le résultat de interp si interp n'est pas NULL. Tk_AllocBitmapFromObj met en cache les informations sur la valeur de retour dans objPtr, ce qui accélère les appels futurs à des procédures telles que Tk_AllocBitmapFromObj et Tk_GetBitmapFromObj.

Tk_GetBitmap est identique à Tk_AllocBitmapFromObj, sauf que la description de la bitmap est spécifiée avec une chaîne au lieu d'un objet. Cela empêche Tk_GetBitmap de mettre en cache la valeur de retour, donc Tk_GetBitmap est moins efficace que Tk_AllocBitmapFromObj.

Tk_GetBitmapFromObj retourne le jeton d'une bitmap existante, étant donné la fenêtre et la description utilisées pour créer la bitmap. Tk_GetBitmapFromObj ne crée pas réellement la bitmap ; la bitmap doit avoir été créée précédemment par un appel à Tk_AllocBitmapFromObj ou Tk_GetBitmap. La valeur de retour est mise en cache dans objPtr, ce qui accélère les appels futurs à Tk_GetBitmapFromObj avec le même objPtr et tkwin.

Tk_DefineBitmap associe un nom à des données de bitmap en mémoire afin que le nom puisse être utilisé dans des appels ultérieurs à Tk_AllocBitmapFromObj ou Tk_GetBitmap. L'argument nameId donne un nom à la bitmap ; il ne doit pas avoir été utilisé précédemment dans un appel à Tk_DefineBitmap. Les arguments source, width, et height décrivent la bitmap. Tk_DefineBitmap retourne normalement TCL_OK ; si une erreur survient (par exemple, une bitmap nommée nameId a déjà été définie), alors TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de l'interpréteur interp. Note : Tk_DefineBitmap s'attend à ce que la mémoire pointée par source soit statique : Tk_DefineBitmap ne fait pas de copie privée de cette mémoire, mais utilise les octets pointés par source plus tard dans les appels à Tk_AllocBitmapFromObj ou Tk_GetBitmap.

Généralement, Tk_DefineBitmap est utilisée en incluant directement un fichier de bitmap dans un programme C et en faisant ensuite référence aux variables définies par le fichier. Par exemple, supposons qu'il existe un fichier stip.bitmap, qui était

Pixmap bitmap ;
#include "stip.bitmap"
Tk_DefineBitmap(interp, "foo", stip_bits,
    stip_width, stip_height) ;
...
bitmap = Tk_GetBitmap(interp, tkwin, "foo") ;
Ce code lit le fichier bitmap au moment de la compilation et intègre les informations du bitmap dans l'image exécutable du programme. Le même fichier bitmap pourrait être lu au moment de l'exécution en utilisant Tk_GetBitmap : 
Pixmap bitmap ;
bitmap = Tk_GetBitmap(interp, tkwin, "@stip.bitmap") ;
La seconde forme est un peu plus flexible (le fichier pourrait être modifié après la compilation du programme, ou une chaîne différente pourrait être fournie pour lire un fichier différent), mais elle est un peu plus lente et nécessite que le fichier bitmap existe séparément du programme.

Tk maintient une base de données de tous les bitmaps actuellement en cours d'utilisation. Dans la mesure du possible, il renverra un bitmap existant plutôt que d'en créer un nouveau. Lorsqu'un bitmap n'est plus utilisé, Tk le libérera automatiquement. Cette approche peut réduire considérablement la surcharge du serveur, de sorte que Tk_AllocBitmapFromObj et Tk_GetBitmap doivent généralement être préférés aux procédures Xlib comme XReadBitmapFile.

Les bitmaps renvoyés par Tk_AllocBitmapFromObj et Tk_GetBitmap sont partagés, de sorte que les appelants ne doivent jamais les modifier. Si un bitmap doit être modifié dynamiquement, il doit alors être créé en appelant directement des procédures Xlib telles que XReadBitmapFile ou XCreatePixmap.

La procédure Tk_NameOfBitmap est approximativement l'inverse de Tk_GetBitmap. Étant donné un argument X Pixmap, elle renvoie la description textuelle qui a été passée à Tk_GetBitmap lors de la création du bitmap. Bitmap doit avoir été la valeur de retour d'un appel précédent à Tk_AllocBitmapFromObj ou Tk_GetBitmap.

Tk_SizeOfBitmap renvoie les dimensions de son argument bitmap dans les mots pointés par les arguments widthPtr et heightPtr. Comme avec Tk_NameOfBitmap, bitmap doit avoir été créé par Tk_AllocBitmapFromObj ou Tk_GetBitmap.

Lorsqu'un bitmap n'est plus nécessaire, Tk_FreeBitmapFromObj ou Tk_FreeBitmap doit être appelé pour le libérer. Pour Tk_FreeBitmapFromObj, le bitmap à libérer est spécifié avec les mêmes informations utilisées pour le créer ; pour Tk_FreeBitmap, le bitmap à libérer est spécifié avec son jeton Pixmap. Il doit y avoir exactement un appel à Tk_FreeBitmapFromObj ou Tk_FreeBitmap pour chaque appel à Tk_AllocBitmapFromObj ou Tk_GetBitmap.

BUGS

Lorsqu'il détermine si un bitmap existant peut être utilisé pour satisfaire une nouvelle demande, Tk_AllocBitmapFromObj et Tk_GetBitmap ne prennent en compte que la valeur immédiate de la description textuelle. Par exemple, lorsqu'un nom de fichier est passé à Tk_GetBitmap, Tk_GetBitmap supposera qu'il est sûr de réutiliser un bitmap existant créé à partir du même nom de fichier : il ne vérifiera pas si le fichier lui-même a changé, ou si le répertoire courant a changé, amenant ainsi le nom à faire référence à un fichier différent.
