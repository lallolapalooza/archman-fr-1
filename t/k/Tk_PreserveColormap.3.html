Tk_GetColormap(3) Procédures de la bibliothèque Tk Tk_GetColormap(3)

NOM

Tk_GetColormap, Tk_PreserveColormap, Tk_FreeColormap - allouer et libérer des palettes de couleurs

SYNOPSIS

#include <tk.h>

Colormap
Tk_GetColormap(interp, tkwin, string)

Tk_PreserveColormap(display, colormap)

Tk_FreeColormap(display, colormap)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur à utiliser pour signaler les erreurs.
Tk_Window tkwin (entrée)
Jeton pour la fenêtre dans laquelle la palette de couleurs sera utilisée.
const char *string (entrée)
Sélectionne une palette de couleurs : soit new soit le nom d'une fenêtre ayant le même écran et la même visualisation que tkwin.
Display *display (entrée)
Affichage pour lequel colormap a été allouée.
Colormap colormap (entrée)
Palette de couleurs à libérer ou préserver ; doit avoir été retournée par un appel précédent à Tk_GetColormap ou Tk_GetVisual.

DESCRIPTION

Ces procédures sont utilisées pour gérer les palettes de couleurs. Tk_GetColormap retourne une palette de couleurs adaptée à une utilisation dans tkwin. Si son argument string est new, une nouvelle palette de couleurs est créée ; sinon, string doit être le nom d'une autre fenêtre ayant le même écran et la même visualisation que tkwin, et la palette de couleurs de cette fenêtre est retournée. Si string n'est pas compréhensible, ou s'il fait référence à une fenêtre sur un écran différent de tkwin ou avec une visualisation différente de tkwin, alors Tk_GetColormap retourne None et laisse un message d'erreur dans le résultat de interp.

Tk_PreserveColormap augmente le compteur de références interne d'une palette de couleurs précédemment retournée par Tk_GetColormap, ce qui permet de stocker la palette de couleurs dans plusieurs emplacements sans connaître l'ordre dans lequel ils seront libérés.

Tk_FreeColormap doit être appelée lorsqu'une palette de couleurs retournée par Tk_GetColormap n'est plus nécessaire. Tk maintient un compteur de références pour chaque palette de couleurs retournée par Tk_GetColormap, il doit donc y avoir finalement un appel à Tk_FreeColormap pour chaque appel à Tk_GetColormap et chaque appel à Tk_PreserveColormap. Lorsque le compteur de références d'une palette de couleurs devient zéro, Tk libère la palette de couleurs X.

Tk_GetVisual et Tk_GetColormap fonctionnent ensemble, en ce sens qu'une nouvelle palette de couleurs créée par Tk_GetVisual peut plus tard être retournée par Tk_GetColormap. Le mécanisme de comptage de références pour les palettes de couleurs inclut les deux procédures, donc les appelants de Tk_GetVisual doivent également appeler Tk_FreeColormap pour libérer la palette de couleurs. Si Tk_GetColormap est appelée avec une valeur de string de new, la palette de couleurs résultante ne sera jamais retournée par Tk_GetVisual ; cependant, elle peut être utilisée dans d'autres fenêtres en appelant Tk_GetColormap avec le nom de la fenêtre d'origine comme string.
