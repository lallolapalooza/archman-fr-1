NOM

Tk::callbacks - Spécifier du code pour que Tk l'appelle.

SYNTAXE

On peut spécifier un callback de l'une des manières suivantes :

Sans arguments :

... => \&nom_sous_routine, ...
... => sub { ... }, ...
... => 'nom_methode', ...

ou avec arguments :

... => [ \&nom_sous_routine, args ... ], ...
... => [ sub { ... }, args... ], ...
... => [ 'nom_methode', args... ], ...

DESCRIPTION

Perl/Tk a un callback, là où Tcl/Tk a une chaîne de commande (c'est-à-dire un fragment de Tcl à exécuter). Un callback perl/Tk peut prendre l'une des formes de base suivantes :

  • Référence à une sous-routine "\&nom_sous_routine"
  • Sous-routine anonyme (fermeture) "sub { ... }"
  • Un nom de méthode 'nom_methode'

N'importe laquelle de celles-ci peut être fournie avec des arguments en les encapsulant, ainsi que les arguments, dans []. Voici quelques exemples :

$mw->bind($classe, "<Delete>" => 'Delete');

Cela appellera $widget->Delete, le $widget étant fourni (par bind) comme celui sur lequel la touche Suppr a été pressée.

Bien qu'il soit idéal dans de nombreux cas que bind fournisse un objet widget, cela peut être irritant dans d'autres. En utilisant la forme liste, ce comportement peut être modifié :

$a->bind("<Delete>",[$b => 'Delete']);

car le premier élément $b est un objet, bind appellera $b->Delete.

Notez que l'ordre méthode/objet n'a d'importance que pour les callbacks "bind", le cytage automatique dans perl5.001 rend le premier de ceux-ci un peu plus lisible :

$w->configure(-yscrollcommand => [ set => $ysb]);
$w->configure(-yscrollcommand => [ $ysb => 'set' ]);

mais les deux appelleront $ysb->set(arguments fournis par Tk)

Une autre utilisation des arguments permet d'écrire des méthodes généralisées plus faciles à réutiliser :

$a->bind("<Next>",['Next','Page']);
$a->bind("<Down>",['Next','Line']);

Cela appellera $a->Next('Page') ou $a->Next('Line') respectivement.

Notez que le contenu de "[]" est évalué par perl lors de la création du callback. Il est souvent souhaitable que les arguments fournis au callback dépendent des détails de l'événement qui l'a déclenché. Pour permettre cela, les callbacks peuvent être imbriqués en utilisant le "constructeur" Ev(...). Ev(...) insère des objets callback dans la liste d'arguments. Lorsque le code de liaison perl/Tk prépare la liste d'arguments pour le callback qu'il est sur le point d'appeler, il repère ces objets spéciaux et leur applique récursivement le processus de callback.

EXEMPLES

$entry->bind('<Return>' => [$w , 'validate', Ev(['get'])]);
$toplevel->bind('all', '<Visibility>', [\&unobscure, Ev('s')]);
$mw->bind($class, '<Down>', ['SetCursor', Ev('UpDownLine',1)]);
