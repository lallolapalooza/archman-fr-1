NOM

Tk_AllocBitmapFromObj, Tk_GetBitmap, Tk_GetBitmapFromObj, Tk_DefineBitmap, Tk_NameOfBitmap, Tk_SizeOfBitmap, Tk_FreeBitmapFromObj, Tk_FreeBitmap - maintenir une base de données de pixmaps à plan unique

SYNTAXE

#include <tk.h>

Pixmap
Tk_AllocBitmapFromObj(interp, tkwin, objPtr)

Pixmap
Tk_GetBitmap(interp, tkwin, info)

Pixmap
Tk_GetBitmapFromObj(tkwin, objPtr)

int
Tk_DefineBitmap(interp, name, source, width, height)

const char *
Tk_NameOfBitmap(display, bitmap)

Tk_SizeOfBitmap(display, bitmap, widthPtr, heightPtr)

Tk_FreeBitmapFromObj(tkwin, objPtr)

Tk_FreeBitmap(display, bitmap)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur à utiliser pour signaler les erreurs ; si NULL alors aucun message d'erreur n'est laissé après les erreurs.
Tk_Window tkwin (entrée)
Jeton pour la fenêtre dans laquelle le bitmap sera utilisé.
Tcl_Obj *objPtr (entrée/sortie)
La valeur de chaîne décrit le bitmap souhaité ; la représentation interne sera modifiée pour mettre en cache le pointeur vers le Pixmap correspondant.
const char *info (entrée)
Identique à objPtr sauf que la description du bitmap est passée sous forme de chaîne et le Pixmap résultant n'est pas mis en cache.
const char *name (entrée)
Nom du nouveau bitmap à définir.
const void *source (entrée)
Données du bitmap, au format bitmap standard. Doit être stocké dans une mémoire statique dont la valeur ne changera jamais.
int width (entrée)
Largeur du bitmap.
int height (entrée)
Hauteur du bitmap.
int *widthPtr (sortie)
Pointeur vers un mot à remplir avec la largeur du bitmap.
int *heightPtr (sortie)
Pointeur vers un mot à remplir avec la hauteur du bitmap.
Display *display (entrée)
Affichage pour lequel le bitmap a été alloué.
Pixmap bitmap (entrée)
Identifiant d'un bitmap alloué par Tk_AllocBitmapFromObj ou Tk_GetBitmap.

DESCRIPTION

Ces procédures gèrent une collection de bitmaps (pixmaps à un plan) utilisés par une application. Les procédures permettent de réutiliser efficacement les bitmaps, évitant ainsi la surcharge du serveur, et permettent également de nommer les bitmaps avec des chaînes de caractères.

Tk_AllocBitmapFromObj renvoie un identifiant Pixmap pour un bitmap qui correspond à la description dans objPtr et qui est approprié pour être utilisé dans tkwin. Il réutilise un bitmap existant, si possible, et en crée un nouveau sinon. La valeur de objPtr doit avoir l'une des formes suivantes :

@fileName
FileName doit être le nom d'un fichier contenant une description de bitmap au format X11 standard.
nom
Nom doit être le nom d'un bitmap défini précédemment avec un appel à Tk_DefineBitmap. Les noms suivants sont prédéfinis par Tk :
erreur
Le symbole international "interdit" : un cercle avec une ligne diagonale le traversant.
gray75
Gris 75% : un motif en damier où trois bits sur quatre sont activés.
gray50
Gris 50% : un motif en damier où un bit sur deux est activé.
gray25
Gris 25% : un motif en damier où un bit sur quatre est activé.
gray12
Gris 12.5% : un motif où un huitième des bits est activé, consistant en un pixel sur quatre dans une ligne sur deux.
hourglass
Un symbole de sablier.
info
Une grande lettre "i".
questhead
La silhouette d'une tête humaine, avec un point d'interrogation dedans.
question
Un grand point d'interrogation.
warning
Un grand point d'exclamation.

De plus, les noms prédéfinis suivants sont disponibles uniquement sur la plateforme Macintosh :

document
Un document générique.
stationery
Papier à lettre de document.
edition
Le symbole de l'édition.
application
Icône d'application générique.
accessory
Un accessoire de bureau.
folder
Icône de dossier générique.
pfolder
Un dossier verrouillé.
trash
Une poubelle.
floppy
Une disquette.
ramdisk
Une disquette avec une puce.
cdrom
Une icône de disque CD.
preferences
Un dossier avec le symbole des préférences.
querydoc
Une icône de document de base de données.
stop
Un panneau stop.
note
Un visage avec des bulles de paroles.
caution
Un triangle avec un point d'exclamation.

Dans des conditions normales, Tk_AllocBitmapFromObj renvoie un identifiant pour le bitmap demandé. Si une erreur survient lors de la création du bitmap, par exemple lorsque objPtr fait référence à un fichier inexistant, alors None est renvoyé et un message d'erreur est laissé dans le résultat de interp si interp n'est pas NULL. Tk_AllocBitmapFromObj met en cache les informations sur la valeur de retour dans objPtr, ce qui accélère les appels futurs à des procédures telles que Tk_AllocBitmapFromObj et Tk_GetBitmapFromObj.

Tk_GetBitmap est identique à Tk_AllocBitmapFromObj sauf que la description du bitmap est spécifiée avec une chaîne au lieu d'un objet. Cela empêche Tk_GetBitmap de mettre en cache la valeur de retour, donc Tk_GetBitmap est moins efficace que Tk_AllocBitmapFromObj.

Tk_GetBitmapFromObj renvoie le jeton d'un bitmap existant, étant donné la fenêtre et la description utilisées pour créer le bitmap. Tk_GetBitmapFromObj ne crée pas réellement le bitmap ; le bitmap doit avoir déjà été créé par un appel précédent à Tk_AllocBitmapFromObj ou Tk_GetBitmap. La valeur de retour est mise en cache dans objPtr, ce qui accélère les appels futurs à Tk_GetBitmapFromObj avec le même objPtr et tkwin.

Tk_DefineBitmap associe un nom à des données de bitmap en mémoire afin que le nom puisse être utilisé dans des appels ultérieurs à Tk_AllocBitmapFromObj ou Tk_GetBitmap. L'argument nameId donne un nom au bitmap ; il ne doit pas avoir été utilisé précédemment dans un appel à Tk_DefineBitmap. Les arguments source, width et height décrivent le bitmap. Tk_DefineBitmap renvoie normalement TCL_OK ; si une erreur se produit (par exemple, un bitmap nommé nameId a déjà été défini) alors TCL_ERROR est renvoyé et un message d'erreur est laissé dans le résultat de l'interpréteur interp. Remarque : Tk_DefineBitmap s'attend à ce que la mémoire pointée par source soit statique : Tk_DefineBitmap ne fait pas de copie privée de cette mémoire, mais utilise les octets pointés par source ultérieurement dans les appels à Tk_AllocBitmapFromObj ou Tk_GetBitmap.

Tk_GetBitmap(3) - Tk Manual

NAME

Tk_GetBitmap, Tk_AllocBitmapFromObj, Tk_FreeBitmap, Tk_FreeBitmapFromObj, Tk_NameOfBitmap, Tk_SizeOfBitmap - retrieve information about bitmaps

SYNOPSIS

#include <tk.h>

Tk_GetBitmap(interp, tkwin, name);
Tk_AllocBitmapFromObj(interp, tkwin, value);
Tk_FreeBitmap(display, bitmap);
Tk_FreeBitmapFromObj(interp, tkwin, value);
Tk_NameOfBitmap(display, bitmap);
Tk_SizeOfBitmap(display, bitmap, widthPtr, heightPtr);

ARGUMENTS

Tcl_Interp *interp (in) Interpréteur Tcl à utiliser pour les erreurs.

Tk_Window *tkwin (in) Fenêtre associée à l'opération bitmap.

CONST char *name (in) Chaîne spécifiant le bitmap à obtenir.

Tcl_Obj *value (in) Objet Tcl spécifiant le bitmap à obtenir ou à libérer.

Display *display (in) Affichage X pour les opérations bitmap.

Pixmap bitmap (in) Jeton pour le bitmap.

int *widthPtr (out) Pointeur vers un emplacement pour stocker la largeur du bitmap.

int *heightPtr (out) Pointeur vers un emplacement pour stocker la hauteur du bitmap.

DESCRIPTION

Les procédures Tk_GetBitmap et Tk_AllocBitmapFromObj sont utilisées pour obtenir un jeton Pixmap X qui peut être utilisé pour représenter un motif de hachure ou une image bitmap. La procédure Tk_AllocBitmapFromObj est la version plus moderne et orientée objet, et devrait généralement être préférée. Les deux procédures recherchent d'abord dans la base de données interne de Tk une bitmap existante qui correspond à la chaîne de name ou à l'objet value. Si une correspondance est trouvée, le jeton de cette bitmap existante est renvoyé. Sinon, Tk essaie de créer une nouvelle bitmap en fonction de la description de la chaîne ou de l'objet et de l'ajouter à la base de données. Si la création réussit, le jeton de la nouvelle bitmap est renvoyé.

La chaîne name peut spécifier un bitmap de plusieurs manières. Si la chaîne commence par un «@», elle est traitée comme le nom d'un fichier bitmap au format X. Tk lit le fichier bitmap au moment de l'exécution. Si la chaîne ne commence pas par «@», elle est traitée comme le nom d'une bitmap précédemment définie à l'aide de Tk_DefineBitmap. Les définitions de bitmaps via Tk_DefineBitmap sont généralement effectuées en incluant un fichier d'en-tête C généré par le programme bitmap et contiennent un motif de hachure. Le code suivant utilise Tk_DefineBitmap pour définir une nouvelle bitmap nommée foo :

Pixmap bitmap;
#include "stip.bitmap"
Tk_DefineBitmap(interp, "foo", stip_bits,
    stip_width, stip_height);
...
bitmap = Tk_GetBitmap(interp, tkwin, "foo");

Ce code provoque la lecture du fichier bitmap au moment de la compilation et incorpore les informations de la bitmap dans l'image exécutable du programme. Le même fichier bitmap pourrait être lu au moment de l'exécution en utilisant Tk_GetBitmap :

Pixmap bitmap;
bitmap = Tk_GetBitmap(interp, tkwin, "@stip.bitmap");

La deuxième forme est un peu plus flexible (le fichier pourrait être modifié après la compilation du programme, ou une chaîne différente pourrait être fournie pour lire un fichier différent), mais elle est un peu plus lente et nécessite que le fichier bitmap existe séparément du programme.

Tk maintient une base de données de toutes les bitmaps actuellement utilisées. Chaque fois que possible, elle renverra une bitmap existante plutôt qu'en créer une nouvelle. Lorsqu'une bitmap n'est plus utilisée, Tk la libérera automatiquement. Cette approche peut réduire considérablement la surcharge du serveur, de sorte que Tk_AllocBitmapFromObj et Tk_GetBitmap doivent généralement être préférés aux procédures Xlib telles que XReadBitmapFile.

Les bitmaps renvoyées par Tk_AllocBitmapFromObj et Tk_GetBitmap sont partagées, les appelants ne doivent donc jamais les modifier. Si une bitmap doit être modifiée dynamiquement, elle doit être créée en appelant directement des procédures Xlib telles que XReadBitmapFile ou XCreatePixmap.

La procédure Tk_NameOfBitmap est à peu près l'inverse de Tk_GetBitmap. Étant donné un argument X Pixmap, elle renvoie la description textuelle qui a été passée à Tk_GetBitmap lors de la création de la bitmap. Bitmap doit avoir été le résultat d'un appel précédent à Tk_AllocBitmapFromObj ou Tk_GetBitmap.

Tk_SizeOfBitmap renvoie les dimensions de son argument bitmap dans les mots pointés par les arguments widthPtr et heightPtr. Comme avec Tk_NameOfBitmap, bitmap doit avoir été créée par Tk_AllocBitmapFromObj ou Tk_GetBitmap.

Lorsqu'une bitmap n'est plus nécessaire, Tk_FreeBitmapFromObj ou Tk_FreeBitmap doit être appelée pour la libérer. Pour Tk_FreeBitmapFromObj, la bitmap à libérer est spécifiée avec les mêmes informations utilisées pour la créer ; pour Tk_FreeBitmap, la bitmap à libérer est spécifiée avec son jeton Pixmap. Il devrait y avoir exactement un appel à Tk_FreeBitmapFromObj ou Tk_FreeBitmap pour chaque appel à Tk_AllocBitmapFromObj ou Tk_GetBitmap.

BUGS

Pour déterminer si une bitmap existante peut être utilisée pour satisfaire une nouvelle demande, Tk_AllocBitmapFromObj et Tk_GetBitmap ne considèrent que la valeur immédiate de la description textuelle. Par exemple, lorsqu'un nom de fichier est passé à Tk_GetBitmap, Tk_GetBitmap supposera qu'il est sûr de réutiliser une bitmap existante créée à partir du même nom de fichier : elle ne vérifiera pas si le fichier lui-même a changé, ou si le répertoire courant a changé, faisant ainsi référence le nom à un fichier différent.
