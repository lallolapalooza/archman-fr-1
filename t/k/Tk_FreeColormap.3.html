Tk_GetColormap(3) Procédures de la bibliothèque Tk Tk_GetColormap(3)

NOM

Tk_GetColormap, Tk_PreserveColormap, Tk_FreeColormap - allouer et libérer des tables de couleurs

SYNTAXE

#include <tk.h>

Colormap
Tk_GetColormap(interp, tkwin, string)

Tk_PreserveColormap(display, colormap)

Tk_FreeColormap(display, colormap)

ARGUMENTS

Tcl_Interp *interp (en entrée)
Interpréteur à utiliser pour la signalisation d'erreurs.
Tk_Window tkwin (en entrée)
Jeton de la fenêtre dans laquelle la table de couleurs sera utilisée.
const char *string (en entrée)
Sélectionne une table de couleurs : soit new, soit le nom d'une fenêtre ayant le même écran et le même visuel que tkwin.
Display *display (en entrée)
Affichage pour lequel colormap a été alloué.
Colormap colormap (en entrée)
Table de couleurs à libérer ou à préserver ; doit avoir été retournée par un appel précédent à Tk_GetColormap ou Tk_GetVisual.

DESCRIPTION

Ces procédures sont utilisées pour gérer les tables de couleurs. Tk_GetColormap retourne une table de couleurs appropriée pour une utilisation dans tkwin. Si son argument string est new, une nouvelle table de couleurs est créée ; sinon, string doit être le nom d'une autre fenêtre ayant le même écran et le même visuel que tkwin, et la table de couleurs de cette fenêtre est retournée. Si string n'a pas de sens, ou s'il fait référence à une fenêtre sur un écran différent de celui de tkwin ou avec un visuel différent de celui de tkwin, alors Tk_GetColormap retourne None et laisse un message d'erreur dans le résultat de interp.

Tk_PreserveColormap augmente le compteur de références interne d'une table de couleurs précédemment retournée par Tk_GetColormap, ce qui permet de stocker la table de couleurs dans plusieurs emplacements sans avoir à connaître l'ordre dans lequel ils seront libérés.

Tk_FreeColormap doit être appelée lorsqu'une table de couleurs retournée par Tk_GetColormap n'est plus nécessaire. Tk maintient un compteur de références pour chaque table de couleurs retournée par Tk_GetColormap, il doit donc y avoir finalement un appel à Tk_FreeColormap pour chaque appel à Tk_GetColormap et chaque appel à Tk_PreserveColormap. Lorsque le compteur de références d'une table de couleurs devient zéro, Tk libère la table de couleurs X.

Tk_GetVisual et Tk_GetColormap fonctionnent ensemble, en ce sens qu'une nouvelle table de couleurs créée par Tk_GetVisual peut plus tard être retournée par Tk_GetColormap. Le mécanisme de comptage de références pour les tables de couleurs inclut les deux procédures, donc les appelants de Tk_GetVisual doivent également appeler Tk_FreeColormap pour libérer la table de couleurs. Si Tk_GetColormap est appelée avec la valeur de string new, la table de couleurs résultante ne sera jamais retournée par Tk_GetVisual ; cependant, elle peut être utilisée dans d'autres fenêtres en appelant Tk_GetColormap avec le nom de la fenêtre d'origine comme string.
