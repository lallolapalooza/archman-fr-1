Tk_FindPhoto(3) Procédures de la bibliothèque Tk Tk_FindPhoto(3)

NOM

Tk_FindPhoto, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoGetImage, Tk_PhotoBlank, Tk_PhotoExpand, Tk_PhotoGetSize, Tk_PhotoSetSize - manipuler les données d'image stockées dans une image photo.

SYNOPSIS

#include <tk.h>

Tk_PhotoHandle
Tk_FindPhoto(interp, imageName)

int
Tk_PhotoPutBlock(interp, handle, blockPtr, x, y, width, height,compRule)

int
Tk_PhotoPutZoomedBlock(interp, handle, blockPtr, x, y, width, height,zoomX, zoomY, subsampleX, subsampleY, compRule)

int
Tk_PhotoGetImage(handle, blockPtr)

void
Tk_PhotoBlank(handle)

int
Tk_PhotoExpand(interp, handle, width, height)

void
Tk_PhotoGetSize(handle, widthPtr, heightPtr)

int
Tk_PhotoSetSize(interp. handle, width, height)

ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur dans lequel l'image a été créée et dans lequel le rapport d'erreur doit être effectué.
const char *imageName (entrée)
Nom de l'image photo.
Tk_PhotoHandle handle (entrée)
Handle opaque identifiant l'image photo à affecter.
Tk_PhotoImageBlock *blockPtr (entrée)
Spécifie l'adresse et la disposition de stockage des données d'image.
int x (entrée)
Spécifie la coordonnée X où le coin supérieur gauche du bloc doit être placé dans l'image.
int y (entrée)
Spécifie la coordonnée Y où le coin supérieur gauche du bloc doit être placé dans l'image.
int width (entrée)
Spécifie la largeur de la zone d'image à affecter (pour Tk_PhotoPutBlock) ou la largeur d'image désirée (pour Tk_PhotoExpand et Tk_PhotoSetSize).
int compRule (entrée)
Spécifie la règle de composition utilisée lors de la combinaison de pixels transparents dans un bloc de données avec une image photo. Doit être l'une des suivantes : TK_PHOTO_COMPOSITE_OVERLAY (qui place le bloc de données par-dessus l'image photo existante, les contenus précédents étant visibles dans les bits transparents) ou TK_PHOTO_COMPOSITE_SET (qui ignore complètement les contenus précédents de l'image photo dans le rectangle couvert par le bloc de données).
int height (entrée)
Spécifie la hauteur de la zone d'image à affecter (pour Tk_PhotoPutBlock) ou la hauteur d'image désirée (pour Tk_PhotoExpand et Tk_PhotoSetSize).
int *widthPtr (sortie)
Pointeur vers l'emplacement où stocker la largeur de l'image.
int *heightPtr (sortie)
Pointeur vers l'emplacement où stocker la hauteur de l'image.
int subsampleX (entrée)
Spécifie le facteur de sous-échantillonnage dans la direction X pour les données d'image d'entrée.
int subsampleY (entrée)
Spécifie le facteur de sous-échantillonnage dans la direction Y pour les données d'image d'entrée.
int zoomX (entrée)
Spécifie le facteur de zoom à appliquer dans la direction X aux pixels écrits dans l'image photo.
int zoomY (entrée)
Spécifie le facteur de zoom à appliquer dans la direction Y aux pixels écrits dans l'image photo.

DESCRIPTION

Tk_FindPhoto renvoie un handle opaque qui est utilisé pour identifier une image photo particulière aux autres procédures. Le paramètre est le nom de l'image, c'est-à-dire le nom spécifié à la commande image create photo, ou assigné par cette commande si aucun nom n'a été spécifié. Si imageName n'existe pas ou n'est pas une image photo, Tk_FindPhoto renvoie NULL.

Tk_PhotoPutBlock est utilisé pour fournir des blocs de données d'image à afficher. L'appel affecte une zone de l'image de taille width x height pixels, dont le coin supérieur gauche est aux coordonnées (x,y). Tous les paramètres width, height, x, et y doivent être non négatifs. Si une partie de cette zone se trouve en dehors des limites actuelles de l'image, l'image sera agrandie pour inclure la zone, sauf si l'utilisateur a spécifié une taille d'image explicite avec les options de configuration du widget -width et/ou -height (voir photo(n)) ; dans ce cas, la zone sera silencieusement coupée aux limites de l'image.

Le paramètre block est un pointeur vers une structure Tk_PhotoImageBlock, définie comme suit :

typedef struct {
    unsigned char *pixelPtr;
    int width;
    int height;
    int pitch;
    int pixelSize;
    int offset[4];
} Tk_PhotoImageBlock;
Le champ pixelPtr pointe vers le premier pixel, c'est-à-dire le pixel en haut à gauche du bloc. Les champs width et height spécifient les dimensions du bloc de pixels. Le champ pixelSize spécifie la différence d'adresse entre deux pixels horizontalement adjacents. Il doit être de 4 pour des données d'image RVB et de 2 pour des données d'image en niveaux de gris. D'autres valeurs sont possibles, si les décalages dans le tableau offset sont ajustés en conséquence (par exemple, pour des données rouges, vertes et bleues stockées dans des plans différents). L'utilisation d'une telle disposition est fortement déconseillée, cependant. En raison d'un bug, cela pourrait ne pas fonctionner correctement si un canal alpha est fourni. (voir la section BOGUES ci-dessous). Le champ pitch spécifie la différence d'adresse entre deux pixels verticalement adjacents. Le tableau offset contient les décalages à partir de l'adresse d'un pixel vers les adresses des octets contenant les composantes rouge, verte, bleue et alpha (transparence). Si les décalages pour le rouge, le vert et le bleu sont égaux, l'image est interprétée comme étant en niveaux de gris. S'ils diffèrent, des données RVB sont supposées. Normalement, les décalages seront 0, 1, 2, 3 pour les données RVB et 0, 0, 0, 1 pour les niveaux de gris. Il est possible de fournir des données d'image sans canal alpha en définissant le décalage alpha à une valeur négative et en ajustant le champ pixelSize en conséquence. Cette utilisation est cependant déconseillée (voir la section BOGUES ci-dessous).

Le paramètre compRule de Tk_PhotoPutBlock spécifie une règle de composition qui indique quoi faire des pixels transparents. La valeur TK_PHOTO_COMPOSITE_OVERLAY indique que le contenu précédent de l'image photo doit être visible, et la valeur TK_PHOTO_COMPOSITE_SET indique que le contenu précédent de l'image photo doit être complètement ignoré, et les valeurs du bloc doivent être copiées directement. Le comportement dans Tk8.3 et versions antérieures était équivalent à avoir TK_PHOTO_COMPOSITE_OVERLAY comme règle de composition.

La valeur donnée pour les paramètres width et height de Tk_PhotoPutBlock n'a pas besoin de correspondre aux valeurs spécifiées dans block. Si elles sont plus petites, Tk_PhotoPutBlock extrait un sous-bloc des données d'image fournies. Si elles sont plus grandes, les données fournies sont répliquées (en mosaïque) pour remplir la zone spécifiée. Ces règles opèrent indépendamment dans les directions horizontale et verticale.

Tk_PhotoPutBlock renvoie normalement TCL_OK, bien que s'il ne parvient pas à allouer suffisamment de mémoire pour stocker l'image résultante, TCL_ERROR soit retourné à la place et, si l'argument interp n'est pas NULL, un message d'erreur soit placé dans le résultat de l'interpréteur.

Tk_PhotoPutZoomedBlock fonctionne comme Tk_PhotoPutBlock, sauf que l'image peut être réduite ou agrandie pour l'affichage. Les paramètres subsampleX et subsampleY permettent de réduire la taille de l'image par sous-échantillonnage. Tk_PhotoPutZoomedBlock utilisera uniquement les pixels de l'image d'entrée dont les coordonnées X sont des multiples de subsampleX, et dont les coordonnées Y sont des multiples de subsampleY. Par exemple, une image de 512x512 pixels peut être réduite à 256x256 en définissant subsampleX et subsampleY à 2.

Les paramètres zoomX et zoomY permettent d'agrandir l'image par réplication de pixels. Chaque pixel de l'image d'entrée (éventuellement sous-échantillonnée) sera écrit dans un bloc de zoomX pixels de large et zoomY pixels de haut de l'image affichée. Le sous-échantillonnage et le zoom peuvent être utilisés ensemble pour des effets spéciaux.

Tk_PhotoGetImage peut être utilisé pour récupérer des données d'image à partir d'une image photo. Tk_PhotoGetImage remplit la structure pointée par le paramètre blockPtr avec des valeurs qui décrivent l'adresse et la disposition des données d'image que l'image photo a stockées en interne. Les valeurs sont valides jusqu'à ce que l'image soit détruite ou que sa taille soit modifiée.

Il est possible de modifier une image en écrivant directement dans les données auxquelles pointe le champ pixelPtr. La taille de l'image ne peut cependant pas être modifiée de cette manière. De plus, les modifications apportées en écrivant directement dans pixelPtr ne seront pas immédiatement visibles, mais seulement après un appel à Tk_ImageChanged ou après un événement qui amène les widgets intéressés à se redessiner. Tk_PhotoGetSize(photo, widthPtr, heightPtr)

Tcl_Interp *interp;
Tk_PhotoImageFormat *photo;

int xSubsample;
int ySubsample;

int
Tk_PhotoGetImage(photo, blockPtr)
Tk_PhotoImageFormat *photo;
TkImageBlock *blockPtr;

ARGUMENTS

blockPtr (in)—
Pointeur vers une structure Tk_PhotoImageBlock contenant les données d'image à placer.
height (in)—
Hauteur souhaitée de l'image en pixels.
heightPtr (out)—
Pointeur vers un emplacement mémoire où la hauteur actuelle de l'image sera stockée.
interp (in/out)—
Interpréteur Tcl à utiliser pour les erreurs et les allocations mémoire.
photo (in)—
Identificateur de l'image de type photo.
width (in)—
Largeur souhaitée de l'image en pixels.
widthPtr (out)—
Pointeur vers un emplacement mémoire où la largeur actuelle de l'image sera stockée.
xSubsample (in)—
Facteur de sous-échantillonnage horizontal. Par exemple, une valeur de 2 signifie qu'un pixel sur deux doit être utilisé dans la direction horizontale.
ySubsample (in)—
Facteur de sous-échantillonnage vertical. Par exemple, une valeur de 2 signifie qu'un pixel sur deux doit être utilisé dans la direction verticale.

DESCRIPTION

Ces procédures gèrent les images de type photo, qui sont des images manipulables par programme. Les images de type photo sont créées avec Tcl_CreatePhotoImageFormat.

Tk_PhotoPutBlock place un bloc de données d'image dans l'image photo spécifiée par photo. Le bloc est défini par blockPtr, qui contient des informations sur les dimensions du bloc, les données pixel, et les offsets des canaux rouge, vert, bleu et alpha.

Tk_PhotoPutZoomedBlock est similaire à Tk_PhotoPutBlock, mais elle permet de spécifier des facteurs de sous-échantillonnage horizontaux et verticaux, xSubsample et ySubsample. Ces facteurs déterminent la manière dont le bloc d'image est redimensionné pour correspondre à sa destination dans l'image photo. Si xSubsample et ySubsample sont tous deux 1, cela équivaut à un appel à Tk_PhotoPutBlock.

Après avoir modifié une image photo avec Tk_PhotoPutBlock ou Tk_PhotoPutZoomedBlock, le widget qui affiche l'image sera mis à jour.

Tk_PhotoGetImage récupère une copie des données d'image actuelles de l'image photo. Les données sont placées dans la structure Tk_PhotoImageBlock pointée par blockPtr. Notez que les données copiées par Tk_PhotoGetImage peuvent avoir un format différent des données qui ont été utilisées pour mettre à jour l'image photo à l'aide de Tk_PhotoPutBlock ou Tk_PhotoPutZoomedBlock. Si vous avez besoin de modifier une copie des données d'image et de les réécrire avec Tk_PhotoPutBlock ou Tk_PhotoPutZoomedBlock.

Tk_PhotoGetImage renvoie 1 pour la compatibilité avec la procédure correspondante dans l'ancien widget photo.

Tk_PhotoBlank efface toute la zone de l'image photo. Les zones vides d'une image photo sont transparentes.

Tk_PhotoExpand demande que l'image du widget soit étendue pour avoir au moins width x height pixels de taille. La largeur et/ou la hauteur ne sont pas modifiées si l'utilisateur a spécifié une largeur ou une hauteur d'image explicite avec les options de configuration -width et/ou -height, respectivement. Si les données d'image sont fournies en plusieurs petits blocs, il est plus efficace d'utiliser Tk_PhotoExpand ou Tk_PhotoSetSize au début plutôt que de laisser l'image s'étendre par petites incrémentations au fur et à mesure que les blocs d'image sont fournis.

Tk_PhotoExpand renvoie normalement TCL_OK, bien que s'il ne peut pas allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est renvoyé à la place et, si l'argument interp n'est pas NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoSetSize spécifie la taille de l'image, comme si l'utilisateur avait spécifié les valeurs width et height données aux options de configuration -width et -height. Une valeur de zéro pour width ou height ne modifie pas la largeur ou la hauteur de l'image, mais permet à la largeur ou à la hauteur d'être modifiée par des appels ultérieurs à Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock ou Tk_PhotoExpand.

Tk_PhotoSetSize renvoie normalement TCL_OK, bien que s'il ne peut pas allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est renvoyé à la place et, si l'argument interp n'est pas NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoGetSize renvoie les dimensions de l'image dans *widthPtr et *heightPtr.

PORTABILITE

Dans Tk 8.3 et antérieur, Tk_PhotoPutBlock et Tk_PhotoPutZoomedBlock avaient des signatures différentes. Si vous voulez compiler du code utilisant l'ancienne interface contre 8.4 sans mettre à jour votre code, compilez-le avec le drapeau -DUSE_COMPOSITELESS_PHOTO_PUT_BLOCK. Le code lié à l'aide de Stubs à des versions plus anciennes de Tk continuera de fonctionner.

Dans Tk 8.4, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoExpand et Tk_PhotoSetSize ne prenaient pas d'argument interp ni ne renvoyaient de code de résultat. Si une mémoire insuffisante était disponible pour une image, Tk paniquait. Ce comportement est toujours pris en charge si vous compilez votre extension avec le drapeau supplémentaire -DUSE_PANIC_ON_PHOTO_ALLOC_FAILURE. Le code lié à l'aide de Stubs à des versions plus anciennes de Tk continuera de fonctionner.

BOGUES

La structure Tk_PhotoImageBlock utilisée pour fournir des données d'image à Tk_PhotoPutBlock promet une grande flexibilité dans la disposition des données (par exemple, des plans séparés pour les canaux rouge, vert, bleu et alpha). Malheureusement, l'implémentation ne tient pas cette promesse. Le problème est que le champ pixelSize est utilisé (incorrectement) pour déterminer si l'image a un canal alpha. Actuellement, si le décalage pour le canal alpha est supérieur ou égal à pixelSize, tk_PhotoPutblock suppose qu'aucune donnée alpha n'est présente et rend l'image complètement opaque. Cela signifie que pour les dispositions où les canaux sont séparés (ou toute autre disposition exotique où pixelSize doit être inférieur au décalage alpha), le canal alpha ne sera pas lu correctement. Pour être prudent si ce problème est corrigé dans une future version, il est fortement recommandé de toujours fournir des données alpha - même si l'image n'a pas de transparence - et d'utiliser uniquement la disposition "standard" avec un pixelSize de 2 pour les données en niveaux de gris et 4 pour les données RVB avec des décalages de 0, 0, 0, 1 ou 0, 1, 2, 3 respectivement.
