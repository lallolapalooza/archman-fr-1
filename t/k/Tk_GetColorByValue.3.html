NOM

Tk_AllocColorFromObj, Tk_GetColor, Tk_GetColorFromObj, Tk_GetColorByValue, Tk_NameOfColor, Tk_FreeColorFromObj, Tk_FreeColor - gestion de la base de données des couleurs

SYNOPIS

#include <tk.h>

XColor *
Tk_AllocColorFromObj(interp, tkwin, objPtr)

XColor *
Tk_GetColor(interp, tkwin, name)

XColor *
Tk_GetColorFromObj(tkwin, objPtr)

XColor *
Tk_GetColorByValue(tkwin, prefPtr)

const char *
Tk_NameOfColor(colorPtr)

GC
Tk_GCForColor(colorPtr, drawable)

Tk_FreeColorFromObj(tkwin, objPtr)

Tk_FreeColor(colorPtr)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur à utiliser pour le rapport d'erreurs.
Tk_Window tkwin (in)
Fenêtre dans laquelle la couleur sera utilisée.
Tcl_Obj *objPtr (in/out)
Valeur texte décrivant la couleur désirée ; le stockage interne sera modifié pour contenir un pointeur vers (XColor *).
const char *name (in)
Description de couleur identique à objPtr sauf que la valeur de couleur est passée sous forme de chaîne et le résultat (XColor *) n'est pas stocké.
XColor *prefPtr (in)
Intensités de rouge, vert et bleu désirées pour la couleur.
XColor *colorPtr (in)
Pointeur vers les informations de couleur X. Il doit avoir été alloué par un appel antérieur à Tk_AllocColorFromObj, Tk_GetColor ou Tk_GetColorByValue, sauf lorsqu'il est passé à Tk_NameOfColor.
Drawable drawable (in)
Dessin sur lequel le contexte graphique sera utilisé. Il doit avoir le même écran et la même profondeur que la fenêtre pour laquelle la couleur a été allouée.

DESCRIPTION

Ces procédures gèrent les couleurs utilisées par une application Tk. Elles permettent le partage des couleurs lorsque cela est possible, afin de préserver l'espace de la carte de couleurs et de choisir les couleurs les plus proches lorsque l'espace de la carte de couleurs est épuisé.

Étant donné une description textuelle d'une couleur, Tk_AllocColorFromObj trouve une valeur de pixel qui peut être utilisée pour afficher la couleur dans une fenêtre donnée. La couleur désirée est spécifiée par une valeur dont la valeur de chaîne doit être dans l'un des formats suivants :

nomcouleur
L'un des noms valides d'une couleur définie dans le fichier de base de données des couleurs du serveur, tel que red ou PeachPuff.
#RGB
#RRGGBB
#RRRGGGBBB
#RRRRGGGGBBBB
Une spécification numérique des intensités rouge, vert et bleu pour afficher la couleur. Chaque R, G ou B représente un chiffre hexadécimal. Les quatre formats permettent de spécifier des couleurs avec 4 bits, 8 bits, 12 bits ou 16 bits. Lorsqu'on spécifie moins de 16 bits par couleur, ils représentent les bits les plus significatifs de la couleur, tandis que les bits les plus bas et vides sont répétés à partir des bits les plus élevés disponibles. Par exemple, #3a7 équivaut à #3333aaaa7777.

Tk_AllocColorFromObj renvoie un pointeur vers une structure XColor ; la structure indique les intensités exactes de la couleur allouée (qui peuvent différer légèrement de celles demandées, en fonction des limites de l'écran) et une valeur de pixel qui peut être utilisée pour dessiner avec la couleur dans tkwin. En cas d'erreur lors de l'appel à Tk_AllocColorFromObj (par exemple, un nom de couleur inconnu), il renvoie NULL et un message d'erreur est stocké dans le résultat de interp si interp n'est pas NULL. Si la carte de couleurs de tkwin est pleine, Tk_AllocColorFromObj utilisera la couleur la plus proche existante dans la carte de couleurs. Tk_AllocColorFromObj stocke les informations sur la valeur renvoyée dans objPtr, ce qui accélère les appels ultérieurs à des procédures telles que Tk_AllocColorFromObj et Tk_GetColorFromObj.

Tk_GetColor est identique à Tk_AllocColorFromObj, sauf que la description de la couleur est passée sous forme de chaîne de caractères au lieu d'une valeur. Cela empêche Tk_GetColor de stocker la valeur renvoyée, ce qui rend Tk_GetColor moins efficace que Tk_AllocColorFromObj.

Tk_GetColorFromObj renvoie le jeton d'une couleur existante, étant donné la fenêtre et la description utilisées pour créer la couleur. Tk_GetColorFromObj ne crée pas réellement la couleur ; la couleur doit avoir été créée précédemment par un appel à Tk_AllocColorFromObj ou Tk_GetColor. La valeur renvoyée est stockée dans objPtr, ce qui accélère les appels ultérieurs à Tk_GetColorFromObj avec le même objPtr et tkwin.

Tk_GetColorByValue est similaire à Tk_GetColor, sauf que la couleur désirée est spécifiée par les champs red, green et blue de la structure pointée par colorPtr.

Ce paquet maintient une base de données de toutes les couleurs actuellement utilisées. Si la même couleur est demandée plusieurs fois à partir de Tk_GetColor ou Tk_AllocColorFromObj (par exemple, par différentes fenêtres), ou si la même intensité est demandée plusieurs fois à partir de Tk_GetColorByValue, les valeurs de pixel existantes seront réutilisées. La réutilisation d'une valeur de pixel évite toute interaction avec le serveur graphique, ce qui rend l'allocation beaucoup plus efficace. Ces procédures fournissent également une interface portable qui fonctionne sur tous les systèmes d'exploitation. Pour cette raison, il est généralement recommandé d'utiliser Tk_AllocColorFromObj, Tk_GetColor ou Tk_GetColorByValue plutôt que des procédures de bas niveau comme XAllocColor.

Étant donné que différents appels à ce paquet peuvent renvoyer la même valeur de pixel partagée, les appelants ne doivent jamais modifier la couleur d'un pixel renvoyé par les procédures. Si une modification dynamique d'une valeur de couleur est nécessaire, XAllocColorCells doit être utilisé pour allouer la valeur de pixel de la couleur.

La procédure Tk_NameOfColor est approximativement l'inverse de Tk_GetColor. Si votre colorPtr a été créé par Tk_AllocColorFromObj ou Tk_GetColor, la valeur renvoyée est la chaîne utilisée pour créer la couleur. Si colorPtr a été créé par un appel à Tk_GetColorByValue ou par toute autre méthode, la valeur renvoyée est une chaîne qui pourrait être passée à Tk_GetColor pour renvoyer la même couleur. Note : la valeur renvoyée par Tk_NameOfColor n'est garantie que pour persister jusqu'au prochain appel à Tk_NameOfColor.

Tk_GCForColor renvoie un contexte graphique dont le champ foreground est le pixel alloué pour colorPtr et dont les autres champs ont des valeurs par défaut. Cela fournit un moyen simple de réaliser des opérations de dessin basiques avec une couleur. Le contexte graphique est stocké avec la couleur et n'existe que tant que colorPtr existe ; il est libéré lorsque la dernière référence à colorPtr est libérée en appelant Tk_FreeColor.

Lorsqu'une couleur n'est plus nécessaire, Tk_FreeColorFromObj ou Tk_FreeColor doit être appelée pour la libérer. Pour Tk_FreeColorFromObj, la couleur à libérer est spécifiée par les mêmes informations que celles utilisées pour la créer ; pour Tk_FreeColor, la couleur à libérer est spécifiée par un pointeur vers sa structure XColor. Il doit y avoir exactement un appel à Tk_FreeColorFromObj ou Tk_FreeColor pour chaque appel à Tk_AllocColorFromObj, Tk_GetColor, ou Tk_GetColorByValue.
