NOM

Tk::Photo - Images en couleur

SYNTAXE

    $widget->Photo(?nom??, options?)

DESCRIPTION

Une photo est une image dont les pixels peuvent afficher n'importe quelle couleur ou être transparents. Une image photo est stockée en interne en couleur (32 bits par pixel) et est affichée en utilisant la tramage si nécessaire. Les données d'image pour une image photo peuvent être obtenues à partir d'un fichier ou d'une chaîne de caractères, ou peuvent être fournies par du code C via une interface procédurale. Actuellement, seuls les formats GIF, XBM, XPM, BMP, JPEG, PNG et PPM/PGM sont pris en charge, mais une interface existe pour permettre l'ajout facile de formats de fichiers d'image supplémentaires. Une image photo est transparente dans les régions où aucune donnée d'image n'a été fournie ou où elle a été définie comme transparente par la sous-commande transparencySet.

CRÉATION DE PHOTOS

Les photos sont créées à l'aide de la méthode Photo. Photo prend en charge les options suivantes :

-data => chaîne
Spécifie le contenu de l'image sous forme de chaîne. La chaîne peut contenir des données encodées en base64 ou des données binaires. Le format de la chaîne doit être l'un de ceux pour lesquels il existe un gestionnaire de format de fichier image qui accepte des données sous forme de chaîne. Si les options -data et -file sont toutes deux spécifiées, l'option -file a la priorité.
-format => nom-format
Spécifie le nom du format de fichier pour les données spécifiées avec l'option -data ou -file.
-file => nom
nom donne le nom d'un fichier qui doit être lu pour fournir des données pour l'image photo. Le format du fichier doit être l'un de ceux pour lesquels il existe un gestionnaire de format de fichier image capable de lire des données.
-gamma => valeur
Spécifie que les couleurs allouées pour afficher cette image dans une fenêtre doivent être corrigées pour un affichage non linéaire avec la valeur de l'exposant gamma spécifiée. (L'intensité produite par la plupart des écrans CRT est une fonction puissance de la valeur d'entrée, de manière approximative ; gamma est l'exposant et est généralement autour de 2). La valeur spécifiée doit être supérieure à zéro. La valeur par défaut est un (pas de correction). En général, les valeurs supérieures à un rendront l'image plus claire, et les valeurs inférieures à un la rendront plus sombre.
-height => nombre
Spécifie la hauteur de l'image, en pixels. Cette option est principalement utile dans les situations où l'utilisateur souhaite construire le contenu de l'image morceau par morceau. Une valeur de zéro (par défaut) permet à l'image de s'agrandir ou de se réduire verticalement pour s'adapter aux données qu'elle contient.
-palette => spéc-palette
Spécifie la résolution du cube de couleurs à allouer pour l'affichage de cette image, et donc le nombre de couleurs utilisées à partir des tables de couleurs des fenêtres où elle est affichée. La chaîne spéc-palette peut être soit un seul nombre décimal, spécifiant le nombre de nuances de gris à utiliser, soit trois nombres décimaux séparés par des barres obliques (/), spécifiant le nombre de nuances de rouge, de vert et de bleu à utiliser, respectivement. Si la première forme (un seul nombre) est utilisée, l'image sera affichée en monochrome (c'est-à-dire en niveaux de gris).
-width => nombre
Spécifie la largeur de l'image, en pixels. Cette option est principalement utile dans les situations où l'utilisateur souhaite construire le contenu de l'image morceau par morceau. Une valeur de zéro (par défaut) permet à l'image de s'agrandir ou de se réduire horizontalement pour s'adapter aux données qu'elle contient.

MÉTHODES D'IMAGE

Lorsqu'une image photo est créée, Tk crée également un nouvel objet. Cet objet prend en charge les méthodes configure et cget décrites dans Tk::options, qui peuvent être utilisées pour interroger et modifier les options décrites ci-dessus.

Les options qui écrivent des données dans l'image développent généralement la taille de l'image, si nécessaire, pour accueillir les données écrites dans l'image, à moins que l'utilisateur n'ait spécifié des valeurs non nulles pour les options de configuration -width et/ou -height, auquel cas la largeur et/ou la hauteur de l'image, respectivement, ne seront pas modifiées.

Les méthodes supplémentaires suivantes sont disponibles pour les images photo :

$image->blank
Efface l'image ; c'est-à-dire, définit toute l'image pour qu'elle n'ait aucune donnée, de sorte qu'elle s'affiche comme transparente, et que l'arrière-plan de toute fenêtre dans laquelle elle est affichée soit visible.
$image->copy(imageSource ?,option(s) valeur(s) ...?)
Copie une région de l'image appelée $imageSource (qui doit être une image photo) vers l'image appelée $image, éventuellement avec zoom et/ou sous-échantillonnage de pixels. Si aucune option n'est spécifiée, cette méthode copie l'intégralité de $imageSource dans $image, en commençant aux coordonnées (0,0) dans $image. Les options suivantes peuvent être spécifiées :
-from => x1, y1, ? ,x2, y2?
Spécifie une sous-région rectangulaire de l'image source à copier. (x1,y1) et (x2,y2) spécifient des coins diagonalement opposés du rectangle. Si x2 et y2 ne sont pas spécifiés, la valeur par défaut est le coin inférieur droit de l'image source. Les pixels copiés incluront les bords gauche et supérieur du rectangle spécifié, mais pas les bords inférieur ou droit. Si l'option -from n'est pas donnée, la valeur par défaut est l'image source entière.
-to => x1, y1, ?, x2, y2?
Spécifie une sous-région rectangulaire de l'image de destination à affecter. (x1,y1) et (x2,y2) spécifient des coins diagonalement opposés du rectangle. Si x2 et y2 ne sont pas spécifiés, la valeur par défaut est (x1,y1) plus la taille de la région source (après sous-échantillonnage et zoom, si spécifié). Si x2 et y2 sont spécifiés, la région source sera répliquée si nécessaire pour remplir la région de destination en mosaïque.
-shrink
Spécifie que la taille de l'image de destination doit être réduite, si nécessaire, de sorte que la région copiée soit dans le coin inférieur droit de l'image. Cette option n'affectera pas la largeur ou la hauteur de l'image si l'utilisateur a spécifié une valeur non nulle pour l'option de configuration -width ou -height, respectivement.
-zoom => x, y
Spécifie que la région source doit être agrandie d'un facteur de x dans la direction X et de y dans la direction Y. Si y n'est pas donné, la valeur par défaut est la même que x. Avec cette option, chaque pixel de l'image source sera agrandi en un bloc de x x y pixels dans l'image de destination, tous de la même couleur. x et y doivent être supérieurs à 0.
-subsample => x, y
Spécifie que l'image source doit être réduite en utilisant seulement un pixel sur x dans la direction X et un pixel sur y dans la direction Y. Des valeurs négatives inverseront l'image par rapport aux axes Y ou X, respectivement. Si y n'est pas donné, la valeur par défaut est la même que x.
-compositingrule => règle
Spécifie comment les pixels transparents de l'image source sont combinés avec l'image de destination. Lorsqu'une règle de composition overlay est définie, le contenu précédent de l'image de destination est visible, comme si l'image source était imprimée sur un film transparent et placée par-dessus la destination. Lorsqu'une règle de composition set est définie, le contenu précédent de l'image de destination est supprimé et l'image source est utilisée telle quelle. T

PROCÉDURES

$image->cget(option)
Renvoie la valeur de l'option spécifiée pour l'objet image. Les options valides sont -file, -data, -format, -height, -width et -comment.
$image->configure(?option value(s), ...?)
Modifie une ou plusieurs des options de l'objet image. Les options disponibles sont les mêmes que pour la commande cget.
$image->data(?option value(s), ...?)
Renvoie les données de l'image sous forme de chaîne de caractères. Les options suivantes peuvent être spécifiées :
-background => couleur
Si la couleur est spécifiée, les données ne contiendront aucune information de transparence. Tous les pixels transparents seront remplacés par la couleur spécifiée.
-format => nom-format
Spécifie le nom du gestionnaire de format de fichier image à utiliser. Plus précisément, cette méthode recherche le premier gestionnaire dont le nom correspond à une sous-chaîne initiale de nom-format et qui a la capacité de lire ces données d'image. Si cette option n'est pas fournie, cette méthode utilise le premier gestionnaire ayant la capacité de lire les données de l'image.
-from => x1, y1, ?, x2, y2?
Spécifie une région rectangulaire de $image à renvoyer. Si seulement x1 et y1 sont spécifiés, la région s'étend de (x1,y1) au coin inférieur droit de $image. Si les quatre coordonnées sont fournies, elles spécifient des coins diagonalement opposés de la région rectangulaire, incluant x1,y1 et excluant x2,y2. Par défaut, si cette option n'est pas fournie, c'est toute l'image.
-grayscale
Si cette option est spécifiée, les données ne contiendront aucune information de couleur. Toutes les données de pixels seront transformées en niveaux de gris.
$image->get(x, y)
Renvoie la couleur du pixel aux coordonnées (x,y) dans l'image sous forme d'une liste de trois entiers compris entre 0 et 255, représentant respectivement les composantes rouge, verte et bleue.
$image->put(data ?,-format=>nom-format? ?,-to=> x1 y1 ?x2 y2??)
Définit les pixels de $image avec les données spécifiées dans data. Cette commande recherche d'abord dans la liste des gestionnaires de formats de fichiers image un gestionnaire capable d'interpréter les données de data, puis lit l'image encodée dans $image (l'image de destination). Si data ne correspond à aucun format connu, une tentative est faite pour l'interpréter comme une liste (de haut en bas) de lignes de balayage, chaque ligne de balayage étant une liste (de gauche à droite) de couleurs de pixels (voir Tk_GetColor pour une description des couleurs valides). Chaque ligne de balayage doit avoir la même longueur. Notez que lorsque data est un nom de couleur unique, vous demandez à Tk de remplir une région rectangulaire avec cette couleur. Les options suivantes peuvent être spécifiées :
-format =>nom-format
Spécifie le format des données de l'image dans data. Plus précisément, seuls les gestionnaires de formats de fichiers image dont les noms commencent par nom-format seront utilisés lors de la recherche d'un gestionnaire de format de données d'image pour lire les données.
-to =>x, y ?, x2, y2?
Spécifie les coordonnées du coin supérieur gauche (x1,y1) de la région de $image dans laquelle les données du fichier filename doivent être lues. La valeur par défaut est (0,0). Si x2,y2 est fourni et que data n'est pas assez grand pour couvrir le rectangle spécifié par cette option, les données de l'image extraites seront répétées en mosaïque pour couvrir tout le rectangle de destination. Notez que si data spécifie une seule valeur de couleur, une région s'étendant jusqu'au coin inférieur droit représenté par (x2,y2) sera remplie de cette couleur.
$image->read(nom-fichier ?,option value(s), ...?)
Lit les données d'image à partir du fichier nommé nom-fichier dans l'image. Cette méthode recherche d'abord dans la liste des gestionnaires de formats de fichiers image un gestionnaire capable d'interpréter les données de nom-fichier, puis lit l'image de nom-fichier dans $image (l'image de destination). Les options suivantes peuvent être spécifiées :
-format => nom-format
Spécifie le format des données d'image dans nom-fichier. Plus précisément, seuls les gestionnaires de formats de fichiers image dont les noms commencent par nom-format seront utilisés lors de la recherche d'un gestionnaire de format de données d'image pour lire les données.
-from => x1, y1, x2, y2
Spécifie une sous-région rectangulaire des données du fichier image à copier dans l'image de destination. Si seulement x1 et y1 sont spécifiés, la région s'étend de (x1,y1) au coin inférieur droit de l'image dans le fichier image. Si les quatre coordonnées sont spécifiées, elles définissent des coins diagonalement opposés de la région. Par défaut, si cette option n'est pas spécifiée, c'est toute l'image du fichier image.
-shrink
Si cette option est spécifiée, la taille de $image sera réduite, si nécessaire, de sorte que la région dans laquelle les données du fichier image sont lues soit au coin inférieur droit de $image. Cette option n'affectera pas la largeur ou la hauteur de l'image si l'utilisateur a spécifié une valeur non nulle pour l'option de configuration -width ou -height, respectivement.
-to => x, y
Spécifie les coordonnées du coin supérieur gauche de la région de $image dans laquelle les données du fichier nom-fichier doivent être lues. La valeur par défaut est (0,0).
$image->redither
L'algorithme de tramage utilisé dans l'affichage des images photographiques propage les erreurs de quantification d'un pixel à ses voisins. Si les données de l'image pour $image sont fournies par morceaux, l'image tramée peut ne pas être exactement correcte. Normalement, la différence n'est pas perceptible, mais si c'est un problème, cette méthode peut être utilisée pour recalculer l'image tramée dans chaque fenêtre où l'image est affichée.
$image->transparency(sous-commande, ?arg, arg ...?);
Permet d'examiner et de manipuler les informations de transparence dans l'image photographique. Plusieurs sous-commandes sont disponibles :
$image->transparencyGet(x, y);
Renvoie une valeur booléenne indiquant si le pixel aux coordonnées (x,y) est transparent.
$image->transparencySet(x, y, booléen);
Rend le pixel aux coordonnées (x,y) transparent si booléen est vrai, et rend ce pixel opaque sinon.
$image->write(nom-fichier ?,option value(s), ...?)
Écrit les données de l'image de $image dans un fichier nommé nom-fichier. Les options suivantes peuvent être spécifiées :
-background => couleur
Si la couleur est spécifiée, les données ne contiendront aucune information de transparence. Tous les pixels transparents seront remplacés par la couleur spécifiée.
-format => nom-format
Spécifie le nom du gestionnaire de format de fichier image à utiliser pour écrire les données dans le fichier. Plus précisément, cette sous-commande recherche le premier gestionnaire dont le nom correspond à une sous-chaîne initiale de nom-format et qui a la capacité d'écrire un fichier image. Si cette option n'est pas fournie, cette sous-commande utilise le premier gestionnaire qui a la capacité d'écrire un fichier image.
-from => x1, y1, ?, x2, y2?
Spécifie une région rectangulaire de $image à écrire dans le fichier image. Si seulement x1 et y1 sont spécifiés, la région s'étend de (x1,y1) au coin inférieur droit de $image. Si les quatre coordonnées sont fournies, elles spécifient des coins diagonalement opposés de la région rectangulaire. Par défaut, si cette option n'est pas fournie, c'est toute l'image.
-grayscale
Si cette option est spécifiée, les données ne contiendront aucune information de couleur. Toutes les données de pixels seront transformées en niveaux de gris.

FORMATS D'IMAGE

Le code des images photographiques est structuré de manière à permettre l'ajout facile de gestionnaires pour des formats de fichiers image supplémentaires. Le code des images photographiques maintient une liste de ces gestionnaires. Les gestionnaires sont ajoutés à la liste en les enregistrant par un appel à Tk_CreatePhotoImageFormat. La distribution standard de Tk fournit des gestionnaires pour les formats XBM, XPM, BMP, JPEG, PNG et PPM/PGM, qui sont automatiquement enregistrés lors de l'initialisation.

Lors de la lecture d'un fichier image ou du traitement de données de chaîne spécifiées avec l'option de configuration -data, le code des images photographiques invoque chaque gestionnaire tour à tour jusqu'à ce qu'un soit trouvé qui affirme pouvoir lire les données du fichier ou de la chaîne. Habituellement, cela trouvera le gestionnaire correct, mais si ce n'est pas le cas, l'utilisateur peut fournir un nom de format avec l'option -format pour spécifier quel gestionnaire utiliser. En fait, le code des images photographiques essaiera les gestionnaires dont les noms commencent par la chaîne spécifiée pour l'option -format (la comparaison n'est pas sensible à la casse). Par exemple, si l'utilisateur spécifie -format => gif, alors un gestionnaire nommé GIF87 ou GIF89 peut être invoqué, mais un gestionnaire nommé JPEG ne le sera pas (en supposant que de tels gestionnaires aient été enregistrés).

Lors de l'écriture de données d'image dans un fichier, le traitement de l'option -format est légèrement différent : la valeur de chaîne fournie pour l'option -format doit commencer par le nom complet du gestionnaire demandé, et peut contenir des informations supplémentaires qui suivent, que le gestionnaire peut utiliser, par exemple, pour spécifier quelle variante utiliser parmi les formats pris en charge par le gestionnaire. Notez que tous les gestionnaires d'images ne peuvent pas prendre en charge l'écriture de données de transparence dans un fichier, même là où la cible

et image format does.

ALLOCATION DES COULEURS

Lorsqu'une image photo est affichée dans une fenêtre, le code de l'image photo alloue les couleurs à utiliser pour afficher l'image et effectue un dithering, si nécessaire, pour afficher une approximation raisonnable de l'image en utilisant les couleurs disponibles. Les couleurs sont allouées sous forme de cube de couleurs, c'est-à-dire que le nombre de couleurs allouées est le produit du nombre de nuances de rouge, de vert et de bleu.

Normalement, le nombre de couleurs allouées est choisi en fonction de la profondeur de la fenêtre. Par exemple, dans une fenêtre PseudoColor 8 bits, le code de l'image photo tentera d'allouer sept nuances de rouge, sept nuances de vert et quatre nuances de bleu, soit un total de 198 couleurs. Dans une fenêtre StaticGray 1 bit (monochrome), il allouera deux couleurs, noir et blanc. Dans une fenêtre DirectColor ou TrueColor 24 bits, il allouera 256 nuances de chaque couleur primaire (rouge, vert, bleu). Heureusement, en raison de la manière dont les valeurs de pixels peuvent être combinées dans les fenêtres DirectColor et TrueColor, cela ne nécessite que 256 couleurs à allouer. Si toutes les couleurs ne peuvent pas être allouées, le code de l'image photo réduit le nombre de nuances de chaque couleur primaire et réessaie.

L'utilisateur peut exercer un certain contrôle sur le nombre de couleurs qu'une image photo utilise avec l'option de configuration -palette. Si cette option est utilisée, elle spécifie le nombre maximum de nuances de chaque couleur primaire à essayer d'allouer. Elle peut également être utilisée pour forcer l'image à être affichée en nuances de gris, même sur un écran couleur, en donnant un seul nombre plutôt que trois nombres séparés par des barres obliques.
