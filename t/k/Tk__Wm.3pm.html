NAME

Tk::Wm - Communiquer avec le gestionnaire de fenêtres

SYNOPSIS

    $toplevel->méthode(?args?)

DESCRIPTION

Les méthodes wm sont utilisées pour interagir avec le gestionnaire de fenêtres afin de contrôler des éléments tels que le titre d'une fenêtre, sa géométrie ou les incréments selon lesquels elle peut être redimensionnée. Les méthodes wm peuvent prendre n'importe quelle forme, en fonction de l'argument spécifique de la méthode. Toutes les formes attendent $toplevel, qui doit être un objet de fenêtre de niveau supérieur.

Les formes légales pour les méthodes wm sont :

$toplevel->aspect(?minNumer minDenom maxNumer maxDenom?)
Si minNumer, minDenom, maxNumer et maxDenom sont spécifiés, ils sont transmis à la fenêtre du gestionnaire de fenêtres et celui-ci doit les utiliser pour imposer une plage de rapports d'aspects acceptables pour $toplevel. Le rapport d'aspect de $toplevel (largeur/hauteur) sera limité entre minNumer/minDenom et maxNumer/maxDenom. Si tous les minNumer, etc. sont spécifiés comme chaînes vides, les contraintes précédentes sont supprimées. Si minNumer, etc. sont spécifiés, la méthode renvoie une chaîne vide. Sinon, elle renvoie un tableau de quatre éléments qui sont les valeurs actuelles de minNumer, minDenom, maxNumer et maxDenom (s'il n'y a pas de contraintes de rapport, elle renvoie une chaîne vide).
$widget->attributes( ?args? );
Cette sous-commande renvoie ou définit des attributs spécifiques au système associés à une fenêtre.
$widget->attributes;
Renvoie une liste des indicateurs spécifiques au système et de leurs valeurs.
$widget->attributes( ?option? );
Renvoie la valeur de l'option spécifiée.
$widget->attributes( ?option value option value...? );
Définit une ou plusieurs valeurs. Les valeurs sont les suivantes :

Sous Windows, -disabled obtient ou définit si la fenêtre est désactivée. -toolwindow obtient ou définit le style de la fenêtre comme fenêtre d'outil (tel que défini dans MSDN). -topmost obtient ou définit si cette fenêtre est une fenêtre au premier plan (affichée par-dessus toutes les autres fenêtres).

Sous Macintosh, il n'y a actuellement pas de valeurs d'attribut spécifiques.

Sous Unix, il n'y a actuellement pas de valeurs d'attribut spécifiques.

$toplevel->client( nom?)
Si nom est spécifié, cette méthode stocke nom (qui devrait être le nom d'hôte sur lequel l'application s'exécute) dans la propriété WM_CLIENT_MACHINE de $toplevel pour être utilisée par le gestionnaire de fenêtres ou le gestionnaire de session. La méthode renvoie une chaîne vide dans ce cas. Si nom n'est pas spécifié, elle renvoie le dernier nom spécifié dans une méthode client pour $toplevel. Si nom est une chaîne vide, la méthode supprime la propriété WM_CLIENT_MACHINE de $toplevel.
$toplevel->colormapwindows( windowList?)
Cette méthode est utilisée pour manipuler la propriété WM_COLORMAP_WINDOWS, qui fournit des informations sur les fenêtres ayant des couleurs privées aux gestionnaires de fenêtres. Si windowList n'est pas spécifié, elle renvoie une liste dont les éléments sont les noms des fenêtres dans la propriété WM_COLORMAP_WINDOWS. Si windowList est spécifié, il consiste en une liste de widgets ; la méthode écrase la propriété WM_COLORMAP_WINDOWS avec les fenêtres données et renvoie une chaîne vide. La propriété WM_COLORMAP_WINDOWS devrait normalement contenir une liste de fenêtres internes dans $toplevel dont les couleurs sont différentes de celles de leurs parents. L'ordre des fenêtres dans la propriété indique un ordre de priorité : lorsque $widget reçoit le focus de la carte de couleurs, le gestionnaire de fenêtres essaiera d'installer autant de couleurs que possible à partir du début de cette liste. Si $widget n'est pas inclus dans windowList, Tk l'ajoute implicitement à la fin de la propriété WM_COLORMAP_WINDOWS, donnant à sa carte de couleurs la priorité la plus basse. Si $widget->colormapwindows n'est pas appelé, Tk définit automatiquement la propriété pour chaque fenêtre de niveau supérieur pour tous les internes dont les couleurs sont différentes de celles de leurs parents, suivis par la fenêtre de niveau supérieur elle-même ; l'ordre des internes est indéterminé. Voir la documentation de l'ICCCM sur la propriété WM_COLORMAP_WINDOWS.
$toplevel->command( valeur?)
Si valeur est spécifiée, cette méthode stocke valeur dans la propriété WM_COMMAND de $toplevel pour être utilisée par le gestionnaire de fenêtres ou le gestionnaire de session et renvoie une chaîne vide. Valeur doit avoir une structure de liste appropriée ; les éléments doivent contenir les commandes utilisées pour invoquer l'application. Si valeur n'est pas spécifié, elle renvoie la dernière valeur spécifiée dans une méthode command pour $toplevel. Si valeur est spécifié comme une chaîne vide, la méthode supprime la propriété WM_COMMAND de $toplevel.
$toplevel->deiconify
Définit $toplevel pour qu'il soit affiché sous sa forme normale (non iconifiée). Ceci est réalisé en mappant la fenêtre. Si la fenêtre n'a jamais été mappée, cette méthode ne mappe pas la fenêtre, mais garantit que lorsque la fenêtre est mappée pour la première fois, elle apparaît sous forme non iconifiée. Renvoie une chaîne vide.
$toplevel->focusmodel( active|passive?)
Si l'argument active ou passive est passé comme argument optionnel à la méthode, il spécifie le modèle de focus pour $toplevel. Dans ce cas, la méthode renvoie une chaîne vide. Si aucun argument supplémentaire n'est spécifié, elle renvoie le modèle de focus actuel pour $toplevel. Un modèle de focus active signifie que $toplevel s'accroche au focus de ses descendants, même lorsque le focus actuel est sur une autre application. Un modèle passive signifie que $toplevel ne s'accroche jamais au focus par lui-même : le gestionnaire de fenêtres doit donner le focus à $toplevel aux moments appropriés. Cependant, une fois que le focus a été donné à $toplevel ou à l'un de ses descendants, l'application peut réaffecter le focus entre les descendants de $toplevel. Le modèle de focus par défaut est passive, et la méthode focus de Tk suppose un modèle de focus passif.
$toplevel->frame
Si le widget $widget a été entouré par le gestionnaire de fenêtres d'un cadre décoratif, la méthode renvoie l'identifiant de fenêtre spécifique du cadre extérieur contenant $toplevel (la fenêtre dont le parent est la racine ou la racine virtuelle). Si $toplevel n'a pas été entouré par le gestionnaire de fenêtres, la méthode renvoie l'identifiant de fenêtre spécifique de $toplevel.
$toplevel->geometry( newGeometry?)
Si newGeometry est spécifié, il modifie la géométrie de $toplevel et renvoie une chaîne vide. Sinon, il renvoie la géométrie actuelle de $toplevel (il s'agit de la dernière géométrie spécifiée par redimensionnement manuel ou dans une méthode geometry). NewGeometry a le format =widthxheight+-x+-y, où n'importe lequel de =, widthxheight, widthxheight+-x+-y peut être spécifié.
$toplevel->iconify
Définit $toplevel pour qu'il soit iconifié. Ceci est réalisé en mappant la fenêtre. Si la fenêtre a déjà été mappée, cette méthode ne la mappe pas, mais garantit que lorsque la fenêtre est mappée pour la première fois, elle sera iconifiée. Renvoie une chaîne vide.
$toplevel->map( map?)
Définit $toplevel pour qu'il soit mappé à un sous-module. Ceci est réalisé en mappant la fenêtre. Si la fenêtre a déjà été mappée, cette méthode ne la mappe pas, mais garantit que lorsque la fenêtre est mappée pour la première fois, elle apparaîtra sous forme non iconifiée. Renvoie une chaîne vide.
$toplevel->mapname( mapname?)
Définit le nom du sous-module à mapper. Ceci est réalisé en mappant la fenêtre. Si la fenêtre a déjà été mappée, cette méthode ne la mappe pas, mais garantit que lorsque la fenêtre est mappée pour la première fois, elle apparaîtra sous forme non iconifiée. Renvoie une chaîne vide.
$toplevel->menu( menu?)
Définit le menu de $toplevel. Ceci est réalisé en mappant la fenêtre. Si la fenêtre a déjà été mappée, cette méthode ne la mappe pas, mais garantit que lorsque la fenêtre est mappée pour la première fois, elle apparaîtra sous forme non iconifiée. Renvoie une chaîne vide.
$toplevel->title( title?)
Définit le titre de $toplevel. Ceci est réalisé en mappant la fenêtre. Si la fenêtre a déjà été mappée, cette méthode ne la mappe pas, mais garantit que lorsque la fenêtre est mappée pour la première fois, elle apparaîtra sous forme non iconifiée. Renvoie une chaîne vide.
$toplevel->translating( translate?)
Définit si la fenêtre doit être traduite. Ceci est réalisé en mappant la fenêtre. Si la fenêtre a déjà été mappée, cette méthode ne la mappe pas, mais garantit que lorsque la fenêtre est mappée pour la première fois, elle apparaîtra sous forme non iconifiée. Renvoie une chaîne vide.
$toplevel->withdraw
Définit $toplevel pour qu'il ne soit pas affiché. Ceci est réalisé en mappant la fenêtre. Si la fenêtre a déjà été mappée, cette méthode ne la mappe pas, mais garantit que lorsque la fenêtre est mappée pour la première fois, elle apparaîtra sous forme non iconifiée. Renvoie une chaîne vide.
$toplevel->zoom( zoom?)
Définit si la fenêtre doit être redimensionnée ou non. Ceci est réalisé en mappant la fenêtre. Si la fenêtre a déjà été mappée, cette méthode ne la mappe pas, mais garantit que lorsque la fenêtre est mappée pour la première fois, elle apparaîtra sous forme non iconifiée. Renvoie une chaîne vide.

or +-x+-y peut être omis. Width et height sont des entiers positifs spécifiant les dimensions souhaitées de $toplevel. Si $toplevel est en grille (voir « GESTION DE GÉOMÉTRIE EN GRILLE » ci-dessous) alors les dimensions sont spécifiées en unités de grille ; sinon elles sont spécifiées en unités de pixels. X et y spécifient l'emplacement souhaité de $toplevel à l'écran, en pixels. Si x est précédé de +, il spécifie le nombre de pixels entre le bord gauche de l'écran et le bord gauche de la bordure de $toplevel ; s'il est précédé de - alors x spécifie le nombre de pixels entre le bord droit de l'écran et le bord droit de la bordure de $toplevel. Si y est précédé de + alors il spécifie le nombre de pixels entre le haut de l'écran et le haut de la bordure de $toplevel ; s'il est précédé de - alors y spécifie le nombre de pixels entre le bas de la bordure de $toplevel et le bas de l'écran. Si newGeometry est spécifié comme une chaîne vide alors toute géométrie existante spécifiée par l'utilisateur pour $toplevel est annulée, et la fenêtre reviendra à la taille demandée en interne par ses widgets.
$toplevel->wmGrid(?baseWidth,baseHeight,widthInc,heightInc?)
Cette méthode indique que $toplevel doit être géré comme une fenêtre en grille. Elle spécifie également la relation entre les unités de grille et les unités de pixels. BaseWidth et baseHeight spécifient le nombre d'unités de grille correspondant aux dimensions en pixels demandées en interne par $toplevel en utilisant Tk_GeometryRequest. WidthInc et heightInc spécifient le nombre de pixels dans chaque unité de grille horizontale et verticale. Ces quatre valeurs déterminent une plage de tailles acceptables pour $toplevel, correspondant à des largeurs et hauteurs basées sur la grille qui sont des entiers non négatifs. Tk transmettra ces informations au gestionnaire de fenêtres ; lors du redimensionnement manuel, le gestionnaire de fenêtres restreindra la taille de la fenêtre à l'une de ces tailles acceptables. De plus, lors du redimensionnement manuel, le gestionnaire de fenêtres affichera la taille actuelle de la fenêtre en unités de grille plutôt qu'en pixels. Si baseWidth etc. sont tous spécifiés comme des chaînes vides, alors $toplevel ne sera plus géré comme une fenêtre en grille. Si baseWidth etc. sont spécifiés alors la valeur de retour est une chaîne vide. Sinon, la valeur de retour est un tableau contenant quatre éléments correspondant à baseWidth, baseHeight, widthInc et heightInc actuels ; si $toplevel n'est actuellement pas en grille, alors une chaîne vide est retournée. Remarque : cette commande ne devrait pas être nécessaire très souvent, car la procédure de bibliothèque Tk_SetGrid et l'option -setgrid fournissent un accès plus facile à la même fonctionnalité.
$toplevel->group(?$widget?)
Si $widget est spécifié, il est le chef de groupe d'un ensemble de fenêtres liées. Le gestionnaire de fenêtres peut utiliser cette information, par exemple, pour désactiver toutes les fenêtres d'un groupe lorsque le chef de groupe est iconifié. $widget peut être spécifié comme une chaîne vide pour supprimer $toplevel de toute association de groupe. Si $widget est spécifié alors la méthode retourne une chaîne vide ; sinon elle retourne le chef de groupe actuel de $toplevel, ou une chaîne vide si $toplevel ne fait partie d'aucun groupe.
$toplevel->iconbitmap(?bitmap?)
Si bitmap est spécifié, alors il nomme un bitmap dans les formes standard acceptées par Tk (voir la documentation de Tk_GetBitmap pour plus de détails). Ce bitmap noir et blanc est passé au gestionnaire de fenêtres pour être affiché dans l'icône de $toplevel, et la méthode retourne une chaîne vide. Si une chaîne vide est spécifiée pour bitmap, alors tout bitmap ou image d'icône actuel est annulé pour $toplevel. Si bitmap est spécifié alors la méthode retourne une chaîne vide. Sinon elle retourne le nom du bitmap d'icône actuel associé à $toplevel, ou une chaîne vide si $toplevel n'a pas de bitmap d'icône.
$toplevel->iconify
Organise l'iconification de $toplevel. Si $toplevel n'a pas encore été mappé pour la première fois, cette méthode organisera son apparition à l'état iconifié lorsqu'il sera éventuellement mappé.
$toplevel->iconimage(?image?)
Si image est spécifié, alors il nomme une image Tk normale. Cette image est rendue dans un bitmap privé en couleur qui est passé au gestionnaire de fenêtres pour être affiché dans l'icône de $toplevel, et la méthode retourne une chaîne vide. Si une chaîne vide est spécifiée pour image, alors toute image ou bitmap d'icône actuel est annulé pour $toplevel. Si image est spécifié alors la méthode retourne une chaîne vide. Sinon elle retourne le nom de l'image d'icône actuelle associée à $toplevel, ou une chaîne vide si $toplevel n'a pas d'image d'icône. Le pixmap privé n'est pas pré-effacé, donc les images qui sont partiellement « transparentes » affichent des détritus dans leurs parties transparentes.

Les tailles des images qui peuvent être utilisées comme icônes de cette manière dépendent de la plateforme. Sur Win32, cela définit l'icône « grande », qui devrait être 32x32 ; elle sera automatiquement réduite à 16x16 pour être utilisée comme petite icône.

$toplevel->iconmask(?bitmap?)
Si bitmap est spécifié, alors il nomme un bitmap dans les formes standard acceptées par Tk (voir la documentation de Tk_GetBitmap pour plus de détails). Ce bitmap est passé au gestionnaire de fenêtres pour être utilisé comme masque en conjonction avec l'option iconbitmap : là où le masque a des zéros, aucune icône ne sera affichée ; là où il a des uns, les bits du bitmap d'icône seront affichés. Si une chaîne vide est spécifiée pour bitmap, alors tout masque d'icône actuel est annulé pour $toplevel (cela équivaut à spécifier un bitmap de tous les uns). Si bitmap est spécifié alors la méthode retourne une chaîne vide. Sinon elle retourne le nom du masque d'icône actuel associé à $toplevel, ou une chaîne vide si aucun masque n'est en vigueur.
$toplevel->iconname(?newName?)
Si newName est spécifié, alors il est passé au gestionnaire de fenêtres ; le gestionnaire de fenêtres devrait afficher newName à l'intérieur de l'icône associée à $toplevel. Dans ce cas, une chaîne vide est retournée comme résultat. Si newName n'est pas spécifié alors la méthode retourne le nom d'icône actuel pour $toplevel, ou une chaîne vide si aucun nom d'icône n'a été spécifié (dans ce cas, le gestionnaire de fenêtres affichera normalement le titre de la fenêtre, tel que spécifié avec la méthode title).
$toplevel->iconphoto(?-default? image1 ?image2 ...?)
Définit l'icône de la barre de titre pour la fenêtre en fonction des images photo nommées. Si -default est spécifié, cela s'applique également à toutes les futures fenêtres créées. Les données des images sont prises comme un instantané au moment de l'invocation. Si les images sont modifiées plus tard, cela n'est pas reflété dans les icônes de la barre de titre. Plusieurs images sont acceptées pour permettre la fourniture d'images de différentes tailles (par exemple, 16x16 et 32x32). Le gestionnaire de fenêtres peut redimensionner les icônes fournies à une taille appropriée.

Sur Windows, les images sont regroupées dans une structure d'icône Windows. Cela remplacera une icône spécifiée via wm iconbitmap, et vice versa. [NOTE : Ceci n'est pas encore implémenté !]

Sur X, les images sont organisées dans la propriété X _NET_WM_ICON, que la plupart des gestionnaires de fenêtres modernes prennent en charge. Un wm iconbitmap peut exister simultanément. Il est recommandé de ne pas utiliser plus de 2 icônes, en plaçant d'abord l'icône la plus grande.

Sur Macintosh, cela ne fait actuellement rien.

$toplevel->iconposition(?x y?)
Si x et y sont spécifiés, ils sont passés au gestionnaire de fenêtres comme une indication de l'endroit où positionner l'icône pour $toplevel. Dans ce cas, une chaîne vide est retournée. Si x et y sont spécifiés comme des chaînes vides alors toute indication de position d'icône existante est annulée. Si ni x ni y ne sont spécifiés, alors la méthode retourne un tableau contenant deux valeurs, qui sont les indications de position d'icône actuelles (s'il n'y a pas d'indications en vigueur, une chaîne vide est retournée).
$toplevel->iconwindow(?$widget?)
Si $widget est spécifié, c'est une fenêtre à utiliser comme icône pour $toplevel : lorsque $toplevel est iconifié alors $widget sera mappé pour servir d'icône, et lorsque $toplevel est dés-iconifié alors $widget sera à nouveau démappé. Si $widget est spécifié comme une chaîne vide alors toute association de fenêtre d'icône existante pour $toplevel sera annulée. Si l'argument $widget est spécifié alors une chaîne vide est retournée. Sinon la méthode retourne la fenêtre d'icône actuelle pour $toplevel, ou une chaîne vide s'il n'y a pas de fenêtre d'icône actuellement spécifiée pour $toplevel. Les événements de clic de bouton sont désactivés pour $toplevel tant qu'il s'agit d'une fenêtre d'icône ; ceci est nécessaireAfin de permettre aux gestionnaires de fenêtres de "posséder" ces événements. Note : tous les gestionnaires de fenêtres ne prennent pas en charge la notion de fenêtre d'icône. $toplevel->maxsize(?width,height?) Si width et height sont spécifiés, ils donnent les dimensions maximales admissibles pour $toplevel. Pour les fenêtres en grille, les dimensions sont spécifiées en unités de grille ; sinon, elles sont spécifiées en unités de pixels. Le gestionnaire de fenêtres restreindra les dimensions de la fenêtre à être inférieures ou égales à width et height. Si width et height sont spécifiés, la méthode renvoie une chaîne vide. Sinon, elle renvoie un tableau avec deux éléments, qui sont la largeur et la hauteur maximales actuellement en vigueur. La taille maximale est par défaut la taille de l'écran. Si le redimensionnement a été désactivé avec la méthode resizable, alors cette méthode n'a aucun effet. Voir les sections sur la gestion de la géométrie ci-dessous pour plus d'informations. $toplevel->minsize(?width,height?) Si width et height sont spécifiés, ils donnent les dimensions minimales admissibles pour $toplevel. Pour les fenêtres en grille, les dimensions sont spécifiées en unités de grille ; sinon, elles sont spécifiées en unités de pixels. Le gestionnaire de fenêtres restreindra les dimensions de la fenêtre à être supérieures ou égales à width et height. Si width et height sont spécifiés, la méthode renvoie une chaîne vide. Sinon, elle renvoie un tableau avec deux éléments, qui sont la largeur et la hauteur minimales actuellement en vigueur. La taille minimale est par défaut d'un pixel dans chaque dimension. Si le redimensionnement a été désactivé avec la méthode resizable, alors cette méthode n'a aucun effet. Voir les sections sur la gestion de la géométrie ci-dessous pour plus d'informations. $toplevel->overrideredirect(?boolean?) Si boolean est spécifié, il doit avoir une forme booléenne correcte et le flag override-redirect pour $toplevel est défini à cette valeur. Si boolean n'est pas spécifié, alors 1 ou 0 est renvoyé pour indiquer si le flag override-redirect est actuellement défini pour $toplevel. Définir le flag override-redirect pour une fenêtre fait qu'elle est ignorée par le gestionnaire de fenêtres ; entre autres choses, cela signifie que la fenêtre ne sera pas reparentée depuis la fenêtre racine dans un cadre décoratif et que l'utilisateur ne pourra pas manipuler la fenêtre en utilisant les mécanismes normaux du gestionnaire de fenêtres. $toplevel->positionfrom(?who?) Si who est spécifié, il doit être soit program, soit user, soit une abréviation de l'un de ces deux. Il indique si la position actuelle de $toplevel a été demandée par le programme ou par l'utilisateur. De nombreux gestionnaires de fenêtres ignorent les positions initiales demandées par le programme et demandent à l'utilisateur de positionner manuellement la fenêtre ; si user est spécifié, le gestionnaire de fenêtres doit positionner la fenêtre à l'endroit donné sans demander d'aide à l'utilisateur. Si who est spécifié comme une chaîne vide, alors la source de position actuelle est annulée. Si who est spécifié, la méthode renvoie une chaîne vide. Sinon, elle renvoie user ou $widget pour indiquer la source de la position actuelle de la fenêtre, ou une chaîne vide si aucune source n'a encore été spécifiée. La plupart des gestionnaires de fenêtres interprètent "aucune source" comme équivalent à program. Tk définira automatiquement la source de position sur user lorsqu'une méthode geometry est appelée, sauf si la source a été explicitement définie sur program. $toplevel->protocol(?name?,?callback?) Cette méthode est utilisée pour gérer les protocoles du gestionnaire de fenêtres tels que WM_DELETE_WINDOW. Name est le nom d'un atome correspondant à un protocole de gestionnaire de fenêtres, tel que WM_DELETE_WINDOW ou WM_SAVE_YOURSELF ou WM_TAKE_FOCUS. Si name et callback sont tous deux spécifiés, alors callback est associé au protocole spécifié par name. Name sera ajouté à la propriété WM_PROTOCOLS de $toplevel pour indiquer au gestionnaire de fenêtres que l'application dispose d'un gestionnaire de protocole pour name, et callback sera appelée à l'avenir chaque fois que le gestionnaire de fenêtres enverra un message au client pour ce protocole. Dans ce cas, la méthode renvoie une chaîne vide. Si name est spécifié mais callback ne l'est pas, alors le callback actuel pour name est renvoyé, ou une chaîne vide s'il n'y a pas de gestionnaire défini pour name. Si callback est spécifié comme une chaîne vide, alors le gestionnaire actuel pour name est supprimé et retiré de la propriété WM_PROTOCOLS sur $toplevel ; une chaîne vide est renvoyée. Enfin, si ni name ni callback ne sont spécifiés, la méthode renvoie une liste de tous les protocoles pour lesquels des gestionnaires sont actuellement définis pour $toplevel.
Tk définit toujours un gestionnaire de protocole pour WM_DELETE_WINDOW, même si vous n'en avez pas demandé un avec protocol. Si un message WM_DELETE_WINDOW arrive alors que vous n'avez pas défini de gestionnaire, Tk gère le message en détruisant la fenêtre pour laquelle il a été reçu.
$toplevel->resizable(?width,height?) Cette méthode contrôle si l'utilisateur peut redimensionner interactivement une fenêtre de premier niveau. Si width et height sont spécifiés, ce sont des valeurs booléennes qui déterminent si la largeur et la hauteur de $toplevel peuvent être modifiées par l'utilisateur. Dans ce cas, la méthode renvoie une chaîne vide. Si width et height sont omis, la méthode renvoie une liste avec deux éléments 0/1 qui indiquent si la largeur et la hauteur de $toplevel sont actuellement redimensionnables. Par défaut, les fenêtres sont redimensionnables dans les deux dimensions. Si le redimensionnement est désactivé, la taille de la fenêtre sera celle de la dernière redimensionnement interactif ou de la méthode geometry. S'il n'y a pas eu une telle opération, la taille naturelle de la fenêtre sera utilisée. $toplevel->sizefrom(?who?) Si who est spécifié, il doit être soit program, soit user, soit une abréviation de l'un de ces deux. Il indique si la taille actuelle de $toplevel a été demandée par le programme ou par l'utilisateur. Certains gestionnaires de fenêtres ignorent les tailles demandées par le programme et demandent à l'utilisateur de dimensionner manuellement la fenêtre ; si user est spécifié, le gestionnaire de fenêtres doit donner à la fenêtre sa taille spécifiée sans demander d'aide à l'utilisateur. Si who est spécifié comme une chaîne vide, alors la source de taille actuelle est annulée. Si who est spécifié, la méthode renvoie une chaîne vide. Sinon, elle renvoie user ou $widget pour indiquer la source de la taille actuelle de la fenêtre, ou une chaîne vide si aucune source n'a encore été spécifiée. La plupart des gestionnaires de fenêtres interprètent "aucune source" comme équivalent à program. $toplevel->stackorder( ?isabove|isbelow $toplevel? ); La commande stackorder renvoie une liste de fenêtres de premier niveau dans l'ordre d'empilement, du plus bas au plus haut. Lorsqu'une seule fenêtre de premier niveau est passée, la liste renvoyée inclut récursivement tous les enfants de la fenêtre qui sont des fenêtres de premier niveau. Seules les fenêtres de premier niveau qui sont actuellement mappées à l'écran sont renvoyées. La commande stackorder peut également être utilisée pour déterminer si une fenêtre de premier niveau est positionnée au-dessus ou en dessous d'une seconde fenêtre de premier niveau. Lorsqu'il est passé deux arguments de fenêtre séparés par isabove ou isbelow, un résultat booléen indique si la première fenêtre est actuellement au-dessus ou en dessous de la seconde fenêtre dans l'ordre d'empilement. $toplevel->state(?newstate?) Si newstate est spécifié, la fenêtre sera mise dans le nouvel état, sinon elle renvoie l'état actuel de $toplevel : soit normal, iconic, withdrawn, icon, ou (Windows uniquement) zoomed. La différence entre iconic et icon est que iconic fait référence à une fenêtre qui a été iconifiée (par exemple, avec la méthode iconify) tandis que icon fait référence à une fenêtre dont le seul objectif est de servir d'icône pour une autre fenêtre (via la méthode iconwindow). L'état icon ne peut pas être défini. $toplevel->title(?string?) Si string est spécifié, alors il sera transmis au gestionnaire de fenêtres pour être utilisé comme titre pour $toplevel (le gestionnaire de fenêtres devrait afficher cette chaîne dans la barre de titre de $toplevel). Dans ce cas, la méthode renvoie une chaîne vide. Si string n'est pas spécifié, la méthode renvoie le titre actuel de $toplevel. Le titre d'une fenêtre est par défaut son nom. $toplevel->transient(?master?) Si master est spécifié, alors le gestionnaire de fenêtres est informé que $toplevel est une fenêtre transitoire (par exemple, un menu déroulant) fonctionnant pour le compte de master (où master est une fenêtre de premier niveau). Certains gestionnaires de fenêtres utiliseront ces informations pour gérer $toplevel spécialement. Si master est spécifié comme une chaîne vide, alors $toplevel est marqué comme n'étant plus une fenêtre transitoire. Si master est spécifié, la méthode renvoie une chaîne vide. Sinon, la méthode renvoie le nom du chemin du maître actuel de $toplevel, ou une chaîne vide si $toplevel n'est pas actuellement une fenêtre transitoire. $toplevel->withdraw Arrange pour que $toplevel soit retirée de l'écran. Cela provoque le démappage de la fenêtre et son oubli par le gestionnaire de fenêtres. Si la fenêtre n'a jamais été mappée, alors cette méthode provoque le mappage de la fenêtre dans l'état retiré. Tous les gestionnaires de fenêtres ne semblent pas savoir comment gérer les fenêtres qui sont mappées dans l'état retiré. Note : il semble parfois nécessaire de retirer une fenêtre puis de la remap (par exemple avec deiconify) pour que certains gestionnaires de fenêtres prêtent attention aux changements d'attributs de fenêtre tels que le groupe. $toplevel->wrapper Renvoie une liste de deux éléments : l'identifiant de la fenêtre de la fenêtre enveloppante dans laquelle Tk a placé $toplevel, et la hauteur de la barre de menu. L'identifiant est celui par lequel le gestionnaire de fenêtres connaîtra $toplevel, et c'est donc l'endroit approprié pour ajouter des propriétés X. La hauteur du menu n'est retournée que sur X. Sous Windows, cette valeur est toujours zéro.

TAILLES DES ICONES

Les tailles des bitmaps/images qui peuvent être utilisées comme icônes de cette manière dépendent de la plate-forme et du gestionnaire de fenêtres. Les gestionnaires de fenêtres Unix sont généralement plus tolérants que Win32. Il est possible que des icônes en "iconimage" en couleur causent des problèmes sur certains gestionnaires de fenêtres X.

  • Win32

    "iconimage" et "iconbitmap" définissent l'icône "grande", qui devrait être de 32x32 ; elle sera automatiquement réduite à 16x16 pour être utilisée comme petite icône. Win32 ignore les requêtes "iconwin".

  • "kwm" de KDE

    Accepte les "iconimage" en couleur et les "iconbitmap" en noir et blanc, mais réduira l'un ou l'autre à une icône petite (14x14 ?). Kwm ignore "iconwin".

  • "olwm" ou "olvwm" de Sun

    Respecte "iconwin", qui remplacera "iconimage" ou "iconbitmap". Les images en couleur fonctionnent.

  • Gestionnaire de fenêtres CDE de Sun

    Les images en couleur fonctionnent. ...

GESTION DE LA GÉOMÉTRIE

Par défaut, une fenêtre de niveau supérieur apparaît à l'écran dans sa taille naturelle, c'est-à-dire celle déterminée en interne par ses widgets et ses gestionnaires de géométrie. Si la taille naturelle d'une fenêtre de niveau supérieur change, la taille de la fenêtre est ajustée pour correspondre. Une fenêtre de niveau supérieur peut recevoir une taille autre que sa taille naturelle de deux manières. Premièrement, l'utilisateur peut redimensionner la fenêtre manuellement à l'aide des fonctionnalités du gestionnaire de fenêtres, telles que les poignées de redimensionnement. Deuxièmement, l'application peut demander une taille particulière pour une fenêtre de niveau supérieur en utilisant la méthode geometry. Ces deux cas sont gérés de manière identique par Tk ; dans les deux cas, la taille demandée remplace la taille naturelle. Vous pouvez redonner à la fenêtre sa taille naturelle en appelant geometry avec une chaîne de géométrie vide.

Normalement, une fenêtre de niveau supérieur peut avoir n'importe quelle taille, d'un pixel dans chaque dimension jusqu'à la taille de son écran. Cependant, vous pouvez utiliser les méthodes minsize et maxsize pour limiter la plage des tailles autorisées. La plage définie par minsize et maxsize s'applique à toutes les formes de redimensionnement, y compris la taille naturelle de la fenêtre ainsi que les redimensionnements manuels et la méthode geometry. Vous pouvez également utiliser la méthode resizable pour désactiver complètement le redimensionnement interactif dans une ou les deux dimensions.

GESTION DE LA GÉOMÉTRIE GRILLEE

La gestion de géométrie en grille se produit lorsqu'un des widgets d'une application supporte une gamme de tailles utiles. Cela se produit, par exemple, dans un éditeur de texte où les barres de défilement, les menus et autres ornements sont de taille fixe, mais le widget d'édition peut supporter n'importe quel nombre de lignes de texte ou de caractères par ligne. Dans ce cas, il est généralement souhaitable de laisser l'utilisateur spécifier le nombre de lignes ou de caractères par ligne, soit avec la méthode geometry, soit en redimensionnant interactivement la fenêtre. Dans le cas du texte, et dans d'autres cas intéressants également, seules des tailles discrètes de la fenêtre ont un sens, comme des nombres entiers de lignes et de caractères par ligne ; des tailles arbitraires en pixels ne sont pas utiles.

La gestion de géométrie en grille prend en charge ce type d'application. Tk (et le gestionnaire de fenêtres) supposent qu'il existe une grille d'une sorte ou d'une autre dans l'application et que l'application doit être redimensionnée en termes d' unités de grille plutôt qu'en pixels. La gestion de géométrie en grille est généralement activée en activant l'option setGrid pour un widget ; elle peut également être activée avec la méthode wmGrid ou en appelant Tk_SetGrid. Dans chacune de ces approches, le widget particulier (ou parfois le code de l'application dans son ensemble) spécifie la relation entre les tailles entières de la grille pour la fenêtre et les tailles en pixels. Pour revenir à la gestion de géométrie sans grille, appelez grid avec des chaînes d'arguments vides.

Lorsque la gestion de géométrie en grille est activée, toutes les dimensions spécifiées dans les méthodes minsize, maxsize et geometry sont traitées comme des unités de grille plutôt que comme des unités de pixels. Le redimensionnement interactif est également effectué par nombres pairs d'unités de grille plutôt que par pixels.

BOGUES

La plupart des gestionnaires de fenêtres existants semblent avoir des bogues qui affectent le fonctionnement des méthodes wm. Par exemple, certains changements peuvent ne pas prendre effet si la fenêtre est déjà active : la fenêtre devra être retirée et dés-iconifiée pour que le changement se produise.
