NOM

Tk::Error - Méthode appelée pour traiter les erreurs en arrière-plan

SYNTAXE

Personnalisation :

require Tk::ErrorDialog;

ou

sub Tk::Error
{
  my ($widget,$error,@locations) = @_;
  ...
}

DESCRIPTION

La méthode Tk::Error est appelée par perl/Tk lorsqu'une erreur en arrière-plan se produit. Deux implémentations possibles sont fournies dans la distribution et les applications individuelles ou les utilisateurs peuvent (re)définir une méthode Tk::Error (par exemple, comme une sous-routine perl) s'ils souhaitent gérer les erreurs en arrière-plan d'une autre manière.

Une erreur en arrière-plan est une erreur qui survient dans une commande qui n'est pas originaire de l'application. Par exemple, si une erreur se produit lors de l'exécution d'un rappel spécifié avec une commande bind ou after, il s'agit d'une erreur en arrière-plan. Pour une erreur non en arrière-plan, l'erreur peut simplement être renvoyée via des sous-routines imbriquées jusqu'à atteindre le code de haut niveau de l'application ; l'application peut alors signaler l'erreur de la manière dont elle le souhaite. Lorsqu'une erreur en arrière-plan se produit, le déroulement se termine dans la bibliothèque Tk et il n'y a aucun moyen évident pour Tk de signaler l'erreur.

Lorsque Tk détecte une erreur en arrière-plan, il enregistre des informations sur l'erreur et appelle la méthode Tk::Error plus tard, lorsque Tk est inactif.

Tk::Error est appelée par perl/Tk comme si elle provenait du code perl :

    $mainwindow->Tk::Error("message d'erreur", location ...);

$mainwindow est la MainWindow associée au widget qui a détecté l'erreur, "message d'erreur" est une chaîne décrivant l'erreur détectée, location est une liste d'une ou plusieurs "emplacements" qui décrivent la séquence d'appels au moment où l'erreur a été détectée.

Les emplacements sont généralement un mélange de rapports d'emplacement perl donnant le nom du script et le numéro de ligne, et de chaînes simples décrivant les emplacements dans le code C principal de Tk ou perl/Tk.

Tk ignorera tout résultat renvoyé par la méthode Tk::Error. Si une autre erreur se produit dans la méthode Tk::Error (par exemple, si elle appelle die), Tk signale cette erreur elle-même en écrivant un message sur stderr (ceci afin d'éviter les boucles infinies dues à d'éventuels bogues dans Tk::Error).

Si plusieurs erreurs en arrière-plan s'accumulent avant que Tk::Error ne soit appelée pour les traiter, Tk::Error sera appelée une fois pour chaque erreur, dans l'ordre où elles se sont produites. Cependant, si Tk::Error appelle Tk->break, toutes les erreurs restantes sont ignorées sans appeler Tk::Error.

Le module Tk inclut une sous-routine Tk::Error par défaut qui signale simplement l'erreur sur stderr.

Tk::ErrorDialog

Une définition alternative est fournie via :

    "require Tk::ErrorDialog;"

qui affiche une boîte de dialogue contenant le message d'erreur et offre à l'utilisateur la possibilité de voir une trace de la pile montrant où l'erreur s'est produite.

Il s'agit d'une implémentation orientée objet de la commande Tcl/Tk bgerror, avec une particularité : comme il n'y a qu'un seul widget ErrorDialog, vous n'êtes pas obligé d'invoquer le constructeur pour le créer ; il sera créé automatiquement lors de la première erreur en arrière-plan. Cependant, afin de configurer les options -cleanupcode et -appendtraceback d'ErrorDialog, vous devez appeler le constructeur et le créer manuellement.

L'objet ErrorDialog se compose essentiellement de deux sous-widgets : un widget Dialog pour afficher l'erreur en arrière-plan et un widget Text pour les informations de la trace de la pile. Si nécessaire, vous pouvez appeler diverses méthodes de widget pour personnaliser ces sous-widgets - leurs noms annoncés sont décrits ci-dessous.

    $mw->ErrorDialog(-cleanupcode => code, -appendtraceback => bool);

$mw est une référence de fenêtre.

code est une référence de CODE si un traitement spécial post-erreur en arrière-plan est requis (par défaut, non défini). La sous-routine de rappel est appelée avec @_ ayant les mêmes arguments que ceux avec lesquels Tk::Error a été appelée.

bool est un booléen indiquant s'il faut ajouter ou non des traces de pile successives (par défaut, 1, ajouter).

Widgets ErrorDialog annoncés

error_dialog est la référence du widget Dialog.

text est la référence du widget Text contenant les informations de la trace de pile.

BOGUES

Si after ou fileevent ne sont pas appelés en tant que méthodes d'un widget, perl/Tk est incapable de fournir un argument $mainwindow. Pour prendre en charge un tel code des versions antérieures de perl/Tk, perl/Tk appelle donc Tk::Error avec la chaîne 'Tk' à la place : Tk->Tk::Error\(...\). Dans ce cas, Tk::Error dans Tk::ErrorDialog et les implémentations similaires ne peuvent pas "faire apparaître" une fenêtre car elles ne savent pas quel affichage utiliser. Un mécanisme pour fournir LA MainWindow dans les applications qui n'en ont qu'une (un cas très courant) devrait être fourni.
