ARGUMENTS

Tcl_Interp *interp (entrée)
Interpréteur à utiliser pour le rapport d'erreurs.
Tk_Window tkwin (entrée)
Jeton pour la fenêtre (pour toutes les procédures sauf Tk_Get3DBorder, doit être la fenêtre pour laquelle la bordure a été allouée).
Tcl_Obj *objPtr (entrée)
Pointeur vers la valeur dont la valeur décrit la couleur correspondant à l'arrière-plan (zones plates). Les bords éclairés seront plus clairs que cela et les bords ombragés seront plus foncés que cela.
const char *colorName (entrée)
Identique à objPtr sauf que la valeur est fournie sous forme de chaîne plutôt que de valeur.
Drawable drawable (entrée)
Jeton X pour la fenêtre ou le pixmap ; indique où les graphiques doivent être dessinés. Doit être soit la fenêtre X pour tkwin, soit un pixmap ayant le même écran et la même profondeur que tkwin.
Tk_3DBorder border (entrée)
Jeton pour la bordure précédemment allouée lors de l'appel à Tk_Get3DBorder.
int x (entrée)
Coordonnée X du coin supérieur gauche du rectangle décrivant la bordure ou le biseau, en pixels.
int y (entrée)
Coordonnée Y du coin supérieur gauche du rectangle décrivant la bordure ou le biseau, en pixels.
int width (entrée)
Largeur du rectangle décrivant la bordure ou le biseau, en pixels.
int height (entrée)
Hauteur du rectangle décrivant la bordure ou le biseau, en pixels.
int borderWidth (entrée)
Largeur de la bordure en pixels. La valeur positive signifie que la bordure est à l'intérieur du rectangle donné par x, y, width, height, la valeur négative signifie que la bordure est à l'extérieur du rectangle.
int relief (entrée)
Indique la position 3D de l'intérieur de la valeur par rapport à l'extérieur ; doit être TK_RELIEF_RAISED, TK_RELIEF_SUNKEN, TK_RELIEF_GROOVE, TK_RELIEF_SOLID ou TK_RELIEF_RIDGE (peut également être TK_RELIEF_FLAT pour Tk_Fill3DRectangle).
XPoint *pointPtr (entrée)
Pointeur vers un tableau de points décrivant l'ensemble des sommets d'un polygone. Le polygone n'a pas besoin d'être fermé (il sera fermé automatiquement s'il ne l'est pas).
int numPoints (entrée)
Nombre de points à *pointPtr.
int polyBorderWidth (entrée)
Largeur de la bordure en pixels. Si positive, la bordure est dessinée à gauche de la trajectoire donnée par pointPtr ; si négative, la bordure est dessinée à droite de la trajectoire. Si leftRelief est TK_RELIEF_GROOVE ou TK_RELIEF_RIDGE, la bordure est centrée sur la trajectoire.
int leftRelief (entrée)
Hauteur du chemin du polygone à gauche par rapport à droite. TK_RELIEF_RAISED signifie que le côté gauche doit apparaître plus haut et TK_RELIEF_SUNKEN signifie que le côté droit doit apparaître plus haut ; TK_RELIEF_GROOVE et TK_RELIEF_RIDGE signifient ce qui est évident. Pour Tk_Fill3DPolygon, TK_RELIEF_FLAT peut également être spécifié pour indiquer aucune différence de hauteur.
int leftBevel (entrée)
Non nul signifie que ce biseau forme le côté gauche de la valeur ; nul signifie qu'il forme le côté droit.
int leftIn (entrée)
Non nul signifie que le bord gauche du biseau horizontal rentre, de sorte que le bas du bord est plus à droite que le haut. Nul signifie que le bord dégage, de sorte que le bas est plus à gauche que le haut.
int rightIn (entrée)
Non nul signifie que le bord droit du biseau horizontal rentre, de sorte que le bas du bord est plus à gauche que le haut. Nul signifie que le bord dégage, de sorte que le bas est plus à droite que le haut.
int topBevel (entrée)
Non nul signifie que ce biseau forme le côté supérieur de la valeur ; nul signifie qu'il forme le côté inférieur.
int which (entrée)
Spécifie lequel des contextes graphiques de la bordure est souhaité. Doit être TK_3D_FLAT_GC, TK_3D_LIGHT_GC ou TK_3D_DARK_GC.

DESCRIPTION

Ces procédures fournissent des facilités pour dessiner des bordures de fenêtre d'une manière qui produit une apparence tridimensionnelle. Tk_Alloc3DBorderFromObj alloue les couleurs et les Pixmaps nécessaires pour dessiner une bordure dans la fenêtre indiquée par l'argument tkwin. La valeur de objPtr est un nom de couleur Tk standard qui détermine les couleurs de la bordure. La couleur indiquée par objPtr ne sera pas réellement utilisée dans la bordure ; elle indique la couleur de fond de la fenêtre (c'est-à-dire une couleur pour les surfaces plates). Les parties éclairées de la bordure apparaîtront plus claires que celles indiquées par objPtr, et les parties ombragées de la bordure apparaîtront plus foncées que objPtr.

Tk_Alloc3DBorderFromObj retourne un jeton qui peut être utilisé dans des appels ultérieurs à Tk_Draw3DRectangle. Si une erreur se produit lors de l'allocation des informations pour la bordure (par exemple, un nom de couleur invalide a été donné), NULL est retourné et un message d'erreur est laissé comme résultat de l'interpréteur interp. Si elle retourne avec succès, Tk_Alloc3DBorderFromObj met en cache les informations sur la valeur de retour dans objPtr, ce qui accélère les appels futurs à Tk_Alloc3DBorderFromObj avec le même objPtr et tkwin.

Tk_Get3DBorder est identique à Tk_Alloc3DBorderFromObj sauf que la couleur est spécifiée avec une chaîne plutôt qu'une valeur. Cela empêche Tk_Get3DBorder de mettre en cache la valeur de retour, donc Tk_Get3DBorder est moins efficace que Tk_Alloc3DBorderFromObj.

Tk_Get3DBorderFromObj retourne le jeton d'une bordure existante, étant donné la fenêtre et le nom de couleur utilisés pour créer la bordure. Tk_Get3DBorderFromObj ne crée pas réellement la bordure ; elle doit déjà avoir été créée avec un appel précédent à Tk_Alloc3DBorderFromObj ou Tk_Get3DBorder. La valeur de retour est mise en cache dans objPtr, ce qui accélère les appels futurs à Tk_Get3DBorderFromObj avec le même objPtr et tkwin.

Une fois qu'une structure de bordure a été créée, Tk_Draw3DRectangle peut être appelée pour dessiner la bordure. L'argument tkwin spécifie la fenêtre pour laquelle la bordure a été allouée, et drawable spécifie une fenêtre ou un pixmap dans lequel la bordure doit être dessinée. Drawable n'a pas besoin de faire référence à la même fenêtre que tkwin, mais il doit faire référence à un pixmap ou une fenêtre compatible : l'un associé au même écran et à la même profondeur que tkwin. Les arguments x, y, width et height définissent la boîte englobante de la région de bordure dans drawable (généralement x et y sont zéro et width et height sont les dimensions de la fenêtre), et borderWidth spécifie le nombre de pixels réellement occupés par la bordure. L'argument relief indique lequel des plusieurs effets tridimensionnels est désiré : TK_RELIEF_RAISED signifie que l'intérieur du rectangle doit apparaître relevé par rapport à l'extérieur du rectangle, et TK_RELIEF_SUNKEN signifie que l'intérieur doit apparaître enfoncé. TK_RELIEF_GROOVE et TK_RELIEF_RIDGE signifient qu'il devrait y avoir une rainure ou une arête autour de l'extérieur du rectangle.

Tk_Fill3DRectangle est en quelque sorte similaire à Tk_Draw3DRectangle

ARGUMENTS

Le border est un jeton retourné par Tk_Alloc3DBorderFromObj ou Tk_Get3DBorder.
Le value est une Tcl_Obj représentant la couleur à utiliser pour le bord.
Le colorName est une chaîne de caractères représentant le nom de la couleur à utiliser pour le bord.
Le tkwin est la fenêtre Tk dans laquelle le dessin sera effectué.
Le drawable est le dessin X sous-jacent pour tkwin.
Le x, y, width, et height spécifient la zone rectangulaire dans laquelle dessiner.
Le borderWidth spécifie la largeur du bord tridimensionnel.
Le relief spécifie l'effet tridimensionnel souhaité. Les valeurs possibles sont TK_RELIEF_FLAT, TK_RELIEF_RAISED, TK_RELIEF_SUNKEN, TK_RELIEF_GROOVE, et TK_RELIEF_RIDGE.
Le pointPtr et numPoints définissent la trajectoire d'un polygone.
Le polyBorderWidth spécifie la largeur du bord du polygone.
Le leftRelief spécifie quel côté de la trajectoire doit apparaître surélevé.
Le leftBorder et topBorder spécifient la position du bord par rapport à l'intérieur de la valeur.
Le leftIn et rightIn spécifient le biseau aux coins pour Tk_3DHorizontalBevel.
Le which spécifie quel contexte graphique retourner pour Tk_3DBorderGC. Les valeurs possibles sont TK_3D_FLAT_GC, TK_3D_LIGHT_GC et TK_3D_DARK_GC.

DESCRIPTION

Les procédures Tk_Draw3DRectangle et Tk_Fill3DRectangle peuvent être utilisées pour dessiner des rectangles avec un effet tridimensionnel.

La procédure Tk_Draw3DRectangle dessine un bord autour de la zone rectangulaire spécifiée en utilisant les couleurs fournies par border. Le paramètre relief détermine l'effet tridimensionnel du bord. Si relief est TK_RELIEF_RAISED, le rectangle apparaît surélevé ; s'il est TK_RELIEF_SUNKEN, il apparaît enfoncé. Les valeurs TK_RELIEF_GROOVE et TK_RELIEF_RIDGE créent des effets de rainure et de crête.

La procédure Tk_Fill3DRectangle remplit d'abord la zone rectangulaire avec la couleur d'arrière-plan (celle utilisée pour créer le border). Ensuite, elle appelle Tk_Draw3DRectangle pour dessiner un bord juste à l'intérieur du bord extérieur de la zone rectangulaire. Le paramètre relief indique l'effet désiré (TK_RELIEF_FLAT signifie qu'aucun bord ne doit être dessiné ; tout ce qui se passe est de remplir le rectangle avec la couleur d'arrière-plan).

La procédure Tk_Draw3DPolygon peut être utilisée pour dessiner des formes plus complexes avec une apparence tridimensionnelle. Les arguments pointPtr et numPoints définissent une trajectoire, polyBorderWidth indique la largeur du bord (et de quel côté de la trajectoire le dessiner), et leftRelief indique quel côté de la trajectoire doit apparaître surélevé. Tk_Draw3DPolygon dessine un bord autour de la trajectoire donnée en utilisant les couleurs de border pour produire une apparence tridimensionnelle. Si la trajectoire ne se croise pas elle-même, l'apparence sera celle d'un polygone surélevé ou enfoncé. La trajectoire peut se croiser elle-même, bien que son utilité soit discutable.

Tk_Fill3DPolygon est à Tk_Draw3DPolygon ce que Tk_Fill3DRectangle est à Tk_Draw3DRectangle : elle remplit la zone polygonale avec la couleur d'arrière-plan de border, puis appelle Tk_Draw3DPolygon pour dessiner un bord autour de la zone (sauf si leftRelief est TK_RELIEF_FLAT ; dans ce cas, aucun bord n'est dessiné).

Les procédures Tk_3DVerticalBevel et Tk_3DHorizontalBevel fournissent des primitives de dessin de plus bas niveau qui sont utilisées par des procédures telles que Tk_Draw3DRectangle. Ces procédures sont également utiles en elles-mêmes pour dessiner des formes de bordure rectilignes. Tk_3DVerticalBevel dessine un bord biseauté vertical, tel que le côté gauche ou droit d'un rectangle, et Tk_3DHorizontalBevel dessine un bord biseauté horizontal, tel que le haut ou le bas d'un rectangle. Chaque procédure prend des arguments x, y, width, et height qui décrivent la zone rectangulaire du bord biseauté (par exemple, width est la largeur du bord pour Tk_3DVerticalBevel). Les arguments leftBorder et topBorder indiquent la position du bord par rapport à « l'intérieur » de la valeur, et relief indique le relief de l'intérieur de la valeur par rapport à l'extérieur. Tk_3DVerticalBevel dessine simplement une région rectangulaire. Tk_3DHorizontalBevel dessine une région trapézoïdale pour générer des coins en onglet ; elle doit être appelée après Tk_3DVerticalBevel (sinon Tk_3DVerticalBevel écrasera le biseau dans le coin). Les arguments leftIn et rightIn de Tk_3DHorizontalBevel décrivent le biseau aux coins ; une valeur de 1 signifie que le bord inférieur du trapèze sera plus court que le bord supérieur, 0 signifie qu'il sera plus long. Par exemple, pour dessiner un bord rectangulaire, le biseau supérieur doit être dessiné avec 1 pour leftIn et rightIn, et le biseau inférieur doit être dessiné avec 0 pour les deux arguments.

La procédure Tk_SetBackgroundFromBorder modifiera le pixel d'arrière-plan et/ou le pixmap de tkwin pour produire un résultat compatible avec border. Pour les écrans couleur, l'arrière-plan résultant sera simplement la couleur spécifiée lors de la création de border ; pour les écrans monochromes, l'arrière-plan résultant sera un motif de hachures claires, afin de distinguer l'arrière-plan de la partie éclairée du bord.

Étant donné un jeton pour un bord, la procédure Tk_NameOf3DBorder retournera le nom de la couleur qui a été utilisée pour créer le bord.

La procédure Tk_3DBorderColor retourne la structure XColor qui sera utilisée pour les surfaces plates dessinées pour son argument border par des procédures comme Tk_Fill3DRectangle. La valeur de retour correspond au nom de la couleur qui a été utilisée pour créer le bord. Le XColor, et sa valeur de pixel associée, resteront alloués tant que border existera.

La procédure Tk_3DBorderGC retourne l'un des contextes graphiques X qui sont utilisés pour dessiner le bord. L'argument which sélectionne lequel des trois GC possibles : TK_3D_FLAT_GC retourne le contexte utilisé pour les surfaces plates, TK_3D_LIGHT_GC retourne le contexte pour les ombres claires, et TK_3D_DARK_GC retourne le contexte pour les ombres foncées.

Lorsqu'un bord n'est plus nécessaire, Tk_Free3DBorderFromObj ou Tk_Free3DBorder doit être appelée pour libérer les ressources qui y sont associées. Pour Tk_Free3DBorderFromObj, le bord à libérer est spécifié avec la fenêtre et le nom de couleur utilisés pour créer le bord ; pour Tk_Free3DBorder, le bord à libérer est spécifié avec le jeton Tk_3DBorder pour le bord. Il doit y avoir exactement un appel à Tk_Free3DBorderFromObj ou Tk_Free3DBorder pour chaque appel à Tk_Alloc3DBorderFromObj ou Tk_Get3DBorder.
