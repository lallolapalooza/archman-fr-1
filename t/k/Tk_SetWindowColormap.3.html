Tk_ConfigureWindow(3) Procédures de la bibliothèque Tk Tk_ConfigureWindow(3)

NOM

Tk_ConfigureWindow, Tk_MoveWindow, Tk_ResizeWindow, Tk_MoveResizeWindow, Tk_SetWindowBorderWidth, Tk_ChangeWindowAttributes, Tk_SetWindowBackground, Tk_SetWindowBackgroundPixmap, Tk_SetWindowBorder, Tk_SetWindowBorderPixmap, Tk_SetWindowColormap, Tk_DefineCursor, Tk_UndefineCursor - modifier la configuration ou les attributs d'une fenêtre

SYNOPSIS

#include <tk.h>

Tk_ConfigureWindow(tkwin, valueMask, valuePtr)

Tk_MoveWindow(tkwin, x, y)

Tk_ResizeWindow(tkwin, width, height)

Tk_MoveResizeWindow(tkwin, x,  y, width, height)

Tk_SetWindowBorderWidth(tkwin, borderWidth)

Tk_ChangeWindowAttributes(tkwin, valueMask, attsPtr)

Tk_SetWindowBackground(tkwin, pixel)

Tk_SetWindowBackgroundPixmap(tkwin, pixmap)

Tk_SetWindowBorder(tkwin, pixel)

Tk_SetWindowBorderPixmap(tkwin, pixmap)

Tk_SetWindowColormap(tkwin, colormap)

Tk_DefineCursor(tkwin, cursor)

Tk_UndefineCursor(tkwin)

ARGUMENTS

Tk_Window tkwin (en entrée)
Jeton de la fenêtre.
unsigned int valueMask (en entrée)
Masque OR des valeurs telles que CWX ou CWBorderPixel, indiquant quels champs de *valuePtr ou *attsPtr utiliser.
XWindowChanges *valuePtr (en entrée)
Pointe vers une structure contenant les nouvelles valeurs pour les paramètres de configuration sélectionnés par valueMask. Les champs non sélectionnés par valueMask sont ignorés.
int x (en entrée)
Nouvelle coordonnée x du pixel supérieur gauche de tkwin (bordure incluse, le cas échéant) dans le parent de tkwin.
int y (en entrée)
Nouvelle coordonnée y du pixel supérieur gauche de tkwin (bordure incluse, le cas échéant) dans le parent de tkwin.
int width (en entrée)
Nouvelle largeur de tkwin (intérieur, bordure non comprise).
int height (en entrée)
Nouvelle hauteur de tkwin (intérieur, bordure non comprise).
int borderWidth (en entrée)
Nouvelle largeur de la bordure de tkwin.
XSetWindowAttributes *attsPtr (en entrée)
Pointe vers une structure contenant les nouvelles valeurs pour les attributs donnés par l'argument valueMask. Les attributs non sélectionnés par valueMask sont ignorés.
unsigned long pixel (en entrée)
Nouvelle couleur de fond ou de bordure pour la fenêtre.
Pixmap pixmap (en entrée)
Nouvelle pixmap à utiliser pour le fond ou la bordure de tkwin. ATTENTION : ne peut pas nécessairement être supprimée immédiatement, comme pour les appels Xlib. Voir la note ci-dessous.
Colormap colormap (en entrée)
Nouvelle carte de couleurs à utiliser pour tkwin.
Tk_Cursor cursor (en entrée)
Nouveau curseur à utiliser pour tkwin. Si None est spécifié, alors tkwin n'aura pas son propre curseur ; il utilisera le curseur de son parent.

DESCRIPTION

Ces procédures sont analogues aux procédures de la bibliothèque X portant des noms similaires, telles que XConfigureWindow. Chacune des procédures ci-dessus appelle la procédure X correspondante et enregistre également les informations de configuration dans la structure locale de Tk pour la fenêtre. Cela permet aux informations d'être récupérées rapidement par l'application (en utilisant des macros telles que Tk_X et Tk_Height) sans avoir à contacter le serveur X. De plus, si aucune fenêtre X n'a encore été créée pour tkwin, ces procédures n'émettent pas d'opérations X et n'invoquent pas de gestionnaires d'événements ; elles enregistrent les informations dans la structure locale de Tk pour la fenêtre ; lorsque la fenêtre est créée ultérieurement, les informations enregistrées seront utilisées pour configurer la fenêtre.

Consultez la documentation de la bibliothèque X pour plus de détails sur ce que font ces procédures et comment elles utilisent leurs arguments.

Dans les procédures Tk_ConfigureWindow, Tk_MoveWindow, Tk_ResizeWindow, Tk_MoveResizeWindow, et Tk_SetWindowBorderWidth, si tkwin est une fenêtre interne, alors les gestionnaires d'événements intéressés par les événements de configuration sont invoqués immédiatement, avant le retour de la procédure. Si tkwin est une fenêtre de niveau supérieur, alors les gestionnaires d'événements seront invoqués plus tard, après que X ait vu la requête et renvoyé un événement correspondant.

Les applications utilisant Tk ne doivent jamais appeler directement des procédures telles que XConfigureWindow ; elles doivent toujours utiliser les procédures Tk correspondantes.

La taille et la position d'une fenêtre ne doivent être modifiées que par le gestionnaire de géométrie approprié pour cette fenêtre et jamais par une fenêtre elle-même (mais voir Tk_MoveToplevelWindow pour déplacer une fenêtre de niveau supérieur).

Vous ne pouvez pas utiliser Tk_ConfigureWindow pour modifier l'ordre de superposition d'une fenêtre (valueMask ne peut pas contenir les bits CWSibling ou CWStackMode). Pour modifier l'ordre de superposition, utilisez la procédure Tk_RestackWindow.

La procédure Tk_SetWindowColormap ajoutera automatiquement tkwin à la propriété TK_COLORMAP_WINDOWS de son ancêtre de niveau supérieur le plus proche si la nouvelle carte de couleurs est différente de celle du parent de tkwin et que tkwin ne figure pas déjà dans la propriété TK_COLORMAP_WINDOWS.

BOGUES

Tk_SetWindowBackgroundPixmap et Tk_SetWindowBorderPixmap diffèrent légèrement de leurs homologues Xlib en ce que l'argument pixmap peut ne pas nécessairement être supprimé immédiatement après avoir appelé l'une de ces procédures. Ceci est dû au fait que la fenêtre de tkwin peut ne pas encore exister au moment de l'appel, auquel cas pixmap est simplement enregistré et utilisé plus tard lorsque la fenêtre de tkwin est effectivement créée. Si vous souhaitez supprimer pixmap, appelez d'abord Tk_MakeWindowExist pour vous assurer que la fenêtre de tkwin existe et que pixmap a été transmis au serveur X.

Un problème similaire se pose pour l'argument cursor passé à Tk_DefineCursor. La solution est la même que pour les pixmaps ci-dessus : appelez Tk_MakeWindowExist avant de libérer le curseur.
