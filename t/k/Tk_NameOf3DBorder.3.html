ARGUMENTS

Tcl_Interp *interp (entree)
Interpréteur à utiliser pour le rapport d'erreurs.
Tk_Window tkwin (entree)
Jeton de la fenêtre (pour toutes les procédures sauf Tk_Get3DBorder, doit être la fenêtre pour laquelle la bordure a été allouée).
Tcl_Obj *objPtr (entree)
Pointeur vers la valeur décrivant la couleur correspondante au fond (zones plates). Les bords éclairés seront plus clairs que ceci et les bords ombragés seront plus sombres que ceci.
const char *colorName (entree)
Identique à objPtr sauf que la valeur est fournie sous forme de chaîne plutôt que de valeur.
Drawable drawable (entree)
Jeton X de la fenêtre ou pixmap ; indique où les graphiques doivent être dessinés. Doit être soit la fenêtre X de tkwin, soit une pixmap avec le même écran et la même profondeur que tkwin.
Tk_3DBorder border (entree)
Jeton de la bordure précédemment allouée lors d'un appel à Tk_Get3DBorder.
int x (entree)
Coordonnée X du coin supérieur gauche du rectangle décrivant la bordure ou le biseau, en pixels.
int y (entree)
Coordonnée Y du coin supérieur gauche du rectangle décrivant la bordure ou le biseau, en pixels.
int width (entree)
Largeur du rectangle décrivant la bordure ou le biseau, en pixels.
int height (entree)
Hauteur du rectangle décrivant la bordure ou le biseau, en pixels.
int borderWidth (entree)
Largeur de la bordure en pixels. Une valeur positive signifie que la bordure est à l'intérieur du rectangle donné par x, y, width, height, une valeur négative signifie que la bordure est à l'extérieur du rectangle.
int relief (entree)
Indique la position 3D de l'intérieur de la valeur par rapport à l'extérieur ; doit être TK_RELIEF_RAISED, TK_RELIEF_SUNKEN, TK_RELIEF_GROOVE, TK_RELIEF_SOLID, ou TK_RELIEF_RIDGE (peut aussi être TK_RELIEF_FLAT pour Tk_Fill3DRectangle).
XPoint *pointPtr (entree)
Pointeur vers un tableau de points décrivant l'ensemble des sommets d'un polygone. Le polygone n'a pas besoin d'être fermé (il sera fermé automatiquement s'il ne l'est pas).
int numPoints (entree)
Nombre de points à *pointPtr.
int polyBorderWidth (entree)
Largeur de la bordure en pixels. Si positive, la bordure est dessinée à gauche de la trajectoire donnée par pointPtr ; si négative, la bordure est dessinée à droite de la trajectoire. Si leftRelief est TK_RELIEF_GROOVE ou TK_RELIEF_RIDGE, alors la bordure est centrée sur la trajectoire.
int leftRelief (entree)
Hauteur du côté gauche du chemin du polygone par rapport au côté droit. TK_RELIEF_RAISED signifie que le côté gauche doit apparaître plus haut et TK_RELIEF_SUNKEN signifie que le côté droit doit apparaître plus haut ; TK_RELIEF_GROOVE et TK_RELIEF_RIDGE signifient ce qui est évident. Pour Tk_Fill3DPolygon, TK_RELIEF_FLAT peut également être spécifié pour indiquer une absence de différence de hauteur.
int leftBevel (entree)
Non nul signifie que ce biseau forme le côté gauche de la valeur ; nul signifie qu'il forme le côté droit.
int leftIn (entree)
Non nul signifie que le bord gauche du biseau horizontal rentre, de sorte que le bas du bord est plus à droite que le haut. Nul signifie que le bord sort, de sorte que le bas est plus à gauche que le haut.
int rightIn (entree)
Non nul signifie que le bord droit du biseau horizontal rentre, de sorte que le bas du bord est plus à gauche que le haut. Nul signifie que le bord sort, de sorte que le bas est plus à droite que le haut.
int topBevel (entree)
Non nul signifie que ce biseau forme le côté supérieur de la valeur ; nul signifie qu'il forme le côté inférieur.
int which (entree)
Spécifie lequel des contextes graphiques de la bordure est souhaité. Doit être TK_3D_FLAT_GC, TK_3D_LIGHT_GC, ou TK_3D_DARK_GC.

DESCRIPTION

Ces procédures fournissent des facilités pour dessiner des bordures de fenêtre d'une manière qui produit une apparence tridimensionnelle. Tk_Alloc3DBorderFromObj alloue les couleurs et les Pixmaps nécessaires pour dessiner une bordure dans la fenêtre donnée par l'argument tkwin. La valeur de objPtr est un nom de couleur Tk standard qui détermine les couleurs de la bordure. La couleur indiquée par objPtr ne sera pas réellement utilisée dans la bordure ; elle indique la couleur de fond de la fenêtre (c'est-à-dire une couleur pour les surfaces plates). Les parties éclairées de la bordure apparaîtront plus claires que celles indiquées par objPtr, et les parties ombragées de la bordure apparaîtront plus sombres que objPtr.

Tk_Alloc3DBorderFromObj retourne un jeton qui peut être utilisé dans les appels ultérieurs à Tk_Draw3DRectangle. Si une erreur se produit lors de l'allocation des informations pour la bordure (par exemple, un nom de couleur invalide a été donné), NULL est retourné et un message d'erreur est laissé comme résultat de l'interpréteur interp. Si elle réussit, Tk_Alloc3DBorderFromObj met en cache les informations sur la valeur de retour dans objPtr, ce qui accélère les appels ultérieurs à Tk_Alloc3DBorderFromObj avec le même objPtr et tkwin.

Tk_Get3DBorder est identique à Tk_Alloc3DBorderFromObj sauf que la couleur est spécifiée avec une chaîne plutôt qu'une valeur. Cela empêche Tk_Get3DBorder de mettre en cache la valeur de retour, donc Tk_Get3DBorder est moins efficace que Tk_Alloc3DBorderFromObj.

Tk_Get3DBorderFromObj retourne le jeton d'une bordure existante, étant donné le nom de la fenêtre et de la couleur utilisés pour créer la bordure. Tk_Get3DBorderFromObj ne crée pas réellement la bordure ; elle doit avoir déjà été créée par un appel précédent à Tk_Alloc3DBorderFromObj ou Tk_Get3DBorder. La valeur de retour est mise en cache dans objPtr, ce qui accélère les appels ultérieurs à Tk_Get3DBorderFromObj avec le même objPtr et tkwin.

Une fois qu'une structure de bordure a été créée, Tk_Draw3DRectangle peut être invoquée pour dessiner la bordure. L'argument tkwin spécifie la fenêtre pour laquelle la bordure a été allouée, et drawable spécifie une fenêtre ou une pixmap dans laquelle la bordure doit être dessinée. Drawable n'a pas besoin de faire référence à la même fenêtre que tkwin, mais il doit faire référence à une pixmap ou une fenêtre compatible : une associée au même écran et avec la même profondeur que tkwin. Les arguments x, y, width et height définissent la boîte englobante de la région de bordure dans drawable (généralement x et y sont zéro et width et height sont les dimensions de la fenêtre), et borderWidth spécifie le nombre de pixels effectivement occupés par la bordure. L'argument relief indique lequel de plusieurs effets tridimensionnels est souhaité : TK_RELIEF_RAISED signifie que l'intérieur du rectangle doit apparaître surélevé par rapport à l'extérieur du rectangle, et TK_RELIEF_SUNKEN signifie que l'intérieur doit apparaître enfoncé. TK_RELIEF_GROOVE et TK_RELIEF_RIDGE signifient qu'il doit y avoir une rainure ou une arête autour de l'extérieur du rectangle.

Tk_Fill3DRectangle est quelque peu similaire à Tk_Draw3DRectangle sauf

ARGUMENTS

The procedures described in this manual page all relate to drawing widgets with a 3-dimensional appearance. The common arguments are:

tkwin
The window for which the border is being allocated. This is used to get screen information for the border.
objPtr
A Tcl object containing a color string specifying the border color.
colorString
A string specifying the border color (e.g., "red", "#ff0000").
border
A token for a Tk border, allocated by Tk_Alloc3DBorderFromObj or Tk_Get3DBorder.
drawable
The X drawable (window or pixmap) in which to draw.
x, y, width, height
Specify the rectangular area in which to draw.
borderwidth
The width of the border to draw, in pixels. If borderwidth is zero, then no border is drawn.
relief
Specifies the 3-D relief for the rectangle. This can be one of TK_RELIEF_RAISED, TK_RELIEF_SUNKEN, TK_RELIEF_FLAT, TK_RELIEF_GROOVE, TK_RELIEF_RIDGE. TK_RELIEF_FLAT means no border is drawn; the rectangle is just filled with the background color.
pointPtr
An array of Tk_Point structures defining the vertices of the polygon. Each Tk_Point structure should have integer fields x and y.
numPoints
The number of points in the pointPtr array.
polyBorderWidth
The width of the border to draw around the polygon, in pixels.
leftRelief
Specifies the relief for the left side of the border. This can be one of TK_RELIEF_RAISED, TK_RELIEF_SUNKEN, or TK_RELIEF_FLAT.
leftBorder
For Tk_3DVerticalBevel, this is the width of the border to the left of the specified rectangle. For Tk_3DHorizontalBevel, this is the width of the border above the specified rectangle.
topBorder
For Tk_3DVerticalBevel, this is the width of the border above the specified rectangle. For Tk_3DHorizontalBevel, this is the width of the border to the top of the specified rectangle.
leftIn
For Tk_3DHorizontalBevel, this specifies the amount of internal mitering on the left corner. A value of 1 means the bottom edge will be shorter than the top edge; 0 means it will be longer.
rightIn
For Tk_3DHorizontalBevel, this specifies the amount of internal mitering on the right corner. A value of 1 means the bottom edge will be shorter than the top edge; 0 means it will be longer.
which
Specifies which of the three graphics contexts to return. This should be one of TK_3D_FLAT_GC, TK_3D_LIGHT_GC, or TK_3D_DARK_GC.

DESCRIPTION

The procedures Tk_Alloc3DBorderFromObj and Tk_Get3DBorder allocate and return a token for a border based on the given color string. Tk_Alloc3DBorderFromObj uses a Tcl object for the color string, while Tk_Get3DBorder uses a C string. The border token can be used in subsequent calls to drawing procedures. Tk maintains a cache of borders, so multiple calls with the same color string for the same window will reuse the same border token. If the border is no longer needed, Tk_Free3DBorderFromObj or Tk_Free3DBorder should be called to release the resources. There should be exactly one call to Tk_Free3DBorderFromObj or Tk_Free3DBorder for each call to Tk_Alloc3DBorderFromObj or Tk_Get3DBorder.

The procedure Tk_NameOf3DBorder returns the color string that was used to create the border. This is useful for saving and restoring border information.

The procedure Tk_3DBorderColor returns the XColor structure that represents the flat color of the border. This color is used for drawing flat surfaces within the border.

The procedure Tk_3DBorderGC returns one of the three X graphics contexts (GC's) used to draw the border. These GC's are used for the flat surfaces, the light shadows, and the dark shadows of the border.

The procedure Tk_SetBackgroundFromBorder modifies the background color of the window to match the flat color of the border. This is useful for ensuring that widgets with borders have a consistent background color.

The procedure Tk_Draw3DRectangle draws a rectangle with a 3-D border. It first fills the rectangle with the background color (the color used to create the border), then draws a border inside the rectangle according to the specified relief.

The procedure Tk_Fill3DRectangle is similar to Tk_Draw3DRectangle, but it fills the entire rectangular area with the background color before drawing the border. This ensures that the entire area has a consistent background color.

The procedure Tk_Draw3DPolygon may be used to draw more complex shapes with a three-dimensional appearance. The pointPtr and numPoints arguments define a trajectory, polyBorderWidth indicates how wide the border should be (and on which side of the trajectory to draw it), and leftRelief indicates which side of the trajectory should appear raised. Tk_Draw3DPolygon draws a border around the given trajectory using the colors from border to produce a three-dimensional appearance. If the trajectory is non-self-intersecting, the appearance will be a raised or sunken polygon shape. The trajectory may be self-intersecting, although it's not clear how useful this is.

Tk_Fill3DPolygon is to Tk_Draw3DPolygon what Tk_Fill3DRectangle is to Tk_Draw3DRectangle: it fills the polygonal area with the background color from border, then calls Tk_Draw3DPolygon to draw a border around the area (unless leftRelief is TK_RELIEF_FLAT; in this case no border is drawn).

The procedures Tk_3DVerticalBevel and Tk_3DHorizontalBevel provide lower-level drawing primitives that are used by procedures such as Tk_Draw3DRectangle. These procedures are also useful in their own right for drawing rectilinear border shapes. Tk_3DVerticalBevel draws a vertical beveled edge, such as the left or right side of a rectangle, and Tk_3DHorizontalBevel draws a horizontal beveled edge, such as the top or bottom of a rectangle. Each procedure takes x, y, width, and height arguments that describe the rectangular area of the beveled edge (e.g., width is the border width for Tk_3DVerticalBevel). The leftBorder and topBorder arguments indicate the position of the border relative to the “inside” of the value, and relief indicates the relief of the inside of the value relative to the outside. Tk_3DVerticalBevel just draws a rectangular region. Tk_3DHorizontalBevel draws a trapezoidal region to generate mitered corners; it should be called after Tk_3DVerticalBevel (otherwise Tk_3DVerticalBevel will overwrite the mitering in the corner). The leftIn and rightIn arguments to Tk_3DHorizontalBevel describe the mitering at the corners; a value of 1 means that the bottom edge of the trapezoid will be shorter than the top, 0 means it will be longer. For example, to draw a rectangular border the top bevel should be drawn with 1 for both leftIn and rightIn, and the bottom bevel should be drawn with 0 for both arguments.

The procedure Tk_SetBackgroundFromBorder will modify the background pixel and/or pixmap of tkwin to produce a result compatible with border. For color displays, the resulting background will just be the color specified when border was created; for monochrome displays, the resulting background will be a light stipple pattern, in order to distinguish the background from the illuminated portion of the border.

Given a token for a border, the procedure Tk_NameOf3DBorder will return the color name that was used to create the border.

The procedure Tk_3DBorderColor returns the XColor structure that will be used for flat surfaces drawn for its border argument by procedures like Tk_Fill3DRectangle. The return value corresponds to the color name that was used to create the border. The XColor, and its associated pixel value, will remain allocated as long as border exists.

The procedure Tk_3DBorderGC returns one of the X graphics contexts that are used to draw the border. The argument which selects which one of the three possible GC's: TK_3D_FLAT_GC returns the context used for flat surfaces, TK_3D_LIGHT_GC returns the context for light shadows, and TK_3D_DARK_GC returns the context for dark shadows.

When a border is no longer needed, Tk_Free3DBorderFromObj or Tk_Free3DBorder should be called to release the resources associated with it. For Tk_Free3DBorderFromObj the border to release is specified with the window and color name used to create the border; for Tk_Free3DBorder the border to release is specified with the Tk_3DBorder token for the border. There should be exactly one call to Tk_Free3DBorderFromObj or Tk_Free3DBorder for each call to Tk_Alloc3DBorderFromObj or Tk_Get3DBorder.
