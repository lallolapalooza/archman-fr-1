NOM

Tk::Tree - Créer et manipuler des widgets Tree

SYNOPIS

    use Tk::Tree;

    $tree = $parent->Tree(?options?);

SUPER-CLASSE

La classe Tree est dérivée de la classe HList et hérite de toutes les méthodes, options et sous-widgets de sa super-classe. Un widget Tree n'est pas défilant par défaut.

OPTIONS STANDARDS

Tree prend en charge toutes les options standard d'un widget HList. Voir Tk::options pour plus de détails sur les options standard.

OPTIONS SPÉCIFIQUES AU WIDGET

Nom: browseCmd
Classe: BrowseCmd
Commutateur: -browsecmd
Spécifie une fonction de rappel à appeler chaque fois que l'utilisateur navigue sur une entrée (généralement en cliquant dessus). La fonction de rappel est appelée avec un argument, le chemin d'accès de l'entrée.
Nom: closeCmd
Classe: CloseCmd
Commutateur: -closecmd
Spécifie une fonction de rappel à appeler chaque fois qu'une entrée doit être fermée (Voir "LIENS" ci-dessous). Cette méthode est appelée avec un argument, le chemin d'accès de l'entrée. Cette méthode doit effectuer les actions appropriées pour fermer l'entrée spécifiée. Si l'option -closecmd n'est pas spécifiée, l'action de fermeture par défaut consiste à masquer toutes les entrées enfants de l'entrée spécifiée.
Nom: command
Classe: Command
Commutateur: -command
Spécifie une fonction de rappel à appeler chaque fois que l'utilisateur active une entrée (généralement en double-cliquant dessus). La fonction de rappel est appelée avec un argument, le chemin d'accès de l'entrée.
Nom: ignoreInvoke
Classe: IgnoreInvoke
Commutateur: -ignoreinvoke
Une valeur booléenne qui spécifie quand une branche doit être ouverte ou fermée. Une branche sera toujours ouverte ou fermée lorsque l'utilisateur appuie sur les indicateurs (+) et (-). Cependant, lorsque l'utilisateur invoque une branche (en double-cliquant ou en appuyant sur <Retour>), la branche ne sera ouverte ou fermée que si -ignoreinvoke est défini sur faux (la valeur par défaut).
Nom: openCmd
Classe: OpenCmd
Commutateur: -opencmd
Spécifie une fonction de rappel à appeler chaque fois qu'une entrée doit être ouverte (Voir "LIENS" ci-dessous). Cette méthode est appelée avec un argument, le chemin d'accès de l'entrée. Cette méthode doit effectuer les actions appropriées pour ouvrir l'entrée spécifiée. Si l'option -opencmd n'est pas spécifiée, l'action d'ouverture par défaut consiste à afficher toutes les entrées enfants de l'entrée spécifiée.

DESCRIPTION

La méthode Tree crée une nouvelle fenêtre et en fait un widget Tree et retourne une référence vers celui-ci. Des options supplémentaires, décrites ci-dessus, peuvent être spécifiées dans la ligne de commande ou dans la base de données d'options pour configurer des aspects du widget Tree tels que son curseur et son relief.

Le widget Tree peut être utilisé pour afficher des données hiérarchiques sous forme d'arbre. L'utilisateur peut ajuster la vue de l'arbre en ouvrant ou en fermant des parties de l'arbre.

Pour afficher une structure d'arbre statique, vous pouvez ajouter les entrées dans le widget Tree et masquer les entrées souhaitées. Ensuite, vous pouvez appeler la méthode autosetmode. Cela configurera le widget Tree de manière à ce qu'il gère automatiquement tous les événements open et close. (Veuillez consulter le programme de démonstration Tixish/examples/perl-tix-tree).

La méthode ci-dessus n'est pas applicable si vous souhaitez maintenir une structure d'arbre dynamique, c'est-à-dire que vous ne connaissez pas toutes les entrées de l'arbre et que vous devez ajouter ou supprimer des entrées ultérieurement. Pour ce faire, vous devez d'abord créer les entrées dans le widget Tree. Ensuite, utilisez la méthode setmode pour indiquer les entrées qui peuvent être ouvertes ou fermées, et utilisez les options -opencmd et -closecmd pour gérer les événements d'ouverture et de fermeture. (Veuillez consulter le programme de démonstration Tixish/examples/perl-tix-dyntree).

Utilisez soit

    $parent->Scrolled('Tree', ... );

soit

    $parent->ScrlTree( ... );

pour créer un Tree défilant. Voir Tk::Scrolled pour plus détails.

MÉTHODES DE WIDGET

La méthode Tree crée un objet widget. Cet objet prend en charge les méthodes configure et cget décrites dans Tk::options qui peuvent être utilisées pour interroger et modifier les options décrites ci-dessus. Le widget hérite également de toutes les méthodes fournies par la classe générique Tk::Widget.

Les méthodes supplémentaires suivantes sont disponibles pour les widgets Tree:

$tree->add_pathimage(treeRegExp [, openImg, closeImg])
Cette méthode définit des images pour un chemin donné (les images doivent être au format xpm). Le chemin peut être déterminé par une expression régulière simplifiée. Il n'y a que trois métacaractères :
^
au début de la "treeRegExp", comme dans les expressions régulières Perl
*
n'importe quoi
$
à la fin de la "TreeRegExp", comme dans les expressions régulières Perl

Exemples :

$tree->add_pathimage('^root','openfolder','folder');

correspond à "root", "root.foo", "root.bar", mais pas "foo.root"

$tree->add_pathimage('root.*.class','openfolder','folder');

correspond à tous les chemins contenant "root.<quelque chose>.class", mais pas "root.<quelque chose>.<quelque chose>.class" "*" est une partie du chemin. Si vous voulez utiliser un joker pour deux niveaux, vous devez utiliser "*.*".

$tree->add_pathimage('class$','openfolder','folder');

Cela correspond à tous les chemins se terminant par "class".

$tree->autosetmode
Cette méthode appelle la méthode setmode pour toutes les entrées de ce widget Tree : si une entrée n'a pas d'entrées enfants, son mode est défini sur none. Sinon, si l'entrée a des entrées enfants masquées, son mode est défini sur open ; sinon, son mode est défini sur close.
$tree->child_entries([$path][,$depth])
Cette méthode retourne dans un contexte de liste un tableau contenant tous les chemins d'accès des sous-entrées dans le chemin donné. En contexte scalaire, elle retourne le nombre de sous-entrées dans le chemin donné. 
Exemple :
  root
   | foo
   | bar
   |  | bar1
   |  | bar2
my @childentries = $tree->child_entries('root.bar');
# retourne (root.bar.bar1, root.bar.bar2)
my $nr_of_subentries = $tree->child_entries('root',2);
# retourne 4

Si $path est omis, on suppose que l'entrée au-dessus de 'root' est visée. $depth définit le nombre de niveaux.

$tree->close(entryPath)

Ferme la sous-arborescence donnée par entryPath si son mode est close.
$tree->getmode(entryPath)
Retourne le mode actuel de la sous-arborescence donnée par entryPath.
$tree->open(entryPath)
Ouvre la sous-arborescence donnée par entryPath si son mode est open.
$tree->setmode(entryPath, mode)
Cette méthode est utilisée pour indiquer si la sous-arborescence donnée par entryPath a des sous-sous-arborescences et si ces sous-sous-arborescences sont visibles. mode doit être l'un de open, close ou none. Si mode est défini sur open, un indicateur (+) est affiché à côté de la sous-arborescence. Si mode est défini sur close, un indicateur (-) est affiché à côté de la sous-arborescence. Si mode est défini sur none, aucun indicateur ne sera affiché pour cette sous-arborescence. Le mode par défaut est none. Le mode open indique que la sous-arborescence a des sous-sous-arborescences cachées et que cette sous-arborescence peut être ouverte par l'utilisateur. Le mode close indique que toutes les sous-sous-arborescences de la sous-arborescence sont maintenant visibles et que la sous-arborescence peut être fermée par l'utilisateur.

BINDINGS

Les liaisons de base de la souris et du clavier du widget Tree sont les mêmes que les liaisons du widget HList. De plus, les sous-arborescences peuvent être ouvertes ou fermées dans les conditions suivantes :

[1]
Si le mode de la sous-arborescence est open, elle peut être ouverte en cliquant sur son indicateur (+).
[2]
Si le mode de la sous-arborescence est close, elle peut être fermée en cliquant sur son indicateur (-).
