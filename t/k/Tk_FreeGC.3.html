Tk_GetGC(3) Procédures de la bibliothèque Tk Tk_GetGC(3)

NOM

Tk_GetGC, Tk_FreeGC - maintenir une base de données de contextes graphiques en lecture seule

SYNOPSIS

#include <tk.h>

GC
Tk_GetGC(tkwin, valueMask, valuePtr)

Tk_FreeGC(display, gc)

ARGUMENTS

Tk_Window tkwin (entrée)
Jeton de la fenêtre dans laquelle le contexte graphique sera utilisé.
unsigned long valueMask (entrée)
Masque de bits (tel que GCForeground ou GCStipple) indiquant quels champs de *valuePtr sont valides.
XGCValues *valuePtr (entrée)
Pointeur vers la structure décrivant les valeurs souhaitées pour le contexte graphique.
Display *display (entrée)
Affichage pour lequel gc a été alloué.
GC gc (entrée)
Identifiant X du contexte graphique qui n'est plus nécessaire. Doit avoir été alloué par Tk_GetGC.

DESCRIPTION

Tk_GetGC et Tk_FreeGC gèrent une collection de contextes graphiques utilisés par une application. Les procédures permettent le partage des contextes graphiques, évitant ainsi la surcharge du serveur qui serait engendrée si un GC distinct était créé pour chaque utilisation. Tk_GetGC prend des arguments décrivant le contexte graphique souhaité et retourne un identifiant X pour un GC qui correspond à la description. Le contexte graphique retourné aura des valeurs par défaut dans tous les champs non explicitement spécifiés par valueMask et valuePtr.

Tk_GetGC maintient une base de données de tous les contextes graphiques qu'il a créés. Dans la mesure du possible, un appel à Tk_GetGC retournera un contexte graphique existant plutôt que d'en créer un nouveau. Cette approche peut réduire considérablement la surcharge du serveur, c'est pourquoi Tk_GetGC devrait généralement être utilisé de préférence à la procédure Xlib XCreateGC, qui crée un nouveau contexte graphique à chaque appel.

Comme les valeurs de retour de Tk_GetGC sont partagées, les appelants ne doivent jamais modifier les contextes graphiques retournés par Tk_GetGC. Si un contexte graphique doit être modifié dynamiquement, il doit être créé en appelant XCreateGC au lieu de Tk_GetGC.

Lorsqu'un contexte graphique n'est plus nécessaire, Tk_FreeGC doit être appelé pour le libérer. Il doit y avoir exactement un appel à Tk_FreeGC pour chaque appel à Tk_GetGC. Lorsqu'un contexte graphique n'est plus utilisé nulle part (c'est-à-dire qu'il a été libéré autant de fois qu'il a été obtenu), Tk_FreeGC le libérera au serveur X et le supprimera de la base de données.
