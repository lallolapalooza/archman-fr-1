ARGUMENTS

Un jeton qui identifie un widget canvas.

Interpréteur à utiliser pour le rapport d'erreurs.

Description textuelle d'une coordonnée de canvas.

Pointe vers l'emplacement où stocker une coordonnée convertie.

Une coordonnée y dans l'espace du canvas.

Pointeur vers un emplacement où stocker une coordonnée x dans l'espace du drawable actuellement utilisé pour réafficher le canvas.
short *drawableYPtr (sortie)
Pointeur vers un emplacement où stocker une coordonnée y dans l'espace du drawable actuellement utilisé pour réafficher le canvas.

Contexte graphique à modifier.
short *screenXPtr (sortie)
Pointe vers un emplacement où stocker la coordonnée écran dans la fenêtre du canvas qui correspond à x.

Pointe vers un emplacement où stocker la coordonnée écran dans la fenêtre du canvas qui correspond à y.
int x1 (entrée)
Bord gauche de la région qui doit être réaffichée. Seuls les pixels à ou à droite de cette coordonnée doivent être réaffichés.

Bord supérieur de la région qui doit être réaffichée. Seuls les pixels à ou en dessous de cette coordonnée doivent être réaffichés.
int x2 (entrée)
Bord droit de la région qui doit être réaffichée. Seuls les pixels à gauche de cette coordonnée doivent être réaffichés.
int y2 (entrée)
Bord inférieur de la région qui doit être réaffichée. Seuls les pixels au-dessus de cette coordonnée doivent être réaffichés.

DESCRIPTION

Ces procédures sont appelées par les gestionnaires de type canvas pour effectuer diverses fonctions utilitaires.

Tk_CanvasTkwin renvoie le Tk_Window associé à un canvas particulier.

Tk_CanvasGetCoord traduit une spécification sous forme de chaîne d'une coordonnée (telle que 2p ou 1.6c) en une coordonnée de canvas en double précision. Si string est une description de coordonnée valide, alors Tk_CanvasGetCoord stocke la coordonnée de canvas correspondante à *doublePtr et renvoie TCL_OK. Sinon, elle stocke un message d'erreur dans le résultat de l'interpréteur et renvoie TCL_ERROR.

Tk_CanvasDrawableCoords est appelée par les gestionnaires de type lors du réaffichage pour calculer où dessiner les éléments. Étant donné des coordonnées x et y dans l'espace du canvas, Tk_CanvasDrawableCoords calcule le pixel correspondant dans le drawable actuellement utilisé pour le réaffichage ; elle renvoie ces coordonnées dans *drawableXPtr et *drawableYPtr. Cette procédure ne doit pas être invoquée sauf pendant le réaffichage.

Tk_CanvasSetStippleOrigin est également utilisée pendant le réaffichage. Elle définit l'origine du stipple dans gc afin que les stipples dessinés avec gc dans le pixmap hors écran courant s'alignent avec les stipples dessinés avec l'origine (0,0) dans la fenêtre réelle du canvas. Tk_CanvasSetStippleOrigin est nécessaire pour garantir que les motifs de stipple s'alignent correctement lorsque le canvas est réaffiché par petits morceaux. Les réaffichages sont effectués de manière doublement tamponnée, où un morceau du canvas est redessiné dans un pixmap hors écran puis recopié sur l'écran. Dans cette approche, les origines de stipple dans les contextes graphiques doivent être ajustées lors de chaque réaffichage pour compenser la position du pixmap hors écran par rapport à la fenêtre. Si un élément est dessiné avec des stipples, son gestionnaire de type appelle généralement Tk_CanvasSetStippleOrigin juste avant d'utiliser gc pour dessiner quelque chose ; une fois le dessin terminé, le gestionnaire de type appelle XSetTSOrigin pour restaurer l'origine dans gc à (0,0) (la restauration est nécessaire car les contextes graphiques sont partagés, ils ne peuvent donc pas être modifiés de manière permanente).

Tk_CanvasWindowCoords est similaire à Tk_CanvasDrawableCoords sauf qu'elle renvoie des coordonnées dans la fenêtre du canvas à l'écran, au lieu de coordonnées dans un pixmap hors écran.

Tk_CanvasEventuallyRedraw peut être invoquée par un gestionnaire de type pour informer Tk qu'une portion d'un canvas doit être redessinée. Les arguments x1, y1, x2 et y2 spécifient la région qui doit être redessinée, en coordonnées de canvas. Les gestionnaires de type ont rarement besoin d'invoquer Tk_CanvasEventuallyRedraw, car Tk peut normalement déterminer quand un élément a changé et effectuer la demande de réaffichage en son nom (cela se produit, par exemple, chaque fois que Tk appelle un configureProc ou un scaleProc). La seule fois où un gestionnaire de type doit appeler Tk_CanvasEventuallyRedraw est si un élément a changé de lui-même sans être invoqué via l'une des procédures de son Tk_ItemType ; cela pourrait se produire, par exemple, dans un élément image si l'image est modifiée à l'aide de commandes image.

Tk_CanvasTagsParseProc et Tk_CanvasTagsPrintProc sont des procédures qui gèrent l'option -tags pour les éléments de canvas. Le code d'un gestionnaire de type canvas n'appellera pas directement ces procédures, mais utilisera leurs adresses pour créer une structure Tk_CustomOption pour l'option -tags. Le code ressemble généralement à ceci :

static const Tk_CustomOption tagsOption = {Tk_CanvasTagsParseProc,
    Tk_CanvasTagsPrintProc, NULL
};
static const Tk_ConfigSpec configSpecs[] = {
    ...
    {TK_CONFIG_CUSTOM, "-tags", NULL, NULL,
        NULL, 0, TK_CONFIG_NULL_OK, &tagsOption},
    ...
};
