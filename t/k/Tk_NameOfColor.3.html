Tk_AllocColorFromObj(3) Procédures de la bibliothèque Tk Tk_AllocColorFromObj(3)

NOM

Tk_AllocColorFromObj, Tk_GetColor, Tk_GetColorFromObj, Tk_GetColorByValue, Tk_NameOfColor, Tk_FreeColorFromObj, Tk_FreeColor - gérer la base de données des couleurs

SYNOPSIS

#include <tk.h>

XColor *
Tk_AllocColorFromObj(interp, tkwin, objPtr)

XColor *
Tk_GetColor(interp, tkwin, name)

XColor *
Tk_GetColorFromObj(tkwin, objPtr)

XColor *
Tk_GetColorByValue(tkwin, prefPtr)

const char *
Tk_NameOfColor(colorPtr)

GC
Tk_GCForColor(colorPtr, drawable)

Tk_FreeColorFromObj(tkwin, objPtr)

Tk_FreeColor(colorPtr)

ARGUMENTS

Tcl_Interp *interp (entree)
Interpréteur à utiliser pour le rapport d'erreurs.
Tk_Window tkwin (entree)
Jeton pour la fenêtre dans laquelle la couleur sera utilisée.
Tcl_Obj *objPtr (entree/sortie)
La valeur chaîne décrit la couleur souhaitée ; la représentation interne sera modifiée pour mettre en cache le pointeur vers le (XColor *) correspondant.
const char *name (entree)
Identique à objPtr, sauf que la description de la couleur est passée sous forme de chaîne et que le (XColor *) résultant n'est pas mis en cache.
XColor *prefPtr (entree)
Indique les intensités rouge, verte et bleue de la couleur souhaitée.
XColor *colorPtr (entree)
Pointeur vers les informations de couleur X. Doit avoir été alloué par un appel précédent à Tk_AllocColorFromObj, Tk_GetColor ou Tk_GetColorByValue, sauf lors du passage à Tk_NameOfColor.
Drawable drawable (entree)
Dessinable dans lequel le contexte graphique résultant sera utilisé. Doit avoir le même écran et la même profondeur que la fenêtre pour laquelle la couleur a été allouée.

DESCRIPTION

Ces procédures gèrent les couleurs utilisées par une application Tk. Elles permettent le partage des couleurs lorsque cela est possible, afin de préserver l'espace de la carte de couleurs, et elles choisissent les couleurs disponibles les plus proches lorsque l'espace de la carte de couleurs est épuisé.

Étant donné une description textuelle d'une couleur, Tk_AllocColorFromObj localise une valeur de pixel qui peut être utilisée pour représenter la couleur dans une fenêtre particulière. La couleur souhaitée est spécifiée avec une valeur dont la valeur chaîne doit avoir l'une des formes suivantes :

nomdecouleur
Tous les noms textuels valides pour une couleur définis dans le fichier de base de données des couleurs du serveur, tels que red ou PeachPuff.
#RGB
#RRGGBB
#RRRGGGBBB
#RRRRGGGGBBBB
Une spécification numérique des intensités rouge, verte et bleue à utiliser pour afficher la couleur. Chaque R, G ou B représente un seul chiffre hexadécimal. Les quatre formes permettent de spécifier les couleurs avec des valeurs de 4 bits, 8 bits, 12 bits ou 16 bits. Lorsque moins de 16 bits sont fournis pour chaque couleur, ils représentent les bits les plus significatifs de la couleur, tandis que les bits inférieurs non remplis seront répliqués de manière répétée à partir des bits supérieurs disponibles. Par exemple, #3a7 est identique à #3333aaaa7777.

Tk_AllocColorFromObj renvoie un pointeur vers une structure XColor ; la structure indique les intensités exactes de la couleur allouée (qui peuvent différer légèrement de celles demandées, en fonction des limitations de l'écran) et une valeur de pixel qui peut être utilisée pour dessiner avec la couleur dans tkwin. Si une erreur se produit dans Tk_AllocColorFromObj (comme un nom de couleur inconnu), NULL est renvoyé et un message d'erreur est stocké dans le résultat de interp si interp n'est pas NULL. Si la carte de couleurs de tkwin est pleine, Tk_AllocColorFromObj utilisera la couleur existante la plus proche dans la carte de couleurs. Tk_AllocColorFromObj met en cache les informations sur la valeur de retour dans objPtr, ce qui accélère les appels futurs à des procédures telles que Tk_AllocColorFromObj et Tk_GetColorFromObj.

Tk_GetColor est identique à Tk_AllocColorFromObj, sauf que la description de la couleur est spécifiée avec une chaîne au lieu d'une valeur. Cela empêche Tk_GetColor de mettre en cache la valeur de retour, donc Tk_GetColor est moins efficace que Tk_AllocColorFromObj.

Tk_GetColorFromObj renvoie le jeton d'une couleur existante, étant donné la fenêtre et la description utilisées pour créer la couleur. Tk_GetColorFromObj ne crée pas réellement la couleur ; la couleur doit déjà avoir été créée par un appel précédent à Tk_AllocColorFromObj ou Tk_GetColor. La valeur de retour est mise en cache dans objPtr, ce qui accélère les appels futurs à Tk_GetColorFromObj avec le même objPtr et tkwin.

Tk_GetColorByValue est similaire à Tk_GetColor, sauf que la couleur souhaitée est indiquée avec les champs red, green et blue de la structure pointée par colorPtr.

Ce paquet gère une base de données de toutes les couleurs actuellement utilisées. Si la même couleur est demandée plusieurs fois à partir de Tk_GetColor ou Tk_AllocColorFromObj (par exemple, par différentes fenêtres), ou si les mêmes intensités sont demandées plusieurs fois à partir de Tk_GetColorByValue, alors les valeurs de pixels existantes seront réutilisées. La réutilisation d'un pixel existant évite toute interaction avec le serveur X, ce qui rend l'allocation beaucoup plus efficace. Ces procédures fournissent également une interface portable qui fonctionne sur toutes les plateformes. Pour cette raison, vous devriez généralement utiliser Tk_AllocColorFromObj, Tk_GetColor ou Tk_GetColorByValue au lieu de procédures de niveau inférieur telles que XAllocColor.

Étant donné que différents appels à ce paquet peuvent renvoyer la même valeur de pixel partagée, les appelants ne doivent jamais modifier la couleur d'un pixel renvoyé par les procédures. Si vous avez besoin de modifier dynamiquement une valeur de couleur, vous devez utiliser XAllocColorCells pour allouer la valeur de pixel pour la couleur.

La procédure Tk_NameOfColor est à peu près l'inverse de Tk_GetColor. Si son argument colorPtr a été créé par Tk_AllocColorFromObj ou Tk_GetColor, alors la valeur de retour est la chaîne qui a été utilisée pour créer la couleur. Si colorPtr a été créé par un appel à Tk_GetColorByValue, ou par tout autre mécanisme, alors la valeur de retour est une chaîne qui pourrait être passée à Tk_GetColor pour renvoyer la même couleur. Remarque : la chaîne renvoyée par Tk_NameOfColor n'est garantie que jusqu'au prochain appel à Tk_NameOfColor.

Tk_GCForColor renvoie un contexte graphique dont le champ foreground est le pixel alloué pour colorPtr et dont les autres champs ont tous des valeurs par défaut. Cela fournit un moyen simple de réaliser des dessins de base avec une couleur. Le contexte graphique est mis en cache avec la couleur et n'existera que tant que colorPtr existera ; il sera libéré lorsque la dernière référence à colorPtr sera libérée en appelant Tk_FreeColor.

Lorsqu'une couleur n'est plus nécessaire, Tk_FreeColorFromObj ou Tk_FreeColor doit être appelée pour la libérer. Pour Tk_FreeColorFromObj, la couleur à libérer est spécifiée avec les mêmes informations que celles utilisées pour la créer ; pour Tk_FreeColor, la couleur à libérer est spécifiée avec un pointeur vers sa structure XColor. Il doit y avoir exactement un appel à Tk_FreeColorFromObj ou Tk_FreeColor pour chaque appel à Tk_AllocColorFromObj, Tk_GetColor ou Tk_GetColorByValue.
