Tk_CreateBindingTable(3) Procédures de la bibliothèque Tk Tk_CreateBindingTable(3)

NOM

Tk_CreateBindingTable, Tk_DeleteBindingTable, Tk_CreateBinding, Tk_DeleteBinding, Tk_GetBinding, Tk_GetAllBindings, Tk_DeleteAllBindings, Tk_BindEvent - invoquer des scripts en réponse aux événements X

SYNOPIS

Tk_BindingTable
Tk_CreateBindingTable(interp)

Tk_DeleteBindingTable(bindingTable)

unsigned long
Tk_CreateBinding(interp, bindingTable, object, eventString, script, append)

int
Tk_DeleteBinding(interp, bindingTable, object, eventString)

const char *
Tk_GetBinding(interp, bindingTable, object, eventString)

Tk_GetAllBindings(interp, bindingTable, object)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur à utiliser lors de l'invocation des liaisons dans la table de liaisons. Il est également utilisé pour renvoyer les résultats et les erreurs des procédures de liaison.
Tk_BindingTable bindingTable (in)
Jeton pour la table de liaisons ; il doit avoir été retourné par un appel précédent à Tk_CreateBindingTable.
ClientData object (in)
Identifie l'objet auquel la liaison est associée.
const char *eventString (in)
Chaîne décrivant la séquence d'événements.
const char *script (in)
Script Tcl à invoquer lorsque la liaison se déclenche.
int append (in)
Si non nul, cela signifie d'ajouter script au script existant pour la liaison, le cas échéant ; si nul, cela signifie de remplacer le script existant par le nouveau.
XEvent *eventPtr (in)
Événement X à faire correspondre avec les liaisons dans bindingTable.
Tk_Window tkwin (in)
Identificateur de n'importe quelle fenêtre de l'écran où l'événement s'est produit. Utilisé pour trouver des informations liées à l'écran telles que les tables de frappe.
int numObjects (in)
Nombre d'identificateurs d'objets pointés par objectPtr.
ClientData *objectPtr (in)
Pointe vers un tableau d'identificateurs d'objets : les liaisons seront prises en compte pour chacun de ces objets dans l'ordre, du premier au dernier.

DESCRIPTION

Ces procédures fournissent un mécanisme à usage général pour créer et invoquer des liaisons. Les liaisons sont organisées en tables de liaisons. Une table de liaisons se compose d'une collection de liaisons plus un historique des événements récents. Au sein d'une table de liaisons, les liaisons sont associées à des objets. La signification d'un objet est définie par les clients du package de liaisons. Par exemple, Tk utilise une table de liaisons pour conserver toutes les liaisons créées par la commande bind. Pour cette table, les objets sont des pointeurs vers des chaînes telles que des noms de fenêtres, des noms de classes ou d'autres balises de liaison comme all. Tk conserve également une table de liaisons séparée pour chaque widget de canevas, qui gère les liaisons créées par la commande de widget bind du canevas ; dans cette table, un objet est soit un pointeur vers la structure interne d'un élément de canevas, soit un Tk_Uid identifiant une balise.

La procédure Tk_CreateBindingTable crée une nouvelle table de liaisons et associe interp à celle-ci (lorsque les liaisons de la table sont invoquées, les scripts seront évalués dans interp). Tk_CreateBindingTable renvoie un jeton pour la table, qui doit être utilisé dans les appels à d'autres procédures telles que Tk_CreateBinding ou Tk_BindEvent.

Tk_DeleteBindingTable libère tout l'état associé à une table de liaisons. Une fois qu'elle retourne, l'appelant ne devrait plus utiliser le jeton bindingTable.

Tk_CreateBinding ajoute une nouvelle liaison à une table existante. L'argument object identifie l'objet auquel la liaison doit être associée, et il peut s'agir de n'importe quelle valeur d'un seul mot. Généralement, il s'agit d'un pointeur vers une chaîne ou une structure de données. L'argument eventString identifie l'événement ou la séquence d'événements pour la liaison ; voir la documentation de la commande bind pour une description de son format. script est le script Tcl à évaluer lorsque la liaison se déclenche. append indique ce qu'il faut faire s'il existe déjà une liaison pour object et eventString : si append est nul, script remplace l'ancien script ; si append n'est pas nul, le nouveau script est ajouté à l'ancien. Tk_CreateBinding renvoie un masque d'événements X pour tous les événements associés aux liaisons. Ces informations peuvent être utiles pour invoquer XSelectInput afin de sélectionner les événements pertinents, ou pour interdire l'utilisation de certains événements dans les liaisons. Si une erreur s'est produite lors de la création de la liaison (par exemple, eventString fait référence à un événement inexistant), alors 0 est renvoyé et un message d'erreur est laissé comme résultat de l'interpréteur interp.

Tk_DeleteBinding supprime de bindingTable la liaison donnée par object et eventString, si une telle liaison existe. Tk_DeleteBinding renvoie toujours TCL_OK. Dans certains cas, elle peut réinitialiser le résultat de l'interpréteur à la valeur vide par défaut.

Tk_GetBinding renvoie un pointeur vers le script associé à eventString et object dans bindingTable. Si aucune liaison de ce type n'existe, NULL est renvoyé et un message d'erreur est laissé comme résultat de l'interpréteur interp.

Tk_GetAllBindings renvoie dans le résultat de interp une liste de toutes les chaînes d'événements pour lesquelles il existe des liaisons dans bindingTable associées à object. S'il n'y a pas de liaisons pour object, le résultat sera une chaîne vide.

Tk_DeleteAllBindings supprime toutes les liaisons de bindingTable qui sont associées à object.

Tk_BindEvent est appelée pour traiter un événement. Elle fait une copie de l'événement dans une liste d'historique interne associée à la table de liaisons, puis elle vérifie les liaisons qui correspondent à l'événement. Tk_BindEvent traite chacun des objets pointés par objectPtr tour à tour. Pour chaque objet, elle trouve toutes les liaisons qui correspondent à l'historique des événements actuel, sélectionne la liaison la plus spécifique en utilisant le mécanisme de priorité décrit dans la documentation de bind, et invoque le script pour cette liaison. S'il n'y a pas de liaisons correspondantes pour un objet particulier, l'objet est ignoré. Tk_BindEvent continue pour tous les objets, en gérant les exceptions telles que les erreurs, break et continue, comme décrit dans la documentation de bind.
