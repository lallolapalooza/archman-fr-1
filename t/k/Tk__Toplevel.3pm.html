NOM

Tk::Toplevel - Créer et manipuler des widgets Toplevel

SYNOPSIS

    $toplevel = $parent->Toplevel(?options?);

OPTIONS STANDARD

-borderwidth -highlightbackground -highlightthickness -takefocus -class -highlightcolor -relief -cursor

Voir Tk::options pour plus de détails sur les options standard.

OPTIONS SPÉCIFIQUES AU WIDGET

Nom : background
Classe : Background
Commutateur : -background
Cette option est identique à l'option standard background, à la différence que sa valeur peut également être spécifiée comme une valeur indéfinie. Dans ce cas, le widget n'affichera ni arrière-plan ni bordure, et aucune couleur ne sera consommée de sa palette de couleurs pour son arrière-plan et sa bordure.
Nom : colormap
Classe : Colormap
Commutateur : -colormap
Spécifie une palette de couleurs à utiliser pour la fenêtre. La valeur peut être new, auquel cas une nouvelle palette de couleurs est créée pour la fenêtre et ses enfants, ou le nom d'une autre fenêtre (qui doit être sur le même écran et avoir la même visualisation que $widget), auquel cas la nouvelle fenêtre utilisera la palette de couleurs de la fenêtre spécifiée. Si l'option colormap n'est pas spécifiée, la nouvelle fenêtre utilise la palette de couleurs par défaut de son écran. Cette option ne peut pas être modifiée avec la méthode configure.
Nom : container
Classe : Container
Commutateur : -container
La valeur doit être booléenne. Si elle est vraie, cela signifie que cette fenêtre sera utilisée comme conteneur dans lequel une autre application sera intégrée (par exemple, un toplevel Tk peut être intégré en utilisant l'option -use). La fenêtre supportera les protocoles appropriés du gestionnaire de fenêtres pour des éléments tels que les requêtes de géométrie. La fenêtre ne doit pas avoir ses propres enfants dans cette application. Cette option ne peut pas être modifiée avec la méthode configure.
Nom : height
Classe : Height
Commutateur : -height
Spécifie la hauteur souhaitée pour la fenêtre dans toutes les formes acceptables par Tk_GetPixels. Si cette option est inférieure ou égale à zéro, la fenêtre ne demandera aucune taille.
Nom : menu
Classe : Menu
Commutateur : -menu
Spécifie un widget menu à utiliser comme barre de menu. Sur Macintosh, la barre de menu s'affichera en haut de l'écran principal. Sur Microsoft Windows et toutes les plateformes UNIX, le menu apparaîtra dans la fenêtre toplevel dans le cadre de la décoration de fenêtre gérée par le gestionnaire de fenêtres.
Nom : ""
Classe : ""
Commutateur : -screen
Spécifie l'écran sur lequel placer la nouvelle fenêtre. Tout nom d'écran valide peut être utilisé, même celui associé à un autre affichage. Par défaut, il s'agit du même écran que celui de son parent. Cette option est spéciale car elle ne peut pas être spécifiée via la base de données d'options et ne peut pas être modifiée avec la méthode configure.
Commutateur : -title
Spécifie le titre de la fenêtre toplevel.
Nom : use
Classe : Use
Commutateur : -use
Cette option est utilisée pour l'intégration. Si la valeur n'est pas une chaîne vide, elle doit être l'identifiant de fenêtre d'une fenêtre conteneur, spécifié sous forme de chaîne hexadécimale comme celles retournées par la commande winfo id. Le widget toplevel sera créé en tant qu'enfant du conteneur donné au lieu de la fenêtre racine pour l'écran. Si la fenêtre conteneur se trouve dans une application Tk, il doit s'agir d'un widget frame ou toplevel pour lequel l'option -container a été spécifiée. Cette option ne peut pas être modifiée avec la méthode configure.
Nom : visual
Classe : Visual
Commutateur : -visual
Spécifie les informations de visualisation pour la nouvelle fenêtre dans toutes les formes acceptées par Tk_GetVisual. Si cette option n'est pas spécifiée, la nouvelle fenêtre utilisera la visualisation par défaut de son écran. L'option visual ne peut pas être modifiée avec la méthode configure.
Nom : width
Classe : Width
Commutateur : -width
Spécifie la largeur souhaitée pour la fenêtre dans toutes les formes acceptables par Tk_GetPixels. Si cette option est inférieure ou égale à zéro, la fenêtre ne demandera aucune taille.

DESCRIPTION

La méthode Toplevel crée un nouveau widget toplevel (donné par l'argument $widget). Des options supplémentaires, décrites ci-dessus, peuvent être spécifiées dans la ligne de commande ou dans la base de données d'options pour configurer des aspects du toplevel tels que sa couleur d'arrière-plan et son relief. La commande toplevel retourne le nom de chemin de la nouvelle fenêtre.

Un toplevel est similaire à un frame, sauf qu'il est créé comme une fenêtre de niveau supérieur : son parent X est la fenêtre racine d'un écran plutôt que le parent logique de son nom de chemin. Le but principal d'un toplevel est de servir de conteneur pour les boîtes de dialogue et autres collections de widgets. Les seules caractéristiques visibles d'un toplevel sont sa couleur d'arrière-plan et une bordure optionnelle en 3D pour donner à la fenêtre une apparence surélevée ou enfoncée.

MÉTHODES DE WIDGET

La méthode Toplevel crée un objet widget. Cet objet prend en charge les méthodes configure et cget décrites dans Tk::options, qui peuvent être utilisées pour interroger et modifier les options décrites ci-dessus. Le widget hérite également de toutes les méthodes fournies par la classe générique Tk::Widget et la classe Tk::Wm.

LIAISONS

Lorsqu'un nouveau toplevel est créé, il n'a aucune liaison d'événement par défaut : les toplevels ne sont pas destinés à être interactifs.
