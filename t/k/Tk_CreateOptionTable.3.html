ARGUMENTS

Tcl_Interp *interp (entrée)
Un interpréteur Tcl. La plupart des procédures l'utilisent uniquement pour retourner des messages d'erreur ; si c'est NULL, aucun message d'erreur n'est retourné. Pour Tk_CreateOptionTable, la valeur ne peut pas être NULL ; elle indique l'interpréteur dans lequel la table d'options sera utilisée.
const Tk_OptionSpec *templatePtr (entrée)
Pointe vers un tableau d'informations statiques décrivant les options de configuration prises en charge. Utilisé pour construire une Tk_OptionTable. Les informations pointées par cet argument doivent exister pendant toute la durée de vie de la Tk_OptionTable.
Tk_OptionTable optionTable (entrée)
Jeton pour une table d'options. Doit avoir été retourné par un appel précédent à Tk_CreateOptionTable.
char *recordPtr (entrée/sortie)
Pointe vers la structure dans laquelle les valeurs des options de configuration sont stockées ; les champs de cet enregistrement sont modifiés par des procédures comme Tk_SetOptions et lus par des procédures comme Tk_GetOptionValue.
Tk_Window tkwin (entrée)
Pour les options telles que TK_OPTION_COLOR, cet argument indique la fenêtre dans laquelle l'option sera utilisée. Si optionTable n'utilise aucune option dépendante de la fenêtre, une valeur NULL peut être fournie pour cet argument.
int objc (entrée)
Nombre de valeurs dans objv.
Tcl_Obj *const *objv (entrée)
Arguments de ligne de commande pour définir les options de configuration.
Tk_SavedOptions *savePtr (sortie)
Si non NULL, la structure pointée par cet argument est remplie avec les anciennes valeurs de toutes les options modifiées et les anciennes valeurs sont restaurées automatiquement en cas d'erreur dans Tk_SetOptions.
int *maskPtr (sortie)
Si non NULL, le mot pointé par maskPtr est rempli avec le OU binaire des champs typeMask des options qui ont été modifiées.
Tk_SavedOptions *savedPtr (entrée/sortie)
Pointe vers une structure précédemment remplie par Tk_SetOptions avec les anciennes valeurs des options modifiées.
Tcl_Obj *namePtr (entrée)
La valeur de cet objet est le nom d'une option particulière. Si NULL est passé à Tk_GetOptionInfo, des informations sont retournées pour toutes les options. Ne doit pas être NULL lors de l'appel à Tk_GetOptionValue.
nom de type type (entrée)
Le nom du type d'un enregistrement.
nom de champ field (entrée)
Le nom d'un champ dans les enregistrements de type type.

DESCRIPTION

Ces procédures gèrent la plupart des détails du traitement des options de configuration, telles que celles des widgets Tk. Étant donné une description des options prises en charge, ces procédures gèrent tous les détails de l'analyse des options et du stockage de leurs valeurs dans une structure C associée au widget ou à l'objet. Les procédures ont été conçues principalement pour les widgets dans Tk, mais elles peuvent également être utilisées pour d'autres types d'objets qui ont des options de configuration. Dans le reste de cette page de manuel, le terme « widget » sera utilisé pour désigner l'objet dont les options sont gérées ; en pratique, l'objet peut ne pas être réellement un widget. Le terme « enregistrement de widget » est utilisé pour désigner la structure au niveau C dans laquelle sont stockées les informations relatives à un widget ou objet particulier.

Notez que la manière la plus simple d'apprendre à utiliser ces procédures est de regarder un exemple fonctionnel. Dans Tk, l'exemple le plus simple est le code qui implémente la famille des widgets « button », qui se trouve dans tkButton.c. D'autres exemples se trouvent dans tkSquare.c et tkMenu.c.

Afin d'utiliser ces procédures, le code qui implémente le widget doit contenir un tableau statique de structures Tk_OptionSpec. Il s'agit d'un modèle qui décrit les différentes options prises en charge par cette classe de widget ; il existe un modèle séparé pour chaque type de widget. Le modèle contient des informations telles que le nom de chaque option, son type, sa valeur par défaut et l'emplacement où la valeur de l'option est stockée dans l'enregistrement du widget. Voir MODÈLES ci-dessous pour plus de détails.

Afin de traiter les options de configuration de manière efficace, le modèle statique doit être augmenté d'informations supplémentaires disponibles uniquement au moment de l'exécution. La procédure Tk_CreateOptionTable crée ces informations dynamiques à partir du modèle et renvoie un jeton Tk_OptionTable qui décrit les informations statiques et dynamiques. Toutes les autres procédures, telles que Tk_SetOptions, prennent un jeton Tk_OptionTable comme argument. En général, Tk_CreateOptionTable est appelée la première fois qu'un widget d'une classe particulière est créé et la Tk_OptionTable résultante est utilisée à l'avenir pour tous les widgets de cette classe. Une Tk_OptionTable ne peut être utilisée que dans un seul interpréteur, spécifié par l'argument interp de Tk_CreateOptionTable. Lorsqu'une table d'options n'est plus nécessaire, Tk_DeleteOptionTable doit être appelée pour libérer toutes ses ressources. Toutes les tables d'options d'un interpréteur Tcl sont libérées automatiquement si l'interpréteur est supprimé.

Tk_InitOptions est invoquée lors de la création d'un nouveau widget pour définir les valeurs par défaut. Tk_InitOptions reçoit un jeton pour une table d'options (optionTable) et un pointeur vers un enregistrement de widget (recordPtr), qui est la structure C contenant les informations sur ce widget. Tk_InitOptions utilise les informations de la table d'options pour choisir une valeur par défaut appropriée pour chaque option, puis stocke la valeur par défaut directement dans l'enregistrement du widget, en écrasant toute information déjà présente dans l'enregistrement du widget. Tk_InitOptions renvoie normalement TCL_OK. Si une erreur s'est produite lors de la définition des valeurs par défaut (par exemple, parce qu'une valeur par défaut était erronée), TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de interp si interp n'est pas NULL. Pour toute option de configuration d'un widget qui a TK_OPTION_DONT_SET_DEFAULT défini dans son champ flags, l'initialisation ci-dessus est complètement ignorée, voir ci-dessous.

Tk_SetOptions est invoquée pour modifier les options de configuration en fonction des informations spécifiées dans une commande Tcl. La commande peut être celle qui crée un nouveau widget, ou une commande qui modifie les options d'un widget existant. Les arguments objc et objv décrivent les valeurs des arguments de la commande Tcl. Objv doit contenir un nombre pair d'objets : le premier objet de chaque paire donne le nom d'une option et le second objet donne la nouvelle valeur pour cette option. Tk_SetOptions recherche chaque nom dans optionTable, vérifie que la nouvelle valeur de l'option est conforme au type spécifié dans optionTable, et stocke la valeur de l'option dans l'enregistrement du widget fourni par recordPtr. Tk_SetOptions renvoie normalement TCL_OK. Si une erreur s'est produite (comme un nom d'option inconnu ou une valeur d'option illégale), TCL_ERROR est retourné et un message d'erreur est laissé dans le résultat de interp si interp n'est pas NULL.

Tk_SetOptions a deux fonctionnalités supplémentaires. Premièrement, si l'argument maskPtr n'est pas NULL, il pointe vers une valeur entière qui est remplie avec des informations sur les options qui ont été modifiées. Pour chaque option du modèle passé à Tk_CreateOptionTable, il existe un champ typeMask. Les bits de ce champ sont définis par le code qui implémente le widget ; par exemple, chaque bit peut correspondre à une option de configuration particulière. Alternativement, les bits peuvent être utilisés fonctionnellement. Par exemple, un bit pourrait être utilisé pour le redessin : toutes les options qui affectent l'affichage du widget, de telle sorte que la modification de l'option nécessite que le widget soit redessiné, pourraient avoir ce bit défini. Un autre bit pourrait indiquer que la géométrie du widget doit être recalculée, etc. Tk_SetOptions combine les champs typeMask par un OU bit à bit

DESCRIPTION

Toutes les options modifiées et renvoie cette valeur au niveau de *maskPtr ; l'appelant peut alors utiliser cette information pour s'optimiser afin de, par exemple, ne pas rediffuser le widget si les options modifiées n'affectent pas l'apparence du widget.

La seconde fonctionnalité supplémentaire de Tk_SetOptions concerne la récupération d'erreurs. Si une erreur survient lors du traitement des options de configuration, cette fonctionnalité permet de restaurer toutes les options de configuration à leurs valeurs précédentes. Les erreurs peuvent survenir soit lors du traitement des options dans Tk_SetOptions, soit plus tard chez l'appelant. Dans de nombreux cas, l'appelant effectue un traitement supplémentaire après le retour de Tk_SetOptions ; par exemple, il peut utiliser la valeur d'une option pour définir un traceur sur une variable et peut détecter une erreur si la variable est un tableau au lieu d'un scalaire. La récupération d'erreurs est activée en passant une valeur non nulle pour l'argument savePtr à Tk_SetOptions ; il doit s'agir d'un pointeur vers une structure Tk_SavedOptions non initialisée sur la pile de l'appelant. Tk_SetOptions écrase la structure pointée par savePtr avec des informations sur les anciennes valeurs de toutes les options modifiées par la procédure. Si Tk_SetOptions retourne avec succès, l'appelant utilise la structure de l'une des deux manières. Si l'appelant termine son traitement des nouvelles options sans aucune erreur, il doit passer la structure à Tk_FreeSavedOptions afin que les anciennes valeurs puissent être libérées. Si l'appelant détecte une erreur dans son traitement des nouvelles options, il doit passer la structure à Tk_RestoreSavedOptions, qui copiera les anciennes valeurs dans le enregistrement du widget et libérera les nouvelles valeurs. Si Tk_SetOptions détecte une erreur, il restaure automatiquement toutes les options qui avaient déjà été modifiées et laisse *savePtr dans un état vide : l'appelant n'a pas besoin d'appeler ni Tk_FreeSavedOptions ni Tk_RestoreSavedOptions. Si l'argument savePtr à Tk_SetOptions est NULL, alors Tk_SetOptions libère immédiatement chaque ancienne valeur d'option lorsqu'il définit une nouvelle valeur pour l'option. Dans ce cas, si une erreur survient dans la troisième option, les anciennes valeurs des deux premières options ne peuvent pas être restaurées.

Tk_GetOptionValue renvoie la valeur actuelle d'une option de configuration pour un widget particulier. L'argument namePtr contient le nom d'une option ; Tk_GetOptionValue utilise optionTable pour rechercher l'option et extraire sa valeur de l'enregistrement du widget pointé par recordPtr, puis renvoie un objet contenant cette valeur. Si une erreur survient (par exemple, parce que namePtr contient un nom d'option inconnu), NULL est renvoyé et un message d'erreur est laissé dans le résultat de interp à moins que interp ne soit NULL.

Tk_GetOptionInfo renvoie des informations sur les options de configuration dans un format adapté aux commandes de widget configure. Si l'argument namePtr n'est pas NULL, il pointe vers un objet qui donne le nom d'une option de configuration ; Tk_GetOptionInfo renvoie un objet contenant une liste de cinq éléments, qui sont le nom de l'option, le nom et la classe utilisés pour l'option dans la base de données d'options, la valeur par défaut de l'option, et la valeur actuelle de l'option. Si l'argument namePtr est NULL, alors Tk_GetOptionInfo renvoie des informations sur toutes les options sous la forme d'une liste de listes ; chaque sous-liste décrit une option. Les options synonymes sont traitées différemment selon que namePtr est NULL ou non : si namePtr est NULL, alors la sous-liste pour chaque option synonyme a seulement deux éléments, qui sont le nom de l'option et le nom de l'autre option à laquelle elle fait référence ; si namePtr n'est pas NULL et nomme une option synonyme, alors l'objet renvoyé est la liste de cinq éléments pour l'autre option à laquelle le synonyme fait référence. Si une erreur survient (par exemple, parce que namePtr contient un nom d'option inconnu), NULL est renvoyé et un message d'erreur est laissé dans le résultat de interp à moins que interp ne soit NULL.

Tk_FreeConfigOptions doit être invoqué lors de la suppression d'un widget. Il libère toutes les ressources associées à toutes les options de configuration définies dans recordPtr par optionTable.

La macro Tk_Offset est fournie comme moyen sûr de générer les valeurs objOffset et internalOffset pour les entrées dans les structures Tk_OptionSpec. Elle prend deux arguments : le nom d'un type d'enregistrement et le nom d'un champ dans cet enregistrement. Elle renvoie le décalage en octets du champ nommé dans les enregistrements du type donné.

TEMPLATES

Le tableau de structures Tk_OptionSpec passé à Tk_CreateOptionTable via son argument templatePtr décrit les options de configuration prises en charge par une classe particulière de widgets. Chaque structure spécifie une option de configuration et possède les champs suivants :

typedef struct {
    Tk_OptionType type;
    const char *optionName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int objOffset;
    int internalOffset;
    int flags;
    const void *clientData;
    int typeMask;
} Tk_OptionSpec;
Le champ type indique le type d'option de configuration (par exemple, TK_OPTION_COLOR pour une valeur de couleur, ou TK_OPTION_INT pour une valeur entière). Le type détermine comment la valeur de l'option est analysée (plus à ce sujet ci-dessous). Le champ optionName est une chaîne telle que -font ou -bg ; c'est le nom utilisé pour l'option dans les commandes Tcl et passé aux procédures via les arguments objc ou namePtr. Les champs dbName et dbClass sont utilisés par Tk_InitOptions pour rechercher une valeur par défaut pour cette option dans la base de données d'options ; si dbName est NULL, alors la base de données d'options n'est pas utilisée par Tk_InitOptions pour cette option. Le champ defValue spécifie une valeur par défaut pour cette option de configuration si aucune valeur n'est spécifiée dans la base de données d'options. Les champs objOffset et internalOffset indiquent où stocker la valeur de cette option dans les enregistrements de widgets (plus à ce sujet ci-dessous) ; les valeurs pour les champs objOffset et internalOffset doivent toujours être générées avec la macro Tk_Offset. Le champ flags contient des informations supplémentaires pour contrôler le traitement de cette option de configuration (voir ci-dessous pour les détails). ClientData fournit des données supplémentaires spécifiques au type nécessaires pour certains types. Par exemple, pour les types TK_OPTION_COLOR, clientData est une chaîne donnant la valeur par défaut à utiliser sur les écrans monochromes. Voir les descriptions des différents types ci-dessous pour les détails. Le dernier champ, typeMask, est utilisé par Tk_SetOptions pour renvoyer des informations sur les options qui ont été modifiées ; voir la description de Tk_SetOptions ci-dessus pour les détails.

Lorsque Tk_InitOptions et Tk_SetOptions stockent la valeur d'une option dans l'enregistrement du widget, ils peuvent le faire de deux manières. Si le champ objOffset de Tk_OptionSpec est supérieur ou égal à zéro, alors la valeur de l'option est stockée sous forme de (Tcl_Obj *) à l'emplacement de l'enregistrement du widget donné par objOffset. Si le champ internalOffset de Tk_OptionSpec est supérieur ou égal à zéro, alors la valeur de l'option est stockée sous une forme interne spécifique au type à l'emplacement de l'enregistrement du widget donné par internalOffset. Par exemple, si le type de l'option est TK_OPTION_INT, alors la forme interne est un entier. Si le champ objOffset ou internalOffset est négatif, la valeur n'est pas stockée sous cette forme. Au moins l'un des décalages doit être supérieur ou égal à zéro.

Le champ flags est constitué d'un ou plusieurs bits combinés par un OU. Les indicateurs suivants sont pris en charge :

TK_OPTION_NULL_OK
Si ce bit est défini pour une option, une chaîne vide sera acceptée comme valeur pour l'option et la forme interne résultante sera un pointeur NULL, une valeur zéro ou None, selon le type de l'option. Si l'indicateur n'est pas défini, les chaînes vides entraîneront des erreurs. TK_OPTION_NULL_OK est généralement utilisé pour permettre à une fonctionnalité d'être désactivée entièrement, par exemple pour définir une valeur de curseur à None afin qu'une fenêtre hérite simplement du curseur de son parent. Tous les types d'options ne prennent pas en charge l'indicateur TK_OPTION_NULL_OK ; pour ceux qui le font, il y a une indication explicite de ce fait dans les descriptions ci-dessous.
TK_OPTION_DONT_SET_DEFAULT
Si ce bit est défini pour une option, aucune valeur par défaut ne sera définie dans Tk_InitOptions pour cette option. Ni la base de données d'options, ni aucune valeur système par défaut, ni optionTable ne sont utilisés pour donner une valeur par défaut à cette option. Au lieu de cela, il est supposé que l'appelant a déjà fourni une valeur par défaut dans le code du widget.

Le champ type de chaque structure Tk_OptionSpec détermine comment analyser la valeur de cette option de configuration. La valeur légale pour type, et les actions correspondantes, sont décrites ci-dessous. Si le type nécessite une valeur tkwin à passer aux procédures telles que Tk_SetOptions, ou s'il utilise le champ clientData du Tk_OptionSpec, alors il est indiqué explicitement ; s'il n'est pas mentionné, le type ne nécessite ni tkwin ni clientData.

TK_OPTION_ANCHOR
La valeur doit être une position d'ancrage standard telle que ne ou center. La forme interne est une valeur Tk_Anchor comme celles renvoyées par Tk_GetAnchorFromObj.
TK_OPTION_BITMAP
La valeur doit être un nom de bitmap Tk standard. La forme interne est un jeton Pixmap comme ceux renvoyés par Tk_AllocBitmapFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge l'indicateur TK_OPTION_NULL_OK.
TK_OPTION_BOOLEAN
La valeur doit être une valeur booléenne standard telle que true ou no. La forme interne est un entier avec la valeur 0 ou 1. Notez que si le champ objOffset n'est pas utilisé, les informations sur la valeur originale de cette option seront perdues.
TK_OPTION_BORDER
La valeur doit être un nom de couleur standard tel que red ou #ff8080. La forme interne est un jeton Tk_3DBorder comme ceux renvoyés par Tk_Alloc3DBorderFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge l'indicateur TK_OPTION_NULL_OK.

Types d'options Tk

Les types d'options suivants sont pris en charge par la procédure Tk_SetOptions. La colonne Type indique le type d'option dans la structure Tk_OptionSpec, la colonne Valeur décrit le format de la valeur de la chaîne de configuration, et la colonne Interne décrit le type de la valeur telle qu'elle est stockée dans l'enregistrement du widget.

TK_OPTION_BOOLEAN
La valeur doit être 0, 1, on, off, true, false, yes ou no. La forme interne est un entier C int (0 ou 1).
TK_OPTION_BITMAP
La valeur doit être un nom d'image bitmap, tel que défini par la commande bitmap de Tcl, ou une chaîne vide. La forme interne est un Picture * comme celui renvoyé par Tk_AllocBitmapFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_BORDER
La valeur doit être une spécification de bordure valide, telle que définie par la commande border de Tk. La forme interne est un Tk_3DBorder * comme celui renvoyé par Tk_Alloc3DBorderFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_BUTTINGTON
La valeur doit être une valeur de justification standard telle que left. La forme interne est un Tk_Justify comme les valeurs renvoyées par Tk_GetJustifyFromObj.
TK_OPTION_CAP_STYLE
La valeur doit être un style de terminaison de ligne standard tel que butt, round ou projecting. La forme interne est un entier comme CAP_BUTT, CAP_ROUND ou CAP_PROJECTING.
TK_OPTION_COLOR
La valeur doit être un nom de couleur standard tel que red ou #ff8080. La forme interne est un jeton (XColor *) comme ceux renvoyés par Tk_AllocColorFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_CURSOR
La valeur doit être un nom de curseur standard tel que cross ou @foo. La forme interne est un jeton Tk_Cursor comme ceux renvoyés par Tk_AllocCursorFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et lorsque l'option est définie, le curseur de la fenêtre est modifié en appelant XDefineCursor. Ce type d'option prend également en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_CUSTOM
Cette option permet aux applications de définir de nouveaux types d'options. Le champ clientData des points d'entrée pointe vers une structure définissant le nouveau type d'option. Voir la section TYPES D'OPTIONS PERSONNALISÉES ci-dessous pour plus de détails.
TK_OPTION_DOUBLE
La valeur de chaîne doit être un nombre à virgule flottante au format accepté par strtol. La forme interne est une valeur double C. Ce type d'option prend en charge le drapeau TK_OPTION_NULL_OK ; si une valeur NULL est définie, la représentation interne est mise à zéro.
TK_OPTION_END
Marque la fin du modèle. Il doit y avoir une structure Tk_OptionSpec avec type TK_OPTION_END à la fin de chaque modèle. Si le champ clientData de cette structure n'est pas NULL, il pointe vers un tableau supplémentaire de Tk_OptionSpec, qui est lui-même terminé par une autre entrée TK_OPTION_END. Les modèles peuvent être enchaînés à n'importe quelle profondeur. Cette fonctionnalité permet de partager des options communes entre plusieurs classes de widgets.
TK_OPTION_FONT
La valeur doit être un nom de police standard tel que Times 16. La forme interne est un handle Tk_Font comme ceux renvoyés par Tk_AllocFontFromObj. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions, et il prend en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_INT
La valeur de chaîne doit être un entier au format accepté par strtol (par exemple, les préfixes 0 et 0x peuvent être utilisés pour spécifier respectivement les nombres octaux ou hexadécimaux). La forme interne est une valeur int C.
TK_OPTION_JUSTIFY
La valeur doit être une valeur de justification standard telle que left. La forme interne est un Tk_Justify comme les valeurs renvoyées par Tk_GetJustifyFromObj.
TK_OPTION_PIXELS
La valeur doit spécifier une distance d'écran telle que 2i ou 6.4. La forme interne est une valeur entière donnant une distance en pixels, comme les valeurs renvoyées par Tk_GetPixelsFromObj. Notez que si le champ objOffset n'est pas utilisé, les informations sur la valeur d'origine de cette option seront perdues. Voir OBJOFFSET VS. INTERNALOFFSET ci-dessous pour plus de détails. Ce type d'option prend en charge le drapeau TK_OPTION_NULL_OK ; si une valeur NULL est définie, la représentation interne est définie à INT_MIN.
TK_OPTION_RELIEF
La valeur doit être un relief standard tel que raised. La forme interne est une valeur de relief entière telle que TK_RELIEF_RAISED. Ce type d'option prend en charge le drapeau TK_OPTION_NULL_OK ; si une valeur NULL est définie, la représentation interne est définie à TK_RELIEF_NULL.
TK_OPTION_STRING
La valeur peut être n'importe quelle chaîne. La forme interne est un pointeur (char *) qui pointe vers une copie allouée dynamiquement de la valeur. Ce type d'option prend en charge le drapeau TK_OPTION_NULL_OK.
TK_OPTION_STRING_TABLE
Pour ce type, clientData est un pointeur vers un tableau de chaînes adapté à être passé à Tcl_GetIndexFromObj. La valeur doit être l'une des chaînes du tableau, ou une abréviation unique d'une des chaînes. La forme interne est un entier donnant l'indice dans le tableau de la chaîne correspondante, comme la valeur de retour de Tcl_GetStringFromObj. Ce type d'option prend en charge le drapeau TK_OPTION_NULL_OK ; si une valeur NULL est définie, la représentation interne est définie à -1.
TK_OPTION_SYNONYM
Ce type est utilisé pour fournir des noms alternatifs à une option (par exemple, -bg est souvent utilisé comme synonyme de -background). Le champ clientData est une chaîne qui donne le nom d'une autre option dans le même tableau. Chaque fois que l'option synonyme est utilisée, les informations de l'autre option seront utilisées à la place.
TK_OPTION_WINDOW
La valeur doit être un nom de chemin de fenêtre. La forme interne est un jeton Tk_Window pour la fenêtre. Ce type d'option nécessite que tkwin soit fourni aux procédures telles que Tk_SetOptions (afin d'identifier l'application), et il prend en charge le drapeau TK_OPTION_NULL_OK.

PROBLÈMES DE GESTION DE LA MÉMOIRE

Si un champ d'un enregistrement de widget a son décalage stocké dans le champ objOffset ou internalOffset d'une structure Tk_OptionSpec, alors les procédures décrites ici géreront toutes les allocations de mémoire et les problèmes de gestion des ressources associés au champ. Lorsque la valeur d'une option est modifiée, Tk_SetOptions (ou Tk_FreeSavedOptions) libérera automatiquement toutes les ressources associées à l'ancienne valeur, telles que les Tk_Fonts pour les options TK_OPTION_FONT ou la mémoire allouée dynamiquement pour les options TK_OPTION_STRING. Pour une option stockée sous forme d'objet à l'aide du champ objOffset d'une Tk_OptionSpec, l'enregistrement du widget partage l'objet pointé par la valeur objv de l'appel à Tk_SetOptions. Le compteur de références pour cet objet est incrémenté lorsqu'un pointeur vers celui-ci est stocké dans l'enregistrement du widget et décrémenté lorsque l'option est modifiée. Lorsque le widget est supprimé, Tk_FreeConfigOptions doit être appelé ; il libérera les ressources associées à toutes les options et décrémentera les compteurs de références pour tous les objets.

Cependant, le code du widget est responsable du stockage de NULL ou None dans tous les champs de pointeur et de jeton avant d'appeler Tk_InitOptions. Ceci est nécessaire pour permettre un nettoyage approprié dans le cas rare où une erreur se produit dans Tk_InitOptions.

OBJOFFSET VS INTERNALOFFSET

Dans la plupart des cas, il est plus simple d'utiliser le champ internalOffset d'une structure Tk_OptionSpec et non le champ objOffset. Cela rend la forme interne de la valeur immédiatement disponible pour le code du widget, de sorte que la valeur n'a pas à être extraite d'un objet chaque fois qu'elle est utilisée. Cependant, il y a deux cas où le champ objOffset est utile. Le premier cas concerne les options TK_OPTION_PIXELS. Dans ce cas, la forme interne est une valeur entière en pixels qui n'est valide que pour un écran particulier. Si la valeur de l'option est récupérée, elle sera renvoyée sous forme de simple nombre. Par exemple, après la commande .b configure -borderwidth 2m, la commande .b configure -borderwidth pourrait renvoyer 7, qui est la valeur entière en pixels correspondant à 2m. Malheureusement, cela perd la valeur d'origine indépendante de l'écran. Ainsi, pour les options TK_OPTION_PIXELS, il est préférable d'utiliser le champ objOffset. Dans ce cas, la valeur d'origine de l'option est conservée dans l'objet et peut être renvoyée lorsque l'option est récupérée. Dans la plupart des cas, il est pratique d'utiliser également le champ internalOffset, de sorte que la valeur entière soit immédiatement disponible pour utilisation dans le code du widget (alternativement, Tk_GetPixelsFromObj peut être utilisé pour extraire la valeur entière de l'objet chaque fois qu'elle est nécessaire). Notez que le problème de perte d'informations lors des récupérations n'existe que pour les options TK_OPTION_PIXELS.

La deuxième raison d'utiliser le champ objOffset est de mettre en œuvre de nouveaux types d'options non pris en charge par ces procédures. Pour mettre en œuvre un nouveau type d'option, vous pouvez utiliser TK_OPTION_STRING comme type dans la structure Tk_OptionSpec et définir le champ objOffset mais pas le champ internalOffset. Ensuite, après avoir appelé Tk_SetOptions, convertissez vous-même l'objet en forme interne.

Les widgets Ttk ne prennent pas en charge le mécanisme internalOffset. Les valeurs d'options des widgets Ttk sont toujours stockées sous forme de (Tcl_Obj *), ce qui signifie que le champ objOffset doit être utilisé.

TYPES D'OPTIONS PERSONNALISÉES

Les applications peuvent étendre les types de configuration intégrés avec des types de configuration supplémentaires en écrivant des procédures pour analyser, imprimer, libérer et restaurer des copies enregistrées du type et en créant une structure pointant vers ces procédures :

typedef struct Tk_ObjCustomOption {
    const char *name;
    Tk_CustomOptionSetProc *setProc;
    Tk_CustomOptionGetProc *getProc;
    Tk_CustomOptionRestoreProc *restoreProc;
    Tk_CustomOptionFreeProc *freeProc;
    ClientData clientData;
} Tk_ObjCustomOption;
typedef int Tk_CustomOptionSetProc(
    ClientData clientData,
    Tcl_Interp *interp,
    Tk_Window tkwin,
    Tcl_Obj **valuePtr,
    char *recordPtr,
    int internalOffset,
    char *saveInternalPtr,
    int flags);
typedef Tcl_Obj *Tk_CustomOptionGetProc(
    ClientData clientData,
    Tk_Window tkwin,
    char *recordPtr,
    int internalOffset);
typedef void Tk_CustomOptionRestoreProc(
    ClientData clientData,
    Tk_Window tkwin,
    char *internalPtr,
    char *saveInternalPtr);
typedef void Tk_CustomOptionFreeProc(
    ClientData clientData,
    Tk_Window tkwin,
    char *internalPtr);

La structure Tk_ObjCustomOption contient six champs : un nom pour le type d'option personnalisé ; des pointeurs vers les quatre procédures ; et une valeur clientData à passer à ces procédures lorsqu'elles sont appelées. Le va clientData

lue pointe généralement vers une structure contenant les informations nécessaires aux procédures lors de l'analyse et de l'impression des options. RestoreProc et freeProc peuvent être NULL, indiquant qu'aucune fonction ne doit être appelée pour ces opérations.

La procédure setProc est appelée par Tk_SetOptions pour convertir un Tcl_Obj en une représentation interne et stocker la valeur résultante dans l'enregistrement du widget. Les arguments sont :

clientData
Une copie du champ clientData de la structure Tk_ObjCustomOption.
interp
Un pointeur vers un interpréteur Tcl, utilisé pour signaler les erreurs.
Tkwin
Une copie de l'argument tkwin de Tk_SetOptions.
valuePtr
Un pointeur vers une référence à un Tcl_Obj décrivant la nouvelle valeur de l'option ; elle peut avoir été spécifiée explicitement dans l'appel à Tk_SetOptions, provenir de la base de données d'options ou d'une valeur par défaut. Si l'objOffset de l'option est non négatif (la valeur de l'option est stockée comme un (Tcl_Obj *) dans l'enregistrement du widget), le pointeur Tcl_Obj référencé par valuePtr est le pointeur qui sera stocké à l'objOffset de l'option. SetProc peut modifier la valeur si nécessaire ; par exemple, setProc peut changer la valeur à NULL pour prendre en charge l'indicateur TK_OPTION_NULL_OK.
recordPtr
Un pointeur vers le début de l'enregistrement du widget à modifier.
internalOffset
Décalage en octets depuis le début de l'enregistrement du widget vers l'emplacement où la représentation interne de la valeur de l'option doit être placée.
saveInternalPtr
Un pointeur vers le stockage alloué dans une structure Tk_SavedOptions pour la représentation interne de la valeur de l'option d'origine. Avant de définir l'option avec sa nouvelle valeur, setProc doit définir la valeur référencée par saveInternalPtr à la valeur d'origine de l'option afin de prendre en charge Tk_RestoreSavedOptions.
flags
Une copie du champ flags de la structure Tk_OptionSpec pour l'option.

SetProc retourne un résultat Tcl standard : TCL_OK pour indiquer un traitement réussi, ou TCL_ERROR pour indiquer un échec de quelque nature que ce soit. Un message d'erreur peut être laissé dans l'interpréteur Tcl fourni par interp en cas d'erreur.

La procédure getProc est appelée par Tk_GetOptionValue et Tk_GetOptionInfo pour récupérer une représentation Tcl_Obj de la représentation interne d'une option. L'argument clientData est une copie du champ clientData de la structure Tk_ObjCustomOption. Tkwin est une copie de l'argument tkwin de Tk_GetOptionValue ou Tk_GetOptionInfo. RecordPtr est un pointeur vers le début de l'enregistrement du widget à interroger. InternalOffset est le décalage en octets depuis le début de l'enregistrement du widget jusqu'à l'emplacement où la représentation interne de la valeur de l'option est stockée. GetProc doit retourner un pointeur vers un Tcl_Obj représentant la valeur de l'option.

La procédure restoreProc est appelée par Tk_RestoreSavedOptions pour restaurer une représentation interne précédemment sauvegardée d'une valeur d'option personnalisée. L'argument clientData est une copie du champ clientData de la structure Tk_ObjCustomOption. Tkwin est une copie de l'argument tkwin de Tk_GetOptionValue ou Tk_GetOptionInfo. InternalPtr est un pointeur vers l'emplacement où la représentation interne de la valeur de l'option est stockée. SaveInternalPtr est un pointeur vers la valeur sauvegardée. RestoreProc doit copier la valeur de saveInternalPtr vers internalPtr pour restaurer la valeur. RestoreProc n'a pas besoin de libérer la mémoire associée à internalPtr ou saveInternalPtr ; freeProc sera appelée pour libérer cette mémoire si nécessaire. RestoreProc n'a pas de valeur de retour.

La procédure freeProc est appelée par Tk_SetOptions et Tk_FreeSavedOptions pour libérer tout stockage alloué pour la représentation interne d'une option personnalisée. L'argument clientData est une copie du champ clientData de la structure Tk_ObjCustomOption. Tkwin est une copie de l'argument tkwin de Tk_GetOptionValue ou Tk_GetOptionInfo. InternalPtr est un pointeur vers l'emplacement où la représentation interne de la valeur de l'option est stockée. Le freeProc doit libérer tout stockage associé à l'option. FreeProc n'a pas de valeur de retour.
