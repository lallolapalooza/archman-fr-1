getOpenFile(3) Documentation Perl fournie par l'utilisateur getOpenFile(3)

NOM

Tk::getOpenFile - ouvre une boîte de dialogue pour que l'utilisateur sélectionne un fichier à ouvrir.

SYNTAXE

    $widget->getOpenFile(?-option=>valeur, ...>?)

    $widget->getSaveFile(?-option=>valeur, ...>?)

DESCRIPTION

Les méthodes getOpenFile et getSaveFile ouvrent une boîte de dialogue pour que l'utilisateur sélectionne un fichier à ouvrir ou à enregistrer.

La méthode getOpenFile est généralement associée à la commande Ouvrir du menu Fichier. Son but est de permettre à l'utilisateur de sélectionner uniquement un fichier existant. Si l'utilisateur saisit un fichier inexistant, la boîte de dialogue affiche une erreur et demande à l'utilisateur de faire une autre sélection. Si une application autorise l'utilisateur à créer de nouveaux fichiers, elle devrait le faire en fournissant une commande distincte Nouveau dans le menu.

La méthode getSaveFile est généralement associée à la commande Enregistrer sous du menu Fichier. Si l'utilisateur saisit un fichier qui existe déjà, la boîte de dialogue demande confirmation à l'utilisateur pour savoir si le fichier existant doit être écrasé ou non.

Si l'utilisateur sélectionne un fichier, les commandes getOpenFile et getSaveFile retournent le chemin complet de ce fichier. Si l'utilisateur annule l'opération, les deux commandes retournent une valeur indéfinie.

Les paires option-valeur suivantes sont possibles en tant qu'arguments de ligne de commande pour ces deux commandes :

-extensionpardefaut => extension
Spécifie une chaîne qui sera ajoutée au nom du fichier si l'utilisateur saisit un nom de fichier sans extension. La valeur par défaut est la chaîne vide, ce qui signifie qu'aucune extension ne sera ajoutée au nom du fichier dans tous les cas. Cette option est ignorée sur la plateforme Macintosh, qui n'exige pas d'extensions pour les noms de fichiers, et l'implémentation UNIX devine des valeurs raisonnables à partir de l'option -typesdefichier lorsque celle-ci n'est pas fournie.
-typesdefichier => [motifFichier ?, ...?]
Si une boîte de liste Types de fichier existe dans la boîte de dialogue de fichier sur la plateforme particulière, cette option donne les typesdefichier dans cette boîte de liste. Lorsque l'utilisateur choisit un type de fichier dans la boîte de liste, seuls les fichiers de ce type sont listés. Si cette option n'est pas spécifiée, ou si elle est définie sur la liste vide, ou si la boîte de liste Types de fichier n'est pas supportée par la plateforme particulière, alors tous les fichiers sont listés indépendamment de leurs types. Voir "SPÉCIFICATION DES MOTIFS DE FICHIER" ci-dessous pour une discussion sur le contenu des motifFichiers.
-repertoireinitial => repertoire
Spécifie que les fichiers dans le repertoire doivent être affichés lorsque la boîte de dialogue s'ouvre. Si ce paramètre n'est pas spécifié, alors les fichiers dans le répertoire de travail courant sont affichés. Cette option peut ne pas toujours fonctionner sur Macintosh. Ce n'est pas un bug. Plutôt, le panneau de configuration Contrôles généraux sur Mac permet à l'utilisateur final de remplacer le répertoire par défaut de l'application.
-fichierinitial => nomFichier
Spécifie un nom de fichier à afficher dans la boîte de dialogue lorsqu'elle s'ouvre. Cette option est ignorée par la méthode getOpenFile.
-multiple
Permet à l'utilisateur de choisir plusieurs fichiers dans la boîte de dialogue Ouvrir. Sur Macintosh, ceci n'est disponible que lorsque les Services de Navigation sont installés.
-message => chaine
Spécifie un message à inclure dans la zone client de la boîte de dialogue. Ceci n'est disponible que sur Macintosh, et uniquement lorsque les Services de Navigation sont installés.
-titre => chaineTitre
Spécifie une chaîne à afficher comme titre de la boîte de dialogue. Si cette option n'est pas spécifiée, alors un titre par défaut est affiché. Cette option est ignorée sur la plateforme Macintosh.

SPÉCIFICATION DES MOTIFS DE FICHIER

Les motifFichiers donnés par l'option -typesdefichier sont une liste de motifs de fichiers. Chaque motif de fichier est une liste de la forme

typeNom [extension ?extension ...?] ?[typeMac ?typeMac ...?]?

typeNom est le nom du type de fichier décrit par ce motif de fichier et est la chaîne de texte qui apparaît dans la boîte de liste Types de fichier. extension est une extension de fichier pour ce motif de fichier. typeMac est un type de fichier Macintosh de quatre caractères. La liste des typeMacs est facultative et peut être omise pour les applications qui n'ont pas besoin de s'exécuter sur la plateforme Macintosh.

Plusieurs motifs de fichier peuvent avoir le même typeNom, auquel cas ils se réfèrent au même type de fichier et partagent la même entrée dans la boîte de liste. Lorsque l'utilisateur sélectionne une entrée dans la boîte de liste, tous les fichiers qui correspondent à au moins un des motifs de fichier correspondant à cette entrée sont listés. Habituellement, chaque motif de fichier correspond à un type de fichier distinct. L'utilisation de plus d'un motif de fichier pour un seul type de fichier n'est nécessaire que sur la plateforme Macintosh.

Sur la plateforme Macintosh, un fichier correspond à un motif de fichier si son nom correspond à au moins une des extensions ET s'il appartient à au moins un des typeMacs du motif de fichier. Par exemple, le motif de fichier Fichiers source C dans le code d'exemple correspond aux fichiers qui ont une extension \.c ET appartiennent au typeMac TEXT. Pour utiliser la règle OU à la place, vous pouvez utiliser deux motifs de fichier, un avec les extensions uniquement et l'autre avec le typeMac uniquement. Le type de fichier Fichiers GIF dans le code d'exemple correspond aux fichiers qui ont SOIT une extension \.gif SOIT appartiennent au typeMac GIFF.

Sur les plateformes Unix et Windows, un fichier correspond à un motif de fichier si son nom correspond à au moins une des extensions du motif de fichier. Les typeMacs sont ignorés.

SPÉCIFICATION DES EXTENSIONS

Sur les plateformes Unix et Macintosh, les extensions sont mises en correspondance à l'aide de la correspondance de motifs de style glob. Sur les plateformes Windows, les extensions sont mises en correspondance par le système d'exploitation sous-jacent. Les types d'extensions possibles sont : (1) l'extension spéciale * correspond à n'importe quel fichier ; (2) l'extension spéciale "" correspond à n'importe quel fichier n'ayant pas d'extension (c'est-à-dire que le nom de fichier ne contient pas de point) ; (3) toute chaîne de caractères ne contenant aucun caractère de métacaractère (* et ?).

En raison des différentes règles de correspondance de motifs sur les plateformes, pour assurer la portabilité, les caractères de métacaractères ne sont pas autorisés dans les extensions, sauf comme dans l'extension spéciale *. Les extensions sans point (par exemple, ~) sont autorisées mais peuvent ne pas fonctionner sur toutes les plateformes.

AVERTISSEMENTS

Voir "AVERTISSEMENTS" dans Tk::chooseDirectory.

EXEMPLE

my $types = [
    ['Fichiers texte',       ['.txt', '.text']],
    ['Scripts TCL',      '.tcl'           ],
    ['Fichiers source C',   '.c',      'TEXT'],
    ['Fichiers GIF',        '.gif',          ],
    ['Fichiers GIF',        '',        'GIFF'],
    ['Tous les fichiers',        '*',             ],
];
my $filename = $widget->getOpenFile(-typesdefichier=>$types);
if ($filename ne "") {
    # Ouvrir le fichier ...
}
