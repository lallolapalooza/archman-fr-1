Tk_CreateGenericHandler(3) Procédures de la bibliothèque Tk Tk_CreateGenericHandler(3)

NOM

Tk_CreateGenericHandler, Tk_DeleteGenericHandler - associer une procédure de rappel à tous les événements X

SYNTAXE

#include <tk.h>

Tk_CreateGenericHandler(proc, clientData)

Tk_DeleteGenericHandler(proc, clientData)

ARGUMENTS

Tk_GenericProc *proc (in)
Procédure à appeler chaque fois qu'un événement X se produit sur n'importe quel écran.
ClientData clientData (in)
Valeur de mot arbitraire à passer à proc.

DESCRIPTION

Tk_CreateGenericHandler arrange pour que proc soit appelée à l'avenir chaque fois qu'un événement X se produit. Ce mécanisme n'est *pas* destiné à la distribution des événements X sur les fenêtres gérées par Tk (vous devriez utiliser Tk_CreateEventHandler à cet effet). Tk_CreateGenericHandler est destiné à d'autres usages, tels que le traçage des événements X, la surveillance des événements sur les fenêtres qui n'appartiennent pas à Tk, l'accès aux bibliothèques liées à X qui n'ont pas été conçues à l'origine pour être utilisées avec Tk, et ainsi de suite.

Le rappel à proc sera effectué par Tk_HandleEvent ; ce mécanisme ne fonctionne que dans les programmes qui distribuent les événements via Tk_HandleEvent (ou via d'autres procédures Tk qui appellent Tk_HandleEvent, telles que Tcl_DoOneEvent ou Tk_MainLoop).

Proc doit avoir des arguments et un résultat qui correspondent au type Tk_GenericProc :

typedef int Tk_GenericProc(
        ClientData clientData,
        XEvent *eventPtr);
Le paramètre clientData de proc est une copie de l'argument clientData donné à Tk_CreateGenericHandler lors de la création du rappel. Typiquement, clientData pointe vers une structure de données contenant des informations spécifiques à l'application sur la manière de gérer les événements. EventPtr est un pointeur vers l'événement X.

Chaque fois qu'un événement X est traité par Tk_HandleEvent, proc est appelée. La valeur de retour de proc est normalement 0. Une valeur de retour non nulle indique que l'événement ne doit pas être traité davantage ; c'est-à-dire que proc a effectué tout le traitement autorisé pour l'événement.

S'il existe plusieurs gestionnaires d'événements génériques, chacun est appelé pour chaque événement, dans l'ordre dans lequel ils ont été établis.

Tk_DeleteGenericHandler peut être appelée pour supprimer un gestionnaire d'événements générique précédemment créé : elle supprime chaque gestionnaire qu'elle trouve qui correspond aux arguments proc et clientData. Si aucun gestionnaire de ce type n'existe, Tk_DeleteGenericHandler retourne sans rien faire. Bien que Tk le supporte, il est probablement déconseillé d'avoir plus d'un rappel avec les mêmes arguments proc et clientData.

L'établissement d'un gestionnaire d'événements générique ne garantit en rien que le processus recevra réellement les événements X que le gestionnaire souhaite traiter. Par exemple, il incombe à l'appelant d'invoquer XSelectInput pour sélectionner les événements désirés, si cela est nécessaire.
