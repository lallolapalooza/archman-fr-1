NOM

Traits — Liste les traits utilisés par le Motif Toolkit.

DESCRIPTION

Un trait est une caractéristique d'un widget. Un widget possédant un trait particulier annonce une capacité particulière à d'autres widgets. Le tableau suivant résume les traits Motif standard.

Objectif de chaque trait
Nom du trait Un widget possédant ce trait peut faire ce qui suit :
XmQTaccessTextual Afficher un seul bloc de texte principal.
XmQTactivatable Être un bouton de commande dans une boîte de dialogue.
XmQTcareParentVisual Emprunter les informations visuelles de son parent.
XmQTcontainer Gérer les enfants de type élément conteneur.
XmQTcontainerItem Être un enfant d'un widget conteneur.
XmQTdialogShellSavvy Être un enfant de DialogShell.
XmQTjoinSide S'attacher à un côté d'un parent approprié.
XmQTmenuSavvy Être un enfant de menu.
XmQTmenuSystem Gérer un système de menu.
XmQTnavigator Agir comme un navigateur pour un widget défilant.
XmQTscrollFrame Gérer un ou plusieurs widgets navigateurs.
XmQTspecifyRenderTable Fournir les noms de ses tables de rendu par défaut.
XmQTtakesDefault Modifier son apparence pour indiquer qu'il est le bouton par défaut.
XmQTtransfer Transférer des données vers d'autres widgets et/ou recevoir des données d'autres widgets.

Les traits ne sont pas souvent utilisés dans les programmes d'application Motif. Cependant, les traits sont très importants pour les développeurs de widgets. Pour des détails complets sur les traits, consultez le Motif Widget Writer's Guide.

Le tableau suivant liste les noms de tous les widgets et gadgets de l'ensemble standard de widgets Motif qui possèdent un trait particulier. Par exemple, le tableau suivant montre que le trait XmQTcontainerItem est possédé par le XmIconGadget. Comme le suggère le tableau, certains traits sont possédés par plusieurs des widgets Motif standard.

Le tableau suivant résume la manière dont les widgets Motif standard accèdent aux traits. Il existe deux manières générales pour un widget d'accéder aux traits d'un autre widget.

Une façon est pour un widget de demander à un autre widget s'il détient un trait particulier. Par exemple, XmBulletinBoard demande à chacun de ses widgets enfants s'ils détiennent le trait XmQTtakesDefault. XmBulletinBoard n'appelle aucune des méthodes de trait de XmQTtakesDefault.

Un autre type d'accès est lorsqu'un widget appelle les méthodes de trait d'un autre widget. Par exemple, XmBulletinBoard appelle la méthode de trait getRenderTable du trait XmQTspecifyRenderTable.

NOM

Traits — Les traits.

DESCRIPTION

Un trait est une sorte de classe virtuelle abstraite (ou interface) qui décrit un ensemble de méthodes qui doivent être implémentées par une classe ou un objet. Les traits sont utilisés pour la programmation orientée objet et sont similaires aux interfaces dans d'autres langages.

Les traits sont un moyen de réutiliser du code dans la programmation orientée objet, de manière similaire à l'héritage. Contrairement à l'héritage, les traits n'introduisent pas de relation "est un". Au lieu de cela, ils introduisent un comportement, qui peut être combiné avec d'autres comportements.

Les traits sont utiles pour résoudre le problème de l'héritage multiple. Dans les langages qui ne prennent pas en charge l'héritage multiple, les traits peuvent être utilisés pour inclure des méthodes de plusieurs sources dans une seule classe. Les traits peuvent également être utilisés pour fournir des implémentations par défaut pour certaines méthodes, qui peuvent être remplacées par des classes qui utilisent les traits.
