TRUNCATE(7) Documentation PostgreSQL 18.1 TRUNCATE(7)

NOM

TRUNCATE - vider une table ou un ensemble de tables

SYNTAXE

TRUNCATE [ TABLE ] [ ONLY ] nom [ * ] [, ... ]
    [ RESTART IDENTITY | CONTINUE IDENTITY ] [ CASCADE | RESTRICT ]

DESCRIPTION

TRUNCATE supprime rapidement toutes les lignes d'un ensemble de tables. Cela a le même effet qu'un DELETE non qualifié sur chaque table, mais comme il ne parcourt pas réellement les tables, il est plus rapide. De plus, il récupère immédiatement l'espace disque, au lieu de nécessiter une opération VACUUM ultérieure. Ceci est particulièrement utile sur les grandes tables.

PARAMETRES

nom

Le nom (éventuellement qualifié par un schéma) d'une table à vider. Si ONLY est spécifié avant le nom de la table, seule cette table est vidée. Si ONLY n'est pas spécifié, la table et toutes ses tables descendantes (le cas échéant) sont vidées. Optionnellement, * peut être spécifié après le nom de la table pour indiquer explicitement que les tables descendantes sont incluses.

RESTART IDENTITY

Redémarre automatiquement les séquences appartenant aux colonnes des tables vidées.

CONTINUE IDENTITY

Ne modifie pas les valeurs des séquences. C'est le défaut.

CASCADE

Vide automatiquement toutes les tables qui ont des références de clé étrangère vers l'une des tables nommées, ou vers toute autre table ajoutée au groupe en raison de CASCADE.

RESTRICT

Refuse de vider si l'une des tables a des références de clé étrangère provenant de tables qui ne sont pas listées dans la commande. C'est le défaut.

NOTES

Vous devez avoir le privilège TRUNCATE sur une table pour la vider.

TRUNCATE acquiert un verrou ACCESS EXCLUSIVE sur chaque table sur laquelle il opère, ce qui bloque toutes les autres opérations concurrentes sur cette table. Lorsque RESTART IDENTITY est spécifié, toute séquence à redémarrer est également verrouillée exclusivement. Si un accès concurrent à une table est requis, alors la commande DELETE doit être utilisée à la place.

TRUNCATE ne peut pas être utilisé sur une table qui a des références de clé étrangère provenant d'autres tables, à moins que toutes ces tables ne soient également vidées dans la même commande. Vérifier la validité dans de tels cas nécessiterait des parcours de table, et le but est justement de ne pas en faire. L'option CASCADE peut être utilisée pour inclure automatiquement toutes les tables dépendantes — mais soyez très prudent lorsque vous utilisez cette option, sinon vous pourriez perdre des données que vous n'aviez pas l'intention de perdre ! Notez en particulier que lorsque la table à vider est une partition, les partitions sœurs ne sont pas touchées, mais le déclenchement en cascade se produit vers toutes les tables référençant et toutes leurs partitions sans distinction.

TRUNCATE ne déclenchera aucun trigger ON DELETE qui pourrait exister pour les tables. Mais il déclenchera des triggers ON TRUNCATE. Si des triggers ON TRUNCATE sont définis pour l'une des tables, tous les triggers BEFORE TRUNCATE sont déclenchés avant que toute opération de vidage ne se produise, et tous les triggers AFTER TRUNCATE sont déclenchés après que le dernier vidage ait été effectué et que les séquences aient été réinitialisées. Les triggers seront déclenchés dans l'ordre où les tables doivent être traitées (d'abord celles listées dans la commande, puis celles qui ont été ajoutées en raison du déclenchement en cascade).

TRUNCATE n'est pas sûr MVCC. Après le vidage, la table apparaîtra vide pour les transactions concurrentes, si elles utilisent un instantané pris avant le vidage. Voir la Section 13.6 pour plus de détails.

TRUNCATE est sûr en transaction pour ce qui est des données dans les tables : le vidage sera annulé en toute sécurité si la transaction environnante ne valide pas.

Lorsque RESTART IDENTITY est spécifié, les opérations implicites ALTER SEQUENCE RESTART sont également effectuées de manière transactionnelle ; c'est-à-dire qu'elles seront annulées si la transaction environnante ne valide pas. Sachez que si des opérations supplémentaires sur les séquences sont effectuées sur les séquences redémarrées avant que la transaction ne soit annulée, les effets de ces opérations sur les séquences seront annulés, mais pas leurs effets sur currval() ; c'est-à-dire qu'après la transaction, currval() continuera de refléter la dernière valeur de séquence obtenue à l'intérieur de la transaction échouée, même si la séquence elle-même n'est peut-être plus cohérente avec cela. Ceci est similaire au comportement habituel de currval() après une transaction échouée.

TRUNCATE peut être utilisé pour les tables étrangères si elles sont prises en charge par le connecteur de données étranger, par exemple, voir postgres_fdw.

EXEMPLES

Vider les tables bigtable et fattable :

TRUNCATE bigtable, fattable;

Idem, et aussi réinitialiser tous les générateurs de séquences associés :

TRUNCATE bigtable, fattable RESTART IDENTITY;

Vider la table othertable, et déclencher en cascade vers toutes les tables qui référencent othertable via des contraintes de clé étrangère :

TRUNCATE othertable CASCADE;

COMPATIBILITE

La norme SQL:2008 inclut une commande TRUNCATE avec la syntaxe TRUNCATE TABLE nom_table. Les clauses CONTINUE IDENTITY/RESTART IDENTITY apparaissent également dans cette norme, mais ont des significations légèrement différentes bien que liées. Une partie du comportement de concurrence de cette commande est laissée à la définition de l'implémentation par la norme, donc les notes ci-dessus doivent être considérées et comparées avec d'autres implémentations si nécessaire.
