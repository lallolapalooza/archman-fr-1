NOM

Try::Tiny - try/catch minimal avec préservation correcte de $@

VERSION

version 0.32

SYNOPSIS

Vous pouvez utiliser les instructions "try" et "catch" de Try::Tiny pour anticiper et gérer les conditions d'erreur, en évitant les astuces Perl et les erreurs courantes :

# gérer les erreurs avec un gestionnaire catch
try {
  die "foo";
}
catch {
  warn "erreur interceptée : $_"; # ce n'est pas $@
};

Vous pouvez également l'utiliser comme un "eval" autonome pour capturer et ignorer toute condition d'erreur. Évidemment, il s'agit d'une mesure extrême qui ne doit pas être prise à la légère :

# simplement faire taire les erreurs
try {
  die "foo";
};

DESCRIPTION

Ce module fournit des instructions de type try/catch avec un minimum de code qui minimise les erreurs courantes avec les blocs eval, et rien de plus.

Ce n'est pas comme TryCatch, qui offre une syntaxe agréable et évite d'ajouter une couche de pile supplémentaire, et supporte l'appel à "return" depuis le bloc "try" pour retourner depuis la sous-routine parente. Ces fonctions supplémentaires ont un coût en dépendances, comme Devel::Declare et Scope::Upper, qui peuvent être problématiques parfois, et l'utilisation des filtres catch utilise des contraintes de type de Moose, ce qui peut ne pas être souhaité.

L'objectif principal de ce module est de fournir une gestion d'erreurs simple et fiable pour ceux qui ont des difficultés à installer TryCatch, mais qui souhaitent néanmoins écrire des blocs eval corrects sans avoir à écrire 5 lignes de code à chaque fois.

Il est conçu pour fonctionner correctement en tenant compte des cas limites des motifs (voir "BACKGROUND") et être compatible avec tous les styles de valeurs d'erreur (chaînes simples, références, objets, objets surchargés, etc.).

Si le bloc "try" ne se termine pas par une instruction, il retourne la valeur de la dernière instruction exécutée dans le bloc "catch", s'il y en a un. Sinon, il retourne "undef" dans un contexte scalaire ou la liste vide dans un contexte de liste. Les exemples suivants assignent "bar" à $x :

my $x = try { die "foo" } catch { "bar" };
my $x = try { die "foo" } || "bar";
my $x = (try { die "foo" }) // "bar";
my $x = eval { die "foo" } || "bar";

Vous pouvez ajouter des blocs "finally", produisant les résultats suivants :

my $x;
try { die 'foo' } finally { $x = 'bar' };
try { die 'foo' } catch { warn "Got a die: $_" } finally { $x = 'bar' };

Les blocs "finally" s'exécutent toujours, ce qui les rend adaptés au code de nettoyage qui ne peut pas être géré avec local. Vous pouvez ajouter autant de blocs "finally" que vous le souhaitez à un bloc "try".

Remarque : ajouter un bloc "finally" sans bloc "catch" précédent supprime toute erreur. Cette fonctionnalité est cohérente avec l'utilisation d'un "eval" autonome, mais elle n'est pas cohérente avec les modèles "try"/"finally" trouvés dans d'autres langages de programmation, tels que Java, Python, JavaScript ou C#. Si vous avez appris le modèle "try"/"finally" à partir de l'un de ces langages, soyez conscient de cette différence.

EXPORTATIONS

Toutes les fonctions sont exportées par défaut via Exporter.

Si vous avez besoin de renommer "try", "catch" ou "finally", envisagez d'utiliser Sub::Import pour obtenir la flexibilité de Sub::Exporter.

try (&;@)
Prend une sous-routine obligatoire "try", une sous-routine facultative "catch" et une sous-routine "finally".

La sous-routine obligatoire est évaluée dans le contexte d'un bloc "eval".

S'il n'y a pas eu d'erreur, la valeur de la première sous-routine est retournée, en conservant le contexte liste/scalaire.

S'il y a eu une erreur et que la sous-routine "catch" a été spécifiée, elle sera appelée avec l'erreur dans $_ (localisé) comme premier et unique argument de ce bloc.

Le $@ ne contient pas l'erreur. Dans le bloc "catch", il a la même valeur qu'avant l'exécution du bloc "try".

Remarque : l'erreur peut être fausse, mais si elle se produit, le bloc "catch" sera quand même appelé.

Une fois l'exécution terminée, le bloc "finally" s'exécutera, s'il est présent.

catch (&;@)
Destiné à être utilisé comme deuxième argument de "try".

Retourne une référence à la sous-routine qui a été donnée, mais la encapsule comme "Try::Tiny::Catch", ce qui permet à try de décider correctement quoi faire de cette référence de code.

catch { ... }

Dans le bloc "catch", l'erreur capturée est stockée dans $_, tandis que la valeur précédente de $@ reste disponible pour utilisation. Cette valeur peut ou peut ne pas être significative en fonction de ce qui s'est passé avant l'exécution du bloc "try", mais il pourrait être judicieux de la préserver dans une pile d'erreurs.

Pour capturer $@ lors du lancement de nouvelles erreurs (c'est-à-dire Class::Throwable), vous devez :

local $@ = $_;
finally (&;@)
try     { ... }
catch   { ... }
finally { ... };

Ou

try     { ... }
finally { ... };

Ou même

try     { ... }
finally { ... }
catch   { ... };

Destiné à être le deuxième ou troisième élément de "try". Les blocs "finally" s'exécutent toujours en cas de succès de "try" ou si "catch" s'exécute. Cela permet de localiser le code de nettoyage qui ne peut pas être effectué avec local(), par exemple la fermeture d'un handle de fichier.

Lorsqu'il est appelé, le bloc "finally" reçoit l'erreur capturée. Si aucune erreur n'a été capturée, rien n'est passé. (Notez que le bloc "finally" ne localise pas $_ avec l'erreur, car dans un bloc "catch", il n'y a aucun moyen de savoir si "$_ == undef" implique qu'il n'y a pas eu d'erreurs. Autrement dit, le code suivant fait ce que vous attendez :

try {
  die_sometimes();
} catch {
  # ... code qui s'exécute en cas d'erreur
} finally {
  if (@_) {
    print "Le bloc try est mort avec : @_\n";
  } else {
    print "Le bloc try s'est exécuté sans erreur.\n";
  }
};

Vous devez gérer vous-même les erreurs dans le bloc "finally". "Try::Tiny" ne fera rien concernant les erreurs provenant du code situé dans ces blocs.

De plus, les exceptions dans les blocs "finally" ne peuvent pas être capturées et ne peuvent pas influencer l'exécution de votre programme. Cela est dû aux limitations des garde-fous basés sur le contexte "DESTROY", sur lesquels "finally" est implémenté. Cela pourrait changer dans les futures versions de "Try::Tiny".

CONTEXTE

Il y a un certain nombre de problèmes avec "eval".

Écrasement de $@

Lorsque vous exécutez un bloc "eval" et qu'il réussit, $@ sera effacé, potentiellement écrasant une erreur qui est actuellement interceptée.

Cela provoque une action à distance, effaçant les erreurs précédentes que votre appelant n'a peut-être pas encore gérées.

$@ doit être correctement localisé avant d'invoquer "eval" afin d'éviter ce problème.

Plus précisément, avant la version 5.14.0 de Perl, $@ était écrasé au début de "eval", ce qui rendait également impossible la capture de l'erreur précédente avant que vous ne mourriez (par exemple, lors de la création d'objets d'exception avec des piles d'erreurs).

Pour cette raison, "try" définira en fait $@ à sa valeur précédente (celle disponible avant d'entrer dans le bloc "try") au début du bloc "eval".

La localisation de $@ masque silencieusement les erreurs

Dans un bloc "eval", "die" se comporte un peu comme ceci:

sub die {
  $@ = $_[0];
  return_undef_from_eval();
}

Cela signifie que si vous avez été poli et avez localisé $@, vous ne pouvez pas mourir dans cette portée, ou votre erreur sera rejetée (affichant "Something's wrong" à la place).

La solution de contournement est très laide :

my $error = do {
  local $@;
  eval { ... };
  $@;
};
...
die $error;

$@ peut ne pas être une valeur vraie

Ce code est faux :

if ( $@ ) {
  ...
}

car en raison des avertissements précédents, il peut avoir été non défini.

$@ pourrait également être un objet d'erreur surchargé qui s'évalue à faux, mais c'est de toute façon demander des ennuis.

Le mode d'échec classique (corrigé dans Perl 5.14.0) est :

sub Object::DESTROY {
  eval { ... }
}
eval {
  my $obj = Object->new;
  die "foo";
};
if ( $@ ) {
}

Dans ce cas, puisque "Object::DESTROY" ne localise pas $@ mais utilise toujours "eval", il définira $@ à "".

Le destructeur est appelé lorsque la pile est déroulée, après que "die" a défini $@ à "foo at Foo.pm line 42\n", donc au moment où "if ( $@ )" est évalué, il a été effacé par "eval" dans le destructeur.

La solution de contournement pour cela est encore plus laide que les précédentes. Même si nous ne pouvons pas sauvegarder la valeur de $@ à partir d'un code qui ne localise pas, nous pouvons au moins être sûrs que l'"eval" a été interrompu en raison d'une erreur :

my $failed = not eval {
  ...
  return 1;
};

C'est parce qu'un "eval" qui a intercepté un "die" retournera toujours une valeur fausse.

SYNTAXE ALTERNATIVE

En utilisant Perl 5.10, vous pouvez utiliser des « instructions Switch » dans perlsyn (mais s'il vous plaît, ne le faites pas, car cette syntaxe a depuis été dépréciée car il y avait trop de comportements magiques inattendus).

Le bloc "catch" est invoqué dans un contexte de topicalisation (comme un bloc "given"), mais notez que vous ne pouvez pas retourner une valeur utile depuis "catch" en utilisant les blocs "when" sans un "return" explicite.

C'est quelque peu similaire aux blocs "CATCH" de Perl 6. Vous pouvez l'utiliser pour faire correspondre des erreurs de manière concise :

try {
  require Foo;
} catch {
  when (/^Can't locate .*?\.pm in \@INC/) { } # ignorer
  default { die $_ }
};

MISES EN GARDE

  • @_ n'est pas disponible dans le bloc "try", vous devez donc copier votre liste d'arguments. Si vous souhaitez travailler directement avec les valeurs des arguments via l'aliasage @_ (c'est-à-dire permettre "$_[1] = "foo""), vous devez passer @_ par référence : 
    sub foo {
  my ( $self, @args ) = @_;
  try { $self->bar(@args) }
}

    ou

    sub bar_in_place {
  my $self = shift;
  my $args = \@_;
  try { $_ = $self->bar($_) for @$args }
}
  • "return" revient du bloc "try", pas de la sous-routine parente (notez que c'est aussi ainsi que fonctionne "eval", mais pas comment fonctionne TryCatch) : 
    sub parent_sub {
  try {
    die;
  }
  catch {
    return;
  };
  say "this text WILL be displayed, even though an exception is thrown";
}

    Au lieu de cela, vous devriez capturer la valeur de retour :

    sub parent_sub {
  my $success = try {
    die;
    1;
  };
  return unless $success;
  say "This text WILL NEVER appear!";
}
# OU
sub parent_sub_with_catch {
  my $success = try {
    die;
    1;
  }
  catch {
    # faire quelque chose avec $_
    return undef; #voir note
  };
  return unless $success;
  say "This text WILL NEVER appear!";
}

    Notez que si vous avez un bloc "catch", il doit retourner "undef" pour que cela fonctionne, car si un bloc "catch" existe, sa valeur de retour est retournée à la place de "undef" lorsqu'une exception est levée.

  • "try" introduit une autre image de la pile de l'appelant. Sub::Uplevel n'est pas utilisé. Carp ne le signalera pas lors de l'utilisation de traces de pile complètes, car %Carp::Internal est utilisé. Ce manque de magie est considéré comme une fonctionnalité.
  • La valeur de $_ dans le bloc "catch" n'est pas garantie d'être la valeur de l'exception levée ($@) dans le bloc "try". Il n'y a aucun moyen sûr de garantir cela, car "eval" peut être utilisé de manière non hygiénique dans les destructeurs. La seule garantie est que le bloc "catch" sera appelé si une exception est levée.
  • La valeur de retour du bloc "catch" n'est pas ignorée, donc si vous testez la vérité de l'expression en cas de succès, assurez-vous de retourner une valeur fausse du bloc "catch" : 
    my $obj = try {
  MightFail->new;
} catch {
  ...
  return; # éviter de retourner une valeur vraie;
};
return unless $obj;
  • $SIG{__DIE__} est toujours en vigueur.

    Bien qu'on puisse soutenir que $SIG{__DIE__} devrait être désactivé dans les blocs "eval", puisqu'il ne l'est pas, les gens s'y sont habitués. Par conséquent, par souci de compatibilité, "try" ne désactive pas $SIG{__DIE__} pour la portée du code lançant l'erreur.

  • Le $_ lexical peut remplacer celui défini par "catch".

    Par exemple, la forme "given" de Perl 5.10 utilise un $_ lexical, créant un comportement déroutant :

    given ($foo) {
  when (...) {
    try {
      ...
    } catch {
      warn $_; # affichera $foo, pas l'erreur
      warn $_[0]; # au lieu de cela, obtenez l'erreur comme ceci
    }
  }
}

    Notez que ce comportement a été modifié une fois de plus dans la version 18 de Perl5 https://metacpan.org/module/perldelta#given-now-aliases-the-global-_. Cependant, étant donné que l'intégralité du $_ lexical est maintenant considérée comme expérimentale
    https://metacpan.org/module/perldelta#Lexical-_-is-now-experimental, il n'est pas clair si le nouveau comportement de la version 18 est définitif.
