TIOCPKT(2const) TIOCPKT(2const)

NOM

TIOCPKT, TIOCGPKT, TIOCSPTLCK, TIOCGPTLCK, TIOCGPTPEER - ioctls de pseudoterminal

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <asm/termbits.h>  /* Définition des constantes TIOC* */
#include <sys/ioctl.h>
int ioctl(int fd, TIOCPKT, const int *mode);
int ioctl(int fd, TIOCPKT, int *mode);
int ioctl(int fd, TIOCSPTLCK, const int *lock);
int ioctl(int fd, TIOCGPTLCK, int *lock);
int ioctl(int fd, TIOCGPTPEER, int flags);

DESCRIPTION

TIOCPKT
Active (lorsque *mode est non nul) ou désactive le mode paquet. Ne peut être appliqué qu'au côté maître d'un pseudoterminal (et retourne ENOTTY sinon). En mode paquet, chaque lecture(2) subsquente retournera un paquet contenant soit un seul octet de contrôle non nul, soit un octet contenant zéro ('\0') suivi des données écrites du côté esclave du pseudoterminal. Si le premier octet n'est pas TIOCPKT_DATA (0), il s'agit d'un OU logique de un ou plusieurs des bits suivants :
TIOCPKT_FLUSHREAD La file d'attente de lecture du terminal est vidée.
TIOCPKT_FLUSHWRITE La file d'attente d'écriture du terminal est vidée.
TIOCPKT_STOP La sortie vers le terminal est arrêtée.
TIOCPKT_START La sortie vers le terminal est redémarrée.
TIOCPKT_DOSTOP Les caractères de début et d'arrêt sont ^S / ^Q .
TIOCPKT_NOSTOP Les caractères de début et d'arrêt ne sont pas ^S / ^Q .
Pendant que le mode paquet est actif, la présence d'informations de statut de contrôle à lire du côté maître peut être détectée par un select(2) pour les conditions exceptionnelles ou un poll(2) pour l'événement POLLPRI.
Ce mode est utilisé par rlogin(1) et rlogind(8) pour implémenter une connexion à distance avec écho à distance et contrôle de flux ^S/^Q local.
TIOCGPKT
Retourne le réglage actuel du mode paquet dans l'entier pointé par mode.
TIOCSPTLCK
Définit (si *lock est non nul) ou supprime (si *lock est zéro) le verrou sur le périphérique esclave de pseudoterminal. (Voir aussi unlockpt(3).)
TIOCGPTLCK
Place l'état actuel du verrou du périphérique esclave de pseudoterminal à l'emplacement pointé par lock.
TIOCGPTPEER
À partir d'un descripteur de fichier dans fd qui fait référence à un maître de pseudoterminal, ouvre (avec les flags de style open(2) donnés) et retourne un nouveau descripteur de fichier qui fait référence au périphérique esclave de pseudoterminal pair. Cette opération peut être effectuée indépendamment du fait que le nom du chemin de l'esclave soit accessible à travers l'espace de nom de montage du processus appelant.
Les programmes soucieux de la sécurité interagissant avec les espaces de noms peuvent souhaiter utiliser cette opération plutôt que open(2) avec le nom du chemin retourné par ptsname(3), et des fonctions de bibliothèque similaires qui ont des API non sécurisées. (Par exemple, une confusion peut survenir dans certains cas en utilisant ptsname(3) avec un nom de chemin où un système de fichiers devpts a été monté dans un espace de montage différent.)

VALEUR RENVOYÉE

En cas de succès, 0 est retourné. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

ENOTTY

HISTORIQUE

TIOCGPKT
Linux 3.8.
TIOCGPTLCK
Linux 3.8.
TIOCGPTPEER
Linux 4.13.

Les ioctls BSD TIOCSTOP, TIOCSTART, TIOCUCNTL, et TIOCREMOTE n'ont pas été implémentés sous Linux.
