Tie::File(3perl) Guide du programmeur Perl Tie::File(3perl)

NOM

Tie::File - Accéder aux lignes d'un fichier sur disque via un tableau Perl

SYNOPSIS

use Tie::File;
tie @array, 'Tie::File', nom_fichier or die ...;
$array[0] = 'blabla';     # la première ligne du fichier est maintenant 'blabla'
                          # (la numérotation des lignes commence à 0)
print $array[42];       # affiche la ligne 43 du fichier
$n_recs = @array;       # combien d'enregistrements y a-t-il dans le fichier ?
$#array -= 2;           # tronque deux enregistrements de la fin
for (@array) {
  s/PERL/Perl/g;       # Remplace PERL par Perl partout dans le fichier
}
# Ce sont exactement comme les push, pop, unshift, shift et splice normaux
# Sauf qu'ils modifient le fichier comme vous vous y attendez
push @array, nouveaux_enr...;
my $r1 = pop @array;
unshift @array, nouveaux_enr...;
my $r2 = shift @array;
@old_recs = splice @array, 3, 7, nouveaux_enr...;
untie @array;           # tout est terminé

DESCRIPTION

"Tie::File" représente un fichier texte normal comme un tableau Perl. Chaque élément du tableau correspond à un enregistrement dans le fichier. La première ligne du fichier est l'élément 0 du tableau ; la deuxième ligne est l'élément 1, et ainsi de suite.

Le fichier n'est *pas* chargé en mémoire, donc cela fonctionnera même pour des fichiers gigantesques.

Les modifications apportées au tableau sont immédiatement répercutées dans le fichier.

Les paresseux et les débutants peuvent maintenant arrêter de lire le manuel.

"unicode"

Vous pouvez lire un fichier unicode (UTF-8) en fournissant un descripteur de fichier ouvert avec l'encodage désiré. Il n'est pas sûr d'écrire dans un tel fichier car la longueur en octets et en caractères est souvent différente ; Tie::File calculera mal la longueur des écritures, écrasant ainsi des parties d'autres enregistrements.

"recsep"

Qu'est-ce qu'un 'enregistrement' ? Par défaut, la signification est la même qu'avec l'opérateur "<...>" : c'est une chaîne terminée par $/, qui est probablement "\n". (Exception mineure : sur les systèmes DOS et Win32, un 'enregistrement' est une chaîne terminée par "\r\n".) Vous pouvez changer la définition d'"enregistrement" en fournissant l'option "recsep" dans l'appel "tie" :

tie @array, 'Tie::File', $fichier, recsep => 'es';

Ceci indique que les enregistrements sont délimités par la chaîne "es". Si le fichier contenait les données suivantes :

Curse these pesky flies!\n

alors le tableau @array semblerait avoir quatre éléments :

"Curse th"
"e p"
"ky fli"
"!\n"

Une valeur indéfinie n'est pas permise comme séparateur d'enregistrement. Les sémantiques spéciales de mode 'paragraphe' de Perl (à la "$/ = """) ne sont pas émulées.

Les enregistrements lus depuis le tableau lié n'ont pas la chaîne de séparateur d'enregistrement à la fin ; ceci est pour permettre

$array[17] .= "extra";

de fonctionner comme prévu.

(Voir "autochomp", ci-dessous.) Les enregistrements stockés dans le tableau auront la chaîne de séparateur d'enregistrement ajoutée avant d'être écrits dans le fichier, s'ils n'en ont pas déjà une. Par exemple, si la chaîne de séparateur d'enregistrement est "\n", alors les deux lignes suivantes font exactement la même chose :

$array[17] = "Tarte aux cerises";
$array[17] = "Tarte aux cerises\n";

Le résultat est que le contenu de la ligne 17 du fichier sera remplacé par "Tarte aux cerises" ; un caractère de nouvelle ligne séparera la ligne 17 de la ligne 18. Cela signifie que ce code ne fera rien :

chomp $array[17];

Parce que la valeur "chompée" aura le séparateur rattaché lors de sa réécriture dans le fichier. Il n'y a aucun moyen de créer un fichier dont la chaîne de séparateur d'enregistrement finale est absente.

L'insertion d'enregistrements qui *contiennent* la chaîne de séparateur d'enregistrement n'est pas prise en charge par ce module. Elle produira probablement un résultat raisonnable, mais ce résultat pourra changer dans une future version. Utilisez 'splice' pour insérer des enregistrements ou remplacer un enregistrement par plusieurs.

"autochomp"

Normalement, les éléments du tableau ont le séparateur d'enregistrement supprimé, donc si le fichier contient le texte

Or
Encens
Myrrhe

le tableau lié semblera contenir "("Or", "Encens", "Myrrhe")". Si vous définissez "autochomp" à une valeur fausse, le séparateur d'enregistrement ne sera pas supprimé. Si le fichier ci-dessus était lié avec

tie @cadeaux, "Tie::File", $cadeaux, autochomp => 0;

alors le tableau @cadeaux semblerait contenir "("Or\n", "Encens\n", "Myrrhe\n")", ou (sur les systèmes Win32) "("Or\r\n", "Encens\r\n", "Myrrhe\r\n")".

"mode"

Normalement, le fichier spécifié sera ouvert en lecture et écriture, et sera créé s'il n'existe pas. (C'est-à-dire que les drapeaux "O_RDWR | O_CREAT" sont fournis dans l'appel "open".) Si vous souhaitez changer cela, vous pouvez fournir des drapeaux alternatifs dans l'option "mode". Voir Fcntl pour une liste des drapeaux disponibles. Par exemple :

# ouvrir le fichier s'il existe, mais échouer s'il n'existe pas
use Fcntl 'O_RDWR';
tie @array, 'Tie::File', $fichier, mode => O_RDWR;
# créer le fichier s'il n'existe pas
use Fcntl 'O_RDWR', 'O_CREAT';
tie @array, 'Tie::File', $fichier, mode => O_RDWR | O_CREAT;
# ouvrir un fichier existant en lecture seule
use Fcntl 'O_RDONLY';
tie @array, 'Tie::File', $fichier, mode => O_RDONLY;

Ouvrir le fichier de données en mode écriture seule ou ajout n'est pas pris en charge.

"memory"

Ceci est une limite supérieure sur la quantité de mémoire que "Tie::File" consommera à tout moment lors de la gestion du fichier. Ceci est utilisé pour deux choses : gérer le *cache de lecture* et le *tampon d'écriture différée*.

Les enregistrements lus du fichier sont mis en cache, pour éviter de les relire plusieurs fois. Si vous lisez le même enregistrement deux fois, la première fois il sera stocké en mémoire, et la seconde fois il sera récupéré depuis le *cache de lecture*. La quantité de données dans le cache de lecture ne dépassera pas la valeur que vous avez spécifiée pour "memory". Si "Tie::File" veut mettre en cache un nouvel enregistrement, mais que le cache de lecture est plein, il fera de la place en expirant les enregistrements les moins récemment consultés du cache de lecture.

La limite de mémoire par défaut est de 2 Mio. Vous pouvez ajuster la taille maximale du cache de lecture en fournissant l'option "memory". L'argument est la taille de cache souhaitée, en octets.

# j'ai beaucoup de mémoire, donc j'utilise un grand cache pour accélérer l'accès
tie @array, 'Tie::File', $fichier, memory => 20_000_000;

Définir la limite de mémoire à 0 inhibera la mise en cache ; les enregistrements seront récupérés du disque chaque fois que vous les examinerez.

La valeur "memory" n'est pas une limite absolue ou exacte sur la mémoire utilisée. Les objets "Tie::File" contiennent des structures supplémentaires au cache de lecture et au tampon d'écriture différée, dont les tailles ne sont pas déduites de "memory".

Le cache lui-même consomme environ 310 octets par enregistrement mis en cache, donc si votre fichier a de nombreux enregistrements courts, vous pourriez vouloir réduire la limite de mémoire du cache, sinon la surcharge du cache peut dépasser la taille des données mises en cache.

Vous pouvez définir l'option "dw_size" pour limiter la quantité de données pouvant être enregistrées dans le tampon d'écriture différée. Cette limite ne peut pas dépasser la limite totale de mémoire. Par exemple, si vous définissez "dw_size" à 1000 et "memory" à 2500, cela signifie que pas plus de 1000 octets d'écritures différées ne seront mis en attente. Si vous ne spécifiez pas de "dw_size", il prend par défaut la limite de mémoire entière.

Format des options

"-mode" est un synonyme de "mode". "-recsep" est un synonyme de "recsep". "-memory" est un synonyme de "memory". Vous avez compris le principe.

Méthodes publiques

L'appel "tie" retourne un objet, disons $o. Vous pouvez appeler

$rec = $o->FETCH($n);
$o->STORE($n, $rec);

pour récupérer ou stocker l'enregistrement à la ligne $n, respectivement ; de même pour les autres méthodes de tableau liées. (Voir perltie pour plus de détails.) Vous pouvez également appeler les méthodes suivantes sur cet objet :

"flock"

$o->flock(MODE)

verrouillera le fichier lié. "MODE" a la même signification que le deuxième argument de la fonction Perl intégrée "flock" ; par exemple "LOCK_SH" ou "LOCK_EX | LOCK_NB". (Ces constantes sont fournies par la déclaration "use Fcntl ':flock'".)

"MODE" est facultatif ; la valeur par défaut est "LOCK_EX".

"Tie::File" maintient une table interne des décalages d'octets de chaque enregistrement qu'il a vu dans le fichier.

Lorsque vous utilisez "flock" pour verrouiller le fichier, "Tie::File" suppose que le cache de lecture n'est plus fiable, car un autre processus aurait pu modifier le fichier depuis la dernière lecture. Par conséquent, un appel réussi à "flock" efface le contenu du cache de lecture et la table interne des décalages d'enregistrements.

"Tie::File" garantit que la séquence d'opérations suivante sera sûre :

my $o = tie @array, "Tie::File", $filename;
$o->flock;

En particulier, "Tie::File" ne lira ni n'écrira dans le fichier pendant l'appel "tie". (Exception : l'utilisation de "mode => O_TRUNC" effacera, bien sûr, le fichier pendant l'appel "tie". Si vous souhaitez faire cela en toute sécurité, ouvrez le fichier sans "O_TRUNC", verrouillez le fichier et utilisez "@array = ()".)

La meilleure façon de déverrouiller un fichier est de supprimer l'objet et de détacher le tableau. Il est probablement dangereux de déverrouiller le fichier sans le détacher également, car si vous le faites, des modifications pourraient rester non écrites à l'intérieur de l'objet. C'est pourquoi il n'y a pas de raccourci pour le déverrouillage. Si vous voulez vraiment déverrouiller le fichier prématurément, vous savez ce qu'il faut faire ; si vous ne savez pas, ne le faites pas.

Tous les avertissements habituels concernant le verrouillage de fichier s'appliquent ici. En particulier, notez que le verrouillage de fichier en Perl est **volontaire**, ce qui signifie que détenir un verrou n'empêchera personne d'autre de lire, écrire ou supprimer le fichier ; cela les empêche seulement d'obtenir un autre verrou en même temps. Les verrous sont analogues aux feux verts : Si vous avez un feu vert, cela n'empêche pas l'idiot venant en sens inverse de vous percuter sur le côté ; cela vous garantit simplement que l'idiot n'a pas non plus de feu vert en même temps.

"autochomp"

my $old_value = $o->autochomp(0);    # désactive l'option autochomp
my $old_value = $o->autochomp(1);    #  active l'option autochomp
my $ac = $o->autochomp();   # récupère la valeur actuelle

Voir "autochomp", ci-dessus.

"defer", "flush", "discard", et "autodefer"

Voir "Écriture différée", ci-dessous.

"offset"

$off = $o->offset($n);

Cette méthode retourne le décalage d'octets du début du $n-ième enregistrement dans le fichier. S'il n'y a pas un tel enregistrement, elle retourne une valeur indéfinie.

Liaison à un filehandle déjà ouvert

Si $fh est un filehandle, comme celui retourné par "IO::File" ou l'un des autres modules "IO", vous pouvez utiliser :

tie @array, 'Tie::File', $fh, ...;

De même, si vous avez ouvert ce handle "FH" avec une commande "open" ou "sysopen" normale, vous pouvez utiliser :

tie @array, 'Tie::File', \*FH, ...;

Les handles ouverts en écriture seule ne fonctionneront pas. Les handles ouverts en lecture seule fonctionneront tant que vous n'essayez pas de modifier le tableau. Les handles doivent être attachés à des sources de données déplaçables (seekable) - cela signifie pas de pipes ni de sockets. Si "Tie::File" peut détecter que vous avez fourni un handle non déplaçable, l'appel "tie" lèvera une exception. (Sur les systèmes Unix, il peut le détecter.)

Notez que Tie::File ne fermera que les filehandles qu'il a ouverts en interne. Si vous lui avez passé un filehandle comme ci-dessus, vous "possédez" le filehandle, et êtes responsable de sa fermeture une fois que vous avez détaché le @array.

Tie::File appelle "binmode" sur les filehandles qu'il ouvre en interne, mais pas sur les filehandles passés par l'utilisateur. Pour plus de cohérence, en particulier si vous utilisez les fichiers liés de manière multiplateforme, vous voudrez peut-être appeler "binmode" sur le filehandle avant de lier le fichier.

Écriture différée

(C'est une fonctionnalité avancée. Sautez cette section lors de la première lecture.)

Normalement, modifier un tableau "Tie::File" écrit immédiatement dans le fichier sous-jacent. Chaque affectation comme "$a[3] = ..." réécrit autant du fichier que nécessaire ; typiquement, tout de la ligne 3 jusqu'à la fin devra être réécrit. C'est le comportement le plus simple et le plus transparent. Les performances, même pour les fichiers volumineux, sont raisonnablement bonnes.

Cependant, dans certaines circonstances, ce comportement peut être excessivement lent. Par exemple, supposez que vous avez un fichier d'un million d'enregistrements, et que vous voulez faire :

for (@FILE) {
  $_ = "> $_";
}

La première fois dans la boucle, vous réécrirez l'intégralité du fichier, de la ligne 0 à la fin. La deuxième fois dans la boucle, vous réécrirez l'intégralité du fichier de la ligne 1 à la fin. La troisième fois dans la boucle, vous réécrirez l'intégralité du fichier de la ligne 2 à la fin. Et ainsi de suite.

Si les performances dans de tels cas sont inacceptables, vous pouvez différer l'écriture réelle, puis la faire en une seule fois. La boucle suivante sera beaucoup plus performante pour les fichiers volumineux :

(tied @a)->defer;
for (@a) {
  $_ = "> $_";
}
(tied @a)->flush;

Si la limite de mémoire de "Tie::File" est suffisamment grande, toutes les écritures seront effectuées en mémoire. Ensuite, lorsque vous appellerez "->flush", le fichier entier sera réécrit en une seule passe.

(En fait, la discussion précédente est un peu un mensonge. Vous n'avez pas besoin d'activer l'écriture différée pour obtenir de bonnes performances dans ce cas courant, car "Tie::File" le fera automatiquement pour vous, sauf si vous lui dites spécifiquement de ne pas le faire. Voir "Autodifférage", ci-dessous.)

L'appel à "->flush" ramène le tableau au mode d'écriture immédiate. Si vous souhaitez ignorer les écritures différées, vous pouvez appeler "->discard" à la place de "->flush". Notez que dans certains cas, une partie des données aura déjà été écrite, et il sera trop tard pour "->discard" d'ignorer tous les changements. Le support pour "->discard" pourrait être retiré dans une future version de "Tie::File".

Les écritures différées sont mises en cache en mémoire jusqu'à la limite spécifiée par l'option "dw_size" (voir ci-dessus). Si le tampon d'écriture différée est plein et que vous essayez d'écrire encore plus de données différées, le tampon sera vidé. Toutes les données mises en tampon seront écrites immédiatement, le tampon sera vidé, et l'espace maintenant vide sera utilisé pour les futures écritures différées.

Si le tampon d'écriture différée n'est pas encore plein, mais que la taille totale du tampon et du cache de lecture dépasserait la limite "memory", les enregistrements les plus anciens seront expirés du cache de lecture jusqu'à ce que la taille totale soit inférieure à la limite.
