Tie::Memoize(3perl) Guide du programmeur Perl Tie::Memoize(3perl)

NOM

Tie::Memoize - ajouter des données à une table de hachage sur demande

SYNTAXE

require Tie::Memoize;
tie %hash, 'Tie::Memoize',
    \&fetch,                  # Le reste est optionnel
    $DATA, \&exists,
    {%ini_value}, {%ini_existence};

DESCRIPTION

Ce paquet permet à une table de hachage liée de charger automatiquement ses valeurs lors du premier accès, et d'utiliser la valeur mise en cache lors des accès suivants.

Seuls les accès en lecture (via la récupération de la valeur ou "exists") entraînent des appels aux fonctions ; les accès en modification sont effectués comme sur une table de hachage normale.

Les arguments requis lors de "tie" sont la table de hachage, le paquet, et la référence à la fonction de "FETCH". Les arguments optionnels sont une valeur scalaire arbitraire $data, la référence à la fonction "EXISTS", et les valeurs initiales de la table de hachage et du cache d'existence.

Les fonctions "FETCH" et "EXISTS" ont la même signature : les arguments sont "$key, $data" ; $data est la même valeur que celle fournie en argument lors de l'appel à tie(). Les deux fonctions doivent retourner une liste vide si la valeur n'existe pas. Si la fonction "EXISTS" est différente de la fonction "FETCH", elle doit retourner une valeur VRAIE en cas de succès. La fonction "FETCH" doit retourner la valeur prévue si la clé est valide.

Hériter de Tie::Memoize

La structure des données tied() est une référence de tableau avec les éléments

0:  cache des valeurs connues
1:  cache de l'existence des clés connues
2:  fonction FETCH
3:  fonction EXISTS
4:  $data

Le reste est réservé à un usage interne de ce paquet. En particulier, si TIEHASH est écrasée, elle doit appeler SUPER::TIEHASH.

EXEMPLE

sub slurp {
  my ($key, $dir) = shift;
  open my $h, '<', "$dir/$key" or return;
  local $/; <$h>                      # tout lire
}
sub exists { my ($key, $dir) = shift; return -f "$dir/$key" }
tie %hash, 'Tie::Memoize', \&slurp, $directory, \&exists,
    { fake_file1 => $content1, fake_file2 => $content2 },
    { pretend_does_not_exists => 0, known_to_exist => 1 };

Cet exemple traite le contenu légèrement modifié de $directory comme une table de hachage. Les modifications sont que les clés fake_file1 et fake_file2 récupèrent les valeurs $content1 et $content2, et pretend_does_not_exists ne sera jamais accédé. De plus, l'existence de known_to_exist n'est jamais vérifiée (donc si elle n'existe pas lorsque son contenu est nécessaire, l'utilisateur de %hash pourrait être confus).

BOGUES

Les méthodes FIRSTKEY et NEXTKEY parcourent les clés qui ont déjà été lues, pas toutes les clés possibles de la table de hachage.
