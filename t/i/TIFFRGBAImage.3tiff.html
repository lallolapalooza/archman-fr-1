TIFFRGBAImage(3tiff) LibTIFF TIFFRGBAImage(3tiff)

NOM

TIFFRGBAImage - lire et décoder une image TIFF en un raster

SYNOPIS

#include <tiffio.h>
typedef unsigned char TIFFRGBValue
typedef struct _TIFFRGBAImage TIFFRGBAImage
int TIFFRGBAImageOK(TIFF *tif, char emsg[1024])
int TIFFRGBAImageBegin(TIFFRGBAImage *img, TIFF *tif, int stopOnError, char emsg[1024])
int TIFFRGBAImageGet(TIFFRGBAImage *img, uint32_t *raster, uint32_t width, uint32_t height)
void TIFFRGBAImageEnd(TIFFRGBAImage *img)

DESCRIPTION

Ces routines fournissent une interface de haut niveau via laquelle les images TIFF peuvent être lues en mémoire. Les images peuvent être basées sur des bandes ou des carreaux et posséder diverses caractéristiques : bits/échantillon, échantillons/pixel, photométrie, etc. L'état de décodage est encapsulé dans une struct TIFFRGBAImage, permettant de capturer l'état de plusieurs images et de passer rapidement de l'une à l'autre. Le format de raster cible peut être personnalisé selon les besoins d'une application spécifique en installant des routines personnalisées qui manipulent les données d'image selon les besoins de l'application.

L'utilisation par défaut de ces routines est la suivante :

  • vérifier si une image peut être traitée avec TIFFRGBAImageOK()
  • construire un bloc d'état de décodage à l'aide de TIFFRGBAImageBegin()
  • lire et décoder une image en un raster cible à l'aide de TIFFRGBAImageGet(), puis
  • libérer les ressources à l'aide de TIFFRGBAImageEnd()

TIFFRGBAImageGet() peut être appelée plusieurs fois pour décoder une image avec différents paramètres d'état. Si plusieurs images doivent être affichées et qu'il n'y a pas suffisamment d'espace pour chaque raster décodé, plusieurs blocs d'état peuvent être gérés, puis des appels à TIFFRGBAImageGet() peuvent être effectués pour afficher une image.

Le raster généré est supposé être un tableau de width × height entrées de 32 bits, où width doit être inférieur ou égal à la largeur de l'image (height peut être de n'importe quelle taille positive). Si les dimensions du raster sont inférieures à celles de l'image, les données de l'image sont tronquées aux limites du raster. Si la hauteur du raster est supérieure à celle de l'image, les données de l'image sont placées dans la partie inférieure du raster. (Note : le raster est supposé organisé de telle sorte que le pixel à la position (x, y) soit raster [ y × width + x ] ; avec l'origine du raster dans le coin inférieur gauche.)

Les pixels du raster sont des échantillons de 8 bits groupés de rouge, vert, bleu et alpha. Les macros TIFFGetR, TIFFGetG, TIFFGetB et TIFFGetA doivent être utilisées pour accéder aux échantillons individuels. Les images sans information de matting alpha ont une valeur alpha constante de 1.0 (255).

TIFFRGBAImageGet() convertit les images non 8 bits en effectuant une mise à l'échelle des valeurs d'échantillons. Les images en palette, en niveaux de gris, bilivelles, CMJN et YCbCr sont converties en RVB de manière transparente. Les pixels du raster sont renvoyés sans ajustement pour toute information de colorimétrie présente dans le répertoire.

Le paramètre stopOnError spécifie le comportement à adopter en cas d'erreur lors de la lecture de l'image. Si stopOnError est non nul, une erreur terminera l'opération ; sinon, TIFFRGBAImageGet() continuera à traiter les données jusqu'à ce que toutes les données possibles dans l'image aient été demandées.

FORMATS DE RASTER ALTERNATIFS

Pour utiliser le support de base de lecture et de traitement des images TIFF, mais écrire les données du raster dans un format différent, il suffit de remplacer les méthodes de stockage du raster définies dans la struct TIFFRGBAImage. Ces méthodes sont initialisées par TIFFRGBAImageBegin() pour pointer vers des routines qui regroupent les données du raster dans le format de pixels ABGR par défaut. Deux routines différentes sont utilisées en fonction de l'organisation physique des données du raster dans le fichier : PlanarConfiguration = 1 (échantillons groupés) et PlanarConfiguration = 2 (échantillons séparés). Notez que ce mécanisme peut être utilisé pour transformer les données avant leur stockage dans le raster. Par exemple, on peut convertir les données en indices de palette pour un affichage sur un écran à palette.

Stockage et affichage simultanés des rasters

Il est simple d'afficher une image pendant qu'elle est lue en mémoire, en remplaçant les méthodes de stockage comme décrit ci-dessus pour supporter les formats de raster alpha. Il suffit de conserver une référence aux méthodes de stockage par défaut définies par TIFFRGBAImageBegin(), puis de les appeler avant ou après chaque opération d'affichage. Un exemple de routine de stockage pour mettre à jour l'affichage pendant le remplissage des pixels du raster :

static void
putContigAndDraw(TIFFRGBAImage* img, uint32_t* raster,
    uint32_t x, uint32_t y, uint32_t w, uint32_t h,
    int32_t fromskew, int32_t toskew,
    unsigned char* cp)
{
    (*putContig)(img, raster, x, y, w, h, fromskew, toskew, cp);
    if (x+w == width) {
        w = width;
        if (img->orientation == ORIENTATION_TOPLEFT)
            lrectwrite(0, y-(h-1), w-1, y, raster-x-(h-1)*w);
        else
            lrectwrite(0, y, w-1, y+h-1, raster);
    }
}

(La routine originale fournie par la bibliothèque est conservée dans la variable putContig.)

Support des formats TIFF supplémentaires

Les routines TIFFRGBAImage() supportent la plupart des formats TIFF courants. Il est possible d'étendre ce support en remplaçant la méthode de lecture get appelée par TIFFRGBAImageGet() pour lire les données d'images TIFF. Les détails sur la façon de procéder sont un peu complexes ; il est préférable de faire une copie d'une routine existante et de la modifier selon les besoins de l'application.

NOTES

Les échantillons doivent être de 1, 2, 4, 8 ou 16 bits. Les échantillons/pixel de colorimétrie doivent être de 1, 3 ou 4 (c'est-à-dire SamplesPerPixel - ExtraSamples).

Les cartes de couleur qui semblent mal écrites comme des valeurs de 8 bits sont automatiquement mises à l'échelle à 16 bits.

VALEURS DE RETOUR

Toutes les routines renvoient 1 si l'opération a réussi. Sinon, elles renvoient 0 si une erreur a été détectée et que stopOnError est nul.

DIAGNOSTICS

Tous les messages d'erreur sont dirigés vers la routine TIFFErrorExtR().

"Désolé, ne peut pas gérer des images %d bits" :

L'image avait un BitsPerSample autre que 1, 2, 4, 8 ou 16.

"Désolé, ne peut pas gérer des images avec %d canaux" :

L'image avait un SamplesPerPixel autre que 1, 3 ou 4.

Aucune étiquette "PhotometricInterpretation" :

L'image n'avait pas d'étiquette décrivant comment afficher les données.

Aucune étiquette "PhotometricInterpretation", suppose RVB :

L'image n'avait pas d'étiquette décrivant comment l'afficher, mais comme elle a 3 ou 4 échantillons/pixel, on suppose qu'il s'agit de RVB.

Aucune étiquette "PhotometricInterpretation", suppose min-is-noir :

L'image n'avait pas d'étiquette décrivant comment l'afficher, mais comme elle a 1 échantillon/pixel, on suppose qu'il s'agit de niveaux de gris.

Aucune étiquette "PhotometricInterpretation", suppose min-is-noir :

L'image n'avait pas d'étiquette décrivant comment l'afficher, mais comme elle a 1 échantillon/pixel, on suppose qu'il s'agit de niveaux de gris.

TIFFRGBAImage(3tiff)

SYNOPSIS

#include <tiffio.h>

int TIFFRGBAImage(TIFF *tif, uint32 *raster, uint32 rwidth, uint32 rheight, int *stop, const TIFFRGBAImage *colormap);

DESCRIPTION

The function TIFFRGBAImage reads a baseline TIFF image and returns it as a 32-bit RGBA image stored in memory. The image is returned as an array of 32-bit uint32 values, each representing an RGBA pixel, and stored contiguously in memory. Each pixel is represented as 8 bits per sample, in the order: red, green, blue, and alpha. The raster is organised as a sequence of rows, with the first row being the top row of the image. The raster image is returned in the structure pointed to by the raster parameter. The actual width and height of the image in pixels are returned in the rwidth and rheight parameters, respectively.

The stop parameter is a pointer to an int that may be set to a non-zero value by the TIFFRGBAImage function to indicate that the caller should stop processing. This is typically used when the library is used to display images incrementally, and the user requests that the operation be aborted. A NULL value should be supplied for this parameter if the caller does not wish to use this facility.

The colormap parameter is a pointer to a structure of type TIFFRGBAImage that defines how palette-based images are to be converted. If colormap is NULL, then a default colormap is used. The structure has the following members:

width
The width of the colormap.
height
The height of the colormap.
BitsPerSample
The number of bits per sample in the colormap (typically 8).
SamplesPerPixel
The number of samples per pixel in the colormap (typically 3 for RGB).
PhotometricInterpretation
The photometric interpretation of the colormap (e.g., PHOTOMETRIC_RGB).
colormap
A pointer to an array of uint16 values representing the colormap. For PHOTOMETRIC_PALETTE images, the colormap is assumed to be organised as an array of red, green, and blue entries. Each entry is a uint16 value representing the intensity of the corresponding colour component. The colormap field of the input TIFFRGBAImage structure should point to this array.
XORcode
A uint16 value used to XOR with palette indices to get the actual palette index. This is used for storing palette indices in compressed data.
alpha
A uint16 value representing the alpha value to be associated with the palette entries. This is typically used to specify the transparency of the palette entries.

The TIFFRGBAImage function returns 1 on success, and 0 on failure. On failure, the errno variable may be set to indicate the cause of the error. Common error conditions include insufficient memory, inability to handle the image format, or an invalid colormap.

The TIFFRGBAImage function supports reading only a subset of TIFF image formats. It is designed to read baseline TIFF images, including bilevel, grayscale, and RGB images. More complex TIFF formats, such as those with multiple samples per pixel or different bit depths, may not be supported directly and may require the use of other functions or a different approach.

ALTERNATE RASTER FORMATS

The TIFFReadRGBAStrip and TIFFReadRGBATile functions provide alternative ways to read TIFF images into RGBA raster format. These functions read the image in strips or tiles, respectively, which can be more memory-efficient for large images. The caller is responsible for managing the memory for the raster image and for assembling the strips or tiles into a complete image.

SIMULTANEOUS RASTER STORE AND DISPLAY

The TIFFRGBAImageOrientedScreenPhoton function is provided for applications that need to display images on a screen while reading them. It allows for incremental display of the image as it is read, which can be useful for large images or slow display devices.

SUPPORTING ADDITIONAL TIFF FORMATS

For TIFF images that are not supported by TIFFRGBAImage, it may be necessary to use lower-level functions such as TIFFReadScanline or TIFFReadTile to read the raw image data. The caller would then be responsible for converting the raw data into the desired RGBA format. This approach provides greater flexibility but requires a deeper understanding of the TIFF format and the image data.

NOTES

The TIFFRGBAImage function reads the image data into memory. For very large images, this can consume a significant amount of memory. In such cases, consider using TIFFReadRGBAStrip or TIFFReadRGBATile to process the image in smaller chunks.

The function assumes that the input TIFF file is a baseline TIFF image. It may not handle all possible TIFF variations or extensions correctly.

The returned raster buffer is allocated using _TIFFmalloc. The caller is responsible for freeing this memory using _TIFFfree when it is no longer needed.

RETURN VALUES

Returns 1 on success, and 0 on failure.

DIAGNOSTICS

The following error messages may be reported by TIFFRGBAImage:

"No space for colormap":

There was insufficient memory to allocate space for a colormap.

"No space for raster buffer":

There was insufficient memory to allocate space for the output raster buffer.

"No space for tile buffer":

There was insufficient memory to allocate an i/o buffer.

"No space for strip buffer":

There was insufficient memory to allocate an i/o buffer.

"Cannot read TIFF header":

The TIFF header could not be read from the file.

"TIFF library error":

An unspecified error occurred within the TIFF library.

"Invalid image dimensions":

The image dimensions (width or height) are invalid or too large.

"Unsupported image format":

The image format is not supported by TIFFRGBAImage. This may include formats with unsupported combinations of BitsPerSample, SamplesPerPixel, or PhotometricInterpretation. For example, images with more than 4 samples per pixel are not directly supported.

"Missing required Colormap tag":

A palette image is missing the required Colormap tag.

"Invalid BitsPerSample value":

The BitsPerSample tag has an invalid value. For example, it is 0 or negative.

"Invalid SamplesPerPixel value":

The SamplesPerPixel tag has an invalid value. For example, it is 0 or negative.

"Invalid PhotometricInterpretation value":

The PhotometricInterpretation tag has an invalid value.

"Unsupported PhotometricInterpretation":

The image uses a PhotometricInterpretation that is not supported by this function, e.g. PHOTOMETRIC_SEPARATED or PHOTOMETRIC_CIELAB.

"Bad field value":

A TIFF tag has a value that is inconsistent with other tags. For instance, ImageLength is zero when ImageWidth is non-zero.

"No space for scanline buffer":

There was insufficient memory to allocate a buffer for a scanline.

"No space for grayscale palette":

There was insufficient memory to allocate a buffer for a grayscale palette mapping table. This might happen if the image is grayscale and a colormap is needed for conversion, but memory allocation fails.

"No space for RGB palette":

There was insufficient memory to allocate a buffer for an RGB palette mapping table. This usually happens for PHOTOMETRIC_PALETTE images when converting to RGB, but memory allocation fails.

"Cannot handle bilevel image":

The image is bilevel (PhotometricInterpretation is PHOTOMETRIC_MINISWHITE or PHOTOMETRIC_MINISBLACK) and has BitsPerSample greater than 1. In this case, it is assumed to be a grayscale or bilevel image.

"No space for photometric conversion table":

There was insufficient memory for a table used to convert image samples to 8-bit RGB.

Missing required "Colormap" tag:

A Palette image did not have a required Colormap tag.

"No space for tile buffer":

There was insufficient memory to allocate an i/o buffer.

"No space for strip buffer":

There was insufficient memory to allocate an i/o buffer.

"Can not handle format":

The image has a format (combination of BitsPerSample, SamplesPerPixel and PhotometricInterpretation) that can not be handled.

"No space for B&W mapping table":

There was insufficient memory to allocate a table used to map grayscale data to RGB.

"No space for Palette mapping table":

There was insufficient memory to allocate a table used to map data to 8-bit RGB.
