TIFFREADSCANLINE(3tiff) LibTIFF TIFFREADSCANLINE(3tiff)

NOM

TIFFReadScanline - lit et décode une ligne de balayage de données d'un fichier TIFF ouvert

SYNTAXE

#include <tiffio.h>
int TIFFReadScanline(TIFF *tif, tdata_t buf, uint32_t row, tsample_t sample)

DESCRIPTION

Lit les données de la ligne spécifiée dans le tampon de données (fourni par l'utilisateur) buf. Les données sont retournées décompressées et dans l'ordre des octets et des bits natifs, mais sont sinon compactées (voir plus bas). Le tampon doit être suffisamment grand pour contenir une ligne de balayage complète de données. Les applications doivent appeler la routine TIFFScanlineSize() pour connaître la taille (en octets) d'un tampon de ligne de balayage. Le paramètre row est toujours utilisé par TIFFReadScanline(); le paramètre sample n'est utilisé que si les données sont organisées en plans séparés (PlanarConfiguration = 2).

NOTES

La bibliothèque tente de masquer les différences d'ordre des bits et des octets entre l'image et la machine native en convertissant les données dans l'ordre de la machine native. L'inversion des bits est effectuée si l'étiquette FillOrder est opposée à l'ordre des bits de la machine native. Les échantillons de 16 et 32 bits sont automatiquement échangés d'octets si le fichier a été écrit avec un ordre d'octets opposé à l'ordre d'octets de la machine native.

En C++, le paramètre sample est défini par défaut sur 0.

VALEURS DE RETOUR

TIFFReadScanline() retourne -1 si une erreur est détectée ; sinon, 1 est retourné.

DIAGNOSTICS

Tous les messages d'erreur sont dirigés vers la routine TIFFErrorExtR().

"L'algorithme de compression ne prend pas en charge l'accès aléatoire" :

Des données ont été demandées dans un ordre non séquentiel à partir d'un fichier qui utilise un algorithme de compression et qui a RowsPerStrip supérieur à un. C'est-à-dire que les données de l'image sont stockées sous forme compressée, avec plusieurs lignes regroupées dans une bande. Dans ce cas, la bibliothèque ne prend pas en charge l'accès aléatoire aux données. Les données doivent être soit accédées séquentiellement, soit le fichier doit être converti de sorte que chaque bande soit constituée d'une seule ligne de données.

BOGUES

La lecture des données YCbCr sous-échantillonnées ne fonctionne pas correctement car, pour PlanarConfiguration = 2, la taille d'une ligne de balayage n'est pas calculée par échantillon, et pour PlanarConfiguration = 1, la bibliothèque ne décompacte pas les échantillons entrelacés par blocs ; utilisez les interfaces basées sur les bandes et les tuiles pour lire ces formats.
