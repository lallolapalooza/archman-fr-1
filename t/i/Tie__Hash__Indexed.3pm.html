NOM

Tie::Hash::Indexed - Hachages ordonnés pour Perl

SYNOPSIS

use Tie::Hash::Indexed;
# Interface Orientée Objet
my $hash = Tie::Hash::Indexed->new(
             I => 1, n => 2, d => 3, e => 4);
$hash->push(x => 5);
print $hash->keys, "\n";   # affiche 'Index'
print $hash->values, "\n"; # affiche '12345'
# Interface Liée
tie my %hash, 'Tie::Hash::Indexed';
%hash = ( I => 1, n => 2, d => 3, e => 4 );
$hash{x} = 5;
print keys %hash, "\n";    # affiche 'Index'
print values %hash, "\n";  # affiche '12345'

DESCRIPTION

Tie::Hash::Indexed est intentionnellement très similaire à d'autres modules de hachage ordonné, et plus particulièrement Hash::Ordered. Cependant, Tie::Hash::Indexed est entièrement écrit en XS et est, souvent de manière significative, plus rapide que d'autres modules. Pour de nombreuses opérations, il est plus de deux fois plus rapide que Hash::Ordered, surtout lorsque l'on utilise l'interface orientée objet plutôt que l'interface liée. D'autres modules, par exemple Tie::IxHash, sont encore plus lents.

L'interface orientée objet de Tie::Hash::Indexed est presque identique à celle de Hash::Ordered, donc dans la plupart des cas, vous devriez pouvoir facilement remplacer l'un par l'autre.

Si vous n'avez pas besoin de la dernière touche de performance et vous sentez plus à l'aise avec un module pur Perl, Hash::Ordered est certainement une bonne alternative.

COMPATIBILITÉ

Tie::Hash::Indexed devrait pouvoir être compilé avec des versions de perl aussi anciennes que 5.005. Il devrait pouvoir être compilé sur n'importe quelle plateforme si un compilateur C est disponible.

Hash::Ordered

Tie::Hash::Indexed n'a pas de méthode "clone", mais le clonage peut être émulé avec :

$clone = Tie::Hash::Indexed->new($orig->items);

Tie::Hash::Indexed a une méthode "items" comme alias pour "as_list", qui manque à Hash::Ordered. Si vous voulez pouvoir changer de module, vous devriez préférer utiliser "as_list".

Tie::Hash::Indexed a également une méthode "has" comme alias pour "exists".

Tie::Hash::Indexed a également "dor_assign" et "or_assign" comme alias pour "dor_equals" et "or_equals".

Tie::Hash::Indexed possède les méthodes "multiply", "divide" et "modulo" en plus de "add" et "subtract". Hash::Ordered ne prend en charge que "add" et "subtract".

Tie::Hash::Indexed possède une méthode "assign" qui peut être utilisée pour assigner directement une nouvelle liste de paires clé-valeur à une instance existante. Avec Hash::Ordered, vous pouvez appeler "clear" suivi de "merge" pour obtenir le même comportement.

Tie::Hash::Indexed a une méthode "reverse_iterator", qui peut être émulée dans Hash::Ordered en passant la liste inversée des clés à "iterator". D'un autre côté, la méthode "iterator" de Tie::Hash::Indexed ne prend pas en charge le passage d'une liste de clés du tout.

Les objets Tie::Hash::Indexed s'évaluent toujours à une valeur vraie dans un contexte booléen, contrairement aux objets Hash::Ordered, qui s'évaluent à une valeur fausse s'ils sont vides, et à une valeur vraie sinon. Vous pouvez utiliser "$obj-"keys> avec Tie::Hash::Indexed à la place, ce qui est extrêmement peu coûteux à appeler en contexte scalaire.

MÉTHODES

new

$obj = Tie::Hash::Indexed->new;
$obj = Tie::Hash::Indexed->new(@kvpairs);

Construit et initialise éventuellement un nouvel objet.

clear

$obj->clear;

Supprime tout le contenu du hachage. Renvoie l'objet, ce qui permet le chaînage de méthodes.

Invalide les itérateurs.

assign

$obj->assign(@kvpairs);

Vide le hachage et assigne la liste de paires clé-valeur. Identique à :

$obj->clear->merge(@kvpairs);

Renvoie le nombre de clés stockées dans le hachage après l'assignation.

Invalide les itérateurs.

merge

$obj->merge(@kvpairs);

Fusionne une liste de paires clé-valeur dans le hachage. Les clés existantes conserveront leur position et leur valeur sera mise à jour. Les nouvelles clés seront ajoutées à la fin.

Renvoie le nombre de clés stockées dans le hachage après la fusion.

Invalide les itérateurs.

exists

$bool = $obj->exists($key)

Renvoie un booléen indiquant si une clé existe dans le hachage.

has

Un alias pour "exists".

get

$value = $obj->get($key)

Renvoie la valeur d'une seule clé, ou "undef" si la clé n'a pas été trouvée.

set

$obj->set($key, $value)

Si la clé existe déjà, met à jour la valeur sans affecter l'ordre des éléments. Sinon, ajoute la paire clé-valeur. Ceci est équivalent à appeler "merge" avec une seule paire clé-valeur, sauf pour la valeur de retour.

Renvoie la valeur.

Invalide les itérateurs.

push

$obj->push(@kvpairs)

Ajoute une ou plusieurs paires clé-valeur. Ceci est similaire à "merge", mais au lieu de préserver la position des clés existantes, cela supprimera les clés existantes et ajoutera toutes les paires clé-valeur à la fin.

Renvoie le nombre de clés stockées dans le hachage après l'ajout.

Invalide les itérateurs.

unshift

$obj->unshift(@kvpairs)

Ajoute une ou plusieurs paires clé-valeur au début. Ceci est similaire à "push", mais opère sur le début du hachage ordonné. Les clés existantes seront supprimées et insérées au début.

Renvoie le nombre de clés stockées dans le hachage après l'opération d'ajout au début.

Invalide les itérateurs.

pop

$value = $obj->pop;
($key, $value) = $obj->pop;

Supprime le dernier élément du hachage ordonné.

Renvoie la valeur en contexte scalaire ou la paire clé-valeur en contexte de liste.

Invalide les itérateurs.

shift

$value = $obj->shift;
($key, $value) = $obj->shift;

Supprime le premier élément du hachage ordonné.

Renvoie la valeur en contexte scalaire ou la paire clé-valeur en contexte de liste.

Invalide les itérateurs.

delete

$value = $obj->delete($key);

Supprime une paire clé-valeur du hachage ordonné et renvoie la valeur.

Invalide les itérateurs si la clé a été trouvée.

items

@kvpairs = $obj->items;
@kvpairs = $obj->items(@keys);

Renvoie les paires clé-valeur pour tous les éléments du hachage, ou uniquement pour les clés sélectionnées. En contexte scalaire, renvoie le nombre d'éléments de la liste retournée.

MÉTHODES

get

my $val = $obj->get($key);
my @vals = $obj->get(@keys);

Récupère la valeur associée à $key, ou les valeurs associées à tous les éléments de @keys. Si $key n'est pas trouvé, undef est retourné. En contexte scalaire, retourne le nombre d'éléments qui seraient retournés en contexte de liste.

set

$obj->set($key, $value);
$obj->set(\%hash);

Définit la valeur associée à $key à $value. Si \%hash est fourni, toutes les paires clé-valeur sont définies.

items

my @items = $obj->items;
my @items = $obj->items(@keys);

Retourne les paires clé-valeur pour tous les éléments du hash, ou seulement pour les clés sélectionnées. En contexte scalaire, retourne le nombre d'éléments qui seraient retournés en contexte de liste.

as_list

Un alias pour "items".

keys

@keys = $obj->keys;
@keys = $obj->keys(@keys);

Retourne les clés de tous les éléments du hash, ou seulement pour les clés sélectionnées. En contexte scalaire, retourne le nombre d'éléments qui seraient retournés en contexte de liste.

values

@values = $obj->values;
@values = $obj->values(@keys);

Retourne les valeurs de tous les éléments du hash, ou seulement pour les clés sélectionnées. En contexte scalaire, retourne le nombre d'éléments qui seraient retournés en contexte de liste.

Si une clé n'est pas trouvée, la valeur associée sera retournée comme "undef".

concat

$obj->concat($key, $str);

Ceci est équivalent à, mais plus efficace que :

$obj->set($key, $obj->get($key) . $str);

add

$obj->add($key, $value);

Ceci est équivalent à, mais plus efficace que :

$obj->set($key, $obj->get($key) + $value);

subtract

$obj->subtract($key, $value);

Ceci est équivalent à, mais plus efficace que :

$obj->set($key, $obj->get($key) - $value);

multiply

$obj->multiply($key, $value);

Ceci est équivalent à, mais plus efficace que :

$obj->set($key, $obj->get($key) * $value);

divide

$obj->divide($key, $value);

Ceci est équivalent à, mais plus efficace que :

$obj->set($key, $obj->get($key) / $value);

modulo

$obj->modulo($key, $value);

Ceci est équivalent à, mais plus efficace que :

$obj->set($key, $obj->get($key) % $value);

dor_assign

$obj->dor_assign($key, $value);

Ceci est équivalent à, mais plus efficace que :

$obj->set($key, $obj->get($key) // $value);

dor_equals

Ceci est un alias pour "dor_assign".

or_assign

$obj->or_assign($key, $value);

Ceci est équivalent à, mais plus efficace que :

$obj->set($key, $obj->get($key) || $value);

or_equals

Ceci est un alias pour "or_assign".

postinc

$val = $obj->postinc($key);

Ceci est équivalent à, mais plus efficace que :

$val = $obj->get($key);
$obj->set($key, $val + 1);

postdec

$val = $obj->postdec($key);

Ceci est équivalent à, mais plus efficace que :

$val = $obj->get($key);
$obj->set($key, $val - 1);

preinc

$val = $obj->preinc($key);

Ceci est équivalent à, mais plus efficace que :

$val = $obj->set($key, $obj->get($key) + 1);

predec

$val = $obj->predec($key);

Ceci est équivalent à, mais plus efficace que :

$val = $obj->set($key, $obj->get($key) - 1);

iterator

my $i = $h->iterator;
while (my($k, $v) = $i->next) {
  push @key, $k;
  push @val, $v;
}

Itérateur avant bidirectionnel pour la traversée de hash ordonné.

reverse_iterator

for (my $i = $h->reverse_iterator; $i->valid; $i->next) {
  push @key, $i->key;
  push @val, $i->value;
}

Itérateur arrière bidirectionnel pour la traversée de hash ordonné.

ENVIRONNEMENT

"THI_DEBUG_OPT"

Si Tie::Hash::Indexed est compilé avec le support du débogage, vous pouvez utiliser cette variable d'environnement pour spécifier les options de débogage. Actuellement, les seules valeurs utiles que vous pouvez passer sont "d" ou "all", qui activent toutes deux la sortie de débogage pour le module.

PROBLÈMES

Comme les données des objets Tie::Hash::Indexed sont cachées à l'intérieur de l'implémentation XS, le clonage/la sérialisation sont problématiques. Tie::Hash::Indexed implémente des hooks pour Storable, donc cloner ou sérialiser des objets en utilisant Storable est sûr.

Tie::Hash::Indexed essaie très fort de détecter toute corruption dans ses données à l'exécution. Donc, si quelque chose se passe mal, vous recevrez très probablement un message d'erreur approprié.

BOGUES

Si vous trouvez des bogues, si Tie::Hash::Indexed ne semble pas se compiler sur votre système ou si l'un de ses tests échoue, veuillez signaler le problème sur https://github.com/mhx/Tie-Hash-Indexed/issues.
