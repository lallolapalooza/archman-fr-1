TIOCPKT(2const) TIOCPKT(2const)

NOM

TIOCPKT, TIOCGPKT, TIOCSPTLCK, TIOCGPTLCK, TIOCGPTPEER - ioctls de pseudoterminal

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <asm/termbits.h>  /* Définition des constantes TIOC* */
#include <sys/ioctl.h>
int ioctl(int fd, TIOCPKT, const int *mode);
int ioctl(int fd, TIOCPKT, int *mode);
int ioctl(int fd, TIOCSPTLCK, const int *lock);
int ioctl(int fd, TIOCGPTLCK, int *lock);
int ioctl(int fd, TIOCGPTPEER, int flags);

DESCRIPTION

TIOCPKT
Active (quand *mode est différent de zéro) ou désactive le mode paquet. Ne peut être appliqué qu'au côté maître d'un pseudoterminal (et renvoie ENOTTY sinon). En mode paquet, chaque read(2) ultérieur renverra un paquet contenant soit un seul octet de contrôle non nul, soit un octet nul ('\0') suivi des données écrites sur le côté esclave du pseudoterminal. Si le premier octet n'est pas TIOCPKT_DATA (0), il s'agit d'un OR bit à bit d'un ou plusieurs des bits suivants :
TIOCPKT_FLUSHREAD La file d'attente de lecture du terminal est vidée.
TIOCPKT_FLUSHWRITE La file d'attente d'écriture du terminal est vidée.
TIOCPKT_STOP La sortie vers le terminal est arrêtée.
TIOCPKT_START La sortie vers le terminal est redémarrée.
TIOCPKT_DOSTOP Les caractères de début et d'arrêt sont ^S / ^Q.
TIOCPKT_NOSTOP Les caractères de début et d'arrêt ne sont pas ^S / ^Q.
Lorsque le mode paquet est utilisé, la présence d'informations de contrôle à lire du côté maître peut être détectée par un select(2) pour les conditions exceptionnelles ou un poll(2) pour l'événement POLLPRI.
Ce mode est utilisé par rlogin(1) et rlogind(8) pour implémenter une connexion à distance avec écho distant et contrôle de flux local ^S/^Q.
TIOCGPKT
Renvoie le réglage actuel du mode paquet dans l'entier pointé par mode.
TIOCSPTLCK
Définit (si *lock est différent de zéro) ou supprime (si *lock est zéro) le verrouillage sur le périphérique esclave du pseudoterminal. (Voir aussi unlockpt(3).)
TIOCGPTLCK
Place l'état de verrouillage actuel du périphérique esclave du pseudoterminal dans l'emplacement pointé par lock.
TIOCGPTPEER
Étant donné un descripteur de fichier dans fd qui fait référence à un maître de pseudoterminal, ouvre (avec les flags de style open(2) donnés) et renvoie un nouveau descripteur de fichier qui fait référence au périphérique esclave du pseudoterminal homologue. Cette opération peut être effectuée, que le nom du chemin de l'esclave soit accessible ou non via l'espace de noms de montage du processus appelant.
Les programmes soucieux de la sécurité interagissant avec les espaces de noms peuvent souhaiter utiliser cette opération plutôt que open(2) avec le nom du chemin renvoyé par ptsname(3), et des fonctions de bibliothèque similaires qui ont des API non sécurisées. (Par exemple, une confusion peut survenir dans certains cas en utilisant ptsname(3) avec un nom de chemin où un système de fichiers devpts a été monté dans un espace de noms de montage différent.)

VALEUR RENVOYÉE

En cas de succès, 0 est renvoyé. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

ENOTTY

HISTORIQUE

TIOCGPKT
Linux 3.8.
TIOCGPTLCK
Linux 3.8.
TIOCGPTPEER
Linux 4.13.

Les ioctls BSD TIOCSTOP, TIOCSTART, TIOCUCNTL et TIOCREMOTE n'ont pas été implémentés sous Linux.

VOIR AUSSI

ioctl(2), ioctl_tty(2)
