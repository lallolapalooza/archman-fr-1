Time::Piece(3perl) Guide du programmeur Perl Time::Piece(3perl)

NOM

Time::Piece - Objets temps orientés objet

SYNOPIS

use Time::Piece;

my $t = localtime;
print "L'heure est $t\n";
print "L'année est ", $t->year, "\n";

DESCRIPTION

Ce module remplace les fonctions standard "localtime" et "gmtime" par des implémentations qui retournent des objets. Il le fait de manière rétrocompatible, de sorte que l'utilisation de localtime/gmtime telle que documentée dans perlfunc retournera toujours ce à quoi vous vous attendez.

Le module implémente en fait la plupart d'une interface décrite par Larry Wall sur la liste de diffusion perl5-porters ici : https://www.nntp.perl.org/group/perl.perl5.porters/2000/01/msg5283.html

UTILISATION

Après avoir importé ce module, lorsque vous utilisez localtime ou gmtime dans un contexte scalaire, au lieu d'obtenir une chaîne scalaire ordinaire représentant la date et l'heure, vous obtenez un objet Time::Piece, dont la stringification produit le même effet que les fonctions localtime et gmtime. Il existe également un constructeur new(), qui est le même que localtime(), sauf lorsqu'il reçoit un objet Time::Piece, auquel cas il agit comme un constructeur de copie. Les méthodes suivantes sont disponibles sur l'objet :

$t->sec                 # aussi disponible sous $t->second
$t->min                 # aussi disponible sous $t->minute
$t->hour                # 24 heures
$t->mday                # aussi disponible sous $t->day_of_month
$t->mon                 # 1 = Janvier
$t->_mon                # 0 = Janvier
$t->monname             # Jan
$t->month               # identique à $t->monname
$t->fullmonth           # Janvier
$t->year                # basé sur 0 (l'an 0 est bien sûr 1 av. J.-C.)
$t->_year               # année moins 1900
$t->yy                  # année sur 2 chiffres
$t->wday                # 1 = Dimanche
$t->_wday               # 0 = Dimanche
$t->day_of_week         # 0 = Dimanche
$t->wdayname            # Dim
$t->day                 # identique à wdayname
$t->fullday             # Dimanche
$t->yday                # aussi disponible sous $t->day_of_year, 0 = 1er Jan
$t->isdst               # aussi disponible sous $t->daylight_savings
$t->hms                 # 12:34:56
$t->hms(".")            # 12.34.56
$t->time                # identique à $t->hms
$t->ymd                 # 2000-02-29
$t->date                # identique à $t->ymd
$t->mdy                 # 29-02-2000
$t->mdy("/")            # 29/02/2000
$t->dmy                 # 29-02-2000
$t->dmy(".")            # 29.02.2000
$t->datetime            # 2000-02-29T12:34:56 (ISO 8601)
$t->cdate               # Dim 29 Fév 12:34:56 2000
"$t"                    # identique à $t->cdate
$t->epoch               # secondes depuis l'époque
$t->tzoffset            # décalage horaire dans un objet Time::Seconds
$t->julian_day          # nombre de jours depuis le début de la période julienne
$t->mjd                 # date julienne modifiée (JD-2400000.5 jours)
$t->week                # numéro de semaine (ISO 8601)
$t->is_leap_year        # vrai si c'est une année bissextile
$t->month_last_day      # 28-31
$t->time_separator($s)  # définit le séparateur par défaut (défaut ":")
$t->date_separator($s)  # définit le séparateur par défaut (défaut "-")
$t->day_list(@jours)     # définit les jours de la semaine par défaut
$t->mon_list(@mois)     # définit les mois par défaut
$t->strftime(FORMAT)    # identique à POSIX::strftime (sans la surcharge
                        # de l'extension POSIX complète)
$t->strftime()          # "Dim, 29 Fév 2000 12:34:56 GMT"

Time::Piece->strptime(CHAÎNE, FORMAT)
                        # voir la page man strptime. Crée un nouvel
                        # objet Time::Piece

Notez que "localtime" et "gmtime" ne sont pas listés ci-dessus. S'ils sont appelés comme méthodes sur un objet Time::Piece, ils agissent comme des constructeurs, retournant un nouvel objet Time::Piece pour l'heure actuelle. En d'autres termes : ils ne sont pas utiles en tant que méthodes.

Locales

Les deux wdayname (jour) et monname (mois) permettent de passer une liste pour indexer le nom des jours. Cela peut être utile si vous avez besoin d'implémenter une forme de localisation sans installer ou utiliser réellement des locales. Notez qu'il s'agit d'une substitution globale qui affectera toutes les instances de Time::Piece.

my @jours = qw( Dimanche Lundi Mardi Mercredi Jeudi Vendredi Samedi );
my $jour_francais = localtime->day(@jours);

Ces paramètres peuvent également être remplacés globalement :

Time::Piece::day_list(@jours);

Ou pour les mois :

Time::Piece::mon_list(@mois);

Et localement pour les mois :

print localtime->month(@mois);

Ou pour peupler avec votre locale système actuelle, appelez :
Time::Piece->use_locale();

Calculs de dates

Il est possible d'utiliser l'addition et la soustraction simples d'objets :

use Time::Seconds;

my $secondes = $t1 - $t2;
$t1 += ONE_DAY; # ajoute 1 jour (constante de Time::Seconds)

Les opérations suivantes sont valides ($t1 et $t2 sont des objets Time::Piece) :

$t1 - $t2; # retourne un objet Time::Seconds
$t1 - 42; # retourne un objet Time::Piece
$t1 + 533; # retourne un objet Time::Piece

Cependant, l'addition d'un objet Time::Piece à un autre objet Time::Piece provoquera une erreur d'exécution.

Notez que la première des opérations ci-dessus retourne un objet Time::Seconds, donc bien que l'examen de l'objet affiche le nombre de secondes (en raison du surcharge), vous pouvez également obtenir le nombre de minutes, d'heures, de jours, de semaines et d'années dans cette différence, en utilisant l'API Time::Seconds.

En plus de l'addition de secondes, il existe deux API pour ajouter des mois et des années :

$t = $t->add_months(6);
$t = $t->add_years(5);

Les mois et les années peuvent être négatifs pour les soustractions. Notez qu'il existe un comportement "étrange" lors de l'ajout et de la soustraction de mois en fin de mois. Généralement, lorsque le mois résultant est plus court que le mois de départ, le nombre de jours de chevauchement est ajouté. Par exemple, soustraire un mois du 2008-03-31 ne donnera pas le 2008-02-31 car c'est une date impossible. Vous obtiendrez plutôt le 2008-03-02. Cela semble cohérent avec d'autres outils de manipulation de dates.

Troncature

Appeler la méthode "truncate" retourne une copie de l'objet mais avec l'heure tronquée au début de l'unité fournie.

$t = $t->truncate(to => 'day');

Cet exemple mettra l'heure à minuit le même jour que $t avait auparavant. Les valeurs autorisées pour le paramètre "to" sont : "year", "quarter", "month", "day", "hour", "minute" et "second".

Comparaisons de dates

Les comparaisons de dates sont également possibles, en utilisant la suite complète de "<", ">", "<=", ">=", "<=>", "==" et "!=".

Analyse de dates

Time::Piece dispose d'une fonction intégrée strptime() (de FreeBSD), vous permettant des routines d'analyse de dates incroyablement flexibles. Par exemple :

my $t = Time::Piece->strptime("Dimanche 3 nov, 1943",
                              "%A %drd %b, %Y");

print $t->strftime("%a, %d %b %Y");

Sortie :

Mer, 03 Nov 1943

(voir, il est même assez intelligent pour corriger mon bug de date évident)

Pour plus d'informations, consultez "man strptime", qui devrait être disponible sur tous les systèmes Unix.

Ou regardez ici : http://www.unix.com/man-page/FreeBSD/3/strftime/

ATTENTION %A, %a, %B, %b, et leurs amis

Par défaut, Time::Piece::strptime ne peut analyser que les noms de dates en anglais américain. Pendant ce temps, Time::Piece->strftime() retournera des noms de dates utilisant la locale système configurée actuelle. Cela signifie que les dates retournées par strf

YYYY-MM-DDThh:mm:ss

La norme ISO 8601 définit le format de date comme YYYY-MM-DD, et le format d'heure comme hh:mm:ss (heure sur 24 heures), et si elles sont combinées, elles doivent être concaténées avec un 'T' avant l'heure.

Numéro de Semaine

Le numéro de semaine peut ne pas être un concept familier à certains lecteurs. La norme ISO 8601 définit que les semaines commencent le lundi, et la semaine 1 de l'année est celle qui inclut à la fois le 4 janvier et le premier mercredi de l'année. Autrement dit, si le premier lundi de janvier tombe le 2, 3 ou 4, les jours précédant celui-ci font partie de la dernière semaine de l'année précédente. Les numéros de semaine vont de 1 à 53.

Remplacement Global

Enfin, il est possible de remplacer localtime et gmtime partout en incluant la balise ':override' dans la liste d'importation :

use Time::Piece ':override';

ATTENTION

Définition de $ENV{TZ} dans les Threads sous Win32

Note : Lorsque perl est utilisé dans la configuration par défaut de Win32 (spécifiquement, lorsque perl est compilé avec PERL_IMPLICIT_SYS), chaque interpréteur perl conserve sa propre copie de l'environnement et seul l'interpréteur principal mettra à jour l'environnement visible par strftime.

Par conséquent, si vous modifiez $ENV{TZ} depuis un thread autre que le thread principal, ces modifications ne seront pas visibles dans strftime si vous l'appelez ultérieurement avec le code de format %Z. Vous devez modifier $ENV{TZ} dans le thread principal pour avoir l'effet désiré (et également appeler _tzset() dans le thread principal pour enregistrer le changement d'environnement).

De plus, rappelez-vous que cette mise en garde s'applique également à fork(), qui est émule par les threads Win32.

Utilisation des secondes epoch

Ce module utilise le système des secondes epoch fourni par la fonction perl time() et pris en charge par gmtime() et localtime().

Si votre perl ne prend pas en charge les dates supérieures à 2^31 secondes, ce module pourrait échouer à traiter les dates au-delà de l'an 2038. Des efforts sont en cours pour corriger cela dans perl. Alternativement, utilisez un perl 64 bits. Ou, si aucune de ces options n'est possible, utilisez le module DateTime qui prend en charge les années bien dans le futur et le passé.

De plus, la représentation interne de Time::Piece->strftime diffère de l'implémentation POSIX standard en ce qu'elle utilise l'epoch (plutôt que des parties séparées d'année, de mois et de jour). Cette modification a été ajoutée dans la version 1.30. Si vous avez besoin d'un strftime plus traditionnel (qui ne calcule normalement pas correctement les heures d'été), vous pouvez passer les composantes de date de Time::Piece à la fonction strftime fournie par le module POSIX (voir strftime dans POSIX).
