NOM

Tie::Scalar, Tie::StdScalar - définitions de classes de base pour les scalaires liés

SYNTAXE

package NewScalar;
require Tie::Scalar;
@ISA = qw(Tie::Scalar);
sub FETCH { ... }           # Fournir une méthode nécessaire
sub TIESCALAR { ... }       # Remplace la méthode héritée
package NewStdScalar;
require Tie::Scalar;
@ISA = qw(Tie::StdScalar);
# Toutes les méthodes sont fournies par défaut, donc ne définissez
# que ce qui doit être remplacé
sub FETCH { ... }
package main;
tie $new_scalar, 'NewScalar';
tie $new_std_scalar, 'NewStdScalar';

DESCRIPTION

Ce module fournit des méthodes squelettiques pour les classes de liaison de scalaires. Voir perltie pour une liste des fonctions requises pour lier un scalaire à un paquet. Le paquet de base Tie::Scalar fournit une méthode "new", ainsi que les méthodes "TIESCALAR", "FETCH" et "STORE". Le paquet Tie::StdScalar fournit toutes les méthodes spécifiées dans perltie. Il hérite de Tie::Scalar et fait en sorte que les scalaires qui lui sont liés se comportent exactement comme les scalaires intégrés, ce qui permet une surcharge sélective des méthodes. La méthode "new" est fournie comme moyen de support hérité pour les classes qui oublient de fournir leur propre méthode "TIESCALAR".

Pour les développeurs souhaitant écrire leurs propres classes de scalaires liés, les méthodes sont résumées ci-dessous. La section perltie non seulement documente celles-ci, mais contient également des exemples de code :

TIESCALAR nom_classe, LISTE
La méthode appelée par la commande "tie $scalaire, nom_classe". Associe une nouvelle instance scalaire à la classe spécifiée. "LISTE" représenterait des arguments supplémentaires (dans la lignée de AnyDBM_File et ses compatriotes) nécessaires pour compléter l'association.
FETCH ce
Récupère la valeur du scalaire lié référencé par ce.
STORE ce, valeur
Stocke la donnée valeur dans le scalaire lié référencé par ce.
DESTROY ce
Libère le stockage associé au scalaire lié référencé par ce. Ceci est rarement nécessaire, car Perl gère sa mémoire assez bien. Mais l'option existe, au cas où une classe souhaiterait effectuer des actions spécifiques lors de la destruction d'une instance.

Tie::Scalar vs Tie::StdScalar

"Tie::Scalar" fournit toutes les méthodes nécessaires, mais il faut réaliser qu'elles ne font rien d'utile. Appeler "Tie::Scalar::FETCH" ou "Tie::Scalar::STORE" entraîne un (intercepable) croak. Et si vous héritez de "Tie::Scalar", vous *devez* fournir soit une méthode "new" soit une méthode "TIESCALAR".

Si vous recherchez une classe qui fait tout pour vous que vous ne définissez pas vous-même, utilisez la classe "Tie::StdScalar", pas la classe "Tie::Scalar".
