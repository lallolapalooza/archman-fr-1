NOM

Tie::CPHash - Table de hachage sensible à la casse mais respectant la casse

VERSION

Ce document décrit la version 2.000 de Tie::CPHash, publiée le 17 janvier 2015.

SYNOPIS

use Tie::CPHash 2; # permet l'initialisation pendant le tie
tie %cphash, 'Tie::CPHash', key => 'value';
$cphash{'Hello World'} = 'Hi there!';
printf("La clé `%s' a été utilisée pour stocker `%s'.\n",
       tied(%cphash)->key('HELLO WORLD'),
       $cphash{'HELLO world'});

DESCRIPTION

Le module Tie::CPHash fournit une table de hachage qui est sensible à la casse mais respecte la casse. Cela signifie que

$cphash{KEY}    $cphash{key}
$cphash{Key}    $cphash{keY}

se réfèrent tous à la même entrée. De plus, le hachage se souvient de la forme de la clé qui a été utilisée en dernier pour stocker l'entrée. Les fonctions "keys" et "each" retourneront la clé qui a été utilisée pour définir la valeur.

Un exemple devrait clarifier cela :

tie %h, 'Tie::CPHash', Hello => 'World';
print $h{HELLO};            # Affiche 'World'
print keys(%h);             # Affiche 'Hello'
$h{HELLO} = 'WORLD';
print $h{hello};            # Affiche 'WORLD'
print keys(%h);             # Affiche 'HELLO'

Tie::CPHash version 2.000 a introduit la possibilité de passer une liste de paires "clé => valeur" pour initialiser le hachage (ainsi que la méthode "add" qui la gère). La liste doit inclure une valeur pour chaque clé, sinon le constructeur échouera.

La méthode supplémentaire "key" vous permet de récupérer la casse d'une clé spécifique :

# Après l'exemple précédent, cela affiche 'HELLO' :
print tied(%h)->key('Hello');

(La fonction "tied" retourne l'objet auquel %h est lié.)

Si vous avez besoin d'un hachage insensible à la casse, mais que vous n'avez pas besoin de conserver la casse, utilisez simplement $hash{lc $key} au lieu de $hash{$key}. Cela a beaucoup moins de surcharge que Tie::CPHash.

"use Tie::CPHash;" n'exporte rien dans votre espace de noms.

MÉTHODES

add

tied(%h)->add( key => value, ... );
tied(%h)->add( \@list_of_key_value_pairs );

Cette méthode (introduite dans la version 2.000) ajoute des clés et des valeurs au hachage. C'est comme

%h = @list_of_key_value_pairs;

sauf qu'elle ne vide pas le hachage d'abord. Elle accepte soit une liste, soit une référence de tableau. Elle échoue si la liste contient un nombre impair d'éléments. Elle retourne l'objet haché lié.

Si la liste contient des clés dupliquées, la dernière paire "clé => valeur" dans la liste l'emporte. (Vous ne pouvez pas passer une référence de hachage à "add" car il serait ambigu de savoir quelle clé l'emporterait si deux clés différaient uniquement par la casse.)

Pour ceux qui sont habitués à Tie::IxHash, "add" est aliasé à la fois pour "Push" et "Unshift". (Tie::CPHash ne conserve pas l'ordre des clés.)

key

$set_using_key = tied(%h)->key( $key )

Cette méthode vous permet de récupérer la casse d'une clé spécifique. Par exemple :

$h{HELLO} = 'World';
print tied(%h)->key('Hello'); # affiche HELLO

Si la clé n'existe pas dans le hachage, elle retourne "undef".

DIAGNOSTICS

Nombre impair d'éléments dans CPHash add
Vous avez passé une liste avec un nombre impair d'éléments à la méthode "add" (ou à "tie", qui utilise "add"). La liste doit contenir une valeur pour chaque clé.

CONFIGURATION ET ENVIRONNEMENT

Tie::CPHash ne nécessite aucun fichier de configuration ni variable d'environnement.
