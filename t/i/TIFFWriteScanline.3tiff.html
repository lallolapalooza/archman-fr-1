NOM

TIFFWriteScanline - écrit une ligne de balayage dans un fichier TIFF ouvert

SYNTAXE

#include <tiffio.h>
int TIFFWriteScanline(TIFF *tif, tdata_t buf, uint32_t row, tsample_t sample)

DESCRIPTION

Écrit des données dans un fichier à la ligne spécifiée. Le paramètre sample est utilisé uniquement si les données sont organisées en plans séparés (PlanarConfiguration = 2). Les données sont supposées être non compressées et dans l'ordre des bits et octets natif de la machine hôte. Les données écrites dans le fichier sont compressées selon le schéma de compression du répertoire TIFF courant (voir ci-dessous). Si la ligne de balayage courante est au-delà de la fin du sous-fichier courant, le champ ImageLength est automatiquement augmenté pour inclure la ligne de balayage (sauf pour PlanarConfiguration = 2, où ImageLength ne peut pas être modifié une fois que les premières données sont écrites). Si ImageLength est augmenté, les champs StripOffsets et StripByteCounts sont similairement agrandis pour refléter les données écrites au-delà de la fin précédente de l'image.

NOTES

La bibliothèque écrit des données encodées en utilisant l'ordre des octets de la machine native. Les lecteurs TIFF correctement implémentés sont censés effectuer les échanges d'octets nécessaires pour traiter correctement les données d'image avec BitsPerSample supérieur à 8. La bibliothèque tente de masquer les différences d'ordre des bits entre l'image et la machine native en convertissant les données de l'ordre de la machine native.

En C++, le paramètre sample est par défaut à 0.

Une fois que des données sont écrites dans un fichier pour le répertoire courant, les valeurs de certaines balises peuvent ne pas être modifiées ; voir TIFFSetField() pour plus d'informations.

Il n'est pas possible d'écrire des lignes de balayage dans un fichier qui utilise une organisation en tuiles. La routine TIFFIsTiled() peut être utilisée pour déterminer si le fichier est organisé en tuiles ou en bandes.

VALEUR DE RETOUR

TIFFWriteScanline() renvoie -1 si une erreur est immédiatement détectée et 1 pour une écriture réussie.

DIAGNOSTICS

Tous les messages d'erreur sont dirigés vers la routine TIFFErrorExtR().

%s : Fichier non ouvert en écriture :

Le fichier a été ouvert en lecture, pas en écriture.

« Impossible d'écrire des lignes de balayage dans une image tuilée » :

Une tentative a été faite pour écrire une ligne de balayage dans une image tuilée. L'image est supposée être organisée en tuiles car les balises TileWidth et TileLength ont été définies avec TIFFSetField().

« L'algorithme de compression ne supporte pas l'accès aléatoire » :

Des données ont été écrites dans un ordre non séquentiel dans un fichier qui utilise un algorithme de compression et qui a RowsPerStrip supérieur à un. C'est-à-dire que les données de l'image doivent être stockées sous forme compressée, avec plusieurs lignes regroupées dans une bande. Dans ce cas, la bibliothèque ne prend pas en charge l'accès aléatoire aux données. Les données doivent être écrites soit sous forme de bandes complètes, séquentiellement par ligne, soit la valeur de RowsPerStrip doit être définie à un.

%s : Doit définir « ImageWidth » avant d'écrire des données :

La largeur de l'image n'a pas été définie avant la première écriture. Voir TIFFSetField() pour savoir comment faire.

%s : Doit définir « PlanarConfiguration » avant d'écrire des données :

L'organisation des données n'a pas été définie avant la première écriture. Voir TIFFSetField() pour savoir comment faire.

Impossible de modifier « ImageLength » lors de l'utilisation de plans séparés :

Des plans d'image séparés sont utilisés (PlanarConfiguration = 2), mais le nombre de lignes n'a pas été spécifié avant la première écriture. La bibliothèque prend en charge la croissance dynamique d'une image uniquement lorsque les données sont organisées de manière contiguë (PlanarConfiguration = 1).

« %d : Échantillon hors limites, max %d » :

Le paramètre sample était supérieur à la valeur de la balise SamplesPerPixel.

%s : Pas assez d'espace pour les tableaux de bandes :

Il n'y avait pas assez d'espace pour les tableaux qui contiennent les décalages de bandes et les nombres d'octets.

BOGUES

L'écriture de données YCbCR sous-échantillonnées ne fonctionne pas correctement car, pour PlanarConfiguration = 2, la taille d'une ligne de balayage n'est pas calculée par échantillon, et pour PlanarConfiguration = 1, la bibliothèque n'entrelace pas les échantillons bloqués.
