NOM

Tie::Simple - Liaisons de variables simplifiées : beaucoup, beaucoup, beaucoup plus simple...

VERSION

version 1.04

SYNOPSIS

use Tie::Simple;
tie $scalaire, 'Tie::Simple', $donnees,
    FETCH     => sub { ... },
    STORE     => sub { ... };
tie @tableau, 'Tie::Simple', $donnees,
    FETCH     => sub { ... },
    STORE     => sub { ... },
    FETCHSIZE => sub { ... },
    STORESIZE => sub { ... },
    EXTEND    => sub { ... },
    EXISTS    => sub { ... },
    DELETE    => sub { ... },
    CLEAR     => sub { ... },
    PUSH      => sub { ... },
    POP       => sub { ... },
    SHIFT     => sub { ... },
    UNSHIFT   => sub { ... },
    SPLICE    => sub { ... };
tie %hash, 'Tie::Simple', $donnees,
    FETCH     => sub { ... },
    STORE     => sub { ... },
    DELETE    => sub { ... },
    CLEAR     => sub { ... },
    EXISTS    => sub { ... },
    FIRSTKEY  => sub { ... },
    NEXTKEY   => sub { ... };
tie *HANDLE, 'Tie::Simple', $donnees,
    WRITE     => sub { ... },
    PRINT     => sub { ... },
    PRINTF    => sub { ... },
    READ      => sub { ... },
    READLINE  => sub { ... },
    GETC      => sub { ... },
    CLOSE     => sub { ... };

DESCRIPTION

Ce module ajoute la capacité de créer rapidement de nouveaux types d'objets de liaison sans avoir à créer une classe complète. Il le fait de manière à essayer de faciliter la vie du programmeur lorsqu'il s'agit de liaisons à usage unique que je trouve utile d'utiliser de temps en temps.

Le paquet "Tie::Simple" est en fait une façade pour d'autres classes qui font réellement tout le travail une fois liées, mais ce paquet s'occupe de déterminer automatiquement ce que vous essayez de faire.

J'ai essayé de rendre cela aussi intuitif que possible et dépendant d'autres éléments de Perl dans la mesure du possible afin de minimiser le besoin de documentation et de rendre cela extra, extra performant.

LIAISONS SIMPLES

Pour configurer votre liaison rapide, commencez simplement par l'instruction de liaison typique sur la variable que vous liez. Vous devriez toujours lier au paquet "Tie::Simple" et non directement aux autres paquets inclus avec ce module, car ceux-ci ne sont présents que comme aides (même s'ils sont réellement les classes de liaison).

Le type de liaison dépend du type du premier argument donné à tie. Cela devrait être assez évident d'après le "SYNOPSIS" ci-dessus. Par conséquent, les arguments sont :

1.
La variable à lier.
2.
La chaîne 'Tie::Simple'.
3.
Une valeur scalaire (ci-après appelée "données locales").
4.
Une liste de paires nom/CODE.

À ce stade, vous devrez avoir une certaine compréhension des liaisons avant de pouvoir continuer. Je suggère de consulter perltie.

Comme vous le remarquerez dans la documentation de perltie, chaque paquet de liaison définit des fonctions dont le premier argument est appelé "this". Le troisième argument, les données locales, prendra la place de "this" dans tous les appels de sous-routine que vous définissez dans la liste des paires nom/CODE. Chaque nom doit être le nom de la fonction qui serait définie pour le type de liaison approprié si vous faisiez une définition complète de paquet. La sous-routine correspondant à ce nom recevra exactement les arguments spécifiés dans la documentation perltie, mais au lieu de "this", elle recevra la valeur scalaire des données locales que vous avez définie (qui pourrait même être "undef" si vous n'en avez pas besoin).

LES LIAISONS PEUVENT ETRE ENCORE PLUS SIMPLES

Le synopsis ci-dessus montre les sous-routines typiques que vous pourriez définir. (J'ai omis les méthodes "UNTIE" et "DESTROY", mais vous pouvez les définir si vous en avez besoin, assurez-vous de lire la documentation perltie sur les inconvénients possibles.) Cependant, le "SYNOPSIS" est beaucoup plus complet que ce dont vous avez probablement besoin dans la plupart des cas. C'est parce que "Tie::Simple" fait de son mieux pour utiliser certaines des constructions Perl utiles qui aident à créer des paquets de liaison.

SCALAIRES

Si vous créez une liaison scalaire, vous pouvez supposer que vous bénéficiez de tous les avantages de Tie::Scalar.

TABLEAUX

Si vous créez une liaison de tableau, vous pouvez supposer que vous bénéficiez de tous les avantages de Tie::Array.

HASHES

Si vous créez une liaison de hachage, vous pouvez supposer que vous bénéficiez de tous les avantages de Tie::Hash.

POIGNEES

Si vous créez une liaison de poignée, vous pouvez supposer que vous bénéficiez de tous les avantages de Tie::Handle.

À FAIRE

Ce serait bien si vous pouviez déclarer des listes @ISA personnalisées, ne serait-ce pas ? J'aimerais ajouter une telle fonctionnalité, mais proposer du code de dispatch "SUPER::" personnalisé ou générer de nouveaux paquets "anonymes" sont les seuls moyens qui me viennent à l'esprit pour le faire. Je n'ai pas vraiment le temps d'ajouter une telle fonctionnalité pour le moment.
