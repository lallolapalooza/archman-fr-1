NOM

Time::JulianDay -- Manipulations du calendrier julien

SYNTAXE

use Time::JulianDay
$jd = julian_day($année, $mois_1_à_12, $jour)
$jd = local_julian_day($secondes_depuis_1970);
$jd = gm_julian_day($secondes_depuis_1970);
($année, $mois_1_à_12, $jour) = inverse_julian_day($jd)
$jour_semaine = day_of_week($jd) 
print (Dim,Lun,Mar,Mer,Jeu,Ven,Sam)[$jour_semaine];
$secondes_depuis_1er_jan_1970 = jd_secondslocal($jd, $heure, $min, $sec)
$secondes_depuis_1er_jan_1970 = jd_secondsgm($jd, $heure, $min, $sec)
$secondes_depuis_1er_jan_1970 = jd_timelocal($sec,$min,$heures,$jour_mois,$mois_0_à_11,$année)
$secondes_depuis_1er_jan_1970 = jd_timegm($sec,$min,$heures,$jour_mois,$mois_0_à_11,$année)

DESCRIPTION

JulianDay est un paquetage qui manipule les dates sous forme de nombre de jours depuis une date très ancienne. Il est facile d'ajouter et de soustraire du temps en utilisant les jours juliens...

Le jour de la semaine renvoyé par day_of_week() est 0 pour le dimanche, et 6 pour le samedi, avec les autres jours entre les deux.

ERRATA

Time::JulianDay n'est pas une implémentation correcte. Il y a deux problèmes. Le premier est que Time::JulianDay ne fonctionne qu'avec des entiers. Le Jour Julien peut être fractionnaire pour représenter le temps au sein d'une journée. Si vous appelez inverse_julian_day() avec un temps non entier, cela vous donnera souvent un résultat incorrect.

Le second problème est que les Jours Juliens commencent à midi plutôt qu'à minuit. La fonction julian_day() renvoie des résultats trop grands de 0.5.

Que faire face à ces problèmes est actuellement sujet à débat. Je suis tenté de laisser les fonctions actuelles telles quelles et d'ajouter un second ensemble avec un comportement plus précis.

Il existe une autre implémentation dans Astro::Time qui pourrait être plus précise.
