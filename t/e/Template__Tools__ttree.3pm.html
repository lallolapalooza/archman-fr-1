NOM

Template::Tools::ttree - traiter les arbres de répertoires de modèles

SYNOPIS

ttree [options] [fichiers]

DESCRIPTION

Le script ttree est utilisé pour traiter des arbres de répertoires contenant des fichiers de modèles. Le résultat du traitement de chaque fichier est écrit dans un fichier correspondant dans un répertoire de destination. Le script compare les horodatages des fichiers source et de destination (lorsqu'ils existent) et ne traite que ceux qui ont été modifiés. En d'autres termes, il est équivalent à 'make' pour le Template Toolkit.

Le script prend en charge un certain nombre d'options qui peuvent être utilisées pour configurer le comportement, définir des emplacements et spécifier des options du Template Toolkit. Le script lit d'abord le fichier de configuration .ttreerc dans le répertoire personnel de l'utilisateur, ou un fichier alternatif spécifié dans la variable d'environnement TTREERC. Il traite ensuite toutes les options de la ligne de commande, y compris tous les fichiers de configuration supplémentaires spécifiés avec l'option "-f" (fichier).

Le fichier de configuration .ttreerc

Lorsque vous exécutez ttree pour la première fois, il vous sera demandé si vous souhaitez qu'il soit créé pour vous. Ce fichier sera créé dans votre répertoire personnel.

$ ttree
Souhaitez-vous que je crée un fichier d'exemple '.ttreerc' pour vous ?
(fichier : /home/abw/.ttreerc)   [y/n] : y
Le fichier /home/abw/.ttreerc a été créé. Veuillez modifier ce fichier et relancer ttree

Le but de ce fichier est de définir toutes les options de configuration globales que vous souhaitez appliquer chaque fois que vous exécutez ttree. Par exemple, vous pouvez utiliser les options "ignore" et "copy" pour définir des expressions régulières indiquant quels fichiers doivent être ignorés et lesquels doivent être copiés au lieu d'être traités comme des modèles. Vous pouvez également définir des drapeaux tels que "verbose" et "recurse" selon vos préférences.

Un exemple minimum de .ttreerc :

# ignorer ces fichiers
ignore = \b(CVS|RCS)\b
ignore = ^#
ignore = ~$
# copier ces fichiers
copy   = \.(gif|png|jpg|pdf)$ 
# récursion dans les répertoires
recurse
# fournir des informations sur ce qui se passe
verbose

Dans la plupart des cas, vous voudrez créer un fichier de configuration différent pour chaque projet sur lequel vous travaillez. L'option "cfg" permet de spécifier un répertoire où ttree peut trouver d'autres fichiers de configuration.

cfg = /home/abw/.ttree

L'option "-f" peut être utilisée pour spécifier quel fichier de configuration doit être utilisé. Vous pouvez spécifier un nom de fichier en utilisant un chemin absolu ou relatif :

$ ttree -f /home/abw/web/example/etc/ttree.cfg
$ ttree -f ./etc/ttree.cfg
$ ttree -f ../etc/ttree.cfg

Si le fichier de configuration ne commence pas par "/" ou "." ou quelque chose qui ressemble à un chemin absolu MS-DOS (par exemple, "C:\\etc\\ttree.cfg"), alors ttree le recherchera dans le répertoire spécifié par l'option "cfg".

$ ttree -f test1          # /home/abw/.ttree/test1

L'option "cfg" ne peut être utilisée que dans le fichier .ttreerc. Toutes les autres options peuvent être utilisées dans le fichier .ttreerc ou dans tout autre fichier de configuration ttree. Elles peuvent également toutes être spécifiées comme options de ligne de commande.

N'oubliez pas que .ttreerc est toujours traité avant tout fichier de configuration spécifié avec l'option "-f". Certaines options comme "lib" peuvent être utilisées un nombre quelconque de fois et accumuler leur valeur.

Par exemple, considérez les configurations suivantes :

/home/abw/.ttreerc :

cfg = /home/abw/.ttree
lib = /usr/local/tt2/templates

/home/abw/.ttree/myconfig :

lib = /home/abw/web/example/templates/lib

Lors de l'invocation de ttree comme suit :

$ ttree -f myconfig

l'option "lib" sera définie sur les répertoires suivants :

/usr/local/tt2/templates
/home/abw/web/example/templates/lib

Tout modèle situé dans /usr/local/tt2/templates sera utilisé de préférence malgré les emplacements dans /home/abw/web/example/templates/lib. Cela peut être ce que vous souhaitez, mais cela peut aussi ne pas l'être. Pour cette raison, il est conseillé de garder .ttreerc aussi simple que possible et d'utiliser différents fichiers de configuration pour chaque projet ttree.

Options de répertoire

L'option "src" est utilisée pour définir le répertoire contenant les modèles sources à traiter. Elle peut être fournie comme une option de ligne de commande ou dans un fichier de configuration, comme illustré ici :

src = /home/abw/web/example/templates/src

Chaque modèle dans ce répertoire correspond généralement à une seule page Web ou document.

L'option "dest" est utilisée pour spécifier le répertoire de destination où les résultats seront générés.

dest = /home/abw/web/example/html

L'option "lib" est utilisée pour définir un ou plusieurs répertoires contenant des modèles de bibliothèque supplémentaires. Ces modèles ne sont pas des documents en soi et incluent généralement des composants plus petits et modulaires tels que des en-têtes, des pieds de page et des menus qui sont intégrés dans des pages ou des modèles.

lib = /home/abw/web/example/templates/lib
lib = /usr/local/tt2/templates

L'option "lib" peut être utilisée plusieurs fois pour ajouter d'autres répertoires au chemin de recherche.

Une liste de modèles peut être transmise à ttree comme arguments de ligne de commande.

$ ttree foo.html bar.html

Cela recherche ces modèles dans le répertoire "src" et les traite via le Template Toolkit, en utilisant tout composant supplémentaire du chemin "lib". Le résultat généré est écrit dans le fichier correspondant dans le répertoire "dest".

Si ttree est invoqué sans spécifier explicitement quels modèles doivent être traités, il traitera tous les fichiers du répertoire "src". Si l'option "-r" (récursion) est activée, il parcourra également les sous-répertoires et traitera les autres fichiers de modèles qu'il y trouve.

$ ttree -r

Si un modèle a déjà été traité, ttree comparera les horodatages du fichier source et du fichier de destination. Si le fichier source (ou un fichier dont il dépend) n'a pas été modifié plus récemment que le fichier de sortie généré, ttree ne le traitera pas. L'option "-a" (tous) peut être utilisée pour forcer ttree à traiter tous les fichiers, indépendamment des horodatages.

$ ttree -a

Tout modèle explicitement nommé comme argument de ligne de commande est toujours traité et le contrôle de l'horodatage est omis.

Options de fichier

Les options "ignore", "copy" et "accept" sont utilisées pour spécifier des expressions régulières sur les noms de fichiers. Les fichiers qui correspondent à l'une des options "ignore" ne sont pas traités. Les fichiers qui survivent et correspondent à l'une des expressions régulières de "copy" sont copiés dans le répertoire de destination. Les fichiers qui survivent et correspondent à l'une des conditions de "accept" sont traités par le Template Toolkit. Si aucune option "accept" n'est spécifiée, les fichiers sont acceptés pour le traitement s'ils n'ont pas déjà été copiés ou ignorés.

# ignorer ces fichiers
ignore = \b(CVS|RCS)\b
ignore = ^#
ignore = ~$
# copier ces fichiers
copy   = \.(gif|png|jpg|pdf)$ 
# accepter uniquement les modèles .tt2
accept = \.tt2$

L'option "suffix" est utilisée pour définir les correspondances entre les extensions de fichiers des modèles sources et les fichiers de sortie générés. L'exemple suivant spécifie que les modèles sources avec l'extension ".tt2" sont traités par le Template Toolkit.

suffix = .tt2

NOM

ttree

SYNOPSIS

ttree [options] [template-file]

DESCRIPTION

ttree est un outil de traitement de modèles, vous permettant de spécifier comment les modèles dépendent d'autres fichiers ou groupes de fichiers. Les options depend et depend_file vous permettent de spécifier comment un fichier modèle donné dépend d'un autre fichier ou groupe de fichiers. L'option depend est utilisée pour exprimer une dépendance unique.

$ ttree --depend foo=bar,baz

Cet exemple de ligne de commande montre l'utilisation de l'option --depend pour spécifier que le fichier foo dépend des modèles bar et baz. Cette option peut être utilisée plusieurs fois sur la ligne de commande :

$ ttree --depend foo=bar,baz --depend crash=bang,wallop

ou dans un fichier de configuration :

depend foo=bar,baz
depend crash=bang,wallop

Le fichier apparaissant à gauche du = est spécifié par rapport aux répertoires src ou lib. Le(s) fichier(s) apparaissant à droite peuvent être spécifiés par rapport à n'importe lequel de ces répertoires ou en tant que chemins de fichiers absolus.

Par exemple :

$ ttree --depend foo=bar,/tmp/baz

Pour définir une dépendance qui s'applique à tous les fichiers, utilisez * à gauche du =.

$ ttree --depend *=header,footer

ou dans un fichier de configuration :

depend *=header,footer

Tous les modèles définis dans les options pre_process, post_process, process ou wrapper seront automatiquement ajoutés à la liste des dépendances globales qui s'appliquent à tous les modèles.

L'option depend_file peut être utilisée pour spécifier un fichier contenant des informations de dépendance.

$ ttree --depend_file=/home/abw/web/example/etc/ttree.dep

Voici un exemple de fichier de dépendances :

# Ceci est un commentaire. Il est ignoré.

index.html: header footer menubar 

header: titlebar hotlinks

menubar: menuitem

# s'étendant sur plusieurs lignes avec la barre oblique inverse
another.html: header footer menubar \
sidebar searchform

Les lignes commençant par le caractère # sont des commentaires et sont ignorées. Les lignes vides sont également ignorées. Toutes les autres lignes doivent fournir un nom de fichier suivi d'un deux-points, puis d'une liste de fichiers dépendants séparés par des espaces, des virgules ou les deux. Les espaces autour du deux-points sont également facultatifs. Les lignes se terminant par un guillemet (\") sont continuées sur la ligne suivante.

Les fichiers contenant des espaces peuvent être mis entre guillemets. Ce n'est nécessaire que pour les fichiers après le deux-points (':'). Le fichier avant le deux-points peut être mis entre guillemets s'il contient un deux-points.

Comme avec les options de ligne de commande, le caractère * peut être utilisé comme joker pour spécifier une dépendance pour tous les modèles.

* : config,header
