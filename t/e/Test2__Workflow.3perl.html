Test2::Workflow(3perl) Guide du programmeur Perl Test2::Workflow(3perl)

NOM

Test2::Workflow - Un flux de travail de test est une manière de structurer les tests à l'aide d'unités composables.

DESCRIPTION

Un flux de travail de test est une manière de structurer les tests à l'aide d'unités composables. Un exemple bien connu de flux de travail de test est RSPEC http://rspec.info/. RSPEC est implémenté en utilisant Test2::Workflow dans Test2::Tools::Spec ainsi que plusieurs extensions.

CONCEPTS IMPORTANTS

BUILD

Test2::Workflow::Build

Un Build est utilisé pour composer des tâches. Habituellement, un objet build est poussé sur la pile avant d'exécuter le code qui ajoute des tâches au build. Une fois le sous-programme build terminé, le build est dépilé et retourné. Généralement, un build est converti en une tâche racine ou un groupe de tâches.

RUNNER

Test2::Workflow::Runner

Un runner prend les tâches composées et les exécute dans le bon ordre.

TASK

Test2::Workflow::Task

Une tâche est une unité de travail à accomplir. Il existe 2 types principaux de tâches.

ACTION

Une action est l'unité la plus simple utilisée dans la composition. Une action est essentiellement un nom et un bloc de code à exécuter.

GROUP

Un groupe est une tâche composée d'autres tâches.

EXPORTS

Tous les exports sont facultatifs, vous devez demander ceux que vous souhaitez.

$parsed = parse_args(args => \@args)
$parsed = parse_args(args => \@args, level => $L)
$parsed = parse_args(args => \@args, caller => [caller($L)])
Ceci analysera les arguments typiques d'un constructeur de tâche. Le tableau @args DOIT contenir un nom (scalaire simple contenant du texte) et également une seule référence de code. Le tableau @args PEUT également contenir n'importe quelle quantité de numéros de ligne ou de hashrefs. La structure de données résultante sera un seul hashref avec tous les hashrefs fournis fusionnés, et les clés 'name', 'code', 'lines' et 'frame' définies à partir des autres arguments. 
{
    # Tous les hashrefs de @args sont fusionnés :
    %donnees_hashref_entree_fusionnees,
    # @args doit avoir exactement 1 scalaire en texte brut qui n'est pas un nombre, il
    # est considéré comme le nom :
    name => 'nom des arguments d\'entrée'
    # Les valeurs entières sont traitées comme des numéros de ligne
    lines => [ 35, 44 ],
    # Exactement 1 référence de code doit être fournie dans @args :
    code => \&some_code,
    # 'frame' contient les données 'caller'. Ceci peut être passé directement,
    # obtenu du paramètre 'level', ou déduit automatiquement.
    frame => ['A::Package', 'a_file.pm', 42, ...],
}
$build = init_root($pkg, %args)
Ceci initialisera (ou retournera le build existant) pour le paquet spécifié. %args sont passés au constructeur Test2::Workflow::Build. Ceci utilise les valeurs par défaut suivantes (qui peuvent être remplacées en utilisant %args) : 
name    => $pkg,
flat    => 1,
iso     => 0,
async   => 0,
is_root => 1,

Notez que %args est complètement ignoré si le build du paquet a déjà été initialisé.

$build = root_build($pkg)
Ceci retournera le build racine pour le paquet spécifié.
$build = current_build()
Ceci retournera le build actuellement en haut de la pile de builds (ou undef).
$build = build($name, \%params, sub { ... })
Ceci poussera un nouvel objet build sur la réserve de builds, puis exécutera le bloc de code fourni. Une fois que le bloc de code a terminé son exécution, le build sera dépilé et retourné.

Voir parse_args() pour les détails sur le traitement des arguments.
