NOM

Test::File -- tester les attributs de fichier

SYNTAXE

use Test::File;

DESCRIPTION

Ce module fournit une collection d'utilitaires de test pour les attributs de fichier.

Certains attributs de fichier dépendent du propriétaire du processus testant le fichier, de la même manière que les opérateurs de test de fichier. Par exemple, root (ou super-utilisateur ou administrateur) peut toujours être capable de lire des fichiers, quelles que soient les permissions.

Certains attributs n'ont pas de sens en dehors de Unix non plus, donc certains tests s'auto-skip s'ils pensent qu'ils ne fonctionneront pas sur la plateforme. Si vous avez un moyen de faire fonctionner ces fonctions sous Windows, par exemple, envoyez-moi un correctif. :) Si vous voulez prétendre être Windows sur une machine non-Windows (par exemple, pour tester skip()), vous pouvez définir la variable d'environnement "PRETEND_TO_BE_WINDOWS".

Le paramètre facultatif NAME pour chaque fonction vous permet de spécifier un nom pour le test. S'il n'est pas fourni, un nom raisonnable par défaut sera généré.

Fonctions

has_symlinks
Retourne vrai si ce module pense que le système actuel prend en charge les liens symboliques.

Ce n'est pas une fonction de test. C'est quelque chose que les tests peuvent utiliser pour déterminer ce à quoi ils doivent s'attendre ou ce qu'ils doivent sauter.

file_contains_like ( NOM_FICHIER, MOTIF [, NOM ] )
Ok si le fichier existe et si son contenu (en une seule chaîne) correspond au MOTIF, non ok si le fichier n'existe pas, n'est pas lisible, ou existe mais ne correspond pas au MOTIF.

Comme le contenu du fichier est lu en mémoire, vous ne devriez pas l'utiliser pour les gros fichiers. Outre la consommation de mémoire, les diagnostics de test pour les tests échoués pourraient être difficiles à déchiffrer. Cependant, pour les fichiers courts, cela fonctionne très bien.

Comme l'intégralité du contenu est traitée comme une seule grande chaîne, vous pouvez créer un motif qui teste plusieurs lignes. N'oubliez pas que vous pourriez avoir besoin d'utiliser le modificateur /s pour de tels motifs :

# s'assurer que le fichier a un ou plusieurs paragraphes avec la classe CSS X
file_contains_like($html_file, qr{<p class="X">.*?</p>}s);

Inversement, si vous avez besoin de faire correspondre le début ou la fin d'une ligne à l'intérieur du fichier, utilisez le modificateur /m :

# s'assurer que le fichier a un réglage pour foo
file_contains_like($config_file, qr/^ foo \s* = \s* \w+ $/mx);

Si vous souhaitez tester le contenu de votre fichier par rapport à plusieurs motifs, mais que vous ne voulez pas que le fichier soit lu de manière répétée, vous pouvez passer un tableau de motifs au lieu d'un seul motif, comme ceci :

# s'assurer que notre modèle a été correctement rendu
file_contains_like($template_out,
        [
        qr/^ $title_line $/mx,
        map { qr/^ $_ $/mx } @chapter_headings,
        qr/^ $footer_line $/mx,
        ]);

Veuillez noter que si vous faites cela, et que votre fichier n'existe pas ou n'est pas lisible, vous n'obtiendrez qu'un seul échec de test au lieu d'un échec pour chaque motif. Cela pourrait décaler votre plan de test, bien que cela puisse ne pas vous importer à ce stade car votre test a échoué de toute façon. Si cela vous importe, ignorez complètement le plan de test en utilisant la fonction done_testing() de Test::More, ou utilisez "file_readable_ok" conjointement avec un bloc "SKIP".

Contribué par Buddy Burden "<barefoot@cpan.org>".

file_mode_has( NOMFICHIER, MODE [, NOM ] )
Ok si le fichier existe et a tous les bits du mode activés, pas ok si le fichier n'existe pas ou si le mode ne correspond pas. C'est-à-dire que "MODEFICHIER & MODE == MODE" doit être vrai.

Ok si le fichier existe et a tous les bits du mode désactivés, pas ok si le fichier n'existe pas ou si le mode ne correspond pas. C'est-à-dire que "MODEFICHIER & MODE == 0" doit être vrai.

NOM

Test::File

SYNTAXE

use Test::File;

DESCRIPTION

Test::File est un module Perl qui fournit un ensemble de fonctions de test pour vérifier les propriétés et les comportements des fichiers.

TACHES EN COURS

* vérifier les propriétés pour d'autres utilisateurs (lu par root, par exemple)

* vérifier les temps

* vérifier le nombre de liens vers un fichier

* vérifier les parties du chemin (répertoire, nom de fichier, extension)

VOIR AUSSI

Test::Builder, Test::More

Si vous utilisez le nouveau "Test2" (Test2::Tools::File), voir Test2::Tools::File (https://github.com/torbjorn/Test2-Tools-File).
