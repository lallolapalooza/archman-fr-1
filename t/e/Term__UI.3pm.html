NAME

Term::UI - Interface utilisateur de Term::ReadLine simplifiée

SYNOPSIS

use Term::UI;
use Term::ReadLine;
my $term = Term::ReadLine->new('brand');
my $reply = $term->get_reply(
                prompt => 'Quelle est votre couleur préférée ?',
                choices => [qw|bleu rouge vert|],
                default => 'bleu',
);
my $bool = $term->ask_yn(
                    prompt => 'Aimez-vous les biscuits ?',
                    default => 'y',
            );
my $string = q[some_command -option --no-foo --quux='this thing'];
my ($options,$munged_input) = $term->parse_options($string);
### pas d'avertissements de Term::UI, par défaut est '1'
$Term::UI::VERBOSE = 0;
### toujours la valeur par défaut (bon pour les terminaux non interactifs)
### -- la valeur par défaut est '0'
$Term::UI::AUTOREPLY = 1;
### récupérer l'intégralité de l'historique sous forme de chaîne imprimable :
$hist = Term::UI::History->history_as_string;
$hist = $term->history_as_string;

DESCRIPTION

"Term::UI" est un moyen transparent d'éliminer la surcharge de devoir formater une question, puis de valider la réponse, en informant l'utilisateur si la réponse n'était pas correcte et en reposant la question.

Il suffit de lui donner la question que vous souhaitez poser, éventuellement avec un ensemble d'options parmi lesquelles l'utilisateur peut choisir et une valeur par défaut, et "Term::UI" s'occupe du reste.

Pour poser une question oui/non, il existe même une forme abrégée.

COMMENT ÇA MARCHE

"Term::UI" se place à la fin du tableau "Term::ReadLine" @ISA, vous pouvez donc appeler ses méthodes via votre objet terminal.

"Term::UI" utilise "Term::UI::History" pour enregistrer toutes les interactions avec la ligne de commande. Vous pouvez récupérer cet historique, ou modifier le flux de sortie sur lequel l'interaction est imprimée. Voir la documentation de "Term::UI::History" ou la section "SYNOPSIS" pour plus de détails.

MÉTHODES

$reply = $term->get_reply( prompt => 'Quelle est votre couleur préférée ?', [choices => \@list, default => $list[0], preput => "texte à placer comme entrée utilisateur par défaut", multi => BOOL, print_me => "texte supplémentaire à imprimer & enregistrer", allow => $ref] );

"get_reply" pose une question à un utilisateur, puis renvoie la réponse à l'appelant. Si la réponse n'est pas valide (voir ci-dessous pour plus d'informations), la question sera reposée jusqu'à ce qu'une réponse satisfaisante soit entrée.

Vous avez la possibilité de fournir un ensemble d'options parmi lesquelles l'utilisateur peut choisir en utilisant l'argument "choices". Si la réponse ne se trouve pas dans la liste des options présentées, la question sera reposée.

Si vous fournissez une réponse par défaut "default", celle-ci sera renvoyée lorsque $AUTOREPLY est défini à true (voir la section "VARIABLES GLOBALES"), ou lorsque l'utilisateur appuie sur "entrée".

L'argument "preput" permet de spécifier un texte qui sera inséré dans la ligne d'invite comme entrée initiale qui peut être modifiée, supprimée ou acceptée par l'utilisateur. Si vous spécifiez une chaîne vide comme argument "preput", alors la valeur "default" sera utilisée. Cela ne fonctionnera que si le module sous-jacent le prend en charge (seul le module "Term::Readline::Gnu" le prend en charge actuellement).

Vous pouvez indiquer que l'utilisateur peut entrer plusieurs réponses avec le drapeau "multi" désactivé. Notez que dans ce cas, une liste de réponses sera renvoyée au lieu d'une seule chaîne.

En spécifiant un "allow" comme gestionnaire de validation, vous pouvez valider la réponse fournie par l'utilisateur. Cela peut être de n'importe lequel des types que la fonction Params::Check "allow" permet, vous devez donc vous référer à la documentation de cette fonction.

Enfin, vous avez la possibilité d'ajouter un argument "print_me" qui est simplement imprimé avant la question. Il est imprimé sur le même flux de sortie que les autres questions, vous pouvez donc l'utiliser pour suivre une session complète de questions-réponses avec l'utilisateur et la récupérer ultérieurement en utilisant la fonction "Term::UI->history_as_string".

Voir la section "EXEMPLES" pour des exemples sur la façon d'utiliser cette fonction.

$bool = $term->ask_yn( prompt => "Aimez-vous les biscuits ?", [default => (y|1,n|0), print_me => "texte supplémentaire à imprimer & enregistrer"] )

Pose une simple question oui/non à l'utilisateur et renvoie un booléen indiquant si le résultat est "vrai" ou "faux" à l'appelant.

La valeur par défaut sera renvoyée si l'utilisateur appuie sur "entrée" ou si $AUTOREPLY est défini sur true. Voir la section "VARIABLES GLOBALES" ci-dessous.

Vous avez également la possibilité d'ajouter un argument "print_me", qui est simplement imprimé avant la question. Il est imprimé sur le même flux de sortie que les autres questions, vous pouvez donc l'utiliser pour suivre une session complète de questions-réponses avec l'utilisateur et la récupérer ultérieurement en utilisant la fonction "Term::UI->history_as_string".

Voir la section "EXEMPLES" pour des exemples sur la façon d'utiliser cette fonction.

($opts, $munged) = $term->parse_options( STRING );

"parse_options" convertit toutes les options fournies à partir d'une chaîne d'entrée en une référence de hachage. Si elle est appelée dans un contexte de liste, elle renvoie également la partie de la chaîne d'entrée qui ne contient pas d'options.

Considérez cet exemple :

my $str =   q[command --no-foo --baz --bar=0 --quux=bleh ] .
            q[--option="some'thing" -one-dash -single=blah' arg];
my ($options,$munged) =  $term->parse_options($str);
### $options contiendra : ###
$options = {
            'foo'       => 0,
            'bar'       => 0,
            'one-dash'  => 1,
            'baz'       => 1,
            'quux'      => 'bleh',
            'single'    => 'blah\'',
            'option'    => 'some\'thing'
};
### et ceci est la chaîne d'entrée modifiée, c'est-à-dire ce qui reste de l'entrée moins les options
$munged = 'command arg';

Comme vous pouvez le voir, vous pouvez utiliser un seul ou un double "-" pour indiquer une option. Si vous utilisez le préfixe "no-" et ne lui donnez pas de valeur, elle sera définie sur 0. Si elle n'a pas de préfixe et pas de valeur, elle sera définie sur 1. Sinon, elle sera définie sur sa valeur. Notez également qu'elle gère bien les problèmes de guillemets simples/doubles.

$str = $term->history_as_string

"history_as_string" convertit toute l'interaction en une chaîne imprimable. Le texte est imprimé sur le même flux de sortie que les autres questions, vous pouvez donc l'utiliser pour suivre une session complète de questions-réponses avec l'utilisateur et la récupérer ultérieurement en utilisant la fonction "Term::UI->history_as_string".

Term::UI(3pm) - Documentation Perl

NAME

Term::UI - une interface simple pour les applications de terminal

SYNOPSIS

    use Term::UI;
    my $term = Term::UI->new();
    my $reply = $term->get_reply( prompt => 'Nom?' );
    my $bool = $term->ask_yn( prompt => 'Voulez-vous continuer?', default => 'y' );

DESCRIPTION

Ce module fournit une interface simple pour interagir avec l'utilisateur via la ligne de commande. Il vous permet de poser des questions, d'accepter des réponses ouvertes, des choix parmi une liste prédéfinie, et de demander des confirmations oui/non.

Il utilise le module "Term::ReadLine" si disponible, sinon il s'appuie sur les entrées/sorties standard.

HOW IT WORKS

Le module vous permet de créer un objet Term::UI, puis d'appeler ses méthodes pour interagir avec l'utilisateur. Les interactions sont gérées de manière à fournir des retours clairs à l'utilisateur et à capturer sa réponse.

Il intègre également des fonctionnalités de journalisation des interactions via le module "Term::UI::History".

METHODS

new
Crée et retourne une nouvelle instance de Term::UI.
get_reply
Pose une question à l'utilisateur et retourne sa réponse. Les options incluent un message d'invite (prompt), une liste de choix (choices), une valeur par défaut (default), un indicateur pour autoriser plusieurs choix (multi), un message à afficher avant la question (print_me), et une condition de validation (allow).
ask_yn
Pose une question oui/non à l'utilisateur, avec une valeur par défaut. Retourne une valeur booléenne.
history_as_string
Retourne l'historique des interactions sous forme de chaîne de caractères. Ceci est un wrapper pratique autour de "Term::UI::History->history_as_string". Consultez la page de manuel de "Term::UI::History" pour plus de détails.

VARIABLES GLOBALES

Le comportement de Term::UI peut être modifié en changeant les variables globales suivantes :

$Term::UI::VERBOSE

Contrôle si Term::UI émet des avertissements et des explications sur les raisons pour lesquelles certaines choses ont pu échouer. Si vous la définissez à 0, Term::UI n'affichera aucun avertissement. La valeur par défaut est 1.

$Term::UI::AUTOREPLY

Permet de répondre automatiquement à chaque question avec la valeur par défaut, et avertit si aucune valeur par défaut n'a été fournie. C'est particulièrement utile si votre programme est exécuté en mode non interactif. La valeur par défaut est 0.

$Term::UI::INVALID

Contient la chaîne de caractères qui sera affichée lorsque l'utilisateur fait un choix invalide. Vous pouvez remplacer cette chaîne depuis votre programme si, par exemple, vous souhaitez effectuer une localisation. La valeur par défaut est "Sélection invalide, veuillez réessayer : ".

$Term::UI::History::HISTORY_FH

C'est le handle de fichier vers lequel toutes les instructions d'impression de ce module sont envoyées. Veuillez consulter la page de manuel "Term::UI::History" pour plus de détails.

La valeur par défaut est *STDOUT.

EXEMPLES

Exemple basique de get_reply

### demander à l'utilisateur (avec une question ouverte) sa couleur préférée
$reply = $term->get_reply( prompt => 'Votre couleur préférée? );

ce qui ressemblerait à :

Votre couleur préférée?

et $reply contiendrait le texte tapé par l'utilisateur.

get_reply avec des choix

### maintenant fournir une liste de choix, pour que l'utilisateur doive en choisir un
$reply = $term->get_reply(
            prompt  => 'Votre couleur préférée?',
            choices => [qw|rouge vert bleu|] );

ce qui ressemblerait à :

  1> rouge
  2> vert
  3> bleu
Votre couleur préférée?

$reply contiendra l'un des choix présentés. "Term::UI" reposera la question si l'utilisateur tente d'entrer une réponse qui ne figure pas dans la liste des choix. La chaîne présentée est contenue dans la variable $Term::UI::INVALID (voir la section "VARIABLES GLOBALES" pour plus de détails).

get_reply avec des choix et une valeur par défaut

### fournir une option par défaut sensée -- tout le monde aime le bleu !
$reply = $term->get_reply(
            prompt  => 'Votre couleur préférée?',
            choices => [qw|rouge vert bleu|],
            default => 'bleu' );

ce qui ressemblerait à :

  1> rouge
  2> vert
  3> bleu
Votre couleur préférée? [3]:

Notez la réponse par défaut après l'invite. Un utilisateur peut maintenant simplement appuyer sur "Entrée" (ou définir $Term::UI::AUTOREPLY -- voir la section "VARIABLES GLOBALES") et la réponse sensée 'bleu' sera retournée.

get_reply en utilisant print_me et multi

### permettre à l'utilisateur de choisir plus d'une couleur et d'ajouter
### un texte d'introduction
@reply = $term->get_reply(
            print_me    => 'Dites-nous quelles couleurs vous aimez',
            prompt      => 'Vos couleurs préférées?',
            choices     => [qw|rouge vert bleu|],
            multi       => 1 );

ce qui ressemblerait à :

Dites-nous quelles couleurs vous aimez
  1> rouge
  2> vert
  3> bleu
Vos couleurs préférées?

Une réponse de "3 2 1" remplirait @reply avec "bleu vert rouge"

get_reply et allow

### poser une question ouverte, mais effectuer une vérification personnalisée sur
### la réponse, qui ne sortira de la boucle de questions que si
### la réponse correspond au gestionnaire allow.
$reply = $term->get_reply(
            prompt  => "Quel est le nombre magique?",
            allow   => 42 );

À moins que l'utilisateur n'entre maintenant 42, la question sera reposée encore et encore. Vous pouvez utiliser des gestionnaires "allow" plus sophistiqués (même des sous-routines peuvent être utilisées). Le gestionnaire "allow" est implémenté en utilisant la fonction "allow" de "Params::Check". Consultez sa page de manuel pour plus de détails.

Un exemple élaboré de ask_yn

### demander à l'utilisateur s'il aime les cookies. Définir par défaut sur un 'oui' sensé
### et l'informer d'abord de ce que sont les cookies.
$bool = $term->ask_yn( prompt   => 'Aimez-vous les cookies?',
                       default  => 'o',
                       print_me => 'Les cookies sont ADORABLES!!!' );

afficherait :

Les cookies sont ADORABLES!!!
Aimez-vous les cookies? [O/n]:

Si un utilisateur frappe simplement "Entrée", acceptant la valeur par défaut, $bool serait défini à "vrai". (Appuyer simplement sur 'o' retournerait également "vrai". Appuyer sur 'n' retournerait "faux")

Nous pourrions plus tard récupérer cette interaction en affichant l'historique des Q&R comme suit :

print $term->history_as_string;

ce qui afficherait alors :

Les cookies sont ADORABLES!!!
Aimez-vous les cookies? [O/n]:  o

Il y a une chance que nous fassions cela de manière non interactive, parce qu'une console est manquante, l'utilisateur a indiqué qu'il voulait juste les valeurs par défaut, etc.

Dans ce cas, définir simplement $Term::UI::AUTOREPLY à vrai, retournera de chaque question avec la réponse par défaut définie pour la question. Notez que si "AUTOREPLY" est vrai, et qu'aucune valeur par défaut n'est définie, "Term::UI" avertira à ce sujet et retournera "undef".

Voir aussi

"Params::Check", "Term::ReadLine", "Term::UI::History"
