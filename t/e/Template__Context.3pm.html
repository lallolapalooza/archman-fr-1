Template::Context(3) Documentation soumise par les utilisateurs de Perl Template::Context(3)

NOM

Template::Context - Contexte en temps réel dans lequel les modèles sont traités

SYNOPIS

use Template::Context;
# constructeur
$context = Template::Context->new(\%config)
    || die $Template::Context::ERROR;
# récupérer (charger et compiler) un modèle
$template = $context->template($template_name);
# récupérer (charger et instancier) un objet plugin
$plugin = $context->plugin($name, \@args);
# récupérer (retourner ou créer) une sous-routine de filtre
$filter = $context->filter($name, \@args, $alias);
# traiter/inclure un modèle, les erreurs sont lancées via die()
$output = $context->process($template, \%vars);
$output = $context->include($template, \%vars);
# lancer une exception via die()
$context->throw($error_type, $error_message, \$output_buffer);
# attraper une exception, la nettoyer et corriger le tampon de sortie
$exception = $context->catch($exception, \$output_buffer);
# sauvegarder/restaurer le stash pour effectuer la localisation des variables
$new_stash = $context->localise(\%vars);
$old_stash = $context->delocalise();
# ajouter de nouvelles définitions BLOCK ou FILTER
$context->define_block($name, $block);
$context->define_filter($name, \&filtersub, $is_dynamic);
# réinitialiser le contexte, en effaçant toutes les définitions BLOCK importées
$context->reset();
# méthodes pour accéder aux éléments internes
$stash     = $context->stash();
$tflag     = $context->trim();
$epflag    = $context->eval_perl();
$providers = $context->templates();
$providers = $context->plugins();
$providers = $context->filters();
...

DESCRIPTION

Le module Template::Context définit une classe d'objets pour représenter un contexte en temps réel dans lequel les modèles sont traités. Il fournit une interface aux opérations fondamentales du moteur de traitement de modèles Template Toolkit, par laquelle les modèles compilés (c'est-à-dire le code Perl construit à partir du code source du modèle) peuvent être traités, les plugins et filtres chargés, les exceptions lancées, etc.

Un objet Template::Context par défaut est créé via le module Template. Toute option de Template::Context peut être transmise au constructeur new() du module Template et sera transmise à la classe du constructeur Template::Context.

use Template;
my $template = Template->new({
    TRIM      => 1,
    EVAL_PERL => 1,
    BLOCKS    => {
        header => 'Ceci est l\'en-tête',
        footer => 'Ceci est le pied de page',
    },
});

De même, le constructeur Template::Context transmettra tous les paramètres de configuration à d'autres objets par défaut (par exemple, Template::Provider, Template::Plugins, Template::Filters, etc.) qu'il peut instancier.

$context = Template::Context->new({
    INCLUDE_PATH => '/home/abw/templates', # option du fournisseur
    TAG_STYLE    => 'html',                # option de l'analyseur
});

Un objet Template::Context (ou son héritage) peut être instancié explicitement et transmis au constructeur new() du module Template comme paramètre CONTEXT.

use Template;
use Template::Context;
my $context  = Template::Context->new({ TRIM => 1 });
my $template = Template->new({ CONTEXT => $context });

Le module Template utilise la méthode usine context() du module Template::Config pour créer un objet contexte par défaut lorsqu'il en a besoin. Le paramètre de variable $Template::Config::CONTEXT peut être spécifié pour désigner un module de contexte alternatif. Ce module sera chargé automatiquement et le constructeur new() du module sera appelé pour context() lorsqu'un objet contexte par défaut est nécessaire.

use Template;
$Template::Config::CONTEXT = 'MyOrg::Template::Context';
my $template = Template->new({
    EVAL_PERL   => 1,
    EXTRA_MAGIC => 'red hot',  # vos éléments de configuration supplémentaires
    ...
});

MÉTHODES

new(\%params)

La méthode constructeur new() est appelée pour instancier un objet Template::Context. Les paramètres de configuration peuvent être spécifiés sous forme de référence HASH ou de liste de paires "nom => valeur".

my $context = Template::Context->new({
    INCLUDE_PATH => 'header',
    POST_PROCESS => 'footer',
});
my $context = Template::Context->new( EVAL_PERL => 1 );

La méthode new() retourne un objet Template::Context ou "undef" en cas d'erreur. Dans ce dernier cas, un message d'erreur pertinent peut être récupéré via la méthode error() du module ou directement à partir de la variable $Template::Context::ERROR.

my $context = Template::Context->new(\%config)
    || die Template::Context->error();
my $context = Template::Context->new(\%config)
    || die $Template::Context::ERROR;

Les paramètres de configuration suivants peuvent être spécifiés. Veuillez consulter Template::Manual::Config pour plus de détails.

VARIABLES

Le paramètre VARIABLES peut être utilisé pour spécifier un tableau de hachages de variables de modèle.

my $context = Template::Context->new({
    VARIABLES => {
        title   => 'Une page de démonstration',
        author  => 'Joe Bidon',
        version => 3.14,
    },
});

BLOCKS

Le paramètre BLOCKS peut être utilisé pour pré-définir un ensemble de blocs de modèles par défaut.

my $context = Template::Context->new({
    BLOCKS => {
        header  => 'L\'en-tête. [% title %]',
        footer  => sub { return $some_output_text },
        another => Template::Document->new({ ... }),
    },
});

VIEWS

Le paramètre VIEWS peut être utilisé pour pré-définir un ou plusieurs objets Template::View.

my $context = Template::Context->new({
    VIEWS => [
        bottom => { prefix => 'bottom/' },
        middle => { prefix => 'middle/', base => 'bottom' },
        top    => { prefix => 'top/',    base => 'middle' },
    ],
});

TRIM

Le paramètre TRIM peut être utilisé pour supprimer les espaces blancs de début et de fin de tous les résultats de fichiers modèles et de "BLOCK".

exemple:

[% BLOCK foo %]
Ligne 1 de foo
[% END %]
avant
[% INCLUDE foo %]
après

sortie:

avant
Ligne 1 de foo
après

EVAL_PERL

Le paramètre EVAL_PERL est utilisé pour indiquer si les blocs "PERL" et/ou "RAWPERL" doivent être évalués. Il est désactivé par défaut.

RECURSION

Le paramètre RECURSION peut être utilisé pour permettre aux modèles de se traiter récursivement, directement (par exemple, le modèle "foo" appelle "INCLUDE foo") ou indirectement (par exemple, le modèle "foo" appelle "INCLUDE bar" qui appelle "INCLUDE foo").

LOAD_TEMPLATES

Le paramètre LOAD_TEMPLATES peut être utilisé pour spécifier une référence à une liste d'objets Template::Provider ou de leurs sous-classes qui sont responsables du chargement et de la compilation des modèles.

my $context = Template::Context->new({
    LOAD_TEMPLATES => [
        MyOrg::Template::Provider->new({ ... }),
        Template::Provider->new({ ... }),
    ],
});

LOAD_PLUGINS

Le paramètre LOAD_PLUGINS peut être utilisé pour spécifier une liste d'objets fournisseurs responsables du chargement et de l'instanciation des objets plugins de modèle.

my $context = Template::Context->new({
    LOAD_PLUGINS => [
        MyOrg::Template::Plugins->new({ ... }),
        Template::Plugins->new({ ... }),
    ],
});

LOAD_FILTERS

Le paramètre LOAD_FILTERS peut être utilisé pour spécifier une liste d'objets fournisseurs responsables de retourner et/ou de créer des fonctions de filtre.

my $context = Template::Context->new({
    LOAD_FILTERS => [
        MyTemplate::Filters->new(),
        Template::Filters->new(),
    ],
});

STASH

Le paramètre STASH peut être utilisé pour spécifier un objet Template::Stash ou sa sous-classe qui est responsable de la gestion des variables de modèle.

my $stash = MyOrg::Template::Stash->new({ ... });
my $context = Template::Context->new({
    STASH => $stash,
});

DEBUG

Le paramètre DEBUG peut être utilisé pour activer diverses fonctionnalités de débogage du module Template::Context.

```
use Template::Constants qw( :debug ); my $template = Template->new({ DEBUG => DEBUG_CONTEXT | DEBUG_DIRS, });

template($name)

Retourne un modèle compilé en interrogeant chaque fournisseur de LOAD_TEMPLATES (instances de Template::Provider, ou sous-classe) à tour de rôle.

$template = $context->template('header');

En cas d'erreur, un objet Template::Exception de type '"file"' est levé via die(). Ceci peut être intercepté en entourant l'appel à template() dans un bloc "eval" et en examinant $@.

eval { $template = $context->template('header') };
if ($@) {
    print "échec de récupération du modèle : $@\n";
}

plugin($name, \@args)

Instancie un objet plugin en interrogeant chaque fournisseur de LOAD_PLUGINS. Le fournisseur par défaut pour LOAD_PLUGINS est un objet Template::Plugins qui tente de charger des modules plugins, conformément aux divers éléments de configuration tels que PLUGIN_BASE, LOAD_PERL, etc., puis instancie un objet via new(). Une référence à une liste d'arguments de constructeur peut être passée comme deuxième paramètre. Ceux-ci sont transmis au constructeur du plugin.

Retourne une référence vers un plugin (qui est généralement un objet, mais pas nécessairement). Les erreurs sont levées sous forme d'objets Template::Exception avec le type défini à '"plugin"'.

$plugin = $context->plugin('DBI', 'dbi:msql:mydbname');

filter($name, \@args, $alias)

Instancie une sous-routine de filtre en interrogeant les fournisseurs de LOAD_FILTERS. Le fournisseur par défaut pour LOAD_FILTERS est un objet Template::Filters.

Des arguments supplémentaires peuvent être passés par référence de liste ainsi qu'un alias optionnel sous lequel le filtre sera mis en cache pour une utilisation ultérieure. Le filtre est mis en cache sous son propre $name si $alias est indéfini. Les appels ultérieurs à filter($name) retourneront l'entrée mise en cache, si elle est définie. La spécification d'arguments contourne le mécanisme de mise en cache et crée toujours un nouveau filtre. Les erreurs sont levées sous forme d'objets Template::Exception avec le type défini à '"filter"'.

# filtre statique (aucun argument)
$filter = $context->filter('html');
# filtre dynamique (arguments) aliasé en 'padright'
$filter = $context->filter('format', '%60s', 'padright');
# récupère le filtre précédent via l'alias 'padright'
$filter = $context->filter('padright');

process($template, \%vars)

Traite un modèle nommé ou référencé par le premier paramètre et retourne la sortie générée. Une référence optionnelle à un tableau associatif peut être passée comme deuxième paramètre, contenant des définitions de variables qui seront définies avant le traitement du modèle. Le modèle est traité dans le contexte actuel, sans aucune localisation de variables effectuée. Les erreurs sont levées sous forme d'objets Template::Exception via die().

$output = $context->process('header', { title => 'Hello World' });

include($template, \%vars)

Similaire à process(), mais utilise des variables localisées. Les modifications apportées aux variables ne persisteront que jusqu'à ce que la méthode include() soit terminée.

$output = $context->include('header', { title => 'Hello World' });

insert($template)

Cette méthode retourne le contenu source d'un fichier modèle sans effectuer d'évaluation. Elle est utilisée pour implémenter la directive "INSERT".

throw($error_type, $error_message, \$output)

Lève une exception sous la forme d'un objet Template::Exception en appelant die(). Cette méthode peut recevoir une référence à un objet Template::Exception existant ; une seule valeur contenant un message d'erreur utilisée pour instancier un Template::Exception de type '"undef"' ; ou une paire de valeurs représentant le "type" et l'"info" de l'exception à partir desquels un objet Template::Exception est instancié. Par exemple :

$context->throw($exception);
$context->throw("Je suis désolé Dave, je ne peux pas faire ça");
$context->throw('denied', "Je suis désolé Dave, je ne peux pas faire ça");

Le troisième paramètre optionnel peut être une référence vers le tampon de sortie actuel. Celui-ci est ensuite stocké dans l'objet exception lors de sa création, permettant au capteur d'examiner et d'utiliser la sortie jusqu'au point où l'exception a été levée.

$output .= 'blah blah blah';
$output .= 'more rhubarb';
$context->throw('yack', 'Trop de bavardages', \$output);

catch($exception, \$output)

Intercepte une exception levée, soit comme une référence à un objet Template::Exception, soit comme une autre valeur. Dans ce dernier cas, la chaîne d'erreur est promue en objet Template::Exception de type '"undef"'. Cette méthode accepte également une référence vers le tampon de sortie actuel qui est passée au constructeur Template::Exception, ou est ajoutée au tampon de sortie stocké dans un objet Template::Exception existant, si unique (c'est-à-dire pas la même référence). Par ce processus, l'état correct du tampon de sortie peut être reconstruit pour des lancements simples ou imbriqués.

define_block($name, $block)

Ajoute une nouvelle définition de bloc au cache interne BLOCKS. Le premier argument doit contenir le nom du bloc et le second une référence à un objet Template::Document ou une sous-routine de modèle, ou du texte de modèle qui est automatiquement compilé en une sous-routine de modèle.

Retourne une valeur vraie (la sous-routine ou la référence Template::Document) en cas de succès ou undef en cas d'échec. Le message d'erreur pertinent peut être récupéré en appelant la méthode error().

define_filter($name, \&filter, $is_dynamic)

Ajoute une nouvelle définition de filtre en appelant la méthode store() sur chaque fournisseur LOAD_FILTERS jusqu'à acceptation (dans le cas habituel, elle est acceptée immédiatement par le seul fournisseur Template::Filters). Le premier argument doit contenir le nom du filtre et le second une référence à une sous-routine de filtre. Le troisième argument optionnel peut être défini à toute valeur vraie pour indiquer que la sous-routine est une fabrique de filtre dynamique.

Retourne une valeur vraie ou lève une exception '"filter"' en cas d'erreur.

define_vmethod($type, $name, $code)

Cette méthode est un wrapper autour de la méthode define_vmethod() de Template::Stash. Elle peut être utilisée pour définir de nouvelles méthodes virtuelles.

# définir une nouvelle méthode virtuelle scalaire (item)
$context->define_vmethod(
    item => ucfirst => sub {
        my $text = shift;
        return ucfirst $text;
    }
)

define_view($name, \%params)

Cette méthode vous permet de définir une vue nommée.

$context->define_view(
    my_view => {
        prefix => 'my_templates/'
    }
);

La vue est ensuite accessible en tant que variable de modèle.

[% my_view.print(some_data) %]

define_views($views)

Cette méthode vous permet de définir plusieurs vues nommées. Une référence à un tableau associatif ou une référence de liste doit être passée comme argument.

$context->define_view({     # référence de tableau associatif
    my_view_one => {
        prefix => 'my_templates_one/'
    },
    my_view_two => {
        prefix => 'my_templates_two/'
    }
});

Si vous définissez plusieurs vues dont une ou plusieurs sont basées sur d'autres vues de la même définition, vous devriez les passer comme une référence de liste. Cela garantit qu'elles seront créées dans le bon ordre (Perl ne préserve pas l'ordre des éléments définis dans une référence de tableau associatif, vous ne pouvez donc pas garantir que votre classe de base de vue sera définie avant votre classe dérivée de vue).

$context->define_view([     # référence de liste
    my_view_one => {
        prefix => 'my_templates_one/'
    },
    my_view_two => {
        prefix => 'my_templates_two/' ,
        base   => 'my_view_one',
    }
]);

Les vues sont ensuite accessibles en tant que variables de modèle.

[% my_view_one.print(some_data) %]
[% my_view_two.print(some_data) %]

Voir aussi l'option VIEWS.

stash()

Cette méthode retourne l'objet Template::Stash utilisé en interne pour gérer les variables de modèle.

localise(\%vars)

Clone le stash pour créer un contexte avec des variables localisées. Retourne une référence vers le nouvel objet stash cloné qui est également stocké en interne.

$stash = $context->localise();

delocalise()

Restaure le stash à son état antérieur à la localisation.

$stash = $context->delocalise();

visit(\%blocks)

Cette méthode est appelée par les objets Template::Document immédiatement avant qu'ils ne traitent leur contenu. Elle est appelée pour enregistrer toutes les définitions locales de "BLOCK" auprès de l'objet contexte afin qu'elles puissent être ultérieurement fournies sur demande.

leave()

Complément de la méthode visit(). Appelée par T

Template::Context(3pm)

NAME

Template::Context - Context object for Template Toolkit

SYNOPSIS

    use Template::Context;

    # Create a context object
    my $context = Template::Context->new(%config);

    # Access configuration items
    my $stash = $context->stash;
    my $provider = $context->provider;
    my $filters = $context->filters;

    # Process a template
    my $output = $template->process($filename, \%variables, $output_handle);

    # Get a view object
    my $view = $context->view();

DESCRIPTION

The Template::Context object holds the configuration and state information for the Template Toolkit processor. It is passed around to all other objects involved in the processing of a template, including the Template::Stash, Template::Provider, Template::Filters and Template::Plugins objects.

It is also responsible for managing the context-specific view, which is typically a Template::View object.

METHODS

new(%config)

Creates a new Template::Context object. The optional %config hash can contain any of the configuration items supported by the constituent objects:

stash
A Template::Stash object or configuration hash.
provider
A Template::Provider object or configuration hash.
filters
A Template::Filters object or configuration hash.
plugins
A Template::Plugins object or configuration hash.
error
A Template::Exception object to handle errors.
virtual
A flag to indicate if the context is virtual (i.e. not associated with a real service).
blocks
A hash reference defining default BLOCK directives to be compiled and stored internally.
encoding
The default output encoding.
debug
The debugging level (0-3).
compat
A hash reference of compatibility flags.
loops
A hash reference of loop variables.
stack
A stack object for managing template include/block calls.

stash()

Returns the Template::Stash object associated with this context.

provider()

Returns the Template::Provider object associated with this context.

filters()

Returns the Template::Filters object associated with this context.

plugins()

Returns the Template::Plugins object associated with this context.

error()

Returns the Template::Exception object associated with this context.

debug([$level])

Gets or sets the debugging level for the context. The level can be an integer from 0 (off) to 3 (verbose).

encoding([$encoding])

Gets or sets the default output encoding for the context.

compat( $flag, [@args] )

Accesses compatibility flags. The behavior depends on the $flag argument:

"get"
Returns the value of the specified compatibility flag.
"set"
Sets the value of the specified compatibility flag.
"hash"
Returns a reference to the hash containing all compatibility flags.

view()

This method creates a Template::View object bound to the context.

reset()

Clears the local BLOCKS cache of any "BLOCK" definitions. Any initial set of BLOCKS specified as a configuration item to the constructor will be reinstated.

debugging($flag, @args)

This method is used to control debugging output. It is used to implement the DEBUG directive.

The first argument can be "on" or "off" to enable or disable debugging respectively. The numerical values 0 and 1 can also be used if you prefer.

$context->debugging('on');

Alternately, the first argument can be "format" to define a new debug message format. The second argument should be the format string which can contain any of the $file, $line or $text symbols to indicate where the relevant values should be inserted.

# note single quotes to prevent interpolated of variables
$context->debugging( format => '## $file line $line: $text' );

The final use of this method is to generate debugging messages themselves. The first argument should be "msg", followed by a reference to a hash array of value to insert into the debugging format string.

$context->debugging(
    msg => {
        line => 20,
        file => 'example.tt',
        text => 'Trampoline! Trampoline!',
    }
);

AUTOLOAD

An "AUTOLOAD" method provides access to context configuration items.

$tflag     = $context->trim();
$epflag    = $context->eval_perl();
