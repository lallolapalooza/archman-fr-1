NOM

Text::CSV_PP - Module pure-Perl compatible avec Text::CSV_XS

SYNOPSIS

Cette section est tirée de Text::CSV_XS.

# Interface fonctionnelle
use Text::CSV_PP qw( csv );
# Lire tout le fichier en mémoire
my $aoa = csv (in => "data.csv");    # comme tableau de tableaux
my $aoh = csv (in => "data.csv",
               headers => "auto");   # comme tableau d'objets hash
# Écrire un tableau de tableaux en fichier csv
csv (in => $aoa, out => "file.csv", sep_char => ";");
# Afficher uniquement les lignes où "code" est impair
csv (in => "data.csv", filter => { code => sub { $_ % 2 }});
# Interface objet
use Text::CSV_PP;
my @rows;
# Lire/analyser le CSV
my $csv = Text::CSV_PP->new ({ binary => 1, auto_diag => 1 });
open my $fh, "<:encoding(utf8)", "test.csv" or die "test.csv: $!";
while (my $row = $csv->getline ($fh)) {
    $row->[2] =~ m/pattern/ or next; # 3ème champ doit correspondre
    push @rows, $row;
    }
close $fh;
# et écrire en CSV
open $fh, ">:encoding(utf8)", "new.csv" or die "new.csv: $!";
$csv->say ($fh, $_) for @rows;
close $fh or die "new.csv: $!";

DESCRIPTION

Text::CSV_PP est un module pure-perl qui fournit des facilités pour la composition et la décomposition de valeurs séparées par des virgules. Il est (presque) compatible avec le très plus rapide Text::CSV_XS, et est principalement utilisé comme module de repli lorsque vous utilisez le module Text::CSV sans avoir installé Text::CSV_XS. Si vous n'avez aucune raison d'utiliser ce module directement, utilisez Text::CSV pour un gain de vitesse et la portabilité (ou peut-être Text::CSV_XS lorsque vous écrivez un script ponctuel et que vous n'avez pas à vous soucier de la portabilité).

Les mises en garde suivantes sont tirées de la documentation de Text::CSV_XS.

Sauts de ligne intégrés

Note importante : Le comportement par défaut est d'accepter uniquement les caractères ASCII de la plage de 0x20 (espace) à 0x7E (tilde). Cela signifie que les champs ne peuvent pas contenir de sauts de ligne. Si vos données contiennent des sauts de ligne intégrés dans des champs, ou des caractères supérieurs à 0x7E (tilde), ou des données binaires, vous **devez** définir "binary => 1" dans l'appel à "new". Pour couvrir la plus large gamme d'options d'analyse, vous voudrez toujours définir `binary`.

Mais vous avez toujours le problème que vous devez passer une ligne correcte à la méthode "parse", ce qui est plus compliqué du point de vue habituel de l'utilisation :

my $csv = Text::CSV_PP->new ({ binary => 1, eol => $/ });
while (<>) {           #  FAUX !
    $csv->parse ($_);
    my @fields = $csv->fields ();
    }

cela échouera, car le "while" pourrait lire des lignes cassées : il ne se soucie pas de la mise entre guillemets. Si vous devez prendre en charge les sauts de ligne intégrés, la meilleure approche est de **ne pas** passer "eol" dans l'analyseur (il accepte "\n", "\r", **et** "\r\n" par défaut) et ensuite :

my $csv = Text::CSV_PP->new ({ binary => 1 });
open my $fh, "<", $file or die "$file: $!";
while (my $row = $csv->getline ($fh)) {
    my @fields = @$row;
    }

L'ancienne méthode d'utilisation des descripteurs de fichier globaux est toujours prise en charge

while (my $row = $csv->getline (*ARGV)) { ... }

Unicode

Unicode est uniquement testé pour fonctionner avec perl-5.8.2 et plus. Voir aussi "BOM".

La manière la plus simple de s'assurer que le bon encodage est utilisé pour l'entrée et la sortie est soit en définissant des couches sur les descripteurs de fichier, soit en définissant l'argument "encoding" pour "csv".

 open my $fh, "<:encoding(UTF-8)", "in.csv"  or die "in.csv: $!";
ou
 my $aoa = csv (in => "in.csv",     encoding => "UTF-8");
 open my $fh, ">:encoding(UTF-8)", "out.csv" or die "out.csv: $!";
ou
 csv (in => $aoa, out => "out.csv", encoding => "UTF-8");

Lors de l'analyse (pour "getline" et "parse"), si la source est marquée comme UTF8, alors tous les champs marqués comme binaires seront également marqués comme UTF8.

Lors de la combinaison ("print" et "combine") : si l'un des champs combinés était marqué UTF8, la chaîne résultante sera marquée comme UTF8. Notez cependant que tous les champs *avant* le premier champ marqué UTF8 et contenant des caractères 8 bits qui n'ont pas été mis à niveau vers UTF8, ceux-ci seront également des "octets" dans la chaîne résultante, provoquant potentiellement des erreurs inattendues. Si vous passez des données d'encodage différent, ou si vous ne savez pas s'il y a un encodage différent, forcez sa mise à niveau avant de les transmettre :

$csv->print ($fh, [ map { utf8::upgrade (my $x = $_); $x } @data ]);

Pour un contrôle complet de l'encodage, veuillez utiliser Text::CSV::Encoded :

use Text::CSV::Encoded;
my $csv = Text::CSV::Encoded->new ({
    encoding_in  => "iso-8859-1", # l'encodage entre dans Perl
    encoding_out => "cp1252",     # l'encodage sort de Perl
    });
$csv = Text::CSV::Encoded->new ({ encoding  => "utf8" });
# combine () et print () acceptent des données encodées *littéralement* en utf8
# parse () et getline () retournent des données encodées *littéralement* en utf8
$csv = Text::CSV::Encoded->new ({ encoding  => undef }); # par défaut
# combine () et print () acceptent des données marquées UTF8
# parse () et getline () retournent des données marquées UTF8

BOM

La gestion du BOM (ou Byte Order Mark) n'est disponible qu'à l'intérieur de la méthode "header". Cette méthode prend en charge les encodages suivants : "utf-8", "utf-1", "utf-32be", "utf-32le", "utf-16be", "utf-16le", "utf-ebcdic", "scsu", "bocu-1", et "gb-18030". Voir Wikipédia https://en.wikipedia.org/wiki/Byte_order_mark.

Si un fichier a un BOM, la manière la plus simple de le gérer est :

my $aoh = csv (in => $file, detect_bom => 1);

Tous les enregistrements seront encodés en fonction du BOM détecté.

Cela implique un appel à la méthode "header", qui, par défaut, définit également les "column_names". Ce n'est donc **pas** la même chose que

my $aoh = csv (in => $file, headers => "auto");

qui lit uniquement le premier enregistrement pour définir les "column_names" mais ignore toute signification d'un éventuel BOM présent.

version

(Méthode de classe) Retourne la version actuelle du module.

new

(Méthode de classe) Retourne une nouvelle instance de la classe Text::CSV_PP. Les attributs sont décrits par la référence de hachage (optionnelle) "\%attr".

my $csv = Text::CSV_PP->new ({ attributs ... });

Les attributs suivants sont disponibles :

eol

my $csv = Text::CSV_PP->new ({ eol => $/ });
          $csv->eol (undef);
my $eol = $csv->eol;

La chaîne de fin de ligne à ajouter aux lignes pour "print" ou le séparateur d'enregistrements pour "getline".

Lorsqu'elle n'est pas passée dans une instance de **parser**, le comportement par défaut est d'accepter "\n", "\r", et "\r\n", il est donc probablement plus sûr de ne pas spécifier "eol" du tout. Passer "undef" ou une chaîne vide se comportent de la même manière.

Lorsqu'elle n'est pas passée dans une instance de **génération**, les enregistrements ne sont pas terminés du tout, il est donc probablement sage de passer quelque chose que vous attendez. Un choix sûr pour "eol" en sortie est soit $/, soit "\r\n".

Les valeurs courantes pour "eol" sont " \n" (ou Saut de ligne), "\r\n" (ou Retour chariot, Saut de ligne), et "\r" (ou Retour chariot). L'attribut "eol" ne peut pas dépasser 7 caractères (ASCII). Si $/ et "eol" sont tous deux égaux à "\r", l'analyse des lignes se terminant uniquement par un retour chariot sans saut de ligne sera "analysée" correctement. eol_type ```perl my $eol = $csv->eol_type; ``` Cette méthode en lecture seule renvoie l'état interne de ce qui est considéré comme l'EOL valide pour l'analyse. sep_char ```perl my $csv = Text::CSV_PP->new ({ sep_char => ";" }); $csv->sep_char (";"); my $c = $csv->sep_char; ``` Le caractère utilisé pour séparer les champs, par défaut une virgule. (","). Limité à un caractère d'un seul octet, généralement dans la plage de 0x20 (espace) à 0x7E (tilde). Lorsque des séquences plus longues sont nécessaires, utilisez "sep". Le caractère de séparation ne peut pas être égal au caractère de citation ou au caractère d'échappement. sep ```perl my $csv = Text::CSV_PP->new ({ sep => "\N{FULLWIDTH COMMA}" }); $csv->sep (";"); my $sep = $csv->sep; ``` Les caractères utilisés pour séparer les champs, par défaut non définis. Limité à 8 octets. Lorsqu'il est défini, il remplace "sep_char". Si sa longueur est d'un octet, il agit comme un alias pour "sep_char". quote_char ```perl my $csv = Text::CSV_PP->new ({ quote_char => "'" }); $csv->quote_char (undef); my $c = $csv->quote_char; ``` Le caractère utilisé pour citer les champs contenant des espaces ou des données binaires, par défaut le guillemet double ("\""). Une valeur de undef supprime les caractères de citation (pour des cas simples uniquement). Limité à un caractère d'un seul octet, généralement dans la plage de 0x20 (espace) à 0x7E (tilde). Lorsque des séquences plus longues sont nécessaires, utilisez "quote". "quote_char" ne peut pas être égal à "sep_char". quote ```perl my $csv = Text::CSV_PP->new ({ quote => "\N{FULLWIDTH QUOTATION MARK}" }); $csv->quote ("'"); my $quote = $csv->quote; ``` Les caractères utilisés pour citer les champs, par défaut non définis. Limité à 8 octets. Lorsqu'il est défini, il remplace "quote_char". Si sa longueur est d'un octet, il agit comme un alias pour "quote_char". Cette méthode ne prend pas en charge "undef". Utilisez "quote_char" pour désactiver la citation. escape_char ```perl my $csv = Text::CSV_PP->new ({ escape_char => "\\" }); $csv->escape_char (":" ); my $c = $csv->escape_char; ``` Le caractère utilisé pour échapper certains caractères à l'intérieur des champs cités. Ceci est limité à un caractère d'un seul octet, généralement dans la plage de 0x20 (espace) à 0x7E (tilde). Le "escape_char" est par défaut le guillemet double ("\""). Autrement dit, le même que le "quote_char" par défaut. Cela signifie que doubler le guillemet dans un champ l'échappe : "foo","bar","Échapper le \"guillemet\" avec deux \"\"guillemets\"\"","baz" Si vous changez le "quote_char" sans changer le "escape_char", le "escape_char" sera toujours le guillemet double ("\""). Si, au contraire, vous souhaitez échapper le "quote_char" en le doublant, vous devrez également changer le "escape_char" pour qu'il soit identique à ce que vous avez changé pour le "quote_char". Définir "escape_char" sur "undef" ou "" désactivera complètement les échappements et est fortement déconseillé. Cela désactivera également "escape_null". Le caractère d'échappement ne peut pas être égal au caractère de séparation. binary ```perl my $csv = Text::CSV_PP->new ({ binary => 1 }); $csv->binary (0); my $f = $csv->binary; ``` Si cet attribut est 1, vous pouvez utiliser des caractères binaires dans les champs cités, y compris les sauts de ligne, les retours chariot et les octets NUL. (Ces derniers pourraient être échappés sous la forme de "\0".) Par défaut, cette fonctionnalité est désactivée. Si une chaîne est marquée UTF8, "binary" sera activé automatiquement lorsque des caractères binaires autres que "CR" et "NL" seront rencontrés. Notez qu'une simple chaîne comme "\x{00a0}" peut toujours être binaire, mais pas marquée UTF8, donc définir "{ binary => 1 }" reste une option judicieuse. strict ```perl my $csv = Text::CSV_PP->new ({ strict => 1 }); $csv->strict (0); my $f = $csv->strict; ``` Si cet attribut est défini à 1, toute ligne qui s'analyse avec un nombre de champs différent de la ligne précédente provoquera une erreur 2014 pour l'analyseur. Les lignes vides ou les lignes qui ne résultent en aucun champ (comme les lignes de commentaires) sont exemptées de ces vérifications. strict_eol ```perl my $csv = Text::CSV_PP->new ({ strict_eol => 1 }); $csv->strict_eol (0); my $f = $csv->strict_eol; ``` Si cet attribut est défini à 0, aucune vérification de cohérence EOL n'est effectuée. Si cet attribut est défini à 1, toute ligne analysée avec un EOL différent de celui de la première ligne provoquera un avertissement. L'erreur sera ignorée et l'analyse se poursuivra. Cet avertissement n'est émis qu'une seule fois. Notez que dans les données avec différentes terminaisons de ligne, "\r\r" provoquera toujours une erreur qui ne peut être ignorée. Si cet attribut est défini à 2 ou plus, toute ligne analysée avec un EOL différent de celui de la première ligne provoquera une erreur 2016. La ligne en cours d'analyse pour cette erreur peut ne pas être stockée dans le résultat. skip_empty_rows ```perl my $csv = Text::CSV_PP->new ({ skip_empty_rows => 1 }); $csv->skip_empty_rows ("eof"); my $f = $csv->skip_empty_rows; ``` Cet attribut définit le comportement pour les lignes vides : un "eol" immédiatement après le début de la ligne. Le comportement par défaut est de renvoyer un seul champ vide. Cet attribut n'est utilisé que lors de l'analyse. Cet attribut est inefficace lors de l'utilisation de "parse" et "fields". Les valeurs possibles pour cet attribut sont 0 | undef ```perl my $csv = Text::CSV_PP->new ({ skip_empty_rows => 0 }); $csv->skip_empty_rows (undef); ``` Aucune action spéciale n'est effectuée. Le résultat sera un seul champ vide. 1 | "skip" ```perl my $csv = Text::CSV_PP->new ({ skip_empty_rows => 1 }); $csv->skip_empty_rows ("skip"); ``` La ligne sera ignorée. 2 | "eof" | "stop" ```perl my $csv = Text::CSV_PP->new ({ skip_empty_rows => 2 }); $csv->skip_empty_rows ("eof"); ``` L'analyse s'arrêtera comme si un "eof" avait été détecté. 3 | "die" ```perl my $csv = Text::CSV_PP->new ({ skip_empty_rows => 3 }); $csv->skip_empty_rows ("die"); ``` L'analyse s'arrêtera. Le code d'erreur interne sera défini à 2015 et l'analyseur "mourra". 4 | "croak" ```perl my $csv = Text::CSV_PP->new ({ skip_empty_rows => 4 }); $csv->skip_empty_rows ("croak"); ``` L'analyse s'arrêtera. Le code d'erreur interne sera défini à 2015 et l'analyseur "croakera". 5 | "error" ```perl my $csv = Text::CSV_PP->new ({ skip_empty_rows => 5 }); $csv->skip_empty_rows ("error"); ``` L'analyse échouera. Le code d'erreur interne sera défini à 2015. callback ```perl my $csv = Text::CSV_PP->new ({ skip_empty_rows => sub { [] } }); $csv->skip_empty_rows (sub { [ 42, $., undef, "empty" ] }); ``` Le callback est appelé et son résultat est utilisé à la place. Si vous souhaitez que l'analyse s'arrête après le callback, assurez-vous de renvoyer une valeur fausse. La valeur renvoyée par le callback doit être un tableau-référence. Tout autre type entraînera l'arrêt de l'analyse, donc ces deux syntaxes sont équivalentes en comportement : csv (in => $fh, skip_empty_rows => "stop"); csv (in => $fh. skip_empty_rows => sub { 0; }); Sans arguments, la valeur actuelle est renvoyée : 0, 1, "eof", "die", "croak" ou le callback. formula_handling Alias pour "formula". formula ```perl my $csv = Text::CSV_PP->new ({ formula => "none" }); $csv->formula ("none"); my $f = $csv->formula; ``` Ceci définit le comportement des champs contenant des *formules*. Les formules étant considérées comme dangereuses dans les feuilles de calcul, cet attribut peut définir une action facultative à entreprendre si un champ commence par un signe égal ("="). Pour des raisons de lisibilité du code, cela peut également être écrit comme suit : ```perl my $csv = Text::CSV_PP->new ({ formula_handling => "none" }); $csv->formula_handling ("none"); my $f = $csv->formula_handling; ``` Les valeurs possibles pour cet attribut sont none Ne prend aucune action spécifique action. C'est la valeur par défaut. 

$csv->formula ("none");
mourir
Faire "mourir" le processus chaque fois qu'un "=" de début est rencontré. 
$csv->formula ("die");
croasser
Faire "croasser" le processus chaque fois qu'un "=" de début est rencontré. (Voir Carp) 
$csv->formula ("croak");
diag
Signaler la position et le contenu du champ chaque fois qu'un "=" de début est trouvé. La valeur du champ reste inchangée. 
$csv->formula ("diag");
vide
Remplacer le contenu des champs qui commencent par un "=" par une chaîne vide. 
$csv->formula ("empty");
$csv->formula ("");
undef
Remplacer le contenu des champs qui commencent par un "=" par "undef". 
$csv->formula ("undef");
$csv->formula (undef);
une fonction de rappel
Modifier le contenu des champs qui commencent par un "=" avec la valeur de retour de la fonction de rappel. Le contenu original du champ est disponible dans la fonction de rappel sous $_ ; 
# Remplacer toutes les formules par 42
$csv->formula (sub { 42; });
# équivalent à $csv->formula ("empty") mais plus lent
$csv->formula (sub { "" });
# Autoriser =4+12
$csv->formula (sub { s/^=(\d+\+\d+)$/$1/eer });
# Autoriser des calculs plus complexes
$csv->formula (sub { eval { s{^=([-+*/0-9()]+)$}{$1}ee }; $_ });

Toutes les autres valeurs généreront un avertissement puis se rabattront sur "diag".

decode_utf8

my $csv = Text::CSV_PP->new ({ decode_utf8 => 1 });
        $csv->decode_utf8 (0);
my $f = $csv->decode_utf8;

Cet attribut est défini sur TRUE par défaut.

Lors de l'analyse, les champs qui sont en UTF-8 valide sont automatiquement définis comme étant en UTF-8, de sorte que

$csv->parse ("\xC4\xA8\n");

résulte en

PV("\304\250"\0) [UTF8 "\x{128}"]

Parfois, cela peut ne pas être une action souhaitée. Pour empêcher ces mises à niveau, définissez cet attribut sur FALSE, et le résultat sera

PV("\304\250"\0)

auto_diag

my $csv = Text::CSV_PP->new ({ auto_diag => 1 });
        $csv->auto_diag (2);
my $l = $csv->auto_diag;

Définir cet attribut sur un nombre compris entre 1 et 9 provoque l'appel automatique de "error_diag" dans un contexte vide en cas d'erreurs.

En cas d'erreur "2012 - EOF", cet appel sera vide.

Si "auto_diag" est défini sur une valeur numérique supérieure à 2, il provoquera un "die" en cas d'erreurs au lieu d'un "warn". Si défini sur quelque chose d'inconnu, il sera ignoré silencieusement.

Les extensions futures de cette fonctionnalité incluront une détection automatique plus fiable de la présence de "autodie" dans la portée où l'erreur s'est produite, ce qui incrémentera la valeur de "auto_diag" de 1 au moment où l'erreur est détectée.

diag_verbose

my $csv = Text::CSV_PP->new ({ diag_verbose => 1 });
        $csv->diag_verbose (2);
my $l = $csv->diag_verbose;

Définit la verbosité de la sortie déclenchée par "auto_diag". Actuellement, elle ajoute uniquement le numéro d'enregistrement d'entrée actuel (si connu) à la sortie de diagnostic avec une indication de la position de l'erreur.

blank_is_undef

my $csv = Text::CSV_PP->new ({ blank_is_undef => 1 });
        $csv->blank_is_undef (0);
my $f = $csv->blank_is_undef;

Dans des circonstances normales, les données "CSV" ne font aucune distinction entre les champs vides cités et non cités. Ceux-ci se retrouvent dans un champ de chaîne vide une fois lus, donc

1,"",," ",2

est lu comme

("1", "", "", " ", "2")

Lors de l'écriture de fichiers "CSV" avec "always_quote" ou "quote_empty" définis, le champ vide non cité est le résultat d'une valeur indéfinie. Pour activer cette distinction lors de la lecture de données "CSV", l'attribut "blank_is_undef" fera que les champs vides non cités soient définis sur "undef", faisant que ce qui précède soit analysé comme

("1", "", undef, " ", "2")

Notez que cela est particulièrement important lors du chargement de champs "CSV" dans une base de données qui autorise les valeurs "NULL", car l'équivalent perl de "NULL" est "undef" dans le monde DBI.

empty_is_undef

my $csv = Text::CSV_PP->new ({ empty_is_undef => 1 });
        $csv->empty_is_undef (0);
my $f = $csv->empty_is_undef;

Allant un pas plus loin que "blank_is_undef", cet attribut convertit tous les champs vides en "undef", donc

1,"",," ",2

est lu comme

(1, undef, undef, " ", 2)

Notez que cela n'affecte que les champs qui sont initialement vides, pas les champs qui sont vides après suppression des espaces blancs autorisés. Vos résultats peuvent varier.

allow_whitespace

my $csv = Text::CSV_PP->new ({ allow_whitespace => 1 });
        $csv->allow_whitespace (0);
my $f = $csv->allow_whitespace;

Lorsque cette option est définie sur TRUE, les espaces blancs ("TAB" et "ESPACE") entourant le caractère de séparation sont supprimés lors de l'analyse. Si "TAB" ou "ESPACE" est l'un des trois caractères "sep_char", "quote_char", ou "escape_char", il ne sera pas considéré comme un espace blanc.

Maintenant, les lignes comme :

1 , "foo" , bar , 3 , zapp

sont analysées comme du "CSV" valide, même si cela viole les spécifications "CSV".

Notez que **tous** les espaces blancs sont supprimés du début et de la fin de chaque champ. Cela en ferait *plus* qu'une *fonctionnalité* pour autoriser l'analyse de mauvaises lignes "CSV", car

1,   2.0,  3,   ape  , monkey

sera maintenant analysé comme

("1", "2.0", "3", "ape", "monkey")

même si la ligne d'origine était un "CSV" parfaitement acceptable.

allow_loose_quotes

my $csv = Text::CSV_PP->new ({ allow_loose_quotes => 1 });
        $csv->allow_loose_quotes (0);
my $f = $csv->allow_loose_quotes;

Par défaut, l'analyse de champs non cités contenant des caractères "quote_char" comme

1,foo "bar" baz,42

entraînerait une erreur d'analyse 2034. Bien qu'il soit toujours déconseillé d'autoriser ce format, nous ne pouvons pas ignorer le fait que certains fournisseurs font produire par leurs applications des lignes de ce style.

S'il y a des données "CSV" **vraiment** mauvaises, comme

1,"foo "bar" baz",42

ou

1,""foo bar baz"",42

il existe un moyen de faire analyser ces lignes de données et de laisser les guillemets à l'intérieur du champ cité tels quels. Ceci peut être réalisé en définissant "allow_loose_quotes" **ET** en s'assurant que "escape_char" n'est **pas** égal à "quote_char".

allow_loose_escapes

my $csv = Text::CSV_PP->new ({ allow_loose_escapes => 1 });
        $csv->allow_loose_escapes (0);
my $f = $csv->allow_loose_escapes;

L'analyse de champs qui ont des caractères "escape_char" qui échappent à des caractères qui n'ont pas besoin d'être échappés, comme :

my $csv = Text::CSV_PP->new ({ escape_char => "\\" });
$csv->parse (qq{1,"my bar\'s",baz,42});

provoquerait une erreur d'analyse 2025. Bien qu'il soit déconseillé d'autoriser ce format, cet attribut vous permet de traiter toutes les séquences de caractères d'échappement de manière égale.

allow_unquoted_escape

my $csv = Text::CSV_PP->new ({ allow_unquoted_escape => 1 });
        $csv->allow_unquoted_escape (0);
my $f = $csv->allow_unquoted_escape;

Un problème de compatibilité ascendante où "escape_char" diffère de "quote_char" empêche "escape_char" d'être en première position d'un champ. Si "quote_char" est égal à """ par défaut et que "escape_char" est défini sur "\", cela serait illégal :

1,\0,2

Définir cet attribut sur 1 peut aider à surmonter les problèmes de compatibilité ascendante et autoriser ce style.

always_quote

my $csv = Text::CSV_PP->new ({ always_quote => 1 });
        $csv->always_quote (0);
my $f = $csv->always_quote;

Par défaut, les champs générés ne sont cités que s'ils en ont **besoin**. Par exemple, s'ils contiennent le caractère séparateur. Si vous définissez cet attribut sur 1, alors **tous** les champs définis seront cités. (Les champs "undef" ne sont pas cités, voir "blank_is_undef"). Cela rend souvent plus facile la gestion des données exportées dans des applications externes.

quote_space

my $csv = Text::CSV_PP->new ({ quote_space => 1 });
        $csv->quote_space (0);
my $f = $csv->quote_space;

Par défaut, un espace dans un champ déclencherait la citation. Comme il n'existe pas de règle imposant cela en "CSV", ni de

ny pour l'inverse, la valeur par défaut est vraie pour la sécurité. Vous pouvez exclure l'espace de ce déclencheur en définissant cet attribut sur 0.

quote_empty

my $csv = Text::CSV_PP->new ({ quote_empty => 1 });
        $csv->quote_empty (0);
my $f = $csv->quote_empty;

Par défaut, les champs générés sont mis entre guillemets uniquement s'ils le nécessitent. Un champ vide (défini) ne nécessite pas de guillemets. Si vous définissez cet attribut sur 1, alors les champs définis vides seront mis entre guillemets. ("undef" les champs ne sont pas mis entre guillemets, voir "blank_is_undef"). Voir aussi "always_quote".

quote_binary

my $csv = Text::CSV_PP->new ({ quote_binary => 1 });
        $csv->quote_binary (0);
my $f = $csv->quote_binary;

Par défaut, tous les octets « non sécurisés » à l'intérieur d'une chaîne entraînent la mise entre guillemets du champ combiné. En définissant cet attribut sur 0, vous pouvez désactiver ce déclencheur pour les octets ">= 0x7F".

escape_null

my $csv = Text::CSV_PP->new ({ escape_null => 1 });
        $csv->escape_null (0);
my $f = $csv->escape_null;

Par défaut, un octet "NULL" dans un champ serait échappé. Cette option vous permet de traiter l'octet "NULL" comme un simple caractère binaire en mode binaire (la valeur "{ binary => 1 }" est définie). La valeur par défaut est vraie. Vous pouvez empêcher les échappements de "NULL" en définissant cet attribut sur 0.

Lorsque l'attribut "escape_char" est défini sur indéfini, cet attribut sera défini sur faux.

La valeur par défaut lors de l'utilisation de la fonction "csv" est "faux".

Pour des raisons de compatibilité ascendante, l'ancien nom déprécié "quote_null" est toujours reconnu.

keep_meta_info

my $csv = Text::CSV_PP->new ({ keep_meta_info => 1 });
        $csv->keep_meta_info (0);
my $f = $csv->keep_meta_info;

Par défaut, l'analyse des enregistrements d'entrée est aussi simple et rapide que possible. Cependant, certaines informations d'analyse - comme la mise entre guillemets du champ d'origine - sont perdues dans ce processus. Définir ce drapeau sur vrai permet de récupérer ces informations après l'analyse avec les méthodes "meta_info", "is_quoted", et "is_binary" décrits ci-dessous. La valeur par défaut est fausse pour des raisons de performance.

Si vous définissez cet attribut sur une valeur supérieure à 9, vous pouvez contrôler le style de citation de sortie tel qu'il était utilisé dans l'entrée de l'enregistreur analysé le plus récemment (sauf si la citation a été ajoutée pour d'autres raisons).

my $csv = Text::CSV_PP->new ({
   binary         => 1,
   keep_meta_info => 1,
   quote_space    => 0,
   });
my $row = $csv->parse (q{1,,"", ," ",f,"g","h""h",help,"help"});
$csv->print (*STDOUT, \@row);
# 1,,, , ,f,g,"h""h",help,help
$csv->keep_meta_info (11);
$csv->print (*STDOUT, \@row);
# 1,,"", ," ",f,"g","h""h",help,"help"

undef_str

my $csv = Text::CSV_PP->new ({ undef_str => "\\N" });
        $csv->undef_str (undef);
my $s = $csv->undef_str;

Cet attribut définit éventuellement la sortie des champs indéfinis. La valeur passée n'est pas modifiée du tout, donc si elle nécessite des guillemets, les guillemets doivent être inclus dans la valeur de l'attribut. À utiliser avec précaution, car passer une valeur comme ",",,,,""" va à coup sûr désorganiser votre sortie. La valeur par défaut pour cet attribut est "undef", ce qui signifie aucun traitement spécial.

Cet attribut est utile lors de l'exportation de données CSV à importer dans des chargeurs personnalisés, comme pour MySQL, qui reconnaissent des séquences spéciales pour les données "NULL".

Cet attribut n'a aucune signification lors de l'analyse des données CSV.

comment_str

my $csv = Text::CSV_PP->new ({ comment_str => "#" });
        $csv->comment_str (undef);
my $s = $csv->comment_str;

Cet attribut définit éventuellement une chaîne à reconnaître comme un commentaire. Si cet attribut est défini, toutes les lignes commençant par cette séquence ne seront pas analysées comme CSV mais ignorées comme commentaires.

Cet attribut n'a aucune signification lors de la génération de CSV.

Les chaînes de commentaires qui commencent par l'un des caractères/séquences spéciaux ne sont pas prises en charge (elles ne peuvent donc pas commencer par l'un des "sep_char", "quote_char", "escape_char", "sep", "quote", ou "eol").

Par souci de commodité, "comment" est un alias pour "comment_str".

verbatim

my $csv = Text::CSV_PP->new ({ verbatim => 1 });
        $csv->verbatim (0);
my $f = $csv->verbatim;

C'est un attribut assez controversé à définir, mais qui rend certaines choses difficiles possibles.

La raison d'être de cet attribut est de dire à l'analyseur que les caractères normalement spéciaux, la nouvelle ligne ("NL") et le retour chariot ("CR") ne seront pas spéciaux lorsque ce drapeau est défini, et seront traités comme des caractères binaires ordinaires. Cela facilitera le travail avec des données contenant des nouvelles lignes incorporées.

Lorsque "verbatim" est utilisé avec "getline", "getline" "chomp" chaque ligne.

Imaginez un format de fichier comme

M^^Hans^Janssen^Klas 2\n2A^Ja^11-06-2007#\r\n

où la fin de ligne est un caractère très spécifique "#\r\n", et le caractère séparateur est un "^" (caret). Aucun des champs n'est mis entre guillemets, mais des données binaires incorporées sont susceptibles d'être présentes. Avec la fin de ligne spécifique, cela ne devrait pas être trop difficile à détecter.

Par défaut, la fonction d'analyse de Text::CSV_PP est instruite de ne connaître que "\n" et "\r" comme fins de ligne légales, et doit donc gérer la nouvelle ligne incorporée comme une vraie "fin de ligne", de sorte qu'elle puisse scanner la ligne suivante si binaire est vrai, et que la nouvelle ligne soit à l'intérieur d'un champ entre guillemets. Avec cette option, nous disons à "parse" d'analyser la ligne comme si "\n" n'est rien de plus qu'un caractère binaire.

Pour "parse", cela signifie que l'analyseur n'a plus connaissance de la fin de ligne et "getline" "chomp" les fins de ligne lors de la lecture.

print

Similaire à "combine" + "string" + "print", mais beaucoup plus efficace. Il attend une référence de tableau comme entrée (pas un tableau !) et la chaîne résultante n'est pas vraiment créée, mais écrite immédiatement dans l'objet $fh, typiquement un handle IO ou tout autre objet qui offre une méthode "print".

Si $colref est "undef" (explicitement, pas via un argument variable) et que "bind_columns" a été utilisé pour spécifier les champs à imprimer, il est possible d'améliorer les performances, car sinon les données devraient être copiées comme arguments à l'appel de la méthode :

$csv->bind_columns (\($foo, $bar));

combine

$status = $csv->combine (@fields);

Cette méthode construit un enregistrement "CSV" à partir de @fields, renvoyant succès ou échec. L'échec peut survenir en raison d'un manque d'arguments ou d'un argument contenant un caractère invalide. Une fois réussie, "string" peut être appelée pour récupérer le texte "CSV" résultant. En cas d'échec, la valeur renvoyée par "string" est indéfinie et "error_input" peut être appelée pour récupérer l'argument invalide.

string

$line = $csv->string ();

Cette méthode renvoie l'entrée de "parse" ou le texte "CSV" résultant de "combine", quelle que soit la dernière appelée.

getline

$colref = $csv->getline ($fh);

C'est l'équivalent de "print", tout comme "parse" est l'équivalent de "combine" : il analyse une ligne depuis le handle $fh en utilisant la méthode "getline" associée au handle $fh et analyse cette ligne dans une référence de tableau. Cette référence de tableau est renvoyée par la fonction ou comme "undef" en cas d'échec. Lorsque $fh ne prend pas en charge "getline", des erreurs sont probables.

Lorsque les colonnes sont liées avec "bind_columns", la valeur renvoyée est une référence à une liste vide.

Les méthodes "string", "fields" et "status" ne sont plus significatives.

getline_all

$arrayref = $csv->getline_all ($fh);
$arrayref = $csv->getline_all ($fh, $offset);
$arrayref = $csv->getline_all ($fh, $offset, $length);

Renvoie une référence à une liste de résultats de "getline ($fh)". Lors de cet appel, "keep_meta_info" est désactivé. Si $offset est négatif, comme dans le cas de "splice", seuls les abs ($offset) derniers enregistrements de $fh sont pris en compte. Les paramètres $offset et $length doivent être des entiers. Les valeurs non entières sont interprétées sans vérification comme des entiers.

Étant donné un fichier CSV avec 10 lignes :

lines call
----- ---------------------------------------------------------
0..9  $csv->getline_all ($fh)         # tous
0..9  $csv->getline_all ($fh,  0)     # tous
8..9  $csv->getline_all ($fh,  8)     # commencer à 8
-     $csv->getline_all ($fh,  0,  0) # commencer à 0, premier 0 enregistrements
0..4  $csv->getline_all ($fh,  0,  5) # commencer à 0, premier 5 enregistrements
4..5  $csv->getline_all ($fh,  4,  2) # commencer à 4, premier 2 enregistrements
8..9  $csv->getline_all ($fh, -2)     # derniers 2 enregistrements
6..7  $csv->getline_all ($fh, -4,  2) # premiers 2 des derniers 4 enregistrements

getline_hr

Les méthodes "getline_hr" et "column_names" travaillent ensemble pour permettre le retour des lignes sous forme de références de hachage. Vous devez d'abord appeler "column_names" pour déclarer vos colonnes.

$csv->column_names (qw( code name price description ));
$hr = $csv->getline_hr ($fh);
print "Price for $hr->{name} is $hr->{price} EUR\n";

"getline_hr" génère une erreur si elle est appelée avant "column_names".

Remarque : "getline_hr" crée un hashref pour chaque ligne et est beaucoup plus lent que l'utilisation combinée de "bind_columns" et "getline", mais offre la même facilité d'utilisation de hashref dans la boucle :

my @cols = @{$csv->getline ($fh)};
$csv->column_names (@cols);
while (my $row = $csv->getline_hr ($fh)) {
    print $row->{price};
    }

Cela peut être facilement réécrit comme suit :

my @cols = @{$csv->getline ($fh)};
my $row = {};
$csv->bind_columns (\@{$row}{@cols});
while ($csv->getline ($fh)) {
    print $row->{price};
    }

Votre kilométrage peut varier en fonction de la taille des données et du nombre de lignes. Avec perl-5.14.2, la comparaison pour un fichier de 100 000 lignes avec 14 colonnes est la suivante :

           Rate hashrefs getlines
hashrefs 1.00/s       --     -76%
getlines 4.15/s     313%       --

$arrayref = $csv->getline_hr_all ($fh, $offset);
$arrayref = $csv->getline_hr_all ($fh, $offset, $length);

Renvoie une référence à une liste de résultats de "getline_hr ($fh)". Lors de cet appel, "keep_meta_info" est désactivé.

parse

$status = $csv->parse ($line);

Cette méthode décompose un texte "CSV" en champs, renvoyant succès ou échec. L'échec peut survenir en raison d'un manque d'argument ou d'un texte "CSV" mal formaté. Une fois réussie, "fields" peut être appelée pour récupérer les champs décomposés. Lors de l'appel à "fields" en cas d'échec, des données indéfinies sont renvoyées et "error_input" peut être appelée pour récupérer l'argument invalide.

Vous pouvez utiliser la méthode "types" pour définir les types de colonnes. Voir la description de "types" ci-dessous.

L'argument $line est supposé être un scalaire simple. Tout le reste est supposé se comporter de manière incorrecte et définir l'erreur 1500.

fragment

Cette fonction tente d'implémenter RFC7111 (Identificateurs de fragments de texte pour le type media text/csv) - https://datatracker.ietf.org/doc/html/rfc7111

my $AoA = $csv->fragment ($fh, $spec);

Dans les spécifications, "*" est utilisé pour spécifier le *dernier* élément, un trait d'union ("-") pour indiquer une plage. Tous les index sont basés sur 1 : la première ligne ou colonne a l'index 1. Les sélections peuvent être combinées avec le point-virgule (";").

Lors de l'utilisation de cette méthode en combinaison avec "column_names", la référence renvoyée pointera vers une liste de hachages au lieu d'une liste de listes. Une sélection basée sur des cellules peut renvoyer des lignes avec un nombre différent de colonnes, ce qui rend l'utilisation de hachages imprévisible.

$csv->column_names ("Name", "Age");
my $AoH = $csv->fragment ($fh, "col=3;8");

Si le rappel "after_parse" est actif, chaque ligne analysée et ignorée avant le fragment est également appelée.

row
row=4
row=5-7
row=6-*
row=1-2;4;6-*
col
col=2
col=1-3
col=4-*
col=1-2;4;7-*
cell
Dans la sélection basée sur des cellules, la virgule (",") est utilisée pour les paires de lignes et de colonnes 
cell=4,1

L'opérateur de plage ("-") utilisant "cell" peut être utilisé pour définir l'emplacement des cellules en haut à gauche et en bas à droite 

cell=3,1-4,6

Le "*" n'est autorisé que dans la seconde partie d'une paire 

cell=3,2-*,2    # ligne 3 jusqu'à la fin, colonne 2 uniquement
cell=3,2-3,*    # colonne 2 jusqu'à la fin, ligne 3 uniquement
cell=3,2-*,*    # supprimer la ligne 1 et 2, et la colonne 1

Les cellules et les plages de cellules peuvent être combinées avec ";", résultant éventuellement en des lignes avec un nombre différent de colonnes 

cell=1,1-2,2;3,3-4,4;1,4;4,1

Les sélections disjointes ne renverront que les cellules sélectionnées. Les cellules non spécifiées ne seront pas incluses dans l'ensemble renvoyé, même comme "undef". Par exemple, étant donné un fichier CSV comme 

11,12,13,...19
21,22,...28,29
:            :
91,...97,98,99

avec "cell=1,1-2,2;3,3-4,4;1,4;4,1" renverra :

11,12,14
21,22
33,34
41,43,44

Les sélections avec des collisions ne renverront les cellules qu'une seule fois, donc "cell=1,1-3,3;2,2-4,4;2,3;4,2" renverra :

11,12,13
21,22,23,24
31,32,33,34
42,43,44

RFC7111 https://datatracker.ietf.org/doc/html/rfc7111 ne permet pas de combiner différents types de spécifications (soit "row" ou "col" ou "cell"). Passer une spécification de fragment invalide provoquera une erreur et définira l'erreur 2013.

column_names

"column_names" ne fait aucune vérification des doublons, ce qui peut entraîner des résultats inattendus. Les entrées indéfinies seront remplacées par la chaîne "\cAUNDEF\cA", donc

header

Cette méthode ne fonctionne PAS sous perl-5.6.x

Analyse l'en-tête CSV et définit "sep", les noms de colonnes et l'encodage.

my @hdr = $csv->header ($fh);
$csv->header ($fh, { sep_set => [ ";", ",", "|", "\t" ] });
$csv->header ($fh, { detect_bom => 1, munge_column_names => "lc" });

Le premier argument doit être un descripteur de fichier.

Cette méthode réinitialise certaines propriétés de l'objet, car elle est censée être invoquée une seule fois par fichier ou flux. Elle laissera les attributs "column_names" et "bound_columns" inchangés si la définition des noms de colonnes est désactivée. La lecture des en-têtes sur des objets précédemment traités peut échouer sous perl-5.8.0 et versions antérieures.

En supposant que le fichier ouvert pour l'analyse a un en-tête, et que cet en-tête ne contient pas de caractères problématiques tels que des sauts de ligne intégrés, lit la première ligne du descripteur de fichier ouvert, puis détecte automatiquement si l'en-tête sépare les noms de colonnes par un caractère de la liste des séparateurs autorisés.

Si l'un des séparateurs autorisés correspond, et qu'aucun des autres séparateurs autorisés ne correspond, définit "sep" sur ce séparateur pour l'instance CSV_PP actuelle et l'utilise pour analyser la première ligne, la mappe en minuscules et l'utilise pour définir les "column_names" de l'instance :

my $csv = Text::CSV_PP->new ({ binary => 1, auto_diag => 1 });
open my $fh, "<", "file.csv";
binmode $fh; # pour Windows
$csv->header ($fh);
while (my $row = $csv->getline_hr ($fh)) {
    ...
    }

Si l'en-tête est vide, contient plus d'un séparateur unique parmi l'ensemble autorisé, contient des champs vides, ou contient des champs identiques (après regroupement), il plantra avec les erreurs 1010, 1011, 1012 ou 1013 respectivement.

Si l'en-tête contient des sauts de ligne intégrés ou n'est pas un CSV valide d'une autre manière, cette méthode plantera et laissera l'erreur d'analyse

Un appel réussi à "header" définira toujours le "sep" de l'objet $csv. Ce comportement ne peut pas être désactivé.

valeur de retour

En cas d'erreur, cette méthode plantera.

En contexte de liste, les en-têtes seront retournés, qu'ils soient utilisés pour définir "column_names" ou non.

En contexte scalaire, l'instance elle-même est retournée. Note : les valeurs telles qu'elles se trouvent dans l'en-tête seront effectivement perdues si "set_column_names" est faux.

Options

sep_set
$csv->header ($fh, { sep_set => [ ";", ",", "|", "\t" ] });

La liste des séparateurs légaux est par défaut "[ ";", "," ]" et peut être modifiée par cette option. Comme c'est probablement l'option la plus utilisée, elle peut être passée seule comme argument sans nom :

$csv->header ($fh, [ ";", ",", "|", "\t", "::", "\x{2063}" ]);

Les séquences multi-octets sont autorisées, à la fois multi-caractères et Unicode. Voir "sep".

detect_bom
$csv->header ($fh, { detect_bom => 1 });

Le comportement par défaut est de détecter si la ligne d'en-tête commence par un BOM. Si l'en-tête a un BOM, utilisez-le pour définir l'encodage de $fh. Ce comportement par défaut peut être désactivé en passant une valeur fausse à "detect_bom".

Les encodages pris en charge par le BOM sont : UTF-8, UTF-16BE, UTF-16LE, UTF-32BE et UTF-32LE. Le BOM prend également en charge UTF-1, UTF-EBCDIC, SCSU, BOCU-1 et GB-18030, mais Encode ne les prend pas en charge (encore). UTF-7 n'est pas pris en charge.

Si un BOM pris en charge a été détecté au début du flux, il est stocké dans l'attribut de l'objet "ENCODING".

my $enc = $csv->{ENCODING};

L'encodage est utilisé avec "binmode" sur $fh.

Si le descripteur a été ouvert dans un encodage (correct), cette méthode ne modifiera **pas** l'encodage, car elle vérifie les octets en tête de la première ligne. Si le flux commence par un BOM décodé ("U+FEFF"), "{ENCODING}" sera "" (vide) au lieu de "undef" par défaut.

munge_column_names
Cette option offre les moyens de modifier les noms de colonnes en quelque chose d'utile pour l'application. Par défaut, tous les noms de colonnes sont mis en minuscules. 
$csv->header ($fh, { munge_column_names => "lc" });

Les valeurs suivantes sont disponibles :

lc     - minuscules
uc     - majuscules
db     - noms de champs valides pour une base de données

Validation

Lors de la réception de fichiers CSV provenant de sources externes, cette méthode peut être utilisée pour se protéger contre les changements de disposition en se limitant aux en-têtes connus (et aux fautes de frappe dans les champs d'en-tête).

my %known = (
    "record key" => "c_rec",
    "rec id"     => "c_rec",
    "id_rec"     => "c_rec",
    "kode"       => "code",
    "code"       => "code",
    "vaule"      => "value",
    "value"      => "value",
    );
my $csv = Text::CSV_PP->new ({ binary => 1, auto_diag => 1 });
open my $fh, "<", "$source" or die "$source: $!";
$csv->header ($fh, { munge_column_names => sub {
    s/\s+$//;
    s/^\s+//;
    $known{lc $_} or die "Unknown column '$_' in $source";
    }});
while (my $row = $csv->getline_hr ($fh)) {
    say join "\t", $row->{c_rec}, $row->{code}, $row->{value};
    }

bind_columns

Prend une liste de références scalaires à utiliser pour la sortie avec "print" ou pour stocker dans les champs récupérés par "getline". Lorsque vous ne passez pas suffisamment de références pour stocker les champs récupérés, "getline" échouera avec l'erreur 3006. Si vous passez plus de références qu'il n'y a de champs à retourner, le contenu des références restantes est laissé inchangé. Sous "strict", les deux doivent correspondre, sinon "getline" échouera avec l'erreur 2014.

$csv->bind_columns (\$code, \$name, \$price, \$description);
while ($csv->getline ($fh)) {
    print "The price of a $name is \x{20ac} $price\n";
    }

Pour réinitialiser ou effacer toutes les liaisons de colonnes, appelez "bind_columns" avec l'argument unique "undef". Cela effacera également les noms de colonnes.

$csv->bind_columns (undef);

Si aucun argument n'est passé du tout, "bind_columns" retournera la liste des liaisons actuelles ou "undef" s'il n'y a pas de liaisons actives.

FONCTIONS

Cette section est également tirée de Text::CSV_XS.

csv

Cette fonction n'est pas exportée par défaut et doit être explicitement demandée :

use Text::CSV_PP qw( csv );

Il s'agit d'une fonction de haut niveau qui vise des interfaces (utilisateurs) simples. Elle peut être utilisée pour lire/analyser un fichier ou un flux "CSV" (comportement par défaut) ou pour produire un fichier ou écrire dans un flux (définir l'attribut "out"). Elle retourne une référence tableau ou hachage lors de l'analyse (ou "undef" en cas d'échec) ou la valeur numérique de "error_diag" lors de l'écriture. Lorsque cette fonction échoue, vous pouvez obtenir l'erreur en appelant la classe à "error_diag"

my $aoa = csv (in => "test.csv") or
    die Text::CSV_PP->error_diag;

Notez que l'échec ici est l'incapacité de démarrer l'analyseur, par exemple lorsque l'entrée n'existe pas ou que les arguments sont inconnus ou contradictoires. Les erreurs d'analyse à l'exécution renverront une référence valide, qui peut être vide, mais contiendra toujours tous les résultats jusqu'à l'erreur. Voir "on_error".

Cette fonction prend les arguments sous forme de paires clé-valeur. Cela peut être passé sous forme de liste ou sous forme de hachage anonyme :

my $aoa = csv (  in => "test.csv", sep_char => ";");
my $aoh = csv ({ in => $fh, headers => "auto" });

Les arguments passés se composent de deux parties : les arguments de "csv" lui-même et les attributs optionnels de l'objet "CSV" utilisé à l'intérieur de la fonction, tels qu'énumérés et expliqués dans "new".

Si elles ne sont pas remplacées, les options par défaut utilisées pour CSV sont

auto_diag   => 1
escape_null => 0
strict_eol  => 1

L'option qui est toujours définie et ne peut pas être modifiée est

binary      => 1

Comme cette fonction sera probablement utilisée dans des one-liners, elle permet d'abréger "quote" en "quo", et "escape_char" en "esc" ou "escape".

Appels alternatifs :

my $aoa = Text::CSV_PP::csv (in => "file.csv");
my $csv = Text::CSV_PP->new ();
my $aoa = $csv->csv (in => "file.csv");

Dans ce dernier cas, les attributs de l'objet sont utilisés à partir de l'objet existant et les arguments d'attribut dans l'appel de fonction sont ignorés :

my $csv = Text::CSV_PP->new ({ sep_char => ";" });
my $aoh = $csv->csv (in => "file.csv", bom => 1);

analysera en utilisant ";" comme "sep_char", et non ",".

in

Utilisé pour spécifier la source. "in" peut être un nom de fichier (par ex. "file.csv"), qui sera ouvert en lecture et fermé une fois terminé, un descripteur de fichier (par ex. $fh ou "FH"), une référence à un glob (par ex. "\*ARGV"), le glob lui-même (par ex. *STDIN), ou une référence à un scalaire (par ex. "\q{1,2,"csv"}").

Lorsqu'il est utilisé avec "out", "in" doit être une référence à une structure CSV (AoA ou AoH) ou une référence CODE qui renvoie une référence tableau ou une référence hachage. La référence CODE sera invoquée sans arguments.

my $aoa = csv (in => "file.csv");
open my $fh, "<", "file.csv";
my $aoa = csv (in => $fh);
my $csv = [ [qw( Foo Bar )], [ 1, 2 ], [ 2, 3 ]];
my $err = csv (in => $csv, out => "file.csv");

S'il est appelé dans un contexte vide sans l'attribut "out", la référence résultante sera utilisée comme entrée pour un appel ultérieur à csv :

csv (in => "file.csv", filter => { 2 => sub { length > 2 }})

sera un raccourci vers

csv (in => csv (in => "file.csv", filter => { 2 => sub { length > 2 }}))

où, en l'absence de l'attribut "out", il s'agit d'un raccourci vers

csv (in  => csv (in => "file.csv", filter => { 2 => sub { length > 2 }}),
     out => *STDOUT)

out

csv (in => $aoa,  out => "file.csv");
csv (in => $aoa,  out => $fh);
csv (in => $aoa,  out =>   STDOUT);
csv (in => $aoa,  out =>  *STDOUT);
csv (in => $aoa,  out => \*STDOUT);
csv (in => $aoa,  out => \my $data);
csv (in => $aoa,  out =>  undef);
csv (in => $aoa,  out => \"skip");
csv (in => $fh,   out => \@aoa);
csv (in => $fh,   out => \@aoh, bom => 1);
csv (in => $fh,   out => \%hsh, key => "key");
csv (in => $file, out => $file);
csv (in => $file, out => $fh);
csv (in => $fh,   out => $file);
csv (in => $fh,   out => $fh);

En mode sortie, les options CSV par défaut lors de la production de CSV sont

eol       => "\r\n"

L'attribut "fragment" est ignoré en mode sortie.

"out" peut être un nom de fichier (par ex. "file.csv"), qui sera ouvert en écriture et fermé une fois terminé, un descripteur de fichier (par ex. $fh ou "FH"), une référence à un glob (par ex. "\*STDOUT"), le glob lui-même (par ex. *STDOUT), ou une référence à un scalaire (par ex. "\my $data").

csv (in => sub { $sth->fetch },            out => "dump.csv");
csv (in => sub { $sth->fetchrow_hashref }, out => "dump.csv",
     headers => $sth->{NAME_lc});

Lorsqu'une référence CODE est utilisée pour "in", la sortie est générée par invocation, il n'y a donc pas de mise en mémoire tampon. Cela implique qu'il n'y a pas de restriction de taille sur le nombre d'enregistrements. La fonction "csv" se termine lorsque la référence CODE renvoie une valeur fausse.

Si "out" est défini sur une référence à la chaîne littérale "skip", la sortie sera complètement supprimée, ce qui pourrait être utile en combinaison avec un filtre pour des effets de bord uniquement.

my %cache;
csv (in    => "dump.csv",
     out   => \"skip",
     on_in => sub { $cache{$_[1][1]}++ });

Actuellement, définir "out" sur n'importe quelle valeur fausse ("undef", "", 0) sera équivalent à "\"skip"".

Si l'argument "in" pointe vers quelque chose à analyser, et que "out" est défini sur une référence à un "ARRAY" ou un "HASH", la sortie est ajoutée aux données dans la référence existante. Le résultat de l'analyse doit correspondre à ce qui existe dans la référence passée. Cela peut être utile lorsque vous devez analyser un ensemble de fichiers avec un contenu similaire (comme des données stockées par période) et que vous souhaitez les collecter dans une seule structure de données :

my %hash;
csv (in => $_, out => \%hash, key => "id") for sort glob "foo-[0-9]*.csv";
my @list; # Liste de tableaux
csv (in => $_, out => \@list)              for sort glob "foo-[0-9]*.csv";
my @list; # Liste de hachages
csv (in => $_, out => \@list, bom => 1)    for sort glob "foo-[0-9]*.csv";

Streaming

Si **à la fois** "in" et "out" sont des fichiers, des descripteurs de fichiers ou des globs, le streaming est imposé en injectant une fonction de rappel "after_parse" qui utilise immédiatement la méthode "say ()" de la même instance pour afficher le résultat et rejette ensuite l'enregistrement.

Si un "after_parse" a déjà été passé en tant qu'attribut, il sera inclus dans l'appel injecté. Si "on_in" a été passé et "after_parse" n'a pas été passé, il sera utilisé à la place. Si les deux ont été passés, "on_in" est ignoré.

L'EOL du premier enregistrement de la source "in" est utilisé de manière cohérente comme EOL pour tous les enregistrements de la destination "out".

L'attribut "filter" n'est pas disponible.

Tous les autres attributs sont partagés pour "in" et "out", vous ne pouvez donc pas définir différents encodages pour "in" et "out". Vous devez passer un $fh, sur lequel "binmode" a été utilisé pour appliquer les couches d'encodage.

Notez qu'il s'agit d'un travail en cours et que les choses pourraient changer.

encoding

S'il est passé, il doit s'agir d'un encodage accepté par l'option :encoding() de "open". Il n'y a pas de valeur par défaut. Cet attribut ne fonctionne pas dans perl 5.6.x. "encoding" peut être abrégé en "enc" pour une utilisation facile dans les appels en ligne de commande.

Si "encoding" est défini sur la valeur littérale "auto", la méthode "header" sera invoquée sur le flux ouvert pour vérifier s'il y a un BOM et définir l'encodage en conséquence. Ceci est équivalent à passer une valeur vraie dans l'option "detect_bom".

Les encodages peuvent être empilés, tels que pris en charge par "binmode" :

# Utilisation de PerlIO::via::gzip
csv (in       => \@csv,
     out      => "test.csv:via.gz",
     encoding => ":via(gzip):encoding(utf-8)",
     );
$aoa = csv (in => "test.csv:via.gz",  encoding => ":via(gzip)");
# Utilisation de PerlIO::gzip
csv (in       => \@csv,
     out      => "test.csv:via.gz",
     encoding => ":gzip:encoding(utf-8)",
     );
$aoa = csv (in => "test.csv:gzip.gz", encoding => ":gzip");

detect_bom

Si "detect_bom" est donné, la méthode "header" sera invoquée sur le flux ouvert pour vérifier si t

voici une nomenclature et définit l'encodage en conséquence.

"detect_bom" peut être abrégé en "bom".

Ceci est équivalent à définir "encoding" sur "auto".

Notez que comme la méthode "header" est appelée, son comportement par défaut est également de définir les en-têtes.

headers

Si cet attribut n'est pas fourni, le comportement par défaut est de produire un tableau de tableaux.

Si "headers" est fourni, il doit s'agir d'une liste anonyme de noms de colonnes, d'un hashref anonyme, d'un coderef ou d'un indicateur littéral : "auto", "lc", "uc", ou "skip".

skip
Lorsque "skip" est utilisé, l'en-tête ne sera pas inclus dans la sortie. 
my $aoa = csv (in => $fh, headers => "skip");

"skip" est invalide/ignoré en combinaison avec "detect_bom".

auto
Si "auto" est utilisé, la première ligne de la source "CSV" sera lue comme la liste des en-têtes de champ et utilisée pour produire un tableau de hachages. 
my $aoh = csv (in => $fh, headers => "auto");
lc
Si "lc" est utilisé, la première ligne de la source "CSV" sera lue comme la liste des en-têtes de champ mappés en minuscules et utilisée pour produire un tableau de hachages. Ceci est une variation de "auto". 
my $aoh = csv (in => $fh, headers => "lc");
uc
Si "uc" est utilisé, la première ligne de la source "CSV" sera lue comme la liste des en-têtes de champ mappés en majuscules et utilisée pour produire un tableau de hachages. Ceci est une variation de "auto". 
my $aoh = csv (in => $fh, headers => "uc");
CODE
Si un coderef est utilisé, la première ligne de la source "CSV" sera lue comme la liste des en-têtes de champ modifiés dans laquelle chaque champ est passé comme seul argument au coderef. Cette liste est utilisée pour produire un tableau de hachages. 
my $aoh = csv (in      => $fh,
               headers => sub { lc ($_[0]) =~ s/kode/code/gr });

cet exemple est une variation de l'utilisation de "lc" où toutes les occurrences de "kode" sont remplacées par "code".

ARRAY
Si "headers" est une liste anonyme, les entrées de la liste seront utilisées comme noms de champ. La première ligne est considérée comme des données et non comme des en-têtes. 
my $aoh = csv (in => $fh, headers => [ qw( Foo Bar )]);
csv (in => $aoa, out => $fh, headers => [ qw( code description price )]);
HASH
Si "headers" est une référence de hachage, cela implique "auto", mais les champs d'en-tête qui existent comme clé dans le hashref seront remplacés par la valeur correspondante. Étant donné un fichier CSV comme 
post-kode,ville,nom,numéro d'id,fubble
1234AA,Duckstad,Donald,13,"X313DF"

en utilisant

csv (headers => { "post-kode" => "pc", "numéro d'id" => "ID" }, ...

retournera une entrée comme

{ pc     => "1234AA",
  ville   => "Duckstad",
  nom   => "Donald",
  ID     => "13",
  fubble => "X313DF",
  }

Voir aussi "munge_column_names" et "set_column_names".

keep_headers

Lors de l'utilisation de hachages, conservez les noms de colonnes dans le tableau passé, de sorte que tous les en-têtes soient disponibles après l'appel dans l'ordre d'origine.

my $aoh = csv (in => "file.csv", keep_headers => \my @hdr);

Cet attribut peut être abrégé en "kh" ou passé comme "keep_column_names".

Cet attribut implique une valeur par défaut de "auto" pour l'attribut "headers".

Les en-têtes peuvent également être conservés en interne pour maintenir un ordre d'en-tête stable :

csv (in      => csv (in => "file.csv", kh => "internal"),
     out     => "new.csv",
     kh      => "internal");

où "internal" peut aussi être 1, "yes", ou "true". Ceci est similaire à

my @h;
csv (in      => csv (in => "file.csv", kh => \@h),
     out     => "new.csv",
     headers => \@h);

fragment

N'afficher que le fragment tel que défini dans la méthode "fragment". Cette option est ignorée lors de la *génération* de "CSV". Voir "out".

use Text::CSV_PP qw( csv );
my $aoh = csv (

sep_set

Si "sep_set" est défini, la méthode "header" est appelée sur le flux ouvert pour détecter et définir "sep_char" avec l'ensemble donné.

"sep_set" peut être abrégé en "seps". Si ni "sep_set" ni "seps" n'est donné, mais que "sep" est défini, "sep_set" prend par défaut "[ sep ]". Ceci n'est pris en charge que pour la version perl 5.10 et supérieure.

Header and column names

Note that as the "header" method is invoked, its default is to also set the headers.

set_column_names

If "set_column_names" is passed, the method "header" is invoked on the opened stream with all arguments meant for "header".

If "set_column_names" is passed as a false value, the content of the first row is only preserved if the output is AoA:

With an input-file like

bAr,foo
1,2
3,4,5

This call

my $aoa = csv (in => $file, set_column_names => 0);

will result in

[[ "bar", "foo"     ],
 [ "1",   "2"       ],
 [ "3",   "4",  "5" ]]

and

my $aoa = csv (in => $file, set_column_names => 0, munge => "none");

will result in

[[ "bAr", "foo"     ],
 [ "1",   "2"       ],
 [ "3",   "4",  "5" ]]

csv

The function "csv" can also be called as a method or with an existing Text::CSV_PP object. This could help if the function is to be invoked a lot of times and the overhead of creating the object internally over and over again would be prevented by passing an existing instance.

my $csv = Text::CSV_PP->new ({ binary => 1, auto_diag => 1 });
my $aoa = $csv->csv (in => $fh);
my $aoa = csv (in => $fh, csv => $csv);

both act the same. Running this 20000 times on a 20 lines CSV file, showed a 53% speedup.

Callbacks

Callbacks enable actions triggered from the inside of Text::CSV_PP.

While most of what this enables can easily be done in an unrolled loop as described in the "SYNOPSIS" callbacks can be used to meet special demands or enhance the "csv" function.

error
$csv->callbacks (error => sub { $csv->SetDiag (0) });

the "error" callback is invoked when an error occurs, but only when "auto_diag" is set to a true value. A callback is invoked with the values returned by "error_diag":

my ($c, $s);
sub ignore3006 {
    my ($err, $msg, $pos, $recno, $fldno) = @_;
    if ($err == 3006) {
        # ignore this error
        ($c, $s) = (undef, undef);
        Text::CSV_PP->SetDiag (0);
        }
    # Any other error
    return;
    } # ignore3006
$csv->callbacks (error => \&ignore3006);
$csv->bind_columns (\$c, \$s);
while ($csv->getline ($fh)) {

$csv->callbacks (after_parse => sub { push @{$_[1]}, "NEW" });

    $row->[-1] eq "NEW";
    }

This callback is invoked after parsing with "getline" only if no error occurred. The callback is invoked with two arguments: the current "CSV" parser object and an array reference to the fields parsed.

The return code of the callback is ignored unless it is a reference to the string "skip", in which case the record will be skipped in "getline_all".

sub add_from_db {
    my ($csv, $row) = @_;
    $sth->execute ($row->[4]);
    push @$row, $sth->fetchrow_array;
    } # add_from_db
my $aoa = csv (in => "file.csv", callbacks => {
    after_parse => \&add_from_db });

This callback is invoked before printing with "print" only if no error occurred. The callback is invoked with two arguments: the current "CSV" parser object and an array reference to the fields passed.

The return code of the callback is ignored.

    my ($csv, $row) = @_;
    @$row > 4 and splice @$row, 4;

filter
This callback can be used to filter records. It is called just after a new record has been scanned. The callback accepts a:
hashref
The keys are the index to the row (the field name or field number, 1-based) and the values are subs to return a true or false value. 
csv (in => "file.csv", filter => {
           3 => sub { m/a/ },       # third field should contain an "a"
           5 => sub { length > 4 }, # length of the 5th field minimal 5
           });
csv (in => "file.csv", filter => { foo => sub { $_ > 4 }});

If the keys to the filter hash contain any character that is not a digit it will also implicitly set "headers" to "auto" unless "headers" was already passed as argument. When headers are active, returning an array of hashes, the filter is not applicable to the header itself.

All sub results should match, as in AND.

The context of the callback sets $_ localized to the field indicated by the filter. The two arguments are as with all other callbacks, so the other fields in the current row can be seen:

filter => { 3 => sub { $_ > 100 ? $_[1][1] =~ m/A/ : $_[1][6] =~ m/B/ }}

If the context is set to return a list of hashes ("headers" is defined), the current record will also be available in the localized %_:

filter => { 3 => sub { $_ > 100 && $_{foo} =~ m/A/ && $_{bar} < 1000  }}

If the filter is used to alter the content by changing $_, make sure that the sub returns true in order not to have that record skipped:

filter => { 2 => sub { $_ = uc }}

will upper-case the second field, and then skip it if the resulting content evaluates to false. To always accept, end with truth:

filter => { 2 => sub { $_ = uc; 1 }}
coderef
csv (in => "file.csv", filter => sub { $n++; 0; });

If the argument to "filter" is a coderef, it is an alias or shortcut to a filter on column 0:

csv (filter => sub { $n++; 0 });

is equal to

csv (filter => { 0 => sub { $n++; 0 });
filter-name
csv (in => "file.csv", filter => "not_blank");
csv (in => "file.csv", filter => "not_empty");

not_blank
Filter out the blank lines

This filter is a shortcut for

filter => { 0 => sub { @{$_[1]} > 1 or
            defined $_[1][0] && $_[1][0] ne "" } }

Due to the implementation, it is currently impossible to also filter lines that consists only of a quoted empty field. These lines are also considered blank lines.

With the given example, lines 2 and 4 will be skipped.

not_empty
Filter out lines where all the fields are empty.

This filter is a shortcut for

filter => { 0 => sub { grep { defined && $_ ne "" } @{$_[1]} } }

A space is not regarded being empty, so given the example data, lines 2, 3, 4, 5, and 7 are skipped.

filled
Filter out lines that have no visible data

This filter is a shortcut for

filter => { 0 => sub { grep { defined && m/\S/ } @{$_[1]} } }

This filter rejects all lines that not have at least one field that does not evaluate to the empty string.
