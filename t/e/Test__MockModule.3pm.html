NOM

Test::MockModule - Remplacer des fonctions dans un module pour les tests unitaires

SYNOPIS

    use Module::Name;
    use Test::MockModule;
    {
            my $module = Test::MockModule->new('Module::Name');
            $module->mock('subroutine', sub { ... });
            Module::Name::subroutine(@args); # mocké
            # Même effet, mais cela provoquera une erreur si other_subroutine()
            # n'existe pas déjà, ce qui est souvent souhaitable.
            $module->redefine('other_subroutine', sub { ... });
            # Cela provoquera une erreur si another_subroutine() est défini.
            $module->define('another_subroutine', sub { ... });
    }
    {
            # vous pouvez aussi chaîner new/mock/redefine/define
            Test::MockModule->new('Module::Name')
            ->mock( one_subroutine => sub { ... })
            ->redefine( other_subroutine => sub { ... } )
            ->define( a_new_sub => 1234 );
    }
    Module::Name::subroutine(@args); # subroutine originale
    # Travailler avec des objets
    use Foo;
    use Test::MockModule;
    {
            my $mock = Test::MockModule->new('Foo');
            $mock->mock(foo => sub { print "Foo!\n"; });
            my $foo = Foo->new();
            $foo->foo(); # imprime "Foo!\n"
    }
# Si vous voulez empêcher noop et mock de fonctionner, vous pouvez
# charger Test::MockModule en mode strict.
use Test::MockModule qw/strict/;
my $module = Test::MockModule->new('Module::Name');
# Redéfini other_subroutine ou échoue si elle n'est pas là.
$module->redefine('other_subroutine', sub { ... });
# Échoue car vous avez spécifié que vous vouliez le mode strict.
$module->mock('subroutine', sub { ... });
# Désactiver la strictness dans cette portée lexicale
{
    use Test::MockModule 'nostrict';
    # ->mock() fonctionne maintenant
    $module->mock('subroutine', sub { ... });
}
# De retour dans la portée stricte, donc mock() échoue ici
$module->mock('subroutine', sub { ... });

DESCRIPTION

"Test::MockModule" permet de remplacer des fonctions dans des modules à des fins de tests unitaires.

Un objet "Test::MockModule" est configuré pour mocker des fonctions dans un module donné. L'objet se souvient de la fonction originale afin de pouvoir la restaurer facilement. Ce processus se produit automatiquement lorsque tous les objets MockModule pour le module donné sortent de portée, ou lorsque unmock() est appelé.

MODE STRICT

L'une des faiblesses des tests utilisant des mocks est que l'implémentation de l'interface que vous mockez peut changer, tandis que vos mocks restent inchangés. Vous ne mockez plus ce que vous pensiez mocker, et vos mocks peuvent maintenant masquer des bugs qui ne seront visibles qu'en production. Pour vous aider à prévenir cela, vous pouvez charger Test::MockModule en mode strict :

use Test::MockModule qw(strict);

Cela désactivera l'utilisation de la méthode mock(), la transformant en une erreur d'exécution. Vous devriez définir les mocks en utilisant redefine(), qui ne mockera que les choses qui existent déjà et vous donnera une erreur si vous essayez de redéfinir quelque chose qui n'existe pas.

La strictness est scopée lexicalement, vous pouvez donc faire ceci dans un fichier :

use Test::MockModule qw(strict);

...->redefine(...);

et dans un autre :

use Test::MockModule; # le défaut est nostrict
...->mock(...);

Vous pouvez également mélanger la strictness à différents endroits d'un même fichier, comme ceci :

use Test::MockModule qw(strict);
# ici mock() échoue
{
    use Test::MockModule qw(nostrict);
    # ici mock() fonctionne
}
# ici mock() échoue à nouveau
use Test::MockModule qw(nostrict);
# et à partir d'ici mock() fonctionne à nouveau

Note : la strictness doit être définie au moment de la compilation et définie à l'aide de "use". Si vous pensez que vous allez essayer d'être malin en appelant la méthode import() de Test::MockModule au moment de l'exécution, il se passe des choses indéfinies, avec des résultats différents selon la version de Perl. Qu'apprendre !

MÉTHODES

new($package[, %options])
Retourne un objet qui mockerra les fonctions dans le module spécifié $package.

Si $VERSION n'est pas défini dans $package, le module sera chargé automatiquement. Vous pouvez modifier ce comportement en utilisant l'option "no_auto" :

my $mock = Test::MockModule->new('Module::Name', no_auto => 1);
get_package()
Retourne le nom du module dont les fonctions sont mockées
is_mocked($subroutine)
Retourne une valeur booléenne indiquant si la fonction $subroutine est actuellement mockée ou non
mock($subroutine => \&coderef)
Remplace une ou plusieurs fonctions dans le module qui est mocké. Une fonction peut être mockée avec une référence à une fonction ou avec une valeur scalaire. Une valeur scalaire sera convertie en une fonction qui retourne la valeur scalaire.

Retourne l'objet "Test::MockModule" actuel, vous permettant ainsi de chaîner new avec mock.

my $mock = Test::MockModule->new->(...)->mock(...);

Les instructions suivantes sont équivalentes :

$module->mock(purge => 'purged');
$module->mock(purge => sub { return 'purged'});

Lorsqu'il s'agit de références, les comportements sont légèrement différents. Les instructions suivantes ne sont pas équivalentes :

# Retourne le même arrayref à chaque fois, avec le localtime() au moment du mock
$module->mock(updated => [localtime()]);
# Retourne un nouvel arrayref à chaque fois, avec la valeur de localtime() mise à jour
$module->mock(updated => sub { return [localtime()]});

Les instructions suivantes sont en fait équivalentes :

my $array_ref = [localtime()]
$module->mock(updated => $array_ref)
$module->mock(updated => sub { return $array_ref });

Cependant, "undef" est un cas spécial. Si vous mockez une fonction avec "undef", vous installerez une fonction vide :

$module->mock(purge => undef);
$module->mock(purge => sub { });

au lieu d'une fonction qui retourne "undef" :

$module->mock(purge => sub { undef });

Vous pouvez appeler mock() pour la même fonction plusieurs fois, mais lorsque vous appelez unmock(), la fonction originale sera restaurée (pas le dernier instancié).

MOCKING + EXPORT

Si vous essayez de mocker une fonction exportée d'un autre module, cela ne se comportera pas comme vous l'attendiez initialement, car Test::MockModule ne mocke que dans le module cible, pas dans tout module qui importe ce module. Si vous mockez le paquet local ou utilisez un nom de fonction entièrement qualifié, vous obtiendrez le comportement souhaité :

use Test::MockModule;
use Test::More;
use POSIX qw/strftime/;
my $posix = Test::MockModule->new("POSIX");
$posix->mock("strftime", "Yesterday");
is strftime("%D", localtime(time)), "Yesterday", "`strftime` was mocked successfully"; # Fails
is POSIX::strftime("%D", localtime(time)), "Yesterday", "`strftime` was mocked successfully"; # Succeeds
my $main = Test::MockModule->new("main", no_auto => 1);
$main->mock("strftime", "today");
is strftime("%D", localtime(time)), "today", "`strftime` was mocked successfully"; # Succeeds

Si vous essayez de mocker une fonction qui a été exportée vers un module que vous testez, au lieu de mocker la fonction dans son module d'origine, vous pouvez la mocker dans le module que vous testez :

package MyModule;
use POSIX qw/strftime/;
sub minus_twentyfour
{
        return strftime("%a, %b %d, %Y", localtime(time - 86400));
}
package main;
use Test::More;
use Test::MockModule;
my $posix = Test::MockModule->new("POSIX");
$posix->mock("strftime", "Yesterday");
is MyModule::minus_twentyfour(), "Yesterday", "`minus-twentyfour` got mocked"; # fails

NOM

Test::MockModule - Stubbing out Perl modules

SYNOPIS

    use Test::MockModule;
    my $module = Test::MockModule->new("MyModule");
    $module->mock("some_subroutine", "some_return_value");
    is MyModule::some_subroutine(), "some_return_value", "some_subroutine mocked";
    
    # mock a subroutine to return a specific value
    $module->mock("subname", $return_value);
    
    # mock a subroutine to return the result of a block
    $module->mock("subname", sub {
        my $self = shift;
        my ($arg1, $arg2) = @_;
        # ... return value ...
    });
    
    # mock a subroutine to be a specific subroutine
    $module->mock("subname", \&other_subroutine);
    
    # mock a subroutine to be a specific method (prepending the package name)
    $module->mock("subname", \&MyModule::other_subroutine);
    
    # mock a subroutine to be a specific method (automatically prepending the package name)
    $module->mock("subname", 'other_subroutine');
    
    # mock a subroutine to be a specific method
    $module->mock("method_name", "return_value");
    
    # mock a subroutine to die
    $module->mock("subname", \&Test::MockModule::die_stub);
    
    # Mock a method that requires the object to be passed
    $module->mock('method_that_takes_self', sub {
        my $self = shift;
        # ...
    });
    
    # Mock a method and check it gets called
    $module->mock('method_that_gets_called', sub {
        my $self = shift;
        # ...
    });
    Test::MockModule::Expect->new($module, 'method_that_gets_called')->once();
    
    # Mock a method with arguments
    $module->mock('method_with_args', sub {
        my $self = shift;
        my ($arg1, $arg2) = @_;
        # ...
    });
    Test::MockModule::Expect->new($module, 'method_with_args')->with($val1, $val2)->once();
    
    # Mock a method with arguments (and check them with a code ref)
    $module->mock('method_with_args', sub {
        my $self = shift;
        my ($arg1, $arg2) = @_;
        # ...
    });
    Test::MockModule::Expect->new($module, 'method_with_args')->with(qr/regex/, sub {
        my $arg2 = shift;
        return $arg2 == 42;
    })->once();
    
    # Mock a method and expect it to be called with a certain value
    $module->mock('method_with_args', sub {
        my $self = shift;
        my ($arg1, $arg2) = @_;
        # ...
    });
    Test::MockModule::Expect->new($module, 'method_with_args')->with('bar', 42)->once();
    
    # Mock a method and expect it to be called with a certain value
    $module->mock('method_with_args', sub {
        my $self = shift;
        my ($arg1, $arg2) = @_;
        # ...
    });
    Test::MockModule::Expect->new($module, 'method_with_args')->with( 'bar', Test::MockModule::Any()->new() )->once();
    
    # mock a function that is not part of the module
    my $other = Test::MockModule->new("OtherModule");
    $other->mock("some_function", "some_value");
    
    # mock a function with a default value
    my $module = Test::MockModule->new("MyModule");
    $module->mock("get_time", "12:00 PM");
    
    # Example usage with different values
    my $mymodule = Test::MockModule->new("MyModule");
    $mymodule->mock("strftime", "Yesterday");
    is MyModule::minus_twentyfour(), "Yesterday", "`minus-twentyfour` got mocked"; # succeeds

DESCRIPTION

Test::MockModule allows you to mock out Perl modules and subroutines within those modules. This is useful for unit testing, where you want to isolate the code you are testing from its dependencies.

When you create a Test::MockModule object, it takes over the specified package and replaces the subroutines you mock with your specified behavior.

STRICT MODE

Test::MockModule respects use strict; and use warnings;. This means that mocked subroutines will be checked for existence and strictures will be enforced.

METHODS

new($package_name, %args)
Creates a new Test::MockModule object for the given $package_name. The %args are optional.
By default, Test::MockModule will attempt to load the target module if it is not already loaded. Setting no_auto => 1 will prevent this automatic loading.
mock($subroutine, $replacement)
Mocks the subroutine named $subroutine in the mocked package. The $replacement can be one of the following:
  • A scalar value: The subroutine will always return this value.
  • A subroutine reference: The subroutine will execute this subroutine. The subroutine will be called with the same arguments as the original subroutine. If the original subroutine was a method, the first argument will be the package name.
  • A subroutine name (string): The subroutine will be replaced with the subroutine of the same name in the current package.

Example:

    my $module = Test::MockModule->new("MyModule");
    $module->mock("constant_value", 42);
    $module->mock("dynamic_value", sub { return time() });
    $module->mock("method_call", "MyModule::real_method");
    $module->mock("another_method", "another_real_method");
redefine($subroutine)
Has the same behavior as mock(), but it will preemptively check to ensure that all passed subroutines actually exist. This is useful to ensure that if a mocked module's interface changes, the test doesn't continue to test a code path that no longer behaves consistently with the mocked behavior.

Note that redefine also checks if a parent provides the sub and will not die if it is available in the chain.

Returns the current "Test::MockModule" object, so you can chain new with redefine.

my $mock = Test::MockModule->new->(...)->redefine(...);
define($subroutine)
The reverse of redefine, this will fail if the passed subroutine exists. While this use case is rare, there are times when the Perl code you are testing inspects a package, and adding a missing subroutine is actually what you want to do.

By using define, you are asserting that the subroutine you want to be mocked should not exist in advance.

Note: define does not check for inheritance like redefine.

Returns the current "Test::MockModule" object, so you can chain new with define.

my $mock = Test::MockModule->new->(...)->define(...);
original($subroutine)
Returns the original (unmocked) subroutine.

Here is a sample of how to wrap a function with custom arguments using the original subroutine. This is useful when you cannot (or do not) want to alter the original code to abstract a hardcoded argument pass to a function.

package MyModule;
sub sample {
        return get_path_for("/a/b/c/d");
}
sub get_path_for {
        ... # anything goes there...
}
package main;
use Test::MockModule;
my $mock = Test::MockModule->new("MyModule");
# replace all calls to get_path_for using a different argument
$mock->redefine("get_path_for", sub {
        return $mock->original("get_path_for")->("/my/custom/path");
});
# or
$mock->redefine("get_path_for", sub {
        my $path = shift;
        if ( $path && $path eq "/a/b/c/d" ) {
                # only alter calls with path set to "/a/b/c/d"
                return $mock->original("get_path_for")->("/my/custom/path");
        } else { # preserve the original arguments
                return $mock->original("get_path_for")->($path, @_);
        }
});
unmock($subroutine [, ...])
Restores the original $subroutine. You can specify a list of subroutines to unmock() at once.
unmock_all()
Restores all the subroutines in the package that were mocked. This is automatically called when all "Test::MockObject" objects for the given package go out of scope.
noop($subroutine [, ...])
Given a list of subroutine names, mocks each of them with a no-op subroutine. Handy for mocking methods you want to ignore! 
# Neuter a list of methods in one go
$module->noop('purge', 'updated');
