NAME

Template::FAQ - Foire aux questions sur le langage Template Toolkit

Langage Template Toolkit

Pourquoi [% a = b IF c %] ne fonctionne-t-il pas comme prévu ?

Il y a une limitation dans le parser TT2 qui signifie que le code suivant ne fonctionne pas comme prévu :

[% a = b IF c %]

Le parser interprète ceci comme une tentative de définir "a" à la valeur de "b IF c", donc :

[% a = (b IF c) %]

Si vous souhaitez définir "a = b" seulement si "c" est vrai, faites ceci :

[% SET a = b IF c %]

Le mot-clé "SET" donne au parser l'indice nécessaire pour faire la bonne chose.

NOTE : Ce problème sera résolu dans TT3.

Y a-t-il un bon moyen d'échapper [% et %] lorsque j'écris un template TT ?

Vous pouvez faire quelque chose comme ceci :

[% stag = "[\%"
   etag = "%\]"
%]

et ensuite :

[% stag; 'hello'; etag %]

Ou vous pouvez utiliser la directive "TAGS", comme ceci :

[% TAGS [- -] %]
[- INCLUDE foo -]   # est une directive
[% INCLUDE foo %]   # n'est pas une directive

Comment parcourir une table de hachage ?

Ce sujet est abordé dans la section Template::Manual::VMethods de la documentation. Une liste de toutes les clés présentes dans la table peut être obtenue via la méthode virtuelle "keys". Vous pouvez ensuite parcourir cette liste et rechercher chaque clé dans l'ordre pour obtenir la valeur.

[% FOREACH key = product.keys %]
   [% key %] => [% product.$key %]
[% END %]

Plugins

Comment faire en sorte que le plugin Table ordonne les données horizontalement plutôt que verticalement ?

Triez les données en lignes :

Steve     Karen     Jeff
Brooklyn  Nantucket Fairfax
NY        MA        VA
[% USE table(data, rows=3) %]

Ensuite, demandez chaque colonne :

[% FOREACH column = table.cols %]

Et ensuite, imprimez chaque élément de la colonne, en parcourant les lignes de sortie :

[% FOREACH item = column %]
    <td>[% item %]</td>
[% END %]

Accès aux cookies

Jeff Boes <jboes@nexcerpt.com> demande :

Existe-t-il un moyen rapide et simple d'accéder aux cookies à partir des modèles ?

Jonas Liljegren répond :

[% USE CGI %]
<p>La valeur est [% CGI.cookie('cookie_name') | html %]

Vous devez avoir le plugin Template::Plugin::CGI installé.

Extension du Template Toolkit

Puis-je servir des modèles depuis une base de données ?

Réponse courte : oui, Chris Nandor l'a fait pour Slash. Vous devez hériter de Template::Provider. Voir les corrections de la liste de diffusion pour plus d'informations.

Puis-je récupérer des modèles via HTTP ?

Pour que cela fonctionne correctement, vous devez hériter de Template::Provider pour "Template::Provider::HTTP" et utiliser une option "PREFIX_MAP" pour mapper le préfixe "http" à ce fournisseur particulier (vous voudrez peut-être consulter le fichier *Changes* autour de la version 2.01 pour plus d'informations sur "PREFIX_MAP" - il pourrait ne pas être bien documenté autrement... pour l'instant !). Par exemple :

use Template::Provider::HTTP;
my $file = Template::Provider( INCLUDE_PATH => [...] );
my $http = Template::Provider::HTTP->new(...);
my $tt2  = Template->new({
    LOAD_TEMPLATES => [ $file, $http ],
    PREFIX_MAP => {
        file    => '0',     # file:foo.html
        http    => '1',     # http:foo.html
        default => '0',     # foo.html => file:foo.html
    }
});

Maintenant, un modèle spécifié comme :

[% INCLUDE foo %]

sera servi par le fournisseur 'file' (par défaut). Si vous ne le spécifiez pas, vous pouvez explicitement ajouter un préfixe :

[% INCLUDE file:foo.html %]
[% INCLUDE http:foo.html %]
[% INCLUDE http://www.xyz.com/tt2/header.tt2 %]

Ce même principe peut être utilisé pour créer un fournisseur DBI. Par exemple :

[% INCLUDE dbi:foo.html %]

Mais nous n'avons pas encore de fournisseur DBI faisant partie de la bibliothèque Template Toolkit. Des discussions ont eu lieu sur la liste de diffusion concernant les efforts visant à développer des fournisseurs DBI et/ou HTTP, mais personne n'a encore relevé le défi...

En attendant, l'article de Craig Barrat sur la liste de diffusion contient des points utiles sur la façon d'y parvenir en utilisant des modules existants. Voir http://tt2.org/pipermail/templates/2001-May/000954.html

Divers

Comment puis-je connaître le nom du modèle principal en cours de traitement ?

La variable "template" contient une référence à un objet Template::Document pour le modèle principal que vous traitez (c'est-à-dire celui passé comme premier argument à la fonction Template::process()). La variable "name" renvoie son nom.

[% template.name %]     # par ex. index.html

Comment puis-je connaître le nom du modèle actuel en cours de traitement ?

La variable "template" fait toujours référence au modèle principal en cours de traitement. Donc, même si vous appelez [% INCLUDE header %] et que cet appel appelle [% INCLUDE menu %], la variable "template" ne change pas.

index.html:

[% template.name %]     # index.html
[% INCLUDE header %]

header:

[% template.name %]     # index.html
[% INCLUDE menu   %]

menu:

[% template.name %]     # index.html

En revanche, la variable "component" fait toujours référence au modèle actuel en cours de traitement.

index.html

[% component.name %]     # index.html
[% INCLUDE header %]

header:

[% component.name %]     # header
[% INCLUDE menu   %]

menu:

[% component.name %]     # menu

Comment imprimer l'heure de modification du modèle ou du composant ?

Les variables "template" et "component" font référence au modèle principal et au modèle actuel en cours de traitement (voir les questions précédentes). La méthode "modtime" renvoie l'heure de modification du fichier correspondant sous forme de secondes depuis l'Epoch Unix (00:00:00 GMT le 1er janvier 1970).

Ce nombre n'a pas beaucoup de sens pour la plupart des gens (sauf pour les vrais geeks Unix), vous voudrez donc probablement utiliser le plugin Date pour le formater pour une consommation humaine.

[% USE Date %]
[% template.name %] modifié pour la dernière fois le [% Date.format(template.modtime) %]

Comment puis-je configurer des variables par requête ?

Une façon simple d'y parvenir est de définir un seul template "PRE_PROCESS" qui charge d'autres fichiers de configuration en fonction de variables ou de conditions définies.

Par exemple, ma configuration ressemble souvent à ceci :

PRE_PROCESS => 'config/main'

config/main :

[%  DEFAULT  style   = 'text'
             section =  template.section or 'home';
    PROCESS  config/site
          +  config/urls
          +  config/macros
          + "config/style/$style"
          + "config/section/$section"
          + ...
%]

Cela me permet de définir une seule variable 'style' pour contrôler quel fichier de configuration est pré-traité afin de définir mes différentes options de style (couleurs, chemins d'images, etc.). Par exemple :

config/style/basic :

[%  style = {
        name = style    # enregistre la variable 'style' existante sous 'style.name'
        # définir d'autres variables de style...
        col = {
            back => '#ffffff'
            text => '#000000'
                # ...etc...
        }
        logo = {
                # ...etc...
        }
        # ...etc...
    }
%]

Chaque template source peut déclarer la section utilisée via une directive META :

[% META
     title   = 'General Information'
     section = 'info'
%]
...

Cela contrôle quel fichier de configuration est chargé pour définir d'autres variables pour le titre de la section, le menu, etc.

config/section/info :

[%  section = {
        name   = section  # enregistre la variable 'section' sous 'section.name'
        title  = 'Information'
        menu   = [ ... ]
        # ...etc...
    }
%]

Ceci illustre le principe de base, mais vous pouvez l'étendre pour effectuer toute initialisation de document dont vous pourriez avoir besoin.

Pourquoi obtiens-je des caractères invalides pour mes templates UTF-8 ?

Tout d'abord, assurez-vous que vos fichiers de template définissent un Marqueur d'Ordre des Octets (Byte Order Mark - BOM) http://en.wikipedia.org/wiki/Byte_Order_Mark

Si vous ne souhaitez pas ajouter de BOM à vos templates, vous pouvez forcer Template à utiliser un encodage spécifique (par exemple, "utf8") pour vos templates avec l'option "ENCODING".

my $template = Template->new({
    ENCODING => 'utf8'
});
