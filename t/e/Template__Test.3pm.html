Template::Test(3) Documentation Perl fournie par l'utilisateur Template::Test(3)

NOM

Template::Test - Module pour automatiser les scripts de test TT2

SYNOPSIS

use Template::Test;
$Template::Test::DEBUG = 0;   # mettez cette valeur à vrai pour voir chaque test s'exécuter
$Template::Test::EXTRA = 2;   # 2 tests supplémentaires suivent test_expect()...
# ok() peut être appelé autant de fois que nécessaire avant test_expect
ok( $vrai_ou_faux )
# test_expect() divise $input en tests individuels, traite chacun
# et compare la sortie générée à la sortie attendue
test_expect($input, $template, \%remplacement );
# $input est une chaîne de texte ou un pointeur de fichier (par exemple, section DATA après __END__)
test_expect( $texte );
test_expect( \*DATA );
# $template est un objet Template ou une configuration de hachage
my $config_template = { ... };
test_expect( $input, $config_template );
my $objet_template = Template->new($config_template);
test_expect( $input, $objet_template );
# $remplacement est une référence de hachage de variables de modèle
my $remplacement = {
    a => 'alpha',
    b => 'bravo'
};
test_expect( $input, $template, $remplacement );
# ok() appelé après test_expect doit être déclaré dans $EXTRA (2)
ok( $vrai_ou_faux )
ok( $vrai_ou_faux )

DESCRIPTION

Le module "Template::Test" définit la sous-routine test_expect() et d'autres sous-routines connexes qui peuvent être utilisées pour automatiser les scripts de test pour le Template Toolkit. Voir les nombreux tests dans le sous-répertoire t de la distribution pour des exemples d'utilisation.

SOUS-ROUTINES DE PAQUET

test_expect()

La sous-routine test_expect() divise un document d'entrée en un certain nombre de tests distincts, traite chacun d'eux en utilisant le Template Toolkit, puis compare la sortie générée à une sortie attendue, également spécifiée dans le document d'entrée. Elle génère la sortie familière "ok"/"not ok" compatible avec "Test::Harness".

L'entrée de test doit être spécifiée comme une chaîne de texte ou une référence à un pointeur de fichier (par exemple, "GLOB" ou "IO::Handle") à partir de laquelle elle peut être lue. En particulier, cela permet à l'entrée de test d'être placée après le marqueur "__END__" et lue via le pointeur de fichier "DATA".

use Template::Test;
test_expect(\*DATA);
__END__
# ceci est le premier test (c'est un commentaire)
-- test --
bla bla bla [% foo %]
-- expect --
bla bla bla valeur_de_foo
# voici le deuxième test (pas de surprise, donc c'est ça)
-- test --
encore bla bla [% bar %]
-- expect --
encore bla bla valeur_de_bar

Les lignes vides entre les sections de test sont généralement ignorées. Toute ligne commençant par "#" est traitée comme un commentaire et est ignorée.

Les deuxième et troisième paramètres de test_expect() sont facultatifs. Le second peut être soit une référence à un objet Template qui doit être utilisé pour traiter les fragments de modèle, soit une référence à un tableau associatif contenant des valeurs de configuration qui doivent être utilisées pour instancier un nouvel objet Template.

# passer une référence à un tableau associatif de configuration
my $config = {
    INCLUDE_PATH => '/ici/là:/partout',
    POST_CHOMP   => 1,
};
test_expect(\*DATA, $config);
# ou créer explicitement un objet Template
my $template = Template->new($config);
test_expect(\*DATA, $template);

Le troisième paramètre peut être utilisé pour référencer un tableau associatif de variables de modèle qui doivent être définies lors du traitement des tests. Ceci est passé à la méthode process() de Template.

my $remplacement = {
    a => 'alpha',
    b => 'bravo',
};
test_expect(\*DATA, $config, $remplacement);

Le deuxième paramètre peut être laissé indéfini pour spécifier une configuration Template par défaut.

test_expect(\*DATA, undef, $remplacement);

Pour tester la sortie de différentes configurations Template, une référence à une liste d'objets Template nommés peut également être passée en deuxième paramètre.

my $tt1 = Template->new({ ... });
my $tt2 = Template->new({ ... });
my @tts = [ un => $tt1, deux => $tt1 ];

Le premier objet de la liste est utilisé par défaut. D'autres objets peuvent être activés avec un marqueur '"-- utiliser $nom --"'. Cela doit suivre immédiatement une ligne '"-- test --"'. Cet objet sera alors utilisé pour le reste du test, ou jusqu'à ce qu'un objet différent soit sélectionné.

-- test --
-- utiliser un --
[% blah %]
-- expect --
bla, bla
-- test --
utilise toujours un...
-- expect --
...
-- test --
-- utiliser deux --
[% blah %]
-- expect --
bla, bla, encore bla

La sous-routine test_expect() compte le nombre de tests, puis appelle ntests() pour générer la ligne familière ""1..$ntests\n"" du gestionnaire de tests. Chaque test défini génère deux numéros de test. Le premier indique que l'entrée a été traitée sans erreur, et le second que la sortie correspond à celle attendue.

Des tests supplémentaires peuvent être exécutés avant test_expect() en appelant ok(). Les résultats de ces tests sont mis en cache jusqu'à ce que ntests() soit appelé et que le nombre total de tests puisse être calculé. Ensuite, la ligne ""1..$ntests"" est produite, ainsi que les lignes ""ok $n"" / ""not ok $n"" pour chacun des résultats de test mis en cache. Les appels ultérieurs à ok() génèrent alors une ligne de sortie immédiatement.

my $quelquechose = SomeObject->new();
ok( $quelquechose );
my $autre = AnotherThing->new();
ok( $autre );
test_expect(\*DATA);

Si des tests doivent suivre après l'appel de test_expect(), ils doivent être prédéclarés en définissant la variable de package $EXTRA. Cette valeur (par défaut : 0) est ajoutée au total général calculé par ntests(). Les résultats des tests supplémentaires sont également enregistrés en appelant ok().

$Template::Test::EXTRA = 2;
# peut appeler ok() un nombre quelconque de fois avant test_expect()
ok( $ceci_a_fonctionné );
ok( $assure_toi );
ok( $certain_de_mort );
# <quelque> nombre de tests...
test_expect(\*DATA, $config, $remplacement);
# voici ces $EXTRA tests
ok( defined $resultat_quelconque && ref $resultat_quelconque eq 'ARRAY' );
ok( $resultat_quelconque->[0] eq 'une valeur attendue quelconque' );

Si vous ne voulez pas appeler test_expect() du tout, vous pouvez appeler ntests($n) pour déclarer le nombre de tests et générer la ligne d'en-tête des tests. Après cela, appelez simplement ok() pour chaque test en passant une valeur vraie ou fausse pour indiquer si le test a réussi ou échoué.

ntests(2);
ok(1);
ok(0);

Si vous êtes vraiment paresseux, vous pouvez simplement appeler ok() et ne pas vous soucier de déclarer le nombre de tests du tout. Tous les résultats de test seront mis en cache jusqu'à la fin du script, puis imprimés en une seule fois avant la sortie du programme.

ok( $x );
ok( $y );

Vous pouvez identifier uniquement une partie spécifique du fichier d'entrée pour les tests en utilisant les marqueurs '"-- début --"' et '"-- fin --"'. Tout ce qui précède le premier '"-- début --"' est ignoré, ainsi que tout ce qui suit le prochain marqueur '"-- fin --"'.

-- test --
ceci est le test 1 (non effectué)
-- expect --
ceci est le test 1 (non effectué)
-- début --
-- test --
ceci est le test 2
-- expect --
ceci est le test 2
-- fin --
...

ntests()

Sous-routine utilisée pour spécifier le nombre de tests que vous attendez d'exécuter.

ok($test)

Génère un message ""ok $n"" ou ""not ok $n"" si $test est vrai ou faux.

not_ok($test)

L'inverse logique de ok(). Affiche un message ""ok $n"" si $test est faux et vice-versa.

callsign()

Pour des raisons historiques et une utilité générale, le module définit également une sous-routine callsign() qui renvoie un tableau associatif mappant les lettres "a" à "z" à leur équivalent dans l'alphabet phonétique (par exemple, indicatifs d'appel radio). Ceci est utilisé par de nombreux scripts de test comme source connue de variables

Template::Test

Template::Test

NOM

Template::Test

SYNTAXE

Ce module permet d'exécuter des tests de manière similaire à test_expect, mais avec une interface plus simple.

test_expect(\*DATA, $config, callsign());

banner()

Cette sous-routine imprime une bannière simple, incluant tout texte passé en paramètres. La variable $DEBUG doit être activée pour générer une sortie.

banner('Testing something-or-other');

Exemple de sortie:

#------------------------------------------------------------
# Testing something-or-other (27 tests completed)
#------------------------------------------------------------

Cette sous-routine imprime une bannière simple, incluant tout texte passé en paramètres. La variable $DEBUG doit être activée pour générer une sortie.

banner('Testing something-or-other');

#------------------------------------------------------------

VARIABLES DU PAQUET

$DEBUG

La variable de paquet $DEBUG peut être configurée pour activer le mode de débogage.

$PRESERVE

La variable de paquet $PRESERVE peut être configurée pour que test_expect() ne convertisse pas les nouvelles lignes en chaînes littérales '\n'.

HISTORIQUE

Ce module a commencé sa vie en tant que script "t/texpect.pl". Il a été nettoyé et transformé en module "Template::Test" autour de la version 0.29. D'autres chirurgies esthétiques ont eu lieu pour la version 2.00, mais il conserve encore quelques ressemblances dans son fondement.

Depuis, les modules "Test::More" et associés sont apparus sur CPAN, rendant ce module, en partie mais pas entièrement, redondant.

BOGUES / "FONCTIONNALITÉS" CONNUES

Il importe tous les méthodes par défaut. C'est généralement une mauvaise chose, mais ce module n'est utilisé que dans des scripts de test (c'est-à-dire au moment de la construction), donc a) nous ne nous en soucions pas vraiment et b) cela réduit la frappe.

La division des lignes peut être un peu stupide, surtout si elle rencontre des lignes comme "-- this --" qui ne devraient pas être des marqueurs spéciaux. Donc, ne faites pas cela.
