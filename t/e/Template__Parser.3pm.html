NOM

Template::Parser - Analyseur LALR(1) pour compiler des documents de gabarit

SYNOPIS

use Template::Parser;
$parser   = Template::Parser->new(\%config);
$template = $parser->parse($text)
    || die $parser->error(), "\n";

DESCRIPTION

Le module "Template::Parser" implémente un analyseur LALR(1) et des méthodes associées pour compiler des documents de gabarit en code Perl.

MÉTHODES PUBLIQUES

new(\%params)

Le constructeur new() crée et retourne un objet "Template::Parser".

Une référence de hachage peut être fournie en tant que paramètre pour fournir des valeurs de configuration. Voir "OPTIONS DE CONFIGURATION" ci-dessous pour un résumé de ces options et Template::Manual::Config pour des détails complets.

my $parser = Template::Parser->new({
    START_TAG => quotemeta('<+'),
    END_TAG   => quotemeta('+>'),
});

parse($text)

La méthode parse() analyse le texte passé en paramètre et retourne une référence de hachage de données qui définit la représentation compilée du texte de gabarit, appropriée pour être passée à la méthode new() de Template::Document. En cas d'erreur, undef est retourné.

$data = $parser->parse($text)
    || die $parser->error();

Le hachage de données $data retourné contient un "BLOCK" qui contient le code Perl compilé pour le gabarit, un "DEFBLOCKS" qui contient une référence à un hachage de données de blocs de gabarit "BLOCK" définis dans le gabarit, et un "METADATA" qui contient une référence à un hachage de valeurs de métadonnées définies dans des balises "META".

OPTIONS DE CONFIGURATION

Le module "Template::Parser" accepte les options de configuration suivantes. Voir Template::Manual::Config pour des détails supplémentaires sur chaque option.

START_TAG, END_TAG

Les options START_TAG et END_TAG sont utilisées pour spécifier des séquences de caractères ou des expressions régulières qui marquent le début et la fin d'un bloc de gabarit.

my $parser = Template::Parser->new({
    START_TAG => quotemeta('<+'),
    END_TAG   => quotemeta('+>'),
});

TAG_STYLE

L'option TAG_STYLE peut être utilisée pour définir à la fois START_TAG et END_TAG selon des styles prédéfinis.

my $parser = Template::Parser->new({
    TAG_STYLE => 'star',     # [* ... *]
});

PRE_CHOMP, POST_CHOMP

Les valeurs PRE_CHOMP et POST_CHOMP peuvent être définies pour supprimer tout espace blanc avant ou après un bloc de balise.

my $parser = Template::Parser->new({
    PRE_CHOMP  => 1,
    POST_CHOMP => 1,
});

INTERPOLATE

L'option INTERPOLATE peut être définie pour autoriser les variables intégrées dans des blocs de texte normaux.

my $parser = Template::Parser->new({
    INTERPOLATE => 1,
});

Les variables doivent être préfixées par "$" pour les identifier, en utilisant des accolades pour délimiter la portée du nom de variable si nécessaire.

Bonjour ${name},
Le jour aujourd'hui est ${day.today}.

ANYCASE

L'option ANYCASE peut être utilisée pour permettre la spécification des mots-clés de gabarit dans n'importe quelle casse.

# avec ANYCASE défini à 1
[% INCLUDE foobar %]    # OK
[% include foobar %]    # OK
[% include = 10   %]    # ERREUR, 'include' est un mot réservé

GRAMMAR

L'option GRAMMAR peut être utilisée pour spécifier une grammaire alternative pour l'analyseur. Cela permet de construire et d'utiliser un langage de gabarit modifié ou entièrement nouveau avec Template Toolkit.

use MyOrg::Template::Grammar;
my $parser = Template::Parser->new({
    GRAMMAR = MyOrg::Template::Grammar->new();
});

Par défaut, une instance du module Template::Grammar par défaut sera automatiquement créée et utilisée si l'élément GRAMMAR n'est pas spécifié.

DEBUG

L'option DEBUG peut être utilisée pour activer diverses fonctionnalités de débogage de la classe "Template::Parser".

use Template::Constants qw( :debug );
my $template = Template->new({
    DEBUG => DEBUG_PARSER | DEBUG_DIRS,
});
