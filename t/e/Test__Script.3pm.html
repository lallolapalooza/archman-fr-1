Test::Script(3) Documentation Perl fournie par l'utilisateur Test::Script(3)

NOM

Test::Script - Tests de base multiplateformes pour scripts

VERSION

version 1.31

SYNOPSIS

use Test2::V0;
use Test::Script;

script_compiles('script/myscript.pl');
script_runs(['script/myscript.pl', '--my-argument']);

program_runs(['ls', '/dev']);

done_testing;

DESCRIPTION

L'intention de ce module est de fournir une série de tests de base pour 80% des tests que vous devrez effectuer pour les scripts dans les chemins script (ou bin comme il est aussi couramment utilisé) de votre distribution Perl.

Il fournit également des fonctions similaires pour tester des programmes qui ne sont pas des scripts Perl.

De plus, il vise à fournir cette fonctionnalité avec une compatibilité plateforme parfaite, et d'une manière aussi discrète que possible.

Autrement dit, si le programme fonctionne sur une plateforme, alors Test::Script devrait toujours fonctionner sur cette plateforme aussi. Moins de 100% est considéré comme inacceptable.

Ce faisant, on espère que Test::Script pourra devenir un module dont vous pourrez faire en toute sécurité une dépendance de tous vos modules, sans risquer que votre module ne s'installe pas sur une certaine plateforme en raison de la dépendance.

Lorsqu'un conflit existe entre la volonté d'avoir plus de fonctionnalités et le maintien de la sécurité de la plateforme, ce module privilégiera la sécurité de la plateforme.

FONCTIONS

script_compiles

[version 1.05]

script_compiles( $script, $test_name );

Le test "script_compiles" appelle le script avec "perl -c script.pl", et vérifie qu'il se termine sans erreur.

Le chemin qui doit lui être passé est un nom de script relatif au format Unix. Celui-ci sera localisé lors de l'exécution de "perl -c" et si le test échoue, le nom local utilisé sera affiché dans la sortie diagnostique.

Notez également que le test sera exécuté avec le même interpréteur Perl qui exécute le script de test (et non avec le Perl système par défaut). Ceci sera également affiché dans la sortie diagnostique en cas d'échec.

script_runs

[version 1.05]

script_runs( $script, $test_name );
script_runs( \@script_and_arguments, $test_name );
script_runs( $script, \%options, $test_name );
script_runs( \@script_and_arguments, \%options, $test_name );

Le test "script_runs" exécute le script avec "perl script.pl" et vérifie qu'il se termine avec succès.

Le chemin qui doit lui être passé est un nom de script relatif au format Unix. Celui-ci sera localisé lors de l'exécution de "perl -c" et si le test échoue, le nom local utilisé sera affiché dans la sortie diagnostique.

Le test sera exécuté avec le même interpréteur Perl qui exécute le script de test (et non avec le Perl système par défaut). Ceci sera également affiché dans la sortie diagnostique en cas d'échec.

[version 1.09]

Vous pouvez passer des options sous forme de hachage comme deuxième argument (depuis la version 1.09).

exit
La valeur de sortie attendue. Par défaut, il utilise ce qui indique le succès sur votre plateforme (généralement 0).
interpreter_options
[version 1.25]

Référence d'un tableau d'options Perl à passer à l'interpréteur. Des éléments comme "-w" ou "-x" peuvent être passés de cette manière. Cela peut être une chaîne unique ou une référence de tableau.

signal
Le signal attendu. La valeur par défaut est 0. À utiliser avec prudence ! Ceci peut ne pas être portable et est connu pour ne pas fonctionner sous Windows.
stdin
L'entrée à passer au script via stdin. La valeur peut être l'un des éléments suivants :
scalaire simple
Est considéré comme un nom de fichier.
référence scalaire
Dans ce cas, l'entrée sera tirée des données contenues dans le scalaire référencé.

Le comportement pour tout autre type est indéfini (l'implémentation actuelle utilise Capture::Tiny). Tout stdin déjà ouvert sera fermé.

stdout
Où envoyer la sortie standard. Si vous utilisez cette option, alors le comportement des fonctions "script_stdout_" ci-dessous est indéfini. La valeur peut être l'un des éléments suivants :
scalaire simple
Est considéré comme un nom de fichier.
référence scalaire

Dans ce cas, la sortie standard sera placée dans le scalaire référencé.

Le comportement pour tout autre type est indéfini (l'implémentation actuelle utilise Capture::Tiny).

stderr
Identique à "stdout" ci-dessus, sauf pour stderr.

script_fails

[ version 1.28 ]

script_fails $script, { exit => $expected_exit }, $test_name );
script_fails $script, \%options, $test_name;

"script_runs" peut être invoqué comme "script_fails". L'option exit est obligatoire lorsqu'elle est utilisée de cette manière. Depuis Perl 5.12, "die" renvoie généralement 255, mais ne promet pas de le faire. Les erreurs fatales comme la division par zéro renvoient également souvent 255, ce n'est donc pas le meilleur code d'erreur pour une exception interceptée. script_runs a besoin d'un code de sortie qu'il considère comme un succès, utilisez "warn; exit;" au lieu de die.

script_stdout_is

[version 1.09]

script_stdout_is $expected_stdout, $test_name;

Teste si la sortie standard du précédent "script_runs" correspond exactement à la valeur attendue.

script_stdout_isnt

[version 1.09]

script_stdout_is $expected_stdout, $test_name;

Teste si la sortie standard du précédent "script_runs" ne correspond PAS exactement à la valeur attendue.

script_stdout_like

[version 1.09]

script_stdout_like $regex, $test_name;

Teste si la sortie standard du précédent "script_runs" correspond à l'expression régulière.

script_stdout_unlike

[version 1.09]

script_stdout_unlike $regex, $test_name;

Teste si la sortie standard du précédent "script_runs" ne correspond PAS à l'expression régulière.

script_stderr_is

[version 1.09]

script_stderr_is $expected_stderr, $test_name;

Teste si la sortie d'erreur standard du précédent "script_runs" correspond exactement à la valeur attendue.

script_stderr_isnt

[version 1.09]

script_stderr_is $expected_stderr, $test_name;

Teste si la sortie d'erreur standard du précédent "script_runs" ne correspond PAS exactement à la valeur attendue.

script_stderr_like

[version 1.09]

script_stderr_like $regex, $test_name;

Teste si la sortie d'erreur standard du précédent "script_runs" correspond à l'expression régulière.

script_stderr_unlike

[version 1.09]

script_stderr_unlike $regex, $test_name;

Teste si la sortie d'erreur standard du précédent "script_runs" ne correspond PAS à l'expression régulière.

PROGRAM_RUNS

[version 1.26]

program_runs( $program, $test_name );
program_runs( \@program_and_arguments, $test_name );
program_runs( $program, \%options, $test_name );
program_runs( \@program_and_arguments, \%options, $test_name );

La fonction "program_runs" exécute un programme (pas nécessairement un script Perl) et vérifie qu'il se termine avec succès.

Les options sont les mêmes que pour script_runs() à l'exception de "interpreter_options" qui n'est pas un argument valide ici.

Si le programme est introuvable, le test échoue.

EXTERNAL_DEPENDENCIES

Ce module utilise Capture::Tiny, et ce, directement, pour capturer la sortie des scripts.

Test::Script(3pm)

Test::Script - A module for testing scripts and programs

NAME

Test::Script - A module for testing scripts and programs

VERSION

1.31

SYNOPSIS

use Test::Script;

# Create a script named 'test.pl'
# print "hello\n"; exit 0;

# Run the script and check for success
ok(script_runs('test.pl'), 'script runs');

# Check stdout
is(script_stdout('test.pl'), "hello\n", 'script stdout is correct');

# Check stderr
is(script_stderr('test.pl'), '', 'script stderr is empty');

# Run a program and check for success
# ok(program_runs('ls', '-l'), 'program runs');

DESCRIPTION

This module provides a set of utility functions for testing Perl scripts and external programs. It simplifies the process of checking exit codes, standard output, and standard error.

FUNCTIONS

script_runs

[version 1.00]

script_runs( $script, $test_name );
script_runs( \@script_and_arguments, $test_name );
script_runs( $script, \%options, $test_name );
script_runs( \@script_and_arguments, \%options, $test_name );

Runs the given Perl script and checks that it returns success (an exit code of 0).

If $script is a string, it is passed to the Perl interpreter. If it is an array reference, the first element is the script path and subsequent elements are arguments to the script. If no arguments are given, the script is executed with no arguments.

The %options hash can contain:

interpreter
The path to the Perl interpreter to use. Defaults to the one running the test.
interpreter_options
An array reference of options to pass to the interpreter. For example, ['-w'] to enable warnings.
script_args
An array reference of arguments to pass to the script. These are appended to any arguments specified in @script_and_arguments.
stdin
A string to be passed to the script's standard input. Note that the STDIN handle will be closed after this is used.

Returns true on success, false on failure.

script_fails

[version 1.28]

script_fails $script, { exit => $expected_exit }, $test_name;
script_fails $script, \%options, $test_name;

Similar to "script_runs", but checks that the script fails. The exit option in %options is required and specifies the expected exit code.

script_stdout_is

[version 1.00]

script_stdout_is $expected_stdout, $test_name;

Tests if the output to stdout from the previous "script_runs" matches the expected value exactly.

script_stdout_isnt

[version 1.00]

[version 1.00]

[version 1.00]

script_stdout_unlike $regex, $test_name;

program_runs

[version 1.26]

program_runs( $program, $test_name );
program_runs( \@program_and_arguments, $test_name );
program_runs( $program, \%options, $test_name );
program_runs( \@program_and_arguments, \%options, $test_name );

The "program_runs" test executes the given program and checks that it returns success. This function works like "script_runs" except:

  • The path $program or @program_and_arguments is passed as-is to system() https://perldoc.perl.org/functions/system.html. This means "program_runs" can test any program, not just Perl scripts.
  • The %options do not support the "interpreter_options" key.

See File::Spec or Path::Class for routines useful in building pathnames in a cross-platform way.

program_fails

[ version 1.28 ]

program_fails $program, { exit => $expected_exit }, $test_name;
program_fails $program, \%options, $test_name;

"program_runs" may be invoked as "program_fails". "program_fails" needs to know the expected exit value, so exit becomes a required option.

CAVEATS

This module is fully supported back to Perl 5.8.1.

The STDIN handle will be closed when using script_runs with the stdin option. An older version used IPC::Run3, which attempted to save STDIN, but apparently this cannot be done consistently or portably. We now use Capture::Tiny instead and explicitly do not support saving STDIN handles.
