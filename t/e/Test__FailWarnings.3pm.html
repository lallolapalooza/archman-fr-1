NOM

Test::FailWarnings - Ajoute des échecs de test si des avertissements sont interceptés

VERSION

version 0.008

SYNOPHIS

Fichier de test :

use strict;
use warnings;
use Test::More;
use Test::FailWarnings;
ok( 1, "premier test" );
ok( 1 + "lkadjaks", "ajouter un non-numérique" );
done_testing;

Sortie :

ok 1 - premier test
not ok 2 - Test::FailWarnings devrait capturer aucun avertissement
#   Échec du test 'Test::FailWarnings devrait capturer aucun avertissement'
#   à t/bin/main-warn.pl ligne 7.
# L'avertissement était 'Argument "lkadjaks" isn't numeric in addition (+) at t/bin/main-warn.pl line 7.'
ok 3 - ajouter un non-numérique
1..3
# Il semble que vous ayez échoué 1 test sur 3.

DESCRIPTION

Ce module intercepte $SIG{__WARN__} et convertit les avertissements en appels fail() de Test::More. Il est conçu pour être utilisé avec "done_testing", lorsque vous n'avez pas besoin de connaître le nombre de tests à l'avance.

Tout comme avec Test::NoWarnings, cela ne capture pas les avertissements si d'autres éléments localisent $SIG{__WARN__}, car il est conçu pour capturer les avertissements *non gérés*.

UTILISATION

Redéfinition de $SIG{__WARN__}

Lors de l'"import", $SIG{__WARN__} est remplacé par "Test::FailWarnings::handler".

use Test::FailWarnings;  # global

Si vous ne souhaitez pas un remplacement global, exigez le module à la place et localisez-le dans la portée de votre choix.

require Test::FailWarnings;
{
    local $SIG{__WARN__} = \&Test::FailWarnings::handler;
    # ... les avertissements généreront fail() ici
}

Lorsque le gestionnaire rapporte la source de l'avertissement, il essaiera d'ignorer les paquets appelants commençant par "Carp" ou "warnings" pour tenter de détecter l'origine réelle de l'avertissement.

Autoriser les avertissements des dépendances

Si vous souhaitez ignorer les échecs provenant de code extérieur au vôtre, vous pouvez définir $Test::FailWarnings::ALLOW_DEPS à une valeur vraie. Vous pouvez le faire lors de la ligne "use" avec "-allow_deps".

use Test::FailWarnings -allow_deps => 1;

Lorsque c'est vrai, les avertissements ne seront déclenchés que s'ils semblent provenir d'un nom de fichier correspondant à "qr/^(?:t|xt|lib|blib)/"

Autoriser les avertissements de modules spécifiques

Si vous souhaitez mettre sur liste blanche des modules spécifiques uniquement, vous pouvez ajouter leurs noms de paquets à @Test::NoWarnings::ALLOW_FROM. Vous pouvez le faire lors de la ligne "use" avec "-allow_from".

use Test::FailWarnings -allow_from => [ qw/Annoying::Module/ ];

VOIR AUSSI

  • Test::NoWarnings -- capture les avertissements et les rapporte dans un bloc "END". N'est pas (encore) compatible avec "done_testing".
  • Test::Warnings -- un remplacement de Test::NoWarnings qui fonctionne avec done_testing
  • Test::Warn -- teste les avertissements sans déclencher d'échecs de ce module
