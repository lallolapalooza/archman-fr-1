Test2::Formatter(3perl) Guide du programmeur Perl Test2::Formatter(3perl)

NOM

Test2::Formatter - Espace de noms pour les formateurs.

DESCRIPTION

Ceci est l'espace de noms pour les formateurs. C'est un paquetage vide.

CRÉER DES FORMATEURS

Un formateur est tout paquetage ou objet avec une méthode "write($event, $num)".

package Test2::Formatter::Foo;
use strict;
use warnings;
sub write {
    my $self_or_class = shift;
    my ($event, $assert_num) = @_;
    ...
}
sub hide_buffered { 1 }
sub terminate { }
sub finalize { }
sub supports_tables { return $BOOL }
sub new_root {
    my $class = shift;
    ...
    $class->new(@_);
}
1;

La méthode "write" est une méthode, donc elle reçoit soit une classe, soit une instance. Les deux arguments sont l'objet $event qu'elle doit enregistrer, et le $assert_num qui est le numéro de l'assertion en cours (ok), ou de la dernière assertion si cet événement n'est pas une assertion en soi. Le numéro d'assertion peut être tout entier 0 ou supérieur, et peut être indéfini dans certains cas.

La méthode hide_buffered() doit retourner une valeur booléenne. Elle est utilisée pour indiquer aux sous-tests tamponnés s'il faut ou non leur envoyer des événements pendant qu'ils sont tamponnés. Voir "run_subtest(...)" dans Test2::API pour plus d'informations.

Les méthodes "terminate" et "finalize" sont des méthodes optionnelles appelées que vous pouvez implémenter si le format que vous générez nécessite de gérer ces cas, par exemple si vous générez du XML et que vous avez besoin de fermer des balises ouvertes.

La méthode "terminate" est appelée lorsque la méthode "terminate" d'un événement retourne vrai, par exemple lorsqu'un Test2::Event::Plan a un plan 'skip_all', ou lorsqu'un événement Test2::Event::Bail est envoyé. La méthode "terminate" reçoit un seul argument, l'objet Test2::Event qui a déclenché la fin.

La méthode "finalize" est toujours la dernière chose appelée sur le formateur, *sauf lorsque* "terminate" *est appelée pour un événement Bail*. Elle reçoit les arguments suivants :

La méthode "supports_tables" doit retourner vrai si le formateur prend en charge le rendu direct des données tabulaires à partir des facettes "info". Il s'agit d'une fonctionnalité plus récente et de nombreux formateurs plus anciens pourraient ne pas la prendre en charge. Lorsqu'elle n'est pas prise en charge, le formateur se rabat sur le rendu de "detail" au lieu des données "table".

La méthode "new_root" est utilisée lors de la construction d'un formateur racine. La valeur par défaut consiste simplement à déléguer à la méthode new() régulière, la plupart des formateurs peuvent l'ignorer.

  • Le nombre de tests qui étaient prévus
  • Le nombre de tests effectivement vus
  • Le nombre de tests qui ont échoué
  • Une valeur booléenne indiquant si la suite de tests a réussi ou non
  • Une valeur booléenne indiquant si cet appel concerne un sous-test ou non

La méthode "new_root" est appelée lorsque "Test2::API::Stack" initialise le hub racine pour la première fois. La plupart des formateurs feront simplement cet appel à "$class->new", ce qui est le comportement par défaut. Cependant, certains formateurs peuvent souhaiter prendre des mesures supplémentaires lors de la construction du formateur racine, c'est là qu'ils peuvent le faire.
