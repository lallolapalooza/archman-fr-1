Test2::Manual::Tooling::Testing(3perl) Guide de référence du programmeur Perl Test2::Manual::Tooling::Testing(3perl)

NOM

Test2::Manual::Tooling::Testing - Tutoriel sur la façon de tester vos outils de test.

DESCRIPTION

Tester vos outils de test était autrefois une perspective complexe et difficile. Les anciens outils tels que Test::Tester et Test::Builder::Tester étaient limités et fragiles. Test2, en revanche, a été conçu dès le départ pour être facilement testable ! Ce tutoriel vous montre comment.

LE SAINT GRAAL DU TEST DE VOS OUTILS

La clé pour rendre Test2 facilement testable (en particulier par rapport à Test::Builder) est la fonction "intercept".

use Test2::API qw/intercept/;
my $events = intercept {
    ok(1, "pass");
    ok(0, "fail");
    diag("A diag");
};

La fonction intercept vous permet d'utiliser les outils de test de votre choix à l'intérieur d'un bloc de code. Aucun événement ou contexte généré dans le bloc de code de l'intercept n'aura d'effet sur l'état de test extérieur. La fonction "intercept" isole complètement les outils appelés à l'intérieur.

Note: Les plugins et les éléments qui affectent l'état global de l'API peuvent ne pas être entièrement isolés. "intercept" est spécifiquement destiné à l'isolation des événements.

La fonction "intercept" retournera un tableau de référence contenant tous les événements générés dans le bloc de code. Vous pouvez maintenant faire toutes les assertions que vous souhaitez concernant les événements que vous attendiez de vos outils.

[
    bless({...}, 'Test2::Event::Ok'),   # pass
    bless({...}, 'Test2::Event::Ok'),   # fail
    bless({...}, 'Test2::Event::Diag'), # Diagnostics d'échec (pas toujours un deuxième événement)
    bless({...}, 'Test2::Event::Diag'), # message 'A diag' personnalisé
]

La plupart des outils de test produisent éventuellement un ou plusieurs événements. Pour vérifier efficacement les événements que vous obtenez de l'intercept, vous devriez vraiment vous familiariser avec le fonctionnement des événements Test2::Manual::Anatomy::Event. Une fois que vous connaissez les événements, vous pouvez passer à la section suivante qui vous indique des outils d'aide.

OUTILS D'AIDE SUPPLÉMENTAIRES

Test2::Tools::Tester

C'est l'ensemble d'outils le plus récent pour vous aider à tester vos événements. Pour vraiment comprendre ceux-ci, vous devriez vous familiariser avec Test2::Manual::Anatomy::Event. Si vous allez écrire quoi que ce soit de plus que des outils très simples, vous devez savoir comment les événements fonctionnent.

La documentation de Test2::Tools::Tester est un bon endroit pour lire davantage.

Test2::Tools::HarnessTester

Test2::Tools::HarnessTester peut exporter l'outil summarize_events(). Cet outil vous permet de faire passer votre tableau de référence d'événements dans Test2::Harness afin d'obtenir un résumé de réussite/échec.

my $summary = summarize_events($events);

Le résumé ressemble à ceci :

{
    plan       => $plan_facet,         # le facet d'événement plan
    pass       => $bool,               # vrai si les événements résultent en un succès
    fail       => $bool,               # vrai si les événements résultent en un échec
    errors     => $error_count,        # Nombre de facets d'erreur vus
    failures   => $failure_count,      # Nombre d'assertions échouées vues
    assertions => $assertion_count,    # Nombre total d'assertions vues
}

Test2::Tools::Compare

OBSOLÈTE Ces outils ont été écrits avant le passage aux événements facettés. Ils fonctionneront toujours, mais ne sont plus la méthode recommandée pour tester vos outils.

La bibliothèque Test2::Tools::Compare exporte une poignée d'extensions pour aider à tester les événements.

event $TYPE => ...
Utilisez dans une vérification de tableau par rapport à $events pour vérifier un type d'événement spécifique avec les propriétés que vous spécifiez.
fail_events $TYPE => ...
Utilisez lorsque vous attendez une assertion échouée de $TYPE. Cela vérifiera automatiquement que l'événement suivant est un message de diagnostic avec le texte d'échec par défaut.

Note: Ceci est obsolète car un seul événement peut désormais posséder à la fois l'assertion échouée ET le texte d'échec, de tels événements échoueront ce test.
