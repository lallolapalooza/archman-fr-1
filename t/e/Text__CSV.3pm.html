NOM

Text::CSV - manipulateur de valeurs séparées par des virgules (utilisant XS ou PurePerl)

SYNOPIS

Cette section est tirée de Text::CSV_XS.

# Interface fonctionnelle
use Text::CSV qw( csv );
# Lire tout le fichier en mémoire
my $aoa = csv (in => "data.csv");    # en tableau de tableaux
my $aoh = csv (in => "data.csv",
               headers => "auto");   # en tableau d'hashes
# Écrire un tableau de tableaux dans un fichier csv
csv (in => $aoa, out => "file.csv", sep_char => ";");
# Afficher uniquement les lignes où "code" est impair
csv (in => "data.csv", filter => { code => sub { $_ % 2 }});
# Interface objet
use Text::CSV;
my @rows;
# Lire/analyser le CSV
my $csv = Text::CSV->new ({ binary => 1, auto_diag => 1 });
open my $fh, "<:encoding(utf8)", "test.csv" or die "test.csv: $!";
while (my $row = $csv->getline ($fh)) {
    $row->[2] =~ m/pattern/ or next; # le 3ème champ doit correspondre
    push @rows, $row;
    }
close $fh;
# et écrire en CSV
open $fh, ">:encoding(utf8)", "new.csv" or die "new.csv: $!";
$csv->say ($fh, $_) for @rows;
close $fh or die "new.csv: $!";

DESCRIPTION

Text::CSV est un mince wrapper pour les modules compatibles Text::CSV_XS maintenant. Tous les modules backend fournissent des installations pour la composition et la décomposition de valeurs séparées par des virgules. Text::CSV utilise Text::CSV_XS par défaut, et lorsque Text::CSV_XS n'est pas disponible, il se rabat sur Text::CSV_PP, qui est inclus dans la même distribution que ce module.

CHOIX DU BACKEND

Ce module respecte une variable d'environnement appelée "PERL_TEXT_CSV" lorsqu'il décide du module backend à utiliser. Si cette variable d'environnement n'est pas définie, il tente de charger Text::CSV_XS, et si Text::CSV_XS n'est pas disponible, il se rabat sur Text::CSV_PP;

Si vous ne voulez jamais qu'il se rabatte sur Text::CSV_PP, définissez la variable comme suit ("export" peut être "setenv", "set" et similaire, selon votre environnement):

> export PERL_TEXT_CSV=Text::CSV_XS

Si vous préférez Text::CSV_XS à Text::CSV_PP (par défaut), alors:

> export PERL_TEXT_CSV=Text::CSV_XS,Text::CSV_PP

Vous voudrez peut-être aussi définir cette variable en haut de vos fichiers de test, afin de ne pas être dérangé par les incompatibilités entre backends (vous devez envelopper cela dans "BEGIN", et définir avant d'"use"-r Text::CSV, car il décide de son backend dès qu'il est chargé):

BEGIN { $ENV{PERL_TEXT_CSV}='Text::CSV_PP'; }
use Text::CSV;

Nouvelles lignes incorporées

Note importante : Le comportement par défaut est d'accepter uniquement les caractères ASCII dans la plage de 0x20 (espace) à 0x7E (tilde). Cela signifie que les champs ne peuvent pas contenir de nouvelles lignes. Si vos données contiennent des nouvelles lignes incorporées dans les champs, ou des caractères supérieurs à 0x7E (tilde), ou des données binaires, vous devez définir "binary => 1" lors de l'appel à "new". Pour couvrir la plus large gamme d'options d'analyse, vous voudrez toujours définir `binary`.

Mais vous avez toujours le problème que vous devez passer une ligne correcte à la méthode "parse", ce qui est plus compliqué que le point d'utilisation habituel:

my $csv = Text::CSV->new ({ binary => 1, eol => $/ });
while (<>) {           #  FAUX!
    $csv->parse ($_);
    my @fields = $csv->fields ();
    }

cela échouera, car la boucle "while" peut lire des lignes cassées : elle ne se soucie pas du guillemet. Si vous avez besoin de prendre en charge les nouvelles lignes incorporées, la bonne approche est de **ne pas** passer "eol" dans l'analyseur (il accepte "\n", "\r", **et** "\r\n" par défaut) et ensuite

my $csv = Text::CSV->new ({ binary => 1 });
open my $fh, "<", $file or die "$file: $!";
while (my $row = $csv->getline ($fh)) {
    my @fields = @$row;
    }

L'ancienne méthode utilisant des poignées de fichier globales est toujours prise en charge

while (my $row = $csv->getline (*ARGV)) { ... }

Unicode

Unicode n'est testé que pour fonctionner avec perl-5.8.2 et versions ultérieures.

Voir aussi "BOM".

La manière la plus simple de s'assurer que le bon encodage est utilisé pour les entrées et sorties est de définir des couches sur les poignées de fichier, ou de définir l'argument "encoding" pour "csv".

 open my $fh, "<:encoding(UTF-8)", "in.csv"  or die "in.csv: $!";
ou
 my $aoa = csv (in => "in.csv",     encoding => "UTF-8");
 open my $fh, ">:encoding(UTF-8)", "out.csv" or die "out.csv: $!";
ou
 csv (in => $aoa, out => "out.csv", encoding => "UTF-8");

Lors de l'analyse (pour "getline" et "parse"), si la source est marquée comme UTF8, alors tous les champs marqués comme binaires seront également marqués comme UTF8.

Lors de la combinaison ("print" et "combine"): si l'un des champs combinés était marqué comme UTF8, la chaîne résultante sera marquée comme UTF8. Notez cependant que tous les champs *avant* le premier champ marqué comme UTF8 et contenant des caractères 8 bits qui n'ont pas été mis à niveau vers UTF8, ceux-ci seront également des "octets" dans la chaîne résultante, causant potentiellement des erreurs inattendues. Si vous passez des données d'encodage différent, ou si vous ne savez pas s'il y a un encodage différent, forcez sa mise à niveau avant de les transmettre:

$csv->print ($fh, [ map { utf8::upgrade (my $x = $_); $x } @data ]);

Pour un contrôle complet de l'encodage, veuillez utiliser Text::CSV::Encoded:

use Text::CSV::Encoded;
my $csv = Text::CSV::Encoded->new ({
    encoding_in  => "iso-8859-1", # l'encodage arrive dans Perl
    encoding_out => "cp1252",     # l'encodage sort de Perl
    });
$csv = Text::CSV::Encoded->new ({ encoding  => "utf8" });
# combine () et print () acceptent des données encodées *littéralement* en utf8
# parse () et getline () retournent des données encodées *littéralement* en utf8
$csv = Text::CSV::Encoded->new ({ encoding  => undef }); # par défaut
# combine () et print () acceptent des données marquées UTF8
# parse () et getline () retournent des données marquées UTF8

BOM

La gestion du BOM (ou Byte Order Mark) n'est disponible qu'à l'intérieur de la méthode "header". Cette méthode prend en charge les encodages suivants : "utf-8", "utf-1", "utf-32be", "utf-32le", "utf-16be", "utf-16le", "utf-ebcdic", "scsu", "bocu-1", et "gb-18030". Voir Wikipedia https://en.wikipedia.org/wiki/Byte_order_mark.

Si un fichier a un BOM, le moyen le plus simple de le gérer est

my $aoh = csv (in => $file, detect_bom => 1);

Tous les enregistrements seront encodés en fonction du BOM détecté.

Cela implique un appel à la méthode "header", qui par défaut définit également les "column_names". Ce n'est donc **pas** la même chose que

my $aoh = csv (in => $file, headers => "auto");

qui ne lit que le premier enregistrement pour définir les "column_names" mais ignore toute signification d'un BOM potentiellement présent.

new

Les attributs suivants sont disponibles :

eol

my $csv = Text::CSV->new ({ eol => $/ });
          $csv->eol (undef);
my $eol = $csv->eol;

La chaîne de fin de ligne à ajouter aux lignes pour "print" ou le séparateur d'enregistrement pour "getline".

Lorsqu'il n'est pas passé dans une instance parser, le comportement par défaut est d'accepter "\n", "\r" et "\r\n", il est donc probablement plus sûr de ne pas spécifier "eol" du tout. Passer "undef" ou la chaîne vide se comporte de la même manière.

Lorsqu'il n'est pas passé dans une instance generating, les lignes ne sont pas terminées du tout, il est donc probable qu'il soit utile de passer quelque chose qui est attendu. Une option sûre pour "eol" en sortie est soit "$/", soit "\r\n".

Les valeurs courantes pour "eol" sont "\012" ("\n" ou Line Feed), "\015\012" ("\r\n" ou Carriage Return, Line Feed), et "\015" ("\r" ou Carriage Return). L'attribut "eol" ne peut pas dépasser 7 caractères (ASCII).

Si à la fois "$/" et "eol" sont "\015", le parsing des lignes se terminant uniquement par un Carriage Return sans Line Feed sera considéré comme correct.

eol_type

my $eol = $csv->eol_type;

Cette méthode en lecture seule renvoie l'état interne de ce qui est considéré comme la fin de ligne valide pour le parsing.

sep_char

my $csv = Text::CSV->new ({ sep_char => ";" });
        $csv->sep_char (";");
my $c = $csv->sep_char;

Le caractère utilisé pour séparer les champs, par défaut une virgule (","). Limité à un seul caractère, généralement dans la plage de "0x20" (espace) à "0x7E" (tilde). Lorsque des séquences plus longues sont nécessaires, utilisez "sep".

Le caractère de séparation ne peut pas être égal au caractère de citation ou au caractère d'échappement.

sep

my $csv = Text::CSV->new ({ sep => "\N{FULLWIDTH COMMA}" });
          $csv->sep (";");
my $sep = $csv->sep;

Les caractères utilisés pour séparer les champs, par défaut indéfini. Limité à 8 octets.

Lorsqu'il est défini, remplace "sep_char". Si sa longueur est d'un octet, il agit comme un alias vers "sep_char".

quote_char

my $csv = Text::CSV->new ({ quote_char => "'" });
        $csv->quote_char (undef);
my $c = $csv->quote_char;

Le caractère à utiliser pour citer les champs contenant des espaces ou des données binaires, par défaut le caractère de citation ("""). Une valeur de undef supprime les citations (uniquement pour les cas simples). Limité à un seul caractère, généralement dans la plage de "0x20" (espace) à "0x7E" (tilde). Lorsque des séquences plus longues sont nécessaires, utilisez "quote".

"quote_char" ne peut pas être égal à "sep_char".

quote

my $csv = Text::CSV->new ({ quote => "\N{FULLWIDTH QUOTATION MARK}" });
            $csv->quote ("'");
my $quote = $csv->quote;

Les caractères utilisés pour citer les champs, par défaut indéfini. Limité à 8 octets.

Lorsqu'il est défini, remplace "quote_char". Si sa longueur est d'un octet, il agit comme un alias vers "quote_char".

Cette méthode ne supporte pas "undef". Utilisez "quote_char" pour désactiver la citation.

escape_char

my $csv = Text::CSV->new ({ escape_char => "\\" });
        $csv->escape_char (":");
my $c = $csv->escape_char;

Le caractère à utiliser pour échapper certains caractères dans les champs cités. Ceci est limité à un seul caractère, généralement dans la plage de "0x20" (espace) à "0x7E" (tilde).

Le "escape_char" par défaut est le caractère de citation ("""). Autrement dit, le même que le "quote_char" par défaut. Cela signifie que doubler le caractère de citation dans un champ l'échappe :

"foo","bar","Escape ""quote mark"" with two ""quote marks""","baz"

Si vous modifiez "quote_char" sans modifier "escape_char", "escape_char" restera le caractère de citation ("""). Si vous souhaitez échapper le caractère de citation en le doublant, vous devrez également modifier "escape_char" pour qu'il corresponde à ce que vous avez modifié "quote_char" en.

Même si "escape_char" est "undef" ou "", il sera complètement désactivé et cela est fortement recommandé. Cela désactivera également "escape_null".

Le caractère d'échappement ne peut pas être égal au caractère de séparation.

binary

my $csv = Text::CSV->new ({ binary => 1 });
        $csv->binary (0);
my $f = $csv->binary;

Si cet attribut est 1, vous pouvez utiliser des caractères binaires dans les champs cités, y compris les sauts de ligne, les retours chariot et les octets "NULL". (Ce dernier peut être échappé comme ""0".) Par défaut, cette fonctionnalité est désactivée.

Si une chaîne est marquée comme UTF8, "binary" sera automatiquement activé lorsque des caractères binaires autres que "CR" ou "NL" seront rencontrés. Notez qu'une chaîne simple comme "\x{00a0}" peut encore être binaire, mais pas marquée comme UTF8, donc définir "{ binary => 1 }" est toujours une bonne idée.

strict

my $csv = Text::CSV->new ({ strict => 1 });
        $csv->strict (0);
my $f = $csv->strict;

Si cet attribut est 1, toute ligne qui produit un nombre différent de champs par rapport à la ligne précédente provoquera une erreur 2014 du parseur.

Les lignes vides ou les lignes qui ne résultent en aucun champ (comme les lignes de commentaires) sont exemptées de ces vérifications.

strict_eol

my $csv = Text::CSV->new ({ strict_eol => 1 });
        $csv->strict_eol (0);
my $f = $csv->strict_eol;

Si cet attribut est 0, aucun contrôle de cohérence EOL n'est effectué.

Si cet attribut est 1, toute ligne analysée avec un EOL différent de l'EOL de la première ligne provoquera un avertissement. L'erreur sera ignorée et le parsing continuera. Cet avertissement n'est émis qu'une seule fois. Notez que dans les données avec des fins de ligne multiples, "\r\r" provoquera toujours une erreur qui ne peut être ignorée.

Si cet attribut est 2 ou plus, toute ligne analysée avec un EOL différent de l'EOL de la première ligne provoquera l'erreur 2016. La ligne en cours d'analyse à cette erreur peut ne pas être stockée dans le résultat.

skip_empty_rows

my $csv = Text::CSV->new ({ skip_empty_rows => 1 });
        $csv->skip_empty_rows ("eof");
my $f = $csv->skip_empty_rows;

Cet attribut définit le comportement pour les lignes vides : un "eol" immédiatement après le début de la ligne. Le comportement par défaut est de renvoyer un seul champ vide.

Cet attribut n'est utilisé qu'en parsing. Il est inefficace lorsqu'il est utilisé avec "parse" et "fields".

Les valeurs possibles pour cet attribut sont :

0 | undef
my $csv = Text::CSV->new ({ skip_empty_rows => 0 });
$csv->skip_empty_rows (undef);

Aucune action spéciale n'est effectuée. Le résultat sera un seul champ vide.

1 | "skip"
my $csv = Text::CSV->new ({ skip_empty_rows => 1 });
$csv->skip_empty_rows ("skip");

La ligne sera ignorée.

2 | "eof" | "stop"
my $csv = Text::CSV->new ({ skip_empty_rows => 2 });
$csv->skip_empty_rows ("eof");

Le parsing s'arrêtera comme s'il avait détecté "eof".

3 | "die"
my $csv = Text::CSV->new ({ skip_empty_rows => 3 });
$csv->skip_empty_rows ("die");

Le parsing s'arrêtera. Le code d'erreur interne sera défini sur 2015 et le parseur s'arrêtera avec "die".

4 | "croak"
my $csv = Text::CSV->new ({ skip_empty_rows => 4 });
$csv->skip_empty_rows ("croak");

Le parsing s'arrêtera. Le code d'erreur interne sera défini sur 2015 et le parseur s'arrêtera avec "croak".

5 | "error"
my $csv = Text::CSV->new ({ skip_empty_rows => 5 });
$csv->skip_empty_rows ("error");

Le parsing échouera. Le code d'erreur interne sera défini sur 2015.

callback
my $csv = Text::CSV->new ({ skip_empty_rows => sub { [] } });
$csv->skip_empty_rows (sub { [ 42, $., undef, "empty" ] });

La callback est appelée et son résultat est utilisé à la place. Si vous souhaitez que le parsing s'arrête après la callback, assurez-vous de renvoyer une valeur fausse.

La valeur renvoyée par la callback doit être une référence de tableau. Tout autre type entraînera l'arrêt du parsing, ces types sont donc équivalents en comportement :

csv (in => $fh, skip_empty_rows => "stop");
csv (in => $fh. skip_empty_rows => sub { 0; });
e>

Sans arguments, la valeur actuelle est retournée : 0, 1, "eof", "die", "croak" ou la fonction de rappel.

formula_handling

Alias pour « formula »

formula

my $csv = Text::CSV->new ({ formula => "none" });
        $csv->formula ("none");
my $f = $csv->formula;

Ceci définit le comportement des champs contenant des formules. Comme les formules sont considérées comme dangereuses dans les tableurs, cet attribut peut définir une action optionnelle à entreprendre si un champ commence par un signe égal ("=").

Pour des raisons de lisibilité du code, cela peut aussi s'écrire :

my $csv = Text::CSV->new ({ formula_handling => "none" });
        $csv->formula_handling ("none");
my $f = $csv->formula_handling;

Les valeurs possibles pour cet attribut sont :

none
Aucune action spécifique. C'est la valeur par défaut. 
$csv->formula ("none");
die
Faire en sorte que le processus "die" chaque fois qu'un signe égal ("=") en début de champ est rencontré. 
$csv->formula ("die");
croak
Faire en sorte que le processus "croak" chaque fois qu'un signe égal ("=") en début de champ est rencontré. (Voir Carp) 
$csv->formula ("croak");
diag
Signaler la position et le contenu du champ chaque fois qu'un signe égal ("=") en début de champ est trouvé. La valeur du champ reste inchangée. 
$csv->formula ("diag");
empty
Remplacer le contenu des champs qui commencent par un signe égal ("=") par la chaîne vide. 
$csv->formula ("empty");
$csv->formula ("");
undef
Remplacer le contenu des champs qui commencent par un signe égal ("=") par "undef". 
$csv->formula ("undef");
$csv->formula (undef);
a callback
Modifier le contenu des champs qui commencent par un signe égal ("=") avec la valeur de retour du rappel. Le contenu original du champ est disponible dans le rappel sous $_ ; 
# Remplacer toutes les formules par 42
$csv->formula (sub { 42; });
# idem que $csv->formula ("empty") mais plus lent
$csv->formula (sub { "" });
# Autoriser =4+12
$csv->formula (sub { s/^=(\d+\+\d+)$/$1/eer });
# Autoriser des calculs plus complexes
$csv->formula (sub { eval { s{^=([-+*/0-9()]+)$}{$1}ee }; $_ });

Toutes les autres valeurs généreront un avertissement puis se rabattront sur "diag".

decode_utf8

my $csv = Text::CSV->new ({ decode_utf8 => 1 });
        $csv->decode_utf8 (0);
my $f = $csv->decode_utf8;

Cet attribut est vrai par défaut.

Lors de l'analyse, les champs qui sont en UTF-8 valide sont automatiquement définis comme étant en UTF-8, de sorte que

$csv->parse ("\xC4\xA8\n");

résulte en

PV("\304\250"\0) [UTF8 "\x{128}"]

Parfois, cela peut ne pas être une action souhaitée. Pour éviter ces mises à niveau, définissez cet attribut à faux, et le résultat sera

PV("\304\250"\0)

auto_diag

my $csv = Text::CSV->new ({ auto_diag => 1 });
        $csv->auto_diag (2);
my $l = $csv->auto_diag;

Définir cet attribut à un nombre entre 1 et 9 provoque l'appel automatique de "error_diag" dans un contexte vide en cas d'erreurs.

En cas d'erreur "2012 - EOF", cet appel sera vide.

Si "auto_diag" est défini à une valeur numérique supérieure à 1, il fera "die" en cas d'erreurs au lieu de "warn". Si défini à quelque chose d'inconnu, il sera ignoré silencieusement.

Les futures extensions de cette fonctionnalité incluront une détection plus fiable de la présence de "autodie" dans le contexte où l'erreur s'est produite, ce qui incrémentera la valeur de "auto_diag" de 1 au moment où l'erreur est détectée.

diag_verbose

my $csv = Text::CSV->new ({ diag_verbose => 1 });
        $csv->diag_verbose (2);
my $l = $csv->diag_verbose;

Définit la verbosité de la sortie déclenchée par "auto_diag". Actuellement, cela ajoute seulement le numéro d'enregistrement d'entrée courant (si connu) à la sortie diagnostique avec une indication de la position de l'erreur.

blank_is_undef

my $csv = Text::CSV->new ({ blank_is_undef => 1 });
        $csv->blank_is_undef (0);
my $f = $csv->blank_is_undef;

Dans des circonstances normales, les données "CSV" ne font pas de distinction entre les champs vides entre guillemets et ceux sans guillemets. Les deux se retrouvent dans un champ de chaîne vide une fois lus, donc

1,"",," ",2

est lu comme

("1", "", "", " ", "2")

Lors de l'écriture de fichiers "CSV" avec "always_quote" ou "quote_empty" activé, le champ vide sans guillemets est le résultat d'une valeur indéfinie. Pour activer cette distinction lors de la lecture de données "CSV", l'attribut "blank_is_undef" fera en sorte que les champs vides sans guillemets soient définis à "undef", ce qui fait que ce qui précède est analysé comme

("1", "", undef, " ", "2")

Notez que ceci est particulièrement important lors du chargement de champs "CSV" dans une base de données qui autorise les valeurs "NULL", car l'équivalent perl pour "NULL" est "undef" dans le monde DBI.

empty_is_undef

my $csv = Text::CSV->new ({ empty_is_undef => 1 });
        $csv->empty_is_undef (0);
my $f = $csv->empty_is_undef;

Allant un peu plus loin que "blank_is_undef", cet attribut convertit tous les champs vides en "undef", donc

1,"",," ",2

est lu comme

(1, undef, undef, " ", 2)

Notez que cela n'affecte que les champs qui sont initialement vides, pas les champs qui sont vides après suppression des espaces autorisés. Vos résultats peuvent varier.

allow_whitespace

my $csv = Text::CSV->new ({ allow_whitespace => 1 });
        $csv->allow_whitespace (0);
my $f = $csv->allow_whitespace;

Lorsque cette option est définie à vrai, les espaces ("TAB" et "ESPACE") entourant le caractère de séparation sont supprimés lors de l'analyse. Si "TAB" ou "ESPACE" est l'un des trois caractères "sep_char", "quote_char", ou "escape_char", il ne sera pas considéré comme un espace.

Maintenant, des lignes comme :

1 , "foo" , bar , 3 , zapp

sont analysées comme du "CSV" valide, même si cela viole les spécifications "CSV".

Notez que **tous** les espaces sont supprimés du début et de la fin de chaque champ. Cela en ferait plus qu'une *fonctionnalité* pour permettre l'analyse de lignes "CSV" incorrectes, car

1,   2.0,  3,   ape  , monkey

sera maintenant analysé comme

("1", "2.0", "3", "ape", "monkey")

même si la ligne originale était du "CSV" parfaitement acceptable.

allow_loose_quotes

my $csv = Text::CSV->new ({ allow_loose_quotes => 1 });
        $csv->allow_loose_quotes (0);
my $f = $csv->allow_loose_quotes;

Par défaut, l'analyse de champs non quotés contenant des caractères de "quote_char" comme

1,foo "bar" baz,42

entraînerait une erreur d'analyse 2034. Bien qu'il soit toujours déconseillé d'autoriser ce format, nous ne pouvons rien faire au fait que certains fournisseurs font que leurs applications produisent des lignes de ce style.

S'il y a des données "CSV" **vraiment** incorrectes, comme

1,"foo "bar" baz",42

ou

1,""foo bar baz"",42

il existe un moyen d'analyser ces données et de laisser les guillemets à l'intérieur du champ quoté tels quels. Cela peut être réalisé en définissant "allow_loose_quotes" **ET** en s'assurant que l'"escape_char" n'est **pas** égal au "quote_char".

allow_loose_escapes

my $csv = Text::CSV->new ({ allow_loose_escapes => 1 });
        $csv->allow_loose_escapes (0);
my $f = $csv->allow_loose_escapes;

L'analyse de champs qui contiennent des caractères "escape_char" qui échappent des caractères qui n'ont pas besoin d'être échappés, comme :

my $csv = Text::CSV->new ({ escape_char => "\\" });
$csv->parse (qq{1,"my bar\'s",baz,42});

Cet attribut est utile lors de l'exportation de données CSV à importer dans des chargeurs personnalisés, comme pour MySQL, qui reconnaissent des séquences spéciales pour les données "NULL".

Cet attribut définit optionnellement une chaîne à reconnaître comme commentaire. Si cet attribut est défini, toutes les lignes commençant par cette séquence ne seront pas analysées comme CSV mais ignorées comme commentaire.

Cet attribut n'a aucune signification lors de la génération de CSV.

Les chaînes de commentaires commençant par l'un des caractères/séquences spéciaux ne sont pas prises en charge (donc elles ne peuvent pas commencer par "sep_char", "quote_char", "escape_char", "sep", "quote", ou "eol").

verbatim

my $csv = Text::CSV->new ({ verbatim => 1 });
        $csv->verbatim (0);
my $f = $csv->verbatim;

C'est un attribut assez controversé à définir, mais il rend certaines choses difficiles possibles.

La raison d'être de cet attribut est d'indiquer à l'analyseur que les caractères normalement spéciaux de nouvelle ligne ("NL") et de retour chariot ("CR") ne seront pas spéciaux lorsque ce flag est activé, et seront traités comme des caractères binaires ordinaires. Cela facilitera le travail avec des données contenant des nouvelles lignes intégrées.

Lorsque "verbatim" est utilisé avec "getline", "getline" "chomp" chaque ligne.

Imaginez un format de fichier comme

M^^Hans^Janssen^Klas 2\n2A^Ja^11-06-2007#\r\n

où la fin de ligne est une séquence très spécifique "#\r\n", et le séparateur est un "^" (caret). Aucun champ n'est cité, mais des données binaires intégrées sont susceptibles d'être présentes. Avec la fin de ligne spécifique, cela ne devrait pas être trop difficile à détecter.

Par défaut, la fonction parse de Text::CSV est configurée pour ne reconnaître que "\n" et "\r" comme fins de ligne légales, et doit donc traiter la nouvelle ligne intégrée comme une véritable "fin de ligne", afin de pouvoir scanner la ligne suivante si binaire est vrai, et si la nouvelle ligne est à l'intérieur d'un champ cité. Avec cette option, nous indiquons à "parse" de traiter la ligne comme si "\n" n'était rien de plus qu'un caractère binaire.

Pour "parse", cela signifie que l'analyseur n'a plus idée de la fin de ligne et que "getline" "chomp" les fins de ligne à la lecture.

API

bind_columns

$csv->bind_columns (\$code, \$name, \$price, \$description);

This method is used to bind a list of scalar references to the columns of the CSV file. When getline reads a line, the fields of that line are assigned to the scalar references in the order they appear in the list.

If the number of fields in the line is less than the number of bound references, the remaining references are left untouched. If the number of fields is greater than the number of references, the remaining fields are ignored.

The following example demonstrates how to use bind_columns to read and print the price of items from a CSV file:

$csv->bind_columns (\$code, \$name, \$price, \$description);
while ($csv->getline ($fh)) {
    print "The price of a $name is \x{20ac} $price\n";
    }

To reset or clear all column bindings, call bind_columns with the single argument "undef". This will also clear column names.

$csv->bind_columns (undef);

If no arguments are passed at all, bind_columns will return the list of current bindings or "undef" if no binds are active.

Note that in parsing with "bind_columns", the fields are set on the fly. That implies that if the third field of a row causes an error (or this row has just two fields where the previous row had more), the first two fields already have been assigned the values of the current row, while the rest of the fields will still hold the values of the previous row. If you want the parser to fail in these cases, use the "strict" attribute.

eof

$eof = $csv->eof ();

If parse or getline was used with an IO stream, this method will return true (1) if the last call hit end of file, otherwise it will return false (''). This is useful to see the difference between a failure and end of file.

Note that if the parsing of the last line caused an error, eof is still true. That means that if you are not using auto_diag, an idiom like

while (my $row = $csv->getline ($fh)) {
    # ...
    }
$csv->eof or $csv->error_diag;

will not report the error. You would have to change that to

while (my $row = $csv->getline ($fh)) {
    # ...
    }
+$csv->error_diag and $csv->error_diag;

meta_info

@flags = $csv->meta_info ();

This method returns the "flags" of the input to combine or the flags of the resultant decomposed fields of parse, whichever was called more recently.

For each field, a meta_info field will hold flags that inform something about the field returned by the fields method or passed to the combine method. The flags are bit-wise-"or"'d like:

0x0001
"CSV_FLAGS_IS_QUOTED"
The field was quoted.
0x0002
"CSV_FLAGS_IS_BINARY"
The field was binary.
0x0004
"CSV_FLAGS_ERROR_IN_FIELD"
The field was invalid.

Currently only used when "allow_loose_quotes" is active.

0x0010
"CSV_FLAGS_IS_MISSING"
The field was missing.

See the "is_***" methods below.

is_quoted

my $quoted = $csv->is_quoted ($column_idx);

where $column_idx is the (zero-based) index of the column in the last result of parse.

This returns a true value if the data in the indicated column was enclosed in "quote_char" quotes. This might be important for fields where content ",20070108," is to be treated as a numeric value, and where ","20070108"," is explicitly marked as character string data.

This method is only valid when keep_meta_info is set to a true value.

is_binary

my $binary = $csv->is_binary ($column_idx);

where $column_idx is the (zero-based) index of the column in the last result of parse.

This returns a true value if the data in the indicated column contained any byte in the range "[\x00-\x08,\x10-\x1F,\x7F-\xFF]".

This method is only valid when keep_meta_info is set to a true value.

is_missing

my $missing = $csv->is_missing ($column_idx);

where $column_idx is the (zero-based) index of the column in the last result of getline_hr.

$csv->keep_meta_info (1);
while (my $hr = $csv->getline_hr ($fh)) {
    $csv->is_missing (0) and next; # This was an empty line
    }

When using getline_hr, it is impossible to tell if the parsed fields are "undef" because they where not filled in the "CSV" stream or because they were not read at all, as all the fields defined by column_names are set in the hash-ref. If you still need to know if all fields in each row are provided, you should enable keep_meta_info so you can check the flags.

If "keep_meta_info" is "false", is_missing will always return "undef", regardless of $column_idx being valid or not. If this attribute is "true" it will return either 0 (the field is present) or 1 (the field is missing).

A special case is the empty line. If the line is completely empty - after dealing with the flags - this is still a valid CSV line: it is a record of just one single empty field. However, if "keep_meta_info" is set, invoking "is_missing" with index 0 will now return true.

$bad_argument = $csv->error_input ();

This method returns the erroneous argument (if it exists) of combine or parse, whichever was called more recently. If the last invocation was successful, error_input will return "undef".

Depending on the type of error, it might also hold the data for the last error-input of getline.

error_diag

Text::CSV->error_diag ();
$csv->error_diag ();
$error_code               = 0  + $csv->error_diag ();
$error_str                = "" . $csv->error_diag ();
($cde, $str, $pos, $rec, $fld, $xs) = $csv->error_diag ();

If (and only if) an error occurred, this function returns the diagnostics of that error.

If called in void context, this will print the internal error code and the associated error message to STDERR.

If called in list context, this will return the error code and the error message in that order. If the last error was from parsing, the rest of the values returned are a best guess at the location within the line that was being parsed. Their values are 1-based. The position currently is index of the byte at which the parsing failed in the current record. It might change to be the index of the current character in a later release. The records is the index of the record parsed by the csv instance. The field number is the index of the field the parser thinks it is currently trying to parse. See examples/csv-check for how this can be used. If $xs is set, it is the line number in XS where the error was triggered (for debugging). "XS" will show in void context only when diag_verbose is set.

If called in scalar context, it will return the diagnostics in a single scalar, a-la $!

. Il contiendra le code d'erreur dans un contexte numérique, et le message de diagnostic dans un contexte de chaîne de caractères.

Lorsqu'elle est appelée en tant que méthode de classe ou appel de fonction directe, les diagnostics sont ceux du dernier appel « new ».

_cache_diag

Note : Il s'agit d'une fonction interne uniquement, et la sortie ne peut pas être garantie. Utilisez à vos risques et périls.

Si vous avez besoin de déboguer au-delà de ce que « error_diag » peut montrer, le cache interne peut être affiché avec cette fonction.

# Quelque chose a échoué...
$csv->error_diag;
$csv->_cache_diag ();

record_number

$recno = $csv->record_number ();

FONCTIONS

csv

Cette fonction n'est pas exportée par défaut et doit être explicitement demandée :

use Text::CSV qw( csv );

Il s'agit d'une fonction de haut niveau qui vise des interfaces simples (utilisateurs). Elle peut être utilisée pour lire/analyser un fichier ou un flux « CSV » (comportement par défaut) ou pour produire un fichier ou écrire dans un flux (définir l'attribut « out »). Elle retourne une référence de tableau ou de hachage lors de l'analyse (ou « undef » en cas d'échec) ou la valeur numérique de « error_diag » lors de l'écriture. Lorsque cette fonction échoue, vous pouvez obtenir l'erreur en appelant la classe « error_diag »

my $aoa = csv (in => "test.csv") or
    die Text::CSV->error_diag;

Notez que l'échec ici est l'incapacité de démarrer l'analyseur, par exemple lorsque l'entrée n'existe pas ou que les arguments sont inconnus ou contradictoires. Les erreurs d'analyse à l'exécution retourneront une référence valide, qui peut être vide, mais contiendra tous les résultats jusqu'à l'erreur. Voir « on_error ».

Cette fonction prend les arguments sous forme de paires clé-valeur. Cela peut être passé sous forme de liste ou sous forme de hachage anonyme :

my $aoa = csv (  in => "test.csv", sep_char => ";");
my $aoh = csv ({ in => $fh, headers => "auto" });

Les arguments passés se composent de deux parties : les arguments de « csv » lui-même et les attributs optionnels de l'objet « CSV » utilisé à l'intérieur de la fonction, tels qu'énumérés et expliqués dans « new ».

Si elles ne sont pas remplacées, les options par défaut utilisées pour CSV sont

auto_diag   => 1
escape_null => 0
strict_eol  => 1

L'option qui est toujours définie et ne peut pas être modifiée est

binary      => 1

Comme cette fonction sera probablement utilisée dans des one-liners, elle permet à « quote » d'être abrégé en « quo », et à « escape_char » d'être abrégé en « esc » ou « escape ».

Appels alternatifs :

my $aoa = Text::CSV::csv (in => "file.csv");
my $csv = Text::CSV->new ();
my $aoa = $csv->csv (in => "file.csv");

Dans ce dernier cas, les attributs de l'objet sont utilisés à partir de l'objet existant et les arguments d'attribut dans l'appel de fonction sont ignorés :

my $csv = Text::CSV->new ({ sep_char => ";" });
my $aoh = $csv->csv (in => "file.csv", bom => 1);

analysera en utilisant « ; » comme « sep_char », et non « , ».

in

Utilisé pour spécifier la source. « in » peut être un nom de fichier (par exemple « file.csv »), qui sera ouvert en lecture et fermé une fois terminé, un descripteur de fichier (par exemple $fh ou « FH »), une référence à un glob (par exemple « \*ARGV »), le glob lui-même (par exemple *STDIN), ou une référence à une chaîne de caractères (par exemple « \q{1,2,"csv"} »).

Lorsqu'il est utilisé avec « out », « in » doit être une référence à une structure CSV (AoA ou AoH) ou une référence CODE qui retourne une référence de tableau ou une référence de hachage. La référence CODE sera appelée sans arguments.

my $aoa = csv (in => "file.csv");
open my $fh, "<", "file.csv";
my $aoa = csv (in => $fh);
my $csv = [ [qw( Foo Bar )], [ 1, 2 ], [ 2, 3 ]];
my $err = csv (in => $csv, out => "file.csv");

Si appelé dans un contexte nul sans l'attribut « out », la référence résultante sera utilisée comme entrée pour un appel ultérieur à csv :

csv (in => "file.csv", filter => { 2 => sub { length > 2 }})

sera un raccourci pour

csv (in => csv (in => "file.csv", filter => { 2 => sub { length > 2 }}))

où, en l'absence de l'attribut « out », ceci est un raccourci pour

csv (in  => csv (in => "file.csv", filter => { 2 => sub { length > 2 }}),
     out => *STDOUT)

out

csv (in => $aoa,  out => "file.csv");
csv (in => $aoa,  out => $fh);
csv (in => $aoa,  out =>   STDOUT);
csv (in => $aoa,  out =>  *STDOUT);
csv (in => $aoa,  out => \*STDOUT);
csv (in => $aoa,  out => \my $data);
csv (in => $aoa,  out =>  undef);
csv (in => $aoa,  out => \"skip");
csv (in => $fh,   out => \@aoa);
csv (in => $fh,   out => \@aoh, bom => 1);
csv (in => $fh,   out => \%hsh, key => "key");
csv (in => $file, out => $file);
csv (in => $file, out => $fh);
csv (in => $fh,   out => $file);
csv (in => $fh,   out => $fh);

En mode sortie, les options CSV par défaut lors de la production de CSV sont

eol       => "\r\n"

L'attribut « fragment » est ignoré en mode sortie.

« out » peut être un nom de fichier (par exemple « file.csv »), qui sera ouvert en écriture et fermé une fois terminé, un descripteur de fichier (par exemple $fh ou « FH »), une référence à un glob (par exemple « \*STDOUT »), le glob lui-même (par exemple *STDOUT), ou une référence à une chaîne de caractères (par exemple « \my $data »).

csv (in => sub { $sth->fetch },            out => "dump.csv");
csv (in => sub { $sth->fetchrow_hashref }, out => "dump.csv",
     headers => $sth->{NAME_lc});

Lorsqu'une référence CODE est utilisée pour « in », la sortie est générée par invocation, donc aucune mise en mémoire tampon n'est impliquée. Cela implique qu'il n'y a pas de restriction de taille sur le nombre d'enregistrements. La fonction « csv » se termine lorsque la référence CODE retourne une valeur fausse.

Si « out » est défini sur une référence vers la chaîne littérale « skip », la sortie sera complètement supprimée, ce qui peut être utile en combinaison avec un filtre pour les effets secondaires uniquement.

my %cache;
csv (in    => "dump.csv",
     out   => \"skip",
     on_in => sub { $cache{$_[1][1]}++ });

Actuellement, définir « out » sur une valeur fausse (« undef », « "" », 0) équivaut à « \"skip\" ».

Si l'argument « in » pointe vers quelque chose à analyser, et que « out » est défini sur une référence à un « ARRAY » ou à un « HASH », la sortie est ajoutée aux données de la référence existante. Le résultat de l'analyse doit correspondre à ce qui existe dans la référence passée. Cela peut être utile lorsque vous devez analyser un ensemble de fichiers avec un contenu similaire (comme des données stockées par période) et que vous souhaitez les collecter dans une seule structure de données :

my %hash;
csv (in => $_, out => \%hash, key => "id") for sort glob "foo-[0-9]*.csv";
my @list; # Liste de tableaux
csv (in => $_, out => \@list)              for sort glob "foo-[0-9]*.csv";
my @list; # Liste de hachages
csv (in => $_, out => \@list, bom => 1)    for sort glob "foo-[0-9]*.csv";

Streaming

Si les deux « in » et « out » sont des fichiers, des descripteurs de fichiers ou des globs, le streaming est appliqué en injectant un rappel « after_parse » qui utilise immédiatement la méthode « say () » de la même instance pour afficher le résultat, puis rejette l'enregistrement.

Si un « after_parse » a déjà été passé en attribut, il sera inclus dans l'appel injecté. Si « on_in » a été passé et « after_parse » n'a pas été passé, il sera utilisé à la place. Si les deux ont été passés, « on_in » est ignoré.

L'EOL du premier enregistrement de la source « in » est systématiquement utilisé comme EOL pour tous les enregistrements de la destination « out ».

L'attribut « filter » n'est pas disponible.

Tous les autres attributs sont partagés pour « in » et « out », de sorte que vous ne pouvez pas définir des encodages différents pour « in » et « out ». Vous devez passer un $fh, où « bi a été utilisé pour appliquer l'encodage des couches.

Notez qu'il s'agit d'un travail en cours et que les choses pourraient changer.

encoding

Si passé, il doit s'agir d'un encodage accepté par l'option :encoding() de "open". Il n'y a pas de valeur par défaut. Cet attribut ne fonctionne pas dans perl 5.6.x. "encoding" peut être abrégé en "enc" pour une utilisation facile dans les appels en ligne de commande.

Si "encoding" est défini sur la valeur littérale "auto", la méthode "header" sera appelée sur le flux ouvert pour vérifier s'il y a un BOM et définir l'encodage en conséquence. Ceci est égal à passer une valeur vraie dans l'option "detect_bom".

Les encodages peuvent être empilés, comme supporté par "binmode":

# Utilisation de PerlIO::via::gzip
csv (in       => \@csv,
     out      => "test.csv:via.gz",
     encoding => ":via(gzip):encoding(utf-8)",
     );
$aoa = csv (in => "test.csv:via.gz",  encoding => ":via(gzip)");
# Utilisation de PerlIO::gzip
csv (in       => \@csv,
     out      => "test.csv:via.gz",
     encoding => ":gzip:encoding(utf-8)",
     );
$aoa = csv (in => "test.csv:gzip.gz", encoding => ":gzip");

detect_bom

Si "detect_bom" est donné, la méthode "header" sera appelée sur le flux ouvert pour vérifier s'il y a un BOM et définir l'encodage en conséquence.

"detect_bom" peut être abrégé en "bom".

Ceci est la même chose que de définir "encoding" à "auto".

Notez qu'étant donné que la méthode "header" est appelée, son comportement par défaut est également de définir les en-têtes.

headers

Si cet attribut n'est pas donné, le comportement par défaut est de produire un tableau de tableaux.

Si "headers" est fourni, il doit s'agir d'une liste anonyme de noms de colonnes, d'un hashref anonyme, d'un coderef, ou d'un indicateur littéral : "auto", "lc", "uc", ou "skip".

skip
Lorsque "skip" est utilisé, l'en-tête ne sera pas inclus dans la sortie. 
my $aoa = csv (in => $fh, headers => "skip");

"skip" est invalide/ignoré en combinaison avec "detect_bom".

auto
Si "auto" est utilisé, la première ligne de la source "CSV" sera lue comme la liste des en-têtes de champ et utilisée pour produire un tableau de hachages. 
my $aoh = csv (in => $fh, headers => "auto");
lc
Si "lc" est utilisé, la première ligne de la source "CSV" sera lue comme la liste des en-têtes de champ mappés en minuscules et utilisée pour produire un tableau de hachages. Ceci est une variation de "auto". 
my $aoh = csv (in => $fh, headers => "lc");
uc
Si "uc" est utilisé, la première ligne de la source "CSV" sera lue comme la liste des en-têtes de champ mappés en majuscules et utilisée pour produire un tableau de hachages. Ceci est une variation de "auto". 
my $aoh = csv (in => $fh, headers => "uc");
CODE
Si un coderef est utilisé, la première ligne de la source "CSV" sera lue comme la liste des en-têtes de champ transformés dans lesquels chaque champ est passé comme seul argument au coderef. Cette liste est utilisée pour produire un tableau de hachages. 
my $aoh = csv (in      => $fh,
               headers => sub { lc ($_[0]) =~ s/kode/code/gr });

cet exemple est une variation de l'utilisation de "lc" où toutes les occurrences de "kode" sont remplacées par "code".

ARRAY
Si "headers" est une liste anonyme, les entrées de la liste seront utilisées comme noms de champs. La première ligne est considérée comme des données et non comme des en-têtes. 
my $aoh = csv (in => $fh, headers => [ qw( Foo Bar ) ]);
csv (in => $aoa, out => $fh, headers => [ qw( code description price ) ]);
HASH
Si "headers" est une référence de hachage, cela implique "auto", mais les champs d'en-tête qui existent en tant que clé dans le hashref seront remplacés par la valeur pour cette clé. Étant donné un fichier CSV comme 
post-kode,ville,nom,numéro id,fubble
1234AA,Duckstad,Donald,13,"X313DF"

en utilisant

csv (headers => { "post-kode" => "pc", "id number" => "ID" }, ...

renverra une entrée comme

{ pc     => "1234AA",
  ville   => "Duckstad",
  nom   => "Donald",
  ID     => "13",
  fubble => "X313DF",
  }

Voir aussi "munge_column_names" et "set_column_names".

munge_column_names

Si "munge_column_names" est défini, la méthode "header" est appelée sur le flux ouvert avec tous les arguments correspondants pour détecter et définir les en-têtes.

"munge_column_names" peut être abrégé en "munge".

key

my $ref = csv (in => "test.csv", key => "code");
my $ref = csv (in => "test.csv", key => [ ":" => "code", "color" ]);

my $ref = csv (

value

my $ref = csv (in => "test.csv", key   => "code",

keep_headers

Lors de l'utilisation de hachages, conservez les noms de colonnes dans le ref d'array passé, de sorte que tous les en-têtes soient disponibles après l'appel dans l'ordre d'origine.

my $aoh = csv (in => "file.csv", keep_headers => \my @hdr);

Cet attribut peut être abrégé en "kh" ou passé en tant que "keep_column_names".

Cet attribut implique une valeur par défaut de "auto" pour l'attribut "headers".

Les en-têtes peuvent également être conservés en interne pour maintenir un ordre stable des en-têtes :

csv (in      => csv (in => "file.csv", kh => "internal"),
out => "new.csv", kh => "internal");

où "internal" peut aussi être 1, "yes", ou "true". Ceci est similaire à

my @h;
csv (in      => csv (in => "file.csv", kh => \@h),
     out     => "new.csv",
     headers => \@h);

fragment

N'afficher que le fragment tel que défini dans la méthode "fragment". Cette option est ignorée lors de la *génération* de "CSV". Voir "out".

En combinant tout, on peut obtenir quelque chose comme

use Text::CSV qw( csv );
my $aoh = csv (
    in       => "test.txt",
    encoding => "utf-8",
    headers  => "auto",
    sep_char => "|",
    fragment => "row=3;6-9;15-*",
    );
say $aoh->[15]{Foo};

sep_set

Si "sep_set" est défini, la méthode "header" est appelée sur le flux ouvert pour détecter et définir "sep_char" avec l'ensemble donné.

"sep_set" peut être abrégé en "seps". Si ni "sep_set" ni "seps" n'est donné, mais que "sep" est défini, "sep_set" prend par défaut "[ sep ]". Ceci n'est pris en charge qu'à partir de la version perl 5.10.

Notez que comme la méthode "header" est appelée, par défaut elle définit également les en-têtes.

set_column_names

Si "set_column_names" est passé, la méthode "header" est appelée sur le flux ouvert avec tous les arguments destinés à "header".

Si "set_column_names" est passé comme une valeur fausse, le contenu de la première ligne est seulement préservé si la sortie est AoA :

Avec un fichier d'entrée comme

bAr,foo
1,2
3,4,5

Cet appel

my $aoa = csv (in => $file, set_column_names => 0);

donnera

[[ "bar", "foo" ],
 [ "1",   "2"   ],
 [ "3",   "4",  "5" ]]

et

my $aoa = csv (in => $file, set_column_names => 0, munge => "none");

donnera

[[ "bAr", "foo" ],
 [ "1",   "2"   ],
 [ "3",   "4",  "5" ]]

csv

La *fonction* "csv" peut aussi être appelée comme une méthode ou avec un objet Text::CSV existant. Cela pourrait aider si la fonction doit être appelée un grand nombre de fois et que le surcoût de la création répétée de l'objet en interne est évité en passant une instance existante.

my $csv = Text::CSV->new ({ binary => 1, auto_diag => 1 });
my $aoa = $csv->csv (in => $fh);
my $aoa = csv (in => $fh, csv => $csv);

les deux agissent de la même manière. L'exécution de ceci 20000 fois sur un fichier CSV de 20 lignes a montré une accélération de 53%.

Callbacks

Les callbacks permettent des actions déclenchées depuis *l'intérieur* de Text::CSV.

Bien que la plupart de ce que cela permet puisse être fait facilement dans une boucle déroulée comme décrit dans la "SYNOPSIS", les callbacks peuvent être utilisés pour répondre à des demandes spéciales ou améliorer la fonction "csv".

error
$csv->callbacks (error => sub { $csv->SetDiag (0) });

Le callback "error" est appelé lorsqu'une erreur survient, mais *uniquement* lorsque "auto_diag" est défini à une valeur vraie. Un callback est appelé avec les valeurs renvoyées par "error_diag" :

my ($c, $s);
sub ignore3006 {
    my ($err, $msg, $pos, $recno, $fldno) = @_;
    if ($err == 3006) {
        # ignorer cette erreur
        ($c, $s) = (undef, undef);
        Text::CSV->SetDiag (0);
        }
    # Toute autre erreur
    return;
    } # ignore3006
$csv->callbacks (error => \&ignore3006);
$csv->bind_columns (\$c, \$s);
while ($csv->getline ($fh)) {
    # L'erreur 3006 n'arrêtera pas la boucle
    }
after_parse
$csv->callbacks (after_parse => sub { push @{$_[1]}, "NEW" });
while (my $row = $csv->getline ($fh)) {
    $row->[-1] eq "NEW";
    }

Ce callback est appelé après l'analyse avec "getline" seulement si aucune erreur ne s'est produite. Le callback est appelé avec deux arguments : l'objet "CSV" actuel et une référence de tableau vers les champs analysés.

Le code de retour du callback est ignoré, sauf s'il s'agit d'une référence à la chaîne de caractères "skip", auquel cas l'enregistrement sera ignoré dans "getline_all".

sub add_from_db {
    my ($csv, $row) = @_;
    $sth->execute ($row->[4]);
    push @$row, $sth->fetchrow_array;
    } # add_from_db
my $aoa = csv (in => "file.csv", callbacks => {
    after_parse => \&add_from_db });

Ce hook peut être utilisé pour la validation :

FAIL
Mourir si l'un des enregistrements ne valide pas une règle : 
after_parse => sub {
    $_[1][4] =~ m/^[0-9]{4}\s?[A-Z]{2}$/ or
        die "5ème champ n'a pas un code postal néerlandais valide";
    }
DEFAULT
Remplacer les champs invalides par une valeur par défaut : 
after_parse => sub { $_[1][2] =~ m/^\d+$/ or $_[1][2] = 0 }
SKIP
Ignorer les enregistrements qui ont des champs invalides (s'applique uniquement à "getline_all") : 
after_parse => sub { $_[1][0] =~ m/^\d+$/ or return "skip"; }
before_print
my $idx = 1;
$csv->callbacks (before_print => sub { $_[1][0] = $idx++ });
$csv->print (*STDOUT, [ 0, $_ ]) for @members;

Ce callback est appelé avant l'impression avec "print" seulement si aucune erreur ne s'est produite. Le callback est appelé avec deux arguments : l'objet "CSV" actuel et une référence de tableau vers les champs passés.

Le code de retour du callback est ignoré.

sub max_4_fields {
    my ($csv, $row) = @_;
    @$row > 4 and splice @$row, 4;
    } # max_4_fields
csv (in => csv (in => "file.csv"), out => *STDOUT,
    callbacks => { before_print => \&max_4_fields });

Ce callback n'est pas actif pour "combine".

Callbacks pour csv ()

La fonction "csv" autorise certains callbacks qui ne s'intègrent pas aux internes XS mais seulement à la fonction "csv".

csv (in        => "file.csv",
     callbacks => {
         filter       => { 6 => sub { $_ > 15 } },    # premier
         after_parse  => sub { say "AFTER PARSE";  }, # premier
         after_in     => sub { say "AFTER IN";     }, # second
         on_in        => sub { say "ON IN";        }, # troisième
         },
     );
csv (in        => $aoh,
     out       => "file.csv",
     callbacks => {
         on_in        => sub { say "ON IN";        }, # premier
         before_out   => sub { say "BEFORE OUT";   }, # second
         before_print => sub { say "BEFORE PRINT"; }, # troisième
         },
     );
filter
Ce callback peut être utilisé pour filtrer les enregistrements. Il est appelé juste après qu'un nouvel enregistrement ait été scanné. Le callback accepte un :
hashref
Les clés sont l'indice de la ligne (le nom ou le numéro de champ, basé sur 1) et les valeurs sont des sous-routines qui retournent une valeur vraie ou fausse. 
csv (in => "file.csv", filter => {
           3 => sub { m/a/ },       # le troisième champ doit contenir un "a"
           5 => sub { length > 4 }, # la longueur du 5ème champ est au moins 5
           });
csv (in => "file.csv", filter => { foo => sub { $_ > 4 }});

Si les clés du hash de filtre contiennent un caractère qui n'est pas un chiffre, cela définira implicitement "headers" à "auto" à moins que "headers" n'ait déjà été passé comme argument. Lorsque les en-têtes sont actifs, si l'on renvoie un tableau de hashes, le filtre ne s'applique pas à l'en-tête lui-même.

Tous les résultats des sous-routines doivent correspondre, comme dans un ET logique.

Le contexte du callback définit $_ localisé au champ indiqué par le filtre. Les deux arguments sont comme pour tous les autres callbacks, donc les autres champs de la ligne actuelle peuvent être vus :

filter => { 3 => sub { $_ > 100 ? $_[1][1] =~ m/A/ : $_[1][6] =~ m/B/ }}

Si le contexte est défini pour renvoyer une liste de hashes ("headers" est défini), l'enregistrement actuel sera également disponible dans %_ localisé :

filter => { 3 => sub { $_ > 100 && $_{foo} =~ m/A/ && $_{bar} < 1000  }}

Si le filtre est utilisé pour *modifier* le contenu en changeant $_, assurez-vous que la sous-routine renvoie vrai afin de ne pas faire ignorer cet enregistrement :

filter => { 2 => sub { $_ = uc }}

mettra en majuscules le deuxième champ, puis l'ignorera si le contenu résultant est évalué comme faux. Pour toujours accepter, terminez par une valeur vraie :

filter => { 2 => sub { $_ = uc; 1 }}
coderef
csv (in => "file.csv", filter => sub { $n++; 0; });

Si l'argument de "filter" est une référence de code, c'est un alias ou un raccourci pour un filtre sur la colonne 0 :

csv (filter => sub { $n++; 0 });

est égal à

csv (filter => { 0 => sub { $n++; 0 });
filter-name
csv (in => "file.csv", filter => "not_blank");
csv (in => "file.csv", filter => "not_empty");
csv (in => "file.csv", filter => "filled");

Encore en construction...

Si une erreur se produit, vous pouvez utiliser "$csv->error_diag" pour obtenir des informations sur la cause de l'échec. Vous devez être conscient que, pour des raisons de performance, la valeur interne n'est jamais nettoyée en cas de succès, de sorte que l'utilisation de la valeur retournée par "error_diag" dans des cas normaux - quand aucune erreur ne s'est produite - peut conduire à des résultats inattendus.

Si le constructeur a échoué, la cause peut être trouvée en utilisant "error_diag" comme méthode de classe, comme "Text::CSV->error_diag".

La méthode "$csv->error_diag" est appelée automatiquement lorsque le constructeur a été appelé avec "auto_diag" défini à 1 ou 2, ou lorsque autodie est en vigueur. Quand il est réglé sur 1, un "warn" est généré avec le message d'erreur, quand il est réglé sur 2, un "die" est généré. Le "2012 - EOF" est exclu des rapports "auto_diag".

Les erreurs peuvent être capturées individuellement en utilisant le callback "error".

Les erreurs décrites ci-dessous sont disponibles. J'ai essayé de rendre l'erreur elle-même aussi explicative que possible, mais d'autres descriptions seront ajoutées. Pour la plupart de ces erreurs, les trois premières lettres majuscules décrivent le type d'erreur :

  • INI

    • Erreur d'initialisation ou conflit d'options.

  • ECR

    • Erreur d'analyse syntaxique liée aux retours chariot.

  • EOF

    • Erreur d'analyse syntaxique liée à la fin du fichier.

  • EIQ

    • Erreur d'analyse syntaxique à l'intérieur des guillemets.

  • EIF

    • Erreur d'analyse syntaxique à l'intérieur d'un champ.

  • ECB

    • Erreur de combinaison.

  • EHR

    • Erreur d'analyse syntaxique liée à un hashref.

Et ci-dessous vous trouverez la liste complète des codes d'erreur qui peuvent être retournés :

  • 1001 "INI - sep_char est égal à quote_char ou escape_char"

    • Le caractère de séparation ne peut pas être égal au caractère de guillemet ou au caractère d'échappement, car cela invaliderait toutes les règles d'analyse.

  • 1002 "INI - allow_whitespace avec escape_char ou quote_char SP ou TAB"

    • Utiliser l'attribut "allow_whitespace" lorsque "quote_char" ou "escape_char" est égal à "ESPACE" ou "TABULATION" est trop ambigu.

  • 1003 "INI - \r ou \n dans l'attribut principal non autorisé"

    • L'utilisation des caractères de fin de ligne par défaut dans "sep_char", "quote_char" ou "escape_char" n'est pas autorisée.

  • 1004 "INI - les callbacks doivent être undef ou un hashref"

    • L'attribut "callbacks" ne peut être que "undef" ou une référence d'objet.

  • 1005 "INI - EOL trop long"

    • La valeur passée pour EOL dépasse sa longueur maximale (16).

  • 1006 "INI - SEP trop long"

    • La valeur passée pour SEP dépasse sa longueur maximale (16).

  • 1007 "INI - QUOTE trop long"

    • La valeur passée pour QUOTE dépasse sa longueur maximale (16).

  • 1008 "INI - SEP indéfini"

    • La valeur passée pour SEP doit être définie et non vide.

  • 1009 "INI - header est vide"

    • La ligne d'en-tête analysée dans "header" est vide.

  • 1010 "INI - header contient plus d'un séparateur valide"

    • La ligne d'en-tête analysée dans "header" contient plus d'un caractère séparateur valide (unique) qui se trouve dans l'ensemble des séparateurs autorisés.

  • 1011 "INI - header contient un champ vide"

    • La ligne d'en-tête analysée dans "header" contient un champ vide.

  • 1012 "INI - header contient des champs non uniques"

    • La ligne d'en-tête analysée dans "header" contient au moins deux champs identiques.

  • 1013 "INI - header appelé dans un flux indéfini"

    • La ligne d'en-tête ne peut pas être analysée à partir d'un flux indéfini.

  • 1500 "PRM - argument(s) invalide(s)/non supporté(s)"

    • La fonction ou méthode est appelée avec des arguments invalides ou des paramètres non supportés.

  • 1501 "PRM - l'attribut key est passé comme un type non supporté"

    • L'attribut "key" est d'un type non supporté.

  • 1502 "PRM - l'attribut value est passé sans l'attribut key"

    • L'attribut "value" n'est autorisé que lorsqu'une clé valide a été fournie.

  • 1503 "PRM - l'attribut value est passé comme un type non supporté"

    • L'attribut "value" est d'un type non supporté.

  • 2010 "ECR - char QUO à l'intérieur des guillemets suivi de CR ne faisant pas partie de EOL"

    • Lorsque "eol" a été défini à quelque chose de différent par défaut, comme "\r\t\n", et que le "\r" suit le deuxième "quote_char" (de fermeture), où les caractères suivant le "quote_char" sont "\r", cela est considéré comme une erreur.

DIAGNOSTICS

Le module Perl Text::CSV renvoie des codes d'erreur numériques en cas de problème. Voici la liste des codes d'erreur possibles et leur signification :

  • 2001 « ESC - Invalid escape character »

    Les séquences d'échappement ne sont valides que pour certains caractères. Par exemple, \" est valide, mais \a ne l'est pas.

  • 2003 « ESC - Invalid separator character »

    Le caractère séparateur est invalide.

  • 2004 « ESC - Invalid quote character »

    Le caractère de citation est invalide.

  • 2005 « ESC - Invalid EOL character »

    Le caractère de fin de ligne est invalide.

  • 2006 « ESC - Invalid field flag character »

    Le caractère de drapeau de champ est invalide.

  • 2007 « ESC - Too many parameters for escape character »

    Trop de paramètres pour le caractère d'échappement.

  • 2008 « ESC - Invalid escape character in input »

    Caractère d'échappement invalide dans l'entrée.

  • 2009 « ESC - Invalid escape character for binary mode »

    Caractère d'échappement invalide pour le mode binaire.

  • 2010 « ESC - Invalid escape character for quote mode »

    Caractère d'échappement invalide pour le mode citation.

  • 2011 « ECR - Characters after end of quoted field"

    Les séquences telles que "1,foo,"bar"baz,22,1" ne sont pas autorisées. "bar" est un champ cité et après le guillemet double fermant, il doit y avoir soit une séquence de nouvelle ligne, soit un caractère de séparation.

  • 2012 « EOF - End of data in parsing input stream"

    Auto-explicatif. Fin du fichier lors de l'analyse d'un flux. Ne peut se produire que lors de la lecture à partir de flux avec "getline", car l'utilisation de "parse" se fait sur des chaînes qui ne sont pas tenues d'avoir un "eol" de fin.

  • 2013 « INI - Specification error for fragments RFC7111"

    Spécification invalide pour la spécification de « fragment » d'URI.

  • 2014 « ENF - Inconsistent number of fields"

    Nombre de champs incohérent lors de l'analyse stricte.

  • 2015 « ERW - Empty row"

    Une ligne vide n'était pas autorisée.

  • 2016 « EOL - Inconsistent EOL"

    Fin de ligne incohérente détectée lors de l'analyse stricte de la fin de ligne.

  • 2021 « EIQ - NL char inside quotes, binary off"

    Les séquences telles que "1,"foo\nbar",22,1" ne sont autorisées que lorsque l'option binaire a été sélectionnée avec le constructeur.

  • 2022 « EIQ - CR char inside quotes, binary off"

    Les séquences telles que "1,"foo\rbar",22,1" ne sont autorisées que lorsque l'option binaire a été sélectionnée avec le constructeur.

  • 2023 « EIQ - QUO character not allowed"

  • 2024 « EIQ - EOF cannot be escaped, not even inside quotes"

    Le caractère d'échappement n'est pas autorisé comme dernier caractère dans un flux d'entrée.

  • 2025 « EIQ - Loose unescaped escape"

    Un caractère d'échappement doit n'échapper que les caractères qui nécessitent un échappement.

    L'autorisation de l'échappement pour d'autres caractères est possible avec l'attribut "allow_loose_escapes".

  • 2026 « EIQ - Binary character inside quoted field, binary off"

    Les caractères binaires ne sont pas autorisés par défaut. Les exceptions sont les champs qui contiennent du UTF-8 valide, qui seront automatiquement mis à niveau si le contenu est du UTF-8 valide. Définissez "binary" sur 1 pour accepter les données binaires.
