NOM

Test::Exec - Tester que du code appelle exec sans terminer les tests

VERSION

version 0.07

SYNOPSIS

use Test::More;
use Test::Exec;

is_deeply exec_arrayref { exec 'foo', 'bar', 'baz' }, [qw( foo bar baz )], 'exec trouvé !';
is exec_arrayref { }, undef, 'n\'a pas exec !';

done_testing;

DESCRIPTION

Test::Exec fournit les outils les plus simples possibles pour tester du code qui pourrait appeler "exec", ce qui, autrement, mettrait fin à votre test en appelant un autre programme. Ce code devrait détecter et capturer les appels "exec", même s'ils sont à l'intérieur d'un "eval".

Le concept et l'implémentation étaient basés sur Test::Exit, mais appliqués à "exec" au lieu de "exit".

FONCTIONS

exec_arrayref

exec_arrayref { ... }

exécute le code donné. Si le code appelle "exec", alors cette fonction retournera un arrayref avec ses arguments. Si le code n'appelle jamais "exec", elle retournera "undef".

never_exec_ok

never_exec_ok { ... }

Exécute le code donné. Si le code appelle "exec", alors le test échouera (mais exec sera intercepté et ne sera pas effectué).

CAVEATS

Ce module installe sa propre version de "exec" dans "CORE::GLOBAL::exec", et peut mal interagir avec tout autre code qui essaie également de faire de telles choses.

VOIR AUSSI

Test::Exit
Très similaire à ce module (et l'a inspiré), mais pour les tests "exit" au lieu des tests "exec".
Test::Mock::Cmd
Fournit une interface pour mocker "system", "qx" et "exec".
