Template::Provider(3) Documentation Perl Contribuée par les Utilisateurs Template::Provider(3)

NOM

Template::Provider - Module fournisseur pour charger/compiler des modèles

SYNTAXE

$provider = Template::Provider->new(\%options);
($template, $error) = $provider->fetch($name);

DESCRIPTION

Le Template::Provider est utilisé pour charger, analyser, compiler et mettre en cache des documents modèles. Cet objet peut être étendu pour fournir des facilités plus spécifiques pour charger, ou autrement accéder aux modèles.

Les objets Template::Context maintiennent une liste d'objets Template::Provider qui sont interrogés en tour (via fetch()) pour retourner un modèle demandé. Chacun peut retourner un modèle compilé, lever une erreur, ou refuser de servir la requête, donnant ainsi une chance aux fournisseurs suivants de le faire.

Template::Provider peut également être étendu pour fournir des modèles depuis une source différente, par exemple une base de données. Voir SOUS-CLASSEMENT ci-dessous.

Cette documentation a besoin d'être améliorée.

MÉTHODES PUBLIQUES

new(\%options)

Méthode constructeur qui instancie et retourne un nouvel objet "Template::Provider". Une référence vers un tableau associatif d'options de configuration peut être passée.

Voir "OPTIONS DE CONFIGURATION" ci-dessous pour un résumé des options de configuration et Template::Manual::Config pour les détails complets.

fetch($name)

Retourne un modèle compilé pour le nom spécifié. Si le modèle ne peut pas être trouvé, alors "(undef, STATUS_DECLINED)" est retourné. Si une erreur se produit (par ex. erreur de lecture, erreur d'analyse) alors "($error, STATUS_ERROR)" est retourné, où $error est le message d'erreur généré. Si l'option TOLERANT est activée, la méthode retourne "(undef, STATUS_DECLINED)" au lieu de retourner une erreur.

load($name)

Charge un modèle sans l'analyser ni le compiler. Ceci est utilisé par la directive INSERT.

store($name, $template)

Stocke le modèle compilé, $template, dans le cache sous le nom $name. Les appels ultérieurs à fetch($name) retourneront ce modèle de préférence à tout fichier basé sur disque.

include_path(\@newpath)

Méthode d'accès pour le réglage "INCLUDE_PATH". Si appelée avec un argument, cette méthode remplacera la valeur existante de "INCLUDE_PATH" par la nouvelle valeur.

paths()

Cette méthode génère une copie de la liste "INCLUDE_PATH". Tous les éléments de la liste qui sont des générateurs dynamiques (par ex. références à des sous-routines ou objets implémentant une méthode paths()) seront appelés et la liste des répertoires retournés sera fusionnée dans la liste de sortie.

Il est possible de fournir un générateur qui se retourne lui-même, envoyant ainsi cette méthode dans une boucle infinie. Pour détecter et empêcher cela, la variable de package $MAX_DIRS, définie à 64 par défaut, limite le nombre maximum de chemins qui peuvent être ajoutés, ou générés pour la liste de sortie. Si ce nombre est dépassé, la méthode retournera immédiatement une erreur signalant cela.

OPTIONS DE CONFIGURATION

La liste suivante résume les options de configuration qui peuvent être fournies au constructeur new() de "Template::Provider". Veuillez consulter Template::Manual::Config pour plus de détails et des exemples sur chaque option de configuration.

INCLUDE_PATH

L'option INCLUDE_PATH est utilisée pour spécifier un ou plusieurs répertoires où se trouvent les fichiers modèles.

# chemin unique
my $provider = Template::Provider->new({
    INCLUDE_PATH => '/usr/local/templates',
});
# plusieurs chemins
my $provider = Template::Provider->new({
    INCLUDE_PATH => [ '/usr/local/templates',
                      '/tmp/my/templates' ],
});

ABSOLUTE

Le drapeau ABSOLUTE est utilisé pour indiquer si les modèles spécifiés avec des noms de fichiers absolus (par ex. '"/foo/bar"') doivent être traités. Il est désactivé par défaut et toute tentative de charger un modèle par un tel nom provoquera une exception '"file"'.

my $provider = Template::Provider->new({
    ABSOLUTE => 1,
});

RELATIVE

Le drapeau RELATIVE est utilisé pour indiquer si les modèles spécifiés avec des noms de fichiers relatifs au répertoire courant (par ex. "./foo/bar" ou "../../some/where/else") doivent être chargés. Il est également désactivé par défaut, et provoquera une erreur "file" si de tels noms de modèles sont rencontrés.

my $provider = Template::Provider->new({
    RELATIVE => 1,
});

DEFAULT

L'option DEFAULT peut être utilisée pour spécifier un modèle par défaut qui devrait être utilisé chaque fois qu'un modèle spécifié ne peut être trouvé dans le INCLUDE_PATH.

my $provider = Template::Provider->new({
    DEFAULT => 'notfound.html',
});

Si un modèle inexistant est demandé via la méthode Template process(), ou par une directive "INCLUDE", "PROCESS" ou "WRAPPER", alors le modèle "DEFAULT" sera plutôt traité, s'il est défini. Notez que le modèle "DEFAULT" n'est pas utilisé lorsque les modèles sont spécifiés avec des noms de fichiers absolus ou relatifs, ou comme référence à un descripteur de fichier d'entrée ou une chaîne de texte.

ENCODING

Template Toolkit décodera automatiquement les modèles Unicode qui ont un marqueur d'ordre d'octets (BOM) au début du fichier. Cette option peut être utilisée pour définir l'encodage par défaut pour les modèles qui ne définissent pas de BOM.

my $provider = Template::Provider->new({
    ENCODING => 'utf8',
});

Voir Encode pour plus d'informations.

CACHE_SIZE

L'option CACHE_SIZE peut être utilisée pour limiter le nombre de modèles compilés que le module devrait mettre en cache. Par défaut, CACHE_SIZE est indéfini et tous les modèles compilés sont mis en cache.

my $provider = Template::Provider->new({
    CACHE_SIZE => 64,   # mettre en cache seulement 64 modèles compilés
});

STAT_TTL

La valeur STAT_TTL peut être définie pour contrôler combien de temps "Template::Provider" conservera un modèle mis en cache en mémoire avant de vérifier si le modèle source a changé.

my $provider = Template::Provider->new({
    STAT_TTL => 60,  # une minute
});

COMPILE_EXT

L'option COMPILE_EXT peut être fournie pour spécifier une extension de nom de fichier pour les fichiers modèles compilés. Elle est indéfinie par défaut et aucune tentative ne sera faite pour lire ou écrire des fichiers modèles compilés.

my $provider = Template::Provider->new({
    COMPILE_EXT => '.ttc',
});

COMPILE_DIR

L'option COMPILE_DIR est utilisée pour spécifier un répertoire racine alternatif sous lequel les modèles compilés.

Template::Provider(3pm) - Manuel d'administration

NOM

Template::Provider - fournisseur de modèles pour le système Template

SYNOPSIS

    use Template::Provider;

    # Créer un fournisseur qui charge les modèles depuis le répertoire 'tmpl'
    my $provider = Template::Provider->new({
        INCLUDE_PATH => 'tmpl',
        COMPILE_DIR  => '/tmp/ttc',
    });

    # Créer un moteur de modèle avec le fournisseur
    my $template = Template->new({
        PROVIDER => $provider,
    });

    # Charger et traiter un modèle
    $template->process('mon_modele.tt', \%variables)
        || die $template->error();

DESCRIPTION

Le module "Template::Provider" est responsable de la localisation, du chargement et de la compilation des modèles à la demande. Il est généralement utilisé comme composant interne du module Template, mais il peut également être instancié et configuré indépendamment pour un contrôle plus fin sur la façon dont les modèles sont localisés et mis en cache.

Le fournisseur recherche les modèles en parcourant une liste de répertoires spécifiés par l'option INCLUDE_PATH. Lorsque le moteur de modèle tente de traiter ou d'inclure un modèle, le fournisseur est chargé de le trouver. S'il ne trouve pas de version compilée du modèle, il lit le contenu du fichier source, le fait parser par le module Template::Parser et enregistre le code compilé dans le répertoire spécifié par COMPILE_DIR pour des accès futurs.

METHODES PUBLIQUES

new(%args)

Constructeur pour la classe Template::Provider. Il accepte une liste d'arguments de configuration sous forme de paires clé-valeur.

Les options courantes comprennent :

  • INCLUDE_PATH : Un chemin de répertoire unique, ou une liste de chemins de répertoires séparés par des délimiteurs appropriés pour le système d'exploitation (généralement « : » sur Unix, « ; » sur Windows), à partir desquels rechercher les fichiers de modèles.
  • COMPILE_DIR : Le répertoire dans lequel les modèles compilés doivent être enregistrés. Si cette option n'est pas spécifiée, le fournisseur tentera d'utiliser le répertoire de travail courant. Les modèles ne seront enregistrés que si le répertoire existe et est accessible en écriture.
  • STRICT : Si défini sur une valeur vraie, le fournisseur générera une erreur si un modèle n'est pas trouvé. Par défaut, il renverra "STATUS_DECLINED".
  • ABSOLUTE : Si défini sur une valeur vraie, le fournisseur recherchera les modèles uniquement dans les répertoires spécifiés dans INCLUDE_PATH. Par défaut, il recherchera également dans le répertoire courant.
  • CACHE_SIZE : Spécifie le nombre maximal de modèles compilés à conserver en mémoire. La valeur par défaut est généralement de 100. Si elle est définie sur 0, la mise en cache est désactivée.
  • CLEAN_DIR : Si défini sur une valeur vraie, le fournisseur tentera de supprimer les fichiers de modèles obsolètes du répertoire de compilation lorsqu'il est initialisé.
  • POSTFIX : Un suffixe de nom de fichier à ajouter aux noms de fichiers de modèles lors de la recherche. Utile pour gérer plusieurs dialectes de modèles dans le même répertoire. Par défaut, ".tt".
  • EXTENSION : Alternativement à POSTFIX, spécifie une extension de fichier à utiliser lors de la recherche de modèles. Si EXTENSION est spécifié, POSTFIX est ignoré.
  • TMPL_OPTIONS : Une référence de hachage contenant des options qui seront transmises au constructeur de Template::Parser.
  • USER_VARS : Si défini sur une valeur vraie, les variables utilisateur (celles qui ne sont pas marquées comme globales) seront traitées comme des variables de modèle normales. Si USER_VARS est défini sur une référence de tableau, seuls les noms de variables spécifiés dans le tableau seront traités comme des variables utilisateur.

fetch($path)

Récupère un modèle compilé à partir du chemin spécifié. Recherche le modèle dans la cache, puis lit et compile le fichier source si nécessaire. Renvoie un objet code compilé ou "undef" en cas d'erreur.

current_dir($path)

Détermine le répertoire à partir duquel le modèle $path doit être chargé. Prenant en compte les options ABSOLUTE et INCLUDE_PATH.

load($path)

Charge le contenu du fichier de modèle à partir du chemin spécifié.

compile($path, $content)

Compile le contenu du modèle donné en utilisant le parseur spécifié.

store($path, $compiled)

Enregistre un modèle compilé dans le répertoire de compilation.

error()

Renvoie la chaîne d'erreur la plus récente rencontrée par le fournisseur.

status()

Renvoie le code d'état de la dernière opération.

OPTIONS DE CONFIGURATION

Outre les options passées au constructeur new(), le fournisseur peut être configuré en utilisant les constantes définies dans Template::Constants.

INCLUDE_PATH

Spécifie le chemin à utiliser lors de la recherche de modèles. Peut être une chaîne unique ou une liste de chemins.

my $provider = Template::Provider->new({
    INCLUDE_PATH => 'templates:/usr/local/share/templates',
});

COMPILE_DIR

Spécifie le répertoire où les fichiers de modèles compilés doivent être enregistrés.

my $provider = Template::Provider->new({
    COMPILE_DIR => '/tmp/ttc',
});

TOLERANT

Le drapeau TOLERANT peut être défini pour indiquer que le module "Template::Provider" doit ignorer toute erreur rencontrée lors du chargement d'un modèle et renvoyer à la place "STATUS_DECLINED".

PARSER

L'option PARSER peut être utilisée pour définir un module de parseur autre que le défaut de Template::Parser.

my $provider = Template::Provider->new({
    PARSER => MyOrg::Template::Parser->new({ ... }),
});

DEBUG

L'option DEBUG peut être utilisée pour activer les messages de débogage du module Template::Provider en la définissant pour inclure la valeur "DEBUG_PROVIDER".

use Template::Constants qw( :debug );
my $template = Template->new({
    DEBUG => DEBUG_PROVIDER,
});

SUBCLASSING

Le module "Template::Provider" peut être sous-classé pour fournir des modèles à partir d'une source différente (par exemple, une base de données). Dans la plupart des cas, il vous suffira de fournir des implémentations personnalisées des méthodes _template_modified() et _template_content(). Si votre fournisseur nécessite une initialisation personnalisée, vous devrez également implémenter une nouvelle méthode _init().

La mise en cache en mémoire et sur disque sera toujours appliquée (si activée) lors de la substitution de ces méthodes.

_template_modified($path)

Renvoie un horodatage du $path passé en appelant stat(). Cela peut être remplacé, par exemple, pour renvoyer une dernière valeur modifiée à partir d'une base de données. La valeur renvoyée doit être une valeur d'horodatage (telle que renvoyée par time(), bien qu'un numéro de séquence devrait fonctionner également.

_template_content($path)

Cette méthode renvoie le contenu du modèle pour toutes les directives "INCLUDE", "PROCESS" et "INSERT".

Lorsqu'elle est appelée dans un contexte scalaire, la méthode renvoie le contenu du modèle situé à $path, ou "undef" si $path n'est pas trouvé.

Lorsqu'elle est appelée dans un contexte de liste, elle renvoie "($content, $error, $mtime)", où $content est le contenu du modèle, $error est une chaîne d'erreur (par exemple, ""$path: File not found""), et $mtime est l'heure de modification du modèle.
