NOM

Template::Plugin::URL - Plugin pour construire des URL complexes

SYNOPSIS

[% USE url('/cgi-bin/foo.pl') %]
[% url(debug = 1, id = 123) %]
   # ==> /cgi/bin/foo.pl?debug=1&amp;id=123
[% USE mycgi = url('/cgi-bin/bar.pl', mode='browse', debug=1) %]
[% mycgi %]
   # ==> /cgi/bin/bar.pl?mode=browse&amp;debug=1
[% mycgi(mode='submit') %]
   # ==> /cgi/bin/bar.pl?mode=submit&amp;debug=1
[% mycgi(debug='d2 p0', id='D4-2k[4]') %]
   # ==> /cgi/bin/bar.pl?mode=browse&amp;debug=d2%20p0&amp;id=D4-2k%5B4%5D

DESCRIPTION

Le plugin "URL" peut être utilisé pour construire des URL complexes à partir d'une base et d'un tableau associatif de paramètres de requête supplémentaires.

Le constructeur doit recevoir une URL de base et, facultativement, un tableau associatif de paramètres et valeurs par défaut. Utilisé depuis un template, cela ressemblerait à ceci :

[% USE url('http://www.somewhere.com/cgi-bin/foo.pl') %]
[% USE url('/cgi-bin/bar.pl', mode='browse') %]
[% USE url('/cgi-bin/baz.pl', mode='browse', debug=1) %]

Lorsque le plugin est ensuite appelé sans arguments, la base et les paramètres par défaut sont renvoyés sous forme de chaîne de requête formatée.

[% url %]

Pour les trois exemples ci-dessus, cela produira les sorties suivantes :

http://www.somewhere.com/cgi-bin/foo.pl
/cgi-bin/bar.pl?mode=browse
/cgi-bin/baz.pl?mode=browse&amp;debug=1

Notez que les paramètres supplémentaires sont séparés par '"&amp;"' plutôt que simplement '"&"'. C'est le comportement correct pour les pages HTML, mais il est, malheureusement, incorrect lors de la création d'URL qui n'ont pas besoin d'être encodées en toute sécurité pour le HTML. Ceci sera probablement corrigé dans une future version du plugin (très probablement avec TT3). En attendant, vous pouvez définir $Template::Plugin::URL::JOINT à "&" pour obtenir le comportement correct.

Des paramètres supplémentaires peuvent également être spécifiés à l'URL :

[% url(mode='submit', id='wiz') %]

Ce qui, pour les trois mêmes exemples, produit :

http://www.somewhere.com/cgi-bin/foo.pl?mode=submit&amp;id=wiz
/cgi-bin/bar.pl?mode=browse&amp;id=wiz
/cgi-bin/baz.pl?mode=browse&amp;debug=1&amp;id=wiz

Une nouvelle URL de base peut également être spécifiée comme première option :

[% url('/cgi-bin/waz.pl', test=1) %]

produisant

/cgi-bin/waz.pl?test=1
/cgi-bin/waz.pl?mode=browse&amp;test=1
/cgi-bin/waz.pl?mode=browse&amp;debug=1&amp;test=1

L'ordre des paramètres n'est pas déterministe en raison du fait que les tables associatives de Perl sont elles-mêmes non ordonnées. Ce n'est pas un problème car l'ordre des paramètres CGI est insignifiant (à ma connaissance). Toutes les valeurs seront correctement échappées grâce à du code emprunté au module "CGI" de Lincoln Stein. par exemple :

[% USE url('/cgi-bin/woz.pl') %]
[% url(name="Elrich von Benjy d'Weiro") %]

Ici, les caractères espace et ""'"" guillemet simple sont échappés dans la sortie :

/cgi-bin/woz.pl?name=Elrich%20von%20Benjy%20d%27Weiro

Un nom alternatif peut être fourni pour le plugin au moment de la construction, conformément à la syntaxe normale de Template Toolkit.

[% USE mycgi = url('cgi-bin/min.pl') %]
[% mycgi(debug=1) %]
