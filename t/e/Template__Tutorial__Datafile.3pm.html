NOM

Template::Tutorial::Datafile - Crée des fichiers de sortie dynamiques en utilisant le Template Toolkit

DESCRIPTION

Introduction au Template Toolkit

Il existe plusieurs modules Perl universellement reconnus comme étant le "bon endroit où aller" pour certaines tâches. Si vous accédiez à une base de données sans utiliser DBI, que vous extrayiez des données d'Internet sans utiliser l'un des modules LWP, ou que vous analysiez du XML sans utiliser XML::Parser ou l'une de ses sous-classes, vous risqueriez d'être rejeté par la société Perl polie.

Je pense que l'an 2000 a marqué la naissance d'un autre module "indispensable" en Perl - le Template Toolkit. Je ne pense pas être seul à le croire, car le Template Toolkit a remporté le prix du "Meilleur Nouveau Module" lors de la conférence Perl l'été dernier. La version 2.0 du Template Toolkit (connue sous le nom de TT2 pour ses amis) a été récemment publiée sur CPAN.

TT2 a été conçu et écrit par Andy Wardley <abw@wardley.org>. Il est né de son module de template précédent, Text::Metatext, dans un style de "plan de laisser tomber le tout". Son objectif est d'être le système de template le plus utile (ou du moins, le plus utilisé) en Perl.

TT2 offre un moyen de prendre un fichier texte avec un template fixe (le template) et d'y intégrer des données variables. Une application évidente de cela est la création de pages Web dynamiques, et c'est là qu'une grande partie de l'attention reçue par TT2 s'est concentrée. Dans cet article, j'espère démontrer que TT2 est tout aussi utile dans des applications non Web.

Utilisation du Template Toolkit

Regardons comment utiliser TT2 pour traiter un simple fichier de données. TT2 est un module orienté objet Perl. Après avoir téléchargé et installé le module depuis CPAN, son utilisation dans votre programme est aussi simple que de placer les lignes

use Template;
my $tt = Template->new;

dans votre code. La fonction constructeur, "new", prend un certain nombre de paramètres optionnels qui sont documentés dans les pages man qui accompagnent le module, mais pour les besoins de cet article, nous allons garder les choses aussi simples que possible.

Pour traiter le template, nous appelons la méthode "process" comme ceci

$tt->process('my_template', \%data)
    || die $tt->error;

Nous passons deux paramètres à "process", le premier étant le nom du fichier contenant le template à traiter (dans ce cas, my_template) et le second étant une référence à un hash contenant les données que vous souhaitez utiliser dans le template. S'il y a une erreur lors du traitement du template, le programme se terminera avec un message d'erreur (espérons-le, utile).

Quel genre de choses peut se trouver dans %data ? La réponse est presque n'importe quoi. Voici un exemple montrant des données sur les équipes de football de la ligue anglaise.

my @teams = ({ name   => 'Man Utd',
               played => 16,
               won    => 12,
               drawn  => 3,
               lost   => 1 },
             { name   => 'Bradford',
               played => 16,
               won    => 2,
               drawn  => 5,
               lost   => 9 });
my %data = ( name   => 'English Premier League',
             season => '2000/01',
             teams  => \@teams );

Cela crée trois éléments de données qui peuvent être accessibles dans le template, nommés "name", "season" et "teams". Notez que "teams" est une structure de données complexe.

Voici un template que nous pourrions utiliser pour traiter ces données.

Standings
League Name: [% name %]
Season: [% season %]
Teams:
[% FOREACH team = teams -%]
[% team.name %] [% team.played -%] 
 [% team.won %] [% team.drawn %] [% team.lost %]
[% END %]

L'exécution de ce template avec ces données donne la sortie suivante :

            Standings
League Name: English Premier League
Season: 2000/01
Teams:
Man Utd 16 12 3 1
Bradford 16 2 5 9

J'espère que la syntaxe du template est suffisamment simple à suivre. Il y a quelques points à noter.

  • Les directives de traitement de template sont écrites en utilisant un langage simple qui n'est pas du Perl.
  • Les noms des variables dans le %data sont devenus les noms des variables de données dans le template.
  • Les directives de traitement de template sont entourées de séquences "[%" et "%]".
  • Si ces tags sont remplacés par "[%-" et "-%]", alors la ligne de texte suivante ou précédente est supprimée.
  • Dans la boucle "FOREACH", chaque élément de la liste "teams" a été assigné, dans l'ordre, à la variable temporaire "team".
  • Chaque élément assigné à la variable "team" est un hash Perl. Les valeurs individuelles dans le hash sont accessibles en utilisant la notation par points.

Il est probable que le premier et le dernier de ces points soient les plus importants. Le premier souligne la séparation entre le processus d'acquisition des données et la logique de présentation. Le concepteur du template de présentation n'a pas besoin de connaître le Perl, il a seulement besoin de connaître les données qui seront transmises au template.

Le dernier point montre comment TT2 protège les concepteurs de templates de l'implémentation des structures de données. Les objets passés au processeur de templates peuvent être des scalaires, des tableaux, des hashes, des objets ou même des sous-routines. Le processeur de templates interprétera correctement vos données et fera ce qu'il faut pour vous retourner la bonne valeur. Dans cet exemple, chaque équipe était un hash, mais dans un système plus large, chaque équipe pourrait être un objet, auquel cas "name", "played", etc., seraient des méthodes d'accès aux propriétés sous-jacentes de l'objet. Aucun changement ne serait requis dans le template, car le processeur de templates se rendrait compte qu'il devait appeler des méthodes au lieu d'accéder à des valeurs de hash.

Un exemple plus complexe

Les statistiques de la Ligue de Football Anglaise sont généralement présentées dans un format légèrement plus complexe que celui utilisé précédemment. Une base complète de statistiques montrera le nombre de matchs gagnés, perdus ou nuls par une équipe, le nombre de buts marqués par l'équipe et le nombre de points que l'équipe a obtenus. Les équipes gagnent trois points pour une victoire et un point pour un nul. Lorsque les équipes ont le même nombre de points, elles sont séparées par la différence de buts, c'est-à-dire le nombre de buts que l'équipe a marqués moins le nombre de buts qu'elle a encaissés. Pour compliquer davantage les choses, les matchs gagnés, nuls et perdus, ainsi que les buts marqués et encaissés, sont souvent divisés entre matchs à domicile et à l'extérieur.

Par conséquent, si vous avez une source de données qui liste le nom de l'équipe ainsi que les matchs gagnés, nuls et perdus et les buts marqués et encaissés, divisés entre les matchs à domicile et à l'extérieur (un total de 11 éléments de données), vous pouvez calculer tous les autres éléments (différence de buts, points obtenus et même position dans le classement). Prenons un tel fichier, mais nous ne regarderons que les trois premières équipes. Il ressemblera à ceci :

Man Utd,7,1,0,26,4,5,2,1,15,6
Arsenal,7,1,0,17,4,2,3,3,7,9
Leicester,4,3,1,10,8,4,2,2,7,4

Un script simple pour lire ces données dans un tableau de hashes ressemblera à ceci (j'ai simplifié les noms des colonnes de données - w, d, et l, ce sont les matchs gagnés, nuls et perdus, et f et a sont les buts marqués et encaissés ; h et a dans le nom d'une donnée indiquent s'il s'agit d'une statistique à domicile ou à l'extérieur) :

my @cols = qw(name hw hd hl hf ha aw ad al af aa);
my @teams;
while (<>) {
    chomp;
    my %team;
    @team{@cols} = split /,/;
    push @teams, \%team;
}

Nous pouvons ensuite parcourir les équipes et calculer toutes les données dérivées :

foreach (@teams) {
    $_->{w} = $_->{hw} + $_->{aw};
    $_->{d} = $_->{hd} + $_->{ad};
    $_->{l} = $_->{hl} + $_->{al};
    $_->{pl} = $_->{w} + $_->{d} + $_->{l};
    $_->{f} = $_->{hf} + $_->{af};
    $_->{a} = $_->{ha} + $_->{aa};
    $_->{gd} = $_->{f} - $_->{a};
    $_->{pt} = (3 * $_->{w}) + $_->{d};
}

$b->{pt} <=> $b->{pt} || $b->{gd} <=> $a->{gd} } @teams;

Et pour finir, ajoutons l'élément de données de position dans la ligue :

$teams[$_]->{pos} = $_ + 1 
    foreach 0 .. $#teams;

Après avoir extrait toutes nos données dans une structure de données interne, nous pouvons commencer à produire des sorties à l'aide de modèles. Un modèle pour créer un fichier CSV contenant les données réparties entre les statistiques à domicile et à l'extérieur ressemblerait à ceci :

[% FOREACH team = teams -%]
[% team.pos %],[% team.name %],[% team.pl %],[% team.hw %],
[%- team.hd %],[% team.hl %],[% team.hf %],[% team.ha %],
[%- team.aw %],[% team.ad %],[% team.al %],[% team.af %],
[%- team.aa %],[% team.gd %],[% team.pt %]
[%- END %]

Et en le traitant comme ceci :

$tt->process('split.tt', { teams => \@teams }, 'split.csv')
  || die $tt->error;

produit la sortie suivante :

1,Man Utd,16,7,1,0,26,4,5,2,1,15,6,31,39
2,Arsenal,16,7,1,0,17,4,2,3,3,7,9,11,31
3,Leicester,16,4,3,1,10,8,4,2,2,7,4,5,29

Notez que nous avons introduit le troisième paramètre de "process". Si ce paramètre est absent, TT2 envoie sa sortie à "STDOUT". Si ce paramètre est un scalaire, il est considéré comme le nom d'un fichier auquel écrire la sortie. Ce paramètre peut également être (entre autres choses) un filehandle ou une référence vers un objet censé implémenter une méthode "print".

Si nous ne nous intéressions pas à la répartition entre les matchs à domicile et à l'extérieur, nous pourrions utiliser un modèle plus simple comme celui-ci :

[% FOREACH team = teams -%]
[% team.pos %],[% team.name %],[% team.pl %],[% team.w %],
[%- team.d %],[% team.l %],[% team.f %],[% team.a %],
[%- team.aa %],[% team.gd %],[% team.pt %]
[% END -%]

Qui produirait une sortie comme ceci :

1,Man Utd,16,12,3,1,41,10,6,31,39
2,Arsenal,16,9,4,3,24,13,9,11,31
3,Leicester,16,8,5,3,17,12,4,5,29

Produire du XML

Cela commence à montrer une partie de la puissance et de la flexibilité de TT2, mais vous pourriez penser que vous pourriez tout aussi facilement produire cette sortie avec une boucle "foreach" et quelques instructions "print" dans votre code. C'est, bien sûr, vrai ; mais c'est parce que j'ai choisi un exemple délibérément simple pour expliquer les concepts. Et si nous voulions produire un fichier XML contenant les données ? Et si (comme je l'ai mentionné précédemment) les données de la ligue étaient stockées dans un objet ? Le code serait alors encore plus simple, car la plupart du code que nous avons écrit auparavant serait caché dans "FootballLeague.pm".

use FootballLeague;
use Template;
my $league = FootballLeague->new(name => 'English Premier');
my $tt = Template->new;
$tt->process('league_xml.tt', { league => $league })
    || die $tt->error;

Et le modèle dans "league_xml.tt" ressemblerait à peu près à ceci :

<?xml version="1.0"?>
<!DOCTYPE LEAGUE SYSTEM "league.dtd">
<league name="[% league.name %]" season="[% league.season %]">
[% FOREACH team = league.teams -%]
  <team name="[% team.name %]"
        pos="[% team.pos %]"
        played="[% team.pl %]"
        goal_diff="[% team.gd %]"
        points="[% team.pt %]">
     <stats type="home">
            win="[% team.hw %]"
            draw="[%- team.hd %]"
            lose="[% team.hl %]"
            for="[% team.hf %]"
            against="[% team.ha %]" />
     <stats type="away">
            win="[% team.aw %]"
            draw="[%- team.ad %]"
            lose="[% team.al %]"
            for="[% team.af %]"
            against="[% team.aa %]" />
  </team>
[% END -%]
&/league>

Notez qu'en passant l'objet entier à "process", nous devons ajouter un niveau d'indirection supplémentaire à nos variables de modèle : tout est maintenant un composant de la variable "league". A part cela, tout dans le modèle est très similaire à ce que nous avons utilisé auparavant. Vraisemblablement maintenant "team.name" appelle une fonction d'accès plutôt que d'effectuer une recherche dans une table de hachage, mais tout cela est transparent pour notre concepteur de modèle.

Plusieurs Formats

Comme dernier exemple, supposons que nous devions créer des sorties de tableaux de ligues de football dans plusieurs formats. Peut-être que nous transmettons ces données à d'autres personnes et qu'elles ne peuvent pas toutes utiliser le même format. Certains de nos utilisateurs ont besoin de fichiers CSV et d'autres de XML. Certains nécessitent des données réparties entre les matchs à domicile et à l'extérieur et d'autres veulent juste les totaux. Au total, nous aurons donc besoin de quatre modèles différents, mais la bonne nouvelle est qu'ils peuvent utiliser le même objet de données. Tout ce que le script doit faire est d'établir quel modèle est requis et de le traiter.

use FootballLeague;
use Template;
my ($name, $type, $stats) = @_;
my $league = FootballLeague->new(name => $name);
my $tt = Template->new;
$tt->process("league_${type}_$stats.tt", 
             { league => $league }
             "league_$stats.$type")
    || die $tt->error;

Par exemple, vous pouvez appeler ce script comme ceci :

league.pl 'English Premier' xml split

Cela traitera un modèle appelé "league_xml_split.tt" et placera les résultats dans un fichier appelé "league_split.xml".

Cela commence à montrer la véritable force du Template Toolkit. Si nous voulions plus tard ajouter un autre format de fichier - peut-être voulions-nous créer une page HTML de tableau de ligue ou même un document LaTeX - alors nous n'aurions qu'à créer le modèle approprié et à le nommer selon notre convention de nommage existante. Nous n'aurions pas besoin de faire de modifications au code.

J'espère que vous comprenez maintenant pourquoi le Template Toolkit devient rapidement une partie essentielle de l'installation Perl de nombreuses personnes.
