Text::BibTeX::Entry(3pm) Documentation Perl fournie par l'utilisateur Text::BibTeX::Entry(3pm)

NOM

Text::BibTeX::Entry - lire et analyser des fichiers BibTeX

SYNTAXE

use Text::BibTeX::Entry;
# ...en supposant que $bibfile et $newbib sont tous deux des objets de classe
# Text::BibTeX::File, ouverts en lecture et en écriture (respectivement) :
# Méthodes de création/analyse d'entrées :
$entry = Text::BibTeX::Entry->new();
$entry->read ($bibfile);
$entry->parse ($filename, $filehandle);
$entry->parse_s ($entry_text);
# ou :
$entry = Text::BibTeX::Entry->new( $bibfile );
$entry = Text::BibTeX::Entry->new( $filename, $filehandle );
$entry = Text::BibTeX::Entry->new( $entry_text );

# Méthodes de requête d'entrée
warn "erreur dans l'entrée" unless $entry->parse_ok;
$metatype = $entry->metatype;
$type = $entry->type;
# si metatype est BTE_REGULAR ou BTE_MACRODEF :
$key = $entry->key;                  # seulement pour le métatype BTE_REGULAR
$num_fields = $entry->num_fields;
@fieldlist = $entry->fieldlist;
$has_title = $entry->exists ('title');
$title = $entry->get ('title');
# ou :
($val1,$val2,...$valn) = $entry->get ($field1, $field2, ..., $fieldn);
# si metatype est BTE_COMMENT ou BTE_PREAMBLE :
$value = $entry->value;
# Méthodes de nom d'auteur
@authors = $entry->split ('author');
($first_author) = $entry->names ('author');
# Méthodes de modification d'entrée
$entry->set_type ($new_type);
$entry->set_key ($new_key);
$entry->set ('title', $new_title);
# ou :
$entry->set ($field1, $val1, $field2, $val2, ..., $fieldn, $valn);
$entry->delete (@fields);
$entry->set_fieldlist (\@fieldlist);
# Méthodes de sortie d'entrée
$entry->write ($newbib);
$entry->print ($filehandle);
$entry_text = $entry->print_s;
# Réinitialiser l'état interne de l'analyseur :
$entry = Text::BibTeX::Entry->new();
$entry->parse ($filename, undef);
$entry->parse_s (undef);
# ou :
$entry = Text::BibTeX::Entry->new( $filename, undef );
$entry = Text::BibTeX::Entry->new( undef );
# Méthodes diverses
$entry->warn ($entry_warning);
# ou :
$entry->warn ($field_warning, $field);
$entry->clone;

DESCRIPTION

"Text::BibTeX::Entry" effectue tout le travail réel de lecture et d'analyse des fichiers BibTeX. (Eh bien, en réalité, il fournit simplement une interface Perl orientée objet à une bibliothèque C qui fait tout cela. Mais ce n'est pas important pour le moment.)

Les entrées BibTeX peuvent être lues soit à partir d'objets "Text::BibTeX::File" (en utilisant la méthode "read"), soit directement depuis un descripteur de fichier (en utilisant la méthode "parse"), soit à partir d'une chaîne (en utilisant "parse_s"). La première option est préférable, car vous n'avez pas à vous soucier de fournir le nom du fichier, et en raison des fonctionnalités supplémentaires fournies par la classe "Text::BibTeX::File". Actuellement, cela signifie que vous pouvez spécifier la *structure de base de données* à laquelle les entrées sont censées se conformer via la classe "File". Cela vous permet de vous assurer que les entrées suivent les règles pour les champs requis et les champs mutuellement contraints pour un type de base de données particulier, et vous donne également accès à toutes les méthodes de la *classe d'entrée structurée* pour cette structure de base de données. Voir Text::BibTeX::Structure pour plus de détails sur les structures de base de données.

Une fois que vous avez l'entrée, vous pouvez la interroger ou la modifier de différentes manières. Les méthodes de requête sont "parse_ok", "type", "key", "num_fields", "fieldlist", "exists", et "get". Les méthodes pour modifier l'entrée sont "set_type", "set_key", "set_fieldlist", "delete", et "set".

Enfin, vous pouvez sortir des entrées BibTeX, à nouveau soit vers un objet "Text::BibTeX::File" ouvert, un descripteur de fichier ou une chaîne. (Un descripteur de fichier ou un objet "File" doit, bien sûr, avoir été ouvert en mode écriture.) La sortie vers un objet "File" se fait avec la méthode "write", vers un descripteur de fichier via "print", et vers une chaîne avec "print_s". L'utilisation de la classe "File" est recommandée pour la future extensibilité, bien qu'elle n'offre actuellement rien de plus.

MÉTHODES

Méthodes de création/analyse d'entrées

new ([OPTS ,] [SOURCE])
Crée un nouvel objet "Text::BibTeX::Entry". Si le paramètre SOURCE est fourni, il doit être l'un des suivants : un objet "Text::BibTeX::File" (ou une classe descendante), une paire nom de fichier/descripteur de fichier, ou une chaîne. Appelle "read" pour lire depuis un objet "Text::BibTeX::File", "parse" pour lire depuis un descripteur de fichier, et "parse_s" pour lire depuis une chaîne.

Un descripteur de fichier peut être spécifié comme une référence GLOB, ou comme un objet "IO::Handle" (ou descendant), ou comme un objet "FileHandle" (ou descendant). (Mais il est vraiment inutile d'utiliser des objets "FileHandle", car "Text::BibTeX" requiert Perl 5.004, qui inclut toujours les modules "IO".) Vous *ne pouvez pas* passer le nom d'un descripteur de fichier sous forme de chaîne, car "Text::BibTeX::Entry" se conforme au pragma "use strict" (qui interdit de telles références symboliques).

Le nom de fichier correspondant doit être fourni afin de permettre des messages d'erreur précis ; si vous n'avez tout simplement pas le nom du fichier, vous pouvez passer "undef" et vous obtiendrez des messages d'erreur sans nom de fichier. (Il est probablement préférable de réorganiser votre code de manière à ce que le nom du fichier soit disponible.)

Ainsi, les lignes suivantes sont équivalentes pour lire un fichier nommé par $filename (gestion des erreurs ignorée) :

# descripteur de fichier traditionnel et référence GLOB
open (BIBFILE, $filename);
$entry = Text::BibTeX::Entry->new($filename, \*BIBFILE);
# nouveau truc IO::File
$file = IO::File->new($filename);
$entry = Text::BibTeX::Entry->new($filename, $file);

Mais l'utilisation d'un objet "Text::BibTeX::File" est plus simple et préférée :

$file  = Text::BibTeX::File->new($filename);
$entry = Text::BibTeX::Entry->new($file);

Retourne le nouvel objet, sauf si SOURCE est fourni et que la lecture/l'analyse de l'entrée échoue (par exemple, en raison de la fin du fichier) - alors il retourne faux.

Vous pouvez fournir une référence à un hachage d'options comme premier argument. Les options prises en charge sont :

BINMODE
Définit la manière dont Text::BibTeX gère les chaînes de caractères. Par défaut, il gère les chaînes comme des octets. Vous pouvez définir BINMODE à 'utf-8' pour obtenir une normalisation NFC
NORMALIZATION
chaînes UTF-8 et vous pouvez personnaliser la normalisation avec l'option NORMALIZATION.

Exemple :

Text::BibTeX::Entry->new(
   { binmode => 'utf-8', normalization => 'NFD' },
    $file });
clone
Cloner un objet Text::BibTeX::Entry, renvoyant le clone. Cela réutilise la référence à tout Text::BibTeX::Structure ou Text::BibTeX::File mais copie tout le reste, de sorte que le clone puisse être modifié indépendamment de l'original.
read (BIBFILE)
Lit et analyse une entrée depuis BIBFILE, qui doit être un objet "Text::BibTeX::File" (ou descendant). La prochaine entrée sera lue depuis le fichier associé à cet objet.

Retourne le même résultat que "parse" (ou "parse_s") : faux si

pas d'entrée trouvée (par exemple, en fin de fichier), vrai sinon. Pour savoir si l'analyse elle-même a échoué (en raison d'erreurs dans l'entrée), appelez la méthode "parse_ok".

parse (FILENAME, FILEHANDLE)
Lit et analyse la prochaine entrée de FILEHANDLE. (C'est-à-dire qu'il analyse l'entrée jusqu'à ce qu'un signe '@' soit vu, puis il lit jusqu'au prochain signe '@'. Tout ce qui se trouve entre les deux signes '@' [y compris le premier, mais pas le second -- il est remis dans le flux d'entrée pour la prochaine entrée] est analysé comme une entrée BibTeX, avec la construction simultanée d'un arbre syntaxique abstrait [AST]. L'AST est parcouru pour extraire les informations les plus intéressantes, et celles-ci sont insérées dans une table de hachage Perl, qui est fortuitement l'objet "Text::BibTeX::Entry" que vous avez manipulé. Mais vous n'avez pas besoin de savoir tout cela -- je me suis juste dit que si vous avez lu jusqu'ici, vous pourriez vouloir connaître le fonctionnement interne de ce module.)

Le succès de l'analyse est stocké en interne afin que vous puissiez plus tard le consulter avec la méthode "parse_ok". Même en présence d'erreurs de syntaxe, vous obtiendrez généralement quelque chose ressemblant à votre entrée, mais il n'est généralement pas sage d'essayer d'en faire quoi que ce soit. Appelez simplement "parse_ok", et s'il renvoie faux, passez silencieusement à l'entrée suivante. (Les messages d'erreur affichés par l'analyseur devraient être tout à fait adéquats pour que l'utilisateur comprenne ce qui ne va pas. Et non, il n'y a actuellement aucun moyen pour vous de capturer ou de rediriger ces messages d'erreur -- ils sont toujours imprimés sur "stderr" par le code C sous-jacent. Cela devrait changer dans les futures versions.)

Si aucun signe '@' n'est vu dans l'entrée avant d'atteindre la fin du fichier, alors nous avons épuisé toutes les entrées du fichier, et "parse" renvoie une valeur fausse. Sinon, il renvoie une valeur vraie -- même s'il y avait des erreurs de syntaxe. Par conséquent, il est important de vérifier "parse_ok".

Le paramètre FILENAME n'est utilisé que pour générer des messages d'erreur, mais toute personne utilisant votre programme appréciera certainement que vous le définissiez correctement !

Passer "undef" à FILEHANDLE réinitialisera l'état de l'analyseur C sous-jacent, ce qui est requis pour analyser plusieurs fichiers.

parse_s (TEXT)
Analyse une entrée BibTeX (en utilisant les règles ci-dessus) à partir de la chaîne TEXT. La chaîne n'est pas modifiée ; appeler de manière répétée "parse_s" avec la même chaîne donnera les mêmes résultats à chaque fois. Par conséquent, il est inutile de mettre plusieurs entrées dans une seule chaîne.

Passer "undef" à TEXT réinitialisera l'état de l'analyseur C sous-jacent, ce qui peut être requis pour analyser plusieurs chaînes.

Méthodes de requête d'entrée

parse_ok ()
Renvoie faux s'il y a eu des erreurs graves rencontrées lors de l'analyse de l'entrée. (Une erreur "grave" est une erreur lexicale ou syntaxique ; actuellement, les avertissements tels que "macro non définie" entraînent l'affichage d'un message d'erreur sur "stderr" pour l'édification de l'utilisateur, mais aucune notification n'est disponible pour le code appelant.)
type ()
Renvoie le type de l'entrée. (Le `type' est le mot qui suit le signe '@' ; par exemple, `article', `book', `inproceedings', etc. pour les styles BibTeX standard.)
metatype ()
Renvoie le méta-type de l'entrée. (Le `méta-type' est une valeur numérique utilisée pour classer les types d'entrée en quatre groupes : commentaire, préambule, définition de macro (entrées @string), et régulier (tous les autres types d'entrée). "Text::BibTeX" exporte quatre constantes pour ces méta-types : "BTE_COMMENT", "BTE_PREAMBLE", "BTE_MACRODEF", et "BTE_REGULAR".)
key ()
Renvoie la clé de l'entrée. (La clé est le jeton qui suit immédiatement le '{' ou '(' ouvrant dans les entrées "régulières". Renvoie "undef" pour les entrées qui n'ont pas de clé, telles que les définitions de macro (@string) entrées.)
num_fields ()
Renvoie le nombre de champs dans l'entrée. (Notez que, actuellement, cela n'est *pas* équivalent à mettre "scalar" devant un appel à "fieldlist". Voir ci-dessous les conséquences de l'appel de "fieldlist" dans un contexte scalaire.)
fieldlist ()
Renvoie la liste des champs de l'entrée.

ATTENTION Dans un contexte scalaire, il ne renvoie plus une référence à la liste des champs de l'objet.

exists (FIELD)
Renvoie vrai si un champ nommé FIELD est présent dans l'entrée, faux sinon.
get (FIELD, ...)
Renvoie la valeur d'un ou plusieurs champs FIELD, sous forme de liste de valeurs. Par exemple : 
$auteur = $entree->get ('auteur');
($auteur, $editeur) = $entree->get ('auteur', 'editeur');

Si un champ FIELD n'est pas présent dans l'entrée, "undef" sera renvoyé à sa place dans la liste de retour. Cependant, vous ne pouvez pas entièrement vous fier à cela comme test de présence ou d'absence d'un champ ; il est possible qu'un champ soit présent mais indéfini. Actuellement, cela ne peut se produire qu'en raison de certaines erreurs de syntaxe dans l'entrée, ou si vous passez une valeur indéfinie à "set", ou si vous créez un nouveau champ avec "set_fieldlist" (la nouvelle valeur du champ est implicitement définie à "undef").

Normalement, la valeur du champ est ce à quoi ressemble l'entrée après un "traitement maximal" -- les guillemets sont supprimés, les espaces sont condensés (de la même manière que BibTeX le fait lui-même), les macros sont développées, et plusieurs jetons sont concaténés. (Voir bt_postprocess pour les détails du post-traitement effectué par btparse.)

Par exemple, si votre fichier d'entrée contient ce qui suit :

@string{de = "de"}
@string{foobars = "Foobars"}
@article{foobar,
  title = {   The Mating Habits      } # de # "Adult   " # foobars
}

alors utiliser "get" pour interroger la valeur du champ "title" de l'entrée "foobar" donnerait la chaîne "The Mating Habits of Adult Foobars".

Cependant, dans certaines circonstances, vous pourriez souhaiter préserver les valeurs telles qu'elles apparaissent dans l'entrée. Ceci est fait en définissant un indicateur "preserve_values" à un moment donné ; ensuite, "get" renverra non pas des chaînes mais des objets "Text::BibTeX::Value". Chaque objet "Value" est une liste d'objets "Text::BibTeX::SimpleValue", qui à son tour consiste en un type de valeur simple (chaîne, macro ou nombre) et le texte de la valeur simple. Divers moyens de définir l'indicateur "preserve_values" et l'interface aux objets "Value" et "SimpleValue" sont décrits dans Text::BibTeX::Value.

value ()
Renvoie la chaîne unique associée aux entrées @comment et @preamble. Par exemple, l'entrée 
@preamble{" Ceci est   une préambule" #
          {---la concaténation de plusieurs chaînes}}

renverrait une valeur de "Ceci est une préambule---la concaténation de plusieurs chaînes".

Si cette entrée a été analysée en mode "préservation de valeur" alors "value" agit comme "get", et renvoie un objet "Value" plutôt qu'une simple chaîne.

Méthodes de nom d'auteur

C'est la seule partie du module qui fait une hypothèse sur la nature des données, à savoir que certains champs sont des listes délimitées par un mot simple tel que "and", et que les sous-chaînes délimitées sont des noms humains du style "First von Last" ou "von Last, Jr., First" utilisé par BibTeX. Si vous utilisez ce module pour autre chose que des données bibliographiques, vous pouvez très probablement oublier ces deux méthodes. Cependant, si vous travaillez en fait sur des données bibliographiques de style BibTeX, celles-ci pourraient être très utiles -- l'analyse des noms faite par BibTeX n'est pas triviale, et la division de listes serait également pénible à implémenter en Perl car il faut prêter attention à la profondeur des accolades. (Sans que cela ait été moins pénible à implémenter en C -- c'est juste beaucoup plus efficace qu'une implémentation Perl.)

Soit dit en passant, ces deux méthodes supposent que les chaînes qui sont divisées ont déjà été "condensées" à la manière de BibTeX, c'est-à-dire que tous les espaces blancs au début et à la fin ont été supprimés et que les espaces blancs internes ont été réduits à des espaces simples. Cela devrait toujours être le cas lorsque vous utilisez ces deux méthodes sur un objet "Text::BibTeX::Entry", mais ce sont en fait juste des interfaces vers des fonctions plus générales dans "Text::BibTeX". (Plus général en ce sens que vous fournissez la chaîne à analyser, plutôt que de fournir le nom d'un champ d'entrée.) Si jamais vous utilisiez directement ces fonctions plus générales, vous pourriez avoir à vous soucier de la condensation des espaces blancs ; voir Text::BibTeX (les fonctions "split_list" et "split_name" en particulier) pour plus d'informations.)

Veuillez noter que l'interface pour l'analyse des noms d'auteurs est expérimentale, sujette à modification et ouverte à discussion. Veuillez me faire savoir si vous avez des problèmes avec

h it, pensez que c'est juste parfait, ou quoi que ce soit.

split (FIELD [, DELIM [, DESC]])
Divise la valeur de FIELD selon DELIM (par défaut : `and'). Ne supposez pas que cela fonctionne de la même manière que la fonction intégrée de Perl "split" juste parce que les noms sont les mêmes : en particulier, DELIM doit être une chaîne simple (pas de regex), et les délimiteurs qui se trouvent au début ou à la fin de la chaîne, ou à une profondeur de crochets non nulle, ou qui ne sont pas entourés d'espaces blancs, sont ignorés. Quelques exemples pourraient éclaircir les choses : 
si le champ F est...                alors split (F) retourne...
'Name1 and Name2'               ('Name1', 'Name2')
'Name1 and and Name2'           ('Name1', undef, 'Name2')
'Name1 and'                     ('Name1 and')
'and Name2'                     ('and Name2')
'Name1 {and} Name2 and Name3'   ('Name1 {and} Name2', 'Name3')
'{Name1 and Name2} and Name3'   ('{Name1 and Name2}', 'Name3')

Notez qu'un avertissement sera émis pour les noms vides (comme dans le deuxième exemple ci-dessus). Un avertissement devrait être émis pour les délimiteurs au début ou à la fin d'une chaîne, mais actuellement cela n'est pas fait. (Hmmm.)

DESC est une description en un mot des sous-chaînes ; elle par défaut à 'name'. Elle n'est utilisée que pour générer des messages d'avertissement.

names (FIELD)
Divise FIELD comme décrit ci-dessus, et divise en outre chaque nom en quatre composants : prénom, von, nom de famille et jr.

Retourne une liste d'objets "Text::BibTeX::Name", chacun représentant un nom. Utilisez la méthode "part" pour interroger ces objets ; voir Text::BibTeX::Name pour les détails sur l'interface des objets de nom (et sur l'analyse des noms également).

Par exemple, si cette entrée :

@article{foo,
         author = {John Smith and 
                   Hacker, J. Random and
                   Ludwig van Beethoven and
                   {Foo, Bar and Company}}}

a été analysée en un objet "Text::BibTeX::Entry" $entry, alors

@names = $entry->names ('author');

mettra une liste d'objets "Text::BibTeX::Name" dans @names. Ceux-ci peuvent être interrogés individuellement comme décrit dans Text::BibTeX::Name ; par exemple,

@last = $names[0]->part ('last');

mettra la liste des jetons composant le nom de famille du premier auteur dans le tableau @last : "('Smith')".

Méthodes de modification d'entrée

set_type (TYPE)
Définit le type de l'entrée.
set_metatype (METATYPE)
Définit le méta-type de l'entrée (doit être l'une des quatre constantes "BTE_COMMENT", "BTE_PREAMBLE", "BTE_MACRODEF", et "BTE_REGULAR", qui sont toutes exportées optionnellement depuis "Text::BibTeX").
set_key (KEY)
Définit la clé de l'entrée.
set (FIELD, VALUE, ...)
Définit la valeur du champ FIELD. (VALUE peut être "undef" ou non fourni, auquel cas FIELD sera simplement défini à "undef" -- c'est là que la différence entre la méthode "exists" et le test de la définissabilité des valeurs de champ devient claire.)

Plusieurs paires (FIELD, VALUE) peuvent être fournies ; elles seront traitées dans l'ordre (c'est-à-dire que l'entrée est traitée comme une liste, pas un hash). Par exemple :

$entry->set ('author', $author);
$entry->set ('author', $author, 'editor', $editor);

VALUE peut être soit une chaîne simple, soit un objet "Text::BibTeX::Value" ; peu importe si l'entrée a été analysée en mode "post-traitement complet" ou "préserver les valeurs d'entrée".

delete (FIELD)
Supprime le champ FIELD d'une entrée.
set_fieldlist (FIELDLIST)
Définit la liste des champs de l'entrée à FIELDLIST, qui doit être une référence de liste. Si des noms de champs fournis dans FIELDLIST ne sont pas actuellement présents dans l'entrée, ils sont créés avec la valeur "undef" et un avertissement est émis. Inversement, si des champs actuellement présents dans l'entrée ne sont pas nommés dans la liste des champs fournie à "set_fields", ils sont supprimés de l'entrée et un autre avertissement est émis.

Méthodes de sortie d'entrée

write (BIBFILE)
Imprime une entrée BibTeX sur le descripteur de fichier associé à BIBFILE (qui devrait être un objet "Text::BibTeX::File", ouvert en écriture). Actuellement, la sortie n'est pas particulièrement lisible par l'homme ; un joli imprimeur hautement configurable sera développé éventuellement.
print (FILEHANDLE)
Imprime une entrée BibTeX sur FILEHANDLE.
print_s ()
Imprime une entrée BibTeX dans une chaîne, qui est la valeur de retour.

Méthodes diverses

warn (WARNING [, FIELD])
Prépende un peu d'information de localisation (nom de fichier et numéro(s) de ligne) à WARNING, ajoute un saut de ligne et le passe à la fonction "warn" de Perl. Si FIELD est fourni, le numéro de ligne indiqué est celui du champ ; sinon, la plage de lignes pour l'entrée entière est donnée. (Enfin, presque -- actuellement, le numéro de ligne du dernier champ est utilisé comme dernière ligne de l'entrée entière. C'est un bug.)

Par exemple, si les lignes 10-15 du fichier foo.bib ressemblent à ceci :

@article{homer97,
  author = {Homer Simpson and Ned Flanders},
  title = {Territorial Imperatives in Modern Suburbia},
  journal = {Journal of Suburban Studies},
  year = 1997
}

alors, après avoir analysé cette entrée en $entry, les appels

$entry->warn ('what a silly entry');
$entry->warn ('what a silly journal', 'journal');

entraîneront l'émission des avertissements suivants :

foo.bib, lignes 10-14: what a silly entry
foo.bib, ligne 13: what a silly journal
line ([FIELD])
Retourne le numéro de ligne de FIELD. Si l'entrée a été analysée à partir d'une chaîne, cela fonctionne toujours -- c'est juste le numéro de ligne relatif au début de la chaîne. Si l'entrée a été analysée à partir d'un fichier, cela fonctionne comme prévu : il retourne le numéro de ligne absolu par rapport au fichier entier. Les numéros de ligne sont basés sur un.

Si FIELD n'est pas fourni, retourne une liste à deux éléments contenant les numéros de ligne du début et de la fin de l'entrée entière. (En fait, le numéro de ligne de "fin" est actuellement inexact : c'est en réalité le numéro de ligne du dernier champ de l'entrée. Mais c'est mieux que rien.)

filename ()
Retourne le nom du fichier à partir duquel l'entrée a été analysée. Ne fonctionne que si le fichier est représenté par un objet "Text::BibTeX::File" --- si vous avez simplement passé un nom de fichier/descripteur de fichier à "parse", vous ne pouvez pas récupérer le nom du fichier. (Désolé.)

Ce projet vise à fournir un moyen pratique et consultable d'accéder à la documentation des pages de manuel d'Arch Linux via une interface web.

Le site web est disponible sous les termes de la licence GPL-3.0, à l'exception du contenu des pages de manuel, qui ont leur propre licence spécifiée dans le paquet Arch Linux correspondant.

Ce projet vise à fournir un moyen pratique et consultable d'accéder à la documentation des pages de manuel d'Arch Linux via une interface web.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.
