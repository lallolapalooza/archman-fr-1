NOM

Text::Markdown - Convertir la syntaxe Markdown en (X)HTML

SYNOPSIS

use Text::Markdown 'markdown';
my $html = markdown($text);
use Text::Markdown 'markdown';
my $html = markdown( $text, {
    empty_element_suffix => '>',
    tab_width => 2,
} );
use Text::Markdown;
my $m = Text::Markdown->new;
my $html = $m->markdown($text);
use Text::Markdown;
my $m = Text::MultiMarkdown->new(
    empty_element_suffix => '>',
    tab_width => 2,
);
my $html = $m->markdown( $text );

DESCRIPTION

Markdown est un filtre texte-vers-HTML ; il traduit un format de texte structuré facile à lire / facile à écrire en HTML. Le format de texte de Markdown est très proche de celui du courrier électronique en texte brut, et prend en charge des fonctionnalités telles que les en-têtes, l'*accentuation*, les blocs de code, les citations et les liens.

La syntaxe de Markdown n'est pas conçue comme un langage de balisage générique, mais spécifiquement pour servir de front-end à (X)HTML. Vous pouvez utiliser des balises HTML de niveau span n'importe où dans un document Markdown, et vous pouvez également utiliser des balises HTML de niveau bloc (comme <div> et <table>).

SYNTAXE

Ce module implémente la syntaxe Markdown « originale » de :

http://daringfireball.net/projects/markdown/

Notez que Text::Markdown garantit que la sortie se termine toujours par un saut de ligne. Le fait que plusieurs sauts de ligne soient réduits à un seul est logique, car c'est le comportement du HTML vis-à-vis des espaces blancs. Le fait qu'il y ait toujours un saut de ligne à la fin est également logique, étant donné que la sortie sera toujours imbriquée dans un élément de niveau bloc (par opposition à un élément en ligne). Cet élément de bloc peut être un "<p>" (le plus souvent), ou un "<table>".

Markdown n'est pas interprété dans les éléments HTML de niveau bloc, afin que des morceaux de HTML collés (par exemple des widgets JavaScript, des compteurs web) ne soient pas magiquement (mal) interprétés. Pour un traitement sélectif de Markdown dans certains éléments HTML de bloc, mais pas d'autres, ajoutez un attribut "markdown" à l'élément de bloc et définissez sa valeur à 1, "on" ou "yes" :

<div markdown="1" class="navbar">
* Accueil
* À propos
* Contact
<div>

L'attribut "markdown" supplémentaire sera supprimé lors de la génération de la sortie.

OPTIONS

Text::Markdown prend en charge un certain nombre d'options pour son processeur qui contrôlent le comportement du document de sortie.

Ces options peuvent être fournies au constructeur, ou dans un hachage au sein d'appels individuels à la méthode « markdown ». Voir le SYNOPSIS pour des exemples des deux styles.

Les options du processeur sont :

empty_element_suffix
Cette option contrôle la fin des balises d'éléments vides : 
'/>' pour XHTML (par défaut)
'>' pour HTML
tab_width
Contrôle la largeur d'indentation dans le balisage généré. Par défaut à 4.
trust_list_start_value
Si vrai, les listes ordonnées utiliseront le premier nombre comme point de départ pour la numérotation. Cela vous permettra de reprendre là où vous vous êtes arrêté en écrivant : 
1. foo
2. bar
un paragraphe
3. baz
6. quux

(Notez que dans ce qui précède, quux sera numéroté 4.)

MÉTHODES

new

Un constructeur simple, voir les sections SYNTAXE et OPTIONS pour plus d'informations.

markdown

La fonction principale en ce qui concerne le monde extérieur. Voir le SYNOPSIS pour les détails d'utilisation.

urls

Renvoie une référence à un hachage dont la clé est la référence markdown et la valeur est l'URL.

Utile pour construire des scripts qui prétraitent une liste de liens avant le contenu principal. Voir t/05options.t pour un exemple de cette référence de hachage renvoyée dans la méthode markdown pour créer des liens.

AUTRES IMPLÉMENTATIONS

Markdown a été réimplémenté dans un certain nombre de langages, et avec un certain nombre d'ajouts.

Ceux que j'ai trouvés sont listés ci-dessous :

C - <http://www.pell.portland.or.us/~orc/Code/discount>
Discount - Markdown original, mais en C. L'implémentation la plus rapide disponible, et passe MDTest. Ajoute son propre ensemble de fonctionnalités personnalisées.
python - <http://www.freewisdom.org/projects/python-markdown/>
Python Markdown qui est principalement compatible avec l'original, avec une API d'extension intéressante.
ruby (maruku) - <http://maruku.rubyforge.org/>
L'une des plus belles implémentations disponibles. Construit un arbre d'analyse en interne, donc très flexible.
php - <http://michelf.com/projects/php-markdown/>
Un portage direct de Markdown.pl, dispose également d'une version « extra » maintenue séparément, qui ajoute un certain nombre de fonctionnalités empruntées par MultiMarkdown.
lua - <http://www.frykholm.se/files/markdown.lua>
Portage vers lua. Simple et léger (comme lua).
haskell - <http://johnmacfarlane.net/pandoc/>
Pandoc est une bibliothèque plus générale, prenant en charge Markdown, reStructuredText, LaTeX et plus encore.
javascript - <http://www.attacklab.net/showdown-gui.html>
Portage (presque) direct de Markdown.pl vers JavaScript

CETTE DISTRIBUTION

Veuillez noter que cette distribution est un fork du projet Markdown original de John Gruber, et qu'elle n'est *en aucun cas* bénie par lui.

Bien que ce code vise à être compatible avec le Markdown.pl original (et intègre et passe la suite de tests Markdown) tout en corrigeant un certain nombre de bogues de l'original - il peut y avoir des différences entre le comportement de ce module et Markdown.pl. Si vous trouvez des différences où vous pensez que Text::Markdown se comporte contrairement à la spécification Markdown, veuillez les signaler comme des bogues.

Text::Markdown *n'étend pas* le dialecte markdown de quelque manière que ce soit par rapport à ce qui est documenté sur daringfireball. Si vous voulez des fonctionnalités supplémentaires, vous devriez regarder Text::MultiMarkdown.
