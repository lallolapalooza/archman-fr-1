NOM

Test2::Tools - Documentation pour les outils.

DESCRIPTION

Les outils sont des paquets qui exportent des fonctions de test, typiquement toutes liées à un aspect spécifique des tests. Si vous avez quelques catégories d'exportations différentes, vous voudrez peut-être les diviser en modules distincts.

Les outils doivent exporter des fonctions de test. Le chargement d'outils **ne doit pas** avoir d'effets secondaires, ni modifier le comportement d'autres outils. Si vous souhaitez modifier des comportements ou créer des effets secondaires, vous devriez probablement écrire un Test2::Plugin.

FAQ

Pourquoi est-il appelé Test2::Tools, et non Test2::Tool ?
Cette question se pose puisque Tools est le seul espace de noms au pluriel. C'est parce que chaque Plugin devrait être une unité de fonctionnalité distincte, mais une distribution Tools peut (et devrait généralement) exporter plusieurs outils. Un bundle est également typiquement décrit comme une unité unique. Personne n'aimerait Test2::Bundles::Foo.
Dois-je faire hériter mes outils de Test2::Tools ?
Non. Actuellement, cette classe est vide. Éventuellement, nous pourrions vouloir ajouter du comportement, auquel cas nous ne voulons pas que quiconque en hérite déjà.

COMMENT ECRIRE UN MODULE 'TOOLS' ?

Il est très facile d'écrire des outils :

package Test2::Tools::Mine
use strict;
use warnings;
# Tous les outils doivent utiliser la fonction context().
use Test2::API qw/context/;
our @EXPORTS = qw/ok plan/;
use base 'Exporter';
sub ok($;$) {
    my ($bool, $name) = @_;
    # Toutes les fonctions d'outils doivent commencer par récupérer un contexte
    my $ctx = context();
    # Le contexte est l'interface principale pour générer des événements
    $ctx->ok($bool, $name);
    # Lorsque vous avez terminé, vous libérez le contexte
    $ctx->release;
    return $bool ? 1 : 0;
}
sub plan {
    my ($max) = @_;
    my $ctx = context();
    $ctx->plan($max);
    $ctx->release;
}
1;

Consultez Test2::API::Context pour la documentation sur ce que l'objet $ctx peut faire.
