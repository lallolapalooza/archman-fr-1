Term::ANSIColor(3perl) Guide de référence des programmeurs Perl Term::ANSIColor(3perl)

NOM

Term::ANSIColor - Couleur de sortie de l'écran en utilisant des séquences d'échappement ANSI

SYNTAXE

use Term::ANSIColor;
print color('bold blue');
print "Ce texte est en bleu gras.\n";
print color('reset');
print "Ce texte est normal.\n";
print colored("Jaune sur magenta.", 'yellow on_magenta'), "\n";
print "Ce texte est normal.\n";
print colored(['yellow on_magenta'], 'Jaune sur magenta.', "\n");
print colored(['bright_red on_black'], 'Rouge vif sur noir.', "\n");
print "\n";
# Mapper les séquences d'échappement aux noms de couleur.
use Term::ANSIColor 1.04 qw(uncolor);
my @names = uncolor('01;31');
print join(q{ }, @names), "\n";
# Supprimer toutes les séquences d'échappement de couleur.
use Term::ANSIColor 2.01 qw(colorstrip);
print colorstrip("\e[1mCe texte est gras\e[0m"), "\n";
# Déterminer si une couleur est valide.
use Term::ANSIColor 2.02 qw(colorvalid);
my $valid = colorvalid('blue bold', 'on_magenta');
print "La chaîne de couleur est ", $valid ? "valide\n" : "invalide\n";
# Créer de nouveaux alias pour les couleurs.
use Term::ANSIColor 4.00 qw(coloralias);
coloralias('alert', 'red');
print "Alert est ", coloralias('alert'), "\n";
print colored("Ceci est en rouge.", 'alert'), "\n";
use Term::ANSIColor qw(:constants);
print BOLD, BLUE, "Ce texte est en bleu gras.\n", RESET;
use Term::ANSIColor qw(:constants);
{
    local $Term::ANSIColor::AUTORESET = 1;
    print BOLD BLUE "Ce texte est en bleu gras.\n";
    print "Ce texte est normal.\n";
}
use Term::ANSIColor 2.00 qw(:pushpop);
print PUSHCOLOR RED ON_GREEN "Ce texte est rouge sur vert.\n";
print PUSHCOLOR BRIGHT_BLUE "Ce texte est bleu vif sur vert.\n";
print RESET BRIGHT_BLUE "Ce texte est juste bleu vif.\n";
print POPCOLOR "Retour au rouge sur vert.\n";
print LOCALCOLOR GREEN ON_BLUE "Ce texte est vert sur bleu.\n";
print "Ce texte est rouge sur vert.\n";
{
    local $Term::ANSIColor::AUTOLOCAL = 1;
    print ON_BLUE "Ce texte est rouge sur bleu.\n";
    print "Ce texte est rouge sur vert.\n";
}
print POPCOLOR "Retour à ce que nous avions au début.\n";

DESCRIPTION

Ce module a deux interfaces, l'une via color() et colored() et l'autre via des constantes. Il offre également les fonctions utilitaires uncolor(), colorstrip(), colorvalid() et coloralias(), qui doivent être explicitement importées pour être utilisées (voir "SYNTAXE").

Si vous utilisez Term::ANSIColor dans une commande console, envisagez de prendre en charge la norme CLICOLOR. Voir "Support de CLICOLOR" pour plus d'informations.

Voir "COMPATIBILITÉ" pour les versions de Term::ANSIColor qui ont introduit des fonctionnalités particulières et les versions de Perl qui les ont incluses.

Couleurs supportées

Les émulateurs de terminaux qui prennent en charge la couleur se divisent en quatre types : ceux qui ne prennent en charge que huit couleurs, ceux qui en prennent en charge seize, ceux qui en prennent en charge 256, et ceux qui en prennent en charge 24 bits. Ce module fournit les codes d'échappement ANSI pour tous. Ces couleurs sont appelées couleurs ANSI 0 à 7 (normales), 8 à 15 (16 couleurs), 16 à 255 (256 couleurs) et couleur vraie (appelée couleur directe par xterm).

Malheureusement, l'interprétation des couleurs 0 à 7 dépend souvent du fait que l'émulateur prenne en charge huit ou seize couleurs. Les émulateurs qui ne prennent en charge que huit couleurs (comme la console Linux) afficheront les couleurs 0 à 7 avec une luminosité normale et ignoreront les couleurs 8 à 15, les traitant de la même manière que le blanc. Les émulateurs qui prennent en charge 16 couleurs, tels que gnome-terminal, affichent normalement les couleurs 0 à 7 comme des versions atténuées ou plus sombres et les couleurs 8 à 15 comme une luminosité normale. Sur de tels émulateurs, le blanc "normal" (couleur 7) est généralement affiché comme un gris pâle, nécessitant l'utilisation du blanc vif (15) pour obtenir une vraie couleur blanche. Le noir vif est généralement une couleur gris foncé, bien que certains terminaux l'affichent comme du noir pur. Certains émulateurs de terminaux à 16 couleurs traitent également le jaune normal (couleur 3) comme orange ou marron, et le jaune vif (couleur 11) comme jaune.

Suivant la convention normale des émulateurs à 16 couleurs, ce module fournit une paire d'attributs pour chaque couleur. Pour chaque couleur normale (0 à 7), la couleur vive correspondante (8 à 15) est obtenue en ajoutant le préfixe "bright_" au nom de la couleur normale. Par exemple, "red" est la couleur 1 et "bright_red" est la couleur 9. Il en va de même pour les couleurs d'arrière-plan : "on_red" est la couleur normale et "on_bright_red" est la couleur vive. Mettez ces chaînes en majuscules pour l'interface constante.

Il n'y a malheureusement aucun moyen de savoir si l'émulateur actuel prend en charge plus de huit couleurs, ce qui rend le choix des couleurs difficile. Le choix le plus prudent est de n'utiliser que les couleurs régulières, qui sont au moins affichées sur tous les émulateurs. Cependant, elles apparaîtront foncées dans les émulateurs de terminaux à 16 couleurs, y compris la plupart des émulateurs courants dans les environnements X UNIX. Si vous savez que l'affichage est l'un de ces émulateurs, vous pourriez vouloir utiliser les variantes vives à la place. Encore mieux, offrez à l'utilisateur un moyen de configurer les couleurs pour une application donnée afin qu'elles correspondent à son émulateur de terminal.

Pour les émulateurs 256 couleurs, ce module fournit en outre "ansi0" à "ansi15", qui sont identiques aux couleurs 0 à 15 des émulateurs 16 couleurs mais utilisent la syntaxe d'échappement 256 couleurs, "grey0" à "grey23" allant de presque noir à presque blanc, et un ensemble de couleurs RVB. Les couleurs RVB sont de la forme "rgbRVB" où R, G et B sont des nombres de 0 à 5 donnant l'intensité du rouge, du vert et du bleu. Les couleurs grises et RVB sont également disponibles sous forme de "ansi16" à "ansi255" si vous souhaitez des noms simples pour les 256 couleurs. Des variantes "on_" de toutes ces couleurs sont également fournies. Ces couleurs peuvent être complètement ignorées sur les terminaux non 256 couleurs ou peuvent être mal interprétées et produire un comportement aléatoire. Des attributs supplémentaires tels que clignotant, italique ou gras peuvent ne pas fonctionner avec la palette 256 couleurs.

Pour les émulateurs de couleur vraie, ce module prend en charge des attributs de la forme "rNNNgNNNbNNN" et "on_rNNNgNNNbNNN" pour toutes les valeurs de NNN entre 0 et 255. Celles-ci représentent les couleurs de premier plan et d'arrière-plan, respectivement, avec les valeurs RVB données par les nombres NNN. Ces couleurs peuvent être complètement ignorées sur les terminaux qui ne supportent pas la couleur vraie ou peuvent être mal interprétées et produire un comportement aléatoire.

Interface de fonction

L'interface de fonction utilise des chaînes d'attributs pour décrire les couleurs et les attributs de texte à assigner au texte. Les attributs non colorés reconnus sont clear, reset, bold, dark, faint, italic, underline, underscore, blink, reverse et concealed. Clear et reset (réinitialiser aux attributs par défaut), dark et faint (atténué et saturé), et underline et underscore sont équivalents, alors utilisez celui qui est le plus intuitif pour vous.

Notez que tous les attributs ne sont pas pris en charge par tous les types de terminaux, et certains terminaux peuvent ne prendre en charge aucune de ces séquences. Dark et faint, italique, clignotant et masqué en particulier ne sont souvent pas implémentés.

Les attributs de couleur de premier plan normaux reconnus (couleurs 0 à 7) sont :

black  red  green  yellow  blue  magenta  cyan  white

Les attributs de couleur de premier plan vifs correspondants (couleurs 8 à 15) sont :

bright_black  bright_red      bright_green  bright_yellow
bright_blue   bright_magenta  bright_cyan   bright_white

Les attributs de couleur d'arrière-plan normaux reconnus (couleurs 0 à 7) sont :

on_black  on_red      on_green  on yellow
on_blue   on_magenta  on_cyan   on_white

Les attributs de couleur d'arrière-plan vifs reconnus (couleurs 8 à 15) sont :

on_br

DESCRIPTION

The Term::ANSIColor module provides routines for dealing with ANSI color escape sequences.

For basic 16-color terminals, the recognized foreground colors are:

   BLACK       RED        GREEN      YELLOW
   BLUE        MAGENTA    CYAN       WHITE
   BRIGHT_BLACK  BRIGHT_RED  BRIGHT_GREEN  BRIGHT_YELLOW
   BRIGHT_BLUE   BRIGHT_MAGENTA  BRIGHT_CYAN   BRIGHT_WHITE

And the recognized background colors are:

   ON_BLACK    ON_RED      ON_GREEN    ON_YELLOW
   ON_BLUE     ON_MAGENTA  ON_CYAN     ON_WHITE
   ON_BRIGHT_BLACK on_BRIGHT_RED   on_BRIGHT_GREEN on_BRIGHT_YELLOW
   ON_BRIGHT_BLUE  on_BRIGHT_MAGENTA on_BRIGHT_CYAN  on_BRIGHT_WHITE

For 256-color terminals, the recognized foreground colors are:

ansi0 .. ansi255
grey0 .. grey23

plus "rgbRGB" for R, G, and B values from 0 to 5, such as "rgb000" or "rgb515". Similarly, the recognized background colors are:

on_ansi0 .. on_ansi255
on_grey0 .. on_grey23

plus "on_rgbRGB" for R, G, and B values from 0 to 5.

For true color terminals, the recognized foreground colors are "rRRRgGGGbBBB" for RRR, GGG, and BBB values between 0 and 255. Similarly, the recognized background colors are "on_rRRRgGGGbBBB" for RRR, GGG, and BBB values between 0 and 255.

For any of the above listed attributes, case is not significant.

Attributes, once set, last until they are unset (by printing the attribute "clear" or "reset"). Be careful to do this, or otherwise your attribute will last after your script is done running, and people get very annoyed at having their prompt and typing changed to weird colors.

color(ATTR[, ATTR ...])
color() takes any number of strings as arguments and considers them to be space-separated lists of attributes. It then forms and returns the escape sequence to set those attributes. It doesn't print it out, just returns it, so you'll have to print it yourself if you want to. This is so that you can save it as a string, pass it to something else, send it to a file handle, or do anything else with it that you might care to. color() throws an exception if given an invalid attribute.
colored(STRING, ATTR[, ATTR ...])
colored(ATTR-REF, STRING[, STRING...])
As an aid in resetting colors, colored() takes a scalar as the first argument and any number of attribute strings as the second argument and returns the scalar wrapped in escape codes so that the attributes will be set as requested before the string and reset to normal after the string. Alternately, you can pass a reference to an array as the first argument, and then the contents of that array will be taken as attributes and color codes and the remainder of the arguments as text to colorize.

Normally, colored() just puts attribute codes at the beginning and end of the string, but if you set $Term::ANSIColor::EACHLINE to some string, that string will be considered the line delimiter and the attribute will be set at the beginning of each line of the passed string and reset at the end of each line. This is often desirable if the output contains newlines and you're using background colors, since a background color that persists across a newline is often interpreted by the terminal as providing the default background color for the next line. Programs like pagers can also be confused by attributes that span lines. Normally you'll want to set $Term::ANSIColor::EACHLINE to "\n" to use this feature.

Particularly consider setting $Term::ANSIColor::EACHLINE if you are interleaving output to standard output and standard error and you aren't flushing standard output (via autoflush() or setting $|). If you don't, the code to reset the color may unexpectedly sit in the standard output buffer rather than going to the display, causing standard error output to appear in the wrong color.

uncolor(ESCAPE)
uncolor() performs the opposite translation as color(), turning escape sequences into a list of strings corresponding to the attributes being set by those sequences. uncolor() will never return "ansi16" through "ansi255", instead preferring the "grey" and "rgb" names (and likewise for "on_ansi16" through "on_ansi255").
colorstrip(STRING[, STRING ...])
colorstrip() removes all color escape sequences from the provided strings, returning the modified strings separately in array context or joined together in scalar context. Its arguments are not modified.
colorvalid(ATTR[, ATTR ...])
colorvalid() takes attribute strings the same as color() and returns true if all attributes are known and false otherwise.
coloralias(ALIAS[, ATTR ...])
If ATTR is specified, it is interpreted as a list of space-separated strings naming attributes or existing aliases. In this case, coloralias() sets up an alias of ALIAS for the set of attributes given by ATTR. From that point forward, ALIAS can be passed into color(), colored(), and colorvalid() and will have the same meaning as the sequence of attributes given in ATTR. One possible use of this facility is to give more meaningful names to the 256-color RGB colors. Only ASCII alphanumerics, ".", "_", and "-" are allowed in alias names.

If ATTR includes aliases, those aliases will be expanded at definition time and their values will be used to define the new alias. This means that if you define an alias A in terms of another alias B, and then later redefine alias B, the value of alias A will not change.

If ATTR is not specified, coloralias() returns the standard attribute or attributes to which ALIAS is aliased, if any, or undef if ALIAS does not exist. If it is aliased to multiple attributes, the return value will be a single string and the attributes will be separated by spaces.

This is the same facility used by the ANSI_COLORS_ALIASES environment variable (see "ENVIRONMENT" below) but can be used at runtime, not just when the module is loaded.

Later invocations of coloralias() with the same ALIAS will override earlier aliases. There is no way to remove an alias.

Aliases have no effect on the return value of uncolor().

WARNING: Aliases are global and affect all callers in the same process. There is no way to set an alias limited to a particular block of code or a particular object.

Constant Interface

Alternately, if you import ":constants", you can use the following constants directly:

CLEAR           RESET             BOLD            DARK
FAINT           ITALIC            UNDERLINE       UNDERSCORE
BLINK           REVERSE           CONCEALED
BLACK           RED               GREEN           YELLOW
BLUE            MAGENTA           CYAN            WHITE
BRIGHT_BLACK    BRIGHT_RED        BRIGHT_GREEN    BRIGHT_YELLOW
BRIGHT_BLUE     BRIGHT_MAGENTA    BRIGHT_CYAN     BRIGHT_WHITE
ON_BLACK        ON_RED            ON_GREEN        ON_YELLOW
ON_BLUE         ON_MAGENTA        ON_CYAN         ON_WHITE
ON_BRIGHT_BLACK ON_BRIGHT_RED     ON_BRIGHT_GREEN ON_BRIGHT_YELLOW
ON_BRIGHT_BLUE  ON_BRIGHT_MAGENTA ON_BRIGHT_CYAN  ON_BRIGHT_WHITE

These are the same as color('attribute') and can be used if you prefer typing:

print BOLD BLUE ON_WHITE "Text", RESET, "\n";

to

print colored ("Text", 'bold blue on_white'), "\n";

(Note that the newline is kept separate to avoid confusing the terminal as described above since a background color is being used.)

If you import ":constants256", you can use the following constants directly:

ANSI0 .. ANSI255
GREY0 .. GREY23
RGBXYZ (for X, Y, and Z values from 0 to 5, like RGB000 or RGB515)
ON_ANSI0 .. ON_ANSI255
ON_GREY0 .. ON_GREY23
ON_RGBXYZ (for X, Y, and Z values from 0 to 5)

Note that ":constants256" does not include the other constants, so if you want to mix both, you need to include ":constants" as well. You may want to explicitly import at least "RESET", as in:

use Term::ANSIColor 4.00 qw(RESET :constants256);

True color and aliases are not supported by the constant interface.

When using the constants, if you don't want to have to remember to add the ", RESET" at the end of each print line, you can set $Term::ANSIColor::AUTORESET to a true value. Then, the display mode will automatically be reset if there is no comma after the constant. In other words, with that variable set:

print BOLD BLUE "Text\n";

will reset the display mode afterward, whereas:

print BOLD, BLUE, "Text\n";

will not. If you are using background colors, you will probably want to either use say() (in newer versions of Perl) or print the newline with a separate print statement to avoid confusing the terminal.

If $Term::ANSIColor::AUTOLOCAL is set (see below), it takes precedence over $Term::ANSIColor::AUTORESET, and the latter is ignored.

The subroutine interface has the advantage over the constants interface in that only two subroutines are exported into your namespace, versus thirty-eight in the constants interface, and aliases and true color attributes are supported. On the flip side, the constants interface has the advantage of better compile time error checking, since misspelled names of

les couleurs ou attributs dans les appels à color() et colored() ne seront pas détectés avant l'exécution, tandis que les noms de constantes mal orthographiés seront détectés à la compilation. Ainsi, polluez votre espace de noms avec près de deux douzaines de sous-routines que vous n'utiliserez peut-être même pas souvent, ou risquez un bug stupide en faisant une faute de frappe dans un attribut. À vous de choisir, TMTOWTDI après tout.

La pile de couleurs

Vous pouvez importer ":pushpop" et maintenir une pile de couleurs en utilisant PUSHCOLOR, POPCOLOR et LOCALCOLOR. PUSHCOLOR prend la chaîne d'attributs qui commence son argument et la place sur une pile d'attributs. POPCOLOR retire le sommet de la pile et restaure les attributs précédents définis par l'argument d'un PUSHCOLOR précédent. LOCALCOLOR entoure son argument d'un PUSHCOLOR et d'un POPCOLOR afin que la couleur soit réinitialisée par la suite.

Si $Term::ANSIColor::AUTOLOCAL est défini, chaque séquence de constantes de couleur sera implicitement précédée par LOCALCOLOR. En d'autres termes, ce qui suit :

{
    local $Term::ANSIColor::AUTOLOCAL = 1;
    print BLUE "Texte\n";
}

est équivalent à :

print LOCALCOLOR BLUE "Texte\n";

Si $Term::ANSIColor::AUTOLOCAL est défini, il a la priorité sur $Term::ANSIColor::AUTORESET, et ce dernier est ignoré.

Lors de l'utilisation de PUSHCOLOR, POPCOLOR et LOCALCOLOR, il est particulièrement important de ne pas mettre de virgules entre les constantes.

print PUSHCOLOR BLUE "Texte\n";

poussera correctement BLUE au sommet de la pile.

print PUSHCOLOR, BLUE, "Texte\n";    # incorrect !

ne le fera pas, et un pop ultérieur ne restaurera pas les attributs corrects. PUSHCOLOR pousse les attributs définis par son argument, qui est normalement une chaîne de constantes de couleur. Il ne peut pas demander au terminal quels sont les attributs actuels.

Support de CLICOLOR

https://bixense.com/clicolors/ propose une norme pour activer et désactiver la sortie couleur des commandes console en utilisant deux variables d'environnement, CLICOLOR et CLICOLOR_FORCE. Term::ANSIColor ne peut pas prendre en charge automatiquement cette norme, car l'action correcte dépend de la destination de la sortie et Term::ANSIColor peut être utilisé dans un contexte où les couleurs doivent toujours être générées même si CLICOLOR est défini dans l'environnement. Mais vous pouvez utiliser la variable d'environnement prise en charge ANSI_COLORS_DISABLED pour implémenter CLICOLOR dans vos propres programmes avec du code comme ceci :

if (exists($ENV{CLICOLOR}) && $ENV{CLICOLOR} == 0) {
    if (!$ENV{CLICOLOR_FORCE}) {
        $ENV{ANSI_COLORS_DISABLED} = 1;
    }
}

Si vous utilisez l'interface de constantes, assurez-vous d'inclure ce code avant d'utiliser des constantes de couleur (telles qu'au tout début de votre script), car cette variable d'environnement n'est prise en compte que lors de la première utilisation d'une constante de couleur.

Soyez conscient que cela exportera ANSI_COLORS_DISABLED aux processus enfants de votre programme également.

DIAGNOSTICS

Mauvais mappage de couleur %s
(W) Le mappage de couleur spécifié par ANSI_COLORS_ALIASES n'est pas valide et n'a pas pu être analysé. Il a été ignoré.
Mauvaise séquence d'échappement %s
(F) Vous avez passé une séquence d'échappement ANSI invalide à uncolor().
Mot nu "%s" non autorisé lorsque "strict subs" est actif
(F) Vous avez probablement fait une faute de frappe dans le nom d'une constante de couleur, par exemple : 
$Foobar = FOOBAR . "Cette ligne devrait être bleue\n";

ou :

@Foobar = FOOBAR, "Cette ligne devrait être bleue\n";

Cela n'apparaîtra que sous `use strict` (une autre bonne raison de fonctionner sous `use strict`).

Impossible d'aliaser la couleur standard %s
(F) Le nom d'alias passé à coloralias() correspond à un nom de couleur standard. Les noms de couleurs standard ne peuvent pas être renommés.
Impossible d'aliaser la couleur standard %s dans %s
(W) Identique, mais dans ANSI_COLORS_ALIASES. Le mappage de couleur a été ignoré.
Nom "%s" utilisé une seule fois : faute de frappe possible
(W) Vous avez probablement fait une faute de frappe dans le nom d'une constante de couleur, par exemple : 
print FOOBAR "Ce texte est de couleur FOOBAR\n";

Il est probablement préférable d'utiliser toujours des virgules après les noms de constantes afin de forcer l'erreur suivante.

Pas de virgule autorisée après le descripteur de fichier
(F) Vous avez probablement fait une faute de frappe dans le nom d'une constante de couleur, par exemple : 
print FOOBAR, "Ce texte est de couleur FOOBAR\n";

Générer cette erreur de compilation fatale est l'un des principaux avantages de l'utilisation de l'interface de constantes, car vous saurez immédiatement si vous faites une faute de frappe dans un nom de couleur.

Pas de nom pour la séquence d'échappement %s
(F) La séquence d'échappement ANSI passée à uncolor() contient des échappements qui ne sont pas reconnus et ne peuvent pas être traduits en noms.

ENVIRONNEMENT

ANSI_COLORS_ALIASES
Cette variable d'environnement permet à l'utilisateur de spécifier des alias de couleur personnalisés qui seront compris par color(), colored() et colorvalid(). Aucune des autres fonctions ne sera affectée, et aucune nouvelle constante de couleur ne sera créée. Les couleurs personnalisées sont des alias pour des noms de couleurs existants ; aucune nouvelle séquence d'échappement ne peut être introduite. Seuls les caractères alphanumériques, ".", "_" et "-" sont autorisés dans les noms d'alias.

Le format est :

ANSI_COLORS_ALIASES='nouvellecouleur1=anciennescouleur1,nouvellecouleur2=anciennescouleur2'

Les espaces blancs sont ignorés. La valeur de l'alias peut être un seul attribut ou une liste d'attributs séparés par des espaces.

Par exemple, les couleurs Solarized https://ethanschoonover.com/solarized peuvent être mappées avec :

ANSI_COLORS_ALIASES='\
    base00=bright_yellow, on_base00=on_bright_yellow,\
    base01=bright_green,  on_base01=on_bright_green, \
    base02=black,         on_base02=on_black,        \
    base03=bright_black,  on_base03=on_bright_black, \
    base0=bright_blue,    on_base0=on_bright_blue,   \
    base1=bright_cyan,    on_base1=on_bright_cyan,   \
    base2=white,          on_base2=on_white,         \
    base3=bright_white,   on_base3=on_bright_white,  \
    orange=bright_red,    on_orange=on_bright_red,   \
    violet=bright_magenta,on_violet=on_bright_magenta'

Cette variable d'environnement est lue et appliquée lorsque le module Term::ANSIColor est chargé, puis ignorée par la suite. Les modifications apportées à ANSI_COLORS_ALIASES après le chargement du module n'auront aucun effet. Voir coloralias() pour une fonctionnalité équivalente qui peut être utilisée à l'exécution.

ANSI_COLORS_DISABLED
Si cette variable d'environnement est définie sur une valeur vraie, toutes les fonctions définies par ce module (color(), colored(), et toutes les constantes) ne généreront aucune séquence d'échappement et retourneront plutôt la chaîne vide ou transmettront le texte original comme approprié. Ceci est destiné à faciliter l'utilisation de scripts utilisant ce module sur des plateformes qui ne prennent pas en charge les séquences d'échappement ANSI.
NO_COLOR
Si cette variable d'environnement est définie sur n'importe quelle valeur, elle supprime la génération des séquences d'échappement comme si ANSI_COLORS_DISABLED était défini sur une valeur vraie. Ceci implémente la norme informelle https://no-color.org/. Les programmes qui souhaitent activer la couleur malgré la présence de NO_COLOR devront désélectionner cette variable d'environnement avant d'utiliser une constante ou une fonction fournie par ce module.

COMPATIBILITÉ

Term::ANSIColor a été inclus pour la première fois avec Perl dans Perl 5.6.0.

La fonction uncolor() et le support de ANSI_COLORS_DISABLED ont été ajoutés dans Term::ANSIColor 1.04, inclus dans Perl 5.8.0.

Le support de dark a été ajouté dans Term::ANSIColor 1.08, inclus dans Perl 5.8.4.

La pile de couleurs, y compris la balise d'importation ":pushpop", PUSHCOLOR, POPCOLOR, LOCALCOLOR, et la variable $Term::ANSIColor::AUTOLOCAL, a été ajoutée dans Term::ANSIColor 2.00, inclus dans Perl 5.10.1.

colorstrip() a été ajouté dans Term::ANSIColor 2.01 et colorvalid() a été ajouté dans Term::ANSIColor 2.02, tous deux inclus dans Perl 5.11.0.
