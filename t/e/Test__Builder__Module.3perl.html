Test::Builder::Module(3perl) Guide du programmeur Perl Test::Builder::Module(3perl)

NOM

Test::Builder::Module - Classe de base pour les modules de test

SYNOPIS

# Émule Test::Simple
package Votre::Module;
my $CLASSE = __PACKAGE__;
use parent 'Test::Builder::Module';
@EXPORT = qw(ok);
sub ok ($;$) {
    my $tb = $CLASSE->builder;
    return $tb->ok(@_);
}

1;

DESCRIPTION

Ceci est une super-classe pour les modules basés sur Test::Builder. Elle fournit une poignée de fonctionnalités communes et une méthode pour accéder à l'objet Test::Builder sous-jacent.

Importation

Test::Builder::Module est une sous-classe de Exporter, ce qui signifie que votre module est également une sous-classe de Exporter. @EXPORT, @EXPORT_OK, etc... agissent normalement.

Quelques méthodes sont fournies pour gérer la partie "use Votre::Module tests => 23".

import

Test::Builder::Module fournit une méthode import() qui agit de la même manière fondamentale que celle de Test::More, en définissant le plan et en contrôlant l'exportation de fonctions et de variables. Cela permet à votre module de définir le plan indépendamment de Test::More.

Tous les arguments passés à import() sont transmis à "Votre::Module->builder->plan()" à l'exception de "import =>[qw(éléments à importer)]".

use Votre::Module import => [qw(ceci cela)], tests => 23;

indique d'importer les fonctions ceci() et cela() ainsi que de définir le plan à 23 tests.

import() définit également l'attribut exported_to() de votre builder comme étant l'appelant de la fonction import().

Des comportements supplémentaires peuvent être ajoutés à votre méthode import() en redéfinissant import_extra().

import_extra

Votre::Module->import_extra(\@args_import);

import_extra() est appelé par import(). Il offre une opportunité d'ajouter des comportements à votre module en fonction de sa liste d'importation.

Tous les arguments supplémentaires qui ne devraient pas être transmis à plan() devraient être retirés par cette méthode.

Voir Test::More pour un exemple de son utilisation.

NOTE Ce mécanisme est TRÈS ALPHA ET SUSCEPTIBLE DE CHANGER car il semble un peu bancal dans sa forme actuelle.

Builder

Test::Builder::Module fournit quelques méthodes pour accéder à l'objet Test::Builder sous-jacent.

builder

my $builder = Votre::Classe->builder;

Cette méthode retourne l'objet Test::Builder associé à Votre::Classe. Ce n'est pas un constructeur, vous pouvez donc l'appeler autant de fois que vous le souhaitez.

C'est la manière préférée d'obtenir l'objet Test::Builder. Vous ne devriez pas l'obtenir via "Test::Builder->new" comme cela était précédemment recommandé.

L'objet retourné par builder() peut changer à l'exécution, vous devriez donc appeler builder() dans chaque fonction plutôt que de le stocker dans une variable globale.

sub ok {
    my $builder = Votre::Classe->builder;
    return $builder->ok(@_);
}
