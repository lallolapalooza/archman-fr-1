Text::BibTeX::Name(3pm) Documentation Perl fournie par l'utilisateur Text::BibTeX::Name(3pm)

NOM

Text::BibTeX::Name - interface pour les noms d'auteurs au format BibTeX

SYNTAXE

use Text::BibTeX::Name;
$name = Text::BibTeX::Name->new();
$name->split('J. Random Hacker');
# ou :
$name = Text::BibTeX::Name->new('J. Random Hacker');
@firstname_tokens = $name->part ('first');
$lastname = join (' ', $name->part ('last'));
$format = Text::BibTeX::NameFormat->new();
# ...personnaliser $format...
$formatted = $name->format ($format);

DESCRIPTION

"Text::BibTeX::Name" fournit une abstraction pour les noms au format BibTeX et quelques opérations de base sur ceux-ci. Un nom, dans le monde BibTeX, se compose d'une liste de jetons qui sont divisés en quatre parties : `first' (prénom), `von' (particule), `last' (nom de famille) et `jr' (suffixe).

Les jetons sont séparés par des espaces blancs ou des virgules au niveau d'accolade zéro. Ainsi, le nom

van der Graaf, Horace Q.

a cinq jetons, tandis que le nom

{Foo, Bar, and Sons}

se compose d'un seul jeton. Descendez à "EXEMPLES" pour plus d'exemples, ou lisez la suite si vous souhaitez connaître les détails exacts de la manière dont les noms sont divisés en jetons et en parties.

La manière dont les jetons sont divisés en parties dépend de la forme du nom. Si le nom ne contient pas de virgules au niveau d'accolade zéro (comme dans le deuxième exemple), il est supposé être sous forme "prénom nom" ou "prénom particule nom". S'il n'y a pas de jetons commençant par une lettre minuscule, la forme "prénom nom" est supposée : le dernier jeton est le nom de famille, et tous les autres jetons forment le prénom. Sinon, la plus ancienne séquence contiguë de jetons avec des lettres initiales minuscules est considérée comme la partie `von' ; si cette séquence inclut le jeton final, un avertissement est affiché et le jeton final est forcé d'être la partie `last'.

Si un nom contient une seule virgule, il est supposé être sous forme "particule nom, prénom". Une séquence initiale de jetons avec des lettres initiales minuscules, s'il y en a, forme la partie `von' ; les jetons entre le `von' et la virgule forment la partie `last' ; les jetons suivant la virgule forment la partie `first'. Là encore, s'il n'y a pas de jetons suivant une séquence initiale de jetons minuscules, un avertissement est affiché et le jeton immédiatement précédant la virgule est considéré comme la partie `last'.

Si un nom contient plus de deux virgules, un avertissement est affiché et le nom est traité comme s'il n'y avait que les deux premières virgules.

Enfin, si un nom contient deux virgules, il est supposé être sous forme "particule nom, suffixe, prénom". (C'est la seule façon de représenter un nom avec une partie `jr'.) L'analyse du nom est la même que pour un nom avec une virgule, sauf que les jetons entre les deux virgules sont considérés comme la partie `jr'.

MISE EN GARDE

Le code C qui effectue le travail réel de division des noms prend un raccourci et fait peu d'hypothèses sur les espaces blancs. En particulier, il ne doit y avoir aucun espace blanc initial, aucun espace blanc final, aucun caractère d'espacement consécutif dans la chaîne, et aucun caractère d'espacement autre que l'espace. En d'autres termes, tous les espaces blancs doivent être constitués d'espaces internes isolés.

EXEMPLES

Les chaînes "John Smith" et "Smith, John" sont des représentations différentes du même nom, elles sont donc divisées en parties et en jetons de la même manière, à savoir :

first => ('John')
von   => ()
last  => ('Smith')
jr    => ()

Notez que chaque partie est une liste de jetons, même s'il n'y a qu'un seul jeton dans cette partie ; les parties vides obtiennent des listes de jetons vides. Chaque jeton n'est qu'une chaîne de caractères. Écrire cet exemple en code réel est simple :

$name = Text::BibTeX::Name->new("John Smith");  # ou "Smith, John"
$name->part ('first');       # retourne la liste ("John")
$name->part ('last');        # retourne la liste ("Smith")
$name->part ('von');         # retourne la liste ()
$name->part ('jr');          # retourne la liste ()

(Nous omettrons les parties vides dans le reste des exemples : supposez simplement que toute partie non mentionnée est une liste vide.) Si plus de deux jetons sont inclus et qu'il n'y a pas de virgule, ils iront au prénom : ainsi "John Q. Smith" se divise en

first => ("John", "Q.")
last  => ("Smith")

et "J. R. R. Tolkein" en

first => ("J.", "R.", "R.")
last  => ("Tolkein")

Le nom ambigu "Kevin Philips Bong" se divise en

first => ("Kevin", "Philips")
last  => ("Bong")

ce qui peut ou non être correct, selon la personne. Il n'y a cependant aucun moyen de le savoir, donc si le nom de famille de cette personne est "Philips Bong" et non "Bong", la représentation sous forme de chaîne de son nom doit lever l'ambiguïté. Une possibilité est "Philips Bong, Kevin" qui se divise en

first => ("Kevin")
last  => ("Philips", "Bong")

Alternativement, "Kevin {Philips Bong}" tire parti du fait que les jetons ne sont séparés que par des espaces blancs *au niveau d'accolade zéro*, et devient

first => ("Kevin")
last  => ("{Philips Bong}")

ce qui convient si vos noms sont destinés à être traités par TeX, mais pourrait poser problème dans d'autres contextes. De même, "St John-Mollusc, Oliver" devient

first => ("Oliver")
last  => ("St", "John-Mollusc")

ce qui peut également s'écrire "Oliver {St John-Mollusc}" :

first => ("Oliver")
last  => ("{St John-Mollusc}")

Étant donné que les jetons sont séparés uniquement par des espaces blancs, les noms avec trait d'union fonctionneront dans les deux sens : "Nigel Incubator-Jones" et "Incubator-Jones, Nigel" donnent tous deux

first => ("Nigel")
last  => ("Incubator-Jones")

Les noms de famille composés de plusieurs jetons avec des composantes en minuscules - la partie "von" - fonctionnent bien : "Ludwig van Beethoven" et "van Beethoven, Ludwig" sont analysés (correctement) en

first => ("Ludwig")
von   => ("van")
last  => ("Beethoven")

ce qui permet à ces noms aristocratiques européens de trier correctement, c'est-à-dire van Beethoven sous B plutôt que sous v. En parlant de noms européens aristocratiques, "Charles Louis Xavier Joseph de la Vall{\'e}e Poussin" est traité sans problème, et se divise en

first => ("Charles", "Louis", "Xavier", "Joseph")
von   => ("de", "la")
last  => ("Vall{\'e}e", "Poussin")

il pourrait donc être trié sous V plutôt que sous d. (Notez que l'algorithme de tri dans Text::BibTeX::BibSort est une imitation servile de BibTeX 0.99, et fait donc la mauvaise chose avec ces noms : la clé de tri commence par la partie "von".)

Cependant, les "parties von" capitalisées ne fonctionnent pas très bien : "R. J. Van de Graaff" se divise en

first => ("R.", "J.", "Van")
von   => ("de")
last  => ("Graaff")

ce qui est clairement faux. Ce nom devrait être représenté par "Van de Graaff, R. J."

first => ("R.", "J.")
last  => ("Van", "de", "Graaff")

ce qui est probablement correct. (Ce Van de Graaff particulier était un Américain, il devrait donc probablement être classé sous V - ce qui est là où mon dictionnaire (britannique) le classe. Les miles des autres Van de Graaff peuvent varier.)

Enfin, de nombreux noms incluent un suffixe : "Jr.", "III", "fils", etc. Ceux-ci sont gérés, mais avec quelques limitations. S'il y a une virgule avant le suffixe (la convention américaine habituelle pour "Jr."), alors le nom doit être sous forme *nom, suffixe, prénom*, par exemple "Doe, Jr., John" donne (correctement) :

first => ("John")
last  => ("Doe")
jr    => ("Jr.")

mais "John Doe, Jr." est ambigu

Text::BibTeX::Name(3pm)

NAME

Text::BibTeX::Name - split and format bibliographic names

SYNOPSIS

    use Text::BibTeX::Name;

    my $name = Text::BibTeX::Name->new('John von Neumann');
    # or
    my $name = Text::BibTeX::Name->new(
        { binmode => 'utf-8', normalization => 'NFD' },
        'John von Neumann'
    );

    my @first = $name->part('first');
    my @von   = $name->part('von');
    my @last  = $name->part('last');
    my @jr    = $name->part('jr');

    # Formatting
    use Text::BibTeX::NameFormat;
    my $formatter = Text::BibTeX::NameFormat->new( format => 'von, last, first jr' );
    my $formatted = $name->format($formatter); # "Neumann, John von"

DESCRIPTION

This module provides a simple way to split a bibliographic name (as found in BibTeX databases) into its constituent parts: first name(s), middle name(s) / particle(s) (e.g., "von", "de la"), last name(s), and suffix (e.g., "Jr.", "III").

The name splitting is performed by the "split" method, which takes a string containing a single name and breaks it down based on commas and capitalization. The parts are stored internally and can be retrieved using the "part" method.

Formatting the name back into a human-readable string according to various conventions is handled by the "format" method, which requires a "Text::BibTeX::NameFormat" object. See the documentation for that module for details.

CAVEAT

The name splitting algorithm is necessarily heuristic. It's designed to work reasonably well for the vast majority of Western names, but it can be fooled. If you encounter a name that doesn't parse correctly, you may need to resort to the curly brace trick explained below.

EXAMPLES

The basic idea is that names are split into parts based on commas at brace-depth zero. Everything before the first comma is considered the last name (potentially including a particle), and everything after is considered the first name (potentially including a suffix). For example, "von Neumann, John" is split into

first => ("John")
von   => ("von")
last  => ("Neumann")

If there are multiple words before the comma, they are all treated as last name or particle, depending on capitalization. For example, "de la Vall{\'e}e Poussin, Charles Louis Xavier Joseph" splits as:

first => ("Charles", "Louis", "Xavier", "Joseph")
von   => ("de", "la")
last  => ("Vall{\'e}e", "Poussin")

If there are multiple words after the comma, they are all treated as first names. However, suffixes like "Jr." or "III" are a problem. If they are preceded by a comma, they are correctly identified as suffixes:

"Doe, John Jr."

This is parsed as

first => ("John")
last  => ("Doe")
jr    => ("Jr.")

But if there's no comma before the suffix -- the usual for Roman numerals, and occasionally seen with "Jr." -- then you're stuck and have to make the suffix part of the last name. Thus, "Gates III, William H." comes out

first => ("William", "H.")
last  => ("Gates", "III")

but "William H. Gates III" is ambiguous, and becomes

first => ("William", "H.", "Gates")
last  => ("III")

-- not what you want. Again, the curly-brace trick comes in handy, so "William H. {Gates III}" splits into

first => ("William", "H.")
last  => ("{Gates III}")

There is no way to make a comma-less suffix the "jr" part. (This is an unfortunate consequence of slavishly imitating BibTeX 0.99.)

Finally, names that aren't really names of people but rather are organization or company names should be forced into a single token by wrapping them in curly braces. For example, "Foo, Bar and Sons" should be written "{Foo, Bar and Sons}", which will split as

last  => ("{Foo, Bar and Sons}")

Of course, if this is one name in a BibTeX "authors" or "editors" list, this name has to be wrapped in braces anyways (because of the " and "), but that's another story.

FORMATTING NAMES

Putting a split-up name back together again in a flexible, customizable way is the job of another module: see Text::BibTeX::NameFormat.

METHODS

new([OPTS,] NAME [, FILENAME, LINE, NAME_NUM])
Creates a new "Text::BibTeX::Name" object. If NAME is supplied, it must be a string containing a single name, and it will be be passed to the "split" method for further processing. FILENAME, LINE, and NAME_NUM, if present, are all also passed to "split" to allow better error messages.

If the first argument is a hash reference, it is used to define configuration values. At the moment the available values are:

BINMODE
Set the way Text::BibTeX deals with strings. By default it manages strings as bytes. You can set BINMODE to 'utf-8' to get NFC normalized UTF-8 strings and you can customise the normalization with the NORMALIZATION option. 
Text::BibTeX::Name->new(
       { binmode => 'utf-8', normalization => 'NFD' },
       "Alberto Simões"});
split (NAME [, FILENAME, LINE, NAME_NUM])
Splits NAME (a string containing a single name) into tokens and subsequently into the four parts of a BibTeX-style name (first, von, last, and jr). (Each part is a list of tokens, and tokens are separated by whitespace or commas at brace-depth zero. See above for full details on how a name is split into its component parts.)

The token-lists that make up each part of the name are then stored in the "Text::BibTeX::Name" object for later retrieval or formatting with the "part" and "format" methods.

part (PARTNAME)
Returns the list of tokens in part PARTNAME of a name previously split with "split". For example, suppose a "Text::BibTeX::Name" object is created and initialized like this: 
$name = Text::BibTeX::Name->new();
$name->split ('Charles Louis Xavier Joseph de la Vall{\'e}e Poussin');

Then this code:

$name->part ('von');

would return the list "('de','la')".

format (FORMAT)
Formats a name according to the specifications encoded in FORMAT, which should be a "Text::BibTeX::NameFormat" (or descendant) object. (In short, it must supply a method "apply" which takes a "Text::BibTeX::NameFormat" object as its only argument.) Returns the formatted name as a string.

See Text::BibTeX::NameFormat for full details on formatting names.

SEE ALSO

Text::BibTeX::Entry, Text::BibTeX::NameFormat, bt_split_names.
