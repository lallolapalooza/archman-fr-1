Test2::API::InterceptResult::Event(3perl) Guide du programmeur Perl Test2::API::InterceptResult::Event(3perl)

NOM

Test2::API::InterceptResult::Event - Représentation d'un événement pour les tests d'autres outils de test.

DESCRIPTION

"intercept { ... }" de Test2::API retourne une instance de Test2::API::InterceptResult, qui est un tableau référencé béni (blessed arrayref) d'objets Test2::API::InterceptResult::Event.

Ce POD documente les méthodes de ces événements, qui sont principalement fournies pour que vous puissiez les utiliser lors du test de vos outils de test.

SYNOPSIS

use Test2::V0;
use Test2::API qw/intercept/;
my $events = intercept {
    ok(1, "Une assertion réussie");
    plan(1);
};
# Ceci convertira tous les événements en instances de
# Test2::API::InterceptResult::Event. Jusqu'à ce que nous fassions cela, ce sont les
# instances originales de Test::Event::*
$events->upgrade(in_place => 1);
# Maintenant, nous pouvons obtenir des événements individuels sous cette forme
my $assert = $events->[0];
my $plan   = $events->[1];
# Ou nous pouvons opérer sur tous les événements simultanément :
my $flattened = $events->flatten;
is(
    $flattened,
    [
      {
        causes_failure => 0,
        name => 'Une assertion réussie',
        pass => 1,
        trace_file => 'xxx.t',
        trace_line => 5,
      },
      {
        causes_failure => 0,
        plan => 1,
        trace_file => 'xxx.t',
        trace_line => 6,
      },
    ],
    "A aplati les deux événements et retourné un tableau référencé des résultats
);

MÉTHODES

!!! NOTES IMPORTANTES SUR LA CONCEPTION !!!

Veuillez prêter attention à ce que ces méthodes retournent. Beaucoup retournent un scalaire lorsque c'est applicable, ou une liste vide lorsqu'il ne l'est pas (contrairement à undef). Beaucoup retournent toujours une liste de 0 ou plusieurs éléments. Certaines retournent toujours un scalaire. Notez qu'aucune des méthodes ne se soucie du contexte ; leur comportement est cohérent quel que soit le contexte scalaire, liste ou vide.

Ceci a été fait car cette classe a été spécifiquement conçue pour être utilisée dans une liste et générer plus de listes dans des opérations en masse. Parfois, dans une opération `map`, vous ne voulez rien pour un événement, et vous ne voulez pas un `undef` à sa place. En général, les instances d'événements uniques ne seront pas utilisées seules, bien que cela soit autorisé.

En règle générale, toute méthode précédée de "the_" implique que l'événement doit avoir exactement 1 élément du type spécifié, et une exception sera levée s'il y en a 0 ou plus d'un.

ATTRIBUTS

$hashref = $event->facet_data
Ceci retournera le hashref des données de facette, qui est tout ce dont Test2 se soucie pour un événement donné.
$class = $event->result_class
Ceci est normalement Test2::API::InterceptResult. Ceci est défini lors de la construction afin que les résultats de sous-tests puissent être transformés en instances de celle-ci à la demande.

DUPLICATION

$copy = $event->clone
Crée une copie profonde de l'événement. Modifier l'un ou l'autre événement n'affectera pas l'autre.

DONNÉES CONDENSÉES MULTI-FACETTES

$bool = $event->causes_failure
$bool = $event->causes_fail
Ce sont deux alias pour la même fonctionnalité.

Ceci retournera toujours une valeur vraie ou une valeur fausse. Cette méthode ne retourne jamais une liste.

Cette méthode peut être relativement lente (toujours super rapide) car elle détermine le succès ou l'échec en créant une instance de Test2::Hub et en lui demandant de traiter l'événement, puis demande au hub son état de succès/échec. C'est plus lent que de construire une logique pour effectuer la vérification, mais c'est plus fiable car cela vous dira toujours ce que le hub pense, donc la logique ne sera jamais obsolète par rapport à la logique Test2 qui s'en soucie réellement.

CHAÎNE_OU_LISTE_VIDE = $event->brief
Tous les événements n'ont pas de résumé (brief). Certains événements ne sont pas rendus par le formateur, d'autres n'ont pas de données de "résumé" qui valent la peine d'être vues. Lorsque c'est le cas, une liste vide est retournée. Ceci est fait intentionnellement afin qu'il puisse être utilisé dans une opération `map` sans avoir "undef" inclus dans le résultat.

Lorsqu'un résumé peut être généré, il s'agit toujours d'une seule chaîne sur une ligne, et il est retourné tel quel, pas dans une liste.

Résumés possibles :

# Provenant des facettes de contrôle
"INTERROMPU"
"INTERROMPU : $why"
# Provenant des facettes d'erreur
"ERREUR"
"ERREUR : $message"
"ERREUR : $partial_message [...]"
"ERREURS : $first_error_message [...]"
# Provenant des facettes d'assertion
"SUCCÈS"
"ÉCHEC"
"SUCCÈS avec amnistie"
"ÉCHEC avec amnistie"
# Provenant des facettes de plan
"PLAN $count"
"PAS DE PLAN"
"TOUT SAUTER"
"TOUT SAUTER : $why"

Notez que seul le premier résumé applicable est retourné. Ceci est essentiellement un TAP simplifié qui n'inclut que les facettes qui pourraient (mais pas nécessairement) causer un échec.

$hashref = $event->flatten
$hashref = $event->flatten(include_subevents => 1)
Ceci retourne TOUJOURS un hashref. Ceci place toutes les données les plus utiles pour les facettes les plus intéressantes dans un seul hashref pour une validation facile.

S'il n'y a pas de facettes significatives, ceci retournera un hashref vide.

Si le paramètre 'include_subevents' est donné, il inclura également les données des sous-tests :

Voici une liste de TOUS les champs possibles. Si un champ n'est pas applicable, il ne sera pas présent.

présent toujours
causes_failure => 1,    # Toujours présent
Présent si l'événement a une facette trace
trace_line    => 42,
trace_file    => 'Foo/Bar.pm',
trace_details => 'Détails de trace supplémentaires',    # habituellement absent
S'il y a une assertion présente

name => "1 + 1 = 2, donc les maths fonctionnent",
S'il y a un plan :

S'il y a des facettes d'amnistie :
Vous obtenez un tableau pour chaque type présent.

    "Je corrigerai cela plus tard",
    "Je promets de corriger ceux-ci",
],

... => ["Autre amnistie"]
S'il y a des facettes Info (note/diag) :
Vous obtenez un tableau référencé pour tous ceux qui sont présents, la clé n'est pas définie s'ils ne sont pas présents.

    "Vous avez oublié de lacer vos chaussures",

S'il y a des facettes d'erreur :
Toujours un tableau référencé.

    "Erreur non fatale (ne cause pas l'échec du test, juste une information)",
    "FATALE : Ceci est une erreur fatale (cause un échec)",
],
# Les erreurs peuvent avoir des étiquettes alternatives, mais en pratique, elles sont toujours 'error',
# listé ici pour la complétude.
... => [ ... ]
Présent si l'événement est un sous-test
subtest => {
    count      => 2,    # Nombre d'assertions effectuées
    failed     => 1,    # Nombre d'échecs de tests observés
    is_passing => 0,    # Booléen, vrai si le test réussissait
                        # après le traitement des événements.
    plan         => 2,  # Plan, soit un nombre, undef, 'SKIP', ou 'NO PLAN'
    follows_plan => 1,  # Vrai s'il y a un plan et qu'il a été suivi.
                        # Faux si le plan et les assertions n'ont pas
                        # correspondu, undef s'il n'y avait pas de plan dans
                        # la liste d'événements.
    bailed_out => "foo",    # s'il y a eu un bail-out dans les
                            # événements, ceci sera une chaîne expliquant

Test2::Event::Abstract - Perl documentation

NAME

Test2::Event::Abstract - Base class for all Test2 events

VERSION

1.302193

SYNOPSIS

use Test2::API;
use Test2::Event::Plan;
use Test2::Event::Ok;

my $plan = Test2::Event::Plan->new(num_planned => 1);
my $ok   = Test2::Event::Ok->new(
    ok      => 1,
    details => "this test passed",
    trace   => Test2::Trace->new(),
);

# Accessors defined on Test2::Event::Abstract
$plan->is_plan;
$ok->is_ok;

# Facet accessors
my $trace = $ok->trace; # get the trace facet

# Accessing raw data
my $hashref = $plan->{+SUPER}; # Get underlying hash data

DESCRIPTION

This is the base class for all events in the Test2 testing system. All events are objects that contain data about an event that has occurred during testing.

All events will have a common set of accessors: ok, details, diag, notes, trace, is_*, has_*, and the_*. These will be defined on the specific event classes.

API

This is a base class, so most of the API is defined in the subclasses of this class.

However, there are a few methods that are defined here:

subevent()
If the event has a sub_event (as is the case with most Test2::Event::Subtest events), this will return that sub_event. Otherwise it will return undef.
causes_failure()
Returns true if this event represents a failure. This is normally determined by the type of event, but can be overridden by the event itself.
is_always_ok()
Returns true if this event type is always considered OK. This is mostly used for events like Test2::Event::Plan that do not represent a pass/fail state in themselves.
bailout()
Returns the bailout information if a bail-out was requested for this event. This will return undef if no bail-out was requested.
skip_all()
Returns the reason for a skip_all if it was requested. Otherwise returns undef.
skip_reason()
Returns the reason for a skip if it was requested. Otherwise returns undef.

The following are methods that are part of the Test2 API that will be available on all event objects.

summary()
Returns a limited summary of the event. This is useful for displaying events without dumping all the data.
flatten()
This method is intended to be used on events that may contain other events (like Test2::Event::Subtest). It will return a list of all events contained within this event, recursively.

For example:

my @events = $subtest_event->flatten;

The result of calling flatten on a subtest event is a list of all events that occurred within that subtest.

If "(include_subtest => 1)" was provided as a parameter then the following will be included. This is the result of turning all subtest child events into an Test2::API::InterceptResult instance and calling the "flatten" method on it.

subevents => Test2::API::InterceptResult->new(@child_events)->flatten(...),

If a bail-out is being requested

If no reason was given this will be set to 1.

DIRECT ARBITRARY FACET ACCESS

@list_of_facets = $event->facet($name)
This always returns a list of 0 or more items. This fetches the facet instances from the event. For facets like 'assert' this will always return 0 or 1 item. For events like 'info' (diags, notes) this will return 0 or more instances, once for each instance of the facet.

These will be blessed into the proper Test2::EventFacet subclass. If no subclass can be found it will be blessed as an Test2::API::InterceptResult::Facet generic facet class.

$undef_or_facet = $event->the_facet($name)
If you know you will have exactly 1 instance of a facet you can call this.

If you are correct and there is exactly one instance of the facet it will always return the hashref.

If there are 0 instances of the facet this will return undef, not an empty list.

If there are more than 1 instance this will throw an exception because your assumption was incorrect.
