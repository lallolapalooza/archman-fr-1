NOM

Test2::Transition - Notes de transition lors de la mise à niveau vers Test2

DESCRIPTION

C'est ici que sont documentées les pièges et les ruptures liés à la mise à niveau de Test2. La mise à niveau fait que Test::Builder délègue à Test2 en arrière-plan. Cette transition est principalement transparente, mais il existe quelques cas qui peuvent vous piéger.

CHOSES QUI CASENT

Voici la liste des scénarios qui se cassent avec les nouvelles internes.

Conditions Test::Builder1.5/2

Le problème

il y a quelques années, il y a eu deux tentatives de mise à niveau/remplacement de Test::Builder. De manière déroutante, elles ont été nommées Test::Builder2 et Test::Builder1.5, dans cet ordre. Beaucoup de gens ont inséré des conditions dans leur code pour vérifier le numéro de version de Test::Builder et adapter leur code en conséquence.

Les projets Test::Builder2/1.5 sont tous deux morts. Maintenant, le code conditionnel que les gens ont ajouté est devenu un champ de mines. Une grande majorité de modules cassés par Test2 entrent dans cette catégorie.

La correction

La correction consiste à supprimer tout code lié à Test::Builder1.5/2. Utilisez soit l'API hérité de Test::Builder, soit Test2 directement.

Remplacement du singleton Test::Builder

Le problème

Certains modules de test remplaçaient l'instance singleton de Test::Builder par leur propre instance ou sous-classe. Cela était généralement fait pour intercepter ou modifier les résultats au fur et à mesure qu'ils se produisaient.

Le singleton Test::Builder est maintenant un simple wrapper de compatibilité autour de Test2. Le singleton Test::Builder n'est plus l'endroit central pour les résultats. De nombreux résultats contournent complètement le singleton Test::Builder, ce qui casse tout comportement prévu lors du remplacement du singleton.

La correction

Si vous souhaitez simplement intercepter tous les résultats au lieu de les laisser aller en TAP, vous devriez consulter la documentation de Test2::API et lire sur le fait de pousser un nouveau hub dans la pile de hubs. Remplacer le hub temporairement est maintenant la bonne façon d'intercepter les résultats.

Si votre objectif est purement la surveillance des événements, utilisez la méthode "Test2::Hub->listen()" exportée par Test::More pour observer les événements lorsqu'ils sont déclenchés. Si vous souhaitez modifier les résultats avant qu'ils ne soient envoyés en TAP, regardez la méthode "Test2::Hub->filter()".

Accès direct aux éléments de tableaux associatifs

Le problème

Certains modules regardent directement les clés de tableau associatif sur le singleton Test::Builder. Le problème ici est que le singleton Test::Builder ne contient plus rien d'important.

La correction

La correction consiste à utiliser l'API spécifiée dans Test2::API pour examiner ou modifier l'état si nécessaire.

Indentation des sous-tests

Le problème

Un changement précoce, en fait le changement qui a fait de Test2 une idée, a été un changement dans l'indentation de la note de sous-test. Il a été décidé qu'il serait plus lisible de désindenter la note du sous-test au lieu de l'avoir en ligne avec le sous-test :

# sous-test foo
    ok 1 - blah
    1..1
ok 1 - sous-test foo

L'ancien style indentait la note :

    # sous-test foo
    ok 1 - blah
    1..1
ok 1 - sous-test foo

Cela casse les tests qui font une comparaison de chaînes de caractères de la sortie TAP.

La correction

my $indent = $INC{'Test2/API.pm'} ? '' : '    ';
is(
    $subtest_output,
    "${indent}# subtest foo",
    "Got subtest note"
);

Vérifiez si $INC{'Test2/API.pm'} est défini, si c'est le cas, aucune indentation ne doit être attendue. S'il n'est pas défini, alors l'ancien Test::Builder est utilisé, une indentation doit être attendue.

DISTRIBUTIONS QUI CASENT OU QUI ONT BESOIN D'ÊTRE MISES À NIVEAU

Voici une liste de modules CPAN qui ont été connus pour avoir été cassés par la mise à niveau à un moment donné.

FONCTIONNE MAIS LES TESTS ÉCHOUERONT

Ces modules fonctionnent toujours correctement, mais leurs suites de tests ne passeront pas. Si vous avez déjà ces modules installés, vous pouvez continuer à les utiliser. Si vous essayez de les installer après avoir mis à niveau Test::Builder, vous devrez forcer l'installation ou contourner les tests cassés.

Test::DBIx::Class::Schema
Ce module a un test qui semble contourner un bug de Test::Builder. Le bug semble avoir été corrigé par Test2, ce qui signifie que le contournement provoque un échec. Cela peut être facilement mis à jour, mais personne ne l'a encore fait.

Versions connues cassées : 1.0.9 et antérieures

Device::Chip
Les tests échouent en raison de l'indentation des sous-tests.

Connu pour être cassé dans la version 0.07. Semble fonctionner correctement dans la version 0.06 cependant. Un correctif a été soumis pour résoudre le problème.

MISE À NIVEAU SUGGÉRÉE

Ce sont des modules qui n'ont pas été cassés, mais dont les suites de tests cassées ont depuis été corrigées.

Test::Exception
Les anciennes versions fonctionnent correctement, mais ont un comportement mineur de nom de test qui se casse avec Test2. Les anciennes versions ne s'installeront plus à cause de cela. La dernière version sur CPAN s'installera sans problème. La mise à niveau n'est pas requise, mais est recommandée.

Corrigé dans la version : 0.43

Data::Peek
Certains tests dépendaient de modifications subtiles de $! et $?. Un correctif a été appliqué pour corriger les changements.

Le module lui-même fonctionne bien, il n'y a pas besoin de mettre à niveau.

Corrigé dans la version : 0.45

circular::require
Certains tests étaient fragiles et nécessitaient que base.pm soit chargé à un stade avancé. Test2 chargeait base.pm trop tôt. Les tests ont été mis à jour pour corriger cela.

Le module lui-même n'a jamais été cassé, vous n'avez pas besoin de le mettre à niveau.

Corrigé dans la version : 0.12

Test::Module::Used
Un test a contourné un bug de planification maintenant corrigé. Il n'y a pas besoin de mettre à niveau si vous avez une ancienne version installée. Les nouvelles versions s'installent sans problème si vous les souhaitez.

Corrigé dans la version : 0.2.5

Test::Moose::More
Certains tests étaient fragiles, mais ont été corrigés. La rupture réelle provenait du changement d'indentation du commentaire de sous-test.

Pas besoin de mettre à niveau, les anciennes versions fonctionnent bien. Seules les nouvelles versions s'installeront.

Corrigé dans la version : 0.025

Test::FITesque
Ceci a été cassé par une correction de bug sur la façon dont la planification est effectuée. Le test a été mis à jour après la correction du bug.

Corrigé dans la version : 0.04

Test::Kit
Les anciennes versions fonctionnent correctement, mais ne s'installeraient pas car Test::Aggregate était dans la chaîne de dépendances. Une mise à niveau ne devrait pas être nécessaire.

Corrigé dans la version : 2.15

autouse
Un test a échoué car il dépendait du fait que Scalar::Util ne soit pas chargé. Test2 charge Scalar::Util. Le test a été mis à jour pour charger Test2 après avoir vérifié l'état de chargement de Scalar::Util.

Il n'est pas nécessaire de mettre à niveau si vous l'avez déjà installé.

Corrigé dans la version : 1.11
