Test::PerlTidy(3) Documentation des contributeurs Perl Test::PerlTidy(3)

NOM

Test::PerlTidy - vérifier que tous tes fichiers sont bien formatés.

VERSION

version 20230226

SYNOPIS

# Dans un fichier comme 't/perltidy.t':
use Test::PerlTidy qw( run_tests );
run_tests();

DESCRIPTION

Cette mauvaise critique a été faite par Ken Arnold dans un article :

"Perl est un vaste lac de désordre lexical et syntaxique et personne ne sait comment formater son propre code correctement, mais c'est le seul langage majeur qui n'ait pas au moins un style qui soit bon."
          http://www.artima.com/weblogs/viewpost.jsp?thread=74230

Hmm... C'est presque vrai dans un sens. Bien que l'article qu'il a écrit soit lié à Python, qui est assez strict sur le formatage de son code.

Ne t'inquiète pas, tu peux maintenant avoir ta propre police de formatage dans le style de Test::PerlTidy ! Il suffit d'ajouter un fichier de test comme suggéré ci-dessus et tout fichier se terminant par .pl, .pm, .t ou .PL provoquera un échec de test s'il n'est pas exactement comme prévu lors de l'utilisation de perltidy.

RAISONS DE FAIRE CECI

Si le style est obligatoire dans les tests, il sera respecté.

Si perltidy décide quel style est bon, il n'y aura pas de débat.

Si le style ne change jamais, les diffs cvs s'arrêteront aux changements non réels.

Cela peut améliorer la lisibilité.

ASTUCES

Si tu veux changer le style par défaut, déplace le fichier '.perltidyrc' ;

Pour faire fonctionner rapidement un fichier, essaie 'perltidy -b the_messy_file.pl'.

COMMENT ÇA MARCHE

Exécute perltidy sur les fichiers et signale les erreurs si un fichier diffère après avoir été reformaté. Il ne modifie pas de façon permanente les fichiers testés.

Par défaut, perltidy s'exécutera sur les fichiers du répertoire actuel et de ses sous-répertoires avec des extensions correspondant à : ".pm .pl .PL .t"

MÉTHODES

run_tests ( [ path | %args ] )

C'est le point d'entrée principal pour exécuter les tests.

Des options peuvent être spécifiées lors de l'exécution des tests, par exemple :

run_tests(
          path       => $start_dir,
          perltidyrc => $path_to_config_file,
          exclude    => [ qr{\.t$}, 'inc/'],
);
debug
Définit "debug" à une valeur vraie pour activer une sortie diagnostique supplémentaire, notamment des informations sur tout traitement effectué suite à la spécification de l'option "exclude". La valeur par défaut est fausse.
exclude
run_tests() recherchera les fichiers à tester dans le répertoire courant et ses sous-répertoires. Par défaut, il exclut les fichiers dans le répertoire "./blib/". Si tu souhaites spécifier des règles supplémentaires par lesquelles les fichiers seront exclus, définis "exclude" à une liste de critères d'exclusion.

Si un élément de la liste "exclude" est une chaîne, par exemple "./blib/", on suppose qu'il s'agit d'un préfixe de chemin. Les fichiers seront exclus si cette chaîne correspond au début du chemin du fichier.

Si un élément de la liste "exclude" est un objet regex, par exemple "qr{\.t$}", les fichiers seront exclus si ce regex correspond à leur chemin.

Remarque : Les chemins des fichiers à tester sont canonisés en utilisant File::Spec"->canonpath" avant toute correspondance, ce qui peut affecter la manière dont les critères d'exclusion sont appliqués. Si tes critères d'exclusion ne semblent pas fonctionner, active l'option "debug" pour voir les chemins de fichiers qui sont conservés/exclus.

path
Définit "path" au chemin du répertoire racine contenant les fichiers à tester. Par défaut, c'est le répertoire courant (c'est-à-dire ".").
perltidyrc
Par défaut, perltidy tentera de lire ses options dans le fichier .perltidyrc de ton système. Si tu souhaites contrôler les options de perltidy pendant les tests, définis "perltidyrc" au chemin d'un fichier personnalisé.
mute
Par défaut, run_tests() affichera des diagnostics sur les erreurs signalées par perltidy, ainsi que les différences entre les fichiers avant et après leur reformatage. Définit "mute" à une valeur vraie pour désactiver cette sortie diagnostique.
skip_all
Définit "skip_all" à une valeur vraie pour ignorer tous les tests. La valeur par défaut est fausse.
perltidy_options
Transmet ceux à Perl::Tidy::perltidy(). (Ajouté dans la version 20200411).

list_files ( [ start_path | %args ] )

Génère la liste des fichiers à tester. Généralement pas appelé directement.

load_file ( path_to_file )

Charge le fichier à tester depuis le disque et renvoie son contenu. Généralement pas appelé directement.

is_file_tidy ( path_to_file [ , path_to_perltidyrc ] [, $named_args ] )

Teste si un fichier est bien formaté ou non. Généralement pas appelé directement.

$named_args peut être un hash ref qui peut avoir une clé appelée 'perltidy_options' qui fait référence à un hash ref d'options qui seront passées à Perl::Tidy::perltidy(). ($named_args a été ajouté dans la version 20200411).
