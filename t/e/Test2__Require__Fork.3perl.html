Test2::Require::Fork(3perl) Guide de référence du programmeur Perl Test2::Require::Fork(3perl)

NOM

Test2::Require::Fork - Ignorer un fichier de test sauf si le système prend en charge le fork

DESCRIPTION

Il est assez courant d'écrire des tests qui nécessitent un fork. Tous les systèmes ne prennent pas en charge le fork. Cette bibliothèque effectue le travail ardu de vérifier si le fork est pris en charge sur le système actuel. Si le fork n'est pas pris en charge, tous les tests seront ignorés et le programme se terminera avec succès.

SYNTAXE

use Test2::Require::Fork;
... Code qui fait un fork ...

EXPLICATION

Vérifier si le système actuel prend en charge le fork n'est pas simple. Voici un exemple de la façon de procéder :

use Config;
sub CAN_FORK {
    return 1 if $Config{d_fork};
    # Certaines plateformes utilisent les ithreads pour simuler le fork
    return 0 unless $^O eq 'MSWin32' || $^O eq 'NetWare';
    return 0 unless $Config{useithreads};
    return 0 unless $Config{ccflags} =~ /-DPERL_IMPLICIT_SYS/;
    # Les threads ne sont pas fiables avant 5.008001
    return 0 unless $] >= 5.008001;
    # Devel::Cover rompt actuellement avec les threads
    return 0 if $INC{'Devel/Cover.pm'};
    return 1;
}

Dupliquer ce code non trivial dans tous les tests qui nécessitent un fork est source d'erreurs. Il est facile d'oublier des parties ou de se tromper. En plus de ces vérifications, vous devez également indiquer à la suite de tests qu'aucun test ne doit être exécuté et pourquoi.

VOIR AUSSI

Test2::Require::RealFork
Similaire à ce module, mais ignorera tout perl qui n'a qu'une émulation de fork.
Test2::Require::Threads
Ignore le fichier de test si le système ne prend pas en charge les threads.
