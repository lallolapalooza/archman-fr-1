NOM

Test::Warnings - tester les avertissements et leur absence

VERSION

version 0.038

SYNOPSIS

use Test::More;
use Test::Warnings;
pass('yay!');
done_testing;

émet du TAP:

ok 1 - yay!
ok 2 - pas d'avertissements (inattendus) (via done_testing)
1..2

et:

use Test::More tests => 3;
use Test::Warnings 0.005 ':all';
pass('yay!');
like(warning { warn "oh noes!" }, qr/^oh noes/, 'nous avons averti');

émet du TAP:

ok 1 - yay!
ok 2 - nous avons averti
ok 3 - pas d'avertissements (inattendus) (via bloc END)
1..3

DESCRIPTION

Si vous avez essayé d'utiliser Test::NoWarnings pour confirmer qu'aucun avertissement n'est généré dans vos tests, combiné avec la commodité de "done_testing" pour éviter de déclarer un numéro de test, vous aurez découvert que ces deux éléments ne fonctionnent pas bien ensemble, car le numéro de test sera calculé *avant* que le test d'avertissement ne soit exécuté, ce qui entraînera une erreur TAP. (Voir "examples/test_nowarnings.pl" dans cette distribution pour une démonstration.)

Ce module est destiné à être utilisé comme substitut de Test::NoWarnings : il ajoute également un test supplémentaire, mais l'exécute *avant* que "done_testing" ne calcule le numéro de test, plutôt qu'après. Il le fait en accrochant "done_testing" ainsi qu'en utilisant un bloc "END". Vous pouvez déclarer un plan, ou non, et tout continuera de fonctionner.

C'est en fait équivalent à:

use Test::NoWarnings 1.04 ':early';

bien que les avertissements soient toujours affichés normalement lorsqu'ils se produisent. Vous êtes libre et heureux de faire un remplacement global de ce qui précède par "use Test::Warnings;", que vos tests aient un plan ou non.

Il peut également être utilisé comme substitut de Test::Warn, si vous souhaitez tester le contenu des avertissements attendus ; lisez la suite pour savoir comment.

FONCTIONS

Les fonctions suivantes sont disponibles pour l'importation (non incluses par défaut ; vous pouvez également toutes les obtenir via le tag ":all") :

allow_warnings([bool]) - EXPÉRIMENTAL - PEUT ÊTRE RETIRÉ

Lorsque cela est appelé avec une valeur vraie, ou aucun argument, les avertissements suivants ne généreront pas d'échec de test ; lorsqu'il est appelé avec une valeur fausse, les avertissements suivants généreront un échec de test. La valeur initiale est "false".

Lorsque les avertissements sont autorisés, tout avertissement sera émis via "Test::Builder::note".

"allowing_warnings" - EXPÉRIMENTAL - PEUT ÊTRE RETIRÉ

Retourne si nous autorisons actuellement les avertissements (comme décrit avec "allow_warnings").

"had_no_warnings(<nom de test optionnel>)"

Teste s'il y a des avertissements avant un appel à "allowing_warnings". S'exécute automatiquement à la fin de tous les tests, mais peut également être appelé manuellement à tout moment, auquel cas vous pouvez faire ce que vous voulez.

"warnings( { code } )"

Étant donné un bloc de code, exécute le bloc et retourne une liste de tous les avertissements (non autorisés au préalable via "allow_warnings") émis à l'intérieur. Cela vous permet de tester la présence d'avertissements qui non seulement seraient autorisés, mais *doivent* être émis. Aucune fonction de test n'est fournie ; vous pouvez tester ceux-ci avec vos propres fonctions de test, comme Test::More::is ou Test::Deep::cmp_deeply).

Vous pouvez utiliser cette construction comme substitut de Test::Warn::warnings_are:

is_deeply(
    [ warnings { ... } ],
    [
        'message d\'avertissement 1',
        'message d\'avertissement 2',
    ],
    'des avertissements sont attendus',
);

ou, pour substituer Test::Warn::warnings_like:

cmp_deeply(
    [ warnings { ... } ],
    bag(    # l'ordre des messages n'a pas d'importance
        re(qr/ message d'avertissement 1 /),
        re(qr/ message d'avertissement 2 /),
    ),
    'des avertissements sont attendus (dans n\'importe quel ordre)',
);

Les avertissements générés par ce bloc de code ne se propagent *pas* au-delà. Cependant, puisqu'ils sont retournés par cette fonction avec le nom de fichier et le numéro de ligne intacts, vous pouvez les réémettre immédiatement après avoir appelé warnings(...), si vous le souhaitez.

Note: "use Test::Warnings 'warnings'" vous donnera une sous-routine "warnings" dans votre espace de noms (très probablement "main", si vous écrivez un test), vous ne pourrez donc pas ensuite faire "warnings->import" — cela donnera une erreur : "Not enough arguments for Test::Warnings::warnings at ... near "warnings->import"". Pour éviter cela, utilisez soit la forme complète ("Test::warnings"), soit effectuez vos appels à la sous-routine "warnings" en premier.

"warning( { code } )"

C'est la même chose que "warnings( { code } )", sauf qu'elle retourne toujours un scalaire (le seul avertissement produit, s'il y en a eu un, ou un arrayref sinon), ce qui peut être plus pratique que warnings() si vous vous attendez à exactement un avertissement.

Nous vous recommandons cependant de capturer le résultat de warning() dans une variable temporaire afin de pouvoir imprimer sa valeur si elle ne contient pas ce que vous attendiez. Par exemple, avec ce test:

like(
    warning { foo() },
    qr/^ceci est un avertissement/,
    'un avertissement de foo() était attendu',
);

si vous obtenez deux avertissements (ou aucun) au lieu d'un, vous obtiendrez un arrayref, ce qui se traduira par un message de test peu utile comme:

#   Failed test 'un avertissement de foo() était attendu'
#   at t/mytest.t line 10.
#                   'ARRAY(0xdeadbeef)'
#     no match '(?^:^ceci est un avertissement)'

Par conséquent, modifiez votre test comme suit:

my $warning = warning { foo() };
like(
    $warning,
    qr/^ceci est un avertissement/,
    'un avertissement de foo() était attendu',
) or diag 'avertissements obtenus (ou aucun): ', explain($warning);

allow_patterns

allow_patterns(qr/ toujours autoriser cet avertissement /);
{
  my $temp = allow_patterns(qr/ autoriser uniquement dans cette portée /, qr/ un autre avertissement temporaire /);
  ... choses ...
}

Étant donné une ou plusieurs expressions régulières, sous forme "qr/.../", ajoutez-les à la liste d'autorisation (les avertissements seront émis avec "note" au lieu de déclencher le gestionnaire d'avertissements). Si la valeur retournée est stockée dans une variable locale, l'exemption d'avertissement ne s'appliquera que dans cette portée (l'ajout est annulé à la fin de la portée) ; sinon, l'effet sera global.

disallow_patterns

Étant donné une ou plusieurs expressions régulières, sous forme "qr/.../", retirez l'avertissement de la liste d'autorisation. L'expression doit correspondre exactement à une expression précédemment fournie à "allow_patterns".
