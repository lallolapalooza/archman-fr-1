Test2::API::Context(3perl) Guide de référence pour les programmeurs Perl Test2::API::Context(3perl)

NAME

Test2::API::Context - Objet représentant un contexte de test.

DESCRIPTION

L'objet contexte est l'interface principale pour les développeurs d'outils de test écrits avec Test2. L'objet contexte représente le contexte dans lequel un test est exécuté (nom de fichier et numéro de ligne), et fournit un moyen rapide de générer des événements à partir de ce contexte. L'objet contexte est également responsable de l'envoi des événements à la bonne instance de Test2::Hub.

SYNOPSIS

En général, vous ne créerez pas de contextes directement. Pour obtenir un contexte, vous devriez toujours utiliser context(), qui est exporté par le module Test2::API.

use Test2::API qw/context/;
sub my_ok {
    my ($bool, $name) = @_;
    my $ctx = context();
    if ($bool) {
        $ctx->pass($name);
    }
    else {
        $ctx->fail($name);
    }
    $ctx->release; # Vous devez faire cela !
    return $bool;
}

Les objets contexte facilitent l'enveloppement d'autres outils qui utilisent également un contexte. Une fois que vous avez obtenu un contexte, tout outil que vous appelez avant de libérer votre contexte héritera du contexte que vous avez :

sub wrapper {
    my ($bool, $name) = @_;
    my $ctx = context();
    $ctx->diag("wrapping my_ok");
    my $out = my_ok($bool, $name);
    $ctx->release; # Vous devez faire cela !
    return $out;
}

DÉTAILS CRITIQUES

Vous devez toujours utiliser la sous-routine context() de Test2::API
Créer votre propre contexte via "Test2::API::Context->new()" ne produira presque jamais le résultat souhaité. Utilisez context(), qui est exporté par Test2::API.

Il existe quelques cas où un auteur d'outil peut choisir de créer manuellement un contexte, c'est pourquoi la méthode "new" existe. Vous ne devriez pas l'utiliser si vous ne savez pas vraiment ce que vous faites.

Vous devez toujours libérer le contexte lorsque vous avez terminé
La libération du contexte donne au système une chance d'exécuter les rappels nécessaires ou les tâches de nettoyage. Si vous oubliez de libérer le contexte, le système essaiera de détecter le problème et vous le signalera.
Vous ne devez pas transmettre d'objets contexte
Lorsque vous obtenez un objet contexte, celui-ci est créé spécifiquement pour votre outil et tout outil imbriqué. Si vous transmettez un objet contexte, vous risquez de contaminer d'autres outils avec des informations de contexte incorrectes.

Si vous êtes sûr de vouloir qu'un autre outil utilise le même contexte, vous pouvez lui passer un instantané. "$ctx->snapshot" vous donnera un clone en profondeur sûr à transmettre ou à stocker.

Vous ne devez pas stocker ou mettre en cache un contexte pour plus tard
Tant qu'un contexte existe pour un hub, tous les outils qui tentent d'obtenir un contexte obtiendront le même objet contexte. Si vous essayez de stocker le contexte, vous contaminerez d'autres outils avec des informations de contexte incorrectes.

Si vous êtes sûr de vouloir sauvegarder le contexte pour plus tard, vous pouvez utiliser un instantané. "$ctx->snapshot" vous donnera un clone en profondeur sûr à transmettre ou à stocker.

context() dispose de certains mécanismes pour vous protéger si vous faites persister un contexte au-delà de la portée dans laquelle il a été obtenu. En pratique, vous ne devriez pas vous fier à ces mécanismes, et ils sont très verbeux avec des avertissements.

Vous devez obtenir le contexte dès que possible dans un outil
Quels outils ne savez-vous pas que vous appellerez dans votre outil pourraient avoir besoin d'un contexte ? Obtenez le contexte dès que possible pour vous assurer que les outils imbriqués peuvent trouver le contexte qu'ils cherchent.

MÉTHODES

$ctx->done_testing;
Note : le test est terminé. Si aucun plan n'a été défini, cela générera un événement Plan.
$clone = $ctx->snapshot()
Cette fonction retourne un clone superficiel du contexte. Le clone superficiel est sûr à transmettre ou à stocker plus tard.
$ctx->release()
Cette fonction libère le contexte. Cela exécute le nettoyage et divers hooks importants. Elle restaurera également $!, $? et $@ à ce qu'ils étaient au moment de la création du contexte.

Note : Si un contexte est obtenu plus d'une fois, un compteur de références interne sera maintenu. release() décrémente le compteur de références, et aucune autre action de release() n'aura lieu, à moins que le compteur de références n'atteigne 0. Cela signifie que seule la dernière invocation de release() réinitialisera $?, $!, $@ et exécutera les tâches de nettoyage.

$ctx->throw($message)
Cette fonction lance une exception rapportant le message dans le fichier et la ligne du contexte. Elle libère également le contexte pour vous.
$ctx->alert($message)
Cette fonction émet une alerte depuis le fichier et la ligne du contexte.
$stack = $ctx->stack()
Cette fonction retourne l'objet Test2::API::Stack qui a été utilisé pour trouver le hub actuel du contexte.
$hub = $ctx->hub()
Cette fonction retourne l'objet Test2::Hub que le contexte reconnaît comme étant le hub actuel via lequel tous les événements doivent être envoyés.
$dbg = $ctx->trace()
Cette fonction retourne l'objet Test2::EventFacet::Trace utilisé par le contexte.
$ctx->do_in_context(\&code, @args);
Parfois, vous avez un contexte qui n'est pas le contexte actuel, et vous voulez que les choses utilisent ce contexte comme contexte actuel. Dans ces cas, vous pouvez appeler "$ctx->do_in_context(sub { ... })". Le bloc de code sera exécuté, et tout ce qui se trouve à l'intérieur qui recherche un contexte trouvera le contexte dans lequel la méthode a été appelée.

Cela n'affecte PAS le contexte dans d'autres hubs, seul le hub utilisé par le contexte sera affecté.

my $ctx = ...;
$ctx->do_in_context(sub {
    my $ctx = context(); # Retourne le $ctx qui est appelé dans le sub
});

Note : Le contexte sera effectivement cloné, et le clone sera utilisé à la place de l'original. Cela permet aux identifiants de fils, de processus et aux variables d'erreur d'être corrects sans modifier le contexte original.

$ctx->restore_error_vars()
Cette fonction définit $!, $? et $@ à ce qu'ils étaient au moment de la création du contexte. Il n'y a pas de localisation ou de choses ici, l'appel de cette fonction définira réellement ces valeurs.
$! = $ctx->errno()
Valeur de $! lorsque le contexte a été créé.
$? = $ctx->child_error()
Valeur de $? lorsque le contexte a été créé.
$@ = $ctx->eval_error()
Valeur de $@ lorsque le contexte a été créé.

MÉTHODES DE CRÉATION D'ÉVÉNEMENTS

Lequel utiliserai-je ?

Les méthodes "pass*" et "fail*" sont optimales si elles correspondent à vos situations, l'utilisation de l'une d'entre elles sera toujours la plus optimale. Bien qu'elles soient optimales en supprimant de nombreuses fonctionnalités.

Les méthodes telles que "ok" et "note" sont des pare-feux pour générer des événements de type 1-tâche basés sur l'ancien API, mais elles sont compatibles avec le futur et faciles à utiliser. Si elles répondent à vos besoins, vous pouvez continuer à les utiliser, mais veuillez vérifier souvent les alternatives qui pourraient être ajoutées.

Si vous souhaitez générer de nouveaux événements de style, des événements qui font beaucoup de choses en une seule fois, alors vous voulez les méthodes "*ev2*". Celles-ci vous permettent de spécifier clairement quelles facettes vous souhaitez utiliser.

$event = $ctx->pass()
$event = $ctx->pass($name)
Cette fonction envoie et retourne un événement Test2::Event::Pass. Vous pouvez facultativement fournir un $name pour l'assertion.

Test2::Event::Pass est un événement spécialement conçu et optimisé. Cet événement est un type spécial et optimisé.

ACCROCHES

Il existe deux types d'accroches : les accroches d'initialisation et les accroches de libération. Comme leur nom l'indique, ces accroches sont déclenchées lors de la création ou de la libération de contextes.

ACCROCHES D'INITIALISATION

Celles-ci sont appelées chaque fois qu'un contexte est initialisé. Cela signifie lors de la création d'une nouvelle instance. Ces accroches ne sont pas appelées à chaque fois que quelqu'un demande un contexte, mais uniquement lorsqu'un nouveau contexte est créé.

GLOBAL

Voici comment ajouter une callback globale d'initialisation. Les callbacks globales s'exécutent pour n'importe quel contexte de n'importe quel hub ou pile.

Test2::API::test2_add_callback_context_init(sub {
    my $ctx = shift;
    ...
});

PAR HUB

Voici comment ajouter une callback d'initialisation pour tous les contextes créés pour un hub donné. Ces callbacks ne s'exécuteront pas pour d'autres hubs.

$hub->add_context_init(sub {
    my $ctx = shift;
    ...
});

PAR CONTEXTE

Voici comment spécifier une accroche d'initialisation qui ne s'exécutera que si votre appel à context() génère un nouveau contexte. La callback sera ignorée si context() renvoie un contexte existant.

my $ctx = context(on_init => sub {
    my $ctx = shift;
    ...
});

ACCROCHES DE LIBÉRATION

Celles-ci sont déclenchées chaque fois qu'un contexte est libéré. Cela signifie lorsque la dernière référence à l'objet est sur le point d'être détruite. Ces accroches ne s'exécutent pas chaque fois que "$ctx->release" est appelée.

GLOBAL

Voici comment ajouter une callback globale de libération. Les callbacks globales s'exécutent pour n'importe quel contexte de n'importe quel hub ou pile.

Test2::API::test2_add_callback_context_release(sub {
    my $ctx = shift;
    ...
});

PAR HUB

Voici comment ajouter une callback de libération pour tous les contextes créés pour un hub donné. Ces callbacks ne s'exécuteront pas pour d'autres hubs.

$hub->add_context_release(sub {
    my $ctx = shift;
    ...
});

PAR CONTEXTE

Voici comment ajouter des callbacks de libération directement à un contexte. La callback sera toujours ajoutée au contexte renvoyé, et peu importe qu'un nouveau soit généré ou qu'un existant soit renvoyé.

my $ctx = context(on_release => sub {
    my $ctx = shift;
    ...
});

MÉTA-DONNÉES TIERS

Cet objet consomme Test2::Util::ExternalMeta, qui fournit un moyen cohérent d'attacher des métadonnées aux instances de cette classe. Ceci est utile pour les outils, les plugins et autres extensions.
