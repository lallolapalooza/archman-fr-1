NOM

Test2::Todo - Extension TODO pour Test2.

DESCRIPTION

C'est un objet qui vous permet de créer et de gérer des états TODO pour les tests. Il s'agit d'une extension, pas d'un plugin ou d'un outil. Cette bibliothèque peut être utilisée par des plugins et des outils pour gérer les états todo.

Si vous souhaitez simplement écrire un test todo, vous devriez regarder la fonction "todo" fournie par Test2::Tools::Basic.

EXEMPLE

use Test2::Todo;
# Démarre le todo
my $todo = Test2::Todo->new(reason => 'Corriger plus tard');
# Sera considéré comme todo, donc la suite passe toujours
ok(0, "oops");
# Termine le todo
$todo->end;
# Le TODO est terminé, ce test échouera réellement.
ok(0, "oops");

OPTIONS DE CONSTRUCTION

raison (obligatoire)
La raison du todo, cela peut être toute valeur définie.
hub (optionnel)
Le hub auquel l'état TODO doit être appliqué. Si aucun n'est fourni, le hub global actuel est utilisé.

MÉTHODES D'INSTANCE

$todo->end
Termine l'état todo.

MÉTHODES DE CLASSE

$count = Test2::Todo->hub_in_todo($hub)
Si le hub a des objets todo, cela retournera le nombre total d'entre eux. Si le hub n'a pas d'objets todo, cela retournera 0.

AUTRES NOTES

Comment ça marche

Lorsqu'une instance est créée, une sous-routine de filtrage est ajoutée à Test2::Hub. Ce filtre définira les attributs "todo" et "diag_todo" sur tous les événements au fur et à mesure qu'ils arrivent. Lorsque l'instance est détruite, ou que end() est appelée, le filtre est supprimé.

Lorsqu'un nouveau hub est empilé (comme lors du démarrage d'un sous-test), le nouveau hub héritera du filtre, mais il ne définira que "diag_todo", il ne définira pas "todo" sur les événements des hubs enfants.

$todo->end est appelé à la destruction

Si votre objet $todo sort de portée et est collecté par le garbage collector, le todo sera terminé.

Puis-je utiliser plusieurs instances ?

Oui. La plus récemment créée qui est toujours active gagnera.
