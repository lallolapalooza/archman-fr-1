Test2::Tools::Basic(3perl) Guide du programmeur Perl Test2::Tools::Basic(3perl)

NOM

Test2::Tools::Basic - Implémentation Test2 des outils de test de base.

DESCRIPTION

Il s'agit d'une implémentation basée sur Test2 des outils plus basiques originellement fournis par Test::More. Tous les outils de Test::More ne sont pas fournis par ce paquet, seulement les outils de base/simples. Certains outils ont été modifiés pour de meilleures capacités de diagnostic.

SYNOPSIS

use Test2::Tools::Basic;
ok($x, "test simple");
if ($passing) {
    pass('un test qui réussit');
}
else {
    fail('un test qui échoue');
}
diag "Ceci est un message de diagnostic sur STDERR";
note "Ceci est un message de diagnostic sur STDOUT";
{
    my $todo = todo "Raison du TODO";
    ok(0, "ce test est TODO");
}
ok(1, "ce test n'est pas TODO");
todo "raison" => sub {
    ok(0, "ce test est TODO");
};
ok(1, "ce test n'est pas TODO");
SKIP: {
    skip "Ceci va effacer votre disque dur";
    # Ceci ne sera jamais exécuté :
    ok(!system('sudo rm -rf /'), "Effacer le disque dur");
}
done_testing;

EXPORTATIONS

Toutes les sous-routines sont exportées par défaut.

PLANIFICATION

plan($num)
plan('tests' => $num)
plan('skip_all' => $reason)
Définit le nombre de tests attendus. Cela doit être fait en premier ou en dernier, jamais au milieu des tests.

Pour des raisons de compatibilité, vous pouvez spécifier 'tests' comme premier argument avant le nombre. Vous pouvez également l'utiliser pour tout sauter avec le préfixe 'skip_all', suivi d'une raison pour sauter.

skip_all($reason)
Définit le plan à 0 avec une raison, puis renvoie vrai. Ceci doit être utilisé avant que tout test ne soit exécuté.
done_testing
Utilisé pour marquer la fin des tests. C'est un moyen sûr d'avoir un nombre dynamique ou inconnu de tests.
bail_out($reason)
Invoqué lorsque quelque chose a terriblement mal tourné : arrêter tout, tuer tous les threads et processus, terminer le processus avec un statut de sortie faux.

ASSERTIONS

ok($bool)
ok($bool, $name)
ok($bool, $name, @diag)
Assertion simple. Si $bool est vrai, le test réussit, et s'il est faux, le test échoue. Le nom du test est facultatif, et tous les arguments après le nom sont ajoutés comme message de diagnostic si et seulement si le test échoue. Si le test réussit, tous les arguments de diagnostic seront ignorés.
pass()
pass($name)
Déclencher un test qui réussit (un événement Ok unique). Le nom est facultatif.
fail()
fail($name)
fail($name, @diag)
Déclencher un test qui échoue (un événement Ok unique). Le nom et le diagnostic sont facultatifs.

DIAGNOSTICS

diag(@messages)
Écrit des messages de diagnostic. Tous les éléments de @messages seront joints en une seule chaîne sans séparateur. Lors de l'utilisation de TAP, les diagnostics sont envoyés sur STDERR.

Renvoie faux, afin de préserver l'échec.

note(@messages)
Écrit des messages de type note-diagnostic. Tous les éléments de @messages seront joints en une seule chaîne sans séparateur. Lors de l'utilisation de TAP, les notes sont envoyées sur STDOUT.

MÉTA

$todo = todo($reason)
todo $reason => sub { ... }
Ceci est utilisé pour marquer certains résultats comme TODO. TODO signifie que le test peut échouer, mais ne fera pas échouer l'ensemble de la suite de tests.

Il y a deux façons d'utiliser cela. La première consiste à utiliser un bloc de code, et le TODO ne s'appliquera qu'au bloc de code.

ok(1, "avant"); # Pas TODO
todo 'cela échouera' => sub {
    # Ceci est TODO, tout comme tout autre test dans ce bloc.
    ok(0, "bof");
};
ok(1, "après"); # Pas TODO

L'autre façon est d'utiliser une variable scopée. Le TODO se terminera lorsque la variable sera détruite ou définie à undef.

ok(1, "avant"); # Pas TODO
{
    my $todo = todo 'cela échouera';
    # Ceci est TODO, tout comme tout autre test dans ce bloc.
    ok(0, "bof");
};
ok(1, "après"); # Pas TODO

C'est la même chose, mais sans la portée "{...}".

ok(1, "avant"); # Pas TODO
my $todo = todo 'cela échouera';
ok(0, "bof"); # TODO
$todo = undef;
ok(1, "après"); # Pas TODO
skip($why)
skip($why, $count)
Ceci est utilisé pour sauter certains tests. Cela nécessite d'encapsuler vos tests dans un bloc étiqueté "SKIP:". Ceci est quelque peu magique. Si aucun $count n'est spécifié, alors cela émettra un seul résultat. Si vous spécifiez $count, cela émettra autant de résultats. 
SKIP: {
    skip "Ceci va effacer votre disque dur";
    # Ceci ne sera jamais exécuté :
    ok(!system('sudo rm -rf /'), "Effacer le disque dur");
}
