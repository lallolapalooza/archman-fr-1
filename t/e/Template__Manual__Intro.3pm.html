NOM

Template::Manual::Intro - Introduction au Template Toolkit

Introduction

Le Template Toolkit est une collection de modules Perl qui implémentent un système de traitement de modèles rapide, flexible, puissant et extensible. Il est le plus souvent utilisé pour générer du contenu web dynamique, bien qu'il puisse être utilisé tout aussi bien pour traiter tout type de documents textuels.

Au niveau le plus simple, il offre un moyen facile de traiter des fichiers modèles, en remplissant les références de variables intégrées avec leurs valeurs équivalentes. Voici un exemple de modèle.

Cher [% name %],
Nous avons attiré votre attention sur le fait que votre compte est en
retard pour la somme de [% debt %].
Veuillez régler votre compte avant le [% deadline %] ou nous serons
contraints de révoquer votre Licence de Jouissance.
La Direction.

Par défaut, les directives de modèle sont intégrées dans les séquences de caractères "[%" ... "%]", mais vous pouvez changer celles-ci et diverses autres options pour configurer l'apparence, le comportement et le fonctionnement du Template Toolkit. Vous pouvez définir l'option "INTERPOLATE", par exemple, si vous préférez intégrer vos variables dans le style Perl :

Cher $name,
Nous avons attiré votre attention sur le fait que votre compte est en
retard pour la somme de $debt.
...etc...

Le Module Perl Template

Le module Perl Template est l'interface du Template Toolkit pour les programmeurs Perl, offrant un accès à toute la gamme de fonctionnalités via un seul module avec une interface simple. Il charge les autres modules selon les besoins et instancie un ensemble d'objets par défaut pour gérer les requêtes de traitement de modèles ultérieures. Des paramètres de configuration peuvent être passés à la méthode constructeur de Template, new(), qui sont ensuite utilisés pour configurer l'objet générateur.

use Template;
my $tt = Template->new({
    INCLUDE_PATH => '/usr/local/templates',
    INTERPOLATE  => 1,
}) || die "$Template::ERROR\n";

L'objet Template implémente une méthode process() pour traiter des fichiers ou du texte modèle. Le nom du modèle d'entrée (ou diverses autres sources) est passé comme premier argument, suivi d'une référence à un tableau associatif de définitions de variables pour substitution dans le modèle.

my $vars = {
    name     => 'Comte Edward van Halen',
    debt     => '3 riffs et un solo',
    deadline => 'le prochain refrain',
};
$tt->process('letters/overdrawn', $vars)
    || die $tt->error(), "\n";

La méthode process() renvoie une valeur vraie (1) en cas de succès et affiche la sortie du modèle sur "STDOUT", par défaut. En cas d'erreur, la méthode process() renvoie une valeur fausse ("undef"). La méthode error() peut alors être appelée pour récupérer les détails de l'erreur.

Construction de Contenu Basée sur des Composants

Un certain nombre de directives spéciales sont fournies, telles que "INSERT", "INCLUDE" et "PROCESS", qui permettent de construire du contenu à partir de petits composants de modèle. Cela permet une approche modulaire de la construction d'un site web ou d'un autre dépôt de contenu, favorisant la réutilisation, la cohérence inter-sites, la facilité de construction et la maintenance ultérieure. Les éléments communs tels que les en-têtes, les pieds de page, les barres de menu, les tableaux, etc., peuvent être créés sous forme de fichiers modèles séparés qui peuvent ensuite être traités dans d'autres documents selon les besoins. Toutes les variables définies sont héritées par ces modèles ainsi que toute valeur "locale" supplémentaire spécifiée.

[% PROCESS header
     title = "Le Chat était assis sur le tapis"
%]
[% PROCESS menu %]
L'emplacement du félin disparu a maintenant été établi.
Merci de votre aide.
[% INSERT legal/disclaimer %]
[% PROCESS footer %]

Vous pouvez également définir un modèle comme un BLOC dans le même fichier et le TRAITER comme tout autre fichier modèle. Cela peut être précieux pour construire des éléments répétitifs tels que des tableaux, des menus, etc.

[% BLOCK tabrow %]
   <tr><td>[% name %]</td><td>[% email %]</td></tr>
[% END %]
<table>
[% PROCESS tabrow name="tom"   email="tom@ici.org"    %]
[% PROCESS tabrow name="dick"  email="disk@là.org"  %]
[% PROCESS tabrow name="larry" email="larry@quelpart.org" %]
</table>

Liaison de Données et de Code

L'une des caractéristiques clés qui distingue le Template Toolkit des autres processeurs de modèles est la capacité de lier des variables de modèle à tout type de données Perl : scalaires, listes, tableaux associatifs, sous-routines et objets.

my $vars = {
    root   => 'http://ici.com/là',
    menu   => [ 'modules', 'auteurs', 'scripts' ],
    client => {
        name => 'Docteur Joseph von Satriani',
        id   => 'JVSAT',
    },
    checkout => sub { my $total = shift; ...; return $quelquechose },
    shopcart => My::Cool::Shopping::Cart->new(),
};

Le Template Toolkit fera automatiquement Ce Qu'il Faut pour accéder aux données de manière appropriée afin de renvoyer une valeur qui pourra ensuite être affichée. L'opérateur point (".") est utilisé pour accéder aux listes et tableaux associatifs ou pour appeler des méthodes d'objet. La directive "FOREACH" est fournie pour itérer sur des listes, et divers tests logiques sont disponibles à l'aide de directives telles que "IF", "UNLESS", "ELSIF", "ELSE", "SWITCH", "CASE", etc.

[% FOREACH section = menu %]
   <a href="[% root %]/[% section %]/index.html">[% section %]</a>
[% END %]
<b>Client</b>: [% client.name %] (id: [% client.id %])
[% IF shopcart.nitems %]
   Votre panier contient les articles suivants :
   <ul>
   [% FOREACH item = shopcart.contents %]
     <li>[% item.name %] : [% item.qty %] @ [% item.price %]
   [% END %]
   </ul>
   [% checkout(shopcart.total) %]
[% ELSE %]
   Aucun article actuellement dans le panier.
[% END %]

Fonctionnalités Avancées : Filtres, Macros, Exceptions, Plugins

Le Template Toolkit fournit également un certain nombre de directives supplémentaires pour le traitement avancé et les fonctionnalités programmatiques. Il prend en charge les filtres de sortie (FILTER), permet de définir des macros personnalisées (MACRO), dispose d'un système de gestion des exceptions complet (TRY, THROW, CATCH, FINAL) et prend en charge une architecture de plugins (USE) qui permet de charger et d'utiliser des modules plugins spéciaux et même des modules Perl réguliers avec un minimum d'effort. Le Template Toolkit est « juste » un processeur de modèles, mais vous pouvez le prolonger trivialement pour intégrer la fonctionnalité de tout module Perl sur lequel vous pouvez mettre la main. Ainsi, c'est aussi un framework de modèles évolutif et extensible, idéal pour gérer la couche de présentation des serveurs d'applications, des systèmes de gestion de contenu et d'autres applications web.

Séparation de la Logique de Présentation et d'Application

Plutôt que d'intégrer du code Perl ou un autre langage de script directement dans les documents modèles, il vous encourage à maintenir les composants fonctionnels (c'est-à-dire le code Perl) séparés des composants de présentation (par exemple, les modèles HTML). Les variables de modèle fournissent l'interface entre les deux couches, permettant aux données d'être générées dans le code puis passées à un composant modèle pour affichage (modèle pipeline) ou à des références de sous-routines ou d'objets d'être liées à des variables qui peuvent ensuite être appelées depuis le modèle quand et comme nécessaire (modèle de rappel).

Les directives fournies par le Template Toolkit implémentent leur propre mini langage de programmation, mais elles ne sont pas vraiment conçues pour une programmation sérieuse et générale. Perl est un langage beaucoup plus approprié pour cela. Si vous intégrez une logique d'application (par exemple, des fragments de code Perl ou d'autres langages de script) dans des modèles HTML, vous risquez de perdre la séparation claire des préoccupations entre la fonctionnalité et la présentation. NAME

Template::Manual::Intro - Introduction to the Template Toolkit

Introduction

The Template Toolkit is a powerful and flexible template system for the Perl programming language. It is designed to be used for all aspects of content creation and delivery, from generating simple HTML pages to complex dynamic documents.

The toolkit is composed of a number of Perl modules that work together to provide a comprehensive templating solution. These modules are highly configurable and extensible, allowing you to tailor them to your specific needs.

The Template Perl Module

The main interface to the Template Toolkit is the Template Perl module. This module provides a simple and intuitive API for processing templates and generating output.

You can use the Template module to define template files, load them, and then process them with your application data. The output can then be directed to standard output, a file, or any other Perl filehandle.

Component Based Content Construction

The Template Toolkit encourages a component-based approach to content construction. This means breaking down your content into smaller, reusable components, such as headers, footers, navigation bars, and content blocks.

These components can then be assembled together to create complete documents. This approach promotes code reuse, simplifies maintenance, and makes it easier to manage complex content structures.

Data and Code Binding

The Template Toolkit allows you to bind your application data to template variables. This means that you can pass data from your Perl code to your templates, and then use that data to dynamically generate content.

The toolkit provides a flexible mechanism for defining and manipulating variables within your templates. You can also use Perl subroutines to generate dynamic data or perform complex calculations within your templates.

Advanced Features: Filters, Macros, Exceptions, Plugins

The Template Toolkit offers a rich set of advanced features that allow you to further customize and extend its functionality. These include:

  • Filters: Modify the output of template variables.
  • Macros: Define reusable blocks of template code.
  • Exceptions: Handle errors and exceptions gracefully.
  • Plugins: Extend the toolkit's functionality with custom modules.

These features provide powerful tools for building complex and dynamic content-driven applications.

Separating Presentation and Application Logic

A key design principle of the Template Toolkit is the separation of presentation logic from application logic. This means that your templates should focus on how data is presented, while your Perl code should handle the underlying data processing and business logic.

By separating these concerns, you can create more maintainable and scalable applications. Designers can work on the templates without needing to understand the intricacies of the Perl code, and Perl programmers can focus on the application logic without being bogged down by presentation details.

While the Template Toolkit is designed to encourage this separation, it does not strictly enforce it. You can embed Perl code directly within your templates using the PERL ... END directives if the EVAL_PERL option is enabled. However, it is generally recommended to keep presentation elements separate from the application logic. You should think of the Template Toolkit language as a set of layout directives for displaying data, not for calculating it.

Performance

The Template Toolkit uses a fast YACC-like parser that compiles templates into Perl code for maximum runtime efficiency. It also features an advanced caching mechanism that manages in-memory and on-disk (i.e., persistent) versions of compiled templates. The modules comprising the toolkit are highly configurable, and the architecture is designed to be extensible. The Template Toolkit provides a powerful framework for content creation and delivery systems while also offering a simple interface through the Template front-end module for general use.
