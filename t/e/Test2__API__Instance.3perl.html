Test2::API::Instance(3perl) Guide de référence du programmeur Perl Test2::API::Instance(3perl)

NOM

Test2::API::Instance - Objet utilisé par Test2::API en arrière-plan

DESCRIPTION

Cet objet encapsule l'état partagé global suivi par Test2. Une seule instance globale de ce paquet est stockée (et cachée) par le paquet Test2::API.

Il n'y a aucune raison d'utiliser directement ce paquet. Ce paquet est documenté pour des raisons de complétude. Ce paquet peut changer, ou disparaître complètement à tout moment. L'utilisation directe, ou le patchage de ce paquet n'est pas supporté de quelque manière que ce soit.

SYNOPSIS

use Test2::API::Instance;
my $obj = Test2::API::Instance->new;
$pid = $obj->pid
PID de cette instance.
$obj->tid
ID de thread de cette instance.
$obj->reset()
Réinitialise l'objet aux valeurs par défaut.
$obj->load()
Définit l'état interne sur chargé et exécute et stocke les callbacks post-chargement.
$bool = $obj->loaded
Vérifie si l'état est défini sur chargé.
$arrayref = $obj->post_load_callbacks
Récupère les callbacks post-chargement.
$obj->add_post_load_callback(sub { ... })
Ajoute un callback post-chargement. Si load() a déjà été appelé alors le callback sera exécuté immédiatement. Si load() n'a pas été appelé alors le callback sera stocké et exécuté plus tard lorsque load() sera appelé.
$hashref = $obj->contexts()
Récupère une référence de hachage de tous les contextes actifs indexés par ID de hub.
$arrayref = $obj->context_acquire_callbacks
Récupère tous les callbacks d'acquisition de contexte.
$arrayref = $obj->context_init_callbacks
Récupère tous les callbacks d'initialisation de contexte.
$arrayref = $obj->context_release_callbacks
Récupère tous les callbacks de libération de contexte.
$arrayref = $obj->pre_subtest_callbacks
Récupère tous les callbacks pre-subtest.
$obj->add_context_init_callback(sub { ... })
Ajoute un callback d'initialisation de contexte. Les sous-routines sont appelées chaque fois qu'un contexte est créé. Les sous-routines reçoivent le nouveau contexte comme seul argument.
$obj->add_context_release_callback(sub { ... })
Ajoute un callback de libération de contexte. Les sous-routines sont appelées chaque fois qu'un contexte est libéré. Les sous-routines reçoivent le contexte libéré comme seul argument. Ces callbacks ne doivent pas appeler la libération sur le contexte.
$obj->add_pre_subtest_callback(sub { ... })
Ajoute un callback pre-subtest. Les sous-routines sont appelées chaque fois qu'un sous-test est sur le point d'être exécuté. Les sous-routines reçoivent le nom du sous-test, le coderef et les arguments éventuels.
$obj->set_exit()
Ceci est destiné à être appelé dans un bloc "END { ... }". Ceci examinera l'état des tests et définira $?. Ceci appellera également tous les callbacks de fin et attendra les processus/threads enfants.
$obj->set_ipc_pending($val)
Indique aux autres processus et threads qu'il y a un événement en attente. $val doit être une valeur unique qu'aucun autre thread/processus ne générera.

Note : Ceci fera également en sorte que le processus actuel voie un événement en attente.

$pending = $obj->get_ipc_pending()
Ceci retourne -1 s'il n'est pas possible de le savoir.

Ceci retourne 0 s'il n'y a pas d'événements en attente.

Ceci retourne 1 s'il y a des événements en attente.

$timeout = $obj->ipc_timeout;
$obj->set_ipc_timeout($timeout);
Combien de temps attendre les processus et threads enfants avant d'abandonner.
$drivers = $obj->ipc_drivers
Récupère la liste des pilotes IPC.
$obj->add_ipc_driver($DRIVER_CLASS)
Ajoute un pilote IPC à la liste. Le pilote IPC ajouté le plus récemment deviendra celui global lors de l'initialisation. Si un pilote est ajouté après que l'initialisation a eu lieu, un avertissement sera généré : 
"IPC driver $driver loaded too late to be used as the global ipc driver"
$bool = $obj->ipc_polling
Vérifie si le polling est activé.
$obj->enable_ipc_polling
Active le polling. Ceci sélectionnera les événements d'autres processus et threads à chaque création de contexte.
$obj->disable_ipc_polling
Désactive le polling IPC.
$bool = $obj->no_wait
$bool = $obj->set_no_wait($bool)
Récupère/définit no_wait. Cette option est utilisée pour désactiver l'attente des processus/threads à la sortie.
$arrayref = $obj->exit_callbacks
Récupère les callbacks de sortie.
$obj->add_exit_callback(sub { ... })
Ajoute un callback de sortie. Ce callback sera appelé par set_exit().
$bool = $obj->finalized
Vérifie si l'objet est finalisé. La finalisation se produit lorsque ipc(), stack(), ou format() sont appelés sur l'objet. Une fois la finalisation effectuée, ces champs sont considérés comme immuables (non appliqué ici, appliqué par Test2).
$ipc = $obj->ipc
Récupère l'unique instance IPC.
$obj->ipc_disable
Désactive l'IPC
$bool = $obj->ipc_disabled
Vérifie si l'IPC est désactivé
$stack = $obj->stack
Récupère la pile de hubs unique.
$formatter = $obj->formatter
Récupère le formateur global. Par défaut, il s'agit du paquet 'Test2::Formatter::TAP'. Il peut s'agir de n'importe quel paquet implémentant la méthode write(). Il peut également s'agir d'un objet instancié.
$bool = $obj->formatter_set()
Vérifie si un formateur a été défini.
$obj->add_formatter($class)
$obj->add_formatter($obj)
Ajoute un formateur. Le formateur ajouté le plus récemment deviendra celui global lors de l'initialisation. Si un formateur est ajouté après que l'initialisation a eu lieu, un avertissement sera généré : 
"Formatter $formatter loaded too late to be used as the global formatter"
$obj->set_add_uuid_via(sub { ... })
$sub = $obj->add_uuid_via()
Ceci vous permet de fournir un générateur d'UUID. S'il est fourni, les UUID seront attachés à tous les événements, hubs et contextes. Ceci est utile pour stocker, suivre et lier ces objets.

La sous-routine que vous fournissez doit toujours retourner un identifiant unique. La plupart des éléments s'attendront à une chaîne UUID valide, cependant rien dans Test2::API ne l'impose.

La sous-routine recevra exactement 1 argument, le type d'élément qui est étiqueté 'context', 'hub' ou 'event'. À l'avenir, d'autres éléments pourraient être étiquetés, auquel cas de nouvelles chaînes seront passées. Celles-ci sont purement informatives, vous pouvez (et devriez généralement) les ignorer.
