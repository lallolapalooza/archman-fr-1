Template::Manual::Variables - Variables de template et liaisons de code

Variables de Template

Une référence à un tableau associatif peut être passée comme deuxième argument à la méthode process(), contenant les définitions des variables de template. L'option "VARIABLES" (alias "PRE_DEFINE") peut également être utilisée pour pré-définir des variables pour tous les templates traités par l'objet.

my $tt = Template->new({
    VARIABLES => {
        version => 3.14,
        release => 'Sahara',
    },
});
my $vars = {
    serial_no => 271828,
};
$tt->process('myfile', $vars);

Template myfile :

Ceci est la version [% version %] ([% release %]).
Numéro de série : [% serial_no %]

Sortie générée :

Ceci est la version 3.14 (Sahara).
Numéro de série : 271828

Les noms de variables peuvent contenir des caractères alphanumériques ou des underscores. Ils peuvent être en minuscules, majuscules ou mixtes bien que la convention habituelle soit d'utiliser des minuscules. La casse *est* cependant significative, et '"foo"', '"Foo"' et '"FOO"' sont des variables différentes. Les noms de variables en majuscules sont autorisés, mais déconseillés en raison d'un conflit potentiel avec un mot réservé existant ou futur. Depuis la version 2.00, ce sont :

GET CALL SET DEFAULT INSERT INCLUDE PROCESS WRAPPER
IF UNLESS ELSE ELSIF FOR FOREACH WHILE SWITCH CASE
USE PLUGIN FILTER MACRO PERL RAWPERL BLOCK META
TRY THROW CATCH FINAL NEXT LAST BREAK RETURN STOP
CLEAR TO STEP AND OR NOT MOD DIV END

Les valeurs des variables peuvent être de quasiment n'importe quel type Perl, y compris des scalaires simples, des références à des listes, des tableaux associatifs, des sous-routines ou des objets. Le Template Toolkit appliquera automatiquement la procédure correcte pour accéder à ces valeurs lorsqu'elles sont utilisées dans le template.

Exemple de données :

my $vars = {
    article => 'The Third Shoe',
    person  => {
        id    => 314,
        name  => 'Mr. Blue',
        email => 'blue@nowhere.org',
    },
    primes  => [ 2, 3, 5, 7, 11, 13 ],
    wizard  => sub { return join(' ', 'Abracadabra!', @_) },
    cgi     => CGI->new('mode=submit&debug=1'),
};

Exemple de template :

[% article %]
[% person.id %]: [% person.name %] <[% person.email %]>
[% primes.first %] - [% primes.last %], including [% primes.3 %]
[% primes.size %] prime numbers: [% primes.join(', ') %]
[% wizard %]
[% wizard('Hocus Pocus!') %]
[% cgi.param('mode') %]

Sortie générée :

The Third Shoe
314: Mr. Blue <blue@nowhere.org>
2 - 13, including 7
6 prime numbers: 2, 3, 5, 7, 11, 13
Abracadabra!
Abracadabra! Hocus Pocus!
submit

Valeurs Scalaires

Les variables scalaires ordinaires sont accessibles en spécifiant simplement leur nom. Comme il s'agit simplement d'entrées dans le tableau associatif de variables de niveau supérieur, elles peuvent être considérées comme des cas particuliers de référence à un tableau associatif comme décrit ci-dessous, avec le tableau associatif de l'espace de noms principal implicitement inclus.

[% article %]

Références à des Tableaux Associatifs

Les membres des tableaux associatifs sont accessibles en spécifiant la référence au tableau associatif et la clé séparées par l'opérateur point '"."'.

Exemple de données :

my $vars = {
    'home' => 'http://www.myserver.com/homepage.html',
    'page' => {
        'this' => 'mypage.html',
        'next' => 'nextpage.html',
        'prev' => 'prevpage.html',
    },
};

Exemple de template :

<a href="[% home %]">Home</a>
<a href="[% page.prev %]">Previous Page</a>
<a href="[% page.next %]">Next Page</a>

Sortie générée :

<a href="http://www.myserver.com/homepage.html">Home</a>
<a href="prevpage.html">Previous Page</a>
<a href="nextpage.html">Next Page</a>

Toute clé dans un tableau associatif qui commence par un caractère '"_"' ou '"."' sera considérée comme privée et ne pourra pas être évaluée ou mise à jour depuis un template. La valeur indéfinie sera retournée pour toute variable de ce type accédée, que le Template Toolkit ignorera silencieusement (sauf si l'option "DEBUG" est activée).

Exemple de données :

my $vars = {
    message => 'Hello World!',
    _secret => "On the Internet, no-one knows you're a dog",
    thing   => {
        public    => 123,
        _private  => 456,
        '.hidden' => 789,
    },
};

Exemple de template :

[% message %]           # affiche "Hello World!"
[% _secret %]           # aucune sortie
[% thing.public %]      # affiche "123"
[% thing._private %]    # aucune sortie
[% thing..hidden %]     # ERREUR : jeton inattendu (..)

Vous pouvez désactiver cette fonctionnalité en définissant la variable de package $Template::Stash::PRIVATE à une valeur fausse.

$Template::Stash::PRIVATE = undef;   # maintenant vous pouvez thing._private

Pour accéder à une entrée de tableau associatif en utilisant une clé stockée dans une autre variable, préfixez la variable clé avec '"$"' pour qu'elle soit interpolée avant utilisation (voir "Interpolation de Variable").

[% pagename = 'next' %]
[% page.$pagename %]       # équivalent à [% page.next %]

Vous pouvez également accéder à une entrée de tableau associatif en utilisant la méthode item(). Cela peut être utile si vous avez des noms de clés complexes.

<pre>
[% files.item('example.txt').content %]
</pre>

Voir Template::Manual::VMethods pour plus d'informations.

Lorsque vous assignez à une variable qui contient plusieurs éléments d'espace de noms (c'est-à-dire qu'elle contient un ou plusieurs caractères '"."' dans son nom), tous les tableaux associatifs nécessaires pour représenter les espaces de noms intermédiaires seront créés automatiquement. Dans l'exemple suivant, la variable "product" devient automatiquement un tableau associatif à moins qu'il ne soit défini autrement.

[% product.id    = 'XYZ-2000'
   product.desc  = 'Bogon Generator'
   product.price = 666
%]
The [% product.id %] [% product.desc %]
costs $[% product.price %].00

Sortie générée :

The XYZ-2000 Bogon Generator
costs $666.00

Vous pouvez utiliser la construction Perl familière "{" ... "}" pour créer explicitement un tableau associatif et l'assigner à une variable. Notez que les virgules sont optionnelles entre les paires clé/valeur et que "=" peut être utilisé à la place de "=>".

# style TT minimal
[% product = {
     id    = 'XYZ-2000'
     desc  = 'Bogon Generator'
     price = 666
   }
%]
# style Perl
[% product = {
     id    => 'XYZ-2000',
     desc  => 'Bogon Generator',
     price => 666,
   }
%]

Références à des Listes

Les éléments des listes sont également accessibles en utilisant l'opérateur point.

Exemple de données :

my $vars = {
    people => [ 'Tom', 'Dick', 'Larry' ],
};

Exemple de template :

[% people.0 %]          # Tom
[% people.1 %]          # Dick
[% people.2 %]          # Larry

La directive "FOREACH" peut être utilisée pour itérer sur les éléments d'une liste.

[% FOREACH person IN people %]
Hello [% person %]
[% END %]

Sortie générée :

Hello Tom
Hello Dick
Hello Larry

Les listes peuvent être construites sur place en utilisant la construction régulière de liste anonyme "[" ... "]". Les virgules entre les éléments sont optionnelles.

[% cols = [ 'red', 'green', 'blue' ] %]
[% FOREACH c IN cols %]
   [% c %]
[% END %]

ou :

[% FOREACH c IN [ 'red', 'green', 'blue' ] %]
   [% c %]
[% END %]

Vous pouvez également créer des séquences numériques simples en utilisant l'opérateur de plage ".." :

[% n = [ 1 .. 4 ] %]    # n est [ 1, 2, 3, 4 ]
[% x = 4
   y = 8
   z = [x..y]           # z est [ 4, 5, 6, 7, 8 ]
%]

Méthodes virtuelles

Le Template Toolkit implémente plusieurs « méthodes virtuelles » qui peuvent être appliquées aux variables scalaires, aux tables de hachage ou aux listes. Par exemple :

[% ma_liste = [ 'foo', 'bar', 'baz' ] %]
[% nouvelle_liste = ma_liste.tri %]

Ici, "ma_liste" est une référence régulière à une liste, et 'tri' est une méthode virtuelle qui renvoie une nouvelle liste avec les éléments triés par ordre croissant. Vous pouvez chaîner plusieurs méthodes virtuelles ensemble. Par exemple :

[% ma_liste.tri.joindre(', ') %]

Ici, "joindre" est une méthode virtuelle appelée pour joindre la liste triée en une seule chaîne, produisant le résultat suivant :

bar, baz, foo

Voir Template::Manual::VMethods pour les détails de toutes les méthodes virtuelles disponibles.

Interpolation de variable

Le Template Toolkit utilise systématiquement "$" pour indiquer qu'une variable doit être interpolée à cet endroit. Le plus souvent, vous la verrez dans les chaînes entre guillemets doubles :

[% nom_complet = "$titre $prenom $nom" %]

Ou intégrée dans du texte brut lorsque l'option "INTERPOLATE" est définie :

Cher/Chère $titre $prenom $nom,

Les mêmes règles s'appliquent à l'intérieur des directives. Si une variable est précédée de "$", elle est remplacée par sa valeur avant d'être utilisée. Son utilisation la plus courante est de récupérer un élément d'une table de hachage dont la clé est stockée dans une variable.

[% uid = 'abw' %]
[% utilisateurs.$uid %]      # équivalent à 'utilisateurs.abw'

Les accolades { } peuvent être utilisées pour délimiter les noms de variables interpolées lorsque nécessaire.

[% utilisateurs.${moi.id}.nom %]

Les directives telles que "INCLUDE", "PROCESS", etc., qui acceptent un nom de template comme premier argument, sont automatiquement découpées pour plus de commodité.

[% INCLUDE foo/bar.txt %]

L'exemple ci-dessus est équivalent à :

[% INCLUDE "foo/bar.txt" %]

Pour inclure un template dont le nom est stocké dans une variable, il suffit de le préfixer avec "$" pour qu'il soit interpolé.

[% mon_fichier = 'entete' %]
[% INCLUDE $mon_fichier %]

Ceci est équivalent à :

[% INCLUDE entete %]

Vous pouvez également traiter une variable contenant une référence à un objet Template::Document.

mon $vars = {
    entete => Template::Document->new({ ... }),
};

Exemple de template :

[% INCLUDE $entete %]

Variables locales et globales

Toute variable simple que vous créez ou modifiez à partir de variables existantes ne persistera que pendant le traitement du template. La table de hachage de l'environnement de portée supérieure est copiée avant que le traitement ne commence, et toutes les modifications apportées aux variables sont effectuées sur cette copie, laissant la variable d'origine intacte.

La même chose se produit lorsque vous incluez un autre template via "INCLUDE". L'espace de noms actuel est cloné pour empêcher les modifications apportées au template inclus d'interférer avec les variables existantes. L'option "PROCESS" évite l'étape de localisation, ce qui la rend légèrement plus rapide, mais nécessite une plus grande attention quant au risque d'effets secondaires dus à la création ou à la modification de toute variable au sein du template traité.

[% BLOC changer_nom %]
   [% nom = 'bar' %]
[% FIN %]
[% nom = 'foo' %]
[% INCLUDE changer_nom %]
[% nom %]              # foo
[% PROCESS changer_nom %]
[% nom %]              # bar

Les variables composites telles que "x.y" se comportent légèrement différemment en raison du processus de localisation, qui n'est que superficiel. L'espace de noms actuel est copié, mais aucun effort n'est fait pour effectuer une copie profonde des structures qu'il contient (tables de hachage, tableaux, objets, etc.). Une variable faisant référence à une table de hachage est copiée pour créer une nouvelle référence, mais celle-ci pointe vers la même table de hachage. Par conséquent, la règle générale est que les variables simples (sans point) sont localisées, mais les structures complexes (avec des points) ne le sont pas.

[% BLOC tout_changer %]
   [% x = 20 %]         # modifie la copie
   [% y.z = 'zulu' %]       # modifie l'original
[% FIN %]
[% x = 10
   y = { z => 'zèbre' }
%]
[% INCLUDE tout_changer %]
[% x %]             # toujours '10'
[% y.z %]               # maintenant 'zulu'

Si vous créez une structure complexe telle qu'une référence à une table de hachage ou à un tableau dans un contexte local, celle-ci disparaîtra à la fin du traitement du template.

[% BLOC nouveau_contenu %]
   [% # définit une nouvelle table de hachage 'y' dans le contexte local
      y = { z => 'zulu' }
   %]
[% FIN %]
[% x = 10 %]
[% INCLUDE nouveau_contenu %]
[% x %]             # affiche '10'
[% y %]             # rien, y est indéfini

De même, si vous mettez à jour un élément d'une variable composite qui n'existe pas encore, il sera automatiquement créé et supprimé à nouveau à la fin du bloc.

[% BLOC nouveau_contenu %]
   [% y.z = 'zulu' %]
[% FIN %]

Cependant, si la table de hachage existe déjà, vous modifierez l'original avec un effet permanent. Pour éviter toute confusion potentielle, il est recommandé d'utiliser...

Template Variables

When you instantiate the Template class, you can provide it with a hash array of variables that will be available for use within any templates processed by that instance. This hash is automatically merged with any variables defined within INCLUDE, PROCESS, or USE directives and in the 'template' or 'component' variables.

my $tt = Template->new({
    VARIABLE => {
        title   => 'My Web Page',
        heading => 'Welcome!',
        items   => [ 'one', 'two', 'three' ],
        footer  => 'Copyright (c) 2003',
    },
});

These variables may be accessed within a template using standard Perl-style hash or array dereferencing syntax:

Title: [% title %]
[% IF heading %]

  [% heading %]
[% END %]

And for arrays:

List:
[% FOREACH item IN items -%]
  - [% item %]
[% END %]

Virtual Methods

The Template Toolkit provides a powerful mechanism for extending its functionality through the use of virtual methods. These methods are invoked using the standard dotted notation, as if they were actual methods of the object or data structure being accessed.

For example, if you have a list of items, you can call the sort() virtual method on it:

[% items.sort %]

The sort() method takes an optional argument specifying the field to sort by. If the items are hash references with a 'name' key, you could sort them like this:

[% items.sort('name') %]

The sort() virtual method returns a new, sorted list. You can then chain further virtual methods onto this result. For instance, to get the first item from the sorted list and print its 'fullname' field:

[% items.sort('name').first.fullname %]

The Template::Toolkit class provides a registry of known virtual methods, which can be extended by user-defined modules.

Virtual methods are implemented as subroutines that accept the object/data structure as their first argument, followed by any arguments passed in the template. The subroutine should return the result of the operation.

package Template::Plugin::MyMethods;
sub sort {
    my ($type, $list, $field) = @_;
    # ... sorting logic ...
    return $sorted_list;
}

To make these methods available, you would typically load them via the PLUGIN directive or configure them via the PLUGINS option when creating the Template object.

Variable Interpolation

Variables defined within the VARIABLES hash or introduced via USE directives may contain references to other variables. These are recursively interpolated until a non-variable value is encountered.

my $tt = Template->new({
    VARIABLES => {
        appname   => 'MyApp',
        title     => '[% appname %] - Main Page',
        footer    => '[% appname %] © 2023',
        long_list => [ '[% appname %] item 1', '[% appname %] item 2' ],
    },
});

When the template is processed, the values for title, footer, and long_list will have appname interpolated into them.

Title: MyApp - Main Page
Copyright (c) 2023 MyApp

Note that interpolation only occurs for scalar values. It does not apply to array or hash references themselves, only to the string values they may contain.

Local and Global Variables

Variables defined within a template using the [% ... %] syntax are local to that template block by default. They are not visible to templates included or processed by that block.

This scoping behaviour is generally desirable as it prevents unintended side effects between different parts of a template structure.

However, there are times when you may wish to define variables that are accessible across multiple templates, including those included or processed by another. It is strongly com

It is strongly recommended that you don't update elements of complex variables from within blocks or templates included by another.

If you want to create or update truly global variables then you can use the 'global' namespace. This is a hash array automatically created in the top-level namespace which all templates, localised or otherwise see the same reference to. Changes made to variables within this hash are visible across all templates.

[% global.version = 123 %]

Compile Time Constant Folding

In addition to variables that get resolved each time a template is processed, you can also define variables that get resolved just once when the template is compiled. This generally results in templates processing faster because there is less work to be done.

To define compile-time constants, specify a "CONSTANTS" hash as a constructor item as per "VARIABLES". The "CONSTANTS" hash can contain any kind of complex, nested, or dynamic data structures, just like regular variables.

my $tt = Template->new({
    CONSTANTS => {
        version => 3.14,
        release => 'skyrocket',
        col     => {
            back => '#ffffff',
            fore => '#000000',
        },
        myobj => My::Object->new(),
        mysub => sub { ... },
        joint => ', ',
    },
});

Within a template, you access these variables using the "constants" namespace prefix.

Version [% constants.version %] ([% constants.release %])
Background: [% constants.col.back %]

When the template is compiled, these variable references are replaced with the corresponding value. No further variable lookup is then required when the template is processed.

You can call subroutines, object methods, and even virtual methods on constant variables.

[% constants.mysub(10, 20) %]
[% constants.myobj(30, 40) %]
[% constants.col.keys.sort.join(', ') %]

One important proviso is that any arguments you pass to subroutines or methods must also be literal values or compile time constants.

For example, these are both fine:

# literal argument
[% constants.col.keys.sort.join(', ') %]
# constant argument
[% constants.col.keys.sort.join(constants.joint) %]

But this next example will raise an error at parse time because "joint" is a runtime variable and cannot be determined at compile time.

# ERROR: runtime variable argument!
[% constants.col.keys.sort.join(joint) %]

The "CONSTANTS_NAMESPACE" option can be used to provide a different namespace prefix for constant variables. For example:

my $tt = Template->new({
    CONSTANTS => {
        version => 3.14,
        # ...etc...
    },
    CONSTANTS_NAMESPACE => 'const',
});

Constants would then be referenced in templates as:

[% const.version %]

Special Variables

A number of special variables are automatically defined by the Template Toolkit.

template

The "template" variable contains a reference to the main template being processed, in the form of a Template::Document object. This variable is correctly defined within "PRE_PROCESS", "PROCESS" and "POST_PROCESS" templates, allowing standard headers, footers, etc., to access metadata items from the main template. The "name" and "modtime" metadata items are automatically provided, giving the template name and modification time in seconds since the epoch.

Note that the "template" variable always references the top-level template, even when processing other template components via "INCLUDE", "PROCESS", etc.

component

The "component" variable is like "template" but always contains a reference to the current, innermost template component being processed. In the main template, the "template" and "component" variable will reference the same Template::Document object. In any other template component called from the main template, the "template" variable will remain unchanged, but "component" will contain a new reference to the current component.

This example should demonstrate the difference:

$template->process('foo')
    || die $template->error(), "\n";

foo template:

[% template.name %]         # foo
[% component.name %]        # foo
[% PROCESS footer %]

footer template:

[% template.name %]         # foo
[% component.name %]        # footer

Additionally, the "component" variable has two special fields: "caller" and "callers". "caller" contains the name of the template that called the current template (or undef if the values of "template" and "component" are the same). "callers" contains a reference to a list of all the templates that have been called on the road to calling the current component template (like a call stack), with the outer-most template first.

Here's an example:

outer.tt2 template:

[% component.name %]        # 'outer.tt2'
[% component.caller %]      # undef
[% component.callers %]     # undef
[% PROCESS 'middle.tt2' %]

middle.tt2 template:

[% component.name %]        # 'middle.tt2'
[% component.caller %]      # 'outer.tt2'
[% component.callers %]     # [ 'outer.tt2' ]
[% PROCESS 'inner.tt2' %]

inner.tt2 template:

[% component.name %]        # 'inner.tt2'
[% component.caller %]      # 'middle.tt2'
[% component.callers %]     # [ 'outer.tt2', 'middle.tt2' ]

loop

Within a "FOREACH" loop, the "loop" variable references the Template::Iterator object responsible for controlling the loop.

[% FOREACH item = [ 'foo', 'bar', 'baz' ] -%]
   [% "Items:\n" IF loop.first -%]
   [% loop.count %]/[% loop.size %]: [% item %]
[% END %]

error

Within a "CATCH" block, the "error" variable contains a reference to the Template::Exception object thrown from within the "TRY" block. The "type" and "info" methods can be called or the variable itself can be printed for automatic stringification into a message of the form ""$type error - $info"". See Template::Exception for further details.

[% TRY %]
   ...
[% CATCH %]
   [% error %]
[% END %]

content

The "WRAPPER" method captures the output from a template block and then includes a named template, passing the captured output as the 'content' variable.

[% WRAPPER box %]
Be not afeard; the isle is full of noises,
Sounds and sweet airs, that give delight and hurt not.
[% END %]
[% BLOCK box %]
<blockquote class="prose">
  [% content %]
</blockquote>
[% END %]

Compound Variables

Compound 'dotted' variables may contain any number of separate elements. Each element may evaluate to any of the permitted variable types and the processor will then correctly use this value to evaluate the rest of the variable. Arguments may be passed to any of the intermediate elements.

[% myorg.people.sort('surname').first.fullname %]

Intermediate variables may be used and will behave entirely as expected.

[% sorted = myorg.people.sort('surname') %]
[% sorted.first.fullname %]

This simplified dotted notation has the benefit of hiding the implementation details of your data. For example, you could implement a data structure as a hash array one day and then change it to an object the next without requiring any change to the templates.
