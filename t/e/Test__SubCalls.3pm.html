NOM

Test::SubCalls - Suivre le nombre d'appels aux sous-programmes

VERSION

version 1.10

SYNTAXE

use Test::SubCalls;

# Commencer à suivre les appels d'un sous-programme nommé
sub_track( 'Foo::foo' );

# Exécuter du code de test
...

# Tester qu'un sous-programme profond dans le code a été appelé
# un nombre spécifique de fois.
sub_calls( 'Foo::foo', 5 );
sub_calls( 'Foo::foo', 5, 'Utiliser un message de test personnalisé' );

# Réinitialiser les compteurs pour un ou tous les sous-programmes
sub_reset( 'Foo::foo' );
sub_reset_all();

DESCRIPTION

Il existe un certain nombre de situations différentes (comme le test de code de mise en cache) où vous voudrez effectuer un certain nombre de tests, puis vérifier qu'un sous-programme sous-jacent profond dans le code a été appelé un nombre spécifique de fois.

Ce module fournit un certain nombre de fonctions pour effectuer des tests de cette manière en association avec vos scripts de test Test::More (ou similaire) normaux.

FONCTIONS

Dans la nature des modules de test, toutes les fonctions sont exportées par défaut.

sub_track $nom_du_sous-programme

La fonction "sub_track" crée un nouveau suivi d'appels pour une fonction nommée.

Le sous-programme à suivre doit être fourni par son nom, les références à la fonction elle-même sont insuffisantes.

Retourne vrai si ajouté, ou meurt en cas d'erreur.

sub_calls $nom_du_sous-programme, $nb_appels_attendus [, $message ]

La fonction "sub_calls" est la fonction de test principale (et unique) fournie par "Test::SubCalls". Un seul appel représentera un test dans votre plan.

Elle prend le nom du sous-programme tel qu'initialement fourni à "sub_track", le nombre attendu de fois où le sous-programme aurait dû être appelé, et un message de test optionnel.

Si aucun message n'est fourni, un message par défaut sera fourni pour vous.

Le test est réussi si le nombre d'appels du sous-programme correspond au nombre attendu, ou échoué sinon.

sub_reset $nom_du_sous-programme

Pour éviter aux utilisateurs récurrents d'avoir à prendre les comptes avant et après lorsqu'ils commencent à tester à partir de zéro, la fonction "sub_reset" a été fournie pour réinitialiser un compteur d'appels de sous-programme à zéro.

Retourne vrai ou meurt si le nom du sous-programme est invalide ou n'est pas actuellement suivi.

sub_reset_all

Fournie principalement par commodité, la fonction "sub_reset_all" réinitialisera tous les compteurs actuellement définis.

Retourne vrai.
