Test::DistManifest(3pm) Documentation perl fournie par les utilisateurs Test::DistManifest(3pm)

NOM

Test::DistManifest - Teste la validation d'un fichier MANIFEST de paquet

VERSION

version 1.014

SYNOPSIS

Voici le langage commun pour les modules de test comme celui-ci, mais voir l'exemple complet dans examples/checkmanifest.t et, plus important encore, l'article d'Adam Kennedy : http://use.perl.org/use.perl.org/_Alias/journal/38822.html

use Test::More;
eval 'use Test::DistManifest';
if ($@) {
  plan skip_all => 'Test::DistManifest requis pour tester MANIFEST';
}
manifest_ok('MANIFEST', 'MANIFEST.SKIP'); # Options par défaut
manifest_ok(); # Fonctionnellement équivalent

DESCRIPTION

Ce module fournit une méthode simple pour tester si un fichier MANIFEST correspond à la distribution.

Trois choses sont testées :

EXPORTATIONS

Par défaut, ce module exporte les fonctions suivantes :

•
manifest_ok
1.
Tout dans MANIFEST existe
2.
Tout dans le paquet est listé dans MANIFEST, ou correspond à un masque dans MANIFEST.SKIP
3.
Rien dans MANIFEST qui correspond également à un masque dans MANIFEST.SKIP, pour éviter des conditions de dépendance non satisfaisables

Si MANIFEST.SKIP n'est pas inclus dans votre distribution, ce module imitera le comportement du système de fichiers par défaut de MANIFEST.SKIP. Pour voir le contenu de ce fichier, utilisez la commande :

$ perldoc -m ExtUtils::MANIFEST.SKIP

FONCTIONS

manifest_ok

manifest_ok( $manifest, $skipfile )

Cette sous-routine vérifie la liste des fichiers dans $manifest en utilisant Module::Manifest pour déterminer la liste des fichiers, puis vérifie l'existence de tous ces fichiers. Ensuite, elle vérifie s'il existe des fichiers dans la distribution qui ne sont pas spécifiés dans le fichier $manifest mais qui ne correspondent à aucune expression régulière fournie dans le fichier d'exclusion $skipfile.

Si votre fichier MANIFEST est généré par un système d'outils d'installation comme ExtUtils::MakeMaker, Module::Build ou Module::Install, vous ne devriez avoir aucun problème avec ces fichiers. C'est juste un test utile pour vous rappeler de mettre à jour ces fichiers avec :

$ make manifest # Pour ExtUtils::MakeMaker
$ ./Build manifest # Pour Module::Build

ERREURS NON FATALES

Par défaut, les erreurs dans le fichier MANIFEST ou MANIFEST.SKIP sont considérées comme fatales, ce qui est en fait le but de l'utilisation de Test::DistManifest comme partie de votre suite de tests d'auteur.

Dans certains cas, ce n'est pas souhaitable, comme avec le Perl Packaging Group Debian, qui exécute tous les tests - y compris ceux d'auteur - dans le cadre de son processus d'empaquetage de modules. Cela pose des problèmes car Debian ajoute ses fichiers de contrôle dans debian/ et ces répertoires ou leurs fichiers ne sont généralement pas dans MANIFEST.SKIP.

En définissant la variable d'environnement MANIFEST_WARN_ONLY à une valeur vraie, les erreurs seront considérées comme non fatales - elles afficheront uniquement des messages de diagnostic, mais tous les tests réussiront du point de vue de Test::Harness.

Ceci peut être utilisé dans un script de test comme :

$ENV{MANIFEST_WARN_ONLY} = 1;

ou depuis d'autres scripts shell comme :

export MANIFEST_WARN_ONLY=1

Remarque : les erreurs dans MANIFEST et les dépendances cycliques seront toujours considérées comme fatales. L'auteur ne connaît aucun cas où d'autres comportements seraient utiles.

DÉTAILS

Ce module planifie en interne quatre tests :

1.
MANIFEST peut être analysé par Module::Manifest
2.
Vérifier les fichiers qui existent dans le répertoire de distribution et qui ne correspondent pas à une expression régulière existante dans MANIFEST.SKIP et ne sont pas listés dans le fichier MANIFEST. Ces fichiers doivent être exclus du test par un masque dans MANIFEST.SKIP (en cas de développement ou de test temporaire) ou doivent être inclus dans MANIFEST.
3.
Vérifier les fichiers qui sont spécifiés dans MANIFEST mais qui n'existent pas sur le disque. Cela se produit généralement lorsque vous supprimez un script de test ou le déplacez accidentellement.
4.
Vérifier les fichiers qui sont spécifiés à la fois dans MANIFEST et MANIFEST.SKIP. Cette condition est clairement insatisfaisable, car le fichier en question n'est pas censé être inclus tout en étant simultanément ignoré.

Si vous souhaitez exécuter des tests sur plusieurs fichiers MANIFEST différents, vous pouvez simplement passer 'no_plan' à la fonction d'importation, comme ceci :

use Test::DistManifest 'no_plan';
# Plusieurs tests fonctionnent maintenant correctement
manifest_ok('MANIFEST', 'MANIFEST.SKIP');
manifest_ok();
manifest_ok('MANIFEST.OTHER', 'MANIFEST.SKIP');

Je doute que cela soit utile aux utilisateurs du module. Cependant, il est utilisé en interne pour les tests et pourrait vous être utile. Vous pouvez également planifier plus de tests, mais rappelez-vous que le concept de "3 tests internes" peut changer à l'avenir.

Exemple de code :

use Test::DistManifest tests => 5;
manifest_ok(); # 4 tests
ok(1, 'est-ce que 1 est vrai ?');

AVERTISSEMENTS

  • Il n'y a actuellement aucun moyen de tester un MANIFEST/MANIFEST.SKIP sans avoir les fichiers réellement sur le disque. Je prévois de changer cela à l'avenir.
  • Ce module n'a pas été très bien testé avec Unicode.
  • Ce module ne génère pas de messages de diagnostic utiles sur la façon de corriger la situation. J'espère que cela sera évident pour quiconque utilise le module ; l'accent devrait être mis sur la génération de messages d'erreur utiles.
