Test::Deep(3) Documentation Perl fournie par l'utilisateur Test::Deep(3)

NOM

Test::Deep - Comparaison profonde extrêmement flexible

VERSION

version 1.205

SYNOPIS

use Test::More tests => $Num_Tests;
use Test::Deep;
cmp_deeply(
  $structure_imbriquee_horrible_actuelle,
  $structure_imbriquee_horrible_attendue,
  "obtenu la bonne structure imbriquée horrible"
);
cmp_deeply(
  $objet,
  methods(name => "John", phone => "55378008"),
  "méthodes de l'objet ok"
);
cmp_deeply(
  \@array,
  [$hash1, $hash2, ignore()],
  "les 2 premiers éléments sont conformes aux attentes, ignorer le 3ème"
);
cmp_deeply(
  $objet,
  noclass({value => 5}),
  "l'objet semble correct, ne pas vérifier sa classe"
);
cmp_deeply(
  \@result,
  bag('a', 'b', {key => [1, 2]}),
  "le tableau contient les 3 éléments souhaités dans un ordre quelconque"
);

DESCRIPTION

Si vous ne savez rien sur les tests automatisés en Perl, vous devriez probablement lire Test::Simple et Test::More avant de continuer. Test::Deep utilise le framework Test::Builder.

Test::Deep vous offre des moyens très flexibles de vérifier que le résultat que vous avez obtenu est bien celui que vous attendiez. À son niveau le plus simple, il compare deux structures en parcourant chaque niveau, en s'assurant que les valeurs correspondent, que les tableaux et les hachages ont les mêmes éléments et que les références sont bénies dans la bonne classe. Il gère également les structures de données circulaires sans se coincer dans une boucle infinie.

Là où cela devient plus intéressant, c'est qu'il vous permet de faire quelque chose d'autre que de simples comparaisons exactes. Avec les chaînes de caractères, l'opérateur "eq" vérifie que 2 chaînes sont exactement égales, mais ce n'est parfois pas ce que vous voulez. Lorsque vous ne savez pas exactement à quoi la chaîne devrait ressembler mais que vous connaissez certains aspects de son apparence, "eq" est inutile et vous devez utiliser la reconnaissance de formes à la place. Test::Deep fournit la reconnaissance de formes pour les structures de données complexes.

Test::Deep a beaucoup d'exportations. Voir "EXPORTS" ci-dessous.

VERSION PERL

Cette bibliothèque devrait fonctionner sur des versions de Perl même anciennes. Elle devrait fonctionner sur toute version de Perl publiée au cours des cinq dernières années.

Bien qu'elle puisse fonctionner sur des versions plus anciennes de Perl, aucune garantie n'est faite que la version minimale requise ne sera pas augmentée. La version peut être augmentée pour quelque raison que ce soit, et il n'est pas promis que des correctifs seront acceptés pour abaisser la version minimale requise de Perl.

EXEMPLES

Il est beaucoup plus facile de comprendre comment fonctionne Test::Deep en voyant quelques exemples.

Sans Test::Deep

Disons que vous voulez tester une fonction qui retourne une chaîne. Vous savez que votre chaîne doit être un nombre à 7 chiffres commençant par 0, "eq" est inutile dans cette situation, vous avez besoin d'une expression régulière. Vous pourriez donc utiliser la fonction like() de Test::More :

like($string, qr/^0[0-9]{6}$/, "le nombre semble correct");

De même, pour vérifier qu'une chaîne ressemble à un nom, vous pouvez faire :

like($string, qr/^(Mr|Mrs|Miss) \w+ \w+$/,
  "obtenu titre, prénom et nom");

Imaginez maintenant que votre fonction produit un hachage avec des informations personnelles. Vous voulez vous assurer qu'il y a 2 clés, Nom et Téléphone, que le nom ressemble à un nom et que le numéro de téléphone ressemble à un numéro de téléphone. Vous pourriez faire :

$hash = make_person();
like($hash->{Name}, qr/^(Mr|Mrs|Miss) \w+ \w+$/, "nom ok");
like($hash->{Phone}, qr/^0[0-9]{6}$/, "téléphone ok");
is(scalar keys %$hash, 2, "nombre correct de clés");

Mais ce n'est pas tout à fait exact, que se passerait-il si make_person avait un problème sérieux et ne retournait même pas un hachage ? Nous devons vraiment écrire :

if (ref($hash) eq "HASH")
{
  like($hash->{Name}, qr/^(Mr|Mrs|Miss) \w+ \w+$/, "nom ok");
  like($hash->{Phone}, qr/^0[0-9]{6}$/, "téléphone ok");
  is(scalar keys %$hash, 2, "nombre correct de clés");
}
else
{
  fail("la personne n'est pas un hachage");
  fail("la personne n'est pas un hachage");
  fail("la personne n'est pas un hachage"); # il en faut 3 pour que le plan soit correct
}

C'est déjà un sacré bazar, maintenant imaginez une autre entrée dans le hachage, un tableau de noms d'enfants. Cela nécessiterait :

if (ref($hash) eq "HASH")
{
  like($hash->{Name}, $name_pat, "nom ok");
  like($hash->{Phone}, '/^0d{6}$/', "téléphone ok");
  my $cn = $hash->{ChildNames};
  if (ref($cn) eq "ARRAY")
  {
    foreach my $child (@$cn)
    {
      like($child, $name_pat);
    }
  }
  else
  {
      fail("les noms d'enfants ne sont pas un tableau")
  }
}
else
{
  fail("la personne n'est pas un hachage");
}

C'est un horrible gâchis et parce que nous ne savons pas à l'avance combien il y aura de noms d'enfants, nous ne pouvons plus faire de plan pour notre test (en fait, nous le pourrions mais cela compliquerait encore les choses).

Test::Deep à la rescousse.

Avec Test::Deep

my $name_re = re('^(Mr|Mrs|Miss) \w+ \w+$');
cmp_deeply(
  $person,
  {
    Name => $name_re,
    Phone => re('^0d{6}$'),
    ChildNames => array_each($name_re)
  },
  "la personne est correcte"
);

Cela fera tout ce que le code désordonné ci-dessus fait et cela donnera un message sensé indiquant exactement ce qui n'a pas fonctionné s'il trouve une partie de $person qui ne correspond pas au motif. re() et array_each() sont des fonctions spéciales importées de Test::Deep. Elles créent un marqueur qui indique à Test::Deep que quelque chose de différent se passe ici. Au lieu de simplement faire une comparaison simple et de vérifier si deux choses sont exactement égales, il doit faire autre chose.

Si une personne était invitée à vérifier que 2 structures sont égales, elle pourrait les imprimer toutes les deux et les comparer ligne par ligne. Les marqueurs ci-dessus sont similaires à l'écriture d'une note au stylo rouge sur l'une des impressions indiquant à la personne que pour cette partie de la structure, elle devrait arrêter de faire une comparaison ligne par ligne et faire autre chose.

re($regex) signifie que Test::Deep doit vérifier que la partie actuelle des données correspond à l'expression régulière dans $regex. array_each($struct) signifie que Test::Deep doit s'attendre à ce que la partie actuelle des données soit un tableau et qu'il doit vérifier que chaque élément de ce tableau correspond à $struct. Dans ce cas, chaque élément de "$person->{ChildNames}" devrait ressembler à un nom. Si, par exemple, le 3ème ne correspondait pas, vous obtiendriez un message d'erreur similaire à

Using Regexp on $data->{ChildNames}[3]
   got    : 'Queen John Paul Sartre'
   expect : /^(Mr|Mrs|Miss) \w+ \w+$/

Il existe de nombreuses autres comparaisons spéciales disponibles, voir "COMPARAISONS SPÉCIALES FOURNIES" ci-dessous pour la liste complète.

Réutilisation des structures

Test::Deep est bon pour réutiliser des structures de test afin que vous puissiez faire ceci

my $name_re = re('^(Mr|Mrs|Miss) \w+ \w+$');
my $person_cmp = {
  Name => $name_re,
  Phone => re('^0d{6}$'),
  ChildNames => array_each($name_re)
};
cmp_deeply($person1, $person_cmp, "la personne est correcte");
cmp_deeply($person2, $person_cmp, "la personne est correcte");
cmp_deeply($person3, $person_cmp, "la personne est correcte");

Vous pouvez même mettre $person_cmp dans un module et laisser les autres l'utiliser lorsqu'ils écrivent des scripts de test pour les modules qui utilisent vos modules.

Pour rendre les choses un peu plus difficiles, changeons la structure des données de personne de sorte qu'au lieu d'une liste de ChildNames, elle contienne une liste de hachages, un pour chaque enfant. Donc, en fait, notre structure de personne contiendra d'autres structures de personne qui peuvent contenir d'autres structures de personne, etc. C'est facile à gérer avec Test::Deep car les structures Test::Deep peuvent s'inclure elles-mêmes. Faites simplement

my $name_re = re('^(Mr|Mrs|Miss) \w+ \w+$');
my $person_cmp = {
  Name => $name_re,
  Phone => re('^0d{6}$'),
  # aucune mention de Children ici
};
$person_cmp->{Children} = array_each($person_cmp);
cmp_deeply($person, $person_cmp, "la personne est correcte");

Cela vérifiera maintenant que $person->{Children} est un tableau et que chaque élément de ce tableau

o correspond à $person_cmp, cela inclut la vérification que ses enfants correspondent également au même modèle et ainsi de suite.

Structures de données circulaires

Une structure de données circulaire est une structure qui boucle sur elle-même. Vous pouvez en créer une facilement en faisant

my @b;
my @a = (1, 2, 3, \@b);
push(@b, \@a);

Maintenant, @a contient une référence à @b et @b contient une référence à @a. Cela pose des problèmes si vous avez un programme qui veut regarder à l'intérieur de @a et continuer à regarder de plus en plus profondément à chaque niveau, il pourrait se retrouver piégé dans une boucle infinie regardant @a puis @b puis @a puis @b et ainsi de suite.

Test::Deep évite ce problème, nous pouvons donc étendre notre exemple en disant qu'une personne devrait également lister ses parents.

my $name_re = re('^(Mr|Mrs|Miss) \w+ \w+$');
my $person_cmp = {
  Name => $name_re,
  Phone => re('^0d{6}$'),
  # aucune mention d'enfants ici
};
$person_cmp->{Children} = each_array($person_cmp);
$person_cmp->{Parents} = each_array($person_cmp);
cmp_deeply($person, $person_cmp, "personne ok");

Cela vérifiera donc que pour chaque enfant $child dans "$person->{Children}" que les "$child->{Parents}" correspondent à $person_cmp, cependant il est suffisamment intelligent pour ne pas se faire piéger dans une boucle infinie où il continue de rebondir entre le même Parent et Enfant.

TERMINOLOGIE

"cmp_deeply($got, $expected, $name)" prend 3 arguments. $got est la structure que vous vérifiez, vous ne devez inclure aucune comparaison spéciale dans cette structure, sinon vous obtiendrez une erreur fatale. $expected décrit ce que Test::Deep recherchera dans $got. Vous pouvez inclure des comparaisons spéciales dans $expected si vous le souhaitez.

Alors que Test::Deep descend à travers les 2 structures, il les compare pièce par pièce, donc à tout moment du processus, Test::Deep pense à 2 choses - la valeur actuelle de $got et la valeur actuelle de $expected. Dans la documentation, je les appelle respectivement $got_v et "exp_v".

FONCTIONS DE COMPARAISON

cmp_deeply

my $ok = cmp_deeply($got, $expected, $name)

$got est le résultat à vérifier. $expected est la structure contre laquelle $got sera vérifié. $name est le nom du test.

C'est la fonction de comparaison principale, les autres ne sont que des wrappers autour de celle-ci. $got et $expected sont comparés récursivement. Chaque valeur de $expected définit ce qui est attendu à l'emplacement correspondant dans $got. Les scalaires simples sont comparés avec "eq". Les références à des structures comme les hashes et les tableaux sont comparées récursivement.

Les éléments de $expected, cependant, peuvent également représenter des tests complexes qui vérifient des nombres dans une plage donnée, des hashes avec au moins un certain ensemble de clés, une chaîne correspondant à une regex, ou bien d'autres choses.

Voir "QUELLES SONT LES COMPARAISONS SPÉCIALES" pour plus de détails.

cmp_bag

my $ok = cmp_bag(\@got, \@bag, $name)

Est un raccourci pour cmp_deeply(\@got, bag(@bag), $name)

n.b.: Les deux arguments doivent être des références de tableaux. Sinon, une exception sera levée.

cmp_set

my $ok = cmp_set(\@got, \@set, $name)

Est un raccourci pour cmp_deeply(\@got, set(@set), $name)

cmp_methods

my $ok = cmp_methods(\@got, \@methods, $name)

Est un raccourci pour cmp_deeply(\@got, methods(@methods), $name)

eq_deeply

my $ok = eq_deeply($got, $expected)

C'est la même chose que cmp_deeply() sauf que cela renvoie juste vrai ou faux. Cela ne crée pas de diagnostics et ne communique pas avec Test::Builder, mais si vous voulez l'utiliser dans un environnement sans test, vous devriez l'importer via Test::Deep::NoTest. Par exemple

use Test::Deep::NoTest;
print "a equals b" unless eq_deeply($a, $b);

sinon le framework Test::Builder sera chargé et des messages de test seront affichés à la fin de votre programme.

cmp_details

($ok, $stack) = cmp_details($got, $expected)

Cela se comporte beaucoup comme eq_deeply, mais cela vous permet en plus de produire des diagnostics en cas d'échec en passant la valeur de $stack à "deep_diag".

Ne faites pas d'hypothèses sur la structure ou le contenu de $stack et ne l'utilisez pas si $ok contient une valeur vraie.

Voir "UTILISER TEST::DEEP AVEC TEST::BUILDER" pour des exemples d'utilisation.

COMPARAISONS SPÉCIALES FOURNIES

Dans la documentation ci-dessous, $got_v est utilisé pour indiquer une valeur quelconque dans la structure $got.

ignore

cmp_deeply( $got, ignore() );

Cela fait que Test::Deep ignore les tests sur $got_v. Quelle que soit la valeur de $got_v, Test::Deep pensera qu'elle est correcte. C'est utile si une partie de la structure que vous testez est très compliquée et déjà testée ailleurs, ou si elle est imprévisible.

cmp_deeply(
  $got,
  {
    name    => 'John',
    random  => ignore(),
    address => [ '5 A street', 'a town', 'a country' ],
  }
);

équivaut à vérifier que

$got->{name} eq 'John';
exists $got->{random};
cmp_deeply($got->{address}, ['5 A street', 'a town', 'a country']);

methods

cmp_deeply( $got, methods(%hash) );

%hash est un hash de paires appel de méthode => valeur attendue.

Cela vous permet d'appeler des méthodes sur un objet et de vérifier le résultat de chaque appel. Les méthodes seront appelées dans l'ordre spécifié. Si vous souhaitez passer des arguments à la méthode, vous devez encapsuler le nom de la méthode et les arguments dans une référence de tableau.

cmp_deeply(
  $obj,
  methods(name => "John", ["favourite", "food"] => "taco")
);

équivaut approximativement à vérifier que

$obj->name eq "John"
$obj->favourite("food") eq "taco"

Les méthodes seront appelées dans l'ordre où vous les fournissez et seront appelées dans un contexte scalaire. Si vous avez besoin de tester des méthodes appelées dans un contexte de liste, vous devriez utiliser listmethods().

NOTE Tout comme dans un script de test normal, vous devez faire attention si les méthodes que vous appelez ont des effets secondaires comme la modification de l'objet ou d'autres objets dans la structure. Bien que l'ordre des méthodes soit fixe, l'ordre de certains autres tests ne l'est pas, donc si $expected est

{
  manager => methods(@manager_methods),
  coder => methods(@coder_methods)
}

il n'y a aucun moyen de savoir lequel, entre manager et coder, sera testé en premier. Si les méthodes que vous testez dépendent de et modifient des variables globales ou si manager et coder sont le même objet, vous pourriez rencontrer des problèmes.

listmethods

cmp_deeply( $got, listmethods(%hash) );

%hash est un hash de paires mappant les noms de méthodes à leurs valeurs de retour attendues.

Ceci est presque identique à methods() sauf que les méthodes sont appelées dans un contexte de liste au lieu d'un contexte scalaire. Cela signifie que les valeurs de retour attendues fournies doivent être des références de tableau.

cmp_deeply(
  $obj,
  listmethods(
    name => [ "John" ],
    ["favourites", "food"] => ["Mapo tofu", "Gongbao chicken"]
  )
);

équivaut à vérifier que

cmp_deeply([$obj->name], ["John"]);
cmp_deeply([$obj->favourites("food")], ["Mapo tofu", "Gongbao chicken"]);

Les méthodes seront appelées dans l'ordre où vous les fournissez.

NOTE Les mêmes mises en garde s'appliquent que pour methods().

shallow

cmp_deeply( $got, shallow($thing) );

$thing est une référence.

Cela empêche Test::Deep de regarder à l'intérieur de $thing. Cela vous permet de vérifier que $got_v et $thing sont des références à la même variable. Donc

my @a = @b = (1, 2, 3);
cmp_deeply(\@a, \@b);

réussira car @a et @b ont les mêmes éléments, cependant

cmp_deeply(\@a, shallow(\@b))

échouera car bien que "\@a" et "\@b" contiennent tous deux "1, 2, 3", ce sont des références à des tableaux différents.

noclass

cmp_deeply( $got, noclass($thing) );

$thing est une structure à comparer.

Cela fait que Test::Deep ignore la classe des objets, il regarde simplement les données qu'ils contiennent. La vérification de classe sera désactivée jusqu'à ce que Test::Deep ait fini de comparer $got_v à $thing. Une fois que Test::Deep sort de $thing, il reviendra à son paramètre précédent pour la vérification de classe.

Cela peut être utile lorsque vous voulez vérifier que les objets ont été correctement construits mais que vous ne voulez pas écrire beaucoup de "bless". Si @people est un tableau d'objets Personne alors

cmp_deeply(\@people, [
  bless {name => 'John', phone => '555-5555'}, "Person",
  bless {name => 'Anne', phone => '444-4444'}, "Person",
]);

peut être remplacé par

cmp_deeply(\@people, noclass([
  {name => 'John', phone => '555-5555'},
  {name => 'Anne', phone => '444-4444'}
]));

Cependant, c'est un test, vous devriez donc également vérifier que les objets sont blesse

correcntement. Vous pouvez utiliser une carte pour bénir toutes ces hachures ou vous pouvez faire un deuxième test comme

cmp_deeply(\@people, array_each(isa("Person"));

useclass

cmp_deeply( $got, useclass($thing) );

Ceci réactive la comparaison de classe à l'intérieur d'un noclass().

cmp_deeply(
  $got,
  noclass(
    [
      useclass( $object )
    ]
  )
)

Dans cet exemple, la classe de la référence de tableau dans $got est ignorée mais la classe de $object est vérifiée, tout comme la classe de tout ce qui se trouve à l'intérieur de $object.

re

cmp_deeply( $got, re($regexp, $capture_data, $flags) );

$regexp est soit une référence d'expression régulière produite avec "qr/.../" soit une chaîne qui sera utilisée pour construire une expression régulière.

$capture_data est facultatif et est utilisé pour vérifier les chaînes capturées par une regex. Cela peut être une référence de tableau ou un comparateur Test::Deep qui fonctionne sur des références de tableaux.

$flags est une chaîne facultative qui contrôle si la regex s'exécute en tant que correspondance globale. Si $flags est "g", alors la regex s'exécutera comme "m/$regexp/g".

Sans $capture_data, cela compare simplement $got_v avec l'expression régulière fournie. Donc

cmp_deeply($got, [ re("ferg") ])

est l'équivalent de

$got->[0] =~ /ferg/

Avec $capture_data,

cmp_deeply($got, [re($regex, $capture_data)])

est l'équivalent de

my @data = $got->[0] =~ /$regex/;
cmp_deeply(\@data, $capture_data);

Vous pouvez donc faire quelque chose de simple comme

cmp_deeply($got, re(qr/(\d\d)(\w\w)/, [25, "ab" ]))

pour vérifier que "(\d\d)" était 25 et "(\w\w)" était "ab", mais vous pouvez également utiliser des objets Test::Deep pour des tests plus complexes des valeurs capturées

cmp_deeply(
  "cat=2,dog=67,sheep=3,goat=2,dog=5",
  re(
    qr/(\D+)=\d+,?/,
    set(qw( cat sheep dog )),
    "g"
  ),
);

ici, la regex correspondra à la chaîne et capturera les noms d'animaux et vérifiera qu'ils correspondent à l'ensemble spécifié, dans ce cas, cela échouera, se plaignant que "goat" n'est pas dans l'ensemble.

all

cmp_deeply( $got, all(@expecteds) );

@expecteds est un tableau de structures attendues.

Cela vous permet de comparer des données avec plusieurs résultats attendus et de vous assurer que chacun d'eux correspond.

cmp_deeply($got, all(isa("Person"), methods(name => 'John')))

est équivalent à

$got->isa("Person")
$got->name eq 'John'

Si l'un des tests échoue, alors l'ensemble est considéré comme un échec. C'est un test d'arrêt sur image, les tests s'arrêtent après le premier échec, bien qu'à l'avenir, il puisse terminer tous les tests afin que les diagnostics puissent être affichés pour tous les échecs. Lors de la signalisation d'un échec, les parties sont comptées à partir de 1.

Grâce à la magie du surcharge, vous pouvez écrire

any( re("^wi"), all(isa("Person"), methods(name => 'John')) )

comme

re("^wi") | isa("Person") & methods(name => 'John')

Notez le **simple** "|" et non double, car "||" ne peut pas être surchargé. Cela ne fonctionnera que lorsqu'il y aura une comparaison spéciale impliquée. Si vous écrivez

"john" | "anne" | "robert"

Perl transformera cela en

"{onort"

ce qui n'est probablement pas ce que vous vouliez. C'est parce que Perl les or-combine comme des chaînes avant que Test::Deep n'ait une chance de faire des astuces de surcharge.

any

cmp_deeply( $got, any(@expecteds) );

@expecteds est un tableau de structures attendues.

Cela peut être utilisé pour comparer des données avec plusieurs résultats attendus et pour s'assurer qu'au moins l'un d'entre eux correspond. C'est un test d'arrêt sur image, donc si un test réussit, aucun des tests suivants ne sera tenté.

Vous pouvez également utiliser la surcharge avec "|" de manière similaire à all().

Isa

cmp_deeply( $got, Isa($class) );

isa

cmp_deeply( $got, isa($class) );

$class est un nom de classe.

Cela utilise UNIVERSAL::isa() pour vérifier que $got_v est béni dans la classe $class.

NOTE : Isa() fait exactement ce qui est documenté ici, mais isa() est légèrement différent. Si isa() est appelé avec 1 argument, il tombe sur Isa(). Si isa() est appelé avec 2 arguments, il tombe sur "UNIVERSAL::isa". Ceci afin d'éviter les problèmes lorsque vous importez isa() dans un package qui est utilisé comme une classe. Sans cela, quiconque appelant "Class->isa($other_class)" obtiendrait la mauvaise réponse. C'est un hack pour pallier le fait que "isa" est exporté par défaut.

obj_isa

cmp_deeply( $got, obj_isa($class) );

Ce test n'accepte que les objets qui sont des instances de $class ou d'une sous-classe. Contrairement au test "Isa", ce test n'acceptera jamais les noms de classes.

array_each

cmp_deeply( \@got, array_each($thing) );

$thing est une structure à comparer.

<$got_v> doit être une référence de tableau. Chaque élément sera comparé à $thing. Ceci est utile lorsque vous avez un tableau de choses similaires, par exemple des objets d'un type connu et que vous ne voulez pas avoir à répéter le même test pour chacun d'eux.

my $common_tests = all(
   isa("MyFile"),
   methods(
     handle => isa("IO::Handle")
     filename => re("^/home/ted/tmp"),
  )
);
cmp_deeply($got, array_each($common_tests));

est similaire à

foreach my $got_v (@$got) {
  cmp_deeply($got_v, $common_tests)
}

Sauf qu'il n'explosera pas si $got n'est pas une référence de tableau. Il vérifiera que chacun des objets dans @$got est un MyFile et que chacun d'eux donne les résultats corrects pour ses méthodes.

Vous pourriez aller plus loin, si par exemple il y avait 3 fichiers et que vous connaissiez la taille de chacun d'eux, vous pourriez faire ceci

cmp_deeply(
  $got,
  all(
    array_each($common_tests),
    [
      methods(size => 1000),
      methods(size => 200),
      methods(size => 20)
    ]
  )
)
cmp_deeply($got, array_each($structure));

hash_each

cmp_deeply( \%got, hash_each($thing) );

Ce test se comporte comme "array_each" (voir ci-dessus) mais vérifie que chaque valeur de hachage réussit ses tests.

str

cmp_deeply( $got, str($string) );

$string est une chaîne.

Cela convertira $got_v en chaîne et la comparera à $string en utilisant "eq", même si $got_v est une référence. C'est utile pour vérifier la valeur chaîne d'une référence surchargée.

num

cmp_deeply( $got, num($number, $tolerance) );

$number est un nombre.

$tolerance est un nombre facultatif.

Cela ajoutera 0 à $got_v et vérifiera s'il est numériquement égal à $number, même si $got_v est une référence. C'est utile pour vérifier la valeur numérique d'une référence surchargée. Si $tolerance est fourni, alors cela vérifiera que $got_v et $exp_v sont à moins de $tolerance l'un de l'autre. Ceci est utile lors de la comparaison de nombres à virgule flottante car les erreurs d'arrondi peuvent rendre difficile ou impossible pour $got_v d'être exactement égal à $exp_v. Lorsque $tolerance est fourni, le test réussit si "abs($got_v - $exp_v) <= $tolerance".

Note en Perl, ""12blah" == 12" car Perl sera intelligent et convertira "12blah" en 12. Vous ne voudrez peut-être pas cela. Il y avait un mode strict mais il a maintenant disparu. Un test "ressemble à un nombre" le remplacera bientôt. D'ici là, vous pouvez généralement utiliser la comparaison string() pour être plus strict. Cela fonctionnera bien pour presque toutes les situations, mais cela ne fonctionnera pas lorsque <$got_v> est une valeur surchargée dont les valeurs chaîne et numériques diffèrent.

bool, true, false

cmp_deeply( $got, bool($value) );
cmp_deeply( $got, true );
cmp_deeply( $got, false );

$value est tout ce que vous voulez, mais il est probablement préférable d'utiliser 0 ou 1

Cela vérifiera que $got_v et $value ont la même valeur de vérité, c'est-à-dire qu'ils donneront le même résultat lorsqu'ils seront utilisés dans un contexte booléen, comme dans une instruction if().

Note : "true" et "false" ne sont importés que sur demande spéciale.

code

cmp_deeply( $got, code(\&subref) );

"\&subref" est une référence à une sous-routine qui recevra un seul argument, elle devrait ensuite retourner vrai ou faux et éventuellement une chaîne

Cela passera $got_v à la sous-routine qui retourne vrai ou faux pour indiquer un succès ou un échec. Les échecs peuvent être accompagnés d'une chaîne de diagnostic qui explique pourquoi c'est un échec.

sub check_name
{
  my $name = shift;
  if ($boss->likes($name))
  {
    return 1;
  }
  else
  {
    return (0, "the boss doesn't like your name");
  }
}
cmp_deeply("Brian", code(\&check_name));

COMPARISONS DE BAG

Les comparaisons de bag donnent un sens spécial aux comparaisons de tableaux, similaires à celles des sets, mais avec de légères différences.

  • L'ordre des éléments dans un bag n'a pas d'importance
  • Les éléments dupliqués dans un bag sont conservés

Ainsi, dans toute comparaison de bag, les tableaux suivants sont égaux :

[ 1, 1, 2 ]
[ 1, 2, 1 ]
[ 2, 1, 1 ]
[ 1, 1, 2 ]

Cependant, ils ne sont pas égaux aux suivants :

[ 1, 2 ]
[ 1, 2, 2 ]
[ 1, 1, 1, 2 ]

Toutes les fonctions de type "bag" renvoient un objet auquel des éléments supplémentaires peuvent être ajoutés :

my $bag = bag( 1, 2 );
$bag->add(1, 3, 1 );  # Le bag est maintenant ( 1, 1, 1, 2, 3 )

Il faut être particulièrement prudent lors de l'utilisation de comparaisons spéciales dans des bags. Voir "SPECIAL CARE WITH SPECIAL COMPARISONS IN SETS AND BAGS" pour plus de détails.

bag

cmp_deeply( \@got, bag(@elements) );

Ceci effectue une comparaison de bag insensible à l'ordre entre $got et @elements, en s'assurant que :

chaque élément dans @elements se trouve dans $got
le nombre de fois où $expected_v apparaît dans @elements est reflété dans $got
il n'y a aucun élément dans $got autre que ceux de @elements

Ainsi, les comparaisons suivantes réussissent et sont équivalentes :

cmp_deeply([1, 2, 2], bag(2, 2, 1))
cmp_deeply([2, 1, 2], bag(2, 2, 1))
cmp_deeply([2, 2, 1], bag(2, 2, 1))

Mais les comparaisons suivantes échouent :

cmp_deeply([1, 2, 2],     bag(2, 2, 1, 1)) # Pas assez de 1 dans Got
cmp_deeply([1, 2, 2, 1],  bag(2, 2, 1)   ) # Trop de 1 dans Got

superbagof

cmp_deeply( \@got, superbagof( @elements ) );

Cette fonction fonctionne de manière très similaire à "bag" et effectue une comparaison de bag entre $got_v et les éléments de @elements.

"superbagof" est légèrement plus flexible, permettant à $got de contenir des éléments non présents dans @elements, mais il doit au moins contenir tous les éléments de @elements.

Ainsi :

# succès
cmp_deeply( [1, 1, 2], superbagof( 1 )      );
# échec : pas assez de 1 dans superbag
cmp_deeply( [1, 1, 2], superbagof( 1, 1, 1 ))

subbagof

cmp_deeply( \@got, subbagof(@elements) );

Cette fonction fonctionne de manière très similaire à "bag" et effectue une comparaison de bag entre $got_v et les éléments de @elements.

C'est l'inverse de "superbagof" et elle s'attend à ce que tous les éléments de $got soient dans @elements, mais permet que des éléments existent dans @elements qui ne sont pas dans $got.

# succès
cmp_deeply( [1],        subbagof( 1, 1, 2 ) );
# échec : trop de 1 dans subbag
cmp_deeply( [1, 1, 1],  subbagof( 1, 1, 2 ) );

COMPARISONS DE HASH

En général, si vous effectuez des comparaisons de hash simples, il suffit de faire :

cmp_deeply( \%got, \%expected )

"cmp_deeply" s'assurera que %got et %hash ont les mêmes clés, et que chaque clé d'un côté a la valeur correspondante.

superhashof

cmp_deeply( \%got, superhashof(\%hash) );

Cela vérifiera que le hash %$got est un "super-hash" de %hash. C'est-à-dire que toutes les paires clé-valeur dans %hash apparaissent dans %$got, mais %$got peut en avoir des supplémentaires.

Par exemple :

cmp_deeply({a => 1, b => 2}, superhashof({a => 1}))

réussira, mais :

cmp_deeply({a => 1, b => 2}, superhashof({a => 1, c => 3}))

échouera.

subhashof

cmp_deeply( \%got, subhashof(\%hash) );

Cela vérifiera que le hash %$got est un "sous-hash" de %hash. C'est-à-dire que toutes les paires clé-valeur dans %$got apparaissent également dans %hash.

Par exemple :

cmp_deeply({a => 1}, subhashof({a => 1, b => 2}))

réussira, mais :

cmp_deeply({a => 1, c => 3}, subhashof({a => 1, b => 2}))

échouera.

FONCTIONS DE DIAGNOSTIC

deep_diag

my $reason = deep_diag($stack);

$stack est la valeur retournée par cmp_details. Vous ne devriez pas appeler cette fonction si cmp_details a retourné une valeur vraie pour $ok.

"deep_diag()" renvoie une chaîne de caractères lisible décrivant pourquoi la comparaison a échoué.

AUTRE EXEMPLE

Vous avez écrit un module pour gérer les personnes et leurs intérêts cinématographiques. Supposons que vous ayez une fonction qui renvoie un tableau de personnes à partir d'une requête, chaque personne étant un hash avec 2 clés : Name et Age, et le tableau est trié par Name. Vous pouvez faire :

cmp_deeply(
  $result,
  [
    {Name => 'Anne', Age => 26},
    {Name => "Bill", Age => 47}
    {Name => 'John', Age => 25},
  ]
);

Peu de temps après, votre fonction de requête change et tous les résultats ont maintenant un champ ID. Votre test échoue maintenant car vous avez omis l'ID de chaque hash. Le problème est que les IDs sont générés par la base de données et vous ne savez pas quel est l'ID de chaque personne. Avec Test::Deep, vous pouvez modifier votre requête en :

cmp_deeply(
  $result,
  [
    {Name => 'John', Age => 25, ID => ignore()},
    {Name => 'Anne', Age => 26, ID => ignore()},
    {Name => "Bill", Age => 47, ID => ignore()}
  ]
);

Mais votre test échoue toujours. Maintenant, comme vous utilisez une base de données, vous ne connaissez plus l'ordre dans lequel les personnes apparaîtront. Vous pourriez ajouter un tri dans la requête de la base de données, mais cela pourrait ralentir votre application. Au lieu de cela, vous pouvez faire en sorte que Test::Deep ignore l'ordre du tableau avec une comparaison de bag.

cmp_deeply(
  $result,
  bag(
    {Name => 'John', Age => 25, ID => ignore()},
    {Name => 'Anne', Age => 26, ID => ignore()},
    {Name => "Bill", Age => 47, ID => ignore()}
  )
);

Enfin, la personne devient encore plus compliquée et inclut un nouveau champ appelé Movies, qui est une liste de films récemment vus. Ces films peuvent réapparaître dans n'importe quel ordre, nous avons donc besoin d'un bag à l'intérieur de notre comparaison de bag, ce qui donne quelque chose comme ceci :

cmp_deeply(
$result,
  bag(
    {Name => 'John', Age => 25, ID => ignore(), Movies => bag(...)},
    {Name => 'Anne', Age => 26, ID => ignore(), Movies => bag(...)},
    {Name => "Bill", Age => 47, ID => ignore(), Movies => bag(...)}
  )
);

NAME

Test::Deep - Perl extension for deep compares

VERSION

1.127

SYNOPSIS

 use Test::Deep;

 cmp_deeply(
     {
         name   => 'Bob',
         age    => 32,
         loves  => [qw( Perl bugs )],
         mother => { name => 'Alice' },
     },
     {
         name   => 'Bob',
         age    => 32,
         loves  => bag( 'bugs', 'Perl' ),
         mother => { name => re( qr/Alice/ ) },
     }
 );

 cmp_deeply( [ 1, 2, 3 ], [ 1, $_, 3 ] ); # $_ is special

DESCRIPTION

Test::Deep allows you to compare arbitrarily complex data structures. It complements Test::More's is_deeply function, adding features like:

  • Comparing only certain elements of an array or hash.
  • Comparing elements using regular expressions.
  • Using special objects (like bag or set) to compare elements without regard to order.
  • Ignoring certain elements.
  • Comparing objects based on their class names or methods.

This module is highly recommended for anyone writing tests for modules that manipulate complex data structures.

PERL VERSION

This module is written and tested with Perl 5.005_03, but it should work with older versions with no problems.

EXAMPLES

See the SYNOPSIS section for a basic example. More examples can be found in the TST file in the distribution.

TERMINOLOGY

A *comparison* is a value that is passed to cmp_deeply as the expected value. A *special comparison* (SC) is a comparison that is an object, inheriting from Test::Deep::Cmp.

COMPARISON FUNCTIONS

The main function is cmp_deeply($got, $expected)

cmp_deeply is a thin wrapper around Test::Deep::no_plan->new->cmp_deeply(@_)

There are also

 ok( cmp_deeply( $got, $expected ) )

and

 my $ok = cmp_deeply( $got, $expected );

The rest of the functions are all special comparisons.

DIAGNOSTIC FUNCTIONS

If a comparison fails, cmp_deeply will return false. If you are using Test::Builder, you can use the diagnostic functions to get more information.

 sub behaves_ok {
   my $self = shift;
   my $expected = shift;
   my $test_name = shift;
   my $got = do_the_important_work_here();

   my ($ok, $diag) = cmp_details($got, $expected);

   unless ( $Test->ok($ok, $test_name) ) {
     $Test->diag(deep_diag($diag));
   }
 }

cmp_details returns a true/false value and a diagnostic message. deep_diag formats the diagnostic message for Test::Builder.

ANOTHER EXAMPLE

This example shows how to compare a hash with some special comparisons:

 use Test::Deep;

 my $data = {
     name   => 'Mimi',
     age    => 5,
     weight => 1.2,
     owner  => { name => 'Alice' },
     toys   => [ 'mouse', 'ball', 'string' ],
 };

 cmp_deeply($data, {
     name   => 'Mimi',
     age    => num(5),
     weight => gt(1.0), # from Test::Builder
     owner  => { name => re('^Ali') },
     toys   => bag('mouse', 'ball', 'string'),
 });

USING TEST::DEEP WITH TEST::BUILDER

Combining "cmp_details" and "deep_diag" makes it possible to use Test::Deep in your own test classes.

In a Test::Builder subclass, create a test method in the following form:

sub behaves_ok {
  my $self = shift;
  my $expected = shift;
  my $test_name = shift;
  my $got = do_the_important_work_here();
  my ($ok, $stack) = cmp_details($got, $expected);
  unless ($Test->ok($ok, $test_name)) {
    my $diag = deep_diag($stack);
    $Test->diag($diag);
  }
}

As the subclass defines a test class, not tests themselves, make sure it uses Test::Deep::NoTest, not "Test::Deep" itself.

LIMITATIONS

Currently any CODE, GLOB or IO refs will be compared using shallow(), which means only their memory addresses are compared.

BUGS

There is a bug in set and bag compare to do with competing SCs. It only occurs when you put certain special comparisons inside bag or set comparisons you don't need to worry about it. The full details are in the bag() docs. It will be fixed in an upcoming version.

CAVEATS

SPECIAL CARE WITH SPECIAL COMPARISONS IN SETS AND BAGS

If you use certain special comparisons within a bag or set comparison there is a danger that a test will fail when it should have passed. It can only happen if two or more special comparisons in the bag are competing to match elements. Consider this comparison

cmp_deeply(['furry', 'furball'], bag(re("^fur"), re("furb")))

There are two things that could happen, hopefully re("^fur") is paired with "furry" and re("^furb") is paired with "furball" and everything is fine but it could happen that re("^fur") is paired with "furball" and then re("^furb") cannot find a match and so the test fails. Examples of other competing comparisons are "bag(1, 2, 2)" vs "set(1, 2)" and "methods(m1 => "v1", m2 => "v2")" vs "methods(m1 => "v1")"

This problem is could be solved by using a slower and more complicated algorithm for set and bag matching. Something for the future...

WHAT ARE SPECIAL COMPARISONS?

A special comparison (SC) is simply an object that inherits from Test::Deep::Cmp. Whenever $expected_v is an SC then instead of checking "$got_v eq $expected_v", we pass control over to the SC and let it do its thing.

Test::Deep exports lots of SC constructors, to make it easy for you to use them in your test scripts. For example is re("hello") is just a handy way of creating a Test::Deep::Regexp object that will match any string containing "hello". So

cmp_deeply([ 'a', 'b', 'hello world'], ['a', 'b', re("^hello")]);

will check 'a' eq 'a', 'b' eq 'b' but when it comes to comparing 'hello world' and re("^hello") it will see that $expected_v is an SC and so will pass control to the Test::Deep::Regexp class by do something like "$expected_v->descend($got_v)". The descend() method should just return true or false.

This gives you enough to write your own SCs but I haven't documented how diagnostics works because it's about to get an overhaul (theoretically).

use Test::Deep ':v0';
