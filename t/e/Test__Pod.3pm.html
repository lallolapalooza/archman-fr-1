NOM

Test::Pod - vérifier les erreurs de POD dans les fichiers

VERSION

Version 1.52

SYNOPSIS

"Test::Pod" vous permet de vérifier la validité d'un fichier POD et de rapporter ses résultats dans le style standard de "Test::Simple".

use Test::Pod tests => $num_tests;
pod_file_ok( $file, "Fichier POD valide" );

Les auteurs de modules peuvent inclure ce qui suit dans un fichier t/pod.t et faire en sorte que "Test::Pod" trouve et vérifie automatiquement tous les fichiers POD d'une distribution de module :

use Test::More;
eval "use Test::Pod 1.00";
plan skip_all => "Test::Pod 1.00 requis pour le test de POD" if $@;
all_pod_files_ok();

Vous pouvez également spécifier une liste de fichiers à vérifier, en utilisant la fonction all_pod_files() fournie :

use strict;
use Test::More;
eval "use Test::Pod 1.00";
plan skip_all => "Test::Pod 1.00 requis pour le test de POD" if $@;
my @poddirs = qw( blib script );
all_pod_files_ok( all_pod_files( @poddirs ) );

Ou même (si vous exécutez sous Apache::Test) :

use strict;
use Test::More;
eval "use Test::Pod 1.00";
plan skip_all => "Test::Pod 1.00 requis pour le test de POD" if $@;
my @poddirs = qw( blib script );
use File::Spec::Functions qw( catdir updir );
all_pod_files_ok(
    all_pod_files( map { catdir updir, $_ } @poddirs )
);

DESCRIPTION

Vérifie les fichiers POD pour des erreurs ou des avertissements dans un fichier de test, en utilisant "Pod::Simple" pour effectuer le gros du travail.

FONCTIONS

pod_file_ok( NOM_FICHIER[, NOM_TEST ] )

pod_file_ok() validera le test si le POD est analysé correctement. Certaines conditions ne sont pas encore signalées, telles qu'un fichier sans aucun POD.

En cas d'échec, pod_file_ok() affichera toutes les erreurs de vérification de POD comme diagnostics.

L'argument optionnel second NOM_TEST est le nom du test. S'il est omis, pod_file_ok() choisit un nom de test par défaut : "Test POD pour NOM_FICHIER".

all_pod_files_ok( [@entrées] )

Vérifie tous les fichiers sous @entrées pour un POD valide. Elle exécute all_pod_files() sur les répertoires et suppose que tout le reste est un fichier à tester. Elle appelle la fonction plan() pour vous (un test pour chaque fichier), vous ne pouvez donc pas avoir déjà appelé "plan".

Si @entrées est vide ou n'est pas passé, la fonction trouve tous les fichiers POD dans les fichiers du répertoire blib s'il existe, ou le répertoire lib sinon. Un fichier POD correspond aux conditions spécifiées ci-dessous dans "all_pod_files".

Si vous testez un module, créez simplement un t/pod.t :

use Test::More;
eval "use Test::Pod 1.00";
plan skip_all => "Test::Pod 1.00 requis pour le test de POD" if $@;
all_pod_files_ok();

Retourne vrai si tous les fichiers pod sont ok, ou faux si l'un d'eux échoue.

all_pod_files( [@répertoires] )

Retourne une liste de tous les fichiers POD dans @répertoires et dans les répertoires inférieurs. Si aucun répertoire n'est passé, elle utilise par défaut blib si blib existe, ou lib sinon. Elle ignore tous les fichiers dans les répertoires CVS, .svn, .git et similaires. Voir %Test::Pod::ignore_dirs pour une liste de ceux-ci.

Un fichier POD est :

  • Tout fichier se terminant par .pl, .PL, .pm, .pod, .psgi ou .t.
  • Tout fichier dont la première ligne contient une ligne shebang et "perl".
  • Tout fichier se terminant par .bat et dont la première ligne contient "--*-Perl-*--".

L'ordre des fichiers retournés dépend de la machine. Si vous voulez les trier, vous devrez le faire vous-même.
