NOM

Test::Needs - Sauter les tests lorsque des modules ne sont pas disponibles

SYNTAXE

# besoin d'un module
use Test::Needs 'Module::Quelconque';
# besoin de plusieurs modules
use Test::Needs 'Module::Quelconque', 'Autre::Module::Quelconque';
# besoin d'une version donnée d'un module
use Test::Needs {
  'Module::Quelconque' => '1.005',
};
# vérifier plus tard
use Test::Needs;
test_needs 'Module::Quelconque';
# saute le reste du sous-test
use Test::More;
use Test::Needs;
subtest 'mon sous-test' => sub {
  test_needs 'Module::Quelconque';
  ...
};
# vérifier la version de perl
use Test::Needs { perl => 5.020 };

DESCRIPTION

Sauter les scripts de test si des modules ne sont pas disponibles. Les modules demandés seront chargés, et optionnellement leur version sera vérifiée. Si le module est manquant, le script de test sera sauté. Les modules qui sont trouvés mais qui échouent à la compilation quitteront avec une erreur plutôt que de sauter.

Si utilisé dans un sous-test, le reste du sous-test sera sauté.

Le saut fonctionnera même si certains tests ont déjà été exécutés, ou si un plan a été déclaré.

Les versions sont vérifiées via un appel "$module->VERSION($version_demandée)". Les versions doivent être fournies dans un format qui sera accepté. Aucun traitement supplémentaire n'est effectué sur celles-ci.

Si "perl" est utilisé comme module, la version est vérifiée par rapport à la version de perl en cours d'exécution ($]). La version peut être spécifiée comme un nombre, une chaîne décimale pointée, une chaîne v, ou un objet version.

Si la variable d'environnement "RELEASE_TESTING" est définie, les tests échoueront plutôt que de sauter. Les sous-tests seront abandonnés, mais le script de test continuera à s'exécuter après ce point.

EXPORTATIONS

test_needs

A la même interface que lors de l'utilisation de Test::Needs dans un "use".

VOIR AUSSI

Test::Requires
Un module similaire, avec des différences importantes. Test::Requires agira comme une instruction "use" (malgré son nom), appelant la sous-routine d'importation. Sous "RELEASE_TESTING", il effectuera un BAIL_OUT si un module ne peut pas être chargé plutôt qu'un échec de test normal. Il ne distingue pas non plus entre les modules manquants et les modules défectueux.
Test2::Require::Module
Fait partie de l'écosystème Test2. Ne prend en charge que l'exécution en tant que commande "use" pour sauter un plan entier.
Test2::Require::Perl
Fait partie de l'écosystème Test2. Ne prend en charge que l'exécution en tant que commande "use" pour sauter un plan entier. Vérifie les versions de perl.
Test::If
Agit comme une instruction "use". Ne prend en charge que l'exécution en tant que commande "use" pour sauter un plan entier. Peut sauter en fonction des résultats d'une sous-routine.
