NOM

Template::Manual::Filters - Filtres standards

format(format)

Le filtre "format" prend une chaîne de format comme paramètre (conformément à printf()) et formate chaque ligne de texte en conséquence.

[% FILTER format('<!-- %-40s -->') %]
Ceci est un bloc de texte filtré
à travers le format ci-dessus.
[% END %]

Sortie :

<!-- Ceci est un bloc de texte filtré        -->
<!-- à travers le format ci-dessus.               -->

upper

Convertit l'entrée en MAJUSCULES.

[% "bonjour le monde" FILTER upper %]

Sortie :

BONJOUR LE MONDE

lower

Convertit l'entrée en minuscules.

[% "Bonjour le Monde" FILTER lower %]

Sortie :

bonjour le monde

ucfirst

Met en majuscule le premier caractère de l'entrée.

[% "bonjour" FILTER ucfirst %]

Sortie :

Bonjour

lcfirst

Met en minuscule le premier caractère de l'entrée.

[% "BONJOUR" FILTER lcfirst %]

Sortie :

bONJOUR

trim

Supprime les espaces blancs de début et de fin du texte d'entrée. Particulièrement utile en conjonction avec "INCLUDE", "PROCESS", etc., ayant le même effet que l'option de configuration "TRIM".

[% INCLUDE myfile | trim %]

collapse

Réduit toute séquence d'espaces blancs dans le texte d'entrée à un seul espace. Les espaces blancs de début et de fin (qui seraient réduits à un seul espace) sont supprimés, comme avec trim.

[% FILTER collapse %]
   Le   chat
   est    assis
   sur   le tapis
[% END %]

Sortie :

Le chat est assis sur le tapis

html

Convertit les caractères "<", ">", "&" et """ en "&lt;", "&gt;", "&amp;" et "&quot;" respectivement, les protégeant de l'interprétation comme balises ou entités HTML.

[% FILTER html %]
Binaire "<=>" retourne -1, 0, ou 1 selon...
[% END %]

Sortie :

Binaire "&lt;=&gt;" retourne -1, 0, ou 1 selon...

html_entity

Le filtre "html" est rapide et simple mais il n'encode pas la gamme complète d'entités HTML que votre texte peut contenir. Le filtre "html_entity" utilise soit le module "Apache::Util" (qui est écrit en C et donc plus rapide) soit le module "HTML::Entities" (écrit en Perl mais tout aussi complet) pour effectuer l'encodage.

Si l'un ou l'autre de ces modules est installé sur votre système, le texte sera encodé (via les sous-routines escape_html() ou encode_entities() respectivement) pour convertir tous les caractères étendus en leurs entités HTML appropriées (par exemple, convertir '"?"' en '"&eacute;"'). Si aucun des modules n'est disponible sur votre système, une exception '"html_entity"' sera levée avec un message approprié.

Si vous souhaitez forcer TT à utiliser l'un des modules ci-dessus de préférence à l'autre, appelez l'une des méthodes de classe de Template::Filters : use_html_entities() ou use_apache_util().

use Template::Filters;
Template::Filters->use_html_entities;

Pour plus d'informations sur l'encodage des entités HTML, voir http://www.w3.org/TR/REC-html40/sgml/entities.html.

xml

Identique au filtre "html", mais ajoute "&apos;" qui est la cinquième entité intégrée XML.

html_para

Ce filtre formate un bloc de texte en paragraphes HTML. Une séquence de deux sauts de ligne ou plus est utilisée comme délimiteur pour les paragraphes qui sont ensuite encapsulés dans des balises HTML "<p>"..."</p>".

[% FILTER html_para %]
Le chat était assis sur le tapis.
Marie avait un petit agneau.
[% END %]

Sortie :

<p>
Le chat était assis sur le tapis.
</p>
<p>
Marie avait un petit agneau.
</p>

html_break / html_para_break

Similaire au filtre html_para décrit ci-dessus, mais utilise la séquence de balises HTML "<br><br>" pour joindre les paragraphes.

[% FILTER html_break %]
Le chat était assis sur le tapis.
Marie avait un petit agneau.
[% END %]

Sortie :

Le chat était assis sur le tapis.
<br>
<br>
Marie avait un petit agneau.

html_line_break

Ce filtre remplace tout saut de ligne par des balises HTML "<br>", préservant ainsi les sauts de ligne du texte original dans la sortie HTML.

[% FILTER html_line_break %]
Le chat était assis sur le tapis.
Marie avait un petit agneau.
[% END %]

Sortie :

Le chat était assis sur le tapis.<br>
Marie avait un petit agneau.<br>

uri

Ce filtre échappe les URI du texte d'entrée, convertissant tout caractère en dehors de l'ensemble de caractères URI autorisé (tel que défini par RFC 3986) en un échappement hexadécimal %nn.

[% 'mon fichier.html' | uri %]

Sortie :

mon%20fichier.html

Le filtre uri encode correctement tous les caractères réservés, y compris "&", "@", "/", ";", ":", "=", "+", "?" et "$". Ce filtre est généralement utilisé pour encoder des paramètres dans une URL qui pourraient autrement être interprétés comme faisant partie de l'URL. Voici un exemple :

[% path  = 'http://tt2.org/example'
   back  = '/other?foo=bar&baz=bam'
   title = 'Terre: "Moyennement sans danger"'
%]
<a href="[% path %]?back=[% back | uri %]&title=[% title | uri %]">

La sortie générée est assez longue, nous allons donc la montrer répartie sur deux lignes :

<a href="http://tt2.org/example?back=%2Fother%3Ffoo%3Dbar%26
baz%3Dbam&title=Terre%3A%20%22Moyennement%20sans%20danger%22">

Sans le filtre uri, la sortie ressemblerait à ceci (également répartie sur deux lignes).

<a href="http://tt2.org/example?back=/other?foo=bar
&baz=bam&title=Terre: "Moyennement sans danger"">

Dans cet exemple plutôt contraint, nous avons réussi à générer à la fois une URL incorrecte (le '?' répété n'est pas autorisé) et un élément HTML incorrect (l'attribut href est terminé par le premier '"' après 'Terre: ' laissant '"Moyennement sans danger"'"' en suspens à la fin de la balise d'une manière qui n'est pas du tout propice aux choses sans danger). Ne faites donc pas cela. Utilisez toujours le filtre uri pour encoder vos paramètres d'URL.

Cependant, vous ne devriez **pas** utiliser le filtre uri

uri

The "uri" filter is intended to encode a string into a valid URI, converting characters that are reserved in URIs into percent-escaped sequences. However, it also encodes characters that are considered safe in URIs but may be problematic in URLs, such as the forward slash ("/").

Because of this, it is generally not the correct filter to use when you need to encode an entire URL.

<a href="[% page_url | uri %]">   # WRONG!

This will incorrectly encode any reserved characters like ":" and "/" and that's almost certainly not what you want in this case. Instead you should use the url (note spelling) filter for this purpose.

<a href="[% page_url | url %]">   # CORRECT

Please note that this behaviour was changed in version 2.16 of the Template Toolkit. Prior to that, the uri filter did not encode the reserved characters, making it technically incorrect according to the RFC 2396 specification (since superceded by RFC2732 and RFC3986). So we fixed it in 2.16 and provided the url filter to implement the old behaviour of not encoding reserved characters.

As of version 2.28 of the Template Toolkit, the "uri" and url filters use the unsafe character set defined by RFC3986. This means that certain characters ("(", ")", "*", "!", "'", and '"') are now deemed unsafe and will be escaped as hex character sequences.

The ability to use the RFC3986 character set was added in 2.26 but not enabled by default; double quote was incorrectly deemed safe in 2.26 but correctly escaped in 2.27.

If you want to enable the old behaviour then call the use_rfc2732() method in Template::Filters

use Template::Filters
Template::Filters->use_rfc2732;

url

The url filter is a less aggressive version of the uri filter. It encodes any characters outside of the permitted URI character set (as defined by RFC 2396) into %nn hex escapes. However, unlike the uri filter, the url filter does not encode the reserved characters "&", "@", "/", ";", ":", "=", "+", "?" and "$".

indent(pad)

Indents the text block by a fixed pad string or width. The '"pad"' argument can be specified as a string, or as a numerical value to indicate a pad width (spaces). Defaults to 4 spaces if unspecified.

[% FILTER indent('ME> ') %]
blah blah blah
cabbages, rhubard, onions
[% END %]

Output:

ME> blah blah blah
ME> cabbages, rhubard, onions

truncate(length,dots)

Truncates the text block to the length specified, or a default length of 32. Truncated text will be terminated with '"..."' (i.e. the '"..."' falls inside the required length, rather than appending to it).

[% FILTER truncate(21) %]
I have much to say on this matter that has previously
been said on more than one occasion.
[% END %]

Output:

I have much to say...

If you want to use something other than '"..."' you can pass that as a second argument.

[% FILTER truncate(26, '&hellip;') %]
I have much to say on this matter that has previously
been said on more than one occasion.
[% END %]

Output:

I have much to say&hellip;

repeat(iterations)

Repeats the text block for as many iterations as are specified (default: 1).

[% FILTER repeat(3) %]
We want more beer and we want more beer,
[% END %]
We are the more beer wanters!

Output:

We want more beer and we want more beer,
We want more beer and we want more beer,
We want more beer and we want more beer,
We are the more beer wanters!

remove(string)

Searches the input text for any occurrences of the specified string and removes them. A Perl regular expression may be specified as the search string.

[% "The  cat  sat  on  the  mat" FILTER remove('\s+') %]

Output:

Thecatsatonthemat

replace(search, replace)

Similar to the remove filter described above, but taking a second parameter which is used as a replacement string for instances of the search string.

[% "The  cat  sat  on  the  mat" | replace('\s+', '_') %]

Output:

The_cat_sat_on_the_mat

redirect(file, options)

The "redirect" filter redirects the output of the block into a separate file, specified relative to the "OUTPUT_PATH" configuration item.

[% FOREACH user IN myorg.userlist %]
   [% FILTER redirect("users/${user.id}.html") %]
      [% INCLUDE userinfo %]
   [% END %]
[% END %]

or more succinctly, using side-effect notation:

[%  FOREACH user IN myorg.userlist;
      INCLUDE userinfo
        FILTER redirect("users/${user.id}.html");
    END
%]

A "file" exception will be thrown if the "OUTPUT_PATH" option is undefined.

An optional "binmode" argument can follow the filename to explicitly set the output file to binary mode.

[% PROCESS my/png/generator
     FILTER redirect("images/logo.png", binmode=1) %]

For backwards compatibility with earlier versions, a single true/false value can be used to set binary mode.

[% PROCESS my/png/generator
     FILTER redirect("images/logo.png", 1) %]

For the sake of future compatibility and clarity, if nothing else, we would strongly recommend you explicitly use the named "binmode" option as shown in the first example.

eval / evaltt

The "eval" filter evaluates the block as template text, processing any directives embedded within it. This allows template variables to contain template fragments, or for some method to be provided for returning template fragments from an external source such as a database, which can then be processed in the template as required.

my $vars  = {
    fragment => "The cat sat on the [% place %]",
};
$template->process($file, $vars);

The following example:

[% fragment | eval %]

is therefore equivalent to

The cat sat on the [% place %]

The "evaltt" filter is provided as an alias for "eval".

perl / evalperl

The "perl" filter evaluates the block as Perl code. The "EVAL_PERL" option must be set to a true value or a "perl" exception will be thrown.

[% my_perl_code | perl %]

In most cases, the "[% PERL %]" ... "[% END %]" block should suffice for evaluating Perl code, given that template directives are processed before being evaluate as Perl. Thus, the previous example could have been written in the more verbose form:

[% PERL %]
[% my_perl_code %]
[% END %]

as well as

[% FILTER perl %]
[% my_perl_code %]
[% END %]

The "evalperl" filter is provided as an alias for "perl" for backwards compatibility.

stdout(options)

The stdout filter prints the output generated by the enclosing block to "STDOUT". The "binmode" option can be passed as either a named parameter or a single argument to set "STDOUT" to binary mode (see the binmode perl function).

[% PROCESS something/cool
       FILTER stdout(binmode=1) # recommended %]
[% PROCESS something/cool
       FILTER stdout(1)         # alternate %]

The "stdout" filter can be used to force "binmode" on "STDOUT", or also inside "redirect", "null" or "stderr" blocks to make sure that particular output goes to "STDOUT". See the "null" filter below for an example.

stderr

The stderr filter prints the output generated by the enclosing block to "STDERR".

null

The "null" filter prints nothing. This is useful for plugins whose methods return values that you don't want to appear in the output. Rather than assigning every plugin method call to a dummy variable to silence it, you can wrap the block in a null filter:

[% FILTER null;
    USE im = GD.Image(100,100);
    black = im.colorAllocate(0,   0, 0);
    red   = im.colorAllocate(255,0,  0);
    blue  = im.colorAllocate(0,  0,  255);
    im.arc(50,50,95,75,0,360,blue);
    im.fill(50,50,red);
    im.png | stdout(1);
   END;
-%]

Notice the use of the "stdout" filter to ensure that a particular expression generates output to "STDOUT" (in this case in binary mode).
