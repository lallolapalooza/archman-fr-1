NOM

Term::ReadPassword - Demander un mot de passe à l'utilisateur

SYNTAXE

use Term::ReadPassword;
while (1) {
  my $password = read_password('mot de passe: ');
  redo unless defined $password;
  if ($password eq 'flubber') {
    print "Accès accordé.\n";
    last;
  } else {
    print "Accès refusé.\n";
    redo;
  }
}

DESCRIPTION

Ce module vous permet de demander un mot de passe à l'utilisateur de la manière traditionnelle, depuis le clavier, sans écho.

Il n'est pas destiné à être utilisé sur le web ; l'authentification des utilisateurs sur le web est une autre affaire. De plus, ce module doit généralement être utilisé en conjonction avec la fonction crypt() de Perl, vendue séparément.

La fonction read_password demande une saisie, lit une ligne de texte depuis le clavier, puis renvoie cette ligne à l'appelant. La ligne de texte n'inclut pas le caractère de nouvelle ligne, il n'est donc pas nécessaire d'utiliser chomp.

Pendant que l'utilisateur saisit le texte, quelques caractères spéciaux sont traités. Le caractère suppr (ou la touche retour arrière) permet de revenir en arrière d'un caractère, en supprimant le dernier caractère du tampon de saisie (s'il y en a un). Le caractère CR (ou LF) signale la fin de la saisie, provoquant le retour du tampon de saisie accumulé. Ctrl-U vide le tampon de saisie. Et, facultativement, le caractère Ctrl-C peut être utilisé pour terminer l'opération de saisie. (Voir les détails ci-dessous.) Tous les autres caractères, même ceux qui auraient normalement des fonctions spéciales, seront ajoutés au tampon de saisie.

Cependant, il n'est pas recommandé d'utiliser les caractères de contrôle non spécifiés dans vos mots de passe, car ces caractères pourraient acquérir une signification dans une future version de ce module. Les applications qui permettent à l'utilisateur de définir ses propres mots de passe peuvent souhaiter appliquer cette règle, peut-être avec un code similaire à celui-ci :

{
  # Bloc nu pour la portée et redo
  my $new_pw = read_password("Entrez votre nouveau mot de passe : ");
  if ($new_pw =~ /([^\x20-\x7E])/) {
    my $bad = unpack "H*", $1;
    print "Votre mot de passe ne peut pas contenir le ";
    print "caractère dont le code hexadécimal est $bad.\n";
    redo;
  } elsif (length($new_pw) < 5) {
    print "Votre mot de passe doit être plus long !\n";
    redo;
  } elsif ($new_pw ne read_password("Entrez-le à nouveau : ")) {
    print "Les mots de passe ne correspondent pas.\n";
    redo;
  } else {
    &change_password($new_pw);
    print "Votre mot de passe est maintenant modifié.\n";
  }
}

Le deuxième paramètre de read_password est la valeur facultative "idle_timeout". Si c'est un nombre non nul et qu'il n'y a pas de saisie clavier pendant ce nombre de secondes, l'opération de saisie se terminera. Notez qu'il ne s'agit pas d'une limite de temps globale, car le minuteur est redémarré à chaque nouveau caractère.

Le troisième paramètre permettra facultativement à l'opération de saisie d'être terminée par l'utilisateur avec Ctrl-C. Si ce n'est pas fourni, ou si c'est faux, un Ctrl-C tapé sera entré dans le tampon de saisie comme tout autre caractère. Dans ce cas, il n'y a aucun moyen depuis le clavier de terminer le programme pendant qu'il attend une saisie. (C'est-à-dire que la capacité normale de générer des signaux depuis le clavier est suspendue pendant l'appel à read_password.)

Si l'opération de saisie se termine prématurément (soit parce que l'idle_timeout a été dépassé, soit parce qu'un Ctrl-C a été activé et tapé), la valeur de retour sera "undef". Dans les deux cas, aucun moyen n'est fourni pour découvrir ce qui (le cas échéant) a été tapé avant la terminaison prématurée, ni pourquoi l'opération de saisie a été terminée.

Afin de décourager les utilisateurs de taper leurs mots de passe ailleurs qu'à l'invite, toute saisie qui a été "pré-tapée" avant l'apparition de l'invite sera ignorée. Et que l'opération de saisie se termine normalement ou non, un caractère de nouvelle ligne sera imprimé, afin que le curseur ne reste pas sur la ligne après l'invite.

BOGUES

Les utilisateurs de Windows voudront Term::ReadPassword::Win32.

Ce module a une interface mal conçue, et devrait être entièrement repensé et probablement réuni avec la version Windows.

Les utilisateurs qui souhaitent voir les caractères du mot de passe affichés sous forme d'étoiles peuvent définir $Term::ReadPassword::USE_STARS sur une valeur vraie. Les bogues sont que certains terminaux peuvent ne pas effacer les étoiles lorsque l'utilisateur corrige une erreur, et que l'utilisation d'étoiles divulgue des informations aux curieux.

SÉCURITÉ

On pourrait penser qu'un module traitant des mots de passe serait plein de fonctionnalités de sécurité. On pourrait penser cela, mais on aurait tort. Par exemple, perl ne fournit aucun moyen d'effacer une donnée de la mémoire. (Il est facile de l'effacer de manière à ce qu'elle ne puisse pas être accédée depuis perl, mais ce n'est pas la même chose que de l'expurger de la mémoire réelle.) Si vous avez saisi un mot de passe, même si la variable qui le contenait a été effacée, il pourrait être possible pour quelqu'un de trouver ce mot de passe, en clair, dans un vidage de noyau (core dump). Et ce n'est qu'un trou de sécurité potentiel.

En bref, si la sécurité sérieuse est une préoccupation, n'utilisez pas ce module.
