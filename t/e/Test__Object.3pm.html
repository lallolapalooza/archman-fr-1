Test::Object(3) Documentation Perl contribuée par l'utilisateur Test::Object(3)

NOM

Test::Object - Tester rigoureusement des objets via des gestionnaires enregistrés

VERSION

version 0.08

SYNOPSIS

###################################################################
# Dans votre module de test, enregistrez à nouveau les gestionnaires
# de test pour les noms de classes.
###################################################################

package My::ModuleTester;

use Test::More;
use Test::Object;

# Foo::Bar est une sous-classe de Foo
Test::Object->register(
      class => 'Foo',
      tests => 5,
      code  => \&foo_ok,
      );
Test::Object->register(
      class => 'Foo::Bar',
      # Pas de nombre fixe de tests
      code  => \&foobar_ok,
      );

sub foo_ok {
      my $object = shift;
      ok( $object->foo, '->foo renvoie vrai' );
}

sub foobar_ok {
      my $object = shift;
      is( $object->foo, 'bar', '->foo renvoie "bar"' );
}

1;



###################################################################
# Dans le script de test, testez l'objet contre toutes les classes
# enregistrées.
###################################################################

#!/usr/bin/perl -w

use Test::More 'no_plan';
use Test::Object;
use My::ModuleTester;

my $object = Foo::Bar->new;
isa_ok( $object, 'Foo::Bar' );
object_ok( $object );

DESCRIPTION

Dans les situations où vous avez des arbres de classes profonds, il existe une situation courante où vous testez un module 4 ou 5 sous-classes en dessous, qui devraient suivre le comportement correct non seulement de la sous-classe, mais de toutes les classes parentes.

Cela doit être fait pour s'assurer que l'implémentation d'une sous-classe n'a pas d'une manière ou d'une autre "cassé" le comportement de l'objet dans un sens plus général.

"Test::Object" est un paquet de test conçu pour vous permettre de tester facilement ce que vous croyez être un objet valide contre le comportement attendu de **toutes** les classes de son arbre d'héritage en un seul appel.

Pour ce faire, vous "enregistrez" des tests (sous forme de références CODE ou de fonctions) auprès de "Test::Object", chaque test étant associé à une classe particulière.

Lorsque vous appelez "object_ok" dans votre script de test, "Test::Object" vérifiera l'objet par rapport à tous les tests enregistrés. Pour chaque classe pour laquelle votre objet répond à "$object->isa($class)", la fonction de test appropriée sera appelée.

Faire cela permet aux objets adaptateurs et autres choses qui répondent à "isa" différemment par défaut d'être toujours testés par rapport aux classes qu'ils annoncent correctement.

Cela signifie également que plus d'un test pourrait être "compté" pour chaque appel à "object_ok". Vous devriez en tenir compte correctement dans votre compte de tests attendu.
