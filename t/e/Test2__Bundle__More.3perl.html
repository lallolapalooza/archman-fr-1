Test2::Bundle::More(3perl) Guide du programmeur Perl Test2::Bundle::More(3perl)

NOM

Test2::Bundle::More - Presque un remplacement direct de Test::More.

DESCRIPTION

Ce paquet est destiné à être un remplacement (principalement) direct de Test::More. Voir "DIFFÉRENCES CLÉS PAR RAPPORT À Test::More" pour les détails.

EXEMPLE

use Test2::Bundle::More;
ok(1, "réussite");
...
done_testing;

PLUGINS

Charge Test2::Plugin::ExitSummary.

OUTILS

Ceux-ci proviennent de Test2::Tools::Basic. Voir Test2::Tools::Basic pour les détails.

ok($bool, $nom)
pass($nom)
fail($nom)
skip($pourquoi, $nombre)
$todo = todo($why)
diag($message)
note($message)
plan($nombre)
skip_all($pourquoi)
done_testing()
BAIL_OUT($pourquoi)

Ceux-ci proviennent de Test2::Tools::ClassicCompare. Voir Test2::Tools::ClassicCompare pour les détails.

is($obtenu, $voulu, $nom)
isnt($obtenu, $nepasvoulu, $nom)
like($obtenu, qr/correspondance/, $nom)
unlike($obtenu, qr/incohérence/, $nom)
is_deeply($obtenu, $voulu, "Comparaison profonde")
cmp_ok($obtenu, $op, $voulu, $nom)

Ceux-ci proviennent de Test2::Tools::Class. Voir Test2::Tools::Class pour les détails.

isa_ok($chose, @classes)
can_ok($chose, @subs)

Ceci provient de Test2::Tools::Subtest. Il est appelé subtest_streamed() dans ce paquet.

subtest $nom => sub { ... }

DIFFÉRENCES CLÉS PAR RAPPORT À Test::More

Vous ne pouvez pas planifier lors de l'importation.
Ceci ne fonctionnera pas : 
use Test2::Bundle::More tests => 5;

Au lieu de cela, vous devez planifier dans une instruction séparée :

use Test2::Bundle::More;
plan 5;
Vous avez trois sous-routines importées pour la planification
Utilisez plan($nombre), skip_all($raison), ou done_testing() pour votre planification.
isa_ok accepte des arguments différents
"isa_ok" dans Test::More était : 
isa_ok($thing, $isa, $alt_thing_name);

C'était très incohérent avec des outils comme "can_ok($thing, @subs)".

Dans Test2::Bundle::More, isa_ok() prend une $chose et une liste de @isa.

isa_ok($chose, $classe1, $classe2, ...);

CES FONCTIONS ET VARIABLES ONT ÉTÉ SUPPRIMÉES

$TODO
Voir todo().
use_ok()
require_ok()
Elles ne sont pas nécessaires. Utilisez "use" et "require" directement. S'il y a une erreur lors du chargement du module, le test capturera l'erreur et échouera.
todo_skip()
Pas nécessaire.
eq_array()
eq_hash()
eq_set()
Déconseillé dans Test::More.
explain()
Cela a déclenché une bataille entre les développeurs de tests, qui peuvent maintenant écrire chacun leurs propres implémentations dans Test2. (Voir explain dans Test::Most vs Test::More. Indice : Test::Most l'a écrit en premier, puis Test::More l'a ajouté, mais a brisé la compatibilité).
new_ok()
Pas nécessaire.
