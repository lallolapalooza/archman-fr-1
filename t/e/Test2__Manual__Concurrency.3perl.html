Test2::Manual::Concurrency(3perl) Guide du programmeur Perl Test2::Manual::Concurrency(3perl)

NOM

Test2::Manual::Concurrency - Documentation pour le support de la concurrence.

FORK

Test2

Test2 supporte le fork. Pour que le fork fonctionne, vous devez charger Test2::IPC.

Test::Builder

Test::Builder ne supportait pas le fork, mais maintenant qu'il est basé sur Test2, il le fait. Test2::IPC doit être chargé tout comme avec Test2.

Test2::Suite

Les outils de Test2::Suite devraient tous fonctionner correctement avec le fork *vrai*, sauf indication contraire. Le pseudo-fork via threads (Windows et quelques autres) n'est pas supporté, mais peut fonctionner.

Les correctifs seront acceptés pour réparer tout problème de pseudo-fork, mais pour qu'ils soient utilisés ou testés, ils doivent être demandés. Les tests de fork ne devraient pas s'exécuter sur des systèmes de pseudo-fork à moins qu'ils ne soient demandés avec une variable d'environnement, ou la variable AUTHOR_TESTING. Le pseudo-fork est fragile, et nous ne voulons pas bloquer l'installation en raison d'un défaut de pseudo-fork.

Test::SharedFork

Test::SharedFork est actuellement supporté et maintenu, bien qu'il ne soit plus nécessaire grâce à Test2::IPC. Si son utilisation venait à diminuer, le module pourrait être déprécié, mais pour l'instant, la politique est de ne pas le laisser casser. Actuellement, il charge simplement Test2::IPC s'il le peut, et se rabat sur les anciennes méthodes sur les installations héritées.

Autres

Les auteurs individuels sont libres de supporter ou non le fork comme bon leur semble.

THREADS

Note Ceci ne s'applique qu'aux ithreads.

Test2

Le cœur de Test2 supporte le threading tant que Test2::IPC est chargé. Le support de base du threading (s'assurer que les événements parviennent au thread parent) est entièrement supporté et ne doit pas être rompu.

Parfois, les installations Perl ont des threads défectueux (certaines versions 5.10 compilées sur des gcc plus récents échouent simplement en démarrant un thread). Ceci est hors du contrôle de Test2 et non résoluble dans Test2. Cela dit, nous nous efforçons d'assurer un support de base du threading sur perl 5.8.1+.

Si Test2 échoue pour les threads sur n'importe quel perl 5.8 ou supérieur, et qu'il est raisonnablement possible pour Test2 de contourner le problème, il devrait le faire. (Correctifs et rapports de bugs bienvenus).

Test::Builder

Test::Builder a supporté le threading pendant longtemps. Avec Test2, le mécanisme de support du threading a été basculé vers Test2::IPC. Test::Builder devrait toujours supporter les threads autant qu'il le faisait avant le basculement vers Test2. Le support inclut l'activation automatique du support du threading si threads est chargé avant Test::Builder.

S'il y a une déviation entre le nouveau comportement de threading et l'ancien, c'est un bug (à moins que l'ancien comportement lui-même ne puisse être classé comme un bug.) Veuillez signaler (ou corriger !) tout problème de threading de ce type.

Test2::Suite

Les outils de Test2::Suite ont un support de threading minimal. La plupart de ces outils ne se soucient pas/ne remarquent pas le threading et fonctionnent simplement parce que Test2::IPC le gère. N'hésitez pas à signaler tout bug lié aux threads dans Test2::Suite. Sachez cependant que ces outils ne sont pas hérités et n'ont pas de support de threading préexistant, nous nous réservons le droit de refuser d'ajouter le support de threading à ceux-ci.

Test2::Workflow

Test2::Workflow a été fusionné dans Test2::Suite, il est donc couvert par cette politique.

Test2::Workflow a un support de threading, mais vous devez le demander. Les tests de threads pour Test2::Workflow ne s'exécutent pas sans définir la variable d'environnement AUTHOR_TESTING, ou la variable T2_DO_THREAD_TESTS.

Pour utiliser les threads avec Test2::Workflow, vous devez définir la variable d'environnement T2_WORKFLOW_USE_THREADS.

Si vous vous fiez aux threads avec Test2::Workflow et que vous trouvez un bug, veuillez le signaler, mais il recevra une priorité ultra-faible. La fusion des correctifs qui résolvent les problèmes de threading recevra une priorité normale.
