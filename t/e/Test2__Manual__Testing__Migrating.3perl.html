Test2::Manual::Testing::Migrating(3perl) Guide de référence des programmeurs Perl Test2::Manual::Testing::Migrating(3perl)

NOM

Test2::Manual::Testing::Migrating - Comment migrer des tests existants de Test::More vers Test2.

DESCRIPTION

Ce tutoriel couvre la conversion d'un test existant. Ce tutoriel suppose que vous avez un test écrit en utilisant Test::More.

TEST LEGACY

Ce tutoriel convertira cet exemple de test section par section :

"t/example.t" :

#####################
# Boilerplate
use strict;
use warnings;
use Test::More tests => 14;
use_ok 'Scalar::Util';
require_ok 'Exporter';
#####################
# Assertions simples (pas de changements)
ok(1, "pass");
is("apple", "apple", "Comparaison de chaînes simple");
like("foo bar baz", qr/bar/, "Correspondance d'expression régulière");
#####################
# Todo
{
    local $TODO = "Ceux-ci sont en attente";
    ok(0, "oops");
}
#####################
# Comparaisons profondes
is_deeply([1, 2, 3], [1, 2, 3], "Comparaison profonde");
#####################
# Comparaison de références
my $ref = [1];
is($ref, $ref, "Vérifier que nous avons la même référence les deux fois");
#####################
# Éléments qui ont disparu
ok(eq_array([1], [1]), "comparaison de tableaux");
ok(eq_hash({a => 1}, {a => 1}), "comparaison de hachages");
ok(eq_set([1, 3, 2], [1, 2, 3]), "comparaison d'ensembles");
note explain([1, 2, 3]);
{
    package THING;
    sub new { bless({}, shift) }
}
my $thing = new_ok('THING');
#####################
# Outils qui ont changé
isa_ok($thing, 'THING', '$thing');
can_ok(__PACKAGE__, qw/ok is/);

BOILERPLATE

AVANT :

use strict;
use warnings;
use Test::More tests => 14;
use_ok 'Scalar::Util';
require_ok 'Exporter';

APRÈS :

use Test2::V0;
plan(11);
use Scalar::Util;
require Exporter;
Remplacer Test::More par Test2::V0
Test2::V0 est le paquet recommandé. Dans une migration complète, vous voudrez remplacer Test::More par le paquet Test2::V0.

Note : Vous devez toujours vérifier la dernière version de Test2 pour voir s'il existe un nouveau paquet recommandé. Lors de l'écriture d'un nouveau test, vous devriez toujours utiliser le module Test::V# le plus récent. Des nombres plus élevés indiquent une version plus récente.

NOTE : srand
Lorsque srand est activé (par défaut), il peut causer des problèmes avec des éléments tels que File::Temp, qui finiront par tenter d'utiliser les mêmes noms de fichiers « aléatoires » pour chaque processus de test lancé un jour donné (ou partageant la même graine).

Si cela vous pose problème, veuillez désactiver srand lors du chargement de Test2::V0 :

use Test2::V0 -no_srand => 1;
Arrêter d'utiliser use_ok()
use_ok() a été supprimé. Une instruction "use MODULE" lèvera une exception en cas d'échec, empêchant ainsi le test de passer.

Si vous voulez/devez *VRAIMENT* vous assurer que le fichier a été chargé, vous pouvez utiliser le module ok :

use ok 'Scalar::Util';

La principale différence ici est qu'il y a un espace au lieu d'un soulignement.

Arrêter d'utiliser require_ok()
"require_ok" a été supprimé, tout comme "use_ok". Il n'y a pas d'équivalent de module ok ici. Utilisez simplement "require".
Supprimer strict/warnings (facultatif)
Le paquet Test2::V0 active strict et warnings pour vous.
Changer l'endroit où le plan est défini
Test2 ne vous permet pas de définir le plan lors de l'importation. Dans l'ancien code, vous passiez "tests => 11" comme argument d'importation. Dans Test2, vous devez soit utiliser la fonction plan() pour définir le plan, soit utiliser done_testing() à la fin du test.

Si votre test utilise déjà done_testing(), vous pouvez le conserver et aucun changement de plan n'est nécessaire.

Note : Nous changeons également le plan de 14 à 11, car nous avons supprimé "use_ok", "require_ok", et nous en supprimerons un autre plus tard. C'est pourquoi done_testing() est recommandé plutôt qu'un plan défini.

ASSERTIONS SIMPLES

La grande majorité des assertions n'aura pas besoin de modifications :

#####################
# Assertions simples (pas de changements)
ok(1, "pass");
is("apple", "apple", "Comparaison de chaînes simple");
like("foo bar baz", qr/bar/, "Correspondance d'expression régulière");

TODO

{
    local $TODO = "Ceux-ci sont en attente";
    ok(0, "oops");
}

La variable de paquet $TODO a disparu. Vous avez maintenant une fonction todo().

Il existe 2 façons de l'utiliser :

todo $raison => sub { ... }
todo "Ceux-ci sont en attente" => sub {
    ok(0, "oops");
};

C'est la façon la plus propre de faire un todo. Cela rendra toutes les assertions à l'intérieur du bloc de code des assertions TODO.

{ my $TODO = todo $raison; ... } 
{
    my $TODO = todo "Ceux-ci sont en attente";
    ok(0, "oops");
}

C'est un système qui émule l'ancienne méthode. Au lieu de modifier une variable globale $TODO, vous créez un objet todo avec la fonction todo() et l'assignez à une variable lexicale. Une fois que l'objet todo sort de la portée, le TODO se termine.

COMPARAISONS PROFONDES

is_deeply([1, 2, 3], [1, 2, 3], "Comparaison profonde");

Les comparaisons profondes sont faciles, remplacez simplement is_deeply() par is().

is([1, 2, 3], [1, 2, 3], "Comparaison profonde");

COMPARAISON DE REFERENCES

my $ref = [1];
is($ref, $ref, "Vérifier que nous avons la même référence les deux fois");

La fonction is() fournie par Test::More force les deux arguments en chaînes de caractères, ce qui en fait une comparaison des adresses de référence. La fonction is() de Test2 est une comparaison profonde, donc cela passera toujours, mais ne parvient pas réellement à tester ce que nous voulons (que les deux références soient la même référence exacte, pas seulement des structures identiques.)

Nous avons maintenant la fonction ref_is() qui fait ce que nous voulons vraiment, elle s'assure que les deux références sont la même référence. Cette fonction fait mieux le travail que l'original, qui pouvait être perturbé par la surcharge de chaînes.

my $ref = [1];
ref_is($ref, $ref, "Vérifier que nous avons la même référence les deux fois");

OUTILS QUI ONT DISPARU

ok(eq_array([1], [1]), "comparaison de tableaux");
ok(eq_hash({a => 1}, {a => 1}), "comparaison de hachages");
ok(eq_set([1, 3, 2], [1, 2, 3]), "comparaison d'ensembles");
note explain([1, 2, 3]);
{
    package THING;
    sub new { bless({}, shift) }
}
my $thing = new_ok('THING');

"eq_array", "eq_hash" et "eq_set" sont considérés comme obsolètes depuis très longtemps, Test2 ne les fournit pas du tout. À la place, vous pouvez simplement utiliser is() :

is([1], [1], "comparaison de tableaux");
is({a => 1}, {a => 1}, "comparaison de hachages");

"eq_set" est un peu plus compliqué, voir Test2::Tools::Compare pour une explication :

is([1, 3, 2], bag { item 1; item 2; item 3; end }, "comparaison d'ensembles");

explain() a une histoire mouvementée. Il y a eu des arguments sur la façon dont il devrait fonctionner.

Test2::Manual::Testing::Migrating(3perl) — Perldoc Browser

NAME

Test2::Manual::Testing::Migrating - Migrating from Test::More to Test2

DESCRIPTION

This document will help you migrate your tests from Test::More to Test2.

LEGACY TEST

Most tests from Test::More are compatible with Test2. This is because Test2 is designed to be backwards compatible with Test::More.

use Test::More;
plan(1);
ok(1);

Becomes:

use Test2::V0;
plan(1);
ok(1);

You can also use Test2::Bundle::More to get Test::More compatibility.

use Test2::Bundle::More;
plan(1);
ok(1);

BOILERPLATE

Test2 does not require any boilerplate.

use Test::More;

Becomes:

use Test2::V0;

Or:

use Test2::Suite;

Or:

use Test2::API;

Or:

use Test2::Tools::Generic;

If you need the features from Test::More, you can use:

use Test2::Bundle::More;

Test2::V0 is generally recommended.

SIMPLE ASSERTIONS

The simple assertions like ok(), is(), unlike(), like(), cmp_ok(), ok_or_diag(), is_deeply(), unlike_or_diag(), like_or_diag(), fail(), skip(), skip_all(), and done_testing() are all compatible.

is([1], [1], "array comparison");
is({a => 1}, {a => 1}, "hash comparison");
is([1, 3, 2], bag { item 1; item 2; item 3; end }, "set comparison");

TODO

The todo() block is compatible.

todo "This is a todo" => sub {
    ok(0, "this should fail");
};

DEEP COMPARISONS

is_deeply() is gone. Use is() instead.

use Test::More;
is_deeply([1, 2, {a => 1}], [1, 2, {a => 1}]);

Becomes:

use Test2::V0;
is([1, 2, {a => 1}], [1, 2, {a => 1}]);

COMPARING REFERENCES

ref_is() is gone. Use is() instead.

use Test::More;
my $array = [1];
ref_is($array, $array);

Becomes:

use Test2::V0;
my $array = [1];
is($array, $array);

TOOLS THAT ARE GONE

Test2 decided to simply not include explain() to avoid the arguments. You can instead directly use Data::Dumper:

use Data::Dumper;
note Dumper([1, 2, 3]);

new_ok() is gone. The implementation was complicated, and did not add much value:

{
    package THING;
    sub new { bless({}, shift) }
}
my $thing = THING->new;
ok($thing, "made a new thing");

The complete section after the conversion is:

is([1], [1], "array comparison");
is({a => 1}, {a => 1}, "hash comparison");
is([1, 3, 2], bag { item 1; item 2; item 3; end }, "set comparison");
use Data::Dumper;
note Dumper([1, 2, 3]);
{
    package THING;
    sub new { bless({}, shift) }
}
my $thing = THING->new;
ok($thing, "made a new thing");

TOOLS THAT HAVE CHANGED

isa_ok($thing, 'THING', '$thing');
can_ok(__PACKAGE__, qw/ok is/);

In Test::More these functions are very confusing, and most people use them wrong!

isa_ok() from Test::More takes a thing, a class/reftype to check, and then uses the third argument as an alternative display name for the first argument (NOT a test name!).

can_ok() from Test::More is not consistent with "isa_ok" as all arguments after the first are subroutine names.

Test2 fixes this by making both functions consistent and obvious:

isa_ok($thing, ['THING'], 'got a THING');
can_ok(__PACKAGE__, [qw/ok is/], "have expected subs");

You will note that both functions take a thing, an arrayref as the second argument, then a test name as the third argument.

FINAL VERSION

#####################
# Boilerplate
use Test2::V0;
plan(11);
use Scalar::Util;
require Exporter;
#####################
# Simple assertions (no changes)
ok(1, "pass");
is("apple", "apple", "Simple string compare");
like("foo bar baz", qr/bar/, "Regex match");
#####################
# Todo
todo "These are todo" => sub {
    ok(0, "oops");
};
#####################
# Deep comparisons
is([1, 2, 3], [1, 2, 3], "Deep comparison");
#####################
# Comparing references
my $ref = [1];
ref_is($ref, $ref, "Check that we have the same ref both times");
#####################
# Things that are gone
is([1], [1], "array comparison");
is({a => 1}, {a => 1}, "hash comparison");
is([1, 3, 2], bag { item 1; item 2; item 3; end }, "set comparison");
use Data::Dumper;
note Dumper([1, 2, 3]);
{
    package THING;
    sub new { bless({}, shift) }
}
my $thing = THING->new;
#####################
# Tools that changed
isa_ok($thing, ['THING'], 'got a THING');
can_ok(__PACKAGE__, [qw/ok is/], "have expected subs");
