NOM

Text::Diff - Effectuer des différences sur des fichiers et des ensembles de données

SYNTAXE

use Text::Diff;
## Mélanger des noms de fichiers, des chaînes, des descripteurs de fichiers, des sous-programmes générateurs,
## ou des tableaux d'enregistrements ; renvoie la différence sous forme de chaîne.
## NOTE : peut renvoyer de grandes différences pour de grands fichiers.
my $diff = diff "file1.txt", "file2.txt", { STYLE => "Context" };
my $diff = diff \$string1,   \$string2,   \%options;
my $diff = diff \*FH1,       \*FH2;
my $diff = diff \&reader1,   \&reader2;
my $diff = diff \@records1,  \@records2;
## Peut également mélanger les types d'entrée :
my $diff = diff \@records1,  "file_B.txt";

DESCRIPTION

diff() fournit un ensemble de services de base similaires à l'utilitaire "diff" de GNU. Il n'est pas aussi complet que le "diff" de GNU, mais il est mieux intégré à Perl et disponible sur tous les systèmes. Il est généralement plus rapide que l'exécution d'un "diff" système pour les petits fichiers, et plus lent pour les grands fichiers.

Il dépend de Algorithm::Diff pour l'algorithme. Cela ne produit pas la même différence exacte que l'exécutable local "diff" du système, mais ce sera une différence valide et compréhensible par "patch". Nous n'avons pas constaté de différences entre la logique de Algorithm::Diff et celle du "diff" de GNU, mais nous n'avons pas examiné pour nous assurer qu'ils sont identiques.

Note : Si vous ne souhaitez pas importer la fonction "diff", faites l'une des choses suivantes :

use Text::Diff ();
require Text::Diff;

C'est très rare, donc diff() est exporté par défaut.

Si vous passez un nom de fichier mais que le fichier ne peut pas être lu, diff() fera un "croak".

OPTIONS

diff() prend deux paramètres à partir desquels les données d'entrée sont dérivées, et un ensemble d'options pour contrôler la sortie. Les options sont :

FILENAME_A, MTIME_A, FILENAME_B, MTIME_B
Le nom du fichier et l'heure de modification des « fichiers ». Ceux-ci sont renseignés automatiquement lorsque diff() reçoit un nom de fichier, sauf si une valeur définie a été passée.
OFFSET_A, OFFSET_B
L'index de la première ligne / élément. Ceux-ci sont par défaut à 1 pour tous les types de paramètres, sauf pour les tableaux de références, pour lesquels la valeur par défaut est 0. C'est parce que les tableaux de références sont censés être des structures de données, tandis que les autres sont du texte linéaire.
STYLE
« Unified », « Context », « OldStyle », ou une classe ou une référence d'objet qui fournit des méthodes telles que file_header(), hunk_header(), hunk(), hunk_footer() et file_footer(). Les deux méthodes footer() sont fournies pour la surcharge uniquement ; aucun des formats ne les fournit.
CONTEXT
Combien de lignes avant et après chaque différence afficher. Ignoré dans les anciens diffs. La valeur par défaut est 3.
OUTPUT
Exemples et leurs sous-programmes équivalents : 
OUTPUT   => \*FOOHANDLE,   # comme : sub { print FOOHANDLE shift() }
OUTPUT   => \$output,      # comme : sub { $output .= shift }
OUTPUT   => \@output,      # comme : sub { push @output, shift }
OUTPUT   => sub { $output .= shift },

Si "OUTPUT" n'est pas spécifié, il renvoie les différences sous forme de chaîne. Si "OUTPUT" est une référence "CODE", elle sera appelée une fois avec l'en-tête de fichier (facultatif), et une autre fois pour chaque corps de « hunk » avec le texte à émettre. Si "OUTPUT" est un objet d'entrée IO, la sortie sera dirigée vers cet objet.

FILENAME_PREFIX_A, FILENAME_PREFIX_B
La chaîne à imprimer avant le nom du fichier dans l'en-tête. Non utilisé dans les anciens diffs. Les valeurs par défaut sont « --- » et « +++ » pour le format Unifié, et « *** » et « +++ » pour le contexte.
KEYGEN, KEYGEN_ARGS
Ceux-ci sont transmis à traverse_sequences dans Algorithm::Diff.

Note : si aucune option "FILENAME_" n'est définie, l'en-tête ne sera pas imprimé. Si au moins une est présente, les autres et les deux options "MTIME_" doivent être définies, sinon des avertissements « Use of undefined variable » seront générés (sauf dans les diffs "OldStyle", qui ignorent ces options).

CLASSES DE FORMATAGE

Ces fonctions implémentent les formats de sortie. Elles sont regroupées en classes afin que diff() puisse utiliser les noms de classes pour appeler les routines de sortie correctes, et afin que vous puissiez facilement en hériter. Il n'y a pas de constructeurs ou de méthodes d'instanciation pour ces classes, bien que les sous-classes puissent en fournir si nécessaire.

Chaque classe a des méthodes file_header(), hunk_header(), hunk() et footer() identiques à celles mentionnées dans le chapitre "Text::Diff::Unified". header() est appelé avant hunk() pour le premier appel, et footer() après. La méthode par défaut de footer() est une fonction vide fournie pour la surcharge :

sub footer { return "Fin de patch\n" }

Certains formats de sortie sont fournis par des modules externes (qui sont chargés automatiquement), tels que Text::Diff::Table. Ceux-ci sont documentés ici pour simplifier la documentation.

NAME

Text::Diff - compute differences between sequences

SYNOPSIS

 use Text::Diff;

 my $diff = diff_files('file1.txt', 'file2.txt');
 print $diff; # Unified format

 my $diff = diff_chars("abcdef", "abcxyz");
 print $diff; # Char-by-char diff

 my $diff = diff (\@list1, \@list2);
 print $diff; # Unified format

 my $diff = diff (\@list1, \@list2, {
     FORMAT => 'Table',
     # Other options...
 });
 print $diff;

 my $diff = diff (\@list1, \@list2, {
     FORMAT => 'Context',
 });
 print $diff;

 my $diff = diff (\@list1, \@list2, {
     FORMAT => 'OldStyle',
 });
 print $diff;

DESCRIPTION

This module provides a simple interface to compute the differences between two sequences (usually lines of text, but can be characters or anything else). It uses the Algorithm::Diff module internally to compute the differences, and then formats the output in several common diff formats.

OPTIONS

The diff() function takes a number of optional arguments:

FORMAT

This specifies the output format. Currently supported formats are:

Unified
The default format. Similar to the output of GNU diff -u.
Context
Similar to the output of GNU diff -c.
OldStyle
Similar to the output of the original Unix diff command.
Table
A human-readable table format, which is very good at highlighting the exact differences between lines, including whitespace.
Chary
A character-by-character diff, useful for finding subtle differences within lines.
SideBySide
A two-column format showing the original and modified files side-by-side. Useful for seeing how lines have changed.
FILENAME_A

The name of the first file (defaults to "A").

FILENAME_B

The name of the second file (defaults to "B").

DATE_A

The modification date of the first file (defaults to the current time).

DATE_B

The modification date of the second file (defaults to the current time).

PREFIX_A

The prefix used for lines from the first file (defaults to "-" for Unified/Context, "<" for OldStyle, "A" for Table).

PREFIX_B

The prefix used for lines from the second file (defaults to "+" for Unified/Context, ">" for OldStyle, "B" for Table).

FILENAME_PREFIX_A

Prefix for the filename line for file A (defaults to "").

FILENAME_PREFIX_B

Prefix for the filename line for file B (defaults to "").

Example:

 my $diff = diff (\@list1, \@list2, {
     FORMAT => 'Unified',
     FILENAME_A => 'original.txt',
     FILENAME_B => 'modified.txt',
     DATE_A => '2001-01-01',
     DATE_B => '2001-01-02',
     PREFIX_A => '---',
     PREFIX_B => '+++',
 });

You can also override the default prefixes:

 my $diff = diff (\@list1, \@list2, {
     FORMAT => 'Unified',
     PREFIX_A => '---',
     PREFIX_B => '+++',
 });

LIMITATIONS

Must suck both input files entirely in to memory and store them with a normal amount of Perlish overhead (one array location) per record. This is implied by the implementation of Algorithm::Diff, which takes two arrays. If Algorithm::Diff ever offers an incremental mode, this can be changed (contact the maintainers of Algorithm::Diff and "Text::Diff" if you need this; it shouldn't be too terribly hard to tie arrays in this fashion).

Does not provide most of the more refined GNU "diff" options: recursive directory tree scanning, ignoring blank lines / whitespace, etc., etc. These can all be added as time permits and need arises, many are rather easy; patches quite welcome.

Uses closures internally, this may lead to leaks on Perl versions 5.6.1 and prior if used many times over a process' life time.
