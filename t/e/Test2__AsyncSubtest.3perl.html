Test2::AsyncSubtest(3perl) Guide du programmeur Perl Test2::AsyncSubtest(3perl)

NOM

Test2::AsyncSubtest - Objet représentant un sous-test asynchrone.

DESCRIPTION

Les sous-tests réguliers ont une portée limitée, ils démarrent, des événements sont générés, puis ils se ferment et envoient un événement Test2::Event::Subtest. C'est un problème si vous souhaitez que le sous-test continue à recevoir des événements pendant que d'autres événements sont également générés. Cette classe implémente des sous-tests qui restent ouverts jusqu'à ce que vous décidiez de les fermer.

Ceci est principalement utile pour les outils qui démarrent un sous-test dans un processus et créent ensuite des enfants. Dans de nombreux cas, il est préférable de laisser le processus parent continuer au lieu d'attendre les enfants.

SYNTAXE

use Test2::AsyncSubtest;
my $ast = Test2::AsyncSubtest->new(name => foo);
$ast->run(sub {
    ok(1, "Événement dans le parent" );
});
ok(1, "Événement en dehors du sous-test");
$ast->run_fork(sub {
    ok(1, "Événement dans le processus enfant");
});
...
$ast->finish;
done_testing;

CONSTRUCTION

my $ast = Test2::AsyncSubtest->new( ... );
name => $nom (requis)
Nom du sous-test. Cet argument de construction est requis.
send_to => $hub (optionnel)
Hub auquel l'événement de sous-test final doit être envoyé. Il doit s'agir d'une instance de Test2::Hub ou d'une sous-classe. Si aucun n'est spécifié, le hub supérieur actuel sera utilisé.
trace => $trace (optionnel)
Fichier/Ligne auxquels les erreurs doivent être attribuées. Il doit s'agir d'une instance de Test2::Util::Trace. Si aucun n'est spécifié, le fichier/ligne où le constructeur a été appelé sera utilisé.
hub => $hub (optionnel)
Utilisez ceci pour spécifier un hub que le sous-test doit utiliser. Par défaut, un nouveau hub est généré. Il doit s'agir d'une instance de Test2::AsyncSubtest::Hub.

MÉTHODES

ACCESSEURS SIMPLES

$bool = $ast->active
Vrai si le sous-test est actif. Le sous-test est actif si son hub apparaît dans la pile globale des hubs. C'est vrai lorsque "$ast->run(...)" est en cours d'exécution.
$arrayref = $ast->children
Obtient un tableau d'enfants de processus/threads. Les éléments numériques sont des PID, les éléments bénis sont des instances de threads.
$arrayref = $ast->events
Obtient un tableau d'événements qui ont été envoyés au hub des sous-tests.
$bool = $ast->finished
Vrai si finished() a déjà été appelé.
$hub = $ast->hub
Le hub créé pour le sous-test.
$int = $ast->id
Compteur d'attachement/détachement. Utilisé en interne, pas utile pour les utilisateurs.
$str = $ast->name
Nom du sous-test.
$pid = $ast->pid
PID dans lequel le sous-test a été créé.
$tid = $ast->tid
ID du thread dans lequel le sous-test a été créé.
$hub = $ast->send_to
Hub auquel l'événement de sous-test final doit être envoyé.
$arrayref = $ast->stack
Pile de sous-tests asynchrones au moment où celui-ci a été créé. Ceci est principalement pour un usage interne.
$trace = $ast->trace
Instance de Test2::Util::Trace utilisée pour le rapport d'erreurs.

INTERFACE

$ast->attach($id)
Attache un sous-test dans un enfant/processus à l'original.

Note : "my $id = $ast->cleave" doit avoir été appelé dans le processus/thread parent avant le démarrage de l'enfant, l'identifiant qu'il retourne doit être utilisé dans l'appel à "$ast->attach($id)"

$id = $ast->cleave
Prépare une fente pour qu'un processus/thread enfant s'attache. Ceci doit être appelé AVANT que le processus ou le thread enfant ne soit démarré. L'ID retourné est utilisé par attach().

Ceci ne doit être appelé que dans le processus/thread d'origine.

$ctx = $ast->context
Obtient une instance de Test2::API::Context qui peut être utilisée pour envoyer des événements au contexte dans lequel le hub a été créé. Ce n'est pas un contexte canonique, vous ne devez pas appeler "$ctx->release" dessus.
$ast->detach
Détache du parent dans un processus/thread enfant. Ceci doit être appelé juste avant que l'enfant ne quitte.
$ast->finish
$ast->finish(%options)
Termine le sous-test, attend les enfants et envoie l'événement de sous-test final.

Ceci ne doit être appelé que dans le processus/thread d'origine.

Note : Ceci appelle "$ast->wait".

Ce sont les options :

collapse => 1
Ceci permet intelligemment à un sous-test d'être vide.

Si aucun événement n'augmente le compteur de tests, aucun plan final ne sera ajouté au sous-test. Le sous-test ne sera pas considéré comme un échec (normalement, un sous-test vide est un échec).

S'il n'y a aucun événement du tout, le sous-test sera réduit à un événement Test2::Event::Ok.

silent => 1
Ceci empêchera finish de générer un événement final Test2::Event::Subtest. Ceci termine efficacement le sous-test sans affecter le sous-test parent (ou le test de niveau supérieur).
no_plan => 1
Ceci empêchera l'ajout d'un plan final au sous-test pour vous lorsqu'aucun n'est directement spécifié.
skip => "raison"
Ceci émettra un Test2::Event::Skip au lieu d'un sous-test. Ceci lèvera une exception si des événements ont été vus, ou si l'état implique que des événements se sont produits.
$out = $ast->fork
Ceci est une interface légèrement plus haut niveau pour fork. L'exécuter forcera votre code sur place, comme fork(). Il retournera un pid dans le parent, et une instance de Test2::Util::Guard dans l'enfant. Une exception sera levée si fork échoue.

Il est recommandé d'utiliser "$ast->run_fork(sub { ... })" à la place.

$bool = $ast->pending
Vrai s'il y a des processus enfants, des threads ou des sous-tests qui en dépendent.
$bool = $ast->ready
Ceci est essentiellement "!$ast->pending".
$ast->run(sub { ... })
Exécute le bloc de code fourni dans le sous-test. Ceci poussera le hub du sous-test sur la pile, exécutera le code, puis retirera le hub de la pile.
$pid = $ast->run_fork(sub { ... })
Identique à "$ast->run()", sauf que le bloc de code est exécuté dans un processus enfant.

Vous n'avez pas besoin d'appeler directement wait($pid), cela sera fait pour vous lorsque "$ast->wait", ou "$ast->finish" seront appelés.

my $thr = $ast->run_thread(sub { ... });
** DÉCONSEILLÉ ** Les threads posent des problèmes. Cette méthode reste pour quiconque la souhaite VRAIMENT, mais elle n'est plus prise en charge. Les tests pour cette fonctionnalité ne s'exécutent même pas sauf si les variables d'environnement AUTHOR_TESTING ou T2_DO_THREAD_TESTS sont activées.

Identique à "$ast->run()", sauf que le bloc de code est exécuté dans un thread enfant.

Vous n'avez pas besoin d'appeler directement "$thr->join", cela est fait pour vous lorsque "$ast->wait", ou "$ast->finish" sont appelés.

$passing = $ast->start
Pousse le hub du sous-test sur la pile. Retourne l'état de réussite/échec actuel du sous-test.
$ast->stop
Retire le hub du sous-test de la pile. Retourne l'état de réussite/échec actuel du sous-test.
$ast->wait
Attend tous les threads/processus qui ont été démarrés en utilisant "$ast->fork", "$ast->run_fork"
