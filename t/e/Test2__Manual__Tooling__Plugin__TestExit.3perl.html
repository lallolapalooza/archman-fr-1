NOM

Test2::Manual::Tooling::Plugin::TestExit - Comment ajouter en toute sécurité des comportements avant la sortie.

DESCRIPTION

Ceci décrit la manière correcte/sûre d'ajouter des comportements avant la sortie aux tests via un plugin personnalisé.

La manière naïve de tenter cela serait d'ajouter un bloc "END { ... }". Cela peut fonctionner, et ne pas causer de problèmes... D'un autre côté, il y a beaucoup de façons dont cela peut vous piéger. Décrire tous les problèmes potentiels d'un bloc END, et comment il pourrait entrer en conflit avec Test2 (qui a son propre bloc END) dépasse le cadre de ce document.

CODE COMPLET DANS LE DÉBUT

package Test2::Plugin::MyPlugin;
use Test2::API qw{test2_add_callback_exit};
sub import {
    my $class = shift;
    test2_add_callback_exit(sub {
        my ($ctx, $orig_code, $new_exit_code_ref) = @_;
        return if $orig_code == 42;
        $$new_exit_code_ref = 42;
    });
}
1;

LIGNE PAR LIGNE

use Test2::API qw{test2_add_callback_exit};
Cela importe le rappel "(test2_add_callback_exit)".
test2_add_callback_exit(sub { ... });
Cela ajoute notre rappel à être appelé avant la sortie.
my ($ctx, $orig_code, $new_exit_code_ref) = @_
Le rappel reçoit 3 arguments. Le premier est un objet de contexte que vous pouvez utiliser. Le second est le code de sortie original du bloc "END" utilisé par Test2. Le troisième argument est une référence scalaire que vous pouvez utiliser pour obtenir le code de sortie actuel, ou en définir un nouveau.
return if $orig_code == 42
C'est un raccourci pour ne rien faire si le code de sortie original était déjà 42.
$$new_exit_code_ref = 42
Cela change le code de sortie à 42.
