NOM

Template - Module frontal pour le Template Toolkit

SYNOPIS

use Template;
# quelques options utiles (voir ci-dessous pour la liste complète)
my $config = {
    INCLUDE_PATH => '/chemin/de/recherche',  # ou une référence de liste
    INTERPOLATE  => 1,               # développer "$var" dans le texte brut
    POST_CHOMP   => 1,               # nettoyer les espaces blancs
    PRE_PROCESS  => 'header',        # préfixer chaque modèle
    EVAL_PERL    => 1,               # évaluer les blocs de code Perl
};
# créer un objet Template
my $template = Template->new($config);
# définir les variables du modèle pour le remplacement
my $vars = {
    var1  => $value,
    var2  => \%hash,
    var3  => \@list,
    var4  => \&code,
    var5  => $object,
};
# spécifier le nom du fichier d'entrée, ou un descripteur de fichier, une référence de texte, etc.
my $input = 'myfile.html';
# traiter le modèle d'entrée, en substituant les variables
$template->process($input, $vars)
    || die $template->error();

DESCRIPTION

Cette documentation décrit le module Template qui est l'interface Perl directe du Template Toolkit. Elle couvre l'utilisation du module et donne un bref résumé des options de configuration et des directives de modèle. Veuillez consulter Template::Manual pour le manuel de référence complet qui traite plus en détail des fonctionnalités et de l'utilisation du Template Toolkit. Template::Tutorial est également disponible comme guide d'introduction à l'utilisation du Template Toolkit.

MÉTHODES

new(\%config)

La méthode constructeur new() (implémentée par la classe de base Template::Base) instancie un nouvel objet "Template". Une référence à un tableau associatif d'éléments de configuration peut être passée en paramètre.

my $tt = Template->new({
    INCLUDE_PATH => '/usr/local/templates',
    EVAL_PERL    => 1,
}) || die $Template::ERROR, "\n";

Une référence vers un nouvel objet "Template" est retournée, ou undef en cas d'erreur. Dans ce dernier cas, le message d'erreur peut être récupéré en appelant error() en tant que méthode de classe ou en examinant directement la variable de paquet $Template::ERROR.

my $tt = Template->new(\%config)
    || die Template->error(), "\n";
my $tt = Template->new(\%config)
    || die $Template::ERROR, "\n";

Pour plus de commodité, les éléments de configuration peuvent également être spécifiés sous forme de liste d'éléments plutôt que de référence à un tableau associatif. Ceux-ci sont automatiquement regroupés dans un tableau associatif par le constructeur.

my $tt = Template->new(INCLUDE_PATH => '/tmp', POST_CHOMP => 1)
    || die $Template::ERROR, "\n";

process($template, \%vars, $output, %options)

La méthode process() est appelée pour traiter un modèle. Le premier paramètre indique le modèle d'entrée comme l'un des éléments suivants :

  • un nom de fichier relatif à "INCLUDE_PATH", s'il est défini
  • une référence à une chaîne de texte contenant le texte du modèle
  • une référence de descripteur de fichier (par ex. "IO::Handle" ou sous-classe) ou "GLOB" (par ex. "\*STDIN"), à partir duquel le modèle peut être lu.

Une référence à un tableau associatif peut être passée comme deuxième paramètre, contenant les définitions des variables du modèle.

# nom de fichier
$tt->process('welcome.tt2')
    || die $tt->error(), "\n";
# référence de texte
$text = "[% INCLUDE header %]\nBonjour le monde !\n[% INCLUDE footer %]";
$tt->process(\$text)
    || die $tt->error(), "\n";
# descripteur de fichier (GLOB)
$tt->process(\*DATA)
    || die $tt->error(), "\n";
__END__
[% INCLUDE header %]
Ceci est un modèle défini dans la section __END__ qui est
accessible via le descripteur de fichier "DATA".
[% INCLUDE footer %]

Par défaut, la sortie du modèle traité est affichée sur "STDOUT". La méthode process() retourne ensuite 1 pour indiquer le succès. Un troisième paramètre peut être passé à la méthode process() pour spécifier un emplacement de sortie différent. Cette valeur peut être l'un des éléments suivants :

  • une chaîne de caractères simple indiquant un nom de fichier qui sera ouvert (relatif à "OUTPUT_PATH", s'il est défini) et la sortie y sera écrite
  • un GLOB de fichier ouvert prêt pour la sortie
  • une référence à un scalaire (par ex. une chaîne de caractères) auquel la sortie/erreur est ajoutée
  • une référence à une sous-routine qui est appelée, passant la sortie comme paramètre
  • toute référence d'objet qui implémente une méthode print() (par ex. "IO::Handle", "Apache::Request", etc.) qui sera appelée, passant la sortie générée comme paramètre.

Exemples :

# nom de fichier de sortie
$tt->process('welcome.tt2', $vars, 'welcome.html')
    || die $tt->error(), "\n";
# référence à une sous-routine de sortie
sub myout {
    my $output = shift;
    ...
}
$tt->process('welcome.tt2', $vars, \&myout)
    || die $tt->error(), "\n";
# référence à une chaîne de texte de sortie
my $output = '';
$tt->process('welcome.tt2', $vars, \$output)
    || die $tt->error(), "\n";
print "sortie : $output\n";

Dans un gestionnaire Apache/mod_perl :

sub handler {
    my $req = shift;
    # ...votre code ici...
    # diriger la sortie vers Apache::Request via $req->print($output)
    $tt->process($file, $vars, $req) || do {
        $req->log_reason($tt->error());
        return SERVER_ERROR;
    };
    return OK;
}

Après le troisième argument de sortie optionnel, peut venir une référence optionnelle à un tableau associatif ou une liste de paires "(nom, valeur)" fournissant des options supplémentaires pour la sortie. La seule option actuellement prise en charge est "binmode" qui, lorsqu'elle est définie sur une valeur vraie, garantira que les fichiers créés (mais pas les descripteurs de fichiers existants transmis) seront définis en mode binaire.

# soit : référence de tableau associatif d'options
$tt->process($infile, $vars, $outfile, { binmode => 1 })
    || die $tt->error(), "\n";
# soit : liste de paires nom, valeur
$tt->process($infile, $vars, $outfile, binmode => 1)
    || die $tt->error(), "\n";

Alternativement, l'argument "binmode" peut spécifier une couche IO particulière telle que ":utf8".

$tt->process($infile, $vars, $outfile, binmode => ':utf8')
    || die $tt->error(), "\n";

L'élément de configuration "OUTPUT" peut être utilisé pour spécifier un emplacement de sortie par défaut autre que "\*STDOUT". "OUTPUT_PATH" spécifie un répertoire qui doit être préfixé à tous les emplacements de sortie spécifiés sous forme de noms de fichiers.

my $tt = Template->new({
    OUTPUT      => sub { ... },       # par défaut
    OUTPUT_PATH => '/tmp',
...
}) || die Template->error(), "\n";
# utilise la sortie par défaut (la sous-routine est appelée)
$tt->process('welcome.tt2', $vars)
    || die $tt->error(), "\n";
# écrit le fichier dans '/tmp/welcome.html'
$tt->process('welcome.tt2', $vars, 'welcome.html')
    || die $tt->error(), "\n";

La méthode process() retourne 1 en cas de succès ou "undef" en cas d'erreur. Le message d'erreur généré dans ce dernier cas peut être récupéré en appelant la méthode error(). Voir aussi "RÉSUMÉ DE LA CONFIGURATION" qui décrit comment la gestion des erreurs peut être personnalisée davantage.

error()

Lorsqu'elle est appelée en tant que méthode de classe, elle retourne la valeur de la variable de paquet $ERROR. Ainsi, les lignes suivantes sont équivalentes.

my $tt = Template->new()
    || die Template->error(), "\n";
my $tt = Template->new()
    || die $Template::ERROR, "\n";

Lorsqu'elle est appelée en tant que méthode d'objet, elle retourne la valeur de la variable interne "_ERROR", telle que définie par une condition d'erreur lors d'un appel précédent à process().

$tt->process('welcome.tt2')
    || die $tt->error(), "\n";

Les méthodes type() et info() peuvent être appelées sur l'objet pour récupérer respectivement le type d'erreur et la chaîne d'informations. $tt->process('somefile') || do {
    my $error = $tt->error();
    print "type d'erreur : ", $error->type(), "\n";
    print "informations sur l'erreur : ", $error->info(), "\n";
    print $error, "\n";
};

service()

Le module "Template" délègue la majeure partie du travail de traitement des modèles à un objet sous-jacent Template::Service. Cette méthode retourne une référence à cet objet.

context()

Le module Template::Service utilise un objet central Template::Context pour le traitement des modèles au moment de l'exécution. Cette méthode retourne une référence à cet objet et est équivalente à "$template->service->context()".

template($name)

Cette méthode est un simple wrapper autour de la méthode Template::Context du même nom. Elle retourne un modèle compilé pour la source fournie comme argument.

RÉSUMÉ DE LA CONFIGURATION

La liste suivante donne un bref résumé de chaque option de configuration de Template Toolkit. Voir Template::Manual::Config pour les détails complets.

Options de style et d'analyse des modèles

ENCODING

Spécifie l'encodage des caractères.

START_TAG, END_TAG

Définissent les jetons qui indiquent le début et la fin des directives (par défaut : '"[%"' et '"%]"').

TAG_STYLE

Définit "START_TAG" et "END_TAG" selon un style prédéfini (par défaut : '"template"', comme ci-dessus).

PRE_CHOMP, POST_CHOMP

Supprime les espaces blancs avant/après les directives (par défaut : 0/0).

TRIM

Supprime les espaces blancs en début et fin de la sortie du modèle (par défaut : 0).

INTERPOLATE

Interpole les variables intégrées comme $this ou "${this}" (par défaut : 0).

ANYCASE

Autorise les mots-clés de directive en minuscules (par défaut : 0 - MAJUSCULES uniquement).

Fichiers et blocs de modèles

INCLUDE_PATH

Un ou plusieurs répertoires pour rechercher les modèles.

DELIMITER

Délimiteur pour séparer les chemins dans "INCLUDE_PATH" (par défaut : '":"').

ABSOLUTE

Autorise les noms de fichiers absolus, par exemple "/foo/bar.html" (par défaut : 0).

RELATIVE

Autorise les noms de fichiers relatifs, par exemple "../foo/bar.html" (par défaut : 0).

DEFAULT

Modèle par défaut à utiliser lorsqu'un autre n'est pas trouvé.

BLOCKS

Tableau associatif pré-définissant les blocs de modèles.

AUTO_RESET

Activé par défaut, provoquant la réinitialisation des définitions "BLOCK" à chaque traitement d'un modèle. Désactivé pour permettre aux définitions "BLOCK" de persister.

RECURSION

Indicateur pour autoriser la récursion dans les modèles (par défaut : 0).

Variables de modèle

VARIABLES

Tableau associatif des variables et de leurs valeurs à pré-définir dans le stash.

Options de traitement au moment de l'exécution

EVAL_PERL

Indicateur pour spécifier si les blocs "PERL"/"RAWPERL" doivent être traités (par défaut : 0).

PRE_PROCESS, POST_PROCESS

Nom du ou des modèles à traiter avant/après le modèle principal.

PROCESS

Nom du ou des modèles à traiter à la place du modèle principal.

ERROR

Nom du modèle d'erreur ou référence à un tableau associatif mappant les types d'erreurs aux modèles.

OUTPUT

Emplacement ou gestionnaire de sortie par défaut.

OUTPUT_PATH

Répertoire dans lequel les fichiers de sortie peuvent être écrits.

DEBUG

Active les messages de débogage.

Options de mise en cache et de compilation

CACHE_SIZE

Nombre maximum de modèles compilés à mettre en cache en mémoire (par défaut : undef - tout mettre en cache)

COMPILE_EXT

Extension de nom de fichier pour les fichiers de modèles compilés (par défaut : undef - ne pas compiler).

COMPILE_DIR

Racine du répertoire dans lequel les fichiers de modèles compilés doivent être écrits (par défaut : undef - ne pas compiler).

Plugins et filtres

PLUGINS

Référence à un tableau associatif mappant les noms de plugins aux packages Perl.

PLUGIN_BASE

Une ou plusieurs classes de base sous lesquelles les plugins peuvent être trouvés.

LOAD_PERL

Indicateur pour spécifier si les modules Perl réguliers doivent être chargés si un plugin nommé ne peut pas être trouvé (par défaut : 0).

FILTERS

Tableau associatif mappant les noms de filtres aux sous-routines ou factories de filtres.

Personnalisation et extension

LOAD_TEMPLATES

Liste des fournisseurs de modèles.

LOAD_PLUGINS

Liste des fournisseurs de plugins.

LOAD_FILTERS

Liste des fournisseurs de filtres.

TOLERANT

Définit les fournisseurs pour tolérer les erreurs comme des déclinatoires (par défaut : 0).

SERVICE

Référence à un objet de service personnalisé (par défaut : Template::Service).

CONTEXT

Référence à un objet de contexte personnalisé (par défaut : Template::Context).

STASH

Référence à un objet stash personnalisé (par défaut : Template::Stash).

PARSER

Référence à un objet parseur personnalisé (par défaut : Template::Parser).

GRAMMAR

Référence à un objet grammaire personnalisé (par défaut : Template::Grammar).

RÉSUMÉ DES DIRECTIVES

La liste suivante donne un bref résumé de chaque directive de Template Toolkit. Voir Template::Manual::Directives pour les détails complets.

GET

Évalue et affiche une variable ou une valeur.

[%   GET variable %]    # Le mot-clé 'GET' est facultatif
[%       variable %]
[%       hash.key %]
[%         list.n %]
[%     code(args) %]
[% obj.meth(args) %]
[%  "valeur : $var" %]

CALL

Comme GET mais sans afficher le résultat (par exemple, appel de code)

[%  CALL variable %]

SET

Assigne des valeurs à des variables.

[% SET variable = valeur %]    # 'SET' est aussi facultatif
[%     variable = autre_variable
       variable = 'texte littéral @ 100 $'
       variable = "texte interpolé : $var"
       list     = [ val, val, val, val, ... ]
       list     = [ val..val ]
       hash     = { var => val, var => val, ... }
%]

DEFAULT

Comme SET, mais les variables ne sont définies que si elles ne sont pas déjà définies (c'est-à-dire qu'elles n'ont pas de valeur vraie).

[% DEFAULT variable = valeur %]

INSERT

Insère un fichier sans aucun traitement effectué sur le contenu.

[% INSERT legalese.txt %]

PROCESS

Traite un autre fichier modèle ou bloc et insère la sortie générée. Tous les blocs ou variables de modèle définis ou mis à jour dans le modèle "PROCESS"é seront ensuite définis dans le modèle appelant.

[% PROCESS template %]
[% PROCESS template  var = val, ... %]

INCLUDE

Similaire à "PROCESS", mais utilise une copie locale des variables courantes. Tous les blocs ou variables de modèle définis dans le modèle "INCLUDE"d restent locaux à celui-ci.

[% INCLUDE template %]
[% INCLUDE template  var = val, ... %]

WRAPPER

Le contenu entre les directives "WRAPPER" et "END" correspondantes est d'abord évalué, la sortie générée étant stockée dans la variable "content". Le modèle nommé est ensuite traité comme pour "INCLUDE".

[% WRAPPER layout %]
   Marqueurs de modèle ici [% blah %]...
[% END %]

Un simple modèle de type *layout* pourrait ressembler à ceci :

Votre en-tête ici...
[% content %]
Votre pied de page ici...
