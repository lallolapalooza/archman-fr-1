Test2::Tools::Compare(3perl) Guide de référence pour programmeurs Perl Test2::Tools::Compare(3perl)

NOM

Test2::Tools::Compare - Outils pour comparer des structures de données profondes.

DESCRIPTION

Test::More avait is_deeply(). Cette bibliothèque est la version Test2 qui peut être utilisée pour comparer des structures de données, mais va plus loin en fournissant des outils pour construire une spécification de structure de données contre laquelle vous pouvez vérifier vos données. Il existe des versions 'strictes' et 'relâchées' des outils.

SYNOPSIS

use Test2::Tools::Compare;
# Hash à des fins de démonstration
my $some_hash = {a => 1, b => 2, c => 3};
# Vérification stricte, tout doit correspondre
is(
    $some_hash,
    {a => 1, b => 2, c => 3},
    "Le hash que nous avons correspond à nos attentes"
);
# Vérification relâchée, seuls les champs qui nous intéressent sont vérifiés, et nous pouvons utiliser
# une regex pour approximer un champ.
like(
    $some_hash,
    {a => 1, b => qr/\A[0-9]+\z/},
    "'a' est 1, 'b' est un entier, nous nous soucions de 'c'."
);

AVANCÉ

Des constructeurs déclaratifs de hash, tableaux et objets sont disponibles et vous permettent de générer des spécifications. Ils sont plus verbeux que de simplement fournir un hash, mais ont l'avantage que chaque composant que vous spécifiez a un numéro de ligne associé. C'est utile pour le débogage car la sortie d'échec vous indiquera non seulement quel champ était incorrect, mais aussi la ligne sur laquelle vous avez déclaré le champ.

use Test2::Tools::Compare qw{
    is like isnt unlike
    match mismatch validator
    hash array bag object meta number float rounded within string subset bool
    in_set not_in_set check_set
    item field call call_list call_hash prop check all_items all_keys all_vals all_values
    etc end filter_items
    T F D DF E DNE FDNE U L
    event fail_events
    exact_ref
};
is(
    $some_hash,
    hash {
        field a => 1;
        field b => 2;
        field c => 3;
    },
    "Le hash correspond à la spécification"
);

OUTILS DE COMPARAISON

$bool = is($got, $expect)
$bool = is($got, $expect, $name)
$bool = is($got, $expect, $name, @diag)
$got est la structure de données que vous voulez vérifier. $expect est ce à quoi vous voulez que $got ressemble. $name est un nom optionnel pour le test. @diag sont des messages de diagnostic optionnels qui seront imprimés sur STDERR en cas d'échec, ils ne seront pas affichés lorsque la comparaison réussit. Le résultat booléen vrai/faux de la comparaison est retourné.

C'est le vérificateur strict. Le vérificateur strict exige une correspondance parfaite entre $got et $expect. Tous les champs de hash doivent être spécifiés, tous les éléments de tableau doivent être présents, etc. Tous les références non scalaires/hash/tableau/regex doivent être identiques (même adresse mémoire). Les références scalaires, de hash et de tableau seront parcourues et comparées. Les références regex seront comparées pour voir si elles ont le même motif.

is(
    $some_hash,
    {a => 1, b => 2, c => 3},
    "Le hash que nous avons correspond à nos attentes"
);

La seule exception à la stricte est lorsqu'elle reçoit un objet $expect qui a été construit à partir d'une spécification, auquel cas la spécification détermine la stricte. La stricte ne s'applique qu'aux valeurs/références littérales qui sont fournies et converties en spécification pour vous.

is(
    $some_hash,
    hash {    # Note: la fonction hash n'est pas exportée par défaut
        field a => 1;
        field b => match(qr/\A[0-9]+\z/);    # Note: La fonction match n'est pas exportée par défaut
        # On ne se soucie pas des autres champs.
    },
    "La comparaison de hash n'est pas stricte"
);

Cela fonctionne pour les structures profondes et peu profondes. Par exemple, vous pouvez l'utiliser pour comparer deux chaînes de caractères :

is('foo', 'foo', "les chaînes correspondent");

Note: Ce n'est pas l'outil à utiliser si vous voulez vérifier si deux références sont exactement la même référence, utilisez ref_is() du plugin Test2::Tools::Ref à la place. Le plus souvent, cela fonctionnera aussi bien, cependant il y a des problèmes si votre référence contient un cycle et se réfère à elle-même à un moment donné. Si cela se produit, une exception sera levée pour rompre une récursion autrement infinie.

Note: Les valeurs non-références seront comparées comme des chaînes en utilisant "eq", ce qui signifie que les chaînes '2.0' et '2' ne correspondront pas, mais que les nombres 2.0 et 2 le feront, car ils sont tous deux stringifiés en '2'.

$bool = isnt($got, $expect)
$bool = isnt($got, $expect, $name)
$bool = isnt($got, $expect, $name, @diag)
L'opposé de is(). Effectue toutes les mêmes vérifications, mais réussit lorsqu'il y a une non-correspondance.
$bool = like($got, $expect)
$bool = like($got, $expect, $name)
$bool = like($got, $expect, $name, @diag)
$got est la structure de données que vous voulez vérifier. $expect est ce à quoi vous voulez que $got ressemble. $name est un nom optionnel pour le test. @diag sont des messages de diagnostic optionnels qui seront imprimés sur STDERR en cas d'échec, ils ne seront pas affichés lorsque la comparaison réussit. Le résultat booléen vrai/faux de la comparaison est retourné.

C'est le vérificateur relâché. Celui-ci ignorera les clés de hash ou les index de tableau que vous ne spécifiez pas réellement dans votre structure $expect. De plus, les références regex et les sous-routines seront utilisées comme validateurs. Si vous fournissez une regex en utilisant "qr/.../", la regex elle-même sera utilisée pour valider la valeur correspondante dans la structure $got. Il en va de même pour les coderefs, la valeur est passée comme premier argument (et dans $_) et la sous-routine doit retourner une valeur booléenne. Dans cet outil, les regex stringifieront ce qu'elles vérifient.

like(
    $some_hash,
    {a => 1, b => qr/\A[0-9]+\z/},
    "'a' est 1, 'b' est un entier, nous ne nous soucions pas des autres champs"
);

Cela fonctionne pour les structures profondes et peu profondes. Par exemple, vous pouvez l'utiliser pour comparer deux chaînes de caractères :

like('foo bar', qr/^foo/, "la chaîne correspond au motif");
$bool = unlike($got, $expect)
$bool = unlike($got, $expect, $name)
$bool = unlike($got, $expect, $name, @diag)
L'opposé de like(). Effectue toutes les mêmes vérifications, mais réussit lorsqu'il y a une non-correspondance.

Les fonctions is(), isnt(), like() et unlike() peuvent être amenées à dumper $got en utilisant Data::Dumper lorsque les tests échouent en réglant la variable d'environnement "T2_AUTO_DUMP" sur "1". (Alternativement, "T2_AUTO_DUMP" peut être réglé sur le nom d'un module Perl fournissant une méthode Dump() compatible.) La variable d'environnement "T2_AUTO_DEPARSE" peut être utilisée pour activer le déparsing des coderefs par Data::Dumper.

VÉRIFICATIONS RAPIDES

Note : Aucune de celles-ci n'est exportée par défaut. Vous devez les demander.

Les vérifications rapides sont un moyen de générer rapidement une spécification de valeur courante. Celles-ci peuvent être utilisées dans les structures passées à "is" et "like" via l'argument $expect.

Exemple :

is($foo, T(), '$foo a une valeur vraie');
$check = T()
Ceci vérifie que la valeur dans la structure $got correspondante est vraie, n'importe quelle valeur vraie fera l'affaire. 
is($foo, T(), '$foo a une valeur vraie');
is(
    { a => 'xxx' },
    { a => T() },
    "La clé 'a' est vraie"
);
$check = F()
Ceci vérifie que la valeur dans la structure $got correspondante est fausse, n'importe quelle valeur fausse fera l'affaire, mais la valeur doit exister. 
is($foo, F(), '$foo a une valeur fausse');

    { a => 0

BUILDERS ÉVÉNEMENTIELS

Remarque : Aucun de ces éléments n'est exporté par défaut. Vous devez les demander.

Vérifie que nous avons reçu un événement d'un type spécifié :

my $check = event 'Ok';

Vérifie les détails de l'événement :

my $check = event Ok => sub {
    # Vérifie une défaillance
    call pass => 0;
    # Succès effectif après prise en compte de TODO/SKIP.
    call effective_pass => 1;
    # Vérifie les diagnostics
    call diag => [ match qr/Échec du test foo/ ];
    # Vérifie le fichier auquel l'événement rapporte
    prop file => 'foo.t';
    # Vérifie le numéro de ligne auquel l'événement rapporte
    prop line => '42';
    # Vous pouvez également vérifier les valeurs todo/skip :
    prop skip => 'broken';
    prop todo => 'fixme';
    # ID de thread et ID de processus où l'événement a été généré
    prop tid => 123;
    prop pid => 123;
};

Vous pouvez également fournir un nom de package d'événement entièrement qualifié avec le préfixe '+' :

my $check = event '+My::Event' => sub { ... }

Vous pouvez également fournir une référence de hachage au lieu d'une sous-routine pour vérifier directement les valeurs de hachage de l'événement :

my $check = event Ok => { pass => 1, ... };

UTILISATION DANS D'AUTRES BUILDERS

Vous pouvez les utiliser tous dans d'autres builders, il suffit de les utiliser dans un contexte vide pour que leurs valeurs soient ajoutées à la construction.

my $check = array {
    event Ok => { ... };
    event Note => { ... };
    fail_events Ok => { pass => 0 };
    # Récupère un Diag gratuitement.
};

SPÉCIFICITÉS

$check = event $TYPE;
$check = event $TYPE => sub { ... };
$check = event $TYPE => { ... };
Cela fonctionne comme un builder d'objet. En plus de prendre en charge tout ce que la vérification d'objet prend en charge, vous devez également spécifier le type d'événement, et de nombreuses méta-propriétés supplémentaires sont disponibles.

Les propriétés supplémentaires sont :

'file'
Nom du fichier auquel l'événement fait rapport (pour utilisation dans les diagnostics).
'line'
Numéro de ligne auquel l'événement fait rapport (pour utilisation dans les diagnostics).
'package'
Package auquel l'événement fait rapport (pour utilisation dans les diagnostics).
'subname'
Sous-routine appelée pour générer l'événement (exemple : ok()).
'skip'
Défini sur la valeur de saut si le résultat a été généré en sautant des tests.
'todo'
Défini sur la valeur todo si TODO était défini lors de la génération de l'événement.
'trace'
La chaîne "à tel fichier foo.t ligne 42" qui sera utilisée dans les diagnostics.
'tid'
ID de thread dans lequel l'événement a été généré.
'pid'
ID de processus dans lequel l'événement a été généré.

REMARQUE : Les vérifications d'événements ont un etc() implicite ajouté. Cela signifie que vous devez utiliser end() si vous souhaitez échouer en cas de clés de hachage ou d'index de tableau inattendus. Cet etc() implicite s'étend à toutes les formes, y compris le builder, la référence de hachage et l'absence d'arguments.

@checks = fail_events $TYPE;
@checks = fail_events $TYPE => sub { ... };
@checks = fail_events $TYPE => { ... };
Identique à event() documenté ci-dessus. La différence est que cela produit deux événements, celui que vous spécifiez et un "Diag" après. Il n'y a pas de vérifications supplémentaires dans le Diag.

Utilisez ceci pour valider une simple défaillance pour laquelle vous ne voulez pas être dérangé par les diagnostics par défaut. Il ajoute une seule vérification Diag, donc si votre défaillance a des diagnostics personnalisés, vous devrez ajouter des vérifications pour ceux-ci.
