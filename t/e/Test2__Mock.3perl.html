Test2::Mock(3perl) Guide du programmeur Perl Test2::Mock(3perl)

NOM

Test2::Mock - Module pour gérer les classes et instances simulées.

DESCRIPTION

Ce module vous permet d'ajouter et de remplacer temporairement des méthodes pour n'importe quel paquet. Lorsque l'instance est détruite, le paquet sera restauré à son état d'origine.

SYNOPSIS

use Test2::Mock;
use MyClass;
my $mock = Test2::Mock->new(
    track => $BOOL, # activer le suivi des appels si désiré
    class => 'MyClass',
    override => [
        name => sub { 'fred' },
        ...
    ],
    add => [
        is_mocked => sub { 1 }
        ...
    ],
    ...
);
# Annuler la simulation de la sous-routine 'name'
$mock->restore('name');
...
$mock = undef; # Supprimera toutes les simulations

CONSTRUCTION

MÉTHODES

$mock = Test2::Mock->new(class => $CLASS, ...)
Ceci créera une nouvelle instance de Test2::Mock qui gérera les simulations pour le $CLASS spécifié.

N'importe quelle méthode de "Test2::Mock" peut être utilisée comme argument du constructeur, chacun doit être suivi d'un tableau d'arguments à utiliser dans la méthode. Par exemple, la méthode add() :

my $mock = Test2::Mock->new(
    class => 'AClass',
    add => [foo => sub { 'foo' }],
);

est identique à ceci :

my $mock = Test2::Mock->new(
    class => 'AClass',
);
$mock->add(foo => sub { 'foo' });
$mock->track($bool)
Active ou désactive le suivi. Toute sous-routine ajoutée/remplacée/définie lorsque le suivi est activé enregistrera chaque appel dans une hash récupérable via "$mock->tracking". Changer le commutateur de suivi n'affectera pas les sous-routines déjà modifiées, mais affectera toute modification supplémentaire.
$hashref = $mock->sub_tracking
Les données de suivi ressemblent à ceci : 
{
    nom_sous_routine => [
        {nom_sous_routine => $nom_sous_routine, ref_sous_routine => $ref_sous_routine_simulee, arguments => [... copie de @_ de l'appel ... ]},
        ...,
        ...,
    ],
}

Contrairement à call_tracking, ceci liste tous les appels par sous-routine, vous pouvez donc choisir de ne regarder que les appels spécifiques à une sous-routine.

Veuillez noter : Les éléments hash avec le nom de sous-routine et les arguments sont partagés avec call_tracking, modifier l'un modifie l'autre, donc copiez d'abord !

$arrayref = $mock->call_tracking
Les données de suivi ressemblent à ceci : 
[
    {nom_sous_routine => $nom_sous_routine, ref_sous_routine => $ref_sous_routine_simulee, arguments => [... copie de @_ de l'appel ... ]},
    ...,
    ...,
]

Contrairement à sub_tracking, ceci liste tous les appels à n'importe quelle sous-routine simulée, dans l'ordre où ils ont été appelés. Pour filtrer par sous-routine, utilisez sub_tracking.

Veuillez noter : Les éléments hash avec le nom de sous-routine et les arguments sont partagés avec sub_tracking, modifier l'un modifie l'autre, donc copiez d'abord !

$mock->clear_sub_tracking()
$mock->clear_sub_tracking(\@noms_sous_routines)
Efface les données de suivi. Sans arguments, TOUTES les données de suivi sont effacées. Lorsque des arguments sont fournis, seuls ces clés spécifiques seront effacées.
$mock->clear_call_tracking()
Efface tous les éléments de call_tracking.
$mock->add('symbole' => ..., 'symbole2' => ...)
$mock->override('symbole1' => ..., 'symbole2' => ...)
$mock->set('symbole1' => ..., 'symbole2' => ...)
add() et override() sont les principaux moyens d'ajouter/modifier des méthodes pour une classe. Les deux acceptent exactement le même type d'arguments. La différence est que "override" échouera à moins que le symbole que vous remplacez n'existe déjà, tandis que "add" échouera si le symbole existe déjà.

set() a été ajouté plus récemment pour les cas où vous ne savez peut-être pas si la sous-routine existe déjà. Ces cas sont rares et set devrait être évité (pensez-y comme à 'no strict'). Cependant, il existe des cas d'utilisation valides, il a donc été ajouté.

Note : Considérez override comme une opération push. Si vous appelez override sur le même symbole plusieurs fois, il le suivra. Vous pouvez utiliser restore() comme une opération pop pour revenir à la simulation précédente. "reset" peut être utilisé pour supprimer toute la simulation d'un symbole.

Les arguments doivent être un nom de symbole, avec un sigil optionnel, suivi d'une nouvelle spécification du symbole. Si aucun sigil n'est spécifié, '&' (sub) est supposé. Un exemple simple de remplacement d'une sous-routine :

$mock->override(foo => sub { 'foo remplacé' });
my $val = $class->foo; # Exécute notre remplacement
# $val est maintenant défini à 'foo remplacé'

Vous pouvez également simplement fournir une valeur et elle sera encapsulée dans une sous-routine pour vous :

$mock->override( foo => 'foo' );

L'exemple ci-dessus générera une sous-routine qui renvoie toujours la chaîne 'foo'.

Il existe trois valeurs *spéciales* qui peuvent être utilisées pour générer des accesseurs :

$mock->add(
    name => 'rw',   # Génère un accesseur en lecture/écriture
    age  => 'ro',   # Génère un accesseur en lecture seule
    size => 'wo',   # Génère un accesseur en écriture seule
);

Si vous voulez qu'une sous-routine retourne réellement l'une des trois chaînes spéciales, ou qu'elle retourne un coderef, vous pouvez utiliser un hashref comme spécification :

my $ref = sub { 'ma sub' };
$mock->add(
    rw_string => { val => 'rw' },
    ro_string => { val => 'ro' },
    wo_string => { val => 'wo' },
    coderef   => { val => $ref }, # la méthode coderef retourne $ref à chaque fois
);

Vous pouvez également remplacer/ajouter d'autres types de symboles, tels que des hash :

package Foo;
...
$mock->add('%foo' => {a => 1});
print $Foo::foo{a}; # affiche '1'

Vous pouvez également indiquer à mock de déduire le type de symbole pour l'ajout/le remplacement à partir de la référence, les règles sont similaires aux affectations glob :

$mock->add(
    -foo => sub { 'foo' },     # Ajoute la sous-routine &foo au paquet
    -foo => { foo => 1 },      # Ajoute le hash %foo au paquet
    -foo => [ 'f', 'o', 'o' ], # Ajoute le tableau @foo au paquet
    -foo => \"foo",            # Ajoute le scalaire $foo au paquet
);
$mock->restore($SYMBOLE)
Restaure le symbole à ce qu'il était avant le dernier remplacement. Si le symbole a été récemment ajouté, il sera supprimé. Si le symbole a été remplacé plusieurs fois, il sera SEULEMENT restauré à l'état précédent. Considérez "override" comme une opération push, et "restore" comme l'opération pop.
$mock->reset($SYMBOLE)
Supprime toute simulation du symbole et restaure le symbole original. Si le symbole avait été ajouté, il sera complètement supprimé.
$mock->orig($SYMBOLE)
Ceci renverra le symbole original, avant toute simulation. Pour les symboles qui ont été ajoutés, ceci renverra undef.
$mock->current($SYMBOLE)
Ceci renverra le symbole actuel.
$mock->reset_all
Supprime tous les symboles ajoutés et restaure tous les symboles remplacés à leurs originaux.
$mock->add_constructor($NOM => $TYPE)
$mock->override_constructor($NOM => $TYPE)
Ceci peut être utilisé pour injecter des constructeurs. Le premier argument doit être le nom du constructeur. Le second argument spécifie le type de constructeur.

Le type "hash" est le plus courant, tous les arguments sont utilisés pour créer un nouveau hash qui est béni.

hash => sub  {
    my ($class, %params) = @_;
    return bless \%params, $class;
};

Le type "array" est similaire au type hash, mais accepte une liste au lieu de paires clé/valeur :

array => sub {
    my ($class, @params) = @_;
    return bless \@params, $class;
};

Le type "ref" prend une référence et la bénit. Ceci modifiera votre argument d'entrée original.

ref => sub {
    my ($class, $params) = @_;
    return bless $params, $class;
};

NOM

Test2::Mock

DESCRIPTION

Test2::Mock est un module qui permet de mocker les méthodes d'objets en Perl. Ce module fournit des fonctionnalités pour créer des objets mockés, permettre la substitution des méthodes originales, et gérer le comportement de ces objets dans divers contextes.

SYNOPSIS

La syntaxe de base pour utiliser Test2::Mock est :


my $mock = Test2::Mock->new;
$mock->before('method_name', sub { ... });
$mock->after('method_name', sub { ... });
$mock->around('method_name', sub { ... });
$mock->autoload;
$mock->block_load;
$mock->file;
$mock->purge_on_destroy;
$mock->stash;
$mock->class;
$mock->parent;
$mock->child;

CONSTRUCTION

Pour construire un objet mocké, utilisez la méthode new :


my $mock = Test2::Mock->new;

Cet objet peut être configuré avec des méthodes telles que before, after, around, autoload, block_load, file, purge_on_destroy, stash, class, parent, et child.

MÉTHODES

Les méthodes disponibles sont :

  • name - Retourne le nom de l'objet mocké.
  • description - Retourne une description de l'objet mocké.
  • synopsis - Retourne la syntaxe de base pour utiliser le module.
  • construction - Retourne la construction de l'objet mocké.
  • methods - Retourne les méthodes disponibles.
  • source - Retourne la source du module.
  • maintainers - Retourne les mainteneurs du module.
  • authors - Retourne les auteurs du module.
  • copyright - Retourne la licence du module.
