NOM

Test2::V0 - Bundle recommandé de la 0ème édition de Test2.

DESCRIPTION

Ceci est le bundle principal. Il inclut presque tous les outils, et plusieurs plugins, que l'auteur de Test2 utilise. Ce bundle est largement utilisé pour tester Test2::Suite lui-même.

NOMMAGE, UTILISATION, DÉPENDANCES

Ce bundle ne devrait pas changer de manière gravement incompatible. Certains changements mineurs cassants, en particulier des corrections de bugs, peuvent être autorisés. Si des changements cassants sont nécessaires, un nouveau module "Test2::V#" devrait plutôt être publié.

Au fur et à mesure que de nouveaux modules "V#" sont publiés, les anciens modules peuvent être déplacés vers différentes distributions CPAN. Vous devriez toujours utiliser une version spécifique du bundle et lister cette version dans les exigences de test de vos distributions. Vous ne devriez jamais simplement lister Test2::Suite comme dépendance de vos modules, mais lister le bundle spécifique, ou les outils et plugins que vous utilisez directement, dans vos métadonnées.

EXEMPLE D'UTILISATION

use Test2::V0;
ok(1, "réussite");
...
done_testing;

RÉSOLUTION DES CONFLITS AVEC MOOSE

use Test2::V0 '!meta';

Moose et Test2::V0 exportent tous deux des sous-routines meta() très différentes. L'ajout de '!meta' aux arguments d'importation empêchera l'importation de la sous-routine. Ce bundle exporte également la sous-routine sous le nom meta_check(), vous pouvez donc utiliser cette orthographe comme alternative.

TAGS

:DEFAULT
Les lignes suivantes sont identiques : 
use Test2::V0;
use Test2::V0 ':DEFAULT';

RENOMMAGE À L'IMPORTATION

use Test2::V0 ':DEFAULT', '!ok', ok => {-as => 'my_ok'};

Ce bundle utilise Test2::Util::Importer pour l'exportation, par conséquent, vous pouvez utiliser tous les arguments qu'il accepte.

Explication :

'!ok'
N'exporte pas ok()
ok => {-as => 'my_ok'}
En fait, importe ok() mais sous le nom my_ok().

Si vous n'aviez pas ajouté l'argument '!ok', vous auriez à la fois ok() et my_ok()

PRAGMAS

Tous ceux-ci peuvent être désactivés via des arguments d'importation individuels, ou via l'argument "-no_pragmas".

use Test2::V0 -no_pragmas => 1;

STRICT

strict est activé pour vous. Vous pouvez le désactiver avec les arguments d'importation "-no_strict" ou "-no_pragmas" :

use Test2::V0 -no_strict => 1;

WARNINGS

warnings est activé pour vous. Vous pouvez le désactiver avec les arguments d'importation "-no_warnings" ou "-no_pragmas" :

use Test2::V0 -no_warnings => 1;

UTF8

Ceci est en fait fait via le plugin Test2::Plugin::UTF8, voir la section "PLUGINS" pour les détails.

Note : "-no_pragmas => 1" désactivera le plugin entier.

PLUGINS

SRAND

Voir Test2::Plugin::SRand.

Ceci définit la graine aléatoire sur la date du jour. Vous pouvez fournir une graine alternative avec l'option d'importation "-srand" :

use Test2::V0 -srand => 1234;

Vous pouvez également désactiver ce comportement :

use Test2::V0 -no_srand => 1;

Note Lorsque srand est activé (par défaut), il peut causer des problèmes avec des modules comme File::Temp qui finiront par tenter les mêmes noms de fichiers "aléatoires" pour chaque processus de test démarré un jour donné (ou partageant la même graine).

UTF8

Voir Test2::Plugin::UTF8.

Ceci définit le fichier, et tous les flux de sortie (y compris les flux de formateur), en utf8. Ceci activera le pragma utf8 pour la portée actuelle.

Ceci peut être désactivé en utilisant les arguments d'importation "-no_utf8 => 1" ou "-no_pragmas => 1".

use Test2::V0 -no_utf8 => 1;

EXIT SUMMARY

Voir Test2::Plugin::ExitSummary.

Ce plugin n'a aucune configuration.

VARIABLES D'ENVIRONNEMENT

Voir Test2::Env pour une liste des variables d'environnement significatives.

FONCTIONS API

Voir Test2::API pour celles-ci

$ctx = context()
$events = intercept { ... }

OUTILS

TARGET

Voir Test2::Tools::Target.

Vous pouvez spécifier une classe cible avec l'argument d'importation "-target". Si vous ne fournissez pas de cible, alors $CLASS et CLASS() ne seront pas importés.

use Test2::V0 -target => 'My::Class';
print $CLASS;  # My::Class
print CLASS(); # My::Class

Ou vous pouvez spécifier des noms :

use Test2::V0 -target => { pkg => 'Some::Package' };
pkg()->xxx; # Appeler 'xxx' sur Some::Package
$pkg->xxx;  # Identique
$CLASS
Variable de package contenant le nom de la classe cible.
$class = CLASS()
Fonction constante qui retourne le nom de la classe cible.

DEFER

Voir Test2::Tools::Defer.

def $func => @args;
do_def()

BASIC

Voir Test2::Tools::Basic.

ok($bool, $name)
ok($bool, $name, @diag)
pass($name)
pass($name, @diag)
fail($name)
fail($name, @diag)
diag($message)
note($message)
$todo = todo($reason)
todo $reason => sub { ... }
skip($reason, $count)
plan($count)
skip_all($reason)
done_testing()

NAME

Test2::V0 - A complete test suite.

DESCRIPTION

This module is a meta-module that exports all the tools that are part of the Test2 suite. This includes the basic testing tools, as well as comparison, subtests, class testing, and more.

This module is useful for any test file that wants to use the full breadth of Test2's capabilities without having to import each module individually.

NAMING, USING, DEPENDING

The name of this module is Test2::V0.

When using this module, you should use:

    use Test2::V0;

Or, if you want to import specific tools:

    use Test2::V0 qw( ... );

If you need to depend on this module, you should add Test2::V0 to your build_requires or test_requires in your Build.PL or Makefile.PL.

SYNOPSIS

    use Test2::V0;
    use Test::More; # Same as use Test2::V0;

    ok(1, 'this is ok');
    is($got, $want, 'this is fine');
    cmp_ok($got, '==', $want, 'this is good');

    subtest 'my subtest' => sub {
        ok(1, 'subtest is ok');
        done_testing;
    };

    my $obj = MyClass->new;
    can_ok($obj, 'method');
    isa_ok($obj, 'MyClass');

    done_testing;

RESOLVING CONFLICTS WITH MOOSE

If you are using Moose or Moo you may encounter conflicts with some of the test functions exported by Test2::V0. Specifically, Test::More and Test::Simple export run_tests, which conflicts with Moose's own run_tests.

To avoid this, you can either:

  1. Explicitly import the functions you need: 
        use Test2::V0 qw( ok plan );
  2. Use Test2::Tools::ResolveConflict. This is often the easiest way: 
        use Test2::V0;
        use Test2::Tools::ResolveConflict;
        # Now moose functions can be used without conflict

PRAGMAS

Test2::V0 supports the following pragmas:

no_plan
Disables the need for a plan. This is often used in conjunction with done_testing().
all_ok
Causes all tests to pass if they are not explicitly failed. Not recommended for general use.
only_run
A pragma that causes only the tests specified by the pragma to run.

PLUGINS

Test2::V0 can be extended with plugins. The following plugins are loaded by default:

Test2::Plugin::BadCall
Provides the bail_out() function.
Test2::Plugin::Compare
Provides comparison functions like is(), isnt(), like(), and unlike().
Test2::Plugin::Config
Provides configuration options for the test suite.
Test2::Plugin::Constants
Provides constants for common test values like T(), F(), D(), etc.
Test2::Plugin::Event
Provides functions for creating and checking events.
Test2::Plugin::Exception
Provides functions for testing exceptions like dies() and lives().
Test2::Plugin::Exports
Provides functions for testing imports like imported_ok() and not_imported_ok().
Test2::Plugin::Ref
Provides functions for testing references like ref_ok() and ref_is().
Test2::Plugin::Refcount
Provides functions for testing reference counts like is_refcount().
Test2::Plugin::Subtest
Provides the subtest() function.
Test2::Plugin::Warnings
Provides functions for testing warnings like warns() and no_warnings().

ENVIRONMENT VARIABLES

TEST_AUTHOR
If this is set, tests that are marked as "author tests" will be run.
TEST_DIFF_BREAKPOINTS
If this is set, diffs will be printed in a way that can be used by debuggers.
TEST_DEBUG
If this is set, verbose debugging information will be printed.
TEST_FOOK
If this is set, tests that are marked as "fook tests" will be run.
TEST_IGNORE_ERRORS
If this is set, errors will be ignored. Not recommended.
TEST_MAX_FAILURES
The maximum number of failures to report before stopping the test run.
TEST_ONLY_MATCH
If this is set, only tests that match the given pattern will be run.
TEST_SHOW_PROPERTIES
If this is set, properties of objects will be shown in test reports.
TEST_SHOW_UNEXPECTED
If this is set, unexpected values will be shown in test reports.
TEST_SOURCE_LOCATION
If this is set, the source location of test failures will be reported.
TEST_STRICT
If this is set, the test suite will be run in strict mode.

API FUNCTIONS

Test2::V0 exports a large number of functions. Here is a subset of the most common ones:

plan( $num_tests )
Declare the number of tests that will be run.
done_testing()
Indicates that all tests have been run. Useful when the number of tests is not known in advance.
bail_out($reason)
Causes the test run to stop immediately with the given reason.
