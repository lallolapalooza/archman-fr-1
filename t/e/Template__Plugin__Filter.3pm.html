NOM

Template::Plugin::Filter - Classe de base pour les filtres de plugins

SYNOPSIS

package MyOrg::Template::Plugin::MyFilter;
use Template::Plugin::Filter;
use base qw( Template::Plugin::Filter );
sub filter {
    my ($self, $text) = @_;
    # ...modifier $text...
    return $text;
}
# maintenant, chargez-le...
[% USE MyFilter %]
# ...et utilisez l'objet retourné comme filtre
[% FILTER $MyFilter %]
  ...
[% END %]

DESCRIPTION

Ce module implémente une classe de base pour les filtres de plugins. Il masque la complexité sous-jacente impliquée dans la création et l'utilisation de filtres qui sont définis et mis à disposition en chargeant un plugin.

Pour utiliser le module, créez simplement votre propre module de plugin dont hérite la classe "Template::Plugin::Filter".

package MyOrg::Template::Plugin::MyFilter;
use Template::Plugin::Filter;
use base qw( Template::Plugin::Filter );

Définissez ensuite simplement votre méthode filter(). Lorsqu'elle est appelée, une référence à votre objet plugin ($self) et le texte à filtrer vous sont passés.

sub filter {
    my ($self, $text) = @_;
    # ...modifier $text...
    return $text;
}

Pour utiliser votre plugin personnalisé, vous devez vous assurer que le Template Toolkit connaît votre espace de noms de plugin.

my $tt2 = Template->new({
    PLUGIN_BASE => 'MyOrg::Template::Plugin',
});

Ou pour des plugins individuels, vous pouvez faire ceci :

my $tt2 = Template->new({
    PLUGINS => {
        MyFilter => 'MyOrg::Template::Plugin::MyFilter',
    },
});

Ensuite, vous "USE"z votre plugin de la manière habituelle.

[% USE MyFilter %]

L'objet retourné est stocké dans la variable du même nom, '"MyFilter"'. Lorsque vous l'utilisez comme "FILTER", vous devez ajouter un préfixe dollar. Cela indique que vous voulez utiliser le filtre stocké dans la variable '"MyFilter"' plutôt que le filtre nommé '"MyFilter"', ce qui est une chose totalement différente (voir plus loin pour des informations sur la définition de filtres par nom).

[% FILTER $MyFilter %]
   ...texte à filtrer...
[% END %]

Vous pouvez, bien sûr, l'assigner à une autre variable.

[% USE blat = MyFilter %]
[% FILTER $blat %]
   ...texte à filtrer...
[% END %]

Tous les paramètres de configuration passés au constructeur du plugin depuis la directive "USE" sont stockés en interne dans l'objet pour être inspectés par la méthode filter() (ou toute autre méthode d'ailleurs). Les arguments positionnels sont stockés sous forme de référence à une liste dans l'élément "_ARGS" tandis que les paramètres de configuration nommés sont stockés sous forme de référence à un tableau associatif dans l'élément "_CONFIG".

Par exemple, charger un plugin comme montré ici :

[% USE blat = MyFilter 'foo' 'bar' baz = 'blam' %]

permettrait à la méthode filter() de faire ceci :

sub filter {
    my ($self, $text) = @_;
    my $args = $self->{ _ARGS   };  # [ 'foo', 'bar' ]
    my $conf = $self->{ _CONFIG };  # { baz => 'blam' }
    # ...modifier $text...
    return $text;
}

Par défaut, les plugins dérivés de ce module créeront des filtres statiques. Un filtre statique est créé une fois lorsque le plugin est chargé via la directive "USE" et réutilisé pour toutes les opérations "FILTER" ultérieures. Cela signifie que tous les arguments spécifiés avec la directive "FILTER" sont ignorés.

Les filtres dynamiques, en revanche, sont recréés chaque fois qu'ils sont utilisés par une directive "FILTER". Cela leur permet d'agir sur tous les paramètres passés depuis la directive "FILTER" et de modifier leur comportement en conséquence.

Il y a deux façons de créer un filtre dynamique. La première est de définir une variable de classe $DYNAMIC définie à une valeur vraie.

package MyOrg::Template::Plugin::MyFilter;
use base 'Template::Plugin::Filter';
our $DYNAMIC = 1;

L'autre façon est de définir la valeur interne "_DYNAMIC" dans la méthode init() qui est appelée par le constructeur new().

sub init {
    my $self = shift;
    $self->{ _DYNAMIC } = 1;
    return $self;
}

Lorsque ceci est défini à une valeur vraie, le plugin créera automatiquement un filtre dynamique. Le résultat est que la méthode filter() recevra également une référence à un tableau d'arguments positionnels et une référence à un tableau associatif de paramètres nommés.

Ainsi, utiliser un filtre de plugin comme ceci :

[% FILTER $blat 'foo' 'bar' baz = 'blam' %]

permettrait à la méthode filter() de fonctionner comme ceci :

sub filter {
    my ($self, $text, $args, $conf) = @_;
    # $args = [ 'foo', 'bar' ]
    # $conf = { baz => 'blam' }
}

Dans ce cas, vous pouvez passer des paramètres aux directives USE et FILTER, votre méthode filter() devrait donc probablement en tenir compte.

[% USE MyFilter 'foo' wiz => 'waz' %]
[% FILTER $MyFilter 'bar' biz => 'baz' %]
   ...
[% END %]

Vous pouvez utiliser les méthodes merge_args() et merge_config() pour fusionner facilement et rapidement les paramètres locaux (par exemple, "FILTER") avec les valeurs internes (par exemple, "USE") et retourner de nouveaux ensembles de données concaténées.

sub filter {
    my ($self, $text, $args, $conf) = @_;
    $args = $self->merge_args($args);
    $conf = $self->merge_config($conf);
    # $args = [ 'foo', 'bar' ]
    # $conf = { wiz => 'waz', biz => 'baz' }
    ...
}

Vous pouvez également faire en sorte que votre plugin s'installe comme filtre nommé en appelant la méthode install_filter() depuis la méthode init(). Vous devriez fournir un nom pour le filtre, quelque chose qui pourrait être une option de configuration.

sub init {
    my $self = shift;
    my $name = $self->{ _CONFIG }->{ name } || 'myfilter';
    $self->install_filter($name);
    return $self;
}

Cela permet d'utiliser le filtre du plugin comme suit :

[% USE MyFilter %]
[% FILTER myfilter %]
   ...
[% END %]

ou

[% USE MyFilter name = 'swipe' %]
[% FILTER swipe %]
   ...
[% END %]

Alternativement, vous pouvez permettre qu'un nom de filtre soit spécifié comme premier argument positionnel.

sub init {
    my $self = shift;
    my $name = $self->{ _ARGS }->[0] || 'myfilter';
    $self->install_filter($name);
    return $self;
}
[% USE MyFilter 'swipe' %]
[% FILTER swipe %]
   ...
[% END %]

EXEMPLE

Voici un exemple complet de module de filtre de plugin.

package My::Template::Plugin::Change;
use Template::Plugin::Filter;
use base qw( Template::Plugin::Filter );
sub init {
    my $self = shift;
    $self->{ _DYNAMIC } = 1;
    # le premier argument peut spécifier le nom du filtre
    $self->install_filter($self->{ _ARGS }->[0] || 'change');
    return $self;
}
sub filter {
    my ($self, $text, $args, $config) = @_;
    $config = $self->merge_config($config);
    my $regex = join('|', keys %$config);
    $text =~ s/($regex)/$config->{ $1 }/ge;
    return $text;
}
1;
