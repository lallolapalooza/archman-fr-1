Test::Harness(3perl) Guide du programmeur Perl Test::Harness(3perl)

NOM

Test::Harness - Exécuter les scripts de test standards de Perl avec des statistiques

VERSION

Version 3.50

SYNOPSIS

use Test::Harness;
runtests(@test_files);

DESCRIPTION

Bien que, pour des raisons historiques, la distribution Test::Harness tire son nom de ce module, il n'existe plus que pour fournir à TAP::Harness une interface quelque peu compatible avec Test::Harness 2.xx. Si vous écrivez du nouveau code, envisagez d'utiliser TAP::Harness directement à la place.

Une émulation est fournie pour "runtests" et "execute_tests", mais l'interface 'Straps' pluggable que les versions précédentes de Test::Harness supportaient n'est pas reproduite ici. Straps est maintenant disponible en tant que module autonome : Test::Harness::Straps.

Voir TAP::Parser, TAP::Harness pour la documentation principale de cette distribution.

FONCTIONS

Les fonctions suivantes sont disponibles.

runtests( @fichiers_de_test )

Ceci exécute tous les @fichiers_de_test donnés et détermine s'ils ont réussi ou échoué en fonction de leur sortie vers STDOUT (détails ci-dessus). Il affiche chaque test individuel qui a échoué ainsi qu'un rapport de résumé et le temps que tout cela a pris.

Il retourne vrai si tout s'est bien passé. Sinon, il die() avec l'un des messages de la section DIAGNOSTICS.

execute_tests( tests => \@fichiers_de_test, out => \*FH )

Exécute tous les @fichiers_de_test donnés (tout comme runtests()) mais ne génère pas le rapport final. Pendant les tests, les informations de progression seront écrites dans le descripteur de fichier de sortie actuellement sélectionné (généralement "STDOUT"), ou dans le descripteur de fichier fourni par le paramètre "out". Le out est facultatif.

Retourne une liste de deux valeurs, $total et $failed, décrivant les résultats. $total est une référence de hachage résumant tous les tests exécutés. Ses clés et valeurs sont les suivantes :

bonus           Nombre de tests individuels à faire inopinément réussis
max             Nombre de tests individuels exécutés
ok              Nombre de tests individuels réussis
sub_skipped     Nombre de tests individuels ignorés
todo            Nombre de tests individuels à faire
files           Nombre de fichiers de test exécutés
good            Nombre de fichiers de test réussis
bad             Nombre de fichiers de test échoués
tests           Nombre de fichiers de test initialement donnés
skipped         Nombre de fichiers de test ignorés

Si "$total->{bad} == 0" et "$total->{max} > 0", vous avez réussi les tests.

$failed est une référence de hachage de tous les scripts de test qui ont échoué. Chaque clé est le nom d'un script de test, chaque valeur est une autre référence de hachage représentant comment ce script a échoué. Ses clés sont les suivantes :

name        Nom du test qui a échoué
estat       Valeur de sortie du script
wstat       Statut d'attente du script
max         Nombre de tests individuels
failed      Nombre d'échecs
canon       Liste des tests qui ont échoué (sous forme de chaîne).

$failed devrait être vide si tout a réussi.

EXPORTATION

&runtests est exporté par "Test::Harness" par défaut.

&execute_tests, $verbose, $switches et $debug sont exportés sur demande.

VARIABLES D'ENVIRONNEMENT QUE TAP::HARNESS::COMPATIBLE DÉFINIT

"Test::Harness" définit celles-ci avant d'exécuter les tests individuels.

"HARNESS_ACTIVE"
Ceci est défini sur une valeur vraie. Il permet aux tests de déterminer s'ils sont exécutés via le harnais ou par tout autre moyen.
"HARNESS_VERSION"
Ceci est la version de "Test::Harness".

VARIABLES D'ENVIRONNEMENT QUI AFFECTENT TEST::HARNESS

"HARNESS_PERL_SWITCHES"
Définir ceci ajoute des commutateurs de ligne de commande perl à chaque fichier de test exécuté.

Par exemple, "HARNESS_PERL_SWITCHES=-T" activera le mode de marquage. "HARNESS_PERL_SWITCHES=-MDevel::Cover" exécutera "Devel::Cover" pour chaque test.

"-w" est toujours défini. Vous pouvez le désactiver dans le test avec "BEGIN { $^W = 0 }".

"HARNESS_TIMER"
Définir ceci sur vrai fera afficher au harnais le nombre de millisecondes prises par chaque test. Vous pouvez également utiliser le commutateur "--timer" de prove.
"HARNESS_VERBOSE"
Si vrai, "Test::Harness" affichera les résultats détaillés de l'exécution de ses tests. Définir $Test::Harness::verbose annulera ceci, ou vous pouvez utiliser le commutateur "-v" dans l'utilitaire prove.
"HARNESS_OPTIONS"
Fournit des options supplémentaires au harnais. Les options actuellement supportées sont :
"j<n>"
Exécute <n> (par défaut 9) jobs parallèles.
"c"
Essaye de coloriser la sortie. Voir "new" dans TAP::Formatter::Base.
"a<file.tgz>"
Utilisera TAP::Harness::Archive comme classe de harnais, et sauvegardera le TAP dans "file.tgz"
"fPackage-With-Dashes"
Définit la classe du formateur du harnais en cours d'exécution. Comme "HARNESS_OPTIONS" est séparé par ":", nous utilisons "-" à la place.

Plusieurs options peuvent être séparées par des deux-points :

HARNESS_OPTIONS=j9:c make test
"HARNESS_SUBCLASS"
Spécifie une sous-classe de TAP::Harness à utiliser à la place de TAP::Harness.
"HARNESS_SUMMARY_COLOR_SUCCESS"
Détermine la couleur Term::ANSIColor pour le résumé en cas de succès. Cette couleur est par défaut 'green'.
"HARNESS_SUMMARY_COLOR_FAIL"
Détermine la couleur Term::ANSIColor pour l'échec en cas de succès. Cette couleur est par défaut 'red'.

Mode de Marquage

Normalement, lorsqu'un programme Perl est exécuté en mode de marquage, le contenu de la variable d'environnement "PERL5LIB" n'apparaît pas dans @INC.

Étant donné que "PERL5LIB" est souvent utilisé pendant les tests pour ajouter des répertoires de construction à @INC, "Test::Harness" passe les noms de tous les répertoires trouvés dans "PERL5LIB" comme commutateurs -I. L'effet net est que "PERL5LIB" est respecté même en mode de marquage.
