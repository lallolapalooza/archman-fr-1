NAME

Test::LeakTrace - Suivi des fuites de mémoire

VERSION

Ce document décrit Test::LeakTrace version 0.17.

SYNOPSIS

use Test::LeakTrace;
# Rapport simple
leaktrace{
    # ...
};
# Sortie détaillée
leaktrace{
    # ...
} -verbose;
# Avec un callback
leaktrace{
    # ...
} sub {
    my($ref, $file, $line) = @_;
    warn "fuite de $ref de $file ligne\n";
};
my @refs = leaked_refs{
    # ...
};
my @info = leaked_info{
    # ...
};
my $count = leaked_count{
    # ...
};
# Interface de test standard
use Test::LeakTrace;
no_leaks_ok{
    # ...
} 'pas de fuites de mémoire';
leaks_cmp_ok{
    # ...
} '<', 10;

DESCRIPTION

"Test::LeakTrace" fournit plusieurs fonctions qui suivent les fuites de mémoire. Ce module scanne les "arenas", le système d'allocation de mémoire, donc il peut détecter tout SV libéré dans des blocs donnés.

Les SV libérés sont des SV qui ne sont pas libérés après la fin de la portée où ils ont été créés. Ces SV incluent les variables globales et les caches internes. Par exemple, si vous appelez une méthode dans un bloc de suivi, Perl pourrait préparer un cache pour la méthode. Pour suivre les vraies fuites, no_leaks_ok() et leaks_cmp_ok() exécutent le bloc plus d'une fois.

INTERFACE

Fonctions exportées

"leaked_info { BLOCK }"

Exécute BLOCK et renvoie une liste de SV libérés et d'où proviennent ces SV, c'est-à-dire "[$ref, $file, $line]".

"leaked_refs { BLOCK }"

Exécute BLOCK et renvoie une liste de SV libérés.

"leaked_count { BLOCK }"

Exécute BLOCK et renvoie le nombre de SV libérés.

"leaktrace { BLOCK } ?($mode | \&callback)"

Exécute BLOCK et signale les SV libérés à *STDERR.

Les valeurs $mode définies sont :

-simple
Par défaut. Signale l'identité des SV libérés (type et adresse), le nom du fichier et le numéro de ligne.
-sv_dump
En plus de -simple, imprime le contenu du SV en utilisant sv_dump(), qui implémente aussi Devel::Peek::Dump().
-lines
En plus de -simple, imprime les lignes suspectes.
-verbose
à la fois -sv_dump et -lines.

"no_leaks_ok { BLOCK } ?$description"

Teste que BLOCK ne libère pas de SV. Ceci est une fonction de test utilisant "Test::Builder".

Note : BLOCK est appelé plus d'une fois. C'est parce que BLOCK peut préparer des caches qui ne sont pas des fuites de mémoire.

"leaks_cmp_ok { BLOCK } $cmp_op, $number, ?$description"

Teste que BLOCK libère un nombre spécifique de SV. Ceci est une fonction de test utilisant "Test::Builder".

Note : BLOCK est appelé plus d'une fois. C'est parce que BLOCK peut préparer des caches qui ne sont pas des fuites de mémoire.

count_sv()

Compte tous les SV dans l'arena.

Interface de script

"Devel::LeakTrace" et "Test::LeakTrace::Script" sont fournis pour des scripts entiers.

Les arguments de "use Test::LeakTrace::Script" sont les mêmes que ceux de leaktrace().

$ TEST_LEAKTRACE=-sv_dump perl -MTest::LeakTrace::Script script.pl
$ perl -MTest::LeakTrace::Script=-verbose script.pl
#!perl
# ...
use Test::LeakTrace::Script sub{
    my($ref, $file, $line) = @_;
    # ...
};
# ...

EXEMPLES

Tests de modules

Voici un exemple de script de test qui vérifie les fuites de mémoire.

#!perl -w
use strict;
use constant HAS_LEAKTRACE => eval{ require Test::LeakTrace };
use Test::More HAS_LEAKTRACE ? (tests => 1) : (skip_all => 'require Test::LeakTrace');
use Test::LeakTrace;
use Some::Module;
leaks_cmp_ok{
    my $o = Some::Module->new();
    $o->something();
    $o->something_else();
} '<', 1;

DÉPENDANCES

Perl 5.8.1 ou version ultérieure, et un compilateur C.

ATTENTION

"Test::LeakTrace" ne fonctionne pas avec "Devel::Cover" et les modules qui installent leurs propres routines "runops" ou l'exécuteur Perl. Si les fonctions de test de ce module détectent des routines "runops" étranges, elles ne font rien et signalent "ok".
