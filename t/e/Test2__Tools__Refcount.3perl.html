Test2::Tools::Refcount(3perl) Guide du programmeur Perl Test2::Tools::Refcount(3perl)

NOM

"Test2::Tools::Refcount" - Asserter les compteurs de références sur les objets

SYNOPIS

use Test2::Tools::Refcount;
use Some::Class;
my $object = Some::Class->new();
is_oneref( $object, '$object a un compteur de références de 1' );
my $otherref = $object;
is_refcount( $object, 2, '$object a maintenant 2 références' );

DESCRIPTION

Le collecteur de garbage de Perl utilise un simple comptage de références pendant l'exécution normale d'un programme. Cela signifie que les cycles ou les références non affaiblies dans d'autres parties du code peuvent conserver un objet plus longtemps que prévu. Pour aider à éviter ce problème, le compteur de références d'un nouvel objet de son constructeur de classe devrait être de 1. Ainsi, l'appelant peut savoir que l'objet sera correctement DESTROYé lorsqu'il abandonnera toutes ses références à celui-ci.

Ce module fournit deux fonctions de test pour aider à garantir que cette propriété est respectée pour une classe d'objets, afin d'être aimable envers ses appelants.

Si l'assertion échoue ; c'est-à-dire si le compteur de références réel est différent de ce qui était attendu, l'un des deux modules suivants peut être utilisé pour aider le développeur à trouver où se trouvent les références.

•
Si Devel::MAT est installé, ce module de test l'utilisera pour vider l'état de la mémoire après un échec. Il créera un fichier .pmat portant le même nom que le test unitaire, mais avec le suffixe .t remplacé par -TEST.pmat où "TEST" est le numéro du test qui a échoué (s'il y en avait plus d'un).

Voir les exemples ci-dessous pour plus d'informations.

FONCTIONS

is_refcount

is_refcount( $object, $count, $name )

Teste que $object a $count références vers lui.

is_oneref

is_oneref( $object, $name )

Affirme que $object n'a qu'une seule référence vers lui.

refcount

$count = refcount( $object )

Retourne le compteur de références de l'objet donné tel qu'utilisé par les fonctions de test. Ceci est utile pour créer des tests qui ne se soucient pas de ce que le compteur était avant de commencer, mais affirment simplement que le compteur n'a pas changé à la fin.

use Test2::Tools::Refcount import => [qw( is_refcount refcount )];
{
   my $count = refcount( $object );
   do_something( $object );
   is_refcount( $object, $count, 'do_something() préserve le compteur de références' );
}

EXEMPLE

Supposons qu'après avoir écrit une nouvelle classe "MyBall", vous souhaitiez maintenant vérifier que son constructeur et ses méthodes se comportent correctement et ne fuient pas de références. Considérez le script de test suivant :

use Test::More tests => 2;
use Test2::Tools::Refcount;
use MyBall;
my $ball = MyBall->new();
is_oneref( $ball, 'Une référence après construction' );
$ball->bounce;
# Tout autre code ici qui pourrait faire partie du script de test
is_oneref( $ball, 'Une référence juste avant EOF' );

La première assertion est juste après le constructeur, pour vérifier que la référence retournée par celui-ci est la seule référence à cet objet. Ce fait est important si nous voulons que "DESTROY" se comporte correctement. Le deuxième appel est juste à la fin du fichier, juste avant que la portée principale ne se ferme. À ce stade, nous nous attendons également à ce que le compteur de références soit de un, afin que l'objet soit correctement nettoyé.

Supposons que, lors de l'exécution, cela produise la sortie suivante (en présumant que Devel::MAT::Dumper est disponible) :

1..2
ok 1 - Une référence après construction
not ok 2 - Une référence juste avant EOF
#   Échec du test 'Une référence juste avant EOF'
#   à ex.pl ligne 26.
#   attendu 1 références, trouvé 2
# L'adresse SV est 0x55e14c310278
# Écriture du dump de tas dans ex-2.pmat
# On dirait que vous avez échoué à 1 test sur 2.

Cela a écrit un fichier ex-2.pmat que nous pouvons charger en utilisant le shell "pmat" et utiliser la commande "identify" sur l'adresse donnée pour trouver où elle se trouve :

$ pmat ex-2.pmat 
Dépôt de mémoire Perl de perl 5.28.1 threaded
Le tas contient 25233 objets
pmat> identify 0x55e14c310278
HASH(0)=MyBall à 0x55e14c310278 est :
├──(via RV) le lexical $ball à la profondeur 1 de CODE() à 0x55e14c3104a0=main_cv, qui est :
│ └─le code principal
└─(via RV) la valeur {self} de HASH(2) à 0x55e14cacb860, qui est (*A) :
  └─(via RV) la valeur {cycle} de HASH(2) à 0x55e14cacb860, qui est :
    elle-même

(Ce document n'est pas destiné à être un tutoriel complet sur Devel::MAT et le shell "pmat" ; pour cela, voir Devel::MAT::UserGuide).

D'après cette sortie, nous pouvons voir que le constructeur était bien comporté, mais qu'une référence a fui à la fin du script - le compteur de références était de 2, alors que nous en attendions seulement 1. En lisant la sortie du trace, nous pouvons voir qu'il y avait 2 références qui pouvaient être trouvées - une stockée dans le lexique $ball dans le programme principal, et une stockée dans un HASH. Puisque nous nous attendions à trouver le lexique $ball, nous savons que nous cherchons maintenant une fuite dans un hash quelque part dans le code. En lisant le script de test, nous pouvons deviner que cette fuite se trouve probablement dans la méthode bounce(). De plus, nous savons que la référence à l'objet sera stockée dans un HASH dans un membre appelé "self".

En lisant le code qui implémente la méthode bounce(), nous pouvons voir que c'est effectivement le cas :

sub bounce
{
   my $self = shift;
   my $cycle = { self => $self };
   $cycle->{cycle} = $cycle;
}

En lisant la sortie de traçage, nous constatons que le HASH dans lequel cet objet est référencé contient également une référence à lui-même, dans un membre appelé "cycle". Cela provient de la dernière ligne de cette fonction, une ligne qui a délibérément créé un cycle, pour démontrer le propos. Bien qu'un programme réel ne ferait probablement rien d'aussi évident, le trace serait toujours utile pour trouver la cause probable de la fuite.

Si "Devel::MAT::Dumper" n'est pas disponible, alors ces traces détaillées ne seront pas produites. Les tests de base du compteur de références auront toujours lieu, mais un message plus petit sera produit :

1..2
ok 1 - Une référence après construction
not ok 2 - Une référence juste avant EOF
#   Échec du test 'Une référence juste avant EOF'
#   à demo.pl ligne 16.
#   attendu 1 références, trouvé 2
# On dirait que vous avez échoué à 1 test sur 2.

BOGUES

•
Temporaires créés sur la pile

Le code qui crée des temporaires sur la pile, pour être libéré à nouveau lorsque la fonction appelée retourne, ne fonctionne pas correctement sur perl 5.8 (et probablement avant). Des exemples tels que

is_oneref( [] );

peuvent échouer et revendiquer un compteur de références de 2.

Passer une variable telle que

my $array = [];
is_oneref( $array );

fonctionne correctement. En raison de l'intention de ce module de test ; c'est-à-dire, affirmer les compteurs de références sur un objet stocké dans une variable pendant la durée de vie du script de test, cela ne devrait probablement causer aucun problème.
