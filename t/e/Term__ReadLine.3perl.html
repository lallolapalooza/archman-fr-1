Term::ReadLine(3perl) Guide de référence du programmeur Perl Term::ReadLine(3perl)

NOM

Term::ReadLine - Interface Perl pour diverses implémentations de « readline ». Si aucune implémentation réelle n'est trouvée, des fonctions stub sont fournies à la place des fonctions de base.

SYNOPIS

use Term::ReadLine;
my $term = Term::ReadLine->new('Simple Perl calc');
my $prompt = "Enter your arithmetic expression: ";
my $OUT = $term->OUT || \*STDOUT;
while ( defined ($_ = $term->readline($prompt)) ) {
  my $res = eval($_);
  warn $@ if $@;
  print $OUT $res, "\n" unless $@;
  $term->addhistory($_) if /\S/;
}

DESCRIPTION

Ce paquet est simplement une façade vers d'autres paquets. C'est un stub pour établir une interface commune aux diverses implémentations de ReadLine trouvées sur CPAN (sous l'espace de noms « Term::ReadLine::* »).

Ensemble minimum de fonctions prises en charge

Toutes les fonctions prises en charge doivent être appelées en tant que méthodes, c'est-à-dire comme

$term = Term::ReadLine->new('name');

ou comme

$term->addhistory('row');

où $term est la valeur renvoyée par Term::ReadLine->new().

"ReadLine"
renvoie le paquet réel qui exécute les commandes. Les valeurs possibles incluent "Term::ReadLine::Gnu", "Term::ReadLine::Perl" et "Term::ReadLine::Stub".
"new"
renvoie le handle pour les appels ultérieurs aux fonctions suivantes. L'argument est le nom de l'application. Il peut éventuellement être suivi de deux arguments pour les descripteurs de fichiers "IN" et "OUT". Ces arguments doivent être globaux.
"readline"
obtient une ligne d'entrée, potentiellement avec une prise en charge réelle de "readline". La ligne de nouvelle ligne est supprimée. Renvoie "undef" en cas de "EOF".
"addhistory"
ajoute la ligne à l'historique d'entrée, d'où elle peut être utilisée si le paquet "readline" réel est présent.
"IN", "OUT"
renvoie les descripteurs de fichiers d'entrée et de sortie ou "undef" si "readline" pour Perl ne peut pas être utilisé.
"MinLine"
s'il est spécifié, est une recommandation sur la longueur minimale de ligne à inclure dans l'historique. "undef" signifie ne rien inclure dans l'historique. Renvoie la valeur précédente.
"findConsole"
renvoie un tableau avec deux chaînes qui sont des noms plus appropriés pour les fichiers d'entrée et de sortie en utilisant les conventions "<$in", ">out". Les chaînes renvoyées peuvent ne pas être utiles pour l'appel à "open() avec trois arguments.
Attribs
renvoie une référence vers une table de hachage décrivant la configuration interne du paquet. Les noms des entrées dans cette table suivent les conventions standard, avec le préfixe "rl_" supprimé.
"Features"
renvoie une référence vers une table de hachage où les clés sont les fonctionnalités présentes dans l'implémentation actuelle. Certaines fonctionnalités optionnelles sont utilisées dans l'interface minimale : "appname" doit être présent si le premier argument de "new" est reconnu, et "minline" doit être présent si la méthode "MinLine" n'est pas un stub. "autohistory" doit être présent si les lignes sont ajoutées à l'historique automatiquement (éventuellement sous "MinLine"), et "addhistory" si la méthode "addhistory" n'est pas un stub. Si "Features" signale une fonctionnalité "attribs" comme présente, la méthode "Attribs" n'est pas un stub.

Fonctions supplémentaires prises en charge

En réalité, "Term::ReadLine" peut utiliser certains autres paquets qui prennent en charge un ensemble de commandes plus riche.

Toutes ces commandes peuvent être appelées via l'interface de méthodes et ont des noms qui suivent les conventions standard, avec le préfixe "rl_" supprimé.

Le paquet de méthodes inclus dans la distribution Perl permet quelques fonctions supplémentaires :

"tkRunning"
fait tourner la boucle d'événements Tk lorsqu'une entrée utilisateur est attendue (c'est-à-dire pendant la méthode "readline").
"event_loop"
enregistre des callbacks pour attendre l'entrée utilisateur (c'est-à-dire pendant la méthode "readline"). Ceci suspend "tkRunning".

La première callback enregistrée est la callback d'attente. La callback est censée appeler la boucle d'événements actuelle jusqu'à ce qu'il y ait quelque chose en attente sur le descripteur de fichier. Le paramètre passé est la valeur renvoyée par la deuxième callback.

La deuxième callback enregistrée est la callback d'enregistrement. Le descripteur de fichier (souvent STDIN, mais pas nécessairement) est passé en paramètre.

Par exemple, avec AnyEvent :

$term->event_loop(sub {
  my $data = shift;
  $data->[1] = AE::cv();
  $data->[1]->recv();
}, sub {
  my $fh = shift;
  my $data = [];
  $data->[0] = AE::io($fh, 0, sub { $data->[1]->send() });
  $data;
});

La deuxième callback est facultative si la callback est enregistrée avant d'appeler $term->readline.

La désinscription se fait en appelant event_loop avec "undef" comme paramètre :

$term->event_loop(undef);

Cela provoquera la suppression de la référence de tableau, permettant une gestion normale de la mémoire. Avec AnyEvent, cela entraînera le nettoyage de $data->[0], et AnyEvent annulera l'observateur à ce moment-là. Si une autre boucle nécessite plus que ce qui est nécessaire pour nettoyer un observateur de fichier, cela sera géré aux frais de l'appelant.

"ornaments"
fait mettre en surbrillance la ligne de commande avec les données termcap. L'argument de "ornaments" doit être 0, 1, ou une chaîne de la forme "aa,bb,cc,dd". Les quatre composants de cette chaîne doivent être des noms de capacités de terminal, les deux premiers seront émis pour mettre en surbrillance l'invite, et les deux derniers pour mettre en surbrillance la ligne d'entrée.
"newTTY"
prend deux arguments qui sont les descripteurs de fichiers d'entrée et de sortie. Change pour utiliser ces descripteurs de fichiers.

Une fois le paquet ReadLine chargé, vous pouvez vérifier s'il prend en charge ces fonctions en vérifiant les "Features" correspondants.

EXPORTS

Aucun

ENVIRONNEMENT

La variable d'environnement "PERL_RL" régit quel clone de ReadLine est chargé. Si la valeur est fausse, une interface bidon est utilisée. Si la valeur est vraie, elle doit être la fin du nom du paquet à utiliser, comme "Perl" ou "Gnu".

Comme cas spécial, si la valeur de cette variable est séparée par des espaces, la fin peut être utilisée pour désactiver les ornements en définissant la fin à "o=0" ou "ornaments=0". L'en-tête doit être tel que décrit ci-dessus, par exemple :

export "PERL_RL=Perl o=0" # Utiliser ReadLine Perl sans ornements
export "PERL_RL= o=0"     # Utiliser le meilleur ReadLine sans ornements

(Note : Le traitement de "PERL_RL" pour les ornements est à la discrétion de)

"Term::ReadLine::*" paquet).
