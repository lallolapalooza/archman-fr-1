Test2::Tools::Spec(3perl) Guide de référence des programmeurs Perl Test2::Tools::Spec(3perl)

NOM

Test2::Tools::Spec - Implémentation RSPEC basée sur Test2::Workflow

DESCRIPTION

Ceci utilise Test2::Workflow pour implémenter une variante d'RSPEC. Cette variante prend en charge l'isolation et/ou la concurrence via le fork ou les threads.

SYNOPSIS

use Test2::Bundle::Extended;
use Test2::Tools::Spec;
describe foo => sub {
    before_all  once => sub { ... };
    before_each many => sub { ... };
    after_all  once => sub { ... };
    after_each many => sub { ... };
    case condition_a => sub { ... };
    case condition_b => sub { ... };
    tests foo => sub { ... };
    tests bar => sub { ... };
};
done_testing;

EXPORTATIONS

Toutes ces fonctions utilisent le même modèle d'arguments. Le premier argument doit toujours être un nom pour le bloc. Le dernier argument doit toujours être une référence de code. Optionnellement, une table de hachage de configuration peut être insérée entre le nom et la référence de code.

FONCTION "nom" => sub { ... };
FONCTION "nom" => {...}, sub { ... };
NOM
Le premier argument d'une fonction Test2::Tools::Spec DOIT être un nom. Le nom n'a pas besoin d'être unique.
PARAMETRES
Cet argument est facultatif. S'il est présent, il doit s'agir d'un hashref.

Voici les clés valides pour le hashref :

plat => $bool
Si cette valeur est définie à vrai, le bloc ne sera pas rendu comme un sous-test ; les événements seront plutôt intégrés au sous-test parent (ou au test principal).
asynchrone => $bool
Définir ceci à vrai pour marquer un bloc comme pouvant s'exécuter en concurrence avec d'autres blocs de test. Cela ne signifie pas que le bloc s'exécutera en concurrence, seulement qu'il le peut.
iso => $bool
Définir ceci à vrai si le bloc DOIT être exécuté de manière isolée. Si c'est le cas, le bloc s'exécutera dans son propre processus forké.

Ces tests seront ignorés sur toute plateforme qui ne dispose pas d'un vrai fork, ou de threads fonctionnels/activés.

Les threads ne seront utilisés QUE si la variable d'environnement T2_WORKFLOW_USE_THREADS est définie. Les tests de threads ne sont exécutés QUE si la variable d'environnement T2_DO_THREAD_TESTS est définie.

todo => $raison
Utilisez ceci pour marquer un bloc entier comme TODO.
skip => $raison
Utilisez ceci pour empêcher l'exécution d'un bloc.
REFCODE
Cet argument est obligatoire. Il doit s'agir d'une référence de code qui exécutera certaines assertions.

ESSENTIELS

tests NOM => sub { ... }
tests NOM => \%params, sub { ... }
tests($NOM, \%PARAMS, \&CODE)
it NOM => sub { ... }
it NOM => \%params, sub { ... }
it($NOM, \%PARAMS, \&CODE)
Ceci définit un bloc de test. Les blocs de test sont essentiellement des sous-tests. Tous les blocs de test seront exécutés et sont censés produire des événements. Les blocs de test peuvent être exécutés plusieurs fois si la fonction case() est également utilisée.

it() est un alias pour tests().

Ceux-ci NE SONT PAS hérités par les blocs describe imbriqués.

case NOM => sub { ... }
case NOM => \%params, sub { ... }
case($NOM, \%PARAMS, \&CODE)
Ceci vous permet de spécifier plusieurs conditions sous lesquelles les blocs de test doivent être exécutés. Chaque bloc de test au sein du même groupe ("describe") sera exécuté une fois par cas.

Ceux-ci NE SONT PAS hérités par les blocs describe imbriqués, mais les blocs describe imbriqués seront exécutés une fois par cas.

avant_chaque NOM => sub { ... }
avant_chaque NOM => \%params, sub { ... }
avant_chaque($NOM, \%PARAMS, \&CODE)
Spécifiez un bloc de code qui doit être exécuté plusieurs fois, une fois avant que chaque bloc tests() ne soit exécuté. Ceux-ci seront exécutés APRÈS les blocs case() mais avant les blocs tests().

Ceux-ci SONT hérités par les blocs describe imbriqués.

avant_cas NOM => sub { ... }
avant_cas NOM => \%params, sub { ... }
avant_cas($NOM, \%PARAMS, \&CODE)
Identique à avant_chaque(), sauf que ces blocs s'exécutent AVANT les blocs case().

Ceux-ci NE SONT PAS hérités par les blocs describe imbriqués.

avant_tout NOM => sub { ... }
avant_tout NOM => \%params, sub { ... }
avant_tout($NOM, \%PARAMS, \&CODE)
Spécifiez un bloc de code qui doit être exécuté une fois, avant que tous les blocs de test ne s'exécutent.

Ceux-ci NE SONT PAS hérités par les blocs describe imbriqués.

autour_de_chaque NOM => sub { ... }
autour_de_chaque NOM => \%params, sub { ... }
autour_de_chaque($NOM, \%PARAMS, \&CODE)
Spécifiez un bloc de code qui doit envelopper chaque bloc de test. Ces blocs s'exécutent APRÈS les blocs case, mais avant les blocs de test. 
autour_de_chaque wrapit => sub {
    my $cont = shift;
    local %ENV = ( ... );
    $cont->();
    ...
};

Le premier argument du bloc de code sera une fonction de rappel qui DOIT être appelée quelque part à l'intérieur du sous-programme pour que les éléments imbriqués s'exécutent.

Ceux-ci SONT hérités par les blocs describe imbriqués.

autour_du_cas NOM => sub { ... }
autour_du_cas NOM => \%params, sub { ... }
autour_du_cas($NOM, \%PARAMS, \&CODE)
Identique à "autour_de_chaque" sauf que ceux-ci s'exécutent AVANT les blocs case.

Ceux-ci NE SONT PAS hérités par les blocs describe imbriqués.

autour_de_tout NOM => sub { ... }
autour_de_tout NOM => \%params, sub { ... }
autour_de_tout($NOM, \%PARAMS, \&CODE)
Identique à "autour_de_chaque" sauf qu'il ne s'exécute qu'une fois pour envelopper TOUS les blocs de test.

Ceux-ci NE SONT PAS hérités par les blocs describe imbriqués.

apres_chaque NOM => sub { ... }
apres_chaque NOM => \%params, sub { ... }
apres_chaque($NOM, \%PARAMS, \&CODE)
Identique à "avant_chaque"
Test2::Tools::Spec(3pm)

NAME

Test2::Tools::Spec - Spec-style testing framework

DESCRIPTION

This module provides a spec-style testing interface. It is loosely based on RSpec, but aims to be simpler and more direct.

This module provides the following keywords:

    describe
    context
    fdescribe
    fcontext
    xdescribe
    xcontext
    before_all
    before_each
    after_all
    after_each
    case
    before_case
    after_case
    tests
    done_testing

SYNOPSIS

    use Test2::Tools::Spec ':ALL';

    describe 'A basic calculator' => sub {
        my $calc;

        before_each {
            $calc = Calculator->new;
        };

        describe 'addition' => sub {
            tests '1 + 1 should equal 2' => sub {
                is $calc->add(1, 1), 2;
            };
        };

        describe 'subtraction' => sub {
            tests '1 - 1 should equal 0' => sub {
                is $calc->subtract(1, 1), 0;
            };
        };
    };

    done_testing;

EXPORTS

This module exports all of the keywords defined above by default. You can also import specific keywords, or none at all.

    use Test2::Tools::Spec 'describe', 'tests';
    use Test2::Tools::Spec; # Exports all
    use Test2::Tools::Spec ':ALL'; # Exports all
    use Test2::Tools::Spec ':functional'; # Exports all but xdescribe, xcontext
    use Test2::Tools::Spec (); # Exports nothing

BLOCKS

These are the core building blocks of Test2::Tools::Spec.

describe NAME => CODE

Defines a block of tests. NAME is a string describing the block, and CODE is a code reference containing the tests.

The NAME is not required, but is highly recommended for readability.

context NAME => CODE

An alias for describe. Use it when you want to group tests without implying a new level of description.

fdescribe NAME => CODE

Similar to describe, but will only run this block and any nested blocks. Everything else will be skipped.

fcontext NAME => CODE

An alias for fdescribe.

xdescribe NAME => CODE

Similar to describe, but this block will be skipped entirely.

xcontext NAME => CODE

An alias for xdescribe.

tests NAME => CODE

Defines a single test. NAME is a string describing the test, and CODE is a code reference containing the actual test assertions.

This is the most basic test type.

tests NAME => HASHREF, CODE

This allows you to pass attributes to a test. The HASHREF is used for this. See the ATTRIBUTES section below.

HOOKS

These are code blocks that run before or after other blocks.

before_all NAME => CODE
before_all NAME => HASHREF, CODE
before_all($NAME, $PARAMS, $CODE)

Runs once before all tests in the current describe/context block.

These ARE NOT inherited by nested describe blocks.

before_each NAME => CODE
before_each NAME => HASHREF, CODE
before_each($NAME, $PARAMS, $CODE)

Runs before each test in the current describe/context block.

These ARE inherited by nested describe blocks.

after_each NAME => CODE
after_each NAME => HASHREF, CODE
after_each($NAME, $PARAMS, $CODE)

Runs after each test in the current describe/context block.

These ARE inherited by nested describe blocks.

after_case NAME => CODE
after_case NAME => HASHREF, CODE
after_case($NAME, $PARAMS, $CODE)

Runs right after the case block, and before the test block.

These ARE NOT inherited by nested describe blocks.

after_all NAME => CODE
after_all NAME => HASHREF, CODE
after_all($NAME, $PARAMS, $CODE)

Same as before_all except it runs after all test blocks have been run.

These ARE NOT inherited by nested describe blocks.

SHORTCUTS

These are shortcuts. Each of these is the same as tests() except some parameters are added for you.

These are NOT exported by default.

mini NAME => CODE

Same as:

tests NAME => { flat => 1 }, CODE
iso NAME => CODE

Same as:

tests NAME => { iso => 1 }, CODE
miso NAME => CODE

Same as:

tests NAME => { mini => 1, iso => 1 }, CODE
async NAME => CODE

Same as:

tests NAME => { async => 1 }, CODE

Note: This conflicts with the async() exported from threads. Don't import both.

masync NAME => CODE

Same as:

tests NAME => { minit => 1, async => 1 }, CODE

CUSTOM ATTRIBUTE DEFAULTS

Sometimes you want to apply default attributes to all tests() or case() blocks. This can be done, and is lexical to your describe or package root!

    use Test2::Bundle::Extended;
    use Test2::Tools::Spec ':ALL';
    # All 'tests' blocks after this declaration will have <<iso => 1>> by default
    spec_defaults tests => (iso => 1);
    tests foo => sub { ... }; # isolated
    tests foo, {iso => 0}, sub { ... }; # Not isolated
    spec_defaults tests => (iso => 0); # Turn it off again

Defaults are inherited by nested describe blocks. You can also override the defaults for the scope of the describe:

    spec_defaults tests => (iso => 1);
    describe foo => sub {
        spec_defaults tests => (async => 1); # Scoped to this describe and any child describes
        tests bar => sub { ... }; # both iso and async
    };
    tests baz => sub { ... }; # Just iso, no async.

You can apply defaults to any type of blocks:

    spec_defaults case => (iso => 1); # All cases are 'iso';

Defaults are not inherited when a builder's return is captured.

    spec_defaults tests => (iso => 1);
    # Note we are not calling this in void context, that is the key here.
    my $d = describe foo => {
        tests bar => sub { ... }; # Not iso
    };

EXECUTION ORDER

As each function is encountered it executes, just like any other function. The describe() function will immediately execute the codeblock it is given. All other functions will stash their codeblocks to be run later. When done_testing() is run the workflow will be compiled, at which point all other blocks will run.

Here is an overview of the order in which blocks get called once compiled (at done_testing()).

    before_all
        for-each-case {
            before_case
                case
            after_case
            # AND/OR nested describes
            before_each
                tests
            after_each
        }
    after_all
