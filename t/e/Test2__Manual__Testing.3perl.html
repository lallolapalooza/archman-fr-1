Test2::Manual::Testing(3perl) Guide de référence des programmeurs Perl Test2::Manual::Testing(3perl)

NOM

Test2::Manual::Testing - Hub pour la documentation sur l'écriture de tests avec Test2.

DESCRIPTION

Ce document présente tous les tutoriels et POD qui couvrent l'écriture de tests. Cette section ne couvre aucun aspect interne de Test2, ni la manière d'écrire de nouveaux outils. Pour cela, consultez Test2::Manual::Tooling.

MAP DES ESPACES DE NOMS

Lors de l'écriture de tests, il y a quelques espaces de noms sur lesquels se concentrer :

Test2::Tools::*
C'est ici que l'on trouve les ensembles d'outils. Un ensemble d'outils exporte des fonctions qui vous aident à faire des assertions sur votre code. Les ensembles d'outils ne doivent exporter que des fonctions, ils ne devraient jamais avoir d'effets supplémentaires/globaux.
Test2::Plugins::*
C'est ici que vivent les plugins. Les plugins ne doivent rien exporter, mais introduire ou modifier des comportements pour Test2 en général. Ces comportements peuvent être limités lexicalement, ou être globaux.
Test2::Bundle::*
Les bundles combinent des ensembles d'outils et des plugins pour réduire la quantité de code répétitif. Il est conseillé aux nouveaux rédacteurs de tests de commencer avec le bundle Test2::V0 (qui est une exception à la règle des espaces de noms car il ne vit pas sous "Test2::Bundle::"). Si vous vous retrouvez à charger plusieurs plugins et ensembles d'outils de manière répétée, vous pourriez bénéficier de l'écriture de votre propre bundle.
Test2::Require::*
Cet espace de noms contient des modules qui provoqueront le saut d'un test si certaines conditions ne sont pas remplies. Utilisez-le si vous avez des tests qui ne s'exécutent que sur des versions spécifiques de Perl, ou qui nécessitent des bibliothèques externes qui ne sont pas toujours disponibles.

LISTAGE DES DÉPENDANCES

Lorsque vous utilisez Test2, en particulier les éléments inclus dans Test2::Suite, vous devez les lister dans les dépendances de test de vos modules. Il est important de noter que vous devez lister les outils/plugins/bundles dont vous avez besoin, vous ne devez pas simplement lister Test2::Suite comme votre dépendance. Test2::Suite est une distribution vivante destinée à représenter les meilleures pratiques "actuelles". À mesure que les outils, plugins et bundles évoluent, les anciens seront déconseillés et potentiellement déplacés de Test2::Suite vers leurs propres distributions.

L'un des objectifs de Test2::Suite est d'éviter de casser la compatibilité ascendante. Un autre objectif est de s'améliorer constamment en remplaçant les mauvaises conceptions par de meilleures. Lorsque nécessaire, Test2::Suite déplacera de vieux modules vers des distributions distinctes et en définira de nouvelles, généralement avec un nouveau bundle. En bref, si nous ressentons le besoin de casser quelque chose, nous le ferons en créant un nouveau bundle et en déconseillant l'ancien, mais nous ne casserons pas l'ancien.

Donc, par exemple, si vous utilisez Test2::V0 et Dist::Zilla, vous devriez avoir ceci dans votre configuration :

[Prereqs / TestRequires]
Test2::V0 = 0.000060

Vous ne devriez **PAS** faire ceci :

[Prereqs / TestRequires]
Test2::Suite = 0.000060

Parce que Test2::V0 pourrait ne pas toujours faire partie de Test2::Suite.

Lors de l'écriture de nouveaux tests, vous devriez souvent consulter Test2::Suite pour voir quel est le bundle recommandé actuellement.

Dist::Zilla

[Prereqs / TestRequires]
Test2::V0 = 0.000060

ExtUtils::MakeMaker

my %WriteMakefileArgs = (
  ...,
  "TEST_REQUIRES" => {
    "Test2::V0" => "0.000060"
  },
  ...
);

Module::Install

test_requires 'Test2::V0' => '0.000060';

Module::Build

my $build = Module::Build->new(
    ...,
    test_requires => {
        "Test2::V0" => "0.000060",
    },
    ...
);
