Term::ProgressBar(3) Documentation Perl fournie par l'utilisateur Term::ProgressBar(3)

NOM

Term::ProgressBar - fournir un indicateur de progression sur un terminal standard.

VERSION

Version 2.23

SYNOPIS

use Term::ProgressBar;
my $progress = Term::ProgressBar->new ({count => 10_000});
$progress->update(5_000);

DESCRIPTION

Term::ProgressBar fournit une barre de progression simple sur le terminal, pour faire savoir à l'utilisateur que quelque chose se passe, approximativement quelle quantité de travail a été effectuée, et éventuellement une estimation du temps restant.

Une utilisation typique consiste à configurer la barre de progression avec un nombre d'éléments à traiter, puis à appeler `update` pour mettre à jour la barre chaque fois qu'un élément est traité.

Souvent, cela impliquera de mettre à jour la barre de progression plusieurs fois sans changement visible pour l'utilisateur. Pour éviter un travail inutile, la méthode `update` renvoie une valeur, qui est la valeur de mise à jour à laquelle l'utilisateur verra le prochain changement. En appelant `update` uniquement lorsque la valeur actuelle dépasse la prochaine valeur de mise à jour, les frais généraux d'appel sont réduits.

N'oubliez pas d'appeler "$progress->update($max_value)" lorsque le travail est terminé pour obtenir une belle barre de progression à 100 %.

Une barre de progression par défaut est simple ; elle va simplement de gauche à droite, remplissant la barre avec des caractères '='. Ce sont les caractères principaux. Pour les travaux de longue durée, cela peut être trop lent, donc deux fonctionnalités supplémentaires sont disponibles : un estimateur linéaire du temps d'achèvement, et/ou un caractère secondaire : il s'agit d'un caractère qui se déplace de gauche à droite sur la barre de progression (il ne la remplit pas comme le caractère principal), le parcourant une fois pour chaque caractère principal ajouté. Cela augmente exponentiellement la granularité de la barre pour la même largeur.

EXEMPLES

Une utilisation vraiment simple

#!/usr/bin/perl
use Term::ProgressBar 2.00;
use constant MAX => 100_000;
my $progress = Term::ProgressBar->new(MAX);
for (0..MAX) {
    my $is_power = 0;
    for (my $i = 0; 2**$i <= $_; $i++) {
        $is_power = 1 if 2**$i == $_;
    }
    if ($is_power) {
        $progress->update($_);
    }
}

voir eg/simle_use.pl

Voici un exemple simple. Le processus considère tous les nombres entre 0 et MAX, et met à jour la barre de progression chaque fois qu'il en trouve un. Notez que la mise à jour de la barre de progression sera très erratique. Voir ci-dessous pour un exemple plus fluide. Notez également que la barre de progression ne se terminera jamais ; voir ci-dessous pour résoudre ce problème.

Le texte complet de cet exemple se trouve dans examples/powers dans le jeu de distribution (il n'est pas installé dans le cadre du module).

Une mise à jour plus fluide de la barre

my $progress = Term::ProgressBar->new($max);
for (0..$max) {
    my $is_power = 0;
    for (my $i = 0; 2**$i <= $_; $i++) {
        $is_power = 1 if 2**$i == $_;
    }
    $progress->update($_)
}

Voir eg/smooth_bar.pl

Cet exemple appelle `update` pour chaque valeur considérée. Cela se traduira par une mise à jour de la barre de progression beaucoup plus fluide, mais plus de temps de programme sera consacré à la mise à jour de la barre qu'au travail « réel ». Voir ci-dessous pour y remédier. Cet exemple n'appelle *pas* "$progress->update($max);" à la fin, car ce n'est pas nécessaire, et ProgressBar lèvera une exception à une tentative de mise à jour d'une barre terminée.

Le texte complet de cet exemple se trouve dans examples/powers2 dans le jeu de distribution (il n'est pas installé dans le cadre du module.

Une mise à jour plus efficace (beaucoup)

my $progress = Term::ProgressBar->new({name => 'Powers', count => $max, remove => 1});
$progress->minor(0);
my $next_update = 0;
for (0..$max) {
    my $is_power = 0;
    for (my $i = 0; 2**$i <= $_; $i++) {
        $is_power = 1 if 2**$i == $_;
    }
    $next_update = $progress->update($_) if $_ >= $next_update;
}
$progress->update($max) if $max >= $next_update;

Cet exemple utilise deux choses pour améliorer l'efficacité : premièrement, il utilise la valeur renvoyée par `update` pour ne le rappeler que lorsque c'est nécessaire ; deuxièmement, il désactive l'utilisation de caractères secondaires pour mettre à jour beaucoup moins fréquemment ("$progress->minor(0);". L'utilisation de la valeur de retour de `update` signifie que l'appel de "$progress->update($max);" à la fin est nécessaire pour garantir que la barre se termine à 100 %, ce qui donne à l'utilisateur une bonne sensation.

Cet exemple définit également le nom de la barre de progression.

Cet exemple démontre également l'utilisation de l'indicateur 'remove', qui supprime la barre de progression du terminal une fois terminée.

Le texte complet de cet exemple se trouve dans examples/powers3 dans le jeu de distribution (il n'est pas installé dans le cadre du module.

Lorsque le nombre maximum d'éléments est parfois inconnu

Parfois, vous pouvez souhaiter utiliser la barre de progression lorsque le nombre d'éléments peut être connu ou non. Un exemple courant est lorsque vous écrivez un script qui peut prendre une entrée redirigée à partir de la sortie d'une autre commande, puis rediriger la sortie vers une autre commande. par ex. :

some_command --arg value | my_script.pl | some_other_command

Ou ...

my_script.pl input_file output_file

Cet exemple montre comment vous pouvez itérer sur un fichier spécifié sur la ligne de commande avec la barre de progression. Étant donné que le fichier d'entrée peut être lu depuis STDIN, le nombre de lignes peut ne pas être connu. Term::ProgressBar gère cela en prenant simplement '-1' comme valeur de décompte et sans autres modifications du code. En appelant `update` avec la même valeur de décompte, vous vous assurez que la barre de progression est supprimée par la suite.

my $input_file = shift;
my $output_file = shift;
my $in_fh = \*STDIN;
my $out_fh = \*STDOUT;
my $message_fh = \*STDERR;
my $num_lines = -1;
if (defined($input_file) and $input_file ne '-') {
    open($in_fh, $input_file) or die "Couldn't open file, '$input_file': $!";
    my $wc_output = `wc -l $input_file`;
    chomp($wc_output);
    $wc_output =~ /^\s*(\d+)(\D.*)?/ or die "Couldn't parse wc output: $wc_output";
    $num_lines = $1;
}
if(defined($output_file)) {
    !-f $output_file or die "Specified output file, '$output_file', already exists";
    open($out_fh, '>', $output_file) or die "Couldn't open output file, '$output_file': $!";
}
my $progress = Term::ProgressBar->new({
    name   => 'file processor',
    count  => $num_lines,
    remove => 1,
    fh     => $message_fh,
});
while (my $line = <$in_fh>) {
    chomp($line);
    print $out_fh "I found a line: $line\n";
    $progress->message("Found 10000!") if($line =~ /10000/);
    $progress->update();
}
$progress->update($num_lines);
print $message_fh "Finished\n";

Lorsque le fichier est défini explicitement, la barre de progression affiche la progression ligne par ligne à travers le fichier. Étant donné que la barre de progression imprime par défaut la sortie sur stderr, la sortie de vos scripts vers STDOUT ne sera pas affectée.

Utilisation de l'estimation du temps d'achèvement

  my $progress = Term::ProgressBar->new({
      name  => 'Powers',
      count => $max,
      ETA   => 'linear',
  });
  $progress->max_update_rate(1);
  my $next_update = 0;
  for (0..$max) {
      my $is_power = 0;
      for (my $i = 0; 2**$i <= $_; $i++) {
      if ( 2**$i == $_ ) {
          $is_power = 1;
          $progress->message(sprintf "Found %8d to be 2 ** %2d", $_, $i);
      }
  }
  $next_update = $progress->update($_)
    if $_ > $next_update;
}
$progress->update($max)
    if $max >= $next_update;

Cet exemple utilise l'option ETA pour activer l'estimation d'achèvement. De plus, la valeur de retour de `update` est ajustée pour tenter de mettre à jour la barre approximativement une fois par seconde, avec l'appel `max_update_rate`. Voir la documentation de la méthode `new` pour connaître les détails des formats utilisés.

Cet exemple fournit également un exemple d'utilisation de la fonction `message` pour afficher des messages dans le même descripteur de fichier tout en conservant la barre de progression intacte

Le texte complet de cet exemple se trouve dans examples/powers5 dans le jeu de distribution (il n'est pas installé dans le cadre du module.

CONSTRUCTION D'INSTANCE

new

Crée & retourne une nouvelle instance de Term::ProgressBar.

ARGUMENTS
Si un argument est fourni, et qu'il s'agit d'un hashref, alors la hash est traitée comme un ensemble de paires clé/valeur, avec les clés suivantes ; sinon, elle est traitée comme un nombre, étant équivalente à la clé "count".
count
Le nombre d'éléments. La progression est marquée à 100% lorsque update count est appelée, et proportionnellement jusqu'alors.

Si vous spécifiez un compte inférieur à zéro, seul le nom (s'il est spécifié) sera affiché et (si l'indicateur de suppression est défini) supprimé lorsque la barre de progression sera mise à jour avec un nombre inférieur à zéro. Cela vous permet d'utiliser la barre de progression lorsque le compte est parfois connu et parfois non, sans faire de multiples changements dans votre code.

name
Un nom pour préfixer la barre de progression.
fh
Le filehandle de sortie. Par défaut, c'est stderr. N'essayez pas d'utiliser la syntaxe *foo{THING} si vous voulez des capacités Term ; cela ne fonctionne pas. Passez plutôt une référence de glob.
term_width
Parfois, nous ne pouvons pas déterminer correctement la largeur du terminal. Vous pouvez utiliser ce paramètre pour forcer une largeur de terminal d'une taille particulière. Utilisez un entier positif, s'il vous plaît :)
silent
Si une valeur vraie est passée, Term::ProgressBar ne fera rien du tout. Utile dans les scripts où la barre de progression est facultative (ou ne fonctionne tout simplement pas en raison de problèmes avec les modules dont elle dépend).

Au lieu de cela, dites au constructeur que vous voulez qu'il soit silencieux et que vous n'avez pas besoin de changer le reste de votre programme :

my $progress = Term::ProgressBar->new( { count => $count, silent => $silent } );
# plus tard
$progress->update; # ne fait rien
ETA
Une estimation du temps total à utiliser. Si activée, une estimation de l'heure d'achèvement est imprimée sur le côté droit (une fois que suffisamment de mises à jour ont été effectuées pour rendre une telle estimation réalisable). Naturellement, il s'agit d'une estimation ; aucune garantie n'est faite. Le format de l'estimation

Notez que le format est conçu pour être aussi compact que possible tout en fournissant les informations pertinentes. Selon le temps restant, le format est sélectionné pour fournir une certaine résolution tout en restant compact. Comme le temps restant diminue, le format change généralement au fil du temps.

À mesure que l'ETA approche, le format indiquera les minutes et secondes restantes. Ceci est identifiable par le mot 'Left' à droite de la ligne. Si l'ETA est plus lointain, alors une estimation de l'heure d'achèvement (plutôt que du temps restant) est donnée, et est identifiable par 'ETA' à gauche de la boîte ETA (à droite de la barre de progression). Une heure ou une date peut être présentée ; celles-ci sont sous la forme d'une horloge de 24 heures, par exemple '13:33', une heure plus les jours (par exemple, ' 7PM+3' pour environ 3 jours plus tard) ou un jour/date, par exemple ' 1Jan' ou '27Feb'.

Si ETA est activé, la valeur de retour de update est également affectée : l'idée est que si la barre de progression semble évoluer plus rapidement que ce que l'œil ne pourrait normalement supporter (et donc beaucoup de temps est passé à faire des mises à jour de progression plutôt que du travail "réel"), la prochaine valeur est augmentée pour ralentir. Le taux maximum visé est réglable via le composant max_update_rate.

Les valeurs disponibles pour ceci sont :

undef
Ne pas faire d'estimation. Par défaut.
linear
Effectuer une estimation linéaire. C'est simplement que la quantité de temps entre la création de la barre de progression et maintenant est divisée par la quantité terminée actuelle, et l'achèvement est estimé linéairement.
EXEMPLES
my $progress = Term::ProgressBar->new(100); # Compte de 1 à 100
my $progress = Term::ProgressBar->new({ count => 100 }); # Idem
# Compte jusqu'à 200 trucs, sortie sur stdout au lieu de stderr,
# préfixe la barre avec 'truc'
my $progress = Term::ProgressBar->new({ count => 200,
                                        fh    => \*STDOUT,
                                        name  => 'truc' });

COMPOSANTS D'INSTANCE

Composants Scalaires.

Voir "get_set" dans Class::MethodMaker pour l'utilisation.

target
La cible finale. Les mises à jour sont mesurées par rapport à cela. Les changements n'auront d'effet qu'à la prochaine mise à jour, mais la valeur de la prochaine mise à jour doit être relative à la nouvelle cible. Donc 
$p = Term::ProgressBar({count => 20});
# Mi-parcours
$p->update(10);
# Double échelle
$p->target(40)
$p->update(21);

entraînera la mise à jour de la barre de progression à 52,5%

max_update_rate
Cette valeur est considérée comme la vitesse maximale entre les mises à jour à viser. Elle n'a de sens que si ETA est activé. Elle est par défaut à 0.5, étant le nombre de secondes entre les mises à jour.

Composants Booléens

Voir "get_set" dans Class::MethodMaker pour l'utilisation.

minor
Par défaut : défini. Si non défini, aucune échelle mineure ne sera calculée ou mise à jour.

Les caractères mineurs sont utilisés sur la barre de progression pour donner à l'utilisateur une idée de la progression, même lorsqu'il y a tellement plus de tâches que la largeur du terminal ne le permet que la granularité serait trop grande. Par défaut, Term::ProgressBar devine quand les caractères mineurs seraient utiles. Cependant, il ne devine pas toujours correctement, donc cette méthode peut être appelée pour la forcer dans un sens ou dans l'autre. Bien sûr, l'économie d'efficacité est minime, sauf si le client utilise la valeur de retour de update.

Voir examples/powers4 et examples/powers3 pour voir les caractères mineurs en action, et non en action, respectivement.

Configuration

lbrack
Crochet gauche (par défaut [ ) 
$progress->lbrack('<');
rbrack
Crochet droit (par défaut ] ) 
$progress->rbrack('>');

PROCÉDURES DE PLUS HAUT NIVEAU D'INSTANCE

update

Met à jour la barre de progression.

ARGUMENTS
so_far
Point de progression actuel, dans les unités qui ont été passées à "new".

Si non défini, est supposé être 1 + la valeur précédente lors de l'appel de "update" (en commençant à 0).

RETOURNE
next_call
La prochaine valeur de so_far à laquelle appeler "update".

message

Affiche un message. C'est très similaire à print, mais nous essayons de ne pas perturber le terminal.

ARGUMENTS
string
Le message à afficher.

COMPATIBILITÉ

Si exactement deux arguments sont fournis, alors new opère en mode de compatibilité v1 : les arguments sont considérés comme le nom et le nombre d'éléments. Divers autres paramètres par défaut sont définis pour émuler la version un (par exemple, le caractère de sortie principal est '#', la largeur de la barre est définie sur 50 caractères et le filehandle de sortie n'est pas traité comme un terminal). Ce mode est déprécié.
