Test2::IPC::Driver(3perl) Guide de référence du programmeur Perl Test2::IPC::Driver(3perl)

NOM

Test2::IPC::Driver - Classe de base pour les pilotes IPC de Test2.

SYNOPIS

package Test2::IPC::Driver::MyDriver;
use base 'Test2::IPC::Driver';
...

MÉTHODES

$self->abort($msg)
Si une IPC rencontre une erreur fatale, elle doit utiliser ceci. Ceci affichera le message sur STDERR avec le préfixe 'IPC Fatal Error: ', puis quittera de force avec le code 255. Des erreurs IPC peuvent survenir dans des threads ou des processus autres que le principal, cette méthode offre la meilleure chance que le système de test remarque l'erreur.
$self->abort_trace($msg)
C'est identique à "$ipc->abort($msg)" sauf qu'il utilise "Carp::longmess" pour ajouter une trace de la pile d'appels au message.

CHARGEMENT DES PILOTES

Test2::IPC::Driver a une méthode import(). Tous les pilotes héritent de cette méthode d'importation. Cette méthode d'importation enregistre le pilote.

Dans la plupart des cas, il vous suffit de charger le pilote IPC souhaité pour qu'il fonctionne. Vous devriez charger ce pilote dès que possible. Un avertissement sera émis si vous le chargez trop tard pour qu'il soit efficace.

use Test2::IPC::Driver::MyDriver;
...

MÉTHODES QUE LES SOUS-CLASSES DOIVENT IMPLÉMENTER

$ipc->is_viable
Doit retourner vrai si le pilote fonctionne dans l'environnement actuel. Doit retourner faux s'il ne fonctionne pas. C'est une méthode DE CLASSE.
$ipc->add_hub($hid)
Ceci est utilisé pour alerter le pilote qu'un nouveau hub attend des événements. Le pilote doit suivre les identifiants de processus et de thread ; le hub ne doit être supprimé que par le processus+thread qui l'a démarré. 
sub add_hub {
    my $self = shift;
    my ($hid) = @_;
    ... # Rendre possible le contact du hub
}
$ipc->drop_hub($hid)
Ceci est utilisé pour alerter le pilote qu'un hub n'accepte plus d'événements. Le pilote doit suivre les identifiants de processus et de thread ; le hub ne doit être supprimé que par le processus+thread qui l'a démarré (c'est la responsabilité du pilote de faire respecter cela). 
sub drop_hub {
    my $self = shift;
    my ($hid) = @_;
    ... # Rien ne devrait plus essayer de joindre le hub.
}
$ipc->send($hid, $event);
$ipc->send($hid, $event, $global);
Utilisé pour envoyer des événements du processus/thread actuel au hub spécifié dans son processus+thread. 
sub send {
    my $self = shift;
    my ($hid, $e) = @_;
    ... # Envoyer l'événement au bon hub.
    # Ceci peut notifier d'autres processus/threads qu'il y a un événement en attente.
    Test2::API::test2_ipc_set_pending($uniq_val);
}

Si $global est vrai, alors le pilote devrait envoyer l'événement à tous les hubs dans tous les processus et threads.

@events = $ipc->cull($hid)
Utilisé pour collecter les événements qui ont été envoyés au hub spécifié. 
sub cull {
    my $self = shift;
    my ($hid) = @_;
    my @events = ...; # Ici, vous récupérez les événements pour le hub
    return @events;
}
$ipc->waiting()
Ceci est appelé dans le processus parent lorsqu'il est terminé et qu'il attend que tous les processus et threads enfants se terminent. 
sub waiting {
    my $self = shift;
    ... # Notifier tous les processus et threads en attente que le processus/thread
    ... # principal attend qu'ils finissent.
}

MÉTHODES QUE LES SOUS-CLASSES PEUVENT IMPLÉMENTER OU REDÉFINIR

$ipc->driver_abort($msg)
Ceci est un crochet appelé par "Test2::IPC::Driver->abort()". C'est votre chance de faire du nettoyage lorsqu'une interruption se produit. Vous ne pouvez pas empêcher l'interruption, mais vous pouvez l'accepter gracieusement.
