NOM

Term::ReadKey - Module Perl pour le contrôle simple du terminal

SYNOPHIS

use Term::ReadKey;
ReadMode 4; # Désactive les touches de contrôle
while (not defined ($key = ReadKey(-1))) {
    # Touche pas encore reçue
}
print "Touche reçue $key\n";
ReadMode 0; # Réinitialise le mode tty avant de quitter

DESCRIPTION

Term::ReadKey est un module Perl compilé dédié à fournir un contrôle simple des modes du pilote de terminal (cbreak, raw, cooked, etc.), une prise en charge des lectures non bloquantes, si l'architecture le permet, et quelques fonctions utilitaires généralisées pour travailler avec les terminaux. L'un des objectifs principaux est de rendre les fonctions aussi portables que possible, afin que vous puissiez simplement insérer "use Term::ReadKey" sur n'importe quelle architecture et avoir une bonne probabilité que cela fonctionne.

Version 2.30.01 : Ajout de la gestion des touches fléchées, page haut/bas, début/fin, insertion/suppression sous Win32. Ces touches émettent des séquences compatibles xterm. Fonctionne avec Term::ReadLine::Perl.

ReadMode MODE [, DescripteurDeFichier]
Prend un argument entier ou un synonyme de chaîne (insensible à la casse), qui peut actuellement être l'une des valeurs suivantes : 
INT   SYNONYME    DESCRIPTION
0    'restore'   Restaure les paramètres d'origine.
1    'normal'    Passe au mode généralement par défaut,
                 écho activé, tamponné, signaux activés, Xon/Xoff
                 éventuellement activé, et mode 8 bits éventuellement désactivé.
2    'noecho'    Identique à 1, mais avec l'écho désactivé. Utile pour
                 lire des mots de passe.
3    'cbreak'    Écho désactivé, non tamponné, signaux activés, Xon/Xoff
                 éventuellement activé, et mode 8 bits éventuellement activé.
4    'raw'       Écho désactivé, non tamponné, signaux désactivés, Xon/Xoff
                 désactivés, et mode 8 bits éventuellement désactivé.
5    'ultra-raw' Écho désactivé, non tamponné, signaux désactivés, Xon/Xoff
                 désactivés, mode 8 bits activé si la parité le permet,
                 et traduction CR en CR/LF désactivée.

Ces fonctions sont automatiquement appliquées au descripteur STDIN si aucun autre descripteur n'est fourni. Les modes 0 et 5 ont des propriétés spéciales qui méritent d'être mentionnées : le mode 0 ne restaurera pas seulement les paramètres d'origine, mais provoquera la sauvegarde d'un nouvel ensemble de paramètres par défaut lors du prochain appel à ReadMode. Le mode 5 est similaire au mode 4, sauf qu'aucune traduction CR/LF n'est effectuée, et si possible, la parité sera désactivée (uniquement si elle n'est pas utilisée par le terminal, cependant. Il n'est pas différent du mode 4 sous Windows.)

Si vous avez juste besoin de lire une touche à la fois, alors les modes 3 ou 4 sont probablement suffisants. Le mode 4 est un peu plus flexible, mais nécessite un peu plus de travail pour le contrôler. Si vous utilisez ReadMode 3, vous devriez installer un gestionnaire SIGINT ou END pour réinitialiser le terminal (via ReadMode 0) si l'utilisateur interrompt le programme via "^C". (Pour n'importe quel mode, un gestionnaire END consistant en "ReadMode 0" est en fait une bonne idée.)

Si vous exécutez un autre programme qui pourrait modifier le mode du terminal, vous voudrez soit dire

ReadMode 1;             # identique à ReadMode 'normal'
system('someprogram');
ReadMode 1;

ce qui réinitialise les paramètres après l'exécution du programme, ou :

$somemode=1;
ReadMode 0;             # identique à ReadMode 'restore'
system('someprogram');
ReadMode 1;

qui enregistre toutes les modifications que le programme aurait pu apporter, avant de réinitialiser le mode.

ReadKey MODE [, DescripteurDeFichier]
Prend un argument entier, qui peut actuellement être l'une des valeurs suivantes : 
0    Effectue une lecture normale en utilisant getc
-1   Effectue une lecture non bloquante
>0   Effectue une lecture avec délai d'attente

Si le descripteur de fichier n'est pas fourni, il sera par défaut STDIN. S'il n'y a rien en attente dans le tampon lors d'une lecture non bloquante, alors undef sera retourné. Dans la plupart des situations, vous voudrez probablement utiliser "ReadKey -1".

NOTE que si le système d'exploitation ne fournit aucun mécanisme connu pour les lectures non bloquantes, alors "ReadKey -1" peut planter avec une erreur fatale. Cela sera, on l'espère, peu fréquent.

Si MODE est supérieur à zéro, alors ReadKey l'utilisera comme valeur de délai d'attente en secondes (les fractions de seconde sont autorisées), et ne retournera pas "undef" avant que ce temps ne soit écoulé.

NOTE, encore une fois, que certains systèmes d'exploitation peuvent ne pas supporter ce comportement de délai d'attente.

Si MODE est inférieur à zéro, alors ceci est traité comme un délai d'attente de zéro, et donc retournera immédiatement si aucun caractère n'est en attente. Un MODE de zéro, cependant, agira comme un getc normal.

NOTE, il y a actuellement certaines limitations avec cet appel sous Windows. Il est possible que les lectures non bloquantes échouent lors de la lecture de touches répétées provenant de plus d'une console.

ReadLine MODE [, DescripteurDeFichier]
Prend un argument entier, qui peut actuellement être l'une des valeurs suivantes : 
0    Effectue une lecture normale en utilisant scalar(<DescripteurFichier>)
-1   Effectue une lecture non bloquante
>0   Effectue une lecture avec délai d'attente

S'il n'y a rien en attente dans le tampon lors d'une lecture non bloquante, alors undef sera retourné.

NOTE, que si le système d'exploitation ne fournit aucun mécanisme connu pour les lectures non bloquantes, alors "ReadLine 1" peut planter avec une erreur fatale. Cela sera, on l'espère, peu fréquent.

NOTE qu'un test non bloquant n'est effectué que pour le premier caractère de la ligne, pas pour la ligne entière. Cet appel ne fera probablement pas ce que vous supposez, en particulier avec les valeurs de MODE "ReadMode" supérieures à 1. Par exemple, appuyer sur Espace puis sur Retour arrière pourrait sembler vous ramener à votre point de départ, mais tous les délais d'attente seraient alors suspendus.

Cet appel n'est actuellement pas disponible sous Windows.

GetTerminalSize [DescripteurDeFichier]
Retourne soit un tableau vide si cette opération n'est pas prise en charge, soit un tableau de quatre éléments contenant : la largeur du terminal en caractères, la hauteur du terminal en caractères, la largeur en pixels et la hauteur en pixels. (La taille en pixels ne sera valide que dans certains environnements.)

NOTE, sous Windows, cette fonction doit être appelée avec un descripteur de fichier de sortie, tel que "STDOUT", ou un descripteur ouvert sur "CONOUT$".

SetTerminalSize LARGEUR,HAUTEUR,PIXELS_X,PIXELS_Y [, DescripteurDeFichier]
Retourne -1 en cas d'échec, 0 sinon.

NOTE que cette taille de terminal est uniquement à titre informatif, et modifier la taille via ce mécanisme ne changera pas la taille de l'écran. Par exemple, XTerm utilise un appel comme celui-ci lorsqu'il redimensionne l'écran. Si l'une des nouvelles mesures diffère des anciennes, le système d'exploitation enverra probablement un signal SIGWINCH à tout ce qui lit ce tty ou pty.

Cet appel ne fonctionne pas sous Windows.

GetSpeed [, DescripteurDeFichier]
Retourne soit un tableau vide si l'opération n'est pas prise en charge, soit un tableau à deux valeurs contenant les vitesses d'entrée et de sortie du terminal, en décimal. Par exemple, une vitesse d'entrée de 9600 bauds et une vitesse de sortie de 4800 bauds seraient retournées sous la forme (9600,4800). Notez qu'actuellement les vitesses d'entrée et de sortie seront toujours identiques sur certains systèmes d'exploitation.

Aucune vitesse n'est rapportée sous Windows.

GetControlChars [, DescripteurDeFichier]
Retourne un tableau contenant des paires clé/valeur appropriées pour une table de hachage. Les paires consistent en une clé, le nom du caractère/signal de contrôle, et la valeur de ce caractère, sous forme d'un seul caractère.

Cet appel ne fait rien sous Windows.

Chaque clé sera une entrée de la liste suivante :

DISCARD
DSUSPEND
EOF
EOL
EOL2
ERASE
ERASEWORD
INTERRUPT
KILL
MIN
QUIT
QUOTENEXT
REPRINT
START
STATUS
STOP
SUSPEND
SWITCH
TIME

Ainsi, le code suivant retournera toujours le caractère d'interruption actuel, quelle que soit la plateforme.

%keys = GetControlChars;
$int = $keys{INTERRUPT};
