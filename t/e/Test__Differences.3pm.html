Test::Differences(3) Documentation soumise par la communauté Perl Test::Differences(3)

NAME

Test::Differences - Tester des chaînes et des structures de données et afficher les différences si elles ne correspondent pas.

SYNOPSIS

use Test;    ## Ou use Test::More
use Test::Differences;
eq_or_diff $got,  "a\nb\nc\n",   "test de chaînes";
eq_or_diff \@got, [qw( a b c )], "test de tableaux";
## Passage d'options :
eq_or_diff $got, $expected, $name, { context => 300 };  ## options
## Utilisation avec des structures de données type DBI
use DBI;
... ouvrir la connexion & préparer l'instruction et @expected_... ici...
eq_or_diff $sth->fetchall_arrayref, \@expected_arrays,  "test de tableaux DBI";
eq_or_diff $sth->fetchall_hashref,  \@expected_hashes, "test de hachages DBI";
## Pour forcer le numéro de ligne de texte ou de données (les lignes de texte sont numérotées 1..):
eq_or_diff_text ...;
eq_or_diff_data ...;

EXPORT

Ce module exporte trois fonctions de test et quatre fonctions de type diff :

•
Fonctions de test
  • "eq_or_diff"
  • "eq_or_diff_data"
  • "eq_or_diff_text"
•
Fonctions de type diff
  • "table_diff" (par défaut)
  • "unified_diff"
  • "oldstyle_diff"
  • "context_diff"

DESCRIPTION

Lorsque le code que vous testez retourne plusieurs lignes, enregistrements ou structures de données et qu'ils sont simplement incorrects, il peut être suffisamment similaire à l'utilitaire Unix "diff" pour être utile. Voici le résultat d'un script de test exemple qui vérifie deux documents texte, puis deux (très simples) structures de données :

t/99example....1..3
not ok 1 - différences dans le texte
#     Échec du test ((eval 2) à la ligne 14)
#     +---+----------------+----------------+
#     | L | Got            | Expected       |
#     +---+----------------+----------------+
#     |  1|this is line 1  |this is line 1  |
#     *  2|this is line 2  |this is line b  *
#     |  3|this is line 3  |this is line 3  |
#     +---+----------------+----------------+
not ok 2 - différences d'espaces blancs
#     Échec du test ((eval 2) à la ligne 20)
#     +---+------------------+------------------+
#     | L | Got              | Expected         |
#     +---+------------------+------------------+
#     |  1|        indented  |        indented  |
#     *  2|        indented  |\tindented        *
#     |  3|        indented  |        indented  |
#     +---+------------------+------------------+
not ok 3
#     Échec du test ((eval 2) à la ligne 22)
#     +----+-------------------------------------+----------------------------+
#     | El | Got                                  | Expected                   |
#     +----+-------------------------------------+----------------------------+
#     *   0|bless( [                             |[                           *
#     *   1|  'Move along, nothing to see here'  |  'Dry, humorless message'  *
#     *   2|], 'Test::Builder' )                 |]                           *
#     +----+-------------------------------------+----------------------------+
# Looks like you failed 3 tests of 3.

eq_or_diff_...() compare deux chaînes ou (de manière limitée) des structures de données et émet un indicateur ok ou un diff des deux côtés. Test::Differences est conçu pour être utilisé avec Test.pm et les modules de test basés sur Test::Builder. Comme le montre le SYNOPSIS, un autre module de test doit être utilisé comme base pour votre suite de tests.

OPTIONS

Les options pour eq_or_diff donnent un certain contrôle fin sur la sortie.

  • "context"

    Ceci permet de contrôler la quantité de contexte affichée :

    eq_or_diff $got, $expected, $name, { context => 50000 };

    Ceci affichera beaucoup de lignes de contexte. Normalement, eq_or_diff() utilise des règles heuristiques pour déterminer s'il faut afficher 3 lignes de contexte (comme un diff normal) ou 25 lignes.

  • "data_type"

    "text" ou "data". Ceci est généralement par défaut "data". Si, cependant, ni $got ni $expected n'est une référence, alors "text" est utilisé par défaut. Vous pouvez également forcer l'un ou l'autre en appelant eq_or_diff_text() ou eq_or_diff_data().

    # +---+-------+----------+
# | L | Got   | Expected |
# +---+-------+----------+
# *  1|'foo'  |'bar'     *
# +---+-------+----------+
# +----+---------+----+----------+
# | Elt| Got      | Elt| Expected |
# +----+---------+----+----------+
# *   0|[        *   0|'bar'     *
# *   1|  'foo'  *    |          |
# *   2|]        *    |          |
# +----+---------+----+----------+

    La différence est qu'en mode texte, les lignes sont numérotées à partir de 1, mais en mode données, elles sont numérotées à partir de 0 (et appelées 'éléments' (Elt) au lieu de lignes) :

  • "Sortkeys"

    Si passé, la valeur qui est ajoutée est utilisée comme argument pour l'option Sortkeys de Data::Dumper. Consultez la documentation de Data::Dumper pour savoir comment vous pouvez contrôler le comportement de Sortkeys.

  • "filename_a" et "filename_b"

    Les en-têtes de colonnes dans la sortie. Par défaut, ce sont 'Got' et 'Expected'.

STYLES DE DIFF

Pour les chaînes très longues, un diff de tableau peut devenir difficile à lire sur votre écran. Si vous êtes habitué à différents styles de diff, vous pouvez passer à un style plus adapté à vos données. Ce sont les quatre styles de diff pris en charge par le module Text::Diff et ils sont définis par les fonctions suivantes :

  • "table_diff" (par défaut)
  • "unified_diff"
  • "oldstyle_diff"
  • "context_diff"

Vous pouvez exécuter ce qui suit pour comprendre les différents styles de diff :

use Test::More 'no_plan';
use Test::Differences;
my $long_string = join '' => 1..40;
TODO: {
    local $TODO = 'Testing diff styles';
    # c'est le défaut et il n'a pas besoin d'être spécifié à moins que vous ayez besoin
    # de le réinitialiser à partir d'un autre type de diff
    table_diff;
    eq_or_diff $long_string, "-$long_string", 'table diff';
    unified_diff;
    eq_or_diff $long_string, "-$long_string", 'unified diff';
    context_diff;
    eq_or_diff $long_string, "-$long_string", 'context diff';
    oldstyle_diff;
    eq_or_diff $long_string, "-$long_string", 'oldstyle diff';
}

UNICODE

Généralement, vous trouverez que la sortie de test suivante est décevante.

use Test::Differences;
use utf8;
my $want = { 'Traditional Chinese' => '中國' };
my $have = { 'Traditional Chinese' => '中国' };
eq_or_diff $have, $want, 'Unicode, baby';

Voici ce que vous obtenez :

#   Échec du test 'Unicode, baby'
#   dans t/unicode.t à la ligne 12.
# +----+-----------------------+-----------------------+
# | Elt| Got                   | Expected              |
# +----+-----------------------+-----------------------+
# |   0|'Traditional Chinese'  |'Traditional Chinese'  |
# *   1|'\x{4e2d}\x{56fd}'     |'\x{4e2d}\x{570b}'     *
# +----+-----------------------+-----------------------+
# Looks like you failed 1 test of 1.
Dubious, test returned 1 (wstat 256, 0x100)
Failed 1/1 subtests

Un patch pour résoudre ce problème serait *le bienvenu*.

Unknown::Values

Unknown::Values est un module qui fournit des valeurs qui ne correspondent jamais à l'égalité avec quoi que ce soit, même elles-mêmes.

Si le code se concentre trop sur l'une de ces valeurs (et que Test::Differences semble trop difficile), c'est une erreur fatale. Cela signifie que même si nous pouvons détecter, le module peut ne pas détecter correctement.

Test::Differences - Perl manual page

NAME

Test::Differences - Perl module to test if two things are different

SYNOPSIS

use Test::Differences;
use Test::More tests => 2;

my $got = {
    foo => "bar",
    baz => [ 1, 2, 3 ],
};

my $expected = {
    foo => "bar",
    baz => [ 1, 2, 4 ],
};

# Use eq_or_diff to compare complex structures
eq_or_diff($got, $expected);

# Or use diff, which returns 1 on difference, 0 on equality.
# diff() is used internally by eq_or_diff().
ok(diff($got, $expected), "got and expected are different");

EXPORT

Both eq_or_diff and diff are exported by default.

DESCRIPTION

This module provides two functions for comparing complex data structures. eq_or_diff compares two values and dies with a useful diagnostic if they are not identical. diff does the same, but returns 1 if they are different, and 0 if they are the same. This allows you to use it in ok() calls.

Both functions use Data::Dumper to get string representations of the values, and then compare those strings. This is usually sufficient for testing complex data structures.

OPTIONS

You may pass options to eq_or_diff and diff that are passed directly to Data::Dumper. This allows you to control how the data structures are represented.

use Test::Differences;
use Test::More tests => 1;

my $got = {
    foo => "bar",
    baz => [ 1, 2, 3 ],
};

my $expected = {
    foo => "bar",
    baz => [ 1, 2, 3 ],
};

# Don't sort hash keys when dumping
eq_or_diff($got, $expected, { key => 'value' }, { SortKeys => 0 });

Note that the options are passed as separate arguments after the values to be compared. The first hash ref is the “got” options, the second hash ref is the “expected” options.

If you only want to set options for one side, you can pass an empty hash ref:

eq_or_diff($got, $expected, {}, { name => 'expected value' });

DIFF STYLES

When a difference is found, eq_or_diff will output a diff between the two structures. The default style is tabular.

You can change this by setting the $Test::Differences::Style variable:

BEGIN { $Test::Differences::Style = 'sidebyside'; }
use Test::Differences;

Or by passing the style as an option:

eq_or_diff($got, $expected, { Style => 'sidebyside' });

The following styles are available:

tabular
The default style, showing elements side-by-side in columns.
sidebyside
A more traditional diff-like output, showing differing lines one after another.
unified
Like sidebyside, but uses the unified diff format.
html
Outputs an HTML table diff.

UNICODE

If you are using unicode characters, you may need to tell Data::Dumper to use them. This is done by setting $Data::Dumper::Useperl => 1.

BEGIN { $Data::Dumper::Useperl = 1; }
use Test::Differences;

Or by passing the option:

eq_or_diff($got, $expected, { Useperl => 1 });

Unknown::Values

Test::Differences has experimental support for comparing objects that stringify to something other than their normal representation. This involves creating temporary objects that are blessed into Unknown::Values.

This is primarily useful when testing modules that might return objects that have overloaded stringification, or objects that don't stringify nicely.

For example, if you have a module that returns objects blessed into DateTime::TimeZone, you might want to compare them with strings.

use Test::Differences;
use Test::More tests => 1;

# Assuming you have a module that returns a DateTime::TimeZone object
# For demonstration purposes, we create one here.
package DateTime::TimeZone;
sub new { bless {}, shift }
sub DESTROY {}
sub TIESCALAR { bless {}, shift }
sub FETCH { 'UTC' }
package main;

my $tz = DateTime::TimeZone->new;

# Now compare it to a string. Without Unknown::Values, this would fail.
eq_or_diff($tz, 'UTC');

The presence of these beasties, and tell you that they compare different, for Complicated Internals Reasons we can't show you much context. Sorry.

NB that the support for these is experimental and relies on an undocumented unstable interface in Unknown::Values. If that fails then Test::Differences will probably just die when it sees them instead of telling you that the comparison failed.

LIMITATIONS

"Test" or "Test::More"

This module "mixes in" with Test.pm or any of the test libraries based on Test::Builder (Test::Simple, Test::More, etc). It does this by peeking to see whether Test.pm or Test/Builder.pm is in %INC, so if you are not using one of those, it will print a warning and play dumb by not emitting test numbers (or incrementing them). If you are using one of these, it should interoperate nicely.

Exporting

Exports all 3 functions by default (and by design). Use

use Test::Differences ();

to suppress this behavior if you don't like the namespace pollution.

This module will not override functions like ok(), is(), is_deeply(), etc. If it did, then you could "eval "use Test::Differences qw( is_deeply );"" to get automatic upgrading to diffing behaviors without the "sub my_ok" shown above. Test::Differences intentionally does not provide this behavior because this would mean that Test::Differences would need to emulate every popular test module out there, which would require far more coding and maintenance that I'm willing to do. Use the eval and my_ok deployment shown above if you want some level of automation.

Booleans

Historically, true and false (whether resulting from logical-not "!" or from equality checks like "==") were represented in perl as numeric 1 for true and the empty string '' for false. In perl 5.36.0 they became real Boolean values which for backward compatibility also have their old numeric/string values. In 5.38 (and in dev releases from 5.37.2 onwards) Data::Dumper belatedly learned about this, and so Test::Differences (which uses Data::Dumper under the bonnet) can also tell the difference.

This means that `eq_or_diff(1, !!1)` will behave differently depending on whether you are using perl 5.38 or later (in which case it will say they are different) or 5.36 or earlier (which will say they are the same).

Unicode

Perls before 5.6.0 don't support characters > 255 at all, and 5.6.0 seems broken. This means that you might get odd results using perl5.6.0 with unicode strings.

"Data::Dumper" and older Perls.

Relies on Data::Dumper (for now), which, prior to perl5.8, will not always report hashes in the same order. $Data::Dumper::Sortkeys is set to 1, so on more recent versions of Data::Dumper, this should not occur. Check CPAN to see if it's been peeled out of the main perl distribution and backported. Reported by Ilya Martynov <ilya@martynov.org>, although the Sortkeys "future perfect" workaround has been set in anticipation of a new Data::Dumper for a while. Note that the two hashes should report the same here:

not ok 5
#     Failed test (t/ctrl/05-home.t at line 51)
# +----+------------------------+----+------------------------+
# | Elt|Got                     | Elt|Expected                |
# +----+------------------------+----+------------------------+
# |   0|{                       |   0|{                       |
# |   1|  'password' => '',     |   1|  'password' => '',     |
# *   2|  'method' => 'login',  *    |                        |
# |   3|  'ctrl' => 'home',     |   2|  'ctrl' => 'home',     |
# |    |                        *   3|  'method' => 'login',  *
# |   4|  'email' => 'test'     |   4|  'email' => 'test'     |
# |   5|}                       |   5|}                       |
# +----+------------------------+----+------------------------+

Data::Dumper also overlooks the difference between

$a[0] = \$a[1];
$a[1] = \$a[0];   # $a[0] = \$a[1]

and

$x = \$y;
$y = \$x;
@a = ( $x, $y );  # $a[0] = \$y, not \$a[1]

The former involves two scalars, the latter 4: $x, $y, and @a[0,1]. This was carefully explained to me in words of two syllables or less by Yves Orton <demerphq@hotmail.com>. The plan to address this is to allow you to select Data::Denter or some other module of your choice as an option.

Code-refs

Test::Differences turns on $Data::Dumper::Deparse, so any code-refs in your data structures will be turned into text before they are examined, using B::Deparse. The precise text generated for a sub-ref might not be what you expect as it is generated from the compiled version of the code, but it should at least be consistent and spot differences correctly.

You can turn this behaviour off by setting $Test::Differences::NoDeparse.
