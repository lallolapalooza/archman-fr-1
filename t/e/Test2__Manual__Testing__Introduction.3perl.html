NOM

Test2::Manual::Testing::Introduction - Introduction aux tests avec Test2.

DESCRIPTION

Ce tutoriel est une introduction aux tests pour débutants. Il vous guidera à travers l'écriture d'un fichier de test, la formulation d'assertions et l'exécution de votre test.

BOILERPLATE

LE FICHIER DE TEST

Les fichiers de test sont généralement placés dans le répertoire "t/" et se terminent par l'extension de fichier ".t".

"t/example.t" :

use Test2::V0;
# Les assertions iront ici
done_testing;

C'est tout le boilerplate dont vous avez besoin.

use Test2::V0;
Ceci charge un ensemble d'outils de test qui seront décrits plus tard dans le tutoriel. Ceci active également "strict" et "warnings" pour vous.
done_testing;
Ceci devrait toujours se trouver à la fin de vos fichiers de test. Ceci indique à Test2 que vous avez terminé de formuler des assertions. C'est important car "test2" supposera que le test n'a pas abouti sans cela, ou une autre forme de "plan" de test.

CONFIG DIST

Vous devez toujours lister directement les bundles et les outils. Vous ne devez pas simplement lister Test2::Suite et considérer que c'est fait, les bundles et les outils peuvent être déplacés de Test2::Suite vers leurs propres distributions à tout moment.

Dist::Zilla

[Prereqs / TestRequires]
Test2::V0 = 0.000060

ExtUtils::MakeMaker

my %WriteMakefileArgs = (
  ...,
  "TEST_REQUIRES" => {
    "Test2::V0" => "0.000060"
  },
  ...
);

Module::Install

test_requires 'Test2::V0' => '0.000060';

Module::Build

my $build = Module::Build->new(
    ...,
    test_requires => {
        "Test2::V0" => "0.000060",
    },
    ...
);

FAIRE DES ASSERTIONS

L'outil le plus simple pour faire des assertions est ok(). ok() vous permet d'affirmer qu'une condition est vraie.

ok($CONDITION, "Description de la condition");

Voici un "t/example.t" complet :

use Test2::V0;
ok(1, "1 est vrai, donc cela réussira");
done_testing;

EXÉCUTER LE TEST

Les fichiers de test sont simplement des scripts. Comme tout autre script, vous pouvez exécuter le test directement avec perl. Une autre option est d'utiliser un "harness" de test qui exécute le test pour vous, fournit des informations supplémentaires et vérifie la valeur de sortie des scripts.

EXÉCUTER DIRECTEMENT

$ perl -Ilib t/example.t

Ce qui devrait produire une sortie similaire à ceci :

# Seeded srand with seed '20161028' from local date.
ok 1 - 1 est vrai, donc cela réussira
1..1

Si le test avait échoué ("ok(0, ...)"), cela ressemblerait à ceci :

# Seeded srand with seed '20161028' from local date.
not ok 1 - 0 est faux, donc cela échouera
1..1

Test2 définira également la valeur de sortie du script, une exécution réussie aura une valeur de sortie de 0, une exécution échouée aura une valeur de sortie non nulle.

UTILISER YATH

L'outil en ligne de commande "yath" est fourni par Test2::Harness, que vous devrez peut-être installer vous-même depuis cpan. "yath" est le harnais écrit spécifiquement pour Test2.

$ yath -Ilib t/example.t

Cela produira une sortie similaire à ceci :

( PASSED )  job  1    t/example.t
================================================================================
Run ID: 1508027909
All tests were successful!

Vous pouvez également demander une sortie détaillée avec le drapeau "-v" :

$ yath -Ilib -v t/example.t

Ce qui produit :

( LAUNCH )  job  1    example.t
(  NOTE  )  job  1    Seeded srand with seed '20171014' from local date.
[  PASS  ]  job  1  + 1 est vrai, donc cela réussira
[  PLAN  ]  job  1    Expected asserions: 1
( PASSED )  job  1    example.t
================================================================================
Run ID: 1508028002
All tests were successful!

UTILISER PROVE

L'outil en ligne de commande "prove" est fourni par le module Test::Harness, qui est inclus dans la plupart des versions de perl. Test::Harness est à double durée de vie, ce qui signifie que vous pouvez également installer la dernière version depuis cpan.

$ prove -Ilib t/example.t

Cela produira une sortie similaire à ceci :

example.t .. ok
All tests successful.
Files=1, Tests=1,  0 wallclock secs ( 0.01 usr  0.00 sys +  0.05 cusr  0.00 csys =  0.06 CPU)
Result: PASS

Vous pouvez également demander une sortie détaillée avec le drapeau "-v" :

$ prove -Ilib -v t/example.t

La sortie détaillée ressemble à ceci :

example.t ..
# Seeded srand with seed '20161028' from local date.
ok 1 - 1 est vrai, donc cela réussira
1..1
ok
All tests successful.
Files=1, Tests=1,  0 wallclock secs ( 0.02 usr  0.00 sys +  0.06 cusr  0.00 csys =  0.08 CPU)
Result: PASS

LE "PLAN"

Tous les tests ont besoin d'un "plan". Le travail d'un plan est de s'assurer que vous avez exécuté tous les tests que vous attendiez. Le plan empêche un résultat de succès d'un test qui se termine avant que tous les tests ne soient exécutés.

Il y a 2 façons principales de définir le plan :

done_testing()
La manière la plus courante et recommandée de définir un plan est d'ajouter "done_testing" à la fin de votre fichier de test. Ceci calculera automatiquement le plan pour vous à la fin du test. Si le test se terminait prématurément, "done_testing" ne s'exécuterait pas et aucun plan ne serait trouvé, forçant un échec.
plan($COUNT)
La fonction plan() vous permet de spécifier un nombre exact d'assertions que vous souhaitez exécuter. Si vous exécutez trop ou trop peu d'assertions, le plan ne correspondra pas et sera compté comme un échec. Le principal problème avec cette façon de planifier est que vous devez additionner le nombre d'assertions et ajuster le compte chaque fois que vous mettez à jour le fichier de test.

plan() doit être utilisé avant toutes les assertions, ou après toutes les assertions, il ne peut pas être fait au milieu de la formulation d'assertions.

OUTILS D'ASSERTION SUPPLÉMENTAIRES

Le bundle Test2::V0 fournit bien plus que ok(), plan() et done_testing(). Les outils les plus importants à noter sont :

is($a, $b, $description)
is() vous permet de comparer 2 structures et de vous assurer qu'elles sont identiques. Vous pouvez l'utiliser pour des comparaisons de chaînes simples, ou même des comparaisons de structures de données profondes. 
is("foo", "foo", "Les deux chaînes sont identiques");
is(["foo", 1], ["foo", 1], "Les deux tableaux contiennent les mêmes éléments");
like($a, $b, $description)
like() est similaire à is() sauf qu'il ne vérifie que les éléments listés à droite, il ignore les valeurs supplémentaires trouvées à gauche.

NOM

Test2::Manual - Introduction au manuel.

DESCRIPTION

Test2::Manual est un outil permettant de vérifier et de générer la documentation du code en utilisant des règles de style et de structure. L'outil permet de créer et d'exécuter des tests de qualité en temps réel, basés sur des règles de style et de structure, afin de garantir que le code respecte les normes de qualité.

BOILERPLATE

Test2::Manual comprend un ensemble de règles et de structures de code qui peuvent être appliquées à n'importe quel projet. Ces règles permettent de générer le code de manière cohérente et standard, garantissant ainsi que le code est lisible et maintenable.

FAIRE DES ASSERTIONS

Test2::Manual permet de générer automatiquement des assertions dans le code, en se basant sur des règles de style et de structure. Cela contribue à garantir que le code respecte les normes de qualité et qu'il peut être maintenu de manière cohérente.

EXÉCUTER LE TEST

Test2::Manual permet d'exécuter des tests de qualité en temps réel, basés sur des règles de style et de structure. Cela contribue à garantir que le code respecte les normes de qualité et qu'il peut être maintenu de manière cohérente.

LE "PLAN"

Test2::Manual suit un plan de développement basé sur des règles de style et de structure. Ce plan garantit que le code est généré de manière cohérente et standard, assurant ainsi que le code est lisible et maintenable.

OUTILS D'ASSERTION SUPPLÉMENTAIRES
