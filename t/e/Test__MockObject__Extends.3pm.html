Test::MockObject::Extends(3) Documentation Perl fournie par l'utilisateur Test::MockObject::Extends(3)

NOM

Test::MockObject::Extends - simuler une partie d'un objet ou d'une classe

SYNOPIS

use Some::Class;
use Test::MockObject::Extends;
# créer un objet à simuler
my $object      = Some::Class->new();
# encapsuler cet objet avec un wrapper de simulation
$object         = Test::MockObject::Extends->new( $object );
# ensuite, chaîner les simulations et contrôler les appels
$object->set_true( 'parent_method' )
       ->set_always( -grandparent_method => 1 )
       ->clear();

DESCRIPTION

Test::MockObject::Extends vous permet de simuler une ou plusieurs méthodes d'un objet ou d'une classe existante. Cela peut être très utile lorsque vous testez un module bien architecturé qui fait presque exactement ce que vous voulez. Ne serait-il pas pratique de prendre le contrôle d'une ou deux méthodes pour vous assurer d'obtenir des résultats testables ? Maintenant, vous le pouvez.

MÉTHODES

"new( $object | $class )"
new() prend un argument optionnel, l'objet ou la classe à simuler. Si vous simulez une méthode pour un objet qui contient un état interne, créez un objet approprié, puis passez-le à ce constructeur. NOTE : cela modifiera l'objet sur place.

Si vous simulez un objet qui n'a pas besoin d'état, comme dans les cas où il n'y a pas de données internes ou si vous n'appellerez que des méthodes de classe, ou si vous simulez tout accès aux données internes, vous pouvez passer le nom de la classe à simuler partiellement.

Si vous n'avez pas encore chargé la classe, cette méthode tentera de la charger pour vous. Cela peut échouer, alors soyez prudent.

Si vous ne passez aucun argument, elle supposera que vous vouliez réellement créer un objet "Test::MockObject" normal et s'y conformera.

Notez que si vous passez une classe, l'objet retourné apparaîtra comme une instance de cette classe ; cela ne simule pas la classe elle-même.

"mock( $methodname, $sub_ref )"
Consultez la documentation de Test::MockObject pour toutes les façons de simuler des méthodes et de récupérer des informations de journalisation des méthodes. Ces méthodes retournent l'invocant, vous pouvez donc les chaîner.
unmock( $methodname )
Supprime toute simulation active de la méthode nommée. Cela signifie que tous les appels à cette méthode atteindront la méthode de ce nom dans la classe simulée, si elle existe. Cette méthode retourne l'invocant, vous pouvez la chaîner.
isa( $class )
Comme vous vous y attendez d'un objet simulé, cela retournera vrai pour la classe qu'il simule.

MÉTHODES INTERNES

Pour faire sa magie, ce module utilise plusieurs méthodes internes :

  • check_class_loaded( $parent_class )

    Cela vérifie que vous avez défini la classe simulée. Sinon, il tente de charger le module correspondant pour vous.

  • gen_autoload( $extended )

    Retourne une sous-routine AUTOLOAD pour l'objet simulé qui vérifie que l'objet (ou la classe) étendu peut exécuter la méthode demandée, que Test::MockObject peut l'exécuter, ou que le parent a sa propre AUTOLOAD appropriée. (Il devrait avoir son propre can() dans ce cas également.)

  • gen_can( $extended )

    Retourne une méthode can() pour l'objet simulé qui respecte le même ordre d'exécution que gen_autoload().

  • gen_isa( $extended )

    Retourne une méthode isa() pour l'objet simulé qui prétend être l'objet $extended de manière appropriée.

  • gen_get_parents( $extended )

    Retourne une méthode "__get_parents()" pour l'objet simulé qui prétend être l'objet $extended de manière appropriée.

  • gen_package( $extended )

    Crée un nouveau paquet unique pour l'objet simulé avec les méthodes appropriées déjà installées.

  • get_class( $invocant )

    Retourne le nom de la classe de l'invocant, qu'il s'agisse d'un objet ou d'un nom de classe.

AVERTISSEMENTS

Il peut y avoir des cas limites étranges avec les méthodes générées dynamiquement dans la classe simulée. Vous devriez vraiment utiliser des déclarations de sous-routine, ou au moins définir can() de manière appropriée.

Il y a également des collisions de noms potentielles avec les méthodes de ce module ou de "Test::MockObject", bien que cela devrait être rare.
