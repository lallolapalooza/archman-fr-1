Test2::Manual::Tooling::FirstTool(3perl) Guide du programmeur Perl Test2::Manual::Tooling::FirstTool(3perl)

NOM

Test2::Manual::Tooling::FirstTool - Écrivez votre premier outil avec Test2.

DESCRIPTION

Ce tutoriel vous aidera à écrire votre tout premier outil en clonant l'outil ok().

CODE COMPLET AVANT TOUT

package Test2::Tools::MyOk;
use strict;
use warnings;
use Test2::API qw/context/;
use base 'Exporter';
our @EXPORT = qw/ok/;
sub ok($;$@) {
    my ($bool, $name, @diag) = @_;
    my $ctx = context();
    return $ctx->pass_and_release($name) if $bool;
    return $ctx->fail_and_release($name, @diag);
}
1;

LIGNE PAR LIGNE

sub ok($;$@) {
Dans ce cas, nous émulerons la fonction ok() exportée par Test2::Tools::Basic.

ok() et les outils de test similaires utilisent des prototypes pour forcer l'analyse des arguments. Vos outils de test n'ont pas nécessairement besoin de prototypes ; comme pour toute fonction perl, vous devez prendre la décision en fonction de la manière dont elle est utilisée.

Le prototype exige au moins 1 argument, qui sera forcé dans un contexte scalaire. Le deuxième argument est optionnel et est également forcé à être scalaire ; il s'agit du nom du test. Tous les arguments restants sont traités comme des messages de diagnostic qui ne seront utilisés que si le test échoue.

my ($bool, $name, @diag) = @_;
Cette ligne ne nécessite pas beaucoup d'explications ; nous récupérons simplement les arguments.
my $ctx = context();
Ceci est une ligne essentielle dans TOUS les outils. L'objet contexte est l'API principale pour les outils de test. Vous DEVEZ obtenir un contexte si vous voulez émettre des événements, tels que des assertions. De plus, le contexte est responsable de s'assurer que les échecs sont attribués au bon fichier et au bon numéro de ligne.

Remarque : Une fonction de test DOIT toujours libérer le contexte lorsqu'elle a terminé ; vous ne pouvez pas simplement la laisser sortir de la portée et être collectée par le garbage collector. Test2 fait un assez bon travail pour vous crier dessus si vous faites cette erreur.

Remarque : Vous NE DEVEZ JAMAIS stocker ou transmettre un objet contexte réel. Si vous souhaitez conserver un contexte pour une raison quelconque, vous devez utiliser `clone` pour en faire une copie "my $copy = $ctx->clone". La copie peut être transmise ou stockée, mais l'original DOIT être libéré lorsque vous avez terminé avec elle.

return $ctx->pass_and_release($name) if $bool;
Lorsque $bool est vrai, cette ligne utilise l'objet contexte pour émettre un événement Test2::Event::Pass. En plus d'émettre l'événement, cela libérera également l'objet contexte et retournera vrai.

Ceci est une forme abrégée de :

if($bool) {
    $ctx->pass($name);
    $ctx->release;
    return 1;
}
return $ctx->fail_and_release($name, @diag);
Cette ligne émet un événement Test2::Event::Fail, libère l'objet contexte et retourne faux. L'événement d'échec inclura tous les messages de diagnostic du tableau @diag.

Ceci est une forme abrégée de :

$ctx->fail($name, @diag);
$ctx->release;
return 0;

DOCUMENTATION OBJET CONTEXTE

Test2::API::Context est l'endroit où lire les méthodes fournies par le contexte.
