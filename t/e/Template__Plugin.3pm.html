NOM

Template::Plugin - Classe de base pour les plugins Template Toolkit

SYNOPIS

package MyOrg::Template::Plugin::MyPlugin;
use base qw( Template::Plugin );
use Template::Plugin;
use MyModule;
sub new {
    my $class   = shift;
    my $context = shift;
    bless {
        ...
    }, $class;
}

DESCRIPTION

Un « plugin » pour Template Toolkit est simplement un module Perl qui existe dans un emplacement de package connu (par exemple, "Template::Plugin::*") et qui se conforme à une norme régulière, lui permettant d'être chargé et utilisé automatiquement.

Le module "Template::Plugin" définit une classe de base à partir de laquelle d'autres modules de plugin peuvent être dérivés. Un plugin n'a pas besoin d'être dérivé de Template::Plugin, mais devrait au moins se conformer à son interface orientée objet.

Il est recommandé de créer des plugins dans votre propre espace de noms de packages pour éviter les conflits avec les plugins de la boîte à outils. Par exemple :

package MyOrg::Template::Plugin::FooBar;

Utilisez l'option PLUGIN_BASE pour spécifier l'espace de noms que vous utilisez. Par exemple :

use Template;
my $template = Template->new({
    PLUGIN_BASE => 'MyOrg::Template::Plugin',
});

MÉTHODES

Les méthodes suivantes forment l'interface de base entre Template Toolkit et les modules de plugin.

load($context)

Cette méthode est appelée par Template Toolkit lors du premier chargement du module plugin. Elle est appelée en tant que méthode de package et reçoit donc implicitement le nom du package comme premier paramètre. Une référence à l'objet Template::Context qui charge le plugin est également passée. Le comportement par défaut de la méthode load() est de simplement retourner le nom de la classe. Le contexte appelant utilise alors ce nom de classe pour appeler la méthode de package new().

package MyPlugin;
sub load {               # appelée comme MyPlugin->load($context)
    my ($class, $context) = @_;
    return $class;       # retourne 'MyPlugin'
}

new($context, @params)

Cette méthode est appelée pour instancier un nouvel objet plugin pour la directive "USE". Elle est appelée en tant que méthode de package contre le nom de classe retourné par load(). Une référence à l'objet Template::Context créant le plugin est passée, ainsi que tous les paramètres supplémentaires spécifiés dans la directive "USE".

sub new {                # appelée comme MyPlugin->new($context)
    my ($class, $context, @params) = @_;
    bless {
        _CONTEXT => $context,
    }, $class;           # retourne un objet MyPlugin béni
}

error($error)

Cette méthode, héritée du module Template::Base, est utilisée pour signaler et retourner des erreurs. Elle peut être appelée en tant que méthode de package pour définir/retourner la variable de package $ERROR, ou en tant que méthode d'objet pour définir/retourner le membre d'objet "_ERROR". Lorsqu'elle est appelée avec un argument, elle définit la variable pertinente et retourne "undef.". Lorsqu'elle est appelée sans argument, elle retourne la valeur de la variable.

package MyPlugin;
use base 'Template::Plugin';
sub new {
    my ($class, $context, $dsn) = @_;
    return $class->error('No data source specified')
        unless $dsn;
    bless {
        _DSN => $dsn,
    }, $class;
}
package main;
my $something = MyPlugin->new()
    || die MyPlugin->error(), "\n";
$something->do_something()
    || die $something->error(), "\n";

MAGIE PLUS PROFONDE

L'objet Template::Context qui gère le chargement et l'utilisation des plugins appelle les méthodes new() et error() contre le nom de package retourné par la méthode load(). En pseudo-code, cela ressemble à ceci :

$class  = MyPlugin->load($context);       # retourne 'MyPlugin'
$object = $class->new($context, @params)  # MyPlugin->new(...)
    || die $class->error();               # MyPlugin->error()

La méthode load() peut alternativement retourner une référence bénie à une instance d'objet. Dans ce cas, new() et error() sont alors appelées en tant que méthodes d'objet contre cette instance prototype.

package YourPlugin;
sub load {
    my ($class, $context) = @_;
    bless {
        _CONTEXT => $context,
    }, $class;
}
sub new {
    my ($self, $context, @params) = @_;
    return $self;
}

Dans cet exemple, nous avons implémenté un plugin « Singleton ». Un objet est créé lorsque load() est appelée et celui-ci se retourne lui-même pour chaque appel à new().

Une autre implémentation pourrait nécessiter la création d'objets individuels pour chaque appel à new(), mais chaque objet partagerait une référence vers un autre objet pour conserver des données mises en cache, des handles de base de données, etc. Cet exemple en pseudo-code démontre le principe.

package MyServer;
sub load {
    my ($class, $context) = @_;
    bless {
        _CONTEXT => $context,
        _CACHE   => { },
    }, $class;
}
sub new {
    my ($self, $context, @params) = @_;
    MyClient->new($self, @params);
}
sub add_to_cache   { ... }
sub get_from_cache { ... }
package MyClient;
sub new {
    my ($class, $server, $blah) = @_;
    bless {
        _SERVER => $server,
        _BLAH   => $blah,
    }, $class;
}
sub get {
    my $self = shift;
    $self->{ _SERVER }->get_from_cache(@_);
}
sub put {
    my $self = shift;
    $self->{ _SERVER }->add_to_cache(@_);
}

Lorsque le plugin est chargé, une instance "MyServer" est créée. La méthode new() est appelée sur cet objet, ce qui crée et retourne un objet "MyClient", prêt à communiquer avec le "MyServer" créateur.
