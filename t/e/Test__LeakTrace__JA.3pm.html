NOM

Test::LeakTrace::JA - Trace les fuites de mémoire

VERSION

Ce document décrit la version 0.17 de Test::LeakTrace.

SYNOPSIS

use Test::LeakTrace;
# rapport simple
leaktrace{
        # ...
};
# sortie verbeuse
leaktrace{
        # ...
} -verbose;
# avec un rappel
leaktrace{
        # ...
} sub {
        my($ref, $file, $line) = @_;
        warn "fuite de $ref depuis $file ligne\n";
};
my @refs = leaked_refs{
        # ...
};
my @info = leaked_info{
        # ...
};
my $count = leaked_count{
        # ...
};
# interface de test standard
use Test::LeakTrace;
no_leaks_ok{
        # ...
} "description";
leaks_cmp_ok{
        # ...
} '<', 10;

DESCRIPTION

Le GC de Perl utilise un compteur de références, ce qui fait que le moment de libération des objets est moins évident, et il y a donc de nombreux avantages. Étant donné que le problème principal est la gestion de la mémoire, le traçage des fuites de mémoire est un problème très important.

"Test::LeakTrce" fournit plusieurs utilitaires pour traquer les fuites de mémoire et des fonctions de test basées sur "Test::Builder". Ce module est un système de gestion de la mémoire Perl

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Interface de script

"Test::LeakTrace::Script" est fourni pour le suivi des fuites de mémoire des scripts, tout comme "Devel::LeakTrace". Les arguments de la déclaration "use Test::LeakTrace::Script" sont les mêmes que pour leaktrace().

$ TEST_LEAKTRACE=-sv_dump perl -MTest::LeakTrace::Script script.pl
$ perl -MTest::LeakTrace::Script=-verbose script.pl
#!perl
# ...
use Test::LeakTrace::Script sub{
        my($ref, $file, $line) = @_;
        # ...
};
# ...

Test::LeakTrace — Mémoire de fuite testeur pour Perl

NOM

Test::LeakTrace - Testeur de fuite mémoire pour Perl

VERSION

0.17

SYNOPSIS

    use strict;
    use warnings;
    use Test::More tests => 2;
    use Test::LeakTrace;

    # Créer des fuites
    my $foo = [];
    push @$foo, [1, 2];
    push @$foo, { a => 1 };
    # ... etc.

    # Ne pas créer de fuites
    no_leaks_ok {
        my $bar = { name => "test" };
        # Faire quelque chose sans fuites...
    } "Test de bloc sans fuite";

    # Vérifier les fuites
    my $leaks = leaked_count();
    ok( $leaks == 0, "Aucune fuite mémoire attendue" );

DESCRIPTION

Ce module fournit un moyen de tester les fuites mémoire dans les programmes Perl.

Il intercepte les allocations et désallocations mémoire du runtime Perl et vous permet de vérifier qu'aucune mémoire allouée n'est laissée sans être libérée.

INTERFACE

no_leaks_ok
Prend un bloc de code et vérifie qu'il ne crée aucune fuite mémoire. Si des fuites sont détectées, le test échoue.
leaked_count
Retourne le nombre actuel d'objets Perl (SV) qui sont considérés comme fuyants. Un objet est considéré comme fuyant s'il a été alloué mais n'a pas été correctement désalloué avant la fin du test.
leaktrace
Prend un bloc de code et, si des fuites sont détectées après son exécution, elle tente de fournir des informations détaillées sur l'emplacement de la fuite, y compris la pile d'appels au moment de l'allocation. Cela peut être très utile pour diagnostiquer les causes profondes des fuites.

EXAMPLES

Le synopsis montre un exemple d'utilisation de base. Les exemples plus avancés, y compris l'utilisation de leaktrace() pour localiser les fuites, peuvent être trouvés dans la documentation du module.

GUTS

Le mécanisme de suivi des fuites mémoire ne surcharge pas nécessairement le comportement standard comme on pourrait s'y attendre avec make_destructor ou sweep. Cependant, en raison de la nature de Perl, des fuites peuvent se produire dans de nombreuses situations. Le module peut fonctionner dans de nombreux environnements car il n'est pas nécessaire de compiler Perl dans des conditions spéciales, et les fonctionnalités dépendantes de la version sont minimisées.

De plus, les fonctions de test comme no_leaks_ok() obtiennent le nombre de fuites actuelles à partir de leaked_count(), puis exécutent leaktrace() pour identifier spécifiquement les emplacements des fuites, afin de pouvoir les localiser avec précision dans la mesure où le test réussit.

DEPENDENCIES

Perl 5.8.1 ou version ultérieure, et un compilateur C.

CAVEATS

"Test::LeakTrace" ne peut pas fonctionner avec "Devel::Cover". Cependant, il est connu que "Devel::Cover" indique que les fonctions de test ne font rien, donc les tests seront automatiquement considérés comme réussis.
