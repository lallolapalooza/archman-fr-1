Test2::Hub(3perl) Manuel pour les développeurs Perl Test2::Hub(3perl)

NAME

Test2::Hub - Le pont par lequel tous les événements circulent.

SYNOPSIS

use Test2::Hub;
my $hub = Test2::Hub->new();
$hub->send(...);

DESCRIPTION

Le pont est l'endroit où tous les événements sont traités et transmis au formateur. Le pont enregistre également l'état des tests et offre divers points d'accroche dans le pipeline d'événements.

TACHES COURANTES

ENVOYER DES ÉVÉNEMENTS

$hub->send($event)

La méthode send() est utilisée pour envoyer un événement au pont. Cette méthode gérera la synchronisation des threads/forks, les filtres, les écouteurs, la sortie TAP, etc.

MODIFIER OU SUPPRIMER DES ÉVÉNEMENTS

Vous pouvez utiliser soit filter(), soit pre_filter(), selon vos besoins. Les deux ont la même syntaxe, donc seul filter() est montré ici.

$hub->filter(sub {
    my ($hub, $event) = @_;
    my $action = get_action($event);
    # Aucune action à entreprendre
    return $event if $action eq 'none';
    # Vous voulez que le filtre supprime l'événement
    return undef if $action eq 'delete';
    if ($action eq 'do_it') {
        my $new_event = copy_event($event);
        ... Changez votre copie de l'événement ...
        return $new_event;
    }
    die "Cela ne devrait pas arriver";
});

Par défaut, les filtres ne sont pas hérités par les hubs enfants. Cela signifie que si vous démarrez un sous-test, le sous-test n'héritera pas du filtre. Vous pouvez changer ce comportement avec le paramètre "inherit" :

$hub->filter(sub { ... }, inherit => 1);

ÉCOUTER LES ÉVÉNEMENTS

$hub->listen(sub {
    my ($hub, $event, $number) = @_;
    ... faites ce que vous voulez avec l'événement ...
    # le retour est ignoré
});

Par défaut, les écouteurs ne sont pas hérités par les hubs enfants comme les sous-tests. Cela signifie que si vous démarrez un sous-test, le sous-test n'héritera pas de l'écouteur. Vous pouvez changer ce comportement avec le paramètre "inherit" :

$hub->listen(sub { ... }, inherit => 1);

COMPORTEMENTS POST-TEST

$hub->follow_up(sub {
    my ($trace, $hub) = @_;
    ... faites ce que vous voulez ...
    # le retour est ignoré
});

Les sous-routines de suivi ne sont appelées qu'une seule fois, soit lorsque done_testing est appelé, soit dans un bloc END.

CONFIGURER LE FORMATEUR

Par défaut, une instance de Test2::Formatter::TAP est créée et utilisée.

my $old = $hub->format(My::Formatter->new);

Changer le formateur remplacera tout formateur existant. Vous pouvez définir le formateur sur undef pour éviter toute sortie. L'ancien formateur sera renvoyé s'il était précédemment défini. Un seul formateur est autorisé à la fois.

MÉTHODES

$hub->send($event)
C'est là que tous les événements entrent dans le hub pour traitement.
$hub->process($event)
Ceci est appelé après que send ait géré tout IPC. Vous pouvez l'utiliser pour éviter le traitement IPC, mais en général, vous devriez éviter de l'utiliser.
$old = $hub->format($formatter)
Remplace l'instance de formateur actuelle par une nouvelle. Les formateurs doivent être des objets qui implémentent une méthode "$formatter->write($event)".
$sub = $hub->listen(sub { ... }, %optional_params)
Vous pouvez l'utiliser pour enregistrer tous les événements après qu'ils aient été envoyés au formateur. Aucun changement ne sera effectué ici, sauf éventuellement pour d'autres écouteurs. 
$hub->listen(sub {
    my ($hub, $event, $number) = @_;
    ... faites ce que vous voulez avec l'événement ...
    # le retour est ignoré
});

Par défaut, les écouteurs ne sont pas hérités par les hubs enfants comme les sous-tests. Vous pouvez ajouter le paramètre "inherit => 1" pour qu'un écouteur soit hérité.

$hub->unlisten($sub)
Vous pouvez l'utiliser pour supprimer un rappel d'écoute. Vous devez passer le rappel renvoyé par la méthode listen().
$sub = $hub->filter(sub { ... }, %optional_params)
$sub = $hub->pre_filter(sub { ... }, %optional_params)
Ceux-ci peuvent être utilisés pour ajouter des filtres. Les filtres peuvent modifier, remplacer ou supprimer des événements avant que d'autres ne les voient. 
$hub->filter(
    sub {
        my ($hub, $event) = @_;
        return $event;    # Pas de changement
        return;           // Supprime l'événement
        // Ou vous pouvez modifier un événement avant de le retourner.
        $event->modify;
        return $event;
    }
);

Si vous n'utilisez pas de threads, de forks ou d'IPC, la seule différence entre un filtre et un pré-filtre est que les pré-filtres s'exécutent en premier. Lorsque vous utilisez des threads, des forks ou de l'IPC, les pré-filtres s'exécutent avant que les événements ne soient envoyés à leur processus/thread de destination, tandis que les filtres ne s'exécutent que dans le hub/thread de destination.

Vous ne pouvez pas ajouter un filtre régulier à un hub s'il a été créé dans un autre processus ou thread. Vous pouvez toujours ajouter un pré-filtre.

$hub->unfilter($sub)
$hub->pre_unfilter($sub)
Ceux-ci peuvent être utilisés pour supprimer les filtres et les pré-filtres. L'argument $sub est le rappel renvoyé par la méthode filter() ou pre_filter().
$hub->follow_op(sub { ... })
Utilisez ceci pour ajouter des comportements qui sont appelés juste avant que le hub ne soit finalisé. Le seul argument du code de bloc sera un objet Test2::EventFacet::Trace. 
$hub->follow_up(sub {
    my ($trace, $hub) = @_;
    ... faites ce que vous voulez ...
    // le retour est ignoré
});

Les sous-routines de suivi ne sont appelées qu'une seule fois, soit lorsque done_testing est appelé, soit dans un bloc END.

$sub = $hub->add_context_acquire(sub { ... });
Ajoute un rappel qui est appelé chaque fois que quelqu'un essaie d'acquérir un contexte. Il reçoit un argument unique, une référence aux paramètres utilisés pour construire le contexte. C'est votre chance de modifier les paramètres en modifiant directement le hash. 
test2_add_callback_context_acquire(sub {
    my $params = shift;
    $params->{level}++;
});

Ceci est une API très délicate. Ne l'utilisez pas sauf si vous devez le faire. Elle est là pour Test::Builder et la compatibilité ascendante. Elle vous demande de modifier le hash au lieu de renvoyer un nouveau, pour des raisons de performance.

Note L'utilisation de ce hook peut avoir un impact majeur sur les performances.

Le coderef que vous fournissez est renvoyé et peut être utilisé pour supprimer le hook plus tard.

$hub->remove_context_acquire($sub);
Vous pouvez l'utiliser pour supprimer un hook d'acquisition de contexte.
$sub = $hub->add_context_init(sub { ... });
Permet d'ajouter des rappels qui s'exécutent chaque fois qu'un nouveau contexte est créé pour le hub. Le seul argument de la sous-routine sera l'objet Test2::API::Context qui a été créé.

Note L'utilisation de ce hook peut avoir un impact majeur sur les performances.

Le coderef que vous fournissez est renvoyé et peut être utilisé pour supprimer le hook plus tard.

$hub->remove_context_init($sub);
Vous pouvez l'utiliser pour supprimer un hook d'initialisation de contexte.
$sub = $hub->add_context_release(sub { ... });
Permet d'ajouter des rappels qui s'exécutent chaque fois que le contexte de ce hub est libéré. Le seul argument de la sous-routine sera l'objet Test2::API::Context qui a été libéré. Ceux-ci s'exécutent dans l'ordre inverse.

Note L'utilisation de ce hook peut avoir un impact majeur sur les performances.

Le coderef que vous fournissez est renvoyé et peut être utilisé pour supprimer le hook plus tard.

$hub->remove_context_release($sub);
Vous pouvez l'utiliser pour supprimer un hook de libération de contexte.
$hub->cull()
Évacuer tous les événements IPC (et les traiter).
$pid = $hub->pid()

>Obtenir l'identifiant du processus sous lequel le hub a été créé.
$tid = $hub->tid()
Obtenir l'identifiant du thread sous lequel le hub a été créé.
$hud = $hub->hid()
Obtenir la chaîne d'identifiant du hub.
$uuid = $hub->uuid()
Si le marquage UUID est activé (voir Test2::API), le hub aura un UUID.
$ipc = $hub->ipc()
Obtenir l'objet IPC utilisé par le hub.
$hub->set_no_ending($bool)
$bool = $hub->no_ending
Ceci peut être utilisé pour désactiver le comportement de fin automatique pour un hub. Le comportement de fin automatique est déclenché par un bloc de fin et est utilisé pour écarter les événements IPC, et afficher le plan final si le plan était 'NO PLAN'.
$bool = $hub->active
$hub->set_active($bool)
Ceux-ci sont utilisés pour obtenir/définir l'attribut 'actif'. Lorsque cette valeur est vraie, cet attribut forceront "hub->finalize()" à agir même s'il n'y a pas de plan, et aucun test n'a été exécuté. Ce drapeau est utile pour les plugins qui ajoutent des comportements de suivi qui doivent s'exécuter même si aucun événement n'est vu.

METHODES DETAT

$hub->reset_state()
Réinitialiser tout l'état au début. Cela met le nombre de tests à 0, efface le plan, supprime les échecs, etc.
$num = $hub->count
Obtenir le nombre de tests qui ont été exécutés.
$num = $hub->failed
Obtenir le nombre d'échecs (Tous les échecs ne proviennent pas d'un échec de test, donc ce nombre peut être supérieur au compte).
$bool = $hub->ended
Vrai si les tests sont terminés. Ceci PEUT retourner le cadre de pile de l'outil qui a terminé le test, mais ce n'est pas garanti.
$bool = $hub->is_passing
$hub->is_passing($bool)
Vérifier si l'exécution globale des tests est un échec. Peut également être utilisé pour définir le statut de succès/échec.
$hub->plan($plan)
$plan = $hub->plan
Obtenir ou définir le plan. Le plan doit être un entier supérieur à 0, la chaîne 'NO PLAN', ou la chaîne 'SKIP'.
$bool = $hub->check_plan
Vérifier si le plan et les comptes correspondent, mais seulement si les tests ont été terminés. Si les tests n'ont pas été terminés, cela retournera undef, sinon ce sera un vrai/faux.

METADONNEES TIERS

Cet objet consomme Test2::Util::ExternalMeta qui fournit un moyen cohérent pour vous de joindre des métadonnées aux instances de cette classe. Ceci est utile pour les outils, les plugins et autres extensions.
