Text::Balanced(3perl) Manuel du programmeur Perl Text::Balanced(3perl)

NAME

Text::Balanced - Extraire des séquences de texte délimitées à partir de chaînes.

SYNOPSIS

use Text::Balanced qw (
    extract_delimited
    extract_bracketed
    extract_quotelike
    extract_codeblock
    extract_variable
    extract_tagged
    extract_multiple
    gen_delimited_pat
    gen_extract_tagged
);
# Extraire la partie initiale du texte $text qui est délimitée par deux (non échappées) occurrences du premier caractère dans $delim.
($extracted, $remainder) = extract_delimited($text,$delim);
# Extraire la partie initiale du texte $text qui est délimitée par un ou plusieurs délimiteurs spécifiés par $delim (où la chaîne $delim contient un ou plusieurs de '(){}[]<>').
($extracted, $remainder) = extract_bracketed($text,$delim);
# Extraire la partie initiale du texte $text qui est un bloc de code Perl, délimité par n'importe lequel des caractères spécifiés par $delim (où la chaîne $delim contient un ou plusieurs de '(){}[]<>').
($extracted, $remainder) = extract_codeblock($text,$delim);
# Extraire la partie initiale du texte $text qui est un bloc Perl, délimité par une paire BEGIN...END.
($extracted, $remainder) = extract_tagged($text,"BEGIN","END",undef,{bad=>["BEGIN"]});
# Extraire la partie initiale du texte $text qui représente un opérateur de type "citation" ou similaire en Perl.
($extracted, $remainder) = extract_quotelike($text);
# Extraire les sous-chaînes initiales du texte $text qui seraient extraites par une ou plusieurs applications séquentielles des fonctions ou expressions spécifiées.
@extracted = extract_multiple($text,
                              [ \&extract_bracketed,
                                \&extract_quotelike,
                                \&some_other_extractor_sub,
                                qr/[xyz]*/,
                                'literal',
                              ]);
# Générer une chaîne représentant un motif optimisé (similaire à Friedl) qui correspond à une sous-chaîne délimitée par n'importe lequel des caractères spécifiés (ici : n'importe quel type de guillemets ou de backtick).
$patstring = gen_delimited_pat(q{'"`/});
# Générer une référence à une sous-routine anonyme qui est presque identique à extract_tagged, mais précompilée et optimisée pour une paire spécifique de balises, ce qui la rend très rapide (par exemple, 3 fois plus rapide). Utilise qr// pour une meilleure performance lors d'appels répétés.
$extract_head = gen_extract_tagged('<HEAD>','</HEAD>');
($extracted, $remainder) = $extract_head->($text);

DESCRIPTION

Les diverses sous-routines "extract_..." peuvent être utilisées pour extraire une sous-chaîne délimitée, éventuellement après avoir sauté un préfixe spécifié. Par défaut, ce préfixe est optionnel ( "/\s*/" ), mais vous pouvez le changer à votre guise (voir ci-dessous).

La sous-chaîne à extraire doit apparaître à la position actuelle de la chaîne (ou à l'index 0, s'il n'y a pas de position "pos" définie). En d'autres termes, les sous-routines "extract_..." *n'extraient pas* la première occurrence d'une sous-chaîne dans une chaîne entière (comme une expression régulière non ancrée). Au lieu de cela, elles extraient une occurrence de la sous-chaîne qui apparaît immédiatement à la position de correspondance actuelle dans la chaîne (comme une expression régulière ancrée \G).

Comportement général dans les contextes de liste

Dans un contexte de liste, toutes les sous-routines renvoient un tableau, dont les trois premiers éléments sont toujours :

[0]
La sous-chaîne extraite, y compris les délimiteurs spécifiés. Si l'extraction échoue, "undef" est renvoyé.
[1]
Le reste de la chaîne (c'est-à-dire les caractères après la sous-chaîne extraite). En cas d'échec, la chaîne entière est renvoyée.
[2]
Le préfixe sauté (c'est-à-dire les caractères avant la sous-chaîne extraite). En cas d'échec, "undef" est renvoyé.

Note : Dans un contexte de liste, le contenu du texte d'origine (le premier argument) n'est modifié en aucun sens.

Cependant, si le texte a été passé dans une variable, la valeur de "pos" de cette variable est mise à jour pour pointer vers le premier caractère après la sous-chaîne extraite. Cela signifie que dans un contexte de liste, les sous-routines peuvent être utilisées de manière similaire aux expressions régulières. Par exemple :

while ( $next = (extract_quotelike($text))[0] )
{
    # traiter le segment suivant (dans $next)
}

Comportement général dans les contextes scalaire et vide

Dans un contexte scalaire, la sous-chaîne extraite est renvoyée, sans être modifiée dans le texte d'origine. Ainsi, le code suivant traite également chaque segment de type "citation" (dans $text), mais le supprime réellement.

while ( $next = extract_quotelike($text) )
{
    # traiter le segment suivant (dans $next)
}

Note : Si le texte est une chaîne immuable (c'est-à-dire un littéral), aucune tentative n'est faite pour supprimer la sous-chaîne extraite.

Dans un contexte vide, le comportement des sous-routines d'extraction est exactement le même que dans un contexte scalaire, sauf que la sous-chaîne extraite n'est pas renvoyée.

Note sur les préfixes

Les motifs de préfixe sont mis en correspondance sans modificateurs ultérieurs ("/gimsox", etc.). Cela peut être dangereux si vous attendez un préfixe tel que '.*?(?=<H1>)' pour sauter tout jusqu'à la première balise <H1>. De tels motifs de préfixe ne réussiront que si la balise <H1> se trouve sur la ligne actuelle, car le point ne correspond normalement pas aux nouvelles lignes.

Pour contourner cette limitation, vous devez activer le module de correspondance /s dans le motif de préfixe, en utilisant la directive "(?s)" : '(?s).*?(?=<H1>)'

Fonctions

"extract_delimited"
La sous-routine "extract_delimited" formalise le langage courant d'extraction d'une sous-chaîne délimitée par un seul caractère depuis le début d'une chaîne. Par exemple, pour extraire une sous-chaîne délimitée par des guillemets, le code suivant est typiquement utilisé : 
($remainder = $text) =~ s/\A('(\\.|[^'])*')//s;
$extracted = $1;

mais avec "extract_delimited", cela peut être simplifié en :

($extracted,$remainder) = extract_delimited($text, q{'});

La sous-routine "extract_delimited" prend jusqu'à quatre scalaires (le texte d'entrée, les délimiteurs, un motif de préfixe à sauter et tout caractère d'échappement) et extrait la sous-chaîne initiale du texte qui est correctement délimitée. Si la chaîne de délimiteurs contient plusieurs caractères, le premier trouvé dans le texte est utilisé comme délimiteur pour la sous-chaîne. Le troisième argument spécifie un motif de préfixe à sauter (mais il doit être présent !) avant la sous-chaîne. Le dernier argument spécifie le caractère d'échappement à utiliser pour chaque délimiteur.

Tous les arguments sont facultatifs. Si les caractères d'échappement ne sont pas spécifiés, chaque délimiteur est écrit avec un antislash ("\"). Si le préfixe n'est pas spécifié, le motif '\s*' - espace optionnel - est utilisé comme préfixe. Si l'ensemble des délimiteurs n'est pas non plus spécifié, l'ensemble "/["'`]/" est utilisé. Si le texte à traiter n'est pas spécifié, $_ est utilisé.

Dans un contexte de liste, "extract_delimited" renvoie un tableau de trois éléments : la sous-chaîne extraite (y compris les délimiteurs), le reste du texte et le préfixe sauté (s'il existe). Si aucune sous-chaîne délimitée appropriée n'est trouvée, le premier élément du tableau est la chaîne vide, le second est le texte d'origine complet et le préfixe renvoyé dans le troisième élément est une chaîne vide.

Dans un contexte scalaire, seule la sous-chaîne extraite est renvoyée. Dans un contexte vide, la sous-chaîne extraite (et tout préfixe) est supprimée du début du premier argument.

Exemples:

while ( $next = extract_quotelike($text) )
{
    # traiter le segment suivant (dans $next)
}

# Supprimer une sous-chaîne unique entre apostrophes du début de $text : $substring = extract_delimited($text, "'", ''); # Supprimer une sous-chaîne de style Pascal (c'est-à-dire une où les apostrophes sont échappées) du début de $text : $substring = extract_delimited($text, "'", '', "'"); # Extraire une sous-chaîne unique ou double entre guillemets du début de $text, éventuellement après quelques espaces (notez le contexte de liste pour protéger $text de la modification) : ($substring) = extract_delimited $text, q{"'}; # Supprimer la sous-chaîne délimitée par le premier '/' dans $text : $text = join '', (extract_delimited($text,'/','[^/]*')[2,1]);

Note : Ce dernier exemple n'est pas le même que la suppression de motifs de guillemets. Par exemple, si $text contient la chaîne :

"if ('./cmd' =~ m/$UNIXCMD/s) { $cmd = $1; }"

alors après la suppression, il contiendrait :

"if ('.$UNIXCMD/s) { $cmd = $1; }"

et non :

"if ('./cmd' =~ ms) { $cmd = $1; }"

Voir "extract_quotelike" pour une solution (partielle) à ce problème.

"extract_bracketed"
Comme "extract_delimited", la fonction "extract_bracketed" prend jusqu'à trois arguments optionnels : une chaîne à extraire, un spécificateur de délimiteur et un motif de préfixe. Comme précédemment, un préfixe manquant est considéré comme facultatif et un texte manquant est considéré comme $_. Cependant, un spécificateur de délimiteur manquant est considéré comme '{}()[]<>' (voir ci-dessous).

"extract_bracketed" extrait une sous-chaîne délimitée par des parenthèses équilibrées (en utilisant n'importe lesquels des délimiteurs spécifiés par l'utilisateur : '(..)', '{..}', '[..]', ou '<..>'). Elle respectera également optionnellement les délimiteurs non équilibrés (voir ci-dessous).

Un "délimiteur" est une parenthèse dans la liste des délimiteurs passée comme deuxième argument de "extract_bracketed". Les délimiteurs sont spécifiés en fournissant la version gauche ou droite (ou les deux) des parenthèses requises. Notez que l'ordre dans lequel plusieurs délimiteurs sont spécifiés est sans importance.

Une "sous-chaîne délimitée par des parenthèses équilibrées" est une sous-chaîne délimitée par des parenthèses équilibrées, c'est-à-dire une sous-chaîne qui a toute autre (parenthèse gauche ou droite) à l'intérieur de la sous-chaîne également équilibrée par une parenthèse opposée (gauche ou droite) au même niveau de profondeur. Tout type de parenthèse qui n'est pas dans la liste des délimiteurs est traité comme un caractère ordinaire.

En d'autres termes, chaque type de parenthèse spécifié comme délimiteur doit être équilibré et correctement imbriqué dans la sous-chaîne, et tout autre type de parenthèse (« non délimiteur ») à l'intérieur de la sous-chaîne est ignoré.

Par exemple, étant donné la chaîne :

$text = "{ an '[irregularly :-(] {} parenthesized >:-)' string }";

alors un appel à "extract_bracketed" dans un contexte de liste :

@result = extract_bracketed( $text, '{}' );

retournerait :

( "{ an '[irregularly :-(] {} parenthesized >:-)' string }" , "" , "" )

car les deux ensembles de '{..}' sont correctement imbriqués et équilibrés. (Dans un contexte scalaire, seul le premier élément du tableau est renvoyé. Dans un contexte vide, $text est remplacé par une chaîne vide.)

De même, l'appel dans :

@result = extract_bracketed( $text, '{[' );

retournerait le même résultat, car tous les ensembles des deux types de délimiteurs spécifiés sont correctement imbriqués et équilibrés.

Cependant, l'appel dans :

@result = extract_bracketed( $text, '{([<' );

échouerait, retournant :

( undef , "{ an '[irregularly :-(] {} parenthesized >:-)' string }"  );

parce que les paires de '(..)' et '[..]' imbriquées sont « croisées » et que le '>' n'est pas équilibré. (Dans un contexte scalaire, cet appel retournerait une chaîne vide. Dans un contexte vide, $text resterait inchangé.)

Note : Les caractères de guillemets imbriqués dans la chaîne n'aident pas dans ce cas, car ils n'ont pas été spécifiés comme délimiteurs acceptés et sont considérés comme des caractères non délimiteurs (et sont ignorés).

Cependant, si un type particulier de caractère de guillemet est inclus dans la spécification des délimiteurs, ce type de guillemet sera correctement géré. Par exemple, si $text est :

$text = '<A HREF=">>>">link</A>';

alors

@result = extract_bracketed( $text, '<">' );

retournerait :

( '<A HREF=">>>">', 'link</A>', "" )

comme prévu. Sans la spécification de """ comme guillemet imbriqué :

@result = extract_bracketed( $text, '<>' );

le résultat serait :

( '<A HREF=">', '>>>">link</A>', "" )

En plus des délimiteurs de guillemets "'", """ et "`", les formes complètes de quoting de Perl (c'est-à-dire q{chaîne}, qq{chaîne}, etc.) peuvent être spécifiées en incluant la lettre 'q' comme délimiteur. Par conséquent :

@result = extract_bracketed( $text, '<q>' );

correspondrait correctement à quelque chose comme :

$text = '<leftop: conj /and/ conj>';

"extract_quotelike"
"extract_variable"
"extract_variable" extrait toute variable valide ou expression impliquant des variables en Perl, y compris les scalaires, tableaux, hachages, accès à des tableaux, consultations de hachages, appels de méthodes via objets, appels de sous-routines via références de sous-routines, etc.

La sous-routine prend jusqu'à deux arguments optionnels :

1.
Une chaîne à traiter ($_ si la chaîne est omise ou "undef")
2.
Une chaîne spécifiant un motif à faire correspondre comme préfixe (qui doit être ignoré). Si omis, les espaces blancs optionnels sont ignorés.

En cas de succès dans un contexte de liste, un tableau de 3 éléments est renvoyé. Les éléments sont :

[0]
la variable extraite, ou l'expression variablistique
[1]
le reste du texte d'entrée,
[2]
la sous-chaîne de préfixe (le cas échéant),

En cas d'échec, toutes ces valeurs (sauf le texte restant) sont "undef".

Dans un contexte scalaire,

extract_variable

renvoie uniquement la sous-chaîne complète qui correspond à une expression variablistique. "undef" est renvoyé en cas d'échec. De plus, le texte d'entrée d'origine voit la sous-chaîne renvoyée (et tout préfixe spécifié) supprimée.

Dans un contexte vide, le texte d'entrée voit simplement la sous-chaîne correspondante (et tout préfixe spécifié) supprimée.

"extract_tagged"
"extract_tagged" extrait et segmente le texte entre des balises spécifiées (équilibrées).

La sous-routine prend jusqu'à cinq arguments optionnels :

1.
Une chaîne à traiter ($_ si la chaîne est omise ou "undef")
2.
Une chaîne spécifiant un motif (c'est-à-dire une expression régulière) à faire correspondre comme balise d'ouverture. Si la chaîne de motif est omise (ou "undef"), alors un motif qui correspond à toute balise XML standard est utilisé.
3.
Une chaîne spécifiant un motif à faire correspondre comme balise de fermeture. Si la chaîne de motif est omise (ou "undef"), alors la balise de fermeture est construite en insérant un "/" après tout caractère de crochet de début dans la balise d'ouverture réelle qui a été trouvée (pas le motif qui a trouvé la balise). Par exemple, si le motif de balise d'ouverture est spécifié comme '{{\w+}}' et qu'il a effectivement trouvé la balise d'ouverture "{{DATA}}", alors la balise de fermeture construite serait "{{/DATA}}".
4.
Une chaîne spécifiant un motif à faire correspondre comme préfixe (qui doit être ignoré). Si omis, les espaces blancs optionnels sont ignorés.
5.
Une référence de hachage contenant diverses options d'analyse (voir ci-dessous)

Les différentes options qui peuvent être spécifiées sont :

"reject => $listref"
La référence de liste contient une ou plusieurs chaînes spécifiant des motifs qui ne doivent *pas* apparaître dans le texte balisé.
"ignore => $listref"
La référence de liste contient une ou plusieurs chaînes spécifiant des motifs qui ne doivent *pas* être traités comme des balises imbriquées dans le texte balisé (même s'ils correspondaient au motif de balise de début).
"fail => $str"
L'option "fail" indique l'action à entreprendre si une balise de fin correspondante n'est pas rencontrée (c'est-à-dire avant la fin de la chaîne ou avant qu'un motif "reject" ne corresponde). Par défaut, un échec de correspondance de balise de fermeture entraîne l'échec immédiat de "extract_tagged". Cependant, si la valeur de chaîne associée à <reject> est "MAX", alors "extract_tagged" renvoie le c Completez le texte jusqu'au point de défaillance. Si la chaîne est "PARA", "extract_tagged" ne renvoie que le premier paragraphe après la balise (jusqu'à la première ligne qui est vide ou qui ne contient que des espaces blancs). Si la chaîne est "", le comportement par défaut (c'est-à-dire l'échec) est rétablis.

Par exemple, supposez que la balise de début "/para" introduit un paragraphe, qui continue ensuite jusqu'à la prochaine balise "/endpara" ou jusqu'à ce qu'une autre balise "/para" soit rencontrée :

$text = "/para line 1\n\nline 3\n/para line 4";
extract_tagged($text, '/para', '/endpara', undef,
                        {reject => '/para', fail => MAX );
# EXTRAIT : "/para line 1\n\nline 3\n"

Supposez plutôt que, si aucune balise "/endpara" correspondante n'est trouvée, la balise "/para" ne fait référence qu'au paragraphe immédiatement suivant :

$text = "/para line 1\n\nline 3\n/para line 4";
extract_tagged($text, '/para', '/endpara', undef,
                {reject => '/para', fail => MAX );
# EXTRAIT : "/para line 1\n"

Notez que le comportement de "fail" spécifié s'applique également aux balises imbriquées.

En cas de succès dans un contexte de liste, un tableau de 6 éléments est renvoyé. Les éléments sont :

[0]
la sous-chaîne marquée extraite (y compris les balises les plus externes),
[1]
le reste du texte d'entrée,
[2]
la sous-chaîne de préfixe (le cas échéant),
[3]
la balise d'ouverture
[4]
le texte entre les balises d'ouverture et de fermeture
[5]
la balise de fermeture (ou "" s'il n'y a pas de balise de fermeture trouvée)

En cas d'échec, toutes ces valeurs (sauf le texte restant) sont "undef".

Dans un contexte scalaire, "extract_tagged" ne renvoie que la sous-chaîne complète qui correspond à un texte balisé (y compris les balises de début et de fin). "undef" est renvoyé en cas d'échec. De plus, le texte d'entrée d'origine a la sous-chaîne renvoyée (et tout préfixe) retirée.

Dans un contexte vide, le texte d'entrée a simplement la sous-chaîne correspondante (et tout préfixe spécifié) retirée.

"gen_extract_tagged"
"gen_extract_tagged" génère une nouvelle sous-routine anonyme qui extrait du texte entre des balises spécifiées (équilibrées). En d'autres termes, elle génère une fonction identique en fonction à "extract_tagged".

La différence entre "extract_tagged" et les sous-routines anonymes générées par "gen_extract_tagged" est que ces sous-routines générées :

  • n'ont pas à réanalyser la spécification de la balise ou les options d'analyse à chaque appel (alors que "extract_tagged" doit effectivement reconstruire son analyseur de balises à chaque appel) ;
  • utilisent la nouvelle construction qr// pour précompiler les expressions régulières qu'elles utilisent (alors que "extract_tagged" utilise l'interpolation de variables de chaîne standard pour créer des modèles de correspondance de balises).

La sous-routine prend jusqu'à quatre arguments optionnels (le même ensemble que "extract_tagged" sauf la chaîne à traiter). Elle renvoie une référence à une sous-routine qui, à son tour, prend un seul argument (le texte à extraire).

En d'autres termes, l'implémentation de "extract_tagged" est exactement équivalente à :

sub extract_tagged
{
        my $text = shift;
        $extractor = gen_extract_tagged(@_);
        return $extractor->($text);
}

(bien que "extract_tagged" ne soit pas actuellement implémenté de cette façon).

Utiliser "gen_extract_tagged" pour créer des fonctions d'extraction pour des balises spécifiques est une bonne idée si ces fonctions sont appelées plus d'une fois, car leurs performances sont généralement deux fois meilleures que celles de la fonction plus générale "extract_tagged".

"extract_quotelike"
"extract_quotelike" tente de reconnaître, d'extraire et de segmenter l'une des diverses citations et opérateurs de type citation de Perl (voir perlop(3)). Les délimiteurs imbriqués échappés, les délimiteurs d'accolades équilibrés incorporés (pour les opérateurs de type citation) et les modificateurs de fin sont tous capturés. Par exemple, dans : 
extract_quotelike 'q # un octothorpe : \# (pas la fin du q!) #'
extract_quotelike '  "Vous avez dit, \"Utilisez sed\".\"  '
extract_quotelike ' s{([A-Z]{1,8}\.[A-Z]{3})} /\L$1\E/; '
extract_quotelike ' tr/\\\/\\\\/\\\//ds; '

les opérations complètes de type citation de Perl sont toutes extraites correctement.

Notez également que, lors de l'utilisation du modificateur /x sur une expression régulière, tout commentaire contenant le délimiteur de modèle actuel provoquera l'arrêt immédiat de l'expression régulière. En d'autres termes :

'm /
        (?i)            # INSENSIBLE À LA CASSE
        [a-z_]          # ALPHABÉTIQUE/UNDERSCORE DE DÉBUT
        [a-z0-9]*       # SUIVI DE TOUT NOMBRE D'ALPHANUMÉRIQUES
   /x'

sera extrait comme s'il s'agissait de :

'm /
        (?i)            # INSENSIBLE À LA CASSE
        [a-z_]          # ALPHABÉTIQUE DE DÉBUT/UNDERSCORE

Ce comportement est identique à celui du compilateur réel.

"extract_quotelike" prend deux arguments : le texte à traiter et un préfixe à faire correspondre au tout début du texte. Si aucun préfixe n'est spécifié, les espaces blancs optionnels sont par défaut. Si aucun texte n'est donné, $_ est utilisé.

Dans un contexte de liste, un tableau de 11 éléments est renvoyé. Les éléments sont :

[0]
la sous-chaîne de type citation extraite (y compris les modificateurs de fin),
[1]
le reste du texte d'entrée,
[2]
la sous-chaîne de préfixe (le cas échéant),
[3]
le nom de l'opérateur de type citation (le cas échéant),
[4]
le délimiteur gauche du premier bloc de l'opération,
[5]
le texte du premier bloc de l'opération (c'est-à-dire le contenu d'une citation, l'expression régulière d'une correspondance ou d'une substitution, ou la liste cible d'une traduction),
[6]
le délimiteur droit du premier bloc de l'opération,
[7]
le délimiteur gauche du deuxième bloc de l'opération (c'est-à-dire s'il s'agit d'un "s", "tr", ou "y"),
[8]
le texte du deuxième bloc de l'opération (c'est-à-dire le remplacement d'une substitution ou la liste de traduction d'une traduction),
[9]
le délimiteur droit du deuxième bloc de l'opération (le cas échéant),
[10]
les modificateurs de fin sur l'opération (le cas échéant).

Pour chacun des champs marqués "(le cas échéant)", la valeur par défaut en cas de succès est une chaîne vide. En cas d'échec, toutes ces valeurs (sauf le texte restant) sont "undef".

Dans un contexte scalaire, "extract_quotelike" ne renvoie que la sous-chaîne complète qui correspond à une opération de type citation (ou "undef" en cas d'échec). Dans un contexte scalaire ou vide, le texte d'entrée a la même sous-chaîne (et tout préfixe spécifié) retirée.

Exemples :

# Supprimer la première littérale de type citation qui apparaît dans le texte
        $quotelike = extract_quotelike($text,'.*?');
# Remplacer une ou plusieurs littérales de type citation séparées par des espaces blancs au début de $_ par ""
        do { $_ = join '', (extract_quotelike)[2,1] } until $@;
# Isoler le motif de recherche dans une opération de type citation de $text
        ($op,$pat) = (extract_quotelike $text)[3,5];
        if ($op =~ /[ms]/)
        {
                print "motif de recherche : $pat\n";
        }
        else
        {
                print "$op n'est pas une opération de correspondance de motif\n";
        }
"extract_quotelike"
"extract_quotelike" peut extraire avec succès des "here documents" d'une chaîne d'entrée, mais avec une mise en garde importante dans les contextes de liste.

Contrairement aux autres types de littérales de type citation, un here document n'est rarement une sous-chaîne contiguë. Par exemple, un morceau de code typique utilisant un here document peut ressembler à ceci :

<<'EOMSG' || die;
Ceci est le message.
EOMSG
exit;

Étant donné ceci comme chaîne d'entrée dans un contexte scalaire, "extract_quotelike" renverrait correctement la chaîne "<<'EOMSG'\nCeci est le message.\nEOMSG", laissant la chaîne " || die;\nexit;" dans la variable d'origine. En d'autres termes, les deux morceaux séparés du here document sont extraits et concaténés avec succès.

Dans un contexte de liste, "extract_quotelike" renverrait la liste

[0]
"<<'EOMSG'\nCeci est le message.\nEOMSG\n" (c'est-à-dire le document ici complet extrait, y compris les délimiteurs avant et après),
[1]
" || die;\nexit;" (c'est-à-dire le reste du texte d'entrée, concaténé),
[2]
"" (c'est-à-dire la sous-chaîne de préfixe - triviale dans ce cas),
[3]
"<<" (c'est-à-dire le "nom" de l'opérateur de type citation)
[4]
"'EOMSG'" (c'est-à-dire le délimiteur gauche du here document, y compris les éventuelles guillemets),
[5]
"Ceci est le message.\n" (c'est-à-dire le texte du here document),
[6]
"EOMSG" (c'est-à-dire le délimiteur droit du here document),
[7..10]
"" (un here document n'a pas de deuxième délimiteur gauche, de deuxième texte, de deuxième délimiteur droit ou de modificateurs de fin).

Cependant, la position de correspondance de la variable d'entrée serait définie sur "exit;" (c'est-à-dire après le délimiteur de fermeture du here document), ce qui provoquerait le saut du " || die;\nexit;" précédent dans toute séquence d'extractions de fragments de code.

Pour éviter ce problème, lorsqu'il rencontre un here document lors de l'extraction d'une chaîne modifiable, "extract_quotelike" silencieusement réécrit

Claro, aquí tienes el contenido traducido al francés, manteniendo la estructura del archivo: Mantén toda la estructura del archivo. arranges la chaîne à une pièce équivalente de Perl :

<<'EOMSG'
This is the message.
EOMSG
|| die;
exit;
</EOMSG>

dans laquelle le here document est contigu. Bien qu'il reste encore une position correspondante après le here document, le reste de la ligne sur laquelle le here document commence ne sera pas sauté.

Pour éviter que "extract_quotelike" ne se fâche contre l'entrée dans ce mode (c'est le seul cas où un "extract_quotelike" en contexte de liste le fait), vous pouvez passer la variable d'entrée comme une chaîne littérale interpolée :

$quotelike = extract_quotelike("$var");
"extract_codeblock"
"extract_codeblock" tente de reconnaître et d'extraire une sous-chaîne équilibrée qui pourrait contenir des parenthèses déséquilibrées dans des blocs Perl ou des opérations de type quote. Autrement dit, "extract_codeblock" est une combinaison de "extract_bracketed" et "extract_quotelike".

"extract_codeblock" prend les trois premiers paramètres identiques à "extract_bracketed" : un texte à traiter, un ensemble de parenthèses délimiteurs à rechercher et un préfixe à faire correspondre en premier. Il prend également un quatrième paramètre optionnel, qui permet de spécifier séparément les parenthèses délimiteurs les plus externes (voir ci-dessous), et un cinquième paramètre utilisé uniquement par Parse::RecDescent.

Omettre le premier argument (texte d'entrée) signifie traiter $_ à la place. Omettre le deuxième argument (parenthèses délimiteurs) indique que seul '{' sera utilisé. Omettre le troisième argument (préfixe) implique qu'il y a des espaces optionnels au début. Omettre le quatrième argument (parenthèses délimiteurs les plus externes) indique que la valeur du deuxième argument sera utilisée pour les délimiteurs les plus externes.

Une fois le préfixe et les parenthèses délimiteurs les plus externes reconnus, les blocs de code sont extraits en parcourant le texte d'entrée et en testant les alternatives en séquence :

1.
Tente de faire correspondre une parenthèse fermante. Si la parenthèse était du même type que la dernière parenthèse ouvrante, renvoie la sous-chaîne jusqu'à là. Si la parenthèse était déséquilibrée, renvoie une erreur.
2.
Tente de faire correspondre un opérateur de type quote ou une guillemet. Si elle est trouvée, appelle "extract_quotelike" pour la consommer. Si "extract_quotelike" échoue, renvoie l'erreur qu'elle a retournée. Sinon, revient à l'étape 1.
3.
Tente de faire correspondre une parenthèse délimiteur. Si elle est trouvée, appelle "extract_codeblock" récursivement pour consommer le bloc imbriqué. Si l'appel récursif échoue, renvoie une erreur. Sinon, revient à l'étape 1.
4.
Fait correspondre inconditionnellement un bareword ou tout autre caractère unique, puis revient à l'étape 1.

Exemples :

# Trouver une boucle while dans le texte
if ($text =~ s/.*?while\s*\{/{/)
{
        $loop = "while " . extract_codeblock($text);
}
# Supprimer la première liste entre parenthèses rondes (qui peut inclure des blocs de code entre parenthèses rondes ou accolades, ou des opérateurs de type quote)
extract_codeblock $text, "(){}", '[^(]*';

La capacité de spécifier un délimiteur externe plus large est utile dans certaines circonstances. Par exemple, dans le module Parse::RecDescent, les actions différées qui ne s'exécutent qu'en cas de succès d'un parsing sont spécifiées à l'aide d'une directive "<defer:...>". Par exemple :

sentence: subject verb object
                <defer: {$::theVerb = $item{verb}} >

Parse::RecDescent utilise "extract_codeblock($text, '{}<>')" pour extraire le code dans la directive "<defer:...>", mais il y a un problème.

Une action différée comme celle-ci :

<defer: {if ($count>10) {$count--}} >

est mal analysée comme :

<defer: {if ($count>

car l'opérateur "inférieur à" est interprété comme un délimiteur fermant.

Cependant, en extrayant la directive à l'aide de "extract_codeblock($text, '{}', undef, '<>')", le "> n'est traité que comme un délimiteur au niveau le plus externe du bloc de code, ainsi la directive est correctement analysée.

"extract_multiple"
La sous-routine "extract_multiple" prend une chaîne à traiter et une liste d'extracteurs (sous-routines ou expressions régulières) à appliquer à cette chaîne.

En contexte de tableau, "extract_multiple" renvoie un tableau de sous-chaînes de la chaîne originale, telles qu'extraites par les extracteurs spécifiés. En contexte scalaire, "extract_multiple" renvoie la première sous-chaîne extraite avec succès de la chaîne originale. Dans les contextes scalaire et void, la chaîne originale a la première sous-chaîne extraite avec succès supprimée. Dans tous les contextes, "extract_multiple" commence à la position "pos" actuelle de la chaîne et ajuste correctement cette position "pos" après une correspondance.

Par conséquent, le but d'un appel à "extract_multiple" en contexte de tableau est de diviser la chaîne traitée en autant de champs non chevauchants que possible, en appliquant répétitivement chacun des extracteurs spécifiés au reste de la chaîne. Ainsi, "extract_multiple" est une forme généralisée de la sous-routine Perl "split".

La sous-routine prend jusqu'à quatre arguments optionnels :

1.
Une chaîne à traiter ($_ si la chaîne est omise ou "undef")
2.
Une référence à une liste de références de sous-routines ou d'objets qr// ou de chaînes littérales ou de références de hachage, spécifiant les extracteurs à appliquer à la chaîne. Si cet argument est omis (ou "undef"), la liste suivante est utilisée :
  [
    sub { extract_variable($_[0], '') },
    sub { extract_quotelike($_[0],'') },
    sub { extract_codeblock($_[0],'{}','') },
  ]

Si cet argument est omis (ou "undef"), la liste ci-dessus est utilisée.

3.
Un nombre spécifiant le nombre maximum de champs à renvoyer. Si cet argument est omis (ou "undef"), l'extraction continue tant que c'est possible.

Si le troisième argument est N, l'extraction continue jusqu'à ce que N champs aient été extraits avec succès, ou jusqu'à ce que la chaîne soit entièrement traitée.

Note : Dans les contextes scalaire et void, la valeur de cet argument est automatiquement réinitialisée à 1 (sous "-w", un avertissement est émis si l'argument doit être réinitialisé).

4.
Une valeur indiquant si les sous-chaînes non correspondantes (voir ci-dessous) dans le texte doivent être omises ou renvoyées comme champs. Si la valeur est vraie, ces sous-chaînes sont omises. Sinon, elles sont renvoyées.

Le processus d'extraction fonctionne en appliquant chaque extracteur séquentiellement à la chaîne de texte.

Si l'extracteur est une sous-routine, il est appelé en contexte de tableau et est censé renvoyer une liste à un élément, c'est-à-dire le texte extrait. Il peut éventuellement renvoyer deux arguments supplémentaires : une chaîne représentant le texte restant après l'extraction (comme $' dans une correspondance de modèle), et une chaîne représentant tout préfixe omis avant l'extraction (comme $` dans une correspondance de modèle). Note : ceci est conçu pour faciliter l'utilisation d'autres sous-routines de Text::Balanced avec "extract_multiple". Notez également que la valeur renvoyée par une sous-routine d'extraction n'a pas besoin d'être liée à la sous-chaîne correspondante du texte original (voir les exemples ci-dessous).

Si l'extracteur est une expression régulière précompilée ou une chaîne, elle est comparée à la chaîne en contexte scalaire avec un préfixe '\G' et les modificateurs gc activés. La valeur extraite est $1 si cette variable est définie après la correspondance, ou la correspondance complète (c'est-à-dire $&).

Si l'extracteur est une référence à un hachage, il doit contenir exactement un élément. La valeur de cet élément est l'un des types d'extracteurs précédents (référence de sous-routine, expression régulière ou chaîne). La clé de cet élément est le nom d'une classe dans laquelle la valeur de retour réussie de la sous-routine sera hachée.

Si un extracteur renvoie une valeur définie, elle est immédiatement traitée comme le champ extrait suivant et ajoutée à la liste des champs. Si l'extracteur a été spécifié dans une référence de hachage, le champ sera également haché dans la classe correspondante.

Si l'extracteur ne correspond pas (dans le cas d'un extracteur regex) ou renvoie une liste vide ou une valeur indéfinie (dans le cas d'un extracteur de sous-routine), on suppose qu'il n'y a pas eu d'extraction. Si aucune des sous-routines d'extraction n'est satisfaite, un seul caractère est extrait de la chaîne et les sous-routines d'extraction sont réappliquées. Les caractères ainsi supprimés sont accumulés et finissent par constituer le champ suivant (sauf si le quatrième argument est vrai, auquel cas ils sont rejetés).

Par exemple, l'exemple suivant extrait les sous-chaînes valides de variables Perl :

@fields = extract_multiple($text,
                           [ sub { extract_variable($_[0]) } ],
                           undef, 1);

Cet exemple sépare le texte en champs délimités, entre crochets et autres. Les parties délimitées et entre crochets sont également hachées pour les identifier (les "autres" ne sont pas hachées) :

@fields = extract_multiple($text,
           [
                { Delim => sub { extract_delimited($_[0],q{'"}) } },
                { Brack => sub { extract_bracketed($_[0],'{}') } },
           ]);

Cet appel extrait la sous-chaîne unique suivante qui est une opération valide de type quote (et la supprime de $text) :

$quotelike = extract_multiple($text,
                              [
                                sub { extract_quotelike($_[0]) },
                              ],
                              undef, 1);

Enfin, voici une autre façon d'analyser des valeurs séparées par des virgules :

$csv_text = "a,'x b',c";
@fields = extract_multiple($csv_text,
                          [
                                sub { extract_delimited(
$_[0],q{'"}) }, qr/([^,]+)/, ], undef,1); # @champs est maintenant ('a', "'x b'", 'c')

La liste dans le deuxième argument signifie : "Essayer d'extraire une chaîne délimitée par une apostrophe ou un guillemet, sinon extraire tout jusqu'à une virgule...". L'argument non défini du troisième signifie : "...autant de fois que possible...", et la valeur vraie du quatrième argument signifie "...en ignorant tout le reste qui apparaît (c'est-à-dire les virgules)".

Si vous vouliez que les virgules soient conservées comme champs séparés (c'est-à-dire comme le fait split si votre motif de séparation contient des parenthèses capturantes), il vous suffirait de rendre le dernier paramètre indéfini (ou de le supprimer).

"gen_delimited_pat"
La sous-routine "gen_delimited_pat" prend un seul argument (une chaîne) et construit une regex optimisée de style Friedl qui correspond à une chaîne délimitée par l'un quelconque des caractères de l'argument unique. Par exemple : 
gen_delimited_pat(q{'"})

renvoie la regex :

(?:\"(?:\\\"|(?!\").)*\"|\'(?:\\\'|(?!\').)*\')

Notez que les délimiteurs spécifiés sont automatiquement quotemeta's.

Une utilisation typique de "gen_delimited_pat" serait de construire des balises spéciales pour "extract_tagged". Par exemple, pour ignorer correctement les éléments XML "vides" (qui pourraient contenir des chaînes entre guillemets) :

my $empty_tag = '<(' . gen_delimited_pat(q{'"}) . '|.)+>';
extract_tagged($text, undef, undef, undef, {ignore => [$empty_tag]} );

"gen_delimited_pat" peut également être appelée avec un deuxième argument optionnel, qui spécifie le(s) caractère(s) d'échappement à utiliser pour chaque délimiteur. Par exemple, pour faire correspondre une chaîne de style Pascal (où ' est le délimiteur et '' est un ' littéral dans la chaîne) :

gen_delimited_pat(q{'},q{'});

Des caractères d'échappement différents peuvent être spécifiés pour des délimiteurs différents. Par exemple, pour spécifier que '/' est l'échappement pour les apostrophes et '%' est l'échappement pour les guillemets :

gen_delimited_pat(q{'"},q{/%});

Si plus de délimiteurs que de caractères d'échappement sont spécifiés, le dernier caractère d'échappement est utilisé pour les délimiteurs restants. Si aucun caractère d'échappement n'est spécifié pour un délimiteur donné, '\' est utilisé.

"delimited_pat"
Notez que "gen_delimited_pat" s'appelait précédemment "delimited_pat". Ce nom peut encore être utilisé, mais il est maintenant obsolète.

DIAGNOSTICS

Dans un contexte de liste, toutes les fonctions renvoient "(undef,$texte_original)" en cas d'échec. Dans un contexte scalaire, l'échec est indiqué par le retour de "undef" (dans ce cas, le texte d'entrée n'est modifié d'aucune manière).

De plus, en cas d'échec dans un contexte quelconque, la variable $@ est définie. L'accès à "$@->{error}" renvoie l'un des diagnostics d'erreur listés ci-dessous. L'accès à "$@->{pos}" renvoie le décalage dans la chaîne d'origine auquel l'erreur a été détectée (bien que pas nécessairement où elle s'est produite !). L'impression directe de $@ produit le message d'erreur, avec le décalage ajouté. En cas de succès, la variable $@ est garantie d'être "undef".

Les diagnostics disponibles sont :

"Did not find a suitable bracket: "%s""
Le délimiteur fourni à "extract_bracketed" n'était pas l'un des '()[]<>{}'.
"Did not find prefix: /%s/"
Un préfixe non optionnel a été spécifié mais n'a pas été trouvé au début du texte.
"Did not find opening bracket after prefix: "%s""
"extract_bracketed" ou "extract_codeblock" s'attendait à un type particulier de parenthèse au début du texte, et ne l'a pas trouvé.
"No quotelike operator found after prefix: "%s""
"extract_quotelike" n'a pas trouvé l'un des opérateurs quotelike "q", "qq", "qw", "qx", "s", "tr" ou "y" au début de la sous-chaîne qu'il extrayait.
"Unmatched closing bracket: "%c""
"extract_bracketed", "extract_quotelike" ou "extract_codeblock" a rencontré une parenthèse fermante alors qu'aucune n'était attendue.
"Unmatched opening bracket(s): "%s""
"extract_bracketed", "extract_quotelike" ou "extract_codeblock" a manqué de caractères dans le texte avant de fermer un ou plusieurs niveaux de parenthèses imbriquées.
"Unmatched embedded quote (%s)"
"extract_bracketed" a tenté de faire correspondre une sous-chaîne intégrée entre guillemets, mais n'a pas trouvé de guillemet fermant pour la faire correspondre.
"Did not find closing delimiter to match '%s'"
"extract_quotelike" n'a pas pu trouver de délimiteur fermant pour faire correspondre celui qui a ouvert l'opération de type guillemet.
"Mismatched closing bracket: expected "%c" but found "%s""
"extract_bracketed", "extract_quotelike" ou "extract_codeblock" a trouvé un délimiteur de parenthèse valide, mais c'était la mauvaise espèce. Cela indique généralement une erreur d'imbrication, mais peut indiquer une citation ou un échappement incorrect.
"No block delimiter found after quotelike "%s""
"extract_quotelike" ou "extract_codeblock" a trouvé l'un des opérateurs quotelike "q", "qq", "qw", "qx", "s", "tr" ou "y" sans bloc approprié après celui-ci.
"Did not find leading dereferencer"
"extract_variable" s'attendait à l'un des '$', '@', ou '%' au début d'une variable, mais n'en a trouvé aucun.
"Bad identifier after dereferencer"
"extract_variable" a trouvé un '$', '@', ou '%' indiquant une variable, mais ce caractère n'a pas été suivi d'un identifiant Perl légal.
"Did not find expected opening bracket at %s"
"extract_codeblock" n'a pas trouvé l'une des parenthèses ouvrantes externes spécifiées.
"Improperly nested codeblock at %s"
Un bloc de code imbriqué a été trouvé qui a commencé par un délimiteur spécifié comme étant utilisé uniquement comme parenthèse externe.
"Missing second block for quotelike "%s""
"extract_codeblock" ou "extract_quotelike" a trouvé l'un des opérateurs quotelike "s", "tr" ou "y" suivi d'un seul bloc.
"No match found for opening bracket"
"extract_codeblock" n'a pas trouvé de parenthèse fermante pour correspondre à la parenthèse ouvrante externe.
"Did not find opening tag: /%s/"
"extract_tagged" n'a pas trouvé de balise ouvrante appropriée (après suppression de tout préfixe spécifié).
"Unable to construct closing tag to match: /%s/"
"extract_tagged" a trouvé la balise ouvrante spécifiée et a tenté de modifier le texte correspondant pour produire une balise fermante correspondante (car aucune n'était spécifiée). Il n'a pas réussi à générer la balise fermante, très probablement parce que la balise ouvrante ne commençait pas par une parenthèse quelconque.
"Found invalid nested tag: %s"
"extract_tagged" a trouvé une balise imbriquée qui apparaissait dans la liste "reject" (et le mode d'échec n'était pas "MAX" ou "PARA").
"Found unbalanced nested tag: %s"
"extract_tagged" a trouvé une balise ouvrante imbriquée qui n'était pas correspondue par une balise fermante imbriquée correspondante (et le mode d'échec n'était pas "MAX" ou "PARA").
"Did not find closing tag"
"extract_tagged" a atteint la fin du texte sans trouver de balise fermante pour correspondre à la balise ouvrante d'origine (et le mode d'échec n'était pas "MAX" ou "PARA").

NAME

Text::Balanced — Analyse and extract balanced text constructs.

SYNOPSIS

    use Text::Balanced qw(:DEFAULT parse_brackets);
    my $text = q{
        This is some text.
        This is an example of a balanced construct:
        (This is enclosed in parentheses).
        And here is another: [This is enclosed in square brackets].
        And another: {This is enclosed in curly braces}.
        This also works with nested constructs:
        (This has [nested brackets] inside).
        (This has {nested braces} inside).
        ([This has both] nested inside).
        This is NOT balanced: (This has unmatched closing parenthesis).
        This is NOT balanced: [This has unmatched closing bracket.
        This is NOT balanced: {This has unmatched closing brace.
        This is NOT balanced: ) This has unmatched opening parenthesis.
        This is NOT balanced: [ This has unmatched opening bracket.
        This is NOT balanced: { This has unmatched opening brace.
    };
    my @constructs = parse_brackets($text);
    foreach my $construct (@constructs) {
        print "Found balanced construct:\n", $construct->text, "\n";
        print "--------------------------\n";
    };

Or, using the general purpose parsing function:

    use Text::Balanced qw(extract_balanced_and_unbalanced);
    my ($balanced, $unbalanced) = extract_balanced_and_unbalanced($text);
    print "Balanced text:\n", $balanced, "\n";
    print "Unbalanced text:\n", $unbalanced, "\n";

Or, to extract quoted strings:

    use Text::Balanced qw(extract_quoted_string);
    my $string = q{This is "a quoted string" and some text.};
    my ($quoted, $rest) = extract_quoted_string($string);
    print "Quoted string: ", $quoted, "\n";
    print "Rest of string: ", $rest, "\n";

DESCRIPTION

The Text::Balanced module provides a range of functions for parsing and extracting balanced text constructs such as parenthesized expressions, quoted strings, or any other construct defined by user-supplied start and end delimiters.

The module is particularly useful for parsing programming languages, markup languages, or configuration files that contain nested or quoted structures.

The primary functions are:

parse_brackets
Parses the given text and returns an array of objects, each representing a balanced construct found in the text. The objects have a text method that returns the full text of the construct, including the delimiters. This function specifically targets parentheses (), square brackets [], and curly braces {}. It correctly handles nesting and identifies unbalanced constructs.
extract_balanced_and_unbalanced
Takes text and returns two strings: the first contains all the balanced constructs found, concatenated together. The second string contains the remaining text that was not part of any balanced construct. This function uses parse_brackets internally.
extract_quoted_string
Extracts the first quoted string (enclosed in double quotes " or single quotes "'") from the beginning of the given text. It returns the extracted quoted string (including the quotes) and the rest of the text. It handles escaped quotes within the string.
extract_delimited_string
Extracts the first string delimited by the specified start and end delimiters. It returns the extracted string (including delimiters) and the rest of the text. It handles nesting and escaped delimiters.
extract_code
Extracts a code block delimited by {...}. This function is specifically designed to handle Perl code blocks, including nested braces. It returns the extracted code block and the remaining text.
extract_html_comment
Extracts an HTML comment <!-- ... --> from the beginning of the given text. It returns the comment and the rest of the text.
extract_variable
Extracts a variable name (e.g., $var, @array, %hash) from the beginning of the given text. It returns the variable name and the rest of the text.
extract_perl_string
Extracts a Perl string literal (single-quoted, double-quoted, or bareword) from the beginning of the given text. It returns the extracted string and the rest of the text.
extract_balanced_construct
A general-purpose function to extract a balanced construct defined by any pair of start and end delimiters. It takes the text, the start delimiter, and the end delimiter as arguments. It returns the extracted construct and the rest of the text.
extract_multiple
Extracts multiple types of constructs from the text based on a list of defined patterns. Returns the extracted text and the remaining text.
gen_delimited_pat
Generates a regular expression pattern to match a delimited string, handling nesting and escapes.
gen_extract_tagged
Generates a subroutine to extract text tagged with specific start and end markers, handling nesting.
delimited_pat
Returns a regular expression pattern for matching delimited strings with nested structures.
extract_tagged
Extracts text enclosed by specific start and end tags, handling nesting.

DIAGNOSTICS

The module does not explicitly die or warn, but unbalanced constructs will simply not be extracted by functions like parse_brackets and will be returned as part of the unbalanced text by extract_balanced_and_unbalanced.
