NOM

Term::ReadLine::Gnu - Extension Perl pour la bibliothèque GNU Readline/History

SYNOPIS

use Term::ReadLine;   # N'utilisez PAS "use Term::ReadLine::Gnu;"
$term = new Term::ReadLine 'NomProgramme';
while ( defined ($_ = $term->readline('invite>')) ) {
  ...
}

DESCRIPTION

Aperçu

Ceci est une implémentation de Term::ReadLine http://search.cpan.org/dist/Term-ReadLine/ utilisant la bibliothèque GNU Readline/History https://tiswww.cwru.edu/php/chet/readline/rltop.html.

Pour les fonctions de base, une interface orientée objet est fournie. Celles-ci sont décrites dans la section "Méthodes standards" et ""Term::ReadLine::Gnu" Fonctions".

Ce paquet dispose également d'une interface avec la quasi-totalité des fonctions et variables documentées dans le Manuel de la bibliothèque GNU Readline/History. Elles sont brièvement documentées dans les sections ""Term::ReadLine::Gnu" Fonctions" et ""Term::ReadLine::Gnu" Variables". Pour plus de détails sur la bibliothèque GNU Readline/History, consultez le Manuel de la bibliothèque GNU Readline https://tiswww.cwru.edu/php/chet/readline/readline.html et le Manuel de la bibliothèque GNU History https://tiswww.cwru.edu/php/chet/readline/history.html.

Il existe des fonctionnalités originales de "Term::ReadLine::Gnu". Elles sont décrites dans la section ""Term::ReadLine::Gnu" Fonctionnalités spécifiques"

Les exemples de programmes dans le répertoire eg/ et les programmes de test dans le répertoire t/ de la distribution "Term::ReadLine::Gnu" http://search.cpan.org/dist/Term-ReadLine-Gnu/ contiennent de nombreux exemples de ce module. Voir eg/README.md pour plus de détails sur le répertoire eg/.

Méthodes standards

Ce sont les méthodes standard définies par Term::ReadLine http://search.cpan.org/dist/Term-ReadLine/.

"ReadLine"
renvoie le paquet réel qui exécute les commandes. Si ce paquet est utilisé, "Term::ReadLine::Gnu" est renvoyé.
"new(NOM,[ENTREE,SORTIE])"
renvoie le handle pour les appels ultérieurs aux fonctions suivantes. L'argument est le nom de l'application. Il peut éventuellement être suivi de deux arguments pour les descripteurs de fichier "ENTREE" et "SORTIE". Ces arguments devraient être des globs.
"readline(INVITE[,PREENTREE])"
obtient une ligne d'entrée, avec le support réel de "GNU Readline". La nouvelle ligne finale est supprimée. Renvoie "undef" en cas de "EOF". "PREENTREE" est un argument optionnel signifiant la valeur initiale de l'entrée.

L'argument optionnel "PREENTREE" n'est accordé que si la valeur "preput" est présente dans "Features".

"INVITE" peut contenir des séquences d'échappement. Utilisez "RL_PROMPT_START_IGNORE" pour commencer une séquence de caractères non imprimables, et "RL_PROMPT_END_IGNORE" pour terminer la séquence.

"AddHistory(LIGNE1, LIGNE2, ...)"
ajoute les lignes à l'historique des entrées, d'où elles peuvent être utilisées si la fonction "readline" réelle est présente.
"IN", "OUT"
renvoient les descripteurs de fichier pour l'entrée et la sortie ou "undef" si l'entrée et la sortie de "readline" ne peuvent pas être utilisées pour Perl.
MinLigne([MAX])
Si l'argument "MAX" est spécifié, il s'agit d'un conseil sur la taille minimale d'une ligne à inclure dans l'historique. "undef" signifie ne rien inclure dans l'historique. Renvoie l'ancienne valeur.
"findConsole"
renvoie un tableau avec deux chaînes qui donnent les noms les plus appropriés pour les fichiers d'entrée et de sortie en utilisant les conventions "<$in", ">$out".
"Attribs"
renvoie une référence vers un hachage qui décrit la configuration interne (variables) du paquet. Les noms des clés dans ce hachage sont conformes aux conventions standard avec le préfixe "rl_" tronqué.

Voir la section ""Term::ReadLine::Gnu" Variables" pour les variables prises en charge.

"Features"
Renvoie une référence vers un hachage dont les clés sont les fonctionnalités présentes dans l'implémentation actuelle. Plusieurs fonctionnalités optionnelles sont utilisées dans l'interface minimale : "appname" doit être présent si le premier argument de "new" est reconnu, et "minline" doit être présent si la méthode "MinLine" n'est pas factice. "autohistory" doit être présent si les lignes sont ajoutées automatiquement à l'historique (potentiellement sous réserve de "MinLine"), et "addHistory" si la méthode "AddHistory" n'est pas factice. "preput" signifie que le deuxième argument de la méthode "readline" est traité. "getHistory" et "setHistory" indiquent que les méthodes correspondantes sont présentes. "tkRunning" indique qu'une application Tk peut s'exécuter pendant que ReadLine reçoit une entrée.
"tkRunning"
fait tourner la boucle d'événements Tk en attendant l'entrée utilisateur (c'est-à-dire pendant la méthode "readline").
"event_loop"
Voir la description de "event_loop" sur Term::ReadLine http://search.cpan.org/dist/Term-ReadLine/.
"ornaments"
fait ressortir la ligne de commande en utilisant les données termcap. L'argument de "ornaments" doit être 0, 1, ou une chaîne de la forme "aa,bb,cc,dd". Quatre composants de cette chaîne doivent être les noms des capacités du terminal, les deux premiers seront utilisés pour faire ressortir l'invite, les deux derniers pour faire ressortir la ligne d'entrée.
"newTTY"
prend deux arguments qui sont les descripteurs de fichier d'entrée et de sortie. Bascule l'utilisation de ces descripteurs de fichier.
"enableUTF8"
Active le support UTF-8.

Si STDIN est en UTF-8 via le commutateur de ligne de commande "-C" ou la variable d'environnement "PERL_UNICODE", ou si le descripteur de fichier "IN" possède une couche d'E/S "utf8", alors le support UTF-8 est également activé. Dans les autres cas, vous avez besoin de cette méthode "enableUTF8".

Il s'agit d'une méthode originale de "Term::ReadLine:Gnu".

Fonctions "Term::ReadLine::Gnu"

Toutes ces fonctions de la bibliothèque GNU Readline/History prises en charge sont appelables via l'interface de méthode et portent des noms conformes aux conventions standard avec le préfixe "rl_" tronqué. Par exemple, la fonction rl_foo() est appelée comme "$term->foo()".

Les titres des sections suivantes sont identiques aux titres des sections correspondantes dans la section "Programmation avec GNU Readline" du Manuel GNU Readl

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Manual de la Biblioteca https://tiswww.cwru.edu/php/chet/readline/readline.html. Refer them para detalles adicionales.

Aunque es preferible utilizar la interfaz método, la mayoría de métodos tienen funciones de nivel inferior en el paquete "Term::ReadLine::Gnu::XS". Para usarlas, se requiere un nombre completo.

Comportamiento Básico

La función readline() imprime un mensaje de promp y luego lee y devuelve una línea de texto del usuario.

$_ = $term->readline('Enter a line: ');

Puedes cambiar las teclas usando la función "bind_key(KEY, FUNCTION [,MAP])". El primer argumento, "KEY", es la tecla que quieres vincular. El segundo argumento, "FUNCTION", es la función a llamar cuando se presione "KEY". La "FUNCTION" puede ser una referencia a una función Perl (ver "Funciones Personalizadas") o una "función nombrada" llamada por add_defun() o comandos descritos en la sección "Comandos de Readline Bindables" de la Manual de la Biblioteca GNU Readline https://tiswww.cwru.edu/php/chet/readline/readline.html.

$term->bind_key(ord "\ci, 'tab-insert');

El ejemplo anterior vincula Control-I a la comando 'tab-insert'.

Funciones Personalizadas

Puedes escribir nuevas funciones usando Perl. La secuencia de llamada para un comando llamado foo es:

sub foo ($count, $key) { ... }

donde $count es el argumento numérico (o 1 si se usa por defecto) y $key es la clave que invocó esta función.

Aquí está un ejemplo;

sub reverse_line {              # invertir toda una línea
    my($count, $key) = @_;      # ignorado en este ejemplo función
    $t->modifying(0, $a->{end}); # guardar información de undo
    $a->{line_buffer} = reverse $a->{line_buffer};
}

Ver la sección "Escribir una Nueva Función" de la Manual de la Biblioteca GNU Readline https://tiswww.cwru.edu/php/chet/readline/readline.html para detalles adicionales.

Funciones de Readline de Conveniencia

Nombre de una Función

"add_defun(NAME, FUNCTION [,KEY=-1])"
Añade el nombre a una función Perl "FUNCTION". Si se especifica el argumento opcional "KEY", lo vincula a "FUNCTION". Devuelve referencia a "FunctionPtr". 
Ejemplo:
      # nombre `reverse-line' a una función reverse_line(), y vincularlo a "\C-t"
      $term->add_defun('reverse-line', \&reverse_line, ord "\ct");

Complétion personnalisée

Cette section décrit les variables et fonctions pour la complétion personnalisée, ainsi que des exemples.

La plupart des descriptions de cette section proviennent du Manuel de la Bibliothèque GNU Readline (https://tiswww.cwru.edu/php/chet/readline/readline.html).

"completion_entry_function"
Cette variable stocke une référence à une fonction génératrice pour completion_matches().

Une fonction génératrice est appelée de manière répétée par completion_matches(), renvoyant une chaîne à chaque fois. Les arguments de la fonction génératrice sont "TEXT" et "STATE". "TEXT" est le mot partiel à compléter. "STATE" est zéro lors du premier appel de la fonction, permettant à la fonction génératrice d'effectuer les initialisations nécessaires, et un nombre positif et non nul pour chaque appel ultérieur. Lorsque la fonction génératrice renvoie "undef", cela signale à completion_matches() qu'il n'y a plus de possibilités.

Si cette variable est définie comme undef, la fonction de complétion standard "filename_completion_function" est utilisée.

Un exemple de fonction génératrice, "list_completion_function", est défini dans Gnu.pm. Vous pouvez l'utiliser comme suit :

use Term::ReadLine;
...
my $term = new Term::ReadLine 'sample';
my $attribs = $term->Attribs;
...
$attribs->{completion_entry_function} =
    $attribs->{list_completion_function};
...
$attribs->{completion_word} =
    [qw(reference to a list of words which you want to use for completion)];
$term->readline("custom completion>");

Voir aussi "completion_matches".

"attempted_completion_function"
Une référence à une fonction alternative pour créer les correspondances.

La fonction est appelée avec "TEXT", "LINE_BUFFER", "START" et "END". "LINE_BUFFER" est une chaîne du tampon d'entrée actuel. "START" et "END" sont des indices dans "LINE_BUFFER" qui indiquent les limites de "TEXT".

Si cette fonction existe et renvoie une liste vide ou "undef", ou si cette variable est définie à "undef", alors la fonction interne rl_complete() appellera la valeur de "completion_entry_function" pour générer les correspondances, sinon le tableau de chaînes renvoyé sera utilisé.

La valeur par défaut de cette variable est "undef". Vous pouvez l'utiliser comme suit :

use Term::ReadLine;
...
my $term = new Term::ReadLine 'sample';
my $attribs = $term->Attribs;
...
sub sample_completion {
    my ($text, $line, $start, $end) = @_;
    # Si c'est le premier mot, complétion utilisateur, sinon complétion de fichier
    if (substr($line, 0, $start) =~ /^\s*$/) {
        return $term->completion_matches($text,
                                         $attribs->{'username_completion_function'});
    } else {
        return ();
    }
}
...
$attribs->{attempted_completion_function} = \&sample_completion;
"completion_matches(TEXT, ENTRY_FUNC)"
Renvoie un tableau de chaînes qui sont les complétions possibles pour "TEXT". S'il n'y a pas de complétions, renvoie "undef". Le premier élément du tableau renvoyé est la substitution pour "TEXT". Les éléments restants sont les complétions possibles.

"ENTRY_FUNC" est une fonction génératrice qui a deux arguments et renvoie une chaîne. Le premier argument est "TEXT", le second est un argument d'état ; il est zéro lors du premier appel, et un nombre positif et non nul lors des appels ultérieurs. "ENTRY_FUNC" renvoie "undef" à l'appelant lorsqu'il n'y a plus de correspondances.

Si la valeur de "ENTRY_FUNC" est undef, la fonction de complétion standard "filename_completion_function" est utilisée.

"completion_matches" est une fonction Perl qui encapsule la fonction interne completion_matches(). Voir aussi "completion_entry_function".

"completion_function"
Une variable qui contient une référence à une fonction qui renvoie une liste de candidats pour la complétion.

Cette variable est compatible avec Term::ReadLine::Perl (http://search.cpan.org/dist/Term-ReadLine-Perl/) et est très facile à utiliser.

use Term::ReadLine;
...
my $term = new Term::ReadLine 'sample';
my $attribs = $term->Attribs;
...
$attribs->{completion_function} = sub {
    my ($text, $line, $start) = @_;
    return qw(a list of candidates to complete);
};
"list_completion_function(TEXT, STATE)"
Une fonction génératrice fournie par "Term::ReadLine::Gnu". Le code d'exemple dans "completion_entry_function" montre comment utiliser cette fonction.

NOM

Term::ReadLine::Gnu

SYNOPIS

  use Term::ReadLine::Gnu;

DESCRIPTION

Term::ReadLine::Gnu est un module Perl qui fournit une interface à la bibliothèque GNU Readline. Il permet aux utilisateurs de manipuler interactivement l'entrée et la sortie de la ligne de commande, offrant des fonctionnalités telles que l'historique, les liaisons de touches, et plus encore.

FICHIERS

Les fichiers suivants sont associés à Term::ReadLine::Gnu :

~/.inputrc
Fichier d'initialisation de Readline. En utilisant ce fichier, vous pourriez souhaiter utiliser un ensemble différent de liaisons de touches. Lorsqu'un programme qui utilise la bibliothèque GNU Readline démarre, le fichier d'initialisation est lu et les liaisons de touches sont définies.
