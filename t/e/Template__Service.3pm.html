NOM

Template::Service - Service de traitement de modèles à usage général

SYNOPIS

use Template::Service;
my $service = Template::Service->new({
    PRE_PROCESS  => [ 'config', 'header' ],
    POST_PROCESS => 'footer',
    ERROR        => {
        user     => 'user/index.html',
        dbi      => 'error/database',
        default  => 'error/default',
    },
});
my $output = $service->process($template_name, \%replace)
    || die $service->error(), "\n";

DESCRIPTION

Le module "Template::Service" implémente une classe d'objet pour fournir un service de traitement de modèles cohérent.

Des modèles d'en-tête (PRE_PROCESS) et de pied de page (POST_PROCESS) standard peuvent être spécifiés, qui sont ajoutés avant et après tous les modèles traités par le service (mais pas aux autres modèles ou blocs "INCLUDE"d ou "PROCESS"és depuis l'intérieur). Un HASH d'erreurs (ERROR) peut être spécifié, qui redirige le service vers un fichier modèle alternatif en cas d'exceptions non interceptées. Cela permet de gérer automatiquement les erreurs par le service et de générer une réponse garantie valide, quels que soient les problèmes de traitement rencontrés.

Un objet "Template::Service" par défaut est créé par le module Template. Toutes les options de "Template::Service" peuvent être passées à la méthode constructeur new() de Template et seront transmises au constructeur de Template::Service.

use Template;
my $template = Template->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
});

De même, le constructeur "Template::Service" transmettra tous les paramètres de configuration aux autres objets par défaut (par ex. Template::Context) qu'il pourrait avoir besoin d'instancier.

Un objet "Template::Service" (ou une sous-classe) peut être explicitement instancié et passé à la méthode constructeur new() de Template en tant qu'élément SERVICE.

use Template;
use Template::Service;
my $service = Template::Service->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
});
my $template = Template->new({
    SERVICE => $service,
});

Le module "Template::Service" peut être sous-classé pour créer des gestionnaires de service personnalisés.

use Template;
use MyOrg::Template::Service;
my $service = MyOrg::Template::Service->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
    COOL_OPTION  => 'enabled in spades',
});
my $template = Template->new({
    SERVICE => $service,
});

Le module Template utilise la méthode d'usine service() de Template::Config pour créer un objet de service par défaut lorsque nécessaire. La variable de paquet $Template::Config::SERVICE peut être définie pour spécifier un module de service alternatif. Celui-ci sera chargé automatiquement et sa méthode constructeur new() sera appelée par la méthode d'usine service() lorsqu'un objet de service par défaut est requis. Ainsi, l'exemple précédent pourrait être écrit comme ceci :

use Template;
$Template::Config::SERVICE = 'MyOrg::Template::Service';
my $template = Template->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
    COOL_OPTION  => 'enabled in spades',
});

MÉTHODES

new(\%config)

La méthode constructeur new() est appelée pour instancier un objet "Template::Service". Les paramètres de configuration peuvent être spécifiés sous forme de référence HASH ou de liste de paires "nom => valeur".

my $service1 = Template::Service->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
});
my $service2 = Template::Service->new( ERROR => 'error.html' );

La méthode new() retourne un objet "Template::Service" ou "undef" en cas d'erreur. Dans ce dernier cas, un message d'erreur pertinent peut être récupéré par la méthode de classe error() ou directement à partir de la variable de paquet $Template::Service::ERROR.

my $service = Template::Service->new(\%config)
    || die Template::Service->error();
my $service = Template::Service->new(\%config)
    || die $Template::Service::ERROR;

process($input, \%replace)

La méthode process() est appelée pour traiter un modèle spécifié par le premier paramètre, $input. Cela peut être un nom de fichier, un descripteur de fichier (par ex. "GLOB" ou "IO::Handle") ou une référence à une chaîne de texte contenant le texte du modèle. Une référence HASH supplémentaire peut être passée contenant les définitions de variables du modèle.

La méthode traite le modèle, ajoute les modèles PRE_PROCESS ou POST_PROCESS définis, et retourne le texte de sortie. Une exception non interceptée lancée par le modèle sera gérée par un gestionnaire d'erreur (ERROR) pertinent si défini. Les erreurs qui surviennent dans les modèles PRE_PROCESS ou POST_PROCESS, ou celles qui surviennent dans le modèle d'entrée principal et ne sont pas gérées, font que la méthode retourne "undef" pour indiquer un échec. Le message d'erreur approprié peut être récupéré via la méthode error().

$service->process('myfile.html', { title => 'Mon Fichier Test' })
    || die $service->error();

context()

Retourne une référence à l'objet de contexte interne qui est, par défaut, une instance de la classe Template::Context.

OPTIONS DE CONFIGURATION

La liste suivante résume les options de configuration qui peuvent être fournies au constructeur "Template::Service" new(). Veuillez consulter Template::Manual::Config pour plus de détails et d'exemples sur chaque option de configuration.

PRE_PROCESS, POST_PROCESS

Les options PRE_PROCESS et POST_PROCESS peuvent être définies pour contenir le(s) nom(s) de fichiers modèles qui doivent être traités juste avant et/ou juste après chaque modèle. Ceux-ci ne sont pas ajoutés aux modèles traités dans un document via des directives telles que "INCLUDE", "PROCESS", "WRAPPER", etc.

my $service = Template::Service->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
};

Plusieurs modèles peuvent être spécifiés sous forme de référence à une liste. Chacun est traité dans l'ordre défini.

my $service = Template::Service->new({
    PRE_PROCESS  => [ 'config', 'header' ],
    POST_PROCESS => 'footer',
};

PROCESS

L'option PROCESS peut être définie pour contenir le(s) nom(s) de fichiers modèles qui doivent être traités à la place du modèle principal passé à la méthode "Template::Service" process(). Ceci peut être utilisé pour appliquer des wrappers cohérents autour de tous les modèles, similaire à l'utilisation des modèles PRE_PROCESS et POST_PROCESS.

my $service = Template::Service->new({
    PROCESS  => 'content',
};
# traite 'content' au lieu de 'foo.html'
$service->process('foo.html');

Une référence au modèle original est disponible dans la variable "template". Les éléments de métadonnées peuvent être inspectés et le modèle peut être traité en le spécifiant comme référence de variable (c'est-à-dire préfixé par '"$"') à une directive "INCLUDE", "PROCESS" ou "WRAPPER".

Exemple de modèle "PROCESS" :

<html>
  <head>
    <title>[% template.title %]</title>
  </head>
  <body>
  [% PROCESS $template %]
  </body>
</html>

; l'élément de configuration peut être utilisé pour nommer un modèle unique ou spécifier un tableau de hachage associant les types d'exception aux modèles qui devraient être utilisés pour la gestion des erreurs. Si une exception non interceptée est levée à partir d'un modèle, le modèle d'erreur approprié sera plutôt traité.

S'il est spécifié comme une seule valeur, ce modèle sera traité pour toutes les exceptions non interceptées.

my $service = Template::Service->new({
    ERROR => 'error.html'
});

Si l'élément ERROR ou ERRORS est une référence de hachage, les clés sont supposées être des types d'exception et le modèle pertinent pour une exception donnée sera sélectionné. Un modèle "default" peut être fourni pour le cas général.

my $service = Template::Service->new({
    ERRORS => {
        user     => 'user/index.html',
        dbi      => 'error/database',
        default  => 'error/default',
    },
});

AUTO_RESET

L'option AUTO_RESET est définie par défaut et provoque la réinitialisation du cache local "BLOCKS" de l'objet Template::Context à chaque appel de la méthode Template::process(). Cela garantit que tous les "BLOCK"s définis dans un modèle ne persistent que jusqu'à ce que ce modèle ait fini d'être traité.

DEBUG

L'option DEBUG peut être utilisée pour activer les messages de débogage du module "Template::Service" en la définissant pour inclure la valeur "DEBUG_SERVICE".

use Template::Constants qw( :debug );
my $template = Template->new({
    DEBUG => DEBUG_SERVICE,
});
