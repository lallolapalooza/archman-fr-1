NOM

Template::Document - Objet de document de template compilé

SYNOPSIS

use Template::Document;
$doc = Template::Document->new({
    BLOCK => sub { # code perl; retourne $quelque_chose },
    DEFBLOCKS => {
        header => sub { # plus de code perl; retourne $quelque_chose },
        footer => sub { # blah blah blah; retourne $quelque_chose },
    },
    METADATA => {
        author  => 'Andy Wardley',
        version => 3.14,
    }
}) || die $Template::Document::ERROR;
print $doc->process($context);

DESCRIPTION

Ce module définit une classe d'objets dont les instances représentent des documents de templates compilés. Le module Template::Parser crée une instance "Template::Document" pour encapsuler un template lors de sa compilation en code Perl.

La méthode constructeur, new(), attend une référence vers un tableau associatif contenant les éléments "BLOCK", "DEFBLOCKS" et "METADATA".

L'élément "BLOCK" doit contenir une référence à une sous-routine Perl ou une représentation textuelle de code Perl, telle que générée par le module Template::Parser. Celle-ci est ensuite évaluée en une référence de sous-routine à l'aide de eval().

L'élément "DEFBLOCKS" doit référencer un tableau associatif contenant d'autres "BLOCK"s nommés qui peuvent être définis dans le template. Les clés représentent les noms de "BLOCK" et les valeurs doivent être des références de sous-routines ou des chaînes de caractères de code Perl, comme pour l'élément "BLOCK" principal.

L'élément "METADATA" doit référencer un tableau associatif d'éléments de métadonnées pertinents pour le document.

La méthode process() peut ensuite être appelée sur l'objet instancié "Template::Document", en passant une référence à un objet Template::Context comme premier paramètre. Ceci installera tous les blocs définis localement ("DEFBLOCKS") dans le cache "BLOCKS" du contexte (via un appel à visit()) afin qu'ils puissent être résolus ultérieurement par le contexte. La sous-routine principale "BLOCK" est ensuite exécutée, en passant la référence du contexte comme paramètre. Le texte retourné par la sous-routine du template est ensuite retourné par la méthode process(), après avoir appelé la méthode leave() du contexte pour permettre le nettoyage et la dés-inscription des "BLOCKS" nommés précédemment installés.

Une méthode "AUTOLOAD" fournit l'accès aux éléments de "METADATA" du document. Le module Template::Service installe une référence à l'objet principal "Template::Document" dans le stash sous la variable "template". Ceci permet d'accéder aux éléments de métadonnées depuis l'intérieur des templates, y compris les templates "PRE_PROCESS".

header:

<html>
<head>
<title>[% template.title %]
</head>
...

Les objets "Template::Document" sont généralement créés par Template::Parser mais peuvent être instanciés manuellement ou sous-classés pour fournir des composants de template personnalisés.

MÉTHODES

new(\%config)

Méthode constructeur qui accepte une référence à un tableau associatif contenant la structure comme montré dans cet exemple :

$doc = Template::Document->new({
    BLOCK => sub { # code perl; retourne $quelque_chose },
    DEFBLOCKS => {
        header => sub { # code perl; retourne $quelque_chose },
        footer => sub { # blah blah blah; retourne $quelque_chose },
    },
    METADATA => {
        author  => 'Andy Wardley',
        version => 3.14,
    }
}) || die $Template::Document::ERROR;

Les éléments "BLOCK" et "DEFBLOCKS" peuvent être exprimés comme des références à des sous-routines Perl ou comme des chaînes de caractères contenant des définitions de sous-routines Perl, telles que générées par le module Template::Parser. Celles-ci sont évaluées en références de sous-routines à l'aide de eval().

Retourne un nouvel objet "Template::Document" ou "undef" en cas d'erreur. La méthode de classe error() peut être appelée, ou la variable de paquet $ERROR inspectée pour récupérer le message d'erreur pertinent.

process($context)

Routine de traitement principale pour le document de template compilé. Une référence à un objet Template::Context doit être passée comme premier paramètre. La méthode installe les blocs définis localement via un appel à la méthode visit() du contexte, traite son propre template (en passant la référence du contexte comme paramètre) puis appelle leave() dans le contexte pour permettre le nettoyage.

print $doc->process($context);

Retourne une chaîne de caractères représentant la sortie générée pour le template. Les erreurs sont lancées via die().

block()

Retourne une référence à la sous-routine principale "BLOCK".

blocks()

Retourne une référence au tableau associatif des "DEFBLOCKS" nommés.

variables()

Retourne une référence à un tableau associatif des variables utilisées dans le template. Ceci nécessite que l'option TRACE_VARS soit activée.

meta()

Retourne une référence à un tableau associatif de tout élément META défini dans le template.

AUTOLOAD

Une méthode autoload retourne les éléments de "METADATA".

print $doc->author();

MÉTHODES DE CLASSE

Ces méthodes sont utilisées en interne.

as_perl($content)

Cette méthode génère une représentation Perl du template.

my $perl = Template::Document->as_perl({
    BLOCK     => $main_block,
    DEFBLOCKS => {
        foo   => $foo_block,
        bar   => $bar_block,
    },
    METADATA  => {
        name  => 'my_template',
    }
});

write_perl_file(\%config)

Cette méthode est utilisée pour écrire des templates Perl compilés sur disque. Si l'option "COMPILE_EXT" (pour indiquer une extension de fichier pour enregistrer les templates compilés) est définie, le module Template::Parser appelle cette sous-routine avant d'appeler le constructeur new(). À ce stade, le parser a une représentation du template sous forme de chaînes de caractères contenant du code Perl. Nous pouvons l'écrire dans un fichier, encapsulé dans un petit wrapper qui nous permettra ensuite de faire un require() du fichier et de laisser Perl le parser et le compiler en un "Template::Document". Nous avons ainsi une persistance des templates compilés.

FONCTIONS INTERNES

catch_warnings()

Ceci est un gestionnaire simple utilisé pour intercepter toute erreur qui survient lorsque le code Perl compilé du template est évalué pour la première fois (c'est-à-dire, évalué par Perl pour créer une sous-routine de template lors de la compilation, plutôt que lors du traitement du template à l'exécution).

is_utf8()

Ceci est mappé à "utf8::is_utf8" pour les versions de Perl qui l'ont (> 5.008) ou à "Encode::is_utf8" pour Perl 5.008. Les versions antérieures de Perl ne sont pas prises en charge.
