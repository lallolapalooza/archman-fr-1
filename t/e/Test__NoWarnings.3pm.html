Test::NoWarnings(3pm) Documentation contributive de Perl Test::NoWarnings(3pm)

NOM

Test::NoWarnings - Assurez-vous de n'avoir émis aucune alerte pendant les tests

SYNOPSIS

Pour les scripts sans plan

use Test::More 'no_plan';
use Test::NoWarnings;

Tout le reste est optionnel

Pour les scripts qui ressemblent à

use Test::More tests => x;

changez en

use Test::More tests => x + 1;
use Test::NoWarnings;

Pour les scripts qui utilisent done_testing, utilisez :

use Test::More;
use Test::NoWarnings 'had_no_warnings';
... # vos tests
had_no_warnings;
done_testing;

DESCRIPTION

En général, vos tests ne devraient pas émettre d'alertes. Ce module capture toute alerte et la stocke. Il ajoute automatiquement un test supplémentaire qui s'exécutera à la fin de votre script pour vérifier qu'aucune alerte n'a été émise. S'il y a eu des alertes, le test échouera ("not ok") et fournira des diagnostics sur où, quand et quoi de l'alerte, y compris une pile d'appels de ce qui se passait lorsque l'alerte s'est produite.

Si certains de vos tests doivent émettre des alertes, vous devriez les capturer et les vérifier avec Test::Warn, de cette façon Test::NoWarnings ne les verra pas et ne se plaindra pas.

Le test est exécuté dans un bloc "END" de Test::NoWarnings. Il ne s'exécutera pas lorsque les processus enfants terminent.

UTILISATION

Le simple fait d'utiliser le module vous donne un test supplémentaire à la fin de votre script qui vérifie qu'aucune alerte n'a été émise. Donc, placez simplement

use Test::NoWarnings;

au début de votre script et continuez normalement.

Si vous voulez plus de contrôle, vous pouvez invoquer le test manuellement à tout moment avec "had_no_warnings".

Les alertes générées par votre test sont stockées dans un tableau. Vous pouvez y accéder et le vider quand vous le souhaitez avec warnings() et "clear_warnings", cependant, si vous faites cela, vous voudrez probablement utiliser Test::Warn en plus de Test::NoWarnings.

Si votre script est écrit en utilisant done_testing et n'a pas de plan de tests, vous devez appeler "had_no_warnings" avant d'appeler done_testing.

use vs require

Je vous recommanderais de faire

use Test::NoWarnings;

Si vous utilisez un "require" au lieu d'un "use", il n'y aura pas de test automatique à la fin de votre script.

Sortie

Si une alerte est capturée pendant votre test, les détails seront affichés dans le cadre des diagnostics. Vous obtiendrez :

  • le numéro et le nom du test qui s'est exécuté juste avant l'alerte (s'il n'y a pas eu de test exécuté, ce sera 0 et '')
  • le message qui a été passé à "warn",
  • une copie complète de la pile d'appels lorsque l'alerte a été appelée, grâce à la librairie "Carp"

Par défaut, tous les messages d'alerte sont émis dans un seul bloc à la fin de votre script.

Le pragma :early

L'une des principales critiques des utilisateurs de Test::NoWarnings est que toutes les alertes sont émises dans un seul bloc à la fin. Bien que ce soit le moment le plus sûr et le plus correct pour émettre ces diagnostics, cela peut rendre le débogage de ces alertes difficile.

Depuis Test::NoWarnings 1.04, vous pouvez fournir un pragma expérimental ":early" lors du chargement du module pour forcer l'émission des alertes via diag lorsqu'elles se produisent réellement.

use Test::NoWarnings ':early';

Mais cela provoquera l'émission du diag par rapport au test précédent et non celui dans lequel l'alerte s'est réellement produite. Par conséquent, il est recommandé de l'activer uniquement pour le débogage et de le désactiver lorsqu'il n'est pas nécessaire.

FONCTIONS

had_no_warnings

Ceci vérifie qu'aucune alerte n'a été émise par vos scripts de test. Généralement, vous ne l'appelez pas explicitement car elle est appelée automatiquement lorsque votre script se termine.

clear_warnings

Ceci effacera le tableau des alertes qui ont été capturées. Si le tableau est vide, un appel à had_no_warnings() produira un résultat de réussite.

warnings

Ceci retournera le tableau des alertes capturées jusqu'à présent. Chaque élément de ce tableau est un objet contenant des informations sur l'alerte. Les méthodes suivantes sont disponibles sur ces objets :

  • $warn->getMessage

    Obtient le message qui serait imprimé par l'alerte.

  • $warn->getCarp

    Obtient une pile d'appels de ce qui se passait lorsque l'alerte s'est produite ; cette pile est juste une chaîne générée par la librairie Carp.

  • $warn->getTrace

    Obtient une pile d'appels générée par la librairie Devel::StackTrace. Ceci retournera undef si Devel::StackTrace n'est pas installé.

  • $warn->getTest

    Obtient le numéro du test qui s'est exécuté avant l'alerte.

  • $warn->getTestName

    Obtient le nom du test qui s'est exécuté avant l'alerte.

PIÈGES

Lorsque vous comptez vos tests pour le plan, n'oubliez pas d'inclure le test qui s'exécute automatiquement lorsque votre script se termine.

La vérification des alertes se fait via $SIG{__WARN__}. Si d'autres modules utilisent ce hook, cela peut interférer avec le fonctionnement de ce module. Par exemple, l'utilisation de la librairie Carp::Always fera que ce module signalera toujours qu'il n'y a pas d'alertes.
