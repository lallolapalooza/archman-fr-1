NOM

Thread::Queue - Files d'attente sûres pour les threads

VERSION

Ce document décrit Thread::Queue version 3.14

SYNOPSIS

use strict;
use warnings;
use threads;
use Thread::Queue;
my $q = Thread::Queue->new();    # Une nouvelle file d'attente vide
# Thread de travail
my $thr = threads->create(
    sub {
        # Le thread bouclera jusqu'à ce qu'il n'y ait plus de travail
        while (defined(my $item = $q->dequeue())) {
            # Travailler sur $item
            ...
        }
    }
);
# Envoyer du travail au thread
$q->enqueue($item1, ...);
# Signaler qu'il n'y a plus de travail à envoyer
$q->end();
# Rejoindre le thread lorsqu'il se termine
$thr->join();
...
# Nombre d'éléments dans la file d'attente
my $left = $q->pending();
# Retrait non bloquant
if (defined(my $item = $q->dequeue_nb())) {
    # Travailler sur $item
}
# Retrait bloquant avec un délai d'attente de 5 secondes
if (defined(my $item = $q->dequeue_timed(5))) {
    # Travailler sur $item
}
# Définir une taille pour une file d'attente
$q->limit = 5;
# Obtenir le deuxième élément de la file d'attente sans rien retirer
my $item = $q->peek(1);
# Insérer deux éléments dans la file d'attente juste derrière la tête
$q->insert(1, $item1, $item2);
# Extraire les deux derniers éléments de la file d'attente
my ($item1, $item2) = $q->extract(-2, 2);

DESCRIPTION

Ce module fournit des files d'attente FIFO sûres pour les threads qui peuvent être accédées en toute sécurité par un nombre quelconque de threads.

Tous les types de données pris en charge par threads::shared peuvent être transmis via les files d'attente :

Scalaires ordinaires
Références de tableaux
Références de hachages
Références de scalaires
Objets basés sur ce qui précède

Les scalaires ordinaires sont ajoutés aux files d'attente tels quels.

S'ils ne sont pas déjà partagés entre threads, les autres types de données complexes seront clonés (récursivement, si nécessaire, et y compris tous les "bless"ages et paramètres en lecture seule) dans des structures partagées entre threads avant d'être placés dans une file d'attente.

Par exemple, ce qui suit amènerait Thread::Queue à créer une référence de tableau partagée vide via &shared([]), à y copier les éléments 'foo', 'bar' et 'baz' depuis @ary, puis à placer cette référence partagée dans la file d'attente :

my @ary = qw/foo bar baz/;
$q->enqueue(\@ary);

Cependant, dans ce qui suit, les éléments sont déjà partagés, donc leurs références sont ajoutées directement à la file d'attente, et aucun clonage n'a lieu :

my @ary :shared = qw/foo bar baz/;
$q->enqueue(\@ary);
my $obj = &shared({});
$$obj{'foo'} = 'bar';
$$obj{'qux'} = 99;
bless($obj, 'My::Class');
$q->enqueue($obj);

Voir "LIMITATIONS" pour les mises en garde liées au passage d'objets via les files d'attente.

CRÉATION DE FILE D'ATTENTE

->new()
Crée une nouvelle file d'attente vide.
->new(LISTE)
Crée une nouvelle file d'attente pré-remplie avec la liste d'éléments fournie.

MÉTHODES DE BASE

Les méthodes suivantes traitent les files d'attente selon un principe FIFO.

->enqueue(LISTE)
Ajoute une liste d'éléments à la fin de la file d'attente.
->dequeue()
->dequeue(NOMBRE)
Retire le nombre demandé d'éléments (1 par défaut) de la tête de la file d'attente et les renvoie. Si la file d'attente contient moins que le nombre demandé d'éléments, alors le thread sera bloqué jusqu'à ce que le nombre requis d'éléments soit disponible (c'est-à-dire jusqu'à ce que d'autres threads fassent un "enqueue" de plus d'éléments).
->dequeue_nb()
->dequeue_nb(NOMBRE)
Retire le nombre demandé d'éléments (1 par défaut) de la tête de la file d'attente et les renvoie. Si la file d'attente contient moins que le nombre demandé d'éléments, alors elle renvoie immédiatement (c'est-à-dire de manière non bloquante) tous les éléments présents dans la file d'attente. Si la file d'attente est vide, alors "undef" est renvoyé.
->dequeue_timed(DÉLAI)
->dequeue_timed(DÉLAI, NOMBRE)
Retire le nombre demandé d'éléments (1 par défaut) de la tête de la file d'attente et les renvoie. Si la file d'attente contient moins que le nombre demandé d'éléments, alors le thread sera bloqué jusqu'à ce que le nombre requis d'éléments soit disponible, ou jusqu'à ce que le délai d'attente soit atteint. Si le délai d'attente est atteint, elle renvoie tous les éléments présents dans la file d'attente, ou "undef" si la file d'attente est vide.

Le délai d'attente peut être un nombre de secondes relatif à l'heure actuelle (par exemple, 5 secondes à partir du moment où l'appel est effectué), ou peut être un délai d'attente absolu en secondes epoch identique à celui qui serait utilisé avec cond_timedwait(). Les secondes fractionnaires (par exemple, 2,5 secondes) sont également prises en charge (dans la mesure de l'implémentation sous-jacente).

Si "DÉLAI" est absent, "undef", ou inférieur ou égal à 0, alors cet appel se comporte comme "dequeue_nb".

->pending()
Renvoie le nombre d'éléments encore présents dans la file d'attente. Renvoie "undef" si la file d'attente a été terminée (voir ci-dessous), et qu'il n'y a plus d'éléments dans la file d'attente.
->limit
Définit la taille de la file d'attente. Si elle est définie, les appels à enqueue() bloqueront jusqu'à ce que le nombre d'éléments en attente dans la file d'attente descende en dessous de la "limit". La "limit" n'empêche pas de mettre en file d'attente des éléments au-delà de ce nombre : 
my $q = Thread::Queue->new(1, 2);
$q->limit = 4;
$q->enqueue(3, 4, 5);   # Ne bloque pas
$q->enqueue(6);         # Bloque jusqu'à ce qu'au moins 2 éléments soient
                        # retirés
my $size = $q->limit;   # Renvoie la limite actuelle (peut renvoyer
                        # 'undef')
$q->limit = 0;          # La taille de la file d'attente est maintenant illimitée

Appeler l'une des méthodes de retrait avec un "NOMBRE" supérieur à la "limit" d'une file d'attente générera une erreur.

->end()
Déclare qu'aucun autre élément ne sera ajouté à la file d'attente.

Tous les threads bloqués sur des appels à dequeue() seront débloqués avec tous les éléments restants dans la file d'attente et/ou "undef" renvoyé. Tout appel ultérieur à dequeue() se comportera comme dequeue_nb().

Une fois terminée, aucun autre élément ne peut être placé dans la file d'attente.

MÉTHODES AVANCÉES

Les méthodes suivantes peuvent être utilisées pour manipuler des éléments n'importe où dans une file d'attente.

Pour empêcher le contenu d'une file d'attente d'être modifié par un autre thread pendant qu'il est examiné et/ou modifié, verrouillez la file d'attente dans un bloc local :

{
    lock($q);   # Empêcher les autres threads de modifier le contenu de la file d'attente
    my $item = $q->peek();
    if ($item ...) {
        ...
    }
}
# La file d'attente est maintenant déverrouillée
->peek()
->peek(INDEX)
Renvoie un élément de la file d'attente sans rien retirer. Par défaut, la tête de la file d'attente (à la position d'index 0) si aucun index n'est spécifié. Les valeurs d'index négatives sont prises en charge comme avec les tableaux (c'est-à-dire que -1 est la fin de la file d'attente, -2 est l'avant-dernier, et ainsi de suite).

Si aucun élément n'existe à l'index spécifié (c'est-à-dire que la file d'attente est vide, ou que l'index dépasse le nombre d'éléments dans la file d'attente), alors "undef" est renvoyé.

N'oubliez pas que l'élément renvoyé n'est pas retiré de la file d'attente, donc manipuler une référence obtenue par "peek" affecte l'élément dans la file d'attente.

->insert(INDEX, LISTE)
Ajoute la liste d'éléments à la file d'attente à la position d'index spécifiée (0 est la tête de la liste). Tous les éléments existants à cette position et au-delà sont repoussés après les éléments nouvellement ajoutés : 
$q->enqueue(1, 2, 3, 4);
$q->insert(1, qw/foo bar/);
# La file d'attente contient maintenant :  1, foo, bar, 2, 3, 4

NAME

Thread::Queue - An object oriented, thread-safe queue.

VERSION

2.20

SYNOPSIS

  use Thread::Queue;
  my $q = Thread::Queue->new;
  $q->enqueue('item1', 'item2');
  my $item = $q->dequeue; # item1
  my @items = $q->items;
  my $empty = $q->is_empty;
  $q->replace(1, 'new_item');
  $q->insert(0, 'first_item');
  my $removed = $q->extract(1, 2); # Removes and returns 2 items starting at index 1

DESCRIPTION

This module provides an object oriented interface to a queue that is safe for use in multithreaded applications.

The queue is created using "Thread::Queue->new". The returned object supports the following methods:

QUEUE CREATION

new([ITEM,...])
Creates and returns a new queue object. Optionally, you can pass a list of items to pre-populate the queue.

BASIC METHODS

->enqueue(ITEM, ...)
Adds one or more items to the end (tail) of the queue.
->dequeue()
Removes and returns the item at the head of the queue. If the queue is empty, this method blocks until an item is available.
->dequeue_nb()
Removes and returns the item at the head of the queue. If the queue is empty, this method returns immediately with an undefined value (or an empty list if called in list context).
->is_empty()
Returns true if the queue currently contains no items, false otherwise.
->pending()
Returns the number of items currently in the queue.
->items()
Returns a list of all items currently in the queue, in order from head to tail. This method is primarily for debugging and inspection, and should not be relied upon in threaded code where the contents can change at any moment.
->clear()
Removes all items from the queue.

ADVANCED METHODS

->replace(INDEX, ITEM, ...)
Replaces the item at the specified index with the new item(s). The index is 0-based, with 0 being the head of the queue. If the index is out of bounds, the call has no effect. If multiple items are provided, they replace the single item at the specified index, effectively inserting them at that position.
->insert(INDEX, ITEM, ...)
Inserts one or more items into the queue at the specified index. The index is 0-based, with 0 being the head of the queue. Negative indices are supported, counting from the tail of the queue (-1 is the last item).

Specifying an index position greater than the number of items in the queue just adds the list to the end.

Negative index positions are supported:

$q->enqueue(1, 2, 3, 4);
$q->insert(-2, qw/foo bar/);
# Queue now contains:  1, 2, foo, bar, 3, 4

Specifying a negative index position greater than the number of items in the queue adds the list to the head of the queue.

->extract()
->extract(INDEX)
->extract(INDEX, COUNT)
Removes and returns the specified number of items (defaults to 1) from the specified index position in the queue (0 is the head of the queue). When called with no arguments, "extract" operates the same as "dequeue_nb".

This method is non-blocking, and will return only as many items as are available to fulfill the request:

$q->enqueue(1, 2, 3, 4);
my $item  = $q->extract(2)     # Returns 3
                               # Queue now contains:  1, 2, 4
my @items = $q->extract(1, 3)  # Returns (2, 4)
                               # Queue now contains:  1

Specifying an index position greater than the number of items in the queue results in "undef" or an empty list being returned.

$q->enqueue('foo');
my $nada = $q->extract(3)      # Returns undef
my @nada = $q->extract(1, 3)   # Returns ()

Negative index positions are supported. Specifying a negative index position greater than the number of items in the queue may return items from the head of the queue (similar to "dequeue_nb") if the count overlaps the head of the queue from the specified position (i.e. if queue size + index + count is greater than zero):

$q->enqueue(qw/foo bar baz/);
my @nada = $q->extract(-6, 2);  # Returns ()      - (3+(-6)+2) <= 0
my @some = $q->extract(-6, 4);  # Returns (foo)   - (3+(-6)+4) > 0
                                # Queue now contains:  bar, baz
my @rest = $q->extract(-3, 4);  # Returns (bar, baz) -
                                #                   (2+(-3)+4) > 0

NOTES

Queues created by Thread::Queue can be used in both threaded and non-threaded applications.

LIMITATIONS

Passing objects on queues may not work if the objects' classes do not support sharing. See "BUGS AND LIMITATIONS" in threads::shared for more.

Passing array/hash refs that contain objects may not work for Perl prior to 5.10.0.
