NOM

Throwable - un rôle pour les classes qui peuvent être levées

VERSION

version 1.001

SYNOPSIS

package Redirect;
# REMARQUE : Moo peut aussi être utilisé ici au lieu de Moose
use Moose;
with 'Throwable';
has url => (is => 'ro');

...puis plus tard...

Redirect->throw({ url => $url });

DESCRIPTION

Throwable est un rôle destiné aux classes qui sont censées être levées comme exceptions pour interrompre le flux d'exécution normal du programme. Il est très simple et ne fait que deux choses : sauvegarder toute valeur précédente pour $@ et appeler "die $self".

Throwable est implémenté avec Moo, vous pouvez donc utiliser Moo ou Moose, selon votre préférence.

VERSION PERL

Cette bibliothèque devrait fonctionner sur des versions de Perl sorties depuis longtemps. Elle devrait fonctionner sur toute version de Perl sortie au cours des cinq dernières années.

Bien qu'elle puisse fonctionner sur des versions plus anciennes de Perl, aucune garantie n'est faite que la version minimale requise ne sera pas augmentée. La version peut être augmentée pour quelque raison que ce soit, et il n'est pas promis que des correctifs seront acceptés pour abaisser la version minimale de Perl requise.

ATTRIBUTS

exception_precedente

Cet attribut est créé automatiquement et stocke la valeur de $@ lorsque l'objet Throwable est créé. Ceci est fait sur une base de meilleur effort. $@ est sujet à de nombreuses actions étranges à distance. Pour l'instant, il existe clairement des moyens par lesquels l'exception précédente pourrait être perdue.

MÉTHODES

throw

Something::Throwable->throw({ attr => $value });

Cette méthode appellera `new`, en passant tous les arguments à `new`, puis utilisera l'objet créé comme seul argument pour "die".

Si elle est appelée sur un objet qui implémente Throwable, l'objet sera relancé.

new_with_previous

die Something::Throwable->new_with_previous({ attr => $value });

Construit un objet exception et le retourne, tout en essayant de s'assurer que toutes les valeurs dans $@ sont sauvegardées en toute sécurité dans "exception_precedente" sans être écrasées par des `eval` pendant le processus de construction.

Ceci est plus fiable que d'appeler `new` directement, mais n'inclut pas le `die` forcé de la méthode `throw`.
