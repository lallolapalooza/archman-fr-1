Module Thread

Threads légers pour Posix 1003.1c et Win32.

type t

Le type des descripteurs de thread.

Création et terminaison de threads

val create : ('a -> 'b) -> 'a -> t

Thread.create funct arg crée un nouveau thread de contrôle, dans lequel l'application de la fonction funct arg est exécutée concurremment avec les autres threads du domaine. L'application de Thread.create retourne le descripteur du nouveau thread créé. Le nouveau thread se termine lorsque l'application funct arg retourne, soit normalement, soit en levant l'exception Thread.Exit, soit en levant toute autre exception non capturée. Dans ce dernier cas, l'exception non capturée est affichée sur la sortie d'erreur standard, mais n'est pas propagée au thread parent. De même, le résultat de l'application funct arg est ignoré et n'est pas directement accessible au thread parent.

Voir aussi Domain.spawn si vous préférez une exécution parallèle.

val self : unit -> t

Retourne le descripteur du thread en cours d'exécution.

val id : t -> int

Retourne l'identifiant du thread donné. Un identifiant de thread est un entier qui identifie le thread de manière unique. Il peut être utilisé pour construire des structures de données indexées par les threads.

val set_current_thread_name : string -> unit

Définit le nom du thread. Ceci devrait être appelé depuis la fonction du thread. La définition du nom de thread est disponible sur la plupart des systèmes.

Ceci ne fait rien si la fonctionnalité n'est pas implémentée, mais affichera un avertissement sur la sortie d'erreur standard si elle est activée.

De même, un avertissement est affiché si l'opération échoue.

Depuis 5.4

exception Exit

Exception levée par le code utilisateur pour initier la terminaison du thread courant. Dans un thread créé par Thread.create funct arg, si l'exception Thread.Exit atteint le sommet de l'application funct arg, elle a pour effet de terminer silencieusement le thread courant. Dans d'autres contextes, il n'y a pas de traitement implicite de l'exception Thread.Exit.

val exit : unit -> unit

Obsolète. Utilisez 'raise Thread.Exit' à la place.

Lève l'exception Thread.Exit. Dans un thread créé par Thread.create, cela entraînera la terminaison prématurée du thread, sauf si la fonction du thread gère elle-même l'exception. Les finaliseurs de Fun.protect et les gestionnaires d'exception généraux seront exécutés.

Pour qu'il soit clair qu'une exception est levée et qu'elle déclenchera les finaliseurs et les gestionnaires d'exception généraux, il est recommandé d'écrire raise Thread.Exit plutôt que Thread.exit ().

Avant 5.0 Une implémentation différente était utilisée, non basée sur le fait de lever une exception, et n'exécutant pas les finaliseurs et les gestionnaires généraux. L'implémentation précédente avait un comportement différent lorsqu'elle était appelée en dehors d'un thread créé par Thread.create.

Suspension des threads

val delay : float -> unit

delay d suspend l'exécution du thread appelant pendant d secondes. Les autres threads du programme continuent de s'exécuter pendant ce temps.

val join : t -> unit

join th suspend l'exécution du thread appelant jusqu'à ce que le thread th se soit terminé.

val yield : unit -> unit

Ré-ordonnance le thread appelant sans le suspendre. Cette fonction peut être utilisée pour donner des indications à l'ordonnanceur, lui disant qu'il est temps de passer à d'autres threads.

Attente de descripteurs de fichier ou de processus

Les fonctions ci-dessous sont des restes d'un ancien système de threads basé sur la VM. Le module Unix fournit une fonctionnalité équivalente, de manière plus générale et plus conforme aux normes. Il est recommandé d'utiliser directement les fonctions Unix.

val wait_timed_read : Unix.file_descr -> float -> bool

Obsolète. Utilisez Unix.select à la place.

Voir Thread.wait_timed_write.

val wait_timed_write : Unix.file_descr -> float -> bool

Obsolète. Utilisez Unix.select à la place.

Suspend l'exécution du thread appelant jusqu'à ce qu'au moins un caractère ou la fin de fichier soit disponible en lecture ( wait_timed_read ) ou qu'un caractère puisse être écrit sans bloquer ( wait_timed_write ) sur le descripteur de fichier Unix donné. Attend au maximum le temps donné en deuxième argument (en secondes). Retourne true si le descripteur de fichier est prêt pour l'entrée/sortie et false si le délai d'attente a expiré. La même fonctionnalité peut être obtenue avec Unix.select.

val select : Unix.file_descr list -> Unix.file_descr list -> Unix.file_descr list -> float -> Unix.file_descr list * Unix.file_descr list * Unix.file_descr list

Obsolète. Utilisez Unix.select à la place.

Même fonction que Unix.select. Suspend l'exécution du thread appelant jusqu'à ce que l'entrée/sortie devienne possible sur les descripteurs de fichier Unix donnés. Les arguments et les résultats ont la même signification que pour Unix.select.

val wait_pid : int -> int * Unix.process_status

Obsolète. Utilisez Unix.waitpid à la place.

Même fonction que Unix.waitpid. wait_pid p suspend l'exécution du thread appelant jusqu'à ce que le processus spécifié par l'identifiant de processus p se termine. Retourne le pid de l'enfant attrapé et son statut de terminaison, conformément à Unix.wait.

Gestion des signaux

La gestion des signaux suit le modèle des threads POSIX : les signaux générés par un thread lui sont délivrés ; les signaux générés extérieurement sont délivrés à l'un des threads qui ne les bloque pas. Chaque thread possède un ensemble de signaux bloqués, qui peut être modifié à l'aide de Thread.sigmask. Cet ensemble est hérité lors de la création du thread. Les masques de signaux par thread ne sont supportés que par la bibliothèque de threads système sous Unix, mais pas sous Win32, ni par la bibliothèque de threads de la VM.

val sigmask : Unix.sigprocmask_command -> int list -> int list

Même fonction que Unix.sigprocmask. sigmask cmd sigs modifie l'ensemble des signaux bloqués pour le thread appelant. Si cmd est SIG_SETMASK, les signaux bloqués sont définis sur ceux de la liste sigs. Si cmd est SIG_BLOCK, les signaux dans sigs sont ajoutés à l'ensemble des signaux bloqués. Si cmd est SIG_UNBLOCK, les signaux dans sigs sont retirés de l'ensemble des signaux bloqués. sigmask retourne l'ensemble des signaux précédemment bloqués pour le thread.

val wait_signal : int list -> int

Même fonction que Unix.sigwait. wait_signal sigs suspend l'exécution du thread appelant jusqu'à ce que le processus reçoive l'un des signaux spécifiés dans la liste sigs. Il retourne alors le numéro du signal reçu. Les gestionnaires de signaux attachés aux signaux dans sigs ne seront pas invoqués. Les signaux sigs sont censés être bloqués avant d'appeler wait_signal.

Exceptions non capturées

val default_uncaught_exception_handler : exn -> unit

Thread.default_uncaught_exception_handler affichera l'ID du thread, l'exception et la trace de la pile (si disponible).

val set_uncaught_exception_handler : (exn -> unit) -> unit

Thread.set_uncaught_exception_handler fn enregistre fn comme gestionnaire pour les exceptions non capturées.

Si le nouveau gestionnaire d'exception non capturée lève une exception, Thread.default_uncaught_exception_handler sera appelé.
