Thread(3perl) Guide de référence du programmeur Perl Thread(3perl)

NOM

Thread - Manipuler les threads en Perl (pour le code ancien uniquement)

DÉPRECATION

Le module "Thread" servait d'interface à l'ancien modèle de threads, appelé 5005threads, qui a été introduit dans la version 5.005. Ce modèle est déprécié et a été supprimé dans la version 5.10.

Pour la compatibilité ascendante avec du code ancien et transitoire, le module "Thread" a été retravaillé pour fonctionner comme une interface au nouveau modèle de threads d'interpréteur (ithreads). Cependant, certaines fonctionnalités précédentes ne sont pas disponibles. De plus, les modèles de partage de données entre les deux modèles de threads sont complètement différents, et tout ce qui concerne le partage de données doit être abordé différemment. Avec ithreads, vous devez explicitement share() des variables entre les threads.

Il est fortement recommandé de migrer tout code utilisant des threads vers le nouveau modèle (c'est-à-dire utiliser les modules "threads" et "threads::shared") dès que possible.

HISTOIRE

Dans Perl 5.005, le modèle de threads impliquait que toutes les données étaient implicitement partagées, et l'accès partagé aux données devait être explicitement synchronisé. Ce modèle est appelé 5005threads.

Dans Perl 5.6, un nouveau modèle a été introduit dans lequel toutes les données sont locales au thread et l'accès partagé aux données doit être explicitement déclaré. Ce modèle est appelé ithreads, pour « threads d'interpréteur ».

Dans Perl 5.6, le modèle ithreads n'était pas disponible en tant qu'API publique ; seulement en tant qu'API interne disponible pour les auteurs d'extensions, et pour implémenter l'émulation de fork() sur les plateformes Win32.

Dans Perl 5.8, le modèle ithreads est devenu disponible via le module "threads", et le modèle 5005threads a été déprécié.

Dans Perl 5.10, le modèle 5005threads a été supprimé de l'interpréteur Perl.

SYNTAXE

use Thread qw(:DEFAULT async yield);
my $t = Thread->new(\&start_sub, @start_args);
$result = $t->join;
$t->detach;
if ($t->done) {
    $t->join;
}
if($t->equal($another_thread)) {
    # ...
}
yield();
my $tid = Thread->self->tid;
lock($scalar);
lock(@array);
lock(%hash);
my @list = Thread->list;

DESCRIPTION

Le module "Thread" fournit un support de multithreading pour Perl.

FONCTIONS

$thread = Thread->new(\&start_sub)
$thread = Thread->new(\&start_sub, LIST)
"new" démarre un nouveau thread d'exécution dans la sous-routine référencée. La liste optionnelle est passée en tant que paramètres à la sous-routine. L'exécution continue à la fois dans la sous-routine et dans le code après l'appel "new".

"Thread->new" retourne un objet thread représentant le thread nouvellement créé.

lock VARIABLE
"lock" place un verrou sur une variable jusqu'à ce que le verrou sorte de portée.

Si la variable est verrouillée par un autre thread, l'appel "lock" bloquera jusqu'à ce qu'elle soit disponible. "lock" est récursif, donc plusieurs appels à "lock" sont sûrs - la variable restera verrouillée jusqu'à ce que le verrou le plus externe sur la variable sorte de portée.

Les verrous sur les variables n'affectent que les appels "lock" - ils n'affectent pas l'accès normal à une variable. (Les verrous sur les subs sont différents et abordés plus loin.) Si vous voulez vraiment, vraiment que les verrous bloquent l'accès, alors liez-les à quelque chose et gérez cela vous-même. Ceci est fait à dessein. Bien que la gestion de l'accès aux variables soit une bonne chose, Perl ne vous expulse pas de son salon...

Si un objet conteneur, tel qu'une table de hachage ou un tableau, est verrouillé, tous les éléments de ce conteneur ne sont pas verrouillés. Par exemple, si un thread exécute "lock @a", tout autre thread exécutant un lock($a[12]) ne bloquera pas.

Enfin, "lock" traverse les références exactement un niveau. lock(\$a) est équivalent à lock($a), tandis que lock(\\$a) ne l'est pas.

async BLOC;
"async" crée un thread pour exécuter le bloc qui le suit immédiatement. Ce bloc est traité comme une sub anonyme, et doit donc avoir un point-virgule après l'accolade fermante. Comme "Thread->new", "async" retourne un objet thread.
Thread->self
La fonction "Thread->self" retourne un objet thread qui représente le thread effectuant l'appel "Thread->self".
Thread->list
Retourne une liste de tous les objets Thread non joints et non détachés.
cond_wait VARIABLE
La fonction "cond_wait" prend une variable verrouillée comme paramètre, déverrouille la variable et bloque jusqu'à ce qu'un autre thread exécute "cond_signal" ou "cond_broadcast" pour cette même variable verrouillée. La variable sur laquelle "cond_wait" a bloqué est relockée après que "cond_wait" soit satisfaite. S'il y a plusieurs threads en "cond_wait" sur la même variable, tous sauf un seront relockés en attendant de réacquérir le verrou sur la variable. (Donc, si vous n'utilisez "cond_wait" que pour la synchronisation, libérez le verrou dès que possible.)
cond_signal VARIABLE
La fonction "cond_signal" prend une variable verrouillée comme paramètre et débloque un thread qui est en "cond_wait" sur cette variable. S'il y a plus d'un thread bloqué en "cond_wait" sur cette variable, un seul (et lequel est indéterminé) sera débloqué.

S'il n'y a pas de threads bloqués en "cond_wait" sur la variable, le signal est ignoré.

cond_broadcast VARIABLE
La fonction "cond_broadcast" fonctionne similairement à "cond_signal". "cond_broadcast" débloquera cependant tous les threads qui sont bloqués en "cond_wait" sur la variable verrouillée, plutôt qu'un seul.
yield
La fonction "yield" permet à un autre thread de prendre le contrôle du CPU. Les résultats exacts dépendent de l'implémentation.

MÉTHODES

join
"join" attend qu'un thread se termine et retourne toutes les valeurs avec lesquelles le thread est sorti. "join" bloquera jusqu'à ce que le thread soit terminé, bien qu'il ne bloquera pas si le thread s'est déjà terminé.

Si le thread sur lequel on appelle "join" a effectué un "die", l'erreur avec laquelle il est mort sera retournée à ce moment-là. Si vous ne voulez pas que le thread effectuant le "join" meure également, vous devriez soit encapsuler le "join" dans un "eval", soit utiliser la méthode de thread "eval" au lieu de "join".

Thread(3pm) — Perl threading library

METHODS

The following methods are available:

detach
"detach" indique à un thread qu'il ne sera jamais joint, c'est-à-dire que toutes les traces de son existence peuvent être supprimées une fois qu'il aura cessé de s'exécuter. Les erreurs dans les threads détachés ne seront visibles nulle part. Si vous souhaitez les intercepter, vous devriez utiliser $SIG{__DIE__} ou quelque chose de similaire.
equal
"equal" teste si deux objets de thread représentent le même thread et renvoie vrai s'ils le font.
tid
La méthode "tid" renvoie le tid d'un thread. Le tid est un entier qui augmente de manière monotone et qui est attribué lorsqu'un thread est créé. Le thread principal d'un programme aura un tid de zéro, tandis que les threads suivants auront des tids attribués à partir de un.
done
La méthode "done" renvoie vrai si le thread que vous vérifiez a terminé son exécution, et faux sinon.

DEFUNCT

Les éléments suivants étaient implémentés avec 5005threads, mais ne sont plus disponibles avec ithreads.

lock(\&sub)
Avec 5005threads, vous pouviez également "lock" une sous-routine de telle sorte que tout appel à cette sous-routine depuis un autre thread serait bloqué jusqu'à ce que le verrou soit libéré.

De plus, les sous-routines pouvaient être déclarées avec l'attribut ":locked", ce qui sérialisait l'accès à la sous-routine, mais permettait à différents threads un accès non simultané.

eval
La méthode "eval" encapsulait un "eval" autour d'un "join", attendant ainsi qu'un thread se termine, transmettant toutes les valeurs que le thread aurait pu renvoyer et plaçant toutes les erreurs dans $@.
flags
La méthode "flags" renvoyait les indicateurs (flags) pour le thread - une valeur entière correspondant aux indicateurs internes du thread.

VOIR AUSSI

threads, threads::shared, Thread::Queue, Thread::Semaphore
