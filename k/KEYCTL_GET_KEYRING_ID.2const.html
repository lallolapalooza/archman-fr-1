KEYCTL_GET_KEYRING_ID(2const) KEYCTL_GET_KEYRING_ID(2const)

NOM

KEYCTL_GET_KEYRING_ID - mapper un ID de clé spécial à un ID de clé réel pour ce processus

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/keyctl.h>  /* Définition des constantes KEY* */
#include <sys/syscall.h>   /* Définition des constantes SYS_* */
#include <unistd.h>
long syscall(SYS_keyctl, KEYCTL_GET_KEYRING_ID, key_serial_t key,
             int arg3);

DESCRIPTION

Mapper un ID de clé spécial à un ID de clé réel pour ce processus.

Cette opération recherche la clé spéciale dont l'ID est fourni dans key. Si la clé spéciale est trouvée, l'ID de la clé réelle correspondante est retourné comme résultat de la fonction. Les valeurs suivantes peuvent être spécifiées dans key :

KEY_SPEC_THREAD_KEYRING
Ceci spécifie la keyring spécifique au thread de l'appelant. Voir thread-keyring(7).
KEY_SPEC_PROCESS_KEYRING
Ceci spécifie la keyring spécifique au processus de l'appelant. Voir process-keyring(7).
KEY_SPEC_SESSION_KEYRING
Ceci spécifie la keyring spécifique à la session de l'appelant. Voir session-keyring(7).
KEY_SPEC_USER_KEYRING
Ceci spécifie la keyring spécifique à l'UID de l'appelant. Voir user-keyring(7).
KEY_SPEC_USER_SESSION_KEYRING
Ceci spécifie la keyring session-UID de l'appelant. Voir user-session-keyring(7).
KEY_SPEC_REQKEY_AUTH_KEY (depuis Linux 2.6.16)
Ceci spécifie la clé d'autorisation créée par request_key(2) et passée au processus qu'elle lance pour générer une clé. Cette clé n'est disponible que dans un programme de type request-key(8) auquel le noyau a passé une clé d'autorisation et cesse d'être disponible une fois la clé demandée instanciée ; voir request_key(2).
KEY_SPEC_REQUESTOR_KEYRING (depuis Linux 2.6.29)
Ceci spécifie l'ID de la clé pour la keyring de destination de request_key(2). Cette keyring n'est disponible que dans un programme de type request-key(8) auquel le noyau a passé une clé d'autorisation et cesse d'être disponible une fois la clé demandée instanciée ; voir request_key(2).

Le comportement si la clé spécifiée dans key n'existe pas dépend de la valeur de arg3. Si arg3 contient une valeur non nulle, alors — s'il est approprié de le faire (par exemple, lors de la recherche de la clé utilisateur, session-utilisateur ou session) — une nouvelle clé est créée et son ID réel est retourné comme résultat de la fonction. Sinon, l'opération échoue avec l'erreur ENOKEY.

Si un ID de clé valide est spécifié dans key, et que la clé existe, alors cette opération retourne simplement l'ID de la clé. Si la clé n'existe pas, l'appel échoue avec l'erreur ENOKEY.

L'appelant doit avoir la permission de recherche sur une keyring pour qu'elle soit trouvée.

VALEUR DE RETOUR

En cas de succès, l'ID de la keyring demandée.

En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

ENOKEY
La clé spécifiée dans key n'existait pas, et arg3 était zéro (ce qui signifie ne pas créer la clé si elle n'existait pas).

VERSIONS

Un wrapper est fourni dans la bibliothèque libkeyutils : keyctl_get_keyring_ID(3).

NORMES

Linux.

HISTORIQUE

Linux 2.6.10.

VOIR AUSSI

keyctl(2), keyctl_get_keyring_ID(3)
