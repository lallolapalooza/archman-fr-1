KEYCTL_ASSUME_AUTHORITY(2const) KEYCTL_ASSUME_AUTHORITY(2const)

NOM

KEYCTL_ASSUME_AUTHORITY - assumer l'autorité d'instancier une clé

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/keyctl.h>  /* Définition des constantes KEY* */
#include <sys/syscall.h>   /* Définition des constantes SYS_* */
#include <unistd.h>
long syscall(SYS_keyctl, KEYCTL_ASSUME_AUTHORITY, key_serial_t key);

DESCRIPTION

Assume (ou abandonne) l'autorité pour le thread appelant d'instancier une clé.

L'argument key spécifie soit un ID de clé non nul pour assumer l'autorité, soit la valeur 0 pour abandonner l'autorité.

Si key est non nul, il spécifie l'ID d'une clé non instanciée pour laquelle l'autorité doit être assumée. Cette clé peut alors être instanciée en utilisant KEYCTL_INSTANTIATE(2const), KEYCTL_INSTANTIATE_IOV(2const), KEYCTL_REJECT(2const), ou KEYCTL_NEGATE(2const). Une fois la clé instanciée, le thread est automatiquement déchargé de l'autorité pour instancier la clé.

L'autorité sur une clé ne peut être assumée que si le thread appelant possède dans ses keyrings la clé d'autorisation associée à la clé spécifiée. (Autrement dit, l'opération KEYCTL_ASSUME_AUTHORITY est disponible uniquement depuis un programme de type request-key(8) ; voir request_key(2) pour une explication de la façon dont cette opération est utilisée.) L'appelant doit avoir la permission de *recherche* sur la clé d'autorisation.

Si la clé spécifiée a une clé d'autorisation correspondante, alors l'ID de cette clé est retourné. La clé d'autorisation peut être lue (KEYCTL_READ(2const)) pour obtenir les informations d'appel transmises à request_key(2).

Si l'ID donné dans key est 0, alors l'autorité actuellement assumée est effacée (abandonnée), et la valeur 0 est retournée.

Le mécanisme KEYCTL_ASSUME_AUTHORITY permet à un programme tel que request-key(8) d'assumer l'autorité nécessaire pour instancier une nouvelle clé non instanciée qui a été créée suite à un appel à request_key(2). Pour plus d'informations, voir request_key(2) et le fichier source du noyau Documentation/security/keys-request-key.txt.

VALEUR RENVOYÉE

En cas de succès, soit 0, si l'ID donné était 0, soit l'ID de la clé d'autorisation correspondant à la clé spécifiée, si un ID de clé non nul a été fourni.

En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

VERSIONS

Un wrapper est fourni dans la bibliothèque libkeyutils : keyctl_assume_authority(3).

NORMES

Linux.

HISTORIQUE

Linux 2.6.16.

VOIR AUSSI

keyctl(2), keyctl_assume_authority(3)
