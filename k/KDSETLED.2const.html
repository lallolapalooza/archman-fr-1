ioctl_kd(2) Manuel des appels système ioctl_kd(2)

NOM

ioctl_kd - ioctls pour le terminal console et les consoles virtuelles

SYNOPSIS

#include <linux/kd.h>  /* Définition des constantes d'opération */
#include <sys/ioctl.h>
int ioctl(int fd, unsigned long op, void *argp);

DESCRIPTION

Les opérations ioctl(2) suivantes, spécifiques à Linux, sont prises en charge pour les terminaux consoles et les consoles virtuelles.

KDGETLED
Obtenir l'état des LEDs. argp pointe vers un char. Les trois bits de poids faible de *argp sont définis sur l'état des LEDs, comme suit :
LED_CAP 0x04 LED de Verr. Maj.
LED_NUM 0x02 LED de Verr. Num.
LED_SCR 0x01 LED de Verr. Arrêt
KDSETLED
Définir les LEDs. Les LEDs sont définies pour correspondre aux trois bits de poids faible de l'entier non signé dans argp. Cependant, si un bit d'ordre supérieur est défini, les LEDs reviennent à la normale : affichant l'état des fonctions du clavier de Verr. Maj., Verr. Num. et Verr. Arrêt.

Avant Linux 1.1.54, les LEDs reflétaient simplement l'état des drapeaux correspondants du clavier, et KDGETLED/KDSETLED modifiaient également les drapeaux du clavier. Depuis Linux 1.1.54, les LEDs peuvent afficher des informations arbitraires, mais par défaut elles affichent les drapeaux du clavier. Les deux ioctls suivants sont utilisés pour accéder aux drapeaux du clavier.

KDGKBLED
Obtenir les drapeaux du clavier Verr. Maj., Verr. Num., Verr. Arrêt (pas les lumières). argp pointe vers un caractère qui est défini sur l'état du drapeau. Les bits de faible ordre (masque 0x7) obtiennent l'état actuel du drapeau, et les bits de faible ordre de la nibble suivante (masque 0x70) obtiennent l'état par défaut du drapeau. (Depuis Linux 1.1.54.)
KDSKBLED
Définir les drapeaux du clavier Verr. Maj., Verr. Num., Verr. Arrêt (pas les lumières). argp est un entier non signé qui contient l'état souhaité du drapeau. Les bits de faible ordre (masque 0x7) ont l'état du drapeau, et les bits de faible ordre de la nibble suivante (masque 0x70) ont l'état par défaut du drapeau. (Depuis Linux 1.1.54.)
KDGKBTYPE
Obtenir le type de clavier. Renvoie la valeur KB_101, définie comme 0x02.
KDADDIO
Ajouter un port d'E/S comme valide. Équivalent à ioperm(arg,1,1).
KDDELIO
Supprimer un port d'E/S comme valide. Équivalent à ioperm(arg,1,0).
KDENABIO
Activer les E/S vers la carte vidéo. Équivalent à ioperm(0x3b4, 0x3df-0x3b4+1, 1).
KDDISABIO
Désactiver les E/S vers la carte vidéo. Équivalent à ioperm(0x3b4, 0x3df-0x3b4+1, 0).
KDSETMODE
Définir le mode texte/graphique. argp est un entier non signé contenant l'une des valeurs suivantes :
KD_TEXT 0x00
KD_GRAPHICS 0x01
KDGETMODE
Obtenir le mode texte/graphique. argp pointe vers un int qui est défini sur l'une des valeurs indiquées ci-dessus pour KDSETMODE.
KDMKTONE
Générer un son de durée spécifiée. Les 16 bits de poids faible de l'entier non signé dans argp spécifient la période en cycles d'horloge, et les 16 bits de poids fort indiquent la durée en millisecondes. Si la durée est de zéro, le son est désactivé. Le contrôle est rendu immédiatement. Par exemple, argp = (125<<16) + 0x637 spécifierait le bip normalement associé à un ctrl-G. (Depuis Linux 0.99pl1 ; défectueux dans Linux 2.1.49-50.)
KIOCSOUND
Démarrer ou arrêter la génération sonore. Les 16 bits de poids faible de argp spécifient la période en cycles d'horloge (c'est-à-dire, argp = 1193180/fréquence). argp = 0 désactive le son. Dans les deux cas, le contrôle est rendu immédiatement.
GIO_CMAP
Obtenir la carte de couleurs par défaut actuelle du noyau. argp pointe vers un tableau de 48 octets. (Depuis Linux 1.3.3.)
PIO_CMAP
Changer la carte de couleurs texte par défaut. argp pointe vers un tableau de 48 octets qui contient, dans l'ordre, les valeurs Rouge, Verte et Bleue pour les 16 couleurs d'écran disponibles : 0 est éteint, et 255 est pleine intensité. Les couleurs par défaut sont, dans l'ordre : noir, rouge foncé, vert foncé, marron, bleu foncé, violet foncé, cyan foncé, gris clair, gris foncé, rouge vif, vert vif, jaune, bleu vif, violet vif, cyan vif, et blanc. (Depuis Linux 1.3.3.)
GIO_FONT
Récupère la police d'écran de 256 caractères sous forme étendue. argp pointe vers un tableau de 8192 octets. Échoue avec le code d'erreur EINVAL si la police actuellement chargée est une police de 512 caractères, ou si la console n'est pas en mode texte.
GIO_FONTX
Récupère la police d'écran et les informations associées. argp pointe vers une struct consolefontdesc (voir PIO_FONTX). À l'appel, le champ charcount doit être défini sur le nombre maximum de caractères qui rentreraient dans le tampon pointé par chardata. Au retour, charcount et charheight sont remplis avec les données respectives de la police actuellement chargée, et le tableau chardata contient les données de la police si la valeur initiale de charcount indiquait que l'espace disponible était suffisant ; sinon, le tampon est inchangé et errno est défini à ENOMEM. (Depuis Linux 1.3.1.)
PIO_FONT
Définit la police d'écran de 256 caractères. Charge la police dans le générateur de caractères EGA/VGA. argp pointe vers une carte de 8192 octets, avec 32 octets par caractère. Seuls les N premiers sont utilisés pour une police de 8xN (0 < N <= 32). Cet appel invalide également le mappage Unicode.
PIO_FONTX
Définit la police d'écran et les informations de rendu associées. argp pointe vers une

struct consolefontdesc {
    unsigned short charcount;  /* caractères dans la police
                                  (256 ou 512) */
    unsigned short charheight; /* lignes de balayage par
                                  caractère (1-32) */
    char          *chardata;   /* données de la police en
                                  forme étendue */
};

Si nécessaire, l'écran sera redimensionné de manière appropriée, et SIGWINCH sera envoyé aux processus appropriés. Cet appel invalide également le mappage Unicode. (Depuis Linux 1.3.1.)
PIO_FONTRESET
Réinitialise la police d'écran, la taille et le mappage Unicode aux valeurs par défaut au démarrage. argp n'est pas utilisé, mais doit être défini à NULL pour assurer la compatibilité avec les futures versions de Linux. (Depuis Linux 1.3.28.)
GIO_SCRNMAP
Récupère la carte d'écran du noyau. argp pointe vers une zone de taille E_TABSZ, qui est chargée avec les positions de police utilisées pour afficher chaque caractère. Cet appel risque de renvoyer des informations inutiles si la police actuellement chargée contient plus de 256 caractères.
GIO_UNISCRNMAP
Récupère la carte d'écran Unicode complète du noyau. argp pointe vers une zone de taille E_TABSZ*sizeof(unsigned short), qui est chargée avec les Unicodes que représente chaque caractère. Un ensemble spécial d'Unicodes, commençant à U+F000, est utilisé pour représenter les mappages "directement dans la police". (Depuis Linux 1.3.1.)
PIO_SCRNMAP
Charge la table "définissable par l'utilisateur" (quatrième) dans le noyau, qui mappe les octets vers les symboles de l'écran de la console. argp pointe vers une zone de taille E_TABSZ.

NOM

PIO_UNISCRNMAP

SYNTAXE

ioctl(2)

DESCRIPTION

Charge la table "définissable par l'utilisateur" (quatrième) dans le noyau qui mappe les octets aux unicodes, lesquels sont ensuite traduits en symboles d'écran selon la table de mappage actuelle des unicodes vers la police. Les unicodes spéciaux commençant par U+F000 peuvent être utilisés directement pour mapper vers des symboles de police. (Depuis Linux 1.3.1.)

VALEUR DE RETOUR

En cas de succès, 0 est retourné (même si indiqué autrement). En cas d'échec, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EINVAL
argp est invalide.

STANDARDS

Linux.

VOIR AUSSI

ioctl(2), ioctl_console(2)

AUTRES FORMATS

Autres formats : txt, raw
