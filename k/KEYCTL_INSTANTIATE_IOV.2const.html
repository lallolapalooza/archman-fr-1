KEYCTL_INSTANTIATE(2const) KEYCTL_INSTANTIATE(2const)

NOM

KEYCTL_INSTANTIATE, KEYCTL_INSTANTIATE_IOV, KEYCTL_NEGATE, KEYCTL_REJECT - fonctions d'instanciation de clé

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <linux/keyctl.h>  /* Définition des constantes KEY* */
#include <sys/syscall.h>   /* Définition des constantes SYS_* */
#include <unistd.h>
long syscall(size_t n;
             SYS_keyctl, KEYCTL_INSTANTIATE, key_serial_t key,
             const void payload[n], size_t n,
             key_serial_t keyring);
long syscall(size_t n;
             SYS_keyctl, KEYCTL_INSTANTIATE_IOV, key_serial_t key,
             const struct iovec payload[n], unsigned int n,
             key_serial_t keyring);
long syscall(SYS_keyctl, KEYCTL_NEGATE, key_serial_t key,
             unsigned int timeout, key_serial_t keyring);
long syscall(SYS_keyctl, KEYCTL_REJECT, key_serial_t key,
             unsigned int timeout, int error, key_serial_t keyring);

DESCRIPTION

KEYCTL_INSTANTIATE
Instancie (positivement) une clé non instanciée avec une charge utile spécifiée.
L'ID de la clé à instancier est fourni dans key.
La charge utile de la clé est spécifiée dans le tampon pointé par payload ; la taille de ce tampon est spécifiée dans n.
La charge utile peut être un pointeur nul et la taille du tampon peut être 0 si cela est supporté par le type de clé (par exemple, si c'est un keyring).
L'opération peut échouer si les données de la charge utile sont dans le mauvais format ou sont invalides.
Si keyring est différent de zéro, alors, sous réserve des mêmes contraintes et règles que KEYCTL_LINK(2const), la clé instanciée est liée au keyring dont l'ID est spécifié dans keyring.
L'appelant doit posséder la clé d'autorisation appropriée, et une fois que la clé non instanciée a été instanciée, la clé d'autorisation est révoquée. En d'autres termes, cette opération n'est disponible que depuis un programme de type request-key(8). Voir request_key(2) pour une explication des clés non instanciées et de l'instanciation de clé.
KEYCTL_INSTANTIATE_IOV
Instancie une clé non instanciée avec une charge utile spécifiée via un vecteur de tampons.
Cette opération est identique à KEYCTL_INSTANTIATE, mais les données de la charge utile sont spécifiées sous forme d'un tableau de structures iovec (voir iovec(3type)).
Le pointeur vers le vecteur de charge utile est spécifié dans payload. Le nombre d'éléments dans le vecteur est spécifié dans n.
Les arguments key et keyring sont interprétés comme pour KEYCTL_INSTANTIATE.
KEYCTL_NEGATE
Instancie négativement une clé non instanciée.
Cette opération est équivalente à l'appel :

keyctl(KEYCTL_REJECT, key, timeout, ENOKEY, keyring);

KEYCTL_REJECT
Marque une clé comme instanciée négativement et définit un minuteur d'expiration sur la clé. Cette opération fournit un sur-ensemble des fonctionnalités de l'opération antérieure KEYCTL_NEGATE.
L'ID de la clé à instancier négativement est spécifié dans key. L'argument timeout spécifie la durée de vie de la clé, en secondes. L'argument error spécifie l'erreur à retourner lorsqu'une recherche atteint cette clé ; typiquement, il s'agit de EKEYREJECTED, EKEYREVOKED ou EKEYEXPIRED.
Si keyring est différent de zéro, alors, sous réserve des mêmes contraintes et règles que KEYCTL_LINK(2const), la clé instanciée négativement est liée au keyring dont l'ID est spécifié dans keyring.
L'appelant doit posséder la clé d'autorisation appropriée. En d'autres termes, cette opération n'est disponible que depuis un programme de type request-key(8). Voir request_key(2).
L'appelant doit posséder la clé d'autorisation appropriée, et une fois que la clé non instanciée a été instanciée, la clé d'autorisation est révoquée. En d'autres termes, cette opération n'est disponible que depuis un programme de type request-key(8). Voir request_key(2) pour une explication des clés non instanciées et de l'instanciation de clé.

VALEUR DE RETOUR

En cas de succès, 0 est retourné.

En cas d'erreur, -1 est retourné, et errno est définie pour indiquer l'erreur.

VERSIONS

Des wrappers sont fournis dans la bibliothèque libkeyutils : keyctl_instantiate(3), keyctl_instantiate_iov(3), keyctl_negate(3) et keyctl_reject(3).

NORMES

NAME

KEYCTL_INSTANTIATE_IOV - instantiate a key with data provided via I/O vectors

SYNOPSIS

This is a constant defined in <keyctl.h>.

DESCRIPTION

The KEYCTL_INSTANTIATE_IOV constant is used with the keyctl(1) command or the keyctl() system call to instantiate a key with data provided through an array of I/O vectors.

When using keyctl(), this constant is passed as the third argument (op) to the keyctl_remote_query() function. The fourth argument (data) should point to a struct keyctl_instantiate_iov structure.

The struct keyctl_instantiate_iov structure is defined as follows:

struct keyctl_instantiate_iov {
    unsigned int	    kiov_count;
    struct iovec	    *kiov;
    key_serial_t	    id;
};
  • kiov_count: The number of elements in the kiov array.
  • kiov: A pointer to an array of struct iovec structures. Each struct iovec defines a buffer containing a portion of the key's data.
  • id: The serial number of the key to instantiate.

This operation allows for constructing the key data from multiple, potentially non-contiguous memory buffers, which can be useful for efficiency or when dealing with data split across different sources.

RETURN VALUE

This is a constant and does not return a value directly. The success or failure of operations using this constant depends on the context in which it is used (e.g., the keyctl() system call).

ERRORS

Errors are reported by the underlying system call or command that uses this constant.

VERSIONS

This constant is available since Linux kernel 5.6.

STANDARDS

This is a Linux-specific extension and is not part of any standard.

HISTORY

This constant was introduced in the Linux kernel.
