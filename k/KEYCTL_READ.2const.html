KEYCTL_READ(2const) KEYCTL_READ(2const)

NOM

KEYCTL_READ - lire une clé

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/keyctl.h>  /* Définition des constantes KEY* */
#include <sys/syscall.h>   /* Définition des constantes SYS_* */
#include <unistd.h>
long syscall(size_t size;
             SYS_keyctl, KEYCTL_READ, key_serial_t key,
             char buf[_Nullable size], size_t size);

DESCRIPTION

Lit la charge utile d'une clé.

L'identifiant de la clé dont la charge utile doit être lue est spécifié dans key. Il peut s'agir de l'identifiant d'une clé existante, ou de l'un des identifiants de clé spéciaux listés pour KEYCTL_GET_KEYRING_ID(2const).

La charge utile est placée dans le tampon pointé par buf ; la taille de ce tampon doit être spécifiée dans size.

Les données retournées seront traitées pour la présentation selon le type de clé. Par exemple, un keyring retournera un tableau d'entrées key_serial_t représentant les identifiants de toutes les clés qui y sont liées. Le type de clé user retournera ses données telles quelles.

Si buf n'est pas NULL, autant de données de la charge utile que possible sont copiées dans le tampon. En cas de retour réussi, la valeur de retour est toujours la taille totale de la charge utile. Pour déterminer si le tampon était de taille suffisante, vérifiez que la valeur de retour est inférieure ou égale à la valeur fournie dans size.

La clé doit accorder à l'appelant la permission de lecture, ou lui accorder la permission de recherche lorsqu'elle est recherchée depuis les keyrings du processus (c'est-à-dire que la clé est possédée).

VALEUR DE RETOUR

En cas de succès, la quantité de données disponibles dans la clé, indépendamment de la taille du tampon fourni.

En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EOPNOTSUPP
Le type de clé ne prend pas en charge la lecture (par exemple, le type est "login").

VERSIONS

Un wrapper est fourni dans la bibliothèque libkeyutils : keyctl_read(3).

NORMES

Linux.

HISTORIQUE

Linux 2.6.10.

VOIR AUSSI

keyctl(2), keyctl_read(3), keyctl_read_alloc(3)
