ioctl_kd(2) Manuel des appels système ioctl_kd(2)

NOM

ioctl_kd - appels système pour terminaux console et fenêtres virtuelles

SYNTAXE

#include <linux/kd.h>  /* Définition des constantes d'opérateurs */
#include <sys/ioctl.h>
int ioctl(int fd, unsigned long op, void *argp);

DESCRIPTION

Les opérations ioctl(2) suivantes, spécifiques à Linux, sont prises en charge pour les terminaux console et les fenêtres virtuelles.

KDGETLED
Récupère l'état des voyants. argp pointe vers un char. Les trois bits de poids faible de *argp indiquent l'état des voyants, comme suit :
LED_CAP 0x04 voyant Verr. Maj.
LED_NUM 0x02 voyant Verr. Num.
LED_SCR 0x01 voyant Verr. Arrêt défil.
KDSETLED
Définit les voyants. Les voyants sont définis selon les trois bits de poids faible de l'entier unsigned long dans argp. Cependant, si un bit de poids fort est actif, les voyants se comportent par défaut : ils indiquent l'état des fonctions du clavier Verr. Maj., Verr. Num. et Verr. Arrêt défil.

Avant Linux 1.1.54, les voyants reflétaient seulement l'état des indicateurs correspondants du clavier, et KDGETLED/KDSETLED changeaient aussi les indicateurs du clavier. Depuis Linux 1.1.54, les voyants peuvent afficher des informations arbitraires, mais indiquent par défaut les indicateurs du clavier. Les deux ioctls suivants sont utilisés pour accéder aux indicateurs du clavier.

KDGKBLED
Récupère les indicateurs du clavier Verr. Maj., Verr. Num., Verr. Arrêt défil. (pas les voyants). argp pointe vers un caractère qui est mis à l'état des indicateurs. Les trois bits de poids faible (masque 0x7) indiquent l'état actuel des indicateurs, et les bits de poids faible du bloc suivant (masque 0x70) indiquent l'état par défaut des indicateurs. (Depuis Linux 1.1.54.)
KDSKBLED
Définit les indicateurs du clavier Verr. Maj., Verr. Num., Verr. Arrêt défil. (pas les voyants). argp est un entier de 32 bits contenant l'état désiré des indicateurs. Les trois bits de poids faible (masque 0x7) ont l'état des indicateurs, et les bits de poids faible du bloc suivant (masque 0x70) ont l'état par défaut des indicateurs. (Depuis Linux 1.1.54.)
KDGKBTYPE
Récupère le type de clavier. Renvoie la valeur KB_101, définie comme 0x02.
KDADDIO
Ajoute un port d'E/S comme valide. C'est équivalent à ioperm(arg,1,1).
KDDELIO
Supprime un port d'E/S comme valide. C'est équivalent à ioperm(arg,1,0).
KDENABIO
Active l'E/S vers la carte vidéo. C'est équivalent à ioperm(0x3b4, 0x3df-0x3b4+1, 1).
KDDISABIO
Désactive l'E/S vers la carte vidéo. C'est équivalent à ioperm(0x3b4, 0x3df-0x3b4+1, 0).
KDSETMODE
Définit le mode texte/graphique. argp est un entier contenant l'une des valeurs suivantes :
KD_TEXT 0x00
KD_GRAPHICS 0x01
KDGETMODE
Récupère le mode texte/graphique. argp pointe vers un entier qui est mis à l'une des valeurs listées ci-dessus pour KDSETMODE.
KDMKTONE
Génère un son de durée spécifiée. Les 16 bits de poids faible de l'entier unsigned long dans argp indiquent la durée en cycles d'horloge, et les 16 bits de poids fort indiquent la durée en millisecondes. Si la durée est zéro, le son est désactivé. Le contrôle est renvoyé immédiatement. Par exemple, argp = (125<<16) + 0x637 spécifie le son normal associé à un ctrl-G. (Depuis Linux 0.99pl1; cassé dans Linux 2.1.49-50.)
KIOCSOUND
Démarre ou arrête la génération de son. Les 16 bits de poids faible de argp indiquent la durée en cycles d'horloge (c'est-à-dire argp = 1193180/fréquence). argp = 0 désactive le son. Dans tous les cas, le contrôle est renvoyé immédiatement.
GIO_CMAP
Récupère la palette de couleurs par défaut du noyau. argp pointe vers un tableau de 48 octets. (Depuis Linux 1.3.3.)
PIO_CMAP
Change la palette de couleurs par défaut en mode texte. argp pointe vers un tableau de 48 octets contenant, dans l'ordre, les valeurs rouge, vert et bleu pour les 16 couleurs disponibles de l'écran : 0 est éteint, 255 est l'intensité maximale. Les couleurs par défaut sont : noir, rouge sombre, vert sombre, marron, bleu sombre, violet sombre, cyan sombre, gris clair, gris sombre, rouge vif, vert vif, jaune, bleu vif, violet vif, cyan vif, blanc. (Depuis Linux 1.3.3.)
GIO_FONT
Récupère la police de caractères de 256 caractères sous forme étendue. argp pointe vers un tableau de 8192 octets. Échoue avec le code d'erreur EINVAL si la police actuellement chargée est de 512 caractères, ou si la console n'est pas en mode texte.
GIO_FONTX
Récupère la police de l'écran et les informations associées. argp pointe vers une struct consolefontdesc (voir PIO_FONTX). Lors de l'appel, le champ charcount doit être défini au nombre maximum de caractères pouvant tenir dans le tampon pointé par chardata. Au retour, les champs charcount et charheight sont remplis avec les données correspondantes pour la police actuellement chargée, et le tableau chardata contient les données de la police si la valeur initiale de charcount indiquait qu'il y avait suffisamment d'espace. Sinon, le tampon n'est pas modifié et errno est défini à ENOMEM. (Depuis Linux 1.3.1.)
PIO_FONT
Définit la police de 256 caractères de l'écran. Charge la police dans le générateur de caractères EGA/VGA. argp pointe vers un tableau de 8192 octets, avec 32 octets par caractère. Seuls les N premiers sont utilisés pour une police de 8xN (0 < N <= 32). Cet appel invalide également le mappage Unicode.
PIO_FONTX
Définit la police de l'écran et les informations de rendu. argp pointe vers une

struct consolefontdesc {
    unsigned short charcount;  /* nombre de caractères dans la police
                                  (256 ou 512) */
    unsigned short charheight; /* lignes de balayage par caractère (1-32) */
    char          *chardata;   /* données de la police sous forme étendue */
};

Si nécessaire, l'écran est correctement redimensionné et le signal SIGWINCH est envoyé aux processus appropriés. Cet appel invalide également le mappage Unicode. (Depuis Linux 1.3.1.)
PIO_FONTRESET
Réinitialise la taille de la police, le mappage Unicode et la palette de couleurs aux valeurs par défaut au démarrage. argp n'est pas utilisé, mais devrait être défini à NULL pour assurer la compatibilité avec les futures versions de Linux. (Depuis Linux 1.3.28.)
GIO_SCRNMAP
Récupère la table de mappage de l'écran depuis le noyau. argp pointe vers une zone de taille E_TABSZ, qui est remplie avec les positions des octets utilisés pour afficher chaque caractère. Cet appel pourrait renvoyer des informations inutiles si la police actuellement chargée est supérieure à 256 caractères.
GIO_UNISCRNMAP
Récupère la table de mappage Unicode complète de l'écran depuis le noyau. argp pointe vers une zone de taille E_TABSZ*sizeof(unsigned short), qui est remplie avec les codes Unicode représentant chaque caractère. Un ensemble spécial de codes Unicode, commençant par U+F000, est utilisé pour représenter les mappages "directement dans la police". (Depuis Linux 1.3.1.)
PIO_SCRNMAP
Charge la table de mappage "définie par l'utilisateur" (quatrième) dans le noyau, qui mappe les octets aux symboles de l'écran de la console. argp pointe vers une zone de taille E_TABSZ.
PIO_UNISCRNMAP
Charge la table de mappage Unicode "définie par l'utilisateur" depuis le noyau. argp pointe vers une zone de taille E_TABSZ*sizeof(unsigned short), qui est remplie avec les codes Unicode représentant chaque caractère. Un ensemble spécial de codes Unicode, commençant par U+F000, est utilisé pour représenter les mappages "directement dans la police". (Depuis Linux 1.3.1.)
PIO_FONTRESET
Réinitialise la taille de la police, le mappage Unicode et la palette de couleurs aux valeurs par défaut au démarrage. argp n'est pas utilisé, mais devrait être défini à NULL pour assurer la compatibilité avec les futures versions de Linux. (Depuis Linux 1.3.28.)
GIO_SCRNMAP
Récupère la table de mappage de l'écran depuis le noyau. argp pointe vers une zone de taille

KDSKBMODE(2) — man pages

NOM

KDSKBMODE, KDGKBMODE, KDSKBMETA, KDGKBMODE, KDGKBENT, KDSKBENT, KDGKBSENT, KDSKBSENT, KDGKBDIACR, KDGETKEYCODE, KDSETKEYCODE, KDSIGACCEPT, PIO_UNISCRNMAP, PIO_UNIMAP, GIO_UNIMAP, PIO_UNIMAPCLR - contrôle du mode du clavier et des tables de traduction

SYN。

#include <sys/ioctl.h>

#include <linux/keyboard.h>

#include <linux/kd.h>

#include <linux/unwind.h>

long ioctl(fd, request, ...);

DESCRIPTION

Ces appels système sont utilisés pour contrôler le fonctionnement du clavier du périphérique console Linux. Ils fonctionnent tous sur un descripteur de fichier fd qui correspond à un périphérique console (par exemple, /dev/tty[0-6]).

PIO_UNISCRNMAP
Charge la table "définissable par l'utilisateur" (la quatrième) dans le noyau qui mappe les octets vers les Unicodes, lesquels sont ensuite traduits en symboles d'écran selon la table de mappage Unicode vers police actuellement chargée. Des Unicodes spéciaux commençant à U+F000 peuvent être utilisés pour mapper directement vers les symboles de la police. (Depuis Linux 1.3.1.)
GIO_UNIMAP
Obtient le mappage Unicode vers police depuis le noyau. argp pointe vers une structure

struct unimapdesc {
    unsigned short  entry_ct;
    struct unipair *entries;
};

où entries pointe vers un tableau de

struct unipair {
    unsigned short unicode;
    unsigned short fontpos;
};

(Depuis Linux 1.1.92.)
PIO_UNIMAP
Place le mappage unicode vers police dans le noyau. argp pointe vers une struct unimapdesc. (Depuis Linux 1.1.92)
PIO_UNIMAPCLR
Efface la table, éventuellement suggère un algorithme de hachage. argp pointe vers une

struct unimapinit {
    unsigned short advised_hashsize;  /* 0 si pas d'avis */
    unsigned short advised_hashstep;  /* 0 si pas d'avis */
    unsigned short advised_hashlevel; /* 0 si pas d'avis */
};

(Depuis Linux 1.1.92.)
KDGKBMODE
Récupère le mode actuel du clavier. argp pointe vers un long qui est mis à l'une des valeurs suivantes :
K_RAW 0x00 /* Mode brut (scancode) */
K_XLATE 0x01 /* Traduit les keycodes en utilisant la table de touches */
K_MEDIUMRAW 0x02 /* Mode brut moyen (scancode) */
K_UNICODE 0x03 /* Mode Unicode */
K_OFF 0x04 /* Mode désactivé (depuis Linux 2.6.39) */
KDSKBMODE
Définit le mode actuel du clavier. argp est un long égal à l'une des valeurs montrées pour KDGKBMODE.
KDGKBMETA
Récupère le mode de gestion de la touche méta. argp pointe vers un long qui est mis à l'une des valeurs suivantes :
K_METABIT 0x03 définit le bit de poids fort
K_ESCPREFIX 0x04 préfixe d'échappement
KDSKBMETA
Définit le mode de gestion de la touche méta. argp est un long égal à l'une des valeurs montrées ci-dessus pour KDGKBMETA.
KDGKBENT
Récupère une entrée dans la table de traduction des touches (keycode vers code d'action). argp pointe vers une

struct kbentry {
    unsigned char  kb_table;
    unsigned char  kb_index;
    unsigned short kb_value;
};

avec les deux premiers membres remplis : kb_table sélectionne la table de touches (0 <= kb_table < MAX_NR_KEYMAPS), et kb_index est le keycode (0 <= kb_index < NR_KEYS). kb_value est mis à jour avec le code d'action correspondant, ou K_HOLE s'il n'y a pas de telle touche, ou K_NOSUCHMAP si kb_table est invalide.
KDSKBENT
Définit une entrée dans la table de traduction. argp pointe vers une struct kbentry.
KDGKBSENT
Récupère une chaîne de touche de fonction. argp pointe vers une

struct kbsentry {
    unsigned char kb_func;
    unsigned char kb_string[512];
};

kb_string est mis à jour avec la chaîne (terminée par null) correspondant au code d'action de la kb_func-ième touche de fonction.
KDSKBSENT
Définit une entrée de chaîne de touche de fonction. argp pointe vers une struct kbsentry.
KDGKBDIACR
Lit la table d'accents du noyau. argp pointe vers une

struct kbdiacrs {
    unsigned int   kb_cnt;
    struct kbdiacr kbdiacr[256];
};

où kb_cnt est le nombre d'entrées dans le tableau, chacune étant une

struct kbdiacr {
    unsigned char diacr;
    unsigned char base;
    unsigned char result;
};

KDGETKEYCODE
Lit une entrée de la table des keycodes du noyau (scan code vers keycode). argp pointe vers une

struct kbkeycode {
    unsigned int scancode;
    unsigned int keycode;
};

keycode est mis à jour pour correspondre au scancode donné. (Seulement 89 <= scancode <= 255. Pour 1 <= scancode <= 88, keycode==scancode.) (Depuis Linux 1.1.63.)
KDSETKEYCODE
Écrit une entrée de la table des keycodes du noyau. argp pointe vers une struct kbkeycode. (Depuis Linux 1.1.63.)
KDSIGACCEPT
Le processus appelant indique sa volonté d'accepter le signal argp lorsqu'il est généré par la pression d'une combinaison de touches appropriée. (1 <= argp <= NSIG). (Voir spawn_console() dans linux/drivers/char/keyboard.c.)

VALEUR RENVOYÉE

En cas de succès, 0 est renvoyé (sauf indication contraire). En cas d'échec, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

ERREURS

EINVAL
argp est invalide.

STANDARDS

Linux.

VOIR AUSSI

ioctl(2), ioctl_console(2)
