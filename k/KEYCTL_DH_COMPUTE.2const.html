DESCRIPTIO

N

Calcule un secret partagé ou une clé publique Diffie-Hellman, en appliquant éventuellement une fonction de dérivation de clé (KDF) au

résultat.

L'argument dh_params est un pointeur vers un ensemble de paramètres contenant les numéros de série de trois clés « user » utilisées dans le calcul Diffie-Hellman, regroupées dans une structure de la forme suivante

: 


struct keyctl_dh_params {
    int32_t private; /* La clé privée locale */
    int32_t prime; /* Le nombre premier, connu des deux parties */
    int32_t base;  /* L'entier de base : soit un générateur partagé
                      soit la clé publique distante */
}
;

Chacune des trois clés spécifiées dans cette structure doit accorder à l'appelant la permission de lecture. Les charges utiles de ces clés sont utilisées pour calculer le résultat Diffie-Hellman comme suit

: 


base ^ private mod
prime

Si la base est le générateur partagé, le résultat est la clé publique locale. Si la base est la clé publique distante, le résultat est le secret

partagé.

L'argument buf pointe vers un tampon où le résultat du calcul est placé. La taille de ce tampon est spécifiée dans n

.

Le tampon doit être assez grand pour accueillir les données de sortie, sinon une erreur est retournée. Si n est spécifié à zéro, dans ce cas le tampon n'est pas utilisé et l'opération retourne la taille de tampon minimale requise (c'est-à-dire la longueur du nombre premier)

.

Les calculs Diffie-Hellman peuvent être effectués en espace utilisateur, mais nécessitent une bibliothèque d'entiers de précision multiple (MPI). Déplacer l'implémentation dans le noyau donne accès à l'implémentation MPI du noyau et permet l'accès à du matériel sécurisé ou

d'accélération.

L'ajout de la prise en charge du calcul DH à l'appel système keyctl() a été considéré comme une bonne adéquation en raison de l'utilisation de l'algorithme DH pour dériver des clés partagées ; cela permet également au type de clé de déterminer quelle implémentation DH (logicielle ou matérielle) est

appropriée.

Si l'argument kdf_params est NULL, alors le résultat DH lui-même est retourné. Sinon (depuis Linux 4.12), c'est un pointeur vers une structure qui spécifie les paramètres de l'opération KDF à appliquer

: 


struct keyctl_kdf_params {
    char *hashname;     /* Nom de l'algorithme de hachage */
    char *otherinfo;    /* OtherInfo SP800-56A */
    __u32 otherinfolen; /* Longueur des données otherinfo */
    __u32 __spare[8];   /* Réservé */
}
;

Le champ hashname est une chaîne terminée par un caractère nul qui spécifie un nom de hachage (disponible dans l'API crypto du noyau ; la liste des hachages disponibles est plutôt délicate à observer ; veuillez consulter la documentation « Kernel Crypto API Architecture » pour les informations sur la manière dont les noms de hachage sont construits, et le code source et la configuration de votre noyau pour savoir quels chiffres et modèles de type CRYPTO_ALG_TYPE_SHASH sont disponibles) à appliquer au résultat DH dans l'opération

KDF.

Le champ otherinfo est des données OtherInfo telles que décrites dans SP800-56A section 5.8.1.2 et est spécifique à l'algorithme. Ces données sont concaténées avec le résultat de l'opération DH et sont fournies en entrée à l'opération KDF. Sa taille est fournie dans le champ otherinfolen et est limitée par la constante KEYCTL_KDF_MAX_OI_LEN définie dans security/keys/internal.h à une valeur de

64.

Le champ __spare est actuellement inutilisé. Il était ignoré jusqu'à Linux 4.13 (mais devrait toujours être adressable par l'utilisateur puisqu'il est copié dans le noyau) et devrait contenir des zéros depuis Linux 4.

13.

L'implémentation de la KDF est conforme à SP800-56A ainsi qu'à SP800-108 (la KDF à compteur)

.

Cette opération est exposée par libkeyutils (à partir de libkeyutils 1.5.10) via les fonctions keyctl_dh_compute(3) et keyctl_dh_comp

ute_al
loc(3).
