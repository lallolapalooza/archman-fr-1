KEYCTL_INSTANTIATE(2const) KEYCTL_INSTANTIATE(2const)

NOM

KEYCTL_INSTANTIATE, KEYCTL_INSTANTIATE_IOV, KEYCTL_NEGATE, KEYCTL_REJECT - fonctions d'instanciation de clé

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/keyctl.h>  /* Définition des constantes KEY* */
#include <sys/syscall.h>   /* Définition des constantes SYS_* */
#include <unistd.h>
long syscall(size_t n;
             SYS_keyctl, KEYCTL_INSTANTIATE, key_serial_t key,
             const void payload[n], size_t n,
             key_serial_t keyring);
long syscall(size_t n;
             SYS_keyctl, KEYCTL_INSTANTIATE_IOV, key_serial_t key,
             const struct iovec payload[n], unsigned int n,
             key_serial_t keyring);
long syscall(SYS_keyctl, KEYCTL_NEGATE, key_serial_t key,
             unsigned int timeout, key_serial_t keyring);
long syscall(SYS_keyctl, KEYCTL_REJECT, key_serial_t key,
             unsigned int timeout, int error, key_serial_t keyring);

DESCRIPTION

KEYCTL_INSTANTIATE
Instancie (positivement) une clé non instanciée avec une charge utile spécifiée.
L'identifiant de la clé à instancier est fourni dans key.
La charge utile de la clé est spécifiée dans le tampon pointé par payload ; la taille de ce tampon est spécifiée dans n.
La charge utile peut être un pointeur nul et la taille du tampon peut être 0 si cela est pris en charge par le type de clé (par exemple, s'il s'agit d'un keyring).
L'opération peut échouer si les données de la charge utile sont dans un format incorrect ou invalides.
Si keyring est différent de zéro, alors, sous réserve des mêmes contraintes et règles que KEYCTL_LINK(2const), la clé instanciée est liée au keyring spécifié par keyring.
L'appelant doit posséder la clé d'autorisation appropriée, et une fois que la clé non instanciée a été instanciée, la clé d'autorisation est révoquée. En d'autres termes, cette opération n'est disponible qu'à partir d'un programme de type request-key(8). Voir request_key(2) pour une explication des clés non instanciées et de l'instanciation de clé.
KEYCTL_INSTANTIATE_IOV
Instancie une clé non instanciée avec une charge utile spécifiée via un vecteur de tampons.
Cette opération est identique à KEYCTL_INSTANTIATE, mais les données de la charge utile sont spécifiées sous forme d'un tableau de structures iovec (voir iovec(3type)).
Le pointeur vers le vecteur de charge utile est spécifié dans payload. Le nombre d'éléments dans le vecteur est spécifié dans n.
Les arguments key et keyring sont interprétés comme pour KEYCTL_INSTANTIATE.
KEYCTL_NEGATE
Instancie négativement une clé non instanciée.
Cette opération est équivalente à l'appel :

keyctl(KEYCTL_REJECT, key, timeout, ENOKEY, keyring);

KEYCTL_REJECT
Marque une clé comme instanciée négativement et définit un minuteur d'expiration sur la clé. Cette opération fournit un sur-ensemble des fonctionnalités de l'opération antérieure KEYCTL_NEGATE.
L'identifiant de la clé à instancier négativement est spécifié dans key. L'argument timeout spécifie la durée de vie de la clé, en secondes. L'argument error spécifie l'erreur qui sera renvoyée lorsqu'une recherche tombe sur cette clé ; généralement, il s'agit de EKEYREJECTED, EKEYREVOKED ou EKEYEXPIRED.
Si keyring est différent de zéro, alors, sous réserve des mêmes contraintes et règles que KEYCTL_LINK(2const), la clé instanciée négativement est liée au keyring spécifié par keyring.
L'appelant doit posséder la clé d'autorisation appropriée. En d'autres termes, cette opération n'est disponible qu'à partir d'un programme de type request-key(8). Voir request_key(2).
L'appelant doit posséder la clé d'autorisation appropriée, et une fois que la clé non instanciée a été instanciée, la clé d'autorisation est révoquée. En d'autres termes, cette opération n'est disponible qu'à partir d'un programme de type request-key(8). Voir request_key(2) pour une explication des clés non instanciées et de l'instanciation de clé.

VALEUR RENVOYÉE

En cas de succès, 0 est renvoyé.

En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

VERSIONS
