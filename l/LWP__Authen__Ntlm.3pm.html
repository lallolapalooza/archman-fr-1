LWP::Authen::Ntlm(3) Documentation Perl fournie par l'utilisateur LWP::Authen::Ntlm(3)

NOM

LWP::Authen::Ntlm - Bibliothèque pour permettre l'authentification NTLM (Microsoft) dans LWP

SYNTAXE

use LWP::UserAgent;
use HTTP::Request::Common;
my $url = 'http://www.company.com/protected_page.html';
# Configurer le client ntlm puis le message de handshake ntlm encodé en base64
my $ua = LWP::UserAgent->new(keep_alive=>1);
$ua->credentials('www.company.com:80', '', "MyDomain\\MyUserCode", 'MyPassword');
$request = GET $url;
print "--Performing request now...-----------\n";
$response = $ua->request($request);
print "--Done with request-------------------\n";
if ($response->is_success) {print "It worked!->" . $response->code . "\n"}
else {print "It didn't work!->" . $response->code . "\n"}

DESCRIPTION

LWP::Authen::Ntlm permet à LWP de s'authentifier auprès des serveurs qui utilisent le schéma d'authentification NTLM popularisé par Microsoft. Ce type d'authentification est courant sur les intranets des organisations centrées sur Microsoft.

Le module tire parti du module Authen::NTLM de Mark Bush. Comme il existe également un autre module Authen::NTLM disponible sur CPAN par Yee Man Chan avec une interface entièrement différente, il est nécessaire de s'assurer que vous avez le bon module NTLM.

De plus, il y a eu des problèmes d'incompatibilité entre les différentes versions de Mime::Base64, que Authen::NTLM de Bush utilise. Par conséquent, il est nécessaire de s'assurer que votre module Mime::Base64 prend en charge l'exportation des fonctions "encode_base64" et "decode_base64".

UTILISATION

Le module est utilisé indirectement par LWP, plutôt que d'être inclus directement dans votre code. Le système LWP invoquera l'authentification NTLM lorsqu'il rencontrera le schéma d'authentification en tentant de récupérer une URL d'un serveur. Pour que l'authentification NTLM fonctionne, vous devez avoir quelques éléments configurés dans votre code avant de tenter de récupérer l'URL :

  • Activer les connexions HTTP persistantes

    Pour ce faire, passez l'option "keep_alive=>1" à LWP::UserAgent lors de sa création, comme ceci :

    my $ua = LWP::UserAgent->new(keep_alive=>1);
  • Définir les informations d'identification sur l'objet UserAgent

    Les informations d'identification doivent être définies comme suit :

    $ua->credentials('www.company.com:80', '', "MyDomain\\MyUserCode", 'MyPassword');

    Notez que vous ne pouvez pas utiliser la méthode authorization_basic() de l'objet HTTP::Request pour définir les informations d'identification. Notez également que la partie 'www.company.com:80' ne définit les informations d'identification que sur le port spécifié ET elle est sensible à la casse (ceci est dû à la manière dont LWP est codé, et n'a rien à voir avec LWP::Authen::Ntlm)
