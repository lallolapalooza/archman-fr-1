NOM

Locale::Po4a::VimHelp - convertit les fichiers d'aide Vim des/vers des fichiers PO.

DESCRIPTION

Le projet po4a (PO pour tout) a pour objectif de faciliter les traductions (et plus intéressant encore, la maintenance des traductions) en utilisant les outils gettext dans des domaines où ils n'étaient pas attendus, comme la documentation.

"Locale::Po4a::VimHelp" est un module pour aider à la traduction des fichiers d'aide Vim. Voir aussi Écrire des fichiers d'aide https://vimhelp.org/helphelp.txt.html#help-writing pour sa syntaxe.

ÉTAT DE CE MODULE

Ce module est à un stade précoce de développement. Il a été testé avec succès sur des fichiers simples comme "helphelp.txt". Cependant, il n'a pas encore été testé sur des fichiers d'aide complets, et la manière dont il les analyse pourrait changer pour des corrections et améliorations, notamment le retour à la ligne.

DÉVELOPPEMENT

L'analyse des fichiers d'aide Vim pour po4a est difficile. Voici quelques obstacles rencontrés lors du développement de ce module. Si vous avez une meilleure idée, n'hésitez pas à proposer un correctif (avec des cas de test supplémentaires).

"1. foo" ressemble à une liste ordonnée
Pas nécessairement. Considérer le paragraphe suivant. 
Il y a 2 tanukis errants, pas
1. Il utilise sa technique de clonage.

Pour la même raison, ce qui ressemble à un titre (par exemple, "1.1 bar") ou à une liste non ordonnée (par exemple, "o baz") ne peut pas être détecté.

Les balises alignées à droite doivent être exclues de la cible de traduction
Ce sujet est également difficile car il est lié aux différences linguistiques dans la localisation.

Considérer l'exemple suivant.

Un concept aussi courant et court dans certaines langues *tags*

qui pourrait être traduit par

Ils sont peu familiers, il n'y a pas de concepts correspondants et *tags*
il faut une phrase plus longue pour les exprimer dans cette langue

Lorsque cela se produit, vous devez décider à quel moment vous souhaitez ajouter une balise *joliment*. Cela ne devrait pas être facile. Le fichier d'aide Vim est au format à retour à la ligne forcé, même pour les parties qui ne sont pas des blocs de code.

Il en va de même pour les références de balises telles que "|ref|".

Exploiter "--wrapcol" pour surveiller les largeurs de texte
L'utilisation de l'option "--wrapcol" pour émettre des avertissements lorsque la largeur du texte dépasse les limites spécifiées semble être une approche raisonnable. Les fichiers d'aide Vim officiels comportent une ligne de mode, telle que "vim:tw=78:ts=8:noet:ft=help:norl:", comme vu dans "runtime/doc/if_perl.txt" https://github.com/vim/vim/blob/04cc8975930b7b2c5d6753d3eddf57dab2816518/runtime/doc/if_perl.txt#L307. Cependant, il y a quelques défis à considérer :
Comportement d'analyse des fichiers
Si cette option est implémentée, il serait idéal de lire le fichier entier en premier, de détecter si la ligne de mode existe et de déterminer quelles sections sont affectées. Malheureusement, le mécanisme d'analyse progressive n'est pas utilisé dans ce cas.
Valeurs par défaut vs personnalisées
La valeur par défaut générique de "--wrapcol" est 76, tandis que les fichiers d'aide Vim utilisent couramment 78. Dans la plupart des cas, la valeur dans les options transmises à ce module est par défaut à 76, mais il n'est pas clair si cette valeur a été explicitement définie ou implicitement appliquée.
