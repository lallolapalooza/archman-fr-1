NOM

Locale::Po4a::Docbook - convertir des documents XML DocBook depuis/vers des fichiers PO

DESCRIPTION

Le projet po4a (PO pour tout) vise à faciliter les traductions (et plus intéressant encore, la maintenance des traductions) à l'aide des outils gettext dans des domaines où ils n'étaient pas attendus, comme la documentation.

Locale::Po4a::Docbook est un module qui aide à la traduction de documents XML DocBook vers d'autres langues [humaines].

STATUT DE CE MODULE

Ce module est pleinement fonctionnel, car il repose sur le module Locale::Po4a::Xml. Il ne définit que les balises et attributs traduisibles.

Le seul problème connu est qu'il ne gère pas encore les entités, et cela inclut les entités d'inclusion de fichiers, mais vous pouvez traduire la plupart de ces fichiers seuls (à l'exception des fichiers d'entités typiques), et il est généralement préférable de les maintenir séparément.

SOUSCRIRE AU COMPORTEMENT PAR DÉFAUT AVEC DES OPTIONS DE LIGNE DE COMMANDE

Le comportement par défaut des modules fournis par le système est réglé pour être prudent.

Par exemple, la valeur par défaut de la balise <author> vise à la faire apparaître sous <para>. Mais vous pourriez l'utiliser uniquement sous <bookinfo>. Dans ce cas, vous voudrez peut-être la traduire indépendamment pour chaque auteur.

Si vous n'aimez pas le comportement par défaut du module xml et de ses modules dérivés, vous pouvez fournir des options de ligne de commande pour changer leur comportement. Par exemple, vous pouvez ajouter ce qui suit au fichier de configuration po4a :

opt:"-k 0 -o nodefault=\"<bookinfo> <author>\" \
          -o break=\"<bookinfo> <author>\" \
          -o untranslated=\"<bookinfo>\" \
          -o translated=\"<author>\""

Ceci surcharge le comportement par défaut pour <bookinfo> et <author>, définit <bookinfo> et <author> pour casser le flux de données d'entrée sur ces balises, définit <bookinfo> pour ne pas traduire son contenu balisé, et définit <author> pour traduire son contenu balisé.
