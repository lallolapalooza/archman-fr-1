DESCRIPTION

Ce module implémente une configuration XML, complétant la configuration de propriétés décrite ailleurs.

POURQUOI ?

Pourquoi vouloir ma configuration en XML ? pourriez-vous demander. Il suffit que vous ayez une préférence personnelle pour les fichiers XML. Peut-être gérez-vous votre configuration avec des outils qui ont une affinité avec XML, tels que des éditeurs XML-aware ou des générateurs de configuration automatiques. Ou peut-être (et c'est le point majeur) ne voulez-vous pas avoir à exécuter votre application juste pour vérifier la syntaxe de votre fichier de configuration.

En utilisant une configuration XML et en référençant un DTD, vous pouvez utiliser un analyseur DTD conscient des espaces de noms pour vérifier si votre configuration XML respecte au moins les règles établies dans le DTD.

COMMENT

Pour référencer un DTD, placez-le après la déclaration XML dans votre fichier de configuration :

<!DOCTYPE log4perl:configuration SYSTEM "log4perl.dtd">

Cela indique à l'analyseur de valider votre configuration par rapport au DTD dans "log4perl.dtd", qui est disponible dans le répertoire xml/ de la distribution log4perl. Notez que vous devrez également obtenir le log4j-1.2.dtd à partir de là, car il est inclus par défaut dans le DTD log4perl.

Les analyseurs DTD conscients des espaces de noms ne sont pas la norme en Perl. Mais le projet Xerces (http://xml.apache.org/xerces-c/index.html -- de nombreux binaires disponibles, même des rpm) fournit un tel analyseur que vous pouvez utiliser comme suit :

StdInParse -ns -v < my-log4perl-config.xml

Ce module lui-même n'utilise pas d'analyseur DTD, XML::DOM::ValParser semble ne pas gérer les espaces de noms.

POURQUOI DEUX DTDs ?

Le DTD log4j provient du projet log4j, conçu pour gérer ses besoins. Log4perl a ajouté quelques extensions à la fonctionnalité originale de log4j qui nécessitaient des extensions dans le DTD log4j. Si vous n'utilisez pas ces fonctionnalités, vous pouvez valider votre configuration par rapport au DTD log4j et être assuré que vous utilisez une configuration log4j non modifiée.

Les fonctionnalités ajoutées par le DTD log4perl sont :

1 réglage global oneMessagePerAppender
log4perl.oneMessagePerAppender=1
2 spécificateurs de conversion utilisateur globaux
log4perl.PatternLayout.cspec.G=sub { return "UID $< GID $("; }
3 spécificateurs de conversion personnalisés locaux à l'appender
log4j.appender.appndr1.layout.cspec.K = sub {return sprintf "%1x", $$ }
4 options imbriquées
log4j.appender.jabbender          = Log::Dispatch::Jabber
#(notez comment ceux-ci sont imbriqués sous 'login')
log4j.appender.jabbender.login.hostname = a.jabber.server
log4j.appender.jabbender.login.port     = 5222
log4j.appender.jabbender.login.username = bobjones
5 filtres spécifiques à log4perl, voir Log::Log4perl::Filter, de nombreux exemples dans t/044XML-Filter.t, voici un court exemple :
<?xml version="1.0" encoding="UTF-8"?> 
<!DOCTYPE log4perl:configuration SYSTEM "log4perl.dtd">
<log4perl:configuration xmlns:log4perl="http://log4perl.sourceforge.net/">

<appender name="A1" class="Log::Log4perl::Appender::TestBuffer">
      <layout class="Log::Log4perl::Layout::SimpleLayout"/>
      <filter class="Log::Log4perl::Filter::Boolean">
          <param name="logic" value="!Match3 &amp;&amp; (Match1 || Match2)"/> 
      </filter>
</appender>   

<appender name="A2" class="Log::Log4perl::Appender::TestBuffer">
      <layout class="Log::Log4perl::Layout::SimpleLayout"/>
      <filter-ref id="Match1"/>
</appender>   

<log4perl:filter name="Match1" value="sub { /let this through/ }" />

<log4perl:filter name="Match2">
      sub { 
          /and that, too/ 
      }
 </log4perl:filter>

</log4perl:configuration>
