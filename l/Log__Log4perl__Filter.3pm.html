NOM

Log::Log4perl::Filter - Classe de base pour les filtres personnalisés de Log4perl

SYNTAXE

use Log::Log4perl;
Log::Log4perl->init(\ <<'EOT');
  log4perl.logger = INFO, Screen
  log4perl.filter.MyFilter        = sub { /laissez passer ceci/ }
  log4perl.appender.Screen        = Log::Log4perl::Appender::Screen
  log4perl.appender.Screen.Filter = MyFilter
  log4perl.appender.Screen.layout = Log::Log4perl::Layout::SimpleLayout
EOT
    # Définir un logger
my $logger = Log::Log4perl->get_logger("Some");
    # Laissez passer ceci
$logger->info("Voici l'info, laissez passer ceci !");
    # Supprimez ceci
$logger->info("Voici l'info, supprimez ceci !");
#################################################################
# Filtre StringMatch :
#################################################################
log4perl.filter.M1               = Log::Log4perl::Filter::StringMatch
log4perl.filter.M1.StringToMatch = laissez passer ceci
log4perl.filter.M1.AcceptOnMatch = true
#################################################################
# Filtre LevelMatch :
#################################################################
log4perl.filter.M1               = Log::Log4perl::Filter::LevelMatch
log4perl.filter.M1.LevelToMatch  = INFO
log4perl.filter.M1.AcceptOnMatch = true

DESCRIPTION

Log4perl permet l'utilisation de filtres personnalisés dans ses appenders pour contrôler la sortie des messages. Ces filtres peuvent rechercher certains blocs de texte dans un message, vérifier que sa priorité correspond ou dépasse un certain niveau, ou que c'est la 10ème fois que le même message est soumis - et prendre une décision de journalisation/non-journalisation basée sur ces faits circonstanciels.

Les filtres ont des noms et peuvent être spécifiés de deux manières différentes dans le fichier de configuration Log4perl : comme sous-routines ou comme classes de filtre. Voici un filtre simple nommé "MyFilter" qui vérifie simplement que le message entrant correspond à l'expression régulière "/laissez passer ceci/i" :

log4perl.filter.MyFilter        = sub { /laissez passer ceci/i }

Il exploite le fait que lorsque la sous-routine définie ci-dessus est appelée sur un message, la variable spéciale $_ de Perl sera définie avec le texte du message (pré-rendu, c'est-à-dire concaténé mais pas mis en forme) à enregistrer. La sous-routine est censée renvoyer une valeur vraie si elle souhaite que le message soit enregistré ou une valeur fausse si ce n'est pas le cas.

De plus, Log::Log4perl passera une hash à la sous-routine, contenant toutes les paires clé/valeur qu'il passerait aux appenders correspondants, comme spécifié dans Log::Log4perl::Appender. Voici un exemple de filtre vérifiant la priorité du message entrant :

log4perl.filter.MyFilter        = sub {    \
     my %p = @_;                           \
     if($p{log4p_level} eq "WARN" or       \
        $p{log4p_level} eq "INFO") {       \
         return 1;                         \
     }                                     \
     return 0;                             \
}

Si la priorité du message est égale à "WARN" ou "INFO", elle renvoie une valeur vraie, provoquant l'enregistrement du message.

Filtres prédéfinis

Pour des tâches courantes comme vérifier que la priorité du message correspond à une certaine priorité, il existe déjà un ensemble de filtres prédéfinis. Pour effectuer une correspondance de niveau exacte, il est beaucoup plus propre d'utiliser le filtre "LevelMatch" de Log4perl à la place :

log4perl.filter.M1               = Log::Log4perl::Filter::LevelMatch
log4perl.filter.M1.LevelToMatch  = INFO
log4perl.filter.M1.AcceptOnMatch = true

Cela laissera passer le message si sa priorité est INFO et le supprimera sinon. L'instruction peut être niée en disant

log4perl.filter.M1.AcceptOnMatch = false

au lieu de cela. De cette façon, le message sera enregistré si sa priorité est autre que INFO.

Dans le même ordre d'idées, le filtre "StringMatch" de Log4perl vérifiera le message entrant pour des chaînes ou des expressions régulières :

log4perl.filter.M1               = Log::Log4perl::Filter::StringMatch
log4perl.filter.M1.StringToMatch = bl.. bl..
log4perl.filter.M1.AcceptOnMatch = true

Cela ouvrira la porte aux messages comme "blah blah" car l'expression régulière dans "StringToMatch" les fait correspondre. Encore une fois, le réglage de "AcceptOnMatch" détermine si le filtre est défini de manière positive ou négative.

Toutes les entrées de classe de filtre dans le fichier de configuration doivent adhérer à la règle suivante : Ce n'est qu'après qu'un filtre a été défini par nom et par classe/sous-routine, que ses valeurs d'attributs peuvent être assignées, tout comme la valeur "true" ci-dessus est assignée à l'attribut "AcceptOnMatch" après que le filtre "M1" ait été défini.

Attacher un filtre à un appendeur

Attacher un filtre à un appendeur est aussi simple que d'assigner son nom à l'attribut "Filter" de l'appendeur :

log4perl.appender.MyAppender.Filter = MyFilter

Cela amènera "Log::Log4perl" à appeler la sous-routine/méthode de filtre chaque fois qu'un message est censé être passé à l'appendeur. Selon la valeur de retour du filtre, "Log::Log4perl" continuera comme prévu ou se retirera immédiatement.

Combiner des filtres avec Log::Log4perl::Filter::Boolean

Parfois, il est utile de combiner les sorties de divers filtres pour arriver à une décision de journalisation/non-journalisation. Alors que Log4j, le vaisseau mère de Log4perl, a choisi d'implémenter cette fonctionnalité comme une chaîne de filtres, similaire aux chaînes IP de Linux, Log4perl tente une approche différente.

Généralement, les résultats des filtres n'ont pas besoin d'être transmis le long de chaînes mais combinés de manière programmatique en utilisant la logique booléenne. "Journaliser si ce filtre dit 'oui' et que ce filtre dit 'non'" est une exigence assez courante, mais difficile à implémenter comme une chaîne.

"Log::Log4perl::Filter::Boolean" est un filtre personnalisé spécialement prédéfini pour Log4perl. Il combine les résultats d'autres filtres personnalisés de manière arbitraire, en utilisant des expressions booléennes :

log4perl.logger = WARN, AppWarn, AppError
log4perl.filter.Match1       = sub { /laissez passer ceci/ }
log4perl.filter.Match2       = sub { /et cela aussi/ }
log4perl.filter.MyBoolean       = Log::Log4perl::Filter::Boolean
log4perl.filter.MyBoolean.logic = Match1 || Match2
log4perl.appender.Screen        = Log::Log4perl::Appender::Screen
log4perl.appender.Screen.Filter = MyBoolean
log4perl.appender.Screen.layout = Log::Log4perl::Layout::SimpleLayout

"Log::Log4perl::Filter::Boolean"'s les expressions booléennes permettent de combiner différents appenders par nom en utilisant AND (&& ou &), OR (|| ou |) et NOT (!) comme expressions logiques. De plus, les parenthèses peuvent être utilisées pour définir les priorités. La précédence des opérateurs suit les conventions standard de Perl. Voici un tas d'exemples :

Match1 && !Match2            # Match1 et pas Match2
!(Match1 || Match2)          # Ni Match1 ni Match2
(Match1 && Match2) || Match3 # Les deux Match1 et Match2 ou Match3

Écrire vos propres classes de filtre

Si aucune des classes de filtre prédéfinies de Log::Log4perl ne répond à vos besoins, vous pouvez facilement créer la vôtre : définissez simplement une nouvelle classe, héritez-la de la classe de base "Log::Log4perl::Filter", et définissez ses méthodes "new" et "ok" comme ceci :

package Log::Log4perl::Filter::MyFilter;
use base Log::Log4perl::Filter;
sub new {
    my ($class, %options) = @_;
    my $self = { %options,
               };

    bless $self, $class;
    return $self;
}
sub ok {
     my ($self, %p) = @_;
     # ... décidez et retournez 1 ou 0
}
1;

Log4perl appellera la méthode ok() pour déterminer si le filtre doit laisser passer le message ou non. Une valeur de retour vraie indique que le message sera enregistré par l'appendeur, une valeur fausse le bloque.

"new" méthode :

log4perl.filter.MyFilter       = Log::Log4perl::Filter::MyFilter
log4perl.filter.MyFilter.color = red

provoquera

Log::Log4perl::Filter::MyFilter->new( name  => "MyFilter",
                                      color => "red" );

La classe de filtre personnalisée doit utiliser ceci pour définir les attributs de l'objet, afin qu'ils soient disponibles plus tard pour prendre des décisions de log/nolog en fonction de ceux-ci.

ok() est la méthode du filtre pour indiquer si le message doit être enregistré ou non. Elle sera appelée par Log::Log4perl lorsqu'il aura besoin que le filtre prenne une décision. Une valeur false retournée par ok() bloquera les messages, une valeur true les laissera passer.
