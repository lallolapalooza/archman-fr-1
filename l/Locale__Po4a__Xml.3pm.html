NOM

Locale::Po4a::Xml — convertir des documents XML et dérivés en/depuis des fichiers PO

DESCRIPTION

Le projet po4a (PO pour tout) a pour but de faciliter les traductions (et plus intéressant, la maintenance des traductions) en utilisant les outils gettext dans des domaines où elles n'étaient pas attendues, comme la documentation.

Locale::Po4a::Xml est un module pour aider à la traduction de documents XML vers d'autres langues. Il peut aussi servir de base pour construire des modules pour des documents basés sur XML.

TRADUIRE AVEC PO4A::XML

Ce module peut être utilisé directement pour gérer des documents XML généraux. Il extraira le contenu de toutes les balises, et non les attributs, car c'est là que le texte est généralement écrit dans les documents XML.

Il existe quelques options (décrites dans la section suivante) qui peuvent personnaliser ce comportement. Si cela ne correspond pas à votre format de document, il est recommandé d'écrire votre propre module dérivé de celui-ci, pour décrire les détails de votre format. Voir la section ÉCRITURE DE MODULES DÉRIVÉS ci-dessous, pour une description du processus.

OPTIONS ACCEPTÉES PAR CE MODULE

L'option globale de débogage permet à ce module d'afficher les mots exclus, afin de vérifier si quelque chose d'important est manqué.

Voici les options spécifiques à ce module :

nostrip
Empêche la suppression des espaces autour des mots extraits.
wrap
Définit le texte à traduire dans un schéma canonique, considérant que les espaces ne sont pas importants, et regroupe le document traduit. Cette option peut être annulée par des options de balise personnalisées. Voir l'option translated ci-dessous.
unwrap_attributes
Les attributs sont groupés par défaut. Cette option désactive le groupement.
caseinsensitive
Permet que la recherche des balises et des attributs soit insensible à la casse. Si elle est définie, <BooK>laNG et <BOOK>Lang seront traités comme <book>lang.
escapequotes
Échappe les guillemets dans les chaînes de sortie. C'est nécessaire, par exemple, pour créer des ressources de chaînes à utiliser par les outils de build d'Android.

Voir aussi : https://developer.android.com/guide/topics/resources/string-resource.html

includeexternal
Si défini, les entités externes sont incluses dans le document traduit (documenté) et pour l'extraction des chaînes. Si non défini, vous devrez traduire les entités externes comme des documents séparés.
ontagerror
Cette option définit le comportement du module lorsqu'il rencontre une syntaxe XML invalide (une balise de fermeture ne correspondant pas à la balise d'ouverture finale). Elle peut prendre les valeurs suivantes :
fail
C'est la valeur par défaut. Le module s'arrêtera avec une erreur.
warn
Le module continuera et émettra un avertissement.
silent
Le module continuera sans émettre d'avertissement.

Vous devez être prudent lorsque vous utilisez cette option. Il est généralement recommandé de corriger le fichier d'entrée.

tagsonly
Note : Cette option est obsolète.

Extrait uniquement les balises spécifiées dans l'option tags. Sinon, il extrait toutes les balises sauf celles spécifiées.

doctype
La chaîne qui tentera de correspondre à la première ligne du type de document du fichier (si elle est définie). Si ce n'est pas le cas, un avertissement sera émis indiquant que le document pourrait être d'un mauvais type.
addlang
La chaîne qui indique le chemin (par exemple, <bbb><aaa>) d'une balise où un attribut lang avec la valeur « ... » devra être ajouté. La langue sera définie comme le nom du fichier PO sans l'extension .po.
optionalclosingtag
Booléen indiquant si les balises de fermeture sont optionnelles (comme en HTML). Par défaut, les balises de fermeture manquantes génèrent une erreur, selon la valeur de ontagerror.
tags
Note : Cette option est obsolète. Vous devez utiliser les options translated et untranslated à la place.

Une liste séparée par des espaces de balises que vous souhaitez traduire ou ignorer. Par défaut, les balises spécifiées seront exclues, mais si vous utilisez l'option tagsonly, les balises spécifiées seront les seules incluses. Les balises doivent être au format <aaa>, mais vous pouvez en joindre certaines (<bbb><aaa>) pour indiquer que le contenu de la balise <aaa> ne sera traduit que lorsqu'il se trouve à l'intérieur d'une balise <bbb>.

Vous pouvez également spécifier certaines options de balise en plaçant certains caractères avant la hiérarchie des balises. Par exemple, vous pouvez utiliser w (wrap) ou W (no wrap) pour ignorer le comportement par défaut spécifié dans l'option globale wrap.

Exemple : W<chapter><title>

attributes
Une liste séparée par des espaces d'attributs de balises que vous souhaitez traduire. Vous pouvez spécifier les attributs par leur nom (par exemple, « lang »), mais vous pouvez également les préfixer avec une hiérarchie de balises pour indiquer que cet attribut ne sera traduit que s'il se trouve dans la balise spécifiée. Par exemple, <bbb><aaa>lang spécifie que l'attribut lang ne sera traduit que s'il est dans une balise <aaa> et qu'il se trouve à l'intérieur d'une balise <bbb>.
foldattributes
Ne traduit pas les attributs dans les balises inline. Au lieu de remplacer tous les attributs d'une balise par po4a-id=<id>.

Ceci est utile lorsque les attributs ne doivent pas être traduits, car cela simplifie les chaînes pour les traducteurs et évite les erreurs de type.

customtag
Une liste séparée par des espaces de balises qui ne sont pas traitées comme des balises. Ces balises sont traitées comme inline et n'ont pas besoin d'être fermées.
break
Une liste séparée par des espaces de balises qui doivent interrompre la séquence. Par défaut, toutes les balises interrompent la séquence.

Les balises doivent être au format <aaa>, mais vous pouvez en joindre certaines (<bbb><aaa>), si une balise (<aaa>) ne doit être prise en compte que lorsqu'elle se trouve à l'intérieur d'une autre balise (<bbb>).

Note : Une balise doit être répertoriée dans une seule des listes break.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

inline placeholder, ou customtag chaîne de configuration.

inline
Liste d'étiquettes séparées par des espaces qui doivent être traitées comme des étiquettes en ligne. Par défaut, toutes les étiquettes interrompent la séquence.

Les étiquettes doivent être sous la forme <aaa>, mais vous pouvez en joindre certaines (<bbb><aaa>), si une étiquette (<aaa>) ne doit être prise en compte que lorsqu'elle se trouve à l'intérieur d'une autre étiquette (<bbb>).

placeholder
Liste d'étiquettes séparées par des espaces qui doivent être traitées comme des espaces réservés. Les espaces réservés n'interrompent pas la séquence, mais le contenu des espaces réservés est traduit séparément.

L'emplacement de l'espace réservé dans son bloc sera marqué par une chaîne similaire à :

<placeholder type=\"footnote\" id=\"0\"/>

Les étiquettes doivent être sous la forme <aaa>, mais vous pouvez en joindre certaines (<bbb><aaa>), si une étiquette (<aaa>) ne doit être prise en compte que lorsqu'elle se trouve à l'intérieur d'une autre étiquette (<bbb>).

break-pi
Par défaut, les instructions de traitement (c'est-à-dire les étiquettes "<? ... ?>") sont traitées comme des étiquettes en ligne. Passez cette option si vous souhaitez que le PI soit traité comme une étiquette qui interrompt la séquence. Notez que les étiquettes PHP non traitées sont traitées comme des instructions de traitement par l'analyseur.
nodefault
Liste d'étiquettes séparées par des espaces que le module ne doit pas essayer de définir par défaut dans aucune catégorie.

Si vous avez une étiquette dont le paramètre par défaut est défini par la sous-classe de ce module, mais que vous souhaitez définir un paramètre alternatif, vous devez lister cette étiquette comme faisant partie de la chaîne de configuration nodefault.

cpp
Prend en charge les directives du préprocesseur C. Lorsque cette option est définie, po4a considérera les directives du préprocesseur comme des séparateurs de paragraphes. Ceci est important si le fichier XML doit être prétraité car, sinon, les directives pourraient être insérées au milieu des lignes si po4a les considère comme appartenant au paragraphe courant, et elles ne seraient pas reconnues par le préprocesseur. Remarque : les directives du préprocesseur ne doivent apparaître qu'entre des balises (elles ne doivent pas interrompre une balise).
translated
Liste d'étiquettes séparées par des espaces que vous souhaitez traduire.

Les étiquettes doivent être sous la forme <aaa>, mais vous pouvez en joindre certaines (<bbb><aaa>), si une étiquette (<aaa>) ne doit être prise en compte que lorsqu'elle se trouve à l'intérieur d'une autre étiquette (<bbb>).

Vous pouvez également spécifier certaines options d'étiquettes en plaçant des caractères devant la hiérarchie des étiquettes. Cela remplace le comportement par défaut spécifié par les options globales wrap et defaulttranslateoption.

w
Les étiquettes doivent être traduites et le contenu peut être réenveloppé.
W
Les étiquettes doivent être traduites et le contenu ne doit pas être réenveloppé.
i
Les étiquettes doivent être traduites en ligne.
p
Les étiquettes doivent être traduites en tant qu'espaces réservés.

En interne, l'analyseur XML ne se soucie que de ces quatre options : w W i p.

* Les étiquettes listées dans break sont définies sur w ou W en fonction de l'option wrap.

* Les étiquettes listées dans inline sont définies sur i.

* Les étiquettes listées dans placeholder sont définies sur p.

* Les étiquettes listées dans untranslated ne sont sans aucune de ces options définies.

Vous pouvez vérifier le comportement réel des paramètres internes en appelant po4a avec l'option --debug.

Exemple : W<chapter><title>

Veuillez noter qu'une étiquette doit être listée dans la chaîne de configuration translated ou untranslated.

untranslated
Liste d'étiquettes séparées par des espaces que vous ne souhaitez pas traduire.

Les étiquettes doivent être sous la forme <aaa>, mais vous pouvez en joindre certaines (<bbb><aaa>), si une étiquette (<aaa>) ne doit être prise en compte que lorsqu'elle se trouve à l'intérieur d'une autre étiquette (<bbb>).

Veuillez noter qu'une étiquette en ligne traduisible dans une étiquette non traduisible est traitée comme une étiquette de rupture traduisible, le réglage i est supprimé et w ou W est défini en fonction de l'option wrap.

defaulttranslateoption
Les catégories par défaut pour les étiquettes qui ne figurent dans aucune des catégories translated, untranslated, break, inline ou placeholder.

Il s'agit d'un ensemble de lettres telles que définies dans translated et ce paramètre n'est valide que pour les étiquettes traduisibles.

ÉCRIRE DES MODULES DÉRIVÉS

DÉFINIR QUELLES BALISES ET ATTRIBUTS TRADUIRE

La personnalisation la plus simple consiste à définir quelles balises et quels attributs vous souhaitez que l'analyseur traduise. Cela doit être fait dans la fonction initialize. Tout d'abord, vous devez appeler l'initialisation principale pour obtenir les options de la ligne de commande, puis ajouter vos définitions personnalisées au hachage des options. Si vous souhaitez traiter de nouvelles options à partir de la ligne de commande, vous devez les définir avant d'appeler l'initialisation principale :

$self->{options}{'new_option'}='';
$self->SUPER::initialize(%options);
$self->{options}{'_default_translated'}.=' <p> <head><title>';
$self->{options}{'attributes'}.=' <p>lang id';
$self->{options}{'_default_inline'}.=' <br>';
$self->treat_options;

Vous devez utiliser les options _default_inline, _default_break, _default_placeholder, _default_translated, _default_untranslated et _default_attributes dans les modules dérivés. Cela permet aux utilisateurs de remplacer le comportement par défaut défini dans votre module par des options de ligne de commande.

REMPLACER LE COMPORTEMENT PAR DÉFAUT AVEC LES OPTIONS DE LIGNE DE COMMANDE

Si le comportement par défaut de ce module xml et de ses modules dérivés ne vous convient pas, vous pouvez fournir des options de ligne de commande pour modifier leur comportement.

Voir Locale::Po4a::Docbook(3pm),

REMPLACER LA FONCTION found_string

Une autre étape simple consiste à remplacer la fonction "found_string", qui reçoit les chaînes extraites de l'analyseur, afin de les traduire. Vous pouvez y contrôler quelles chaînes vous souhaitez traduire et effectuer des transformations sur celles-ci avant ou après la traduction elle-même.

Elle reçoit le texte extrait, la référence à son emplacement et un hachage contenant des informations supplémentaires pour contrôler quelles chaînes traduire, comment les traduire et générer le commentaire.

Le contenu de ces options dépend du type de chaîne (spécifié dans une entrée de ce hachage) :

type="tag"
La chaîne trouvée est le contenu d'une étiquette traduisible. L'entrée "tag_options" contient les caractères d'option devant la hiérarchie des étiquettes dans l'option "tags" du module.
type="attribute"
Indique que la chaîne trouvée est la valeur d'un attribut traduisible. L'entrée "attribute" contient le nom de l'attribut.

Elle doit retourner le texte qui remplacera l'original dans le document traduit. Voici un exemple basique de cette fonction :

sub found_string {
  my ($self,$text,$ref,$options)=@_;
  $text = $self->translate($text,$ref,"type ".$options->{'type'},
    'wrap'=>$self->{options}{'wrap'});
  return $text;
}

Il existe un autre exemple simple dans le nouveau module Dia, qui filtre uniquement certaines chaînes.

MODIFIER LES TYPES DE BALISES (À FAIRE)

C'est une tâche plus complexe, mais elle permet une personnalisation (presque) totale. Elle est basée sur une liste de hachages, chacun définissant le comportement d'un type d'étiquette. La liste doit être triée de manière à ce que les étiquettes les plus générales soient après les plus concrètes (triées d'abord par les clés de début, puis par les clés de fin). Pour définir un type d'étiquette, vous devrez créer un hachage avec les clés suivantes :

beginning
Spécifie le début de l'étiquette, après le "<".
end
Spécifie la fin de l'étiquette, avant le ">".
breaking
Indique s'il s'agit d'une classe d'étiquettes qui interrompent la séquence. Une étiquette non interrompue (en ligne) est une étiquette qui peut faire partie du contenu d'une autre étiquette. Elle peut prendre les valeurs false (0), true (1) ou undefined. Si vous laissez cette valeur indéfinie, vous devrez définir la fonction f_breaking qui indiquera si une étiquette concrète de cette classe interrompt la séquence ou non.
f_breaking
C'est une fonction qui indiquera si l'étiquette suivante interrompt la séquence ou non. Elle doit être définie si l'option breaking ne l'est pas.
f_extract
Si vous laissez cette clé indéfinie, la fonction d'extraction générique devra extraire l'étiquette elle-même. C'est utile pour les étiquettes qui peuvent contenir d'autres étiquettes ou des structures spéciales, afin que l'analyseur principal ne pose pas de problème. Cette fonction reçoit un booléen qui indique si l'étiquette doit être supprimée du flux d'entrée ou non.
f_translate
Cette fonction reçoit l'étiquette (au format get_string_until()) et retourne l'étiquette traduite (attributs traduits ou toutes les transformations nécessaires) sous forme de chaîne unique.

FONCTIONS INTERNES utilisées pour écrire des analyseurs dérivés

FONCTIONS INTERNES utilisées pour écrire des analyseurs dérivés

TRAVAIL AVEC LES BALISES

get_path()
Cette fonction retourne le chemin vers la balise actuelle depuis la racine du document, sous la forme <html><body><p>.

Un tableau supplémentaire de balises (sans crochets) peut être passé en argument. Ces éléments de chemin sont ajoutés à la fin du chemin actuel.

tag_type()
Cette fonction retourne l'index de la liste `tag_types` qui correspond à la prochaine balise dans le flux d'entrée, ou -1 si nous sommes à la fin du fichier d'entrée.

Ici, la balise a la structure commencée par < et terminée par > et elle peut contenir plusieurs lignes.

Ceci fonctionne sur le tableau "@{$self->{TT}{doc_in}}" contenant les données du document d'entrée et la référence indirectement via "$self->shiftline()" et "$self->unshiftline($$)".

extract_tag($$)
Cette fonction retourne la prochaine balise du flux d'entrée sans le début et la fin, sous forme de tableau, afin de maintenir les références du fichier d'entrée. Elle possède deux paramètres: le type de la balise (tel que retourné par tag_type) et un booléen qui indique si elle doit être supprimée du flux d'entrée.

Ceci fonctionne sur le tableau "@{$self->{TT}{doc_in}}" contenant les données du document d'entrée et la référence indirectement via "$self->shiftline()" et "$self->unshiftline($$)".

get_tag_name(@)
Cette fonction retourne le nom de la balise passée en argument, sous la forme de tableau retournée par extract_tag.
breaking_tag()
Cette fonction retourne un booléen qui indique si la prochaine balise dans le flux d'entrée est une balise de rupture (balise en ligne) ou non. Elle laisse le flux d'entrée intact.
treat_tag()
Cette fonction traduit la prochaine balise du flux d'entrée. Elle utilise les fonctions de traduction personnalisées de chaque type de balise.

Ceci fonctionne sur le tableau "@{$self->{TT}{doc_in}}" contenant les données du document d'entrée et la référence indirectement via "$self->shiftline()" et "$self->unshiftline($$)".

tag_in_list($@)
Cette fonction retourne une valeur de chaîne de caractères indiquant si le premier argument (une hiérarchie de balises) correspond à l'une des balises de la seconde liste d'arguments (une liste de balises ou de hiérarchies de balises). Si elle ne correspond pas, elle retourne 0. Sinon, elle retourne les options de la balise correspondante (les caractères devant la balise) ou 1 (si cette balise n'a pas d'options).

TRAVAIL AVEC LES ATTRIBUTS

treat_attributes(@)
Cette fonction gère la traduction des attributs des balises. Elle reçoit la balise sans les marques de début/fin, puis elle trouve les attributs et traduit ceux qui sont traduisibles (spécifiés par l'option du module attributes). Elle retourne une chaîne de caractères simple avec la balise traduite.

TRAVAIL AVEC LES CONTENUS BALISÉS

treat_content()
Cette fonction récupère le texte jusqu'à la prochaine balise de rupture (non en ligne) du flux d'entrée. Elle le traduit en utilisant les fonctions de traduction personnalisées de chaque type de balise.

Ceci fonctionne sur le tableau "@{$self->{TT}{doc_in}}" contenant les données du document d'entrée et la référence indirectement via "$self->shiftline()" et "$self->unshiftline($$)".

TRAVAIL AVEC LES OPTIONS DU MODULE

treat_options()
Cette fonction remplit les structures internes qui contiennent les balises, les attributs et les données en ligne avec les options du module (spécifiées sur la ligne de commande ou dans la fonction d'initialisation).

OBTENIR DU TEXTE DU DOCUMENT D'ENTRÉE

get_string_until($%)
Cette fonction retourne un tableau avec les lignes (et leurs références) du document d'entrée jusqu'à ce qu'elle trouve le premier argument. Le second argument est une table d'options. La valeur 0 signifie désactivé (par défaut) et 1, activé.

Les options valides sont:

include
Ceci fait que le tableau retourné contienne le texte recherché
remove
Ceci supprime le flux retourné de l'entrée
unquoted
Ceci garantit que le texte recherché est à l'extérieur de toute citation
regex
Ceci indique que le premier argument est une expression régulière plutôt qu'une chaîne de caractères simple
skip_spaces(\@)
Cette fonction reçoit en argument la référence à un paragraphe (dans le format retourné par get_string_until), saute ses espaces en tête et les retourne sous forme de chaîne de caractères simple.
join_lines(@)
Cette fonction retourne une chaîne de caractères simple avec le texte du tableau d'arguments (en écartant les références).

    Locale::Po4a::Xml

    Version : 3pm

    Section : Perl module

    DESCRIPTION

    Cette page de manuel décrit la bibliothèque Perl Locale::Po4a::Xml.

    Elle fait partie du système po4a (po 4 all) qui vise à faciliter la traduction de la documentation technique.

    UTILISATION

    La bibliothèque Locale::Po4a::Xml est utilisée par d'autres scripts po4a pour gérer la traduction de fichiers XML.

    Elle fournit des fonctionnalités pour :

    • Analyser les fichiers XML d'entrée.
    • Extraire les chaînes de caractères à traduire.
    • Gérer les fichiers de traduction .po associés.
    • Réintégrer les traductions dans le fichier XML de sortie.

    EXEMPLES

    Des exemples d'utilisation peuvent être trouvés dans la documentation du paquet po4a.
