NOM

Locale::Po4a::Po - Module pour la manipulation de catalogues de messages

SYNTAXE

use Locale::Po4a::Po;
my $pofile=Locale::Po4a::Po->new();
# Lire un catalogue de messages
$pofile->read('file.po');
# Ajouter une entrée
$pofile->push('msgid' => 'Hello', 'msgstr' => 'bonjour',
              'flags' => "wrap", 'reference'=>'file.c:46');
# Extraire une traduction
$pofile->gettext("Hello"); # retourne 'bonjour'
# Écrire à nouveau dans un fichier
$pofile->write('otherfile.po');

DESCRIPTION

Locale::Po4a::Po est un module qui permet de manipuler des catalogues de messages. Vous pouvez charger et écrire dans un fichier (dont le nom est généralement po), vous pouvez construire de nouvelles entrées à la volée ou demander la traduction d'une chaîne.

Pour une description plus complète des catalogues de messages au format PO et de leur utilisation, veuillez consulter la documentation d'information du programme gettext (nœud « `Fichiers PO` »).

Ce module fait partie du projet po4a, qui vise à utiliser des fichiers de type PO (développés initialement pour faciliter la traduction des messages de programmes) pour traduire tout, y compris la documentation (pages man, manuels d'info), la description de paquets, les templates debconf et tout ce qui pourrait en bénéficier.

OPTIONS ACCEPTÉES PAR CE MODULE

--porefs type
Indique le format de référence. L'argument type peut être never pour ne produire aucune référence, file pour indiquer le fichier sans numéro de ligne, counter pour remplacer le numéro de ligne par un compteur incrémenté, et full pour inclure des références complètes (valeur par défaut : full).
--wrap-po no|newlines|nombre (valeur par défaut : 76)
Indique comment le fichier po doit être empaqueté. Ceci offre le choix entre des fichiers bien empaquetés mais pouvant provoquer des conflits dans git, ou des fichiers plus faciles à gérer automatiquement mais plus difficiles à lire pour les humains.

Historiquement, la suite gettext reformattait les fichiers po à la colonne 77 pour une meilleure lisibilité. Cette option indique le comportement de po4a. Si elle est définie à une valeur numérique, po4a empaquète le fichier po après cette colonne et après de nouvelles lignes dans le contenu. Si elle est définie à newlines, po4a divise le msgid et le msgstr après de nouvelles lignes dans le contenu. Si elle est définie à no, po4a n'empaquète pas le fichier. Les commentaires de référence sont toujours empaquetés par les outils de texte internes.

Note : cette option n'a pas d'impact sur la façon dont les msgid et msgstr sont empaquetés, c'est-à-dire sur la façon dont les nouvelles lignes sont ajoutées aux contenus de ces chaînes.

--msgid-bugs-address courriel@adresse
Définit l'adresse de courriel pour signaler les bugs dans les msgid. Par défaut, les fichiers POT créés n'ont pas de champ Report-Msgid-Bugs-To.
--copyright-holder chaîne
Définit le détenteur du copyright dans l'en-tête POT. La valeur par défaut est « Free Software Foundation, Inc. ».
--package-name chaîne
Définit le nom du paquet pour l'en-tête POT. La valeur par défaut est « PACKAGE ».
--package-version chaîne
Définit la version du paquet pour l'en-tête POT. La valeur par défaut est « VERSION ».

Fonctions concernant les catalogues de messages complets

new()
Crée un nouveau catalogue de messages. Si un argument est fourni, c'est le nom d'un fichier po à charger.
read($)
Lit un catalogue de messages (dont le nom est fourni en argument). Les entrées déjà existantes dans self ne sont pas supprimées, mais ajoutées à la fin du catalogue.
write($)
Écrit le catalogue actuel dans le fichier donné.
write_if_needed($$)
Comme write, mais si le fichier po ou POT existe déjà, l'objet sera écrit dans un fichier temporaire qui sera comparé au fichier existant pour vérifier si la mise à jour est nécessaire (évite de changer un POT juste pour mettre à jour une référence de ligne ou le champ POT-Creation-Date).
filter($)
Cette fonction extrait un catalogue d'un catalogue existant. Seules les entrées ayant une référence dans le fichier donné seront placées dans le catalogue résultat.

Cette fonction analyse son argument, le transforme en une définition de fonction Perl, évalue cette définition et filtre les entrées dont le champ retourne vrai.

J'adore Perl parfois ;)

Fonctions pour utiliser un catalogue de messages pour des traductions

gettext($%)
Requiert la traduction de la chaîne donnée en argument dans le catalogue actuel. Si la chaîne n'est pas trouvée, retourne la chaîne originale (non traduite).

Après la chaîne à traduire, vous pouvez passer un hash d'arguments supplémentaires. Voici les entrées valides :

wrap
un booléen indiquant si nous pouvons considérer les espaces blancs dans la chaîne comme importants. Si oui, la fonction canonise la chaîne avant de chercher une traduction, et arrange le résultat.
wrapcol
la colonne à laquelle nous devons arranger (valeur par défaut : 76).
stats_get()
Retourne des statistiques sur le pourcentage de succès de gettext depuis la dernière fois que stats_clear() a été appelé. Veuillez noter que ce ne sont pas les mêmes statistiques que celles imprimées par msgfmt --statistic. Ici, ce sont des statistiques sur l'utilisation récente du fichier PO, tandis que msgfmt rapporte l'état du fichier. Exemple d'utilisation : 
[utilisation d'un fichier PO pour traduire quelque chose]
($percent,$hit,$queries) = $pofile->stats_get();
print "Jusqu'à présent, nous avons trouvé des traductions pour $percent\%  ($hit sur $queries) chaînes.\n";
stats_clear()
Réinitialise les statistiques sur les succès de gettext.

Fonctions pour construire un catalogue de messages

push(%)
Aj

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

ush une nouvelle entrée à la fin du catalogue actuel. Les arguments doivent former une table de hachage. Les clés valides sont :
msgid
la chaîne dans la langue originale.
msgstr
la traduction.
reference
une indication de l'endroit où cette chaîne a été trouvée. Exemple : file.c:46 (ce qui signifie dans 'file.c' à la ligne 46). Il peut s'agir d'une liste séparée par des espaces en cas de multiples occurrences.
comment
un commentaire ajouté manuellement ici (par les traducteurs). Le format ici est libre.
automatic
un commentaire qui a été ajouté automatiquement par le programme d'extraction de chaînes. Voir l'option --add-comments du programme xgettext pour plus d'informations.
flags
liste d'indicateurs séparés par des espaces pour toutes les entrées définies pour cette entrée.

Les indicateurs valides sont : c-text, python-text, lisp-text, elisp-text, librep-text, smalltalk-text, java-text, awk-text, object-pascal-text, ycp-text, tcl-text, wrap, no-wrap et fuzzy.

Voir la documentation gettext pour leur signification.

type
c'est principalement un argument interne : il est utilisé lors de la traduction de documents. L'idée ici est d'analyser l'original et la traduction en un objet PO, et de les fusionner, en utilisant le msgid de l'un comme msgid et le msgid de l'autre comme msgstr. Pour s'assurer que tout se passe bien, chaque msgid dans les objets PO se voit attribuer un type, basé sur sa structure (comme "chapt", "sect1", "p" et ainsi de suite dans DocBook). Si les types des chaînes ne sont pas les mêmes, cela signifie que les deux fichiers ne partagent pas la même structure, et le processus signale une erreur.

Cette information est écrite comme un commentaire automatique dans le fichier PO car cela donne aux traducteurs un contexte sur les chaînes à traduire.

wrap
booléen indiquant si les espaces blancs peuvent être modifiés lors de la mise en forme cosmétique. Si vrai, la chaîne est canonisée avant utilisation.

Cette information est écrite dans le fichier PO en utilisant l'indicateur wrap ou no-wrap.

wrapcol
ignoré ; la clé est conservée pour la compatibilité ascendante.

Fonctions diverses

count_entries()
Retourne le nombre d'entrées dans le catalogue (sans l'en-tête).
count_entries_doc()
Retourne le nombre d'entrées dans le document. Si une chaîne apparaît plusieurs fois dans le document, elle sera comptée plusieurs fois.
msgid($)
Retourne le msgid du numéro donné.
msgid_doc($)
Retourne le msgid avec la position donnée dans le document.
type_doc($)
Retourne le type du msgid avec la position donnée dans le document. Ceci est probablement uniquement utile pour la traduction automatique, et il est stocké séparément de {$msgid}{'type'} car ce dernier peut être écrasé par un autre type lorsque le $msgid est dupliqué dans le document maître.
get_charset()
Retourne le jeu de caractères spécifié dans l'en-tête du PO. S'il n'a pas été défini, il retournera "UTF-8".
