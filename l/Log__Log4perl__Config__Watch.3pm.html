NOM

Log::Log4perl::Config::Watch - Détecter les changements de fichiers

SYNOPSIS

use Log::Log4perl::Config::Watch;
my $watcher = Log::Log4perl::Config::Watch->new(
                      file            => "/data/my.conf",
                      check_interval  => 30,
              );
while(1) {
    if($watcher->change_detected()) {
        print "Changement détecté !\n";
    }
    sleep(1);
}

DESCRIPTION

Ce module aide à détecter les changements dans les fichiers. Bien qu'il provienne de la distribution "Log::Log4perl", il peut être utilisé indépendamment.

Le constructeur définit le fichier à surveiller et l'intervalle de vérification en secondes. Les appels ultérieurs à change_detected()

  • renverront une valeur fausse immédiatement sans effectuer de vérifications physiques du fichier si "check_interval" n'a pas expiré.
  • effectueront un test physique sur le fichier spécifié si le nombre de secondes spécifié dans "check_interval" s'est écoulé depuis la dernière vérification physique. Si la date de modification du fichier a changé depuis la dernière vérification physique, il renverra une valeur vraie, sinon une valeur fausse sera renvoyée.

En résumé : "check_interval" vous permet d'appeler la fonction change_detected() aussi souvent que vous le souhaitez, sans payer une pénalité de performance significative car les opérations du système de fichiers sont effectuées (cependant, vous payez le prix de ne pas connaître les changements de fichiers avant que "check_interval" secondes ne se soient écoulées).

Le module distingue clairement l'heure système de l'heure du système de fichiers. Si votre système de fichiers (par exemple, monté en NFS) a un décalage constant par rapport à l'horloge de l'ordinateur exécutant le code, cela fonctionnera correctement.

Pour désactiver la fonction de délai d'économie de ressources, définissez simplement "check_interval" sur 0 et change_detected() exécutera une vérification physique du fichier à chaque appel.

Si vous disposez déjà de l'heure actuelle, vous pouvez la passer à change_detected() en tant que paramètre optionnel, comme dans

change_detected($time)

qui ne déclenchera alors pas un appel à time(), mais utilisera la valeur fournie.

MODE SIGNAUX

Au lieu d'interroger l'heure et les changements de fichiers, new() peut être instruit pour configurer un gestionnaire de signaux. Si vous appelez le constructeur comme ceci :

my $watcher = Log::Log4perl::Config::Watch->new(
                      file    => "/data/my.conf",
                      signal  => 'HUP'
              );

alors un gestionnaire de signaux sera installé, réglant la variable de l'objet "$self->{signal_caught}" à une valeur vraie lorsque le signal arrive. Cela s'accompagne de tous les problèmes liés aux gestionnaires de signaux.

DÉCLENCHEMENT_DES_VÉRIFICATIONS

Pour déclencher une vérification physique du fichier lors du prochain appel à change_detected(), que "check_interval" ait expiré ou non, appelez :

$watcher->force_next_check();

sur l'objet watcher.

DÉTECTION_DES_FICHIERS_DÉPLACÉS

Le watcher peut également être utilisé pour détecter les fichiers qui ont été déplacés. Il ne détectera pas seulement si un fichier surveillé a disparu, mais aussi s'il a été remplacé par un nouveau fichier entre-temps.

my $watcher = Log::Log4perl::Config::Watch->new(
    file           => "/data/my.conf",
    check_interval => 30,
);
while(1) {
    if($watcher->file_has_moved()) {
        print "Le fichier a été déplacé !\n";
    }
    sleep(1);
}

Les paramètres "check_interval" et "signal" limitent le nombre de vérifications physiques du système de fichiers, de manière similaire à change_detected().
