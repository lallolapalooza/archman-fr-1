NOM

LWP::Protocol::ldap - Fournit le support LDAP pour LWP::UserAgent

SYNOPSIS

use LWP::UserAgent;
$ua = LWP::UserAgent->new();
$res = $ua->get('ldap://ldap.example.com/' .
                'o=University%20of%20Michigan,c=US??sub?(cn=Babs%20Jensen)',
                 Accept => 'text/json'):

DESCRIPTION

Le module LWP::Protocol::ldap fournit le support pour utiliser les URLs avec le schéma ldap suivant la RFC 4516 avec LWP. Ce module est un module d'extension pour la gestion des protocoles de LWP, donc vous ne l'utilisez pas directement.

En plus d'être utilisé avec les URIs LDAP, LWP::Protocol::ldap sert également de classe de base pour ses modules frères LWP::Protocol::ldaps et LWP::Protocol::ldapi.

Fonctionnalités

Méthodes HTTP supportées

LWP::Protocol::ldap implémente les méthodes HTTP GET et HEAD. Elles sont mappées à l'opération de recherche LDAP,

Format de réponse

Selon l'en-tête HTTP Accept fourni par l'agent utilisateur, LWP::Protocol::ldap peut répondre aux requêtes dans l'un des formats suivants :

DSML
Lorsque l'en-tête HTTP Accept contient le type MIME "text/dsml", la réponse est envoyée en DSMLv1.
JSON
Lorsque l'en-tête HTTP Accept contient le type MIME "text/json", la réponse est envoyée en JSON. Pour que cela fonctionne, le module Perl JSON doit être installé.
LDIF
Lorsque l'en-tête HTTP Accept contient le type MIME "text/ldif", la réponse est envoyée au format LDIFv1.
HTML
Si aucun en-tête HTTP Accept n'a été envoyé ou si aucun des types MIME ci-dessus n'a pu être détecté, et que l'extension x-format n'a pas non plus été fournie, la réponse est envoyée en utilisant du balisage HTML dans un tableau à 2 colonnes (globalement inspiré de LDIF).

En alternative à l'envoi d'un en-tête HTTP Accept, LWP::Protocol::ldap accepte également l'extension "x-format"

Exemple:

ldap://ldap.example.com/o=University%20of%20Michigan,c=US??sub?(cn=Babs%20Jensen)?x-format=dsml

Support TLS

Pour les URIs ldap et ldapi, le module implémente l'extension "x-tls" qui bascule la connexion LDAP vers TLS en utilisant un appel à la méthode start_tls.

Exemple:

ldap://ldap.example.com/o=University%20of%20Michigan,c=US??sub?(cn=Babs%20Jensen)?x-tls=1

Note : Dans l'exemple ci-dessus, donner idéalement "x-tls" devrait suffire, mais malheureusement le parseur dans URI::ldap a un petit défaut.

Autorisation

Habituellement, la connexion est effectuée de manière anonyme, mais si l'en-tête HTTP Authorization est fourni avec des identifiants pour une autorisation HTTP basique, les identifiants donnés dans cet en-tête seront utilisés pour effectuer une liaison simple au serveur LDAP.
