Module Location
: sig end

Codes d'emplacement (plages de positions), utilisés dans parsetree.

Avertissement : ce module est instable et fait partie de Compiler_libs .

type t = Warnings.loc = {
loc_start : Lexing.position ;
loc_end : Lexing.position ;
loc_ghost : bool ;
}

t représente une plage de caractères dans le code source.

loc_ghost=false lorsque l'arbre de syntaxe décrit par l'emplacement peut être analysé à partir de l'emplacement. Dans tous les autres cas, loc_ghost doit être true. La plupart des emplacements produits par l'analyseur ont loc_ghost=false. Lorsque loc_ghost=true, l'emplacement est une approximation de meilleure tentative.

Ces informations sont utilisées par des outils comme merlin qui veulent relier le code source aux arbres d'analyse ou aux arbres ultérieurs. ocamlprof ignore l'instrumentation des nœuds fantômes.

Exemple : dans `let f x = x`, nous avons :

- un élément de structure à l'emplacement "let f x = x"

- un modèle "f" à l'emplacement "f"

- une expression "fun x -> x" à l'emplacement "x = x" avec loc_ghost=true

- un modèle "x" à l'emplacement "x"

- une expression "x" à l'emplacement "x" Dans ce cas, chaque nœud a loc_ghost=false, à l'exception du nœud "fun x -> x", car Parser.expression (Lexing.from_string "x = x") échouerait à l'analyse. En revanche, dans `let f = fun x -> x`, chaque nœud a loc_ghost=false.

Les directives de ligne peuvent modifier arbitrairement les noms de fichiers et les numéros de ligne, ce qui est orthogonal à loc_ghost, qui décrit la plage de caractères de loc_start.pos_cnum à loc_end.pos_cnum dans la chaîne analysée.

Remarque sur l'utilisation de Lexing.position dans ce module. Si pos_fname = "", alors il utilise !input_name. Si pos_lnum = -1, alors pos_bol = 0. Il utilise pos_cnum et ré-analyse le fichier pour obtenir le numéro de ligne et de caractère. Sinon, tous les champs sont corrects.

Chemin de réécriture

val rewrite_absolute_path : string -> string

rewrite_absolute_path path réécrit path pour honorer la variable BUILD_PATH_PREFIX_MAP si elle est définie. Il ne vérifie pas si path est absolu ou non. Le résultat est le suivant :

- Si BUILD_PATH_PREFIX_MAP n'est pas défini, il renvoie simplement path.

- Sinon, il réécrit en utilisant le mappage (et si aucun mappage ne correspond, il renvoie path).

Voir la spécification de BUILD_PATH_PREFIX_MAP.

val rewrite_find_first_existing : string -> string option

rewrite_find_first_existing path utilise un mappage de BUILD_PATH_PREFIX_MAP et essaie de trouver un fichier auquel il correspond à un résultat qui existe dans le système de fichiers. Les résultats possibles sont :

- None , ce qui signifie que :

- BUILD_PATH_PREFIX_MAP n'est pas défini et path n'existe pas, ou

- aucun préfixe source pour path n'est dans le mappage, ou

- Some target , ce qui signifie que target existe et :

- BUILD_PATH_PREFIX_MAP n'est pas défini et target = path , ou

- target est le premier fichier (dans l'ordre de priorité) auquel path correspond à un résultat qui existe dans le système de fichiers.

- Not_found levé, ce qui signifie que certains préfixes sources dans le mappage correspondent à path mais aucun d'entre eux n'existe dans le système de fichiers. L'appelant doit intercepter cette erreur et émettre un message approprié.

Voir la spécification de BUILD_PATH_PREFIX_MAP.

val rewrite_find_all_existing_dirs : string -> string list

rewrite_find_all_existing_dirs dir accumule une liste de répertoires existants, dirs , qui sont les résultats de la mise en correspondance d'un répertoire abstrait, dir , à travers toutes les paires de mappage dans l'environnement BUILD_PATH_PREFIX_MAP, s'il y en a. La liste dirs est triée par priorité (la tête ayant la plus haute priorité).

Les résultats possibles sont :

- [] , ce qui signifie que :

- BUILD_PATH_PREFIX_MAP n'est pas défini et dir n'est pas un répertoire existant, ou

- s'il est défini, aucun préfixe ne correspond à dir .

- Some dirs , ce qui signifie que dirs sont les répertoires trouvés. Soit :

- BUILD_PATH_PREFIX_MAP n'est pas défini et dirs = [dir] , ou

- il a été défini et dirs sont les répertoires existants qui ont été mis en correspondance.

- Not_found levé, ce qui signifie que certains préfixes sources dans le mappage correspondent à dir , mais aucun des résultats de mappage n'était un répertoire existant (potentiellement dû à une configuration incorrecte). L'appelant doit intercepter cette erreur et émettre un message approprié.

Voir la spécification de BUILD_PATH_PREFIX_MAP.

val absolute_path : string -> string

absolute_path path crée d'abord un chemin absolu, s , à partir de path , en ajoutant le répertoire courant si path était relatif. Ensuite, s est réécrit avec rewrite_absolute_path . Enfin, le résultat est normalisé en supprimant les instances de '.' ou '..' .

Rapports automatiques d'erreurs pour les exceptions levées

val register_error_of_exn : (exn -> error option) -> unit

Chaque module de compilation qui définit un type d'exception personnalisé pouvant apparaître comme une erreur visible doit enregistrer un "imprimeur" pour cette exception en utilisant register_error_of_exn . Le résultat de l'imprimeur est une valeur error contenant une localisation, un message et optionnellement des sous-messages (chacun étant également localisé).

val error_of_exn : exn -> [ `Already_displayed | `Ok of error ] option

exception Error of error

Lancer Error e signale une erreur e ; l'exception sera interceptée et l'erreur sera imprimée.

exception Already_displayed_error

Lancer Already_displayed_error signale une erreur qui a déjà été imprimée. L'exception sera interceptée, mais rien ne sera imprimé.
