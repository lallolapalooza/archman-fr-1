List::Compare(3) Documentation Perl fournie par l'utilisateur List::Compare(3)

NOM

List::Compare - Comparer les éléments de deux listes ou plus

VERSION

Ce document fait référence à la version 0.55 de List::Compare. Cette version a été publiée le 16 août 2020.

SYNOPIS

Les éléments essentiels :

@Llist = qw(abel abel baker camera delta edward fargo golfer);
@Rlist = qw(baker camera delta delta edward fargo golfer hilton);
$lc = List::Compare->new(\@Llist, \@Rlist);
@intersection = $lc->get_intersection;
@union = $lc->get_union;

... et ainsi de suite.

DISCUSSION : Modes et Méthodes

Cas Régulier : Comparer Deux Listes

  • Constructeur : new()

    Crée un objet List::Compare. Placez les deux listes dans des tableaux (nommés ou anonymes) et passez des références aux tableaux au constructeur.

    $lc = List::Compare->new(\@Llist, \@Rlist);

    Par défaut, les méthodes de List::Compare retournent des listes qui sont triées en utilisant le mode de tri par défaut de Perl "sort" : tri ASCII-alphabétique. Si vous n'avez pas besoin que ces listes soient triées, vous pouvez obtenir un gain de vitesse en construisant l'objet List::Compare avec l'option non triée :

    $lc = List::Compare->new('-u', \@Llist, \@Rlist);

    ou

    $lc = List::Compare->new('--unsorted', \@Llist, \@Rlist);
  • Constructeur Alternatif

    Si vous préférez une délimitation plus explicite des types d'arguments passés à une fonction, vous pouvez utiliser ce constructeur de type 'hashref unique' pour construire un objet List::Compare :

    $lc = List::Compare->new( { lists => [\@Llist, \@Rlist] } );

    ou

    $lc = List::Compare->new( {
    lists    => [\@Llist, \@Rlist],
    unsorted => 1,
} );
  • get_intersection()

    Obtient les éléments qui apparaissent au moins une fois dans les deux listes (leur intersection).

    @intersection = $lc->get_intersection;
  • get_union()

    Obtient les éléments qui apparaissent au moins une fois dans l'une ou l'autre liste (leur union).

    @union = $lc->get_union;
  • get_unique()

    Obtient les éléments qui apparaissent (au moins une fois) uniquement dans la première liste.

    @Lonly = $lc->get_unique;
@Lonly = $lc->get_Lonly;    # alias
  • get_complement()

    Obtient les éléments qui apparaissent (au moins une fois) uniquement dans la seconde liste.

    @Ronly = $lc->get_complement;
@Ronly = $lc->get_Ronly;            # alias
  • get_symmetric_difference()

    Obtient les éléments qui apparaissent au moins une fois dans la première ou la seconde liste, mais pas dans les deux.

    @LorRonly = $lc->get_symmetric_difference;
@LorRonly = $lc->get_symdiff;       # alias
@LorRonly = $lc->get_LorRonly;      # alias
  • get_bag()

    Crée un sac de tous les éléments des deux listes. Le sac diffère de l'union des deux listes en ce qu'il contient autant de copies d'éléments individuels qu'ils apparaissent dans les listes d'origine.

    @bag = $lc->get_bag;
  • Retourner des références plutôt que des listes

    Une approche alternative aux méthodes ci-dessus : Si vous n'avez pas immédiatement besoin d'un tableau comme valeur de retour de l'appel de méthode, mais avez simplement besoin d'une *référence* à un tableau (anonyme), utilisez l'une des méthodes parallèles suivantes :

    $intersection_ref = $lc->get_intersection_ref;
$union_ref        = $lc->get_union_ref;
$Lonly_ref        = $lc->get_unique_ref;
$Lonly_ref        = $lc->get_Lonly_ref;                 # alias
$Ronly_ref        = $lc->get_complement_ref;
$Ronly_ref        = $lc->get_Ronly_ref;                 # alias
$LorRonly_ref     = $lc->get_symmetric_difference_ref;
$LorRonly_ref     = $lc->get_symdiff_ref;               # alias
$LorRonly_ref     = $lc->get_LorRonly_ref;              # alias
$bag_ref          = $lc->get_bag_ref;
  • is_LsubsetR()

    Retourne une valeur vraie si le premier argument passé au constructeur ('L' pour 'gauche') est un sous-ensemble du second argument passé au constructeur ('R' pour 'droite').

    $LR = $lc->is_LsubsetR;

    Retourne une valeur vraie si R est un sous-ensemble de L.

    $RL = $lc->is_RsubsetL;
  • is_LequivalentR()

    Retourne une valeur vraie si les deux listes passées au constructeur sont équivalentes, c'est-à-dire si chaque élément de la liste de gauche ('L') apparaît au moins une fois dans la liste de droite ('R') et vice versa.

    $eqv = $lc->is_LequivalentR;
$eqv = $lc->is_LeqvlntR;            # alias
  • is_LdisjointR()

    Retourne une valeur vraie si les deux listes passées au constructeur sont disjointes, c'est-à-dire si les deux listes n'ont aucun élément en commun (ou, ce qui revient au même, si leur intersection est un ensemble vide).

    $disj = $lc->is_LdisjointR;
  • print_subset_chart()

    Imprime joliment un tableau montrant si une liste est un sous-ensemble de l'autre.

    $lc->print_subset_chart;
  • print_equivalence_chart()

    Imprime joliment un tableau montrant si les deux listes sont équivalentes (les mêmes éléments apparaissent au moins une fois dans les deux).

    $lc->print_equivalence_chart;
  • is_member_which()

    Détermine dans *quelle(s)* liste(s) (le cas échéant) passée(s) au constructeur une chaîne donnée peut être trouvée. En contexte de liste, retourne une liste de ces indices dans la liste d'arguments du constructeur correspondant aux listes contenant la chaîne testée.

    @memb_arr = $lc->is_member_which('abel');

    Dans l'exemple ci-dessus, @memb_arr sera :

    ( 0 )

    car 'abel' se trouve uniquement dans @Al qui détient la position 0 dans la liste des arguments passés à new().

    En contexte scalaire, la valeur de retour est le nombre de listes passées au constructeur dans lesquelles une chaîne donnée est trouvée.

    Comme pour les autres méthodes de List::Compare qui retournent une liste, vous pourriez souhaiter que la méthode ci-dessus retourne une référence (scalaire) à un tableau contenant la liste :

    $memb_arr_ref = $lc->is_member_which_ref('baker');

    Dans l'exemple ci-dessus, $memb_arr_ref sera :

    [ 0, 1 ]

    car 'baker' se trouve dans @Llist et @Rlist, qui détiennent les positions 0 et 1, respectivement, dans la liste des arguments passés à new().

    Note : les méthodes is_member_which() et "is_member_which_ref" ne testent qu'une seule chaîne à la fois et ne prennent donc qu'un seul argument. Pour tester plus d'une chaîne à la fois, voir la méthode suivante, are_members_which().

  • are_members_which()

    Détermine dans *quelle(s)* liste(s) (le cas échéant) passée(s) au constructeur une ou plusieurs chaînes données peuvent être trouvées. Les chaînes à tester sont placées dans un tableau (nommé ou anonyme) ; une référence à ce tableau est passée à la méthode.

    $memb_hash_ref =
    $lc->are_members_which([ qw| abel baker fargo hilton zebra | ]);

    *Note :* Dans les versions de List::Compare antérieures à 0.25 (avril 2004), les chaînes à tester pouvaient être passées comme une liste plate. Ce n'est plus possible ; l'argument doit maintenant être une référence à un tableau.

    La valeur de retour est une référence à un hachage de tableaux. La clé pour chaque élément de ce hachage est la chaîne testée. La valeur de chaque élément est une référence à un tableau anonyme dont les éléments sont les indices dans la liste d'arguments du constructeur correspondant aux listes contenant les chaînes testées.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Dans les exemples ci-dessus, $memb_hash_ref sera :

{
     abel     => [ 0    ],
     baker    => [ 0, 1 ],
     fargo    => [ 0, 1 ],
     hilton   => [    1 ],
     zebra    => [      ],
};

Note : are_members_which() peut prendre plus d'un argument ; is_member_which() et is_member_which_ref() ne prennent chacun qu'un seul argument. Contrairement à ces deux méthodes, are_members_which() retourne une référence de hachage.

  • is_member_any()

    Détermine si une chaîne de caractères donnée peut être trouvée dans *n'importe laquelle* des listes passées en argument au constructeur. Retourne 1 si une chaîne spécifiée peut être trouvée dans l'une des listes et 0 sinon.

    $found = $lc->is_member_any('abel');

    Dans l'exemple ci-dessus, $found sera 1 car 'abel' est trouvé dans une ou plusieurs des listes passées en argument à new().

  • are_members_any()

    Détermine si une chaîne de caractères spécifiée ou plusieurs chaînes peuvent être trouvées dans *n'importe laquelle* des listes passées en argument au constructeur. Les chaînes à tester sont placées dans un tableau (nommé ou anonyme) ; une référence à ce tableau est passée à "are_members_any".

    $memb_hash_ref = $lc->are_members_any([ qw| abel baker fargo hilton zebra | ]);

    Note : Dans les versions de List::Compare antérieures à la 0.25 (avril 2004), les chaînes à tester pouvaient être passées sous forme de liste plate. Ce n'est plus possible ; l'argument doit maintenant être une référence à un tableau.

    La valeur de retour est une référence à un hachage où la clé d'un élément est la chaîne testée et la valeur de l'élément est 1 si la chaîne peut être trouvée dans *n'importe laquelle* des listes et 0 sinon. Dans les exemples ci-dessus, $memb_hash_ref sera :

    {
     abel     => 1,
     baker    => 1,
     fargo    => 1,
     hilton   => 1,
     zebra    => 0,
};

    "zebra"'s la valeur est 0 car "zebra" n'est trouvée dans aucune des listes passées en argument à new().

  • get_version()

    Retourne le numéro de version actuel de List::Compare.

    $vers = $lc->get_version;

    • Cas accéléré : Quand l'utilisateur ne veut qu'une seule comparaison

    • Constructeur new()

      Si vous êtes certain que vous ne voudrez que les résultats d'une *seule* comparaison, le calcul peut être accéléré en passant '-a' ou "'--accelerated" comme premier argument au constructeur.

      @Llist = qw(abel abel baker camera delta edward fargo golfer);
@Rlist = qw(baker camera delta delta edward fargo golfer hilton);
$lca = List::Compare->new('-a', \@Llist, \@Rlist);

      ou

      $lca = List::Compare->new('--accelerated', \@Llist, \@Rlist);

      Comme pour le cas régulier de List::Compare, si vous n'avez pas besoin que la méthode renvoie une liste triée dans une comparaison accélérée, vous pouvez obtenir un gain de vitesse en construisant l'objet List::Compare accéléré avec l'option non triée :

      $lca = List::Compare->new('-u', '-a', \@Llist, \@Rlist);

      ou

      $lca = List::Compare->new('--unsorted', '--accelerated', \@Llist, \@Rlist);
    • Constructeur alternatif

      Vous pouvez utiliser le format de constructeur 'hashref unique' pour construire un objet List::Compare appelant le mode Accéléré :

      $lca = List::Compare->new( {
    lists    => [\@Llist, \@Rlist],
    accelerated => 1,
} );

      ou

      $lca = List::Compare->new( {
    lists    => [\@Llist, \@Rlist],
    accelerated => 1,
    unsorted => 1,
} );
    • Méthodes

      Toutes les méthodes de comparaison disponibles dans le cas Régulier sont également disponibles dans le cas Accéléré.

      @intersection     = $lca->get_intersection;
@union            = $lca->get_union;
@Lonly            = $lca->get_unique;
@Ronly            = $lca->get_complement;
@LorRonly         = $lca->get_symmetric_difference;
@bag              = $lca->get_bag;
$intersection_ref = $lca->get_intersection_ref;
$union_ref        = $lca->get_union_ref;
$Lonly_ref        = $lca->get_unique_ref;
$Ronly_ref        = $lca->get_complement_ref;
$LorRonly_ref     = $lca->get_symmetric_difference_ref;
$bag_ref          = $lca->get_bag_ref;
$LR               = $lca->is_LsubsetR;
$RL               = $lca->is_RsubsetL;
$eqv              = $lca->is_LequivalentR;
$disj             = $lca->is_LdisjointR;
                    $lca->print_subset_chart;
                    $lca->print_equivalence_chart;
@memb_arr         = $lca->is_member_which('abel');
$memb_arr_ref     = $lca->is_member_which_ref('baker');
$memb_hash_ref    = $lca->are_members_which(
                        [ qw| abel baker fargo hilton zebra | ]);
$found            = $lca->is_member_any('abel');
$memb_hash_ref    = $lca->are_members_any(
                        [ qw| abel baker fargo hilton zebra | ]);
$vers             = $lca->get_version;

      Tous les alias des méthodes disponibles dans le cas Régulier sont également disponibles dans le cas Accéléré.

    Cas multiple : Comparer trois listes ou plus

    • Constructeur new()

      Crée un objet List::Compare. Placez chaque liste dans un tableau et passez des références aux tableaux au constructeur.

      @Al     = qw(abel abel baker camera delta edward fargo golfer);
@Bob    = qw(baker camera delta delta edward fargo golfer hilton);
@Carmen = qw(fargo golfer hilton icon icon jerky kappa);
@Don    = qw(fargo icon jerky);
@Ed     = qw(fargo icon icon jerky);
$lcm = List::Compare->new(\@Al, \@Bob, \@Carmen, \@Don, \@Ed);

      Comme pour le cas régulier de List::Compare, si vous n'avez pas besoin que la méthode renvoie une liste triée, vous pouvez obtenir un gain de vitesse en construisant l'objet avec l'option non triée :

      $lcm = List::Compare->new('-u', \@Al, \@Bob, \@Carmen, \@Don, \@Ed);

      ou

      $lcm = List::Compare->new('--unsorted', \@Al, \@Bob, \@Carmen, \@Don, \@Ed);
    • Constructeur alternatif

      Vous pouvez utiliser le format de constructeur 'hashref unique' pour construire un objet List::Compare afin de traiter trois listes ou plus à la fois :

      $lcm = List::Compare->new( {
    lists    => [\@Al, \@Bob, \@Carmen, \@Don, \@Ed],
} );

      ou

      $lcm = List::Compare->new( {
    lists    => [\@Al, \@Bob, \@Carmen, \@Don, \@Ed],
    unsorted => 1,
} );
    • Méthodes analogues aux méthodes des cas régulier et accéléré en mode multiple

      Chaque méthode List::Compare disponible dans les cas Régulier et Accéléré a un analogue dans le cas Multiple. Cependant, les résultats produits nécessitent généralement une spécification plus minutieuse.

      Note : Certaines des méthodes suivantes disponibles en mode Multiple de List::Compare prennent des arguments numériques optionnels où ces nombres représentent la position de l'index d'une liste particulière dans la liste des arguments passés au constructeur. Pour spécifier correctement cette position d'index,

    • commencez le comptage à 0 (comme il est d'usage avec les indices de tableau Perl) ; et
    • ne comptez *pas* les options non triées ('-u' ou '--unsorted') précédant les références aux tableaux dans la propre liste d'arguments du constructeur.

    Exemple :

    $lcmex = List::Compare->new('--unsorted', \@alpha, \@beta, \@gamma);

    Pour la fourniture d'un argument numérique à une méthode qui accepte optionnellement un tel argument, '--unsorted' est ignoré, @alpha est 0, @beta est 1, et ainsi de suite.

    • get_intersection()

      Obtient les éléments trouvés dans *chaque* liste passée au constructeur (leur intersection) :

      @intersection = $lcm->get_intersection;
    • get_union()

      Obtient les éléments trouvés dans *n'importe quelle* liste passée au constructeur (leur union) :

      @union = $lcm->get_union;
    • get_unique()

      Pour obtenir les éléments qui apparaissent dans *une seule liste particulière,*, fournissez à get_unique() la position de l'index de cette liste dans la liste des arguments passés au constructeur (sans compter les options '-u' ou '--unsorted').

      Exemple : @Carmen a la position de l'index 2 dans le constructeur @_. Pour obtenir les éléments uniques à @Carmen :

      @Lonly = $lcm->get_unique(2);

      Si aucun indice n'est passé à get_unique(), il utilisera par défaut 0 et rapportera les éléments uniques de la première liste passée au constructeur.

    • get_complement()

      Pour obtenir les éléments qui apparaissent dans n'importe quelle liste *autre qu'une liste particulière,*, fournissez à get_complement() la position de l'index de cette liste dans la liste des arguments passés au constructeur (sans compter les options '-u' ou '--unsorted').

      Exemple : @Don a la position de l'index 3 dans le constructeur @_. Pour obtenir les éléments non trouvés dans @Don :

      @Ronly = $lcm->get_complement(3);

      Si aucun indice n'est passé à get_complement(), il utilisera par défaut 0 et rapportera les éléments trouvés dans n'importe quelle liste autre que la première liste passée au constructeur.

    • get_symmetric_difference()

      Obtient les éléments trouvés dans chaque o

      f qui apparaît dans *une seule* des listes passées au constructeur (leur différence symétrique) ;

      @LorRonly = $lcm->get_symmetric_difference;
    • get_bag()

      Crée un sac de tous les éléments trouvés dans n'importe quelle liste. Le sac diffère de l'union des listes en ce qu'il contient autant de copies d'éléments individuels qu'ils apparaissent dans les listes d'origine.

      @bag = $lcm->get_bag;
    • Retourner une référence au lieu d'une liste

      Une approche alternative des méthodes ci-dessus : Si vous n'avez pas immédiatement besoin d'un tableau comme valeur de retour de l'appel de méthode, mais que vous avez simplement besoin d'une *référence* à un tableau, utilisez l'une des méthodes parallèles suivantes :

      $intersection_ref = $lcm->get_intersection_ref;
$union_ref        = $lcm->get_union_ref;
$Lonly_ref        = $lcm->get_unique_ref(2);
$Ronly_ref        = $lcm->get_complement_ref(3);
$LorRonly_ref     = $lcm->get_symmetric_difference_ref;
$bag_ref          = $lcm->get_bag_ref;
    • is_LsubsetR()

      Pour déterminer si une liste particulière est un sous-ensemble d'une autre liste passée au constructeur, fournissez à is_LsubsetR() la position d'indice du sous-ensemble présumé (en ignorant toute option non triée), suivie de la position d'indice du sur-ensemble présumé.

      Exemple : Pour déterminer si @Ed est un sous-ensemble de @Carmen, appelez :

      $LR = $lcm->is_LsubsetR(4,2);

      Une valeur vraie (1) est retournée si la liste de gauche est un sous-ensemble de la liste de droite ; une valeur fausse (0) est retournée sinon.

      Si aucun argument n'est passé, is_LsubsetR() prend par défaut "(0,1)" et compare les deux premières listes passées au constructeur.

    • is_LequivalentR()

      Pour déterminer si deux listes particulières sont équivalentes l'une à l'autre, fournissez à "is_LequivalentR" leurs positions d'indice dans la liste des arguments passés au constructeur (en ignorant toute option non triée).

      Exemple : Pour déterminer si @Don et @Ed sont équivalentes, appelez :

      $eqv = $lcm->is_LequivalentR(3,4);

      Une valeur vraie (1) est retournée si les listes sont équivalentes ; une valeur fausse (0) sinon.

      Si aucun argument n'est passé, "is_LequivalentR" prend par défaut et compare les deux premières listes passées au constructeur.

    • is_LdisjointR()

      Pour déterminer si deux listes particulières sont disjointes l'une de l'autre (c'est-à-dire n'ont aucun membre en commun), fournissez à "is_LdisjointR" leurs positions d'indice dans la liste des arguments passés au constructeur (en ignorant toute option non triée).

      Exemple : Pour déterminer si @Don et @Ed sont disjointes, appelez :

      $disj = $lcm->is_LdisjointR(3,4);

      Une valeur vraie (1) est retournée si les listes sont équivalentes ; une valeur fausse (0) sinon.

      Si aucun argument n'est passé, "is_LdisjointR" prend par défaut et compare les deux premières listes passées au constructeur.

    • print_subset_chart()

      Imprime joliment un tableau montrant les relations de sous-ensembles entre les différentes listes sources :

      $lcm->print_subset_chart;
    • print_equivalence_chart()

      Imprime joliment un tableau montrant les relations d'équivalence entre les différentes listes sources :

      $lcm->print_equivalence_chart;
    • is_member_which()

      Détermine dans *quelle* (le cas échéant) des listes passées au constructeur une chaîne donnée peut être trouvée. En contexte de liste, retourne une liste de ces indices dans la liste d'arguments du constructeur (en ignorant toute option non triée) correspondant aux listes contenant la chaîne testée.

      @memb_arr = $lcm->is_member_which('abel');

      Dans l'exemple ci-dessus, @memb_arr sera :

      ( 0 )

      car 'abel' n'est trouvé que dans @Al, qui détient la position 0 dans la liste des arguments passés à new().

    • is_member_which_ref()

      Comme pour les autres méthodes List::Compare qui retournent une liste, vous pourriez souhaiter que la méthode ci-dessus retourne une référence (scalaire) à un tableau contenant la liste :

      $memb_arr_ref = $lcm->is_member_which_ref('jerky');

      Dans l'exemple ci-dessus, $memb_arr_ref sera :

      [ 3, 4 ]

      car 'jerky' est trouvé dans @Don et @Ed, qui détiennent respectivement les positions 3 et 4 dans la liste des arguments passés à new().

      Note : les méthodes is_member_which() et "is_member_which_ref" ne testent qu'une seule chaîne à la fois et prennent donc un seul argument. Pour tester plus d'une chaîne à la fois, voir la méthode suivante, are_members_which().

    • are_members_which()

      Détermine dans *quelles* (le cas échéant) des listes passées au constructeur une ou plusieurs chaînes données peuvent être trouvées. Les chaînes à tester sont placées dans un tableau anonyme, une référence à celui-ci étant passée à la méthode.

      $memb_hash_ref =
    $lcm->are_members_which([ qw| abel baker fargo hilton zebra | ]);

      Note : Dans les versions de List::Compare antérieures à 0.25 (avril 2004), les chaînes à tester pouvaient être passées sous forme de liste plate. Ce n'est plus possible ; l'argument doit maintenant être une référence à un tableau anonyme.

      La valeur de retour est une référence à un hachage. La clé de chaque élément de ce hachage est la chaîne testée. La valeur de chaque élément est une référence à un tableau anonyme dont les éléments sont les indices dans la liste d'arguments du constructeur correspondant aux listes contenant les chaînes testées.

      Dans les deux exemples ci-dessus, $memb_hash_ref sera :

      {
     abel     => [ 0             ],
     baker    => [ 0, 1          ],
     fargo    => [ 0, 1, 2, 3, 4 ],
     hilton   => [    1, 2       ],
     zebra    => [               ],
};

      Note : are_members_which() peut prendre plus d'un argument ; is_member_which() et is_member_which_ref() prennent chacun un seul argument. are_members_which() retourne une référence de hachage ; les autres méthodes retournent soit une liste, soit une référence à un tableau contenant cette liste, selon le contexte.

    • is_member_any()

      Détermine si une chaîne donnée peut être trouvée dans *une quelconque* des listes passées comme arguments au constructeur.

      $found = $lcm->is_member_any('abel');

      Retourne 1 si une chaîne spécifiée peut être trouvée dans *une quelconque* des listes et 0 sinon.

      Dans l'exemple ci-dessus, $found sera 1 car 'abel' est trouvé dans une ou plusieurs des listes passées comme arguments à new().

    • are_members_any()

      Détermine si une ou plusieurs chaînes spécifiées peuvent être trouvées dans *une quelconque* des listes passées comme arguments au constructeur. Les chaînes à tester sont placées dans un tableau (anonyme ou nommé), une référence à celui-ci étant passée à la méthode.

      $memb_hash_ref = $lcm->are_members_any([ qw| abel baker fargo hilton zebra | ]);

      Note : Dans les versions de List::Compare antérieures à 0.25 (avril 2004), les chaînes à tester pouvaient être passées sous forme de liste plate. Ce n'est plus possible ; l'argument doit maintenant être une référence à un tableau anonyme.

      La valeur de retour est une référence à un hachage où la clé d'un élément est la chaîne testée et la valeur de l'élément est 1 si la chaîne peut être trouvée dans *quelconque* des listes et 0 sinon. Dans les deux exemples ci-dessus, $memb_hash_ref sera :

      {
     abel     => 1,
     baker    => 1,
     fargo    => 1,
     hilton   => 1,
     zebra    => 0,
};

      La valeur de "zebra" sera 0 car "zebra" n'est trouvée dans aucune des listes passées comme arguments à new().

        Si vous êtes sûr que vous n'aurez besoin que des résultats d'une seule comparaison entre trois listes ou plus, vous pouvez accélérer le calcul en passant '-a' ou "'--accelerated" comme premier argument au constructeur.

        $lcma = List::Compare->new('-u', '-a',

      DISCUSSION : Principes

      Commentaires Généraux

      List::Compare est une implémentation orientée objet d'un code courant en Perl (voir "Histoire, Références et Développement" ci-dessous) utilisé pour déterminer des relations intéressantes entre deux listes ou plus à la fois. Un objet List::Compare est créé et calcule automatiquement les valeurs nécessaires pour fournir les résultats appropriés aux méthodes de List::Compare. Dans l'implémentation actuelle, les méthodes de List::Compare retournent de nouvelles listes contenant les éléments trouvés dans toute liste désignée uniquement (unique), toute liste autre qu'une liste désignée (complément), l'intersection et l'union de toutes les listes, etc. List::Compare dispose également de (a) méthodes pour retourner des valeurs booléennes indiquant si une liste est un sous-ensemble d'une autre et si deux listes sont équivalentes l'une à l'autre et (b) méthodes pour imprimer des graphiques simples montrant les relations de sous-ensemble et d'équivalence entre les listes sous forme de tableaux.

      À l'exception de la méthode get_bag() de List::Compare, **les instances multiples d'un élément dans une liste ne sont comptées qu'une seule fois par rapport à l'intersection, l'union, etc. des deux listes.** En particulier, List::Compare considère deux listes comme équivalentes si chaque élément de la première liste peut être trouvé dans la seconde liste et *inversement*. 'Équivalence' dans cet usage ne tient pas compte de la fréquence à laquelle les éléments apparaissent dans une liste ou de leur ordre dans l'autre.

      List::Compare Modes

      Dans son implémentation actuelle, List::Compare possède quatre modes de fonctionnement.

      • Mode Normal

        Le mode Normal de List::Compare est basé sur List::Compare v0.11 – la première version de List::Compare publiée sur CPAN (juin 2002). Il ne compare que deux listes à la fois. En interne, son initialisateur effectue tous les calculs nécessaires pour rapporter toute comparaison souhaitée et son constructeur stocke les résultats de ces calculs. Ses méthodes publiques ne font que rapporter ces résultats.

        Cette approche présente l'avantage que si vous avez besoin d'examiner plus d'une forme de comparaison entre deux listes (p. ex., l'union, l'intersection et la différence symétrique de deux listes), les comparaisons sont pré-calculées. Cette approche est efficace car certains types de comparaison supposent que d'autres types ont déjà été calculés. Par exemple, pour calculer la différence symétrique de deux listes, il faut d'abord déterminer les éléments uniques de chacune des deux listes.

      • Mode Accéléré

        L'implémentation actuelle de List::Compare offre la possibilité d'obtenir des résultats encore plus rapides à condition que vous n'ayez besoin que du résultat d'une seule forme de comparaison entre deux listes. (p. ex., juste l'union – rien d'autre). En mode Accéléré, l'initialisateur de List::Compare n'effectue aucun calcul et son constructeur ne stocke que des références aux deux listes d'origine. Tous les calculs nécessaires pour rapporter les résultats sont reportés aux appels de méthodes.

        L'utilisateur sélectionne cette approche en passant le paramètre d'option '-a' au constructeur avant de passer les références aux deux listes d'origine. List::Compare note le paramètre d'option et passe silencieusement en mode Accéléré. Du point de vue de l'utilisateur, il n'y a aucune différence dans le code ou dans les résultats.

        Les benchmarks suggèrent que le mode Accéléré de List::Compare (a) est plus rapide que son mode Normal lorsqu'une seule comparaison est demandée ; (b) est à peu près aussi rapide que le mode Normal lorsqu'on demande deux comparaisons ; et (c) devient considérablement plus lent que le mode Normal lorsqu'on demande de plus en plus de comparaisons au-delà de deux.

      • Mode Multiple

        List::Compare offre désormais la possibilité de comparer trois listes ou plus à la fois. Il suffit de stocker les listes supplémentaires dans des tableaux et de passer des références à ces tableaux au constructeur. List::Compare détecte que plus de deux listes ont été passées au constructeur et passe silencieusement en mode Multiple.

        Comme décrit dans le résumé ci-dessus, la comparaison de plus de deux listes à la fois offre un ensemble de méthodes de comparaison large et complexe. Un élément peut apparaître dans une seule liste d'origine, dans toutes les listes d'origine, ou dans un nombre de listes compris entre un et toutes. La signification de « union », « intersection » et « différence symétrique » ne change pas conceptuellement lorsqu'elles sont appliquées à plusieurs listes, car ce sont des propriétés de toutes les listes considérées. En revanche, la signification de « unique », « complément », « sous-ensemble » et « équivalent » change car ce sont des propriétés d'une liste comparée à une autre ou à toutes les autres listes combinées.

        List::Compare prend en compte cette complexité en vous permettant de passer des arguments aux méthodes publiques pour demander des résultats par rapport à une liste spécifique (pour get_unique() et get_complement()) ou à une paire spécifique de listes (pour is_LsubsetR() et is_LequivalentR()).

        List::Compare prend également en compte cette complexité en proposant les nouvelles méthodes get_shared() et get_nonintersection() décrites dans le résumé ci-dessus.

      • Mode Multiple Accéléré

        Depuis la version 0.25 introduite en avril 2004, List::Compare offre la possibilité d'effectuer des calculs accélérés d'une comparaison entre trois listes ou plus à la fois. Il suffit de stocker les listes supplémentaires dans des tableaux et de passer des références à ces tableaux au constructeur, précédées du paramètre d'option '-a' comme cela a été fait pour le mode accéléré simple (deux listes seulement). List::Compare détecte que plus de deux listes ont été passées au constructeur et passe silencieusement en mode Multiple Accéléré.

      • Option Non Triée

        Lorsque List::Compare est utilisé pour renvoyer des listes représentant des comparaisons de plusieurs listes (p. ex., l'union ou l'intersection de plusieurs listes), les listes renvoyées sont, par défaut, triées à l'aide du mode « sort » de Perl : tri ascendant. Le tri produit des résultats plus facilement lisibles par l'utilisateur mais peut entraîner un coût de performance.

        Si vous n'avez pas besoin de résultats triés, vous pouvez éviter le coût de performance en évitant l'appel au constructeur de List::Compare avec l'option non triée. Cela se fait en appelant '-u' ou '--unsorted' comme premier argument passé au constructeur, c'est-à-dire comme un argument nommé avant de passer toute référence à des listes au constructeur.

        Note: Si vous appelez List::Compare en mode Accéléré ou en mode Multiple Accéléré et que vous souhaitez que les listes renvoyées soient non triées, passez d'abord l'argument pour l'option non triée ('-u' ou '--unsorted') puis l'argument pour le mode Accéléré ('-a' ou '--accelerated').

      Méthodes Diverses

      Il ne serait pas approprié d'appeler get_shared() et get_nonintersection() en mode Normal ou en mode Accéléré, car ils sont conceptuellement basés sur la comparaison de plus de deux listes. Cependant, il y a toujours la possibilité qu'un utilisateur ne compare que deux listes (accéléré ou non) et appelle par erreur l'une de ces deux méthodes. Pour éviter des erreurs d'exécution fatales et pour vous avertir d'utiliser une méthode plus appropriée, ces deux méthodes sont définies pour les modes Normal et Accéléré afin de renvoyer des résultats appropriés mais aussi de générer un message de "carp" vous avertissant de réécrire le code.

      De même, la méthode is_RsubsetL() est appropriée pour les modes Normal et Accéléré mais n'est pas appropriée pour le mode Multiple. Par mesure de sécurité, elle a été définie pour le mode Multiple afin de renvoyer des résultats appropriés mais aussi de générer un message de "carp" vous avertissant de réécrire le code.

      Dans List::Compare v0.11 et les versions antérieures, l'auteur fournissait des alias pour plusieurs méthodes basés sur la supposition que les listes d'origine seraient désignées par 'A' et 'B'. Maintenant que vous pouvez comparer plus de deux listes, l'auteur estime qu'il serait plus approprié de désigner les éléments de listes à deux arguments comme les éléments de gauche et de droite. C'est pourquoi nous déconseillons l'utilisation de méthodes telles que get_Aonly(), get_Bonly() et get_AorBonly() comme alias de get_unique(), get_complement() et get_symmetric_difference(). Cependant, pour garantir la compatibilité descendante avec le vaste public de programmeurs Perl qui utilisent des versions antérieures de List::Compare (les 10e1 d'entre vous), ces méthodes et d'autres méthodes liées aux relations de sous-ensembles sont toujours définies.

      List::Compare::SeenHash Abandonné à partir de la version 0.26

      Avant la v0.26, introduite le 11 avril 2004, si vous vouliez passer des références "seen-hash" à des listes au constructeur de List::Compare au lieu de références à des tableaux, vous deviez appeler un module différent : List::Compare::SeenHash. Le code pour cela ressemblait à ceci :

      use List::Compare::SeenHash;
my %Llist = (
   abel     => 2,
   baker    => 1,
   camera   => 1,
   delta    => 1,
   edward   => 1,
   fargo    => 1,
   golfer   => 1,
);
my %Rlist = (
   baker    => 1,
   camera   => 1,
   delta    => 2,
   edward   => 1,
   fargo    => 1,
   golfer   => 1,
   hilton   => 1,
);
my $lcsh = List::Compare::SeenHash->new(\%Llist, \%Rlist);

      List::Compare::SeenHash est abandonné depuis la version 0.26. Toutes ses fonctionnalités (et plus encore) ont été implémentées dans List::Compare lui-même, car un utilisateur peut désormais passer, soit un ensemble de références à des tableaux soit un ensemble de références "seen-hash" au constructeur de List::Compare.

      Pour simplifier la maintenance future de List::Compare, List::Compare::SeenHash.pm ne sera plus distribué avec List::Compare, ni les fichiers de la suite de tests qui testaient List::Compare::SeenHash lors de l'installation ne seront distribués.

      Si vous avez toujours besoin de List::Compare::SeenHash, utilisez la version 0.25 de CPAN, ou modifiez simplement vos programmes Perl qui utilisaient List::Compare::SeenHash. Ces scripts peuvent être rapidement modifiés avec, par exemple, cette commande d'édition dans un éditeur de texte Unix vi :

      :1,$s/List::Compare::SeenHash/List::Compare/gc

      Une Interface Non Orientée Objet : List::Compare::Functional

      La version 0.21 de List::Compare a introduit List::Compare::Functional, une interface fonctionnelle (c'est-à-dire, non orientée objet) pour les fonctions de comparaison de listes. List::Compare::Functional supporte les mêmes fonctionnalités que List::Compare. Elle fonctionne de manière similaire aux modes Accéléré et Multiple Accéléré de List::Compare (décrits ci-dessus), mais ne nécessite pas l'utilisation du paramètre d'option '-a' dans l'appel de fonction. List::Compare::Functional renverra des comparaisons non triées de deux listes en passant '-u' ou '--unsorted' comme premier argument à la fonction. Consultez la documentation de List::Compare::Functional pour savoir comment importer ses fonctions dans votre package principal.

    HISTORIQUE, RÉFÉRENCES ET DÉVELOPPEMENT

    Le Code Lui-Même

    List::Compare est basé sur du code présenté par Tom Christiansen et Nathan Torkington dans Perl Cookbook http://www.oreilly.com/catalog/cookbook/ (alias le livre 'Ram'), O'Reilly & Associates, 1998, recettes 4.7 et 4.8. Un code similaire est présenté dans le livre Camel : Programming Perl, par Larry Wall, Tom Christiansen, Jon Orwant. http://www.oreilly.com/catalog/pperl3/, 3e éd., O'Reilly & Associates, 2000. Le code de comparaison de listes est si basique et Perlesque que je suppose qu'il a pu être écrit par Larry lui-même à l'aube de Perl. La méthode get_bag() a été inspirée par le module Set::Bag de Jarkko Hietaniemi et le module Set::Array de Daniel Berger, tous deux disponibles sur CPAN.

    L'objectif initial de List::Compare était simplement de mettre ce code dans un cadre modulaire et orienté objet. Ce cadre, sans surprise, est tiré en grande partie de Object Oriented Perl de Damian Conway http://www.manning.com/Conway/index.html, Manning Publications, 2000.

    Avec l'ajout des modes Accéléré, Multiple et Multiple Accéléré, List::Compare s'étend considérablement en taille et en capacités. Néanmoins, le code du Cookbook de Tom et Nat reste au cœur : l'utilisation de tables de hachage comme tables de consultation pour enregistrer les éléments vus dans les listes. Veuillez noter : List::Compare ne se préoccupe pas du concept « d'égalité » entre listes qui dépend de la fréquence ou de l'ordre d'apparition des éléments dans les listes à comparer. Si cela ne répond pas à vos besoins, vous devriez chercher ailleurs ou écrire votre propre module.

    Dans une présentation du Perl Seminar New York en novembre 2003, Ben Holtzman a discuté des coûts de performance entraînés par la fonction "sort" de Perl. Cela m'a conduit à me demander : « Pourquoi un utilisateur de List::Compare devrait-il payer ce coût de performance s'il n'a pas besoin d'une liste lisible par l'homme en résultat (comme ce serait le cas si la liste retournée était utilisée comme entrée dans une autre fonction) ? » Cela a conduit au développement de l'option non triée de List::Compare.

    Une offre en avril 2004 de Kevin Carlson pour écrire un article pour The Perl Journal (http://tpj.com) m'a amené à reconsidérer si un module séparé (l'ancien List::Compare::SeenHash) était vraiment nécessaire lorsqu'un utilisateur voulait fournir au constructeur des références à des tables de hachage vues plutôt que des références à des tableaux. Comme j'avais déjà adapté List::Compare::Functional pour accepter les deux types d'arguments, j'ai adapté List::Compare de la même manière. Cela signifiait que List::Compare::SeenHash et ses tests d'installation associés pouvaient être dépréciés et supprimés de la distribution CPAN.

    Une remarque de David H. Adler lors d'une réunion des New York Perlmongers en avril 2004 m'a conduit à développer le format de constructeur alternatif « single hashref », introduit dans la version 0.29 le mois suivant.

    Des présentations lors de deux éditions différentes du Yet Another Perl Conference (YAPC) ont inspiré le développement des versions 0.30 et 0.31 de List::Compare. J'ai été choisi pour donner une conférence sur List::Compare à YAPC::NA::2004 à Buffalo. Cela m'a poussé à améliorer certains aspects de la documentation. La version 0.31 doit son inspiration à une conférence à YAPC de Buffalo et à une conférence antérieure à YAPC::EU::2003 à Paris. À Paris, j'ai entendu Paul Johnson parler de son module CPAN Devel::Cover et de l'analyse de couverture en général. Ce matériel était au-dessus de mes possibilités à l'époque, mais à Buffalo, j'ai entendu Andy Lester discuter de Devel::Cover dans le cadre de sa discussion sur les tests et du projet Phalanx (http://qa.perl.org/phalanx). Cette fois, j'ai compris, et à mon retour de Buffalo, j'ai appliqué Devel::Cover à List::Compare et écrit des tests supplémentaires pour améliorer sa couverture de sous-programmes et d'instructions. De plus, j'ai ajouté deux nouvelles méthodes, "get_unique_all" et "get_complement_all". En écrivant ces deux méthodes, j'ai suivi un modèle de développement piloté par les tests beaucoup plus que dans les versions antérieures de List::Compare et mes autres modules CPAN. Le résultat ? La suite de tests de List::Compare a augmenté de plus de 3300 tests pour atteindre près de 23 000 tests.

    Lors du Second New York Perl Hackathon (2 mai 2015), un projet a été créé pour demander des améliorations de performance dans certaines fonctions de List::Compare (https://github.com/nyperlmongers/nyperlhackathon2015/wiki/List-Compare-Performance-Improvements). Michael Rawson, participant au Hackathon, a soumis une demande de tirage avec des modifications à List::Compare::Base::_Auxiliary. Après l'évaluation des performances de ces révisions, un correctif incarnant la demande de tirage a été accepté, conduisant à la version 0.53 de CPAN.

    Si Vous Aimez List::Compare, Vous Allez Adorer ...

    En préparant ce module pour la distribution via CPAN, j'ai eu l'occasion d'étudier un certain nombre d'autres modules déjà disponibles sur CPAN. Chacun de ces modules est plus sophistiqué que List::Compare -- ce qui n'est pas surprenant puisque tout ce que List::Compare a initialement aspiré à faire était d'éviter de taper du code Cookbook à plusieurs reprises. Voici une brève description des fonctionnalités de ces modules. (Attention : La discussion suivante n'est valide qu'à partir de juin 2002. Certains de ces modules peuvent avoir changé depuis.)

    • Algorithm::Diff - Calculer des différences « intelligentes » entre deux fichiers/listes (http://search.cpan.org/dist/Algorithm-Diff/)

      Algorithm::Diff est un module sophistiqué initialement écrit par Mark-Jason Dominus, ensuite maintenu par Ned Konz, maintenant par Tye McQueen. Pensez à l'utilitaire Unix "diff" et vous serez sur la bonne voie. Algorithm::Diff exporte des méthodes telles que "diff", qui « calcule le plus petit ensemble d'ajouts et de suppressions nécessaires pour transformer la première séquence en la seconde, et retourne une description de ces changements ». Algorithm::Diff s'intéresse principalement à la séquence d'éléments dans deux listes. Il n'exporte pas de fonctions pour l'intersection, l'union, le statut de sous-ensemble, etc.

    • Array::Compare - Extension Perl pour comparer des tableaux (http://search.cpan.org/dist/Array-Compare/)

      Array::Compare, par Dave Cross, demande si deux tableaux sont identiques ou différents en faisant un "join" de chaque chaîne avec un caractère séparateur et en comparant les chaînes résultantes. Comme List::Compare, c'est un module orienté objet. Une caractéristique sophistiquée d'Array::Compare est qu'il vous permet de spécifier comment les « espaces blancs » dans un tableau (un élément qui est indéfini, la chaîne vide, ou des espaces blancs dans un élément) doivent être évalués pour déterminer l'égalité ou la différence. Il ne fournit pas directement de méthodes pour l'intersection et l'union.

    • Data::Compare - comparer des structures de données Perl (http://search.cpan.org/dist/Data-Compare/)

      Cette bibliothèque compare récursivement des structures de données Perl. Recommandé par Slaven Rezić !

    • List::Util - Une sélection de sous-programmes de listes d'utilité générale (http://search.cpan.org/dist/Scalar-List-Utils/)

      List::Util, par Graham Barr, exporte une variété de fonctions simples et utiles pour opérer sur une liste à la fois. La fonction "min" retourne la plus petite valeur numérique dans une liste ; la fonction "max" retourne la plus haute valeur ; et ainsi de suite. List::Compare diffère de List::Util en ce qu'il est orienté objet et qu'il fonctionne sur deux chaînes à la fois plutôt qu'une seule -- mais il vise à être aussi simple et utile que List::Util. List::Util sera inclus dans la distribution Perl standard à partir de Perl 5.8.0.
