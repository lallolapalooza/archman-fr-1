NOM

Log::Log4perl::Appender::Buffer - Appender de mise en mémoire tampon

SYNOP

use Log::Log4perl qw(:easy);
my $conf = qq(
log4perl.category                  = DEBUG, Buffer
    # Appender d'écran régulier
log4perl.appender.Screen           = Log::Log4perl::Appender::Screen
log4perl.appender.Screen.stdout    = 1
log4perl.appender.Screen.layout    = PatternLayout
log4perl.appender.Screen.layout.ConversionPattern = %d %p %c %m %n
    # Appender de mise en mémoire tampon, utilisant l'appender ci-dessus comme sortie
log4perl.appender.Buffer               = Log::Log4perl::Appender::Buffer
log4perl.appender.Buffer.appender      = Screen
log4perl.appender.Buffer.trigger_level = ERROR
);
Log::Log4perl->init(\$conf);
DEBUG("Ce message sera mis en mémoire tampon.");
INFO("Ce message sera également mis en mémoire tampon.");
# Le temps passe. Rien ne se passe. Mais ensuite ...
print "C'est le moment d'agir !!!\n";
ERROR("Ce message déclenche la vidange de la mémoire tampon.");

DESCRIPTION

"Log::Log4perl::Appender::Buffer" accepte ces arguments :

"appender"
Spécifie le nom de l'appender pour lequel il met en mémoire tampon les messages. L'appender spécifié doit être défini quelque part dans le fichier de configuration, pas nécessairement avant la définition de "Log::Log4perl::Appender::Buffer".
"max_messages"
Spécifie le nombre maximum de messages que l'appender conservera dans son tampon circulaire. "max_messages" est optionnel. Par défaut, "Log::Log4perl::Appender::Buffer" ne limitera pas le nombre de messages mis en mémoire tampon. Cela pourrait être indésirable dans les processus de longue durée accumulant beaucoup de messages avant qu'une vidange ne se produise. Si "max_messages" est défini sur une valeur numérique, "Log::Log4perl::Appender::Buffer" déplacera les anciens messages de son tampon pour faire de la place si le tampon est plein.
"trigger_level"
Si trigger_level est défini sur l'un des niveaux de Log4perl (voir Log::Log4perl::Level), une fonction "trigger" sera définie en interne pour vider le tampon si un message de priorité $level ou supérieure arrive. C'est juste une fonction pratique. Définir 
log4perl.appender.Buffer.trigger_level = ERROR

équivaut à créer une fonction de déclenchement comme

log4perl.appender.Buffer.trigger = sub {   \
    my($self, $params) = @_;               \
    return $params->{log4p_level} >=       \
           $Log::Log4perl::Level::ERROR; }

Voir la section suivante pour la définition de fonctions de déclenchement génériques.

"trigger"
"trigger" contient une référence à une sous-routine, que "Log::Log4perl::Appender::Buffer" appellera sur chaque message entrant avec les mêmes paramètres que la méthode log() de l'appender : 
my($self, $params) = @_;

$params référence un hachage contenant la priorité du message (clé "l4p_level"), la catégorie du message (clé "l4p_category") et le contenu du message (clé "message").

Si la sous-routine renvoie 1, elle déclenchera une vidange des messages mis en mémoire tampon.

NOTES DE DÉVELOPPEMENT

"Log::Log4perl::Appender::Buffer" est un appender composite. Contrairement aux autres appenders, il ne journalise aucun message, il les transmet simplement à son sous-appendeur attaché. Pour cette raison, il n'a pas besoin de mise en forme (contrairement aux appenders réguliers). S'il n'en définit aucune, les messages sont transmis tels quels.

Les filtres personnalisés sont également appliqués uniquement à l'appender composite. Ils ne sont pas appliqués au sous-appendeur. Il en va de même pour les seuils d'appender. Ce comportement pourrait changer à l'avenir.
