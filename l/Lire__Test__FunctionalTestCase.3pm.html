NOM

Lire::Test::FunctionalTestCase - Classe de base pour écrire des tests fonctionnels

SYNOPIS

use base qw/ Lire::Test::FunctionalTestCase/;

DESCRIPTION

Ceci est une sous-classe de Test::Unit::TestCase qui peut être utilisée pour faciliter l'écriture de tests fonctionnels.

QUELLES SONT LES TESTS FONCTIONNELS

Contrairement aux tests unitaires qui testent la sémantique de l'API et documentent les hypothèses internes, les tests fonctionnels sont des tests qui vérifient la 'fonctionnalité' globale du logiciel. Ils documentent en quelque sorte la fonctionnalité attendue du logiciel.

Lire::Test::FunctionalTestCase

Dans Lire, la "fonctionnalité attendue" est exercée en exécutant des commandes. Ce module fournit donc des méthodes pratiques pour exécuter des commandes Lire et tester leur sortie attendue.

Il configure également un faux sendmail qui peut être utilisé pour analyser les e-mails que le système Lire devrait envoyer.

Certaines fonctionnalités de Lire ne peuvent plus être testées simplement en exécutant des commandes (par exemple, l'interface utilisateur basée sur Curses::UI ne peut pas être testée de cette manière, mais plutôt grâce à Lire::Test::CursesUIDriver). Pour ces types de tests, cette classe de base configurera une nouvelle instance de Lire::Config et Lire::PluginManager dans la méthode set_up. Les tests qui nécessitent ces fonctionnalités peuvent simplement appeler Lire::Config->init() et Lire::PluginManager->instance()->register_default_converters() sans crainte de perturber l'environnement de test.

homedir()

Retourne le répertoire qui sera assigné à ENV{'HOME'} lorsque les commandes seront exécutées. Ce répertoire est nettoyé après chaque test.

rundir()

Retourne le répertoire qui sera le répertoire de travail lorsque les commandes seront exécutées. Ce répertoire est nettoyé après chaque test.

config_spec()

Retourne l'objet Lire::Config::TypeSpec qui sera utilisé à l'exécution par les tests fonctionnels. Il peut être utilisé pour configurer des fichiers de configuration pour le test.

locale( [nouveau_locale] )

Modifie la locale sous laquelle le test fonctionnel sera exécuté. Par défaut, tous les tests sont exécutés sous la locale 'C', ignorant toutes les variables d'environnement de l'utilisateur.

Retourne la locale précédente définie.

lire_run( $commande_shell )

Cette méthode exécute la commande $commande_shell via le shell et retourne un objet Lire::Test::CommandResult qui peut être utilisé pour effectuer des tests sur cette commande. L'environnement Lire sera configuré avant d'invoquer le shell.

sent_mail()

Retourne dans une référence de tableau les messages qui ont été envoyés pendant le test. Les éléments de ce tableau sont des références de hachage contenant deux clés :

destinataires
Une référence de tableau contenant les destinataires tels qu'ils ont été passés sur la ligne de commande à sendmail.
message
L'e-mail qui a été envoyé. C'est le texte complet de l'e-mail. C'est ce qui a été passé à sendmail via STDIN.

create_test_file( $nom_fichier, [$contenu] )

Crée un fichier $nom_fichier avec le contenu $contenu. Ce fichier sera supprimé après l'exécution du test lors de la méthode tear_down(). Un fichier vide sera créé si le paramètre $contenu est omis.

install_xml_spec( $type_spec, $superservice, $fichier )

Installe la spécification XML dans $fichier du schéma de base $superservice. Le paramètre $type_spec spécifie où le fichier sera installé :

site_filter
Le fichier sera installé en tant que spécification de filtre dans le répertoire système.
site_report
Le fichier sera installé en tant que spécification de rapport dans le répertoire système.
site_schema
Le fichier sera installé en tant que spécification de schéma dans le répertoire système.
filter
Le fichier sera installé en tant que spécification de filtre dans le répertoire HOME.
report
Le fichier sera installé en tant que spécification de rapport dans le répertoire HOME.
schema
Le fichier sera installé en tant que spécification de schéma dans le répertoire HOME.

Ces fichiers seront supprimés après le test.

create_test_cfg_file( $nom )

Retourne un objet Lire::Config::ConfigFile initialisé avec la spécification de configuration appropriée. Ce fichier de configuration sera créé sous $HOME/.lire/config/$nom.xml lorsque lire_run() sera utilisé. Il peut être utilisé pour définir des options de configuration qui seront utilisées lors de l'exécution de la commande :

my $cfg = $self->create_test_cfg_file( "test" );
$cfg->global->get( "lr_from" )->set( "flacoste\@logreport.org" );

Si un fichier de configuration $nom a déjà été créé, il retourne l'objet ConfigFile associé.

Notez que si vous souhaitez que ces variables de configuration aient un effet lors de l'exécution des tests en processus (pas via lire_run()), vous devez appeler save() sur l'objet avant d'appeler Lire::Config->init(). Sinon, il est préférable de définir l'option de configuration directement en utilisant l'API Lire::Config.
