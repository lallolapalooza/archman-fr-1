NOM

Lire::ReportParser - Lire::XMLParser qui analyse des rapports XML

SYNTAXE

package MonAnalyseur;
use base qw/ Lire::ReportParser /;
sub parse_end {
    return "Terminé";
}
package main::
my $analyseur = new MonAnalyseur;
my $resultat = eval { $analyseur->parsefile( "rapport.xml" ) };
croak "Erreur lors de l'analyse de rapport.xml : $@" if $@
print $resultat, "\n";

DESCRIPTION

Ceci est un Lire::XMLParser(3pm) qui gère les documents XML qui suivent le format Lire Report Markup Language. Son but principal est d'écrire des gestionnaires personnalisés pour les rapports XML de Lire.

UTILISATION

Créez une instance d'une sous-classe de Lire::ReportParser et utilisez l'une des méthodes parse() ou parsefile() pour traiter des rapports XML. Vous n'utiliserez probablement jamais le module Lire::ReportParser directement ; vous utiliserez probablement une sous-classe qui fait réellement quelque chose lors du traitement du document.

new( %args )

my $analyseur = new Lire::ReportParser::ReportBuilder();

La méthode new() accepte des paramètres sous forme de paires clé-valeur. Les paramètres disponibles sont spécifiques à chaque analyseur. Il n'y a pas de paramètres généraux.

ÉCRIRE UN ANALYSEUR DE RAPPORTS XML

En utilisant Lire::ReportParser, vous pouvez écrire un analyseur de rapports XML.

Le modèle de programmation est similaire à l'interface événementielle d'expat ou au modèle connu sous le nom de SAX. La principale différence avec ces modèles est que ce module offre des ponts spécifiques pour les rapports Lire. Par exemple, au lieu d'avoir un événement générique de début d'élément, vous avez des méthodes spécifiques pour chaque type d'élément, ce qui facilite la liaison des éléments qui vous intéressent uniquement. Il offre également des fonctions qui facilitent la détermination du contexte (un problème constant dans la programmation événementielle).

Si vous n'êtes pas habitué à ce type de programmation, une API orientée objet pour les rapports XML est également disponible. Cette API est plus proche d'un modèle DOM. Son principal inconvénient est qu'elle est plus lente car elle doit analyser l'intégralité de la documentation XML en mémoire pour construire une représentation objet. Mais si vous avez besoin de parcourir la documentation, elle est bien meilleure que l'API événementielle.

La manière principale d'utiliser cette API pour écrire un analyseur de rapports XML personnalisé est de sous-classer Lire::ReportParser et de remplacer les fonctions liées aux éléments qui vous intéressent.

Il existe trois catégories de méthodes que vous pouvez remplacer.

Méthodes de personnalisation
Ce sont des méthodes qui personnalisent le fonctionnement de Lire::ReportParser. La plus importante est le « constructeur » new().
Méthodes d'éléments génériques
Ce sont des méthodes qui sont appelées avant les méthodes plus spécifiques ou de plus haut niveau et peuvent être utilisées pour la liaison avant que les autres événements ne soient synthétisés.

MÉTHODES D'ÉVÉNEMENTS DE HAUT NIVEAU

Pour chaque élément défini, une méthode nom_element_start() et une méthode nom_element_end() sont appelées. Pour les éléments contenant du texte, une méthode nom_element_char() est appelée, bien que vous préfériez probablement utiliser les méthodes plus simples handle_nom_element() dans ces cas.

Lorsque vous remplacez l'une de ces méthodes (à l'exception de la méthode handle_nom_element()), vous **devez** également appeler la méthode parente :

sub subreport_start {
    my ( $self, $name, $attr ) = @_;
    $self->SUPER::subreport_start( $name, $attr );
    # Traitement spécifique à l'analyseur.
}

report_start( $name, $attr )

Est appelée lorsque la balise de début de l'élément "report" est détectée.

Le seul attribut défini est "version". La version actuelle est 2.0, mais les rapports de version 1.0 peuvent également être analysés.

report_end( $name )

Est appelée lorsque la balise de fermeture de l'élément "report" est détectée.

handle_title( $title )

Est appelée après le traitement de l'élément "title". Le paramètre $title contient le contenu de l'élément. Il peut s'agir du titre d'un rapport, d'un sous-rapport ou d'une section. Vous devez utiliser la méthode in_element() pour déterminer le contexte.

handle_description( $docbook_desc )

Si vous ne remplacez pas les événements description_start et description_end, le contenu de la description sera collecté et sera disponible dans la méthode handle_description().

handle_date( $date, $date_epoch )

Est appelée après l'analyse de l'élément "date". La date formatée est disponible dans le paramètre $date, et le nombre de secondes depuis l'époque est disponible dans le paramètre $date_epoch.

Il peut s'agir de la date d'un rapport ou d'un sous-rapport ; vous devez utiliser la méthode in_element() pour déterminer le contexte approprié.

handle_timespan( $timespan, $epoch_start, $epoch_end, $period )

Est appelée après l'analyse de l'élément "timespan". La forme formatée du temps est disponible dans le paramètre $timespan, et les dates de début et de fin de la période sont disponibles sous forme de secondes depuis l'époque dans les paramètres $epoch_start et $epoch_end. Le paramètre $period contient l'attribut de période du temps.

Il peut s'agir de la période d'un rapport ou d'un sous-rapport ; vous devez utiliser la méthode in_element() pour déterminer le contexte approprié.

section_start( $name, $attr )

Est appelée lorsque la balise d'ouverture d'un élément "section" est détectée.

section_end( $name )

Est appelée lorsque la balise de fermeture d'un élément "section" est détectée.

missing_subreport_start( $name, $attr )

Est appelée lorsque la balise d'ouverture d'un élément "missing-subreport" est détectée. L'attribut "superservice" contient le superservice du sous-rapport, l'attribut "type" contient l'ID de spécification du rapport et l'attribut "reason" contiendra la raison pour laquelle le sous-rapport est manquant.

missing_subreport_end( $name )

Est appelée lorsque la balise de fermeture d'un élément "missing-subreport" est détectée.

subreport_start( $name, $attr )

Est appelée lorsque la balise d'ouverture d'un élément "subreport" est détectée.

  • Le nom du champ.

table_start( $name, $attr )

Appelé lorsque la balise ouvrante de l'élément "table" est rencontrée. L'attribut "show" contient le nombre maximal d'entrées qui doivent être affichées (il peut y avoir plus d'entrées que ce nombre).

table_end( $name )

Appelé lorsque la balise fermante de "table" est rencontrée.

table_info_start( $name, $attr )

Appelé lorsque la balise fermante de l'élément "table-info" est rencontrée.

Il ne devrait y avoir aucune raison pour que les sous-classes remplacent cette méthode. Le Lire::ReportParser s'occupe de l'analyse du contenu de "table-info" et propose ces informations via un objet Lire::Report::TableInfo qui est accessible via la méthode current_table_info().

table_info_end( $name )

Appelé lorsque la balise fermante de "table-info" est rencontrée. Voir la documentation de table_info_start() pour des commentaires importants.

group_info_start( $name, $attr )

Appelé lorsque la balise ouvrante de "group-info" est rencontrée. Voir la documentation de table_info_start() pour des commentaires importants.

group_info_end( $name )

Appelé lorsque la balise fermante de "group-info" est rencontrée. Voir la documentation de table_info_start() pour des commentaires importants.

column_info_start( $name, $attr )

Appelé lorsque la balise ouvrante de "column-info" est rencontrée. Voir la documentation de table_info_start() pour des commentaires importants.

column_info_end( $name )

Appelé lorsque la balise fermante de "column-info" est rencontrée. Voir la documentation de table_info_start() pour des commentaires importants.

group_summary_start( $name, $attr )

Appelé lorsque la balise ouvrante de "group-summary" est rencontrée.

group_summary_end( $name )

Appelé lorsque la balise fermante de "group-summary" est rencontrée.

group_start( $name, $attr )

Appelé lorsque la balise ouvrante de l'élément "group" est rencontrée. Les éléments "group" introduisent une sorte de table imbriquée. L'attribut "show" contient le nombre maximal d'entrées qui doivent être affichées, bien que plus d'entrées puissent être présentes dans le rapport.

group_end( $name )

Appelé lorsque la balise fermante de "group" est rencontrée.

entry_start( $name, $attr )

Appelé lorsque la balise ouvrante d'un élément "entry" est rencontrée.

entry_end( $name )

Appelé lorsque la balise fermante de "entry" est rencontrée.

handle_name( $name_rec )

Appelé après qu'un élément "name" ait été analysé. Le paramètre $name_rec est une référence de hachage qui contient les différentes valeurs de la donnée nom. Les clés définies dans ce hachage sont :

content
C'est le contenu réel de l'élément nom. Il contient le nom dans un format adapté à l'affichage.
value
Ceci contient la valeur non formatée du nom. Par exemple, lorsque le nom est une chaîne de caractères temporelle, cet attribut contiendra le temps en secondes depuis l'époque.
range
Pour certains noms, le contenu réel exprime une plage (temps, taille, etc.). Cet attribut contient la longueur de la plage.
col_info
L'objet Lire::ColumnInfo décrivant la colonne dans laquelle ce nom apparaît.

handle_value( $value_rec )

Appelé après qu'un élément "value" ait été analysé. Le paramètre $value_rec est une référence de hachage qui contient les différentes valeurs de la donnée valeur. Les clés définies dans ce hachage sont :

content
C'est le contenu réel de l'élément valeur. Il contient la valeur dans un format adapté à l'affichage.
value
Ceci contient la valeur non formatée. Par exemple, lorsque les octets sont affichés en utilisant "1M" ou "1.1G", ceci contiendra la valeur en octets.
total
Ceci est utilisé par les valeurs qui représentent une moyenne. Il contient le total qui compose la moyenne.
n
Ceci est utilisé par les valeurs qui représentent une moyenne. Il contient le total qui a été utilisé dans la division pour calculer la moyenne.
col_info
L'objet Lire::ColumnInfo décrivant la colonne dans laquelle ce nom apparaît.

handle_summary_value( $value_rec )

Appelé après qu'un élément "value" situé dans l'élément group-summary ait été analysé. Le paramètre $value_rec est identique à celui de la méthode handle_value().

handle_chart_configs( $configs )

Si le Sous-rapport contenait des configurations de graphiques, une référence d'tableau d'objets Lire::Report::ChartConfig sera passée à ce gestionnaire d'événements.

MÉTHODES DE CONTEXTE

current_subreport_count( )

Retourne le nombre de sous-rapports présents à ce jour dans le rapport. Ce nombre est égal au nombre d'éléments "subreport" traités, c'est-à-dire que le sous-rapport actuel n'est pas compté tant que sa balise fermante n'a pas été traitée.

current_section_subreport_count( )

Retourne le nombre de sous-rapports présents à ce jour dans la section. Ce nombre est égal au nombre d'éléments "subreport" traités, c'est-à-dire que le sous-rapport actuel n'est pas compté tant que sa balise fermante n'a pas été traitée.
