NAME

Lire::XMLParser - Analyseur XML orienté objet de base.

SYNOPSIS

package MyParser;
use base qw/ Lire::XMLParser /;

DESCRIPTION

Ce module permet d'écrire des analyseurs orientés objet en utilisant le module XML::Parser, non orienté objet.

MÉTHODES CLIENT

parse( $xml )

Analyse le XML et retourne le résultat. $xml peut être une chaîne de caractères, une référence vers un descripteur de fichier ou un objet IO::Handle ouvert.

parsefile( $file )

Analyse le XML contenu dans $file et retourne le résultat.

MÉTHODES TEMPLATE DE MÉTADONNÉES

Deux méthodes template doivent être implémentées par les sous-classes. Ces méthodes fournissent des informations sur le modèle de contenu du XML attendu par l'analyseur.

namespaces()

Cette méthode doit retourner une référence de hachage. Les clés sont les espaces de noms XML compris par l'analyseur. La valeur est le préfixe utilisé pour cet espace de noms dans la méthode elements_spec().

elements_spec()

Cette méthode doit retourner une référence de hachage. Les clés sont les éléments XML connus. Une erreur sera levée par l'analyseur lorsqu'un élément non défini dans ce hachage sera rencontré.

La clé doit être de la forme [ préfixe : ] nom_élément. Si un préfixe est utilisé, il doit être défini dans la méthode namespaces().

La valeur du hachage correspond aux spécifications de l'élément. Cette spécification peut être utilisée pour configurer les gestionnaires d'événements qui seront appelés, ainsi que pour spécifier le modèle de contenu des éléments. Cette spécification est une référence de hachage avec les clés suivantes :

content
Ceci est une référence de tableau qui doit contenir le nom des éléments autorisés à apparaître dans cet élément. Ces noms sont dans le même format que pour les clés de elements_spec(). Si cet élément est omis, l'élément est considéré comme vide et ne peut donc contenir aucun autre élément. Si l'élément peut contenir du PCDATA, la chaîne 'PCDATA' doit être listée dans le tableau.
start
Ceci spécifie le gestionnaire appelé lorsque la balise d'ouverture de cet élément est rencontrée. Il peut s'agir d'une référence de fonction ou d'un nom de méthode. Si cet élément est omis, le gestionnaire sera la méthode nommée élément_start s'il existe, ou aucun gestionnaire sinon. '_' est substitué pour les caractères invalides de nom de méthode, c'est-à-dire que report-spec devient report_spec_start.
end
Ceci spécifie le gestionnaire appelé lorsque la balise de fermeture de cet élément est rencontrée. Il peut s'agir d'une référence de fonction ou d'un nom de méthode. Si cet élément est omis, le gestionnaire sera la méthode nommée élément_end s'il existe, ou aucun gestionnaire sinon. '_' est substitué pour les caractères invalides de nom de méthode, c'est-à-dire que report-spec devient report_spec_end.
char
Ceci spécifie le gestionnaire appelé lorsque du PCDATA est rencontré dans l'élément. Cela ne peut se produire que si 'PCDATA' est apparu dans l'attribut 'content'. Il peut s'agir d'une référence de fonction ou d'un nom de méthode. Si cet élément est omis, le gestionnaire sera la méthode nommée élément_char s'il existe, ou aucun gestionnaire sinon. '_' est substitué pour les caractères invalides de nom de méthode, c'est-à-dire que list-item devient list_item_char.

La spécification peut également être une référence de tableau, auquel cas elle sera interprétée comme le contenu de l'attribut de hachage 'content'.

Des erreurs seront signalées pour les spécifications invalides.

MÉTHODES UTILITAIRES

expat()

Pendant l'analyse, ceci retourne l'objet d'analyse sous-jacent Lire::XMLParser::Expat.

error( $msg )

Terminera l'analyse avec le message d'erreur $msg. Le contexte d'analyse actuel sera ajouté au message.

warning( $msg )

Affichera un message d'avertissement $msg. Le contexte d'analyse actuel sera ajouté au message.

context()

Retourne sous forme de référence de tableau les noms des éléments actuellement ouverts. Dans les balises de début et de fin, le dernier élément sera la balise de l'élément parent. Le nom des éléments sera dans le même format que celui utilisé par elements_spec().

current_element()

Retourne le nom de l'élément actuellement ouvert le plus interne. Dans les balises de début et de fin, le dernier élément sera la balise de l'élément parent. Le nom des éléments sera dans le même format que celui utilisé par elements_spec().

in_element( $element_name )

Ceci retourne vrai si l'élément actuellement ouvert le plus interne a le même nom que $element_name. $element_name devrait être l'un des éléments définis par elements_spec(), sinon la méthode provoquera une erreur.

Exemple :

if ( $self->in_element( "lire:report") ) {
    # L'élément parent est un élément de rapport Lire.
} elsif ( $self->in_element( "listitem" ) ) {
    # Nous sommes dans un élément listitem de DocBook
}

within_element( $element_name )

Ceci retourne le nombre de fois qu'un élément est ouvert dans l'ancêtre élémentaire actuel. Comme pour in_element(), le nom de l'élément devrait avoir été défini par elements_spec(), sinon la méthode provoquera une erreur.

recognized_string()

Retourne la chaîne qui déclenche l'événement actuel.

depth()

Retourne le nombre d'éléments ouverts et non encore fermés. Dans les gestionnaires de début et de fin, l'élément actuel fait partie de cette liste.

MÉTHODES DE GESTIONNAIRES D'ÉVÉNEMENTS

Ce sont des méthodes qui sont appelées pendant l'analyse du XML.

parse_start()

Cette méthode est invoquée une fois avant que le document ne soit analysé. Elle peut être utilisée pour toute initialisation que le processeur doit effectuer. L'implémentation par défaut ne fait rien.

parse_end( )

Cette méthode est invoquée une fois après que tout le fichier XML a été traité. La valeur retournée par cette méthode sera retournée par la méthode parse() ou parsefile() (celle qui a été utilisée pour démarrer l'analyse). L'implémentation par défaut ne fait rien.

element_start( $name, $attributes )

Appelée lorsqu'un élément valide est ouvert. $name contient le nom de l'élément. Ce nom est la forme canonique, c'est-à-dire que si l'élément fait partie d'un espace de noms, il sera préfixé par le préfixe déclaré par la méthode namespaces(). $attributes contient les attributs définis sous forme de référence de hachage.

La méthode par défaut redirigera vers les gestionnaires définis par elements_spec().

element_end( $name )

Appelée lorsqu'un élément valide est fermé. $name contient le nom de l'élément.

NOM

XMLParser

SYNOPIS

XMLParser

DESCRIPTION

XMLParser est une classe qui fournit des méthodes pour l'analyse de documents XML. Elle prend en charge différents modes d'analyse et fournit des méthodes pour gérer différents types d'événements.

MÉTHODES CLIENT

XMLParser offre des méthodes pour la gestion des événements côté client. Ces méthodes sont utilisées pour traiter les documents XML et gérer différents types d'événements.

MÉTHODES DE MODÈLE MÉTADONNÉES

XMLParser fournit des méthodes pour la gestion des métadonnées dans l'analyse de modèles. Ces méthodes sont utilisées pour traiter et manipuler les données du modèle.

MÉTHODES UTILITAIRES

XMLParser offre des méthodes utilitaires pour les tâches courantes d'analyse. Ces méthodes sont utilisées pour gérer diverses opérations liées à l'analyse de documents XML.

MÉTHODES DE GESTIONNAIRES D'ÉVÉNEMENTS

XMLParser fournit des méthodes pour la gestion des gestionnaires d'événements côté client. Ces méthodes sont utilisées pour traiter différents types d'événements lors de l'analyse XML.

MÉTHODES D'ASSISTANCE

XMLParser offre des méthodes d'assistance pour les tâches courantes d'analyse. Ces méthodes sont utilisées pour gérer diverses opérations liées à l'analyse de documents XML.
