Module Lexing
: sig end

La bibliothèque d'exécution pour les analyseurs lexicaux générés par ocamllex.

Positions

type position = {
pos_fname : string ;
pos_lnum : int ;
pos_bol : int ;
pos_cnum : int ;
}

Une valeur de type position décrit un point dans un fichier source. pos_fname est le nom du fichier ; pos_lnum est le numéro de ligne ; pos_bol est le décalage du début de la ligne (nombre de caractères entre le début du lexbuf et le début de la ligne) ; pos_cnum est le décalage de la position (nombre de caractères entre le début du lexbuf et la position). La différence entre pos_cnum et pos_bol est le décalage de caractère dans la ligne (c'est-à-dire le numéro de colonne, en supposant que chaque caractère a une largeur de colonne).

Voir la documentation du type lexbuf pour des informations sur la manière dont le moteur d'analyse lexicale gère les positions.

val dummy_pos : position

Une valeur de type position, garantie d'être différente de toute position valide.

Tampons d'analyse lexicale

type lexbuf = {
refill_buff : lexbuf -> unit ;

mutable lex_buffer : bytes ;

mutable lex_buffer_len : int ;

mutable lex_abs_pos : int ;

mutable lex_start_pos : int ;

mutable lex_curr_pos : int ;

mutable lex_last_pos : int ;

mutable lex_last_action : int ;

mutable lex_eof_reached : bool ;

mutable lex_mem : int array ;

mutable lex_start_p : position ;

mutable lex_curr_p : position ;
}

Le type des tampons d'analyse lexicale. Un tampon d'analyse lexicale est l'argument passé aux fonctions de balayage définies par les analyseurs générés. Le tampon d'analyse lexicale contient l'état actuel de l'analyseur, plus une fonction pour recharger le tampon à partir de l'entrée.

Les analyseurs peuvent éventuellement maintenir les champs de position lex_curr_p et lex_start_p. Ce mode de « suivi de position » est le mode par défaut, et il correspond à passer ~with_position:true aux fonctions qui créent des tampons d'analyse lexicale. Dans ce mode, le moteur d'analyse lexicale et les actions de l'analyseur sont coresponsables de la mise à jour correcte des champs de position, comme décrit au paragraphe suivant. Lorsque le mode est explicitement désactivé (avec ~with_position:false), le moteur d'analyse lexicale ne touchera pas les champs de position et les actions de l'analyseur ne devraient pas non plus le faire ; les champs lex_curr_p et lex_start_p contiendront alors toujours la position invalide dummy_pos. Ne pas suivre les positions évite les allocations et les écritures mémoire et peut améliorer significativement les performances de l'analyseur dans les contextes où lex_start_p et lex_curr_p ne sont pas nécessaires.

Le mode de suivi de position fonctionne comme suit. À chaque jeton, le moteur d'analyse lexicale copiera lex_curr_p dans lex_start_p, puis modifiera le champ pos_cnum de lex_curr_p en le mettant à jour avec le nombre de caractères lus depuis le début du lexbuf. Les autres champs sont laissés inchangés par le moteur d'analyse lexicale. Afin de les maintenir précis, ils doivent être initialisés avant la première utilisation du lexbuf, et mis à jour par les actions pertinentes de l'analyseur (c'est-à-dire à chaque fin de ligne – voir aussi new_line).

val from_channel : ?with_positions:bool -> in_channel -> lexbuf

Crée un tampon d'analyse lexicale sur le canal d'entrée donné. Lexing.from_channel inchan renvoie un tampon d'analyse lexicale qui lit à partir du canal d'entrée inchan, à la position de lecture actuelle.

val from_string : ?with_positions:bool -> string -> lexbuf

Crée un tampon d'analyse lexicale qui lit à partir de la chaîne donnée. La lecture commence à partir du premier caractère de la chaîne. Une condition de fin d'entrée est générée lorsque la fin de la chaîne est atteinte.

val from_function : ?with_positions:bool -> (bytes -> int -> int) -> lexbuf

Crée un tampon d'analyse lexicale avec la fonction donnée comme méthode de lecture. Lorsque l'analyseur a besoin de caractères supplémentaires, il appellera la fonction donnée, lui passant une séquence d'octets s et un nombre d'octets n. La fonction doit placer n octets ou moins dans s, en commençant à l'index 0, et renvoyer le nombre d'octets fournis. Une valeur de retour de 0 signifie fin d'entrée.

val set_position : lexbuf -> position -> unit

Définit la position d'entrée initiale suivie pour lexbuf à une valeur personnalisée. Ignore pos_fname. Voir Lexing.set_filename pour changer ce champ.

Depuis 4.11

val set_filename : lexbuf -> string -> unit

Définit le nom de fichier dans la position initiale suivie à file dans lexbuf.

Depuis 4.11

val with_positions : lexbuf -> bool

Indique si le tampon d'analyse lexicale suit les champs de position lex_curr_p / lex_start_p, tels que déterminés par l'argument optionnel correspondant pour les fonctions qui créent des tampons d'analyse lexicale (dont la valeur par défaut est true).

Lorsque with_positions est false, les actions de l'analyseur ne doivent pas modifier les champs de position. Le faire néanmoins pourrait réactiver le mode with_position et dégrader les performances.

Fonctions pour les actions sémantiques de l'analyseur lexicale

Les fonctions suivantes peuvent être appelées à partir des actions sémantiques des définitions d'analyseurs lexicaux (le code ML entre accolades qui calcule la valeur renvoyée par les fonctions d'analyse lexicale). Elles donnent accès à la chaîne de caractères correspondant à l'expression régulière associée à l'action sémantique. Ces fonctions doivent être appliquées à l'argument lexbuf, qui, dans le code généré par ocamllex, est lié au tampon d'analyse lexicale passé à la fonction d'analyse.

val lexeme : lexbuf -> string

Lexing.lexeme lexbuf renvoie la chaîne correspondant à l'expression régulière.

val lexeme_char : lexbuf -> int -> char

Lexing.lexeme_char lexbuf i renvoie le caractère numéro i dans la chaîne correspondante.

val lexeme_start : lexbuf -> int

Lexing.lexeme_start lexbuf renvoie le décalage dans le flux d'entrée du premier caractère de la chaîne correspondante. Le premier caractère du flux a le décalage 0.

val lexeme_end : lexbuf -> int

Lexing.lexeme_end lexbuf renvoie le décalage dans le flux d'entrée du caractère suivant le dernier caractère de la chaîne correspondante. Le premier caractère du flux a le décalage 0.

val lexeme_start_p : lexbuf -> position

Comme lexeme_start, mais renvoie une position complète au lieu d'un décalage. Lorsque le suivi de position est désactivé, la fonction renvoie dummy_pos.

val lexeme_end_p : lexbuf -> position

Comme lexeme_end, mais renvoie une position complète au lieu d'un décalage. Lorsque le suivi de position est désactivé, la fonction renvoie dummy_pos.

val new_line : lexbuf -> unit

Met à jour le champ lex_curr_p du lexbuf pour refléter le début d'une nouvelle ligne. Vous pouvez appeler cette fonction dans l'action sémantique de la règle qui correspond au caractère de fin de ligne. La fonction ne fait rien lorsque le suivi de position est désactivé.

Depuis 3.11

Fonctions diverses

val flush_input : lexbuf -> unit

Jette le contenu du tampon et réinitialise la position actuelle à 0. La prochaine utilisation du lexbuf déclenchera un rechargement.
