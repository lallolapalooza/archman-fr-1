NAME

Lire::Proxy::SquidAccessDlfConverter - convertir les logs squid au format dlf

DESCRIPTION

squid_access2dlf attend un fichier access.log, comme celui produit par le proxy cache SQUID (http://www.squid-cache.org/) sur l'entrée standard.

Ces fichiers de logs sont séparés par des espaces, les colonnes sont

time elapsed remotehost code/status bytes method URL rfc931 peerstatus/peerhost type

Une ligne de log typique ressemble à ceci :

979992041.366 502 192.168.1.160 TCP_IMS_HIT/304 216 GET
 http://example.com/home2.html - NONE/- text/html

La signification des champs est :

time
Un horodatage Unix en secondes sous forme d'UTC avec une résolution en millisecondes.
elapsed
Le temps écoulé indique combien de millisecondes le proxy cache a mis pour rechercher l'objet.
remotehost
L'adresse IP du client, l'adresse IP de destination.
code/status
Cette colonne est composée de deux entrées séparées par un slash. Cette colonne code le résultat de la requête.

Les informations de résultat du cache contiennent des détails sur le type de requête, comment elle a été satisfaite ou sous quelle forme elle a échoué. La partie statut contient des codes HTTP avec quelques extensions spécifiques à Squid. Squid utilise un sous-ensemble des codes définis dans les RFC pour HTTP.

TCP_HIT
Une copie valide de l'objet demandé a été trouvée dans le cache.
TCP_MISS
L'objet demandé n'a pas été trouvé dans le cache.
TCP_REFRESH_HIT
L'objet demandé a été trouvé dans le cache, mais il était expiré. La requête IMS de l'objet a résulté en un "304 not modified".
TCP_REF_FAIL_HIT
L'objet demandé a été trouvé dans le cache, mais il était expiré. La requête IMS a échoué et l'objet expiré a été servi.
TCP_REFRESH_MISS
L'objet demandé a été trouvé dans le cache, mais il était expiré. La requête IMS a renvoyé le nouveau contenu.
TCP_CLIENT_REFRESH_MISS
Le client a émis une directive "no-cache" pragma, ou une autre instruction de contrôle de cache avec la requête. Par conséquent, le cache doit récupérer l'objet.
TCP_IMS_HIT
Le client a émis une requête IMS pour un objet qui était dans le cache et frais.
TCP_SWAPFAIL_MISS
L'objet était supposé être dans le cache, mais il était inaccessible.
TCP_NEGATIVE_HIT
Une requête pour un objet négativement mis en cache, par exemple "404 not found", pour lequel le cache pense qu'il est inaccessible.
TCP_MEM_HIT
Une copie valide de l'objet demandé a été trouvée dans le cache et était en mémoire, évitant les accès disque.
TCP_DENIED
La requête a été rejetée.
TCP_OFFLINE_HIT
L'objet demandé a été récupéré du cache pendant le mode hors ligne. Le mode hors ligne ne valide jamais aucun objet, voir offline_mode dans squid.conf.
UDP_HIT
Une copie valide de l'objet demandé a été trouvée dans le cache.
UDP_MISS
L'objet demandé n'est pas trouvé dans ce cache.
UDP_DENIED
La requête a été rejetée.
UDP_INVALID
Une requête invalide a été reçue.
UDP_MISS_NOFETCH
Lors du démarrage de ""-Y"" ou lors de pannes fréquentes, un cache en mode hit ne renverra que UDP_HIT ou ce code. Les voisins ne récupéreront donc que les hits.
NONE
Vus avec les erreurs et les requêtes de cache.
bytes
La quantité correspond à la taille des données livrées au client. Il faut noter que cela ne constitue pas la taille nette de l'objet, car les en-têtes sont également comptés.
method
La méthode de requête pour obtenir un objet. Les méthodes sont : 
method    defined    cachabil.  meaning
--------- ---------- ---------- --------------------
GET       HTTP/0.9   possibly   objet de récupération et de recherche simple.
HEAD      HTTP/1.0   possibly   récupération des métadonnées.
POST      HTTP/1.0   CC ou Exp. envoi de données (vers un programme).
PUT       HTTP/1.1   never      téléchargement de données (par exemple, dans un fichier).
DELETE    HTTP/1.1   never      suppression de la ressource (par exemple, fichier).
TRACE     HTTP/1.1   never      traçage du chemin de requête dans la couche
      applicative.
OPTIONS   HTTP/1.1   never      requête d'options de communication.
CONNECT   HTTP/1.1r3 never      connexion SSL tunnelisée.
ICP_QUERY Squid never   utilisé pour les échanges ICP.
PURGE     Squid never   supprimer l'objet du cache.
PROPFIND  rfc2518    ?          récupérer les propriétés d'un objet.
PROPATCH  rfc2518    ?          modifier les propriétés d'un objet.
MKCOL     rfc2518    never      créer une nouvelle collection.
MOVE      rfc2518    never      créer une copie dupliquée de la source à la destination.
COPY      rfc2518    never      déplacer atomiquement la source vers la destination.
LOCK      rfc2518    never      verrouiller un objet contre les modifications.
UNLOCK    rfc2518    never      déverrouiller un objet.
URL
Cette colonne contient l'URL demandée. Il faut noter que le fichier de log peut contenir des espaces pour l'URI. Dans le DLF de Lire, l'URL est divisée en protocole, hôte et chemin.
rfc931
La huitième colonne peut contenir les identifications des clients qui demandent.
peerstatus/peerhost
Résultats des caches voisins.
type
Le type de contenu de l'objet tel qu'il apparaît dans l'en-tête de réponse HTTP.

EXEMPLES

Pour traiter un log comme celui produit par SQUID :

$ squid_access2dlf < squid.log

squid_access2dlf sera rarement utilisé tel quel, mais sera plus probablement appelé par lr_log2report :

$ cat /var/log/squid.log | lr_run lr_log2report squid_access
