NOM

Lire::Test::DlfAnalyserTestCase - Classe de base pour écrire des tests unitaires de DlfAnalyser

SYNTAXE

use base qw/ Lire::Test::DlfAnalyserTestCase /;
use MyAnalyser;
use File::Basename;
sub create_analyser {
  return new MyAnalyser();
}
sub schemasdir {
  return dirname( __FILE__ ) .  "../..";
}
sub registration_file {
  return dirname( __FILE__ ) .  "../../myanalyser_init";
}

DESCRIPTION

Ceci est une sous-classe de Test::Unit::TestCase qui peut être utilisée pour écrire facilement des tests pour DlfAnalyser. Cette classe implémente ce qui est nécessaire pour fournir le cadre nécessaire dans set_up() et tear_down().

Elle fournit deux tests de base : test_api() et test_registration_file().

La classe de test doit implémenter trois méthodes pour aider à compléter le cadre.

CADRES

Ce sont les méthodes que les sous-classes remplacent généralement pour fournir les données nécessaires afin que les cadres de test DlfAnalyser soient configurés.

registration_file()

Ceci devrait retourner le script responsable de l'enregistrement de l'analyseur avec le Lire::PluginManager. Ceci est utilisé par le test_registration_file() par défaut.

schemasdir()

Cette méthode doit retourner le répertoire qui contient les schémas utilisés par l'analyseur. Ceci sera ajouté à la variable de configuration lr_schemas_path.

create_analyser()

Ceci devrait retourner une instance de l'instance Lire::DlfAnalyser à tester.

Mock Converter Process

create_mock_process( [ $store ])

Cette méthode retournera un MockDlfAnalyserProcess qui peut être utilisé pour aider à tester DlfAnalyser. Toutes les valeurs pour write_dlf() et error() sont sauvegardées et peuvent être interrogées via les méthodes dlf() et errors(). Notez que la méthode dlf() retourne une référence d'un tableau de références de tableaux. Le premier élément dans les tableaux internes est le dlf et les autres éléments sont l'ID DLF associé, le cas échéant.

La méthode de processus mock analyser_instance() retourne l'instance DlfAnalyser créée par create_analyser() et associée à son instance.

Le paramètre optionnel $store devrait être une instance de Lire::DlfStore qui sera disponible via la méthode dlf_store().

TESTS PAR DÉFAUT

test_api()

S'assure que toutes les méthodes requises par Lire::DlfAnalyser sont implémentées. Il teste également que src_schema() et dst_schema() sont disponibles.

Il vérifie que description() est correctement formaté en DocBook.

test_registration_file()

Vérifie que le script d'enregistrement enregistre correctement l'analyseur auprès du PluginManager.

VOIR AUSSI

Lire::Test::TestCase(3pm), Lire::DlfAnalyser(3pm)
