DESCRIPTION

Ces macros définissent et manipulent quatre types de structures de données qui peuvent être utilisées dans le code source C et C++ :

  1. Listes
  2. Listes chaînées simples
  3. Files de liste chaînées simples (tail queues)
  4. Files de liste chaînées (tail queues)
Les quatre structures prennent en charge les fonctionnalités suivantes :
  1. Insertion d'une nouvelle entrée en tête de liste.
  2. Insertion d'une nouvelle entrée après un élément existant dans la liste.
  3. Suppression d'une entrée en tête de liste en temps O(1).
  4. Parcours de la liste dans le sens direct.
  5. Échange du contenu de deux listes.

Les listes chaînées simples sont les plus simples des quatre structures de données et ne prennent en charge que les fonctionnalités ci-dessus. Les listes chaînées simples sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une file LIFO (dernier entré, premier sorti). Les listes chaînées simples ajoutent les fonctionnalités suivantes :

  1. Suppression d'une entrée quelconque dans la liste en temps O(n).
  2. Concaténation de deux listes en temps O(n).

Les files de liste chaînées simples (singly-linked tail queues) ajoutent les fonctionnalités suivantes :

  1. Les entrées peuvent être ajoutées à la fin d'une liste.
  2. Suppression d'une entrée quelconque dans la liste en temps O(n).
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions dans la liste doivent spécifier la tête de la liste.
  2. Chaque entrée de tête nécessite deux pointeurs au lieu d'un seul.
  3. La taille du code est environ 15% plus grande et les opérations sont environ 20% plus lentes que pour les listes chaînées simples.

Les files de liste chaînées simples sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une file FIFO (premier entré, premier sorti).

Toutes les structures de données doublement chaînées (listes et files de liste chaînées) permettent en outre :

  1. Insertion d'une nouvelle entrée avant un élément de la liste.
  2. Suppression d'une entrée quelconque de la liste en temps O(1).
Cependant :
  1. Chaque élément nécessite deux pointeurs au lieu d'un seul.
  2. La taille du code et le temps d'exécution des opérations (à l'exception de la suppression) sont environ le double de ceux des structures de données chaînées simples.

Les listes chaînées sont les plus simples des structures de données doublement chaînées. Elles ajoutent les fonctionnalités suivantes par rapport aux précédentes :

  1. Concaténation de deux listes en temps O(n).
  2. Elles peuvent être parcourues en arrière.
Cependant :
  1. Pour parcourir en arrière, une entrée pour commencer le parcours et la liste dans laquelle elle est contenue doivent être spécifiées.

Les files de liste chaînées (tail queues) ajoutent les fonctionnalités suivantes :

  1. Les entrées peuvent être ajoutées à la fin d'une liste.
  2. Elles peuvent être parcourues en arrière, de la fin au début.
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions et suppressions de liste doivent spécifier la tête de la liste.
  2. Chaque entrée de tête nécessite deux pointeurs au lieu d'un seul.
  3. La taille du code est environ 15% plus grande et les opérations sont environ 20% plus lentes que pour les listes chaînées simples.

Dans les définitions de macros, TYPE est le nom d'une structure définie par l'utilisateur. La structure doit contenir un champ appelé NAME qui est de type SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY, ou TAILQ_ENTRY. Dans les définitions de macros, CLASSTYPE est le nom d'une classe définie par l'utilisateur. La classe doit contenir un champ appelé NAME qui est de type SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY, ou TAILQ_CLASS_ENTRY. L'argument HEADNAME est le nom d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD, ou TAILQ_CLASS_HEAD. Voir les exemples ci-dessous pour plus d'explications sur l'utilisation de ces macros.

LISTES CHAÎNÉES SIMPLES

Une liste chaînée simple est dirigée par une structure définie par la macro SLIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont chaînés simplement pour un minimum d'espace et de surcharge de manipulation de pointeurs, au détriment de la suppression en O(n) pour les éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant ou en tête de la liste. Une structure SLIST_HEAD est déclarée comme suit :

SLIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la liste. Un pointeur vers la tête de la liste peut ensuite être déclaré comme :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro SLIST_HEAD_INITIALIZER évalue à un initialiseur pour la liste head.

La macro SLIST_CONCAT concatène la liste dirigée par head2 à la fin de celle dirigée par head1, en supprimant toutes les entrées de la première. L'utilisation de cette macro doit être évitée car elle parcourt la totalité de la liste head1. Une file de liste chaînée simple (singly-linked tail queue) doit être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro SLIST_EMPTY évalue à vrai s'il n'y a aucun élément dans la liste.

La macro SLIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro SLIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro SLIST_FOREACH parcourt la liste référencée par head dans le sens direct, en assignant chaque élément en tour à var.

La macro SLIST_FOREACH_FROM se comporte identiquement à SLIST_FOREACH lorsque var est NULL, sinon elle traite var comme un élément SLIST précédemment trouvé et commence la boucle à var au lieu du premier élément de la SLIST référencée par head.

La macro SLIST_FOREACH_SAFE parcourt la liste référencée par head dans le sens direct, en assignant chaque élément en tour à var. Cependant, contrairement à SLIST_FOREACH() ici, il est permis de supprimer var ainsi que de la libérer depuis l'intérieur de la boucle en toute sécurité sans interférer avec le parcours.

La macro SLIST_FOREACH_FROM_SAFE se comporte identiquement à SLIST_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément SLIST précédemment trouvé et commence la boucle à var au lieu du premier élément de la SLIST référencée par head.

La macro SLIST_INIT initialise la liste référencée par head.

La macro SLIST_INSERT_HEAD insère le nouvel élément elm en tête de la liste.

La macro SLIST_INSERT_AFTER insère le nouvel élément elm après l'élément

EXEMPLE DE LISTE CHAÎNÉE SIMPLE

SLIST_HEAD(slisthead, entry) head =
    SLIST_HEAD_INITIALIZER(head);
struct slisthead *headp;		/* Tête de liste chaînée simple. */
struct entry {
	...
	SLIST_ENTRY(entry) entries;	/* Chaîne simple. */
	...
} *n1, *n2, *n3, *np;

SLIST_INIT(&head);			/* Initialiser la liste. */

n1 = malloc(sizeof(struct entry));	/* Insérer en tête. */
SLIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
SLIST_INSERT_AFTER(n1, n2, entries);

SLIST_REMOVE(&head, n2, entry, entries);/* Suppression. */
free(n2);

n3 = SLIST_FIRST(&head);
SLIST_REMOVE_HEAD(&head, entries);	/* Suppression de la tête. */
free(n3);
					/* Parcours avant. */
SLIST_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours sécurisé. */
SLIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	SLIST_REMOVE(&head, np, entry, entries);
	free(np);
}

while (!SLIST_EMPTY(&head)) {		/* Suppression de la liste. */
	n1 = SLIST_FIRST(&head);
	SLIST_REMOVE_HEAD(&head, entries);
	free(n1);
}

FILES DE CODA À CHAÎNAGE SIMPLE

Une file de coda à chaînage simple est gérée par une structure définie à l'aide de la macro STAILQ_HEAD. Cette structure contient deux pointeurs : un vers le premier élément de la file de coda et un vers le dernier élément de la file de coda. Les éléments sont chaînés de manière simple afin de minimiser la surcharge d'espace et de manipulation des pointeurs, bien que le temps de suppression puisse être de O(n) pour des éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la file de coda après un élément existant, en tête de la file de coda ou à la fin de la file de coda. Une structure STAILQ_HEAD est déclarée comme suit :

STAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et TYPE est le type des éléments chaînés dans la file de coda. Une adresse de pointeur vers la tête de la file de coda peut être déclarée ultérieurement comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont choisissables par l'utilisateur.)

La macro STAILQ_HEAD_INITIALIZER est évaluée comme un initialiseur pour la file de coda head.

La macro STAILQ_CONCAT concatène la file de coda gérée par head2 à la fin de la file de coda gérée par head1, en vidant la première.

La macro STAILQ_EMPTY renvoie vrai si la file de coda est vide.

La macro STAILQ_ENTRY déclare une structure qui relie les éléments de la file de coda.

La macro STAILQ_FIRST renvoie le premier élément de la file de coda ou NULL si la file de coda est vide.

La macro STAILQ_FOREACH parcourt la file de coda gérée par head dans le sens avant, en assignant chaque élément à var.

La macro STAILQ_FOREACH_FROM fonctionne de manière similaire à STAILQ_FOREACH lorsque var est NULL ; sinon, elle traite var comme un élément précédemment trouvé dans la file de coda et commence la boucle à partir de var au lieu du premier élément de la file de coda gérée par head.

La macro STAILQ_FOREACH_SAFE parcourt la file de coda gérée par head dans le sens avant, en assignant chaque élément à var. Cependant, contrairement à STAILQ_FOREACH(), il est permis de supprimer var et de libérer son contenu pendant la boucle sans interférer avec le parcours.

La macro STAILQ_FOREACH_FROM_SAFE fonctionne de manière similaire à STAILQ_FOREACH_SAFE lorsque var est NULL ; sinon, elle traite var comme un élément précédemment trouvé dans la file de coda et commence la boucle à partir de var au lieu du premier élément de la file de coda gérée par head.

La macro STAILQ_INIT initialise la file de coda gérée par head.

La macro STAILQ_INSERT_HEAD insère le nouvel élément elm en tête de la file de coda.

La macro STAILQ_INSERT_TAIL insère le nouvel élément elm à la fin de la file de coda.

La macro STAILQ_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro STAILQ_LAST renvoie le dernier élément de la file de coda. Si la file de coda est vide, la valeur renvoyée est NULL.

La macro STAILQ_NEXT renvoie l'élément suivant dans la file de coda, ou NULL si c'est le dernier.

La macro STAILQ_REMOVE_AFTER supprime l'élément qui suit elm de la file de coda. Contrairement à STAILQ_REMOVE, cette macro ne parcourt pas toute la file de coda.

La macro STAILQ_REMOVE_HEAD supprime l'élément en tête de la file de coda. Pour une efficacité optimale, les éléments supprimés de la tête de la file de coda devraient utiliser explicitement cette macro plutôt que la macro générale STAILQ_REMOVE.

La macro STAILQ_REMOVE supprime l'élément elm de la file de coda. Son utilisation doit être évitée car elle parcourt toute la file. Une file de coda à double chaînage doit être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues files de coda.

La macro STAILQ_SWAP échange les contenus de head1 et head2.

EXEMPLE DE FILE DE CODA À CHAÎNAGE SIMPLE

STAILQ_HEAD(stailhead, entry) head =
    STAILQ_HEAD_INITIALIZER(head);
struct stailhead *headp;		/* Tête de file de coda à chaînage simple. */
struct entry {
	...
	STAILQ_ENTRY(entry) entries;	/* File de coda. */
	...
} *n1, *n2, *n3, *np;

STAILQ_INIT(&head);			/* Initialiser la file. */

n1 = malloc(sizeof(struct entry));	/* Insérer en tête. */
STAILQ_INSERT_HEAD(&head, n1, entries);

n1 = malloc(sizeof(struct entry));	/* Insérer à la fin. */
STAILQ_INSERT_TAIL(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
STAILQ_INSERT_AFTER(&head, n1, n2, entries);
					/* Suppression. */
STAILQ_REMOVE(&head, n2, entry, entries);
free(n2);
					/* Suppression de la tête. */
n3 = STAILQ_FIRST(&head);
STAILQ_REMOVE_HEAD(&head, entries);
free(n3);
					/* Parcours avant. */
STAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours sécurisé. */
STAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	STAILQ_REMOVE(&head, np, entry, entries);
	free(np);
}
					/* Suppression de la file de coda. */
while (!STAILQ_EMPTY(&head)) {
	n1 = STAILQ_FIRST(&head);
	STAILQ_REMOVE_HEAD(&head, entries);
	free(n1);
}
					/* Suppression plus rapide. */
n1 = STAILQ_FIRST(&head);
while (n1 != NULL) {
	n2 = STAILQ_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
STAILQ_INIT(&head);

LISTES

Une liste est gérée par une structure définie à l'aide de la macro LIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont à double chaînage, ce qui permet de supprimer n'importe quel élément sans parcourir la liste. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant, avant un élément existant ou en tête de liste. Une structure LIST_HEAD est déclarée comme suit :

LIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et TYPE est le type des éléments de la liste. Une adresse de pointeur vers la tête de la liste peut être déclarée ultérieurement comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont choisissables par l'utilisateur.)

La macro LIST_HEAD_INITIALIZER est évaluée comme un initialiseur pour la liste head.

La macro LIST_CONCAT concaténera la liste gérée par head2 à la fin de la liste gérée par head1, en vidant la première. Son utilisation doit être évitée car elle parcourt toute la liste head1. Une file de coda doit être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro LIST_EMPTY renvoie vrai si la liste est vide.

La macro LIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro LIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro LIST_FOREACH parcourt la liste gérée par head dans le sens avant, en assignant chaque élément à var.

EXEMPLE DE LISTE

LIST_HEAD(listhead, entry) head =
    LIST_HEAD_INITIALIZER(head);
struct listhead *headp;			/* Tête de liste. */
struct entry {
	...
	LIST_ENTRY(entry) entries;	/* Liste. */
	...
} *n1, *n2, *n3, *np, *np_temp;

LIST_INIT(&head);			/* Initialise la liste. */

n1 = malloc(sizeof(struct entry));	/* Insertion en tête. */
LIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insertion après. */
LIST_INSERT_AFTER(n1, n2, entries);

n3 = malloc(sizeof(struct entry));	/* Insertion avant. */
LIST_INSERT_BEFORE(n2, n3, entries);

LIST_REMOVE(n2, entries);		/* Suppression. */
free(n2);
					/* Parcours avant. */
LIST_FOREACH(np, &head, entries)
	np-> ...

					/* Parcours avant sécurisé. */
LIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	LIST_REMOVE(np, entries);
	free(np);
}

while (!LIST_EMPTY(&head)) {		/* Suppression de la liste. */
	n1 = LIST_FIRST(&head);
	LIST_REMOVE(n1, entries);
	free(n1);
}

n1 = LIST_FIRST(&head);			/* Suppression de liste plus rapide. */
while (n1 != NULL) {
	n2 = LIST_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
LIST_INIT(&head);

QUEUES À POINTE

Une queue à pointe est dirigée par une structure définie à l'aide de la macro TAILQ_HEAD. Cette structure contient une paire de pointeurs, l'un vers le premier élément de la queue à pointe et l'autre vers le dernier élément de la queue à pointe. Les éléments sont doublement chaînés, permettant la suppression de n'importe quel élément sans parcourir la queue à pointe. Les nouveaux éléments peuvent être ajoutés à la queue à pointe après un élément existant, avant un élément existant, au début de la queue à pointe ou à la fin de la queue à pointe. Une structure TAILQ_HEAD est déclarée comme suit :

TAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et TYPE est le type des éléments chaînés dans la queue à pointe. Un pointeur vers la tête de la queue à pointe peut ensuite être déclaré comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro TAILQ_HEAD_INITIALIZER évalue à un initialiseur pour la queue à pointe head.

La macro TAILQ_CONCAT concaténera la queue à pointe dirigée par head2 à la fin de la queue à pointe dirigée par head1, supprimant tous les éléments de la première.

La macro TAILQ_EMPTY évalue à vrai s'il n'y a aucun élément dans la queue à pointe.

La macro TAILQ_ENTRY déclare une structure qui relie les éléments de la queue à pointe.

La macro TAILQ_FIRST renvoie le premier élément de la queue à pointe ou NULL si la queue à pointe est vide.

La macro TAILQ_FOREACH parcourt la queue à pointe dirigée par head dans la direction forward, assignant chaque élément à var. var est défini à NULL si la boucle se termine normalement ou s'il n'y a aucun élément.

La macro TAILQ_FOREACH_FROM se comporte de manière identique à TAILQ_FOREACH lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans la queue à pointe et commence la boucle à var au lieu du premier élément de la queue à pointe dirigée par head.

La macro TAILQ_FOREACH_REVERSE parcourt la queue à pointe dirigée par head dans la direction inverse, assignant chaque élément à var.

La macro TAILQ_FOREACH_REVERSE_FROM se comporte de manière identique à TAILQ_FOREACH_REVERSE lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans la queue à pointe et commence la boucle inverse à var au lieu du dernier élément de la queue à pointe dirigée par head.

Les macros TAILQ_FOREACH_SAFE et TAILQ_FOREACH_REVERSE_SAFE parcourent la liste dirigée par head dans la direction forward ou reverse respectivement, assignant chaque élément à var. Cependant, contrairement à leurs homologues non sécurisées, TAILQ_FOREACH et TAILQ_FOREACH_REVERSE permettent de supprimer var et de la libérer dans la boucle en toute sécurité sans interférer avec la trajectoire.

La macro TAILQ_FOREACH_FROM_SAFE se comporte de manière identique à TAILQ_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans la queue à pointe et commence la boucle à var au lieu du premier élément de la queue à pointe dirigée par head.

La macro TAILQ_FOREACH_REVERSE_FROM_SAFE se comporte de manière identique à TAILQ_FOREACH_REVERSE_SAFE lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans la queue à pointe et commence la boucle inverse à var au lieu du dernier élément de la queue à pointe dirigée par head.

La macro TAILQ_INIT initialise la queue à pointe dirigée par head.

La macro TAILQ_INSERT_HEAD insère le nouvel élément elm au début de la queue à pointe.

La macro TAILQ_INSERT_TAIL insère le nouvel élément elm à la fin de la queue à pointe.

La macro TAILQ_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro TAILQ_INSERT_BEFORE insère le nouvel élément elm avant l'élément listelm.

La macro TAILQ_LAST renvoie le dernier élément de la queue à pointe. Si la queue à pointe est vide, la valeur renvoyée est NULL.

La macro TAILQ_NEXT renvoie l'élément suivant de la queue à pointe, ou NULL si cet élément est le dernier.

La macro TAILQ_PREV renvoie l'élément précédent de la queue à pointe, ou NULL si cet élément est le premier.

La macro TAILQ_REMOVE supprime l'élément elm de la queue à pointe.

La macro TAILQ_SWAP échange les contenus de head1 et head2.

EXEMPLE DE QUEUE À POINTE

TAILQ_HEAD(tailhead, entry) head =
    TAILQ_HEAD_INITIALIZER(head);
struct tailhead *headp;			/* Tête de queue à pointe. */
struct entry {
	...
	TAILQ_ENTRY(entry) entries;	/* Queue à pointe. */
	...
} *n1, *n2, *n3, *np;

TAILQ_INIT(&head);			/* Initialise la queue. */

n1 = malloc(sizeof(struct entry));	/* Insertion en tête. */

n1 = malloc(sizeof(struct entry));	/* Insertion en fin. */

n2 = malloc(sizeof(struct entry));	/* Insertion après. */

n3 = malloc(sizeof(struct entry));	/* Insertion avant. */
TAILQ_INSERT_BEFORE(n2, n3, entries);

TAILQ_REMOVE(&head, n2, entries);	/* Suppression. */
free(n2);
					/* Parcours avant. */
TAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sécurisé. */
TAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	TAILQ_REMOVE(&head, np, entries);
	free(np);
}
					/* Parcours inverse. */
TAILQ_FOREACH_REVERSE(np, &head, tailhead, entries)
	np-> ...
					/* Suppression de la queue à pointe. */
while (!TAILQ_EMPTY(&head)) {
	n1 = TAILQ_FIRST(&head);
	TAILQ_REMOVE(&head, n1, entries);
	free(n1);
}
					/* Suppression de queue à pointe plus rapide. */
n1 = TAILQ_FIRST(&head);
while (n1 != NULL) {
	n2 = TAILQ_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}

DIAGNOSTICS

Lors du débogage de queue(3), il peut être utile de tracer les modifications apportées à la liste.

Pour activer le traçage, définissez la macro QUEUE_MACRO_DEBUG_TRACE au moment de la compilation.

Il peut également être utile de détruire les pointeurs qui ont été retirés d'une liste, afin de détecter une utilisation après suppression. Pour activer la destruction des pointeurs, définissez la macro QUEUE_MACRO_DEBUG_TRASH au moment de la compilation. La macro QMD_IS_TRASHED(void *ptr) retourne true si le pointeur ptr a été détruit par l'option QUEUE_MACRO_DEBUG_TRASH.
