DESCRIPTION

Ces macros définissent et opèrent sur quatre types de structures de données utilisables à la fois en C et en C++.

  1. Liste
  2. Liste chaînée simplement
  3. Liste chaînée en queue
  4. File
Les quatre structures supportent la fonctionnalité suivante :
  1. Insertion d'un nouvel élément au début de la liste.
  2. Insertion d'un nouvel élément après n'importe quel élément de la liste.
  3. Suppression d'un élément du début de la liste en temps constant.
  4. Parcours avant de la liste.
  5. Échanges de contenu entre deux listes.

Les listes chaînées simplement sont les plus simples des quatre structures de données et ne supportent que la fonctionnalité décrite ci-dessus. Les listes chaînées simplement sont idéales pour les applications avec de grandes quantités de données et peu ou pas de suppressions, ou pour implémenter une pile (LIFO). Les listes chaînées simplement ajoutent la fonctionnalité suivante :

  1. Suppression de n'importe quel élément de la liste en temps O(n).
  2. Connexion de deux listes en temps O(n).

Les listes chaînées en queue ajoutent la fonctionnalité suivante :

  1. Les éléments peuvent être ajoutés à la fin d'une liste.
  2. Suppression de n'importe quel élément de la liste en temps O(n).
  3. Peuvent être concaténées.

Cependant :

  1. Toute insertion dans une liste doit spécifier l'en-tête de la liste.
  2. Chaque en-tête de liste nécessite deux pointeurs au lieu d'un.
  3. La taille du code est approximativement 15% plus grande et les opérations prennent environ 20% plus de temps que dans les listes chaînées simplement.

Les listes chaînées en queue sont idéales pour les applications avec de grandes quantités de données et peu ou pas de suppressions, ou pour implémenter une file (FIFO).

Toutes les structures de données doublement chaînées (listes et files) permettent en plus :

  1. Insertion d'un nouvel élément avant n'importe quel élément de la liste.
  2. Suppression de n'importe quel élément de la liste en temps O(1).

Cependant :

  1. Chaque élément nécessite deux pointeurs au lieu d'un.
  2. La taille du code et le temps d'exécution des opérations (sauf pour la suppression) sont environ le double de ceux des structures de données simplement chaînées.

Les listes chaînées sont les plus simples des structures de données doublement chaînées. Elles ajoutent la fonctionnalité suivante par rapport à celles mentionnées ci-dessus :

  1. Connexion de deux listes en temps O(n).
  2. Peuvent être parcourues en sens inverse.

Cependant :

  1. Pour parcourir en sens inverse, un élément de départ de parcours et la liste dans laquelle cet élément se trouve doivent être spécifiés.

Les files ajoutent la fonctionnalité suivante :

  1. Les éléments peuvent être ajoutés à la fin d'une liste.
  2. Peuvent être parcourues en sens inverse, de la fin vers le début.
  3. Peuvent être concaténées.

Cependant :

  1. Toute insertion ou suppression dans une liste doit spécifier l'en-tête de la liste.
  2. Chaque en-tête de liste nécessite deux pointeurs au lieu d'un.
  3. La taille du code est approximativement 15% plus grande et les opérations prennent environ 20% plus de temps que dans les listes chaînées simplement.

Dans les définitions de macros, TYPE est le nom d'une structure définie par l'utilisateur. La structure doit contenir un champ nommé NAME de type SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY ou TAILQ_ENTRY. Dans les définitions de macros, CLASSTYPE est le nom d'une classe définie par l'utilisateur. La classe doit contenir un champ nommé NAME de type SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY ou TAILQ_CLASS_ENTRY. L'argument HEADNAME est le nom d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD ou TAILQ_CLASS_HEAD. Voir les exemples ci-dessous pour une explication supplémentaire de l'utilisation de ces macros.

LISTES CHAÎNÉES SIMPLEMENT

Une liste chaînée simplement est dirigée par une structure définie via la macro SLIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont chaînés simplement pour minimiser l'espace et la surcharge de manipulation des pointeurs, bien que cela se fasse au prix de O(n) pour la suppression d'éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant ou au début de la liste. Une structure SLIST_HEAD est déclarée ainsi :

SLIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et TYPE est le type des éléments de la liste. Une adresse de pointeur vers l'en-tête de la liste peut être déclarée plus tard ainsi :

struct HEADNAME *headp;

(Les noms head et headp sont choisissables par l'utilisateur.)

La macro SLIST_HEAD_INITIALIZER évalue à un initialiseur pour la liste head.

La macro SLIST_CONCAT concaténera la liste dirigée par head2 à la fin de la liste dirigée par head1, vidant la première. Son utilisation doit être évitée dans les chemins de code fréquemment exécutés ou lors de l'opération sur de longues listes. Une liste chaînée en queue doit être utilisée dans de tels cas.

La macro SLIST_EMPTY évalue à vrai si la liste ne contient aucun élément.

La macro SLIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro SLIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro SLIST_FOREACH parcourt la liste référencée par head dans le sens avant, affectant chaque élément à var.

La macro SLIST_FOREACH_FROM fonctionne de manière identique à SLIST_FOREACH lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans la liste référencée par head et commence la boucle à partir de var au lieu du premier élément de la liste référencée par head.

La macro SLIST_FOREACH_SAFE parcourt la liste référencée par head dans le sens avant, affectant chaque élément à var. Cependant, comme SLIST_FOREACH(), il est permis de supprimer var et de le libérer à l'intérieur de la boucle en toute sécurité sans interférer avec le parcours.

La macro SLIST_FOREACH_FROM_SAFE fonctionne de manière identique à SLIST_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans la liste référencée par head et commence la boucle à partir de var au lieu du premier élément de la liste référencée par head.

La macro SLIST_INIT initialise la liste référencée par head.

La macro SLIST_INSERT_HEAD insère le nouvel élément elm au début de la liste.

La macro SLIST_INSERT_AFTER insère le nouvel élément elm après l'élément listelm dans la liste.

La macro SLIST_INIT initialise la liste référencée par head.

s="Fa">listelm.

La macro SLIST_NEXT renvoie le suivant élément de la liste.

La macro SLIST_REMOVE_AFTER supprime l'élément après elm de la liste. Contrairement à SLIST_REMOVE, cette macro ne parcourt pas la liste entière.

La macro SLIST_REMOVE_HEAD supprime l'élément elm de la tête de la liste. Pour une efficacité optimale, les éléments supprimés de la tête de la liste devraient utiliser explicitement cette macro plutôt que la macro générique SLIST_REMOVE.

La macro SLIST_REMOVE supprime l'élément elm de la liste. L'utilisation de cette macro devrait être évitée car elle parcourt la liste entière. Une liste doublement chaînée devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro SLIST_SWAP échange le contenu de head1 et head2.

EXEMPLE DE LISTE SIMPLEMENT CHAÎNEE

SLIST_HEAD(slisthead, entry) head =
    SLIST_HEAD_INITIALIZER(head);
struct slisthead *headp;		/* Tête de liste simplement chaînée. */
struct entry {
	...
	SLIST_ENTRY(entry) entries;	/* Liste simplement chaînée. */
	...
} *n1, *n2, *n3, *np;

SLIST_INIT(&head);			/* Initialiser la liste. */

n1 = malloc(sizeof(struct entry));	/* Insérer en tête. */
SLIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
SLIST_INSERT_AFTER(n1, n2, entries);

SLIST_REMOVE(&head, n2, entry, entries);/* Suppression. */
free(n2);

n3 = SLIST_FIRST(&head);
SLIST_REMOVE_HEAD(&head, entries);	/* Suppression de la tête. */
free(n3);
					/* Parcours avant. */
SLIST_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sûr. */
SLIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	SLIST_REMOVE(&head, np, entry, entries);
	free(np);
}

while (!SLIST_EMPTY(&head)) {		/* Suppression de liste. */
	n1 = SLIST_FIRST(&head);
	SLIST_REMOVE_HEAD(&head, entries);
	free(n1);
}

FILES D'ATTENTE SIMPLEMENT CHAÎNÉES

Une file d'attente simplement chaînée est dirigée par une structure définie par la macro STAILQ_HEAD. Cette structure contient une paire de pointeurs, l'un vers le premier élément de la file d'attente et l'autre vers le dernier élément de la file d'attente. Les éléments sont chaînés simplement pour une surcharge minimale d'espace et de manipulation de pointeurs, au prix d'une suppression en O(n) pour les éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la file d'attente après un élément existant, en tête de la file d'attente ou à la fin de la file d'attente. Une structure STAILQ_HEAD est déclarée comme suit :

STAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à chaîner dans la file d'attente. Un pointeur vers la tête de la file d'attente peut ensuite être déclaré comme :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro STAILQ_HEAD_INITIALIZER évalue à un initialiseur pour la file d'attente head.

La macro STAILQ_CONCAT concatène la file d'attente dirigée par head2 à la fin de celle dirigée par head1, supprimant toutes les entrées de la première.

La macro STAILQ_EMPTY évalue à vrai s'il n'y a aucun élément dans la file d'attente.

La macro STAILQ_ENTRY déclare une structure qui connecte les éléments dans la file d'attente.

La macro STAILQ_FIRST renvoie le premier élément de la file d'attente ou NULL si la file d'attente est vide.

La macro STAILQ_FOREACH parcourt la file d'attente référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var.

La macro STAILQ_FOREACH_FROM se comporte identiquement à STAILQ_FOREACH lorsque var est NULL, sinon elle traite var comme un élément STAILQ trouvé précédemment et commence la boucle à var au lieu du premier élément de la STAILQ référencée par head.

La macro STAILQ_FOREACH_SAFE parcourt la file d'attente référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var. Cependant, contrairement à STAILQ_FOREACH(), il est permis ici de supprimer var ainsi que de le libérer depuis l'intérieur de la boucle en toute sécurité sans interférer avec le parcours.

La macro STAILQ_FOREACH_FROM_SAFE se comporte identiquement à STAILQ_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément STAILQ trouvé précédemment et commence la boucle à var au lieu du premier élément de la STAILQ référencée par head.

La macro STAILQ_INIT initialise la file d'attente référencée par head.

La macro STAILQ_INSERT_HEAD insère le nouvel élément elm en tête de la file d'attente.

La macro STAILQ_INSERT_TAIL insère le nouvel élément elm à la fin de la file d'attente.

La macro STAILQ_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro STAILQ_LAST renvoie le dernier élément de la file d'attente. Si la file d'attente est vide, la valeur renvoyée est NULL.

La macro STAILQ_NEXT renvoie le prochain élément de la file d'attente, ou NULL si cet élément est le dernier.

La macro STAILQ_REMOVE_AFTER supprime l'élément après elm de la file d'attente. Contrairement à STAILQ_REMOVE, cette macro ne parcourt pas toute la file d'attente.

La macro STAILQ_REMOVE_HEAD supprime l'élément en tête de la file d'attente. Pour une efficacité optimale, les éléments supprimés de la tête de la file d'attente devraient utiliser explicitement cette macro plutôt que la macro générique STAILQ_REMOVE.

La macro STAILQ_REMOVE supprime l'élément elm de la file d'attente. L'utilisation de cette macro devrait être évitée car elle parcourt toute la liste. Une file d'attente doublement chaînée devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues files d'attente.

La macro STAILQ_SWAP échange le contenu de head1 et head2.

EXEMPLE DE FILE D'ATTENTE SIMPLEMENT CHAÎNEE

STAILQ_HEAD(stailhead, entry) head =
    STAILQ_HEAD_INITIALIZER(head);
struct stailhead *headp;		/* Tête de file d'attente simplement chaînée. */
struct entry {
	...
	STAILQ_ENTRY(entry) entries;	/* File d'attente. */
	...
} *n1, *n2, *n3, *np;

STAILQ_INIT(&head);			/* Initialiser la file d'attente. */

n1 = malloc(sizeof(struct entry));	/* Insérer en tête. */
STAILQ_INSERT_HEAD(&head, n1, entries);

n1 = malloc(sizeof(struct entry));	/* Insérer à la fin. */
STAILQ_INSERT_TAIL(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
STAILQ_INSERT_AFTER(&head, n1, n2, entries);
					/* Suppression. */
STAILQ_REMOVE(&head, n2, entry, entries);
free(n2);
					/* Suppression de la tête. */
n3 = STAILQ_FIRST(&head);
STAILQ_REMOVE_HEAD(&head, entries);
free(n3);
					/* Parcours avant. */
STAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sûr. */
STAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	STAILQ_REMOVE(&head, np, entry, entries);
	free(np);
}
					/* Suppression de la file d'attente. */
while (!STAILQ_EMPTY(&head)) {
	n1 = STAILQ_FIRST(&head);
	STAILQ_REMOVE_HEAD(&head, entries);
	free(n1);
}
					/* Suppression plus rapide de la file d'attente. */
n1 = STAILQ_FIRST(&head);
while (n1 != NULL) {
	n2 = STAILQ_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
STAILQ_INIT(&head);

LISTES

Une liste est dirigée par une structure définie par la macro LIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont doublement chaînés afin qu'un élément arbitraire puisse être supprimé sans parcourir la liste. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant, avant un élément existant, ou en tête de la liste. Une structure LIST_HEAD est déclarée comme suit :

LIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à chaîner dans la liste. Un pointeur vers la tête de la liste peut ensuite être déclaré comme :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro LIST_HEAD_INITIALIZER évalue à un initialiseur pour la liste head.

La macro LIST_CONCAT concatène la liste dirigée par head2 à la fin de celle dirigée par head1, supprimant toutes les entrées de la première. L'utilisation de cette macro devrait être évitée car elle parcourt l'intégralité de la liste head1. Une file d'attente devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro LIST_EMPTY évalue à vrai s'il n'y a aucun élément dans la liste.

La macro LIST_ENTRY déclare une structure qui connecte les éléments dans la liste.

La macro LIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro LIST_FOREACH parcourt la liste référencée par head /var> dans la direction avant, assignant chaque élément tour à tour à var.

La macro LIST_FOREACH_FROM se comporte identiquement à LIST_FOREACH lorsque var est NULL, sinon elle traite var comme un élément LIST précédemment trouvé et commence la boucle à var au lieu du premier élément de la LIST référencée par head.

La macro LIST_FOREACH_SAFE parcourt la liste référencée par head dans la direction avant, assignant chaque élément tour à tour à var. Cependant, contrairement à LIST_FOREACH(), elle permet ici de supprimer var ainsi que de le libérer depuis la boucle en toute sécurité sans interférer avec le parcours.

La macro LIST_FOREACH_FROM_SAFE se comporte identiquement à LIST_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément LIST précédemment trouvé et commence la boucle à var au lieu du premier élément de la LIST référencée par head.

La macro LIST_INIT initialise la liste référencée par head.

La macro LIST_INSERT_HEAD insère le nouvel élément elm à la tête de la liste.

La macro LIST_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro LIST_INSERT_BEFORE insère le nouvel élément elm avant l'élément listelm.

La macro LIST_NEXT retourne l'élément suivant de la liste, ou NULL s'il s'agit du dernier.

La macro LIST_PREV retourne l'élément précédent de la liste, ou NULL s'il s'agit du premier. La liste head doit contenir l'élément elm.

La macro LIST_REMOVE retire l'élément elm de la liste.

La macro LIST_SWAP échange le contenu de head1 et head2.

EXEMPLE LIST

LIST_HEAD(listhead, entry) head =
    LIST_HEAD_INITIALIZER(head);
struct listhead *headp;			/* Tête de liste. */
struct entry {
	...
	LIST_ENTRY(entry) entries;	/* Liste. */
	...
} *n1, *n2, *n3, *np, *np_temp;

LIST_INIT(&head);			/* Initialiser la liste. */

n1 = malloc(sizeof(struct entry));	/* Insérer à la tête. */
LIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
LIST_INSERT_AFTER(n1, n2, entries);

n3 = malloc(sizeof(struct entry));	/* Insérer avant. */
LIST_INSERT_BEFORE(n2, n3, entries);

LIST_REMOVE(n2, entries);		/* Suppression. */
free(n2);
					/* Parcours avant. */
LIST_FOREACH(np, &head, entries)
	np-> ...

					/* Parcours avant sécurisé. */
LIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->faire_quelque_chose();
	...
	LIST_REMOVE(np, entries);
	free(np);
}

while (!LIST_EMPTY(&head)) {		/* Suppression de liste. */
	n1 = LIST_FIRST(&head);
	LIST_REMOVE(n1, entries);
	free(n1);
}

n1 = LIST_FIRST(&head);			/* Suppression de liste plus rapide. */
while (n1 != NULL) {
	n2 = LIST_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
LIST_INIT(&head);

FILES D'ATTENTE À EXTÉMITÉ

Une file d'attente à extrémité est dirigée par une structure définie par la macro TAILQ_HEAD. Cette structure contient une paire de pointeurs, l'un vers le premier élément de la file d'attente à extrémité et l'autre vers le dernier élément de la file d'attente à extrémité. Les éléments sont doublement chaînés de sorte qu'un élément arbitraire puisse être retiré sans parcourir la file d'attente à extrémité. De nouveaux éléments peuvent être ajoutés à la file d'attente à extrémité après un élément existant, avant un élément existant, à la tête de la file d'attente à extrémité, ou à la fin de la file d'attente à extrémité. Une structure TAILQ_HEAD est déclarée comme suit :

TAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la file d'attente à extrémité. Un pointeur vers la tête de la file d'attente à extrémité peut ensuite être déclaré comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro TAILQ_HEAD_INITIALIZER évalue à un initialiseur pour la file d'attente à extrémité head.

La macro TAILQ_CONCAT concatène la file d'attente à extrémité dirigée par head2 à la fin de celle dirigée par head1, en retirant toutes les entrées de la première.

La macro TAILQ_EMPTY évalue à vrai s'il n'y a pas d'éléments dans la file d'attente à extrémité.

La macro TAILQ_ENTRY déclare une structure qui connecte les éléments de la file d'attente à extrémité.

La macro TAILQ_FIRST retourne le premier élément de la file d'attente à extrémité ou NULL si la file d'attente à extrémité est vide.

La macro TAILQ_FOREACH parcourt la file d'attente à extrémité référencée par head dans la direction avant, assignant chaque élément tour à tour à var. var est mis à NULL si la boucle se termine normalement, ou s'il n'y avait aucun élément.

La macro TAILQ_FOREACH_FROM se comporte identiquement à TAILQ_FOREACH lorsque var est NULL, sinon elle traite var comme un élément TAILQ précédemment trouvé et commence la boucle à var au lieu du premier élément de la TAILQ référencée par head.

La macro TAILQ_FOREACH_REVERSE parcourt la file d'attente à extrémité référencée par head dans la direction inverse, assignant chaque élément tour à tour à var.

La macro TAILQ_FOREACH_REVERSE_FROM se comporte identiquement à TAILQ_FOREACH_REVERSE lorsque var est NULL, sinon elle traite var comme un élément TAILQ précédemment trouvé et commence la boucle inverse à var au lieu du dernier élément de la TAILQ référencée par head.

Les macros TAILQ_FOREACH_SAFE et TAILQ_FOREACH_REVERSE_SAFE parcourent la liste référencée par head dans la direction avant ou inverse respectivement, assignant chaque élément tour à tour à var. Cependant, contrairement à leurs homologues non sécurisés, TAILQ_FOREACH et TAILQ_FOREACH_REVERSE permettent de supprimer var ainsi que de le libérer depuis la boucle en toute sécurité sans interférer avec le parcours.

La macro TAILQ_FOREACH_FROM_SAFE se comporte identiquement à TAILQ_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément TAILQ précédemment trouvé et commence la boucle à var au lieu du premier élément de la TAILQ référencée par head.

La macro TAILQ_FOREACH_REVERSE_FROM_SAFE se comporte identiquement à TAILQ_FOREACH_REVERSE_SAFE lorsque var est NULL, sinon elle traite var comme un élément TAILQ précédemment trouvé et commence la boucle inverse à var au lieu du dernier élément de la TAILQ référencée par head.

La macro TAILQ_INIT initialise la file d'attente à extrémité référencée par head.

La macro TAILQ_INSERT_HEAD insère le nouvel élément elm à la tête de la file d'attente à extrémité.

La macro TAILQ_INSERT_TAIL insère le nouvel élément elm à la fin de la file d'attente à extrémité.

La macro TAILQ_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro TAILQ_INSERT_BEFORE insère le nouvel élément elm avant l'élément listelm.

La macro TAILQ_LAST retourne le dernier élément de la file d'attente à extrémité. Si la file d'attente à extrémité est vide, la valeur de retour est NULL.

La macro TAILQ_NEXT retourne l'élément suivant de la file d'attente à extrémité, ou NULL si cet élément est le dernier.

La macro TAILQ_PREV retourne l'élément précédent de la file d'attente à extrémité, ou NULL si cet élément est le premier.

La macro TAILQ_REMOVE retire l'élément elm de la file d'attente à extrémité.

La macro TAILQ_SWAP échange le contenu de head1 et head2.

EXEMPLE DE FILE D'ATTENTE À EXTÉMITÉ

TAILQ_HEAD(tailhead, entry) head =
    TAILQ_HEAD_INITIALIZER(head);
struct tailhead *headp;			/* Tête de file d'attente à extrémité. */
struct entry {
	...
	TAILQ_ENTRY(entry) entries;	/* File d'attente à extrémité. */
	...
} *n1, *n2, *n3, *np;

TAILQ_INIT(&head);			/* Initialiser la file d'attente. */

n1 = malloc(sizeof(struct entry));	/* Insérer à la tête. */
TAILQ_INSERT_HEAD(&head, n1, entries);

n1 = malloc(sizeof(struct entry));	/* Insérer à la fin. */
TAILQ_INSERT_TAIL(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
TAILQ_INSERT_AFTER(&head, n1, n2, entries);

n3 = malloc(sizeof(struct entry));	/* Insérer avant. */
TAILQ_INSERT_BEFORE(n2, n3, entries);

TAILQ_REMOVE(&head, n2, entries);	/* Suppression. */
free(n2);
					/* Parcours avant. */
TAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sécurisé. */
TAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->faire_quelque_chose();
	...
	TAILQ_REMOVE(&head, np, entries);
	free(np);
}
					/* Parcours inverse. */
TAILQ_FOREACH_REVERSE(np, &head, tailhead, entries)
	np-> ...
					/* Suppression de file d'attente à extrémité. */
while (!TAILQ_EMPTY(&head)) {
	n1 = TAILQ_FIRST(&head);
	TAILQ_REMOVE(&head, n1, entries);
	free(n1);
}
					/* Suppression de file d'attente à extrémité plus rapide. */
n1 = TAILQ_FIRST(&head);
while (n1 != NULL) {
	n2 = TAILQ_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
TAILQ_INIT(&head);

DIAGNOSTICS

Lors du débogage de queue(3), il peut être utile de tracer les changements de file d'attente. Pour activer le traçage, définissez la macro QUEUE_MACRO_DEBUG_TRACE au moment de la compilation.

Il peut également être utile de corrompre les pointeurs qui ont été désolidarisés d'une file d'attente, afin de détecter une utilisation après suppression. Pour activer la corruption de pointeurs, définissez la macro QUEUE_MACRO_DEBUG_TRASH au moment de la compilation. La macro QMD_IS_TRASHED(void *ptr) renvoie vrai si ptr a été corrompu par l'option QUEUE_MACRO_DEBUG_TRASH.
