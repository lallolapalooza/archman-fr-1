NOM

Locale::Po4a::TeX — convertir des documents TeX et dérivés à partir de fichiers PO

DESCRIPTION

Le projet po4a (PO pour tout) vise à faciliter les traductions (et plus intéressant, la maintenance des traductions) en utilisant les outils gettext dans des domaines où on ne les attendait pas, comme la documentation.

Locale::Po4a::TeX est un module pour aider à la traduction de documents TeX vers d'autres [langues humaines]. Il peut également être utilisé comme base pour construire des modules pour des documents TeX.

Les utilisateurs devraient probablement utiliser le module LaTeX, qui hérite de ce module et contient les définitions des commandes LaTeX courantes.

TRADUCTION AVEC PO4A::TEX

Ce module peut être utilisé directement pour gérer des documents TeX génériques. Il divisera votre document en petits blocs (paragraphes, blocs verbatim, ou même plus petits comme des titres ou des tables des matières).

Il y a quelques options (décrites dans la section suivante) qui peuvent personnaliser ce comportement. Si cela ne correspond pas à votre format de document, nous vous encourageons à écrire votre propre module qui hérite de celui-ci, afin de décrire les détails de votre format. Voir la section ÉCRIRE DES MODULES DÉRIVÉS ci-dessous, pour une description du processus.

Ce module peut également être personnalisé par des lignes commençant par "% po4a:" dans le fichier TeX. Ce processus est décrit dans la section PERSONNALISATION EN LIGNE.

OPTIONS ACCEPTÉES PAR CE MODULE

Ce sont les options particulières de ce module :

debug
Active le débogage de certains mécanismes internes de ce module. Utilisez le code source pour voir quelles parties peuvent être déboguées.
no_wrap
Liste séparée par des virgules d'environnements qui ne doivent pas être ré-encapsulés.

Notez qu'il existe une différence entre verbatim et no_wrap. Il n'y a pas d'analyse de commandes et de commentaires dans les blocs verbatim.

Si cet environnement n'était pas déjà enregistré, po4a considérera que cet environnement ne prend pas de paramètres.

exclude_include
Liste séparée par des deux-points de fichiers qui ne doivent pas être inclus par \input et \include.
definitions
Nom d'un fichier contenant des définitions pour po4a, comme décrit dans la section PERSONNALISATION EN LIGNE. Vous pouvez utiliser cette option s'il n'est pas possible de placer les définitions dans le document en cours de traduction.
verbatim
Liste séparée par des virgules d'environnements qui doivent être considérés comme verbatim.

Si cet environnement n'était pas déjà enregistré, po4a considérera que cet environnement ne prend pas de paramètres.

Utilisez ces options pour remplacer le comportement par défaut des commandes définies.

PERSONNALISATION EN LIGNE

Le module TeX peut être personnalisé par des lignes commençant par % po4a: . Ces lignes sont interprétées comme des commandes pour l'analyseur. Les commandes suivantes sont reconnues :

% po4a: command command1 alias command2
Indique que les arguments de command1 doivent être traités comme les arguments de command2.
% po4a: command command1 parameters
Décrit en détail les paramètres de command1. Ces informations seront utilisées pour vérifier le nombre d'arguments et leur type.

Vous pouvez précéder command1 d'un

astérisque (*)
po4a extraira cette commande des paragraphes (si elle est au début ou à la fin d'un paragraphe). Les traducteurs devront traduire les paramètres marqués comme traduisibles.
plus (+)
Comme dans le cas d'un astérisque, la commande sera extraite si elle apparaît à une extrémité d'un bloc, mais les paramètres ne seront pas traduits séparément. Le traducteur devra traduire la commande concaténée à tous ses paramètres. Cela conserve plus de contexte et est utile pour les commandes avec des mots courts en paramètre, qui peuvent avoir plusieurs significations (et traductions).

Note : Dans ce cas, vous n'avez pas besoin de spécifier quels paramètres sont traduisibles, mais po4a doit connaître le type et le nombre de paramètres.

un moins (-)
Dans ce cas, la commande ne sera extraite d'aucun bloc. Mais si elle apparaît seule dans un bloc, seuls les paramètres marqués comme traduisibles seront présentés au traducteur. Ceci est utile pour les commandes de police. Ces commandes ne doivent généralement pas être séparées de leur paragraphe (pour conserver le contexte), mais il n'y a aucune raison de déranger le traducteur avec elles si une chaîne entière est encapsulée dans une telle commande.

Les paramètres parameters est une liste de [] (pour un argument optionnel) ou {} (pour un argument obligatoire). Vous pouvez placer un _ (underscore) entre ces parenthèses pour indiquer que le paramètre doit être traduit. Par exemple :
% po4a: command *chapter [_]{_}

Cela indique que la commande chapter a deux paramètres : un optionnel (titre court) et un obligatoire, tous deux doivent être traduits. Si vous voulez indiquer que la commande href a deux paramètres obligatoires, que vous ne voulez pas traduire l'URL (premier paramètre) et que vous ne voulez pas que cette commande soit séparée de son paragraphe (ce qui permet au traducteur de déplacer le lien dans la phrase), vous pouvez utiliser :
% po4a: command -href {}{_}

Dans ce cas, l'information indiquant quels paramètres doivent être traduits ne sera utilisée que si le paragraphe est composé uniquement de cette commande href.

% po4a: environment env parameters
Définit les paramètres acceptés par l'environnement env et spécifie ceux qui doivent être traduits. Ces informations seront utilisées plus tard pour vérifier le nombre d'arguments de la commande \begin. Le format des paramètres parameters est le même que celui décrit pour les autres commandes. Le premier argument de la commande \begin est le nom de l'environnement. Ce paramètre ne doit pas être spécifié dans la liste des paramètres. Voici quelques exemples :
% po4a: environment multicols {}
% po4a: environment equation

Comme pour les commandes, env peut être précédé d'un + (+) pour indiquer que la commande \begin doit être traduite avec tous ses arguments.

% po4a: separator env "regex"
Indique qu'un environnement doit être divisé selon le motif régulier spécifié.

Le motif régulier est délimité par des guillemets. Il faut garder à l'esprit que le motif est utilisé pour séparer les environnements.

NOM

PO4A::TEX

DESCRIPTION

PO4A::TEX est un module qui fournit des capacités de traduction pour les documents TeX. Il permet aux utilisateurs de traduire du texte en utilisant le format PO (Portable Object), couramment utilisé dans les documents LaTeX.

TRADUCTION AVEC PO4A::TEX

PO4A::TEX permet aux utilisateurs de traduire du texte dans des documents TeX en utilisant le format PO. Ce module fournit des outils pour manipuler les fichiers PO et traduire le contenu dans différentes langues.

OPTIONS ACCEPTÉES PAR CE MODULE

Ce module accepte plusieurs options pour personnaliser son comportement. Ces options peuvent être utilisées pour contrôler la manière dont le module traite les fichiers PO et traduit le contenu.

PERSONNALISATION EN LIGNE

La personnalisation en ligne permet aux utilisateurs de modifier le comportement du module en ajoutant des directives personnalisées au fichier PO. Ces directives peuvent être utilisées pour personnaliser le processus de traduction.

ÉCRITURE DE MODULES DÉRIVÉS

Les modules dérivés sont des modules qui étendent les fonctionnalités du module principal. Ces modules peuvent être écrits pour fournir des capacités de traduction supplémentaires ou pour personnaliser le processus de traduction.

FONCTIONS INTERNES utilisées pour écrire des analyseurs dérivés

Ce module fournit des fonctions internes utilisées pour écrire des analyseurs dérivés. Ces fonctions sont responsables de l'analyse et de la traduction du contenu selon des directives spécifiques.

ÉTAT DE CE MODULE

Ce module est en cours de développement et n'a pas été entièrement testé. Il peut contenir des bogues ou des fonctionnalités incomplètes.

Locale::Po4a::TeX(3pm)

NOM

Locale::Po4a::TeX - Traduction de documents TeX

SYNOPIS

use Locale::Po4a::TeX;

DESCRIPTION

Locale::Po4a::TeX est une classe qui permet de traduire des documents TeX en utilisant le système po4a. Elle gère la structure spécifique des fichiers TeX et s'assure que la traduction est effectuée correctement tout en préservant la mise en forme.

OPTIONS

Cette classe ne propose pas d'options spécifiques directement. Les options sont généralement gérées par l'outil principal de po4a.

EXEMPLE

Pour traduire un document TeX, vous utiliseriez généralement la commande po4a de la manière suivante : 

                    po4a-translate --format tex --language fr mon_document.tex

Cela générera un fichier mon_document.po contenant les chaînes à traduire, et après traduction, vous pourrez reconstruire le document en français.
