W3CExtendedLog(3pm) Documentation Lire pour LogReport W3CExtendedLog(3pm)

NOM

Lire::W3CExtendedLog - Implémentation de base d'un analyseur de journal W3C Extended

SYNTAXE

use Lire::W3CExtendedLog;

my $parser = new Lire::W3CExtendedLog;

my $w3c_rec = $parser->parse( $line );

DESCRIPTION

Ce module définit des objets capables d'analyser le format W3C Extended Log. Ce format de journal est défini dans http://www.w3.org/TR/WD-logfile.html

Tous les attributs de l'objet créé peuvent être redéfinis par, par exemple, des modules qui étendent l'objet. Les attributs sont :

type2regex

type2regex est une table de hachage contenant des paires clé-valeur telles que

'name' => '([-_.0-9a-zA-Z]+)'

Les clés sont tous les formats de données pour les entrées de champ de fichier journal tels que définis dans la spécification W3C : 'integer', 'fixed', 'uri', 'date', 'time' et 'string', ainsi que les types 'name' et 'address'.

identifier2type

identifier2type est une table de hachage contenant des paires clé-valeur telles que

'dns'        => 'name',
'uri-query'  => 'uri',
'ip'         =>

Les clés sont les identifiants de champ définis par le W3C, sans leurs préfixes.

field2re

field2re est une sous-routine ; appelée comme ceci :

$self->{field2re('c-ip')}

elle retournera par exemple :

'(\d+\.\d+\.\d+\.\d+|-)'

Les arguments sont tels que trouvés dans la directive Fields, donc, dans un monde idéal, devraient être des identifiants. Elle utilise type2regex.

field2decoder

field2decoder est une sous-routine ; elle retourne soit \&uri_decode , \&string_decode , soit undef, selon, entre autres, is_iis. Elle est utilisée par build_parser.

parse

parse est l'interface préférée de ce module. Elle attend une ligne comme argument, et retourne une référence vers une table de hachage (comme &w3c_parser), ou exécute &parse_directive.

parse_directive

parse_directive attend une directive dans son argument, elle remplit l'objet.

w3c_parser

w3c_parser est une sous-routine ; elle attend une ligne de journal comme argument, et retourne une référence vers une table de hachage, mappant les entrées de $self->{'fields'} à leurs valeurs décodées. Elle utilise les sous-routines &field2re et &field2decoder. Elle est construite dans build_parser.

build_parser

build_parser est une sous-routine, elle construit et retourne &w3c_parser. Elle est appelée dans &parse_directive.

log_date et log_time

log_date et log_time contiennent des chaînes construites à partir de la directive Date.

version et sofware

version et software contiennent des chaînes construites à partir des directives Version et Software, respectivement.

fields

fields contient la chaîne entière de la directive Fields.

is_iis

is_iis est défini si la directive Software contient 'Microsoft Internet' comme sous-chaîne. Il est utilisé pour activer le support spécifique IIS.

tab_sep

tab_sep est défini si des tabulations sont trouvées dans la directive Fields. Nous supposons qu'elles seront également utilisées dans le journal lui-même, et autorisons les espaces non échappés dans le journal.

En résumé :

&parse --appelle--> &parse_directive
       `--appelle--> &w3c_parser
&parse_directive --appelle--> &build_parser
&build_parser --appelle--> &field2decoder
             `--appelle--> &field2re
             `--retourne--> &w3c_parser
&field2decoder --retourne--> &uri_decode, &string_decode
&field2re --utilise--> %type2regex
          `--utilise--> %identifier2type
