DESCRIPTION

The queue.h header defines four types of list macros: singly-linked lists (SLIST_ macros), singly-linked tail queues (STAILQ_ macros), doubly-linked lists (LIST_ macros), and doubly-linked tail queues (TAILQ_ macros). Tail queues are like lists, but they also maintain a pointer to the tail element, allowing for constant time insertion at the end of the queue.

Each type of list requires two macros to be defined for each data type that is to be placed in a list. The first macro is TYPE_ENTRY(TYPE), which defines the structure that will hold the element in the list. The second macro is HEAD(HEADNAME, TYPE), which defines the head of the list. HEAD defines a structure that contains pointers to the first and last elements of the list. For tail queues, the head structure also contains a pointer to the tail element.

To use these macros, you must first define the macros TYPE_ENTRY(TYPE) and HEAD(HEADNAME, TYPE), then declare variables of these types. For example:

  • SLIST_ENTRY(mydata);

  • SLIST_HEAD(mydata_list, mydata);

  • struct mydata_list my_list;

  • struct mydata_entry { ... };

  • struct mydata { struct mydata_entry list_entry; ... };

The macros starting with SLIST_ manipulate singly-linked lists. The macros starting with STAILQ_ manipulate singly-linked tail queues. The macros starting with LIST_ manipulate doubly-linked lists. The macros starting with TAILQ_ manipulate doubly-linked tail queues.

In the synopsis, TYPE is the name of the data structure that will be stored in the list, and NAME is the name of the field within that structure that holds the list pointer. HEADNAME is the name to be given to the list head structure.

The _CLASS_ENTRY and _CLASS_HEAD macros are used when defining list entry and head structures within a class. They are functionally equivalent to _ENTRY and _HEAD, respectively.

The macros are as follows:

SLIST_HEAD(HEADNAME, TYPE)
Defines a singly-linked list head named HEADNAME. The list elements are of type TYPE.
SLIST_ENTRY(TYPE)
Defines a singly-linked list entry. The entry should be embedded in the TYPE structure.
SLIST_HEAD_INITIALIZER(head)
Returns an initializer for a list head.
SLIST_INIT(head)
Initializes an empty list head.
SLIST_INSERT_HEAD(head, elm, name)
Inserts the element elm at the head of the list head. name is the name of the list entry field in the elm structure.
SLIST_INSERT_AFTER(listelm, elm, name)
Inserts the element elm after the element listelm in the list. name is the name of the list entry field.
SLIST_REMOVE(head, elm, type, name)
Removes the element elm from the list head. type is the name of the element type, and name is the name of the list entry field.
SLIST_REMOVE_HEAD(head, name)
Removes the head element from the list head. name is the name of the list entry field.
SLIST_FIRST(head)
Returns the first element in the list head.
SLIST_NEXT(elm, name)
Returns the next element after elm in the list. name is the name of the list entry field.
SLIST_EMPTY(head)
Returns true if the list head is empty.
SLIST_FOREACH(var, head, name)
Iterates through the list head, assigning each element to var. name is the name of the list entry field.
SLIST_FOREACH_SAFE(var, head, name, temp_var)
Similar to SLIST_FOREACH, but safe for removal of elements during iteration. temp_var is used to temporarily store the next element.
SLIST_FOREACH_FROM(var, head, name)
Iterates through the list head starting from the element var.
SLIST_FOREACH_FROM_SAFE(var, head, name, temp_var)
Similar to SLIST_FOREACH_FROM, but safe for removal of elements during iteration.
SLIST_SWAP(head1, head2, type)
Swaps the contents of two list heads.
SLIST_CONCAT(head1, head2, type, name)
Concatenates list head2 to the end of list head1.

DESCRIPTION

Ces macros définissent et opèrent sur quatre types de structures de données utilisables en C et C++ :

  1. Listes
  2. Listes chaînées simples
  3. Listes chaînées doublement
  4. Files
Les quatre structures supportent la fonctionnalité suivante :
  1. Insertion d'un nouvel élément au début de la liste.
  2. Insertion d'un nouvel élément après n'importe quel élément de la liste.
  3. Suppression d'un élément du début de la liste en O(1).
  4. Parcours avant de la liste.
  5. Échange du contenu de deux listes.

Les listes chaînées simples sont les plus simples des quatre structures de données et ne supportent que la fonctionnalité mentionnée. Les listes chaînées simples sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une pile LIFO. Les listes chaînées simples ajoutent la fonctionnalité suivante :

  1. Suppression de n'importe quel élément de la liste en O(n).
  2. Concaténation de deux listes en O(n).

Les listes chaînées doublement ajoutent la fonctionnalité suivante :

  1. On peut ajouter un élément à la fin d'une liste.
  2. Suppression de n'importe quel élément de la liste en O(n).
  3. Elles peuvent être concaténées.
Mais :
  1. Toute insertion dans une liste doit spécifier l'en-tête de la liste.
  2. Chaque entrée d'en-tête nécessite deux pointeurs au lieu d'un.
  3. La taille du code est d'environ 15% plus grande et les opérations prennent environ 20% de temps en plus que dans les listes chaînées simples.

Les listes chaînées doublement sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une file FIFO.

Toutes les structures de données chaînées doublement (listes et files) ajoutent en outre :

  1. Insertion d'un nouvel élément avant n'importe quel élément de la liste.
  2. Suppression de n'importe quel élément de la liste en O(1).
Mais :
  1. Chaque élément nécessite deux pointeurs au lieu d'un.
  2. La taille du code et le temps d'exécution des opérations (à l'exception de la suppression) sont approximativement le double de ceux des structures de données chaînées simplement.

Les listes chaînées sont les plus simples des structures de données chaînées doublement. Elles ajoutent la fonctionnalité suivante par rapport à celles mentionnées ci-dessus :

  1. Concaténation de deux listes en O(n).
  2. Elles peuvent être parcourues en sens inverse.
Mais :
  1. Pour parcourir en sens inverse, il est nécessaire de spécifier l'élément à partir duquel commence le parcours et la liste dans laquelle il est contenu.

Les files ajoutent la fonctionnalité suivante :

  1. On peut ajouter un élément à la fin d'une liste.
  2. Elles peuvent être parcourues en sens inverse, de la fin vers le début.
  3. Elles peuvent être concaténées.
Mais :
  1. Toute insertion et suppression dans une liste doit spécifier l'en-tête de la liste.
  2. Chaque entrée d'en-tête nécessite deux pointeurs au lieu d'un.
  3. La taille du code est d'environ 15% plus grande et les opérations prennent environ 20% de temps en plus que dans les listes chaînées simplement.

Dans les définitions de macros, TYPE est le nom d'une structure définie par l'utilisateur. La structure doit contenir un champ nommé NAME de type SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY ou TAILQ_ENTRY. Dans les définitions de macros, CLASSTYPE est le nom d'une classe définie par l'utilisateur. La classe doit contenir un champ nommé NAME de type SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY ou TAILQ_CLASS_ENTRY. L'argument HEADNAME est le nom d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD ou TAILQ_CLASS_HEAD. Voir les exemples ci-dessous pour une explication plus détaillée de la façon dont ces macros sont utilisées.

LISTES CHAÎNÉES SIMPLES

Une liste chaînée simple est dirigée par une structure définie à l'aide de la macro SLIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont chaînés de manière unique pour minimiser l'espace et la surcharge de manipulation des pointeurs, bien que la suppression d'éléments arbitraires nécessite O(n). De nouveaux éléments peuvent être ajoutés à la liste après un élément existant ou au début de la liste. Une structure SLIST_HEAD est déclarée comme suit :

SLIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure qui est définie et TYPE est le type des éléments qui sont chaînés dans la liste. Après cela, un pointeur vers l'en-tête de la liste peut être déclaré comme :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro SLIST_HEAD_INITIALIZER évalue à un initialiseur pour la liste head.

La macro SLIST_CONCAT concaténera la liste dirigée par head2 à la fin de la liste dirigée par head1, vidant la première. L'utilisation de cette macro doit être évitée car elle parcourt tout le contenu de la liste dirigée par head1. Une liste chaînée doublement devrait être utilisée si cette macro est nécessaire dans des chemins d'utilisation fréquents ou si elle doit opérer sur de longues listes.

La macro SLIST_EMPTY évalue à vrai si la liste ne contient aucun élément.

La macro SLIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro SLIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro SLIST_FOREACH parcourt la liste référencée par head dans le sens avant, affectant chaque élément dans son ordre à var.

La macro SLIST_FOREACH_FROM se comporte de manière identique à SLIST_FOREACH lorsque var est NULL, auquel cas elle traite var comme un élément précédemment trouvé dans la liste référencée par head et commence la boucle à partir de var au lieu du premier élément de la liste référencée par head.

La macro SLIST_FOREACH_SAFE parcourt la liste référencée par head dans le sens avant, affectant chaque élément dans son ordre à var. Cependant, contrairement à SLIST_FOREACH() ici, il est permis de supprimer var et de la libérer à l'intérieur de la boucle en toute sécurité sans interférer avec le chemin de parcours.

La macro SLIST_FOREACH_FROM_SAFE se comporte de manière identique à SLIST_FOREACH_SAFE lorsque var est NULL, auquel cas elle traite var comme un élément précédemment trouvé dans la liste référencée par head et commence la boucle à partir de var au lieu du premier élément de la liste référencée par head.

La macro SLIST_INIT initialise la liste référencée par head.

La macro SLIST_INSERT_HEAD insère le nouvel élément elm au début de la liste.

La macro SLIST_INSERT_AFTER insère le nouvel élément elm après l'élément

listelm.

La macro SLIST_NEXT renvoie l'élément suivant dans la liste.

La macro SLIST_REMOVE_AFTER supprime l'élément suivant elm de la liste. Bien que différente de SLIST_REMOVE, cette macro ne parcourt pas toute la liste.

La macro SLIST_REMOVE_HEAD supprime l'élément elm de la tête de la liste. Pour optimiser l'efficacité, les éléments à supprimer de la tête de la liste doivent explicitement utiliser cette macro plutôt que la macro générique SLIST_REMOVE.

La macro SLIST_REMOVE supprime l'élément elm de la liste. Son utilisation doit être évitée car elle parcourt toute la liste. Une liste doublement chaînée doit être utilisée si nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro SLIST_SWAP échange le contenu de head1 et head2.

EXEMPLE DE LISTE SIMPLEMENT ENCHAÎNÉE

SLIST_HEAD(slisthead, entry) head =
    SLIST_HEAD_INITIALIZER(head);
struct slisthead *headp;		/* Tête de liste simplement chaînée. */
struct entry {
	...
	SLIST_ENTRY(entry) entries;	/* Liste simplement chaînée. */
	...
} *n1, *n2, *n3, *np;

SLIST_INIT(&head);			/* Initialise la liste. */

n1 = malloc(sizeof(struct entry));	/* Insertion en tête. */
SLIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insertion après. */
SLIST_INSERT_AFTER(n1, n2, entries);

SLIST_REMOVE(&head, n2, entry, entries);/* Suppression. */
free(n2);

n3 = SLIST_FIRST(&head);
SLIST_REMOVE_HEAD(&head, entries);	/* Suppression de la tête. */
free(n3);
					/* Parcours avant. */
SLIST_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sécurisé. */
SLIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	SLIST_REMOVE(&head, np, entry, entries);
	free(np);
}

while (!SLIST_EMPTY(&head)) {		/* Suppression de la liste. */
	n1 = SLIST_FIRST(&head);
	SLIST_REMOVE_HEAD(&head, entries);
	free(n1);
}

FILES D'ATTENTE SIMPLEMENT ENCHAÎNÉES AVEC POINTEUR DE FIN

Une file d'attente simplement chaînée avec pointeur de fin est dirigée par une structure définie à l'aide de la macro STAILQ_HEAD. Cette structure contient une paire de pointeurs, l'un vers le premier élément de la file d'attente et l'autre vers le dernier élément. Les éléments sont chaînés de manière singulière pour minimiser l'utilisation de l'espace et la manipulation des pointeurs, bien qu'au prix d'un coût en O(n) lors de la suppression d'éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la file d'attente après un élément existant, en tête de la file d'attente, ou à la fin de la file d'attente. Une structure STAILQ_HEAD est déclarée comme suit :

STAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et TYPE est le type des éléments à chaîner dans la file d'attente. Une adresse de pointeur vers la tête de la file d'attente peut être déclarée plus tard comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont choisissables par l'utilisateur.)

La macro STAILQ_HEAD_INITIALIZER est évaluée comme un initialiseur pour la file d'attente head.

La macro STAILQ_CONCAT concatène la file d'attente dirigée par head2 à la fin de la file d'attente dirigée par head1, vidant la première. Son utilisation doit être évitée car elle parcourt toute la liste head1. Une liste doublement chaînée doit être utilisée si nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro STAILQ_EMPTY est évaluée comme vraie s'il n'y a pas d'éléments dans la file d'attente.

La macro STAILQ_ENTRY déclare une structure qui relie les éléments de la file d'attente.

La macro STAILQ_FIRST renvoie le premier élément de la file d'attente ou NULL si la file d'attente est vide.

La macro STAILQ_FOREACH parcourt la file d'attente dirigée par head dans le sens avant, en assignant chaque élément à var.

La macro STAILQ_FOREACH_FROM se comporte de manière identique à STAILQ_FOREACH lorsque var est NULL ; sinon, elle traite var comme un élément déjà trouvé dans la file d'attente et commence l'itération à partir de var au lieu du premier élément de la file d'attente dirigée par head).

La macro STAILQ_FOREACH_SAFE parcourt la file d'attente dirigée par head dans le sens avant, en assignant chaque élément à var. Cependant, contrairement à STAILQ_FOREACH(), il est permis de supprimer var et de le libérer de la mémoire pendant le parcours, sans interférer avec l'itération.

La macro STAILQ_FOREACH_FROM_SAFE se comporte de manière identique à STAILQ_FOREACH_SAFE lorsque var est NULL ; sinon, elle traite var comme un élément déjà trouvé dans la file d'attente et commence l'itération à partir de var au lieu du premier élément de la file d'attente dirigée par head).

La macro STAILQ_INIT initialise la file d'attente dirigée par head.

La macro STAILQ_INSERT_HEAD insère le nouvel élément elm en tête de la file d'attente.

La macro STAILQ_INSERT_TAIL insère le nouvel élément elm à la fin de la file d'attente.

La macro STAILQ_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro STAILQ_LAST renvoie le dernier élément de la file d'attente. Si la file d'attente est vide, la valeur renvoyée est NULL.

La macro STAILQ_NEXT renvoie l'élément suivant de la file d'attente, ou NULL si c'est le dernier.

La macro STAILQ_REMOVE_AFTER supprime l'élément suivant elm de la file d'attente. Bien que différente de STAILQ_REMOVE, cette macro ne parcourt pas toute la file d'attente.

La macro STAILQ_REMOVE_HEAD supprime l'élément en tête de la file d'attente. Pour optimiser l'efficacité, les éléments à supprimer de la tête de la file d'attente doivent explicitement utiliser cette macro plutôt que la macro générique STAILQ_REMOVE.

La macro STAILQ_REMOVE supprime l'élément elm de la file d'attente. Son utilisation doit être évitée car elle parcourt toute la liste. Une file d'attente doublement chaînée doit être utilisée si nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro STAILQ_SWAP échange le contenu de head1 et head2.

EXEMPLE DE FILE D'ATTENTE SIMPLEMENT ENCHAÎNÉE AVEC POINTEUR DE FIN

STAILQ_HEAD(stailhead, entry) head =
    STAILQ_HEAD_INITIALIZER(head);
struct stailhead *headp;		/* Tête de file d'attente simplement chaînée avec pointeur de fin. */
struct entry {
	...
	STAILQ_ENTRY(entry) entries;	/* File d'attente avec pointeur de fin. */
	...
} *n1, *n2, *n3, *np;

STAILQ_INIT(&head);			/* Initialise la file d'attente. */

n1 = malloc(sizeof(struct entry));	/* Insertion en tête. */
STAILQ_INSERT_HEAD(&head, n1, entries);

n1 = malloc(sizeof(struct entry));	/* Insertion en fin. */
STAILQ_INSERT_TAIL(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insertion après. */
STAILQ_INSERT_AFTER(&head, n1, n2, entries);
					/* Suppression. */
STAILQ_REMOVE(&head, n2, entry, entries);
free(n2);
					/* Suppression de la tête. */
n3 = STAILQ_FIRST(&head);
STAILQ_REMOVE_HEAD(&head, entries);
free(n3);
					/* Parcours avant. */
STAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sécurisé. */
STAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	STAILQ_REMOVE(&head, np, entry, entries);
	free(np);
}
					/* Suppression de la file d'attente. */
while (!STAILQ_EMPTY(&head)) {
	n1 = STAILQ_FIRST(&head);
	STAILQ_REMOVE_HEAD(&head, entries);

}
					/* Suppression plus rapide de la file d'attente. */
n1 = STAILQ_FIRST(&head);
while (n1 != NULL) {

}
STAILQ_INIT(&head);

LISTES

LISTS

A list is headed by a structure defined by the LIST_HEAD macro. This structure contains a pointer to the first element in the list. The elements are singly linked so that an arbitrary element may be removed without traversing the list. New elements can be added to the list after an existing element, or at the head of the list. A LIST_HEAD structure is declared as follows:

LIST_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the list. A pointer to the head of the list can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro LIST_HEAD_INITIALIZER evaluates to an initializer for the list head.

The macro LIST_CONCAT concatenates the list headed by head2 onto the end of the one headed by head1.

The macro LIST_EMPTY evaluates to true if there are no items on the list.

The macro LIST_ENTRY declares a structure that connects the elements in the list.

The macro LIST_FIRST returns the first item on the list or NULL if the list is empty.

The macro LIST_FOREACH traverses the list referenced by head in the forward direction, assigning each element in turn to var.

The macro LIST_FOREACH_FROM behaves identically to LIST_FOREACH when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_FOREACH_SAFE traverses the list referenced by head in the forward direction, assigning each element in turn to var. However, unlike LIST_FOREACH() here it is permitted to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro LIST_FOREACH_FROM_SAFE behaves identically to LIST_FOREACH_SAFE when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_INIT initializes the list referenced by head.

The macro LIST_INSERT_HEAD inserts the new element elm at the head of the list.

The macro LIST_INSERT_AFTER inserts the new element elm after the element listelm.

The macro LIST_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro LIST_NEXT returns the next element in the list, or NULL if this is the last.

The macro LIST_PREV returns the previous element in the list, or NULL if this is the first. List head must contain element elm.

The macro LIST_REMOVE removes the element elm from the list.

The macro LIST_SWAP swaps the contents of head1 and head2.

LIST EXAMPLE

LIST_HEAD(listhead, entry) head =
    LIST_HEAD_INITIALIZER(head);
struct listhead *headp;			/* List head. */
struct entry {
	...
	LIST_ENTRY(entry) entries;	/* List. */
	...
} *n1, *n2, *n3, *np, *np_temp;

LIST_INIT(&head);			/* Initialize the list. */

n1 = malloc(sizeof(struct entry));	/* Insert at the head. */
LIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insert after. */
LIST_INSERT_AFTER(n1, n2, entries);

n3 = malloc(sizeof(struct entry));	/* Insert before. */
LIST_INSERT_BEFORE(n2, n3, entries);

LIST_REMOVE(n2, entries);		/* Deletion. */
free(n2);
					/* Forward traversal. */
LIST_FOREACH(np, &head, entries)
	np-> ...

					/* Safe forward traversal. */
LIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	LIST_REMOVE(np, entries);
	free(np);
}

while (!LIST_EMPTY(&head)) {		/* List Deletion. */
	n1 = LIST_FIRST(&head);
	LIST_REMOVE(n1, entries);
	free(n1);
}

TAIL QUEUES

A tail queue is headed by a structure defined by the TAILQ_HEAD macro. This structure contains a pair of pointers, one to the first element in the tail queue and the other to the last element in the tail queue. The elements are doubly linked so that an arbitrary element can be removed without traversing the tail queue. New elements can be added to the tail queue after an existing element, before an existing element, at the head of the tail queue, or at the end of the tail queue. A TAILQ_HEAD structure is declared as follows:

TAILQ_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the tail queue. A pointer to the head of the tail queue can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro TAILQ_HEAD_INITIALIZER evaluates to an initializer for the tail queue head.

The macro TAILQ_CONCAT concatenates the tail queue headed by head2 onto the end of the one headed by head1 removing all entries from the former.

The macro TAILQ_EMPTY evaluates to true if there are no items on the tail queue.

The macro TAILQ_ENTRY declares a structure that connects the elements in the tail queue.

The macro TAILQ_FIRST returns the first item on the tail queue or NULL if the tail queue is empty.

The macro TAILQ_FOREACH traverses the tail queue referenced by head in the forward direction, assigning each element in turn to var. var is set to NULL if the loop completes normally, or if there were no elements.

The macro TAILQ_FOREACH_FROM behaves identically to TAILQ_FOREACH when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.

The macro TAILQ_FOREACH_REVERSE traverses the tail queue referenced by head in the reverse direction, assigning each element in turn to var.

The macro TAILQ_FOREACH_REVERSE_FROM behaves identically to TAILQ_FOREACH_REVERSE when var is NULL, else it treats var as a previously found TAILQ element and begins the reverse loop at var instead of the last element in the TAILQ referenced by head.

The macros TAILQ_FOREACH_SAFE and TAILQ_FOREACH_REVERSE_SAFE traverse the list referenced by head in the forward or reverse direction respectively, assigning each element in turn to var. However, unlike their unsafe counterparts, TAILQ_FOREACH and TAILQ_FOREACH_REVERSE make it possible to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro TAILQ_FOREACH_FROM_SAFE behaves identically to TAILQ_FOREACH_SAFE when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.

The macro TAILQ_FOREACH_REVERSE_FROM_SAFE behaves identically to TAILQ_FOREACH_REVERSE_SAFE when var is NULL, else it treats var as a previously found TAILQ element and begins the reverse loop at var instead of the last element in the TAILQ referenced by head.

The macro TAILQ_INIT initializes the tail queue referenced by head.

The macro TAILQ_INSERT_HEAD inserts the new element elm at the head of the tail queue.

The macro TAILQ_INSERT_TAIL inserts the new element elm at the end of the tail queue.

The macro TAILQ_INSERT_AFTER inserts the new element elm after the element listelm.

The macro TAILQ_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro TAILQ_LAST returns the last item on the tail queue. If the tail queue is empty the return value is NULL.

The macro TAILQ_NEXT returns the next item on the tail queue, or NULL if this item is the last.

The macro TAILQ_PREV returns the previous item on the tail queue, or NULL if this item is the first.

The macro TAILQ_REMOVE removes the element elm from the tail queue.

The macro TAILQ_SWAP swaps the contents of head1 and head2.

DIAGNOSTICS

Lors du débogage de queue(3), il peut être utile de tracer les modifications de la file d'attente. Pour activer le traçage, définissez la macro QUEUE_MACRO_DEBUG_TRACE au moment de la compilation.

Il peut également être utile de corrompre les pointeurs qui ont été détachés d'une file d'attente, afin de détecter une utilisation après suppression. Pour activer la corruption des pointeurs, définissez la macro QUEUE_MACRO_DEBUG_TRASH au moment de la compilation. La macro QMD_IS_TRASHED(void *ptr) retourne vrai si ptr a été corrompu par l'option QUEUE_MACRO_DEBUG_TRASH.
