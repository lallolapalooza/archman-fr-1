NOM

Log::Log4perl::Appender::Limit - Limite la livraison des messages via une période de blocage

SYNOPSIS

use Log::Log4perl qw(:easy);
my $conf = qq(
  log4perl.category = WARN, Limiter

      # Appender email
  log4perl.appender.Mailer          = Log::Dispatch::Email::MailSend
  log4perl.appender.Mailer.to       = drone\@pageme.com
  log4perl.appender.Mailer.subject  = Something's broken!
  log4perl.appender.Mailer.buffered = 0
  log4perl.appender.Mailer.layout   = PatternLayout
  log4perl.appender.Mailer.layout.ConversionPattern=%d %m %n
      # Appender de limitation, utilisant l'appender email ci-dessus
  log4perl.appender.Limiter              = Log::Log4perl::Appender::Limit
  log4perl.appender.Limiter.appender     = Mailer
  log4perl.appender.Limiter.block_period = 3600
);
Log::Log4perl->init(\$conf);
WARN("Ce message sera envoyé immédiatement.");
WARN("Ce message sera retardé d'une heure.");
sleep(3601);
WARN("Ce message et le dernier seront envoyés maintenant, séparément.");

DESCRIPTION

"appender"
Spécifie le nom de l'appender utilisé par le limiteur. L'appender spécifié doit être défini quelque part dans le fichier de configuration, pas nécessairement avant la définition de "Log::Log4perl::Appender::Limit".
"block_period"
Période en secondes entre la livraison des messages. Si des messages arrivent entre-temps, ils seront soit sauvegardés (si "accumulate" est défini à une valeur vraie) soit écartés (si "accumulate" n'est pas défini).
"persistent"
Nom du fichier dans lequel "Log::Log4perl::Appender::Limit" stocke de manière persistante les heures de livraison. S'il est omis, l'appender n'aura aucun souvenir de ce qui s'est passé au redémarrage du programme.
"max_until_flushed"
Nombre maximum de messages accumulés. S'il est dépassé, l'appender vide tous les messages, même si l'intervalle défini dans "block_period" est écoulé ou non. Ne pas mélanger avec "max_until_discarded".
"max_until_discarded"
Nombre maximum de messages accumulés. S'il est dépassé, l'appender écartera simplement les messages supplémentaires, attendant que la période "block_period" expire pour vider tous les messages accumulés. Ne pas mélanger avec "max_until_flushed".
"appender_method_on_flush"
Nom de méthode optionnel à appeler sur l'appender attaché au limiteur lorsque les messages sont vidés. Par exemple, pour que l'exemple de code dans la section SYNOPSIS regroupe les emails mis en tampon dans un seul, changez le paramètre "buffered" du mailer à 1 et définissez la valeur de "appender_method_on_flush" du limiteur à la chaîne "flush" : 
log4perl.category = WARN, Limiter

    # Appender email
log4perl.appender.Mailer          = Log::Dispatch::Email::MailSend
log4perl.appender.Mailer.to       = drone\@pageme.com
log4perl.appender.Mailer.subject  = Something's broken!
log4perl.appender.Mailer.buffered = 1
log4perl.appender.Mailer.layout   = PatternLayout
log4perl.appender.Mailer.layout.ConversionPattern=%d %m %n
    # Appender de limitation, utilisant l'appender email ci-dessus
log4perl.appender.Limiter              = Log::Log4perl::Appender::Limit
log4perl.appender.Limiter.appender     = Mailer
log4perl.appender.Limiter.block_period = 3600
log4perl.appender.Limiter.appender_method_on_flush = flush

Cela amènera le mailer à mettre les messages en tampon et à attendre que flush() envoie tout le lot. Le limiteur appellera alors la méthode flush() de l'appender lorsque son propre tampon sera vidé.

Si l'appender attaché à "Limit" utilise "PatternLayout" avec un spécificateur d'horodatage, vous remarquerez que les horodatages des messages reflètent l'événement de log d'origine, et non l'heure de rendu du message dans l'appender attaché. Des astuces majeures ont été appliquées pour y parvenir (Toux !).

NOTES DE DÉVELOPPEMENT

"Log::Log4perl::Appender::Limit" est un appender composite. Contrairement aux autres appenders, il ne logue aucun message, il les transmet simplement à son sous-appendeur attaché. Pour cette raison, il n'a pas besoin de mise en page (contrairement aux appenders réguliers). S'il n'en définit aucun, les messages sont transmis tels quels.

Les filtres personnalisés sont également appliqués uniquement à l'appender composite. Ils ne sont pas appliqués au sous-appendeur. Il en va de même pour les seuils d'appendeur. Ce comportement pourrait changer à l'avenir.
