NAME

Log::Log4perl::Config - Syntaxe des fichiers de configuration Log4perl

DESCRIPTION

Dans "Log::Log4perl", les fichiers de configuration sont utilisés pour décrire comment les enregistreurs du système doivent se comporter.

Le format est le même que celui utilisé par "log4j", avec quelques extensions spécifiques à perl, comme la possibilité d'activer "Bar::Twix" au lieu de devoir utiliser le "Bar.Twix" spécifique à Java.

Les lignes de commentaire et les lignes vides (contenant uniquement des espaces ou étant vides) sont ignorées.

Les lignes de commentaire peuvent commencer par n'importe quel espace suivi de l'un des caractères suivants :

# - Délimiteur de commentaire courant
! - Délimiteur de commentaire de fichier .properties accepté par log4j
; - Délimiteur de commentaire de fichier .ini courant

Les commentaires en fin de ligne ne sont pas pris en charge. Ainsi, si vous écriviez

log4perl.appender.A1.filename=error.log #dans le répertoire courant

vous verriez vos messages dans un fichier nommé "error.log #dans le répertoire courant".

De plus, les espaces entre les entités syntaxiques sont ignorés ; peu importe que vous écriviez

log4perl.logger.Bar.Twix=WARN,Screen

ou

log4perl.logger.Bar.Twix = WARN, Screen

L'"Log::Log4perl" supprimera les espaces lors de l'analyse de votre entrée.

Les affectations doivent être sur une seule ligne. Cependant, vous pouvez sauter de ligne si vous le souhaitez, en utilisant un caractère de continuation à la fin de la ligne. Au lieu d'écrire

log4perl.appender.A1.layout=Log::Log4perl::Layout::SimpleLayout

vous pouvez sauter la ligne à n'importe quel endroit, en plaçant un antislash à la fin de la ligne pour continuer :

log4perl.appender.A1.layout=\
    Log::Log4perl::Layout::SimpleLayout

Notez que les espaces après l'antislash pourraient empêcher la bonne concaténation de la ligne.

Enregistreurs (Loggers)

Les enregistreurs font référence aux catégories :

log4perl.logger.Bar.Twix      = WARN, Screen

Ceci définit tous les enregistreurs de la hiérarchie "Bar::Twix" avec une priorité "WARN" et leur attache un gestionnaire (appender) défini ultérieurement, nommé "Screen". Les configurations de gestionnaire de la racine (qui n'a pas de nom) peuvent être effectuées simplement en omettant le nom :

log4perl.logger = FATAL, Database, Mailer

Ceci définit le niveau du gestionnaire racine à "FATAL" et leur attache les gestionnaires définis ultérieurement "Database" et "Mailer". Alternativement, l'enregistreur racine peut être référencé comme "rootLogger" :

log4perl.rootLogger = FATAL, Database, Mailer

Le drapeau d'additivité d'un enregistreur est défini ou supprimé via le mot-clé "additivity" :

log4perl.additivity.Bar.Twix = 0|1

(Notez : l'ordre inversé du mot-clé et du nom de l'enregistreur, dû au dilemme qu'un nom d'enregistreur pourrait se terminer par ".additivity" selon le manuel de log4j).

Gestionnaires et Mises en page (Layouts)

Les noms de gestionnaires utilisés dans les lignes de configuration Log4perl doivent être résolus plus tard, pour définir les propriétés du gestionnaire et sa mise en page. Pour spécifier les propriétés d'un gestionnaire, utilisez simplement le mot-clé "appender" après l'introduction de "log4perl" et le nom du gestionnaire :

    # L'enregistreur Bar::Twix et son gestionnaire
log4perl.logger.Bar.Twix = DEBUG, A1
log4perl.appender.A1=Log::Log4perl::Appender::File
log4perl.appender.A1.filename=test.log
log4perl.appender.A1.mode=append
log4perl.appender.A1.layout=Log::Log4perl::Layout::SimpleLayout

Ceci définit un niveau "DEBUG" pour les enregistreurs de la hiérarchie "Bar::Twix" et leur assigne le gestionnaire "A1", qui est résolu plus tard comme un gestionnaire de type "Log::Log4perl::Appender::File", qui ajoute à un fichier journal. Selon le manuel de "Log::Log4perl::Appender::File", le paramètre "filename" spécifie le nom du fichier journal, et le paramètre "mode" peut être réglé à "append" ou "write" (le premier ajoute au fichier journal si un fichier du nom spécifié existe déjà, tandis que le second l'écrase).

L'ordre des entrées dans le fichier de configuration n'a pas d'importance, "Log::Log4perl" lira l'ensemble du fichier d'abord et tentera de donner un sens aux lignes une fois qu'il connaît le contexte complet.

Vous pouvez facilement définir tous les enregistreurs d'abord, puis leurs gestionnaires (vous pourriez même définir les gestionnaires d'abord, puis les enregistreurs, mais ne faisons pas cela) :

log4perl.logger.Bar.Twix = DEBUG, A1
log4perl.logger.Bar.Snickers = FATAL, A2
log4perl.appender.A1=Log::Log4perl::Appender::File
log4perl.appender.A1.filename=test.log
log4perl.appender.A1.mode=append
log4perl.appender.A1.layout=Log::Log4perl::Layout::SimpleLayout
log4perl.appender.A2=Log::Log4perl::Appender::Screen
log4perl.appender.A2.stderr=0
log4perl.appender.A2.layout=Log::Log4perl::Layout::PatternLayout
log4perl.appender.A2.layout.ConversionPattern = %d %m %n

Note : vous devez spécifier le chemin complet de la classe de mise en page et que "ConversionPattern" est le mot-clé pour spécifier les instructions de formatage de style printf.

Recettes de fichiers de configuration

Voici quelques exemples de fichiers de configuration Log4perl courants :

Ajouter à STDERR

log4perl.category.Bar.Twix      = WARN, Screen
log4perl.appender.Screen        = Log::Log4perl::Appender::Screen
log4perl.appender.Screen.layout = \
    Log::Log4perl::Layout::PatternLayout
log4perl.appender.Screen.layout.ConversionPattern = %d %m %n

Ajouter à STDOUT

log4perl.category.Bar.Twix      = WARN, Screen
log4perl.appender.Screen        = Log::Log4perl::Appender::Screen
log4perl.appender.Screen.stderr = 0
log4perl.appender.Screen.layout = \
    Log::Log4perl::Layout::PatternLayout
log4perl.appender.Screen.layout.ConversionPattern = %d %m %n

Ajouter à un fichier journal

log4perl.logger.Bar.Twix = DEBUG, A1
log4perl.appender.A1=Log::Log4perl::Appender::File
log4perl.appender.A1.filename=test.log
log4perl.appender.A1.mode=append
log4perl.appender.A1.layout = \
    Log::Log4perl::Layout::PatternLayout
log4perl.appender.A1.layout.ConversionPattern = %d %m %n

Note : vous pourriez même omettre

log4perl.appender.A1.mode=append

et le logger ajouterait toujours au fichier journal par défaut, bien que le module "Log::Log4perl::Appender::File" fasse exactement le contraire. C'est dû à certaines astuces inhabituelles de "Log::Log4perl" pour s'assurer que les applications CGI débutantes ne suppriment pas le fichier journal à chaque appel.

Écrire un fichier journal à partir de zéro

Si la stratégie d'ajout par défaut de "Log::Log4perl" vous ennuie, vous pouvez la remplacer :

log4perl.logger.Bar.Twix = DEBUG, A1
log4perl.appender.A1=Log::Log4perl::Appender::File
log4perl.appender.A1.filename=test.log
log4perl.appender.A1.mode=write
log4perl.appender.A1.layout=Log::Log4perl::Layout::SimpleLayout

Le "write" est le mode où "Log::Log4perl::Appender::File" écrase explicitement le fichier journal s'il existe.

Fichiers de configuration codés en UTF-8

Ce qui suit est un exemple d'un fichier de configuration Log4perl :

Note : vous devez spécifier le chemin complet de la classe de mise en page et que "ConversionPattern" est le mot-clé pour spécifier les instructions de formatage de style printf.

NOM

Log::Log4perl::Config

DESCRIPTION

Log4perl est un module Perl qui fournit des capacités de journalisation similaires au framework Java Log4j. Il permet aux développeurs de configurer et de gérer les sorties de journalisation de manière flexible et puissante.

Manuel de configuration des fichiers

Cette section fournit un guide sur la façon de configurer Log4perl en utilisant diverses méthodes.
