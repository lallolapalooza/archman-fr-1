NOM

Locale::Po4a::TransTractor - extracteur générique de traducteur (trans(lator ex)tractor).

DESCRIPTION

Le projet po4a (PO pour tout) vise à faciliter la traduction (et, plus intéressant, la maintenance des traductions) à l'aide des outils gettext dans des domaines où ils n'étaient pas attendus, comme la documentation.

Cette classe est l'ancêtre de chaque analyseur po4a utilisé pour analyser un document, rechercher des chaînes traduisibles, les extraire dans un fichier PO et les remplacer par leur traduction dans le document de sortie.

Plus formellement, elle prend les arguments suivants en entrée :

  • un document à traduire ;
  • un fichier PO contenant les traductions à utiliser.

En sortie, elle produit :

  • un autre fichier PO, résultant de l'extraction des chaînes traduisibles du document d'entrée ;
  • un document traduit, avec la même structure que celui en entrée, mais avec toutes les chaînes traduisibles remplacées par les traductions trouvées dans le fichier PO fourni en entrée.

Voici une représentation graphique :

Document d'entrée --\                             /---> Document de sortie
                    \                           /       (traduit)
                     +-> fonction parse() -----+
                    /                           \
Fichier PO d'entrée-/                             \---> Fichier PO de sortie
                                                      (extrait)

FONCTIONS QUE VOTRE ANALYSEUR DOIT REDÉFINIR

parse()
C'est ici que tout le travail se déroule : l'analyse des documents d'entrée, la génération de la sortie, et l'extraction des chaînes traduisibles. C'est assez simple en utilisant les fonctions fournies présentées dans la section FONCTIONS INTERNES ci-dessous. Voir aussi le SYNOPSIS, qui présente un exemple.

Cette fonction est appelée par la fonction process() ci-dessous, mais si vous choisissez d'utiliser la fonction new(), et d'ajouter du contenu manuellement à votre document, vous devrez appeler cette fonction vous-même.

docheader()
Cette fonction retourne l'en-tête que nous devrions ajouter au document produit, correctement cité pour être un commentaire dans la langue cible. Voir la section Éduquer les développeurs sur les traductions, de po4a(7), pour son utilité.

SYNOPSIS

L'exemple suivant analyse une liste de paragraphes commençant par "<p>". Pour simplifier, nous supposons que le document est bien formaté, c'est-à-dire que les balises '<p>' sont les seules balises présentes, et que cette balise se trouve tout au début de chaque paragraphe.

sub parse {
  my $self = shift;
  PARAGRAPH: while (1) {
      my ($paragraph,$pararef)=("","");
      my $first=1;
      my ($line,$lref)=$self->shiftline();
      while (defined($line)) {
          if ($line =~ m/<p>/ && !$first--; ) {
              # Pas la première fois que nous voyons <p>.
              # Remettre la ligne actuelle dans l'entrée,
              #  et mettre le paragraphe construit en sortie
              $self->unshiftline($line,$lref);
              # Maintenant que le document est formé, le traduire :
              #   - Supprimer la balise de début
              $paragraph =~ s/^<p>//s;
              #   - ajouter à la sortie la balise de début (non traduite) et le
              #     reste du paragraphe (traduit)
              $self->pushline(  "<p>"
                              . $self->translate($paragraph,$pararef)
                              );
              next PARAGRAPH;
          } else {
              # Ajouter au paragraphe
              $paragraph .= $line;
              $pararef = $lref unless(length($pararef));
          }
          # Réinitialiser la boucle
          ($line,$lref)=$self->shiftline();
      }
      # Pas de ligne définie ? Fin du fichier d'entrée.
      return;
  }
}

Une fois que vous avez implémenté la fonction parse, vous pouvez utiliser votre classe de document, en utilisant l'interface publique présentée dans la section suivante.

Manipulation des fichiers documentaires

read($$$)
Ajoute les données d'un autre document d'entrée à la fin du tableau existant "@{$self->{TT}{doc_in}}".

Cette fonction prend deux arguments obligatoires et un optionnel.
* Le nom du fichier à lire sur disque ;
* Le nom à utiliser comme nom de fichier lors de la construction de la référence dans le fichier PO ;
* Le jeu de caractères à utiliser pour lire ce fichier (UTF-8 par défaut)

Ce tableau "@{$self->{TT}{doc_in}}" contient ces données de document d'entrée sous forme de tableau de chaînes avec des significations alternées.
* La chaîne $textline contenant chaque ligne des données textuelles d'entrée.
* La chaîne "$filename:$linenum" contenant son emplacement et appelée comme
"référence" ("$linenum" commence à 1).

Veuillez noter qu'elle ne parse rien. Vous devriez utiliser la fonction parse() une fois que vous avez terminé de regrouper les fichiers d'entrée dans le document.

write($)
Écrit le document traduit dans le nom de fichier donné.

Ces données de document traduit sont fournies par :
* "$self->docheader()" contenant le texte d'en-tête pour le plugin, et
* "@{$self->{TT}{doc_out}}" contenant chaque ligne du texte traduit principal dans le tableau.

Manipulation des fichiers PO

readpo($)
Ajoute le contenu d'un fichier (dont le nom est passé en argument) au PO d'entrée existant. L'ancien contenu n'est pas supprimé.
writepo($)
Écrit le fichier PO extrait dans le nom de fichier donné.
stats()
Retourne quelques statistiques sur la traduction effectuée jusqu'à présent. Veuillez noter que ce ne sont pas les mêmes statistiques que celles imprimées par msgfmt --statistic. Ici, il s'agit de statistiques sur l'utilisation récente du fichier PO, tandis que msgfmt rapporte l'état du fichier. C'est un wrapper de la fonction Locale::Po4a::Po::stats_get appliquée au fichier PO d'entrée. Exemple d'utilisation : 
[utilisation normale du document po4a...]
($percent,$hit,$queries) = $document->stats();
print "Nous avons trouvé des traductions pour $percent\%  ($hit sur $queries) des chaînes.\n";

Manipulation des annexes

addendum($)
Veuillez vous référer à po4a(7) pour plus d'informations sur ce que sont les annexes et comment les traducteurs doivent les écrire. Pour appliquer une annexe au document traduit, il suffit de passer son nom de fichier à cette fonction et c'est terminé ;)

Cette fonction renvoie un entier non nul en cas d'erreur.

FONCTIONS INTERNES utilisées pour écrire des parseurs dérivés

Obtenir l'entrée, fournir la sortie

Quatre fonctions sont fournies pour obtenir l'entrée et retourner la sortie. Elles sont très similaires aux fonctions shift/unshift et push/pop de Perl.

* Perl shift renvoie le premier élément du tableau et le supprime du tableau.
* Perl unshift ajoute un élément au début du tableau en tant que premier élément du tableau.
* Perl pop renvoie le dernier élément du tableau et le supprime du tableau.
* Perl push ajoute un élément à la fin du tableau en tant que dernier élément du tableau.

La première paire concerne l'entrée, tandis que la seconde concerne la sortie. Mnémonique : en entrée, vous vous intéressez à la première ligne, ce que shift fournit, et en sortie, vous voulez ajouter votre résultat à la fin, comme le fait push.

shiftline()
Cette fonction renvoie la première ligne à parser et sa référence correspondante (regroupée sous forme de tableau) à partir du tableau "@{$self->{TT}{doc_in}}" et supprime ces deux premiers éléments du tableau. Ici, la référence est fournie par une chaîne "$filename:$linenum".
unshiftline($$)
Ajoute la dernière ligne décalée du document d'entrée et sa référence correspondante au début de "{$self->{TT}{doc_in}}".
pushline($)
Ajoute une nouvelle ligne à la fin de "{$self->{TT}{doc_out}}".
popline()
Retire la dernière ligne ajoutée à la fin de "{$self->{TT}{doc_out}}".

Marquer les chaînes comme traduisibles

Une fonction est fournie pour gérer le texte qui doit être traduit.

translate($$$)
Arguments obligatoires :
  • Une chaîne à traduire
  • La référence de cette chaîne (c'est-à-dire la position dans le fichier d'entrée)
  • Le type de cette chaîne (c'est-à-dire la description textuelle de son rôle structurel ; utilisé dans Locale::Po4a::Po::gettextization() ; voir aussi po4a(7), section Gettextization : comment ça marche ?)

Cette fonction peut également prendre des arguments supplémentaires. Ils doivent être organisés sous forme de hachage. Par exemple :

$self->translate("string","ref","type",
                 'wrap' => 1);
wrap
booléen indiquant si nous pouvons considérer que les espaces dans la chaîne n'ont pas d'importance. Si oui, la fonction canonise la chaîne avant de rechercher une traduction ou de l'extraire, et renvoie la traduction.
wrapcol
la colonne à laquelle renvoyer (par défaut : la valeur de wrapcol spécifiée lors de la création du TransTractor ou 76).

La valeur négative sera soustraite de la valeur par défaut.

comment
un commentaire supplémentaire à ajouter à l'entrée.

Actions :

  • Ajoute la chaîne, la référence et le type à po_out.
  • Retourne la traduction de la chaîne (telle que trouvée dans po_in) afin que le parseur puisse construire doc_out.
  • Gère les jeux de caractères pour recoder les chaînes avant de les envoyer à po_out et avant de retourner les traductions.

Fonctions diverses

verbose()
Retourne si l'option verbose a été passée lors de la création du TransTractor.
debug()
Retourne si l'option debug a été passée lors de la création du TransTractor.
get_in_charset()
Cette fonction renvoie le jeu de caractères qui a été fourni comme jeu de caractères maître.
get_out_charset()
Cette fonction renvoie le jeu de caractères qui doit être utilisé dans le document de sortie (généralement utile pour substituer le jeu de caractères détecté du document d'entrée lorsqu'il a été trouvé).

Elle utilisera le jeu de caractères de sortie spécifié sur la ligne de commande. S'il n'a pas été spécifié, elle utilisera le jeu de caractères du PO d'entrée, et si le PO d'entrée a le jeu de caractères par défaut "CHARSET", elle renverra le jeu de caractères du document d'entrée, de sorte qu'aucun encodage ne soit effectué.

ORIENTATIONS FUTURES

Une lacune du TransTractor actuel est qu'il ne peut pas gérer les documents traduits contenant toutes les langues, comme les modèles debconf, ou les fichiers .desktop.

Pour résoudre ce problème, les seuls changements d'interface nécessaires sont :

  • prendre un hachage comme po_in_name (une liste par langue)
  • ajouter un argument à translate pour indiquer la langue cible
  • créer une fonction pushline_all, qui ferait pushline de son contenu pour toutes les langues, en utilisant une syntaxe de type carte : 
    $self->pushline_all({ "Description[".$langcode."]=".
                      $self->translate($line,$ref,$langcode)
                    });

Nous verrons si c'est suffisant ;)
