DESCRIPTION

Ces macros définissent et opèrent sur quatre types de structures de données qui peuvent être utilisés aussi bien en C qu'en C++ :

  1. Liste
  2. Liste doublement chaînée
  3. File à accès terminal
  4. File
Les quatre structures supportent la fonctionnalité suivante :
  1. Insertion d'une nouvelle entrée en tête de liste.
  2. Insertion d'une nouvelle entrée après un élément quelconque de la liste.
  3. Suppression d'une entrée en tête de liste avec une complexité en O(1).
  4. Parcours linéaire de la liste.
  5. Échange du contenu de deux listes.

Les listes doublement chaînées sont les plus simples des quatre structures de données et ne supportent que la fonctionnalité mentionnée ci-dessus. Les listes doublement chaînées sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une pile LIFO. Les listes doublement chaînées ajoutent la fonctionnalité suivante :

  1. Suppression d'une entrée quelconque de la liste avec une complexité en O(n).
  2. Jonction de deux listes.

Les files à accès terminal ajoutent la fonctionnalité suivante :

  1. Des entrées peuvent être ajoutées à la fin d'une liste.
  2. Suppression d'une entrée quelconque de la liste avec une complexité en O(n).
  3. Elles peuvent être concaténées.
Cependant :
  1. Les insertions dans les listes doivent spécifier la tête de liste.
  2. Chaque entrée de tête nécessite deux pointeurs au lieu d'un.
  3. La taille du code est environ 15% plus grande et les opérations prennent environ 20% de temps en plus que dans les listes doublement chaînées.

Les files à accès terminal sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une file FIFO.

En plus des structures de données doublement chaînées (listes et files à accès terminal), les structures de type doublement chaînées permettent également :

  1. Insertion d'une nouvelle entrée avant un élément quelconque de la liste.
  2. Suppression d'une entrée quelconque de la liste avec une complexité en O(1).
Cependant :
  1. Chaque élément nécessite deux pointeurs au lieu d'un.
  2. La taille du code et le temps d'exécution des opérations (sauf la suppression) sont environ le double de ceux des structures de données doublement chaînées.

Les listes sont les plus simples des structures de données doublement chaînées. Elles ajoutent la fonctionnalité suivante par rapport à ce qui a été mentionné précédemment :

  1. Jonction de deux listes avec une complexité en O(n).
  2. Elles peuvent être parcourues en sens inverse.
Cependant :
  1. Pour parcourir en sens inverse, il faut spécifier l'élément de départ du parcours et la liste dans laquelle il se trouve.

Les files ajoutent la fonctionnalité suivante :

  1. Des entrées peuvent être ajoutées à la fin d'une liste.
  2. Elles peuvent être parcourues en sens inverse, de la fin vers la tête.
  3. Elles peuvent être concaténées.
Cependant :
  1. Les insertions et suppressions dans les listes doivent spécifier la tête de liste.
  2. Chaque entrée de tête nécessite deux pointeurs au lieu d'un.
  3. La taille du code est environ 15% plus grande et les opérations prennent environ 20% de temps en plus que dans les listes doublement chaînées.

Dans les définitions de macros, TYPE est le nom d'une structure définie par l'utilisateur. La structure doit contenir un champ nommé NAME de type SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY ou TAILQ_ENTRY. Dans les définitions de macros, CLASSTYPE est le nom d'une classe définie par l'utilisateur. La classe doit contenir un champ nommé NAME de type SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY ou TAILQ_CLASS_ENTRY. L'argument HEADNAME est le nom d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD ou TAILQ_CLASS_HEAD. Pour plus d'informations sur la façon dont ces macros sont utilisées, consultez les exemples ci-dessous.

LISTES SIMPLEMENT CHAÎNÉES

Une liste simplement chaînée est dirigée par une structure définie à l'aide de la macro SLIST_HEAD. Cette structure contient un unique pointeur vers le premier élément de la liste. Les éléments sont simplement chaînés pour minimiser l'espace et la surcharge de manipulation des pointeurs, mais avec un coût en O(n) pour supprimer des éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant ou en tête de liste. Une structure SLIST_HEAD est déclarée comme suit :

SLIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et TYPE est le type des éléments de la liste. Un pointeur vers la tête de la liste peut alors être déclaré comme :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro SLIST_HEAD_INITIALIZER évalue un initialiseur pour la liste head.

La macro SLIST_CONCAT concaténera la liste dirigée par head2 à la fin de la liste dirigée par head1, en vidant la première. Son utilisation doit être évitée dans les chemins de code à forte utilisation, car elle parcourt tout le contenu de la liste dirigée par head1. Une file à accès terminal doit être utilisée si nécessaire dans les chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro SLIST_EMPTY évalue à true s'il n'y a pas d'éléments dans la liste.

La macro SLIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro SLIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro SLIST_FOREACH parcourt la liste référencée par head dans le sens direct, en affectant chaque élément à var dans l'ordre.

La macro SLIST_FOREACH_FROM se comporte de manière identique à SLIST_FOREACH lorsque var est NULL, auquel cas elle traite var comme un élément précédemment trouvé dans la liste référencée par head et commence la boucle à partir de var au lieu du premier élément de la liste référencée par head).

La macro SLIST_FOREACH_SAFE parcourt la liste référencée par head dans le sens direct, en affectant chaque élément à var. Cependant, bien que SLIST_FOREACH ne soit pas spécifié ici, il est permis de supprimer var et de libérer sa mémoire à l'intérieur de la boucle en toute sécurité, sans interférer avec le parcours.

La macro SLIST_FOREACH_FROM_SAFE se comporte de manière identique à SLIST_FOREACH_SAFE lorsque var est NULL, auquel cas elle traite var comme un élément précédemment trouvé dans la liste référencée par head et commence la boucle à partir de var au lieu du premier élément de la liste référencée par head).

La macro SLIST_INIT initialise la liste référencée par head.

La macro SLIST_INSERT_HEAD insère le nouvel élément elm en tête de liste.

La macro SLIST_INSERT_AFTER insère le nouvel élément elm après l'élément

EXEMPLE DE LISTE SIMPLEMENTE ENLACÉE

SLIST_HEAD(slisthead, entry) head =
    SLIST_HEAD_INITIALIZER(head);
struct slisthead *headp;		/* Tête de liste simplement enlacée. */
struct entry {
	...
	SLIST_ENTRY(entry) entries;	/* Liste simplement enlacée. */
	...
} *n1, *n2, *n3, *np;

SLIST_INIT(&head);			/* Initialise la liste. */

n1 = malloc(sizeof(struct entry));	/* Insertion en tête. */
SLIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insertion après. */
SLIST_INSERT_AFTER(n1, n2, entries);

SLIST_REMOVE(&head, n2, entry, entries);/* Suppression. */
free(n2);

n3 = SLIST_FIRST(&head);
SLIST_REMOVE_HEAD(&head, entries);	/* Suppression de la tête. */
free(n3);
					/* Parcours avant. */
SLIST_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sécurisé. */
SLIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	SLIST_REMOVE(&head, np, entry, entries);
	free(np);
}

while (!SLIST_EMPTY(&head)) {		/* Suppression de la liste. */
	n1 = SLIST_FIRST(&head);
	SLIST_REMOVE_HEAD(&head, entries);
	free(n1);
}

FILES D'ATTENTE À QUEUE SIMPLEMENT ENLACÉES

Une file d'attente à queue simplement enlacée est dirigée par une structure définie par la macro STAILQ_HEAD. Cette structure contient une paire de pointeurs, l'un vers le premier élément de la file d'attente à queue, et l'autre vers le dernier élément de la file d'attente à queue. Les éléments sont enlacés de manière singulière pour minimiser l'espace et la surcharge de manipulation des pointeurs, bien que l'accès aux éléments arbitraires nécessite un temps O(n). De nouveaux éléments peuvent être ajoutés à la file d'attente à queue après un élément existant, au début de la file d'attente à queue ou à la fin de la file d'attente à queue. Une structure STAILQ_HEAD est déclarée comme suit :

STAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et TYPE est le type des éléments de la file d'attente à queue. Un pointeur vers la tête de la file d'attente à queue peut être déclaré plus tard comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro STAILQ_HEAD_INITIALIZER évalue un initialiseur pour la file d'attente à queue nommée head.

La macro STAILQ_CONCAT concaténera la file d'attente à queue dirigée par head2 à la fin de la file d'attente à queue dirigée par head1, vidant ainsi tous les éléments de la première.

La macro STAILQ_EMPTY évalue à vrai s'il n'y a aucun élément dans la file d'attente à queue.

La macro STAILQ_ENTRY déclare une structure qui relie les éléments de la file d'attente à queue.

La macro STAILQ_FIRST renvoie le premier élément de la file d'attente à queue ou NULL si la file d'attente à queue est vide.

La macro STAILQ_FOREACH parcourt la file d'attente à queue référencée par head dans le sens avant, assignant chaque élément à var.

La macro STAILQ_FOREACH_FROM fonctionne de manière identique à STAILQ_FOREACH lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans la file d'attente à queue et commence la boucle à partir de var au lieu du premier élément de la file d'attente à queue référencée par head.

La macro STAILQ_FOREACH_SAFE parcourt la file d'attente à queue référencée par head dans le sens avant, assignant chaque élément à var. Cependant, contrairement à STAILQ_FOREACH, il est permis de supprimer var et de la libérer depuis l'intérieur de la boucle en toute sécurité sans interférer avec la trajectoire de parcours.

La macro STAILQ_FOREACH_FROM_SAFE fonctionne de manière identique à STAILQ_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans la file d'attente à queue et commence la boucle à partir de var au lieu du premier élément de la file d'attente à queue référencée par head.

La macro STAILQ_INIT initialise la file d'attente à queue référencée par head.

La macro STAILQ_INSERT_HEAD insère le nouvel élément elm au début de la file d'attente à queue.

La macro STAILQ_INSERT_TAIL insère le nouvel élément elm à la fin de la file d'attente à queue.

La macro STAILQ_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro STAILQ_LAST renvoie le dernier élément de la file d'attente à queue. Si la file d'attente à queue est vide, la valeur renvoyée est NULL.

La macro STAILQ_NEXT renvoie l'élément suivant dans la file d'attente à queue, ou NULL si c'est le dernier.

La macro STAILQ_REMOVE_AFTER supprime l'élément qui suit elm de la file d'attente à queue. Contrairement à STAILQ_REMOVE, cette macro ne parcourt pas toute la file d'attente à queue.

La macro STAILQ_REMOVE_HEAD supprime l'élément au début de la file d'attente à queue. Pour une efficacité optimale, les éléments à supprimer de la tête de la file d'attente à queue doivent explicitement utiliser cette macro plutôt que la macro générique STAILQ_REMOVE.

La macro STAILQ_REMOVE supprime l'élément elm de la file d'attente à queue. Son utilisation doit être évitée car elle parcourt toute la liste. Une file d'attente à double enchaînement doit être utilisée si elle est nécessaire dans des chemins de code à usage intensif ou pour opérer sur de longues listes.

La macro STAILQ_SWAP échange les contenus de head1 et head2.

LISTES

Une liste est dirigée par une structure définie par la macro LIST_HEAD. Cette structure contient un unique pointeur vers le premier élément de la liste. Les éléments sont doublement enlacés, permettant de supprimer n'importe quel élément sans parcourir la liste entière. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant, avant un élément existant ou au début de la liste. Une structure LIST_HEAD est déclarée comme suit :

LIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et TYPE est le type des éléments de la liste. Un pointeur vers la tête de la liste peut être déclaré plus tard comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro LIST_HEAD_INITIALIZER évalue un initialiseur pour la liste nommée head.

La macro LIST_CONCAT concaténera la liste dirigée par head2 à la fin de la liste dirigée par head1, vidant ainsi tous les éléments de la première. Son utilisation doit être évitée car elle parcourt toute la liste dirigée par head1. Une file d'attente à queue doit être utilisée si elle est nécessaire dans des chemins de code à usage intensif ou pour opérer sur de longues listes.

La macro LIST_EMPTY évalue à vrai s'il n'y a aucun élément dans la liste.

La macro LIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro LIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro LIST_FOREACH parcourt la liste référencée par head dans le sens avant, assignant chaque élément à var.

La macro LIST_FOREACH_FROM fonctionne de manière identique à LIST_FOREACH lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans la liste et commence la boucle à partir de var au lieu du premier élément de la liste référencée par head.

La macro LIST_FOREACH_SAFE parcourt la liste référencée par head dans le sens avant, assignant chaque élément à var. Cependant, contrairement à LIST_FOREACH, il est permis de supprimer var et de la libérer depuis l'intérieur de la boucle en toute sécurité sans interférer avec la trajectoire de parcours.

La macro LIST_FOREACH_FROM_SAFE fonctionne de manière identique à LIST_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans la liste et commence la boucle à partir de var au lieu du premier élément de la liste référencée par head.

LISTS

A list is headed by a structure defined by the LIST_HEAD macro. This structure contains a pointer to the first element in the list. The elements are singly linked so that an arbitrary element may be removed without traversing the list. New elements can be added to the list before or after an existing element, or at the head of the list. A LIST_HEAD structure is declared as follows:

LIST_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the list. A pointer to the head of the list can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro LIST_HEAD_INITIALIZER evaluates to an initializer for the list head.

The macro LIST_EMPTY evaluates to true if there are no elements in the list.

The macro LIST_ENTRY declares a structure that connects the elements in the list.

The macro LIST_FIRST returns the first element in the list, or NULL if the list is empty.

The macro LIST_FOREACH traverses the list referenced by head in the forward direction, assigning each element in turn to var.

The macro LIST_FOREACH_FROM behaves identically to LIST_FOREACH when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_FOREACH_SAFE traverses the list referenced by head in the forward direction, assigning each element in turn to var. However, unlike LIST_FOREACH() here it is permitted to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro LIST_FOREACH_FROM_SAFE behaves identically to LIST_FOREACH_SAFE when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_INIT initializes the list referenced by head.

The macro LIST_INSERT_HEAD inserts the new element elm at the head of the list.

The macro LIST_INSERT_AFTER inserts the new element elm after the element listelm.

The macro LIST_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro LIST_NEXT returns the next element in the list, or NULL if this is the last.

The macro LIST_PREV returns the previous element in the list, or NULL if this is the first. List head must contain element elm.

The macro LIST_REMOVE removes the element elm from the list.

The macro LIST_SWAP swaps the contents of head1 and head2.

A tail queue is headed by a structure defined by the TAILQ_HEAD macro. This structure contains a pair of pointers, one to the first element in the tail queue and the other to the last element in the tail queue. The elements are doubly linked so that an arbitrary element can be removed without traversing the tail queue. New elements can be added to the tail queue after an existing element, before an existing element, at the head of the tail queue, or at the end of the tail queue. A TAILQ_HEAD structure is declared as follows:

TAILQ_HEAD(HEADNAME, TYPE) head;

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro TAILQ_HEAD_INITIALIZER evaluates to an initializer for the tail queue head.

The macro TAILQ_CONCAT concatenates the tail queue headed by head2 onto the end of the one headed by head1 removing all entries from the former.

The macro TAILQ_EMPTY evaluates to true if there are no items on the tail queue.

The macro TAILQ_ENTRY declares a structure that connects the elements in the tail queue.

The macro TAILQ_FIRST returns the first item on the tail queue or NULL if the tail queue is empty.

The macro TAILQ_FOREACH traverses the tail queue referenced by head in the forward direction, assigning each element in turn to var. var is set to NULL if the loop completes normally, or if there were no elements.

The macro TAILQ_FOREACH_FROM behaves identically to TAILQ_FOREACH when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.

The macro TAILQ_FOREACH_REVERSE traverses the tail queue referenced by head in the reverse direction, assigning each element in turn to var.

The macro TAILQ_FOREACH_REVERSE_FROM behaves identically to TAILQ_FOREACH_REVERSE when var is NULL, else it treats var as a previously found TAILQ element and begins the reverse loop at var instead of the last element in the TAILQ referenced by head.

The macros TAILQ_FOREACH_SAFE and TAILQ_FOREACH_REVERSE_SAFE traverse the list referenced by head in the forward or reverse direction respectively, assigning each element in turn to var. However, unlike their unsafe counterparts, TAILQ_FOREACH and TAILQ_FOREACH_REVERSE make it possible to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro TAILQ_INIT initializes the tail queue referenced by head.

The macro TAILQ_INSERT_HEAD inserts the new element elm at the head of the tail queue.

The macro TAILQ_INSERT_TAIL inserts the new element elm at the end of the tail queue.

The macro TAILQ_INSERT_AFTER inserts the new element elm after the element listelm.

The macro TAILQ_INSERT_BEFORE inserts the new element elm before the element listelm.
