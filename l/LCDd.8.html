NOM

LCDd - Serveur LCDproc

SYNTAXE

LCDd [-hf] [-c config] [-d driver] [-i bool] [-a addr] [-p port] [-u user] [-w time] [-r level] [-s bool]

DESCRIPTION

LCDd est la partie serveur de LCDproc, un programme démon qui écoute sur un certain port (normalement 13666) et affiche des informations sur un écran LCD. Il fonctionne avec plusieurs types et tailles d'écrans.

La plupart des paramètres de LCDd sont configurés via son fichier de configuration /etc/LCDd.conf, certains pouvant être remplacés en utilisant des options sur la ligne de commande. Avant d'exécuter LCDd, vous devriez lire attentivement ce fichier et modifier tout ce qui est nécessaire selon vos besoins. Sinon, vous pourriez constater que LCDd ne fonctionne pas correctement sur votre système.

Pour utiliser pleinement LCDd, un client tel que lcdproc(1), lcdexec(1), ou lcdvc est requis.

OPTIONS

Options disponibles :

-h
Afficher l'aide
-c config
Utiliser un fichier de configuration différent de /etc/LCDd.conf
-d driver
Spécifier un driver à utiliser (ne sort qu'au premier), remplace le paramètre Driver dans le fichier de configuration [Server].
-f
Exécuter en avant-plan, remplace le paramètre Foreground dans le fichier de configuration [Server]. Par défaut, si non spécifié dans le fichier de configuration, LCDd se transforme en démon pour fonctionner en arrière-plan.
-i bool
Indique s'il faut (1) ou non (0) afficher l'écran LCDproc en rotation d'écran, remplace le paramètre ServerScreen dans le fichier de configuration [Server].
-w waittime
Temps de pause entre chaque écran (en secondes), remplace le paramètre WaitTime dans le fichier de configuration [Server].
-a addr
Lier à l'adresse IP addr, remplace le paramètre Bind dans le fichier de configuration [Server].
-p port
Écouter sur le port port pour les connexions entrantes, remplace le paramètre Port dans le fichier de configuration [Server].
-u user
Exécuter en tant qu'utilisateur user, remplace le paramètre User dans le fichier de configuration [Server].
-s bool
Envoyer les messages à syslog (1) ou à stdout (0), remplace le paramètre ReportToSyslog dans le fichier de configuration [Server].
-r level
Définir le niveau de rapport à level, remplace le paramètre ReportLevel dans le fichier de configuration [Server].

LCDPROC CLIENT-SERVER PROTOCOL

Il existe une séquence de base:

1. Ouvrez une connexion TCP au port du serveur LCDd (normalement 13666).
2. Dites "hello"
3. Le serveur renverra des données sur le type d'écran disponible.
type d'écran
4. Définissez (et utilisez) un nouvel écran et ses widgets.
5. Fermez la connexion une fois que les données ont été affichées.

CLIENT COMMANDS

Il existe de nombreuses commandes à envoyer aux serveurs LCDd:

hello
Démarre une session client-serveur avec le serveur LCDd ; le serveur renverra une chaîne de données détaillant le type d'écran et sa taille.
client_set -name name
Définit le nom du client.
screen_add #id
Ajoute un nouvel écran à l'écran.
screen_del #id
Supprime un écran de l'écran.
screen_set #id [-name name ] [-wid width] [-hgt height] [-priority prio]
Initialise un écran, ou réinitialise ses données.
widget_add #screen #id type [-in #frame]
Ajoute un widget de type type à l'écran #screen.
widget_del #screen #id
Supprime le widget #id de l'écran #screen.
widget_set #screen #id data
Définit les données utilisées pour définir un widget #id sur l'écran #screen.

HEARTBEAT MODES

Les valeurs valides du mode heartbeat (pour la commande screen_set) sont:

on
Afficher un symbole de cœur battant.
off
Afficher un symbole de cœur.
open
Utilise le réglage de battement de cœur du client. C'est la valeur par défaut.

MODES DE RÉTROÉCLAIRAGE

Les valeurs valides pour le mode de rétroéclairage (pour la commande screen_set) sont :

on
Allume le rétroéclairage.
off
Éteint le rétroéclairage.
toggle
Éteint le rétroéclairage s'il est allumé et vice versa.
open
Utilise le réglage de rétroéclairage du client. C'est la valeur par défaut.
blink
Rétroéclairage clignotant.
flash
Rétroéclairage en flash.

Priorités

Les réglages de priorité valides (utilisés dans la commande screen_set) sont les suivants :

input
Le client effectue une saisie interactive.
alert
L'écran a un message important pour l'utilisateur.
foreground
Un client actif.
info
Écran d'information normal, priorité par défaut.
background
L'écran n'est visible que lorsqu'aucun écran d'information normal n'existe.
hidden
L'écran ne sera jamais visible.

Pour assurer la compatibilité avec les anciennes versions de clients, une correspondance de valeurs numériques de priorité est également prise en charge :

1 - 64
foreground
65 - 192
normal
193 - (infini)
background

Un exemple d'utilisation correcte des priorités est le suivant :

Imaginez que vous créez un lecteur MP3 pour lcdproc. Lorsque la chanson change, il est agréable d'afficher immédiatement le nouveau nom. Vous pourriez donc définir la priorité de votre écran sur foreground, attendre que le serveur affiche (ou ignore) votre écran, puis rétablir la priorité de l'écran à normal. Cela aurait pour effet d'afficher l'écran MP3 dès que celui qui est actuellement affiché serait terminé, puis de revenir à la priorité normale par la suite.

Ou, disons que votre client surveille la santé des patients hospitalisés. Si l'un des patients a une crise cardiaque, vous pourriez définir la priorité de l'écran sur alert, et il serait affiché immédiatement. Il n'attendrait même pas que l'écran précédent se termine. De plus, l'affichage resterait allumé la plupart du temps jusqu'à ce que l'utilisateur fasse quelque chose à ce sujet.

TYPES DE WIDGETS

Les widgets peuvent être l'un des suivants :

string
Une chaîne de caractères à afficher (telle quelle).
hbar
Un graphique à barres horizontales.
vbar
Un graphique à barres verticales.
title
Un titre affiché en haut de l'écran, dans une bannière.
icon
Une icône graphique.
scroller
Un affichage de texte déroulant, défilant horizontalement ou verticalement.
frame
Un *conteneur* pour contenir d'autres widgets, permettant de les référencer comme une unité unique. Un widget est placé à l'intérieur d'un cadre en utilisant le paramètre -in #id, où #id fait référence à l'identifiant du cadre.
num
Affiche un grand chiffre décimal.

Les widgets sont dessinés sur l'écran dans l'ordre de leur création.

DÉFINITION DES DONNÉES DES WIDGETS

Dans la commande widget_set, l'argument data dépend du widget qui est défini. Chaque widget prend un ensemble spécifique d'arguments qui définissent sa forme et son comportement :

string x y texte
Affiche texte à la position (x,y).
title texte
Utilise texte comme titre à afficher.
hbar x y longueur
Affiche une barre horizontale commençant à la position (x,y) et ayant une largeur de longueur pixels.
vbar x y longueur
Affiche une barre verticale commençant à la position (x,y) et ayant une hauteur de longueur pixels.
icon x y nom
Affiche l'icône nom à la position (x,y).
scroller gauche haut droite bas direction vitesse texte
Le texte défini défilera dans la direction définie. Les directions valides sont h (horizontal), m (marquee) et v (vertical). La vitesse définit combien de "mouvements" (ou changements) auront lieu par image. Un nombre positif indique des images par mouvement ; un nombre négatif indique des mouvements par image.
frame gauche haut droite bas largeur hauteur dir vitesse
Les cadres définissent une "boîte" visible à l'écran, du coin (gauche, haut) au coin (droite, bas). Les données réelles peuvent être plus grandes, et sont définies par largeur (wid) par hauteur (hgt) ; si elles sont plus grandes, alors le cadre défilera dans la direction (dir) et à la vitesse définies.
num x entier
Affiche le grand chiffre décimal entier à la position horizontale x, qui est une coordonnée x normale sur l'affichage. La valeur spéciale 10 pour entier affiche un double point.

BOGUES

Si LCDd ne semble pas fonctionner comme prévu, essayez de l'exécuter en premier plan avec le niveau de rapport réglé au maximum et le rapport vers stderr. Ceci peut être réalisé sans modifications du fichier de configuration en utilisant la ligne de commande :

LCDd -f -r 5 -s 0
