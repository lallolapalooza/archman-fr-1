NOM

Log::Log4perl::Layout::PatternLayout - Mise en page par modèle

SYNOPSIS

use Log::Log4perl::Layout::PatternLayout;
my $layout = Log::Log4perl::Layout::PatternLayout->new(
                                                 "%d (%F:%L)> %m");

DESCRIPTION

Crée une mise en page par modèle selon http://jakarta.apache.org/log4j/docs/api/org/apache/log4j/PatternLayout.html et quelques extensions spécifiques à Log::Log4perl.

La méthode new() crée une nouvelle PatternLayout, en spécifiant son format de journalisation. La chaîne de format peut contenir un certain nombre de placeholders qui seront remplacés par le moteur de journalisation lorsqu'il sera temps de journaliser le message :

%c Catégorie de l'événement de journalisation.
%C Nom complet du paquet (ou de la classe) de l'appelant
%d Date actuelle au format aaaa/MM/jj hh:mm:ss
%d{...} Date actuelle dans un format personnalisé (voir ci-dessous)
%F Fichier où s'est produit l'événement de journalisation
%H Nom d'hôte (si Sys::Hostname est disponible)
%l Nom complet de la méthode appelante suivi du
   nom du fichier source de l'appelant et du numéro de ligne entre 
   parenthèses.
%L Numéro de ligne dans le fichier où l'instruction de journalisation a été émise
%m Le message à journaliser
%m{chomp} Message de journalisation, sans le saut de ligne final
%m{indent} Message de journalisation, plusieurs lignes indentées pour s'aligner avec la première
%m{indent=n} Message de journalisation, plusieurs lignes indentées de n espaces
%M Méthode ou fonction où la requête de journalisation a été émise
%n Saut de ligne (indépendant du système d'exploitation)
%p Niveau de priorité de l'événement de journalisation (%p{1} affiche la première lettre)
%P ID du processus courant
%r Nombre de millisecondes écoulées depuis le début du programme jusqu'à l'événement de journalisation 
%R Nombre de millisecondes écoulées depuis le dernier événement de journalisation jusqu'à l'événement courant 
%T Trace de la pile des fonctions appelées
%x Le NDC (voir ci-dessous) le plus haut
%X{clé} L'entrée 'clé' du MDC (voir ci-dessous)
%% Un signe pour cent littéral (%)

NDC et MDC sont expliqués dans "Nested Diagnostic Context (NDC)" dans Log::Log4perl et "Mapped Diagnostic Context (MDC)" dans Log::Log4perl.

La granularité des valeurs temporelles est en millisecondes si Time::HiRes est disponible. Sinon, seules les secondes complètes sont utilisées.

De temps en temps, quelqu'un utilise le modèle "%m%n" et fournit en plus un saut de ligne supplémentaire dans le message de journalisation (par exemple, "->log("message\n")". Pour éviter d'imprimer un saut de ligne supplémentaire dans ce cas, PatternLayout va tronquer le message, en n'imprimant qu'un seul saut de ligne. Cette option peut être contrôlée par l'option "message_chomp_before_newline" de PatternLayout. Voir "Options avancées" pour plus de détails.

Quantifier les placeholders

Tous les placeholders peuvent être étendus avec des instructions de formatage, comme dans printf :

%20c   Réserve 20 caractères pour la catégorie, aligne à droite et remplit
       avec des espaces si elle est plus courte
%-20c  Identique à %20c, mais aligne à gauche et remplit le côté droit 
       avec des espaces
%09r   Remplit avec des zéros le nombre de millisecondes sur 9 chiffres
%.8c   Spécifie la largeur maximale du champ et fait en sorte que le formateur
       coupe le reste de la valeur

Ajustement fin avec des accolades

Certains placeholders ont des fonctions spéciales définies si vous ajoutez des accolades avec du contenu après eux :

%c{1}  Affiche uniquement le composant de catégorie le plus à droite, utile dans les hiérarchies
       de classes volumineuses (Foo::Baz::Bar -> Bar)
%c{2}  Affiche uniquement les deux composants de catégorie les plus à droite
       (Foo::Baz::Bar -> Baz::Bar)
%F     Affiche le fichier source, y compris le chemin complet
%F{1}  Affiche uniquement le nom du fichier
%F{2}  Affiche le nom du fichier et le dernier composant du chemin (dir/test.log)
%F{3}  Affiche le nom du fichier et les deux derniers composants du chemin (d1/d2/test.log)
%M     Affiche le nom complet de la méthode/fonction
%M{1}  Affiche uniquement le nom de la méthode (foo)
%M{2}  Affiche le nom de la méthode et le dernier composant du chemin (main::foo)

De cette façon, vous pouvez réduire la catégorie affichée ou limiter les composants de fichier/chemin pour économiser de l'espace dans vos journaux.

Ajustement fin de la date

Si le format par défaut %d pour la date ne vous convient pas, qui ressemble à

aaaa/MM/JJ hh:mm:ss

(qui est légèrement différent de Log4j qui utilise "aaaa-MM-jj hh:mm:ss,SSS") vous êtes libre de l'ajuster pour afficher seulement certaines caractéristiques d'une date, conformément au SimpleDateFormat du monde Java (http://docs.oracle.com/javase/8/docs/api/java/text/SimpleDateFormat.html) :

%d{HH:mm}     "23:45" -- Affiche seulement les heures et les minutes
%d{yy, EEEE}  "02, Lundi" -- Affiche seulement l'année à deux chiffres 
                              et le jour de la semaine épelé
%d{e}         "1473741760" -- Secondes depuis l'époque
%d{h a}       "12 PM"      -- Heure et marqueur am/pm
... et bien d'autres

Pour une liste exhaustive de toutes les fonctionnalités de date supportées, consultez Log::Log4perl::DateFormat.

cspecs personnalisés

Tout d'abord, "cspecs" est l'abréviation de "conversion specifiers" (spécificateurs de conversion), qui est le terme utilisé dans log4j et printf(3) pour ce que Mike appelle "placeholders". J'ai suggéré "cspecs" pour cette partie de l'API avant de voir que Mike utilisait "placeholders" de manière cohérente dans la documentation log4perl. Ah, les joies de la collaboration ;=) --kg

Si le corpus existant de placeholders/cspecs ne vous convient pas, vous pouvez facilement créer les vôtres :

#'U' un cspec global défini par l'utilisateur     
log4j.PatternLayout.cspec.U = sub { return "UID: $< "}

#'K' cspec local à appndr1                 (pid en hexadécimal)
log4j.appender.appndr1.layout.cspec.K = sub { return sprintf "%1x", $$}

#et maintenant vous pouvez les utiliser
log4j.appender.appndr1.layout.ConversionPattern = %K %U %m%n

L'avantage de cette approche est que vous pouvez définir et utiliser les cspecs juste à côté l'un de l'autre dans le fichier de configuration.

Si vous préférez une approche API, il existe également cet appel : 

Log::Log4perl::Layout::PatternLayout::
                add_global_cspec('Z', sub {'zzzzzzzz'}); #sommeil?

Lorsque le message de journalisation est assemblé, votre sous-routine anonyme sera appelée avec ces arguments :

($layout, $message, $category, $priority, $caller_level);

layout: la référence à l'objet PatternLayout qui l'a appelé
message: le message de journalisation (%m)
category: par exemple, groceries.beverages.adult.beer.schlitz
priority: par exemple, DEBUG|WARN|INFO|ERROR|FATAL
caller_level: combien de niveaux remonter dans la pile d'appels 
    pour trouver l'appelant

Veuillez noter que les sous-routines que vous définissez de cette manière seront exécutées dans l'espace de noms "main", donc assurez-vous de qualifier entièrement les fonctions et les variables si elles se trouvent dans des paquets différents. Assurez-vous également que ces sous-routines n'utilisent pas Log4perl, sinon Log4perl entrera dans une récursion infinie.

Avec Log4perl 1.20 et supérieur, les cspecs peuvent être écrits avec des paramètres entre accolades. Écrire quelque chose comme

log4perl.appender.Screen.layout.ConversionPattern = %U{user} %U{id} %m%n

provoquera l'appel de la fonction cspec définie pour %U deux fois, une fois avec le paramètre 'user' et ensuite à nouveau avec le paramètre 'id', et les placeholders dans la chaîne cspec seront remplacés par les valeurs de retour respectives.

La valeur du paramètre est disponible dans l'entrée 'curlies' du premier paramètre passé à la sous-routine (la référence à l'objet layout). Donc, si vous vouliez mapper %U{xxx} à des entrées dans la table de hachage de session POE, vous écririez quelque chose comme :

log4perl.PatternLayout.cspec.U = sub { \
  POE::Kernel->get_active_session->get_heap()->{ $_[0]->{curlies} } }

NOTE DE SÉCURITÉ

Cette fonctionnalité signifie que du code Perl arbitraire peut être intégré dans le fichier de configuration. Dans le cas rare où les personnes ayant accès à votre fichier de configuration sont différentes de celles qui écrivent votre code et ne devraient pas avoir de droits d'exécution, vous pourriez vouloir définir

$Log::Log4perl::Config->allow_code(0);

avant d'appeler init(). Alternativement, vous pouvez fournir un ensemble restreint d'opcodes Perl qui peuvent être intégrés dans le fichier de configuration, comme décrit dans "Restricting what Opcodes can be in a Perl Hook" dans Log::Log4perl.

Options avancées

Le constructeur de la

NOM

Log::Log4perl::Layout::PatternLayout - mise en forme des messages de journalisation dans des chaînes de caractères.

SYNOPIS

  use Log::Log4perl::Layout::PatternLayout;

  my $layout = Log::Log4perl::Layout::PatternLayout->new(
    "%d %p %m%n"
  );

  my $log_message = $layout->format( $log_event );

  # ou en utilisant le paramètre de configuration Log4perl:
  #
  # log4perl.appender.App.layout   = PatternLayout
  # log4perl.appender.App.layout.ConversionPattern = %d %p %m%n

DESCRIPTION

Log::Log4perl::Layout::PatternLayout permet de formater les événements de journalisation en chaînes de caractères selon un modèle spécifié. Le modèle utilise des spécificateurs de conversion, qui sont des séquences de caractères commençant par un signe pourcentage (%).

Voici quelques spécificateurs de conversion courants :

  • %d : La date et l'heure de l'événement de journalisation.
  • %p : La gravité du message (par exemple, DEBUG, INFO, WARN, ERROR, FATAL).
  • %m : Le message de journalisation lui-même.
  • %n : La fin de ligne du système d'exploitation.
  • %c : Le nom de la catégorie (logger).
  • %F : Le nom du fichier dans lequel l'appel de journalisation a été effectué.
  • %L : Le numéro de ligne dans le fichier où l'appel de journalisation a été effectué.
  • %r : Le temps passé depuis le début de l'application, en millisecondes.
  • %t : Le nom du thread qui a émis le message.
  • %% : Un signe pourcentage littéral.

Le constructeur new accepte un argument optionnel : une référence de hachage pour spécifier des options supplémentaires.

my $layout = Log::Log4perl::Layout::PatternLayout->new(
  { time_function       => \&my_time_func,
  },
  "%d (%F:%L)> %m");

Voici une liste des paramètres :

time_function
Accepte une référence à une fonction renvoyant l'heure pour les champs d'heure/date, soit en secondes depuis l'époque, soit sous forme de tableau, contenant les secondes et les microsecondes, tout comme le fait "Time::HiRes::gettimeofday".
message_chomp_before_newline
Si une mise en forme contient le modèle « %m%n » et que le message se termine par une nouvelle ligne, PatternLayout supprimera la nouvelle ligne du message, afin d'éviter l'impression de deux nouvelles lignes. Si cela n'est pas souhaité et que vous voulez deux nouvelles lignes dans ce cas, la fonctionnalité peut être désactivée en définissant l'option "message_chomp_before_newline" sur une valeur fausse :
my $layout = Log::Log4perl::Layout::PatternLayout->new(
    { message_chomp_before_newline => 0
    },
    "%d (%F:%L)> %m%n");

Dans un fichier de configuration Log4perl, la fonctionnalité peut être désactivée comme suit :

log4perl.appender.App.layout   = PatternLayout
log4perl.appender.App.layout.ConversionPattern = %d %m%n
  # Oui, je veux deux nouvelles lignes
log4perl.appender.App.layout.message_chomp_before_newline = 0

Suppression des nouvelles lignes

Si votre code contient des instructions de journalisation comme

  # INCORRECT, ne faites pas ça !
$logger->debug("Un message\n");

il est généralement préférable de supprimer les nouvelles lignes de ces appels. Comme expliqué dans « Logging newlines » dans Log::Log4perl, les instructions de journalisation ne doivent jamais contenir de nouvelles lignes, mais doivent s'appuyer sur les mises en forme des appenders pour ajouter les nouvelles lignes nécessaires.

Si modifier le code n'est pas une option, utilisez le placeholder spécial de PatternLayout %m{chomp} pour faire référence au message sans la nouvelle ligne finale :

log4perl.appender.App.layout.ConversionPattern = %d %m{chomp}%n

Ceci ajoutera une seule nouvelle ligne à chaque message, qu'il soit conforme ou non aux directives de nouvelle ligne de Log4perl (merci à Tim Bunce pour cette idée).

Lignes multiples

Si un message de journalisation se compose de plusieurs lignes, comme

$logger->debug("ligne1\nligne2\nligne3");

par défaut, elles sont journalisées comme suit (en supposant que la mise en forme est définie sur « %d>%m%n » ):

  # mise en forme %d>%m%n
2014/07/27 12:46:16>ligne1
ligne2
ligne3

Si vous préférez que les messages soient alignés comme

  # mise en forme %d>%m{indent}%n
2014/07/27 12:46:16>ligne1
                    ligne2
                    ligne3

utilisez l'option %m{indent} pour le spécificateur %m. Cette option peut également accepter une valeur fixe, comme dans %m{indent=2}, qui décale les lignes suivantes de deux espaces :

  # mise en forme %d>%m{indent=2}%n
2014/07/27 12:46:16>ligne1
  ligne2
  ligne3

Notez que vous pouvez toujours ajouter l'option "chomp" pour le spécificateur %m dans ce cas (voir ci-dessus ce qu'elle fait), ajoutez-la simplement après une virgule de séparation, comme dans %m{indent=2,chomp}.
