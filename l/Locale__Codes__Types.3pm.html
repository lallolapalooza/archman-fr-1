NOM

Locale::Codes::Types - types de jeux de données pris en charge

DESCRIPTION

Ce document contient une description des différents types de jeux de codes pris en charge par la distribution Locale-Codes.

Les types suivants sont pris en charge :

"country"
"language"
"currency"
"script"
"langfam"
"langvar"
"langext"

Chaque fois que vous devez spécifier le type de données, utilisez une des valeurs de cette liste. Lors de l'utilisation de l'interface OO, vous devez spécifier le type de données avec lequel vous travaillez. Par exemple :

use Locale::Codes;
...
$obj->type('country');
$obj->type('langext');

Lors de l'utilisation des interfaces traditionnelles, toutes les fonctions ont le type de données inclus dans le nom de la fonction. Par exemple :

use Locale::Codes::Country;
code2country(...);
use Locale::Codes::LangExt;
code2langext(...);

Chaque type de données peut avoir un nombre quelconque de jeux de codes. Les jeux de codes peuvent être spécifiés par nom. Traditionnellement, une constante perl était exportée et pouvait également être utilisée pour spécifier le jeu de codes.

Les deux méthodes sont disponibles pour les interfaces OO et traditionnelles, donc chaque fois qu'une fonction ou une méthode prend un argument spécifiant un jeu de codes, le nom ou une constante peuvent être utilisés.

Dans les listes ci-dessous, un jeu de codes est spécifié dans la liste en incluant le nom et la constante. Ainsi, par exemple, le premier jeu de codes de pays est nommé 'alpha-2' et a une constante perl "LOCALE_COUNTRY_ALPHA_2" associée. Lors de l'utilisation de l'interface OO, les constantes ne sont disponibles que si vous les importez en chargeant le module avec :

use Locale::Codes ':constants';

Les constantes sont toujours disponibles lors de l'utilisation des interfaces traditionnelles.

Certains des anciens noms de constantes perl n'étaient pas cohérents, et dans ces cas, deux constantes sont disponibles (un nouveau nom cohérent et l'ancien nom incohérent). L'une ou l'autre peut être utilisée.

Le jeu de codes par défaut pour chaque type est marqué d'un astérisque (*).

country

Les jeux de codes pour identifier les pays sont maintenus par plusieurs organismes et normes différents.

Les jeux de codes suivants sont maintenus dans la norme ISO 3166. La page d'accueil officielle de l'agence de maintenance ISO 3166 est : http://www.iso.org/iso/home/standards/country_codes.htm .

Seuls les codes officiellement attribués sont inclus.

* alpha-2, LOCALE_COUNTRY_ALPHA_2, LOCALE_CODE_ALPHA_2
C'est l'ensemble des codes à deux lettres (minuscules) de l'ISO 3166-1, comme 'tv' pour Tuvalu.
alpha-3, LOCALE_COUNTRY_ALPHA_3, LOCALE_CODE_ALPHA_3
C'est l'ensemble des codes à trois lettres (minuscules) de l'ISO 3166-1, comme 'brb' pour la Barbade. Ces codes sont en fait définis et maintenus par la division statistique de l'ONU.
numeric, LOCALE_COUNTRY_NUMERIC, LOCALE_CODE_NUMERIC
C'est l'ensemble des codes numériques à trois chiffres de l'ISO 3166-1, comme 064 pour le Bhoutan.

Si un code à 2 chiffres est saisi, il est converti en 3 chiffres en ajoutant un 0 au début.

Une liste de noms de domaines est maintenue par l'IANA (Internet Assigned Numbers Authority). Ils sont disponibles ici : http://www.iana.org/domains/root/db/ . Seuls les codes pays réels sont utilisés, et les noms de pays proviennent de l'ISO 3166.

dom, LOCALE_COUNTRY_DOM, LOCALE_CODE_DOM
Les domaines pays attribués par l'IANA sont généralement les codes à deux lettres (minuscules) de l'ISO 3166, mais il y a quelques ajouts.

Les Nations Unies maintiennent également des listes de pays. Leur liste est également similaire, mais pas identique, à la liste ISO 3166.

Les données sont disponibles ici : https://unstats.un.org/unsd/methodology/m49/

Auparavant, cette table était traitée comme une source des données ISO 3166, mais j'ai constaté que la table était incomplète, je l'ai donc arrêtée de l'utiliser. Plus tard, elle a été réintégrée comme sa propre liste de codes.

un-alpha-3, LOCALE_COUNTRY_UN_ALPHA_3, LOCALE_CODE_UN_ALPHA_3
Similaire à l'ensemble 'alpha-3' de l'ISO 3166, sauf que les codes sont en majuscules.
un-numeric, LOCALE_COUNTRY_UN_NUMERIC, LOCALE_CODE_UN_NUMERIC
Similaire à l'ensemble 'numeric' de l'ISO 3166.

Le gouvernement américain maintient également une liste de codes. À l'origine, il maintenait le jeu de codes FIPS-11, mais celui-ci a été déprécié et remplacé par le jeu de codes GENC. Les jeux de codes FIPS-11 ne sont plus pris en charge par Locale-Codes.

Les jeux de codes GENC sont disponibles ici : https://nsgreg.nga.mil/genc/discovery . Ils sont également similaires, mais pas identiques, aux jeux de codes ISO 3166.

genc-alpha-2, LOCALE_COUNTRY_GENC_ALPHA_2, LOCALE_CODE_GENC_ALPHA_2
Similaire à l'ensemble 'alpha-2', mais en majuscules.
genc-alpha-3, LOCALE_COUNTRY_GENC_ALPHA_3, LOCALE_CODE_GENC_ALPHA_3
Similaire à l'ensemble 'alpha-3', mais en majuscules.
genc-numeric, LOCALE_COUNTRY_GENC_NUMERIC, LOCALE_CODE_GENC_NUMERIC
Similaire à l'ensemble 'numeric'.

Il existe d'autres sources de codes qui ne sont actuellement pas utilisées dans cette distribution.

Codes ISO pour les subdivisions de pays (états, comtés, provinces, etc.), tels que définis dans ISO 3166-2. Ce module ne fait pas partie de la distribution Locale-Codes, mais est disponible sur CPAN dans CPAN/modules/by-module/Locale/

Le World Factbook maintenu par la CIA est une source potentielle de données. Malheureusement, il ajoute/conserve des codes non standard, il n'est donc pas utilisé comme source de données. https://www.cia.gov/library/publications/the-world-factbook/appendix/appendix-d.html

Une autre source de données non officielle est le site Web Statoids : http://www.statoids.com/wab.html . Actuellement, il n'est pas utilisé pour obtenir des données, mais les notes et le matériel explicatif ont été très utiles pour comprendre les divergences entre les sources.

language

Les jeux de codes pour identifier les langues proviennent de quelques sources différentes.

La source principale est l'ISO 639. Les codes ISO 639-2 sont disponibles ici : http://www.loc.gov/standards/iso639-2/ et les codes ISO 639-5 sont disponibles ici : http://www.loc.gov/standards/iso639-5/ .

De plus, l'IANA maintient un registre des langues qui sont ajoutées aux listes ISO. Parce qu'il est destiné à compléter la norme ISO, la liste IANA n'est pas séparée.

Les données IANA sont disponibles ici : http://www.iana.org/assignments/language-subtag-registry

Les jeux de codes sont :

* alpha-2, LOCALE_LANGUAGE_ALPHA_2, LOCALE_LANG_ALPHA_2
C'est l'ensemble des codes à deux lettres (minuscules) de l'ISO 639-1, comme 'he' pour l'hébreu. Il comprend également des ajouts à cet ensemble inclus dans le registre des langues de l'IANA.
alpha-3, LOCALE_LANGUAGE_ALPHA_3, LOCALE_LANG_ALPHA_3
C'est l'ensemble des codes bibliographiques à trois lettres (minuscules) de l'ISO 639-2 et 639-5, comme 'heb' pour l'hébreu. Il comprend également des ajouts à cet ensemble inclus dans le registre des langues de l'IANA.
term, LOCALE_LANGUAGE_TERM, LOCALE_LANG_TERM
C'est l'ensemble des codes terminologiques à trois lettres (minuscules) de l'ISO 639.

currency

NOM

Locale::Codes

DESCRIPTION

Locale::Codes est un ensemble de codes pour les langues, les devises, les scripts, les familles de langues, les variations de langues, les extensions de langues et les nouveaux ensembles de codes.

pays

Les codes de pays sont une extension des codes de langues, devises, scripts, familles de langues, variations de langues, extensions de langues et nouveaux ensembles de codes.

langue

Les codes de langues sont une extension des codes de langues, devises, scripts, familles de langues, variations de langues, extensions de langues et nouveaux ensembles de codes.

devise

Les codes de devises sont une extension des codes de langues, devises, scripts, familles de langues, variations de langues, extensions de langues et nouveaux ensembles de codes.

script

Les codes de scripts sont une extension des codes de langues, devises, scripts, familles de langues, variations de langues, extensions de langues et nouveaux ensembles de codes.

famille

Les familles de langues sont spécifiées à l'aide des codes ISO 639-5 disponibles ici : http://www.loc.gov/standards/iso639-5/id.php

Les ensembles de codes sont :

* alpha, LOCALE_LANGFAM_ALPHA
Il s'agit d'une collection de codes ISO 639-5 à trois lettres (en minuscules) tels que 'apa' pour les langues Apache.

variation

Les variations de langues sont spécifiées à l'aide des codes du registre des sous-tags de langue IANA disponibles ici : http://www.iana.org/assignments/language-subtag-registry

Les ensembles de codes sont :

* alpha, LOCALE_LANGVAR_ALPHA
Il s'agit d'une collection de codes alphanumériques du registre des sous-tags de langue IANA, tels que 'arevela' pour l'arménien oriental.

extension

Les extensions de langues sont spécifiées à l'aide des codes du registre des sous-tags de langue IANA disponibles ici : http://www.iana.org/assignments/language-subtag-registry

Les ensembles de codes sont :

* alpha, LOCALE_LANGEXT_ALPHA
Il s'agit d'une collection de codes IANA à trois lettres (en minuscules) du registre des sous-tags de langue, tels que 'acm' pour l'arabe mésopotamien.

NOUVEAUX ENSEMBLES DE CODES

Je suis toujours ouvert aux suggestions de nouveaux ensembles de codes.

Pour qu'un ensemble de codes soit ajouté, je souhaite qu'il remplisse les conditions suivantes :

Ensemble de codes d'utilisation générale
Si un ensemble de codes n'est pas d'usage général, je ne suis pas disposé à consacrer du temps à son ajout et à son support.
Source officielle de données
Elle nécessite une source officielle (ou du moins, une source quasi officielle) à partir de laquelle je peux obtenir les données régulièrement.

Idéalement, je ne recevrais des données que d'une seule source officielle, mais parfois ce n'est pas possible. Par exemple, les normes ISO ne sont généralement pas disponibles moyennant paiement, je pourrais donc devoir obtenir certaines données de sources alternatives dont je suis sûr qu'elles obtiennent leurs données de la source officielle. Cependant, je serai toujours prudent quant à l'acceptation d'une source non officielle.

À titre d'exemple, j'obtenais auparavant des données de certains pays du CIA World Factbook. Étant donné le type de source, je suis sûr qu'ils mettent à jour les données à partir de sources officielles et je le considère comme quasi officiel. Cependant, même dans ce cas, j'ai constaté qu'ils ajoutaient des codes qui n'étaient pas dans la norme, j'ai donc cessé de les utiliser comme source.

Il existe de nombreux sites tiers qui maintiennent des listes (plus qu'il n'est pratique de trouver sur les sites officiels). Cependant, je rejetterai la plupart d'entre eux car je n'ai aucune idée de leur caractère « officiel ».

Source gratuite de données
Clairement, les données doivent être gratuites. Je ne suis pas intéressé à payer pour des données (et je ne suis pas intéressé par les frais généraux liés à quelqu'un d'autre qui paie pour des données pour moi).
Source fiable de données
La source des données doit être une source dont je peux m'attendre à ce qu'elle existe dans un avenir proche, car je serai extrêmement réticent à cesser de prendre en charge un ensemble de données une fois qu'il sera inclus.

Je serai également prudent quant à l'acceptation de données qui me sont envoyées par un individu. Bien que j'apprécie l'offre, il n'est tout simplement pas pratique de considérer une contribution individuelle comme une source fiable de données. La source doit être une agence officielle d'une sorte.

Ces exigences sont ouvertes à la discussion. Si vous avez un ensemble de codes que vous souhaitez voir ajouté, mais qui ne répond pas à toutes les exigences ci-dessus, n'hésitez pas à m'envoyer un e-mail et nous pourrons en discuter. Selon les circonstances, il pourrait être possible que j'ignore certains de ces critères.
