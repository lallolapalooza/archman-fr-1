NOM

Log::Log4perl::Catalyst - Module Catalyst de Log::Log4perl

SYNTAXE

Dans votre module d'application Catalyst principal :

use Log::Log4perl::Catalyst;
  # Soit faire en sorte que Log4perl agisse comme le logger par défaut de Catalyst :
__PACKAGE__->log(Log::Log4perl::Catalyst->new());
  # soit utiliser un fichier de configuration Log4perl, en exploitant la pleine
  # fonctionnalité de Log4perl
__PACKAGE__->log(Log::Log4perl::Catalyst->new('l4p.conf'));

... et ensuite parsemer de déclarations de journalisation dans tout code exécuté par Catalyst :

$c->log->debug("Ceci utilise log4perl !");

DESCRIPTION

Ce module fournit des fonctions Log4perl aux applications Catalyst. Il a été inspiré par Catalyst::Log::Log4perl sur CPAN, mais a été entièrement réécrit et utilise une approche différente pour unir Catalyst et Log4perl.

Log4perl fournit des journaux, généralement associés au paquet courant, qui peuvent ensuite être télécommandés par une configuration centrale. Cela signifie que si vous avez une fonction de contrôleur comme

package MyApp::Controller::User;
sub add : Chained('base'): PathPart('add'): Args(0) {
    my ( $self, $c ) = @_;
    $c->log->info("Ajout d'un utilisateur");
    # ...
}

Le contrôle basé sur les niveaux est disponible via les méthodes suivantes :

$c->log->debug("Lecture de la configuration");
$c->log->info("Ajout d'un utilisateur");
$c->log->warn("Impossible de lire la configuration ($!)");
$c->log->error("Impossible d'ajouter l'utilisateur ", $user);
$c->log->fatal("Base de données en panne, interruption de la requête");

Mais ce n'est pas tout, Log4perl est beaucoup plus puissant.

La déclaration de journalisation peut être supprimée ou activée en fonction d'un fichier Log4perl ressemblant à

  # Tous les journaux MyApp ouverts pour DEBUG et au-delà
log4perl.logger.MyApp = DEBUG, Screen
# ...

ou

  # Tous les journaux bloquent les messages en dessous de INFO
log4perl.logger=INFO, Screen
# ...

respectivement. Consultez la page de manuel de Log4perl pour savoir comment effectuer un filtrage précis des niveaux de journalisation et des emplacements, et comment transmettre les messages non seulement à l'écran ou à des fichiers journaux, mais aussi à des bases de données, des expéditeurs d'e-mails, et bien plus encore.

De plus, vous pouvez modifier la mise en page des messages. Par exemple, si vous voulez savoir où une déclaration particulière a été enregistrée, activez les noms de fichiers et les numéros de ligne :

# Fichier de configuration Log4perl
# ...
log4perl.appender.Screen.layout.ConversionPattern = \
      %F{1}-%L: %p %m%n

Les messages ressembleront alors à

MyApp.pm-1869: INFO Sauvegarde du profil utilisateur pour l'utilisateur "wonko"

Ou voulez-vous enregistrer l'adresse IP d'une requête avec chaque déclaration de journalisation ? Aucun problème avec Log4perl, appelez simplement

Log::Log4perl::MDC->put( "ip", $c->req->address() );

au début du cycle de requête et utilisez

# Fichier de configuration Log4perl
# ...
log4perl.appender.Screen.layout.ConversionPattern = \
      [%d]-%X{ip} %F{1}-%L: %p %m%n

comme mise en page Log4perl. Les messages ressembleront à

[2010/02/22 23:25:55]-123.122.108.10 MyApp.pm-1953: INFO Lecture du profil pour l'utilisateur "wonko"

Encore une fois, consultez la page de manuel de Log4perl, il existe une pléthore d'options de configuration.

MÉTHODES

new($config, [%options])
Si appelé sans paramètres, new() initialise Log4perl de manière à ce que les messages soient journalisés de manière similaire au mécanisme de journalisation par défaut de Catalyst. Si vous fournissez une configuration, soit le nom d'un fichier de configuration, soit une référence à une chaîne scalaire contenant la configuration, il appellera Log4perl avec ces paramètres.

Le deuxième paramètre (optionnel) est une liste de paires clé/valeur :

'autoflush'   =>  1   # Journaliser sans mise en tampon ('abort' non supporté)
'watch_delay' => 30   # Si défini, utiliser init_and_watch de L<Log::Log4perl>
_flush()
Vide le cache.
abort($abort)
Efface les tampons internes du système de journalisation sans rien enregistrer.

Utilisation des macros :easy avec Catalyst

Si vous en avez marre de taper

$c->log->debug("...");

et préféreriez utiliser les macros pratiques du mode :easy de Log4perl comme

DEBUG "...";

alors importez simplement ces macros via le mode :easy de Log::Log4perl et commencez à créer :

use Log::Log4perl qw(:easy);
  # ... utiliser les macros plus tard
sub base :Chained('/') :PathPart('apples') :CaptureArgs(0) {
    my ( $self, $c ) = @_;
    DEBUG "Gestion des pommes";
}

Notez la différence entre l'initialisation de Log4perl dans Catalyst, qui utilise le module spécifique à Catalyst Log::Log4perl::Catalyst (en haut de cette page), et l'utilisation des journaux de Log4perl avec les journaux et macros standard de Log::Log4perl. Bien que l'initialisation nécessite que Log4perl effectue une magie noire pour se conformer à la stratégie de journalisation différente de Catalyst, l'obtention des objets journaux de Log4perl ou l'appel de ses macros restent inchangés.

Au lieu d'utiliser la manière de Catalyst de référencer l'objet "contexte" $c pour obtenir des références de journalisation via sa méthode log(), vous pouvez tout aussi bien utiliser get_logger() de Log4perl ou les macros pour accéder aux singleton de journalisation de Log4perl. Le résultat est le même.
