List::Util(3) Documentation des paquets contribués de Perl List::Util(3)

NOM

List::Util - Un ensemble de fonctions utilitaires générales pour les listes

SYNOPSIS

use List::Util qw(
  reduce any all none notall first reductions
  max maxstr min minstr product sum sum0
  pairs unpairs pairkeys pairvalues pairfirst pairgrep pairmap
  shuffle uniq uniqint uniqnum uniqstr head tail zip mesh
);

DESCRIPTION

«List::Util» contient une sélection de fonctions que les utilisateurs ont exprimé souhaiter dans le noyau de Perl, bien que leur utilisation ne soit pas suffisamment fréquente pour justifier l'utilisation d'un mot-clé, et leur taille est si faible qu'il serait inefficace d'en faire des fonctions individuelles dans le répertoire d'extensions.

Par défaut, «List::Util» n'exporte aucune fonction.

FONCTIONS DE RÉDUCTION DE LISTE

Les fonctions suivantes appliquent un bloc de code à une liste de valeurs.

reduce

$result = reduce { BLOCK } @list

Réduit @list en appelant BLOCK dans un contexte scalaire plusieurs fois, en définissant $a et $b à chaque fois. Le premier appel aura $a et $b définis sur les deux premiers éléments de la liste, et les appels suivants seront effectués en remplaçant $a par le résultat de l'appel précédent et $b par l'élément suivant de la liste.

Retourne le résultat du dernier appel à BLOCK. Si @list est vide, undef est retourné. Si @list ne contient qu'un seul élément, cet élément est retourné et BLOCK n'est pas exécuté.

Les exemples suivants montrent comment reduce pourrait être utilisé pour implémenter d'autres fonctions de réduction de liste dans ce module. (Ils ne sont pas implémentés de cette manière, mais de manière plus efficace en fonctions C individuelles).

$foo = reduce { defined($a)            ? $a :
                $code->(local $_ = $b) ? $b :
                                         undef } undef, @list # first
$foo = reduce { $a > $b ? $a : $b } 1..10       # max
$foo = reduce { $a gt $b ? $a : $b } 'A'..'Z'   # maxstr
$foo = reduce { $a < $b ? $a : $b } 1..10       # min
$foo = reduce { $a lt $b ? $a : $b } 'aa'..'zz' # minstr
$foo = reduce { $a + $b } 1 .. 10               # sum
$foo = reduce { $a . $b } @bar                  # concatener
$foo = reduce { $a || $code->(local $_ = $b) } 0, @bar   # any
$foo = reduce { $a && $code->(local $_ = $b) } 1, @bar   # all
$foo = reduce { $a && !$code->(local $_ = $b) } 1, @bar  # none
$foo = reduce { $a || !$code->(local $_ = $b) } 0, @bar  # notall
   # Note: ces implémentations ne coupent pas complètement le court-circuit

Si votre algorithme nécessite que reduce produise une valeur identitaire, assurez-vous de toujours passer cette valeur comme premier argument pour éviter que undef ne soit retourné.

$foo = reduce { $a + $b } 0, @values;             # sum avec valeur identitaire 0

Les blocs de code mentionnés suggèrent également comment utiliser reduce pour construire une version plus efficace de l'une de ces fonctions de base associée à un bloc map. Par exemple, pour trouver la longueur totale de toutes les chaînes d'une liste, on pourrait utiliser :

$total = sum map { length } @strings;

Cependant, cette forme produit des valeurs entières temporaires telles que les longueurs de chaque chaîne de la liste d'origine, uniquement pour les réduire à nouveau à une seule valeur. On peut obtenir le même résultat plus efficacement en utilisant reduce avec un bloc de code qui accumule les longueurs en écrivant ceci plutôt que :

$total = reduce { $a + length $b } 0, @strings

Les autres fonctions de retour scalaire de liste sont des spécialisations de ce concept général.

reductions

@results = reductions { BLOCK } @list

Depuis la version 1.54.

Similaire à reduce, mais renvoie également les valeurs intermédiaires ainsi que le résultat final. Comme précédemment, $a est défini sur le premier élément de la liste donnée, et le bloc de code est appelé une fois pour chaque élément restant de la liste, le résultat étant capturé pour être retourné et devenant la nouvelle valeur de $a.

La liste retournée commencera par la valeur initiale de $a, suivie de chaque valeur retournée par le bloc dans l'ordre. La valeur résultante finale sera identique à celle que la fonction reduce retournerait étant donné le même bloc et la même liste.

reduce     { "$a-$b" } "a".."d"    # "a-b-c-d"
reductions { "$a-$b" } "a".."d"    # "a", "a-b", "a-b-c", "a-b-c-d"

any

my $bool = any { BLOCK } @list;

Depuis la version 1.33.

Similaire à grep en ce sens qu'il évalue BLOCK en assignant $_ à chaque élément de @list. any retourne vrai si un élément fait que BLOCK retourne une valeur vraie. Si BLOCK ne retourne jamais vrai ou si @list est vide, il retourne faux.

De nombreux cas d'utilisation de grep dans des conditions peuvent être écrits en utilisant any, car il peut couper le court-circuit après le premier résultat vrai.

if( any { length > 10 } @strings ) {
    # au moins une chaîne a plus de 10 caractères
}

Note : En raison de problèmes XS, le bloc passé peut accéder directement à @_ externe. Ceci n'est pas intentionnel et échouera sous le débogueur.

all

my $bool = all { BLOCK } @list;

Depuis la version 1.33.

Similaire à any, sauf qu'il exige que tous les éléments de @list fassent retourner vrai à BLOCK. Si un élément retourne faux, il retourne faux. Si le bloc ne retourne jamais faux ou si @list est vide, il retourne vrai.

Note : En raison de problèmes XS, le bloc passé peut accéder directement à @_ externe. Ceci n'est pas intentionnel et échouera sous le débogueur.

none

notall

my $bool = none { BLOCK } @list;
my $bool = notall { BLOCK } @list;

Depuis la version 1.33.

Similaire à any et all, mais avec le sens de retour inversé. none retourne vrai uniquement si aucune valeur dans @list ne fait retourner vrai à BLOCK, et notall retourne vrai uniquement si ce n'est pas tous les valeurs qui le font.

Note : En raison de problèmes XS, le bloc passé peut accéder directement à @_ externe. Ceci n'est pas intentionnel et échouera sous le débogueur.

first

my $val = first { BLOCK } @list;

Similaire à grep en ce sens qu'il évalue BLOCK en assignant $_ à chaque élément de @list. first retourne le premier élément pour lequel le résultat de BLOCK est une valeur vraie. Si BLOCK ne retourne jamais vrai ou si @list est vide, il retourne undef.

$foo

= first { defined($_) } @list # première valeur définie dans @list $foo = first { $_ > $value } @list # valeur dans @list plus grande que $value

max

my $num = max @list;

Renvoie l'élément de la liste ayant la valeur numérique la plus élevée. Si la liste est vide, renvoie "undef".

$foo = max 1..10                # 10
$foo = max 3,9,12               # 12
$foo = max @bar, @baz           # n'importe quelle valeur

maxstr

my $str = maxstr @list;

Similaire à "max", mais traite tous les éléments de la liste comme des chaînes de caractères et renvoie la chaîne la plus élevée selon l'opérateur "gt". Si la liste est vide, renvoie "undef".

$foo = maxstr 'A'..'Z'          # 'Z'
$foo = maxstr "hello","world"   # "world"
$foo = maxstr @bar, @baz        # n'importe quelle valeur

min

my $num = min @list;

Similaire à "max", mais renvoie l'élément de la liste ayant la valeur numérique la plus basse. Si la liste est vide, renvoie "undef".

$foo = min 1..10                # 1
$foo = min 3,9,12               # 3
$foo = min @bar, @baz           # n'importe quelle valeur

minstr

my $str = minstr @list;

Similaire à "min", mais traite tous les éléments de la liste comme des chaînes de caractères et renvoie la chaîne la plus basse selon l'opérateur "lt". Si la liste est vide, renvoie "undef".

$foo = minstr 'A'..'Z'          # 'A'
$foo = minstr "hello","world"   # "hello"
$foo = minstr @bar, @baz        # n'importe quelle valeur

product

my $num = product @list;

Depuis la version 1.35.

Renvoie le produit numérique de tous les éléments de "@list". Si "@list" est vide, renvoie 1.

$foo = product 1..10            # 3628800
$foo = product 3,9,12           # 324

sum

my $num_or_undef = sum @list;

Renvoie la somme numérique de tous les éléments de "@list". Pour des raisons de compatibilité descendante, si "@list" est vide, renvoie "undef".

$foo = sum 1..10                # 55
$foo = sum 3,9,12               # 24
$foo = sum @bar, @baz           # n'importe quelle valeur

sum0

my $num = sum0 @list;

Depuis la version 1.26.

Similaire à "sum", mais renvoie 0 lorsqu'on lui passe une liste vide, au lieu de "undef".

FONCTIONS DE LISTES DE PAIRES CLÉ/VALEUR

L'ensemble de fonctions suivant, toutes inspirées de List::Pairwise, consomment une liste de paires de taille paire. Les paires peuvent être des associations clé-valeur d'un hash ou simplement une liste de valeurs. Toutes les fonctions préservent l'ordre d'origine des paires et ne seront pas déroutées par des paires multiples ayant la même valeur de clé. Elles n'ont même pas besoin que le premier élément de chaque paire soit une chaîne commune.

NOTE: Au moment de la rédaction, les fonctions "pair*" suivantes qui acceptent un bloc ne modifient pas la valeur de $_ dans le bloc, et opèrent plutôt en utilisant les variables globales $a et $b. Cela s'est avéré être une mauvaise conception, car cela empêchait la possibilité de fournir une fonction "pairsort". Il serait préférable de passer des objets de paire similaires sous forme de références à des tableaux de deux éléments dans $_, dans un style similaire à la valeur renvoyée par la fonction "pairs". À l'avenir, ce comportement pourrait être ajouté.

En attendant, les utilisateurs sont avertis de NE PAS dépendre de la valeur de $_ entre l'extérieur et l'intérieur du bloc de contrôle. En particulier, l'exemple suivant est NON SÉCURISÉ:

my @kvlist = ...
foreach (qw( some keys here )) {
   my @items = pairgrep { $a eq $_ } @kvlist;
   ...
}

Écrivez plutôt ceci avec une variable lexicale:

foreach my $key (qw( some keys here )) {
   my @items = pairgrep { $a eq $key } @kvlist;
   ...
}

pairs

my @pairs = pairs @kvlist;

Depuis la version 1.29.

Un moyen pratique d'opérer sur des listes de paires de taille paire, cette fonction renvoie une liste de références de tableaux, contenant chacune deux éléments de la liste donnée. C'est une version plus efficace de

@pairs = pairmap { [ $a, $b ] } @kvlist

Il est plus pratique de l'utiliser dans une boucle "foreach", par exemple:

foreach my $pair ( pairs @kvlist ) {
   my ( $key, $value ) = @$pair;
   ...
}

Depuis la version 1.39, ces références de tableaux sont des objets bien habillés, reconnaissant les méthodes "key" et "value". Le code suivant est équivalent:

foreach my $pair ( pairs @kvlist ) {
   my $key   = $pair->key;
   my $value = $pair->value;
   ...
}

Depuis la version 1.51, elles ont également une méthode "TO_JSON" pour faciliter la sérialisation.

unpairs

my @kvlist = unpairs @pairs

Depuis la version 1.42.

La fonction inverse de "pairs"; cette fonction prend une liste de références de tableaux contenant deux éléments chacune, et renvoie une liste des deux valeurs de chaque paire, dans l'ordre. Ceci est notoirement équivalent à

my @kvlist = map { @{$_}[0,1] } @pairs

bien qu'elle soit implémentée de manière plus efficace en interne. Plus précisément, pour toute entrée, elle extraira exactement deux valeurs pour la liste de sortie ; utilisant "undef" si les références de tableaux d'entrée sont courtes.

Entre "pairs" et "unpairs", une fonction de liste de haut niveau peut être utilisée pour opérer sur les paires en tant que scalaires ; par exemple, les quasi-égalités suivantes des autres fonctions "pair*":

@kvlist = unpairs grep { FUNC } pairs @kvlist
# Comme pairgrep, mais utilise $_ au lieu de $a et $b
@kvlist = unpairs map { FUNC } pairs @kvlist
# Comme pairmap, mais utilise $_ au lieu de $a et $b

Cependant, ces versions ne se comporteront pas aussi bien en contexte scalaire.

Enfin, cette technique peut être utilisée pour implémenter un tri sur une liste de paires clé-valeur ; par exemple:

@kvlist = unpairs sort { $a->key cmp $b->key } pairs @kvlist

pairkeys

my @keys = pairkeys @kvlist;

Depuis la version 1.29.

Un moyen pratique d'opérer sur des listes de paires de taille paire, cette fonction renvoie une liste des premières valeurs de chaque paire dans la liste donnée. C'est une version plus efficace de

@keys = pairmap { $a } @kvlist

pairvalues

my @values = pairvalues @kvlist;

Depuis la version 1.29.

Un moyen pratique d'opérer sur des listes de paires de taille paire, cette fonction renvoie une liste des deuxièmes valeurs de chaque paire dans la liste donnée. C'est une version plus efficace de

@values = pairmap { $b } @kvlist

pairgrep

my @kvlist = pairgrep { BLOCK } @kvlist;
my $count = pairgrep { BLOCK } @kvlist;

Depuis la version 1.29.

Similaire au mot-clé "grep" de Perl, mais interprète la liste donnée comme une liste de paires de taille paire. Il invoque le bloc "BLOCK" plusieurs fois, en contexte scalaire, avec "$a" et "$b" définis aux paires successives de valeurs de "@kvlist".

Il renvoie une liste de paires de taille paire pour lesquelles le bloc "BLOCK" renvoie vrai en contexte de liste, ou le nombre de paires en contexte scalaire (la taille de la liste des paires est le double). (Notez, par conséquent, qu'en contexte scalaire, il renvoie un nombre qui est la moitié de la taille des éléments de liste qu'il aurait renvoyé en contexte de liste).

@subset = pairgrep { $a =~ m/^[[:upper:]]+$/ } @kvlist

Comme avec "grep", il aliasse "$_" aux éléments de la liste ; "pairgrep" aliasse "$a" et "$b" aux éléments de la liste donnée. Toute modification de cette liste par le code du bloc sera visible par l'appelant.

pairfirst

my ( $key, $val ) = pairfirst { BLOCK } @kvlist;
my $found = pairfirst { BLOCK } @kvlist;

Depuis la version 1.30.

Similaire à la fonction "first", mais interprète la liste donnée comme une liste de paires de taille paire. Il invoque le bloc "BLOCK" plusieurs fois, en contexte scalaire, avec "$a" et "$b" définis aux paires successives de valeurs de "@kvlist".

Il renvoie la première paire de valeurs de la liste pour laquelle le bloc "BLOCK" renvoie vrai en contexte de liste, ou une liste vide si aucune paire de ce type n'a été trouvée. En contexte scalaire, il renvoie une valeur booléenne simple, au lieu de la clé ou de la valeur trouvée.

( $key, $value ) = pairfirst { $a =~ m/^[[:upper:]]+$/ } @kvlist

Comme avec "grep", il aliasse "$_" aux éléments de la liste ; "pairfirst" aliasse "$a" et "$b" aux éléments de la liste donnée. Toute modification de cette liste par le code du bloc sera visible par l'appelant.

AUTRES FONCTIONS

pairmap

my @list = pairmap { BLOCK } @kvlist;
my $count = pairmap { BLOCK } @kvlist;

Depuis la version 1.29.

Similaire au mot-clé "map" de Perl, mais interprète la liste donnée comme une liste de paires de taille paire. Il appelle le "BLOCK" plusieurs fois, en contexte de liste, avec $a et $b définis sur des paires successives de valeurs de la @kvlist.

Renvoie la concaténation de toutes les valeurs renvoyées par le "BLOCK" en contexte de liste, ou le nombre d'éléments qui auraient été renvoyés en contexte scalaire.

@result = pairmap { "La clé $a a la valeur $b" } @kvlist

Comme avec "map" qui aliase $_ aux éléments de la liste, "pairmap" aliase $a et $b aux éléments de la liste donnée. Toute modification de ceux-ci par le bloc de code sera visible par l'appelant.

Voir "BOGUES CONNUS" pour un bogue connu avec "pairmap" et une solution de contournement.

AUTRES FONCTIONS

shuffle

my @values = shuffle @values;

Renvoie les valeurs de l'entrée dans un ordre aléatoire.

@cards = shuffle 0..51      # 0..51 dans un ordre aléatoire

Cette fonction est affectée par la variable $RAND.

sample

my @items = sample $count, @values

Depuis la version 1.54.

Sélectionne aléatoirement le nombre d'éléments donné à partir de la liste d'entrée. Toute position donnée dans la liste d'entrée sera sélectionnée au plus une fois.

S'il y a moins de $count éléments dans la liste, alors la fonction renverra une fois qu'ils auront tous été sélectionnés aléatoirement ; effectivement, la fonction se comporte de manière similaire à "shuffle".

Cette fonction est affectée par la variable $RAND.

uniq

my @subset = uniq @values

Depuis la version 1.45.

Filtre une liste de valeurs pour supprimer les doublons subséquents, selon un test d'égalité de chaîne de caractères DWIM-ish ou un test "undef". Préserve l'ordre des éléments uniques et conserve la première valeur de tout ensemble de doublons.

my $count = uniq @values

En contexte scalaire, renvoie le nombre d'éléments qui auraient été renvoyés sous forme de liste.

La valeur "undef" est traitée par cette fonction comme distincte de la chaîne vide, et aucun avertissement ne sera produit. Elle est laissée telle quelle dans la liste renvoyée. Les valeurs "undef" subséquentes sont toujours considérées comme identiques à la première et seront supprimées.

uniqint

my @subset = uniqint @values

Depuis la version 1.55.

Filtre une liste de valeurs pour supprimer les doublons subséquents, selon un test d'égalité numérique entière. Préserve l'ordre des éléments uniques et conserve la première valeur de tout ensemble de doublons. Les valeurs de la liste renvoyée seront converties en entiers.

my $count = uniqint @values

En contexte scalaire, renvoie le nombre d'éléments qui auraient été renvoyés sous forme de liste.

Notez que "undef" est traité de manière similaire à d'autres opérations numériques ; il est égal à zéro mais produit en outre un avertissement si de tels avertissements sont activés ("use warnings 'uninitialized';"). De plus, un "undef" dans la liste renvoyée est converti en un zéro numérique, de sorte que toute la liste de valeurs renvoyée par "uniqint" se comporte bien en tant qu'entiers.

uniqnum

my @subset = uniqnum @values

Depuis la version 1.44.

Filtre une liste de valeurs pour supprimer les doublons subséquents, selon un test d'égalité numérique. Préserve l'ordre des éléments uniques et conserve la première valeur de tout ensemble de doublons.

my $count = uniqnum @values

En contexte scalaire, renvoie le nombre d'éléments qui auraient été renvoyés sous forme de liste.

Notez que "undef" est traité de manière similaire à d'autres opérations numériques ; il est égal à zéro mais produit en outre un avertissement si de tels avertissements sont activés ("use warnings 'uninitialized';"). De plus, un "undef" dans la liste renvoyée est converti en un zéro numérique, de sorte que toute la liste de valeurs renvoyée par "uniqnum" se comporte bien en tant que nombres.

Notez également que plusieurs valeurs IEEE "NaN" sont traitées comme des doublons les unes des autres, quelles que soient les différences dans leurs charges utiles, et ce malgré le fait que "0+'NaN' == 0+'NaN'" renvoie faux.

uniqstr

my @subset = uniqstr @values

Depuis la version 1.45.

Filtre une liste de valeurs pour supprimer les doublons subséquents, selon un test d'égalité de chaîne de caractères. Préserve l'ordre des éléments uniques et conserve la première valeur de tout ensemble de doublons.

my $count = uniqstr @values

En contexte scalaire, renvoie le nombre d'éléments qui auraient été renvoyés sous forme de liste.

Notez que "undef" est traité de manière similaire à d'autres opérations de chaîne ; il est égal à la chaîne vide mais produit en outre un avertissement si de tels avertissements sont activés ("use warnings 'uninitialized';"). De plus, un "undef" dans la liste renvoyée est converti en une chaîne vide, de sorte que toute la liste de valeurs renvoyée par "uniqstr" se comporte bien en tant que chaînes de caractères.

head

my @values = head $size, @list;

Depuis la version 1.50.

Renvoie les $size premiers éléments de @list. Si $size est négatif, renvoie tous les éléments sauf les $size derniers éléments de @list.

@result = head 2, qw( foo bar baz );
# foo, bar
@result = head -2, qw( foo bar baz );
# foo

tail

my @values = tail $size, @list;

Depuis la version 1.50.

Renvoie les $size derniers éléments de @list. Si $size est négatif, renvoie tous les éléments sauf les $size premiers éléments de @list.

@result = tail 2, qw( foo bar baz );
# bar, baz
@result = tail -2, qw( foo bar baz );
# baz

zip

my @result = zip [1..3], ['a'..'c'];
# [1, 'a'], [2, 'b'], [3, 'c']

Depuis la version 1.56.

Renvoie une liste de références de tableaux, composées d'éléments provenant de la liste de références de tableaux donnée. Chaque tableau de la liste renvoyée est composé d'éléments à la position correspondante de chacun des tableaux d'entrée. Si un tableau d'entrée manque d'éléments avant les autres, alors "undef" sera inséré dans le résultat pour combler les manques.

La fonction "zip" est particulièrement utile pour itérer sur plusieurs tableaux en même temps avec une boucle "foreach", en prenant un élément de chacun :

foreach ( zip \@xs, \@ys, \@zs ) {
    my ($x, $y, $z) = @$_;
    ...
}

NOTE aux utilisateurs de List::MoreUtils : Cette fonction ne se comporte pas de la même manière que "List::MoreUtils::zip", mais est en réalité un équivalent non prototypé de "List::MoreUtils::zip_unflatten". Cette fonction n'applique pas de prototype, donc assurez-vous de l'invoquer avec des références de tableaux.

Pour une fonction similaire à la fonction "zip" de "List::MoreUtils", voir mesh.

my @result = zip_shortest ...

Une variation de la fonction qui diffère dans son comportement lorsqu'elle reçoit des tableaux d'entrée de longueurs différentes. "zip_shortest" s'arrêtera dès que l'un des tableaux d'entrée manquera d'éléments, en supprimant toutes les valeurs restantes non utilisées des autres.

my @result = zip_longest ...

"zip_longest" est un alias pour la fonction "zip", fourni simplement pour être explicite sur ce comportement par rapport à "zip_shortest".

mesh

my @result = mesh [1..3], ['a'..'c'];
# (1, 'a', 2, 'b', 3, 'c')

Depuis la version 1.56.

Renvoie une liste d'éléments collectés à partir des éléments de la liste donnée de références de tableaux. Chaque section d'éléments dans la liste renvoyée est composée d'éléments à la position correspondante de chacun des tableaux d'entrée. Si un tableau d'entrée manque d'éléments avant les autres, alors "undef" sera inséré dans le résultat pour combler les manques.

C'est similaire à zip, sauf que toutes les plages du résultat sont renvoyées dans une seule longue liste aplatie, au lieu d'être regroupées dans des tableaux séparés.

Parce qu'il renvoie une liste plate d'éléments, la fonction "mesh" est particulièrement utile pour construire une table de hachage à partir de deux tableaux séparés de clés et de valeurs :

my %hash = mesh \@keys, \@values;
my $href = { mesh \@keys, \@values };

NOTE aux utilisateurs de List::MoreUtils : Cette fonction est un équivalent non prototypé de "List::MoreUtils::mesh

" ou "List::MoreUtils::zip" (eux-mêmes alias l'un de l'autre). Cette fonction n'applique pas de prototype, donc assurez-vous de l'invoquer avec des références à des tableaux.

my @result = mesh_shortest ...
my @result = mesh_longest ...

Ces variations sont similaires à celles de zip, en ce qu'elles diffèrent par leur comportement lorsqu'une des listes d'entrée est épuisée avant les autres.

VARIABLES DE CONFIGURATION

$RAND

local $List::Util::RAND = sub { ... };

Depuis la version 1.54.

Cette variable de paquet est utilisée par le code qui a besoin de générer des nombres aléatoires (comme les fonctions "shuffle" et "sample"). Si elle est définie sur une référence CODE, elle fournit une alternative à la fonction intégrée rand() de perl. Lorsqu'un nouveau nombre aléatoire est nécessaire, cette fonction sera invoquée sans arguments et est censée retourner une valeur flottante, dont seule la partie fractionnaire sera utilisée.

BOGUES CONNUS

RT #95409

https://rt.cpan.org/Ticket/Display.html?id=95409

Si le bloc de code donné à "pairmap" contient des variables lexicales qui sont capturées par une fermeture renvoyée, et que la fermeture est exécutée après que le bloc a été réutilisé pour l'itération suivante, ces variables lexicales ne verront pas les valeurs correctes. Par exemple :

my @subs = pairmap {
   my $var = "$a is $b";
   sub { print "$var\n"; }
} one => 1, two => 2, three => 3;
$_->() for @subs;

Imprimera incorrectement

three is 3
three is 3
three is 3

Ceci est dû à l'optimisation des performances de l'utilisation de "MULTICALL" pour le bloc de code, ce qui signifie que de nouveaux SVs ne sont pas alloués pour chaque appel au bloc. Au lieu de cela, le même SV est réaffecté pour chaque itération, et toutes les fermetures partageront la valeur vue lors de la dernière itération.

Pour contourner ce bogue, entourez le code d'un deuxième ensemble d'accolades. Cela crée un bloc intérieur qui déjoue la logique de "MULTICALL", et obtient de nouveaux SVs alloués à chaque fois :

my @subs = pairmap {
   {
      my $var = "$a is $b";
      sub { print "$var\n"; }
   }
} one => 1, two => 2, three => 3;

Ce bogue n'affecte que les fermetures qui sont générées par le bloc mais utilisées par la suite. Les variables lexicales qui ne sont utilisées que pendant la durée de l'exécution du bloc prendront leurs valeurs individuelles pour chaque invocation, comme normalement.

uniqnum() sur des bignums surdimensionnés

En raison de la manière dont uniqnum() compare les nombres, il ne peut pas distinguer les différences entre les bignums (en particulier les bigints) qui sont trop grands pour tenir dans les types natifs de la plateforme. Par exemple, 

my $x = Math::BigInt->new( "1" x 100 );
my $y = $x + 1;
say for uniqnum( $x, $y );

Imprimera uniquement la valeur de $x, croyant que $y est une valeur numériquement équivalente. Ce bogue n'affecte pas uniqstr(), qui observera correctement que les deux valeurs se transforment en chaînes de caractères différentes.
