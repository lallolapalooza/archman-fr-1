NOM

Log::Log4perl::Appender - Classe d'appender de log

SYNTAXE

use Log::Log4perl;
    # Définir un logger
my $logger = Log::Log4perl->get_logger("abc.def.ghi");
    # Définir un layout
my $layout = Log::Log4perl::Layout::PatternLayout->new(
                 "%d (%F:%L)> %m");
    # Définir un appender
my $appender = Log::Log4perl::Appender->new(
                 "Log::Log4perl::Appender::Screen",
                 name => 'dumpy');
    # Configurer le layout de l'appender
$appender->layout($layout);
$logger->add_appender($appender);

DESCRIPTION

Cette classe est une couche qui encapsule la classe d'appender "Log::Log4perl::Appender" de la collection.

Elle supporte également les collections d'appenders de "Log::Dispatch::*". La librairie masque les aspects étranges de "Log::Dispatch" (par exemple, chaque dispatcher doit avoir un nom, mais il n'y a aucun moyen de le récupérer) de "Log::Log4perl" et recycle les types d'appenders déjà créés et éprouvés dans "Log::Dispatch".

FONCTIONS

Log::Log4perl::Appender->new($dispatcher_class_name, ...);

La fonction new() prend le nom de la classe d'appender à créer comme un argument chaîne (!) suivi éventuellement de paramètres spécifiques à l'appender, par exemple :

    # Définir un appender
my $appender = Log::Log4perl::Appender->new(
    "Log::Log4perl::Appender::File"
    filename => 'out.log');

Dans le cas des appenders de "Log::Dispatch", si le paramètre "name" n'est pas spécifié, l'objet appender créera un nom unique (format "appNNN"), qui peut être récupéré plus tard via la méthode name() :

print "Le nom de l'appender est ", $appender->name(), "\n";

D'autres paramètres sont spécifiques à la classe d'appender utilisée. Dans l'exemple ci-dessus, le paramètre "filename" spécifie le nom de l'appender "Log::Log4perl::Appender::File" utilisé.

Cependant, si vous utilisez un appender de "Log::Dispatch::Email" pour envoyer des e-mails, vous devrez spécifier les adresses e-mail "from" et "to". Chaque appender est différent. Veuillez consulter la documentation de "Log::Dispatch::*" pour les détails sur les exigences spécifiques de l'appender utilisé.

La fonction new() passera simplement ces paramètres à un objet appender "Log::Dispatch::*" de la classe spécifiée.

Lorsqu'il s'agit de logs, l'appender "Log::Log4perl::Appender" relaye de manière transparente tous les messages via l'objet appender "Log::Dispatch::*" qu'il contient.

$appender->layout($layout);

La méthode layout() établit le format de log utilisé par l'appender, qui est passé comme un objet de la classe "Log::Log4perl::Layout::*". Actuellement, deux layouts sont disponibles :

Log::Log4perl::Layout::SimpleLayout
Log::Log4perl::Layout::PatternLayout

Veuillez consulter les pages de documentation de "Log::Log4perl::Layout::SimpleLayout" et "Log::Log4perl::Layout::PatternLayout" pour plus de détails.

Paramètres transmis à la méthode log() de l'appender

Lorsque la méthode log() de l'appender est appelée, Log::Log4perl transmet une liste de paires clé/valeur. Les entrées correspondant aux paires suivantes sont garanties d'être présentes :

message
Texte du message rendu.
log4p_category
Nom de la catégorie du logger qui a déclenché l'événement.
log4p_level
Niveau de log Log::Log4perl de l'événement.

Pièges à éviter

Étant donné que l'appender "Log::Dispatch::File" tronque les fichiers de log par défaut et que la plupart du temps ce n'est pas ce que vous souhaitez, nous avons indiqué à "Log::Log4perl" de modifier ce comportement, en passant le paramètre "mode => append" sous le capot. Ainsi, avec "Log::Log4perl" 0.23, une configuration comme :

log4perl.category = INFO, FileAppndr
log4perl.appender.FileAppndr          = Log::Dispatch::File
log4perl.appender.FileAppndr.filename = test.log
log4perl.appender.FileAppndr.layout   = Log::Log4perl::Layout::SimpleLayout

va toujours *ajouter* à un fichier de log existant "test.log" alors que si vous spécifiez comme ceci :

log4perl.category = INFO, FileAppndr
log4perl.appender.FileAppndr          = Log::Dispatch::File
log4perl.appender.FileAppndr.filename = test.log
log4perl.appender.FileAppndr.mode     = write
log4perl.appender.FileAppndr.layout   = Log::Log4perl::Layout::SimpleLayout

va *écraser* un fichier de log existant "test.log" et recommencer à zéro.

Appendeurs attendant des fragments de message

Au lieu de chaînes simples, certains appendeurs attendent plusieurs champs comme corps de messages de log. Si une déclaration comme

$logger->debug($ip, $user, "signed in");

provoque l'activation d'un appender comme "Log::Log4perl::Appender::Screen", l'appender utilisera simplement la concaténation des trois corps de message qui lui sont passés pour former une seule chaîne. Les corps seront séparés par une chaîne définie dans

$Log::Log4perl::JOIN_MSG_ARRAY_CHAR
(par défaut, c'est la chaîne vide "").

Cependant, différents appendeurs peuvent interpréter le message ci-dessus différemment : un appender comme "Log::Log4perl::Appender::DBI" pourrait placer les trois arguments passés au logger dans trois champs séparés dans la base de données.

L'option "warp_message" de l'appender est utilisée pour spécifier le comportement désiré. Si aucune valeur n'est définie pour la propriété de l'appender

# *** Non défini ***
# log4perl.appender.SomeApp.warp_message

dans le fichier de configuration Log4perl, l'appender référencé par "SomeApp" reviendra au comportement standard et concaténera tous les corps de message, en les séparant par

$Log::Log4perl::JOIN_MSG_ARRAY_CHAR
.

Log::Log4perl::Appender(3pm)

Version 2.07 du 2021-01-27

NOM

Log::Log4perl::Appender - classe de base des appenders

SYNOPSIS

use Log::Log4perl::Appender;

# Créer un nouveau composant appender
my $appender = Log::Log4perl::Appender->new();

# Configurer le niveau de sévérité pour l'appender
$appender->level($level);

# Définir le niveau de sévérité pour l'appender à partir d'une chaîne
$appender->level(Log::Log4perl::Level::INFO);

# Récupérer le niveau de sévérité de l'appender
my $level = $appender->level();

# Définir un layout
$appender->layout($layout);

# Récupérer le layout
my $layout = $appender->layout();

# Créer un appender de test
my $appender = Log::Log4perl::Appender::Test::TestAppender->new(
    'test_appender',
    Log::Log4perl::Layout::PatternLayout->new(
        '%d %p %m%n'
    )
);

DESCRIPTION

Dans Log4perl, un Appender est responsable de l'envoi des messages de log aux destinations souhaitées. Par exemple, un FileAppender écrit les messages dans un fichier, un SocketAppender les envoie via le réseau, et un ScreenAppender les affiche sur la sortie standard.

La classe Log::Log4perl::Appender est la classe de base pour tous les appenders. Elle fournit des méthodes communes pour la configuration et le contrôle des appenders, telles que la définition du niveau de sévérité et l'attachement d'un objet layout.

Les objets appender sont généralement créés via la méthode new(), qui accepte des arguments pour spécifier le nom de l'appender et, éventuellement, son layout. Les appenders spécifiques (par exemple, FileAppender, ScreenAppender) sont créés en utilisant leurs noms de classe correspondants.

Chaque appender possède un niveau de sévérité associé. Les messages dont la sévérité est inférieure au niveau de l'appender ne seront pas traités par cet appender.

Un Layout est utilisé pour formater les messages de log avant qu'ils ne soient envoyés par l'appender. La classe Log::Log4perl::Appender gère l'association d'un layout à un appender.

MÉTHODES

new(NAME, LAYOUT)
Constructeur pour la classe Log::Log4perl::Appender. Les sous-classes peuvent définir leurs propres constructeurs pour accepter des arguments de configuration spécifiques.
level(LEVEL)
Définit le niveau de sévérité de l'appender. Le paramètre LEVEL doit être l'un des niveaux définis dans Log::Log4perl::Level (par exemple, DEBUG, INFO, WARN, ERROR, FATAL).
level()
Récupère le niveau de sévérité actuel de l'appender.
layout(LAYOUT)
Définit l'objet layout à utiliser pour formater les messages de log.
layout()
Récupère l'objet layout actuel de l'appender.
is_enabled_for(LEVEL)
Retourne vrai (true) si le niveau de sévérité de l'appender est supérieur ou égal au niveau spécifié, indiquant que l'appender devrait traiter ce message. Sinon, retourne faux (false).
do_log(REMOTE_OBJECT, LOG_EVENT)
Cette méthode est appelée par la classe Logger pour effectuer la journalisation réelle. Elle est responsable de la mise en forme du message à l'aide du layout et de son écriture dans la destination de l'appender. Les sous-classes doivent implémenter cette méthode pour fournir leur comportement de journalisation spécifique.
name()
Retourne le nom de l'appender.

Paramètres passés à la méthode log() de l'appender

La méthode do_log() reçoit deux arguments :

  • REMOTE_OBJECT : Une référence à l'objet logger qui a appelé cette méthode.
  • LOG_EVENT : Un objet Log::Log4perl::LogEvent qui contient toutes les informations sur l'événement de log, y compris le niveau, le message, la classe et la méthode d'où il provient, et le timestamp.

Pièges courants

  • Niveau de sévérité incorrect : Assurez-vous que le niveau de sévérité de l'appender est configuré correctement pour capturer les messages souhaités. Si le niveau est trop élevé, certains messages peuvent ne pas être enregistrés.
  • Layout manquant ou incorrect : Sans layout, les messages seront probablement enregistrés dans leur format brut. Vérifiez que le layout est correctement configuré et qu'il correspond au format de sortie désiré.
  • Permissions des fichiers : Si vous utilisez un FileAppender, assurez-vous que le processus a les permissions d'écriture nécessaires dans le répertoire et pour le fichier de destination.

Appenders attendant des morceaux de message

Certains appenders, notamment ceux qui impliquent la mise en réseau ou l'écriture dans des fichiers tamponnés, peuvent recevoir le message de log en plusieurs parties. La méthode do_log() doit être conçue pour gérer ces cas, en concaténant les parties si nécessaire avant de les écrire ou de les envoyer.

La classe de base Log::Log4perl::Appender ne gère pas directement la segmentation des messages. C'est la responsabilité des appenders spécifiques d'implémenter cette logique si nécessaire. Un mécanisme courant consiste à utiliser un tampon interne dans l'appender et à le vider lorsqu'un message complet est reçu ou lorsqu'une opération de vidage est déclenchée.
