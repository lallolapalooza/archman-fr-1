List::UtilsBy(3) Documentation Perl fournie par l'utilisateur List::UtilsBy(3)

NOM

"List::UtilsBy" - fonctions utilitaires de liste d'ordre supérieur

SYNOPSIS

use List::UtilsBy qw( nsort_by min_by );
use File::stat qw( stat );
my @files_by_age = nsort_by { stat($_)->mtime } @files;
my $shortest_name = min_by { length } @names;

DESCRIPTION

Ce module fournit un certain nombre de fonctions utilitaires de liste, qui prennent toutes un bloc de code initial pour contrôler leur comportement. Ce sont des variations sur des fonctions de base similaires de Perl ou de "List::Util" de noms similaires, mais qui utilisent le bloc pour contrôler leur comportement. Par exemple, la fonction de base de Perl "sort" prend une liste de valeurs et les retourne, triées selon leur valeur de chaîne. La fonction "sort_by" les trie selon la valeur de chaîne retournée par la fonction supplémentaire, lorsqu'elle reçoit chaque valeur.

my @names_sorted = sort @names;
my @people_sorted = sort_by { $_->name } @people;

FONCTIONS

Toutes les fonctions ajoutées depuis la version 0.04, sauf indication contraire, car les noms originaux des versions précédentes ont été renommés.

sort_by

@vals = sort_by { KEYFUNC } @vals

Retourne la liste des valeurs triées selon les valeurs de chaîne retournées par le bloc ou la fonction "KEYFUNC". Une utilisation typique peut être de trier des objets selon la valeur de chaîne d'un accesseur, tel que

sort_by { $_->name } @people

La fonction clé est appelée en contexte scalaire, recevant chaque valeur successivement comme $_ et comme seul argument dans les paramètres, @_. Les valeurs sont ensuite triées selon des comparaisons de chaînes sur les valeurs retournées.

Ceci est équivalent à

sort { $a->name cmp $b->name } @people

sauf que cela garantit que l'accesseur "name" ne sera exécuté qu'une seule fois par valeur.

Un cas d'utilisation intéressant est de trier des chaînes qui peuvent contenir des nombres intégrés de manière "naturelle", plutôt que lexicalement.

sort_by { s/(\d+)/sprintf "%09d", $1/eg; $_ } @strings

Ceci trie des chaînes en générant des clés de tri qui complètent avec des zéros les nombres intégrés jusqu'à un certain niveau (9 chiffres dans ce cas), aidant à assurer que le tri lexical les place dans le bon ordre.

nsort_by

@vals = nsort_by { KEYFUNC } @vals

Similaire à "sort_by" mais compare ses valeurs clés numériquement.

rev_sort_by

rev_nsort_by

@vals = rev_sort_by { KEYFUNC } @vals
@vals = rev_nsort_by { KEYFUNC } @vals

Depuis la version 0.06.

Similaire à "sort_by" et "nsort_by" mais retourne la liste dans l'ordre inverse. Équivalent à

@vals = reverse sort_by { KEYFUNC } @vals

sauf que ces fonctions sont légèrement plus efficaces car elles évitent l'opération finale de "reverse".

max_by

$optimal = max_by { KEYFUNC } @vals
@optimal = max_by { KEYFUNC } @vals

Retourne la (première) valeur de @vals qui donne le résultat numériquement le plus élevé de la fonction clé.

my $tallest = max_by { $_->height } @people
use File::stat qw( stat );
my $newest = max_by { stat($_)->mtime } @files;

En contexte scalaire, la première valeur maximale est retournée. En contexte liste, une liste de toutes les valeurs maximales est retournée. Ceci peut être utilisé pour obtenir des positions autres que la première, si l'ordre est significatif.

Si appelée sur une liste vide, une liste vide est retournée.

Par symétrie avec la fonction "nsort_by", ceci est également fourni sous le nom "nmax_by" car il se comporte numériquement.

min_by

$optimal = min_by { KEYFUNC } @vals
@optimal = min_by { KEYFUNC } @vals

Similaire à "max_by" mais retourne les valeurs qui donnent le résultat numériquement le plus bas de la fonction clé. Également fourni sous le nom "nmin_by".

minmax_by

( $minimal, $maximal ) = minmax_by { KEYFUNC } @vals

Depuis la version 0.11.

Similaire à l'appel de "min_by" et "max_by" avec la même fonction clé sur la même liste. Cette version est plus efficace que d'appeler les deux autres fonctions individuellement, car elle a moins de travail à effectuer au total. En cas d'égalité, seul le premier élément optimal trouvé dans chaque cas est retourné. Également fourni sous le nom "nminmax_by".

uniq_by

@vals = uniq_by { KEYFUNC } @vals

Retourne une liste du sous-ensemble de valeurs pour lesquelles le bloc de fonction clé retourne des valeurs uniques. La première valeur produisant une clé donnée est choisie, les valeurs ultérieures sont rejetées.

my @some_fruit = uniq_by { $_->colour } @fruit;

Pour sélectionner à la place la dernière valeur par clé, inversez la liste d'entrée. Si l'ordre des résultats est significatif, n'oubliez pas d'inverser également le résultat :

my @some_fruit = reverse uniq_by { $_->colour } reverse @fruit;

Étant donné que les valeurs retournées par la fonction clé sont utilisées comme clés de hachage, elles devraient être soit des chaînes, soit au moins se comporter correctement en tant que chaînes (comme des nombres, ou des références d'objets qui surchargent la stringification de manière appropriée).

partition_by

%parts = partition_by { KEYFUNC } @vals

Retourne une liste de paires clé/valeur de références ARRAY contenant toutes les valeurs originales distribuées selon le résultat du bloc de fonction clé. Chaque valeur sera une référence ARRAY contenant toutes les valeurs qui ont retourné la chaîne de la fonction clé, dans leur ordre d'origine.

my %balls_by_colour = partition_by { $_->colour } @balls;

Étant donné que les valeurs retournées par la fonction clé sont utilisées comme clés de hachage, elles devraient être soit des chaînes, soit au moins se comporter correctement en tant que chaînes (comme des nombres, ou des références d'objets qui surchargent la stringification de manière appropriée).

count_by

%counts = count_by { KEYFUNC } @vals

Depuis la version 0.07.

Retourne une liste de paires clé/valeur d'entiers, donnant le nombre de fois où le bloc de fonction clé a retourné la clé, pour chaque valeur de la liste.

my %count_of_balls = count_by { $_->colour } @balls;

Étant donné que les valeurs retournées par la fonction clé sont utilisées comme clés de hachage, elles devraient être soit des chaînes, soit au moins se comporter correctement en tant que chaînes (comme des nombres, ou des références d'objets qui surchargent la stringification de manière appropriée).

zip_by

@vals = zip_by { ITEMFUNC } \@arr0, \@arr1, \@arr2,...

Retourne une liste de chacune des valeurs retournées par le bloc de fonction, lorsqu'elle est appelée avec des valeurs provenant de chacun des références ARRAY données. Chaque valeur de la liste retournée sera le résultat de la fonction ayant été invoquée avec les arguments à cette position, provenant de chacun des tableaux donnés.

my @transposition = zip_by { [ @_ ] } @matrix;
my @names = zip_by { "$_[1], $_[0]" } \@firstnames, \@surnames;
print zip_by { "$_[0] => $_[1]\n" } [ keys %hash ], [ values %hash ];

Si certains des tableaux sont plus courts que d'autres, la fonction se comportera comme s'ils avaient "undef" dans les positions restantes. Les deux lignes suivantes sont équivalentes :

zip_by { f(@_) } [ 1, 2, 3 ], [ "a", "b" ]
f( 1, "a" ), f( 2, "b" ), f( 3, undef )

La fonction d'élément est appelée par "map", donc si elle retourne une liste, la liste entière est incluse dans le résultat. Ceci peut être utile par exemple pour générer une table de hachage à partir de deux listes distinctes de clés et de valeurs

NOM

List::UtilsBy - fonctions utilitaires de liste qui opèrent sur les résultats de fonctions

SYNOPSIS

  use List::UtilsBy qw(
      count_by
      max_by
      min_by
      sum_by
      product_by
      any_by
      all_by
      none_by
      first_by
      first_index_by
      sort_by
      zip_by
      unzip_by
      extract_by
      extract_first_by
      weighted_shuffle_by
      bundle_by
  );

  # exemple de count_by
  my %counts = count_by { $_->{type} } @items;

  # exemple de max_by
  my $max_val = max_by { $_->salary } @employees;

  # exemple de min_by
  my $min_val = min_by { $_->{size} } @items;

  # exemple de sum_by
  my $total = sum_by { $_->value } @items;

  # exemple de product_by
  my $product = product_by { $_->value } @items;

  # exemple de any_by
  my $found = any_by { $_ eq "red" } @colors;

  # exemple de all_by
  my $all_odd = all_by { $_ % 2 } @numbers;

  # exemple de none_by
  my $none_negative = none_by { $_ < 0 } @numbers;

  # exemple de first_by
  my $first_even = first_by { $_ % 2 == 0 } @numbers;

  # exemple de first_index_by
  my $first_even_idx = first_index_by { $_ % 2 == 0 } @numbers;

  # exemple de sort_by
  my @sorted_by_name = sort_by { $_->name } @users;

  # exemple de zip_by
  my %hash = zip_by { @_ } [qw( a b c )], [ 1, 2, 3 ];
  # %hash = ( a => 1, b => 2, c => 3 )

  # exemple de unzip_by
  my ( $firstnames, $lastnames ) = unzip_by { m/^(.*?) (.*)$/ } @names;

  # exemple de extract_by
  my @red_balls = extract_by { $_->color eq "red" } @balls;

  # exemple de extract_first_by
  my $first_red_ball = extract_first_by { $_->color eq "red" } @balls;

  # exemple de weighted_shuffle_by
  my @shuffled = weighted_shuffle_by { $_->priority } @items;

  # exemple de bundle_by
  my @bundles = bundle_by { $_ } 3, @items;

DESCRIPTION

Ce module fournit un certain nombre de fonctions qui sont des variantes des fonctions de liste standards, qui opèrent sur les résultats d'une fonction de bloc que vous spécifiez.

La plupart de ces fonctions prennent une liste et une fonction de bloc. La fonction de bloc est appelée pour chaque élément de la liste, et le résultat de l'appel est utilisé par la fonction utilitaire.

Certaines fonctions (comme extract_by et extract_first_by) modifient la liste d'origine. Celles-ci nécessitent un tableau réel plutôt qu'une simple liste de valeurs.

Toutes ces fonctions sont implémentées en Perl pur, mais sont potentiellement rapides. Voir la section TODO pour discuter des implémentations XS.

FONCTIONS

count_by

  %counts = count_by { KEYFUNC } @vals

Retourne une table de hachage où les clés sont les valeurs retournées par la fonction de bloc, et les valeurs sont le nombre de fois que chaque clé a été retournée. La liste d'entrée est itérée, la fonction de bloc est appelée pour chaque élément, et le résultat est utilisé comme clé pour incrémenter le compteur.

  my @items = ( { type => 'apple',  value => 1 },
              { type => 'banana', value => 2 },
              { type => 'apple',  value => 3 } );
  my %counts = count_by { $_->{type} } @items;
  # %counts = ( apple => 2, banana => 1 )

max_by

  $max_val = max_by { VALUEFUNC } @vals

Retourne l'élément de la liste pour lequel la fonction de bloc a retourné la plus grande valeur. Si plusieurs éléments retournent la même valeur maximale, le premier est retourné.

  my @employees = ( { name => 'Alice', salary => 50000 },
                  { name => 'Bob',   salary => 60000 },
                  { name => 'Carol', salary => 55000 } );
  my $highest_paid = max_by { $_->salary } @employees;
  # $highest_paid = { name => 'Bob', salary => 60000 }

min_by

  $min_val = min_by { VALUEFUNC } @vals

Retourne l'élément de la liste pour lequel la fonction de bloc a retourné la plus petite valeur. Si plusieurs éléments retournent la même valeur minimale, le premier est retourné.

  my @items = ( { name => 'A', size => 10 },
              { name => 'B', size => 5 },
              { name => 'C', size => 7 } );
  my $smallest = min_by { $_->{size} } @items;
  # $smallest = { name => 'B', size => 5 }

sum_by

  $total = sum_by { VALUEFUNC } @vals

Retourne la somme des valeurs retournées par la fonction de bloc pour chaque élément de la liste.

  my @items = ( { value => 10 }, { value => 20 }, { value => 30 } );
  my $total = sum_by { $_->value } @items;
  # $total = 60

product_by

  $product = product_by { VALUEFUNC } @vals

Retourne le produit des valeurs retournées par la fonction de bloc pour chaque élément de la liste.

  my @items = ( { value => 2 }, { value => 3 }, { value => 4 } );
  my $product = product_by { $_->value } @items;
  # $product = 24

any_by

  $found = any_by { BOOLEANFUNC } @vals

Retourne vrai (1) si la fonction de bloc retourne vrai pour au moins un élément de la liste, et faux (0) sinon. La recherche s'arrête dès qu'un élément vrai est trouvé.

  my @numbers = (1, 3, 5, 7, 9);
  my $found_even = any_by { $_ % 2 == 0 } @numbers;
  # $found_even = 0

all_by

  $all_true = all_by { BOOLEANFUNC } @vals

Retourne vrai (1) si la fonction de bloc retourne vrai pour tous les éléments de la liste, et faux (0) sinon. La recherche s'arrête dès qu'un élément faux est trouvé.

  my @numbers = (2, 4, 6, 8);
  my $all_even = all_by { $_ % 2 == 0 } @numbers;
  # $all_even = 1

none_by

  $none_true = none_by { BOOLEANFUNC } @vals

Retourne vrai (1) si la fonction de bloc retourne faux pour tous les éléments de la liste, et faux (0) sinon. La recherche s'arrête dès qu'un élément vrai est trouvé.

  my @numbers = (1, 3, 5, 7);
  my $none_negative = none_by { $_ < 0 } @numbers;
  # $none_negative = 1

first_by

  $first_match = first_by { BOOLEANFUNC } @vals

Retourne le premier élément de la liste pour lequel la fonction de bloc retourne vrai. Si aucun élément ne correspond, retourne undef.

  my @numbers = (1, 3, 4, 5, 6);
  my $first_even = first_by { $_ % 2 == 0 } @numbers;
  # $first_even = 4

first_index_by

  $first_index = first_index_by { BOOLEANFUNC } @vals

Retourne l'index du premier élément de la liste pour lequel la fonction de bloc retourne vrai. Si aucun élément ne correspond, retourne -1.

  my @numbers = (1, 3, 4, 5, 6);
  my $first_even_idx = first_index_by { $_ % 2 == 0 } @numbers;
  # $first_even_idx = 2

sort_by

  @sorted = sort_by { VALUEFUNC } @vals

Retourne une nouvelle liste contenant les éléments de la liste d'origine triés selon les valeurs retournées par la fonction de bloc. Ceci est équivalent à List::Util::sort_by, mais est inclus ici pour la cohérence.

  my @users = ( { name => 'Bob',   age => 30 },
              { name => 'Alice', age => 25 },
              { name => 'Carol', age => 35 } );
  my @sorted_by_age = sort_by { $_->age } @users;
  # @sorted_by_age = ( { name => 'Alice', age => 25 },
  #                  { name => 'Bob',   age => 30 },
  #                  { name => 'Carol', age => 35 } )

zip_by

  %hash = zip_by { BLOCKFUNC } @list1, @list2, ...

Prend plusieurs listes en entrée, et les "zippe" ensemble en utilisant la fonction de bloc pour déterminer comment combiner les éléments. La fonction de bloc reçoit les éléments correspondants de chaque liste comme arguments et doit retourner une clé et une valeur pour la table de hachage résultante.

Si les listes d'entrée ont des longueurs différentes, le zippage s'arrête à la longueur de la liste la plus courte.

  my %nums = zip_by { join '-', @_ } [qw( one two three )], [ 1, 2, 3 ];
  # %nums = ( 'one-1' => 'one-1', 'two-2' => 'two-2', 'three-3' => 'three-3' )

Une utilisation courante est de créer une table de hachage à partir de deux listes, où la première liste fournit les clés et la seconde fournit les valeurs.

  my %nums = zip_by { @_ } [qw( one two three )], [ 1, 2, 3 ];
  # %nums = ( one => 1, two => 2, three => 3 )

(Une fonction ayant ce comportement est parfois appelée "zipWith", par exemple en Haskell, mais ce nom ne correspondrait pas au schéma de nommage utilisé par ce module).

unzip_by

  $arr0, $arr1, $arr2, ... = unzip_by { ITEMFUNC } @vals

Depuis la version 0.09.

Retourne une liste de références de tableaux contenant les valeurs retournées par le bloc de fonction, lorsqu'il est invoqué pour chacune des valeurs données dans la liste d'entrée. Chacune des références de tableaux renvoyées contiendra les valeurs retournées à cette position correspondante par le bloc de fonction. C'est-à-dire que la première référence de tableau retournée conterra toutes les valeurs retournées en première position par le bloc de fonction, la seconde contiendra toutes les valeurs de la deuxième position, et ainsi de suite.

  my ( $firstnames, $lastnames ) = unzip_by { m/^(.*?) (.*)$/ } @names;

Si la fonction retourne des listes de longueurs différentes, le résultat sera complété avec "undef" dans les éléments manquants.

Cette fonction est l'inverse de "zip_by", si elle est donnée une fonction inverse correspondante.

extract_by

  @vals = extract_by { SELECTFUNC } @arr

Depuis la version 0.05.

Supprime les éléments du tableau référencé pour lesquels la fonction de sélection retourne vrai, et retourne une liste contenant ces éléments. Cette fonction est similaire à "grep", sauf qu'elle modifie le tableau référencé pour en supprimer les valeurs sélectionnées, ne laissant que celles qui n'ont pas été sélectionnées.

  my @red_balls = extract_by { $_->color eq "red" } @balls;
  # Il n'y a maintenant plus de balles rouges dans le tableau @balls

Cette fonction modifie un tableau réel, contrairement à la plupart des autres fonctions de ce module. Pour cette raison, elle nécessite un tableau réel, pas seulement une liste.

Cette fonction est implémentée en invoquant "splice" sur le tableau, et non en construisant une nouvelle liste et en l'assignant. L'un des résultats est que les références faibles ne seront pas perturbées.

  extract_by { !defined $_ } @refs;

laissera les références faibles affaiblies dans le tableau @refs, alors que

  @refs = grep { defined $_ } @refs;

les renforcera toutes à nouveau.

extract_first_by

  $val = extract_first_by { SELECTFUNC } @arr

Depuis la version 0.10.

Un hybride entre "extract_by" et "List::Util::first". Supprime le premier élément du tableau référencé pour lequel la fonction de sélection retourne vrai, et le retourne.

Comme avec "extract_by", cette fonction nécessite un tableau réel et non juste une liste, et est également implémentée en utilisant "splice" afin que les références faibles ne soient pas perturbées.

Si cette fonction ne trouve pas d'élément correspondant, elle retournera une liste vide en contexte de liste. Cela permet à un appelant de distinguer le cas où il n'y a pas d'élément correspondant, et le cas où le premier élément correspondant est "undef".

weighted_shuffle_by

  @vals = weighted_shuffle_by { WEIGHTFUNC } @vals

Depuis la version 0.07.

Retourne la liste des valeurs mélangées dans un ordre aléatoire. La randomisation n'est pas uniforme, mais pondérée par la valeur retournée par la "WEIGHTFUNC". La probabilité que chaque élément soit retourné en premier sera distribuée selon la distribution des poids, et ainsi de suite récursivement pour les éléments restants.

bundle_by

  @vals = bundle_by { BLOCKFUNC } $number, @vals

Depuis la version 0.07.

Similaire à une fonction "map" régulière, retourne une liste des valeurs retournées par "BLOCKFUNC". Les valeurs de la liste d'entrée sont données à la fonction de bloc par lots de $number.

Si la liste de valeurs donnée n'est pas divisible par $number, le dernier appel recevra moins d'éléments que les autres.

EXEMPLES

Comme beaucoup de ces fonctions prennent et retournent des listes de valeurs, des comportements plus utiles peuvent être créés en les combinant ensemble.

Valeur Modale

Pour choisir la valeur modale dans une liste (c'est-à-dire la valeur qui apparaît le plus fréquemment selon une fonction clé) combinez "count_by" et "max_by" :

  my %counts = count_by { KEYFUNC } ITEMS;
  my $modal = max_by { $counts{$_} } keys %counts;

Cela peut être effectué en une seule étape en utilisant la fonction "pairs" de List::Util :

  use List::Util qw( pairs );
  my $modal = ( max_by { $_->value } pairs count_by { KEYFUNC } ITEMS )->key;
