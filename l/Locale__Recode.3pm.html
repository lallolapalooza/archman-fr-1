NAME

Locale::Recode - Objet orienté pour la conversion de jeux de caractères

SYNOPSIS

use Locale::Recode;
$cd = Locale::Recode->new (from => 'UTF-8',
                           to   => 'ISO-8859-1');
die $cd->getError if $cd->getError;
$cd->recode ($text) or die $cd->getError;
$mime_name = Locale::Recode->resolveAlias ('latin-1');
$supported = Locale::Recode->getSupported;
$complete = Locale::Recode->getCharsets;

DESCRIPTION

Ce module fournit des routines qui convertissent des données textuelles d'un jeu de caractères à un autre de manière portable. Le module a été initié avant que Encode(3) ne soit écrit. Son but principal est de fournir une conversion de jeux de caractères même lorsque Encode(3) n'est pas disponible sur le système. Il devrait également fonctionner pour les anciennes versions de Perl sans support Unicode.

En interne, Locale::Recode(3) utilisera Encode(3) lorsque cela est possible, pour permettre une conversion plus rapide et une gamme plus large de jeux de caractères supportés, et ne se rabattra sur l'implémentation Perl que lorsque Encode(3) n'est pas disponible ou ne supporte pas un jeu de caractères spécifique que Locale::Recode(3) possède.

Locale::Recode(3) fait partie de libintl-perl et son but principal est d'implémenter un cadre de conversion de jeux de caractères portable pour les systèmes de traduction décrits dans Locale::TextDomain(3).

CONSTRUCTEUR

Le constructeur new() requiert deux arguments clés :

from
Le jeu de caractères d'origine. La casse n'a pas d'importance, les alias sont résolus.
to
Le jeu de caractères de destination. La casse n'a pas d'importance, et les alias sont résolus.

Le constructeur ne échouera jamais. En cas d'erreur, l'état interne de l'objet sera défini sur 'bad' et il n'effectuera aucune conversion. Vous pouvez demander la raison de l'erreur avec la méthode getError().

MÉTHODES D'OBJET

Les méthodes d'objet suivantes sont disponibles :

recode (STRING)
Convertit STRING du jeu de caractères source vers le jeu de caractères de destination. En cas de succès, une valeur vraie est retournée, sinon, false. Vous pouvez demander la raison de l'erreur avec la méthode getError().
getError
Retourne false si l'objet n'est pas dans un état d'erreur, ou un message d'erreur.

MÉTHODES DE CLASSE

L'objet fournit quelques méthodes de classe supplémentaires :

getSupported
Retourne une référence vers une liste de tous les jeux de caractères supportés. Cela peut impliquer le chargement supplémentaire de Encode(3) comme Encode::HanExtra(3) qui peut avoir un impact considérable sur votre système. La méthode n'est pas intentionnellement conçue pour une utilisation régulière, mais pour obtenir ou afficher une liste des encodages disponibles une seule fois.
getCharsets
Comme getSupported(), mais retourne également tous les alias disponibles.

JEUX DE CARACTÈRES SUPPORTÉS

La gamme de jeux de caractères supportés dépend du système. Les encodages suivants sont toujours disponibles :

UTF-8
UTF-8 est disponible indépendamment de votre version de Perl. Pour Perl 5.6 ou supérieur ou en présence de Encode(3), les conversions ne sont pas effectuées en Perl, mais via les interfaces fournies par ces systèmes, écrites en C, elles sont donc beaucoup plus rapides. La donnée d'encodage en UTF-8 est rapide, même si elle est effectuée en Perl. La décodification en Perl peut devenir lente. Si vous devez fréquemment décoder UTF-8 avec Locale::Recode, je vous recommande de le faire avec Perl 5.6 ou supérieur, ou d'installer Encode(3) pour accélérer.
INTERNAL
UTF-8 est rapide à écrire mais difficile à lire pour les applications. Par conséquent, ce n'est pas le pire pour la représentation interne des chaînes, mais ce n'est pas très différent. Locale::Recode(3) stocke les chaînes en interne comme une référence à un tableau de valeurs entières, comme le font la plupart des langages de programmation (Perl est une exception). Il troque la mémoire contre la performance. Les valeurs entières sont les codes UCS-4 des caractères dans l'ordre des octets de l'hôte.

Le jeu de caractères INTERNAL est disponible directement via Locale::Recode(3), mais en fait, vous ne devriez pas l'utiliser pour l'échange de données, à moins que vous ne sachiez ce que vous faites.

Le jeu de caractères INTERNAL est disponible directement via Locale::Recode(3), mais en fait, vous ne devriez pas l'utiliser pour l'échange de données, à moins que vous ne sachiez ce que vous faites.

Locale::Recode(3) a un support natif pour une large gamme d'autres jeux de caractères, y compris de nombreux codes 8 bits rapides à décoder, comme ceux des micro-ordinateurs populaires tels que les séries ISO-8859 et les codes Windows (également connus sous le nom de CP*), Macintosh, Atari, etc.

NOMS ET ALIAS

Chaque jeu de caractères ou encodage est disponible en interne sous un nom unique. Lorsque les informations étaient disponibles, le nom MIME préféré (voir http://www.iana.org/assignments/character-sets/) a été choisi comme nom interne.

La gestion des alias est assez stricte. Le module ne fait pas d'hypothèses aléatoires sur ce que vous voulez dire ("qu'est-ce que l'acronyme JIS signifie ?") mais cherche à offrir des alias courants. Il en va de même pour les alias qui sont de véritables erreurs, comme "utf8" pour UTF-8.

Le module connaît tous les alias listés dans le registre IANA des jeux de caractères (http://www.iana.org/assignments/character-sets/), ainsi que ceux connus dans libiconv version 1.8 et une variété d'autres.

TABLES DE CONVERSION

Les tables de conversion ont été tirées de sources officielles comme l'IANA ou le Consortium Unicode, de libiconv de Bruno Haible, ou des sources de GNU libc et des tests de régression pour libintl-perl qui vérifieront la conformité ici. Pour certains jeux de caractères, les informations diffèrent de celles de Encode(3), ce qui entraînerait l'échec des tests. Dans ces cas, le module n'invoquera pas les méthodes Encode(3), mais se rabattra sur l'implémentation interne pour maintenir la cohérence.

Les quelques jeux de caractères affectés sont si simples qu'ils n'entraîneront pas de pénalité de performance réelle, à moins que vous ne convertissiez de grands blocs de données. Cependant, le paquet n'est pas vraiment conçu pour une telle utilisation et, étant donné que Encode(3) est relativement nouveau, je pense que les différences sont des bugs dans Encode qui seront corrigés bientôt.

BUGS

Le module devrait fournir des conversions de jeux de caractères à partir d'autres schémas d'encodage Unicode tels que UCS-2, UCS-4 (big- et little-endian).

Le décodeur de texte Perl de UTF-8 ne gérera pas toujours correctement les données corrompues UTF-8, en particulier au début et à la fin de la chaîne. Cela ne devrait pas être corrigé, car le but du module n'est pas de vérifier la cohérence des données UTF-8.
