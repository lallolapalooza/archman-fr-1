NOM

Log::Log4perl::Config::BaseConfigurator - Classe de base du configurateur

SYNOPIS

Il s'agit d'une classe de base virtuelle, tous les configurateurs devraient en dériver.

DESCRIPTION

MÉTHODES

"new"
Constructeur, généralement appelé comme ceci : 
my $config_parser = SomeConfigParser->new(
    file => $file,
);
my $data = $config_parser->parse();

Au lieu de "file", la classe dérivée "SomeConfigParser" peut définir tout type de support d'entrée de configuration (par exemple "url => 'http://foobar'"). Elle doit juste s'assurer que sa méthode parse() extraira plus tard les données d'entrée du support spécifié.

La classe de base accepte un nom de fichier ou une référence à un tableau de lignes de texte :

"file"
Spécifie un fichier que la méthode parse() analysera plus tard.
"text"
Spécifie une référence à un tableau de scalaires, représentant des enregistrements de configuration (typiquement des lignes d'un fichier). Accepte également un scalaire simple, qu'il découpe à ses sauts de ligne et transforme en tableau : 
my $config_parser = MyYAMLParser->new(
    text => ['foo: bar',
             'baz: bam',
            ],
);
my $data = $config_parser->parse();

Si les paramètres "file" ou "text" ont été spécifiés dans l'appel du constructeur, un appel ultérieur à la méthode text() du configurateur renverra une référence à un tableau de lignes de texte de configuration. Ceci sera typiquement utilisé par la méthode parse() pour traiter l'entrée.

"parse"
Méthode virtuelle, doit être définie par la classe dérivée.

Exigences du parser

  • Si le parser fournit une fonctionnalité de substitution de variables, il doit l'implémenter.
  • La méthode parse() du parser renvoie une référence à une table associative de tables associatives (HoH). La table associative principale contient les mots-clés de premier niveau ("category", "appender") comme clés, associées à des valeurs qui sont des références à des tables associatives plus imbriquées.
  • Le préfixe "log4perl." (par exemple, tel qu'utilisé dans la classe PropertyConfigurator) est supprimé, il ne fait pas partie de la structure HoH.
  • Chaque valeur de configuration Log4perl est indiquée par la clé "value", comme dans 
    $data->{category}->{Bar}->{Twix}->{value} = "WARN, Logfile"

EXEMPLES

La configuration Log::Log4perl suivante :

log4perl.category.Bar.Twix        = WARN, Screen
log4perl.appender.Screen          = Log::Log4perl::Appender::File
log4perl.appender.Screen.filename = test.log
log4perl.appender.Screen.layout   = Log::Log4perl::Layout::SimpleLayout

doit être transformée par la méthode parse() du parser en cette structure de données :

{ appender => {
    Screen  => {
      layout => { 
        value  => "Log::Log4perl::Layout::SimpleLayout" },
        value  => "Log::Log4perl::Appender::Screen",
    },
  },
  category => { 
    Bar => { 
      Twix => { 
        value => "WARN, Screen" } 
    } }
}

Pour un exemple complet, consultez l'implémentation du parser YAML exemple dans "eg/yamlparser". Il utilise une syntaxe YAML simple pour spécifier la configuration Log4perl afin d'illustrer le concept.
