List::SomeUtils(3) Documentation Perl fournie par l'utilisateur List::SomeUtils(3)

NOM

List::SomeUtils - Fournit ce qui manque dans List::Util

VERSION

version 0.59

SYNOPSIS

# importer des fonctions spécifiques
use List::SomeUtils qw( any uniq );
if ( any {/foo/} uniq @has_duplicates ) {
    # faire quelque chose
}
# importer tout
use List::SomeUtils ':all';

DESCRIPTION

List::SomeUtils fournit des fonctionnalités triviales mais couramment nécessaires sur les listes, qui n'iront pas dans List::Util.

Toutes les fonctions ci-dessous sont implémentables en seulement quelques lignes de code Perl. Utiliser les fonctions de ce module devrait cependant donner des performances légèrement meilleures car tout est implémenté en C. L'implémentation pure Perl de ces fonctions ne sert qu'en cas de repli au cas où les parties C de ce module ne pourraient pas être compilées sur cette machine.

POURQUOI CE MODULE EXISTE-T-IL?

Vous pourriez vous demander pourquoi ce module existe alors que nous avons déjà List::MoreUtils. En fait, ce module est (presque) le même code que celui trouvé dans LMU sans changements significatifs. Cependant, la distribution LMU dépend de plusieurs modules de configuration (pour exécuter Makefile.PL) que certains membres de la communauté Perl ne jugent pas appropriés pour un module situé en amont dans le flux CPAN.

Je (Dave Rolsky) n'ai pas d'opinion forte à ce sujet, mais j'aime les fonctionnalités fournies par LMU, et je suis fatigué de recevoir des correctifs et des demandes d'extraction pour supprimer LMU de mon code.

Cette distribution existe pour me permettre d'utiliser les fonctionnalités que j'aime sans avoir à me lancer dans des arguments fatigants sur des problèmes qui ne m'importent pas vraiment.

EXPORTS

Comportement par défaut

Rien par défaut. Pour importer tous les symboles de ce module, utilisez la balise ":all". Sinon, les fonctions peuvent être importées par leur nom comme d'habitude :

use List::SomeUtils ':all';
use List::SomeUtils qw{ any firstidx };

En raison de modifications historiques de l'API qui pourraient rendre la mise à niveau de List::SomeUtils difficile pour certains projets, l'API héritée est disponible via des balises d'importation spéciales.

FONCTIONS

Jonctions

Traitement d'une liste vide

Il existe deux écoles de pensée quant à la manière d'évaluer une jonction sur une liste vide :

  • Réduction à une identité (booléenne)
  • Résultat indéfini (trois valeurs)

Dans le premier cas, le résultat de la jonction appliquée à la liste vide est déterminé par une réduction mathématique à une identité en fonction de si la comparaison sous-jacente est « ou » ou « et ». Conceptuellement :

                "quelques-uns sont vrais"      "tous sont vrais"
                --------------      --------------
2 éléments:     A || B || 0         A && B && 1
1 élément:      A || 0              A && 1
0 élément:     0                   1

Dans le second cas, la logique à trois valeurs est souhaitée, dans laquelle une jonction appliquée à une liste vide renvoie "undef" plutôt que vrai ou faux.

Les jonctions avec un suffixe "_u" implémentent la logique à trois valeurs. Celles sans sont booléennes.

all BLOCK LIST

all_u BLOCK LIST

Renvoie une valeur vraie si tous les éléments de LIST respectent le critère donné par BLOCK. Définit $_ pour chaque élément de LIST tour à tour :

print "Toutes les valeurs sont non négatives"
  if all { $_ >= 0 } ($x, $y, $z);

Pour une LISTE vide, "all" renvoie vrai (c'est-à-dire qu'aucune valeur n'a échoué au test) et "all_u" renvoie "undef".

Ainsi, all_u(@list) est équivalent à "@list ? all(@list) : undef".

Note : comme Perl traite "undef" comme faux, vous devez vérifier la valeur de retour de "all_u" avec "defined" ou vous obtiendrez le résultat opposé de celui attendu.

any BLOCK LIST

any_u BLOCK LIST

Renvoie une valeur vraie si un élément quelconque de LIST respecte le critère donné par BLOCK. Définit $_ pour chaque élément de LIST tour à tour :

print "Au moins une valeur non négative"
  if any { $_ >= 0 } ($x, $y, $z);

Pour une LISTE vide, "any" renvoie faux et "any_u" renvoie "undef".

Ainsi, any_u(@list) est équivalent à "@list ? any(@list) : undef".

none BLOCK LIST

none_u BLOCK LIST

Logiquement, c'est la négation de "any". Renvoie une valeur vraie si aucun élément de LIST ne respecte le critère donné par BLOCK. Définit $_ pour chaque élément de LIST tour à tour :

print "Aucune valeur non négative"
  if none { $_ >= 0 } ($x, $y, $z);

Pour une LISTE vide, "none" renvoie vrai (c'est-à-dire qu'aucune valeur n'a échoué au test) et "none_u" renvoie "undef".

Ainsi, none_u(@list) est équivalent à "@list ? none(@list) : undef".

Note : comme Perl traite "undef" comme faux, vous devez vérifier la valeur de retour de "none_u" avec "defined" ou vous obtiendrez le résultat opposé de celui attendu.

notall BLOCK LIST

notall_u BLOCK LIST

Logiquement, c'est la négation de "all". Renvoie une valeur vraie si tous les éléments de LIST ne respectent pas le critère donné par BLOCK. Définit $_ pour chaque élément de LIST tour à tour :

print "Toutes les valeurs ne sont pas non négatives"
  if notall { $_ >= 0 } ($x, $y, $z);

Pour une LISTE vide, "notall" renvoie faux et "notall_u" renvoie "undef".

Ainsi, notall_u(@list) est équivalent à "@list ? notall(@list) : undef".

one BLOCK LIST

one_u BLOCK LIST

Renvoie une valeur vraie si précisément un élément de LIST respecte le critère donné par BLOCK. Définit $_ pour chaque élément de LIST tour à tour :

print "Précisément une valeur définie"
    if one { defined($_) } @list;

Renvoie faux sinon.

Pour une LISTE vide, "one" renvoie faux et "one_u" renvoie "undef".

L'expression "one BLOCK LIST" est presque équivalente à "1 == true BLOCK LIST", sauf pour la coupure. L'évaluation de BLOCK s'arrêtera immédiatement à la deuxième valeur vraie.

Transformation

apply BLOCK LIST

Crée une copie de la liste et passe ensuite chaque élément de la copie au BLOCK. Toutes les modifications ou affectations à $_ dans le BLOCK n'affecteront que les éléments de la nouvelle liste. Cependant, si $_ est une référence, les modifications apportées à la valeur référencée seront visibles dans la liste originale et la nouvelle liste.

Cette fonction est similaire à "map" mais ne modifiera pas les éléments de la liste d'entrée :

my @list = (1 .. 4);
my @mult = apply { $_ *= 2 } @list;
print "\@list = @list\n";
print "\@mult = @mult\n";
__END__
@list = 1 2 3 4
@mult = 2 4 6 8

Pensez-y comme un sucre syntaxique pour

for (my @mult = @list) { $_ *= 2 }

Partitionnement

après LIST BLOQUÉE

Retourne une liste des valeurs de LIST après (et n'incluant pas) le point où BLOCK retourne une valeur vraie. Assigne $_ à chaque élément de LIST en ordre.

@x = après { $_ % 5 == 0 } (1..9);    # retourne 6, 7, 8, 9

après_incl BLOCK LIST

Identique à "après", mais inclut également l'élément pour lequel BLOCK est vrai.

avant BLOCK LIST

Retourne une liste des valeurs de LIST jusqu'au point (et n'incluant pas) où BLOCK retourne une valeur vraie. Assigne $_ à chaque élément de LIST en ordre.

avant_incl BLOCK LIST

Identique à "avant", mais inclut également l'élément pour lequel BLOCK est vrai.

part BLOCK LIST

Divise LIST selon la valeur retournée par BLOCK, qui indique dans quelle partition se trouve la valeur actuelle. Retourne une liste des partitions ainsi créées. Chaque partition créée est une référence à un tableau.

my $i = 0;
my @part = part { $i++ % 2 } 1 .. 8;   # retourne [1, 3, 5, 7], [2, 4, 6, 8]

Il est également possible d'avoir des listes de partitions éparses où les partitions non définies seront undef :

my @part = part { 2 } 1 .. 10;            # retourne undef, undef, [ 1 .. 10 ]

Soyez prudent avec les valeurs négatives, cependant :

my @part = part { -1 } 1 .. 10;
__END__
Tentative de modification de valeur non créable, indice -1 ...

Les valeurs négatives ne sont valides que lorsqu'elles font référence à une partition précédemment créée :

my @idx  = ( 0, 1, -1 );
my $i    = 0;
my @part = part { $idx[$i++ % 3] } 1 .. 8; # [1, 4, 7], [2, 3, 5, 6, 8]

Itération

each_array ARRAY1 ARRAY2 ...

Crée un itérateur de tableaux pour retourner les éléments des tableaux ARRAY1, ARRAY2, ..., ARRAYn en ordre. La première fois qu'il est appelé, il retourne le premier élément de chaque tableau. La fois suivante, il retourne le deuxième élément. Et ainsi de suite jusqu'à ce que tous les éléments soient épuisés.

Il est utile pour parcourir plus d'un tableau en même temps :

my $ea = each_array(@a, @b, @c);
while ( my ($a, $b, $c) = $ea->() )   { .... }

L'itérateur retourne une liste vide lorsque la fin de tous les tableaux est atteinte.

Si l'itérateur reçoit l'argument '"index"', il retourne l'indice de la dernière valeur obtenue, sous forme d'un scalaire.

each_arrayref LIST

Identique à each_array, mais les arguments sont des références à des tableaux, pas des tableaux normaux.

natatime EXPR, LIST

Crée un itérateur pour parcourir un tableau par blocs de $n éléments à la fois. (n à la fois, vous avez compris ?). Un exemple est probablement une meilleure explication que ce que je peux donner par mots.

Exemple :

my @x = ('a' .. 'g');
my $it = natatime 3, @x;
while (my @vals = $it->())
{
  print "@vals\n";
}

Cela imprime

a b c
d e f
g

Recherche

bsearch BLOCK LIST

Effectue une recherche binaire dans LIST, qui doit être une liste triée de valeurs. BLOCK doit retourner une valeur négative si l'élément courant (assigné à $_) est plus petit, positive s'il est plus grand, et zéro s'il correspond.

Retourne une valeur booléenne dans un contexte scalaire. Dans un contexte de liste, retourne l'élément s'il est trouvé, sinon une liste vide.

bsearchidx BLOCK LIST

bsearch_index BLOCK LIST

Effectue une recherche binaire dans LIST, qui doit être une liste triée de valeurs. BLOCK doit retourner une valeur négative si l'élément courant (assigné à $_) est plus petit, positive s'il est plus grand, et zéro s'il correspond.

Retourne l'indice de l'élément trouvé, sinon -1.

"bsearch_index" est un alias pour "bsearchidx".

firstval BLOCK LIST

first_value BLOCK LIST

Retourne le premier élément de LIST pour lequel BLOCK évalue à vrai. Chaque élément de LIST est assigné à $_ en ordre. Retourne "undef" si un tel élément n'est pas trouvé.

"first_value" est un alias pour "firstval".

onlyval BLOCK LIST

only_value BLOCK LIST

Retourne l'unique élément de LIST pour lequel BLOCK évalue à vrai. Assigne $_ à chaque élément de LIST en ordre. Retourne "undef" si un tel élément n'est pas trouvé.

"only_value" est un alias pour "onlyval".

lastval BLOCK LIST

last_value BLOCK LIST

Retourne la dernière valeur dans LIST pour laquelle BLOCK évalue à vrai. Chaque élément de LIST est assigné à $_ en ordre. Retourne "undef" si un tel élément n'est pas trouvé.

"last_value" est un alias pour "lastval".

firstres BLOCK LIST

first_result BLOCK LIST

Retourne le résultat de BLOCK pour le premier élément de LIST pour lequel BLOCK évalue à vrai. Chaque élément de LIST est assigné à $_ en ordre. Retourne "undef" si un tel élément n'est pas trouvé.

"first_result" est un alias pour "firstres".

onlyres BLOCK LIST

only_result BLOCK LIST

Retourne le résultat de BLOCK pour le premier élément de LIST pour lequel BLOCK évalue à vrai. Assigne $_ à chaque élément de LIST en ordre. Retourne "undef" si un tel élément n'est pas trouvé.

"only_result" est un alias pour "onlyres".

lastres BLOCK LIST

last_result BLOCK LIST

Retourne le résultat de BLOCK pour le dernier élément de LIST pour lequel BLOCK évalue à vrai. Chaque élément de LIST est assigné à $_ en ordre. Retourne "undef" si un tel élément n'est pas trouvé.

"last_result" est un alias pour "lastres".

indexes BLOCK LIST

@x = indexes { $_ % 2 == 0 } (1..10);   # retourne 1, 3, 5, 7, 9

Trien

sort_by BLOCK LIST

Renvoie la liste de valeurs triée selon les valeurs de chaînes renvoyées par le bloc de fonction clé ou fonction. Une utilisation typique de ceci peut être de trier des objets selon la valeur de chaîne d'un accessoire, comme

sort_by { $_->name } @people

La fonction clé est appelée en contexte scalaire, chaque valeur étant passée à tour de rôle comme $_ et le seul argument dans les paramètres, @_. Les valeurs sont ensuite triées selon des comparaisons de chaînes sur les valeurs renvoyées. Ceci est équivalent à

sort { $a->name cmp $b->name } @people

bien que cela garantisse que l'accessoire name sera exécuté une seule fois par valeur. Une utilisation intéressante est de trier des chaînes qui peuvent contenir des nombres "naturellement", plutôt que logiquement.

sort_by { s/(\d+)/sprintf "%09d", $1/eg; $_ } @strings

Ceci trie des chaînes en générant des clés de tri qui sont complétées par des zéros à gauche pour certains niveaux (9 chiffres dans ce cas), aidant à garantir que le tri logique les place dans le bon ordre.

nsort_by BLOCK LIST

Similaire à sort_by, mais compare numériquement ses valeurs.

Comptage et calcul

true BLOCK LIST

Compte le nombre d'éléments dans LIST pour lesquels le critère dans BLOCK est vrai. Définit $_ pour chaque élément dans LIST dans l'ordre :

printf "%i item(s) are defined", true { defined($_) } @list;

false BLOCK LIST

Compte le nombre d'éléments dans LIST pour lesquels le critère dans BLOCK est faux. Définit $_ pour chaque élément dans LIST dans l'ordre :

printf "%i item(s) are not defined", false { defined($_) } @list;

minmax LIST

Calcule le minimum et le maximum de LIST et renvoie une liste de deux éléments dont le premier est le minimum et le second le maximum. Renvoie une liste vide si LIST était vide.

L'algorithme "minmax" diffère d'une itération naïve sur la liste où chaque élément est comparé à deux valeurs, le minimum et le maximum actuels calculés jusqu'à présent. Il ne nécessite que 3n/2 - 2 comparaisons. Par conséquent, c'est l'algorithme le plus efficace possible.

Cependant, l'implémentation Perl de l'algorithme a quelques surcoûts simplement parce qu'il y a plus de lignes de code Perl impliquées. Par conséquent, LIST doit être assez grand pour que "minmax" gagne sur une implémentation non naïve. Cette limitation ne s'applique pas à la version XS.

mode LIST

Calcule les éléments les plus communs dans la liste et renvoie les mêmes sous forme de liste. Ceci est effectué par des comparaisons de chaînes, donc les références seront sérialisées. S'ils implémentent une surcharge de chaînes, celle-ci sera utilisée.

Si plusieurs éléments apparaissent le même nombre de fois dans la liste, tous ces éléments seront renvoyés. Par exemple, le mode d'une liste unique est la liste elle-même.

Cette fonction renvoie une liste en contexte de liste. En contexte scalaire, elle renvoie un compte indiquant le nombre de modes dans la liste.

MAINTENANCE

L'objectif de maintenance est de préserver la sémantique documentée de l'API ; les corrections de bugs qui conduisent à un comportement conforme à la sémantique sont autorisées. De nouvelles fonctions d'API peuvent être ajoutées au fil du temps. Si une modification incompatible est inévitable, nous essaierons de fournir un support pour l'ancienne API en utilisant le même mécanisme d'exportation.

Ce module tente d'utiliser peu de dépendances non essentielles. Les dépendances de configuration et de test non essentielles ne seront incluses que lorsque cela sera raisonnable ; les dépendances d'exécution ne seront ajoutées que si elles apportent un avantage substantiel.

PROBLEMES CONNUS

Il existe un problème avec un bug dans la version 5.6.x de Perl. C'est une erreur de syntaxe d'écrire des choses comme :

my @x = apply { s/foo/bar/ } qw{ foo bar baz };

Il faut l'écrire comme :

my @x = apply { s/foo/bar/ } 'foo', 'bar', 'baz';

ou

my @x = apply { s/foo/bar/ } my @dummy = qw/foo bar baz/;

Les versions Perl 5.5.x et 5.8.x ne souffrent pas de cette limitation.

Si vous avez une fonctionnalité que vous pouvez imaginer être dans ce module, s'il vous plaît envoyez-moi un message. La politique de ce module sera plus laxiste que celle de List::Util lors de l'ajout de fonctions, car ce n'est pas un module essentiel.

Lorsque vous signalez des bugs, ce serait formidable si vous pouviez également me donner la sortie de votre programme avec la variable d'environnement "LIST_MOREUTILS_PP" définie à une valeur vraie. Ainsi, je saurai où chercher le problème (dans XS, dans le code Perl ou peut-être les deux).
