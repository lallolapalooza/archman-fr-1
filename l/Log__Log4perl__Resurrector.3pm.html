NOM

Log::Log4perl::Resurrector - Magie noire pour ressusciter les instructions L4p cachées

DESCRIPTION

Le chargement de "use Log::Log4perl::Resurrector" fait que les modules chargés par la suite auront leurs instructions

###l4p use Log::Log4perl qw(:easy);
###l4p DEBUG(...)
###l4p INFO(...)
...

commentées et donc « ressuscités », c'est-à-dire activées.

Cela permet à un module "Foobar.pm" d'être écrit avec des instructions Log4perl commentées et de fonctionner à pleine vitesse en mode normal. Lors du chargement via

use Foobar;

toutes les instructions Log4perl cachées seront ignorées.

Cependant, si un script charge le module "Foobar" *après* avoir chargé "Log::Log4perl::Resurrector", comme ceci :

use Log::Log4perl::Resurrector;
use Foobar;

alors "Log::Log4perl::Resurrector" aura mis en place un filtre source qui extraira toutes les instructions Log4perl cachées dans "Foobar" avant que "Foobar" ne soit effectivement chargé.

Par conséquent, "Foobar" se comportera alors comme si les instructions

###l4p use Log::Log4perl qw(:easy);
###l4p DEBUG(...)
###l4p INFO(...)
...

avaient été réellement écrites comme

use Log::Log4perl qw(:easy);
DEBUG(...)
INFO(...)
...

et le module "Foobar" sera effectivement activé par Log4perl. Que les instructions Log4perl activées déclenchent effectivement des messages de log dépendra bien sûr de la configuration Log4perl.

Il y a un coût de démarrage à l'utilisation de "Log::Log4perl::Resurrector" (tous les modules chargés par la suite sont examinés) mais une fois la phase de compilation terminée, le programme perl fonctionnera à pleine vitesse.

Certaines des techniques utilisées dans ce module ont été volées au module CPAN "Acme::Incorporated", écrit par *chromatic*. Longue vie à CPAN !
