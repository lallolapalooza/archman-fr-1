NOM

Log::Log4perl::Appender::Synchronized - Synchronisation d'autres appenders

SYNTAXE

    use Log::Log4perl qw(:easy);
    my $conf = qq(
    log4perl.category                   = WARN, Syncer

        # Appender de fichier (non synchronisé)
    log4perl.appender.Logfile           = Log::Log4perl::Appender::File
    log4perl.appender.Logfile.autoflush = 1
    log4perl.appender.Logfile.filename  = test.log
    log4perl.appender.Logfile.mode      = truncate
    log4perl.appender.Logfile.layout    = SimpleLayout

        # Appender de synchronisation, utilisant l'appender de fichier ci-dessus
    log4perl.appender.Syncer            = Log::Log4perl::Appender::Synchronized
    log4perl.appender.Syncer.appender   = Logfile
);
    Log::Log4perl->init(\$conf);
    WARN("Ce message est garanti d'être complet.");

DESCRIPTION

Si plusieurs processus utilisent le même appender "Log::Log4perl" sans synchronisation, des écrasements peuvent se produire. Un scénario typique pour cela serait un processus lançant des enfants, chacun héritant de la configuration Log::Log4perl du parent.

Dans la plupart des cas, vous n'aurez pas besoin d'un outil de synchronisation externe comme Log::Log4perl::Appender::Synchronized. L'appender de fichier de Log4perl, Log::Log4perl::Appender::File, par exemple, fournit le mécanisme "syswrite" pour garantir que même les longues lignes de log ne s'entrelacent pas. Les lignes courtes ne s'entrelaceront de toute façon pas, car le système d'exploitation veille à ce que la ligne soit écrite avant qu'un changement de tâche ne se produise.

Dans les cas où vous avez besoin d'une synchronisation supplémentaire, cependant, vous pouvez utiliser "Log::Log4perl::Appender::Synchronized" comme passerelle entre vos loggers et vos appenders. Un appender lui-même, "Log::Log4perl::Appender::Synchronized" prend simplement deux arguments supplémentaires :

"appender"
Spécifie le nom de l'appender dont il synchronise l'accès. L'appender spécifié doit être défini quelque part dans le fichier de configuration, pas nécessairement avant la définition de "Log::Log4perl::Appender::Synchronized".
"key"
Cet argument optionnel spécifie la clé du sémaphore que "Log::Log4perl::Appender::Synchronized" utilise en interne pour assurer des opérations atomiques. Il est par défaut à "_l4p". Si vous définissez plus d'un appender "Log::Log4perl::Appender::Synchronized", il est important de spécifier des clés différentes pour eux, car sinon chaque nouvel appender "Log::Log4perl::Appender::Synchronized" détruira les sémaphores précédemment définis. La longueur maximale de la clé est de quatre caractères, les clés plus longues seront tronquées à 4 caractères -- "mylongkey1" et "mylongkey2" sont interprétés comme identiques : "mylo" (merci à David Viner <dviner@yahoo-inc.com> d'avoir signalé cela).

"Log::Log4perl::Appender::Synchronized" utilise Log::Log4perl::Util::Semaphore en interne pour effectuer le verrouillage avec les sémaphores fournis par le système d'exploitation utilisé.

Conseils de performance

"Log::Log4perl::Appender::Synchronized" sérialise l'accès à une ressource protégée globalement, ralentissant les actions autrement effectuées en parallèle.

Sauf indication contraire, toutes les instances des objets "Log::Log4perl::Appender::Synchronized" dans le système utiliseront la même clé IPC globale "_l4p".

Pour contrôler l'accès à différentes instances d'appenders, il est souvent judicieux de définir des clés différentes pour différents appenders synchronisés. Ainsi, Log::Log4perl sérialise l'accès à chaque instance d'appender séparément :

log4perl.category                   = WARN, Syncer1, Syncer2

    # Appender de fichier 1 (non synchronisé)
log4perl.appender.Logfile1           = Log::Log4perl::Appender::File
log4perl.appender.Logfile1.filename  = test1.log
log4perl.appender.Logfile1.layout    = SimpleLayout

    # Appender de fichier 2 (non synchronisé)
log4perl.appender.Logfile2           = Log::Log4perl::Appender::File
log4perl.appender.Logfile2.filename  = test2.log
log4perl.appender.Logfile2.layout    = SimpleLayout

    # Appender de synchronisation, utilisant l'appender de fichier ci-dessus
log4perl.appender.Syncer1            = Log::Log4perl::Appender::Synchronized
log4perl.appender.Syncer1.appender   = Logfile1
log4perl.appender.Syncer1.key        = l4p1
    # Appender de synchronisation, utilisant l'appender de fichier ci-dessus
log4perl.appender.Syncer2            = Log::Log4perl::Appender::Synchronized
log4perl.appender.Syncer2.appender   = Logfile2
log4perl.appender.Syncer2.key        = l4p2

Sans les lignes ".key = l4p1" et ".key = l4p2", les deux appenders Synchronized utiliseraient la clé par défaut "_l4p", provoquant une sérialisation inutile de la sortie écrite dans différents fichiers.

Configuration avancée

Pour configurer le module sous-jacent Log::Log4perl::Util::Semaphore d'une manière différente des paramètres par défaut fournis par Log::Log4perl::Appender::Synchronized, utilisez les paramètres suivants :

log4perl.appender.Syncer1.destroy  = 1
log4perl.appender.Syncer1.mode     = sub { 0775 }
log4perl.appender.Syncer1.uid      = hugo
log4perl.appender.Syncer1.gid      = 100

Les options valides sont "destroy" (Supprimer le sémaphore à la sortie), "mode" (permissions sur le sémaphore), "uid" (uid ou nom d'utilisateur propriétaire du sémaphore), et "gid" (id du groupe propriétaire du sémaphore),

Notez que "mode" est généralement donné en octal et doit donc être spécifié comme une sous-routine Perl {}, à moins que vous ne vouliez calculer ce que 0755 signifie en décimal.

Modifier les paramètres de propriété ou de groupe pour un sémaphore ne fonctionnera évidemment que si l'ID utilisateur actuel possède déjà le sémaphore ou si l'utilisateur actuel est "root". L'option "destroy" demande au processus actuel de supprimer le sémaphore à sa sortie. Les enfants lancés par le processus n'hériteront pas de ce comportement.

IDs utilisateur et groupe de sémaphore avec mod_perl

La définition des ID utilisateur et groupe est particulièrement importante lorsque l'appender Synchronized est utilisé avec mod_perl. Si Log4perl est initialisé par un gestionnaire de démarrage, qui s'exécute en tant que root, et non en tant qu'utilisateur qui utilisera plus tard le sémaphore, les paramètres pour uid, gid et mode peuvent aider à établir une propriété et des droits d'accès correspondants au sémaphore.

NOTES DE DÉVELOPPEMENT

"Log::Log4perl::Appender::Synchronized" est un appender *composite*. Contrairement aux autres appenders, il ne logge aucun message, il les transmet simplement à son sous-appendeur attaché. Pour cette raison, il n'a pas besoin de layout (contrairement aux appenders réguliers). S'il n'en définit aucun, les messages sont transmis sans modification.

Les filtres personnalisés sont également appliqués uniquement à l'appender composite. Ils ne sont *pas* appliqués au sous-appendeur. Il en va de même pour les seuils d'appender. Ce comportement pourrait changer à l'avenir.

Log::Log4perl::Appender::Synchronized(3pm) — Perl log4perl logging library

NAME

Log::Log4perl::Appender::Synchronized - A synchronized wrapper for Log4perl appenders.

SYNOPSIS

use Log::Log4perl qw(:easylog);

my $logger = get_logger();
my $file_appender = Log::Log4perl::Appender::File->new("test.log");
my $sync_appender = Log::Log4perl::Appender::Synchronized->new($file_appender);
$logger->add_appender($sync_appender);

WARN "This message will be logged safely from multiple threads.";

DESCRIPTION

This appender is a wrapper around any other Log4perl appender. It ensures that the wrapped appender's methods are called in a thread-safe manner by using a mutual exclusion lock.

This is useful if you are using Log4perl in a multi-threaded application and want to log messages from multiple threads to the same appender (e.g., a file appender).

The constructor takes a single argument: the appender object to be wrapped.

DEVELOPMENT NOTES

This appender uses the threads module to provide thread safety. If you are not using threads, this appender is unnecessary.
