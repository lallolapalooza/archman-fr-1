NOM

Locale::Codes - une distribution de modules pour gérer les codes de locale

DESCRIPTION

Locale-Codes est une distribution contenant un ensemble de modules conçus pour travailler avec des ensembles de codes qui identifient de manière unique quelque chose. Par exemple, il existe des codes associés à différents pays, différentes monnaies, différentes langues, etc. Ces ensembles de codes sont généralement maintenus selon une norme.

Cette distribution fournit un moyen de travailler avec ces listes de codes. Comme les données des différentes normes ne sont pas disponibles via une API cohérente, l'accès aux listes n'est pas disponible directement. Pour compenser cela, la liste des codes est stockée en interne dans cette distribution, et la distribution est mise à jour régulièrement pour inclure tous les codes connus à ce moment-là. Cela signifie qu'il est nécessaire de maintenir cette distribution à jour pour suivre les diverses modifications apportées aux différentes normes.

Traditionnellement, un module a été créé pour travailler avec chaque type d'ensemble de codes. Ainsi, il existe un module pour travailler avec les listes de pays, un pour les listes de devises, etc. Depuis la version 3.00, tous ces modules individuels ont été écrits comme des wrappers autour d'un module central (qui n'était pas destiné à être utilisé directement) qui effectuait tout le travail réel.

À partir de la version 3.50, le module central a été légèrement retravaillé pour fournir une interface orientée objet. Tous les modules destinés à travailler avec des types individuels d'ensembles de codes ont été retravaillés pour utiliser le module OO amélioré, de sorte que les interfaces traditionnelles fonctionnent toujours comme elles l'ont toujours fait. Par conséquent, vous êtes libre d'utiliser les interfaces fonctionnelles traditionnelles (non-OO), ou d'utiliser l'interface OO et de contourner complètement les modules wrapper.

Les deux méthodes seront prises en charge à l'avenir, alors utilisez celle qui convient le mieux à vos besoins.

Dans chaque type, un nombre quelconque d'ensembles de codes est autorisé. Par exemple, les ensembles de codes de pays sont maintenus dans plusieurs endroits différents, y compris la norme ISO-3166, l'IANA et les Nations Unies. Les listes de pays sont similaires, mais pas identiques. Plusieurs ensembles de codes sont pris en charge, bien que les tentatives de conversion d'un ensemble de codes à un autre ne fonctionnent pas toujours car la liste des pays n'est pas bijective.

Toutes les données dans tous ces modules proviennent directement des normes originales (ou aussi directement que possible), elles devraient donc être à jour au moment de la publication.

Je prévois de publier une nouvelle version plusieurs fois par an pour intégrer toute modification apportée aux normes. Cependant, je ne suis pas toujours au courant des changements qui se produisent, donc si l'une des normes change et que vous souhaitez une nouvelle version plus tôt, envoyez-moi simplement un e-mail et j'en publierai une.

SYNOPSIS (INTERFACE ORIENTÉE OBJET)

use Locale::Codes;
ou
use Locale::Codes ':constants';
$obj = new Locale::Codes 'country';

MÉTHODES ORIENTÉES OBJET

Les méthodes suivantes sont disponibles.

Dans toutes les méthodes, lors de la spécification d'un ensemble de codes, le nom (sous forme de chaîne de caractères) est toujours disponible.

Traditionnellement, vous pouviez également utiliser une constante perl pour spécifier l'ensemble de codes. Pour ce faire avec l'interface OO, vous devez importer les constantes. Pour ce faire, chargez le module avec :

use Locale::Codes ':constants';
new ( [TYPE [,CODESET]] )
$obj = new Locale::Codes;
$obj = new Locale::Codes 'country';
$obj = new Locale::Codes 'country','alpha-3';
$obj = new Locale::Codes 'country',LOCALE_COUNTRY_ALPHA_3;

Ceci crée un nouvel objet qui peut accéder aux données. Si aucun type n'est spécifié (dans le premier argument), vous devez utiliser la méthode type décrite ci-dessous. Aucune opération ne fonctionnera à moins que le type ne soit spécifié.

Le deuxième argument est l'ensemble de codes par défaut à utiliser. Il est facultatif, car chaque type a un ensemble de codes par défaut. L'ensemble de codes par défaut peut être défini à l'aide de la méthode codeset ci-dessous.

Le dernier exemple n'est disponible que si les constantes ont été importées lors du chargement du module.

show_errors ( FLAG )
$obj->show_errors(1);
$obj->show_errors(0);

Par défaut, des messages d'erreur seront générés lorsque des données invalides sont passées à une méthode. En passant '0', ceux-ci seront désactivés afin que tous les échecs soient silencieux.

type ( TYPE )
$obj->type($type)

Ceci définira le type de codes avec lesquels travailler. $type peut être l'un des types d'ensembles de codes reconnus, y compris :

country
language
currency
script
etc.

La liste des types valides, et les ensembles de codes pris en charge dans chacun, sont décrits dans le document Locale::Codes::Types.

Cette méthode peut être appelée plusieurs fois pour basculer entre différents types d'ensembles de codes.

codeset ( CODESET )
$obj->codeset($codeset);

Ceci définit l'ensemble de codes par défaut à utiliser. La liste des ensembles de codes disponibles pour chaque type est décrite dans le document Locale::Codes::Types.

Dans toutes les autres méthodes ci-dessous, lorsqu'un argument facultatif CODESET est omis, il prendra par défaut cette valeur.

code2name ( CODE [,CODESET] [,'retired'] )
$name = $obj->code2name($code [,$codeset] [,'retired']);

Cette fonction prend un code et renvoie une chaîne de caractères contenant le nom de l'élément identifié. Si le code n'est pas un code valide dans le CODESET spécifié, "undef" sera retourné.

Le nom de l'élément est le nom tel que spécifié dans la norme, et par conséquent, différentes variations du nom d'un élément peuvent être retournées pour différentes valeurs de CODESET.

Par exemple, le jeu de codes pays alpha-2 définit le code à deux lettres « bo » comme « Bolivie, État plurinational de », tandis que le jeu de codes alpha-3 définit le code « bol » comme le pays « Bolivie (État plurinational de) ». Donc :

$obj->code2name('bo','alpha-2');
   => 'Bolivie, État plurinational de'
$obj->code2name('bol','alpha-3');
   => 'Bolivie (État plurinational de)'

Par défaut, seuls les codes actifs seront utilisés, mais si la chaîne 'retired' est passée en argument, les codes actifs et retirés seront examinés.

code2names ( CODE [,CODESET] )
@name = $obj->code2names($code [,$codeset]);

Cette fonction prend un code et renvoie une liste de tous les noms et alias associés à ce code.

Seuls les codes actifs peuvent être utilisés et seuls les noms et alias actifs seront retournés.

name2code ( NAME [,CODESET] [,'retired'] )
$code = $obj->name2code($name [,$codeset] [,'retired']);

Cette fonction prend le nom d'un élément (ou l'un de ses alias) et renvoie le code qui lui correspond, s'il existe. Si NAME n'a pas pu être identifié comme le nom de l'un des éléments, alors "undef" sera retourné.

Le nom n'est pas sensible à la casse. De plus, toute variation connue d'un nom peut être passée.

Par exemple, même si le nom du pays retourné en utilisant les codes pays 'alpha-2' et 'alpha-3' pour la Bolivie sont différents, n'importe lequel des noms de pays peut être passé car pour chaque ensemble de codes (en plus de l'alias plus courant 'Bolivie'). Donc :

$obj->name2code('Bolivie, État plurinational de','alpha-2');
   => bo
$obj->name2code('Bolivie (État plurinational de)','alpha-2');
   => bo
$obj->name2code('Bolivie','alpha-2');
   => bo

Par défaut, seuls les noms actifs seront utilisés, mais si la chaîne 'retired' est passée en argument, les noms actifs et retirés seront examinés.

code2code ( CODE [,CODESET] ,CODESET2 )
$code = $obj->code2code($code [,$codeset] ,$codeset2);

MÉTHODES

code2name ( CODE [,CODESET] )
$name = $obj->code2name($code [,$codeset]);

This method returns the name associated with the given CODE. If the code is not found in the specified CODESET (or the default code set if none is specified), then it returns "undef".

For example:

$obj->code2name('us');
   => 'United States'
$obj->code2name('en', 'language');
   => 'English'

Note that this function does NOT support retired codes.

name2code ( NAME [,CODESET] )
$code = $obj->name2code($name [,$codeset]);

This method returns the code associated with the given NAME. If the name is not found in the specified CODESET (or the default code set if none is specified), then it returns "undef".

For example:

$obj->name2code('United States');
   => 'us'
$obj->name2code('English', 'language');
   => 'en'

Note that this function does NOT support retired codes.

code2code ( CODE ,CODESET ,CODESET2 )
$code = $obj->code2code($code, $codeset, $codeset2);

This method takes a CODE from one code set (CODESET or the default code set), and returns the corresponding code from another code set (CODESET2). CODE must exists in the code set specified by CODESET and must have a corresponding code in the code set specified by CODESET2 or "undef" will be returned.

$obj->code2code('fin','alpha-3','alpha-2');
   => 'fi'

Note that this function does NOT support retired codes.

all_codes ( [CODESET] [,'retired'] )
@code = $obj->all_codes([$codeset] [,'retired']);

This returns a list of all code in the code set. The codes will be sorted.

By default, only active codes will be returned, but if the string 'retired' is passed in as an argument, both active and retired codes will be returned.

all_names ( [CODESET] [,'retired'] )
@name = $obj->all_names([$codeset] [,'retired']);

This method returns a list of all elements names for which there is a corresponding code in the specified code set.

The names returned are exactly as they are specified in the standard, and are sorted.

Since not all elements are listed in all code sets, the list of elements may differ depending on the code set specified.

By default, only active names will be returned, but if the string 'retired' is passed in as an argument, both active and retired names will be returned.

The following additional methods are available and can be used to modify the code list data (and are therefore not generally useful).

rename_code ( CODE ,NEW_NAME [,CODESET] )
$flag = $obj->rename_code($code,$new_name [,$codeset]);

This method can be used to change the official name of an element. At that point, the name returned by the "code2name" method would be NEW_NAME instead of the name specified in the standard.

The original name will remain as an alias.

For example, the official country name for code 'gb' is 'United Kingdom'. If you want to change that, you might call:

$obj->rename_code('gb', 'Great Britain');

This means that calling code2name('gb') will now return 'Great Britain' instead of 'United Kingdom'.

If any error occurs, a warning is issued and 0 is returned. An error occurs if CODE doesn't exist in the specified code set, or if NEW_NAME is already in use but for a different element.

If the method succeeds, 1 is returned.

add_code ( CODE ,NAME [,CODESET] )
$flag = $obj->add_code($code,$name [,$codeset]);

This method is used to add a new code and name to the data.

Both CODE and NAME must be unused in the data set or an error occurs (though NAME may be used in a different data set).

For example, to create the fictitious country named "Duchy of Grand Fenwick" with codes "gf" and "fen", use the following:

$obj->add_code("fe","Duchy of Grand Fenwick",'alpha-2');
$obj->add_code("fen","Duchy of Grand Fenwick",'alpha-3');

The return value is 1 on success, 0 on an error.

delete_code ( CODE [,CODESET] )
$flag = $obj->delete_code($code [,$codeset]);

This method is used to delete a code from the data.

CODE must refer to an existing code in the code set.

The return value is 1 on success, 0 on an error.

add_alias ( NAME ,NEW_NAME )
$flag = $obj->add_alias($name,$new_name);

This method is used to add a new alias to the data. They do not alter the return value of the "code2name" function.

NAME must be an existing element name, and NEW_NAME must be unused or an error occurs.

The return value is 1 on success, 0 on an error.

delete_alias ( NAME )
$flag = $obj->delete_alias($name);

This method is used to delete an alias from the data. Once removed, the element may not be referred to by NAME.

NAME must be one of a list of at least two names that may be used to specify an element. If the element may only be referred to by a single name, you'll need to use the "add_alias" method to add a new alias first, or the "remove_code" method to remove the element entirely.

If the alias is used as the name in any code set, one of the other names will be used instead. Predicting exactly which one will be used requires you to know the order in which the standards were read, which is not reliable, so you may want to use the "rename_code" method to force one of the alternate names to be used.

The return value is 1 on success, 0 on an error.

replace_code ( CODE ,NEW_CODE [,CODESET] )
$flag = $obj->replace_code($code,$new_code [,$codeset]);

This method is used to change the official code for an element. At that point, the code returned by the "name2code" method would be NEW_CODE instead of the code specified in the standard.

NEW_CODE may either be a code that is not in use, or it may be an alias for CODE (in which case, CODE becomes an alias and NEW_CODE becomes the "real" code).

The original code is kept as an alias, so that the "code2name" routines will work with either the code from the standard or the new code.

However, the "all_codes" method will only return the codes which are considered "real" (which means that the list of codes will now contain NEW_CODE, but will not contain CODE).

add_code_alias ( CODE ,NEW_CODE [,CODESET] )
$flag = $obj->add_code_alias($code,$new_code [,$codeset]);

This method adds an alias for the code. At that point, NEW_CODE and CODE will both work in the "code2name" method. However, the "name2code" method will still return the original code.

delete_code_alias ( CODE [,CODESET] )
Ces routines suppriment un alias pour le code.

Celles-ci ne fonctionneront que si CODE est réellement un alias. S'il s'agit du code "réel", il ne sera pas supprimé. Vous devrez utiliser la méthode "rename_code" pour échanger le code réel avec l'un des alias, puis supprimer l'alias.

INTERFACES TRADITIONNELLES

En plus du module OO principal, les modules suivants sont inclus dans la distribution pour la manière traditionnelle de travailler avec les ensembles de codes.

Chaque module fonctionnera avec un type spécifique d'ensembles de codes.

Locale::Codes::Country, Locale::Country
Ceci inclut le support pour les codes de pays (tels que ceux listés dans ISO-3166) pour spécifier le pays.

Comme ce module était à l'origine distribué sous le nom de Locale::Country, il est également disponible sous ce nom.

Locale::Codes::Language, Locale::Language
Ceci inclut le support pour les codes de langue (tels que ceux listés dans ISO-639) pour spécifier la langue.

Comme ce module était à l'origine distribué sous le nom de Locale::Language, il est également disponible sous ce nom.

Locale::Codes::Currency, Locale::Currency
Ceci inclut le support pour les codes de devise (tels que ceux listés dans ISO-4217) pour spécifier la devise.

Comme ce module était à l'origine distribué sous le nom de Locale::Currency, il est également disponible sous ce nom.

Locale::Codes::Script, Locale::Script
Ceci inclut le support pour les codes de script (tels que ceux listés dans ISO-15924) pour spécifier le script.

Comme ce module était à l'origine distribué sous le nom de Locale::Script, il est également disponible sous ce nom.

Locale::Codes::LangExt
Ceci inclut le support pour les codes d'extension de langue (tels que ceux listés dans le registre des langues IANA) pour spécifier l'extension de langue.
Locale::Codes::LangVar
Ceci inclut le support pour les codes de variation de langue (tels que ceux listés dans le registre des langues IANA) pour spécifier la variation de langue.
Locale::Codes::LangFam
Ceci inclut le support pour les codes de familles de langues (tels que ceux listés dans ISO 639-5) pour spécifier les familles de langues.

En plus des modules ci-dessus, un certain nombre de modules de support sont inclus dans la distribution. Tout module non listé ci-dessus entre dans cette catégorie.

Ces modules ne sont pas destinés à être utilisés par les programmeurs. Ils contiennent des fonctions ou des données utilisées par les modules listés ci-dessus. Aucun support d'aucune sorte n'est offert pour l'utilisation directe de ces modules. Ils peuvent être modifiés à tout moment.

Locale::Codes - Man pages

NOM

Locale::Codes - Support pour les codes de localisation et leurs noms.

DESCRIPTION

Ce module fournit des fonctions pour rechercher des codes de localisation (par exemple, des codes de pays, de langue, de devise, etc.) à partir de leurs noms, et vice versa. Il supporte un certain nombre de jeux de codes différents, dont beaucoup sont basés sur des normes ISO.

Le module est conçu pour être aussi complet que possible, et pour supporter les variantes courantes des noms des codes. Il inclut également une gestion des codes obsolètes et des alias courants.

SYNOPSIS (INTERFACE ORIENTÉE OBJET)

  use Locale::Codes;

  my $codes = Locale::Codes->new();

  # Obtenir le code ISO 3166-1 alpha-2 pour "France"
  my $country_code = $codes->code2name('fr', 'country_code');
  print "Le code pour la France est $country_code\n"; # Imprime 'fr'

  # Obtenir le nom associé au code de pays "JP"
  my $country_name = $codes->name2code('JP', 'country');
  print "Le nom pour le code JP est $country_name\n"; # Imprime 'Japan'

  # Obtenir le code ISO 639-1 pour l'anglais
  my $lang_code = $codes->code2name('English', 'language_code');
  print "Le code pour l'anglais est $lang_code\n"; # Imprime 'en'

  # Obtenir le nom associé au code de langue "es"
  my $lang_name = $codes->name2code('es', 'language');
  print "Le nom pour le code es est $lang_name\n"; # Imprime 'Spanish'

  # Obtenir le code ISO 4217 pour l'euro
  my $currency_code = $codes->code2name('Euro', 'currency_code');
  print "Le code pour l'euro est $currency_code\n"; # Imprime 'EUR'

  # Obtenir le nom associé au code de devise "USD"
  my $currency_name = $codes->name2code('USD', 'currency');
  print "Le nom pour le code USD est $currency_name\n"; # Imprime 'US Dollar'

MÉTHODES ORIENTÉES OBJET

new
Crée un nouvel objet Locale::Codes.
code2name( $code, $type )
Renvoie le nom associé au code donné pour le type spécifié. Si le code n'est pas trouvé, renvoie undef. Le paramètre facultatif $type peut être 'country', 'language', 'currency', 'script', 'variant', etc. Si $type n'est pas spécifié, la fonction essaiera de deviner le type.
name2code( $name, $type )
Renvoie le code associé au nom donné pour le type spécifié. Si le nom n'est pas trouvé, renvoie undef. Le paramètre facultatif $type peut être 'country', 'language', 'currency', 'script', 'variant', etc. Si $type n'est pas spécifié, la fonction essaiera de deviner le type.
all_codes( $type )
Renvoie une liste de tous les codes pour le type spécifié.
all_names( $type )
Renvoie une liste de tous les noms pour le type spécifié.
types()
Renvoie une liste de tous les types de codes supportés.

INTERFACES TRADITIONNELLES

En plus de l'interface orientée objet, Locale::Codes fournit également des interfaces traditionnelles pour chaque type de code.

  use Locale::Codes;

  # Pour les pays
  my $country_code = country2code('France');
  my $country_name = code2country('FR');

  # Pour les langues
  my $lang_code = language2code('English');
  my $lang_name = code2language('en');

  # Pour les devises
  my $currency_code = currency2code('Euro');
  my $currency_name = code2currency('EUR');

Il existe des interfaces similaires pour les scripts et les variantes. Pour une liste complète, voir la documentation de Locale::Codes::Types.

ALIAS COURANTS

À partir de la version 2.00, les modules supportent des variantes courantes des noms.

Par exemple, Locale::Country supporte des noms variants pour les pays, et quelques-uns des plus courants sont inclus dans les données. Le code pays pour "États-Unis" est "us", donc :

country2code('United States');
  => "us"

Maintenant, les appels suivants retourneront également 'us' :

country2code('United States of America');
country2code('USA');

Un nombre quelconque d'alias courants peut être inclus dans les données, en plus des noms provenant directement des normes. Si vous avez un alias courant pour un pays, une langue, ou tout autre type de code, faites-le moi savoir et je l'ajouterai, avec quelques restrictions.

Par exemple, le nom de pays "Corée du Nord" n'est jamais apparu dans aucune des sources officielles (il était plutôt "Corée, Nord" ou "Corée, République populaire démocratique de". J'honorerai une demande pour ajouter un alias "Corée du Nord" car c'est une façon très courante de spécifier le pays (s'il vous plaît, ne demandez pas cela... je l'ai déjà ajouté).

D'un autre côté, une demande pour ajouter Zaïre comme alias pour "Congo, République démocratique du" ne sera pas honorée. Le nom officiel du pays n'est plus Zaïre, donc l'ajouter comme alias viole la norme. Zaïre a été conservé comme alias dans les versions de ce module antérieures à 3.00, mais il a été supprimé. D'autres alias (s'il y en a) qui n'apparaissent plus dans aucune norme (et qui ne sont pas des variations courantes du nom dans les normes) ont également été supprimés.

CODES OBSOLÈTES

Occasionnellement, un code est déprécié, mais il peut encore être souhaitable d'y avoir accès.

Bien qu'il n'y ait aucun moyen de voir tous les codes qui ont jamais existé et ont été dépréciés (car la plupart des jeux de codes ne disposent pas de ces informations), à partir de la version 3.20, chaque code qui a jamais été inclus dans ces modules peut être référencé.

Pour plus d'informations, reportez-vous à la documentation des méthodes code2name, name2code, all_codes et all_names ci-dessus.

BOGUES ET LIMITATIONS CONNUS

Relation entre les jeux de codes
Comme chaque jeu de codes utilise une liste d'éléments légèrement différente, et qu'ils ne sont pas nécessairement un-à-un, il peut y avoir une certaine confusion quant à la relation entre les codes de différents jeux de codes.

Par exemple, ISO 3166 attribue un code au pays "Îles mineures éloignées des États-Unis", mais les codes IANA attribuent différents codes à différentes îles (Île Baker, Île Howland, etc.).

Cela peut causer une certaine confusion... J'ai fait de mon mieux pour la minimiser.

Caractères non-ASCII non supportés
Actuellement, tous les noms doivent être entièrement en ASCII. J'ai l'intention de relâcher cette limitation à l'avenir.
