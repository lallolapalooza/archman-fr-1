NOM

Lire::DlfSchema - Interface aux spécifications XML des schémas DLF de Lire

SYNOPIS

Dans les convertisseurs DLF :

use Lire::DlfSchema;
my $schema = Lire::DlfSchema::load_schema( "email" );
my $fields = $schema->fields();
my $dlf_id = $schema->field( 'dlf_id' );
my $dlf_src = $schema->field( 'dlf_source' );

DESCRIPTION

Ce module est l'interface aux schémas DLF de Lire définis dans des fichiers XML. Un schéma définit l'ordre des champs ainsi que leurs noms, descriptions et types.

Chaque DlfSchema a au moins deux champs prédéfinis :

dlf_id
Il s'agit d'un entier qui identifie de manière unique un enregistrement DLF dans son flux. Il est utilisé pour lier l'enregistrement à ses champs de schémas étendus et également pour lier l'enregistrement aux enregistrements des schémas dérivés.
dlf_source
Il s'agit d'un identifiant qui peut être utilisé pour suivre l'enregistrement du ImportJob qui l'a créé.

ACCÈS À UN OBJET SCHÉMA

La manière d'accéder à un schéma pour un superservice est via la fonction du module load_schema(). Vous l'utilisez comme ceci :

my $schema = Lire::DlfSchema::load_schema( $superservice);

Cette fonction renverra un objet schéma qui pourra ensuite être utilisé pour interroger des informations sur le schéma. Cette fonction mourra() en cas d'erreur.

a_superservice( $superservice )

Renvoie vrai s'il existe un superservice nommé $schema_name. Une erreur sera levée si le nom du schéma n'est pas valide pour un superservice.

a_schema( $schema_name )

Renvoie vrai s'il existe $schema_name. Une erreur sera levée si le nom du schéma n'est pas valide.

superservices()

Renvoie le nom des superservices disponibles dans un tableau.

schemas()

Renvoie le nom des schémas disponibles dans un tableau.

MÉTHODES DE L'OBJET SCHÉMA

id()

my $id = $schema->id();

Cette méthode renverra l'identifiant du schéma. Ce sera le nom du superservice pour le schéma principal du superservice. (Il existe d'autres types de schémas (schémas dérivés et étendus) pour lesquels l'identifiant sera différent du nom du superservice.)

superservice()

my $super = $schema->superservice();

Cette méthode renverra le nom du superservice du schéma.

titre( [$nouveau_titre] )

Cette méthode renverra (ou modifiera) le titre lisible du schéma. (C'est le contenu de l'élément titre dans la spécification XML.)

description( [$nouvelle_description] )

Cette méthode renverra (ou modifiera) la description du schéma. (C'est le contenu de l'élément description dans la spécification XML.) Attention, cela contiendra très probablement du balisage DocBook.

field_by_pos()

my $field = $schema->field_by_pos( 0 );

Cette méthode prend un entier comme paramètre et renvoie le champ à cette position dans le schéma. Les champs sont indexés à partir de 0. Cette méthode mourra() si une position invalide est passée en paramètre.

La méthode renvoie un objet Lire::Field(3pm).

ajouter_champ( $champ )

Ajoute le Lire::Field $champ à ce schéma.

a_champ()

if ( $schema->a_champ( 'test ) ) { 
    print "le schéma a le champ 'test'\n"; 
}

Cette méthode prend une chaîne de caractères comme paramètre et renvoie une valeur booléenne. Cette valeur sera vraie s'il existe un champ dans le schéma portant ce nom, sinon elle sera fausse.

champ()

my $field = $schema->champ( 'from_email' );

Cette méthode prend le nom d'un champ comme paramètre et renvoie l'objet Lire::Field(3pm) décrivant ce champ dans le schéma. La méthode mourra() s'il n'y a pas de champ portant ce nom dans le schéma.

champs()

my $fields = $schema->champs();
my @fields = $schema->champs();

Dans un contexte de tableau, cette méthode renverra un tableau contenant tous les champs (sous forme d'objets Lire::Field(3pm)) du schéma. L'ordre des champs dans le tableau est l'ordre des champs dans le schéma.

Dans un contexte scalaire, elle renverra une référence de tableau. Cette méthode est plus efficace que la création d'un tableau. NE MODIFIEZ PAS LE TABLEAU RETOURNÉ.

noms_champs()

Renvoie le nom des champs dans ce schéma. Les noms sont dans le même ordre que les champs.

nb_champs()

my $nombre_de_champs = $schema->nb_champs;

Cette méthode renvoie le nombre de champs dans le schéma.

champ_horodatage()

my $champ_temps = $schema->champ_horodatage;

Cette méthode renverra l'objet Lire::Field(3pm) représentant le champ d'horodatage dans le schéma. Le champ d'horodatage est celui qui définit l'ordre de tri des enregistrements DLF.

est_schema_compatible()

if ( $schema->est_schema_compatible( $autre_schema ) ) {
}

Cette méthode prend un objet Lire::DlfSchema(3pm) comme paramètre et renvoie une valeur booléenne. Cette valeur sera vraie si le schéma passé en paramètre est compatible avec l'autre, sinon elle sera fausse.

Pour un schéma de superservice, le seul schéma compatible est un objet représentant le schéma du même superservice.

peut_rejoindre_schema( $schema )

Renvoie vrai si $schema peut être joint avec ce schéma. Pour un DlfSchema, cela ne sera vrai que lorsque $schema est un ExtendedSchema de ce schéma.

Méthodes liées à SQL

Ces méthodes sont utilisées pour mapper les enregistrements DLF dans des tables SQL.

table_sql()

Renvoie la table SQL utilisée pour stocker les enregistrements DLF de ce schéma.

creer_schema_sql( $dlf_store, [ $supprimer ] )

Cela créera les schémas SQL nécessaires pour stocker les enregistrements DLF pour ce schéma dans le Lire::DlfStore. Si $supprimer est vrai, un DROP TABLE sera effectué avant de créer le schéma.

a_besoin_migration_schema_sql( $dlf_store )

Cette méthode renverra vrai si le schéma SQL n'est pas à jour dans le DlfStore. La méthode migrer_schema_sql() peut être utilisée pour mettre à jour le schéma.

migrer_schema_sql( $dlf_store )

Met à jour les schémas SQL vers la version actuelle.

NOM

Lire::DlfSchema

SYNOPIS

use Lire::DlfSchema;

DESCRIPTION

Lire::DlfSchema est un module qui fournit un accès aux enregistrements DLF dans le schéma. Il permet aux utilisateurs d'interroger, d'insérer et de supprimer des enregistrements DLF à l'aide d'instructions SQL.

ACCÈS À UN OBJET DE SCHÉMA

Pour accéder à un objet de schéma, vous pouvez utiliser les méthodes suivantes :

  • La méthode get_schema() renvoie une référence à l'objet de schéma.
  • La méthode get_schema_by_name() renvoie une référence à l'objet de schéma par son nom.
  • La méthode get_schema_by_id() renvoie une référence à l'objet de schéma par son identifiant.

MÉTHODES DE L'OBJET DE SCHÉMA

L'objet de schéma fournit les méthodes suivantes :

  • La méthode query() renvoie un objet Lire::DlfQuery qui peut être utilisé pour récupérer des enregistrements DLF.
  • La méthode insert_sql_query() renvoie l'instruction SQL INSERT pour insérer des enregistrements DLF.
  • La méthode sql_clean_query() renvoie l'instruction SQL DELETE pour nettoyer les enregistrements DLF.
  • La méthode sql_clean_period_query() renvoie l'instruction SQL DELETE pour nettoyer les enregistrements DLF avec des limites temporelles.
  • La méthode sort_spec() renvoie la spécification de tri pour l'interrogation des enregistrements DLF.
  • La méthode sort_spec($sort_spec) définit la spécification de tri pour l'interrogation des enregistrements DLF.
  • La méthode insert_query() renvoie l'instruction SQL INSERT pour insérer des enregistrements DLF.
  • La méthode execute_insert_query() exécute l'instruction SQL INSERT avec une poignée DBI::st.
  • La méthode clean_query() renvoie l'instruction SQL DELETE pour nettoyer les enregistrements DLF.
  • La méthode clean_period_query() renvoie l'instruction SQL DELETE pour nettoyer les enregistrements DLF avec des limites temporelles.
  • La méthode clean_period_query($with_time) renvoie l'instruction SQL DELETE pour nettoyer les enregistrements DLF avec des limites temporelles.
  • La méthode clean_period_query($with_time, $time1, $time2) renvoie l'instruction SQL DELETE pour nettoyer les enregistrements DLF avec des limites temporelles.

MÉTHODES LIÉES À SQL

L'objet de schéma fournit les méthodes suivantes liées à SQL :

  • La méthode query() renvoie un objet Lire::DlfQuery qui peut être utilisé pour récupérer des enregistrements DLF.
  • La méthode insert_sql_query() renvoie l'instruction SQL INSERT pour insérer des enregistrements DLF.
  • La méthode sql_clean_query() renvoie l'instruction SQL DELETE pour nettoyer les enregistrements DLF.
  • La méthode sql_clean_period_query() renvoie l'instruction SQL DELETE pour nettoyer les enregistrements DLF avec des limites temporelles.
  • La méthode sort_spec() renvoie la spécification de tri pour l'interrogation des enregistrements DLF.
  • La méthode sort_spec($sort_spec) définit la spécification de tri pour l'interrogation des enregistrements DLF.
  • La méthode insert_query() renvoie l'instruction SQL INSERT pour insérer des enregistrements DLF.
  • La méthode execute_insert_query() exécute l'instruction SQL INSERT avec une poignée DBI::st.
  • La méthode clean_query() renvoie l'instruction SQL DELETE pour nettoyer les enregistrements DLF.
  • La méthode clean_period_query() renvoie l'instruction SQL DELETE pour nettoyer les enregistrements DLF avec des limites temporelles.
  • La méthode clean_period_query($with_time, $time1, $time2) renvoie l'instruction SQL DELETE pour nettoyer les enregistrements DLF avec des limites temporelles.
