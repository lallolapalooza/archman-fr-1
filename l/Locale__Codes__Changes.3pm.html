NOM

Locale::Codes::Changes - détails des changements apportés à Locale::Codes

SYNOPSIS

Ceci décrit les changements apportés aux modules de la distribution Locale-Codes. Les changements majeurs sont marqués d'astérisques (*). Pour la plupart, tous les modules sont restés rétrocompatibles à chaque version, mais occasionnellement un changement est apporté qui est rétrocompatibilité. Ceux-ci sont marqués d'un point d'exclamation (!).

Depuis la version 3.00, les codes sont générés automatiquement à partir des normes. Avec chaque version, les codes seront régénérés et testés pour voir si un code a changé. Tout changement apporté aux codes sera signalé ci-dessous avec un changement : NOUVEAU(X) CODE(S).

J'ai l'intention de vérifier les nouveaux codes quatre fois par an (mars, juin, septembre, décembre). J'essaierai également de répondre aux demandes de publication en raison de changements apportés aux normes, donc si un code que vous utilisez change, n'hésitez pas à me contacter. En fonction de mon temps disponible et du temps restant avant la prochaine publication prévue, j'essaierai de faire une publication chaque fois que les normes changeront.

Codes pays FIPS-10 obsolètes
Le document FIPS-10 est en cours de retrait. Il était obsolète en 2008 et n'est actuellement mis à jour que jusqu'à ce que toutes les agences qui l'utilisent soient passées à autre chose. La version actuelle ne liste plus les noms longs des pays. Il est conseillé de ne plus utiliser le jeu de codes FIPS-10.

Les codes pays de domaine proviennent maintenant de l'ISO 3166
Les codes de domaine IANA ont légèrement changé. L'IANA ne publie plus une liste de pays associés à leurs codes. Au lieu de cela, ils utilisent les codes et les noms de pays ISO 3166. Cependant, ils prennent en charge quelques codes non standard, je continuerai donc à maintenir ce jeu de codes. Les codes de domaine sont maintenant en minuscules pour correspondre aux codes ISO 3166.

Déplacement des fichiers de support dans l'espace de noms Locale::Codes.

Le travail effectué dans chacun des modules Locale::XXX était pratiquement identique. Tout a été déplacé vers un module central et les modules Locale::XXX ne sont plus que des wrappers.

(!) Comportement de XXX_code2code légèrement modifié
Dans les versions précédentes, passer le même ensemble de codes pour les deux arguments d'ensemble de codes renvoyait automatiquement undef. Par exemple : 
country_code2code('bo',LOCALE_CODE_ALPHA_2,LOCALE_CODE_ALPHA_2);
   => undef

Cela ne semble pas être un comportement raisonnable, il a donc été modifié pour autoriser le même ensemble de codes :

country_code2code('bo',LOCALE_CODE_ALPHA_2,LOCALE_CODE_ALPHA_2);
   => 'bo'

Notez que si un code invalide est passé, undef sera toujours renvoyé :

country_code2code('bol',LOCALE_CODE_ALPHA_2,LOCALE_CODE_ALPHA_2);
   => undef

VERSION 3.00 (2010-02-10 sbeck)

NOUVEAU(X) CODE(S)
(*) Nouveau mainteneur
De 1997 à 2004, Locale::Codes a été maintenu par Neil Bowers. Malheureusement, aucune mise à jour n'a été effectuée de juin 2004 à janvier 2010. Pendant cette période, un certain nombre de changements ont été apportés aux normes, de sorte que les données incluses étaient obsolètes.

J'ai contacté Neil pour obtenir sa permission de reprendre la maintenance du module, et il a gentiment accepté.

(*) (!) Tous les codes sont générés à partir des normes
Toutes les valeurs renvoyées par les différentes fonctions sont maintenant des valeurs directement issues des normes. Cela signifie que les valeurs renvoyées dans la série 2.xx ne sont pas nécessairement les mêmes que celles renvoyées ici.

À titre d'exemple, la norme ISO 3166 qui répertorie les codes pays fait référence au pays associé au code "bo" comme "Bolivie, État plurinational de", c'est donc ce qui est renvoyé. Dans la série 2.xx, "Bolivie" était renvoyé. De plus, les noms de pays varient d'une norme à l'autre. Ainsi, le code "bol", maintenu par les Nations Unies, renvoie le nom du pays comme "Bolivie (État plurinational de)". Certains alias courants ont été ajoutés, de sorte que vous pouvez toujours demander un code associé au nom de pays "Bolivie".

Étant donné que les données proviennent des normes, certaines valeurs "incorrectes" ne sont plus prises en charge. Par exemple, la version 2.07 traitait "Zaïre" comme un alias pour "Congo", mais le pays a changé de nom, et "Zaïre" n'est pas dans la norme, il a donc été supprimé dans la version 3.00.

Codes monétaires numériques (demandé dans RT 18797)

(*) (!) Locale::Script modifié
Dans la version 2.xx, Locale::Script associait des scripts à des codes pays, ce qui N'EST PAS la façon dont cela est fait actuellement dans les normes. Il semble qu'une ancienne version de l'ISO 15924 le faisait, mais je n'ai pas trouvé d'ancienne version pour le confirmer, et en tout cas, ce n'est pas le cas dans les normes actuelles.

En conséquence, le module Locale::Script est complètement incompatible avec la version 2.xx en ce qui concerne les types de codes qu'il prend en charge. Aucun des anciens codes ne fonctionnera.

Ajout de fonctions manquantes
J'ai ajouté quelques fonctions qui étaient précédemment "manquantes" (comme il n'y avait qu'un seul ensemble de codes pris en charge, les fonctions code2code n'étaient pas applicables) : 
language_code2code
currency_code2code

ainsi, les interfaces pour chaque type de codes sont cohérentes.

(!) Suppression du support pour _alias_code
Dans Locale::Country, _alias_code était une fonction autorisée mais dépréciée, dont il était documenté qu'elle était prise en charge dans la série 2.xx. Je l'ai supprimée.
(!) Toutes les fonctions renvoient la valeur standard
code2country (et autres fonctions équivalentes) renvoie maintenant le nom du pays spécifié dans la norme (si les différentes normes font référence à
Locale::Country - Les codes pays, langues et monnaies ISO

CHANGES

(!) rename_country function changed
The previous behaviour of this function was to guess the CODESET. This could lead to problems, since (with the addition of FIPS) codes may appear in different codesets for different countries. The behaviour has been changed to be the same as other functions (default to LOCALE_CODE_ALPHA_2).
(*) Added FIPS codes
The FIPS codes have been added to the country codes.
(!) Changed behaviour
The previously undocumented behaviour of allowing the use of codes from different codesets in the same call has been removed. The country names will now correspond to the CODESET.
(!) New CODESET
The new CODESET `LOCALE_CODE_FIPS_10` has been added. The documentation has been updated to reflect this.
(!) Country name matching
Previously the country names were matched as a substring of the country name. This has been changed to a full match, so that the country name is only matched if it is the complete name. This means that if you use the full country name and it is the same as a different country name, the results will differ based on the CODESET.
(!) rename_country function altered
The rename_country function from 2.07 would guess the CODESET (unlike all other functions which used a default of LOCALE_CODE_ALPHA_2). The guess can cause problems since (with the addition of FIPS) codes may appear in different codesets for different countries. The behavior has been changed to be the same as other functions (default to LOCALE_CODE_ALPHA_2).

VERSION 2.00 (2002-02-17 neilb)

Created Locale::Script which provides an interface to the ISO codes for identification of scripts (writing scripts, rather than perl style scripts). The codes are defined by ISO 15924, which is currently in final draft. Thanks to Jarkko for pointing out this new standard. All three code sets are supported, and a test-suite added.

Added support for country name variants to Locale::Country, so that
country2code('USA')
country2code('United States')
country2code('United States of America') will all return 'us'. This had been in the LIMITATIONS section since the first version. Patch from TJ Mather with additional variants from me. Added test-cases for these.

Added VERSION to Locale::Constants. Thanks to Jarkko for pointing that it was missing.

Should really have bumped major version with previous release, since there was a change to the API.
