NOM

Lire::ReportParser::AsciiDocBookFormatter - Sous-classe de Lire::ReportParser qui formate la description.

SYNTAXE

Pour formater en DocBook :

use Lire::ReportParser::AsciiDocBookFormatter qw/dbk2txt/;
my $txt = dbk2txt( "<para>Test</para>" );

Dans les processeurs de rapports XML :

package MyParser;
use base qw/ Lire::ReportParser::AsciiDocBookFormatter Lire::ReportParser /;
sub new {
    my $self = shift->SUPER::new( @_ );
    $self->init_docbook_formatter( @_ );
    return $self;
}
sub handle_description {
    my ( $self, $desc ) = @_;
    print $desc;
    return;
}

DESCRIPTION

Ce paquet implémente des méthodes qui peuvent gérer le contenu des éléments "description" et peut être utilisé par une sous-classe de Lire::ReportParser. Le client n'a qu'à hériter de ce module afin qu'une méthode handle_description() soit disponible pour traiter la description DocBook formatée en texte.

Ce module fournit également une fonction pratique dbk2txt() qui peut être utilisée pour formater une chaîne contenant des éléments DocBook en un équivalent ASCII.

UTILISATION DE Lire::ReportParser::AsciiDocBookFormatter

Les processeurs Lire::ReportParser qui souhaitent travailler avec la version texte de la description doivent hériter de Lire::ReportParser::AsciiDocBookFormatter en plus de Lire::ReportParser. S'ils redéfinissent les méthodes description_start() et description_end(), ils doivent faire appel à la version de leurs parents en utilisant "SUPER::".

De plus, ils doivent fusionner la valeur de elements_spec() dans leur implémentation de elements_spec().

Lire::ReportParser::AsciiDocBookFormatter doit être listé avant Lire::ReportParser dans @ISA. AsciiDocBookFormatter n'hérite pas directement de Lire::ReportParser afin qu'il puisse être utilisé dans des scénarios d'héritage multiple.

La sous-classe doit appeler la méthode init_docbook_formatter() depuis sa méthode constructeur pour initialiser le module DocBookFormatter.

init_docbook_formatter( %params )

L'initialiseur reconnaît certains paramètres qui peuvent être utilisés pour contrôler le comportement de la gestion DocBook :

colonnes
Le nombre de colonnes dans lesquelles le texte DocBook doit être formaté. La valeur par défaut est 72.

dbk_start_processing()

Initialise la structure du parseur pour formater le XML DocBook en ASCII. Ceci est utilisé à partir de l'implémentation de description_start.

dbk_end_processing()

Nettoie la structure du parseur. Ceci est utilisé à partir de l'implémentation de description_end().

handle_description( $description )

Cette méthode est appelée après la rencontre de la balise de fermeture de l'élément "description". $description contient la description formatée en texte brut.

FORMATAGE DES CHAÎNES DocBook

Si vous avez du contenu DocBook dans une chaîne, comme vous pouvez en obtenir de certains objets de Spécification de Rapport, vous pouvez le formater en texte brut en utilisant la fonction dbx2txt().

dbk2txt( $docbook_str, [$colonnes] )

Retourne une version texte brut du fragment XML DocBook $docbook_str. Le paramètre "colonnes" définit le nombre de colonnes dans lesquelles le texte DocBook doit être formaté.

Cette méthode provoquera une erreur (die()) en cas de problème.
