NOM

Locale::Po4a::SimplePod - convertir des données POD depuis/vers des fichiers PO, avec Pod::Simple

SYNTAXE

[po4a_paths] /chemin/vers/pot $lang:/chemin/vers/po
[type:SimplePod] /chemin/vers/source.pod $lang:/chemin/vers/localise.pod

ou

[po4a_paths] /chemin/vers/pot $lang:/chemin/vers/po
[po4a_alias:pod] SimplePod
[type:pod] /chemin/vers/source.pod $lang:/chemin/vers/localise.pod

DESCRIPTION

Ceci est un module pour aider à la traduction de la documentation au format POD (la langue préférée pour documenter Perl) vers d'autres langues humaines.

Les principales différences entre le format Pod actuel et le format SimplePod sont les suivantes :

  • Le format SimplePod n'inclut jamais de sauts de ligne supplémentaires dans les messages à traduire. Le format Pod actuel, cependant, peut contenir des sauts de ligne supplémentaires, en particulier dans les entrées de messages littéraux.
  • Les paragraphes peuvent être rendus avec retour à la ligne. Le module Pod::Parser pourrait appliquer un traitement spécial pour le retour à la ligne, rendant la réplication difficile avec Pod::Simple. Cependant, Pod::Simple semble produire un résultat plus naturel.
  • Dans SimplePod, le message "=for" (par exemple, "=for comment texte") n'inclut pas de nom de format (comme "comment"), donc le message ne consiste qu'en du texte. En revanche, le format Pod actuel conserve le nom du format, résultant en un message comme "comment texte". Le comportement précédent est considéré comme plus confortable pour les traducteurs.
  • Les entrées comme celle ci-dessous, qui dénotent "=end comment", ne sont plus présentes comme on le voit dans le module Pod actuel. Comme ce ne sont pas des messages traduisibles, leur absence est une amélioration. 
    #. type: =end
#: sample.pod:10
msgid "comment"
msgstr ""
  • Les blocs de texte dont la validité du format POD est incertaine sont maintenant traités comme "no-wrap". Ceci s'applique, par exemple, au contenu d'un bloc "=begin html". Dans le module Pod, ceux-ci n'étaient pas traités comme "no-wrap", ce qui entraînait parfois un retour à la ligne.
  • La section de paramètre "=begin" n'est plus soumise à traduction. Dans le module Pod actuel, elle est incluse. S'il y a une demande pour l'inclure dans la traduction, veuillez la signaler.

ÉTAT DE CE MODULE

Ce module est encore nouvellement développé, il est donc moins stable que Locale::Po4a::Pod. Il continue d'évoluer et il y a place pour une amélioration supplémentaire. Son comportement pourrait changer avec le temps, et des options supplémentaires pourraient être introduites pour mieux optimiser l'expérience de traduction pour les utilisateurs. Les retours et les cas d'utilisation d'applications réelles joueront un rôle clé dans l'orientation de son développement futur.

Le code est entièrement couvert par notre suite de tests, et nous n'avons connaissance d'aucun bug existant. Cependant, à partir de 2025, il n'a pas été testé en conditions réelles de flux de traduction par des projets externes. Cela dit, nous pensons que le module est prêt pour une utilisation en production, même si certains bugs seront inévitablement découverts à mesure qu'il gagnera en adoption.

Ce module est destiné à remplacer le module actuel Locale::Po4a::Pod. La raison est que Pod::Parser, utilisé par Locale::Po4a::Pod actuel, est maintenant obsolète, et il est recommandé d'utiliser Pod::Simple à la place. Voir aussi le problème GitHub #256 « Consider migrating away from deprecated "Pod::Parser" » https://github.com/mquinson/po4a/issues/256.
