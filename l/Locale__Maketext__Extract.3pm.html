NOM Documentation des contributeurs Perl Locale::Maketext::Extract(3)

NOM

Extraire des chaînes traduisibles à partir des sources

VERSION

version 1.00

SYNOPSIS

my $Ext = Locale::Maketext::Extract->new;
$Ext->read_po('messages.po');
$Ext->extract_file($_) for <*.pl>;
# Configurer $entries_are_in_gettext_format si les fichiers ci-dessus utilisent
# loc('%1') au lieu de loc('[_1]')
$Ext->compile($entries_are_in_gettext_format);
$Ext->write_po('messages.po');
-----------------------------------
### Spécifier les plugins de parser ###
my $Ext = Locale::Maketext::Extract->new(
    # Spécifier quels plugins de parser utiliser
    plugins => {
        # Utiliser le parser Perl, traiter les fichiers avec extension .pl .pm .cgi
        perl => [],
        # Utiliser le parser YAML, traiter tous les fichiers
        yaml => ['*'],
        # Utiliser le parser TT2, traiter les fichiers avec extension .tt2 .tt .html
        # ou qui correspondent au regex
        tt2  => [
            'tt2',
            'tt',
            'html',
            qr/\.tt2?\./
        ],
        # Utiliser My::Module comme parser pour tous les fichiers
        'My::Module' => ['*'],
    },
    # Afficher les erreurs si un parser ne peut pas traiter un fichier ou s'il y a des problèmes
    warnings => 1,
    # Lister les fichiers traités
    verbose => 1,
);

DESCRIPTION

Ce module peut extraire des chaînes traduisibles à partir des sources et les réécrire dans des fichiers PO. Il peut également parser des fichiers existants et fusionner leur contenu avec les nouvelles chaînes extraites.

Ce module est livré avec un utilitaire en ligne de commande, xgettext.pl, ainsi qu'avec celui-ci.

Les parsers de format sont chargés en tant que plugins, il est donc possible de définir vos propres parsers.

Les formats de fichiers suivants sont pris en charge :

Fichiers sources Perl (plugin : perl)
Les noms de fonctions de localisation valides sont : "translate", "maketext", "gettext", "l", "loc", "x", "_" et "__".

Pour un parser plus précis mais lent, vous pouvez utiliser le plugin PPI. Celui-ci n'a pas de nom court (comme « perl »), mais doit être spécifié sous sa forme complète.

HTML::Mason (Mason 1) et Mason (Mason 2) (plugin : mason)
HTML::Mason (alias Mason 1)
Les chaînes à l'intérieur de <&|/l>...</&> et <&|/loc>...</&> sont extraites.

Mason (alias Mason 2) Les chaînes à l'intérieur de <% $.floc { %>...</%> ou <% $.fl { %>...</%> ou <% $self->floc { %>...</%> ou <% $self->fl { %>...</%> sont extraites.

Template Toolkit (plugin : tt2)
Les formats valides sont : 
[% | l(arg1,argn) %]string[% END %]
[% 'string' | l(arg1,argn) %]
[% l('string',arg1,argn) %]
FILTER y | sont interchangeables
l et loc sont interchangeables
les arguments sont optionnels
Text::Template (plugin : text)
Les phrases entre « STARTxxx » et « ENDxxx » sont extraites individuellement.
YAML (plugin : yaml)
Les formats valides sont _« chaîne » ou _'chaîne', par exemple : 
title: _"My title"
desc:  _'My "quoted" string'

Les guillemets n'ont pas besoin d'être échappés, vous pouvez donc également faire :

desc:  _"My "quoted" string"
HTML::FormFu (plugin : formfu)
HTML::FormFu utilise un fichier de configuration pour générer des formulaires, avec un support intégré pour la localisation des erreurs, des étiquettes, etc.

Les textes après « _loc :  » sont extraits.


content_loc: ceci est la chaîne
message_loc: ['Max string length: [_1]', 10]
Modèle générique (plugin : generic)
Les chaînes entre {{...}} sont extraites.

Voir « Plugins », « Warnings » et « Verbose » pour plus de détails.

Plugins

$ext->plugins({...});

Locale::Maketext::Extract utilise des plugins (voir ci-dessous pour la liste) pour parser différents formats.

Chaque plugin peut également spécifier quels types de fichiers il peut parser.

# utiliser uniquement le plugin YAML
# ne parser que les fichiers avec l'extension par défaut définie dans le plugin
# c'est-à-dire .yaml .yml .conf
$ext->plugins({
    yaml => [],
})
# utiliser uniquement le plugin Perl
# ne traiter aucun type de fichier
$ext->plugins({
    perl => '*'
})
$ext->plugins({
    tt2  => [
        'tt',              # correspond au nom de fichier de base par rapport à /\.tt$/
        qr/\.tt2?\./,      # correspond au nom de fichier de base par rapport au regex
        \&my_filter,       # coderef appelé
    ]
})
sub my_filter {
    my ($base_filename,$path_to_file) = @_;
    return 1 | 0;
}
# Spécifier votre propre parser
# ne parser que les fichiers avec la liste d'extensions par défaut définie dans le plugin
$ext->plugins({
    'My::Extract::Parser'  => []
})

Par défaut, si aucun plugin n'est spécifié, il essaie d'abord de déterminer quels plugins sont spécifiquement pour le type de fichier et les utilise. Si aucun plugin de ce type n'est trouvé, il utilise les plugins prédéfinis, en surchargeant les extensions définies dans chacun.

Plugins disponibles

"perl" : Locale::Maketext::Extract::Plugin::Perl
Pour un parser plus précis mais lent, vous pouvez utiliser le plugin PPI. Celui-ci n'a pas de nom court, mais doit être spécifié sous sa forme complète, c'est-à-dire : Locale::Maketext::Extract::Plugin::PPI
"tt2" : Locale::Maketext::Extract::Plugin::TT2
"yaml" : Locale::Maketext::Extract::Plugin::YAML
"formfu" : Locale::Maketext::Extract::Plugin::FormFu
"mason" : Locale::Maketext::Extract::Plugin::Mason
"text" : Locale::Maketext::Extract::Plugin::TextTemplate
"generic" : Locale::Maketext::Extract::Plugin::Generic

Voir également Locale::Maketext::Extract::Plugin::Base pour les détails sur la façon d'écrire votre propre plugin.

Warnings

Étant donné que les plugins YAML et TT2 utilisent des parsers corrects au lieu de simples regex, si un fichier source n'est pas valide et ne peut pas être parsé, le parser lèvera une erreur et arrêtera le processus de parsing.

Le plugin activé suivant sera tenté.

Par défaut, ces erreurs ne seront pas affichées. Si vous souhaitez les afficher, activez les avertissements via new(). Toutes les erreurs de parsing seront imprimées sur STDERR.

De plus, si vous développez votre propre plugin, activez les avertissements pour voir toutes les erreurs qui se produisent lors du chargement de votre plugin.

Verbose

Si vous souhaitez voir quels fichiers ont été traités, quels plugins ont été utilisés et quelles chaînes ont été extraites, activez "verbose". Si aucun plugin n'est accepté ou si aucune chaîne n'est extraite, le fichier ne sera pas listé :

   $ext = Locale::Extract->new( verbose => 1 | 2 | 3);
OU
   xgettext.pl ... -v           # fichiers rapportés
   xgettext.pl ... -v -v        # fichiers et plugins rapportés
   xgettext.pl ... -v -v -v     # fichiers, plugins et chaînes rapportés

Compilation

compile($les_entrées_sont_en_style_gettext?)

Fusionne les "entrées" dans "compiled_entries".

Si $les_entrées_sont_en_style_gettext est vrai, les entrées précédemment extraites sont supposées être dans le style Gettext (par exemple, %1).

Sinon, elles sont supposées être dans le style Maketext (par exemple, "[_1]") et sont converties dans le style Gettext avant d'être fusionnées dans "compiled_entries".

Les "entrées" ne sont *pas* effacées après chaque compilation ; utilisez "-"set_entries() pour les effacer si vous avez besoin d'extraire à partir de sources de styles différents.
