Locale::Util(3) Documentation Perl fournie par l'utilisateur Locale::Util(3)

NOM

Locale::Util - Fonctions portables de l10n et i10n

SYNOPSIS

use Locale::Util;
my @linguas = parse_http_accept_language $ENV{HTTP_ACCEPT_LANGUAGE};
my @charsets = parse_http_accept_charset $ENV{HTTP_ACCEPT_CHARSET};
# Essayer de définir la locale en portugais brésilien en UTF-8.
my $set_locale = set_locale LC_ALL, 'pt', 'BR', 'utf-8';
set_locale_cache $last_cache;

my $cache = get_locale_cache;
web_set_locale ($ENV{HTTP_ACCEPT_LANGUAGE}, $ENV_ACCEPT_CHARSET);
web_set_locale (['fr-BE', 'fr', 'it'], ['cp1252', 'utf-8']);

DESCRIPTION

Ce module fournit des fonctions portables pour la localisation (l10n) et l'internationalisation (i10n). Il n'exporte rien par défaut, vous devez spécifier chaque fonction dont vous avez besoin dans la liste d'importation, ou utiliser le nom entièrement qualifié.

Les fonctions ici sont axées sur le développement web, bien qu'elles soient suffisamment générales pour figurer dans l'espace de noms Locale::.

Ce module est considéré comme du code alpha. L'interface n'est pas stable. Veuillez contacter l'auteur si vous souhaitez l'utiliser dans du code de production.

Ce module a été introduit dans libintl-perl 1.17.

FONCTIONS

parse_http_accept_language CHAINE
Analyse une chaîne de caractères telle qu'elle est fournie dans l'en-tête HTTP "Accept-Language". Elle retourne une liste de jetons triés par valeur de qualité, voir la RFC 2616 pour les détails.

Exemple :

parse_http_accept ("fr-fr, fr; q=0.7, de; q=0.3");

Cela signifie : Donnez-moi du français de France avec une valeur de qualité de 1.0 (le maximum). Sinon, j'accepterai toute autre version française (qualité 0.7), l'allemand a une qualité de 0.3 pour moi.

La fonction retournera une liste de jetons dans l'ordre de leurs valeurs de qualité, dans ce cas "fr-fr", "fr" et "de".

La fonction est plus tolérante que la RFC 2616. Elle accepte des valeurs de qualité supérieures à 1.0 et avec plus de 3 décimales. Elle accepte également des noms de langues et de pays de plus de 8 caractères. La langue "*" est traduite en "C".

parse_http_accept_charset CHAINE
Analyse une chaîne de caractères telle qu'elle est fournie dans l'en-tête HTTP "Accept-Charset". Elle retourne une liste de jetons triés par valeur de qualité, voir la RFC 2616 pour les détails.

Le jeu de caractères spécial "*" (signifie tous les jeux de caractères) sera traduit en valeur indéfinie.

set_locale CATEGORIE, LANGUE[, PAYS, JEU_DE_CARACTERES]
Tente de définir la locale de l'utilisateur au moyen de POSIX::setlocale(). Cette dernière fonction a l'inconvénient que son deuxième argument (la chaîne de description de la locale) est complètement non standard et dépendant du système. Cette fonction essaie de deviner au mieux la notion d'identifiant de locale du système, avec les arguments fournis :
CATEGORIE
Un argument entier pour une catégorie de locale valide. Ce sont les constantes LC_* (LC_ALL, LC_CTIME, LC_COLLATE, ...) définies dans Locale::Messages(3pm) et dans POSIX(3pm).
LANGUE
Un identifiant de langue à 2 lettres selon l'ISO 639. La casse n'a pas d'importance, mais une version non modifiée (c'est-à-dire non mise en minuscules) de la langue que vous avez fournie sera toujours essayée.
PAYS
Un identifiant de langue à 2 lettres selon l'ISO 639. La casse n'a pas d'importance, mais une version non modifiée (c'est-à-dire non mise en minuscules) de la langue que vous avez fournie sera toujours essayée.

Ce paramètre est optionnel. S'il n'est pas défini, la fonction essaiera de deviner un pays approprié, sinon elle le laissera au système d'exploitation.

JEU_DE_CARACTERES
Un nom de jeu de caractères valide. Valide signifie valide ! Le jeu de caractères "utf8" n'est pas valide (c'est "utf-8"). Les noms de jeux de caractères acceptés par les algorithmes de devinette dans Encode(3pm) ne sont pas nécessairement non plus valides.

Si le paramètre est indéfini, il est ignoré. Il est toujours ignoré sous Windows.

La fonction tente d'approcher la locale souhaitée par boucles, en l'affinant à chaque succès. Elle essaiera d'abord de définir la langue (pour n'importe quel pays), puis tentera de sélectionner la bonne langue, et enfin tentera de sélectionner le bon jeu de caractères.

La valeur de retour est fausse en cas d'échec, ou la valeur de retour de l'appel sous-jacent POSIX::setlocale() en cas de succès.

En contexte de tableau, la fonction retourne le nom du pays qui a été passé dans l'appel réussi à POSIX::setlocale(). Si cette chaîne est égale au nom du pays que vous avez passé en argument, vous pouvez être raisonnablement sûr que les paramètres pour ce pays sont réellement utilisés. S'ils ne sont pas égaux, la fonction a fait une supposition sur le pays (elle a une liste de pays "par défaut" pour chaque langue). Il semble que sous Windows, POSIX::setlocale() réussisse également si vous passez un nom de pays qui n'est pas réellement supporté. Par conséquent, l'information n'est pas complètement fiable.

Veuillez noter que cette fonction est destinée aux processus serveur (en particulier les applications web) qui ont besoin de basculer de manière portable vers une certaine locale. Ce n'est pas la manière recommandée de définir la locale du programme pour une application ordinaire. Dans une application ordinaire, vous devriez faire ceci :

use POSIX qw (setlocale LC_ALL);
setlocale LC_ALL, '';

La chaîne vide comme deuxième argument signifie que le système doit basculer vers la locale par défaut de l'utilisateur.

get_locale_cache
La fonction set_locale() peut être coûteuse, surtout en cas d'échec, car elle peut essayer de nombreuses combinaisons différentes, et le système peut avoir à charger de nombreuses définitions de locale à partir de sa base de données interne.

Afin d'accélérer les choses, les résultats sont mis en cache en interne dans une table de hachage, les clés étant les langues, les sous-clés les pays, et les sous-sous-clés les jeux de caractères. Vous pouvez obtenir une référence à cette table de hachage avec get_locale_cache().

La fonction ne peut pas échouer.

set_locale_cache TABLEAU_DE_HACHAGE
Définit le cache interne. Vous pouvez passer une table de hachage ou une référence à une table de hachage. La fonction utilisera ceci comme cache, en discardant son ancien cache. Cela vous permet de conserver la table de hachage persistante.

La fonction ne peut pas échouer.

web_set_locale (ACCEPT_LANGUAGE, ACCEPT_CHARSET, CATEGORIE, DISPONIBLES)

Vous pouvez passer une référence optionnelle à une liste de locales au format XPG4 qui sont disponibles dans votre application. Ceci est utile si vous connaissez les langues supportées par votre application. NAME

Locale::Util - utility functions for POSIX locales

SYNOPSIS

  use Locale::Util;
  my $locale = locale_name();
  if ( locale_equal($locale, "C") ) {
      print "Using C locale.\n";
  }
  set_locale("de_DE.UTF-8");
  ...
  locale_free();

DESCRIPTION

This module provides utility functions for manipulating POSIX locales. It allows you to query the current locale name, compare locale names, and set the locale for the current process. Note that this module is a wrapper around the C functions in the libintl library.

FUNCTIONS

locale_name
Returns the name of the current locale as a string. This is equivalent to calling `setlocale(LC_ALL, NULL)` in C.
locale_equal
Compares two locale names. Returns true if they are equal, false otherwise. This function handles potential differences in locale string representations.
set_locale
Sets the locale for the current process. The argument is a string representing the desired locale. This function attempts to automatically determine the correct category (e.g., LC_ALL, LC_CTYPE, etc.) based on the provided locale string. It may return undef on failure.
locale_free
Frees any resources allocated by the libintl library. It is recommended to call this function before exiting your program.

The set_locale() function tries to guess the category based on the requested locale string. This might not always be correct, especially on systems with unusual locale configurations. For more precise control, you might need to use the C API directly or a module that provides more fine-grained control over locale categories.

The function set_locale() tries to guess the locale category (e.g. LC_ALL, LC_CTYPE, LC_TIME, etc.) based on the provided locale string. This behaviour is intended to be convenient but might be problematic on some systems. If you want to be sure, use the C API. Please submit a bug report if you find a case where this guessing fails.

Note that the actual locale used might depend on system configurations and environment variables (LANG, LC_*). This module provides an interface to query the language, the country, and the charset actually used.

BUGS

The function set_locale() probably fails to guess the correct locale identifier on a lot of systems. If you have found such a case, please submit it as a bug report.

The bug tracking system for this packags is at http://rt.cpan.org/NoAuth/Bugs.html?libintl-perl

Please note that this module is considered alpha code, and the interface is not stable. Please contact the author, if you want to use it in production code.
