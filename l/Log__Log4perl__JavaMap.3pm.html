NOM

Log::Log4perl::JavaMap - mappe les appenders java log4j aux classes Log::Dispatch

SYNOPSIS

###############################
log4j.appender.FileAppndr1        = org.apache.log4j.FileAppender
log4j.appender.FileAppndr1.File   = /var/log/onetime.log
log4j.appender.FileAppndr1.Append = false
log4j.appender.FileAppndr1.layout = org.apache.log4j.PatternLayout
log4j.appender.FileAppndr1.layout.ConversionPattern=%d %4r [%t] %-5p %c %x - %m%n
###############################

DESCRIPTION

Si quelqu'un veut créer un appender appelé "org.apache.log4j.ConsoleAppender", nous voulons le traduire en Log::Dispatch::Screen, puis traduire les options log4j en paramètres Log::Dispatch.

Qu'est-ce qui est implémenté

(Notez que vous pouvez toujours utiliser le module Log::Dispatch::*. Par 'implémenté', je veux dire avoir une classe de traduction qui traduit les options log4j en options Log::Dispatch afin que vous puissiez utiliser la syntaxe log4j plutôt que log4perl dans votre fichier de configuration.)

Voici la liste des appenders que l'on trouve sur le site log4j actuel (06/2002).

Ceux-ci sont implémentés

ConsoleAppender     - Log::Dispatch::Screen
FileAppender        - Log::Dispatch::File
RollingFileAppender - Log::Dispatch::FileRotate (par Mark Pfeiffer)
JDBCAppender        - Log::Log4perl::Appender::DBI
SyslogAppender      - Log::Dispatch::Syslog
NTEventLogAppender  - Log::Dispatch::Win32EventLog

Ceux-ci devraient/vont/pourraient être implémentés

DailyRollingFileAppender -
SMTPAppender     - Log::Dispatch::Email::MailSender

Ceux-ci pourraient être implémentés mais ils n'ont pas de classes correspondantes dans Log::Dispatch (encore) :

NullAppender
TelnetAppender

Ceux-ci pourraient être simulés

LF5Appender - utiliser Tk ?
ExternallyRolledFileAppender - attraper un HUP à la place ?

Ceux-ci ne seront probablement pas implémentés

AsyncAppender
JMSAppender
SocketAppender - (envoie un LoggingEvent sérialisé au serveur)
SocketHubAppender

Créez votre propre

Disons que vous êtes dans un environnement mixte Java/Perl et que vous avez créé un appender Java personnalisé avec un comportement que vous voulez utiliser dans les deux mondes, "myorg.customAppender". Vous écrivez un appender Perl avec le même comportement "Myorg::CustomAppender". Vous voulez utiliser un seul fichier de configuration pour les deux applications, donc le fichier de configuration devra dire 'myorg.customAppender'. Mais la correspondance entre "myorg.customAppender" et "Myorg::CustomAppender" n'est pas dans cette classe JavaMap, alors que faites-vous ?

Dans votre code Perl, avant d'appeler Log::Log4perl::init(), faites ceci :

$Log::Log4perl::JavaMap::user_defined{'myorg.customAppender'} =
    'Myorg::CustomAppender';

et vous pouvez utiliser 'myorg.customAppender' dans votre fichier de configuration en toute impunité.
