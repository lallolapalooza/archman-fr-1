NOM

Log::Message - Un mécanisme générique de stockage de messages ;

SYNTAXE

use Log::Message private => 0, config => '/notre/fichier_de_config';
my $log = Log::Message->new(    private => 1,
                                level   => 'log',
                                config  => '/mon/fichier_de_config',
                           );
$log->store('ceci est mon premier message');
$log->store(    message => 'message #2',
                tag     => 'MON_TAG',
                level   => 'carp',
                extra   => ['ceci est un argument pour le gestionnaire'],
           );
my @derniers_cinq_elements = $log->retrieve(5);
my @elements = $log->retrieve( tag     => qr/mon_tag/i,
                            message => qr/\d/,
                            remove  => 1,
                          );
my @elements = $log->final( level => qr/carp/, amount => 2 );
my $premier_erreur = $log->first()
# croak avec la dernière erreur dans la pile
$log->final->croak;
# vider la pile
$log->flush();

DESCRIPTION

Log::Message est un mécanisme générique de stockage de messages. Il vous permet de stocker des messages dans une pile - qu'elle soit partagée ou privée - et d'y associer des métadonnées. Certaines métadonnées seront automatiquement ajoutées pour vous, comme un horodatage et une trace de pile, mais d'autres peuvent être remplies par l'utilisateur, comme une étiquette pour l'identifier ou le regrouper, et un niveau auquel le message sera traité (par exemple, l'enregistrer ou mourir avec lui).

Log::Message fournit également un moyen puissant de rechercher des éléments par expressions régulières sur les messages, les étiquettes et les niveaux.

Hiérarchie

Il y a 4 modules d'intérêt lorsque l'on traite des modules Log::Message::* :

Log::Message
Log::Message fournit quelques méthodes pour manipuler la pile qu'il conserve. Il a l'option de conserver une pile privée ou publique. Plus à ce sujet ci-dessous.
Log::Message::Item
Ce sont des éléments de message individuels, qui sont des objets contenant le message de l'utilisateur ainsi que les métadonnées décrites ci-dessus. Voir la page de manuel de Log::Message::Item pour savoir comment extraire ces métadonnées et comment travailler avec les objets Item. Vous ne devriez jamais avoir besoin de créer vos propres objets Item, mais connaître leurs méthodes et accesseurs est important si vous voulez écrire vos propres gestionnaires. (Voir ci-dessous)
Log::Message::Handlers
Ce sont une collection de gestionnaires qui seront appelés pour un niveau utilisé dans un objet Log::Message::Item. Par exemple, si un message est enregistré avec le niveau 'carp', le gestionnaire 'carp' de Log::Message::Handlers sera appelé. Voir la page de manuel de Log::Message::Handlers pour plus d'explications sur le fonctionnement des gestionnaires, ceux qui sont disponibles et comment créer les vôtres.
Log::Message::Config
Par objet Log::Message, une configuration est requise pour définir les valeurs par défaut si l'utilisateur n'a pas spécifié d'arguments pour les remplacer (par exemple, quelle étiquette sera définie si aucune n'a été fournie), Log::Message::Config gère la création de ces configurations.

La configuration peut être spécifiée de 4 manières :

  • Sous forme de fichier de configuration lorsque vous "use Log::Message"
  • Sous forme d'arguments lorsque vous "use Log::Message"
  • Sous forme de fichier de configuration lorsque vous créez un nouvel objet Log::Message. (La configuration ne s'appliquera alors qu'à cet objet si vous l'avez marqué comme privé)
  • Sous forme d'arguments lorsque vous créez un nouvel objet Log::Message.

    Vous ne devriez jamais avoir besoin d'utiliser vous-même le module Log::Message::Config, car cela est fait de manière transparente par Log::Message, mais sa page de manuel explique comment créer un fichier de configuration.

Options

Lors de l'utilisation de Log::Message, ou de la création d'un nouvel objet Log::Message, vous pouvez fournir diverses options pour modifier son comportement. Bien sûr, il existe des valeurs par défaut raisonnables si vous choisissez d'omettre ces options.

Ci-dessous une explication de toutes les options et de leur fonctionnement.

config
Le chemin vers un fichier de configuration à lire. Voir la page de manuel de Log::Message::Config pour le format requis.

Ces options seront remplacées par tous les arguments explicites fournis.

private
S'il faut créer, par défaut, des objets privés ou partagés. Si vous choisissez de créer des objets partagés, tous les objets Log::Message utiliseront la même pile.

Cela signifie que même si chaque module peut créer son propre objet $log, ils partageront toujours la même pile d'erreurs sur laquelle ils ajoutent les erreurs et d'où ils les récupèrent.

Cela peut être utile dans les grands projets.

Si vous choisissez de créer un objet privé, la pile sera bien sûr privée à cet objet, mais il se rabattra toujours sur la configuration partagée si aucune configuration privée ou aucun argument de remplacement n'est fourni.

verbose
Log::Message utilise un autre module pour valider ses arguments, appelé Params::Check, qui est un vérificateur et analyseur d'entrée léger mais puissant. (Voir la page de manuel de Params::Check pour plus de détails).

Le réglage verbose contrôlera si ce module générera des avertissements si quelque chose d'inapproprié est passé en entrée, ou se contentera de retourner silencieusement undef, auquel cas Log::Message générera un avertissement.

Il est préférable de laisser cela à sa valeur par défaut, qui est '1'.

tag
L'étiquette à ajouter aux messages si aucune n'a été fournie. Si ni votre configuration ni aucun argument spécifique ne fournissent une étiquette, Log::Message la définira sur 'NONE'.

Les étiquettes sont utiles pour la recherche ou le regroupement. Par exemple, vous pourriez étiqueter tous les messages que vous voulez envoyer à l'utilisateur comme 'ERREUR UTILISATEUR' et ceux qui ne sont que des informations de débogage comme 'DEBUG'.

À la fin de votre programme, vous pourriez alors imprimer ceux étiquetés 'ERREUR UTILISATEUR' sur STDOUT, et ceux marqués 'DEBUG' dans un fichier journal.

level
"level" décrit l'action à entreprendre lorsqu'un message est enregistré. Tout comme "tag", Log::Message fournira une valeur par défaut (qui est 'log') si votre fichier de configuration ni aucun argument explicite n'est donné pour la remplacer.

Voir la page de manuel de Log::Message::Handlers pour voir quels gestionnaires sont disponibles par défaut et ce qu'ils font, ainsi que pour savoir comment ajouter vos propres gestionnaires.

remove
Ceci indique s'il faut automatiquement supprimer les messages de la pile une fois que vous les avez récupérés ou non. Le paramètre par défaut fourni par Log::Message est '0' : ne pas supprimer.
chrono
Ceci indique si les messages doivent toujours être récupérés dans l'ordre chronologique ou non. Cela signifie simplement que vous pouvez choisir si, lors de la récupération des éléments, l'élément ajouté le plus récemment doit être renvoyé en premier, ou celui qui avait été ajouté il y a le plus longtemps.

La valeur par défaut est de renvoyer les plus récents en premier.

Méthodes

new

Ceci crée un nouvel objet Log::Message ; Les paramètres qu'il prend sont décrits dans la section "Options" ci-dessous et il suffit de le répéter que vous pouvez utiliser ces options comme ceci :

my $log = Log::Message->new( %options );

ainsi qu'au moment de "use", comme ceci :

use Log::Message option1 => valeur, option2 => valeur

Il y a seulement 3 règles à garder à l'esprit :

  • Les arguments fournis ont la priorité sur un fichier de configuration.
  • Les arguments de new ont la priorité sur les options fournies au moment de "use".
  • Un objet marqué comme privé aura toujours une pile vide

ack pour commencer avec

store

Ceci créera un nouvel objet Item et le stockera sur la pile.

Les arguments possibles sont :

message
C'est le seul argument requis. Si aucun autre argument n'est fourni, vous pouvez même omettre la clé "message". L'argument sera alors automatiquement supposé être le message.
tag
Le tag à ajouter à ce message. S'il n'est pas fourni, Log::Message le cherchera dans votre configuration.
level
Le niveau auquel ce message doit être traité. S'il n'est pas fourni, Log::Message le cherchera dans votre configuration.
extra
C'est une référence à un tableau avec les arguments passés au gestionnaire pour ce message, lorsqu'il est appelé par store() ;

Le gestionnaire les recevra comme une liste normale.

store() retournera vrai en cas de succès et undef en cas d'échec, et émettra également un avertissement expliquant pourquoi cela a échoué.

retrieve

Ceci récupérera tous les éléments de message correspondant aux critères spécifiés à partir de la pile.

Voici les critères sur lesquels vous pouvez discriminer :

tag
Une regex à laquelle le tag doit adhérer. Par exemple "qr/\w/".
level
Une regex à laquelle le niveau doit adhérer.
message
Une regex à laquelle le message doit adhérer.
amount
Quantité maximale d'erreurs à retourner.
chrono
Retourner dans l'ordre chronologique, ou non ?
remove
Supprimer les éléments de la pile lors de la récupération ?

En contexte scalaire, il retournera le premier élément correspondant à vos critères et en contexte de liste, il les retournera tous.

Si une erreur survient lors de la récupération, un avertissement sera émis et undef sera retourné.

first

Ceci est un raccourci pour récupérer le(s) premier(s) élément(s) stocké(s) sur la pile. Il ne récupérera par défaut qu'un seul élément s'il est appelé sans arguments, et retournera toujours les résultats dans l'ordre chronologique.

Si vous ne fournissez qu'un seul argument, il est supposé être la quantité que vous souhaitez retourner.

De plus, il peut prendre les mêmes arguments que "retrieve".

last

Ceci est un raccourci pour récupérer le(s) dernier(s) élément(s) stocké(s) sur la pile. Il ne récupérera par défaut qu'un seul élément s'il est appelé sans arguments, et retournera toujours les résultats dans l'ordre chronologique inversé.

Si vous ne fournissez qu'un seul argument, il est supposé être la quantité que vous souhaitez retourner.

De plus, il peut prendre les mêmes arguments que "retrieve".

flush

Ceci supprime tous les éléments de la pile et les retourne à l'appelant.
