NOM

DJabberd::Component - Classe abstraite représentant un composant dans DJabberd

SYNOPSIS

package MonPaquet::DJabberd::MonComposant;
use base DJabberd::Component;

# Exemple de composant qui accepte les XEP-0050 Ad-Hoc Commands

sub finalize {
    my ($self, $opts) = @_;

    # Laissons la classe parente finaliser
    $self->SUPER::finalize;

    $self->register_iq_handler(
        "set-{http://jabber.org/protocol/commands}command",
        sub { $self->handle_adhoc_command(@_) },
    );
}

sub handle_adhoc_command {
    my ($self, $vhost, $stanza) = @_;

    # gérez la strophe DJabberd::IQ dans $stanza,
    # ou envoyez une sorte de réponse d'erreur.
}

Cette classe fournit une classe parente pour tous les composants DJabberd. Les composants qui héritent de cette classe peuvent alors être utilisés directement par le serveur comme plugins de livraison, ou utilisés directement par d'autres classes.

Voir DJabberd::Component::Example pour un exemple d'implémentation de composant.

UTILISATION

Cette classe est une spécialisation de DJabberd::Agent qui s'adresse à ceux qui souhaitent créer des "composants", qui sont des agents logiciels gérant un domaine XMPP entier, y compris tous les nœuds de ce domaine.

Dans la plupart des cas, les utilisateurs de cette classe utiliseront l'API exposée par DJabberd::Agent. Cependant, il y a des comportements spéciaux à noter et des méthodes supplémentaires qui ne font pas partie de la classe agent de base.

handles_destination($self, $to_jid, $vhost)

Cette classe fournit une version surchargée de cette méthode qui répond par une valeur vraie si et seulement si le domaine du JID donné correspond au domaine du composant lui-même. Il est peu probable que vous ayez besoin de surcharger ceci.

handle_stanza($self, $vhost, $stanza)

La version surchargée de cette méthode a un comportement spécial lors de la gestion des strophes adressées aux nœuds du domaine géré par votre composant. (C'est-à-dire, des JID de la forme "utilisateur@exemple.com", plutôt que juste "exemple.com".)

Lorsqu'une telle strophe est reçue, la méthode "get_node" sera appelée pour récupérer un objet représentant ce nœud.

Si vous souhaitez gérer de bas niveau toutes les strophes entrantes, vous pouvez surcharger cette méthode. Comme avec DJabberd::Agent, surcharger cette méthode désactivera toutes les méthodes de gestion de plus haut niveau à moins que vous ne déléguiez à la méthode surchargée.

Si vous souhaitez conserver les méthodes de gestion de plus haut niveau mais ne pas gérer les nœuds comme des objets distincts, vous pourriez vouloir surcharger cette méthode pour appeler la version originale de DJabberd::Agent comme suit :

sub handle_stanza {
    $self->DJabberd::Agent::handle_stanza(@_);
}

Avec cette méthode en place, la méthode "get_node" ne sera plus utilisée et toutes les strophes appropriées seront transmises aux méthodes de gestion de cette instance, quel que soit le nom du nœud du JID de destination.

get_node($self, $nodename)

Appelé lorsque cette classe souhaite trouver un agent pour gérer un nœud donné dans le domaine de ce composant.

La plupart des implémentations normales de cette méthode retourneront une instance d'une sous-classe de DJabberd::Agent::Node, mais en réalité, toute sous-classe de DJabberd::Agent fera l'affaire tant qu'elle acceptera les strophes adressées au nom de nœud donné.

vcard($self)

La version surchargée de cette méthode retournera une vCard où le nom complet est défini sur le nom de domaine du composant. Les sous-classes peuvent surcharger ceci pour faire quelque chose de plus sophistiqué.

identities($self)

La version surchargée de cette méthode retourne une identité unique et générique qui indique que le composant est une "branche" dans l'arbre de découverte de services. Ceci est inclus car certains clients semblent s'énerver un peu si un JID prend en charge la découverte mais n'a pas d'identités.
