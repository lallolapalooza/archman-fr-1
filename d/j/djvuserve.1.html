Le serveur web Apache fournit un moyen d'exécuter automatiquement djvuserve pour tous les documents DjVu. Cela peut être réalisé en utilisant les directives suivantes dans le fichier de configuration Apache ou les fichiers .hta

Fournir l'URL d'un fichier DjVu sert ce fichier DjVu comme d'habitude, sauf que les documents multipages groupés sont convertis en documents indirects à la volée. CONTRÔLE

D'ACCÈS

Programme djvuserve, comme beaucoup de programmes CGI, contourne un certain nombre de protections d'accès établies dans un serveur web. Supposons par exemple que votre site web contienne des fichiers DjVu protégés par un mot de passe. Le programme djvuserve ne connaît rien de cette protection et servira volontiers n'importe quel fichier DjVu associé à une URL

valide.

Le contrôle d'accès avec djvuserve peut être mis en œuvre en se rappelant d'abord que le serveur web exécute toujours le programme djvuserve via le script shell /var/www/cgi–bin/djvuserve

.

Ce script peut décider d'exécuter le vrai programme djvuserve sur la base du nom de fichier cible disponible dans la variable d'environnement PATH_TRANSLATED

.

Il peut y avoir plusieurs scripts de ce type fournissant l'accès à diverses coll

ections de fichiers DjVu. Chacun de ces scripts peut être protégé par un mot de pas
se en utilisant les méthodes habituelles prises en charge par votre serveur web.

BOGUES

CONNUS

Les hyperliens spécifiés en utilisant une URL relative peuvent ne pas fonctionner avec djvuserve. Ces URL sont relatives à l'URL du document DjVu. Pourtant djvuserve change l'URL apparente du document URL http://serveur/dir/doc.djvu en l'URL plus compliquée URL http://serveur/cgi–bin/djvuserve/dir/doc.djvu/index.djvu. Les composants supplémentaires changent l'interprétation des URL r

elat
ives.
