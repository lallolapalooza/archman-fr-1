DGEDMDQ calcule la Décomposition en Modes Dynamiques (DMD) pour une paire de matrices d'instantanés de données.

But :

!>     DGEDMDQ calcule la Décomposition en Modes Dynamiques (DMD) pour
!>     une paire de matrices d'instantanés de données, en utilisant une
!>     compression des données basée sur une factorisation QR. Pour les
!>     matrices d'entrée X et Y telles que Y = A*X avec une matrice A
!>     inaccessible, DGEDMDQ calcule un certain nombre de paires de Ritz
!>     de A en utilisant l'extraction standard de Rayleigh-Ritz à partir
!>     d'un sous-espace de range(X) qui est déterminé à l'aide des
!>     vecteurs singuliers gauches principaux de X. En option, DGEDMDQ
!>     retourne les résidus des paires de Ritz calculées, les informations
!>     nécessaires pour un raffinement des vecteurs de Ritz, ou les
!>     vecteurs propres du DMD Exact.
!>     Pour plus de détails, voir les références listées ci-dessous.
!>     Pour plus de détails sur l'implémentation, voir [3].
!>

Références :

!>        decompositions: analysis and enhancements,

Paramètres

JOBS 
!>    JOBS (entrée) CHARACTER*1
!>    Détermine si les instantanés de données initiaux sont mis à l'échelle
!>    par une matrice diagonale. Les instantanés de données sont les colonnes
!>    de F. Les N-1 premières colonnes de F sont notées X et les
!>    N-1 dernières colonnes sont notées Y.
!>    'S' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D de sorte que X*D ait des colonnes
!>           non nulles de norme unitaire (dans la 2-norme euclidienne)
!>    'C' :: Les instantanés sont mis à l'échelle comme avec l'option 'S'.
!>           S'il est constaté que la i-ème colonne de X est un vecteur nul
!>           et que la i-ème colonne correspondante de Y est non nulle,
!>           alors la i-ème colonne de Y est mise à zéro et un drapeau
!>           d'avertissement est levé.
!>    'Y' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D de sorte que Y*D ait des colonnes
!>           non nulles de norme unitaire (dans la 2-norme euclidienne)
!>    'N' :: Pas de mise à l'échelle des données.
!>

JOBZ

!>    JOBZ (entrée) CHARACTER*1
!>    Détermine si les vecteurs propres (modes de Koopman) seront
!>    calculés.
!>    'V' :: Les vecteurs propres (modes de Koopman) seront calculés
!>           et retournés dans la matrice Z.
!>           Voir la description de Z.
!>    'F' :: Les vecteurs propres (modes de Koopman) seront retournés
!>           sous forme factorisée comme le produit Z*V, où Z
!>           est orthonormale et V contient les vecteurs propres
!>           du quotient de Rayleigh correspondant.
!>           Voir les descriptions de F, V, Z.
!>    'Q' :: Les vecteurs propres (modes de Koopman) seront retournés
!>           sous forme factorisée comme le produit Q*Z, où Z
!>           contient les vecteurs propres de la compression de
!>           l'opérateur discretisé sous-jacent sur l'enveloppe des
!>           instantanés de données. Voir les descriptions de F, V, Z.
!>           Q provient de la factorisation QR initiale.
!>    'N' :: Les vecteurs propres ne sont pas calculés.
!>

JOBR

!>    JOBR (entrée) CHARACTER*1
!>    Détermine s'il faut calculer les résidus.
!>    'R' :: Les résidus des paires de valeurs propres calculées seront
!>           calculés et stockés dans le tableau RES.
!>           Voir la description de RES.
!>           Pour que cette option soit valide, JOBZ doit être 'V'.
!>    'N' :: Les résidus ne sont pas calculés.
!>

JOBQ_

!>    JOBQ (entrée) CHARACTER*1
!>    Spécifie s'il faut calculer et retourner explicitement la
!>    matrice orthogonale de la factorisation QR.
!>    'Q' :: La matrice Q de la factorisation QR de la matrice
!>           des snapshots de données est calculée et stockée
!>           dans le tableau F. Voir la description de F.
!>    'N' :: La matrice Q n'est pas explicitement calculée.
!>

JOBT

!>    JOBT (entrée) CHARACTER*1
!>    Spécifie s'il faut retourner le facteur triangulaire supérieur
!>    de la factorisation QR.
!>    'R' :: La matrice R de la factorisation QR de la matrice
!>           des snapshots de données F est retournée dans le
!>           tableau Y. Voir la description de Y et Détails supplémentaires.
!>    'N' :: La matrice R n'est pas retournée.
!>

JOBF

!>    JOBF (entrée) CHARACTER*1
!>    Spécifie s'il faut stocker les informations nécessaires au
!>    post-traitement (par exemple, le calcul des vecteurs de Ritz affinés).
!>    'R' :: La matrice nécessaire à l'affinage des vecteurs de Ritz
!>           est calculée et stockée dans le tableau B. Voir la
!>           description de B.
!>    'E' :: Les vecteurs propres non normalisés du DMD exact sont
!>           calculés et retournés dans le tableau B. Voir la
!>           description de B.
!>    'N' :: Aucune donnée d'affinage de vecteurs propres n'est calculée.
!>    Pour être utile en sortie, cette option nécessite JOBQ='Q'.
!>

WHTSVD

!>    WHTSVD (entrée) INTEGER, WHSTVD dans { 1, 2, 3, 4 }
!>    Permet de sélectionner l'algorithme SVD de la bibliothèque
!>    LAPACK.
!>    1 :: DGESVD (l'algorithme QR SVD)
!>    2 :: DGESDD (l'algorithme Divide and Conquer; s'il y a assez
!>         d'espace de travail, c'est l'option la plus rapide)
!>    3 :: DGESVDQ (le QR SVD préconditionné; ceci et 4 sont les
!>         options les plus précises)
!>    4 :: DGEJSV (le Jacobi SVD préconditionné; ceci et 3 sont les
!>         options les plus précises)
!>    Pour les quatre méthodes ci-dessus, une différence significative
!>    dans la précision des petites valeurs singulières est possible si
!>    les snapshots varient en norme de telle sorte que X soit sévèrement
!>    mal conditionné. Si des petites valeurs singulières (inférieures à EPS*||X||)
!>    sont d'intérêt et JOBS=='N', alors les options (3, 4) donnent les résultats les
!>    plus précis, où l'option 4 est légèrement meilleure et avec un fondement
!>    théorique plus solide.
!>    Si JOBS=='S', c'est-à-dire si les colonnes de X seront normalisées,
!>    alors toutes les méthodes donnent des résultats presque également précis.
!>

M

!>    M (entrée) INTEGER, M >= 0
!>    La dimension de l'espace d'états (le nombre de lignes de F).
!>

N

!>    N (entrée) INTEGER, 0 <= N <= M
!>    Le nombre de snapshots de données d'une seule trajectoire,
!>    pris à des instants discrets équidistants. C'est le
!>    nombre de colonnes de F.
!>

F

!>    F (entrée/sortie) REAL(KIND=WP) tableau M x N
!>    > À l'entrée,
!>    les colonnes de F sont la séquence des snapshots de données
!>    d'une seule trajectoire, pris à des instants discrets
!>    équidistants. Il est supposé que les normes des colonnes de F
!>    sont dans la plage des nombres flottants normalisés.
!>    < À la sortie,
!>    Si JOBQ == 'Q', le tableau F contient la matrice orthogonale
!>    ou le facteur de la factorisation QR des snapshots de données
!>    initiaux de la matrice F. Voir la description de JOBQ.
!>    Si JOBQ == 'N', les entrées dans F strictement sous la
!>    diagonale principale contiennent, colonne par colonne, les
!>    informations sur les vecteurs de Householder, tels que retournés
!>    par DGEQRF. Les informations restantes pour restaurer la matrice
!>    orthogonale de la factorisation QR initiale sont stockées dans
!>    WORK(1:N). Voir la description de WORK.
!>

LDF

!>    LDF (entrée) INTEGER, LDF >= M
!>    La dimension principale du tableau F.
!>

X

!>    X (espace de travail/sortie) REAL(KIND=WP) tableau MIN(M,N) x (N-1)
!>    X est utilisé comme espace de travail pour contenir des
!>    représentations des N-1 snapshots principaux dans la base
!>    orthonormale calculée dans la factorisation QR de F.
!>    À la sortie, les colonnes principales K de X contiennent les
!>    K premières colonnes des vecteurs singuliers gauches du contenu
!>    de X décrit ci-dessus. Pour les porter dans l'espace des vecteurs
!>    singuliers gauches U(:,1:K) des données d'entrée, multiplier par
!>    pré-multiplication avec le facteur Q de la factorisation QR initiale.
!>    Voir les descriptions de F, K, V et Z.
!>

LDX

!>    LDX (entrée) INTEGER, LDX >= N
!>    La dimension principale du tableau X.
!>

Y

!>    Y (espace de travail/sortie) REAL(KIND=WP) tableau MIN(M,N) x (N-1)
!>    Y est utilisé comme espace de travail pour contenir des
!>    représentations des N-1 snapshots finaux dans la base
!>    orthonormale calculée dans la factorisation QR de F.
!>    À la sortie,
!>    Si JOBT == 'R', Y contient le facteur triangulaire supérieur
!>    MIN(M,N) x N de la factorisation QR de la matrice des snapshots
!>    de données F.
!>

LDY

!>    LDY (entrée) INTEGER , LDY >= N
!>    La dimension principale du tableau Y.
!>

NRNK

!>    NRNK (entrée) INTEGER
!>    Détermine le mode de calcul du rang numérique, c'est-à-dire
!>    comment tronquer les petites valeurs singulières de la matrice
!>    d'entrée X. À l'entrée, si
!>    NRNK = -1 :: la i-ème valeur singulière sigma(i) est tronquée
!>                 si sigma(i) <= TOL*sigma(1)
!>                 Cette option est recommandée.
!>    NRNK = -2 :: la i-ème valeur singulière sigma(i) est tronquée
!>                 si sigma(i) <= TOL*sigma(i-1)
!>                 Cette option est incluse à des fins de R&D.
!>                 Elle nécessite une SVD de haute précision, ce qui
!>                 peut ne pas être réalisable.
!>    Le rang numérique peut être imposé en utilisant une valeur positive
!>    de NRNK comme suit :
!>    0 < NRNK <= N-1 :: au plus NRNK plus grandes valeurs singulières
!>    seront utilisées. Si le nombre de valeurs singulières non nulles calculées
!>    est inférieur à NRNK, alors seules ces valeurs non nulles seront
!>    utilisées et la dimension réellement utilisée sera inférieure à NRNK.
!>    Le nombre réel de valeurs singulières non nulles est retourné dans la
!>    variable K. Voir la description de K.
!>

TOL

!>     TOL (entrée) REAL(KIND=WP), 0 <= TOL < 1
!>     La tolérance pour tronquer les petites valeurs singulières.
!>     Voir la description de NRNK.
!>

K

!>     K (sortie) INTEGER,  0 <= K <= N
!>     La dimension de la base SVD/POD pour les N-1 premiers
!>     snapshots de données (colonnes de F) et le nombre de paires de
!>     Ritz calculées. La valeur de K est déterminée selon la règle
!>     définie par les paramètres NRNK et TOL. Voir les descriptions
!>     de NRNK et TOL.
!>

REIG

!>    REIG (sortie) REAL(KIND=WP) tableau (N-1)x1
!>    Les K premières entrées (K<=N) de REIG contiennent
!>    les parties réelles des valeurs propres calculées
!>    REIG(1:K) + sqrt(-1)*IMEIG(1:K).
!>    Voir les descriptions de K, IMEIG, Z.
!>

IMEIG

!>    IMEIG (sortie) REAL(KIND=WP) tableau (N-1)x1
!>    Les K premières entrées (K<N) de REIG contiennent
!>    les parties imaginaires des valeurs propres calculées
!>    REIG(1:K) + sqrt(-1)*IMEIG(1:K).
!>    Les valeurs propres sont déterminées comme suit :
!>    Si IMEIG(i) == 0, alors la valeur propre correspondante est
!>    réelle, LAMBDA(i) = REIG(i).
!>    Si IMEIG(i)>0, alors la paire de valeurs propres conjuguées
!>    complexes correspondante se lit
!>    LAMBDA(i)   = REIG(i) + sqrt(-1)*IMAG(i)
!>    LAMBDA(i+1) = REIG(i) - sqrt(-1)*IMAG(i)
!>    C'est-à-dire que les paires conjuguées complexes ont des indices
!>    consécutifs (i,i+1), avec la partie imaginaire positive listée
!>    en premier.
!>    Voir les descriptions de K, REIG, Z.
!>

Z

!>    Z (espace de travail/sortie) REAL(KIND=WP)  tableau M x (N-1)
!>    Si JOBZ =='V' alors
!>       Z contient des vecteurs de Ritz réels comme suit :
!>       Si IMEIG(i)=0, alors Z(:,i) est un vecteur propre de
!>       la i-ème valeur de Ritz.
!>       Si IMEIG(i) > 0 (et IMEIG(i+1) < 0) alors
!>       [Z(:,i) Z(:,i+1)] engendrent un sous-espace invariant et
!>       les valeurs de Ritz extraites de ce sous-espace sont
!>       REIG(i) + sqrt(-1)*IMEIG(i) et
!>       REIG(i) - sqrt(-1)*IMEIG(i).
!>       Les vecteurs propres correspondants sont
!>       Z(:,i) + sqrt(-1)*Z(:,i+1) et
!>       Z(:,i) - sqrt(-1)*Z(:,i+1), respectivement.
!>    Si JOBZ == 'F', alors les descriptions ci-dessus s'appliquent
!>    aux colonnes de Z*V, où les colonnes de V sont les
!>    vecteurs propres du quotient de Rayleigh KxK, et Z est
!>    orthonormale. Les colonnes de V sont structurées de manière
!>    similaire :
!>    Si IMEIG(i) == 0 alors Z*V(:,i) est un vecteur propre, et si
!>    IMEIG(i) > 0 alors Z*V(:,i)+sqrt(-1)*Z*V(:,i+1) et
!>                      Z*V(:,i)-sqrt(-1)*Z*V(:,i+1)
!>    sont les vecteurs propres de LAMBDA(i), LAMBDA(i+1).
!>    Voir les descriptions de REIG, IMEIG, X et V.
!>

LDZ

!>    LDZ (entrée) INTEGER , LDZ >= M
!>    La dimension principale du tableau Z.
!>

RES

!>    RES (sortie) REAL(KIND=WP) tableau (N-1)x1
!>    RES(1:K) contient les résidus pour les K paires de Ritz calculées.
!>    Si LAMBDA(i) est réelle, alors
!>       RES(i) = || A * Z(:,i) - LAMBDA(i)*Z(:,i))||_2.
!>    Si [LAMBDA(i), LAMBDA(i+1)] est une paire conjuguée complexe
!>    alors
!>    RES(i)=RES(i+1) = || A * Z(:,i:i+1) - Z(:,i:i+1) *B||_F
!>    où B = [ real(LAMBDA(i)) imag(LAMBDA(i)) ]
!>              [-imag(LAMBDA(i)) real(LAMBDA(i)) ].
!>    Il est vrai que
!>    RES(i)   = || A*ZC(:,i)   - LAMBDA(i)  *ZC(:,i)   ||_2
!>    RES(i+1) = || A*ZC(:,i+1) - LAMBDA(i+1)*ZC(:,i+1) ||_2
!>    où ZC(:,i)   =  Z(:,i) + sqrt(-1)*Z(:,i+1)
!>          ZC(:,i+1) =  Z(:,i) - sqrt(-1)*Z(:,i+1)
!>    Voir la description de Z.
!>

B

!>    B (sortie) REAL(KIND=WP)  tableau MIN(M,N) x (N-1).
!>    SI JOBF =='R', B(1:N,1:K) contient A*U(:,1:K), et peut
!>    être utilisé pour calculer les vecteurs affinés ; voir les
!>    détails supplémentaires dans les références fournies.
!>    Si JOBF == 'E', B(1:N,1;K) contient
!>    A*U(:,1:K)*W(1:K,1:K), qui sont les vecteurs du DMD exact,
!>    jusqu'à l'échelle par l'inverse des valeurs propres.
!>    Dans les deux cas, le contenu de B peut être porté à la
!>    dimension d'origine des données d'entrée en pré-multipliant
!>    avec le facteur Q de la factorisation QR initiale.
!>    Ici, A désigne une compression de l'opérateur sous-jacent.
!>    Voir les descriptions de F et X.
!>    Si JOBF =='N', alors B n'est pas référencé.
!>

LDB

!>    LDB (entrée) INTEGER, LDB >= MIN(M,N)
!>    La dimension principale du tableau B.
!>

V

!>    V (espace de travail/sortie) REAL(KIND=WP) tableau (N-1) x (N-1)
!>    À la sortie, V(1:K,1:K) contient les K vecteurs propres
!>    du quotient de Rayleigh. Les vecteurs propres d'une paire
!>    conjuguée complexe de valeurs propres sont retournés sous
!>    forme réelle comme expliqué dans la description de Z. Les
!>    vecteurs de Ritz (retournés dans Z) sont le produit de X et V ;
!>    voir les descriptions de X et Z.
!>

LDV

!>    LDV (entrée) INTEGER, LDV >= N-1
!>    La dimension principale du tableau V.
!>

S

!>    S (sortie) REAL(KIND=WP) tableau (N-1)-par-(N-1)
!>    Le tableau S(1:K,1:K) est utilisé pour le quotient de
!>    Rayleigh de la matrice. Ce contenu est écrasé pendant
!>    la décomposition en valeurs propres par DGEEV.
!>    Voir la description de K.
!>

LDS

!>    LDS (entrée) INTEGER, LDS >= N-1
!>    La dimension principale du tableau S.
!>

WORK

!>    WORK (espace de travail/sortie) REAL(KIND=WP) tableau LWORK-par-1
!>    À la sortie,
!>    WORK(1:MIN(M,N)) contient les facteurs scalaires des
!>    réflecteurs élémentaires tels que renvoyés par DGEQRF de la
!>    matrice d'entrée F de dimensions M-par-N.
!>    WORK(MIN(M,N)+1:MIN(M,N)+N-1) contient les valeurs singulières de
!>    la sous-matrice d'entrée F(1:M,1:N-1).
!>    Si l'appel à DGEDMDQ n'est qu'une interrogation d'espace de travail, alors
!>    WORK(1) contient la longueur minimale d'espace de travail et
!>    WORK(2) est la longueur optimale d'espace de travail. Par conséquent, la
!>    longueur de work est au moins 2.
!>    Voir la description de LWORK.
!>

LWORK

!>    LWORK (entrée) INTEGER
!>    La longueur minimale du vecteur d'espace de travail WORK.
!>    LWORK est calculé comme suit :
!>    Soit MLWQR  = N (espace de travail minimal pour DGEQRF[M,N])
!>        MLWDMD = espace de travail minimal pour DGEDMD (voir la
!>                 description de LWORK dans DGEDMD) pour
!>                 des instantanés de dimensions MIN(M,N)-par-(N-1)
!>        MLWMQR = N (espace de travail minimal pour
!>                   DORMQR['L','N',M,N,N])
!>        MLWGQR = N (espace de travail minimal pour DORGQR[M,N,N])
!>    Alors
!>    LWORK = MAX(N+MLWQR, N+MLWDMD)
!>    est mis à jour comme suit :
!>       si   JOBZ == 'V' ou JOBZ == 'F' ALORS
!>            LWORK = MAX( LWORK, MIN(M,N)+N-1+MLWMQR )
!>       si   JOBQ == 'Q' ALORS
!>            LWORK = MAX( LWORK, MIN(M,N)+N-1+MLWGQR)
!>    Si à l'entrée LWORK = -1, alors une interrogation d'espace de travail est
!>    supposée et la procédure ne calcule que les longueurs
!>    minimales et optimales d'espace de travail pour WORK et
!>    IWORK. Voir les descriptions de WORK et IWORK.
!>

IWORK

!>    IWORK (espace de travail/sortie) INTEGER tableau LIWORK-par-1
!>    Espace de travail qui est requis uniquement si WHTSVD vaut
!>    2 , 3 ou 4. (Voir la description de WHTSVD).
!>    Si à l'entrée LWORK =-1 ou LIWORK=-1, alors la
