Documentation de la fonction/sous-programme

sous-programme dggglm (entier n, entier m, entier p, double précision, dimension( lda, * ) a, entier lda, double précision, dimension( ldb, * ) b, entier ldb, double précision, dimension( * ) d, double précision, dimension( * ) x, double précision, dimension( * ) y, double précision, dimension( * ) work, entier lwork, entier info)

DGGGLM

Objectif:

!>
!> DGGGLM résout un problème de modèle linéaire Gauss-Markov général (GLM) :
!>
!>         minimiser || y ||_2   sous contrainte   d = A*x + B*y
!>             x
!>
!> où A est une matrice N x M, B est une matrice N x P, et d est un
!> vecteur N donné. On suppose que M <= N <= M+P, et
!>
!>            rang(A) = M    et    rang( A B ) = N.
!>
!> Sous ces hypothèses, l'équation contrainte est toujours
!> cohérente, et il existe une solution unique x et une solution y
!> de norme 2 minimale, qui est obtenue en utilisant une factorisation QR
!> généralisée des matrices (A, B) donnée par
!>
!>    A = Q*(R),   B = Q*T*Z.
!>          (0)
!>
!> En particulier, si la matrice B est carrée et inversible, alors le problème
!!> GLM est équivalent au problème des moindres carrés linéaires pondérés suivant
!>
!>              minimiser || inv(B)*(d-A*x) ||_2
!>                  x
!>
!> où inv(B) dénote l'inverse de B.
!>
!> Les appelants de ce sous-programme doivent noter que les vérifications de singularité/dégénérescence
!> mises en œuvre dans ce sous-programme sont rudimentaires. Le sous-programme DTRTRS appelé par ce
!> sous-programme ne signale un échec dû à une singularité que si le problème est exactement singulier.
!>
!> Il est concevable que l'un (ou plusieurs) des facteurs impliqués dans la factorisation QR
!> généralisée de la paire (A, B) soit subnormalement proche de la singularité sans que ce
!> sous-programme ne signale d'erreur. Les solutions calculées pour de tels problèmes presque dégénérés
!> peuvent être moins précises en raison d'une perte de précision numérique.
!> 
!>

Paramètres

N 
!>          N est ENTIER
!>          Le nombre de lignes des matrices A et B.  N >= 0.
!>

M

!>          M est ENTIER
!>          Le nombre de colonnes de la matrice A.  0 <= M <= N.
!>

P

!>          P est ENTIER
!>          Le nombre de colonnes de la matrice B.  P >= N-M.
!>

A

!>          A est un tableau DOUBLE PRECISION, de dimension (LDA,M)
!>          En entrée, la matrice N x M A.
!>          En sortie, la partie triangulaire supérieure du tableau A contient
!>          la matrice triangulaire supérieure M x M R.
!>

LDA

!>          LDA est ENTIER
!>          La dimension principale du tableau A. LDA >= max(1,N).
!>

B

!>          B est un tableau DOUBLE PRECISION, de dimension (LDB,P)
!>          En entrée, la matrice N x P B.
!>          En sortie, si N <= P, le triangle supérieur de la sous-matrice
!>          B(1:N,P-N+1:P) contient la matrice triangulaire supérieure N x N T ;
!>          si N > P, les éléments sur et au-dessus de la (N-P)-ième sous-diagonale
!>          contiennent la matrice trapézoïdale supérieure N x P T.
!>

LDB

!>          LDB est ENTIER
!>          La dimension principale du tableau B. LDB >= max(1,N).
!>

D

!>          D est un tableau DOUBLE PRECISION, de dimension (N)
!>          En entrée, D est le membre de gauche de l'équation GLM.
!>          En sortie, D est détruit.
!>

X

!>          X est un tableau DOUBLE PRECISION, de dimension (M)
!>

Y

!>          Y est un tableau DOUBLE PRECISION, de dimension (P)
!>
!>          En sortie, X et Y sont les solutions du problème GLM.
!>

WORK

!>          WORK est un tableau DOUBLE PRECISION, de dimension (MAX(1,LWORK))
!>          En sortie, si INFO = 0, WORK(1) contient la valeur optimale de LWORK.
!>

LWORK

!>          LWORK est ENTIER
!>          La dimension du tableau WORK. LWORK >= max(1,N+M+P).
!>          Pour une performance optimale, LWORK >= M+min(N,P)+max(N,P)*NB,
!>          où NB est une borne supérieure pour les tailles de bloc optimales pour
!>          DGEQRF, SGERQF, DORMQR et SORMRQ.
!>
!>          Si LWORK = -1, alors une requête d'espace de travail est supposée ; le sous-programme
!>          calcule uniquement la taille optimale du tableau WORK, renvoie
!>          cette valeur dans la première entrée du tableau WORK, et aucun message d'erreur
!>          lié à LWORK n'est émis par XERBLA.
!>

INFO

!>          INFO est ENTIER
!>          = 0 :  sortie réussie.
!>          < 0 :  si INFO = -i, le i-ème argument avait une valeur illégale.
!>          = 1 :  le facteur triangulaire supérieur R associé à A dans la
!>                factorisation QR généralisée de la paire (A, B) est exactement
!>                singulier, de sorte que rang(A) < M ; la solution des moindres
!>                carrés n'a pas pu être calculée.
!>          = 2 :  la partie inférieure (N-M) x (N-M) du facteur trapézoïdal supérieur
!>                T associé à B dans la factorisation QR généralisée
!>                de la paire (A, B) est exactement singulière, de sorte que
!!>                rang( A B ) < N ; la solution des moindres carrés n'a pas pu
!>                être calculée.
!>
