DGEJSV

Documentation de fonction/sous-programme

sous-programme dgejsv (character*1 joba, character*1 jobu, character*1 jobv, character*1 jobr, character*1 jobt, character*1 jobp, integer m, integer n, double precision, dimension( lda, * ) a, integer lda, double precision, dimension( n ) sva, double precision, dimension( ldu, * ) u, integer ldu, double precision, dimension( ldv, * ) v, integer ldv, double precision, dimension( lwork ) work, integer lwork, integer, dimension( * ) iwork, integer info)

DGEJSV

Objectif :

!>
!> DGEJSV calcule la décomposition en valeurs singulières (SVD) d'une matrice réelle M par N
!> [A], où M >= N. La SVD de [A] est écrite comme suit :
!>
!>              [A] = [U] * [SIGMA] * [V]^t,
!>
!> où [SIGMA] est une matrice N par N (M par N) nulle sauf ses N éléments diagonaux,
!> [U] est une matrice orthonormée M par N (ou M par M), et
!> [V] est une matrice orthogonale N par N. Les éléments diagonaux de [SIGMA] sont
!> les valeurs singulières de [A]. Les colonnes de [U] et [V] sont les vecteurs singuliers gauches et
!> droits de [A], respectivement. Les matrices [U] et [V]
!> sont calculées et stockées dans les tableaux U et V, respectivement. La diagonale
!> de [SIGMA] est calculée et stockée dans le tableau SVA.
!> DGEJSV peut parfois calculer des valeurs singulières minuscules et leurs vecteurs singuliers beaucoup
!> plus précisément que d'autres routines SVD, voir ci-dessous dans Détails supplémentaires.
!>

Paramètres

JOBA 
!>          JOBA est CHARACTER*1
!>        Spécifie le niveau de précision :
!>       = 'C' : Cette option fonctionne bien (haute précision relative) si A = B * D,
!>             avec B bien conditionnée et D une matrice diagonale arbitraire.
!>             La précision ne peut pas être gâchée par une mise à l'échelle des COLONNES. La
!>             précision de la sortie calculée dépend de la condition de
!>             B, et la procédure vise la meilleure précision théorique.
!>             L'erreur relative max_{i=1:N}|d sigma_i| / sigma_i est
!>             bornée par f(M,N)*epsilon* cond(B), indépendamment de D.
!>             La matrice d'entrée est prétraitée avec la décomposition QR avec pivotement de
!>             COLONNE. Ce prétraitement initial et ce préconditionnement par
!>             une factorisation QR révélatrice de rang sont communs à toutes les valeurs de
!>             JOBA. Les actions supplémentaires sont spécifiées comme suit :
!>       = 'E' : Calcul comme avec 'C' avec une estimation supplémentaire du
!>             nombre de condition de B. Elle fournit une borne d'erreur réaliste.
!>       = 'F' : Si A = D1 * C * D2 avec des mises à l'échelle diagonales mal conditionnées
!>             D1, D2, et une matrice C bien conditionnée, cette option donne
!>             une précision plus élevée que l'option 'C'. Si la structure de la
!>             matrice d'entrée n'est pas connue, et que la précision relative
!>             est souhaitée, alors cette option est conseillée. La matrice d'entrée A
!>             est prétraitée avec une factorisation QR avec pivotement COMPLET (ligne et
!>             colonne).
!>       = 'G' : Calcul comme avec 'F' avec une estimation supplémentaire du
!>             nombre de condition de B, où A=D*B. Si A a des lignes fortement pondérées,
!>             alors l'utilisation de ce nombre de condition donne une borne d'erreur trop pessimiste.
!>       = 'A' : Les valeurs singulières petites sont le bruit et la matrice est traitée
!>             comme numériquement de rang déficient. L'erreur dans les valeurs
!>             singulières calculées est bornée par f(m,n)*epsilon*||A||.
!>             La SVD calculée A = U * S * V^t restaure A jusqu'à
!>             f(m,n)*epsilon*||A||.
!>             Cela donne à la procédure la licence de supprimer (mettre à zéro)
!>             toutes les valeurs singulières inférieures à N*epsilon*||A||.
!>       = 'R' : Similaire à 'A'. La propriété révélatrice de rang de la factorisation QR
!>             initiale est utilisée pour révéler (en utilisant le facteur triangulaire)
!>             un écart sigma_{r+1} < epsilon * sigma_r, auquel cas le
!>             RANG numérique est déclaré comme étant r. La SVD est calculée avec
!>             des bornes d'erreur absolues, mais plus précisément qu'avec 'A'.
!>

JOBU

!>          JOBU est CHARACTER*1
!>        Spécifie si les colonnes de U doivent être calculées :
!>       = 'U' : N colonnes de U sont retournées dans le tableau U.
!>       = 'F' : L'ensemble complet des M vecteurs singuliers gauches est retourné dans le tableau U.
!>       = 'W' : U peut être utilisé comme espace de travail de longueur M*N. Voir la description
!>             de U.
!>       = 'N' : U n'est pas calculé.
!>

JOBV

!>          JOBV est CHARACTER*1
!>        Spécifie si la matrice V doit être calculée :
!>       = 'V' : N colonnes de V sont retournées dans le tableau V ; les rotations de Jacobi
!>             ne sont pas explicitement accumulées.
!>       = 'J' : N colonnes de V sont retournées dans le tableau V, mais elles sont
!>             calculées comme produit de rotations de Jacobi. Cette option est
!>             autorisée uniquement si JOBU .NE. 'N', c'est-à-dire lors du calcul de la SVD complète.
!>       = 'W' : V peut être utilisé comme espace de travail de longueur N*N. Voir la description
!>             de V.
!>       = 'N' : V n'est pas calculé.
!>

JOBR

!>          JOBR est CHARACTER*1
!>        Spécifie la PLAGE des valeurs singulières. Donne la licence de mettre
!>        à zéro les petites valeurs singulières positives si elles sont hors de
!>        la plage spécifiée. Si A .NE. 0 est mise à l'échelle de sorte que la plus grande valeur singulière
!>        de c*A soit autour de DSQRT(BIG), BIG=SLAMCH('O'), alors JOBR donne
!>        la licence de supprimer les colonnes de A dont la norme dans c*A est inférieure à
!>        DSQRT(SFMIN) (pour JOBR = 'R'), ou inférieure à SMALL=SFMIN/EPSLN,
!>        où SFMIN=SLAMCH('S'), EPSLN=SLAMCH('E').
!>       = 'N' : Ne supprime pas les petites colonnes de c*A. Cette option suppose que
!>             les BLAS et les factorisations QR et les solveurs triangulaires sont
!>             implémentés pour fonctionner dans cette plage. Si la condition de A
!>             est supérieure à BIG, utilisez DGESVJ.
!>       = 'R' : Plage RESTREINTE pour sigma(c*A) est [DSQRT(SFMIN), DSQRT(BIG)]
!>             (approximativement, comme décrit ci-dessus). Cette option est recommandée.
!>                                            ~~~~~~~~~~~~~~~~~~~~~~~~~~~
!>        Pour calculer les valeurs singulières dans la plage COMPLÈTE [SFMIN,BIG]
!>        utilisez DGESVJ.
!>

JOBT

!>          JOBT est CHARACTER*1
!>        Si la matrice est carrée, la procédure peut décider d'utiliser
!>        la transposée de A si A^t semble meilleure en termes de convergence.
!>        Si la matrice n'est pas carrée, JOBT est ignoré. Ceci est sujet
!>        à des changements futurs.
!>        La décision est basée sur deux valeurs d'entropie sur l'orbite adjointe
!>        de A^t * A. Voir les descriptions de WORK(6) et WORK(7).
!>       = 'T' : transpose si le test d'entropie indique une convergence potentiellement plus rapide
!>        du processus de Jacobi si A^t est prise comme entrée. Si A est
!>        remplacée par A^t, alors le pivotement de ligne est inclus automatiquement.
!>       = 'N' : ne pas spéculer.
!>        Cette option peut être utilisée pour calculer uniquement les valeurs singulières, ou la
!>        SVD complète (U, SIGMA et V). Pour un seul ensemble de vecteurs singuliers
!>        (U ou V), l'appelant doit fournir à la fois U et V, car l'une des
!>        matrices est utilisée comme espace de travail si la matrice A est transposée.
!>        L'implémenteur peut facilement supprimer cette contrainte et rendre le
!>        code plus complexe. Voir les descriptions de U et V.
!>

JOBP

!>          JOBP est CHARACTER*1
!>        Donne la licence d'introduire des perturbations structurées pour noyer
!>        les nombres dénormalisés. Cette licence devrait être active si les
!>        dénormalisés sont mal implémentés, causant un calcul lent,
!>        surtout dans les cas de convergence rapide (!). Pour

M

!>          M est INTEGER
!>         Le nombre de lignes de la matrice d'entrée A.  M >= 0.
!>

N

!>          N est INTEGER
!>         Le nombre de colonnes de la matrice d'entrée A. M >= N >= 0.
!>

A

!>          A est un tableau DOUBLE PRECISION, dimension (LDA,N)
!>          À l'entrée, la matrice M par N A.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale du tableau A.  LDA >= max(1,M).
!>

SVA

!>          SVA est un tableau DOUBLE PRECISION, dimension (N)
!>          À la sortie,
!>          - Pour WORK(1)/WORK(2) = ONE : les valeurs singulières de A. Pendant
!>            le calcul, SVA contient les normes euclidiennes des colonnes des
!>            matrices itérées dans le tableau A.
!>          - Pour WORK(1) .NE. WORK(2) : les valeurs singulières de A sont
!>            (WORK(1)/WORK(2)) * SVA(1:N). Cette forme factorisée est utilisée si
!>            sigma_max(A) déborde ou si les petites valeurs singulières ont été
!>            préservées d'un débordement vers zéro (underflow) en mettant à
!>            l'échelle la matrice d'entrée A.
!>          - Si JOBR='R' alors certaines valeurs singulières peuvent être
!>            retournées comme des zéros exacts obtenus par  car elles sont
!>            en dessous du seuil de rang numérique ou sont des nombres
!>            dénormalisés.
!>

U

!>          U est un tableau DOUBLE PRECISION, dimension ( LDU, N ) ou ( LDU, M )
!>          Si JOBU = 'U', alors U contient à la sortie la matrice M par N des
!>                         vecteurs singuliers gauches.
!>          Si JOBU = 'F', alors U contient à la sortie la matrice M par M des
!>                         vecteurs singuliers gauches, incluant une ONB
!>                         (base orthonormale) du complément orthogonal de Range(A).
!>          Si JOBU = 'W'  .AND. (JOBV = 'V' .AND. JOBT = 'T' .AND. M = N),
!>                         alors U est utilisé comme espace de travail si la
!>                         procédure remplace A par A^t. Dans ce cas, [V] est
!>                         calculé dans U comme vecteurs singuliers gauches de A^t
!>                         puis copié dans le tableau V. Cette option 'W' est
!>                         simplement un rappel à l'appelant que dans ce cas U est
!>                         réservé comme espace de travail de longueur N*N.
!>          Si JOBU = 'N'  U n'est pas référencé, sauf si JOBT='T'.
!>

LDU

!>          LDU est INTEGER
!>          La dimension principale du tableau U,  LDU >= 1.
!>          SI  JOBU = 'U' ou 'F' ou 'W',  alors LDU >= M.
!>

V

!>          V est un tableau DOUBLE PRECISION, dimension ( LDV, N )
!>          Si JOBV = 'V', 'J' alors V contient à la sortie la matrice N par N des
!>                         vecteurs singuliers droits ;
!>          Si JOBV = 'W', ET (JOBU = 'U' ET JOBT = 'T' ET M = N),
!>                         alors V est utilisée comme espace de travail si la
!>                         procédure remplace A par A^t. Dans ce cas, [U] est
!>                         calculé dans V comme vecteurs singuliers droits de A^t
!>                         puis copié dans le tableau U. Cette option 'W' est
!>                         simplement un rappel à l'appelant que dans ce cas V est
!>                         réservée comme espace de travail de longueur N*N.
!>          Si JOBV = 'N'  V n'est pas référencé, sauf si JOBT='T'.
!>

LDV

!>          LDV est INTEGER
!>          La dimension principale du tableau V,  LDV >= 1.
!>          Si JOBV = 'V' ou 'J' ou 'W', alors LDV >= N.
!>

WORK

!>          WORK est un tableau DOUBLE PRECISION, dimension (MAX(7,LWORK))
!>          À la sortie, si N > 0 .AND. M > 0 (sinon non référencé),
!>          WORK(1) = SCALE = WORK(2) / WORK(1) est le facteur d'échelle tel
!>                    que SCALE*SVA(1:N) sont les valeurs singulières calculées
!>                    de A. (Voir la description de SVA().)
!>          WORK(2) = Voir la description de WORK(1).
!>          WORK(3) = SCONDA est une estimation du conditionnement de
!>                    A après équilibrage des colonnes. (Si JOBA = 'E' ou 'G')
!>                    SCONDA est une estimation de DSQRT(||(R^t * R)^(-1)||_1).
!>                    Elle est calculée à l'aide de DPOCON. Elle vérifie
!>                    N^(-1/4) * SCONDA <= ||R^(-1)||_2 <= N^(1/4) * SCONDA
!>                    où R est le facteur triangulaire de la QRF de A.
!>                    Cependant, si R est tronqué et que le rang numérique est
!>                    déterminé comme strictement inférieur à N, SCONDA est
!>                    retournée comme -1, indiquant ainsi que les plus petites
!>                    valeurs singulières pourraient être perdues.
!>
!>          Si la SVD complète est nécessaire, les deux nombres de condition
!>          suivants sont utiles pour l'analyse de l'algorithme. Ils sont
!>          fournis pour un développeur/implémenteur familier avec les
!>          détails de la méthode.
!>
!>          WORK(4) = une estimation du nombre de condition mis à l'échelle du
!>                    facteur triangulaire dans la première factorisation QR.
!>          WORK(5) = une estimation du nombre de condition mis à l'échelle du
!>                    facteur triangulaire dans la deuxième factorisation QR.
!>          Les deux paramètres suivants sont calculés si JOBT = 'T'.
!>          Ils sont fournis pour un développeur/implémenteur familier avec
!>          les détails de la méthode.
!>
!>          WORK(6) = l'entropie de A^t*A :: c'est l'entropie de Shannon
!>                    de diag(A^t*A) / Trace(A^t*A) prise comme point dans le
!>                    simplexe de probabilité.
!>          WORK(7) = l'entropie de A*A^t.
!>

LWORK

!>          LWORK est INTEGER
!>          Longueur de WORK pour confirmer l'allocation correcte de l'espace
!>          de travail.
!>          LWORK dépend du travail demandé :
!>
!>          Si seul SIGMA est nécessaire (JOBU = 'N', JOBV = 'N') et
!>            -> .. aucune estimation de condition mis à l'échelle requise (JOBE = 'N') :
!>               LWORK >= max(2*M+N,4*N+1,7). C'est l'exigence minimale.
!>               ->> Pour des performances optimales (code à blocs) la valeur optimale
!>               est LWORK >= max(2*M+N,3*N+(N+1)*NB,7). Ici NB est la taille
!>               de bloc optimale pour DGEQP3 et DGEQRF.
!>               En général, le LWORK optimal est calculé comme
!>               LWORK >= max(2*M+N,N+LWORK(DGEQP3),N+LWORK(DGEQRF), 7).
!>            -> .. une estimation du nombre de condition mis à l'échelle de A est
!>               requise (JOBA='E', 'G'). Dans ce cas, LWORK est le maximum
!>               de ce qui précède et N*N+4*N, c.-à-d. LWORK >= max(2*M+N,N*N+4*N,7).
!>               ->> Pour des performances optimales (code à blocs) la valeur optimale
!>               est LWORK >= max(2*M+N,3*N+(N+1)*NB, N*N+4*N, 7).
!>               En général, la longueur optimale LWORK est calculée comme
!>               LWORK >= max(2*M+N,N+LWORK(DGEQP3),N+LWORK(DGEQRF),
!>                                                     N+N*N+LWORK(DPOCON),7).
!>
!>          Si SIGMA et les vecteurs singuliers droits sont nécessaires (JOBV = 'V'),
!>            -> l'exigence minimale est LWORK >= max(2*M+N,4*N+1,7).
!>            -> Pour des performances optimales, LWORK >= max(2*M+N,3*N+(N+1)*NB,7),
!>               où NB est la taille de bloc optimale pour DGEQP3, DGEQRF, DGELQF,
!>               DORMLQ. En général, la longueur optimale LWORK est calculée comme
!>               LWORK >= max(2*M+N,N+LWORK(DGEQP3), N+LWORK(DPOCON),
!>                       N+LWORK(DGELQF), 2*N+LWORK(DGEQRF), N+LWORK(DORMLQ)).
!>
!>          Si SIGMA et les vecteurs singuliers gauches sont nécessaires
!>            -> l'exigence minimale est LWORK >= max(2*M+N,4*N+1,7).
!>            -> Pour des performances optimales :
!>               si JOBU = 'U' :: LWORK >= max(2*M+N,3*N+(N+1)*NB,7),
!>               si JOBU = 'F' :: LWORK >= max(2*M+N,3*N+(N+1)*NB,N+M*NB,7),
!>               où NB est la taille de bloc optimale pour DGEQP3, DGEQRF, DORMQR.
!>               En général, la longueur optimale LWORK est calculée comme
!>               LWORK >= max(2*M+N,N+LWORK(DGEQP3),N+LWORK(DPOCON),
!>                        2*N+LWORK(DGEQRF), N+LWORK(DORMQR)).
!>               Ici LWORK(DORMQR) égale N*NB (pour JOBU = 'U') ou
!>               M*NB (pour JOBU = 'F').
!>
!>          Si la SVD complète est nécessaire : (JOBU = 'U' ou JOBU = 'F') et
!>            -> si JOBV = 'V'
!>               l'exigence minimale est LWORK >= max(2*M+N,6*N+2*N*N).
!>            -> si JOBV = 'J' l'exigence minimale est
!>               LWORK >= max(2*M+N, 4*N+N*N,2*N+N*N+6).
!>            -> Pour des performances optimales, LWORK devrait être en plus
!>               supérieur à N+M*NB, où NB est la taille de bloc optimale
!>               pour DORMQR.
!>

IWORK

!>          IWORK est un tableau INTEGER, dimension (MAX(3,M+3*N)).
!>          À la sortie,
!>          IWORK(1) = le rang numérique déterminé après la première
!>                     factorisation QR avec pivotement. Voir les descriptions
!>                     de JOBA et JOBR.
!>          IWORK(2) = le nombre de valeurs singulières non nulles calculées
!>          IWORK(3) = si non nul, un message d'avertissement :
!>                     Si IWORK(3) = 1 alors certaines des normes de colonnes de A
!>                     étaient des flottants dénormalisés. La haute précision
!>                     demandée n'est pas garantie par les données.
!>

INFO

!>          INFO est INTEGER
!>           < 0 :  si INFO = -i, alors le i-ème argument avait une valeur illégale.
!>           = 0 :  sortie réussie ;
!>           > 0 :  DGEJSV n'a pas convergé dans le nombre maximal de balayages
!>                 autorisés. Les valeurs calculées peuvent être inexactes.
!>

Détails supplémentaires :

!>
!>  DGEJSV implémente un algorithme SVD de Jacobi préconditionné. Il utilise DGEQP3,
!>  DGEQRF, et DGELQF comme préprocesseurs et préconditionneurs. De manière
!>  optionnelle, un pivotement de lignes supplémentaire peut être utilisé comme
!>  préprocesseur, ce qui dans certains cas donne une précision beaucoup plus
!>  élevée. Un exemple est la matrice A avec la structure A = D1 * C * D2, où D1,
!>  D2 sont des matrices diagonales arbitrairement mal conditionnées et C est une
!>  matrice bien conditionnée. Dans ce cas, le pivotement complet dans les
!>  premières factorisations QR fournit une précision dépendant du nombre de
!>  condition de C, et indépendante de D1, D2. Cette précision accrue n'est pas
!>  entièrement comprise théoriquement, mais elle fonctionne bien en pratique.
!>  De plus, si A peut être écrite comme A = B*D, avec B bien conditionné et D
!>  diagonal, alors la haute précision est garantie, tant théoriquement que dans
!>  le logiciel, indépendamment de D. Pour plus de détails, voir [1], [2].
!>     La plage de calcul pour les valeurs singulières peut être la plage complète
!>  ( UNDERFLOW,OVERFLOW ), à conditionded que l'arithmétique de la machine et les routines BLAS
!>  & LAPACK appelées par DGEJSV sont implémentées pour fonctionner dans cette plage.
!>  Si ce n'est pas le cas, alors la restriction pour un calcul sûr avec
!>  les valeurs singulières dans la plage des nombres IEEE normalisés est que le
!>  nombre de condition spectral kappa(A)=sigma_max(A)/sigma_min(A) ne doit pas
!>  déborder. Ce code (DGEJSV) est mieux utilisé dans cette plage restreinte,
!>  ce qui signifie que les valeurs singulières de magnitude inférieure à ||A||_2 / DLAMCH('O') sont
!>  retournées comme zéros. Voir JOBR pour plus de détails à ce sujet.
!>     De plus, cette implémentation est quelque peu plus lente que celle décrite
!>  dans [1,2] en raison du remplacement de certains composants non-LAPACK, et parce que
!>  le choix de certains paramètres de réglage dans la partie itérative (DGESVJ) est
!>  laissé à l'implémenteur sur une machine particulière.
!>     La factorisation QR révélant le rang (dans ce code : DGEQP3) doit être
!>  implémentée comme dans [3]. Nous avons une nouvelle version de DGEQP3 en développement
!>  qui est plus robuste que l'actuelle dans LAPACK, avec une coupure plus nette dans
!>  les cas de rang défectueux. Elle sera disponible dans la bibliothèque SIGMA [4].
!>  Si M est beaucoup plus grand que N, il est évident que le QRF initial avec
!>  pivotement de colonnes peut être prétraité par le QRF sans pivotement. Ce
!>  truc bien connu n'est pas utilisé dans DGEJSV car dans certains cas un fort pondération de lignes
!>  peut être traité avec un pivotement complet. Le surcoût dans les cas où
!>  M est beaucoup plus grand que N est alors seulement dû au pivotement, mais les bénéfices en
!>  termes de précision ont prévalu. L'implémenteur/l'utilisateur peut incorporer
!>  cette étape de QRF supplémentaire facilement. L'implémenteur peut aussi améliorer le mouvement des données
!>  (transposition de matrice, copie de matrice, copie transposée de matrice) - cette
!>  implémentation de DGEJSV utilise seulement le mouvement de données le plus simple et naïf.
!>
