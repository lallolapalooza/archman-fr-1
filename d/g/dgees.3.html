DGEES calcule les valeurs propres, la forme de Schur et, optionnellement, la matrice des vecteurs de Schur pour les matrices GE

Documentation de la fonction/de la

sous-routine

sous-routine dgees (character jobvs, character sort, external select, integer n, double precision, dimension( lda, * ) a, integer lda, integer sdim, double precision, dimension( * ) wr, double precision, dimension( * ) wi, double precision, dimension( ldvs, * ) vs, integer ldvs, double precision, dimension( * ) work, integer lwork, logical, dimension( * ) bwork, integer

info)

DGEES calcule les valeurs propres, la forme de Schur et, optionnellement, la matrice des vecteurs de Schur pour les matrices

GE

But

: 
!>
!> DGEES calcule pour une matrice réelle non symétrique A de taille N par N, les
!> valeurs propres, la forme de Schur réelle T et, optionnellement, la matrice
!> des vecteurs de Schur Z. Cela donne la factorisation de Schur A = Z*T*(Z**T).
!>
!> Optionnellement, il trie également les valeurs propres sur la diagonale de la
!> forme de Schur réelle afin que les valeurs propres sélectionnées soient en
!> haut à gauche. Les colonnes principales de Z forment alors une base
!> orthonormale pour le sous-espace invariant correspondant aux valeurs propres
!> sélectionnées.
!>
!> Une matrice est en forme de Schur réelle si elle est quasi-triangulaire
!> supérieure avec des blocs de taille 1 par 1 et 2 par 2. Les blocs de taille 2
!> par 2 seront standardisés sous la forme
!>         [  a  b  ]
!>         [  c  a  ]
!>
!> où b*c < 0. Les valeurs propres d'un tel bloc sont a +- sqrt(bc).
!
>

Paramètre

s
JOBVS 
!>          JOBVS est CHARACTER*1
!>          = 'N' : les vecteurs de Schur ne sont pas calculés ;
!>          = 'V' : les vecteurs de Schur sont calculés.
!
>

SOR

T 
!>          SORT est CHARACTER*1
!>          Indique s'il faut trier ou non les valeurs propres sur la
!>          diagonale de la forme de Schur.
!>          = 'N' : les valeurs propres ne sont pas triées ;
!>          = 'S' : les valeurs propres sont triées (voir SELECT).
!
>

SELEC

T 
!>          SELECT est une fonction LOGICAL de deux arguments DOUBLE PRECISION
!>          SELECT doit être déclarée EXTERNAL dans la sous-routine appelante.
!>          Si SORT = 'S', SELECT est utilisée pour sélectionner les valeurs
!>          propres à trier en haut à gauche de la forme de Schur.
!>          Si SORT = 'N', SELECT n'est pas référencée.
!>          Une valeur propre WR(j)+sqrt(-1)*WI(j) est sélectionnée si
!>          SELECT(WR(j),WI(j)) est vraie ; c'est-à-dire, si l'une des valeurs
!>          propres d'une paire conjuguée complexe est sélectionnée, alors les
!>          deux valeurs propres complexes sont sélectionnées.
!>          Notez qu'une valeur propre complexe sélectionnée peut ne plus
!>          satisfaire SELECT(WR(j),WI(j)) = .TRUE. après le tri, car le
!>          tri peut changer la valeur des valeurs propres complexes
!>          (surtout si la valeur propre est mal conditionnée) ; dans ce
!>          cas, INFO est défini à N+2 (voir INFO ci-dessous).
!
>

N 
!>          N est INTEGER
!>          L'ordre de la matrice A. N >= 0.
!
>

A 
!>          A est un tableau DOUBLE PRECISION, dimension (LDA,N)
!>          À l'entrée, la matrice A de taille N par N.
!>          À la sortie, A a été écrasée par sa forme de Schur réelle T.
!
>

LD

A 
!>          LDA est INTEGER
!>          La dimension principale du tableau A. LDA >= max(1,N).
!
>

SDI

M 
!>          SDIM est INTEGER
!>          Si SORT = 'N', SDIM = 0.
!>          Si SORT = 'S', SDIM = le nombre de valeurs propres (après
!>                         tri) pour lesquelles SELECT est vraie. (Les
!>                         paires conjuguées complexes pour lesquelles
!>                         SELECT est vraie pour l'une ou l'autre des
!>                         valeurs propres comptent pour 2.)
!
>

W

R 
!>          WR est un tableau DOUBLE PRECISION, dimension (N)
!
>

W

I 
!>          WI est un tableau DOUBLE PRECISION, dimension (N)
!>          WR et WI contiennent les parties réelle et imaginaire,
!>          respectivement, des valeurs propres calculées, dans le même
!>          ordre qu'elles apparaissent sur la diagonale de la forme de
!>          Schur de sortie T. Les paires conjuguées complexes de
!>          valeurs propres apparaîtront consécutivement, la valeur
!>          propre ayant la partie imaginaire positive en premier.
!
>

V

S 
!>          VS est un tableau DOUBLE PRECISION, dimension (LDVS,N)
!>          Si JOBVS = 'V', VS contient la matrice orthogonale Z des
!>          vecteurs de Schur.
!>          Si JOBVS = 'N', VS n'est pas référencée.
!
>

LDV

S 
!>          LDVS est INTEGER
!>          La dimension principale du tableau VS. LDVS >= 1 ; si
!>          JOBVS = 'V', LDVS >= N.
!
>

WOR

K 
!>          WORK est un tableau DOUBLE PRECISION, dimension (MAX(1,LWORK))
!>          À la sortie, si INFO = 0, WORK(1) contient le LWORK optimal.
!
>

LWOR

K 
!>          LWORK est INTEGER
!>          La dimension du tableau WORK. LWORK >= max(1,3*N).
!>          Pour de bonnes performances, LWORK doit généralement être
!>          plus grand.
!>
!>          Si LWORK = -1, une interrogation de l'espace de travail est
!>          supposée ; la routine calcule uniquement la taille optimale
!>          du tableau WORK, renvoie cette valeur comme première entrée
!>          du tableau WORK, et aucun message d'erreur lié à LWORK n'est
!>          émis par XERBLA.
!
>

BWOR

K 
!>          BWORK est un tableau LOGICAL, dimension (N)
!>          Non référencé si SORT = 'N'.
!
>

INF

O 
!>          INFO est INTEGER
!>          = 0 : sortie réussie
!>          < 0 : si INFO = -i, le i-ème argument avait une valeur
!>                illégale.
!>          > 0 : si INFO = i, et i est
!>             <= N : l'algorithme QR a échoué à calculer toutes les
!>                    valeurs propres ; les éléments 1:ILO-1 et i+1:N de
!>                    WR et WI contiennent les valeurs propres qui ont
!>                    convergé ; si JOBVS = 'V', VS contient la matrice
!>                    qui réduit A à sa forme de Schur partiellement
!>                    convergée.
!>             = N+1 : les valeurs propres n'ont pas pu être réordonnées
!>                    car certaines valeurs propres étaient trop proches
!>                    pour être séparées (le problème est très mal
!>                    conditionné) ;
!>             = N+2 : après le réordonnancement, l'arrondi a changé les
!>                    valeurs de certaines valeurs propres complexes de
!>                    sorte que les valeurs propres principales dans la
!>                    forme de Schur ne satisfont plus SELECT=.TRUE.
!>                    Cela peut aussi être causé par un débordement
!>                    inférieur dû à la mise à l'échelle.
!
>
