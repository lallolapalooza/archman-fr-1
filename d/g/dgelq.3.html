Documentation de la fonction/sous-routine

subroutine dgelq (integer m, integer n, double precision, dimension( lda, * ) a, integer lda, double precision, dimension( * ) t, integer tsize, double precision, dimension( * ) work, integer lwork, integer info)

DGELQ

But :

!>
!> DGELQ calcule une factorisation LQ d'une matrice réelle A de dimensions M par N :
!>
!>    A = ( L 0 ) *  Q
!>
!> où :
!>
!>    Q est une matrice orthogonale de dimensions N par N ;
!>    L est une matrice triangulaire inférieure de dimensions M par M ;
!>    0 est une matrice nulle de dimensions M par (N-M), si M < N.
!>
!>

Paramètres

M 
!>          M est INTEGER
!>          Le nombre de lignes de la matrice A.  M >= 0.
!>

N

!>          N est INTEGER
!>          Le nombre de colonnes de la matrice A.  N >= 0.
!>

A

!>          A est un tableau DOUBLE PRECISION, de dimensions (LDA,N)
!>          À l'entrée, la matrice A de dimensions M par N.
!>          À la sortie, les éléments sur et sous la diagonale du tableau
!>          contiennent la matrice trapézoïdale inférieure L de dimensions M par min(M,N)
!>          (L est triangulaire inférieure si M <= N) ;
!>          les éléments au-dessus de la diagonale sont utilisés pour stocker une partie de la
!>          structure de données représentant Q.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale du tableau A.  LDA >= max(1,M).
!>

T

!>          T est un tableau DOUBLE PRECISION, de dimensions (MAX(5,TSIZE))
!>          À la sortie, si INFO = 0, T(1) renvoie la taille TSIZE optimale (ou soit minimale
!>          soit optimale, si une interrogation est supposée). Voir TSIZE pour les détails.
!>          Le reste de T contient une partie de la structure de données utilisée pour représenter Q.
!>          Si l'on souhaite appliquer ou construire Q, il faut conserver T
!>          (en plus de A) et le passer aux sous-routines suivantes.
!>

TSIZE

!>          TSIZE est INTEGER
!>          Si TSIZE >= 5, la dimension du tableau T.
!>          Si TSIZE = -1 ou -2, une interrogation d'espace de travail est supposée. La routine
!>          ne calcule que les tailles des tableaux T et WORK, renvoie ces
!>          valeurs comme les premières entrées des tableaux T et WORK, et aucun message
!>          d'erreur lié à T ou WORK n'est émis par XERBLA.
!>          Si TSIZE = -1, la routine calcule la taille optimale de T pour les
!>          performances optimales et renvoie cette valeur dans T(1).
!>          Si TSIZE = -2, la routine calcule la taille minimale de T et
!>          renvoie cette valeur dans T(1).
!>

WORK

!>          (espace de travail) tableau DOUBLE PRECISION, de dimensions (MAX(1,LWORK))
!>          À la sortie, si INFO = 0, WORK(1) contient la taille LWORK optimale (ou soit minimale
!>          soit optimale, si une interrogation a été supposée).
!>          Voir LWORK pour les détails.
!>

LWORK

!>          LWORK est INTEGER
!>          La dimension du tableau WORK. LWORK >= 1.
!>          Si LWORK = -1 ou -2, une interrogation d'espace de travail est supposée. La routine
!>          ne calcule que les tailles des tableaux T et WORK, renvoie ces
!>          valeurs comme les premières entrées des tableaux T et WORK, et aucun message
!>          d'erreur lié à T ou WORK n'est émis par XERBLA.
!>          Si LWORK = -1, la routine calcule la taille optimale de WORK pour les
!>          performances optimales et renvoie cette valeur dans WORK(1).
!>          Si LWORK = -2, la routine calcule la taille minimale de WORK et
!>          renvoie cette valeur dans WORK(1).
!>

INFO

!>          INFO est INTEGER
!>          = 0 :  sortie réussie
!>          < 0 :  si INFO = -i, le i-ème argument avait une valeur illégale
!>

Détails supplémentaires

!>
!> Le but de l'interface est de donner le maximum de liberté aux développeurs pour
!> créer l'algorithme de factorisation LQ de leur choix. Le L
!> triangulaire (trapézoïdal) doit être stocké dans la partie inférieure de A. La partie inférieure de A
!> et le tableau T peuvent être utilisés pour stocker toute information pertinente pour appliquer ou
!> construire le facteur Q. Le tableau WORK peut être supprimé sans risque après la sortie.
!>
!> Attention : on ne doit pas s'attendre à ce que les tailles de T et WORK soient les mêmes d'une
!> implémentation de LAPACK à l'autre, ni même d'une exécution à l'autre.
!> Une interrogation d'espace de travail (pour T et WORK) est nécessaire à chaque exécution. Toutefois,
!> pour une exécution donnée, la taille de T et WORK est fixe et ne changera pas
!> d'une interrogation à l'autre.
!>
!>

Détails supplémentaires particuliers à cette implémentation de LAPACK :

!>
!> Ces détails sont particuliers à cette implémentation de LAPACK. Les utilisateurs ne doivent pas
!> les tenir pour acquis. Ces détails peuvent changer à l'avenir et ne sont probablement pas
!> vrais pour une autre implémentation de LAPACK. Ces détails sont pertinents si l'on souhaite
!> essayer de comprendre le code. Ils ne font pas partie de l'interface.
!>
!> Dans cette version,
!>
!>          T(2) : taille de bloc de lignes (MB)
!>          T(3) : taille de bloc de colonnes (NB)
!>          T(6:TSIZE) : structure de données nécessaire pour Q, calculée par
!>                           DLASWLQ ou DGELQT
!>
!>  Selon les dimensions de la matrice M et N, et les tailles de bloc de lignes
!>  et de colonnes MB et NB renvoyées par ILAENV, DGELQ utilisera soit
!>  DLASWLQ (si la matrice est courte et large) soit DGELQT pour calculer
!>  la factorisation LQ.
!>
