DGEDMD calcule la Décomposition Dynamique en Modes (DMD) pour une paire de matrices d'instantanés de

données.

But

: 
!>    DGEDMD calcule la Décomposition Dynamique en Modes (DMD) pour
!>    une paire de matrices d'instantanés de données. Pour les matrices
!>    d'entrée X et Y telles que Y = A*X avec une matrice A
!>    inaccessible, DGEDMD calcule un certain nombre de paires de Ritz de A en utilisant
!>    l'extraction standard de Rayleigh-Ritz à partir d'un sous-espace de
!>    range(X) qui est déterminé à l'aide des vecteurs singuliers gauches
!>    dominants de X. En option, DGEDMD renvoie les résidus
!>    des paires de Ritz calculées, les informations nécessaires pour
!>    un raffinement des vecteurs de Ritz, ou les vecteurs propres de
!>    l'Exact DMD.
!>    Pour plus de détails, voir les références listées
!>    ci-dessous. Pour plus de détails sur l'implémentation, voir [3].
!
>

Paramètre

s
JOBS 
!>    JOBS (entrée) est CHARACTER*1
!>    Détermine si les instantanés de données initiaux sont mis à l'échelle
!>    par une matrice diagonale.
!>    'S' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D de sorte que X*D ait des
!>           colonnes non nulles unitaires (dans la 2-norme euclidienne)
!>    'C' :: Les instantanés sont mis à l'échelle comme avec l'option 'S'.
!>           S'il est constaté que la i-ième colonne de X est un vecteur
!>           nul et que la i-ième colonne correspondante de Y est
!>           non nulle, alors la i-ième colonne de Y est mise à
!>           zéro et un drapeau d'avertissement est levé.
!>    'Y' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D de sorte que Y*D ait des
!>           colonnes non nulles unitaires (dans la 2-norme euclidienne)
!>    'N' :: Pas de mise à l'échelle des données.
!
>

JOB

Z 
!>    JOBZ (entrée) CHARACTER*1
!>    Détermine si les vecteurs propres (modes de Koopman) seront
!>    calculés.
!>    'V' :: Les vecteurs propres (modes de Koopman) seront calculés
!>           et renvoyés dans la matrice Z.
!>           Voir la description de Z.
!>    'F' :: Les vecteurs propres (modes de Koopman) seront renvoyés
!>           sous forme factorisée comme le produit X(:,1:K)*W, où X
!>           contient une base POD (vecteurs singuliers gauches
!>           dominants de la matrice de données X) et W contient les vecteurs propres
!>           du quotient de Rayleigh correspondant.
!>           Voir les descriptions de K, X, W, Z.
!>    'N' :: Les vecteurs propres ne sont pas calculés.
!
>

JOB

R 
!>    JOBR (entrée) CHARACTER*1
!>    Détermine s'il faut calculer les résidus.
!>    'R' :: Les résidus pour les paires propres calculées seront
!>           calculés et stockés dans le tableau RES.
!>           Voir la description de RES.
!>           Pour que cette option soit valide, JOBZ doit être 'V'.
!>    'N' :: Les résidus ne sont pas calculés.
!
>

JOB

F 
!>    JOBF (entrée) CHARACTER*1
!>    Spécifie s'il faut stocker les informations nécessaires au post-
!>    traitement (par ex. le calcul de vecteurs de Ritz raffinés)
!>    'R' :: La matrice nécessaire au raffinement des vecteurs
!>           de Ritz est calculée et stockée dans le tableau B.
!>           Voir la description de B.
!>    'E' :: Les vecteurs propres non mis à l'échelle de l'Exact DMD sont
!>           calculés et renvoyés dans le tableau B. Voir la
!>           description de B.
!>    'N' :: Aucune donnée de raffinement de vecteurs propres n'est calculée.
!
>

WHTSV

D 
!>    WHTSVD (entrée) INTEGER, WHSTVD dans { 1, 2, 3, 4 }
!>    Permet la sélection de l'algorithme SVD de la
!>    bibliothèque LAPACK.
!>    1 :: DGESVD (l'algorithme SVD par QR)
!>    2 :: DGESDD (l'algorithme Divide and Conquer ; si suffisamment
!>         d'espace de travail est disponible, c'est l'option la plus rapiden)
!>    3 :: DGESVDQ (le SVD QR préconditionné ; ceci et 4
!>         sont les options les plus précises)
!>    4 :: DGEJSV (le SVD Jacobi préconditionné ; ceci et 3
!>         sont les options les plus précises)
!>    Pour les quatre méthodes ci-dessus, une différence
!>    significative dans la précision des petites valeurs
!>    singulières est possible si les instantanés varient en
!>    norme de sorte que X soit sévèrement mal conditionné.
!>    Si les petites valeurs singulières (plus petites que
!>    EPS*||X||) sont d'intérêt et que JOBS=='N', alors les
!>    options (3, 4) donnent les résultats les plus précis,
!>    où l'option 4 est légèrement meilleure et avec un
!>    fondement théorique plus solide.
!>    Si JOBS=='S', c'est-à-dire si les colonnes de X seront
!>    normalisées, alors toutes les méthodes donnent des
!>    résultats presque également précis.
!>

M

!>    M (entrée) INTEGER, M>= 0
!>    La dimension de l'espace d'état (la dimension des
!>    lignes de X, Y).
!>

N

!>    N (entrée) INTEGER, 0 <= N <= M
!>    Le nombre de paires d'instantanés de données
!>    (le nombre de colonnes de X et Y).
!>

X

!>    X (entrée/sortie) tableau REAL(KIND=WP) M-par-N
!>    > À l'entrée, X contient la matrice d'instantanés de
!>    données X. On suppose que les normes de colonne de X
!>    sont dans l'intervalle des nombres flottants normalisés.
!>    < À la sortie, les K premières colonnes de X contiennent
!>    une base POD, c'est-à-dire les K premiers vecteurs
!>    singuliers gauches de la matrice de données d'entrée X,
!>    U(:,1:K). Les N colonnes de X contiennent tous les
!>    vecteurs singuliers gauches de la matrice d'entrée X.
!>    Voir les descriptions de K, Z et W.
!>

LDX

!>    LDX (entrée) INTEGER, LDX >= M
!>    La dimension de tête du tableau X.
!>

Y

!>    Y (entrée/espace de travail/sortie) tableau REAL(KIND=WP) M-par-N
!>    > À l'entrée, Y contient la matrice d'instantanés de
!>    données Y
!>    < À la sortie,
!>    Si JOBR == 'R', les K premières colonnes de Y contiennent
!>    les vecteurs résidus pour les paires de Ritz calculées.
!>    Voir la description de RES.
!>    Si JOBR == 'N', Y contient les données d'entrée
!>    originales, mises à l'échelle selon la valeur de JOBS.
!>

LDY

!>    LDY (entrée) INTEGER , LDY >= M
!>    La dimension de tête du tableau Y.
!>

NRNK

!>    NRNK (entrée) INTEGER
!>    Détermine le mode de calcul du rang numérique,
!>    c'est-à-dire comment tronquer les petites valeurs
!>    singulières de la matrice d'entrée X. À l'entrée, si
!>    NRNK = -1 :: la i-ème valeur singulière sigma(i) est
!>                 tronquée si sigma(i) <= TOL*sigma(1).
!>                 Cette option est recommandée.
!>    NRNK = -2 :: la i-ème valeur singulière sigma(i) est
!>                 tronquée si sigma(i) <= TOL*sigma(i-1)
!>                 Cette option est incluse à des fins de
!>                 R&D. Elle nécessite un SVD hautement
!>                 précis, ce qui peut ne pas être faisable.
!>
!>    Le rang numérique peut être imposé en utilisant une
!>    valeur positive de NRNK comme suit :
!>    0 < NRNK <= N :: au plus NRNK des plus grandes valeurs
!>    singulières seront utilisées. Si le nombre des valeurs
!>    singulières non nulles calculées est inférieur à NRNK,
!>    alors seules ces valeurs non nulles seront utilisées et
!>    la dimension réellement utilisée est inférieure à NRNK.
!>    Le nombre réel des valeurs singulières non nulles est
!>    renvoyé dans la variable K. Voir les descriptions de
!>    TOL et K.
!>

TOL

!>    TOL (entrée) REAL(KIND=WP), 0 <= TOL < 1
!>    La tolérance pour tronquer les petites valeurs
!>    singulières.
!>    Voir la description de NRNK.
!>

K

!>    K (sortie) INTEGER,  0 <= K <= N
!>    La dimension de la base POD pour la matrice
!>    d'instantanés de données X et le nombre des paires de
!>    Ritz calculées.
!>    La valeur de K est déterminée selon la règle établie
!>    par les paramètres NRNK et TOL.
!>    Voir les descriptions de NRNK et TOL.
!>

REIG

!>    REIG (sortie) tableau REAL(KIND=WP) N-par-1
!>    Les K premières entrées (K<=N) de REIG contiennent
!>    les parties réelles des valeurs propres calculées
!>    REIG(1:K) + sqrt(-1)*IMEIG(1:K).
!>    Voir les descriptions de K, IMEIG et Z.
!>

IMEIG

!>    IMEIG (sortie) tableau REAL(KIND=WP) N-par-1
!>    Les K premières entrées (K<=N) de IMEIG contiennent
!>    les parties imaginaires des valeurs propres calculées
!>    REIG(1:K) + sqrt(-1)*IMEIG(1:K).
!>    Les valeurs propres sont déterminées comme suit :
!>    Si IMEIG(i) == 0, alors la valeur propre correspondante
!>    est réelle, LAMBDA(i) = REIG(i).
!>    Si IMEIG(i)>0, alors la paire conjuguée complexe
!>    correspondante de valeurs propres s'écrit
!>    LAMBDA(i)   = REIG(i) + sqrt(-1)*IMAG(i)
!>    LAMBDA(i+1) = REIG(i) - sqrt(-1)*IMAG(i)
!>    C'est-à-dire que les paires conjuguées complexes ont
!>    des indices consécutifs (i,i+1), avec la partie
!>    imaginaire positive listée en premier.
!>    Voir les descriptions de K, REIG et Z.
!>

Z

!>    Z (espace de travail/sortie) tableau REAL(KIND=WP) M-par-N
!>    Si JOBZ =='V' alors
!>       Z contient des vecteurs de Ritz réels comme suit :
!>       Si IMEIG(i)=0, alors Z(:,i) est un vecteur propre
!>       de la i-ème valeur de Ritz ; ||Z(:,i)||_2=1.
!>       Si IMEIG(i) > 0 (et IMEIG(i+1) < 0) alors
!>       [Z(:,i) Z(:,i+1)] engendrent un sous-espace
!>       invariant et les valeurs de Ritz extraites de ce
!>       sous-espace sont
!>       REIG(i) + sqrt(-1)*IMEIG(i) et
!>       REIG(i) - sqrt(-1)*IMEIG(i).
!>       Les vecteurs propres correspondants sont
!>       Z(:,i) + sqrt(-1)*Z(:,i+1) et
!>       Z(:,i) - sqrt(-1)*Z(:,i+1), respectivement.
!>       || Z(:,i:i+1)||_F = 1.
!>    Si JOBZ == 'F', alors les descriptions ci-dessus
!>    s'appliquent aux colonnes de X(:,1:K)*W(1:K,1:K),
!>    où les colonnes de W(1:k,1:K) sont les vecteurs propres
!>    calculés du quotient de Rayleigh K-par-K. Les colonnes
!>    de W(1:K,1:K) sont de structure similaire : Si
!>    IMEIG(i) == 0 alors X(:,1:K)*W(:,i) est un vecteur
!>    propre, et si IMEIG(i)>0 alors
!>    X(:,1:K)*W(:,i)+sqrt(-1)*X(:,1:K)*W(:,i+1) et
!>         X(:,1:K)*W(:,i)-sqrt(-1)*X(:,1:K)*W(:,i+1)
!>    sont les vecteurs propres de LAMBDA(i), LAMBDA(i+1).
!>    Voir les descriptions de REIG, IMEIG, X et W.
!>

LDZ

!>    LDZ (entrée) INTEGER , LDZ >= M
!>    La dimension de tête du tableau Z.
!>

RES

!>    RES (sortie) tableau REAL(KIND=WP) N-par-1
!>    RES(1:K) contient les résidus pour les K paires de
!>    Ritz calculées.
!>    Si LAMBDA(i) est réelle, alors
!>       RES(i) = || A * Z(:,i) - LAMBDA(i)*Z(:,i))||_2.
!>    Si [LAMBDA(i), LAMBDA(i+1)] est une paire conjuguée
!>    complexe alors
!>    RES(i)=RES(i+1) = || A * Z(:,i:i+1) - Z(:,i:i+1) *B||_F
!>    où B = [ real(LAMBDA(i)) imag(LAMBDA(i)) ]
!>          [-imag(LAMBDA(i)) real(LAMBDA(i)) ].
!>    Il tient que
!>    RES(i)   = || A*ZC(:,i)   - LAMBDA(i)  *ZC(:,i)   ||_2
!>    RES(i+1) = || A*ZC(:,i+1) - LAMBDA(i+1)*ZC(:,i+1) ||_2
!>    où ZC(:,i)   =  Z(:,i) + sqrt(-1)*Z(:,i+1)
!>          ZC(:,i+1) =  Z(:,i) - sqrt(-1)*Z(:,i+1)
!>    Voir la description de REIG, IMEIG et Z.
!>

B

!>    B (sortie) tableau REAL(KIND=WP) M-par-N.
!>    Si JOBF =='R', B(1:M,1:K) contient A*U(:,1:K), et peut
!>    être utilisé pour calculer les vecteurs raffinés ; voir
!>    les détails supplémentaires dans les références
!>    fournies.
!>    Si JOBF == 'E', B(1:M,1;K) contient
!>    A*U(:,1:K)*W(1:K,1:K), qui sont les vecteurs du
!>    Exact DMD, à la mise à l'échelle par les valeurs propres
!>    inverses près.
!>    Si JOBF =='N', alors B n'est pas référencé.
!>    Voir les descriptions de X, W, K.
!>

LDB

!>    LDB (entrée) INTEGER, LDB >= M
!>    La dimension de tête du tableau B.
!>

W

!>    W (espace de travail/sortie) tableau REAL(KIND=WP) N-par-N
!>    À la sortie, W(1:K,1:K) contient les K vecteurs
!>    propres calculés du quotient de Rayleigh de la matrice
!>    (parties réelle et imaginaire pour chaque paire
!>    conjuguée complexe des valeurs propres). Les vecteurs
!>    de Ritz (renvoyés dans Z) sont le produit de X
!>    (contenant une base POD pour la matrice d'entrée X) et
!>    W. Voir les descriptions de K, S, X et Z.
!>    W est également utilisé comme espace de travail pour
!>    stocker temporairement les vecteurs singuliers droits
!>    de X.
!>

LDW

!>    LDW (entrée) INTEGER, LDW >= N
!>    La dimension de tête du tableau W.
!>

S

!>    S (espace de travail/sortie) tableau REAL(KIND=WP) N-par-N
!>    Le tableau S(1:K,1:K) est utilisé pour le quotient de
!>    Rayleigh de la matrice. Ce contenu est écrasé pendant
!>    la décomposition en valeurs propres par DGEEV.
!>    Voir la description de K.
!>

LDS

!>    LDS (entrée) INTEGER, LDS >= N
!>    La dimension de tête du tableau S.
!>

WORK

!>    WORK (espace de travail/sortie) tableau REAL(KIND=WP) LWORK-par-1
!>    À la sortie, WORK(1:N) contient les valeurs singulières
!>    de X (pour JOBS=='N') ou de X mis à l'échelle par
!>    colonne (JOBS=='S', 'C').
!>    Si WHTSVD==4, alors WORK(N+1) et WORK(N+2) contiennent
!>    le facteur d'échelle WORK(N+2)/WORK(N+1) utilisé pour
!>    mettre X et Y à l'échelle afin d'éviter le débordement
!>    dans le SVD de X.
!>    Cela peut être d'intérêt si l'option d'échelle est
!>    désactivée et si autant que possible de plus petites
!>    valeurs propres sont souhaitées à la plus haute précision
!>    faisable.
!>    Si l'appel à DGEDMD n'est qu'une interrogation d'espace
!>    de travail, alors WORK(1) contient la longueur minimale
!>    de l'espace de travail et WORK(2) est la longueur
!>    optimale de l'espace de travail. Ainsi, la longueur de
!>    travail est au moins 2.
!>    Voir la description de LWORK.
!>

LWORK

!>    LWORK (entrée) INTEGER
!>    La longueur minimale du vecteur d'espace de travail WORK.
!>    LWORK est calculé comme suit :
!>    Si WHTSVD == 1 ::
!>       Si JOBZ == 'V', alors
!>       LWORK >= MAX(2, N + LWORK_SVD, N+MAX(1,4*N)).
!>       Si JOBZ == 'N'  alors
!>       LWORK >= MAX(2, N + LWORK_SVD, N+MAX(1,3*N)).
!>       Ici LWORK_SVD = MAX(1,3*N+M,5*N) est la longueur
!>       minimale de l'espace de travail de DGESVD.
!>    Si WHTSVD == 2 ::
!>       Si JOBZ == 'V', alors
!>       LWORK >= MAX(2, N + LWORK_SVD, N+MAX(1,4*N))
!>       Si JOBZ == 'N', alors
!>       LWORK >= MAX(2, N + LWORK_SVD, N+MAX(1,3*N))
!>       Ici LWORK_SVD = MAX(M, 5*N*N+4*N)+3*N*N est la
!>       longueur minimale de l'espace de travail de DGESDD.
!>    Si WHTSVD == 3 ::
!>       Si JOBZ == 'V', alors
!>       LWORK >= MAX(2, N+LWORK_SVD,N+MAX(1,4*N))
!>       Si JOBZ == 'N', alors
!>       LWORK >= MAX(2, N+LWORK_SVD,N+MAX(1,3*N))
!>       Ici LWORK_SVD = N+M+MAX(3*N+1,
!>                       MAX(1,3*N+M,5*N),MAX(1,N))
!>       est la longueur minimale de l'espace de travail de
!>       DGESVDQ.
!>    Si WHTSVD == 4 ::
!>       Si JOBZ == 'V', alors
!>       LWORK >= MAX(2, N+LWORK_SVD,N+MAX(1,4*N))
!>       Si JOBZ == 'N', alors
!>       LWORK >= MAX(2, N+LWORK_SVD,N+MAX(1,3*N))
!>       Ici LWORK_SVD = MAX(7,2*M+N,6*N+2*N*N) est la
!>       longueur minimale de l'espace de travail de DGEJSV.
!>    Les expressions ci-dessus ne sont pas simplifiées afin
!>    de rendre l'utilisation de WORK plus transparente, et
!>    pour faciliter la vérification. Dans tous les cas, LWORK >= 2.
!>    Si à l'entrée LWORK = -1, alors une interrogation d'espace de travail est
!>    supposée et la procédure ne calcule que les longueurs d'espace de travail
!>    minimales et optimales pour WORK et
!>    IWORK. Voir les descriptions de WORK et IWORK.
!
>

IWOR

K 
!>    IWORK (espace de travail/sortie) Tableau INTEGER LIWORK-par-1
!>    Espace de travail requis uniquement si WHTSVD égale
!>    2 , 3 ou 4. (Voir la description de WHTSVD).
!>    Si à l'entrée LWORK =-1 ou LIWORK=-1, alors la
!>    longueur minimale de IWORK est calculée et retournée dans
!>    IWORK(1). Voir la description de LIWORK.
!
>

LIWOR

K 
!>    LIWORK (entrée) INTEGER
!>    La longueur minimale du vecteur d'espace de travail IWORK.
!>    Si WHTSVD == 1, alors seul IWORK(1) est utilisé ; LIWORK >=1
!>    Si WHTSVD == 2, alors LIWORK >= MAX(1,8*MIN(M,N))
!>    Si WHTSVD == 3, alors LIWORK >= MAX(1,M+N-1)
