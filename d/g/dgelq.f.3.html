subroutine dgelq (m, n, a, lda, t, tsize, work, lwork, info)
DGELQ

Documentation de la fonction/sous-routine

sous-routine dgelq (integer m, integer n, double precision, dimension( lda, * ) a, integer lda, double precision, dimension( * ) t, integer tsize, double precision, dimension( * ) work, integer lwork, integer info)

DGELQ

But :

!>
!> DGELQ calcule une factorisation LQ d'une matrice réelle M-par-N A :
!>
!>    A = ( L 0 ) *  Q
!>
!> où :
!>
!>    Q est une matrice orthogonale N-par-N ;
!>    L est une matrice triangulaire inférieure M-par-M ;
!>    0 est une matrice zéro M-par-(N-M), si M < N.
!>
!>

Paramètres

M 
!>          M est un ENTIER
!>          Le nombre de lignes de la matrice A.  M >= 0.
!>

N

!>          N est un ENTIER
!>          Le nombre de colonnes de la matrice A.  N >= 0.
!>

A

!>          A est un tableau DOUBLE PRECISION, de dimension (LDA,N)
!>          En entrée, la matrice M-par-N A.
!>          En sortie, les éléments sur et en dessous de la diagonale du tableau
!>          contiennent la matrice trapézoïdale inférieure L
!>          M-par-min(M,N) (L est triangulaire inférieure si M <= N) ;
!>          les éléments au-dessus de la diagonale sont utilisés pour stocker une partie de la
!>          structure de données pour représenter Q.
!>

LDA

!>          LDA est un ENTIER
!>          La dimension de tête du tableau A.  LDA >= max(1,M).
!>

T

!>          T est un tableau DOUBLE PRECISION, de dimension (MAX(5,TSIZE))
!>          En sortie, si INFO = 0, T(1) renvoie la taille optimale (ou une taille minimale
!>          ou optimale, si une requête est supposée) TSIZE. Voir TSIZE pour les détails.
!>          Le reste de T contient une partie de la structure de données utilisée pour représenter Q.
!>          Si l'on souhaite appliquer ou construire Q, il faut conserver T
!>          (en plus de A) et le passer à des sous-routines supplémentaires.
!>

TSIZE

!>          TSIZE est un ENTIER
!>          Si TSIZE >= 5, la dimension du tableau T.
!>          Si TSIZE = -1 ou -2, une requête de taille de mémoire tampon est supposée. La routine
!>          calcule uniquement les tailles des tableaux T et WORK, renvoie ces
!>          valeurs comme premières entrées des tableaux T et WORK, et aucun message d'erreur
!>          relatif à T ou WORK n'est émis par XERBLA.
!>          Si TSIZE = -1, la routine calcule la taille optimale de T pour
!>          les performances optimales et renvoie cette valeur dans T(1).
!>          Si TSIZE = -2, la routine calcule la taille minimale de T et
!>          renvoie cette valeur dans T(1).
!>

WORK

!>          (mémoire tampon) tableau DOUBLE PRECISION, de dimension (MAX(1,LWORK))
!>          En sortie, si INFO = 0, WORK(1) contient la taille optimale (ou une taille minimale
!>          ou optimale, si une requête a été effectuée) LWORK.
!>          Voir LWORK pour les détails.
!>

LWORK

!>          LWORK est un ENTIER
!>          La dimension du tableau WORK. LWORK >= 1.
!>          Si LWORK = -1 ou -2, une requête de taille de mémoire tampon est supposée. La routine
!>          calcule uniquement les tailles des tableaux T et WORK, renvoie ces
!>          valeurs comme premières entrées des tableaux T et WORK, et aucun message d'erreur
!>          relatif à T ou WORK n'est émis par XERBLA.
!>          Si LWORK = -1, la routine calcule la taille optimale de WORK pour
!>          les performances optimales et renvoie cette valeur dans WORK(1).
!>          Si LWORK = -2, la routine calcule la taille minimale de WORK et
!>          renvoie cette valeur dans WORK(1).
!>

INFO

!>          INFO est un ENTIER
!>          = 0:  terminaison réussie
!>          < 0:  si INFO = -i, le i-ième argument était illégal
!>

Détails supplémentaires

!>
!> Le but de l'interface est de donner une liberté maximale aux développeurs pour
!> créer n'importe quel algorithme de factorisation LQ qu'ils souhaitent. Le
!> triangulaire (trapézoïdal) L doit être stocké dans la partie inférieure de A. La partie inférieure de A
!> et le tableau T peuvent être utilisés pour stocker toute information pertinente pour l'application ou
!> la construction du facteur Q. Le tableau WORK peut être éliminé en toute sécurité après la sortie.
!>
!> Attention : Il ne faut pas s'attendre à ce que les tailles de T et WORK soient identiques d'une
!> implémentation LAPACK à l'autre, ni même d'une exécution à l'autre.
!> Une requête de taille de mémoire tampon (pour T et WORK) est nécessaire à chaque exécution. Cependant,
!> pour une exécution donnée, la taille de T et WORK est fixe et ne changera pas
!> d'une requête à l'autre.
!>
!>

Détails supplémentaires propres à cette implémentation LAPACK :

!>
!> Ces détails sont spécifiques à cette implémentation LAPACK. Les utilisateurs ne doivent pas
!> les tenir pour acquis. Ces détails peuvent changer à l'avenir et ne sont pas susceptibles
!> d'être vrais pour une autre implémentation LAPACK. Ces détails sont pertinents si l'on souhaite
!> essayer de comprendre le code. Ils ne font pas partie de l'interface.
!>
!> Dans cette version,
!>
!>          T(2) : taille de bloc de ligne (MB)
!>          T(3) : taille de bloc de colonne (NB)
!>          T(6:TSIZE) : structure de données nécessaire pour Q, calculée par
!>                           DLASWLQ ou DGELQT
!>
!>  Selon les dimensions de la matrice M et N, et les tailles de bloc de ligne et de colonne
!>  MB et NB renvoyées par ILAENV, DGELQ utilisera soit
!>  DLASWLQ (si la matrice est courte et large) soit DGELQT pour calculer
!>  la factorisation LQ.
!>
