NOM

dcmp2pgm - Lit une image DICOM et un état de présentation et rend un bitmap

SYNOPSIS

dcmp2pgm [options] dcmimage-in [bitmap-out]

DESCRIPTION

L'utilitaire dcmp2pgm rend une image DICOM monochrome sous le contrôle d'un objet d'état de présentation softcopy en nuances de gris en un bitmap monochrome avec 8 bits/pixel. Le bitmap est stocké soit au format "Portable Gray Map" (PGM), soit comme objet d'image de capture secondaire DICOM. Si aucun état de présentation n'est lu depuis un fichier, un état de présentation par défaut est créé. L'utilitaire permet de lire un fichier de configuration du Visualiseur d'état de présentation softcopy au démarrage. Dans ce cas, les paramètres du fichier de configuration affectant le rendu de l'état de présentation sont utilisés, par exemple une correction de l'étendue de l'échelle de gris selon le modèle de Barten (DICOM partie 14) peut être effectuée si la courbe caractéristique du système d'affichage est disponible et définie dans le fichier de configuration.

PARAMÈTRES

dcmimage-in  image DICOM d'entrée ("-" pour stdin)
bitmap-out   image DICOM ou bitmap PGM de sortie

OPTIONS

options générales

  -h   --help
         affiche ce texte d'aide et quitte
       --version
         affiche les informations de version et quitte
       --arguments
         affiche les arguments de la ligne de commande étendus
  -q   --quiet
         mode silencieux, n'affiche ni avertissements ni erreurs
  -v   --verbose
         mode verbeux, affiche les détails du traitement
  -d   --debug
         mode débogage, affiche les informations de débogage
  -ll  --log-level  [l]evel: constante de chaîne
         (fatal, error, warn, info, debug, trace)
         utilise le niveau l pour le journaliseur
  -lc  --log-config  [f]ilename: chaîne
         utilise le fichier de configuration f pour le journaliseur

options de traitement

  -p   --pstate  [f]ilename: chaîne
         traite en utilisant le fichier d'état de présentation
  -c   --config  [f]ilename: chaîne
         traite en utilisant les paramètres du fichier de configuration
  -f   --frame  [f]rame: entier
         traite en utilisant l'image de trame f (par défaut : 1)

format de sortie

  -D   --pgm
         enregistre l'image au format PGM (par défaut)
  +D   --dicom
         enregistre l'image comme capture secondaire DICOM

options de sortie

  +S   --save-pstate  [f]ilename: chaîne
         enregistre l'état de présentation dans un fichier

NOTES

Limitations

Veuillez noter que l'outil dcmp2pgm ne rend pas tous les aspects définis par l'objet Grayscale Softcopy Presentation State (GSPS), mais seulement ceux qui sont pris en charge par les classes DCMTK sous-jacentes. En particulier, les annotations textuelles et graphiques ne seront pas visibles dans l'image de sortie. La raison est que ces aspects d'un objet GSPS sont généralement rendus par DICOMscope, l'interface graphique utilisateur placée au-dessus des classes DCMTK associées et écrite en Java.

De plus, les concepts introduits après la définition initiale de l'IOD GSPS (voir Supplement 33) sont ignorés. Cela inclut le Supplement 120 avec ses fonctionnalités étendues comme par exemple les graphiques composés (Compound Graphics).

JOURNALISATION

Le niveau de sortie de journalisation des différentes lignes de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seules les erreurs et les avertissements sont écrits sur le flux d'erreur standard. En utilisant l'option --verbose des messages informatifs tels que les détails du traitement sont également rapportés. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet seules les erreurs fatales sont rapportées. Dans de tels événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, voir la documentation du module "oflog".

Si la sortie de journalisation doit être écrite dans un fichier (avec rotation des journaux en option), dans syslog (Unix) ou dans le journal des événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets enclos des valeurs facultatives (0-1), trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie de 0 à n valeurs.

Les options de ligne de commande sont distinguées des paramètres par un signe '+' ou '-' en tête, respectivement. Habituellement, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si des options sont mutuellement exclusives, la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

De plus, un ou plusieurs fichiers de commande peuvent être spécifiés en utilisant le signe '@' comme préfixe du nom de fichier (par exemple @command.txt). Un tel argument de commande est remplacé par le contenu du fichier de texte correspondant (plusieurs espaces blancs sont traités comme un seul séparateur sauf s'ils apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite des lignes de commande longues et déroutantes (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

ENVIRONNEMENT

L'utilitaire dcmp2pgm tentera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH . Par défaut, c'est-à-dire si la variable DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé sauf si le dictionnaire est intégré à l'application (par défaut sous Windows).

Le comportement par défaut devrait être préféré et la variable DCMDICTPATH d'environnement n'est utilisée que lorsque des dictionnaires de données alternatifs sont nécessaires. La variable DCMDICTPATH d'environnement a le même format que la variable PATH du shell Unix en ce sens qu'un deux-points (":") sépare les entrées. Sur les systèmes Windows, un point-virgule (";") est utilisé comme séparateur. Le code du dictionnaire de données tentera de charger chaque fichier spécifié dans la variable DCMDICTPATH d'environnement. C'est une erreur si aucun dictionnaire de données ne peut être chargé.
