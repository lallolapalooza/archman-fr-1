SYNOPSI

DESCRIPTIO

N

L'utilitaire dcm2json convertit le contenu d'un fichier DICOM (format de fichier ou jeu de données brut) en JSON (JavaScript Object Notation). La sortie fait référence au « DICOM JSON Model », qui se trouve dans la partie 18, section F, de la norme

DICOM.

Si dcm2json lit un jeu de données brut (données DICOM sans en-tête méta de format de fichier), il essaiera de deviner la syntaxe de transfert en examinant les premiers octets du fichier. Il n'est pas toujours possible de deviner correctement la syntaxe de transfert et il est préférable de convertir un jeu de données en format de fichier chaque fois que c'est possible (en utilisant l'utilitaire dcmconv). Il est également possible d'utiliser les options -f et -t[ieb] pour forcer dcm2json à lire un jeu de données avec

une syntaxe de tran
sfert particulière.

Données

volumineuses

Les données binaires, c'est-à-dire les valeurs d'éléments DICOM dont les représentations de valeur (VR) sont OB ou OW, ainsi que les valeu

rs OD, OF, OL, OV et UN, sont toujours écrites sous la forme « InlineBinary » (encodage base64) dans la sortie JSON. Une version future d
e cet outil pourrait éventuellement utiliser un « BulkDataURI » à la place, c'est-à-dire l'URL WADO-RS d'un élément de données volumineus
es contenant la valeur de l'élément. Cela serait particulièrement utile pour de grandes quantités de données, comme les données de pixels.

REMARQUE

S

Nombres sous forme de

chaînes

La norme DICOM permet à certaines représentations de valeur numériques DICOM, DS, IS, SV et UV, d'être converties soit en nombre JSON, soit en chaîne JSON. dcm2json convertit les valeurs DS et IS en nombres JSON si elles sont des chaînes décimales ou entières valides, et en chaînes si elles contiennent un caractère illégal. dcm2json convertit les valeurs SV et UV en nombres s'ils ne dépassent pas 9007199254740991ll et ne sont pas inférieurs à -9007199254740991ll, et en cha

înes de caractères dans le cas contraire. Bien que la spécification JSON autorise des nombres plus grands, il s'agit des entiers les
plus grands que JavaScript puisse gérer. Par conséquent, de nombreux analyseurs JSON ne peuvent pas traiter de nombres plus grands.

Encodage des

caractères

Comme l'exige l'encodage JSON DICOM, dcm2json crée toujours une sortie en encodage Unicode UTF-8 et convertit les jeux de données DICOM en co

nséquence. Si cela n'est pas possible, par exemple parce
que DCMTK a été compilé sans prise en charge de la c
onversion de jeu de caractères, une erreur est renvoyée.

JOURNALISATI

ON

Le niveau de journalisation des différentes lignes de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seules les erreurs et les avertissements sont écrits sur le flux d'erreur standard. En utilisant l'option --verbose, des messages informatifs tels que les détails du traitement sont également rapportés. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet, seules les erreurs fatales sont rapportées. En cas d'événement d'erreur très grave, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, voir la documentation du module « oflog »

.

Si la sortie de journalisation doit être écrite dans un fichier (avec rotation éventuelle des fichiers journaux), dans syslog (Unix) ou dans le journal des événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/l

ogger
.cfg.

LIGNE DE

COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets enclos des valeurs facultatives (0-1), trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie de 0 à n

valeurs.

Les options de ligne de commande se distinguent des paramètres par un signe '+' ou '-' en tête, respectivement. En général, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si des options sont mutuellement exclusives, la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix

courants.

En outre, un ou plusieurs fichiers de commande peuvent être spécifiés en utilisant un signe '@' comme préfixe du nom de fichier (par exemple @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (plusieurs espaces blancs sont traités comme un seul séparateur s'ils n'apparaissent pas entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite des lignes de commande longues et déroutantes (un exemple est fourni dans le fichier <datadir>/du

mppat
.txt).

ENVIRONNEMEN

T

L'utilitaire dcm2json tentera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH. Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé, sauf si le dictionnaire est intégré à l'application (par défaut sous Windows)

.

Le comportement par défaut doit être préféré et la variable d'environnement DCMDICTPATH n'est utilisée que lorsque des dictionnaires de données alternatifs sont nécessaires. La variable d'environnement DCMDICTPATH a le même format que la variable PATH du shell Unix, à savoir qu'un deux-points (« : ») sépare les entrées. Sur les systèmes Windows, un point-virgule (« ; ») est utilisé comme séparateur. Le code du dictionnaire de données tentera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH. C'est une erreur si aucun dictionnaire de données ne peut être

chargé.

L'utilitaire dcm2json tentera de charger les tables de correspondance de jeu de caractères. Cela se produit lorsque DCMTK a été compilé avec la bibliothèque oficonv (ce qui est le cas par défaut) et que les tables de correspondance ne sont pas intégrées à la bibliothèque (par défaut lorsque DCMTK utilise des bibliothèques partagées)

.

Les fichiers de table de correspondance sont attendus dans le <datadir> de DCMTK. La variable d'environnement DCMICONVPATH peut être utilisée pour spécifier un emplacement différent. Si un emplacement diffé

rent est spécifié, ces tables de correspondance
remplacent également toutes les tables intégrées.
