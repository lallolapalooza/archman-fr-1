affiche le contenu d'un fichier DICOM
    (format de fichier ou jeu de données brut) sur stdout sous forme textuelle. Les attributs ayant

S

i

dcmdump lit un jeu de données brut (données DICOM sans en-tête méta de format de fichier), il essaiera de deviner la syntaxe de transfert en examinant les premiers octets du fichier. Il n'est pas toujours possible de deviner correctement la syntaxe de transfert et il est préférable de convertir un jeu de données en format de fichier chaque fois que c'est possible (en utilisant

l'utilitaire

dcmconv [[25]]). Il est également possible d'utiliser les options -f et -t[ieb] pour forcer dcmd

u
mp

à lire un jeu de données avec une syntaxe de transfert

particulière.

JOURNALISATION Le niveau de sortie de journalisation des différentes outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seules les erreurs et les avertissements sont écrits sur le flux d'erreur standard. En utilisant l'option --verbose [[10]], des messages informatifs tels que les détails de traitement sont également rapportés. L'option --debu

g

peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level . En mode --quiet [[16]], seules les erreurs fatales sont rapportées. Dans de tels événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, voir la documentation

du
module "oflog".

Si la sortie de journalisation doit être écrite dans un fichier (avec rotation optionnelle des journaux), dans syslog (Unix) ou dans le journal des événements (Windows)

, l'option

--log-confi

g

peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni

dans

<etcdir>/logger.cfg . LIGNE DE COMMANDE Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets enclos des valeurs facultatives (0-1), trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie de 0 à n valeurs. Les options de ligne de commande sont distinguées des paramètres par un signe '+' ou '-' en tête, respectivement. Habituellement, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si des options sont mutuellement exclusives, l'apparence la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation

standard des
shells Unix courants.

De plus, un ou plusieurs fichiers de commande peuvent être spécifiés en utilisant un signe '@' comme préfixe au nom de fichier

(par exemple

@command.txt ). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (plusieurs espaces blancs sont traités comme un seul séparateur sauf s'ils apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite des lignes de commande longues et déroutantes (un exemple est fourni dans le fichier <datadir>/dumppat.txt ). Le comportement par défaut doit être préféré et la variable d'environnement DCMDICTPATH n'est utilisée que lorsque des dictionnaires de données
