NOM

dcmconv - Convertit l'encodage d'un fichier DICOM

SYNOPSIS

dcmconv [options] dcmfile-in dcmfile-out

DESCRIPTION

L'utilitaire dcmconv lit un fichier DICOM (dcmfile-in), effectue une conversion d'encodage et écrit les données converties dans un fichier de sortie (dcmfile-out).

PARAMÈTRES

dcmfile-in   Nom du fichier DICOM d'entrée à convertir ("-" pour stdin)
dcmfile-out  Nom du fichier DICOM de sortie ("-" pour stdout)

OPTIONS

options générales

  -h   --help
         affiche ce texte d'aide et quitte
       --version
         affiche les informations de version et quitte
       --arguments
         affiche les arguments de la ligne de commande étendus
  -q   --quiet
         mode silencieux, n'affiche ni avertissements ni erreurs
  -v   --verbose
         mode verbeux, affiche les détails du traitement
  -d   --debug
         mode débogage, affiche les informations de débogage
  -l   --log-level  [l]evel: constante de chaîne
         (fatal, error, warn, info, debug, trace)
         utilise le niveau l pour le journal
  -l   --log-config  [f]ilename: chaîne
         utilise le fichier de configuration f pour le journal

options d'entrée

format du fichier d'entrée :
  +f   --read-file
         lit le format de fichier ou le jeu de données (par défaut)
  +fo  --read-file-only
         lit uniquement le format de fichier
  -f   --read-dataset
         lit le jeu de données sans méta-informations de fichier
syntaxe de transfert d'entrée :
  -t=  --read-xfer-auto
         utilise la reconnaissance de la syntaxe de transfert (par défaut)
  -td  --read-xfer-detect
         ignore la syntaxe de transfert spécifiée dans l'en-tête méta du fichier
  -te  --read-xfer-little
         lit avec la syntaxe de transfert VR explicite little endian
  -tb  --read-xfer-big
         lit avec la syntaxe de transfert VR explicite big endian
  -ti  --read-xfer-implicit
         lit avec la syntaxe de transfert VR implicite little endian
analyse des méta-informations de fichier :
  +ml  --use-meta-length
         utilise la longueur de groupe des méta-informations de fichier (par défaut)
  -ml  --ignore-meta-length
         ignore la longueur de groupe des méta-informations de fichier
analyse des attributs de longueur impaire :
  +ao  --accept-odd-length
         accepte les attributs de longueur impaire (par défaut)
  +ae  --assume-even-length
         suppose que la longueur réelle est plus grande d'un octet
traitement du VR explicite :
  +ev  --use-explicit-vr
         utilise le VR explicite du jeu de données (par défaut)
  -ev  --ignore-explicit-vr
         ignore le VR explicite (préfère le dictionnaire de données)
traitement des VR non standard :
  +vr  --treat-as-unknown
         traite les VR non standard comme inconnus (par défaut)
  -vr  --assume-implicit
         essaie de lire avec la syntaxe de transfert VR implicite little endian
traitement des éléments UN de longueur indéfinie :
  +ui  --enable-cp246
         lit les UN de longueur indéfinie comme VR implicite (par défaut)
  -ui  --disable-cp246
         lit les UN de longueur indéfinie comme VR explicite
traitement des éléments UN de longueur définie :
  -uc  --retain-un
         conserve les éléments comme UN (par défaut)
  +uc  --convert-un
         convertit en VR réel si connu
traitement des éléments privés de longueur maximale (VR implicite) :
  -sq  --maxlength-dict
         lit comme défini dans le dictionnaire (par défaut)
  +sq  --maxlength-seq
         lit comme séquence avec longueur indéfinie
traitement des éléments de délimitation incorrects :
  -rd  --use-delim-items
         utilise les éléments de délimitation du jeu de données (par défaut)
  +rd  --replace-wrong-delim
         remplace les éléments de délimitation de séquence/élément incorrects
traitement des éléments OB/OW de longueur indéfinie illégaux :
  -oi  --illegal-obow-rej
         rejette le jeu de données contenant un élément illégal (par défaut)
  +oi  --illegal-obow-conv
         convertit l'élément OB/OW de longueur indéfinie en SQ
traitement de la séquence VOI LUT avec VR OW et longueur explicite :
  -vi  --illegal-voi-rej
         rejette le jeu de données contenant un VOI LUT illégal (par défaut)
  +vi  --illegal-voi-conv
         convertit le VOI LUT illégal en SQ
traitement des données de pixel de longueur explicite pour les syntaxes de transfert encapsulées :
  -pe  --abort-expl-pixdata
         interrompt en cas de données de pixel de longueur explicite (par défaut)
  +pe  --use-expl-pixdata
         utilise les données de pixel de longueur explicite
traitement général des erreurs d'analyse :
  +Ep  --ignore-parse-errors
         essaie de récupérer des erreurs d'analyse
  -Ep  --handle-parse-errors
         traite les erreurs d'analyse et arrête l'analyse (par défaut)
autres options d'analyse :
  +st  --stop-after-elem  [t]ag: "gggg,eeee" ou nom de dictionnaire
         arrête l'analyse après l'élément spécifié par t
correction automatique des données :
  +dc  --enable-correction
         active la correction automatique des données (par défaut)
  -dc  --disable-correction
         désactive la correction automatique des données
format de flux de bits pour l'entrée décompressée :
  +bd  --bitstream-deflated
         attend un flux de bits décompressé (par défaut)
  +bz  --bitstream-zlib
         attend un flux de bits zlib décompressé

options de traitement

jeu de caractères spécifique :
  # les options suivantes nécessitent la prise en charge d'une bibliothèque
  # d'encodage de caractères sous-jacente (voir la sortie de --version pour
  # savoir laquelle est disponible)
  +U8  --convert-to-utf8
         convertit toutes les valeurs d'éléments affectées par le Jeu de
         Caractères Spécifique (0008,0005) en UTF-8
  +L1  --convert-to-latin1
         convertit les valeurs d'éléments affectées en ISO 8859-1
  +A7  --convert-to-ascii
         convertit les valeurs d'éléments affectées en ASCII 7 bits
  +C   --convert-to-charset  [c]harset: chaîne
         convertit les valeurs d'éléments affectées en le jeu de caractères
         spécifié par le terme défini DICOM c
  -Ct  --transliterate
         essaie d'approcher les caractères qui ne peuvent être représentés
         par des caractères d'apparence similaire
  -Cd  --discard-illegal
         supprime les caractères qui ne peuvent être représentés dans le jeu
         de caractères de destination
autres options de traitement :
  -ig  --no-invalid-groups
         supprime les éléments avec un numéro de groupe invalide

options de sortie

format du fichier de sortie :
  +Fm  --write-new-meta-info
         écrit le format de fichier avec de nouvelles méta-informations (par défaut)
  +F   --write-file
         écrit le format de fichier
  -F   --write-dataset
         écrit le jeu de données sans méta-informations de fichier
syntaxe de transfert de sortie :
  +t=  --write-xfer-same
         écrit avec la même syntaxe de transfert que l'entrée (par défaut)
  +te  --write-xfer-little
         écrit avec la syntaxe de transfert VR explicite little endian
  +tb  --write-xfer-big
         écrit avec la syntaxe de transfert VR explicite big endian
  +ti  --write-xfer-implicit
         écrit avec la syntaxe de transfert VR implicite little endian
  +td  --write-xfer-deflated
         écrit avec la syntaxe de transfert VR explicite little endian décompressée
  +tg  --write-xfer-ge
         écrit la syntaxe de transfert GE privée VR implicite little endian
         avec données de pixel big endian (non standard)
représentations de valeurs post-1993 :
  +u   --enable-new-vr
         active la prise en charge des nouveaux VR (UN/UT) (par défaut)
  -u   --disable-new-vr
         désactive la prise en charge des nouveaux VR, convertit en OB
encodage de la longueur de groupe :
  +g=  --group-length-recalc
         recalcule les longueurs de groupe si présentes (par défaut)
  +g   --group-length-create
         écrit toujours avec les éléments de longueur de groupe
  -g   --group-length-remove
         écrit toujours sans les éléments de longueur de groupe
encodage de la longueur dans les séquences et les éléments :
  +e   --length-explicit
         écrit avec des longueurs explicites (par défaut)
  -e   --length-undefined
         écrit avec des longueurs indéfinies
  +eo  --write-oversized
         écrit les séquences et éléments de longueur explicite surdimensionnés
         avec longueur indéfinie (par défaut)
  -eo  --abort-oversized
         interrompt en cas de séquences/éléments explicites surdimensionnés
remplissage de fin de jeu de données (pas avec --write-dataset) :
  -p=  --padding-retain
         ne change pas le remplissage (par défaut si pas --write-dataset)
  -p   --padding-off
         pas de remplissage (implicite si --write-dataset)
  +p   --padding-create  [f]ile-pad [i]tem-pad: entier
         aligne le fichier sur un multiple de f octets
         et les éléments sur un multiple de i octets
niveau de compression deflate (uniquement avec --write-xfer-deflated) :
  +cl  --compression-level  [l]evel: entier (par défaut : 6)
         0=non compressé, 1=le plus rapide, 9=meilleure compression

JOURNALISATION

Le niveau de sortie de journalisation des différentes outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seules les erreurs et les avertissements sont écrits sur le flux d'erreur standard. En utilisant l'option --verbose les messages informatifs tels que les détails de traitement sont également rapportés. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet seules les erreurs fatales sont rapportées. Dans de tels événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, voir la documentation du module "oflog".

Si la sortie de journalisation doit être écrite dans un fichier (avec rotation optionnelle des fichiers journal), dans syslog (Unix) ou dans le journal des événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet égalementpermet de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un fichier de configuration d'exemple est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets enclos des valeurs facultatives (0-1), trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie de 0 à n valeurs.

Les options de ligne de commande se distinguent des paramètres par un signe '+' ou '-' en tête, respectivement. Habituellement, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si des options sont mutuellement exclusives, la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

De plus, un ou plusieurs fichiers de commande peuvent être spécifiés en utilisant le signe '@' comme préfixe du nom de fichier (par exemple @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (plusieurs espaces blancs sont traités comme un seul séparateur à moins qu'ils n'apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite des lignes de commande longues et déroutantes (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

ENVIRONNEMENT

L'utilitaire dcmconv tentera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH . Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé, à moins que le dictionnaire ne soit intégré à l'application (par défaut sous Windows).

Le comportement par défaut devrait être préféré et la variable d'environnement DCMDICTPATH ne devrait être utilisée que lorsque des dictionnaires de données alternatifs sont nécessaires. La variable d'environnement DCMDICTPATH a le même format que la variable PATH du shell Unix, un deux-points (« : ») séparant les entrées. Sur les systèmes Windows, un point-virgule (« ; ») est utilisé comme séparateur. Le code du dictionnaire de données tentera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH . C'est une erreur si aucun dictionnaire de données ne peut être chargé.

Selon les options de ligne de commande spécifiées, l'utilitaire dcmconv tentera de charger des tables de correspondance d'ensembles de caractères. Cela se produit lorsque DCMTK a été compilé avec la bibliothèque oficonv (ce qui est le cas par défaut) et que les tables de correspondance ne sont pas intégrées à la bibliothèque (par défaut lorsque DCMTK utilise des bibliothèques partagées).

Les fichiers de table de correspondance sont attendus dans le <datadir>de DCMTK. La variable d'environnement DCMICONVPATH peut être utilisée pour spécifier un emplacement différent. Si un emplacement différent est spécifié, ces tables de correspondance remplacent également toutes les tables intégrées.
