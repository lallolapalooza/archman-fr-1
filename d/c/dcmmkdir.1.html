NOM

dcmmkdir - Créer un fichier DICOMDIR

SYNOPSIS

dcmmkdir [options] [dcmfile-in...]

DESCRIPTION

L'utilitaire dcmmkdir crée un fichier DICOMDIR à partir des fichiers DICOM référencés spécifiés, conformément aux profils d'application de stockage sur média de la partie 11 de la norme DICOM.

Actuellement, les profils suivants sont pris en charge (d'autres pourraient être ajoutés plus tard) :

  • Interchange général sur CD-R (STD-GEN-CD)
  • Interchange général sur média DVD-RAM (STD-GEN-DVD-RAM)
  • Interchange général sur média BD (STD-GEN-BD)
  • Interchange général DVD avec JPEG (STD-GEN-DVD-JPEG)
  • Interchange général DVD avec JPEG 2000 (STD-GEN-DVD-J2K)
  • Interchange général BD avec JPEG (STD-GEN-BD-JPEG)
  • Interchange général BD avec JPEG 2000 (STD-GEN-BD-J2K)
  • Interchange général BD avec MPEG2 MP@ML (STD-GEN-BD-MPEG2-MPML)
  • Interchange général BD avec MPEG2 MP@HL (STD-GEN-BD-MPEG2-MPHL)
  • Interchange général BD avec MPEG-4 AVC/H.264 HiP@Niveau4.1 (STD-GEN-BD-MPEG4-HPLV41)
  • Interchange général BD avec MPEG-4 AVC/H.264 BD-Compatible HiP@Niveau4.1 (STD-GEN-BD-MPEG4-HPLV41BD)
  • Interchange général BD avec MPEG-4 AVC/H.264 HiP@Niveau4.2 pour vidéo 2D (STD-GEN-BD-MPEG4-HPLV42-2D)
  • Interchange général BD avec MPEG-4 AVC/H.264 HiP@Niveau4.2 pour vidéo 3D (STD-GEN-BD-MPEG4-HPLV42-3D)
  • Interchange général BD avec MPEG-4 AVC/H.264 Stereo HiP@Niveau4.2 (STD-GEN-BD-MPEG4-SHPLV42)
  • Interchange général USB et mémoire flash avec JPEG (STD-GEN-USB/MMC/CF/SD-JPEG)
  • Interchange général USB et mémoire flash avec JPEG 2000 (STD-GEN-USB/MMC/CF/SD-J2K)
  • Interchange général MIME (STD-GEN-MIME)
  • Interchange DVD avec MPEG2 MP@ML (STD-DVD-MPEG2-MPML)
  • Études angiographiques radiologiques cardiaques de base sur média CD-R (STD-XABC-CD)
  • Études angiographiques radiologiques 1024 sur média CD-R (STD-XA1K-CD)
  • Études angiographiques radiologiques 1024 sur média DVD (STD-XA1K-DVD)
  • Interchange de radiographies dentaires (STD-DEN-CD)
  • Études CT/IRM sur divers médias (STD-CTMR-xxxx)
  • Échographie image unique pour affichage d'image (STD-US-ID-SF-xxxx)
  • Échographie image unique avec calibration spatiale (STD-US-SC-SF-xxxx)
  • Échographie image unique avec calibration combinée (STD-US-CC-SF-xxxx)
  • Échographie image unique et multi-images pour affichage d'image (STD-US-ID-MF-xxxx)
  • Échographie image unique et multi-images avec calibration spatiale (STD-US-SC-MF-xxxx)
  • Échographie image unique et multi-images avec calibration combinée (STD-US-CC-MF-xxxx)
  • Interchange ECG 12 dérivations sur disquette (STD-WVFM-ECG-FD)
  • Interchange de formes d'onde hémodynamiques sur disquette (STD-WVFM-HD-FD)

Cet outil étend dcmgpdir qui ne peut créer que des fichiers DICOMDIR de type usage général. Le comportement par défaut de dcmmkdir (avec --general-purpose) est équivalent à celui de dcmgpdir.

dcmfile-in  fichier DICOM référencé (ou répertoire à analyser)

NOTES


Tous les fichiers spécifiés sur la ligne de commande (ou découverts
    en examinant récursivement le contenu des répertoires avec l'option
    +r) sont d'abord évalués pour leur compatibilité avec le profil
    d'application Media Storage spécifié (Partie 11). Seuls les fichiers appropriés
    encodés à l'aide de l'une des syntaxes de transfert autorisées seront acceptés.
    Les fichiers dont les noms sont invalides seront rejetés (les règles peuvent
    être assouplies via l'option +m). Les fichiers manquant d'attributs
    requis seront rejetés (l'option +I peut assouplir ce comportement).


Un fichier DICOMDIR ne sera construit que si tous les
    fichiers ont passé les tests initiaux.


L'utilitaire dcmmkdir permet également d'ajouter de nouvelles
    entrées et de mettre à jour des entrées existantes dans un fichier
    DICOMDIR. En utilisant l'option +A, de nouvelles entrées sont
    uniquement ajoutées au DICOMDIR, c'est-à-dire que les enregistrements existants
    comme ceux pour les informations du PATIENT ne sont pas mis à jour. En utilisant
    l'option +U, les enregistrements existants sont également mis à jour
    conformément aux informations trouvées dans les fichiers DICOM référencés.
    Veuillez noter que ce processus de mise à jour peut être plus lent que le simple
    ajout de nouvelles entrées. Cependant, il garantit que des informations
    supplémentaires requises pour le profil d'application sélectionné sont également
    ajoutées aux enregistrements existants.


Le support des images d'icônes est actuellement limité aux images
    monochromes. Cela pourrait changer à l'avenir. Jusque-là, les images couleur
    sont automatiquement converties en mode niveaux de gris. La taille de l'icône est
    de 128*128 pixels pour les profils cardiaques (conformément aux exigences de la
    norme DICOM) et de 64*64 pour tous les autres.




Scanning   Directories


L'ajout de fichiers à partir de répertoires est possible en utilisant
    l'option --recurse. Si aucun autre paramètre de ligne de commande n'est
    fourni, le répertoire spécifié par l'option --input-directory (par
    défaut : répertoire courant) est parcouru pour y trouver des fichiers. Si des
    paramètres sont fournis, ils peuvent spécifier un nom de fichier ou de
    répertoire; le répertoire d'entrée est toujours préfixé. Si les fichiers des
    répertoires fournis doivent être sélectionnés selon un modèle de nom
    spécifique (par exemple, en utilisant la correspondance de motifs), l'option
    --pattern doit être utilisée. Veuillez noter que ce modèle de fichier
    s'applique uniquement aux fichiers dans les répertoires parcourus, et, si
    d'autres modèles sont spécifiés sur la ligne de commande en dehors de
    l'option --input-directory (par exemple, pour sélectionner d'autres
    fichiers), ceux-ci ne s'appliquent pas aux répertoires spécifiés.








LOGGING


Le niveau de sortie de journalisation des différents outils en ligne de
    commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur.
    Par défaut, seules les erreurs et les avertissements sont écrits sur le flux
    d'erreurs standard. En utilisant l'option --verbose, des messages
    informatifs comme les détails de traitement sont également rapportés. L'option
    --debug peut être utilisée pour obtenir plus de détails sur l'activité
    interne, par exemple à des fins de débogage. D'autres niveaux de journalisation
    peuvent être sélectionnés à l'aide de l'option --log-level. En mode
    --quiet, seuls les erreurs fatales sont rapportées. Dans ces cas d'erreurs
    très graves, l'application se terminera généralement. Pour plus de détails sur
    les différents niveaux de journalisation, voir la documentation du module
    « oflog ».


Dans le cas où la sortie de journalisation devrait être écrite dans un
    fichier (avec rotation optionnelle du fichier journal), vers syslog (Unix) ou
    le journal des événements (Windows), l'option --log-config peut être
    utilisée. Ce fichier de configuration permet également de diriger uniquement
    certains messages vers un flux de sortie particulier et de filtrer certains
    messages en fonction du module ou de l'application où ils sont générés. Un
    exemple de fichier de configuration est fourni dans
    <etcdir>/logger.cfg.






COMMAND   LINE


Tous les outils en ligne de commande utilisent la notation suivante pour les
    paramètres : les crochets encadrent les valeurs optionnelles (0-1), trois points
    suspendus indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison
    des deux signifie 0 à n valeurs.


Les options de la ligne de commande sont distinguées des paramètres par un
    signe '+' ou '-' respectivement. Habituellement, l'ordre et la position des
    options de la ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent
    apparaître n'importe où). Cependant, si les options sont mutuellement exclusives,
    l'apparition la plus à droite est utilisée. Ce comportement est conforme aux
    règles d'évaluation standard des shells Unix courants.


De plus, un ou plusieurs fichiers de commandes peuvent être spécifiés en
    utilisant un signe '@' comme préfixe du nom de fichier (par exemple,
    @command.txt). Un tel argument de commande est remplacé par le contenu du
    fichier texte correspondant (les espaces multiples sont traités comme un seul
    séparateur sauf s'ils apparaissent entre deux guillemets) avant toute autre
    évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un
    autre fichier de commande. Cette approche simple mais efficace permet de résumer
    les combinaisons courantes d'options/paramètres et évite les lignes de commande
    trop longues et confuses (un exemple est fourni dans le fichier
    <datadir>/dumppat.txt).






ENVIRONMENT


L'utilitaire dcmmkdir tentera de charger les dictionnaires de données
    DICOM spécifiés dans la variable d'environnement DCMDICTPATH. Par défaut,
    c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie,
    le fichier <datadir>/dicom.dic sera chargé à moins que le
    dictionnaire ne soit intégré à l'application (par défaut pour Windows).


Le comportement par défaut doit être privilégié et la variable d'environnement
    DCMDICTPATH ne doit être utilisée que lorsque des dictionnaires de données
    alternatifs sont requis. La variable d'environnement DCMDICTPATH a le même
    format que la variable PATH du shell Unix, c'est-à-dire qu'un deux-points
    (":") sépare les entrées. Sur les systèmes Windows, un point-virgule
    (";") est utilisé comme séparateur. Le code du dictionnaire de données
    tentera de charger chaque fichier spécifié dans la variable d'environnement
    DCMDICTPATH. Une erreur se produit si aucun dictionnaire de données ne peut
    être chargé.
