NOM

dcmprscu - Spouleur d'impression pour la visionneuse d'état de présentation

SYNOPSIS

dcmprscu [options] [dcmfile-in...]

DESCRIPTION

L'utilitaire dcmprscu implémente la classe de service de gestion d'impression en niveaux de gris de base DICOM en tant qu'SCU. Il prend également en charge les classes SOP facultatives de boîte d'annotation de base et de LUT de présentation. L'utilitaire est destiné à être utilisé dans la visionneuse DICOMscope.

L'utilitaire dcmprscu prend des travaux d'impression complets constitués d'un objet d'impression stockée et d'un ou plusieurs objets de copie intermédiaire en niveaux de gris et les spoule vers l'imprimante. Aucune tentative n'est faite pour vérifier si les attributs définis dans l'objet d'impression stockée sont pris en charge par le SCP d'impression. Cependant, le spouleur d'impression n'essaiera pas d'utiliser les services facultatifs d'annotation ou de LUT de présentation s'ils ne sont pas négociés avec succès avec le SCP d'impression.

L'utilitaire dcmprscu lit les caractéristiques de l'imprimante avec laquelle communiquer depuis le fichier de configuration. Selon la prise en charge de la LUT de présentation par l'imprimante, toute LUT de présentation présente dans le travail d'impression sera rendue dans les images de copie intermédiaire avant d'être spoulée vers l'imprimante si nécessaire. Si l'imprimante ne prend pas en charge la transmission d'images avec 12 bits/pixel (selon le fichier de configuration), les images de copie intermédiaire en niveaux de gris sont sous-échantillonnées à 8 bits/pixel avant la transmission à l'imprimante.

L'utilitaire dcmprscu peut être exécuté soit en « mode imprimante », auquel cas le nom de fichier d'un objet d'impression stockée doit être passé, soit en « mode spouleur », auquel cas des commandes sont lues périodiquement depuis un répertoire de spoule.

PARAMÈTRES

dcmfile-in   fichier(s) d'impression stockée à spouler ("-" pour stdin)

OPTIONS

options générales

  -h   --help
         afficher ce texte d'aide et quitter
       --version
         afficher les informations de version et quitter
       --arguments
         afficher les arguments de la ligne de commande développés
  -q   --quiet
         mode silencieux, ne pas afficher les avertissements et les erreurs
  -v   --verbose
         mode bavard, afficher les détails du traitement
  -d   --debug
         mode débogage, afficher les informations de débogage
  -ll  --log-level  [l]evel: constante de chaîne
         (fatal, error, warn, info, debug, trace)
         utiliser le niveau l pour le journaliseur
  -lc  --log-config  [f]ilename: chaîne
         utiliser le fichier de configuration f pour le journaliseur

options d'impression

       --noprint
         ne pas créer d'impression (pas de n-action-rq)
       --session-print
         envoyer le n-action-rq de session de film (au lieu de boîte de film)
       --monochrome1
         transmettre les images en niveaux de gris de base en MONOCHROME1

options de mode

  +p   --print
         mode imprimante, imprimer le(s) fichier(s) et terminer (par défaut)
  +s   --spool  [n]ame: chaîne
         mode spouleur, utiliser le préfixe de tâche n

options de traitement

  -c   --config  [f]ilename: chaîne
         traiter en utilisant les paramètres du fichier de configuration
  -p   --printer  [n]ame: chaîne (par défaut : 1re imprimante dans le fichier cfg)
         sélectionner l'imprimante avec l'identifiant n depuis le fichier cfg
  +d   --dump
         afficher tous les messages DIMSE

options du spouleur (uniquement avec --spool)

       --sleep  [d]elay: entier (par défaut : 1)
         dormir d secondes entre les vérifications du spouleur

options de session de film de base (pas avec --spool) :

       --copies  [v]alue: entier (1..100, par défaut : 1)
         définir le nombre de copies à v
       --medium-type  [v]alue: chaîne
         définir le type de support à v
       --destination  [v]alue: chaîne
         définir la destination du film à v
       --label  [v]alue: chaîne
         définir l'étiquette de la session de film à v
       --priority  [v]alue: chaîne
         définir la priorité d'impression à v
       --owner  [v]alue: chaîne
         définir l'identifiant du propriétaire de la session de film à v

JOURNALISATION

Le niveau de sortie de journalisation des différentes outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seules les erreurs et les avertissements sont écrits sur le flux d'erreur standard. En utilisant l'option --verbose les messages informatifs tels que les détails du traitement sont également rapportés. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet seules les erreurs fatales sont rapportées. Dans de tels événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, voir la documentation du module « oflog ».

Si la sortie de journalisation doit être écrite dans un fichier (avec rotation optionnelle des journaux), dans syslog (Unix) ou dans le journal d'événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets enclos des valeurs facultatives (0-1), trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie de 0 à n valeurs.

Les options de ligne de commande sont distinguées des paramètres par un signe '+' ou '-' en tête, respectivement. Habituellement, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si des options sont mutuellement exclusives, l'apparence la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

De plus, un ou plusieurs fichiers de commande peuvent être spécifiés en utilisant le signe '@' comme préfixe du nom de fichier (par exemple @command.txt). Un tel argument de commande est remplacé par le contenu du fichier de texte correspondant (plusieurs espaces blancs sont traités comme un seul séparateur sauf s'ils apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite des lignes de commande longues et déroutantes (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

ENVIRONNEMENT

L'utilitaire dcmprscu essaiera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH . Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé à moins que le dictionnaire ne soit intégré à l'application (par défaut sur Windows).

Le comportement par défaut devrait être préféré et la variable d'environnement DCMDICTPATH ne devrait être utilisée que lorsque des dictionnaires de données alternatifs sont requis. La variable d'environnement DCMDICTPATH a le même format que la variable PATH du shell Unix en ce sens que deux-points (« : ») séparent les entrées. Sur les systèmes Windows, un point-virgule (« ; ») est utilisé comme séparateur. Le code du dictionnaire de données essaiera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH . C'est une erreur si aucun dictionnaire de données ne peut être chargé.
