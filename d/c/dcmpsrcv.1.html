NOM

dcmpsrcv - Réception réseau pour le visualiseur d'état de présentation

SYNTAXE

dcmpsrcv [options] fichier-config

DESCRIPTION

L'application dcmpsrcv est appelée par le visualiseur d'état de présentation en niveaux de gris et n'est pas destinée à être appelée manuellement. L'application lit le fichier de configuration commun qui est partagé entre les différents composants du visualiseur et ouvre une socket TCP/IP sur laquelle les requêtes d'association entrantes sont acceptées. L'application lance un processus séparé pour chaque connexion DICOM. Elle prend en charge les mêmes classes SOP de stockage que l'utilitaire storescp en tant que SCP, mais ne prend pas en charge les syntaxes de transfert encapsulées. Les images entrantes sont stockées dans la base de données commune du visualiseur. Voir la déclaration de conformité complète pour plus de détails.

PARAMETRES

fichier-config  fichier de configuration à lire

OPTIONS

options générales

  -h   --help
         affiche ce texte d'aide et quitte
       --version
         affiche les informations de version et quitte
       --arguments
         affiche les arguments étendus de la ligne de commande
  -q   --quiet
         mode silencieux, n'affiche aucun avertissement ni erreur
  -v   --verbose
         mode verbeux, affiche les détails du traitement
  -d   --debug
         mode de débogage, affiche les informations de débogage
  -ll  --log-level  [l]evel: chaîne de caractères
         (fatal, error, warn, info, debug, trace)
         utilise le niveau l de l'enregistreur
  -lc  --log-config  [f]ichier: chaîne de caractères
         utilise le fichier de configuration f pour l'enregistreur
  -t   --terminate
         termine tous les récepteurs en cours d'exécution

ENREGISTREMENT

Le niveau de sortie de l'enregistrement des différents outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seuls les erreurs et les avertissements sont écrits dans le flux d'erreur standard. L'utilisation de l'option --verbose permet également de signaler des messages informatifs tels que les détails du traitement. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux d'enregistrement peuvent être sélectionnés en utilisant l'option --log-level. En mode --quiet, seules les erreurs fatales sont signalées. Dans de tels événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux d'enregistrement, voir la documentation du module "oflog".

Dans le cas où la sortie de l'enregistrement doit être écrite dans un fichier (éventuellement avec rotation des fichiers journaux), vers syslog (Unix) ou le journal des événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets encadrent les valeurs optionnelles (0-1), trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie 0 à n valeurs.

Les options de ligne de commande se distinguent des paramètres par un signe '+' ou '-' respectivement. Habituellement, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si les options sont mutuellement exclusives, l'apparition la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

En outre, un ou plusieurs fichiers de commande peuvent être spécifiés en utilisant un signe '@' comme préfixe du nom de fichier (par exemple, @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (plusieurs espaces sont traités comme un seul séparateur sauf s'ils apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite des lignes de commande longues et confuses (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

ENVIRONNEMENT

L'utilitaire dcmpsrcv tentera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH. Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé, sauf si le dictionnaire est intégré à l'application (par défaut pour Windows).

Le comportement par défaut doit être privilégié et la variable d'environnement DCMDICTPATH utilisée uniquement lorsque des dictionnaires de données alternatifs sont requis. La variable d'environnement DCMDICTPATH a le même format que la variable PATH du shell Unix, où un deux-points (":") sépare les entrées. Sur les systèmes Windows, un point-virgule (";") est utilisé comme séparateur. Le code du dictionnaire de données tentera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH. Une erreur se produit si aucun dictionnaire de données ne peut être chargé.
