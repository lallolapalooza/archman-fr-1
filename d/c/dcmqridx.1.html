NOM

dcmqridx - Enregistre un fichier image DICOM dans un fichier d'index de base de données d'images.

SYNTAXE

dcmqridx [options] index-out [dcmfile-in...]

DESCRIPTION

L'utilitaire dcmqridx enregistre les fichiers image DICOM dans le fichier d'index de base de données utilisé par les applications dcmqrscp et dcmqrti. Aucun fichier image n'est copié. dcmqridx peut également lister le contenu du fichier d'index de base de données.

PARAMETRES

index-out   zone de stockage pour le fichier d'index (répertoire)
dcmfile-in  fichier image DICOM à enregistrer dans le fichier d'index

OPTIONS

  -h   --help
         affiche ce texte d'aide et quitte
       --version
         affiche les informations de version et quitte
       --arguments
         affiche les arguments de ligne de commande développés
  -q   --quiet
         mode silencieux, n'affiche aucun avertissement ni erreur
  -v   --verbose
         mode verbeux, affiche les détails du traitement
  -d   --debug
         mode débogage, affiche les informations de débogage
  -ll  --log-level  [l]evel: chaîne de caractères
         (fatal, error, warn, info, debug, trace)
         utilise le niveau l de l'enregistreur
  -lc  --log-config  [f]ichier: chaîne de caractères
         utilise le fichier de configuration f pour l'enregistreur
  -p   --print
         liste le contenu du fichier d'index de base de données
  -n   --not-new
         définit le statut de l'instance examinée sur 'pas nouveau'

NOTES

dcmqridx tente d'ajouter une référence au fichier d'index de base de données pour chaque fichier image fourni sur la ligne de commande.

dcmqridx désactive le système de quotas du backend de base de données afin qu'aucun fichier image ne soit supprimé.

ENREGISTREMENT DES JOURNAUX

Le niveau de sortie des journaux des différents outils en ligne de commande et bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seuls les erreurs et les avertissements sont écrits dans le flux d'erreur standard. L'utilisation de l'option --verbose permet également de signaler des messages d'information tels que les détails de traitement. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet, seules les erreurs fatales sont signalées. Dans de tels événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, voir la documentation du module "oflog".

Dans le cas où la sortie des journaux doit être écrite dans un fichier (éventuellement avec rotation de fichier journal), vers syslog (Unix) ou le journal des événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets indiquent des valeurs facultatives (0-1), trois points indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie 0 à n valeurs.

Les options en ligne de commande se distinguent des paramètres par un signe '+' ou '-' respectivement. Habituellement, l'ordre et la position des options en ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si des options sont mutuellement exclusives, l'apparition la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

De plus, un ou plusieurs fichiers de commande peuvent être spécifiés en utilisant le signe '@' comme préfixe du nom de fichier (par exemple, @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (plusieurs espaces sont traités comme un seul séparateur sauf s'ils apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite les lignes de commande trop longues et confuses (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

ENVIRONNEMENT

L'utilitaire dcmqridx tentera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH. Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé à moins que le dictionnaire ne soit intégré à l'application (par défaut pour Windows).

Le comportement par défaut doit être privilégié et la variable d'environnement DCMDICTPATH ne doit être utilisée que lorsque des dictionnaires de données alternatifs sont requis. La variable d'environnement DCMDICTPATH a le même format que la variable PATH du shell Unix, en ce sens qu'un deux-points (":") sépare les entrées. Sur les systèmes Windows, un point-virgule (";") est utilisé comme séparateur. Le code du dictionnaire de données tentera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH. C'est une erreur si aucun dictionnaire de données ne peut être chargé.
