NOM

dcmqrscp - Archive d'images DICOM (nœud de test central)

SYNOPSIS

dcmqrscp [options] [port]

DESCRIPTION

L'application Image Central Test Node (dcmqrscp) implémente une archive d'images simple. Elle gère un certain nombre de zones de stockage et permet de stocker des images dans ces zones de stockage à l'aide de la classe de service de stockage DICOM. Elle permet également d'interroger les attributs des images et de récupérer des images à l'aide de la classe de service d'interrogation/récupération DICOM. L'application dcmqrscp implémente également des règles de restriction d'accès pour limiter les opérations à des entités d'application pairs spécifiques.

L'application dcmqrscp est destinée à être utilisée dans des démonstrations DICOM et comme outil de test de compatibilité. En particulier, dcmqrscp supprimera des images si ses restrictions de quota ont été dépassées.

Attention : Notez que le format du fichier binaire dcmqrdb's binaire index.dat a changé le 20130705 en raison d'une correction de bug dans le code correspondant. Un fichier index.dat créé avant cette date ne fonctionnera pas avec le code dcmqrdb compilé après cette date et doit être recréé. Utilisez dcmqridx pour cette tâche ou renvoyez toutes les images au serveur après avoir supprimé tous les anciens fichiers (et créé un nouveau fichier index.dat vide).

NOTES

Opération

dcmqrscp attend qu'une autre application se connecte à l'adresse de présentation (numéro de port) spécifiée dans son fichier de configuration (ou remplacée par une option de ligne de commande). Quand une autre application se connecte, dcmqrscp s'attend à ce qu'elle soit une application DICOM et qu'elle utilise les titres d'AE appelant et appelé spécifiés dans le fichier de configuration de dcmqrscp. dcmqrscp acceptera les associations avec des contextes de présentation pour les classes SOP de la classe de service de vérification, de la classe de service de stockage et de la classe de service de requête/récupération. Les associations seront rejetées ou les contextes de présentation seront refusés si l'application pair n'a pas les droits d'accès appropriés tels que spécifiés par le fichier de configuration de dcmqrscp.

dcmqrscp recevra des images sur les contextes de présentation de la classe de service de stockage, les écrira dans un espace de stockage configurable associé au titre d'AE de la classe, extraira des attributs de ces images et les stockera dans une base de données. dcmqrscp recevra des requêtes de requête et générera des réponses aux requêtes sur les contextes de présentation de la classe de service de requête/récupération. dcmqrscp recevra des requêtes de récupération et générera des réponses de récupération sur les contextes de présentation de la classe de service de requête/récupération. dcmqrscp traitera également les messages C-CANCEL pour interrompre les opérations de requête/récupération.

En fonctionnement normal dcmqrscp ne se terminera jamais, il continuera à attendre de nouvelles associations jusqu'à ce qu'il soit tué.

Configuration

Le programme dcmqrscp utilise le même fichier de configuration que le programme dcmqrti . Consultez la documentation sur la configuration pour plus d'informations.

Contrôle d'accès

Lorsqu'il est compilé sur les plateformes Unix avec la prise en charge des wrappers TCP, le contrôle d'accès basé sur l'hôte peut être activé avec l'option de ligne de commande --access-control . Dans ce cas, les règles de contrôle d'accès définies dans les tables de contrôle d'accès des hôtes du système pour dcmqrscp sont appliquées. Les emplacements par défaut des tables de contrôle d'accès des hôtes sont /etc/hosts.allow et /etc/hosts.deny. Des détails supplémentaires sont décrits dans hosts_access(5).

JOURNALISATION

Le niveau de sortie de journalisation des différentes outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seules les erreurs et les avertissements sont écrits sur le flux d'erreur standard. En utilisant l'option --verbose , des messages informatifs tels que les détails de traitement sont également rapportés. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet , seules les erreurs fatales sont rapportées. Dans de tels événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, consultez la documentation du module "oflog".

Si la sortie de journalisation doit être écrite dans un fichier (avec rotation optionnelle des journaux), dans syslog (Unix) ou dans le journal des événements (Windows) option --log-config peut être utilisé. Ce fichier de configuration permet également de diriger certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets enclos des valeurs facultatives (0-1), trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie de 0 à n valeurs.

Les options de la ligne de commande se distinguent des paramètres par un signe '+' ou '-' en tête, respectivement. Habituellement, l'ordre et la position des options de la ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si des options sont mutuellement exclusives, l'apparence la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

De plus, un ou plusieurs fichiers de commande peuvent être spécifiés en utilisant le signe '@' comme préfixe du nom de fichier (par exemple @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (plusieurs espaces blancs sont traités comme un seul séparateur à moins qu'ils n'apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite des lignes de commande longues et déroutantes (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

ENVIRONNEMENT

L'utilitaire dcmqrscp essaiera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH . Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé, à moins que le dictionnaire ne soit intégré à l'application (par défaut sous Windows).

Le comportement par défaut devrait être préféré et la variable d'environnement DCMDICTPATH n'est utilisée que lorsque des dictionnaires de données alternatifs sont nécessaires. La variable d'environnement DCMDICTPATH a le même format que la variable PATH du shell Unix, un deux-points (":") séparant les entrées. Sur les systèmes Windows, un point-virgule (";") est utilisé comme séparateur. Le code du dictionnaire de données essaiera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH . C'est une erreur si aucun dictionnaire de données ne peut être chargé.

Selon les options de ligne de commande spécifiées, l'utilitaire dcmqrscp essaiera de charger les tables de correspondance de jeu de caractères. Cela se produit lorsque DCMTK a été compilé avec la bibliothèque oficonv (ce qui est le défaut) et que les tables de correspondance ne sont pas intégrées à la bibliothèque (par défaut lorsque DCMTK utilise des bibliothèques partagées).

Les fichiers de table de correspondance sont attendus dans le <datadir>de DCMTK. La variable d'environnement DCMICONVPATH peut être utilisée pour spécifier un emplacement différent. Si un emplacement différent est spécifié, ces tables de correspondance remplacent également toutes les tables intégrées.
