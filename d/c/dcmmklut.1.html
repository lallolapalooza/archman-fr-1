DESCRIPTIO

N

L'utilitaire dcmmklut permet de créer diverses tables de correspondance (LUT) de modalité, de présentation et de VOI DICOM et est destiné à la création d'images de test. L'utilitaire est capable de lire un fichier d'image DICOM existant, de créer une table de correspondance selon les options de ligne de commande, et d'écrire le nouvel objet dans un fichier. Il est également possible de créer un nouvel objet contenant la LUT spécifiée sans lire un fichier d'image DICOM existant. C'est par exemple utile pour stocker simplement différentes tables de correspondance dans une structure de type DICOM. Par défaut, le fichier de sortie est encodé avec la même syntaxe de transfert que celle utilisée pour le fichier d'entrée, mais la syntaxe de transfert peut également être spécifiée comme option de ligne de

commande.

Les données de la LUT peuvent être dérivées de la forme d'une courbe gamma (le facteur gamma par défaut est 1) ou importées depuis un fichier (actuellement, le format MAP de PhotoImpact d'Ulead et un format texte simple sont pris en charge). La largeur d'entrée et de sortie de la LUT peut également être spécifiée dans la plage autorisée par la norme DICOM. L'interpolation de la plage d'entrée est effectuée par un algorithme d'ajustement de courbe

polynomiale.

En plus du fichier de sortie DICOM, les données de la LUT peuvent également être

exportées vers un fichier texte tabulé, ce qui permet une visualisation facile
des courbes avec une application tableur courante (par exemple Microsoft Excel).

JOURNALISATI

ON

Le niveau de sortie de journalisation des différentes outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seules les erreurs et les avertissements sont écrits dans le flux d'erreur standard. En utilisant l'option --verbose, des messages informatifs tels que les détails du traitement sont également rapportés. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet, seules les erreurs fatales sont rapportées. Dans de tels événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, voir la documentation du module

"oflog".

Si la sortie de journalisation doit être écrite dans un fichier (avec rotation optionnelle des journaux), dans syslog (Unix) ou dans le journal d'événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/l

ogger
.cfg.

LIGNE DE

COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets enclos des valeurs optionnelles (0-1), trois points de suite indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie de 0 à n

valeurs.

Les options de ligne de commande se distinguent des paramètres par un signe '+' ou '-' en tête, respectivement. Habituellement, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si des options sont mutuellement exclusives, l'apparence la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix

courants.

De plus, un ou plusieurs fichiers de commandes peuvent être spécifiés en utilisant le signe '@' comme préfixe du nom de fichier (par exemple @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (plusieurs espaces blancs sont traités comme un seul séparateur sauf s'ils apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commandes ne peut pas contenir un autre fichier de commandes. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite des lignes de commande longues et déroutantes (un exemple est fourni dans le fichier <datadir>/du

mppat
.txt).

ENVIRONNEMEN

T

L'utilitaire dcmmklut essaiera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH. Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé, sauf si le dictionnaire est intégré à l'application (par défaut sous Windows)

.

Le comportement par défaut doit être préféré et la variable d'environnement DCMDICTPATH n'est utilisée que lorsque des dictionnaires de données alternatifs sont nécessaires. La variable d'environnement DCMDICTPATH a le même format que la variable PATH du shell Unix, c'est-à-dire qu'un deux-points (":") sépare les entrées. Sur les systèmes Windows, un point-virgule (";") est utilisé comme séparateur. Le code du dictionnaire de données essaiera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH.s une erreur si aucun

dictionnaire de donnée
s ne peut être chargé.
