NOM

dcmscale - Mettre à l'échelle des images DICOM

SYNOPSIS

dcmscale [options] dcmfile-in dcmfile-out

DESCRIPTION

L'utilitaire dcmscale lit une image DICOM, la met à l'échelle selon les paramètres de la ligne de commande et réécrit l'image DICOM. Cet utilitaire ne prend en charge que les images DICOM non compressées et compressées en RLE.

PARAMÈTRES

dcmfile-in   Nom du fichier d'entrée DICOM à mettre à l'échelle ("-" pour stdin)
dcmfile-out  Nom du fichier de sortie DICOM à écrire ("-" pour stdout)

OPTIONS

options générales

  -h    --help
          afficher ce texte d'aide et quitter
        --version
          afficher les informations de version et quitter
        --arguments
          afficher les arguments de la ligne de commande étendus
  -q    --quiet
          mode silencieux, ne pas afficher les avertissements ni les erreurs
  -v    --verbose
          mode verbeux, afficher les détails du traitement
  -d    --debug
          mode débogage, afficher les informations de débogage
  -ll   --log-level  [l]evel: string constant
          (fatal, error, warn, info, debug, trace)
          utiliser le niveau l pour le journal
  -lc   --log-config  [f]ilename: string
          utiliser le fichier de configuration f pour le journal

options d'entrée

format du fichier d'entrée:
  +f    --read-file
          lire le format de fichier ou le jeu de données (par défaut)
  +fo   --read-file-only
          lire uniquement le format de fichier
  -f    --read-dataset
          lire le jeu de données sans méta-informations de fichier
syntaxe de transfert d'entrée:
  -t=   --read-xfer-auto
          utiliser la reconnaissance de la syntaxe de transfert (par défaut)
  -td   --read-xfer-detect
          ignorer la syntaxe de transfert spécifiée dans l'en-tête méta du fichier
  -te   --read-xfer-little
          lire avec la syntaxe de transfert VR explicite little endian
  -tb   --read-xfer-big
          lire avec la syntaxe de transfert VR explicite big endian
  -ti   --read-xfer-implicit
          lire avec la syntaxe de transfert VR implicite little endian

options de traitement et d'encodage d'image

mise à l'échelle:
  +a    --recognize-aspect
          prendre en compte le rapport d'aspect des pixels lors de la mise à l'échelle (par défaut)
  -a    --ignore-aspect
          ignorer le rapport d'aspect des pixels lors de la mise à l'échelle
  +i    --interpolate  [n]umber of algorithm: integer
          utiliser l'interpolation lors de la mise à l'échelle (1..4, par défaut: 1)
  -i    --no-interpolation
          pas d'interpolation lors de la mise à l'échelle
  -S    --no-scaling
          pas de mise à l'échelle, ignorer le rapport d'aspect des pixels (par défaut)
  +Sxf  --scale-x-factor  [f]actor: float
          mettre l'axe x à l'échelle par le facteur, calculer automatiquement l'axe y
  +Syf  --scale-y-factor  [f]actor: float
          mettre l'axe y à l'échelle par le facteur, calculer automatiquement l'axe x
  +Sxv  --scale-x-size  [n]umber: integer
          mettre l'axe x à l'échelle sur n pixels, calculer automatiquement l'axe y
  +Syv  --scale-y-size  [n]umber: integer
          mettre l'axe y à l'échelle sur n pixels, calculer automatiquement l'axe x
autres transformations:
  +C    --clip-region  [l]eft [t]op [w]idth [h]eight: integer
          découper une région rectangulaire de l'image (l, t, w, h)
UID d'instance SOP:
  +ua   --uid-always
          toujours attribuer un nouvel UID d'instance SOP (par défaut)
  +un   --uid-never
          ne jamais attribuer un nouvel UID d'instance SOP

options de sortie

format du fichier de sortie:
  +F    --write-file
          écrire le format de fichier (par défaut)
  -F    --write-dataset
          écrire le jeu de données sans méta-informations de fichier
syntaxe de transfert de sortie:
  +t=   --write-xfer-same
          écrire avec la même syntaxe de transfert que l'entrée (par défaut)
  +te   --write-xfer-little
          écrire avec la syntaxe de transfert VR explicite little endian
  +tb   --write-xfer-big
          écrire avec la syntaxe de transfert VR explicite big endian
  +ti   --write-xfer-implicit
          écrire avec la syntaxe de transfert VR implicite little endian
représentations de valeurs post-1993:
  +u    --enable-new-vr
          activer la prise en charge des nouveaux VR (UN/UT) (par défaut)
  -u    --disable-new-vr
          désactiver la prise en charge des nouveaux VR, convertir en OB
encodage de la longueur de groupe:
  +g=   --group-length-recalc
          recalculer les longueurs de groupe si présentes (par défaut)
  +g    --group-length-create
          toujours écrire avec les éléments de longueur de groupe
  -g    --group-length-remove
          toujours écrire sans les éléments de longueur de groupe
encodage de la longueur dans les séquences et les éléments:
  +e    --length-explicit
          écrire avec des longueurs explicites (par défaut)
  -e    --length-undefined
          écrire avec des longueurs indéfinies
remplissage de fin de jeu de données (pas avec --write-dataset):
  -p=   --padding-retain
          ne pas modifier le remplissage
          (par défaut si pas --write-dataset)
  -p    --padding-off
          pas de remplissage (implicite si --write-dataset)
  +p    --padding-create  [f]ile-pad [i]tem-pad: integer
          aligner le fichier sur un multiple de f octets et les éléments sur
          un multiple de i octets

NOTES

Les algorithmes d'interpolation préférés suivants peuvent être sélectionnés à l'aide de l'option --interpolate :

  • 1 = algorithme de mise à l'échelle libre avec interpolation de la boîte à outils pbmplus
  • 2 = algorithme de mise à l'échelle libre avec interpolation du magazine c't
  • 3 = algorithme d'agrandissement avec interpolation bilinéaire d'Eduard Stanescu
  • 4 = algorithme d'agrandissement avec interpolation bicubique d'Eduard Stanescu

JOURNALISATION

Le niveau de sortie du journal des différentes outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seules les erreurs et les avertissements sont écrits sur le flux d'erreur standard. En utilisant l'option --verbose les messages informatifs tels que les détails de traitement sont également rapportés. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet seules les erreurs fatales sont rapportées. En cas d'événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, voir la documentation du module « oflog ».

Si la sortie du journal doit être écrite dans un fichier (avec rotation du journal en option), dans syslog (Unix) ou dans le journal des événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets enclos des valeurs facultatives (0-1), trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie de 0 à n valeurs.

Les options de la ligne de commande se distinguent des paramètres par un signe '+' ou '-' respectivement. En général, l'ordre et la position des options de la ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si des options sont mutuellement exclusives, la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

De plus, un ou plusieurs fichiers de commande peuvent être spécifiés en utilisant un signe '@' comme préfixe du nom de fichier (par exemple @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (plusieurs espaces blancs sont traités comme un seul séparateur s'ils n'apparaissent pas entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite des lignes de commande longues et déroutantes (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

ENVIRONNEMENT

L'utilitaire dcmscale essaiera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH . Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé, sauf si le dictionnaire est intégré à l'application (par défaut sous Windows).

Le comportement par défaut doit être préféré et la variable d'environnement DCMDICTPATH ne doit être utilisée que lorsque des dictionnaires de données alternatifs sont nécessaires. La variable d'environnement DCMDICTPATH a le même format que la variable PATH du shell Unix dans laquelle un deux-points (« : ») sépare les entrées. Sur les systèmes Windows, un point-virgule (« ; ») est utilisé comme séparateur.arateur. Le code du dictionnaire de données tentera de charger chaque fichier spécifié dans la DCMDICTPATH variable d'environnement. C'est une erreur si aucun dictionnaire de données ne peut être chargé.
