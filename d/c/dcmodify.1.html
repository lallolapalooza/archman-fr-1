DESCRIPTIO

N

dcmodify est un outil qui permet de modifier, d'insérer et de supprimer des balises et des éléments dans des fichiers DICOM. Les séquences et les balises avec une multiplicité de valeur > 1 sont également prises en charge. Les informations de l'en-tête méta et la VR de la balise ne peuvent pas être modifiées directement par dcmodify à ce moment. En plus des modifications de balises, dcmodify met à disposition certaines options d'entrée - forçant dcmodify à traiter ses fichiers d'entrée comme l'utilisateur le spécifie - et des options de sortie pour contrôler le format de sortie des fichiers

résultants.

En cas de plusieurs modifications à effectuer, dcmodify effectue les modifications dans le même ordre qu'elles apparaissent sur la ligne de commande. Veuillez noter que dcmodify ne vérifie pas si une valeur donnée correspond à sa représentation de valeur (VR). Habituellement, un message d'erreur est imprimé mais généralement l'utilisateur doit veiller à l'utilisation correcte de la

VR.

Si dcmodify ne connaît pas la balise qu'il doit insérer, alors la VR de la balise est définie sur UN et la valeur fournie sur la ligne de commande est interprétée comme étant une série de nombres hexadécimaux (comme ils sont fournis pour VR=OB). Veuillez insérer ces balises dans le dictionnaire pour éviter ce comportement. De plus, en spécifiant l'option -iun, il est possible de forcer dcmodify à laisser les valeurs UN intactes. En utilisant l'option -u, on permet à dcmodify de sauvegarder tous les attributs VR=UN en tant

qu'OB.

dcmodify est capable de travailler avec les soi-disant chemins de balises pour accéder aux balises dans les séquences. La syntaxe (pseudo-formalisée)

est 
{sequence[item-no].}
*element

où 'sequence' est une balise de séquence comme (0008,1111) ou un nom de dictionnaire pour une balise. 'item-no' décrit le numéro d'élément à accéder (compté à partir de zéro). 'element' définit la balise cible sur laquelle travailler. Une balise peut être spécifiée directement comme (0010,0010) ou par le nom de dictionnaire correspondant "PatientName". Le '' indique que vous pouvez répéter les instructions de séquence pour accéder à des niveaux plus profonds dans les fichiers DICOM (voir la section EXEMPLES). Pour 'item-no', un caractère générique '' peut également être utilisé pour sélectionner tous les éléments de la séquence englobante (voir la section CARACTÈRES GÉNÉRIQUES ci-dessous)

.

Lors de l'insertion de chemins de balises composés de plusieurs nœuds (c'est-à-dire pas un seul élément) en utilisant l'option -i, tout élément de chemin manquant (éléments, séquences, éléments terminaux) est inséré automatiquement s'il manque. Cela ne fonctionne pas pour les caractères génériques d'éléments : Lorsqu'aucun élément n'existe dans la séquence englobante, dcmodify ne peut bien sûr pas décider combien d'éléments doivent être générés. Cependant, si l'on spécifie un numéro d'élément comme '5', les 6 éléments (comptés à partir de zéro) peuvent être (et sont) automatiquement générés en mode insertion. Si 2 éléments existaient déjà, le reste (4) serait

inséré.

dcmodify ne fonctionne pas sur les répertoires, c'est-à-dire que le paramètre dcmfile-in... ne doit pas inclure de noms de

répertoires.

Veuillez noter qu'il y a certains problèmes concernant la modif

ication des balises privées (voir la section BALISES PRIVÉ
ES) et pour le changement d'UID (section CHANGEMENT D'UID).

NAME

dcmodify — modify DICOM file contents

SYNOPSIS

dcmodify [-h | --help] [-v | --version] [-d | --debug] [-q | --quiet] [--log-level level] [--log-config file] [-i | --ignore-missing-tags] [-m | --create-missing-groups] [-u | --change-uids] [-a | --append-to-file] [-b | --binary] [-x | --xml] [-y | --macro file] [--disable-automatic-input-conversion] [--check-file-format] [-c | --create] [-e | --erase] [-r | --replace] [-s | --set] [-t | --type type] [--insert] [--replace-from-file] [--insert-from-file] [--erase-from-file] [--null-value] [--no-pixel-data] [--no-full-prefix] [--strict] [--verbose] [--] input-file...

DESCRIPTION

The command line utility dcmodify can be used to modify DICOM file contents. It allows to replace, erase, insert or create DICOM elements as well as to change DICOM UIDs. The tool is designed to operate on one or more DICOM files passed as command line arguments.

PARAMETERS

input-file
One or more DICOM files that should be modified. If the option --append-to-file is used, the files are appended to the first file specified.

OPTIONS

All command line options are listed below:

-h, --help
Print help information and exit.
-v, --version
Print version information and exit.
-d, --debug
Enable debugging output on stderr.
-q, --quiet
Quiet mode. Only fatal errors are reported.
--log-level level
Use specified logging level. Supported levels are: trace, debug, info, warn, error, fatal. Default is 'info'.
--log-config file
Read logging configuration from specified file. See section LOGGING.
-i, --ignore-missing-tags
Do not treat missing tags as an error. See section ERROR HANDLING.
-m, --create-missing-groups
Create missing groups for private tags.
-u, --change-uids
Generate new SOP Instance UIDs and/or Series Instance UIDs for each input file. See section CHANGING UIDS.
-a, --append-to-file
Append the DICOM files specified on the command line to the first file. Note that this option can only be used with binary DICOM files (transfer syntax explicitly set to Little Endian Explicit, Big Endian Explicit or Implicit Little Endian).
-b, --binary
Force binary mode for all input and output files. Normally, this is the default for DICOM files. This option is mainly useful when modifying other file formats.
-x, --xml
Read the list of DICOM modifications from an XML file instead of from the command line. This option is mutually exclusive with options -c, -e, -r, -s, --insert, --replace-from-file, --insert-from-file and --erase-from-file.
-y, --macro file
Read macro definitions from the specified file. This allows to define custom tags or groups of tags that can be used later on the command line or in an XML file.
--disable-automatic-input-conversion
Disable automatic conversion of input files to the explicit VR little-endian transfer syntax. This option is useful if you want to preserve the original transfer syntax of the input files.
--check-file-format
Check the DICOM file format of the input files. This includes checking the DICOM preamble, the meta header and the file meta information.
-c, --create
Create a new DICOM element. The element is created at the position where it is first encountered in the list of modifications. If the element already exists, it is replaced. This option is mutually exclusive with -e, -r, -s, --insert, --replace-from-file, --insert-from-file and --erase-from-file.
-e, --erase
Erase an existing DICOM element. If the element does not exist, it is ignored unless the option --strict is used. This option is mutually exclusive with -c, -r, -s, --insert, --replace-from-file, --insert-from-file and --erase-from-file.
-r, --replace
Replace the value of an existing DICOM element. If the element does not exist, it is ignored unless the option --strict is used. This option is mutually exclusive with -c, -e, -s, --insert, --replace-from-file, --insert-from-file and --erase-from-file.
-s, --set
Set the value of a DICOM element. If the element does not exist, it is created. This option is mutually exclusive with -c, -e, -r, --insert, --replace-from-file, --insert-from-file and --erase-from-file.
-t, --type type
Specify the DICOM VR (Value Representation) of the element to be created or modified. This option is only used in conjunction with options -c, -s, --insert, --replace-from-file and --insert-from-file. If not specified, the VR is automatically determined from the DICOM data dictionary.
--insert
Insert a new DICOM element at the position where it is first encountered in the list of modifications. If the element already exists, it is ignored. This option is mutually exclusive with -c, -e, -r, -s, --replace-from-file, --insert-from-file and --erase-from-file.
--replace-from-file
Replace the value of an existing DICOM element by reading the value from a file. If the element does not exist, it is ignored unless the option --strict is used. This option is mutually exclusive with -c, -e, -r, -s, --insert, --insert-from-file and --erase-from-file.
--insert-from-file
Insert a new DICOM element by reading the value from a file. If the element already exists, it is ignored. This option is mutually exclusive with -c, -e, -r, -s, --insert, --replace-from-file and --erase-from-file.
--erase-from-file
Erase an existing DICOM element by reading the tag from a file. If the element does not exist, it is ignored unless the option --strict is used. This option is mutually exclusive with -c, -e, -r, -s, --insert, --replace-from-file and --insert-from-file.
--null-value
Set the value of the element to an empty string (NULL). This option is used in conjunction with options -s, -r, --replace, --set, --replace-from-file and --insert-from-file.
--no-pixel-data
Do not modify or erase pixel data elements (007FE0,0010) and (007FE0,0009).
--no-full-prefix
Do not use the full tag prefix (group, element) when searching for a tag. This can be useful when working with tags that have a group tag but no element tag, e.g. (0009,xxxx).
--strict
Enforce strict checking of DICOM element existence. If an element that is supposed to be replaced or erased does not exist, an error is reported and the application terminates.
--verbose
Print verbose output on stderr, including processing details.
--
Marks the end of options. Any subsequent arguments are treated as filenames, even if they start with a dash.

PRIVATE TAGS

Private DICOM tags are specified using the standard group and element numbers, e.g. (gggg,eeee), where gggg and eeee are hexadecimal numbers. If the group number is not known, it can be specified as a wildcard character (e.g. (xxxx,eeee)). For private tags, the group number usually starts with a lowercase letter.

CHANGING UIDS

By using the option --change-uids, each input file is assigned a new SOP Instance UID and optionally a new Series Instance UID. The old UIDs are replaced by new ones. If the option --append-to-file is used, the UIDs of the appended files are changed accordingly.

CREATING NEW FILES

If the input file is an empty file or a file that does not contain any DICOM data, dcmodify can be used to create a new DICOM file. In this case, the modifications specified on the command line are used to populate the new file.

ELEMENT VALUES FROM FILE

The options --replace-from-file, --insert-from-file and --erase-from-file allow to specify the DICOM tags and their values in a separate file. The format of this file is: tag=value where tag is a DICOM tag in the format (gggg,eeee) and value is the string representation of the element's value. If the value contains spaces, it should be enclosed in quotation marks. For binary values, the option --binary must be used. The options --replace-from-file and --insert-from-file can also be used with the option --null-value to set the element's value to an empty string.

WILDCARDS

Wildcards can be used in tag specifications to match multiple elements. For example, (0010,0010) matches the Patient Name element, while (0010,xxxx) matches all elements in the Patient's Name group (0010,00xx). Wildcards can also be used for group numbers, e.g. (xxxx,0010) matches all elements with tag (xxxx,0010).

EXAMPLES

Replace the Patient's Name in file input.dcm:

dcmodify -e "(0010,0010)" input.dcm

Set the Patient's Sex to 'M' in file input.dcm:

dcmodify -s "(0010,0040)"=M input.dcm

Replace the values of tags (0010,0010) and (0020,000D) in file input.dcm:

dcmodify -r "(0010,0010)" -r "(0020,000D)" input.dcm

Create a new DICOM file with Patient's Name set to 'Doe^John' and Patient's Sex set to 'M':

dcmodify -c "(0010,0010)"="Doe^John" -c "(0010,0040)"=M new_file.dcm

Erase all elements in group (0009,xxxx):

dcmodify -e "(0009,xxxx)" input.dcm

Change UIDs in all DICOM files in the current directory:

dcmodify -u *.dcm

ERROR HANDLING

By default, dcmodify exits after the first file that had modification errors.

If the --ignore-missing-tags option is enabled, any modify or erase operations (i.e. not --insert) that fails because of a non-existing tag is treated as being successful. That does make sense if someone wants to be sure that specific tags are not present in the file or that - if they exist - that they are set to a specific value.

LOGGING

The level of logging output of the various command line tools and underlying libraries can be specified by the user. By default, only errors and warnings are written to the standard error stream. Using option --verbose also informational messages like processing details are reported. Option --debug can be used to get more details on the internal activity, e.g. for debugging purposes. Other logging levels can be selected using option --log-level. In --quiet mode only fatal errors are reported. In such very severe error events, the application will usually terminate. For more details on the different logging levels, see documentation of module "oflog".

In case the logging output should be written to file (optionally with logfile rotation), to syslog (Unix) or the event log (Windows) option --log-config can be used. This configuration file also allows for directing only certain messages to a particular output stream and for filtering certain messages based on the module or application where they are generated. An example configuration file is provided in <etcdir>/logger.cfg.

COMMAND LINE

All command line tools use the following notation for parameters: square brackets enclose optional values (0-1), three trailing dots indicate that multiple values are allowed (1-n), a combination of both means 0 to n values.

Command line options are distinguished from parameters by a leading '+' or '-' sign, respectively. Usually, order and position of command line options are arbitrary (i.e. they can appear anywhere). However, if options are mutually exclusive the rightmost appearance is used. This behavior conforms to the standard evaluation rules of common Unix shells.

In addition, one or more command files can be specified using an '@' sign as a prefix to the filename (e.g. @command.txt). Such a command argument is replaced by the content of the corresponding text file (multiple whitespaces are treated as a single separator unless they appear between two quotation marks) prior to any further evaluation. Please note that a command file cannot contain another command file. This simple but effective approach allows one to summarize common combinations of options/parameters and avoids longish and confusing command lines (an example is provided in file <datadir>/dumppat.txt).

ENVIRONMENT

The dcmodify utility will attempt to load DICOM data dictionaries specified in the DCMDICTPATH environment variable. By default, i.e. if the DCMDICTPATH environment variable is not set, the file <datadir>/dicom.dic will be loaded unless the dictionary is built into the application (default for Windows).

The default behavior should be preferred and the DCMDICTPATH environment variable only used when alternative data dictionaries are required. The DCMDICTPATH environment variable has the same format as the Unix shell PATH variable in that a colon (":") separates entries. On Windows systems, a semicolon (";") is used as a separator. The data dictionary code will attempt to load each file specified in the DCMDICTPATH environment variable. It is an error if no data dictionary can be loaded.
