NOM

dcmqrti - Le programme client Telnet initiateur

SYNTAXE

dcmqrti [options] peer...

DESCRIPTION

Le programme dcmqrti (initiateur telnet) est un programme interactif basé sur des caractères, destiné à être utilisé pour examiner les bases de données d'images dcmqrscp et envoyer des images contenues dans ces bases de données à des nœuds Vendeurs. Lors d'une démonstration DICOM, le programme dcmqrti peut être activé par un Vendeur en se connectant à l'ordinateur exécutant le programme dcmqrscp. Chaque vendeur aura son propre compte de connexion et le programme dcmqrti sera lancé à la place d'un shell normal lorsqu'il se connectera.

Le programme dcmqrti prend un argument principal, le nom d'hôte ou le nom symbolique du vendeur (provenant de VendorTable dans le fichier de configuration) d'un Vendeur. Il recherche ensuite dans le fichier de configuration tous les titres AE associés à ce nom d'hôte ou nom de vendeur, ainsi que toutes les zones de stockage accessibles à ces titres AE. Ainsi, seules les bases de données accessibles et les applications pairs découvertes dans le fichier de configuration sont disponibles comme choix au sein de l'interface utilisateur de dcmqrti.

PARAMÈTRES

peer  nom d'hôte pair ou nom symbolique du fichier cfg

OPTIONS

options générales

  -h    --help
          afficher ce texte d'aide et quitter
        --version
          afficher les informations de version et quitter
        --arguments
          afficher les arguments de la ligne de commande développés
  -q    --quiet
          mode silencieux, n'afficher aucun avertissement ni erreur
  -v    --verbose
          mode verbeux, afficher les détails de traitement
  -d    --debug
          mode de débogage, afficher les informations de débogage
  -ll   --log-level  [l]evel: chaîne de caractères constante
          (fatal, error, warn, info, debug, trace)
          utiliser le niveau l
          pour le journal
  -lc   --log-config  [f]ichier: chaîne
          utiliser le fichier de configuration f
          pour le journal
  -c    --config  [f]ichier: chaîne
          utiliser un fichier de configuration spécifique
          (défaut: /usr/local/etc/dcmtk-<VERSION>/dcmqrscp.cfg)

options réseau

  -to   --timeout  [s]econdes: entier (défaut: illimité)
          délai d'attente pour les requêtes de connexion
  -ta   --acse-timeout  [s]econdes: entier (défaut: 30)
          délai d'attente pour les messages ACSE
  -td   --dimse-timeout  [s]econdes: entier (défaut: illimité)
          délai d'attente pour les messages DIMSE
  -xi   --propose-implicit
          ne proposer que le TS implicite VR little endian
  -aet  --aetitle  [a]pplication entity title: chaîne
          définir mon titre AE (défaut: TELNET_INITIATOR)
  -pdu  --max-pdu  [n]ombre d'octets: entier (4096..131072)
          définir le PDU de réception maximum à n octets
          (défaut: utiliser la valeur du fichier de configuration)

autres options

  -u    --disable-new-vr
          désactiver la prise en charge des nouveaux VR, convertir en OB
  -rmt  --remote  [t]itle: chaîne
          se connecter à une base de données distante définie dans le fichier cfg

NOTES dcmqrti

Commandes

Toutes les commandes peuvent être abrégées. Une abréviation est autorisée si elle ne conflit pas avec une autre commande.

Commande "help"

La commande "help" donne un résumé de toutes les commandes disponibles. Sa sortie est montrée ci-dessous. Afin de séparer les exemples du texte environnant, tous les exemples sont encadrés par des lignes de tirets. Ces lignes n'apparaissent pas lors de l'exécution du programme.

------------------------------------------------------------
Résumé des commandes :
help                liste ce résumé
?                   aide courte
title [#]           liste [définit] le titre AE pair actuel
database [#]        liste [définit] la base de données actuelle
study [#]           liste [définit] l'étude actuelle
series [#]          liste [définit] la série actuelle
image [#]           liste [définit] l'image actuelle
display [#]         affiche l'image actuelle [spécifique]
send study [#]      envoie l'étude actuelle [spécifique]
send series [#]     envoie la série actuelle [spécifique]
send image [#]      envoie l'image actuelle [spécifique]
echo [#]            vérifie la connectivité [# fois]
quit                quitte le programme
exit                synonyme de quit
------------------------------------------------------------

Commande "title"

La commande "title" sans argument permet à l'utilisateur de lister les Entités Applicatives (AE) distantes connues. Un exemple de sortie pourrait ressembler à ceci :

------------------------------------------------------------
Titres AE pairs :
     AE pair          Nom d'hôte:Numéro de port
* 0) ACME1            (swallow:2001)
  1) ACME2            (swallow:2002)
  2) UNITED1          (kolibri:2001)
  3) UNITED2          (kolibri:2002)
------------------------------------------------------------

L'AE pair actuel est marqué d'un astérisque (*). Chaque AE pair a un index (deuxième colonne) qui peut être utilisé comme argument à la commande "title" pour définir l'AE pair actuel. La troisième colonne donne le titre AE de l'AE pair. La quatrième colonne montre le nom d'hôte et le numéro de port TCP/IP de l'AE pair.

Lorsqu'elle est invoquée avec un index d'argument, la commande "title" définira l'AE pair actuel. Le programme dcmqrti tentera d'initier une association avec l'AE pair actuel lorsqu'il sera demandé d'envoyer une étude/série/image ou d'envoyer un écho.

Commande "database"

La commande "database" sans argument permet à l'utilisateur de lister les bases de données locales connues (celles-ci correspondent aux Titres d'Entités Applicatives de dcmqrscp). Un exemple de sortie pourrait ressembler à ceci :

------------------------------------------------------------
Titres des bases de données :
     Base de données
* 0) COMMON
  1) ACME_QUERY
  2) ACME_STORE
  3) UNITED_QUERY
------------------------------------------------------------

La base de données actuelle est marquée d'un astérisque (*). Chaque base de données a un index (deuxième colonne) qui peut être utilisé comme argument à la commande "database" pour définir la base de données actuelle. La troisième colonne montre le nom de la base de données (c'est-à-dire le titre de l'Entité Applicative dcmqrscp pour la zone de stockage particulière).

Lorsqu'elle est invoquée avec un index d'argument, la commande "database" définira la base de données actuelle. La base de données actuelle est utilisée comme base pour d'autres actions spécifiques à la base de données.

Commande "study"

La commande "study" sans argument liste les études dans la base de données actuelle. Un exemple de sortie pourrait ressembler à ceci :

------------------------------------------------------------
      Patient                        PatientID    StudyID
*  0) JACKSON^ANDREW^^^              M4997106     20001
   1) GRANT^MARY^^^                  F4997108     20002
   2) ARTHUR^CHESTER^^^              M4997107     20003
   3) JEFFERSON^THOMAS^^^            M4997096     9465
   4) MADISON^DOLLY^^^               F4997097     9443
4 Études dans la base de données : COMMON
------------------------------------------------------------

L'étude actuelle est marquée d'un astérisque (*). Chaque étude a un index (deuxième colonne) qui peut être utilisé comme argument à la commande "study" pour définir l'étude actuelle. La troisième colonne montre le nom du patient, la quatrième colonne l'ID du patient et la cinquième colonne l'ID de l'étude.

Lorsqu'elle est invoquée avec un index d'argument, la commande "study" définira l'étude actuelle. L'étude actuelle est utilisée comme base pour d'autres actions spécifiques à l'étude.

Commande "series"

La commande "series" sans argument liste les séries dans l'étude actuelle. Un exemple de sortie pourrait ressembler à ceci :

------------------------------------------------------------
      Series Modality SeriesInstanceUID
*  0) 1      MR       1.2.840.113654.2.3.1993.201
   1) 2      MR       1.2.840.113654.2.3.1993.202
   2) 3      MR       1.2.
840.113654.2.3.1993.204
   4) 5      MR       1.2.840.113654.2.3.1993.205
5 Séries dans StudyID 05381,
  Patient : MONROE^JAMES^^^ (Base de données : COMMON)
------------------------------------------------------------

La série courante est marquée d'un astérisque (*). Chaque série a un index (deuxième colonne) qui peut être utilisé comme argument de la commande « series » afin de définir la série courante. La troisième colonne indique le numéro de la série, la quatrième colonne la modalité de la série, et la cinquième colonne l'UID de l'instance de série.

Lorsqu'elle est appelée avec un index d'argument, la commande « series » définit la série courante. La série courante est utilisée comme base pour les actions futures spécifiques à la série.

L'image courante est marquée d'un astérisque (*). Chaque image a un index (deuxième colonne) qui peut être utilisé comme argument de la commande « image » afin de définir l'image courante. La troisième colonne indique le numéro de l'image, et la quatrième colonne l'UID de l'instance d'image (UID de l'instance SOP).

Lorsqu'elle est appelée avec un index d'argument, la commande « image » définit l'image courante. L'image courante est utilisée comme base pour les actions futures spécifiques à l'image.

Commande « display »

La commande display n'a aucun but dans la version actuelle de DCMTK. Elle était utilisée dans les versions précédentes pour demander au programme CTN Display d'afficher une image.

Commande « send »

La commande « send » permet de stocker une étude/série complète ou une image individuelle sur un AE distant. Lorsque cette commande est appelée, le programme dcmqrti fonctionne comme un SCU du service de stockage DICOM et tente d'établir une association avec l'AE pair courant (défini via la commande « title »). Les contextes de présentation pour toutes les classes SOP de stockage pertinentes seront proposés. Une tentative sera faite pour stocker toutes les images spécifiées. Si aucune association ne peut être négociée, un message d'erreur sera affiché. Si une opération de stockage échoue ou si aucun contexte de présentation approprié n'est disponible, un message d'erreur sera affiché.

La commande « send » existe en trois formes :
        send study [#]
        send series [#]
        send image [#]

Le mot-clé « study » signifie envoyer toutes les images de l'étude courante. Lorsqu'elle est appelée avec un index d'argument, l'étude spécifiée dans la base de données courante sera stockée. Le mot-clé « series » signifie envoyer toutes les images de la série courante. Lorsqu'elle est appelée avec un index d'argument, la série spécifiée dans l'étude courante sera stockée. Le mot-clé « image » signifie envoyer l'image courante. Lorsqu'elle est appelée avec un index d'argument, l'image spécifiée dans la série courante sera stockée.

Lorsqu'une image est stockée, un message sera affiché sous la forme suivante :

------------------------------------------------------------
Nouvelle association démarrée (swallow:2001,ACME1)
[MsgID 1] Store,
  PatientName: JACKSON^ANDREW^^^, StudyID: 20001,
  Series: 2, Modality: CR, Image: 1,
  Image UID: 1.2.840.113654.2.3.1993.9.123.6.1834
  0%________25%_________50%__________75%________100%
  --------------------------------------------------
[MsgID 1] Complété [Status: Success]
Association libérée (swallow:2001,ACME1)
------------------------------------------------------------

Commande « echo »

La commande « echo » permet à l'utilisateur de vérifier la connectivité avec l'AE pair courant (défini via la commande « title »). Lorsqu'elle est appelée, le programme dcmqrti agit comme un SCU de la Classe de Service de Vérification.

Lorsqu'elle est appelée sans argument, un seul message C-ECHO est généré. Lorsqu'elle est appelée avec un argument, le nombre spécifié de messages C-ECHO sera envoyé. Un message sera affiché sous la forme :

------------------------------------------------------------
Nouvelle association démarrée (localhost:2001,CMOVE)
[MsgID 1] Echo, Complété [Status: Success]
Association libérée (localhost:2001,CMOVE)
------------------------------------------------------------

Commandes « quit », exit »

Les commandes « quit » et « exit » ont le même effet. Elles terminent le programme dcmqrti.

Conformité DICOM

L'application dcmqrti prend en charge le même ensemble de classes SOP en tant que SCU que l'application dcmqrscp - voir la documentation de dcmqrscp.

L'application dcmqrti proposera des contextes de présentation pour toutes les classes SOP prises en charge mentionnées ci-dessus en utilisant les syntaxes de transfert suivantes :

LittleEndianImplicitTransferSyntax  1.2.840.10008.1.2
LittleEndianExplicitTransferSyntax  1.2.840.10008.1.2.1
BigEndianExplicitTransferSyntax     1.2.840.10008.1.2.2

L'application dcmqrti ne prend pas en charge la négociation étendue.

Configuration

Le programme dcmqrti utilise le même fichier de configuration que le programme dcmqrscp. Voir la documentation sur la configuration pour plus d'informations (dcmqrcnf.txt et le fichier de configuration d'exemple dcmqrscp.cfg).

JOURNALISATION

Le niveau de sortie de journalisation des divers outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seuls les erreurs et les avertissements sont écrits dans le flux d'erreur standard. L'utilisation de l'option --verbose permet également de signaler des messages informatifs comme les détails de traitement. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet, seuls les erreurs fatales sont signalées. Dans de tels événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, voir la documentation du module « oflog ».

Dans le cas où la sortie de journalisation devrait être écrite dans un fichier (éventuellement avec rotation de fichier journal), vers syslog (Unix) ou le journal des événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets encadrent les valeurs optionnelles (0-1), trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie 0 à n valeurs.

Les options de ligne de commande sont distinguées des paramètres par un signe « + » ou « - » respectivement. Habituellement, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si les options sont mutuellement exclusives, l'apparition la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

De plus, un ou plusieurs fichiers de commande peuvent être spécifiés à l'aide d'un signe « @ » comme préfixe du nom de fichier (par exemple, @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (plusieurs espaces blancs sont traités comme un seul séparateur sauf s'ils apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et d'éviter des lignes de commande trop longues et confuses (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

ENVIRONNEMENT

L'utilitaire dcmqrti tentera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH. Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé, sauf si le dictionnaire est intégré à l'application (par défaut pour Windows).

Le comportement par défaut doit être privilégié et la variable d'environnement DCMDICTPATH ne doit être utilisée que lorsque des dictionnaires de données alternatifs sont requis. La variable d'environnement DCMDICTPATH a le même format que la variable PATH du shell Unix, en ce sens qu'un deux-points (« : ») sépare les entrées. Sur les systèmes Windows, un point-virgule (« ; ») est utilisé comme séparateur. Le code du dictionnaire de données tentera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH. Une erreur se produit si aucun dictionnaire de données ne peut être chargé.
