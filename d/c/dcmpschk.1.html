NOM

dcmpschk - Outil de vérification des états de présentation

SYNTAXE

dcmpschk [options] [fichier-etats-diag...]

DESCRIPTION

L'utilitaire dcmpschk vérifie les objets DICOM Grayscale Softcopy Presentation State pour leur conformité à la norme. Le test est effectué en trois phases :

  • Phase 1 vérifie le méta-en-tête du fichier DICOM. On teste si tous les attributs requis sont présents, si les UID de la classe SOP et de l'instance correspondent aux UID de l'objet principal et si l'attribut de longueur de groupe contient une valeur correcte. Le format de transfert du méta-en-tête est également vérifié.
  • Phase 2 effectue une vérification syntaxique des valeurs, des représentations de valeurs et des multiplicités de valeurs pour chaque attribut de l'objet. Les valeurs présentes dans l'objet testé sont comparées aux définitions du dictionnaire de données DICOM.
  • Phase 3 effectue une vérification sémantique de l'intégrité de l'état de présentation. Cette phase est omise lorsque des objets d'autres classes SOP sont rencontrés. Les phases 1 et 2 peuvent également être appliquées à d'autres objets DICOM de classe SOP arbitraire. Il convient de noter que dcmpschk ne prend pas en charge les états de présentation qui contiennent le module de masque. Ceux-ci seront rejetés avec un message indiquant que le module de masque n'est pas pris en charge.

PARAMETRES

fichier-etats-diag  fichiers d'état de présentation à vérifier

OPTIONS

options générales

  -h   --help
         imprimer ce texte d'aide et quitter
       --version
         imprimer les informations de version et quitter
       --arguments
         imprimer les arguments de la ligne de commande développés
  -q   --quiet
         mode silencieux, n'imprimer aucune avertissement ni erreur
  -v   --verbose
         mode verbeux, imprimer les détails du traitement
  -d   --debug
         mode debug, imprimer les informations de débogage
  -ll  --log-level  [n]iveau: chaîne de caractères
         (fatal, error, warn, info, debug, trace)
         utiliser le niveau n pour le logger
  -lc  --log-config  [f]ichier: chaîne de caractères
         utiliser le fichier de configuration f pour le logger

LOGGING

Le niveau de sortie des journaux des divers outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seuls les erreurs et les avertissements sont écrits dans le flux d'erreur standard. L'utilisation de l'option --verbose permet également de rapporter des messages informatifs tels que les détails de traitement. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet, seules les erreurs fatales sont signalées. Dans ces cas d'événements d'erreur très graves, l'application s'arrêtera généralement. Pour plus de détails sur les différents niveaux de journalisation, consultez la documentation du module "oflog".

Dans le cas où la sortie des journaux doit être écrite dans un fichier (éventuellement avec rotation des fichiers journaux), vers syslog (Unix) ou le journal des événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets indiquent les valeurs optionnelles (0-1), trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie 0 à n valeurs.

Les options de ligne de commande se distinguent des paramètres par un signe '+' ou '-' respectivement. Généralement, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si les options sont mutuellement exclusives, c'est l'apparition la plus à droite qui est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

De plus, un ou plusieurs fichiers de commande peuvent être spécifiés en faisant précéder le nom du fichier d'un signe '@' (par exemple, @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (les espaces multiples sont traités comme un seul séparateur sauf s'ils apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite les lignes de commande longues et confuses (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

ENVIRONNEMENT

L'utilitaire dcmpschk tentera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH. Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé, sauf si le dictionnaire est intégré à l'application (par défaut pour Windows).

Le comportement par défaut doit être préféré et la variable d'environnement DCMDICTPATH ne doit être utilisée que lorsque des dictionnaires de données alternatifs sont requis. La variable d'environnement DCMDICTPATH a le même format que la variable PATH du shell Unix, en ce sens qu'un deux-points (":") sépare les entrées. Sur les systèmes Windows, un point-virgule (";") est utilisé comme séparateur. Le code du dictionnaire de données tentera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH. Une erreur se produira si aucun dictionnaire de données ne peut être chargé.
