NOM

dcmmkcrv - Ajouter des données de courbe 2D à une image

SYNTAXE

dcmmkcrv [options] dcmfile-in curvedata-in dcmfile-out

DESCRIPTION

L'utilitaire dcmmkcrv permet de créer des images DICOM contenant des données de courbe. Étant donné que les données de courbe sont peu utilisées par les fournisseurs aujourd'hui, ceci est destiné à tester les implémentations capables de lire des données de courbe. L'utilitaire lit une image DICOM existante et un fichier texte contenant les données de courbe sous forme textuelle. Un groupe répétitif de données de courbe DICOM est créé selon les options spécifiées en ligne de commande, ajouté à l'image existante et réécrit dans un fichier. Le fichier de sortie est encodé avec la même syntaxe de transfert que celle utilisée pour le fichier d'entrée. Cet utilitaire ne prend en charge que la création de courbes bidimensionnelles.

PARAMETRES

dcmfile-in    Fichier image DICOM d'entrée ("-" pour stdin)
curvedata-in  Fichier de données de courbe d'entrée (texte)
dcmfile-out   Nom de fichier DICOM de sortie ("-" pour stdout)

OPTIONS

options générales

  -h   --help
         imprimer ce texte d'aide et quitter
       --version
         imprimer les informations de version et quitter
       --arguments
         imprimer les arguments étendus de la ligne de commande
  -q   --quiet
         mode silencieux, n'imprimer aucun avertissement ni erreur
  -v   --verbose
         mode verbeux, imprimer les détails du traitement
  -d   --debug
         mode débogage, imprimer les informations de débogage
  -ll  --log-level  [l]evel: chaîne de caractères
         (fatal, error, warn, info, debug, trace)
         utiliser le niveau l pour le logger
  -lc  --log-config  [f]ichier: chaîne de caractères
         utiliser le fichier de configuration f pour le logger

options de création de courbe

type de courbe:
  -r  --poly
        créer comme courbe POLY (par défaut)
  +r  --roi
        créer comme courbe ROI
représentation des valeurs de courbe:
  +v  --data-vr  [n]uméro: entier 0..4 (défaut: 4)
        sélectionner le VR des données de courbe : 0=US, 1=SS, 2=FL, 3=FD, 4=SL
  -c  --curve-vr  [n]uméro: entier 0..2 (défaut: 0)
        sélectionner le VR avec lequel l'élément Curve Data est écrit
        0=VR selon --data-vr, 1=OB, 2=OW
groupe répétitif:
  -g  --group  [n]uméro: entier 0..15 (défaut: 0)
        sélectionner le groupe répétitif : 0=0x5000, 1=0x5002 etc.
description de la courbe:
  -l  --label  s: chaîne de caractères
        définir le libellé de la courbe à s (défaut: absent)
  +d  --description  s: chaîne de caractères
        définir la description de la courbe à s (défaut: absent)
  -a  --axis  x: chaîne de caractères, y: chaîne de caractères
        définir les unités d'axe à x\y (défaut: absent)

NOTES

Syntaxe du fichier de données de courbe

Le fichier de données de courbe est attendu comme un fichier texte ASCII brut contenant des nombres (entiers ou à virgule flottante) formant les valeurs des coordonnées des points. Les nombres doivent être séparés par des espaces blancs. Aucune vérification de la plage de valeurs ou de conversion de plage de valeurs n'est effectuée. Exemple :

 256.451947    1.000000
 477.689863  128.822080
 128.822080  477.689863
  35.310137  128.822080
 256.451947    1.000000

JOURNALISATION

Le niveau de sortie de journalisation des divers outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seuls les erreurs et les avertissements sont écrits dans le flux d'erreurs standard. L'utilisation de l'option --verbose permet également de rapporter des messages informatifs tels que les détails du traitement. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés en utilisant l'option --log-level. En mode --quiet, seuls les erreurs fatales sont rapportées. Dans de tels événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, voir la documentation du module "oflog".

Si la sortie de journalisation doit être écrite dans un fichier (éventuellement avec rotation de fichier), vers syslog (Unix) ou le journal d'événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets indiquent des valeurs optionnelles (0-1), trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie 0 à n valeurs.

Les options de ligne de commande se distinguent des paramètres par un signe '+' ou '-' respectivement. Habituellement, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si des options s'excluent mutuellement, l'apparition la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

De plus, un ou plusieurs fichiers de commande peuvent être spécifiés en utilisant un signe '@' comme préfixe du nom de fichier (par exemple, @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (plusieurs espaces blancs sont traités comme un seul séparateur sauf s'ils apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite des lignes de commande trop longues et confuses (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

ENVIRONNEMENT

L'utilitaire dcmmkcrv tentera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH. Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé, sauf si le dictionnaire est intégré à l'application (par défaut pour Windows).

Le comportement par défaut doit être privilégié et la variable d'environnement DCMDICTPATH ne doit être utilisée que lorsque des dictionnaires de données alternatifs sont requis. La variable d'environnement DCMDICTPATH a le même format que la variable PATH du shell Unix, c'est-à-dire qu'un deux-points (":") sépare les entrées. Sur les systèmes Windows, un point-virgule (";") est utilisé comme séparateur. Le code du dictionnaire de données tentera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH. Il s'agit d'une erreur si aucun dictionnaire de données ne peut être chargé.
