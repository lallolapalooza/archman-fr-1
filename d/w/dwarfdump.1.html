DWARFDUMP() DWARFDUMP()

NOM

dwarfdump - affiche les informations de débogage DWARF d'un objet ELF

SYNOPSIS

dwarfdump [options] nomdefichierobjet

DESCRIPTION

La commande dwarfdump affiche ou vérifie les sections DWARF comme demandé par des options spécifiques. Sans options (mais avec le nomdefichierobjet requis), toutes les sections sont affichées (mais certaines sections ne peuvent pas être affichées indépendamment en toute sécurité, elles ne sont donc affichées qu'aux décalages où la section .debug_info fait référence à ces sections).

Pour les fichiers objets split-dwarf (DWARF5), voir Split Object Files, DWARF5 section 7.3.

Presque toutes les options sont disponibles dans la forme traditionnelle (lettre unique) et dans une forme d'options longues avec des noms significatifs. Les nouvelles options ne sont disponibles que sous la forme d'options longues.

Sans options, dwarfdump affiche un ensemble de base d'informations sur les sections DWARF. Si une option est donnée sur la ligne de commande, l'ensemble de base est ignoré et il faut indiquer à dwarfdump quoi afficher ou vérifier (par exemple en ajoutant l'option -a ).

Les options d'affichage et les options de vérification sont mutuellement exclusives (si des options de vérification sont sélectionnées, les détails de la section ne sont pas affichés). Lorsqu'une erreur est rencontrée, dwarfdump tente d'afficher un contexte suffisant pour que l'on puisse comprendre exactement où se trouve l'erreur dans le DWARF. Ce changement rend la vérification de fichiers objets très volumineux beaucoup plus facile.

Le format est destiné à être lisible par l'humain. Si un script doit analyser la sortie, l'option --format-dense (-d) est utile.

Les expressions DWARF sont réparties pour afficher chaque expression (DW_OP_plus par exemple) dans un bloc sur une ligne séparée. Pour restaurer le comportement précédent, un peu comme --format-dense mais s'appliquant uniquement aux blocs d'opérateurs d'expressions DWARF (DW_OP*), l'option --format-expr-ops-joined est utile. Si l'option est placée dans le fichier dwarfdump.conf (voir le fichier lui-même pour le format), elle s'appliquera sans avoir besoin de la mettre sur la ligne de commande.

Toutes les sections n'existent pas réellement dans un fichier objet donné.

Le format de sortie peut changer d'une version à l'autre, il est donc imprudent de dépendre trop du format.

Les informations de trame (.debug_frame et .eh_frame) dépendent fortement de l'ABI/ISA du fichier objet. Par défaut, nous utilisons un ensemble générique de noms de registres gérant jusqu'à 100 registres nommés r0-r99.

Il existe trois façons différentes dont les auteurs de compilateurs séparent les informations DWARF d'un exécutable/objet partagé. L'une est DWARF5 Split Dwarf (l'option --file-tied est utile pour ceux-ci). L'autre est GNU debuglink (libdwarf trouve automatiquement le DWARF lorsque le nom de l'exécutable est donné, utilisez --no-follow-debuglink pour supprimer cela et rendre possible l'impression des données de backtrace dans la section .eh_frame). La troisième façon est sur Macos : le DWARF de débogage est dans un objet séparé (dwarfdump/libdwarf le trouve automatiquement s'il est présent, --no-follow-debuglink supprime cette recherche). Voir aussi --suppress-debuglink-crc.

Dans de nombreux cas, on peut obtenir des détails supplémentaires en spécifiant -v (parfois -v -v en obtient encore plus, voir la discussion sur --verbose ci-dessous). Lors de l'impression des DIE (Debugging Information Entries), les options -G (affichage des décalages globaux) et -M (nommage des DW_FORM* des attributs) (ou leurs homologues --) peuvent être une grande aide pour comprendre le DWARF.

L'option --format-registers (-R) utilise un ensemble générique intégré de noms de registres gérant jusqu'à 1200 registres nommés r0-r1199.

La description de --file-abi=<abi> (-x abi=<abi>) ci-dessous montre comment nommer une abi et l'utiliser pour guider le traitement --print-frame (-f) ou --print-eh-frame (-F) .

L'une des options --print-frame (-f) ou --print-eh-frame (-F) implique beaucoup d'abi (noms de registres, nombres de registres) dans la sortie, mais les sections autres que les sections de trame peuvent également nécessiter des noms de registres.

À moins que le cpu du fichier objet en cours de dump n'ait beaucoup de registres, n'utilisez pas --format-registers ou -file-abi=<abi> car cela peut être inutilement lent pour dumper les sections de trame. Utilisez plutôt l'abi correcte (si elle existe dans dwarfdump.conf) ou une générique telle que --file-abi=abi=generic100 ou --file-abi=abi=generic500
.

Les choix d'abi les plus utiles sont probablement mips ou x86 ou x86_64 ou ppc ou arm
. Sans --format-registers (-R) ou -file-abi=<abi> (-x abi=<abi>) dwarfdump utilise un ensemble générique compilé de noms de registres. Si aucun --file-name=<path> (-x name=<path>) n'est donné, dwarfdump cherche "./dwarfdump.conf", "$HOME/dwarfdump.conf", "$HOME/.dwarfdump.conf", "<install-prefix>/lib/dwarfdump.conf" et prend le premier qu'il trouve. Utilisez l'option --show-dwarfdump-conf pour voir ce que dwarfdump trouve. Si un ou plusieurs --file-name=<path> (-x name=<path>) sont donnés, le dernier est utilisé et tous les autres fichiers de ce type sont ignorés.

VÉRIFICATION DES ERREURS

Certaines options de vérification ( -k) (voir "Check DWARF Integrity" dans la sortie d'aide) affichent les soi-disant erreurs inoffensives. Ce sont des erreurs de compilateur qui ne causent aucun problème connu et ne sont détectées qu'à l'intérieur de libdwarf lui-même. Elles sont difficiles à signaler correctement dans dwarfdump et les chaînes d'erreur peuvent ne pas apparaître à proximité du moment où l'erreur a été rencontrée.

Si un ou plusieurs attributs d'abréviation sont dupliqués dans une liste d'abréviations pour une certaine entrée d'information de débogage (une violation directe de la norme DWARF), vous constaterez que l'ajout de l'option --no-dup-attr-check aux options vous permettra de voir l'ensemble cassé d'attributs en modifiant un drapeau à l'intérieur de libdwarf lui-même. On pourrait utiliser l'option -kD pour découvrir quels attributs dupliqués existent dans le fichier objet.

Si la compression zlib a été utilisée sur les sections DWARF du fichier objet en cours de lecture, les vrais noms de sections tels que .zdebug_info etc seront signalés par dwarfdump. Lorsque dwarfdump dit que quelque chose est à l'offset 55 de .zdebug_info (ou le genre), gardez à l'esprit que l'offset s'applique à la section non compressée (en mémoire), pas à la section compressée .zdebug_ dans nomdefichierobjet.

CHAÎNES D'ENTRÉE DE STYLE URI

Le <nomdefichierobjet> et toutes les options prenant des chaînes de noms recherchent des URI et traduisent les chaînes URI en caractères par défaut. Ainsi, tout caractère % unique est traité comme si les deux caractères suivants étaient des chiffres hexadécimaux représentant le caractère réel sous-jacent. Divers caractères sont significatifs pour les shells (comme bash ou sh) et pour getopt (comme l'espace). Si la traduction URI fait quelque chose, elle imprime l'avant et l'après de la traduction URI sur la sortie standard, de sorte que l'examen des premières lignes de la sortie montrera si l'URI a fait quelque chose. Les options elles-mêmes sont supposées ne pas être des URI. Ainsi, dans l'option --format-producer=S&T (-cS&T) le caractère & pourrait causer des problèmes d'entrée, donc --format-producer=S%26T devrait être utilisé à la place. Pour entrer réellement un caractère % unique (dans un nom, par exemple), doublez-le en %% sur la ligne de commande (ou utilisez %25).

Les options --format-suppress-uri (-U) (désactiver l'interprétation URI) et --format-suppress-uri-msg (-q) (rendre silencieuse la recherche de séquences URI) donnent un contrôle plus fin de l'interprétation URI.

Par exemple, pour obtenir une chaîne 'a b', faites la chaîne 'a%20b' (ici le guillemet (') est pour l'exposition et ne fait pas partie de la chaîne, bien que le guillemet soit certainement problématique dans un nom). Au lieu d'échapper les guillemets " dans la chaîne, tapez %25, comme dans 'a "b' devrait être tapé 'a%20%25b'. N'importe quels caractères peuvent être tapés en style URI, pas seulement les caractères problématiques pour le shell ou getopt. Nous vous suggérons fortement de ne pas taper de caractères en style URI là où cela n'est pas nécessaire ou d'utiliser le caractère % lui-même dans les chaînes de ligne de commande, sauf si vous devez.

SORTIE DE STYLE URI (impression)

Dwarfdump traduit tous les caractères dans les chaînes qui ne sont pas des ASCII imprimables ordinaires (et certains qui le sont) à l'inverse de la section précédente. Il imprime dans une sortie de style uri sous la forme %xx, où xx sont des chiffres hexadécimaux sous la forme ASCII 0-9a-f. Le caractère pourcentage (%) est imprimé comme '%25'.

C'est une façon maladroite de gérer les chaînes UTF-8 et une façon sensée de gérer les faibles valeurs ASCII qui sur de nombreux systèmes font que votre terminal se comporte étrangement.

TRADUCTIONS

Les traductions ne sont pas idempotentes, donc dwarfdump évite de traduire une chaîne plus d'une fois. Voir l'option --format-suppress-sanitize ci-dessous pour éliminer la transformation de la sortie.

MODIFICATEURS D'OPTIONS

--format-extensions (-C)
Il s'agit d'une option secondaire après --check-tag-tag (-kt) ou --check-tag-attr (-kr). Normalement, lors de la vérification des combinaisons tag-tag ou tag-attribut, à la fois les combinaisons standard et certaines extensions courantes sont autorisées (non signalées). Avec cette option, les extensions sont retirées de la classe des combinaisons autorisées.
-kuf (--check-usage-extended)
Cela modifie --check-tag-attr (-kr) ou --check-usage (-ku) pour imprimer des détails supplémentaires dans le résumé. Ajoutez le -kuf (--check-usage-extended) avant ou après l'option qu'il modifie.
--format-dense (-d)
Lors de l'impression des DIE, met tous les attributs de chaque DIE sur la même ligne (longue) que la TAG. Cela rend la recherche d'informations sur les DIE (comme avec grep) beaucoup plus simple car le DIE entier est sur une seule ligne.
--format-suppress-offsets (-D)
Désactive l'affichage des décalages de section et des valeurs d'attributs dans la sortie imprimée. Ainsi, la sortie .debug_info ne contient que les TAG et les Attributs. Pour les pubnames (et similaires), cela supprime les décalages de la sortie. Pour les listes de localisations, cela supprime les décalages de la sortie, mais cela est inutile car les valeurs d'attributs ne sont pas affichées, donc les données de localisation non plus.
--format-ellipsis (-e)
Active la troncature des noms d'attributs et de tags. Par exemple DW_TAG_foo devient foo. Non compatible avec la vérification, seulement utile pour imprimer les DIE.
--format-global-offsets (-G)
Lors de l'impression, ajoute les décalages globaux aux décalages imprimés.
--format-limit=<num> (-H number)
Lors de l'impression ou de la vérification de .debug_info, cela termine la recherche après 'number' unités de compilation. Lors de l'impression des informations de trame, cela termine le rapport des FDE après 'number' FDE et le rapport des CIE (qui se produit si on ajoute -v) après 'number' CIE. Exemple '--format-limit=1'
--format-attr-name (-M)
Lors de l'impression, montre le FORM pour chaque attribut. Si un -v est ajouté (ou plus d'un), les détails de toute indirection de forme sont également montrés.
--format-suppress-lookup (-n)
Lors de l'impression des trames, cela désactive la recherche de noms de fonctions dans les portées internes. À moins que la langue utilisée pour construire le fichier objet ne prenne en charge les définitions de fonctions dans les portées internes, il est inutile de chercher des noms de fonctions dans les portées internes. Et pour un objet vraiment volumineux, la recherche peut prendre plus de temps que ce que l'on souhaite attendre. Cette option supprime la recherche dans les portées internes.
--file-output=<path> (-Ofile=<path>)
Le <path> sera utilisé comme nom de fichier pour la sortie au lieu d'écrire sur stdout (stdout est la valeur par défaut).
--format-suppress-data (-Q)
Supprime l'impression des données de section (défini automatiquement avec une option de vérification).
--format-suppress-sanitize
Supprime les traductions d'impression de chaînes par défaut afin que les caractères non-ascii et non-imprimables du fichier objet soient imprimés tels quels. Voir "SORTIE DE STYLE URI" ci-dessus.
--format-suppress-uri (-U)
Supprime la traduction URI par défaut des options suivantes sur la ligne de commande. Voir "CHAÎNES D'ENTRÉE DE STYLE URI" ci-dessus.
--format-registers (-R)
Lors de l'impression des trames pour les ABI avec beaucoup de registres, cela permet de nommer jusqu'à 1200 registres (comme R999) sans choisir un ABI avec, par exemple '-x abi=ppc' ou, de manière équivalente, '--file-abi=ppc'
--verbose (-v)
Augmente le niveau de détail affiché lors de l'impression. Dans certaines sections, l'utilisation de plus d'options -v augmentera le détail (de une à quatre sont utiles) ou peut changer le rapport pour montrer, par exemple, les commandes de données de ligne réelles au lieu de la table de lignes résultante. Deux à quatre options -v font une différence lors de l'impression des DIE et rnglists (-i), lignes (-l), trames (-f,-F), gdb_index(-I). Des -v supplémentaires au-delà de quatre n'ajoutent actuellement pas à ou ne changent pas la sortie.
--show-dwarfdump-conf
Montre quels fichiers sont vérifiés pour trouver un dwarfdump.conf et ses tables de noms de registres.

LIMITATION DE LA SORTIE

L'option de limitation la plus simple est d'arrêter l'examen/l'impression après <num> unités de compilation. Voir -H et --format-limit ci-dessus. Cette option limite également le nombre de FDE et CIE imprimés à partir de n'importe quelle section .debug_frame ou .eh_frame.

Les options --search (-S) impriment des informations sur l'unité de compilation et le DIE où la ou les chaînes apparaissent. Elles ne peuvent pas être combinées avec d'autres options. Au plus un de chacune des options suivantes est efficace (ainsi, par exemple, on ne peut avoir qu'un seul 'match', mais on peut avoir un 'match', un 'any', et un 'regex'). Tout --search (-S) provoque l'inspection de la section .debug_info. Aucune option de vérification ou d'impression ne doit être fournie avec les options --search(-S). Les chaînes doivent utiliser le style URI pour éviter tout conflit avec le analyseur de ligne de commande applicable (bash, sh, ...) ou getopt(), ainsi que l'utilisation de l'URI pour gérer la recherche de chaînes en non-ASCII comme le français, (etc) ou le maintenant quasi-universel UTF8. L'implémentation des expressions régulières n'autorise que l'ASCII dans l'expression et l'expression ne traite que les expressions régulières de base, qui sont comme les Expressions Régulières de Base Posix (PBRE), mais le constructif de regroupement () dans PBRE semble inutile ici, nous suggérons donc de ne pas utiliser () le regroupement

Celles-ci sont particulièrement utiles lorsque la quantité d'informations DWARF produite par -i est de plusieurs gigaoctets de données.

Si -Sv est utilisé au lieu de -S, le nombre d'occurrences est imprimé. (voir ci-dessous pour un exemple).

--search-match=<string> (-Smatch=string)
--search-match-count=<string> (-Svmatch=string)
Lors de l'impression des DIE, pour chaque valeur de tag ou nom d'attribut qui correspond exactement à 'string', imprime les informations de l'unité de compilation et son décalage de section. Toute CU sans correspondance n'est pas imprimée. La 'string' est lue comme une chaîne URI. La forme count (Sv) rapporte le nombre d'occurrences.
--search-any=<string> (-Sany=string)
--search-any-count=<string> (-Svany=string)
Lors de l'impression des DIE, pour chaque valeur de tag ou nom d'attribut qui contient 'string' quelque part dans le tag ou l'attribut (insensible à la casse), imprime les informations de l'unité de compilation et son décalage de section. Toute CU sans correspondance n'est pas imprimée. La 'string' est lue comme une chaîne URI. La forme count (Sv) rapporte le nombre d'occurrences.
--search-regex=string (-Sregex=string)
--search-regex-count=string (-Svregex=string)
Lors de l'impression des DIE, pour chaque valeur de tag ou nom d'attribut où l'expression régulière 'string' correspond, imprime les informations de l'unité de compilation et son décalage de section. Toute CU sans correspondance n'est pas imprimée. La 'string' est lue comme une chaîne URI. La forme count (Sv) rapporte le nombre d'occurrences.

La chaîne ne peut pas avoir d'espaces ou d'autres caractères qui sont significatifs pour getopt(3) et le shell supprimera les guillemets et autres caractères. Ainsi, la chaîne est supposée être en style URI et est traduite. En d'autres termes, pour correspondre à 'a b', faites que la chaîne -S soit 'a%20b' Au lieu de échapper les guillemets " dans la chaîne, tapez %25, comme dans
'a "b' devrait être tapé 'a%20%25b' (les ' sont pour l'exposition ici, pas partie des chaînes). N'importe quels caractères peuvent être tapés en style URI, pas seulement les caractères qui sont problématiques pour le shell ou getopt.

Les --search-any (-Sany) et --regex-any (-Sregex) ne sont utilisables que si les expressionsles fonctions de la bibliothèque d'expressions requises sont trouvées au moment de la configuration.

L'option --search-print (-W) est un modificateur de l'option -S, et augmente la quantité de sortie imprimée par -S. Un exemple de modificateur pour l'option -S est montré ci-dessous. Et nous montrons -W dans le contexte avec une option -S.

SPLIT DWARF

Avec Split Dwarf (DWARF5), le corps principal du DWARF est dans un fichier séparé, souvent ayant le suffixe de nom .dwp ou .dwo .

Par exemple, si /path/to/myapp.dwp est l'objet split-dwarf et /path/to/myapp est l'exécutable, faire "dwarfdump --file-tied=/path/to/myapp /path/to/myapp.dwp" . Le chemin du fichier lié nomme l'exécutable qui possède la section .debug_addr et d'autres sections qui peuvent être référencées depuis l'objet .dwo/.dwp.

Voir Split Object Files (parfois appelé Debug Fission) dans la norme DWARF5, section 7.3.

NOTES

À partir de la version 2.2.0, dwarfdump vérifiera les FORMS de bloc tels que DW_FORM_block2 (etc) pour un contenu qui ressemble à une chaîne UTF8 valide. Tout tel contenu est imprimé en hexadécimal avec un 0x initial et se terminant par deux-points (:). Ensuite, la chaîne (si plus longue que 1 octet et moins de 5000 octets de long) est imprimée avec un "Block As Quoted String " initial qui est là pour rendre la recherche de telles chaînes dans la sortie de dwarfdump relativement simple.

Dans certains cas, les compilateurs utilisent DW_FORM_data1 (par exemple) et dans de tels cas, le signe de la valeur doit être déduit du contexte. Plutôt que d'essayer de déterminer le contexte, dwarfdump imprime la valeur avec les deux signes chaque fois qu'il y a ambiguïté sur l'interprétation correcte. Par exemple, "DW_AT_const_value 176(as signed = -80)". Pour les consommateurs DWARF normaux qui évaluent correctement et complètement tous les attributs, il n'y a pas d'ambiguïté de signe : l'ambiguïté pour dwarfdump est due au fait que dwarfdump évalue les DIEs dans un ordre simple et ne garde pas trace de beaucoup de contexte.

    DESCRIPTION

    dwarfdump est un outil qui lit les informations DWARF (Debugging With Attributed Record Formats) d'un fichier objet (par exemple, un fichier ELF) et les affiche dans un format lisible. Les informations DWARF sont utilisées par les débogueurs et d'autres outils de développement pour comprendre la structure d'un programme compilé, y compris les variables, les fonctions, les types, etc.

    OPTIONS

    dwarfdump accepte un certain nombre d'options pour contrôler le type et le format de la sortie. Les options courantes incluent :

    • -a, --all : Affiche toutes les sections DWARF.
    • -o, --only=[section,...] : Affiche uniquement les sections spécifiées.
    • -e, --exclude=[section,...] : Exclut les sections spécifiées de la sortie.
    • -f, --format=[format] : Spécifie le format de sortie. Les formats disponibles peuvent inclure human (lisible par l'homme), json, xml, etc.
    • -r, --relocs : Affiche les informations de relocalisation.
    • -v, --verbose : Augmente le niveau de détail de la sortie.
    • -h, --help : Affiche l'aide et quitte.
    • -V, --version : Affiche les informations de version et quitte.

    Pour une liste complète des options, consultez la page de manuel (man dwarfdump) ou utilisez l'option --help.

    LIMITER LA SORTIE

    Vous pouvez limiter la sortie en spécifiant les sections à inclure ou à exclure. Par exemple, pour afficher uniquement les informations de la section .debug_info :

    dwarfdump -o .debug_info votre_fichier_objet

    Pour exclure les informations de relocalisation :

    dwarfdump -e .debug_info_reloc votre_fichier_objet

    AUTRES OPTIONS

    Il existe d'autres options pour contrôler la façon dont les informations sont affichées, comme le filtrage par ligne de code source, le nom de fonction, etc. Ces options sont généralement utilisées pour des analyses plus ciblées.

    SPLIT DWARF

    dwarfdump peut également gérer les informations DWARF divisées (split DWARF), où les informations de débogage sont stockées dans des fichiers séparés. Cela est courant dans les environnements de développement où les fichiers binaires sont distribués sans les informations de débogage complètes.

    FICHIERS

    dwarfdump opère sur des fichiers objets, généralement des fichiers ELF (Executable and Linkable Format) tels que les exécutables, les bibliothèques partagées ou les fichiers objet compilés.

    NOTES

    Les informations DWARF peuvent être volumineuses. Utilisez les options de filtrage et de formatage appropriées pour rendre la sortie gérable.

    La structure et le contenu des informations DWARF peuvent varier en fonction du compilateur, des options de compilation et de la version du standard DWARF utilisée.
