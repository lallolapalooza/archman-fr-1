NOM

dub-test - Exécute les tests du paquet sélectionné

SYNTAXE

dub test [<paquet>[@<spécification-version>]] OPTIONS... [-- <arguments-application...>]

DESCRIPTION

Compile le paquet et exécute tous les tests unitaires contenus.

Si aucune configuration explicite n'est donnée, une configuration existante "unittest" sera préférée pour les tests. Si aucune n'existe, la première configuration de type bibliothèque sera utilisée, et si elle n'existe pas non plus, la première configuration exécutable sera choisie.

Lorsqu'un fichier principal personnalisé (--main-file) est spécifié, seules les configurations de bibliothèque peuvent être utilisées. Sinon, selon le type de la configuration sélectionnée, un fichier principal existant sera utilisé (et devra être correctement ajusté pour simplement exécuter les tests unitaires pour 'version(unittest)'), ou DUB en générera un pour les configurations de type bibliothèque.

Enfin, si le paquet contient une dépendance au paquet "tested", le fichier principal généré automatiquement l'utilisera pour exécuter les tests unitaires.

OPTIONS

--temp-build

Compile le projet dans le dossier temporaire si possible.

--main-file=VALEUR

Spécifie un fichier personnalisé contenant la fonction main() à utiliser pour exécuter les tests.

--combined

Essaie de compiler l'ensemble du projet en une seule passe du compilateur.

--parallel

Exécute plusieurs instances du compilateur en parallèle, si possible.

-f, --force

Force une recompilation même si la cible est à jour

--coverage

Active la génération de statistiques de couverture de code.

--coverage-ctfe

Active la génération de statistiques de couverture de code (y compris CTFE).

-b, --build=VALEUR

Spécifie le type de compilation à effectuer. Notez que la définition de la variable d'environnement DFLAGS remplacera le type de compilation par des indicateurs personnalisés. Noms possibles :
debug, plain, release, release-debug, release-nobounds, unittest, profile, profile-gc, docs, ddox, cov, cov-ctfe, unittest-cov, unittest-cov-ctfe, syntax et types personnalisés

-c, --config=VALEUR

Compile la configuration spécifiée. Les configurations peuvent être définies dans dub.json

--override-config=VALEUR

Utilise la configuration spécifiée pour une certaine dépendance. Peut être spécifié plusieurs fois. Format : --override-config=<dépendance>/<config>

--compiler=VALEUR

Spécifie le binaire du compilateur à utiliser (peut être un chemin). Les préfixes et suffixes arbitraires aux identifiants ci-dessous sont reconnus (par exemple, ldc2 ou dmd-2.063) et correspondent au type de compilateur approprié :
dmd, gdc, ldc, gdmd, ldmd

-a, --arch=VALEUR

Force une architecture différente (par exemple, x86 ou x86_64)

-d, --debug=VALEUR

Définit l'identifiant de version `debug` spécifié lors de la compilation - peut être utilisé plusieurs fois

--d-version=VALEUR

Définit l'identifiant de version `version` spécifié lors de la compilation - peut être utilisé plusieurs fois. À utiliser avec parcimonie, avec un grand pouvoir vient une grande responsabilité ! Pour les versions couramment utilisées ou combinées et les versions que les dépendants devraient pouvoir utiliser, créez des configurations dans votre paquet.

--nodeps

Ne résout pas les dépendances manquantes avant la compilation

--build-mode=VALEUR

Spécifie la manière dont le compilateur et l'éditeur de liens sont invoqués. Valeurs valides :
separate (par défaut), allAtOnce, singleFile

--single

Traite le nom du paquet comme un nom de fichier. Le fichier doit contenir un commentaire de recette de paquet.

--force-remove

Option obsolète qui ne fait rien.

--filter-versions

[Expérimental] Filtre les identifiants de version et les identifiants de version de débogage pour améliorer l'efficacité du cache de compilation.

OPTIONS COMMUNES

Voir dub(1)

STATUT DE SORTIE

0
DUB a réussi
1
erreurs d'utilisation, drapeaux de ligne de commande inconnus
2
paquet introuvable, échec du chargement du paquet, erreur diverse
