DUMPKEYS(1) Manuel des commandes générales DUMPKEYS(1)

NOM

dumpkeys - dumper les tables de traduction du clavier

SYNTAXE

dumpkeys [OPTIONS]

DESCRIPTION

dumpkeys écrit sur la sortie standard le contenu actuel des tables de traduction du pilote du clavier, dans le format spécifié par keymaps(5).

En utilisant les diverses options, le format de la sortie peut être contrôlé et d'autres informations du noyau et des programmes dumpkeys(1) et loadkeys(1) peuvent être obtenues.

OPTIONS

-h --help
Affiche le numéro de version du programme et un court message d'utilisation sur la sortie d'erreur standard du programme et quitte.
-i --short-info
Affiche quelques caractéristiques du pilote du clavier du noyau. Les éléments affichés sont :
Plage de codes de touches supportée par le noyau
Ceci indique quelles valeurs peuvent être utilisées après le mot-clé keycode dans les fichiers de table de touches. Voir keymaps(5) pour plus d'informations et la syntaxe de ces fichiers.

Nombre d'actions pouvant être liées à une touche

Ceci indique combien d'actions différentes une seule touche peut produire en utilisant diverses touches modificatrices. Si la valeur est de 16 par exemple, vous pouvez définir jusqu'à 16 actions différentes pour une touche combinée avec des modificatrices. Lorsque la valeur est de 16, le noyau connaît probablement quatre touches modificatrices, que vous pouvez appuyer dans différentes combinaisons avec la touche pour accéder à toutes les actions liées.

Plages de codes d'actions supportées par le noyau

Cet élément contient une liste de plages de codes d'actions en notation hexadécimale. Ce sont les valeurs qui peuvent être utilisées du côté droit d'une définition de touche, c'est-à-dire les vv dans une ligne
keycode xx = vv vv vv vv

(voir keymaps(5) pour plus d'informations sur le format des lignes de définition de touches). dumpkeys(1) et loadkeys(1) supportent une notation symbolique, qui est préférable à la notation numérique, car les codes d'actions peuvent varier d'un noyau à l'autre tandis que les noms symboliques restent généralement les mêmes. Cependant, la liste des plages de codes d'actions peut être utilisée pour déterminer si le noyau supporte effectivement tous les symboles que loadkeys(1) connaît, ou s'il existe peut-être des actions supportées par le noyau qui n'ont pas de nom symbolique dans votre programme loadkeys(1). Pour cela, comparez la liste des plages avec la liste des symboles d'actions, voir l'option --long-info ci-dessous.

Nombre de touches de fonction supportées par le noyau

Ceci indique le nombre de codes d'actions qui peuvent être utilisés pour produire des chaînes de caractères. Ces codes d'actions sont traditionnellement liés aux diverses touches de fonction et d'édition du clavier et sont définis pour envoyer des séquences d'échappement standard. Cependant, vous pouvez les redéfinir pour envoyer des lignes de commande courantes, des adresses e-mail ou tout ce que vous voulez. Surtout si le nombre de cet élément est supérieur au nombre de touches de fonction et d'édition de votre clavier, vous pourriez avoir des codes d'actions « de secours » que vous pouvez lier à des combinaisons AltGr-lettre, par exemple, pour envoyer des chaînes utiles. Voir loadkeys(1) pour plus de détails.

Chaînes de fonction

Vous pouvez voir vos définitions actuelles de touches de fonction avec la commande
dumpkeys --funcs-only
-l -s --long-info
Cette option demande à dumpkeys d'afficher une liste d'informations détaillée. La sortie est la même qu'avec --short-info, avec en plus la liste des symboles d'actions supportés par loadkeys(1) et dumpkeys(1), ainsi que les valeurs numériques des symboles.
-n --numeric
Cette option fait que dumpkeys contourne la conversion des valeurs de codes d'actions en notation symbolique et affiche plutôt les valeurs au format hexadécimal.
-f --full-table
Ceci fait que dumpkeys ignore toutes les heuristiques de raccourci (voir keymaps(5)) et affiche les liaisons de touches sous forme canonique. D'abord, une ligne de table de touches décrivant les combinaisons de modificateurs actuellement définies est affichée. Ensuite, pour chaque touche, une ligne avec une colonne pour chaque combinaison de modificateurs est imprimée. Par exemple, si la table de touches actuellement utilisée utilise sept modificateurs, chaque ligne aura sept colonnes de codes d'actions. Ce format peut être utile, par exemple, pour les programmes qui traitent la sortie de dumpkeys.
-Sforme --shape=forme
Formes disponibles :
2 sortie par défaut.
4 une ligne par code de touche.
8 une ligne par paire (modificateur, code de touche).
16 une ligne par code de touche jusqu'au premier trou.
-1 --separate-lines
Ceci force dumpkeys à écrire une ligne par paire (modificateur, code de touche). Il préfixe le mot plain pour les codes de touches simples.
-t --funcs-only
Lorsque cette option est donnée, dumpkeys affiche uniquement les définitions de chaînes de touches de fonction. Normalement, dumpkeys affiche à la fois les liaisons de touches et les définitions de chaînes.
-k --keys-only
Lorsque cette option est donnée, dumpkeys affiche uniquement les liaisons de touches. Normalement, dumpkeys affiche à la fois les liaisons de touches et les définitions de chaînes.
-d --compose-only
Lorsque cette option est donnée, dumpkeys affiche uniquement les combinaisons de touches de composition. Cette option n'est disponible que si votre noyau supporte la touche de composition.
-cjeu_de_caracteres --charset=jeu_de_caracteres
Ceci demande à dumpkeys d'interpréter les valeurs des codes de caractères selon le jeu de caractères spécifié. Cela n'affecte que la traduction des valeurs des codes de caractères en noms symboliques. Les valeurs valides pour jeu_de_caracteres sont actuellement iso-8859-X, où X est un chiffre de 1 à 9. Si aucun jeu_de_caracteres n'est spécifié, iso-8859-1 est utilisé par défaut. Cette option produit une ligne de sortie `charset "iso-8859-X"', indiquant à loadkeys comment interpréter la table de touches. (Par exemple, « division » est 0xf7 en iso-8859-1 mais 0xba en iso-8859-8.)
-Cpériph --console=périph
Le périphérique de console concerné peut être spécifié à l'aide de l'option -C (ou --console). Cette option supporte exactement un nom de périphérique.
-v --verbose
Active la sortie détaillée.
-V --version
Affiche le numéro de version et quitte.

FICHIERS

/usr/share/kbd/keymaps
Le répertoire recommandé pour les fichiers de table de touches.

VOIR AUSSI

loadkeys(1), keymaps(5)
