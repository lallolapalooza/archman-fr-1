NOM

dune-init - Groupe de commandes pour initialiser les composants Dune.

SYNTAXE

dune init project NOM [CHEMIN] [OPTION]...

dune init executable NOM [CHEMIN] [OPTION]...

dune init library NOM [CHEMIN] [OPTION]...

dune init test NOM [CHEMIN] [OPTION]...

DESCRIPTION

dune init COMPOSANT NOM [CHEMIN] [OPTION]... initialise une nouvelle configuration dune pour un composant du type spécifié par la sous-commande COMPOSANT, nommé NOM, avec des champs déterminés par les OPTIONs fournies.

Exécutez une sous-commande avec --help pour plus de détails sur les arguments supportés.

Si le CHEMIN optionnel est fourni, il doit s'agir d'un chemin vers un répertoire, et le composant y sera créé. Sinon, il est créé dans un sous-répertoire du répertoire de travail courant, nommé NOM. Pour initialiser un composant dans le répertoire de travail courant, utilisez `.` comme CHEMIN.

Toute préfixe du nom d'une COMMANDE peut être fournie à la place du nom complet (comme illustré dans la syntaxe).

Pour plus de détails, voir https://dune.readthedocs.io/en/stable/usage.html#initializing-components

COMMANDES

executable [OPTION]… NOM [CHEMIN]
Un exécutable binaire.
library [OPTION]… NOM [CHEMIN]
Une bibliothèque OCaml.
project [OPTION]… NOM [CHEMIN]
Un projet est une composition prédéfinie de composants arrangés dans une structure de répertoires standard. Le type de projet initialisé est déterminé par la valeur de l'indicateur --kind et par défaut un projet exécutable, composé d'une bibliothèque, d'un exécutable et d'un composant de test.
test [OPTION]… NOM [CHEMIN]
Un banc d'essai. (Pour les tests intégrés, utilisez l'indicateur --inline-tests avec les autres types de composants.)

OPTIONS COMMUNES

--help[=FMT] (par défaut=auto)
Afficher cette aide dans le format FMT. La valeur FMT doit être l'une des suivantes : auto, pager, groff ou plain. Avec auto, le format est pager ou plain lorsque la variable d'environnement TERM est dumb ou indéfinie.
--version
Afficher les informations sur la version.

STATUT DE SORTIE

dune init se termine avec :

0
en cas de succès.
1
si une erreur s'est produite.
130
s'il a été interrompu par un signal.

EXEMPLES

1.
Générer un squelette de projet pour un exécutable nommé `myproj' dans un nouveau répertoire nommé `myproj', dépendant de la bibliothèque bos et utilisant des tests intégrés avec ppx_inline_test :
      dune init project myproj --libs bos --ppx ppx_inline_test --inline-tests
2.
Configurer un composant exécutable nommé `myexe' dans un fichier dune du répertoire courant :
      dune init executable myexe
3.
Configurer un composant bibliothèque nommé `mylib' dans un fichier dune du répertoire ./src dépendant des bibliothèques core et cmdliner, des préprocesseurs ppx_let et ppx_inline_test, et déclaré comme utilisant des tests intégrés :
      dune init library mylib src --libs core,cmdliner --ppx ppx_let,ppx_inline_test --inline-tests
4.
Configurer un composant de test nommé `mytest' dans un fichier dune du répertoire ./test qui dépend de `mylib' :
      dune init test mytest test --libs mylib
