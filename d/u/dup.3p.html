Paquet: man-pages

DUP(3P) Manuel du programmeur POSIX DUP(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

dup, dup2 — dupliquer un descripteur de fichier ouvert

SYNOPSIS

#include <unistd.h>
int dup(int fildes);
int dup2(int fildes, int fildes2);

DESCRIPTION

La fonction dup() fournit une interface alternative au service fourni par fcntl() en utilisant la commande F_DUPFD. L'appel dup(fildes) sera équivalent à :

fcntl(fildes, F_DUPFD, 0);

La fonction dup2() fera en sorte que le descripteur de fichier fildes2 se réfère à la même description de fichier ouverte que le descripteur de fichier fildes et partage les verrous éventuels, et retournera fildes2. Si fildes2 est déjà un descripteur de fichier valide et ouvert, il sera d'abord fermé, sauf si fildes est égal à fildes2, auquel cas dup2() retournera fildes2 sans le fermer. Si la fermeture échoue à fermer fildes2, dup2() retournera -1 sans modifier la description de fichier ouverte à laquelle fildes2 se réfère. Si fildes n'est pas un descripteur de fichier valide, dup2() retournera -1 et ne fermera pas fildes2. Si fildes2 est inférieur à 0 ou supérieur ou égal à {OPEN_MAX}, dup2() retournera -1 avec errno défini à [EBADF].

En cas de succès, si fildes n'est pas égal à fildes2, l'indicateur FD_CLOEXEC associé à fildes2 sera effacé. Si fildes est égal à fildes2, l'indicateur FD_CLOEXEC associé à fildes2 ne sera pas modifié.

Si fildes se réfère à un objet de mémoire typé, le résultat de la fonction dup2() n'est pas spécifié.

VALEUR DE RETOUR

En cas de succès, un entier non négatif, c'est-à-dire le descripteur de fichier, sera retourné ; sinon, -1 sera retourné et errno sera défini pour indiquer l'erreur.

ERREURS

La fonction dup() échouera si :

EBADF
L'argument fildes n'est pas un descripteur de fichier valide et ouvert.
EMFILE
Tous les descripteurs de fichiers disponibles pour le processus sont actuellement ouverts.

La fonction dup2() échouera si :

EBADF
L'argument fildes n'est pas un descripteur de fichier valide et ouvert ou l'argument fildes2 est négatif ou supérieur ou égal à {OPEN_MAX}.
EINTR
La fonction dup2() a été interrompue par un signal.

La fonction dup2() peut échouer si :

EIO
Une erreur d'E/S s'est produite lors de la tentative de fermeture de fildes2.

Les sections suivantes sont informatives.

EXEMPLES

Redirection de la sortie standard vers un fichier S

L'exemple suivant ferme la sortie standard pour le processus actuel, réaffecte la sortie standard pour aller vers le fichier référencé par pfd, et ferme le descripteur de fichier d'origine pour nettoyer.

#include <unistd.h>
...
int pfd;
...
close(1);
dup(pfd);
close(pfd);
...

Redirection des messages d'erreur

L'exemple suivant redirige les messages de stderr vers stdout.

#include <unistd.h>
...
dup2(1, 2);
...

USAGE PAR L'APPLICATION

Les implémentations peuvent utiliser des descripteurs de fichiers qui doivent être hérités par les processus fils pour que le processus fils reste conforme, par exemple à des fins de catalogue de messages ou de traçage. Par conséquent, une application qui appelle dup2() avec un entier arbitraire pour fildes2 risque un comportement non conforme, et dup2() ne peut être utilisée de manière portable que pour remplacer des valeurs de descripteurs de fichiers que l'application a obtenues par des actions explicites, ou pour les trois descripteurs de fichiers correspondant aux flux de fichiers standard. Afin d'éviter une condition de concurrence de fuite d'un descripteur de fichier non intentionnel vers un processus fils, une application devrait envisager d'ouvrir tous les descripteurs de fichiers avec l'indicateur FD_CLOEXEC défini, sauf si le descripteur de fichier est destiné à être hérité lors d'un exec.

RATIONNEL

La fonction dup() est redondante. Ses services sont également fournis par la fonction fcntl(). Elle a été incluse dans ce volume de POSIX.1‐2017 principalement pour des raisons historiques, car de nombreuses applications existantes l'utilisent. En revanche, la fonction dup2() fournit des services uniques, car aucune autre interface n'est capable de remplacer atomiquement un descripteur de fichier existant.

La fonction dup2() n'est pas marquée comme obsolète car elle présente une version type-safe de fonctionnalités fournies dans une version type-unsafe par fcntl(). Elle est utilisée dans la liaison Ada POSIX.

La fonction dup2() n'est pas destinée à être utilisée dans des régions critiques comme mécanisme de synchronisation.

Dans la description de [EBADF], le cas où fildes est hors limites est couvert par le cas donné où fildes n'est pas valide. Les descriptions de fildes et fildes2 sont différentes car le seul type d'invalidité pertinent pour fildes2 est s'il est hors limites ; c'est-à-dire qu'il n'importe pas si fildes2 fait référence à un fichier ouvert lors de l'appel à dup2().
