Avertisseme

nt

N'assignez pas le même modificateur à deux touches que vous prévoyez de presser en même temps, car elles interféreront l'une avec l'autre. Utilisez les versions gauche et droite des modificateurs, par ex. alt-tab avec space-caps

:

  - KEY: KEY_CAPSLOCK
TAP: KEY_TAB HOLD: KEY_LEF

Multiples

Dispositifs

Lors de l'utilisation d'entrées provenant de plusieurs dispositifs, par ex. ctrl-scroll, il peut être nécessaire de multiplexer (https://gitlab.com/interception/linux/tools#mux) ces dispositifs pour que dual-function-keys fonctionne à travers ces dispositifs par ex. le défilement consommant

ctrl.

Exemple de configuration udevmon pour une souris et un clavier

: 
- CMD: mux -c dfk -c my-keyboard -c my-mouse
- JOB:
  - mux -i dfk | dual-function-keys -c /etc/interception/dual-function-keys/my-cfg.yaml | mux -o my-
keyboard -o my-mouse - mux -i my-keyboard | uinput -c /etc/interception/udevmon.d/my-keyboard.yaml - mux -i my-mouse | uinput -c /etc/interception/ud
evmon.d/my-mouse.yaml - JOB: intercept -g $DEVNODE | mux -o dfk DEVICE: NAME: AT Translated Set 2 keyboard EVENTS: EV_KEY: [ KEY_LEFTCTRL
] - JOB: intercept -g $DEVNODE | mux -o dfk DEVICE: NAME: Razer Razer Naga Trinity EVENTS: EV_REL: [REL_WHEEL] EV_KEY: [BTN_LEFT]

Dans l'exemple ci-dessus, my-keyboard.yaml et my-mouse.yaml représentent les dispositifs virtuels que udevmon créera pour sortir les événements. Ils sont générés une fois à partir du dispositif lui-même, par

ex. 
sudo uinput -p -d
/dev/input/by-id/u
sb-my-keyboard-kbd
> my-keyboard.yaml

Une alternative, si vous voulez vivre dangereusement (https://gitlab.com/interception/linux/plugins/dual-function-keys/-/issues/31#note_725722450), est de générer la configuration du dispositif virtuel à la volée, par ex.

: 
- CMD: mux -c dfk -c my-keyboard -c my-mouse
- JOB:
  - mux -i dfk | dual-function-keys -c /etc/interception/dual-function-keys/my-cfg.yaml | mux -o my-keyboard -o my-mouse
  - mux -i my-keyboard | uinput -d /dev/input/by-path/my-keyboard-event-kbd
  - mux -i my-mouse | uinput -d /dev/input/by-id/usb-my-mouse-event-mouse
- JOB: intercept -g $DEVNODE | mux -o dfk
  DEVICE:
    LINK: /dev/input/by-path/my-keyboard-event-kbd

MISES EN

GARDE

Comme toujours, il y a une mise en garde : dual-function-keys opère sur les keycodes bruts keycodes, pas les keysyms, tels que vus par X11 ou

Wayland.

Si vous avez quelque chose qui modifie le mappage keycode->keysym, comme XKB (https://www.x.org/wiki/XKB/) ou xmodmap (https://wiki.archlinux.org/index.php/Xmodmap), soyez conscient que dual-function-keys opère avant

eux.

Quelques usages courants de XKB qui pourraient être trouvés dans votre configuration X11

: 
    Option "XkbModel" "pc105
" Option "XKbLayout"
"us" Option "XkbVari
ant" "dvp" Option "X
kbOptions" "caps:escape"
