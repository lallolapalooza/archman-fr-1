DESCRIPTIO

N

Gère le projet DUB dans le répertoire courant. DUB peut servir de système de co

mpilation et de gestionnaire de paquets, en gardant automatiquement une trace de
s dépendances du projet - en les téléchargeant et en les liant à l'application.

Initialise un paquet vide du type spécifié dans le répertoire donné. Par défaut, le répertoire de travail courant est utilisé.

Des modèles personnalisés peuvent être définis par les paquets en fournissant un sous-paquet appelé "init-exec". Aucun fichier source par défaut

n'est ajouté dans ce cas. Le sous-paquet "init-exec" est compilé et exécuté dans le dossier de destination après la création du répertoire de pro
jet de base. Les arguments libres "dub init -t custom -- free args" sont passés au sous-paquet "init-exec" en tant qu'arguments de l'application.

Compile le paquet et exécute tous les tests unitaires qu'il contient.

Si aucune configuration explicite n'est donnée, une configuration "unittest" existante sera préférée pour les tests. Si aucune n'existe, la première configuration de type bibliothèque sera utilisée, et si celle-ci n'existe pas non plus, la première configuration exécutable est

choisie.

Lorsqu'un fichier principal personnalisé (--main-file) est spécifié, seules les configurations de bibliothèque peuvent être utilisées. Sinon, selon le type de la configuration sélectionnée, un fichier principal existant sera utilisé (et doit être correctement ajusté pour n'exécuter que les tests unitaires pour 'version(unittest)'), ou DUB en générera un pour les configurations de type

Affiche une description de compilation JSON pour le paquet racine et toutes ses dépendances dans un format similaire à un fichier de description de paquet JSON. C'est principalement utile pour les IDE.

Toutes les options habituelles utilisées pour build/run/generate

s'appliquent.

Lorsque --data=VALUE est fourni, les paramètres de compilation spécifiques d'un projet seront affichés à la place (par défaut, formatés pour le compilateur

courant).

L'option --data=VALUE peut être spécifiée plusieurs fois pour récupérer plusieurs informations à la fois. Une liste séparée par des virgules est également acceptable (ex : --data=dflags,libs). Les données seront sorties dans le même ordre que celui demandé sur la ligne de

commande.

Cette commande utilise l'utilitaire Dustmite pour isoler la cause des erreurs de compilation dans un projet DUB.

Elle créera une copie de tous les paquets impliqués et exécutera dustmite sur cette copie, laissant un cas de test

réduit.

La détermination de la condition d'erreur souhaitée se fait en vérifiant le code de statut du compilateur/lieur, ainsi

que leur sortie (stdout et stderr combinés). Si --program-status ou --program-regex est donné et que le binai
re généré est exécutable, il sera exécuté et sa sortie sera également prise en compte dans la décision finale.

Lorsqu'il est exécuté avec un ou plusieurs arguments, quel que soit l'endroit où il est exécuté, il récupérera les paquets correspondant aux arguments. Exemples : $ dub fetch vibe-d $ dub fetch vibe-d@v0.9.0 --cache=local --recursive

Lorsqu'il est exécuté dans un projet sans arguments, il récupérera toutes les dépendances de ce projet. Si le projet n'a pas de dépendances définies (pas de 'dub.selections.json'), il effectuera également la résolution des dépendances. Exemple : $ cd myProject && dub

add-pa
th
Ajoute un chemin de recherche de paquets par défaut. Tous les sous-dossiers directs de ce chemin seront recherchés pour les descriptions de paquets et seront disponibles en tant que paquets. L'utilisation de cette commande a le même effet que d'appeler 'dub add-local' manuellement sur chacun des sous-dossiers.

Tous les paquets enregistrés à l'aide de add-path seront préférés aux paquets téléchargés depuis le registre de paquets lors de la recherche de dépendances pendant une opération de

compilation.

La version des paquets sera déterminée par l'une des méthodes suivantes :
- Pour les copies de travail GIT, la dernière balise (git describe) est utilisée pour déterminer la version
- Si le paquet contient un champ "version" dans la description du paquet, celui-ci est utilisé
- Si aucune de ces con

ditions ne s'applique,
"~master" est supposé

La version du paquet est soit déterminée automatiquement (voir la commande "add-path"), soit peut être explicitement écrasée en passant une version sur la ligne de

commande.
