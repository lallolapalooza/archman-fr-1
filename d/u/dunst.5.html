NOM

dunstrc - Fichier de configuration de dunst

DESCRIPTION

La configuration est divisée en sections dans un format similaire à celui des fichiers ini. Chaque section commence par le nom de la section entre crochets. Ensuite vient une liste de paires clé-valeur qui spécifient les paramètres. Les espaces blancs sont purement cosmétiques et ne changent pas le résultat.

La section "global" contient les paramètres généraux s'appliquant à tous les dunst. Le reste des paramètres peut être spécifié via des règles et peut être situé dans n'importe quelle section. Ces règles peuvent modifier une notification en fonction de ses propriétés. Il existe des règles de filtrage et des règles de modification. Les règles de filtrage spécifient à quelles notifications la règle s'applique. Les règles de modification spécifient les changements apportés aux notifications correspondantes. Certaines sections spéciales ont des filtres implicites qui ne peuvent pas être modifiés. Par exemple, la section "global" n'a pas de filtres : elle s'applique à toutes les notifications.

Voir REGLES pour plus de détails.

La section "experimental" contient des paramètres expérimentaux et instables. Ces options peuvent changer de manière non rétrocompatible entre les versions. Si vous trouvez un problème avec ces nouvelles fonctionnalités, assurez-vous de le signaler.

Section globale

default_pause_level (valeurs : [0-100], par défaut : 0)
Spécifie un niveau de pause à définir au démarrage de dunst. Les notifications ne sont affichées que si leur niveau d'urgence est supérieur au niveau de pause. Voir override_pause_level pour plus d'informations.
monitor (par défaut : 0)
Spécifie sur quel moniteur les notifications doivent être affichées, soit par nom, soit par numéro, en commençant à 0. Voir le paramètre follow.
follow (valeurs : [none/mouse/keyboard], par défaut : none)
Définit où les notifications doivent être placées dans une configuration multi-moniteurs. Toutes les valeurs sauf none remplacent le paramètre monitor.

Sur Wayland, il n'y a pas de différence entre le focus de la souris et du clavier. Lorsque l'un d'eux est utilisé, le compositeur choisira une sortie. Ce sera généralement la sortie avec laquelle vous avez interagi en dernier.

none
Les notifications seront placées sur le moniteur spécifié par le paramètre monitor.
mouse
Les notifications seront placées sur le moniteur où se trouve actuellement la souris.
keyboard
Les notifications seront placées sur le moniteur qui a le focus clavier.
enable_posix_regex (par défaut : false)
Lorsque défini sur true (recommandé), vous pouvez utiliser les expressions régulières POSIX pour les règles de filtrage. Il utilise la syntaxe des expressions régulières étendues POSIX : https://en.m.wikibooks.org/wiki/Regular_Expressions/POSIX-Extended_Regular_Expressions.

Si ceci est défini sur false (non recommandé), dunst utilisera fnmatch(3) pour faire correspondre les chaînes. Dunst ne passe aucun indicateur à fnmatch, vous ne pouvez donc pas utiliser de motifs étendus.

La syntaxe POSIX est plus puissante et deviendra finalement la valeur par défaut. Les principales différences entre POSIX et fnmatch(3) sont que POSIX utilise ".*" pour les jokers au lieu de "*" et POSIX permet des correspondances partielles sans avoir besoin de jokers. Cela signifie que le motif "abc" correspondra à toutes les chaînes contenant "abc", comme "abcdef".

geometry OBSOLÈTE
Ce paramètre est obsolète et supprimé. Il est divisé en width, height, origin, notification_limit et offset. Pour passer rapidement à la nouvelle syntaxe, vous pouvez prendre les nombres de votre ancienne configuration de géométrie comme suit :
geometry = <largeur>x<hauteur>+<décalage>

width = <largeur>

width
La largeur de la fenêtre de notification en pixels. Il peut s'agir d'un nombre unique pour spécifier une largeur constante ou de deux nombres pour la largeur minimale et maximale. La notification s'étendra à partir de la largeur minimale si nécessaire.

Exemples :

width = 300      # largeur constante de 300
width = (0, 300) # largeur entre 0 et 300

Lors de la définition d'une largeur supérieure à celle de l'écran, dunst limitera la largeur à la largeur de l'écran. Donc, si vous voulez que la notification s'étende dynamiquement sur tout l'écran, vous pouvez définir la largeur sur un nombre suffisamment élevé que vos écrans ne dépassent pas (par exemple, 10000).

height
La hauteur de chaque notification en pixels. Il peut s'agir d'un nombre unique pour spécifier une hauteur constante ou de deux nombres pour la hauteur minimale et maximale. La notification s'étendra à partir de la hauteur minimale si nécessaire.

Exemples :

height = 300      # hauteur constante de 300
height = (0, 300) # hauteur entre 0 et 300

Notez qu'à la différence de la largeur, différentes notifications peuvent avoir des valeurs de hauteur différentes.

Dunst v1.11 et antérieur ne supportent pas une hauteur dynamique et height accepte une seule valeur dont le comportement est équivalent à (0, valeur).

notification_limit (par défaut : 20)
Le nombre de notifications pouvant apparaître simultanément. Lorsque cette limite est atteinte, toutes les notifications supplémentaires seront mises en file d'attente et affichées lorsque celles actuellement affichées expireront ou seront supprimées manuellement. La valeur 0 signifie aucune limite. Si indicate_hidden est vrai, alors la limite spécifiée est réduite de 1 et la dernière notification est un message informant du nombre de notifications cachées en attente d'affichage. Voir l'entrée indicate_hidden pour plus d'informations.

alignment (values: [center/left/right], default: center)
Définit comment le texte et l'icône doivent être alignés verticalement dans la notification.
show_age_threshold (défaut: 60)
Affiche l'âge du message si le message est plus ancien que ce délai. Voir FORMAT DE TEMPS pour les formats valides.

Définir à -1 pour désactiver.

ignore_newline (valeurs : [true/false], défaut : false)
Si défini sur true, remplace les caractères de nouvelle ligne dans les notifications par des espaces blancs.
stack_duplicates (valeurs : [true/false], défaut : true)
Si défini sur true, les notifications dupliquées seront empilées ensemble au lieu d'être affichées séparément.

Deux notifications sont considérées comme des doublons si le nom du programme qui l'a envoyée, le résumé, le corps, l'icône et l'urgence sont tous identiques.

hide_duplicate_count (valeurs : [true/false], défaut : false)
Masque le nombre de notifications dupliquées empilées.
show_indicators (valeurs : [true/false], défaut : true)
Affiche un indicateur si une notification contient des actions et/ou des URL ouvrables. Voir ACTIONS ci-dessous pour plus de détails.
icon_path (défaut : "/usr/share/icons/gnome/16x16/status/:/usr/share/icons/gnome/16x16/devices/")
Peut être défini comme une liste de chemins séparés par des deux-points pour rechercher les icônes à utiliser avec les notifications.

Dunst ne recherche pas en dehors de ces répertoires. Pour un système de recherche récursive d'icônes, voir enable_recursive_icon_lookup. Ce nouveau système remplacera à terme la recherche via icon_path.

icon_theme (défaut : "Adwaita", exemple : "Adwaita, breeze")
Liste séparée par des virgules des noms des thèmes à utiliser pour rechercher les icônes. Il doit s'agir du nom du répertoire dans lequel se trouve le thème, et non du nom convivial du thème. Ainsi, par exemple, le thème Breeze Dark se trouve dans /usr/share/icons/breeze-dark. Dans ce cas, vous devez définir le thème sur breeze-dark.

Le premier thème de la liste est le plus important. Ce n'est que si l'icône ne peut pas être trouvée dans ce thème que le thème suivant sera essayé.

Dunst recherchera les thèmes dans XDG_DATA_HOME/icons et $XDG_DATA_DIRS/icons comme spécifié dans la spécification des thèmes d'icônes : https://specifications.freedesktop.org/icon-theme-spec/icon-theme-spec-latest.html.

Si le thème hérite d'autres thèmes, ceux-ci seront utilisés comme solution de secours.

Ce paramètre n'est pas activé par défaut. Voir enable_recursive_icon_lookup pour savoir comment l'activer.

enable_recursive_icon_lookup (défaut : false)
Ce paramètre active la nouvelle méthode de recherche d'icônes. Ce nouveau système remplacera à terme l'ancienne méthode de recherche.

Actuellement, les icônes sont recherchées dans icon_path. Comme icon_path n'était pas récursif, il fallait ajouter une tonne de chemins à cette liste. Cela a été considérablement simplifié par la nouvelle méthode de recherche. Vous n'avez maintenant qu'à définir icon_theme sur le nom du thème que vous souhaitez. Pour activer ce nouveau comportement, définissez enable_recursive_icon_lookup sur true dans la section [global]. Voir les paramètres respectifs pour plus de détails.

Définit le rayon des coins en pixels. Un rayon de coin de 0 entraînera des notifications de forme rectangulaire.

Ignore le message dbus CloseNotification. Ceci est utile pour forcer le délai d'expiration défini par la configuration de dunst. Sans ce paramètre, une application peut fermer la notification envoyée avant le délai défini par l'utilisateur.
override_pause_level (valeurs : [0-100], défaut : 0)
Une notification apparaîtra lorsque le override_pause_level de la notification sera supérieur au niveau de pause. Définir cela sur des valeurs autres que 0 vous permet de créer des modes de pause partiels, où les notifications plus urgentes passent, mais les moins urgentes restent en pause.

Par exemple, lorsque vous pouvez définir le override_pause_level d'une notification de batterie faible à 60, puis définir le niveau de pause de dunst à 60. Cela amènera dunst à afficher uniquement la notification du niveau de batterie (et d'autres notifications avec override_pause_level >= 60), tout en suspendant les autres.

Raccourcis clavier (X11 seulement)

Les raccourcis clavier sont définis dans le format suivant : "Modificateur+touche" où le modificateur est l'un de ctrl,mod1,mod2,mod3,mod4 et la touche est n'importe quelle touche du clavier.

Notez que les raccourcis clavier ont été déplacés dans la section global de la configuration pour plus de cohérence avec les autres paramètres.

Alternativement, vous pouvez également définir des raccourcis dans votre gestionnaire de fenêtres et les lier à des commandes dunstctl(1).

Wayland ne permet pas aux applications d'écouter les événements clavier globaux, cette fonctionnalité ne peut donc être implémentée que pour X.

HISTORIQU

E

Dunst enregistre un certain nombre de notifications (spécifié par history_length) en mémoire. Ces notifications peuvent être rappelées (c'est-à-dire réaffichées) en appelant dunstctl history (voir dunstctl(1)). Que ces notifications expirent ou non comme si elles venaient d'être envoyées dépend de la valeur du paramètre sticky_history. Les actions sont invalidées une fois la notification fermée, vous ne pouvez donc pas exécuter cette action lorsque vous rappelez une notification depuis

l'historique.

Les notifications passées sont réaffichées dans un ordre dernier arrivé, pr

emier servi, ce qui signifie qu'appuyer une fois sur la touche d'historique
fera apparaître la notification la plus récente qui a été fermée ou a expiré.

WAYLAN

D

Dunst prend en charge Wayland depuis la version 1.6.0. Parce que le protocole Wayland est plus axé sur la sécurité, certaines choses possibles en X11 ne sont pas possibles en Wayland. Ces différences sont reflétées dans la configuration. Les principaux changements sont que dunst sur Wayland ne peut pas utiliser de raccourcis clavier globaux, utilisez dunstctl à la

place.

Certaines fonctionnalités de dunst sur Wayland peuvent nécessiter que votre compositeur prenne en charge un certain protocole. Dunst vous avertira si une fonctionnalité optionnelle n'est pas prise en charge et désactivera la fonctionnalité

correspondante.

La détection du plein écran fonctionne sur wayland avec certaines limitations (voir fullscreen). Si vous voulez que les notifications apparaissent par-dessus les fenêtres en plein écran, définissez layer = overlay dans les options

globales.

Notez que les mêmes limitations existent lors de l'utilisation de

XWayland.

Si quelque chose ne fonctionne pas tout à fait sur Wayland, veuillez soumettre un rapport de bogue. En attendant, vous pouvez essayer si la sortie X11 fonctionne sur wayland. Utilisez force_xwayland = true pour

cela.

Si vous avez vos notifications dunst du même côté de votre écran que votre barre de statut, vous pourriez remarquer que vos notifications apparaissent un peu plus haut ou plus bas que sur X11. C'est parce que la notification ne peut pas être placée au-dessus de votre barre de statut. Les notifications sont placées par rapport à votre barre de statut, ce qui les fait apparaître plus haut ou plus bas de la hauteur de votre barre de statut. Nous ne pouvons rien faire à ce

sujet.

Notez que dunst crée un « desktop layer » en utilisant le protocole layer shell et

non une fenêtre Wayland régulière. Cela a certaines limitations comme indiqué ci-d
essus. Par exemple, vous ne pouvez pas définir le titre ou la classe d'une fenêtre.

SCRIPTIN

G

Dans les règles, vous pouvez spécifier un script à exécuter à chaque fois que la règle est correspondue en assignant l'option 'script' au nom du script à

exécuter.

Lorsque le script est appelé, les détails de la notification qui l'a déclenché seront transmis via des variables d'environnement. Les variables suivantes sont disponibles : DUNST_APP_NAME, DUNST_SUMMARY, DUNST_BODY, DUNST_ICON_PATH, DUNST_URGENCY, DUNST_ID, DUNST_PROGRESS, DUNST_CATEGORY, DUNST_STACK_TAG, DUNST_URLS, DUNST_TIMEOUT, DUNST_TIMESTAMP, DUNST_DESKTOP_ENTRY, et DUNST_STACK_TAG

.

Une autre façon, moins recommandée, d'obtenir les détails des notifications depuis un script est via les paramètres de ligne de commande. Ceux-ci sont passés au script dans l'ordre suivant : appname, summary, body, icon_path, urgency

.

Où DUNST_ICON_PATH ou icon_path est le chemin absolu vers le fichier d'icône s'il y en a un. DUNST_URGENCY ou urgency est l'un de "LOW", "NORMAL" ou "CRITICAL". DUNST_URLS est une liste d'URLs séparées par des sauts de ligne associées à la

notification.

Notez que certaines variables peuvent être

vides.

Si la notification est supprimée, le script ne sera pas exécuté sauf si always_run_script est défini sur

true.

Le paramètre script est développé selon wordexp(3) avec la substitution de commandes désactivée. Si la valeur développ

ée n'est pas un chemin absolu, les rép

ACTION

S

Dunst permet aux notificateurs (c'est-à-dire aux programmes qui envoient les notifications) de spécifier des actions. Dunst prend en charge l'affichage d'indicateurs pour celles-ci, ainsi que l'interaction avec ces

actions.

Si "show_indicators" est vrai et qu'une notification a une action, un "(A)" sera préfixé au format de la notification. De même, un "(U)" est préfixé aux notifications contenant des URL. Il est possible d'interagir avec les notifications ayant des actions indépendamment de ce paramètre, bien qu'il ne soit pas toujours évident de savoir quelles notifications ONT des

actions.

Le raccourci "context" est utilisé pour interagir avec ces actions, en affichant un menu des actions possibles. Cette fonctionnalité nécessite la présence de "dmenu" ou d'un remplaçant compatible avec

dmenu.

Alternativement, vous pouvez invoquer une action avec un clic central sur la notification. S'il y a exact

ement une action associée, ou si l'une est marquée comme par défaut, celle-ci est invoquée. S'il y en a p
lusieurs, le menu contextuel est affiché. La même chose s'applique aux URL lorsqu'il n'y a pas d'actions.
