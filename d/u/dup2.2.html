dup(2) Manuel des appels système dup(2)

NOM

dup, dup2, dup3 - dupliquer un descripteur de fichier

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int dup(int oldfd);
int dup2(int oldfd, int newfd);
#define _GNU_SOURCE             /* Voir feature_test_macros(7) */
#include <fcntl.h>              /* Définition des constantes O_* */
#include <unistd.h>
int dup3(int oldfd, int newfd, int flags);

DESCRIPTION

L'appel système dup() alloue un nouveau descripteur de fichier qui pointe vers la même description de fichier ouverte que le descripteur oldfd. (Pour une explication des descriptions de fichiers ouvertes, voir open(2).) Le nouveau numéro de descripteur de fichier est garanti d'être le descripteur de fichier utilisable ayant le plus petit numéro.

Après un retour réussi, les anciens et nouveaux descripteurs de fichier peuvent être utilisés de manière interchangeable. Étant donné que les deux descripteurs de fichier pointent vers la même description de fichier ouverte, ils partagent l'offset du fichier et les indicateurs d'état du fichier ; par exemple, si l'offset du fichier est modifié en utilisant lseek(2) sur l'un des descripteurs de fichier, l'offset est également modifié pour l'autre descripteur de fichier.

Les deux descripteurs de fichier ne partagent pas les indicateurs de descripteur de fichier (l'indicateur de fermeture à l'exécution). L'indicateur de fermeture à l'exécution (FD_CLOEXEC ; voir fcntl(2)) pour le descripteur dupliqué est désactivé.

dup2()

L'appel système dup2() effectue la même tâche que dup(), mais au lieu d'utiliser le descripteur de fichier utilisable le plus petit, il utilise le numéro de descripteur de fichier spécifié dans newfd. En d'autres termes, le descripteur de fichier newfd est ajusté de manière à pointer vers la même description de fichier ouverte que oldfd.

Si le descripteur de fichier newfd était précédemment ouvert, il est fermé avant d'être réutilisé ; la fermeture est effectuée silencieusement (c'est-à-dire que toute erreur survenant lors de la fermeture n'est pas rapportée par dup2()).

Les étapes de fermeture et de réutilisation du descripteur de fichier newfd sont effectuées atomiquement. Ceci est important, car tenter d'implémenter une fonctionnalité équivalente en utilisant close(2) et dup() serait sujet à des conditions de concurrence, où newfd pourrait être réutilisé entre les deux étapes. Une telle réutilisation pourrait se produire car le programme principal est interrompu par un gestionnaire de signaux qui alloue un descripteur de fichier, ou parce qu'un thread parallèle alloue un descripteur de fichier.

Notez les points suivants :

•
Si oldfd n'est pas un descripteur de fichier valide, l'appel échoue et newfd n'est pas fermé.
•
Si oldfd est un descripteur de fichier valide et que newfd a la même valeur que oldfd, alors dup2() ne fait rien et retourne newfd.

dup3()

dup3() est identique à dup2(), à ceci près que :

•
L'appelant peut forcer l'indication de fermeture à l'exécution à être définie pour le nouveau descripteur de fichier en spécifiant O_CLOEXEC dans flags. Voir la description de la même indication dans open(2) pour les raisons pour lesquelles cela peut être utile.
•
Si oldfd est égal à newfd, alors dup3() échoue avec l'erreur EINVAL.

VALEUR DE RETOUR

En cas de succès, ces appels système retournent le nouveau descripteur de fichier. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EBADF
oldfd n'est pas un descripteur de fichier ouvert.
EBADF
newfd est hors de la plage autorisée pour les descripteurs de fichier (voir la discussion sur RLIMIT_NOFILE dans getrlimit(2)).
EBUSY
(Linux uniquement) Peut être retourné par dup2() ou dup3() lors d'une condition de concurrence avec open(2) et dup().
EINTR
L'appel dup2() ou dup3() a été interrompu par un signal ; voir signal(7).
EINVAL
(dup3()) flags contient une valeur invalide.
EINVAL
(dup3()) oldfd était égal à newfd.
EMFILE
La limite par processus sur le nombre de descripteurs de fichier ouverts a été atteinte (voir la discussion sur RLIMIT_NOFILE dans getrlimit(2)).
ENOMEM
Mémoire noyau insuffisante disponible.

NORMES

POSIX.1-2024.

NOTES

L'erreur retournée par dup2() est différente de celle retournée par fcntl(..., F_DUPFD, ...) lorsque newfd est hors de portée. Sur certains systèmes, dup2() retourne également parfois EINVAL comme F_DUPFD.

Si newfd était ouvert, toutes les erreurs qui auraient été signalées au moment de close(2) sont perdues. Si cela pose problème, alors — à moins que le programme ne soit monothreadé et n'alloue pas de descripteurs de fichier dans les gestionnaires de signaux — l'approche correcte est de ne pas fermer newfd avant d'appeler dup2(), en raison de la condition de concurrence décrite ci-dessus. Au lieu de cela, un code comme celui-ci peut être utilisé :


/* Obtenir un duplicata de 'newfd' qui peut ensuite
   être utilisé pour vérifier les erreurs de close() ; une erreur EBADF
   signifie que 'newfd' n'était pas ouvert.  */
tmpfd = dup(newfd);
if (tmpfd == -1 && errno != EBADF) {
    /* Gérer l'erreur dup() inattendue.  */
}
/* Dupliquer atomiquement 'oldfd' sur 'newfd'.  */
if (dup2(oldfd, newfd) == -1) {
    /* Gérer l'erreur dup2().  */
}
/* Vérifier maintenant les erreurs de close() sur le fichier
   précédemment référencé par 'newfd'.  */
if (tmpfd != -1) {
    if (close(tmpfd) == -1) {
        /* Gérer les erreurs de close.  */
    }
}
