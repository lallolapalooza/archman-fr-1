--action-stderr-on-success=VA
L
Identique à --action-stdout-on-success mais pour la sortie d'erreur standard au lieu de la sortie standard. Un bon défaut pour les grands mono-repertoires est --action-stdout-on-success=swallow --action-stderr-on-success=must-be-empty. Cela garantit qu'une construction réussie a une sortie vide « propre
».
--action-stdout-on-success=VA
L
Spécifier comment traiter la sortie standard des actions lorsqu'elles réussissent. Les valeurs possibles sont : print pour simplement l'imprimer dans la sortie de Dune, swallow pour l'ignorer complètement et must-be-empty pour imposer que l'action n'ait rien imprimé. Avec must-be-empty, Dune considérera que l'action a échoué si elle a imprimé quelque chose sur sa sortie standard. La valeur par défaut est prin

--no-buff
er
Ne pas mettre en tampon la sortie des commandes exécutées par dune. Par défaut, dune met en tampon la sortie des sous-commandes afin d'éviter l'entrelacement lorsque plusieurs commandes sont exécutées en parallèle. Cependant, cela peut poser problème lors du débogage de tests de longue durée. Avec --no-buffer, les commandes ont un accès direct au terminal. Notez qu'en conséquence, leur sortie ne sera pas capturée dans le fichier journal. Vous devriez utiliser cette option en conjonction avec -j 1, pour éviter l'entrelacement. De plus, vous devriez utiliser --verbose également, pour vous assurer que les commandes sont imprimées avant d'être
exécutées.

ÉTAT DE SORTIE

dune build se termine avec :

0
en cas de succès.
1
si une erreur s'est produite.
130
si elle a été interrompue par un signal.

ENVIRONNEMENT

Ces variables d'environnement affectent l'exécution de build :

CLICOLOR
Si différent de 0, les couleurs ANSI sont supportées et doivent être utilisées lorsque le programme n'est pas redirigé. Si égal à 0, n'émet pas de codes d'échappement de couleur ANSI.
CLICOLOR_FORCE
Si différent de 0, les couleurs ANSI doivent être activées quoi qu'il arrive.
DUNE_BUILD_DIR
Répertoire de build spécifié. _build si non spécifié.
DUNE_CACHE
Active ou désactive le cache Dune (un parmi disabled, enabled-except-user-rules ou enabled). La valeur par défaut est `enabled-except-user-rules'.
DUNE_CACHE_CHECK_PROBABILITY
Vérifie la reproductibilité des builds en réexécutant des règles choisies aléatoirement et en comparant leurs résultats avec ceux stockés dans le cache Dune. Remarque : en augmentant la probabilité de telles vérifications, vous ralentissez le build. La probabilité par défaut est zéro, c'est-à-dire qu'aucune règle n'est vérifiée.
DUNE_CACHE_ROOT
Si défini, détermine l'emplacement du cache partagé global de la machine.
DUNE_CACHE_STORAGE_MODE
Mode de stockage du cache Dune (un parmi auto, hardlink ou copy). La valeur par défaut est `hardlink'.
DUNE_DEBUG_PACKAGE_LOGS
Affiche toujours les journaux standard lors de la construction des packages.
DUNE_DIFF_COMMAND
Commande shell à utiliser pour comparer les fichiers. Utilisez - pour désactiver l'affichage du diff.
DUNE_DISABLE_PROMOTION
Désactive toutes les règles de promotion.
DUNE_INSTRUMENT_WITH
Active l'instrumentation par BACKENDS. BACKENDS est une liste séparée par des virgules de noms de bibliothèques, chacune devant déclarer un backend d'instrumentation.
DUNE_PROFILE
Profil de build. dev si non spécifié ou release si -p est défini.
DUNE_SANDBOX
Mode de sandboxing à utiliser par défaut. (voir --sandbox)
DUNE_STORE_ORIG_SOURCE_DIR
Stocke l'emplacement source d'origine dans les métadonnées dune-package.
DUNE_WORKSPACE
Utilise ce fichier d'espace de travail spécifique au lieu de le rechercher.

EXEMPLES

1.
Construire toutes les cibles dans l'arborescence source actuelle :
      dune build
2.
Construire les cibles dans le répertoire `./foo/bar' :
      dune build ./foo/bar
3.
Construire l'ensemble minimal de cibles requis pour les outils tels que Merlin (utile pour détecter rapidement les erreurs) :
      dune build @check
4.
Exécuter tous les outils de formatage de code sur place :
      dune build --auto-promote @fmt
