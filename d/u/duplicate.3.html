Description Détaillée

Une interface d'entrée/sortie abstraite.

Avertissement

Ceci est du matériel avancé et pointu. Vous n'en avez pas besoin à moins de savoir vraiment ce que vous faites. La plupart des applications n'auront pas besoin de cela.

Historiquement, PhysicsFS fournissait l'accès au système de fichiers physique et aux archives au sein de ce système de fichiers. Cependant, vous avez parfois besoin de plus de puissance que cela. Peut-être avez-vous besoin de fournir une archive entièrement contenue en RAM, ou vous devez faire le pont entre une autre API d'entrée/sortie de fichiers et PhysicsFS, ou vous devez transformer les bits (peut-être avez-vous un fichier .zip standard qui est chiffré, et vous devez déchiffrer à la volée pour l'archivier zip qui ne s'y attend pas).

Un PHYSFS_Io est l'interface que les Archivers utilisent pour obtenir les données d'archive. Historiquement, cela correspondait à l'entrée/sortie de fichiers vers le système de fichiers physique, mais à partir de PhysicsFS 2.1, les applications peuvent fournir leurs propres implémentations d'entrée/sortie à l'exécution.

Cette interface n'est pas nécessairement un bon ajustement universel pour l'entrée/sortie. Il y a quelques exigences notables :

  • Elles ne font que de l'entrée/sortie bloquante (au moins, pour l'instant).
  • Elles doivent pouvoir être dupliquées. Si vous avez un descripteur de fichier de fopen(), vous devez pouvoir créer un clone unique de celui-ci (afin que nous ayons deux descripteurs vers le même fichier qui peuvent tous deux chercher/lire/etc. sans se marcher dessus).
  • Elles doivent connaître la taille de leur ensemble de données complet.
  • Elles doivent pouvoir chercher et revenir en arrière à la demande.

...en bref, vous n'allez probablement pas écrire une implémentation HTTP.

Sécurité des threads : PHYSFS_Io les implémentations ne sont pas garanties comme étant sûres pour les threads en elles-mêmes. Sous le capot, là où PhysicsFS les utilise, la bibliothèque fournit ses propres verrous. Si vous prévoyez de les utiliser directement depuis des threads séparés, vous devriez soit utiliser des mutex pour les protéger, soit ne pas utiliser le même PHYSFS_Io depuis deux threads en même temps.

Documentation des champs

void(* PHYSFS_Io::destroy) (struct PHYSFS_Io *io)

Nettoyer et désallouer l'instance d'entrée/sortie. Libérer les ressources associées, y compris (opaque) si applicable.

Cette fonction doit toujours réussir : en tant que telle, elle retourne void. Le système peut appeler votre flush() méthode avant celle-ci. Vous pouvez signaler un échec là-bas si nécessaire. Cette méthode peut toujours être appelée si flush() échoue, auquel cas vous devrez abandonner les données non vidées et les autres conditions d'échec et nettoyer.

Une fois que cette méthode est appelée pour une instance donnée, le système supposera qu'il n'est pas sûr de toucher à cette instance à nouveau et rejettera toute référence à celle-ci.

Paramètres

s L'instance d'entrée/sortie à détruire.

struct PHYSFS_Io *(* PHYSFS_Io::duplicate) (struct PHYSFS_Io *io)

Dupliquer cette instance d'entrée/sortie. Cela doit résulter en une copie complète de ce PHYSFS_Io, qui peut vivre complètement indépendamment. La copie doit pouvoir effectuer toutes ses opérations sans altérer l'original, y compris la destruction séparée de l'un ou l'autre objet (donc, par exemple : ils ne peuvent pas partager un descripteur de fichier ; chacun doit avoir le sien).

Si vous ne pouvez pas dupliquer un descripteur, il est légal de retourner NULL, mais vous avez presque certainement besoin de cette fonctionnalité si vous voulez utiliser cela pour PHYSFS_Io pour soutenir une archive.

Paramètres

io L'instance d'entrée/sortie à dupliquer.

Retourne

Une nouvelle valeur pour le champ (opaque) d'un flux, ou NULL en cas d'erreur.

int(* PHYSFS_Io::flush) (struct PHYSFS_Io *io)

Vider les ressources vers le support de stockage, ou ailleurs. C'est l'occasion de signaler un échec pour des écritures qui avaient annoncé un succès plus tôt, mais qui avaient encore une chance d'échouer réellement. Cette méthode peut être NULL si le vidage n'est pas nécessaire.

Cette fonction peut être appelée avant destroy(), car elle peut signaler un échec et destroy() ne le peut pas. Elle peut être appelée à d'autres moments aussi.

Paramètres

io L'instance d'entrée/sortie à vider.

Retourne

Zéro en cas d'erreur, non-zéro en cas de succès.

PHYSFS_sint64(* PHYSFS_Io::length) (struct PHYSFS_Io *io)

Déterminer la taille de l'ensemble de données de l'instance d'entrée/sortie. Retourner le nombre d'octets disponibles dans le fichier, ou -1 si vous n'êtes pas en mesure de le déterminer. Un échec sera presque certainement fatal pour une utilisation ultérieure de ce flux, donc vous ne pouvez pas laisser cela non implémenté.

Paramètres

io L'instance d'entrée/sortie à interroger.

Retourne

La taille totale, en octets, de l'ensemble de données.

void* PHYSFS_Io::opaque

Données d'instance pour cette structure. Chaque instance a un pointeur associé qui peut être utilisé pour stocker ce qu'elle veut. Ce pointeur est par instance du flux, donc il changera probablement lors de l'appel de duplicate(). Cela peut être désalloué pendant la destroy() méthode.

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buf, PHYSFS_uint64 len)

Lire plus de données. Lire (len) octets depuis l'interface, à la position d'entrée/sortie actuelle, et les stocker dans (buffer). La position d'entrée/sortie actuelle devrait avancer du nombre d'octets lus avec succès.

Vous n'avez pas à implémenter cela ; mettez-le à NULL si non implémenté. Cela ne sera utilisé que si le fichier est ouvert en lecture. Si mis à NULL, une implémentation par défaut qui signale immédiatement un échec sera utilisée.

Paramètres

io L'instance d'entrée/sortie à lire.
buf Le tampon où stocker les données. Il doit faire au moins (len) octets de long et ne peut pas être NULL.
len Le nombre d'octets à lire depuis l'interface.

Retourne

nombre d'octets lus depuis le fichier, 0 en cas de fin de fichier, -1 en cas d'échec complet.

int(* PHYSFS_Io::seek) (struct PHYSFS_Io *io, PHYSFS_uint64 offset)

Déplacer la position d'entrée/sortie à un décalage en octets donné depuis le début. Cette méthode déplace la position d'entrée/sortie, donc la prochaine lecture/écriture sera de l'octet à (offset) décalage. Les recherches au-delà de la fin du fichierould être traitée comme une erreur.

Paramètres

io L'instance d'entrée/sortie à positionner.
offset Le nouvel octet d'offset pour la position d'entrée/sortie.

Retourne

non nul en cas de succès, zéro en cas d'erreur.

PHYSFS_sint64(* PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Signaler la position d'entrée/sortie actuelle. Retourner l'octet d'offset, ou -1 si vous n'êtes pas en mesure de le déterminer. Un échec sera presque certainement fatal à l'utilisation ultérieure de ce flux, vous ne pouvez donc pas laisser cela non implémenté.

Paramètres

io L'instance d'entrée/sortie à interroger.

Retourne

L'octet d'offset actuel pour la position d'entrée/sortie, -1 si inconnu.

PHYSFS_uint32 PHYSFS_Io::version

Informations de compatibilité binaire. Cela doit être défini à zéro pour le moment. Les futures versions de cette structure incrémenteront ce champ, afin que nous sachions ce qu'une implémentation donnée prend en charge. Nous continuerons probablement à prendre en charge les anciennes versions à mesure que nous proposons de nouvelles fonctionnalités, cependant.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Écrire plus de données. Écrire (len) octets depuis (buffer) vers l'interface à la position d'entrée/sortie actuelle. La position d'entrée/sortie actuelle doit avancer du nombre d'octets écrits avec succès.

Vous n'avez pas à implémenter cela ; définissez-le à NULL si ce n'est pas implémenté. Cela ne sera utilisé que si le fichier est ouvert en écriture. Si défini à NULL, une implémentation par défaut qui signale immédiatement un échec sera utilisée.

Vous êtes autorisé à mettre en tampon ; une écriture peut réussir ici puis échouer plus tard lors du vidage. Notez que PHYSFS_setBuffer() peut opérer à un niveau supérieur à votre entrée/sortie, vous ne devriez donc généralement pas implémenter vos propres routines de mise en tampon.

Paramètres

io L'instance d'entrée/sortie vers laquelle écrire.
buffer Le tampon à partir duquel lire les données. Il doit faire au moins (len) octets de long et ne peut pas être NULL.
len Le nombre d'octets à lire depuis (buffer).

Retourne

nombre d'octets écrits dans le fichier, -1 en cas d'échec complet.
