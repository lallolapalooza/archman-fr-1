DESCRIPTIO

N

Exécute les tests donnés. L'argument [TEST] peut être soit

:
-
Un répertoire : Si un répertoire est fourni, dune exécute récursivement tous les tests dans ce
répertoire.
-
Un nom de fichier : Si un nom de fic
hier spécifique est fourni, dune exé
cute les tests portant ce nom.

Si aucun [TEST] n'est fourni, dune exécute tous les tests dans le répertoire courant et ses sous-répertoires

.

OPTION

S
--action-stderr-on-success=VA
L
Identique à --action-stdout-on-success mais pour la sortie d'erreur standard au lieu de la sortie standard. Un bon défaut pour les grands mono-dépôts est --action-stdout-on-success=swallow --action-stderr-on-success=must-be-empty. Cela garantit qu'une compilation réussie a une sortie vide « propre
».
--action-stdout-on-success=VA
L
Spécifie comment traiter la sortie standard des actions lorsqu'elles réussissent. Les valeurs possibles sont : print pour simplement l'imprimer dans la sortie de Dune, swallow pour l'ignorer complètement et must-be-empty pour imposer que l'action n'ait rien imprimé. Avec must-be-empty, Dune considérera que l'action a échoué si elle a imprimé quelque chose sur sa sortie standard. La valeur par défaut est prin
t.
--build-in
fo
Affiche les informations de
compilation.
--display-separate-messa
ges
Sépare les messages d'erreur par une ligne
vide.
--error-reporting=VAL (absent=deterministi
c)
Contrôle quand les erreurs de compilation sont signalées. early signale les erreurs dès qu'elles sont découvertes. deterministic signale les erreurs à la fin de la compilation dans un ordre déterministe. twice signale chaque erreur deux fois : une fois dès que l'erreur est découverte, puis à nouveau à la fin de la compilation, dans un ordre
déterministe.
-f, --for
ce
Force la ré-exécution des actions associées aux alias même si leurs dépendances n'ont pas
changé.
--file-watcher=VAL (absent=automati
c)
Mécanisme pour détecter les changements dans la source. Automatic pour faire exécuter à dune un programme externe pour détecter les changements. Manual pour notifier manuellement à dune que des fichiers ont
changé.
--passive-watch-m
ode
Similaire à [--watch], mais ne lance une compilation que lorsqu'il est instruit de le faire par un RPC
externe.
--sandbox=VAL (absent DUNE_SANDBO
X env)
Définit le mode de bac à sable. Certaines actions nécessitent un certain mode de bac à sable, elles ignoreront donc ce paramètre. Les valeurs autorisées sont : none, symlink, copy,
hardlink.
--stop-on-first-er
ror
Arrête la compilation dès qu'une erreur est
rencontrée.
-w, --wat
ch
Au lieu de terminer la compilation après son achèvement, attend continuellement les changements de
fichiers.
--wait-for-filesystem-cl
ock
Dune calcule des empreintes (digests) du contenu des fichiers pour une meilleure incrémentalité. Ces empreintes sont elles-mêmes mises en cache. Dans
certains cas, Dune doit supprimer certaines entrées du cache d'empreintes pour que les choses soient fiables. Cette option fait attendre à Dune que l
'horloge du système de fichiers avance afin qu'il n'ait pas besoin de supprimer quoi que ce soit. Vous ne devriez probablement pas vous soucier de ce
tte option ; elle est principalement utile aux développeurs de Dune pour rendre les tests de Dune sur le cache d'empreintes plus reproductibles.

--no-buff
er
Ne met pas en tampon la sortie des commandes exécutées par dune. Par défaut, dune met en tampon la sortie des sous-commandes afin d'éviter l'entrelacement lorsque plusieurs commandes sont exécutées en parallèle. Cependant, cela peut poser problème lors du débogage de tests de longue durée. Avec --no-buffer, les commandes ont un accès direct au terminal. Notez qu'en conséquence, leur sortie ne sera pas capturée dans le fichier journal. Vous devriez utiliser cette option en conjonction avec -j 1, pour éviter l'entrelacement. De plus, vous devriez utiliser --verbose également, pour vous assurer que les commandes sont imprimées avant d'être
exécutées.
