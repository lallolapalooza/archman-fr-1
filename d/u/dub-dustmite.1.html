NOM

dub-dustmite - Créer des cas de test réduits pour les erreurs de compilation

SYNTAXE

dub dustmite <chemin-destination> OPTIONS... [-- <arguments-application...>]

DESCRIPTION

Cette commande utilise l'utilitaire Dustmite pour isoler la cause des erreurs de compilation dans un projet DUB.

Elle créera une copie de tous les paquets impliqués et exécutera dustmite sur cette copie, laissant un cas de test réduit.

La détermination de la condition d'erreur souhaitée se fait en vérifiant le code de retour du compilateur/éditeur de liens, ainsi que leur sortie (stdout et stderr combinés). Si --program-status ou --program-regex sont donnés et que le binaire généré est un exécutable, il sera exécuté et sa sortie sera également intégrée dans la décision finale.

OPTIONS

--compiler-status=VALEUR

Le code de retour attendu de l'exécution du compilateur

--compiler-regex=VALEUR

Une expression régulière utilisée pour correspondre à la sortie du compilateur

--linker-status=VALEUR

Le code de retour attendu de l'exécution de l'éditeur de liens

--linker-regex=VALEUR

Une expression régulière utilisée pour correspondre à la sortie de l'éditeur de liens

--program-status=VALEUR

Le code de retour attendu de l'exécutable compilé

--program-regex=VALEUR

Une expression régulière utilisée pour correspondre à la sortie du programme

--test-package=VALEUR

Effectue une exécution de test - généralement utilisé uniquement en interne

--combined

Compile plusieurs paquets avec une seule exécution du compilateur

--no-redirect

Ne redirige pas les flux stdout/stderr de la commande de test

--strategy=VALEUR

Définit la stratégie (careful/lookback/pingpong/indepth/inbreadth)

-j

Définit le nombre de processus d'anticipation

--trace

Sauvegarde toutes les réductions tentées dans DIR.trace

-b, --build=VALEUR

Spécifie le type de build à effectuer. Notez que la définition de la variable d'environnement DFLAGS remplacera le type de build par des indicateurs personnalisés. Noms possibles :
debug, plain, release, release-debug, release-nobounds, unittest, profile, profile-gc, docs, ddox, cov, cov-ctfe, unittest-cov, unittest-cov-ctfe, syntax et types personnalisés

-c, --config=VALEUR

Compile la configuration spécifiée. Les configurations peuvent être définies dans dub.json

--override-config=VALEUR

Utilise la configuration spécifiée pour une dépendance donnée. Peut être spécifié plusieurs fois. Format : --override-config=<dépendance>/<config>

--compiler=VALEUR

Spécifie le binaire du compilateur à utiliser (peut être un chemin). Des préfixes et suffixes arbitraires aux identifiants ci-dessous sont reconnus (par exemple, ldc2 ou dmd-2.063) et correspondent au type de compilateur approprié :
dmd, gdc, ldc, gdmd, ldmd

-a, --arch=VALEUR

Force une architecture différente (par exemple, x86 ou x86_64)

-d, --debug=VALEUR

Définit l'identifiant de version `debug` spécifié lors de la compilation - peut être utilisé plusieurs fois

--d-version=VALEUR

Définit l'identifiant `version` spécifié lors de la compilation - peut être utilisé plusieurs fois. À utiliser avec parcimonie, un grand pouvoir implique de grandes responsabilités ! Pour les versions couramment utilisées ou combinées, et les versions que les dépendants devraient pouvoir utiliser, créez des configurations dans votre paquet.

--nodeps

Ne résout pas les dépendances manquantes avant la compilation

--build-mode=VALEUR

Spécifie la manière dont le compilateur et l'éditeur de liens sont invoqués. Valeurs valides :
separate (par défaut), allAtOnce, singleFile

--single

Traite le nom du paquet comme un nom de fichier. Le fichier doit contenir un commentaire de recette de paquet.

--force-remove

Option obsolète qui ne fait rien.

--filter-versions

[Expérimental] Filtre les identifiants de version et les identifiants de version de débogage pour améliorer l'efficacité du cache de compilation.
