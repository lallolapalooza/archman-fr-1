NOM

dtconfchk - Vérifier la cohérence d'un fichier de configuration DNSSEC-Tools

SYNOPSIS

dtconfchk [options] [fichier_de_configuration]

DESCRIPTION

dtconfchk vérifie un fichier de configuration DNSSEC-Tools afin de déterminer si les entrées sont valides. Si un fichier de configuration n'est pas spécifié, le fichier de configuration du système sera vérifié.

Sans aucune option d'affichage, dtconfchk affiche des messages d'erreur pour les problèmes trouvés, suivis d'une ligne de résumé. Les options d'affichage augmenteront ou diminueront le niveau de détail sur la cohérence du fichier de configuration. Dans tous les cas, le code de sortie est le nombre d'erreurs trouvées dans le fichier.

Les tests sont divisés en cinq groupes : vérifications relatives aux clés, vérifications relatives aux zones, vérifications des chemins, vérifications de rotation et vérifications diverses. Les vérifications dans chacun de ces groupes auto-explicatifs sont décrites ci-dessous.

L'entrée de configuration default_keyrec n'est pas vérifiée. Cette entrée spécifie le nom de fichier keyrec par défaut et n'est pas nécessairement censée exister à un endroit particulier.

Valeurs booléennes

Le fichier de configuration DNSSEC-Tools contient un certain nombre de champs qui sont censés contenir des valeurs booléennes. Les valeurs reconnues pour les booléens sont les suivantes :

valeurs vraies  - 1, true,  t, yes, y
valeurs fausses - 0, false, f, no,  n

Les valeurs positives supérieures à 1 sont reconnues comme valeurs vraies, mais il vaudrait probablement mieux utiliser 1.

Les valeurs textuelles qui ne font pas partie de l'ensemble ci-dessus ne sont pas valides et seront interprétées comme des valeurs fausses.

Vérifications relatives aux clés

Les vérifications relatives aux clés suivantes sont effectuées :

algorithm
S'assurer que le champ algorithm est valide. Les valeurs acceptables peuvent être trouvées dans la page man dnssec-keygen .
ksklength
S'assurer que le champ ksklength est valide. Les valeurs acceptables peuvent être trouvées dans la page man dnssec-keygen . Cela peut aussi être spécifié comme ksklen.
ksklife
S'assurer que le champ ksklife est valide. Les valeurs acceptables peuvent être trouvées dans la page man defaults.pm .
zskcount
S'assurer que le champ zskcount est valide. Le nombre de ZSK doit être positif.
zsklength
S'assurer que le champ zsklength est valide. Les valeurs acceptables peuvent être trouvées dans la page man dnssec-keygen . Cela peut aussi être spécifié comme zsklen.
zsklife
S'assurer que le champ zsklife est valide. Les valeurs acceptables peuvent être trouvées dans la page man defaults.pm .
random
S'assurer que le champ random est valide. Ce fichier doit être un fichier périphérique de caractère.

Vérifications relatives aux zones

Les vérifications relatives aux zones suivantes sont effectuées :

endtime
S'assurer que le champ endtime est valide. Cette valeur est supposée être au format « +NNNNNN ». Il y a une limite inférieure de deux heures. (Ceci est une limite artificielle en dessous de laquelle il peut ne pas avoir de sens d'avoir une heure de fin.)

Vérifications des chemins

Des vérifications de chemins sont effectuées pour plusieurs commandes DNSSEC-Tools, plusieurs commandes BIND et quelques fichiers divers.

Les vérifications de chemins suivantes sont effectuées pour les commandes DNSSEC-Tools :

genkrf
S'assurer que le champ genkrf est valide. Si le nom de fichier commence par un « / », le fichier doit être un fichier exécutable régulier.
keyarch
S'assurer que le champ keyarch est valide. Si le nom de fichier commence par un « / », le fichier doit être un fichier exécutable régulier.
rollchk
S'assurer que le champ rollchk est valide. Si le nom de fichier commence par un « / », le fichier doit être un fichier exécutable régulier.
rollctl
S'assurer que le champ rollctl est valide. Si le nom de fichier commence par un « / », le fichier doit être un fichier exécutable régulier.
zonesigner
S'assurer que le champ zonesigner est valide. Si le nom de fichier commence par un « / », le fichier doit être un fichier exécutable régulier.

Les vérifications de chemins suivantes sont effectuées pour les outils BIND :

keygen
S'assurer que le champ keygen est valide. Si le nom de fichier commence par un « / », le fichier doit être un fichier exécutable régulier.
rndc
S'assurer que le champ rndc est valide. Si le nom de fichier commence par un « / », le fichier doit être un fichier exécutable régulier.
zonecheck
S'assurer que le champ zonecheck est valide. Si le nom de fichier commence par un « / », le fichier doit être un fichier exécutable régulier.
zonesign
S'assurer que le champ zonesign est valide. Si le nom de fichier commence par un « / », le fichier doit être un fichier exécutable régulier.

Les vérifications de chemins suivantes sont effectuées pour les fichiers et répertoires divers :

random
S'assurer que le champ random est valide. Le fichier doit être un fichier périphérique de caractère.
roll_logfile
S'assurer que le champ roll_logfile est un fichier régulier.
taresolvconf
S'assurer que le champ taresolvconf est un fichier régulier.
tatmpdir
S'assurer que le champ tatmpdir est un répertoire.

Vérifications du démon de rotation

Les vérifications suivantes sont effectuées pour les valeurs de rollerd :

autosign
S'assurer que le drapeau autosign est un booléen valide.
log_tz
S'assurer que le champ log_tz est soit « gmt » soit « local ».
prog_normal
prog_ksk1 ... prog_ksk7
prog_zsk1 ... prog_zsk4
S'assurer que les commandes de phase de rotation sont des chemins valides. Chacun de ces champs est une liste de commandes séparées par des points-virgules. Les vérifications de fichier sont effectuées sur les commandes pour s'assurer que les commandes existent et sont exécutables. Les options et arguments des commandes sont ignorés, tout comme le mot-clé default .
roll_loadzone
S'assurer que le drapeau roll_loadzone est un booléen valide.
roll_logfile
S'assurer que le fichier journal pour rollerd est valide. Si le fichier existe, il doit être un fichier régulier.
roll_loglevel
S'assurer que le niveau de journalisation pour rollerd est raisonnable. Le niveau de journal doit être l'une des valeurs textuelles ou numériques suivantes : 
tmi        1       Messages informatifs excessivement verbeux.
expire     3       Un décompte verbeux de l'expiration de la zone est donné.
info       4       Messages informatifs.
phase      6       État actuel de la zone.
err        8       Messages d'erreur.
fatal      9       Erreurs fatales.

Spécifier un niveau de journal particulier causera l'affichage des messages de valeur numérique supérieure soient également affichés.

roll_sleeptime
S'assurer que le temps de sommeil de rollerdest raisonnable. rollerddoit dormir au moins une minute.
roll_username
S'assurer que le nom d'utilisateur pour rollerd est valide. S'il s'agit d'un nom d'utilisateur, il doit être convertible en uid ; s'il s'agit d'un uid, il doit correspondre à un nom d'utilisateur connu.
zone_errors
S'assurer que le compteur d'erreurs de zone est numérique et supérieur ou égal à 0.

Vérifications NSEC3

Les vérifications suivantes sont effectuées pour les valeurs liées à NSEC3 :

nsec3iter
S'assurer que le nombre d'itérations de nsec3iter se situe dans la plage utilisée par dnssec-signzone. Les valeurs actuelles vont de 1 à 65535.
nsec3optout
S'assurer que l'indicateur nsec3optout est un booléen valide.
usensec3
S'assurer que l'indicateur usensec3 est un booléen valide.

Vérifications diverses

Les vérifications diverses suivantes sont effectuées :

admin-email
S'assurer que le champ admin-email est défini et possède une valeur. dtconfchk ne tente pas de valider l'adresse e-mail elle-même.
archivedir
S'assurer que le répertoire archivedir est bien un répertoire. Cette vérification n'est effectuée que si l'indicateur savekeys est activé.
entropy_msg
S'assurer que l'indicateur entropy_msg est un booléen valide.
savekeys
S'assurer que l'indicateur savekeys est un booléen valide. Si cet indicateur est défini à 1, le champ archivedir sera également vérifié.
usegui
S'assurer que l'indicateur usegui est un booléen valide.
zonefile-parser
S'assurer que l'indicateur zonefile-parser est un module Perl valide. Cette vérification est effectuée en utilisant la fonctionnalité « require » de Perl pour charger le module spécifié.

OPTIONS

-expert
Cette option contournera les vérifications suivantes : 
- La durée de vie de la KSK est plus longue que la durée de vie minimale par défaut du fichier de configuration
- La durée de vie de la KSK est plus courte que la durée de vie maximale par défaut du fichier de configuration
- Les durées de vie des ZSK sont plus longues que la durée de vie minimale par défaut du fichier de configuration
- Les durées de vie des ZSK sont plus courtes que la durée de vie maximale par défaut du fichier de configuration
-quiet
Aucune sortie ne sera donnée. Le nombre d'erreurs sera utilisé comme code de sortie.
-summary
Un résumé final du succès ou de l'échec sera imprimé. Le nombre d'erreurs sera utilisé comme code de sortie.
-verbose
Le statut de succès ou d'échec de chaque vérification sera donné. Un + ou - sera ajouté en préfixe pour chaque entrée valide et invalide. Le nombre d'erreurs sera utilisé comme code de sortie.
-Version
Affiche les informations de version pour dtconfchk et le paquet DNSSEC-Tools.
-help
Affiche un message d'utilisation.
