DESCRIPTIO

N

dtrealms gère plusieurs environnements de renouvellement DNSSEC-Tools distincts fonctionnant simultanément. Chaque environnement de renouvellement, appelé un realm, est défini dans un fichier realms. dtrealms utilise ce fichier pour déterminer comment l'environnement de renouvellement doit être initialisé afin qu'il puisse fonctionner indépendamment des autres environnements de renouvellement sur un système particulier. Cela est utile pour des tâches telles que la gestion de très grandes collections de zones, la séparation des zones des clients et les tests

logiciels.

Le fichier realms peut être créé avec realminit. Actuellement, l'environnement distinct pour chaque realm doit être créé manuellement. On espère qu'un outil sera bientôt disponible pour aider à créer l'environnement de chaque

realm.

dtrealms n'est pas nécessaire pour exécuter plusieurs realms. Cependant, cela facilite la gestion de plusieurs realms exécutés

consécutivement
.

CONFIGURATION DU

REALM

Un realm est principalement défini par son entrée dans un fichier realms. Quatre champs en particulier décrivent où se trouvent les fichiers du realm et comment il s'exécute. Ce sont le répertoire de configuration du realm, le répertoire d'état, le répertoire du realm et le fichier rollrec. Ces répertoires sont utilisés pour définir les variables d'environnement DT_STATEDIR et DT_SYSCONFDIR, et le fichier rollrec définit quelles zones sont gérées par le gestionnaire de renouvellement du

realm.

https://www.dnssec-tools.org/wiki/index.php/Rollover_Realms:_Multiple,_Simultaneous,_Independent_Rollover_Environments contient plus d'informations sur la création de

realms.
configd
ir
Le champ configdir du fichier realms contient le nom du répertoire de configuration du realm. Ce fichier fournit les chemins de commandes et les valeurs de configuration pour exécuter les DNSSEC-Tools. Les modules DNSSEC-Tools s'attendent à ce que cette hiérarchie de répertoires contienne un sous-répertoire dnssec-tools et un fichier dnssec-tools.conf à l'intérieur de ce sous-répertoire. Les champs de chemin dans le fichier de configuration pointent vers diverses choses, telles que des commandes et des archives de clés. Il est recommandé que ces chemins ne pointent que vers l'intérieur de la hiérarchie configdir, à l'exception des utilitaires système.

La variable d'environnement DT_SYSCONFDIR est définie sur le champ configdir. Cela indiquera aux programmes et

modules DNSSEC-Tools où tro
uver leurs données requises.
stated
ir
Le champ statedir du fichier realms contient le nom du répertoire d'état du realm. Ce répertoire contient des fichiers tels que le fichier de verrouillage rollrec et le socket de communication de rollerd. Si une définition de realm ne contient pas de champ statedir, alors ce realm utilisera le champ configdir comme champ statedir.

La variable d'environnement DT_STATEDIR est définie sur le champ statedir. Cela indiquera aux programmes et

modules DNSSEC-Tool
s où trouver ces fichiers.
realmd
ir
Le champ realmdir du fichier realms contient le nom du répertoire dans lequel le realm s'exécute. C'est là que se trouvent les fichiers de zone, de clés et autres fichiers du
realm.
rollr
ec
Le champ rollrec du fichier realms est le nom du fichier qui contrôle le renouvellement des zones. Ce fichier pointe vers les divers fichiers keyrec qui définissent les emplacements des fichiers de zone et de leurs fichiers de clés associés. Le fichier rollrec d'un realm peut localiser ces fichiers n'importe où sur le système, mais il est fortement recommandé qu'ils restent tous dans la hiérarchie realmdir
du re
alm.

Bien que les programmes DNSSEC-Tools fonctionnent correctement si les répertoires de configuration, d'état et de realm d'un realm sont en réalité un seul répertoire, il est recommandé qu'au minimum les fichiers realmdir soient séparés des fichiers configdir et statedir
