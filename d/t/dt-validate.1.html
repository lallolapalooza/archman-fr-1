NOM

dt-validate - Interroger le système DNS et afficher les résultats du processus de validation DNSSEC

SYNTAXE

dt-validate [options] NOM_DOMAINE

DESCRIPTION

dt-validate est un outil de diagnostic basé sur le validateur DNSSEC. Il prend NOM_DOMAINE comme argument et interroge le DNS pour ce nom de domaine. Il affiche la série de réponses reçues du DNS et les résultats de validation DNSSEC pour chaque nom de domaine. L'examen des requêtes et des résultats de validation peut aider un administrateur à découvrir des erreurs dans la configuration DNSSEC des zones DNS.

OPTIONS

-c CLASSE, --class=CLASSE
Cette option permet de spécifier la classe DNS de l'enregistrement de ressource interrogé. Si cette option n'est pas donnée, la classe par défaut IN est utilisée.
-h, --help
Afficher l'aide et quitter.
-p, --print
Imprimer les réponses et les résultats de validation. Par défaut, dt-validate affiche seulement une série de réponses et leurs résultats de validation sur stderr. Lorsque l'option -p est utilisée, dt-validate affichera également le résultat final sur stdout.
-t TYPE, --type=TYPE
Cette option permet de spécifier le type DNS de l'enregistrement de ressource interrogé. Si cette option n'est pas donnée, dt-validate interrogera l'enregistrement A pour le NOM_DOMAINE donné.
-v FICHIER, --dnsval-conf=FICHIER
Cette option permet de spécifier l'emplacement du fichier de configuration dnsval.conf.
-r FICHIER, --resolv-conf=FICHIER
Cette option permet de spécifier l'emplacement du fichier de configuration resolv.conf contenant les serveurs de noms à utiliser pour les recherches.
-i FICHIER, --root-hints=FICHIER
Cette option permet de spécifier l'emplacement du fichier de configuration root.hints, contenant les serveurs de noms racines. Ceci est seulement utilisé lorsqu'aucun serveur de noms n'est trouvé, et que dt-validate doit effectuer lui-même des recherches récursives.
-S suite[:suite], --test-suite=suite[:suite]
Cette option spécifie la suite de tests (ou la plage de suites de tests) à utiliser pour les tests internes.
-s, --selftest
Cette option permet de spécifier que l'application doit effectuer ses tests internes en utilisant les noms de la suite de tests configurée.
-T nombre[:nombre], --testcase=nombre[:nombre]
Cette option permet d'exécuter un test spécifique (ou une plage de tests) de la suite de tests.
-F fichier, --testcase-conf=fichier
Cette option est utilisée pour spécifier le fichier contenant les cas de tests.
-l étiquette, --label=étiquette
Cette option permet de spécifier la politique à utiliser lors de la validation, à partir du fichier dnsval.conf.
-w secondes, --wait=secondes
Cette option permet d'exécuter les requêtes spécifiées par d'autres drapeaux en boucle, avec l'intervalle spécifié entre les requêtes successives.
-o, --output=<niveau-débogage>:<type-destination>[:<options-destination>]
<niveau-débogage> est de 1 à 7, correspondant aux niveaux syslog ALERT à DEBUG. <type-destination> est l'un des suivants : file, net, syslog, stderr, stdout. <options-destination> dépend de <type-destination>.
file:<nom-fichier> (ouvert en mode ajout)
net[:<nom-hôte>:<port-hôte>] (127.0.0.1:1053
syslog[:facilité] (0-23 (par défaut 1 USER))
