DTRACE(1) Manuel des commandes générales DTRACE(1)

NOM

dtrace - Outil de génération de sondes statiques d'applications utilisateur compatible Dtrace.

SYNTAXE

dtrace -s fichier [OPTIONS]

DESCRIPTION

La commande dtrace convertit les descriptions de sondes définies dans file.d en un fichier d'en-tête de sondes via l'option -h ou en un fichier de description de sondes via l'option -G.

OPTIONS

-h
génère un fichier d'en-tête systemtap.
-G
génère un fichier objet de définition de sondes systemtap. Ceci invoque le compilateur C avec un ensemble judicieux d'options de compilation. Si vous avez besoin d'en ajouter, les options trouvées dans la variable d'environnement CFLAGS seront transcrites au compilateur. Si cela ne suffit pas, utilisez l'option -k pour capturer le fichier C généré et le compiler selon vos besoins.
-o fichier
est le nom du fichier de sortie. Si l'option -G est donnée, le fichier de sortie sera nommé fichier.o ; si l'option -h est donnée, le fichier de sortie sera nommé fichier.h.
-C
exécute le préprocesseur cpp sur le fichier d'entrée lorsque l'option -h est donnée.
-I fichier
donne ce chemin d'inclusion à cpp lorsque l'option -C est donnée.
-k
conserve les fichiers temporaires, par exemple le code source C pour l'option -G.

EXEMPLES

Systemtap est compatible source avec le support de sondes statiques d'applications utilisateur de dtrace. Étant donné un fichier test.d contenant :

provider sdt_probes 
{
  probe test_0 (int type);
  probe test_1 (struct astruct node);
};
struct astruct {int a; int b;};

Alors la commande "dtrace -s test.d -G" créera le fichier de définition de sondes test.o et la commande "dtrace -stest.d -h" créera le fichier d'en-tête de sondes test.h. Par la suite, l'application pourra utiliser les macros générées de cette manière :

#include "test.h"
 ...
struct astruct s;
 ...
SDT_PROBES_TEST_0(valeur);
 ...
if (SDT_PROBES_TEST_1_ENABLED())
    SDT_PROBES_TEST_1(fonction_couteuse(s));

SEMAPHORES

Les sémaphores sont des variables d'indicateur utilisées par les sondes comme moyen de contourner un traitement potentiellement coûteux pour préparer les arguments des sondes qui pourraient même ne pas être actives. Ils sont automatiquement définis/effacés par systemtap lorsqu'un script pertinent est en cours d'exécution, de sorte que le coût de préparation des arguments n'est payé que lorsque nécessaire. Ces variables de sémaphores sont définies dans le fichier objet "test.o", qui doit donc être lié à une application.

Parfois, les variables de sémaphores ne sont ni nécessaires ni utiles. Les ignorer peut simplifier le processus de construction, en omettant le fichier "test.o" supplémentaire. Pour ignorer la dépendance aux variables de sémaphores, incluez "<sys/sdt.h>" dans l'application avant "test.h" :

#include <sys/sdt.h>
#include "test.h"
 ...
struct astruct s;
 ...
SDT_PROBES_TEST_0(valeur);
 ...
if (SDT_PROBES_TEST_1_ENABLED())
   SDT_PROBES_TEST_1(fonction_peu_couteuse(s));

Dans ce mode, le test ENABLED() est fixé à 1.
