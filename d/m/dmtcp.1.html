DESCRIPTIO

N

DMTCP est un outil pour effectuer de manière transparente un checkpoint de l'état d'un groupe arbitraire de programmes répartis sur de nombreuses machines et connectés par sockets. Il ne modifie ni le programme de l'utilisateur ni le système d'exploitation. MTCP est un composant autonome de DMTCP disponible en tant qu

e bibliothèque de checkpoin
ting pour un processus unique.

DMTCP_COORDINATO

R

Chaque calcul à mettre en checkpoint doit inclure un processus coordinateur DMTCP. On peut explicitement démarrer un coordinateur via dmtcp_coordinator, ou permettre à l'un d'être démarré implicitement en arrière-plan par soit dmtcp_launch soit dmtcp_restart pour fonctionner. L'adresse du coordinateur unique devrait être spécifiée par dmtcp_launch, dmtcp_restart et dmtcp_command soit via les indicateurs --host et --port en ligne de commande ou via les variables d'environnement DMTCP_HOST et DMTCP_PORT. Si aucune n'est donnée, la paire hôte-port par défaut est localhost-7779. La paire hôte-port associée à un coordinateur particulier est donnée par les indicateurs en ligne de commande utilisés dans la commande dmtcp_coordinator, ou les variables d'environnement alors en vigueur, ou la valeur par défaut

localhost-7779.

Le coordinateur est sans état et n'est pas mis en checkpoint. Au redémarrage, on peut utiliser un coordinateur existant ou un nouveau. Plusieurs calculs sous le contrôle de DMTCP peuvent coexister en fournissant un coordinateur unique (avec une paire hôte-port unique) pour chaque tel

calcul.

Le coordinateur initie un checkpoint pour tous les processus de son groupe de calcul. Les checkpoints peuvent être : effectués automatiquement sur un intervalle (voir DMTCP_CHECKPOINT_INTERVAL ci-dessus) ; ou initiés manuellement sur l' entrée standard du coordinateur (voir le paragraphe suivant) ; ou initiés directement sous le contrôle du programme par le calcul via l'API de plugin (voir ci-dessous)

.

Le coordinateur accepte les commandes suivantes sur son entrée standard. Chaque commande doit être suivie de la touche <retour>. Les commandes sont :
l : Lister les nœuds connectés
s : Afficher un message d'état
c : Mettre en checkpoint tous les nœuds
f : Forcer un redémarrage même s'il y a des nœuds manquants (débogage)
k : Tuer tous les nœuds
q : Tuer tous les nœuds et quitter
? : Afficher ce

message

Les commandes du coordinateur peuvent également être émises à distance en utilisant dmtcp_comman

d

PLUGIN

DMTCP

La distribution source inclut un répertoire plugin au niveau supérieur, avec des exemples de la manière d'écrire un plugin pour DMTCP. Les plugins permettent à une application mise en checkpoint de se déconnecter d'une ressource externe, puis de se reconnecter à celle-ci au moment du redémarrage. D'autres exemples se trouvent dans le répertoire test/plugin. En particulier, test/plugin/applic-initiated démontre comment une application peut demander un checkpoint sous le contrôle du

programme.

La fonctionnalité plugin ajoute trois nouvelles capacités programmables par l'utilisateur. Un plugin peut : ajouter des wrappers autour des appels système ; prendre des actions spéciales lors de certains événements (par ex. pré-checkpoint, reprise/post-checkpoint, redémarrage) ; et peut insérer des paires clé-valeur dans une base de données au moment du redémarrage qui est ensuite disponible pour être interrogée par les processus redémarrés d'un calcul. (Les événements disponibles pour la fonctionnalité plugin forment un sur-ensemble des événements disponibles avec l'interface dmtcpaware.) Un ou plusieurs plugins sont invoqués via une liste de chemins absolus séparés par des

deux-points.


dmtcp_launch --with-plugin PLUGIN1[:PLUGIN2].

.

API

DMTCPAWARE

Cette API est désormais obsolète au profit des plugins DMTCP (voir ci-dessus). DMTCP fournit une interface de programmation pour permettre aux applications mises en checkpoint d' interagir avec dmtcp. Dans la distribution source, voir dmtcpaware/dmtcpaware.h pour les fonctions disponibles. Voir test/dmtcpaware[123].c pour trois exemples d'applications. Pour un exemple de son utilisation, essayer

CODE DE

RETOUR

Un programme cible sous le contrôle de DMTCP renvoie normalement le même code de retour que s'il était exécuté sans DMTCP. Cependant, si DMTCP échoue (par opposition à l'échec du programme cible), DMTCP renvoie un code de retour spécifique à DMTCP, rc (ou rc+1, rc+2 pour deux cas spéciaux), où rc est la valeur entière de la variable d'environnement DMTCP_FAIL_RC si elle est définie, sinon la valeur par défautult v

alue
, 99.
