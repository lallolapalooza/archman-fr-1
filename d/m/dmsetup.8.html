DESCRIPTIO

N

dmsetup gère les périphériques logiques qui utilisent le pilote device-mapper. Les périphériques sont créés en chargeant une table qui spécifie une cible pour chaque secteur (512 octets) dans le périphérique

logique.

Le premier argument de dmsetup est une commande. Le deuxième argument est le nom ou l'uuid du périphérique

logique.

Invoquer l'outil dmsetup en tant que devmap_name (qui n'est pas normalement distribué et n'est pris en charge que pour des raisons historiques) est équivalent à dmsetup info -c --noheadings -j major -m minor

.

S'assure que les noms et UUID
existants des périphériques device-mapperr nom_périphérique et l'UUID sont sous la forme correcte entre parenthèses contenant uniquement des caractères autorisés (supportés par udev) et effectue un renommage si nécessaire. Les UUID incorrects sont uniquement signalés et doivent être corrigés manuellement en désactivant d'abord le périphérique, puis en le réactivant avec le mode entre parenthèses approprié utilisé (voir aussi --manglename).

remove [-f|--force] [--retry] [--deferred] nom_périphérique ...
Supprime un périphérique. Il ne sera plus visible par dmsetup. Les périphériques ouverts ne peuvent pas être supprimés, mais l'ajout de --force remplacera la table par une qui échoue à toutes les E/S. --deferred activera la suppression différée des périphériques ouverts - le périphérique sera supprimé lorsque le dernier utilisateur le fermera. La fonction de suppression différée est supportée depuis la version 4.27.0 du pilote device-mapper disponible dans le noyau principal version 3.13. (Utilisez dmsetup version pour vérifier cela.) Si une tentative de suppression d'un périphérique échoue, peut-être parce qu'un processus exécuté à partir d'une règle udev rapide a temporairement ouvert le périphérique, l'option --retry fera réessayer l'opération pendant quelques secondes avant d'échouer. Ne combinez PAS --force et --udevcookie, car udev pourrait commencer à traiter les règles udev au milieu du remplacement de la cible d'erreur et entraîner un résultat non déterministe.

remove_all [-f|--force] [--deferred]
Tente de supprimer toutes les définitions de périphériques, c'est-à-dire de réinitialiser le pilote. Ceci exécute également mknodes par la suite. À utiliser avec précaution ! Les périphériques ouverts ne peuvent pas être supprimés, mais l'ajout de --force remplacera la table par une qui échoue à toutes les E/S. --deferred activera la suppression différée des périphériques ouverts - le périphérique sera supprimé lorsque le dernier utilisateur le fermera. La fonction de suppression différée est supportée depuis la version 4.27.0 du pilote device-mapper disponible dans le noyau principal version 3.13.

splitname nom_périphérique [sous-système]
Divise le nom_périphérique donné en constituants de sous-système. Le sous-système par défaut est LVM. LVM génère actuellement des noms de périphériques en concaténant les noms du groupe de volumes, du volume logique et de toute couche interne avec un trait d'union comme séparateur. Tous les traits d'union dans les noms sont doublés pour les échapper. L'encodage précis peut changer sans préavis dans toute version future, nous vous recommandons donc de toujours décoder en utilisant la version actuelle de cette commande.

stats commande [options]
Gère les régions de statistiques d'E/S pour les périphériques. Voir dmstats(8) pour plus de détails.

status [--target type_cible] [--noflush] [nom_périphérique ...]
Affiche les informations d'état pour chacune des cibles du périphérique. Avec --target, seules les informations relatives au type de cible spécifié sont affichées. Avec --noflush, la cible thin (à partir de la version 1.3.0) ne valide aucune modification en attente sur le disque avant de rapporter ses statistiques.

suspend nom_périphérique ... [--nolockfs] [--noflush]
Suspend un périphérique. Toute E/S déjà mappée par le périphérique mais qui n'a pas encore été terminée sera vidée. Toute E/S supplémentaire vers ce périphérique sera postposée tant que le périphérique est suspendu. S'il y a un système de fichiers sur le périphérique qui supporte l'opération, une tentative sera faite pour le synchroniser d'abord, sauf si --nolockfs est spécifié. Certaines cibles comme les versions récentes (octobre 2006) de multipath peuvent supporter l'option --noflush. Cela permet aux E/S en attente qui n'ont pas encore atteint le périphérique de rester non vidées.

table [--concise] [--target type_cible] [--showkeys] [nom_périphérique ...]
Affiche la table actuelle du périphérique dans un format qui peut être renvoyé en utilisant les commandes create ou load. Avec --target, seules les informations relatives au type de cible spécifié sont affichées. Les clés de chiffrement réelles sont supprimées de la sortie de la table pour les cibles crypt et integrity, sauf si le paramètre --showkeys est fourni. Les références de clés du noyau préfixées par : ne sont pas affectées par le paramètre et sont toujours affichées (cible crypt uniquement). Avec --concise, la sortie est présentée de manière concise sur une seule ligne. Les virgules séparent ensuite le nom, l'UUID, le numéro de périphérique mineur, les drapeaux ('ro' ou 'rw') et la table (si présente). Les points-virgules séparent les périphériques. Les barres obliques inversées échappent les virgules, les points-virgules ou les barres obliques inversées. Voir FORMAT CONCIS ci-dessous.

targets
Affiche les noms et les versions des cibles actuellement chargées.

udevcomplete cookie
Réveille tout processus en attente que udev termine le traitement du cookie spécifié.

udevcomplete_all [âge_en_minutes]
Supprime tous les cookies plus anciens que le nombre de minutes spécifié. Tout processus en attente d'un cookie sera repris immédiatement.

udevcookie
Liste tous les cookies existants. Les cookies sont des sémaphores système avec des clés précédées de deux octets prédéfinis (0x0D4D).

udevcreatecookie
Crée un nouveau cookie pour synchroniser les actions avec le traitement udev. La sortie est une valeur de cookie. Normalement, nous n'avons pas besoin de créer de cookies car dmsetup en crée et en détruit automatiquement pour chaque action. Cependant, nous pouvons en générer un explicitement pour regrouper plusieurs actions et n'utiliser qu'un seul cookie. Nous pouvons définir un cookie à utiliser pour chaque commande pertinente en utilisant l'option --udevcookie. Alternativement, nous pouvons exporter cette valeur dans l'environnement du processus dmsetup sous la variable DM_UDEV_COOKIE et elle sera utilisée automatiquement avec toutes les commandes suivantes jusqu'à ce qu'elle soit désactivée. L'invocation de cette commande créera un sémaphore système qui devra être nettoyé explicitement en appelant la commande udevreleasecookie.

udevflags cookie
Analyse la valeur de cookie donnée et extrait tous les indicateurs de contrôle udev encodés. La sortie est au format de clé d'environnement approprié pour une utilisation dans les règles udev. Si l'indicateur a son nom symbolique attribué, la sortie est DM_UDEV_FLAG_<nom_indicateur> = '1', DM_UDEV_FLAG<position_indicateur> = '1' sinon. Les indicateurs de sous-système udev n'ont pas de noms symboliques attribués et ceux-ci sont toujours rapportés comme DM_SUBSYSTEM_UDEV_FLAG<position_indicateur> = '1'. Il y a 16 indicateurs udev au total.

udevreleasecookie [cookie]
Attend que tout le traitement udev en attente lié à la valeur du cookie donnée soit terminé et nettoie le cookie avec le sémaphore sous-jacent. Si le cookie n'est pas donné directement, la commande essaiera d'utiliser une valeur définie par la variable d'environnement DM_UDEV_COOKIE.

version
Affiche les informations de version.

wait nom_périphérique [--noflush] [num_événement]
Attend jusqu'à ce que le compteur d'événements pour nom_périphérique dépasse num_événement. Utilisez -v pour voir le numéro d'événement renvoyé. Pour attendre le prochain événement, utilisez info pour trouver le dernier numéro d'événement. Avec --noflush, la cible thin (à partir de la version 1.3.0) ne valide aucune modification en attente sur le disque avant de rapporter ses statistiques.

wipe_table nom_périphérique ... [-f|--force] [--noflush] [--nolockfs]
Attend que toutes les E/S en cours dans le périphérique soient terminées, puis remplace la table par une nouvelle table qui échoue à toutes les nouvelles E/S envoyées au périphérique. Si cette opération réussit, elle devrait libérer tous les périphériques détenus par la ou les tables du périphérique.

FORMAT DE TABLE

Chaque ligne de la table spécifie une seule cible et est de la forme :

secteur_de_début_logique nb_secteurs type_cible arguments_cible

Les types de cibles et arguments de cibles simples incluent :

linear périphérique_destination secteur_de_début
Le mappage linéaire traditionnel.

striped nb_bandes taille_bande [destination secteur_de_début] ...
Crée une zone striée.
par exemple : striped 2 32 /dev/hda1 0 /dev/hdb1 0 mappera le premier bloc (16 KiB) comme suit :

Bloc LV 1 → hda1, bloc 1
Bloc LV 2 → hdb1, bloc 1
Bloc LV 3 → hda1, bloc 2
Bloc LV 4 → hdb1, bloc 2
etc.
error
Génère une erreur pour toute E/S allant dans cette zone. Utile pour les tests ou pour créer des périphériques avec des trous.
zero
Renvoie des blocs de zéros lors des lectures. Toute donnée écrite est discardée silencieusement. C'est l'équivalent périphérique bloc de l'évier de données de périphérique caractère /dev/zero décrit dans null(4).
