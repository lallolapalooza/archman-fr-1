DMA(8) Manuel de l'administrateur système DMA(8)

NOM

dma — Agent de messagerie DragonFly

SYNOPSIS

dma [-DiOt] [-Amode] [-bmode] [-f sender] [-L tag] [-ooption] [-r sender] [-q[arg]] [destinataire ...]

DESCRIPTION

dma est un petit agent de transport de courrier (MTA), conçu pour un usage domestique et de bureau. Il accepte les courriels provenant des agents utilisateur de courrier (MUA) installés localement et les livre soit localement, soit vers une destination distante. La livraison distante inclut plusieurs fonctionnalités telles que la prise en charge de TLS/SSL et l'authentification SMTP.

dma n'est pas destiné à remplacer de vrais MTAs complets comme sendmail(8) ou postfix(1). Par conséquent, dma n'écoute pas sur le port 25 pour les connexions entrantes.

Les options sont les suivantes :

-Amode
-Ac sert d'option de compatibilité pour sendmail.
-bmode
-bp
Liste tous les courriels actuellement stockés dans la file d'attente.
-bq
Met le courrier en file d'attente sans tenter de le livrer. Voir aussi le paramètre de fichier de configuration ‘DEFER’ ci-dessous.

Tous les autres modes sont ignorés.

-D
Ne pas s'exécuter en arrière-plan. Utile pour le débogage.
-f sender
Définit l'adresse de l'expéditeur (envelope-from) à sender. Cela remplace la valeur de la variable d'environnement EMAIL , mais est remplacé par le paramètre de fichier de configuration ‘MASQUERADE’.
-i
Ignore les points seuls sur leur propre ligne dans les messages entrants. Cela devrait être défini si vous lisez des données depuis un fichier.
-L tag
Définit l'identifiant utilisé dans les messages syslog à la valeur tagfournie. C'est une option de compatibilité pour sendmail.
-O
C'est une option de compatibilité pour sendmail.
-ooption
Spécifier -oi est synonyme de -i. Toutes les autres options sont ignorées.
-q[arg]
Traite les messages enregistrés dans la file d'attente. L'argument est facultatif et ignoré.
-r sender
Identique à -f.
-t
Obtient les adresses des destinataires à partir de l'en-tête du message. dma analysera les en-têtes To:, Cc:et Bcc: . L'en-tête Bcc: sera supprimé que -t soit spécifié ou non.

CONFIGURATION

dma peut être configuré avec deux fichiers de configuration :

  • auth.conf
  • dma.conf

Ces deux fichiers sont stockés par défaut dans /etc/dma.

FORMAT DES FICHIERS

Chaque fichier contient des paramètres de la forme ‘nom valeur’. Les lignes contenant des valeurs booléennes sont définies à ‘NO’ si la ligne est commentée et à ‘YES’ si la ligne est décommentée. Les lignes vides ou les lignes commençant par un ‘#’ sont ignorées. Les noms de paramètres et leurs valeurs sont sensibles à la casse.

PARAMÈTRES

auth.conf

L'authentification SMTP peut être configurée dans auth.conf. Chaque ligne a le format “user|smarthost:password”.

dma.conf

La plupart du comportement de dma peut être configuré dans dma.conf.

SMARTHOST (chaîne, par défaut=vide)
Si vous souhaitez envoyer les courriels sortants via un smarthost, définissez cette variable à l'adresse de votre smarthost.
PORT (numérique, par défaut=25)
Utilisez ce port pour livrer les courriels distants. Utile uniquement en conjonction avec l'option ‘SMARTHOST’, car dma livrera tous les courriels vers ce port, que un smarthost soit défini ou non.
ALIASES (chaîne, par défaut=/etc/aliases)
Chemin vers le fichier d'alias locaux. Restez simplement avec la valeur par défaut. Le fichier d'alias est au format
nom: dest1 dest2 ...
Dans ce cas, les courriels destinés à nom seront à la place livrés à dest1 et dest2, qui pourraient à leur tour être des entrées dans /etc/aliases. Le nom spécial ‘*’ peut être utilisé pour créer un alias catch-all, qui est utilisé si aucun autre alias correspondant n'est trouvé. N'utilisez l'alias catch-all que si vous ne souhaitez recevoir aucun courrier local.
SPOOLDIR (chaîne, par défaut=/var/spool/dma)
Chemin vers le répertoire de spool de dma. Restez simplement avec la valeur par défaut.
AUTHPATH (chaîne, par défaut=non défini)
Chemin vers le fichier ‘auth.conf’.
SECURETRANSFER (booléen, par défaut=commenté)
Décommentez si vous souhaitez un transfert sécurisé par TLS/SSL.
STARTTLS (booléen, par défaut=commenté)
Décommentez si vous souhaitez utiliser STARTTLS. Utile uniquement en conjonction avec ‘SECURETRANSFER’.
VERIFYCERT (booléen, par défaut=commenté)
Vérifie le certificat du serveur par rapport à l'autorité de certification (CA). N'a de sens que si vous utilisez un smarthost.
FINGERPRINT (chaîne, par défaut=vide)
Épingle le certificat du serveur en spécifiant son empreinte SHA256. N'a de sens que si vous utilisez un smarthost.
OPPORTUNISTIC_TLS (booléen, par défaut=commenté)
Décommentez si vous souhaitez autoriser la négociation STARTTLS à échouer. Utile surtout lorsque dma est utilisé sans smarthost, livrant les messages distants directement aux échangeurs de courrier externes ; en mode TLS opportuniste, la connexion sera chiffrée si le serveur distant prend en charge STARTTLS, mais une livraison non chiffrée sera tout de même effectuée si la négociation échoue. Utile uniquement en conjonction avec ‘SECURETRANSFER’ et ‘STARTTLS’.
CERTFILE (chaîne, valeur par défaut=vide)
Chemin vers votre fichier de certificat SSL.
SECURE (booléen, valeur par défaut=commenté)
Décommentez cette entrée et changez-la en ‘INSECURE’ pour utiliser une connexion SMTP en texte clair sur une connexion non sécurisée. Vous devez renommer cette variable manuellement pour éviter d'envoyer votre mot de passe accidentellement sur une connexion non sécurisée.
DEFER (booléen, valeur par défaut=commenté)
Décommentez si vous voulez que dma diffère votre courrier. Vous devez vider votre file d'attente de courrier manuellement avec l'option -q . Cette option est pratique si vous êtes derrière une connexion commutée.
FULLBOUNCE (booléen, valeur par défaut=commenté)
Décommentez si vous voulez que le message de rebond inclue le message original complet, et pas seulement les en-têtes.
MAILNAME (chaîne, valeur par défaut=vide)
Le nom d'hôte internet que dma utilise pour identifier l'hôte. S'il n'est pas défini ou est vide, le résultat de gethostname(3) est utilisé. Si ‘MAILNAME’ est un chemin absolu vers un fichier, la première ligne de ce fichier sera utilisée comme nom d'hôte.
MASQUERADE (chaîne, valeur par défaut=vide)
Déguise les adresses d'enveloppe-expéditeur avec cette adresse/nom d'hôte. Utilisez ce paramètre si les courriers ne sont pas acceptés par les serveurs de courrier de destination parce que votre domaine expéditeur est invalide. Ce paramètre remplace l'indicateur -f et la variable d'environnement EMAIL .

Si ‘MASQUERADE’ ne contient pas de signe @ , la chaîne est interprétée comme un nom d'hôte. Par exemple, définir ‘MASQUERADE’ à ‘john@’ sur l'hôte ‘hamlet’ enverra tous les courriers en tant que ‘john@hamlet’ ; le définir à ‘percolator’ enverra tous les courriers en tant que ‘Sm off nomdutilisateur @percolator’.

NULLCLIENT (booléen, valeur par défaut=commenté)
Contourne les alias et la livraison locale, et transmet à la place tous les courriers au ‘SMARTHOST’ défini. ‘NULLCLIENT’ requiert que ‘SMARTHOST’ soit défini.

Variables d'environnement

Le comportement de dma peut être influencé par quelques variables d'environnement.

EMAIL
Utilisée pour définir l'adresse de l'expéditeur (enveloppe-expéditeur). Utilisez une adresse simple, sous la forme de user@example.com. Cette valeur sera remplacée lorsque le paramètre de configuration ‘MASQUERADE’ ou l'indicateur -f est utilisé.
