NOM

dmmp_path_status_get - Récupérer le statut du chemin.

SYNTAXE

uint32_t dmmp_path_status_get (struct dmmp_path *dmmp_p);

ARGUMENTS

dmmp_p
Pointeur de 'struct dmmp_path'. Si ce pointeur est NULL, votre programme sera terminé par assert.

DESCRIPTION

Les statuts de chemin valides sont :

* DMMP_PATH_STATUS_UNKNOWN

* DMMP_PATH_STATUS_DOWN

Le chemin est inactif et vous ne devriez pas essayer d'envoyer des commandes dessus.

* DMMP_PATH_STATUS_UP

Le chemin est actif et les opérations d'E/S peuvent lui être envoyées.

* DMMP_PATH_STATUS_SHAKY

Uniquement pour le vérificateur emc_clariion lorsque le chemin n'est pas disponible pour les opérations "normales".

* DMMP_PATH_STATUS_GHOST

Uniquement pour les vérificateurs hp_sw et rdac. Indique un chemin "passif/en veille" sur les baies HP actif/passif. Ces chemins renverront des réponses valides à certaines commandes SCSI (tur, read_capacity, inquiry, start_stop), mais échoueront aux commandes d'E/S. Un command d'initialisation doit être envoyé au chemin pour que les E/S réussissent.

* DMMP_PATH_STATUS_PENDING

Disponible pour tous les vérificateurs asynchrones lorsqu'une E/S de vérification est en cours.

* DMMP_PATH_STATUS_TIMEOUT

Uniquement pour le vérificateur tur lorsque la commande a expiré.

* DMMP_PATH_STATUS_DELAYED

Si un chemin échoue après avoir été actif pendant moins de delay_watch_checks vérifications, lorsqu'il revient en ligne, il ne sera pas marqué comme actif jusqu'à ce qu'il le soit pendant delay_wait_checks vérifications. Pendant ce temps, il est marqué comme "en retard".

RETOUR

uint32_t.
