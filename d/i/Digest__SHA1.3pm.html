DESCRIPTIO

N

Le module "Digest::SHA1" vous permet d'utiliser l'algorithme de message digest SHA-1 du NIST depuis des programmes Perl. L'algorithme prend en entrée un message de longueur arbitraire et produit en sortie une "empreinte" ou un "message digest" de 160 bits de

l'entrée.

En 2005, des failles de sécurité ont été identifiées dans SHA-1, à savoir qu'une faiblesse mathématique possible pourrait exister, indiquant qu'une fonction de hachage plus forte serait souhaitable. Le module Digest::SHA implémente les algorithmes plus forts de la famille

SHA.

Le module "Digest::SHA1" fournit une interface procédurale pour une utilisation simple, ainsi qu'une interface ori

entée objet qui peut traiter des messages de longueur
arbitraire et qui peut lire des fichiers directement.

FONCTION

S

Les fonctions suivantes peuvent être exportées depuis le module "Digest::SHA1". Aucune fonction n'est exportée par

défaut.
sha1($data,.
..)
Cette fonction va concaténer tous les arguments, calculer le digest SHA-1 de ce "message", et le retourner sous forme binaire. La chaîne retournée fera 20 octets de long.

Le résultat de sha1("a", "b",

"c") sera exactement le même que
le résultat de sha1("abc").
sha1_hex($data,.
..)
Identique à sha1(), mais retournera le digest sous forme hexadécimale. La longueur de la chaîne retournée sera de 40 et elle ne contiendra que des caractères de cet ensemble : '0'..'9' et 'a'..
'f'.
sha1_base64($data,.
..)
Identique à sha1(), mais retournera le digest sous forme de chaîne encodée en base64. La longueur de la chaîne retournée sera de 27 et elle ne contiendra que des caractères de cet ensemble : 'A'..'Z', 'a'..'z', '0'..'9', '+' et '/'.

Notez que la chaîne encodée en base64 retournée n'est pas remplie pour être multip

le de 4 octets. Si vous voulez l'interopérabilité avec d'autres digests sha1 enco
dés en base64, vous pourriez vouloir ajouter la chaîne redondante "=" au résultat.
sha1_transform($da
ta)
Implémente la transformation SHA1 de base sur un bloc de 64 octets. L'argument $data et le $digest retourné sont sous forme binai
re. Cet algorithme
est utilisé d
ans NIST FIPS 186-2

MÉTHODE

S

L'interface orientée objet pour "Digest::SHA1" est décrite dans cette section. Après qu'un objet "Digest::SHA1" a été créé, vous ajouterez des données à celui-ci et finalement demanderez le digest dans un format adapté. Un seul objet peut être utilisé pour calculer plusieurs

digests.

Les méthodes suivantes sont fournies

:
$sha1 = Digest::SHA1->
new
Le constructeur retourne un nouvel objet "Digest::SHA1" qui encapsule l'état de l'algorithme de message digest SHA-1.

S'il est appelé comme méthode d'instance (c'est-à-dire $sha1->new), il réinitialisera simplement l'état de l'objet à l'état d'un objet nouvellement créé. Aucun nouvel objet n'est créé dans

ce
cas.
$sha1->
reset
Ceci est juste un alias pour $sha1->
new.
$sha1->
clone
Ceci est une copie de l'objet $sha1. C'est utile quand vous ne voulez pas détruire l'état du digest, mais avez besoin d'une valeur intermédiaire du digest, par exemple lors du calcul de digests de manière itérative sur un flux de données continu. Exemple : 
my $sha1 = Digest::SHA1->new;
while (<>) {
    $sha1->add($_);
    print "Ligne $. : ", $sha1->clone->hexdigest,
"\n";
}
$sha1->add($data,.
..)
Les $data fournis en argument sont ajoutés au message pour lequel nous calculons le digest. La valeur de retour est l'objet $sha1 lui-même.

Toutes ces lignes auront le même effet sur l'état de l'objet $s

ha1 :

$sha1->add("a")->add("b")->add("c");
$sha1->add("a", "b", "c");

;
$sha1->addfile($io_hand
le)
Le $io_handle sera lu jusqu'à EOF et son contenu ajouté au message pour lequel nous calculons le digest. La valeur de retour est l'objet $sha1 lui-même.

La méthode addfile() va croak() si elle échoue à lire les données pour une raison quelconque. Si elle échoue, il est imprévisible quel sera l'état de l'objet $sha1. La méthode addfile() a peut-être pu lire le fichier partiellement avant d'échouer. Il est probablement sage de supprimer ou de réinitialiser l'objet $sha1 si cela se

produit.

Dans la plupart des cas, vous voudrez vous assurer que $io_handle est en "binmode" avant de le passer comme argument à la méthode a

ddfil

Cette implémentation de SHA-1 ne supporte que les entrées orientées octets, donc vous ne pouvez ajouter des bits que par multiples de 8. Si vous avez besoin d'un support au niveau des bits, veuillez envisager d'utiliser le module "Digest::SHA" à la place. La méthode add_bits() est fournie ici pour la compatibilité avec d'autres implémentations de digest. Voir Digest pour la description des arguments que add_bits()
