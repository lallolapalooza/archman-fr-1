DISTROBOX-ENTER(1) Manuel utilisateur DISTROBOX-ENTER(1)

NOM

distrobox enter
distrobox-enter

DESCRIPTION

distrobox-enter se charge d'entrer dans le conteneur avec le nom spécifié. La commande par défaut exécutée est votre SHELL, mais vous pouvez spécifier différents shells ou des commandes complètes à exécuter. Si vous l'utilisez dans un script, une application ou un service, vous pouvez spécifier le mode --headless pour désactiver le tty et l'interactivité.

SYNOPIS

distrobox enter

--name/-n:      nom pour la distrobox                      par défaut : my-distrobox
--/-e:          les arguments de fin exécutent le reste comme commande à exécuter à la connexion   par défaut : le shell de ${USER} par défaut
--no-tty/-T:        ne pas instancier de tty
--no-workdir/-nw:   toujours démarrer le conteneur depuis le répertoire personnel du conteneur
--additional-flags/-a:  flags supplémentaires à passer à la commande de gestionnaire de conteneur
--help/-h:      afficher ce message
--root/-r:      lancer podman/docker/lilipod avec les privilèges root. Notez que si vous avez besoin de root, c'est la manière préférée
            plutôt que "sudo distrobox" (note : si vous utilisez un programme autre que 'sudo' pour les privilèges root est nécessaire,
            spécifiez-le via la variable d'environnement DBX_SUDO_PROGRAM, ou la variable de configuration 'distrobox_sudo_program')
--dry-run/-d:       imprimer uniquement la commande du gestionnaire de conteneur générée
--verbose/-v:       afficher plus de verbosité
--version/-V:       afficher la version

EXEMPLES

Entrer dans une distrobox nommée “example”

distrobox-enter example

Entrer dans une distrobox en spécifiant une commande

distrobox-enter --name fedora-toolbox-35 -- bash -l
distrobox-enter my-alpine-container -- sh -l

Utiliser des flags podman/docker/lilipod supplémentaires lors de l'entrée dans une distrobox

distrobox-enter --additional-flags "--preserve-fds" --name test -- bash -l

Spécifier des variables d'environnement supplémentaires lors de l'entrée dans une distrobox

distrobox-enter --additional-flags "--env MY_VAR=value" --name test -- bash -l
MY_VAR=value distrobox-enter --additional-flags "--preserve-fds" --name test -- bash -l

Vous pouvez également utiliser des variables d'environnement pour spécifier le gestionnaire de conteneur et le nom du conteneur :

DBX_CONTAINER_MANAGER="docker" DBX_CONTAINER_NAME=test-alpine distrobox-enter

VARIABLES D'ENVIRONNEMENT

DBX_CONTAINER_NAME
DBX_CONTAINER_MANAGER
DBX_SKIP_WORKDIR
DBX_SUDO_PROGRAM

EXTRA

Cette commande est utilisée pour entrer dans la distrobox elle-même. Personnellement, je crée simplement plusieurs profils dans mon gnome-terminal pour avoir plusieurs distributions accessibles.

Le drapeau --additional-flags ou -a est utile pour modifier la commande par défaut lors de l'exécution dans le conteneur. Par exemple :

distrobox enter -n dev-arch --additional-flags "--env my_var=test" -- printenv &| grep my_var
my_var=test

Ceci est également possible en utilisant des variables d'environnement normales :

my_var=test distrobox enter -n dev-arch --additional-flags -- printenv &| grep my_var
my_var=test

Si vous souhaitez entrer dans un conteneur rootful en faisant en sorte que distrobox utilise un programme autre que `sudo' pour exécuter podman/docker/lilipod en tant que root, tel que `pkexec' ou `doas', vous pouvez le spécifier avec la variable d'environnement DBX_SUDO_PROGRAM. Par exemple, pour utiliser `doas' pour entrer dans un conteneur rootful :

DBX_SUDO_PROGRAM="doas" distrobox enter -n container --root

De plus, dans l'un des chemins de fichiers de configuration que distrobox prend en charge, tel que ~/.distroboxrc, vous pouvez également ajouter la ligne distrobox_sudo_program="doas" (par exemple) pour toujours exécuter les commandes distrobox impliquant des conteneurs rootful en utilisant `doas'.
