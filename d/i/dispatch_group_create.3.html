dispatch_group_create(3) Manuel des fonctions de bibliothèque dispatch_group_create(3)

NOM

dispatch_group_create, dispatch_group_async, dispatch_group_wait, dispatch_group_notify — regroupe les blocs soumis aux files d'attente

SYNTAXE

#include <dispatch/dispatch.h>

dispatch_group_t
dispatch_group_create(void);

void
dispatch_group_enter(dispatch_group_t group);

void
dispatch_group_leave(dispatch_group_t group);

long
dispatch_group_wait(dispatch_group_t group, dispatch_time_t timeout);

void
dispatch_group_notify(dispatch_group_t group, dispatch_queue_t queue, void (^block)(void));

void
dispatch_group_notify_f(dispatch_group_t group, dispatch_queue_t queue, void *context, void (*function)(void *));

void
dispatch_group_async(dispatch_group_t group, dispatch_queue_t queue, void (^block)(void));

void
dispatch_group_async_f(dispatch_group_t group, dispatch_queue_t queue, void *context, void (*function)(void *));

DESCRIPTION

Un groupe de dispatch est une association d'un ou plusieurs blocs soumis à des files d'attente de dispatch pour une invocation asynchrone. Les applications peuvent utiliser les groupes de dispatch pour attendre l'achèvement des blocs associés au groupe.

La fonction dispatch_group_create() renvoie un nouveau groupe de dispatch vide.

Les fonctions dispatch_group_enter() et dispatch_group_leave() mettent à jour le nombre de blocs en cours d'exécution dans un groupe.

La fonction dispatch_group_wait() attend que tous les blocs associés au group soient terminés, ou que le délai d'attente spécifié timeout soit écoulé. Si le group devient vide dans le temps imparti, la fonction renverra zéro, indiquant le succès. Sinon, un code de retour non nul sera renvoyé. Lorsque DISPATCH_TIME_FOREVER est passé comme timeout, les appels à cette fonction attendront indéfiniment jusqu'à ce que le groupe soit vide et que la valeur de retour soit toujours zéro.

La fonction dispatch_group_notify() fournit une notification asynchrone de l'achèvement des blocs associés au group en soumettant le block à la queue spécifiée une fois que tous les blocs associés au group sont terminés. Le système conserve une référence au groupe de dispatch pendant qu'une notification asynchrone est en attente, il est donc valide de libérer le group après avoir défini un bloc de notification. Le groupe sera vide au moment où le bloc de notification est soumis à la file d'attente cible. Le groupe peut être libéré avec dispatch_release() ou réutilisé pour des opérations supplémentaires.

La fonction utilitaire dispatch_group_async() se comporte comme suit :

void
dispatch_group_async(dispatch_group_t group, dispatch_queue_t queue, dispatch_block_t block)
{
	dispatch_retain(group);
	dispatch_group_enter(group);
	dispatch_async(queue, ^{
		block();
		dispatch_group_leave(group);
		dispatch_release(group);
	});
}

VALEUR DE RETOUR

La fonction dispatch_group_create() renvoie NULL en cas d'échec et non-NULL en cas de succès.

La fonction dispatch_group_wait() renvoie zéro en cas de succès et non-zéro après l'expiration du délai d'attente. Si le délai d'attente est DISPATCH_TIME_FOREVER, alors dispatch_group_wait() attend indéfiniment et renvoie toujours zéro.

MODÈLE DE MÉMOIRE

Les groupes de dispatch sont conservés et libérés via des appels à dispatch_retain() et dispatch_release().

FONDAMENTAUX

Les fonctions dispatch_group_async() et dispatch_group_notify() sont des enveloppes pour dispatch_group_async_f() et dispatch_group_notify_f() respectivement.

ATTENTION

Afin d'assurer un comportement déterministe, il est recommandé d'appeler dispatch_group_wait() uniquement une fois que tous les blocs ont été soumis au groupe. S'il est déterminé ultérieurement que de nouveaux blocs doivent être exécutés, il est recommandé de ne pas réutiliser un groupe déjà en cours d'exécution, mais d'en créer un nouveau.

dispatch_group_wait() revient dès qu'il y a exactement zéro blocs en attente ou en cours d'exécution associés à un groupe (plus précisément, dès que chaque appel à dispatch_group_enter() a été équilibré par un appel à dispatch_group_leave()). Si un thread attend un groupe pendant qu'un autre thread soumet de nouveaux blocs au groupe, le nombre de blocs associés peut momentanément atteindre zéro avant que tous les blocs n'aient été soumis. Si cela se produit, dispatch_group_wait() reviendra trop tôt : certains blocs associés au groupe sont terminés, mais d'autres n'ont pas encore été soumis ou exécutés.

Cependant, à titre de cas particulier, un bloc associé à un groupe peut soumettre de nouveaux blocs associés à son propre groupe. Dans ce cas, le comportement est déterministe : un thread en attente ne se réveillera pas tant que les blocs nouvellement soumis n'auront pas également terminé.

Tout ce qui précède s'applique également à dispath_group_notify(), avec "bloc à soumettre" remplacé par "thread en attente".
