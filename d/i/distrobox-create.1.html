DESCRIPTIO

N

distrobox-create s'occupe de créer le conteneur avec le nom et l'image fournis. Le conteneur créé sera ét

roitement intégré à l'hôte, permettant le partage du répertoire HOME de l'utilisateur, du stockage extern
e, des périphériques USB externes et des applications graphiques (X11/Wayland), ainsi que de l'audio.

SYNOPSI

S

distrobox

create 
--image/-i:     image à utiliser pour le conteneur  par défaut: ${container_image_default}
--name/-n:      nom pour la distrobox          par défaut: ${container_name_default}
--hostname:     nom d'hôte pour la distrobox      par défaut: <container-name>.$(uname -n)
--pull/-p:      récupérer l'image même si elle existe localement (implique --yes)
--yes/-Y:       non-interactif, récupérer les images sans demander
--root/-r:      lancer podman/docker/lilipod avec les privilèges root. Notez que si vous avez besoin de root, c'est la méthode
            préférée plutôt que "sudo distrobox" (note: si l'utilisation d'un programme autre que 'sudo' pour les privilèges
root est nécessaire, spécifiez-le à travers la variable d'environnement DBX_SUDO_PROGRAM, ou la variable de configuration 'distrobox_sudo_program') --clone/-c: nom du conteneur distrobox à utiliser comme base pour un nouveau conteneur cela sera utile soit pour renommer une distrobox existante soit pour avoir plusieurs copies du même environnement. --home/-H: sélectionner un répertoire HOME personnalisé pour le conteneur. Utile pour éviter de polluer le répertoire home de l'hôte avec des fichiers temporaires. --volume: volumes supplémentaires à ajouter au conteneur --additional-flags/-a: drapeaux supplémenta
ires à passer à la commande du gestionnaire de conteneurs --additional-packages/-ap: paquets supplémentaires à installer lors de la configuration initiale du conteneur --init-hooks: commandes supplémentaires à exécuter à la fin de l'initialisation du conteneur --pre-init-hooks: commandes supplémentaires à exécuter au début de l'initialisation du conteneur --init/-I: utiliser le système d'init (comme systemd) à l'intérieur du conteneur. cela rendra les processus de l'hôte non visibles depuis l'intérieur du conteneur. (suppose --unshare-process) peut nécessiter des paquets supplémentaires selon l'image du conteneur: https://
github.com/89luca89/distrobox/blob/main/docs/useful_tips.md#using-init-system-inside-a-distrobox --nvidia: essayer d'intégrer les pilotes nVidia de l'hôte dans l'invité --platform: spécifier quelle plateforme utiliser, ex: linux/arm64 --unshare-devsys: ne pas partager les périphériques de l'hôte et les répertoires sysfs de l'hôte --unshare-groups: ne pas transférer les groupes supplémentaires de l'utilisateur vers le conteneur --unshare-ipc: ne pas partager l'espace de noms ipc avec l'hôte --unshare-netns: ne pas partager l'espace de noms réseau avec l'hôte --unshare-process: ne pas partager l'espace de nom
s des processus avec l'hôte --unshare-all: activer tous les drapeaux unshare ci-dessous --compatibility/-C: afficher la liste des images compatibles --help/-h: afficher ce message --no-entry: ne pas générer une entrée de conteneur dans la liste des applications --dry-run/-d: afficher uniquement la commande du gestionnaire de conteneurs générée --verbose/-v: afficher plus de verbosité --version/-V: afficher la version --absolutely-disable-root-password-i-am-really-positively-sure: ⚠️ ⚠️ lors de la configuration d'une distrobox avec privilèges root, cela sautera la configuration du mot de passe utilisateur, le laissant vide. ⚠️ ⚠️

L'option

--home vous permet de spécifier un HOME personnalisé pour le conteneur. Notez que cela n'empêchera PAS le montage du répertoire home de l'hôte, mais garantira que les configurations et les fichiers cachés ne le rempliront pas. L'option --root vous permet de créer un conteneur avec de véritables privilèges root.
