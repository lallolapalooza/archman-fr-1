RÉSUM

É

Digest::SHA est une implémentation complète du Secure Hash Standard du NIST. Il offre aux programmeurs Perl un

moyen pratique de calculer les digests de messages SHA-1, SHA-224, SHA-256, SHA-384, SHA-512, SHA-512/224 et SHA
-512/256. Le module peut traiter tous les types d'entrée, y compris les données partiellement sur un octet.

DESCRIPTIO

N

Digest::SHA est écrit en C pour la rapidité. Si votre plateforme ne dispose pas d'un compilateur C, vous pouvez installer le module fonctionnellement équivalent (mais beaucoup plus lent) Digest::SHA::

PurePerl.

L'interface de programmation est facile à utiliser : c'est la même que celle trouvée dans le module Digest de CPAN. Ainsi, si vos applications utilisent actuellement Digest::MD5 et que vous préférez la sécurité accrue de SHA, il suffit de les

convertir.

L'interface propose deux façons de calculer les digests : d'un seul coup, ou par étapes. Pour illustrer, le programme suivant calcule le digest SHA-256 de « hello world » en utilisant chaque approche

: 
use Digest::SHA qw(sha256_hex);
$data = "hello world";
@frags = split(//, $data);
# d'un seul coup (style fonctionnel)
$digest1 = sha256_hex($data);
# par étapes (style POO)
$state = Digest::SHA->new(256);
for (@frags) { $state->add($_) }
$digest2 = $state->hexdigest;
print $digest1 eq $digest2 ?
        "whew!\n" : "oops!
\n";

Pour calculer le digest d'un message de n bits où n n'est pas un multiple de 8, utilisez la méthode add_bits(). Par exemple, considérez le message de 446 bits composé de la chaîne de bits « 110 » répétée 148 fois, suivie de « 11 ». Voici comment afficher son digest SHA-1

: 
use Digest::SHA;
$bits = "110" x 148 . "11";
$sha = Digest::SHA->new(1)->add_bits($bits);
print $sha->hexdigest,
"\n";

Notez que pour les chaînes de bits plus longues, il est plus efficace d'utiliser la version à deux arguments add_bits($data, $nbits), où $data est dans le format binaire compact habituel utilisé pour les chaînes

Perl.

Le module vous permet également d'enregistrer des états SHA intermédiaires dans une chaîne. La méthode getstate() génère un texte lisible par l'humain et portable décrivant l'état actuel du calcul. Vous pouvez ensuite restaurer cet état avec putstate() pour reprendre le calcul là où il s'était

arrêté.

Pour voir à quoi ressemble une description d'état, exécutez simplement ce qui suit

: 
use Digest::SHA;
print Digest::SHA->new->add("Shaw" x 1962)->
getstate;

En plus de cela, le module Digest::SHA propose des routines pour calculer des hachages avec clé en utilisant les algorithmes HMAC-SHA-1/224/256/384/512. Ces services n'existent que sous forme fonctionnelle et imitent le style et le comportement des fonctions sha(), sha_hex()et sha_base64()

. 
# Vecteur de test de draft-ietf-ipsec-ciph-sha-256
-01.txt use Digest::SHA qw(hmac_sha256_hex); print
hmac_sha256_hex("Hi There", chr(0x0b) x 32), "\n";

UNICODE ET EFFETS

SECONDAIRES

Perl prend en charge les chaînes Unicode depuis la version 5.6. Ces chaînes peuvent contenir des caractères larges, c'est-à-dire des caractères dont les valeurs ordinales sont supérieures à 255. Cela peut poser des problèmes pour les algorithmes de digest tels que SHA qui sont spécifiés pour opérer sur des séquences

d'octets.

La règle par laquelle Digest::SHA traite une chaîne Unicode est facile à énoncer, mais potentiellement déroutante à comprendre : la chaîne est interprétée comme une séquence de valeurs d'octets, où chaque valeur d'octet est égale à la valeur ordinale (c'est-à-dire le point de code) du caractère Unicode correspondant. De cette façon, la chaîne Unicode 'abc' a exactement la même valeur de digest que la chaîne ordinaire

'abc'.

Comme un caractère large ne tient pas dans un octet, les routines de Digest::SHA émettent une erreur fatale si elles en rencontrent un. En revanche, si une chaîne Unicode ne contient pas de caractères larges, le module l'accepte volontiers. Le code suivant illustre les deux cas

: 
$str1 = pack('U*', (0..255));
print sha1_hex($str1);          # ok
$str2 = pack('U*', (0..256));
print sha1_hex($str2);          # erreur
fatale

Sachez que les routines de digest convertissent silencieusement l'entrée UTF-8 en sa séquence d'octets éq

uivalente dans l'encodage natif (cf. utf8::downgrade). Cet effet secondaire n'influence que la manière do
nt Perl stocke les données en interne, mais laisse par ailleurs la valeur réelle des données intacte.

DÉCLARATION DU NIST SUR

SHA-1

Le NIST reconnaît que les travaux du Prof. Xiaoyun Wang constituent une attaque de collision pratique sur SHA-1. Par conséquent, le NIST encourage l'adoption rapide des fonctions de hachage SHA-2 (par exemple SHA-256) pour les applications nécessitant une forte résistance aux collisions, telles que les signatures

numériques.

COMPLÉMENT DES DIGESTS

BASE64

Par convention, les modules Digest de CPAN ne complètent pas (pad) leur sortie Base64. Des problèmes peuvent survenir lorsque de tels digests sont fournis à d'autres logiciels qui s'attendent à des encodages Base64 correctement

complétés.

Pour l'instant, tout complément nécessaire doit être effectué par l'utilisateur. Heureusement, il s'agit d'une opération simple : si la longueur d'un digest encodé en Base64 n'est pas un multiple de 4, il suffit d'ajouter des caractères « = » à la fin du digest jusqu'à ce qu'elle le soit

: 
while (length($b64_digest) % 4) {
        $b64_digest .= '=';
}

Pour illustrer, sha256_base64("abc") est calculé comme

étant 
ungWv48Bz+pBQUDeXa4iI7ADYaOWF3qctBD/YfIAFa
0

qui a une longueur de 43. Ainsi, la version correctement complétée

est 
ungWv48Bz+pBQUDeXa4iI7ADYaOWF3qctBD/YfIAFa
0
=

Le mode « U » est inspiré du concept de « Universal Newlines » (retours à la ligne universels) de Python, où les terminateurs de ligne DOS et Mac OS sont convertis internement en retours à la ligne UNIX avant le traitement. Cela garantit des valeurs d'empreinte cohérentes lorsqu'on travaille simultanément sur plusieurs systèmes de fichiers. Le mode « U » n'influence que les fichiers texte, à savoir ceux qui passent le test -T de Perl ; les fichiers binaires sont traités sans aucune

traduction.

Le mode BITS (« 0 ») interprète le contenu de $filename comme un flux logique de bits, où chaque caractère ASCII '0' ou '1' représente respectivement un bit 0 ou 1. Tous les autres caractères sont ignorés.
