COMPATIBILITE

Ce projet ne nécessite pas d'image dédiée. Il peut utiliser toutes les images OCI provenant de docker-hub, quay.io, ou n'importe quel registre de votre choix.

De nombreuses images cloud sont intentionnellement allégées pour réduire la taille et peuvent ne pas inclure des commandes telles que which, mount, less ou vi). Des paquets supplémentaires peuvent être installés une fois à l'intérieur du conteneur. Nous recommandons d'utiliser votre outil d'automatisation préféré à l'intérieur du conteneur si vous vous retrouvez à devoir créer répétitivement de nouveaux conteneurs. La maintenance de votre propre image personnalisée est également une option.

La principale préoccupation est d'avoir les utilitaires Linux de base (mount), les utilitaires de gestion d'utilisateurs de base (usermod, passwd), et sudo correctement configurés.

GESTIONNAIRES DE CONTENEURS SUPPORTES

distrobox peut fonctionner avec podman, docker ou lilipod

Il dépend soit de podman configuré en mode rootless, soit de docker configuré sans sudo (suivez CES instructions)

•
Version minimale de podman : 2.1.0
•
Version minimale du client docker : 19.03.15
•
Version minimale de lilipod : v0.0.1

Suivez le guide d'installation officiel ici :

•
https://podman.io/getting-started/installation
•
https://docs.docker.com/engine/install
•
https://docs.docker.com/engine/install/linux-postinstall/

ANCIENNES

DISTRIBUTIONS

Pour les anciennes distributions comme CentOS 5, CentOS 6, Debian 6, Ubuntu 12.04, la compatibilité n'est pas

assurée.

Leur version de libc est incompatible avec les versions du noyau postérieures à >=4.11. Une solution de contournement consiste à utiliser l'option vsyscall=emulate dans le chargeur de démarrage de

l'hôte.

Gardez également à l'esprit que les miroirs peuvent être indisponibles pour d

e si anciennes versions, vous devrez donc construire une image distrobox
personnalisée pour vous assurer que les dépendances de base sont satisfaites.
