DESCRIPTIO

N

Les modules "Digest::" calculent des empreintes, aussi appelées "empreintes digitales" ou "hachages", de certaines données, appelées un message. L'empreinte est (généralement) une chaîne de taille fixe et petite. La taille réelle de l'empreinte dépend de l'algorithme utilisé. Le message est simplement une séquence d'octets ou de bits

arbitraires.

Une propriété importante des algorithmes d'empreinte est que l'empreinte est susceptible de changer si le message change d'une manière ou d'une autre. Une autre propriété est que les fonctions d'empreinte sont des fonctions à sens unique, c'est-à-dire qu'il devrait être difficile de trouver un message qui correspond à une empreinte donnée. Les algorithmes diffèrent dans la façon dont ils sont "susceptibles" et "difficiles", ainsi que dans leur efficacité de

calcul.

Notez que les propriétés des algorithmes changent avec le temps, à mesure que les algorithmes sont analysés et que les machines deviennent plus rapides. Si votre application, par exemple, dépend du fait qu'il est "impossible" de générer la même empreinte pour un message différent, il est judicieux de faciliter l'intégration d'algorithmes plus forts à mesure que ceux utilisés deviennent plus faibles. L'utilisation de l'interface documentée ici devrait faciliter le changement d'algorithme plus

tard.

Tous les modules "Digest::" fournissent la même interface de programmation. Une interface fonctionnelle pour une utilisation simple, ainsi qu'une interface orientée objet qui peut traiter des messages de longueur arbitraire et qui peut lire des fichiers

directement.

L'empreinte peut être livrée sous trois formats

:

L'interface fonctionnelle est simplement des fonctions importables portant le même nom que l'algorithme. Les fonctions prennent le message comme argument et retournent l'empreinte. Exemple

INTERFACE

OO

Les méthodes suivantes sont disponibles pour tous les modules "Digest::"

:
$ctx = Digest->XXX($arg,.
..)
$ctx = Digest->new(XXX => $arg,.
..)
$ctx = Digest::XXX->new($arg,.
..)
Le constructeur retourne un objet qui encapsule l'état de l'algorithme d'empreinte de message. Vous pouvez ajouter des données à l'objet et enfin demander l'empreinte. Le "XXX" devrait bien sûr être remplacé par le nom approprié de l'algorithme d'empreinte que vous voulez utiliser.

Les deux premières formes sont simplement du sucre syntaxique qui charge automatiquement le bon module à la première utilisation. La deuxième forme vous permet d'utiliser des noms d'algorithmes qui contiennent des lettres qui ne sont pas des identifiants perl légaux, par exemple "SHA-1". Si aucune implémentation pour l'algorithme donné ne peut être trouvée, alors une exception est

levée.

Pour savoir quels arguments (le cas échéant) le constructeur prend (le "$args,..." ci-dessus), consultez la documentation de l'implémentation d'empreinte

spécifique.

Si new() est appelée comme méthode d'instance (c'est-à-dire $ctx->new), elle réinitialisera simplement l'état de l'objet à l'état d'un objet nouvellement créé. Aucun nouvel objet n'est créé dans ce cas, et la valeur de retour est la référence à l'objet (c'est-à-dire $ct

La méthode add_bits() est une alternative à add() qui permet d'ajouter des octets partiels au message. La plupart des utilisateurs peuvent simplement ignorer cette méthode car les applications typiques n'impliquent que des données d'octets entiers.

La forme à deux arguments de add_bits() ajoutera les premiers $nbits bits de $data. Pour le dernier octet potentiellement partiel, seuls les bits de poids fort "$nbits % 8" sont utilisés. Si $nbits est supérieur à "length($data) * 8", alors cette méthode ferait la même chose que "$ctx->add($d
