NOM

dirmngr-client - Outil pour accéder aux services de Dirmngr

SYNTAXE

dirmngr-client [options] [certificat|motif]

DESCRIPTION

dirmngr-client est un outil simple pour contacter un dirmngr en cours d'exécution et vérifier si un certificat a été révoqué — soit en étant listé dans la CRL correspondante, soit en utilisant le protocole OCSP. Si aucun dirmngr n'est en cours d'exécution, une nouvelle instance sera démarrée, mais ce n'est généralement pas une bonne idée en raison de la lourde surcharge de performance.

La manière habituelle d'utiliser cet outil est soit :

dirmngr-client un_certificat

ou

dirmngr-client <un_certificat

Où un_certificat est un certificat X.509 codé en DER (binaire) à tester.

VALEUR DE RETOUR

dirmngr-client renvoie ces valeurs :

0
Le certificat en question est valide ; c'est-à-dire qu'une CRL valide est disponible et qu'il n'y est pas listé, ou que la requête OCSP a indiqué que le certificat est valide.
1
Le certificat a été révoqué.
2 (et autres valeurs)
Il y a eu un problème lors de la vérification de l'état de révocation du certificat. Un message vers stderr a donné des informations plus détaillées. Il s'agit très probablement d'un problème de CRL manquante ou expirée, ou d'un problème réseau.

OPTIONS

dirmngr-client peut être appelé avec les options suivantes :

--version
Affiche la version du programme et les informations de licence. Notez que vous ne pouvez pas abréger cette commande.
--help, -h
Affiche un message d'utilisation résumant les options de ligne de commande les plus utiles. Notez que vous ne pouvez pas abréger cette commande.
--quiet, -q
Rend la sortie extra-brève en supprimant les messages d'information.
-v
--verbose
Affiche des informations supplémentaires pendant l'exécution. Vous pouvez augmenter la verbosité en donnant plusieurs commandes verbose à dirmngr, telles que ‘-vv’.
--pem
Suppose que le certificat donné est au format PEM (blindé).
--ocsp
Effectue la vérification en utilisant le protocole OCSP et ignore toutes les CRL.
--force-default-responder
Lors de la vérification à l'aide du protocole OCSP, force l'utilisation du répondeur OCSP par défaut. C'est-à-dire de ne pas utiliser le répondeur tel que donné par le certificat.
--ping
Vérifie si le démon dirmngr est en cours d'exécution.
--cache-cert
Place le certificat donné dans le cache d'un dirmngr en cours d'exécution. Ceci est principalement utile pour le débogage.
--validate
Valide le certificat donné en utilisant le code de validation interne de dirmngr. Ceci est principalement utile pour le débogage.
--load-crl
Cette commande attend une liste de noms de fichiers contenant des fichiers CRL codés en DER. Avec l'option --url, des URL sont attendues à la place des noms de fichiers et elles sont chargées directement depuis l'emplacement donné. Toutes les CRL seront validées puis chargées dans le cache de dirmngr.
--lookup
Prend les arguments restants et exécute une commande de recherche sur chacun d'eux. Les résultats sont des sorties encodées en Base-64 (sans les lignes d'en-tête). Ceci peut être utilisé pour récupérer des certificats depuis un serveur. Cependant, le format de sortie n'est pas très adapté si plus d'un certificat est retourné.
--url
-u
Modifie les commandes lookup et load-crl pour accepter une URL.
--local
-l
Indique à la commande lookup de ne rechercher que dans le cache local.
--squid-mode
Exécute dirmngr-client dans un mode adapté comme programme d'aide pour l'option external_acl_type de Squid.
