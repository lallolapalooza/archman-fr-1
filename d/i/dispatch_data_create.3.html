DESCRIPTIO

N

Les objets de données de dispatch sont des conteneurs opaques de octets qui représentent une ou plusieurs régions de mémoire. Ils sont créés soit à partir de tampons de mémoire gérés par l'application ou par le système, soit à p

artir d'autres objets de données de dispatch. Les objets de données de dispatch sont immuables et les régions de mémoire qu'ils représentent doivent rester inchangées pendant toute la durée de vie de tous les objets de données qu
i les référencent. Les objets de données de dispatch évitent autant que possible la copie de la mémoire représentée. Plusieurs objets de données peuvent représenter les mêmes régions de mémoire ou des sous-sections de celles-ci.

CRÉATIO

N

La fonction dispatch_data_create() crée un nouvel objet de données de dispatch de la taille donnée à partir d'un tampon. Le bloc destructeur fourni sera soumis à la file d'attente spécifiée lorsque l'objet atteint la fin de son cycle de vie, indiquant que le système ne référence plus le tampon. Cela permet à l'application de désallouer le stockage associé. L'argument queue est ignoré si l'un des destructeurs prédéfinis suivants est passé

:

REE

La fonction dispatch_data_create_subrange() crée un nouvel objet de données représentant la sous-région de l'objet de données fourni spécifiée par les paramètres offset et length

La fonction dispatch_data_create_map() crée un nouvel objet de données en associant la mémoire représentée par l' objet de données fourni en une seule région de mémoire contiguë (en déplaçant ou copiant la mémoire si nécessaire). Si les références buffer_ptr et size_ptr ne sont pas NULL, elles sont remplies avec l'emplacement et l'étendue de la région contiguë, permettant un accès en lecture dire

ACCÈ

La fonction dispatch_data_apply() fournit un accès en lecture à la mémoire représentée sans nécessiter qu'elle soit mappée en une seule région contiguë. Elle parcourt les régions de mémoire représentées par l'argument data dans l'ordre logique, invoque le bloc applier spécifié pour chaque région et renvoie un booléen indiquant si le parcours s'est terminé avec succès. Le bloc applier reçoit les arguments suivants pour chaque région de mémoire et renvoie un booléen indiquant si le parcours doit continuer

OBJET DE DONNÉES

VIDE

L'objet dispatch_data_empty est l'objet singleton global représentant une région de mémoire de longueur zéro. C'est un

e entrée valide pour toutes les fonctions dispatch_d
ata qui prennent des objets de données en paramètres.

MODÈLE DE

MÉMOIRE

Les objets de données de dispatch sont retenus et libérés via des appels à dispatch_retain() et dispatch_release(). Les objets de données passés en arguments à une fonction de données de dispatch create ou copy peuvent être libérés lorsque la fonction se termine. L'objet nouvellement créé détient des références implicites à ses régions de mémoire constituantes selon les besoins.

Les fonctions dispatch_data_create_map() et dispatch_data_apply() retournent un pointeur interne vers la mémoire représentée qui n'est valide que tant qu'un objet associé n'a pas été libéré. Lorsque le comptage de références automatique Objective-C est activé, il faut faire attention si cet objet est conservé dans une variable à stockage automatique. Il peut être nécessaire de l'annoter avec l'attribut objc_precise_lifetime, ou de le stocker dans une variable d'instance __strong à la place, pour s'assurer que l'objet n'est pas libéré

prématurément avant que les accès mémoire
via le pointeur interne soient terminés.
