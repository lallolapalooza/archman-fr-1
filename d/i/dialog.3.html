DIALOG() Appels de bibliothèque DIALOG()

NOM

dialog - widgets et utilitaires pour le programme dialog

SYNTAXE

cc [ flag ... ] fichier ... -ldialog [ bibliothèque ... ]
   ou
cc $(dialog-config --cflags) fichier ... $(dialog-config --libs) ]

#include <dialog.h>

Dialog est un programme qui permet de présenter une variété de questions ou d'afficher des messages à l'aide de boîtes de dialogue depuis un script shell. Il est construit à partir de la bibliothèque dialog, qui se compose de plusieurs widgets ainsi que de fonctions utilitaires utilisées par les widgets ou le programme principal.

DESCRIPTION

Cette page de manuel documente les fonctionnalités de <dialog.h> qui sont susceptibles d'être importantes pour les développeurs utilisant directement les widgets. Quelques indications sont également données pour le développement de nouveaux widgets.

Voici une version dialog de Hello World :

int main(void)
{
	int status;
	init_dialog(stdin, stdout);
	status = dialog_yesno(
			"Bonjour, en format dialog",
			"Bonjour le monde !",
			0, 0);
	end_dialog();
	return status;
}

DÉFINITIONS

Les codes de sortie (renvoyés au programme principal pour son utilisation) sont définis avec un préfixe "DLG_EXIT_". Les constantes définies peuvent être mappées à l'aide de variables d'environnement comme décrit dans dialog(1), par exemple, DLG_EXIT_OK correspond à $DIALOG_OK.

Les constantes de caractères utiles qui correspondent à l'entrée utilisateur sont nommées avec le préfixe "CHR_", par exemple, CHR_BACKSPACE.

Les couleurs et les attributs vidéo sont catégorisés et associés aux réglages du fichier de configuration (voir la discussion sur $DIALOGRC dans dialog(1)). La macro DIALOG_ATR(n) est utilisée pour définir les références à la table combinée de couleurs et d'attributs dlg_color_table[].

L'application dialog transmet ses paramètres de ligne de commande aux fonctions de widget. Certains de ces paramètres sont des valeurs uniques, mais certains widgets acceptent des données sous forme de tableau de valeurs. Il s'agit notamment des listes de contrôle/boîtes radio, des boîtes de menu et des boîtes de formulaire. Lorsque l'option --item-help est donnée, une colonne de données supplémentaire est attendue. Les macros USE_ITEM_HELP(), CHECKBOX_TAGS, MENUBOX_TAGS et FORMBOX_TAGS sont utilisées pour masquer cette différence par rapport à l'application appelante.

La plupart des autres définitions trouvées dans <dialog.h> sont utilisées par commodité pour construire la bibliothèque ou le programme principal. Celles-ci incluent des définitions basées sur l'en-tête généré <dlg_config.h>.

STRUCTURES DE DONNÉES

Toutes les données globales de la bibliothèque dialog sont stockées dans quelques structures : DIALOG_STATE, DIALOG_VARS et DIALOG_COLORS. Les variables globales correspondantes dialog_state, dialog_vars et dlg_color_table doivent être initialisées à zéro, puis remplies avec les données à utiliser. Quelques-unes de ces variables doivent être non nulles pour que les widgets correspondants fonctionnent. Comme pour les noms de fonctions, les variables commençant par "dialog_" sont destinées à être utilisées par l'application appelante, tandis que les variables commençant par "dlg_" sont prévues pour les niveaux inférieurs, par exemple, par la bibliothèque dialog.

DIALOG_STATE

Les variables d'état sont les variables de travail de dialog. Il les initialise, les utilise pour gérer les widgets.

.toutes_les_sous-fenetres

Ceci est une liste chaînée de toutes les sous-fenêtres créées par la bibliothèque. La fonction dlg_del_window l'utilise pour libérer le stockage des sous-fenêtres lors de la suppression d'une fenêtre.

.toutes_les_fenetres

Ceci est une liste chaînée de toutes les fenêtres créées par la bibliothèque. La fonction dlg_del_window l'utilise pour localiser les fenêtres qui peuvent être redessinées après la suppression d'une fenêtre.

.ratio_d_aspect

Ceci correspond à l'option de ligne de commande "--aspect-ratio". La valeur donne à l'application un certain contrôle sur les dimensions de la boîte lors de l'utilisation du dimensionnement automatique (spécifiant 0 pour la hauteur et la largeur). Elle représente largeur / hauteur. La valeur par défaut est 9, ce qui signifie 9 caractères de large pour chaque ligne de hauteur.

.chaine_fin

Lorsqu'elle est définie sur vrai, cela permet aux appels à dlg_finish_string de supprimer les données correspondantes qui sont créées pour accélérer les calculs de mise en page pour la chaîne de paramètres donnée. Le widget gauge utilise cette fonctionnalité.

.callbacks_getc

Ceci est configuré dans ui_getc.c pour enregistrer les fenêtres qui doivent être interrogées pour obtenir des entrées, par exemple, pour gérer le widget de boîte de queue en arrière-plan. Une fenêtre est désignée comme fenêtre de premier plan ou de contrôle.

.redirection_getc

Si la fenêtre de contrôle pour DIALOG_STATE.getc_callbacks est fermée, la liste est transférée à cette variable. La fermeture de toutes les fenêtres entraîne la sortie de l'application.

.redimensionnement_effectué

Ceci est défini à TRUE dans dlg_will_resize ou dlg_result_key lorsque KEY_RESIZE est lu, pour indiquer à dialog d'ignorer les ERR ultérieurs.

.pas_de_souris

Ceci correspond à l'option de ligne de commande "--no-mouse". Si vrai, dialog n'initialisera pas (et n'activera pas) la souris dans init_dialog.

.sortie

Ceci est défini dans l'application dialog pour le flux sur lequel les fonctions de l'application et de la bibliothèque peuvent écrire les résultats textuels. Normalement, il s'agit de la sortie d'erreur standard, car la bibliothèque curses préfère écrire ses données sur la sortie standard. Certains scripts, privilégiant la commodité à la portabilité, préfèrent écrire les résultats sur la sortie standard, par exemple, en utilisant l'option "--stdout".

.compteur_sortie

Ceci est incrémenté par dlg_does_output, qui est appelé par chaque widget qui écrit du texte sur la sortie. L'application dialog l'utilise pour décider si elle doit également écrire un séparateur, c'est-à-dire DIALOG_STATE.separate_str, entre les appels à chaque widget.

.entree_pipe

Ceci est défini dans init_dialog pour un flux qui peut être utilisé par le widget gauge, qui doit être l'entrée standard de l'application. L'application dialog appelle normalement init_dialog avec input défini sur l'entrée standard, mais éventuellement basé sur l'option "--input-fd". Étant donné que l'application ne peut pas lire à partir d'un tuyau (entrée standard) tout en lisant l'entrée curses depuis l'entrée standard, elle doit permettre de rouvrir cette dernière à partir d'un descripteur de fichier spécifique, ou directement depuis le terminal. La valeur ajustée du flux du tuyau est stockée dans cette variable.

.hauteur_ecran

Les fonctions de formatage de texte l'utilisent pour le nombre de lignes utilisées pour formater une chaîne.

Elle est utilisée par dialog pour les options de ligne de commande "--print-text-size" et "--print-text-only".

.ecran_initialise

Ceci est défini dans init_dialog et réinitialisé dans end_dialog. Il est utilisé pour vérifier si curses a été initialisé et si la fonction endwin doit être appelée à la sortie.

.dlg_clear_screen

Cela correspond à l'option de ligne de commande "--clear". Cette option est implémentée dans le programme principal, pas dans la bibliothèque. Si elle est vraie, l'écran sera effacé à la sortie. Cela peut être utilisé seul, sans autres options.

.erase_on_exit

Cela correspond à l'option de ligne de commande "--erase-on-exit". Si elle est vraie, supprime le widget de dialogue à la sortie du programme, effaçant tout l'écran jusqu'à sa couleur d'arrière-plan native, et place le curseur du terminal dans le coin inférieur gauche de l'écran.

Cela est utile pour rendre le contenu de la fenêtre invisible à la fin d'une série de boîtes de dialogue. Cela peut aussi être utilisé à des étapes antérieures d'une série d'invocations de dialog, si la série peut être interrompue avant d'être entièrement terminée.

.exit_label

Cela correspond à l'option de ligne de commande "--exit-label string". La chaîne donnée remplace l'étiquette utilisée pour les boutons « EXIT ».

.extra_button

Cela correspond à l'option de ligne de commande "--extra-button". Si elle est vraie, certains widgets affichent un bouton supplémentaire, entre les boutons « OK » et « Cancel », ou « Yes » et « No ».

.extra_label

Cela correspond à l'option de ligne de commande "--extra-label string". La chaîne donnée remplace l'étiquette utilisée pour les boutons « Extra ». Note : pour les widgets inputmenu, la valeur par défaut est « Rename ».

.formitem_type

Cela est défini par l'option de ligne de commande "--passwordform" pour indiquer au widget formulaire que ses champs de texte doivent être traités comme des widgets de mot de passe.

.help_button

Cela correspond à l'option de ligne de commande "--help-button". Si elle est vraie, certains widgets affichent un bouton d'aide après les boutons « OK » et « Cancel », c'est-à-dire dans les boîtes checklist, radiolist et menu, ou les boutons « Yes » et « No » pour la boîte yesno .

Si --item-help est également donné, à la sortie le statut de retour sera le même que pour le bouton « OK », et le texte d'aide de l'élément sera écrit dans la dialogsortie après le jeton « HELP ». Sinon, le statut de retour indiquera que le bouton Help a été pressé, et aucun message ne sera affiché.

.help_file

Cela correspond à l'option de ligne de commande "--hfile string". Le nom de fichier donné est passé à dialog_helpfile lorsque l'utilisateur appuie sur F1.

.help_label

Cela correspond à l'option de ligne de commande "--help-label string". La chaîne donnée remplace l'étiquette utilisée pour les boutons « Help ».

.help_line

Cela correspond à l'option de ligne de commande "--hline string". La chaîne donnée est affichée en bas des fenêtres de dialogue, comme un sous-titre.

.help_status

Cela correspond à l'option de ligne de commande "--help-status". Si elle est vraie, et que le bouton d'aide est sélectionné, écrit les informations de checklist ou de radiolist après les informations d'aide de l'élément « HELP ». Cela peut être utilisé pour reconstruire l'état d'une checklist après le traitement de la demande d'aide.

.help_tags

Cela correspond à l'option de ligne de commande "--help-tags". Si elle est vraie, dlg_add_help_formitem et dlg_add_help_listitem utilisent la valeur de la balise de l'élément de manière cohérente plutôt que d'utiliser la valeur du texte d'aide de la balise lorsque DIALOG_VARS.item_help est défini.

.input_length

Cela est non nul si DIALOG_VARS.input_result est alloué, par opposition à être un pointeur vers les variables locales de l'utilisateur.

.input_menu

Ce drapeau est défini pour indiquer si le widget menubox implémente un menu par opposition à un widget inputmenu.

.input_result

Cela peut être soit un tampon fourni par l'utilisateur, soit un tampon alloué dynamiquement par la bibliothèque, selon DIALOG_VARS.input_length:

  • Si DIALOG_VARS.input_length est zéro, c'est un pointeur vers le tampon de l'utilisateur (sur la pile, ou statique). La taille du tampon est supposée être MAX_LEN, qui est défini dans <dialog.h>.
  • Quand DIALOG_VARS.input_length est non nul, c'est un tampon alloué dynamiquement utilisé par les widgets pour renvoyer des résultats imprimables à l'application appelante.

Certains widgets copient un résultat dans ce tampon. Si le pointeur est NULL, ou si la longueur est insuffisante pour le résultat, alors la bibliothèque dialog alloue un tampon suffisamment grand, et définit DIALOG_VARS.input_length. Les appelants devraient vérifier ce cas s'ils ont fourni leur propre tampon.

.insecure

Cela correspond à l'option de ligne de commande "--insecure". Si elle est vraie, rend le widget de mot de passe plus convivial mais moins sécurisé, en affichant des astérisques pour chaque caractère.

.in_helpfile

Cette variable est utilisée pour empêcher dialog_helpfile d'afficher quoi que ce soit, par exemple, si F1 était pressé dans l'affichage d'un fichier d'aide.

.iso_week

Cela correspond à l'option de ligne de commande "--iso-week". Elle est utilisée dans le widget calendrier pour indiquer comment calculer la semaine de début de l'année :

  • par défaut, le calendrier considère le 1er janvier comme la première semaine de l'année.
  • Si cette variable est vraie, le calendrier utilise la convention de l'ISO 8601. L'ISO 8601 numérote les semaines à partir de la première semaine de janvier contenant un jeudi de l'année en cours. Le 1er janvier peut être dans l' année précédente .

.item_help

Cela correspond à l'option de ligne de commande "--item-help". Si elle est vraie, interprète les données de balises pour les boîtes checklist, radiolist et menu en ajoutant une colonne dont le texte est affiché dans la ligne inférieure de l'écran, pour l'élément actuellement sélectionné.

.keep_tite

Cela est défini par l'option de ligne de commande "--keep-tite" pour indiquer à dialog de ne pas tenter d'annuler les séquences d'initialisation du terminal (termcap ti/te) qui correspondent au basculement d'écran alternatif de xterm. Normalement dialog fait cela pour éviter le scintillement lorsqu'il est exécuté plusieurs fois dans un script.

.keep_window

Cela correspond à l'option de ligne de commande "--keep-window". Si elle est vraie, ne pas supprimer/redessiner la fenêtre à la sortie. Cela est utile pour garder le contenu de la fenêtre visible lorsque plusieurs widgets sont exécutés dans le même processus. Notez que curses effacera l'écran lors du démarrage d'un nouveau processus.

.last_key

Cela correspond à l'option de ligne de commande "--last-key".

.max_input

Cela correspond à l'option de ligne de commande "--max-input size". Limite les chaînes d'entrée à la taille donnée. Si non spécifié, la limite est de 2048.

.no_hot_key

Cela correspond à l'option de ligne de commande "--no-hot-list".

Certains widgets (buildlist, checklist, inputmenu, menu, radiolist, treeview) affichent une liste pour laquelle la lettre majuscule initiale de chaque entrée est acceptée comme touche de raccourci, pour déplacer rapidement le focus vers cette entrée.

Définir cette variable à TRUE désactive cette fonctionnalité.

.no_items

Cela correspond à l'option de ligne de commande "--no-items". Certains widgets (checklist, inputmenu, radiolist, menu) affichent une liste avec deux colonnes (une « tag » et un « item », c'est-à-dire une « description »). Cela indique à dialog de lire des lignes plus courtes à partir des données, en omettant le « list ».

.no_label

Cela correspond à l'option de ligne de commande "--no-label string". La chaîne donnée remplace l'étiquette utilisée pour les boutons « No ».

.no_lines

Cela correspond à l'option de ligne de commande "--no-lines. Cela supprime le dessin des lignes. Voir DIALOG_VARS.ascii_lines.

.no_nl_expand

Cela correspond à l'option de ligne de commande "--no-nl-expand". Si elle est fausse, dlg_trim_string convertit les sous-chaînes littérales "\n" dans un message en sauts de ligne.

.no_tags

Cela correspond à l'option de ligne de commande

--no-tags

Certains widgets (checklist, inputmenu, radiolist, menu) affichent une liste à deux colonnes (une « étiquette » et un « élément », également connu sous le nom de « description »). L'étiquette est utile pour le scripting, mais peut ne pas aider l'utilisateur. L'option --no-tags (de Xdialog) peut être utilisée pour supprimer la colonne des étiquettes de l'affichage.

Normalement, dialog vous permet de vous déplacer rapidement vers des entrées dans la liste affichée, en faisant correspondre un seul caractère au premier caractère de l'étiquette. Lorsque l'option --no-tags est donnée, dialog correspond au premier caractère de la description. Dans les deux cas, le caractère correspondant est mis en surbrillance.

--no-cancel

Ceci correspond à l'option en ligne de commande "--no-cancel". Si vrai, supprime le bouton « Annuler » dans les modes checklist, inputbox et menu. Un script peut toujours tester si l'utilisateur a appuyé sur la touche ESC pour annuler et quitter.

--no-collapse

Ceci correspond à l'option en ligne de commande "--no-collapse". Normalement, dialog convertit les tabulations en espaces et réduit les espaces multiples à un seul espace pour le texte affiché dans les boîtes de messages, etc. Si vrai, cette fonctionnalité est désactivée. Notez que dialog conservera le retour à la ligne du texte, sous réserve de l'option --cr-wrap.

--no-ok

Ceci correspond à l'option en ligne de commande "--no-ok. Dialog supprimera le bouton « ok » (ou « oui ») du widget.

--ok-label

Ceci correspond à l'option en ligne de commande "--ok-label chaîne". La chaîne donnée remplace l'étiquette utilisée pour les boutons « OK ».

pause_secs

Lorsqu'il est défini, force dlg_set_timeout à utiliser 10 millisecondes au lieu d'utiliser la valeur DIALOG_VARS.timeout_secs.

--print-size

Ceci correspond à l'option en ligne de commande "--print-size". Si vrai, chaque widget imprime sa taille dans la sortie de dialog lorsqu'il est invoqué.

--quoted

Ceci correspond à l'option en ligne de commande "--quoted. Normalement, dialog met entre guillemets les chaînes renvoyées par checklist ainsi que le texte d'aide des éléments. Si vrai, dialog mettra toutes les chaînes de résultats entre guillemets.

--reorder

Ceci correspond à l'option en ligne de commande "--reorder. Par défaut, le widget buildlist utilise le même ordre pour la liste de sortie (droite) que pour l'entrée (gauche). Si vrai, dialog utilisera l'ordre dans lequel un utilisateur ajoute des sélections à la liste de sortie.

--separate-output

Ceci correspond à l'option en ligne de commande "--separate-output". Si vrai, les widgets checklist renvoient le résultat une ligne à la fois, sans guillemets. Cela facilite l'analyse par un autre programme.

--single-quoted

Ceci correspond à l'option en ligne de commande "--single-quoted". Si vrai, utilise des apostrophes si nécessaire (et pas de guillemets si non nécessaire) pour la sortie des checklists ainsi que le texte d'aide des éléments. Si cette option n'est pas définie, dialog utilise des guillemets doubles autour de chaque élément. Ce dernier nécessite l'utilisation occasionnelle d'antislashs pour rendre la sortie utile dans les scripts shell.

--size-err

Ceci correspond à l'option en ligne de commande "--size-err". Si vrai, vérifie la taille résultante d'une boîte de dialogue avant d'essayer de l'utiliser, en imprimant la taille résultante si elle est plus grande que l'écran. (Cette option est obsolète, car tous les appels de nouvelle fenêtre sont vérifiés).

--sleep

Ceci correspond à l'option en ligne de commande "--sleep secondes". Cette option est implémentée dans le programme principal, pas dans la bibliothèque. Si non nul, c'est le nombre de secondes de délai après le traitement d'une boîte de dialogue.

--tab-correct

Ceci correspond à l'option en ligne de commande "--tab-correct". Si vrai, convertit chaque caractère de tabulation du texte en un ou plusieurs espaces. Sinon, les tabulations sont rendues selon l'interprétation de la bibliothèque curses.

--time-format

Ceci correspond à l'option en ligne de commande "--time-format chaîne". Si l'hôte fournit strftime, et que la valeur est non nulle, le widget timebox l'utilise pour formater sa sortie.

--timeout

Ceci correspond à l'option en ligne de commande "--timeout secondes". Si non nul, expire les requêtes d'entrée (sort avec un code d'erreur) si aucune réponse de l'utilisateur n'est donnée dans le nombre de secondes spécifié.

--title

Ceci correspond à l'option en ligne de commande "--title titre". Spécifie une chaîne de titre à afficher en haut de la boîte de dialogue.

--trim

Ceci correspond à l'option en ligne de commande "--trim". Si vrai, élimine les blancs de début, coupe les sauts de ligne littéraux et les espaces répétés du texte du message.

--week-start

Ceci correspond à l'option en ligne de commande "--week-start". Il est utilisé dans le widget calendrier pour définir le jour de départ de la semaine. La valeur de la chaîne peut être

  • un nombre (0 à 6, du dimanche au samedi selon POSIX) ou
  • la valeur spéciale « locale » (cela fonctionne avec les systèmes utilisant glibc, en fournissant une extension à la locale de la commande, la valeur first_weekday ).
  • une chaîne correspondant à l'une des abréviations des jours de la semaine affichées dans le widget calendrier, par exemple « Mo » pour

« Monday » (lundi).

dlg_trim_string

Le dialog programme utilise ceci dans chaque widget pour ajuster la chaîne de message, qui peut contenir le caractère de saut de ligne (appelé '\n') et/ou la sous-chaîne spéciale "\n" (qui peut être traduite en un caractère de saut de ligne).

Il existe plusieurs fonctionnalités optionnelles :

  • Sauf si dialog_vars.nocollapse est défini, chaque tabulation est convertie en un espace avant tout autre traitement.
  • Si dialog_vars.no_nl_expand n'est pas défini, et que la chaîne contient des sous-chaînes "\n" :
•
La fonction remplace les sous-chaînes "\n" intégrées par des caractères '\n' .
La fonction préserve les espaces supplémentaires après ces substitutions. Par exemple, les espaces suivant un saut de ligne (sous-chaîne ou caractère) sont préservés pour servir d'indentation.
•
Si dialog_vars.cr_wrap est défini, la fonction préserve les caractères de saut de ligne '\n' . Sinon, chaque caractère de saut de ligne '\n' est converti en un espace.
•
Sinon, si dialog_vars.trim_whitespace est défini :
  • Cette fonction supprime tous les espaces supplémentaires pour simplifier la justification.
  • Si dialog_vars.cr_wrap est défini, la fonction préserve les caractères de saut de ligne '\n' . Sinon, chaque caractère de saut de ligne '\n' est converti en un espace.
•
Enfin (si dialog_vars.no_nl_expand est défini, ou que la chaîne ne contient pas de sous-chaînes "\n", et que dialog_vars.trim_whitespace n'est pas défini) :
•
Sauf si dialog_vars.nocollapse est défini, les séquences d'espaces sont réduites à un seul espace.
