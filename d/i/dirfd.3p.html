DIRFD(3P) Manuel du programmeur POSIX DIRFD(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

dirfd — extraire le descripteur de fichier utilisé par un flux DIR

SYNTAXE

#include <dirent.h>
int dirfd(DIR *dirp);

DESCRIPTION

La fonction dirfd() doit retourner un descripteur de fichier faisant référence au même répertoire que l'argument dirp. Ce descripteur de fichier doit être fermé par un appel à closedir(). Si une tentative est faite pour fermer le descripteur de fichier, ou pour modifier l'état de la description associée, autrement que par closedir(), readdir(), readdir_r(), rewinddir() ou seekdir(), le comportement est indéfini.

VALEUR RETOURNÉE

En cas de succès, la fonction dirfd() doit retourner un entier contenant un descripteur de fichier pour le flux pointé par dirp. Sinon, elle doit retourner -1 et définir errno pour indiquer l'erreur.

ERREURS

La fonction dirfd() peut échouer si :

EINVAL
L'argument dirp ne fait pas référence à un flux de répertoire valide.

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

UTILISATION PAR L'APPLICATION

La fonction dirfd() est destinée à être un mécanisme par lequel une application peut obtenir un descripteur de fichier à utiliser pour la fonction fchdir().

RATIONNEL

Cette interface a été introduite car le volume Bases de définitions de POSIX.1‐2017 ne rend pas publique la structure de données DIR. Les applications ont tendance à utiliser la fonction fchdir() sur le descripteur de fichier retourné par cette interface, et cela s'est avéré utile pour des raisons de sécurité ; en particulier, c'est une meilleure technique que d'autres où les noms de répertoires peuvent changer.

La description utilise le terme « un descripteur de fichier » plutôt que « le descripteur de fichier ». L'implication voulue est qu'une implémentation qui n'utilise pas un fd pour opendir() pourrait toujours open() le répertoire pour implémenter la fonction dirfd(). Un tel descripteur doit être fermé plus tard lors d'un appel à closedir().

S'il est nécessaire d'allouer un fd à retourner par dirfd(), cela doit être fait au moment d'un appel à opendir().

ORIENTATIONS FUTURES

Aucune.

VOIR AUSSI

closedir(), fchdir(), fdopendir(), fileno(), open(), readdir()
