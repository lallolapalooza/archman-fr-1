NOM

disorderfs - Système de fichiers FUSE introduisant du non-déterminisme

SYNTAXE

disorderfs [OPTIONS...] ROOTDIR MOUNTPOINT

DESCRIPTION

disorderfs est un système de fichiers FUSE en superposition qui introduit du non-déterminisme dans les métadonnées du système de fichiers. Par exemple, il peut randomiser l'ordre dans lequel les entrées de répertoire sont lues. Ceci est utile pour détecter du non-déterminisme dans le processus de construction.

ROOTDIR est le chemin vers le répertoire sous-jacent qui doit être mis en miroir, et MOUNTPOINT est l'endroit où la superposition doit être montée.

OPTIONS

Voir fusermount(1), mount.fuse(8) et mount(8) pour une liste complète d'options.

Options spécifiques à disorderfs :

--multi-user=yes|no

Indique si d'autres utilisateurs peuvent accéder au montage de superposition (défaut : non). Lorsque cette option est activée, disorderfs accède au fichier sous-jacent avec les mêmes identifiants (ID utilisateur, ID groupe, liste de groupes supplémentaires) que le processus accédant au fichier superposé. Ceci est différent de l'option allow_other de FUSE, qui permet à d'autres utilisateurs d'accéder, mais fait que disorderfs accède au système de fichiers sous-jacent avec les identifiants de l'utilisateur exécutant disorderfs, ce qui est généralement indésirable.

--multi-user=yes nécessite que disorderfs soit exécuté en tant que root.

--shuffle-dirents=yes|no

Indique s'il faut mélanger aléatoirement les entrées de répertoire (défaut : non). Les entrées de répertoire sont mélangées à chaque lecture du répertoire, de sorte que les lectures répétées du même répertoire renverront probablement des résultats différents.

--reverse-dirents=yes|no

Indique s'il faut renvoyer les entrées de répertoire dans l'ordre inverse (défaut : oui).

--sort-dirents=yes|no

Indique s'il faut renvoyer les entrées de répertoire dans l'ordre trié (défaut : non).

Notez que vous devez explicitement outrepasser la valeur par défaut --reverse-dirents=no pour obtenir les résultats dans l'ordre attendu.

--pad-blocks=N

Ajoute N au champ st_blocks dans struct stat(2) (défaut : 1).

--share-locks=yes|no

Indique si les verrous doivent être partagés entre disorderfs et le système de fichiers sous-jacent (défaut : non). Lorsque cette option est activée, les verrous créés sur le système de fichiers sous-jacent sont visibles dans disorderfs, et vice versa. Lorsque cette option est désactivée, les verrous fonctionnent toujours dans disorderfs, mais si un processus accède directement au système de fichiers sous-jacent, et qu'un autre processus accède via disorderfs, ils ne verront pas les verrous des autres.

Le partage de verrous est actuellement bogué, il est donc désactivé par défaut.

--help, -h

Affiche l'aide.

--version, -V

Affiche la version.

BOGUES

--share-locks=yes est actuellement bogué : les programmes peuvent signaler qu'un fichier est verrouillé alors qu'il ne l'est pas réellement.

EXEMPLE

Si vous essayez de tester un problème de Builds Reproducibles, il est recommandé d'utiliser --sort-dirents=yes plutôt que --shuffle-dirents=yes pour garantir que toute différence entre les constructions est déterministe en soi. Par exemple :

$ mkdir rootdir sorted reversed
$ touch rootdir/a rootdir/b rootdir/c (1)
$ disorderfs --sort-dirents=yes --reverse-dirents=no rootdir sorted (2)
$ ls -f sorted
.  ..  a  b  c (3)
$ disorderfs --sort-dirents=yes --reverse-dirents=yes rootdir reversed (4)
$ ls -f reversed
c  b  a  ..  . (5)
1. Tout d'abord, nous créons quelques fichiers d'exemple
2. Montons rootdir en mode trié...
3. ... et les résultats sont dans l'ordre trié.
4. Nous montons rootdir à nouveau, triant les résultats dans l'ordre inversé...
5. ... et le contenu du répertoire est retourné en sens inverse.

$ fusermount -u sorted $ fusermount -u reversed
