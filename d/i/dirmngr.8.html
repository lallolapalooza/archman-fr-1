DESCRIPTIO

N

Depuis la version 2.1 de GnuPG, dirmngr s'occupe de l'accès aux serveurs de clés OpenPGP. Comme dans les versions précédentes, il est également utilisé comme serveur pour gérer et télécharger les listes de révocation de certificats (CRL) pour les certificats X.509, télécharger des certificats X.509 et fournir l'accès aux fournisseurs OCSP. Dirmngr est invoqué en interne par gpg, gpgsm, ou via l'outil gpg-conne

ct-ag
ent.

--keyserver na
me
Utilise name comme votre serveur de clés. C'est le serveur avec lequel gpg communique pour recevoir des clés, envoyer des clés et rechercher des clés. Le format de name est une URI : `scheme:[//]keyservername[:port]' Le schéma est le type de serveur de clés : "hkp" pour les serveurs de clés HTTP (ou compatibles) ou "ldap" pour les serveurs de clés LDAP. Notez que votre installation particulière de GnuPG peut avoir d'autres types de serveurs de clés disponibles. Les schémas de serveurs de clés ne sont pas sensibles à la casse. Après le nom du serveur de clés, des options de configuration optionnelles peuvent être fournies. Ce sont les mêmes que --keyserver-options de gpg, mais elles ne s'appliquent qu'à ce serveur de clés particulier.

Certains serveurs de clés se synchronisent entre eux, il n'est donc pas toujours nécessaire d'envoyer des clés à plus d'un serveur. Certains serveurs de clés utilisent le DNS round robin pour donner un serveur de clés différent à chaque fois que vous

l'utilisez.

Si exactement deux serveurs de clés sont configurés et qu'un seul est un service caché Tor (.onion), Dirmngr sélectionne le serveur de clés à utiliser en fonction du fait que Tor est localement en cours d'exécution ou non. La vérification de l'exécution de Tor est effectuée pour chaque nouvelle

connexion.

Si aucun serveur de clés n'est explicitement configuré, dirmngr utilisera la valeur par défaut intégrée https://keyserver.ubuntu.com. Pour éviter l'utilisation d'un serveur de clés par défaut, la valeur none peut être

utilisée.

Les utilisateurs Windows avec un serveur de clés fonctionnant sur leur Active Directory peuvent utiliser la forme courte ldap:/// pour name afin d'accéder à cet

annuaire.

Pour accéder aux serveurs de clés LDAP anonymes, name est généralement simplement un ldaps://ldap.example.com. Un paramètre BaseDN ne devrait jamais être spécifié. Si une authentification est requise, les choses sont plus compliquées et deux méthodes sont disponibles

--add-serve
rs
Cette option fait que dirmngr ajoute tous les serveurs qu'il découvre lors de la validation des certificats contre les CRL à la liste interne des serveurs à consulter pour les certificats et les CRL. Cette option ne devrait généralement pas être utilisée.

Cette option peut être utile lorsqu'on essaie de valider un certificat qui a un point de distribution de CRL pointant vers un serveur qui n'est pas déjà listé dans la ldapserverlist. Dirmngr ira toujours vers ce serveur et essaiera de télécharger le CRL, mais il y a de fortes chances que le certificat utilisé pour signer le CRL se trouve sur le même serveur. Ainsi, si dirmngr n'ajoute pas ce nouveau serveur à la liste, il ne pourra souvent pas vérifier la signature du CRL à moins que l'option --add-servers ne soit

utilisée.

Caveat emptor : l'utilisation de cette option peut permettre des attiques par déni de service et faire fuiter les requêtes de recherche vers des tiers inconnus. C'est parce que des serveurs arbitraires sont ajoutés à la liste interne des serveurs LDAP, qui est à son tour utilisée pour toutes les requêtes LDAP non spécifiques ainsi que comme solution de repli pour les requêtes qui n'ont pas

Pour vous assurer que le fichier est recherché dans le répertoire personnel, préfixez le nom avec « ./ » ou utilisez un nom qui contient un point. Le format d'un tel fichier est une liste d'empreintes SHA-1, une par ligne avec des deux-points optionnels entre les octets. Les lignes vides et les lignes préfixées par un dièse sont ignorées.

FICHIER

S

Dirmngr utilise plusieurs répertoires lorsqu'il s'exécute en mode démon : il y a quelques fichiers de configuration pour contrôler le fonctionnement de dirmngr. Par défaut, ils peuvent tous être trouvés dans le répertoire personnel courant (voir : [option --homedir])

.
dirmngr.
conf
C'est le fichier de configuration standard lu par dirmngr au démarrage. Il peut contenir n'importe quelle option longue valide ; les deux tirets de début ne doivent pas être saisis et l'option ne peut pas être abrégée. Ce fichier est également lu après un SIGHUP, cependant toutes les options n'auront pas nécessairement d'effet. Ce nom par défaut peut être changé en ligne de commande (voir : [option --options]). Vous devriez sauvegarder ce
fichier.
/etc/gnupg/trusted-ce
rts
Ce répertoire devrait être rempli avec les certificats des AC racines en lesquelles vous avez confiance pour vérifier les CRL et signer les réponses OCSP.

Habituellement, ce sont les mêmes certificats que vous utilisez avec les applications utilisant dirmngr. On s'attend à ce que chacun de ces fichiers de certificats contienne exactement un certificat encodé en DER dans un fichier avec le suffixe «.crt » ou «.der ». dirmngr lit those certificates on startup and when given a SIGHUP. Certificates which are not readable or do not make up a proper X.509 certificate are ignored; see the log file for

details.

Applications using dirmngr (e.g. gpgsm) can request these certificates to complete a trust chain in the same way as with the extra-certs directory (see

below).

Note that for OCSP responses the certificate specified using the option --ocsp-signer is always considered v

alid to sign OCSP
requests.
/etc/gnupg/extra-ce
rts
This directory may contain extra certificates which are preloaded into the internal cache on startup. Applications using dirmngr (e.g. gpgsm) can request cached certificates to complete a trust chain. This is convenient in cases you have a couple intermediate CA certificates or certificates usually used to sign OCSP responses. These certificates are first tried before going out to the net to look for them. These certificates must also be DER encoded and suffixed with ‘.crt’ or ‘.der
