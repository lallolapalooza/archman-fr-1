NOM

dict - Client du protocole DICT

SYNOPSIS

dict mot
dict [options] [mot]
dict [options] dict://hôte:port/d:mot:base_de_données
dict [options] dict://hôte:port/m:mot:base_de_données:stratégie

DESCRIPTION

dict est un client pour le protocole de serveur de dictionnaire (DICT), un protocole de requête/réponse basé sur des transactions TCP qui donne accès aux définitions de dictionnaires provenant d'un ensemble de bases de données de dictionnaires en langage naturel. Le code de sortie est 0 si l'opération a réussi, ou non nul dans le cas contraire.
Voir la section CODE DE SORTIE .

OPTIONS

-h serveur ou --host serveur
Spécifie le nom d'hôte du serveur DICT. Les combinaisons serveur/port peuvent être spécifiées dans le fichier de configuration. Si aucun serveur n'est spécifié dans le fichier de configuration ou sur la ligne de commande, dict échouera. Si la résolution IP d'un serveur renvoie une liste d'adresses IP (comme dict.org le fait actuellement), alors chaque IP sera essayée dans l'ordre indiqué.
-p service ou --port service
Spécifie le port (par ex., 2628) ou le service (par ex., dict) pour les connexions. La valeur par défaut est 2628, comme spécifié dans la RFC du protocole DICT. Les combinaisons serveur/port peuvent être spécifiées dans le fichier de configuration.
-d nom_base ou --database nom_base
Spécifie une base de données spécifique à rechercher. Par défaut, toutes les bases de données sont recherchées (un "*" dans le protocole DICT). Notez qu'un "!" dans le protocole DICT signifie de rechercher dans toutes les bases de données jusqu'à ce qu'une correspondance soit trouvée, puis d'arrêter la recherche.
-m ou --match
Au lieu d'afficher une définition, effectue une recherche de correspondance en utilisant la stratégie spécifiée.
-s stratégie ou --strategy stratégie
Spécifie une stratégie de correspondance. Par défaut, la stratégie de correspondance par défaut du serveur est utilisée. C'est généralement "exact" pour les définitions, et une forme de stratégie de correction orthographique pour les correspondances ("." dans le protocole DICT). Les stratégies disponibles dépendent de l'implémentation du serveur. Pour une liste des stratégies disponibles, voir l'option -S ou --strats.
-C ou --nocorrect
Généralement, si une définition est demandée et que le mot ne peut être trouvé, une correction orthographique est demandée au serveur, et une liste de mots possibles est fournie. Cette option désactive la génération de cette liste.
-c fichier ou --config fichier
Spécifie le fichier de configuration. Par défaut, essaie ~/.dictrc et /etc/dict/dict.conf, en utilisant le premier fichier qui existe. Si un fichier de configuration spécifique est spécifié, les valeurs par défaut ne seront pas essayées.
-D ou --dbs
Interroge le serveur et affiche la liste des bases de données disponibles.
-S ou --strats
Interroge le serveur et affiche la liste des stratégies de recherche disponibles.
-H ou --serverhelp
Interroge le serveur et affiche les informations d'aide qu'il fournit.
-i nom_base ou --info nom_base
Demande des informations sur la base de données spécifiée (généralement le serveur fournira l'origine, une description ou d'autres informations sur la base de données ou son contenu).
-I ou --serverinfo
Interroge le serveur et affiche des informations sur le serveur.
-M ou --mime
Envoie la commande OPTION MIME au serveur.
NOTE : Les capacités du serveur ne sont pas vérifiées.
-f ou --formatted
Active la sortie formatée, c'est-à-dire une sortie adaptée au post-traitement par les utilitaires UNIX standards. Non, ce n'est pas du XML ;-) De plus, les messages d'erreur et d'avertissement comme
" No matches...", " Invalid strategy..." etc. sont envoyés vers stderr, et non vers stdout.
Format :
-I, -i, -H et similaires :
hôte<TAB>port
<SPC><SPC>ligne1
<SPC><SPC>ligne2
...
-S :
hôte<TAB>port<TAB>stratégie1<TAB>description_courte1
hôte<TAB>port<TAB>stratégie2<TAB>description_courte2
...
-D :
hôte<TAB>port<TAB>base_de_données1<TAB>description_base1
hôte<TAB>port<TAB>base_de_données2<TAB>description_base2
...
-m :
hôte<TAB>port<TAB>base_de_données1<TAB>correspondance1
hôte<TAB>port<TAB>base_de_données2<TAB>correspondance2
...
-a ou --noauth
Désactive l'authentification (c'est-à-dire n'envoie pas de commande AUTH).
-u utilisateur ou --user utilisateur
Spécifie le nom d'utilisateur pour l'authentification.
-k clé ou --key clé
Spécifie le secret partagé pour l'authentification.
-V ou --version
Affiche les informations de version.
-L ou --license
Affiche les informations de copyright et de licence.
-4
Force dict à utiliser uniquement des adresses IPv4.
-6
Force dict à utiliser uniquement des adresses IPv6.
--help
Affiche les informations d'aide.
-v ou --verbose
Mode bavard.
-r ou --raw
Très bavard : affiche l'interaction brute client/serveur.
--pipesize
Spécifie la taille du tampon pour la mise en pipeline des commandes. La valeur par défaut est 256, ce qui devrait être suffisant pour les tâches générales et inférieur au MTU pour la plupart des supports de transport. Des valeurs plus grandes peuvent fournir un débit plus rapide ou plus lent, selon le MTU. Si le tampon est trop petit, les requêtes seront sérialisées. Les valeurs inférieures à 0 et supérieures à un million sont silencieusement remplacées par quelque chose de plus raisonnable.
--client texte
Spécifie un texte supplémentaire à envoyer en utilisant la commande CLIENT.
--debug indicateur
Définit un indicateur de débogage. Les indicateurs valides sont :
verbose
Identique à -v ou --verbose.
raw
Identique à -r ou --raw.
scan
Débogue le scanner pour le fichier de configuration.
parse
Débogue l'analyseur pour le fichier de configuration.
pipe
Débogue la prise en charge du pipeline TCP (voir la RFC DICT et la RFC1854).
serial
Désactive la prise en charge du pipeline.
time
Effectue la temporisation des transactions.

CONFIGURATION

Le fichier de configuration a actuellement un format très simple. Les lignes sont utilisées pour spécifier des serveurs, par exemple :

server dict.org
ou, avec des options :
server dict.org { port 8080 }
server dict.org { user nom_utilisateur secret }
server dict.org { port dict user nom_utilisateur secret }
les options port et user peuvent être spécifiées dans n'importe quel ordre. L'option port est utilisée pour spécifier un port optionnel (par ex., 2628) ou un service (par ex., dict) pour la connexion TCP/IP. L'option user est utilisée pour spécifier un nom d'utilisateur et un secret partagé à utiliser pour l'authentification auprès de ce serveur particulier.

Les serveurs sont essayés dans l'ordre indiquéjusqu'à ce qu'une connexion soit établie.

CODES DE SORTIE


0 Exécution réussie


20 Aucune correspondance trouvée
21 Correspondances approximatives trouvées
22 Aucune base de données disponible
23 Aucune stratégie disponible


30 Code de réponse inattendu du serveur
31 Le serveur est temporairement indisponible
32 Le serveur est en cours d'arrêt
33 Erreur de syntaxe, commande non reconnue
34 Erreur de syntaxe, paramètres illégaux
35 Commande non implémentée
36 Paramètre de commande non implémenté
37 Accès refusé
38 Échec de l'authentification
39 Base de données invalide
40 Stratégie invalide
41 Échec de la connexion au serveur

BOGUES

Si une dict: URL est donnée sur la ligne de commande, seule la première est utilisée. Les autres sont ignorées.

Si une dict: URL contient un spécificateur pour la nième définition ou correspondance d'un mot, il sera ignoré et toutes les définitions ou correspondances seront fournies. Cela viole la RFC et sera corrigé dans une version future.

Si une dict: URL contient un secret partagé, il ne sera pas analysé correctement.

Lorsque la commande OPTION MIME est envoyée au serveur (option -M ), les capacités du serveur ne sont pas vérifiées.
