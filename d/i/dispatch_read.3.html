dispatch_read(3) Manuel des fonctions de bibliothèque dispatch_read(3)

NOM

dispatch_read, dispatch_write — lecture et écriture asynchrones sur des descripteurs de fichiers

SYNTAXE

#include <dispatch/dispatch.h>

void
dispatch_read(int fd, size_t length, dispatch_queue_t queue, void (^handler)(dispatch_data_t data, int error));

void
dispatch_write(int fd, dispatch_data_t data, dispatch_queue_t queue, void (^handler)(dispatch_data_t data, int error)));

DESCRIPTION

Les fonctions dispatch_read() et dispatch_write() lisent et écrivent de manière asynchrone sur des descripteurs de fichiers POSIX. Elles peuvent être considérées comme des versions asynchrones basées sur des callbacks des fonctions fread() et fwrite() fournies par la bibliothèque C standard. Ce sont des fonctions de commodité basées sur les fonctions dispatch_io_read(3) et dispatch_io_write(3), destinées à des requêtes de lecture ou d'écriture simples et ponctuelles. Les multiples requêtes sur le même descripteur de fichier sont mieux gérées avec les fonctions complètes du canal d'E/S dispatch sous-jacent.

COMPORTEMENT

La fonction dispatch_read() planifie une opération de lecture asynchrone sur le descripteur de fichier fd. Une fois que le descripteur de fichier est lisible, le système lira autant de données que disponibles actuellement, jusqu'à la length spécifiée, en partant de la position actuelle du pointeur de fichier. Le bloc handler donné sera soumis à queue lorsque l'opération se terminera ou qu'une erreur surviendra. Le bloc recevra un objet dispatch data avec le résultat de l'opération de lecture. Si une erreur s'est produite lors de la lecture du descripteur de fichier, le paramètre error du bloc sera défini au code d'erreur POSIX approprié et data contiendra toutes les données qui ont pu être lues avec succès. Si la position du pointeur de fichier est en fin de fichier, une data vide et une error de zéro seront transmises au bloc gestionnaire.

La fonction dispatch_write() planifie une opération d'écriture asynchrone sur le descripteur de fichier fd. Le système tentera d'écrire tout le contenu de l'objet data fourni sur fd à la position actuelle du pointeur de fichier. Le bloc handler donné sera soumis à queue lorsque l'opération se terminera ou qu'une erreur surviendra. Si l'opération d'écriture s'est terminée avec succès, le paramètre error du bloc sera mis à zéro, sinon il sera défini au code d'erreur POSIX approprié et le paramètre data contiendra toutes les données qui n'ont pas pu être écrites.

MISE EN GARDE

L'objet data passé à un bloc handler est libéré par le système lorsque le bloc revient. Si data est nécessaire en dehors du bloc gestionnaire, il doit être concaténé, copié ou conservé.

Une fois qu'une opération de lecture ou d'écriture asynchrone a été soumise sur un descripteur de fichier fd, le système prend le contrôle de ce descripteur de fichier jusqu'à ce que le bloc handler soit exécuté. Pendant cette période, l'application ne doit pas manipuler fd directement, en particulier il est uniquement sûr de fermer fd depuis le bloc gestionnaire (ou après qu'il soit revenu).

Si plusieurs opérations de lecture ou d'écriture asynchrones sont soumises sur le même descripteur de fichier, elles seront exécutées dans l'ordre, mais leurs gestionnaires ne seront soumis qu'une fois toutes les opérations terminées et le contrôle du descripteur de fichier abandonné. Pour plus de détails à ce sujet et sur l'interaction avec les canaux d'E/S dispatch créés à partir du même descripteur de fichier, voir PROPRIÉTÉ DU DESCIPTEUR DE FICHIER dans dispatch_io_create(3).
