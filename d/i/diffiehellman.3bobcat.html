FBB::DiffieHellman(3bobcat) Calculs de clés Diffie-Hellman FBB::DiffieHellman(3bobcat)

NOM

FBB::DiffieHellman - PKI Diffie-Hellman, calcul des clés partagées

SYNTAXE

#include <bobcat/diffiehellman>
Option de compilation : -lbobcat -lcrypto

DESCRIPTION

La classe FBB::DiffieHellman calcule des clés partagées (secrets partagés) en utilisant l'algorithme de Diffie-Hellman (1976). L'algorithme de Diffie-Hellman utilise des informations publiques et privées, fournissant une infrastructure à clé publique (PKI). Les informations publiques consistent en un nombre premier (par exemple, un nombre premier de 1024 bits), un générateur (pour lequel la valeur 5 est couramment utilisée), et (en utilisant ** pour représenter l'opérateur de puissance sur les entiers) la valeur générateur ** privé mod premier, où privé est un grand nombre sélectionné aléatoirement, qui constitue l'information privée.

L'algorithme de Diffie-Hellman est couramment utilisé pour calculer une clé partagée qui peut être utilisée pour chiffrer les informations envoyées entre deux parties. Une partie, appelée ici l'initiateur, calcule le nombre premier et définit le générateur. Le nombre premier est calculé par le premier constructeur de FBB::DiffieHellman, tandis que le générateur est passé à ce constructeur comme l'un de ses arguments. La valeur 5 est souvent utilisée comme générateur.

Ensuite, l'initiateur transmet ses informations publiques, composées du nombre premier, du générateur, et de la valeur pow(générateur, privé) mod premier à l'autre partie, appelée ici le pair. Les informations publiques sont écrites au format binaire, big-endian, dans un fichier en utilisant le membre save. L'initiateur peut éventuellement enregistrer les informations privées dans un fichier séparé.

Le pair reçoit alors les informations publiques de l'initiateur. Les informations publiques de l'initiateur sont lues par un constructeur FBB::DiffieHellman qui attend soit le nom d'un fichier, soit un std::istream contenant les informations publiques de l'initiateur.

Ayant obtenu le nombre premier et le générateur, les informations publiques (et optionnellement privées) du pair sont enregistrées en appelant également save. Ceci résulte, entre autres, en la valeur pow(générateur, privé) mod premier, mais en utilisant maintenant les informations privées du pair.

À ce stade, le pair est déjà capable de calculer la clé partagée. La clé est retournée en appelant le membre key, qui renvoie la clé partagée sous forme d'une série d'octets stockée dans une std::string.

Avant que l'initiateur puisse calculer la clé partagée, la valeur générateur ** privé mod premier du pair doit être disponible. Le pair envoie les données publiques enregistrées à l'initiateur. L'initiateur transmet alors les données publiques du pair, soit par nom de fichier, soit par std::istream, au membre key, qui retourne la clé partagée.

Confidentialité persistante (Perfect Forward Secrecy) et Diffie Hellman éphémère

Si l'initiateur et le pair décident de ne pas enregistrer leurs informations privées, la confidentialité persistante et le Diffie Hellman éphémère peuvent être obtenus. Voici comment la procédure est appliquée :

o
L'initiateur et le pair ont convenu et échangé de manière sécurisée un secret commun de longue durée, qui peut être utilisé en combinaison avec, par exemple, des méthodes de chiffrement symétrique.
o
En appliquant la procédure mentionnée ci-dessus, les informations privées ne sont jamais enregistrées dans un fichier. Par conséquent, la clé partagée, une fois calculée, ne peut plus être reconstruite.
o
La valeur générateur ** privé mod premier n'est pas envoyée à l'un ou l'autre pair ou initiateur « en clair », mais chiffrée à l'aide du secret commun de longue durée. Comme l'implémentation actuelle enregistre toutes les informations publiques dans un fichier, il est probablement plus simple de chiffrer le fichier contenant les informations publiques.
o
Les destinataires, après avoir reçu les informations publiques chiffrées de l'autre partie, les déchiffrent à l'aide du secret commun de longue durée et calculent la clé partagée.
o
Comme les informations secrètes ne sont pas conservées, la clé partagée ne peut pas être reconstruite, tandis qu'une attaque de l'homme du milieu (Man-In-The-Middle) est évitée en n'échangeant que des informations publiques chiffrées.
o
La clé partagée peut maintenant être utilisée pour chiffrer une session de communication.

Chiffrement de documents utilisant Diffie Hellman

Comme pour la PKI en général, la méthode d'échange de clés Diffie Hellman n'est normalement pas utilisée pour chiffrer des documents. Au lieu de cela, elle est généralement utilisée pour échanger la clé qui sera utilisée pour les méthodes de chiffrement symétrique comme 3DES et CBC. Ces méthodes de chiffrement symétrique sont disponibles via, par exemple, les classes EncryptBuf, DecryptBuf et ISymCryptStream de Bobcat.

CONSTRUCTEURS

o
DiffieHellman(size_t primeLength = 1024, size_t generator = 5, bool progress = false) :
Ce constructeur calcule un nombre premier de la longueur spécifiée et initialise les informations publiques avec le générateur indiqué. La longueur du nombre premier doit être d'au moins 1024 bits, sinon une FBB::Exception sera levée. Si progress est true, la progression du processus de construction du nombre premier est affichée sur std::cout par une série de points, de tirets et de plus. La génération d'un nombre premier approprié peut échouer, entraînant la levée d'une FBB::Exception. Sauf si le générateur est spécifié comme étant 2 ou 5, l'avertissement cannot check the validity of generator ... est inséré dans l'objet wmsg de mstream(3bobcat). Un avertissement est également inséré si le générateur fourni n'est pas un générateur pour le nombre premier calculé.
Ce constructeur doit être appelé par l'initiateur pour démarrer la procédure de calcul de clé partagée Diffie-Hellman.
o
DiffieHellman(FBB::BigInt const &prime, size_t generator = 5, bool progress = false) :
Alternativement, ce constructeur peut être utilisé par l'initiateur après avoir construit séparément le nombre premier à utiliser. Le nombre premier doit avoir au moins 1024 bits.
o
DiffieHellman(std::string const &initiatorPublicFileName) :
Ce constructeur doit être appelé par le pair, après avoir reçu les informations publiques de l'initiateur. Il rend les informations publiques de l'initiateur disponibles au pair, après quoi les informations publiques et privées du pair peuvent être calculées.
o
DiffieHellman(std::stream &initiatorPublicStream) :
Ce constructeur agit comme le constructeur précédent, attendant un std::istream plutôt qu'un nom de fichier. Il doit être appelé par le pair, après avoir reçu les informations publiques de l'initiateur. Il rend les informations publiques de l'initiateur disponibles au pair, après quoi les informations publiques et privées du pair peuvent être calculées.
o
DiffieHellman(std::string const &initiatorPublicFileName, std::string const &initiatorPrivateFileName) :
Sauf si l'objet DiffieHellman de l'initiateur est toujours disponible, ce constructeur doit être à nouveau appelé par l'initiateur, pour charger les données publiques et privées de l'initiateur.
o
DiffieHellman(std::stream &initiatorPublicStream, std::stream &initiatorPrivateStream) :
Ce constructeur agit comme le constructeur précédent, attendant des std::istream plutôt que des noms de fichiers. Il doit être appelé par l'initiateur, pour charger les informations publiques et privées de l'initiateur.

Les constructeurs et opérateurs de copie et de déplacement sont disponibles.

FONCTIONS MEMBRE

o
std::string key() const:
Cet membre doit être appelé par le pair. Il retourne la clé partagée. Si la clé ne peut pas être calculée, ou si la clé n'est pas résistante à l'attaque par petit groupe (c'est-à-dire si la clé est égale à 1, ou si elle est au moins égale à la valeur du nombre premier public, ou si key ** ((prime - 1) / 2) mod prime != 1), alors une FBB::Exception est
levée.
o
std::string key(std::string const &peerPublicFileName) const:
Cet membre doit être appelé par l'initiateur. Il saute les données relatives au nombre premier et au générateur trouvées dans peerPublicFileName puis lit la valeur du pair generator ** private mod prime. Si cette valeur ne peut pas être lue ou si la clé n'est pas résistante à l'attaque par petit groupe (cf. la description du membre key précédent) alors une FBB::Exception est levée. Il retourne la clé
partagée.
o
std::string key(std::istream const &peerPublicStream) const:
Cet membre doit être appelé par l'initiateur. Il se comporte comme le membre key précédent, en lisant la valeur du pair generator ** private mod prime depuis peerPublicStream. Il retourne la clé
partagée.
o
void save(std::string const &basename):
Cet membre doit être appelé par l'initiateur. Il sauvegarde les informations publiques dans le fichier ’basename’.pub. Les informations sont écrites en format binaire, big-endian, en utilisant l'organisation suivante
:
- la taille du nombre premier en octets ;
- les octets du nombre premier ;
- la taille du générateur en octets ;
- les octets du générateur ;
- la taille des informations publiques (generator ** private mod prime) en octets ;
- les octets des informations
publiques.
De plus, les informations privées sont écrites dans le fichier ’basename’.sec en format binaire, big-endian, en utilisant l'organisation suivante
:
- la taille des informations privées en octets ;
- les octe
ts des informations privées.

EXEMPL

E

Lorsqu'il est appelé sans arguments, le programme d'exemple génère des paramètres Diffie-Hellman en écrivant les informations publiques et privées de l'initiateur respectivement dans init.pub et init.s

ec.

Lorsqu'il est appelé avec un argument, init.pub est lu, et les informations publiques et privées du pair sont écrites respectivement dans peer.pub et peer.sec. Ensuite, la clé partagée (du pair) est écrite dans peerkey

.

Lorsqu'il est appelé avec deux arguments, init.pub et init.sec sont lus, ainsi que les informations publiques du pair (dans le fichier peer.pub). Ensuite, la clé partagée (de l'initiateur) est écrite dans initkey

.

Les fichiers peerkey et initkey devraient être

identiques. 
#include <fstream>
#include <iostream>
#include <bobcat/exception>
#include "../diffiehellman"
using namespace FBB;
using namespace std;
int main(int argc, char **argv)
try
{
    if (argc == 1)
    {
        cout << "1: create prime and generator, write to ’params’\n"
                "2: create secret and public parts, arg 2: 0 or 1,\n"
                "   write secret and public parts to <arg 2>.sec and "
                                                     "<arg 2>.pub\n"
                "3: create common key arg 2: 0 or 1,\n"
                "   0: write common0 using 0.pub, 0.sec and 1.pub\n"
                "   1: write common1 using 1.pub, 1.sec and 0.pub\n"
                ;
        return 0;
    }
    switch (*argv[1])                       // using generator == 5
    {
        case ’1’:
        {
            ofstream out = Exception::factory<ofstream>("params");
            out << hex << DiffieHellman::prime(1024, true, true) << ’\n’;
        }
        break;
        case ’2’:
        {
            char *nr = argv[2];
            if (nr == 0 || "01"s.find(*nr) == string::npos)
                throw Exception{} << "mode ’2’ needs 0 or 1 as 2nd argument";
            ifstream in = Exception::factory<ifstream>("params");
            BigInt prime;
            in >> hex >> prime;
            DiffieHellman dh{ prime };
            dh.save(nr);
        }
        break;
        case ’3’:
        {
            char *nr = argv[2];
            if (nr == 0 || "01"s.find(*nr) == string::npos)
                throw Exception{} << "mode ’3’ needs 0 or 1 as 2nd argument";
            DiffieHellman dh{ nr + ".pub"s, nr + ".sec"s };
            cout << "common key computed by " << nr << ":\n" <<
                hex << dh.key((nr[0] == ’0’ ? ’1’ : ’0’) + ".pub"s) << ’\n’;
        }
        break;
        default:
        throw Exception{} << "undefined action `" << *argv[1] <<’\’’;
    }
}
catch (std::exception const &exc)
{
    std::cout << exc.what() << ’\n’;
}
