UTILISATION PAR LES

APPLICATIONS

La définition de chemin d'accès spécifie un comportement défini par l'implémentation pour les chemins d'accès commençant par deux caractères <slash>. Par conséquent, les applications ne doivent pas ajouter arbitrairement de caractères <slash> au début d'un chemin d'accès, à moins qu'elles ne puissent s'assurer qu'il y en a plus ou moins que deux ou qu'elles soient prêtes à gérer les conséquences définies par l'implémentatio

n

JUSTIFICATIO

N

Les comportements de basename et dirname dans ce volume de POSIX.1‐2017 ont été coordonnés de sorte que lorsque string est un chemin d'accès valide

: 
$(basename -- "string
"
)

serait un nom de fichier valide pour le fichier dans le répertoire

: 
$(dirname -- "string
"
)

Cela ne fonctionnerait pas pour les versions de ces utilitaires dans les premières propositions en raison de la manière dont le traitement des caractères <slash> finaux était spécifié. La possibilité de laisser le traitement non spécifié s'il y avait des caractères <slash> finaux a été envisagée, mais cela ne peut être fait ; le volume Définitions de base de POSIX.1‐2017, Section 3.271, Chemin d'accès autorise les caractères <slash> finaux. Les utilitaires basename et dirname doivent spécifier un traitement co

hérent pour tous les c
hemins d'accès valides.
