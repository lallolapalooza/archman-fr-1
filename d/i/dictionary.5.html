dictionary(5) Manuel des formats de fichiers dictionary(5)

NOM

dictionary - Fichier dictionnaire RADIUS

DESCRIPTION

Le fichier dictionnaire RADIUS principal se trouve dans /etc/raddb/dictionary. Il référence d'autres fichiers dictionary situés dans /usr/share/freeradius/. Chaque fichier dictionnaire contient une liste d'attributs et de valeurs RADIUS, que le serveur utilise pour établir la correspondance entre les noms descriptifs et les données transmises sur le réseau. Les noms n'ont aucune signification en dehors du serveur RADIUS lui-même, et ne sont jamais échangés entre le serveur et les clients.

C'est-à-dire que la modification des dictionnaires n'aura AUCUN EFFET sur autre chose que le serveur qui lit ces fichiers. L'ajout de nouveaux attributs aux dictionnaires n'aura AUCUN EFFET sur les clients RADIUS, et ne fera pas en sorte que les clients RADIUS comprennent magiquement ces attributs. Les dictionnaires sont uniquement destinés à la commodité de l'administrateur local, et sont spécifiques à chaque version de FreeRADIUS.

Les dictionnaires dans /usr/share NE DEVRAIENT PAS être modifiés sauf si vous savez exactement ce que vous faites. Leur modification risque très probablement de casser votre déploiement RADIUS.

Si vous avez besoin d'ajouter de nouveaux attributs, veuillez modifier le fichier /etc/raddb/dictionary. Son seul but est de contenir les définitions locales qui sont ajoutées par l'administrateur local.

FORMAT

Chaque ligne commençant par un signe dièse ('#') est traitée comme un commentaire et ignorée.

Chaque ligne du fichier peut contenir l'une des chaînes suivantes:

ATTRIBUTE nom oid type [indicateurs]
Définit un mappage nom-nombre d'attribut RADIUS.

Le champ nom est un champ imprimable, tiré de diverses spécifications ou définitions de fournisseurs. Il est le plus souvent utilisé sous forme de mots séparés par des tirets. Par exemple, "User-Name". Les attributs spécifiques aux fournisseurs (VSA) sont précédés du nom du fournisseur, par exemple "Cisco-AVPair". Les noms doivent être globalement uniques, car ils sont utilisés comme clé pour rechercher les propriétés de l'attribut.

Le champ oid est tiré de la spécification pertinente pour ce nom. Dans la plupart des cas, il s'agit d'un nombre décimal, comme "256". Pour certains attributs, une notation "nombre pointé" est utilisée, par exemple "1.2". La notation "nombre pointé" n'est utilisée que pour certains attributs.

Le champ type peut être l'un des types standard:


string Texte imprimable UTF-8 (les RFC appellent cela "text")
octets Données binaires opaques (les RFC appellent cela "string")
ipaddr Adresse IPv4
date Secondes depuis le 1er janvier 1970 (32 bits)
integer Entier non signé de 32 bits
ipv6addr Adresse IPv6
ipv6prefix Préfixe IPV6, avec masque
ifid Identifiant d'interface (hex:hex:hex:hex)
integer64 Entier non signé de 64 bits

Le champ type peut être l'un des types non standard suivants:


ether Adresse MAC Ethernet
abinary Filtre binaire Ascend
byte Entier non signé de 8 bits
short Entier non signé de 16 bits
signed Entier signé de 31 bits (empacté dans un champ de 32 bits)
tlv Type-Longueur-Valeur (permet des attributs imbriqués)
ipv4prefix Préfixe IPv4 tel que donné dans la RFC 6572.

Le dernier champ (facultatif) d'une définition d'attribut sont des indicateurs supplémentaires pour cet attribut, dans une liste séparée par des virgules. Les versions précédentes du serveur permettaient à ces indicateurs de contenir un nom de fournisseur. Ce comportement peut toujours fonctionner, mais il est déprécié et non recommandé.

Les options sont:


array Plusieurs valeurs sont regroupées dans un seul attribut.
concat Plusieurs attributs doivent être concaténés
encrypt=# définit le type de chiffrement 1, 2 ou 3.
has_tag L'attribut peut avoir une étiquette de style RFC 2868
secret Une valeur qui ne doit pas être affichée en mode débogage
virtual L'attribut est spécial pour le serveur.

L'indicateur "array" est uniquement utilisé pour DHCP. Il indique qu'une option DHCP peut contenir un tableau de plusieurs valeurs.

Les indicateurs "concat" indiquent que lorsque plusieurs attributs sont présents dans un paquet, leurs contenus doivent être concaténés pour obtenir le contenu final. De même, lors de l'encodage des paquets, une longue valeur doit être divisée en plusieurs attributs.

L'indicateur "encrypt" marque l'attribut comme étant chiffré avec l'une des trois méthodes possibles. "1" signifie que l'attribut est chiffré avec la méthode définie dans la RFC2865 pour l'attribut User-Password. "2" signifie que le mot de passe est chiffré avec la méthode définie dans la RFC2868 pour l'attribut Tunnel-Password. "3" signifie que l'attribut est chiffré selon les définitions d'Ascend pour l'attribut Ascend-Send-Secret.

L'indicateur "has_tag" marque l'attribut comme étant autorisé à avoir une étiquette, telle que définie dans la RFC2868. Le but de l'étiquette est de permettre le regroupement d'attributs pour les utilisateurs tunnelisés. Voir la RFC2868 pour plus de détails.

L'indicateur "secret" indique que la valeur ne doit pas être affichée en mode de débogage normal. La valeur sera affichée lorsque le niveau de débogage est de 3 ou plus.

L'indicateur "virtual" est pour le serveur et indique que l'attribut n'existe pas réellement. La valeur est plutôt prise d'un rappel interne.

Lorsque le serveur reçoit un attribut encodé dans un paquet RADIUS, il recherche cet attribut par son numéro dans le dictionnaire et utilise la définition trouvée pour l'affichage des messages de diagnostic et de journalisation. Lorsque le serveur rencontre un nom d'attribut dans un fichier de configuration, il recherche cet attribut par son nom dans le dictionnaire et utilise la définition trouvée.

VALUE nom-attribut nom-valeur nombre
Définit un mappage nom-valeur d'attribut pour un attribut de type integer. Le champ nom-attribut DOIT être précédemment défini par une entrée ATTRIBUTE. Le champ nom-valeur peut être n'importe quel texte sans espace, mais est généralement tiré de la RFC2865 ou d'autres documents. Le champ nombre est également tiré des documents pertinents pour ce nom.

Lorsque le serveur reçoit une valeur encodée dans un paquet RADIUS, il recherche la valeur de cet attribut par son nombre dans le dictionnaire et utilise le nom trouvé pour l'affichage des messages de diagnostic et de journalisation.

VENDOR nom-fournisseur nombre [format=...]
Définit un encapsulage d'Attribut Spécifique Fournisseur pour nom-fournisseur vers nombre. Pour une liste de noms et numéros de fournisseurs, voir http://www.iana.org/enterprise-numbers.txt.

L'énoncé "format=t,l" indique au serveur combien d'octets utiliser pour encoder/décoder les champs "type" et "longueur" du fournisseur dans les attributs. Par défaut, c'est "format=1,1", ce qui n'a pas besoin d'être spécifié. Pour les VSA USR, le format est "format=4,0", pour les VSA Lucent c'est "format=2,1", et pour les VSA Starent c'est "format=2,2".

Les valeurs prises en charge pour le nombre d'octets de type (c'est-à-dire le premier chiffre) sont 1, 2 et 4. Les valeurs prises en charge pour le nombre d'octets de longueur (c'est-à-dire le second chiffre) sont 0, 1 et 2. Toute combinaison de ces valeurs fonctionnera.

BEGIN-VENDOR nom-fournisseur
Définit le début d'un bloc d'attributs spécifiques au fournisseur. Toutes les définitions ATTRIBUTE suivantes sont interprétées comme étant pour le fournisseur nommé, jusqu'à ce que le bloc soit fermé par une instruction "END-VENDOR".

Cette pratique est préférée à l'ajout du nom du fournisseur à la fin d'une définition ATTRIBUTE.

Pour les VSA dans l'espace "Extended vendor-specific" de la RFC 6929, un format peut être spécifié après "nom-fournisseur". Le format doit être "format=Extended-Vendor-Specific-1" à "format=Extended-Vendor-Specific-6". Le "END-VENDOR" correspondant devrait simplement contenir le "nom-fournisseur", sans la chaîne de format.

END-VENDOR nom-fournisseur
Ferm
d un bloc BEGIN-VENDOR défini précédemment. Le "vendor-name" doit correspondre.
$INCLUDE filename
Inclure les entrées du dictionnaire depuis le fichier filename. Le filename est considéré comme relatif à l'emplacement du fichier qui demande l'inclusion.
BEGIN-TLV name
Cette fonctionnalité est prise en charge pour assurer la rétrocompatibilité avec les anciens dictionnaires. Elle ne devrait pas être utilisée. La nouvelle forme "oid" pour définir le numéro d'attribut devrait être utilisée à la place.
END-TLV name
Cette fonctionnalité est prise en charge pour assurer la rétrocompatibilité avec les anciens dictionnaires. Elle ne devrait pas être utilisée. La nouvelle forme "oid" pour définir le numéro d'attribut devrait être utilisée à la place.

FICHIERS

/etc/raddb/dictionary, /usr/share/freeradius/dictionary.*
