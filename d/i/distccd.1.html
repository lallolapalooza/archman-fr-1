distccd est le serveur pour le compilateur distribué distcc(1). Il accepte et exécute des travaux de compilation pour les

clients réseau.

distcc peut fonctionner soit via TCP, soit via une commande de connexion telle que ssh(1). Les connexions TCP sont rapides mais relativement peu sécurisées. Les connexions SSH sont sécurisées mais plus lentes. Pour les connexions SSH, distccd doit être installé sur le volontaire mais ne doit pas fonctionner comme un démon -- il sera démarré via SSH selon les besoins. Les connexions SSH présentent plusieurs avantages : ni le client ni le serveur n'écoutent sur de nouveaux ports ; les compilations s'exécutent avec les privilèges de l'utilisateur qui les a demandées ; les utilisateurs non autorisés ne peuvent

pas accéder au serveur ; et le code source et
les sorties sont protégés pendant le transit.

Pour les connexions TCP, distccd peut fonctionner soit à partir d'un programme de style inetd, soit comme un serveur autonome. Le mode autonome est recommandé car il est légèrement plus efficace et permet à distccd de réguler le nombre de travaux

entrants. Les options

--liste

n

e

t

--allow peuvent être utilisées pour un contrôle d'accès simple basé sur l'adresse

IP.

distcc peut être démarré soit par root, soit par tout autre utilisateur. S'il est exécuté par root, il abandonne ses privilèges et passe à l'utilisateur spécifié par l'option --user [[30]], ou à l'utilisateur nommé « distcc », ou à l'utilisateur nommé « nobody ». distccd n'a pas de fichier de configuration ; son comportement est contrôlé uniquement par les options de ligne de commande et les requêtes des

clients.

SERVEUR AUTONOME La méthode recommandée pour exécuter distccd est en tant que serveur autonome. distccd écoutera les connexions réseau et créera plusieurs processus enfants pour les

servir.

Pour l'inetd Unix traditionnel, une ligne comme celle-ci peut être ajoutée à /etc/inetd.conf

distcc stream tcp nowait.6000 root /usr/local/bin/distccd distccd

--inetd

inetd impose une limite au taux de connexions à un service pour se protéger contre une utilisation accidentelle ou intentionnelle excessive. La valeur par défaut dans l'inetd de Linux NetKit est de 40 par minute, ce qui est beaucoup trop bas pour distccd. L'option .6000 porte la limite à 6000 par

minute.

--inetd
Sert un client connecté à stdin/stdout. Comme son nom l'indique, cette option doit être utilisée lorsque distccd est exécuté depuis un super-serveur comme inetd. distccd suppose le mode inetd lorsque stdin est un socket.
--daemon
Se lie et écoute sur un socket, plutôt que d'être exécuté depuis inetd. C'est utilisé pour le mode autonome. distccd suppose le mode daemon au démarrage si stdin est un tty, donc --daemon doit être spécifié explicitement lors du démarrage de distccd depuis un script ou dans une connexion ssh non interactive.
--enable-tcp-insecure
Par défaut (depuis Distcc 3.3), distcc n'exécutera que des binaires qui sont masqués en distcc dans /usr/lib/distcc. Cette option désactive cela et permet à distcc d'exécuter du code arbitraire. Cette fonctionnalité est principalement destinée à la suite de tests de distcc. Voir MASQUERADING de distcc(1).
--zeroconf
Enregistre la disponibilité de ce serveur distccd en utilisant la découverte de service DNS Zeroconf d'Avahi (DNS-SD). Cela permet aux clients distcc du réseau local d'accéder à ce serveur distccd sans lister explicitement son nom d'hôte ou son adresse IP dans leur liste d'hôtes distcc : les clients distcc peuvent simplement utiliser "+zeroconf" dans leurs listes d'hôtes distcc. Peut utiliser -j paramètre pour spécifier le nombre maximum de tâches que ce serveur peut traiter simultanément. Cette option n'est disponible que si distccd a été compilé avec le support Avahi activé.
--auth
Effectue une authentification mutuelle basée sur GSS-API. Cette option n'est disponible que si distccd a été compilé avec l'option de configuration --with-auth.
--show-principal
Affiche le nom du principal de sécurité de distccd extrait de l'environnement. Cette option n'est disponible que si distccd a été compilé avec l'option de configuration --with-auth.
--blacklist=FICHIER
Indique à distccd de rejeter les connexions des utilisateurs dont les noms de principal sont listés dans FICHIER. Cette option n'est disponible que si distccd a été compilé avec l'option de configuration --with-auth et si distccd est exécuté avec l' option --auth.
--whitelist=FICHIER
Indique à distccd d'accepter les connexions uniquement des utilisateurs dont les noms de principal sont listés dans FICHIER. Cette option n'est disponible que si distccd a été compilé avec l'option de configuration --with-auth et si distccd est exécuté avec l' option --auth.

CHEMINS DE RECHERCHE

distcc peut transmettre à distccd un nom de compilateur relatif ou absolu. Si distcc reçoit un nom de fichier de compilateur absolu explicite, ce nom est utilisé tel quel sur le client et le serveur. Si le nom du compilateur n'est pas un chemin absolu, ou si le client est utilisé en mode masquage, alors le PATH du serveur est recherché.

distccd hérite de son chemin de recherche de son processus parent. Par défaut, distccd essaie de supprimer les répertoires qui semblent contenir des liens de masquage distccd, pour se prémunir contre une récursion involontaire. La variable DISTCCD_PATH d'environnement peut être utilisée pour définir le chemin.

Le chemin de recherche est journalisé lorsque --verbose est donné. En cas de doute, vérifiez les journaux.

Lorsque distccd est exécuté via ssh, le fichier $HOME/.ssh/environment peut être utile pour définir le chemin. Voir ssh(1).

DIAGNOSTICS

distccd journalise les messages vers la facilité daemon de syslog par défaut, ce qui écrit normalement vers /var/log/daemon ou /var/log/messages. Les messages du journal peuvent être envoyés vers un autre fichier en utilisant l' option --log-file.

VARIABLES D'ENVIRONNEMENT

DISTCC_CMDLIST
Si la variable d'environnement DISTCC_CMDLIST est définie, charge une liste de commandes prises en charge depuis le fichier nommé par DISTCC_CMDLIST, et refuse de servir toute commande dont les DISTCC_CMDLIST_MATCHWORDS derniers mots ne correspondent pas à ceux d'une commande de cette liste. Voir les commentaires dans src/serve.c.
DISTCC_CMDLIST_NUMWORDS
Le nombre de mots, à partir de la fin de la commande, à comparer. La valeur par défaut est 1.
DISTCCD_PATH
Lors du démarrage de distccd, si cette valeur est définie, elle sera utilisée sans modification pour le PATH d'exécution des commandes. Le code qui essaie normalement de supprimer les répertoires de masquage du chemin est ignoré.
DISTCC_SAVE_TEMPS
Si défini à 1, les fichiers temporaires ne sont pas supprimés après usage.

Notez que DISTCC_LOG n'affecte pas la destination du journal pour le serveur.

DISTCC_TCP_DEFER_ACCEPT
Sur Linux, active l'option de socket TCP_DEFER_ACCEPT. Activé par défaut.
TMPDIR
Répertoire pour les fichiers temporaires tels que la sortie du préprocesseur. Par défaut /tmp/ est utilisé.
DISTCCD_PRINCIPAL
Si défini, spécifie le nom du principal sous lequel distccd s'exécute, et est utilisé pour s'authentifier avec le client. Cette variable d'environnement n'est utilisée que si distccd a été compilé avec l'option de configuration --with-auth et si distccd est exécuté avec l'option --auth.

BOGUES

Le contrôle d'accès basé sur l'IP n'est pas sécurisé contre les attaquants capables de falsifier des connexions TCP, et ne peut pas discriminer les différents utilisateurs sur un client.

Les connexions TCP ne sont pas sécurisées contre les attaquants capables d'observer ou de modifier le trafic réseau.

Parce que ccache ne met pas en cache la compilation à partir de fichiers .i , il n'est pas utile de l'appeler depuis distccd.
