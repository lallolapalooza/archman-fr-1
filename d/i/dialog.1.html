DIALOG() Commandes utilisateur DIALOG()

NOM

dialog - afficher des boîtes de dialogue à partir de scripts shell

SYNTAXE

dialog --clear
dialog --create-rc fichier
dialog --print-maxsize
dialog options-communes options-boite

DESCRIPTION

Dialog est un programme qui permet de présenter une variété de questions ou d'afficher des messages à l'aide de boîtes de dialogue à partir d'un script shell. Ces types de boîtes de dialogue sont implémentés (bien que tous ne soient pas nécessairement compilés dans dialog) :

buildlist, calendar, checklist, dselect, editbox, form, fselect, gauge, infobox, inputbox, inputmenu, menu, mixedform, mixedgauge, msgbox (message), passwordbox, passwordform, pause, prgbox, programbox, progressbox, radiolist, rangebox, tailbox, tailboxbg, textbox, timebox, treeview, et yesno (oui/non).

Vous pouvez mettre plus d'une boîte de dialogue dans un script :

  • Utilisez le jeton « --and-widget » pour forcer dialog à passer à la boîte de dialogue suivante, sauf si vous avez appuyé sur Échap pour annuler, ou
  • Ajoutez simplement les jetons pour la boîte de dialogue suivante, créant une chaîne. Dialog s'arrête de chaîner lorsque le code de retour d'une boîte de dialogue est non nul, par exemple Annuler ou Non (voir DIAGNOSTICS).

Certains widgets, par exemple, checklist, écrivent du texte sur la sortie de dialog. Normalement, c'est la sortie d'erreur standard, mais il existe des options pour changer cela : “--output-fd”, “--stderr” et “--stdout”. Aucun texte n'est écrit si le bouton Annuler (ou Échap) est pressé ; dialog sort immédiatement dans ce cas.

OPTIONS

Toutes les options commencent par “--” (deux tirets ASCII, pour les utilisateurs de systèmes avec un support de locale défectueux).

Un “--” seul est utilisé comme échappement, c'est-à-dire que le jeton suivant sur la ligne de commande n'est pas traité comme une option. Ceci est différent de getopt(1), qui utilise ce jeton pour traiter les jetons restants comme des paramètres plutôt que comme des options.

dialog --title -- --Not an option
dialog --title This -- --title est pas une option

Dialog n'utilise pas de paramètres et utilise son propre analyseur d'*options*.

Lorsqu'une option commune (par exemple, non-widget) est répétée, la dernière trouvée est celle qui est utilisée. Les options booléennes sont gérées spécialement afin qu'elles puissent être annulées, en ajoutant (ou en omettant) un modificateur “no” après le “--” initial. Par exemple, --no-shadow est documenté ici, mais --shadow est également accepté.

L'option “--args” demande à dialog d'afficher les paramètres de la ligne de commande sur la sortie d'erreur standard. Ceci est utile lors du débogage de scripts complexes utilisant “--” et “--file”, car la ligne de commande peut être réécrite lorsque ces derniers sont développés.

L'option “--file” demande à dialog de lire les paramètres depuis le fichier nommé comme valeur.

dialog --file fichierparametre

Les espaces non entourés de guillemets sont ignorés (utilisez des barres obliques inverses pour citer des caractères uniques). Le résultat est inséré dans la ligne de commande, remplaçant “--file” et sa valeur d'option. L'interprétation de la ligne de commande reprend à partir de ce point. Si fichierparametre commence par “&”, dialog interprète le texte suivant comme un numéro de descripteur de fichier plutôt qu'un nom de fichier.

La plupart des widgets acceptent les paramètres de *hauteur* et de *largeur*, qui peuvent être utilisés pour dimensionner automatiquement le widget afin d'accueillir des invites de message multi-lignes :

  • Si le paramètre est négatif, dialog utilise la taille de l'écran.
  • Si le paramètre est zéro, dialog utilise la taille minimale pour que le widget affiche l'*invite* et les données.
  • Sinon, dialog utilise la taille donnée pour le widget.

La plupart des options communes sont réinitialisées avant le traitement de chaque widget.

Plutôt que de dessiner des lignes graphiques autour des boîtes, dessinez des signes « + » et « - » ASCII au même endroit. Voir également “--no-lines”.

Efface l'écran du widget, ne gardant que l'arrière-plan de couleur d'écran. Utilisez ceci lorsque vous combinez des widgets avec « --and-widget » pour effacer le contenu d'un widget précédent à l'écran, afin qu'il ne soit pas visible sous le contenu d'un widget suivant. Comprenez cela comme le complément de « --keep-window ». Pour comparer les effets, utilisez ceux-ci :
Les trois widgets visibles, effet d'escalier, ordonnés 1,2,3 :

    --and-widget               --begin 6 6 --yesno "" 0 0

Inversement, si vous voulez effacer l'écran et envoyer votre curseur en bas à gauche après la sortie du programme dialog, utilisez l'option --erase-on-exit.

--colors
Interprète les séquences “\Z” intégrées dans le texte de la dialogue par le caractère suivant, qui indique à dialog de définir les couleurs ou les attributs vidéo :
  • 0 à 7 sont les numéros de couleur ANSI utilisés dans curses : noir, rouge, vert, jaune, bleu, magenta, cyan et blanc respectivement.
  • Gras est défini par 'b', réinitialisé par 'B'.
  • Inversé est défini par 'r', réinitialisé par 'R'.
  • Souligné est défini par 'u', réinitialisé par 'U'.

  • Restaurez les paramètres normaux avec “\Zn”.

Options d'espacement

Ces options peuvent être utilisées pour transformer les espaces blancs (espace, tabulation, nouvelle ligne) lors de la lecture du script par dialog :

--cr-wrap, --no-collapse, --no-nl-expand, et --trim

Les options ne sont pas indépendantes :

  • Dialog vérifie si le script contient au moins un “\n” et (sauf si --no-nl-expand est défini) ignorera les options --no-collapse et --trim.
  • Après avoir vérifié “\n” et l'option --no-nl-expand, dialog traite l'option --trim.
Si l'option --trim prend effet, alors dialog ignore --no-collapse. Elle transforme les séquences de tabulations, d'espaces (et de nouvelles lignes sauf si -cr-wrap est défini) en un seul espace.
•
Si ni le cas “\n” ni le cas --trim ne s'appliquent, dialog vérifie --no-collapse pour décider s'il faut réduire les séquences de tabulations et d'espaces en un seul espace.
Dans ce cas, dialog ignore --cr-wrap et ne modifie pas les nouvelles lignes.

RACCßIS CLAVIER

Vous pouvez remplacer ou ajouter des raccourcis clavier dans dialog en ajoutant des entrées au fichier de configuration. La commande bindkey de Dialog associe des touches uniques à son codage interne.

bindkey widget touche_curses touche_dialog

Le nom du widget peut être “*” (tous les widgets), ou des widgets spécifiques tels que textbox. Les liaisons de widgets spécifiques remplacent les liaisons “*”. Les liaisons définies par l'utilisateur remplacent les liaisons intégrées.

La touche_curses peut être exprimée sous différentes formes :

  • Il peut s'agir de l'un des noms dérivés de curses.h, par exemple “HELP” à partir de “KEY_HELP”.
  • Dialog reconnaît également les caractères de contrôle ANSI tels que “^A”, “^?”, ainsi que les contrôles C1 tels que “~A” et “~?”.
  • Enfin, dialog autorise les échappements par antislash comme en C. Il peut s'agir de valeurs de caractères octales telles que “\033” (le caractère d'échappement ASCII), ou des caractères listés dans ce tableau :

Liaisons intégrées

Cette page de manuel ne liste pas les raccourcis clavier pour chaque widget, car ces informations détaillées peuvent être obtenues en exécutant dialog. Si vous avez défini l'option --trace, dialog écrit les informations de liaison de touches pour chaque widget au fur et à mesure de son enregistrement.

Quelques liaisons sont intégrées, indépendantes des widgets particuliers :

Touche Objectif
Control-I parcours des champs avant, par exemple avec --tailboxbg.
Control-L repeint l'écran.
Control-T écrit une capture d'écran dans le fichier --trace.
Control-V supprime les touches spéciales pour le prochain octet d'entrée.
DLGK_FIELD_NEXT parcours des champs avant, comme Control-I.
DLGK_FIELD_PREV parcours des champs arrière, comme retour tabulation.
DLGK_HELPFILE affiche le fichier d'aide spécifié avec --hfile.
KEY_BTAB parcours des champs arrière, par exemple avec --tailboxbg.

Exemple

Normalement, dialog utilise des touches différentes pour naviguer entre les boutons et la partie édition d'une boîte de dialogue, par rapport à la navigation à l'intérieur de la partie édition. C'est-à-dire que tabulation (et retour tabulation) parcourt les boutons (ou entre les boutons et la partie édition), tandis que les touches fléchées parcourent les champs à l'intérieur de la partie édition. Les tabulations sont également reconnues comme un cas particulier pour parcourir les widgets, par exemple lors de l'utilisation de plusieurs widgets tailboxbg.

Certains utilisateurs souhaiteront peut-être utiliser la même touche pour parcourir l'intérieur de la partie édition que pour passer d'un bouton à l'autre. Le widget form est écrit pour supporter ce type de redéfinition des touches, en ajoutant un groupe spécial dans dlgk_keys.h pour « form » (gauche/droite/suivant/précédent). Voici un exemple de liaison démontrant comment faire cela :

bindkey formfield TAB  form_NEXT
bindkey formbox   TAB  form_NEXT
bindkey formfield BTAB form_prev
bindkey formbox   BTAB form_prev

Ce type de redéfinition ne serait pas utile dans d'autres widgets, par exemple le calendrier, en raison du nombre potentiellement important de champs à parcourir.

STATUT DE SORTIE

Le statut de sortie est susceptible d'être remplacé par des variables d'environnement. Les valeurs par défaut et les variables d'environnement correspondantes qui peuvent les remplacer sont :

0
si le bouton YES ou OK est pressé (DIALOG_OK).
1
si le bouton No ou Cancel est pressé (DIALOG_CANCEL).
2
si le bouton Help est pressé (DIALOG_HELP),
sauf indication contraire ci-dessous concernant DIALOG_ITEM_HELP.
3
si le bouton Extra est pressé (DIALOG_EXTRA).
4
si le bouton Help est pressé,
et que l'option --item-help est définie
et que la variable d'environnement DIALOG_ITEM_HELP est définie à 4.
Bien que tous les codes de sortie puissent être remplacés par des variables d'environnement, ce cas particulier a été introduit en 2004 pour simplifier la compatibilité. Dialog utilise DIALOG_ITEM_HELP (4) en interne, mais à moins que la variable d'environnement ne soit également définie, elle la transforme en DIALOG_HELP (2) à la sortie.
5
si un délai d'attente expire et que la variable DIALOG_TIMEOUT est définie à 5.
-1
en cas d'erreurs à l'intérieur de dialog (DIALOG_ERROR) ou si dialog se termine car la touche ESC (DIALOG_ESC) a été pressée.
