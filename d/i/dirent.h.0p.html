dirent.h(0P) Manuel du programmeur POSIX dirent.h(0P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

dirent.h — format des entrées de répertoire

SYNTAXE

#include <dirent.h>

DESCRIPTION

Le format interne des répertoires n'est pas spécifié.

L'en-tête <dirent.h> définira le type suivant :

DIR
Un type représentant un flux de répertoire. Le type DIR peut être un type incomplet.

Il définira également la structure dirent qui inclura les membres suivants :

ino_t  d_ino       Numéro de série du fichier.
char   d_name[]    Chaîne de nom de fichier de l'entrée.

L'en-tête <dirent.h> définira le type ino_t tel que décrit dans <sys/types.h>.

Le tableau d_name est de taille non spécifiée, mais contiendra un nom de fichier d'au plus {NAME_MAX} octets suivi d'un octet nul de terminaison.

Les éléments suivants seront déclarés comme fonctions et pourront également être définis comme macros. Les prototypes de fonctions seront fournis.

int            alphasort(const struct dirent **, const struct dirent **);
int            closedir(DIR *);
int            dirfd(DIR *);
DIR           *fdopendir(int);
DIR           *opendir(const char *);
struct dirent *readdir(DIR *);
int            readdir_r(DIR *restrict, struct dirent *restrict,
                   struct dirent **restrict);
void           rewinddir(DIR *);
int            scandir(const char *, struct dirent ***,
                   int (*)(const struct dirent *),
                   int (*)(const struct dirent **,
                   const struct dirent **));
void           seekdir(DIR *, long);
long           telldir(DIR *);

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICATION

Aucune.

RATIONNEL

Des informations similaires à celles de l'en-tête <dirent.h> sont contenues dans un fichier <sys/dir.h> dans 4.2 BSD et 4.3 BSD. L'équivalent dans ces implémentations de struct dirent de ce volume de POSIX.1‐2017 est struct direct. Le nom du fichier a été modifié car le nom <sys/dir.h> était également utilisé dans les implémentations précédentes pour faire référence à des définitions liées à l'ancienne méthode d'accès ; cela produisait des conflits de noms. Le nom de la structure a été modifié car ce volume de POSIX.1‐2017 ne définit pas complètement ce qui se trouve dans la structure, de sorte qu'elle pourrait être différente dans certaines implémentations de struct direct.

Le nom d'un tableau de char de taille non spécifiée ne doit pas être utilisé comme lvalue. L'utilisation de :

sizeof(d_name)

est incorrecte ; utilisez :

strlen(d_name)

à la place.

Le tableau de char d_name n'est pas de taille fixe. Les implémentations peuvent avoir besoin de déclarer struct dirent avec une taille de tableau de 1 pour d_name, mais le nombre réel d'octets fournis correspond (ou dépasse légèrement) la longueur de la chaîne du nom de fichier.
