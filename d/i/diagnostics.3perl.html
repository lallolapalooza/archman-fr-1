diagnostics(3perl) Guide de référence des programmeurs Perl diagnostics(3perl)

NOM

diagnostics, splain - produire des diagnostics d'avertissement détaillés

SYNOPSIS

Utiliser la pragme "diagnostics" :

use diagnostics;
use diagnostics -verbose;
diagnostics->enable;
diagnostics->disable;

Utiliser le programme de filtrage autonome "splain" :

perl program 2>diag.out
splain [-v] [-p] diag.out

Utiliser diagnostics pour obtenir des traces d'appels d'un script défaillant :

perl -Mdiagnostics=-traceonly my_script.pl

DESCRIPTION

La pragme "diagnostics"

Ce module étend les diagnostics concis normalement émis à la fois par le compilateur perl et l'interpréteur perl (en exécutant perl avec l'option -w ou "use warnings"), en les augmentant des descriptions plus explicatives et plus engageantes trouvées dans perldiag. Comme les autres pragmes, il affecte la phase de compilation de votre programme plutôt que simplement la phase d'exécution.

Pour l'utiliser dans votre programme comme une pragme, invoquez

use diagnostics;

au début (ou près du début) de votre programme. (Notez que cela active l'option -w de perl.) Toute votre compilation sera alors soumise (soumise :-) aux diagnostics améliorés. Ceux-ci sont toujours émis sur STDERR.

En raison de l'interaction entre les problèmes d'exécution et de compilation, et parce que ce n'est probablement pas une très bonne idée de toute façon, vous ne pouvez pas utiliser "no diagnostics" pour les désactiver au moment de la compilation. Cependant, vous pouvez contrôler leur comportement à l'exécution en utilisant les méthodes disable() et enable() pour les désactiver et les activer respectivement.

L'option -verbose imprime d'abord l'introduction de perldiag avant tout autre diagnostic. La variable $diagnostics::PRETTY peut générer de plus jolies séquences d'échappement pour les paginateurs.

Les avertissements émis par perl lui-même (ou plus précisément, ceux qui correspondent aux descriptions trouvées dans perldiag) ne sont affichés qu'une seule fois (pas de descriptions en double). Les avertissements générés par le code utilisateur à la manière de warn() ne sont pas affectés, permettant l'affichage de messages utilisateur en double.

Ce module ajoute également une trace d'appels au message d'erreur quand perl meurt. C'est utile pour déterminer ce qui a causé la mort. L'option -traceonly (ou simplement -t) désactive les explications des messages d'avertissement en ne laissant que les traces d'appels. Donc si votre script est en train de mourir, relancez-le avec

perl -Mdiagnostics=-traceonly my_bad_script

pour voir la pile d'appels au moment de la mort. En fournissant l'option -warntrace (ou simplement -w), tout avertissement émis sera également accompagné d'une trace d'appels.

Le programme splain

Un autre programme, splain est en fait rien de plus qu'un lien vers le module (exécutable) diagnostics.pm , ainsi qu'un lien vers la documentation diagnostics.pod . L'option -v est comme la directive "use diagnostics -verbose" . L'option -p est comme la variable $diagnostics::PRETTY . Puisque vous post-traitez avec splain, il n'y a pas de raison de pouvoir enable() ou disable() le traitement.

La sortie de splain est dirigée vers STDOUT, contrairement à la pragme.

EXEMPLES

Le fichier suivant déclenchera certainement quelques erreurs à la fois à l'exécution et à la compilation :

use diagnostics;
print NOWHERE "nothing\n";
print STDERR "\n\tThis message should be unadorned.\n";
warn "\tThis is a user warning";
print "\nDIAGNOSTIC TESTER: Please enter a <CR> here: ";
my $a, $b = scalar <STDIN>;
print "\n";
print $x/$y;

Si vous préférez exécuter votre programme d'abord et examiner ses problèmes ensuite, faites ceci :

perl -w test.pl 2>test.out
./splain < test.out

Notez que ce n'est généralement pas possible dans les shells d'origine plus douteuse, car théoriquement

(perl -w test.pl >/dev/tty) >& test.out
./splain < test.out

Parce que vous venez de déplacer le stdout existant ailleurs.

Si vous ne voulez pas modifier votre code source, mais voulez toujours des avertissements en temps réel, faites ceci :

exec 3>& perl -w test.pl 2>&1 1>&3 3>&- | splain 1>&2 3>&-

Astucieux, n'est-ce pas ?

Si vous voulez contrôler les avertissements en temps réel, faites quelque chose comme ceci. Assurez-vous de faire le "use" d'abord, ou vous ne pourrez pas accéder aux méthodes enable() ou disable() .

use diagnostics; # checks entire compilation phase 
    print "\ntime for 1st bogus diags: SQUAWKINGS\n";
    print BOGUS1 'nada';
    print "done with 1st bogus\n";
diagnostics->disable; # only turns off runtime warnings
    print "\ntime for 2nd bogus: (squelched)\n";
    print BOGUS2 'nada';
    print "done with 2nd bogus\n";
diagnostics->enable; # turns back on runtime warnings
    print "\ntime for 3rd bogus: SQUAWKINGS\n";
    print BOGUS3 'nada';
    print "done with 3rd bogus\n";
diagnostics->disable;
    print "\ntime for 4th bogus: (squelched)\n";
    print BOGUS4 'nada';
    print "done with 4th bogus\n";

DÉTAILS INTERNES

Les messages de diagnostic proviennent du fichier perldiag.pod lorsqu'il est disponible à l'exécution. Sinon, ils peuvent être intégrés dans le fichier lui-même lorsque le paquet splain est construit. Voir le Makefile pour les détails.

Si un gestionnaire $SIG{__WARN__} existant est découvert, il continuera d'être honoré, mais seulement après que la fonction diagnostics::splainthis() (l'intercepteur $SIG{__WARN__} du module) ait eu son effet sur vos avertissements.

Il existe une variable $diagnostics::DEBUG que vous pouvez définir si vous êtes désespérément curieux de savoir quels types de choses sont interceptés.

BEGIN { $diagnostics::DEBUG = 1 }

BUGS

Ne pas pouvoir dire "no diagnostics" est ennuyeux, mais peut ne pas être insurmontable.

La directive "-pretty" est appelée trop tard pour affecter les choses. Vous devez faire ceci à la place, et avant de charger le module.

BEGIN { $diagnostics::PRETTY = 1 }

Je pourrais démarrer plus vite en retardant la compilation jusqu'à ce qu'elle soit nécessaire, mais cela donne un "panic: top_level" lors de l'utilisation de la forme pragme dans Perl 5.001e.

Bien que cette documentation soit quelque peu peu sérieuse, si vous utilisez un programme nommé splain, vous devriez vous attendre à un peu de fantaisie.
