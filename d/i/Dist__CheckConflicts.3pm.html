NOM

Dist::CheckConflicts - déclarer les conflits de version pour votre dist

VERSION

version 0.11

SYNOPSIS

use Dist::CheckConflicts
    -dist => 'Class-MOP',
    -conflicts => {
        'Moose'                => '1.14',
        'namespace::autoclean' => '0.08',
    },
    -also => [
        'Package::Stash::Conflicts',
    ];
__PACKAGE__->check_conflicts;

DESCRIPTION

Un inconvénient des clients CPAN existants actuellement est qu'ils n'ont aucun moyen de spécifier des dépendances en aval conflictuelles pour les modules. Ce module tente de contourner ce problème en vous permettant de spécifier des versions conflictuelles de modules séparément, et de les traiter après que le module ait terminé son installation.

Par exemple, disons que vous avez un module "Foo", et qu'un autre module "Bar" utilise "Foo". Si "Foo" devait changer son API de manière non rétrocompatible, cela causerait "Bar" à cesser de fonctionner jusqu'à ce qu'il soit mis à jour pour utiliser la nouvelle API. "Foo" ne peut pas simplement dépendre de la version corrigée de "Bar", car cela causerait une dépendance circulaire (parce que "Bar" dépend déjà de "Foo"), et cela n'exprime pas l'intention correctement de toute façon - "Foo" n'utilise pas "Bar" du tout. La solution idéale serait qu'il existe un moyen de spécifier des versions conflictuelles de modules d'une manière qui permettrait aux clients CPAN de mettre à jour automatiquement les modules conflictuels après qu'un module existant soit mis à jour, mais jusqu'à ce que cela arrive, ce module permettra aux utilisateurs de faire cela manuellement.

Ce module accepte un hash d'options passé à son "use" statement, avec ces clés étant valides:

-conflicts
Un hashref de spécifications de conflit, où les clés sont des noms de modules, et les valeurs sont la dernière version cassée - toute version supérieure à la version spécifiée devrait fonctionner.
-also
Modules supplémentaires pour obtenir des conflits de (potentiellement récursivement). Cela devrait généralement être une liste de modules qui utilisent Dist::CheckConflicts, qui correspondent aux dists dont votre dist dépend. (Dans un monde idéal, cela serait déduit directement de votre liste de dépendances, mais la liste de dépendances n'est pas disponible en dehors du temps de build).
-dist
Le nom de la distribution, pour rendre le message d'erreur de check_conflicts plus convivial pour l'utilisateur.

Les méthodes listées ci-dessous sont exportées par ce module dans le module qui l'utilise, vous devriez donc appeler ces méthodes sur votre module, et non sur Dist::CheckConflicts.

Par exemple, cette ligne de commande peut être utilisée pour mettre à jour vos modules, après avoir installé la "Foo" dist (en supposant que "Foo::Conflicts" est le module dans la "Foo" dist qui utilise Dist::CheckConflicts):

perl -MFoo::Conflicts -e'print "$_\n"
    for map { $_->{package} } Foo::Conflicts->calculate_conflicts' | cpanm

En bonus, le chargement de votre module de conflits fournira des avertissements à l'exécution si des modules conflictuels sont détectés (indépendamment de s'ils sont chargés avant ou après).

MÉTHODES

conflicts

Retourne la spécification de conflit (le "-conflicts" paramètre à import()), en tant que hash.

dist

Retourne le nom du dist (soit tel que spécifié par le "-dist" paramètre à import(), soit le nom du paquet qui a "use"d ce module).

check_conflicts

Examine les modules actuellement installés, et lance une exception avec des informations utiles si certains modules sont à des versions qui entrent en conflit avec le dist.

calculate_conflicts

Examine les modules actuellement installés, et retourne une liste de modules qui entrent en conflit avec le dist. Les modules seront retournés en tant que liste de hashrefs, chacun contenant les clés "package", "installed", et "required" .
