DESCRIPTIO

N

digitaglinktree créera un arbre de liens pour toutes les photos d'une base de données digikam qui ont des tags définis. Les tags (comme par exemple « famille », « événements », ...) sont utilisés dans digikam pour créer des dossiers virtuels contenant des images qui ont toutes un ou plusieurs tags assignés. Veuillez noter : les photos qui n'ont aucun tag assigné sont ignorées silencieusement par ce script. Le programme ne modifiera pas ni ne touchera vos photos originales gérées par

digikam.

Le script peut être utilisé de deux manières : si vous l'appelez avec l'option -l taglinkdir, le script créera le répertoire spécifié par l'utilisateur taglinkdir et, à l'intérieur de ce répertoire, il créera des sous-répertoires pour les tags digikam définis sur les photos. À l'intérieur de ces sous-répertoires, il placera finalement des liens symboliques ou physiques (voir -H) vers les photos ayant les tags en question. En résultat, vous verrez les tags de vos photos sous forme de dossiers et, dans ces dossiers, vous trouverez des liens vers vos photos

originales.

De cette façon, vous pouvez accéder à la collection de toutes les images partageant un tag donné en changeant de répertoire vers le dossier portant le nom du tag créé par ce script. Cela vous permet par exemple d'exécuter JAlbum, un logiciel d'album photo qui a besoin de trouver les images à mettre dans un album web dans le système de fichiers, car JAlbum ne peut pas accéder directement aux dossiers virtuels de

digikam.

La deuxième façon d'appeler ce script est le mode archive en définissant l'option -A archiveDir

.

Le mode archive est pensé pour les personnes qui veulent archiver des photos taguées indépendamment des répertoires racines de digikam et des photos qui s'y trouvent. De cette façon, vous pouvez mettre vos photos et leur structure de tags dans par exemple une archive tar et l'envoyer à un ami, qui pourra regarder les photos via leur structure de tags. Dans ce mode, le script crée le répertoire donné en paramètre à -A et, dans ce répertoire, deux sous-répertoires de plus. L'un nommé Photos et un second nommé Tags. Le répertoire Photos contient des liens physiques vers vos photos originales, et le répertoire Tags contient un sous-répertoire pour chaque tag utilisé par l'une de vos photos. À l'intérieur de ce sous-répertoire, il y a des liens (soit symboliques, soit physiques) vers les fichiers du répertoire Photos. De cette façon, le répertoire d'archive n'a presque besoin d'aucun espace supplémentaire sur votre disque dur et vous avez une archive qui permet à vous ou à un ami de regarder facilement la structure de tags des

photos.

Un autre avantage de l'utilisation de ce script est que vous avez une sorte de sauvegarde de vos paramètres de tags pour toute

s vos photos. La sauvegarde est simplement la structure de répertoires contenant des liens vers les images originales qui porte
nt les tags. Cela pourrait devenir important si, pour une raison quelconque, le fichier digikam.db est corrompu ou même perdu.

OPTIONS DE LIGNE DE

COMMANDE
-l taglinkd
ir
Paramètre taglinkdir désigne un répertoire dans lequel la structure de tags de toutes vos photos stockées dans rootdir sera exportée en créant des sous-répertoires pour chaque tag et en y plaçant des liens symboliques pointant vers les photos originales portant les tags. Si vous appelez le script avec l'option -l taglinkDir, vous devez également spécifier les options -r rootdir ainsi que -d database
.
-A archivedirect
ory
archivedirectory désigne un répertoire dans lequel le script exportera les photos et leur structure de tags. -A doit être utilisé avec l'option -r rootdir si vous utilisez digikam version < 0.10, ainsi que database, sinon le script se terminera. À l'intérieur du répertoire d'archive, le script créera un répertoire Photos et un répertoire Tags. Il placera des liens physiques dans le répertoire Photos pointant vers vos photos originales. En utilisant des liens physiques, vous êtes indépendant des changements dans votre répertoire racine digikam, mais d'un autre côté vous êtes limité à un seul système de fichiers. Ainsi, le répertoire donné par -r rootdir et le répertoire spécifié pour -A archivedir doivent être sur le même système de fichiers. Si vous utilisez digikam en version >= 0.10, vous ne pouvez pas spécifier -r rootdir. À la place, les chemins racines de tous les albums sont directement extraits de la base de données de digikam. Cependant, l'exigence reste que archivedir doit être sur le même système de fichiers que tous les répertoires racines contenant les photos que vous avez définies dans digikam. Si l'un des répertoires racines de digikam est sur un autre système de fichiers, celui-ci ne sera pas traité, car le lien physique des photos à l'intérieur du répertoire Photos ne fonctionnerait pas dans ce cas ! Le sous-répertoire Tags contiendra des liens vers les fichiers du répertoire Photos. De cette façon, vous avez un répertoire d'archive entièrement autonome. Vous pouvez le compresser avec tar, l'envoyer à un ami ou simplement le mettre quelque part pour archivage ou sauvegarde. Habituellement, seules les photos ayant un tag digikam défini seront archivées. Cependant, en utilisant l'option -C, vous pouvez effectuer une archive complète. Voir -C pour plus
d'informations.
-d databa
se
database est le chemin complet incluant le nom du fichier vers la base de données photo de digikam, qui se trouve généralement dans le répertoire racine de digikam. Le nom du fichier est généralement digikam.
db.
-r rootd
ir
rootdir désigne le répertoire de base de digikam contenant toutes vos photos si vous utilisez digikam dans une version antérieure à 0.10. Si vous utilisez digikam 0.10 ou plus récent, vous ne devez pas utiliser cette option. Si vous le faites quand même, vous verrez un avertissement indiquant que l'option donnée sera ignorée car la base de données de digikam version 0.10 contient les répertoires racines de tous les albums définis dans
digikam.
-
C
Lorsque le script est appelé avec l'option -A archivedir, seules les photos ayant au moins un tag digikam défini seront archivées (en plaçant des liens) dans le sous-répertoire Photos de archivedir. En définissant l'option -C, toutes les photos seront archivées dans archivedir, qu'elles aient un tag défini ou non. Note : cela ne change que le contenu du sous-répertoire Photos, pas celui du sous-répertoire Tags dans le répertoire archivedir
.
-
a
Par défaut, le script essaiera de créer des liens symboliques relatifs depuis le répertoire taglinkdir défini par l'option -l vers les fichiers photo sous rootdir donné par l'option -r. L'utilisation de cette option entraînera la création de liens symboliques absolus au lieu de
relatifs.
-
H
Par défaut, le script créera des liens souples (symboliques) de l'arbre de tags vers les photos. En définissant l'option -H, le script utilisera des liens physiques à la place. Veuillez noter que les liens physiques ne peuvent être créés qu'à l'intérieur d'un seul système de fichiers. Ainsi, vos photos et l'arbre de tags doivent être sur le même système de fichiers. Sinon, vous verrez un avertissement à ce sujet et le script ne s'exécutera
pas.
-
f
Dans digikam, les photos peuvent avoir des tags hiérarchiques (des tags qui ont des sous-tags). Dans ce cas, digitaglinktree ajouterait par défaut un répertoire pour le tag et un sous-répertoire pour chacun des sous-tags de ce tag. En définissant -f, un sous-tag est traité comme un tag régulier, tout comme son tag parent, de sorte que digitaglinktree créera tous les sous-répertoires pour les tags et sous-tags au même niveau, indépendamment de la hiérarchie tag -
sous-tag.
-
Y
Créer un répertoire d'année sous chaque répertoire de tag. L'information d'année est prise de « Date de prise de vue » dans la base de
données.
-i tag1,..,
tagn
tag1,..,tagn Inclure uniquement les images avec les tags de la liste. Utiliser la virgule comme séparateur de tags. La valeur par défaut est « none ». Utiliser « all » pour inclure tous les tags à la fois si vous le voulez vraiment. Mieux vaut essayer d'abord une liste avec seulement quelques tags pour voir combien de temps cela prend à se
terminer.
-e tag1,..,
tagn
tag1,..,tagn Exclure les images avec les tags de la liste. Utiliser la virgule comme séparateur de tags. La valeur par défaut est « none
».
-M level_numb
er
level_number spécifie le nombre de niveaux de répertoire. -M spécifie que, au lieu de suivre la hiérarchie normale des balises, il crée une hiérarchie combinant différentes balises ensemble et pas seulement au sein d'une seule hiérarchie de balises (par exemple en combinant les balises Lieux et Personnes). Vous devez ajouter des balises à inclure en utilisant l'option -i (voir ci-dessus). Selon le niveau donné et le nombre de balises que vous avez incluses et combien de photos vous gérez avec digikam, cette option peut prendre un temps considérable (possiblement plus d'une heure) pour se terminer ! un niveau_number de "5" semble être le niveau raisonnable maximum pour commencer dans ce mode. Les options -A -C -a -H -f n'ont pas été testées avec cette option
!

verbeux.

CONFIGURATIO

N

Par défaut, ce script s'exécutera avec toutes les bases de données de photos créées par digikam version 0.10 ainsi que les versions plus anciennes comme 0.9 et 0.8. Si vous avez encore digikam version 0.7, vous devez reconfigurer le script

lui-même.

Vous devez reconfigurer le script en définissant le chemin vers le binaire sqlite utilisé par le script pour interroger la base de données digikam digikam.db. Puisque les très anciennes versions de digikam utilisent sqlite en version 2, mais les versions ultérieures de digikam nécessitent sqlite version 3, vous devez veiller à installer la version correcte de sqlite pour la version de digikam installée et à définir le chemin vers l'exécutable sqlite correct dans l'en-tête des scripts

:

Choisisse

z

$SQLITE="/usr/bin/sqlite3"

;

pour digikam version 0.8x et 0.9x et 0.

10x

$SQLITE="/usr/bin/sqlite"

;

pour digi

kam vers
ion 0.7x.

EXEMPL

E

Un appel à digitaglinktree est montré ci-dessous

:

digiTagLinktree -l /home/user/tags
-d /home/user/photos/digikam.

db

Dans cet exemple, nous supposons que vous exécutez digikam version 0.10 ou supérieure, de sorte qu'aucune option -r n'a été utilisée pour spécifier le répertoire racine des photos. À la place, cette information sera automatiquement récupérée depuis la base de données de

digikam.

Si vous souhaitez exécuter le script sur une base de données digikam qui a été créée par digikam version 0.9 ou antérieure, vous devez utiliser -r pour spécifier le répertoire racine où vous conservez toutes vos photos gérées par digikam

:

digiTagLinktree -l /home/user/tags
-d /home/user/photos/digikam.

db

Dans cet exemple, la racine des photos de digikam indiquée par -r est /home/user/photos

.

L'option -l /home/user/tags indique au script que tous les sous-répertoires et liens symboliques seront placés dans le répertoire /home/user/tags. Le dossier a été choisi de sorte que le répertoire des tags ne se trouve pas sous la racine des photos de digikam. Vous pouvez mettre le dossier des tags à l'intérieur de la racine des photos de digikam mais ce n'est pas la méthode préférée. Parce que le répertoire de liens ne contient que des liens, cette structure de tags n'a pratiquement besoin d'aucun espace supplémentaire sur votre disque

dur.

digiTagLinktree -r /home/user/photos -l /home/user/tags -d /home/user/photos/digikam.db
-i People,Place
-M 2
-

Y

Dans cet exemple, si vous avez une image avec les balises People/me, Place/home de 1970, elle créera le répertoire suivant (lien vers l'image sous le répertoire

_all)

/

/

/home/user/tags/Date/1970/Place/home/_all

/

/home/user/tags/Date/1970/Place/home/People/me/_all

/

idem en commençant par /Place ... idem en commençant par /People .
