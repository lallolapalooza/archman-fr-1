Devel::SelfStubber(3perl) Guide du programmeur Perl Devel::SelfStubber(3perl)

NOM

Devel::SelfStubber - générer des stubs pour un module SelfLoading

SYNTAXE

Pour générer uniquement les stubs :

use Devel::SelfStubber;
Devel::SelfStubber->stub('NOM_DU_MODULE','CHEMIN_BIB_PERSO');

ou pour générer le module entier avec les stubs insérés correctement

use Devel::SelfStubber;
$Devel::SelfStubber::JUST_STUBS=0;
Devel::SelfStubber->stub('NOM_DU_MODULE','CHEMIN_BIB_PERSO');

NOM_DU_MODULE est le nom du module Perl, par ex. Devel::SelfStubber, PAS 'Devel/SelfStubber' ou 'Devel/SelfStubber.pm'.

CHEMIN_BIB_PERSO vaut '.' par défaut s'il n'est pas présent.

DESCRIPTION

Devel::SelfStubber imprime les stubs que vous devez placer dans le module avant le jeton __DATA__ (ou il peut imprimer le module entier avec les stubs correctement placés). Les stubs garantissent que si une méthode est appelée, elle sera chargée. Ils sont spécifiquement nécessaires pour les méthodes héritées autoloadées.

Ceci est mieux expliqué par l'exemple suivant :

Supposons quatre classes, A, B, C & D.

A est la classe racine, B est une sous-classe de A, C est une sous-classe de B, et D est une autre sous-classe de A.

    A
   / \
  B   D
 /
C

Si D appelle une méthode autoloadée 'foo' qui est définie dans la classe A, alors la méthode est chargée dans la classe A, puis exécutée. Si C appelle ensuite la méthode 'foo', et que cette méthode a été réimplémentée dans la classe B, mais définie comme autoloadable, alors le mécanisme de recherche n'atteint jamais le mécanisme AUTOLOAD dans B car il trouve d'abord la méthode déjà chargée dans A, et l'utilise donc par erreur. Si la méthode foo avait été stubbée dans B, alors le mécanisme de recherche aurait trouvé le stub, et chargé et utilisé correctement la sous-routine de B.

Ainsi, pour que les classes et sous-classes aient un héritage correctement fonctionnel avec l'autoloading, vous devez vous assurer que les stubs sont chargés.

Le SelfLoader peut charger automatiquement les stubs lors de l'initialisation du module avec l'instruction 'SelfLoader->load_stubs();', mais vous pourriez souhaiter éviter la surcharge de chargement de stub associée à votre initialisation (bien que notez que la méthode SelfLoader::load_stubs sera appelée tôt ou tard - au plus tard lorsque la première sous-routine sera en cours d'autoloading). Dans ce cas, vous pouvez placer les stubs de sous-routines avant le jeton __DATA__. Ceci peut être fait manuellement, mais ce module permet la génération automatique des stubs.

Par défaut, il imprime simplement les stubs, mais vous pouvez régler la variable globale $Devel::SelfStubber::JUST_STUBS à 0 et il imprimera le module entier avec les stubs positionnés correctement.

Au minimum, ceci est utile pour voir ce que le SelfLoader considère comme des stubs - afin de s'assurer que les futures versions du SelfStubber restent synchronisées avec le SelfLoader, le SelfStubber utilise en fait le SelfLoader pour déterminer quels stubs sont nécessaires.
