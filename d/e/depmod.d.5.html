NOM

depmod.d - Répertoire de configuration pour depmod

SYNTAXE

/etc/depmod.d/*.conf

/run/depmod.d/*.conf

/usr/local/lib/depmod.d/*.conf

/usr/lib/depmod.d/*.conf

/lib/depmod.d/*.conf

DESCRIPTION

Lors de son exécution, depmod lit les fichiers de configuration des emplacements ci-dessus et, en fonction de ceux-ci, traite les modules disponibles et leurs dépendances. Par exemple, on peut modifier l'ordre de recherche, exclure des dossiers, remplacer l'emplacement de modules spécifiques, et plus encore.

Ceci est généralement utile dans les cas où les modules intégrés au noyau sont complétés par des versions personnalisées du même module et que l'utilisateur souhaite affecter la priorité de traitement afin de remplacer la version du module fournie par le noyau.

FORMAT DE CONFIGURATION

Les fichiers de configuration contiennent une commande par ligne, les lignes vides et celles commençant par '#' étant ignorées (utile pour ajouter des commentaires). Un '\' à la fin d'une ligne provoque sa continuation sur la ligne suivante, ce qui rend les fichiers un peu plus nets.

Voir la section COMMANDES ci-dessous pour plus de détails.

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

Les fichiers de configuration sont lus depuis les répertoires listés dans la SYNTAXE, selon l'ordre de précédence indiqué. Une fois qu'un fichier d'un nom donné est chargé, tout fichier du même nom dans les répertoires ultérieurs est ignoré.

Tous les fichiers de configuration sont triés par ordre lexicographique, indépendamment du répertoire dans lequel ils résident. Les fichiers de configuration peuvent soit être complètement remplacés (en ayant un nouveau fichier de configuration du même nom dans un répertoire de plus haute priorité) soit partiellement remplacés (en ayant un fichier de configuration qui est ordonné plus tard).

COMMANDES

search sous-répertoire...

Ceci vous permet de spécifier l'ordre dans lequel les sous-répertoires de /lib/modules (ou tout autre emplacement de module configuré) seront traités par depmod. Les répertoires sont listés dans l'ordre, la priorité la plus élevée étant attribuée au premier répertoire listé et la priorité la plus basse au dernier répertoire listé. Le mot-clé spécial built-in fait référence aux répertoires de modules standards installés par le noyau. Un autre mot-clé spécial, external, fait référence à la liste des répertoires externes, définie par la commande external.

Par défaut, depmod accorde une priorité plus élevée à un répertoire nommé updates en utilisant cette chaîne de recherche intégrée : "updates built-in", mais des arrangements plus complexes sont possibles et sont utilisés dans plusieurs distributions populaires.

override nom_module version_noyau sous-répertoire_modules

Cette commande permet de remplacer quelle version d'un module spécifique sera utilisée lorsque plus d'un module portant le même nom est traité par la commande depmod. Il est possible de spécifier un noyau ou tous les noyaux en utilisant le caractère générique *. sous-répertoire_modules est le nom du sous-répertoire sous /lib/modules (ou un autre emplacement de module) où le module cible est installé.

Par exemple, il est possible de remplacer la priorité d'un module de test mis à jour appelé kmod en spécifiant la commande suivante : "override kmod * extra". Cela garantira que tout nom de module correspondant installé sous le sous-répertoire extra dans /lib/modules (ou un autre emplacement de module) aura la priorité sur tout module de nom similaire déjà fourni par le noyau.

external version_noyau répertoire_absolu_modules...

Ceci spécifie une liste de répertoires qui seront vérifiés selon les priorités dans la commande search. L'ordre est également important, le premier répertoire ayant la priorité la plus élevée.

Le version_noyau est une expression régulière POSIX ou un caractère générique *, comme dans override.

exclude répertoire_exclu

Ceci spécifie les répertoires terminaux qui seront exclus lors de la recherche des modules du noyau.

Le répertoire_exclu est le répertoire terminal à exclure.
