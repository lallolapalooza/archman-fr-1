DEJAGNU-REPORT-CARD(1) Manuel des commandes générales (urm) DEJAGNU-REPORT-CARD(1)

NOM

dejagnu report card — résumer les résultats des tests de plusieurs outils

SYNTAXE

dejagnu report card [⟨option⟩ | ⟨outil⟩ | ⟨fichier⟩] ...

DESCRIPTION

La commande dejagnu report card affiche les résultats des tests de plusieurs outils dans un format tabulaire. Le tableau produit liste, pour chaque outil (et si plusieurs passes ont été exécutées, chaque passe) le nombre de tests réussis, échoués, non supportés, non résolus et non testés. Les tests qui doivent échouer sont comptés dans des colonnes séparées des tests qui doivent réussir, mais les échecs « connus » et les échecs « attendus » sont résumés ensemble. Si un test a généré des avertissements ou des erreurs, une étiquette ‘!W!’ ou ‘!E!’ est ajoutée à la fin de la ligne pertinente.

Outre les options, la liste des arguments peut inclure des noms d'outils ou de fichiers. La commande dejagnu report card préfère lire les fichiers résumés de DejaGnu et traduira les noms en conséquence :

*.sum
Utilisé tel quel.
*.log
Réécrit en *.sum avec la même racine.
*.
La chaîne sum est ajoutée pour sélectionner un fichier résumé. Ce traitement est effectué pour plus de commodité lors de l'utilisation de la complétion de noms de fichiers Readline dans un shell, qui complètera jusqu'au point.
*
Pris comme nom d'outil ; .sum est ajouté.

OPTIONS

-v, --verbose
Émet des sorties supplémentaires décrivant le fonctionnement de dejagnu report card lui-même.

FICHIERS

La commande dejagnu report card produit sa sortie en lisant les fichiers résumés produits par DejaGnu et en comptant « PASS », « FAIL », etc.

Si aucun nom n'est donné en argument, tous les fichiers correspondant à *.sum dans le répertoire courant sont lus.

EXEMPLES

Un exemple simple de la propre suite de tests de DejaGnu

$ dejagnu report card
             __________________________________________________
            /    PASS   FAIL  ?PASS  ?FAIL  UNSUP  UNRES UNTEST
            |--------------------------------------------------
  launcher  |      52      0      0      0      0      0      0
libdejagnu  |       5      0      0      0      0      0      0
   runtest  |     135      0      0      0      0      0      0
            |--------------------------------------------------
            |     192      0      0      0      0      0      0
            \__________________________________________________

Trois outils ont été testés, avec un total de 192 tests, tous devant réussir. Dans cet exemple, tous les tests ont réussi, donc toutes les autres colonnes sont à zéro. Les colonnes « ‘?PASS’ » et « ‘?FAIL’ » comptent les tests connus ou attendus d'échouer qui ont soit réussi de manière inattendue, soit échoué comme prévu. Les trois colonnes restantes comptent les résultats exceptionnels pour les tests non supportés, les tests non résolus et les tests fantoches qui se déclarent simplement comme non testés.

Le même exemple après l'ajout de tests pour dejagnu-report-card

$ dejagnu report-card
                    __________________________________________________
                   /    PASS   FAIL  ?PASS  ?FAIL  UNSUP  UNRES UNTEST
                   |--------------------------------------------------
   launcher        |      52      0      0      0      0      0      0
 libdejagnu        |       5      0      0      0      0      0      0
report-card / awk  |      36      0      0      0      0      0      0
report-card / sh   |      36      0      0      0      0      0      0
report-card / tcl  |      36      0      0      0      0      0      0
    runtest        |     135      0      0      0      0      0      0
                   |--------------------------------------------------
              awk  |      36      0      0      0      0      0      0
              sh   |      36      0      0      0      0      0      0
              tcl  |      36      0      0      0      0      0      0
                   |--------------------------------------------------
                   |     300      0      0      0      0      0      0
                   \__________________________________________________

L'outil ‘report-card’ a été ajouté, avec trois passes, une pour chaque implémentation. (Les implémentations shell et Tcl ont été supprimées plus tard pour réduire la charge de maintenance future.) Comme précédemment, tous les tests ont réussi comme prévu. La différence intéressante par rapport à l'exemple précédent est l'utilisation de la fonctionnalité de test multipasse de DejaGnu et l'ajout des lignes de résumé par passe. Pour cet exemple, seul l'outil ‘report-card’ utilise le test multipasse, donc chaque total de passe est simplement le nombre de tests pour ‘report-card’ au lieu d'un total distinct.

Notez également que la commande utilisée pour invoquer dejagnu report card est légèrement différente ici. Le lanceur dejagnu(1) acceptera également plusieurs mots joints par des tirets en un seul argument. Cela permet aux mots individuels d'un nom de commande d'être séparés par des tirets ou des espaces sur la ligne de commande de manière interchangeable.
