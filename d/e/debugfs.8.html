DESCRIPTIO

N

Le programme debugfs est un débogueur de système de fichiers interactif. Il peut être utilisé pour examiner et modifier l'état d'un système de fichiers ext2, ext3 ou

ext4.

périphérique est un périphérique de bloc (p. ex., /dev/s

dXX) ou un fichier conte
nant le système de fichiers.

OPTION

S
-
w
Indique que le système de fichiers doit être ouvert en mode lecture- écriture. Sans cette option, le système de fichiers est ouvert en mode lecture
seule.
-
n
Désactive la vérification des sommes de contrôle des métadonnées. Cela ne doit être utilisé que si vous pensez que les métadonnées sont correctes malgré les plaintes de
e2fsprogs.
-
c
Indique que le système de fichiers doit être ouvert en mode catastrophique, dans lequel les tables de bits d'inodes et de groupes ne sont pas lues initialement. Cela peut être utile pour les systèmes de fichiers présentant une corruption importante, mais en raison de cela, le mode catastrophique force l'ouverture du système de fichiers en lecture
seule.
-
i
Indique que périphérique représente un fichier image ext2 créé par le programme e2image. Comme le fichier image ext2 ne contient que le superbloc, les descripteurs de groupe de blocs, les tables de bits d'allocation de blocs et d'inodes, et la table d'inodes, de nombreuses commandes debugfs ne fonctionneront pas correctement. Avertissement : aucune vérification de sécurité n'est en place, et debugfs peut échouer de manière inattendue si des commandes telles que ls, dump, etc. sont essayées sans spécifier le périphérique_source_de_données à l'aide de l'option -d. debugfs est un outil de débogage. Il a ses défauts
!
-d périphérique_source_de_don
nées
Utilisé avec l' option -i, spécifie que périphérique_source_de_données doit être utilisé lors de la lecture de blocs introuvables dans le fichier image ext2. Cela inclut les blocs de données, de répertoires et
indirects.
-b
taille_de_bloc
Force l'utilisation de la taille de bloc donnée (en octets) pour le système de fichiers, plutôt que de détecter automatiquement la taille de bloc correcte. (Cette option est rarement nécessaire ; elle est principalement utilisée lorsque le système de fichiers est extrêmement endommagé/corrompu.
)
-s
superbloc
Fait lire le superbloc du système de fichiers depuis le numéro de bloc donné, au lieu d'utiliser le superbloc primaire (situé à un décalage de 1024 octets depuis le début du système de fichiers). Si vous spécifiez l' option -s , vous devez également fournir la taille de bloc du système de fichiers via l' option -b. (Cette option est rarement nécessaire ; elle est principalement utilisée lorsque le système de fichiers est extrêmement endommagé/corrompu.
)
-f fichier_de_comm
andes
Fait lire à debugfs des commandes depuis fichier_de_commandes et les exécuter. Quand debugfs a fini d'exécuter ces commandes, il se
termine.
-
D
Fait ouvrir à debugfs le périphérique en utilisant l'E/S directe (Direct I/O), en contournant le cache tampon. Notez que certains périphériques Linux, notamment le mappeur de périphériques (device mapper) au moment de la rédaction, ne prennent pas en charge l'E/S
directe.
-R
requête
Fait exécuter à debugfs la commande unique requête, puis se
terminer.
-
V
affiche le numéro de version de debugfs et se
termine.
-z fichier_d'annul
ation
Avant d'écraser un bloc de système de fichiers, écrire l'ancien contenu du bloc dans un fichier d'annulation. Ce fichier d'annulation peut être utilisé avec e2undo(8) pour restaurer l'ancien contenu du système de fichiers si quelque chose se passe mal. Si la chaîne vide est passée comme argument fichier_d'annulation, le fichier d'annulation sera écrit dans un fichier nommé debugfs-périphérique.e2undo dans le répertoire spécifié via la variable d'environnement E2FSPROGS_UNDO_DIR.

SPÉCIFICATION DES

FICHIERS

De nombreuses commandes debugfs prennent un fichpec comme argument pour spécifier un inode (par opposition à un chemin) dans le système de fichiers actuellement ouvert par debugfs. L' argument fichpec peut être spécifié sous deux formes. La première forme est un numéro d'inode entouré de chevrons, p. ex., <2>. La deuxième forme est un chemin ; si le chemin est préfixé par une barre oblique ('/'), alors il est interprété relativement à la racine du système de fichiers actuellement ouvert par debugfs. Sinon, le chemin est interprété relativement au répertoire de travail courant tel que maintenu par debugfs. Cela peut être modifié en utilisant la commande debugfs cd

.

VARIABLES

D'ENVIRONNEMENT
DEBUGFS_PAGER,
PAGER
Le programme debugfs achemine toujours la sortie de certaines commandes via un programme de pagination. Ces commandes incluent : show_super_stats (stats), list_directory (ls), show_inode_info (stat), list_deleted_inodes (lsdel) et htree_dump. Le pagineur spécifique peut être explicitement spécifié par la variable d'environnement DEBUGFS_PAGER, et si elle n'est pas définie, par la variable d'environnement PAGER.t variable.
Notez que comme un pagineur est toujours utilisé, le pagineur less(1) n'est pas particulièrement approprié, car il efface l'écran avant d'afficher la sortie de la commande et efface l'écran lorsque le pagineur est quitté. De nombreux utilisateurs préfèrent utiliser le pagineur less(1) pour la plupart des usages, c'est pourquoi la variable d'environnement DEBUGFS_PAGER est disponible pour remplacer la variable d'environnement plus générale PAGER.
