DESCRIPTIO

N

delv est un outil pour envoyer des requêtes DNS et valider les résultats, en utilisant le même résolveur interne et la même logique de validation que named <#std-iscman-named>

.

delv envoie à un serveur de noms spécifié toutes les requêtes nécessaires pour récupérer et valider les données demandées ; cela inclut la requête initiale demandée, les requêtes ultérieures pour suivre les chaînes CNAME ou DNAME, les requêtes pour les enregistrements DNSKEY et DS afin d'établir une chaîne de confiance pour la validation DNSSEC. Il n'effectue pas de résolution itérative, mais simule le comportement d'un serveur de noms configuré pour la validation DNSSEC et le

transfert.

Par défaut, les réponses sont validées à l'aide de l'ancre de confiance DNSSEC intégrée pour la zone racine ("."). Les enregistrements renvoyés par delv sont soit entièrement validés, soit non signés. Si la validation échoue, une explication de l'échec est incluse dans la sortie ; le processus de validation peut être tracé en détail. Parce que delv ne s'appuie pas sur un serveur externe pour effectuer la validation, il peut être utilisé pour vérifier la validité des réponses DNS dans des environnements où les serveurs de noms locaux peuvent ne pas être dignes de

confiance.

Sauf s'il est invité à interroger un serveur de noms spécifique, delv essaie chacun des serveurs listés dans /etc/resolv.conf. Si aucune adresse de serveur utilisable n'est trouvée, delv envoie les requêtes aux adresses localhost (127.0.0.1 pour IPv4, ::1 pour IPv6)

.

Lorsqu'aucun argument ou option de ligne de commande n'est donné, delv effectue une requête

NS pour "." (l
a zone racine).

delv fournit un certain nombre d'options de requête qui affectent la façon dont les résultats sont affichés et, dans certains cas, la façon dont les recherches sont

effectuées.

Chaque option de requête est identifiée par un mot-clé précédé d'un signe plus (+). Certains mots-clés définissent ou réinitialisent une option. Ceux-ci peuvent être précédés par la chaîne no pour annuler la signification de ce mot-clé. D'autres mots-clés assignent des valeurs aux options comme l'intervalle d'attente. Ils ont la forme +keyword=value. Les options de requête sont

+cdflag,
+nocdflag
Cette option contrôle s'il faut définir le bit CD (checking disabled) dans les requêtes envoyées par delv. Cela peut être utile pour dépanner des problèmes DNSSEC depuis derrière un résolveur validant. Un résolveur validant bloque les réponses invalides, ce qui rend difficile leur récupération pour analyse. Le fait de définir le drapeau CD sur les requêtes cause au résolveur de retourner des réponses invalides, que delv peut ensuite valider en in
terne et
signaler les err

Cette option bascule le mode serveur de noms. Lorsque cette option est utilisée, le processus delv instancie un résolveur récursif complet et l'utilise pour rechercher le nom et le type de requête demandés. Ces messages journalisés seront écrits vers stdout plutôt que stderr comme d'habitude, de sorte que la trace complète puisse être capturée plus facilement.
