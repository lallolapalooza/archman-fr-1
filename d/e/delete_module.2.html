delete_module(2) Manuel des appels système delete_module(2)

NOM

delete_module - décharger un module du noyau

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#include <fcntl.h>            /* Définition des constantes O_* */
#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_delete_module, const char *name, unsigned int flags);

Note: glibc ne fournit pas de fonction enveloppe pour delete_module(), ce qui nécessite l'utilisation de syscall(2).

DESCRIPTION

L'appel système delete_module() tente de supprimer l'entrée de module chargeable inutilisé identifiée par name. Si le module possède une fonction exit , cette fonction est exécutée avant le déchargement du module. L'argument flags est utilisé pour modifier le comportement de l'appel système, comme décrit ci-dessous. Cet appel système nécessite des privilèges.

La suppression du module est tentée selon les règles suivantes :

(1)
S'il existe d'autres modules chargés qui dépendent de ce module (c'est-à-dire qui référencent des symboles définis dans celui-ci), l'appel échoue.
(2)
Sinon, si le compteur de références du module (c'est-à-dire le nombre de processus utilisant actuellement le module) est nul, le module est immédiatement déchargé.
(3)
Si un module a un compteur de références non nul, le comportement dépend des bits définis dans flags. Dans un usage normal (voir NOTES), l'indicateur O_NONBLOCK est toujours spécifié, et l'indicateur O_TRUNC peut être spécifié en supplément.
Les différentes combinaisons pour flags ont l'effet suivant :
flags == O_NONBLOCK
L'appel retourne immédiatement, avec une erreur.
flags == (O_NONBLOCK | O_TRUNC)
Le module est déchargé immédiatement, que son compteur de références soit non nul ou non.
(flags & O_NONBLOCK) == 0
Si flags ne spécifie pas O_NONBLOCK, les étapes suivantes se produisent :
•
Le module est marqué de manière à ce que de nouvelles références ne soient plus autorisées.
•
Si le compteur de références du module est non nul, l'appelant est placé dans un état de sommeil non interrompable (TASK_UNINTERRUPTIBLE) jusqu'à ce que le compteur de références soit nul, auquel cas l'appel se débloque.
•
Le module est déchargé de la manière habituelle.

L'indicateur O_TRUNC a un effet supplémentaire sur les règles décrites ci-dessus. Par défaut, si un module possède une fonction init mais pas de fonction exit , une tentative de suppression du module échoue. Cependant, si O_TRUNC a été spécifié, cette exigence est contournée.

L'utilisation de l'indicateur O_TRUNC est dangereuse ! Si le noyau n'a pas été compilé avec CONFIG_MODULE_FORCE_UNLOAD, cet indicateur est ignoré silencieusement. (Normalement, CONFIG_MODULE_FORCE_UNLOAD est activé.) L'utilisation de cet indicateur contamine le noyau (TAINT_FORCED_RMMOD).

VALEUR RENVOYÉE

En cas de succès, zéro est renvoyé. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EBUSY
Le module n'est pas « actif » (c'est-à-dire qu'il est toujours en cours d'initialisation ou déjà marqué pour suppression) ; ou, le module possède une fonction init mais pas de fonction exit , et O_TRUNC n'a pas été spécifié dans flags.
EFAULT
name fait référence à une localisation en dehors de l'espace d'adressage accessible du processus.
ENOENT
Aucun module portant ce nom n'existe.
EPERM
L'appelant n'était pas privilégié (n'avait pas la capacité CAP_SYS_MODULE ), ou le déchargement de modules est désactivé (voir /proc/sys/kernel/modules_disabled dans proc(5)).
EWOULDBLOCK
D'autres modules dépendent de ce module ; ou, O_NONBLOCK a été spécifié dans flags, mais le compteur de références de ce module est non nul et O_TRUNC n'a pas été spécifié dans flags.

NORMES

Linux.

HISTORIQUE

L'appel système delete_module() n'est pas pris en charge par glibc. Aucune déclaration n'est fournie dans les en-têtes de glibc, mais, par une bizarrerie de l'histoire, les versions de glibc antérieures à glibc 2.23 exportaient une ABI pour cet appel système. Par conséquent, pour utiliser cet appel système, il suffit (avant glibc 2.23) de déclarer manuellement l'interface dans votre code ; alternativement, vous pouvez invoquer l'appel système en utilisant syscall(2).

Linux 2.4 et antérieur

Dans Linux 2.4 et antérieur, l'appel système ne prenait qu'un seul argument :

int delete_module(const char *name);

Si name est NULL, tous les modules inutilisés marqués auto-clean sont supprimés.

Quelques détails supplémentaires sur les différences de comportement de delete_module() dans Linux 2.4 et antérieur ne sont pas actuellement expliqués dans cette page de manuel.

NOTES

Le sommeil non interrompable qui peut survenir si O_NONBLOCK est omis de flags est considéré comme indésirable, car le processus en sommeil est laissé dans un état inkillable. À partir de Linux 3.7, spécifier O_NONBLOCK est facultatif, mais dans les futurs noyaux il deviendra probablement obligatoire.
