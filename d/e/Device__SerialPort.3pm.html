DESCRIPTIO

N

Ce module fournit une interface utilisateur basée sur des objets essentiellement identique à celle fournie par le module Win32::

SerialPort.

Initialisatio

n

Le constructeur principal est new avec soit un PortName, soit un Fichier de configuration spécifié. Avec un PortName, cela ouvrira le port et créera l'objet. Le port n'est pas encore prêt pour l'accès en lecture/écriture. D'abord, les paramètres souhaités doivent être établis. Puisqu'il s'agit de constantes de réglage pour un pilote matériel sous-jacent dans le Système d'Exploitation, ils sont tous vérifiés pour leur validité par les méthodes qui les définissent. La méthode write_settings met à jour le port (et retournera Vrai sous POSIX). Les ports sont ouverts pour les transferts binaires. Un "binmode" séparé n'est pas

nécessaire. 
$PortObj = new Device::SerialPort ($PortName, $quiet, $lockfile)
     || die "Can't open $PortName: $!
\n";

Le paramètre $quiet est ignoré et est seulement là pour la compatibilité avec Win32::SerialPort. Le paramètre $lockfile est optionnel. Il tentera de créer un fichier (contenant seulement l'identifiant du processus actuel) à l'emplacement spécifié. Ce fichier sera automatiquement supprimé lorsque le $PortObj n'est plus utilisé (par DESTROY). Vous demanderiez habituellement $lockfile avec $quiet vrai pour désactiver les messages lors de la tentative d'obtention de la propriété exclusive du port via le verrou. Les fichiers de verrouillage sont expérimentaux dans la Version 0.07. Ils sont destinés à être utilisés avec d'autres applications. Aucune tentative n'est faite pour résoudre les alias de ports (/dev/modem == /dev/ttySx) ou pour gérer les processus de connexion tels que getty et

uugetty.

En utilisant un Fichier de configuration avec new ou en utilisant le second constructeur, start, les scripts peuvent être simplifiés s'ils ont besoin d'une configuration constante. Il exécute toutes les étapes de new à write_settings basé sur une configuration précédemment sauvegardée. Ce constructeur retournera "undef" en cas de fichier de configuration invalide ou d'échec d'un contrôle de validité. L'objet retourné est prêt pour l'accès. C'est nouveau et expérimental pour la Version 0.

055. 
$PortObj2 = start Device::SerialPort ($Configuration_File_Name)
     ||
die;

Le troisième constructeur, tie, combinera le start avec le support de Perl pour les FileHandles liés (voir perltie). Device::SerialPort implémentera l'ensemble complet des méthodes : TIEHANDLE, PRINT, PRINTF, WRITE, READ, GETC, READLINE, CLOSE et DESTROY. Le support des FileHandle liés est nouveau avec la Version 0.04 et les méthodes READ et READLINE ont été ajoutées dans la Version 0.06. En "contexte scalaire", READLINE définit stty_icanon pour effectuer le traitement des caractères et appelle lookfor. Il restaure stty_icanon après la lecture. En "contexte liste", READLINE effectue des lectures canoniques (par ligne) si stty_icanon est défini ou appelle streamline s'il ne l'est pas. (stty_icanon n'est pas modifié). Le choix streamline permet de dupliquer l'opération de Win32::SerialPort pour les scripts multiplateformes

.

L'implémentation tente de reproduire le comportement de STDIN/STDOUT aussi fidèlement que possible : les appels se bloquent jusqu'à la fin et les chaînes de données qui dépassent les tampons internes sont divisées de manière transparente en plusieurs appels. Dans la Version 0.06, les séparateurs de sortie $, et "$\" sont également appliqués à PRINT s'ils sont définis. Les méthodes output_record_separator et output_field_separator peuvent définir des versions spécifiques au Port-FileHandle de $, et "$\" si désiré. Puisque PRINTF est traité interne comme un seul enregistrement PRINT, "$\" sera appliqué. Les séparateurs de sortie ne sont pas appliqués à WRITE (appelé comme "syswrite FH, $scalar, $length, [$offset]"). Le séparateur d'enregistrement d'entrée $/ n'est pas explicitement supporté - mais une fonction identique peut être obtenue avec un are_match app

roprié. 
$PortObj2 = tie (*FH, 'Device::SerialPort', $Configuration_File_Name)
     ||
die;

Les méthodes de FileHandle lié peuvent être combinées avec les méthodes Device::SerialPort pour read, input, et write ainsi que d'autres méthodes. Les restrictions habituelles contre le mélange de print avec syswrite ne s'appliquent pas. Puisque les deux read (lié) et sysread appellent la même méthode "$ob->READ", et puisqu'une méthode "$ob->read" séparée existe depuis un certain temps dans Device::SerialPort, vous devriez toujours utiliser sysread avec l'interface liée (quand elle est implémentée)

Méthodes de configuration et de

capacité

L'API Win32 Serial Comm fournit des informations étendues concernant les capacités et les options disponibles pour un port (et une instance) spécifique. Ce module retournera des réponses appropriées pour faciliter le portage de code depuis cet

environnement.

La méthode get_tick_count est un clone de la fonction Win32::GetTickCount() . Elle correspond à une méthode correspondante dans Win32::CommPort. Elle retourne le temps en millisecondes - mais peut être utilisée dans des scripts multiplateformes

.
Les sélections binaires accepteront comme vrai l'un des suivants : "("YES", "Y", "ON", "TRUE", "T", "1", 1)" (majuscules/minuscules/mixte) Tout autre est faux.

Il existe un grand nombre de paramètres de configuration et d'options possibles. Pour faciliter la vérification de la validité des options dans les scripts, la plupart des méthodes de configuration peuvent être utilisées de deux manières différentes

méthode appelée avec un

argument

Le paramètre est défini à l'argument, si valide. Un argument invalide retourne faux (undef) et le paramètre est inchangé. La fonction émettra également un carp si $user_msg est vrai. Le port sera mis à jour immédiatement si autorisé (un write_settings automatique est appelé)

méthode appelée sans argument en contexte

scalaire

La valeur actuelle est retournée. Si la valeur n'est pas initialisée ni directement ni par défaut, retourne "undef" qui sera analysé comme faux. Pour les sélections binaires (vrai/faux), retourne la valeur actuelle. Toutes les valeurs actuelles des sélections "multivalue" seront analysées comme vrai

Méthodes

d'exploitation

La version 0.04 ajoute des méthodes de pulse pour les bits RTS, BREAK et DTR. Les méthodes de pulse supposent que le bit est dans l'état opposé au moment où la méthode est appelée. Elles définissent l'état demandé, attendent le nombre spécifié de millisecondes, définissent l'état opposé, et attendent à nouveau le temps spécifié. Ces méthodes sont conçues pour supporter des périphériques, tels que le contrôleur X10 "FireCracker" et certains modems, qui nécessitent des pulses sur ces lignes pour signaler des événements ou des données spécifiques. Le minutage de la partie active de pulse_break_on est géré par POSIX::tcsendbreak (0), qui envoie un pulse BREAK de 250 à 500 millisecondes. Il n'est PAS GARANTI de bloquer

jusqu'à 
la fin.

spécifique soit détecté. Pour les lignes, le motif est une fin de ligne. Mais il y a aussi des besoins de recherche d'autres chaînes dans l'entrée telles que "username:" et "password:". La méthode lookfor fournit un mécanisme cohérent pour résoudre ce problème. Elle recherche l'entrée caractère par caractère à la recherche d'une correspondance avec n'importe lequel des éléments d'un tableau défini avec la méthode are_match. Elle retourne l'entrée entière jusqu'au motif de correspondance si une correspondance est trouvée. Si aucune correspondance n'est trouite, elle retourne "" sauf si une erreur d'entrée ou une interruption est détectée (ce qui retourne undef). Contrairement à Win32::SerialPort, lookfor ne gère pas le retour arrière, l'écho et

d'autres

traitements de caractères. Elle s'attend à ce que le pilote série gère cela et soit contrôlé via stty. Pour interagir avec des humains, vous voudrez probablement stty_icanon(1) pendant lookfor pour obtenir une réponse de ligne de commande familière. La correspondance réelle et les caractères après celle-ci (s'il y en a) peuvent aussi être vus en utilisant la méthode lastlook. Elle adopte aussi la convention d'Expect.pm selon laquelle les chaînes de correspondance sont du texte littéral (testé en utilisant index) sauf si précédées dans la liste are_match par une entrée "-re". La liste are_match par défaut est "("\n")", qui correspond aux lignes complètes. my ($match, $after, $pattern, $instead) = $PortObj->lastlook; # entrée

Pour les chaînes littérales, $match et $pattern devraient être identiques. La valeur $instead retourne le tampon interne testé par la logique de correspondance. Une correspondance réussie ou un lookclear le réinitialise à "" - donc il n'est utile que pour le traitement d'erreurs comme le traitement du timeout ou le signalement de réponses inattendues. La

méthode

lookfor est conçue pour être échantillonnée périodiquement (interrogée). Tous les caractères après le motif de correspondance sont sauvegardés pour un lookfor subséquent. En interne, lookfor est implémentée en utilisant la méthode d'entrée non bloquante lorsqu'elle est appelée sans paramètre. Si appelée avec un compte, lookfor appelle "$PortObj->read(count)" qui bloque jusqu'à ce que le read soit terminé ou qu'un timeout survienne. L'alternative bloquante ne devrait pas être utilisée sauf si un temps de défaut a été défini en utilisant read_interval, read_const_time, et read_char_time. Elle existe principalement pour supporter les fonctions FileHandle liées sysread, getc, et <FH>. Quand stty_icanon est actif, même les appels non bloquants ne retourneront pas de données tant que la ligne n'est pas complète. Les

tampons

internes utilisés par lookfor peuvent être purgés par la méthode lookclear (qui efface aussi la dernière correspondance). Pour les tests, lookclear peut accepter une chaîne qui est "bouclée en retour" vers l' entrée suivante. Cette fonctionnalité n'est activée que lorsque set_test_mode_active(1). Normalement, lookclear retournera "undef" si on lui donne des paramètres. Elle purge toujours les tampons et last_match dans ce cas (mais rien n'est "bouclé en retour"). Vous voudrez stty_echo(0) lorsque vous testerez la boucle en retour.

La

méthode matchclear est conçue pour gérer le "cas spécial" où la chaîne de correspondance est le ou les premiers caractères reçus par lookfor. Dans ce cas, "$lookfor_return == """, lookfor ne fournit pas d'indication claire qu'une correspondance a été trouvée. La matchclear retourne le même $match qui serait retourné par lastlook et le réinitialise à "" sans réinitialiser aucun des autres tampons. Puisque lookfor a déjà cherché à travers la correspondance, matchclear est utilisée à la fois pour détecter et passer par-dessus les lignes "vides". Le traitement caractère par

caractère

utilisé par lookfor est bien pour les activités interactives et les tâches qui attendent des réponses courtes. Mais il a trop de "surcoût" pour gérer des flux de données rapides. Il y a aussi une méthode streamline qui est une alternative rapide, orientée ligne, avec seulement la recherche de motifs. Puisque streamline utilise les mêmes tampons internes, les méthodes lookclear, lastlook, are_match et matchclear fonctionnent de la même manière dans les deux cas. En fait, les appels à streamline et lookfor peuvent être entrelacés si désiré (par exemple, une tâche interactive qui démarre un téléchargement et revient à l'activité interactive lorsque celui-ci est terminé). supplémentaires
