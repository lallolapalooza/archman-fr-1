Le but du stockage par défaut est triple

:
1
)
Créer un espace de stockage global sans créer tout un tas de variables accessibles globalement ou tout un tas de fonctions d'accès pour travailler avec des variables à accès plus
restreint.
2
)
Fournir un emplacement unique où le verrouillage des threads doit être implémenté. Au moment de la rédaction de cette page, cependant, le verrouillage des threads n'est pas encore en
place.
3
)
Réduire le nombre de dépendances croisées entre les morceaux de code qui peuvent ou non être liés ensemble à
long terme. Cela fournit un emplacement unique dans lequel les données de configuration, par exemple, peuvent
être stockées pour une section de code distincte qui peut ne pas être liée à l'application en question.

Les fonctions définies ici mettent en œuvre ces

objectifs.

Actuellement, trois types de données sont pris en charge : les booléens, les entiers et les chaînes de caractères. Chacun de ces types de données a des espaces de stockage séparés. De plus, l'espace de stockage pour chaque type de données est divisé davantage par le niveau de l'application. Actuellement, il y a deux espaces de stockage. Le premier est réservé à la bibliothèque SNMP elle-même. Le deuxième est destiné à être utilisé dans les applications et n'est pas modifié ni vérifié par la bibliothèque et, par conséquent, c'est l'espace utilisable par

vous.

Vous pouvez considérer ces espaces de stockage comme étant 3 tableaux, quelque chose comme bool_storage[storeid][which], int_storage[storeid][which], et string_storage[storeid][which]. Les données sont ensuite accessibles via les fonctions définies ci-dessous. Pour les données que vous souhaitez stocker, vous devez utiliser un paramètre store

de

NETSNMP_DS_APPLICATION_ID. L'espace de stockage utilisé par la bibliothèque (pour lequel le paramètre store est NETSNMP_DS_LIBRARY_ID) est défini dans le fichier default_store.h, qui contient actuellement les définitions suivantes
