DESCRIPTIO

N

La fonction ef_expand_file() fait partie de la bibliothèque tecla (voir la page man libtecla(3)). Elle développe un nom de fichier spécifié, en convertissant ~user/ et ~/ au début du nom de fichier en répertoires personnels correspondants, en remplaçant $envvar par la valeur de la variable d'environnement correspondante, puis, s'il y a des caractères génériques, en les faisant correspondre aux noms de fichiers existants. Les barres obliques inverses dans le nom de fichier d'entrée sont interprétées comme échappant le sens spécial des caractères qui les suivent. Seules les barres obliques inverses qui sont elles-mêmes précédées par d'autres barres obliques inverses sont conservées dans le nom de fichier

développé.

En présence de caractères génériques, la liste de noms de fichiers retournée n'inclut que les noms de fichiers existants qui correspondent aux caractères génériques. Sinon, le nom de fichier original est retourné après le développement des expressions tilde et dollar, et le résultat n'est pas vérifié par rapport aux fichiers existants. Cela imite le comportement de globbing de fichiers du shell unix tcsh

.

Les caractères génériques pris en charge et leurs significations sont

: 
  *        -  Correspond à toute séquence de zéro ou plusieurs caractères.
  ?        -  Correspond à n'importe quel caractère unique.
  [chars]  -  Correspond à n'importe quel caractère unique qui apparaît dans
              'chars'. Si 'chars' contient une expression de
              la forme a-b, alors tout caractère entre a et
              b, y compris a et b, correspond. Le caractère '-'
              perd son sens spécial en tant que
              spécificateur de plage lorsqu'il apparaît au début
              de la séquence de caractères. Le caractère ']'
              perd également sa signification en tant que
              terminateur de l'expression de plage s'il
              apparaît immédiatement après le '[' d'ouverture, au
             quel cas il est traité comme l'un des
              caractères de la plage. Si vous voulez que '-'
              et ']' fassent tous deux partie de la plage, le '-'
              doit venir en premier et le ']' en second.
  [^chars] -  Identique à [chars] sauf qu'il correspond à n'importe quel
              caractère unique qui n'apparaît pas dans
'chars'.

Notez que les caractères génériques ne correspondent jamais au point initial dans les noms de fichiers qui commencent par '.'. Le '.' initial doit être explicitement spécifié dans le nom de fichier. Cela imite à nouveau le comportement de globbing de la plupart des shells unix, et sa justification repose sur le fait que dans unix, les fichiers dont les noms commencent par '.' sont généralement des fichiers de configuration cachés, qui ne sont pas listés par défaut par la commande

ls.

Voici un exemple complet d'utilisation de la fonction de développement de

fichiers. 
  #include <stdio.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  {
    ExpandFile *ef;      /* L'objet ressource d'expansion */
    char *filename;      /* Le nom de fichier en cours de développement */
    FileExpansion *expn; /* Les résultats du développement */
    int i;
    ef = new_ExpandFile();
    if(!ef)
      return 1;
    for(arg = *(argv++); arg; arg = *(argv++)) {
      if((expn = ef_expand_file(ef, arg, -1)) == NULL) {
        fprintf(stderr, "Erreur lors du développement de %s (%s).\n", arg,
                         ef_last_error(ef));
      } else {
        printf("%s correspond aux fichiers suivants :\n", arg);
        for(i=0; i<expn->nfile; i++)
          printf(" %s\n", expn->files[i]);
      }
    }
    ef = del_ExpandFile(ef);
    return 0;
}

  FileExpansion *ef_expand_file(ExpandFile *ef,

La fonction ef_expand_file() effectue le développement de noms de fichiers, comme documenté au début de cette section. Son premier argument est un objet ressource retourné par new_ExpandFile(). Un pointeur vers le début du nom de fichier à faire correspondre est passé via l' argument path. Cela doit être une chaîne normale terminée par NUL, mais sauf si une longueur de -1 est passée dans pathlen, seuls les premiers caractères pathlen seront utilisés dans le développement du nom de fichier. Si la longueur est spécifiée comme -1, toute la chaîne sera

développée.

La fonction retourne un pointeur vers un conteneur dont le contenu est le résultat du développement. S'il n'y avait pas de caractères génériques dans le nom de fichier, le membre nfile sera 1, et le membre exists doit être interrogé s'il est important de savoir si le fichier développé existe actuellement ou non. S'il y avait des caractères génériques, alors le tableau files[] contiendra les noms des fichiers existants nfile qui correspondaient au nom de fichier avec caractères génériques, et le membre exists aura la valeur 1. Notez que le conteneur retourné appartient à l'objet ef spécifié, et son contenu changera à chaque appel ; si vous devez conserver les résultats de plus d'un appel à ef_expand_file(), vous devriez soit faire une copie privée des résultats retournés, soit créer plusieurs objets ressources de développement de fichiers via plusieurs appels à new_ExpandF

ile().

En cas d'erreur, NULL est retourné, et une explication de l'erreur peut être obtenue en appelant ef_last_erro

r(ef).

Cette fonction retourne le message qui décrit l'erreur survenue lors du dernier appel à ef_expand_file(), pour l'objet ressource (ExpandFile *ef)

donné. 
  int ef_list_expansions(FileExpansion *result, FILE *fp,
                         int terminal_width)
;

La fonction ef_list_expansions() fournit un moyen pratique de lister les développements de noms de fichiers retournés par ef_expand_file(). Comme la commande unix ls, elle organise les noms de fichiers en colonnes de largeur égale, chaque colonne ayant la largeur du plus grand fichier. Le nombre de colonnes utilisées est donc déterminé par la longueur du nom de fichier le plus long et la largeur de terminal spécifiée. Attention, les noms de fichiers plus longs que la largeur de terminal spécifiée sont imprimés sans être tronqués ; une sortie plus longue que la largeur de terminal spécifiée peut donc survenir. La liste est écrite dans le flux stdio spécifié par l' argume

nt
fp.

SÉCURITÉ DES

THREADS

Dans les programmes multi-thread, vous devriez utiliser la version libtecla_r.a de la bibliothèque. Celle-ci utilise les fonctions réentrantes POSIX lorsqu'elles sont disponibles (d'où le suffixe _r), et désactive les fonctionnalités qui reposent sur des fonctions système non réentrantes. Actuellement, aucune fonctionnalité n'est désactivée dans ce

module.

En utilisant la version libtecla_r.a de la bibliothèque, il est sûr d'utiliser les fonctionnalités de ce module dans plusieurs threads, à condition que chaque thread utilise un objet ExpandFile alloué séparément. En d'autres termes, si deux threads veulent effectuer un développement de fichiers, ils devraient chacun appeler new_ExpandFile() pour allouer leurs prop

res objets de dévelo
ppement de fichiers.
