DESCRIPTIO

N

Avant que dpkg-source, dpkg-gencontrol et dpkg-genchanges n'écrivent leurs informations de contrôle (dans le fichier de contrôle source .dsc pour dpkg-source et sur la sortie standard pour dpkg-gencontrol et dpkg-genchanges), elles effectuent certaines substitutions de variables sur le fichier de

sortie.

Variable

Syntaxe

Une substitution de variable prend la forme ${nom-de-variable}. Les noms de variables sont composés de caractères alphanumériques (a-zA-Z0-9), de tirets (-) et de deux-points (:) et commencent par un caractère alphanumérique. Ils sont sensibles à la casse, même s'ils peuvent faire référence à d'aut

res entités qui préservent la casse. Les substitutions de variables sont effectuées de manière répétée jusqu'à ce qu'i
l n'en reste plus ; le texte complet du champ après la substitution est réexaminé pour rechercher d'autres substitutions.

Fichier

Syntaxe

Les variables de substitution peuvent être spécifiées dans un fichier. Ces fichiers se composent de lignes de la forme nom=valeur, nom?=valeur, ou nom!=valeur. L'opérateur = assigne une variable de substitution normale, l'opérateur ?= (depuis dpkg 1.21.8) assigne une variable de substitution optionnelle qui n'émettra aucun avertissement même si elle n'est pas utilisée, et l'opérateur != (depuis dpkg 1.22.7) assigne une variable de substitution requise qui provoquera une erreur si elle n'est pas utilisée. Les espaces en fin de ligne, les lignes vides et les lignes commençant par un symbole # (commentaires

) sont
ignorés.

Substitutio

n

Les variables peuvent être définies à l'aide de l'option commune -V. Elles peuvent également être spécifiées dans le fichier debian/substvars (ou tout autre fichier spécifié à l'aide de l'option commune -T)

.

Une fois toutes les substitutions effectuées, chaque occurrence de la chaîne ${} (qui n'est pas une véritable variable de substitution) est remplacée par un signe $. Cela peut être utilisé comme séquence d'échappement, par exemple ${}{VARIABLE} qui donnera ${VARIABLE} dans la

sortie.

Si une variable est référencée mais non définie, cela génère un avertissement et une valeur vide est

supposée.

Bien que la substitution de variables soit effectuée sur tous les champs de contrôle, certains de ces champs sont utilisés et nécessaires pendant la construction lorsque la substitution n'a pas encore eu lieu. C'est pourquoi vous ne pouvez pas utiliser de variables dans les champs Package, Source et Architecture

.

La substitution de variables se produit sur le contenu des champs après qu'ils ont été analysés ; ainsi, si vous voulez qu'une variable s'étende sur plusieurs lignes, vous n'avez pas à inclure un espace après le retour à la ligne. Cela est fait implicitement lorsque le champ est écrit. Par exemple, si la variable ${Description} est définie à « foo is bar.${Newline}foo is great. » et si vous avez le champ suivant

: 
Description: foo application
 ${Description}
 .
 More
text.

Cela donnera

: 
Description: foo applica
tion foo is bar. foo
is great. . More text.

La taille totale approximative des fichiers installés du paquet. Cette valeur est copiée dans le champ correspondant du fichier de contrôle ; la définir modifiera la valeur de ce champ. Si cette variable n'est pas définie, dpkg-gencontrol calculera la valeur par défaut en additionnant la taille de chaque fichier régulier et lien symbolique arrondie à l'unité de 1 KiB utilisée, et une base de 1 KiB pour tout autre type d'objet du système de fichiers. Remarque : Prenez en compte que cela ne peut être qu'une approximation, car la taille réelle utilisée sur le système installé dépendra grandement du système de fichiers utilisé et de ses paramètres, qui pourraient finir par utiliser soit plus, soit moins d'espace que ce qui est spécifié dans ce
