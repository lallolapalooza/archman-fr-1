DESCRIPTIO

N

Les modules du noyau Linux peuvent fournir des services (appelés « symboles ») que d'autres modules peuvent utiliser (en utilisant une des variantes EXPORT_SYMBOL dans le code). Si un second module utilise ce symbole, ce second module dépend clairement du premier module. Ces dépendances peuvent devenir assez

complexes.

depmod crée une liste des dépendances des modules en lisant chaque module sous <BASEDIR>/<MODULEDIR>/version. Par défaut, <MODULEDIR> est /lib/modules et <BASEDIR> est vide. Voir les options ci-dessous pour les remplacer si nécessaire. Il détermine quels symboles chaque module exporte et dont il a besoin. Cette liste est écrite dans modules.dep, et une version hachée binaire nommée modules.dep.bin, dans le même répertoire. Si des noms de fichiers sont donnés sur la ligne de commande, seuls ces modules sont examinés (ce qui est rarement utile sauf si tous les modules sont listés). depmod crée également une liste des symboles fournis par les modules dans le fichier nommé modules.symbols et sa version hachée binaire, modules.symbols.bin. Enfin, depmod produira un fichier nommé modules.devname si les modules fournissent des noms de périphériques spéciaux (devname) qui doivent être créés dans /dev au démarrage (par un utilitaire tel que systemd-tmpfiles)

.

Si une version est fournie, alors le répertoire des modules de cette version du noyau est utilisé plutôt que la version du noyau courant (telle que retournée par uname

-r
).

OPTION

S

-a, --al

l
Interroge tous les modules. Cette option est activée par défaut si aucun nom de fichier n'est donné sur la ligne de
commande.

-A, --quic

k
Cette option scanne pour voir si des modules sont plus récents que le fichier modules.dep avant que tout travail ne soit fait : si ce n'est pas le cas, elle se termine silencieusement au lieu de régénérer les
fichiers.

-b basedir, --basedir=basedi

r
Remplace le répertoire de base <BASEDIR> où les modules sont situés. Si vos modules ne sont pas actuellement dans le répertoire (normal) /lib/modules/version, mais dans une zone de préparation, vous pouvez spécifier un basedir qui est préfixé au nom du répertoire. Ce basedir est retiré du fichier modules.dep résultant, afin qu'il soit prêt à être déplacé vers l'emplacement normal. Utilisez cette option si vous êtes un distributeur qui a besoin de pré-générer les fichiers de métadonnées plutôt que d'exécuter depmod ultérieurement.

Si un chemin relatif est donné, il est relatif au répertoire de travail

courant.

Exemple

:
depmod -b /my/build/staging/dir
/

Cela attend tous les fichiers d'entrée sous /my/build/staging/dir/lib/modules/$(uname -r) et gén

ère les fichiers d'inde
x sous ce même répertoire.

-m moduledir, --moduledir=moduledi

r
Remplace le répertoire des modules <MODULEDIR>, qui par défaut est /lib/modules, le préfixe défini à la compilation. Ceci est utile lors de la construction du fichier modules.dep dans le basedir pour un système qui utilise un préfixe différent, par exemple /usr/lib/modules par rapport à /lib/modules.

Les chemins relatifs et absolus sont acceptés, mais ils sont toujours relatifs au basedir

.

Exemples

:
depmod -b /tmp/build -m /kernel-modules
depmod -b /tmp/build -m
kernel-modules

Cela attend tous les fichiers d'entrée sous /tmp/build/kernel-modules/$(uname -r) et génère les fichiers d'index sous ce même

répertoire.

Sans argument -b accompagnant, le moduledir est relatif à /. Exemple

:
depmod -m
foo/bar

Cela attend tous les fichiers d'entrée sous /foo/bar/$(uname -r) et génère les fichiers d'index sous le même répertoire. À moins que lib

kmod soit préparé à gérer cet emplacement arb
itraire, cela ne fonctionnera pas à l'exécution.

-o outdir, --outdir=outdi

r
Définit le répertoire de sortie où depmod stockera tout fichier généré. outdir sert de racine pour cet emplacement, de manière similaire à l'utilisation de basedir. De plus, ce réglage a la priorité et s'il est utilisé avec basedir, cela résultera en une entrée étant ce répertoire, mais une sortie étant celle définie par outdir.

Si un chemin relatif est donné, il est relatif au répertoire de travail

courant.

Exemple

:
depmod -o /my/build/staging/dir
/

Cela attend tous les fichiers d'entrée sous /lib/modules/$(uname -r) et génère les fichiers d'index sous /my/build/staging/dir/lib

/modules/$(un
ame -r).

-C fichier ou répertoire, --config=fichier ou répertoir

e
Cette option remplace les fichiers de configuration par défaut. Voir depmod.d
(5).

-e, --errsym

s
Lorsqu'elle est combinée avec l'option -F, elle signale tout symbole dont un module a besoin et qui n'est pas fourni par d'autres modules ou par le noyau. Normalement, tout symbole non fourni par des modules est supposé être fourni par le noyau (ce qui devrait être vrai dans un monde parfait), mais cette supposition peut être fausse, surtout lorsque des pilotes tiers mis à jour ne sont pas correctement installés ou ont été compilés
incorrectement.

-E Module.symvers, --symvers=Module.

symvers
Lorsqu'elle est combinée avec l'option -e, elle signale toute version de symbole fournie par des modules qui ne correspond pas aux versions de symboles fournies par le noyau dans son Module.symvers. Cette option est mutuellement incompatible avec -F
.

-F System.map, --filesyms=System.

map
Fourni avec le System.map produit lors de la compilation du noyau, cela permet à l'option -e de signaler les symboles non résolus. Cette option est mutuellement incompatible avec -E
.

-h, --hel

p
Affiche le message d'aide et se
termine.

-n, --show, --dry-ru

n
Cela envoie le modules.dep résultant et les divers fichiers de correspondance vers la sortie standard au lieu de les écrire dans le répertoire des
modules.

-

P
Certaines architectures préfixent les symboles avec un caractère superflu. Cela spécifie un caractère de préfixe (par exemple '_') à
ignorer.

-v, --verbos

e
En mode verbeux, depmod affichera (sur stdout) tous les symboles dont chaque module dépend et le nom du fichier du module qui fournit ce
symbole.

-V, --versio

n
Affiche la version du programme et se termine. Voir ci-dessous les avertissements lors de l'exécution sur des noyaux plus
anciens.

-

w
Avertit sur les dépendanc
es, alias, versions de sy
mboles, etc. en double.
