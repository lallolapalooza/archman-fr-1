DELTA(1P) Manuel du programmeur POSIX DELTA(1P)

PROLOGUE

Cette page manuelle fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page manuelle Linux correspondante pour les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

delta — appliquer un delta (changement) à un fichier SCCS (DÉVELOPPEMENT)

SYNOPSIS

delta [-nps] [-g liste] [-m liste_mr] [-r SID] [-y[commentaire]] fichier...

DESCRIPTION

L'utilitaire delta doit être utilisé pour introduire définitivement dans les fichiers SCCS nommés les changements qui ont été apportés aux fichiers récupérés par get (appelés les g-files, ou fichiers générés).

OPTIONS

L'utilitaire delta doit se conformer au volume des définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires, sauf que l'option -y a un argument d'option facultatif. Cet argument d'option facultatif ne doit pas être présenté comme un argument séparé.

Les options suivantes doivent être prises en charge :

-rSID
Identifier de manière unique le delta à appliquer au fichier SCCS. L'utilisation de cette option n'est nécessaire que si deux commandes get ou plus pour l'édition (get -e) sur le même fichier SCCS ont été effectuées par la même personne (nom de connexion). La valeur SID spécifiée avec l'option -r peut être soit le SID spécifié sur la ligne de commande get , soit le SID à appliquer tel que rapporté par l'utilitaire get ; voir get.
-s
Supprimer le rapport vers la sortie standard de l'activité associée à chaque fichier. Voir la section SORTIE STANDARD.
-n
Spécifier la conservation du g-file édité (normalement supprimé à la fin du traitement de delta).
-gliste
Spécifier une liste (voir get pour la définition de liste) de deltas qui doivent être ignorés lorsque le fichier est accédé au niveau de changement (SID) créé par ce delta.
-mliste_mr
Spécifier un numéro de demande de modification (MR) que l'application doit fournir comme raison de la création du nouveau delta. Ceci doit être utilisé si le fichier SCCS a le drapeau v défini ; voir admin.

Si -m n'est pas utilisé et '-' n'est pas spécifié comme argument de fichier, et que l'entrée standard est un terminal, l'invite décrite dans la section SORTIE STANDARD doit être écrite vers la sortie standard avant la lecture de l'entrée standard ; si l'entrée standard n'est pas un terminal, aucune invite ne doit être émise.

Les MR dans une liste doivent être séparés par des caractères <espace> ou des caractères <retour à la ligne> échappés. Un <retour à la ligne> non échappé doit terminer la liste de MR. Le caractère d'échappement est <barre oblique inverse>.

Si le drapeau v a une valeur, elle doit être considérée comme le nom d'un programme qui valide la correction des numéros de MR. Si un statut de sortie non nul est renvoyé par le programme de validation des numéros de MR, l'utilitaire delta doit se terminer. (On suppose que les numéros de MR n'étaient pas tous valides.)

-y[commentaire]
Décrire la raison d'appliquer le delta. Le commentaire doit être un groupe arbitraire de lignes qui répondrait à la définition d'un fichier texte. Les implémentations doivent prendre en charge des commentairesallant de zéro à 512 octets et peuvent prendre en charge des valeurs plus longues. Une chaîne nulle (spécifiée soit comme -y, -y"", ou en réponse à une invite pour un commentaire) doit être considérée comme un commentairevalide.

Si -y n'est pas spécifié et '-' n'est pas spécifié comme argument de fichier, et que l'entrée standard est un terminal, l'invite décrite dans la section SORTIE STANDARD doit être écrite vers la sortie standard avant la lecture de l'entrée standard ; si l'entrée standard n'est pas un terminal, aucune invite ne doit être émise. Un <retour à la ligne> non échappé doit terminer le texte du commentaire. Le caractère d'échappement est <barre oblique inverse>.

L'option -y doit être requise si l'opérande fichier est spécifiée comme '-'.

-p
Écrire (vers la sortie standard) les différences du fichier SCCS avant et après l'application du delta au format diff ; voir diff.

OPÉRANDES

L'opérande suivant doit être pris en charge :

fichier
Un chemin d'accès vers un fichier SCCS existant ou un répertoire. Si fichier est un répertoire, l'utilitaire delta doit se comporter comme si chaque fichier du répertoire était spécifié comme fichier nommé, sauf que les fichiers non-SCCS (le dernier composant du chemin d'accès ne commence pas par s.) et les fichiers illisibles doivent être ignorés silencieusement.

Si exactement un opérande fichier apparaît, et qu'il est '-', l'entrée standard doit être lue ; chaque ligne de l'entrée standard doit être considérée comme le nom d'un fichier SCCS à traiter. Les fichiers non-SCCS et les fichiers illisibles doivent être ignorés silencieusement.

ENTRÉE STANDARD

L'entrée standard doit être un fichier texte utilisé uniquement dans les cas suivants :

*
Pour lire une liste_mr ou un commentaire (voir les options -m et -y ).
*
Un opérande fichier doit être spécifié comme '-'. Dans ce cas, l'option -y doit être utilisée pour spécifier le commentaire, et si le fichier SCCS a le drapeau v défini, l'option -m doit également être utilisée pour spécifier la liste de MR.

FICHIERS D'ENTRÉE

Les fichiers d'entrée doivent être des fichiers texte dont les données doivent être incluses dans les fichiers SCCS. Si le premier caractère de n'importe quelle ligne d'un fichier d'entrée est <SOH> dans la locale POSIX, les résultats sont indéterminés. Si ce fichier contient plus de 99999 lignes, le nombre de lignes enregistré dans l'en-tête pour ce fichier doit être 99999 pour ce delta.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes doivent affecter l'exécution de delta:

LANG
Fournir une valeur par défaut pour les variables d'internationalisation qui sont non définies ou nulles. (Voir le volume des définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
S'il est défini à une valeur de chaîne non vide, remplacer les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Déterminer la locale pour l'interprétation des séquences d'octets de données texte en tant que caractères (par exemple, caractères sur un seul octet par opposition à caractères sur plusieurs octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Déterminer la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits vers la sortie d'erreur, et des messages informatifs écrits vers la sortie standard.
NLSPATH
Déterminer l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.
TZ
Déterminer le fuseau horaire dans lequel l'heure et la date sont écrites dans le fichier SCCS. Si la variable TZ n'est pas définie ou est NULL, un fuseau horaire par défaut du système indéterminé est utilisé.

ÉVÉNEMENTS ASYNCHRONES

Si SIGINT est capturé, les fichiers temporaires doivent être nettoyés et delta doit se terminer avec unnul. L'action standard doit être prise pour tous les autres signaux ; voir Section 1.4, Description des utilitaires par défaut.

SORTIE STANDARD

La sortie standard ne doit être utilisée que pour les messages suivants dans la locale POSIX :

*
Les invites (voir les -m et -y options) aux formats suivants :
"MRs? "
"comments? "

L'invite MR, si elle est écrite, doit toujours précéder l'invite de commentaires.

*
Un rapport des activités de chaque fichier (sauf si l'option -s est spécifiée) au format suivant :
"%s\n%d inserted\n%d deleted\n%d unchanged\n", <Nouvel SID>,
    <nombre de lignes insérées>, <nombre de lignes supprimées>,
    <nombre de lignes inchangées>

ERREUR STANDARD

La sortie d'erreur ne doit être utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Tout fichier SCCS mis à jour doit être un fichier de format non spécifié.

DESCRIPTION ÉTENDUE

Système Date et Heure

Lorsqu'un delta est ajouté à un fichier SCCS, la date et l'heure du système doivent être enregistrées pour le nouveau delta. Si une commande get est effectuée avec un fichier SCCS dont la date enregistrée est apparemment dans le futur, le comportement est non spécifié.

CODE DE SORTIE

Les valeurs de sortie suivantes doivent être retournées :

0
Exécution réussie.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION PAR LES APPLICATIONS

Des problèmes peuvent survenir si la date et l'heure du système ont été modifiées (par exemple, avancées puis remises en arrière, ou horloges désynchronisées sur un réseau) et peuvent également survenir lorsque différentes valeurs de la variable TZ d'environnement sont utilisées.

Des problèmes de nature similaire peuvent également survenir pour l'opération de l'utilitaire get , qui enregistre la date et l'heure dans le corps du fichier.
