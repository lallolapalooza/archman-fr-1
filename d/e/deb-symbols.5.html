NOM

deb-symbols - Fichier d'informations étendu sur les bibliothèques partagées de Debian

SYNTAXE

DEBIAN/symbols

DESCRIPTION

Les fichiers de symboles sont livrés dans les paquets binaires Debian, et leur format est un sous-ensemble des fichiers de symboles modèles utilisés par dpkg-gensymbols(1) dans les paquets sources Debian, voir deb-src-symbols(5).

Le format d'une entrée d'information de dépendance de bibliothèque partagée étendue dans ces fichiers est :


soname-bibliotheque modèle-dépendance-principale
[| modèle-dépendance-alternative]
[...]
[* nom-champ: valeur-champ]
[...]
symbole version-minimale [id-du-modèle-de-dépendance]

Le soname-bibliotheque est exactement la valeur du champ SONAME telle qu'exportée par objdump(1). Un modèle-dépendance est une dépendance où #MINVER# est remplacé dynamiquement soit par une vérification de version comme « (>= version-minimale) », soit par rien (si une dépendance non versionnée est jugée suffisante).

Chaque symbole exporté (listé sous forme de nom@version, avec version étant « Base » si la bibliothèque n'est pas versionnée) est associé à une version-minimale de son modèle de dépendance (le modèle de dépendance principal est toujours utilisé et finira par être combiné avec le modèle de dépendance référencé par id-du-modèle-de-dépendance s'il est présent). Le premier modèle de dépendance alternative est numéroté 1, le second 2, etc. Chaque colonne est séparée par exactement un espace unique.

Chaque entrée pour une bibliothèque peut également contenir des champs de métadonnées. Ces champs sont stockés sur des lignes commençant par un astérisque. Actuellement, les seuls champs valides sont :

Build-Depends-Package
Il indique le nom du paquet « -dev » associé à la bibliothèque et est utilisé par dpkg-shlibdeps pour s'assurer que la dépendance générée est au moins aussi stricte que la dépendance de construction correspondante (depuis dpkg 1.14.13).
Build-Depends-Packages
Identique à Build-Depends-Package, mais accepte une liste de noms de paquets séparés par des virgules (depuis dpkg 1.20.0). Ce champ remplacera tout champ Build-Depends-Package présent, et est principalement utile avec les paquets « -dev » et les métapaquets qui en dépendent, par exemple lors d'une période de transition.
Allow-Internal-Symbol-Groups
Il indique quels groupes de symboles internes doivent être ignorés, sous forme d'une liste séparée par des espaces, afin que les symboles contenus dans ces groupes soient inclus dans le fichier de sortie (depuis dpkg 1.20.1). Cela ne devrait être nécessaire que pour les paquets de chaîne d'outils fournissant ces symboles internes. Les groupes disponibles dépendent du système, pour les systèmes ELF et basés sur GNU, il s'agit de aeabi et gomp.
Ignore-Blacklist-Groups
Un alias obsolète pour Allow-Internal-Symbol-Groups (depuis dpkg 1.20.1, pris en charge depuis dpkg 1.17.6).

EXEMPLES

Fichier simple de symboles

libftp.so.3 libftp3 #MINVER#
 DefaultNetbuf@Base 3.1-1-6
 FtpAccess@Base 3.1-1-6
 [...]

Avancé fichier de symboles

libGL.so.1 libgl1
| libgl1-mesa-glx #MINVER#
* Build-Depends-Package: libgl1-mesa-dev
 publicGlSymbol@Base 6.3-1
 [...]
 implementationSpecificSymbol@Base 6.5.2-7 1
 [...]
