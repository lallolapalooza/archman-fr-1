NOM

deb-shlibs - Fichier d'informations sur les bibliothèques partagées Debian

SYNTAXE

debian/shlibs, debian/nom-binaire.shlibs, DEBIAN/shlibs

DESCRIPTION

Les fichiers shlibs associent les noms et versions de bibliothèques partagées (SONAMEs) à des dépendances appropriées pour un fichier de contrôle de paquet. Il y a une entrée par ligne. Les lignes vides ne sont **pas** autorisées. Les lignes commençant par un caractère # sont considérées comme des commentaires et sont ignorées. Toutes les autres lignes doivent respecter le format :

[type:] bibliothèque version dépendances

Les champs bibliothèque et version sont délimités par des espaces, mais le champ dépendances s'étend jusqu'à la fin de la ligne. Le champ type est optionnel et normalement pas nécessaire.

Le champ dépendances a la même syntaxe que le champ Depends dans un fichier de contrôle binaire, voir deb-control(5).

FORMATS DE SONAME

Les formats de SONAME pris en charge sont :

nom.so.version

et

nom-version.so

où nom est généralement préfixé par lib.

Le premier est généralement utilisé par les bibliothèques partagées avec des interfaces stables. Le second par les bibliothèques partagées avec des interfaces instables, où la version entière fait partie du SONAME et doit être spécifiée en entier lors de la liaison avec ces bibliothèques.

EXEMPLES

Le fichier shlibs pour un paquet de bibliothèque typique, nommé libcrunch1, qui fournit une bibliothèque dont le SONAME est libcrunch.so.1, pourrait se lire comme suit :

libcrunch 1 libcrunch1 (>= 1.2-1)

Les dépendances doivent mentionner la version la plus récente du paquet qui a ajouté de nouveaux symboles à la bibliothèque : dans l'exemple ci-dessus, de nouveaux symboles ont été ajoutés à la version 1.2 de libcrunch. Ce n'est pas la seule raison pour laquelle les dépendances pourraient devoir être resserrées.

VOIR AUSSI
