DESCRIPTIO

N

L'API de Perl a changé au fil du temps, gagnant de nouvelles fonctionnalités, de nouvelles fonctions, augmentant sa flexibilité et réduisant l'impact sur l'environnement de noms C (pollution réduite). Le fichier d'en-tête écrit par ce module, généralement ppport.h, tente d'apporter certaines des fonctionnalités les plus récentes de l'API Perl aux anciennes versions de Perl, afin que vous puissiez moins vous soucier de suivre les anciennes versions, mais que les utilisateurs puissent toujours en

profiter.

"Devel::PPPort" contient deux fonctions, "WriteFile" et "GetFileContents". Le seul but de "WriteFile" est d'écrire le fichier d'en-tête C ppport.h. Ce fichier contient une série de macros et, si explicitement demandé, des fonctions qui permettent aux modules XS d'être construits en utilisant d'anciennes versions de Perl. Actuellement, les versions de Perl de 5.003_07 à 5.35.9 sont prises en

charge.

"GetFileContents" peut être utilisé pour récupérer le contenu du fichier au lieu de

l'écrire.

Ce module est utilisé par "h2xs" pour écrire le fichier ppport

.h.

Pourquoi utiliser ppport.

h?

Vous devriez utiliser ppport.h dans le code moderne afin que votre code fonctionne avec la gamme la plus large possible d'interpréteurs Perl, sans travail supplémentaire

important.

Vous devriez essayer de faire en sorte que l'ancien code utilise pleinement ppport.h, car la pollution réduite des nouvelles versions de Perl est une chose importante. C'est si important que les anciennes méthodes polluantes des modules Perl originaux ne seront pas prises en cha

rge très longtemps dans le futur, et votre module cassera presque certainement ! En vous y adaptant mai
ntenant, vous gagnerez en compatibilité et un sentiment d'avoir rendu service à l'écologie électronique.

Comment utiliser ppport.

h

Ne dirigez pas les utilisateurs de votre module vers le téléchargement de "Devel::PPPort". Ils ne sont très probablement pas des auteurs de XS. De plus, ne rendez pas ppport.h optionnel. Prenez plutôt simplement la copie la plus récente de ppport.h que vous pouvez trouver (par ex. en la générant avec la dernière version de "Devel::PPPort" de CPAN), copiez-la dans votre projet, ajustez votre projet pour l'utiliser, testez-la, et distribuez l'en-tête avec votre

module.

Il est important d'utiliser la version la plus récente de ppport.h. Vous devez tester avant de livrer une version plus récente que celle que vous aviez déjà. Un échec possible est que quelqu'un ait dû convertir un élément rétroporté d'une macro en une fonction, et les fonctions réelles doivent être activées avec une macro NEED pour minimiser la possibilité de pollution de l'espace de noms. Voir HACKERS pour les détails. Les développeurs de "Devel::PPPort" veulent savoir s'il y a d'autres problèmes qui surviennent de l'utilisation d'un ppport.h plus récent. Utilisez https://github.com/Dual-Life/Devel

-PPPort/issues p
our les signaler.

Exécuter ppport.

h

Mais ppport.h est plus qu'un simple en-tête C. C'est aussi un script Perl qui peut vérifier votre code source. Il suggérera des indices et des notes de portabilité, et peut même faire des suggestions sur la manière de modifier votre code. Vous pouvez l'exécuter comme n'importe quel autre programme Perl

: 
perl ppport.h [options]
[fichiers]

Il contient également de la documentation intégrée, vous pouvez donc

utiliser 
perldoc ppport.
h

pour en savo

ir plus sur
la façon de
l'utiliser.

fois.

003_07.

perl ppport.h --api-info=ELEMEN
