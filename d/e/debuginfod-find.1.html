interroge un ou plusieurs serveurs debuginfodpour des données liées au debuginfo. En cas de correspondance, il enregistre le fichier demandé dans un cache local, imprime le nom du fichier sur la sortie standard et se termine avec un statut de succès de 0. En cas d'erreur, il se termine avec un statut d'échec et un message d'erreur sur la sortie d'erreur standard. Le système debuginfod utilise des buildids pour identifier les données liées au debuginfo. Ceux-ci sont stockés sous forme de notes binaires dans les fichiers ELF/DWARF, et sont représentés en hexadécimal minuscule. Les chemins relatifs apparaissent couramment dans le répertoire source du fichier DWARF, mais ces chemins sont relatifs aux chemins AT_comp_dir des unités de compilation individuelles, et pourtant un exécutable est composé de plusieurs UC. VARIABLES D'ENVIRONNEMENT

$TMPDIR
Cette variable d'environnement indique un système de fichiers à utiliser pour les fichiers temporaires. La valeur par défaut est /tmp.
$DEBUGINFOD_URLS
Cette variable d'environnement contient une liste de préfixes d'URL pour les instances debuginfod de confiance. Les préfixes d'URL alternatifs sont séparés par des espaces. Cette variable d'environnement peut être définie par des scripts /etc/profile.d lisant les fichiers /etc/debuginfod/*.urls.

Cette variable d'environnement peut également contenir des balises définissant la politique qui dictent la politique de réponse pour la vérification des signatures IMA par fichier dans les RPM. Comme la liste séparée par des espaces est lue de gauche à droite, lorsqu'une balise est rencontrée, les URL suivantes jusqu'à la prochaine balise seront traitées en utilisant cette politique spécifiée. Toutes les URL avant la première balise utiliseront la politique par défaut, ima:ignore. Par exemple :


DEBUGINFOD_URLS="https://foo.com ima:enforcing https://bar.ca http://localhost:8002/ ima:ignore https://baz.org"

Où foo.com et baz.org utilisent la politique par défaut ignore et bar.ca et localhost utilisent une politique enforcing . La balise de politique peut être l'une des suivantes :

ima:enforcing Chaque fichier téléchargé nécessite une signature valide, protégeant pleinement l'intégrité.
ima:ignore Saute complètement la vérification, sans fournir aucune protection.

Les alertes d'échec de validation seront dirigées comme spécifié dans $DEBUGINFOD_VERBOSE.

$DEBUGINFOD_CACHE_PATH
Cette variable d'environnement gouverne l'emplacement du cache où les fichiers téléchargés et les fichiers de contrôle de cache sont conservés. Le répertoire par défaut est choisi en fonction d'autres variables d'environnement, voir ci-dessous.
$DEBUGINFOD_PROGRESS
Cette variable d'environnement gouverne la fonction de progression par défaut. Si définie, et si une progressfn n'est pas explicitement définie, alors la bibliothèque configurera une progressfn par défaut. Cette fonction ajoutera périodiquement un simple message de progression à stderr. La valeur par défaut est aucune sortie de fonction de progression.
$DEBUGINFOD_VERBOSE
Cette variable d'environnement gouverne le descripteur de fichier par défaut pour la sortie verbeuse. Si définie, et si un verbose fd n'est pas explicitement défini, alors la sortie verbeuse sera produite sur STDERR_FILENO.
$DEBUGINFOD_RETRY_LIMIT
Cette variable d'environnement gouverne la limite par défaut des tentatives de nouvelle tentative. Si une requête a échoué avec un errno autre que ENOENT, elle initiera plusieurs tentatives dans la limite.
$DEBUGINFOD_TIMEOUT
Cette variable d'environnement gouverne le délai d'attente de commencement téléchargement pour chaque connexion HTTP debuginfod. Un serveur qui échoue à fournir au moins 100K de données dans ce nombre de secondes est ignoré. La valeur par défaut est 90 secondes. (Zéro ou négatif signifie « pas de délai d'attente ».)
$DEBUGINFOD_MAXTIME
Cette variable d'environnement dicte combien de temps le client attendra pour terminer le téléchargement d'un fichier trouvé sur un serveur en secondes. Elle est mieux utilisée pour s'assurer qu'un fichier est téléchargé rapidement ou être rejeté. La valeur par défaut est 0 (temps infini).
$DEBUGINFOD_MAXSIZE
Cette variable d'environnement dicte la taille maximale d'un fichier à télécharger en octets. Elle est mieux utilisée si l'utilisateur souhaite s'assurer que seuls de petits fichiers sont téléchargés. Une valeur de 0 signifie aucune considération pour la taille, et le client peut tenter de télécharger un fichier de n'importe quelle taille. La valeur par défaut est 0 (taille infinie).
$DEBUGINFOD_HEADERS_FILE
Cette variable d'environnement pointe vers un fichier qui fournit des en-têtes aux requêtes HTTP sortantes, un par ligne. Les lignes d'en-tête ne devraient pas se terminer par CRLF, sauf si c'est la convention de nouvelle ligne du système. Les lignes contenant uniquement des espaces sont ignorées.
$DEBUGINFOD_IMA_CERT_PATH
Cette variable d'environnement contient une liste de chemins de répertoires absolus contenant des certificats X.509 pour la vérification IMA par fichier des RPM. Les chemins alternatifs sont séparés par des deux-points.

CACHE

Avant chaque requête, la bibliothèque client debuginfod vérifie la nécessité de nettoyer le cache. Si c'est le moment de nettoyer, la bibliothèque parcourt le répertoire de cache et supprime les artefacts liés au debuginfo téléchargés et les répertoires devenus vides, s'ils n'ont pas été accédés récemment.

Les fichiers de contrôle sont situés directement sous le répertoire de cache. Ils contiennent de simples nombres décimaux pour définir les paramètres de configuration liés au cache. Si les fichiers n'existent pas, la bibliothèque client crée les fichiers avec les valeurs de paramètres par défaut comme contenu.

Après chaque requête, la bibliothèque client debuginfod dépose les fichiers nouvellement reçus dans un répertoire et un fichier nommés en fonction du build-id. Une requête échouée est également mise en cache par un fichier spécial. La convention de nommage utilisée pour ces artefacts est délibérément non documentée.

$XDG_CACHE_HOME/debuginfod_client/
Répertoire de cache par défaut, si $XDG_CACHE_HOME est défini.
$HOME/.cache/debuginfod_client/
Répertoire de cache par défaut, si $XDG_CACHE_HOME n'est pas défini.
$HOME/.debuginfod_client_cache/
Répertoire de cache obsolète, utilisé seulement s'il existe déjà.
cache_clean_interval_s
Ce fichier de contrôle donne l'intervalle entre les cycles de nettoyage du cache, en secondes. La valeur par défaut est 86400, un jour. 0 signifie « immédiatement ».
max_unused_age_s
Ce fichier de contrôle définit combien de temps les fichiers liés au debuginfo non accédés sont conservés, en secondes. La valeur par défaut est 604800, une semaine. 0 signifie « immédiatement ».
cache_miss_s
Ce fichier de contrôle définit combien de temps se souvenir d'un échec de requête, en secondes. Les nouvelles requêtes pour les mêmes artefacts dans cette fenêtre temporelle sont court-circuitées (retournant un échec immédiat au lieu d'envoyer une nouvelle requête aux serveurs). Cela accélère les requêtes qui échoueraient probablement encore. La valeur par défaut est 600, 10 minutes. 0 signifie « oublier immédiatement ».
metadata_retention_s
Ce fichier de contrôle définit combien de temps se souvenir des résultats d'une requête de métadonnées. Les nouvelles requêtes pour les mêmes artefacts dans cette fenêtre temporelle sont court-circuitées (répétant les mêmes résultats). Cela accélère les requêtes qui auraient probablement les mêmes résultats. La valeur par défaut est 3600, 1 heure. 0 signifie « ne pas conserver ».
