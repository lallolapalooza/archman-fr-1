DESCRIPTION

L'objet PathCache fait partie de la bibliothèque tecla (voir la page de manuel libtecla(3)).

Les objets PathCache permettent à une application de rechercher des fichiers dans n'importe quelle liste de répertoires séparés par des deux-points, comme la variable d'environnement d'exécution unix PATH. Les fichiers dans les répertoires absolus sont mis en cache dans un objet PathCache, tandis que les répertoires relatifs sont analysés au besoin. En utilisant un objet PathCache, vous pouvez rechercher le nom de chemin complet d'un nom de fichier simple, ou vous pouvez obtenir une liste des complétions possibles d'un préfixe de nom de fichier donné. Par défaut, tous les fichiers de la liste des répertoires sont des cibles pour la recherche et la complétion, mais un mécanisme polyvalent est fourni pour ne sélectionner que certains types de fichiers. L'application évidente de cette fonctionnalité est de fournir la complétion par tabulation et la recherche de commandes exécutables dans le PATH unix, ainsi une fonction de rappel optionnelle qui rejette tout sauf les fichiers exécutables, est fournie.

UN EXEMPLE

Sous UNIX, l'exemple de programme suivant recherche et affiche les chemins complets de chacun des noms de commande sur la ligne de commande.

  #include <stdio.h>
  #include <stdlib.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  {
    int i;
  /*
   * Créer un cache pour les fichiers exécutables.
   */
    PathCache *pc = new_PathCache();
    if(!pc)
      exit(1);
  /*
   * Analyser le PATH de l'utilisateur pour les exécutables.
   */
    if(pca_scan_path(pc, getenv("PATH"))) {
      fprintf(stderr, "%s\n", pca_last_error(pc));
      exit(1);
    }
  /*
   * S'arranger pour ne signaler que les fichiers exécutables.
   */
   pca_set_check_fn(pc, cpl_check_exe, NULL);
  /*
   * Rechercher et afficher le nom de chemin complet de chaque
   * commande listée sur la ligne de commande.
   */
    for(i=1; i<argc; i++) {
      char *cmd = pca_lookup_file(pc, argv[i], -1, 0);
      printf("Le nom de chemin complet de '%s' est %s\n", argv[i],
             cmd ? cmd : "inconnu");
    }
    pc = del_PathCache(pc);  /* Nettoyage */
    return 0;
  }

Voici un exemple de ce que cela fait sur mon ordinateur portable sous linux :

  $ ./example less more blob
  Le nom de chemin complet de 'less' est /usr/bin/less
  Le nom de chemin complet de 'more' est /bin/more
  Le nom de chemin complet de 'blob' est inconnu
  $

DESCRIPTIONS DES FONCTIONS

Pour utiliser les fonctionnalités de ce module, vous devez d'abord allouer un objet PathCache en appelant la fonction constructeur new_PathCache().

  PathCache *new_PathCache(void)

Cette fonction crée les ressources nécessaires pour mettre en cache et rechercher des fichiers dans une liste de répertoires. Elle retourne NULL en cas d'erreur.

REMPLIR LE CACHE

Une fois que vous avez créé un cache, il doit être rempli de fichiers. Pour ce faire, appelez la fonction pca_scan_path().

  int pca_scan_path(PathCache *pc, const char *path);

Chaque fois que cette fonction est appelée, elle rejette le contenu actuel du cache, puis analyse la liste des répertoires spécifiés dans son argument path pour y trouver des fichiers. L'argument path doit être une chaîne contenant une liste de répertoires séparés par des deux-points, telle que "/usr/bin:/home/mcs/bin:.". Cela peut inclure des répertoires spécifiés par des chemins absolus tels que "/usr/bin", ainsi que des sous-répertoires spécifiés par des chemins relatifs tels que "." ou "bin". Les fichiers des répertoires absolus sont immédiatement mis en cache dans l'objet PathCache spécifié, tandis que les sous-répertoires, dont l'identité change évidemment chaque fois que le répertoire de travail courant est modifié, sont marqués pour être analysés à la volée chaque fois qu'un fichier est recherché.

En cas de succès, cette fonction retourne 0. En cas d'erreur, elle retourne 1, et une description de l'erreur peut être obtenue en appelant pca_last_error(pc).

RECHERCHER DES FICHIERS

Une fois que le cache a été rempli de fichiers, vous pouvez rechercher le nom de chemin complet d'un fichier, simplement en spécifiant son nom de fichier à pca_lookup_file().

  char *pca_lookup_file(PathCache *pc, const char *name,
                        int name_len, int literal);

Pour permettre de passer à cette fonction un nom de fichier qui fait en réalité partie d'une chaîne plus longue, l'argument name_len peut être utilisé pour spécifier la longueur du nom de fichier au début de l'argument name[]. Si vous passez -1 pour cette longueur, la longueur de la chaîne sera déterminée avec strlen(). Si la chaîne name[] peut contenir des barres obliques inverses qui échappent la signification spéciale des espaces et des tabulations dans le nom de fichier, donnez à l'argument literal la valeur 0. Sinon, si les barres obliques inverses doivent être traitées comme des caractères normaux, passez 1 pour la valeur de l'argument literal.

COMPLETION DE NOMS DE FICHIER

La recherche des complétions potentielles d'un préfixe de nom de fichier dans le cache de noms de fichiers est réalisée en passant la fonction de rappel fournie pca_path_completions() à la fonction cpl_complete_word() (voir la page de manuel cpl_complete_word(3)).

  CPL_MATCH_FN(pca_path_completions);

Cette fonction de rappel exige que son argument data soit un pointeur vers un objet PcaPathConf. Les objets de configuration de ce type sont alloués en appelant new_PcaPathConf().

  PcaPathConf *new_PcaPathConf(PathCache *pc);

Cette fonction retourne un objet initialisé avec des paramètres de configuration par défaut, qui déterminent le comportement de la fonction de rappel cpl_path_completions(). Les fonctions qui permettent de changer individuellement ces paramètres sont décrites ci-dessous.

Par défaut, la fonction de rappel pca_path_completions() recherche en arrière à partir du début du nom de fichier en cours de complétion, à la recherche du premier espace non échappé ou du début de la ligne d'entrée. Si vous souhaitez spécifier un emplacement différent, appelez ppc_file_start() avec l'indice où le nom de fichier commence dans la ligne d'entrée. Passer start_index=-1 réactive le comportement par défaut.

  void ppc_file_start(PcaPathConf *ppc, int start_index);

Par défaut, lorsque pca_path_completions() examine un nom de fichier dans la ligne d'entrée, chaque barre oblique inverse isolée dans la ligne d'entrée est interprétée comme un caractère spécial qui supprime toute signification spéciale du caractère qui la suit, tel qu'un espace qui doit être considéré comme faisant partie du nom de fichier plutôt que de délimiter le début du nom de fichier. Ces barres obliques inverses sont donc ignorées lors de la recherche de complétions, et ajoutées ensuite avant les espaces, les tabulations et les barres obliques inverses littérales dans la liste des complétions. Pour que les barres obliques inverses non échappées soient traitées comme des caractères normaux, appelez ppc_literal_escapes() avec une valeur non nulle dans son argument literal.

  void ppc_literal_escapes(PcaPathConf *ppc, int literal);

Lorsque vous avez terminé avec une variable PcaPathConf, vous pouvez la passer à la fonction destructeur del_PcaPathConf() pour récupérer sa mémoire.

  PcaPathConf *del_PcaPathConf(PcaPathConf *ppc);

ETRE SELECTIF

Si vous n'êtes intéressé que par certains types de fichiers, tels que, par exemple, les fichiers exécutables, ou les fichiers dont les noms se terminent par un suffixe particulier, vous pouvez faire en sorte que les fonctions de complétion et de recherche de fichiers soient sélectives dans les noms de fichiers qu'elles retournent. Ceci est fait en enregistrant une fonction de rappel avec votre objet PathCache.
