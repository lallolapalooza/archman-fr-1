VARIABLES

D'ENVIRONNEMENT
$TMPD
IR
Cette variable d'environnement indique un système de fichiers à utiliser pour les fichiers temporaires. La valeur par défaut est
/tmp.
$DEBUGINFOD_U
RLS
Cette variable d'environnement contient une liste de préfixes d'URL pour les instances debuginfod de confiance. Les préfixes d'URL alternatifs sont séparés par des espaces. Cette variable d'environnement peut être définie par des scripts /etc/profile.d lisant les fichiers /etc/debuginfod/*.urls.

Cette variable d'environnement peut également contenir des balises définissant la politique qui dicte la politique de réponse pour la vérification des signatures IMA par fichier dans les RPM. Comme la liste séparée par des espaces est lue de gauche à droite, lorsqu'une balise est rencontrée, les URL suivantes jusqu'à la prochaine balise seront traitées en utilisant cette politique spécifiée. Toutes les URL avant la première balise utiliseront la politique par défaut, ima:ignore. Par exemple

: 


DEBUGINFOD_URLS="https://foo.com ima:enforcing https://bar.ca http://localhost:8002/ ima:ignore https://baz.
org"

Où foo.com et baz.org utilisent la politique d'ignorance par défaut et bar.ca et localhost utilisent une politique d'application. La balise

de politique
peut être l'un
e des suivantes :
ima:enforcing Chaque fichier téléchargé nécessite une signature valide, protégeant pleinement
l'intégrité.
ima:ignore Saute complètement la vérification, ne fournissant aucune
protection.

Les alertes d'échec de validation seront dirigées comme spécifié dans

$DEBUGINFOD_VERBOS
E
.
$DEBUGINFOD_CACHE_P
ATH
Cette variable d'environnement régit l'emplacement du cache où les fichiers téléchargés et les fichiers de contrôle du cache sont conservés. Le répertoire par défaut est choisi en fonction d'autres variables d'environnement, voir
ci-dessous.
$DEBUGINFOD_PROGR
ESS
Cette variable d'environnement régit la fonction de progression par défaut. Si définie, et si une progressfn n'est pas explicitement définie, alors la bibliothèque configurera une progressfn par défaut. Cette fonction ajoutera périodiquement un simple message de progression à stderr. La valeur par défaut est aucune sortie de fonction de
progression.
$DEBUGINFOD_VERB
OSE
Cette variable d'environnement régit le descripteur de fichier par défaut pour la sortie verbeuse. Si définie, et si un fd verbeux n'est pas explicitement défini, alors la sortie verbeuse sera produite sur
STDERR_FILENO.
$DEBUGINFOD_RETRY_LI
MIT
Cette variable d'environnement régit la limite par défaut des tentatives de nouvelle tentative. Si une requête a échoué avec un errno autre que ENOENT, elle initiera plusieurs tentatives dans la
limite.
$DEBUGINFOD_TIME
OUT
Cette variable d'environnement régit le délai d'attente de début du téléchargement pour chaque connexion HTTP debuginfod. Un serveur qui ne fournit pas au moins 100K de données dans ce nombre de secondes est ignoré. La valeur par défaut est 90 secondes. (Zéro ou négatif signifie « pas de délai d'attente
».)
$DEBUGINFOD_MAXT
IME
Cette variable d'environnement dicte combien de temps le client attendra pour terminer le téléchargement d'un fichier trouvé sur un serveur, en secondes. Elle est mieux utilisée pour s'assurer qu'un fichier est téléchargé rapidement ou être rejeté. La valeur par défaut est 0 (temps infini)
.
$DEBUGINFOD_MAXS
IZE
Cette variable d'environnement dicte la taille maximale d'un fichier à télécharger en octets. Elle est mieux utilisée si l'utilisateur souhaite s'assurer que seuls de petits fichiers sont téléchargés. Une valeur de 0 signifie aucune considération de taille, et le client peut tenter de télécharger un fichier de n'importe quelle taille. La valeur par défaut est 0 (taille infinie)
.
$DEBUGINFOD_HEADERS_F
ILE
Cette variable d'environnement indique un fichier qui fournit des en-têtes aux requêtes HTTP sortantes, un par ligne. Les lignes d'en-tête ne doivent pas se terminer par CRLF, sauf si c'est la convention de nouvelle ligne du système. Les lignes contenant uniquement des espaces sont
ignorées.

ATH

CACH

E

Avant chaque requête, la bibliothèque cliente debuginfod vérifie la nécessité de nettoyer le cache. S'il est temps de nettoyer, la bibliothèque parcourt le répertoire de cache et supprime les artefacts liés aux debuginfo téléchargés et les répertoires devenus vides, s'ils n'ont pas été accédés

récemment.

Les fichiers de contrôle sont situés directement sous le répertoire de cache. Ils contiennent de simples nombres décimaux pour définir les paramètres de configuration liés au cache. Si les fichiers n'existent pas, la bibliothèque cliente crée les fichiers avec les valeurs de paramètres par défaut comme

contenu.

Après chaque requête, la bibliothèque cliente debuginfod dépose les fichiers nouvellement reçus dans un répertoire et un fichier nommés en fonction du build-id. Une requête échouée est également mise en cache par un fichier spécial. La convention de nommage utilisée pour ces artefacts est délibérément non docume

ntée.
$XDG_CACHE_HOME/debuginfod_clie
nt/
Répertoire de cache par défaut, si $XDG_CACHE_HOME est
défini.
$HOME/.cache/debuginfod_clie
nt/
Répertoire de cache par défaut, si $XDG_CACHE_HOME n'est pas
défini.
$HOME/.debuginfod_client_cac
he/
Répertoire de cache obsolète, utilisé seulement s'il existe
déjà.
cache_clean_interva
l_s
Ce fichier de contrôle donne l'intervalle entre les cycles de nettoyage du cache, en secondes. La valeur par défaut est 86400, un jour. 0 signifie « immédiatement
».
max_unused_ag
e_s
Ce fichier de contrôle définit combien de temps les fichiers liés aux debuginfo non accédés sont conservés, en secondes. La valeur par défaut est 604800, une semaine. 0 signifie « immédiatement
».
cache_miss
_s
Ce fichier de contrôle définit combien de temps se souvenir d'un échec de requête, en secondes. Les nouvelles requêtes pour les mêmes artefacts dans cette fenêtre temporelle sont court-circuitées (retournant un échec immédiat au lieu d'envoyer une nouvelle requête aux serveurs). Cela accélère les requêtes qui échoueraient probablement encore. La valeur par défaut est 600, 10 minutes. 0 signifie « oublier immédiatement
».
metadata_retentio
n_s
Ce fichier de contrôle définit combien de temps se souvenir des résultats d'une r
equête de métadonnées. Les nouvelles requêtes pour les mêmes artefacts dans
cette fenêtre temporelle sont court-circuitées (répétant les mêmes résultat
s). Cela accélère les requêtes qui auraient probablement les mêmes résultat
s. La valeur par défaut est 3600, 1 heure. 0 signifie « ne pas conserver ».
