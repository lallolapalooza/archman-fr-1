Description Détaillée

Une interface d'entrée/sortie abstraite.

Attention

Ceci est du matériel avancé. Vous n'en avez pas besoin à moins de vraiment savoir ce que vous faites. La plupart des applications n'auront pas besoin de cela.

Historiquement, PhysicsFS fournissait un accès au système de fichiers physique et aux archives dans ce système de fichiers. Cependant, parfois, vous avez besoin de plus de puissance que cela. Peut-être avez-vous besoin de fournir une archive entièrement contenue en RAM, ou vous avez besoin de relier une autre API d'E/S de fichiers à PhysicsFS, ou vous avez besoin de traduire les bits (peut-être avez-vous un fichier .zip standard crypté, et vous avez besoin de le décrypter à la volée pour l'archiveur zip inconscient).

Un PHYSFS_Io est l'interface que les archiveurs utilisent pour obtenir des données d'archive. Historiquement, cela correspondait aux E/S de fichiers vers le système de fichiers physique, mais depuis PhysicsFS 2.1, les applications peuvent fournir leurs propres implémentations d'E/S à l'exécution.

Cette interface n'est pas nécessairement un bon ajustement universel pour les E/S. Il y a quelques exigences notables :

  • Elles ne font que des E/S bloquantes (du moins, pour l'instant).
  • Elles doivent pouvoir être dupliquées. Si vous avez un descripteur de fichier de fopen(), vous devez pouvoir en créer un clone unique (afin que nous ayons deux descripteurs pour le même fichier qui peuvent tous deux chercher/lire/etc. sans se gêner).
  • Elles doivent connaître la taille de l'ensemble de leurs données.
  • Elles doivent pouvoir se positionner et rembobiner à la demande.

... en bref, vous n'allez probablement pas implémenter HTTP.

Sécurité des threads : Les implémentations de PHYSFS_Io ne sont pas garanties d'être sûres en elles-mêmes pour les threads. Sous le capot, lorsque PhysicsFS les utilise, la bibliothèque fournit ses propres verrous. Si vous prévoyez de les utiliser directement à partir de threads séparés, vous devriez soit utiliser des mutex pour les protéger, soit ne pas utiliser le même PHYSFS_Io à partir de deux threads en même temps.

void(* PHYSFS_Io::destroy) (struct PHYSFS_Io *io)

Nettoyer et désallouer l'instance d'E/S. Libérer les ressources associées, y compris (opaque) le cas échéant.

Cette fonction doit toujours réussir : en tant que telle, elle retourne void. Le système peut appeler votre méthode flush() avant cela. Vous pouvez y signaler un échec si nécessaire. Cette méthode peut toujours être appelée si flush() échoue, auquel cas vous devrez abandonner les données non vidées et autres conditions d'échec et nettoyer.

Une fois que cette méthode est appelée pour une instance donnée, le système supposera qu'il est dangereux de toucher à nouveau cette instance et supprimera toute référence à celle-ci.

Paramètres

s L'instance d'E/S à détruire.

struct PHYSFS_Io *(* PHYSFS_Io::duplicate) (struct PHYSFS_Io *io)

Dupliquer cette instance d'E/S. Cela doit aboutir à une copie complète de ce PHYSFS_Io, qui peut vivre complètement indépendamment. La copie doit être capable d'effectuer toutes ses opérations sans altérer l'original, y compris la destruction séparée de chaque objet (ainsi, par exemple : ils ne peuvent pas partager un descripteur de fichier ; chacun a besoin du sien).

Si vous ne pouvez pas dupliquer un descripteur, il est légal de retourner NULL, mais vous aurez presque certainement besoin de cette fonctionnalité si vous voulez utiliser ce PHYSFS_Io pour sauvegarder une archive.

Paramètres

io L'instance d'E/S à dupliquer.

Retourne

Une nouvelle valeur pour le champ (opaque) d'un flux, ou NULL en cas d'erreur.

int(* PHYSFS_Io::flush) (struct PHYSFS_Io *io)

Vider les ressources vers le média, ou ailleurs. C'est l'occasion de signaler les échecs pour les écritures qui avaient prétendu réussir plus tôt, mais qui avaient encore une chance d'échouer réellement. Cette méthode peut être NULL si le vidage n'est pas nécessaire.

Cette fonction peut être appelée avant destroy(), car elle peut signaler un échec et destroy() ne le peut pas. Elle peut être appelée à d'autres moments également.

Paramètres

io L'instance d'E/S à vider.

Retourne

Zéro en cas d'erreur, non nul en cas de succès.

PHYSFS_sint64(* PHYSFS_Io::length) (struct PHYSFS_Io *io)

Déterminer la taille de l'ensemble de données de l'instance d'E/S. Retourner le nombre d'octets disponibles dans le fichier, ou -1 si vous ne pouvez pas le déterminer. Un échec sera presque certainement fatal à une utilisation ultérieure de ce flux, vous ne pouvez donc pas laisser cela non implémenté.

Paramètres

io L'instance d'E/S à interroger.

Retourne

Taille totale, en octets, de l'ensemble de données.

void* PHYSFS_Io::opaque

Données d'instance pour cette structure. Chaque instance a un pointeur associé qui peut être utilisé pour stocker tout ce qu'elle aime. Ce pointeur est par instance de flux, il changera donc probablement lors de l'appel à duplicate(). Il peut être désalloué pendant la méthode destroy().

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buf, PHYSFS_uint64 len)

Lire plus de données. Lire (len) octets à partir de l'interface, à la position d'E/S actuelle, et les stocker dans (buffer). La position d'E/S actuelle doit avancer du nombre d'octets lus avec succès.

Vous n'êtes pas obligé d'implémenter cela ; définissez-le sur NULL si non implémenté. Ceci ne sera utilisé que si le fichier est ouvert en lecture. S'il est défini sur NULL, une implémentation par défaut qui signale immédiatement un échec sera utilisée.

Paramètres

io L'instance d'E/S à lire.
buf Le tampon pour stocker les données. Il doit avoir au moins (len) octets et ne peut pas être NULL.
len Le nombre d'octets à lire à partir de l'interface.

Retourne

nombre d'octets lus du fichier, 0 en fin de fichier, -1 en cas d'échec complet.

NAME

PHYSFS_Io - an abstract interface to read and write data.

SYNOPSIS

#include <physfs.h>

struct PHYSFS_Io {
    PHYSFS_uint32 version;
    PHYSFS_sint64 (*read) (struct PHYSFS_Io *io, void *buffer, PHYSFS_uint64 len);
    PHYSFS_sint64 (*write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len);
    PHYSFS_sint64 (*seek) (struct PHYSFS_Io *io, PHYSFS_uint64 offset);
    PHYSFS_sint64 (*tell) (struct PHYSFS_Io *io);
    void (*close) (struct PHYSFS_Io *io);
    void *opaque;
};

Detailed Description

This structure represents a handle to some form of input/output stream. It can be used to read data from archives, or to write to files. It's an abstract interface, so the underlying implementation doesn't matter to PhysFS itself. The only thing that matters is that the functions it points to work correctly.

The `opaque` field is for the user's private data. For example, if you were implementing a custom i/o driver, you might store a pointer to your file handle or other relevant data in this field.

Field Documentation

void(* PHYSFS_Io::close) (struct PHYSFS_Io *io)

Close the i/o stream. This function should free any resources associated with the stream, including the i/o structure itself if it was dynamically allocated.

Parameters

io The i/o instance to close.

void * PHYSFS_Io::opaque

A pointer for user-defined data. It is not used by PhysFS itself, but can be used by the i/o implementation to store context-specific data.

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buffer, PHYSFS_uint64 len)

Read more data. Read up to (len) bytes from the stream into (buffer). The current i/o position should advance by the number of bytes successfully read.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for reading. If set to NULL, a default implementation that immediately reports failure will be used.

Parameters

io The i/o instance to read from.
buffer The buffer to read data into. It must be at least (len) bytes long and can't be NULL.
len The maximum number of bytes to read.

Returns

number of bytes read, or -1 on error. A return value of 0 indicates end-of-file.

PHYSFS_sint64(* PHYSFS_Io::seek) (struct PHYSFS_Io *io, PHYSFS_uint64 offset)

Set the current i/o position. The offset is a byte offset from the beginning of the stream.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for reading or writing. If set to NULL, a default implementation that immediately reports failure will be used.

Parameters

io The i/o instance to seek within.
offset The new byte offset for the i/o position.

Returns

non-zero on success, zero on error.

PHYSFS_sint64(* PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Report current i/o position. Return bytes offset, or -1 if you aren't able to determine. A failure will almost certainly be fatal to further use of this stream, so you may not leave this unimplemented.

Parameters

io The i/o instance to query.

Returns

The current byte offset for the i/o position, -1 if unknown.

PHYSFS_uint32 PHYSFS_Io::version

Binary compatibility information. This must be set to zero at this time. Future versions of this struct will increment this field, so we know what a given implementation supports. We'll presumably keep supporting older versions as we offer new features, though.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Write more data. Write (len) bytes from (buffer) to the interface at the current i/o position. The current i/o position should move ahead by the number of bytes successfully written.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for writing. If set to NULL, a default implementation that immediately reports failure will be used.

You are allowed to buffer; a write can succeed here and then later fail when flushing. Note that PHYSFS_setBuffer() may be operating a level above your i/o, so you should usually not implement your own buffering routines.

Parameters

io The i/o instance to write to.
buffer The buffer to read data from. It must be at least (len) bytes long and can't be NULL.
len The number of bytes to read from (buffer).

Returns

number of bytes written to file, -1 if complete failure.
