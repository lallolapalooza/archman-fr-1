S

Les exemples suivants n'essaient pas de tout montrer car ce serait une tâche monumentale et, franchement, nous ne voulons pas que cette page man soit un document sur les internes de Perl. Les exemples démontrent quelques bases des types de données bruts de Perl, et devraient suffire à mettre la plupart des gens déterminés en route. Il n'y a pas de guide-fils, ni de filets de sécurité, ni de sentiers balisés, alors soyez prêt à voyager seul à partir de ce point et, si possible, ne tombez pas dans le sable mouvant (c'est mauvais pour les affaires)

.

Oh, un dernier conseil : emmenez perlguts avec vous. Quand vous reviendrez, nous attendons de le voir bien

corné.

Un scalaire chaîne

simple

Commençons par regarder un scalaire simple qui contient une

chaîne. 
use Devel::Peek;
$a = 42; $a = "hello";
Dump
$a;

La sortie

: 
SV = PVIV(0xbc288) at 0xbe9a8
  REFCNT = 1
  FLAGS = (POK,pPOK)
  IV = 42
  PV = 0xb2048 "hello"\0
  CUR = 5
  LEN =
8

Cela dit que $a est un SV, un scalaire. Le type de scalaire est un PVIV, qui est capable de contenir une valeur entière (IV) et/ou une chaîne (PV). L'en-tête du scalaire est alloué à l'adresse 0xbe9a8, tandis que le corps est à 0xbc288. Son comptage de références est 1. Il a le "POK"> drapeau défini, ce qui signifie que son champ PV actuel est valide. Comme POK est défini, nous regardons l'élément PV pour voir ce qui est dans le scalaire. Le \0 à la fin indique que ce PV est correctement terminé par NUL. Notez que le champ IV contient toujours son ancienne valeur numérique, mais parce que FLAGS n'a pas IOK défini, nous devons ignorer l'élément IV. CUR indique le nombre de caractères dans le PV. LEN indique le nombre d'octets alloués pour le PV (au moins un de plus que CUR, car LEN inclut un octet supplémentaire pour le marqueur de fin de chaîne, puis généralement arrondi à une unité d'allocation efficace).

Un scalaire numérique simple

Si le scalaire contient un nombre, le SV brut sera plus léger.

use Devel::Peek;
$a = 42;
Dump $a;

La sortie :

SV = IV(0xbc818) at 0xbe9a8
  REFCNT = 1
  FLAGS = (IOK,pIOK)
  IV = 42

Cela indique que $a est un SV, un scalaire. Le scalaire est un IV, un nombre. Son nombre de références est 1. Il a le drapeau "IOK" défini, ce qui signifie qu'il est actuellement évalué comme un nombre. Comme IOK est défini, nous regardons l'élément IV pour voir ce qui est dans le scalaire.

Un scalaire simple avec une référence supplémentaire

Si le scalaire de l'exemple précédent avait une référence supplémentaire :

use Devel::Peek;
$a = 42;
$b = \$a;
Dump $a;

La sortie :

SV = IV(0xbe860) at 0xbe9a8
  REFCNT = 2
  FLAGS = (IOK,pIOK)
  IV = 42

Remarquez que cet exemple ne diffère de l'exemple précédent que par son nombre de références. Comparez cela à l'exemple suivant, où nous vidons $b au lieu de $a.

Une référence vers un scalaire simple

Cela montre à quoi ressemble une référence lorsqu'elle pointe vers un scalaire simple.

use Devel::Peek;
$a = 42;
$b = \$a;
Dump $b;

La sortie :

SV = IV(0xf041c) at 0xbe9a0
  REFCNT = 1
  FLAGS = (ROK)
  RV = 0xbab08
  SV = IV(0xbe860) at 0xbe9a8
    REFCNT = 2
    FLAGS = (IOK,pIOK)
    IV = 42

En commençant par le haut, cela indique que $b est un SV. Le scalaire est un IV, qui est capable de contenir une valeur entière ou une référence. Il a le drapeau "ROK" défini, ce qui signifie que c'est une référence (plutôt qu'un entier ou une chaîne). Remarquez que Dump suit la référence et nous montre ce que $b référençait. Nous voyons le même $a que nous avons trouvé dans l'exemple précédent.

Notez que la valeur de "RV" coïncide avec les nombres que nous voyons lorsque nous convertissons en chaîne $b. Les adresses à l'intérieur de IV() sont des adresses de structures "X***" qui contiennent l'état actuel d'un "SV". Cette adresse peut changer pendant la durée de vie d'un SV.

Une référence vers un tableau

Cela montre à quoi ressemble une référence vers un tableau.

use Devel::Peek;
$a = [42];
Dump $a;

La sortie :

SV = IV(0xc85998) at 0xc859a8
  REFCNT = 1
  FLAGS = (ROK)
  RV = 0xc70de8
  SV = PVAV(0xc71e10) at 0xc70de8
    REFCNT = 1
    FLAGS = ()
    ARRAY = 0xc7e820
    FILL = 0
    MAX = 0
    FLAGS = (REAL)
    Elt No. 0
    SV = IV(0xc70f88) at 0xc70f98
      REFCNT = 1
      FLAGS = (IOK,pIOK)
      IV = 42

Cela indique que $a est une référence (ROK), qui pointe vers un autre SV qui est un PVAV, un tableau. Le tableau a un élément, l'élément zéro, qui est un autre SV. Le champ "FILL" ci-dessus indique le dernier élément dans le tableau, similaire à "$#$a".

Si $a pointait vers un tableau de deux éléments alors nous verrions ce qui suit.

use Devel::Peek 'Dump';
$a = [42,24];
Dump $a;

La sortie :

SV = IV(0x158c998) at 0x158c9a8
  REFCNT = 1
  FLAGS = (ROK)
  RV = 0x1577de8
  SV = PVAV(0x1578e10) at 0x1577de8
    REFCNT = 1
    FLAGS = ()
    ARRAY = 0x1585820
    FILL = 1
    MAX = 1
    FLAGS = (REAL)
    Elt No. 0
    SV = IV(0x1577f88) at 0x1577f98
      REFCNT = 1
      FLAGS = (IOK,pIOK)
      IV = 42
    Elt No. 1
    SV = IV(0x158be88) at 0x158be98
      REFCNT = 1
      FLAGS = (IOK,pIOK)
      IV = 24

Notez que "Dump" ne rapportera pas tous les éléments du tableau, seulement les premiers (selon la profondeur à laquelle il est déjà entré dans l'arborescence du rapport).

Une référence vers un hash

Ce qui suit montre la forme brute d'une référence vers un hash.

use Devel::Peek;
$a = {hello=>42};
Dump $a;

La sortie :

SV = IV(0x55cb50b50fb0) at 0x55cb50b50fc0
  REFCNT = 1
  FLAGS = (ROK)
  RV = 0x55cb50b2b758
  SV = PVHV(0x55cb50b319c0) at 0x55cb50b2b758
    REFCNT = 1
    FLAGS = (SHAREKEYS)
    ARRAY = 0x55cb50b941a0  (0:7, 1:1)
    hash quality = 100.0%
    KEYS = 1
    FILL = 1
    MAX = 7
    Elt "hello" HASH = 0x3128ece4
    SV = IV(0x55cb50b464f8) at 0x55cb50b46508
      REFCNT = 1
      FLAGS = (IOK,pIOK)
      IV = 42

Cela montre que $a est une référence pointant vers un SV. Ce SV est un PVHV, un hash.

La « qualité » d'un hash est définie comme le nombre total de comparaisons nécessaires pour accéder à chaque élément une fois, par rapport au nombre attendu pour un hash aléatoire. La valeur peut dépasser 100 %.

Le nombre total de comparaisons est égal à la somme des carrés du nombre d'entrées dans chaque seau. Pour un hash aléatoire de "<n"> clés dans "<k"> seaux, la valeur attendue est :

n + n(n-1)/2k

Vidage d'un grand tableau ou hash

La fonction Dump() , par défaut, vide jusqu'à 4 éléments d'un tableau ou hash de premier niveau. Ce nombre peut être augmenté en fournissant un second argument à la fonction.

use Devel::Peek;
$a = [10,11,12,13,14];
Dump $a;

Remarquez que Dump() n'imprime que les éléments 10 à 13 dans le code ci-dessus. Le code suivant imprimera tous les éléments.

use Devel::Peek 'Dump';
$a = [10,11,12,13,14];
Dump $a, 5;

Une référence vers un SV qui contient un pointeur C

C'est ce que vous avez vraiment besoin de savoir en tant que programmeur XS, bien sûr. Quand un XSUB retourne un pointeur vers une structure C, ce pointeur est stocké dans un SV et une référence vers ce SV est placée sur la pile de l'XSUB. Ainsi la sortie d'un XSUB qui utilise quelque chose comme le mappage T_PTROBJ pourrait ressembler à quelque chose comme ceci :

SV = IV(0xf381c) at 0xc859a8
  REFCNT = 1
  FLAGS = (ROK)
  RV = 0xb8ad8
  SV = PVMG(0xbb3c8) at 0xc859a0
    REFCNT = 1
    FLAGS = (OBJECT,IOK,pIOK)
    IV = 729160
    NV = 0
    PV = 0
    STASH = 0xc1d10       "CookBookB::Opaque"

Cela montre que nous avons un SV qui est une référence, qui pointe vers un autre SV. Dans ce cas, ce second SV est un PVMG, un scalaire béni. Parce qu'il est béni, il a le drapeau "OBJECT" défini. Notez qu'un SV qui contient un pointeur C a aussi le drapeau "IOK" défini. Le "STASH" est défini au nom du paquet dans lequel ce SV a été béni.

La sortie d'un XSUB qui utilise quelque chose comme le mappage T_PTRREF, qui ne bénit pas l'objet, pourrait ressembler à quelque chose comme ceci :

SV = IV(0xf381c) at 0xc859a8
  REFCNT = 1
  FLAGS = (ROK)
  RV = 0xb8ad8
  SV = PVMG(0xbb3c8) at 0xc859a0
    REFCNT = 1
    FLAGS = (IOK,pIOK)
    IV = 729160
    NV = 0
    PV = 0

Une référence vers une sous-routine

Ressemble à ceci :

SV = IV(0x24d2dd8) at 0x24d2de8
  REFCNT = 1
  FLAGS = (TEMP,ROK)
  RV = 0x24e79d8
  SV = PVCV(0x24e5798) at 0x24e79d8
    REFCNT = 2
    FLAGS = ()
    COMP_STASH = 0x22c9c50      "main"
    START = 0x22eed60 ===> 0
    ROOT = 0x22ee490
    GVGV::GV = 0x22de9d8        "MY" :: "top_targets"
    FILE = "(eval 5)"
    DEPTH = 0
    FLAGS = 0x0
    OUTSIDE_SEQ = 93
    PADLIST = 0x22e9ed8
    PADNAME = 0x22e9ec0(0x22eed00) PAD = 0x22e9ea8(0x22eecd0)
    OUTSIDE = 0x22c9fb0 (MAIN)

Cela montre que

  • la sous-routine n'est pas un XSUB (puisque "START" et "ROOT" sont non nuls, et "XSUB" n'est pas listé, et est donc nul) ;
  • qu'elle a été compilée dans le paquet "main";
  • sous le nom "MY::top_targets";
  • à l'intérieur d'un 5e eval dans le programme ;
  • elle n'est pas actuellement en cours d'exécution (parce que "DEPTH" est 0) ;
  • elle n'a pas de prototype (le champ"PROTOTYPE" est absent).
