NOM

daxctl-create-device - Créer un périphérique devdax

SYNTAXE

daxctl create-device [<options>]

EXEMPLES

•Crée dax0.1 d'une taille de 4G
# daxctl create-device -s 4G
[
  {
    "chardev":"dax0.1",
    "size":4294967296,
    "target_node":0,
    "mode":"devdax"
  }
]
•Crée des périphériques avec la taille entièrement disponible sur toutes les régions
# daxctl create-device -u
[
  {
    "chardev":"dax0.1",
    "size":"15.63 GiB (16.78 GB)",
    "target_node":0,
    "mode":"devdax"
  },
  {
    "chardev":"dax1.1",
    "size":"15.63 GiB (16.78 GB)",
    "target_node":1,
    "mode":"devdax"
  }
]
•Crée dax0.1 avec la taille entièrement disponible sur la région id 0
# daxctl create-device -r 0 -u
{
  "chardev":"dax0.1",
  "size":"15.63 GiB (16.78 GB)",
  "target_node":0,
  "mode":"devdax"
}

DESCRIPTION

Crée un périphérique dax en mode devdax dans des régions dynamiques. Le résultat peut également être converti en mode system-ram qui organise la plage dax pour qu'elle soit hot-plugged dans le système en tant que mémoire ordinaire.

daxctl create-device s'attend à ce que le BIOS ou le noyau définisse une plage dans la carte mémoire EFI avec EFI_MEMORY_SP. Les plages résultantes impliquent que sa capacité à 100% est réservée aux applications.

OPTIONS

-r, --region=

Restreint l'opération aux périphériques appartenant aux régions spécifiées. Une région dax-périphérique est une plage de mémoire contiguë qui héberge un ou plusieurs périphériques /dev/daxX.Y, où X est l'identifiant de la région et Y est l'identifiant de l'instance du périphérique.

-s, --size=

Pour les régions qui prennent en charge la création de périphériques dax, définit la taille du périphérique en octets. Sinon, elle défaut à la taille maximale spécifiée par la région. Cette option prend en charge les suffixes "k" ou "K" pour KiB, "m" ou "M" pour MiB, "g" ou "G" pour GiB et "t" ou "T" pour TiB. 
La taille doit être un multiple de l'alignement de la région.

-a, --align

Les applications qui souhaitent établir des mappages de mémoire dax avec des entrées de table de pages supérieures à la taille de page de base du système (4 Ko sur x86) nécessitent un périphérique suffisamment aligné. Cela est par défaut à 2 Mo. Notez que le mode "devdax" impose que tous les mappages soient alignés sur cette valeur, c'est-à-dire qu'il échoue aux tentatives de mappage non alignées.

--input

Les applications qui souhaitent sélectionner les plages attribuées à une instance dax-périphérique, ou qui souhaitent établir des périphériques créés précédemment, peuvent passer un fichier d'entrée JSON. L'option de fichier permet à un utilisateur de passer un objet JSON similaire à celui répertorié avec "daxctl list". 
Le nom du périphérique n'est pas recréé, mais si un "chardev" est passé
dans le fichier JSON, il sera utilisé pour obtenir l'identifiant de la
région.
Notez que le contenu JSON dans le fichier ne peut pas être un tableau
d'objets JSON mais plutôt un seul objet JSON, c'est-à-dire sans les
crochets englobant le tableau.

-u, --human

Par défaut, la commande affichera des données brutes et lisibles par machine. Au lieu de cela, avec ce drapeau, les nombres représentant la taille du stockage seront formatés en chaînes lisibles par l'homme avec des unités, d'autres champs seront convertis en chaînes hexadécimales.

-v, --verbose

Afficher plus de messages de débogage
