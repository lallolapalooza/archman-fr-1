PRÉFAC

E

Fondamentalement, Date::Calendar n'est qu'une classe de proxy avec cache pour les objets Date::Calendar::Year, qui sont intégrés dans chaque objet Date::

Calendar.

Cependant, et contrairement aux méthodes de Date::Calendar::Year, les méthodes de Date::Calendar permettent des calculs s'étendant sur un nombre arbitraire d'années, sans perte

d'efficacité.

Vous devriez donc généralement utiliser Date::Calendar et non Date::Calendar::Year, car de cette façon vous n'avez pas à vous soucier des calculs traversant les limites

d'année.

Notez cependant que Date::Calendar et Date::Cal

endar::Year ne peuvent traiter que des ann
ées situées dans l'intervalle [1583..2299].

INTERFAC

E

Notez que chaque fois qu'un numéro d'année, une date, une heure ou une date et heure combinées sont attendus comme paramètres d'entrée par l'une des méthodes de cette classe, vous pouvez toujours passer un objet date Date::Calc[::Object] ou une référence de tableau (d'un tableau de longueur appropriée) à la place

!

Voir Date::Calc::Object(3) pour plus de

détails.

Ainsi, au lieu d'appeler une méthode donnée comme ceci

: 
$object->method1( $year,$month,$day );
$object->method2( $year1,$month1,$day1, $year2,$month2,$day2 );
$object->method3( $year1, $year2, $year3 )
;

Vous pouvez aussi l'appeler ainsi

: 
$object->method1( $date );
$object->method1( [1964,1,3] );
$object->method2( $year1,$month1,$day1, $date2 );
$object->method2( $date1, $year2,$month2,$day2 );
$object->method2( $date1, $date2 );
$object->method2( $year1,$month1,$day1, [2001,3,17] );
$object->method2( [1964,1,3], $year2,$month2,$day2 );
$object->method2( [1964,1,3], [2001,3,17] );
$object->method2( $date1, [2001,3,17] );
$object->method2( [1964,1,3], $date2 );
$object->method3( $year1, $date2, [2001,3,17] )
;

Et de même si une heure ou une date et heure combinées sont

attendues.

Si vous remplacez un numéro d'année attendu par un tableau anonyme (c'est la manière recommandée d'écrire des constantes de date, pour une meilleure lisibilité de vos programmes), il doit néanmoins contenir trois valeurs (sinon l'utilisation d'un tableau anonyme serait inutile)

.

Ne confondez pas les numéros d'année et leurs substituts (un objet date ou une référence de tableau) avec les objets Date::Calendar::Year, qui sont quelque chose de totalement différent

!

Mais incidemment ":-)", vous pouvez aussi passer un objet Date::Calendar::Year chaque fois qu'un numéro d'année est attendu. Cependant, et peut-être contrairement à vos attentes parfois, surtout en conjonction avec la méthode "cache_add()", seul le numéro d'année de cet objet sera utilisé, pas l'objet année lui-même (l'objet année en question pourrait utiliser le mauvais profil !)

.

De plus, chaque fois qu'une méthode de cette

classe renvoie une date, elle le fait en
renvoyant un objet date Date::Calc[::Object].

  • "$calendar = Date::Calendar->new(PROFILE[,LANG[,WEEKEND]]);"

    Le premier argument doit être la référence d'un hachage, qui contient un schéma de jours fériés ou un « profil » à utiliser dans toutes les calculs impliquant le nouvel objet

    calendrier.

    Le deuxième argument est facultatif et doit être constitué du nom ou du numéro valide d'une langue tel que fourni par le Date::Calc(3) module s'il est

    donné.

    Après le deuxième argument, une liste de numéros de jours qui constitueront le « week-end » peut être spécifiée facultativement, où 1=lundi, 2=mardi, 3=mercredi, 4=jeudi, 5=vendredi, 6=samedi et

    7=dimanche.

    Si aucune valeur n'est donnée, 6 et 7 (samedi et dimanche) sont automatiquement pris par

    défaut.

    Si des valeurs en dehors de l'intervalle 1..7 sont données, elles seront

    ignorées.

    Cela peut être utilisé pour désactiver cette fonctionnalité et n'avoir aucun jour férié régulièrement récurrent du tout, par exemple lorsqu'un zéro est

    donné.

    Voir Date::Calendar::Profiles(3) et Date::Calendar::Year(3) pour plus de détails sur ces arguments et sur la manière de créer vos propres profils de

    calendrier.

    La méthode crée un nouvel objet calendrier pour un profil donné, c'est-à-dire un emplacement donné et son schéma de jours fériés (ou un schéma de votre

    choix).

    Cet objet calendrier est un objet proxy avec cache ; il stocke la référence du profil donné et contient un hachage (le cache) d'objets Date::Calendar:

    :
    • Year.
  • "$year = $calendar->year(YEAR|DATE);"

    Cette méthode renvoie un objet Date::Calendar::Year pour l'année donnée et le profil qui a été associé à l'objet calendrier

    donné.

    renvoyée.

    Sinon, un nouvel objet Date::Calendar::Year est créé en utilisant le profil qui a été associé à l'objet calendrier donné. Le nouvel objet Date::Calendar::Year est ensuite stocké dans le cache de l'objet calendrier et sa référence d'objet est

    renvoyée.

    • 2299].

    Si des arguments sont donnés, ils sont censés représenter une date. Dans ce cas, une liste de tous les libellés (= noms des jours fériés) associés à cette date est renvoyée. Le premier élément renvoyé est toujours le nom du jour de la semaine pour cette date. L'objet année correspondant pour l'année de la date donnée est ajouté au cache du calendrier en premier si

    nécessaire.

    Si aucun argument n'est donné, la liste de tous les libellés disponibles dans toutes les années qui ont été précédemment accédées dans le calendrier donné (c'est-à-dire les années qui sont déjà dans le cache du calendrier donné) est construite. Notez que cela signifie que la liste renvoyée sera vide s'il n'y a pas encore d'objets année dans le cache du calendrier donné (!). La liste renvoyée ne contient PAS de noms de jours de la semaine (ce qui serait sans objet dans ce

    cas).

    Les libellés multiples ne sont rapportés qu'une seule

    fois.

    Habituellement, toutes les années ont le même ensemble de libellés, il peut donc sembler superflu de parcourir toutes les années du cache au lieu d'une seule. Mais il peut y avoir des exceptions, car il est possible de définir des profils de calendrier qui ne contiennent pas tous les jours fériés possibles dans chaque année. Voir Date::Calendar::Profiles(3) et Date::Calendar::Year(3) pour plus de

    En contexte liste, la liste résultante elle-même est

  • "$hashref = $calendar->tags(YEAR,MONTH,DAY|DATE);"

    Cette méthode renvoie une référence de hachage pour le calendrier et la date donnés. Le hachage auquel elle fait référence est une copie du hachage interne du profil de calendrier qui contient les noms pour la date donnée comme clés et 0, 1, 2 ou 3 comme leurs valeurs correspondantes signifiant ce

    qui suit : 
    0    =>    jour commémoratif
1    =>    jour férié « demi-journée »
2    =>    jour férié « complet »
3    =>    à la fois un jour férié « demi-journée » et «
    complet »

    La valeur « 3 » ne devrait apparaître que si une date a été re

    définie par le profil sous-jacent utilisant la même clé (c'est-
    • à-dire le même nom) mais avec un type de jour férié différent.
  • "$days = $calendar->delta_workdays(YEAR1,MONTH1,DAY1, YEAR2,MONTH2,DAY2, FLAG1,FLAG2);"

    "$days = $calendar->delta_workdays(DATE1,DATE2,FLAG1,

    FLAG2);"

    Cette méthode calcule le nombre de jours ouvrables (c'est-à-dire le nombre de jours, mais en excluant tous les jours fériés) entre deux

    dates.

    En d'autres termes, cette méthode est équivalente à la fonction "Delta_Days()" du module Date::Calc, sauf qu'elle ignore les jours fériés dans son

    décompte.

    Les deux indicateurs indiquent si les dates de début et de fin doivent être incluses dans le décompte (ce qui, bien sûr, n'est le cas que si ce ne sont pas des jours fériés), ou

    non.

    Il est courant, par exemple, de vouloir savoir combien de jours ouvrables restent entre la date actuelle et une date limite

    donnée.

    Typiquement, vous voudrez compter la date actuelle mais pas la date limite. Vous spécifieriez donc « true » (« 1 ») pour FLAG1 et « false » (« 0 ») pour FLAG2 afin d'obtenir

    cela.

    En d'autres termes, une valeur de « true » signifie « inclure cette date », une valeur de « false » signifie « exclure cette

    date ».

    Comme avec la fonction "Delta_Days()" du module Date::Calc, les dates doivent être données dans l'ordre chronologique pour obtenir un résultat positif. Si les dates sont inversées, le résultat sera

    négatif.

    Le paramètre FLAG1 est associé à la première date donnée, le paramètre FLAG2 à la seconde date donnée (que les dates soient dans l'ordre chronologique ou

    non).

    Une exception (« invalid date ») est

    levée si l'un des deux arguments de d
    • ate ne constitue pas une date valide.
  • "($date,$rest) = $calendar->add_delta_workdays(YEAR,MONTH,DAY, DELTA);"

    "($date,$rest) = $calendar->add_delta_workdays(DATE,

    DELTA);"

    "$date = $calendar->add_delta_workdays(YEAR,MONTH,DAY,

    DELTA);"

    "$date = $calendar->add_delta_workdays(DATE,

    DELTA);"

    Cette méthode est l'équivalent de la fonction "Add_Delta_Days()" du module Date::Calc, sauf qu'elle ajoute des jours ouvrables et saute les jours

    fériés.

    En d'autres termes, vous pouvez ajouter ou soustraire un nombre de jours ouvrables « DELTA » à/à partir d'une date donnée et obtenir une nouvelle date comme résultat (comme un objet Date::

    Calc).

    Vous ajoutez des jours (c'est-à-dire que vous avancez dans le temps) avec un décalage positif « DELTA », et vous soustrayez des jours (c'est-à-dire que vous reculez dans le temps) avec un décalage

    négatif.

    Notez qu'une exception (« invalid date ») est levée si l'argument de date donné ne constitue pas une date

    valide.

    En contexte scalaire, la méthode renvoie simplement l'objet date résultant, alors qu'en contexte liste, la méthode renvoie non seulement la nouvelle date, mais aussi un « reste ». Ce reste est utile dans les cas où votre profil contient des jours fériés « demi-journée », ou lorsque vous ajoutez ou soustrayez des fractions de

    jour.

    Parfois, il n'est pas possible d'accommoder le nombre demandé de jours ouvrables, et un reste

    subsiste.

    Ce reste ne peut actuellement prendre que la valeur « 0.0 » (zéro), « -0.5 » (moins un demi) ou « 0.5 » (un demi), à condition que vous n'utilisiez que des décalages entiers ou des multiples de 0.5. Un reste de zéro indique que le calcul a donné un résultat exact. Si le reste est 0.5 ou -0.5, cela doit être interprété comme « la date résultante à 12:00 heures », au lieu de « la date résultante à 0:00 heures

    ».

    Le reste est toujours positif (ou zéro) si le décalage « DELTA » est positif (ou zéro), et toujours négatif (ou zéro) si le décalage est négatif (ou

    zéro).

    Exemple

    : 
    #!perl
use Date::Calendar;
use Date::Calendar::Profiles qw( $Profiles );
$year = shift;
$cal = Date::Calendar->new( $Profiles->{'sdm-MUC'} );
($date,$rest) = $cal->add_delta_workdays($year,1,3, -3);
$date->date_format(1);
print "\$date = $date, \$rest = $rest.\n";
    __END__

    Ce programme calcule « le 3 janvier de l'année donnée moins 3 jours

    ouvrables » : 
    > perl test.pl 2001
$date = 28-Dec-2000, $rest = 0.
> perl test.pl 2002
$date = 28-Dec-2001, $rest =
    -0.5.

    Notez que le 31 décembre est un jour férié « demi-journée » en 2001 pour le profil de calendrier utilisé dans cet

    exemple.

    Vous pouvez facilement vérifier les résultats ci-dessus à l'aide du script CGI « calendar.cgi » ou du script « linearcal.pl » du sous-répertoire « examples » de la distribution Date::

    Calc.

    ATTENTION, cette méthode peut actuellement renvoyer des résultats inattendus (c'est-à-dire contredisant la documentation ci-dessus) ou carrément erronés lorsqu'on recule dans le temps (c'est un

    bug !).

    Cependant, elle fonctionne correc

    tement et comme documenté ci-dessu
    • s lorsqu'on avance dans le temps.
  • "$flag = $calendar->is_full(YEAR,MONTH,DAY|DATE);"

  • "$flag = $calendar->is_work(YEAR,MONTH,DAY|DATE);"

    Cette méthode renvoie "true" ("1") si le bit correspondant à la date donnée est défini dans le vecteur de bits utilisé pour effectuer toutes sortes de calculs, et "false" ("0")

    sinon.

    L'objet Date::Calendar::Year correspondant est d'abord créé et stocké dans le cache de l'objet calendrier si nécessaire (s'il n'est pas déjà

    présent).

    ATTENTION, le "work" dans le nom de cette méthode ne provient PAS de "work days" (jours

    ouvrables) !

    Il provient du fait que le vecteur de bits correspondant peut être utilisé pour tout "travail" que vous devez effectuer. En d'autres termes, c'est un "espace de

    travail".

    Par conséquent, ce vecteur de bits pourrait contenir à peu près tout ce que vous pouvez imaginer - y compris un motif de bits qui marque tous les "jours ouvrables" avec des bits définis, si tel est le

    cas !

    Mais il vaut mieux ne pas vous y fier, à moins que vous n'y placiez le motif de bits vous-même au

    départ.

    Notez que vous pouvez obtenir une référence à ce vecteur de bits (afin de le remplir avec le motif de bits de votre choix)

    comme suit :

LIMITATION

S

délité hi
