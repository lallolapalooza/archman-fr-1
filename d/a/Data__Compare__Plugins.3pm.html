NOM

Data::Compare::Plugins - comment étendre Data::Compare

DESCRIPTION

Data::Compare gère nativement plusieurs types de données intégrés : scalaires, références à des scalaires, références à des tableaux, références à des hachages, références à des sous-routines, expressions régulières compilées et globs. Pour les objets, il essaie de faire la bonne chose et compare le type de données sous-jacent. Cependant, ce n'est pas toujours ce que vous voulez. C'est particulièrement vrai si vous avez des objets complexes qui surchargent la stringification et/ou la numification.

Nous autorisons donc des plugins.

TROUVER DES PLUGINS

Data::Compare essaiera de charger tout module installé sur votre système dans les divers répertoires @INC/Data/Compare/Plugins/. S'il y a un problème lors du chargement de l'un d'eux, un avertissement approprié sera émis.

En raison de la manière dont nous trouvons les plugins, aucun plugin n'est disponible lors de l'exécution en mode "taint".

ECRIRE DES PLUGINS

En interne, les plugins sont "require"d dans Data::Compare. Cela signifie qu'ils doivent s'évaluer à vrai. Nous utilisons cette valeur vraie. Là où normalement vous mettez juste :

1;

à la fin d'un fichier inclus, vous devriez plutôt vous assurer que vous retournez une référence à un tableau. Ceci est traité comme étant vrai, donc satisfait perl, et est considérablement plus utile.

À l'intérieur de ce tableau devrait se trouver soit une description de ce que ce plugin est censé faire, soit des références à plusieurs tableaux contenant de telles descriptions. Une description se compose de deux ou trois éléments. Premièrement, une chaîne nous indiquant quel est le premier type de données géré par votre plugin. Deuxièmement, (et facultatif, par défaut le même que le premier) le deuxième type de données à comparer. Pour gérer les comparaisons avec des scalaires ordinaires, donnez une chaîne vide pour le type de données, c'est-à-dire :

['MonType', '', sub { ...}]

Troisièmement et dernier, nous avons besoin d'une référence à la sous-routine qui effectue la comparaison. Cette sous-routine doit s'attendre à recevoir deux paramètres, qui seront du type spécifié. Elle doit retourner 1 s'ils sont identiques, ou 0 s'ils sont différents.

Soyez conscient que bien que vous puissiez donner une description comme :

['Type1', 'Type2', sub { ... }]

cela gérera à la fois la comparaison de Type1 à Type2, et de Type2 à Type1. C'est-à-dire que la comparaison est commutative.

Si vous souhaitez utiliser la propre fonction de comparaison de Data::Compare depuis votre gestionnaire (pour, par exemple, comparer une structure de données que vous avez stockée quelque part dans votre objet), vous devrez l'appeler comme Data::Compare::Compare. Cependant, vous devez faire attention à éviter la récursion infinie en appelant D::C::Compare qui à son tour rappelle votre gestionnaire.

Le nom de vos plugins n'a pas d'importance, seulement qu'il se trouve dans l'un de ces répertoires. Bien sûr, lui donner un nom sensé signifie que les mécanismes d'installation habituels le placeront au bon endroit, et des noms significatifs rendront votre code plus facile à déboguer.

Pour un exemple, regardez le plugin qui gère les objets Scalar::Properties, qui est distribué avec Data::Compare.

DISTRIBUTION

À condition que les règles ci-dessus soient suivies, je ne vois pas de raison pour que vous n'uploadiez pas votre plugin sur CPAN vous-même. Vous devrez faire de Data::Compare une pré-requête, afin que l'installateur de CPAN.pm fasse la bonne chose.

Alternativement, si vous préférez que j'intègre votre plugin dans la distribution Data::Compare, je serais heureux de le faire à condition que le code soit clair et bien commenté, et que vous inclusiez des tests et de la documentation.
