Data::Dump::Filtered(3) Documentation Perl fournie par l'utilisateur Data::Dump::Filtered(3)

NOM

Data::Dump::Filtered - Impression soignée avec filtrage

DESCRIPTION

Les fonctions suivantes sont fournies :

add_dump_filter( \&filter )
Enregistre une fonction de filtre à utiliser par la fonction régulière Data::Dump::dump(). Par défaut, aucun filtre n'est actif.

Étant donné que l'enregistrement de filtres a un effet global, il peut être plus approprié d'utiliser la fonction dump_filtered() à la place.

remove_dump_filter( \&filter )
Désenregistre la fonction de rappel donnée en tant que fonction de rappel de filtre. Cela annule l'effet de add_filter.
dump_filtered(..., \&filter )
Fonctionne comme Data::Dump::dump(), mais le dernier argument doit être une fonction de rappel de filtre. Lorsque les objets sont visités, la fonction de rappel de filtre est appelée et peut influencer la manière dont les objets sont imprimés.

Tous les filtres enregistrés avec add_filter() sont ignorés lorsque cette interface est appelée. En fait, passer "undef" comme \&filter est autorisé et "dump_filtered(..., undef)" est la manière officielle de forcer les impressions non filtrées.

Fonction de rappel de filtre

Une fonction de rappel de filtre est une fonction qui sera appelée avec 2 arguments ; un objet de contexte et une référence vers l'objet en cours de visite. La valeur de retour doit être une référence de hachage ou "undef".

sub filter_callback {
    my($ctx, $object_ref) = @_;
    ...
    return { ... }
}

Si la fonction de rappel de filtre retourne "undef" (ou rien), le traitement et le formatage normaux de l'objet visité se produisent. Si la fonction de rappel de filtre retourne un hachage, il peut remplacer ou annoter la représentation de l'objet actuel.

Contexte de filtre

L'objet de contexte fournit des méthodes qui peuvent être utilisées pour déterminer quel type d'objet est actuellement visité et où il se trouve. L'objet de contexte a l'interface suivante :

$ctx->object_ref
Moyen alternatif d'obtenir une référence vers l'objet actuel
$ctx->class
Si l'objet est "blessed", cela retourne la classe. Retourne "" pour les objets non "blessed".
$ctx->reftype
Retourne le type d'objet. C'est une chaîne comme "SCALAR", "ARRAY", "HASH", "CODE",...
$ctx->is_ref
Retourne vrai si une référence a été fournie.
$ctx->is_blessed
Retourne vrai si l'objet est "blessed". En fait, c'est juste un alias pour "$ctx->class".
$ctx->is_array
Retourne vrai si l'objet est un tableau.
$ctx->is_hash
Retourne vrai si l'objet est un hachage.
$ctx->is_scalar
Retourne vrai si l'objet est un scalaire (une chaîne ou un nombre).
$ctx->is_code
Retourne vrai si l'objet est une fonction (ou sous-routine).
$ctx->container_class
Retourne la classe du conteneur le plus interne qui contient cet objet. Retourne "" s'il n'y a pas de conteneur "blessed".
$ctx->container_self
Retourne une expression textuelle relative à l'objet conteneur qui nomme cet objet. La variable $self dans cette expression est le conteneur lui-même.
$ctx->object_isa( $class )
Retourne VRAI si l'objet actuel est de la classe donnée ou d'une sous-classe.
$ctx->container_isa( $class )
Retourne VRAI si le conteneur le plus interne est de la classe donnée ou d'une sous-classe.
$ctx->depth
Retourne la profondeur de récursion dans la structure (à partir des arguments originaux de dump_filtered()).
$ctx->expr
$ctx->expr( $top_level_name )
Retourne une expression textuelle qui désigne l'objet actuel. Dans l'expression, $var est utilisé comme nom de l'objet de niveau supérieur imprimé. Ceci peut être remplacé en fournissant un nom différent comme argument.

Hachage de retour de filtre

Les éléments suivants ont une importance dans le hachage retourné :

dump => $string
incorpore la chaîne donnée comme représentation de la valeur actuelle
object => $value
imprime la valeur donnée au lieu de celle visitée et passée comme $object. Essentiellement la même chose que de spécifier "dump => Data::Dump::dump($value)".
comment => $comment
préfère la valeur avec la chaîne de commentaire donnée
bless => $class
fait comme si l'objet actuel était de la classe donnée $class au lieu de la classe qu'il a réellement (le cas échéant). Les internes de l'objet sont imprimés de manière régulière. La $class peut être une chaîne vide pour faire croire à Data::Dump que l'objet n'était pas "blessed" du tout.
hide_keys => ['key1', 'key2',...]
hide_keys => \&code
Si l'$object est un hachage, il est imprimé normalement mais fait comme si les clés listées n'existaient pas. Si l'argument est une fonction, alors la fonction est appelée pour déterminer si la clé donnée doit être cachée.
