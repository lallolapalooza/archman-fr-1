NOM

Data::Grove::Visitor - ajoute des méthodes de visiteur/rappel aux objets Data::Grove

SYNTAXE

use Data::Grove::Visitor;
@resultats = $objet->accept ($visiteur, ...);
@resultats = $objet->accept_name ($visiteur, ...);
@resultats = $objet->children_accept ($visiteur, ...);
@resultats = $objet->children_accept_name ($visiteur, ...);

DESCRIPTION

Data::Grove::Visitor ajoute des méthodes de visiteur (rappel) aux objets Data::Grove. Un « visiteur » est une classe (un paquet) que vous écrivez et qui possède des méthodes (subs) correspondant aux objets des classes visitées. Vous utilisez les méthodes du visiteur en créant une instance de votre classe visiteur, puis en appelant `accept($mon_visiteur)' sur l'objet le plus haut niveau que vous souhaitez visiter. Cet objet appellera à son tour votre visiteur avec la méthode `"visit_OBJET"', où OBJET est le type de l'objet.

Il existe plusieurs formes de `"accept"'. Appeler simplement `"accept"' appelle votre paquet avec le type d'objet que vous visitez. Appeler `"accept_name"' sur un objet élément vous appelle avec la méthode `"visit_name_NOM"' où NOM est le nom de balise de l'élément, sur tous les autres objets, cela équivaut à appeler `"accept"'.

Toutes les formes de `"accept"' retournent une liste concaténée du résultat de toutes les méthodes `"visit"'.

`"children_accept"' appelle `"accept"' sur chacun des enfants de l'élément. Ceci est généralement utilisé dans les rappels d'élément pour récursivement descendre dans les enfants de l'élément ; vous n'avez pas besoin d'obtenir le contenu de l'élément et d'appeler `"accept"' sur chaque élément. `"children_accept_name"' fait la même chose mais appelle `"accept_name"' sur chacun des enfants. `"attr_accept"' appelle `"accept"' sur chacun des objets de l'attribut nommé.

Référez-vous à la documentation des classes que vous visitez (XML::Grove, etc.) pour les noms de types (`"element"', `"document"', etc.) des objets qu'elle implémente.

NOMS RÉSERVÉS

Les clés de hachage `"Contents"' et `"Name"' sont utilisées pour indiquer les objets avec des enfants (pour `"children_accept"') et les objets nommés (pour `"accept_name"').

NOTES

Ce sont des idées aléatoires qui n'ont pas encore été implémentées :

•
Plusieurs objets appartiennent à des sous-classes, ou vous pouvez vouloir sous-classer un objet visité et toujours pouvoir faire la différence. Dans SGML::Grove, j'avais utilisé le nom du paquet dans le rappel (`"visit_SGML_Element"') au lieu d'un nom générique (`"visit_element"'). L'idée ici serait d'essayer d'appeler `"visit_PAQUET"' en commençant par la classe la plus spécifique, puis d'essayer les superclasses, et enfin d'essayer le générique.
