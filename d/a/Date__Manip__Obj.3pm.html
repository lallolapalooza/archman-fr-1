MÉTHODES POUR CRÉER DES

OBJETS

Dans les exemples ci-dessous, toute variable nommée une variation de $date ($date, $date1, $date2, ...) est un objet Date::Manip::Date. De même, $delta, $recur, $tz et $base font référence à des objets de la classe

appropriée.

Toute variable $obj fait référence à un objet de n'importe laquelle des

classes.
ne
w
Il y a deux façons d'utiliser la méthode new. Elles sont : 
$obj2  = new CLASS ($obj1,$string,@parse_opts,\@opts);
$obj2  = $obj1->new($string,@parse_opts,
\@opts)

Dans les deux cas, tous les arguments sont

optionnels.

Les deux méthodes sont utilisées pour créer un nouvel objet d'une classe donnée. Dans le premier cas, CLASS est la classe du nouvel objet. Par

exemple : 
$date  = new Date::Manip::Date;
$delta = new Date::Manip::
Delta;

Dans la deuxième méthode, la classe du nouvel objet sera dérivée du premier objet. Par

exemple : 
$date1 = new Date::Manip::Date;
$date2 = $date1->
new();

la classe du deuxième objet ($date2) est Date::Manip::Date car c'est la classe de l'objet ($date1) utilisé pour le

créer.

Dans la première méthode (quand un $obj1 est passé) et toujours dans la deuxième méthode, le nouvel objet partagera autant d'informations que possible de l'ancien objet ($obj1

).

Par exemple, si vous appelez l'une ou l'autre de ces

commandes : 
$date2 = new Date::Manip::Date $date1;
$date2 = $date1->
new();

le nouvel objet date utilisera les mêmes objets Date::Manip::TZ et Date::Manip::Base

intégrés.

Lorsque vous spécifiez CLASS et incluez un ancien objet, les objets n'ont pas besoin d'être de la même classe. Par exemple, les suivants sont tous

valides : 
$date = new Date::Manip::Date $delta;
$date = new Date::Manip::Date
$tz;

Vous pouvez même

faire : 
$date = new Date::Manip::Date
$base;

mais cela devra créer un objet Date::Manip::TZ complètement nouveau, ce qui signifie qu'une performance optimale pourrait ne pas être atteinte si un objet Date::Manip::TZ existe

déjà.

Il y a deux cas particuliers. L'un ou l'autre des suivants créera un nouvel objet Date::Manip::Base pour gérer plusieurs

configurations : 
$base2 = new Date::Manip::Base $base1;
$base2 = $base1->
new();

L'un ou l'autre des suivants créera un nouvel objet Date::Manip::TZ avec le même objet Date::Manip::Base

intégré : 
$tz2   = new Date::Manip::TZ $tz1;
$tz2   = $tz1->
new();

Le nouvel objet base aura initialement la même configuration que l'objet base original, mais changer sa configuration n'affectera pas l'objet base

original.

Si l'argument "\@opts" est passé, il s'agit d'une référence de liste contenant une liste convenant à être passée à la méthode config (décrite ci-dessous). Dans ce cas, un nouvel objet Date::Manip::Base (et peut-être un objet Date::Manip::TZ) sera créé. Le nouvel objet Base commencera comme identique à l'original (si un objet défini précédemment a été utilisé pour créer le nouvel objet) avec les options supplémentaires dans @opts ajou

tées.

En d'autres termes, les suivants sont

équivalents : 
$date  = new Date::Manip::Date $obj,\@opts;
$base  = $obj->base();
$base2 = $base->new();
$date = new Date::Manip::Date $base2;
$date->config(@opts)
;

Il convient de noter que les options sont appliquées au NOUVEL objet Date::Manip::Base, pas à

l'ancien.

Une chaîne optionnelle ($string et options de parse @parse_opts) ne peut être passée que lors de la création d'un objet Date::Manip::Date, Date::Manip::Delta ou Date::Manip::Recur. Si elle est passée lors de la création d'un objet Date::Manip::TZ ou Date::Manip::Base, un avertissement sera émis, mais l'exécution

continuera.

Si la chaîne est incluse, elle sera analysée pour donner une valeur initiale à l'objet. Cela ne sera fait qu'APRÈS que toutes les options aient été traitées, donc les suivants sont

équivalents : 
$date = new Date::Manip::Date $string,@parse_opts,\@opts;
$date = new Date::Manip::Date;
$date->config(@opts);
$date->parse($string,@parse_opts)
;

Une fois qu'un objet Date::Manip::Date (ou tout objet dans une autre classe Date::Manip) est créé, il devrait toujours être utilisé pour créer des objets supplémentaires afin de préserver les données en cache pour des performances et une utilisation de la mémoire

optimales.

La seule réserve est si vous travaillez avec plusieurs configurations comme décrit dans le document Date::Manip::Objects. Dans ce cas, vous pourriez avoir besoin de créer des objets complètement nouveaux pour permettre l'utilisation de plusieurs objets Date::Manip:
