NOM

Date::Manip::Migration5to6 - comment mettre à niveau de la version 5.xx à la version 6.00

SYNOPSIS

Lors de la mise à niveau de Date::Manip 5.xx vers la 6.00, quelques changements peuvent être nécessaires à vos scripts.

Le document Date::Manip::Changes5to6 détaille les changements apportés à Date::Manip, mais très peu d'entre eux nécessitent réellement des modifications de votre script.

Il est à noter qu'une fois les modifications apportées à votre script, celui-ci ne fonctionnera plus correctement avec la version 5.xx.

CHANGEMENTS REQUIS ET SUGGÉRÉS

Les changements suivants sont nécessaires, ou fortement suggérés :

Lecture des fichiers de configuration avec Date_Init
Si vous utilisez Date_Init pour lire des fichiers de configuration (si vous effectuez des calculs en mode professionnel, vous le faites probablement), vous devriez supprimer toutes les variables de configuration suivantes de votre appel à Date_Init : 
GlobalCnf=FILE
PersonalCnf=FILE
PathSep=*
IgnoreGlobalCnf=*
PersonalCnfPath=*

et les remplacer par :

ConfigFile=FILE

où FILE est maintenant le chemin complet vers un fichier de configuration. De plus, l'argument ConfigFile doit être le premier argument de Date_Init.

Date_ConvTZ
La fonction Date_ConvTZ a changé. Elle doit maintenant prendre 3 arguments : 
$date = Date_ConvTZ($date,$from,$to);

Si $from n'est pas fourni, il prend par défaut le fuseau horaire local. Si $to n'est pas fourni, il prend par défaut le fuseau horaire local.

La date est convertie du fuseau horaire $from vers le fuseau horaire $to. Les deux doivent être un fuseau horaire (ou un alias) supporté par Date::Manip.

L'ancien argument $errlevel n'est plus géré.

Variables de configuration ConvTZ et TZ
Si vous utilisez les variables de configuration ConvTZ ou TZ, vous devriez les remplacer par SetDate ou ForceDate. Voir la documentation de Date::Manip::Config pour plus d'informations.

La variable TZ continuera de fonctionner jusqu'en décembre 2015, date à laquelle elle sera supprimée.

Autres variables de configuration obsolètes
Les variables de configuration suivantes ont été dépréciées, mais continueront de fonctionner (bien qu'elles soient supprimées à une date ultérieure) : 
TZ           (supprimée en mars 2016)

Les variables suivantes ont été supprimées. Si vous en utilisez une, vous devrez peut-être modifier vos scripts :

IntCharSet
GlobalCnf
PersonalCnf
PathSep
IgnoreGlobalCnf
PersonalCnfPath
ConvTZ
Internal
TodayIsMidnight
DeltaSigns
UpdateCurrTZ
ResetWorkdDay
aujourd'hui, hier, demain
Si vous analysez les chaînes "aujourd'hui", "hier" ou "demain" pour obtenir l'heure actuelle, ou 24 heures passées/futures, cela ne fonctionnera plus. Ces chaînes se réfèrent maintenant strictement à la date (ainsi, "aujourd'hui" correspond au jour actuel à minuit, "hier" au jour précédent à minuit, etc.).

Pour obtenir l'heure actuelle, il y a 24 heures, ou dans 24 heures, vous devrez analyser les chaînes "maintenant", "-24:00:00", ou "+24:00:00" respectivement.

Ne pas utiliser Memoize
Dans la version 5.xx, il était indiqué que vous pouviez utiliser le module Memoize pour accélérer Date::Manip, en particulier lors du tri des dates.

Cette information n'est plus exacte. L'utilisation de Memoize en conjonction avec Date::Manip devrait avoir peu d'impact sur les performances et pourrait entraîner des résultats incorrects, surtout si vous modifiez les variables de configuration.

Veuillez vous référer à la section "CHANGEMENTS GÉNÉRAUX" de Date::Manip::Changes5to6 pour plus d'informations.

Si vous trouvez d'autres cas où il est nécessaire de modifier votre script, veuillez m'envoyer un e-mail afin que je puisse ajouter cette information à ce document.

BOGUES ET QUESTIONS

Veuillez vous référer à la documentation de Date::Manip::Problems pour savoir comment soumettre des rapports de bogues ou des questions à l'auteur.
