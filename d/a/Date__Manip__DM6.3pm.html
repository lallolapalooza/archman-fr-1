Cela est similaire à la routine UnixDate, sauf qu'elle extrait des informations d'un delta. Lors du formatage des champs dans un delta, les formats de Date::Manip 6.00 ont changé et sont beaucoup plus puissants. Les anciens formats 5.xx sont toujours disponibles pour la commande

Delta_Format pour la
rétrocompatibilité. Ces formats incluent :
%Xv : affiche la valeur du champ X %Xd : affiche la valeur du champ X et toutes les unités plus petites en termes de X %Xh : affiche la valeur du champ X et toutes les unités plus grandes en termes de X %Xt :
affiche la valeur de tous les champs en termes de X 
Ceux-ci utilisent les
arguments

$mod

e

e

t 
$de
c

pour déterminer comment formater les informations. $dec est un entier et est requis. Il indique le nombre de décimales à

utiliser.

$mod

e

est soit "exact", "semi" ou "approx" et vaut par défaut &quot;exact" s'il n'est pas inclus.

En mode "exact", seules les relations exactes sont utilisées. Cela signifie qu'il ne peut y avoir de mélange entre les segments Y/M, W/D et H/MN/S (pour les deltas non ouvrés, ou les segments Y/M, W et D/H/MN/S pour les deltas ouvrés) car il n'existe pas de relation exacte entre les champs de chaque ensemble.

En mode "semi", les relations semi-approximatives sont utilisées, il n'y a donc pas de mélange entre Y/M et W/D/H/MN/S.

En mode "approx", des relations approximatives sont utilisées afin que tous les champs puissent se mélanger.

Les relations semi-approximatives et approximatives sont décrites dans le manuel Date::Manip::Delta.

Ainsi, en mode "exact", avec un delta non ouvré, et $dec = 2, les éléments suivants sont équivalents :

ancien style    nouveau style
---------    ---------
%Xv          %Xv
%hd          %.2hhs
%hh          %.2hdh
%ht          %.2hds
%yd          %.2yyM

En mode "approximate", les éléments suivants sont équivalents :

ancien style    nouveau style
---------    ---------
%Xv          %Xv
%hd          %.2hhs
%hh          %.2hdh
%ht          %.2hys
%yd          %.2yys

Si vous souhaitez utiliser les nouveaux formats dans Delta_Format, utilisez l'une des formes suivantes :

Delta_Format($delta, @in);
Delta_Format($delta, undef, @in);

Si le premier élément de @in est un entier, vous devez utiliser la deuxième forme.

Les anciens formats resteront disponibles pour le moment, bien qu'ils puissent être déconseillés à terme.

DateCalc
$d = DateCalc($d1,$d2 [,\$err] [,$mode]);

Cette fonction prend deux dates, deux deltas, ou l'un de chaque et effectue le calcul approprié. Les dates doivent être une chaîne pouvant être analysée par ParseDateString. Les deltas doivent être une chaîne pouvant être analysée par ParseDateDelta. Deux deltas s'additionnent pour former un troisième delta. Une date et un delta renvoient une 2ème date. Deux dates renvoient un delta (la différence entre les deux dates).

Puisque les deux éléments peuvent être interprétés comme des dates ou des deltas, et que de nombreuses chaînes peuvent être interprétées comme une date ou un delta, il est conseillé de faire passer l'entrée par ParseDateDelta, si approprié, en cas d'ambiguïté. Par exemple, la chaîne "09:00:00" peut être interprétée soit comme une date (aujourd'hui à 9:00:00) soit comme un delta (9 heures). Pour éviter des résultats inattendus, évitez d'appeler DateCalc comme ceci :

$d = DateCalc("09:00:00",$someothervalue);

Préférez plutôt l'appel suivant :

$d = DateCalc(ParseDate("09:00:00"),$someothervalue);

pour forcer l'interprétation comme une date, ou :

$d = DateCalc(ParseDateDelta("09:00:00"),$someothervalue);

pour forcer l'interprétation comme un delta. Cela évitera des résultats inattendus. Le passage par ParseDate est facultatif car les chaînes seront traitées comme des dates par défaut (et pour des raisons de performance, il vaut mieux ne pas appeler ParseDate).

S'il n'y a pas d'ambiguïté, il vaut mieux NE PAS faire cela pour des raisons de performance. Si le delta est un delta ouvré, vous ne devriez surtout pas faire cela.

Une autre chose à noter est que lors de l'analyse des dates, un delta peut être interprété comme une date relative à maintenant. DateCalc traitera TOUJOURS un delta comme un delta, et NON comme une date.

Pour plus de détails sur la manière dont les calculs sont effectués, consultez la documentation de Date::Manip::Calc.

Par défaut, les calculs sont effectués en mode exact.

Si deux deltas, ou une date et un delta sont passés, $mode peut être utilisé pour forcer le delta à être un delta ouvré ou non ouvré. Si $mode vaut 0 ou 1, le(s) delta(s) seront non ouvrés. Sinon, ce seront des deltas ouvrés. Si $mode est passé, il ne sera utilisé que si l'état ouvré ou non ouvré n'a pas été défini explicitement dans le delta. $mode peut également être l'un des modes discutés dans la documentation de Date::Manip::Calc.

Si deux dates sont passées, $mode est utilisé pour déterminer le type de calcul. Par défaut, un delta exact est produit. Si $mode vaut 1, un delta approximatif est produit. Si $mode vaut 2, un calcul en mode approximatif ouvré (bapprox) est effectué. Si $mode vaut 3, un delta en mode exact ouvré est produit.

Si \$err est passé, il est défini comme suit :

1 est renvoyé si $d1 n'est ni un delta ni une date
2 est renvoyé si $d2 n'est ni un delta ni une date
3 si une autre erreur survient.

Cet argument est facultatif, mais s'il est inclus, il doit venir avant $mode.

Rien n'est renvoyé si une erreur survient.

ParseRecur
$recur = ParseRecur($string [,$base,$date0,$date1,$flags]);
@dates = ParseRecur($string [,$base,$date0,$date1,$flags]);

Cette fonction analyse une chaîne contenant une récurrence et renvoie une récurrence entièrement spécifiée, ou une liste de dates référencées.

$string peut être l'une des formes suivantes :

FREQ
FREQ*FLAGS
FREQ*FLAGS*BASE
FREQ*FLAGS*BASE*DATE0
FREQ*FLAGS*BASE*DATE0*DATE1

où FREQ est une fréquence (voir la documentation de Date::Manip::Delta), FLAGS est une liste de drapeaux séparés par des virgules, et BASE, DATE0 et DATE1 sont des chaînes de dates. Les dates et les drapeaux peuvent également être passés sous la forme $base, $date0, $date1, et $flags, et ceux-ci remplaceront les valeurs dans $string.

En contexte scalaire, la récurrence entièrement spécifiée (ou autant d'informations que possible) sera renvoyée. En contexte liste, une liste de dates sera renvoyée.

Cette fonction prend deux dates et les compare. Toutes les dates pouvant être analysées seront comparées.

Events_List
$ref = Events_List($date);
$ref = Events_List($date,0      [,$flag]);
$ref = Events_List($date,$date1 [,$flag]);

Cette fonction renvoie une liste d'événements. Si $flag n'est pas donné, ou est égal à 0, la liste (renvoyée sous forme de référence) est similaire à la liste renvoyée par la méthode Date::Manip::Date::list_events avec $format = "dates". La seule différence est qu'elle est formatée légèrement différemment pour assurer la compatibilité avec Date::Manip 5.xx.

Les données de la méthode list_events sont :

( [DATE1, NAME1a, NAME1b, ...],
  [DATE2, NAME2a, NAME2b, ...],
  ...
)

La référence renvoyée par Events_List (si $flag = 0) est :

[ DATE1, [NAME1a, NAME1b, ...],
  DATE2, [DATE2a, DATE2b, ...],
  ...
]

Par exemple, si les événements suivants sont définis :

2000-01-01 ; 2000-03-21  = Winter
2000-03-22 ; 2000-06-21  = Spring
2000-02-01               = Event1
2000-05-01               = Event2
2000-04-01-12:00:00      = Event3

les exemples suivants illustrent la fonction :

Events_List("2000-04-01")
 => [ 2000040100:00:00, [ Spring ] ]
Events_List("2000-04-01 12:30");
 => [ 2000040112:30:00, [ Spring, Event3 ] ]
Events_List("2000-04-01",0);
 => [ 2000040100:00:00, [ Spring ],
      2000040112:00:00, [ Spring, Event3 ],
      2000040113:00:00, [ Spring ] ]
Events_List("2000-03-15","2000-04-10");
 => [ 2000031500:00:00, [ Hiver ],
      2000032200:00:00, [ Printemps ]
      2000040112:00:00, [ Printemps, Event3 ]
      2000040113:00:00, [ Printemps ] ]

Si $flag vaut 1, un décompte du temps accordé à chaque événement est renvoyé. Le temps pendant lequel deux événements ou plus s'appliquent est compté pour chacun.

Events_List("2000-03-15","2000-04-10",1);
 => { Event3 => +0:0:+0:0:1:0:0,
      Printemps => +0:0:+2:4:23:0:0,
      Hiver => +0:0:+1:0:0:0:0
    }

Quand $flag vaut 2, un décompte plus complexe où aucun événement n'est compté deux fois est renvoyé.

Events_List("2000-03-15","2000-04-10",2);
 => { Event3+Printemps => +0:0:+0:0:1:0:0,
      Printemps        => +0:0:+2:4:22:0:0,
      Hiver            => +0:0:+1:0:0:0:0
    }

Le hachage contient un élément pour chaque combinaison d'événements.

Dans ces deux cas, il peut y avoir un élément de hachage avec une chaîne vide comme clé, qui contient le temps pendant lequel aucun événement n'est actif.

Date_DaysSince1BC

Renvoie le nombre de jours depuis le 31 décembre 1 av. J.-C. Cela inclut l'année 0001.

Date_DayOfYear
$day = Date_DayOfYear($m,$d,$y);

Renvoie le jour de l'année (1 à 366)

Date_NthDayOfYear
($y,$m,$d,$h,$mn,$s) = Date_NthDayOfYear($y,$n);

Renvoie l'année, le mois, le jour, l'heure, les minutes et les secondes décimales étant donné un jour de l'année en virgule flottante.

Tous les arguments doivent être numériques. $n doit être supérieur ou égal à 1 et inférieur à 366 les années non bissextiles et 367 les années bissextiles.

NOTE : Quand $n est un nombre décimal, les résultats peuvent être contre-intuitifs. Le jour 1 est le 01/01 à 00:00. Le jour 2 est le 02/01 à 00:00. Intuitivement, vous pourriez penser que le jour 1.5 est 1.5 jours après le 01/01 à 00:00, mais cela signifierait que le jour 1.5 était le 02/01 à 12:00 (ce qui est plus tard que le jour 2). La meilleure façon de penser à cette fonction est une ligne de temps commençant à 1 et se terminant à 366 (dans une année non bissextile). En termes d'un delta, pensez à $n comme le nombre de jours après le 31/12 à 00:00 de l'année précédente.

Date_DaysInYear
$days = Date_DaysInYear($y);

Renvoie le nombre de jours dans l'année (365 ou 366)

Date_DaysInMonth
$days = Date_DaysInMonth($m,$y);

Renvoie le nombre de jours dans le mois.

Date_WeekOfYear
$wkno = Date_WeekOfYear($m,$d,$y,$first);

Détermine le numéro de semaine. $first est le premier jour de la semaine qui est habituellement 1 (lundi) ou 7 (dimanche), mais pourrait être n'importe quel nombre entre 1 et 7 en pratique.

NOTE : Cette routine ne devrait être appelée que dans de rares cas. Utilisez printf avec les %W, %U, %J, %L formats à la place car cela renverra toujours les valeurs correctes pour la semaine et l'année.

Cette routine renvoie une semaine entre 0 et 53 qui doit ensuite être « corrigée » pour obtenir les semaines ISO 8601 de 1 à 53. Une date qui renvoie une semaine de 0 appartient en fait à la dernière semaine de l'année précédente. Une date qui renvoie une semaine de 53 peut appartenir à la première semaine de l'année suivante.

Date_LeapYear
$flag = Date_LeapYear($y);

Renvoie 1 si l'argument est une année bissextile. Écrit par David Muir Sharnoff <muir@idiom.com>

Date_DaySuffix
$day = Date_DaySuffix($d);

Ajoute « st », « nd », « rd », « th » à une date (c'est-à-dire 1st, 22nd, 29th). Fonctionne pour les dates internationales.

Date_TimeZone
$tz = Date_TimeZone;

Cela détermine et renvoie le fuseau horaire local. S'il est incapable de déterminer le fuseau horaire local, l'erreur suivante se produit :

ERROR: Date::Manip unable to determine Time Zone.

Voir la documentation de Date::Manip::TZ (DETERMINING THE LOCAL TIME ZONE) pour plus d'informations.

Date_ConvTZ
$date = Date_ConvTZ($date,$from,$to);

Cela convertit une date (qui DOIT être au format renvoyé par ParseDate) d'un fuseau horaire à un autre.

$from et $to ont chacun comme valeur par défaut le fuseau horaire local. S'ils sont donnés, ils doivent être n'importe quel fuseau horaire ou alias compris par Date::Manip.

Si une erreur se produit, une chaîne vide est renvoyée.

Date_NextWorkDay
$date = Date_NextWorkDay($date,$off [,$time]);

Trouve le jour $off jours ouvrables à partir de maintenant. Si $time est passé, nous devons également prendre en compte l'heure de la journée.

Si $time n'est pas passé, le jour 0 est aujourd'hui (si aujourd'hui est un jour ouvrable) ou le prochain jour ouvrable si ce n'est pas le cas. Dans tous les cas, l'heure de la journée n'est pas affectée.

Si $time est passé, le jour 0 est maintenant (si maintenant fait partie d'un jour ouvrable) ou le début du tout prochain jour ouvrable.

Date_PrevWorkDay
$date = Date_PrevWorkDay($date,$off [,$time]);

Similaire à Date_NextWorkDay.

Date_NearestWorkDay
$date = Date_NearestWorkDay($date [,$tomorrowfirst]);

Cela cherche le jour ouvrable le plus proche de $date. Si $date est un jour ouvrable, il est renvoyé. Sinon, il cherchera vers l'avant ou vers l'arrière dans le temps 1 jour à la fois jusqu'à ce qu'un jour ouvrable soit trouvé. Si $tomorrowfirst est non nul (ou s'il est omis et que la variable de configuration TomorrowFirst est non nulle), nous cherchons dans le futur d'abord. Sinon, nous cherchons dans le passé d'abord. En d'autres termes, dans une semaine normale, si $date est mercredi, $date est renvoyé. Si $date est samedi, vendredi est renvoyé. Si $date est dimanche, lundi est renvoyé. Si le mercredi est un jour férié, jeudi est renvoyé si $tomorrowfirst est non nul ou mardi sinon.

Pour toutes les fonctions qui renvoient une date, le format de la date renvoyée est régi par la variable de configuration Printable. Si une date est renvoyée, elle est dans le fuseau horaire local, PAS le fuseau horaire dans lequel la date a été analysée.
