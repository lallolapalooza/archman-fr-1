INTERFAC

E

Notez que lorsqu'un numéro d'année, une date, une heure ou une date et heure combinées sont attendus comme paramètres d'entrée par l'une des méthodes de cette classe, vous pouvez toujours passer un objet date Date::Calc[::Object] ou une référence de tableau (d'un tableau de longueur appropriée) à la place

!

Voir Date::Calc::Object(3) pour plus de

détails.

Ainsi, au lieu d'appeler une méthode donnée comme ceci

: 
$object->method1( $year,$month,$day );
$object->method2( $year1,$month1,$day1, $year2,$month2,$day2 );
$object->method3( $year1, $year2, $year3 )
;

Vous pouvez aussi l'appeler ainsi

: 
$object->method1( $date );
$object->method1( [1964,1,3] );
$object->method2( $year1,$month1,$day1, $date2 );
$object->method2( $date1, $year2,$month2,$day2 );
$object->method2( $date1, $date2 );
$object->method2( $year1,$month1,$day1, [2001,3,17] );
$object->method2( [1964,1,3], $year2,$month2,$day2 );
$object->method2( [1964,1,3], [2001,3,17] );
$object->method2( $date1, [2001,3,17] );
$object->method2( [1964,1,3], $date2 );
$object->method3( $year1, $date2, [2001,3,17] )
;

Et de même si une heure ou une date et heure combinées sont

attendues.

Si vous remplacez un numéro d'année attendu par un tableau anonyme (c'est la manière recommandée d'écrire des constantes de date, pour une meilleure lisibilité de vos programmes), il doit néanmoins contenir trois valeurs (sinon l'utilisation d'un tableau anonyme serait sans objet)

.

Ne confondez pas les numéros d'année et leurs substituts (un objet date ou une référence de tableau) avec les objets Date::Calendar::Year, qui sont une chose totalement différente

!

Mais incidemment ":-)", vous pouvez aussi passer un objet Date::Calendar::Year lorsqu'un numéro d'année est attendu. Cependant, et peut-être contre vos attentes parfois, seul le numéro d'année de cet objet sera utilisé, pas l'objet année lui-même (l'objet année en question pourrait utiliser le mauvais profil !)

.

De plus, lorsqu'une méthode de cette clas

se renvoie une date, elle le fait en renv
oyant un objet date Date::Calc[::Object].

IMPLÉMENTATIO

N

Chaque objet Date::Calendar::Year se compose principalement de trois vecteurs de bits, plus quelques attributs administratifs, le tout stocké dans un hachage (béni)

.

Les trois vecteurs de bits contiennent autant de bits qu'il y a de jours dans l'année correspondante, c'est-à-dire soit 365 soit

366.

Le premier vecteur de bits, appelé "FULL", contient les bits activés pour les samedis, les dimanches et tous les jours fériés légaux "complets" (c'est-à-dire les jours de congé, pendant lesquels vous ne travaillez généralement pas)

.

Le deuxième vecteur de bits, appelé "HALF", contient les bits activés pour tous les jours fériés "demi-jours", c'est-à-dire les jours fériés où vous ne bénéficiez que d'une demi-journée de

congé.

Le troisième et dernier vecteur de bits, appelé "WORK", est utilisé comme espace de travail, dans lequel divers calculs sont effectués tout au long de ce

module.

Son nom ne vient pas de "jours ouvrables" (comme vous pourriez le penser), mais de "espace de travail" (workspace)

.

Il se trouve simplement qu'il est utilisé pour calculer les jours ouvrables parfois, à certains endroits de ce

module.

Mais vous êtes libre de l'utiliser vous-même, pour tout calcul que vous souhaiteriez effectuer

vous-même.

Les deux autres vecteurs de bits, "FULL" et "HALF", ne devraient jamais être modifiés, à moins que vous ne sachiez EXACTEMENT ce qu

e vous
faites !

    La méthode "init()" procède comme

    suit :

    D'abord, elle vérifie si le numéro d'année donné se trouve dans la plage [1583..2299]. Une erreur fatale se produit

    sinon.

    donné.

    Elle appelle ensuite le module Bit::Vector(3) pour allouer trois vecteurs de bits avec un nombre de bits égal au nombre de jours dans l'année demandée, et stocke les trois références d'objet (des vecteurs de bits) dans l'objet Date::Calendar::

    Year.

    ».

    valid.

    A fatal error occurs if the date formula cannot be parsed or if the date returned by a formula or callback function is invalid (e.g. 30-Feb-2001 or the like) or lies outside the given year (e.g. Easter+365)

    .

    Finally, the "init()" method makes sure that days marked as "full" holidays do not appear as "half" holidays as

    well.

    Then the "init()" method

    returns.

    language-dependent.

    Therefore the "init()" method allows you to pass it an optional third argument, which must consist of the valid name or number of a language as provided by the Date::Calc(3)

    module.

    For the time of scanning the given holiday scheme, the "init()" method will use the language that has been specified, or the global setting from "Language()" if no or an invalid language parameter is

    given.

    modified.

    This means that you can provide the names of months and days of week in your holiday profile in any of the languages supported by the Date::Calc(3) module, provided you give the "init()" method a clue (the third param

    following: 
    0    =>    commemorative day
1    =>    "half" holiday
2    =>    "full" holiday
3    =>    both a "half" and a "full"
    holiday

    The value "3" should only occur if a date has been redefined by the underlying profile using the same key (i.e., the same name) but with a different type of

    holiday.

    The index must be a number such as returned by the method "date2index()"; it can be used here instead of a date or a date object

    in order to speed up processing (= no ne

  • "$days = $year->delta_workdays(YEAR,MONTH1,DAY1, YEAR,MONTH2,DAY2, FLAG1,FLAG2);"

    "$days = $year->delta_workdays(DATE1,DATE2,FLAG1,

    FLAG2);"

    This method calculates the number of work days (i.e., the number of days, but excluding all holidays) between two

    dates.

    In other words, this method is equivalent to the "Delta_Days()" function of the Date::Calc module, except that it disregards holidays in its

    counting.

    The two flags indicate whether the start and end dates should be included in the counting (that is, of course, only in case they aren't holidays), or

    not.

    It is common, for example, that you want to know how many work days are left between the current date and a given

    deadline.

    Typically, you will want to count the current date but not the deadline's date. So you would specify "true" ("1") for FLAG1 and "false" ("0") for FLAG2 in order to achieve

    that.

    In other words, a value of "true" means "including this date", a value of "false" means "excluding this

    date".

    As with the "Delta_Days()" function from the Date::Calc module, the dates have to be given in chronological order to yield a positive result. If the dates are reversed, the result will be

    negative.

    The parameter FLAG1 is associated with the first given date, the parameter FLAG2 with the second given date (regardless of whether the dates are in chronological order or

    not).

    An exception ("given year != object's year") is thrown if the year number of either of the two given dates does not match the year number associated with the given year

    object.

    An exception ("invalid date") is also rai

    sed if either of the two date ar
    • guments does not constitute a valid date.
  • "($date,$rest,$sign) = $year->add_delta_workdays(YEAR,MONTH,DAY, DELTA, SIGN);"

    "($date,$rest,$sign) = $year->add_delta_workdays(DATE,DELTA,

    SIGN);"

    This method is the equivalent of the "Add_Delta_Days()" function from the Date::Calc module, except that it adds work days and skips

    holidays.

    In other words, you can add or subtract a number of work days "DELTA" to/from a given date and get a new date as the result (as a Date::Calc object)

    .

    Vous ajoutez des jours (c.-à-d., vous avancez dans le temps) avec un décalage "DELTA" positif, et vous soustrayez des jours (c.-à-d., vous reculez dans le temps) avec un décalage

    négatif.

    Notez qu'une exception ("invalid date") est levée si l'argument de date donné (la date de départ) ne constitue pas une date

    valide.

    Attention, cette méthode est limitée aux calculs de dates à l'intérieur d'une seule année (contrairement à la méthode du même nom du module Date::Calendar)

    .

    Par conséquent, la méthode ne retourne pas seulement une date (objet), mais aussi un "rest" (reste) et un "sign"

    (signe).

    Le "rest" indique combien de jours il reste de votre DELTA original après avoir avancé dans la direction souhaitée et avoir atteint une limite

    d'année.

    Le "sign" indique dans quelle direction (futur ou passé) il faut aller pour "épuiser" le "rest" (en soustrayant un jour du "rest" pour chaque jour ouvrable passé), ou pour ajuster la date résultante (afin de sauter les jours fériés directement après une limite d'année), le cas

    échéant.

    Le "sign" est -1 pour aller en arrière dans le temps, +1 pour aller en avant, et 0 si le résultat n'a plus besoin de correction (par exemple parce que le résultat se trouve dans la même année que la date de

    départ).

    La méthode "add_delta_workdays()" du module Date::Calendar utilise les valeurs de retour "rest" et "sign" de cette méthode afin d'effectuer des calculs qui peuvent traverser des limites

    d'année.

    Par conséquent, il n'est pas recommandé d'utiliser cette méthode directement ici, car elle est plutôt pénible à utiliser, mais plutôt d'utiliser la méthode du même nom du module Date::Calendar, qui fait la même chose mais est beaucoup plus facile à utiliser et permet en outre des calculs qui traversent un nombre arbitraire de limites

    d'année.

    ATTENTION, cette méthode peut actuellement retourner des résultats inattendus (c.-à-d., contredisant la documentation ci-dessus) ou complètement erronés lorsqu'on recule dans le temps (c'est un

    bug !).

    Cependant, elle fonctionne correctem

    ent et comme documenté ci-de
    • ssus lorsqu'on avance dans le temps.
