DateTime::TimeZone(3) Documentation Perl contribuée par les utilisateurs DateTime::TimeZone(3)

NOM

DateTime::TimeZone - Classe de base des objets de fuseau horaire et fabrique

VERSION

version 2.65

RÉSUMÉ

use DateTime;
use DateTime::TimeZone;
my $tz = DateTime::TimeZone->new( name => 'America/Chicago' );
my $dt = DateTime->now();
my $offset = $tz->offset_for_datetime($dt);

DESCRIPTION

Cette classe est la classe de base pour tous les objets de fuseau horaire. Un fuseau horaire est représenté en interne comme un ensemble d'observances, chacune décrivant le décalage par rapport au GMT pour une période de temps donnée.

Notez que sans le module DateTime, ce module ne fait pas grand-chose. Son interface principale est à travers un objet DateTime, et la plupart des utilisateurs n'auront pas besoin d'utiliser directement les "DateTime::TimeZone" méthodes.

Plateformes spéciales

Si vous êtes sur la plateforme Win32, vous voudrez également installer DateTime::TimeZone::Local::Win32. Cela vous permettra de spécifier un fuseau horaire 'local' lors de la création d'un objet DateTime.

Si vous êtes sur HPUX, installez DateTime::TimeZone::HPUX. Cela fournit la prise en charge des fuseaux horaires de style HPUX comme 'MET-1METDST'.

UTILISATION

Cette classe possède les méthodes suivantes :

DateTime::TimeZone->new( name => $tz_name )

Étant donné un nom de fuseau horaire valide, cette méthode retourne un nouveau fuseau horaire béni dans la sous-classe appropriée. Les sous-classes sont nommées d'après le fuseau horaire donné, de sorte que le fuseau horaire "America/Chicago" est la classe DateTime::TimeZone::America::Chicago.

Si le nom donné est un nom de "lien" dans la base de données Olson, l'objet créé peut avoir un nom différent. Par exemple, il existe un lien de l'ancien nom "EST5EDT" vers "America/New_York".

Lors du chargement d'un fuseau horaire depuis la base de données Olson, le constructeur vérifie la version de la classe chargée pour s'assurer qu'elle correspond à la version de l'installation actuelle de DateTime::TimeZone. Si elles ne correspondent pas, il émettra un avertissement. Cela est utile car les noms de fuseaux horaires peuvent tomber en désuétude, mais vous pouvez avoir un ancien fichier de module installé pour ce fuseau horaire.

Il existe également plusieurs valeurs spéciales qui peuvent être données comme noms.

Si le paramètre "name" est "floating", alors un "DateTime::TimeZone::Floating" objet est retourné. Un fuseau horaire flottant n'a pas aucun décalage, et est toujours la même heure. C'est utile pour les applications de calendrier, qui peuvent avoir besoin de spécifier qu'un événement donné se produit à la même heure locale , peu importe où il se produit. Voir la RFC 2445 https://www.ietf.org/rfc/rfc2445.txt pour plus de détails.

Si le paramètre "name" est "UTC", alors un "DateTime::TimeZone::UTC" objet est retourné.

Si le "name" est une chaîne de décalage, elle est convertie en un nombre, et un "DateTime::TimeZone::OffsetOnly" objet est retourné.

Le fuseau horaire "local"

Si le paramètre "name" est "local", alors le module tente de déterminer le fuseau horaire local du système.

La méthode pour trouver la zone locale varie selon le système d'exploitation. Voir le module approprié pour les détails sur la manière dont nous vérifions le fuseau horaire local.

  • DateTime::TimeZone::Local::Unix
  • DateTime::TimeZone::Local::Android
  • DateTime::TimeZone::Local::hpux
  • DateTime::TimeZone::Local::Win32
  • DateTime::TimeZone::Local::VMS

Si un fuseau horaire local n'est pas trouvé, une exception sera levée. Cette exception sera toujours convertie en chaîne en quelque chose contenant le texte "Cannot determine local time zone".

Si vous écrivez du code pour des utilisateurs qui l'exécuteront sur des systèmes que vous ne contrôlez pas, vous devriez essayer de prendre en compte la possibilité que cette exception soit levée. Revenir à UTC pourrait être une alternative raisonnable.

Lors de l'écriture de tests pour vos modules qui pourraient être exécutés sur les systèmes d'autres personnes, il vous est fortement recommandé de ne pas utiliser "local" lors de la création d'objets DateTime ou de définir $ENV{TZ} à une valeur connue dans votre code de test. Toutes les classes par OS vérifient cette variable d'environnement.

$tz->offset_for_datetime( $dt )

Étant donné un "DateTime" objet, cette méthode retourne le décalage en secondes pour la date et l'heure données. Cela prend en compte les informations historiques du fuseau horaire, ainsi que l'heure d'été. Le décalage est déterminé en examinant les jours et secondes Rata Die UTC de l'objet.

$tz->offset_for_local_datetime( $dt )

Étant donné un "DateTime" objet, cette méthode retourne le décalage en secondes pour la date et l'heure données. Contrairement à la méthode précédente, cette méthode utilise les jours et secondes Rata Die de l'heure locale. Cela ne devrait être fait que lorsque l'heure UTC correspondante n'est pas encore connue, car les heures locales peuvent être ambiguës en raison des règles d'heure d'été.

$tz->is_dst_for_datetime( $dt )

Étant donné un "DateTime" objet, cette méthode retourne vrai si le DateTime est actuellement en heure d'été.

$tz->name

Retourne le nom du fuseau horaire.

$tz->short_name_for_datetime( $dt )

Étant donné un "DateTime" objet, cette méthode retourne le "nom court" pour l'observance et la règle actuelles dans lesquelles se trouve cette date et heure. Ce sont des noms comme "EST", "GMT", etc.

Il est fortement recommandé de ne pas vous fier à ces noms pour autre chose que l'affichage. Ces noms ne sont pas officiels, et beaucoup d'entre eux sont simplement l'invention des mainteneurs de la base de données Olson. De plus, ces noms ne sont pas uniques. Par exemple, il y a un "EST" à la fois à -0500 et +1000/+1100.

$tz->is_floating

Retourne un booléen indiquant si cet objet représente ou non un fuseau horaire flottant, tel que défini par la RFC 2445 https://www.ietf.org/rfc/rfc2445.txt.

$tz->is_utc

Indique si cet objet représente ou non le fuseau horaire UTC (GMT).

$tz->has_dst_changes

Indique si cette zone a jamais eu un changement vers et depuis l'heure d'été, que ce soit dans le passé ou le futur.

$tz->is_olson

Retourne vrai si le fuseau horaire est un fuseau horaire nommé de la base de données Olson.

$tz->category

Retourne la partie du nom du fuseau horaire avant la première barre oblique. Par exemple, le fuseau horaire "America/Chicago" retournerait "America".

DateTime::TimeZone->is_valid_name($name)

Étant donné une chaîne, cette méthode retourne une valeur booléenne indiquant si la chaîne est un nom de fuseau horaire valide ou non. Si vous utilisez "DateTime::TimeZone::Alias", tous les alias que vous avez créés seront valides.

DateTime::TimeZone->all_names

Cela retourne une liste pré-triée de tous les noms de fuseaux horaires. Cette liste n'inclut pas les noms de liens. Dans scaen contexte tableau, il renvoie une référence de tableau, tandis qu'en contexte liste il renvoie un tableau.

DateTime::TimeZone->categories

Cela renvoie une liste de toutes les catégories de fuseaux horaires. En contexte scalaire, il renvoie une référence de tableau, tandis qu'en contexte liste il renvoie un tableau.

DateTime::TimeZone->links

Cela renvoie une table de hachage de tous les liens de fuseaux horaires, où les clés sont les anciens noms dépréciés et les valeurs sont les nouveaux noms. En contexte scalaire, il renvoie une référence de hachage, tandis qu'en contexte liste il renvoie un hachage.

DateTime::TimeZone->names_in_category( $category )

Étant donné une catégorie valide, cette méthode renvoie une liste des noms dans cette catégorie, sans la partie correspondant à la catégorie. Ainsi, la liste pour la catégorie "America" inclurait les chaînes "Chicago", "Kentucky/Monticello" et "New_York". En contexte scalaire, il renvoie une référence de tableau, tandis qu'en contexte liste il renvoie un tableau.

DateTime::TimeZone->countries()

Renvoie une liste triée de tous les codes de pays valides (en minuscules) qui peuvent être passés à names_in_country(). En contexte scalaire, il renvoie une référence de tableau, tandis qu'en contexte liste il renvoie un tableau.

Si vous devez convertir des codes de pays en noms ou vice versa, vous pouvez utiliser "Locale::Country" pour ce faire. Notez que l'un des codes renvoyés est "uk", qui est un alias pour le code de pays "gb", et n'est pas un code de pays ISO valide.

DateTime::TimeZone->names_in_country( $country_code )

Étant donné un code de pays ISO3166 à deux lettres, cette méthode renvoie une liste des fuseaux horaires utilisés dans ce pays. Le code de pays peut être de n'importe quelle casse. En contexte scalaire, il renvoie une référence de tableau, tandis qu'en contexte liste il renvoie un tableau.

Cette liste est renvoyée dans un ordre vaguement basé sur la géographie et la population. En général, les fuseaux les moins utilisés arrivent en dernier, mais il n'y a pas de garantie d'un ordre spécifique d'une version à l'autre. Cet ordre est probablement la meilleure option pour présenter les noms de fuseaux aux utilisateurs finaux.

DateTime::TimeZone->offset_as_seconds( $offset )

Étant donné un décalage sous forme de chaîne, cela renvoie le nombre de secondes représenté par le décalage sous forme de nombre positif ou négatif. Renvoie "undef" si $offset n'est pas dans la plage "-99:59:59" à "+99:59:59".

Le décalage doit correspondre soit à "/^([\+\-])?(\d\d?):(\d\d)(?::(\d\d))?$/" soit à "/^([\+\-])?(\d\d)(\d\d)(\d\d)?$/". S'il ne correspond à aucun de ceux-ci, "undef" sera renvoyé.

Cela signifie que si vous voulez spécifier les heures avec un seul chiffre, alors chaque élément du décalage doit être séparé par deux-points (:).

DateTime::TimeZone->offset_as_string( $offset, $sep )

Étant donné un décalage sous forme de nombre, cela renvoie le décalage sous forme de chaîne. Renvoie "undef" si $offset n'est pas dans la plage -359999 à 359999.

Vous pouvez également fournir un séparateur facultatif qui sera placé entre les parties heures, minutes et secondes (le cas échéant) du décalage.

Hooks Storable

Ce module fournit des hooks de gel (freeze) et de dégel (thaw) pour "Storable" afin que les énormes structures de données des fuseaux horaires Olson ne soient pas réellement stockées dans la structure sérialisée.

Si vous créez une sous-classe de "DateTime::TimeZone", vous hériterez de ses hooks, qui peuvent ne pas fonctionner pour votre module, alors veuillez tester l'interaction de votre module avec Storable.

CHARGEMENT DES FUSEAUX HORAIRES DANS UN SYSTÈME PRÉ-FORK

Si vous exécutez une application qui effectue un pré-fork (par exemple avec Starman), vous devriez essayer de charger tous les fuseaux horaires dont vous aurez besoin dans le processus parent. Les fuseaux horaires sont chargés à la demande, donc les charger une fois dans chaque enfant gaspillera de la mémoire qui pourrait autrement être partagée.
