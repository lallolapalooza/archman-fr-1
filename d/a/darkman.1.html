darkman(1) Manuel des commandes générales darkman(1)

NOM

darkman - contrôle les transitions mode sombre et mode clair

SYNOPIS

darkman [OPTIONS] COMMANDE

DESCRIPTION

darkman s'exécute en arrière-plan et active le mode sombre au coucher du soleil, puis le désactive au lever du soleil. darkman n'est pas conçu pour être utilisé interactivement : il est conçu pour être configuré une fois et exécuté en arrière-plan.

Il est également possible de déclencher des transitions manuelles et de désactiver complètement les transitions automatiques.

COMMANDES

run [--ready-fd FD]

Exécute le service darkman. Cette commande est destinée à être exécutée par un gestionnaire de service, un script d'initialisation ou similaire.

Le descripteur de fichier FD facultatif est un descripteur de fichier où darkman notifiera lorsqu'il sera prêt à recevoir des connexions des clients. Le protocole utilisé est compatible avec les notifications de préparation pour s6, dinit et systemd.

set <light|dark>

Définit le mode actuel.

get

Affiche le mode actuel.

toggle

Inverse le mode actuel.

OPTIONS

--verbose

Affiche des journaux détaillés. Par défaut, la valeur est true pour la commande run et false pour toutes les autres commandes.

INTÉGRATIONS

L'écosystème de bureau open source est assez hétérogène et faire basculer différentes applications entre le mode sombre/clair nécessite des mécanismes différents.

Darkman cherche à implémenter les normes les plus largement adoptées, tout en laissant la place aux utilisateurs pour intégrer des scripts personnalisés pour d'autres applications.

Exécutables personnalisés

Darkman peut exécuter des exécutables personnalisés (qui peuvent être de simples scripts shell).

Les scripts sont recherchés dans un répertoire nommé darkman à l'intérieur des chemins définis dans XDG_DATA_DIRS ainsi que dans XDG_DATA_HOME. Chaque script reçoit le mode actuel ("dark" ou "light") comme premier argument ($1). Cela permet à un seul script de gérer les deux modes :

#!/bin/sh
case "$1" in
dark) THEME=dark-theme ;;
light) THEME=light-theme ;;
esac
gsettings set org.example.app theme "$THEME"

Pour des raisons de compatibilité ascendante, darkman recherche également les répertoires dark-mode.d et light-mode.d (format hérité). Les scripts dans ces répertoires sont exécutés sans arguments. Les scripts dans le répertoire darkman portant le même nom remplacent les scripts hérités.

Ces deux variables et leurs solutions de repli sont définies dans la spécification des répertoires de base XDG :

https://specifications.freedesktop.org/basedir-spec/latest/

Ces scripts ou exécutables peuvent effectuer toutes les actions nécessaires, comme réécrire des fichiers de configuration pour un lecteur PDF, contrôler un démon de notification pour passer à un autre thème, ou basculer un paramètre spécifique à l'environnement de bureau.

Les fichiers doivent avoir le bit exécutable défini pour être considérés comme exécutables. Les scripts doivent avoir le shebang approprié pour que le système d'exploitation les exécute correctement.

Typiquement, les variables XDG_DATA_* mentionnées ci-dessus se résoudront aux ensembles de répertoires suivants :

  • ~/.local/share/
  • /usr/local/share/
  • /usr/share/

Des exemples de scripts (et une discussion sur la manière d'intégrer différentes applications) sont disponibles dans le dépôt du projet :

https://gitlab.com/WhyNotHugo/darkman

Les paquets peuvent également déposer leurs propres scripts dans n'importe lequel de ces emplacements, bien que les développeurs d'applications soient encouragés à utiliser l'API D-Bus pour déterminer le mode actuel et écouter les changements (voir ci-dessous pour plus de détails).

Portail de paramètres XDG

Darkman implémente la norme du portail de bureau XDG pour le mode sombre. Les applications utilisant cette API devraient basculer entre le mode sombre/clair en fonction des préférences actuelles de darkman. Cette norme a été initialement promue par les équipes GNOME et Elementary, et est actuellement prise en charge par KDE, Firefox et de nombreux autres projets. Vous pouvez vous attendre à ce que les applications de ces environnements la prennent en charge, entre autres.

Pour plus de détails sur ce protocole, consultez :

https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Settings.html

Depuis la version 1.17.0 de xdg-desktop-portal, les portails DOIVENT être configurés avec une configuration par utilisateur portals.conf(5). Pour forcer l'utilisation de darkman pour la définition du mode sombre/clair, utilisez quelque chose comme ce qui suit :

[preferred]
org.freedesktop.impl.portal.Settings=darkman

Lorsque vous utilisez une configuration spécifique à l'environnement de bureau (par exemple : swaywm-portals.conf), veuillez garder à l'esprit que la variable d'environnement XDG_CURRENT_DESKTOP doit être définie pour le xdg-desktop-portal.

Le xdg-desktop-portal devrait démarrer après que darkman ait démarré et soit prêt. Utilisez --ready-fd pour la notification de préparation. Ceci n'est probablement pas pertinent dans les configurations basées sur systemd, où le gestionnaire de service intervient pour prendre le bus nommé.

Pour une explication plus approfondie, consultez cet article :

https://whynothugo.nl/journal/2024/04/09/darkman-portal-configuration/

API D-Bus

Pour des intégrations personnalisées, darkman expose une API D-Bus qui permet d'interroger et de contrôler le mode actuel. Les commandes get, set et toggle utilisent toutes cette API. L'utilisation de cette API est également l'approche recommandée lors de l'écriture d'outils personnalisés (par exemple : changer le mode actuel en fonction de l'entrée d'un capteur de lumière).

EMPLACEMENT

L'emplacement actuel peut être spécifié dans le fichier de configuration. L'emplacement est utilisé pour calculer l'heure du coucher et du lever du soleil.

Il est également possible pour darkman de déterminer automatiquement l'emplacement du système à l'aide de geoclue. La fiabilité de Geoclue varie en fonction de la distribution et de l'environnement de bureau, car un agent doit souvent être configuré pour qu'il fonctionne correctement.

Si aucun emplacement n'est connu, les transitions automatiques sont désactivées.

CONFIGURATION

Un fichier de configuration et tous les paramètres sont facultatifs. La configuration est lue à partir de ~/.config/darkman/config.yaml (ou d'autres chemins définis dans les spécifications de base XDG), et a le format suivant :

lat: 52.3
lng: 4.8
dbusserver: true

Les paramètres suivants sont disponibles :

•
lat, lng : Latitude et longitude respectivement. Cette valeur sera utilisée au démarrage, mais sera ensuite remplacée par ce que geoclue résoudra (si activé). Plus d'un point décimal n'est généralement pas nécessaire, comme décrit dans https://xkcd.com/2170/.
•
usegeoclue (true/false) : Faut-il utiliser une instance locale de geoclue pour déterminer l'emplacement actuel. Sur certaines distributions/configurations, cela peut nécessiter la configuration d'un agent geoclue pour fonctionner correctement. CONFIDENTIALI

TÉ

Darkman déclenchera une transition darkmode/lightmode au coucher du soleil dans l'emplacement actuel. Toute application exécutée localement peut enregistrer ou transmettre l'heure de ces transitions et tenter d'extrapoler des informations relatives à l'emplacement

actuel.

Lorsqu'un navigateur web applique cette transition en même temps, les sites web ouverts peuvent également enregistrer ces

informations.

Un éventuel harceleur ou traqueur peut utiliser les informations ci-dessus pour déduire que vous vous trouvez probablement dans une région du monde où le coucher du soleil est survenu à une heure précise. Cette région est généralement une vaste zone s'étendant sur des dizaines de milliers de kilomètres, mais peut être plus petite pour certaines localisations

géographiques.

L'auteur de cet outil utilise un emplacement configuré manuelleme

nt avec une latitude et une longitude entières pour atteindre
un équilibre raisonnable entre confidentialité et commodité.
