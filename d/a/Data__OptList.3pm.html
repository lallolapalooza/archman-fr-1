DESCRIPTIO

N

Les hachages sont excellents pour stocker des données nommées, mais si vous voulez plus d'une entrée pour un nom, vous devez utiliser une liste de paires. Même dans ce cas, c'est vraiment ennuyeux à écrire

: 
$values = [
  foo => undef,
  bar => undef,
  baz => undef,
  xyz => { ... },
]
;

Regardez tous ces undef ! Ne vous inquiétez pas, nous pouvons nous en débarrasser

: 
$values = [
  map { $_ => undef } qw(foo bar baz),
  xyz => { ... },
]
;

Aaaauuugh ! Nous avons économisé un peu de frappe, mais maintenant il faut réfléchir pour lire, et réfléchir est encore pire que taper... et il y a un bug ! Cela semblait correct, n'est-ce pas ? Eh bien, le "xyz => { ... }" est consommé par le map, et nous n'obtenons pas les données que nous

voulions.

Avec Data::OptList, vous pouvez faire ceci à la place

: 
$values = Data::OptList::mkopt([
  qw(foo bar baz),
  xyz => { ... },
])
;

Cela fonctionne en supposant que tout s

calaire défini est un nom et que toute
référence suivant un nom est sa valeur.

VERSION

PERL

Cette bibliothèque devrait fonctionner sur des versions de perl sorties il y a longtemps. Elle devrait fonctionner sur toute version de perl publiée au cours des cinq dernières

années.

Bien qu'elle puisse fonctionner sur des versions plus anciennes de perl, aucune garantie n'est donnée selon la

quelle la version minimale requise ne sera pas augmentée. La version peut être augmentée pour toute raison, et
il n'y a aucune promesse que des correctifs seront acceptés pour abaisser la version minimale de perl requise.

FONCTION

S

mkop

t 
my $opt_list = Data::OptList::mkopt($input, \%arg)
;

Les arguments valides sont

: 
moniker        - un mot utilisé dans les erreurs pour décrire la liste d'options ; encouragé
require_unique - si vrai, aucun nom ne peut apparaître plus d'une fois
must_be        - les types auxquels les valeurs de la liste d'options sont limitées (décrit ci-dessous)
name_test      - une référence de code utilisée pour tester si une valeur peut être un nom
                 (décrit ci-dessous, mais vous ne voulez probablement pas
cela)

Cela produit un tableau de tableaux ; les tableaux internes sont des paires nom/valeur. Les valeurs seront soit "undef", soit une

référence.

Des paramètres positionnels peuvent être utilisés pour la compatibilité avec l'ancienne interface "mkopt"

: 
my $opt_list = Data::OptList::mkopt($input, $moniker, $req_uni, $must_be)
;

Les valeurs valides pour $inpu

t : 
undef    -> []
hashref  -> [ [ key1 => value1 ] ... ] # les valeurs non-référence deviennent undef
arrayref -> chaque nom suivi d'un non-nom devient une paire : [ name => ref ]
            chaque nom suivi de undef devient une paire : [ name => undef ]
            sinon, cela devient [ name => undef ] comme ceci :
            [ "a", "b", [ 1, 2 ] ] -> [ [ a => undef ], [ b => [ 1, 2 ] ]
]

Par défaut, un nom est tout scalaire défini non-référence. Le paramètre "name_test" peut être une référence de code qui teste si l'argument qui lui est passé est un nom ou non. Cela devrait être utilisé rarement. Les interactions entre "require_unique" et "name_test" ne sont pas encore particulièrement élégantes, car "require_unique" teste simplement l'égalité de chaînes. Cela peut

changer.

Le paramètre "must_be" est soit un scalaire, soit un tableau de scalaires ; il définit quel(s) type(s) de références peuvent être des valeurs. Si une valeur invalide est trouvée, une exception est levée. Si aucune valeur n'est passée pour cet argument, toute référence est valide. Si "must_be" spécifie que les valeurs doivent être CODE, HASH, ARRAY ou SCALAR, alors Params::Util est utilisé pour vérifier si la valeur donnée peut fournir cette interface. Sinon, il vérifie que la valeur donnée est un objet de ce

type.

En d'autres termes

: 
[ qw(SCALAR HASH Object::Known)
]

Signifie

: 
_SCALAR0($value) or _HAS
H($value) or _INSTANCE(
$value, 'Object::Known')

mkopt_has

h 
my $opt_hash = Data::OptList::mkopt_hash($input, $moniker, $must_be)
;

Étant donné une entrée valide pour "mkopt", cette routine renvoie une référence v

ers un hachage. Elle lèver
a une exception si un
nom a plus d'une valeur.
