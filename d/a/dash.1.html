NOM

dash — interpréteur de commandes (shell)

SYNTAXE

dash [-aCefnuvxIimqVEb] [+aCefnuvxIimqVEb] [-o nom_option] [+o nom_option] [fichier_commande [argument ...]]

dash -c [-aCefnuvxIimqVEb] [+aCefnuvxIimqVEb] [-o nom_option] [+o nom_option] chaîne_commande [nom_commande [argument ...]]

dash -s [-aCefnuvxIimqVEb] [+aCefnuvxIimqVEb] [-o nom_option] [+o nom_option] [argument ...]

DESCRIPTION

dash est l'interpréteur de commandes standard pour le système. La version actuelle de dash est en cours de modification pour se conformer aux spécifications POSIX 1003.2 et 1003.2a pour le shell. Cette version possède de nombreuses fonctionnalités qui la font apparaître similaire par certains aspects au shell Korn, mais ce n'est pas un clone du shell Korn (voir ksh(1)). Seules les fonctionnalités désignées par POSIX, plus quelques extensions Berkeley, sont incorporées dans ce shell. Cette page de manuel n'est pas destinée à être un tutoriel ou une spécification complète du shell.

Vue d’ensemble

Le shell est une commande qui lit des lignes depuis un fichier ou le terminal, les interprète et exécute généralement d'autres commandes. C'est le programme qui s'exécute lorsqu'un utilisateur se connecte au système (bien qu'un utilisateur puisse choisir un autre shell avec la commande chsh(1)). Le shell implémente un langage qui a des constructions de contrôle de flux, une facilité de macro qui fournit une variété de fonctionnalités en plus du stockage de données, ainsi que des capacités intégrées d'historique et d'édition de ligne. Il intègre de nombreuses fonctionnalités pour faciliter l'utilisation interactive et présente l'avantage que le langage interprétatif est commun à l'utilisation interactive et non interactive (scripts shell). C'est-à-dire que les commandes peuvent être tapées directement au shell en cours d'exécution ou peuvent être placées dans un fichier et le fichier peut être exécuté directement par le shell.

Invocation

Si aucun argument n'est présent et si l'entrée standard du shell est connectée à un terminal (ou si l'indicateur -i est défini), et que l'option -c n'est pas présente, le shell est considéré comme un shell interactif. Un shell interactif invite généralement avant chaque commande et gère les erreurs de programmation et de commande différemment (comme décrit ci-dessous). Lors du premier démarrage, le shell inspecte l'argument 0, et s'il commence par un tiret ‘-’, le shell est également considéré comme un shell de connexion. Ceci est normalement fait automatiquement par le système lorsque l'utilisateur se connecte pour la première fois. Un shell de connexion lit d'abord les commandes depuis les fichiers /etc/profile et .profile s'ils existent. Si la variable d'environnement ENV est définie à l'entrée d'un shell interactif, ou est définie dans le .profile d'un shell de connexion, le shell lit ensuite les commandes à partir du fichier nommé dans ENV. Par conséquent, un utilisateur devrait placer les commandes à exécuter uniquement au moment de la connexion dans le fichier .profile, et les commandes à exécuter pour chaque shell interactif à l'intérieur du fichier ENV. Pour définir la variable ENV sur un fichier, placez la ligne suivante dans votre .profile de votre répertoire personnel

ENV=$HOME/.shinit; export ENV

en substituant “.shinit” par le nom de fichier de votre choix.

Si des arguments de ligne de commande autres que les options ont été spécifiés, le shell traite le premier argument comme le nom d'un fichier à partir duquel lire les commandes (un script shell), et les arguments restants sont définis comme les paramètres positionnels du shell ($1, $2, etc.). Sinon, le shell lit les commandes depuis son entrée standard.

Traitement de la liste des arguments

Toutes les options à une seule lettre qui ont un nom correspondant peuvent être utilisées comme argument de l'option -o. L'ensemble -o nom est fourni à côté de l'option à une seule lettre dans la description ci-dessous. Spécifier un tiret “-” active l'option, tandis qu'utiliser un plus “+” désactive l'option. Les options suivantes peuvent être définies depuis la ligne de commande ou avec la commande intégrée set (décrite plus loin).

-f noglob

Structure lexicale

Le shell lit l'entrée par lignes à partir d'un fichier et la divise en mots selon les espaces blancs (espaces et tabulations), et selon certaines séquences de caractères spéciales pour le shell appelées « opérateurs ». Il existe deux types d'opérateurs : les opérateurs de contrôle et les opérateurs de redirection (leur signification est discutée plus tard). Voici une liste d'opérateurs :

Opérateurs de contrôle :
& && ( ) ; ;; | || <nouvelle ligne>
Opérateurs de redirection :
< > >| << >> <& >& <<- <>

Guillemets

Les guillemets sont utilisés pour supprimer la signification spéciale de certains caractères ou mots pour le shell, tels que les opérateurs, les espaces blancs ou les mots-clés. Il existe trois types de guillemets : les guillemets simples correspondants, les guillemets doubles correspondants et la barre oblique inverse.

Barre oblique inverse

Une barre oblique inverse préserve le sens littéral du caractère suivant, à l'exception de la ⟨nouvelle ligne⟩. Une barre oblique inverse précédant une ⟨nouvelle ligne⟩ est traitée comme une continuation de ligne.

Guillemets simples

Encadrer des caractères par des guillemets simples préserve le sens littéral de tous les caractères (sauf les guillemets simples, ce qui rend impossible de mettre des guillemets simples dans une chaîne entre guillemets simples).

Guillemets doubles

Encadrer des caractères entre guillemets doubles préserve le sens littéral de tous les caractères sauf le signe dollar ($), le guillemet arrière (`) et la barre oblique inverse (\). La barre oblique inverse à l'intérieur des guillemets doubles est historiquement étrange et sert à n'échapper que les caractères suivants :

$ ` " \ <nouvelle ligne>
. Sinon, elle reste littérale.

Mots réservés

Les mots réservés sont des mots qui ont une signification spéciale pour le shell et qui sont reconnus au début d'une ligne et après un opérateur de contrôle. Les mots suivants sont des mots réservés :

! elif fi while case
else for then { }
do done until if esac

Leur signification est discutée plus loin.

Alias

Un alias est un nom et une valeur correspondante définis à l'aide de la commande intégrée alias(1). Chaque fois qu'un mot réservé peut apparaître (voir ci-dessus), et après vérification des mots réservés, le shell vérifie si le mot correspond à un alias. Si c'est le cas, il le remplace dans le flux d'entrée par sa valeur. Par exemple, s'il existe un alias nommé « lf » avec la valeur « ls -F », alors l'entrée :

lf foobar ⟨retour⟩

deviendrait

ls -F foobar ⟨retour⟩

Les alias fournissent un moyen pratique aux utilisateurs novices de créer des raccourcis pour des commandes sans avoir à apprendre à créer des fonctions avec des arguments. Ils peuvent également être utilisés pour créer du code lexicalement obscur. Cette utilisation est déconseillée.

Commandes

Le shell interprète les mots qu'il lit selon un langage dont la spécification sort du cadre de cette page de manuel (référez-vous à la BNF du document POSIX 1003.2). Essentiellement, une ligne est lue et si le premier mot de la ligne (ou après un opérateur de contrôle) n'est pas un mot réservé, alors le shell a reconnu une commande simple. Sinon, une commande complexe ou une autre construction spéciale peut avoir été reconnue.

Commandes simples

Si une commande simple a été reconnue, le shell effectue les actions suivantes :

  1. Les mots en tête de ligne de la forme « nom=valeur » sont dépouillés et attribués à l'environnement de la commande simple. Les opérateurs de redirection et leurs arguments (tels que décrits ci-dessous) sont dépouillés et sauvegardés pour traitement.
  2. Les mots restants sont développés comme décrit dans la section intitulée « Développements », et le premier mot restant est considéré comme le nom de la commande et la commande est localisée. Les mots restants sont considérés comme les arguments de la commande. Si aucun nom de commande n'en résulte, les affectations de variables « nom=valeur » reconnues à l'étape 1 affectent le shell courant.
  3. Les redirections sont effectuées comme décrit dans la section suivante.

Redirections

Les redirections sont utilisées pour changer l'endroit où une commande lit son entrée ou envoie sa sortie. En général, les redirections ouvrent, ferment ou dupliquent une référence existante à un fichier. Le format général utilisé pour la redirection est :

[n] redir-op fichier

où redir-op est l'un des opérateurs de redirection mentionnés précédemment. Voici une liste des redirections possibles. Le [n] est un nombre optionnel compris entre 0 et 9, comme dans « 3 » (pas « [3] »), qui fait référence à un descripteur de fichier.

[n]> fichier
Redirige la sortie standard (ou n) vers le fichier.
[n]>| fichier
Identique, mais remplace l'option -C.
[n]>> fichier
Ajoute la sortie standard (ou n) au fichier.
[n]< fichier
Redirige l'entrée standard (ou n) depuis le fichier.
[n1]<&n2
Copie le descripteur de fichier n2 en sortie standard (ou descripteur n1). descripteur n2.
[n]<&-
Ferme l'entrée standard (ou n).
[n1]>&n2
Copie le descripteur de fichier n2 en entrée standard (ou descripteur n1). descripteur n2.
[n]>&-
Ferme la sortie standard (ou n).
[n]<> fichier
Ouvre le fichier en lecture et écriture sur l'entrée standard (ou n).

La redirection suivante est souvent appelée « here-document ».

  • [n]<< delimiteur
    texte-here-doc ...
    delimiteur

Tout le texte des lignes successives jusqu'au délimiteur est enregistré et rendu disponible pour la commande sur l'entrée standard, ou sur le descripteur de fichier n s'il est spécifié. Si le délimiteur tel que spécifié sur la ligne initiale est échappé, alors le texte du here-doc est traité littéralement, sinon le texte est soumis à l'expansion des paramètres, à la substitution de commande et à l'expansion arithmétique (comme décrit dans la section sur les « Développements »). Si l'opérateur est « <<- » au lieu de « << », alors les tabulations initiales dans le texte du here-doc sont supprimées.

Recherche et exécution

Il existe trois types de commandes : les fonctions shell, les commandes intégrées et les programmes normaux – et la commande est recherchée (par nom) dans cet ordre. Chacun est exécuté d'une manière différente.

Lorsqu'une fonction shell est exécutée, tous les paramètres positionnels du shell (sauf $0, qui reste inchangé) sont définis sur les arguments de la fonction shell. Les variables qui sont explicitement placées dans l'environnement de la commande (en y affectant des valeurs avant le nom de la fonction) sont rendues locales à la fonction et reçoivent les valeurs données. Ensuite, la commande donnée dans la définition de la fonction est exécutée. Les paramètres positionnels sont restaurés à leurs valeurs d'origine lorsque la commande se termine. Tout cela se produit dans le shell courant.

Les commandes intégrées du shell sont exécutées en interne au shell, sans créer de nouveau processus.

Sinon, si le nom de la commande ne correspond pas à une fonction ou à une commande intégrée, la commande est recherchée comme un programme normal dans le système de fichiers (comme décrit dans la section suivante). Lorsqu'un programme normal est exécuté, le shell exécute le programme, en passant les arguments et l'environnement au programme. Si le programme n'est pas un fichier exécutable normal (c'est-à-dire s'il ne commence pas par le « nombre magique » dont la représentation ASCII est « #! », de sorte que execve(2) renvoie ENOEXEC alors), le shell interprétera le programme dans un sous-shell. Le shell enfant se réinitialisera dans ce cas, de sorte que l'effet sera comme si un nouveau shell avait été invoqué pour gérer le script shell ad hoc, sauf que l'emplacement des commandes mises en cache trouvées dans le shell parent sera mémorisé par l'enfant.

Notez que les versions précédentes de ce document et du code source itself misleadingly and sporadically refer to a shell script without a magic number as a "shell procedure".

Recherche du chemin

Pour localiser une commande, le shell vérifie d'abord s'il possède une fonction shell portant ce nom. Ensuite, il recherche une commande intégrée portant ce nom. Si une commande intégrée n'est pas trouvée, l'une des deux choses suivantes se produit :

  1. Les noms de commandes contenant une barre oblique sont simplement exécutés sans effectuer de recherches.
  2. Le shell recherche successivement chaque entrée dans PATH pour la commande. La valeur de la variable PATH doit être une série d'entrées séparées par des deux-points. Chaque entrée se compose d'un nom de répertoire. Le répertoire courant peut être indiqué implicitement par un nom de répertoire vide, ou explicitement par un point unique.

Statut de sortie de la commande

Chaque commande a un statut de sortie qui peut influencer le comportement des autres commandes shell. Le paradigme est qu'une commande se termine avec zéro pour un succès normal ou une réussite, et une valeur non nulle pour un échec, une erreur ou une indication fausse. La page de manuel de chaque commande doit indiquer les différents codes de sortie et ce qu'ils signifient. De plus, les commandes intégrées retournent des codes de sortie, tout comme une fonction shell exécutée.

Si une commande se compose entièrement d'affectations de variables, le statut de sortie de la commande est celui de la dernière substitution de variable, le cas échéant, sinon 0.

Commandes complexes

Les commandes complexes sont des combinaisons de commandes simples avec des opérateurs de contrôle ou des mots réservés, créant ainsi une commande complexe plus grande. Plus généralement, une commande est l'une des suivantes :

  • commande simple
  • pipeline
  • liste ou liste composée
  • commande composée
  • définition de fonction

Sauf indication contraire, le statut de sortie d'une commande est celui de la dernière commande simple exécutée par la commande.

Pipelines

Un pipeline est une séquence d'une ou plusieurs commandes séparées par l'opérateur de contrôle |. La sortie standard de toutes les commandes sauf la dernière est connectée à l'entrée standard de la commande suivante. La sortie standard de la dernière commande est héritée du shell, comme d'habitude.

Le format d'un pipeline est :

[!] commande1 [| commande2 ...]

La sortie standard de commande1 est connectée à l'entrée standard de commande2. L'entrée standard, la sortie standard ou les deux d'une commande sont considérées comme étant affectées par le pipeline avant toute redirection spécifiée par les opérateurs de redirection qui font partie de la commande.

Si le pipeline n'est pas en arrière-plan (discuté plus tard), le shell attend que toutes les commandes soient terminées.

Si le mot réservé ! ne précède pas le pipeline, le statut de sortie est le statut de sortie de la dernière commande spécifiée dans le pipeline. Sinon, le statut de sortie est le NOT logique du statut de sortie de la dernière commande. C'est-à-dire, si la dernière commande retourne zéro, le statut de sortie est 1 ; si la dernière commande retourne une valeur supérieure à zéro, le statut de sortie est zéro.

Étant donné que l'affectation de pipeline de l'entrée standard ou de la sortie standard ou des deux a lieu avant la redirection, elle peut être modifiée par la redirection. Par exemple :

$ command1 2>&1 | command2

envoie la sortie standard et la sortie d'erreur de command1 à l'entrée standard de command2.

Un terminateur ; ou ⟨nouvelle ligne⟩ provoque l'exécution séquentielle de la liste ET-OU précédente (décrite ensuite) ; un & provoque l'exécution asynchrone de la liste ET-OU précédente.

Notez que, contrairement à certains autres shells, chaque processus du pipeline est un enfant du shell appelant (sauf s'il s'agit d'une commande intégrée du shell, auquel cas il s'exécute dans le shell courant – mais tout effet qu'il a sur l'environnement est annulé).

Commandes en arrière-plan – &

Si une commande est terminée par l'opérateur de contrôle ampersand (&), le shell exécute la commande de manière asynchrone – c'est-à-dire que le shell n'attend pas que la commande soit terminée avant d'exécuter la commande suivante.

Le format pour exécuter une commande en arrière-plan est :

commande1 & [commande2 & ...]

Si le shell n'est pas interactif, l'entrée standard d'une commande asynchrone est définie sur /dev/null.

Listes – en général

Une liste est une séquence de zéro ou plusieurs commandes séparées par des nouvelles lignes, des points-virgules ou des ampersands, et facultativement terminée par l'un de ces trois caractères. Les commandes d'une liste sont exécutées dans l'ordre où elles sont écrites. Si une commande est suivie d'un ampersand, le shell démarre la commande et passe immédiatement à la commande suivante ; sinon, il attend que la commande se termine avant de passer à la suivante.

Opérateurs de liste à court-circuit

“&&” et “||” sont des opérateurs de liste ET-OU. “&&” exécute la première commande, puis exécute la seconde commande si et seulement si le statut de sortie de la première commande est zéro. “||” est similaire, mais exécute la seconde commande si et seulement si le statut de sortie de la première commande est non nul. “&&” et “||” ont tous deux la même priorité.

Structures de contrôle – if, while, for, case

La syntaxe de la commande if est

if liste
then liste
[ elif liste
then    liste ] ...
[ else liste ]
fi

La syntaxe de la commande while est

while liste
do   liste
done

Les deux listes sont exécutées de manière répétée tant que le statut de sortie de la première liste est zéro. La commande until est similaire, mais porte le mot until à la place de while, ce qui provoque sa répétition jusqu'à ce que le statut de sortie de la première liste soit zéro.

La syntaxe de la commande for est

for variable [ in [ mot ... ] ]
do   liste
done

Les mots suivant in sont développés, puis la liste est exécutée de manière répétée avec la variable définie sur chaque mot à tour de rôle. Omettre in word ... équivaut à in "$@".

La syntaxe des commandes break et continue est

break [ num ]
continue [ num ]

Break termine les num boucles for ou while les plus imbriquées. Continue continue avec la prochaine itération de la boucle la plus imbriquée. Celles-ci sont implémentées comme des commandes intégrées.

La syntaxe de la commande case est

case mot in
[(]motif) liste ;;
...
esac

Le motif peut en fait être un ou plusieurs motifs (voir Motifs du shell décrits plus loin), séparés par des caractères “|”. Le caractère “(” avant le motif est facultatif.

Regroupement des commandes

Les commandes peuvent être regroupées en écrivant soit

(liste)

soit

{ liste; }

La première de ces formes exécute les commandes dans un sous-shell. Les commandes intégrées groupées dans un (liste) n'affecteront pas le shell courant. La seconde forme ne crée pas un nouveau processus pour le shell, elle est donc légèrement plus efficace. Le regroupement des commandes de cette manière vous permet de rediriger leur sortie comme s'il s'agissait d'un seul programme :

{ printf " bonjour " ; printf " monde\n" ; } > greeting

Notez que “}” doit suivre un opérateur de contrôle (ici, “;”) afin qu'il soit reconnu comme un mot réservé et non comme un autre argument de commande.

Fonctions

La syntaxe d'une définition de fonction est

nom () commande

Une définition de fonction est une instruction exécutable ; lorsqu'elle est exécutée, elle installe une fonction nommée nom et retourne un statut de sortie de zéro. La commande est normalement une liste encadrée par “{” et “}”.

Les variables peuvent être déclarées comme locales à une fonction en utilisant la commande local. Celle-ci doit apparaître comme première instruction d'une fonction, et sa syntaxe est

local [variable | -] ...

Local est implémenté comme une commande intégrée.

Lorsqu'une variable est rendue locale, elle hérite de la valeur initiale et des drapeaux exportés et en lecture seule de la variable du même nom dans la portée environnante, s'il y en a une. Sinon, la variable est initialement non définie. Le shell utilise la portée dynamique, de sorte que si vous rendez la variable x locale à la fonction f, qui appelle ensuite la fonction g, les références à la variable x faites dans g feront référence à la variable x déclarée dans f, et non à la variable globale nommée x.

Le seul paramètre spécial qui peut être rendu local est “-”. Rendre “-” local signifie que toute option de shell modifiée via la commande set à l'intérieur de la fonction sera restaurée à ses valeurs d'origine lorsque la fonction retournera.

La syntaxe de la commande return est

return [exitstatus
]

Elle termine la fonction actuellement exécutée. Return est implémenté comme une commande intégrée.

Variables et paramètres

Le shell maintient un ensemble de paramètres. Un paramètre désigné par un nom est appelé une variable. Au démarrage, le shell transforme toutes les variables d'environnement en variables shell. De nouvelles variables peuvent être définies en utilisant la forme

nom=valu

Expansion du chemin (Génération de noms de fichiers)

Sauf si le drapeau -f est défini, la génération des noms de fichiers est effectuée une fois la division des mots terminée. Chaque mot est considéré comme une série de motifs, séparés par des barres obliques. Le processus d'expansion remplace le mot par les noms de tous les fichiers existants dont les noms peuvent être formés en remplaçant chaque motif par une chaîne qui correspond au motif spécifié. Il y a deux restrictions à cela : premièrement, un motif ne peut pas correspondre à une chaîne contenant une barre oblique, et deuxièmement, un motif ne peut pas correspondre à une chaîne commençant par un point, à moins que le premier caractère du motif ne soit un point. La section suivante décrit les motifs utilisés pour l'expansion du chemin et la commande case.

Motifs de Shell

Un motif se compose de caractères normaux, qui correspondent à eux-mêmes, et de métacaractères. Les métacaractères sont « ! », « * », « ? », et « [ ». Ces caractères perdent leur signification spéciale s'ils sont mis entre guillemets. Lorsque la substitution de commande ou de variable est effectuée et que le signe dollar ou les guillemets inversés ne sont pas entre guillemets doubles, la valeur de la variable ou la sortie de la commande est analysée pour ces caractères et ils sont transformés en métacaractères.

Un astérisque (« * ») correspond à toute chaîne de caractères. Un point d'interrogation correspond à un seul caractère. Une parenthèse gauche (« [ ») introduit une classe de caractères. La fin de la classe de caractères est indiquée par une parenthèse droite (« ] ») ; si le « ] » est manquant, alors le « [ » correspond à un « [ » plutôt qu'à l'introduction d'une classe de caractères. Une classe de caractères correspond à l'un des caractères situés entre les crochets. Une plage de caractères peut être spécifiée à l'aide d'un trait d'union. La classe de caractères peut être complétée en faisant du point d'exclamation le premier caractère de la classe de caractères.

Pour inclure un « ] » dans une classe de caractères, faites-en le premier caractère listé (après le « ! », le cas échéant). Pour inclure un trait d'union, faites-en le premier ou le dernier caractère listé.

Pour les formats e, E, f, g et G, le résultat contiendra toujours un point décimal, même si aucun chiffre ne suit le point (normalement, un point décimal n'apparaît dans les résultats de ces formats que si un chiffre suit le point décimal). Pour les formats g et G, les zéros de fin ne sont pas supprimés du résultat comme ils le seraient autrement.

set [{ -options | +options | -- }] arg ...
La commande set effectue trois fonctions différentes.

Sans arguments, elle liste les valeurs de toutes les variables du shell.

Si des options sont données, elle définit les indicateurs d'options spécifiés, ou les efface comme décrit dans la section intitulée Traitement de la liste des arguments. À titre de cas spécial, si l'option est -o ou +o et qu'aucun argument n'est fourni, le shell imprime les paramètres de toutes ses options. Si l'option est -o, les paramètres sont imprimés dans un format lisible par l'homme ; si l'option est +o, les paramètres sont imprimés dans un format adapté à une ré-entrée dans le shell pour affecter les mêmes paramètres d'options.

La troisième utilisation de la commande set est de définir les valeurs des paramètres positionnels du shell aux arguments spécifiés. Pour modifier les paramètres positionnels sans modifier les options, utilisez « -- » comme premier argument de set. Si aucun argument n'est présent, la commande set effacera tous les paramètres positionnels (équivalent à l'exécution de « shift $# »).
