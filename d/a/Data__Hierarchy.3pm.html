NOM

Data::Hierarchy - Gérer des données dans une structure hiérarchique

SYNOPSIS

my $tree = Data::Hierarchy->new();
$tree->store ('/', {access => 'all'});
$tree->store ('/private', {access => 'auth',
                           '.note' => 'this is private'});
$info = $tree->get ('/private/somewhere/deep');
# return actual data points in list context
($info, @fromwhere) = $tree->get ('/private/somewhere/deep');
my @items = $tree->find ('/', {access => qr/.*/});
# override all children
$tree->store ('/', {'.note' => undef}, {override_sticky_descendents => 1});

DESCRIPTION

Data::Hierarchy fournit une interface simple pour manipuler des données héritables attachées à un environnement hiérarchique (comme un système de fichiers).

Une utilisation de Data::Hierarchy est de permettre à une application d'annoter des chemins dans un vrai système de fichiers dans une seule structure de données compacte. Cependant, la hiérarchie n'a pas besoin de correspondre réellement à un système de fichiers existant.

Les chemins dans une hiérarchie sont référencés avec une syntaxe de type Unix ; "/" est le « répertoire » racine. (Vous pouvez spécifier un caractère séparateur différent du slash lorsque vous construisez un objet Data::Hierarchy.) À l'exception du chemin racine, les chemins ne doivent jamais contenir de slash final. Vous pouvez associer des propriétés, qui sont des paires nom/valeur arbitraires, à n'importe quel chemin. (Les propriétés ne peuvent pas contenir la valeur indéfinie.) Par défaut, les propriétés sont héritées par les chemins enfants : ainsi, si vous stockez des données à "/some/path":

$tree->store('/some/path', {color => 'red'});

vous pouvez les récupérer à nouveau à "/some/path/below/that":

print $tree->get('/some/path/below/that')->{'color'};
# prints red

D'un autre côté, les propriétés dont les noms commencent par un point ne sont pas héritées, ou sont « collantes » (sticky) :

$tree->store('/some/path', {'.color' => 'blue'});
print $tree->get('/some/path')->{'.color'};            # prints blue
print $tree->get('/some/path/below/that')->{'.color'}; # undefined

Notez que vous n'avez pas besoin (et en fait, vous ne pouvez pas) d'ajouter explicitement des « fichiers » ou des « répertoires » à la hiérarchie ; vous ajoutez et supprimez simplement des propriétés aux chemins.

CONSTRUCTEUR

Crée un nouvel objet hiérarchie. Prend les options suivantes :

sep
La chaîne utilisée comme séparateur entre les niveaux de chemin. Par défaut '/'.

MÉTHODES

Méthodes d'instance

"store $path, $properties, {%options}"
Étant donné un chemin et une référence de hachage de propriétés, stocke les propriétés au chemin.

Sauf si l'option "override_descendents" est fournie avec une valeur fausse, cela élimine toute propriété non collante dans un descendant de $path avec le même nom.

Si l'option "override_sticky_descendents" est fournie avec une valeur vraie, cela élimine toute propriété collante dans un descendant de $path avec le même nom. La remplacer.

Une valeur undef supprime cette valeur ; notez cependant que si un ancêtre de $path définit cette propriété, la valeur de l'ancêtre y sera héritée ; c'est-à-dire, avec :

$t->store('/a',   {k => 'top'});
$t->store('/a/b', {k => 'bottom'});
$t->store('/a/b', {k => undef});
print $t->get('/a/b')->{'k'};

cela affichera 'top'.

"get $path, [$dont_clone]"
Étant donné un chemin, recherche toutes les propriétés (collantes ou non) et les retourne dans une référence de hachage. Les valeurs sont des clones, sauf si vous passez une valeur vraie pour $dont_clone.

Si appelé en contexte de liste, retourne cette référence de hachage suivie de tous les chemins ancestraux de $path qui contiennent des propriétés non collantes (possiblement en incluant lui-même).

"find $path, $property_regexps"
Étant donné un chemin et une référence de hachage de paires nom/expression régulière, retourne une liste de tous les chemins qui sont des descendants de $path (y compris lui-même) et qui définissent à ce chemin lui-même (non héritées) toutes les propriétés du hachage avec des valeurs correspondant aux expressions régulières données. (Vous voudrez peut-être utiliser "qr/.*/" pour simplement voir s'il a une valeur définie là.) Les propriétés peuvent être collantes ou non.
"merge $other_hierarchy, $path"
Étant donné un second objet Data::Hierarchy et un chemin, copie toutes les propriétés de l'autre objet à $path ou en dessous vers les chemins correspondants de l'objet sur lequel cette méthode est invoquée. Toutes les propriétés de l'objet sur lequel elle est invoquée à $path ou en dessous sont d'abord effacées.
"to_relative $base_path"
Étant donné un chemin qui doit contenir chaque élément de la hiérarchie, retourne un objet spécial Data::Hierarchy::Relative qui représente la hiérarchie relative à ce chemin. La seule chose que vous pouvez faire avec un objet Data::Hierarchy::Relative est d'appeler seulement thing you can do with a Data::Hierarchy::Relative object is call to_absolute($new_base_path) dessus, qui retourne un nouvel objet Data::Hierarchy à ce chemin de base. Par exemple, si tout dans la hiérarchie est enraciné à "/home/super_project" et que cela doit être déplacé vers "/home/awesome_project", vous pouvez faire 
$hierarchy = $hierarchy->to_relative('/home/super_project')->to_absolute('/home/awesome_project');

(Les objets Data::Hierarchy::Relative peuvent être un format de sérialisation plus pratique que les objets Data::Hierarchy, s'ils suivent l'état de certaines ressources relocalisables.)
