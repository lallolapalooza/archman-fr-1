tzset(3) Manuel des fonctions de bibliothèque tzset(3)

NOM

tzset, tzname, timezone, daylight - initialiser les informations de conversion de l'heure

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#include <time.h>
void tzset(void);
extern char *tzname[2];
extern long timezone;
extern int daylight;
Exigences des macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

tzset() :

    _POSIX_C_SOURCE

tzname:

    _POSIX_C_SOURCE

timezone, daylight:

    _XOPEN_SOURCE
        || /* glibc >= 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */ _SVID_SOURCE

DESCRIPTION

La fonction tzset() initialise la variable tzname à partir de la variable d'environnement TZ . Cette fonction est automatiquement appelée par les autres fonctions de conversion de l'heure qui dépendent du fuseau horaire. Dans un environnement de type System-V, elle définit également les variables timezone (secondes à l'ouest de l'UTC) et daylight (à 0 si ce fuseau horaire n'a pas de règles d'heure d'été, ou à une valeur non nulle s'il existe un moment, passé, présent ou futur, où l'heure d'été s'applique).

La fonction tzset() initialise ces variables à des valeurs indéterminées si ce fuseau horaire est un fuseau horaire géographique comme « America/New_York » (voir ci-dessous).

Si la variable TZ n'apparaît pas dans l'environnement, le fuseau horaire du système est utilisé. Le fuseau horaire du système est configuré en copiant, ou en liant, un fichier au format tzfile(5) vers /etc/localtime. Une base de données de fuseaux horaires de ces fichiers peut être située dans le répertoire des fuseaux horaires du système (voir la section FICHIERS ci-dessous).

Si la variable TZ apparaît dans l'environnement, mais que sa valeur est vide, ou que sa valeur ne peut pas être interprétée en utilisant l'un des formats spécifiés ci-dessous, alors le Temps Universel Coordonné (UTC) est utilisé.

Une valeur non vide de TZ peut être l'un des deux formats, chacun pouvant être précédé par un deux-points qui est ignoré. Le premier format est une chaîne de caractères qui représente directement le fuseau horaire à utiliser :


std offset[dst[offset][,start[/time],end[/time]]]

Il n'y a pas d'espaces dans la spécification. La chaîne std spécifie une abréviation pour le fuseau horaire et doit être composée de trois caractères alphabétiques ou plus. Lorsqu'elle est encadrée par les signes inférieur à (<) et supérieur à (>), le jeu de caractères est étendu pour inclure le signe plus (+), le signe moins (-) et les chiffres. La chaîne offset suit immédiatement std et spécifie la valeur temporelle à ajouter à l'heure locale pour obtenir le Temps Universel Coordonné (UTC). Le offset est positif si le fuseau horaire local est à l'ouest du méridien de Greenwich et négatif s'il est à l'est. L'heure doit être comprise entre 0 et 24, et les minutes et secondes entre 00 et 59 :


[+|-]hh[:mm[:ss]]

La chaîne dst et le offset spécifient le nom et le décalage pour le fuseau horaire d'été correspondant. Si le décalage est omis, il vaut par défaut une heure de plus que l'heure standard.

Le champ start spécifie quand l'heure d'été entre en vigueur et le champ end spécifie quand le retour à l'heure standard est effectué. Ces champs peuvent avoir les formats suivants :

Jn
Cela spécifie le jour julien avec n entre 1 et 365. Les jours bissextiles ne sont pas comptés. Dans ce format, le 29 février ne peut pas être représenté ; le 28 février est le jour 59, et le 1er mars est toujours le jour 60.
n
Cela spécifie le jour julien à base zéro avec n entre 0 et 365. Le 29 février est compté les années bissextiles.
Mm.w.d
Cela spécifie le jour d (0 <=d<= 6) de la semaine w (1 <=w<= 5) du mois m (1 <=m<= 12). La semaine 1 est la première semaine où le jour d survient et la semaine 5 est la dernière semaine où le jour d survient. Le jour 0 est un dimanche.

Les champs time spécifient quand, dans l'heure locale actuellement en vigueur, le changement vers l'autre heure se produit. Ils utilisent le même format que offset sauf que l'heure peut être dans l'intervalle [-167, 167] pour représenter des moments avant et après le jour nommé. Si omis, la valeur par défaut est 02:00:00.

Voici un exemple pour la Nouvelle-Zélande, où l'heure standard (NZST) est de 12 heures à l'avance sur l'UTC, et l'heure d'été (NZDT), de 13 heures à l'avance sur l'UTC, s'applique du dernier dimanche de septembre, à l'heure par défaut 02:00:00, au premier dimanche d'avril à 03:00:00.


TZ="NZST-12:00:00NZDT-13:00:00,M9.5.0,M4.1.0/3"

Le second — ou « géographique » — format spécifie que les informations de fuseau horaire doivent être lues depuis un fichier :


filespec

Le filespec spécifie un fichier au format tzfile(5)à partir duquel lire les informations de fuseau horaire. Si filespec ne commence pas par un «/», la spécification de fichier est relative au répertoire des fuseaux horaires du système. Si le fichier spécifié ne peut pas être lu ou interprété, le Temps Universel Coordonné (UTC) est utilisé ; cependant, les applications ne doivent pas compter sur le fait que des valeurs arbitraires de filespec représentent l'UTC, car les formats TZ peuvent être étendus à l'avenir.

Voici un exemple, encore une fois pour la Nouvelle-Zélande :


TZ="Pacific/Auckland"

ENVIRONNEMENT

TZ
Si cette variable est définie, sa valeur prime sur le fuseau horaire configuré par le système.
TZDIR
Si cette variable est définie, sa valeur prime sur le chemin du répertoire de la base de données des fuseaux horaires configuré par le système.

FICHIERS

/etc/localtime
Le fichier du fuseau horaire du système.
/usr/share/zoneinfo/
Le répertoire de la base de données des fuseaux horaires du système.
/usr/share/zoneinfo/posixrules
Lorsqu'une chaîne TZ inclut un fuseau horaire dst sans rien après, ce fichier est utilisé pour les règles de début/fin. Il est au format tzfile(5) . Par défaut, le Makefile de zoneinfo le lie durement au fichier America/New_York tzfile.

Ce qui précède sont les emplacements de fichiers standards actuels, mais ils sont configurables lorsque glibc est compilé.
