PRÉAMBUL

E

Ce module fournit quelques profils d'exemple (c'est-à-dire des schémas de jours fériés) pour une utilisation avec les modules Date::Calendar(3) et Date::Calendar::Year(3)

.

Vous n'êtes pas obligé d'utiliser ceux-ci, vous pouvez toujours créer les vôtres (c'est très facile). Voir la section « COMMENT CRÉER LES VÔTRES » ci-dessous pour plus d'instructions sur la façon de procéder, et prenez les profils de ce module comme

exemples.

Je n'ai pas l'intention d'apporter de corrections à l'un des profils de calendrier de ce module, sauf s'il y a des raisons TRÈS convaincantes de le faire. Ces profils ne sont destinés qu'à servir

d'exemples.

La façon recommandée d'utiliser ces profils est de les copier dans votre propre code puis de les modifier selon vos besoins. Sinon, beaucoup de gens pourraient être négativement affectés si j'apportais des modifications à un profil que quelqu'un utilise depuis des

années.

Toute amélioration est do

nc laissée comme exercice
au lecteur intéressé.

DESCRIPTIO

N

La méthode «init() » dans le module Date::Calendar::Year(3) est responsable de l'analyse des schémas de calendrier contenus ici dans le module Date::Calendar::

Profiles.

Cette méthode offre un « mini-langage » qui permet de spécifier des formules de date courantes, comme par exemple une date fixe simple (dans différents formats, p. ex. américain ou européen), ou des choses comme « le deuxième dimanche de mai » (fête des mères), ou « dimanche de Pâques moins 46 jours » (mercredi des Cendres), pour n'en citer que

quelques-unes.

Voir la section « SYNTAXE DES FORMULES DE DATE » ci-dessous pour plus de

détails.

Il existe cependant des formules plus compliquées qui ne peuvent pas être exprimées en des termes aussi

simples.

La règle selon laquelle, si un jour férié tombe un week-end, il sera remplacé soit par le vendredi ou le lundi adjacent (selon lequel est le plus proche), en est un

exemple.

Afin de pouvoir traiter de telles formules, et afin d'être aussi flexible que possible, la méthode «init() » offre la possibilité d'utiliser des fonctions de rappel (callbacks) pour traiter de telles dates et

formules.

Voir la section « INTERFACE DE RAPPEL » ci-dessous pour plus de détails sur ce

sujet.

Afin de vous aider avec les cas plus courants de formules inhabituelles, le module Date::Calendar::Profiles exporte les sous-routines utilitaires suivantes (qui sont destinées à être utilisées comme « filtres » dans des fonctions de rappel de votre propre code) 

:
  • « ($year,$month,$day[,ANYTHING]) = Previous_Friday($year,$month,$day[,ANYTHING]); »

    Si la date donnée tombe un samedi ou un dimanche, cette fonction change la date en le vendredi adjacent précédent, et retourne cette nouvelle

    date.

    Sinon, la date donnée est retournée

    inchangée.

    Le reste des paramètres d'entr

    ée, s'il y en a, est simplement
    • copié vers la sortie.
  • « ($year,$month,$day[,ANYTHING]) = Next_Monday($year,$month,$day[,ANYTHING]); »

    Si la date donnée tombe un samedi ou un dimanche, cette fonction change la date en le lundi adjacent suivant, et retourne cette nouvelle

    date.

    Sinon, la date donnée est retournée

    inchangée.

    Le reste des paramètres d'entr

    ée, s'il y en a, est simplement
    • copié vers la sortie.
  • « ($year,$month,$day[,ANYTHING]) = Next_Monday_or_Tuesday($year,$month,$day[,ANYTHING]); »

    Si la date donnée tombe un samedi, la date du prochain lundi (après ce week-end) est

    retournée.

    Si la date donnée tombe un dimanche, la date du prochain mardi (après ce week-end) est

    Si la date donnée tombe un lundi, la date du prochain mardi (le jour suivant le lundi) est

INTERFACE DES FONCTIONS DE

RAPPEL

L'interface des fonctions de rappel à utiliser avec la méthode "init()" du module Date::Calendar::Year(3) est très simple

:

La fonction de rappel reçoit deux arguments lorsqu'elle est appelée : d'abord le numéro de l'année pour laquelle le jour férié doit être calculé, puis le nom (le « label ») du jour férié en question (qui sert de clé dans le hachage d'un schéma de jours fériés)

.

Ce deuxième paramètre vous permet d'utiliser la même fonction de rappel pour différents jours fériés, ce qui peut être plus pratique (que des fonctions de rappel distinctes) si, par exemple, vous avez un ensemble de jours fériés similaires à calculer, comme par exemple les quatre dimanches avant Noël (« Avent »)

.

La fonction de rappel "Advent()" (exportée par le module Date::Calendar::Profiles) illustre cette

technique.

On attend que la fonction de rappel retourne une liste ""($year,$month,$day)"" avec la date exacte du jour férié (le numéro d'année dans la sortie doit bien sûr correspondre au numéro d'année passé en paramètre)

.

Une erreur fatale se produit si la liste retournée ne constitue pas une date valide, dans l'année

demandée.

En option, la fonction de rappel peut retourner une quatrième valeur (après la date) contenant une chaîne, qui peut être soit "#" ou ":

".

La chaîne "#" signifie que la date en question est une date purement commémorative, c'est-à-dire que vous n'avez pas de jour de congé ce

jour-là.

La chaîne ":" signifie que la date en question est un jour férié « partiel », c'est-à-dire un jour où vous avez un demi-jour de

congé.

Si le jour férié en question n'a pas été observé ou n'existait pas dans l'année demandée, la fonction de rappel peut également retourner une liste vide. Cela fera que la méthode "init()" ignorera simplement ce jour férié pour cette

année.

Le module Date::Calendar::Profiles exporte les fonctions de rappel d'exemple "Advent1()", "Advent2()", "Advent3()", "Advent4()" et "Advent()", qui peuvent vous aider

à élaborer vos pro
pres profils.

COMMENT ÉLABORER VOTRE PROPRE

PROFIL

Chaque profil de calendrier (schéma de jours fériés) est un

hachage.

Le nom du jour férié (comme « Noël », par exemple) sert de clé dans ce hachage et doit donc être unique (sauf si vous souhaitez remplacer une valeur par défaut qui a été définie précédemment, mais voir ci-dessous pour plus de détails à ce sujet)

.

La valeur de chaque clé est soit une chaîne, qui spécifie une formule de date simple, soit la référence d'une fonction de

rappel.

Voir la section « INTERFACE DES FONCTIONS DE RAPPEL » ci-dessus pour une description de l'interface (entrée et sortie) de ces fonctions de

rappel.

Voir la section « SYNTAXE DES FORMULES DE DATE » ci-dessus et la description de la méthode "init()" dans Date::Calendar::Year(3) pour la syntaxe exacte des chaînes de formules de

date.

ATTENTION : si les clés ne sont pas uniques dans le code source, les entrées ultérieures écraseront les précédentes ! C'est-à-dire que

: 
...
"Mon jour férié spécial" => "01-11",
"Mon jour férié spécial" => "02-11",
..
.

ne définira PAS deux jours fériés portant le même nom, l'un le premier novembre, l'autre le deuxième novembre, mais seulement un, le deuxième novembre

!

Par conséquent, afin d'utiliser des ensembles de valeurs par défaut et de pouvoir en remplacer certaines, vous devez D'ABORD inclure tout hachage contenant les définitions par défaut, puis ENSUITE écrire vos propres définitions (voir aussi le module Date::Calendar::Profiles pour des exemples de cela !), comme ceci

: 
$defaults =
{
    "Jour férié #1" => "01-01",
    "Jour férié #2" => "02-02",
    "Jour férié #3" => "03-03"
};
$variant1 =
{
    %$defaults,
    "Jour férié #2" => "09-02",
    "Jour férié #4" => "04-04"
}
;

Cela est dû à la manière dont fonctionnent les hachages en

Perl.

Maintenant, supposons que vous souhaitiez écrire un profil contenant les anniversaires ou les dates de fête de tous vos proches et

amis.

Simplement, énumérez-les dans votre programme, dans l'ordre de votre choix, comme suit (par exemple)

: 
$Birthdays =
{
    "Conjoint 1971"             =>  "30.12.",
    "Jour de mariage 1992"        =>  "01.09.",
    "Saint-Valentin"         =>  "14.02.",
    "Fils Richard 1996"        =>  "11.05.",
    "Fille Irene 1994"     =>  "17.01.",
    "Maman 1939"                =>  "19.08.",
    "Papa 1937"                =>  "23.04.",
    "Frère Timothy 1969"    =>  "24.04.",
    "Sœur Catherine 1973"   =>  "21.10.",
    "Cousin Paul 1970"        =>  "16.10.",
    "Tante Marjorie 1944"      =>  "09.06.",
    "Oncle George 1941"       =>  "02.08.",
    "Ami Alexander 1968"   =>  "12.06.",
}
;

Les numéros d'année après les noms ne sont pas vraiment nécessaires, mais ils nous permettent d'afficher l'âge actuel de la personne. Si ce numéro d'année est omis, nous n'affichons tout simplement pas

l'âge.

Maintenant, pour interroger cette base de données d'anniversaires, nous pouvons utiliser le petit programme suivant

: 
#!perl -w
use strict;
no strict "vars";
use Date::Calc qw(:all);
use Date::Calendar;
$Birthdays =
{
    ... # (voir ci-dessus)
};
@today = Today();
$calendar = Date::Calendar->new( $Birthdays );
$calendar->year( $today[0] );
foreach $key (@ARGV)
{
    if (@list = $calendar->search( $key ))
    {
        foreach $date (@list)
        {
            @labels = $calendar->labels( $date );
            $dow = shift(@labels);
            # Plusieurs personnes peuvent avoir leur anniversaire à la même date :
            $name = $key;
            foreach $person (@labels)
            {
                if (index(lc($person),lc($key)) >= 0)
                {
                    $name = $person;
                    last;
                }
            }
            $delta = Delta_Days(@today, $date->date());
            $age = '';
            if ($name =~ s!\s*(\d+)\s*$!!)
            {
                $age = $today[0] - $1;
                $age-- if ($delta > 0);
                $age = sprintf(" (%2d ans)", $age);
            }
            printf
            (
                "%-20.20s: %+5d jours => %3.3s %2d-%3.3s-%4d%s\n",
                $name,
                $delta,
                $dow,
                $date->day(),
                Month_to_Text($date->month()),
                $date->year(),
                $age
            );
        }
    }
    else { print "Aucune entrée trouvée dans la liste d'anniversaires pour '$key' !\n" }
}
__END__

Enregistrons ce programme sous le nom, par exemple, "birthday.

pl".

LIMITATION

S

Les profils de calendrier inclus dans ce module ne prennent généralement pas en compte les irrégularités historiques (même si certains le font afin de montrer comment cela peut être fait), ils ne fournissent que les moyens de calculer les événements qui se répètent régulièrement (les profils ne doivent donc pas être considérés comme faisant f

oi sur le plan
historique).

BUGS

CONNUS

Les profils de calendrier australiens sont connus pour contenir des dates erronées. Cela est dû au fait que l'Australie décrète ses jours fériés individuel

lement pour chaque année, ce qui rend difficile le calcul des jours fériers au moyen d'une formule. Un effort est en cours pour comparer (et corriger) l'im
plémentation actuelle avec les documents officiels (pages web) des autorités australiennes. Cela n'est pas encore terminé car cela prend beaucoup de temps.
