Ce document décrit les informations de configuration stockées dans chaq

DESCRIPTIO

N

Date::Manip est un ensemble de modules très configurable. Beaucoup de ses comportements peuvent être modifiés pour changer la façon dont les opérations sur les dates sont effectuées. Pour ce faire, une liste de variables de configuration peut être définie qui spécifie de nombreux comportements de Date::

Manip.

Il existe trois façons de définir les variables de configuration. Les deux premières consistent à les passer lors de la création d'un objet, ou à les passer à la méthode config après la création de l'objet. Tous les modules principaux de Date::Manip (Date::Manip::Base, Date::Manip::TZ, Date::Manip::Date, Date::Manip::Delta et Date::Manip::Recur) ont la méthode

config.

Par exemple, vous pouvez créer et configurer un objet Date::Manip::Date en utilisant les commandes

: 
$date = new Date::Manip::Date;
$date->config($var1,$val1,$var2,$val2,...)
;

Cela peut être raccourci en

: 
$date = new Date::Manip::Date [$var1,$val1,...]
;

Les valeurs des variables de configuration sont stockées dans l'objet Date::Manip::Base. Ainsi, si vous avez un objet Date::Manip::Date, il a un objet Date::Manip::Base qui lui est associé, et les informations de configuration y sont stockées. Le même objet Date::Manip::Base peut être utilisé par un nombre quelconque d'objets de niveau supérieur, et tous partageront la même configuration. Si plusieurs objets Date::Manip::Date partagent le même objet Date::Manip::Base, définir une variable de configuration sur l'un d'eux affecte tous les objets Date::Manip::Date. Si vous devez travailler avec différentes configurations simultanément, il est nécessaire de travailler avec plusieurs objets Date::Manip::Base. Ceci est couvert dans le document Date::Manip::

Objects.

Une méthode alternative existe si vous utilisez l'une des interfaces fonctionnelles. Pour définir une variable en utilisant l'interface fonctionnelle, utilisez l'appel

: 
Date_Init("$var1=$val1")
;

La troisième façon de définir les variables de configuration est de les stocker dans un fichier de configuration. Le fichier de configuration est lu en passan

t les valeurs appropriées à la méthode config comme décrit ci-dessous. Un fichier de configuration est un bon moyen de changer facilement un grand nombre de p
aramètres. Ils sont également nécessaires à d'autres fins (comme les événements et les jours fériés qui sont couverts dans le document Date::Manip::Holidays).

FICHIERS DE

CONFIGURATION

L'une des variables qui peuvent être passées à la méthode config est "ConfigFile". La valeur de cette variable est le chemin vers un fichier de

configuration.

Lorsqu'un objet Date::Manip::* est configuré, un nombre quelconque de fichiers de configuration peuvent être lus (et les fichiers de configuration peuvent spécifier des fichiers supplémentaires à lire)

.

La section de départ d'un fichier de configuration contient les variables de configuration générales. Une liste de toutes les variables de configuration est donnée

ci-dessous.

Après cela, un nombre quelconque de sections spéciales peuvent être incluses dans le fichier de configuration. Les sections spéciales sont utilisées pour spécifier d'autres types d'informations, comme une liste de jours fériés ou d'événements spéciaux. Ces sections spéciales sont décrites ailleurs dans la

documentation.

La syntaxe du fichier de configuration est très simple. Chaque ligne est de la forme

:

VAL

o

u 
*SECTIO
N

Les lignes vides et les lignes commençant par une dièse (#) sont ignorées. Toute la blanc est facultatif. Les noms de variables dans la section principale et les noms de sections ne sont pas sensibles à la casse (bien que les valeurs dans la section principale soient généralement sensibles à la casse). Les chaînes dans les autres sections (à la fois les variables et les valeurs) sont sensibles à la

casse.

Voici un exemple de fichier de configuration

:

Language   = English
*Holidays
Dec 25 =  Christmas
Jan 1  =  New
Year's

Toutes les variables de configuration qui peuvent apparaître dans la partie principale d'un fichier de configuration sont décrites dans la section suivante. Les autres sections sont décrites ailleurs. Les sections *Holidays et *Events sont toutes deux décrites dans la documentation Date::Manip::

Holidays.

Un fichier de configuration d'exemple est inclus avec la distribution Date::Manip. Modifiez-le selon vos besoins et copiez-le dans un répertoire approprié, puis utilisez la variable ConfigFile pour y accéder. Par exemple, si un fichier de configuration est stocké dans /home/foo/Manip.cnf, vous pouvez le charger par

;

ou (si vous utilisez une interface fonctionnelle)

NOTE : si vous utilisez des calculs en mode business, vous devez avoir un fichier de configuration car c'est le seul endroit où vous pouvez définir les jours

fériés.

VARIABLES DE CONFIGURATION DE L'ANALYSE DES

DATES
DateForm
at
Différents pays considèrent la date 12/10 comme le 10 décembre ou le 12 octobre. Aux États-Unis, la première est la plus courante, mais ce n'est certainement pas le cas pour d'autres pays. Définir DateFormat à "US" (insensible à la casse) force le premier comportement (10 décembre). Définir DateFormat à autre chose force le second comportement (12 octobre). Le paramètre "US" est la valeur par défaut (désolé pour cela... je vis aux États-Unis)
.
YYtoYY
YY
Lors de l'analyse d'une date contenant une année à 2 chiffres, l'année doit être convertie en 4 chiffres. Cette variable de configuration détermine comment cela est fait.

Par défaut, une année à 2 chiffres est considérée comme tombant dans la période de 100 ans de CURR-89 à CURR+10. Ainsi, en l'an 2005, une année à 2 chiffres sera quelque part dans la plage de 1916 à

2015.

YYtoYYYY peut être défini sur n'importe quel entier N pour forcer une année à 2 chiffres dans la période CURR-N à CURR+(99-N). Une valeur de 0 force l'année à être l'année courante ou ultérieure. Une valeur de 99 force l'année à être l'année courante ou antérieure. Bien que le choix le plus courant des valeurs se situe entre 0 et 99, il n'y a aucune restriction sur N qui l'y oblige. Cela peut en fait être n'importe quel nombre positif ou négatif que vous souhaitez pour la forcer dans n'importe quelle période de 100 ans

désirée.

YYtoYYYY peut également être défini à "C" pour la forcer dans le siècle actuel, ou à "C##" pour la forcer dans un siècle spécifique. Ainsi, en 1998, "C" force les années à 2 chiffres à être 1900-1999. "C18" forcerait toujours une année à 2 chiffres à être dans la plage 1800-1899. Note : je suis conscient que les définitions réelles des siècles sont 1901-2000, et NON 1900-1999, donc pour les puristes, traitez cela comme la manière de fournir les deux premiers chiffres plutôt que comme la fourniture d'un

siècle.

Elle peut également être définie sous la forme "

C####" pour la forcer dans une période de 100 a
ns spécifique. C1950 fait référence à 1950-2049.

VARIABLES DE CONFIGURATION LIÉES AU FUSEAU

HORAIRE

Les variables de configuration suivantes peuvent modifier le fuseau horaire actuel. En tant que telles, elles ne sont disponibles qu'une fois que le module Date::Manip::TZ est disponible. Une façon simple de gérer cela est de ne les transmettre qu'à la méthode config d'un objet Date::Manip::TZ ou de l'un des objets de haut niveau (Date::Manip::Date, Date::Manip::Delta ou Date::Manip::Recur)

.

Beaucoup des opérations de Date::Manip reposent sur la connaissance de l'heure actuelle. Cela se compose de trois choses : connaître quelle date et quelle heure il est, connaître le fuseau horaire, et savoir s'il s'agit d'heure d'été ou non. Tout cela est nécessaire pour gérer correctement chaque date

possible.

Les informations sur l'heure d'été ne sont utilisées que pendant quelques heures chaque année lors des changements d'heure d'été (à tous les autres moments, la date, l'heure et le fuseau horaire sont des informations suffisantes), elles sont donc facultatives et par défaut à l'heure standard si elles sont

omises.

Le comportement par défaut de Date::Manip est d'utiliser la fonction système localtime pour déterminer la date, l'heure et les informations sur l'heure d'été, et d'utiliser diverses méthodes (voir "DETERMINING THE SYSTEM TIME ZONE" dans Date::Manip::TZ) pour déterminer dans quel fuseau horaire se trouve

l'ordinateur.
SetDa
te
La variable de configuration SetDate est utilisée pour définir la date, l'heure ou le fuseau horaire actuels, mais permet ensuite de les faire évoluer dans le temps en utilisant les règles de ce fuseau horaire.

Il y a plusieurs cas où cela peut être

utile.

Souvent, vous voudrez peut-être utiliser l'heure système pour obtenir la date et l'heure, mais vous voulez travailler dans un autre fuseau horaire. Pour cela, utilisez

l'appel : 
$date->config("setdate","now,
ZONE");

ou dans l'interface

fonctionnelle : 
Date_Init("setdate=now,
ZONE");

S'il est

actuellement 
Jun 6, 2009 12:00:00 dans le fuseau horaire
America/New_York

et que vous

appelez : 
$date->config("setdate","now,Europe/Rome")
;

Date::Manip traitera cet instant exact

comme 
Jun 6, 2009 12:00:00 dans le fuseau horaire
Europe/Rome

À ce moment précis, regarder l'heure système et analyser la date "now" dans Date::Manip donnera la même date et

heure.

L'heure continuera d'avancer, mais elle utilisera les règles de changement d'heure du fuseau horaire Europe/Rome. Ce que cela signifie, c'est que si un changement d'heure d'été se produit sur l'ordinateur, mais PAS dans le fuseau horaire Europe/Rome (ou inversement), la date et l'heure système ne correspondront plus aux résultats de l'analyse de la date "now" dans Date::

Manip.

En général (sauf si le programme s'exécute pendant une période prolongée de temps), la date et l'heure système CORRESPONDront à la valeur de "now", c'est donc une bonne façon de simuler le placement de l'ordinateur dans un autre fuseau

horaire.

Si la date/heure actuelle est ambiguë (c'est-à-dire qu'elle existe à la fois en heure standard et en heure d'été dans le fuseau alternatif), vous pouvez utiliser

l'appel : 
$date->config("setdate","now,DSTFLAG,
ZONE");

pour forcer à être dans l'un ou l'autre. DSTFLAG peut être "std", "dst", "stdonly" ou "dstonly". "std" et "dst" signifient que la date peut être en heure standard ou en heure d'été, mais essaiera d'abord l'heure standard (pour "dst") ou l'heure d'été d'abord (si "dst"), et n'essaiera l'autre que si la date n'est pas valide. Si "stdonly" ou "dstonly" est utilisé, la date sera forcée à être en heure standard ou en heure d'été respectivement (une erreur sera déclenchée s'il n'y a pas de date valide à cette

heure).

Si la date/heure actuelle n'existe pas dans le fuseau alternatif, une erreur se

produira.

L'autre opération courante est que vous voudrez peut-être voir les résultats tels qu'ils apparaîtraient sur un ordinateur fonctionnant dans un fuseau horaire

différent.

Cela peut être fait en utilisant

l'appel : 
$date->config("setdate","zone,ZONE");
$date->config("setdate","zone,DSTFLAG,
ZONE");

S'il est

actuellement 
Jun 6, 2009 12:00:00 dans le fuseau horaire
America/New_York

et que vous

appelez : 
$date->config("setdate","zone,America/Chicago")
;

alors analyser "now" à ce moment précis renverra "Jun 6, 2009 11:00:00". Cela équivaut à travailler dans le fuseau actuel, mais en convertissant ensuite tout vers le fuseau

alternatif.

Notez que DSTFLAG n'est utilisé que si ZONE est entré sous forme de

décalage.

Le dernier cas où la variable de configuration SetDate est utilisée est pour modifier la date et l'heure à une autre valeur (complètement indépendante de la date et de l'heure actuelles) et permettre à celle-ci d'avancer normalement à partir de ce

point. 
$date->config("setdate","DATE");
$date->config("setdate","DATE,ZONE");
$date->config("setdate","DATE,DSTFLAG,
ZONE");

définit à la fois la date/l'heure et le fuseau

horaire.

Si DATE n'est pas valide dans le fuseau horaire (soit le fuseau horaire local ou celui spécifié), une erreur se

produit.

L'appel

: 
$date->config("setdate",
"now");

réinitialise tout pour utiliser la date/l

'heure et le fuseau horaire actuels et
laisse celui-ci avancer normalement.
ForceDa
te
La variable de configuration ForceDate est similaire à la variable SetDate, sauf qu'une fois que "now" est défini, il n'est pas autorisé à changer. L'analyse de la date "now" ne changera pas, peu importe la durée d'exécution du programme (sauf si les variables SetDate ou ForceDate sont définies à une autre valeur). 
$date->config("forcedate","now,ZONE");
$date->config("forcedate","now,DSTFLAG,ZONE");
$date->config("forcedate","zone,ZONE");
$date->config("forcedate","zone,DSTFLAG,ZONE");
$date->config("forcedate","DATE");
$date->config("forcedate","DATE,ZONE");
$date->config("forcedate","DATE,DSTFLAG,ZONE");
$date->config("forcedate",
"now");

définissent tous "now" de la m

ême manière que la variable
SetDate. Les espaces ap
rès les virgules sont ignorés.

ZONE peut être n'importe quel nom de fuseau horaire, alias, abréviation ou décalage, et le meilleur fuseau horaire sera déterminé à partir de toutes les informations

fournies.

Il convient de noter que définir la variable SetDate ou ForceDate deux fois fera toujours référence à la date/heure système comme point de départ. Par exemple, si un programme s'exécute et appelle la méthode

: 
$date->config("forcedate","now")
;

à Jun 6, 2009 à 12:00, cette heure sera traitée comme "now" à partir de ce moment. Si le même appel est fait une heure plus tard, "now" sera alors Jun 6, 2009 à 13:00 à partir de ce

moment.

Puisque la date actuelle est utilisée dans les routines d'analyse de date, aucune analyse ne peut être effectuée sur la valeur DATE dans aucun des appels. À la place, DATE doit être une date dans l'un des deux formats suivants

: 
YYYY-MM-DD-H
H:MN:SS YYYY
MMDDHH:MN:SS
