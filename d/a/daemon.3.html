daemon(3) Manuel des fonctions de bibliothèque daemon(3)

NOM

daemon - s'exécuter en arrière-plan

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int daemon(int nochdir, int noclose);
Exigences des macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

daemon():

    Depuis glibc 2.21:
        _DEFAULT_SOURCE
    Dans glibc 2.19 et 2.20:
        _DEFAULT_SOURCE || (_XOPEN_SOURCE && _XOPEN_SOURCE < 500)
    Jusqu'à glibc 2.19 inclus:
        _BSD_SOURCE || (_XOPEN_SOURCE && _XOPEN_SOURCE < 500)

DESCRIPTION

La fonction daemon() est destinée aux programmes qui souhaitent se détacher du terminal de contrôle et s'exécuter en arrière-plan en tant que démons système.

Si nochdir est zéro, daemon() change le répertoire de travail courant du processus pour le répertoire racine ("/") ; sinon, le répertoire de travail courant n'est pas modifié.

Si noclose est zéro, daemon() redirige l'entrée standard, la sortie standard et l'erreur standard vers /dev/null ; sinon, aucune modification n'est apportée à ces descripteurs de fichiers.

VALEUR DE RETOUR

(Cette fonction utilise fork, et si fork(2) réussit, le parent appelle _exit(2), de sorte que les erreurs ultérieures ne soient vues que par l'enfant.) En cas de succès, daemon() retourne zéro. En cas d'erreur, daemon() retourne -1 et définit errno avec l'une des erreurs spécifiées pour fork(2) et setsid(2).

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
daemon () Sécurité des threads MT-Safe

VERSIONS

Une fonction similaire existe sur les BSD.

L'implémentation glibc peut également retourner -1 lorsque /dev/null existe mais n'est pas un périphérique caractère avec les numéros majeur et mineur attendus. Dans ce cas, errno n'a pas besoin d'être défini.

NORMES

Aucune.

HISTORIQUE

4.4BSD.

BOGUES

L'implémentation de cette fonction par la bibliothèque C GNU a été empruntée à BSD et n'utilise pas la technique du double fork (c'est-à-dire, fork(2), setsid(2), fork(2)) qui est nécessaire pour garantir que le processus démon résultant n'est pas un chef de session. Au lieu de cela, le démon résultant est un chef de session. Sur les systèmes qui suivent la sémantique System V (par exemple, Linux), cela signifie que si le démon ouvre un terminal qui n'est pas déjà un terminal de contrôle pour une autre session, alors ce terminal deviendra involontairement le terminal de contrôle du démon.

VOIR AUSSI

fork(2), setsid(2), daemon(7), logrotate(8)
