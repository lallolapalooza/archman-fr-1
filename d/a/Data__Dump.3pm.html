DESCRIPTIO

N

Ce module fournit quelques fonctions qui parcourent leur liste d'arguments et retournent une chaîne contenant du code Perl qui, lorsqu'il est "évalué", produit une copie profonde des arguments

originaux.

La caractéristique principale du module est qu'il s'efforce de produire une sortie facile à lire. Exemple

: 
@a = (1, [2, 3], {4 => 5});
dump(@a)
;

Produit

: 
"(1, [2, 3], { 4 => 5 })
"

Si vous dumppez un petit peu de données, elles sont sorties sur une seule ligne. Si vous dumppez des données plus complexes ou s'il y en a beaucoup, des sauts de ligne sont automatiquement ajoutés pour les garder faciles à

lire.

Les fonctions suivantes sont fournies (seules les fonctions dd* sont exportées par défaut)

:
dump( ...
)
pp( ...
)
Retourne une chaîne contenant une expression Perl. Si vous passez cette chaîne à la fonction intégrée eval() de Perl, elle devrait retourner une copie des arguments que vous avez passés à dump().

Si vous appelez la fonction avec plusieurs arguments, alors la sortie sera enveloppée entre parenthèses "( ..., ... )". Si vous appelez la fonction avec un seul argument, la sortie n'aura pas d'enveloppement. Si vous appelez la fonction avec un seul argument scalaire (non-référence), elle retournera simplement le scalaire entre guillemets si nécessaire, mais ne le cassera jamais en plusieurs lignes. Si vous passez plusieurs arguments ou des références à des tableaux de hachages, la valeur retournée peut contenir des sauts de ligne pour la formater afin de la rendre plus facile à lire. La chaîne retournée ne sera jamais terminée par "\n", même si elle contient plusieurs lignes. Cela permet à un code comme celui-ci de placer le point-virgule à l'endroit

attendu : 
print '$obj = ', dump($obj), ";
\n";

Si dump() est appelé dans un contexte void, alors le dump est imprimé sur STDERR puis terminé par "\n". Vous pourriez trouver cela utile pour des impressions de débogage rapides, mais les fonctions dd*() pourraient être de meilleures alternatives pour

cela.

Il n'y a pas de différence entre dump() et pp(), sauf que dump() partage son nom avec une fonction intégrée de perl pas très utile. À cause de cela, certains pourraient vouloir éviter d'utiliser

ce
nom.
quote( $string
)
Retourne une version entre guillemets de la chaîne fournie.

Elle diffère de dump($string) en ce qu'elle mettra entre guillemets même les nombres et n'essaiera pas de trouver des expressions astucieuses qu

i pourraient raccourcir la sortie. Si un argument non-scalaire e
st fourni, il est simplement converti en chaîne au lieu d'être traversé.

)
ddx( ...
)
Ces fonctions appelleront dump() sur leurs arguments et imprimeront le résultat sur STDOUT (en fait, c'est le descripteur de sortie actuellement sélectionné, mais STDOUT est la valeur par défaut pour cela).

La différence entre elles est seulement que ddx() préfixera les lignes qu'il imprime avec "# " et marquera la première ligne avec le fichier et le numéro de l

igne où il a été appelé. Cela est destiné à être utile p
our les impressions de débogage de l'état au sein des programmes.

N

Il y a quelques variables globales qui peuvent être définies pour modifier la sortie générée par les fonctions de dump. Il est judicieux de localiser la définition de

celles-ci.

INDENT
Elle contient la chaîne utilisée pour indenter les structures de données multilignes. Sa valeur par défaut est " " (deux espaces). Définissez-la à "" pour supprimer l'indentation. La définir à "| " donne de beaux visuels même si la sortie du dump n'est alors plus du Perl
valide.
$Data::Dump::

Quelle doit être la longueur d'une chaîne binaire avant que nous essayions d'utiliser l'encodage base64 pour la sortie du dump. La valeur par défaut est 50. Définissez-la à 0 pour désactiver les dumps
base64.
$Data::Dump::
LINEWIDTH
Cela contrôle la largeur à laquel
le la chaîne doit être avant que
nous ajoutions un saut de ligne. L
a valeur par défaut est 60.

LIMITATION

S

Les références de code seront dumpées sous la forme "sub { ... }". Ainsi, les "évaluer" ne reproduira pas la routine originale. L'opérateur "..." utilisé nécessitera aussi perl-5.12 ou plus pour être

évalué.

Si vous oubliez d'importer explicitement la fonction "dump", votre code produira un core dump. C'est parce que vous venez d'appeler par accident la fonction intégrée "dump", qui dépose intentionnellement un core. À cause de cela, vous pouvez aussi importer la même fonction sous le nom "pp", mnémonique pour "prett

y-print" (impre
ssion formatée).

HISTORIQU

E

Le module "Data::Dump" est né de la frustration face au "Data::Dumper" de Sarathy, excellent dans la plupart des cas. Des idées de base et du code sont partagés avec le module de

Sarathy.

Le module "Data::Dump" fournit une interface beaucoup plus simple que "Data::Dumper". Aucune interface OO n'est disponible et il y a moins d'options de configuration dont se soucier. L'autre avantage est que le dump produit n'essaie pas de définir de variables. Il retourne seulement ce qui est nécessaire pour produire une copie des arguments. Cela signifie que dump("foo") retourne simplement '"foo"', et dump(1..3) retourne simplement '(1, 2,

3)'.
