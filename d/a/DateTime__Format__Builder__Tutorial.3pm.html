CRÉER UNE CLASSE

Comme la plupart des personnes qui écrivent des modules le savent, vous commencez un paquet par une déclaration de paquet et une indication de la version du module :

package DateTime::Format::ICal; our $VERSION = '0.04';

Ensuite, vous appelez Builder avec quelques options. Il n'y en a que quelques-unes (détaillées plus tard). Pour l'instant, nous ne sommes intéressés que par parsers.

use DateTime::Format::Builder ( parsers => {...} );

L'option parsers prend une référence à un hash de noms de méthodes et de spécifications :

parsers => {
        parse_datetime => ... ,
        parse_datetime_with_timezone => ... ,
        ...
    }

Builder créera des méthodes dans votre classe, chaque méthode étant un analyseur qui suit les spécifications données. Il est fortement recommandé qu'une méthode soit appelée parse_datetime, qu'il s'agisse d'une méthode créée par Builder ou de l'une des vôtres.

En plus de créer toutes les méthodes d'analyse, il crée également une méthode "new" qui peut instancier (ou cloner) des objets de cette classe. Ce comportement peut être modifié avec l'option constructor , mais nous n'avons pas encore besoin de le savoir.

Chaque valeur correspondant à un nom de méthode dans la liste parsers est soit une spécification unique, soit une liste de spécifications. Nous commencerons par le cas simple.

parse_briefdate => { params => [qw( year month day )], regex => qr/^(\d\d\d\d)(\d\d)(\d\d)$/, },

Cela créera une méthode nommée parse_briefdate qui prendra des chaînes de la forme 20040716 et renverra des objets DateTime représentant cette date. Un utilisateur de la classe pourrait écrire :

use DateTime::Format::ICal;
my $date = '19790716';
my $dt   = DateTime::Format::ICal->parse_briefdate($date);
print "My birth month is ", $dt->month_name, "\n";

Le "regex" est appliqué à la chaîne d'entrée, et s'il correspond, alors $1, $2, ... sont mappés aux params donnés et transmis à "DateTime->new". Essentiellement :

my $rv = DateTime->new( year => $1, month => $2, day => $3 );

Il y a des choses plus compliquées que l'on peut faire au sein d'une seule spécification, mais nous les couvrirons plus tard.

Souvent, vous voudrez qu'une méthode puisse prendre une chaîne et la tester contre plusieurs spécifications d'analyse. Ce serait très irritant si l'utilisateur devait déterminer dans quel format la chaîne datetime se trouve et ensuite quelle méthode est la plus appropriée.

Ainsi, Builder vous permet de spécifier plusieurs spécifications :

parse_datetime => [
    {
        params => [qw( year month day hour minute second )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)(\d\d)$/,
    },
    {
        params => [qw( year month day hour minute )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)$/,
    },
    {
        params => [qw( year month day hour )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)$/,
    },
    {
        params => [qw( year month day )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)$/,
    },
],

C'est un arrayref de spécifications. Un analyseur sera créé qui essaiera chacune de ces spécifications séquentiellement, dans l'ordre que vous avez spécifié.

Il y a cependant un défaut dans cela. Dans cet exemple, nous construisons un analyseur pour les datetimes ICal. On peut placer un identifiant de fuseau horaire au début d'un datetime ICal. Vous pourriez extraire un tel identifiant avec le code suivant :

if ( $date =~ s/^TZID=([^:]+):// ) {
    $time_zone = $1;
}
# Z at end means UTC
elsif ( $date =~ s/Z$// ) {
    $time_zone = 'UTC';
}
else {
    $time_zone = 'floating';
}

$date se retrouverait sans l'identifiant, et $time_zone contiendrait quelque chose d'adapté à donner à la méthode set_time_zone de DateTime, ou à l'argument time_zone .

Mais comment intégrer ce morceau de code dans votre analyseur ? Vous pourriez être tenté d'appeler l'analyseur autrement et de construire un petit wrapper. Il n'y a pas besoin cependant car une option est fournie pour le prétraitement des dates :

parse_datetime => [
    [ preprocess => \&_parse_tz ],    # Only changed line!
    {
        params => [qw( year month day hour minute second )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)(\d\d)$/,
    },
    {
        params => [qw( year month day hour minute )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)$/,
    },
    {
        params => [qw( year month day hour )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)$/,
    },
    {
        params => [qw( year month day )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)$/,
    },
],

Cela nécessitera que _parse_tz soit écrit, et cette routine ressemble à ceci :

sub _parse_tz {
    my %args = @_;
    my ( $date, $p ) = @args{qw( input parsed )};
    if ( $date =~ s/^TZID=([^:]+):// ) {
        $p->{time_zone} = $1;
    }
    # Z at end means UTC
    elsif ( $date =~ s/Z$// ) {
        $p->{time_zone} = 'UTC';
    }
    else {
        $p->{time_zone} = 'floating';
    }
    return $date;
}

En entrée, on lui donne un hash contenant deux éléments : la date d'entrée et un hashref qui sera utilisé dans l'analyse. La valeur de retour de la routine est ce contre quoi les spécifications d'analyse seront exécutées, et tout ce qui est dans le hash parsed ($p dans l'exemple) sera mis dans l'appel à "DateTime->new(...)".

Ainsi, nous avons maintenant un analyseur ICal qui fonctionne joyeusement. Il analyse les formats divers et peut aussi gérer les fuseaux horaires. Y a-t-il autre chose qu'il doit faire ? Non. Mais nous pouvons le faire fonctionner plus efficacement.

Actuellement, les spécifications sont testées séquentiellement. Cependant, chacune s'applique à des chaînes de longueurs particulières. Ainsi, nous pourrions être efficaces et faire en sorte que l'analyseur ne teste les chaînes données que contre un analyseur qui gère cette longueur de chaîne. Encore une fois, Builder le rend facile :

parse_datetime => [
    [ preprocess => \&_parse_tz ],
    {
        length => 15,    # We handle strings of exactly 15 chars
        params => [qw( year month day hour minute second )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)(\d\d)$/,
    },
    {
        length => 13,                                # exactly 13 chars...
        params => [qw( year month day hour minute )],
        regex => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)$/,
    },
    {
        length => 11,                                    # 11..
        params => [qw( year month day hour )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)$/,
    },
    {
        length => 8,                                     # yes.
        params => [qw( year month day )],
        regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)$/,
    },
],

Maintenant, l'analyseur créé créera un analyseur qui n'exécute les spécifications que contre les chaînes appropriées.

Ainsi, notre code complet ressemble à :

package DateTime::Format::ICal;
use strict;
our $VERSION = '0.04';
use DateTime::Format::Builder (
    parsers => {
        parse_datetime => [
            [ preprocess => \&_parse_tz ],
            {
                length => 15,
                params => [qw( year month day hour minute second )],
                regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)(\d\d)$/,
            },
            {
                length => 13,
                params => [qw( year month day hour minute )],
                regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)(\d\d)$/,
            },
            {
                length => 11,
                params => [qw( year month day hour )],
                regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)T(\d\d)$/,
            },
            {
                length => 8,
                params => [qw( year month day )],
                regex  => qr/^(\d\d\d\d)(\d\d)(\d\d)$/,
            },
        ],
    },
);
sub _parse_tz {
    my %args = @_;
    my ( $date, $p ) = @args{qw( input parsed )};
    if ( $date =~ s/^TZID=([^:]+):// ) {
        $p->{time_zone} = $1;
    }
    # Z at end means UTC
    elsif ( $date =~ s/Z$// ) {
        $p->{time_zone} = 'UTC';
    }
    else {
        $p->{time_zone} = 'floating';
    }
    return $date;
}
1;

Et c'est un analyseur ICal. Le module DateTime::Format::ICal réel inclut aussi des méthodes de formatage et l'analyse des durées, mais Builder ne les prend pas encore en charge. Un remplacement direct (au moment de l'écriture du remplacement) peut être trouvé dans le répertoire examples de la distribution Builder, avec des variantes similaires deautres modules courants.
