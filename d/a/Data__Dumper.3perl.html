DESCRIPTIO

N

Étant donné une liste de scalaires ou de variables de référence, écrit leur contenu en syntaxe perl. Les références peuvent également être des objets. Le contenu de chaque variable est produit dans une seule instruction Perl. Gère correctement les structures auto-référentielles

.

La valeur de retour peut être "eval"uée pour obtenir une copie identique de la structure de référence originale. (Veuillez considérer les implications de sécurité de l'"eval" de code provenant de sources non fiables !

)

Toute référence identique à l'une de celles fournies sera nommée $VARn (où n est un suffixe numérique), et les autres références en double vers des sous-structures dans $VARn seront étiquetées de manière appropriée à l'aide de la notation flèche. Vous pouvez spécifier des noms pour les valeurs individuelles à sérialiser si vous utilisez la méthode Dump(), ou vous pouvez changer le préfixe $VAR par défaut pour autre chose. Voir $Data::Dumper::Varname et $Data::Dumper::Terse dans "Variables de configuration ou méthodes"

ci-dessous.

La sortie par défaut des structures auto-référentielles peut être "eval"uée, mais les références imbriquées vers $VARn seront indéfinies, car une structure récursive ne peut pas être construite avec une seule instruction Perl. Vous devriez définir le drapeau "Purity" à 1 pour obtenir des instructions supplémentaires qui rempliront correctement ces références. De plus, si "eval"uée lorsque les restrictions strictes sont en vigueur, vous devez vous assurer que toutes les variables auxquelles elle accède sont préalablement

déclarées.

Dans la forme d'utilisation étendue, les références à sérialiser peuvent recevoir des noms spécifiés par l'utilisateur. Si un nom commence par un "*", la sortie décrira le type dé-référencé de la référence fournie pour les hachages, les tableaux et les références de code. La sortie des noms sera évitée autant que possible si le drapeau "Terse" est

défini.

Dans de nombreux cas, les méthodes utilisées pour définir l'état interne de l'objet renvoient l'objet lui-même, de sorte que les appels de méthodes peuvent être facilement

chaînés.

Plusieurs styles de sortie sont possibles, tous contrôlés en définissant le drapeau "Indent". Voir "Variables de configuration ou méthodes" ci-dessous pour plus de

détails.

Variables de configuration ou

méthodes

Plusieurs variables de configuration peuvent être utilisées pour contrôler le type de sortie généré lors de l'utilisation de l'interface procédurale. Ces variables sont généralement "local"isées dans un bloc afin que d'autres parties du code ne soient pas affectées par le

changement.

Ces variables déterminent l'état par défaut de l'objet créé en appelant la méthode "new", mais ne peuvent pas être utilisées pour modifier l'état de l'objet par la suite. Les noms de méthodes équivalents doivent être utilisés à la place pour interroger ou définir l'état interne de

l'objet.

Les formes de méthode renvoient l'objet lui-même lorsqu'elles sont appelées avec des arguments, afin qu'elles puissent être facilement

chaînées.
  • $Data::Dumper::Indent ou $OBJ->Indent([NOUVELLEVALEUR])

    Contrôle le style d'indentation. Il peut être défini à 0, 1, 2 ou 3. Le style 0 produit une sortie sans aucun saut de ligne, indentation ou espace entre les éléments de la liste. C'est le format le plus compact possible qui peut encore être considéré comme du perl valide. Le style 1 produit une forme lisible avec des sauts de ligne mais sans indentation sophistiquée (chaque niveau dans la structure est simplement indenté d'une quantité fixe d'espaces). Le style 2 (par défaut) produit une forme très lisible qui aligne les clés de hachage. Le style 3 est semblable au style 2, mais annote également les élémentsnts de tableaux avec leur index (mais le commentaire es

    t sur sa propre ligne, la sortie d'un tableau consomme donc deux
    • fois plus de lignes). Le style 2 est celui par défaut.
  • $Data::Dumper::Trailingcomma ou $OBJ->Trailingcomma([NEWVAL])

    Contrôle si une virgule est ajoutée après le dernier élément d'un tableau ou d'un hachage. Même si ce

    tte option est vraie, aucune virgule n'est ajoutée entre le dernier élément d'un tableau ou d'un hac
    • hage et un crochet fermant lorsqu'ils apparaissent sur la même ligne. La valeur par défaut est false.
  • $Data::Dumper::Purity ou $OBJ->Purity([NEWVAL])

    Contrôle le degré auquel la sortie peut être "eval"ué pour recréer les structures de référence fournies. Si vous le définissez à 1, des instructions perl supplémentaires seront générées pour recréer correctement les références imbriquées. La valeur par défaut

    • est 0.
  • $Data::Dumper::Pad ou $OBJ->Pad([NEWVAL])

    Spécifie la chaîne qui sera préf

    • sortie. Chaîne vide par défaut.
  • $Data::Dumper::Varname ou $OBJ->Varname([NEWVAL])

    Contient le préfixe à utiliser pour étiqu

    • sortie. La valeur par défaut est "VAR".
  • $Data::Dumper::Useqq ou $OBJ->Useqq([NEWVAL])

    Lorsqu'il est défini, active l'utilisation des guillemets doubles pour représenter les valeurs de chaînes. Les espaces blancs autres que l'espace seront représentés par "[\n\t\r]", les caractères "unsafe" seront échappés par une barre oblique inverse, et les caractères n

    on imprimables seront sortis sous forme d'entie
    • rs octaux entre guillemets. La valeur par défaut est 0.
  • $Data::Dumper::Terse ou $OBJ->Terse([NEWVAL])

    Lorsqu'il est défini, Data::Dumper émettra des valeurs simples, non auto-référentielles en tant qu'atomes/termes plutôt qu'en tant qu'instructions. Cela signifie que les $VARnoms seront évités si possible, mais sachez que ce type de sortie ne pourra pas toujours être analysé par "eva

    l
    • ".
  • $Data::Dumper::Freezer ou $OBJ->Freezer([NEWVAL])

    Peut être défini sur un nom de méthode, ou sur une chaîne vide pour désactiver la fonctionnalité. Data::Dumper invoquera cette méthode via l'objet avant d'essayer de le convertir en chaîne. Cette méthode peut modifier le contenu de l'objet (si, par exemple, il contient des données allouées depuis C), et même le rebénir dans un autre paquet. Le client est responsable de s'assurer que la méthode spécifiée peut être appelée via l'objet, et que l' objet ne contient que des types de données perl après l'appel de la méthode. Par défaut, c'est une chaîne

    vide.

    Si un objet ne prend pas en charge la méthode spécifiée (déterminé en utilisant UNIVERSAL::can()) alors l'appel sera ignoré. Si la

    méthode meurt, un
    • avertissement sera généré.
  • $Data::Dumper::Toaster ou $OBJ->Toaster([NEWVAL])

    Peut être défini sur un nom de méthode, ou sur une chaîne vide pour désactiver la fonctionnalité. Data::Dumper émettra un appel de méthode pour tout objet qui doit être déversé en utilisant la syntaxe "bless(DATA, CLASS)->METHOD()". Notez que cela signifie que la méthode spécifiée devra effectuer toutes les modifications requises sur l'objet (comme créer un nouvel état à l'intérieur, et/ou le rebé

    nir dans un autre paquet) puis le renvoyer. Le client est responsable de s'assurer que la métho
    • de peut être appelée via l'objet, et qu'elle renvoie un objet valide. Par défaut, c'est une chaîne vide.

Cela est destiné à servir de mesure de sécurité pour empêcher perl de manquer d'espace de pile lors du déversement d'une structure excessivement profonde.   • $Data::Dumper::Useperl ou $OBJ->Useperl([NEWVAL])

    Peut être défini sur une valeur booléenne qui contrôle si l'implémentation pure Perl de "Data::Dumper" est utilisée. Le module "Data::Dumper" est une implémentation double, avec presque toute la fonctionnalité écrite à la fois en Perl pur et aussi en XS ('C'). Comme la version XS est beaucoup plus rapide, elle sera toujours utilis

  • $Data::Dumper::Sortkeys ou $OBJ->Sortkeys([NEWVAL])

    Peut être défini sur une valeur booléenne pour contrôler si les clés de hachage sont déversées dans un ordre trié. Une valeur vraie fera en sorte que les clés de tous les hachages soient déversées dans l'ordre de tri par défaut de Perl. Peut aussi être défini sur une référence de sous-programme qui sera appelée pour chaque hachage déversé. Dans ce cas "Data::Dumper" appellera le sous-programme une fois pour chaque hachage, en lui passant la référence du hachage. Le but du sous-programme est de renvoyer une référence vers un tableau des clés qui seront déversées, dans l'ordre où elles doivent l'être. En utilisant cette fonctionnalité, vo

  • $Data::Dumper::Deparse ou $OBJ->Deparse([NEWVAL])

    Peut être défini sur une valeur booléenne pour contrôler si les références de code sont converties en code source perl. Si défini à une valeur vraie, "B::Deparse" sera utilisé pour obtenir le source de la référence de code. Dans les versions plus anciennes, l'utilisation de cette option imposait une pénalité de performance importante lors du déversement de parties d'une structure de données autres que les références de code, mais ce n'est plus le

    • e".

sub my_filter {
    my ($hash) = @_;
    # renvoyer une référence de tableau contenant les clés du hash à imprimer
    # dans l'ordre dans lequel vous voulez qu'elles soient imprimées
    return [
      # Trier les clés de %$foo par ordre numérique décroissant
        $hash eq $foo ? (sort {$b <=> $a} keys %$hash) :
      # N'imprimer que les clés impaires de %$bar
        $hash eq $bar ? (grep {$_ % 2} keys %$hash) :
      # Trier les clés dans l'ordre par défaut pour tous les autres hashes
        (sort keys %$hash)
    ];
}

BUG

S

En raison des limitations de la sémantique d'appel de sous-programmes de Perl, vous ne pouvez pas passer un tableau ou un hash. Préfixez-le avec un "\" pour passer sa référence à la place. Cela sera corrigé avec le temps, maintenant que Perl possède des prototypes de sous-programmes. Pour l'instant, vous devez utiliser la forme d'utilisation étendue, et préfixer le nom avec un "*" pour l'afficher en tant que hash ou

tableau.

"Data::Dumper" triche avec les références CODE. Si une référence de code est rencontrée dans la structure en cours de traitement (et si vous n'avez pas défini l'indicateur "Deparse"), un sous-programme anonyme contenant la chaîne '"DUMMY"' sera inséré à sa place, et un avertissement sera affiché si "Purity" est défini. Vous pouvez "eval" le résultat, mais gardez à l'esprit que le sous-programme anonyme qui est créé n'est qu'un espace réservé. Même l'utilisation de l'indicateur "Deparse" produira dans certains cas des résultats qui se comportent différemment après avoir été passés à "eval"; voir la documentation de B::

Deparse.

Les objets SCALAR ont la solution de contournement "bless" la plus

étrange.

NOT

Différentes exécutions de Perl auront un ordre différent des clés de hash. Ce changement a été effectué pour une plus grande sécurité, voir « Algorithmic Complexity Attacks » dans perlsec. Cela signifie que différentes exécutions de Perl auront des sorties Data::Dumper différentes si les données contiennent des hashes. Si vous avez besoin d'avoir des sorties Data::Dumper identiques de différentes exécutions de Perl, utilisez la variable d'environnement PERL_HASH_SEED, voir « PERL_HASH_SEED » dans perlrun. Son utilisation restaure l'ancien ordre (spécifique à la plateforme) : une solution encore plus élégante pourrait être d'utiliser le filtre "Sortkeys"
