@CONFIGFILE@(5) Manuel des formats de fichiers @CONFIGFILE@(5)

NOM

@CONFIGFILE@ - Fichier de configuration pour @PROGRAM_NAME@

DESCRIPTION

Il existe un fichier de configuration global @SYS_CONF_DIR@/@CONFIGFILE@ et des fichiers de configuration utilisateur ~/.@PACKAGE@/@CONFIGFILE@. Lorsque @PROGRAM_NAME@ est invoqué par root, seul le fichier de configuration global est lu. Lorsqu'il est invoqué par un utilisateur ordinaire, le fichier de configuration utilisateur est lu en plus. Les paramètres du fichier de configuration utilisateur ont priorité sur la configuration globale.

Le fichier de configuration se compose de lignes contenant chacune une paire mot-clé valeur. Le mot-clé et la valeur sont séparés par des espaces et/ou des tabulations.

Le fichier peut contenir des sections qui s'appliquent à un seul point de montage. Une telle section commence par une ligne contenant le chemin complet du point de montage entre crochets. La section se termine au début de la section suivante ou à la fin du fichier. Les options qui doivent s'appliquer à tous les systèmes de fichiers montés doivent précéder les sections. Les options données dans une section spécifique au montage auront la priorité.

EXEMPLE

proxy foo.bar:8080
use_locks 0
[/media/dav]
use_locks 1
[/home/otto/mywebspace]
gui_optimize 1

Tous les systèmes de fichiers @PACKAGE@ montés utiliseront le proxy foo.bar. Tous les systèmes de fichiers @PACKAGE@, sauf /media/dav, désactiveront l'utilisation des verrous. /home/otto/mywebspace utilisera l'option gui_optimize.

RÈGLES SYNTAXIQUES GÉNÉRALES

Les lignes ne contenant que des espaces et des tabulations (lignes vides) sont ignorées.

# indique un commentaire. Le reste de la ligne est ignoré.

\ est le caractère d'échappement.

"" est utilisé pour les guillemets.

Si une valeur contient l'un des caractères spéciaux espace, tabulation, #, \, ou ", ce caractère doit être échappé par un \ précédent. Utilisez ’\ ’ au lieu de ’ ’, ’\#’ au lieu de ’#’, ’\\’ au lieu de ’\’ et ’\"’ au lieu de ’"’.

Les valeurs contenant des espaces, des tabulations ou # peuvent être entourées de guillemets doubles. Mais " et ’ doivent être échappés même à l'intérieur de guillemets doubles. Si la ligne de départ d'une section est entourée de guillemets doubles, les crochets doivent être à l'intérieur des guillemets (comme "[/home/otto/avec espace]").

Les valeurs d'options booléennes (oui/non) doivent être données comme une valeur numérique. 0 pour non, 1 pour oui.

OPTIONS DE CONFIGURATION DISPONIBLES

Options Générales

dav_user
Lorsqu'il est invoqué par root, le démon @PROGRAM_NAME@ s'exécutera en tant que cet utilisateur. La valeur doit être donnée sous forme de nom, pas d'ID numérique.
Par défaut : @USER@
Autorisé uniquement dans le fichier de configuration global.
dav_group
Le groupe du démon @PROGRAM_NAME@ en cours d'exécution. Les utilisateurs ordinaires doivent être membres de ce groupe pour pouvoir monter un système de fichiers @PACKAGE@. La valeur doit être donnée sous forme de nom, pas d'ID numérique.
Par défaut : @GROUP@
Autorisé uniquement dans le fichier de configuration global.
buf_size
Taille en KiOctets du tampon utilisé pour communiquer avec le système de fichiers du noyau. Utile uniquement avec fuse, où les opérations de lecture et d'écriture peuvent bénéficier d'un tampon plus grand.
Par défaut : 16

Options liées à WebDAV

use_proxy
Indique s'il faut utiliser un proxy pour se connecter au serveur WebDAV. 0 = non, 1 = oui. Si aucun proxy n'est défini dans le fichier de configuration ou les variables d'environnement https_proxy, http_proxy et all_proxy, cette option n'a aucun effet.
Par défaut : 1
Autorisé uniquement dans le fichier de configuration global.
proxy
Nom du proxy. Le nom doit être le nom de domaine pleinement qualifié (pas de schéma). Si le port du proxy diffère du port par défaut 8080, il doit être ajouté, séparé par un deux-points. Exemples : foo.bar:1704 ou foo.bar
Autorisé uniquement dans le fichier de configuration global.
trust_ca_cert
Nom d'un fichier certificat au format PEM. Le nom du fichier peut être donné en chemin absolu ou simplement en nom de fichier. Dans ce dernier cas, les répertoires ~/.@PACKAGE@/@CERTS_DIR@ et @SYS_CONF_DIR@/@CERTS_DIR@ seront recherchés.
Cette option est utile lorsque le certificat présenté par le serveur ne peut pas être vérifié à l'aide de la base de données système des autorités de certification (CA) de confiance. Le fichier certificat doit contenir le certificat auto-signé de la CA de plus haut niveau dans la chaîne de confiance. Il peut s'agir d'un certificat serveur auto-signé (mais voir aussi trust_server_cert). Avec cette option, la base de données CA du système est ignorée.
Note : Même si le certificat du serveur est digne de confiance, cela ne signifie pas qu'il est accepté. De plus, la date du certificat doit être valide et soit le CommonName, soit le SubjectAltName doit correspondre au nom d'hôte du serveur.
servercert
Identique à trust_ca_cert mais mal nommé.
Obsolète
trust_server_cert
Nom d'un fichier certificat au format PEM. Le nom du fichier peut être donné en chemin absolu ou simplement en nom de fichier. Dans ce dernier cas, les répertoires ~/.@PACKAGE@/@CERTS_DIR@ et @SYS_CONF_DIR@/@CERTS_DIR@ seront recherchés.
Utile lorsque le certificat du serveur ne peut pas être vérifié ou est même invalide, mais que vous savez que vous pouvez faire confiance à ce certificat. Lorsque le serveur présente un certificat qui est exactement identique à celui-ci et que le serveur est capable de s'authentifier auprès de la clé publique contenue dans ce certificat, la connexion sera établie.
C'est l'option préférée pour les certificats serveur auto-signés.
Aucun autre moyen de vérifier le certificat ne sera tenté et la validité du certificat ne sera pas vérifiée.
clientcert
Nom d'un certificat au format PKCS#12 qui sera utilisé pour s'authentifier auprès du serveur. Le nom du fichier peut être donné en chemin absolu ou simplement en nom de fichier. Dans ce dernier cas, les répertoires ~/.@PACKAGE@/@CERTS_DIR@/@CLICERTS_DIR@ et @SYS_CONF_DIR@/@CERTS_DIR@/@CLICERTS_DIR@ seront recherchés.
Attention : Si le certificat client est émis par une CA intermédiaire et non par une CA de premier niveau, la spécification TLS exige que le client envoie la chaîne complète des certificats (sans le certificat CA de premier niveau). davfs2 n'envoie que le certificat client. Pour contourner ce bug, le serveur doit stocker et faire confiance à la chaîne complète des certificats CA jusqu'à la CA qui a émis le certificat client.
secrets
Nom d'un fichier contenant les informations d'identification pour les serveurs et le proxy, et les mots de passe pour déchiffrer le certificat client. Le nom doit être un chemin absolu. Le fichier doit être lisible et inscriptible uniquement par le propriétaire (mode 600).
Par défaut : ~/.@PACKAGE@/@SECRETSFILE@
Autorisé uniquement dans le fichier de configuration utilisateur. Le fichier de secrets global est toujours @SYS_CONF_DIR@/@SECRETSFILE@.
ask_auth
Demander interactivement à l'utilisateur ses identifiants et mots de passe s'ils ne sont pas trouvés dans le fichier secrets. Demander à l'utilisateur si un servercert ne peut pas être vérifié. 0 = non, 1 = oui.
Par défaut : 1
use_locks
Indique s'il faut verrouiller les fichiers sur le se
rver lorsqu'ils sont ouverts en écriture. 0 = non, 1 = oui.
Par défaut : 1
lock_owner
lock_owner
Une chaîne de caractères envoyée au serveur pour identifier le propriétaire d'un verrou. Si une ressource WebDAV est utilisée simultanément par différents clients utilisant les mêmes informations d'identification, des valeurs différentes pour lock_owner devraient être choisies.
Par défaut : le nom d'utilisateur des informations d'identification
lock_timeout
Pendant combien de secondes les verrous doivent être valides, avant que le serveur ne les supprime. Le serveur peut ignorer cela et définir sa propre valeur de délai d'attente.
Par défaut : 1800
lock_refresh
Ce nombre de secondes avant l'expiration du verrou, @PROGRAM_NAME@ essaiera de renouveler le verrou. La valeur doit être substantiellement supérieure à delay_upload.
Par défaut : 60
use_expect100
Pour éviter de télécharger de gros fichiers qui seront refusés par le serveur, @PROGRAM_NAME@ utilise l'en-tête expect: 100-continue pour obtenir l'accord du serveur avant le téléchargement. Tous les serveurs ne comprennent pas cela. 0 = non, 1 = oui.
Par défaut : 0
if_match_bug
Certains serveurs ne gèrent pas correctement les en-têtes If-Match et If-None-Match. Cette option indique à @PROGRAM_NAME@ d'utiliser HEAD au lieu de ces en-têtes. 0 = non, 1 = oui.
Par défaut : 0
drop_weak_etags
Les serveurs populaires envoient un etag faible lorsqu'ils ne sont pas en mesure d'en calculer un fort. Cet etag faible ne sera jamais valide, mais après une seconde il est silencieusement transformé en un etag fort et valide. Avec ce drapeau défini à 1, @PROGRAM_NAME@ n'utilisera jamais ces etags faibles. Si le drapeau est à 0, l'indicateur de faiblesse sera supprimé et l'etag est supposé être fort. Il y a un certain danger de Problème de Mise à Jour Perdue avec cela. Mais il est minimisé lors de l'utilisation de verrous.
Vous devriez activer cette option lorsque vous ne pouvez pas utiliser de verrous et qu'il y a un risque d'accès concurrentiel à la même ressource. Dans ce cas, l'etag n'est pas utilisé du tout et la ressource ne peut pas être mise en cache.
0 = non, 1 = oui.
Par défaut : 0
n_cookies
Certains serveurs ne fonctionneront que lorsqu'ils seront autorisés à définir un cookie et que ce cookie sera retourné dans les requêtes ultérieures. Cette option définit le nombre de cookies que vous êtes prêt à accepter et à inclure dans les requêtes ultérieures. davfs2 ne se souciera que du nom et de la valeur du cookie et ignorera tous les attributs possibles.
Par défaut : 0
precheck
Si l'option if_match_bug est définie : utiliser des requêtes HEAD pour vérifier l'existence ou la modification d'un fichier afin d'éviter d'écraser involontairement ce que quelqu'un d'autre a modifié. N'a aucun effet si l'option if_match_bug est à 0. Vous ne devriez la définir à 0 que s'il n'y a pas d'accès concurrentiel au serveur. 0 = non, 1 = oui.
Par défaut : 1
ignore_dav_header
Certains serveurs envoient des informations incorrectes sur leurs capacités dans l'en-tête DAV. Dans ce cas, l'en-tête doit être ignoré.
Par défaut : 0
use_compression
Utiliser la compression gzip pour télécharger des fichiers, si supporté par le serveur. Les téléchargements resteront non compressés.
Par défaut : 0
min_propset
Il est rapporté que certains serveurs ralentissent considérablement lorsque les propriétés Etag et Last-Modified sont demandées. Cette option réduira l'ensemble des propriétés WebDAV demandées au serveur à l'ensemble minimal. Ne l'utilisez pas si votre système de fichiers est utilisé pour la lecture et l'écriture. Sans Etag ou Last-Modified, davfs2 ne sera pas en mesure de vérifier les modifications sur le serveur, ce qui peut entraîner des téléchargements inutiles et des mises à jour perdues. Cette option désactivera également efficacement la mise en cache des fichiers, car les fichiers dans le cache ne pourront pas être réutilisés.
Par défaut : 0
follow_redirect
Si le serveur redirige une requête GET vers une ressource différente (peut-être sur un serveur différent), suivez cette redirection.
Actuellement, il y a quelques restrictions : toutes les redirections sont traitées comme des redirections temporaires ; si le nouveau serveur nécessite une authentification, les mêmes informations d'identification sont utilisées que pour le serveur d'origine ; si la connexion est via TLS, le certificat du serveur sera vérifié par rapport aux CA de confiance connus du système ; les certificats serveur configurés par l'utilisateur et les certificats client ne sont pas utilisés pour le nouveau serveur.
Par défaut : 0
sharepoint_href_bug
SharePoint n'encode pas correctement les caractères UTF8 dans l'élément href. Pour cette raison, certains fichiers sont invisibles car l'élément href enfreint les règles. Neon 0.31 et versions ultérieures ont une solution de contournement pour ce bug de SharePoint. Cette option activera cette solution de contournement.
Par défaut : 0
server_charset
Lors de l'extraction des noms de fichiers du composant de chemin de l'URL, @PROGRAM_NAME@ supposera qu'ils sont codés à l'aide de cet ensemble de caractères et traduira les noms de fichiers vers l'ensemble de caractères local. Ceci ne concerne pas l'encodage du contenu des fichiers et pas les règles d'échappement HTTP.
Il n'y a aucun moyen en HTTP de connaître l'encodage des caractères du composant de chemin. Il peut même y avoir différents encodages au sein du même chemin, car l'encodage des noms de fichiers est souvent défini par les clients qui les ont créés. Aujourd'hui, il est préférable d'utiliser uniquement l'encodage UTF-8 et de ne pas effectuer de conversion. Si vous n'êtes pas sûr que tous les clients comprennent l'UTF-8, limitez les noms de fichiers à du pur us-ascii. N'utilisez jamais de caractères dans les noms de fichiers qui pourraient avoir une fonction spéciale sur certains systèmes d'exploitation (comme /, : et \).
Par défaut : aucune conversion d'ensemble de caractères
connect_timeout
Lors de la création d'une connexion TCP avec le serveur, @PROGRAM_NAME@ attendra ce nombre de secondes une réponse avant de supposer une erreur. Si une valeur de '0' est utilisée, aucun délai d'attente explicite n'est défini et l'appel de connexion ne sera limité que par la pile TCP.
Ce paramètre n'est effectif que si la version de neon utilisée (version neon > 0.26) et le système d'exploitation prennent en charge les E/S non bloquantes.
Par défaut : 10
read_timeout
Pendant combien de secondes @PROGRAM_NAME@ attendra une réponse du serveur avant de supposer une erreur.
Par défaut : 30
retry
Lorsque @PROGRAM_NAME@ ne peut pas atteindre le serveur, il réessayera après retry secondes. Pour les tentatives ultérieures, l'intervalle sera augmenté jusqu'à max_retry secondes.
Par défaut : 30
max_retry
Valeur maximale de l'intervalle de nouvelle tentative.
Par défaut : 300
max_upload_attempts
Lorsqu'un téléchargement de fichier modifié échoue temporairement, @PROGRAM_NAME@ réessayera avec des intervalles croissants, mais pas plus souvent que cela.
Avec une mauvaise connexion, cela provoquera un trafic supplémentaire. Pour réduire le trafic causé par des tentatives infructueuses, l'option use_expect100 peut être définie. Mais veuillez la tester. La plupart des proxys et certains serveurs ne prennent pas en charge cet en-tête.
Par défaut : 15
add_header
Votre serveur pourrait s'attendre à des en-têtes spéciaux pour faire ce que vous voulez. Contrairement aux autres options, celle-ci prend deux valeurs : le nom de l'en-tête et sa valeur. Certains backends ASP pour IIS semblent nécessiter l'en-tête spécifique à Microsoft "Translate: F". Vous pouvez l'ajouter comme ceci :
add_header Translate F
@PROGRAM_NAME@ ajoutera l'en-tête "Translate: F" à toutes les requêtes.
Cette option est cumulative. Vous pouvez entrer plusieurs options add_header et toutes seront ajoutées. Les options add_header de @SYS_CONF_DIR@/@CONFIGFILE@ et de ~/.@PACKAGE@/@CONFIGFILE@ sont également fusionnées.

Options liées à la mise en cache

backup_dir
Chaque système de fichiers @PACKAGE@ monté possède un répertoire pour stocker les sauvegardes des fichiers qui n'ont pas pu être renvoyés au serveur. Ceci définit le nom de ce répertoire. Vous devriez vérifier régulièrement ce répertoire.
Par défaut : lost+found
cache_dir
Le répertoire où @PROGRAM_NAME@ stockera les fichiers mis en cache. Pour chaque point de montage, un sous-répertoire sera créé.
Dans le fichier de configuration système, cela définira le cache système, utilisé par root. Dans un fichier de configuration utilisateur, cela définira le cache utilisé par cet utilisateur.
Par défaut : @SYS_CACHE_DIR@ et ~/.@PACKAGE@/cache
cache_size
La quantité d'espace disque en Mio qui peut être utilisée. @PROGRAM_NAME@ utilisera toujours suffisamment d'espace pour mettre en cache les fichiers ouverts, ignorant cette valeur si nécessaire.
Par défaut : 50
table_size
@PROGRAM_NAME@ maintient une table de hachage avec une entrée pour chaque fichier ou répertoire connu. Ceci donne le nombre d'entrées dans cette table. Pour de grands systèmes de fichiers (plusieurs centaines de fichiers), augmenter ce nombre peut accélérer les opérations de fichiers. La valeur doit être une puissance de 2.
Par défaut : 1024
dir_refresh
Après que @PROGRAM_NAME@ ait obtenu des informations sur les fichiers d'un répertoire, il les considère comme valides pendant ce temps en secondes. Remarque : Cela n'affecte pas l'ouverture des fichiers et la lecture d'un répertoire par une application.
Par défaut : 60
file_refresh
Lorsqu'un fichier ou un répertoire est ouvert par une application, @PROGRAM_NAME@ vérifiera d'abord auprès du serveur pour une version plus récente. Mais certaines applications effectuent des appels open sur le même fichier en succession rapide. Pour éviter un trafic inutile @PROGRAM_NAME@ attendra ce nombre de secondes avant d'envoyer une nouvelle requête pour les mêmes informations.
Par défaut : 1
delay_upload
Lorsqu'un fichier modifié est fermé, @PROGRAM_NAME@ attendra ce nombre de secondes avant de l'envoyer au serveur. Cela évitera l'envoi de fichiers temporaires qui seront supprimés immédiatement après la fermeture. Si vous avez besoin que les fichiers apparaissent sur le serveur immédiatement après la fermeture, définissez cette option à 0.
Par défaut : 10
gui_optimize
Lorsqu'un fichier est ouvert, @PROGRAM_NAME@ doit vérifier auprès du serveur s'il existe une version plus récente. Les interfaces graphiques ont tendance à ouvrir n'importe quel fichier, ralentissant considérablement les choses pour les grands répertoires. Avec cette option @PROGRAM_NAME@ essaiera d'obtenir cette information pour tous les fichiers d'un répertoire avec une seule requête PROPFIND. 0 = non, 1 = oui.
Par défaut : 0
minimize_mem
davfs2 conserve des informations sur les fichiers et les répertoires en mémoire vive. Elles y restent tant que le système de fichiers est monté et que le fichier n'est pas supprimé. L'utilisation mémoire par davfs2 augmentera donc avec le temps et pourrait ralentir davfs2. Lorsque cette option est définie à 1, davfs2 nettoiera régulièrement la mémoire des informations qui n'ont pas été utilisées depuis un certain temps. 0 = non, 1 = oui.
Avertissement : La plupart des attributs de fichiers ne sont maintenus localement que parce qu'il n'existe pas de propriété WebDAV correspondante. Ainsi, si des utilisateurs modifient des attributs (propriétaire, groupe, bits d'accès) localement, ces modifications seront perdues et les valeurs des attributs seront réinitialisées aux valeurs par défaut.
Par défaut : 0

Options de débogage

debug
Envoie des messages de débogage au démon syslog. La valeur indique quel type d'information doit être journalisé. Les messages sont envoyés avec la facilité LOG_DAEMON et la priorité LOG_DEBUG. Cela dépend de la configuration du démon syslog où les messages iront (probablement /var/log/messages, /var/log/syslog ou /var/log/daemon.log). La disponibilité des messages de débogage liés à HTTP dépend de votre bibliothèque neon.
Contrairement aux autres options, cette option est cumulative. S'il existe plusieurs entrées de débogage avec des valeurs différentes, toutes seront appliquées. Les options de débogage de @SYS_CONF_DIR@/@CONFIGFILE@ et ~/.@PACKAGE@/@CONFIGFILE@ sont également fusionnées.
Remarque : Les messages de débogage font rapidement grossir les fichiers de journal. N'utilisez jamais cette option lors du fonctionnement normal de mount.davfs.
Par défaut : aucun message de débogage
Valeurs reconnues :
config
Ligne de commande et options de configuration.
kernel
Appels entrants du système de fichiers noyau.
cache
Opérations de cache comme l'ajout et la suppression de nœuds.
http
En-têtes HTTP.
xml
Analyse du corps XML des requêtes WebDAV.
httpauth
Négociation de l'authentification.
locks
Informations sur les verrous.
ssl
Éléments liés à TLS/SSL comme les certificats.
httpbody
Corps complet des réponses HTTP.
secrets
Affiche également des informations confidentielles, qui sont généralement omises ou obscurcies.
most
Inclut config, kernel, cache et http.
