DESCRIPTIO

N

darktable est une application de flux de travail de photographie numérique pour Linux, Mac OS X et plusieurs autres systèmes de typ

e Unix.

L'application est conçue pour faciliter l'édition et le traitement cohérent de grandes sessions photo et fournit une table lumineuse numérique facile à utiliser et un ensemble d'outils de post-traitement

sophistiqués.

La plupart des traitements sont effectués en mode flottant 32 bits par canal dans l'espace colorimétrique CIE L*a*b* indépendant de l'appareil. darktable est également entièrement géré colorimétriquement, ce qui vous donne un contrôle total sur l'apparence des

photos.

L'application repose sur une architecture moderne de plugins, ce qui facilite pour les développeurs tiers d'étendre les capacités existantes de l'application. Toutes les fonctionnalités de la table lumineuse et de la chambre noire sont implémentées en tant que plugins, vous pouvez donc créer vos plugins en réutilisant le code existant. La plupart des éléments spécifiques au flux de travail peuvent également être scriptés en Lu

a
.

OPTION

S
IMG_1234.RAW ou
dossier_images/
Vous pouvez éventuellement fournir le nom de fichier d'une image ou le nom d'un dossier contenant des fichiers d'images. Si un nom de fichier est donné, darktable démarre en vue chambre noire avec ce fichier ouvert. Si un dossier est donné, darktable démarre en vue table lumineuse avec le contenu de ce dossier comme collection courante. S'il existe déjà une instance de darktable en cours d'exécution (utilisant la même bibliothèque), l'image ou le dossier y sera ouvert, en utilisant D-Bus pour communiquer entre les deux
processus.
--cachedir <répertoire de
cache>
darktable conserve un cache des miniatures d'images pour un aperçu rapide des images et des binaires OpenCL précompilés pour un démarrage rapide. Par défaut, le cache est situé dans "$HOME/.cache/darktable/". Il peut exister plusieurs caches de miniatures en parallèle - un pour chaque fichier de
bibliothèque.
--conf <clé>
=<valeur>
darktable prend en charge un riche ensemble de paramètres de configuration que l'utilisateur définit dans "darktablerc" - le fichier de configuration de darktable dans le répertoire de configuration de l'utilisateur. Vous pouvez temporairement écraser des paramètres individuels sur la ligne de commande avec cette option - cependant, ces paramètres ne seront pas stockés dans "darktablerc
".
--configdir <répertoire de
configuration>
Cette option définit le répertoire où darktable stocke la configuration spécifique à l'utilisateur. L'emplacement par défaut est "$HOME/.config/darktable
/".
-d <option de
débogage>
Cette option active la sortie de débogage vers le terminal. Il existe plusieurs sous-systèmes de darktable et le débogage de chacun d'entre eux peut être activé séparément. Vous pouvez utiliser cette option plusieurs fois si vous souhaitez la sortie de débogage de plus d'un sous-système.

threads.

Cela vous donnera beaucoup d'informations de débogage sur le cache des miniatures pour le mode table lumineuse. S'il est compilé en mode débogage, cela indiquera également où dans le code un certain buffer a été verrouillé pour la dernière
fois.

--datadir <répertoire de
données>
Cette option définit le répertoire où darktable trouve ses données d'exécution. L'emplacement par défaut dépend de votre installation. Les emplacements typiques sont "/opt/darktable/share/darktable/" et "/usr/share/darktable
/".
--disable-ope
ncl
Empêche darktable d'initialiser le sous-système OpenCL. Utilisez cette option si darktable plante au démarrage en raison d'une implémentation OpenCL
défectueuse.
-h, --he
lp
Affiche les options de ligne de commande disponibles et
quitte.
--library <fichier de
bibliothèque>
darktable conserve les informations d'image dans une base de données sqlite pour un accès rapide. L'emplacement par défaut de ce fichier de base de données est "$HOME/.config/darktable/library.db". Vous pouvez indiquer un emplacement alternatif, par exemple si vous souhaitez faire quelques expériences sans compromettre votre library.db original. Si le fichier de base de données n'existe pas, darktable le crée pour vous. Vous pouvez également indiquer ":memory:" comme fichier de bibliothèque, auquel cas la base de données est conservée en mémoire système - toutes les modifications sont ignorées lorsque darktable se
termine.
--localedir <répertoire de
localisation>
L'endroit où darktable trouve ses chaînes de texte spécifiques à la langue. L'emplacement par défaut dépend de votre installation. Les emplacements typiques sont "/opt/darktable/share/locale/" et "/usr/share/lo
cale/".
--luacmd <commande
lua>
Une chaîne contenant des commandes lua à exécuter après l'initialisation de lua. Ces commandes seront exécutées après votre fichier "luarc".

Si lua n'est pas compilé,

cette option sera acceptée
mais ne fera rien.
--moduledir <répertoire de
modules>
darktable a une structure modulaire et organise ses modules en tant que bibliothèques partagées à charger à l'exécution. Avec cette option, vous indiquez à darktable où chercher ses bibliothèques partagées. L'emplacement par défaut dépend de votre installation ; les emplacements typiques sont "/opt/darktable/lib/darktable/" et "/usr/lib/darktable
/".
--noiseprofiles <fichier json de profils de
bruit>
Le module de réduction de bruit profilé de darktable utilise des données de profil spécifiques à l'appareil photo qui sont chargées depuis un fichier JSON externe. Avec cette option, le fichier à charger peut être modifié pour permettre de tester des profils alternatifs. Le fichier de profil par défaut est "noiseprofiles.json" et se trouve généralement dans "/opt/darktable/share/darktable/" ou "/usr/share/darktable
/".
-t <nombre de threads
openmp>
darktable utilise OpenMP pour paralléliser de nombreuses étapes de calcul et utiliser tous les cœurs de CPU disponibles. Avec cette option, vous pouvez spécifier le nombre de threads à utiliser. Les valeurs valides sont comprises entre 1 et 100
.
--tmpdir <répertoire
temporaire>
L'endroit où darktable stocke ses fichiers temporaires. Si cette option n'est pas fournie, darktable utilise la valeur par défaut du
système.

on
