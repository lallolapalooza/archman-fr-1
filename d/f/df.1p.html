DESCRIPTIO

N

L'utilitaire df doit afficher la quantité d'espace disponible et d'emplacements de fichiers pour les systèmes de fichiers auxquels l'utilisateur appelant a un accès en lecture approprié. Les systèmes de fichiers doivent être spécifiés par les opérandes fichier ; lorsqu'aucun n'est spécifié, les informations doivent être affichées pour tous les systèmes de fichiers. Le format de la sortie par défaut de df n'est pas spécifié, mais toutes les valeurs d'espace sont rapportées en unités de 512 octets, sauf si l'option -k est spécifiée. Cette sortie doit contenir au moins les noms des systèmes de fichiers, la quantité d'espace disponible sur chacun de ces systèmes de fichiers et, si aucune option autre que -t n'est spécifiée, le nombre d'emplacements de fichiers libres, ou inœuds, disponibles ; lorsque -t est spécifié, la sortie doit co

JUSTIFICATIO

N

Le comportement de df avec l'option -P est l'action par défaut de l'utilitaire df de 4.2 BSD . Le -P majuscule a été sélectionné pour éviter une collision avec une extension industrielle connue utilisant -p

.

Les implémentations df historiques varient considérablement dans leur sortie par défaut. Il a donc été nécessaire de décrire la sortie par défaut de manière souple afin d'accommoder toutes les implémentations historiques connues et d'ajouter une option portable (-P) pour fournir des informations dans un format

portable.

L'utilisation d'unités de 512 octets est une pratique historique et maintient la compatibilité avec ls et les autres utilitaires de ce volume de POSIX.1‐2017. Cela n'oblige pas le système de fichiers lui-même à être basé sur des blocs de 512 octets. L' option -k a été ajoutée comme mesure de compromis. Les développeurs de la norme ont convenu que 512 octets était l'unité par défaut la plus appropriée en raison de sa cohérence historique complète sur System V (contrairement à l'utilisation mixte de 512/1024 octets sur les systèmes BSD), et qu'une option -k pour passer aux unités de 1024 octets était un bon compromis. Les utilisateurs qui préfèrent la quantité plus logique de 1024 octets peuvent facilement créer un alias df vers df -k sans casser de nombreux scripts historiques reposant sur les unités de 512

octets.

Il a été suggéré que df et les divers utilitaires associés soient modifiés pour accéder à une variable d'environnement BLOCKSIZE afin d'atteindre la cohérence et l'acceptation par l'utilisateur. Puisque ce n'est pas une pratique historique sur

aucun système, cela est laissé comme une possible zone d'extension du systè
me et sera réévalué dans une version future s'il est largement implémenté.
