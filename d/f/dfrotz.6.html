NOM

dfrotz - interpréteur pour les jeux Infocom et autres jeux Z-Machine (interface basique)

SYNTAXE

dfrotz [options] fichier [fichier_blorb]

Au moins un fichier doit être spécifié dans la ligne de commande. Il peut s'agir d'un fichier Z-code simple ou d'un fichier Blorb. Un fichier Z-code est un exécutable compilé pour la Z-Machine. Un fichier Blorb contient de l'audio, des graphiques et d'autres éléments en plus du jeu, le tout regroupé dans un seul fichier. Il peut également contenir l'exécutable Z-Machine de manière optionnelle. Si un fichier Z-code simple est fourni, Frotz recherchera un fichier Blorb portant le même nom de base mais avec une extension de .blb, .blorb, ou .zblorb et le chargera s'il est trouvé.

Si le fichier fourni dans la ligne de commande est un fichier Blorb, Frotz vérifiera s'il contient un fichier Z-code. Si aucun n'est trouvé, Frotz se plaindra et quittera.

Un fichier Blorb nommé différemment peut être fourni comme deuxième paramètre optionnel à l'invocation de commande.

Si vous souhaitez jouer à l'un des jeux d'Infocom qui utilisent du son ou des graphiques, vous devrez obtenir un fichier Blorb correspondant auprès de l'Interactive Fiction Archive. Voir INFORMATIONS COMPLÉMENTAIRES ci-dessous.

DESCRIPTION

Frotz est un interpréteur Z-Machine. La Z-machine est une machine virtuelle conçue par Infocom pour exécuter toutes leurs aventures textuelles. Elle a subi plusieurs révisions au cours de la vie de l'entreprise, et deux révisions supplémentaires (V7 et V8) ont été créées par Graham Nelson après la disparition de l'entreprise. La spécification est maintenant bien documentée ; cette version de Frotz prend en charge la version 1.1. Voir NORMES Z-MACHINE ci-dessous.

Cette version de Frotz prend entièrement en charge toutes ces versions de la Z-Machine, à l'exception de la version 6. La version 6 est semi-prise en charge en affichant les contours des graphiques V6 avec le numéro d'image en bas à droite.

Cette page de manuel concerne Frotz avec l'interface basique. Frotz basique ne prend pas en charge les effets sonores, les graphiques, les couleurs, ni même la gestion de l'écran (par exemple, curses(3)). Son objectif est de fournir un interpréteur Z-machine avec le minimum absolu de prérequis système ou pour les applications où ces fonctionnalités ne sont pas nécessaires.

OPTIONS

-a
Surveiller la définition des attributs. La définition et la suppression d'attributs sur les objets seront notées dans les messages de débogage.
-A
Surveiller le test des attributs. Chaque fois que la Z-machine teste la valeur d'un attribut, le test et le résultat seront rapportés.
-f [irc | ansi | normal]
Sélectionner le type de codes de formatage. Frotz basique peut éventuellement marquer sa sortie avec des codes pour la couleur, le gras, le soulignement, etc. Actuellement, les codes de formatage pour les clients irc et les terminaux ansi sont pris en charge. Spécifier normal ou ne pas utiliser ce drapeau du tout entraînera le comportement normal de Frotz basique qui n'utilise aucun type de marquage.
-h N
Hauteur du texte. Toutes les N lignes, une invite MORE sera affichée. L'utilisation de l'option -m rend cette option obsolète.
-i
Ignorer les erreurs fatales. Si un interpréteur Z-Machine rencontre une erreur zcode telle qu'une division par zéro ou une adresse d'objet illégale, la réponse appropriée est d'interrompre l'exécution. Ceci est fait car le programme zcode n'a pas une idée claire de ce qui se passe. Il existe certains jeux où des erreurs fatales se produisent parce que les auteurs ont été négligents et ont utilisé un interpréteur qui ne vérifiait pas correctement les erreurs. Cette option est destinée à contourner de tels bugs, mais attention, des choses étranges peuvent se produire si les erreurs fatales ne sont pas interceptées.
-I N
Définir le numéro de l'interpréteur. Infocom a conçu la Z-machine de telle sorte qu'un jeu puisse savoir sur quel type de machine tournait l'interpréteur. Voir NUMÉRO D'INTERPRÉTEUR ci-dessous.
-L <nom_fichier>
Lorsque le jeu démarre, charge ce fichier de sauvegarde.
-m
Désactiver les invites MORE. Cela peut être souhaitable lors de l'utilisation d'un terminal d'impression.
-o
Surveiller le déplacement des objets. Cette option active les messages de débogage de l'interpréteur qui décrivent le déplacement des objets dans l'arbre d'objets.
-O
Surveiller l'emplacement des objets. Ces messages de débogage détaillent les emplacements des objets dans l'arbre d'objets.
-p
Sortie ASCII simple uniquement. Cela empêche la sortie des lettres accentuées et d'autres caractères de l'ensemble de caractères Latin-1, en les remplaçant par des alternatives raisonnables. Cela peut être nécessaire sur des appareils qui ne disposent pas de ces caractères. Les diphtongues OE/oe sont absentes de l'ensemble Latin-1. Celles-ci sont également gérées.
-P
Modifier l'opcode @piracy. L'opcode @piracy n'a jamais été utilisé par Infocom. Ce commutateur est vraiment utile uniquement pour ceux qui aiment manipuler du Z-code.
-q
Mode silencieux. Supprime les messages de démarrage tels que "Loading zork1.z3".
-r xxx
Définir les options d'exécution. Cette option peut être utilisée à plusieurs reprises. Voir CONFIGURATION ci-dessous. Il n'est pas nécessaire de préfixer avec une barre oblique inverse.
-R <chemin>
Lecture/écriture restreinte. La lecture et l'écriture de fichiers seront restreintes uniquement au chemin fourni. Normalement, Frotz écrira ou lira ses sauvegardes, transcriptions et enregistrements de déplacements dans le chemin ou le répertoire que l'utilisateur fournit lorsque les commandes SAVE, SCRIPT, ou RECORDING sont données. Cela peut être indésirable si Frotz est exécuté dans un environnement restreint, par une interface utilisateur ou par un chatbot. Cette option amènera Frotz à écrire ou lire uniquement dans le chemin fourni et nulle part ailleurs. Ensuite, le processus de contrôle pourra surveiller ce répertoire pour les changements et n'aura pas à s'inquiéter de quelqu'un qui griffonne ou fouine je-ne-sais-où.
-s N
Définir la valeur de la graine du nombre aléatoire. La valeur de graine donnée est utilisée comme valeur de graine initiale à chaque redémarrage. Par défaut, le générateur de nombres aléatoires est initialisé en fonction de l'horloge système ; cela vous permet de rendre le générateur de nombres aléatoires prévisible, pour une utilisation dans des scripts enregistrés ou pour le débogage. Par exemple, Curses prend des décisions aléatoires avant la première entrée (de sorte que la touche de raccourci Alt-S n'aide pas vraiment).
-S N
Définir la largeur de la transcription. Par défaut, vos fichiers de transcription sont formatés sur une largeur de 80 colonnes par ligne, quelle que soit la largeur de texte actuelle. Ce commutateur vous permet de modifier ce paramètre. En particulier, utilisez -S 0 pour désactiver le découpage automatique des lignes dans les fichiers de transcription.
-t
Définit le bit Tandy de la Z-machine, ce qui peut affecter le comportement de certains jeux Infocom. Par exemple, Zork I prétend ne pas avoir de suites, et Witness a un langage atténué.
-u N
Définit le nombre d'emplacements disponibles pour la combinaison de touches d'annulation multiple de Frotz (voir ci-dessous). Cela est défini par défaut à vingt, ce qui devrait suffire pour la plupart des usages. Définir un nombre trop élevé ici peut être dangereux sur les machines à mémoire limitée.
-w N
Définit manuellement la largeur du texte. Cela ne devrait pas être nécessaire sauf dans des circonstances spéciales.
-x
Développe les abréviations "g", "x" et "z" en "again", "examine" et "wait". Ce commutateur est destiné à être utilisé avec les anciens jeux Infocom qui manquent de ces abréviations courantes qui ont été introduites dans les jeux ultérieurs. Utilisez-le avec prudence : quelques jeux pourraient utiliser "g", "x" ou "z" à des fins différentes.
-v
Afficher les informations de version et quitter. Cela affichera la version de Frotz, des informations sur ce qui est activé et ce qui ne l'est pas, la date de validation du code source, et un hachage git(1) de cette validation.
-Z N
Mode de vérification des erreurs.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.


0 = ne pas signaler d'erreurs.
1 = signaler la première occurrence d'une erreur.
2 = signaler toutes les erreurs.
3 = quitter après toute erreur.
La valeur par défaut est 1 (signaler la première occurrence d'une erreur).

INTERPRÉTATEUR

NOMBRE

Le numéro d'interpréteur est un paramètre dans l'en-tête de la machine Z qui est utilisé pour indiquer au jeu sur quel type de machine l'interpréteur s'exécute. Frotz choisira automatiquement le numéro le plus approprié pour un jeu produit par Infocom. Si vous souhaitez remplacer le numéro, l' -I est

disponible.

Un interpréteur doit choisir le numéro d'interpréteur le plus adapté à la machine sur laquelle il s'exécutera. Dans les versions jusqu'à 5, la principale considération est que le comportement de 'Beyond Zork' dépend du numéro d'interpréteur (en ce qui concerne son utilisation de la police de caractères graphiques). En version 6, la décision est plus sérieuse, car les fichiers de jeu d'Infocom existants dépendent du numéro d'interpréteur de nombreuses manières : de plus, certains fichiers de jeu s'attendent à être exécutés uniquement sur les interpréteurs d'une machine particulière. Il existe, par exemple, des versions spécifiques à l'Amiga. Le DECSystem-20 était le mainframe interne

d'Infocom.

Pour les quatre jeux V6 d'Infocom, le numéro d'interpréteur sera automatiquement choisi en fonction du titre et du numéro de version. Bien sûr, cela peut être remplacé en ligne de

commande.

UNICOD

E

Dumb Frotz prend en charge les glyphes Unicode via UTF-8 si le terminal utilisé prend en charge UTF-8. Si vous préférez utiliser xterm, lancez-le en tant qu'uxterm. Il s'agit d'un script wrapper qui configure xterm avec une locale UTF-8. Vous pouvez aussi indiquer manuellement à un xterm de passer en mode UTF-8 en maintenant CTRL et le bouton droit de la souris pour faire apparaître le menu VT FONTS. Selon la manière dont xterm a été installé, vous pouvez voir une option pour "UTF-8 Fonts" qui permettra à Unicode d'être correctement

affiché.

Faire en sorte que xterm se comporte ainsi en permanence peut varier d'un système à l'autre. Les autres émulateurs de terminal ont leurs propres méthodes pour être configurés à utiliser l'encodage de caractères

UTF-8.

Si vous utilisez une sorte de wrapper autour de dfrotz et souhaitez utiliser Unicode, il est de la responsabilité du

wrapper de donner un sens aux c
aractères passés dans les deux sens.

CARACTÈRES NON

ASCII

Les glyphes non ASCII peuvent être affichés sans utiliser UTF-8 via les jeux de caractères ISO-8859-1 ou ISO-8859-15 (Latin-1 ou Latin-9). ISO-8859-15 est plus ou moins identique à ISO-8859-1 sauf que les diphtongues OE/oe sont prises en charge, remplaçant les glyphes rarement utilisés 1/2 et 1/4. Voir aussi luit(1) charsets(7) iso_8859-1(7) et iso_8859-15(7) pour plus

d'informations.

E

NAME

dfrotz - Unix Frotz, a Z-Machine interpreter

SYNOPSIS

dfrotz [-a] [-A] [-b] [-c] [-C] [-d] [-e] [-f] [-F] [-g] [-h] [-i] [-I] [-j] [-J] [-k] [-l] [-L] [-m] [-M] [-n] [-N] [-o] [-O] [-p] [-P] [-q] [-r] [-R] [-s] [-S] [-t] [-T] [-u] [-U] [-v] [-V] [-w] [-W] [-x] [-X] [-y] [-Y] [-?] [-z] [--] [story-file]

DESCRIPTION

dfrotz is a Unix port of Stefan Jokisch's Frotz, a Z-Machine interpreter. The Z-Machine is the machine language for the popular interactive fiction games produced by Infocom.

dfrotz reads a story file (typically with a .z3, .z4, .z5, .z6, or .z8 file extension) and plays the game. You interact with the game by typing commands.

OPTIONS

The following options are supported:

-a
Auto-detect Blorb files. Blorb is a container format for multimedia files, often used for sound and graphics in interactive fiction. This option makes dfrotz try to find and use associated sound and graphics files if they are present in the same directory as the story file or in a subdirectory named blorb.
-A
Disable auto-detection of Blorb files.
-b
Don't use the TTY driver's color capabilities (if any). This is useful if the TTY driver doesn't properly support color, or if you are redirecting output and don't want color escape codes. The interpreter will also use the correct color codes for the terminal if this option is not used.
-c
Turn off all console output. Use this if you want to redirect output to a file. No screen updates will occur.
-C
Turn on console output. This is the default.
-d
Enable interpreter debugging commands. Typing `debug` at the game prompt will give you access to the interpreter's debugging capabilities.
-e
Echo commands typed by the user. This is the default.
-f
Disable command echoing. Commands typed by the user will not be displayed on the screen.
-F
Force 80 column width. This can be useful if dfrotz is guessing the terminal width incorrectly.
-g
Display the interpreter's graphical status line (if the game supports it). This is the default.
-h
Display a help message and exit.
-i
Disable interpreter status line. The game will not display its status line (e.g., score, location, health).
-I
Enable interpreter status line. This is the default.
-j
Disable automatic saving of the game state on exit. By default, dfrotz saves the game state when you exit normally (e.g., by typing `quit`). This saved state can be restored the next time you run dfrotz with the same story file.
-J
Enable automatic saving of the game state on exit. This is the default.
-k
Disable the interpreter's built-in help ( invoked by typing `help` or `?`).
-l
List available story files in the current directory. This option exits after listing the files.
-L
List available story files in the current directory and exit.
-m
Treat story files as if they were version 5 Z-Machine files. This is the default.
-M
Treat story files as if they were version 8 Z-Machine files. This is useful for playing newer games that may not be recognized as version 8 by default.
-n
Disable sound effects. This is the default.
-N
Enable sound effects (if supported by the game and the system).
-o
Disable the display of screen routines (e.g., text scrolls, clearing the screen). This can be useful for debugging or for capturing raw text output.
-O
Enable the display of screen routines. This is the default.
-p
Turn off prompting for confirmation before restoring saved games. By default, dfrotz will ask for confirmation before overwriting a saved game.
-P
Turn on prompting for confirmation before restoring saved games. This is the default.
-q
Quiet mode. Suppresses introductory messages and prompts.
-r
Reverse the order in which saved games are displayed when using the `restore` command. Instead of newest first, it lists oldest first.
-R
Restricted read/write mode. When this option is active, file access (reading and writing) is restricted to the directory specified by the -w option. This is a security feature.
-s
Enable sound. This is the default.
-S
Disable sound. This is equivalent to the -n option.
-t
Turn off the display of text. Useful for debugging or performance testing.
-T
Turn on the display of text. This is the default.
-u
Treat story files as if they were version 3 Z-Machine files. This is useful for playing older games.
-U
Treat story files as if they were version 6 Z-Machine files. This is rarely needed.
-v
Display the version of dfrotz and exit.
-V
Display the version of dfrotz and exit.
-w path
Set the working directory for save files and other file operations. If -R is also specified, file access will be restricted to this path.
-W
Don't use the TTY driver's windowing capabilities (if any). This can be useful if your TTY driver doesn't support windows properly.
-x
Enable extended Z-machine features. This is generally recommended for playing modern games.
-X
Disable extended Z-machine features. This is the default for older games.
-y
Treat story files as if they were version 4 Z-Machine files. This is rarely needed.
-Y
Treat story files as if they were version 7 Z-Machine files. This is rarely needed.
-?
Display a help message and exit.
-z
Use the curses library. This is the default, as it provides a more interactive experience with features like line editing and history.
--
Signals the end of options. Any subsequent arguments are treated as story file names.

Note: Not all options may be supported by all versions of dfrotz. The specific options available may depend on how dfrotz was compiled.

INTERPRETER NUMBER

dfrotz will recognize and attempt to play Z-Machine files of versions 1 through 8. Files of versions 1-3 are treated as version 3, files of version 4 are treated as version 4, files of versions 5-7 are treated as version 5, and files of version 8 are treated as version 8. You can override this behavior with the -u, -m, -y, -U, -M, -Y, and -X options.

CONFIGURATION

Configuration for dfrotz can be set in the environment variable $FROTZ_CONFIG. This should be a string of options to be passed to dfrotz every time it is run. For example:

    FROTZ_CONFIG="-a -x"

This would enable Blorb support and extended Z-machine features by default.

UNICODE

dfrotz supports Unicode characters in story files and for terminal output, provided that the terminal itself supports Unicode and is configured correctly.

NON ASCII CHARACTERS

If your terminal supports non-ASCII characters (e.g., accented letters, special symbols), dfrotz will attempt to use them correctly. This includes displaying them when they appear in the game text and allowing you to type them as part of your commands. The Z-Machine standard has a specific way of handling non-ASCII characters, and dfrotz aims to implement this correctly.

Z-MACHINE STANDARDS

dfrotz supports the following Z-Machine specifications:

  • Version 3
  • Version 4
  • Version 5
  • Version 6 (with the -x option)
  • Version 7 (with the -x option)
  • Version 8 (with the -x option)

Games written for older Z-Machine versions (1 and 2) will generally work correctly when run as version 3 games.

The -x option enables support for Z-Machine versions 6, 7, and 8, which include features like 16-bit characters and advanced screen manipulation. It is recommended to use this option for most modern interactive fiction games.

ENVIRONMENT

Unlike its curses-using or SDL-using siblings, dfrotz does not search any path for game files.

CAVEATS

The Z Machine itself has trouble with the concept of resizing a terminal. It assumes that once the text height and width are set, they will never change; even across saves. This made sense when 24x80 terminals were the norm and graphical user interfaces were mostly unknown. I'm fairly sure there's a way around this problem, but for now, don't resize an xterm in which Frotz is running. Also, you should try to make sure the terminal on which you restore a saved game has the same dimensions as the one on which you saved the game.
