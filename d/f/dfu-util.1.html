NOM

dfu-util - Programme USB de mise à jour du firmware (DFU)

SYNTAXE

dfu-util -l [-v] [-d vid:pid[,vid:pid]] [-p chemin] [-c configuration] [-i interface] [-a alt-intf] [-S serie[,serie]]

dfu-util [-v] [-d vid:pid[,vid:pid]] [-p chemin] [-c configuration] [-i interface] [-a alt-intf] [-S serie[,serie]] [-t taille] [-Z taille] [-w] [-s adresse] [-R] [-D|-U fichier]

dfu-util [-hV]

DESCRIPTION

dfu-util est un programme qui implémente le côté hôte (ordinateur) du protocole DFU (Universal Serial Bus Device Firmware Upgrade) USB.

dfu-util communique avec les appareils qui implémentent le côté appareil du protocole DFU USB, et est souvent utilisé pour mettre à jour le firmware de tels appareils.

OPTIONS

-l, --lister
Liste les périphériques USB capables de DFU actuellement connectés.
-d, --appareil [VLANDEUR en cours d'exécution]:[PRODUIT en cours d'exécution][,[VLANDEUR en mode DFU]:[PRODUIT en mode DFU]]
Spécifie les identifiants de vendeur et/ou de produit en cours d'exécution et/ou en mode DFU du périphérique DFU à utiliser. VLANDEUR et PRODUIT sont des nombres hexadécimaux (aucun préfixe requis), "*" (correspond à n'importe lequel), ou "-" (ne correspond à rien). Par défaut, tout appareil capable de DFU en cours d'exécution ou en mode DFU sera considéré.

Si vous n'avez qu'un seul appareil DFU conforme aux normes connecté à votre ordinateur, ce paramètre est facultatif. Cependant, dès que vous avez plusieurs appareils DFU connectés, dfu-util le détectera et s'arrêtera, vous demandant de spécifier quel appareil utiliser.

Si seuls les identifiants en cours d'exécution sont spécifiés (par exemple, "--appareil 1457:51ab"), alors en plus des identifiants en cours d'exécution spécifiés, tout appareil en mode DFU sera également considéré. Ceci est bénéfique pour permettre de retrouver un appareil capable de DFU après un passage en mode DFU, car l'identifiant du vendeur et/ou du produit d'un appareil change généralement en mode DFU.

Si seuls les identifiants en mode DFU sont spécifiés (par exemple, "--appareil ,951:26"), alors tous les appareils en cours d'exécution seront ignorés, ce qui facilite le ciblage d'un appareil spécifique en mode DFU.

Si les identifiants en cours d'exécution et en mode DFU sont tous deux spécifiés (par exemple, "--appareil 1457:51ab,:2bc"), alors les composants du mode DFU non spécifiés utiliseront la valeur en cours d'exécution spécifiée.

Exemples:

--appareil 1457:51ab,951:26

Utilise un appareil en mode d'exécution avec l'ID vendeur 0x1457 et l'ID produit 0x51ab, ou en mode DFU avec l'ID vendeur 0x0951 et l'ID produit 0x0026
--appareil 1457:51ab,:2bc

Utilise un appareil en mode d'exécution avec l'ID vendeur 0x1457 et l'ID produit 0x51ab, ou en mode DFU avec l'ID vendeur 0x1457 et l'ID produit 0x02bc
--appareil 1457:51ab

Utilise un appareil en mode d'exécution avec l'ID vendeur 0x1457 et l'ID produit 0x51ab, ou en mode DFU avec n'importe quel ID vendeur et produit
--appareil ,951:26

Utilise un appareil en mode DFU avec l'ID vendeur 0x0951 et l'ID produit 0x0026
--appareil *,-

Utilise n'importe quel appareil en mode d'exécution, et ignore tout appareil en mode DFU
--appareil ,

Ignore tout appareil en mode d'exécution, et utilise n'importe quel appareil en mode DFU
-p, --chemin BUS-PORT. ... .PORT
Spécifie le chemin vers le périphérique DFU.
-c, --cfg NR-CONFIG
Spécifie la configuration du périphérique DFU. Notez que ceci est seulement utilisé pour la correspondance, la configuration n'est pas définie par dfu-util.
-i, --intf NR-INTF
Spécifie le numéro de l'interface DFU.
-a, --alt ALT
Spécifie le réglage alternatif de l'interface DFU par nom ou par numéro.
-S, --serie [SERIE en cours d'exécution][,[SERIE en mode DFU]]
Spécifie les numéros de série en cours d'exécution et en mode DFU utilisés pour restreindre davantage les correspondances de périphériques. Si plusieurs périphériques DFU identiques sont connectés simultanément à un système, les identifiants du vendeur et du produit seront insuffisants pour cibler un seul appareil. Dans cette situation, il peut être possible d'utiliser ce paramètre pour spécifier un numéro de série qui doit également correspondre.

Si un seul numéro de série est spécifié, alors le même numéro de série est utilisé en mode d'exécution et en mode DFU. Un numéro de série vide correspondra à n'importe quel numéro de série dans le mode correspondant.

-t, --taille-transfert TAILLE
Spécifie le nombre d'octets par transfert USB. La valeur optimale est généralement déterminée automatiquement, donc cette option est rarement utile. Si vous devez utiliser cette option pour un appareil, veuillez la signaler comme un bug.
-Z, --taille-upload TAILLE
Spécifie la taille de téléversement attendue, en octets. Notez que la valeur est seulement utilisée pour mettre à l'échelle la barre de progression, la taille réelle du téléversement est déterminée par l'appareil.
-U, --upload FICHIER
Lit le firmware depuis l'appareil vers FICHIER.
-D, --download FICHIER
Écrit le firmware depuis FICHIER vers l'appareil. Lorsque FICHIER est -, le firmware est lu depuis stdin.
-R, --reset
Émet un signal de réinitialisation USB après la fin du téléversement ou du téléchargement.
-e, --detacher
Demande à l'appareil de se ré-énumérer hors du mode d'exécution et en mode DFU comme lors du téléversement ou du téléchargement, mais sort immédiatement après l'envoi de la requête.
-E, --delai-detachement SECONDES
Lors du téléversement ou du téléchargement, attend SECONDES pour que l'appareil se ré-énumère après l'envoi de la demande de détachement avant d'abandonner. La valeur par défaut est 5 secondes. Cette option n'a aucun effet avec -e, car cela fait que dfu-util sort immédiatement après l'envoi de la demande de détachement.
-w, --attendre
Attend que l'appareil correspondant apparaisse sur le bus USB.
-s, --adresse-dfuse [ADRESSE][:LONGUEUR][:MODIFICATEURS]
Spécifie l'adresse cible pour le téléchargement/téléversement binaire brut sur les appareils DfuSe. N'utilisez PAS cette option pour télécharger des fichiers DfuSe (.dfu). Une longueur peut être spécifiée pour les téléversements. Des modificateurs peuvent être ajoutés après l'adresse, séparés par un deux-points, pour exécuter des commandes spéciales DfuSE telles que sortir du mode DFU ("leave"), "déverrouiller" ("unprotect") et "effacer-en-masse" ("mass-erase") la mémoire flash. Si l'appareil peut être amené à se réinitialiser lui-même après l'opération, "will-reset" devrait être ajouté. Le modificateur "force" remplacera certaines vérifications de sécurité, et est également nécessaire pour les opérations "unprotect" et "mass-erase".
-v, --verbeux
Affiche plus d'informations sur le fonctionnement de dfu-util. Un deuxième -v ajoute plus de détails. Un troisième -v active la journalisation verbeuse des requêtes USB (sortie de débogage libusb).
-h, --aide
Affiche un texte d'aide et quitte.
-V, --version
Affiche les informations de version et quitte.

dfu-util(1) - Arch Linux man pages

NAME

dfu-util

utility for the Downloader Protocol

SYNOPSIS

dfu-util

[OPTIONS...]

DESCRIPTION

dfu-util is a cross-platform software program designed to allow users to download and upload files to and from devices that are programmed using the USB Implementers Forum specification, which is commonly referred to as the Device Firmware Upgrade Specification.

The DFU specification can be obtained from the USB web site.

dfu-util supports plain DFU devices (DFU 1.0 and DFU 1.1) as well as DfuSe devices from STMicroelectronics.

OPTIONS

The behavior of dfu-util is determined by various command line options.

Options for device selection:

-l
--list
List all DFU capable devices attached to the system.
-d vid[:pid]
--device vid[:pid]
Select a device by Vendor ID (VID) and optionally Product ID (PID). If PID is omitted, the first device with the matching VID is chosen.
-i interface_number
--interface interface_number
Select a DFU interface number. DFU interfaces are usually numbered starting from 0.
-a alt_setting_number
--alt-iface alt_setting_number
Select an alternate DFU interface setting number. The meaning of alternate settings depends on the device. For OpenMoko devices, the default setting is usually the one for the DFU protocol, and other settings might be used for copying data into RAM. For example, setting 0 is often used for downloading arbitrary data into RAM.

Options for file transfer:

-D file
--download file
Download file to the DFU device. The file is expected to be in a format suitable for the device. For some devices, this means a raw binary file, for others a specific format like openmoko-devel-image.jffs2.
-U file
--upload file
Upload a file from the DFU device and save it to file.

Options for specifying memory addresses and sizes:

-s spec
--set-address spec
Specify the address and optionally size of the memory region for download or upload operations. The spec format is address[:size][:leave]. The address is a hexadecimal number. The optional size is a decimal number of bytes. If size is omitted, it defaults to the size of the file being transferred. The optional keyword leave tells dfu-util to detach from the device after the operation is completed (if the device supports it).

Other options:

-R
--detach
Request the DFU device to detach from the USB bus and re-enumerate. This is often required after flashing firmware to make the device reboot into the new firmware.
-s spec
--set-address spec
See above. The leave keyword in the address specification implicitly performs a detach.
-v
--verbose
Enable verbose output. This option can be repeated for increased verbosity.
-h
--help
Show a help message and exit.
-V
--version
Show program information and exit.

EXAMPLES

Using dfu-util with OpenMoko devices

Flashing the rootfs:
$ dfu-util -a rootfs -R -D /path/to/openmoko-devel-image.jffs2

Flashing the kernel:
$ dfu-util -a kernel -R -D /path/to/uImage

Flashing the bootloader:
$ dfu-util -a u-boot -R -D /path/to/u-boot.bin

Copying a kernel into RAM:
$ dfu-util -a 0 -R -D /path/to/uImage

Once this has finished, the kernel will be available at the default load address of 0x32000000 in Neo1973 RAM. Note: You cannot transfer more than 2MB of data into RAM using this method.

Using dfu-util with a DfuSe device

Flashing a .dfu (special DfuSe format) file to the device:
$ dfu-util -D /path/to/dfuse-image.dfu

Reading out 1 KB of flash starting at address 0x8000000:
$ dfu-util -a 0 -s 0x08000000:1024 -U newfile.bin

Flashing a binary file to address 0x8004000 of device memory and ask the device to leave DFU mode:
$ dfu-util -a 0 -s 0x08004000:leave -D /path/to/image.bin

HISTORY

dfu-util was originally written for the OpenMoko project by Weston Schmidt <weston_schmidt@yahoo.com> and Harald Welte <hwelte@hmw-consulting.de>. Over time, nearly complete support of DFU 1.0, DFU 1.1 and DfuSe ("1.1a") has been added.
