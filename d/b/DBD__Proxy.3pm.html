DESCRIPTIO

N

DBD::Proxy est un module Perl pour se connecter à une base de données via un pilote DBI distant. Voir DBD::Gofer pour une alternative avec des compromis

différents.

Ceci n'est bien sûr pas nécessaire pour les pilotes DBI qui prennent déjà en charge la connexion à une base de données distante, mais il existe des moteurs qui n'offrent pas de connectivité

réseau.

Une autre application est l'offre d'accès à la base de données à travers un pare-feu, car le pilote offre des restrictions basées sur les requêtes. Par exemple, vous pouvez restreindre les requêtes à exactement celles qui sont utilisées dans une application CGI

donnée.

En parlant de CGI, une autre application est (ou plutôt, sera) de réduire la surcharge de connexion/déconnexion à la base de données des scripts CGI en utilisant

le proxying de la méthode connect_cached. Le serveur proxy maintiendra les connexions à la base de données ouvertes dans un cache. Le script CGI échange alo
rs la surcharge de connexion/déconnexion à la base de données pour la surcharge de connexion/déconnexion de DBD::Proxy qui est généralement beaucoup moindre.

CONNEXION À LA BASE DE

DONNÉES

Avant de vous connecter à une base de données distante, vous devez vous assurer qu'un serveur Proxy est en cours d'exécution sur la machine distante. Il n'y a pas de port par défaut, donc vous devez demander le numéro de port à votre administrateur système. Voir DBI::ProxyServer pour les

détails.

Disons que votre serveur Proxy est en cours d'exécution sur la machine "alpha", port 3334, et que vous souhaitez vous connecter à une base de données ODBC appelée "mydb" en tant qu'utilisateur "joe" avec le mot de passe "hello". Lors de l'utilisation directe de DBD::ODBC, vous

feriez 
$dbh = DBI->connect("DBI:ODBC:mydb", "joe", "hello")
;

Avec DBD::Proxy, cela

devient 
$dsn = "DBI:Proxy:hostname=alpha;port=3334;dsn=DBI:ODBC:mydb";
$dbh = DBI->connect($dsn, "joe", "hello")
;

Vous voyez, c'est principalement la même chose. Le module DBD::Proxy va créer une connexion au serveur Proxy sur "alpha" qui à son tour se connectera à la base de données

ODBC.

Consultez la documentation DBI sur la méthode "connect" pour une façon d'utiliser automatiquement DBD::Proxy sans avoir à modifier votre

code.

PROBLÈMES

CONNUS

Appels de méthodes non

proxifiés

Si une méthode n'est pas proxifiée, essayez de déclarer un sous-programme stub dans le paquet approprié (DBD::Proxy::db pour une méthode dbh, et DBD::Proxy::st pour une méthode sth). Par exemple

: 
sub DBD::Proxy::db::selectall_arrayref
;

Cela permettra à selectall_arrayref d'être

proxifié.

Actuellement, de nombreuses méthodes ne sont pas explicitement proxifiées et vous obtenez donc l'exécution des méthodes par défaut du DBI sur le

client.

Certaines de ces méthodes, comme selectall_arrayref, peuvent ensuite appeler d'autres méthodes qui sont proxifiées (selectall_arrayref appelle fetchall_arrayref qui appelle fetch qui est proxifié). Ainsi, les choses peuvent sembler fonctionner mais fonctionner plus lentement qu'elles ne le

pourraient.

Tout cela peut ch

anger dans une ve
rsion ultérieure.

Attributs de gestionnaire

complexes

Parfois, les gestionnaires ont des attributs complexes comme des références de hachage ou des références de tableau et non des chaînes ou des entiers simples. Par exemple, avec DBD::CSV, vous voudriez écrire quelque chose

comme 
$dbh->{"csv_tables"}->{"passwd"} =
      { "sep_char" => ":", "eol" =>
"\n";

L'exemple ci-dessus indiquerait au pilote CSV de supposer que le fichier "passwd" est au format du fichier /etc/passwd : Deux-points comme séparateurs et un saut de ligne sans retour à la ligne comme terminateur de

ligne.

Étonnamment, cet exemplene fonctionne pas avec le pilote proxy. Pour comprendre les raisons, vous devriez considérer ce qui suit : le compilateur Perl exécute l'exemple ci-dessus en deux étapes

:
1
.
La première étape consiste à récupérer la valeur de la clé "csv_tables" dans le handle $dbh. La valeur retournée est complexe, une référence de
hachage.
2
.
La deuxième étape consiste à stocker une certaine vale
ur (le côté droit de l'affectation) comme clé "
passwd" dans la référence de hachage de l'étape 1.

Cela devient un peu plus clair si nous réécrivons le code ci-dessus

: 
$tables = $dbh->{"csv_tables"};
$tables->{"passwd"} = { "sep_char" => ":", "eol" =>
"\n";

Bien que les exemples fonctionnent correctement sans le proxy, ils échouent en raison d'une différence subtile à l'étape 1 : grâce à la magie de DBI, la référence de hachage $dbh->{'csv_tables'} est renvoyée du serveur au client. Le client crée une copie locale. Cette copie locale est le résultat de l'étape 1. En d'autres termes, l'étape 2 modifie une copie locale de la référence de hachage, mais pas la référence de hachage du

serveur.

La solution consiste à stocker la copie locale modifiée sur le serveur

: 
$tables = $dbh->{"csv_tables"}
; $tables->{"passwd"} = { "sep
_char" => ":", "eol" => "\n"; $
dbh->{"csv_tables"} = $tables;
