NOM

db2x_texixml - Crée des fichiers Texinfo à partir de Texi-XML

SYNOPSIS


db2x_texixml
[options]... [xml-document]

DESCRIPTION

db2x_texixml convertit un document Texi-XML en un ou plusieurs documents Texinfo.

Si xml-document n'est pas spécifié, le document à convertir provient de l'entrée standard.

Les noms de fichiers des documents Texinfo sont déterminés par le balisage dans la source Texi-XML. (Si les noms de fichiers ne sont pas spécifiés dans le balisage, alors db2x_texixml tente de les déduire du nom du fichier d'entrée. Cependant, la source Texi-XML devrait spécifier le nom de fichier, car cela ne fonctionne pas lorsqu'il y a plusieurs fichiers de sortie ou lorsque la source Texi-XML provient de l'entrée standard.)

OPTIONS

--encoding=encoding
Sélectionne l'encodage de caractères utilisé pour les fichiers de sortie. Les encodages disponibles sont ceux de iconv(1). L'encodage par défaut est us-ascii.

La source XML peut contenir des caractères qui ne sont pas représentables dans l'encodage que vous sélectionnez ; dans ce cas, le programme plantera pendant le traitement, et vous devriez choisir un autre encodage. (Cela ne se produit pas avec un encodage Unicode tel que UTF-8, mais malheureusement tout le monde n'est pas capable de traiter des textes Unicode.)

Si vous utilisez la version GNU de iconv(1), vous pouvez ajouter //TRANSLIT à la fin du nom de l'encodage pour tenter des translittérations de tout caractère non convertible dans la sortie. Attention cependant, les caractères réellement inconvertibles seront transformés en un autre de ces maudits points d'interrogation. (N'en avez-vous pas assez ?)

Le suffixe //TRANSLIT appliqué à un encodage Unicode — en particulier utf-8//TRANSLIT — signifie que les fichiers de sortie doivent rester en Unicode, mais que les traductions de caractères au niveau du balisage utilisant utf8trans doivent toujours être effectuées. Ainsi, dans la plupart des cas, un document en anglais, converti avec --encoding=utf-8//TRANSLIT finira en réalité par être un document US-ASCII, mais tout caractère non traduisible restera en UTF-8 sans aucun avertissement. (Remarque : à proprement parler, ceci n'est pas une « translittération ».) Cette méthode de conversion est un compromis par rapport au traitement strict --encoding=us-ascii , qui s'interrompt si des caractères non traduisibles sont rencontrés.

Notez que les pages man et les documents Texinfo dans des encodages non ASCII (y compris UTF-8) peuvent ne pas être portables sur des systèmes plus anciens (non internationalisés), c'est pourquoi la valeur par défaut de cette option est us-ascii.

Pour supprimer toute correspondance automatique de caractères ou conversion d'encodage quelconque, passez l'option --encoding=utf-8.

--list-files
Écrit une liste de tous les fichiers de sortie sur la sortie standard, en plus du traitement normal.
--output-dir=dir
Spécifie le répertoire où les fichiers de sortie sont placés. La valeur par défaut est le répertoire de travail courant.

Cette option est ignorée si la sortie doit être écrite sur la sortie standard (déclenchée par l'option --to-stdout).

--to-stdout
Écrit la sortie sur la sortie standard au lieu de fichiers individuels.

Si cette option est utilisée même lorsqu'il devrait y avoir plusieurs documents de sortie, alors tout est concaténé sur la sortie standard. Mais attention, la plupart des autres programmes n'accepteront pas cette sortie concaténée.

Cette option est incompatible avec --list-files, évidemment.

--info
Envoie la sortie Texinfo à makeinfo(1), créant directement des fichiers Info au lieu de fichiers Texinfo.
--plaintext
Envoie la sortie Texinfo à makeinfo --no-headers, créant ainsi des fichiers texte brut.
--help
Affiche un bref résumé de l'utilisation et se termine.
--version
Affiche la version et se termine.

Ce programme utilise certains autres programmes pour son fonctionnement. S'ils ne sont pas à leurs emplacements d'installation par défaut, utilisez les options suivantes pour définir leur emplacement :

--utf8trans-program=path, --utf8trans-map=charmap
Utilise la table de caractères charmap avec le programme utf8trans(1) , inclus avec docbook2X, trouvé sous path.
--iconv-program=path
L'emplacement du programme iconv(1) , utilisé pour les conversions d'encodage.

NOTES

Compatibilité du langage Texinfo. Les fichiers Texinfo générés par db2x_texixml nécessitent parfois la version 4.7 de Texinfo (la dernière version) pour fonctionner correctement. En particulier :

•
db2x_texixml s'appuie sur makeinfo pour ajouter automatiquement une ponctuation après un @ref si elle n'est pas déjà là. Sinon, le lien hypertexte ne fonctionnera pas dans le lecteur Info (bien que makeinfo n'émettra aucune erreur).
•
La nouvelle commande @comma{} est utilisée pour les virgules (,) survenant dans des listes d'arguments de commandes Texinfo, pour lever l'ambiguïté avec la virgule utilisée pour séparer différents arguments. La seule alternative sinon serait de traduire , en . ce qui est évidemment indésirable (mais les versions antérieures de docbook2X faisaient cela).

Si vous ne pouvez pas utiliser la version 4.7 de makeinfo, vous pouvez toujours utiliser un script sed pour effectuer manuellement la procédure décrite ci-dessus.

Relation entre Texi-XML et le format de sortie XML de makeinfo. Le format Texi-XML utilisé par docbook2X est différent et incompatible avec le format XML généré par makeinfo(1) avec son --xml option. Cette situation est en partie due au fait que le format Texi-XML de docbook2X a été conçu et implémenté indépendamment avant l'apparition du format XML de makeinfo. De plus, Texi-XML est très orienté vers la génération machine à partir d'autres formats XML, alors qu'il semble ne pas y avoir d'applications non triviales du makeinfoformat XML. Il n'y a donc pas de raison à ce stade pour que docbook2X adopte le makeinfoformat XML au lieu de Texi-XML.

BOGUES

•
Le retour à la ligne dans les menus est complètement cassé pour le texte non ASCII. C'est probablement aussi cassé partout ailleurs dans la sortie, mais ce serait la faute de makeinfo.
•
--list-files pourrait ne pas fonctionner correctement avec --info. Plus précisément, lorsque le fichier Info de sortie devient trop gros, makeinfo décidera de le diviser en parties nommées abc.info-1, abc.info-2, abc.info-3, etc. db2x_texixml ne sait pas exactement combien de fichiers de ce type il y a, mais vous pouvez simplement faire un ls pour le savoir.
