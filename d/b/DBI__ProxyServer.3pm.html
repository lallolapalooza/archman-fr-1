De plus, le serveur vous offre des restrictions de requêtes. Suggérez la liste de clients suivante :

'clients' => [
    { 'mask' => '^admin\.company\.com$',
      'accept' => 1,
      'users' => [ 'root', 'wwwrun' ],
    },
    {
      'mask' => '^admin\.company\.com$',
      'accept' => 1,
      'users' => [ 'root', 'wwwrun' ],
      'sql' => {
           'select' => 'SELECT * FROM foo',
           'insert' => 'INSERT INTO foo VALUES (?, ?, ?)'
           }
    }

alors seuls les utilisateurs root et wwwrun peuvent se connecter depuis admin.company.com, en exécutant des requêtes arbitraires, mais seul wwwrun peut se connecter depuis d'autres hôtes et est limité à

$sth->prepare("select");

ou

$sth->prepare("insert");

qui sont en fait "SELECT * FROM foo" ou "INSERT INTO foo VALUES (?, ?, ?)".

Serveur proxy Fichier de configuration (plus grand exemple)

Cette section vous indique comment restreindre un DBI-Proxy : tous les utilisateurs de tous les postes de travail ne doivent pas pouvoir exécuter toutes les requêtes.

Il existe un programme perl "dbiproxy" qui s'exécute sur une machine capable de se connecter à toutes les bases de données que nous souhaitons atteindre. Tous les pilotes Perl-DBD doivent être installés sur cette machine. Vous pouvez également atteindre des bases de données pour lesquelles les pilotes ne sont pas disponibles sur la machine où vous exécutez le programme interrogeant la base de données, par exemple interroger une base de données MS-Access depuis Linux.

Créez un fichier de configuration "proxy_oracle.cfg" sur le serveur dbproxy :

{
    # Cela doit s'exécuter dans un shell ou une fenêtre DOS
    # facility => 'daemon',
    pidfile => 'your_dbiproxy.pid',
    logfile => 1,
    debug => 0,
    mode => 'single',
    localport => '12400',
    # Contrôle d'accès, la première correspondance dans cette liste gagne !
    # L'ordre est donc important
    clients => [
            # indice pour organiser :
            # les règles les plus spécialisées pour les machines/utilisateurs individuels sont en 1er
            # puis les règles de refus
            # puis les règles concernant les réseaux entiers
            # règle : internal_webserver
            # desc : pour obtenir des informations statistiques
            {
                    # seule cette adresse IP est visée
                    mask => '^10\.95\.81\.243$',
                    # accepter (ne pas différer) les connexions comme celle-ci
                    accept => 1,
                    # seuls les utilisateurs de cette liste
                    # sont autorisés à se connecter
                    users => [ 'informationdesk' ],
                    # seule cette requête statistique est autorisée
                    # pour obtenir les résultats d'une requête web
                    sql => {
                            alive => 'select count(*) from dual',
                            statistic_area => 'select count(*) from e01admin.e01e203 where geb_bezei like ?',
                    }
            },
            # règle : internal_bad_guy_1
            {
                    mask => '^10\.95\.81\.1$',
                    accept => 0,
            },
            # règle : employee_workplace
            # desc : obtenir des informations détaillées
            {
                    # toute adresse IP est visée ici
                    mask => '^10\.95\.81\.(\d+)$',
                    # accepter (ne pas différer) les connexions comme celle-ci
                    accept => 1,
                    # seuls les utilisateurs de cette liste
                    # sont autorisés à se connecter
                    users => [ 'informationdesk', 'lippmann' ],
                    # toutes ces requêtes sont autorisées :
                    sql => {
                            search_city => 'select ort_nr, plz, ort from e01admin.e01e200 where plz like ?',
                            search_area => 'select gebiettyp, geb_bezei from e01admin.e01e203 where geb_bezei like ? or geb_bezei like ?',
                    }
            },
            # règle : internal_bad_guy_2
            # Cela ne FONCTIONNE PAS, car la règle "employee_workplace" correspond
            # avec son masque d'adresse IP couvrant tout le réseau
            {
                    # ne pas accepter la connexion depuis cette adresse IP
                    mask => '^10\.95\.81\.5$',
                    accept => 0,
            }
    ]
}

Démarrez le serveur proxy comme ceci :

rem well-set Oracle_home needed for Oracle
set ORACLE_HOME=d:\oracle\ora81
dbiproxy --configfile proxy_oracle.cfg

Test de la connexion avec un script perl

Créez un script perl comme ceci :

# file: oratest.pl
# call me like this: perl oratest.pl user password
use strict;
use DBI;
my $user = shift || die "Usage: $0 user password";
my $pass = shift || die "Usage: $0 user password";
my $config = {
        dsn_at_proxy => "dbi:Oracle:e01",
        proxy => "hostname=oechsle.zdf;port=12400",
};
my $dsn = sprintf "dbi:Proxy:%s;dsn=%s",
        $config->{proxy},
        $config->{dsn_at_proxy};
my $dbh = DBI->connect( $dsn, $user, $pass )
        || die "connect did not work: $DBI::errstr";
my $sql = "search_city";
printf "%s\n%s\n%s\n", "="x40, $sql, "="x40;
my $cur = $dbh->prepare($sql);
$cur->bind_param(1,'905%');
&show_result ($cur);
my $sql = "search_area";
printf "%s\n%s\n%s\n", "="x40, $sql, "="x40;
my $cur = $dbh->prepare($sql);
$cur->bind_param(1,'Pfarr%');
$cur->bind_param(2,'Bronnamberg%');
&show_result ($cur);
my $sql = "statistic_area";
printf "%s\n%s\n%s\n", "="x40, $sql, "="x40;
my $cur = $dbh->prepare($sql);
$cur->bind_param(1,'Pfarr%');
&show_result ($cur);
$dbh->disconnect;
exit;
sub show_result {
        my $cur = shift;
        unless ($cur->execute()) {
                print "Could not execute\n";
                return;
        }
        my $rownum = 0;
        while (my @row = $cur->fetchrow_array()) {
                printf "Row is: %s\n", join(", ",@row);
                if ($rownum++ > 5) {
                        print "... and so on\n";
                        last;
                }
        }
        $cur->finish;
}

Comment la configuration fonctionne

La section la plus importante pour contrôler l'accès à votre dbi-proxy est "client=>" dans le fichier "proxy_oracle.cfg" :

Contrôler quelle personne sur quelle machine est autorisée à accéder

  • "mask" est une expression régulière perl appliquée à l'adresse ip brute de la machine qui souhaite se connecter _ou_ au résultat de la recherche inverse depuis un serveur de noms.
  • "accept" indique au serveur dbiproxy si les adresses ip comme dans "mask" sont autorisées à se connecter ou non (0/1)
  • "users" est une référence à une liste de noms d'utilisateurs qui doivent correspondre, ceci N'EST PAS une expression régulière.

Contrôler quelles instructions SQL sont autorisées

Vous pouvez mettre n'importe quelle instruction SQL que vous voulez en omettant simplement "sql => ...", mais la chose la plus importante est de restreindre la connexion pour que seules les requêtes autorisées soient possibles.

Si vous incluez une section sql dans votre fichier de configuration comme ceci :

sql => {
        alive => 'select count(*) from dual',
        statistic_area => 'select count(*) from e01admin.e01e203 where geb_bezei like ?',
}

L'utilisateur est autorisé à effectuer deux requêtes contre le dbi-proxy. Les requêtes ne sont _pas_ "select count(*)...", les requêtes sont "alive" et "statistic_area" ! Ces mots-clés sont remplacés par la requête réelle. Ainsi vous pouvez lancer une requête pour "alive" :

my $sql = "alive";
my $cur = $dbh->prepare($sql);
...

La flexibilité réside dans le fait que vous pouvez mettre des paramètres dans la partie where de la requête afin que les requêtes ne soient pas statiques. Remplacez simplement une valeur dans la partie where de la requête par un point d'interrogation et liez-la comme paramètre à la requête.

my $sql = "statistic_area";
my $cur = $dbh->prepare($sql);
$cur->bind_param(1,'905%');
# A second parameter would be called like this:
# $cur->bind_param(2,'98%');

Le résultat est cette requête :

select count(*) from e01admin.e01e203
where geb_bezei like '905%'

N'essayez pas de mettre des paramètres dans la requête sql comme ceci :

# Does not work like you think.
# Only the first word of the query is parsed,
# so it's changed to "statistic_area", the rest is omitted.
# You _have_ to work with $cur->bind_param.
my $sql = "statistic_area 905%";
my $cur = $dbh->prepare($sql);
...

AVERTISSEMENT DE SÉCURITÉ

RPC::PlServer utilisé en dessous n'est pas sécurisé en raison de la sérialisation et de la désérialisation des données avec le module Storable. N'utilisez le pilote proxy que dans un environnement de confiance.
