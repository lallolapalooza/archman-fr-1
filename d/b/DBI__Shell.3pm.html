NOM

DBI::Shell - Shell de commandes interactif pour le DBI

SYNOPSIS

perl -MDBI::Shell -e shell [<source de données DBI> [<utilisateur> [<mot de passe>]]]

ou

dbish [<source de données DBI> [<utilisateur> [<mot de passe>]]]
dbish --debug [<source de données DBI> [<utilisateur> [<mot de passe>]]]
dbish --batch [<source de données DBI> [<utilisateur> [<mot de passe>]]] < fichier_lot

DESCRIPTION

Le module DBI::Shell (et la commande dbish, si installée) fournit une interface en ligne de commande simple mais efficace pour le module Perl DBI.

CONFIGURATION

Le fichier de configuration (~/.dbish_config par défaut, surchargé par $DBISH_CONFIG) est évalué comme code perl et doit renvoyer une référence de hachage contenant les éléments de configuration. Les clés notables incluent

options
La valeur est une autre référence de hachage contenant les options et leurs valeurs. Tapez "/option" à l'invite pour obtenir une liste des options acceptables.
plug-ins
Plug-ins à charger. C'est plutôt une structure de données complexe qui est parcourue récursivement pour déterminer quels greffons doivent être chargés. Au niveau supérieur, on trouve les phases « pre-init », « post-init », « pre-connect », et « post-connect ». À des niveaux inférieurs, les greffons peuvent être sélectionnés par le nom du pilote de base de données, et des options individuelles peuvent être définies. Enfin, à un certain niveau, une référence de tableau contenant les noms des paquets des greffons à charger doit être trouvée.

Étant donné que le fichier de configuration peut contenir du code perl arbitraire, il peut faire tout ce qui peut être fait en perl. Un hack plutôt utile est d'appeler binmode pour définir l'encodage pour l'entrée et la sortie standard.

Exemple

binmode STDIN,  ":utf8";
binmode STDOUT, ":utf8";
{
    options => {
        format => 'partbox',
    },
    'plug-ins' => {
        'pre-init' => [
            'DBI::Shell::Timing',
            'DBI::Shell::Spool',
        ],
    },
};

Ce fichier de configuration définit d'abord la couche :utf8 pour l'entrée et la sortie afin de correspondre au terminal (si vous n'utilisez pas UTF-8, vous pourriez utiliser :encoding() ici), puis retourne la référence de hachage avec les éléments de configuration : le format est défini sur 'partbox', et les deux greffons 'DBI::Shell::Timing' et 'DBI::Shell::Spool' sont chargés.

AUTEURS et REMERCIEMENTS

DBI::Shell a une longue lignée.

Il a commencé sa vie vers 1994-1997 sous la forme du script pmsql écrit par Andreas König. Jochen Wiedmann l'a repris et l'a fait évoluer (en ajoutant beaucoup au passage) sous la forme de dbimon, inclus avec ses modules pilotes DBD::mSQL. En 1998, au moment où je voulais inclure un shell avec le DBI, Adam Marks travaillait sur un dbish modélisé après l'utilitaire sqsh de Sybase.

Souhaitant partir d'une base plus propre que le dbimon complet mais complexe, j'ai travaillé avec Adam pour créer un module DBI::Shell modulaire et très configurable, assez ouvert. En chemin, Tom Lowery a apporté des idées et des correctifs. À mesure que nous avancerons, du code et des concepts plus utiles du dbimon de Jochen trouveront certainement leur chemin en retour.
