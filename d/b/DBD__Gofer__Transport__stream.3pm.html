NOM

DBD::Gofer::Transport::stream - Transport DBD::Gofer pour le streaming stdio

SYNTAXE

DBI->connect('dbi:Gofer:transport=stream;url=ssh:username@host.example.com;dsn=dbi:...',...)

ou, activez en définissant la variable d'environnement DBI_AUTOPROXY:

export DBI_AUTOPROXY='dbi:Gofer:transport=stream;url=ssh:username@host.example.com'

DESCRIPTION

Sans le paramètre "url=", il lance un sous-processus comme

perl -MDBI::Gofer::Transport::stream -e run_stdio_hex

et lui envoie des requêtes et en lit les réponses. Mais ce n'est pas très utile.

Avec un paramètre "url=ssh:username@host.example.com", il utilise ssh pour lancer le sous-processus sur un système distant. C'est beaucoup plus utile !

Cela vous donne un accès sécurisé à distance aux bases de données DBI sur n'importe quel système auquel vous pouvez vous connecter. L'utilisation de ssh offre également une compression optionnelle et de nombreuses autres fonctionnalités (voir le manuel de ssh pour savoir comment configurer cela et de nombreuses autres options via le fichier ~/.ssh/config).

La commande réelle invoquée est quelque chose comme:

ssh -xq ssh:username@host.example.com bash -c $setup $run

où $run est la commande montrée ci-dessus, et $command est

. .bash_profile 2>/dev/null || . .bash_login 2>/dev/null || . .profile 2>/dev/null; exec "$@"

ce qui tente (d'une manière limitée et assez non portable) de configurer l'environnement (PATH, PERL5LIB etc) tel qu'il serait si vous vous étiez connecté à ce système.

Le ""perl"" utilisé dans la commande sera par défaut la valeur de $^X lorsqu'il n'utilise pas ssh. Sur la plupart des systèmes, il s'agit du chemin complet vers le perl en cours d'exécution.

PERSISTANCE

Actuellement, les connexions gofer stream persistent (restent connectées) une fois que tous les descripteurs de base de données ont été déconnectés. Cela rend les connexions ultérieures dans le même processus très rapides.

Actuellement, jusqu'à 5 connexions gofer stream différentes (basées sur l'URL) peuvent persister. Si plus de 5 sont dans le cache lorsqu'une nouvelle connexion est établie, le cache est vidé avant d'ajouter la nouvelle connexion. Simple mais efficace.

À FAIRE

Documenter l'attribut go_perl

Reconnecter automatiquement (dans la mesure du possible) en cas d'erreur de transport.

Décider de la valeur par défaut pour la connexion persistante - activée ou désactivée ? limites ? ttl ?
