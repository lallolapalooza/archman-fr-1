dbmail-imapd - fournit l'accès au système DBMail aux clients

prenant en charge le protocole IMAP (Internet Message Acce
ss Protocol, IMAP4r1), tel que spécifié dans la RFC 3501.

SYNOPSI

S 
dbmail-imapd [--config fichier_de_configuration] [--pidfile fichier_pid]
dbmail
-imapd [--config fichier_de_configuration] [--pidfile fichier_pid] --no-daemon d
bmail-imapd [--config fichier_de_configuration] [--pidfile fichier_pid] --inetd

DESCRIPTIO

N

Le démon dbmail-imapd e

st un serveur IMAP4r1 e
ntièrement fonctionnel.

OPTION

S

-p, --pidfile

fichier_pid
Spécifie un fichier pid alternatif. Par défaut, les démons utilisent dbmail-<demon>.pid pour leurs fichiers pid, les enregistrant dans le répertoire spécifié par l'entrée pid_directory dans dbmail.conf ou, si celui-ci n'existe pas, la valeur définie par l'option de configuration --localstatedir, et ils s'arrêteront si le fichier pid ne peut pas être écrit. Utilisez l'option -p fichier_pid pour placer le fichier pid à l'emplacement préféré de votre
système.

-n,

--no-daemon
Pas de mise en démon : mode inetd. Le programme reste attaché à la console à partir de laquelle il a été lancé et lira et écrira sur stdin/stdout. Cela est utile pour le débogage lorsqu'il est combiné avec l'option -v. Il est également utilisé pour l'exécution depuis (x)
inetd.

-D,

--inetd
Pas de mise en démon : Le programme reste attaché à la console et
écoutera sur les sockets réseau définis dans dbmail.conf. C'est pri
ncipalement utilisé pour xinetd (Extended Internet Service Daemon)

OPTIONS

COMMUNES

-f, --config fichier_de_configurati

on
Spécifie un fichier de configuration alternatif.

Utilisez dbmail-<utilitair

e> --help pour afficher l
'emplacement par défaut.

-q,

--quiet
Ignore silencieusement les invites interactives et les messages d'état utiles qui seraient autrement imprimés sur stdout. Utilisez deux -q pour faire taire les erreurs qui seraient autrement imprimées sur
stderr.

-v,

--verbose
Fonctionner de manière verbeuse. Certains des utilitaires de la suite DBMail peuvent accepter deux -v pour une verbosité supplémentaire. Ceux qui ne comprennent pas cette convention ne se plaindront pas d'avoir le -v supplémentaire et fonctionneront simplement à leur verbosité
normale.

-V,

--version
Affiche la version et le copyright, puis
quitte.

-h,

--help
Affiche un bref
résumé des optio
ns, puis quitte.

EXEMPL

E

Pour xinetd

: 
-----------------------------------------------------------
# /etc/xinet.d/dbmail-imap
#
service imap
{
        socket_type     = stream
        wait            = no
        user            = root
        server          = /usr/local/sbin/dbmail-imapd
        protocol        = tcp
        server_args     = -n
        log_on_failure  += USERID
        disable         = no
}
---------------------------------------------------------

Pour stunnel

: 
-----------------------------------------------------------
pid = /var/run/stunnel.pid
cert = /etc/stunnel/yourkeys.pem
# Les deux sections suivantes transformeront stunnel
# en un 'inetd sécurisé'. Cela est mutuellement
# exclusif avec les sections proxy ci-dessous.
[dbmail-pop3d]
accept = 995
exec = /usr/local/sbin/dbmail-pop3d
execargs = dbmail-pop3d -n
[dbmail-imapd]
accept = 993
exec = /usr/local/sbin/dbmail-imapd
execargs = dbmail-imapd -n
# Les deux sections suivantes feront un proxy
# du protocole sécurisé vers le
# protocole non sécurisé. Dans ce cas,
# utilisez BINDIP=localhost dans dbmail.conf !
[pop3s]
accept  = 995
connect = 110
[imaps]
accept  = 993
connect = 143
# Utile si votre serveur SMTP préféré ne fait pas SSL/TLS.
# Cela concerne votre configuration MTA, pas DBMail en soi.
[ssmtp]
accept  = 465
connect = 25
