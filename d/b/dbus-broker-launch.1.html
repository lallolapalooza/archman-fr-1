NOM

dbus-broker-launch - Lanceur pour les brokers de messages D-Bus

SYNOPSIS

dbus-broker-launch [ OPTIONS ]
dbus-broker-launch --version
dbus-broker-launch --help

DESCRIPTION

dbus-broker-launch est un lanceur pour dbus-broker, qui démarre et gère un bus de messages D-Bus. Le lanceur vise à être entièrement compatible avec l'implémentation de référence de D-Bus, dbus-daemon(1), en supportant la même syntaxe de configuration et l'environnement d'exécution.

Chaque instance de dbus-broker-launch gère exactement un bus de messages. Chaque bus de messages est indépendant. Le fichier de configuration peut être spécifié via la ligne de commande, ou bien le fichier par défaut est choisi dans /usr/share/dbus-1/. Presque tous les attributs de configuration sont supportés. Voir dbus-daemon(1) pour les détails sur la syntaxe de configuration.

OPTIONS

Les options de ligne de commande suivantes sont supportées. Si une option qui n'est pas listée ici est passée, le lanceur refusera le démarrage et sortira avec une erreur.

-h, --help
affiche les informations d'utilisation et quitte immédiatement
--version
affiche la version de compilation et quitte immédiatement
--audit
active la journalisation vers le sous-système d'audit Linux (sans effet si le support d'audit n'a pas été compilé ; Par défaut : désactivé)
--config-file=PATH
fichier de configuration à utiliser (Par défaut : /usr/share/dbus-1/{system,session}.conf)
--scope=SCOPE
sélectionne le scope dans lequel exécuter (un parmi : system, user ; Par défaut : system)

JOURNALISATION

Par défaut, dbus-broker-launch enregistre les messages dans le journal système. Les messages sont enrichis de nombreuses métadonnées, assurez-vous donc de vérifier les champs supplémentaires du journal. Le message de journal lisible par l'homme est intentionnellement court.

Au démarrage et à l'arrêt, le lanceur enregistre des messages initiaux qui contiennent des informations sur les fichiers de configuration et les définitions de service analysés. Aucun autre message de journal n'est généré, sauf ceux provenant de dbus-broker(1).

SCOPE

Contrairement à dbus-daemon(1), dbus-broker-launch active toutes les services en tant qu'unités systemd. Les services qui viennent déjà avec une unité systemd sont activés comme d'habitude, mais les services qui n'ont pas d'unité systemd sont activés en tant qu'unité transitoire, avec un fichier d'unité ad hoc généré à l'exécution. Cela garantit que tous les services s'exécutent dans un environnement bien défini.

Le paramètre --scope définit quelle instance systemd le lanceur doit utiliser pour activer les services. Dans le cas de system, le lanceur utilisera l'instance système de systemd. Dans le cas de user, l'instance utilisateur est utilisée à la place.

De plus, le scope sélectionné définit également quel fichier de configuration est utilisé si aucun n'est spécifié sur la ligne de commande.

Le scope sélectionné n'a aucun autre effet. Il est seulement nécessaire pour définir l'environnement d'activation des définitions de service chargées. S'il n'y a pas de services activables déclarés, le scope n'aura aucun effet.

SOCKETS

Le socket pour écouter les connexions client doit être créé et passé à dbus-broker-launch par son processus parent. Le protocole doit suivre l'activation par socket telle que définie par systemd.socket(1). Un seul socket est supporté pour le moment.

Les attributs supplémentaires <listen>%path%</listen> dans la configuration sont ignorés.

PRIVILÈGES

Le lanceur a besoin d'un accès en lecture à son fichier de configuration. En dehors de cela, aucun privilège n'est nécessaire. Si l'attribut de configuration <user>%user%</user> est utilisé, le lanceur abandonnera ses privilèges lors de l'exécution de dbus-broker.

Si des services activables sont déclarés, le lanceur aura besoin d'accéder à l'instance systemd correspondante. Le lanceur doit être autorisé à démarrer des unités transitoires, ainsi qu'à gérer les unités déclarées dans les définitions de service.
