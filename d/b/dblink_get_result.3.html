NOM

dblink_get_result - récupère le résultat d'une requête asynchrone

SYNTAXE

dblink_get_result(text connname [, bool fail_on_error]) returns setof record

DESCRIPTION

dblink_get_result collecte les résultats d'une requête asynchrone envoyée précédemment avec dblink_send_query. Si la requête n'est pas encore terminée, dblink_get_result attendra jusqu'à ce qu'elle le soit.

ARGUMENTS

connname

Nom de la connexion à utiliser.

fail_on_error

Si vrai (par défaut lorsque non spécifié), une erreur survenue du côté distant de la connexion provoque également une erreur locale. Si faux, l'erreur distante est signalée localement comme une NOTICE, et la fonction ne retourne aucune ligne.

VALEUR DE RETOUR

Pour une requête asynchrone (c'est-à-dire une instruction SQL retournant des lignes), la fonction retourne la ou les lignes produites par la requête. Pour utiliser cette fonction, vous devrez spécifier l'ensemble attendu de colonnes, comme discuté précédemment pour dblink.

Pour une commande asynchrone (c'est-à-dire une instruction SQL ne retournant pas de lignes), la fonction retourne une seule ligne avec une seule colonne de type text contenant la chaîne d'état de la commande. Il est toujours nécessaire de spécifier que le résultat aura une seule colonne de type text dans la clause FROM appelante.

NOTES

Cette fonction doit être appelée si dblink_send_query a retourné 1. Elle doit être appelée une fois pour chaque requête envoyée, et une fois de plus pour obtenir un résultat vide, avant que la connexion ne puisse être réutilisée.

Lors de l'utilisation de dblink_send_query et dblink_get_result, dblink récupère l'intégralité du résultat de la requête distante avant d'en retourner une partie au processeur de requête local. Si la requête retourne un grand nombre de lignes, cela peut entraîner un gonflement de mémoire transitoire dans la session locale. Il peut être préférable d'ouvrir une telle requête comme un curseur avec dblink_open et ensuite de récupérer un nombre gérable de lignes à la fois. Alternativement, utilisez simplement dblink(), qui évite le gonflement de mémoire en mettant en mémoire tampon les grands jeux de résultats sur disque.

EXEMPLES

contrib_regression=# SELECT dblink_connect('dtest1', 'dbname=contrib_regression');
 dblink_connect
----------------
 OK
(1 row)
contrib_regression=# SELECT * FROM
contrib_regression-# dblink_send_query('dtest1', 'select * from foo where f1 < 3') AS t1;
 t1
----
  1
(1 row)
contrib_regression=# SELECT * FROM dblink_get_result('dtest1') AS t1(f1 int, f2 text, f3 text[]);
 f1 | f2 |     f3
----+----+------------
  0 | a  | {a0,b0,c0}
  1 | b  | {a1,b1,c1}
  2 | c  | {a2,b2,c2}
(3 rows)
contrib_regression=# SELECT * FROM dblink_get_result('dtest1') AS t1(f1 int, f2 text, f3 text[]);
 f1 | f2 | f3
----+----+----
(0 rows)
contrib_regression=# SELECT * FROM
contrib_regression-# dblink_send_query('dtest1', 'select * from foo where f1 < 3; select * from foo where f1 > 6') AS t1;
 t1
----
  1
(1 row)
contrib_regression=# SELECT * FROM dblink_get_result('dtest1') AS t1(f1 int, f2 text, f3 text[]);
 f1 | f2 |     f3
----+----+------------
  0 | a  | {a0,b0,c0}
  1 | b  | {a1,b1,c1}
  2 | c  | {a2,b2,c2}
(3 rows)
contrib_regression=# SELECT * FROM dblink_get_result('dtest1') AS t1(f1 int, f2 text, f3 text[]);
 f1 | f2 |      f3
----+----+---------------
  7 | h  | {a7,b7,c7}
  8 | i  | {a8,b8,c8}

 10 | k  | {a10,b10,c10}
