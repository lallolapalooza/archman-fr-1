NOM

dbus-binding-tool - utilitaire de génération de liaisons dbus-glib pour le langage C.

SYNTAXE

dbus-binding-tool [--force] [--help] [--ignore-unsupported] [--mode=pretty|glib-client|glib-server] [--output=fichier] [--prefix=préfixe-symbole] [--version] [fichier...]

DESCRIPTION

dbus-binding-tool est utilisé pour exposer un GObject via D-Bus, en utilisant la liaison obsolète dbus-glib pour GLib. En entrée, dbus-binding-tool utilise un fichier XML d'introspection D-Bus. En sortie, les liaisons côté client ou côté serveur sont générées. Cette sortie est un fichier d'en-tête qui facilite l'utilisation d'un objet D-Bus distant. La sortie est envoyée à la sortie standard ou au nom de fichier spécifié avec l'argument --output.

DESCRIPTION ÉTENDUE

Voici un exemple de fichier XML d'introspection D-Bus qui décrit un objet exposant une méthode, nommée ManyArgs:

<?xml version="1.0" encoding="UTF-8" ?>
<node name="/com/example/MyObject">
  <interface name="com.example.MyObject">
    <method name="ManyArgs">
      <arg type="u" name="x" direction="in" />
      <arg type="s" name="str" direction="in" />
      <arg type="d" name="trouble" direction="in" />
      <arg type="d" name="d_ret" direction="out" />
      <arg type="s" name="str_ret" direction="out" />
    </method>
  </interface>
</node>

dbus-binding-tool prend en charge les annotations dans le format XML pour contrôler davantage la manière dont les liaisons sont générées.

liaisons côté client

Lors de la création de liaisons côté client, l'argument --mode=glib-client est utilisé. Les liaisons côté client prennent en charge l'annotation "org.freedesktop.DBus.Glib.NoReply". Ceci est spécifié dans la balise <method> pour indiquer que le client ne s'attend pas à une réponse à l'appel de méthode, donc aucune réponse ne doit être envoyée. Ceci est souvent utilisé pour accélérer les appels de méthodes rapides où il n'y a pas d'arguments "out", et ne pas savoir si la méthode a réussi est un compromis acceptable pour réduire de moitié le trafic sur le bus. Par exemple :

<method name "FooMethod">
  [...]
  <annotation name="org.freedesktop.DBus.GLib.NoReply" value="yes"/>
  [...]
</method>

liaisons côté serveur

Lors de la création de liaisons côté serveur, l'argument --mode=glib-server est utilisé. De plus, l'argument --prefix doit être utilisé lors de la création de liaisons côté serveur afin que les fonctions dans la sortie générée soient précédées de la valeur spécifiée. Les liaisons côté serveur prennent en charge les annotations suivantes :

"org.freedesktop.DBus.GLib.CSymbol"

Cette annotation est utilisée pour spécifier les noms de symboles C pour les différents types (interface, méthode, etc.), s'ils diffèrent du nom généré par D-Bus.

<interface name="com.example.MyObject">
  <annotation name="org.freedesktop.DBus.GLib.CSymbol" value="my_object"/>
  [...]
  <method name "ManyArgs">
    <annotation name="org.freedesktop.DBus.GLib.CSymbol" value="my_object_many_args"/>
    [...]
  </method>
</interface>

"org.freedesktop.DBus.GLib.Async"

Cette annotation marque l'implémentation de la méthode comme une fonction asynchrone, qui ne renvoie pas de réponse immédiatement mais enverra la réponse plus tard pour compléter l'appel. Ceci est utilisé pour implémenter des services non bloquants où les appels de méthodes peuvent prendre du temps.

Lorsqu'une méthode est asynchrone, le prototype de la fonction est différent. Il est requis que la fonction respecte les règles suivantes :


•
La fonction doit renvoyer une valeur de type gboolean ; TRUE en cas de succès, et FALSE sinon.
•
Le premier paramètre est un pointeur vers une instance de l'objet.
•
Suivent le pointeur de l'instance de l'objet, les valeurs d'entrée de la méthode.
•
Le dernier paramètre doit être un (DBusGMethodInvocation *). Ceci est utilisé lors de l'envoi du message de réponse au client, en appelant dbus_g_method_return ou dbus_g_method_return_error.

Par exemple :

<method name "FooMethod">
  [...]
  <annotation name="org.freedesktop.DBus.GLib.Async" value="yes"/>
  [...]
</method>

"org.freedesktop.DBus.GLib.Const"

Cet attribut ne peut être appliqué qu'aux nœuds <arg> "out", et spécifie que le paramètre n'est pas copié lors du retour. Par exemple, cela transforme un argument 's' d'un (char **) en (const char **), et a pour résultat que l'argument n'est pas libéré par D-Bus après l'envoi du message. Par exemple :

  <arg type="u" name="x" direction="out">
    <annotation name="org.freedesktop.DBus.GLib.Const" value=""/>
  </arg>

"org.freedesktop.DBus.GLib.ReturnVal"

Cet attribut ne peut être appliqué qu'aux nœuds <arg> "out", et modifie la signature de la fonction attendue. Il peut actuellement être défini sur deux valeurs : "" ou "error". L'argument marqué avec cet attribut n'est pas retourné via un argument pointeur, mais par la valeur de retour de la fonction. Si la valeur de l'attribut est une chaîne vide, l'argument (GError *) est également omis, il n'y a donc pas de moyen standard de retourner une valeur d'erreur. Ceci est très utile pour l'interfaçage avec du code existant, car il est possible de correspondre à des API existantes. Si la valeur de l'attribut est "error", alors le dernier argument est un (GError *) comme d'habitude. Par exemple :

  <arg type="u" name="x" direction="out">
    <annotation name="org.freedesktop.DBus.GLib.ReturnVal" value=""/>
  </arg>

OPTIONS

Les options suivantes sont prises en charge :

--force


Écrase le fichier de sortie s'il existe déjà avec un horodatage plus récent que les fichiers source.


--help


Affiche les informations d'utilisation.


--ignore-unsupported


Si défini, les signatures non prises en charge pour les paramètres de <method> sont ignorées.


--mode=pretty|glib-client|glib-server


Si la valeur est "glib-client", des liaisons client sont générées. Si la valeur est "glib-server", des liaisons serveur sont générées. Si la valeur est "pretty", la sortie est dans un format plus lisible par l'homme.


--output=fichier


Spécifie le fichier de sortie.


--prefix=préfixe-symbole


Les fonctions dans la sortie générée sont précédées de la valeur préfixe-symbole.


--version


Affiche le numéro de version de la commande dbus-binding-tool.


OPÉRANDES

Les opérandes suivants sont pris en charge :

fichier
Une liste d'un ou plusieurs fichiers XML d'introspection D-Bus d'entrée à inclure dans la sortie générée.


FICHIERS

NOTES

dbus-binding-tool fait partie de dbus-glib, qui est un liaison D-Bus obsolète pour GLib.

dbus-glib reçoit une maintenance minimale et des correctifs de sécurité pour le bénéfice de projets comme Telepathy et NetworkManager qui en dépendent encore, mais ne devrait pas être utilisé dans de nouveaux projets (et les projets existants devraient essayer de s'en éloigner également). Veuillez utiliser GDBus, partie de GLib depuis 2.26.

gdbus-codegen(1) est le remplacement GDBus pour dbus-binding-tool.
