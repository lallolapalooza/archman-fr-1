MULTI-HOP

Dropbear permet également de spécifier plusieurs "sauts", séparés par des virgules. Dans ce cas, une connexion sera établie avec le premier hôte, puis une connexion TCP transférée sera établie à travers celui-ci vers le deuxième hôte, et ainsi de suite. Les hôtes autres que la destination finale ne verront rien d'autre que le flux SSH chiffré. Un port pour un hôte peut être spécifié avec un accent circonflexe (par ex. matt@martello^44 ). Cette syntaxe peut aussi être utilisée avec scp ou rsync (en spécifiant dbclient comme commande ssh/rsh). Un fichier peut être "rebondi" à travers plusieurs sauts SSH, par ex.

scp -S dbclient matt@martello,root@wrt,canyons:/tmp/dump .

Notez que les noms d'hôtes sont résolus par le saut précédent (ainsi "canyons" serait résolu par l'hôte "wrt") dans l'exemple ci-dessus, de la même manière que les autres hôtes transférés TCP avec -L. Les clés d'hôte sont vérifiées localement en fonction du nom d'hôte donné.

CARACTÈRES D'ÉCHAPPEMENT

Taper une nouvelle ligne suivie de la séquence de touches ~. (tilde, point) mettra fin à une connexion. La séquence ~^Z (tilde, ctrl-z) placera la connexion en arrière-plan. Ce comportement ne s'applique que lorsqu'un PTY est utilisé.

~R effectuera une renégociation des clés de session éphémères.

ENVIRONNEMENT

DROPBEAR_PASSWORD
Un mot de passe à utiliser pour l'authentification distante peut être spécifié dans la variable d'environnement DROPBEAR_PASSWORD. Il faut veiller à ce que le mot de passe ne soit pas exposé à d'autres utilisateurs sur un système multi-utilisateurs, ou stocké dans des fichiers accessibles.
SSH_ASKPASS
dbclient peut utiliser un programme externe pour demander un mot de passe à un utilisateur. SSH_ASKPASS doit être défini sur le chemin d'un programme qui renverra un mot de passe sur la sortie standard. Ce programme ne sera utilisé que si DISPLAY est défini et que l'entrée standard n'est pas un TTY, ou si la variable d'environnement SSH_ASKPASS_ALWAYS est définie.

FICHIERS

~/.ssh/dropbear_config

C'est le fichier de configuration par utilisateur. Un sous-ensemble très limité des mots-clés de ssh_config(5) est pris en charge, et aucune des fonctionnalités avancées. Le fichier contient des paires clé-valeur sur une seule ligne séparées par un espace ou '='. Les lignes vides sont ignorées. Le texte commençant par '#' est un commentaire, et est également ignoré.

Le fichier n'est pas pris en compte si une connexion multi-hop est utilisée. Les valeurs de la ligne de commande remplacent les valeurs respectives du fichier.

Les mots-clés reconnus sont les suivants. Les mots-clés ne sont pas sensibles à la casse et les valeurs ne sont pas sensibles à la casse.

Host
Définit les options qui seraient appliquées si cette valeur correspond à l'hôte spécifié sur la ligne de commande. L'entrée Host suivante ou la fin de fichier déterminent la liste des options applicables.
HostName
Spécifie le nom d'hôte réel auquel se connecter. Peut être un nom DNS ou une adresse IP.
Port
Spécifie le numéro de port à utiliser pour se connecter à l'hôte distant.
User
Spécifie le nom d'utilisateur avec lequel se connecter.
IdentityFile
Spécifie le fichier contenant la clé privée utilisée pour l'authentification par clé publique avec l'hôte distant. Le fichier doit être au format Dropbear. Voir dropbearkey(1) pour en générer un. Un '~/' au début du chemin sera développé vers le répertoire personnel de l'utilisateur qui exécute la commande. Un chemin qui ne commence pas par '/' sera traité relativement au répertoire de ce fichier de configuration. Sinon, le chemin sera utilisé tel quel.

Parce que ce fichier contient un secret, il doit avoir des permissions strictes pour empêcher les tentatives d'abus - lecture/écriture pour l'utilisateur qui exécute la commande, et aucun accès pour quiconque d'autre.

NOTES

Si compilé avec le support de zlib et si le serveur le prend en charge, dbclient utilisera toujours la compression.
