dbopen(3) Manuel des fonctions de bibliothèque dbopen(3)

NOM

dbopen - méthodes d'accès aux bases de données

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/types.h>
#include <limits.h>
#include <db.h>
#include <fcntl.h>
DB *dbopen(const char *path, int flags, int mode, DBTYPE type,
           const void *openinfo);

DESCRIPTION

Remarque importante : Cette page documente les interfaces fournies jusqu'à glibc 2.1. Depuis glibc 2.2, glibc ne fournit plus ces interfaces. Vous recherchez probablement plutôt les API fournies par la bibliothèque libdb.

dbopen() est l'interface de bibliothèque pour les fichiers de base de données. Les formats de fichiers pris en charge sont btree, hashed et orientés fichier UNIX. Le format btree est une représentation d'une structure arborescente triée et équilibrée. Le format hashed est un schéma de hachage extensible et dynamique. Le format de fichier plat est un fichier de flux d'octets avec des enregistrements de longueur fixe ou variable. Les formats et les informations spécifiques au format de fichier sont décrits en détail dans leurs pages de manuel respectives btree(3), hash(3) et recno(3).

dbopen() ouvre path en lecture et/ou en écriture. Les fichiers qui ne sont jamais destinés à être conservés sur disque peuvent être créés en réglant l'argument path à NULL.

Les arguments flags et mode sont tels que spécifiés pour la routine open(2), cependant, seuls les indicateurs O_CREAT, O_EXCL, O_EXLOCK, O_NONBLOCK, O_RDONLY, O_RDWR, O_SHLOCK et O_TRUNC sont significatifs. (Notez qu'il n'est pas possible d'ouvrir un fichier de base de données en mode O_WRONLY.)

L'argument type est de type DBTYPE (tel que défini dans le fichier d'inclusion <db.h>) et peut être réglé sur DB_BTREE, DB_HASH ou DB_RECNO.

L'argument openinfo est un pointeur vers une structure spécifique à la méthode d'accès décrite sur la page de manuel de la méthode d'accès. Si openinfo est NULL, chaque méthode d'accès utilisera les valeurs par défaut appropriées pour le système et la méthode d'accès.

dbopen() renvoie un pointeur vers une structure DB en cas de succès et NULL en cas d'erreur. La structure DB est définie dans le fichier d'inclusion <db.h>, et contient au moins les champs suivants :


typedef struct {
    DBTYPE type;
    int (*close)(const DB *db);
    int (*del)(const DB *db, const DBT *key, unsigned int flags);
    int (*fd)(const DB *db);
    int (*get)(const DB *db, DBT *key, DBT *data,
               unsigned int flags);
    int (*put)(const DB *db, DBT *key, const DBT *data,
               unsigned int flags);
    int (*sync)(const DB *db, unsigned int flags);
    int (*seq)(const DB *db, DBT *key, DBT *data,
               unsigned int flags);
} DB;

Ces éléments décrivent un type de base de données et un ensemble de fonctions effectuant diverses actions. Ces fonctions prennent un pointeur vers une structure renvoyée par dbopen(), et parfois un ou plusieurs pointeurs vers des structures clé/donnée et une valeur d'indicateur.

type
Le type de la méthode d'accès sous-jacente (et du format de fichier).
close
Un pointeur vers une routine pour vider toute information mise en cache sur le disque, libérer toutes les ressources allouées et fermer les fichiers sous-jacents. Étant donné que les paires clé/donnée peuvent être mises en cache en mémoire, l'échec de la synchronisation du fichier avec une fonction close ou sync peut entraîner des informations incohérentes ou perdues. Les routines close renvoient -1 en cas d'erreur (en définissant errno) et 0 en cas de succès.
del
Un pointeur vers une routine pour supprimer des paires clé/donnée de la base de données.
L'argument flag peut être réglé sur la valeur suivante :
R_CURSOR
Supprimer l'enregistrement référencé par le curseur. Le curseur doit avoir été précédemment initialisé.
Les routines delete renvoient -1 en cas d'erreur (en définissant errno), 0 en cas de succès, et 1 si la clé spécifiée n'était pas dans le fichier.
fd
Un pointeur vers une routine qui renvoie un descripteur de fichier représentatif de la base de données sous-jacente. Un descripteur de fichier référençant le même fichier sera renvoyé à tous les processus qui appellent dbopen() avec le même nom de path. Ce descripteur de fichier peut être utilisé en toute sécurité comme argument aux fonctions de verrouillage fcntl(2) et flock(2). Le descripteur de fichier n'est pas nécessairement associé à l'un des fichiers sous-jacents utilisés par la méthode d'accès. Aucun descripteur de fichier n'est disponible pour les bases de données en mémoire. Les routines fd renvoient -1 en cas d'erreur (en définissant errno), et le descripteur de fichier en cas de succès.
get
Un pointeur vers une routine qui est l'interface pour la récupération par clé à partir de la base de données. L'adresse et la longueur des données associées à la clé spécifiée sont renvoyées dans la structure référencée par data. Les routines get renvoient -1 en cas d'erreur (en définissant errno), 0 en cas de succès, et 1 si la clé n'était pas dans le fichier.
put
Un pointeur vers une routine pour stocker des paires clé/donnée dans la base de données.
L'argument flag peut être réglé sur l'une des valeurs suivantes :
R_CURSOR
Remplacer la paire clé/donnée référencée par le curseur. Le curseur doit avoir été précédemment initialisé.
R_IAFTER
Ajouter les données immédiatement après les données référencées par key, en créant une nouvelle paire clé/donnée. Le numéro d'enregistrement de la paire clé/donnée ajoutée est renvoyé dans la structure key. (Applicable uniquement à la méthode d'accès DB_RECNO.)
R_IBEFORE
Insérer les données immédiatement avant les données référencées par key, en créant une nouvelle paire clé/donnée. Le numéro d'enregistrement de la paire clé/donnée insérée est renvoyé dans la structure key. (Applicable uniquement à la méthode d'accès DB_RECNO.)
R_NOOVERWRITE
Entrer la nouvelle paire clé/donnée uniquement si la clé n'existe pas déjà.
R_SETCURSOR
Stocker la paire clé/donnée, en réglant ou en initialisant la position du curseur pour la référencer. (Applicable uniquement aux méthodes d'accès DB_BTREE et DB_RECNO.)
R_SETCURSOR n'est disponible que pour les méthodes d'accès DB_BTREE et DB_RECNO car cela implique que les clés ont un ordre inhérent qui ne change pas.
R_IAFTER et R_IBEFORE ne sont disponibles que pour la méthode d'accès DB_RECNO car elles impliquent toutes deux que la méthode d'accès est capable de créer de nouvelles clés. Ceci n'est vrai que si les clés sont ordonnées et indépendantes, comme les numéros d'enregistrement.
Le comportement par défaut des routines put est d'entrer la nouvelle paire clé/donnée, en remplaçant toute clé existante.
Les routines put renvoient -1 en cas d'erreur (en définissant errno), 0 en cas de succès, et 1 si l'indicateur R_NOOVERWRITE était défini et que la clé existe déjà dans le fichier.
sync
Un pointeur vers une routine pour vider toute information mise en cache sur le disque. Les routines sync renvoient -1 en cas d'erreur (en définissant errno) et 0 en cas de succès.
seq
Un pointeur vers une routine qui est l'interface pour la récupération séquentielle à partir de la base de données. L'adresse et la longueur de la clé sont renvoyées dans la structure référencée par key, et l'adresse et la longueur des données sont renvoyées dans la structure référencée par data.
La récupération séquentielle de paires clé/donnée peut commencer à tout moment, et la position du « curseur » n'est pas affectée par les appels aux routines del, get, put ou sync. Les modifications apportées à la base de données pendant un balayage séquentiel seront reflétées dans le balayage, c'est-à-dire que les enregistrements insérés après le curseur ne seront pas renvoyés tandis que les enregistrements insérés...
