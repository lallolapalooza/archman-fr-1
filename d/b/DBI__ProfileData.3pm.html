DESCRIPTIO

N

Ce module offre la possibilité de lire, manipuler et formater les données de profil de DBI::

ProfileDumper.

Conceptuellement, un profil se compose d'une série d'enregistrements, ou nœuds, chacun ayant u

n ensemble de statistiques et un ensemble de clés. Chaque enregistrement doit avoir un ensemble
de clés unique, mais il n'est pas exigé que chaque enregistrement ait le même nombre de clés.

Crée un nouvel objet DBI::ProfileData. Prend soit un fichier unique via l'option File, soit une liste de fichiers dans une référence de tableau. Si plusieurs fichiers sont spécifiés, les données d'en-tête du premier fichier sont

En fait, les fichiers sont renommés avec un suffixe "deleteme" avant d'être lus, et ensuite, après avoir lu tous les fichiers, ils sont tous supprimés

Filte

r

Le paramètre "Filter" peut être utilisé pour fournir une référence de code qui peut manipuler les données de profil pendant leur lecture. C'est surtout utile pour éditer les instructions SQL afin que des instructions légèrement différentes dans les données brutes soient fusionnées et agrégées dans les données chargées. Par exemple

: 
Filter => sub {
    my ($path_ref, $data_ref) = @_;
    s/foo = '.*?'/foo = '...'/ for @$path_ref;
}

Voici un exemple qui effectue une certaine normalisation sur le SQL. Il convertit tous les nombres en "N" et toutes les chaînes entre guillemets en "S". Il peut aussi convertir les chiffres en N à l'intérieur des noms. Enfin, il résume les longues clauses "IN (...)

".

C'est agressif et simpliste, mais c'est souvent suffisant, et sert d'exemple que vous pouvez adapter à vos propres besoins

: 
Filter => sub {
    my ($path_ref, $data_ref) = @_;
    local $_ = $path_ref->[0]; # quel que soit l'élément qui contient l'instruction SQL
    s/\b\d+\b/N/g;             # 42 -> N
    s/\b0x[0-9A-Fa-f]+\b/N/g;  # 0xFE -> N
    s/'.*?'/'S'/g;             # chaînes entre guillemets simples (ne gère pas les échappements)
    s/".*?"/"S"/g;             # chaînes entre guillemets doubles (ne gère pas les échappements)
    # convertir les noms comme log_20001231 en log_NNNNNNNN, contrôlé par $opt{n}
    s/([a-z_]+)(\d{$opt{n},})/$1.('N' x length($2))/ieg if $opt{n};
    # abréger les instructions massives "in (...)" et similaires
    s!(([NS],){100,})!sprintf("$2,{repeated %d times}",length($1)/2)!eg;
}

Il est souvent préférable d'effectuer ce genre de normalisation dans le DBI pendant

que les données sont collectées, pour éviter d'utiliser trop de mémoire en stockant
les données de profil pour beaucoup d'instructions SQL différentes. Voir DBI::Profile.
