DESCRIPTION

Ce document fournit un guide étape par étape sur la façon de créer un nouveau pilote basé sur "DBD::File". Il suppose que vous avez lu attentivement la documentation DBI et que vous êtes familier avec DBI::DBD et que vous avez lu et compris DBD::ExampleP.

Ce document s'adresse aux développeurs expérimentés qui sont vraiment sûrs de vouloir investir du temps dans l'écriture d'un nouveau pilote DBI. L'écriture d'un pilote DBI n'est ni un projet de week-end ni un travail facile pour les codeurs amateurs après le travail. Attendez-vous à un à deux mois-homme pour le démarrage.

Ceux qui continuent à lire devraient être capables de chanter les règles de "CRÉATION D'UN NOUVEAU PILOTE" dans DBI::DBD.

Bien sûr, DBD::File est un DBI::DBD::SqlEngine et vous avez sûrement lu DBI::DBD::SqlEngine::HowTo avant de continuer ici.

CRÉATION DES CLASSES DE PILOTES

Avez-vous une entrée dans le registre DBD de DBI ? Pour ce guide, un préfixe de "foo_" est supposé.

Exemple de squelette

package DBD::Foo;
use strict;
use warnings;
use base qw(DBD::File);
use DBI ();
our $VERSION = "0.001";
package DBD::Foo::dr;
our @ISA = qw(DBD::File::dr);
our $imp_data_size = 0;
package DBD::Foo::db;
our @ISA = qw(DBD::File::db);
our $imp_data_size = 0;
package DBD::Foo::st;
our @ISA = qw(DBD::File::st);
our $imp_data_size = 0;
package DBD::Foo::Statement;
our @ISA = qw(DBD::File::Statement);
package DBD::Foo::Table;
our @ISA = qw(DBD::File::Table);
1;

Minuscule, hein ? Et tout ce que vous avez maintenant est un pilote nommé foo qui sera capable de gérer les tables temporaires, tant que vous utilisez SQL::Statement. Dans les environnements DBI::SQL::Nano, ce pilote ne peut rien faire.

Redémarrer

Basé sur DBI::DBD::SqlEngine::HowTo, nous avons maintenant un pilote qui pourrait faire des choses basiques. Bien sûr, il devrait maintenant dériver de DBD::File au lieu de DBI::DBD::SqlEngine, n'est-ce pas ?

DBD::File étend DBI::DBD::SqlEngine pour gérer tout type de fichiers. En principe, les seules extensions requises concernent la classe de table :

package DBD::Foo::Table;
sub bootstrap_table_meta
{
    my ( $self, $dbh, $meta, $table ) = @_;
    # initialiser tous les attributs $meta qui pourraient être pertinents pour
    # file2table
    return $self->SUPER::bootstrap_table_meta($dbh, $meta, $table);
}
sub init_table_meta
{
    my ( $self, $dbh, $meta, $table ) = @_;
    # appelé après que $meta contienne les résultats de file2table
    # initialiser tous les attributs $meta manquants
    $self->SUPER::init_table_meta( $dbh, $meta, $table );
}

Dans le cas où "DBD::File::Table::open_file" n'ouvrirait pas les fichiers comme le pilote en a besoin, surchargez-le !

sub open_file
{
    my ( $self, $meta, $attrs, $flags ) = @_;
    # s'assurer que $meta->{f_dontopen} est défini
    $self->SUPER::open_file( $meta, $attrs, $flags );
    # faire maintenant ce qui doit être fait
}

Combiné avec les méthodes implémentées en utilisant le guide SQL::Statement::Embed, la table est entièrement fonctionnelle et vous pourriez essayer de redémarrer.

Confort utilisateur

"DBD::File" depuis la version 0.39 consolide toutes les métadonnées persistantes d'une table en une seule structure stockée dans "$dbh->{f_meta}". Avec la version de "DBD::File" 0.41 et la version de "DBI::DBD::SqlEngine" 0.05, cette consolidation se déplace vers DBI::DBD::SqlEngine. C'est toujours l'attribut "$dbh->{$drv_prefix . "_meta"}" qui s'en charge, donc ce que vous avez appris ici auparavant est toujours valide.

sub init_valid_attributes
{
    my $dbh = $_[0];
    $dbh->SUPER::init_valid_attributes ();
    $dbh->{foo_valid_attrs} = { ... };
    $dbh->{foo_readonly_attrs} = { ...  };
    $dbh->{foo_meta} = "foo_tables";
    return $dbh;
}

Voir les mises à jour dans "Confort utilisateur" de DBI::DBD::SqlEngine::HowTo.

Tests

Vous devriez maintenant avoir votre propre pilote basé sur DBD::File. C'était facile, n'est-ce pas ? Mais est-ce que ça fonctionne bien ? Prouvez-le en écrivant des tests et n'oubliez pas d'utiliser dbd_edit_mm_attribs de DBI::DBD pour garantir des tests même dans des cas rares.
