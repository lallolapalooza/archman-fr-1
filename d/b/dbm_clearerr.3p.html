DBM_CLEARERR(3P) Manuel du programmeur POSIX DBM_CLEARERR(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

dbm_clearerr, dbm_close, dbm_delete, dbm_error, dbm_fetch, dbm_firstkey, dbm_nextkey, dbm_open, dbm_store — fonctions de base de données

SYNTAXE

#include <ndbm.h>
int dbm_clearerr(DBM *db);
void dbm_close(DBM *db);
int dbm_delete(DBM *db, datum key);
int dbm_error(DBM *db);
datum dbm_fetch(DBM *db, datum key);
datum dbm_firstkey(DBM *db);
datum dbm_nextkey(DBM *db);
DBM *dbm_open(const char *file, int open_flags, mode_t file_mode);
int dbm_store(DBM *db, datum key, datum content, int store_mode);

DESCRIPTION

Ces fonctions créent, accèdent et modifient une base de données.

Un datum se compose d'au moins deux membres, dptr et dsize. Le membre dptr pointe vers un objet qui a une taille de dsize octets. Des données binaires arbitraires, ainsi que des chaînes de caractères, peuvent être stockées dans l'objet pointé par dptr.

Une base de données sera stockée dans un ou deux fichiers. Lorsqu'un seul fichier est utilisé, le nom du fichier de la base de données est formé en ajoutant le suffixe .db à l'argument file fourni à dbm_open(). Lorsqu'on utilise deux fichiers, les noms des fichiers de la base de données sont formés en ajoutant les suffixes .dir et .pag respectivement à l'argument file.

La fonction dbm_open() ouvre une base de données. L'argument file de la fonction est le chemin d'accès à la base de données. L'argument open_flags a la même signification que l'argument flags de open(), sauf qu'une base de données ouverte en accès en écriture seule ouvre les fichiers en lecture et écriture et que le comportement du drapeau O_APPEND n'est pas spécifié. L'argument file_mode a la même signification que le troisième argument de open().

La fonction dbm_open() n'est pas obligée d'accepter des chemins plus longs que {PATH_MAX}-4 octets (y compris le terminateur nul), ou des chemins dont la dernière composante est plus longue que {NAME_MAX}-4 octets (sans le terminateur nul).

La fonction dbm_close() ferme une base de données. L'application doit s'assurer que l'argument db est un pointeur vers une structure dbm qui a été retournée par un appel à dbm_open().

Ces fonctions de base de données doivent supporter une taille de bloc interne suffisamment grande pour supporter des paires clé/contenu d'au moins 1023 octets.

La fonction dbm_fetch() lit un enregistrement d'une base de données. L'argument db est un pointeur vers une structure de base de données retournée par un appel à dbm_open(). L'argument key est un datum qui a été initialisé par l'application avec la valeur de la clé qui correspond à la clé de l'enregistrement que le programme récupère.

La fonction dbm_store() écrit un enregistrement dans une base de données. L'argument db est un pointeur vers une structure de base de données retournée par un appel à dbm_open(). L'argument key est un datum initialisé par l'application avec la valeur de la clé qui identifie (pour une lecture, écriture ou suppression ultérieure) l'enregistrement que l'application écrit. L'argument content est un datum initialisé par l'application avec la valeur de l'enregistrement que le programme écrit. L'argument store_mode contrôle si dbm_store() remplace un enregistrement préexistant ayant la même clé que celle spécifiée par l'argument key. L'application doit définir store_mode sur DBM_INSERT ou DBM_REPLACE. Si la base de données contient un enregistrement correspondant à l'argument key et que store_mode est DBM_REPLACE, l'enregistrement existant sera remplacé par le nouvel enregistrement. Si la base de données contient un enregistrement correspondant à l'argument key et que store_mode est DBM_INSERT, l'enregistrement existant restera inchangé et le nouvel enregistrement sera ignoré. Si la base de données ne contient pas d'enregistrement correspondant à l'argument key et que store_mode est soit DBM_INSERT, soit DBM_REPLACE, le nouvel enregistrement sera inséré dans la base de données.

Si la somme d'une paire clé/contenu dépasse la taille de bloc interne, le résultat n'est pas spécifié. De plus, l'application doit s'assurer que toutes les paires clé/contenu qui hachage ensemble tiennent sur un seul bloc. La fonction dbm_store() retournera une erreur si un bloc disque se remplit de données inséparables.

La fonction dbm_delete() supprime un enregistrement et sa clé de la base de données. L'argument db est un pointeur vers une structure de base de données retournée par un appel à dbm_open(). L'argument key est un datum initialisé par l'application avec la valeur de la clé qui identifie l'enregistrement que le programme supprime.

La fonction dbm_firstkey() retourne la première clé de la base de données. L'argument db est un pointeur vers une structure de base de données retournée par un appel à dbm_open().

La fonction dbm_nextkey() retourne la clé suivante dans la base de données. L'argument db est un pointeur vers une structure de base de données retournée par un appel à dbm_open(). L'application doit s'assurer que la fonction dbm_firstkey() est appelée avant d'appeler dbm_nextkey(). Les appels successifs à dbm_nextkey() retournent la clé suivante jusqu'à ce que toutes les clés de la base de données aient été retournées.

La fonction dbm_error() retourne l'état d'erreur de la base de données. L'argument db est un pointeur vers une structure de base de données retournée par un appel à dbm_open().

La fonction dbm_clearerr() efface l'état d'erreur de la base de données. L'argument db est un pointeur vers une structure de base de données retournée par un appel à dbm_open().

Les pointeurs dptr retournés par ces fonctions peuvent pointer vers une mémoire statique qui peut être modifiée par des appels ultérieurs.

Ces fonctions ne sont pas nécessairement thread-safe.

VALEUR RENVOYÉE

Les fonctions dbm_store() et dbm_delete() retournent 0 en cas de succès et une valeur négative en cas d'échec.

La fonction dbm_store() retourne 1 si elle est appelée avec une valeur de flags de DBM_INSERT et si la fonction trouve un enregistrement existant avec la même clé.

La fonction dbm_error() retourne 0 si l'état d'erreur n'est pas défini et une valeur non nulle si l'état d'erreur est défini.

La valeur de retour de dbm_clearerr() n'est pas spécifiée.

Les fonctions dbm_firstkey() et dbm_nextkey() retournent un datum de clé. Lorsque la fin de la base de données est atteinte, le membre dptr de la clé est un pointeur nul. Si une erreur est détectée, le membre dptr de la clé sera un pointeur nul et l'état d'erreur de la base de données sera défini.

La fonction dbm_fetch() retourne un datum de contenu. Si aucun enregistrement dans la base de données ne correspond à la clé ou si un état d'erreur a été détecté dans la base de données, le membre dptr du contenu sera un pointeur nul.

La fonction dbm_open() retourne un pointeur vers une structure de base de données. Si une erreur est détectée pendant l'opération, dbm_open() retourne un (DBM *)0.

ERREURS

Aucune erreur n'est définie.

EXEMPLES

Aucun.

UTILISATION PAR L'APPLICATION

Le code suivant peut être utilisé pour parcourir la base de données :

for(key = dbm_firstkey(db); key.dptr != NULL; key = dbm_nextkey(db))

Les fonctions dbm_* fournies dans cette bibliothèque ne doivent pas être confondues d'une quelconque manière avec celles d'un système de gestion de base de données à usage général. Ces fonctions ne fournissent pas de clés de recherche multiples par entrée, elles ne protègent pas contre les accès multi-utilisateurs (en d'autres termes, elles ne verrouillent pas les enregistrements ou les fichiers), et elles ne fournissent pas les nombreuses autres fonctions de base de données utiles que l'on trouve dans des systèmes de gestion de base de données plus robustes.

NAME

dbm_clearerr, dbm_close, dbm_delete, dbm_error, dbm_fetch, dbm_firstkey, dbm_nextkey, dbm_open, dbm_store, dbm_sync - gestion de base de données de style dbm

SYNOPSIS

#include <ndbm.h>

void
dbm_clearerr(DBM *db);

void
dbm_close(DBM *db);

int
dbm_delete(DBM *db, datum key);

int
dbm_error(DBM *db);

datum
dbm_fetch(DBM *db, datum key);

datum
dbm_firstkey(DBM *db);

datum
dbm_nextkey(DBM *db);

DBM *
dbm_open(const char *name, int oflag, mode_t mode);

int
dbm_store(DBM *db, datum key, datum content, int replace);

int
dbm_sync(DBM *db);

DESCRIPTION

Ces fonctions fournissent une interface pour accéder à une base de données de style dbm.

Le nom de base de données est spécifié par name. Le système d'exploitation crée et ouvre deux fichiers : un fichier d'index et un fichier de données. Ces deux fichiers ont le nom de base spécifié par name, avec les suffixes .dir et .pag respectivement.

L'argument oflag est une combinaison des indicateurs décrit dans open(2). Les indicateurs valides sont O_RDONLY, O_WRONLY, et O_RDWR. L'indicateur O_CREAT peut être inclus pour créer la base de données si elle n'existe pas. L'indicateur O_TRUNC peut être inclus pour tronquer un fichier existant.

L'argument mode est le mode de permissions à définir pour les fichiers si la base de données est créée. Il est utilisé par open(2) et est modifié par la valeur de umask du processus.

La structure datum est utilisée pour représenter des paires clé/valeur :

typedef struct {
    char *dptr;
    int dsize;
} datum;

dbm_open() renvoie un pointeur vers une structure opaque DBM qui sera utilisée dans les appels de fonction ultérieurs. Si dbm_open() échoue, il renvoie NULL.

dbm_close() ferme la base de données associée au pointeur DBM. Il écrit toutes les données en cache sur le disque et libère les ressources associées.

dbm_store() stocke une paire clé/valeur dans la base de données. Si replace est zéro, et si la clé existe déjà, alors dbm_store() renvoie une erreur. Si replace est non nul, alors la valeur existante est remplacée. Il renvoie 0 en cas de succès, et une valeur non nulle en cas d'échec.

dbm_delete() supprime une paire clé/valeur de la base de données. Il renvoie 0 en cas de succès, et une valeur non nulle en cas d'échec.

dbm_fetch() récupère la valeur associée à une clé donnée. Si la clé n'est pas trouvée, il renvoie une structure datum dont le membre dptr est NULL.

dbm_firstkey() renvoie la première clé de la base de données. dbm_nextkey() renvoie la clé suivante dans la base de données. L'ordre des clés n'est pas spécifié. Lorsque toutes les clés ont été renvoyées, dbm_nextkey() renvoie une structure datum dont le membre dptr est NULL.

dbm_error() renvoie une valeur non nulle si une erreur s'est produite lors d'une opération précédente sur le descripteur de fichier DBM. Sinon, il renvoie zéro.

dbm_clearerr() efface les indicateurs d'erreur pour le descripteur de fichier DBM donné.

dbm_sync() écrit toutes les données mises en cache sur le disque.

RETURN VALUE

Voir les descriptions individuelles des fonctions.

ERRORS

Aucun.

EXAMPLES

Pour stocker une paire clé/valeur :

    datum key, content;
    DBM *db = dbm_open("mydb", O_RDWR | O_CREAT, 0664);
    // ... vérifier si db est NULL ...
    key.dptr = "mykey";
    key.dsize = strlen(key.dptr);
    content.dptr = "myvalue";
    content.dsize = strlen(content.dptr);
    dbm_store(db, key, content, 1);
    dbm_close(db);

Pour récupérer une valeur :

    datum key, content;
    DBM *db = dbm_open("mydb", O_RDONLY, 0);
    // ... vérifier si db est NULL ...
    key.dptr = "mykey";
    key.dsize = strlen(key.dptr);
    content = dbm_fetch(db, key);
    if (content.dptr != NULL) {
        // Traiter la valeur
    }
    dbm_close(db);

Pour itérer sur toutes les paires clé/valeur :

    DBM *db = dbm_open("mydb", O_RDONLY, 0);
    // ... vérifier si db est NULL ...
    for (key = dbm_firstkey(db); key.dptr != NULL; key = dbm_nextkey(db)) {
        content = dbm_fetch(db, key);
        // Traiter la paire clé/valeur
    }
    dbm_close(db);

APPLICATION USAGE

Ces fonctions sont des fonctions de base de données de bas niveau et sont généralement remplacées par des interfaces de plus haut niveau comme Perl. Les fonctions sont relativement lentes car elles créent et mettent à jour des bases de données en utilisant des fonctions de hachage et en copiant des données lors de collisions de hachage. Ces fonctions sont utiles pour les applications nécessitant une recherche rapide d'informations relativement statiques qui doivent être indexées par une seule clé.

Notez qu'une application strictement conforme est extrêmement limitée par ces fonctions : puisqu'il n'y a aucun moyen de déterminer que les clés utilisées ne hachent pas toutes vers la même valeur (bien que ce soit rare), une application strictement conforme ne peut pas garantir qu'elle peut stocker plus d'un bloc de données dans la base de données. Tant qu'une collision de clés ne se produit pas, des données supplémentaires peuvent être stockées, mais comme il n'y a aucun moyen de déterminer si une erreur est due à une collision de clés ou à une autre condition d'erreur (dbm_error() étant effectivement booléenne), une fois qu'une erreur est détectée, l'application est effectivement limitée à deviner quelle pourrait être l'erreur si elle souhaite continuer à utiliser ces fonctions.

La fonction dbm_delete() n'a pas besoin de récupérer physiquement l'espace fichier, bien qu'elle le rende disponible pour une réutilisation par la base de données.

Après avoir appelé dbm_store() ou dbm_delete() pendant une itération sur les clés par dbm_firstkey() et dbm_nextkey(), l'application doit réinitialiser la base de données en appelant dbm_firstkey() avant de rappeler dbm_nextkey(). Le contenu de ces fichiers n'est pas spécifié et peut ne pas être portable.

Les applications doivent veiller à ce que les arguments de chemin de base de données spécifiés à dbm_open() ne soient pas des préfixes de fichiers sans rapport. Cela pourrait être fait, par exemple, en plaçant les bases de données dans un répertoire séparé.

Étant donné que certaines implémentations utilisent trois caractères pour un suffixe et d'autres en utilisent quatre, les applications doivent s'assurer que la longueur maximale du chemin portable passée à dbm_open() n'est pas supérieure à {PATH_MAX}-4 octets, le dernier composant du chemin ne dépassant pas {NAME_MAX}-4 octets.

RATIONALE

Auparavant, la norme exigeait que la base de données soit stockée dans deux fichiers, l'un étant un répertoire contenant une bitmap de clés et ayant .dir comme suffixe. Le second fichier contenant toutes les données et ayant .pag comme suffixe. Cela a été modifié pour ne pas spécifier l'utilisation des fichiers et pour permettre des implémentations plus récentes de l'interface Berkeley DB utilisant un seul fichier qui ont évolué tout en restant compatibles avec l'interface de programmation d'application. Les développeurs de la norme ont envisagé de supprimer complètement les suffixes spécifiques mais ont décidé de les conserver afin de ne pas polluer l'espace de noms de fichiers d'application plus que nécessaire et de permettre des sauvegardes portables de la base de données.
