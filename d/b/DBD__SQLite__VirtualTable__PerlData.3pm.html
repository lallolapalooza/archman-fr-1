DESCRIPTIO

N

Une table virtuelle "PerlData" est une vue de base de données sur une certaine structure de données au sein d'un programme Perl. Les données peuvent être lues ou modifiées à la foi

s depuis SQL et depuis Perl. C'est utile pour des opérations simples d'import/export,
à des fins de débogage, pour joindre des données provenant de sources différentes, etc.

PARAMÈTRE

S

Les paramètres pour créer une table virtuelle "PerlData" sont spécifiés dans l'instruction "CREATE VIRTUAL TABLE", mélangés avec les déclarations de colonnes normales, mais avec un signe

'='.

Le seul paramètre autorisé (et obligatoire) est celui qui spécifie la structure de données Perl à laquelle la table virtuelle est liée. Il doit être donné sous forme de nom entièrement qualifié d'une variable globale ; le paramètre peut être de l'un des trois types suivants

:
"arrayref
s"
tableau de références (arrayref) qui contient un arrayref pour chaque ligne. Chaque telle ligne aura une taille équivalente au nombre de colonnes déclarées pour la table
virtuelle.
"hashref
s"
arrayref qui contient une référence de hachage (hashref) pour chaque ligne. Les clés de chaque hashref devraient correspondre aux colonnes déclarées pour la table
virtuelle.
"colre
f"
arrayref qui contient un seul sc
alaire pour chaque ligne ; évid
emment, il s'agit d'une t
able virtuelle à colonne unique.

UTILISATI

ON

Partie commune à tous les exemples : déclaration du

module

Dans tous les exemples ci-dessous, la partie commune est que le programme Perl devrait se connecter à la base de données puis déclarer le module de table virtuelle "PerlData", comme

ceci 
# connect to the database
my $dbh = DBI->connect("dbi:SQLite:dbname=$dbfile", '', '',
                        {RaiseError => 1, AutoCommit => 1});
                        # or any other options suitable to your needs

# register the module
$dbh->sqlite_create_module(perl => "DBD::SQLite::VirtualTable::PerlData")
;

Puis créez une variable globale de type arrayref, en utilisant "our" au lieu de "my", afin que la variable soit stockée dans la table de symboles du module

englobant. 
package Foo::Bar; # could as well be just "main"
our $rows = [ ... ]
;

Enfin, créez la table virtuelle et liez-la à la variable globale (ici nous supposons que @$rows contient des arrayrefs)

: 
$dbh->do('CREATE VIRTUAL TABLE temp.vtab'
        .'  USING perl(col1 INT, col2 TEXT, etc,
                       arrayrefs="Foo::Bar::rows')
;

Dans la plupart des cas, la table virtuelle sera pour un usage temporaire, ce qui est la raison pour laquelle cet exemple préfixe "temp." devant le nom de la table : cela indique à SQLite de nettoyer cette table lorsque le descripteur de base de données sera déconnecté, sans avoir besoin d'émettre une instruction DROP

explicite.

Les noms de colonnes (et éventuellement leurs types) so

nt spécifiés dans la déclaration de la table virtuel
le, tout comme pour n'importe quelle table normale.

Exemple avec colref : SELECT WHERE ... IN ..

.

Note : L'idée pour l'exemple suivant est empruntée au fichier "test_intarray.h" dans la source d'SQLite (http://www.sqlite.

org/src).

Une table virtuelle "colref" est conçue pour faciliter l'utilisation d'un tableau de valeurs comme côté droit d'un opérateur IN. La syntaxe habituelle pour IN est de préparer une instruction comme ceci

: 
SELECT * FROM table WHERE x IN (?,?,?,...,?)
;

puis de lier les valeurs individuelles à chacun des emplacements ? ; mais cela a l'inconvénient que le nombre de valeurs doit être connu à l'avance. À la place, nous pouvons stocker les valeurs dans un tableau Perl, lier ce tableau à une table virtuelle, puis écrire une instruction comme

celle-ci 
SELECT * FROM table WHERE x IN
perl_array;

Voici à quoi ressemblerait un tel programme

: 
# connect to the database
my $dbh = DBI->connect("dbi:SQLite:dbname=$dbfile", '', '',
                        {RaiseError => 1, AutoCommit => 1});

# Declare a global arrayref containing the values. Here we assume
# they are taken from @ARGV, but any other datasource would do.
# Note the use of "our" instead of "my".
our $values = \@ARGV; 

# register the module and declare the virtual table
$dbh->sqlite_create_module(perl => "DBD::SQLite::VirtualTable::PerlData");
$dbh->do('CREATE VIRTUAL TABLE temp.intarray'
        .'  USING perl(i INT, colref="main::values');

# now we can SELECT from another table, using the intarray as a constraint
my $sql    = "SELECT * FROM some_table WHERE some_col IN intarray";
my $result = $dbh->selectall_arrayref($sql)
;

Attention, la table virtuelle est en lecture-écriture, donc l'instruction ci-dessous pousserait 99 dans @ARGV
