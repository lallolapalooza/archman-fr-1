DESCRIPTIO

N

DBD::mysql est le pilote de l'Interface de Base de Données Perl5 pour la base de données MySQL. En d'autres termes : DBD::mysql est une interface entre le langage de programmation Perl et l'API de programmation MySQL qui accompagne le système de gestion de base de données relationnelle MySQL. La plupart des fonctions fournies par cette API de programmation sont prises en charge. Certaines fonctions rarement utilisées sont manquantes, principalement parce que personne ne les a jamais demandées. :

-)

Dans ce qui suit, nous discutons d'abord de l'utilisation de DBD::mysql, car c'est ce dont vous aurez le plus besoin. Pour l'installation, voir le document séparé DBD::mysql::INSTALL. Voir "EXEMPLE" pour un exemple simple

ci-dessus.

Depuis perl, vous activez l'interface avec

l'instruction 
use
DBI;

Après cela, vous pouvez vous connecter à plusieurs serveurs de base de données MySQL et envoyer plusieurs requêtes à n'importe lequel d'entre eux via une simple interface orientée objet. Deux types d'objets sont disponibles : les descripteurs de base de données et les descripteurs d'instructions. Perl renvoie un descripteur de base de données à la méthode connect comme ceci

: 
$dbh = DBI->connect("DBI:mysql:database=$db;host=$host",
  $user, $password, {RaiseError => 1})
;

Une fois que vous êtes connecté à une base de données, vous pouvez exécuter des instructions SQL avec

: 
my $query = sprintf("INSERT INTO foo VALUES (%d, %s)",
                    $number, $dbh->quote("name"));
$dbh->do($query)
;

Voir DBI pour les détails sur les méthodes quote et do. Une approche alternative

est 
$dbh->do("INSERT INTO foo VALUES (?, ?)", undef,
         $number, $name)
;

dans lequel la méthode quote est exécutée automatiquement. Voir aussi la méthode bind_param dans DBI. Voir "DESCRIPTEURS DE BASE DE DONNÉES" ci-dessous pour plus de détails sur les descripteurs de base de

données.

Si vous voulez récupérer des résultats, vous devez créer un soi-disant descripteur d'instruction avec

: 
$sth = $dbh->prepare("SELECT * FROM $table");
$sth->execute()
;

Ce descripteur d'instruction peut être utilisé pour plusieurs choses. Tout d'abord, vous pouvez récupérer une ligne de données

: 
my $row = $sth->fetchrow_hashref()
;

Si votre table a des colonnes ID et NAME, alors $row sera une référence de hachage avec les clés ID et NAME. Voir "DESCRIPTEURS D'INSTRUCTION" ci-dessous pour plus de détails sur les descripteurs

d'instruction.

D'INSTRUCTIONS

Les gestionnaires d'instructions de DBD::mysql prennent en charge un certain nombre d'attributs. Vous y accédez en utilisant, par

exemple, 
my $numFields = $sth->{NUM_OF_FIELDS}
;

Notez que la plupart des attributs ne sont valides qu'après un execute réussi. Un "undef" sera retourné sinon. L'exception la plus importante est l'attribut "mysql_use_result", qui force le pilote à utiliser mysql_use_result plutôt que mysql_store_result. Le premier est plus rapide et consomme moins de mémoire, mais a tendance à bloquer d'autres processus. (C'est pourquoi mysql_store_result est la valeur par défaut.

)

Pour définir l'attribut "mysql_use_result", utilisez l'une des méthodes suivantes

: 
my $sth = $dbh->prepare("QUERY", { mysql_use_result => 1})
;

o

u 
my $sth = $dbh->prepare($sql);
$sth->{mysql_use_result} =
1;

Les attributs dépendant des colonnes, par exemple NAME, les noms de colonnes, sont retournés sous forme de référence à un tableau. Les indices du tableau correspondent aux indices des tableaux retournés par fetchrow et des méthodes similaires. Par exemple, le code suivant imprimera un en-tête avec les noms de tables ainsi que toutes les lignes

: 
my $sth = $dbh->prepare("SELECT * FROM $table") ||
  die "Error:" . $dbh->errstr . "\n";
$sth->execute ||  die "Error:" . $sth->errstr . "\n";
my $names = $sth->{NAME};
my $numFields = $sth->{'NUM_OF_FIELDS'} - 1;
for my $i ( 0..$numFields ) {
    printf("%s%s", $i ? "," : "", $$names[$i]);
}
print "\n";
while (my $ref = $sth->fetchrow_arrayref) {
    for my $i ( 0..$numFields ) {
    printf("%s%s", $i ? "," : "", $$ref[$i]);
    }
    print "\n";
}

PRISE EN CHARGE DES

TRANSACTIONS

La prise en charge des transactions fonctionne comme suit

:
  • Par défaut, le mode AutoCommit est activé, conformément aux spécifications du
    • DBI.
  • Si vous exécutez 
    $dbh->{AutoCommit}
    = 0;

    o

    u 
    $dbh->{AutoCommit}
    = 1;

    alors le pilote définira la variable du serveur MySQL autocommit à 0 ou 1, respectivement. Le passage de 0 à 1 émettra également un COMMIT, conformément aux spécifications

    du
    • DBI.
  • Les méthodes 
    $dbh->rollback();
$dbh->commit()
    ;

    émettront respectivement les commandes ROLLBACK et COMMIT. Un

    ROLLBACK sera également émis si le mode AutoCommit est désacti
    • vé et que la méthode DESTROY du gestionnaire de base de donnée
s est appelée. Là encore, cela suit les spécifications du DBI.

Compte tenu de ce qui précède, vous devriez noter ce qui suit

:
  • Vous ne devriez jamais changer manuellement la variable du serveur autocommit, sauf si vous ignorez la prise en charge des transactions du
    • DBI.
  • Le passage du mode AutoCommit d'activé à désactivé ou inversement peut échouer. Vous devriez toujours vérifier les erreurs lors du changement de mode AutoCommit. La manière recommandée de le faire est d'utiliser le drapeau DBI RaiseError. Si vous n'aimez pas RaiseError, vous devez utiliser du code comme le suivant : 
    $dbh->{AutoCommit} = 0;
i
    f ($dbh->{AutoCommit}) {
    • # An error occurred! }
  • Si vous détectez une erreur lors du changement de mode AutoCommit, vous ne devriez plus utiliser le gestionnaire de base de données. En d'autres termes, vous devriez vous déconnecter et vous reconnecter, car le mode de transaction est imprévisible. Alternativement, vous pouvez vérifier le mode de transaction en contrôlant la valeur de la variable du serveur autocommit. Cependant, un tel comportement n'est pas
    • portable.
  • DBD::mysql a une fonctionnalité "reconnect" qui gère le soi-disant "bug du matin" de MySQL : si le serveur s'est déconnecté, très probablement en raison d'un délai d'attente, alors par défaut le pilote se reconnectera et tentera d'exécuter à nouveau la même instruction SQL. Cependant, ce comportement est désactivé lorsque AutoCommit est désactivé : sinon, l'état de la transaction serait complètement imprévisible après une
    • reconnexion.
  • La fonctionnalité "reconnect" de DBD::mysql peut être activée ou désactivée en utilisant
    • l'attribut mysql_auto_reconnect. Ce comportement devrait être désactivé dans le code qu
i utilise LOCK TABLE, car si le serveur de base de données expire et que DBD::mysql se
reconnecte, les verrous de table seront perdus sans aucune indication d'une telle perte.

Les capacités de multitranchage de DBD::mysql dépendent entièrement des bibliothèques C sous-jacentes. Les modules ne travaillent qu'avec les données des handles, aucune variable globale n'est accédée et, à ma connaissance, aucune fonction non sûre pour les tranches n'est appelée. REQUÊTES

ASYNCHRONES

Vous pouvez effectuer une seule requête asynchrone par connexion MySQL ; cela vous permet de soumettre une requête longue au serveur et de faire informer une boucle d'événements lorsqu'elle est prête. Une requête asynchrone est démarrée soit en définissant l'attribut 'async' à une valeur vraie dans la méthode "do" de DBI, soit dans la méthode "prepare" de DBI. Les instructions créées avec 'async' défini à vrai dans prepare exécutent toujours leurs requêtes de manière asynchrone lorsque "execute" de DBI est appelé. Le pilote propose également trois méthodes supplémentaires : "mysql_async_result", "mysql_async_ready", et "mysql_fd". "mysql_async_result" renvoie ce que do ou execute auraient renvoyé ; c'est-à-dire le nombre de lignes affectées. "mysql_async_ready" renvoie vrai si "mysql_async_result" ne bloquera pas, et zéro sinon. Tous deux renvoient "undef" si ce handle n'a pas été créé avec 'async' défini à vrai ou si une requête asynchrone n'a pas encore été démarrée. "mysql_fd" renvoie le numéro de descripteur de fichier pour la connexion MySQL ; vous pouvez l'utiliser dans une boucle

d'événements.

Voici un exemple d'utilisation de l'interface de requête asynchrone

: 
use feature 'say';
$dbh->do('SELECT SLEEP(10)', { async => 1 });
until($dbh->mysql_async_ready) {
  say 'not ready yet!';
  sleep 1;
}
