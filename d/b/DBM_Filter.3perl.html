DESCRIPTIO

N

Ce module fournit une interface permettant d'appliquer des filtres aux tables associées liées aux fichiers DBM. Il s'appuie sur les crochets de filtre DBM prése

nts dans tous les modules *DB*_File inclus avec la distribution standard de Perl à partir de la version 5.6.1. En plus des modules *DB*_File distribués avec Perl
, le module BerkeleyDB, disponible sur CPAN, prend en charge les crochets de filtre DBM. Voir perldbmfilter pour plus de détails sur les crochets de filtre DBM.

Qu'est-ce qu'un filtre DBM

?

Un filtre DBM permet de modifier les clés et/ou les valeurs d'une table liée par un code défini par l'utilisateur juste avant l'écriture dans le fichier DBM et juste après la lecture depuis le fichier DBM. Par exemple, cet extrait de

code 
$some_hash{"abc"} =
42;

pourrait potentiellement déclencher deux filtres, un pour l'écriture de la clé "abc" et un autre pour l'écriture de la valeur 42. De même, cet

extrait 
my ($key, $value) = each
%some_hash

déclenchera deux filtres, un pour la lecture de la clé et un pour la lecture de la

valeur.

Comme la fonctionnalité de filtre DBM existante, ce module s'arrange pour que la variable $_ soit remplie avec la clé ou la valeur qu'un filtre va vérifier. Cela signifie généralement que la plupart des filtres DBM sont très

courts.

?

Les principales améliorations par rapport aux crochets de filtre DBM standard sont

  • La possibilité de créer des f

Filtres

Un filtre immédiat vous permet de spécifier le code du filtre à utiliser au moment où le filtre est appliqué à un dbm. Dans ce mode, les méthodes Filter_*_Push attendent de recevoir exactement deux

paramètres.

La référence de code associée à "Store" sera appelée avant toute écriture de clé/valeur dans la base de données et la référence de code associée à "Fetch" sera appelée après toute lecture de clé/valeur depuis la base de

NOTE

S

Maintenir l'intégrité de

l'aller-retour

Lors de la rédaction d'un filtre DBM, il est très important de s'assurer qu'il est possible de récupérer toutes les données que vous avez écrites lorsque le filtre DBM est en place. En pratique, cela signifie que quelle que soit la transformation qui est appliquée aux données dans la méthode Store, l' opération inverse exacte doit être appliquée dans la méthode

Fetch.

Si vous ne fournissez pas une transformation inverse exacte, vous constaterez que du code comme celui-ci ne se comportera pas comme vous

l'attendez. 
while (my ($k, $v) = each %hash)
{
    ...
}

Selon la transformation, vous constaterez qu'un ou plusieurs des phénomènes suivants se

jamais.
2

Trop peu d'enregistrements seront
récupérés.
3

Trop d'enregistrements seront

4

Ne mélangez pas de données filtrées et non filtrées dans le même fichier de base de

données.
