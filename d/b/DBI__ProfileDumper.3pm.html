DBI::ProfileDumper(3) Documentation Perl contribuée par les utilisateurs DBI::ProfileDumper(3)

NOM

DBI::ProfileDumper - profile l'utilisation de DBI et écrit les données dans un fichier

SYNOPSIS

Pour profiler un programme existant utilisant DBI::ProfileDumper, définissez la variable d'environnement DBI_PROFILE et exécutez votre programme comme d'habitude. Par exemple, avec bash :

DBI_PROFILE=2/DBI::ProfileDumper program.pl

Analysez ensuite le fichier généré (dbi.prof) avec dbiprof :

dbiprof

Vous pouvez aussi activer DBI::ProfileDumper depuis votre code :

use DBI;
# profile avec le chemin par défaut (2) et le fichier de sortie (dbi.prof)
$dbh->{Profile} = "!Statement/DBI::ProfileDumper";
# la même chose, explicitement
$dbh->{Profile} = "!Statement/DBI::ProfileDumper/File:dbi.prof";
# une autre façon de l'écrire
use DBI::ProfileDumper;
$dbh->{Profile} = DBI::ProfileDumper->new(
                      Path => [ '!Statement' ],
                      File => 'dbi.prof' );
# avec un chemin personnalisé
$dbh->{Profile} = DBI::ProfileDumper->new(
    Path => [ "foo", "bar" ],
    File => 'dbi.prof',
);

DESCRIPTION

DBI::ProfileDumper est une sous-classe de DBI::Profile qui écrit les données de profilage sur le disque au lieu d'afficher un résumé à l'écran. Vous pouvez ensuite utiliser dbiprof pour analyser les données de plusieurs manières intéressantes, ou vous pouvez créer votre propre analyse en utilisant DBI::ProfileData.

NOTE : Pour les applications Apache/mod_perl, utilisez DBI::ProfileDumper::Apache.

UTILISATION

Une façon d'utiliser ce module est simplement de l'activer dans votre $dbh:

$dbh->{Profile} = "1/DBI::ProfileDumper";

Cela écrira les données de profilage par instruction dans un fichier appelé dbi.prof. Si vous souhaitez modifier l'une ou l'autre de ces propriétés, vous pouvez construire l'objet DBI::ProfileDumper vous-même :

use DBI::ProfileDumper;
$dbh->{Profile} = DBI::ProfileDumper->new(
    Path => [ '!Statement' ],
    File => 'dbi.prof'
);

L'option "Path" accepte les mêmes valeurs que dans DBI::Profile. L'option "File" donne le nom du fichier où les résultats seront collectés. S'il existe déjà, il sera écrasé.

Vous pouvez aussi activer ce module en définissant la variable d'environnement DBI_PROFILE :

$ENV{DBI_PROFILE} = "!Statement/DBI::ProfileDumper";

Cela fera en sorte que tous les handles DBI partagent le même objet de profilage.

MÉTHODES

Les méthodes suivantes peuvent être appelées via l'objet de profilage. Vous pouvez accéder à l'objet de profilage via la clé Profile dans n'importe quel handle DBI :

my $profile = $dbh->{Profile};

flush_to_disk

$profile->flush_to_disk()

Vide toutes les données de profilage collectées sur le disque et efface le hachage Data. Retourne le nom du fichier écrit. Si aucune donnée de profilage n'a été collectée, le fichier n'est pas écrit et flush_to_disk() retourne undef.

Le fichier est verrouillé pendant son écriture. Un processus qui « consomme » les fichiers pendant qu'ils sont écrits doit d'abord renommer le fichier, puis le verrouiller, puis le lire, puis le fermer et le supprimer. L'option "DeleteFiles" de DBI::ProfileData fait les choses correctement.

Cette méthode peut être appelée plusieurs fois pendant l'exécution d'un programme.

empty

$profile->empty()

Efface le hachage Data sans écrire sur le disque.

filename

$filename = $profile->filename();

Obtient ou définit le nom du fichier.

Le nom du fichier peut être spécifié comme une référence CODE, auquel cas le code référencé doit retourner le nom du fichier à utiliser. Le code sera appelé avec l'objet de profilage comme premier argument.

FORMAT DES DONNÉES

Le format de données écrit par DBI::ProfileDumper commence par un en-tête contenant le numéro de version du module utilisé pour le générer. Puis un bloc de déclarations de variables décrit le profil. Après deux sauts de ligne, les données de profilage forment le corps du fichier. Par exemple :

DBI::ProfileDumper 2.003762
Path = [ '!Statement', '!MethodName' ]
Program = t/42profile_data.t
+ 1 SELECT name FROM users WHERE id = ?
+ 2 prepare
= 1 0.0312958955764771 0.000490069389343262 0.000176072120666504 0.00140702724456787 1023115819.83019 1023115819.86576
+ 2 execute
1 0.0312958955764771 0.000490069389343262 0.000176072120666504 0.00140702724456787 1023115819.83019 1023115819.86576
+ 2 fetchrow_hashref
= 1 0.0312958955764771 0.000490069389343262 0.000176072120666504 0.00140702724456787 1023115819.83019 1023115819.86576
+ 1 UPDATE users SET name = ? WHERE id = ?
+ 2 prepare
= 1 0.0312958955764771 0.000490069389343262 0.000176072120666504 0.00140702724456787 1023115819.83019 1023115819.86576
+ 2 execute
= 1 0.0312958955764771 0.000490069389343262 0.000176072120666504 0.00140702724456787 1023115819.83019 1023115819.86576

Les lignes commençant par le signe "+" signifient des clés. Le nombre après le signe "+" indique le niveau d'imbrication de la clé. Les lignes commençant par "=" sont les données de profilage réelles, dans le même ordre que dans DBI::Profile.

Notez que le même chemin peut être présent plusieurs fois dans le fichier de données car format() peut être appelé plus d'une fois. Lorsqu'elles sont lues par DBI::ProfileData, les points de données seront fusionnés pour produire un seul ensemble de données pour chaque chemin distinct.

Les chaînes de clés sont transformées de trois manières. D'abord, tous les antislashs sont doublés. Puis tous les sauts de ligne et retours à la ligne sont transformés en "\n" et "\r" respectivement. Enfin, tous les octets NULL ("\0") sont complètement supprimés. Quand DBI::ProfileData lit le fichier, les deux premières transformations seront inversées, mais les octets NULL ne seront pas restaurés.
