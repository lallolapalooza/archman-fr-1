DBI::DBD::Metadata(3) Documentation Perl fournie par l'utilisateur DBI::DBD::Metadata(3)

NOM

DBI::DBD::Metadata - Génère le code et les données pour certaines méthodes de métadonnées DBI

SYNOPSIS

L'idée est d'extraire des informations de métadonnées d'un pilote ODBC de bonne qualité et de les utiliser pour générer du code et des données à utiliser dans votre propre pilote DBI pour la même base de données.

Pour générer le code pour supporter la méthode get_info :

perl -MDBI::DBD::Metadata -e "write_getinfo_pm('dbi:ODBC:dsn-name','user','pass','Driver')"
perl -MDBI::DBD::Metadata -e write_getinfo_pm dbi:ODBC:foo_db username password Driver

Pour générer le code pour supporter la méthode type_info :

perl -MDBI::DBD::Metadata -e "write_typeinfo_pm('dbi:ODBC:dsn-name','user','pass','Driver')"
perl -MDBI::DBD::Metadata -e write_typeinfo_pm dsn-name user pass Driver

Où "dbi:ODBC:dsn-name" est la connexion à utiliser pour extraire les données, et "Driver" est le nom du pilote pour lequel le code sera généré (le nom du pilote est intégré dans la sortie à de nombreux endroits).

Génération d'un package GetInfo pour un pilote

La méthode "write_getinfo_pm" du module DBI::DBD::Metadata génère un package DBD::Driver::GetInfo sur la sortie standard.

Cette méthode génère un package DBD::Driver::GetInfo à partir de la source de données que vous avez spécifiée dans la liste des paramètres ou dans la variable d'environnement DBI_DSN. DBD::Driver::GetInfo devrait aider un auteur de DBD à implémenter la méthode get_info() de DBI. Comme vous créez ce package, il est très peu probable que DBD::Driver fournisse déjà une bonne implémentation pour get_info(). Vous vous connecterez donc probablement via DBD::ODBC.

Une fois que vous êtes sûr que les données produites sont raisonnablement cohérentes, vous devriez généralement rediriger la sortie standard vers lib/DBD/Driver/GetInfo.pm, puis éditer manuellement le résultat. N'oubliez pas de mettre à jour votre Makefile.PL et MANIFEST pour inclure ceci comme un fichier PM supplémentaire à installer.

Si vous vous connectez via DBD::ODBC, vous devriez utiliser la version 0.38 ou supérieure ;

Veuillez examiner attentivement les données retournées ! Les pilotes ODBC varient considérablement en qualité.

Le générateur suppose que la plupart des valeurs sont statiques et place ces valeurs directement dans le hachage %info. Quelques exemples montrent l'utilisation de références CODE et l'implémentation via des sous-routines. Il est très probable que vous devrez écrire des sous-routines supplémentaires pour les valeurs dépendant de l'état de la session ou de la version du serveur, par exemple SQL_DBMS_VER.

Une implémentation possible de DBD::Driver::db::get_info() pourrait ressembler à ceci :

sub get_info {
  my($dbh, $info_type) = @_;
  require DBD::Driver::GetInfo;
  my $v = $DBD::Driver::GetInfo::info{int($info_type)};
  $v = $v->($dbh) if ref $v eq 'CODE';
  return $v;
}

Veuillez remplacer Driver (ou "<foo>") par le nom de votre pilote. Notez que cette fonction stub vous est générée par la fonction write_getinfo_pm, mais vous devez transférer manuellement le code dans Driver.pm.

Génération d'un package TypeInfo pour un pilote

La fonction "write_typeinfo_pm" du module DBI::DBD::Metadata génère sur la sortie standard les données nécessaires à la méthode type_info_all d'un pilote. Elle fournit également des implémentations par défaut de la méthode type_info_all à inclure dans le fichier principal d'implémentation du pilote.

Le paramètre du pilote est le nom du pilote pour lequel les méthodes seront générées ; pour des exemples, ce sera "Driver". Typiquement, le paramètre dsn sera de la forme "dbi:ODBC:odbc_dsn", où odbc_dsn est un DSN pour l'une des bases de données du pilote. Les paramètres user et pass sont les autres paramètres de connexion optionnels qui seront fournis à la méthode de connexion DBI.

Une fois que vous êtes sûr que les données produites sont raisonnablement cohérentes, vous devriez généralement rediriger la sortie standard vers lib/DBD/Driver/TypeInfo.pm, puis éditer manuellement le résultat si nécessaire. N'oubliez pas de mettre à jour votre Makefile.PL et MANIFEST pour inclure ceci comme un fichier PM supplémentaire à installer.

Veuillez examiner attentivement les données retournées ! Les pilotes ODBC varient considérablement en qualité.

Le générateur suppose que toutes les valeurs sont statiques et place ces valeurs directement dans le hachage %info.

Une implémentation possible de DBD::Driver::type_info_all() pourrait ressembler à ceci :

sub type_info_all {
  my ($dbh) = @_;
  require DBD::Driver::TypeInfo;
  return [ @$DBD::Driver::TypeInfo::type_info_all ];
}

Veuillez remplacer Driver (ou "<foo>") par le nom de votre pilote. Notez que cette fonction stub vous est générée par la fonction write_typeinfo_pm, mais vous devez transférer manuellement le code dans Driver.pm.
