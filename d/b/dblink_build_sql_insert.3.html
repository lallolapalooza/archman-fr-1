dblink_build_sql_insert(3)

Paquet: postgresql

Licences: PostgreSQL

DBLINK_BUILD_SQL_INSERT(3) Documentation PostgreSQL 18.1 DBLINK_BUILD_SQL_INSERT(3)

NOM

dblink_build_sql_insert - construit une instruction INSERT en utilisant une tuple locale, remplaçant les valeurs du champ de clé primaire par les valeurs alternatives fournies

SYNTAXE

dblink_build_sql_insert(text relname,
                        int2vector primary_key_attnums,
                        integer num_primary_key_atts,
                        text[] src_pk_att_vals_array,
                        text[] tgt_pk_att_vals_array) returns text

DESCRIPTION

dblink_build_sql_insert peut être utile pour répliquer de manière sélective une table locale vers une base de données distante. Elle sélectionne une ligne de la table locale en se basant sur la clé primaire, puis construit une commande SQL INSERT qui dupliquera cette ligne, mais avec les valeurs de la clé primaire remplacées par les valeurs du dernier argument. (Pour faire une copie exacte de la ligne, spécifiez simplement les mêmes valeurs pour les deux derniers arguments.)

ARGUMENTS

relname

Nom d'une relation locale, par exemple foo ou myschema.mytab. Incluez des guillemets doubles si le nom est en casse mixte ou contient des caractères spéciaux, par exemple "FooBar"; sans guillemets, la chaîne sera convertie en minuscules.

primary_key_attnums

Numéros d'attributs (à partir de 1) des champs de la clé primaire, par exemple 1 2.

num_primary_key_atts

Le nombre de champs de la clé primaire.

src_pk_att_vals_array

Valeurs des champs de la clé primaire utilisées pour rechercher la tuple locale. Chaque champ est représenté sous forme de texte. Une erreur est générée s'il n'y a pas de ligne locale avec ces valeurs de clé primaire.

tgt_pk_att_vals_array

Valeurs des champs de la clé primaire qui seront placées dans la commande INSERT résultante. Chaque champ est représenté sous forme de texte.

VALEUR DE RETOUR

Retourne l'instruction SQL demandée sous forme de texte.

NOTES

Depuis PostgreSQL 9.0, les numéros d'attributs dans primary_key_attnums sont interprétés comme des numéros de colonne logiques, correspondant à la position de la colonne dans SELECT * FROM relname. Les versions précédentes interprétaient les numéros comme des positions de colonne physiques. Il y a une différence si une ou plusieurs colonnes à gauche de la colonne indiquée ont été supprimées pendant la durée de vie de la table.

EXEMPLES

SELECT dblink_build_sql_insert('foo', '1 2', 2, '{"1", "a"}', '{"1", "b''a"}');
             dblink_build_sql_insert
--------------------------------------------------
 INSERT INTO foo(f1,f2,f3) VALUES('1','b''a','1')
(1 row)
