NOM

db2x_xsltproc - enveloppe d'invocation du processeur XSLT

SYNTAXE


db2x_xsltproc
[options] document-xml

DESCRIPTION

db2x_xsltproc invoque le processeur XSLT 1.0 pour docbook2X.

Cette commande applique la feuille de style XSLT (généralement donnée par l'option --stylesheet) au document XML du fichier document-xml. Le résultat est écrit sur la sortie standard (sauf modification avec --output).

Pour lire le document XML source depuis l'entrée standard, spécifiez - comme document d'entrée.

OPTIONS

--version
Affiche la version de docbook2X.

OPTIONS DE SORTIE DE TRANSFORMATION

--output fichier, -o fichier
Écrit la sortie dans le fichier (ou l'URI) donné, au lieu de la sortie standard.

OPTIONS DU DOCUMENT SOURCE

--xinclude, -I
Traite les directives XInclude dans le document source.
--sgml, -S
Indique que le document d'entrée est SGML plutôt que XML. Vous devez définir cette option si document-xml est en réalité un fichier SGML.

L'analyse SGML est implémentée par conversion en XML via sgml2xml(1) du paquet SP (ou osx(1) du paquet OpenSP). Tous les noms de balises du fichier SGML seront normalisés en minuscules (c'est-à-dire que l'option -xlower de sgml2xml(1) est utilisée). Les attributs ID sont disponibles pour la feuille de style (c'est-à-dire l'option -xid). De plus, toutes les entités SDATA ISO utilisées dans le document SGML sont automatiquement converties en leurs équivalents Unicode XML. (Ceci est fait par un filtre sed.)

L'encodage du document SGML, s'il n'est pas us-ascii, doit être spécifié avec les variables d'environnement SP standard : SP_CHARSET_FIXED=1 SP_ENCODING=encodage. (Notez que les fichiers XML spécifient leur encodage avec la déclaration XML <?xml version="1.0" encoding="encodage" ?> en haut du fichier.)

Les options de conversion ci-dessus ne peuvent pas être modifiées. Si vous souhaitez des options de conversion différentes, vous devez invoquer sgml2xml(1) manuellement, puis passer les résultats de cette conversion à ce programme.

OPTIONS DE RÉCUPÉRATION

--catalogs fichiers-catalogue, -C fichiers-catalogue
Spécifie des catalogues XML supplémentaires à utiliser pour résoudre les Identifiants Publics Formels ou les URI. Les catalogues SGML ne sont pas pris en charge.

Ces catalogues ne sont pas utilisés pour analyser un document SGML sous l'option --sgml. Utilisez la variable d'environnement SGML_CATALOG_FILES à la place pour spécifier les catalogues pour l'analyse du document SGML.

--network, -N
db2x_xsltproc refusera normalement de charger des ressources externes depuis le réseau, pour des raisons de sécurité. Si vous souhaitez charger depuis le réseau, définissez cette option.

Habituellement, vous voudrez avoir installé localement les DTD et autres fichiers pertinents, et configuré des catalogues pour ceux-ci, plutôt que de les charger automatiquement depuis le réseau.

OPTIONS DE FEUILLE DE STYLE

--stylesheet fichier, -s fichier
Spécifie le nom de fichier (ou l'URI) de la feuille de style à utiliser. Les valeurs spéciales man et texi sont acceptées comme abréviations, pour spécifier que document-xml est en DocBook et doit être converti en pages de manuel (man) ou en Texinfo (texi) respectivement.
--param nom=expression, -p nom=expression
Ajoute ou modifie un paramètre de la feuille de style. nom est un nom de paramètre XSLT, et expression est une expression XPath qui évalue à la valeur souhaitée pour le paramètre. (Cela signifie que les chaînes doivent être mises entre guillemets, en plus des guillemets habituels des arguments du shell ; utilisez --string-param pour éviter cela.)
--string-param nom=chaîne, -g nom=chaîne
Ajoute ou modifie un paramètre de type chaîne de caractères pour la feuille de style.

La chaîne doit être encodée en UTF-8 (quel que soit l'encodage de caractères de la locale).

DÉBOGAGE ET PROFILAGE

--debug, -d
Affiche, sur la sortie d'erreur, les journaux de ce qui se passe pendant la transformation XSL.
--nesting-limit n, -D n
Modifie le nombre maximum d'appels imbriqués aux templates XSL, utilisé pour détecter les boucles infinies potentielles. Si non spécifié, la limite est de 500 (la valeur par défaut de libxslt).
--profile, -P
Affiche les informations de profilage : le nombre total d'appels à chaque template dans la feuille de style et le temps passé pour chacun. Ces informations sont envoyées sur la sortie d'erreur.
--xslt-processor processeur, -X processeur
Sélectionne le processeur XSLT sous-jacent utilisé. Les choix possibles pour processeur sont : libxslt, saxon, xalan-j.

Le processeur par défaut est celui qui a été défini lors de la compilation de docbook2X. libxslt est recommandé (car il est léger et rapide), mais SAXON est beaucoup plus robuste et serait plus utile lors du débogage des feuilles de style.

Tous les processeurs ont le support des catalogues XML activé. (docbook2X le requiert.) Mais notez que toutes les options ci-dessus ne fonctionnent pas avec des processeurs autres que celui de libxslt.

ENVIRONNEMENT

XML_CATALOG_FILES
Spécifie les catalogues XML. Si non spécifié, le catalogue standard (/etc/xml/catalog) est chargé, s'il est disponible.
DB2X_XSLT_PROCESSOR
Spécifie le processeur XSLT à utiliser. L'effet est le même que l'option --xslt-processor. L'utilisation principale de cette variable est de vous permettre de tester rapidement différents processeurs XSLT sans avoir à ajouter --xslt-processor à chaque script ou fichier make de votre système de construction de documentation.

CONFORMITÉ

XML Stylesheet Language – Transformations (XSLT), version 1.0 ⟨http://www.w3.org/TR/xslt⟩ , une recommandation du W3C.

NOTES

Dans ses versions précédentes (< 0.8.4), docbook2X nécessitait des extensions XSLT pour fonctionner, et db2x_xsltproc était un processeur spécial basé sur libxslt qui avait ces extensions compilées. Lorsque l'exigence des extensions XSLT a été supprimée, db2x_xsltproc est devenu un script Perl qui traduit les options de db2x_xsltproc pour qu'elles soient conformes au format accepté par le xsltproc(1) standard fourni avec libxslt.
