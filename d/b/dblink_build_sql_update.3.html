NOM

dblink_build_sql_update - construit une instruction UPDATE en utilisant un tuple local, remplaçant les valeurs du champ de clé primaire par des valeurs alternatives fournies

SYNOPSIS

dblink_build_sql_update(text relname,
                        int2vector primary_key_attnums,
                        integer num_primary_key_atts,
                        text[] src_pk_att_vals_array,
                        text[] tgt_pk_att_vals_array) returns text

DESCRIPTION

dblink_build_sql_update peut être utile pour répliquer sélectivement une table locale vers une base de données distante. Il sélectionne une ligne de la table locale en fonction de la clé primaire, puis construit une commande SQL UPDATE qui dupliquera cette ligne, mais avec les valeurs de la clé primaire remplacées par les valeurs du dernier argument. (Pour faire une copie exacte de la ligne, spécifiez simplement les mêmes valeurs pour les deux derniers arguments.) La commande UPDATE assigne toujours tous les champs de la ligne — la principale différence entre ceci et dblink_build_sql_insert est qu'on suppose que la ligne cible existe déjà dans la table distante.

ARGUMENTS

relname

Nom d'une relation locale, par exemple foo ou myschema.mytab. Incluez des guillemets doubles si le nom est en casse mixte ou contient des caractères spéciaux, par exemple "FooBar" ; sans guillemets, la chaîne sera convertie en minuscules.

primary_key_attnums

Numéros d'attributs (base 1) des champs de la clé primaire, par exemple 1 2.

num_primary_key_atts

Le nombre de champs de la clé primaire.

src_pk_att_vals_array

Valeurs des champs de la clé primaire utilisées pour rechercher le tuple local. Chaque champ est représenté sous forme de texte. Une erreur est générée s'il n'y a pas de ligne locale avec ces valeurs de clé primaire.

tgt_pk_att_vals_array

Valeurs des champs de la clé primaire à placer dans la commande UPDATE résultante. Chaque champ est représenté sous forme de texte.

VALEUR DE RETOUR

Renvoie l'instruction SQL demandée sous forme de texte.

NOTES

Depuis PostgreSQL 9.0, les numéros d'attributs dans primary_key_attnums sont interprétés comme des numéros de colonne logiques, correspondant à la position de la colonne dans SELECT * FROM relname. Les versions précédentes interprétaient les numéros comme des positions de colonne physiques. Il y a une différence si des colonnes à gauche de la colonne indiquée ont été supprimées au cours de la durée de vie de la table.

EXEMPLES

SELECT dblink_build_sql_update('foo', '1 2', 2, '{"1", "a"}', '{"1", "b"}');
                   dblink_build_sql_update
-------------------------------------------------------------
 UPDATE foo SET f1='1',f2='b',f3='1' WHERE f1='1' AND f2='b'
(1 row)
