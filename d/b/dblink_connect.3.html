dblink_connect(3)

Paquet: postgresql

Licences: PostgreSQL

DBLINK_CONNECT(3) Documentation PostgreSQL 18.1 DBLINK_CONNECT(3)

NOM

dblink_connect - ouvre une connexion persistante à une base de données distante

SYNTAXE

dblink_connect(text connstr) retourne text
dblink_connect(text connname, text connstr) retourne text

DESCRIPTION

dblink_connect() établit une connexion à une base de données PostgreSQL distante. Le serveur et la base de données à contacter sont identifiés par une chaîne de connexion libpq standard. Optionnellement, un nom peut être attribué à la connexion. Plusieurs connexions nommées peuvent être ouvertes simultanément, mais une seule connexion sans nom est autorisée à la fois. La connexion persistera jusqu'à sa fermeture ou jusqu'à la fin de la session de base de données.

La chaîne de connexion peut également être le nom d'un serveur étranger existant. Il est recommandé d'utiliser le wrapper de données étrangères dblink_fdw lors de la définition du serveur étranger. Voir l'exemple ci-dessous, ainsi que CREATE SERVER (CREATE_SERVER(7)) et CREATE USER MAPPING (CREATE_USER_MAPPING(7)).

ARGUMENTS

connname

Le nom à utiliser pour cette connexion ; si omis, une connexion sans nom est ouverte, remplaçant toute connexion sans nom existante.

connstr

Chaîne d'informations de connexion de style libpq, par exemple hostaddr=127.0.0.1 port=5432 dbname=mydb user=postgres password=mypasswd options=-csearch_path=. Pour plus de détails, voir la Section 32.1.1. Alternativement, le nom d'un serveur étranger.

VALEUR RETOURNEE

Retourne le statut, qui est toujours OK (car toute erreur provoque le déclenchement d'une erreur par la fonction au lieu de retourner).

NOTES

Si des utilisateurs non fiables ont accès à une base de données qui n'a pas adopté un schéma d'utilisation sécurisé des schémas, commencez chaque session en supprimant les schémas publiquement écrivables de search_path. On pourrait, par exemple, ajouter options=-csearch_path= à connstr. Cette considération n'est pas spécifique à dblink ; elle s'applique à toutes les interfaces pour exécuter des commandes SQL arbitraires.

Le wrapper de données étrangères dblink_fdw a une option booléenne supplémentaire use_scram_passthrough qui contrôle si dblink utilisera l'authentification de passage SCRAM pour se connecter à la base de données distante. Avec l'authentification de passage SCRAM, dblink utilise des secrets hachés SCRAM au lieu de mots de passe utilisateur en texte brut pour se connecter au serveur distant. Cela évite de stocker des mots de passe utilisateur en texte brut dans les catalogues système PostgreSQL. Voir la documentation de l'option équivalente use_scram_passthrough de postgres_fdw pour plus de détails et de restrictions.

Seuls les super-utilisateurs peuvent utiliser dblink_connect pour créer des connexions qui n'utilisent ni l'authentification par mot de passe, ni le passage SCRAM, ni l'authentification GSSAPI. Si des non-super-utilisateurs ont besoin de cette capacité, utilisez dblink_connect_u à la place.

Il est déconseillé de choisir des noms de connexion contenant des signes égal, car cela ouvre un risque de confusion avec les chaînes d'informations de connexion dans d'autres fonctions dblink.

EXEMPLES

SELECT dblink_connect('dbname=postgres options=-csearch_path=');
 dblink_connect
----------------
 OK
(1 row)
SELECT dblink_connect('myconn', 'dbname=postgres options=-csearch_path=');
 dblink_connect
----------------
 OK
(1 row)
-- Fonctionnalité du WRAPPER DE DONNÉES ÉTRANGÈRES
-- Note : les connexions locales qui n'utilisent pas le passage SCRAM nécessitent
--       l'authentification par mot de passe pour fonctionner correctement. Sinon, vous recevrez
--       l'erreur suivante de dblink_connect() :
--       ERROR:  password is required
--       DETAIL:  Non-superuser cannot connect if the server does not request a password.
--       HINT:  Target server's authentication method must be changed.
CREATE SERVER fdtest FOREIGN DATA WRAPPER dblink_fdw OPTIONS (hostaddr '127.0.0.1', dbname 'contrib_regression');
CREATE USER regress_dblink_user WITH PASSWORD 'secret';
CREATE USER MAPPING FOR regress_dblink_user SERVER fdtest OPTIONS (user 'regress_dblink_user', password 'secret');
GRANT USAGE ON FOREIGN SERVER fdtest TO regress_dblink_user;
GRANT SELECT ON TABLE foo TO regress_dblink_user;
\set ORIGINAL_USER :USER
\c - regress_dblink_user
SELECT dblink_connect('myconn', 'fdtest');
 dblink_connect
----------------
 OK
(1 row)
