NOM

DBD::Gofer::Policy::Base - Classe de base pour les politiques de DBD::Gofer

SYNTAXE

$dbh = DBI->connect("dbi:Gofer:transport=...;policy=...", ...)

DESCRIPTION

DBD::Gofer peut être configuré via un mécanisme de « politique » qui vous permet d'affiner le nombre d'allers-retours vers le serveur Gofer. Les politiques sont regroupées en classes (qui peuvent être sous-classées) et référencées par le nom de la classe.

La classe DBD::Gofer::Policy::Base est la classe de base pour toutes les classes de politiques et décrit tous les éléments de politique individuels.

La politique de base (Base) n'est pas utilisée directement. Vous devriez utiliser une classe de politique dérivée de celle-ci.

CLASSES DE POLITIQUES

Trois classes de politiques sont fournies avec DBD::Gofer :

DBD::Gofer::Policy::pedantic est la plus « transparente » mais la plus lente car elle effectue plus d'allers-retours vers le serveur Gofer.

DBD::Gofer::Policy::classic est un compromis raisonnable - c'est la politique par défaut.

DBD::Gofer::Policy::rush est la plus rapide, mais peut nécessiter des changements de code dans vos applications.

Généralement, la politique par défaut « classic » convient. Lors des premiers tests d'une application existante avec Gofer, il est conseillé de commencer par la politique « pedantic », puis de passer à « classic » ou à une politique personnalisée, pour les tests finaux.

Ce sont des documents temporaires : consultez le code source pour la liste des politiques et leurs valeurs par défaut.

PERSONNALISATION DES POLITIQUES

Il existe trois façons de personnaliser les politiques :

Les classes de politiques sont conçues pour influencer le comportement général de DBD::Gofer avec des programmes existants et non modifiés, de sorte qu'ils fonctionnent de manière raisonnablement optimale sans nécessiter de changements de code. Vous pouvez implémenter de nouvelles classes de politiques en tant que sous-classes des politiques existantes.

Dans de nombreux cas, les éléments de politique individuels peuvent être remplacés au cas par cas dans le code de votre application. Vous le faites en passant un attribut correspondant « <go_<policy_name">> aux méthodes DBI par le code de votre application. Cela vous permet d'affiner le comportement pour des cas particuliers.

Les éléments de politique sont implémentés sous forme de méthodes. Dans de nombreux cas, les méthodes reçoivent des paramètres relatifs au code DBD::Gofer en cours d'exécution. Cela signifie que la politique peut implémenter un comportement dynamique qui varie en fonction des circonstances particulières, telles que l'instruction particulière exécutée.
