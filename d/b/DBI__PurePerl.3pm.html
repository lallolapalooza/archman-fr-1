DBI::PurePerl(3) Documentation Perl contribuée par les utilisateurs DBI::PurePerl(3)

NOM

DBI::PurePerl -- une émulation de DBI utilisant du perl pur (pas de compilation C/XS requise)

SYNOPSIS

BEGIN { $ENV{DBI_PUREPERL} = 2 }
use DBI;

DESCRIPTION

Ceci est une émulation en perl pur des parties internes de DBI. Dans presque tous les cas, vous serez mieux servi en utilisant le DBI standard puisque les portions de la version standard écrites en C le rendent *beaucoup* plus rapide.

Cependant, si vous vous trouvez dans une situation où il n'est pas possible d'installer une version compilée du DBI standard, et que vous utilisez des pilotes DBD en perl pur, alors ce module vous permet d'utiliser la plupart des fonctionnalités courantes de DBI sans avoir besoin de modifications dans vos scripts.

STATUT EXPÉRIMENTAL

DBI::PurePerl est nouveau, veuillez donc le traiter comme expérimental en attendant des tests plus approfondis. Jusqu'à présent, il a passé tous les tests avec DBD::CSV, DBD::AnyData, DBD::XBase, DBD::Sprite, DBD::mysqlPP. Veuillez envoyer les rapports de bogue à Jeff Zucker à <jeff@vpservices.com> avec une copie à <dbi-dev@perl.org>.

UTILISATION

L'utilisation est la même que pour le DBI standard à l'exception que vous devez définir la variable d'environnement DBI_PUREPERL si vous voulez utiliser la version PurePerl.

DBI_PUREPERL == 0 (par défaut) Utiliser toujours le DBI compilé, échouer
                  s'il n'est pas correctement compilé et installé
DBI_PUREPERL == 1 Utiliser le DBI compilé s'il est correctement compilé
                  et installé, sinon utiliser PurePerl
DBI_PUREPERL == 2 Utiliser toujours PurePerl

Vous pouvez définir la variable d'environnement dans votre shell (par exemple avec set ou setenv ou export, etc) ou la définir dans votre script comme ceci :

BEGIN { $ENV{DBI_PUREPERL}=2 }

avant votre "use DBI;".

INSTALLATION

Dans la plupart des situations, installez simplement DBI (voir le pod de DBI pour les détails).

Dans la situation où vous ne pouvez pas installer DBI lui-même, vous pouvez copier manuellement DBI.pm et PurePerl.pm dans les répertoires appropriés.

Par exemple :

cp DBI.pm      /usr/jdoe/mylibs/.
cp PurePerl.pm /usr/jdoe/mylibs/DBI/.

Ajoutez ensuite ceci en haut des scripts :

BEGIN {
  $ENV{DBI_PUREPERL} = 1;      # ou =2
  unshift @INC, '/usr/jdoe/mylibs';
}

(Ou devrions-nous peut-être patcher Makefile.PL pour que si DBI_PUREPERL est défini à 2 avant make, le processus de compilation normal soit ignoré et les fichiers soient installés automatiquement ?)

DIFFÉRENCES ENTRE DBI ET DBI::PurePerl

Attributs

Les attributs booléens retournent toujours des valeurs booléennes mais les valeurs réelles utilisées peuvent être différentes, c'est-à-dire 0 ou undef au lieu d'une chaîne vide.

Certains attributs des descripteurs ne sont soit pas supportés soit ont des fonctionnalités très limitées :

ActiveKids
InactiveDestroy
AutoInactiveDestroy
Kids
Taint
TaintIn
TaintOut

(et probablement d'autres)

Traçage

Les fonctionnalités de traçage sont plus limitées et le code pour gérer le traçage n'est intégré dans DBI:PurePerl que si la variable d'environnement DBI_TRACE est définie. Pour activer le traçage total, vous pouvez définir la variable d'environnement DBI_TRACE comme d'habitude. Mais pour activer le traçage individuel des descripteurs en utilisant la méthode trace() , vous devez aussi définir la variable d'environnement DBI_TRACE, mais en la définissant à 0.

Vérification de l'utilisation des paramètres

Le DBI effectue une vérification basique du nombre de paramètres sur les appels de méthode. DBI::PurePerl ne le fait pas.

Vitesse

DBI::PurePerl est plus lent. Bien que, avec certains pilotes dans certains contextes, cela peut ne pas être très significatif pour vous.

À titre d'exemple... le script test.pl dans la distribution source de DBI contient un simple benchmark qui fait juste :

my $null_dbh = DBI->connect('dbi:NullP:','','');
my $i = 10_000;
$null_dbh->prepare('') while $i--;

En d'autres termes, il prépare simplement une requête, créant et détruisant un descripteur de requête, encore et encore. En utilisant le vrai DBI, cela s'exécute à ~4550 descripteurs par seconde alors que DBI::PurePerl en gère ~2800 par seconde sur la même machine (pas trop mal en fait).

Peut ne pas supporter entièrement hash()

Si vous voulez utiliser le hash de type 1, c'est-à-dire "hash($string,1)" avec DBI::PurePerl, vous aurez besoin de la version 1.56 ou supérieure de Math::BigInt (disponible sur CPAN).

Ne supporte pas preparse()

La méthode DBI->preparse() n'est pas supportée dans DBI::PurePerl.

Ne supporte pas DBD::Proxy

Il y a un problème subtil quelque part que je n'ai pas pu identifier. DBI::ProxyServer semble fonctionner correctement avec DBI::PurePerl mais DBD::Proxy ne fonctionne pas à 100% (ce qui est triste car ce serait bien plus utile :) Essayez de réactiver t/80proxy.t pour DBI::PurePerl pour voir si le problème restant affectera votre utilisation.

Autres

can() - n'a pas de comportement spécial

Veuillez nous informer si vous trouvez d'autres différences entre DBI et DBI::PurePerl.
