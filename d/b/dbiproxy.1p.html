NOM

dbiproxy - Un serveur proxy pour le pilote DBD::Proxy

SYNTAXE

dbiproxy <options> --localport=<port>

DESCRIPTION

Cet outil n'est qu'une interface pour le paquet DBI::ProxyServer. Tout ce qu'il fait est de sélectionner les options de la ligne de commande et d'appeler DBI::ProxyServer::main(). Voir DBI::ProxyServer pour les détails.

Les options disponibles incluent :

--chroot=dir
(UNIX seulement) Après avoir effectué un bind(), change le répertoire racine vers le répertoire donné en effectuant un chroot(). Ceci est utile pour la sécurité, mais restreint beaucoup l'environnement. Par exemple, vous devez charger les pilotes DBI dans le fichier de configuration ou créer des liens physiques vers les sockets Unix, si vos pilotes les utilisent. Par exemple, avec MySQL, un fichier de configuration pourrait contenir les lignes suivantes : 
my $rootdir = '/var/dbiproxy';
my $unixsockdir = '/tmp';
my $unixsockfile = 'mysql.sock';
foreach $dir ($rootdir, "$rootdir$unixsockdir") {
    mkdir 0755, $dir;
}
link("$unixsockdir/$unixsockfile",
     "$rootdir$unixsockdir/$unixsockfile");
require DBD::mysql;
{
    'chroot' => $rootdir,
    ...
}

Si vous ne connaissez pas chroot(), pensez à un serveur FTP où vous ne pouvez voir une arborescence de répertoires donnée qu'après vous être connecté. Voir aussi les options --group et --user.

--configfile=file
Les fichiers de configuration sont supposés retourner une seule référence de hachage qui remplace les arguments de la nouvelle méthode. Cependant, les arguments de la ligne de commande ont à leur tour la priorité sur le fichier de configuration. Voir la section "FICHIER DE CONFIGURATION" dans la documentation de DBI::ProxyServer pour les détails sur le fichier de configuration.
--debug
Active le mode de débogage. Principalement, cela garantit que les messages de journalisation de niveau "debug" sont créés.
--facility=mode
(UNIX seulement) Installation à utiliser pour Sys::Syslog. Par défaut, daemon.
--group=gid
Après avoir effectué un bind(), change le GID réel et effectif au donné. Ceci est utile si vous voulez que votre serveur se lie à un port privilégié (<1024), mais ne voulez pas que le serveur s'exécute en tant que root. Voir aussi l'option --user.

Les GID peuvent être passés sous forme de noms de groupe ou de valeurs numériques.

--localaddr=ip
Par défaut, un démon écoute sur n'importe quel numéro IP qu'une machine possède. Cet attribut permet de restreindre le serveur au numéro IP donné.
--localport=port
Cet attribut définit le port sur lequel le démon écoute. Il doit être donné d'une manière ou d'une autre, car il n'y a pas de valeur par défaut.
--logfile=file
Par défaut, les messages de journalisation seront écrits dans syslog (Unix) ou dans le journal des événements (Windows NT). Sur d'autres systèmes d'exploitation, vous devez spécifier un fichier journal. La valeur spéciale "STDERR" force la journalisation vers stderr. Voir Net::Daemon::Log pour les détails.
--mode=modename
Le serveur peut fonctionner dans trois modes différents, selon l'environnement.

Si vous utilisez Perl 5.005 et l'avez compilé pour les threads, alors le serveur créera un nouveau thread pour chaque connexion. Le thread exécutera la méthode Run() du serveur puis se terminera. Ce mode est par défaut, vous pouvez le forcer avec "--mode=threads".

Si les threads ne sont pas disponibles, mais que vous avez un fork() fonctionnel, alors le serveur se comportera de manière similaire en créant un nouveau processus pour chaque connexion. Ce mode sera utilisé automatiquement en l'absence de threads ou si vous utilisez l'option "--mode=fork".

Enfin, il existe un mode à connexion unique : lorsque le serveur a accepté une connexion, il entrera dans la méthode Run(). Aucune autre connexion ne sera acceptée tant que la méthode Run() ne sera pas retournée (si le client se déconnecte). Ce mode de fonctionnement est utile si vous n'avez ni threads ni fork(), par exemple sur Macintosh. À des fins de débogage, vous pouvez forcer ce mode avec "--mode=single".

--pidfile=file
(UNIX seulement) Si cette option est présente, un fichier PID sera créé à l'emplacement donné. Par défaut, aucun fichier PID n'est créé.
--user=uid
Après avoir effectué un bind(), change l'UID réel et effectif au donné. Ceci est utile si vous voulez que votre serveur se lie à un port privilégié (<1024), mais ne voulez pas que le serveur s'exécute en tant que root. Voir aussi les options --group et --chroot.

Les UID peuvent être passés sous forme de noms de groupe ou de valeurs numériques.

--version
Supprime le démarrage du serveur ; au lieu de cela, la chaîne de version sera affichée et le programme se terminera immédiatement.
