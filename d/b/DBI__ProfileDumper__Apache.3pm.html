DESCRIPTIO

N

Ce module relie DBI::ProfileDumper à Apache/mod_perl. En utilisant ce module, vous pouvez collecter des données de profilage à partir

d'applications mod_perl. Il fonctionne en créant un fichier de données DBI::ProfileDumper pour chaque processus Apache. Ces fichiers son
t créés dans votre répertoire de logs Apache. Vous pouvez ensuite utiliser l'utilitaire dbiprof pour analyser les fichiers de profil.

UTILISATI

ON

CHARGEMENT DU

MODULE

La façon la plus simple d'utiliser ce module est de définir la variable d'environnement DBI_PROFILE dans votre httpd.co

nf : 
PerlSetEnv DBI_PROFILE 2/DBI::ProfileDumper::
Apache

DBI se chargera de charger et d'utiliser le module lorsque le premier descripteur DBI est

créé.

Il est également possible d'utiliser ce module en définissant l'attribut Profile de n'importe quel descripteur DBI

: 
$dbh->{Profile} = "2/DBI::ProfileDumper::
Apache";

Consultez DBI::ProfileDumper pour plus de pos

sibilités, et DBI::Profile pour tous les
détails sur le mécanisme de profilage de DBI.

ÉCRITURE DES DONNÉES DE

PROFIL

Les fichiers de données de profil seront écrits par défaut dans votre répertoire de logs

Apache.

L'utilisateur sous lequel les processus httpd s'exécutent devra avoir un accès en écriture au répertoire. Ainsi, par exemple, si vous exécutez les processus httpd enfants en tant qu'utilisateur « nobody » et utilisez chronolog pour écrire dans le répertoire de logs, vous devrez modifier la valeur par

défaut.

Vous pouvez changer le répertoire de destination soit en spécifiant une valeur « Dir » lors de la création du profil (comme « File » dans la documentation de DBI::ProfileDumper), soit en utilisant la variable d'environnement « DBI_PROFILE_APACHE_LOG_DIR » pour changer cela. Par exemple

: 
PerlSetEnv DBI_PROFILE_APACHE_LOG_DIR /racine_du_serveur/log
s

Lors de l'utilisation de

mod_perl2

Sous mod_perl2, vous devrez soit définir la variable d'environnement « DBI_PROFILE_APACHE_LOG_DIR », soit activer l'option mod_perl2 « GlobalRequest », comme ceci

: 
PerlOptions
+GlobalRequest

dans la section de configuration globale que vous êtes sur le point de tester avec DBI::ProfileDumper::Apache. Si vous ne faites pas l'un de ces deux, vous verrez des messages dans votre error_log similaires à

: 
DBI::ProfileDumper::Apache on_destroy failed: Global $r object is not available. Set:
  PerlOptions +GlobalRequest in httpd.conf at ..../DBI/ProfileDumper/Apache.pm line
144

Nommage des

fichiers

Le nom de fichier par défaut est hérité de DBI::ProfileDumper via la méthode filename(), mais DBI::ProfileDumper::Apache ajoute le pid parent et le pid courant, séparés par des points, à ce

nom.

Silencier le

journal

Par défaut, un message est écrit sur STDERR (c'est-à-dire le fichier error_log d'apache) lorsque flush_to_disk() est appelé (soit explicitement, soit implicitement via DESTROY)

.

C'est généralement très utile. Si vous ne voulez pas du message de journal, vous pouvez le silencer en définissant l'attribut « Quiet

» 
à
vra
i.

PerlSetEnv DBI_PROFILE 2/DBI::ProfileDumper::Apache/Quiet:1 $dbh->{Profile} = "!Statement/DBI::ProfileDumper/Quiet:1"; $dbh->{Profile} = DBI::ProfileDumper->new( Path => [ '!Statement' ] Quiet

=> 1 );

AUTRES

QUESTIONS

Utilisation de la mémoire DBI::Profile peut utiliser beaucoup de mémoire pour les applications très actives car il collecte les données de profilage en mémoire pour chaque requête distincte exécutée.

Appeler 
flush_to_disk() écrira les données actuelles sur le disque
    et libérera la mémoire qu'il utilise. Par exemple
:

$dbh->{Profile}->flush_to_disk() if $dbh->{Profile}

; 
ou, plutôt que de vi
der à chaque fois,
vous pourriez vider
moins souvent :

$dbh->{Profile}->flush_to_disk() if $dbh->{Profile} and

++$i % 100;
