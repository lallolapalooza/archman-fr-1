dblink(3)

Paquet: postgresql

Licences: PostgreSQL

DBLINK(3) Documentation PostgreSQL 18.1 DBLINK(3)

NOM

dblink - exécute une requête dans une base de données distante

SYNTAXE

dblink(text nom_connexion, text sql [, bool ignorer_erreur]) returns setof record
dblink(text chaine_connexion, text sql [, bool ignorer_erreur]) returns setof record
dblink(text sql [, bool ignorer_erreur]) returns setof record

DESCRIPTION

dblink exécute une requête (généralement un SELECT, mais cela peut être n'importe quelle instruction SQL qui retourne des lignes) dans une base de données distante.

Lorsque deux arguments texte sont fournis, le premier est d'abord recherché comme nom de connexion persistante ; s'il est trouvé, la commande est exécutée sur cette connexion. S'il n'est pas trouvé, le premier argument est traité comme une chaîne d'informations de connexion comme pour dblink_connect, et la connexion indiquée est établie uniquement pour la durée de cette commande.

ARGUMENTS

nom_connexion

Nom de la connexion à utiliser ; omettre ce paramètre pour utiliser la connexion sans nom.

chaine_connexion

Une chaîne d'informations de connexion, comme décrit précédemment pour dblink_connect.

sql

La requête SQL que vous souhaitez exécuter dans la base de données distante, par exemple select * from foo.

ignorer_erreur

Si vrai (la valeur par défaut lorsqu'elle est omise), une erreur levée côté distant de la connexion provoque également une erreur locale. Si faux, l'erreur distante est signalée localement comme un NOTICE, et la fonction ne retourne aucune ligne.

VALEUR DE RETOUR

La fonction retourne la ou les lignes produites par la requête. Puisque dblink peut être utilisé avec n'importe quelle requête, il est déclaré pour retourner un enregistrement (record), plutôt que de spécifier un ensemble particulier de colonnes. Cela signifie que vous devez spécifier l'ensemble attendu de colonnes dans la requête appelante ; sinon PostgreSQL ne saurait pas quoi attendre. Voici un exemple :

SELECT *
    FROM dblink('dbname=mydb options=-csearch_path=',
                'select proname, prosrc from pg_proc')
      AS t1(proname name, prosrc text)
    WHERE proname LIKE 'bytea%';

La partie « alias » de la clause FROM doit spécifier les noms et types de colonnes que la fonction retournera. (Spécifier des noms de colonnes dans un alias est en fait une syntaxe SQL standard, mais spécifier des types de colonnes est une extension PostgreSQL.) Cela permet au système de comprendre ce que * représente et à quoi se réfère proname dans la clause WHERE, avant d'essayer d'exécuter la fonction. À l'exécution, une erreur sera levée si le résultat réel de la requête de la base de données distante n'a pas le même nombre de colonnes que celui indiqué dans la clause FROM. Les noms de colonnes n'ont pas besoin de correspondre, et dblink n'insiste pas non plus sur des correspondances de types exactes. Cela réussira tant que les chaînes de données retournées sont des entrées valides pour le type de colonne déclaré dans la clause FROM.

NOTES

Un moyen pratique d'utiliser dblink avec des requêtes prédéterminées est de créer une vue. Cela permet aux informations de type de colonne d'être intégrées dans la vue, au lieu d'avoir à les épeler dans chaque requête. Par exemple,

CREATE VIEW myremote_pg_proc AS
  SELECT *
    FROM dblink('dbname=postgres options=-csearch_path=',
                'select proname, prosrc from pg_proc')
    AS t1(proname name, prosrc text);
SELECT * FROM myremote_pg_proc WHERE proname LIKE 'bytea%';
