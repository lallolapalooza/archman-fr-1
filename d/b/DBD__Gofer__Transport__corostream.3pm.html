NOM

DBD::Gofer::Transport::corostream - Transport de flux asynchrone DBD::Gofer utilisant Coro et AnyEvent

SYNTAXE

DBI_AUTOPROXY="dbi:Gofer:transport=corostream" perl script-perl-utilisant-dbi.pl

ou

$dsn = ...; # le DSN pour le pilote et la base de données que vous souhaitez utiliser
$dbh = DBI->connect("dbi:Gofer:transport=corostream;dsn=$dsn", ...);

DESCRIPTION

Le GRAND AVANTAGE de l'utilisation de Coro est qu'il permet l'utilisation de frameworks DBI existants tels que DBIx::Class.

PROBLÈMES CONNUS ET LIMITATIONS

- Utilise Coro::Select, modifie donc CORE::select globalement
  La classe parente a probablement besoin d'être refactorisée pour permettre une approche plus encapsulée.
- N'empêche pas les requêtes concurrentes multiples
  Probablement juste besoin d'un sémaphore par connexion
- Coro a de nombreuses mises en garde. Attention à l'acheteur.

ANNEXE

Exemple de code :

#!perl
use strict;
use warnings;
use Time::HiRes qw(time);
BEGIN { $ENV{PERL_ANYEVENT_STRICT} = 1; $ENV{PERL_ANYEVENT_VERBOSE} = 1; }
use AnyEvent;
BEGIN { $ENV{DBI_TRACE} = 0; $ENV{DBI_GOFER_TRACE} = 0; $ENV{DBD_GOFER_TRACE} = 0; };
use DBI;
$ENV{DBI_AUTOPROXY} = 'dbi:Gofer:transport=corostream';
my $ticker = AnyEvent->timer( after => 0, interval => 0.1, cb => sub {
    warn sprintf "-tick- %.2f\n", time
} );
warn "connecting...\n";
my $dbh = DBI->connect("dbi:NullP:");
warn "...connected\n";
for (1..3) {
    warn "entering DBI...\n";
    $dbh->do("sleep 0.3"); # pseudo-sql compris par le pilote DBD::NullP
    warn "...returned\n";
}
warn "done.";
