DESCRIPTION

Ce document décrit comment les développeurs de DBD peuvent écrire des pilotes DBI basés sur DBD::File. Il complète DBI::DBD et DBI::DBD::SqlEngine::Developers, que vous devriez lire en premier.

CLASSES

Chaque pilote DBI doit fournir une méthode globale au paquet "driver" et trois classes liées à DBI :

DBD::File::dr
Paquet du pilote, contient les méthodes que DBI appelle indirectement via l'interface DBI : 
DBI->connect ('DBI:DBM:', undef, undef, {})
# invokes
package DBD::DBM::dr;
@DBD::DBM::dr::ISA = qw( DBD::File::dr );
sub connect ($$;$$$)
{
    ...
    }

De même pour "data_sources" et "disconnect_all".

Les pilotes DBI en Perl pur dérivés de DBD::File n'ont généralement pas besoin de redéfinir l'une des méthodes fournies via le paquet DBD::XXX::dr, cependant, si vous avez besoin d'une initialisation supplémentaire dans la méthode connect, vous devrez peut-être le faire.

DBD::File::db
Contient les méthodes qui sont appelées via les poignées de base de données DBI ($dbh). p. ex., 
$sth = $dbh->prepare ("select * from foo");
# returns the f_encoding setting for table foo
$dbh->csv_get_meta ("foo", "f_encoding");

DBD::File fournit les méthodes typiques requises ici. Les développeurs qui écrivent des pilotes DBI basés sur DBD::File doivent redéfinir les méthodes "set_versions" et "init_valid_attributes".

DBD::File::st
Contient les méthodes pour gérer les poignées de déclarations préparées. p. ex., 
$sth->execute () or die $sth->errstr;

DBD::File

C'est le paquet principal contenant les routines pour initialiser les pilotes DBI basés sur DBD::File. Principalement la "DBD::File::driver" méthode est invoquée, soit directement par DBI lorsque le pilote est initialisé, soit par la classe dérivée.

package DBD::DBM;
use base qw( DBD::File );
sub driver
{
    my ($class, $attr) = @_;
    ...
    my $drh = $class->SUPER::driver ($attr);
    ...
    return $drh;
    }

Il n'est pas nécessaire d'implémenter votre propre méthode driver tant que une initialisation supplémentaire (p. ex. l'installation de plus de méthodes de pilote privées) n'est pas requise. Vous n'avez pas besoin d'appeler "setup_driver" car DBD::File s'en charge.

DBD::File::dr

Le paquet du pilote contient les méthodes que DBI appelle indirectement via l'interface DBI (voir « DBI Class Methods » dans DBI).

Les pilotes DBI basés sur DBD::File n'ont généralement pas besoin d'implémenter quoi que ce soit ici, il suffit de faire l'initialisation de base :

package DBD:XXX::dr;
@DBD::XXX::dr::ISA = qw (DBD::File::dr);
$DBD::XXX::dr::imp_data_size     = 0;
$DBD::XXX::dr::data_sources_attr = undef;
$DBD::XXX::ATTRIBUTION = "DBD::XXX $DBD::XXX::VERSION by Hans Mustermann";

DBD::File::db

Ce paquet définit les méthodes de base de données, qui sont appelées via la poignée de base de données DBI $dbh.

Méthodes fournies par DBD::File :

ping
Renvoie simplement le contenu de l'attribut "Active" . Redéfinissez-le si votre pilote a besoin d'actions plus complexes ici.
prepare
Prépare une nouvelle déclaration SQL à exécuter. Renvoie une poignée de déclaration, $sth - instance de DBD:XXX::st. Il n'est ni requis ni recommandé de redéfinir cette méthode.
FETCH
Récupère un attribut d'un objet base de données DBI. Les attributs privés de poignée doivent avoir un préfixe (c'est obligatoire). Si un attribut demandé est détecté comme attribut privé sans préfixe valide, le préfixe du pilote (écrit $drv_prefix) est ajouté.

Le préfixe du pilote est extrait du nom de l'attribut et vérifié par rapport à "$dbh->{$drv_prefix . "valid_attrs"}" (quand il existe). Si la valeur de l'attribut demandé n'est pas listée comme attribut valide, cette méthode provoque une erreur fatale. Si l'attribut est valide et en lecture seule (listé dans "$dbh->{ $drv_prefix . "readonly_attrs" }" quand il existe), une copie réelle de la valeur de l'attribut est renvoyée. Il n'est donc pas possible de modifier "f_valid_attrs" de l'extérieur de DBD::File::db ou d'une classe dérivée.

STORE
Stocke un attribut privé de base de données. Les attributs privés de poignée doivent avoir un préfixe (c'est obligatoire). Si un attribut demandé est détecté comme un attribut privé sans préfixe valide, le préfixe du pilote (écrit $drv_prefix) est ajouté. Si la poignée de base de données a un attribut "${drv_prefix}_valid_attrs" - pour les noms d'attributs qui ne sont pas listés dans ce hachage, cette méthode provoque une erreur fatale. Si la poignée de base de données a un attribut "${drv_prefix}_readonly_attrs", seuls les attributs qui ne sont pas listés là peuvent être stockés (une fois qu'ils sont initialisés). Tenter d'écraser un tel attribut immuable force cette méthode à provoquer une erreur fatale.

Un exemple de liste d'attributs valides peut être trouvé dans "DBD::File::db::init_valid_attributes".

set_versions
Cette méthode définit l'attribut "f_version" avec la version de DBD::File.

Cette méthode est appelée au début de la phase "connect ()" .

Lorsque vous redéfinissez cette méthode, n'oubliez pas d'invoquer la méthode supérieure.

init_valid_attributes
Cette méthode est appelée après que la poignée de base de données est instanciée comme première initialisation d'attribut.

"DBD::File::db::init_valid_attributes" initialise les attributs "f_valid_attrs" et "f_readonly_attrs".

Lorsque vous redéfinissez cette méthode, n'oubliez pas d'invoquer la méthode supérieure, de préférence avant de faire quoi que ce soit d'autre. L'accès aux attributs de compatibilité doit be initialisé ici pour permettre à DBD::File d'instancier le tie de la map :

# pour DBD::CSV
$dbh->{csv_meta} = "csv_tables";
# pour DBD::DBM
$dbh->{dbm_meta} = "dbm_tables";
# pour DBD::AnyData
$dbh->{ad_meta}  = "ad_tables";
init_default_attributes
Cette méthode est appelée après l'instanciation du handle de base de données pour initialiser les attributs par défaut.

"DBD::File::db::init_default_attributes" initialise les attributs "f_dir", "f_meta", "f_meta_map", "f_version".

Lorsque la classe d'implémentation dérivée fournit l'attribut pour valider les attributs (par ex. "$dbh->{dbm_valid_attrs} = {...};") ou l'attribut contenant les attributs immuables (par ex. "$dbh->{dbm_readonly_attrs} = {...};"), les attributs "drv_valid_attrs", "drv_readonly_attrs", "drv_version" et "drv_meta" sont ajoutés (lorsqu'ils sont disponibles) à la liste des attributs valides et immuables (où "drv_" est interprété comme le préfixe du pilote).

Si "drv_meta" est défini, un attribut portant le nom de "drv_meta" est initialisé, fournissant un accès en lecture/écriture restreint aux métadonnées des tables en utilisant "DBD::File::TieTables" au premier niveau (table) et "DBD::File::TieMeta" pour le niveau de l'attribut méta. "DBD::File::TieTables" utilise "DBD::DRV::Table::get_table_meta" pour initialiser le hash lié du second niveau sur FETCH/STORE. La classe "DBD::File::TieMeta" utilise "DBD::DRV::Table::get_table_meta_attr" pour FETCH les valeurs d'attributs et "DBD::DRV::Table::set_table_meta_attr" pour STORE les valeurs d'attributs. Cela lui permet de faire correspondre les attributs méta pour des raisons de compatibilité.

get_single_table_meta
get_file_meta
Récupère un attribut à partir des métadonnées d'une table. La signature de la méthode est "get_file_meta ($dbh, $table, $attr)". Cette méthode est appelée par la méthode de handle de base de données injectée "${drv_prefix}get_meta".

Alors que get_file_meta permet $table ou $attr d'être une liste de tables ou d'attributs à récupérer, get_single_table_meta n'autorise qu'un seul nom de table et un seul nom d'attribut. Un nom de table '.' (point unique) est interprété comme la table par défaut et cela récupérera l'attribut approprié globalement depuis le dbh. Cela a les mêmes restrictions que "$dbh->{$attrib}".

get_file_meta autorise '+' et '*' comme caractères génériques pour les noms de tables et $table pouvant être une expression régulière correspondant aux noms de tables (évaluée sans la table par défaut). Le nom de table '*' est toutes les tables actuellement connues, y compris la table par défaut. Le nom de table '+' est tous les noms de tables qui sont conformes aux restrictions de nom de fichier ANSI (/^[_A-Za-z0-9]+$/).

Les métadonnées de la table sont récupérées en utilisant les méthodes get_table_meta et get_table_meta_attr de la classe table de l'implémentation.

set_single_table_meta
set_file_meta
Définit un attribut dans les métadonnées d'une table. La signature de la méthode est "set_file_meta ($dbh, $table, $attr, $value)". Cette méthode est appelée par la méthode de handle de base de données injectée "${drv_prefix}set_meta".

Alors que set_file_meta permet $table d'être une liste de tables et $attr d'être un hash de plusieurs attributs à définir, set_single_table_meta n'autorise qu'un seul nom de table et un seul couple nom de attribut/valeur.

Les caractères génériques pour le nom de table sont les mêmes que pour get_file_meta.

Les métadonnées de la table sont mises à jour en utilisant les méthodes get_table_meta et set_table_meta_attr de la classe table de l'implémentation.

clear_file_meta
Efface toutes les métadonnées en cache concernant une table. La signature de la méthode est "clear_file_meta ($dbh, $table)". Cette méthode est appelée par la méthode de handle de base de données injectée "${drv_prefix}clear_meta".

DBD::File::st

Contient les méthodes pour gérer les handles de requêtes préparées :

FETCH
Récupère les attributs du handle de requête. Les attributs pris en charge (pour un aperçu complet voir "Statement Handle Attributes" dans DBI) sont "NAME", "TYPE", "PRECISION" et "NULLABLE" dans le cas où SQL::Statement est utilisé comme moteur d'exécution SQL et une requête est préparée avec succès. Lorsque SQL::Statement a des informations supplémentaires sur une table, ces informations sont retournées. Sinon, les mêmes valeurs par défaut que dans DBI::DBD::SqlEngine sont utilisées.

Cette méthode nécessite généralement d'être étendue dans une implémentation dérivée. Voir DBD::CSV ou DBD::DBM pour quelques exemples.

DBD::File::TableSource::FileSystem

Fournit les sources de données et les informations de table au niveau du pilote de base de données et du handle de base de données.

package DBD::File::TableSource::FileSystem;
sub data_sources ($;$)
{
    my ($class, $drh, $attrs) = @_;
    ...
    }
sub avail_tables
{
    my ($class, $drh) = @_;
    ...
    }

La méthode "data_sources" est appelée lorsque l'utilisateur invoce l'une des commandes suivantes :

@ary = DBI->data_sources ($driver);
@ary = DBI->data_sources ($driver, \%attr);

@ary = $dbh->data_sources ();
@ary = $dbh->data_sources (\%attr);

La méthode "avail_tables" est appelée lorsque l'utilisateur invoque l'une des commandes suivantes :

@names = $dbh->tables ($catalog, $schema, $table, $type);

$sth   = $dbh->table_info ($catalog, $schema, $table, $type);
$sth   = $dbh->table_info ($catalog, $schema, $table, $type, \%attr);
$dbh->func ("list_tables");

Chaque fois qu'un argument "\%attr" peut être spécifié, l'attribut "sql_table_source" de cet objet "\%attr" est préféré à l'attribut $dbh ou à la valeur par défaut du pilote.

sub can_flock { ... }

Indique si "flock (2)" est disponible ou non (évite de retester dans les sous-classes).

DBD::File::DataSource::File

package DBD::File::DataSource::File;
sub complete_table_name ($$;$)
{
    my ($self, $meta, $table, $respect_case) = @_;
    ...
    }

La méthode "complete_table_name" essaie de faire correspondre un nom de fichier au nom de table associé. Elle est appelée avec une structure de métadonnées partiellement remplie pour la table résultante contenant au moins les attributs suivants : "f_ext", "f_dir", "f_lockfile" et "sql_identifier_case".

Si une correspondance fichier/table peut être trouvée, alors cette méthode définit les attributs "f_fqfn", "f_fqbn", "f_fqln" et "table_name" dans la structure de métadonnées. Si une correspondance ne peut pas être trouvée, le nom de table sera undef.

package DBD::File::DataSource::File;
sub open_data ($)
{
    my ($self, $meta, $attrs, $flags) = @_;
    ...
    }

Selon les attributs définis dans les métadonnées de la table, les étapes suivantes sont effectuées. À moins que "f_dontopen" ne soit défini à une valeur vraie, "f_fqfn" doit contenir le nom de fichier entièrement qualifié pour la table à traiter (file2table garantit cela). L'encodage dans "f_encoding" est appliqué s'il est défini et le fichier est ouvert. Si "<f_fqln "> (entièrement nom de verrou qualifié) est défini, ce fichier est également ouvert. Selon la valeur dans "f_lock", le verrou approprié est défini sur le fichier de données ou le fichier de verrouillage ouvert.

DBD::File::Statement

Dérive de DBI::SQL::Nano::Statement pour fournir la méthode suivante :

open_table
Implémente la méthode open_table requise par SQL::Statement et DBI::SQL::Nano. Tout le travail d'ouverture des fichiers appartenant à la table est géré et paramétré dans DBD::File::Table. À moins que vous ne prévoyez d'ajouter quelque chose à l'implémentation suivante, un paquet DBD::XXX::Statement vide satisfait DBD::File. 
sub open_table ($$$$$)
{
    my ($self, $data, $table, $createMode, $lockMode) = @_;
    my $class = ref $self;
    $class =~ s/::Statement/::Table/;
    my $flags = {
        createMode => $createMode,
        lockMode   => $lockMode,
        };
    $self->{command} eq "DROP" and $flags->{dropMode} = 1;
    return $class->new ($data, { table => $table }, $flags);
    } # open_table

DBD::File::Table

Dérive de DBI::SQL::Nano::Table et fournit l'accès physique aux données de la table qui sont stockées dans les fichiers.

bootstrap_table_meta
Initialise une structure de métadonnées de table. Peut être surchargée en toute sécurité dans une classe dérivée, à condition que la "SUPER" méthode soit appelée à la fin de la méthode surchargée.

Elle copie les attributs suivants de la base de données vers les métadonnées de la table : "f_dir", "f_ext", "f_encoding", "f_lock", "f_schema" et "f_lockfile" et les rend collants à la table.

Cette méthode devrait être appelée avant de tenter de faire la correspondance entre le nom de fichier et le nom de table afin de s'assurer que le bon répertoire, la bonne extension, etc. sont utilisés.

init_table_meta
Initialise d'autres attributs des métadonnées de la table - généralement des attributs plus coûteux (par exemple ceux qui nécessitent l'instanciation de classes) - lorsque le nom de fichier et le nom de table ont pu être mis en correspondance.
get_table_meta
Retourne les métadonnées de la table. S'il n'y en a pas pour la table requise, une nouvelle structure est initialisée. En cas d'échec, rien n'est retourné. En cas de succès, le nom de la table et la structure des métadonnées sont retournés.
get_table_meta_attr
Retourne un attribut unique des métadonnées de la table. Si le nom de l'attribut apparaît dans %compat_map, le nom de l'attribut est mis à jour à partir de celui-ci.
set_table_meta_attr
Définit un attribut unique dans les métadonnées de la table. Si le nom de l'attribut apparaît dans %compat_map, le nom de l'attribut est mis à jour à partir de celui-ci.
table_meta_attr_changed
Appelé lorsqu'un attribut des métadonnées est modifié.

Si l'attribut modifié nécessite de réinitialiser un attribut calculé, l'attribut calculé est réinitialisé (supprimé de la structure des métadonnées) et le initialized flag est également supprimé. La décision est prise sur la base de %register_reset_on_modify.

register_reset_on_modify
Permet à "set_table_meta_attr" de réinitialiser des attributs de métadonnées lorsque des attributs spéciaux sont modifiés. Pour DBD::File, la modification de l'un de "f_file", "f_dir", "f_ext" ou "f_lockfile" réinitialisera "f_fqfn". DBD::DBM étend la liste pour "dbm_type" et "dbm_mldbm" afin de réinitialiser la valeur de "dbm_tietype".

Si votre DBD a des valeurs calculées dans la zone des métadonnées, appelez alors "register_reset_on_modify":

my %reset_on_modify = (xxx_foo => "xxx_bar");
__PACKAGE__->register_reset_on_modify (\%reset_on_modify);
register_compat_map
Permet à "get_table_meta_attr" et "set_table_meta_attr" de mettre à jour le nom de l'attribut vers celui actuellement préféré : 
# from DBD::DBM
my %compat_map = (dbm_ext => "f_ext");
__PACKAGE__->register_compat_map (\%compat_map);
open_file
Appelé pour ouvrir le fichier de données de la table.

Selon les attributs définis dans les métadonnées de la table, les étapes suivantes sont effectuées. À moins que "f_dontopen" ne soit défini à une valeur vraie, "f_fqfn" doit contenir le nom de fichier qualifié complet pour que la table fonctionne (file2table garantit cela). L'encodage dans "f_encoding" est appliqué s'il est défini et le fichier est ouvert. Si "<f_fqln "> (nom de verrouillage qualifié complet) est défini, ce fichier est également ouvert. Selon la valeur dans "f_lock", le verrou approprié est défini sur le fichier de données ou le fichier de verrouillage ouvert.

Une fois cela fait, une classe dérivée peut ajouter d'autres étapes dans une méthode "open_file" surchargée.

new
Instancie la table. Cela se fait en 3 étapes : 
1. obtenir les métadonnées de la table
2. ouvrir le fichier de données
3. bénir la structure de données de la table en utilisant le constructeur hérité new

Il n'est pas recommandé de surcharger le constructeur de la classe de table. Trouvez un endroit raisonnable pour ajouter vos extensions dans l'une des quatre méthodes ci-dessus.

drop
Implémente la méthode abstraite de table pour la commande "DROP" . Jette les métadonnées de la table après que tous les fichiers appartenant à la table ont été fermés et déliés.

Surcharger cette méthode pourrait être raisonnable dans de très rares cas.

seek
Implémente la méthode abstraite de table utilisée lors de l'accès à la table depuis le moteur. "seek" est appelé chaque fois que le moteur utilise des algorithmes naïfs pour parcourir le contenu de la table.
truncate
Implémente la méthode abstraite de table utilisée lorsque les algorithmes naïfs de table pour "UPDATE" ou "DELETE" doivent tronquer le stockage de la table après la dernière ligne écrite.

Vous devriez consulter la documentation de "SQL::Eval::Table" (voir SQL::Eval) pour obtenir plus d'informations sur les méthodes abstraites de la classe de base de la table que vous devez surcharger et une description des informations de métadonnées de table attendues par les moteurs SQL.
