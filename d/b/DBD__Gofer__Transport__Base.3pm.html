NOM

DBD::Gofer::Transport::Base - classe de base pour les transports clients de DBD::Gofer

SYNTAXE

my $remote_dsn = "..."
DBI->connect("dbi:Gofer:transport=...;url=...;timeout=...;retry_limit=...;dsn=$remote_dsn",...)

ou, activer en définissant la variable d'environnement DBI_AUTOPROXY :

export DBI_AUTOPROXY='dbi:Gofer:transport=...;url=...'

ce qui forcera *toutes* les connexions DBI à passer par ce serveur Gofer.

DESCRIPTION

Ceci est la classe de base pour tous les transports clients de DBD::Gofer.

ATTRIBUTS

Les attributs de transport Gofer peuvent être spécifiés soit dans le paramètre des attributs de l'appel de la méthode connect(), soit dans la chaîne DSN. Lorsqu'ils sont utilisés dans la chaîne DSN, les noms des attributs n'ont pas le préfixe "go_".

go_dsn

Le DSN DBI complet auquel le serveur Gofer doit se connecter en votre nom.

Lorsqu'il est utilisé dans le DSN, il doit être le dernier élément de la chaîne DSN.

go_timeout

Une limite de temps pour l'envoi d'une requête et la réception d'une réponse. Certains pilotes peuvent implémenter l'envoi et la réception comme des étapes distinctes, auquel cas (actuellement) le timeout s'applique à chacun séparément.

Si une requête doit être renvoyée, le timeout est redémarré pour chaque envoi d'une requête et réception d'une réponse.

go_retry_limit

Le nombre maximum de fois qu'une requête peut être retentée. La valeur par défaut est 2.

go_retry_hook

Cette référence de sous-routine est appelée, si elle est définie, pour chaque réponse reçue où $response->err est vrai.

La sous-routine reçoit trois paramètres : l'objet requête, l'objet réponse et l'objet transport.

Si elle renvoie une valeur indéfinie, le comportement de retry par défaut est utilisé. Voir "RETRY ON ERROR" ci-dessous.

Si elle renvoie une valeur définie mais fausse, la requête n'est pas renvoyée.

Si elle renvoie une valeur vraie, la requête est renvoyée, tant que le nombre de retries n'excède pas "go_retry_limit".

RETRY SUR ERREUR

Le comportement par défaut de retry sur erreur est :

- Retenter si l'erreur est due à DBI_GOFER_RANDOM. Voir L<DBI::Gofer::Execute>.
- Retenter si $request->is_idempotent renvoie vrai. Voir L<DBI::Gofer::Request>.

Un retry ne sera pas autorisé si le nombre de retries précédents a atteint "go_retry_limit".

TRAÇAGE

Le traçage des requêtes et réponses gofer peut être activé en définissant la variable d'environnement "DBD_GOFER_TRACE". Une valeur de 1 donne un résumé raisonnablement compact de chaque requête et réponse. Une valeur de 2 ou plus donne un dump détaillé et volumineux.

Le trace est écrit en utilisant DBI->trace_msg() et est donc écrit dans la sortie de trace DBI par défaut, qui est généralement STDERR.

MÉTHODES

Cette section est actuellement loin d'être complète.

response_retry_preference

$retry = $transport->response_retry_preference($request, $response);

La préférence de retry de réponse est appelée par DBD::Gofer lors de l'examen si une requête doit être retentée après une erreur.

Renvoie vrai (souhaite retenter), faux (ne doit pas retenter), undef (aucune préférence).

Si une valeur vraie est renvoyée sous forme de référence CODE, alors, si DBD::Gofer décide de retenter la requête, il appelle la référence CODE en transmettant $retry_count, $retry_limit. Peut être utilisé pour la journalisation et/ou pour implémenter un comportement de back-off exponentiel. Actuellement, le code appelé doit retourner en utilisant "return;" pour permettre des extensions futures.
