NOM

dvilj4, dvilj4l, dvilj2p, dvilj - convertir un fichier DVI TeX en PCL, pour les imprimantes HP LaserJet

SYNTAXE

dvilj [--Dnombre] [-ccopie] [-dmode] [-D] [-E] [-efichier_sortie]
      [-ffrompage] [-g] [-hfichier_en_tete] [-l] [-Mflag] [-mmag] [-ppages]
      [-q] [-r] [-ttopage] [-spagesize] [-v] [-Vmode] [-w] [-xxoff(mm)]
      [-yyoff(mm)] [-Xxoff(points)] [-Yyoff(points)] [-z] [fichier]

DESCRIPTION

dvilj et ses variantes convertissent les fichiers ".dvi" issus de TeX en commandes PCL (le langage de contrôle d'imprimante de Hewlett-Packard) adaptées à l'impression sur les imprimantes HP LaserJet+, HP LaserJet IIP (en utilisant dvilj2p), HP LaserJet 4 (en utilisant dvilj4) et les imprimantes entièrement compatibles.

dvilj4 prend également en charge les polices Intellifont et TrueType intégrées ; les fichiers TFM et VF sont fournis dans la distribution. Les polices virtuelles ne sont pas directement prises en charge par dvilj, vous devez donc exécuter dvicopy(1) au préalable, ou développer les polices virtuelles autrement.

Tous les programmes sont générés à partir d'un seul fichier source dvi2xx.c. Ils sont généralement appelés via un script shell ou comme filtre d'imprimante. Un tel script, dvihp(1), est inclus dans la distribution. Il fournit des options de ligne de commande similaires à celles de dvips(1).

OPTIONS

--Dnombre
Débogue selon les bits de nombre ; voir le manuel de kpathsea(3) pour les valeurs. Active également la verbosité générale.
-cnombre
Imprime chaque page nombre fois (y compris l'original).
-dmode
imprime en mode recto-verso. L'option -d1 signifie reliure par le bord long, -d2 signifie reliure par le bord court. Cette option est uniquement sélectionnable dans dvilj4 et dvilj2p.
-D[-12]
Impression double face - voir ci-dessous ; -D1 imprime uniquement les côtés impairs, -D2 est pour les pages paires, un - final supprime l'impression des pages de remplissage vides.
-E
Commute l'imprimante en mode économique (dvilj4 uniquement).
-efichier_sortie
Envoie la sortie vers fichier_sortie au lieu du nom de base du fichier dvi prolongé par ".lj". Si fichier_sortie est - (comme dans "-e-"), la sortie est dirigée vers la sortie standard et peut être directement redirigée vers un système d'impression.
-fnum_page
Imprime les pages dont le numéro de page TeX est supérieur ou égal à num_page.
-g
Mode Go : ne réinitialise pas l'imprimante au début du travail.
-hfichier_en_tete
Copie fichier_en_tete dans la sortie avant la traduction du fichier DVI. Utilisé pour envoyer des commandes arbitraires à l'imprimante laser.
-l
Imprime la sortie en mode paysage ; pris en charge uniquement par dvilj2p et dvilj4.
-Mflag
Appelle (ou non) mktexpk(1) pour générer les polices à la demande. -M1 et -M sont équivalents. -M0 active l'appel à mktexpk(1). (Ceci est identique à dvips(1).) Le comportement par défaut (c'est-à-dire, si aucune option -M n'est donnée) est choisi au moment de la compilation ; tel que distribué, mktexpk est activé.
-magrandissement
Spécifie l'agrandissement à utiliser. Les suivants sont disponibles : 
-m#usermag par exemple, #900
-m0 équivalent à -m#1000
-mh équivalent à -m#1095
-m1 équivalent à -m#1200
-mq équivalent à -m#1250
-m2 équivalent à -m#1440
-m3 équivalent à -m#1728
-m4 équivalent à -m#2074
-m5 équivalent à -m#2488
-pnombre_pages
Imprime nombre_pages pages après la page de départ.
-q
Mode silencieux : omet les statistiques finales, etc.
-r
Inverse l'ordre des pages.
-staille_page
Spécifie la taille de la page : 
-s1 : Exécutif (7.25" x 10.5")
-s2 : Lettre (8.5" x 11")
-s3 : Légal (8.5" x 14")
-s6 : Ledger (11" x 17")
-s25 : Papier A5 (148mm x 210mm)
-s26 : Papier A4 (210mm x 297mm)
-s27 : A3 (297mm x 420mm)
-s45 : Papier JIS B5 (182mm x 257mm)
-s46 : Papier JIS B4 (250mm x 354mm)
-s71 : Carte postale Hagaki (100mm x 148mm)
-s72 : Carte postale Oufuku-Hagaki (200mm x 148mm)
-s80 : Enveloppe Monarque (3 7/8" x 7 1/2")
-s81 : Enveloppe commerciale 10 (4 1/8" x 9 1/2")
-s90 : DL international (110mm x 220mm)
-s91 : C5 international (162mm x 229mm)
-s100 : B5 international (176mm x 250mm)

Ces valeurs proviennent du manuel de référence technique PCL 5. Si l'option de ligne de commande -s est omise, aucun découpage n'est effectué en bas de la page. (Mais l'impression sous le bas du papier ne devrait pas déranger une imprimante PCL qui fonctionne correctement.) N'oubliez pas que le bac papier correct doit être installé pour la taille de papier sélectionnée, utilisez donc cette option uniquement si vous avez un contrôle total sur votre destination d'impression.

-tnum_page
Imprime les pages dont le numéro de page TeX est inférieur ou égal à num_page.
-v
Mode verbeux : liste les polices utilisées, etc.
-Vmode
Mode de compatibilité. Comme mode, utilisez "K" pour Kyocera, "B" pour Brother, 6 pour les imprimantes LJ6.
-w
Omet les avertissements.
-xdecalage
Décalage global x en mm sur la page de sortie par rapport à l'origine 1 pouce/1 pouce.
-ydecalage
Décalage global y en mm sur la page de sortie par rapport à l'origine 1 pouce/1 pouce.
-Xdecalage
Décalage global x en points sur la page de sortie (remplace l'origine 1 pouce/1 pouce).
-Ydecalage
Décalage global y en points sur la page de sortie (remplace l'origine 1 pouce/1 pouce).
-z
Imprime une page de test avec le compteur de pages à la fin du travail.

OPERANDES

Si aucun opérande n'est spécifié, un bref message d'utilisation s'affiche.

fichier
Le nom du fichier DVI qui doit être converti par dvilj. Il doit toujours être accessible en lecture.

Le nom du fichier de sortie est construit à partir de fichier. Soit l'extension ".dvi" est remplacée par ".lj", soit l'extension ".lj" est ajoutée.

Si fichier est -, le fichier DVI est lu depuis l'entrée standard et le document PCL résultant est écrit sur la sortie standard. (N'oubliez pas que le fichier DVI doit être accessible en lecture, même s'il s'agit de l'entrée standard.)

COMMANDES TeX \special SUPPORTÉES

Les commandes "\special" prises en charge par dvilj ont la syntaxe générique

\special{clef1=valeur clef1="valeur avec espace"}
\special{clef3 = valeur clef4 = 'notez les espaces optionnels autour du signe égal'}

C'est-à-dire, les spécials sont une séquence de paires clé/valeur, séparées par un signe égal. Les espaces autour du signe égal sont ignorés. La valeur est soit un mot séparé par des espaces, soit une chaîne entre guillemets. Les guillemets doubles et simples peuvent être utilisés, de manière alternative. Il n'y a pas de prise en charge pour mettre des guillemets dans les valeurs ; si vous voulez des guillemets doubles et simples dans la même valeur, vous avez de la chance.

Les combinaisons clé/valeur suivantes sont valides :

hpfile=fich
ier
Insère le fichier à la position courante. Le fichier est recherché avec kpathsea(3), voir ci-dessous.

Le contenu du fichier doit être valide pour cette imprimante, c'est-à-dire qu'il doit contenir des séquences d'échappement PCL ou des commandes HP-GL/2. Si le fichier est un fichier graphique, cela signifie généralement que le coin supérieur gauche du graphique est placé à la position

courante.

Les séquences d'échappement de positionnement absolu PCL dans le fichier sont réécrites en commandes de positionnement relatif ; la

coordonnée la plus basse apparaissant
est utilisée comme référence.
hpfile_verbatim=fich
ier
Insère le fichier tel quel à la position courante, sans aucune modification du contenu du fichier. Le fichier est recherché avec kpathsea(3), voir ci-dessous.

C'est principalement utilisé pour conserver les positions absolues dans les fichiers

PCL.
psfile=fichier llx=x0 lly=y0 urx=x1 ury=y1 rwi=
s
Convertit le fichier PostScript fichier en HP PCL, par Ghostscript avec le périphérique "ljetplus", et insère le fichier graphique résultant à la position courante, en réécrivant les séquences d'échappement de position absolu. Le fichier est recherché avec kpathsea(3), voir ci-dessous.

Les paires clé/valeur accompagnatrices sont obligatoires, elles peuvent être spécifiées dans un ordre arbitraire. Les valeurs x0, x1, y0, y1, et s sont des entiers. (x0,y0) est le coin inférieur gauche, (x1,y1) le coin supérieur droit de

l'image.

Veuillez noter : la sémantique spécifique de ce spécial n'est pas connue. En particulier, le paramètre rwi est un certain facteur d'échelle ; mais même en examinant le code source, il n'est pas tout à fait clair ce que l'auteur du spécial a voulu implémenter ici. De plus, il n'est pas clair quelles dimensions sont utilisées pour spécifier les coins, des points PostScript ou des points

PCL.

Si vous connaissez la sémantique de psfile, ou si vous avez pris la peine de l' analyser, veuillez nous informer à tex-k@tug.org, afin que nous puissions mettre à jour cette page d

Recherche des Fichiers

Inclus

Les spéciaux d'inclusion de fichiers appropriés recherchent le fichier avec kpathsea(3). Le chemin de recherche est configuré par la variable "DVILJINPUTS" et, si le fichier n'est pas trouvé dans ce chemin de recherche, par la variable "TEXINPUTS"

.

La recherche via "DVILJINPUTS" couvre le cas d'utilisation où l'on a des graphiques communs au site qui doivent être inclus dans des documents, par exemple des signatures numérisées. La recherche via "TEXINPUTS" couvre le cas d'utilisation où l'on a des graphiques faisant partie de son document

courant.

"dvilj" est utilisé comme le nom ".PROGRAM" dans texmf.cnf, pour toutes les variantes de pi

lote, indépendamment du
nom réel du programme.

Spéciaux Inconnus et Configuration

"TEX_HUSH"

Kpathsea(3) a le concept de suppression d'avertissements avec la variable de configuration "TEX_HUSH", veuillez vous référer à son nœud Info TeX support / Suppressing warnings. Cette variable contient des identifiants séparés par des deux-points qui spécifient les avertissements à

supprimer.

Si "special" est parmi les valeurs listées, dvilj ne produit plus d'avertissements sur les spéciaux qu'il ne connaît pas. Mais s'il y a un spécial reconnu et si ce spécial a un paramètre invalide, un avertissement est produit quand même, indépendamment du contenu de "TEX

_HU
SH
".

IMPRESSION DE PAGES

DOUBLES

Si l'imprimante a une unité duplex installée, l'impression recto-verso peut être demandée avec l' option

-d.

Sinon, l'option de ligne de commande -D fait imprimer à l'imprimante en mode double page, c'est-à-dire, grosso modo, imprimerst les pages paires puis les pages impaires d'un document. Si -D est utilisé pour imprimer à la fois les pages paires et impaires (-D est utilisé sans l'option 1 ou 2), ce qui suit se produit après que la moitié des pages a été imprimée : LJ : l'imprimante s'arrête, affiche le message « FEED » et allume la LED d'alimentation manuelle. L'imprimante continue lorsque les pages imprimées sont insérées dans l'alimentation manuelle ou lorsque l'opérateur appuie sur le bouton de continuation (après avoir d'abord placé les pages imprimées dans le bac à papier)

.

Si -D1 a été spécifié, seules les pages impaires seront imprimées, -D2 peut être utilisé pour les pages paires. Un « - » final (comme dans -D-, -D1- ou -D2-) supprime l'impression des pages vides qui sont générées pour le remplissage

autrement.

Le pilote permet l'option -D pour les deux sens d'impression (impression recto-verso ou verso-verso). Il essaie d'être intelligent dans certains cas : lorsqu'un document a un nombre impair de pages, il insère une page vide à l'endroit approprié ; lorsqu'un document commence par la page 0, le pilote insère une page vide après la page 0 ; lorsqu'un fragment de document est imprimé et commence par un numéro de page pair, il imprime cette page au verso de la première page pour s'assurer que les côtés impairs sont toujours au recto. La page 0 est traitée comme une page

impaire.

L'option doubleside fonctionne pour tous les LJ, pas seulement pour le nouveau modèle D qui fait l'impression recto-verso (en fait, je ne sais pas si cela a beaucoup de sens sur le nouveau LJ II D)

.

Avertissement concernant l'option doubleside : lorsqu'elle est utilisée fréquemment ou sur de très grands fichiers, il peut devenir nécessaire de nettoyer l'imprimante beaucoup plus

fréquemment.

L'option de ligne de commande -pX peut être utilisée pour interrompre l'impression après la sortie de X pages (peut conduire à des résultats étranges avec -D). Personnellement, je n'aime pas cette option. La manière sûre d'imprimer une partie d'un document est d'utiliser -f (from) et -t

(t
o).
