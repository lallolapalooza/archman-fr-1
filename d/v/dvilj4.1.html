RISES EN CHARGE Les commandes "\special"

prises en charge par dvilj ont

la

syntaxe générique \special{key1=value key1="value with space"}

\special{key3 
= value key4 = 'note optional spaces around equal sign'}
C'est-à-dire que les specials sont une séquence de paires
clé/valeur,

séparées par un signe égal. Les espaces autour du signe égal sont ignorées. La valeur est soit un mot séparé par des espaces, soit une chaîne entre guillemets. Les guillemets doubles et simples peuvent être utilisés alternativement. Il n'y a pas de support pour échapper les caractères de guillemets dans les valeurs ; si vous voulez à la fois des guillemets doubles et simples dans une même valeur, vous avez de la

malchance.

Les combinaisons clé/valeur suivantes sont valides

:
hpfile=fichier
Insère le fichier fichier à la position actuelle. fichier est recherché à l'aide de kpathsea(3), voir ci-dessous.

Le contenu du fichier doit être valide pour cette imprimante, c'est-à-dire qu'il doit contenir des séquences d'échappement PCL ou des commandes HP-GL/2. Si le fichier est un fichier graphique, cela signifie généralement que le coin supérieur gauche du graphique est placé à la position actuelle.

Les séquences d'échappement de positionnement absolu PCL dans fichier sont réécrites en commandes de positionnement relatives ; la coordonnée la plus basse apparaissant est utilisée comme référence.

hpfile_verbatim=fichier
Insère le fichier fichier tel quel à la position actuelle, sans aucune modification du contenu du fichier. fichier est recherché à l'aide de kpathsea(3), voir ci-dessous.

Ceci est principalement utilisé pour conserver les positions absolues dans les fichiers PCL.

psfile=fichier llx=x0 lly=y0 urx=x1 ury=y1 rwi=s
Convertit le fichier PostScript fichier en HP PCL, par Ghostscript avec le périphérique "ljetplus", et insère le fichier graphique résultant à la position actuelle, en réécrivant les séquences d'échappement de position absolue. fichier est recherché à l'aide de kpathsea(3), voir ci-dessous.

Les paires clé/valeur accompagnatrices sont obligatoires, elles peuvent être spécifiées dans n'importe quel ordre. Les valeurs x0, x1, y0, y1 et s sont des entiers. (x0,y0) est le coin inférieur gauche, (x1,y1) le coin supérieur droit de l'image.

Veuillez noter : La sémantique spécifique de cette commande spéciale n'est pas connue. En particulier, le paramètre rwi est un facteur d'échelle ; mais même en examinant le code source, il n'est pas tout à fait clair ce que l'auteur de la commande spéciale avait l'intention d'implémenter ici. De plus, il est incertain quelles dimensions sont utilisées pour spécifier les coins, les points PostScript ou les points PCL.

Si vous connaissez la sémantique de psfile, ou si vous avez consacré du temps à leur analyse, veuillez nous en informer à tex-k@tug.org, afin que nous puissions mettre à jour cette page de manuel avec les informations pertinentes.

dvilj-psfile-syntax=syntaxe
où syntaxe est soit "dvilj" soit "ignore". C'est une manière très grossière de dire au pilote quoi faire avec les commandes spéciales psfile.

Si la valeur est "ignore", toutes les commandes spéciales psfile qui sont traitées par la suite sont ignorées, jusqu'à ce que la prochaine commande spéciale dvilj-psfile-syntax soit traitée.

Si la valeur est "dvilj", les commandes spéciales psfiles sont traitées comme expliqué ci-dessus, jusqu'à ce que la prochaine commande spéciale dvilj-psfile-syntax soit traitée.

Une extension évidente et prévue est la valeur "dvips", mais cela n'a pas encore été implémenté.

Cette commande spéciale n'est pas aussi simple qu'il y paraît à première vue. Étant donné que sa sémantique est définie par l'ordre de traitement, elle n'est utile que si elle est placée sur la même page que la commande spéciale psfile. L'avoir une fois dans un fichier (par exemple, sur la première page) n'aide pas si vous n'imprimez qu'une seule page du document -- dvilj ne fait pas de pré-balayage des commandes spéciales de première page comme certains autres pilotes le font. (Des patchs seraient les bienvenus, bien sûr.)

comment=texte arbitraire
comment texte arbitraire
Ceci fait que le reste de la commande spéciale est ignoré ; elle peut être utilisée pour ajouter des méta-informations à un fichier DVI.

Avec la première forme, le commentaire peut apparaître n'importe où dans la commande spéciale. Lorsqu'il apparaît en premier, le traitement de cette commande spéciale est terminé et tout le texte suivant est ignoré.

La deuxième forme est une particularité qui a été introduite pour la compatibilité avec d'autres pilotes. Si le premier mot-clé de la commande spéciale est comment et n'a pas de valeur, il est également considéré comme une syntaxe de commentaire valide ; le reste de la commande spéciale est ignoré.

orientation=po
Positionne la page sur le papier physique. La valeur po peut être l'une des valeurs suivantes : 
0  pour portrait
1  pour paysage
2  pour portrait inversé
3  pour paysage inversé
defpoint=n(x,y)
Définit le point numéro n. Ce point peut être référencé plus tard dans d'autres commandes spéciales pour spécifier des zones qui seront remplies avec un motif. n doit être compris entre 0 et 79.

x et y sont la position de ce point et ont la forme "?pt" où "?" est un nombre à virgule flottante. Les positions sont relatives à l'origine de la page DVI ; c'est-à-dire que les coordonnées augmentent en allant vers la droite et vers le bas, le point d'origine étant (1in,1in) dans le coin supérieur gauche, modifié par les options -x, -y, -X et -Y, mais pas par \hoffset et \voffset.

x et y peuvent être omis, c'est-à-dire que les valeurs 3 ou "4(,)" sont valides. Alors, la position actuelle de la page est utilisée comme position pour le point n.

resetpoints="all"
Redéfinit tous les points.
gray=échelle_de_gris
grey=échelle_de_gris
Ceci définit le mode de remplissage pour la prochaine commande spéciale fill, la zone sera remplie avec une couleur grise. (grey est un alias pour gray.) Toute spécification de motif est réinitialisée.

échelle_de_gris est le pourcentage de gris qui doit être utilisé ; 0 signifiant blanc et 100 signifiant noir.

Attention : Cette commande spéciale est en fait un terme impropre. PCL nomme ces échelles de gris des motifs de tramage et elles sont créées en plaçant des points dans la zone. L'échelle de gris sélectionne la dispersion des points. Dans les gammes inférieures, cela ne ressemble pas vraiment à du gris de près, mais plutôt à un fond pointillé. De plus, les échelles de gris ne sont pas aussi finement granulées que la plage de valeurs 0..100 pourrait le laisser croire. En réalité, il n'y a que 8 motifs de gris différents disponibles :

 1 -  2%
 3 - 10%
11 - 20%
21 - 35%
36 - 55%
56 - 80%
81 - 99%
100%

L'un de ces motifs est sélectionné en fonction de la valeur échelle_de_gris.

pattern=pat
Ceci définit le mode de remplissage pour la prochaine commande spéciale fill, la zone sera remplie avec un motif. Toute spécification de couleur grise est réinitialisée.

pat est l'une des valeurs suivantes :

1  lignes horizontales
2  lignes verticales
3  lignes diagonales, du coin inférieur gauche au coin supérieur droit
4  lignes diagonales, du coin supérieur droit au coin inférieur gauche
5  lignes croisées, verticalement
6  lignes croisées, en diagonale
fill=a/b
Remplit la zone entre les points a et b, selon le mode de remplissage actuel.

Le point a doit être le coin supérieur gauche et le point b doit être le coin inférieur gauche du rectangle. Sinon, le résultat sera du charabia.

Le mode de remplissage par défaut est le remplissage de couleur grise à 10%.

nom_de_fichier
C'est une commande spéciale héritée, son utilisation est dépréciée. Si la commande spéciale est juste un seul mot qui nomme un fichier existant, ce fichier est inclus tel quel. Contrairement aux autres moyens d'inclusion de fichiers, le fichier n'est pas recherché avec kpathsea(3). Vous ne devez pas utiliser cette commande spéciale et nous ne corrigerons aucun problème la concernant.

Il convient de noter que l'analyseur de commandes spéciales accepte parfois des constructions qui ne sont pas valides selon la documentation ci-dessus. Dans ce cas, la sortie est le plus souvent endommagée d'une manière ou d'une autre.

Recherche des Fichiers Inclus

Les commandes spéciales d'inclusion de fichiers appropriées recherchent le fichier avec kpathsea(3). Le chemin de recherche est configuré par la variable "DVILJINPUTS" et, si le fichier n'est pas trouvé dans ce chemin de recherche, par la variable "TEXINPUTS".

La recherche via "DVILJINPUTS" couvre le cas où l'on a des graphiques communs à l'échelle du site qui doivent être inclus dans les documents, par exemple, des signatures scannées. La recherche via "TEXINPUTS" couvre le cas où l'on a des graphiques dans le cadre de son document actuel.

"dvilj" est utilisé comme nom ".PROGRAM" dans texmf.cnf, pour toutes les variantes de pilotes, indépendamment du nom réel du programme.

Commandes Spéciales Inconnues et configuration "TEX_HUSH"

Kpathsea(3) a le concept de suppression d'avertissements avec la variable de configuration "TEX_HUSH", veuillez vous référer à son nœud Info TeX support / Suppressing warnings. Cette variable contient des identifiants séparés par des deux-points qui spécifient les avertissements à supprimer.

Si "special" fait partie des valeurs listées, dvilj n'affiche plus d'avertissements concernant les commandes spéciales qu'il ne connaît pas. Mais s'il y a une commande spéciale reconnue et si cette commande spéciale a un paramètre invalide, un avertissement est néanmoins émis, indépendamment du contenu de "TEX_HUSH".

IMPRESSION DOUBLE PAGE

Si l'imprimante dispose d'une unité recto-verso installée, l'impression recto-verso peut être demandée avec l'option -d.

Sinon, l'option de ligne de commande -D fait que l'imprimante imprime en mode double page, c'est-à-dire, grosso modo, en imprimant d'abordles pages paires puis les pages impaires d'un document. Si -D est utilisé pour imprimer à la fois les pages paires et impaires (-D est utilisé sans le 1 ou 2 optionnel), le comportement suivant se produira après l'impression de la moitié des pages : LJ : l'imprimante s'arrête, affiche le message "FEED" et allume le voyant de chargement manuel. L'imprimante continue lorsque les pages imprimées sont insérées dans le chargeur de pages manuel, ou lorsque l'opérateur appuie sur le bouton de continuation (après avoir placé d'abord les pages imprimées dans le bac à papier).

Si -D1 a été spécifié, seules les pages impaires seront imprimées, -D2 peut être utilisé pour les pages paires. Un trait d'union final ("-" (comme dans -D-, -D1- ou -D2-) supprime l'impression des pages vierges qui sont générées pour le remplissage autrement.

Le pilote autorise l'option -D pour les deux directions d'impression (de l'avant vers l'arrière ou de l'arrière vers l'avant). Il essaie d'être intelligent dans certains cas : lorsqu'un document a un nombre impair de pages, il insère une page vierge à l'endroit approprié ; lorsqu'un document commence par la page 0, le pilote insère une page vierge après la page 0 ; lorsqu'une partie d'un document est imprimée qui commence par un numéro de page pair, il imprime cette page au verso de la première page pour s'assurer que les côtés impairs sont toujours au recto. La page 0 est traitée comme une page impaire.

L'option recto-verso fonctionne pour tous les LJ, pas seulement pour le nouveau modèle D qui fait de l'impression recto-verso (en fait, je ne sais pas si cela a beaucoup de sens sur le nouveau LJ II D).

Mise en garde sur l'option recto-verso : lorsqu'elle est utilisée fréquemment ou sur de très grands fichiers, il peut devenir nécessaire de nettoyer l'imprimante beaucoup plus fréquemment.

L'option de ligne de commande -pX peut être utilisée pour interrompre l'impression après la sortie de X pages (peut conduire à des résultats étranges avec -D). Je n'aime personnellement pas cette option. Le moyen sûr d'imprimer une partie d'un document est d'utiliser -f (de) et -t (à).

ENVIRONNEMENT

dvilj utilise les mêmes variables d'environnement et algorithmes pour trouver les fichiers de polices que TeX et ses amis. Voir la documentation de la bibliothèque kpathsea(3) pour plus de détails. (Le répéter ici est trop fastidieux.)

"DVILJFONTS"
S'il est défini, remplace tous les autres chemins de polices.
"DVILJMAKEPK"
S'il est défini, remplace mktexpk(1) comme nom de la commande à exécuter pour créer un fichier PK s'il n'en est pas trouvé.
"DVILJSIZES"
Peut être défini pour indiquer quelles tailles de polices sont disponibles. Il doit consister en une liste de nombres séparés par des deux-points. Si la liste commence par un deux-points, les tailles par défaut du système sont également utilisées. Les tailles sont exprimées en points par pouce ; les décimales peuvent être utilisées pour les fichiers "pxl" : par exemple, un fichier de 300 points par pouce agrandi d'un demi-pas donne 1643 points par cinq pouces, ce qui doit être codé en 328,6. dvilj essaie la taille réelle de la police avant d'essayer l'une des tailles données.
"DVILJINPUTS"
Chemin de recherche principal pour les fichiers d'inclusion.
"TEXINPUTS"
Chemin de recherche secondaire pour les fichiers d'inclusion.
"TEX_HUSH"
Liste d'identifiants séparés par des deux-points qui nomment les situations où aucun avertissement ne doit être émis. Les identifiants suivants sont utilisés : 
checksum  supprime les avertissements de sommes de contrôle de police non conformes
readable  supprime les avertissements concernant les fichiers illisibles
special   supprime les avertissements concernant les spéciaux inconnus
all       supprime toutes les classes d'avertissement ci-dessus
none      ne supprime aucun avertissement
"KPATHSEA_DEBUG"
Traquer les recherches de kpathsea(3) ; définir à -1 pour un traçage complet.
"GS_PATH"
Sur Windows, il peut s'agir du chemin vers Ghostscript ; là, la valeur par défaut est gswin32c.exe.

Sur Unix, cette variable d'environnement n'est pas utilisée. Ghostscript est appelé comme gs(1) et doit être trouvé via $PATH.
