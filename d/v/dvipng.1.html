DESCRIPTIO

N

Ce programme produit des graphiques PNG et/ou GIF à partir de fichiers DVI tels que produits par TeX et ses

dérivés.

Si le support GIF est activé, la sortie GIF est choisie en utilisant le binaire dvigif ou avec l' option --

gif.

Les avantages de dvipng/dvigif inc

luent
  • La vitesse. C'est un code de rendu de bitmap très rapide pour les fichiers DVI, ce qui le rend adapté à la génération d'un grand nombre d'images à la volée, comme nécessaire dans preview-latex, WeBWorK et
    • d'autres.
  • Il ne lit pas le postambule, il peut donc être démarré avant que TeX ne termine. Il existe un commutateur --follow qui fait attendre dvipng à la fin de fichier pour d'autres sorties, à moins qu'il ne trouve le marqueur POST qui indique la fin du
    • DVI.
  • Interrogation interactive des options. dvipng peut lire les options de manière interactive via stdin, et toutes les options sont utilisables. Il est même possible de changer le fichier d'entrée via cette
    • interface.
  • Prend en charge les polices PK, VF, PostScript Type1 et TrueType, les sous-polices (c'est-à-dire comme utilisées dans CJK-LaTeX), les specials de couleur, et l'inclusion d'images PostScript, PNG, JPEG ou
    • GIF.

'
Définir la largeur en pixels de la bordure transparente (par défaut 0). L'utilisation de cette option rendra les bords de l'image transparents, mais cela n'affecte que les pixels ayant la couleur d'arrière-plan. Donner un color_spec définira la couleur de repli, à utiliser dans les visualiseurs qui ne gèrent pas la transparence (par défaut c'est la couleur d'arrière-plan). La spécification de couleur doit être dans la syntaxe \special de couleur TeX, par ex. 'rgb 1.0 0.0 0.0'. Définir la couleur de repli rend la largeur de bordure par défaut de
1 px.

Cette option n'a d'effet que lors de l'utilisation de polices bitmap (PK). L'option définit la résolution de base (Metafont), à la fois horizontale et verticale, à num dpi (points par pouce). Cette option est nécessaire lors de la sélection manuelle du mode Metafont avec l'option --mode (voir ci-dessous)

-bg color_sp
ec
Choisir la couleur d'arrière-plan des images. Cette option sera ignorée s'il y a un \special de couleur d'arrière-plan dans le DVI. La spécification de couleur doit être dans la syntaxe \special de couleur TeX, par ex. 'rgb 1.0 0.0 0.0'. Vous pouvez aussi spécifier 'Transparent' ou 'transparent', ce qui vous donnera un arrière-plan transparent avec l'arrière-plan normal comme couleur de repli. Un 'Transparent' avec une majuscule donnera une transparence alpha complète, tandis qu'un 'transparent' entièrement en minuscules donnera un simple arrière-plan entièrement transparent avec des pixels anti-crénelés non transparents. Ce dernier conviendrait aux visualiseurs qui ne peuvent pas gérer un véritable canal alpha. Les images GIF ne supportent pas la transparence alpha complète, donc en cas de sortie GIF, les deux variantes utiliseront ce dernier
comportement.

m
Définir les indicateurs de débogage, montrant ce que dvipng (croit) faire. Cela fonctionnera à moins que dvipng n'ait été compilé sans l' option "DEBUG" (non recommandé). Définissez les indicateurs selon vos besoins, utilisez -d -1 comme première option pour une sortie
maximale.
-D nu
m
Définir la résolution de sortie, à la fois horizontale et verticale, à num dpi (points par pouce).

On peut vouloir l'ajuster pour s'adapter à une certaine taille de police de texte (par ex., sur une page web), et pour une hauteur de police de texte de font_px pixels (dans Mozilla) la formule

correcte est 
<dpi> = <font_px> * 72.27 / 10 [px * TeXpt/in /
TeXpt]

La dernière division par dix est due à la hauteur de police standard 10pt dans votre document, si vous utilisez 12pt, divisez par 12. Malheureusement, certains navigateurs propriétaires ont la hauteur de police en pt (points), pas en pixels. Vous devez la reconvertir en pixels, en utilisant la résolution de l'écran (par défaut est généralement 96 dpi), ce qui signifie que la

formule est 
<font_px> = <font_pt> * 96 / 72 [pt * px/in / (pt/in)
]

Sur certains écrans haute résolution, la valeur est plutôt 120 dpi. Bonne

chance
!

--freetyp
e*
Activer/désactiver le rendu de polices FreeType (activé par défaut). Cette option est disponible si la bibliothèque de polices FreeType2 était présente au moment de la compilation. Si c'est le cas, dvipng aura un support direct pour les polices PostScript Type1 et TrueType en interne, plutôt que d'utiliser gsftopk pour le rendu des polices. Si vous avez les versions PostScript de Computer Modern installées, il ne sera pas nécessaire de générer les variantes bitmap (PK) sur disque de celles-ci. Ensuite, vous pourrez rendre des images à différentes résolutions (et inhabituelles) sans encombrer le disque avec beaucoup de polices bitmap. Une raison de désactiver le rendu de polices FreeType serait de générer une sortie identique sur différentes plateformes, car FreeType utilise le moteur de rendu natif et peut donc donner une sortie légèrement différente sur chaque
plateforme.

OPTIONS

--bdpi num
Used with the --mode option, this specifies the base resolution (in dots per inch) for Metafont generation of PK fonts. For example, if the mode is set to ljfour, then this option specifies the resolution (e.g., 600) at which the fonts are generated.
-dvi0
When using the -o option, do not append the DVI page number to the output filename.
--dvinum num
This specifies which page number is used in the output filename specified with the -o option, when the filename contains a %d or similar placeholder. The default is the physical page number. If num is specified as dvi, then the page number from the DVI file (the value of TeX's \count0) is used instead.
--dvivis
This option is intended for debugging. It will mark the physical page number on the output image, and also the DVI origin. This is one inch down, one inch to the right from the upper left corner of the paper.
--depth num
The vertical dimension of the output image in the selected unit. Default is 0.
--fade*
Output images with a fade from the background color (default white) to the background color of the page. This is done by filling the page with the background color, and then drawing the page contents.
-firstpage num
This is equivalent to the -p option.
--fits
This option is intended for internal use. It tries to select a PK font which fits the requested output resolution. It is not documented any further.
--gif
The images are output in the GIF format. See also the --png option.
--height num
The horizontal dimension of the output image in the selected unit. Default is 0.
--hsize num
Set the horizontal size of the output image to num. This option should be used with the -T option. See also --depth.
--grayscale
Output grayscale images. By default, color images are produced.
--bg color
Set the background color to color. The default is white. The supported color specifications are the same as for X11.
--fg color
Set the foreground color to color. The default is black. The supported color specifications are the same as for X11.
--fontresolution num
The resolution (in dpi) to use for PK fonts. Defaults to the value of --bdpi.
--halftone*
Use grayscale halftoning for output. This is equivalent to the --grayscale option.
--ignoreboundingbox*
This option is intended for internal use. It overrides the bounding box calculation for included EPS files.
--includeallfonts*
This option is intended for internal use. It forces the inclusion of all fonts used in the document, even if they are not used.
-lastpage num
This is equivalent to the -l option.
--mode mode
This option only has an effect when using bitmapped (PK) fonts. Use mode as the Metafont device name for the PK fonts (both for path searching and font generation). This needs to be augmented with the base device resolution, given with the --bdpi option. See the file <ftp://ftp.tug.org/tex/modes.mf> for a list of resolutions and mode names for most devices.
-M*
This option only has an effect when using bitmapped (PK) fonts. It turns off automatic PK font generation (mktexpk).
--nogs*
This switch prohibits the internal call to GhostScript for displaying PostScript specials. --nogs0 turns the call back on.
--nogssafer*
Normally, if GhostScript is used to render PostScript specials, the GhostScript interpreter is run with the option -dSAFER. The --nogssafer option runs GhostScript without -dSAFER. The -dSAFER option in Ghostscript disables PostScript operators such as deletefile, to prevent possibly malicious PostScript programs from having any effect.
--norawps*
Some packages generate raw PostScript specials, even non-rendering such specials. This switch turns off the internal call to GhostScript intended to display these raw PostScript specials. --norawps0 turns the call back on.
-o name
Send output to the file name. A single occurrence of %d or %01d, ..., %09d will be exchanged for the physical page number (this can be changed, see the --dvinum switch). The default output filename is file%d.png where the input DVI file was file.dvi.
-O x-offset,y-offset
Move the origin by x-offset,y-offset, a comma-separated pair of dimensions such as .1in,-.3cm. The origin of the page is shifted from the default position (of one inch down, one inch to the right from the upper left corner of the paper) by this amount.
-p [=]num
The first page printed will be the first one numbered num. Default is the first page in the document. If num is prefixed by an equals sign, then it (and the argument to the -l option, if specified) is treated as a physical (absolute) page number, rather than a value to compare with the TeX \count0 values stored in the DVI file. Thus, using -p =3 will start with the third page of the document, no matter what the pages are actually numbered.
--palette*
When an external image is included, dvipng will automatically switch to truecolor mode, to avoid unnecessary delay and quality reduction, and enable the EPS translator to draw on a transparent background and outside of the boundingbox. This switch will force palette (256-color) output and make dvipng revert to opaque clipped image inclusion. This will also override the --truecolor switch if present.
--picky*
No images are output when a warning occurs. Normally, dvipng will output an image in spite of a warning, but there may be something missing in this image. One reason to use this option would be if you have a more complete but slower fallback converter. Mainly, this is useful for failed figure inclusion and unknown \special occurrences, but warnings will also occur for missing or unknown color specs and missing PK fonts.
--png*
The images are output in the PNG format. This is the default for the dvipng binary. See also the --gif option.
-pp firstpage-lastpage
Print pages firstpage through lastpage; but not quite equivalent to -p firstpage -l lastpage. For example, when rendering a book, there may be several instances of a page in the DVI file (one in "\frontmatter", one in "\mainmatter", and one in "\backmatter"). In case of several pages matching, -pp firstpage-lastpage will render all pages that matches the specified range, while -p firstpage -l lastpage will render the pages from the first occurrence of firstpage to the first occurrence of lastpage. This is the (undocumented) behaviour of dvips. In dvipng you can give both kinds of options, in which case you get all pages that matches the range in -pp between the pages from -p to -l. Also multiple -pp options accumulate, unlike -p and -l. The - separator can also be :. Note that -pp -1 will be interpreted as "all pages up to and including 1", if you want a page numbered -1 (only the table of contents, say) put -pp -1--1, or more readable, -pp -1:-1.
-q*
Run quietly. Don't chatter about pages converted, etc. to standard output; report no warnings (only errors) to standard error.
-Q num
Set the quality to num. That is, choose the number of antialiasing levels for bitmapped fonts (PK), to be num*num+1. The default value is 4 which gives 17 levels of antialiasing for antialiased fonts from these two. If FreeType is available, its rendering is unaffected by this option.
-r*
Toggle output of pages in reverse/forward order. By default, the first page in the DVI is output first.
--strict*
The program exits when a warning occurs. Normally, dvipng will output an image in spite of a warning, but there may be something missing in this image. One reason to use this option would be if you have a more complete but slower fallback converter. See the --picky option above for a list of when warnings occur.
-T image_size
Set the image size to image_size which can be either of bbox, tight, or a comma-separated pair of dimensions hsize,vsize such as .1in,.3cm. The default is bbox which produces a PNG that includes all ink put on the page and in addition the DVI origin, located 1in from the top and 1in from the left edge of the paper. This usually gives whitespace above and to the left in the produced image. The value tight will make dvipng only include all ink put on the page, producing neat images.
--truecolor*
This will make dvipng generate truecolor output. Note that truecolor output is automatic if you include an external image in your DVI, e.g., via a PostScript special (i.e., the graphics or graphicx package). This switch is overridden by the --palette switch.
-v*
Enable verbose operation. This will currently indicate what fonts is used, in addition to the usual output.
--width*
Report the width of the image. See also --height and --depth.
-x num
This option is deprecated; it should not be used. It is much better to select the output resolution directly with the -D option. This option sets the magnification ratio to num/1000 and overrides the magnification specified in the DVI file. Must be between 10 and 100000. It is recommended that you use standard magstep values (1095, 1200, 1440, 1728, 2074, 2488, 2986, and so on) to help reduce the total number of PK files generated. num may be a real number, not an integer, for increased precision.
-z num
Set the PNG compression level to num. This option is enabled if your libgd is new enough. The default compression level is 1, which selects maximum speed at the price of slightly larger PNGs. For an older libgd, the hard-soldered value 5 is used. The include file png.h says "Currently, valid values range from 0 - 9, corresponding directly to the zlib compression levels 0 - 9 (0 - no compression, 9 - "maximal" compression). Note that tests have shown that zlib compression levels 3-6 usually perform as well as level 9 for PNG images, and do considerably fewer calculations. In the future, these values may not correspond directly to the zlib compression levels."
