DESCRIPTIO

N

dvgrab est un programme qui capture des données vidéo et audio DV ou HDV (MPEG2-TS) depuis des caméscopes numériques via FireWire (IEEE 1394). Les données sont stockées dans un ou plusieurs fichiers et peuvent ensuite être traitées par un logiciel de montage vidéo. dvgrab peut piloter à distance le caméscope mais il ne affiche pas le contenu de la vidéo à

l'écran.

dvgrab prend également en charge les périphériques DV conformes à UVC (USB Video Class) utilisant le module du noyau Linux uvcvideo, qui est un pilote V4L2. Dans ce mode, il n'y a pas de contrôle AV/C VTR et par conséquent le mode interactif est presque inutile. La fonctionnalité interactive

est

L'argument base est utilisé pour construire le nom de fichier afin de stocker les données vidéo : base-num.ext. num est un numéro incrémental commençant à 001, et ext est l'extension du nom de fichier spécifiant le format de fichier utilisé, p. ex. avi. Un schéma de nommage différent est utilisé lorsque -timestamp, -timecode, ou -timesys est spécifié (voir ci-dessous). Si base est un nom de fichier complet incluant l'extension, alors dvgrab tente de déterminer le format du fichier de sortie à partir de l'extension, mais il insère quand même num. La valeur par défaut pour base est « dvgrab- »

.

Si vous spécifiez un « - » final, le format est forcé à DV brut ou HDV et est envoyé vers stdout. dvgrab enverra également du DV brut ou HDV vers stdout tout en capturant vers un fichier si stdout est redirigé ou connecté via un

tube.

Vous pouvez utiliser les puissantes capacités d'écriture de fichiers de dvgrab avec d'autres programmes qui produisent du DV brut ou HDV. En utilisant l'option -stdin et si dvgrab détecte qu'il se trouve à l'extrémité réceptrice d'un tube et qu'il n'est

pas en mode interactif, alors il essaier
a de lire du DV brut ou HDV sur stdin.

OPTION

S

Les options plus longues qu'un seul caractère peuvent être spécifiées avec un ou deux tirets initiaux. De plus, vous pouvez utiliser un espace ou un signe égal pour séparer le nom de l'option et la valeur de son

argument.
-a[num], -autosplit[=num]
Tente de détecter chaque fois qu'un nouvel enregistrement commence, et le stocke dans un fichier séparé. Cela peut être combiné avec les options -frames et -size, et une division se produit chaque fois qu'un événement spécifié survient. La division automatique est désactivée par
défaut.
num est facultatif. Sans lui, dvgrab détermine quand diviser en utilisant un indicateur dans le flux ou une discontinuité dans le timecode, où une discontinuité de timecode est tout recul ou une valeur supérieure à une seconde. Si vous définissez l'argument facultatif num, vous pouvez définir la sensibilité temporelle en secondes et ignorer l'indicateur de nouvel enregistrement du flux. Cela vous permet essentiellement de diviser sur de plus grands intervalles de temps tels que des minutes ou des heures. Par exemple, -autosplit=3600 divise l'enregistrement chaque fois qu'il y a un intervalle dans l'enregistrement d'une heure ou
plus.
-buffers num
Le nombre de trames à utiliser pour tamponner les retards d'E/S du périphérique. Par défaut à
100.
-card num
Indique à dvgrab de recevoir les données de la carte FireWire num. Le comportement par défaut est de sélectionner automatiquement la première carte contenant la première caméra découverte. S'il est utilisé en conjonction avec -noavc, alors aucune interrogation du bus n'est effectuée. S'il est utilisé en conjonction avec -guid hex, alors seul le bus spécifié est interrogé pour trouver le nœud avec le guid hex
.
-channel num
Canal isochrone à partir duquel recevoir les données. Par défaut à 63, ce qui est à peu près standard parmi les caméscopes DV de nos jours. Si vous spécifiez autre chose, aucune tentative n'est faite à ce moment pour indiquer au périphérique quel canal utiliser. Vous devez avoir un moyen manuel d'indiquer au périphérique émetteur quel canal
utiliser.
-cmincutsize num
Cette option est utilisée pour démarrer la collection si une coupure survient num mégaoctets (en fait, mébioctets) avant la fin de la collection. Cette option réduit la création de petits fichiers lors de l'utilisation de l'option -csize . Lorsqu'une nouvelle collection est démarrée de cette manière, la quantité d'espace libre dans la collection précédente est enregistrée, et tant que les clips suivants tiennent dans la collection précédente, le point de départ de la nouvelle collection est
réinitialisé.
-csize num
Cette option indique à dvgrab de diviser les fichiers lorsque la collection de fichiers dépasse num . Cette option est utilisée pour créer des collections de fichiers qui tiennent parfaitement dans num mégaoctets (en fait, mébioctets) (c.-à-d. pour archiver sur DVD). Lorsque cela se produit, une nouvelle collection est démarrée (voir aussi l'option -cmincutsize
)
-debug type
Affiche les informations de débogage HDV, type est un ou plusieurs des éléments suivants : all,pat,pmt,pids,pid=N,pes,packet,video,
sonya1
-d, -duration time
Définit la durée de capture maximale sur l'ensemble des divisions de fichiers pour une seule session de capture (plusieurs sessions sont possibles en mode interactif). La valeur time est exprimée au format SMIL2 MediaClipping Time. Voir http://w3.org/AudioVideo/ pour la
spécification.
Brièvement, les formats sont
:
XXX[.Y]h, XXX[.Y]min, XXX[.Y][s],

[[HH:]MM:]SS[.ms], ou smpte=[[[HH:]MM:]SS:]

-every n
Cette option indique à dvgrab d'écrire seulement une trame sur n (par défaut toutes les trames)
.
-f, -format dv1 | dv2 | avi | raw | dif | qt | mov | jpeg | jpg | mpeg2 | hdv
Spécifie le format du/des fichier(s) de sortie. Le format de fichier peut également être déterminé si vous incluez une extension sur le nom de base. Les extensions suivantes sont reconnues : avi, dv, dif, mov, jpg, jpeg, et m2t (HDV)
.
dv1 et dv2 sont tous deux des fichiers AVI avec des formats légèrement différents. dv2 stocke une piste audio séparée en plus de la piste vidéo DV, ce qui est plus compatible avec d'autres applications. dv1 ne stocke qu'une seule piste DV intégrée puisque le format DV entrelace nativement l'audio avec la vidéo. Par conséquent, bien que dv1 produise une sortie plus petite, certaines applications ne le comprennent pas et nécessitent dv2 à la place. dvgrab est capable de créer des fichiers AVI extrêmement volumineux — bien au-delà de 2 ou 4 Go — cependant, la compatibilité avec d'autres outils commence à diminuer au-delà de 1
Go.
raw stocke les données non modifiées et a l'extension .dv. Ces fichiers sont lus par un certain nombre d'outils GNU/Linux ainsi que par Apple
Quicktime.
dif est une variation du DV brut qui nomme les fichiers avec une extension .dif afin qu'ils puissent être chargés plus immédiatement dans MainConcept
MainActor5.
qt est Quicktime, mais nécessite que dvgrab soit compilé avec
libquicktime.
jpg ou jpeg est pour une séquence de fichiers d'images JPEG si dvgrab a été compilé avec libdv et jpeglib. Cette option ne peut être utilisée qu'avec une entrée DV, et non HDV (MPEG2-TS)
.
mpeg2 ou hdv est pour un flux de transport MPEG-2 lors de l'utilisation, par exemple, d'un caméscope HDV ou d'un décodeur TV
numérique.
Par défaut à ra
w
-F, -frames num
Cette option indique à dvgrab de stocker au plus num trames par fichier avant de diviser vers un nouveau fichier, où num = 0 signifie illimité. Le temps correspondant dépend du système vidéo utilisé. PAL affiche 25, NTSC environ 30 trames par
seconde.
-guid hex
Si vous avez plus d'un périphérique DV, alors sélectionnez-en un en utilisant le GUID du nœud spécifié en format hex (hexadécimal). C'est le format affiché dans /proc/bus/ieee1394/devices ou le nouveau système de fichiers /sys du noyau 2.6. Lorsque vous spécifiez un GUID, dvgrab établira (ou superposera) une connexion pair-à-pair avec le périphérique au lieu d'écouter la diffusion du périphérique. Si vous fournissez une valeur hex de 1, alors dvgrab tentera de découvrir le périphérique ainsi que d'établir une connexion pair-à-pair. C'est particulièrement utile avec les boîtes décodeurs MPEG2-TS, qui nécessitent généralement une procédure de gestion de connexion pour commencer à
transmettre.
-h,
-help
Affiche un résumé des
options.
-I, -input fichier
Lit depuis le fichier au lieu de FireWire. Vous pouvez utiliser '-' pour stdin au lieu d'utiliser -stdin
.
-i,
-interactive
Rend dvgrab interactif où des appuis sur une seule touche de stdin contrôlent le VTR de la caméra ou démarrent et arrêtent la capture. Sinon, dvgrab s'exécute en mode session, où il démarre immédiatement la capture et s'arrête selon les directives ou l'interruption (ctrl-c)
.
-jpeg-deinterl
ace
Si vous utilisez -format jpeg, désentrelace la sortie en doublant les lignes du champ supérieur. C'est une forme bon marché de désentrelacement qui résulte en une perte effective de 50% en
résolution.
-jpeg-height num
Si vous utilisez -format jpeg, met à l'échelle la hauteur de la sortie vers num (1 - 2048)
.
-jpeg-overwrite nom
Écrit dans le même fichier image pour chaque image, au lieu de créer une séquence de fichiers
image.
-jpeg-quality num
Si vous utilisez -format jpeg, définit le niveau de qualité JPEG de 0 (pire) à 100 (meilleur)
.
-jpeg-temp nom 1
0
Utilise un fichier temporaire pour créer le jpeg, renomme le fichier vers le nom de fichier cible une fois terminé. Utile lorsque vous utilisez dvgrab avec -jpeg-overwrite pour générer une image de
webcam.
-jpeg-width num
Si vous utilisez -format jpeg, met à l'échelle la largeur de la sortie vers num (1 - 2048)
.
La largeur et la hauteur de mise à l'échelle JPEG doivent être toutes deux soit inférieures soit supérieures à la taille normale de l'image. Par exemple, la taille mise à l'échelle de 700 de large par 525 de haut donne une belle image au rapport d'aspect 4:3 avec des pixels carrés, mais c'est illégal pour NTSC car 700 est inférieur à la largeur normale de 720 alors que la hauteur est supérieure à la hauteur normale de
480.
Puisque DV utilise des pixels non carrés, il est agréable de pouvoir mettre à l'échelle vers une image basée sur un rapport d'aspect 4:3 en utilisant des pixels carrés. Pour NTSC, les tailles d'exemple sont 800x600, 640x480, et 320x240. Pour PAL, les tailles de pixels carrés d'exemple sont 384x270 et
768x540.
-jvc-p
25
Supprime le drapeau repeat_first_field et définit les images par seconde à 25 pour corriger un flux enregistré en mode JVC HDV
P25.
-lockst
ep
Aligner la capture sur un multiple de -frames basé sur le timecode. C'est utile pour la redondance, lorsque plus d'une machine capture depuis le même périphérique FireWire, et que vous voulez vous assurer que chaque fichier contient les mêmes images. Pour vous assurer que les fichiers de chaque machine ont le même nom, utilisez l'option -timecode et le même nom de
base.
-lockstep_maxdrops num
Si num images sont perdues consécutivement, alors fermez le fichier et reprenez la capture à l'intervalle lockstop suivant. Si num est -1, alors autorisez un nombre illimité d'images perdues consécutivement ; c'est le
défaut.
-lockstep_totaldrops num
Si num images sont perdues dans le fichier courant, alors fermez le fichier et reprenez la capture à l'intervalle lockstep suivant. Si num est -1, alors autorisez un nombre illimité d'images perdues au total ; c'est le
défaut.
-noa
vc
Désactive l'utilisation du contrôle VTR AV/C. C'est utile si vous capturez de la vidéo en direct depuis une caméra car en mode caméra, une commande de lecture AV/C indique à la caméra de commencer l'enregistrement, peut-être par-dessus du matériel sur la bande courante. Cela s'applique soit au mode interactif soit au non-interactif car le non-interactif envoie toujours une lecture et un arrêt au VTR au début et à la fin de la
capture.
-nost
op
Désactive l'envoi de la commande d'arrêt VTR AV/C lors de la sortie de dvgrab
.
-opend
ml
Si vous utilisez -format dv2, crée un DV AVI de type 2 conforme OpenDML. C'est requis pour supporter les fichiers dv2 >1GB. dv1 supporte toujours les fichiers >
1GB.
-r,
-recordonly
Lorsque la caméra est en mode enregistrement, cette option fait que dvgrab ne capture que lorsque la caméra enregistre et n'est pas en pause. Normalement, en mode enregistrement, dvgrab capture toujours pour vous permettre d'utiliser la caméra purement comme une caméra où l'opérateur de l'ordinateur est aux commandes. Cette option fait que dvgrab agit comme le magnétoscope où l'opérateur de la caméra contrôle quand la capture a lieu. C'est très pratique lorsqu'il est utilisé avec l'option -autosplit pour créer automatiquement un nouveau fichier pour chaque prise. Cette option nécessite AV/C et ne fonctionnera pas avec l'option -noavc
.
-rewi
nd
Rembobine complètement la bande jusqu'au début avant de commencer la capture. Naturellement, cela nécessite AV/C ; cependant, peut-être moins évident est que cela ne s'applique pas au mode
interactif.
-showstat
us
Normalement, les informations d'état de la capture sont affichées après avoir terminé l'écriture dans chaque fichier. Cette option les affiche pendant la capture, mise à jour pour chaque
image.
-s, -size num
Cette option indique à dvgrab de stocker au plus num mégaoctets (en fait, mébioctets) par fichier, où num = 0 signifie une taille de fichier illimitée pour les grands fichiers. La limite de taille par défaut est de 1024
Mo.
-s
rt
Génère des fichiers de sous-titres contenant la date et l'heure d'enregistrement au format SRT. Pour chaque fichier vidéo créé, deux fichiers supplémentaires avec l'extension .srt0 et .srt1 sont créés. Ils contiennent la date et l'heure d'enregistrement comme sous-titres au format SRT. Le fichier .srt0 contient les sous-titres avec un minutage basé sur le temps écoulé depuis le début du fichier courant. Utilisez ce fichier si vous transcodez vers un format comme AVI. Le fichier .srt1 contient les sous-titres avec un minutage basé sur le timecode tel que fourni par la caméra. Le programme mplayer comprend ce type de
sous-titres.
-std
in
Lit le flux DV depuis un tube sur stdin au lieu de
FireWire.
-timeco
de
Place le timecode de la première image de chaque fichier dans le nom du
fichier.
-t,
-timestamp
Place les informations sur la date et l'heure d'enregistrement dans le nom du
fichier.
-times
ys
Place la date et l'heure du système plutôt que celles de l'enregistrement dans le nom du fichier. C'est utile lorsque vous utilisez des convertisseurs qui ne changent pas la date et l'heure d'enregistrement dans le flux
DV.

-v4l2
Capture depuis un périphérique USB Video Class (UVC) qui supporte DV. Cela utilise le module de noyau uvcvideo via V4L2. Le fichier de périphérique par défaut est /dev/video. Utilisez l'option -input pour définir un fichier de périphérique
différent.

programme.

EXEMPLE

S
dvgrab
foo-
Capture les données vidéo depuis la source FireWire par défaut et les stocke dans les fichiers foo-001.avi, foo-002.avi,
etc.
dvgrab -frames 25
foo-
En supposant une source vidéo PAL, cette commande enregistre l'équivalent d'une seconde de données vidéo par
fichier.
dvgrab -autosplit -frames 750 -timestamp
foo-
Enregistre les données vidéo depuis la source FireWire par défaut, les découpe en morceaux de 30 secondes (en supposant PAL) ou lorsqu'un nouvel enregistrement commence et nomme les fichiers résultants selon les informations de date et d'heure dans le flux
vidéo.
dvgrab -autosplit -size 1998 -csize 4400 -cmincutsize 10
foo-
Enregistre les données vidéo depuis la source FireWire par défaut, les découpe en morceaux lorsqu'un nouvel enregistrement commence ou lorsque le fichier courant dépasse 1998 mégaoctets (en fait, mébioctets), ou que la collection courante de fichiers dépasse 4400 mégaoctets. Cela réduit aussi la taille du plus petit fichier créé dû à une découpe de taille de collection à 10
mégaoctets.
Cette option est parfaite pour sauvegarder DV sur des DVD car 2 Go est environ la taille de fichier maximale que (l'implémentation actuelle) linux du système de fichiers ISO9660 peut gérer
!
Avertissement : il est possible de créer des systèmes de fichiers ISO9660 avec des fichiers supérieurs à 2 Go, mais le pilote IS09660 actuel de linux ne peut pas les lire ! Les noyaux linux plus récents peuvent être capables de gérer les systèmes de fichiers ISO9660ems avec des tailles de fichiers supérieures à 2
Go.
