DESCRIPTIO

N

Le programme dvipdfmx génère un fichier PDF à partir d'un fichier DVI. Les fichiers DVI sont la sortie produite par TeX. groff peut également générer des fichiers DVI en utilisant grodvi(-T

dvi).

Dans TeX Live, dvipdfm est une autre incarnation de dvipdfmx plutôt qu'un programme séparé. La compatibilité est tentée dans la mesure du

possible.

xdvipdfmx est une autre incarnation. Il est utilisé comme arrière-plan pour xetex(1) et n'est pas destiné à être invoqué

directement.

dvipdfmx reconnaît plusieurs commandes \special couramment utilisées, qui sont des extensions du format DVI. Plus précisément, il comprend les specials de couleur, les specials de taille du papier, les specials tpic (qui permettent de l'utiliser avec pic), les specials hypertex et certains specials PostScript. Ces extensions permettent aux documents de contenir de la couleur, des figures et des liens hypertextes. Le programme tente d'imiter le comportement de dvips dans la mesure du possible, afin que de nombreux paquets de macros produits pour être utilisés avec dvips fonctionnent également avec dvipdfmx. De plus, dvipdfmx comprend ses propres commandes \special spécifiques permettant d'accéder à des fonctionnalités PDF telles que les annotations et les

signets.

Depuis décembre 2018, un tel special spécifique à dvipdfmx est pdf:trailerid, qui spécifie le /ID dans le trailer PDF. Il est utilisé comme ceci (au niveau TeX) :
\special{pdf:trailerid [ (0123456789abcdef) (01234567890abcdef) ]}
C'est-à-dire que le special prend un tableau (les crochets) de deux chaînes PDF de 16 octets (les parenthèses). C'est la même syntaxe que celle de \pdfvariable trailerid de LuaTeX, mais différente de celle de \pdftrailerid de pdfTeX. Il doit apparaître sur la première page de sortie, sinon il est

ignoré.

Les specials non reconnus généreront des messages d'avertissement. Les paquets qui peuvent nécessiter une option de pilote dvipdfm ou dvipdfmx incluent geometry, hyperref, bookmark, graphicx et xcolor. Pour les problèmes liés aux boîtes englobantes (et donc aux tailles d'images)

, voir

BALLES DE LIMITE D'IMAGE

Lors de l'inclusion d'images avec dvipdfmx, leurs balles de limite doivent être générées en exécutant extractbb. Le résultat sera dans un fichier .xbb ; les informations xbb sont identiques à celles du format PDF.

ENVIRONNEMENT

dvipdfmx utilise la bibliothèque kpathsea pour localiser les fichiers qu'il ouvre. Par conséquent, les variables d'environnement documentées dans la documentation de la bibliothèque Kpathsea influencent dvipdfmx. Il utilise également la valeur de la variable d'environnement TMPDIR comme répertoire pour rechercher les images miniatures de chaque page.

FICHIERS

L'emplacement précis des fichiers suivants est déterminé par la configuration de la bibliothèque Kpathsea. L'emplacement peut être déterminé en utilisant kpsewhich, par exemple,

kpsewhich -progname=dvipdfmx -format='other text files' dvipdfmx.cfg
dvipdfmx.cfg
Fichier de configuration par défaut
dvipdfmx-unsafe.cfg
Fichier de configuration qui exécute Ghostscript sans vérifications de sécurité ; à utiliser uniquement pour les fichiers sources de confiance. Il est actuellement requis pour utiliser PSTricks avec XeTeX : xetex -output-driver="xdvipdfmx -i dvipdfmx-unsafe.cfg -q -E" ...
pdftex.map
Le fichier de mappage de polices par défaut (peut être modifié dans le fichier de configuration).
*.tfm
Métriques de polices TeX
*.vf
Fichiers de polices virtuelles TeX
*.pfb
Fichiers de polices PostScript Type 1
texmf.cnf
Le fichier de configuration de la bibliothèque Kpathsea. L'emplacement de ce fichier peut être trouvé en tapant 
kpsewhich texmf.cnf
