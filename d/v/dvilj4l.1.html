DESCRIPTIO

N

dvilj et ses variantes convertissent les fichiers de sortie TeX « .dvi » en commandes PCL (Printer Control Language de Hewlett-Packard) adaptées à l'impression sur un HP LaserJet+, un HP LaserJet IIP (en utilisant dvilj2p), un HP LaserJet 4 (en utilisant dvilj4), et les imprimantes entièrement

compatibles.

dvilj4 fournit également la prise en charge des polices Intellifont et TrueType intégrées ; les fichiers TFM et VF sont fournis dans la distribution. Les polices virtuelles ne sont pas prises en charge directement par dvilj, vous devez donc exécuter dvicopy(1) au préalable, ou autrement étendre les polices

virtuelles

Tous les programmes sont générés à partir d'un seul fichier source dvi2xx.c. Ils sont généralement appelés via un script shell ou en tant que filtre d'imprimante ligne. Un tel script, dvihp(1), est inclus dans la distribution. Il fournit des options en ligne de commande similaires à celles de dvip

s(1
).

COMMANDES TeX \special PRISES EN

CHARGE

Les commandes « \special » prises en charge par dvilj ont la syntaxe

générique 
\special{key1=value key1="value with space"}
\special{key3 = value key4 = 'note optional spaces around equal
sign'}

C'est-à-dire que les specials sont une séquence de paires clé/valeur, séparées par un signe égal. Les espaces autour du signe égal sont ignorées. La valeur est soit un mot séparé par des espaces, soit une chaîne entre guillemets. Les guillemets doubles et simples peuvent être utilisés, alternativement. Il n'y a pas de support pour échapper les caractères de guillemets dans les valeurs ; si vous voulez à la fois des guillemets doubles et simples dans une même valeur, vous avez de la

malchance.

Les combinaisons clé/valeur suivantes sont valides

:
hpfile=fich
ier
Insère le fichier à la position courante. Le fichier est recherché avec kpathsea(3), voir ci-dessous.

Le contenu du fichier doit être valide pour cette imprimante, c'est-à-dire qu'il doit contenir des séquences d'échappement PCL ou des commandes HP-GL/2. Si le fichier est un fichier graphique, cela signifie généralement que le coin supérieur gauche du graphique est placé à la position

courante.

Les séquences d'échappement de positionnement absolu PCL dans le fichier sont réécrites en commandes de positionnement relatif ; la

coordonnée la plus basse apparaissant
est utilisée comme référence.
hpfile_verbatim=fich
ier
Insère le fichier tel quel à la position courante, sans aucune modification du contenu du fichier. Le fichier est recherché avec kpathsea(3), voir ci-dessous.

C'est principalement utilisé pour conserver les positions absolues dans les fichiers

PCL.
psfile=fichier llx=x0 lly=y0 urx=x1 ury=y1 rwi=
s
Convertit le fichier PostScript fichier en HP PCL, par Ghostscript avec le périphérique "ljetplus", et insère le fichier graphique résultant à la position courante, en réécrivant les séquences d'échappement de positionnement absolu. Le fichier est recherché avec kpathsea(3), voir ci-dessous.

Les paires clé/valeur accompagnatrices sont obligatoires, elles peuvent être spécifiées dans un ordre arbitraire. Les valeurs x0, x1, y0, y1, et s sont des entiers. (x0,y0) est le coin inférieur gauche, (x1,y1) le coin supérieur droit de

l'image.

Veuillez noter : La sémantique spécifique de cette commande spéciale n'est pas connue. En particulier, le paramètre rwi est un certain facteur d'échelle ; mais même en examinant le code source, il n'est pas tout à fait clair ce que l'auteur de la spéciale avait l'intention d'implémenter ici. De plus, il n'est pas clair quelles dimensions sont utilisées pour spécifier les coins, des points PostScript ou des points

PCL.

Si vous connaissez la sémantique de psfile, ou si vous avez pris la peine de l' analyser, veuillez nous informer à tex-k@tug.org, afin que nous puissions mettre à jour cette page d

e manuel avec les informa
tions pertinentes.
dvilj-psfile-syntax=synta
xe
où la syntaxe est soit "dvilj" soit "ignore". C'est une manière très rudimentaire de dire au pilote quoi faire avec les commandes spéciales psfile.

Si la valeur est "ignore", toutes les commandes spéciales psfile traitées par la suite sont ignorées, jusqu'à ce que la prochaine commande spéciale dvilj-psfile-syntax soit

traitée.

Si la valeur est "dvilj", les commandes spéciales psfile sont traitées comme expliqué ci-dessus, jusqu'à ce que la prochaine commande spéciale dvilj-psfile-syntax soit

traitée.

Une extension évidente et prévue est la valeur "dvips", mais cela n'a pas été implémenté pour

l'instant.

Cette spéciale n'est pas aussi simple qu'elle le semble à première vue. Puisque sa sémantique est définie par l'ordre de traitement, elle n'est utile que si elle est placée sur la même page que la commande spéciale psfile. L'avoir une seule fois dans un fichier (par exemple, sur la première page) n'aide pas si vous n'imprimez qu'une seule page du document -- dvilj ne fait pas de préscan des commandes spéciales de première page comme le

font certains autres pilotes. (Les correc
tifs seraient bienvenus, bien sûr.)

Recherche des Fichiers

Inclus

Les commandes spéciales d'inclusion de fichiers appropriées recherchent le fichier avec kpathsea(3). Le chemin de recherche est configuré par la variable "DVILJINPUTS" et, si le fichier n'est pas trouvé dans ce chemin de recherche, par la variable "TEXINPUTS"

.

La recherche via "DVILJINPUTS" couvre le cas d'utilisation où l'on a des graphiques communs à l'échelle du site qui doivent être inclus dans des documents, par exemple des signatures numérisées. La recherche via "TEXINPUTS" couvre le cas d'utilisation où l'on a des graphiques faisant partie de son document

courant.

"dvilj" est utilisé comme le nom ".PROGRAM" dans texmf.cnf, pour toutes les variantes de pi

lote, indépendamment du
nom réel du programme.

Commandes Spéciales Inconnues et Configuration

"TEX_HUSH"

Kpathsea(3) a le concept de suppression d'avertissements avec la variable de configuration "TEX_HUSH", veuillez vous référer à son nœud Info TeX support / Suppressing warnings. Cette variable contient des identifiants séparés par des deux-points qui spécifient les avertissements à

supprimer.

Si "special" est parmi les valeurs listées, dvilj ne produit plus d'avertissements sur les commandes spéciales qu'il ne connaît pas. Mais s'il y a une spéciale reconnue et si cette spéciale a un paramètre invalide, un avertissement est produit quand même, indépendamment du contenu de "TEX

_HU
SH
".

IMPRESSION DE PAGES

DOUBLES

Si l'imprimante a une unité duplex installée, l'impression duplex peut être demandée avec l' option

-d.

Sinon, l'option de ligne de commande -D fait imprimer l'imprimante en mode double page, c'est-à-dire, en gros, imprimerst les pages paires puis les pages impaires d'un document. Si -D est utilisé pour imprimer à la fois les pages paires et impaires (-D est utilisé sans l'option 1 ou 2) ce qui suit se produit après que la moitié des pages a été imprimée : LJ : l'imprimante s'arrête, affiche le message "FEED" et allume la LED d'alimentation manuelle. L'imprimante continue lorsque les pages imprimées sont soit insérées dans l'alimentation manuelle, soit que l'opérateur appuie sur le bouton de continuation (après avoir d'abord placé les pages imprimées dans le bac à papier)

.

Si -D1 a été spécifié, seules les pages impaires seront imprimées, -D2 peut être utilisé pour les pages paires. Un tiret final "-" (comme dans -D-, -D1- ou -D2-) supprime l'impression des pages vides qui sont autrement générées pour le

remplissage.

Le pilote permet l'option -D pour les deux sens d'impression (impression recto-verso ou verso-verso). Il essaie d'être intelligent dans certains cas : lorsqu'un document a un nombre impair de pages, il insère à l'endroit approprié une page vide ; lorsqu'un document commence par la page 0, le pilote insère une page vide après la page 0 ; lorsqu'un fragment d'un document est imprimé et commence par un numéro de page pair, il imprime cette page au verso de la première page pour s'assurer que les pages impaires sont toujours au recto. La page 0 est traitée comme une page

impaire.

L'option doubleside fonctionne pour tous les LJ, pas seulement pour le nouveau modèle D qui fait l'impression recto-verso (en fait, je ne sais pas si cela a beaucoup de sens sur le nouveau LJ II D)

.

Avertissement sur l'option doubleside : lorsqu'elle est utilisée fréquemment ou sur de très grands fichiers, il peut devenir nécessaire de nettoyer l'imprimante beaucoup plus

fréquemment.

L'option de ligne de commande -pX peut être utilisée pour interrompre l'impression après la sortie de X pages (peut conduire à des résultats étranges combinée avec -D). Personnellement, je n'aime pas cette option. La manière sûre d'imprimer une partie d'un document est d'utiliser -f (from) et -t

(t
o).
