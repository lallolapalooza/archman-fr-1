NOM

DVIasm - un programme utilitaire TeX pour éditer directement les fichiers DVI

SYNOPIS

dviasm [<options>] <fichier_dvi>|<fichier_dump_dvi>

DESCRIPTION

DVIasm est un programme utilitaire TeX conçu pour éditer directement les fichiers DeVice-Independent (DVI). Il se compose d'un unique script Python, dviasm.py, sous une forme textuelle lisible par l'homme. Il s'exécute sur toute plateforme sur laquelle Python 3 est installé.

Les fonctionnalités de DVIasm incluent :
1) Désassembler un fichier DVI (ou un fichier XDV de XeTeX) en un fichier texte lisible par l'homme, dont le contenu est facile à modifier.
2) Assembler le fichier texte de sortie pour revenir au format binaire.
Il existe plusieurs alternatives pour exporter et éditer des fichiers DVI :
1) DVItype développé par Donald E. Knuth prend en charge la conversion unidirectionnelle du DVI vers un format texte. Il existe également certains dérivés : pDVItype pour pTeX, upDVItype pour upTeX, ODVItype pour Omega.
2) Les programmes dv2dt et dt2dv peuvent être utilisés par paires pour permettre une conversion bidirectionnelle entre DVI et le DVI Text Language (DTL).
3) Le programme dvispc (qui fait partie de l'aperçuteur DVIOUT) a également la capacité de convertir entre DVI et texte.

Parmi ceux-ci, DVIasm est conçu pour permettre aux utilisateurs d'éditer facilement les fichiers DVI, par exemple en unifiant « right1 »-« right4 » en une seule commande « right » qui peut être utilisée indépendamment de la quantité de déplacement.

OPTIONS

--version
Affiche le numéro de version du programme et quitte.
-h, --help
Affiche ce message d'aide et quitte.
-u <CHAÎNE>, --unit=<CHAÎNE>
Définit l'unité [par défaut : `pt']. Les valeurs autorisées sont : `sp', `pt', `bp', `mm', `cm' et `in'.
-o <FICHIER>, --output=<FICHIER>
Définit le nom du fichier de sortie au lieu de stdout.
-e <CHAÎNE>, --encoding=<CHAÎNE>
Définit le codage pour l'entrée/sortie du texte exporté [par défaut : `utf8']. Les valeurs autorisées sont : `ascii', `latin1', `utf8', `sjis' et `eucjp'. Lorsqu'il est utilisé avec l'option -p (ou --ptex), les valeurs autorisées sont uniquement `utf8', `sjis' et `eucjp'.
# NOTE : Cette fonctionnalité ne prend pas en charge l'exportation via stdout.
-x <CHAÎNE>, --xxx-encoding=<CHAÎNE>
Définit le codage pour l'interprétation des chaînes `xxx:' [par défaut : `none']. Les valeurs autorisées sont : `none', `utf8', `sjis' et `eucjp'.
Cette option permet aux utilisateurs de spécifier le codage correct pour l'exportation/compilation du contenu des commandes \special.
Les utilisations typiques sont les suivantes :
1) Par défaut, le contenu de \special est exporté/compilé sous forme de séquences d'échappement octet par octet au format `\x..' . Cela suffira si vous n'avez pas besoin de lire/modifier le contenu de \special.
3) Pour les utilisateurs de XeTeX et upTeX, `-x utf8' serait utile car ces moteurs utilisent UTF-8 pour coder les chaînes à l'intérieur des commandes \special.
2) Pour les utilisateurs de pTeX avec un DVI codé en ISO-2022-JP, il serait utile de sélectionner l'option appropriée `-x eucjp' (pour Unix) ou `-x sjis' (pour Windows) pour être cohérent avec le codage Kanji interne utilisé par le moteur pTeX.
-t <INT>, --tabsize=<INT>
Définit la taille de tabulation pour push/pop [par défaut : 2].
-p, --ptex
Exporte et compile un DVI codé en ISO-2022-JP pour pTeX japonais. Cette option est requise pour décoder ou coder correctement les caractères japonais composés (en utilisant `set2' ou `put2').
-s <CHAÎNE>, --subfont=<CHAÎNE>
Spécifie la liste des polices avec un schéma de sous-police UCS2 au format séparé par des virgules. Si <CHAÎNE> est vide, la liste interne prédéfinie des sous-polices est désactivée.
Cette option serait utile par exemple lors de l'utilisation du package CJK.

AUTEURS

La première version a été écrite en Python 2 par Jin-Hwan Cho en 2007. Khaled Hosny a commencé à prendre en charge l'exportation/compilation du format XDV de XeTeX en 2014. Arthur Reutenauer a porté le script vers Python 3 en 2019. Le mainteneur actuel de DVIasm est Hironobu Yamashita, depuis 2020.
