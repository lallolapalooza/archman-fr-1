DVIPDFMX(1) Manuel des commandes générales DVIPDFMX(1)

NOM

dvipdfmx, xdvipdfmx, dvipdfm - produit des fichiers PDF directement à partir de fichiers DVI

SYNTAXE

dvipdfmx ou dvipdfm [options] fichier[.dvi]

DESCRIPTION

Le programme dvipdfmx génère un fichier PDF à partir d'un fichier DVI. Les fichiers DVI sont la sortie produite par TeX. groff peut également générer des fichiers DVI en utilisant grodvi(-Tdvi).

Dans TeX Live, dvipdfm est une autre incarnation de dvipdfmx plutôt qu'un programme distinct. La compatibilité est tentée au mieux possible.

xdvipdfmx est une autre incarnation. Il est utilisé comme backend pour xetex(1) et n'est pas destiné à être appelé directement.

dvipdfmx reconnaît plusieurs commandes \special couramment utilisées, qui sont des extensions du format DVI. Spécifiquement, il comprend les \specials de couleur, de format de papier, les \specials tpic (qui lui permettent d'être utilisé avec pic), les \specials hypertex, et certains \specials PostScript. Ces extensions permettent aux documents de contenir des couleurs, des figures et des liens hypertexte. Le programme essaie d'imiter le comportement de dvips autant que possible, de sorte que de nombreux packages de macros produits pour être utilisés avec dvips fonctionneront également avec dvipdfmx. De plus, dvipdfmx comprend ses propres commandes \special spécifiques pour permettre l'accès aux fonctionnalités PDF telles que les annotations et les signets.

Depuis décembre 2018, un tel spécial spécifique à dvipdfmx est pdf:trailerid, qui spécifie le /ID dans la bande annonce PDF. Il est utilisé comme suit (depuis le niveau TeX):
\special{pdf:trailerid [ (0123456789abcdef) (01234567890abcdef) ]}
C'est-à-dire que le spécial prend un tableau (les crochets) de deux chaînes PDF de 16 octets (les parenthèses). C'est la même syntaxe que LuaTeX \pdfvariable trailerid, alors qu'elle diffère de pdfTeX \pdftrailerid. Il doit apparaître sur la première page de sortie, sinon il est ignoré.

Les \specials non reconnus généreront des messages d'avertissement. Les packages qui pourraient nécessiter une option de pilote dvipdfm ou dvipdfmx incluent geometry, hyperref, bookmark, graphicx, et xcolor.

Pour les problèmes liés aux boîtes englobantes (et donc aux tailles d'images), voir extractbb(1).

OPTIONS

Contrairement à de nombreux autres programmes, les valeurs des arguments doivent être séparées des noms d'options par un espace, et non par un signe = ; les noms d'options ne peuvent pas être abrégés ; et - et -- ne peuvent pas être utilisés de manière interchangeable.

-c
Ignore (ou accepte) les \specials de couleur. Par défaut, les \specials de couleur sont interprétés normalement (modifiable dans le fichier de configuration). L'option -c peut être utilisée pour produire un document en noir et blanc à partir d'un document contenant des commandes \special TeX couleur.
--dvipdfm
Active le mode d'émulation dvipdfm. C'est le comportement par défaut si le nom de l'exécutable est `dvipdfm'.
-d nombre
Spécifie le nombre de chiffres décimaux dans la sortie PDF ; doit être compris entre 0 et 5, la valeur par défaut est 2.
-e
Ignoré, pour une compatibilité (semi-) avec dvipdfm.
-f fichier_carte
Lit le fichier de carte de polices donné par fichier_carte. Le fichier de carte par défaut dans TeX Live est pdftex.map, tel que défini dans le fichier de configuration.
--help
Affiche un message d'aide et quitte avec succès.
-i fichier_config
Lit fichier_config comme un autre fichier inclus, après avoir lu le dvipdfmx.cfg par défaut.
--kpathsea-debug nombre
Fait en sorte que Kpathsea affiche des informations de débogage ; `-1' pour tout (volumineux).
-l
Sélectionne le mode paysage. En d'autres termes, échange les dimensions x et y du papier.
-m facteur_agrandissement
Agrandit le document d'entrée par facteur_agrandissement.
-o nom_fichier
Définit le nom du fichier de sortie PDF ; utiliser `-' pour stdout. Par défaut, le nom du fichier de sortie est dérivé de l'entrée, c'est-à-dire fichier.pdf.
-p papier
Sélectionne le format de papier par son nom (par exemple, letter, legal, ledger, tabloid, a3, a4, ou a5 )
--pdfm-str-utf8
Suppose que les chaînes PDFMark dans les commandes \special sont encodées en UTF-8.
-q
Mode silencieux.
-r taille
Définit la résolution des polices bitmap à taille points par pouce. Les polices bitmap sont générées par la bibliothèque Kpathsea, qui utilise Metafont. Les polices bitmap sont incluses en tant que polices de Type 3 dans le fichier de sortie PDF. La valeur par défaut est 600.
-s specifications_pages
Sélectionne les pages du fichier DVI à traiter ; la valeur par défaut est `-', ce qui signifie toutes les pages. Les specifications_pages consistent en une liste séparée par des virgules de plages_pages: 
specifications_pages := specification_page[,specifications_pages]
où 
specification_page := page_unique|plage_pages
plage_pages := [page_première]-[page_dernière]
Une page_première vide est traitée comme la première page du fichier DVI, et une page_dernière vide est traitée comme la dernière page du fichier DVI.

Exemples :

-s 1,3,5
inclut les pages 1, 3 et 5 ;
-s -
inclut toutes les pages ;
-s -,-
inclut deux copies de toutes les pages du fichier DVI ; et
-s 1-10
inclut les dix premières pages du fichier DVI.
-t
Recherche des miniatures de chaque page dans le répertoire nommé par la variable d'environnement TMPDIR. Les miniatures doivent être nommées selon un format spécifique : le même nom de base que le fichier DVI et le numéro de page comme extension du nom de fichier. dvipdfmx ne génère pas lui-même ces miniatures, mais il est distribué avec un programme wrapper nommé dvipdft qui le fait.
--version
Affiche un message d'aide et quitte avec succès.
-v
Augmente la verbosité. Les résultats de l'option -v sont cumulatifs (par exemple, -vv augmente la verbosité de deux crans). La verbosité maximale est de quatre.
-x decalage_x
Définit la marge gauche à decalage_x. La marge gauche par défaut est 1.0in. La dimension peut être spécifiée dans n'importe quelle unité comprise par TeX (par exemple, bp, pt, in, cm).
-y decalage_y
Définit la marge supérieure à decalage_y. La marge supérieure par défaut est 1.0in. La dimension peut être spécifiée dans n'importe quelle unité comprise par TeX (par exemple, bpt, pt, in, cm).
-z nombre
Définit le niveau de compression à niveau_compression. Les niveaux de compression vont de 0 (aucune compression) à 9 (compression maximale) et correspondent aux valeurs comprises par zlib ; la valeur par défaut est 9.
-C nombre
Drapeaux d'options divers ; voir la sortie de --help pour les détails.
-D modele
Modèle de ligne de commande pour la conversion PostScript vers PDF ; la valeur par défaut est prise dans le fichier de configuration, qui donne également tous les détails et mentionne plusieurs possibilités.
-E
Essaye toujours d'intégrer les polices, en ignorant les indicateurs de licence, etc.
-I nombre
Durée de vie du cache d'images en heures ; la valeur par défaut est -2, ce qui signifie ne pas mettre en cache les images du tout. Une valeur de -1 signifie effacer toutes les anciennes images et al
de nouvelles images ; 0 signifie effacer toutes les anciennes images mais conserver les nouvelles.
