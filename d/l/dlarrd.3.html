Documentation de la fonction/sous-routine

sous-routine dlarrd (character range, character order, integer n, double precision vl, double precision vu, integer il, integer iu, double precision, dimension( * ) gers, double precision reltol, double precision, dimension( * ) d, double precision, dimension( * ) e, double precision, dimension( * ) e2, double precision pivmin, integer nsplit, integer, dimension( * ) isplit, integer m, double precision, dimension( * ) w, double precision, dimension( * ) werr, double precision wl, double precision wu, integer, dimension( * ) iblock, integer, dimension( * ) indexw, double precision, dimension( * ) work, integer, dimension( * ) iwork, integer info)

DLARRD calcule les valeurs propres d'une matrice symétrique tridiagonale avec une précision appropriée.

But :

!>
!> DLARRD calcule les valeurs propres d'une matrice symétrique
!> tridiagonale T avec une précision appropriée. C'est un code auxiliaire
!> destiné à être appelé depuis DSTEMR.
!> L'utilisateur peut demander toutes les valeurs propres, toutes les valeurs
!> propres dans l'intervalle semi-ouvert (VL, VU], ou les valeurs propres
!> de la IL-ième à la IU-ième.
!>
!> Pour éviter le débordement, la matrice doit être mise à l'échelle de
!> sorte que son plus grand élément ne dépasse pas en valeur absolue
!> overflow**(1/2) * underflow**(1/4), et pour une précision maximale,
!> il ne devrait pas être beaucoup plus petit que cela.
!>
!> Voir W. Kahan, Report CS41, Computer Science Dept., Stanford
!> University, July 21, 1966.
!>

Paramètres

RANGE 
!>          RANGE est CHARACTER*1
!>          = 'A' : () toutes les valeurs propres seront trouvées.
!>          = 'V' : () toutes les valeurs propres dans l'intervalle
!>                           semi-ouvert (VL, VU] seront trouvées.
!>          = 'I' : () les valeurs propres de la IL-ième à la IU-ième
!>                           (de la matrice entière) seront trouvées.
!>

ORDER

!>          ORDER est CHARACTER*1
!>          = 'B' : () les valeurs propres seront regroupées par
!>                              bloc détaché (voir IBLOCK, ISPLIT) et
!>                              ordonnées de la plus petite à la plus
!>                              grande à l'intérieur du bloc.
!>          = 'E' : ()
!>                              les valeurs propres de la matrice
!>                              entière seront ordonnées de la plus
!>                              petite à la plus grande.
!>

N

!>          N est INTEGER
!>          L'ordre de la matrice tridiagonale T.  N >= 0.
!>

VL

!>          VL est DOUBLE PRECISION
!>          Si RANGE='V', la borne inférieure de l'intervalle dans
!>          lequel rechercher les valeurs propres. Les valeurs propres
!>          inférieures ou égales à VL, ou supérieures à VU, ne seront
!>          pas retournées.  VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

VU

!>          VU est DOUBLE PRECISION
!>          Si RANGE='V', la borne supérieure de l'intervalle dans
!>          lequel rechercher les valeurs propres. Les valeurs propres
!>          inférieures ou égales à VL, ou supérieures à VU, ne seront
!>          pas retournées.  VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

IL

!>          IL est INTEGER
!>          Si RANGE='I', l'indice de la plus petite valeur propre
!>          à retourner.
!>          1 <= IL <= IU <= N, si N > 0 ; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

IU

!>          IU est INTEGER
!>          Si RANGE='I', l'indice de la plus grande valeur propre
!>          à retourner.
!>          1 <= IL <= IU <= N, si N > 0 ; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

GERS

!>          GERS est un tableau DOUBLE PRECISION, dimension (2*N)
!>          Les N intervalles de Gerschgorin (le i-ième intervalle de
!>          Gerschgorin est (GERS(2*i-1), GERS(2*i)).
!>

RELTOL

!>          RELTOL est DOUBLE PRECISION
!>          La largeur relative minimale d'un intervalle. Lorsqu'un
!>          intervalle est plus étroit que RELTOL fois le plus grand
!>          (en valeur absolue) de ses bornes, il est considéré comme
!>          suffisamment petit, c'est-à-dire convergé. Remarque : cela
!>          devrait toujours être au moins radix*machine epsilon.
!>

D

!>          D est un tableau DOUBLE PRECISION, dimension (N)
!>          Les n éléments diagonaux de la matrice tridiagonale T.
!>

E

!>          E est un tableau DOUBLE PRECISION, dimension (N-1)
!>          Les (n-1) éléments hors diagonaux de la matrice tridiagonale T.
!>

E2

!>          E2 est un tableau DOUBLE PRECISION, dimension (N-1)
!>          Les (n-1) éléments hors diagonaux au carré de la matrice tridiagonale T.
!>

PIVMIN

!>          PIVMIN est DOUBLE PRECISION
!>          Le pivot minimum autorisé dans la suite de Sturm pour T.
!>

NSPLIT

!>          NSPLIT est INTEGER
!>          Le nombre de blocs diagonaux dans la matrice T.
!>          1 <= NSPLIT <= N.
!>

ISPLIT

!>          ISPLIT est un tableau INTEGER, dimension (N)
!>          Les points de séparation, auxquels T se divise en sous-matrices.
!>          La première sous-matrice se compose des lignes/colonnes 1 à
!>          ISPLIT(1), la deuxième des lignes/colonnes ISPLIT(1)+1 à
!>          ISPLIT(2), etc., et la NSPLIT-ième se compose des
!>          lignes/colonnes ISPLIT(NSPLIT-1)+1 à ISPLIT(NSPLIT)=N.
!>          (Seuls les premiers NSPLIT éléments seront réellement
!>          utilisés, mais comme l'utilisateur ne peut pas savoir a
!>          priori quelle valeur NSPLIT aura, N mots doivent être
!>          réservés pour ISPLIT.)
!>

M

!>          M est INTEGER
!>          Le nombre réel de valeurs propres trouvées. 0 <= M <= N.
!>          (Voir aussi la description de INFO=2,3.)
!>

W

!>          W est un tableau DOUBLE PRECISION, dimension (N)
!>          À la sortie, les premiers M éléments de W contiendront les
!>          approximations des valeurs propres. DLARRD calcule un
!>          intervalle I_j = (a_j, b_j] qui inclut la valeur propre j.
!>          L'approximation de la valeur propre est donnée comme le
!>          point médian de l'intervalle W(j)= ( a_j + b_j)/2. L'erreur
!>          correspondante est bornée par WERR(j) = abs( a_j - b_j)/2
!>

WERR

!>          WERR est un tableau DOUBLE PRECISION, dimension (N)
!>          La borne d'erreur sur l'approximation de la valeur propre
!>          correspondante dans W.
!>

WL

!>          WL est DOUBLE PRECISION
!>

WU

!>          WU est DOUBLE PRECISION
!>          L'intervalle (WL, WU] contient toutes les valeurs propres
!>          désirées.
!>          Si RANGE='V', alors WL=VL et WU=VU.
!>          Si RANGE='A', alors WL et WU sont les bornes globales de
!>                        Gerschgorin sur le spectre.
!>          Si RANGE='I', alors WL et WU sont calculés par DLAEBZ à partir de
!>                        l'indice range spécifié.
!>

IBLOCK

!>          IBLOCK est un tableau INTEGER, de dimension (N)
!>          À chaque ligne/colonne j où E(j) est nul ou petit, la
!>          matrice T est considérée comme scindée en une matrice
!>          diagonale par blocs. À la sortie, si INFO = 0, IBLOCK(i)
!>          indique à quel bloc (de 1 au nombre de blocs) l' propre
!>          W(i) appartient. (DLARRD peut utiliser les N-M éléments
!>          restants comme espace de travail.)
!>

INDEXW

!>          INDEXW est un tableau INTEGER, de dimension (N)
!>          Les indices des propres au sein de chaque bloc (sous-matrice) ;
!>          par exemple, INDEXW(i)= j et IBLOCK(i)=k impliquent que le
!>          i-ème propre W(i) est le j-ème propre du bloc k.
!>

WORK

!>          WORK est un tableau DOUBLE PRECISION, de dimension (4*N)
!>

IWORK

!>          IWORK est un tableau INTEGER, de dimension (3*N)
!>

INFO

!>          INFO est un entier
!>          = 0 :  sortie réussie
!>          < 0 :  si INFO = -i, le i-ème argument avait une valeur
!>                 illégale
!>          > 0 :  certains ou tous les propres n'ont pas convergé ou
!>                 n'ont pas été calculés :
!>                 =1 ou 3 : La bissection n'a pas convergé pour certains
!>                           propres ; ces propres sont signalés par un
!>                           numéro de bloc négatif. L'effet est que les
!>                           propres peuvent ne pas être aussi précis que
!>                           les tolérances absolue et relative. Cela est
!>                           généralement causé par une arithmétique
!>                           inattendument imprécise.
!>                 =2 ou 3 : uniquement RANGE='I' : Tous les propres
!>                           IL:IU n'ont pas été trouvés.
!>                           Effet : M < IU+1-IL
!>                           Cause : arithmétique non monotone, causant la
!>                                   séquence de Sturm non monotone.
!>                           Remède : recalculer en utilisant RANGE='A', et
!>                                   extraire les propres IL:IU. Dans
!>                                   certains cas, augmenter le PARAMÈTRE
!>                                   peut résoudre le problème.
!>                 = 4 :    RANGE='I', et l'intervalle de Gershgorin
!>                          initialement utilisé était trop petit. Aucun
!>                          propre n'a été calculé.
!>                          Cause probable : votre machine a une
!>                                          arithmétique flottante imprécise.
!>                          Remède : Augmenter le PARAMÈTRE,
!>                                   recompiler, et réessayer.
!>

Paramètres internes :

!>  FUDGE   DOUBLE PRECISION, défaut = 2
!>          Un  pour élargir les intervalles de Gershgorin. Idéalement,
!>          une valeur de 1 devrait fonctionner, mais sur les machines
!>          avec une arithmétique imprécise, cela doit être plus grand.
!>          La valeur par défaut des versions publiées devrait être assez
!>          grande pour gérer la pire machine existante. Notez que cela
!>          n'a aucun effet sur la précision de la solution.
!>
