dladdr(3) Manuel des fonctions de bibliothèque dladdr(3)

NOM

dladdr, dladdr1 - traduire une adresse en informations symboliques

BIBLIOTHÈQUE

Bibliothèque de liaison dynamique (libdl,-ldl)

SYNOPSIS

#define _GNU_SOURCE
#include <dlfcn.h>
int dladdr(const void *addr, Dl_info *info);
int dladdr1(const void *addr, Dl_info *info, void **extra_info,
            int flags);

DESCRIPTION

La fonction dladdr() détermine si l'adresse spécifiée dans addr se trouve dans l'un des objets partagés chargés par l'application appelante. Si c'est le cas, dladdr() renvoie des informations sur l'objet partagé et le symbole qui recouvrent addr. Ces informations sont renvoyées dans une structure Dl_info :


typedef struct {
    const char *dli_fname;  /* Chemin de l'objet partagé qui
                               contient l'adresse */
    void       *dli_fbase;  /* Adresse de base à laquelle l'objet
                               partagé est chargé */
    const char *dli_sname;  /* Nom du symbole dont la définition
                               recouvre addr */
    void       *dli_saddr;  /* Adresse exacte du symbole nommé
                               dans dli_sname */
} Dl_info;

Si aucun symbole correspondant à addr n'a pu être trouvé, alors dli_sname et dli_saddr sont définis à NULL.

La fonction dladdr1() est semblable à dladdr(), mais renvoie des informations supplémentaires via l'argument extra_info. Les informations renvoyées dépendent de la valeur spécifiée dans flags, qui peut prendre l'une des valeurs suivantes :

RTLD_DL_LINKMAP
Obtenir un pointeur vers la table de liaison (link map) du fichier correspondant. L'argument extra_info pointe vers un pointeur vers une structure link_map (c'est-à-dire struct link_map **), définie dans <link.h> comme suit :

struct link_map {
    ElfW(Addr) l_addr;  /* Différence entre l'adresse dans le
                           fichier ELF et l'adresse en mémoire */
    char      *l_name;  /* Chemin absolu où l'objet
                           a été trouvé */
    ElfW(Dyn) *l_ld;    /* Section dynamique de l'objet
                           partagé */
    struct link_map *l_next, *l_prev;
                        /* Chaîne des objets chargés */
    /* Plus des champs supplémentaires privés à
       l'implémentation */
};

RTLD_DL_SYMENT
Obtenir un pointeur vers l'entrée de table des symboles ELF du symbole correspondant. L'argument extra_info est un pointeur vers un pointeur de symbole : const ElfW(Sym) **. La ElfW() macro définition transforme son argument en le nom d'un type de données ELF adapté à l'architecture matérielle. Par exemple, sur une plateforme 64 bits, ElfW(Sym) donne le nom du type de données Elf64_Sym, qui est défini dans <elf.h> comme suit :

typedef struct  {
    Elf64_Word    st_name;     /* Nom du symbole */
    unsigned char st_info;     /* Type et liaison du symbole */
    unsigned char st_other;    /* Visibilité du symbole */
    Elf64_Section st_shndx;    /* Index de section */
    Elf64_Addr    st_value;    /* Valeur du symbole */
    Elf64_Xword   st_size;     /* Taille du symbole */
} Elf64_Sym;

Le champ st_name est un index dans la table de chaînes.
Le champ st_info encode le type et la liaison du symbole. Le type peut être extrait à l'aide de la macro ELF64_ST_TYPE(st_info) (ou ELF32_ST_TYPE() sur les plateformes 32 bits), qui donne l'une des valeurs suivantes :
Valeur Description
STT_NOTYPE Le type du symbole n'est pas spécifié
STT_OBJECT Le symbole est un objet de données
STT_FUNC Le symbole est un objet de code
STT_SECTION Symbole associé à une section
STT_FILE Le nom du symbole est un nom de fichier
STT_COMMON Le symbole est un objet de données commun
STT_TLS Le symbole est un objet de données local au thread
STT_GNU_IFUNC Le symbole est un objet de code indirect

La liaison du symbole peut être extraite du champ st_info à l'aide de la macro ELF64_ST_BIND(st_info) (ou ELF32_ST_BIND() sur les plateformes 32 bits), qui donne l'une des valeurs suivantes :
Valeur Description
STB_LOCAL Symbole local
STB_GLOBAL Symbole global
STB_WEAK Symbole faible
STB_GNU_UNIQUE Symbole unique

Le champ st_other contient la visibilité du symbole, qui peut être extraite à l'aide de la macro ELF64_ST_VISIBILITY(st_info) (ou ELF32_ST_VISIBILITY() sur les plateformes 32 bits), qui donne l'une des valeurs suivantes :
Valeur Description
STV_DEFAULT Règles de visibilité par défaut des symboles
STV_INTERNAL Classe cachée spécifique au processeur
STV_HIDDEN Symbole indisponible dans les autres modules
STV_PROTECTED Non préemptible, non exporté

VALEUR RENVOYÉE

En cas de succès, ces fonctions renvoient une valeur non nulle. Si l'adresse spécifiée dans addr a pu être associée à un objet partagé, mais pas à un symbole dans l'objet partagé, alors les champs info->dli_sname et info->dli_saddr sont définis à NULL.

Si l'adresse spécifiée dans addr n'a pas pu être associée à un objet partagé, alors ces fonctions renvoient 0. Dans ce cas, un message d'erreur n'est pas disponible via dlerror(3).

ANOMALIES

Parfois, les pointeurs de fonction que vous passez à dladdr() peuvent vous surprendre. Sur certaines architectures (notamment i386 et x86-64), dli_fname et dli_fbase peuvent finir par pointer vers l'objet à partir duquel vous avez appelé dladdr(), même si la fonction utilisée comme argument devrait provenir d'une bibliothèque liée dynamiquement.

Le problème est que le pointeur de fonction sera toujours résolu au moment de la compilation, mais pointera simplement vers la section plt (Procedure Linkage Table) de l'objet d'origine (qui distribue l'appel après avoir demandé au lien dynamique de résoudre le symbole). Pour contourner cela, vous pouvez essayer de compiler le code pour qu'il soit indépendant de la position : alors, le compilateur ne peut plus préparer le pointeur à la compilation et gcc(1) générera du code qui charge simplement l'adresse finale du symbole depuis la got (Global Offset Table) au moment de l'exécution avant de la passer à dladdr().
