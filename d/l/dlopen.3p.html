DESCRIPTIO

N

La fonction dlopen() doit rendre les symboles (identifiants de fonctions et identifiants d'objets de données) du fichier objet exécutable spécifié par file disponibles au programme

appelant.

La classe de fichiers objets exécutables éligibles pour cette opération et la manière dont ils sont construits sont définies par l'implémentation, bien que généralement de tels fichiers soient des bibliothèques partagées ou des

programmes.

Les implémentations peuvent permettre la construction de dépendances intégrées dans les fichiers objets exécutables. Dans de tels cas, une opération dlopen() doit charger ces dépendances en plus du fichier objet exécutable spécifié par file. Les implémentations peuvent également imposer des contraintes spécifiques sur la construction des programmes pouvant utiliser dlopen() et ses services

associés.

Un dlopen() réussi doit retourner un descripteur de table de symboles que l'appelant peut utiliser dans les appels suivants à dlsym() et dlclose

().

La valeur de ce descripteur de table de symboles ne doit pas être interprétée de quelque manière que ce soit par

l'appelant.

L'argument file est utilisé pour construire un chemin d'accès vers le fichier objet exécutable. Si file contient un caractère <slash>, l'argument file est utilisé comme chemin d'accès pour le fichier. Sinon, file est utilisé d'une manière définie par l'implémentation pour produire un chemin

d'accès.

Si file est un pointeur nul, dlopen() doit retourner un descripteur de table de symboles global pour l'image du processus actuellement en cours d'exécution. Ce descripteur de table de symboles doit fournir l'accès aux symboles d'un ensemble ordonné de fichiers objets exécutables composé du fichier d'image du programme original, de tout fichier objet exécutable chargé au démarrage du programme comme spécifié par ce fichier de processus (par exemple, des bibliothèques partagées), et de l'ensemble des fichiers objets exécutables chargés à l'aide d'opérations dlopen() avec l'indicateur RTLD_GLOBAL. Comme ce dernier ensemble de fichiers objets exécutables peut changer pendant l'exécution, l'ensemble des symboles rendus disponibles par ce descripteur de table de symboles peut également changer

dynamiquement.

Une seule copie d'un fichier objet exécutable doit être apportée dans l'espace d'adressage, même si dlopen() est invoqué plusieurs fois en référence au fichier objet exécutable, et même si différents chemins d'accès sont utilisés pour référencer le fichier objet

exécutable.

Le paramètre mode décrit comment dlopen() doit opérer sur file en ce qui concerne le traitement des relocalisations et la portée de visibilité des symboles fournis dans file. Lorsqu'un fichier objet exécutable est apporté dans l'espace d'adressage d'un processus, il peut contenir des références à des symboles dont les adresses ne sont pas connues jusqu'à ce que le fichier objet exécutable soit

chargé.

Ces références doivent être relocalisées avant que les symboles puissent être accessibles. Le paramètre mode détermine quand ces relocalisations ont lieu et peut avoir les valeurs suivantes

:
RTLD_LA
ZY
Les relocalisations doivent être effectuées à un moment défini par l'implémentation, allant du moment de l'appel dlopen() jusqu'à la première référence à un symbole donné. Spécifier RTLD_LAZY devrait améliorer les performances sur les implémentations prenant en charge la liaison dynamique de symboles, car un processus pourrait ne pas référencer tous les symboles d'un fichier objet exécutable. De plus, pour les systèmes prenant en charge la résolution dynamique de symboles pour l'exécution normale des processus, ce comportement imite le traitement normal de l'exécution des
processus.
RTLD_N
OW
Toutes les relocalisations nécessaires doivent être effectuées lorsque le fichier objet exécutable est chargé pour la première fois. Cela peut gaspiller un peu de traitement si des relocalisations sont effectuées pour des symboles qui ne sont jamais référencés. Ce comportement peut être utile pour les applications qui ont besoin de savoir que tous les symboles référencés pendant l'exécution seront disponibles avant que dlopen() n
e reto
urne.

Tout fichier objet exécutable chargé par dlopen() nécessitant des relocalisations contre des symboles globaux peut référencer les symboles du fichier d'image du processus original, de tout fichier objet exécutable chargé au démarrage du programme, de l'image du processus initial elle-même, de tout autre fichier objet exécutable inclus dans la même invocation dlopen(), et de tout fichier objet exécutable chargé lors de n'importe quelle invocation dlopen() et qui spécifiait l'indicateur RTLD_GLOBAL. Pour déterminer la portée de visibilité des symboles chargés avec une invocation dlopen(), le paramètre mode doit être un OU inclusif au niveau des bits avec l'une des valeurs suivantes

:
RTLD_GLOB
AL
Les symboles du fichier objet exécutable doivent être rendus disponibles pour le traitement de relocalisation de tout autre fichier objet exécutable. De plus, la recherche de symboles utilisant dlopen(NULL,mode) et un dlsym() associé permet de rechercher les fichiers objets exécutables chargés avec ce
mode.
RTLD_LOC
AL
Les symboles du fichier objet exécutable ne doivent
pas être rendus disponibles pour le traitement de re
localisation de tout autre fichier objet exécutable.

Si ni RTLD_GLOBAL ni RTLD_LOCAL n'est spécifié, le comportement par défaut est

indéfini.

Si un fichier objet exécutable est spécifié dans plusieurs invocations dlopen(), mode est interprété à chaque

invocation.

Si RTLD_NOW a été spécifié, toutes les relocalisations doivent avoir été complétées, rendant toute opération RTLD_NOW supplémentaire redondante et toute opération RTLD_LAZY supplémentaire non

pertinente.

Si RTLD_GLOBAL a été spécifié, le fichier objet exécutable doit maintenir le statut RTLD_GLOBAL quelles que soient les spécifications antérieures ou futures de RTLD_LOCAL, tant que le fichier objet exécutable reste dans l'espace d'adressage (voir dlclose(

)).

Les symboles introduits dans l'image du processus par des appels à dlopen() peuvent être utilisés dans des activités de relocalisation. Les symboles ainsi introduits peuvent dupliquer des symboles déjà définis par le programme ou par des opérations dlopen() précédentes. Pour résoudre les ambiguïtés qu'une telle situation pourrait présenter, la résolution d'une référence de symbole vers une définition de symbole est basée sur un ordre de résolution de symboles. Deux tels ordres de résolution sont définis : l'ordre de chargement et l'ordre de dépendance. L'ordre de chargement établit un ordre parmi les définitions de symboles, de sorte que la première définition chargée (y compris les définitions du fichier d'image du processus et de tout fichier objet exécutable dépendant chargé avec lui) a la priorité sur les fichiers objets exécutables ajoutés plus tard (par dlopen()). L'ordre de chargement est utilisé dans le traitement des relocalisations. L'ordre de dépendance utilise un ordre en largeur commençant par un fichier objet exécutable donné, puis toutes ses dépendances, puis tous les dépendants de celles-ci, en itérant jusqu'à ce que toutes les dépendances soient satisfaites. À l'exception du descripteur de table de symboles global obtenu via une opération dlopen() avec un pointeur nul comme argument file, l'ordre de dépendance est utilisé par la fonction dlsym(). L'ordre de chargement est utilisé dans les opérations dlsym() sur le descripteur de table de symboles

global.

Lorsqu'un fichier objet exécutable est rendu accessible pour la première fois via dlopen(), lui et ses fichiers objets exécutables dépendants sont ajoutés en ordre de dépendance. Une fois que tous les fichiers objets exécutables sont ajoutés, les relocalisations sont effectuées en utilisant l'ordre de chargement. Notez que si un fichier objet exécutable ou ses dépendances avaient été chargés précédemment, les ordres de chargement et de dépendance peuvent produire des résolutions

différentes.

Les symboles introduits par les opérations dlopen() et disponibles via dlsym() sont au minimum ceux qui sont exportés comme identifiants de portée globale par le fichier objet exécutable. Généralement, de tels identifiants doivent être ceux qui étaient spécifiés dans (par exemple) le code source C comme ayant une liaison extern. La manière précise dont une implémentation construit l'ensemble des symboles exportés pour un fichier objet exécutable est définie par l'implémentatio

n
.

VALEUR

RETOURNÉE

À l'issue de son exécution, dlopen() doit retourner un descripteur de table de symboles. Si file ne peut pas être trouvé, ne peut pas être ouvert en lecture, n'est pas dans un format de fichier objet exécutable approprié pour lesing by dlopen(), ou si une erreur se produit lors du chargement du fichier ou du relocalisation de ses références symboliques, dlopen() doit renvoyer un pointeur nul. Des informations de diagnostic plus détaillées doivent être disponibles via dlerr

or(
).
