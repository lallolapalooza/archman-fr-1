DESCRIPTIO

N

La fonction dlsym() prend un « handle » d'un objet partagé chargé dynamiquement renvoyé par dlopen(3) ainsi qu'un nom de symbole terminé par un caractère nul, et renvoie l'adresse à laquelle ce symbole est chargé en mémoire. Si le symbole est introuvable, dans l'objet spécifié ou dans l'un des objets partagés qui ont été chargés automatiquement par dlopen(3) lorsque cet objet a été chargé, dlsym() renvoie NULL. (La recherche effectuée par dlsym() est en largeur à travers l'arbre de dépendances de ces objets partagés.

)

Dans des cas inhabituels (voir REMARQUES), la valeur du symbole peut en réalité être NULL. Par conséquent, un retour NULL de dlsym() n'indique pas nécessairement une erreur. La manière correcte de distinguer une erreur d'un symbole dont la valeur est NULL est d'appeler dlerror(3) pour effacer d'éventuelles conditions d'erreur anciennes, puis d'appeler dlsym(), puis d'appeler dlerror(3) à nouveau, en enregistrant sa valeur de retour dans une variable, et de vérifier si cette valeur enregistrée n'est pas

NULL.

REMARQUE

S

Il existe plusieurs scénarios dans lesquels l'adresse d'un symbole global est NULL. Par exemple, un symbole peut être placé à l'adresse zéro par l'éditeur de liens, via un script d'édition de liens ou avec l'option de ligne de commande --defsym. Les symboles faibles indéfinis ont également une valeur NULL. Enfin, la valeur du symbole peut être le résultat d'une fonction résolveuse de fonction indirecte GNU (IFUNC) qui renvoie NULL comme valeur résolue. Dans ce dernier cas, dlsym() renvoie également NULL sans erreur. Cependant, dans les deux premiers cas, le comportement de l'éditeur de liens dynamique GNU est incohérent : le traitement de la relocation réussit et on peut observer que le symbole a une valeur NULL, mais dlsym() échoue et dlerror() indique une erreur de

recherche.
