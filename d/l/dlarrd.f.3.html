DLARRD calcule les valeurs propres d'une matrice tridiagonale symétrique avec une précision appropriée.

Objectif :

!>
!> DLARRD calcule les valeurs propres d'une matrice tridiagonale symétrique
!> T avec une précision appropriée. Il s'agit d'un code auxiliaire à appeler
!> depuis DSTEMR.
!> L'utilisateur peut demander toutes les valeurs propres, toutes les valeurs propres
!> dans l'intervalle semi-ouvert (VL, VU], ou les valeurs propres de l'indice IL à IU.
!>
!> Pour éviter le débordement, la matrice doit être mise à l'échelle de sorte que son
!> plus grand élément ne dépasse pas overflow**(1/2) * underflow**(1/4) en valeur absolue, et pour une précision maximale,
!> elle ne doit pas être beaucoup plus petite que cela.
!>
!> Voir W. Kahan, Rapport CS41, Département des sciences informatiques, Université de Stanford,
!> 21 juillet 1966.
!>

Paramètres

RANGE 
!>          RANGE est CHARACTER*1
!>          = 'A': ()   toutes les valeurs propres seront trouvées.
!>          = 'V': () toutes les valeurs propres dans l'intervalle semi-ouvert
!>                           (VL, VU] seront trouvées.
!>          = 'I': () les valeurs propres de l'indice IL à IU (de la
!>                           matrice entière) seront trouvées.
!>

ORDER

!>          ORDER est CHARACTER*1
!>          = 'B': () les valeurs propres seront regroupées par
!>                              bloc découpé (voir IBLOCK, ISPLIT) et
!>                              ordonnées de la plus petite à la plus grande dans
!>                              le bloc.
!>          = 'E': ()
!>                              les valeurs propres de la matrice entière
!>                              seront ordonnées de la plus petite à la plus
!>                              grande.
!>

N

!>          N est INTEGER
!>          L'ordre de la matrice tridiagonale T. N >= 0.
!>

VL

!>          VL est DOUBLE PRECISION
!>          Si RANGE='V', la borne inférieure de l'intervalle à
!>          rechercher pour les valeurs propres. Les valeurs propres inférieures ou égales
!>          à VL, ou supérieures à VU, ne seront pas retournées. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

VU

!>          VU est DOUBLE PRECISION
!>          Si RANGE='V', la borne supérieure de l'intervalle à
!>          rechercher pour les valeurs propres. Les valeurs propres inférieures ou égales
!>          à VL, ou supérieures à VU, ne seront pas retournées. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

IL

!>          IL est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus petite valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

IU

!>          IU est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus grande valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

GERS

!>          GERS est tableau DOUBLE PRECISION, dimension (2*N)
!>          Les N intervalles de Gerschgorin (le i-ème intervalle de Gerschgorin
!>          est (GERS(2*i-1), GERS(2*i)).
!>

RELTOL

!>          RELTOL est DOUBLE PRECISION
!>          La largeur relative minimale d'un intervalle. Lorsqu'un intervalle
!>          est plus étroit que RELTOL fois le plus grand (en
!>          valeur absolue) des points de terminaison, il est considéré comme
!>          suffisamment petit, c'est-à-dire convergé. Note : cela devrait
!>          toujours être au moins radix*epsilon machine.
!>

D

!>          D est tableau DOUBLE PRECISION, dimension (N)
!>          Les N éléments diagonaux de la matrice tridiagonale T.
!>

E

!>          E est tableau DOUBLE PRECISION, dimension (N-1)
!>          Les N-1 éléments hors diagonale de la matrice tridiagonale T.
!>

E2

!>          E2 est tableau DOUBLE PRECISION, dimension (N-1)
!>          Les N-1 éléments hors diagonale au carré de la matrice tridiagonale T.
!>

PIVMIN

!>          PIVMIN est DOUBLE PRECISION
!>          Le pivot minimal autorisé dans la séquence de Sturm pour T.
!>

NSPLIT

!>          NSPLIT est INTEGER
!>          Le nombre de blocs diagonaux dans la matrice T.
!>          1 <= NSPLIT <= N.
!>

ISPLIT

!>          ISPLIT est tableau INTEGER, dimension (N)
!>          Les points de découpage, où T se décompose en sous-matrices.
!>          La première sous-matrice comprend les lignes/colonnes 1 à ISPLIT(1),
!>          la seconde les lignes/colonnes ISPLIT(1)+1 à ISPLIT(2),
!>          etc., et la NSPLIT-ième comprend les lignes/colonnes
!>          ISPLIT(NSPLIT-1)+1 à ISPLIT(NSPLIT)=N.
!>          (Seuls les NSPLIT premiers éléments seront réellement utilisés, mais
!>          comme l'utilisateur ne peut pas savoir a priori quelle valeur NSPLIT aura,
!>          N mots doivent être réservés pour ISPLIT.)
!>

M

!>          M est INTEGER
!>          Le nombre réel de valeurs propres trouvées. 0 <= M <= N.
!>          (Voir aussi la description de INFO=2,3.)
!>

W

!>          W est tableau DOUBLE PRECISION, dimension (N)
!>          En sortie, les M premiers éléments de W contiendront les
!>          approximations des valeurs propres. DLARRD calcule un intervalle
!>          I_j = (a_j, b_j] qui inclut la valeur propre j. L'approximation de la valeur propre
!>          est donnée par le milieu de l'intervalle
!>          W(j)= ( a_j + b_j)/2. L'erreur correspondante est bornée par
!>          WERR(j) = abs( a_j - b_j)/2
!>

WERR

!>          WERR est tableau DOUBLE PRECISION, dimension (N)
!>          La borne d'erreur sur l'approximation correspondante de la valeur propre
!>          dans W.
!>

WL

!>          WL est DOUBLE PRECISION
!>

WU

!>          WU est DOUBLE PRECISION
!>          L'intervalle (WL, WU] contient toutes les valeurs propres recherchées.
!>          Si RANGE='V', alors WL=VL et WU=VU.
!>          Si RANGE='A', alors WL et WU sont les bornes de Gerschgorin globales
!>                        sur le spectre.
!>          Si RANGE='I', alors WL et WU sont calculés par DLAEBZ à partir de l'indice

NAME

dlarrd — translates eigenvalues and eigenvectors from the local coordinate system to the global coordinate system.

SYNOPSIS

SUBROUTINE DLARRD(
   N,              )
INTEGER N
DOUBLE PRECISION W( * ), VL, VU, ABSTOL
INTEGER IBLOCK( * ), INDEXW( * ), M, ISPLIT, INFO
DOUBLE PRECISION WORK( * )
INTEGER IWORK( * )

Arguments

N

INTEGER. (Input)

The number of rows and columns of the matrix T, and the number of eigenvalues and eigenvectors.

W

DOUBLE PRECISION array, dimension (N)

On entry, the real parts of the eigenvalues of the partitioned tridiagonal matrix T.

On exit, the computed eigenvalues, sorted in increasing order. If INFO = 0, W(I) is the I-th eigenvalue in the interval [VL, VU].

VL

DOUBLE PRECISION. (Input)

The lower bound of the interval for the eigenvalues.

VU

DOUBLE PRECISION. (Input)

The upper bound of the interval for the eigenvalues.

ABSTOL

DOUBLE PRECISION. (Input)

The absolute tolerance for the eigenvalues. The algorithm computes eigenvalues with respect to the current approximation of the eigenvalues of the original matrix T. The tolerance ABSTOL is used to distinguish eigenvalues near each other.

M

INTEGER. (Output)

The number of eigenvalues found in the interval [VL, VU].

ISPLIT

INTEGER. (Input)

The number of splitting points, i.e., the number of blocks minus 1.

IBLOCK

INTEGER array, dimension (N).

On exit, if INFO = 0, IBLOCK(I) specifies to which block (from 1 to the number of blocks) the eigenvalue W(I) belongs. (DLARRD may use the remaining N-M elements as workspace.)

INDEXW

INTEGER array, dimension (N).

The indices of the eigenvalues within each block (submatrix); for example, INDEXW(I)= J and IBLOCK(I)=K imply that the I-th eigenvalue W(I) is the J-th eigenvalue in block K.

WORK

DOUBLE PRECISION array, dimension (4*N).

IWORK

INTEGER array, dimension (3*N).

INFO

INTEGER.

  • = 0: successful exit
  • < 0: if INFO = -I, the I-th argument had an illegal value
  • > 0: some or all of the eigenvalues failed to converge or were not computed:
    • =1 or 3: Bisection failed to converge for some eigenvalues; these eigenvalues are flagged by a negative block number. The effect is that the eigenvalues may not be as accurate as the absolute and relative tolerances. This is generally caused by unexpectedly inaccurate arithmetic.
    • =2 or 3: RANGE='I' only: Not all of the eigenvalues IL:IU were found. Effect: M < IU+1-IL Cause: non-monotonic arithmetic, causing the Sturm sequence to be non-monotonic. Cure: recalculate, using RANGE='A', and pick out eigenvalues IL:IU. In some cases, increasing the PARAMETER may make things work.
    • = 4: RANGE='I', and the Gershgorin interval initially used was too small. No eigenvalues were computed. Probable cause: your machine has sloppy floating-point arithmetic. Cure: Increase the PARAMETER , recompile, and try again.

Description

This subroutine is a utility routine for the parallel computation of eigenvalues of a symmetric tridiagonal matrix T. It is used in conjunction with the routine DLARRF to compute the eigenvalues of T in a given interval [VL, VU].

The matrix T is assumed to be split into blocks, where each block is an independent tridiagonal matrix. The routine computes the eigenvalues of T within the interval [VL, VU] by computing the eigenvalues of each block and then merging them.

The routine uses the bisection method to compute the eigenvalues of each block. The number of eigenvalues in each block is determined by the Sturm sequence property of the characteristic polynomial of the tridiagonal matrix.

The routine returns the computed eigenvalues in the array W, sorted in increasing order. The routine also returns the block assignment for each eigenvalue in the array IBLOCK, and the index of the eigenvalue within its block in the array INDEXW.

The routine returns an error code in the INFO argument to indicate whether the computation was successful.

The routine uses the following internal parameters:

FUDGE

DOUBLE PRECISION, default = 2

A parameter to widen the Gershgorin intervals. Ideally, a value of 1 should work, but on machines with sloppy arithmetic, this needs to be larger. The default for publicly released versions should be large enough to handle the worst machine around. Note that this has no effect on accuracy of the solution.
