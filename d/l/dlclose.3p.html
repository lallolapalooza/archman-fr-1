DESCRIPTIO

N

La fonction dlclose() doit informer le système que le descripteur de table de symboles spécifié par handle n'est plus nécessaire à

l'application.

Un auteur d'application peut utiliser dlclose() pour exprimer une intention de la part du processus, mais cette déclaration ne crée aucune exigence pour l'implémentation. Lorsque le descripteur de table de symboles est fermé, l'implémentation peut décharger les fichiers objets exécutables qui ont été chargés par dlopen() lorsque le descripteur de table de symboles a été ouvert, ainsi que ceux qui ont été chargés par dlsym() lors de l'utilisation du descripteur de table de symboles identifié par handle

.

Une fois qu'un descripteur de table de symboles a été fermé, une application doit supposer que tous les symboles (identifiants de fonctions et identifiants d'objets de données) rendus visibles à l'aide de handle ne sont plus disponibles pour le

processus.

Bien qu'une opération dlclose() ne soit pas tenue de retirer des fonctions ou des objets de données de l'espace d'adressage, une implémentation n'est pas non plus interdite de le faire. La seule restriction sur un tel retrait est qu'aucune fonction ni aucun objet de données ne doit être retiré auquel des références ont été relocalisées, tant que toutes ces références n'ont pas été retirées. Par exemple, un fichier objet exécutable qui avait été chargé avec une opération dlopen() spécifiant l'indicateur RTLD_GLOBAL pourrait fournir une cible pour les relocalisations dynamiques effectuées lors du traitement d'autres objets relocalisables — dans de tels environnemen

ts, une application peut supposer qu'une relocalisation, une fois effectuée, ne sera ni annulée n
i refaite, sauf si le fichier objet exécutable contenant l'objet relocalisé a lui-même été retiré.

VALEUR DE

RETOUR

Si le descripteur de table de symboles référencé a été fermé avec succès, dlclose() doit retourner 0. Si handle ne fait pas référence à un descripteur de table de symboles ouvert ou si le descripteur de table de symboles n'a pas pu être fermé, dlclose() doit retourner une valeur non nulle. Des informations de diagnostic plus détaillées doivent être disponibles via dlerr

or(
).

UTILISATION PAR LES

APPLICATIONS

Une application conforme doit utiliser un descripteur de table de symboles retourné par une invocation de dlopen() uniquement dans un certain domaine délimité par une opération dlopen() et l'opération dlclose() correspondante. Les implémentations sont libres d'utiliser un comptage de références ou d'autres techniques telles que des appels multiples à dlopen() faisant référence au même fichier objet exécutable puissent retourner un pointeur vers le même objet de données que le descripteur de table de

symboles.

Les implémentations sont également libres de réutiliser un descripteur. Pour ces raisons, la valeur d'un descripteur doit être traitée comme un type de données opaque par l'application, utilisée uniquement dans les appels à dlsym() et dlclo

se(
