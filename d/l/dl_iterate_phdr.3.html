dl_iterate_phdr(3) Manuel des fonctions de la bibliothèque dl_iterate_phdr(3)

NOM

dl_iterate_phdr - parcourir la liste des objets partagés

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#define _GNU_SOURCE         /* Voir feature_test_macros(7) */
#include <link.h>
int dl_iterate_phdr(
         typeof(int (struct dl_phdr_info *info, size_t size, void *data))
             *callback,
         void *data);

DESCRIPTION

La fonction dl_iterate_phdr() permet à une application de s'interroger à l'exécution pour découvrir quels objets partagés elle a chargés, et l'ordre dans lequel ils ont été chargés.

La fonction dl_iterate_phdr() parcourt la liste des objets partagés d'une application et appelle la fonction callback une fois pour chaque objet, jusqu'à ce que tous les objets partagés aient été traités ou que callback renvoie une valeur non nulle.

Chaque appel à callback reçoit trois arguments : info, qui est un pointeur vers une structure contenant des informations sur l'objet partagé ; size, qui est la taille de la structure pointée par info; et data, qui est une copie de la valeur passée par le programme appelant en tant que deuxième argument (également nommé data) dans l'appel à dl_iterate_phdr().

L'argument info est une structure du type suivant :


struct dl_phdr_info {
    ElfW(Addr)        dlpi_addr;  /* Adresse de base de l'objet */
    const char       *dlpi_name;  /* Nom de l'objet
                                     (terminé par un octet nul) */
    const ElfW(Phdr) *dlpi_phdr;  /* Pointeur vers le tableau des
                                     en-têtes de programme ELF
                                     de cet objet */
    ElfW(Half)        dlpi_phnum; /* Nombre d'éléments dans dlpi_phdr */
    /* Les champs suivants ont été ajoutés dans glibc 2.4, après la
       première version de cette structure. Vérifiez l'argument size
       passé au rappel dl_iterate_phdr pour déterminer
       si chaque membre ultérieur est disponible. */
    unsigned long long dlpi_adds;
                    /* Incrémenté lorsqu'un nouvel objet a pu
                       être ajouté */
    unsigned long long dlpi_subs;
                    /* Incrémenté lorsqu'un objet a pu
                       être supprimé */
    size_t dlpi_tls_modid;
                    /* S'il existe un segment PT_TLS, son
                       identifiant de module tel qu'utilisé dans les
                       relocalisations TLS, sinon zéro */
    void  *dlpi_tls_data;
                    /* L'adresse de l'instance de ce module du
                       segment PT_TLS pour le thread appelant, s'il en
                       a un et s'il a été alloué dans le thread
                       appelant, sinon un pointeur nul */
};

(La définition de la macro ElfW() transforme son argument en le nom d'un type de données ELF adapté à l'architecture matérielle. Par exemple, sur une plateforme 32 bits, ElfW(Addr) donne le nom du type de données Elf32_Addr. Des informations supplémentaires sur ces types se trouvent dans les fichiers d'en-tête <elf.h> et <link.h> .)

Le champ dlpi_addr indique l'adresse de base de l'objet partagé (c'est-à-dire la différence entre l'adresse de la mémoire virtuelle de l'objet partagé et le décalage de cet objet dans le fichier à partir duquel il a été chargé). Le champ dlpi_name est une chaîne terminée par un octet nul donnant le chemin d'accès à partir duquel l'objet partagé a été chargé.

Pour comprendre la signification des champs dlpi_phdr et dlpi_phnum , il faut savoir qu'un objet partagé ELF se compose d'un certain nombre de segments, chacun ayant un en-tête de programme correspondant décrivant le segment. Le champ dlpi_phdr est un pointeur vers un tableau des en-têtes de programme de cet objet partagé. Le champ dlpi_phnum indique la taille de ce tableau.

Ces en-têtes de programme sont des structures de la forme suivante :


typedef struct {
    Elf32_Word  p_type;    /* Type de segment */
    Elf32_Off   p_offset;  /* Décalage du segment dans le fichier */
    Elf32_Addr  p_vaddr;   /* Adresse virtuelle du segment */
    Elf32_Addr  p_paddr;   /* Adresse physique du segment */
    Elf32_Word  p_filesz;  /* Taille du segment dans le fichier */
    Elf32_Word  p_memsz;   /* Taille du segment en mémoire */
    Elf32_Word  p_flags;   /* Drapeaux du segment */
    Elf32_Word  p_align;   /* Alignement du segment */
} Elf32_Phdr;

Notez que nous pouvons calculer l'emplacement d'un en-tête de programme particulier, x, en mémoire virtuelle à l'aide de la formule :


addr == info->dlpi_addr + info->dlpi_phdr[x].p_vaddr;

Les valeurs possibles pour p_type incluent les suivantes (voir <elf.h> pour plus de détails) :


#define PT_LOAD         1    /* Segment de programme chargeable */
#define PT_DYNAMIC      2    /* Informations de liaison dynamique */
#define PT_INTERP       3    /* Interpréteur de programme */
#define PT_NOTE         4    /* Informations auxiliaires */
#define PT_SHLIB        5    /* Réservé */
#define PT_PHDR         6    /* Entrée pour la table d'en-têtes elle-même */
#define PT_TLS          7    /* Segment de stockage local aux threads */
#define PT_GNU_EH_FRAME 0x6474e550 /* Segment .eh_frame_hdr de GCC */
#define PT_GNU_STACK  0x6474e551 /* Indique l'exécutabilité de la pile */
#define PT_GNU_RELRO  0x6474e552 /* Lecture seule après relocalisation */

VALEUR RENVOYÉE

La fonction dl_iterate_phdr() renvoie la valeur renvoyée par le dernier appel à callback.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
dl_iterate_phdr () Sécurité des threads MT-Safe

VERSIONS

Divers autres systèmes fournissent une version de cette fonction, bien que les détails de la structure dl_phdr_info renvoyée diffèrent. Sur les BSD et Solaris, la structure inclut les champs dlpi_addr, dlpi_name, dlpi_phdret dlpi_phnum en plus d'autres champs spécifiques à l'implémentation.

Les futures versions de la bibliothèque C peuvent ajouter d'autres champs à la structure dl_phdr_info ; dans ce cas, l'argument size fournit un mécanisme permettant à la fonction de rappel de découvrir si elle s'exécute sur un système comportant des champs supplémentaires.

NORMES

Aucune.

HISTORIQUE

glibc 2.2.4.

NOTES

Le premier objet visité par callback est le programme principal. Pour le programme principal, le champ dlpi_name sera une chaîne vide.

Source du programme


#define _GNU_SOURCE
#include <link.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
static int
callback(struct dl_phdr_info *info, size_t size, void *data)
{
    char *type;
    int p_type;
    printf("Nom : \"%s\" (%d segments)\n", info->dlpi_name,
           info->dlpi_phnum);
    for (size_t j = 0; j < info->dlpi_phnum; j++) {
        p_type = info->dlpi_phdr[j].p_type;
        type = (p_type == PT_LOAD) ? "PT_LOAD" :
               (p_type == PT_DYNAMIC) ? "PT_DYNAMIC" :
               (p_type == PT_INTERP) ? "PT_INTERP" :
               (p_type == PT_NOTE) ? "PT_NOTE" :
               (p_type == PT_INTERP) ? "PT_INTERP" :
               (p_type == PT_PHDR) ? "PT_PHDR" :
               (p_type == PT_TLS) ? "PT_TLS" :
               (p_type == PT_GNU_EH_FRAME) ? "PT_GNU_EH_FRAME" :
               (p_type == PT_GNU_STACK) ? "PT_GNU_STACK" :
               (p_type == PT_GNU_RELRO) ? "PT_GNU_RELRO" : NULL;
        printf("    %2zu: [%14p; memsz:%7jx] flags: %#jx; ", j,
               (void *) (info->dlpi_addr + info->dlpi_phdr[j].p_vaddr),
               (uintmax_t) info->dlpi_phdr[j].p_memsz,
               (uintmax_t) info->dlpi_phdr[j].p_flags);
        if (type != NULL)
            printf("%s\n", type);
        else
            printf("[autre (%#x)]\n", p_type);
    }
    return 0;
}
int
main(void)
{
    dl_iterate_phdr(callback, NULL);
    exit(EXIT_SUCCESS);
}
