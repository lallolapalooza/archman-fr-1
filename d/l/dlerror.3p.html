DLERROR(3P) Manuel du programmeur POSIX DLERROR(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

dlerror — obtenir des informations de diagnostic

SYNOPSIS

#include <dlfcn.h>
char *dlerror(void);

DESCRIPTION

La fonction dlerror() renvoie une chaîne de caractères terminée par un caractère nul (sans retour à la ligne final) qui décrit la dernière erreur survenue lors du traitement de la liaison dynamique. Si aucune erreur de liaison dynamique ne s'est produite depuis le dernier appel à dlerror(), dlerror() renvoie NULL. Ainsi, un second appel à dlerror() immédiatement après un appel précédent renverra NULL.

Il est défini par l'implémentation si la fonction dlerror() est thread-safe ou non. Une implémentation thread-safe ne doit renvoyer que les erreurs survenant sur le thread courant.

VALEUR DE RETOUR

En cas de succès, dlerror() renvoie une chaîne de caractères terminée par un caractère nul ; sinon, NULL est renvoyé.

L'application ne doit pas modifier la chaîne renvoyée. Le pointeur renvoyé peut être invalidé ou le contenu de la chaîne peut être écrasé par un appel ultérieur à dlerror() dans le même thread (si dlerror() est thread-safe) ou dans n'importe quel thread (si dlerror() n'est pas thread-safe). Le pointeur renvoyé peut également être invalidé si le thread appelant est terminé.

ERREURS

Aucune erreur n'est définie.

Les sections suivantes sont informatives.

EXEMPLES

L'exemple suivant affiche la dernière erreur de liaison dynamique :

...
#include <dlfcn.h>
char *errstr;
errstr = dlerror();
if (errstr != NULL)
    printf ("Une erreur de liaison dynamique s'est produite : (%s)\n", errstr);
...

UTILISATION APPLICATIVE

Selon l'environnement de l'application par rapport aux événements d'exécution asynchrones, tels que les signaux ou d'autres calculs asynchrones partageant l'espace d'adressage, les applications conformes devraient utiliser une section critique pour récupérer le pointeur d'erreur et le tampon.
