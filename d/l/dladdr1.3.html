DESCRIPTIO

N

La fonction dladdr() détermine si l'adresse spécifiée dans addr se trouve dans l'un des objets partagés chargés par l'application appelante. Si c'est le cas, dladdr() renvoie des informations sur l'objet partagé et le symbole qui recouvrent addr. Ces informations sont renvoyées dans une structure Dl_inf

o : 


typedef struct {
    const char *dli_fname;  /* Chemin de l'objet partagé qui
                               contient l'adresse */
    void       *dli_fbase;  /* Adresse de base à laquelle l'objet
                               partagé est chargé */
    const char *dli_sname;  /* Nom du symbole dont la définition
                               recouvre addr */
    void       *dli_saddr;  /* Adresse exacte du symbole nommé
                               dans dli_sname */
}
Dl_info;

Si aucun symbole correspondant à addr n'a pu être trouvé, alors dli_sname et dli_saddr sont mis à

NULL.

La fonction dladdr1() est similaire à dladdr(), mais renvoie des informations supplémentaires via l'argument extra_info. Les informations renvoyées dépendent de la valeur spécifiée dans flags, qui peut prendre l'une des valeurs suivantes

:

ANOMALI

ES

Parfois, les pointeurs de fonction que vous passez à dladdr() peuvent vous surprendre. Sur certaines architectures (notamment i386 et x86-64), dli_fname et dli_fbase peuvent finir par pointer vers l'objet à partir duquel vous avez appelé dladdr(), même si la fonction utilisée comme argument devrait provenir d'une bibliothèque liée

dynamiquement.

Le problème est que le pointeur de fonction sera toujours résolu à la compilation, mais pointera simplement vers la section plt (Procedure Linkage Table) de l'objet original (qui distribue l'appel après avoir demandé au lien dynamique de résoudre le symbole). Pour contourner cela, vous pouvez essayer de compiler le code pour qu'il soit indépendant de la position : alors, le compilateur ne pourra plus préparer le pointeur à la compilation et 1.en'>gcc(1) générera du code qui charge simplement l'adresse finale du symbole depuis la got (Global Offset Table) au moment de l'exécution avant de la passer à dlad

dr(
).
