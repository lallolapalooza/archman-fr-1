dlsym(3) Manuel des fonctions de bibliothèque dlsym(3)

NOM

dlsym, dlvsym - obtenir l'adresse d'un symbole dans un objet partagé ou un exécutable

BIBLIOTHÈQUE

Bibliothèque de liaison dynamique (libdl,-ldl)

SYNOPSIS

#include <dlfcn.h>
void *dlsym(void *restrict handle, const char *restrict symbol);
#define _GNU_SOURCE
#include <dlfcn.h>
void *dlvsym(void *restrict handle, const char *restrict symbol,
             const char *restrict version);

DESCRIPTION

La fonction dlsym() prend un « handle » d'un objet partagé chargé dynamiquement renvoyé par dlopen(3) ainsi qu'un nom de symbole terminé par un caractère nul, et renvoie l'adresse à laquelle ce symbole est chargé en mémoire. Si le symbole est introuvable, dans l'objet spécifié ou dans l'un des objets partagés qui ont été chargés automatiquement par dlopen(3) lorsque cet objet a été chargé, dlsym() renvoie NULL. (La recherche effectuée par dlsym() s'effectue en largeur à travers l'arbre de dépendances de ces objets partagés.)

Dans des cas inhabituels (voir REMARQUES), la valeur du symbole pourrait en fait être NULL. Par conséquent, un retour NULL de dlsym() n'indique pas nécessairement une erreur. La manière correcte de distinguer une erreur d'un symbole dont la valeur est NULL est d'appeler dlerror(3) pour effacer les anciennes conditions d'erreur, puis d'appeler dlsym(), puis d'appeler dlerror(3) à nouveau, en enregistrant sa valeur de retour dans une variable, et de vérifier si cette valeur enregistrée n'est pas NULL.

Il existe deux pseudo-handles spéciaux qui peuvent être spécifiés dans handle:

RTLD_DEFAULT
Trouver la première occurrence du symbole souhaité en utilisant l'ordre de recherche par défaut des objets partagés. La recherche inclura les symboles globaux dans l'exécutable et ses dépendances, ainsi que les symboles dans les objets partagés qui ont été chargés dynamiquement avec l'indicateur RTLD_GLOBAL .
RTLD_NEXT
Trouver la prochaine occurrence du symbole souhaité dans l'ordre de recherche après l'objet courant. Cela permet de fournir un wrapper autour d'une fonction dans un autre objet partagé, de sorte que, par exemple, la définition d'une fonction dans un objet partagé préchargé (voir LD_PRELOAD dans ld.so(8)) peut trouver et invoquer la fonction « réelle » fournie dans un autre objet partagé (ou à cet égard, la définition « suivante » de la fonction dans les cas où il y a plusieurs couches de préchargement).

La macro de test de fonctionnalité _GNU_SOURCE doit être définie afin d'obtenir les définitions de RTLD_DEFAULT et RTLD_NEXT à partir de <dlfcn.h>.

La fonction dlvsym() fait la même chose que dlsym() mais prend une chaîne de version comme argument supplémentaire.

VALEUR RENVOYÉE

En cas de succès, ces fonctions renvoient l'adresse associée au symbole. En cas d'échec, elles renvoient NULL ; l'erreur peut être diagnostiquée en utilisant dlerror(3).

Pour une explication des termes utilisés dans cette section, voir attributes(7).

HISTORIQUE

glibc 2.0. POSIX.1-2001.
dlvsym()
glibc 2.1.

REMARQUES

Il existe plusieurs scénarios où l'adresse d'un symbole global est NULL. Par exemple, un symbole peut être placé à l'adresse zéro par l'éditeur de liens, via un script de liens ou avec l'option de ligne de commande --defsym . Les symboles faibles indéfinis ont également une valeur NULL. Enfin, la valeur du symbole peut être le résultat d'une fonction résolveuse de fonction indirecte GNU (IFUNC) qui renvoie NULL comme valeur résolue. Dans ce dernier cas, dlsym() renvoie également NULL sans erreur. Cependant, dans les deux premiers cas, le comportement du lien dynamique GNU est incohérent : le traitement de la relocalisation réussit et le symbole peut être observé comme ayant une valeur NULL, mais dlsym() échoue et dlerror() indique une erreur de recherche.

Historique

La fonction dlsym() fait partie de l'API dlopen, dérivée de SunOS. Ce système n'a pas dlvsym().

EXEMPLES

Voir dlopen(3).
