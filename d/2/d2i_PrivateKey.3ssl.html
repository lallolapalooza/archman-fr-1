d2i_PrivateKey(3ssl)

D2I_PRIVATEKEY(3ssl) OpenSSL D2I_PRIVATEKEY(3ssl)

NOM

d2i_PrivateKey_ex, d2i_PrivateKey, d2i_PublicKey, d2i_KeyParams, d2i_AutoPrivateKey_ex, d2i_AutoPrivateKey, i2d_PrivateKey, i2d_PKCS8PrivateKey, i2d_PublicKey, i2d_KeyParams, i2d_KeyParams_bio, d2i_PrivateKey_ex_bio, d2i_PrivateKey_bio, d2i_PrivateKey_ex_fp, d2i_PrivateKey_fp, d2i_KeyParams_bio, i2d_PrivateKey_bio, i2d_PrivateKey_fp - fonctions de décodage et d'encodage pour la lecture et la sauvegarde de structures EVP_PKEY

DESCRIPTION

d2i_PrivateKey_ex() décode une clé privée en utilisant l'algorithme type. Il tente d'utiliser n'importe quel format spécifique à la clé ou le format PKCS#8 non chiffré PrivateKeyInfo. Le paramètre type doit être une constante d'algorithme de clé publique telle que EVP_PKEY_RSA. Une erreur se produit si la clé décodée ne correspond pas à type. Certaines implémentations de décodage de clé privée peuvent utiliser des algorithmes cryptographiques (par exemple pour dériver automatiquement la clé publique si elle n'est pas explicitement incluse dans l'encodage). Dans ce cas, le contexte de bibliothèque fourni libctx et la chaîne de requête de propriété propq sont utilisés. En cas de succès et si le paramètre a n'est pas NULL, la fonction attribue le pointeur de structure EVP_PKEY retourné à *a, écrasant toute valeur précédente.

d2i_PrivateKey() fait la même chose que d2i_PrivateKey_ex(), sauf que le contexte de bibliothèque par défaut et la chaîne de requête de propriété sont utilisés. d2i_PublicKey() fait la même chose pour les clés publiques. d2i_KeyParams() fait la même chose pour les paramètres de clé.

Les fonctions d2i_PrivateKey_ex_bio() et d2i_PrivateKey_bio() sont similaires à d2i_PrivateKey_ex() et d2i_PrivateKey() respectivement, sauf qu'elles décodent les données lues à partir du BIO donné. Les fonctions d2i_PrivateKey_ex_fp() et d2i_PrivateKey_fp() sont identiques, sauf qu'elles lisent les données du fichier FILE donné.

d2i_AutoPrivateKey_ex() et d2i_AutoPrivateKey() sont similaires à d2i_PrivateKey_ex() et d2i_PrivateKey() respectivement, sauf qu'elles tentent de détecter automatiquement le format de la clé privée.

i2d_PrivateKey() encode a. Il utilise un format spécifique à la clé ou, si aucun n'est défini pour ce type de clé, le format PKCS#8 non chiffré PrivateKeyInfo. i2d_PKCS8PrivateKey() fait la même chose en utilisant uniquement le format PKCS#8 non chiffré PrivateKeyInfo. i2d_PublicKey() fait la même chose pour les clés publiques. i2d_KeyParams() fait la même chose pour les paramètres de clé. Ces fonctions sont similaires aux fonctions d2i_X509() ; voir d2i_X509(3). i2d_PrivateKey_bio() et i2d_PrivateKey_fp() font la même chose, sauf qu'elles encodent vers un BIO ou un FILE respectivement. Encore une fois, celles-ci fonctionnent de manière similaire aux fonctions décrites dans d2i_X509(3).

NOTES

Toutes les fonctions qui opèrent sur des données en mémoire mettent à jour le pointeur de données *pp après une opération réussie, tout comme les autres fonctions d2i et i2d ; voir d2i_X509(3).

Toutes ces fonctions utilisent le format DER et des clés non chiffrées. Les applications souhaitant chiffrer ou déchiffrer des clés privées devraient utiliser d'autres fonctions telles que d2i_PKCS8PrivateKey() à la place.

Pour décoder une clé de type EVP_PKEY_EC, d2i_PublicKey() nécessite que *a soit une structure EVP_PKEY non NULL à laquelle est associée une structure EC_KEY référençant le EC_GROUP approprié.

VALEUR DE RETOUR

Les fonctions d2i_PrivateKey_ex(), d2i_PrivateKey(), d2i_AutoPrivateKey_ex(), d2i_AutoPrivateKey(), d2i_PrivateKey_ex_bio(), d2i_PrivateKey_bio(), d2i_PrivateKey_ex_fp(), d2i_PrivateKey_fp(), d2i_PublicKey(), d2i_KeyParams() et d2i_KeyParams_bio() renvoient une structure EVP_PKEY valide ou NULL si une erreur se produit. Le code d'erreur peut être obtenu en appelant ERR_get_error(3).

i2d_PrivateKey(), i2d_PKCS8PrivateKey(), i2d_PublicKey() et i2d_KeyParams() renvoient le nombre d'octets codés avec succès ou une valeur négative si une erreur se produit. Le code d'erreur peut être obtenu en appelant ERR_get_error(3).

i2d_PrivateKey_bio(), i2d_PrivateKey_fp() et i2d_KeyParams_bio() renvoient 1 en cas d'encodage réussi ou zéro en cas d'erreur.

VOIR AUSSI

HISTORIQUE

d2i_PrivateKey_ex(), d2i_PrivateKey_ex_bio(), d2i_PrivateKey_ex_fp(), et d2i_AutoPrivateKey_ex() ont été ajoutées dans OpenSSL 3.0.

i2d_PKCS8PrivateKey() a été ajoutée dans OpenSSL 3.6.
