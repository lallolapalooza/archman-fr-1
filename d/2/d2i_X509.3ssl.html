DESCRIPTION

Dans la description ici, TYPE est utilisé comme espace réservé pour l'un des types de données OpenSSL, tel que X509_CRL. Les paramètres de fonction ppin et ppout sont généralement nommés soit pp dans les en-têtes, soit in et out.

Ces fonctions convertissent les objets OpenSSL de et vers leur encodage ASN.1/DER. Contrairement aux structures C qui peuvent avoir des pointeurs vers des sous-objets internes, DER est un encodage sérialisé, adapté pour l'envoi sur le réseau, l'écriture dans un fichier, etc.

d2i_TYPE() tente de décoder len octets à partir de *ppin. En cas de succès, un pointeur vers la structure TYPE est retourné et *ppin est incrémenté pour pointer vers l'octet suivant les données analysées. Si a n'est pas NULL, un pointeur vers la structure retournée est également écrit dans *a. Si une erreur se produit, NULL est retourné. L'appelant conserve la propriété de l'objet retourné et doit le libérer lorsqu'il n'est plus nécessaire, par exemple en utilisant X509_free() pour les objets X509 ou DSA_SIG_free() pour les objets DSA_SIG.

En cas de retour réussi, si *a n'est pas NULL, il est supposé que *a contient une structure TYPE valide et une tentative est faite pour la réutiliser. Pour les structures TYPE où cela est important, il est possible de configurer un contexte de bibliothèque sur la structure décodée de cette manière (voir la section EXEMPLES). Cependant, l'utilisation de la capacité de "réutilisation" à d'autres fins est **fortement déconseillée** (voir la section BOGUES ci-dessous, et la discussion dans la section VALEURS DE RETOUR).

d2i_TYPE_bio() est similaire à d2i_TYPE() sauf qu'elle tente d'analyser les données du BIO bp.

d2i_TYPE_fp() est similaire à d2i_TYPE() sauf qu'elle tente d'analyser les données du pointeur de fichier fp.

i2d_TYPE() encode la structure pointée par a au format DER. Si ppout n'est pas NULL, elle écrit les données encodées DER dans le tampon à *ppout, et l'incrémente pour pointer après les données qui viennent d'être écrites. Si la valeur de retour est négative, une erreur s'est produite, sinon elle retourne la longueur des données encodées.

Si *ppout est NULL, de la mémoire sera allouée pour un tampon et les données encodées y seront écrites. Dans ce cas, *ppout n'est pas incrémenté et pointe vers le début des données qui viennent d'être écrites.

i2d_TYPE_bio() est similaire à i2d_TYPE() sauf qu'elle écrit l'encodage de la structure a dans le BIO bp et retourne 1 en cas de succès et 0 en cas d'échec.

i2d_TYPE_fp() est similaire à i2d_TYPE() sauf qu'elle écrit l'encodage de la structure a dans le pointeur de fichier fp et retourne 1 en cas de succès et 0 en cas d'échec.

Ces routines ne chiffrent pas les clés privées et n'offrent donc aucune sécurité ; utilisez PEM_write_PrivateKey(3) ou similaire pour écrire dans des fichiers.

NOTES

Les lettres i et d dans i2d_TYPE() signifient "internal" (c'est-à-dire une structure C interne) et "DER" respectivement. Ainsi, i2d_TYPE() convertit de l'interne vers DER.

Les fonctions peuvent également comprendre les formes BER.

La structure TYPE réelle passée à i2d_TYPE() doit être une structure TYPE valide et peuplée -- elle ne peut **pas** simplement être alimentée avec une structure vide telle que celle retournée par TYPE_new().

Les données encodées sont sous forme binaire et peuvent contenir des zéros incorporés. Par conséquent, tous les pointeurs de fichier ou BIO doivent être ouverts en mode binaire. Des fonctions comme strlen() ne retourneront **pas** la longueur correcte de la structure encodée.

La manière dont *ppin et *ppout sont incrémentés après l'opération peut piéger les imprudents. Voir la section AVERTISSEMENTS pour certaines erreurs courantes. La raison de ce comportement d'auto-incrémentation est de refléter une utilisation typique des fonctions ASN1 : après qu'une structure a été encodée ou décodée, une autre sera traitée après elle.

VALEURS DE RETOUR

d2i_TYPE(), d2i_TYPE_bio() et d2i_TYPE_fp() retournent une structure TYPE valide ou NULL si une erreur se produit. Si la fonctionnalité de "réutilisation" a été utilisée avec une structure valide passée via a, alors l'objet est libéré en cas d'erreur et *a est mis à NULL.

i2d_TYPE() retourne le nombre d'octets encodés avec succès ou une valeur négative si une erreur se produit.

i2d_TYPE_bio() et i2d_TYPE_fp(), ainsi que i2d_ASN1_bio_stream(), retournent 1 en cas de succès et 0 en cas d'échec.

EXEMPLES

Allouer et encoder la représentation DER d'une structure X509 :

int len;
unsigned char *buf;
buf = NULL;
len = i2d_X509(x, &buf);
if (len < 0)
    /* erreur */

Tenter de décoder un tampon :

X509 *x;
unsigned char *buf;
const unsigned char *p;
int len;
/* Configurer buf et len pour pointer vers le tampon d'entrée. */
p = buf;
x = d2i_X509(NULL, &p, len);
if (x == NULL)
    /* erreur */

Technique alternative :

X509 *x;
unsigned char *buf;
const unsigned char *p;
int len;
/* Configurer buf et len pour pointer vers le tampon d'entrée. */
p = buf;
x = NULL;
if (d2i_X509(&x, &p, len) == NULL)
    /* erreur */

Configuration d'un contexte de bibliothèque et d'une requête de propriétés :

X509 *x;
unsigned char *buf;
const unsigned char *p;
int len;
OSSL_LIB_CTX *libctx = ....;
const char *propq = ....;
/* Configurer buf et len pour pointer vers le tampon d'entrée. */
p = buf;
x = X509_new_ex(libctx, propq);
if (d2i_X509(&x, &p, len) == NULL)
    /* erreur, x a été libéré et NULL lui a été assigné (voir VALEURS DE RETOUR) */

AVERTISSEMENTS

L'utilisation d'une variable temporaire est obligatoire. Une erreur courante consiste à tenter d'utiliser un tampon directement comme suit :

int len;
unsigned char *buf;
len = i2d_X509(x, NULL);
buf = OPENSSL_malloc(len);
...
i2d_X509(x, &buf);
...
OPENSSL_free(buf);

Ce code aura pour conséquence que buf contiendra apparemment des données incorrectes car il a été incrémenté après l'appel pour pointer après les données qui viennent d'être écrites. De plus, buf ne contiendra plus le pointeur alloué par OPENSSL_malloc() et l'appel ultérieur à OPENSSL_free() risque de provoquer un crash.

Un autre piège à éviter est la mauvaise utilisation de l'argument a à d2i_TYPE() :

X509 *x;
if (d2i_X509(&x, &p, len) == NULL)
    /* erreur */

Cela provoquera probablement un crash quelque part dans d2i_X509(). La raison est que la variable x n'est pas initialisée et une tentative sera faite pour interpréter sa valeur (invalide) comme une structure X509, provoquant généralement une violation de segmentation. Si x est mis à NULL d'abord, cela ne se produira pas.

BOGUES

Dans certaines versions d'OpenSSL, le comportement de "réutilisation" de d2i_TYPE() lorsque *a est valide est défectueux et certaines parties de la structure réutilisée peuvent persister si elles ne sont pas présentes dans la nouvelle. De plus, dans les versions d'OpenSSL antérieures à 1.1.0, lorsque le comportement de "réutilisation" est utilisé et qu'une erreur se produit, le comportement est incohérent. Certaines fonctions se sont comportées comme décrit ici, tandis que d'autres n'ont pas libéré *a en cas d'erreur et n'ont pas mis *a à NULL.

En raison des problèmes ci-dessus, le comportement de "réutilisation" est fortement déconseillé.

i2d_TYPE() ne retournera pas d'erreur dans de nombreuses versions d'OpenSSL ; si les champs obligatoires ne sont pas initialisés en raison d'une erreur de programmation, la structure encodée peut contenir des données invalides ou omettre complètement les champs et ne sera pas analysée par d2i_TYPE(). Cela pourrait être corrigé à l'avenir, donc le code ne devrait pas supposer que i2d_TYPE() réussira toujours.

Toute fonction qui encode une structure (i2d_TYPE(), i2d_TYPE_bio() ou i2d_TYPE_fp()) peut retourner un encodage obsolète si la structure a été modifiée après désérialisation ou sérialisation précédente. C'est parce que certains objets mettent en cache l'encodage pour des raisons d'efficacité.
