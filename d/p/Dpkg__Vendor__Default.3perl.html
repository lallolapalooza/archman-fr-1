NOM

Dpkg::Vendor::Default - classe fournisseur par défaut

DESCRIPTION

Une classe fournisseur est utilisée pour fournir un comportement spécifique au fournisseur à divers endroits. C'est la classe par défaut utilisée lorsqu'il n'y en a pas pour le fournisseur actuel ou lorsque le fournisseur n'a pas pu être identifié (voir la documentation de Dpkg::Vendor).

Elle fournit certains points d'ancrage (hooks) qui sont appelés par divers outils dpkg-*. Si vous avez besoin d'un nouveau point d'ancrage, veuillez signaler un bogue contre dpkg-dev et expliquer votre besoin. Notez que l'API des points d'ancrage n'a aucune garantie de stabilité sur une période prolongée. Si vous gérez une distribution importante qui utilise des points d'ancrage fournisseur, il vaut mieux les soumettre pour intégration afin que nous évitions de casser votre code.

Note: Ceci est un module privé, son API peut changer à tout moment.

MÉTHODES

$vendor_obj = Dpkg::Vendor::Default->new()
Crée l'objet fournisseur par défaut. Peut être hérité par tous les objets fournisseur s'ils n'ont pas besoin d'initialisation spécifique lors de la création de l'objet.
$vendor_obj->run_hook($id, @params)
Exécute le point d'ancrage correspondant. Les paramètres sont spécifiques à chaque point d'ancrage. Les points d'ancrage pris en charge sont :
before-source-build ($srcpkg)
Le premier paramètre est un objet Dpkg::Source::Package. Le point d'ancrage est appelé juste avant l'exécution de $srcpkg->build().
package-keyrings ()
Le point d'ancrage est appelé lorsque dpkg-source vérifie une signature sur un paquet source (depuis dpkg 1.18.11). Il ne prend aucun paramètre, mais retourne une liste (éventuellement vide) de trousseaux de clés spécifiques au fournisseur.
archive-keyrings ()
Le point d'ancrage est appelé lorsqu'il est nécessaire de vérifier des signatures sur des artefacts provenant de dépôts, par exemple par une méthode de téléchargement (depuis dpkg 1.18.11). Il ne prend aucun paramètre, mais retourne une liste (éventuellement vide) de trousseaux de clés spécifiques au fournisseur.
archive-keyrings-historic ()
Le point d'ancrage est appelé lorsqu'il est nécessaire de vérifier des signatures sur des artefacts provenant de dépôts historiques, par exemple par une méthode de téléchargement (depuis dpkg 1.18.11). Il ne prend aucun paramètre, mais retourne une liste (éventuellement vide) de trousseaux de clés spécifiques au fournisseur.
builtin-build-depends ()
Le point d'ancrage est appelé lorsque dpkg-checkbuilddeps initialise les dépendances de construction du paquet source (depuis dpkg 1.18.2). Il ne prend aucun paramètre, mais retourne une liste (éventuellement vide) de Build-Dependsspécifiques au fournisseur.
builtin-build-conflicts ()
Le point d'ancrage est appelé lorsque dpkg-checkbuilddeps initialise les conflits de construction du paquet source (depuis dpkg 1.18.2). Il ne prend aucun paramètre, mais retourne une liste (éventuellement vide) de Build-Conflictsspécifiques au fournisseur.
register-custom-fields ()
Le point d'ancrage est appelé dans Dpkg::Control::Fields pour enregistrer des champs personnalisés. Vous devez retourner une liste de tableaux. Chaque tableau est une opération à effectuer. Le premier élément est le nom de l'opération et correspond à une fonction field_* fournie par Dpkg::Control::Fields. Les champs restants sont les paramètres qui sont passés inchangés à la fonction correspondante.

Les opérations connues sont "register", "insert_after" et "insert_before".

post-process-changelog-entry ($fields)
Le point d'ancrage est appelé dans Dpkg::Changelog pour post-traiter une Dpkg::Changelog::Entry après qu'elle a été créée et remplie avec les valeurs appropriées.
update-buildflags ($flags)
Le point d'ancrage est appelé dans Dpkg::BuildFlags pour permettre au fournisseur de remplacer les valeurs par défaut définies pour les diverses options de construction. $flags est un objet Dpkg::BuildFlags.
builtin-system-build-paths ()
Le point d'ancrage est appelé par dpkg-genbuildinfo pour déterminer si le chemin actuel doit être enregistré dans le champ Build-Path (depuis dpkg 1.18.11). Il ne prend aucun paramètre, mais retourne une liste (éventuellement vide) de chemins racines considérés comme acceptables. Par exemple, si la liste contient "/build/", un champ Build-Path sera créé si le répertoire courant est "/build/dpkg-1.18.0". Si la liste contient "/", le chemin sera toujours enregistré. Si la liste est vide, le chemin actuel ne sera jamais enregistré.
build-tainted-by ()
Le point d'ancrage est appelé par dpkg-genbuildinfo pour déterminer si le système actuel a été contaminé d'une manière qui pourrait affecter la construction résultante, ce qui sera enregistré dans le champ Build-Tainted-By (depuis dpkg 1.19.5). Il ne prend aucun paramètre, mais retourne une liste (éventuellement vide) d'étiquettes de raisons de contamination (formées de caractères alphanumériques et de tirets).
sanitize-environment ()
Le point d'ancrage est appelé par dpkg-buildpackage pour assainir son environnement de construction (depuis dpkg 1.20.0).
backport-version-regex ()
Le point d'ancrage est appelé par dpkg-genchanges et dpkg-mergechangelog pour déterminer la chaîne de version de rétroportation qui doit être traitée spécialement comme n'étant pas une version antérieure ou remappée afin qu'elle ne soit pas considérée comme une pré-version (depuis dpkg 1.21.3). La chaîne retournée est une expression régulière avec un groupe de capture pour la chaîne délimiteur de rétroportation, ou undef s'il n'y a pas d'expression régulière.
$vendor->set_build_features($flags)
Définit les fonctionnalités de construction du fournisseur, qui seront ensuite utilisées pour initialiser les options de construction.
$vendor->add_build_flags($flags)
Ajoute les options de construction du fournisseur aux variables d'options du compilateur en se basant sur les valeurs par défaut du fournisseur et les fonctionnalités de construction définies précédemment.
