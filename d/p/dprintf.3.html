Largeur de

champ

Une chaîne de chiffres décimaux optionnelle (avec un premier chiffre non nul) spécifiant une largeur de champ minimale. Si la valeur convertie a moins de caractères que la largeur de champ, elle sera complétée par des espaces à gauche (ou à droite, si le drapeau d'ajustement à gauche a été donné). Au lieu d'une chaîne de chiffres décimaux, on peut écrire "*" ou "*m$" (pour un entier décimal m) pour spécifier que la largeur de champ est donnée dans l'argument suivant, ou dans le m-ième argument, respectivement, qui doit être de type int. Une largeur de champ négative est considérée comme un drapeau '-' suivi d'une largeur de champ positive. Dans aucun cas une largeur de champ inexistante ou petite

ne cause la troncature d'un champ ; si le résultat d'une conversion est plus large
que la largeur de champ, le champ est étendu pour contenir le résultat de la conversion.

AVERTISSEMEN

TS

Certains programmes se fient imprudemment à du code tel que le

suivant 


sprintf(buf, "%s some further text", buf)
;

pour ajouter du texte à buf. Cependant, les normes notent explicitement que les résultats sont indéfinis si les tampons source et destination se chevauchent lors de l'appel à sprintf(), snprintf(), vsprintf(), et vsnprintf(). Selon la version de gcc(1) utilisée, et les options de compilation employées, des appels tels que celui ci-dessus ne produiront pas les résultats

attendus.

L'implémentation glibc des fonctions snprintf() et vsnprintf() est conforme à la norme C99, c'est-à-dire qu'elle se comporte comme décrit ci-dessus

, depuis glibc 2.1. Jusqu'à glibc 2.0.6, elles
renvoyaient -1 lorsque la sortie était tronquée.

BOGUE

S

Parce que sprintf() et vsprintf() supposent une chaîne de longueur arbitraire, les appelants doivent faire attention à ne pas dépasser l'espace réel ; c'est souvent impossible à garantir. Notez que la longueur des chaînes produites dépend de la locale et est difficile à prédire. Utilisez snprintf() et vsnprintf() à la place (ou asprintf(3) et vasprintf(3))

.

Du code tel que printf(foo); indique souvent un bug, car foo peut contenir un caractère %. Si foo provient d'une entrée utilisateur non fiable, il peut contenir %n, ce qui amènerait l'appel printf() à écrire en mémoire

et créer une fai
lle de sécurité.

EXEMPLES

Pour imprimer Pi avec cinq décimales :


#include <math.h>
#include <stdio.h>
fprintf(stdout, "pi = %.5f\n", 4 * atan(1.0));

Pour imprimer une date et une heure au format « dimanche, juillet 3, 10:02 », où weekday et month sont des pointeurs de chaînes :


#include <stdio.h>
fprintf(stdout, "%s, %s %d, %.2d:%.2d\n",
        weekday, month, day, hour, min);

De nombreux pays utilisent l'ordre jour-mois-année. Par conséquent, une version internationalisée doit être capable d'imprimer les arguments dans un ordre spécifié par le format :


#include <stdio.h>
fprintf(stdout, format,
        weekday, month, day, hour, min);

où format dépend de la locale, et peut permuter les arguments. Avec la valeur :


"%1$s, %3$d. %2$s, %4$d:%5$.2d\n"

on pourrait obtenir « Sonntag, 3. Juli, 10:02 ».

Pour allouer une chaîne suffisamment grande et y écrire (code correct pour glibc 2.0 et glibc 2.1) :

#include <stdio.h>
#include <stdlib.h>
#include <stdarg.h>
char *
make_message(const char *fmt, ...)
{
    int n = 0;
    size_t size = 0;
    char *p = NULL;
    va_list ap;
    /* Déterminer la taille requise.  */
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0)
        return NULL;
    size = (size_t) n + 1;      /* Un octet supplémentaire pour '\0' */
    p = malloc(size);
    if (p == NULL)
        return NULL;
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0) {
        free(p);
        return NULL;
    }
    return p;
}

Si une troncature se produit dans les versions de glibc antérieures à glibc 2.0.6, cela est traité comme une erreur au lieu d'être géré correctement.
