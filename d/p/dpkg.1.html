NOM

dpkg - gestionnaire de paquets pour Debian

SYNOPSIS

dpkg [option...] action

AVERTISSEMENT

Ce manuel est destiné aux utilisateurs souhaitant comprendre les options en ligne de commande de dpkget les états des paquets plus en détail que ce que fournit dpkg --help.

Il ne doit pas être utilisé par les responsables de paquets souhaitant comprendre comment dpkg installera leurs paquets. Les descriptions de ce que dpkg fait lors de l'installation et de la suppression des paquets sont particulièrement inadéquates.

DESCRIPTION

dpkg est un outil de niveau intermédiaire pour installer, construire, supprimer et gérer les paquets Debian. L'interface principale et plus conviviale pour dpkg en tant qu'IGC (interface en ligne de commande) est apt(8) et en tant qu'IUT (interface utilisateur terminal) est aptitude(8). dpkg lui-même est entièrement contrôlé via des paramètres en ligne de commande, qui consistent en exactement une action et zéro ou plusieurs options. Le paramètre action indique à dpkg quoi faire et les options contrôlent le comportement de l'action d'une certaine manière.

dpkg peut également être utilisé comme interface pour dpkg-deb(1) et dpkg-query(1). La liste des actions prises en charge se trouve plus loin dans la section ACTIONS . Si une telle action est rencontrée, dpkg exécute simplement dpkg-deb ou dpkg-query avec les paramètres qui lui sont donnés, mais aucune option spécifique n'est actuellement passée à ceux-ci ; pour utiliser une telle option, les programmes de traitement doivent être appelés directement.

INFORMATIONS SUR LES PAQUETS

dpkg maintient certaines informations utilisables sur les paquets disponibles. L'information est divisée en trois classes : états, états de sélection et indicateurs. Ces valeurs sont destinées à être modifiées principalement avec dselect.

États des paquets

not-installed
Le paquet n'est pas installé sur votre système.
config-files
Seuls les fichiers de configuration ou le script postrm et les données dont il a besoin pour supprimer le paquet existent sur le système.
half-installed
L'installation du paquet a été commencée, mais n'est pas terminée pour une raison quelconque.
unpacked
Le paquet est décompressé, mais pas configuré.
half-configured
Le paquet est décompressé et la configuration a été commencée, mais n'est pas encore terminée pour une raison quelconque.
triggers-awaited
Le paquet attend le traitement de ses déclencheurs par un autre paquet.
triggers-pending
Le paquet a été déclenché.
installed
Le paquet est correctement décompressé et configuré.

États de sélection des paquets

install
Le paquet est sélectionné pour l'installation.
hold
Un paquet marqué comme hold est maintenu sur la même version, c'est-à-dire qu'aucune nouvelle installation, mise à niveau ou suppression automatique ne sera effectuée sur lui, sauf si ces actions sont demandées explicitement ou si leur exécution automatique est autorisée avec l'option --force-hold .
deinstall
Le paquet est sélectionné pour la désinstallation (c'est-à-dire que nous voulons supprimer tous les fichiers, sauf les fichiers de configuration).
purge
Le paquet est sélectionné pour être purgé (c'est-à-dire que nous voulons supprimer tout des répertoires système, y compris les fichiers de configuration).
unknown
La sélection du paquet est inconnue. Un paquet qui est également dans un état not-installed et avec un indicateur ok sera oublié lors du prochain enregistrement de la base de données.

Indicateurs des paquets

ok
Un paquet marqué ok est dans un état connu, mais pourrait nécessiter un traitement supplémentaire.
reinstreq
Un paquet marqué reinstreq est endommagé et nécessite une réinstallation. Ces paquets ne peuvent pas être supprimés, sauf si on force avec l'option --force-remove-reinstreq.

ACTIONS

-i, --install fichier-paquet...
Installe le paquet. Si l'option --recursive ou -R est spécifiée, fichier-paquet doit faire référence à un répertoire à la place.

L'installation se compose des étapes suivantes :

1.
Extraire les fichiers de contrôle du nouveau paquet.
2.
Si une autre version du même paquet était installée avant la nouvelle installation, exécuter le script prerm de l'ancien paquet.
3.
Exécuter le script preinst , s'il est fourni par le paquet.
4.
Décompresser les nouveaux fichiers, et en même temps sauvegarder les anciens fichiers, afin qu'ils puissent être restaurés si quelque chose se passe mal.
5.
Si une autre version du même paquet était installée avant la nouvelle installation, exécuter le script postrm de l'ancien paquet. Notez que ce script est exécuté après le script preinst du nouveau paquet, car les nouveaux fichiers sont écrits en même temps que les anciens fichiers sont supprimés.
6.
Configurer le paquet. Voir --configure pour des informations détaillées sur la manière dont cela est fait.
--unpack fichier-paquet...
Décompresser le paquet, mais ne pas le configurer. Si l'option --recursive ou -R est spécifiée, fichier-paquet doit faire référence à un répertoire à la place.

Traitera les déclencheurs pour Pre-Depends sauf si --no-triggers a été spécifié.

--configure paquet...|-a|--pending
Configurer un paquet qui a été décompressé mais pas encore configuré. Si -a ou --pending est donné à la place de paquet, tous les paquets décompressés mais non configurés sont configurés.

Pour reconfigurer un paquet qui a déjà été configuré, essayez plutôt la commande dpkg-reconfigure(8) (qui fait partie du projet debconf ).

La configuration se compose des étapes suivantes :

1.
Décompresser les fichiers de configuration, et en même temps sauvegarder les anciens fichiers de configuration, afin qu'ils puissent être restaurés si quelque chose se passe mal.
2.
Exécuter le script postinst , s'il est fourni par le paquet.

Traitera les déclencheurs sauf si --no-triggers a été spécifié.

--triggers-only paquet...|-a|--pending
Traite uniquement les déclencheurs (depuis dpkg 1.14.17). Tous les déclencheurs en attente seront traités. Si des noms de paquets sont fournis, seuls les déclencheurs de ces paquets seront traités, exactement une fois chacun si nécessaire. L'utilisation de cette option peut laisser des paquets dans les états inappropriés triggers-awaited et triggers-pending . Cela peut être corrigé plus tard en exécutant : dpkg --configure --pending.
-r, --remove paquet...|-a|--pending
Supprimer un paquet installéage. Cela supprime tout sauf les conffiles et autres données nettoyées par le postrm script, ce qui peut éviter d'avoir à reconfigurer le paquet s'il est réinstallé plus tard (les conffiles sont les fichiers de configuration listés dans le DEBIAN/conffiles fichier de contrôle). S'il n'y a pas de DEBIAN/conffiles fichier de contrôle ni de DEBIAN/postrm script, cette commande est équivalente à appeler --purge. Si -a ou --pending est donné à la place d'un nom de paquet, alors tous les paquets dépaquetés, mais marqués pour être supprimés dans le fichier /var/lib/dpkg/status, sont supprimés.

La suppression d'un paquet consiste aux étapes suivantes :

1.
Exécuter le prerm script.
2.
Supprimer les fichiers installés.
3.
Exécuter le postrm script.

Les déclencheurs seront traités sauf si --no-triggers a été spécifié.

-P, --purge paquet...|-a|--pending
Purger un paquet installé ou déjà supprimé. Cela supprime tout, y compris les conffiles, et tout ce qui est nettoyé par postrm. Si -a ou --pending est donné à la place d'un nom de paquet, alors tous les paquets dépaquetés ou supprimés, mais marqués pour être purgés dans le fichier /var/lib/dpkg/status, sont purgés.

Remarque: Certains fichiers de configuration peuvent être inconnus de dpkg car ils sont créés et gérés séparément par les scripts de configuration. Dans ce cas, dpkg ne les supprimera pas lui-même, mais le postrm script du paquet (qui est appelé par dpkg) doit prendre en charge leur suppression lors de la purge. Bien sûr, cela ne s'applique qu'aux fichiers des répertoires système, et non aux fichiers de configuration écrits dans les répertoires personnels des utilisateurs.

La purge d'un paquet consiste aux étapes suivantes :

1.
Supprimer le paquet, s'il n'a pas déjà été supprimé. Voir --remove pour des informations détaillées sur la façon dont cela est fait.
2.
Exécuter le postrm script.

Les déclencheurs seront traités sauf si --no-triggers a été spécifié.

-V, --verify [nom-paquet...]
Vérifie l'intégrité du nom-paquet ou de tous les paquets s'il est omis, en comparant les informations des fichiers installés par un paquet avec les métadonnées des fichiers stockées dans la base de données dpkg (depuis dpkg 1.17.2). L'origine des métadonnées des fichiers dans la base de données est les paquets binaires eux-mêmes. Ces métadonnées sont collectées au moment du dépaquetage du paquet pendant le processus d'installation.

Actuellement, la seule vérification fonctionnelle effectuée est une vérification md5sum du contenu des fichiers par rapport à la valeur stockée dans la base de données des fichiers. Elle ne sera effectuée que si la base de données contient le md5sum du fichier. Pour vérifier les métadonnées manquantes dans la base de données, la commande --audit peut être utilisée. Ceci n'est qu'une vérification d'intégrité et ne doit pas être considéré comme un type de vérification de sécurité.

Le format de sortie est sélectionnable avec l'option --verify-format , qui utilise par défaut le format rpm , mais cela pourrait changer à l'avenir, et en tant que tel, les programmes analysant la sortie de cette commande doivent être explicites sur le format qu'ils attendent.

-C, --audit [nom-paquet...]
Effectue des vérifications de cohérence et de santé de la base de données pour le nom-paquet ou tous les paquets s'il est omis (vérifications par paquet depuis dpkg 1.17.10). Par exemple, recherche les paquets qui n'ont été installés que partiellement sur votre système ou qui ont des données de contrôle ou des fichiers manquants, incorrects ou obsolètes. dpkg suggérera quoi faire avec eux pour les réparer.
--update-avail [fichier-Packages]
--merge-avail [fichier-Packages]
Met à jour la notion de dpkget de dselectsur les paquets disponibles. Avec l'action --merge-avail, les anciennes informations sont combinées avec les informations du fichier-Packages. Avec l'action --update-avail, les anciennes informations sont remplacées par les informations du fichier-Packages. Le fichier-Packages distribué avec Debian est simplement nommé «Packages». Si l'argument fichier-Packages est manquant ou nommé «-» alors il sera lu depuis l'entrée standard (depuis dpkg 1.17.7). dpkg conserve son enregistrement des paquets disponibles dans /var/lib/dpkg/available.

Une commande unique plus simple pour récupérer et mettre à jour le fichier available est dselect update. Remarquez que ce fichier est inutile si vous n'utilisez pas dselect mais une interface basée sur APT : APT a son propre système pour garder la trace des paquets disponibles.

-A, --record-avail fichier-paquet...
Met à jour la notion de dpkg et de dselectsur les paquets disponibles avec les informations du paquet fichier-paquet. Si l'option --recursive ou -R est spécifiée, fichier-paquet doit faire référence à un répertoire à la place.
--forget-old-unavail
Maintenant obsolète et sans effet car dpkg oubliera automatiquement les paquets non installés et non disponibles (depuis dpkg 1.15.4), mais seulement ceux qui ne contiennent pas d'informations utilisateur telles que les sélections de paquets.
--clear-avail
Efface les informations existantes sur les paquets disponibles.
--get-selections [motif-nom-paquet...]
Obtient la liste des sélections de paquets et l'écrit sur stdout. Sans motif, les paquets non installés (c'est-à-dire ceux qui ont été purgés précédemment) ne seront pas affichés.
--set-selections
Définit les sélections de paquets à l'aide du fichier lu depuis stdin. Ce fichier doit être au format «paquet état», où état est l'un de install, hold, deinstall ou purge. Les lignes vides et les lignes de commentaire commençant par «#» sont également autorisées.

Le fichier available doit être à jour pour que cette commande soit utile, sinon les paquets inconnus seront ignorés avec un avertissement. Voir les commandes --update-avail et --merge-avail pour plus d'informations.

--clear-selections
Définit l'état demandé de chaque paquet non essentiel à deinstall (depuis dpkg 1.13.18). Cela est destiné à être utilisé immédiatement avant --set-selections, pour désinstaller tous les paquets qui ne sont pas dans la liste donnée à --set-selections.
--yet-to-unpack
Recherche les paquets sélectionnés pour l'installation, mais qui pour une raison quelconque n'ont toujours pas été installés.

Remarque: Cette commande utilise à la fois le fichier available et les sélections de paquets.

--predep-package
Affiche un seul paquet qui est la cible d'une ou plusieurs prédépendances pertinentes et qui n'a lui-même aucune prédépendance non satisfaite.

Si un tel paquet est présent, affichez-le sous la forme d'une entrée de fichier Packages, qui peut être traitée selon les besoins.

Remarque: Cette commande utilise à la fois le fichier available et les sélections de paquets.

Renvoie 0 lorsqu'un paquet est imprimé, 1 lorsqu'aucun paquet approprié n'est disponible et 2 en cas d'erreur.

--add-architecture architecture
Ajoute architecture à la liste des architectures pour lesquelles les paquets peuvent être installés sans utiliser --force-architecture (depuis dpkg 1.16.2). L'architecture pour laquelle dpkg est construit (c'est-à-dire la sortie de --print-architecture) fait toujours partie de cette liste.
--remove-architecture architecture
Supprime architecture de la liste des architectures pour lesquelles les paquets peuvent être installés sans utiliser --force-architecture (depuis dpkg 1.16.2). Si l'architecture est actuellement utilisée dans la base de données, l'opération sera refusée, sauf si --force-architecture est spécifié. L'architecture pour laquelle dpkg est construit (c'est-à-dire la sortie de --print-architecture) ne peut jamais être supprimée de cette liste.
--print-architecture
Affiche l'architecture des paquets que dpkg installe (par exemple, « i386 »).
--print-foreign-architectures
Affiche une liste des architectures supplémentaires séparées par des sauts de ligne pour lesquelles dpkg est configuré pour permettre l'installation de paquets (depuis dpkg 1.16.2).
--assert-help
Donne de l'aide sur les options --assert-fonctionnalité (depuis dpkg 1.21.0).
--assert-fonctionnalité
Affirme que dpkg prend en charge la fonctionnalité demandée. Renvoie 0 si la fonctionnalité est entièrement prise en charge, 1 si la fonctionnalité est connue mais que dpkg ne peut pas encore y apporter de support, et 2 si la fonctionnalité est inconnue. La liste actuelle des fonctionnalités assertables est :
support-predepends
Prend en charge le champ Pre-Depends (depuis dpkg 1.1.0).
working-epoch
Prend en charge les époques dans les chaînes de version (depuis dpkg 1.4.0.7).
long-filenames
Prend en charge les noms de fichiers longs dans les archives deb(5) (depuis dpkg 1.4.1.17).
multi-conrep
Prend en charge plusieurs Conflicts et Replaces (depuis dpkg 1.4.1.19).
multi-arch
Prend en charge les champs et la sémantique multi-arch (depuis dpkg 1.16.2).
versioned-provides
Prend en charge les Provides avec version (depuis dpkg 1.17.11).
protected-field>
Prend en charge le champ Protected (depuis dpkg 1.20.1).
--validate-thing string
Valide que la thing string a une syntaxe correcte (depuis dpkg 1.18.16). Retourne 0 si la string est valide, 1 si la string est invalide mais pourrait être acceptée dans des contextes permissifs, et 2 si la string est invalide. La liste actuelle des thingvalidables est :
pkgname
Valide le nom de paquet donné (depuis dpkg 1.18.16).
trigname
Valide le nom de déclencheur donné (depuis dpkg 1.18.16).
archname
Valide le nom d'architecture donné (depuis dpkg 1.18.16).
version
Valide la version donnée (depuis dpkg 1.18.16).
--compare-versions ver1 op ver2
Compare des numéros de version, où op est un opérateur binaire. dpkg retourne vrai (0) si la condition spécifiée est satisfaite, et faux (1) sinon. Il existe deux groupes d'opérateurs, qui diffèrent dans la façon dont ils traitent une ver1 ou ver2vide. Ceux-ci traitent une version vide comme antérieure à toute version : lt le eq ne ge gt. Ceux-ci traitent une version vide comme postérieure à toute version : lt-nl le-nl ge-nl gt-nl. Ceux-ci ne sont fournis que pour compatibilité avec la syntaxe des fichiers de contrôle : < << <= = >= >> >. Les < et > opérateurs sont obsolètes et ne doivent pas être utilisés, en raison de sémantiques déroutantes. Pour illustrer : 0.1 < 0.1 évalue à vrai.
-?, --help
Affiche un court message d'aide.
--force-help
Donne de l'aide sur les options --force-thing .
-Dh, --debug=help
Donne de l'aide sur les options de débogage.
--version
Affiche les informations de version de dpkg .

Lorsqu'il est utilisé avec --robot, la sortie sera le numéro de version du programme au format numérique pointé, sans retour à la ligne.

dpkg-deb actions
Voir dpkg-deb(1) pour plus d'informations sur les actions suivantes, et d'autres actions et options non exposées par l'interface dpkg .
-b, --build directory [archive|directory]
Construit un paquet deb.
-c, --contents archive
Liste le contenu d'un paquet deb.
-e, --control archive [directory]
Extrait les informations de contrôle d'un paquet.
-x, --extract archive directory
Extrait les fichiers contenus dans le paquet.
-X, --vextract archive directory
Extrait et affiche les noms de fichiers contenus dans un paquet.
-f, --field archive [control-field...]
Affiche le ou les champs de contrôle d'un paquet.
--ctrl-tarfile archive
Affiche l'archive tar de contrôle contenue dans un paquet Debian.
--fsys-tarfile archive
Affiche l'archive tar du système de fichiers contenue dans un paquet Debian.
-I, --info archive [control-file...]
Affiche des informations sur un paquet.
dpkg-query actions
Voir dpkg-query(1) pour plus d'informations sur les actions suivantes, et d'autres actions et options non exposées par l'interface dpkg .
-l, --list package-name-pattern...
Liste les paquets correspondant au motif donné.
-s, --status package-name...
Rapporte l'état des paquets spécifiés.
-L, --listfiles package-name...
Liste les fichiers installés sur votre système à partir du package-name.
-S, --search filename-search-pattern...
Recherche un nom de fichier dans les paquets installés.
-p, --print-avail package-name...
Affiche des détails sur package-name, tels que trouvés dans /var/lib/dpkg/available. Les utilisateurs d'interfaces basées sur APT devraient utiliser apt show package-name à la place.

OPTIONS

Toutes les options peuvent être spécifiées à la fois sur la ligne de commande et dans le fichier de configuration de dpkg /etc/dpkg/dpkg.cfg ou les fichiers fragments (avec des noms correspondant à ce motif de shell '[0-9a-zA-Z_-]*') dans le répertoire de configuration /etc/dpkg/dpkg.cfg.d/. Chaque ligne du fichier de configuration est soit une option (exactement la même que l'option de la ligne de commande mais sans les tirets de début) soit un commentaire (si elle commence par un «#»).

--abort-after=number
Modifie le nombre d'erreurs après lequel dpkg s'arrêtera. La valeur par défaut est 50.
-B, --auto-deconfigure
Lorsqu'un paquet est supprimé, il est possible qu'un autre paquet installé dépendait du paquet supprimé. Spécifier cette option entraînera la déconfiguration automatique du paquet qui dépendait du paquet supprimé.
-Doctal, --debug=octal
Active le débogage. octal est formé en combinant par un OU bit à bit les valeurs désirées de la liste ci-dessous (notez que ces valeurs peuvent changer dans de futures versions). -Dh ou --debug=help affiche ces valeurs de débogage. 
Numéro   Description
     1   Informations de progression généralement utiles
     2   Invocation et état des scripts de maintenance
    10   Sortie pour chaque fichier traité
   100   Beaucoup de sortie pour chaque fichier traité
    20   Sortie pour chaque fichier de configuration
   200   Beaucoup de sortie pour chaque fichier de configuration
    40   Dépendances et conflits
   400   Beaucoup de sortie sur les dépendances/conflits
 10000   Activation et traitement des déclencheurs
 20000   Beaucoup de sortie concernant les déclencheurs
 40000   Des quantités absurdes de sortie concernant les déclencheurs
  1000   Beaucoup de bavardages sur par exemple le répertoire dpkg/info
  2000   Des quantités insensées de bavardages
--force-things
--no-force-things, --refuse-things
Force ou refuse (no-force et refuse signifient la même chose) de faire certaines choses. things est une liste de choses séparées par des virgules spécifiées ci-dessous. --force-help affiche un message les décrivant. Les éléments marqués avec (*) sont forcés par défaut.

Avertissement: Ces options sont principalement destinées à être utilisées uniquement par des experts. Les utiliser sans comprendre pleinement leurs effets peut casser votre système entier.

all:
Active (ou désactive) toutes les options de force.
downgrade(*):
Installe un paquet, même si une version plus récente est déjà installée.

Avertissement: Actuellement dpkg n'effectue aucune vérification des dépendances lors des rétrogradations et ne vous avertira donc pas si la rétrogradation casse la dépendance d'un autre paquet. Cela peut avoir des effets secondaires graves, la rétrogradation de composants essentiels du système peut même rendre votre système entier inutilisable. À utiliser avec précaution.

configure-any:
Configure également tous les paquets déballés mais non configurés dont dépend le paquet courant.
hold:
Autorise les installations, mises à jour ou suppressions automatiques de paquets même lorsqu'ils sont marqués comme « en attente ». Note: Lorsque ces actions sont demandées explicitement, l'état de sélection « en attente » du paquet est toujours ignoré.
remove-reinstreq:
Supprime un paquet, même s'il est cassé et marqué comme nécessitant une réinstallation. Cela peut, par exemple, faire que des parties du paquet restent sur le système, qui seront alors oubliées par dpkg.
remove-protected:
Supprime, même si le paquet est considéré comme protégé (depuis dpkg 1.20.1). Les paquets protégés contiennent principalement l'infrastructure de démarrage importante du système ou sont utilisés pour des méta-paquets locaux personnalisés. Les supprimer pourrait faire que le système entier ne puisse plus démarrer ou perde des fonctionnalités nécessaires à son fonctionnement, alors utilisez cette option avec précaution.
remove-essential:
Supprime, même si le paquet est considéré comme essentiel. Les paquets essentiels contiennent principalement des commandes Unix très basiques, nécessaires pour le système d'empaquetage, pour le fonctionnement général du système ou lors du démarrage (bien que ces dernières devraient être converties en paquets protégés à la place). Les supprimer pourrait faire que le système entier cesse de fonctionner, alors utilisez cette option avec précaution.
depends:
Transforme tous les problèmes de dépendances en avertissements. Cela affecte les champs Pre-Depends et Depends .
depends-version:
Ignore les versions lors de la vérification des dépendances. Cela affecte les champs Pre-Depends et Depends .
breaks:
Installe, même si cela casserait un autre er package (depuis dpkg 1.14.6). Ceci affecte le champ Breaks.
conflicts :
Installer, même si cela entre en conflit avec un autre paquet. C'est dangereux, car cela écrase généralement certains fichiers. Ceci affecte le champ Conflicts.
confmiss :
Installer toujours le fichier de configuration manquant sans demander. C'est dangereux, car cela signifie ne pas préserver une modification (suppression) apportée au fichier.
confnew :
Si un fichier de configuration a été modifié et que la version dans le paquet a changé, installer toujours la nouvelle version sans demander, sauf si l'option --force-confdef est également spécifiée, auquel cas l'action par défaut est préférée.
confold :
Si un fichier de configuration a été modifié et que la version dans le paquet a changé, conserver toujours l'ancienne version sans demander, sauf si l'option --force-confdef est également spécifiée, auquel cas l'action par défaut est préférée.
confdef :
Si un fichier de configuration a été modifié et que la version dans le paquet a changé, choisir toujours l'action par défaut sans demander. S'il n'y a pas d'action par défaut, cela s'arrêtera pour demander à l'utilisateur, sauf si --force-confnew ou --force-confold est également donné, auquel cas cela sera utilisé pour décider de l'action finale.
confask :
Si un fichier de configuration a été modifié, proposer toujours de le remplacer par la version du paquet, même si la version du paquet n'a pas changé (depuis dpkg 1.15.8). Si l'une des options --force-confnew, --force-confold ou --force-confdef est également donnée, elle sera utilisée pour décider de l'action finale.
overwrite :
Écraser un fichier d'un paquet par un fichier d'un autre.
overwrite-dir :
Écraser un répertoire d'un paquet par un fichier d'un autre.
overwrite-diverted :
Écraser un fichier détourné par une version non détournée.
statoverride-add :
Écraser une surcharge de statistiques existante lors de son ajout (depuis dpkg 1.19.5).
statoverride-remove :
Ignorer une surcharge de statistiques manquante lors de sa suppression (depuis dpkg 1.19.5).
security-mac(*) :
Utiliser des contrôles d'accès obligatoires (MAC) spécifiques à la plateforme lors de l'installation de fichiers dans le système de fichiers (depuis dpkg 1.19.5). Sur les systèmes Linux, l'implémentation utilise SELinux.
unsafe-io :
Ne pas effectuer d'opérations d'E/S sûres lors du dépaquetage (depuis dpkg 1.15.8.6). Actuellement, cela implique de ne pas synchroniser le système de fichiers avant le renommage de fichiers, ce qui est connu pour causer une dégradation significative des performances sur certains systèmes de fichiers, malheureusement ceux qui nécessitent les E/S sûres en premier lieu en raison de leur comportement peu fiable qui produit des fichiers de longueur nulle lors de plantages système abrupts.

Note : Pour ext4, le principal coupable, envisagez d'utiliser l'option de montage nodelalloc à la place, qui corrigera à la fois la dégradation des performances et les problèmes de sécurité des données, ces derniers en empêchant le système de fichiers de produire des fichiers de longueur nulle lors de plantages système abrupts avec tout logiciel qui ne synchronise pas avant les renommages atomiques.

Attention : L'utilisation de cette option peut améliorer les performances au coût d'une perte de données, utilisez avec prudence.

script-chrootless :
Exécuter les scripts de maintenance sans chroot(2) dans instdir même si le paquet ne prend pas en charge ce mode de fonctionnement (depuis dpkg 1.18.5).

Attention : Cela peut détruire votre système hôte, utilisez avec une extrême précaution.

architecture :
Traiter même les paquets avec une architecture incorrecte ou inexistante.
bad-version :
Traiter même les paquets avec des versions incorrectes (depuis dpkg 1.16.1).
bad-path :
PATH ne contient pas les programmes importants, donc des problèmes sont probables.
not-root :
Essayer d'installer/désinstaller des choses même sans être root.
bad-verify :
Installer un paquet même s'il échoue à la vérification d'authenticité.
--ignore-depends=paquet,...
Ignorer la vérification des dépendances pour les paquets spécifiés (en réalité, la vérification est effectuée, mais seuls des avertissements sur les conflits sont émis, rien d'autre). Cela affecte les champs Pre-Depends, Depends et Breaks.
--no-act, --dry-run, --simulate
Faire tout ce qui est censé être fait, mais sans écrire de changements. Ceci est utilisé pour voir ce qui se passerait avec l'action spécifiée, sans modifier quoi que ce soit.

Assurez-vous de donner --no-act avant le paramètre d'action, sinon vous pourriez vous retrouver avec des résultats indésirables (par exemple, dpkg --purge foo --no-act purgera d'abord le paquet « foo » puis tentera de purger le paquet « --no-act », même si vous vous attendiez probablement à ce qu'il ne fasse rien).

-R, --recursive
Traiter récursivement tous les fichiers réguliers correspondant au motif *.deb trouvés dans les répertoires spécifiés et tous leurs sous-répertoires. Ceci peut être utilisé avec les actions -i, -A, --install, --unpack et --record-avail.
-G
Ne pas installer un paquet si une version plus récente du même paquet est déjà installée. Ceci est un alias de --refuse-downgrade.
--admindir=rép
Définir le répertoire administratif à répertoire. Ce répertoire contient de nombreux fichiers qui donnent des informations sur l'état des paquets installés ou non installés, etc. La valeur par défaut est « /var/lib/dpkg » si DPKG_ADMINDIR n'a pas été défini.
--instdir=rép
Définir le répertoire d'installation, qui fait référence au répertoire où les paquets doivent être installés. instdir est aussi le répertoire passé à chroot(2) avant d'exécuter les scripts d'installation du paquet, ce qui signifie que les scripts voient instdir comme un répertoire racine. La valeur par défaut est « / ».
--root=rép
Définir le répertoire racine à répertoire, ce qui définit le répertoire d'installation à « rép » et le répertoire administratif à « rép/var/lib/dpkg ».
-O, --selected-only
Traiter uniquement les paquets qui sont sélectionnés pour l'installation. La sélection réelle est effectuée avec dselect ou par dpkg, lorsqu'il traite les paquets. Par exemple, lorsqu'un paquet est supprimé, il sera marqué sélectionné pour la désinstallation.
-E, --skip-same-version
Ne pas installer le paquet si la même version et architecture du paquet est déjà installée.

Depuis dpkg 1.21.10, l'architecture est également prise en compte, ce qui permet de mettre à niveau des paquets ou d'installer des instances co-installables supplémentaires avec la même version, mais une architecture différente.

--pre-invoke=commande
--post-invoke=commande
Définir une commande de déclenchement (hook) commande à exécuter via « sh -c » avant ou après l'exécution de dpkg pour les actions unpack, configure, install, triggers-only, remove et purge (depuis dpkg 1.15.4), et les actions add-architecture et remove-architecture (depuis dpkg 1.17.19). Cette option peut être spécifiée plusieurs fois. L'ordre dans lequel les options sont spécifiées est préservé, les options provenant des fichiers de configuration ayant la priorité. La variable d'environnement DPKG_HOOK_ACTION est définie pour les hooks à l'action dpkg en cours.

Les hooks d'invocation ne sont pas exécutés lorsque --no-act est spécifié, ou lors de l'exécution en tant qu'utilisateur non root sans --force-not-root.

Note : Les frontaux peuvent appeler dpkg plusieurs fois par invocation, ce qui peut exécuter les hooks plus de fois que prévu.

--path-exclude=motif-glob
--path-include=motif-glob
Définir motif-glob comme filtre de chemin, soit en excluant, soit en ré-incluant les chemins précédemment exclus correspondant aux motifs spécifiés lors de l'installation (depuis dpkg 1.15.8).

Attention : Tenez compte du fait qu'en fonction des chemins exclus, vous pourriez complètement casser votre système, utilisez avec prudence.

Les motifs glob utilisent les mêmes jokers que ceux utilisés dans le shell, où « * » correspond à toute séquence de caractères, y compris la chaîne vide et aussi « / ». Par exemple, « /usr/*/READ* » correspond à « /usr/share/doc/package/README ». Comme d'habitude, « ? » correspond à un seul caractère (encore une fois, y compris « / »). Et « [’ commence une classe de caractères, qui peut contenir une liste de caractères, des plages et des compléments. Voir glob(7) pour des informations détaillées sur le globbing. Note : L'implémentation actuelle peut ré-inclure plus de répertoires et de liens symboliques que nécessaire, en particulier lorsqu'il y a une ré-inclusion plus spécifique, pour être sûr et éviter d'éventuels échecs de dépaquetage ; des travaux futurs pourraient corriger cela.

Ceci peut être utilisé pour supprimer tous les chemins sauf certains particuliers ; un cas typique est :

--path-exclude=/usr/share/doc/*
--path-include=/usr/share/doc/*/copyright

pour

supprime tous les fichiers de documentation à l'exception des fichiers de copyright.

Ces deux options peuvent être spécifiées plusieurs fois et être entrelacées entre elles. Les deux sont traitées dans l'ordre donné, la dernière règle qui correspond à un nom de fichier prenant la décision.

Les filtres sont appliqués lors du dépaquetage des paquets binaires et en tant que tels n'ont connaissance que du type d'objet actuellement filtré (par exemple un fichier normal ou un répertoire) et n'ont aucune visibilité sur les objets qui suivront. Comme ces filtres ont des effets de bord (contrairement aux find(1) ), exclure un chemin exact qui est un objet répertoire comme /usr/share/doc n'aura pas le résultat désiré et seul ce chemin sera exclu (ce qui pourrait être automatiquement ré-inclu si le code le juge nécessaire). Tous les fichiers ultérieurs contenus dans ce répertoire échoueront au dépaquetage.

Astuce: assurez-vous que les motifs génériques ne sont pas développés par votre interpréteur de commandes.

--verify-format format-name
Définit le format de sortie pour la commande --verify (depuis dpkg 1.17.2).

Le seul format de sortie actuellement pris en charge est rpm, qui consiste en une ligne pour chaque chemin qui a échoué à une vérification. Ces lignes ont le format suivant :


missing [c] pathname [(error-message)]
?M5?????? [c] pathname

Les 9 premiers caractères sont utilisés pour rapporter le résultat des vérifications, soit le littéral missing lorsque le fichier est absent ou que ses métadonnées ne peuvent pas être récupérées, soit l'un des caractères spéciaux suivants qui rapportent le résultat pour chaque vérification :

«?»
Indique que la vérification n'a pas pu être effectuée (manque de prise en charge, permissions de fichier, etc.).
«.»
Indique que la vérification a réussi.
«A-Za-z0-9»
Indique qu'une vérification spécifique a échoué. Les positions et caractères alphanumériques suivants sont actuellement pris en charge :
1 «?»
Ces vérifications ne sont actuellement pas prises en charge, elles seront toujours «?».
2 «M»
La vérification du mode du fichier a échoué (depuis dpkg 1.21.0). Comme les métadonnées des chemins ne sont actuellement pas suivies, cette vérification ne peut être que partiellement émulée via une heuristique très simple pour les chemins qui ont une empreinte connue, ce qui implique qu'ils devraient être des fichiers réguliers, où la vérification échouera si le chemin n'est pas un fichier régulier sur le système de fichiers. Cette vérification ne réussira actuellement jamais car elle n'a pas suffisamment d'informations disponibles.
3 «5»
La vérification de l'empreinte a échoué, ce qui signifie que le contenu du fichier a changé. Ceci n'est qu'un contrôle d'intégrité et ne doit pas être considéré comme une sorte de vérification de sécurité.
4-9 «?»
Ces vérifications ne sont actuellement pas prises en charge, elles seront toujours «?».

La ligne est suivie d'une espace et d'un caractère d'attribut. Le caractère d'attribut suivant est pris en charge :

«c»
Le chemin est un fichier de configuration.

Suivi finalement d'une autre espace et du chemin.

Dans le cas où l'entrée était de type missing et que le fichier n'était pas réellement présent sur le système de fichiers, la ligne est suivie d'une espace et du message d'erreur encadré entre parenthèses.

--status-fd n
Envoie l'état du paquet et les informations de progression au format lisible par la machine vers le descripteur de fichier n. Cette option peut être spécifiée plusieurs fois. Les informations sont généralement un enregistrement par ligne, sous l'une des formes suivantes :
status: package: status
L'état du paquet a changé ; status est comme dans le fichier de statut.
status: package : error : extended-error-message
Une erreur s'est produite. Tous les sauts de ligne possibles dans extended-error-message seront convertis en espaces avant la sortie.
status: file : conffile-prompt : 'real-old' 'real-new' useredited distedited
On pose une question à l'utilisateur concernant un fichier de configuration.
processing: stage: package
Envoyé juste avant le début d'une étape de traitement. stage est l'une des valeurs suivantes : upgrade, install (toutes deux envoyées avant le dépaquetage), configure, trigproc, disappear, remove, purge.
--status-logger=command
Envoie l'état du paquet et les informations de progression au format lisible par la machine vers l'entrée standard de la commande shell command, exécutée via « sh -c » (depuis dpkg 1.16.0). Cette option peut être spécifiée plusieurs fois. Le format de sortie utilisé est le même que pour --status-fd.

Les enregistreurs d'état ne sont pas exécutés lorsque --no-act est spécifié, ou lorsqu'on s'exécute en tant que non-root sans --force-not-root.

--log=filename
Journalise les mises à jour de changement d'état et les actions dans filename, au lieu du fichier par défaut /var/log/dpkg.log. Si cette option est donnée plusieurs fois, le dernier nom de fichier est utilisé. Les messages de journal ont la forme :
AAAA-MM-JJ HH:MM:SS startup type command
Pour chaque invocation de dpkg où type est archives (avec une command de unpack ou install) ou packages (avec une command de configure, triggers-only, remove ou purge).
AAAA-MM-JJ HH:MM:SS status state pkg installed-version
Pour les mises à jour de changement d'état.
AAAA-MM-JJ HH:MM:SS action pkg installed-version available-version
Pour les actions où action est l'une des valeurs suivantes : install, upgrade, configure, trigproc, disappear, remove ou purge.
AAAA-MM-JJ HH:MM:SS conffile filename decision
Pour les changements de fichiers de configuration où decision est soit install soit keep.
--robot
Utilise un format de sortie lisible par la machine. Cela fournit une interface pour les programmes qui doivent analyser la sortie de certaines commandes qui n'émettent pas autrement un format de sortie lisible par la machine. Aucune localisation ne sera utilisée et la sortie sera modifiée pour la rendre plus facile à analyser.

La seule commande actuellement prise en charge est --version.

--no-pager
Désactive l'utilisation de tout afficheur lors de l'affichage d'informations (depuis dpkg 1.19.2).
--no-debsig
N'essaie pas de vérifier les signatures des paquets.
--no-triggers
N'exécute aucun déclencheur dans cette exécution (depuis dpkg 1.14.17), mais les activations seront toujours enregistrées. S'il est utilisé avec --configure package ou --triggers-only package alors le postinst du paquet nommé sera toujours exécuté même si seule une exécution de déclencheurs est nécessaire. L'utilisation de cette option peut laisser des paquets dans les états inappropriés triggers-awaited et triggers-pending . Cela peut être corrigé plus tard en exécutant : dpkg --configure --pending.
--triggers
Annule un --no-triggers précédent (depuis dpkg 1.14.17).

CODE DE SORTIE

0
L'action demandée a été effectuée avec succès. Ou une commande de vérification ou d'assertion a renvoyé vrai.
1
Une commande de vérification ou d'assertion a renvoyé faux.
2
Erreur fatale ou irrécupérable due à une utilisation invalide de la ligne de commande, ou à des interactions avec le système, comme des accès à la base de données, des allocations de mémoire, etc.

ENVIRONNEMENT

Environnement externe

PATH
Cette variable est censée être définie dans l'environnement et pointer vers les chemins du système où plusieurs programmes requis doivent être trouvés. Si elle n'est pas définie ou si les programmes ne sont pas trouvés, dpkg s'interrompra.
HOME
Si définie, dpkg l'utilisera comme le répertoire à partir duquel lire le fichier de configuration spécifique à l'utilisateur.
TMPDIR
Si définie, dpkg l'utilisera comme le répertoire dans lequel créer des fichiers et répertoires temporaires.
SHELL
Le programme dpkg exécutera lors du démarrage d'un nouvel interpréteur de commandes interactif, ou lors de la création d'une commande via un interpréteur.
PAGER
DPKG_PAGER
Le programme dpkg exécutera lors de l'exécution d'un afficheur, qui sera exécuté avec «$SHELL -c», par exemple lors de l'affichage des différences entre fichiers de configuration. Si SHELL n'est pas définie, «sh» sera utilisé à la place.

La variable DPKG_PAGER remplace la variable d'environnement PAGER (depuis dpkg 1.19.2). Si aucun des programmes pointés par DPKG_PAGER ou PAGER n'est présent, les programmes suivants seront essayés dans l'ordre (depuis dpkg 1.22.12) : l'afficheur par défaut more, puis less, more, et enfin cat.

DPKG_COLORS
Définit le mode de couleur (depuis dpkg 1.18.5). Les valeurs actuellement acceptées sont : auto (par défaut), always et never.
DPKG_NLS
Si défini, il sera utilisé pour décider d'activer la prise en charge de la langue native, aussi connue sous le nom de prise en charge de l'internationalisation (ou i18n) (depuis dpkg 1.22.7). Les valeurs acceptées sont : 0 et 1 (par défaut).
DPKG_DEBUG
Définit le masque de débogage (depuis dpkg 1.21.10) à partir d'une valeur octale. Les indicateurs actuellement acceptés sont décrits dans l'option --debug .
DPKG_FORCE
Définit les indicateurs de force (depuis dpkg 1.19.5). Lorsque cette variable est présente, aucun réglage par défaut de force intégré ne sera appliqué. Si la variable est présente mais vide, tous les indicateurs de force seront désactivés.
DPKG_ADMINDIR
Si défini et que les options --admindir ou --root n'ont pas été spécifiées, il sera utilisé comme répertoire administratif de dpkg (depuis dpkg 1.20.0).
DPKG_FRONTEND_LOCKED
Défini par une interface de gestionnaire de paquets pour informer dpkg qu'il ne doit pas acquérir le verrou de l'interface (depuis dpkg 1.19.1).
DPKG_PATH_PASSWD
Définit le chemin d'accès pour le fichier système passwd . Ce chemin est relatif au répertoire --root . La valeur par défaut est /etc/passwd.

Depuis dpkg 1.22.16.

DPKG_PATH_GROUP
Définit le chemin d'accès pour le fichier système group . Ce chemin est relatif au répertoire --root . La valeur par défaut est /etc/group.

Depuis dpkg 1.22.16.

Environnement interne

LESS
Défini par dpkg à «-FRSXMQ», s'il n'est pas déjà défini, lors de l'appel d'un afficheur (depuis dpkg 1.19.2). Pour changer le comportement par défaut, cette variable peut être prédéfinie à une autre valeur, y compris une chaîne vide, ou les variables PAGER ou DPKG_PAGER peuvent être définies pour désactiver des options spécifiques avec «-+», par exemple DPKG_PAGER="less -+F".
DPKG_ROOT
Défini par dpkg dans l'environnement des scripts de maintien pour indiquer sur quelle installation agir (depuis dpkg 1.18.5). DPKG_ADMINDIR
Défini par dpkg dans l'environnement des scripts de maintien pour indiquer le répertoire dpkg administratif à utiliser (depuis dpkg 1.16.0). Cette variable est toujours définie à la valeur actuelle de --admindir .

DPKG_MAINTSCRIPT_PACKAGE

Fichiers de configuration fragmentaire (depuis dpkg 1.15.4).
/etc/dpkg/dpkg.cfg
Fichier de configuration avec les options par défaut.

Fichier journal par défaut (voir /etc/dpkg/dpkg.cfg et l'option --log).

Les autres fichiers listés ci-dessous se trouvent dans leurs répertoires par défaut, voir l'option --admindir pour savoir comment changer l'emplacement de ces fichiers.

Liste des paquets disponibles.
/var/lib/dpkg/status
États des paquets disponibles. Ce fichier contient des informations sur le fait qu'un paquet est marqué pour suppression ou non, s'il est installé ou non, etc. Voir la section « INFORMATIONS SUR LES PAQUETS » pour plus de détails.

Le format et le contenu d'un paquet binaire sont décrits dans deb(5).

Noms de fichiers du système de fichiers

Lors du dépaquetage et de la configuration, dpkg utilise divers noms de fichiers à des fins de sauvegarde et de retour arrière. La explication suivante est une version simplifiée de la façon dont ces noms de fichiers sont utilisés lors de l'installation d'un paquet.

*.dpkg-new
Lors du dépaquetage, dpkg extrait les nouveaux objets du système de fichiers dans chemin.dpkg-new (sauf pour les répertoires existants ou les liens symboliques vers des répertoires qui sont ignorés), une fois cela fait et après avoir effectué les sauvegardes des anciens objets, les objets sont renommés en chemin.
*.dpkg-tmp
Lors du dépaquetage, dpkg effectue des sauvegardes des anciens objets du système de fichiers dans chemin.dpkg-tmp après avoir extrait les nouveaux objets. Ces sauvegardes sont effectuées soit par un renommage pour les répertoires (mais seulement s'ils changent de type de fichier), une nouvelle copie de lien symbolique pour les liens symboliques, ou un lien physique pour tout autre objet du système de fichiers, sauf pour les fichiers de configuration qui ne sont pas sauvegardés car ils sont traités à un stade ultérieur.

En cas de nécessité de retour arrière, ces sauvegardes sont utilisées pour restaurer le contenu précédent des objets. Elles sont supprimées automatiquement une fois l'installation terminée.

*.dpkg-old
Lors de la configuration, lors de l'installation d'une nouvelle version, dpkg peut effectuer une sauvegarde de l'ancien fichier de configuration modifié dans chemin.dpkg-old.
*.dpkg-dist
Lors de la configuration, lors de la conservation de l'ancienne version, dpkg peut effectuer une sauvegarde du nouveau fichier de configuration non modifié dans chemin.dpkg-dist.

SÉCURITÉ

Toute opération nécessitant un accès en écriture à la base de données ou au système de fichiers est considérée comme une opération privilégiée qui pourrait permettre une escalade de privilèges vers root. Ces opérations ne doivent jamais être déléguées à un utilisateur non fiable ni effectuées sur des paquets non fiables, car cela pourrait permettre un accès root au système.

Certaines opérations (comme la vérification des paquets) pourraient nécessiter les privilèges root pour pouvoir accéder à des fichiers sur le système de fichiers qui seraient autrement inaccessibles en raison de permissions restreintes, mais devraient autrement fonctionner normalement et produire des messages appropriés dans ces cas.

Les opérations d'interrogation ne devraient jamais nécessiter root, et déléguer leur exécution à des utilisateurs non privilégiés via une commande de gain de privilèges root peut avoir des implications de sécurité (comme l'escalade de privilèges), par exemple lorsqu'un afficheur est invoqué automatiquement par l'outil.

Voir aussi la section SÉCURITÉ des pages de manuel dpkg-deb(1) et dpkg-split(1) .

BOGUES

--no-act donne généralement moins d'informations que ce qui pourrait être utile.

EXEMPLES

Pour lister les paquets installés liés à l'éditeur vi(1) (notez que dpkg-query ne charge plus le fichier available par défaut, et l'option dpkg-query --load-avail doit être utilisée à la place pour cela) :

dpkg -l '*vi*'

Pour voir les entrées dans /var/lib/dpkg/available de deux paquets :

dpkg --print-avail vim neovim | less

Pour rechercher vous-même dans la liste des paquets :

dpkg --print-avail | less

Pour supprimer un paquet neovim installé :

dpkg -r neovim

Pour installer un paquet, vous devez d'abord le trouver dans une archive ou un support physique. Lors de l'utilisation d'une archive basée sur une structure de pool, connaître la zone de l'archive et le nom du paquet suffit pour en déduire le chemin :

dpkg -i /media/bdrom/pool/main/v/vim/vim_9.0.2018-1_amd64.deb

Pour faire une copie locale des états de sélection des paquets :

dpkg --get-selections >myselections

Vous pouvez transférer ce fichier sur un autre ordinateur, et après avoir mis à jour le fichier available sur celui-ci avec votre interface de gestionnaire de paquets de votre choix (voir https://wiki.debian.org/Teams/Dpkg/FAQ#set-selections pour plus de détails), par exemple :

apt-cache dumpavail | dpkg --merge-avail

vous pouvez l'installer avec :

dpkg --clear-selections
dpkg --set-selections <myselections

Notez que cela n'installera ni ne supprimera réellement quoi que ce soit, mais définira simplement l'état de sélection des paquets demandés. Vous aurez besoin d'une autre application pour réellement télécharger et installer les paquets demandés. Par exemple, exécutez apt-get dselect-upgrade.

Habituellement, vous constaterez que dselect(1) fournit un moyen plus pratique de modifier les états de sélection des paquets.
