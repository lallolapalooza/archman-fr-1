NOM

dpkg-source - Outil de manipulation des paquets source Debian (.dsc)

SYNOPSIS

dpkg-source [option...] commande

DESCRIPTION

dpkg-source compresse et décompresse les archives source Debian.

Aucune de ces commandes ne permet de combiner plusieurs options en une seule, et elles ne permettent pas de spécifier la valeur d'une option dans un argument séparé.

COMMANDES

-x, --extract fichier.dsc [répertoire-de-sortie]
Extraire un paquet source (--extract depuis dpkg 1.17.14). Un argument non-option doit être fourni, le nom du fichier de contrôle source Debian (.dsc). Un deuxième argument non-option facultatif peut être fourni pour spécifier le répertoire dans lequel extraire le paquet source, celui-ci ne doit pas exister. Si aucun répertoire de sortie n'est spécifié, le paquet source est extrait dans un répertoire nommé source-version sous le répertoire de travail courant.

dpkg-source lira les noms des autres fichiers composant le paquet source à partir du fichier de contrôle ; ils sont supposés se trouver dans le même répertoire que le .dsc.

Les fichiers dans le paquet extrait auront leurs permissions et propriétés définies sur celles qui auraient été attendues si les fichiers et répertoires avaient simplement été créés - les répertoires et fichiers exécutables seront 0777 et les fichiers ordinaires seront 0666, tous deux modifiés par le umask de l'extracteur ; si le répertoire parent est setgid, alors les répertoires extraits le seront aussi, et tous les fichiers et répertoires hériteront de sa propriété de groupe.

Si le paquet source utilise un format non standard (actuellement cela signifie tous les formats sauf « 1.0 »), son nom sera stocké dans debian/source/format afin que les compilations suivantes du paquet source utilisent le même format par défaut.

-b, --build répertoire [paramètres-spécifiques-au-format]
Compiler un paquet source (--build depuis dpkg 1.17.14). Le premier argument non-option est considéré comme le nom du répertoire contenant l'arborescence source debianisée (c'est-à-dire avec un sous-répertoire debian et éventuellement des modifications des fichiers originaux). Selon le format du paquet source utilisé pour compiler le paquet, des paramètres supplémentaires peuvent être acceptés.

dpkg-source compilera le paquet source avec le premier format trouvé dans cette liste ordonnée : le format indiqué avec l'option de ligne de commande --format , le format indiqué dans debian/source/format, « 1.0 ». Le repli sur « 1.0 » est obsolète et sera supprimé à un moment donné dans le futur, vous devriez toujours documenter le format source souhaité dans debian/source/format. Voir la section « FORMATS DES PAQUETS SOURCE » pour une description détaillée des différents formats de paquets source.

--print-format répertoire
Afficher le format source qui serait utilisé pour compiler le paquet source si dpkg-source --build répertoire était appelé (dans les mêmes conditions et avec les mêmes paramètres ; depuis dpkg 1.15.5).
--before-build répertoire
Exécuter le crochet correspondant du format du paquet source (depuis dpkg 1.15.8). Ce crochet est appelé avant toute compilation du paquet (dpkg-buildpackage l'appelle très tôt, même avant debian/rules clean). Cette commande est idempotente et peut être appelée plusieurs fois. Tous les formats source n'implémentent pas quelque chose dans ce crochet, et ceux qui le font préparent généralement l'arborescence source pour la compilation, par exemple en s'assurant que les correctifs Debian sont appliqués.
--after-build répertoire
Exécuter le crochet correspondant du format du paquet source (depuis dpkg 1.15.8). Ce crochet est appelé après toute compilation du paquet (dpkg-buildpackage l'appelle en dernier). Cette commande est idempotente et peut être appelée plusieurs fois. Tous les formats source n'implémentent pas quelque chose dans ce crochet, et ceux qui le font l'utilisent généralement pour annuler ce que --before-build a fait.
--commit [répertoire] ...
Enregistrer les modifications dans l'arborescence source décompressée dans répertoire (depuis dpkg 1.16.1). Cette commande peut prendre des paramètres supplémentaires selon le format source. Elle échouera pour les formats où cette opération n'a pas de sens.
-?, --help
Afficher le message d'utilisation et quitter. Les options de compilation et d'extraction spécifiques au format peuvent être affichées en utilisant l'option --format .
--version
Afficher la version et quitter.

OPTIONS

Options de compilation génériques

-cfichier-de-contrôle
Spécifie le fichier de contrôle source principal à partir duquel lire les informations. La valeur par défaut est debian/control. Si spécifié avec un chemin relatif, celui-ci est interprété à partir du répertoire de premier niveau de l'arborescence source.
-lfichier-changelog
Spécifie le fichier changelog à partir duquel lire les informations. La valeur par défaut est debian/changelog. Si spécifié avec un chemin relatif, celui-ci est interprété à partir du répertoire de premier niveau de l'arborescence source.
-Fformat-changelog
Spécifie le format du changelog. Voir dpkg-parsechangelog(1) pour des informations sur les formats alternatifs.
--format=valeur
Utiliser le format donné pour compiler le paquet source (depuis dpkg 1.14.17). Cela remplace tout format donné dans debian/source/format.
-Vnom=valeur
Définir une variable de substitution de sortie. Voir deb-substvars(5) pour une discussion sur la substitution de sortie.
-Tfichier-substvars
Lire les variables de substitution dans fichier-substvars; par défaut, aucun fichier n'est lu. Cette option peut être utilisée plusieurs fois pour lire des variables de substitution depuis plusieurs fichiers (depuis dpkg 1.15.6).
-Dchamp=valeur
Remplacer ou ajouter un champ du fichier de contrôle de sortie.
-Uchamp
Supprimer un champ du fichier de contrôle de sortie.
-Zcompression, --compression=compression
Spécifier la compression à utiliser pour les fichiers tar et les fichiers diff créés (--compression depuis dpkg 1.15.5). Notez que cette option ne provoquera pas la recompression des fichiers tar existants, elle n'affecte que les nouveaux fichiers. Les valeurs prises en charge sont : gzip, bzip2, lzma et xz. La valeur par défaut est xz pour les formats 2.0 et plus récents, et gzip pour le format 1.0. xz n'est pris en charge que depuis dpkg 1.15.5.
-zniveau, --compression-level=niveau
Niveau de compression à utiliser (--compression-level depuis dpkg 1.15.5). Comme avec -Z cela n'affecte que les fichiers nouvellement créés. Les valeurs prises en charge sont : 1 à 9, best, et fast. La valeur par défaut est 9 pour gzip et bzip2, 6 pour xz et lzma.
-i[expression-régulière], --diff-ignore[=expression-régulière]
Vous pouvez spécifier une expression régulière perl pour faire correspondre les fichiers que vous voulez filtrer de la liste des fichiers pour le diff (--diff-ignore depuis dpkg 1.15.6). (Cette liste est générée par une commande find.) (Si le paquet source est compilé en tant que paquet source de version 3 à l'aide d'un VCS, cela peut être utilisé pour ignorer les modifications non committées sur des fichiers spécifiques. L'utilisation de -i.* ignorera toutes ces modifications.)

L'option -i par elle-même active ce réglage avec une expression régulière par défaut (préservant toute modification de l'expression régulière par défaut effectuée par une utilisation précédente de --extend-diff-ignore) qui filtrera les fichiers de contrôle et les répertoires des systèmes de contrôle de révision les plus courants systèmes, fichiers de sauvegarde et d'échange (swap) et répertoires de sortie de compilation de Libtool. Il ne peut y avoir qu'une seule expression régulière active ; parmi plusieurs options -i, seule la dernière prendra effet.

Ceci est très utile pour éliminer les fichiers superflus qui sont inclus dans la différence, par exemple si vous maintenez votre source dans un système de contrôle de révision et souhaitez utiliser un checkout pour construire un paquet source sans inclure les fichiers et répertoires supplémentaires qu'il contiendra habituellement (par exemple CVS/, .cvsignore, .svn/). L'expression régulière par défaut est déjà très exhaustive, mais si vous avez besoin de la remplacer, veuillez noter qu'elle peut, par défaut, correspondre à n'importe quelle partie d'un chemin, donc si vous souhaitez correspondre au début d'un nom de fichier ou uniquement à des noms de fichiers complets, vous devrez fournir vous-même les ancres nécessaires (par exemple ‘(^|/)’, ‘($|/)’).

--extend-diff-ignore=regex
L'expression régulière Perl spécifiée étendra la valeur par défaut utilisée par --diff-ignore et sa valeur actuelle, si elle est définie (depuis dpkg 1.15.6). Elle le fait en concaténant “|regex” à la valeur existante. Cette option est pratique à utiliser dans debian/source/options pour exclure certains fichiers auto-générés de la génération automatique de patchs.
-I[modèle-fichier], --tar-ignore[=modèle-fichier]
Si cette option est spécifiée, le modèle sera passé à l'option --exclude de tar(1) lorsqu'elle sera appelée pour générer un fichier .orig.tar ou .tar (--tar-ignore depuis dpkg 1.15.6). Par exemple, -ICVS fera ignorer les répertoires CVS à tar lors de la génération d'un fichier .tar.gz. L'option peut être répétée plusieurs fois pour lister plusieurs modèles à exclure.

-I par elle-même ajoute des options --exclude par défaut qui filtreront les fichiers et répertoires de contrôle des systèmes de contrôle de révision les plus courants, les fichiers de sauvegarde et d'échange (swap) et les répertoires de sortie de compilation de Libtool.

Note : Bien qu'ayant des objectifs similaires, -i et -I ont des syntaxes et des sémantiques très différentes. -i ne peut être spécifié qu'une fois et prend une expression régulière compatible Perl qui est mise en correspondance avec le chemin relatif complet de chaque fichier. -I peut être spécifié plusieurs fois et prend un modèle de nom de fichier avec des jokers de shell. Le modèle est appliqué au chemin relatif complet mais aussi à chaque partie du chemin individuellement. La sémantique exacte de l'option --exclude de tar est quelque peu compliquée, voir https://www.gnu.org/software/tar/manual/tar.html#wildcards pour une documentation complète.

L'expression régulière et les modèles par défaut pour les deux options peuvent être vus dans la sortie de la commande --help.

Options génériques d'extraction

--no-copy
Ne pas copier les tarballs originaux près du paquet source extrait (depuis dpkg 1.14.17).
--no-check
Ne pas vérifier les signatures et les sommes de contrôle avant le dépaquetage (depuis dpkg 1.14.17).
--no-overwrite-dir
Ne pas écraser le répertoire d'extraction s'il existe déjà (depuis dpkg 1.18.8).
--require-valid-signature
Refuser de dépaqueter le paquet source s'il ne contient pas une signature OpenPGP qui peut être vérifiée (depuis dpkg 1.15.0) soit avec la keyring trustedkeys.gpg de l'utilisateur, l'une des keyrings spécifiques au vendeur, ou l'une des keyrings officielles Debian (/usr/share/keyrings/debian-keyring.gpg, /usr/share/keyrings/debian-nonupload.gpg et /usr/share/keyrings/debian-maintainers.gpg).
--require-strong-checksums
Refuser de dépaqueter le paquet source s'il ne contient pas de sommes de contrôle fortes (depuis dpkg 1.18.7). Actuellement, la seule somme de contrôle considérée comme forte est SHA-256.
--ignore-bad-version
Transformer la vérification de mauvaise version du paquet source en un avertissement non fatal (depuis dpkg 1.17.7). Cette option ne devrait être nécessaire que lors de l'extraction d'anciens paquets sources avec des versions incorrectes, uniquement pour la compatibilité ascendante.

Options générales

--threads-max=threads
Définit le nombre maximum de threads autorisés pour les compresseurs qui supportent les opérations multi-threadées (depuis dpkg 1.21.14).
-q
Active le mode silencieux pour supprimer les avertissements.

FORMATS DE PAQUETS SOURCE

Si vous ne savez pas quel format de source utiliser, vous devriez probablement choisir soit “3.0 (quilt)” soit “3.0 (natif)”. Voir https://wiki.debian.org/Projects/DebSrc3.0 pour des informations sur le déploiement de ces formats au sein de Debian.

Format : 1.0

Un paquet source dans ce format consiste soit en un .orig.tar.gz associé à un .diff.gz soit en un seul .tar.gz (dans ce cas, le paquet est dit natif). Optionnellement, le tarball original peut être accompagné d'une signature amont détachée .orig.tar.gz.asc, dont l'extraction est supportée depuis dpkg 1.18.5.

Extraction

L'extraction d'un paquet natif est une simple extraction du tarball unique dans le répertoire cible. L'extraction d'un paquet non natif se fait en décompressant d'abord le .orig.tar.gz, puis en appliquant le patch contenu dans le fichier .diff.gz. L'horodatage de tous les fichiers patchés est remis à l'heure d'extraction du paquet source (cela évite les décalages d'horodatage qui causent des problèmes lorsque des fichiers auto-générés sont patchés). Le diff peut créer de nouveaux fichiers (tout le répertoire debian est créé de cette manière) mais ne peut pas supprimer de fichiers (des fichiers vides subsisteront) et ne peut pas créer ou modifier de liens symboliques.

Construction

La construction d'un paquet natif consiste simplement à créer un tarball unique avec le répertoire source. La construction d'un paquet non natif implique d'extraire le tarball original dans un répertoire “.orig” séparé et de régénérer le .diff.gz en comparant le répertoire du paquet source avec le répertoire .orig.

Options de construction (avec --build) :

Si un deuxième argument sans option est fourni, il doit être le nom du répertoire source original ou du fichier tar, ou la chaîne vide si le paquet est spécifique à Debian et n'a donc pas de diffs de départementalisation. Si aucun deuxième argument n'est fourni, dpkg-source recherchera le fichier tar source original package_version-amont.orig.tar.gz ou le répertoire source original directory.orig en fonction des arguments -sX.

-sa, -sp, -sk, -su et -sr n'écraseront pas les fichiers tar ou les répertoires existants. Si cela est souhaité, -sA, -sP, -sK, -sU et -sR devraient être utilisés à la place.

-sk
Spécifie de s'attendre à la source originale sous forme de fichier tar, par défaut package_version-amont.orig.tar.extension. Il laissera cette source originale en place sous forme de fichier tar, ou la copiera dans le répertoire courant si elle n'y est pas déjà. Le tarball sera décompressé dans directory.orig pour la génération du diff.
-sp
Comme -sk mais supprimera le répertoire par la suite.
-su
Spécifie que la source originale est attendue sous forme de répertoire, par défaut package-version-amont.orig et dpkg-source créera une nouvelle archive source originale à partir de celui-ci.
-sr
Comme -su mais supprimera ce répertoire après son utilisation.
-ss
Spécifie que la source originale est disponible à la fois sous forme de répertoire et de fichier tar. dpkg-source utilisera le répertoire pour créer le diff, mais le fichier tar pour créer le .dsc. Cette option doit être utilisée avec précaution - si le répertoire et le fichier tar ne correspondent pas, une archive source incorrecte sera générée.
-sn
Spécifie de ne pas rechercher de source originale et de ne pas générer de diff. Le deuxième argument, s'il est fourni, doit être la chaîne vide. Ceci est utilisé pour les paquets spécifiques à Debian qui n'ont pas de source amont séparée et donc pas de diffs de départementalisation.
-sa ou -sA
Spécifie de rechercher l'archive source originale sous forme de fichier tar ou de répertoire - le deuxième argument, s'il y en a un, peut être l'un ou l'autre, ou la chaîne vide (ce qui équivaut à utiliser -sn). Si un fichier tar est trouvé, il le décompressera pour créer le diff et le supprimera ensuite (ce qui équivaut à -sp) ; si un répertoire est trouvé, il le compressera pour créer la source originale et le supprimera ensuite (ce qui équivaut à -sr) ; si aucun des deux n'est trouvé, il supposera que le paquet n'a pas de diffs de départementalisation, seulement une archive source directe (ce qui équivaut à -sn). Si les deux sont trouvés, dpkg-source ignorera le répertoire, en l'écrasant, si -sA a été spécifié (ce qui équivaut à -sP) ou lèvera une erreur si -sa a été spécifié. -sa est la valeur par défaut.
--abort-on-upstream-changes
Le processus échoue si le diff généré contient des modifications apportées à des fichiers en dehors du sous-répertoire debian (depuis dpkg 1.15.8). Cette option n'est pas autorisée dans debian/source/options mais peut être utilisée dans debian/source/local-options.

Format: 3.0 (custom)

Pris en charge depuis dpkg 1.14.17. Ce format est spécial. Il ne représente pas un véritable format de paquet source, mais peut être utilisé pour créer des paquets sources avec des fichiers arbitraires.

Options de construction

Tous les arguments non-options sont considérés comme des fichiers à intégrer dans le paquet source généré. Ils doivent exister et sont de préférence dans le répertoire courant. Au moins un fichier doit être fourni.

--target-format=valeur
Requis. Définit le format réel du paquet source généré. Le fichier .dsc généré contiendra cette valeur dans son champ Format et non « 3.0 (custom) ».

Format: 3.0 (git)

Pris en charge depuis dpkg 1.14.17. Ce format est expérimental.

Un paquet source dans ce format consiste en un seul paquet d'un dépôt git .git pour contenir la source d'un paquet. Il peut également y avoir un fichier .gitshallow listant les révisions pour un clone git superficiel.

Extraction

Le paquet est cloné comme un dépôt git dans le répertoire cible. S'il y a un fichier gitshallow, il est installé comme .git/shallow à l'intérieur du dépôt git cloné.

Notez que par défaut, le nouveau dépôt aura la même branche extraite que celle qui était extraite dans la source d'origine. (Typiquement « main », mais cela pourrait être autre chose.) Toutes les autres branches seront disponibles sous remotes/origin/.

Construction

Avant d'aller plus loin, certaines vérifications sont effectuées pour s'assurer que nous n'avons aucun changement non ignoré et non validé.

git-bundle(1) est utilisé pour générer un paquet du dépôt git. Par défaut, toutes les branches et étiquettes du dépôt sont incluses dans le paquet.

Options de construction

--git-ref=ref
Permet de spécifier une référence git à inclure dans le paquet git. L'utilisation désactive le comportement par défaut d'inclusion de toutes les branches et étiquettes. Peut être spécifié plusieurs fois. Le ref peut être le nom d'une branche ou d'une étiquette à inclure. Il peut également s'agir de n'importe quel paramètre pouvant être passé à git-rev-list(1). Par exemple, pour inclure uniquement la branche principale, utilisez --git-ref=main. Pour inclure toutes les étiquettes et branches, à l'exception de la branche privée, utilisez --git-ref=--all --git-ref=^private
--git-depth=nombre
Crée un clone superficiel avec un historique tronqué au nombre spécifié de révisions.

Format: 3.0 (bzr)

Pris en charge depuis dpkg 1.14.17. Ce format est expérimental. Il génère une seule tarball contenant le dépôt bzr.

Extraction

La tarball est décompressée, puis bzr est utilisé pour extraire la branche courante.

Construction

Ensuite, la partie spécifique au VCS du répertoire source est copiée dans un répertoire temporaire. Avant que ce répertoire temporaire ne soit empaqueté dans une tarball, divers nettoyages sont effectués pour économiser de l'espace.

DIAGNOSTICS

aucun format source spécifié dans debian/source/format

Le fichier debian/source/format doit toujours exister et indiquer le format source souhaité. Par souci de compatibilité ascendante, le format « 1.0 » est supposé lorsque le fichier n'existe pas, mais vous ne devriez pas vous y fier : à l'avenir, dpkg-source sera modifié pour échouer lorsque ce fichier n'existe pas.

La raison est que le format « 1.0 » n'est plus le format recommandé, vous devriez généralement choisir l'un des formats plus récents (« 3.0 (quilt) », « 3.0 (native) »), mais dpkg-source ne le fera pas automatiquement pour vous. Si vous souhaitez continuer à utiliser l'ancien format, vous devez le préciser en mettant « 1.0 » dans debian/source/format.

la diff modifie les fichiers en amont suivants

Lorsque vous utilisez le format source « 1.0 », il est généralement déconseillé de modifier directement les fichiers en amont, car les modifications finissent par être cachées et mal documentées dans le fichier .diff.gz. Vous devriez plutôt stocker vos modifications sous forme de patchs dans le répertoire debian et les appliquer au moment de la construction. Pour éviter cette complexité, vous pouvez également utiliser le format « 3.0 (quilt) » qui offre cela nativement.

impossible de représenter la modification de file

Les modifications des sources en amont sont généralement stockées avec des fichiers de patch, mais toutes les modifications ne peuvent pas être représentées par des patchs : elles ne peuvent modifier que le contenu des fichiers texte. Si vous essayez de remplacer un fichier par quelque chose d'un type différent (par exemple, remplacer un fichier ordinaire par un lien symbolique ou un répertoire), vous obtiendrez ce message d'erreur.

le nouveau fichier vide créé file ne sera pas représenté dans le diff

Les fichiers vides ne peuvent pas être créés avec des fichiers de patch. Par conséquent, cette modification n'est pas enregistrée dans le paquet source et vous êtes averti.

le mode exécutable perms de file ne sera pas représenté dans le diff

Les fichiers de patch n'enregistrent pas les permissions des fichiers et donc les permissions d'exécution ne sont pas stockées dans le paquet source. Cet avertissement vous rappelle ce fait.

le mode spécial perms de file ne sera pas représenté dans le diff

Les fichiers de patch n'enregistrent pas les permissions des fichiers et donc les permissions modifiées ne sont pas stockées dans le paquet source. Cet avertissement vous rappelle ce fait.

FICHIERS

debian/source/format

Ce fichier contient sur une seule ligne le format qui doit être utilisé pour construire le paquet source (les formats possibles sont décrits ci-dessus). Aucun espace de début ou de fin n'est autorisé.

debian/source/include-binaries

Ce fichier contient une liste de chemins de fichiers binaires (un par ligne) relatifs au répertoire racine de la source qui doivent être inclus dans le tarball debian. Les espaces de début et de fin sont supprimés. Les lignes commençant par «#» sont des commentaires et sont ignorées. Les lignes vides sont ignorées.

debian/source/options

Ce fichier contient une liste d'options longues qui doivent être automatiquement ajoutées en tête de l'ensemble des options de ligne de commande d'un appel à dpkg-source --build ou dpkg-source --print-format . Des options comme --compression et --compression-level conviennent bien à ce fichier.

Chaque option doit être placée sur une ligne séparée. Les lignes vides et les lignes commençant par «#» sont ignorées. Le «--» initial doit être supprimé et les options courtes ne sont pas autorisées. Des espaces optionnels sont autorisés autour du symbole «=» et des guillemets optionnels sont autorisés autour de la valeur. Voici un exemple de tel fichier :

# let dpkg-source create a debian.tar.bz2 with maximal compression
compression = "bzip2"
compression-level = 9
# use debian/patches/debian-changes as automatic patch
single-debian-patch
# ignore changes on config.{sub,guess}
extend-diff-ignore = "(^|/)(config.sub|config.guess)$"

Remarque: format les options ne sont pas acceptées dans ce fichier, vous devriez plutôt utiliser debian/source/format .

debian/source/local-options

Exactement comme debian/source/options sauf que le fichier n'est pas inclus dans le paquet source généré. Il peut être utile pour stocker une préférence liée au mainteneur ou au dépôt VCS où le paquet source est maintenu.

debian/source/local-patch-header

debian/source/patch-header

Texte en forme libre qui est placé en tête du correctif généré automatiquement dans les formats « 2.0 » ou « 3.0 (quilt) ». local-patch-header n'est pas inclus dans le paquet source généré, tandis que patch-header l'est.

debian/patches/fournisseur.series

debian/patches/series

Ce fichier liste tous les correctifs qui doivent être appliqués (dans l'ordre donné) par-dessus le paquet source amont. Les espaces de début et de fin sont supprimés. Le fournisseur sera le nom en minuscules du fournisseur actuel, ou debian s'il n'y a pas de fournisseur défini. Si le fichier series spécifique au fournisseur n'existe pas, le fichier series sans fournisseur sera utilisé. Les lignes commençant par «#» sont des commentaires et sont ignorées. Les lignes vides sont ignorées. Les lignes restantes commencent par un nom de fichier de correctif (relatif au répertoire debian/patches/ ) jusqu'au premier caractère espace ou à la fin de la ligne. Des options quilt facultatives peuvent suivre jusqu'à la fin de la ligne ou jusqu'au premier «#» précédé d'un ou plusieurs espaces (ce qui marque le début d'un commentaire jusqu'à la fin de la ligne).

SÉCURITÉ

L'examen de paquets sources non fiables ou leur extraction dans des répertoires de travail temporaire doit être considéré comme une frontière de sécurité, et toute violation de cette frontière provenant de ces opérations doit être considérée comme une vulnérabilité de sécurité. Mais la gestion de paquets sources non fiables ne doit pas être prise à la légère, car la surface d'attaque inclut toutes les commandes de compression prises en charge, les commandes pour gérer des formats de données spécifiques (comme tar(1) ou patch(1)) en plus des formats de paquets sources et des fichiers de contrôle eux-mêmes. Effectuer ces opérations sur des données non fiables en tant que root est fortement déconseillé.

La construction de paquets sources ne doit être effectuée que sur des données fiables.

BOGUES

Le moment où se produit la surcharge des champs par rapport à certains paramètres de sortie standard est plutôt confus.
