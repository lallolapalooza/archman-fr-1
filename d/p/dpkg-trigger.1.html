NOM

dpkg-trigger - utilitaire de déclenchement de paquet

SYNTAXE

dpkg-trigger [option...] nom-déclencheur

dpkg-trigger [option...] commande

DESCRIPTION

dpkg-trigger est un outil permettant d'activer explicitement des déclencheurs et de vérifier leur support sur le dpkg en cours d'exécution.

Il peut être utilisé par les scripts de mainteneur dans des situations complexes et conditionnelles où les déclencheurs basés sur les fichiers, ou la directive déclarative activate du fichier de contrôle, sont insuffisamment riches. Il peut également être utilisé pour les tests et par les administrateurs système (mais notez que les déclencheurs ne seront pas réellement exécutés par dpkg-trigger).

Les syntaxes de nom de déclencheur non reconnues sont une erreur pour dpkg-trigger.

Ce programme a été introduit dans dpkg 1.14.17.

COMMANDES

--check-supported
Vérifie si le dpkg en cours d'exécution supporte les déclencheurs (généralement appelé depuis un postinst). Se terminera avec 0 si un dpkg capable de gérer les déclencheurs s'est exécuté, ou avec 1 accompagné d'un message d'erreur sur stderr sinon. Normalement, cependant, il est préférable d'activer simplement le déclencheur souhaité avec dpkg-trigger.
-?, --help
Affiche le message d'utilisation et quitte.
--version
Affiche la version et quitte.

OPTIONS

--admindir=dir
Change l'emplacement de la base de données de dpkg. Par défaut /var/lib/dpkg si DPKG_ADMINDIR n'a pas été défini.
--root=directory
Définit le répertoire racine à directory, ce qui définit le répertoire administratif à «directory/var/lib/dpkg» (depuis dpkg 1.21.0).
--by-package=paquet
Remplace le demandeur de déclencheur (normalement défini par dpkg via la variable d'environnement DPKG_MAINTSCRIPT_PACKAGE des scripts de maintenance, nommant le paquet auquel appartient le script, et ceci sera utilisé par défaut).
--no-await
Cette option permet que le paquet appelant T (le cas échéant) n'ait pas besoin d'attendre le traitement de ce déclencheur ; les paquet(s) intéressé(s) I ne seront pas ajoutés à la liste d'attente de traitement des déclencheurs de T et le statut de T reste inchangé. T peut être considéré comme installé même si I n'a pas encore traité le déclencheur.
--await
Cette option fait l'inverse de --no-await (depuis dpkg 1.17.21). Si le paquet intéressé a déclaré une directive “noawait”, alors cette option ne sera pas effective. C'est actuellement le comportement par défaut.
--no-act
Simule l'action, ne change rien réellement.

STATUT DE SORTIE

0
L'action demandée a été effectuée avec succès. Ou une commande de vérification ou d'assertion a retourné vrai.
1
Une commande de vérification ou d'assertion a retourné faux.
2
Erreur fatale ou irrécupérable due à une utilisation invalide de la ligne de commande, ou des interactions avec le système, comme les accès à la base de données, les allocations mémoire, etc.

ENVIRONNEMENT

DPKG_ROOT
Si définie et que l'option --root n'a pas été spécifiée, elle sera utilisée comme répertoire racine du système de fichiers (depuis dpkg 1.21.0).
DPKG_ADMINDIR
Si définie et que l'option --admindir n'a pas été spécifiée, elle sera utilisée comme répertoire de données de dpkg.
DPKG_DEBUG
Définit le masque de débogage (depuis dpkg 1.21.10) à partir d'une valeur octale. Les indicateurs actuellement acceptés sont décrits dans l'option dpkg --debug, mais tous ces indicateurs n'auront peut-être pas d'effet sur ce programme.
DPKG_COLORS
Définit le mode couleur (depuis dpkg 1.18.5). Les valeurs actuellement acceptées sont : auto (par défaut), always et never.
DPKG_NLS
Si définie, elle sera utilisée pour décider d'activer ou non le support des langues nationales, également appelé internationalisation (ou i18n) (depuis dpkg 1.22.7). Les valeurs acceptées sont : 0 et 1 (par défaut).
