NOM

dpkg-architecture - définit et détermine l'architecture pour la construction de paquets

SYNTAXE

dpkg-architecture [option...] [commande]

DESCRIPTION

dpkg-architecture fournit une facilité pour déterminer et définir l'architecture de construction et l'architecture hôte pour la construction de paquets.

L'architecture de construction est toujours déterminée par la variable DEB_BUILD_ARCH si elle est définie (et si --force n'est pas spécifié) ou par un appel externe à dpkg(1), et ne peut pas être définie en ligne de commande.

Vous pouvez spécifier l'architecture hôte en fournissant une ou les deux options --host-arch et --host-type, sinon la variable DEB_HOST_ARCH est utilisée si elle est définie (et si --force n'est pas spécifié). La valeur par défaut est déterminée par un appel externe à gcc(1), ou est la même que l'architecture de construction si CC ou gcc ne sont pas disponibles. Une des options --host-arch et --host-type est suffisante, la valeur de l'autre sera définie à une valeur par défaut utilisable. En effet, il est souvent préférable de n'en spécifier qu'une, car dpkg-architecture vous avertira si votre choix ne correspond pas à la valeur par défaut.

COMMANDES

-l, --list
Affiche les variables d'environnement, une par ligne, au format VARIABLE=valeur. C'est l'action par défaut.
-e, --equal architecture
Vérifie l'égalité de l'architecture (depuis dpkg 1.13.13). Il compare l'architecture hôte Debian actuelle ou spécifiée avec architecture, pour vérifier si elles sont égales. Cette action n'étend pas les caractères génériques d'architecture. La commande se termine avec un code de sortie de 0 si correspondant, 1 si non correspondant.
-i, --is architecture-generique
Vérifie l'identité de l'architecture (depuis dpkg 1.13.13). Il compare l'architecture hôte Debian actuelle ou spécifiée avec architecture-generique après l'avoir étendue en tant que caractère générique d'architecture, pour vérifier si elles correspondent. La commande se termine avec un code de sortie de 0 si correspondant, 1 si non correspondant.
-q, --query nom-variable
Affiche la valeur d'une seule variable.
-s, --print-set
Affiche une commande d'exportation. Elle peut être utilisée pour définir les variables d'environnement en utilisant le shell POSIX ou make avec eval, en fonction du format de sortie.
-u, --print-unset
Affiche une commande similaire à --print-set mais pour annuler toutes les variables.
-c, --command chaine-commande
Exécute une chaine-commande dans un environnement où toutes les variables sont définies à la valeur déterminée.

Si la chaine-commande contient des métacaractères du shell, alors elle sera invoquée via le shell Bourne système.

-L, --list-known
Affiche une liste des noms d'architecture valides. Éventuellement restreinte par une ou plusieurs des options de correspondance --match-wildcard, --match-bits ou --match-endian (depuis dpkg 1.17.14).
-?, --help
Affiche le message d'utilisation et quitte.
--version
Affiche la version et quitte.

OPTIONS

-a, --host-arch architecture
Définit l'architecture Debian hôte.
-t, --host-type type-systeme-gnu
Définit le type système GNU hôte.
-A, --target-arch architecture
Définit l'architecture Debian cible (depuis dpkg 1.17.14).
-T, --target-type type-systeme-gnu
Définit le type système GNU cible (depuis dpkg 1.17.14).
-W, --match-wildcard architecture-generique
Restreint les architectures listées par --list-known à celles qui correspondent au caractère générique d'architecture spécifié (depuis dpkg 1.17.14).
-B, --match-bits bits-architecture
Restreint les architectures listées par --list-known à celles ayant le nombre de bits CPU spécifié (depuis dpkg 1.17.14). Soit 32 soit 64.
-E, --match-endian boutisme-architecture
Restreint les architectures listées par --list-known à celles ayant le boutisme spécifié (depuis dpkg 1.17.14). Soit little soit big.
--print-format format
Définit le format de sortie pour --print-set et --print-unset (depuis dpkg 1.20.6), à soit shell (par défaut) soit make.
-f, --force
Les valeurs définies par des variables d'environnement existantes portant le même nom que ceux utilisés par les scripts sont respectées (c'est-à-dire utilisées par dpkg-architecture), sauf si ce drapeau de force est présent. Cela permet à l'utilisateur de remplacer une valeur même lorsque l'appel à dpkg-architecture est caché dans un autre script (par exemple dpkg-buildpackage(1)).

TERMES

machine de construction
La machine sur laquelle le paquet est construit.
machine hôte
La machine pour laquelle le paquet est construit.
machine cible
La machine pour laquelle le compilateur construit, ou pour laquelle l'émulateur exécute du code. Ceci n'est nécessaire que lors de la construction d'une chaîne d'outils croisée (ou d'un émulateur), qui sera construite sur l'architecture de construction, destinée à être exécutée sur l'architecture hôte, et qui elle-même construira (ou exécutera en émulation) du code pour l'architecture cible.
architecture Debian
La chaîne d'architecture Debian, utilisée dans les paquets binaires, qui spécifie l'arborescence binaire dans un dépôt de paquets.

Exemples : i386, sparc, hurd-i386.

tuple d'architecture Debian
Un tuple d'architecture Debian est l'architecture complètement qualifiée avec tous ses composants explicites. Cela diffère des architectures Debian en ce que le composant cpu au minimum n'intègre pas l'abi. Le tuple actuel a la forme abi-libc-os-cpu.

Exemples : base-gnu-linux-amd64, eabihf-musl-linux-arm.

caractère générique d'architecture Debian
Un caractère générique d'architecture Debian est une chaîne d'architecture spéciale qui correspondra à toute architecture réelle dont elle fait partie. La forme générale est un tuple d'architecture Debian avec quatre éléments ou moins, et avec au moins un d'entre eux étant any. Les éléments manquants du tuple sont implicitement préfixés par any, et donc les paires suivantes sont équivalentes :
any-any-any-any = any
any-any-os-any = os-any
any-libc-any-any = libc-any-any

Exemples : linux-any, any-i386, hurd-any, eabi-any-any-arm, musl-any-any.

type système GNU
Une chaîne de spécification d'architecture composée de deux parties séparées par un trait d'union : CPU et système.

La partie CPU ne contient jamais de trait d'union, tandis que la partie système peut elle-même contenir un trait d'union pour séparer un noyau de son ABI général, où l'ABI général peut contenir à la fois l'exécution (comme libc) et l'exé

spécificateurs ABI de la table, joints sans

tiret.

Exemples : i586-linux-gnu, sparc-

linux-gnu, i686-gnu, x86_64-netbsd. multiarch triplet
Le type de système GNU clarifié, utilisé pour les chemins de fichiers. Ce triplet ne change pas même lorsque l'ISA de base est mis à jour, de sorte que les chemins résultants sont stables dans le temps. La seule différence actuelle avec le type de système GNU est que la partie CPU pour
les systèmes basés sur i386 est toujours i386.
Exemples : i386-linux-gnu, x86_64-linux-gnu. Exemples de chemins : /lib/powerpc64le-linux-gnu/, /usr/lib/i386-kfreebsd-gnu/. VARIABLES

ENVIRONNEMENT

DPKG_DATADIR
S'il est défini, il sera utilisé comme répertoire de données dpkg , où se trouvent les tables d'architecture (depuis dpkg 1.14.17). Par défaut, il est défini sur «/usr/share/dpkg».
DPKG_COLORS
Définit le mode de couleur (depuis dpkg 1.18.5). Les valeurs actuellement acceptées sont : auto (par défaut), always et never.
DPKG_NLS
S'il est défini, il sera utilisé pour décider s'il faut activer la prise en charge de la langue native (Native Language Support), également connue sous le nom de prise en charge de l'internationalisation (ou i18n) (depuis dpkg 1.19.0). Les valeurs acceptées sont : 0 et 1 (par défaut).

NOTES

Tous les noms de commandes et d'options longs ne sont disponibles que depuis dpkg 1.17.17.
