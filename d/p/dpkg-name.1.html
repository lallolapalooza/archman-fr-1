NOM

dpkg-name - renomme les paquets Debian avec leurs noms complets

SYNTAXE

dpkg-name [option...] [--] fichier...

DESCRIPTION

Cette page de manuel documente le programme dpkg-name qui fournit un moyen facile de renommer les paquets Debian avec leurs noms de paquet complets. Un nom de paquet complet se compose de paquet_version_architecture.type-de-paquet comme spécifié dans le fichier de contrôle du paquet. La partie version du nom de fichier se compose des informations de version en amont, éventuellement suivies d'un trait d'union et des informations de révision. La partie type-de-paquet provient de ce champ s'il est présent, sinon il utilisera deb par défaut.

OPTIONS

-a, --no-architecture
Le nom de fichier de destination n'aura pas les informations d'architecture.
-k, --symlink
Crée un lien symbolique, au lieu de déplacer.
-o, --overwrite
Les fichiers existants seront écrasés s'ils portent le même nom que le nom de fichier de destination.
-s, --subdir [rép]
Les fichiers seront déplacés dans un sous-répertoire. Si le répertoire donné en argument existe, les fichiers seront déplacés dans ce répertoire, sinon le nom du répertoire cible est extrait du champ « section » dans la partie contrôle du paquet. Le répertoire cible sera « unstable/binary-architecture/section ». Si la section n'est pas trouvée dans le contrôle, alors no-section est supposé, et dans ce cas, ainsi que pour les sections non-free et contrib, le répertoire cible sera « section/binary-architecture ». Le champ section n'est pas obligatoire, donc beaucoup de paquets trouveront leur place dans la zone no-section.

Attention : Utilisez cette option avec prudence, elle peut être désordonnée.

-c, --create-dir
Cette option peut être utilisée conjointement avec l'option -s. Si un répertoire cible n'est pas trouvé, il sera créé automatiquement.

Attention : Utilisez cette option avec prudence.

-?, --help
Affiche le message d'utilisation et quitte.
-v, --version
Affiche la version et quitte.

ENVIRONNEMENT

DEB_HOST_ARCH
Définit l'architecture hôte. Cela affecte le nom de l'architecture utilisé dans le nom de fichier du paquet.
DPKG_COLORS
Définit le mode couleur (depuis dpkg 1.18.5). Les valeurs actuellement acceptées sont : auto (par défaut), always et never.
DPKG_NLS
Si défini, il sera utilisé pour décider si oui ou non activer le support des langues natives, également connu sous le nom d'internationalisation (ou i18n) (depuis dpkg 1.19.0). Les valeurs acceptées sont : 0 et 1 (par défaut).

BOGUES

Certains paquets ne suivent pas la structure de nommage paquet_version_architecture.deb. Les paquets renommés par dpkg-name suivront cette structure. Généralement, cela n'aura aucun impact sur la façon dont les paquets sont installés par dselect(1)/dpkg(1), mais d'autres outils d'installation pourraient dépendre de cette structure de nommage.

EXEMPLES

dpkg-name bar-foo.deb
Le fichier bar-foo.deb sera renommé en bar-foo_1.0-2_i386.deb ou quelque chose de similaire (selon les informations présentes dans la partie contrôle de bar-foo.deb).
find /root/debian/ -name '*.deb' | xargs -n 1 dpkg-name -a
Tous les fichiers avec l'extension deb dans le répertoire /root/debian et ses sous-répertoires seront renommés par dpkg-name si nécessaire en noms sans informations d'architecture.
find -name '*.deb' | xargs -n 1 dpkg-name -a -o -s -c
Ne faites pas cela. Votre archive sera complètement désordonnée car beaucoup de paquets ne fournissent pas d'informations de section. Ne faites pas cela.
dpkg-deb --build debian-tmp && dpkg-name -o -s .. debian-tmp.deb
Ceci peut être utilisé lors de la construction de nouveaux paquets.
