DESCRIPTIO

N

dpkg-split divise les fichiers de paquets binaires Debian en plusieurs parties et les réassemble à nouveau, afin de permettre le stockage de fichiers de paquets volumineux sur de petits supports tels que les

disquettes.

Il peut être utilisé manuellement à l'aide des --split, --join et --info

.

Il possède également un mode automatique, invoqué à l'aide de l'option --auto, où il maintient une file d'attente des parties vues mais pas encore réassemblées et réassemble un fichier de paquet lorsqu'il a vu toutes ses parties. Les options --listq et --discard permettent la gestion de la file

d'attente.

Toutes les opérations de division, de réassemblage et de mise

en file d'attente produisent des messages informatifs s
ur la sortie standard ; ils peuvent être ignorés sans risque.

COMMANDE

S
-s, --split archive-complète [préfix
e]
Divise un paquet binaire Debian unique en plusieurs parties.

Les parties sont nommées préfixe.NdeM.deb où N est le numéro de partie, commençant à 1, et M est le nombre total de parties (tous deux en

décimal).

Si aucun préfixe n'est fourni, le nom de fichier de l'archive-complète est utilisé, répertoire compris, avec le suffixe final .deb su

ppr
imé.
-j, --join partie
...
Réassemble les parties d'un fichier de paquet, reconstituant le fichier original tel qu'il était avant sa division.

Les fichiers de parties fournis en arguments doivent être toutes les parties de exactement le même fichier binaire original. Chaque partie doit apparaître exactement une fois dans la liste d'arguments, bien que les parties n'aient pas besoin d'être listées dans

l'ordre.

Les parties doivent bien sûr avoir toutes été générées avec la même taille de partie spécifiée au moment de la division, ce qui signifie qu'elles doivent généralement avoir été générées par la même invocation de dpkg-split

--split.

Les noms de fichiers des parties ne sont pas significatifs pour le processus de

réassemblage.

Par défaut, le fichier de sortie est nommé paquet_version_arch.d

eb
.
-I, --info partie
...
Affiche des informations, dans un format lisible par l'humain, sur le(s) fichier(s) de partie spécifié(s). Les arguments qui ne sont pas des parties de paquets binaires produisent un message indiquant cela à la place (mais toujours sur la sortie standard)
.
-a, --auto -o sortie-complète par
tie
Met automatiquement les parties en file d'attente et réassemble un paquet si possible.

La partie spécifiée est examinée et comparée avec d'autres parties du même paquet (le cas échéant) dans la file d'attente des fichiers de parties de

paquets.

Si toutes les parties du fichier de paquet dont la partie fait partie sont disponibles, alors le paquet est réassemblé et écrit dans sortie-complète (qui ne devrait généralement pas déjà exister, bien que ce ne soit pas une

erreur).

Sinon, la partie est copiée dans la file d'attente et sortie-complète n'est pas

créée.

Si la partie n'est pas une partie de paquet binaire divisé, alors dpkg-split se terminera avec le statut 1 ; si un autre problème survient, il se terminera avec le statut 2

.

L'option --output ou -o doit être fournie lors de l'utilisation de --auto. (Si ce n'était pas obligatoire, le programme appelant ne saurait pas quel fichier de sortie

attendre.
)
-l, --lis
tq
Liste le contenu de la file d'attente des paquets à réassembler.

Pour chaque fichier de paquet dont des parties sont dans la file d'attent

e, la sortie donne le nom du paquet, les parties dans la file d'at
tente et le nombre total d'octets stockés dans la file d'attente.

.]
Cela supprime de la file d'attente les parties de ceux qui attendent les parties restantes de leurs paquets.

Si aucun paquet n'est spécifié, la file d'attente est vidée complètement ; si des paquets

sont spécifiés, seules les parties du(des)
paquet(s) concerné(s) sont supprimées.

OPTION

S
--depotdir répertoi
re
Spécifie un répertoire alternatif pour la file d'attente des parties en attente de réassemblage automatique. La valeur par défaut est /var/lib/dpkg
/parts.
--admindir répertoi
re
Définit le répertoire administratif sur répertoire (depuis dpkg 1.21.10). C'est ici que le fichier statoverride est stocké. La valeur par défaut est «/var/lib/dpkg » si DPKG_ADMINDIR n'a pas été
défini.
--root répertoi
re
Définit le répertoire racine sur répertoire (depuis dpkg 1.21.10), ce qui définit le répertoire d'installation sur «répertoire » et le répertoire administratif sur «répertoire/var/lib/dpkg » si DPKG_ROOT n'a pas été
défini.
-S, --partsize kibibyt
es
Spécifie la taille maximale des parties lors de la division, en kibibytes (1024 octets). La valeur par défaut est 450
KiB.
-o, --output sortie-compl
ète
Spécifie le nom du fichier de sortie pour un réassemblage.

Cela remplace la valeur par défaut pour un réassemblage manuel (--join) et est obligatoire pour une mise en file d'attente ou un réassemblage automatique (--au

to
).
-Q, --npqui
et
Lors d'une mise en file d'attente ou d'un réassemblage automatique, dpkg-split affiche généralement un message s'il reçoit une partie qui n'est pas une partie de paquet binaire. Cette option supprime ce message, pour permettre à des programmes tels que dpkg de gérer à la fois les paquets divisés et non divisés sans produire de messages
erronés.
--msd
os
Force les noms de fichiers de sortie générés par --split à être compatibles MSDOS.

Cela altère le préfixe - soit celui dérivé par défaut du nom de fichier d'entrée, soit celui fourni en argument : les caractères alphanumériques sont mis en minuscules, les signes plus sont remplacés par des x et tous les autres caractères sont

supprimés.

Le résultat est ensuite tronqué autant que nécessaire, et des noms de fichiers de la forme préfixeNdeM.deb sont

géné
rés.

SÉCURIT

É

L'examen ou la réunion d'archives de paquets divisés non fiables doit être considéré comme une limite de sécurité, et toute violation de cette limite résultant de ces opérations doit être considérée comme une vulnérabilité de sécurité. Il est fortement déconseillé d'effectuer ces opérations sur des données non fiables en tant que

root.

L'accumulation automatique et la suppression des parties de paquets divisés sont considérées comme des opérations privilégiées qui pourraient permettre une escalade de privilèges vers root. Ces opérations ne doivent jamais être déléguées à un utilisateur non fiable ni être effectuées sur des paquets non fiables, car cela pourrait permettre un accès root au

système.

La division des archives de pa

quets ne doit être effectuée qu
e sur des données fiables.

S

Il est impossible d'obtenir des détails complets sur les paquets dans la file d'attente sans fouiller vous-même dans le répertoire de la file

d'attente.

Il n'existe pas de moyen simple pour tes

ter si un fichier qui pourrait être
une partie de paquet binaire en est une.
