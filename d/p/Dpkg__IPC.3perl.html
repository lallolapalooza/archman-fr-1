NOM

Dpkg::IPC - fonctions d'aide pour la communication inter-processus (IPC)

DESCRIPTION

Dpkg::IPC offre des fonctions d'aide pour vous permettre d'exécuter d'autres programmes de manière simple, mais flexible, tout en cachant tous les détails complexes de la communication inter-processus (IPC) pour vous.

FONCTIONS

$pid = spawn(%opts)
Crée un processus enfant et exécute un autre programme en son sein. Les arguments sont interprétés comme une table de hachage d'options, spécifiant comment gérer les entrées et sorties du programme à exécuter. Renvoie le pid du processus enfant (sauf si l'option wait_child a été fournie).

Toute erreur entraînera la sortie de la fonction avec une des fonctions Dpkg::ErrorHandling.

Options :

exec (requis)
Peut être soit un scalaire, c'est-à-dire le nom du programme à exécuter, soit une référence de tableau, c'est-à-dire le nom du programme plus les arguments supplémentaires. Notez que le programme ne sera jamais exécuté via le shell, vous ne pouvez donc pas spécifier d'arguments supplémentaires dans la chaîne scalaire et vous ne pouvez pas utiliser de fonctionnalités de shell comme le globbing.
from_file, to_file, error_to_file
Nom de fichier comme scalaire. L'entrée/sortie standard/erreur du processus enfant sera redirigée vers le fichier spécifié.
from_handle, to_handle, error_to_handle
Descripteur de fichier. L'entrée/sortie standard/erreur du processus enfant sera dupliquée à partir du descripteur.
from_pipe, to_pipe, error_to_pipe
Référence scalaire ou objet basé sur IO::Handle. Un pipe sera ouvert pour chacune des deux options et soit l'extrémité de lecture ("to_pipe" et "error_to_pipe"), soit l'extrémité d'écriture ("from_pipe") sera renvoyée dans le scalaire référencé. L'entrée/sortie standard/erreur du processus enfant sera dupliquée vers les autres extrémités des pipes.
from_string, to_string, error_to_string
Référence scalaire. L'entrée/sortie standard/erreur du processus enfant sera redirigée vers la chaîne donnée en référence. Notez qu'il ne serait pas strictement nécessaire d'utiliser une référence scalaire pour "from_string", car la chaîne n'est modifiée d'aucune manière. Ceci a été choisi uniquement pour des raisons de symétrie avec "to_string" et "error_to_string". "to_string" et "error_to_string" impliquent l'option "wait_child".
wait_child
Scalaire. Si contenant une valeur vraie, wait_child() sera appelée avant de retourner. La valeur de retour de spawn() sera une valeur vraie, pas le pid.
nocheck
Scalaire. Option de l'appel wait_child().
timeout
Scalaire. Option de l'appel wait_child().
chdir
Scalaire. Le processus enfant effectuera un chdir dans le répertoire indiqué avant d'appeler exec.
env
Référence de table de hachage. Le processus enfant remplira %ENV avec les éléments de la table avant d'appeler exec. Ceci permet d'exporter des variables d'environnement.
delete_env
Référence de tableau. Le processus enfant supprimera toutes les variables d'environnement listées dans le tableau avant d'appeler exec.
sig
Référence de table de hachage. Le processus enfant remplira %SIG avec les éléments de la table avant d'appeler exec. Ceci permet de définir les dispositions des signaux.
delete_sig
Référence de tableau. Le processus enfant réinitialisera tous les signaux listés dans le tableau à leurs dispositions par défaut avant d'appeler exec.
wait_child($pid, %opts)
Prend comme premier argument le pid du processus à attendre. Les arguments restants sont pris comme une table de hachage d'options. Ne renvoie rien. Échoue si l'enfant a été terminé par un signal ou s'il s'est terminé avec un code non nul.

Options :

cmdline
Chaîne pour identifier le processus enfant dans les messages d'erreur. Par défaut, "child process".
nocheck
Si vrai, ne vérifie pas le statut de retour de l'enfant (et donc ne l'échoue pas s'il a été tué ou s'il s'est terminé avec un code de retour non nul).
timeout
Définit un temps maximum pour attendre le processus, après quoi il est tué et une erreur est générée.

CHANGEMENTS

Version 1.02 (dpkg 1.18.0)

Modification des options : wait_child() tue maintenant le processus lorsqu'il atteint le 'timeout'.

Version 1.01 (dpkg 1.17.11)

Nouvelles options : spawn() accepte maintenant 'sig' et 'delete_sig'.

Version 1.00 (dpkg 1.15.6)

Marque le module comme public.
