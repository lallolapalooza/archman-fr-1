DESCRIPTION

La fonction val_resolve_and_check() interroge un ensemble de serveurs de noms pour le tuple <domain_name, type, class> et vérifie et valide la réponse. La vérification implique de vérifier les RRSIGs, et la validation est la vérification d'une chaîne d'authentification à partir d'une ancre de confiance configurée.

Le paramètre flags peut être utilisé pour contrôler les résultats de la validation. Les valeurs suivantes, qui peuvent être combinées par OU, sont actuellement définies pour ce champ :

VAL_QUERY_DONT_VALIDATE
Cet indicateur demande au validateur de désactiver la validation pour cette requête.
VAL_QUERY_IGNORE_SKEW
Cet indicateur demande au validateur de désactiver la vérification des heures d'inception et d'expiration des signatures sur les RRSIGs.
VAL_QUERY_AC_DETAIL
Cet indicateur demande au validateur de copier les détails de la chaîne d'authentification dans le membre val_rc_answer de la structure val_result_chain retournée.
VAL_QUERY_ASYNC
Cet indicateur active la résolution asynchrone des requêtes pour cette recherche.
VAL_QUERY_NO_DLV
Cet indicateur demande au validateur de désactiver le traitement DLV pour cette requête. Ceci n'est disponible que si la bibliothèque libval(3) a été compilée avec le support DLV.
VAL_QUERY_NO_EDNS0_FALLBACK
Lors de l'interrogation de divers serveurs de noms, libsres(3) tente également différentes tailles EDNS0, se terminant par une requête où EDNS0 est désactivé (c'est-à-dire que le bit CD n'est pas défini). Cet indicateur demande à libval de désactiver le fallback EDNS0 pour la requête.
VAL_QUERY_ITERATE
Cet indicateur force libval à effectuer une recherche itérative en interrogeant divers serveurs de noms dans la hiérarchie de délégation, au lieu de demander ces informations à un serveur de noms de cache qui pourrait être configuré dans dnsval.conf.
VAL_QUERY_SKIP_RESOLVER
Cet indicateur force libval à ne consulter que son cache lors de la tentative de résolution d'un nom.
VAL_QUERY_SKIP_CACHE
Il existe deux niveaux de mise en cache dans libval : au niveau de l'assertion et au niveau de la réponse. Cet indicateur force libval à ignorer les données des deux caches lors de la tentative de résolution d'un nom.
VAL_QUERY_SKIP_ANS_CACHE
Il existe deux niveaux de mise en cache dans libval : au niveau de l'assertion et au niveau de la réponse. Cet indicateur force libval à ignorer les données du cache de réponses lors de la tentative de résolution d'un nom. Si une assertion existe déjà pour le nom, la classe et le type donnés, cette assertion est réutilisée jusqu'à son expiration. Une fois expirée, le nom est recherché via une requête même si un enregistrement plus récent (récupéré par une autre assertion dans le même contexte ou un contexte différent) est disponible dans son cache de réponses.

Le premier paramètre de val_resolve_and_check() est le contexte du validateur. Les applications peuvent créer un nouveau contexte de validateur en utilisant la fonction val_create_context(). Cette fonction analyse les fichiers de configuration du résolveur et du validateur et crée le descripteur newcontext pour ces informations analysées. Les informations stockées dans le contexte du validateur incluent la politique de validation et la politique du résolveur.

Les politiques de validateur et de résolveur sont lues à partir des fichiers /etc/dnsval.conf et /etc/resolv.conf par défaut. /etc/root.hints fournit des informations d'amorçage pour le validateur lorsqu'il fonctionne comme résolveur complet (voir dnsval.conf(3)). Ces valeurs par défaut peuvent être différentes si une autre valeur a été spécifiée lors de la configuration de la bibliothèque. Si le fichier de configuration du résolveur par défaut n'est pas trouvé à l'emplacement spécifié, libval tentera également de se replier sur /etc/resolv.conf en dernier recours.

Les applications peuvent également créer un contexte de validateur avec une politique personnalisée en utilisant la fonction val_create_context_ex().

L'argument opt dans val_create_context_ex() pointe vers la structure suivante :

typedef struct val_context_opt {
    unsigned int vc_qflags;
    unsigned int vc_polflags;
    char *vc_valpol;
    char *vc_nslist;
    char *vc_val_conf;
    char *vc_res_conf;
    char *vc_root_conf;
    val_global_opt_t *gopt, 
} val_context_opt_t;

vc_qflags spécifie les indicateurs de requête par défaut pour les requêtes associées au contexte. Ce champ est identique au paramètre flags de la fonction val_resolve_and_check().

Les champs vc_val_conf, vc_res_conf et vc_root_conf peuvent être utilisés pour spécifier des fichiers de configuration alternatifs à la place des fichiers par défaut utilisés pour les informations de configuration du validateur, du résolveur et des indices racine.

Le champ vc_valpol peut être utilisé pour fournir un "extrait" de configuration de validateur personnalisé au validateur. Le validateur analyse ces informations et les applique à la configuration du validateur par défaut, soit comme une extension, soit comme une substitution, selon ce qui est spécifié par le champ vc_polflags. Le champ vc_nslist, de manière similaire, peut être utilisé pour fournir une liste personnalisée de serveurs de noms récursifs vers lesquels envoyer les requêtes, en plus (ou à la place) de la liste des serveurs de noms spécifiée dans le fichier resolv.conf. La liste des serveurs de noms dans vc_res_conf doit être spécifiée comme une liste d'adresses IP ou IPv6 délimitées par des espaces blancs.

Un mappage personnalisé entre une zone et un serveur de noms peut être créé en utilisant la fonction val_context_store_ns_for_zone().

vc_polflags peut être configuré avec les valeurs suivantes :

CTX_DYN_POL_VAL_OVR
Lorsque cet indicateur est défini, seule la configuration du validateur spécifiée dans le champ vc_valpol est utilisée pour la configuration du validateur. Les options spécifiées dans le fichier dnsval.conf sont ignorées.
CTX_DYN_POL_RES_OVR
Lorsque cet indicateur est défini, seule la configuration du résolveur spécifiée dans le champ vc_res_conf est utilisée pour la configuration du résolveur. Les options spécifiées dans le fichier resolv.conf sont ignorées.

La fonction val_context_setqflags() permet de modifier les indicateurs par défaut pour un contexte donné. L'argument action peut être défini sur VAL_SET_FLAGS pour définir les indicateurs ou VAL_CLEAR_FLAGS pour les effacer. L'argument flags spécifie quels indicateurs doivent être définis ou effacés.

Les fonctions val_istrusted(), val_isvalidated() et val_does_not_exist() sont des fonctions utilitaires qui interprètent la valeur de statut retournée par val_resolve_and_check() et retournent un booléen indiquant si la réponse est digne de confiance, validée cryptographiquement, ou si elle indique une existence nulle.

Les fonctions p_val_status(), p_ac_status() et p_val_error() convertissent les codes d'état de validation, de chaîne d'authentification et d'erreur en chaînes de caractères lisibles par l'homme.

La fonction val_log_add_optarg() permet de contrôler la verbosité des messages de journal et l'emplacement de leur sortie. L'argument args est une chaîne de caractères délimitée par des espaces qui peut contenir des options telles que -v pour augmenter la verbosité ou -o pour spécifier un fichier de sortie. Si use_stderr est défini sur vrai, la sortie du journal sera dirigée vers la sortie d'erreur standard.

La fonction val_free_context() libère la mémoire allouée pour un contexte de validateur. La fonction val_free_result_chain() libère la mémoire allouée pour une chaîne de résultats.

VALEURS DE RETOUR

Toutes les fonctions retournent VAL_SUCCESS en cas de succès, ou un code d'erreur approprié en cas d'échec. Les codes d'erreur incluent VAL_NO_CONTEXT, VAL_NO_MEMORY, VAL_INVALID_DOMAIN_NAME, VAL_INVALID_TYPE, VAL_INVALID_CLASS, VAL_QUERY_FAILED, VAL_DNSSEC_FAILED, et VAL_INVALID_POLICY.

VOIR AUSSI

dnsval.conf(3), resolv.conf(5), root.hints(5).

Le champ gopt pointe vers la structure suivante :

typedef struct val_global_opt {
    int local_is_trusted;
    long edns0_size;
    int env_policy;
    int app_policy;
    char *log_target;
    int closest_ta_only;
    int rec_fallback;
    long max_refresh;
    int proto;
} val_global_opt_t;

Définir la valeur 1 pour local_is_trusted est équivalent à spécifier l'option trust-oob-answers dans le fichier dnsval.conf à yes. De même, définir les membres closest_ta_only et rec_fallback à 1 est équivalent à définir les options closest-ta-only et rec-fallback à yes dans le dnsval.conf fichier. La valeur 0 est équivalent au paramètre no pour ces options.

Définir le membre edns0_size à une valeur particulière a le même effet que de définir l'option edns0-size dans le fichier dnsval.conf .

Définir le membre max_refresh à une valeur particulière a le même effet que de définir l'option max-refresh dans le fichier dnsval.conf .

Définir le membre proto à une valeur particulière a le même effet que de définir l'option proto dans le fichier dnsval.conf .

env_policy et app_policy peuvent être définis à l'une des valeurs VAL_POL_GOPT_DISABLE, VAL_POL_GOPT_ENABLE, ou VAL_POL_GOPT_OVERRIDE. Ces valeurs correspondent directement aux options disable, enable et override pour les paramètres env-policy et app-policy dans le fichier dnsval.conf .

Les valeurs -1 pour les champs ci-dessus sont traitées comme des conditions « ignorer », c'est-à-dire que le validateur n'inclura pas les options globales fournies dynamiquement ayant une valeur de -1 lors de la création de son contexte. Cela permet à une application de remplacer un sous-ensemble d'options globales tout en utilisant par défaut les options globales fournies dans le dnsval.conf fichier.

Le champ log_target permet à l'application de fournir des cibles de journalisation en plus de celles configurées dans le fichier de configuration.

Voir dnsval.conf(3) pour plus de détails sur la spécification de la politique du validateur.

Les indicateurs de requête par défaut peuvent être définis et annulés pour un contexte donné à l'aide de val_context_setqflags(). Cela permet à une application de modifier le traitement du validateur DNSSEC, tout en conservant la plupart de la configuration par défaut plus détaillée spécifiée dans son fichier de configuration. Le paramètre action peut être défini à l'une des valeurs suivantes.

VAL_CTX_FLAG_SET
Cette option amène le validateur à définir l'indicateur donné comme l'un des indicateurs de requête par défaut.
VAL_CTX_FLAG_RESET
Cette option amène le validateur à réinitialiser l'indicateur donné s'il était défini comme l'un des indicateurs de requête par défaut du contexte.

Les réponses renvoyées par val_resolve_and_check() sont disponibles dans la liste chaînée *results . Chaque réponse correspond à un ensemble de RR distinct ; plusieurs RR au sein de l'ensemble de RR font partie de la même réponse. Plusieurs réponses sont possibles lorsque type est ns_t_any ou ns_t_rrsig.

Les éléments individuels dans *results pointent vers les listes chaînées val_authentication_chain . Les éléments de la chaîne d'authentification dans val_authentication_chain contiennent les ensembles de RR réellement renvoyés par le serveur de noms en réponse à la requête.

Les valeurs de résultat de validation renvoyées dans val_result_chain peuvent être converties au format ASCII à l'aide de p_val_status(). Les valeurs d'état de la chaîne d'authentification renvoyées dans chaque élément de la liste chaînée val_authentication_chain peuvent être converties au format ASCII à l'aide des fonctions p_ac_status() .

Bien que certaines applications telles que les utilitaires de dépannage DNSSEC et les outils d'inspection de paquets puissent examiner les éléments individuels de la chaîne d'authentification pour identifier les raisons réelles d'une erreur de validation, la plupart des applications ne s'intéresseront qu'à un seul code d'erreur pour déterminer l'authenticité des données.

val_isvalidated() identifie si une valeur d'état de résultat de validation donnée correspond à une réponse qui a été vérifiée cryptographiquement et validée à l'aide d'une ancre de confiance configurée localement.

val_istrusted() identifie si une valeur d'état de validateur donnée est de confiance. Une réponse peut être de confiance localement sans avoir été validée.

val_does_not_exist() identifie si une valeur d'état de validateur donnée correspond à l'un des types de non-existence.

La bibliothèque libval alloue en interne de la mémoire pour *results et celle-ci doit être libérée par l'application appelante à l'aide de l'interface free_result_chain() .

STRUCTURES DE DONNÉES

struct val_result_chain
struct val_result_chain
{
    val_status_t                     val_rc_status;
    char                            *val_rc_alias;
    struct val_rrset_rec            *val_rc_rrset;
    struct val_authentication_chain *val_rc_answer;
    int                              val_rc_proof_count;
    struct val_authentication_chain *val_rc_proofs[MAX_PROOFS];
    struct val_result_chain         *val_rc_next;
};
val_rc_answer
Chaîne d'authentification pour un ensemble de RR donné.
val_rc_next
Pointeur vers l'ensemble de RR suivant dans l'ensemble des réponses renvoyées pour une requête.
val_rc_proofs
Pointeur vers les chaînes d'authentification pour toute preuve de non-existence qui a été renvoyée pour la requête.
val_rc_proof_count
Nombre d'éléments de preuve stockés dans val_rc_proofs. Le nombre ne peut pas dépasser MAX_PROOFS.
val_rc_alias
Pour un élément val_result_chain qui pointe vers un alias de nom, ce champ contient la valeur cible.
val_rc_rrset
Pour un élément val_result_chain qui contient un champ val_rc_answer valide (non NULL), le champ val_rc_rrset pointe vers l'élément le plus haut val_rrset_rec dans la chaîne d'authentification val_rc_answer .
val_rc_status
Statut de validation pour un ensemble de RR donné. Cela peut être l'une des valeurs suivantes :
VAL_SUCCESS
Réponse reçue et validée avec succès.
VAL_NONEXISTENT_NAME
Le nom n'existait pas et une preuve de non-existence valide confirmant le nom manquant (intervalle NSEC ou NSEC3) a été renvoyée. Les composants de la preuve ont également été validés individuellement.
VAL_NONEXISTENT_TYPE
Aucun type n'existe pour le nom et une preuve de non-existence valide confirmant le nom manquant a été renvoyée. Les composants de la preuve ont également été validés individuellement.
VAL_NONEXISTENT_NAME_NOCHAIN
Le nom n'existait pas et une preuve de non-existence valide confirmant le nom manquant a été renvoyée. Les composants de la preuve ont également été identifiés comme dignes de confiance, mais ils n'ont pas été validés individuellement.
VAL_NONEXISTENT_TYPE_NOCHAIN
Aucun type n'existe pour le nom et une preuve de non-existence valide confirmant le nom manquant (intervalle NSEC ou NSEC3) a été renvoyée. Les composants de la preuve ont également été identifiés comme dignes de confiance, mais ils n'ont pas été validés individuellement.
VAL_PINSECURE
L'enregistrement ou un certain ancêtre de l'enregistrement dans la chaîne d'authentification vers l'ancre de confiance était connu comme étant de manière vérifiable non sécurisé.
VAL_PINSECURE_UNTRUSTED
L'enregistrement ou un certain ancêtre de l'enregistrement dans la chaîne d'authentification vers l'ancre de confiance était connu comme étant de manière vérifiable non sécurisé. Mais la condition de non-sécurité vérifiable était configurée comme non digne de confiance.
VAL_BARE_RRSIG
Pas de validation DNSSEC possible, la requête portait sur un RRSIG.
VAL_IGNORE_VALIDATION
La politique locale était configurée pour ignorer la validation pour la zone à partir de laquelle ces données ont été reçues.
VAL_UNTRUSTED_ZONE
La politique locale était configurée pour rejeter toute donnée reçue de la zone donnée.
VAL_OOB_ANSWER
La réponse a été obtenue à l'aide d'une méthode hors bande, telle qu'un fichier de configuration local.
VAL_BOGUS
La réponse n'a pas pu être validée en raison d'échecs de vérification de signature ou de l'impossibilité de vérifier les preuves dans la chaîne d'authentification.
VAL_DNS_ERROR
Une erreur a été rencontrée lors du traitement DNS.
VAL_INDETERMINATE
La réponse n'a pas pu être validée en raison de métadonnées DNSSEC manquantes.
VAL_NOTRUST
Tous les composants disponibles dans la chaîne d'authentification ont été vérifiés correctement, mais aucun point d'ancrage de confiance n'était disponible.

Les valeurs de statut dans val_status_t retournées par le validateur peuvent être affichées au format ASCII en utilisant p_val_status().

val_ac_status
État de validation de l'élément de la chaîne d'authentification. Ce champ contiendra le code de statut pour le composant donné dans la chaîne d'authentification. Ce champ peut contenir l'une des valeurs suivantes :
VAL_AC_UNSET
Le statut n'a pas pu être déterminé.
VAL_AC_IGNORE_VALIDATION
La validation de l'enregistrement de ressources donné a été ignorée, soit en raison d'une directive de politique locale, soit en raison d'un comportement spécifique au protocole.
VAL_AC_UNTRUSTED_ZONE
La politique locale a défini une zone donnée comme non fiable, sans autre validation jugée nécessaire.
VAL_AC_PINSECURE
La chaîne d'authentification d'un point d'ancrage de confiance vers une zone donnée n'a pas pu être construite en raison de l'absence prouvable d'un enregistrement DS pour cette zone dans le parent.
VAL_AC_BARE_RRSIG
La réponse concernait une requête de type RRSIG. Les RRSIG contiennent les signatures cryptographiques pour d'autres données DNS et ne peuvent pas être validés eux-mêmes.
VAL_AC_NO_LINK
Aucun point d'ancrage de confiance n'était configuré pour une chaîne d'authentification donnée ou la chaîne n'était pas connectée.
VAL_AC_TRUST
Au moins une des signatures couvrant le jeu d'enregistrements DNSKEY donné a été directement vérifiée à l'aide d'une clé configurée comme point d'ancrage de confiance DNSSEC.
VAL_AC_RRSIG_MISSING
Les données RRSIG n'ont pas pu être récupérées pour un enregistrement de ressources.
VAL_AC_DNSKEY_MISSING
Le DNSKEY pour un RRSIG couvrant un enregistrement de ressources n'a pas pu être récupéré.
VAL_AC_DS_MISSING
L'enregistrement DS couvrant un enregistrement DNSKEY n'était pas disponible.
VAL_AC_DATA_MISSING
Aucune donnée n'a été retournée pour une requête et le DNS n'a indiqué aucune erreur.
VAL_AC_DNS_ERROR
Une erreur s'est produite lors du traitement DNS.
VAL_AC_NOT_VERIFIED
Tous les RRSIG couvrant le jeu d'enregistrements n'ont pas pu être vérifiés.
VAL_AC_VERIFIED
Au moins un RRSIG couvrant un enregistrement de ressources avait un statut de VAL_AC_RRSIG_VERIFIED.
val_ac_rrset
Pointeur vers un jeu d'enregistrements de type struct val_rrset_rec obtenu à partir de la réponse DNS.
val_ac_trust
Pointeur vers un élément de chaîne d'authentification qui contient soit un jeu d'enregistrements DNSKEY pouvant être utilisé pour vérifier les RRSIG sur l'enregistrement actuel, soit un jeu d'enregistrements DS pouvant être utilisé pour construire la chaîne de confiance vers un point d'ancrage de confiance.

    Un RRSIG donné couvrant un enregistrement de ressources indique
    que l'enregistrement a été développé par joker.
VAL_AC_RRSIG_VERIFIED_SKEW
    Le RRSIG a été vérifié avec succès après prise en compte du décalage horaire.
VAL_AC_WCARD_VERIFIED_SKEW
    Un RRSIG donné couvrant un enregistrement de ressources indique que
    l'enregistrement a été développé par joker, mais il n'a été vérifié
    qu'après prise en compte du décalage horaire.
VAL_AC_WRONG_LABEL_COUNT
    Le nombre d'étiquettes dans la signature était supérieur
    au nombre indiqué dans le RDATA du RRSIG.
VAL_AC_INVALID_RRSIG
    Le RRSIG n'a pas pu être analysé.
VAL_AC_RRSIG_NOTYETACTIVE
    La date de début du RRSIG est dans le futur.
VAL_AC_RRSIG_EXPIRED
    Le RRSIG a expiré.
VAL_AC_ALGORITHM_NOT_SUPPORTED
    L'algorithme du RRSIG n'était pas pris en charge.
VAL_AC_RRSIG_VERIFY_FAILED
    Un RRSIG donné couvrant un jeu d'enregistrements était erroné.
VAL_AC_RRSIG_ALGORITHM_MISMATCH
    Le keytag référencé dans le RRSIG correspondait à un
    DNSKEY mais les algorithmes étaient différents.
VAL_AC_DNSKEY_NOMATCH
    Un RRSIG a été créé par un DNSKEY qui n'existait pas
    dans le jeu de clés de l'apex.

Pour chaque membre val_rr_rec de type DNSKEY (ou DS, le cas échéant) dans la chaîne d'authentification val_ac_rrset, le statut de validation est stocké dans la variable rr_status et peut retourner l'une des valeurs suivantes :

VAL_AC_TRUST_POINT
    Le DNSKEY donné ou un enregistrement DS a été configuré
    comme point d'ancrage de confiance DNSSEC.
VAL_AC_SIGNING_KEY
    Ce DNSKEY a été utilisé pour créer un RRSIG pour
    le jeu d'enregistrements de ressources.
VAL_AC_VERIFIED_LINK
    Ce DNSKEY a fourni le lien dans la chaîne d'authentification
    depuis le point d'ancrage de confiance jusqu'à l'enregistrement signé.
VAL_AC_UNKNOWN_ALGORITHM_LINK
    Ce DNSKEY a fourni le lien dans la chaîne d'authentification
    depuis le point d'ancrage de confiance jusqu'à l'enregistrement signé,
    mais l'algorithme du DNSKEY était inconnu.
VAL_AC_UNKNOWN_DNSKEY_PROTOCOL
    Le numéro de protocole du DNSKEY n'a pas été reconnu.
VAL_AC_ALGORITHM_NOT_SUPPORTED
    L'algorithme du DNSKEY ou DS n'était pas pris en charge.

VAL_AC_DS_NOMATCH
    Un RRSIG a été créé avec une clé qui n'existait pas
    dans le jeu d'enregistrements DS parent.
VAL_AC_INVALID_KEY
    La clé utilisée pour vérifier le RRSIG n'était pas un DNSKEY valide.
VAL_AC_INVALID_DS
    Le DS utilisé pour valider le DNSKEY n'a pas pu être analysé.
rr_next
Pointe vers l'enregistrement de ressource suivant dans le jeu d'enregistrements.

JOURNALISATION

libval fournit la fonction val_log_add_optarg() pour contrôler la verbosité et l'emplacement de la sortie des messages de journalisation.

La fonction val_log_add_optarg() prend deux arguments : le premier argument args est une chaîne de caractères qui spécifie l'emplacement et la verbosité. Le second argument, use_stderr, s'il est défini sur une valeur supérieure à 0, permet à libval d'envoyer des messages de journalisation à stderr.

La chaîne de caractères qui spécifie l'emplacement et la verbosité de la cible du journal a un format spécifique :

<niveau-debug>:<type-destination>[:<options-destination>]

où
<niveau-debug> est 1-7, pour des niveaux de verbosité croissants
<type-destination> est l'un des suivants : file, net, syslog, stderr, stdout
<options-destination> dépend de <type-destination>
file:<nom-fichier> (ouvert en mode ajout)
net[:<nom-hote>:<port-hote>] (127.0.0.1:1053)
syslog[:facility] (0-23 (par défaut 1 USER))

Les niveaux de journalisation peuvent être approximativement traduits en différents types de messages de journalisation comme suit (les messages retournés pour chaque niveau dans cette liste englobent les messages retournés pour le niveau supérieur) :

3 : Erreur   : erreur rencontrée
4 : Avertissement : récupération d'une erreur
5 : Notice  : donne les résultats de validation finaux pour une requête
              et des détails sur les fichiers de politique et les étiquettes utilisés
6 : Info
: donne des détails sur les chaînes d'authentification 7 : Debug : donne des informations sur le niveau de débogage
