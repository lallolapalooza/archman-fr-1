DESCRIPTION

Note : Cette page est incomplète (diverses fonctions du résolveur fournies par glibc ne sont pas décrites) et probablement obsolète.

Les fonctions décrites ci-dessous effectuent des requêtes aux serveurs de noms de domaine Internet et interprètent leurs réponses.

L'API se compose d'un ensemble de fonctions plus modernes et réentrantes, et d'un ancien ensemble de fonctions non réentrantes qui ont été remplacées. Les interfaces traditionnelles du résolveur telles que res_init() et res_query() utilisent un état statique (global) stocké dans la structure _res, rendant ces fonctions non sûres pour les threads. BIND 8.2 a introduit un ensemble de nouvelles interfaces res_ninit(), res_nquery(), etc., qui prennent un res_state comme premier argument, vous pouvez donc utiliser un état de résolveur par thread.

Les fonctions res_ninit() et res_init() lisent les fichiers de configuration (voir resolv.conf(5)) pour obtenir le nom de domaine par défaut et l'adresse du ou des serveurs de noms. Si aucun serveur n'est indiqué, l'hôte local est essayé. Si aucun domaine n'est indiqué, celui associé à l'hôte local est utilisé. Il peut être remplacé par la variable d'environnement LOCALDOMAIN. res_ninit() ou res_init() est normalement exécuté par le premier appel à l'une des autres fonctions. Chaque appel à res_ninit() nécessite un appel correspondant à res_nclose() pour libérer la mémoire allouée par res_ninit() et les appels ultérieurs à res_nquery().

Les fonctions res_nquery() et res_query() interrogent le serveur de noms pour le nom de domaine entièrement qualifié name du type et de la class spécifiés. La réponse est laissée dans le tampon answer d'une longueur anslen fournie par l'appelant.

Les fonctions res_nsearch() et res_search() effectuent une requête et attendent la réponse comme res_nquery() et res_query(), mais en plus, elles implémentent les règles de défaut et de recherche contrôlées par RES_DEFNAMES et RES_DNSRCH (voir la description des options de _res ci-dessous).

Les fonctions res_nquerydomain() et res_querydomain() effectuent une requête en utilisant res_nquery()/res_query() sur la concaténation de name et domain.

Les fonctions suivantes sont des routines de plus bas niveau utilisées par res_nquery()/res_query().

Les fonctions res_nmkquery() et res_mkquery() construisent un message de requête dans buf de longueur buflen pour le nom de domaine dname. Le type de requête op est l'un des suivants (typiquement QUERY):

QUERY
Requête standard.
IQUERY
Requête inverse. Cette option a été supprimée dans glibc 2.26, car elle n'est plus supportée par les serveurs DNS depuis très longtemps.
NS_NOTIFY_OP
Notifier le secondaire d'un changement SOA (Start of Authority).

newrr est actuellement inutilisé.

La fonction res_nsend() et res_send() envoie une requête préformatée donnée dans msg de longueur msglen et renvoie la réponse dans answer qui est de longueur anslen. Elles appelleront res_ninit()/res_init() si ce n'a pas déjà été fait.

La fonction dn_comp() compresse le nom de domaine exp_dn et le stocke dans le tampon comp_dn de longueur length. La compression utilise un tableau de pointeurs dnptrs vers des noms précédemment compressés dans le message actuel. Le premier pointeur pointe vers le début du message et la liste se termine par NULL. La limite du tableau est spécifiée par lastdnptr. Si dnptr est NULL, les noms de domaine ne sont pas compressés. Si lastdnptr est NULL, la liste des labels n'est pas mise à jour.

La fonction dn_expand() développe le nom de domaine compressé comp_dn en un nom de domaine complet, qui est placé dans le tampon exp_dn de taille length. Le nom compressé est contenu dans une requête ou une réponse, et msg pointe vers le début du message.
