NOM

dnssec-importkey - importer des enregistrements DNSKEY provenant de systèmes externes pour qu'ils puissent être gérés

SYNTAXE

dnssec-importkey [-K répertoire] [-L ttl] [-P date/décalage] [-P sync date/décalage] [-D date/décalage] [-D sync date/décalage] [-h] [-v niveau] [-V] {fichierclé}

dnssec-importkey {-f nomfichier} [-K répertoire] [-L ttl] [-P date/décalage] [-P sync date/décalage] [-D date/décalage] [-D sync date/décalage] [-h] [-v niveau] [-V] [nomdomaine]

DESCRIPTION

dnssec-importkey lit un enregistrement DNSKEY public et génère une paire de fichiers .key/.private. L'enregistrement DNSKEY peut être lu à partir d'un fichier .key existant, auquel cas un fichier .private correspondant est généré, ou il peut être lu à partir de tout autre fichier ou de l'entrée standard, auquel cas les fichiers .key et .private sont générés.

Le fichier .private nouvellement créé ne contient pas de données de clé privée et ne peut pas être utilisé pour la signature. Cependant, la présence d'un fichier .private permet de définir des heures de publication (-P) et de suppression (-D) pour la clé, ce qui signifie que la clé publique peut être ajoutée et retirée de l'ensemble d'enregistrements RR DNSKEY à une date prévue, même si la véritable clé privée est stockée hors ligne.

Lors de l'utilisation de dnssec-policy, n'utilisez pas dnssec-importkey pour importer des fichiers de clé qui ne peuvent pas être utilisés pour la signature. Dans ce cas, publiez simplement l'enregistrement DNSKEY importé dans la zone et assurez-vous que les fichiers se trouvent en dehors du key-directory configuré.

OPTIONS

-f nomfichier
Cette option indique le mode fichier de zone. Au lieu d'un nom de fichier de clé publique, l'argument est le nom de domaine DNS d'un fichier maître de zone, qui peut être lu à partir de nomfichier. Si le nom de domaine est identique à nomfichier, il peut être omis.

Si nomfichier est défini sur "-", les données de la zone sont lues à partir de l'entrée standard.

-K répertoire
Cette option définit le répertoire où doivent résider les fichiers de clé.
-L ttl
Cette option définit la durée de vie (TTL) par défaut à utiliser pour cette clé lors de sa conversion en un enregistrement RR DNSKEY. Il s'agit de la TTL utilisée lors de l'importation de la clé dans une zone, sauf s'il existait déjà un ensemble d'enregistrements RR DNSKEY, auquel cas la TTL existante a la priorité. Définir la TTL par défaut sur 0 ou none la supprime de la clé.
-h
Cette option affiche un message d'utilisation et se termine.
-v niveau
Cette option définit le niveau de débogage.
-V
Cette option affiche les informations de version.

OPTIONS DE TEMPORISATION

Les dates peuvent être exprimées au format AAAAMMJJ ou AAAAMMJJHHMMSS. (qui est le format utilisé dans les fichiers clés), ou 'Jour Mois JJ HH:MM:SS AAAA' (tel qu'affiché par dnssec-settime -p), ou le temps UNIX epoch (tel qu'affiché par dnssec-settime -up), ou le littéral now.

L'argument peut être suivi de + ou - et d'un décalage par rapport à la date donnée. Le littéral now peut être omis avant un décalage. Le décalage peut être suivi de l'un des suffixes y, mo, w, d, h, ou mi, de sorte qu'il soit calculé en années (définies comme 365 jours de 24 heures, ignorant les années bissextiles), mois (définis comme 30 jours de 24 heures), semaines, jours, heures, ou minutes, respectivement. Sans suffixe, le décalage est calculé en secondes.

Pour empêcher explicitement qu'une date soit définie, utilisez none, never, ou unset.

Tous ces formats sont insensibles à la casse.

-P date/décalage
Cette option définit la date à laquelle une clé doit être publiée dans la zone. Après cette date, la clé est incluse dans la zone mais n'est pas utilisée pour la signer.
sync date/décalage
Cette option définit la date à laquelle les enregistrements CDS et CDNSKEY correspondant à cette clé doivent être publiés dans la zone.
-D date/décalage
Cette option définit la date à laquelle la clé doit être supprimée. Après cette date, la clé n'est plus incluse dans la zone. (Cependant, elle peut rester dans le dépôt de clés.)
sync date/décalage
Cette option définit la date à laquelle les enregistrements CDS et CDNSKEY correspondant à cette clé doivent être supprimés.

FICHIERS

Un fichier clé peut être identifié par l'identification de clé Knnnn.+aaa+iiiii ou le nom de fichier complet Knnnn.+aaa+iiiii.key, tel que généré par dnssec-keygen <#std-iscman-dnssec-keygen>.
