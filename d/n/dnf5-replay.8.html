NOM

dnf5-replay - Commande de relecture

SYNTAXE

dnf5 replay [options] <chemin-transaction>

DESCRIPTION

Relit une transaction stockée dans un répertoire à <chemin-transaction>. Le répertoire de transaction peut être créé soit par l'option --store, disponible pour toutes les commandes de transaction, soit par la commande History Store Command. La relecture effectuera exactement les mêmes opérations sur les paquets que lors de la transaction d'origine et retournera une erreur en cas de différences dans les paquets installés ou leurs versions.

Pour exécuter la relecture, le répertoire de transaction doit contenir un fichier avec la transaction au format JSON nommé transaction.json. Le répertoire peut également contenir des paquets, des groupes comps ou des environnements comps qui seront utilisés dans la transaction relue.

OPTIONS

--ignore-extras
Ne pas considérer les paquets supplémentaires inclus dans la transaction comme des erreurs.
Ils seront quand même signalés comme avertissements.
--ignore-installed
Ne pas considérer les écarts entre les paquets installés et ceux stockés dans la transaction comme des erreurs.
Ils seront quand même signalés comme avertissements.
Pour les actions d'installation, ignorer les paquets déjà installés.
Pour les actions de mise à niveau, ignorer les groupes ou environnements qui ne sont pas installés.
Pour les actions de suppression, ignorer les paquets/groupes/environnements non installés.
L'utilisation de cette option peut entraîner une transaction vide.
--skip-broken
Résoudre les problèmes de dépendances en supprimant les paquets qui causent des problèmes de la transaction.
--skip-unavailable
Si certains paquets stockés dans la transaction ne sont pas disponibles sur le système cible,
les ignorer au lieu de générer une erreur.

EXEMPLES

dnf5 replay ./transaction
Relire une transaction stockée dans ./transaction.
dnf5 replay ./transaction --skip-unavailable
Relire une transaction stockée dans ./transaction en ignorant les paquets indisponibles.
