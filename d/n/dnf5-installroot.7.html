NOM

dnf5-installroot - Paramètre Installroot

DESCRIPTION

Le paramètre --installroot est utilisé pour spécifier un installroot alternatif, relatif à l'endroit où tous les paquets seront installés. Considérez cela comme l'équivalent de chroot <root> dnf, sauf que l'utilisation de --installroot permet à DNF5 de fonctionner avant la création du chroot.

Le répertoire du cache (cachedir), le répertoire du cache système (system_cachedir), les fichiers de journalisation (log), le numéro de version de publication (releasever) et les clés GPG (gpgkey) sont pris à partir de, ou stockés dans, l'installroot. Les clés OpenPGP sont importées dans l'installroot à partir d'un chemin relatif à l'hôte, qui peut être spécifié dans la section dépôts des fichiers de configuration.

Le fichier de configuration, le répertoire des dépôts (reposdir), et le répertoire des variables (vars) sont pris depuis l'intérieur de l'installroot, sauf si l'argument de ligne de commande --use-host-config est passé, auquel cas la configuration et l'environnement du système hôte seront utilisés.

Note : Lorsqu'un chemin est spécifié dans un argument de ligne de commande (par exemple, --config=CHEMIN_FICHIER_CONFIG pour le fichier de configuration, --setopt=reposdir=/chemin/vers/repodir pour reposdir, --setopt=cachedir=/chemin/vers/cachedir pour cachedir, --setopt=system_cachedir=/chemin/vers/system_cachedir pour system_cachedir, --setopt=logdir=/chemin/vers/logdir pour logdir, ou --setopt=varsdir=/chemins/vers/varsdir pour vars), ce chemin est toujours relatif à l'hôte, sans exception. pluginpath et pluginconfpath sont relatifs à l'hôte.

Note : Vous pourriez également vouloir utiliser l'option de ligne de commande --releasever=NUMERO_VERSION lors de la création de l'installroot, sinon la valeur $releasever est prise à partir de la rpmdb dans l'installroot (et donc elle est vide au moment de la création et la transaction échouera). Si --use-host-config est utilisé, le releasever sera détecté à partir du système hôte (/). Le nouveau chemin d'installroot au moment de la création ne contient pas le répertoire des dépôts, le releasever et les fichiers dnf.conf.

Sur un système modulaire, vous pourriez également vouloir utiliser l'option de ligne de commande --setopt=module_platform_id=<nom_plateforme_module:stream> lors de la création de l'installroot, sinon la valeur module_platform_id sera prise à partir du fichier /etc/os-release dans l'installroot (et donc elle sera vide au moment de la création, la dépendance modulaire pourrait ne pas être satisfaite et le contenu des modules pourrait être exclu).

EXEMPLES

dnf5 --installroot=INSTALLROOT --releasever=NUMERO_VERSION install system-release
Définit de manière permanente le releasever du système dans le répertoire INSTALLROOT à NUMERO_VERSION.
dnf5 --installroot=INSTALLROOT --setopt=reposdir=CHEMIN --config /chemin/dnf.conf upgrade
Met à niveau les paquets à l'intérieur de l'installroot à partir d'un dépôt décrit par --setopt en utilisant la configuration de /chemin/dnf.conf.
