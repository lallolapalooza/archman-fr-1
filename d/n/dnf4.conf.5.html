booléen

gpgkey_dns_verification
booléen

dnf doit-il tenter de vérifier automatiquement les clés de vérification GPG à l'aide du système DNS. Cette option nécessite le module python unbound (python3-unbound) installé sur le système client. Ce système présente deux caractéristiques principales. La première consiste à vérifier si l'une des clés déjà installées a été révoquée. La suppression automatique de la clé n'est pas encore disponible, il appartient donc à l'utilisateur de supprimer les clés révoquées du système. La deuxième caractéristique est la vérification automatique de nouvelles clés lorsqu'un dépôt est ajouté au système. En mode interactif, le résultat est écrit dans la sortie sous forme de suggestion à l'utilisateur. En mode non interactif (c'est-à-dire lorsque -y est utilisé), ce système acceptera automatiquement les clés disponibles dans le DNS et correctement signées à l'aide de DNSSEC. Il acceptera également les clés qui n'existent pas dans le système DNS et dont la NON-existence est prouvée de manière cryptographique à l'aide de DNSSEC. Cela sert principalement à préserver la compatibilité ascendante. La valeur par défaut est False.

group_package_types
liste

Liste des éléments suivants : optional, default, mandatory. Indique à dnf quel type de paquets dans les groupes sera installé lorsque 'groupinstall' est appelé. La valeur par défaut est : default, mandatory.

ignorearch
booléen

Si défini à True, RPM autorisera les tentatives d'installation de paquets incompatibles avec l'architecture du CPU. La valeur par défaut est False. Souvent utilisé avec l'option arch.

installonlypkgs
liste

Liste des noms de fournitures de paquets qui ne doivent être que installés, jamais mis à jour. Les noyaux en particulier entrent dans cette catégorie. Ces paquets ne sont jamais supprimés par dnf autoremove même s'ils ont été installés comme dépendances (voir clean_requirements_on_remove pour les détails de la suppression automatique). Cette option ajoute les valeurs de la liste à la liste installonlypkgs par défaut utilisée par DNF. Le nombre de versions de paquets conservées est régulé par installonly_limit.

installonly_limit
entier

Nombre de paquets installonly autorisés à être installés simultanément. La valeur par défaut est 3. Le nombre minimal de paquets installonly est 2. La valeur 0 signifie un nombre illimité de paquets installonly. La valeur 1 n'est explicitement pas autorisée car elle complique les mises à jour du noyau en raison de la protection du noyau en cours d'exécution contre la suppression.

installroot
chaîne

La racine du système de fichiers pour toutes les opacités de paquetage. Elle nécessite un chemin absolu. Voir aussi l'option de ligne de commande --installroot.

install_weak_deps
booléen

Lorsque cette option est définie à True et qu'un nouveau paquet est sur le point d'être installé, tous les paquets liés par une relation de dépendance faible (drapeaux Recommends ou Supplements) avec ce paquet seront ajoutés à la transaction. La valeur par défaut est True.

keepcache
booléen

Conserve les paquets téléchargés dans le cache lorsque défini à True. Même s'il est défini à False et que les paquets n'ont pas été installés, ils persisteront jusqu'à la prochaine transaction réussie. La valeur par défaut est False.

logdir
chaîne

Répertoire où les fichiers journal seront stockés. La valeur par défaut est /var/log.

logfilelevel
entier

Niveau de sortie des messages du fichier journal, dans la plage de 0 à 10. Plus le nombre est élevé, plus la sortie de débogage est ajoutée aux journaux. La valeur par défaut est 9.

Cette option contrôle dnf.log, dnf.librepo.log et hawkey.log. Bien que dnf.librepo.log et hawkey.log ne soient affectés que lorsque le logfilelevel est défini à 10.

log_compress
booléen

Lorsqu'il est défini à True, les fichiers journal sont compressés lorsqu'ils sont pivotés. La valeur par défaut est False.

log_rotate
entier

Les fichiers journal sont pivotés log_rotate fois avant d'être supprimés. Si log_rotate vaut 0, la rotation n'est pas effectuée. La valeur par défaut est 4.

log_size
taille de stockage

Les fichiers journal sont pivotés lorsqu'ils dépassent la taille de log_size octets. Si log_size vaut 0, la rotation n'est pas effectuée. La valeur par défaut est 1 Mo. Les unités valides sont 'k', 'M', 'G'.

La taille s'applique aux fichiers journal individuels, et non à la somme de tous les fichiers journal. Voir aussi log_rotate.

metadata_timer_sync
temps en secondes

La période minimale entre deux exécutions consécutives du makecache timer . La commande s'arrêtera immédiatement si le temps écoulé depuis sa dernière exécution est inférieur à cette période. N'affecte pas une exécution simple de makecache . Utilisez 0 pour désactiver complètement la synchronisation automatique des métadonnées. La valeur par défaut correspond à trois heures. La valeur est arrondie à l'heure suivante.

module_obsoletes
booléen

Cette option contrôle si dnf doit appliquer les obsoletes modulaires lorsque c'est possible. La valeur par défaut est False.

module_platform_id
chaîne

Définissez ceci à $name:$stream pour remplacer le PLATFORM_ID détecté à partir de /etc/os-release. C'est nécessaire pour effectuer une mise à niveau du système et basculer vers une nouvelle plateforme.

module_stream_switch
booléen

Cette option contrôle s'il est possible de basculer les flux activés d'un module. La valeur par défaut est False.

multilib_policy
chaîne

Contrôle la manière dont les paquets multilib sont traités lors des opérations d'installation. Peut être soit "best" (la valeur par défaut) pour que le résolveur de dépendances préfère les paquets qui correspondent le mieux à l'architecture du système, soit "all" pour installer les paquets pour toutes les architectures disponibles.

obsoletes
booléen

Cette option n'a d'effet que lors d'une installation/mise à jour. Elle active la logique de traitement des obsoletes de dnf, ce qui signifie qu'elle fait vérifier à dnf si certaines dépendances d'un paquet donné ne sont plus nécessaires et les supprime. Utile lors des mises à niveau au niveau de la distribution. La valeur par défaut est 'true'.

Option de ligne de commande : --obsoletes <#obsoletes-option-label>

optional_metadata_types
liste

Liste des types de métadonnées à charger en plus de primary, modules, comps, updateinfo et presto, qui sont toujours chargés.

Notez que la liste peut être étendue par des commandes individuelles pour demander explicitement le chargement d'un type de métadonnées spécifique.

Actuellement, seule la valeur filelists est prise en charge. La valeur par défaut est une liste vide.

persistdir
chaîne

Répertoire où DNF stocke ses données persistantes entre les exécutions. La valeur par défaut est "/var/lib/dnf".

persistence
chaîne

Si les modifications doivent persister après les redémarrages du système. La valeur par défaut est auto. Le passage de --transient <#transient-option-label> remplacera ce paramètre par transient. Les valeurs valides sont :

  • auto: Les modifications persisteront après les redémarrages, sauf si la cible est un système bootc en cours d'exécution et que le système est déjà dans un état déverrouillé (c'est-à-dire que /usr est accessible en écriture).
  • transient: Les modifications seront perdues au prochain redémarrage. Applicable uniquement sur les systèmes bootc. Attention, les modifications de /etc et /var serontll persist, selon la configuration de votre système bootc. Voir aussi https://bootc-dev.github.io/bootc/man/bootc-usr-overlay.html.
  • persist: Les modifications persisteront après les redémarrages.

Liste des répertoires dans lesquels sont recherchées les configurations de plugin à charger. Tous les fichiers de configuration trouvés dans ces répertoires, portant le même nom qu'un plugin, sont analysés. Le chemin par défaut est /etc/dnf/plugins.

pluginpath
list

Liste des répertoires dans lesquels sont recherchés les plugins à charger. Les plugins trouvés dans n'importe lequel des répertoires de cette option de configuration sont utilisés. La valeur par défaut contient un chemin spécifique à la version de Python.

plugins
boolean

Contrôle si les plugins sont activés. La valeur par défaut est True.

protected_packages
list

Liste des paquets que DNF ne doit jamais supprimer complètement. Ils sont protégés via Obsoletes ainsi que par les suppressions utilisateur/plugin.

La valeur par défaut est : dnf, glob:/etc/yum/protected.d/*.conf et glob:/etc/dnf/protected.d/*.conf. Ainsi, tout paquet qui doit être protégé peut l'être en incluant un fichier dans /etc/dnf/protected.d contenant son nom de paquet.

DNF protégera également le paquet correspondant à la version du noyau en cours d'exécution. Voir aussi l'option protect_running_kernel.

protect_running_kernel
boolean

Contrôle si le paquet correspondant à la version du noyau en cours d'exécution est protégé contre la suppression. La valeur par défaut est True.

releasever
string

Utilisé pour la substitution de $releasever dans la configuration des dépôts.

Les $releasever_major et $releasever_minor variables seront automatiquement dérivées de $releasever en la divisant au premier .. Par exemple, si $releasever est défini à 1.23, alors $releasever_major sera 1 et $releasever_minor sera 23.

$releasever_major et $releasever_minor peuvent aussi être définis par la distribution.

Voir aussi les variables de dépôt.

reposdir
list

DNF recherche les fichiers de configuration de dépôt dans les chemins spécifiés par reposdir. Le comportement de reposdir peut différer lorsqu'il est utilisé avec l'option --installroot.

rpmverbosity
string

Niveau de sortie de débogage des scriptlets RPM. L'un des : critical, emergency, error, warn, info ou debug. La valeur par défaut est info.

strict
boolean

Si désactivé, tous les paquets indisponibles ou les paquets avec des dépendances cassées donnés à la commande DNF seront ignorés sans lever d'erreur qui ferait échouer l'opération entière. Fonctionne actuellement uniquement pour la commande install. La valeur par défaut est True.

tsflags
list

Liste de chaînes ajoutant des drapeaux supplémentaires pour la transaction RPM.

valeur de tsflag Drapeau de transaction RPM
noscripts RPMTRANS_FLAG_NOSCRIPTS
test RPMTRANS_FLAG_TEST
notriggers RPMTRANS_FLAG_NOTRIGGERS
nodocs RPMTRANS_FLAG_NODOCS
justdb RPMTRANS_FLAG_JUSTDB
nocontexts RPMTRANS_FLAG_NOCONTEXTS
nocaps RPMTRANS_FLAG_NOCAPS

L'option nocrypto définira également les drapeaux VS _RPMVSF_NOSIGNATURES et _RPMVSF_NODIGESTS . L'option test fournit une vérification de transaction sans effectuer la transaction. Elle inclut le téléchargement des paquets, la vérification des clés gpg (y compris l'importation permanente de clés supplémentaires si nécessaire) et la vérification rpm pour prévenir les conflits de fichiers. nocaps est pris en charge avec rpm-4.14 ou plus récent. Lorsque nocaps est utilisé mais que rpm ne le supporte pas, DNF le signale simplement comme un tsflag invalide.

upgrade_group_objects_upgrade
boolean

Définissez ceci à False pour désactiver l'exécution automatique de l'upgrade de groupe lors de l'exécution de la commande upgrade . La valeur par défaut est True (effectuer l'opération).

usr_drift_protected_paths
list

Liste des chemins susceptibles de causer des problèmes lorsque leur contenu dérive par rapport à /usr, par ex. /etc/pam.d/*. Si une transaction transitoire modifiait ces chemins, DNF annule l'opération et affiche une erreur. Prend en charge les globs. Par défaut, glob:/etc/dnf/usr-drift-protected-paths.d/*.conf. Ainsi, une liste de chemins peut être protégée en créant un fichier .conf dans /etc/dnf/usr-drift-protected-paths.d/ contenant un chemin (ou un motif glob) par ligne.

Lors de l'utilisation de persistence=transient sur les systèmes bootc, un calque transitoire est créé sur /usr, et toutes les modifications que DNF apporte à /usr seront abandonnées au redémarrage. Cependant, d'autres chemins tels que /etc et /var ne sont (souvent) pas soutenus par un calque transitoire, donc les modifications y apportées persisteront après les redémarrages. Habituellement, ce « dérive du système de fichiers » est acceptable, mais il peut causer des problèmes dans certaines situations. Par exemple, un fichier de configuration dans /etc partagé par plusieurs paquets pourrait référencer un fichier .so situé sous /usr/lib64 qui n'existe plus.

varsdir
list

Liste des répertoires où sont recherchés les fichiers de définition de variables. Par défaut, "/etc/dnf/vars", "/etc/yum/vars". Voir les fichiers de variables dans la référence de configuration.

zchunk
boolean

Active ou désactive l'utilisation des métadonnées de dépôt compressées au format zchunk (si disponible). La valeur par défaut est True.

OPTIONS DE DÉPÔT

baseurl
liste

Liste des URL pour le dépôt. La valeur par défaut est [].

Les URL sont essayées dans l'ordre listé (équivalent au comportement « failovermethod=priority » de yum).

cost
entier

Le coût relatif de l'accès à ce dépôt, 1000 par défaut. Cette valeur est comparée lorsque les priorités de deux dépôts sont les mêmes. Le dépôt avec le coût le plus bas est choisi. C'est utile pour faire préférer à la bibliothèque les dépôts sur disque aux dépôts distants.

enabled
booléen

Inclure ce dépôt comme source de paquets. La valeur par défaut est Vrai.

gpgkey
liste de chaînes

URL des fichiers de clés GPG qui peuvent être utilisées pour signer les métadonnées et les paquets de ce dépôt, vide par défaut. Si un fichier ne peut pas être vérifié à l'aide des clés déjà importées, l'importation des clés depuis cette option est tentée et les clés sont ensuite utilisées pour la vérification.

metalink
chaîne

URL d'un metalink pour le dépôt. La valeur par défaut est None.

mirrorlist
chaîne

URL d'une liste de miroirs pour le dépôt. La valeur par défaut est None.

module_hotfixes
booléen

Définissez cette option à Vrai pour désactiver le filtrage des RPM de module et rendre tous les RPM du dépôt disponibles. La valeur par défaut est Faux. Cela permet à l'utilisateur de créer un dépôt avec des correctifs chauds sélectionnés qui sont inclus dans un ensemble de paquets sur un système modulaire.

name
chaîne

Un nom lisible par l'homme pour le dépôt. La valeur par défaut est l'identifiant du dépôt.

priority
entier

La valeur de priorité de ce dépôt, 99 par défaut. S'il y a plus d'un paquet candidat pour une opération particulière, celui du dépôt avec la valeur de priorité la plus basse est choisi, éventuellement malgré d'autres inconvénients (par exemple s'il s'agit d'une version inférieure).

type
chaîne

Type des métadonnées du dépôt. Les valeurs prises en charge sont : rpm-md. Alias pour rpm-md: rpm, repomd, rpmmd, yum, YUM.

NOMS DES DÉPÔTS SOURCE ET DEBUGINFO

Pour un dépôt donné avec un identifiant de la forme « <ID>-rpms », son dépôt source correspondant est censé avoir un identifiant de la forme « <ID>-source-rpms » et le dépôt debuginfo un identifiant de la forme « <ID>-debug-rpms ». Sinon (si l'identifiant du dépôt n'a pas le suffixe « -rpms »), le dépôt source est censé avoir un identifiant de la forme « <ID>-source » et le dépôt debuginfo un identifiant de la forme « <ID>-debuginfo ».

Par exemple, pour le dépôt « fedora », le dépôt source est « fedora-source » et le dépôt debuginfo est « fedora-debuginfo ». Pour le dépôt « fedora-rpms », le dépôt source est « fedora-source-rpms » et le dépôt debuginfo est « fedora-debug-rpms ».

VARIABLES DE DÉPÔT

Le côté droit de chaque option de dépôt peut être enrichi par les variables suivantes :

$arch

Fait référence à l'architecture CPU du système, par exemple aarch64, i586, i686 et x86_64.

$basearch

Fait référence à l'architecture de base du système. Par exemple, les machines i686 et i586 ont toutes deux une architecture de base i386, et les machines AMD64 et Intel64 ont une architecture de base x86_64.

$releasever

Fait référence à la version de la distribution du système d'exploitation que DNF déduit des informations disponibles dans la RPMDB.

$releasever_major

Version majeure de $releasever, c'est-à-dire le composant de $releasever survenant avant le premier ..

$releasever_minor

Version mineure de $releasever, c'est-à-dire le composant de $releasever survenant après le premier ..

En plus de ces variables codées en dur, des variables définies par l'utilisateur peuvent également être utilisées. Elles peuvent être définies soit via des fichiers de variables, soit en utilisant des variables d'environnement spéciales. Les noms de ces variables doivent être préfixés par DNF_VAR_ et ne peuvent être composés que de caractères alphanumériques et de tirets bas :

$ DNF_VAR_MY_VARIABLE=value

Pour utiliser une telle variable dans votre configuration de dépôt, retirez le préfixe. Par exemple :

[myrepo]
baseurl=https://example.site/pub/fedora/$MY_VARIABLE/releases/$releasever

Notez qu'il n'est pas possible de remplacer les arch et basearch variables en utilisant des fichiers de variables ou des variables d'environnement.

Bien que les utilisateurs soient encouragés à utiliser des variables nommées, les variables d'environnement numérotées DNF0 - DNF9 sont toujours prises en charge :

$ DNF1=value
[myrepo]
baseurl=https://example.site/pub/fedora/$DNF1/releases/$releasever

Une forme limitée d'expansion de paramètres de type shell est prise en charge pour les variables.

${my_variable:-word} Si my_variable n'est pas définie ou est vide, alors word sera substitué. Sinon, la valeur de my_variable sera substituée.

${my_variable:+word} Si my_variable est définie et n'est pas vide, alors word sera substitué. Sinon, la chaîne vide sera substituée.

Les expansions de paramètres peuvent être imbriquées jusqu'à une profondeur maximale de 32. Par exemple :

${my_defined_variable:+${my_undefined_variable:-foobar}}

sera évalué à foobar.

OPTIONS POUR [MAIN] ET DÉPÔT

Certaines options peuvent être appliquées soit dans la section principale, soit par dépôt, soit dans une combinaison. La valeur fournie dans la section principale est utilisée pour tous les dépôts comme valeur par défaut, que les dépôts peuvent ensuite remplacer dans leur configuration.

bandwidth
taille de stockage

Bande passante totale disponible pour le téléchargement. Significatif lorsqu'il est utilisé avec l'option throttle. La taille de stockage est en octets par défaut mais peut être spécifiée avec une unité de stockage. Les unités valides sont 'k', 'M', 'G'.

countme
booléen

Lorsqu'il est activé, une (et une seule) requête HTTP GET pour le fichier metalink sera sélectionnée au hasard chaque semaine pour porter un drapeau d'URL spécial.

Ce drapeau permet au fournisseur de dépôt d'estimer le nombre de systèmes consommant le dépôt, en comptant de telles requêtes sur une semaine. Cette méthode est plus précise que le simple comptage d'adresses IP uniques (qui est sujet à la fois au sur-comptage et au sous-comptage en raison des baux DHCP courts et du NAT, respectivement).

Il ne s'agit pas d'une requête HTTP hors bande faite dans ce seul but. Seules les requêtes initiées par DNF en fonctionnement normal, telles que la vérification des mises à jour de métadonnées, peuvent porter ce drapeau.

Le drapeau est un simple paramètre "countme=N" ajouté à l'URL metalink où N est un entier représentant le "seau" d'âge auquel ce système appartient. Quatre seaux sont définis, basés sur le nombre de semaines complètes écoulées depuis l'installation d'un système :

seau âge du système
1 première semaine
2 premier mois (2 - 4 semaines)
3 les 6 premiers mois (5 - 24 semaines)
4 plus de 6 mois (> 24 semaines)

Ce nombre vise à distinguer les machines à courte durée de vie (jetables) des installations à long terme et à mieux comprendre comment les systèmes sont utilisés au fil du temps.

Pour déterminer le temps d'installation du système ("époque"), l'heure de dernière modification du fichier machine-id(5) est utilisée comme source unique de vérité. Ce fichier est sémantiquement lié à la durée de vie du système car il est généralement renseigné au moment de l'installation ou lors du premier démarrage par un outil d'installation ou un système d'initialisation (tel que systemd(1)), respectivement, et reste inchangé.

Si le fichier est vide ou manquant (comme dans les conteneurs), l'heure de la toute première requête effectuée à l'aide de l'URL metalink développée (c'est-à-dire avec toutes les variables de dépôt telles que $releasever substituées) qui portait le drapeau est déclarée comme l'époque.

Si aucune URL metalink n'est définie pour ce dépôt mais qu'une URL mirrorlist l'est, cette dernière est utilisée à cette fin à la place.

Par défaut, c'est Faux.

deltarpm
booléen

Lorsqu'il est activé, DNF économise de la bande passante en téléchargeant des fichiers delta RPM beaucoup plus petits, et les reconstruit en RPM localement. Cependant, cela demande beaucoup de CPU et d'I/O. Par défaut, c'est Faux. Nécessite /usr/bin/applydeltarpm sur le système.

deltarpm_percentage
entier

Lorsque la taille relative du delta par rapport au pkg est supérieure à celle-ci, le delta n'est pas utilisé. La valeur par défaut est 75 (les deltas doivent être au moins 25% plus petits que le pkg). Utilisez 0 pour désactiver le traitement des deltas RPM. Les dépôts locaux (avec baseurl <file://>) ont les deltas RPM désactivés par défaut.

enablegroups
booléen

Détermine si DNF autorisera l'utilisation des groupes de paquets pour ce dépôt. Par défaut, c'est Vrai (les groupes de paquets sont autorisés).

excludepkgs
liste

Exclure les paquets de ce dépôt, spécifiés par un nom ou un glob et séparés par une virgule, de toutes les opérations. Peut être désactivé à l'aide de l'interrupteur de ligne de commande --disableexcludes. Par défaut, c'est [].

fastestmirror
booléen

Si activé, la latence du socket TCP est utilisée pour trouver le miroir disponible le plus proche. Un miroir est ensuite sélectionné au hasard avec moins du double de la latence la plus basse à des fins d'équilibrage de charge. Cela remplace l'ordre fourni par le fichier mirrorlist/metalink lui-même, et ne prend pas en compte les paramètres de mirrorlist tels que la bande passante du miroir ni les miroirs préférés pour les adresses IP des clients.

gpgcheck
booléen

Si une vérification de signature GPG doit être effectuée sur les paquets trouvés dans ce dépôt. La valeur par défaut est Faux.

Cette option ne peut être utilisée que pour renforcer la politique de sécurité RPM active définie avec la macro %_pkgverify_level (voir le fichier /usr/lib/rpm/macros pour plus de détails). Cela signifie que si la macro est définie sur 'signature' ou 'all' et que cette option est Faux, elle sera remplacée par Vrai pendant l'exécution de DNF, et un avertissement sera imprimé. Pour supprimer l'avertissement, assurez-vous que cette option est Vraie pour chaque dépôt activé, et activez également localpkg_gpgcheck.

includepkgs
liste

Inclure les paquets de ce dépôt, spécifiés par un nom ou un glob et séparés par une virgule, dans toutes les opérations. Inverse de excludepkgs, DNF exclura tout paquet du dépôt qui ne correspond pas à cette liste. Cela fonctionne en conjonction avec excludepkgs et ne le remplace pas, donc si vous avez 'excludepkgs=*.i386' et 'includepkgs=python*' alors seuls les paquets commençant par python qui n'ont pas d'architecture i386 seront vus par DNF dans ce dépôt. Peut être désactivé à l'aide de l'interrupteur de ligne de commande --disableexcludes. Par défaut, c'est [].

ip_resolve
type d'adresse IP

Détermine comment DNF résout les noms d'hôtes. Définissez-le sur '4'/'IPv4' ou '6'/'IPv6' pour résoudre uniquement vers des adresses IPv4 ou IPv6, respectivement. Par défaut, DNF résout vers les deux types d'adresses.

localpkg_gpgcheck
booléen

Si une vérification de signature GPG doit être effectuée sur les paquets locaux (paquets dans un fichier, pas dans un dépôt). Par défaut, c'est Faux. Cette option est soumise à la politique de sécurité RPM active (voir gpgcheck pour plus de détails).

max_parallel_downloads
entier

Nombre maximum de téléchargements de paquets simultanés. Par défaut, c'est 3. Maximum 20.

metadata_expire
temps en secondes

La période après laquelle le dépôt distant est vérifié pour une mise à jour des métadonnées et, en cas de succès, le cache local des métadonnées est mis à jour. Par défaut, cela correspond à 48 heures. Définissez-le sur -1 ou never pour que le dépôt ne soit jamais considéré comme expiré. L'expiration des métadonnées peut également être déclenchée par un changement d'horodatage des fichiers de configuration (dnf.conf, <repo>.repo). Voir également check_config_file_age.

minrate
taille de stockage

Ceci définit le seuil de basse vitesse en octets par seconde. Si le serveur envoie des données à une vitesse égale ou inférieure à cette valeur pendant au moins timeout secondes, DNF abandonne la connexion. La valeur par défaut est 1000. Les unités valides sont 'k', 'M', 'G'.

password
chaîne

Le mot de passe à utiliser pour se connecter à un dépôt avec authentification HTTP basique. Vide par défaut.

proxy
chaîne

URL d'un serveur proxy à travers lequel se connecter. Définissez sur une chaîne vide dans la configuration du dépôt pour désactiver le paramètre proxy hérité de la section principale. Le format attendu de cette option est <scheme>://<ip-or-hostname>[:port]. (Pour la compatibilité descendante, '_none_' peut être utilisé à la place de la chaîne vide.)

Note : Les variables d'environnement curl (telles que http_proxy) sont effectives si cette option n'est pas définie (ou si '_none_' est défini dans la configuration du dépôt). Voir la page de manuel de curl pour plus de détails.

proxy_username
chaîne

Le nom d'utilisateur à utiliser pour se connecter au serveur proxy. Vide par défaut.

proxy_password
chaîne

Le mot de passe à utiliser pour se connecter au serveur proxy. Vide par défaut.
