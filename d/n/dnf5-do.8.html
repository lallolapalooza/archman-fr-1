NOM

dnf5-do - Commande Do

SYNTAXE

dnf5 do [options] [arguments]

DESCRIPTION

La commande do est une commande universelle pour la gestion des paquets dans DNF5. Elle permet à un utilisateur de définir plusieurs actions (install, remove, upgrade, downgrade, et reinstall).

Contrairement à une série de commandes spécifiques (install, remove, upgrade, downgrade, et reinstall), la commande do gère toutes les actions demandées ensemble et les exécute en une seule transaction. Cela simplifie les opérations complexes et les rend plus efficaces.

Une autre différence est que la commande do permet la spécification explicite des types d'objets dans la transaction : package, group, ou auto. Pour le type group, il est possible de spécifier si un ID de groupe ou un nom de groupe est utilisé. Par défaut, le type auto est actif. Dans ce mode, la commande do se comporte comme les autres commandes, déduisant le type de l'objet de sa spécification. Par exemple, si une spécification commence par le caractère @, elle est traitée comme un ID de groupe ou un module.

Les actions individuelles et les types d'objets sont spécifiés par des options et sont combinables.

Les autres options ont la même signification et le même usage que pour les commandes (install, remove, upgrade, downgrade, et reinstall). Les exceptions sont les options --installed-from-repo et --from-repo. Bien qu'elles aient la même signification, elles ne s'appliquent qu'aux paquets qui les suivent sur la ligne de commande. De plus, elles peuvent être répétées avec des valeurs différentes.

OPTIONS

--action
Action à effectuer sur les éléments suivants.

Il s'agit d'une option obligatoire qui doit précéder les éléments (objets) de la transaction. La commande do a besoin de cette information pour savoir quelle action effectuer sur les éléments spécifiés. Prend en charge : install, remove, upgrade, downgrade, reinstall.

--type
Type des éléments suivants.

Prend en charge : auto, package, group. auto est la valeur par défaut jusqu'à ce que l'option type soit utilisée.

--allowerasing
Permet la suppression de paquets installés pour résoudre tout problème potentiel de dépendances.
--skip-broken
Résout tout problème de dépendances en supprimant les paquets qui causent des problèmes de la transaction.
--skip-unavailable
Permet de sauter les paquets qui ne sont pas disponibles dans les dépôts. Tous les paquets disponibles seront installés.
--allow-downgrade
Active la rétrogradation des dépendances lors de la résolution de l'opération demandée.
--no-allow-downgrade
Désactive la rétrogradation des dépendances lors de la résolution de l'opération demandée.
--installed-from-repo=REPO_ID,...
Filtre les paquets installés par l'ID du dépôt à partir duquel ils ont été installés.
--from-repo=REPO_ID,...
Les paquets (ou leursProvides) spécifiés explicitement sur la ligne de commande ne seront recherchés que dans les dépôts spécifiés.
Ces dépôts sont automatiquement activés.
L'activation et la désactivation des dépôts s'appliquent toujours. Les dépendances de ces paquets seront résolues à partir de tout dépôt activé.
--downloadonly
Télécharge l'ensemble des paquets résolus sans exécuter de transaction RPM.
--offline
Stocke la transaction à effectuer hors ligne. Voir dnf5-offline(8), Commande hors ligne <#offline-command-ref-label>.
--advisories=ADVISORY_NAME,...
Inclut le contenu des avis de sécurité portant les noms spécifiés.
Il s'agit d'une option de liste.
Les valeurs attendues sont les ID d'avis, par exemple FEDORA-2201-123.
Toute commande de transaction (install, upgrade) échouera avec une erreur s'il n'y a pas d'avis existant dans la liste ; ceci peut être contourné en utilisant l'option --skip-unavailable.
--advisory-severities=ADVISORY_SEVERITY,...
Inclut le contenu des avis de sécurité portant les niveaux de gravité spécifiés.
Il s'agit d'une option de liste.
Les valeurs acceptées sont : critical, important, moderate, low, none.
--bzs=BUGZILLA_ID,...
Inclut le contenu des avis de sécurité qui corrigent un ticket de l'ID Bugzilla donné.
Il s'agit d'une option de liste.
Les valeurs attendues sont des ID numériques, par exemple 123123.
Toute commande de transaction (install, upgrade) échouera avec une erreur s'il n'y a pas d'avis corrigeant le ticket donné ; ceci peut être contourné en utilisant l'option --skip-unavailable.
--cves=CVE_ID,...
Inclut le contenu des avis de sécurité qui corrigent un ticket de l'ID CVE (Common Vulnerabilities and Exposures) donné.
Il s'agit d'une option de liste.
Les valeurs attendues sont des ID de chaîne au format CVE, par exemple CVE-2201-0123.
Toute commande de transaction (install, upgrade) échouera avec une erreur s'il n'y a pas d'avis corrigeant le ticket donné ; ceci peut être contourné en utilisant l'option --skip-unavailable.
--security
Inclut le contenu des avis de sécurité.
--bugfix
Inclut le contenu des avis de correction de bugs.
--enhancement
Inclut le contenu des avis d'amélioration.
--newpackage
Inclut le contenu des avis de nouveau paquet.

EXEMPLES

dnf5 do --action=install tito
Installe le paquet tito.
dnf5 do --action=remove sddm-wayland-plasma --action=install sddm-x11
Remplace le paquet sddm-wayland-plasma par sddm-x11.
dnf5 do --action=install --type=group id=office 'name=Games and Entertainment' --type=package iftop --action=remove atop
Installe le groupe office (par ID), le groupe Games and Entertainment (par nom), et le paquet iftop, et supprime le paquet atop.
dnf5 do --action=install pkg --from-repo=myrepo1 pkg1 --from-repo=myrepo2 pkg2 --action=remove --installed-from-repo=compromised_repo '*'
Installe le paquet pkg depuis n'importe quel dépôt activé, ainsi que le paquet pkg1 depuis le dépôt myrepo1 et le paquet pkg2 depuis le dépôt myrepo2. Les dépendances
s pour que ces paquets soient installés depuis n'importe quel dépôt activé. De plus, supprimer tous les paquets installés depuis le dépôt compromis.
