Paquet: bind

DNSSEC-VERIFY(1) BIND 9 DNSSEC-VERIFY(1)

NOM

dnssec-verify - Outil de vérification de zone DNSSEC

SYNTAXE

dnssec-verify [-c classe] [-E moteur] [-I format-entrée] [-J nom-fichier] [-o origine] [-q] [-v niveau] [-V] [-x] [-z] {fichier-zone}

DESCRIPTION

dnssec-verify vérifie qu'une zone est entièrement signée pour chaque algorithme trouvé dans l'ensemble d'enregistrements DNSKEY pour la zone, et que les chaînes NSEC/NSEC3 sont complètes.

OPTIONS

-c classe
Cette option spécifie la classe DNS de la zone.
-E moteur
Cette option spécifie le matériel cryptographique à utiliser, le cas échéant.

Lorsque BIND 9 est compilé avec OpenSSL, cela doit être défini sur l'identifiant du moteur OpenSSL qui pilote l'accélérateur cryptographique ou le module de service matériel (généralement pkcs11).

-I format-entrée
Cette option définit le format du fichier de zone d'entrée. Les formats possibles sont text (par défaut) et raw. Cette option est principalement destinée à être utilisée pour les zones signées dynamiquement, afin que le fichier de zone vidé dans un format non textuel contenant des mises à jour puisse être vérifié indépendamment. Cette option n'est pas utile pour les zones non dynamiques.
-J nom-fichier
Cette option indique à dnssec-verify de lire le journal depuis le fichier donné lors du chargement du fichier de zone.
-o origine
Cette option indique l'origine de la zone. Si elle n'est pas spécifiée, le nom du fichier de zone est supposé être l'origine.
-v niveau
Cette option définit le niveau de débogage.
-V
Cette option affiche les informations de version.
-q
Cette option active le mode silencieux, qui supprime la sortie. Sans cette option, lorsque dnssec-verify est exécuté, il affiche sur la sortie standard le nombre de clés en cours d'utilisation, les algorithmes utilisés pour vérifier que la zone a été correctement signée, et d'autres informations de statut. Avec cette option, toute sortie non-erreur est supprimée, et seul le code de sortie indique le succès.
-x
Cette option vérifie uniquement que l'ensemble d'enregistrements DNSKEY est signé avec des clés de signature de clés. Sans ce drapeau, il est supposé que l'ensemble d'enregistrements DNSKEY est signé par toutes les clés actives. Lorsque ce drapeau est défini, ce n'est pas une erreur si l'ensemble d'enregistrements DNSKEY n'est pas signé par des clés de signature de zone. Cela correspond à l'option -x de dnssec-signzone <#cmdoption-dnssec-signzone-x>.
-z
Cette option indique que le drapeau KSK sur les clés doit être ignoré lors de la détermination si la zone est correctement signée. Sans ce drapeau, il est supposé qu'il existe un enregistrement DNSKEY auto-signé, non révoqué, avec le drapeau KSK défini pour chaque algorithme, et que les ensembles d'enregistrements autres que DNSKEY sont signés avec une clé DNSKEY différente sans le drapeau KSK défini.

Avec ce drapeau défini, BIND 9 exige uniquement que pour chaque algorithme, il y ait au moins un enregistrement DNSKEY auto-signé, non révoqué, quel que soit l'état du drapeau KSK, et que les autres ensembles d'enregistrements soient signés par une clé non révoquée pour le même algorithme qui inclut la clé auto-signée ; la même clé peut être utilisée pour les deux objectifs. Cela correspond à l'option -z de dnssec-signzone <#cmdoption-dnssec-signzone-z>.

fichier-zone
Cette option indique le fichier contenant la zone à signer.
