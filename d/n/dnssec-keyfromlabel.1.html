NOM

dnssec-keyfromlabel - outil de génération de clé DNSSEC

SYNTAXE

dnssec-keyfromlabel {-l label} [-3] [-a algorithme] [-A date/décalage] [-c classe] [-D date/décalage] [-D sync date/décalage] [-E moteur] [-f indicateur] [-G] [-I date/décalage] [-i intervalle] [-k] [-K répertoire] [-L ttl] [-M étiquette_min:étiquette_max] [-n type_nom] [-P date/décalage] [-P sync date/décalage] [-p protocole] [-R date/décalage] [-S clé] [-t type] [-v niveau] [-V] [-y] {nom}

DESCRIPTION

dnssec-keyfromlabel génère une paire de fichiers de clé qui font référence à un objet clé stocké dans un module de service cryptographique matériel (HSM). Le fichier de clé privée peut être utilisé pour la signature DNSSEC des données de zone comme s'il s'agissait d'une clé de signature conventionnelle créée par dnssec-keygen <#std-iscman-dnssec-keygen>, mais le matériel de clé est stocké dans le HSM et la signature réelle a lieu là.

Le nom de la clé est spécifié sur la ligne de commande. Il doit correspondre au nom de la zone pour laquelle la clé est générée.

OPTIONS

-a algorithme
Cette option sélectionne l'algorithme cryptographique. La valeur de algorithme doit être l'un de RSASHA1 (obsolète), NSEC3RSASHA1 (obsolète), RSASHA256, RSASHA512, ECDSAP256SHA256, ECDSAP384SHA384, ED25519, ou ED448.

Ces valeurs ne sont pas sensibles à la casse. Dans certains cas, des abréviations sont prises en charge, telles que ECDSA256 pour ECDSAP256SHA256 et ECDSA384 pour ECDSAP384SHA384. Si RSASHA1 (obsolète) est spécifié avec l'option -3, alors NSEC3RSASHA1 (obsolète) est utilisé à la place.

Cette option est obligatoire sauf lors de l'utilisation de l'option -S, qui copie l'algorithme de la clé précédente.

Modifié dans la version 9.12.0 : La valeur par défaut RSASHA1 (obsolète) pour les nouvelles clés générées a été supprimée.

-3
Cette option utilise un algorithme compatible NSEC3 pour générer une clé DNSSEC. Si cette option est utilisée avec un algorithme qui a des versions NSEC et NSEC3, alors la version NSEC3 est utilisée ; par exemple, dnssec-keygen -3a RSASHA1 spécifie l'algorithme NSEC3RSASHA1 (obsolète).
-E moteur
Cette option spécifie le matériel cryptographique à utiliser.

Lorsque BIND 9 est compilé avec OpenSSL, cela doit être défini sur l'identifiant du moteur OpenSSL qui pilote l'accélérateur cryptographique ou le module de service matériel (généralement pkcs11).

-l etiquette
Cette option spécifie l'étiquette d'une paire de clés dans le matériel cryptographique.

Lorsque BIND 9 est compilé avec le support PKCS#11 basé sur OpenSSL, l'étiquette est une chaîne arbitraire qui identifie une clé particulière. Elle peut être précédée d'un nom de moteur OpenSSL optionnel, suivi d'un deux-points, comme dans pkcs11:labelclé.

-n type_nom
Cette option spécifie le type de propriétaire de la clé. La valeur de type_nom doit être ZONE (pour une clé de zone DNSSEC (KEY/DNSKEY)), HOST ou ENTITY (pour une clé associée à un hôte (KEY)), USER (pour une clé associée à un utilisateur (KEY)), ou OTHER (DNSKEY). Ces valeurs ne sont pas sensibles à la casse.
-C
Cette option active le mode de compatibilité, qui génère une clé de style ancien, sans métadonnées. Par défaut, dnssec-keyfromlabel inclut la date de création de la clé dans les métadonnées stockées avec la clé privée ; d'autres dates peuvent également y être définies, notamment la date de publication, la date d'activation, etc. Les clés qui incluent ces données peuvent être incompatibles avec les versions antérieures de BIND ; l'option -C les supprime.
-c classe
Cette option indique que l'enregistrement DNS contenant la clé doit avoir la classe spécifiée. Si elle n'est pas spécifiée, la classe IN est utilisée.
-f indicateur
Cette option définit l'indicateur spécifié dans le champ indicateur de l'enregistrement KEY/DNSKEY. Les seuls indicateurs reconnus sont KSK (Key-Signing Key) et REVOKE.
-G
Cette option génère une clé, mais ne la publie pas et ne signe pas avec elle. Cette option est incompatible avec -P et -A.
-h
Cette option imprime un bref résumé des options et arguments pour dnssec-keyfromlabel.
-K répertoire
Cette option définit le répertoire dans lequel les fichiers de clé doivent être écrits.
-k
Cette option génère des enregistrements KEY plutôt que des enregistrements DNSKEY.
-L ttl
Cette option définit la durée de vie par défaut (TTL) à utiliser pour cette clé lorsqu'elle est convertie en RR DNSKEY. Il s'agit de la TTL utilisée lorsque la clé est importée dans une zone, à moins qu'il n'y ait déjà un jeu d'enregistrements RR DNSKEY en place, auquel cas la TTL existante aurait la priorité. Définir la TTL par défaut à 0 ou none la supprime.
-M etiquette_min:etiquette_max
Cette option définit la plage des valeurs de tag de clé que dnssec-keyfromlabel acceptera. Si le tag de clé de la nouvelle clé ou le tag de clé de la version révoquée de la nouvelle clé est en dehors de cette plage, la nouvelle clé sera rejetée. Ceci est conçu pour être utilisé lors de la génération de clés dans un scénario multi-signataires, où chaque opérateur se voit attribuer une plage de tags de clé pour éviter les collisions entre différents opérateurs. Les valeurs valides pour etiquette_min et etiquette_max sont [0..65535]. La valeur par défaut permet à toutes les valeurs de tag de clé d'être acceptées.
-p protocole
Cette option définit la valeur du protocole pour la clé. Le protocole est un nombre compris entre 0 et 255. La valeur par défaut est 3 (DNSSEC). D'autres valeurs possibles pour cet argument sont listées dans RFC 2535 https://datatracker.ietf.org/doc/html/rfc2535.html et ses successeurs.
-S clé
Cette option génère une clé comme successeur explicite d'une clé existante. Le nom, l'algorithme, la taille et le type de la clé sont définis pour correspondre au prédécesseur. La date d'activation de la nouvelle clé est définie à la date de désactivation de l'ancienne. La date de publication est définie à la date d'activation moins l'intervalle de pré-publication, qui est de 30 jours par défaut.
-t type
Cette option indique le type de la clé. type doit être l'un de AUTHCONF, NOAUTHCONF, NOAUTH, ou NOCONF. La valeur par défaut est AUTHCONF. AUTH fait référence à la capacité d'authentifier les données, et CONF à la capacité de chiffrer les données.
-v niveau
Cette option définit le niveau de débogage.
-V
Cette option affiche les informations de version.
-y
Cette option permet de générer des fichiers de clé DNSSEC même si l'ID de clé entrerait en collision avec celui d'une clé existante, en cas de révocation de l'une ou l'autre clé. (Cela n'est sûr d'être activé que si RFC 5011 https://datatracker.ietf.org/doc/html/rfc5011.html est utilisé pour la gestion des clés).

EXEMPLES

Pour générer une clé de signature de zone pour la zone example.com avec un HSM, en utilisant l'algorithme ECDSA256 et en définissant l'étiquette de la clé sur key_for_example_com:

dnssec-keyfromlabel -l key_for_example_com -a ECDSAP256SHA256 example.com

OPTIONS DE TEMPS

Les dates peuvent être exprimées au format AAAAMMJJ ou AAAAMMJJHHMMSS (qui est le format utilisé dans les fichiers de clés), ou 'Jour Mois JJ HH:MM:SS AAAA' (tel qu'affiché par dnssec-settime -p), ou en temps UNIX (tel qu'affiché par dnssec-settime -up), ou le littéral now.

L'argument peut être suivi par + ou - et un décalage par rapport à l'heure donnée. Le littéral now peut être omis avant un décalage. Le décalage peut être suivi par l'un des suffixes y, mo, w, d, h, ou mi, de sorte qu'il soit calculé en années (définies comme 365 jours de 24 heures, en ignorant les années bissextiles), mois (définis comme 30 jours de 24 heures), semaines, jours, heures ou minutes, respectivement. Sans un suffixe, le décalage est calculé en secondes.

Pour empêcher explicitement la définition d'une date, utilisez none, never, ou unset.

Tous ces formats ne sont pas sensibles à la casse.

-P date/décalage
Cette option définit la date à laquelle la clé doit être publiée dans la zone. Après cette date, la clé est incluse dans la zone mais n'est pas utilisée pour la signer. Si elle n'est pas définie, et si l'option -G n'a pas été utilisée, la valeur par défaut est la date courante.
sync date/décalage
Cette option définit la date à laquelle les enregistrements CDS et CDNSKEY correspondant à cette clé doivent être publiés dans la zone.
-A date/décalage
Cette option définit la date à laquelle la clé doit être activée. Après cette date, la clé est incluse dans la zone et utilisée pour la signer. Si elle n'est pas définie, et si l'option -G n'a pas été utilisée, la valeur par défaut est la date courante.
-R date/décalage
Cette option définit la date à laquelle la clé doit être révoquée. Après cette date, la clé est marquée comme révoquée. Elle est incluse dans la zone et est utilisée pour la signer.
-I date/décalage
Cette option définit la date à laquelle la clé doit être retirée. Après cette date, la clé est toujours incluse dans la zone, mais elle n'est pas utilisée pour la signer.
-D date/décalage
Cette option définit la date à laquelle la clé doit être supprimée. Après cette date, la clé n'est plus incluse dans la zone. (Cependant, elle peut rester dans le dépôt de clés.)
sync date/décalage
Cette option définit la date à laquelle les enregistrements CDS et CDNSKEY correspondant à cette clé doivent être supprimés.
-i intervalle
Cette option définit l'intervalle de prépublication d'une clé. Si elle est définie, les dates de publication et d'activation doivent être séparées d'au moins cet intervalle. Si la date d'activation est spécifiée mais pas la date de publication, la date de publication vaut par défaut cet intervalle avant la date d'activation ; inversement, si la date de publication est spécifiée mais pas la date d'activation, l'activation est définie à cet intervalle après la publication.

Si la clé est créée comme successeur explicite d'une autre clé, l'intervalle de prépublication par défaut est de 30 jours ; sinon, il est de zéro.

Comme pour les décalages de date, si l'argument est suivi par l'un des suffixes y, mo, w, d, h, ou mi, l'intervalle est mesuré en années, mois, semaines, jours, heures ou minutes, respectivement. Sans suffixe, l'intervalle est mesuré en secondes.

FICHIERS DE CLÉS GÉNÉRÉS

Lorsque dnssec-keyfromlabel se termine avec succès, il affiche une chaîne de la forme Knnnn.+aaa+iiiii sur la sortie standard. C'est une chaîne d'identification pour les fichiers de clés qu'il a générés.

  • nnnn est le nom de la clé.
  • aaa est la représentation numérique de l'algorithme.
  • iiiii est l'identifiant (ou l'empreinte) de la clé.

dnssec-keyfromlabel crée deux fichiers, dont les noms sont basés sur la chaîne affichée. Knnnn.+aaa+iiiii.key contient la clé publique, et Knnnn.+aaa+iiiii.private contient la clé privée.

Le fichier .key contient un enregistrement DNS KEY qui peut être inséré dans un fichier de zone (directement ou avec une instruction $INCLUDE).

Le fichier .private contient des champs spécifiques à l'algorithme. Pour des raisons de sécurité évidentes, ce fichier n'a pas de permission de lecture générale.
