NOM

dnssec-settime - définir les métadonnées temporelles de clé pour une clé DNSSEC

SYNTAXE

dnssec-settime [-f] [-K répertoire] [-L ttl] [-P date/décalage] [-P ds date/décalage] [-P sync date/décalage] [-A date/décalage] [-R date/décalage] [-I date/décalage] [-D date/décalage] [-D ds date/décalage] [-D sync date/décalage] [-S clé] [-i intervalle] [-h] [-V] [-v niveau] [-E moteur] {fichier_clé} [-s] [-g état] [-d état date/décalage] [-k état date/décalage] [-r état date/décalage] [-z état date/décalage]

DESCRIPTION

dnssec-settime lit un fichier de clé privée DNSSEC et définit les métadonnées temporelles de la clé comme spécifié par les options -P, -A, -R, -I et -D. Les métadonnées peuvent ensuite être utilisées par dnssec-signzone <#std-iscman-dnssec-signzone> ou par d'autres logiciels de signature pour déterminer quand une clé doit être publiée, si elle doit être utilisée pour signer une zone, etc.

Si aucune de ces options n'est définie sur la ligne de commande, dnssec-settime affiche simplement les métadonnées temporelles de clé déjà stockées dans la clé.

Lorsque les champs de métadonnées de la clé sont modifiés, les deux fichiers d'une paire de clés ( Knnnn.+aaa+iiiii.key et Knnnn.+aaa+iiiii.private) sont régénérés.

Les métadonnées sont stockées dans le fichier privé. Une description lisible par l'homme des métadonnées est également placée dans des commentaires dans le fichier de clé. Les permissions du fichier privé sont toujours définies pour être inaccessibles à quiconque d'autre que le propriétaire (mode 0600).

Lorsqu'on travaille avec des fichiers d'état, il est possible de mettre à jour les métadonnées temporelles dans ces fichiers également avec -s. Avec cette option, il est également possible de mettre à jour les états de clé avec -d (DS), -k (DNSKEY), -r (RRSIG de KSK), ou -z (RRSIG de ZSK). Les états autorisés sont HIDDEN, RUMOURED, OMNIPRESENT et UNRETENTIVE.

L'état cible de la clé peut également être défini avec -g. Cela doit être HIDDEN ou OMNIPRESENT, représentant si la clé doit être supprimée de la zone ou publiée.

Il est DÉCONSEILLÉ de manipuler les fichiers d'état manuellement, sauf à des fins de test.

OPTIONS

-f
Cette option force la mise à jour d'une clé au format ancien sans champs de métadonnées. Sans cette option, dnssec-settime échoue lors de la tentative de mise à jour d'une clé héritée. Avec cette option, la clé est recréée dans le nouveau format, mais avec les données de clé d'origine conservées. La date de création de la clé est définie sur le moment présent. Si aucune autre valeur n'est spécifiée, les dates de publication et d'activation de la clé sont également définies sur le moment présent.
-K répertoire
Cette option définit le répertoire dans lequel doivent résider les fichiers de clé.
-L ttl
Cette option définit la durée de vie (TTL) par défaut à utiliser pour cette clé lorsqu'elle est convertie en RR DNSKEY. Il s'agit de la TTL utilisée lorsque la clé est importée dans une zone, sauf s'il y avait déjà un jeu d'enregistrements RR DNSKEY en place, auquel cas la TTL existante a la priorité. Si cette valeur n'est pas définie et qu'il n'y a pas d'enregistrement RR DNSKEY existant, la TTL par défaut est celle du SOA. Définir la TTL par défaut à 0 ou none la supprime de la clé.
-h
Cette option affiche un message d'utilisation et quitte.
-V
Cette option imprime les informations de version.
-v niveau
Cette option définit le niveau de débogage.
-E moteur
Cette option spécifie le matériel cryptographique à utiliser, le cas échéant.

Lorsque BIND 9 est compilé avec OpenSSL, cela doit être défini sur l'identifiant du moteur OpenSSL qui pilote l'accélérateur cryptographique ou le module de service matériel (généralement pkcs11).

OPTIONS DE TEMPORISATION

Les dates peuvent être exprimées au format YYYYMMDD ou YYYYMMDDHHMMSS (qui est le format utilisé dans les fichiers de clé), ou 'Jour Mois JJ HH:MM:SS ANNÉE' (tel qu'affiché par dnssec-settime -p), ou le temps Unix epoch (tel qu'affiché par dnssec-settime -up), ou le littéral now.

L'argument peut être suivi de + ou - et d'un décalage par rapport au temps donné. Le littéral now peut être omis avant un décalage. Le décalage peut être suivi de l'un des suffixes y, mo, w, d, h, ou mi, de sorte qu'il soit calculé en années (définies comme 365 jours de 24 heures, ignorant les années bissextiles), mois (définis comme 30 jours de 24 heures), semaines, jours, heures, ou minutes, respectivement. Sans suffixe, le décalage est calculé en secondes.

Pour annuler une date, utilisez none, never, ou unset.

Tous ces formats ne sont pas sensibles à la casse.

-P date/décalage
Cette option définit la date à laquelle une clé doit être publiée dans la zone. Après cette date, la clé est incluse dans la zone mais n'est pas utilisée pour la signer.
ds date/décalage
Cette option définit la date à laquelle les enregistrements DS correspondant à cette clé ont été vus dans la zone parente.
sync date/décalage
Cette option définit la date à laquelle les enregistrements CDS et CDNSKEY correspondant à cette clé doivent être publiés dans la zone.
-A date/décalage
Cette option définit la date à laquelle la clé doit être activée. Après cette date, la clé est incluse dans la zone et utilisée pour la signer.
-R date/décalage
Cette option définit la date à laquelle la clé doit être révoquée. Après cette date, la clé est marquée comme révoquée. Elle est incluse dans la zone et utilisée pour la signer.
-I date/décalage
Cette option définit la date à laquelle la clé doit être retirée. Après cette date, la clé est toujours incluse dans la zone, mais elle n'est pas utilisée pour la signer.
-D date/décalage
Cette option définit la date à laquelle la clé doit être supprimée. Après cette date, la clé n'est plus incluse dans la zone. (Cependant, elle peut rester dans le dépôt de clés.)
ds date/décalage
Cette option définit la date à laquelle les enregistrements DS correspondant à cette clé ont été vus retirés de la zone parente.
sync date/décalage
Cette option définit la date à laquelle les enregistrements CDS et CDNSKEY correspondant à cette clé doivent être supprimés.
-S prédécesseur clé
Cette option sélectionne une clé pour laquelle la clé en cours de modification est un successeur explicite. Le nom, l'algorithme, la taille et le type de la clé prédécesseure doivent correspondre exactement à ceux de la clé en cours de modification. La date d'activation de la clé successeur est définie sur la date de désactivation du prédécesseur. La date de publication est définie sur la date d'activation moins l'intervalle de pré-publication, qui est de 30 jours par défaut.
-i intervalle
Cette option définit l'intervalle de pré-publication pour une clé. S'il est défini, les dates de publication et d'activation doivent être séparées par au moins ce laps de temps. Si la date d'activation est spécifiée mais pas la date de publication, la date de publication
te par défaut cette durée avant la date d'activation ; inversement, si la date de publication est spécifiée mais pas la date d'activation, l'activation est fixée à cette durée après la publication.

Si la clé est créée comme successeur explicite d'une autre clé, l'intervalle de prépublication par défaut est de 30 jours ; sinon, il est de

zéro.

Comme pour les décalages de date, si l'argument est suivi de l'un des suffixes y, mo, w, d, h ou mi, l'intervalle est mesuré en années, mois, se

maines, jours, heures ou minutes, respectivement. Sans suffixe, l'intervalle est mesuré en secondes.
