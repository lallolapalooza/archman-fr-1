NOM

ds-logpipe.py - Créer et lire à partir d'un tube nommé au lieu d'un fichier journal

SYNTAXE

ds-logpipe.py /chemin/complet/vers/tubenommé
[-m maxlignesatransmettre] [-u idutilisateur] [-s pidserveur] [-t delaiserveur] [--plugin=/chemin/vers/fichierplugin.py] [argumentfichierplugin=valeur]

DESCRIPTION

Le script de tube nommé pour les journaux vous permet de remplacer un fichier journal par un tube nommé connecté à un script. Le serveur peut alors envoyer la sortie du journal à un script au lieu d'un fichier journal. Cela vous permet de faire de nombreuses choses différentes telles que :


* journaliser uniquement certains événements, par exemple les échecs de connexion, les connexions à partir de certaines adresses IP, etc.
* journaliser uniquement les lignes qui correspondent à un certain motif
* journaliser uniquement les N dernières lignes - utile pour activer les niveaux de débogage complets des journaux d'erreurs dans les environnements de production
* envoyer un e-mail ou une autre notification lorsqu'un certain événement est détecté

Le script est écrit en python et prend en charge les plugins. Par défaut, le script journalisera les N dernières lignes (par défaut 1000). Deux plugins sont fournis : un pour journaliser uniquement les tentatives de connexion échouées, et un autre qui journalisera uniquement les lignes qui correspondent aux expressions régulières données.

OPTIONS

Un résumé des options est inclus ci-dessous.

/chemin/complet/vers/tubenommé
Requis - chemin complet et nom de fichier du tube nommé. S'il n'existe pas, il sera créé. S'il existe et est un tube nommé, le script l'utilisera. S'il existe et n'est pas un tube, le script s'arrêtera. La propriété sera la même que celle de l'utilisateur exécutant le script (ou voir l'option -u ci-dessous).
-m|--maxlignes=N
Nombre de lignes à mettre en mémoire tampon - la valeur par défaut est 1000.
-u|--idutilisateur=utilisateur
Le tube et tous les autres fichiers créés par le script seront chown() à cet idutilisateur. Il peut s'agir d'un nom d'utilisateur textuel ou d'une valeur d'id utilisateur numérique.
-s|--pidserveur=/chemin/vers/nomserveur.pid
Si vous souhaitez que le script s'arrête lorsqu'un serveur de répertoire particulier existe, spécifiez le chemin complet du fichier contenant le pid du serveur. La valeur par défaut est généralement quelque chose comme /var/run/dirsrv/slapd-<nominstance>.pid où <nominstance> est généralement le nom d'hôte.
-t|--delaiserveur=N
Comme le fichier pid du serveur peut ne pas encore exister lorsque le script est exécuté, le script attendra par défaut 60 secondes que le fichier pid existe et que le serveur démarre. Utilisez cette option pour spécifier un délai différent. L'option -t ne s'applique que lorsque vous utilisez -s ou --serverpid ; sinon, elle ne fait rien.
--pidserveur=P
SI le serveur que vous souhaitez suivre est déjà en cours d'exécution, vous pouvez le spécifier en utilisant cet argument. Si le pid spécifié n'est pas valide, le script s'arrêtera.
-p|--plugin=/chemin/complet/vers/nomplugin.py
Spécifiez un plugin à utiliser. Le plugin doit être un fichier python et doit se terminer par .py. Il doit spécifier une fonction appelée plugin et peut spécifier des fonctions appelées pre et post.
nomplugin.arg1=valeur ... nomplugin.argN=valeur
Vous pouvez spécifier des arguments pour les plugins sur la ligne de commande. S'il y a un plugin spécifié comme --plugin=/chemin/complet/vers/nomplugin.py, les arguments de ce plugin sont spécifiés comme nomplugin.nomarg=valeur. Le script analyse ces arguments et les passe à la fonction pre du plugin sous forme de dictionnaire python. S'il y a plus d'un argument nommé nomplugin.nomarg, les valeurs sont passées sous forme de liste python.

NOTES SUR LE SERVEUR DE RÉPERTOIRE

Le serveur de répertoire devra généralement être configuré pour écrire dans le tube nommé au lieu du fichier journal habituel. Par exemple, utilisez le LDIF suivant pour indiquer au serveur d'utiliser le fichier access.pipe pour le journal d'accès :
dn: cn=config
changetype: modify
replace: nsslapd-accesslog-maxlogsperdir
nsslapd-accesslog-maxlogsperdir: 1
-
replace: nsslapd-accesslog-logexpirationtime
nsslapd-accesslog-logexpirationtime: -1
-
replace: nsslapd-accesslog-logrotationtime
nsslapd-accesslog-logrotationtime: -1
-
replace: nsslapd-accesslog
nsslapd-accesslog: /var/log/dirsrv/slapd-localhost/access.pipe
-
replace: nsslapd-accesslog-logbuffering
nsslapd-accesslog-logbuffering: off

NOTE : Avant de faire cela, vous devriez sauvegarder votre configuration actuelle afin de pouvoir la restaurer plus tard.
ldapsearch ... -s base -b "cn=config" nsslapd-accesslog-maxlogsperdir nsslapd-accesslog-logexpirationtime nsslapd-accesslog-logrotationtime nsslapd-accesslog > savedaccesslog.ldif

Le journal d'erreurs et le journal d'audit ont des attributs de configuration de noms similaires, par exemple nsslapd-errorlog, nsslapd-auditlog. Notez que le journal d'audit est désactivé par défaut - utilisez nsslapd-auditlog-logging-enabled: on pour l'activer.
