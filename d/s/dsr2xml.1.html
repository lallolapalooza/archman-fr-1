NOM

dsr2xml - Convertit un fichier et un jeu de données DICOM SR en XML

SYNOPSIS

dsr2xml [options] dsrfile-in [xmlfile-out]

DESCRIPTION

L'utilitaire dsr2xml convertit le contenu d'un document DICOM Structured Reporting (SR) (format de fichier ou jeu de données brut) en XML (Extensible Markup Language). Le schéma XML dsr2xml.xsd ne suit pas encore de format standard. Cependant, l'application dsr2xml pourrait être améliorée à cet égard à l'avenir (par ex. en prenant en charge HL7/CDA - Clinical Document Architecture).

Si dsr2xml lit un jeu de données brut (données DICOM sans en-tête méta de format de fichier), il essaiera de deviner la syntaxe de transfert en examinant les premiers octets du fichier. Il n'est pas toujours possible de deviner correctement la syntaxe de transfert et il est préférable de convertir un jeu de données en format de fichier chaque fois que possible (à l'aide de l'utilitaire dcmconv ). Il est également possible d'utiliser les options -f et -t[ieb] pour forcer dsr2xml à lire un jeu de données avec une syntaxe de transfert particulière.

PARAMÈTRES

dsrfile-in   Nom du fichier d'entrée DICOM SR à convertir ("-" pour stdin)
xmlfile-out  Nom du fichier de sortie XML (par défaut : stdout)

OPTIONS

options générales

  -h   --help
         affiche ce texte d'aide et quitte
       --version
         affiche les informations de version et quitte
       --arguments
         affiche les arguments de la ligne de commande étendus
  -q   --quiet
         mode silencieux, n'affiche ni avertissements ni erreurs
  -v   --verbose
         mode verbeux, affiche les détails du traitement
  -d   --debug
         mode débogage, affiche les informations de débogage
  -ll  --log-level  [l]evel: constante de chaîne
         (fatal, error, warn, info, debug, trace)
         utilise le niveau l pour le logger
  -lc  --log-config  [f]ilename: chaîne
         utilise le fichier de configuration f pour le logger

options d'entrée

format de fichier d'entrée :
  +f   --read-file
         lit le format de fichier ou le jeu de données (par défaut)
  +fo  --read-file-only
         lit uniquement le format de fichier
  -f   --read-dataset
         lit le jeu de données sans méta-informations de fichier
syntaxe de transfert d'entrée :
  -t=  --read-xfer-auto
         utilise la reconnaissance de syntaxe de transfert (par défaut)
  -td  --read-xfer-detect
         ignore la syntaxe de transfert spécifiée dans l'en-tête méta du fichier
  -te  --read-xfer-little
         lit avec la syntaxe de transfert little endian VR explicite
  -tb  --read-xfer-big
         lit avec la syntaxe de transfert big endian VR explicite
  -ti  --read-xfer-implicit
         lit avec la syntaxe de transfert little endian VR implicite

options de traitement

gestion des erreurs :
  -Er  --unknown-relationship
         accepte un type de relation inconnu/manquant
  -Ev  --invalid-item-value
         accepte une valeur d'élément de contenu invalide
         (par ex. violation de la définition VR ou VM)
  -Ec  --ignore-constraints
         ignore les contraintes de contenu de relation
  -Ee  --ignore-item-errors
         n'interrompt pas en cas d'erreur d'élément de contenu, émet simplement un avertissement
         (par ex. attributs spécifiques au type de valeur manquants)
  -Ei  --skip-invalid-items
         ignore les éléments de contenu invalides (y compris le sous-arbre)
  -Dv  --disable-vr-checker
         désactive la vérification des valeurs de chaîne conformes au VR
jeu de caractères spécifique :
  +Cr  --charset-require
         exige la déclaration d'un jeu de caractères étendu (par défaut)
  +Ca  --charset-assume  [c]harset: chaîne
         suppose le jeu de caractères c si aucun jeu de caractères étendu n'est déclaré
  +Cc  --charset-check-all
         vérifie tous les éléments de données avec des valeurs de chaîne
         (par défaut : uniquement PN, LO, LT, SH, ST, UC et UT)
         # cette option n'est utilisée que pour la vérification étendue de la présence
         # de l'attribut Specific Character Set (0008,0005), mais pas pour la conversion
         # des valeurs d'éléments non affectées en UTF-8 (par ex. les valeurs d'éléments avec un VR de CS)
  +U8  --convert-to-utf8
         convertit toutes les valeurs d'éléments affectées
         par le Specific Character Set (0008,0005) en UTF-8
         # nécessite la prise en charge d'une bibliothèque de codage de caractères
         # sous-jacente (voir la sortie de --version pour savoir laquelle est disponible)

options de sortie

encodage :
  +Ea  --attr-all
         encode tout en attribut XML
         (raccourci pour +Ec, +Er, +Ev et +Et)
  +Ec  --attr-code
         encode la valeur du code, le désignateur du schéma de codage
         et la version du schéma de codage en attribut XML
  +Er  --attr-relationship
         encode le type de relation en attribut XML
  +Ev  --attr-value-type
         encode le type de valeur en attribut XML
  +Et  --attr-template-id
         encode l'identifiant du modèle en attribut XML
  +Ee  --template-envelope
         l'élément modèle englobe les éléments de contenu
         (nécessite +Wt, implique +Et)
structure XML :
  +Xs  --add-schema-reference
         ajoute une référence au schéma XML "dsr2xml.xsd"
         (pas avec +Ea, +Ec, +Er, +Ev, +Et, +Ee, +We)
  +Xn  --use-xml-namespace
         ajoute une déclaration d'espace de noms XML à l'élément racine
écriture :
  +We  --write-empty-tags
         écrit toutes les balises même si leur valeur est vide
  +Wi  --write-item-id
         écrit toujours l'identifiant de l'élément
  +Wt  --write-template-id
         écrit les informations d'identification du modèle

LIGNE DE COMMANDE Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets enclos des valeurs facultatives (0-1), trois points de suite indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie de 0 à n valeurs. Les options de ligne de commande se distinguent des paramètres par un signe '+' ou '-' respectivement. Habituellement, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si des options sont mutuellement exclusives, l'apparence la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants. En outre, un ou plusieurs fichiers de commande peuvent être spécifiés en utilisant le signe '@' comme préfixe au nom de fichier (par exemple @command.

txt

). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (plusieurs espaces blancs sont traités comme un seul séparateur sauf s'ils apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite des lignes de commande longues et déroutantes (un exemple est fourni dans le fichier <datadir>/dumppat.txt ).
