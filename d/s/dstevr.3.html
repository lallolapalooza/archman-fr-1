DSTEVR calcule les valeurs propres et, de manière facultative, les vecteurs propres gauche et/ou droit pour les matrices

OTHER

But

: 
!>
!> DSTEVR calcule les valeurs propres sélectionnées et, de manière facultative,
!> les vecteurs propres d'une matrice réelle symétrique tridiagonale T. Les
!> valeurs propres et les vecteurs propres peuvent être sélectionnés en
!> spécifiant soit une plage de valeurs, soit une plage d'indices pour les
!> valeurs propres souhaitées.
!>
!> Chaque fois que c'est possible, DSTEVR appelle DSTEMR pour calculer le
!> spectre propre en utilisant les représentations robustes relatives
!> (Relatively Robust Representations). DSTEMR calcule les valeurs propres par
!> l'algorithme dqds, tandis que les vecteurs propres orthogonaux sont calculés
!> à partir de diverses représentations L D L^T (également connues sous le nom
!> de représentations robustes relatives). L'orthogonalisation de Gram-Schmidt
!> est évitée autant que possible. Plus précisément, les différentes étapes de
!> l'algorithme sont les suivantes. Pour le i-ème bloc non réduit de T,
!>    (a) Calculer T - sigma_i = L_i D_i L_i^T, de telle sorte que L_i D_i L_i^T
!>         soit une représentation robuste relative,
!>    (b) Calculer les valeurs propres, lambda_j, de L_i D_i L_i^T avec une
!>        précision relative élevée par l'algorithme dqds,
!>    (c) S'il existe un groupe de valeurs propres proches, sigma_i
!>        proche du groupe, et retourner à l'étape (a),
!>    (d) Étant donné la valeur propre approximative lambda_j de L_i D_i L_i^T,
!>        calculer le vecteur propre correspondant en formant une
!>        factorisation tordue révélant le rang.
!> La précision souhaitée de la sortie peut être spécifiée par le paramètre
!> d'entrée ABSTOL.
!>
!> Pour plus de détails, voir , par Inderjit Dhillon,
!> Rapport technique du Computer Science Division n° UCB//CSD-97-971,
!> UC Berkeley, mai 1997.
!>
!>
!> Remarque 1 : DSTEVR appelle DSTEMR lorsque le spectre complet est demandé
!> sur les machines conformes à la norme de points flottants ieee-754.
!> DSTEVR appelle DSTEBZ et DSTEIN sur les machines non-ieee et
!> lorsque des demandes de spectre partiel sont faites.
!>
!> L'exécution normale de DSTEMR peut créer des NaN et des infinis et
!> peut donc être interrompue en raison d'une exception de point flottant dans
!> les environnements qui ne gèrent pas les NaN et les infinis de la manière
!> par défaut de la norme ieee.
!
>

Paramètre

s
JOBZ 
!>          JOBZ est CHARACTER*1
!>          = 'N' :  calculer uniquement les valeurs propres ;
!>          = 'V' :  calculer les valeurs propres et les vecteurs propres.
!
>

RANG

E 
!>          RANGE est CHARACTER*1
!>          = 'A' : toutes les valeurs propres seront trouvées.
!>          = 'V' : toutes les valeurs propres dans l'intervalle semi-ouvert (VL,VU]
!>                 seront trouvées.
!>          = 'I' : les valeurs propres de la IL-ème à la IU-ème seront trouvées.
!>          Pour RANGE = 'V' ou 'I' et IU - IL < N - 1, DSTEBZ et
!>          DSTEIN sont appelés
!
>

N 
!>          N est INTEGER
!>          L'ordre de la matrice.  N >= 0.
!
>

D 
!>          D est un tableau DOUBLE PRECISION, dimension (N)
!>          À l'entrée, les n éléments diagonaux de la matrice
!>          tridiagonale A.
!>          À la sortie, D peut être multiplié par un facteur constant choisi
!>          pour éviter le dépassement/le sous-flux lors du calcul des valeurs propres.
!
>

E 
!>          E est un tableau DOUBLE PRECISION, dimension (max(1,N-1))
!>          À l'entrée, les (n-1) éléments sous-diagonaux de la matrice
!>          tridiagonale A dans les éléments 1 à N-1 de E.
!>          À la sortie, E peut être multiplié par un facteur constant choisi
!>          pour éviter le dépassement/le sous-flux lors du calcul des valeurs propres.
!
>

V

L 
!>          VL est DOUBLE PRECISION
!>          Si RANGE='V', la borne inférieure de l'intervalle à
!>          rechercher pour les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!
>

V

U 
!>          VU est DOUBLE PRECISION
!>          Si RANGE='V', la borne supérieure de l'intervalle à
!>          rechercher pour les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!
>

I

L 
!>          IL est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus petite valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0 ; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!
>

I

U 
!>          IU est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus grande valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0 ; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!
>

ABSTO

L 
!>          ABSTOL est DOUBLE PRECISION
!>          La tolérance d'erreur absolue pour les valeurs propres.
!>          Une valeur propre approximative est acceptée comme convergée
!>          lorsqu'il est déterminé qu'elle se situe dans un intervalle [a,b]
!>          de largeur inférieure ou égale à
!>
!>                  ABSTOL + EPS *   max( |a|,|b| ) ,
!>
!>          où EPS est la précision machine. Si ABSTOL est inférieur ou
!>          égal à zéro, alors EPS*|T| sera utilisé à sa place,
!>          où |T| est la 1-norme de la matrice tridiagonale obtenue
!>          en réduisant A à une forme tridiagonale.
!>
!>          Voir  par Demmel et
!>          Kahan, LAPACK Working Note #3.
!>
!>          Si une précision relative élevée est importante, définissez ABSTOL à
!>          DLAMCH( 'Safe minimum' ). Cela garantira que les valeurs propres
!>          sont calculées avec une précision relative élevée lorsque c'est
!>          possible dans les futures versions. Le code actuel ne fait
!>          aucune garantie concernant la précision relative élevée, mais
!>          les futures versions le feront. Voir J. Barlow et J. Demmel,
!>          , LAPACK Working Note #7, pour une discussion
!>          sur les matrices qui définissent leurs valeurs propres avec une
!>          précision relative élevée.
!
>

M 
!>          M est INTEGER
!>          Le nombre total de valeurs propres trouvées.  0 <= M <= N.
!>          Si RANGE = 'A', M = N, et si RANGE = 'I', M = IU-IL+1.
!
>

W 
!>          W est un tableau DOUBLE PRECISION, dimension (N)
!>          Les M premiers éléments contiennent les valeurs propres sélectionnées
!>          dans l'ordre croissant.
!
>

Z 
!>          Z est un tableau DOUBLE PRECISION, dimension (LDZ, max(1,M) )
!>          Si JOBZ = 'V', alors si INFO = 0, les M premières colonnes de Z
!>          contiennent les vecteurs propres orthonormaux de la matrice A
!>          correspondant aux valeurs propres sélectionnées, avec la i-ème
!>          colonne de Z contenant le vecteur propre associé à W(i).
!>          Remarque : l'utilisateur doit s'assurer qu'au moins max(1,M) colonnes sont
!>          fournies dans le tableau Z ; si RANGE = 'V', la valeur exacte de M
!>          n'est pas connue à l'avance et une borne supérieure doit être utilisée.
!
>

LD

Z 
!>          LDZ est INTEGER
!>          La dimension principale du tableau Z.  LDZ >= 1, et if
!>          JOBZ = 'V', LDZ >= max(1,N).
!
>

ISUPP

Z 
!>          ISUPPZ est un tableau INTEGER, de dimension ( 2*max(1,M) )
!>          Le support des vecteurs propres dans Z, c'est-à-dire les indices
!>          indiquant les éléments non nuls dans Z. Le i-ème vecteur propre
!>          est non nul uniquement dans les éléments ISUPPZ( 2*i-1 ) à
!>          ISUPPZ( 2*i ).
!>          Implémenté uniquement pour RANGE = 'A' ou 'I' et IU - IL = N - 1
!
>

WOR

K 
!>          WORK est un tableau DOUBLE PRECISION, de dimension (MAX(1,LWORK))
!>          À la sortie, si INFO = 0, WORK(1) renvoie la taille optimale (et
!>          minimale) de LWORK.
!
>

LWOR

K 
!>          LWORK est INTEGER
!>          La dimension du tableau WORK.  LWORK >= max(1,20*N).
!>
!>          Si LWORK = -1, une interrogation d'espace de travail est supposée ; la routine
!>          ne calcule que les tailles optimales des tableaux WORK et IWORK,
!>          renvoie ces valeurs comme les premières entrées des tableaux WORK
!>          et IWORK, et aucun message d'erreur lié à LWORK ou
!>          LIWORK n'est émis par XERBLA.
!
>

IWOR

K 
!>          IWORK est un tableau INTEGER, de dimension (MAX(1,LIWORK))
!>          À la sortie, si INFO = 0, IWORK(1) renvoie la taille optimale (et
!>          minimale) de LIWORK.
!
>

LIWOR

K 
!>          LIWORK est INTEGER
!>          La dimension du tableau IWORK.  LIWORK >= max(1,10*N).
!>
!>          Si LIWORK = -1, une interrogation d'espace de travail est supposée ; la
!>          routine ne calcule que les tailles optimales des tableaux WORK et
!>          IWORK, renvoie ces valeurs comme les premières entrées des
!>          tableaux WORK et IWORK, et aucun message d'erreur lié à
!>          LWORK ou LIWORK n'est émis par XERBLA.
!
>

INF

O 
!>          INFO est INTEGER
!>          = 0:  sortie réussie
!>          < 0:  si INFO = -i, le i-ème argument avait une valeur illégale
!>          > 0:  Erreur interne
!
>
