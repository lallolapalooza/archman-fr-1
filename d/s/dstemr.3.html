subroutine dstemr (character jobz, character range, integer n, double precision, dimension( * ) d, double precision, dimension( * ) e, double precision vl, double precision vu, integer il, integer iu, integer m, double precision, dimension( * ) w, double precision, dimension( ldz, * ) z, integer ldz, integer nzc, integer, dimension( * ) isuppz, logical tryrac, double precision, dimension( * ) work, integer lwork, integer, dimension( * ) iwork, integer liwork, integer info)

DSTEMR

But :

!>
!> DSTEMR calcule des valeurs propres sélectionnées et, en option, des vecteurs propres
!> d'une matrice tridiagonale symétrique réelle T. Toute matrice non réductible de ce type possède
!> un ensemble bien défini de valeurs propres réelles distinctes deux à deux ; les vecteurs propres
!> réels correspondants sont orthogonaux deux à deux.
!>
!> Le spectre peut être calculé complètement ou partiellement en spécifiant
!> soit un intervalle (VL,VU], soit une plage d'indices IL:IU pour les valeurs
!> propres désirées.
!>
!> Selon le nombre de valeurs propres désirées, celles-ci sont calculées soit
!> par bissection, soit par l'algorithme dqds. Des vecteurs propres numériquement orthogonaux
!> sont calculés à l'aide de diverses factorisations L D L^T appropriées à proximité de grappes
!> de valeurs propres proches (appelées RRR, Relatively Robust
!> Representations). Un brouillon informel de l'algorithme suit.
!>
!> Pour chaque bloc (sous-matrice) non réductible de T,
!>    (a) Calculer T - sigma I  = L D L^T, de sorte que L et D
!>        définissent toutes les valeurs propres voulues avec une grande précision relative.
!>        Cela signifie que de petites variations relatives des entrées de D et L
!>        n'entraînent que de petites variations relatives des valeurs propres et
!>        des vecteurs propres. La représentation standard (non factorisée) de la
!>        matrice tridiagonale T n'a pas cette propriété en général.
!>    (b) Calculer les valeurs propres avec une précision appropriée.
!>        Si les vecteurs propres sont désirés, l'algorithme n'atteint la pleine
!>        précision des valeurs propres calculées qu'à l'instant précédant
!>        le calcul des vecteurs correspondants, voir les étapes c) et d).
!>    (c) Pour chaque grappe de valeurs propres proches, sélectionner un nouveau
!>        décalage proche de la grappe, trouver une nouvelle factorisation, et affiner
!>        les valeurs propres décalées à une précision appropriée.
!>    (d) Pour chaque valeur propre avec une séparation relative suffisante, calculer
!>        le vecteur propre correspondant en formant une factorisation twistée à révélation de rang.
!>        Revenir à (c) pour toutes les grappes restantes.
!>
!> Pour plus de détails, voir :
!> - Inderjit S. Dhillon et Beresford N. Parlett :
!>   Linear Algebra and its Applications, 387(1), pp. 1-28, août 2004.
!> - Inderjit Dhillon et Beresford Parlett : SIAM Journal on Matrix Analysis and Applications, Vol. 25,
!>   2004. Aussi LAPACK Working Note 154.
!> - Inderjit Dhillon : ,
!>   Computer Science Division Technical Report No. UCB/CSD-97-971,
!>   UC Berkeley, mai 1997.
!>
!> Détails supplémentaires
!> 1.DSTEMR ne fonctionne que sur les machines qui suivent la norme IEEE-754
!> pour les nombres flottants dans leur traitement des infinis et des NaN.
!> Cela permet l'utilisation de boucles internes efficaces en évitant une vérification des
!> diviseurs nuls.
!>

Paramètres

JOBZ 
!>          JOBZ est CHARACTER*1
!>          = 'N' :  calculer uniquement les valeurs propres ;
!>          = 'V' :  calculer les valeurs propres et les vecteurs propres.
!>

RANGE

!>          RANGE est CHARACTER*1
!>          = 'A' : toutes les valeurs propres seront trouvées.
!>          = 'V' : toutes les valeurs propres dans l'intervalle semi-ouvert (VL,VU]
!>                 seront trouvées.
!>          = 'I' : les valeurs propres de la IL-ième à la IU-ième seront trouvées.
!>

N

!>          N est INTEGER
!>          L'ordre de la matrice.  N >= 0.
!>

D

!>          D est un tableau DOUBLE PRECISION, dimension (N)
!>          À l'entrée, les N éléments diagonaux de la matrice tridiagonale
!>          T. À la sortie, D est écrasé.
!>

E

!>          E est un tableau DOUBLE PRECISION, dimension (N)
!>          À l'entrée, les (N-1) éléments sous-diagonaux de la matrice
!>          tridiagonale T dans les éléments 1 à N-1 de E. E(N) n'a pas besoin d'être défini en
!>          entrée, mais est utilisé en interne comme espace de travail.
!>          À la sortie, E est écrasé.
!>

VL

!>          VL est DOUBLE PRECISION
!>
!>          Si RANGE='V', la borne inférieure de l'intervalle dans
!>          lequel rechercher les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

VU

!>          VU est DOUBLE PRECISION
!>
!>          Si RANGE='V', la borne supérieure de l'intervalle dans
!>          lequel rechercher les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

IL

!>          IL est INTEGER
!>
!>          Si RANGE='I', l'indice de la
!>          plus petite valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

IU

!>          IU est INTEGER
!>
!>          Si RANGE='I', l'indice de la
!>          plus grande valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

M

!>          M est INTEGER
!>          Le nombre total de valeurs propres trouvées.  0 <= M <= N.
!>          Si RANGE = 'A', M = N, et si RANGE = 'I', M = IU-IL+1.
!>

W

!>          W est un tableau DOUBLE PRECISION, dimension (N)
!>          Les M premiers éléments contiennent les valeurs propres sélectionnées dans
!>          l'ordre croissant.
!>

Z

!>          Z est un tableau DOUBLE PRECISION, dimension (LDZ, max(1,M) )
!>          Si JOBZ = 'V', et si INFO = 0, alors les M premières colonnes de Z
!>          contiennent les vecteurs propres orthonormaux de la matrice T
!>          correspondant aux valeurs propres sélectionnées, avec la i-ième
!>          colonne de Z contenant le vecteur propre associé à W(i).
!>          Si JOBZ = 'N', alors Z n'est pas référencé.
!>          Remarque : l'utilisateur doit s'assurer qu'au moins max(1,M) colonnes sont
!>          fournies dans le tableau Z ; si RANGE = 'V', la valeur exacte de M
!>          n'est pas connue à l'avance et peut être calculée avec une
!>          interrogation d'espace de travail en définissant NZC = -1, voir ci-dessous.
!>

LDZ

!>          LDZ est INTEGER
!>          La dimension principale du tableau Z.  LDZ >= 1, et si
!>          JOBZ = 'V', alors LDZ >= max(1,N).
!>

NZC

!>          NZC est INTEGER
!>          Le nombre de vecteurs propres à contenir dans le tableau Z.
!>          Si RANGE = 'A', alors NZC >= max(1,N).
!>          Si RANGE = 'V', alors NZC >= le nombre de valeurs propres dans (VL,VU].
!>          Si RANGE = 'I', alors NZC >= IU-IL+1.
!>          Si NZC = -1, alors une interrogation d'espace de travail est supposée ; la
!>          routine calcule le nombre de colonnes du tableau Z qui
!>          sont nécessaires pour contenir les vecteurs propres.
!>          Cette valeur est retournée comme la première entrée du tableau Z, et
!>          aucun message d'erreur lié à NZC n'est émis par XERBLA.
!>

ISUPPZ

!>          ISUPPZ est un tableau INTEGER, dimension ( 2*max(1,M) )
!>          Le support des vecteurs propres dans Z, c'est-à-dire les indices
!>          indiquant les éléments non nuls dans Z. Le vecteur propre calculé à la i-ième position
!>          est non nulo seulement dans les éléments ISUPPZ( 2*i-1 ) à
!>          ISUPPZ( 2*i ). Ceci est pertinent dans le cas où la matrice
!>          est séparée. ISUPPZ n'est accédé que lorsque JOBZ est 'V' et N > 0.
!>

TRYRAC

!>          TRYRAC est LOGIQUE
!>          Si TRYRAC = .VRAI., indique que le code doit vérifier si
!>          la matrice tridiagonale définit ses valeurs propres avec une
!>          haute précision relative. Si tel est le cas, le code utilise des
!>          algorithmes préservant la précision relative qui peuvent être
!>          (un peu) plus lents en fonction de la matrice. Si la matrice ne
!>          définit pas ses valeurs propres avec une haute précision relative,
!>          le code peut utiliser des algorithmes potentiellement plus rapides.
!>          Si TRYRAC = .FAUX., le code n'est pas tenu de garantir des
!>          valeurs propres relativement précises et peut utiliser les
!>          techniques les plus rapides possibles.
!>          À la sortie, un TRYRAC .VRAI. sera mis à .FAUX. si la matrice
!>          ne définit pas ses valeurs propres avec une haute précision relative.
!>

WORK

!>          WORK est un tableau de DOUBLE PRÉCISION, de dimension (LWORK)
!>          À la sortie, si INFO = 0, WORK(1) contient la taille optimale
!>          (et minimale) de LWORK.
!>

LWORK

!>          LWORK est un ENTIER
!>          La dimension du tableau WORK. LWORK >= max(1,18*N)
!>          si JOBZ = 'V', et LWORK >= max(1,12*N) si JOBZ = 'N'.
!>          Si LWORK = -1, alors une requête d'espace de travail est supposée ; la
!>          routine calcule seulement la taille optimale du tableau WORK,
!>          renvoie cette valeur comme première entrée du tableau WORK, et aucun
!>          message d'erreur lié à LWORK n'est émis par XERBLA.
!>

IWORK

!>          IWORK est un tableau d'ENTIERS, de dimension (LIWORK)
!>          À la sortie, si INFO = 0, IWORK(1) contient la taille optimale
!>          de LIWORK.
!>

LIWORK

!>          LIWORK est un ENTIER
!>          La dimension du tableau IWORK. LIWORK >= max(1,10*N)
!>          si les vecteurs propres sont désirés, et LIWORK >= max(1,8*N)
!>          si seulement les valeurs propres doivent être calculées.
!>          Si LIWORK = -1, alors une requête d'espace de travail est supposée ; la
!>          routine calcule seulement la taille optimale du tableau IWORK,
!>          renvoie cette valeur comme première entrée du tableau IWORK, et
!>          aucun message d'erreur lié à LIWORK n'est émis par XERBLA.
!>

INFO

!>          INFO est un ENTIER
!>          À la sortie, INFO
!>          = 0 : sortie réussie
!>          < 0 : si INFO = -i, le i-ème argument avait une valeur illégale
!>          > 0 : si INFO = 1X, erreur interne dans DLARRE,
!>                si INFO = 2X, erreur interne dans DLARRV.
!>                Ici, le chiffre X = ABS( IINFO ) < 10, où IINFO est
!>                le code d'erreur non nul renvoyé par DLARRE ou
!>                DLARRV, respectivement.
!>
