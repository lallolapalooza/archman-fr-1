DESCRIPTIO

N

L'utilitaire dsrdump affiche le contenu d'un document DICOM Structured Reporting (SR) (format fichier ou jeu de données brut) sur la sortie standard sous forme textuelle. Le contenu du document suit le format proposé dans le livre de David Clunie « DICOM Structured Reporting » (PixelMed Publishing, 2000)

.

Si dsrdump lit un jeu de données brut (données DICOM sans en-tête méta de fichier), il essaiera de deviner la syntaxe de transfert en examinant les premiers octets du fichier. Il n'est pas toujours possible de deviner correctement la syntaxe de transfert et il est préférable de convertir un jeu de données en format fichier chaque fois que c'est possible (en utilisant l'utilitaire dcmconv). Il est également possible d'utiliser les options -f et -t[ieb] pour forcer dsrdump à lire un jeu de données avec

une syntaxe de tran
sfert particulière.

JOURNALISATI

ON

Le niveau de journalisation de sortie des différentes outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seules les erreurs et les avertissements sont écrits sur le flux d'erreur standard. En utilisant l'option --verbose, des messages informatifs tels que les détails de traitement sont également rapportés. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par ex. à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés en utilisant l'option --log-level. En mode --quiet, seules les erreurs fatales sont rapportées. Dans de tels événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, voir la documentation du module « oflog »

.

Si la sortie de journalisation doit être écrite dans un fichier (avec rotation du journal de fichier en option), dans syslog (Unix) ou dans le journal des événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/l

ogger
.cfg.

LIGNE DE

COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets enclos des valeurs facultatives (0-1), trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie de 0 à n

valeurs.

Les options de la ligne de commande sont distinguées des paramètres par un signe '+' ou '-' en tête, respectivement. Habituellement, l'ordre et la position des options de la ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si options sont mutuellement exclusifs, la dernière occurrence est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix

courants.

De plus, un ou plusieurs fichiers de commandes peuvent être spécifiés en utilisant le signe '@' comme préfixe du nom de fichier (par ex. @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (les espaces multiples sont traités comme un seul séparateur, sauf s'ils apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite des lignes de commande longues et déroutantes (un exemple est fourni dans le fichier <datadir>/du

mppat
.txt).

ENVIRONNEMEN

T

L'utilitaire dsrdump essaiera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH. Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé, sauf si le dictionnaire est intégré à l'application (par défaut sous Windows)

.

Le comportement par défaut doit être préféré et la variable d'environnement DCMDICTPATH ne doit être utilisée que lorsque des dictionnaires de données alternatifs sont nécessaires. La variable d'environnement DCMDICTPATH a le même format que la variable PATH du shell Unix, un deux-points (":") séparant les entrées. Sur les systèmes Windows, un point-virgule (";") est utilisé comme séparateur. Le code du dictionnaire de données essaiera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH. C'est une erreur si aucun dictionnaire de données ne peut être

chargé.

Selon les options de ligne de commande spécifiées, l'utilitaire dsrdump essaiera de charger des tables de correspondance de jeux de caractères. Cela se produit lorsque DCMTK a été compilé avec la bibliothèque oficonv (qui est la configuration par défaut) et que les tables de correspondance ne sont pas intégrées à la bibliothèque (par défaut lorsque DCMTK utilise des bibliothèques partagées)

.

Les fichiers de tables de correspondance sont attendus dans le <datadir> de DCMTK. La variable d'environnement DCMICONVPATH peut être utilisée pour spécifier un emplacement différent. Si un emplacement diffé

rent est spécifié, ces tables de correspondance
remplacent également toutes les tables intégrées.
