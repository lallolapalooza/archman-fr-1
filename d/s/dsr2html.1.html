NOM

dsr2html - Rendre un fichier DICOM SR et un ensemble de données en HTML/XHTML

SYNTAXE

dsr2html [options] dsrfile-in [htmlfile-out]

DESCRIPTION

L'utilitaire dsr2html rend le contenu d'un document DICOM Structured Reporting (SR) (format de fichier ou ensemble de données brut) en HTML (Hyper Text Markup Language) version 3.2 ou 4.01 ainsi qu'en XHTML (Extensible Hyper Text Markup Language) version 1.1.

Si dsr2html lit un ensemble de données brut (données DICOM sans en-tête méta de format de fichier), il tentera de deviner la syntaxe de transfert en examinant les premiers octets du fichier. Il n'est pas toujours possible de deviner correctement la syntaxe de transfert, il est donc préférable de convertir un ensemble de données en format de fichier autant que possible (en utilisant l'utilitaire dcmconv). Il est également possible d'utiliser les options -f et -t[ieb] pour forcer dsr2html à lire un ensemble de données avec une syntaxe de transfert particulière.

PARAMETRES

dsrfile-in    Nom du fichier d'entrée DICOM SR à rendre ("-" pour stdin)
htmlfile-out  Nom du fichier de sortie HTML/XHTML (par défaut : stdout)

OPTIONS

options générales

  -h   --help
         affiche ce texte d'aide et quitte
       --version
         affiche les informations de version et quitte
       --arguments
         affiche les arguments de ligne de commande étendus
  -q   --quiet
         mode silencieux, n'affiche aucun avertissement ni erreur
  -v   --verbose
         mode verbeux, affiche les détails du traitement
  -d   --debug
         mode debug, affiche les informations de débogage
  -ll  --log-level  [l]evel: chaîne de caractères
         (fatal, error, warn, info, debug, trace)
         utilise le niveau l pour le logger
  -lc  --log-config  [f]ilename: chaîne de caractères
         utilise le fichier de configuration f pour le logger

options d'entrée

format de fichier d'entrée :
  +f   --read-file
         lit le format de fichier ou l'ensemble de données (par défaut)
  +fo  --read-file-only
         lit uniquement le format de fichier
  -f   --read-dataset
         lit l'ensemble de données sans les métadonnées du fichier
syntaxe de transfert d'entrée :
  -t=  --read-xfer-auto
         utilise la reconnaissance TS (par défaut)
  -td  --read-xfer-detect
         ignore la TS spécifiée dans l'en-tête méta du fichier
  -te  --read-xfer-little
         lit avec la syntaxe de transfert explicite VR little endian
  -tb  --read-xfer-big
         lit avec la syntaxe de transfert explicite VR big endian
  -ti  --read-xfer-implicit
         lit avec la syntaxe de transfert VR implicite little endian

options de traitement

informations supplémentaires :
  -Ip  --processing-details
         affiche l'élément de contenu actuellement traité
gestion des erreurs :
  -Er  --unknown-relationship
         accepte un type de relation inconnu/manquant
  -Ev  --invalid-item-value
         accepte une valeur d'élément de contenu invalide
         (par exemple, violation de la définition VR ou VM)
  -Ec  --ignore-constraints
         ignore les contraintes de contenu des relations
  -Ee  --ignore-item-errors
         n'interrompt pas en cas d'erreurs d'élément de contenu, affiche seulement un avertissement
         (par exemple, attributs spécifiques au type de valeur manquants)
  -Ei  --skip-invalid-items
         ignore les éléments de contenu invalides (y compris l'arbre de sous-éléments)
  -Dv  --disable-vr-checker
         désactive la vérification des valeurs de chaînes conformes à VR
jeu de caractères spécifique :
  +Cr  --charset-require
         exige la déclaration d'un jeu de caractères étendu (par défaut)
  +Ca  --charset-assume  [c]harset: chaîne de caractères
         suppose le jeu de caractères c si aucun jeu de caractères étendu n'est déclaré
       --charset-check-all
         vérifie tous les éléments de données avec des valeurs de chaîne
         (par défaut : uniquement PN, LO, LT, SH, ST, UC et UT)
         # cette option est uniquement utilisée pour la vérification étendue afin de déterminer si
         # l'attribut Specific Character Set (0008,0005) doit être
         # présent, mais pas pour la conversion des valeurs d'élément non affectées
         # en UTF-8 (par exemple, valeurs d'élément avec un VR de CS)
  +U8  --convert-to-utf8
         convertit toutes les valeurs d'élément affectées
         par le jeu de caractères spécifique (0008,0005) en UTF-8
         # nécessite la prise en charge d'une bibliothèque d'encodage de caractères sous-jacente
         # (voir la sortie de --version pour savoir laquelle est disponible)

options de sortie

compatibilité HTML/XHTML :
  +H3  --html-3.2
         utilise uniquement des fonctionnalités compatibles HTML version 3.2
  +H4  --html-4.0
         autorise toutes les fonctionnalités HTML version 4.01 (par défaut)
  +X1  --xhtml-1.1
         est conforme à la spécification XHTML version 1.1
  +Hd  --add-document-type
         ajoute une référence à la définition de type de document SGML
feuille de style en cascade (CSS), pas avec HTML 3.2 :
  +Sr  --css-reference  URL: chaîne de caractères
         ajoute une référence à la CSS spécifiée au document
  +Sf  --css-file  [f]ilename: chaîne de caractères
         incorpore le contenu de la CSS spécifiée dans le document
rendu général :
  +Ri  --expand-inline
         développe les éléments de contenu courts en ligne (par défaut)
  -Ri  --never-expand-inline
         ne développe jamais les éléments de contenu en ligne
  +Ra  --always-expand-inline
         développe toujours les éléments de contenu en ligne
  +Rd  --render-full-data
         rend les données complètes des éléments de contenu
  +Rt  --section-title-inline
         rend les titres de section en ligne, pas séparément
  +Rh  --hyperlink-url-prefix  [p]refix: chaîne de caractères
         utilise le préfixe d'URL p pour les hyperliens vers les objets composites
         (par défaut : http://localhost/dicom.cgi)
rendu du document :
  +Dt  --document-type-title
         utilise le type de document comme titre du document (par défaut)
  +Dp  --patient-info-title
         utilise les informations du patient comme titre du document
  -Dh  --no-document-header
         ne rend pas les informations générales du document
rendu des codes :
  +Ci  --render-inline-codes
         rend les codes dans des blocs de texte continus
  +Cn  --concept-name-codes
         rend le code des noms de concepts
  +Cu  --numeric-unit-codes
         rend le code des unités de mesure numériques
  +Cv  --code-value-unit
         utilise la valeur du code comme unité de mesure (par défaut)
  +Cm  --code-meaning-unit
         utilise la signification du code comme unité de mesure
  +Cc  --render-all-codes
         rend tous les codes (implique +Ci, +Cn et +Cu)
  +Ct  --code-details-tooltip
         rend les détails du code sous forme d'infobulle (implique +Cc)

L'encodage HTML/XHTML est déterminé automatiquement à partir de l'attribut DICOM (0008,0005) "Specific Character Set" en utilisant le mappage suivant :

ASCII         (ISO_IR 6)                       =>  (aucun)
UTF-8         "ISO_IR 192"                     =>  "UTF-8"
ISO Latin 1   "ISO_IR 100"                     =>  "ISO-8859-1"
ISO Latin 2   "ISO_IR 101"                     =>  "ISO-8859-2"
ISO Latin 3   "ISO_IR 109"                     =>  "ISO-8859-3"
ISO Latin 4   "ISO_IR 110"                     =>  "ISO-8859-4"
ISO Latin 5   "ISO_IR 148"                     =>  "ISO-8859-9"
ISO Latin 9   "ISO_IR 203"                     =>  "ISO-8859-15"
Cyrillique    "ISO_IR 144"                     =>  "

Si cet attribut DICOM est absent du fichier d'entrée, bien qu'il soit nécessaire, l'option --charset-assume peut être utilisée pour spécifier manuellement un jeu de caractères approprié (à l'aide de l'un des termes définis par DICOM). Pour des raisons de rétrocompatibilité avec les versions précédentes de cet outil, les termes suivants sont également pris en charge et automatiquement associés aux termes DICOM correspondants : latin-1, latin-2, latin-3, latin-4, latin-5, latin-9, cyrillic, arabic, greek, hebrew.

L'option --convert-to-utf8 peut être utilisée pour convertir le fichier ou le jeu de données DICOM en encodage UTF-8 avant le rendu au format HTML/XHTML.

JOURNALISATION

Le niveau de sortie de journalisation des différentes lignes de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seules les erreurs et les avertissements sont écrits sur le flux d'erreur standard. En utilisant l'option --verbose les messages informatifs tels que les détails de traitement sont également rapportés. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet seules les erreurs fatales sont rapportées. En cas d'erreur aussi grave, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, voir la documentation du module "oflog".

Si la sortie de journalisation doit être écrite dans un fichier (éventuellement avec rotation des journaux), dans syslog (Unix) ou dans le journal des événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets enclos des valeurs facultatives (0-1), les trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie de 0 à n valeurs.

Les options de ligne de commande se distinguent des paramètres par un signe '+' ou '-' en tête, respectivement. Habituellement, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si des options sont mutuellement exclusives, la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

De plus, un ou plusieurs fichiers de commandes peuvent être spécifiés en utilisant le signe '@' comme préfixe du nom de fichier (par exemple @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (les multiples espaces blancs sont traités comme un seul séparateur à moins qu'ils n'apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commandes ne peut pas contenir un autre fichier de commandes. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite des lignes de commande longues et déroutantes (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

ENVIRONNEMENT

L'utilitaire dsr2html tentera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH . Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé, à moins que le dictionnaire ne soit intégré à l'application (par défaut sous Windows).

Le comportement par défaut doit être préféré et la variable DCMDICTPATH d'environnement ne doit être utilisée que lorsque des dictionnaires de données alternatifs sont nécessaires. La variable DCMDICTPATH d'environnement a le même format que la variable PATH du shell Unix, un deux-points (":") séparant les entrées. Sur les systèmes Windows, un point-virgule (";") est utilisé comme séparateur. Le code du dictionnaire de données tentera de charger chaque fichier spécifié dans la variable DCMDICTPATH d'environnement. C'est une erreur si aucun dictionnaire de données ne peut être chargé.

Selon les options de ligne de commande spécifiées, l'utilitaire dsr2html tentera de charger les tables de correspondance de jeu de caractères. Cela se produit lorsque DCMTK a été compilé avec la bibliothèque oficonv (ce qui est le cas par défaut) et que les tables de correspondance ne sont pas intégrées à la bibliothèque (par défaut lorsque DCMTK utilise des bibliothèques partagées).

Les fichiers de table de correspondance sont attendus dans <datadir>de DCMTK. La variable DCMICONVPATH d'environnement peut être utilisée pour spécifier un emplacement différent. Si un emplacement différent est spécifié, ces tables de correspondance remplacent également toutes les tables intégrées.
