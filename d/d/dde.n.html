NOM

dde - Exécuter une commande Dynamic Data Exchange

SYNOPSIS

package require dde 1.4

dde servername ?-force? ?-handler proc? ?--? ?topic?

dde execute ?-async? ?-binary? service topic data

dde poke ?-binary? service topic item data

dde request ?-binary? service topic item

dde services service topic

dde eval ?-async? topic cmd ?arg arg ...?

DESCRIPTION

Cette commande permet à une application d'envoyer une commande Dynamic Data Exchange (DDE) lorsqu'elle s'exécute sous Microsoft Windows. Dynamic Data Exchange est un mécanisme permettant aux applications d'échanger des données brutes. Chaque transaction DDE nécessite un nom de service et un topic. À la fois le nom de service et le topic sont définis par l'application ; Tcl utilise le nom de service TclEval, tandis que le nom du topic est le nom de l'interpréteur donné par dde servername. D'autres applications ont leurs propres noms de service et leurs topics. Par exemple, Microsoft Excel a le nom de service Excel.

COMMANDES DDE

Les commandes suivantes font partie d'un sous-ensemble de l'ensemble complet des commandes Dynamic Data Exchange.

dde servername ?-force? ?-handler proc? ?--? ?topic?
dde servername enregistre l'interpréteur comme un serveur DDE avec le nom de service TclEval et le nom de topic spécifié par topic. Si aucun topic n'est donné, dde servername retourne le nom du topic courant ou la chaîne vide s'il n'est pas enregistré comme service. Si le nom de topic donné est déjà utilisé, un suffixe de la forme « #2 » ou « #3 » est ajouté au nom pour le rendre unique. Le résultat de la commande sera le nom réellement utilisé. L'option -force est utilisée pour forcer l'enregistrement du nom de topic exactement tel que donné.

L'option -handler spécifie une procédure Tcl qui sera appelée pour traiter les appels au serveur dde. Si le paquet a été chargé dans un interpréteur sûr, une procédure -handler doit être définie. La procédure est appelée avec tous les arguments fournis par l'appel distant.

dde execute ?-async? ?-binary? service topic data
dde execute prend les data et les envoie au serveur indiqué par service avec le topic indiqué par topic. Typiquement, service est le nom d'une application, et topic est un fichier sur lequel travailler. Le champ data est donné à l'application distante. Typiquement, l'application traite le champ data comme un script, et le script est exécuté dans l'application. L'option -async demande une invocation asynchrone. La commande retourne un message d'erreur si le script ne s'est pas exécuté, sauf si l'indicateur -async a été utilisé, auquel cas la commande retourne immédiatement sans erreur. Sans l'option -binary toutes les données seront envoyées en unicode. Pour les clients dde qui n'implémentent pas le format de presse-papiers CF_UNICODE, cela sera automatiquement traduit vers l'encodage du système. Vous pouvez utiliser l'option -binary en combinaison avec le résultat de encoding convertto pour envoyer des données dans n'importe quel autre encodage.
dde poke ?-binary? service topic item data
dde poke passe les data au serveur indiqué par service en utilisant le topic et l' item spécifiés. Typiquement, service est le nom d'une application. topic est spécifique à l'application mais peut être une commande pour le serveur ou le nom d'un fichier sur lequel travailler. L' item est également spécifique à l'application et est souvent non utilisé, mais il doit toujours être non nul. Le champ data est donné à l'application distante. Sans l'option -binary toutes les données seront envoyées en unicode. Pour les clients dde qui n'implémentent pas le format de presse-papiers CF_UNICODE, cela sera automatiquement traduit vers l'encodage du système. Vous pouvez utiliser l'option -binary en combinaison avec le résultat de encoding convertto pour envoyer des données dans n'importe quel autre encodage.
dde request ?-binary? service topic item
dde request est typiquement utilisé pour obtenir la valeur de quelque chose ; la valeur d'une cellule dans Microsoft Excel ou le texte d'une sélection dans Microsoft Word. service est typiquement le nom d'une application, topic est typiquement le nom du fichier, et item est spécifique à l'application. La commande retourne la valeur de item telle que définie dans l'application. Normalement, cela est interprété comme une chaîne avec un terminateur null. Si -binary est spécifié, le résultat est retourné sous forme de tableau d'octets.
dde services service topic
dde services retourne une liste de paires service-topic qui existent actuellement sur la machine. Si service et topic sont tous deux des chaînes vides ({}), toutes les paires service-topic actuellement disponibles sur le système sont retournées. Si service est vide et topic ne l'est pas, alors tous les services avec le topic spécifié sont retournés. Si service n'est pas vide et topic l'est, tous les topics pour un service donné sont retournés. Si les deux ne sont pas vides, si cette paire service-topic existe actuellement, elle est retournée ; sinon, une chaîne vide est retournée.
dde eval ?-async? topic cmd ?arg arg ...?
dde eval évalue une commande et ses arguments en utilisant l'interpréteur spécifié par topic. Le service DDE doit être le service TclEval . L'option -async demande une invocation asynchrone. La commande retourne un message d'erreur si le script ne s'est pas exécuté, sauf si l'indicateur -async a été utilisé, auquel cas la commande retourne immédiatement sans erreur. Cette commande peut être utilisée pour remplacer send sous Windows.

DDE ET TCL

Un interpréteur Tcl a toujours un nom de service TclEval. Chaque interpréteur différent de toutes les applications Tcl en cours d'exécution doit recevoir un nom unique spécifié par dde servername. Chaque interp est disponible comme un topic DDE seulement si la commande dde servername a été utilisée pour définir le nom du topic pour chaque interp. Ainsi, une commande dde services TclEval {} retournera une liste de paires service-topic, où chacun des interps actuellement en cours d'exécution sera un topic.

Lorsque Tcl traite une commande dde execute , les données pour l'exécution sont exécutées comme un script dans l'interp nommé par le topic de la commande dde execute .

Lorsque Tcl traite une commande dde request , il retourne la valeur de la variable donnée dans la commande dde dans le contexte de l'interp nommé par le topic dde. Tcl réserve la variable $TCLEVAL$EXECUTE$RESULT pour un usage interne, et les commandes dde request pour cette variable donneront des résultats imprévisibles.

Une application externe qui souhaite exécuter un script dans Tcl doit faire en sorte que ce script stocke son résultat dans une variable, exécute la commande dde execute , puis exécute dde request pour obtenir la valeur de la variable.

Lors de l'utilisation de DDE, veillez à vous assurer que la file d'événements est vidée en utilisant soit update ou vwait. Cela se produit par défaut lors de l'utilisation de wish sauf si une commande bloquante est appelée (comme exec sans ajouter le & pour mettre le processus en arrière-plan). Si pour une raison quelconque la file d'événements n'est pas vidée, les commandes DDE peuvent se bloquer jusqu'à ce que la file d'événements soit vidée. Cela peut créer une situation d'interblocage.

EXEMPLE

Cela demande à Internet Explorer (qui doit déjà être en cours d'exécution) d'aller sur un site web particulièrement important :

package require dde
dde execute -async iexplore WWW_OpenURL http://www.tcl-lang.org/
