AppleTalk

.

Seules les couches DDP et AARP sont présentes dans le noyau. Elles sont conçues pour être utilisées via les bibliothèques de protocoles netatalk. Cette page documente l'interface pour ceux qui souhaitent ou doivent utiliser la couche DDP directement. La communication entre AppleTalk et le programme

utilisateur

fonctionne via une interface de socket compatible BSD. Pour plus d'informations sur les sockets, voir socket(7). Un socket AppleTalk est créé en appelant la fonct

ion

socket(2) avec un argument de famille de socket AF_APPLETALK. Les types de socket valides sont SOCK_DGRAM pour ouvrir un socket ddp ou SOCK_RAW pour ouvrir un socket brut. protocol est le protocole AppleTalk à recevoir ou à envoyer. Pour SOCK_RAW, vous devez spécifier ATPROTO_DDP. Les sockets bruts ne peuvent être ouverts que par

un

processus dont l'UID effectif est 0 ou lorsque le processus possède la capacité CAP_NET_RAW. Format d'adresse Une adresse de

sat_port contient le port. Les numéros de port inférieurs à 129 sont connus comme ports réservés. Seuls les processus ayant l'UID effectif 0 ou la capacité CAP_NET_BIND_SERVICE peuvent bind(2) à ces sockets. sat_addr est l'hôte. Le membre net de struct at_addr contient le réseau de l'hôte dans l'ordre des octets du réseau. La valeur de AT_ANYNET est un caractère générique et implique aussi « ce réseau » . Le membre node de struct at_addr contient le numéro de nœud de l'hôte. La valeur de AT_ANYNODE est un caractère générique et implique aussi « ce nœud ».
