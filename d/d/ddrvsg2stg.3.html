subroutine ddrvsg2stg (integer nsizes, integer, dimension( * ) nn, integer ntypes, logical, dimension( * ) dotype, integer, dimension( 4 ) iseed, double precision thresh, integer nounit, double precision, dimension( lda, * ) a, integer lda, double precision, dimension( ldb, * ) b, integer ldb, double precision, dimension( * ) d, double precision, dimension( * ) d2, double precision, dimension( ldz, * ) z, integer ldz, double precision, dimension( lda, * ) ab, double precision, dimension( ldb, * ) bb, double precision, dimension( * ) ap, double precision, dimension( * ) bp, double precision, dimension( * ) work, integer nwork, integer, dimension( * ) iwork, integer liwork, double precision, dimension( * ) result, integer info)

DDRVSG2STG

Objectif :

!>
!>      DDRVSG2STG teste les pilotes du problème aux valeurs propres généralisé réel symétrique.
!>
!>              DSYGV calcule toutes les valeurs propres et, éventuellement,
!>              les vecteurs propres d'un problème généralisé réel symétrique-défini.
!>
!>              DSYGVD calcule toutes les valeurs propres et, éventuellement,
!>              les vecteurs propres d'un problème généralisé réel symétrique-défini
!>              en utilisant un algorithme de division et de conquête.
!>
!>              DSYGVX calcule des valeurs propres sélectionnées et, éventuellement,
!>              les vecteurs propres d'un problème généralisé réel symétrique-défini.
!>
!>              DSPGV calcule toutes les valeurs propres et, éventuellement,
!>              les vecteurs propres d'un problème généralisé réel symétrique-défini
!>              en stockage compacté.
!>
!>              DSPGVD calcule toutes les valeurs propres et, éventuellement,
!>              les vecteurs propres d'un problème généralisé réel symétrique-défini
!>              en stockage compacté en utilisant un algorithme de division et de conquête.
!>
!>              DSPGVX calcule des valeurs propres sélectionnées et, éventuellement,
!>              les vecteurs propres d'un problème généralisé réel symétrique-défini
!>              en stockage compacté.
!>
!>              DSBGV calcule toutes les valeurs propres et, éventuellement,
!>              les vecteurs propres d'un problème généralisé réel symétrique-défini
!>              bandé.
!>
!>              DSBGVD calcule toutes les valeurs propres et, éventuellement,
!>              les vecteurs propres d'un problème généralisé réel symétrique-défini
!>              bandé en utilisant un algorithme de division et de conquête.
!>
!>              DSBGVX calcule des valeurs propres sélectionnées et, éventuellement,
!>              les vecteurs propres d'un problème généralisé réel symétrique-défini
!>              bandé.
!>
!>      Lorsque DDRVSG2STG est appelé, un certain nombre de matrices de taille ()
!>      et un certain nombre de matrices de type sont spécifiés. Pour chaque taille ()
!>      et chaque type de matrice, une matrice A du type donné sera générée ;
!>      une matrice B aléatoire bien conditionnée est également générée et la paire (A,B)
!>      est utilisée pour tester les pilotes.
!>
!>      Pour chaque paire (A,B), les tests suivants sont effectués :
!>
!>      (1) DSYGV avec ITYPE = 1 et UPLO ='U' :
!>
!>              | A Z - B Z D | / ( |A| |Z| n ulp )
!>              | D - D2 | / ( |D| ulp )   où D est calculé par
!>                                         DSYGV et D2 est calculé par
!>                                         DSYGV_2STAGE. Ce test n'est effectué que pour DSYGV.
!>
!>      (2) idem que (1) mais appelant DSPGV
!>      (3) idem que (1) mais appelant DSBGV
!>      (4) idem que (1) mais avec UPLO = 'L'
!>      (5) idem que (4) mais appelant DSPGV
!>      (6) idem que (4) mais appelant DSBGV
!>
!>      (7) DSYGV avec ITYPE = 2 et UPLO ='U' :
!>
!>              | A B Z - Z D | / ( |A| |Z| n ulp )
!>
!>      (8) idem que (7) mais appelant DSPGV
!>      (9) idem que (7) mais avec UPLO = 'L'
!>      (10) idem que (9) mais appelant DSPGV
!>
!>      (11) DSYGV avec ITYPE = 3 et UPLO ='U' :
!>
!>              | B A Z - Z D | / ( |A| |Z| n ulp )
!>
!>      (12) idem que (11) mais appelant DSPGV
!>      (13) idem que (11) mais avec UPLO = 'L'
!>      (14) idem que (13) mais appelant DSPGV
!>
!>      DSYGVD, DSPGVD et DSBGVD effectuent les mêmes 14 tests.
!>
!>      DSYGVX, DSPGVX et DSBGVX effectuent les 14 tests ci-dessus avec
!>      le paramètre RANGE = 'A', 'N' et 'I', respectivement.
!>
!>      Les tailles de matrices sont spécifiées par un tableau NN(1:NSIZES) ; la valeur
!>      de chaque élément NN(j) spécifie une taille.
!>      Les types de matrices sont spécifiés par un tableau logique DOTYPE( 1:NTYPES ) ;
!>      si DOTYPE(j) est .VRAI., alors le type de matrice j sera généré.
!>      Ce type est utilisé pour la matrice A qui a une demi-bande KA.
!>      B est générée comme une matrice définie positive bien conditionnée
!>      avec une demi-bande KB (<= KA).
!>      Actuellement, la liste des types possibles pour A est :
!>
!>      (1) La matrice nulle.
!>      (2) La matrice identité.
!>
!>      (3) Une matrice diagonale avec des entrées espacées régulièrement
!>           1, ..., ULP  et des signes aléatoires.
!>           (ULP = (premier nombre supérieur à 1) - 1)
!>      (4) Une matrice diagonale avec des entrées espacées géométriquement
!>           1, ..., ULP  et des signes aléatoires.
!>      (5) Une matrice diagonale avec des entrées
!>           1, ULP, ..., ULP et des signes aléatoires.
!>
!>      (6) Identique à (4), mais multiplié par SQRT( seuil de dépassement de capacité )
!>      (7) Identique à (4), mais multiplié par SQRT( seuil de sous-dépassement de capacité )
!>
!>      (8) Une matrice de la forme U* D U, où U est orthogonale et
!>           D a des entrées espacées régulièrement 1, ..., ULP avec des signes aléatoires
!>           sur la diagonale.
!>
!>      (9) Une matrice de la forme U* D U, où U est orthogonale et
!>           D a des entrées espacées géométriquement 1, ..., ULP avec des signes aléatoires
!>           sur la diagonale.
!>
!>      (10) Une matrice de la forme U* D U, où U est orthogonale et
!>           D a des entrées  1, ULP,..., ULP avec des signes aléatoires
!>           sur la diagonale.
!>
!>      (11) Identique à (8), mais multiplié par SQRT( seuil de dépassement de capacité )
!>      (12) Identique à (8), mais multiplié par SQRT( seuil de sous-dépassement de capacité )
!>
!>      (13) Matrice symétrique avec des entrées aléatoires choisies dans (-1,1).
!>      (14) Identique à (13), mais multiplié par SQRT( seuil de dépassement de capacité )
!>      (15) Identique à (13), mais multiplié par SQRT( seuil de sous-dépassement de capacité )
!>
!>      (16) Identique à (8), mais avec KA = 1 et KB = 1
!>      (17) Identique à (8), mais avec KA = 2 et KB = 1
!>      (18) Identique à (8), mais avec KA = 2 et KB = 2
!>      (19) Identique à (8), mais avec KA = 3 et KB = 1
!>      (20) Identique à (8), mais avec KA = 3 et KB = 2
!>      (21) Identique à (8), mais avec KA = 3 et KB = 3
!> 
!>  NSIZES  INTEGER
!>          Le nombre de tailles de matrices à utiliser. S'il est égal à zéro,
!>          DDRVSG2STG ne fait rien. Il doit être supérieur ou égal à zéro.
!>          Non modifié.
!>
!>  NN      INTEGER array, dimension (NSIZES)
!>          Un tableau contenant les tailles à utiliser pour les matrices.
!>          Les valeurs nulles seront ignorées. Les valeurs doivent être supérieures ou égales à zéro.
!>          Non modifié.
!>
!>  NTYPES  INTEGER
!>
Le nombre d'éléments dans DOTYPE. S'il est égal à zéro, DDRVSG2STG !> ne fait rien. Il doit être au moins égal à zéro. S'il est !> égal à MAXTYP+1 et que NSIZES vaut 1, alors un type !> supplémentaire, MAXTYP+1, est défini, qui consiste à !> utiliser quelle que soit la matrice dans A. Cela n'est !> utile que si DOTYPE(1:MAXTYP) vaut .FALSE. et !> DOTYPE(MAXTYP+1) vaut .TRUE. . !> Non modifié. !> !> DOTYPE Tableau LOGICAL, dimension (NTYPES) !> Si DOTYPE(j) vaut .TRUE., alors pour chaque taille dans NN, !> une matrice de cette taille et de type j sera générée. !> Si NTYPES est inférieur au nombre maximal de types défini !> (PARAMETER MAXTYP), les types NTYPES+1 à MAXTYP ne seront !> pas générés. Si NTYPES est supérieur à MAXTYP, !> DOTYPE(MAXTYP+1) à DOTYPE(NTYPES) seront ignorés. !> Non modifié. !> !> ISEED Tableau INTEGER, dimension (4) !> À l'entrée, ISEED spécifie la graine du générateur de !> nombres aléatoires. Les éléments du tableau doivent être !> compris entre 0 et 4095 ; sinon, ils seront réduits modulo !> 4096. De plus, ISEED(4) doit être impair. Le générateur de !> nombres aléatoires utilise une suite congruentielle linéaire !> limitée à de petits entiers, et devrait donc produire des !> nombres aléatoires indépendants de la machine. Les valeurs !> de ISEED sont modifiées à la sortie, et peuvent être !> utilisées dans le prochain appel à DDRVSG2STG pour !> continuer la même suite de nombres aléatoires. !> Modifié. !> !> THRESH DOUBLE PRECISION !> Un test sera considéré comme réussi si la valeur, calculée !> comme décrit ci-dessus, dépasse THRESH. Notez que l'erreur !> est mise à l'échelle pour être O(1), donc THRESH devrait !> être un multiple raisonnablement petit de 1, p. ex., 10 ou !> 100. En particulier, il ne devrait pas dépendre de la !> précision (simple vs. double) ni de la taille de la !> matrice. Il doit être au moins égal à zéro. !> Non modifié. !> !> NOUNIT INTEGER !> Le numéro d'unité FORTRAN pour l'affichage des messages !> d'erreur (p. ex., si une routine retourne IINFO différent !> de 0). !> Non modifié. !> !> A Tableau DOUBLE PRECISION, dimension (LDA , max(NN)) !> Utilisé pour stocker la matrice dont les valeurs !> propres doivent être calculées. À la sortie, A contient la !> dernière matrice effectivement utilisée. !> Modifié. !> !> LDA INTEGER !> La dimension principale de A et AB. Elle doit être au !> moins 1 et au moins max( NN ). !> Non modifié. !> !> B Tableau DOUBLE PRECISION, dimension (LDB , max(NN)) !> Utilisé pour stocker la matrice symétrique définie positive !> pour le problème généralisé. !> À la sortie, B contient la dernière matrice !> effectivement utilisée. !> Modifié. !> !> LDB INTEGER !> La dimension principale de B et BB. Elle doit être au !> moins 1 et au moins max( NN ). !> Non modifié. !> !> D Tableau DOUBLE PRECISION, dimension (max(NN)) !> Les valeurs propres de A. À la sortie, les valeurs propres !> dans D correspondent à la matrice dans A. !> Modifié. !> !> Z Tableau DOUBLE PRECISION, dimension (LDZ, max(NN)) !> La matrice des vecteurs propres. !> Modifié. !> !> LDZ INTEGER !> La dimension principale de Z. Elle doit être au moins 1 et !> au moins max( NN ). !> Non modifié. !> !> AB Tableau DOUBLE PRECISION, dimension (LDA, max(NN)) !> Espace de travail. !> Modifié. !> !> BB Tableau DOUBLE PRECISION, dimension (LDB, max(NN)) !> Espace de travail. !> Modifié. !> !> AP Tableau DOUBLE PRECISION, dimension (max(NN)**2) !> Espace de travail. !> Modifié. !> !> BP Tableau DOUBLE PRECISION, dimension (max(NN)**2) !> Espace de travail. !> Modifié. !> !> WORK Tableau DOUBLE PRECISION, dimension (NWORK) !> Espace de travail. !> Modifié. !> !> NWORK INTEGER !> Le nombre d'entrées dans WORK. Cela doit être au moins !> 1+5*N+2*N*lg(N)+3*N**2 où N = max( NN(j) ) et !> lg( N ) = plus petit entier k tel que 2**k >= N. !> Non modifié. !> !> IWORK Tableau INTEGER, dimension (LIWORK) !> Espace de travail. !> Modifié. !> !> LIWORK INTEGER !> Le nombre d'entrées dans WORK. Cela doit être au moins 6*N. !> Non modifié. !> !> RESULT Tableau DOUBLE PRECISION, dimension (70) !> Les valeurs calculées par les 70 tests décrits ci-dessus. !> Modifié. !> !> INFO INTEGER !> Si 0, tout s'est déroulé correctement. !> -1 : NSIZES < 0 !> -2 : Certains NN(j) < 0 !> -3 : NTYPES < 0 !> -5 : THRESH < 0 !> -9 : LDA < 1 ou LDA < NMAX, où NMAX est max( NN(j) ). !> -16 : LDZ < 1 ou LDZ < NMAX. !> -21 : NWORK trop petit. !> -23 : LIWORK trop petit. !> Si DLATMR, SLATMS, DSYGV, DSPGV, DSBGV, SSYGVD, SSPGVD, !> DSBGVD, DSYGVX, DSPGVX ou SSBGVX retourne un code !> d'erreur, sa valeur absolue est retournée. !> Modifié. !> !> ---------------------------------------------------------------------- !> !> Quelques variables et paramètres locaux : !> ---- ----- --------- --- ---------- !> ZERO, ONE Réels 0 et 1. !> MAXTYP Le nombre de types définis. !> NTEST Le nombre de tests effectués !> sur cette matrice. !> NTESTT Le nombre total de tests pour cet appel. !> NMAX La plus grande valeur dans NN. !> NMATS Le nombre de matrices générées jusqu'à présent. !> NERRS Le nombre de tests qui ont dépassé THRESH !> jusqu'à présent (calculé par DLAFTS). !> COND, IMODE Valeurs à transmettre aux générateurs de !> matrices. !> ANORM Norme de A ; transmise aux générateurs de !> matrices. !> !> OVFL, UNFL Seuils de débordement et de sous-flux. !> ULP, ULPINV Précision relative la plus fine et son inverse. !> RTOVFL, RTUNFL Racines carrées des 2 valeurs précédentes. !> Les quatre tableaux suivants décodent JTYPE : !> KTYPE(j) Le type général (1-10) pour le type . !> KMODE(j) La valeur MODE à transmettre au générateur !> de matrices pour le type . !> KMAGN(j) L'ordre de grandeur ( O(1), !> O(débordement^(1/2) ), O(sous-flux^(1/2) ) !>
