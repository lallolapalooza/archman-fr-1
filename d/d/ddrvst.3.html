!>
!>      DDRVST vérifie les pilotes du problème des valeurs propres symétriques.
!>
!>              DSTEV calcule toutes les valeurs propres et, optionnellement,
!>              les vecteurs propres d'une matrice tridiagonale symétrique réelle.
!>
!>              DSTEVX calcule des valeurs propres sélectionnées et, optionnellement,
!>              les vecteurs propres d'une matrice tridiagonale symétrique réelle.
!>
!>              DSTEVR calcule des valeurs propres sélectionnées et, optionnellement,
!>              les vecteurs propres d'une matrice tridiagonale symétrique réelle
!>              en utilisant la Représentation Robuste Relative lorsque c'est possible.
!>
!>              DSYEV calcule toutes les valeurs propres et, optionnellement,
!>              les vecteurs propres d'une matrice symétrique réelle.
!>
!>              DSYEVX calcule des valeurs propres sélectionnées et, optionnellement,
!>              les vecteurs propres d'une matrice symétrique réelle.
!>
!>              DSYEVR calcule des valeurs propres sélectionnées et, optionnellement,
!>              les vecteurs propres d'une matrice symétrique réelle
!>              en utilisant la Représentation Robuste Relative lorsque c'est possible.
!>
!>              DSPEV calcule toutes les valeurs propres et, optionnellement,
!>              les vecteurs propres d'une matrice symétrique réelle en stockage
!>              compacté.
!>
!>              DSPEVX calcule des valeurs propres sélectionnées et, optionnellement,
!>              les vecteurs propres d'une matrice symétrique réelle en stockage
!>              compacté.
!>
!>              DSBEV calcule toutes les valeurs propres et, optionnellement,
!>              les vecteurs propres d'une matrice bande symétrique réelle.
!>
!>              DSBEVX calcule des valeurs propres sélectionnées et, optionnellement,
!>              les vecteurs propres d'une matrice bande symétrique réelle.
!>
!>              DSYEVD calcule toutes les valeurs propres et, optionnellement,
!>              les vecteurs propres d'une matrice symétrique réelle en utilisant
!>              un algorithme de diviser pour régner.
!>
!>              DSPEVD calcule toutes les valeurs propres et, optionnellement,
!>              les vecteurs propres d'une matrice symétrique réelle en stockage
!>              compacté, en utilisant un algorithme de diviser pour régner.
!>
!>              DSBEVD calcule toutes les valeurs propres et, optionnellement,
!>              les vecteurs propres d'une matrice bande symétrique réelle,
!>              en utilisant un algorithme de diviser pour régner.
!>
!>      Lorsque DDRVST est appelé, un nombre de tailles de matrices  () et un
!>      nombre de types de matrices  sont spécifiés. Pour chaque taille ()
!>      et chaque type de matrice, une matrice sera générée et utilisée
!>      pour tester les pilotes appropriés. Pour chaque matrice et chaque
!>      routine pilote appelée, les tests suivants seront effectués :
!>
!>      (1)     | A - Z D Z' | / ( |A| n ulp )
!>
!>      (2)     | I - Z Z' | / ( n ulp )
!>
!>      (3)     | D1 - D2 | / ( |D1| ulp )
!>
!>      où Z est la matrice des vecteurs propres retournée lorsque
!>      l'option vecteur propre est donnée et D1 et D2 sont les valeurs propres
!>      retournées avec et sans l'option vecteur propre.
!>
!>      Les  sont spécifiés par un tableau NN(1:NSIZES) ; la valeur de
!>      chaque élément NN(j) spécifie une taille.
!>      Les  sont spécifiés par un tableau logique DOTYPE( 1:NTYPES ) ;
!>      si DOTYPE(j) est .TRUE., alors le type de matrice  sera généré.
!>      Actuellement, la liste des types possibles est :
!>
!>      (1)  La matrice nulle.
!>      (2)  La matrice identité.
!>
!>      (3)  Une matrice diagonale avec des valeurs propres espacées uniformément
!>           1, ..., ULP  et des signes aléatoires.
!>           (ULP = (premier nombre plus grand que 1) - 1 )
!>      (4)  Une matrice diagonale avec des valeurs propres espacées géométriquement
!>           1, ..., ULP  et des signes aléatoires.
!>      (5)  Une matrice diagonale avec  valeurs propres
!>           1, ULP, ..., ULP et des signes aléatoires.
!>
!>      (6)  Identique à (4), mais multiplié par SQRT( seuil de débordement )
!>      (7)  Identique à (4), mais multiplié par SQRT( seuil de débordement négatif )
!>
!>      (8)  Une matrice de la forme  U' D U, où U est orthogonale et
!>           D a des entrées espacées uniformément 1, ..., ULP avec des signes
!>           aléatoires sur la diagonale.
!>
!>      (9)  Une matrice de la forme  U' D U, où U est orthogonale et
!>           D a des entrées espacées géométriquement 1, ..., ULP avec des signes
!>           aléatoires sur la diagonale.
!>
!>      (10) Une matrice de la forme  U' D U, où U est orthogonale et
!>           D a des entrées 1, ULP,..., ULP avec des signes
!>           aléatoires sur la diagonale.
!>
!>      (11) Identique à (8), mais multiplié par SQRT( seuil de débordement )
!>      (12) Identique à (8), mais multiplié par SQRT( seuil de débordement négatif )
!>
!>      (13) Matrice symétrique avec des entrées choisies aléatoirement dans (-1,1).
!>      (14) Identique à (13), mais multiplié par SQRT( seuil de débordement )
!>      (15) Identique à (13), mais multiplié par SQRT( seuil de débordement négatif )
!>      (16) Une matrice bande avec une demi-largeur de bande choisie aléatoirement entre
!>           0 et N-1, avec des valeurs propres espacées uniformément 1, ..., ULP
!>           et des signes aléatoires.
!>      (17) Identique à (16), mais multiplié par SQRT( seuil de débordement )
!>      (18) Identique à (16), mais multiplié par SQRT( seuil de débordement négatif )
!
> 
!>  NSIZES  INTEGER
!>          Le nombre de tailles de matrices à utiliser. S'il est zéro,
!>          DDRVST ne fait rien. Il doit être au moins zéro.
!>          Non modifié.
!>
!>  NN      INTEGER array, dimension (NSIZES)
!>          Un tableau contenant les tailles à utiliser pour les matrices.
!>          Les valeurs nulles seront ignorées. Les valeurs doivent être au moins
!>          zéro.
!>          Non modifié.
!>
!>  NTYPES  INTEGER
!>          Le nombre d'éléments dans DOTYPE. S'il est zéro, DDRVST
!>          ne fait rien. Il doit être au moins zéro. S'il est MAXTYP+1
!>          et que NSIZES vaut 1, alors un type supplémentaire, MAXTYP+1, est
!>          défini, qui consiste à utiliser quelle que soit la matrice dans A. Cela
!>          n'est utile que si DOTYPE(1:MAXTYP) est .FALSE. et
!>          DOTYPE(MAXTYP+1) est .TRUE. .
!>          Non modifié.
!>
!>  DOTYPE  LOGICAL array, dimension (NTYPES)
!>          Si DOTYPE(j) est .TRUE., alors pour chaque taille dans NN une
!>          matrice de cette taille et de type j sera générée.
!>          Si NTYPES est inférieur au nombre maximal de types
!>          défini (PARAMETER MAXTYP), les types NTYPES+1 à
!>          MAXTYP ne seront pas générés.  Si NTYPES est supérieur
!>          à MAXTYP, DOTYPE(MAXTYP+1) à DOTYPE(NTYPES)
!>          seront ignorés.
!>          Non modifié.
!>
!>  ISEED   tableau INTEGER, dimension (4)
!>          À l'entrée, ISEED spécifie la graine du générateur de
!>          nombres aléatoires. Les éléments du tableau doivent être
!>          compris entre 0 et 4095 ; sinon ils seront réduits
!>          modulo 4096.  De plus, ISEED(4) doit être impair.  Le
!>          générateur de nombres aléatoires utilise une séquence
!>          congruentielle linéaire limitée à de petits entiers, et
!>          doit donc produire des nombres aléatoires indépendants
!>          de la machine. Les valeurs de ISEED sont modifiées à la
!>          sortie, et peuvent être utilisées dans l'appel suivant à
!>          DDRVST pour poursuivre la même séquence de nombres
!>          aléatoires.
!>          Modifié.
!>
!>  THRESH  DOUBLE PRECISION
!>          Un test sera considéré comme en échec si la valeur
!>          calculée comme décrit ci-dessus dépasse THRESH.  Notez
!>          que l'erreur est mise à l'échelle pour être O(1), donc
!>          THRESH devrait être un multiple raisonnablement petit de
!>          1, p. ex., 10 ou 100.  En particulier, elle ne devrait
!>          pas dépendre de la précision (simple vs. double) ni de
!>          la taille de la matrice.  Elle doit être au moins zéro.
!>          Non modifié.
!>
!>  NOUNIT  INTEGER
!>          Le numéro d'unité FORTRAN pour imprimer les messages
!>          d'erreur (p. ex., si une routine retourne IINFO différent
!>          de 0.)
!>          Non modifié.
!>
!>  A       tableau DOUBLE PRECISION, dimension (LDA , max(NN))
!>          Utilisé pour contenir la matrice dont les valeurs
!>          propres doivent être calculées.  À la sortie, A contient
!>          la dernière matrice effectivement utilisée.
!>          Modifié.
!>
!>  LDA     INTEGER
!>          La dimension principale de A.  Elle doit être au moins 1
!>          et au moins max( NN ).
!>          Non modifié.
!>
!>  D1      tableau DOUBLE PRECISION, dimension (max(NN))
!>          Les valeurs propres de A, calculées par DSTEQR
!>          simultanément avec Z.  À la sortie, les valeurs propres
!>          dans D1 correspondent à la matrice dans A.
!>          Modifié.
!>
!>  D2      tableau DOUBLE PRECISION, dimension (max(NN))
!>          Les valeurs propres de A, calculées par DSTEQR si Z
!>          n'est pas calculé.  À la sortie, les valeurs propres
!>          dans D2 correspondent à la matrice dans A.
!>          Modifié.
!>
!>  D3      tableau DOUBLE PRECISION, dimension (max(NN))
!>          Les valeurs propres de A, calculées par DSTERF.  À la
!>          sortie, les valeurs propres dans D3 correspondent à la
!>          matrice dans A.
!>          Modifié.
!>
!>  D4      tableau DOUBLE PRECISION, dimension
!>
!>  EVEIGS  tableau DOUBLE PRECISION, dimension (max(NN))
!>          Les valeurs propres telles que calculées par
!>          DSTEV('N', ... )
!>          (Je me réserve le droit de changer cela pour la sortie
!>          de l'algorithme qui calcule les valeurs propres les plus
!>          précises).
!>
!>  WA1     tableau DOUBLE PRECISION, dimension
!>
!>  WA2     tableau DOUBLE PRECISION, dimension
!>
!>  WA3     tableau DOUBLE PRECISION, dimension
!>
!>  U       tableau DOUBLE PRECISION, dimension (LDU, max(NN))
!>          La matrice orthogonale calculée par DSYTRD + DORGTR.
!>          Modifié.
!>
!>  LDU     INTEGER
!>          La dimension principale de U, Z, et V.  Elle doit être
!>          au moins 1 et au moins max( NN ).
!>          Non modifié.
!>
!>  V       tableau DOUBLE PRECISION, dimension (LDU, max(NN))
!>          Les vecteurs de Householder calculés par DSYTRD lors de
!>          la réduction de A en forme tridiagonale.
!>          Modifié.
!>
!>  TAU     tableau DOUBLE PRECISION, dimension (max(NN))
!>          Les facteurs de Householder calculés par DSYTRD lors de
!>          la réduction de A en forme tridiagonale.
!>          Modifié.
!>
!>  Z       tableau DOUBLE PRECISION, dimension (LDU, max(NN))
!>          La matrice orthogonale des vecteurs propres calculée par
!>          DSTEQR, DPTEQR, et DSTEIN.
!>          Modifié.
!>
!>  WORK    tableau DOUBLE PRECISION, dimension (LWORK)
!>          Espace de travail.
!>          Modifié.
!>
!>  LWORK   INTEGER
!>          Le nombre d'entrées dans WORK.  Il doit être au moins
!>          1 + 4 * Nmax + 2 * Nmax * lg Nmax + 4 * Nmax**2
!>          où Nmax = max( NN(j), 2 ) et lg = logarithme base 2.
!>          Non modifié.
!>
!>  IWORK   tableau INTEGER,
!>             dimension (6 + 6*Nmax + 5 * Nmax * lg Nmax )
!>          où Nmax = max( NN(j), 2 ) et lg = logarithme base 2.
!>          Espace de travail.
!>          Modifié.
!>
!>  RESULT  tableau DOUBLE PRECISION, dimension (105)
!>          Les valeurs calculées par les tests décrits ci-dessus.
!>          Les valeurs sont actuellement limitées à 1/ulp, pour
!>          éviter le débordement.
!>          Modifié.
!>
!>  INFO    INTEGER
!>          Si 0, tout s'est déroulé correctement.
!>           -1: NSIZES < 0
!>           -2: Certains NN(j) < 0
!>           -3: NTYPES < 0
!>           -5: THRESH < 0
!>           -9: LDA < 1 ou LDA < NMAX, où NMAX est max( NN(j) ).
!>          -16: LDU < 1 ou LDU < NMAX.
!>          -21: LWORK trop petit.
!>          Si  DLATMR, DLATMS, DSYTRD, DORGTR, DSTEQR, DSTERF,
!>              ou DORMTR retourne un code d'erreur, la valeur
!>              absolue de celui-ci est retournée.
!>          Modifié.
!>
!>-----------------------------------------------------------------------
!>
!>       Quelques variables et paramètres locaux :
!>       ---- ----- --------- --- ----------
!>       ZERO, ONE       Réels 0 et 1.
!>       MAXTYP          Le nombre de types définis.
!>       NTEST           Le nombre de tests effectués, ou qui peuvent
!>                       être effectués jusqu'ici, pour la matrice
!>                       courante.
!>       NTESTT          Le nombre total de tests effectués jusqu'ici.
!>       NMAX            La plus grande valeur dans NN.
!>       NMATS           Le nombre de matrices générées jusqu'ici.
!>       NERRS           Le nombre de tests qui ont dépassé THRESH
!>                       jusqu'ici (calculés par DLAFTS).
!>       COND, IMODE     Valeurs à passer aux générateurs de matrices.
!>       ANORM           Norme de A ; passée aux générateurs de
!>                       matrices.
!>
!>       OVFL, UNFL      Seuils de débordement et de sous-flux.
!>       ULP, ULPINV     Précision relative la plus fine et son
!>                       inverse.
!>       RTOVFL, RTUNFL  Racines carrées des 2 valeurs précédentes.
!>               Les quatre tableaux suivants décodent JTYPE :
!>       KTYPE(j)        Le type général (1-10) pour le type .
!>       KMODE(j)        La valeur MODE à passer au générateur de
!>                       matrices pour le type .
!>       KMAGN(j)        L'ordre de grandeur ( O(1),
!>                       O(overflow^(1/2) ), O(underflow^(1/2) )
!>
!>     Les tests effectués sont :                 Routine testée
!>    1= | A - U S U' | / ( |A| n ulp )         DSTEV('V', ... )
!>    2= | I - U U' | / ( n ulp )               DSTEV('V', ... )
!>    3= |D(avec Z) - D(sans Z)| / (|D| ulp)    DSTEV('N', ... )
!>    4= | A - U S U' | / ( |A| n ulp )         DSTEVX('V','A', ... )
!>    5= | I - U U' | / ( n ulp )               DSTEVX('V','A', ... )
!>    6= |D(avec Z) - EVEIGS| / (|D| ulp)       DSTEVX('N','A', ... )
!>    7= | A - U S U' | / ( |A| n ulp )         DSTEVR('V','A', ... )
!>    8= | I - U U' | / ( n ulp )               DSTEVR('V','A', ... )
!>    9= |D(avec Z) - EVEIGS| / (|D| ulp)       DSTEVR('N','A', ... )
!>    10= | A - U S U' | / ( |A| n ulp )        DSTEVX('V','I', ... )
!>    11= | I - U U' | / ( n ulp )              DSTEVX('V','I', ... )
!>    12= |D(avec Z) - D(sans Z)| / (|D| ulp)   DSTEVX('N','I', ... )
!>    13= | A - U S U' | / ( |A| n ulp )        DSTEVX('V','V', ... )
!>    14= | I - U U' | / ( n ulp )              DSTEVX('V','V', ... )
!>    15= |D(avec Z) - D(sans Z)| / (|D| ulp)   DSTEVX('N','V', ... )
!>    16= | A - U S U' | / ( |A| n ulp )        DSTEVD('V', ... )
!>    17= | I - U U' | / ( n ulp )              DSTEVD('V', ... )
!>    18= |D(avec Z) - EVEIGS| / (|D| ulp)      DSTEVD('N', ... )
!>    19= | A - U S U' | / ( |A| n ulp )        DSTEVR('V','I', ... )
!>    20= | I - U U' | / ( n ulp )              DSTEVR('V','I', ... )
!>    21= |D(avec Z) - D(sans Z)| / (|D| ulp)   DSTEVR('N','I', ... )
!>    22= | A - U S U' | / ( |A| n ulp )        DSTEVR('V','V', ... )
!>    23= | I - U U' | / ( n ulp )              DSTEVR('V','V', ... )
!>    24= |D(avec Z) - D(sans Z)| / (|D| ulp)   DSTEVR('N','V', ... )

!>    37= | A - U S U' | / ( |A| n ulp )        DSPEV('L','V', ... )
!>    38= | I - U U' | / ( n ulp )              DSPEV('L','V', ... )
!>    39= |D(avec Z) - D(sans Z)| / (|D| ulp)   DSPEV('L','N', ... )
