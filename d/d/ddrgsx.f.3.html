DDRGSX

But :

!>
!> DDRGSX vérifie le pilote expert DGGESX pour le problème des valeurs propres généralisées non symétriques (forme de Schur).
!>
!> DGGESX factorise A et B en Q S Z' et Q T Z', où ' désigne la transposée, T est triangulaire supérieur, S est en forme de Schur généralisée (triangulaire par blocs supérieur, avec des blocs 1x1 et 2x2 sur la diagonale, les blocs 2x2 correspondant aux paires conjuguées complexes de valeurs propres généralisées), et Q et Z sont orthogonales. Il calcule également les valeurs propres généralisées (alpha(1),beta(1)), ..., (alpha(n),beta(n)). Ainsi, w(j) = alpha(j)/beta(j) est une racine de l'équation caractéristique
!>
!>     det( A - w(j) B ) = 0
!>
!> Optionnellement, il réordonne également les valeurs propres afin qu'un groupe sélectionné de valeurs propres apparaisse dans le bloc diagonal principal des formes de Schur ; calcule un nombre de condition réciproque pour la moyenne des valeurs propres sélectionnées ; et calcule un nombre de condition réciproque pour les sous-espaces de déflation droite et gauche correspondant aux valeurs propres sélectionnées.
!>
!> Lorsque DDRGSX est appelé avec NSIZE > 0, cinq (5) types de paires de matrices intégrées sont utilisés pour tester la routine DGGESX.
!>
!> Lorsque DDRGSX est appelé avec NSIZE = 0, il lit des données de matrices de test pour tester DGGESX.
!>
!> Pour chaque paire de matrices, les tests suivants seront effectués et comparés au seuil THRESH, à l'exception des tests (7) et (9) :
!>
!> (1)   | A - Q S Z' | / ( |A| n ulp )
!>
!> (2)   | B - Q T Z' | / ( |B| n ulp )
!>
!> (3)   | I - QQ' | / ( n ulp )
!>
!> (4)   | I - ZZ' | / ( n ulp )
!>
!> (5)   si A est en forme de Schur (c'est-à-dire en forme quasi-triangulaire)
!>
!> (6)   le maximum sur j de D(j)  où :
!>
!>       si alpha(j) est réelle :
!>                     |alpha(j) - S(j,j)|        |beta(j) - T(j,j)|
!>           D(j) = ------------------------ + -----------------------
!>                  max(|alpha(j)|,|S(j,j)|)   max(|beta(j)|,|T(j,j)|)
!>
!>       si alpha(j) est complexe :
!>                                 | det( s S - w T ) |
!>           D(j) = ---------------------------------------------------
!>                  ulp max( s norm(S), |w| norm(T) )*norm( s S - w T )
!>
!>           et S et T sont ici les blocs diagonaux 2 x 2 de S et T
!>           correspondant aux valeurs propres j et j+1.
!>
!> (7)   si le tri a fonctionné et que SDIM est le nombre de valeurs propres
!>       qui ont été sélectionnées.
!>
!> (8)   la valeur estimée DIF ne diffère pas des valeurs vraies de
!>       Difu et Difl d'un facteur supérieur à 10*THRESH. Si l'estimation DIF
!>       est égale à zéro, les valeurs vraies correspondantes de Difu et Difl
!>       devraient être inférieures à EPS*norm(A, B). Si les valeurs vraies de Difu
!>       et Difl sont égales à zéro, l'estimation DIF devrait être inférieure à
!>       EPS*norm(A, B).
!>
!> (9)   Si INFO = N+3 est retourné par DGGESX, le réordonnancement
!>       et nous vérifions que DIF = PL = PR = 0 et que la valeur vraie de
!>       Difu et Difl est < EPS*norm(A, B). Nous comptons les événements lorsque
!>       INFO=N+3.
!>
!> Pour les matrices de test lues, les tests ci-dessus sont exécutés, sauf que la
!> valeur exacte pour DIF (et PL) est une donnée d'entrée. De plus, il y a
!> un test supplémentaire exécuté pour les matrices de test lues :
!>
!> (10)  la valeur estimée PL ne diffère pas de la valeur vraie de
!>       PLTRU d'un facteur supérieur à THRESH. Si l'estimation PL est égale
!>       à zéro, la valeur vraie correspondante de PLTRU devrait être inférieure à
!>       EPS*norm(A, B). Si la valeur vraie de PLTRU est égale à zéro, l'estimation
!>       PL devrait être inférieure à EPS*norm(A, B).
!>
!> Notez que pour les tests intégrés, un total de 10*NSIZE*(NSIZE-1)
!> paires de matrices sont générées et testées. NSIZE devrait être maintenu petit.
!>
!> SVD (routine DGESVD) est utilisé pour calculer la valeur vraie de DIF_u
!> et DIF_l lors du test des problèmes de test intégrés.
!>
!> Matrices de test intégrées
!> ==========================
!>
!> Toutes les matrices de test intégrées sont le bloc 2 par 2 de matrices
!> triangulaires
!>
!>          A = [ A11 A12 ]    et      B = [ B11 B12 ]
!>              [     A22 ]                 [     B22 ]
!>
!> où pour différents types, A11 et A22 sont donnés comme suit.
!> A12 et B12 sont choisis de sorte que l'équation de Sylvester généralisée
!>
!>          A11*R - L*A22 = -A12
!>          B11*R - L*B22 = -B12
!>
!> ait les solutions prescrites R et L.
!>
!> Type 1 :  A11 = J_m(1,-1) et A_22 = J_k(1-a,1).
!>           B11 = I_m, B22 = I_k
!>           où J_k(a,b) est le bloc de Jordan k par k avec ``a'' sur la
!>           diagonale et ``b'' sur la surdiagonale.
!>
!> Type 2 :  A11 = (a_ij) = ( 2(.5-sin(i)) ) et
!>           B11 = (b_ij) = ( 2(.5-sin(ij)) ) pour i=1,...,m, j=i,...,m
!>           A22 = (a_ij) = ( 2(.5-sin(i+j)) ) et
!>           B22 = (b_ij) = ( 2(.5-sin(ij)) ) pour i=m+1,...,k, j=i,...,k
!>
!> Type 3 :  A11, A22 et B11, B22 sont choisis comme pour le Type 2, mais chaque
!>           deuxième bloc diagonal dans A_11 et chaque troisième bloc diagonal
!>           dans A_22 sont faits comme des blocs 2 par 2.
!>
!> Type 4 :  A11 = ( 20(.5 - sin(ij)) ) et B22 = ( 2(.5 - sin(i+j)) )
!>              pour i=1,...,m,  j=1,...,m et
!>           A22 = ( 20(.5 - sin(i+j)) ) et B22 = ( 2(.5 - sin(ij)) )
!>              pour i=m+1,...,k,  j=m+1,...,k
!>
!> Type 5 :  (A,B) ont potentiellement des valeurs propres proches ou communes et
!>           un très grand écart par rapport à la diagonale par blocs. A_11 est choisi
!>           comme la sous-matrice principale m x m de A_1 :
!>                   |  1  b                            |
!>                   | -b  1                            |
!>                   |        1+d  b                    |
!>                   |         -b 1+d                   |
!>            A_1 =  |                  d  1            |
!>                   |                 -1  d            |
!>                   |                        -d  1     |
!>                   |                        -1 -d     |
!>                   |                               1  |
!>           et A_22 est choisi comme la sous-matrice principale k x k de A_2 :
!>                   | -1  b                            |
!>                   | -b -1                            |
!>                   |       1-d  b                     |
!>                   |       -b  1-d                    |
!>            A_2 =  |                 d 1+b            |
!>                   |               -1-b d             |
!>                   |

NAME


ddrgsx


définit le comportement de DGGESX







SYNOPSIS


 subroutine ddrgsx( NSIZE, NCMAX, THRESH, NIN, NOUT, A, LDA, B, AI, BI, Z, Q,
 &                  ALPHAR, ALPHAI, BETA, C, LDC, S, WORK, LWORK, IWORK,
 &                  LIWORK, BWORK, INFO )








Function/Subroutine Documentation




Cette routine teste DGGESX. Les matrices de test sont générées à
    partir de matrices de Toeplitz structurées de manière aléatoire ou de matrices
    identités. Les matrices de Kronecker pour calculer DIF sont également générées.


Le test est basé sur le calcul de l'erreur sur les valeurs propres de
    la matrice généralisée eigenvalue A B, et sur le calcul de la fiabilité de
    l'algorithme de mise en cache.


Les matrices d'entrée A et B sont initialisées comme suit :
    La matrice A est une matrice de Toeplitz aléatoire avec des entrées dans
    [−1, 1]. La matrice B est remplie avec des valeurs aléatoires dans [0, 1].
    Elle est ensuite mise à l'échelle pour avoir une valeur propre de 1.
    Alternativement, pour les grandes matrices, les matrices A et B sont choisies
    comme matrices d'identité (voir DLATM5).


Paramètres


NSIZE

!>          NSIZE est INTEGER
!>          La taille maximale des matrices à utiliser. NSIZE >= 0.
!>          Si NSIZE = 0, aucune matrice de test intégrée n'est utilisée, mais
!>          des matrices de test lues sont utilisées pour tester DGGESX.
!> 


NCMAX


!>          NCMAX est INTEGER
!>          NMAX maximum autorisé pour la génération de la matrice de Kronecker
!>          dans l'appel à DLAKF2
!> 


THRESH


!>          THRESH est DOUBLE PRECISION
!>          Un test sera considéré comme une erreur si l'erreur calculée,
!>          telle que décrite ci-dessus, dépasse THRESH. Notez que l'erreur
!>          est mise à l'échelle pour être de l'ordre de 1, donc THRESH devrait être
!>          un multiple raisonnablement petit de 1, par exemple, 10 ou 100.
!>          En particulier, il ne doit pas dépendre de la précision (simple ou double)
!>          ou de la taille de la matrice. THRESH >= 0.
!> 


NIN


!>          NIN est INTEGER
!>          Le numéro d'unité FORTRAN pour la lecture du fichier de données des
!>          problèmes à résoudre.
!> 


NOUT


!>          NOUT est INTEGER
!>          Le numéro d'unité FORTRAN pour l'impression des messages d'erreur
!>          (par exemple, si une routine retourne IINFO différent de 0).
!> 


A


!>          A est un tableau DOUBLE PRECISION, dimension (LDA, NSIZE)
!>          Utilisé pour stocker la matrice dont les valeurs propres doivent être
!>          calculées. À la sortie, A contient la dernière matrice réellement utilisée.
!> 


LDA


!>          LDA est INTEGER
!>          La dimension principale de A, B, AI, BI, Z et Q,
!>          LDA >= max( 1, NSIZE ). Pour le test lu,
!>          LDA >= max( 1, N ), où N est la taille des matrices de test.
!> 


B


!>          B est un tableau DOUBLE PRECISION, dimension (LDA, NSIZE)
!>          Utilisé pour stocker la matrice dont les valeurs propres doivent être
!>          calculées. À la sortie, B contient la dernière matrice réellement utilisée.
!> 


AI


!>          AI est un tableau DOUBLE PRECISION, dimension (LDA, NSIZE)
!>          Copie de A, modifiée par DGGESX.
!> 


BI


!>          BI est un tableau DOUBLE PRECISION, dimension (LDA, NSIZE)
!>          Copie de B, modifiée par DGGESX.
!> 


Z


!>          Z est un tableau DOUBLE PRECISION, dimension (LDA, NSIZE)
!>          Z contient les vecteurs de Schur gauches calculés par DGGESX.
!> 


Q


!>          Q est un tableau DOUBLE PRECISION, dimension (LDA, NSIZE)
!>          Q contient les vecteurs de Schur droits calculés par DGGESX.
!> 


ALPHAR


!>          ALPHAR est un tableau DOUBLE PRECISION, dimension (NSIZE)
!> 


ALPHAI


!>          ALPHAI est un tableau DOUBLE PRECISION, dimension (NSIZE)
!> 


BETA


!>          BETA est un tableau DOUBLE PRECISION, dimension (NSIZE)
!>
!>          À la sortie, (ALPHAR + ALPHAI*i)/BETA sont les valeurs propres.
!> 


C


!>          C est un tableau DOUBLE PRECISION, dimension (LDC, LDC)
!>          Stocke la matrice générée par la sous-routine DLAKF2, c'est la
!>          matrice formée par des produits de Kronecker utilisés pour estimer
!>          DIF.
!> 


LDC


!>          LDC est INTEGER
!>          La dimension principale de C. LDC >= max(1, LDA*LDA/2 ).
!> 


S


!>          S est un tableau DOUBLE PRECISION, dimension (LDC)
!>          Valeurs singulières de C
!> 


WORK


!>          WORK est un tableau DOUBLE PRECISION, dimension (LWORK)
!> 


LWORK


!>          LWORK est INTEGER
!>          La dimension du tableau WORK.
!>          LWORK >= MAX( 5*NSIZE*NSIZE/2 - 2, 10*(NSIZE+1) )
!> 


IWORK


!>          IWORK est un tableau INTEGER, dimension (LIWORK)
!> 


LIWORK


!>          LIWORK est INTEGER
!>          La dimension du tableau IWORK. LIWORK >= NSIZE + 6.
!> 


BWORK


!>          BWORK est un tableau LOGICAL, dimension (LDA)
!> 


INFO


!>          INFO est INTEGER
!>          = 0 : sortie réussie
!>          < 0 : si INFO = -i, le i-ème argument avait une valeur illégale.
!>          > 0 : une routine a retourné un code d'erreur.
!>
