DESCRIPTIO

N

À

propos

XZ est un format d'archivage qui utilise l'algorithme de compression LZMA2, également connu sous le nom d'algorithme de chaîne de Markov Lempel-Ziv. LZMA2 a corrigé certaines particularités de l'algorithme LZMA très performant, qui offre des taux de compression élevés et est connu pour ses vitesses de décompression supérieures. Il est optimisé pour des taux de compression bien meilleurs au détriment de la vitesse de compression par rapport à LZO, par exemple. Ses niveaux préréglés les plus bas tendent à surpasser les niveaux les plus hauts de gzip et les niveaux les plus bas de bzip2, tant en taux de compression qu'en

vitesse.

Ce plugin a été écrit pour dd_rescue et utilise l'interface de plugin de celui-ci. Voir la page man dd_rescue(1) pour plus d'informations sur dd

_re
scu
e.

OPTION

S

Les options sont transmises en utilisant la syntaxe de transmission d'options de dd_rescue : le nom du plugin (lzma) est éventuellement suivi d'un signe égal (=) et les options sont séparées par deux-points (:). Le plugin lzma autorise également la plupart des options courantes de l'utilitaire xz, avec quelques-unes supplémentaires. Voir la section EXEMPLES

ci-dessous.

Compression ou

décompression

Le plugin lzma de dd_rescue (par la suite appelé simplement ddr_lzma, ce qui reflète les parties variables du nom de fichier libddr_lzma.so) choisit automatiquement le mode compression ou décompression si l'un des fichiers d'entrée/sortie a un suffixe [lt]xz ; sinon, vous pouvez spécifier les paramètres z ou d sur la ligne de commande pour la compression et la décompression

respectivement.

Le paramètre mt indiquera à ddr_lzma d'effectuer la dé/compression en mode multithreadé. Cela peut accélérer le traitement des données en utilisant tous les cœurs du CPU. Si le nombre de cœurs ne peut pas être détecté, un seul sera utilisé. Vous pouvez également passer mt=N pour spécifier explicitement le nombre de threads à utiliser.
Notez que liblzma antérieur à 5.2.0 ne prend pas en charge la compression multithreadée, tandis que liblzma antérieur à 5.4.0 ne prend pas en charge la décompression multithreadée. Ce paramètre sera alors

ignoré.

Le plugin prend également en charge le paramètre bench[mark] ; s'il est spécifié, il produira des informations sur l'utilisation du

CPU.

Si vous voulez seulement effectuer une vérification d'intégrité du fichier compressé en xz, vous pouvez utiliser test ; si les données sont corrompues, vous obtiendrez un message dans la console à ce sujet. Au lieu de test, vous pouvez utiliser simplement

t.

Passez check=XXX où XXX peut être l'un des algorithmes de somme de contrôle d'intégrité suivants : CRC32, CRC64, SHA256, NONE. Si NONE est spécifié, la somme de contrôle d'intégrité ne sera pas calculée lors de la compression. Par défaut, CRC32 sera calculé par le

plugin.

De plus, si vous voulez limiter l'utilisation de la mémoire lors du décodage, utilisez le paramètre suivant : memlimit=XXX , où XXX est la limite de mémoire pour le décodage. Les suffixes habituels k, M, G sont pris en

charge. Les valeurs inférieures à 1M ou supérieures à
la taille de la mémoire de la machine seront rejetées.

Préréglages de

compression

Le paramètre preset=X , sélectionne le taux de compression, où X peut être un entier de 0 à 9 inclus. La valeur par défaut est 3, ce qui est inférieur à la valeur par défaut de 6 utilisée par xz mais offre une bande passante bien meilleure. L'effet sur la vitesse et le taux de compression est significatif, voir la documentation de xz. Notez que la vitesse de décompression est toujours très bonne avec lzma, même sans multithreading. Vous pouvez aj

outer un e au niveau de préréglage pour utiliser plus de CPU (mais pas plus de mémoire), en essayant de mieux compresser les données. Cela correspond à l'indicateur --extreme dans xz. Utilisez les niveaux 0,1,2 si vous
voulez des niveaux de compression meilleurs que le plus haut de gzip (ou le bas de bzip2) avec une meilleure vitesse. Le multithreading peut accélérer encore les choses, bien que vous deviez le tester sur votre système
, voir ci-dessous. Utilisez plutôt le plugin lzo pour obtenir les vitesses de compression les plus élevées (utilisation CPU la plus faible) et la consommation de mémoire la plus basse avec une compression très modeste.

BUGS/LIMITATION

S

Maturit

é

Le plugin est nouveau depuis dd_rescue 1.99.17. Ne vous fiez pas encore aux données sauvegardées avec ddr_lzma comme seule sauvegarde pour des données précieuses. Les options peuvent également encore changer à l'avenir. Après les événements autour de xz/liblzma en mars 2024, des examens supplémentaires devraient être effectués sur ce code avant de lui passer des fichiers compressés non

fiables.

Les données compressées sont plus sensibles aux corruptions de données que les données en clair. Notez que les sommes de contrôle dans le format de fichier xz ne permettent PAS de corriger les erreurs, car les octets suivants dépendent des précédents. Les sommes de contrôle permettent seulement une détection plutôt fiable des corruptions de

données.

Contrairement à ddr_lzo, aucun travail n'a été investi pour récupérer efficacement des données compressées corrompues. liblzma peut récupérer dans certains cas, mais ne comptez pas

dessus.

Lorsque vous décidez quel format de stockage compressé utiliser, veuillez lire https://www.nongnu.org/lzip/xz_inadequate.html. Bien que toutes les raisons données là-bas ne soient peut-être pas aussi sérieuses que l'auteur le laisse entendre, elles sont valides. En ce moment, le plugin lzma est le seul choix que vous avez pour une compression élevée dans dd_rescue ; envisagez d'utiliser des outils comme par2 pour vous protéger contre les corruptions pour le stockage à long terme. L'avenir peut apporter lzip, zstd ou d'autres plugins. Pour de nombreux objectifs, le plugin lzo éprouvé reste un choix

raisonnable.

Lors de l'utilisation du multithreading, vous pouvez rencontrer des bugs. Des symbol

es de fonction manquants lors de l'initialisation du décodeur, une memlimit pour le d
écodeur toujours définie à 1 octet pourraient être des problèmes que vous rencontrez
(cela dépend du système que vous utilisez). Testez l'option mt avant de vous y fier.

S

fichier_sortie

fichier_entree2
décompressera fichier_entree vers fichier_entree2 en mode multithreadé avec une limite de mémoire égale à 1234
mégaoctets.
dd_rescue -L lzma fichier_entree.xz
fichier_sortie
décompressera fichier_entree.xz vers fichier_sor
tie. (Le fait que le fichier d'entrée ait une e
xtension .xz fait que ddr_lzma suppose qu'il es
t compressé et que vous voulez le décompresser.)
