NOM

dropbear - serveur SSH léger

SYNTAXE

dropbear [arguments optionnels] [-b bannière] [-r fichier_clé_hote] [-p [adresse:]port]

DESCRIPTION

dropbear est un petit serveur SSH

OPTIONS

-b bannière
fichier_bannière. Affiche le contenu du fichier bannière avant la connexion de l'utilisateur (par défaut : aucun).
-r clé_hote
Utilise le contenu du fichier clé_hote comme clé hôte SSH. Ce fichier est généré avec dropbearkey(1) ou automatiquement avec l'option '-R'. Voir « Fichiers de clé hôte » ci-dessous.
-R
Génère automatiquement les clés hôtes. Voir « Fichiers de clé hôte » ci-dessous.
-F
Ne pas se détacher en arrière-plan.
-E
Journaliser vers la sortie d'erreur standard plutôt que syslog.
-e
Transmet l'environnement du serveur à tous les processus enfants. Ceci est requis, par exemple, si Dropbear est lancé à la volée par un gestionnaire de charge de travail SLURM. L'environnement n'est pas transmis par défaut. Notez que cela pourrait exposer des secrets dans les variables d'environnement du processus appelant - utilisez avec prudence.
-m
N'affiche pas le message du jour à la connexion.
-w
Interdit les connexions root.
-s
Désactive les connexions par mot de passe.
-g
Désactive les connexions par mot de passe pour root.
-t
Active l'authentification à deux facteurs. L'authentification par mot de passe et par clé publique est requise. Ne doit pas être utilisé avec l'option '-s'.
-j
Désactive le transfert de port local. Cela inclut les transferts de flux Unix.
-k
Désactive le transfert de port distant.
-p [adresse:]port
Écoute sur l'adresse et le port TCP spécifiés. Si seul un port est donné, écoute sur toutes les adresses. Jusqu'à 10 peuvent être spécifiés (par défaut 22 si aucun n'est spécifié).
-l interface
Écoute sur l'interface spécifiée
-i
Mode programme de service. Utilisez cette option pour exécuter dropbear sous des serveurs TCP/IP comme inetd, tcpsvd, ou tcpserver. En mode programme, l'option -F est implicite et les options -p sont ignorées.
-P fichier_pid
Spécifie un fichier PID à créer lors de l'exécution en tant que démon. S'il n'est pas spécifié, le défaut est /var/run/dropbear.pid
-a
Permet aux hôtes distants de se connecter aux ports transférés.
-W taille_fenêtre
Spécifie la taille du tampon de fenêtre de réception par canal. Augmenter ceci peut améliorer les performances réseau au détriment de l'utilisation de la mémoire. Utilisez -h pour voir la taille du tampon par défaut.
-K secondes_délai
Assure que le trafic est transmis à un certain intervalle en secondes. Ceci est utile pour contourner les pare-feux ou les routeurs qui interrompent les connexions après une certaine période d'inactivité. Le compromis est qu'une session peut être fermée s'il y a une interruption temporaire de la connectivité réseau. Un réglage de 0 désactive les keepalives. Si aucune réponse n'est reçue pendant 3 keepalives consécutifs, la connexion sera fermée.
-I délai_inactivité
Déconnecte la session si aucun trafic n'est transmis ou reçu pendant délai_inactivité secondes.
-z
Par défaut, Dropbear envoie le trafic réseau avec le réglage AF21 pour le QoS, permettant aux appareils réseau de lui donner une priorité plus élevée. Certains appareils peuvent avoir des problèmes avec cela, -z peut être utilisé pour le désactiver.
-T tentatives_authentification_max
Définit le nombre de tentatives d'authentification autorisées par connexion. Si non spécifié, la valeur par défaut est 10 (MAX_AUTH_TRIES)
-c commande_forcée
Ignore la commande fournie par l'utilisateur et exécute toujours commande_forcée. Cela remplace également toute option command= dans authorized_keys. La commande originale est enregistrée dans la variable d'environnement SSH_ORIGINAL_COMMAND (voir ci-dessous).
-D répertoire_clés_autorisées
Spécifie le répertoire à utiliser pour les fichiers authorized_keys. Le défaut est ~/.ssh , les chemins commençant par ~/ seront développés par rapport au répertoire personnel.
-V
Affiche la version

FICHIERS

Clés autorisées

~/.ssh/authorized_keys peut être configuré pour autoriser la connexion à distance avec une clé RSA, ECDSA, Ed25519 ou DSS. Chaque ligne est de la forme

[restrictions] ssh-rsa AAAAB3NzaC1yc2EAAAABIwAAAIgAsp... [commentaire]

et peut être extraite d'une clé hôte privée Dropbear avec "dropbearkey -y". C'est le même format qu'utilisé par OpenSSH, bien que les restrictions soient un sous-ensemble (les clés avec des restrictions inconnues sont ignorées). Les restrictions sont séparées par des virgules, avec des guillemets doubles autour des espaces dans les arguments. Les restrictions disponibles sont :

aucun-transfert-port
Ne pas autoriser le transfert de port pour cette connexion, y compris les flux Unix.
aucun-transfert-agent
Ne pas autoriser le transfert d'agent pour cette connexion
aucun-transfert-X11
Ne pas autoriser le transfert X11 pour cette connexion
aucun-pty
Désactiver l'allocation de PTY. Notez qu'un utilisateur peut toujours obtenir la plupart des fonctionnalités similaires par d'autres moyens même si aucun-pty est défini.
restreindre
Applique toutes les restrictions 'aucun-' listées ci-dessus.
autoriser-ouverture-port="hote:port"
Restreint le transfert de port local de sorte que la connexion ne soit autorisée qu'à l'hôte et au port spécifiés. Plusieurs options autoriser-ouverture-port séparées par des virgules peuvent être définies dans authorized_keys. Le caractère générique ('*') peut être utilisé dans la spécification du port pour correspondre à n'importe quel port. Les hôtes doivent être des noms de domaine littéraux ou des adresses IP.
commande="commande_forcée"
Ignore la commande fournie par l'utilisateur et exécute toujours commande_forcée. L'option de ligne de commande -c remplace ceci.

Le fichier authorized_keys et son répertoire ~/.ssh parent doivent être inscriptibles uniquement par l'utilisateur, sinon Dropbear n'autorisera pas une connexion utilisant l'authentification par clé publique.

Fichiers de clé hôte

Les fichiers de clé hôte sont lus au démarrage à partir d'un emplacement standard, par défaut /etc/dropbear/dropbear_dss_host_key, /etc/dropbear/dropbear_rsa_host_key, /etc/dropbear/dropbear_ecdsa_host_key et /etc/dropbear/dropbear_ed25519_host_key

Si l'option de ligne de commande -r est spécifiée, les fichiers par défaut ne sont pas chargés. Les fichiers de clé hôte sont du type généré par dropbearkey. L'option -R peut être utilisée pour générer automatiquement des clés à l'emplacement par défaut - les clés seront générées après le démarrage lors de l'établissement de la première connexion. Cela présente l'avantage que la source d'aléa /dev/urandom du système a une meilleure chance d'être initialisée de manière sécurisée.
