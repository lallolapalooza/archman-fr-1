DROP_PROCEDURE(7)

Paquet: postgresql

Licences: PostgreSQL

DROP PROCEDURE(7) Documentation PostgreSQL 18.1 DROP PROCEDURE(7)

NOM

DROP PROCEDURE - supprimer une procédure

SYNTAXE

DROP PROCEDURE [ IF EXISTS ] nom [ ( [ [ argmode ] [ argname ] argtype [, ...] ] ) ] [, ...]
    [ CASCADE | RESTRICT ]

DESCRIPTION

DROP PROCEDURE supprime la définition d'une ou plusieurs procédures existantes. Pour exécuter cette commande, l'utilisateur doit être le propriétaire de la ou des procédures. Les types d'arguments de la ou des procédures doivent généralement être spécifiés, car plusieurs procédures différentes peuvent exister avec le même nom et des listes d'arguments différentes.

PARAMETRES

IF EXISTS

Ne lance pas d'erreur si la procédure n'existe pas. Une notification est émise dans ce cas.

nom

Le nom (éventuellement qualifié par un schéma) d'une procédure existante.

argmode

Le mode d'un argument : IN, OUT, INOUT, ou VARIADIC. Si omis, la valeur par défaut est IN (mais voir ci-dessous).

argname

Le nom d'un argument. Notez que DROP PROCEDURE ne prend pas réellement en compte les noms d'arguments, car seuls les types de données des arguments sont utilisés pour déterminer l'identité de la procédure.

argtype

Le(s) type(s) de données des arguments de la procédure (éventuellement qualifié par un schéma), le cas échéant. Voir ci-dessous pour plus de détails.

CASCADE

Supprime automatiquement les objets qui dépendent de la procédure, et à leur tour tous les objets qui dépendent de ces objets (voir Section 5.15).

RESTRICT

Refuse de supprimer la procédure si des objets en dépendent. C'est la valeur par défaut.

NOTES

S'il n'y a qu'une seule procédure du nom donné, la liste des arguments peut être omise. Omettez aussi les parenthèses dans ce cas.

Dans PostgreSQL, il suffit de lister les arguments d'entrée (y compris INOUT), car aucune autre procédure du même nom n'est autorisée à partager la même liste d'arguments d'entrée. De plus, la commande DROP ne vérifiera pas réellement que vous avez correctement écrit les types des arguments OUT ; les arguments explicitement marqués OUT ne sont donc que des informations supplémentaires. Mais les écrire est recommandé pour la cohérence avec la commande CREATE correspondante.

Par souci de compatibilité avec la norme SQL, il est également permis d'écrire tous les types de données des arguments (y compris ceux des arguments OUT) sans aucun marqueur argmode. Lorsque cela est fait, les types des arguments OUT de la procédure seront vérifiés par rapport à la commande. Cette disposition crée une ambiguïté, car lorsque la liste des arguments ne contient aucun marqueur argmode, il n'est pas clair quelle règle est destinée. La commande DROP tentera la recherche des deux manières, et générera une erreur si deux procédures différentes sont trouvées. Pour éviter le risque d'une telle ambiguïté, il est recommandé d'écrire explicitement les marqueurs IN plutôt que de les laisser par défaut, forçant ainsi l'utilisation de l'interprétation traditionnelle de PostgreSQL.

Les règles de recherche expliquées ci-dessus sont également utilisées par d'autres commandes qui agissent sur les procédures existantes, telles que ALTER PROCEDURE et COMMENT ON PROCEDURE.

EXEMPLES

S'il n'y a qu'une seule procédure do_db_maintenance, cette commande suffit pour la supprimer :

DROP PROCEDURE do_db_maintenance;

Étant donné cette définition de procédure :

CREATE PROCEDURE do_db_maintenance(IN target_schema text, OUT results text) ...

l'une quelconque de ces commandes permettrait de la supprimer :

DROP PROCEDURE do_db_maintenance(IN target_schema text, OUT results text);
DROP PROCEDURE do_db_maintenance(IN text, OUT text);
DROP PROCEDURE do_db_maintenance(IN text);
DROP PROCEDURE do_db_maintenance(text);
DROP PROCEDURE do_db_maintenance(text, text);  -- potentiellement ambigu

Cependant, le dernier exemple serait ambigu s'il existait également, par exemple :

CREATE PROCEDURE do_db_maintenance(IN target_schema text, IN options text) ...

COMPATIBILITE

Cette commande est conforme à la norme SQL, avec ces extensions PostgreSQL :

•La norme n'autorise la suppression que d'une seule procédure par commande.
•L'option IF EXISTS est une extension.
•La capacité de spécifier les modes et les noms des arguments est une extension, et les règles de recherche diffèrent lorsque les modes sont donnés.
