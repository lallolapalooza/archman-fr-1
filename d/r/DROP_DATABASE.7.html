DROP_DATABASE(7)

Paquet: postgresql

Licences: PostgreSQL

DROP DATABASE(7) Documentation PostgreSQL 18.1 DROP DATABASE(7)

NOM

DROP_DATABASE - supprimer une base de données

SYNTAXE

DROP DATABASE [ IF EXISTS ] nom [ [ WITH ] ( option [, ...] ) ]
où option peut être :
    FORCE

DESCRIPTION

DROP DATABASE supprime une base de données. Elle retire les entrées du catalogue pour la base de données et supprime le répertoire contenant les données. Elle ne peut être exécutée que par le propriétaire de la base de données. Elle ne peut pas être exécutée pendant que vous êtes connecté à la base de données cible. (Connectez-vous à postgres ou à toute autre base de données pour émettre cette commande.) De plus, si quelqu'un d'autre est connecté à la base de données cible, cette commande échouera à moins que vous n'utilisiez l'option FORCE décrite ci-dessous.

DROP DATABASE ne peut pas être annulée. Utilisez-la avec précaution !

PARAMÈTRES

IF EXISTS

Ne génère pas d'erreur si la base de données n'existe pas. Un message d'information est émis dans ce cas.

nom

Le nom de la base de données à supprimer.

FORCE

Tente de terminer toutes les connexions existantes à la base de données cible. Elle ne se termine pas si des transactions préparées, des slots de réplication logique actifs ou des abonnements sont présents dans la base de données cible.

Cela termine les connexions des travailleurs en arrière-plan et les connexions que l'utilisateur actuel a la permission de terminer avec pg_terminate_backend, décrit dans la Section 9.28.2. Si des connexions subsistent, cette commande échouera.

NOTES

DROP DATABASE ne peut pas être exécutée à l'intérieur d'un bloc de transaction.

Cette commande ne peut pas être exécutée pendant que vous êtes connecté à la base de données cible. Ainsi, il peut être plus pratique d'utiliser le programme dropdb(1) à la place, qui est un wrapper autour de cette commande.

COMPATIBILITÉ

Il n'y a pas d'instruction DROP DATABASE dans la norme SQL.

VOIR AUSSI
