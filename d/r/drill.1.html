drill(1) Manuel des commandes générales drill(1)

NOM

drill - extraire (déboguer) des informations de DNS(SEC)

SYNTAXE

drill [ OPTIONS ] nom [ @serveur ] [ type ] [ classe ]

DESCRIPTION

drill est un outil conçu pour extraire toutes sortes d'informations du DNS. Il est spécifiquement conçu pour être utilisé avec DNSSEC.

Le nom drill est un jeu de mots avec dig. Avec drill, vous devriez pouvoir obtenir encore plus d'informations qu'avec dig.

Si aucun argument n'est donné, la classe par défaut est 'IN' et le type 'A'. Les serveurs spécifiés dans /etc/resolv.conf sont utilisés pour les requêtes.

nom Demander cette information pour ce nom.

@serveur Envoyer la requête à ce serveur. Si non spécifié, utiliser les serveurs de noms de /etc/resolv.conf.

type Demander ce type d'enregistrement (RR). Si le type n'est pas donné en ligne de commande, il est par défaut 'A'. Sauf en cas de recherche inversée où il est par défaut 'PTR'.

classe Utiliser cette classe lors de la requête.

EXEMPLE D'UTILISATION

drill mx miek.nl Afficher les enregistrements MX du domaine miek.nl

drill -S jelte.nlnetlabs.nl
Suivre les signatures dans le domaine jelte.nlnetlab.nl. Cette option n'est disponible que si ldns a été compilé avec le support d'openssl.
drill -TD www.example.com
Effectuer une trace DNSSEC (-D) (-T) depuis les serveurs racine jusqu'à www.example.com. Cette option ne fonctionne que si ldns a été compilé avec le support d'openssl.
drill -s dnskey jelte.nlnetlabs.nl
Afficher les enregistrements DNSKEY pour jelte.nlnetlabs.nl. Pour chaque enregistrement DNSKEY trouvé, afficher également l'enregistrement DS.

OPTIONS

-D
Activer DNSSEC dans la requête. Lors de la requête pour des types DNSSEC (DNSKEY, RRSIG, DS et NSEC), cette option n'est pas automatiquement activée.
-T
Tracer le nom depuis la racine. Lors de l'utilisation de cette option, l'argument @serveur n'est pas utilisé.
-S
Suivre la ou les signatures de 'nom' jusqu'à une clé connue ou aussi haut que possible dans l'arbre.
-I adresse IPv4 ou IPv6
Adresse source depuis laquelle interroger. L'adresse source doit être présente sur une interface de la machine exécutant drill.
-V niveau
Être plus verbeux. Définir le niveau à 5 pour voir la requête réelle envoyée.
-Q
Mode silencieux, cela remplace -V.
-f fichier
Lire la requête depuis un fichier. La requête doit avoir été sauvegardée avec -w.
-i fichier
Lire la réponse depuis le fichier au lieu du réseau. Cela aide au débogage et peut être utilisé pour vérifier si une requête sur disque est valide. Si le fichier contient des données binaires, il est supposé être une requête dans l'ordre réseau.
-w fichier
Écrire un paquet de réponse dans le fichier.
-q fichier
Écrire le paquet de requête dans le fichier.
-v
Afficher la version de drill.
-h
Afficher un court message d'aide.

OPTIONS DE REQUETE

-4
Rester en ip4. N'envoyer des requêtes qu'aux serveurs de noms compatibles ip4.
-6
Rester en ip6. N'envoyer des requêtes qu'aux serveurs de noms compatibles ip6.
-a
Utiliser le mécanisme de repli de la structure du résolveur si la réponse est tronquée (TC=1). Si un paquet tronqué est reçu et que cette option est activée, drill enverra d'abord une nouvelle requête avec une taille de tampon EDNS0 de 4096.

Si la taille du tampon EDNS0 était déjà définie à 512 octets ou plus, ou si la nouvelle tentative susmentionnée aboutit également à une réponse tronquée, la structure du résolveur utilisera TCP.

-b taille
Utiliser taille comme taille de tampon dans l'enregistrement pseudo-RR EDNS0.
-c fichier
Utiliser fichier au lieu de /etc/resolv.conf pour la configuration des serveurs de noms.
-d domaine
Lors du traçage (-T), commencer à partir de ce domaine au lieu de la racine.
-t
Utiliser TCP/IP lors de l'interrogation d'un serveur.
-k fichierclé
Utiliser ce fichier pour lire une clé (de confiance). Lorsque cette option est donnée, drill essaie de valider la réponse actuelle avec cette clé. Aucun suivi n'est effectué. Lorsque drill effectue un traçage sécurisé, cette clé sera utilisée comme ancre de confiance. Peut contenir un enregistrement DNSKEY ou DS.

Alternativement, lorsque le traçage DNSSEC activé (-TD) ou le suivi de signature (-S) est utilisé, si -k n'est pas spécifié et qu'une ancre de confiance par défaut (/etc/trusted-key.key) existe et contient un enregistrement DNSKEY ou DS valide, elle sera utilisée comme ancre de confiance.

-o mnémonique
Utiliser cette option pour définir ou désactiver des bits d'en-tête spécifiques. Un bit est défini en utilisant la mnémonique du bit en LETTRES MAJUSCULES. Un bit est désactivé lorsque la mnémonique est donnée en minuscules. Les mnémoniques suivantes sont comprises par drill:


QR, qr: définir, désactiver QueRy (par défaut: activé)
AA, aa: définir, désactiver Authoritative Answer (par défaut: désactivé)
TC, tc: définir, désactiver TrunCated (par défaut: désactivé)
RD, rd: définir, désactiver Recursion Desired (par défaut: activé)
CD, cd: définir, désactiver Checking Disabled (par défaut: désactivé)
RA, ra: définir, désactiver Recursion Available (par défaut: désactivé)
AD, ad: définir, désactiver Authenticated Data (par défaut: désactivé)

Ainsi: -o CD, activeront Checking Disabled, ce qui indique au cache de ne pas valider les réponses qu'il fournit.

-p port
Utiliser ce port au lieu du port par défaut 53.
-r fichier
Lors du traçage (-T), utiliser fichier comme fichier d'indices pour les serveurs racine.
-s
Lors de la rencontre d'un DNSKEY, afficher également le DS équivalent.
-u
Utiliser UDP lors de l'interrogation d'un serveur. C'est le comportement par défaut.
-w fichier
écrire la réponse dans un fichier. Le fichier contiendra un vidage hexadécimal de la requête. Ceci peut être utilisé en conjonction avec -f.
-x
Effectuer une recherche inversée. L'argument type n'est pas utilisé, il est prédéfini à PTR.
-y <nom:clé[:algo]>
spécifier une clé tsig nommée en base64, et optionnellement un algorithme (par défaut hmac-md5.sig-alg.reg.int)
-z
ne pas aléatoiriser la liste des serveurs de noms avant d'envoyer des requêtes.

OPTIONS DE REQUETE EDNS

+nsid
Lorsqu'elle est définie, cette option EDNS inclut une demande d'identifiant de serveur de noms EDNS dans la requête.

STATUT DE RETOUR

Le statut de retour est 0 si la réponse recherchée est sécurisée et de confiance, ou non sécurisée. Le statut de retour n'est pas 0 si la réponse recherchée n'est pas de confiance ou est invalide, ou si une erreur s'est produite lors de la recherche.

FICHIERS

/etc/trusted-key.key
Le fichier à partir duquel les clés de confiance sont chargées.
