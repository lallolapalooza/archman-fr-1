DROP OWNED(7) Documentation PostgreSQL 18.1 DROP OWNED(7)

NOM

DROP_OWNED - supprimer les objets de base de données appartenant à un rôle de base de données

SYNTAXE

DROP OWNED BY { nom | CURRENT_ROLE | CURRENT_USER | SESSION_USER } [, ...] [ CASCADE | RESTRICT ]

DESCRIPTION

DROP OWNED supprime tous les objets de la base de données actuelle qui appartiennent à l'un des rôles spécifiés. Tous les privilèges accordés aux rôles donnés sur des objets dans la base de données actuelle ou sur des objets partagés (bases de données, tablespaces, paramètres de configuration) seront également révoqués.

PARAMETRES

nom

Le nom d'un rôle dont les objets seront supprimés, et dont les privilèges seront révoqués.

CASCADE

Supprimer automatiquement les objets qui dépendent des objets affectés, et à leur tour tous les objets qui dépendent de ces objets (voir Section 5.15).

RESTRICT

Refuser de supprimer les objets appartenant à un rôle si d'autres objets de base de données dépendent de l'un des objets affectés. C'est le comportement par défaut.

NOTES

DROP OWNED est souvent utilisé pour préparer la suppression d'un ou plusieurs rôles. Comme DROP OWNED n'affecte que les objets de la base de données actuelle, il est généralement nécessaire d'exécuter cette commande dans chaque base de données qui contient des objets appartenant à un rôle à supprimer.

L'utilisation de l'option CASCADE peut faire régresser la commande vers des objets appartenant à d'autres utilisateurs.

La commande REASSIGN OWNED est une alternative qui réaffecte la propriété de tous les objets de base de données appartenant à un ou plusieurs rôles. Cependant, REASSIGN OWNED ne traite pas les privilèges pour d'autres objets.

Les bases de données et les tablespaces appartenant au(x) rôle(s) ne seront pas supprimés.

Voir Section 21.4 pour plus de discussions.

COMPATIBILITE

La commande DROP OWNED est une extension PostgreSQL.

VOIR AUSSI

REASSIGN OWNED (REASSIGN_OWNED(7)), DROP ROLE (DROP_ROLE(7))
