DESCRIPTIO

N

dracut.conf est chargé pendant la phase d'initialisation de

dracut.

Les fichiers *.conf sont lus depuis /run/initramfs/dracut.conf.d, /usr/lib/dracut/dracut.conf.d et /etc/dracut.conf.d. Les fichiers portant le même nom dans /etc/dracut.conf.d remplaceront les fichiers dans /usr/lib/dracut/drac

ut.conf.d.

Les fichiers sont ensuite lus dans l'ordre alphanumérique et remplaceront les paramètres définis dans /etc/dracut.conf. Chaque ligne spécifie un attribut et une valeur. Un '#' indique le début d'un commentaire ; les caractères suivants, jusqu'à la fin de la ligne, ne sont pas

interprétés.

Les options de ligne de commande de dracut remplaceront toutes les valeurs définies

ici.

Les fichiers de configuration doivent avoir l'extension .conf ; les autres ext

ensions son
t ignorées.

"
Spécifie une liste de modules dracut séparés par des espaces à appeler lors de la construction de l'initramfs. Les modules sont situés dans /usr/lib/dracut/modules.d. hostonly="{oui|non}"

Mode hôte uniquement : Installe uniquement ce qui est nécessaire pour le démarrage de l'hôte local au lieu d'un hôte générique et génère une configuration spécifique à l'hôte (par défaut=oui).

hostonly_mode="{sloppy|strict}"

Spécifie le mode hôte uniquement à utiliser (par défaut=sloppy).

En mode hôte uniquement "sloppy", des pilotes et modules supplémentaires seront installés, de sorte qu'un changement matériel mineur ne rendra pas l'image in-démarrable (par exemple, un clavier changé), et l'image reste portable entre hôtes similaires.

Avec le mode "strict" activé, tout ce qui n'est pas nécessaire pour démarrer l'hôte local dans son état actuel ne sera pas inclus, et les modules peuvent faire des efforts supplémentaires pour économiser plus d'espace. Des changements mineurs dans le matériel ou l'environnement peuvent rendre l'image in-démarrable.

hostonly_cmdline="{oui|non}"

Si défini sur "oui", stocke les arguments de la ligne de commande du noyau nécessaires dans l'initramfs. Si hostonly="oui" et cette option n'est pas configurée, elle est automatiquement définie sur "oui". (par défaut=non)

hostonly_nics+=" [<nic>[ <nic> ...]] "

N'active que les cartes réseau listées dans l'initramfs. La liste peut être vide, afin que d'autres modules n'installent que les pilotes réseau nécessaires.

persistent_policy="<politique>"

Utilise <politique> pour adresser les disques et partitions. <politique> peut être n'importe quel nom de répertoire trouvé dans /dev/disk (par exemple, "by-uuid", "by-label"), ou "mapper" pour utiliser les noms d'appareils /dev/mapper (par défaut=mapper).

tmpdir="<répertoire temporaire>"

Spécifie le répertoire temporaire à utiliser.

Attention

Si vous vous chrootez vers une racine autre que la vraie racine de l'appareil, utilisez
--fstab et fournissez un /etc/fstab valide.

use_fstab="{oui|non}"

Utilise /etc/fstab au lieu de /proc/self/mountinfo (par défaut=non).

add_fstab+=" <nom de fichier> "

Ajoute les entrées de <nom de fichier> au /etc/fstab de l'initramfs.

add_device+=" <appareil> "

Active <appareil> dans l'initramfs, <appareil> doit être le nom de l'appareil. Ceci peut être utile en mode hôte uniquement pour la prise en charge de la reprise lorsque votre swap est sur LVM ou une partition chiffrée.

mdadmconf="{oui|non}"

Inclut le fichier local /etc/mdadm.conf (par défaut=non).

lvmconf="{oui|non}"

Inclut le fichier local /etc/lvm/lvm.conf (par défaut=non).

fscks=" <outils fsck> "

Ajoute une liste d'outils fsck séparés par des espaces.

Si rien n'est spécifié, la valeur par défaut est umount mount /sbin/fsck* xfs_db xfs_check xfs_repair e2fsck jfs_fsck btrfsck.

L'installation est opportuniste (les outils non existants sont ignorés).

nofscks="{oui|non}"

Si spécifié, empêche l'installation de tout outil fsck (par défaut=non).

ro_mnt="{oui|non}"

Monte / et /usr en lecture seule par défaut (par défaut=non).

kernel_cmdline="paramètres"

Spécifie les paramètres par défaut de la ligne de commande du noyau. Malgré son nom, cette commande ne définit que les paramètres de l'initrd.

kernel_only="{oui|non}"

Installe uniquement les pilotes et fichiers de firmware du noyau (par défaut=non).

no_kernel="{oui|non}"

N'installe pas les pilotes et fichiers de firmware du noyau (par défaut=non).

acpi_override="{oui|non}"


Attention

N'utilisez ceci que si vous savez ce que vous faites !

Remplace les tables ACPI fournies par le BIOS. Pour plus de documentation, lisez Documentation/acpi/initrd_table_override.txt https://www.kernel.org/doc/Documentation/acpi/initrd_table_override.txt dans les sources du noyau. Recherchez les fichiers de table ACPI (doivent avoir le suffixe .aml) dans le répertoire acpi_table_dir= (voir ci-dessous) et ajoutez-les à une archive cpio distincte non compressée.

Cette archive cpio est collée (concaténée, l'archive non compressée doit être la première) à l'archive cpio compressée. La première archive cpio non compressée est destinée aux données auxquelles le noyau doit pouvoir accéder très tôt (et ne peut pas encore utiliser d'algorithmes de décompression) comme le microcode ou les tables ACPI.

(par défaut=non).

acpi_table_dir="<dir>"

Répertoire où rechercher les tables ACPI si acpi_override= est défini sur oui.

early_microcode="{oui|non}"

Combine le microcode précoce avec la ramdisk (par défaut=oui).

stdloglvl="{0-6}"

Spécifie le niveau de journalisation pour la sortie d'erreur standard (par défaut=3).

Tableau 1. Niveaux de journalisation

0 supprimer tout message
1 erreurs fatales uniquement
2 toutes les erreurs
3 avertissements
4 informations
5 informations de débogage (ici commence beaucoup de sortie)
6 informations de trace (et encore plus)

sysloglvl="{0-6}"

Spécifie le niveau de journalisation pour syslog (par défaut=0).

fileloglvl="{0-6}"

Spécifie le niveau de journalisation pour le fichier journal (par défaut=4).

Chemin vers le fichier journal.

Fichier de clé SSH utilisé avec le module ssh-client.

show_modules="{oui|non}"

Affiche le nom des modules inclus sur la sortie standard pendant la construction (par défaut=non).

Mappage de variables spécifique à la distribution. Voir dracut/modules.d/10i18n/README pour une description détaillée.

i18n_default_font="<nom de police>"

La police <nom de police> à installer, si non spécifiée autrement. La valeur par défaut est "eurlatgr".

i18n_install_all="{oui|non}"

Installe tout, indépendamment du mode générique ou hôte uniquement (par défaut=non).

reproducible="{oui|non}"

Crée des images reproductibles (par défaut=non).

noimageifnotneeded="{oui|non}"

Ne crée pas d'image en mode hôte uniquement, si aucun pilote de noyau n'est nécessaire et si aucun fichier /etc/cmdline/*.conf ne sera généré dans l'initramfs (par défaut=non).

loginstall="<répertoire>"

Journalise tous les fichiers installés depuis l'hôte dans <répertoire>.

uefi="{oui|non}"

Au lieu de créer une image initramfs, dracut créera un exécutable UEFI, qui peut être exécuté par un BIOS UEFI (par défaut=non).

Le nom de fichier de sortie par défaut est <EFI>/EFI/Linux/linux-$kernel$-<MACHINE_ID>-<BUILD_ID>.efi. <EFI> peut être /efi, /boot ou /boot/efi selon l'endroit où la partition ESP est montée. Le <BUILD_ID> est pris de BUILD_ID dans /usr/lib/os-release ou s'il existe /etc/os-release et est omis si BUILD_ID n'existe pas ou est vide.

machine_id="{oui|non}"

Affecte le nom de fichier de sortie par défaut de l'exécutable UEFI, y compris la partie <MACHINE_ID> (par défaut=oui).

uefi_stub="<fichier>"

Spécifie le chargeur d'amorçage UEFI, qui chargera le noyau, l'initramfs et la ligne de commande du noyau attachés et démarrera le noyau. La valeur par défaut est /lib/systemd/boot/efi/linux<EFI-MACHINE-TYPE-NAME>.efi.stub.

uefi_splash_image="<fichier>"

Spécifie l'image d'écran de démarrage du chargeur d'amorçage UEFI. Nécessite le format d'image bitmap (.bmp).

uefi_secureboot_cert="<fichier>", uefi_secureboot_key="<fichier>"

Spécifie un certificat et la clé correspondante, qui sont utilisés pour signer l'exécutable UEFI créé. Nécessite que le certificat et la clé soient spécifiés et que sbsign soit installé.

uefi_secureboot_engine="paramètre"

Spécifie un moteur à utiliser lors de la signature de l'exécutable UEFI créé. Par exemple, "pkcs11"

kernel_image="<fichier>"

Spécifie l'image du noyau à inclure dans l'exécutable UEFI. La valeur par défaut est /lib/modules/<KERNEL-VERSION>/vmlinuz ou /boot/vmlinuz-<KERNEL-VERSION>.

sbat="paramètres"

Spécifie les paramètres SBAT à inclure dans l'exécutable UEFI. Par défaut, le SBAT par défaut est retiré
ng ajouté est sbat,1,SBAT Version,sbat,1, https://github.com/rhboot/shim/blob/main/SBAT
.
