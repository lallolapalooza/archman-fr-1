NOM

dropuser - supprimer un compte utilisateur PostgreSQL

SYNTAXE

dropuser [option-connexion...] [option...] [nomutilisateur]

DESCRIPTION

dropuser supprime un compte utilisateur PostgreSQL existant. Les superutilisateurs peuvent utiliser cette commande pour supprimer n'importe quel rôle ; sinon, seuls les rôles non superutilisateurs peuvent être supprimés, et seulement par un utilisateur qui possède le privilège CREATEROLE et qui a reçu l'option ADMIN sur le rôle cible.

dropuser est un script enveloppant la commande SQL DROP ROLE. Il n'y a pas de différence effective entre la suppression d'utilisateurs via cet utilitaire et via d'autres méthodes d'accès au serveur.

OPTIONS

dropuser accepte les arguments de ligne de commande suivants :

nomutilisateur

Spécifie le nom de l'utilisateur PostgreSQL à supprimer. Une invite vous sera demandée si aucun n'est spécifié sur la ligne de commande et que l'option -i/--interactive est utilisée.

-e
--echo

Affiche les commandes que dropuser génère et envoie au serveur.

-i
--interactive

Demande confirmation avant de supprimer réellement l'utilisateur, et demande le nom d'utilisateur si aucun n'est spécifié sur la ligne de commande.

-V
--version

Affiche la version de dropuser et quitte.

--if-exists

Ne génère pas d'erreur si l'utilisateur n'existe pas. Un avis est émis dans ce cas.

-?
--help

Affiche l'aide sur les arguments de la ligne de commande de dropuser et quitte.

dropuser accepte également les arguments de ligne de commande suivants pour les paramètres de connexion :

-h hôte
--host=hôte

Spécifie le nom d'hôte de la machine sur laquelle le serveur s'exécute. Si la valeur commence par un slash, elle est utilisée comme répertoire pour le socket de domaine Unix.

-p port
--port=port

Spécifie le port TCP ou l'extension de fichier de socket de domaine Unix local sur lequel le serveur écoute les connexions.

-U nomutilisateur
--username=nomutilisateur

Nom d'utilisateur pour se connecter (pas le nom d'utilisateur à supprimer).

-w
--no-password

Ne jamais demander de mot de passe. Si le serveur exige une authentification par mot de passe et qu'un mot de passe n'est pas disponible par d'autres moyens tels qu'un fichier .pgpass, la tentative de connexion échouera. Cette option peut être utile dans les tâches batch et les scripts où aucun utilisateur n'est présent pour saisir un mot de passe.

-W
--password

Force dropuser à demander un mot de passe avant de se connecter à une base de données.

Cette option n'est jamais essentielle, car dropuser demandera automatiquement un mot de passe si le serveur l'exige. Cependant, dropuser gaspillera une tentative de connexion pour découvrir que le serveur veut un mot de passe. Dans certains cas, il vaut la peine de taper -W pour éviter la tentative de connexion supplémentaire.

ENVIRONNEMENT

PGHOST
PGPORT
PGUSER

Paramètres de connexion par défaut

PG_COLOR

Spécifie si il faut utiliser la couleur dans les messages de diagnostic. Les valeurs possibles sont always, auto et never.

Cet utilitaire, comme la plupart des autres utilitaires PostgreSQL, utilise également les variables d'environnement prises en charge par libpq (voir la section 32.15).

DIAGNOSTICS

En cas de difficulté, consultez DROP ROLE (DROP_ROLE(7)) et psql(1) pour des discussions sur les problèmes potentiels et les messages d'erreur. Le serveur de base de données doit être en cours d'exécution sur l'hôte cible. De plus, tous les paramètres de connexion par défaut et les variables d'environnement utilisés par la bibliothèque frontale libpq s'appliqueront.

EXEMPLES

Pour supprimer l'utilisateur joe du serveur de base de données par défaut :

$ dropuser joe

Pour supprimer l'utilisateur joe en utilisant le serveur sur l'hôte eden, port 5000, avec vérification et un aperçu de la commande sous-jacente :

$ dropuser -p 5000 -h eden -i -e joe
Le rôle « joe » sera supprimé définitivement.
Êtes-vous sûr ? (o/n) o
DROP ROLE joe;

VOIR AUSSI
