DROP ROLE(7) Documentation PostgreSQL 18.1 DROP ROLE(7)

NOM

DROP ROLE - supprimer un rôle de base de données

SYNTAXE

DROP ROLE [ IF EXISTS ] nom [, ...]

DESCRIPTION

DROP ROLE supprime le ou les rôles spécifiés. Pour supprimer un rôle superutilisateur, vous devez être vous-même un superutilisateur ; pour supprimer des rôles non-superutilisateurs, vous devez avoir le privilège CREATEROLE et avoir reçu l'option ADMIN sur le rôle.

Un rôle ne peut pas être supprimé s'il est encore référencé dans une base de données du cluster ; une erreur sera générée si c'est le cas. Avant de supprimer le rôle, vous devez supprimer tous les objets dont il est propriétaire (ou réassigner leur propriété) et révoquer tous les privilèges qui ont été accordés au rôle sur d'autres objets. Les commandes REASSIGN OWNED et DROP OWNED peuvent être utiles à cet effet ; voir la section 21.4 pour plus de discussions.

Cependant, il n'est pas nécessaire de supprimer les appartenances de rôles impliquant le rôle ; DROP ROLE révoque automatiquement toutes les appartenances du rôle cible dans d'autres rôles, et des autres rôles dans le rôle cible. Les autres rôles ne sont ni supprimés ni affectés autrement.

PARAMETRES

IF EXISTS

Ne pas générer d'erreur si le rôle n'existe pas. Un avis est émis dans ce cas.

nom

Le nom du rôle à supprimer.

NOTES

PostgreSQL inclut un programme dropuser(1) qui a la même fonctionnalité que cette commande (en fait, il appelle cette commande) mais peut être exécuté depuis la ligne de commande.

EXEMPLES

Pour supprimer un rôle :

DROP ROLE jonathan;

COMPATIBILITE

La norme SQL définit DROP ROLE, mais elle n'autorise qu'un seul rôle à être supprimé à la fois, et elle spécifie des exigences de privilèges différentes de celles utilisées par PostgreSQL.
