drm(7) Gestionnaire de rendu direct drm(7)

Nom

drm - Gestionnaire de rendu direct

Synopsis

#include <xf86drm.h>

Description

Le gestionnaire de rendu direct (DRM) est un framework pour gérer les processeurs graphiques (GPU). Il est conçu pour répondre aux besoins des périphériques graphiques complexes, contenant généralement des pipelines programmables bien adaptés à l'accélération graphique 3D. De plus, il est responsable de la gestion de la mémoire, de la gestion des interruptions et du DMA pour fournir une interface uniforme aux applications.

Auparavant, le framework du noyau était uniquement utilisé pour fournir un accès matériel brut aux processus privilégiés de l'espace utilisateur qui implémentent toutes les couches d'abstraction matérielle. Mais de plus en plus de tâches ont été déplacées vers le noyau. Toutes ces interfaces sont basées sur des commandes ioctl(2) sur le périphérique caractère DRM. La bibliothèque libdrm fournit des wrappers pour ces appels système et de nombreuses fonctions d'aide pour simplifier l'API.

Lorsqu'un GPU est détecté, le système DRM charge un pilote pour le type de matériel détecté. Chaque GPU connecté est ensuite présenté à l'espace utilisateur via un périphérique caractère qui est généralement disponible sous le nom de /dev/dri/card0 et peut être accédé avec open(2) et close(2). Cependant, cela dépend toujours du pilote graphique des interfaces disponibles sur ces périphériques. Si une interface n'est pas disponible, les appels système échoueront avec EINVAL.

Authentification

Tous les périphériques DRM fournissent des mécanismes d'authentification. Seul un maître DRM est autorisé à effectuer des réglages de mode ou à modifier l'état principal et un seul utilisateur peut être maître DRM à la fois. Voir drmSetMaster(3) pour savoir comment devenir maître DRM et quelles sont les limitations. D'autres utilisateurs DRM peuvent être authentifiés auprès du maître DRM via drmAuthMagic(3) afin qu'ils puissent effectuer des allocations de tampons et du rendu.

Réglage de mode

La gestion des moniteurs et des écrans connectés et la modification des modes actuels sont appelées réglage de mode. Ceci est réservé au maître DRM actuel. Historiquement, cela était implémenté dans l'espace utilisateur, mais les nouveaux pilotes DRM implémentent une interface noyau pour effectuer le réglage de mode appelée réglage de mode du noyau (KMS). Si votre pilote matériel le prend en charge, vous pouvez utiliser l'API KMS fournie par DRM. Cela inclut l'allocation de tampons de trame, la sélection des modes et la gestion des CRTCs et des encodeurs. Voir drm-kms(7) pour plus d'informations.

Gestion de la mémoire

Les tâches les plus sophistiquées pour les GPU aujourd'hui consistent à gérer les objets mémoire. Les textures, les tampons de trame, les tampons de commandes et toutes sortes d'autres commandes pour le GPU doivent être stockés en mémoire. Le pilote DRM s'occupe de la gestion de tous les objets mémoire, du vidage des caches, de la synchronisation de l'accès et de la fourniture d'un accès CPU à la mémoire GPU. Toute la gestion de la mémoire dépend du pilote matériel. Cependant, deux frameworks génériques sont disponibles et utilisés par la plupart des pilotes DRM. Ce sont le Translation Table Manager (TTM) et le Graphics Execution Manager (GEM). Ils fournissent des API génériques pour créer, détruire et accéder aux tampons depuis l'espace utilisateur. Cependant, il existe encore de nombreuses différences entre les pilotes, de sorte que du code dépendant du pilote est toujours nécessaire. De nombreuses fonctions d'aide sont fournies dans libgbm (Graphics Buffer Manager) du projet Mesa. Pour plus d'informations sur la gestion de la mémoire DRM, voir drm-memory(7).

Rapporter les bugs

Les bugs dans ce manuel doivent être signalés à https://gitlab.freedesktop.org/mesa/libdrm/-/issues.
