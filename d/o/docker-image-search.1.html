NOM

podman-search - Rechercher une image dans un registre

SYNOPSIS

podman search [options] terme

DESCRIPTION

podman search recherche une image correspondante dans un registre ou une liste de registres. L'utilisateur peut spécifier quel registre rechercher en préférant le nom du registre dans le terme de recherche (par exemple, registry.fedoraproject.org/fedora). Par défaut, tous les registres de recherche non qualifiés dans containers-registries.conf(5) sont utilisés.

Le nombre de résultats par défaut est de 25. Le nombre de résultats peut être limité à l'aide de l'indicateur --limit. Si plus d'un registre est recherché, la limite s'applique à chaque registre. La sortie peut être filtrée à l'aide de l'indicateur --filter. Pour obtenir toutes les images disponibles dans un registre sans terme de recherche spécifique, l'utilisateur peut simplement entrer le nom du registre avec une barre oblique finale (exemple : registry.fedoraproject.org/).

Notez que podman search n'est pas une méthode fiable pour déterminer la présence ou l'existence d'une image. Le comportement de recherche de l'API de distribution Docker v1 et v2 est spécifique à l'implémentation de chaque registre. Certains registres peuvent ne pas prendre en charge la recherche du tout. Notez également que la recherche sans terme de recherche ne fonctionne qu'avec les registres qui implémentent l'API v2.

podman [OPTIONS GLOBALES]

podman search [OPTIONS GLOBALES]

podman search [OPTIONS] TERME

OPTIONS

--authfile=chemin

Chemin du fichier d'authentification. Le défaut est ${XDG_RUNTIME_DIR}/containers/auth.json sous Linux, et $HOME/.config/containers/auth.json sous Windows/macOS. Le fichier est créé par podman login. Si l'état d'autorisation n'y est pas trouvé, $HOME/.docker/config.json est vérifié, ce qui est défini via docker login.

Remarque : Il existe également la possibilité de remplacer le chemin par défaut du fichier d'authentification en définissant la variable d'environnement REGISTRY_AUTH_FILE. Cela peut être fait avec export REGISTRY_AUTH_FILE=chemin.

--cert-dir=chemin

Utiliser les certificats situés dans le répertoire chemin (*.crt, *.cert, *.key) pour se connecter au registre. (Défaut : /etc/containers/certs.d) Pour plus de détails, voir containers-certs.d(5). (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exception de WSL2)).

--compatible

Après le nom et la description, afficher également les descripteurs d'étoiles, officiels et automatisés comme le fait Docker. Podman n'affiche pas ces descripteurs par défaut car ils ne sont pas pris en charge par la plupart des registres de conteneurs publics.

--creds=[nomdutilisateur[:motdepasse]]

Le [nomdutilisateur[:motdepasse]] à utiliser pour s'authentifier auprès du registre, si nécessaire. Si une ou les deux valeurs ne sont pas fournies, une invite de commande apparaît et la valeur peut être saisie. Le mot de passe est saisi sans écho.

Notez que les identifiants spécifiés ne sont utilisés que pour s'authentifier auprès des registres cibles. Ils ne sont pas utilisés pour les miroirs ni lorsque le registre est réécrit (voir containers-registries.conf(5)) ; pour s'authentifier auprès de ceux-ci, envisagez d'utiliser un fichier containers-auth.json(5).

--filter, -f=filtre

Filtrer la sortie en fonction des conditions fournies (défaut [])

Les filtres pris en charge sont :

  • stars (int) - nombre minimum d'étoiles requis pour que les images soient affichées
  • is-automated (booléen - true | false) - si l'image est automatisée ou non
  • is-official (booléen - true | false) - si l'image est officielle ou non

--format=format

Changer le format de sortie en un modèle Go

Les espaces réservés valides pour le modèle Go sont listés ci-dessous :

Espace réservé Description
.Automated "[OK]" si l'image est automatisée
.Description Description de l'image
.Index Registre
.Name Nom de l'image
.Official "[OK]" si l'image est officielle
.Stars Nombre d'étoiles de l'image
.Tag Balise du dépôt

Remarque : utilisez .Tag uniquement si --list-tags est défini.

--help, -h

Afficher le message d'utilisation

--limit=limite

Limiter le nombre de résultats (défaut 25). Remarque : Les résultats de chaque registre sont limités à cette valeur. Exemple : si la limite est de 10 et que deux registres sont recherchés, le nombre total de résultats est de 20, 10 de chaque (s'il y a au moins 10 correspondances dans chaque). L'ordre des résultats de la recherche est l'ordre dans lequel le point d'accès API renvoie les résultats.

--list-tags

Lister les balises disponibles dans le dépôt pour l'image spécifiée. Remarque : --list-tags nécessite que le terme de recherche soit un nom d'image entièrement spécifié. Le résultat contient le nom de l'image et sa balise, une ligne pour chaque balise associée à l'image.

--no-trunc

Ne pas tronquer la sortie (défaut false).

--tls-verify

Exiger HTTPS et vérifier les certificats lors du contact avec les registres (défaut : true). S'il est explicitement défini sur true, la vérification TLS est utilisée. S'il est défini sur false, la vérification TLS n'est pas utilisée. Si non spécifié, la vérification TLS est utilisée à moins que le registre cible ne soit listé comme registre non sécurisé dans containers-registries.conf(5)

EXEMPLES

Rechercher des images contenant le nom spécifié, en renvoyant les trois premières images de chaque registre défini.

registry.fedoraproject.org/f31/fedora-toolbox

docker.io/kasmweb/fedora-37-desktop            Fedora 37 desktop for Kasm Workspaces
docker.io/kasmweb/fedora-38-desktop            Fedora 38 desktop for Kasm Workspaces
quay.io/fedora/fedora
quay.io/containerdisks/fedora                  # Fedora Containerdisk Images  <img src="htt...
quay.io/fedora/fedora-minimal

Notez que les descripteurs Étoiles, Officiel et Automatisé ne sont disponibles que sur Docker Hub et ne sont donc pas affichés par défaut.

$ podman search --format "{{.Name}}\t{{.Stars}}\t{{.Official}}" alpine --limit 3
docker.io/library/alpine       7956        [OK]
docker.io/alpine/git           192
docker.io/anapsix/alpine-java  474
quay.io/libpod/alpine          0
quay.io/vqcomms/alpine-tools   0

Rechercher et lister les balises de l'image spécifiée en renvoyant les quatre premières images de chaque registre défini.

$ podman search --list-tags registry.access.redhat.com/ubi8 --limit 4
NAME                             TAG
registry.access.redhat.com/ubi8  8.4-211

Remarque : cela ne fonctionne qu'avec les registres qui implémentent l'API v2. Si cela est essayé avec un registre v1, une erreur est retournée.

FICHIERS

registries.conf (/etc/containers/registries.conf)

registries.conf est le fichier de configuration qui spécifie quels registres de conteneurs sont consultés lors de la complétion des noms d'images qui n'incluent pas de portion de registre ou de domaine.

NAME

docker-image-search - Search the Docker Hub for images

SYNOPSIS

podman(1) image search [options] term

DESCRIPTION

The podman image search command searches the Docker Hub for images matching the specified search term.

By default, it searches the official Docker Hub repository. You can specify a different registry using the --registry option.

OPTIONS

--filter, -f
Filter the search results. The supported filters are:
is-official=true|false
Only show official images or images that are not official.
stars=N
Only show images with at least N stars.
--limit, -l=N
Maximum number of results to return.
--no-trunc
Do not truncate output.
--registry=REGISTRY
Search the specified registry instead of Docker Hub. The default is docker.io.

EXAMPLES

Search for the official Ubuntu image:

podman image search --filter is-official=true ubuntu

Search for images containing "webserver" with at least 10 stars and limit the results to 5:

podman image search --filter stars=10 --limit 5 webserver
