NOM

docheckgroups - Traite les checkgroups et affiche une liste des changements

SYNTAXE

docheckgroups [-u] [motif-inclusion [motif-exclusion]]

DESCRIPTION

docheckgroups est généralement exécuté par controlchan afin de traiter les messages de contrôle des checkgroups. Il lit une liste de groupes de news ainsi que leurs descriptions sur son entrée standard. Cette liste doit être formatée comme le fichier newsgroups(5) : chaque ligne contient le nom d'un groupe de news suivi d'une ou plusieurs tabulations et de sa description.

docheckgroups ne vérifiera la présence que des groupes de news qui correspondent au motif-inclusion (une expression egrep comme "^comp\..*$" pour les groupes de news commençant par "comp.") et qui ne correspondent pas au motif-exclusion (également une expression egrep), à l'exception des groupes de news mentionnés dans le fichier pathetc/localgroups. Ce fichier est également formaté comme le fichier newsgroups(5) et doit contenir les groupes de news locaux qui seraient autrement mentionnés pour suppression. Il n'est pas nécessaire d'y inclure les groupes de news locaux des hiérarchies pour lesquelles aucun message de contrôle checkgroups n'est envoyé, à moins que vous ne traitiez manuellement les textes des checkgroups pour ceux-ci. Les lignes commençant par un signe dièse ("#") ne sont pas prises en compte dans ce fichier. Tous les groupes de news et descriptions mentionnés dans pathetc/localgroups sont ajoutés aux checkgroups traités.

Si le motif-exclusion est fourni, le motif-inclusion doit également être fourni avant (vous pouvez utiliser une chaîne vide ("") si vous souhaitez inclure tous les groupes de news). Quoi qu'il en soit, docheckgroups ne vérifiera que les groupes de news dans les hiérarchies de premier niveau qui sont présents dans les checkgroups.

Ensuite, docheckgroups vérifie les fichiers active et newsgroups et affiche sur sa sortie standard une liste des changements, le cas échéant. Il ne change rien par défaut ; il indique seulement ce qui devrait être changé :

  • Les groupes de news qui devraient être supprimés (ils sont dans le fichier active mais pas dans les checkgroups) et les commandes ctlinnd pertinentes pour y parvenir ;
  • Les groupes de news qui devraient être ajoutés (ils ne sont pas dans le fichier active mais dans les checkgroups) et les commandes ctlinnd pertinentes pour y parvenir ;
  • Les groupes de news qui sont incorrectement marqués comme modérés ou non modérés (ils sont à la fois dans le fichier active et les checkgroups mais leur statut diffère) et les commandes ctlinnd pertinentes pour résoudre ce problème ;
  • Les descriptions qui devraient être supprimées (elles sont dans le fichier newsgroups mais pas dans les checkgroups) ;
  • Les descriptions qui devraient être ajoutées (elles ne sont pas dans le fichier newsgroups mais dans les checkgroups).

La sortie de docheckgroups peut être envoyée à mod-active (il mettra en pause le serveur de news, mettra à jour le fichier active en conséquence, le rechargera et reprendra le travail du serveur de news) ou au shell (les commandes pour ctlinnd seront traitées une par une). Afin de mettre à jour le fichier newsgroups, le drapeau -u doit être donné à docheckgroups.

Lors du traitement manuel d'un checkgroups, il est toujours conseillé de vérifier d'abord la sortie brute de docheckgroups. Ensuite, si tout semble correct, utilisez mod-active et le drapeau -u.

OPTIONS

-u
Si ce drapeau est donné, docheckgroups mettra à jour le fichier newsgroups : il supprime les descriptions obsolètes et ajoute les nouvelles. Il trie également ce fichier par ordre alphabétique et améliore son format général (voir newsgroups(5) pour une explication du nombre de tabulations préféré).

EXEMPLES

Afin de mieux comprendre le fonctionnement de docheckgroups, voici des exemples avec le fichier active suivant :

a.first 0000000000 0000000001 y
a.second.announce 0000000000 0000000001 y
a.second.group 0000000000 0000000001 y
b.additional 0000000000 0000000001 y
b.third 0000000000 0000000001 y
c.fourth 0000000000 0000000001 y

le fichier newsgroups suivant (utilisant des tabulations) :

a.first             Premier groupe.
a.second.announce   Groupe d'annonce.
a.second.group      Deuxième groupe.
b.third             Troisième groupe.
c.fourth            Quatrième groupe.

et le fichier localgroups suivant (utilisant des tabulations) :

b.additional        Un groupe de news local que je veux garder.

Le checkgroups que nous traitons se trouve dans le fichier test qui contient :

a.first             Premier groupe.
a.second.announce   Groupe d'annonce. (Modéré)
a.second.group      Deuxième groupe.
b.third             Troisième groupe.
c.fourth            Quatrième groupe.

Si nous exécutons :

cat test | docheckgroups

docheckgroups indiquera que a.second.announce est incorrectement marqué comme non modéré et que sa description est obsolète. De plus, deux nouvelles descriptions seront mentionnées pour ajout (la nouvelle pour a.second.announce et la description manquante pour b.additional -- elle devrait en effet être dans le fichier newsgroups et pas seulement dans localgroups). Maintenant que nous avons vérifié la sortie de docheckgroups et que nous sommes d'accord avec les changements, nous l'exécutons avec le drapeau -u pour mettre à jour le fichier newsgroups et nous redirigeons la sortie standard vers mod-active pour mettre à jour le fichier active :

cat test | docheckgroups -u | mod-active

C'est tout !

Maintenant, supposons que nous exécutons :

cat test | docheckgroups "^c\..*$"

Rien n'est affiché (en effet, tout est correct pour la hiérarchie c.*). Il en aurait été de même si le fichier test n'avait contenu que les checkgroups pour la hiérarchie c.* (docheckgroups n'aurait pas vérifié a.* et b.*, même s'ils avaient été dans include-pattern).

Afin de vérifier à la fois a.* et c.*, vous pouvez exécuter :

cat test | docheckgroups "^a\..*$|^c\..*$"

Et si vous voulez vérifier a.* mais pas a.second.*, vous pouvez exécuter :

cat test | docheckgroups "^a\..*$" "^a\.second\..*$"

Dans notre exemple, docheckgroups mentionnera alors a.second.announce et a.second.group pour suppression car ils sont dans le fichier active (il en va de même pour leurs descriptions). Néanmoins, si vous voulez conserver a.second.announce, ajoutez simplement ce groupe à localgroups et docheckgroups ne le mentionnera plus pour suppression.

FICHIERS

pathbin/docheckgroups
Le script shell lui-même utilisé pour traiter les checkgroups.
pathetc/localgroups
La liste des groupes de news locaux avec leurs descriptions.
