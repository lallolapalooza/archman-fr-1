podman-kube-generate - Génère d

u YAML Kubernetes à partir de
conteneurs, pods ou volumes

SYNOPSI

S

podman kube generate [options] conteneur... | pod... | volume.

.
.

DESCRIPTIO

N

podman kube generate génère du YAML Kubernetes (spécification v1) à partir de conteneurs, pods ou volumes Podman. Que l'entrée soit destinée à des conteneurs ou à des pods, Podman génère la spécification sous forme de Pod par défaut. L'entrée peut être constituée d'un ou plusieurs noms ou ID de conteneurs, de pods ou de

volumes.

Conteneurs ou Pods

Podman

Les volumes apparaissent dans le YAML généré selon deux types de volume différents. Les volumes montés par liaison (bind) deviennent des types de volume hostPath et les volumes nommés deviennent des types de volume persistentVolumeClaim. Les types de volume hostPath générés sont l'un des trois sous-types selon l'état du chemin hôte : DirectoryOrCreate quand aucun fichier ou répertoire n'existe sur l'hôte, Directory quand le chemin hôte est un répertoire, ou File quand le chemin hôte est un fichier. La valeur de claimName pour un persistentVolumeClaim est le nom du volume nommé enregistré dans

Podman.

Les conflits de noms potentiels entre les volumes sont évités en utilisant un schéma de nommage standard pour chaque type de volume. Les types de volume hostPath sont nommés selon le chemin sur la machine hôte, en remplaçant les barres obliques avant par des tirets, sans les barres obliques avant et après. Le cas spécial de la racine du système de fichiers, /, est traduit par le nom root. De plus, le nom est suffixé par -host pour éviter les conflits de noms avec les volumes persistentVolumeClaim. Chaque type de volume persistentVolumeClaim utilise le nom de son volume nommé associé suffixé par -pvc

.

Notez que si un conteneur d'initialisation est créé avec le type once et que le pod a été démarré, il n'apparaît pas dans le YAML kube généré car les conteneurs d'initialisation de type once sont supprimés après leur exécution. Si le pod n'a été que créé et non démarré, il est présent dans le YAML kube généré. Les conteneurs d'initialisation créés avec le type always sont toujours générés dans le YAML kube car ils ne sont jamais supprimés, même après avoir terminé leur

exécution.

Note : Lors de l'utilisation de volumes et de la génération d'un YAML Kubernetes pour un conteneur podman non privilégié et sans root sur un système SELinux activé, l'une des options suivantes doit être appliquée :
* Ajouter l'option "privileged: true" à la spécification du pod
* Ajouter type: spc_t sous les seLinuxOptions de securityContext dans la spécification du pod
* Relier les étiquettes du volume via la commande CLI chcon -t container_file_t -R

<répertoire>

Une fois cela fait, les permissions correctes sont en place pour accéder au volume lorsque le pod/conteneur est créé dans un cluster

Kubernetes.

Notez que le fichier YAML Kubernetes généré peut être utilisé pour relancer le déploiement via podman-play-kube(1)

.

Notez que si le pod généré a été créé avec l'indicateur --infra-name défini, alors le YAML kube généré aura l'annotation io.podman.annotations.infra.name définie, la valeur étant le nom du conteneur infra défini par

l'utilisateur.

Notez que Deployment et DaemonSet ne peuvent avoir restartPolicy défini qu'à Always

.

Notez que Job ne peut avoir restartPolicy défini qu'à OnFailure ou Never. Par défaut, podman le définit à Never lors de la génération d'un YAML kube en utilisant kube ge

ner
ate.

OPTION

S

--filename, -f=fichie

r

Sortie vers le fichier donné au lieu de STDOUT. Si le fichier existe déjà, kube generate refuse de le rem

placer et renv
oie une erreur.

--podman-onl

y

Ajoute les annotations réservées à pod

man dans le fichier YAML généré (Ne
peut pas être utilisé par Kubernetes)

--replicas, -r=nombre de

réplicas

La valeur à définir pour replicas lors de la génération d'un type Deployment. Note : cela ne peut être défini qu'avec l'option --type=deploymen

t
.

--service, -

s

Génère un objet service Kubernetes en plus des Pods. Utilisé pour générer une spécification de Service pour la sort

ie du Pod correspondant. En particulier, si l'objet a des liaisons portmap, la spécification du service inclut
une déclaration NodePort pour exposer le service. Un port aléatoire est attribué par Podman dans la spécification.

--type, -t=pod | deployment | daemonset | jo

b

Le type Kubernetes à générer dans le fichier YAML. Actuellement, les seules spécifications Kubernetes prises en charge sont Pod, Deployment, Job et DaemonSet. Par défaut, la spécification

Pod
est g
énérée.

EXEMPLE

S

Crée un YAML de Pod Kubernetes pour le conteneur

spécifié. 
$ podman kube generate some-mariadb
# Enregistrez la sortie de ce fichier et utilisez kubectl create -f pour l'importer
# dans Kubernetes.
#
# Créé avec podman-4.8.2
# NOTE : Si vous avez généré ce yaml à partir d'un conteneur podman non privilégié et sans root sur un système
# SELinux activé, consultez la page man de podman generate kube pour les étapes à suivre afin de vous assurer que votre pod/conteneur
# a les bonnes permissions pour accéder aux volumes ajoutés.
---
apiVersion: v1
kind: Pod
metadata:
  creationTimestamp: "2024-01-09T02:24:55Z"
  labels:
    app: some-mariadb-pod
  name: some-mariadb-pod
spec:
  containers:
  - args:
    - mariadbd
    env:
    - name: MARIADB_ROOT_PASSWORD
      value: x
    image: docker.io/library/mariadb:10.11
    name: some-mariadb
    ports:
    - containerPort: 3306
      hostPort: 34891
    volumeMounts:
    - mountPath: /var/lib/mysql
      name: mariadb_data-pvc
  volumes:
  - name: mariadb_data-pvc
    persistentVolumeClaim:
      claimName:
mariadb_data

Crée un YAML de Deployment Kubernetes avec 3 réplicas pour le conteneur

spécifié. 
$ podman kube generate --type deployment --replicas 3 dep-ct
r
# Enregistrez la sortie de ce fichier et utilisez kubectl create -f pour l'importer

  creationTimestamp: "2023-03-27T20:45:08Z"
  labels:
    app: dep-ctr-pod
  name: dep-ctr-pod-deployment

  replicas: 3
  selector:
    matchLabels:
      app: dep-ctr-pod
  template:
    metadata:
      annotations:
        io.podman.annotations.ulimit: nofile=524288:524288,nproc=127332:127332
      creationTimestamp: "2023-03-27T20:45:08Z"
      labels:
        app: dep-ctr-pod
      name: dep-ctr-pod
    spec:
      containers:
      - command:
        - top
        image: docker.io/library/alpine:latest
        name:
dep-ctr
