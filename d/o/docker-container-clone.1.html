--destroy

Supprime le conteneur original que nous clonons une fois qu'il a été utilisé pour reproduire la configuration.

--device-read-bps=chemin:débit

Limite le débit de lecture (en octets par seconde) depuis un périphérique (par ex. --device-read-bps=/dev/sda:1mb).

Sur certains systèmes, la modification des limites de ressources peut ne pas être autorisée pour les utilisateurs non-root. Pour plus de détails, voir https://github.com/containers/podman/blob/main/troubleshooting.md#26-running-containers-with-resource-limits-fails-with-a-permissions-error

Cette option n'est pas prise en charge sur les systèmes cgroups V1 sans root.

--device-write-bps=chemin:débit

Limite le débit d'écriture (en octets par seconde) vers un périphérique (par ex. --device-write-bps=/dev/sda:1mb).

Sur certains systèmes, la modification des limites de ressources peut ne pas être autorisée pour les utilisateurs non-root. Pour plus de détails, voir https://github.com/containers/podman/blob/main/troubleshooting.md#26-running-containers-with-resource-limits-fails-with-a-permissions-error

Cette option n'est pas prise en charge sur les systèmes cgroups V1 sans root.

--force, -f

Force la suppression du conteneur original que nous clonons. Peut uniquement être utilisé en conjonction avec --destroy.

--memory, -m=nombre[unité]

Limite de mémoire. Une unité peut être b (octets), k (kibioctets), m (mébioctets), ou g (gibioctets).

Permet de contraindre la mémoire disponible à un conteneur. Si l'hôte prend en charge la mémoire swap, alors le paramètre de mémoire -m peut être plus grand que la RAM physique. Si une limite de 0 est spécifiée (sans utiliser -m), la mémoire du conteneur n'est pas limitée. La limite réelle peut être arrondie à un multiple de la taille de page du système d'exploitation (la valeur est très grande, des millions de trillions).

Cette option n'est pas prise en charge sur les systèmes cgroups V1 sans root.

Si aucune limite de mémoire n'est spécifiée, les limites de mémoire du conteneur original sont utilisées.

--memory-reservation=nombre[unité]

Limite souple de mémoire. Une unité peut être b (octets), k (kibioctets), m (mébioctets), ou g (gibioctets).

Après avoir défini la réservation de mémoire, lorsque le système détecte une contention en mémoire ou une faible mémoire, les conteneurs sont forcés de restreindre leur consommation à leur réservation. Définissez donc toujours la valeur en dessous de --memory, sinon la limite stricte prend le dessus. Par défaut, la réservation de mémoire est la même que la limite de mémoire.

Cette option n'est pas prise en charge sur les systèmes cgroups V1 sans root.

Si elle n'est pas spécifiée, la réservation de mémoire est la même que la limite de mémoire du conteneur qui est cloné.

--memory-swap=nombre[unité]

Une valeur de limite égale à la mémoire plus le swap. Une unité peut être b (octets), k (kibioctets), m (mébioctets), ou g (gibioctets).

Doit être utilisé avec l'indicateur -m (--memory). La valeur de l'argument doit être plus grande que celle de
-m (--memory). Par défaut, elle est définie au double de la valeur de --memory.

Définissez nombre à -1 pour activer un swap illimité.

Cette option n'est pas prise en charge sur les systèmes cgroups V1 sans root.

Si elle n'est pas spécifiée, le conteneur qui est cloné est utilisé pour dériver la valeur du swap.

--memory-swappiness=nombre

Ajuste le comportement de « swappiness » de la mémoire d'un conteneur. Accepte un entier compris entre 0 et 100.

Cet indicateur n'est pris en charge que sur les systèmes cgroups V1 avec root.

--name

Définit un nom personnalisé pour le conteneur cloné. La valeur par défaut, si elle n'est pas spécifiée, utilise la syntaxe : <NOM_ORIGINAL>-clone

--pod=nom

Clone le conteneur dans un pod existant. Cela permet de déplacer un conteneur vers un pod existant. Le conteneur rejoint les espaces de noms partagés du pod, perdant sa configuration qui entre en conflit avec les espaces de noms partagés.

--run

Lorsqu'il est défini à true, cet indicateur lance le nouveau conteneur créé après que le processus de clonage est terminé, cela spécifie un mode d'exécution détaché.

EXEMPLES

Clone le conteneur spécifié dans un nouveau conteneur :

# podman container clone d0cf1f782e2ed67e8c0050ff92df865a039186237a4df24d7acba5b1fa8cc6e7
6b2c73ff8a1982828c9ae2092954bcd59836a131960f7e05221af9df5939c584

Clone le conteneur spécifié dans un nouveau conteneur avec un nom :

# podman container clone --name=clone d0cf1f782e2ed67e8c0050ff92df865a039186237a4df24d7acba5b1fa8cc6e7
6b2c73ff8a1982828c9ae2092954bcd59836a131960f7e05221af9df5939c584

Remplace le conteneur spécifié avec les contraintes de ressources sélectionnées dans un nouveau conteneur, en supprimant le conteneur original :

# podman container clone --destroy --cpus=5 d0cf1f782e2ed67e8c0050ff92df865a039186237a4df24d7acba5b1fa8cc6e7
6b2c73ff8a1982828c9ae2092954bcd59836a131960f7e05221af9df5939c584

Clone le conteneur spécifié en lui donnant un nouveau nom, puis remplace l'image du conteneur original par le nom de l'image spécifié :
