NOM

doveadm-acl - Gérer les listes de contrôle d'accès (ACL)

SYNOPSIS

doveadm [OPTIONS GLOBALES] acl commande [OPTIONS] [ARGUMENTS]

DESCRIPTION

Les doveadm acl COMMANDES peuvent être utilisées pour exécuter diverses actions liées aux listes de contrôle d'accès (ACL).

OPTIONS GLOBALES

Options globales de doveadm(1)

-D

Active la verbosité et les messages de débogage.

-O

Ne lit aucun fichier de configuration, utilise uniquement les valeurs par défaut. Le dovecot_storage_version paramètre a pour valeur par défaut la dernière version, mais peut être remplacée avec

-k

Préserve l'environnement complet pour doveadm, pas seulement le paramètre import_environment .

-v

Active la verbosité, y compris le compteur de progression.

-i nom_instance

Si vous utilisez plusieurs instances Dovecot, choisissez le fichier de configuration en fonction de ce nom d'instance.

Voir le paramètre instance_name pour plus d'informations.

-c fichier_config

Lit la configuration à partir du fichier_configdonné. Par défaut, il lit d'abord le socket de configuration, puis utilise par défaut /etc/dovecot/dovecot.conf. Vous pouvez également pointer vers le socket de configuration d'une instance exécutant une version compatible.

-o paramètre=valeur

Remplace le paramètre de configuration de /etc/dovecot/dovecot.conf et de la userdb par la valeurdonnée. Afin de remplacer plusieurs paramètres, l' option -o peut être spécifiée plusieurs fois.

-f formateur

Spécifie le formateur pour formater la sortie. Les formateurs pris en charge sont :

flow

affiche chaque ligne avec des paires clé=valeur .

json

affiche un tableau JSON d'objets JSON.

pager

affiche chaque paire clé: valeur sur sa propre ligne et sépare les enregistrements avec un caractère de saut de page (^L).

tab

affiche un en-tête de tableau suivi de lignes de valeurs séparées par des tabulations.

table

affiche un en-tête de tableau suivi de lignes de valeurs alignées.

Cette commande utilise par défaut le formateur de sortie table.

OPTIONS

-A

Si l' option -A est présente, la commande sera effectuée pour tous les utilisateurs. L'utilisation de cette option en combinaison avec les utilisateurs système de userdb { driver = passwd } n'est pas recommandée, car elle contient également des utilisateurs avec un UID inférieur à celui configuré avec le paramètre first_valid_uid .

Lorsque le module userdb SQL est utilisé, assurez-vous que le paramètre userdb_sql_iterate_query correspond à la disposition de votre base de données.

Lors de l'utilisation du module userdb LDAP, assurez-vous que les paramètres userdb_fields et userdb_ldap_iterate_fields correspondent à votre schéma LDAP. Sinon doveadm(1) ne pourra pas itérer sur tous les utilisateurs.

-F fichier

Exécute la commande pour tous les utilisateurs du fichier. C'est similaire à l' option -A , mais au lieu d'obtenir la liste des utilisateurs depuis la userdb, ils sont lus depuis le fichierdonné. Le fichier contient un nom d'utilisateur par ligne.

--no-userdb-lookup

N'effectue pas de recherche dans la userdb. Utilise la variable d'environnement USER pour spécifier le nom d'utilisateur.

-S chemin_socket

L'argument de l'option est soit un chemin absolu vers un socket de domaine UNIX local, soit un nom d'hôte et un port (nom_hôte:port), afin de se connecter à un hôte distant via un socket TCP.

Cela permet à un administrateur d'exécuter les commandes de courrier de doveadm(1) via le socket donné.

-u utilisateur/masque

Exécute la commande uniquement pour l' utilisateurdonné. Il est également possible d'utiliser les caractères génériques '*' et '?' (par ex. -u *@example.org).

ARGUMENTS

id

L'id (identifiant) est l'un des suivants :

  • group-override = nom_groupe
  • user = nom_utilisateur
  • owner
  • group = nom_groupe
  • authenticated
  • anyone
  • anonymous, qui est un alias pour anyone

Les ACL sont traitées dans la priorité donnée ci-dessus, donc par exemple si vous avez donné un accès en lecture à un groupe, vous pouvez toujours le retirer pour des utilisateurs spécifiques au sein du groupe.

L'identifiant group-override vous permet de remplacer les ACL des utilisateurs. La raison la plus utile de le faire est probablement de désactiver temporairement l'accès pour certains utilisateurs. Par exemple :

user=timo rw
group-override=tempdisabled

Maintenant, si timo est membre du groupe tempdisabled, il n'a aucun accès à la boîte aux lettres. Cela ne serait pas possible avec un identifiant de groupe normal, car user=timo le remplacerait.

mailbox

Le nom de la boîte aux lettres pour laquelle la manipulation des ACL doit être effectuée. Il est également possible d'utiliser les caractères génériques "*" et/ou "?" dans le nom de la boîte aux lettres.

right

Nom du droit ACL de Dovecot. Ce n'est pas la même chose que les lettres d'ACL IMAP, qui ne sont actuellement pas prises en charge.

Voici une correspondance des lettres d'ACL IMAP vers les noms d'ACL Dovecot :

l -> lookup : La boîte aux lettres est visible dans la liste des boîtes aux lettres. La boîte aux lettres peut être abonnée.

r -> read : La boîte aux lettres peut être ouverte pour la lecture.

w -> write : Les indicateurs et mots-clés des messages peuvent être modifiés, sauf \Seen et \Deleted.

s -> write-seen : L'indicateur \Seen peut être modifié.

t -> write-deleted : L'indicateur \Deleted peut être modifié.

i -> insert : Les messages peuvent être écrits ou copiés dans la boîte aux lettres.

p -> post : Les messages peuvent être postés dans la boîte aux lettres par dovecot-lda, par ex. depuis des scripts Sieve.

e -> expunge : Les messages peuvent être expurgés.


(mais pas nécessairement sous ses enfants, voir acl_inheritance. Remarque : Le renommage nécessite également le droit de suppression.

x -> delete : La boîte aux lettres peut être supprimée.

a -> admin : Droits d'administration sur la boîte aux lettres (actuellement : capacité de modifier les ACL pour la boîte aux lettres).

COMMANDES

acl add

doveadm [OPTIONS GLOBALESacl add [-u utilisateur | -A | -F fichier | --no-userdb-lookup] [-S chemin_socket] mailboxx id right [right ...]

Ajouter des droits ACL au mailbox/id. Si lid existe déjà, les droits existants sont préservés.

acl debug

doveadm [GLOBAL OPTIONS] acl debug [-u user | -A | -F file | --no-userdb-lookup] [-S socket_path] mailbox

Cette commande peut être utilisée pour déboguer pourquoi une boîte aux lettres partagée n'est pas accessible à l'utilisateur. Elle indiquera exactement quel est le problème.

acl delete

doveadm [GLOBAL OPTIONS] acl delete [-u user | -A | -F file | --no-userdb-lookup] [-S socket_path] mailbox id

Supprimer toute l'entrée ACL pour le mailbox/id.

acl get

doveadm [GLOBAL OPTIONS] acl get [-u user | -A | -F file | --no-userdb-lookup] [-S socket_path] [-m] mailbox

Afficher toutes les ACL pour la mailbox.

-m

Afficher uniquement les ACL qui correspondent à la boîte aux lettres.

acl recalc

doveadm [GLOBAL OPTIONS] acl recalc [-u user | -A | -F file | --no-userdb-lookup] [-S socket_path]

Assurez-vous que les boîtes aux lettres partagées de luser existent correctement dans lacl_sharing_map.

acl remove

doveadm [GLOBAL OPTIONS] acl remove [-u user | -A | -F file | --no-userdb-lookup] [-S socket_path] mailbox id right [right ...]

Supprimer les droits ACL spécifiés du mailbox/id. Si tous les droits sont supprimés, l'entrée existe toujours sans aucun droit.

acl rights

doveadm [GLOBAL OPTIONS] acl rights [-u user | -A | -F file | --no-userdb-lookup] [-S socket_path] mailbox

Afficher les droits ACL actuels de l luser pour la mailbox.

acl set

doveadm [GLOBAL OPTIONS] acl set [-u user | -A | -F file | --no-userdb-lookup] [-S socket_path] mailbox id right [right ...]

Définir les droits ACL sur le mailbox/id. Si l lid existe déjà, les droits existants sont remplacés.
