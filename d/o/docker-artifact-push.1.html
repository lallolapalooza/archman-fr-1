podman-artifact-push(1) Manuel des commandes générales podman-artifact-push(1)

NOM

podman artifact push - Pousse un artefact OCI depuis le stockage local vers un registre d'images

SYNOPSIS

podman artifact push [options] image

DESCRIPTION

Pousse un artefact depuis le magasin d'artefacts local vers un registre d'images.

# Pousser un artefact vers un registre de conteneurs
$ podman artifact push quay.io/artifact/foobar1:latest

OPTIONS

--authfile=chemin

Chemin du fichier d'authentification. Par défaut, ${XDG_RUNTIME_DIR}/containers/auth.json sous Linux, et $HOME/.config/containers/auth.json sous Windows/macOS. Le fichier est créé par podman login. Si l'état d'autorisation n'y est pas trouvé, $HOME/.docker/config.json est vérifié, qui est défini à l'aide de docker login.

Note : Il existe également une option pour remplacer le chemin par défaut du fichier d'authentification en définissant la variable d'environnement REGISTRY_AUTH_FILE. Cela peut être fait avec export REGISTRY_AUTH_FILE=chemin.

--cert-dir=chemin

Utiliser les certificats situés dans chemin (*.crt, *.cert, *.key) pour se connecter au registre. (Défaut : /etc/containers/certs.d) Pour plus de détails, voir containers-certs.d(5). (Cette option n'est pas disponible avec le client Podman distant, y compris sur les machines Mac et Windows (à l'exception de WSL2))

--creds=[nom_utilisateur[:mot_de_passe]]

Le [nom_utilisateur[:mot_de_passe]] à utiliser pour s'authentifier auprès du registre, si requis. Si une ou les deux valeurs ne sont pas fournies, une invite de commande apparaît et la valeur peut être saisie. Le mot de passe est saisi sans écho.

Notez que les identifiants spécifiés sont uniquement utilisés pour l'authentification auprès des registres cibles. Ils ne sont pas utilisés pour les miroirs ou lorsque le registre est réécrit (voir containers-registries.conf(5)) ; pour vous authentifier auprès de ceux-ci, envisagez d'utiliser un fichier containers-auth.json(5).

--digestfile=FichierDigest

Après la copie de l'image, écrire le digest de l'image résultante dans le fichier.

--quiet, -q

Lors de l'écriture de l'image de sortie, supprimer l'affichage de la progression

--retry=tentatives

Nombre de tentatives pour tirer ou pousser des images entre le registre et le stockage local en cas d'échec. Le défaut est de 3.

--retry-delay=durée

Durée du délai entre les tentatives de retrait ou de poussée d'images entre le registre et le stockage local en cas d'échec. Par défaut, le délai commence à deux secondes, puis augmente de manière exponentielle. Le délai est utilisé lorsque cette valeur est définie, et aucune augmentation exponentielle ne se produit.

--sign-by=clé

Ajouter une signature "simple" à la destination en utilisant la clé spécifiée. (Cette option n'est pas disponible avec le client Podman distant, y compris sur les machines Mac et Windows (à l'exception de WSL2))

--sign-by-sigstore=param-fichier

Ajouter une signature sigstore basée sur d'autres options spécifiées dans un fichier de paramètres de signature sigstore du conteneur, param-fichier. Voir containers-sigstore-signing-params.yaml(5) pour les détails sur le format du fichier.

--sign-by-sigstore-private-key=chemin

Ajouter une signature sigstore à la destination en utilisant une clé privée située au chemin spécifié. (Cette option n'est pas disponible avec le client Podman distant, y compris sur les machines Mac et Windows (à l'exception de WSL2))

--sign-by-sq-fingerprint=empreinte

Ajouter une signature "simple" en utilisant une clé Sequoia-PGP avec l'empreinte spécifiée. (Cette option n'est pas disponible avec le client Podman distant, y compris sur les machines Mac et Windows (à l'exception de WSL2))

--sign-passphrase-file=chemin

Si l'image est signée (en utilisant --sign-by, sign-by-sq-fingerprint ou --sign-by-sigstore-private-key), lire la phrase secrète à utiliser depuis le chemin spécifié.

--tls-verify

Exiger HTTPS et vérifier les certificats lors du contact des registres (défaut : true). S'il est explicitement défini sur true, la vérification TLS est utilisée. S'il est défini sur false, la vérification TLS n'est pas utilisée. Si non spécifié, la vérification TLS est utilisée sauf si le registre cible est listé comme registre non sécurisé dans containers-registries.conf(5)

EXEMPLE

Pousse l'image spécifiée vers un registre de conteneurs :

$ podman artifact push quay.io/baude/artifact:single
Getting image source signatures
Copying blob 3ddc0a3cdb61 done   |
Copying config 44136fa355 done   |
Writing manifest to image destination
