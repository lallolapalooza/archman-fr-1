DESCRIPTIO

N

podman container restore restaure un conteneur à partir d'un point de sauvegarde de conteneur ou d'une image de point de sauvegarde. Les identifiants de conteneur, identifiants d'image ou noms sont util

isés en
entrée.

OPTION

S

--all, -

a

Restaurer tous les conteneurs mis en point de sauvegarde.
La valeur par défaut est false.
IMPORTANT : Cette OPTION n'a pas be

soin d'un nom ou d'un identifiant de
conteneur comme argument d'entrée.

--file-lock

s

Restaurer un conteneur avec les verrous de fichiers. Cette option est requise pour restaurer les verrous de fichiers à partir d'une image de point de sauvegarde. Si l'image de point de sauvegarde ne contient pas de verrous de fichiers, cette option est ignorée. Par défaut, les verrous de fichiers ne sont pas restaurés.
La valeur par défaut est fal

s
e.

--ignore-rootf

s

Si un conteneur est restauré à partir d'un fichier point de sauvegarde tar.gz, il est possible qu'il contienne également toutes les modifications du système de fichiers racine. Avec --ignore-rootfs, il est possible de désactiver explicitement l'application de ces modifications du système de fichiers racine au conteneur restauré.
La valeur par défaut est false.
IMPORTANT : Cette OPTION n'est disponible qu'en combinaison avec --import, -i.

--ignore-static-i

p

Si le conteneur a été démarré avec --ip, le conteneur restauré essaie également d'utiliser cette adresse IP et la restauration échoue si cette adresse IP est déjà utilisée. Cela peut se produire si un conteneur est restauré plusieurs fois à partir d'un point de sauvegarde exporté avec --name,

-n.

Utiliser --ignore-static-ip indique à Podman d'ignorer l'adresse IP si elle a été configurée avec --ip lors de la création du

conteneur.

La valeur par défaut est fal

s
e.

--ignore-static-ma

c

Si le conteneur a été démarré avec --mac-address, le conteneur restauré essaie également d'utiliser cette adresse MAC et la restauration échoue si cette adresse MAC est déjà utilisée. Cela peut se produire si un conteneur est restauré plusieurs fois à partir d'un point de sauvegarde exporté avec --name,

-n.

Utiliser --ignore-static-mac indique à Podman d'ignorer l'adresse MAC si elle a été configurée avec --mac-address lors de la création du

conteneur.

La valeur par défaut est fal

s
e.

--ignore-volume

s

Cette option doit être utilisée en combinaison avec l'option --import, -i. Lors de la restauration de conteneurs à partir d'un fichier point de sauvegarde tar.gz avec cette option, le contenu des volumes associés n'est pas restauré.
La valeur par défaut est fal

s
e.

--import, -i=fichie

r

Importer un fichier point de sauvegarde tar.gz, qui a été exporté par Podman. Cela peut être utilisé pour importer un conteneur mis en point de sauvegarde depuis un autre hôte.
IMPORTANT : Cette OPTION n'a pas besoin d'un nom ou d'un identifiant de conteneur comme argument

d'entrée.

Lors de l'importation d'un fichier de point de sauvegarde, Podman sélectionne le même environnement d'exécution de conteneur qui a été utilisé lors de la mise en point de sauvegarde. C'e

st particulièrement important si un environnement d'exécution de conteneur spécifique (non par défaut) a été spécifié lors de la création du conteneur. Podman interrompt également la res
tauration si l'environnement d'exécution de conteneur spécifié lors de la restauration ne correspond pas à l'environnement d'exécution de conteneur utilisé pour la création du conteneur.

--import-previous=fichie

r

Importer un fichier point de sauvegarde préalable tar.gz qui a été exporté par Podman. Cette option doit être utilisée avec -i ou --import. Elle ne fonctionne que sur runc 1.0-rc3 ou supérieur. IMPORTANT : Cette OPTION n'est pas prise en c

harge sur le client distant, y compris les mac
hines Mac et Windows (à l'exception de WSL2).

--keep, -

k

Conserver tous les fichiers de journal et de statistiques temporaires créés par CRIU lors de la mise en point de sauvegarde ainsi que de la restauration. Ces fichiers ne sont pas supprimés si la restauration échoue, pour un débogage ultérieur. Si la restauration réussit, ces fichiers ne sont théoriquement pas nécessaires, mais si ces fichiers sont nécessaires, Podman peut les conserver pour une analyse ultérieure. Cela inclut le répertoire de point de sauvegarde avec tous les fichiers créés lors de la mise en point de sauvegarde. La taille requise par le répertoire de point de sauvegarde est approximativement la même que la quantité de mémoire requise par les processus dans le conteneur mis en point de sauvegarde.
Sans l'option --keep, -k, le point de sauvegarde est consommé et ne peut pas être utilisé à nouveau.
La valeur par défaut est fal

s
e.

--latest, -

l

Au lieu de fournir l' identifiant ou le nom du conteneur, utiliser le dernier conteneur créé. La valeur par défaut est false. IMPORTANT : Cette OPTION n'est pas disponible avec le client Podman distant, y

compris les machines Mac et Windows (à l'exception de WSL2). Cette OPTION n'a
pas besoin d'un nom ou d'un identifiant de conteneur comme argument d'entrée.

--name, -n=no

m

Si un conteneur est restauré à partir d'un fichier point de sauvegarde tar.gz, il est possible de le renommer avec --name, -n. De cette façon, il est possible de restaurer un conteneur à partir d'un point de sauvegarde plusieurs fois avec des noms

différents.

Si l'option --name, -n est utilisée, Podman n'essaie pas d'attribuer la même adresse IP au conteneur qu'elle utilisait avant la mise en point de sauvegarde, car chaque adresse IP ne peut être utilisée qu'une seule fois, et le conteneur restauré a une autre adresse IP. Cela signifie également que --name, -n ne peut pas être utilisé en combinaison avec --tcp-established.
IMPORTANT : Cette OPTION n'est disponible que pour une image de point de sauvegarde ou en combinaison avec --import, -i.

--pod=no

m

Restaurer un conteneur dans le pod nom. Le pod de destination pour cette restauration doit avoir les mêmes espaces de noms partagés que le pod à partir duquel ce conteneur a été mis en point de sauvegarde (voir **podman pod create --share.
IMPORTANT : Cette OPTION n'est disponible que pour une image de point de sauvegarde ou en combinaison avec --import, -i.

Cette option n

écessite au mo
ins CRIU 3.16.

--print-stat

s

Afficher des statistiques sur la restauration du/des conteneur(s). La sortie est rendue sous forme de tableau JSON et contient des informations sur le temps nécessaire aux différentes opérations de restauration. Beaucoup des statistiques de restauration sont créées par CRIU et simplement transmises à Podman. Les informations suivantes sont fournies dans le tableau JSON

:
  • podman_restore_duration : Temps total (en microsecondes) nécessaire pour restaurer tous les points de
    • sauvegarde.
  • runtime_restore_duration : Temps (en microsecondes) que l'environnement d'exécution du conteneur a mis pour restaurer le point de
    • sauvegarde.
  • forking_time : Temps (en microsecondes) que CRIU a mis pour créer (fork) tous les processus dans le conteneur restauré (mesuré par CRIU)
    • .
  • restore_time : Temps (en microsecondes) que CRIU a mis pour restaurer tous les processus dans le conteneur (mesuré par CRIU)
    • .
  • pages_restored : Nombre de pages mé
    • moire restaurées
(mesuré par CRIU).

La valeur par défaut est fal

s
e.

--publish, -p=por

t

Remplace les ports que le conteneur publie, tels que configurés lors du démarrage initial du conteneur, par un nouvel ensemble de règles de transfert de

ports.

Pour plus de détails, voir podman run

--pub
lish.

--tcp-clos

e

Restaurer un conteneur et fermer toutes les connexions TCP. Cette option est utile lorsque les connexions TCP ne sont pas nécessaires après la restauration ou lorsque les connexions seront rétablies par l'application. Si l'image de point de sauvegarde a été créée avec --tcp-close, cette option devrait être utilisée lors de la restauration.
La valeur par défaut est fal

s
e.

--tcp-establishe

d

Restaurer un conteneur avec des connexions TCP établies. Si l'image de point de sauvegarde contient des connexions TCP établies, cette option est requise lors de la restauration. Si l'image de point de sauvegarde ne contient pas de connexions TCP établies, cette option est ignorée. Par défaut, les conteneurs avec des connexions établies connexions TCP.
La valeur par défaut est fa

ls
e
.
