NOM

docbook2man-spec.pl - convertir les RefEntries DocBook en pages man

SYNTAXE

sgmlspl docbook2man-spec.pl

nsgmls [ document sgml ]| sgmlspl docbook2man-spec.pl

DESCRIPTION

docbook2man est un fichier de spécification sgmlspl qui produit des pages man (en utilisant les macros -man) à partir du balisage DocBook RefEntry.

Le programme lit l'ESIS produit par nsgmls (ou d'autres analyseurs SGML) depuis l'entrée standard. Le balisage non trouvé dans RefEntry est ignoré.

Sa sortie, les pages man converties, est écrite dans le répertoire courant. Si les informations RefMeta ne sont pas spécifiées dans une RefEntry, la page man sera écrite sur la sortie standard.

Le fichier manpage.links sera également créé, contenant les alias des pages man générées. Ce fichier est au format :

<page man> <alias
    page man>

Le fichier manpage.refs garde une trace des références XRef. Notez que si le document d'entrée contient des références antérieures, docbook2man peut avoir à être invoqué deux fois (la première fois pour mettre à jour manpage.refs) pour les résoudre.

PRÉREQUIS

Le paquet SGMLSpm de CPAN. Ce paquet inclut le script sgmlspl qui est également nécessaire.

LIMITATIONS

Essayer docbook2man sur du SGML non DocBook ou non conforme entraîne un comportement indéfini. :-)

Ce programme est un script Perl lent et bancal.

Ce programme ne prend pas en charge l'intégralité du balisage possible en DocBook, et peut produire des résultats erronés dans certains cas avec du balisage pris en charge.

À FAIRE

Évidences :

•
Corriger les plantages de docbook2man rencontrés dans les documents de test, en particulier weird.sgml.
•
Ajouter la gestion de nouveaux éléments et corriger la gestion existante. Être robuste.
•
Produire une sortie man aussi propre et lisible que possible (contrairement à d'autres convertisseurs). Suivre la convention man(7) de Linux. Comme la conversion en pages man n'est généralement pas effectuée très souvent, il est préférable d'être plus lent/plus compliqué que de produire un résultat erroné. De plus, si quelqu'un décide d'arrêter d'utiliser DocBook pour une raison quelconque, les pages man converties peuvent alors être maintenues manuellement.
•
Le rendre plus rapide. Je pense que la plupart des problèmes de vitesse jusqu'à présent proviennent de l'analyse de l'ESIS. Réécrire SGMLS.pm en C et/ou obtenir l'entrée directement de SP.
•
Prendre en charge d'autres langues (humaines). Mais que faire des jeux de caractères non ASCII ? SGMLSpm ne les signale pas et roff ne les comprend pas. [Commentaire : le texte après les listes imbriquées (et les blocs SS) cassera docbook2man] Si nous faisons cela, plus de personnes pourront utiliser DocBook.
