DESCRIPTIO

N

La commande docker container update met à jour dynamiquement la configuration du conteneur. Vous pouvez utiliser cette commande pour empêcher les conteneurs de consommer trop de ressources de leur hôte Docker. Avec une seule commande, vous pouvez imposer des limites à un seul conteneur ou à plusieurs. Pour spécifier plus d'un conteneur, fournissez une liste de noms ou d'identifiants de conteneurs séparés par des

espaces.

À l'exception de l'option --kernel-memory, vous pouvez spécifier ces options sur un conteneur en cours d'exécution ou arrêté. Sur une version du noyau antérieure à 4.6, vous ne pouvez mettre à jour --kernel-memory que sur un conteneur arrêté ou sur un conteneur

en cours d'exécution dont la mémoi
re du noyau a été initialisée.

N
S

y

Limite de mémoire du noyau (format : <nombre>[<unité>], où unité = b, k, m ou

g)

Notez que sur une version du noyau antérieure à 4.6, vous ne pouvez pas mettre à jour la mémoire du noyau sur un conte

neur en cours d'exécution si le conteneur a été démarré sans mémoire du noyau initialisée ; dans ce cas, elle ne p

memor

Limite de mémoire (format : , où unité = b, k, m ou

Notez que la mémoire doit être inférieure à la limite de mémoire swap déjà définie. Si vous souhaitez mettre à jour une limite de mémoire supérie

EXEMPLE

S

Les sections suivantes illustrent les façons d'utiliser cette

commande.

Mettre à jour les cpu-shares d'un

conteneur

Pour limiter les cpu-shares d'un conteneur à 512, identifiez d'abord le nom ou l'identifiant du conteneur. Vous pouvez utiliser docker ps pour trouver ces valeurs. Vous pouvez aussi utiliser l'identifiant renvoyé par la commande docker run. Ensuite, procédez comme suit

: 
$ docker container
update --cpu-share
s 512 abebf7571666

Mettre à jour un conteneur avec cpu-shares et

mémoire

Pour mettre à jour plusieurs configurations de ressources pour plusieurs conteneurs

: 
$ docker container update
--cpu-shares 512 -m 300M
abebf7571666 hopeful_morse

Mettre à jour les contraintes de mémoire du noyau d'un

conteneur

Vous pouvez mettre à jour la limite de mémoire du noyau d'un conteneur à l'aide de l'option --kernel-memory. Sur une version du noyau antérieure à 4.6, cette option ne peut être mise à jour sur un conteneur en cours d'exécution que si le conteneur a été démarré avec --kernel-memory. Si le conteneur a été démarré sans --kernel-memory, vous devez arrêter le conteneur avant de mettre à jour la mémoire du

noyau.

REMARQUE : L'option --kernel-memory est obsolète depuis Docker 20.

10.

Par exemple, si vous avez démarré un conteneur avec cette commande

: 
$ docker run -dit --name test --kernel-memory 50M ubuntu
bash

Vous pouvez mettre à jour la mémoire du noyau pendant que le conteneur est en cours d'exécution

: 
$ docker container update --kernel-memory 80M
test

Si vous avez démarré un conteneur sans mémoire du noyau initialisée

: 
$ docker run -dit --name test2 --memory 300M ubuntu
bash

La mise à jour de la mémoire du noyau du conteneur en cours d'exécution test2 échouera. Vous devez arrêter le conteneur avant de mettre à jour le paramètre --kernel-memory. La prochaine fois que vous le démarrerez, le conteneur utilisera la nouvelle

valeur.

Les versions du noyau plus récentes que 4.6 (incluse) n'ont pas cette limitation ; vous pouvez utiliser --kernel-memory de la même mani

ère que les aut
res options.

Mettre à jour la politique de redémarrage d'un

conteneur

Vous pouvez changer la politique de redémarrage d'un conteneur en cours d'exécution. La nouvelle politique de redémarrage prend effet immédiatement après avoir exécuté docker container update sur un

conteneur.

Pour mettre à jour la politique de redémarrage d'un ou plusieurs conteneurs

: 
$ docker container update --restart=on-failure:3 abebf7571666
hopeful_morse

Notez que si le conteneur est démarré avec l'indicateur « --rm », vous ne pouvez pas mettre à jour sa politique de redémarrage. Le AutoRemove et le RestartPolicy sont mutue

llement excl
usifs pour l
e conteneur.
