DOSEMU.BIN(1) Émulation DOS DOSEMU.BIN(1)

NOM

dosemu.bin, dosdebug - exécuter DOS et des programmes DOS sous Linux

SYNTAXE

dosemu.bin [ -234ABCcdKkmNnOpSstVwX ] [ -h niveau ] [ -F fichier ] [ --Fusers fichier ] [ --Flibdir répertoire ] [ --Fimagedir répertoire ] [ -f fichier ] [ -L fichier_dexefile ] [ -u variable_conf ] [ -D indicateurs ] [ -M taille ] [ -e taille ] [ -x taille ] [ -P fichier ] [ -o fichier ] [ 2> fichier_debug ] [ -I options_config ] [ -i [rép_boot] ] [ -U tube_entrée[:tube_sortie] ] [ [-E] commande_dos ]

dosdebug

DESCRIPTION

dosemu.bin est le binaire encapsulé par le script dosemu (1) qui invoque l'émulateur DOS Linux, également connu sous le nom de DOSEMU.
fichier_debug est un fichier optionnel dans lequel toutes les sorties de débogage seront redirigées.

dosdebug est utilisé pour contrôler ou déboguer un DOSEMU déjà en cours d'exécution.

Bien que ce programme soit connu comme l'émulateur DOS, il s'agit en fait d'une machine virtuelle pour DOS, permettant à DOS et aux programmes écrits pour DOS de fonctionner dans un environnement similaire à un IBM PC/AT standard ou compatible avec un processeur Intel 80x86 en mode réel. DOSEMU fournit une émulation de services tels que la vidéo BIOS, le disque, le clavier, les ports série et l'imprimante ; la mémoire CMOS pour les informations de configuration ; une horloge en temps réel ; l'allocation de mémoire via la spécification XMS 3.0, EMS 4.0 et DPMI 0.9.

Étant donné que DOSEMU n'est pas vraiment un émulateur DOS, une copie de FreeDos est nécessaire, qui est maintenant pré-configurée et fait partie de la distribution binaire officielle de DOSEMU. De plus, tout DOS propriétaire actuellement disponible (tel que MS-DOS, PC-DOS, DR-DOS) peut être démarré, une fois correctement configuré.

EXIGENCES DU NOYAU

Actuellement, vous aurez besoin de Linux 2.0.28 ou supérieur avec l'option SYSV IPC (facilities de communication inter-processus System V, voir ipc(2)) compilée. SYSV IPC est une option dans la configuration lors d'une compilation du noyau Linux.

OPTIONS

-2,3,4,5
choisir le processeur 286, 386, 486 ou 586 à simuler.
-A
démarrer depuis la disquette A (il n'est pas nécessaire que ce soit une vraie disquette, voir ci-dessous)
-B
démarrer depuis la disquette B (il n'est pas nécessaire que ce soit une vraie disquette, voir ci-dessous)
-C
démarrer depuis le disque dur C (il n'est pas nécessaire que ce soit un vrai disque dur ou même un système de fichiers msdos, voir ci-dessous)
-c
utiliser la vidéo console directe (doit être sur la console, nécessite des privilèges spéciaux et -s).
-d
se détacher de la console virtuelle ou du tty courant et s'attacher à la première console virtuelle libre
[-E] commande_dos
Exécute une commande DOS lors du démarrage de DOSEMU, et, si '-E' n'est pas donné, quitte DOSEMU après avoir exécuté la commande. La commande peut aussi être donnée avec un chemin Linux (par exemple /home/joeuser/dosemu/freedos/bin/xcopy.exe). Note : cela ne fonctionne que si votre autoexec.bat contient une commande "unix -e".
-k
utiliser le clavier console RAW (doit être sur la console)
-F
Analyser ce script de configuration au lieu du fichier global.conf intégré (vous devez exécuter en tant que root sur DOSEMU suid pour cela)
--Fusers
Ignorer dosemu.users et utiliser ce fichier à la place (uniquement accepté lorsque dosemu.bin n'est *pas* suid-root).
--Flibdir
Ignorer le DOSEMU_LIB_DIR par défaut (tel que potentiellement défini dans dosemu.users) et utiliser ce répertoire à la place.
--Fimagedir
Ignorer le répertoire par défaut pour les répertoires de démarrage et les images de disque dur (DOSEMU_HDIMAGE_DIR) et utiliser ce répertoire à la place.
-f
Analyser ce fichier de configuration au lieu de .dosemurc
-n
Ignorer (ne pas utiliser) dosemu.users et dosemu.conf (uniquement accepté lorsque dosemu.bin n'est *pas* suid-root).
-u
définir une variable de configuration utilisateur. Un préfixe u_ est ajouté au nom pour éviter les conflits de noms. Cette variable peut alors être vérifiée dans dosemu.conf ou global.conf pour une configuration spéciale.
-L
Charger et démarrer un fichier DEXE (image disque amorçable spéciale pré-configurée contenant une seule application DOS)
-I
Analyser la chaîne après -I avec la même syntaxe que global.conf ou .dosemurc, comme
dos ... -I '{ video { mda }}'

Ceci est utile si vous souhaitez simplement remplacer un paramètre de configuration donné temporairement. Vous pouvez également avoir une configuration générique en exécutant un script tel que

dos ... -I "`monconf.sh`"

où monconf.sh est un script écrivant la configuration sur la sortie standard. Si vous avez un fichier de configuration alternatif en plus de .dosrc,

dos ... -I "`cat monautre.conf`"

fera l'affaire. Notez cependant que vous devez mettre entre guillemets le paramètre derrière -I car il est attendu comme *un seul* argument.

-i[rép_boot]
lancé dans le cadre d'une installation système, cette option réinstalle un DOS utilisé dans DOSEMU (ce peut être le FreeDOS distribué avec DOSEMU ou tout autre DOS propriétaire, démarrable via fatfs). rép_boot est le nom de base d'un répertoire. Le lien symbolique ~/.dosemu/drives/c pointera vers ce répertoire. La réinstallation est rarement nécessaire, car en pratique, le(s) lien(s) symbolique(s) pointera(ont) automatiquement vers des fichiers mis à jour.
-D
spécifier quels messages de débogage autoriser/supprimer
-h
afficher la configuration sur la sortie d'erreur et quitter (définit implicitement -D+c). Ceci est utile pour déboguer les fichiers de configuration, vous devriez aussi utiliser -O pour diriger les messages de type +c vers la sortie d'erreur. `niveau' peut être 0, 1 ou 2 et contrôle la quantité de sortie de débogage du parseur de configuration : Pas de débogage du parseur (0), débogage de la boucle du parseur (1), débogage if_else_endif (2).
-H
spécifier les indicateurs de prise en charge de dosdebug, actuellement seul `1' est raisonnable. avec -H1, vous forcez dosemu à attendre que le terminal dosdebug se connecte. Ainsi, pour déboguer une session DOS depuis le tout début, vous démarrez d'abord dosemu avec -H1 puis démarrez dosdebug. DOSEMU se bloquera alors avant de sauter dans le secteur de démarrage chargé, attendant que dosdebug se connecte. Une fois connecté, vous êtes dans un état `arrêté' et pouvez définir des points d'arrêt ou exécuter pas à pas le code de démarrage.
-M
définir la mémoire de base à TAILLE Kilooctets
-m
activer/désactiver le support interne de la souris
-O
utiliser la sortie d'erreur pour la sortie des messages de débogage
-o
utiliser ce fichier pour la sortie des messages de débogage
-P
copier la sortie de débogage dans FICHIER
-p
arrêter pour demander une confirmation si un problème de configuration non fatal est détecté
-S
exécuter en utilisant SDL
-s
mode super-utilisateur / fonctionnalités complètes : activer l'accès direct au matériel. Utilisez ce commutateur si vous souhaitez utiliser les graphiques sur la console, avoir besoin d'un accès direct aux ports, d'interruptions matérielles ou d'un accès réseau brut. Implique -V et -k par défaut
-t
démarrer une session tty, avec le même effet que si vous aviez tapé `dosemu' dans une xterm (ou équivalent).
-V
mode sans privilèges : désactiver l'accès direct au matériel. Ne pas utiliser ce commutateur si vous souhaitez utiliser les graphiques sur la console, avoir besoin d'un accès direct aux ports, d'interruptions matérielles ou d'un accès réseau brut.
-w
ne pas se détacher de la console virtuelle ou du tty courant (utile pour lancer une session tty et ne pas la détacher)
-x
démarrer une session X11, avec le même effet que si vous aviez tapé `dosemu' dans une xterm.
-X
démarrer une session X11, comme avec -x mais, en outre, cette option rend dosemu `transparent' aux événement du clavier et de la souris, et au son. Cela permet d'exécuter des programmes dos sous windows, par exemple.
-U
spécifier un tube (pipe) pour l'entrée et un tube pour la sortie. Ceci peut être utilisé pour passer des commandes à DOSEMU et recevoir des réponses d'une application exécutée dans DOSEMU. Par exemple, vous pouvez envoyer des commandes à une application interactive lancée dans DOSEMU. La syntaxe est : -U nom_tube_entrée[:nom_tube_sortie]. Le tube de sortie est optionnel. Si le tube de sortie n'est pas spécifié, alors la sortie standard de DOSEMU sera utilisée. Si aucun nom de tube n'est spécifié, alors DOSEMU lira depuis l'entrée standard et écrira sur la sortie standard.

VIDÉ

O

DOSEMU peut être exécuté sur n'importe quel périphérique tty. Cependant, des performances et des fonctionnalités accrues peuvent être obtenues en tirant parti de caractéristiques spéciales de la console Linux. Ceux qui exécutent DOSEMU sur la console pourraient vouloir examiner les -c, -k et -V commutateurs, expliqués plus en détail dans README.txt. Il y a aussi une documentation très brève dans le fichier dosemu.conf, qui peut être édité selon vos

besoins.

En bref, l'utilisation correcte du périphérique console et des commutateurs correspondants permet

à l'utilisateur de voir un programme DOS dans ses couleurs et sa police d'origine, sans aucun des
problèmes périodiques de mise à jour d'écran rencontrés avec le code de sortie tty générique.

CTRL et SHIFT peut être utilisée pour générer les codes de

MESSAGES DE

DÉBOGAGE

Les messages de débogage peuvent être contrôlés soit sur la ligne de commande, soit dans le fichier de configuration. Consultez la documentation à l'intérieur du fichier config.dist inclus avec DOSEMU dans le sous-répertoire examples, pour les options de débogage. Sur la ligne de commande, vous pouvez spécifier quelles classes de messages vous souhaitez que dos autorise. La syntaxe est DOSEMU prend une option "-D FLAGS", où FLAGS est une chaîne de lettres qui spécifie quelles options imprimer ou supprimer. DOSEMU analyse cette chaîne de gauche à

droite.


+ active les options suivantes (état initial)
- désactive les options suivantes
a active/désactive toutes les options, selon le signe
0 désactive toutes les options
1-9 définit le niveau de débogage, plus il est élevé, plus il y a de sortie
# où # est une lettre de la liste des classes valides,
désactive/active cette option selon l'état
+/-

.

Classes de messages

:


d disque R lecture disque W écriture disque
D int 21h C cdrom v vidéo
X support X k clavier i E/S de port
s série m souris # ints par défaut
p imprimante g général c configuration
w avertissement h matériel I IPC
E EMS x XMS M DPMI
n réseau IPX P pilote Pkt S SON
r PIC T traçage E/S Z PCI-BIOS
A pilote ASPI Q pilote de

mapping

Toutes les classes de débogage suivant un caractère +, jusqu'à un caractère -, seront activées (non supprimées). Toutes celles après un caractère -, jusqu'à un caractère +, seront supprimées. Le caractère a agit comme une chaîne de toutes les classes de débogage possibles, donc +a active tous les messages de débogage, et -a désactive tous les messages de débogage. Les caractères 0 et 1-9 sont également spéciaux : 0 désactive tous les messages de débogage, et 1-9 active tous les messages de débogage, mais définit aussi le niveau de

débogage.

Un caractère + est supposé au début de la chaîne FLAGS. Certaines classes, comme error, ne peuvent pas être désactivées. Si vous n'avez pas redirigé stderr, presque toute la sortie vers stderr va vers /dev/null

.

Quelques exemples :
"-D+a-v" ou "-D1-v" : tous les messages sauf vidéo
"-D+kd" : par défaut + clavier et disque
"-D0+RW" : seulement LECTURE et ÉCRITURE

disque

N'importe quelle lettre d'option peut apparaître n'importe où. Même des combinaisons inutiles, comme -D01-a-1+0, seront analysées sans erreur, alors soyez prudent. Certaines options sont définies par défaut, d'autres sont effacées. Cela dépend de

mon humeur et changera probablement entre les versions. Vous pouvez vous a
ssurer desquelles sont définies en les spécifiant toujours explicitement.
