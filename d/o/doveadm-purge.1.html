NOM

doveadm-purge - Supprimer les messages avec refcount=0 des fichiers mdbox

SYNTAXE

doveadm [OPTIONS GLOBALES] purge [-S socket_path] -A

doveadm [OPTIONS GLOBALES] purge [-S socket_path] -F fichier

doveadm [OPTIONS GLOBALES] purge [-S socket_path] --no-userdb-lookup

doveadm [OPTIONS GLOBALES] purge [-S socket_path] -u utilisateur

DESCRIPTION

La commande doveadm purge est utilisée pour supprimer tous les messages avec refcount=0 du stockage de courrier d'un utilisateur. Le refcount d'un message est diminué à 0 lorsque l'utilisateur (ou un utilitaire d'administration) a expurgé toutes les instances d'un message de toutes les boîtes aux lettres.

Dans la première forme, la commande sera exécutée pour tous les utilisateurs.

Dans la deuxième forme, la commande sera exécutée pour tous les utilisateurs listés dans le fichier donné.

Dans la troisième forme, la commande sera effectuée pour l'utilisateur contenu dans la variable d'environnement USER.

Dans la dernière forme, seuls les messages du ou des utilisateurs donnés seront purgés.

OPTIONS GLOBALES

doveadm global(1)

-D

Active la verbosité et les messages de débogage.

-O

Ne lit aucun fichier de configuration, utilise simplement les valeurs par défaut. Le réglage dovecot_storage_version est par défaut la dernière version, mais peut être remplacé avec

-k

Préserve l'environnement entier pour doveadm, pas seulement le réglage import_environment.

-v

Active la verbosité, y compris le compteur de progression.

-i nom-instance

Si vous utilisez plusieurs instances Dovecot, choisissez le fichier de configuration en fonction de ce nom d'instance.

Voir le réglage instance_name pour plus d'informations.

-c fichier-config

Lit la configuration du fichier-config donné. Par défaut, il lit d'abord le socket de configuration, puis se rabat sur /etc/dovecot/dovecot.conf. Vous pouvez également pointer cela vers le socket de configuration d'une instance exécutant une version compatible.

-o réglage=valeur

Remplace le réglage de configuration de /etc/dovecot/dovecot.conf et de la base d'utilisateurs par la valeur donnée. Pour remplacer plusieurs réglages, l'option -o peut être spécifiée plusieurs fois.

OPTIONS

-A

Si l'option -A est présente, la commande sera effectuée pour tous les utilisateurs. L'utilisation de cette option en combinaison avec des utilisateurs système de userdb { driver = passwd } n'est pas recommandée, car elle inclut également des utilisateurs avec un UID inférieur à celui configuré avec le réglage first_valid_uid.

Lorsque le module userdb SQL est utilisé, assurez-vous que le réglage userdb_sql_iterate_query correspond à la disposition de votre base de données.

Lors de l'utilisation du module userdb LDAP, assurez-vous que les réglages userdb_fields et userdb_ldap_iterate_fields correspondent à votre schéma LDAP. Sinon, doveadm(1) ne pourra pas itérer sur tous les utilisateurs.

-F fichier

Exécute la commande pour tous les utilisateurs du fichier. C'est similaire à l'option -A, mais au lieu d'obtenir la liste des utilisateurs à partir de la base d'utilisateurs, ils sont lus à partir du fichier donné. Le fichier contient un nom d'utilisateur par ligne.

--no-userdb-lookup

N'effectue pas de recherche dans la base d'utilisateurs. Utilise la variable d'environnement USER pour spécifier le nom d'utilisateur.

-S chemin-socket

L'argument de l'option est soit un chemin absolu vers un socket de domaine UNIX local, soit un nom d'hôte et un port (nom-hôte:port), afin de se connecter à un hôte distant via un socket TCP.

Cela permet à un administrateur d'exécuter des commandes de messagerie doveadm(1) via le socket donné.

-u utilisateur/masque

Exécute la commande uniquement pour l'utilisateur donné. Il est également possible d'utiliser les caractères génériques '*' et '?' (par exemple, -u *@example.org).

SIGNALEMENT DE BOGUES

Signalez les bogues, y compris la sortie de doveconf -n, à la liste de diffusion Dovecot ⟨dovecot@dovecot.org⟩. Les informations sur le signalement des bogues sont disponibles à l'adresse : https://dovecot.org/bugreport.html
