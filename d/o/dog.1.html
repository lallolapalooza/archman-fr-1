dog est un client DNS en ligne de commande. Il dispose d'une sortie colorée, prend

Par défaut, dog interrogera les enregistrements A en utilisant le résolveur par défaut du système. Au moins un nom de domaine doit être passé — dog n'interrogera pas automatiquement les serveurs de noms

racines.

Les options de requête peuvent être passées via une option en ligne de commande, comme `--query lookup.dog' ou `--type MX', ou comme arguments simples, comme `lookup.dog' ou `MX'. dog fera une supposition intelligente quant au sens des arguments simples (MX est assez clairement un type), ce qui facilite la composition rapide de requêtes ad hoc. Si la précision est souhaitée, utilisez les options sous leur forme

longue.

Si plus d'un domaine, type, serveur de noms ou classe est spécifié, dog effectuera une requête pour chaque combinaison et affichera les résultats combinés dans un tableau. Par exemple, passer trois arguments de type et deux arguments de nom de domaine enverra six

requêtes.

Le DNS utilise traditionnellement le port 53 pour TCP et UDP. Pour ut

iliser un résolveur avec un port différent, incluez le numéro de
port après un deux-points (:) dans l'adresse du serveur de noms.

Par défaut, dog utilisera le protocole UDP, renvoyant automatiquement la requête via TCP si la réponse indique que le message est trop volumineux pour UDP. Passer --udp n'utilisera que UDP et échouera dans ce cas ; passer --tcp utilisera TCP par

défaut.

Les protocoles DNS-over-TLS (DoT) et DNS-over-HTTPS (DoH) sont disponibles avec les options --tls et --https. Gardez à l'esprit que le résolveur par défaut du système ne répondra probablement pas aux requêtes utilisant ces

protocoles.

Notez que si un nom d'hôte ou de domaine est donné comme serveur de noms, plutôt qu'une adresse IP, la résolution de cet hôte est effectuée par le système d'exploitation, et non par

dog.

Lorsqu'un paquet DNS de réponse contient un enregistrement de l'un de ces types connus, dog l'affichera dans un tableau contenant le nom du type et un résumé lisible de son

contenu.

Les enregistrements dont le numéro de type ne correspond à aucun type d'enregistrement connu seront également affichés. Comme ils ne peuvent pas être interprétés, leur contenu sera affiché sous forme de série de

nombres.

dog contient également une liste de noms de types d'enregistrement dont il connaît le numéro de type mais qu'il ne peut pas interpréter, comme IXFR, AN

Y ou AFSDB. Ceux-ci sont acceptés comme arguments en ligne de commande, ce qui signifie que vous pouvez envoyer une requête AFSDB avec `dog AFSDB'.
Cependant, leur contenu de réponse sera toujours affiché sous forme de nombres. Ils pourraient être pris en charge dans des versions futures de dog.
