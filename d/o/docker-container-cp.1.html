NOM

docker-container-cp - Copier des fichiers/dossiers entre un conteneur et le système de fichiers local

SYNOPSIS

docker container cp [OPTIONS] CONTAINER:SRC_PATH DEST_PATH|- docker cp [OPTIONS] SRC_PATH|- CONTAINER:DEST_PATH

DESCRIPTION

L'utilitaire docker container cp copie le contenu de SRC_PATH vers DEST_PATH. Vous pouvez copier du système de fichiers du conteneur vers la machine locale ou l'inverse, du système de fichiers local vers le conteneur. Si - est spécifié pour SRC_PATH ou DEST_PATH, vous pouvez aussi diffuser une archive tar depuis STDIN ou vers STDOUT. Le CONTAINER peut être un conteneur en cours d'exécution ou arrêté. Le SRC_PATH ou DEST_PATH peut être un fichier ou un répertoire.

La commande docker container cp suppose que les chemins du conteneur sont relatifs au répertoire / (racine) du conteneur. Cela signifie que le slash initial est facultatif ; la commande considère compassionate_darwin:/tmp/foo/myfile.txt et compassionate_darwin:tmp/foo/myfile.txt comme identiques. Les chemins de la machine locale peuvent être absolus ou relatifs. La commande interprète les chemins relatifs de la machine locale comme relatifs au répertoire de travail courant depuis lequel docker container cp est exécutée.

La commande cp se comporte comme la commande Unix cp -a en ce sens que les répertoires sont copiés récursivement avec les permissions préservées si possible. La propriété est définie sur l'utilisateur et le groupe principal à la destination. Par exemple, les fichiers copiés vers un conteneur sont créés avec un UID:GID correspondant à l'utilisateur root. Les fichiers copiés vers la machine locale sont créés avec le UID:GID de l'utilisateur qui a invoqué la commande docker container cp . Si vous spécifiez l'option -L , docker container cp suit tout lien symbolique dans SRC_PATH. docker container cp ne crée pas les répertoires parents pour DEST_PATH s'ils n'existent pas.

En supposant un séparateur de chemin /, un premier argument SRC_PATH et un second argument DEST_PATH, le comportement est le suivant :

•
SRC_PATH spécifie un fichier
•
DEST_PATH n'existe pas
•
le fichier est enregistré dans un fichier créé à DEST_PATH
•
DEST_PATH n'existe pas et se termine par /
•
Condition d'erreur : le répertoire de destination doit exister.
•
DEST_PATH existe et est un fichier
•
la destination est écrasée avec le contenu du fichier source
•
DEST_PATH existe et est un répertoire
•
le fichier est copié dans ce répertoire en utilisant le nom de base de SRC_PATH
•
SRC_PATH spécifie un répertoire
•
DEST_PATH n'existe pas
•
DEST_PATH est créé en tant que répertoire et le contenu du répertoire source est copié dans ce répertoire
•
DEST_PATH existe et est un fichier
•
Condition d'erreur : impossible de copier un répertoire vers un fichier
•
DEST_PATH existe et est un répertoire
•
SRC_PATH ne se termine pas par /. (c'est-à-dire : slash suivi de point)
•
le répertoire source est copié dans ce répertoire
•
SRC_PATH se termine par /. (c'est-à-dire : slash suivi de point)
•
le contenu du répertoire source est copié dans ce répertoire

La commande exige que SRC_PATH et DEST_PATH existent selon les règles ci-dessus. Si SRC_PATH est local et est un lien symbolique, le lien symbolique, et non la cible, est copié par défaut. Pour copifier la cible du lien et non le lien, spécifiez l'option -L .

Un deux-points (:) est utilisé comme délimiteur entre CONTAINER et son chemin. Vous pouvez aussi utiliser : lors de la spécification de chemins pour un SRC_PATH ou DEST_PATH sur une machine locale, par exemple file:name.txt. Si vous utilisez un : dans un chemin de machine locale, vous devez être explicite avec un chemin relatif ou absolu, par exemple :

`/chemin/vers/fichier:name.txt` ou `./fichier:name.txt`

Il n'est pas possible de copier certains fichiers système tels que les ressources sous /proc, /sys, /dev, tmpfs et les montages créés par l'utilisateur dans le conteneur. Cependant, vous pouvez toujours copifier de tels fichiers en exécutant manuellement tar dans docker exec. Par exemple (en supposant que SRC_PATH et DEST_PATH sont des répertoires) :

$ docker exec foo tar Ccf $(dirname SRC_PATH) - $(basename SRC_PATH) | tar Cxf DEST_PATH -

ou

$ tar Ccf $(dirname SRC_PATH) - $(basename SRC_PATH) | docker exec -i foo tar Cxf DEST_PATH -

L'utilisation de - comme SRC_PATH diffuse le contenu de STDIN sous forme d'archive tar. La commande extrait le contenu du tar vers DEST_PATH dans le système de fichiers du conteneur. Dans ce cas, DEST_PATH doit spécifier un répertoire. L'utilisation de - comme DEST_PATH diffuse le contenu de la ressource sous forme d'archive tar vers STDOUT.

EXEMPLES

Supposons qu'un conteneur ait terminé de produire une sortie sous forme de fichier qu'il enregistre quelque part dans son système de fichiers. Il peut s'agir de la sortie d'un job de compilation ou d'un autre calcul. Vous pouvez copier ces sorties du conteneur vers un emplacement sur votre hôte local.

Si vous voulez copier le répertoire /tmp/foo d'un conteneur vers le répertoire existant /tmp sur votre hôte. Si vous exécutez docker container cp dans votre répertoire ~ (d'accueil) sur la machine locale :

$ docker container cp compassionate_darwin:tmp/foo /tmp

Docker crée un répertoire /tmp/foo sur votre hôte. Alternativement, vous pouvez omettre le slash initial dans la commande. Si vous exécutez cette commande depuis votre répertoire d'accueil :

$ docker container cp compassionate_darwin:tmp/foo tmp

Si ~/tmp n'existe pas, Docker le créera et copiera le contenu de /tmp/foo du conteneur vers ce nouveau répertoire. Si ~/tmp existe déjà en tant que répertoire, Docker copiera le contenu de /tmp/foo du conteneur vers un répertoire à ~/tmp/foo.

Lors de la copie d'un fichier unique vers un CHEMINLOCALexistant, la commande docker container cp écrasera le contenu de CHEMINLOCAL s'il s'agit d'un fichier, ou le placera dans CHEMINLOCAL s'il s'agit d'un répertoire, en écrasant un fichier existant portant le même nom si tel est le cas. Par exemple, cette commande :

$ docker container cp sharp_ptolemy:/tmp/foo/myfile.txt /test

Si /test n'existe pas sur la machine locale, il sera créé en tant que fichier avec le contenu de /tmp/foo/myfile.txt du conteneur. Si /test existe en tant que fichier, il sera écrasé. Enfin, si /test existe en tant que répertoire, le fichier sera copié vers /test/myfile.txt.

Ensuite, supposons que vous vouliez copier un fichier ou un dossier dans un conteneur. Par exemple, il pourrait s'agir d'un fichier de configuration ou d'une autre entrée pour un calcul long que vous aimeriez placer dans un conteneur créé avant son démarrage. C'est utile car cela ne nécessite pas que le fichier de configuration ou l'autre entrée existe dans l'image du conteneur.

Si vous avez un fichier, config.yml, dans le répertoire courant de votre machine locale et que vous souhaitez le copier vers un répertoire existant à /etc/my-app.d dans un conteneur, cette commande peut être utilisée :

$ docker container cp config.yml myappcontainer:/etc/my-app.d

Si vous avez plusieurs fichiers dans un répertoire local /config que vous devez copier vers un répertoire /etc/my-app.d dans un conteneur :

$ docker container cp /config/. myappcontainer:/etc/my-app.d

La syntaxeove command will copy the contents of the local /config directory into the directory /etc/my-app.d in the container.

Finally, if you want to copy a symbolic link into a container, you typically want to copy the linked target and not the link itself. To copy the target, use the -L option, for example:

$ ln -s /tmp/somefile /tmp/somefile.ln
$ docker container cp -L /tmp/somefile.ln myappcontainer:/tmp/

This command copies content of the local /tmp/somefile into the file /tmp/somefile.ln in the container. Without -L option, the /tmp/somefile.ln preserves its symbolic link but not its content.

OPTIONS

-a, --archive[=false] Archive mode (copy all uid/gid information)

-L, --follow-link[=false] Always follow symbol link in SRC_PATH

-q, --quiet[=false] Suppress progress output during copy. Progress output is automatically suppressed if no terminal is attached
