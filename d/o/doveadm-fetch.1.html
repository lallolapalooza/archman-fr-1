NOM

doveadm-fetch - Récupérer des messages partiels/complets ou des informations sur les messages

SYNOPSIS

doveadm [OPTIONS GLOBALES] [-f formateur] fetch [-S chemin_du_socket] -A champs requête_de_recherche

doveadm [OPTIONS GLOBALES] [-f formateur] fetch [-S chemin_du_socket] -F fichier champs requête_de_recherche

doveadm [OPTIONS GLOBALES] [-f formateur] fetch [-S chemin_du_socket] --no-userdb-lookup champs requête_de_recherche

doveadm [OPTIONS GLOBALES] [-f formateur] fetch [-S chemin_du_socket] -u utilisateur champs requête_de_recherche

DESCRIPTION


peut être utilisé pour récupérer le contenu et les métadonnées des messages. Cela peut être utile pour les scripts et pour le débogage. Si vous souhaitez récupérer les messages un par un, consultez doveadm-search(1).

•
Veuillez respecter la vie privée de vos utilisateurs.

OPTIONS GLOBALES

Options globales de doveadm(1)

-D

Active la verbosité et les messages de débogage. verbosité et les messages de débogage.

-O

Ne lit aucun fichier de configuration, utilise uniquement les valeurs par défaut. Le paramètre dovecot_storage_version a par défaut la dernière version, mais peut être remplacé avec

-k

Préserve l'environnement entier pour doveadm, pas seulement le paramètre import_environment .

-v

Active la verbosité, y compris le compteur de progression.

-i nom_instance

Si vous utilisez plusieurs instances Dovecot, choisissez le fichier de configuration en fonction de ce nom d'instance.

Consultez le paramètre instance_name pour plus d'informations.

-c fichier_de_configuration

Lit la configuration à partir du fichier_de_configurationdonné. Par défaut, il lit d'abord le socket de configuration, puis utilise /etc/dovecot/dovecot.conf. Vous pouvez également pointer vers le socket de configuration d'une instance exécutant une version compatible.

-o paramètre=valeur

Remplace le paramètre de configuration paramètre de /etc/dovecot/dovecot.conf et de la userdb avec la valeurdonnée. Afin de remplacer plusieurs paramètres, l'option -o peut être spécifiée plusieurs fois.

-f formateur

Spécifie le formateur pour formater la sortie. Les formateurs pris en charge sont :

flow

imprime chaque ligne avec des paires clé=valeur .

json

imprime un tableau JSON d'objets JSON.

pager

imprime chaque paire clé: valeur sur sa propre ligne et sépare les enregistrements avec un caractère de saut de page (^L).

tab

imprime un en-tête de tableau suivi de lignes de valeurs séparées par des tabulations.

table

imprime un en-tête de tableau suivi de lignes de valeurs alignées.

Cette commande utilise par défaut le formateur de sortie pager.

OPTIONS

-A

Si l'option -A est présente, la commande sera effectuée pour tous les utilisateurs. L'utilisation de cette option en combinaison avec les utilisateurs système de userdb { driver = passwd } n'est pas recommandée, car elle contient également des utilisateurs avec un UID inférieur à celui configuré avec le paramètre first_valid_uid .

Lorsque le module userdb SQL est utilisé, assurez-vous que le paramètre userdb_sql_iterate_query correspond à la disposition de votre base de données.

Lors de l'utilisation du module userdb LDAP, assurez-vous que les paramètres userdb_fields et userdb_ldap_iterate_fields correspondent à votre schéma LDAP. Sinon, doveadm(1) ne pourra pas itérer sur tous les utilisateurs.

-F fichier

Exécute la commande pour tous les utilisateurs du fichier. Cela est similaire à l'option -A , mais au lieu d'obtenir la liste des utilisateurs depuis la userdb, ils sont lus depuis le fichierdonné. Le fichier contient un nom d'utilisateur par ligne.

--no-userdb-lookup

N'effectue pas de recherche dans la userdb. Utilise la variable d'environnement USER pour spécifier le nom d'utilisateur.

-S chemin_du_socket

L'argument de l'option est soit un chemin absolu vers un socket de domaine UNIX local, soit un nom d'hôte et un port (nom_hôte:port), afin de se connecter à un hôte distant via un socket TCP.

Cela permet à un administrateur d'exécuter les commandes de courrier de doveadm(1) via le socket donné.

-u utilisateur/masque

Exécute la commande uniquement pour l' utilisateurdonné. Il est également possible d'utiliser les caractères génériques '*' et '?' (par ex. -u *@example.org).

ARGUMENTS

champs

Un ou plusieurs noms de champs de résultat à afficher, si la requête_de_recherche correspond à des messages. Afin de spécifier plusieurs champs, entourez-les de guillemets simples ou doubles.

Les champs pris en charge sont :

binary : Corps du message au format décodé.

binary.<section> : Partie du corps décodée, par ex. binary.1

body : Le corps d'un message.

body.<section> : Partie du corps, par ex. body.1

body.preview : Aperçu court du corps.

body.snippet : Ancien alias pour preview.

date.received : Date et heure de la livraison finale, lorsque le message a été livré pour la première fois dans la boîte aux lettres d'un utilisateur.

La date et l'heure internes du message source, lorsque le message a été copié par la commande IMAP COPY.

L'attribut date-heure lorsqu'il est présent, sinon l'heure actuelle, lorsque le message a été enregistré par la commande IMAP APPEND.

date.received.unixtime : date.received en horodatage unix.

date.saved : Date et heure où le message a été enregistré dans la boîte aux lettres.

date.saved.unixtime : date.saved en horodatage unix.

date.sent : Date et heure de l'en-tête Date: du message.

date.sent.unixtime : date.sent en horodatage unix.

flags : Les drapeaux IMAP d'un message, par ex. \Seen

guid : L'identifiant globalement unique d'un message.

hdr : L'en-tête du message.

hdr.<nom> : En-tête nommé du message.


: La sortie IMAP BODY du message (voir RFC 3501).


: La sortie IMAP BODYSTRUCTURE du message (voir RFC 3501).


: La sortie IMAP ENVELOPE du message (voir RFC 3501).

mailbox : Nom de la boîte aux lettres dans laquelle le message est stocké. Le nom est en UTF-8.

mailbox-guid : L'identifiant globalement unique de la boîte aux lettres dans laquelle se trouve le message.

modseq : Numéro de séquence de modification du courrier.

pop3.order : Le numéro d'ordre d'un message au sein d'une boîte aux lettres.

pop3.uidl : L'identifiant unique (POP3) d'un message au sein d'une boîte aux lettres.

refcount : Compteur de références du courrier, uniquement pour mdbox.

seq : Le numéro de séquence d'un message dans une boîte aux lettres.

size.physical : La taille physique d'un message.

size.virtual : La taille virtuelle d'un message, calculée avec des terminaisons de ligne CRLF.

storageid : ID spécifique au pilote de boîte aux lettres du courrier.

text : Le message entier (en-tête et corps).

text.utf8 : Le message entier (en-tête et corps) — encodé en UTF-8.

uid : L'identifiant unique (IMAP) d'un message dans une boîte aux lettres.

user : Le nom de connexion du propriétaire du message.

search_query

Récupérer les messages correspondant à cette requête de recherche. Voir doveadm-search-query(1) pour plus de détails.

EXEMPLE

Cet exemple est basé sur le premier exemple de doveadm-search(1). Nous récupérons les champs

doveadm fetch -u bob "mailbox date.sent" mailbox-guid 3a94c928d66ebe4bda04000015811c6a uid 8,25,45
mailbox: dovecot/pigeonhole/2.0
date.sent: 2010-01-19 01:17:41 (+0100)
^L
mailbox: dovecot/pigeonhole/2.0
date.sent: 2010-01-28 09:38:49 (+0100)
^L
mailbox: dovecot/pigeonhole/2.0
date.sent: 2010-03-28 18:41:14 (+0200)
