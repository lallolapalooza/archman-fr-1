podman-remote(1) Manuel des commandes générales podman-remote(1)

NOM

podman-remote - CLI distant pour Podman : un outil de gestion simple pour les pods, conteneurs et images.

SYNTAXE

podman-remote [options] commande

DESCRIPTION

Podman (Pod Manager) est un moteur de conteneurisation complet, un outil simple et sans démon. Podman fournit une ligne de commande comparable à celle de Docker (CLI), ce qui facilite la transition depuis d'autres moteurs de conteneurisation et permet la gestion des pods, conteneurs et images. En bref : alias docker=podman. La plupart des commandes Podman peuvent être exécutées par un utilisateur ordinaire, sans nécessiter de privilèges supplémentaires.

Podman utilise Buildah(1) en interne pour créer des images de conteneur. Les deux outils partagent le stockage des images (pas des conteneurs), par conséquent chacun peut utiliser ou manipuler les images (mais pas les conteneurs) créées par l'autre.

Podman-remote fournit un client local interagissant avec un nœud backend Podman via une API RESTful tunnellisée par une connexion SSH. Dans ce contexte, un nœud Podman est un système Linux avec Podman installé et le service API activé. Les informations d'identification pour cette session peuvent être passées via des indicateurs (flags), des variables d'environnement ou dans containers.conf.

Le fichier containers.conf est placé sous $HOME/.config/containers/containers.conf sous Linux et macOS, et %APPDATA%\containers\containers.conf sous Windows.

podman [OPTIONS GLOBALES]

OPTIONS GLOBALES

--connection=nom, -c

Nom de la connexion distante

Remplace la variable d'environnement CONTAINER_CONNECTION si elle est définie.

--help, -h

Affiche le message d'utilisation.

--identity=chemin

Chemin vers le fichier d'identité SSH. Si le fichier d'identité a été chiffré, Podman demande à l'utilisateur la phrase secrète. Si aucun fichier d'identité n'est fourni et qu'aucun utilisateur n'est spécifié, Podman utilise par défaut l'utilisateur qui exécute la commande podman. Podman demande le mot de passe de connexion sur le serveur distant.

Priorité de résolution de la valeur d'identité :
- Valeur de la ligne de commande
- Variable d'environnement CONTAINER_SSHKEY, si CONTAINER_HOST est trouvée
- containers.conf

--log-level=niveau

Niveau de journalisation : debug, info, warn, error (défaut), fatal ou panic.

--url=valeur

URL pour accéder au service Podman (par défaut à partir de containers.conf, socket Unix rootless « unix:///run/user/$UID/podman/podman.sock » ou en tant que root « unix:///run/podman/podman.sock »).

  • CONTAINER_HOST est du format <schéma>://[<utilisateur[:<motdepasse>]@]<hôte>[:<port>][<chemin>]
  • CONTAINER_PROXY est du format <socks5|socks5h>://[<utilisateur[:<motdepasse>]@]<hôte>[:<port>]

Détails :
- schéma est l'un des suivants :
* ssh (par défaut) : un socket Unix local (man 7 unix) sur l'hôte et le port nommés, accessible via SSH
* tcp : une connexion TCP non chiffrée et non authentifiée vers l'hôte et le port nommés, peut fonctionner avec un proxy si CONTAINER_PROXY est défini
* unix : un socket Unix local (man 7 unix) au chemin spécifié, ou le défaut pour l'utilisateur
- utilisateur : par défaut, soit root, soit l'utilisateur courant (uniquement pour ssh)
- motdepasse : pas de valeur par défaut (uniquement pour ssh)
- hôte : doit être fourni et est soit l'adresse IP, soit le nom de la machine hébergeant le service Podman (pour ssh et tcp)
- port : par défaut 22 (pour ssh et tcp)
- chemin : par défaut, soit /run/podman/podman.sock, soit /run/user/$UID/podman/podman.sock si l'exécution est sans root (pour unix), soit doit être explicitement spécifié (pour ssh)
- CONTAINER_PROXY : utiliser un proxy (socks5 ou socks5h) pour accéder au service Podman (uniquement pour tcp)

Priorité de résolution de la valeur d'URL :
- Valeur de la ligne de commande
- Variable d'environnement CONTAINER_HOST
- Table engine.service_destinations dans containers.conf, à l'exclusion du répertoire /usr/share/containers
- unix:///run/podman/podman.sock

Les connexions distantes utilisent le fichier containers.conf local pour les valeurs par défaut.

Quelques exemples de valeurs d'URL dans des formats valides :
- unix:///run/podman/podman.sock
- unix:///run/user/$UID/podman/podman.sock
- ssh://notroot@localhost:22/run/user/$UID/podman/podman.sock
- ssh://root@localhost:22/run/podman/podman.sock
- tcp://localhost:34451
- tcp://127.0.0.1:34451

--version

Affiche la version.

Variables d'environnement

Podman peut configurer des variables d'environnement à partir de la section env de la table [engine] dans containers.conf. Ces variables peuvent être remplacées en passant des variables d'environnement avant les commandes podman.

CONTAINERS_CONF

Définit les emplacements par défaut du fichier containers.conf.

CONTAINER_CONNECTION

Définit la valeur par défaut de --connection pour accéder au service Podman.

CONTAINER_HOST

Définit la valeur par défaut de --url pour accéder au service Podman.

CONTAINER_SSHKEY

Définit le chemin par défaut de --identity pour le fichier de clé SSH utilisé pour accéder au service Podman.

Statut de sortie

Le code de sortie de podman donne des informations sur la raison pour laquelle le conteneur n'a pas pu démarrer ou pourquoi il s'est arrêté. Lorsque les commandes podman se terminent avec un code non nul, les codes de sortie suivent la norme chroot, voir ci-dessous :

125 L'erreur concerne podman lui-même

$ podman run --foo busybox; echo $?
Error: unknown flag: --foo
125

126 Exécution d'une commande contenue et la commande ne peut pas être invoquée

$ podman run busybox /etc; echo $?
Error: container_linux.go:346: starting container process caused "exec: \"/etc\": permission denied": OCI runtime error
126

127 Exécution d'une commande contenue et la commande ne peut pas être trouvée
$ podman run busybox foo; echo $?
Error: container_linux.go:346: starting container process caused "exec: \"foo\": executable file not found in $PATH": OCI runtime error
127

Code de sortie Code de sortie de la commande contenue

$ podman run busybox /bin/sh -c 'exit 3'; echo $?
3
