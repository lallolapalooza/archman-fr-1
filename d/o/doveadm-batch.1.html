NOM

doveadm-batch - Exécuter plusieurs commandes pour plusieurs utilisateurs

SYNTAXE

doveadm [-Dv] batch [-S socket_path] -A sep commande sep commande [...]
doveadm [-Dv] batch [-S socket_path] -F fichier sep commande sep commande [...]
doveadm [-Dv] batch [-S socket_path] -u masque_utilisateur sep commande sep commande [...]

DESCRIPTION

La commande doveadm batch est utilisée pour exécuter séquentiellement plusieurs commandes de doveadm(1) pour plusieurs utilisateurs. C'est principalement une optimisation où Dovecot peut effectuer toutes les opérations de boîte aux lettres pour le même utilisateur en une seule fois, au lieu d'avoir à passer par les utilisateurs plusieurs fois.

Dans la première forme, doveadm(1) parcourra tous les utilisateurs, définis dans les user_db configurés, et exécutera la séquence de commandes pour chacun d'eux.

Dans la seconde forme, doveadm(1) parcourra tous les utilisateurs, listés dans le fichier donné.

Dans la troisième forme, les commandes seront exécutées pour chaque utilisateur correspondant au masque_utilisateur donné.

OPTIONS

Options globales de doveadm(1) :

-D
Active les messages verbeux et de débogage.
-o parametre=valeur
Remplace le parametre de configuration de /etc/dovecot/dovecot.conf et de l'userdb par la valeur donnée. Pour remplacer plusieurs paramètres, l'option -o peut être spécifiée plusieurs fois.
-v
Active la verbosité, y compris le compteur de progression.

Options spécifiques à la commande :

-A
Si l'option -A est présente, la commande sera effectuée pour tous les utilisateurs. L'utilisation de cette option en combinaison avec les utilisateurs système de userdb { driver = passwd } n'est pas recommandée, car elle inclut également les utilisateurs avec un UID inférieur à celui configuré avec le paramètre first_valid_uid.

Lorsque le module userdb SQL est utilisé, assurez-vous que le paramètre iterate_query dans /etc/dovecot/dovecot-sql.conf.ext correspond à la structure de votre base de données. Lors de l'utilisation du module userdb LDAP, assurez-vous que les paramètres iterate_attrs et iterate_filter dans /etc/dovecot/dovecot-ldap.conf.ext correspondent à votre schéma LDAP. Sinon, doveadm(1) ne pourra pas parcourir tous les utilisateurs.

-F fichier
Exécute la commande pour tous les utilisateurs du fichier. Ceci est similaire à l'option -A, mais au lieu de récupérer la liste des utilisateurs depuis l'userdb, ils sont lus depuis le fichier donné. Le fichier contient un nom d'utilisateur par ligne.
-S socket_path
L'argument de l'option est soit un chemin absolu vers un socket UNIX local, soit un nom d'hôte et un port (hostname:port), afin de se connecter à un hôte distant via un socket TCP.

Cela permet à un administrateur d'exécuter des commandes mail de doveadm(1) via le socket donné.

-u utilisateur/masque
Exécute la commande uniquement pour l'utilisateur donné. Il est également possible d'utiliser les caractères génériques '*' et '?' (par exemple, -u *@example.org).
Lorsque ni l'option -A, ni l'option -F fichier, ni l'option -u utilisateur n'a été spécifiée, la commande sera exécutée avec l'environnement de l'utilisateur actuellement connecté.

ARGUMENTS

commande
Toute commande de doveadm(1), avec arguments et options — à l'exception des options -A, -S et -u.
sep
Un seul caractère utilisé comme séparateur de commande, par exemple ':'. Attention, les caractères non cités, comme ; ou &, peuvent être interprétés par votre shell et ne seront jamais vus par doveadm(1).

EXEMPLE

Dans cet exemple, nous déplaçons les mails lus, plus vieux qu'un mois, pour tous les utilisateurs de example.net vers le stockage alternatif sous /nfsmount : 

mail_location = mdbox:~/mdbox:ALT=/nfsmount/%h/mdbox

La seconde commande supprimera les messages avec refcount=0 du stockage principal.

doveadm batch -u \*@example.net : altmove seen savedbefore 30d : purge

SIGNALEMENT DE BOGUES

Signalez les bogues, y compris la sortie de doveconf -n, à la liste de diffusion Dovecot <dovecot@dovecot.org>. Les informations sur le signalement de bogues sont disponibles à l'adresse : http://dovecot.org/bugreport.html
