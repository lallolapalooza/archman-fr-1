-e, --add-eol
Ajoute un saut de ligne à la dernière ligne s'il n'y en a pas. Ceci fonctionne pour chaque conversion.

Un fichier converti du format DOS vers Unix peut manquer d'un saut de ligne sur la dernière ligne. Certains éditeurs de texte écrivent des fichiers texte sans saut de ligne sur la dernière ligne. Certains programmes Unix ont des problèmes pour traiter ces fichiers, car la norme POSIX définit que chaque ligne d'un fichier texte doit se terminer par un caractère de nouvelle ligne. Par exemple, la concaténation de fichiers peut ne pas donner le résultat attendu.

-m, --add-bom
Écrit une Marque d'Ordre des Octets (BOM) dans le fichier de sortie. Par défaut, une BOM UTF-8 est écrite.

Lorsque le fichier d'entrée est UTF-16 et que l'option "-u" est utilisée, une BOM UTF-16 sera écrite.

N'utilisez jamais cette option lorsque le codage de sortie est autre que UTF-8, UTF-16 ou GB18030. Voir également la section UNICODE.

-n, --newfile ENTRÉE SORTIE ...
Mode nouveau fichier. Convertit le fichier ENTRÉE et écrit la sortie dans le fichier SORTIE. Les noms de fichiers doivent être donnés par paires et les noms génériques (wildcards) ne devraient PAS être utilisés, sinon vous perdrez vos fichiers.

La personne qui lance la conversion en mode nouveau fichier (apparié) sera le propriétaire du fichier converti. Les permissions de lecture/écriture du nouveau fichier seront les permissions du fichier d'origine moins l'umask(1) de la personne qui exécute la conversion.

--no-allow-chown
N'autorise pas le changement de propriétaire du fichier en mode ancien fichier (par défaut).

Interrompt la conversion lorsque la propriété utilisateur et/ou groupe du fichier d'origine ne peut pas être préservée en mode ancien fichier. Voir également les options "-o" et "-n". Cette option n'est disponible que si dos2unix est compilé avec le support de la préservation du propriétaire et du groupe des fichiers.

--no-add-eol
N'ajoute pas de saut de ligne à la dernière ligne s'il n'y en a pas.
-O, --to-stdout
Écrit sur la sortie standard, comme un filtre Unix. Utilisez l'option "-o" pour revenir au mode ancien fichier (sur place).

Combiné avec l'option "-e", les fichiers peuvent être correctement concaténés. Pas de lignes finales et initiales fusionnées, et pas de marques d'ordre des octets Unicode au milieu du fichier concaténé. Exemple :

dos2unix -e -O file1.txt file2.txt > output.txt
-o, --oldfile FICHIER ...
Mode ancien fichier. Convertit le fichier FICHIER et écrit la sortie sur celui-ci. Le programme s'exécute par défaut dans ce mode. Les noms génériques (wildcards) peuvent être utilisés.

En mode ancien fichier (sur place), le fichier converti obtient le même propriétaire, groupe et permissions de lecture/écriture que le fichier d'origine. Également lorsque le fichier est converti par un autre utilisateur qui a des permissions d'écriture sur le fichier (par exemple, l'utilisateur root). La conversion sera interrompue s'il n'est pas possible de préserver les valeurs d'origine. Le changement de propriétaire peut signifier que le propriétaire d'origine n'est plus capable de lire le fichier. Le changement de groupe peut être un risque de sécurité, le fichier pourrait être rendu lisible par des personnes pour lesquelles il n'est pas destiné. La préservation du propriétaire, du groupe et des permissions de lecture/écriture n'est supportée que sous Unix.

Pour vérifier si dos2unix a le support de la préservation du propriétaire et du groupe des fichiers, tapez "dos2unix -V".

La conversion est toujours effectuée via un fichier temporaire. Si une erreur se produit à mi-chemin de la conversion, le fichier temporaire est supprimé et le fichier d'origine reste intact. Si la conversion est réussie, le fichier d'origine est remplacé par le fichier temporaire. Vous pouvez avoir la permission d'écrire sur le fichier d'origine, mais pas la permission d'appliquer les mêmes propriétés de propriétaire et/ou de groupe sur le fichier temporaire que celles du fichier d'origine. Cela signifie que vous n'êtes pas en mesure de préserver le propriétaire et/ou le groupe du fichier d'origine. Dans ce cas, vous pouvez utiliser l'option "--allow-chown" pour continuer la conversion :

dos2unix --allow-chown foo.txt

Une autre option est d'utiliser le mode nouveau fichier :

dos2unix -n foo.txt foo.txt

L'avantage de l'option "--allow-chown" est que vous pouvez utiliser des jokets (wildcards) et que les propriétés de propriété seront préservées lorsque cela est possible.

-q, --quiet
Mode silencieux. Supprime tous les avertissements et messages. La valeur de retour est zéro. Sauf en cas d'utilisation d'options de ligne de commande incorrectes.
-r, --remove-bom
Supprime la Marque d'Ordre des Octets (BOM). N'écrit pas de BOM dans le fichier de sortie. Ceci est le comportement par défaut lors de la conversion en sauts de ligne Unix. Voir également l'option "-b".
-s, --safe
Ignore les fichiers binaires (par défaut).

L'ignorance des fichiers binaires est faite pour éviter des erreurs accidentelles. Soyez conscient que la détection des fichiers binaires n'est pas infaillible à 100%. Les fichiers d'entrée sont

scanné pour les symboles binaires qui ne sont généralement pas trouvés dans les fichiers texte. Il est possible qu'un fichier binaire contienne uniquement des caractères texte normaux. Un tel fichier binaire sera vu par erreur comme un fichier texte.

-u, --keep-utf16
Conserve le codage UTF-16 d'origine du fichier d'entrée. Le fichier de sortie sera écrit dans le même codage UTF-16, petit ou grand boutien, que le fichier d'entrée. Cela empêche la transformation en UTF-8. Un BOM UTF-16 sera écrit en conséquence. Cette option peut être désactivée avec l'option "-ascii".
-ul, --assume-utf16le
Suppose que le format du fichier d'entrée est UTF-16LE.

Lorsqu'il y a une marque d'ordre des octets (BOM) dans le fichier d'entrée, le BOM a la priorité sur cette option.

Si vous avez fait une mauvaise supposition (le fichier d'entrée n'était pas au format UTF-16LE) et que la conversion a réussi, vous obtiendrez un fichier de sortie UTF-8 avec du texte incorrect. Vous pouvez annuler la mauvaise conversion avec iconv(1) en reconvertissant le fichier de sortie UTF-8 en UTF-16LE. Cela restaurera le fichier d'origine.

La supposition d'UTF-16LE fonctionne comme un mode de conversion. En passant au mode ascii par défaut, la supposition d'UTF-16LE est désactivée.

-ub, --assume-utf16be
Suppose que le format du fichier d'entrée est UTF-16BE.

Cette option fonctionne de la même manière que l'option "-ul".

-v, --verbose
Affiche des messages détaillés. Des informations supplémentaires sont affichées concernant les marques d'ordre des octets (BOM) et la quantité de sauts de ligne convertis.
-F, --follow-symlink
Suit les liens symboliques et convertit leurs cibles.
-R, --replace-symlink
Remplace les liens symboliques par des fichiers convertis (les fichiers cibles d'origine restent inchangés).
-S, --skip-symlink
Laisse les liens symboliques et leurs cibles inchangés (par défaut).
-V, --version
Affiche les informations de version et quitte.

MODE MAC

Par défaut, les sauts de ligne sont convertis de DOS à Unix et vice versa. Les sauts de ligne Mac ne sont pas convertis.

En mode Mac, les sauts de ligne sont convertis de Mac à Unix et vice versa. Les sauts de ligne DOS ne sont pas modifiés.

Pour exécuter en mode Mac, utilisez l'option en ligne de commande "-c mac" ou les commandes "mac2unix" ou "unix2mac".

MODES DE CONVERSION

ascii
C'est le mode de conversion par défaut. Ce mode est destiné à la conversion de fichiers encodés en ASCII et compatibles ASCII, comme UTF-8. L'activation du mode ascii désactive les modes 7bit et iso.

Si dos2unix dispose du support UTF-16, les fichiers encodés en UTF-16 sont convertis vers l'encodage de caractères du locale courant sur les systèmes POSIX et vers UTF-8 sous Windows. L'activation du mode ascii désactive l'option de conservation de l'encodage UTF-16 ("-u") et les options d'hypothèse d'entrée UTF-16 ("-ul" et "-ub"). Pour savoir si dos2unix dispose du support UTF-16, tapez "dos2unix -V". Voir aussi la section UNICODE.

7bit
Dans ce mode, tous les caractères non-ASCII de 8 bits (avec des valeurs de 128 à 255) sont convertis en un espace de 7 bits.
iso
Les caractères sont convertis entre un jeu de caractères DOS (page de code) et un jeu de caractères ISO ISO-8859-1 (Latin-1) sous Unix. Les caractères DOS sans équivalent ISO-8859-1, pour lesquels la conversion n'est pas possible, sont convertis en un point. Il en va de même pour les caractères ISO-8859-1 sans contrepartie DOS.

Lorsque seule l'option "-iso" est utilisée, dos2unix tente de déterminer la page de code active. Lorsque cela n'est pas possible, dos2unix utilise la page de code par défaut CP437, principalement utilisée aux États-Unis. Pour forcer une page de code spécifique, utilisez les options -437 (US), -850 (Europe de l'Ouest), -860 (Portugais), -863 (Canadien français), ou -865 (Nordique). La page de code Windows CP1252 (Europe de l'Ouest) est également prise en charge avec l'option -1252. Pour d'autres pages de code, utilisez dos2unix en combinaison avec iconv(1). Iconv peut convertir entre une longue liste d'encodages de caractères.

N'utilisez jamais la conversion ISO sur des fichiers texte Unicode. Cela corrompra les fichiers encodés en UTF-8.

Quelques exemples :

Conversion de la page de code par défaut DOS vers Unix Latin-1 :

dos2unix -iso -n in.txt out.txt

Conversion de DOS CP850 vers Unix Latin-1 :

dos2unix -850 -n in.txt out.txt

Conversion de Windows CP1252 vers Unix Latin-1 :

dos2unix -1252 -n in.txt out.txt

Conversion de Windows CP1252 vers Unix UTF-8 (Unicode) :

iconv -f CP1252 -t UTF-8 in.txt | dos2unix > out.txt

Conversion d'Unix Latin-1 vers la page de code par défaut DOS :

unix2dos -iso -n in.txt out.txt

Conversion d'Unix Latin-1 vers DOS CP850 :

unix2dos -850 -n in.txt out.txt

Conversion d'Unix Latin-1 vers Windows CP1252 :

unix2dos -1252 -n in.txt out.txt

Conversion d'Unix UTF-8 (Unicode) vers Windows CP1252 :

unix2dos < in.txt | iconv -f UTF-8 -t CP1252 > out.txt

Voir aussi http://czyborra.com/charsets/codepages.html et http://czyborra.com/charsets/iso8859.html.

UNICODE

Encodages

Il existe différents encodages Unicode. Sous Unix et Linux, les fichiers Unicode sont généralement encodés en UTF-8. Sous Windows, les fichiers texte Unicode peuvent être encodés en UTF-8, UTF-16 ou UTF-16 big endian, mais sont le plus souvent encodés en format UTF-16.

Conversion

Les fichiers texte Unicode peuvent avoir des sauts de ligne DOS, Unix ou Mac, tout comme les fichiers texte ASCII.

Toutes les versions de dos2unix et unix2dos peuvent convertir les fichiers encodés en UTF-8, car UTF-8 a été conçu pour la compatibilité descendante avec ASCII.

dos2unix et unix2dos avec support Unicode UTF-16 peuvent lire les fichiers texte encodés en UTF-16 little et big endian. Pour savoir si dos2unix a été compilé avec le support UTF-16, tapez "dos2unix -V".

Sous Unix/Linux, les fichiers encodés en UTF-16 sont convertis vers l'encodage de caractères du locale. Utilisez la commande locale(1) pour savoir quel est l'encodage de caractères du locale. Lorsqu'une conversion n'est pas possible, une erreur de conversion se produit et le fichier est ignoré.

Sous Windows, les fichiers UTF-16 sont par défaut convertis en UTF-8. Les fichiers texte au format UTF-8 sont bien pris en charge sous Windows et Unix/Linux.

Les encodages UTF-16 et UTF-8 sont entièrement compatibles, aucune perte de texte ne se produira lors de la conversion. Lorsqu'une erreur de conversion UTF-16 vers UTF-8 se produit, par exemple si le fichier d'entrée UTF-16 contient une erreur, le fichier sera ignoré.

Lorsque l'option "-u" est utilisée, le fichier de sortie sera écrit dans le même encodage UTF-16 que le fichier d'entrée. L'option "-u" empêche la conversion en UTF-8.

dos2unix et unix2dos n'ont pas d'option pour convertir les fichiers UTF-8 en UTF-16.

Les modes de conversion ISO et 7 bits ne fonctionnent pas sur les fichiers UTF-16.

Marque d'Ordre des Octets

Sous Windows, les fichiers texte Unicode ont généralement une Marque d'Ordre des Octets (BOM), car de nombreux programmes Windows (y compris Notepad) ajoutent des BOM par défaut. Voir aussi https://en.wikipedia.org/wiki/Byte_order_mark.

Sous Unix, les fichiers Unicode n'ont généralement pas de BOM. On suppose que les fichiers texte sont encodés dans l'encodage de caractères du locale.

dos2unix ne peut détecter qu'un fichier est au format UTF-16 que si le fichier possède un BOM. Lorsqu'un fichier UTF-16 n'a pas de BOM, dos2unix le considérera comme un fichier binaire.

Utilisez l'option "-ul" ou "-ub" pour convertir un fichier UTF-16 sans BOM.

Par défaut, dos2unix n'écrit pas de BOM dans le fichier de sortie. Avec l'option "-b", dos2unix écrit un BOM si le fichier d'entrée en avait un.

unix2dos écrit par défaut un BOM dans le fichier de sortie si le fichier d'entrée en avait un. Utilisez l'option "-r" pour supprimer le BOM.

dos2unix et unix2dos écrivent toujours un BOM lorsque l'option "-m" est utilisée.

Noms de fichiers Unicode sous Windows

dos2unix prend en charge la lecture et l'écriture des noms de fichiers Unicode dans l'invite de commande Windows. Cela signifie que dos2unix peut ouvrir des fichiers dont le nom contient des caractères qui ne font pas partie de la page de code ANSI par défaut du système. Pour savoir si dos2unix pour Windows a été compilé avec la prise en charge des noms de fichiers Unicode, tapez "dos2unix -V".

Il y a quelques problèmes d'affichage des noms de fichiers Unicode dans une console Windows. Voir l'option "-D", "--display-enc". Les noms de fichiers peuvent s'afficher incorrectement dans la console, mais les fichiers seront enregistrés avec le bon nom.

RÉCURSIVE

Dans un shell Unix, les commandes find(1) et xargs(1) peuvent être utilisées pour exécuter dos2unix récursivement sur tous les fichiers texte d'une arborescence de répertoires. Par exemple, pour convertir tous les fichiers .txt de l'arborescence sous le répertoire courant, tapez

: 
find . -name '*.txt' -print0 |xargs -0
dos2unix

L'option find(1) "-print0" et l'option correspondante xargs(1) -0 sont nécessaires lorsque des fichiers ont des espaces ou des guillemets dans leur nom. Sinon, ces options peuvent être omises. Une autre option est d'utiliser find(1) avec l' option "-exec"

: 
find . -name '*.txt' -exec dos2unix {}
\;

Dans une invite de commande Windows, la commande suivante peut être utilisée

: 
for /R %G in (*.txt) do dos2unix
"%G"

Les utilisateurs de PowerShell peuvent utiliser la commande suivante dans Windows PowerShell

: 
get-childitem -path . -filter
'*.txt' -recurse | foreach-
object {dos2unix $_.Fullname}

La langue principale est sélectionnée avec la variable d'environnement LANG. La variable LANG se compose de plusieurs parties. La première partie est en petites lettres, le code de langue. La deuxième est optionnelle et est le code de pays en majuscules, précédé d'un souligné. Il existe également une troisième partie optionnelle : l'encodage de caractères, précédé d'un point. export LANG=es_MX            Espagnol, Mexique
export LANG=en_US.iso88591   Anglais, USA, encodage Latin-1
export LANG=en_GB.UTF-8      Anglais, Royaume-Uni, encodage
UTF-8
