NOM

docbook2texi-spec.pl - convertir des Livres DocBook en documents Texinfo

SYNTAXE

sgmlspl docbook2man-spec.pl

nsgmls [ document sgml ]| sgmlspl docbook2texi-spec.pl [ basename ]

DESCRIPTION

docbook2texi est un fichier de spécification sgmlspl qui produit des documents GNU Texinfo à partir de documents DocBook.

Le programme lit l'ESIS produit par nsgmls (ou d'autres analyseurs SGML) depuis l'entrée standard. Actuellement, l'élément de document doit être Book, sinon les résultats sont indéfinis.

Sa sortie, le document Texinfo converti, est écrite sur la sortie standard.

Le fichier basename.refs sera également créé, contenant tous les nœuds du document et leurs nœuds 'enfants' immédiats. Comme le traitement des nœuds nécessite toujours des références avant, docbook2texi doit être exécuté deux fois pour chaque document : la première fois pour construire les références, et la seconde pour générer réellement un document valide.

EXIGENCES

Le paquet SGMLSpm de CPAN. Ce paquet inclut le script sgmlspl qui est également nécessaire.

LIMITATIONS

Essayer docbook2man sur du SGML non-DocBook ou non-conforme entraîne un comportement indéfini. :-)

Ce programme est un script Perl lent et douteux.

Ce programme ne prend pas en charge l'intégralité du balisage possible en DocBook et peut produire une sortie incorrecte dans certains cas avec le balisage pris en charge.

À FAIRE

•
Comment diable représente-t-on un backslash (\) en Texinfo !!@? J'ai essayé \\ mais TeX se plaint.
•
Corriger les erreurs trouvées dans les documents de test.
•
Ajouter la gestion de nouveaux éléments et corriger la gestion existante. Être robuste.
•
Le rendre plus rapide. Je pense que la plupart des problèmes de vitesse jusqu'à présent concernent l'analyse de l'ESIS. Réécrire SGMLS.pm en C et/ou obtenir les entrées directement de SP.
•
Il existe des dépendances sur des éléments qui se produisent alors qu'ils sont en fait optionnels (selon la DTD). Nous devons corriger cela (de préférence) ou indiquer clairement les exigences.
•
Autoriser d'autres éléments de document plus courants.
•
Séparer la référencement des nœuds dans un script distinct. Non seulement cela le rendrait plus rapide/plus facile à maintenir car il serait séparé du code principal, mais j'aimerais aussi qu'il évolue en un générateur de table des matières DocBook automatique.
