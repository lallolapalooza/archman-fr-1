DESCRIPTIO

N

Crée un nouveau réseau. Le DRIVER accepte bridge ou overlay qui sont les pilotes de réseau intégrés. Si vous avez installé un pilote de réseau tiers ou votre propre pilote personnalisé, vous pouvez spécifier ce DRIVER ici également. Si vous ne spécifiez pas l'option --driver, la commande crée automatiquement un réseau bridge pour vous. Lorsque vous installez Docker Engine, il crée un réseau bridge automatiquement. Ce réseau correspond au bridge docker0 sur lequel Engine s'est traditionnellement appuyé. Lorsque vous lancez un nouveau conteneur avec docker run, il se connecte automatiquement à ce réseau bridge. Vous ne pouvez pas supprimer ce réseau bridge par défaut, mais vous pouvez en créer de nouveaux en utilisant la commande network

create. 
$ docker network create -d bridge my-bridge-networ
k

Les réseaux bridge sont des réseaux isolés sur une seule installation d'Engine. Si vous souhaitez créer un réseau qui s'étend sur plusieurs hôtes Docker exécutant chacun un Engine, vous devez activer le mode Swarm et créer un réseau overlay. Pour en savoir plus sur les réseaux overlay avec le mode Swarm, voir « ⟨https://docs.docker.com/network/overlay/⟩ »

.

Une fois le mode swarm activé, vous pouvez créer un réseau overlay au périmètre du swarm

: 
$ docker network create --scope=swarm --attachable -d overlay my-multihost-networ
k

Par défaut, les réseaux au périmètre du swarm n'autorisent pas l'attachement de conteneurs démarrés manuellement. Cette restriction est ajoutée pour empêcher une personne ayant accès à un nœud non-manager dans le cluster swarm d'exécuter un conteneur capable d'accéder à la pile réseau d'un service

swarm.

L'option --attachable utilisée dans l'exemple ci-dessus désactive cette restriction et permet à la fois aux services swarm et aux conteneurs démarrés manuellement de s'attacher au réseau

overlay.

Les noms de réseau doivent être uniques. Le démon Docker tente d'identifier les conflits de noms, mais cela n'est pas garanti. Il incombe à l'utilisateur d'éviter les conflits de

noms.

Limites des réseaux

overlay

Vous devriez créer des réseaux overlay avec des blocs /24 (par défaut), ce qui vous limite à 256 adresses IP, lorsque vous créez des réseaux en utilisant le mode de point de terminaison VIP par défaut. Cette recommandation aborde les limitations du mode swarm ⟨https://github.com/moby/moby/issues/30820⟩. Si vous avez besoin de plus de 256 adresses IP, n'augmentez pas la taille du bloc IP. Vous pouvez soit utiliser le mode de point de terminaison dnsrr avec un équilibreur de charge externe, soit utiliser plusieurs réseaux overlay plus petits. Voir Configurer la découverte de services ⟨https://docs.docker.com/engine/swarm/networking/#configure-ser

vice-discovery⟩ pour plus d'
informations sur les différents
modes de point de terminaison.

Connecter des

conteneurs

Lorsque vous démarrez un conteneur, utilisez l'indicateur --network pour le connecter à un réseau. Cet exemple ajoute le conteneur busybox au réseau mynet

: 
$ docker run -itd --network=mynet
busybox

Si vous souhaitez ajouter un conteneur à un réseau après que le conteneur est déjà en cours d'exécution, utilisez le sous-commande docker network

connect.

Vous pouvez connecter plusieurs conteneurs au même réseau. Une fois connectés, les conteneurs peuvent communiquer en utilisant uniquement l'adresse IP ou le nom d'un autre conteneur. Pour les réseaux overlay ou les plugins personnalisés prenant en charge la connectivité multi-hôtes, les conteneurs connectés au même réseau multi-hôtes mais lancés depuis différents Engines peuvent également communiquer de cette

manière.

Vous pouvez déconnecter un conteneur d'un réseau en utilisant la commande docker network di

sconnect.

Spécifier des options

avancées

Lorsque vous créez un réseau, Engine crée par défaut un sous-réseau non superposé pour le réseau. Ce sous-réseau n'est pas une subdivision d'un réseau existant. Il est purement destiné à l'adressage IP. Vous pouvez remplacer ce comportement par défaut et spécifier directement les valeurs du sous-réseau en utilisant l'option --subnet. Sur un réseau bridge, vous ne pouvez créer qu'un seul sous-réseau

: 
$ docker network create --driver=bridge --subnet=192.168.0.0/16
br0

De plus, vous spécifiez également les options --gateway, --ip-range et --aux-address

. 
$ docker network create \
  --driver=bridge \
  --subnet=172.28.0.0/16 \
  --ip-range=172.28.5.0/24 \
  --gateway=172.28.5.254 \
br0

Si vous omettez l'indicateur --gateway, Engine en sélectionne un pour vous à partir d'un pool préféré. Pour les réseaux overlay et pour les plugins de pilote de réseau qui le prennent en charge, vous pouvez créer plusieurs sous-réseaux. Cet exemple utilise deux masques de sous-réseau /25 pour respecter la recommandation actuelle de ne pas avoir plus de 256 IP dans un seul réseau overlay. Chacun des sous-réseaux a 126 adresses

utilisables. 
$ docker network create -d overlay \
  --subnet=192.168.10.0/25 \
  --subnet=192.168.20.0/25 \
  --gateway=192.168.10.100 \
  --gateway=192.168.20.100 \
  --aux-address="my-router=192.168.10.5" --aux-address="my-switch=192.168.10.6" \
  --aux-address="my-printer=192.168.20.5" --aux-address="my-nas=192.168.20.6" \
  my-multihost-networ
k

Assurez-vous que vos sous-réseaux ne se chevauc

hent pas. S'ils se chevauchent, la création
du réseau échoue et Engine renvoie une erreur.

Mode interne du

réseau

Par défaut, lorsque vous connectez un conteneur à un réseau overlay, Docker connecte également un réseau bridge à celui-ci pour fournir une connectivité externe. Si vous souhaitez créer un réseau overlay isolé de l'extérieur, vous pouvez spécifier l'option --inte

rn
al.

Mode d'ingress

réseau

Vous pouvez créer le réseau qui sera utilisé pour fournir le routing-mesh dans le cluster swarm. Vous le faites en spécifiant --ingress lors de la création du réseau. Un seul réseau d'ingress peut être créé à la fois. Le réseau ne peut être supprimé que si aucun service n'en dépend. Toute option disponible lors de la création d'un réseau overlay est également disponible lors de la création du réseau d'ingress, en plus de l'option --attachable

. 
$ docker network create -d overlay \
  --subnet=10.11.0.0/16 \
  --ingress \
  --opt com.docker.network.driver.mtu=9216 \
  --opt encrypted=true \
  my-ingress-netwo
r
k

Exécuter des services sur des réseaux

prédéfinis

Vous pouvez créer des services sur les réseaux docker prédéfinis bridge et host

. 
$ docker service create --name
my-service \ --network host \
--replicas 2 \ busybox top

Réseaux swarm avec des pilotes de portée

locale

Vous pouvez créer un réseau swarm avec des pilotes réseau de portée locale. Vous le faites en promouvant la portée du réseau à swarm lors de la création du réseau. Vous pourrez ensuite utiliser ce réseau lors de la création de

services. 
$ docker network create -d bridge \
  --scope swarm \
  --attachable \
swarm-network

Pour les pilotes réseau qui fournissent une connectivité entre hôtes (ex. macvlan), si des configurations spécifiques au nœud sont nécessaires pour raccorder le réseau sur chaque hôte, vous fournirez cette configuration via un réseau de configuration uniquement. Lors de la création du réseau de portée swarm, vous spécifierez alors le nom du réseau qui contient la

configuration. 
node1$ docker network create --config-only --subnet 192.168.100.0/24 --gateway
192.168.100.115 mv-config node2$ docker network create --config-only --subnet
192.168.200.0/24 --gateway 192.168.200.202 mv-config node1$ docker network crea
te -d macvlan --scope swarm --config-from mv-config --attachable swarm-network
