-U
définir inpipe et outpipe pour un contrôle asynchrone de DOSEMU depuis un autre processus. Le format est (sans espace entre les deux)
inpipe:outpipe

où `:outpipe' peut être omis. Dans ce dernier cas, aucun retour de DOSEMU ne peut être attendu.

Pour des raisons de sécurité, DOSEMU ne crée pas les tubes nommés lui-même, l'utilisateur est donc responsable de la configuration correcte des permissions des tubes. Notez qu'en utilisant ces options, le processus externe peut contrôler votre session DOSEMU (par exemple, en simulant des frappes au clavier). Cette option ne doit donc être utilisée que par des interfaces (comme kdos), qui créent d'abord les tubes nommés appropriés, puis lancent DOSEMU. Une commande de contrôle spéciale ( ack on ) peut être utilisée pour forcer DOSEMU à renvoyer des balises de synchronisation via `outpipe' afin que l'interface sache quand la commande de contrôle a commencé ou s'est terminée et si elle a réussi. Le format de cette balisage est

SYN: <nom_commande>
<toute sortie de la commande>
ACK: code=n

où n est 0 en cas de succès. Un petit terminal de contrôle, qui peut servir d'exemple, est le programme dosctrl fourni. Il prend simplement les deux tubes comme arguments et vous pouvez ensuite entrer des commandes de contrôle, dont `help' est la plus importante ;-). Notez que dosctrl ne lance pas DOSEMU, vous devez le faire vous-même.

-V

DISQUES DURS

DOSEMU prend en charge quatre méthodes pour fournir à DOS des disques durs :

1.
un fichier disque virtuel résidant sur un système de fichiers Linux qui émule un disque dur.
2.
un accès direct à une partition DOS via un périphérique disque brut (c'est-à-dire /dev/hda, /dev/hdb, /dev/sdX).
3.
un accès direct à une partition DOS via un accès à une partition unique (c'est-à-dire /dev/hda1, /dev/hdb2, /dev/sdxx).
4.
un accès à un système de fichiers Linux comme lecteur "réseau" en utilisant le pilote emufs.sys fourni avec DOSEMU dans commands/emufs.sys ou ldir.exe.

La configuration des ressources de disque dur de DOSEMU se fait en éditant dosemu.conf ou .dosemurc avant d'exécuter DOSEMU. Consultez /usr/share/doc/dosemu/README.txt.

DISQUES SOUPLES

DOSEMU prend en charge deux méthodes pour fournir à DOS des disques souples :

1.
un fichier disque virtuel résidant sur un système de fichiers Linux qui émule un lecteur de disquette
2.
un accès direct à une disquette physique via un périphérique disque brut (c'est-à-dire /dev/fd0, /dev/fd1).

Ceci est également expliqué plus en détail dans README.txt.

La configuration des ressources de disque souple de DOSEMU se fait en éditant le fichier dosemu.conf avant d'exécuter DOSEMU.

VIDÉO

DOSEMU peut être exécuté sur n'importe quel périphérique tty. Cependant, des performances et des fonctionnalités accrues peuvent être obtenues en tirant parti des caractéristiques spéciales de la console Linux. Ceux qui exécutent DOSEMU sur la console peuvent souhaiter examiner les commutateurs -c, -k, et -V, expliqués plus en détail dans README.txt. Il y a également une très brève documentation dans le fichier dosemu.conf, qui peut être édité selon vos besoins.

En bref, une utilisation correcte du périphérique console et des commutateurs correspondants permet à l'utilisateur de visualiser un programme DOS dans sa couleur et sa police d'origine, sans les problèmes périodiques de mise à jour de l'écran avec le code de sortie tty générique.

CLAVIER

Ceux qui utilisent DOSEMU sur la console Linux peuvent également souhaiter utiliser le support clavier BRUT. Ce mode de fonctionnement, sélectionné par le commutateur -k, offre à l'utilisateur l'accès à l'intégralité du clavier accessible sous DOS. Toute combinaison des touches ALT, CTRL et MAJ peut être utilisée pour générer les codes de touches étranges attendus par de nombreux programmes DOS.

IMPRESSION

Les services d'imprimante du BIOS sont émulés via les E/S de fichiers UNIX standard, à l'aide de fichiers temporaires qui sont ensuite mis en file d'attente périodiquement par LPR ou un autre client d'impression, tel que défini par $_printer_commands dans dosemu.conf.

MESSAGES DE DÉBOGAGE

Les messages de débogage peuvent être contrôlés soit à la ligne de commande, soit dans le fichier de configuration. Consultez la documentation du fichier config.dist inclus avec DOSEMU dans le sous-répertoire examples, pour les options de débogage. À la ligne de commande, vous pouvez spécifier quelles classes de messages vous souhaitez que dos autorise. La syntaxe est : DOSEMU prend une option "-D FLAGS", où FLAGS est une chaîne de lettres qui spécifie quelles options imprimer ou supprimer. DOSEMU analyse cette chaîne de gauche à droite.


+ active les options suivantes (état initial)
- désactive les options suivantes
a active/désactive toutes les options, en fonction du drapeau
0 désactive toutes les options
1-9 définit le niveau de débogage, plus il est élevé, plus il y a de sorties
# où # est une lettre de la liste des classes valides,
désactive/active cette option en fonction de l'état
+/-.

Classes de messages :


d disque R lecture disque W écriture disque
D int 21h C cdrom v vidéo
X support X k clavier i E/S port
s série m souris # interruptions par défaut
p imprimante g général c configuration
w avertissement h matériel I IPC
E EMS x XMS M DPMI
n réseau IPX P pilote Pkt S SON
r PIC T suivi E/S Z BIOS PCI
A pilote ASPI Q pilote mapping

Toutes les classes de débogage suivant un caractère +, jusqu'à un caractère -, seront activées (non supprimées). Celles suivant un caractère -, jusqu'à un caractère +, seront supprimées. Le caractère a agit comme une chaîne de toutes les classes de débogage possibles, donc +a active tous les messages de débogage, et -a désactive tous les messages de débogage. Les caractères 0 et 1-9 sont également spéciaux : 0 désactive tous les messages de débogage, et 1-9 active tous les messages de débogage, mais définit également le niveau de débogage.

Il y a un + implicite au début de la chaîne FLAGS. Certaines classes, comme les erreurs, ne peuvent pas être désactivées. Si vous n'avez pas redirigé stderr, presque toutes les sorties vers stderr vont vers /dev/null.

Quelques exemples :
"-D+a-v" ou "-D1-v" : tous les messages sauf vidéo
"-D+kd" : par défaut + clavier et disque
"-D0+RW" : uniquement lecture et écriture disque

N'importe quelle lettre d'option peut apparaître n'importe où. Même les combinaisons inutiles, comme -D01-a-1+0, seront analysées sans erreur, alors soyez prudent. Certaines options sont définies par défaut, d'autres sont effacées. Ceci est sujet à mon bon vouloir et changera probablement entre les versions. Vous pouvez vous assurer de celles qui sont définies en les spécifiant toujours explicitement.

TOUCHE SPÉCIALES

En mode clavier BRUT (voir l'option -k), DOSEMU répond à certaines séquences de touches comme fonctions de contrôle.

ctrl-arrête défilement = affiche les vecteurs d'interruption 0x32
alt-arrête défilement = affiche les registres vm86
maj droite-arrête défilement = génère une int8 (minuteur)
maj gauche-arrête défilement = génère une int9 (clavier)
ctrl-pause = ctrl-pause comme sous DOS.
ctrl-alt-page haut = redémarre DOS. Ne vous fiez pas à cela !
ctrl-alt-page bas = quitte l'émulateur

Utilisez <CTRL GAUCHE>-<ALT GAUCHE>-<Touche fonction> pour basculer vers une autre console virtuelle.

MÉMOIRE

Le support mémoire XMS dans DOSEMU est conforme à la spécification mémoire étendue 3.0 de Lotus/Intel/Microsoft/AST. J'ai implémenté toutes les fonctions XMS à l'exception de la fonction 0x12 (Reallocate Upper Memory Block).

DOSEMU prend également en charge EMS 4.0 et implémente DPMI 0.9 (1.0 partiellement).

AUTEUR

DOSEMU (composé des fichiers dosemu.bin et dosemu) est basé sur la version 0.4 du programme original écrit par Matthias Lautner (je ne connais pas d'adresse actuelle).

Robert Sanders <gt8134b@prism.gatech.edu> maintenait et améliorait l'incarnation de DOSEMU avec laquelle cette page de manuel était initialement distribuée. Pendant environ 4 ans, James B. MacLean <macleajb@ednet.ns.ca> a été le chef infatigable de l'équipe dosemu, l'implémentation de DPMI (qui a permis de faire tourner Windows-3.1, dos4gw, djgpp, etc.) a eu lieu sous sa 'gouvernance' et a rapproché le projet de l'état Beta. Hans Lermen <lermen@fgan.de> a pris la relève et a publié la première version 1.0. Maintenant, Bart Oldeman <bart@dosemu.org> maintient ce logiciel amusant.
