-- Un ENTRYPOINT vous aide à configurer un
conteneur qui peut être exécuté comme un exécutable. Lorsque vous spécifiez un ENTRYPOINT,
tout le conteneur s'exécute comme s'il n'était que cet exécutable. L'instruction ENTRYPOINT
ajoute une commande d'entrée qui n'est pas écrasée lorsque des arguments sont passés à
docker run. C'est différent du comportement de CMD. Cela permet de passer des arguments à
l'entrypoint, par exemple docker run <image> -d passe l'argument -d à ENTRYPOINT. Spécifiez
les paramètres soit dans le tableau JSON de ENTRYPOINT (comme dans la forme exec préférée
ci-dessus), ou en utilisant une instruction CMD. Les paramètres dans le ENTRYPOINT ne
sont pas écrasés par les arguments de docker run. Les paramètres spécifiés via CMD sont
écrasés par les arguments de docker run. Spécifiez une chaîne de caractères simple
pour ENTRYPOINT, et elle sera exécutée dans /bin/sh -c, comme une instruction CMD :

ONBUILD [INSTRUCTION] L'instruction
O NBUILD ajoute une instruction de déclenchement à une image. Le déclenchement
est exécuté à un moment ultérieur, lorsque l'image est utilisée comme base pour une
autre construction. Docker exécute le déclenchement dans le contexte de la construction
en aval, comme si le déclenchement existait immédiatement après l'instruction FROM
dans le dDockerfile en

aval.

Vous pouvez enregistrer n'importe quelle instruction de construction comme déclencheur. Un déclencheur est utile si
vous définissez une image à utiliser comme base pour construire d'autres images. Par
exemple, si vous définissez un environnement de construction d'application ou un démon
personnalisé avec une configuration spécifique à

l'utilisateur.

Considérez une image destinée à être un constructeur d'applications python réutilisable. Elle doit
ajouter le code source de l'application à un répertoire particulier, et pourrait avoir besoin d'un script de construction
appelé après cela. Vous ne pouvez pas simplement appeler ADD et RUN maintenant,
car vous n'avez pas encore accès au code source de l'application, et il est différent
pour chaque construction

d'application.

-- Fournir aux développeurs d'applications un Dockerfile générique à copier-coller
dans leur application est inefficace, sujet aux erreurs, et
difficile à mettre à jour car il se mélange avec le code spécifique à l'application.
La solution est d'utiliser ONBUILD pour enregistrer les instructions à l'avance, pour
les exécuter plus tard

, lors de la prochaine
étape de construction.
