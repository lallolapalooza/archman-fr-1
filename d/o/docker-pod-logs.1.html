NOM

podman-pod-logs - Afficher les journaux pour un pod avec un ou plusieurs conteneurs

SYNOPSIS

podman pod logs [options] pod

DESCRIPTION

La commande podman pod logs récupère par lot tous les journaux présents pour tous les conteneurs d'un pod. Les journaux du pod peuvent être filtrés par nom ou identifiant de conteneur à l'aide de l'option -c ou --container si nécessaire.

Note : Une commande podman pod log longue avec l'option -f ou --follow doit être réinvoquée si un nouveau conteneur est ajouté dynamiquement au pod ; sinon, les journaux des conteneurs nouvellement ajoutés ne seront pas visibles dans le flux de journaux.

OPTIONS

--color

Afficher les conteneurs avec des couleurs différentes dans le journal.

--container, -c

Par défaut, podman pod logs récupère les journaux de tous les conteneurs disponibles dans le pod, différenciés par le champ container. Cependant, il existe des cas d'utilisation où l'utilisateur souhaite limiter le flux de journaux à un conteneur particulier d'un pod. Pour ces cas, -c peut être utilisé comme podman pod logs -c nomOuIdCtr nomOuIdPod.

--follow, -f

Suivre la sortie des journaux. Par défaut : false.

Note : Lors du suivi d'un pod supprimé par podman pod rm ou supprimé à la sortie (podman run --rm ...), il y a une chance que le fichier journal soit supprimé avant que podman pod logs ne lise le contenu final.

--latest, -l

Au lieu de fournir le nom ou l'identifiant du pod, utiliser le dernier pod créé. Note : le dernier pod démarré peut appartenir à d'autres utilisateurs de Podman sur la machine hôte. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exclusion de WSL2))

--names, -n

Afficher les noms des conteneurs au lieu de leurs identifiants dans le journal.

--since=TIMESTAMP

Afficher les journaux depuis TIMESTAMP. L'option --since peut être des horodatages Unix, des horodatages formatés par date, ou des chaînes de durée Go (par exemple, 10m, 1h30m) calculées par rapport à l'heure de la machine cliente. Les formats pris en charge pour les horodatages formatés par date incluent RFC3339Nano, RFC3339, 2006-01-02T15:04:05, 2006-01-02T15:04:05.999999999, 2006-01-02Z07:00, et 2006-01-02.

--tail=LIGNES

Afficher le nombre spécifié de LIGNES à la fin des journaux. LIGNES doit être un entier. Par défaut : -1, ce qui imprime toutes les lignes.

--timestamps, -t

Afficher les horodatages dans la sortie des journaux. Par défaut : false.

--until=TIMESTAMP

Afficher les journaux jusqu'à TIMESTAMP. L'option --until peut être des horodatages Unix, des horodatages formatés par date, ou des chaînes de durée Go (par exemple, 10m, 1h30m) calculées par rapport à l'heure de la machine cliente. Les formats pris en charge pour les horodatages formatés par date incluent RFC3339Nano, RFC3339, 2006-01-02T15:04:05, 2006-01-02T15:04:05.999999999, 2006-01-02Z07:00, et 2006-01-02.

EXEMPLE

Pour afficher les journaux d'un pod :

podman pod logs -t idOuNomPod

Pour afficher les journaux d'un conteneur spécifique dans le pod :

podman pod logs -c idOuNomCtr idOuNomPod

Pour afficher tous les journaux du pod :

podman pod logs -t --since 0 nom-de-mon-serveur-pod-1

Pour afficher les journaux d'un pod depuis une certaine heure :

podman pod logs -t --since 2017-08-07T10:10:09.055837383-04:00 nom-de-mon-serveur-pod-1

Pour afficher les journaux d'un pod générés au cours des 10 dernières minutes :

podman pod logs --since 10m nom-de-mon-serveur-pod-1

Pour afficher les journaux d'un pod jusqu'à il y a 30 minutes :

podman pod logs --until 30m nom-de-mon-serveur-pod-1
