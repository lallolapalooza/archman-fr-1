NOM

domain - Résolveur de domaine nnrpd

SYNTAXE

domain nom-de-domaine

DESCRIPTION

Ce programme peut être utilisé dans readers.conf pour accorder l'accès basé sur la partie sous-domaine du nom d'hôte distant. Plus précisément, il ne renvoie un succès que si le nom d'hôte distant se termine par nom-de-domaine. (Un point initial sur nom-de-domaine est facultatif ; même sans lui, l'argument doit correspondre aux limites séparées par des points). Le "nomdutilisateur" retourné est la partie initiale du nom d'hôte distant qui reste après la suppression de nom-de-domaine. C'est une erreur s'il n'y a pas de partie initiale (c'est-à-dire si le nom d'hôte distant est *exactement* le nom-de-domaine spécifié).

EXEMPLE

Le fragment readers.conf(5) suivant accorde l'accès aux hôtes ayant des noms de domaine internes :

auth internal {
    res: "domain .internal"
    default-domain: "example.com"
}
access internal {
    users: "*@example.com"
    newsgroups: example.*
}

L'accès est accordé aux groupes example.* pour toutes les connexions provenant d'hôtes qui se résolvent en noms d'hôtes se terminant par ".internal" ; une connexion depuis "foo.internal" correspondrait aux groupes d'accès en tant qu'identité "foo@example.com".

BOGUES

Il semble que le code ne confirme pas que la partie correspondante se trouve effectivement à la fin du nom d'hôte distant (par exemple, "domain: example.com" correspondrait à l'hôte distant "foo.example.com.org" en ignorant la partie finale ".org").

Ce résolveur fournit-il réellement une fonctionnalité utile qui n'est pas disponible en utilisant des jokers dans le paramètre hosts de readers.conf(5) ? Si c'est le cas, l'exemple ci-dessus devrait refléter cette fonctionnalité.
