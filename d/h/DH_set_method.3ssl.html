DH_set_method(3ssl)

Paquet: openssl

Licences: Apache-2.0

DH_SET_METHOD(3ssl) OpenSSL DH_SET_METHOD(3ssl)

NOM

DH_set_default_method, DH_get_default_method, DH_set_method, DH_new_method, DH_OpenSSL - sélectionner la méthode DH

SYNOPSIS

#include <openssl/dh.h>

Les fonctions suivantes ont été dépréciées depuis OpenSSL 3.0, et peuvent être entièrement masquées en définissant OPENSSL_API_COMPAT avec une valeur de version appropriée, voir openssl_user_macros(7).

void DH_set_default_method(const DH_METHOD *meth);
const DH_METHOD *DH_get_default_method(void);
int DH_set_method(DH *dh, const DH_METHOD *meth);
DH *DH_new_method(ENGINE *engine);
const DH_METHOD *DH_OpenSSL(void);

DESCRIPTION

Toutes les fonctions décrites dans cette page sont dépréciées. Les applications doivent plutôt utiliser les API de fournisseurs.

Une DH_METHOD spécifie les fonctions qu'OpenSSL utilise pour les opérations Diffie-Hellman. En modifiant la méthode, des implémentations alternatives telles que des accélérateurs matériels peuvent être utilisées. IMPORTANT : Voir la section NOTES pour des informations importantes sur la manière dont ces fonctions de l'API DH sont affectées par l'utilisation des appels de l'API ENGINE.

Initialement, la DH_METHOD par défaut est l'implémentation interne d'OpenSSL, telle que retournée par DH_OpenSSL().

DH_set_default_method() fait de meth la méthode par défaut pour toutes les structures DH créées ultérieurement. NB : Ceci est vrai uniquement tant qu'aucun ENGINE n'a été défini comme défaut pour DH, donc cette fonction n'est plus recommandée. Cette fonction n'est pas thread-safe et ne doit pas être appelée en même temps que d'autres fonctions OpenSSL.

DH_get_default_method() retourne un pointeur vers la DH_METHOD par défaut actuelle. Cependant, la signification de ce résultat dépend de l'usage ou non de l'API ENGINE, donc cette fonction n'est plus recommandée.

DH_set_method() sélectionne meth pour effectuer toutes les opérations utilisant la clé dh. Cela remplacera la DH_METHOD utilisée par la clé DH et si la méthode précédente était fournie par un ENGINE, le handle de cet ENGINE sera libéré lors du changement. Il est possible d'avoir des clés DH qui ne fonctionnent qu'avec certaines implémentations DH_METHOD (par exemple, provenant d'un module ENGINE qui prend en charge les clés protégées par matériel embarqué), et dans de tels cas, tenter de changer la DH_METHOD pour la clé peut avoir des résultats inattendus.

DH_new_method() alloue et initialise une structure DH de sorte que engine sera utilisé pour les opérations DH. Si engine est NULL, l'ENGINE par défaut pour les opérations DH est utilisé, et si aucun ENGINE par défaut n'est défini, la DH_METHOD contrôlée par DH_set_default_method() est utilisée.

Un nouvel objet DH_METHOD peut être construit en utilisant DH_meth_new() (voir DH_meth_new(3)).

VALEURS DE RETOUR

DH_OpenSSL() et DH_get_default_method() retournent des pointeurs vers les DH_METHODs respectives.

DH_set_default_method() ne retourne aucune valeur.

DH_set_method() retourne une valeur non nulle si le meth fourni a été défini avec succès comme méthode pour dh (y compris le déchargement du handle ENGINE si la méthode précédente était fournie par un ENGINE).

DH_new_method() retourne NULL et définit un code d'erreur qui peut être obtenu par ERR_get_error(3) si l'allocation échoue. Sinon, il retourne un pointeur vers la structure nouvellement allouée.

VOIR AUSSI

DH_new(3), DH_new(3), DH_meth_new(3)
