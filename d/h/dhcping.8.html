dhcping(8) Manuel des commandes générales dhcping(8)

NOM

dhcping - envoyer une requête DHCP au serveur DHCP pour vérifier s'il est opérationnel

SYNTAXE

dhcping [-v] [-q] [-i] [-r] -t maxwait -c adresse-IP-client -s adresse-IP-serveur -h adresse-MAC-client [-g adresse-IP-passerelle]

DESCRIPTION

Cette commande permet à l'administrateur système de vérifier si un serveur DHCP distant fonctionne toujours.

Les options sont :

-v
Verbeux, affiche certaines informations.
-i
Utiliser des paquets DHCPINFORM.
-r
Utiliser des paquets DHCPREQUEST (comportement par défaut).
-q
Silencieux, n'affiche rien à l'écran.
-t maxwait
Temps maximum d'attente d'une réponse du serveur en secondes. Par défaut, 3 secondes.
-c adresse-IP-client
Requiert cette adresse IP. Notez que c'est aussi l'adresse IP à laquelle la réponse sera envoyée.
-s adresse-IP-serveur
Envoie le paquet DHCP à cette adresse IP.
-h adresse-MAC-client
Utilise cette adresse MAC dans la requête DHCP. Elle peut comporter jusqu'à seize octets séparés par des deux-points (par exemple, 01:02:03:04).
-g adresse-IP-passerelle
Utilise cette adresse IP comme adresse IP de passerelle dans le paquet DHCP. Cette option est actuellement défectueuse.

VALEURS DE RETOUR

Si tout s'est bien passé, retourne 0. S'il y a eu un problème, retourne 1.

CONFIGURATION

Ce programme doit être installé avec les droits setuid root ou exécuté uniquement par root. Voir SECURITE pour plus d'informations.

Sur votre serveur DHCP, ajoutez ces lignes au fichier dhcpd.conf :

host <nom-de-domaine-qualifie-de-votre-hote-de-surveillance> {
   hardware ethernet <adresse-MAC-de-votre-hote-de-surveillance>;
   fixed-address     <adresse-IP-de-votre-hote-de-surveillance>;
}
Puis essayez :

$ dhcping -c adresse-IP-de-votre-hote-de-surveillance \
-s adresse-IP-de-votre-serveur-DHCP \
-h adresse-MAC-de-votre-hote-de-surveillance

Il répondra soit par "no answer" soit par "Got answer from: adresse-IP-de-votre-serveur-DHCP"

Le fichier journal du serveur DHCP indiquera :
DHCPREQUEST pour 192.168.1.1 de 00:20:18:56:29:8f via ed0
DHCPACK sur 192.168.1.1 pour 00:20:18:56:29:8f via ed0
DHCPRELEASE de 192.168.1.1 de 00:20:18:56:29:8f via ed0 (trouvé)

En mode DHCPINFORM avec -i :

Si vous voyez "DHCPINFORM from 192.168.1.1 via xl0: not authoritative for subnet 192.168.1.0", vous devriez ajouter l'instruction authoritative au sous-réseau. Voir dhcpd.conf(5) pour les détails.

Lorsqu'il est exécuté en mode très verbeux, dhcping tente d'afficher toutes les données des paquets DHCP envoyés et reçus. Il affichera d'abord le paquet au format hexadécimal, puis décodera l'en-tête et enfin les options.

COMMENT IL FONCTIONNE

Le client envoie soit un paquet DHCPREQUEST soit un paquet DHCPINFORM au serveur et attend une réponse. Ensuite, si un DHCPREQUEST a été envoyé, il renverra un DHCPRELEASE au serveur.

SÉCURITÉ

Ce programme est installé setuid root car il nécessite les privilèges pour se lier au port 68 (bootpc). Les privilèges root sont abandonnés dès que le programme s'est lié à ce port.

BOGUES

Actuellement (cela peut changer ou non à l'avenir), le démon DHCP de l'ISC n'écrit pas les baux avec une adresse IP fixe dans le fichier dhcpd.leases.

Les paquets DHCPINFORM ne peuvent être utilisés que sur les sous-réseaux pour lesquels le serveur est faisant autorité. Si le script de surveillance s'exécute sur un sous-réseau pour lequel le serveur n'est pas faisant autorité, il devrait utiliser les paquets DHCPREQUEST. J'ai également rencontré des problèmes avec les serveurs ISC DHCPD v2, mais cela est également mentionné dans le README.

L'option -V fonctionne toujours, mais ne devrait pas être utilisée pour le débogage des paquets. Il est préférable d'utiliser dhcpdump(8) pour cela, qui est disponible sur mon site Web. Je voulais la supprimer, mais j'ai décidé de ne le faire que dans la documentation, pas dans le code. Peut-être que j'en aurai besoin un jour pour le débogage.
