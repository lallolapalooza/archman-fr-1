DESCRIPTIO

N

Le client et le serveur DHCP de l'Internet Systems Consortium fournissent tous deux la po

ssibilité d'effectuer un comportement conditionnel en fonction du contenu des paquets qu'
ils reçoivent. La syntaxe pour spécifier ce comportement conditionnel est documentée ici.

RÉFÉRENCE : COMPORTEMENT

CONDITIONNEL

Le comportement conditionnel peut être spécifié à l'aide de l'instruction if et des instructions else ou elsif, ou des instructions switch et case. Une instruction conditionnelle peut apparaître n'importe où une instruction normale (par exemple, une instruction option) peut apparaître, et peut englober une ou plusieurs de ces

instructions.

COMPORTEMENT CONDITIONNEL :

IF

Une instruction if conditionnelle typique dans un serveur pourrait être 

: 
if option dhcp-user-class = "accounting" {
  max-lease-time 17600;
  option domain-name "accounting.example.org";
  option domain-name-servers ns1.accounting.example.org,
			     ns2.accounting.example.org;
} elsif option dhcp-user-class = "sales" {
  max-lease-time 17600;
  option domain-name "sales.example.org";
  option domain-name-servers ns1.sales.example.org,
			     ns2.sales.example.org;
} elsif option dhcp-user-class = "engineering" {
  max-lease-time 17600;
  option domain-name "engineering.example.org";
  option domain-name-servers ns1.engineering.example.org,
			     ns2.engineering.example.org;
} else {
  max-lease-time 600;
  option domain-name "misc.example.org";
  option domain-name-servers ns1.misc.example.org,
			     ns2.misc.example.org;
}

Côté client, un exemple d'évaluation conditionnelle pourrait être 

: 
# example.org filtre le DNS sur son pare-feu, nous devons donc utiliser leurs serveurs DNS
# lorsque nous nous connectons à leur réseau.  Si nous ne sommes pas chez
# example.org, préférons notre propre serveur DNS.
if not option domain-name = "example.org" {
  prepend domain-name-servers 127.0.0.1;
}

L'instruction if et l'instruction de continuation elsif prennent toutes deux des expressions booléennes en arguments. C'est-à-dire qu'elles prennent des expressions qui, lorsqu'elles sont évaluées, produisent un résultat booléen. Si l'expression est évaluée à vrai, alors les instructions encadrées par des accolades suivant l'instruction if sont exécutées, et toutes les clauses elsif et else suivantes sont ignorées. Sinon, l'expression de chaque clause elsif suivante est vérifiée jusqu'à ce qu'une clause elsif soit rencontrée dont le test est évalué à vrai. Si une telle clause est trouvée, les instructions entre accolades qui la suivent sont exécutées, puis toutes les clauses elsif et else suivantes sont ignorées. Si toutes les clauses if et elsif sont vérifiées mais qu'aucune de leurs expressions n'est évaluée à vrai, alors s'il existe une clause else, les instructions encadrées par des accolades suivant le else sont évaluées. Les expressions booléennes évaluées à null sont considérées comme fausses dans les

conditionnels.

COMPORTEMENT CONDITIONNEL :

SWITCH

L'exemple ci-dessus peut également être réécrit à l'aide d'une construction

switch. 
switch (option dhcp-user-class) {
  case "accounting":
    max-lease-time 17600;
    option domain-name "accounting.example.org";
    option domain-name-servers ns1.accounting.example.org,
			       ns2.accounting.example.org;
  case "sales":
    max-lease-time 17600;
    option domain-name "sales.example.org";
    option domain-name-servers ns1.sales.example.org,
			       ns2.sales.example.org;
    break;
  case "engineering":
    max-lease-time 17600;
    option domain-name "engineering.example.org";
    option domain-name-servers ns1.engineering.example.org,
			       ns2.engineering.example.org;
    break;
  default:
    max-lease-time 600;
    option domain-name "misc.example.org";
    option domain-name-servers ns1.misc.example.org,
			       ns2.misc.example.org;
    break;
}

L'instruction switch et les instructions case peuvent être à la fois des expressions de données ou des expressions numériques. Dans une instruction switch, elles doivent toutes être du même type. Le serveur évalue l'expression de l'instruction switch, puis évalue les expressions des instructions case jusqu'à ce qu'il trouve une

correspondance.

S'il trouve une correspondance, il commence à exécuter les instructions de ce case jusqu'à l'instruction

break suivante. S'il ne trouve pas de correspondance, il commence à l'instruction default et procède de
nouveau jusqu'à l'instruction break suivante. S'il n'y a ni correspondance ni default, il ne fait rien.

EXPRESSIONS

BOOLÉENNES

Voici la liste actuelle des expressions booléennes prises en charge par la distribution

DHCP.

data-expression-1 = data-expression-

2

L'opérateur = compare les valeurs de deux expressions de données, renvoyant vrai si elles sont identiques, faux

si elles ne le sont pas. Si le côté gauche ou le cô
té droit est null, le résultat est également null.

data-expression-1 ~= data-expression-2 data-expression-1 ~~ data-expression-

2

Les opérateurs ~= et ~~ (non disponibles sur tous les systèmes) effectuent une correspondance regex(7) étendue des valeurs de deux expressions de données, renvoyant vrai si data-expression-1 correspond à l'expression régulière évaluée par data-expression-2, ou faux si elle ne correspond pas ou rencontre une erreur. Si le côté gauche ou le côté droit est null ou une chaîne vide, le résultat est également faux. L'opérateur ~~ diffère de l'opérateur ~= en ce qu'il ne tient

pas compte
de la casse.

boolean-expression-1 and boolean-expression-

2
L'opérateur and est évalué à vrai si l'expression booléenne du côté gauche et l'expression booléenne du côté droit sont toutes deux évaluées à vrai. Sinon, il est évalué à faux. Si l'expression du côté gauche ou l'expression du côté droit est null, le résultat est
null.

boolean-expression-1 or boolean-expression-

2
L'opérateur or est évalué à vrai si l'expression booléenne du côté gauche ou l'expression booléenne du côté droit est évaluée à vrai. Sinon, il est évalué à faux. Si l'expression du côté gauche ou l'expression du côté droit est null, le résultat est
null.

not boolean-expressio

n
L'opérateur not est évalué à vrai si boolean-expression est évalué à faux, et renvoie faux si boolean-expression est évalué à vrai. Si boolean-expression est évalué à null, le résultat est également
null.

exists option-nam

e
L'expression exists renvoie vrai si l'option spécifiée existe dans le paquet DHCP entrant en cours de
traitement. known
L'expression known renvoie vrai si le client dont la requête est en cours de traitement est connu, c'est-à-dire s'il existe une déclaration de hôte pour
lui. static
L'expression static renvoie vrai si le bail attribué au client dont la requête est
en cours de traitement est dérivé d'
une attribution d'adresse statique.

EXPRESSIONS DE

DONNÉES

Plusieurs des expressions booléennes ci-dessus dépendent des résultats de l'évaluation d'expressions de données. Une liste de ces expressions est fournie

ici.

substring (data-expr, offset, length

)
L'opérateur substring évalue l'expression de données et renvoie la sous-chaîne du résultat de cette évaluation qui commence à offset octets du début, et se poursuit sur length octets. Offset et length sont tous deux des expressions numériques. Si data-expr, offset ou length est évalué à null, alors le résultat est également null. Si offset est supérieur ou égal à la longueur des données évaluées, une chaîne de données de longueur nulle est renvoyée. Si length est supérieur à la longueur restante des données évaluées après offset, une chaîne de données contenant toutes les données de offset jusqu'à la fin des données évaluées est
renvoyée.

suffix (data-expr, length

)
L'opérateur suffix évalue data-expr et renvoie les derniers length octets du résultat de cette évaluation. Length est une expression numérique. Si data-expr ou length est évalué à null, alors le résultat est également null. Si suffix est évalué à un nombre supérieur à la longueur de les données évaluées, alors les données évaluées sont
retournées.

lcase (data-expr

)
La fonction lcase retourne le résultat de l'évaluation de data-expr converti en minuscules. Si data-expr évalue à null, alors le résultat est également
null.

ucase (data-expr

)
La fonction ucase retourne le résultat de l'évaluation de data-expr converti en majuscules. Si data-expr évalue à null, alors le résultat est également
null.

option option-nam

e
L' opérateur option retourne le contenu de l'option spécifiée dans le paquet auquel le serveur
répond.

config-option option-nam

e
L' opérateur config-option retourne la valeur de l'option spécifiée que le client ou le serveur DHCP a été configuré pour
envoyer.

gethostname(

)
La fonction gethostname() retourne une chaîne de données dont le contenu est une chaîne de caractères, les résultats de l'appel à gethostname() sur le système local avec une limite de taille de 255 octets (non compris le terminateur NULL). Cela peut être utilisé par exemple pour configurer dhclient afin d'envoyer le nom d'hôte local sans connaître le nom d'hôte local au moment où dhclient.conf est
écrit.

hardwar

e
L' opérateur hardware retourne une chaîne de données dont le premier élément est le type d'interface réseau indiqué dans le paquet en cours d'examen, et dont les éléments suivants sont l'adresse de couche liaison du client. S'il n'y a pas de paquet, ou si le champ hlen de la RFC2131 est invalide, alors le résultat est null. Les types de matériel incluent ethernet (1), token-ring (6), et fddi (8). Les types de matériel sont spécifiés par l'IETF, et les détails sur la façon dont les numéros de type sont définis se trouvent dans la RFC2131 (dans la distribution ISC DHCP, cela est inclus dans le sous-répertoire doc/)
.

packet (offset, length

)
L' opérateur packet retourne la portion spécifiée du paquet en cours d'examen, ou null dans les contextes où aucun paquet n'est en cours d'examen. Offset et length sont appliqués au contenu du paquet comme dans l' opérateur sub
string.

chaîn

e
Une chaîne, entourée de guillemets, peut être spécifiée comme une expression de données, et retourne le texte entre les guillemets, encodé en ASCII. Le caractère backslash ('\') est traité de manière spéciale, comme en programmation C : '\t' signifie TAB, '\r' signifie retour chariot, '\n' signifie nouvelle ligne, et '\b' signifie cloche. Toute valeur octale peut être spécifiée avec '\nnn', où nnn est un nombre octal positif inférieur à 0400. Toute valeur hexadécimale peut être spécifiée avec '\xnn', où nn est un nombre hexadécimal positif inférieur ou égal à
0xff.

liste hexadécimale séparée par des

deux-points
Une liste de valeurs octales hexadécimales, séparées par des deux-points, peut être spécifiée comme une expression de
données.

concat (data-expr1, ..., data-exprN

)
Les expressions sont évaluées, et les résultats de chaque évaluation sont concaténés dans la séquence dans laquelle les sous-expressions sont listées. Si une sous-expression évalue à null, le résultat de la concaténation est
null.

reverse (numeric-expr1, data-expr2

)
Les deux expressions sont évaluées, puis le résultat de l'évaluation de l'expression de données est inversé sur place, en utilisant des blocs de la taille spécifiée dans l'expression numérique. Par exemple, si l'expression numérique évalue à quatre, et que l'expression de données évalue à douze octets de données, alors l'expression reverse évaluera à douze octets de données, constitués des quatre derniers octets des données d'entrée, suivis des quatre octets du milieu, suivis des quatre premiers
octets.

leased-addres

s
Dans tout contexte où le client dont la requête est en cours de traitement s'est vu attribuer une adresse IP, cette expression de données retourne cette adresse IP. Dans tout contexte où le client dont la requête est en cours de traitement ne s'est pas vu attribuer une adresse ip, si cette expression de données se trouve dans des instructions exécutables exécutées au nom de ce client, un message de journalisation indiquant « there is no lease associated with this client » est journalisé via syslog au niveau de débogage (cela est considéré comme une information de débogage de dhcpd.conf)
.

binary-to-ascii (numeric-expr1, numeric-expr2, data-expr1, data-expr2

)
Convertit le résultat de l'évaluation de data-expr2 en une chaîne de texte contenant un nombre pour chaque élément du résultat de l'évaluation de data-expr2. Chaque nombre est séparé des autres par le résultat de l'évaluation de data-expr1. Le résultat de l'évaluation de numeric-expr1 spécifie la base (2 à 16) dans laquelle les nombres doivent être convertis. Le résultat de l'évaluation de numeric-expr2 spécifie la largeur en bits de chaque nombre, qui peut être soit 8, 16 ou 32.

Comme exemple des trois types d'expressions précédents, pour p

roduire le nom d'un enregistrement PTR pour l'adresse IP étant as
signée à un client, on pourrait écrire l'expression suivante : 
        concat (binary-to-ascii (10, 8, ".",
                                 reverse (1, leased-address)),
                ".in-addr.arpa.")
;

encode-int (numeric-expr, width

)
Numeric-expr est évalué et encodé comme une chaîne de données de la largeur spécifiée, dans l'ordre des octets réseau (l'octet le plus significatif d'abord). Si l'expression numérique évalue à la valeur null, le résultat est également
null.

pick-first-value (data-expr1 [ ... exprn ]

)
La fonction pick-first-value prend un nombre quelconque d'expressions de données comme arguments. Chaque expression est évaluée, en commençant par la première de la liste, jusqu'à ce qu'une expression soit trouvée qui n'évalue pas à une valeur null. Cette expression est retournée, et aucune des expressions suivantes n'est évaluée. Si toutes les expressions évaluent à une valeur null, la valeur null est
retournée.

host-decl-nam

e
La fonction host-decl-name retourne le nom de la déclaration d'hôte qui a correspo
ndu au client dont la requête est actuellement en cours de traitement, le cas éché
ant. Si aucune déclaration d'hôte n'a correspondu, le résultat est la valeur null.

EXPRESSIONS

NUMÉRIQUES

Les expressions numériques sont des expressions qui évaluent à un entier. En général, la taille maximale d'un tel entier ne doit pas être supposée être représentable en moins de 32 bits, mais la précision de tels entiers peut être supérieure à 32

bits.

En plus des opérateurs suivants, plusieurs fonctions mathématiques standard sont disponibles. Ce sont

: 
opération    symbole
addition            +
soustraction       -
division         /
multiplication       *
modulo        %
et binaire    &
ou binaire     |
ou exclusif binaire
^

extract-int (data-expr, width

)
L' opérateur extract-int extrait une valeur entière dans l'ordre des octets réseau à partir du résultat de l'évaluation de l'expression de données spécifiée. Width est la largeur en bits de l'entier à extraire. Actuellement, les seules largeurs prises en charge sont 8, 16 et 32. Si l'évaluation de l'expression de données ne fournit pas suffisamment de bits pour extraire un entier de la taille spécifiée, la valeur null est
retournée.

lease-tim

e
La durée du bail actuel - c'est-à-dire, la différence entre l'heure actuelle et l'heure à laquelle le bail
expire.

nombr

e
Tout nombre entre zéro et la taille maximale représentable peut être spécifié comme une expression
numérique.

client-stat

e
L'état actuel de l'instance client en cours de traitement. Cela n'est utile que dans les fichiers de configuration du client DHCP. Les valeurs possibles sont :
•
Booting - Le client DHCP est dans l'état INIT, et n'a pas encore d'adresse IP. Le prochain message transmis sera un DHCPDISCOVER, qui sera
diffusé.
•
Reboot - Le client DHCP est dans l'état INIT-REBOOT. Il a une adresse IP, mais ne l'utilise pas encore. Le prochain message à transmettre sera un DHCPREQUEST, qui sera diffusé. Si aucune réponse n'est reçue, le client se liera à son adresse et passera à l'état
BOUND.
•
Select - Le client DHCP est dans l'état SELECTING - il a reçu au moins un message DHCPOFFER, mais attend de voir s'il peut recevoir d'autres messages DHCPOFFER d'autres serveurs. Aucun message n'est envoyé dans l'état
SELECTING.
•
Request - Le client DHCP est dans l'état REQUESTING - il a reçu au moins un message DHCPOFFER, et a choisi celui qu'il demandera. Le prochain message à envoyer sera un message DHCPREQUEST, qui sera
diffusé.
•
Bound - Le client DHCP est dans l'état BOUND - il a une adresse IP. Aucun message n'est transmis dans cet
état.
•
Renew - Le client DHCP est dans l'état RENEWING - il a une adresse IP, et essaie de contacter le serveur pour la renouveler. Le prochain message à envoyer sera un message DHCPREQUEST, qui sera envoyé en unicast directement au
serveur.
•
Rebind - Le client DHCP est dans l'état REBI
NDING - il a une adresse IP, et essaie
de contacter n'importe quel serveur pour l
a renouveler. Le prochain message à envoyer
sera un DHCPREQUEST, qui sera diffusé.

RÉFÉRENCE : EXPRESSIONS

D'ACTION

log (priority, data-expr

)

Les instructions de journalisation peuvent être utilisées pour envoyer des informations aux canaux de journalisation standard. Une instruction de journalisation inclut une priorité optionnelle (fatal, error, info, ou debug), et une expression de

données.

Les instructions de journalisation ne prennent qu'un seul argument d'expression de données, donc si vous voulez sortir plusieurs valeurs de données, vous devrez utiliser l' opérateur concat p

our les co
ncaténer.

execute (command-path [, data-expr1, ... data-exprN])

;

L' instruction execute exécute une commande externe. Le premier argument est une chaîne littérale contenant le nom ou le chemin de la commande à exécuter. Les autres arguments, s'ils sont présents, sont soit des chaînes littérales soit des expressions de données qui évaluent à des chaînes de texte, à passer comme arguments de ligne de commande à la

commande.

execute est synchrone ; le programme se bloquera jusqu'à ce que la commande externe en cours d'exécution ait terminé. Veuillez noter qu'une exécution de programme longue (par exemple, dans un « on commit » dans dhcpd.conf) peutulte à une mauvaise performance et à des dépassements de délai. Seules les applications externes dont le temps d'exécution est très court conviennent à une

utilisation.

Transmettre des données fournies par l'utilisateur à une application externe peut être dangereux. Assurez-vous que l'application externe vérifie la validité des tampons d'entrée. Les caractères ASCII non imprimables seront convertis en échappements octaux du langage dhcpd.conf (« \nnn »), assurez-vous que votre commande externe les gère comme

tels.

Il est possible d'utiliser l'instruction execute dans n'importe quel contexte, pas se

ulement sur des événements. Si vous la placez dans une portée régulière du fichier de
configuration, vous exécuterez cette commande chaque fois qu'une portée est évaluée.

parse-vendor-option

;

L'instruction parse-vendor-option tente d'analyser une option fournisseur (code 43). Elle n'est utile que lors du traitement d'un paquet sur le serveur et nécessite que l'administrateur ait déjà utilisé l'instruction vendor-option-space pour sélectionner un espace fournisseur

valide.

Cette fonctionnalité peut être utilisée si le serveur doit prendre des actions différentes en

fonction des valeurs que le client a placées dans l'option fournisseur et que les sous-optio
ns ne sont pas à des emplacements fixes. Elle est traitée comme une action pour permettre à u
n administrateur d'examiner les options entrantes et de choisir l'espace fournisseur correct.
