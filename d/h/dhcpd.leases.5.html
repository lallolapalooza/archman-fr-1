4

lease ip-address { instructions... } Chaque déclaration de bail inclut l'adresse IP unique qui a été louée au client. Les instructions entre les accolades définissent la durée du bail et à qui il est

attribué. 
starts datee;
ends date;
tstp date;
tsfp date;
atsfp date;
cltt date;

L'heure de début et de fin d'un bail sont enregistrées à l'aide des instructions starts et ends. L'instruction tstp est présente si le protocole de basculement est utilisé, et indique à quelle heure le pair a été informé que le bail expire. L'instruction tsfp est également présente si le protocole de basculement est utilisé, et indique l'heure d'expiration du bail que le pair a reconnue. L'instruction atsfp est l'heure réelle envoyée par le partenaire de basculement. L'instruction cltt est l'heure de la dernière transaction du client.

Voir la description des dates dans la section sur les structures communes.

hardware type-matériel adresse-mac;

L'instruction matérielle enregistre l'adresse MAC de l'interface réseau sur laquelle le bail sera utilisé. Elle est spécifiée sous forme d'une série d'octets hexadécimaux, séparés par des deux-points.

uid identifiant-client;

L'instruction uid enregistre l'identifiant client utilisé par le client pour acquérir le bail. Les clients ne sont pas tenus d'envoyer des identifiants clients, et cette instruction n'apparaît que si le client en a effectivement envoyé un. Les identifiants clients sont normalement un type ARP (1 pour ethernet) suivi de l'adresse MAC, tout comme dans l'instruction hardware, mais ce n'est pas obligatoire.

L'identifiant client est enregistré sous forme de liste hexadécimale séparée par des deux-points ou sous forme de chaîne entre guillemets. S'il est enregistré sous forme de chaîne entre guillemets et qu'il contient un ou plusieurs caractères non imprimables, ces caractères sont représentés par des échappements octaux : un caractère d'antislash suivi de trois chiffres octaux. Le format utilisé est déterminé par le paramètre lease-id-format, qui est par défaut octal.

client-hostname nom-hôte ;

La plupart des clients DHCP envoient leur nom d'hôte dans l'option host-name. Si un client envoie son nom d'hôte de cette manière, le nom d'hôte est enregistré dans le bail avec une instruction client-hostname. Ce n'est cependant pas requis par le protocole, donc de nombreux clients DHCP spécialisés n'envoient pas d'option nom d'hôte.

binding state état;
next binding state état;

L'instruction binding state déclare l'état de liaison du bail. Lorsque le serveur DHCP n'est pas configuré pour utiliser le protocole de basculement, l'état de liaison d'un bail peut être active, free ou abandoned. Le protocole de basculement ajoute quelques états de transition supplémentaires, ainsi que l'état backup, qui indique que le bail est disponible pour allocation par le secondaire de basculement. Veuillez consulter la page de manuel de dhcpd.conf(5) pour plus d'informations sur les baux abandonnés.

L'instruction next binding state indique dans quel état le bail passera lorsque l'état actuel expirera. L'heure à laquelle l'état actuel expire est spécifiée dans l'instruction ends.

rewind binding state état;

Cette instruction fait partie d'une optimisation pour une utilisation avec le basculement. Elle aide un serveur à rembobiner un bail vers l'état le plus récemment transmis à son pair.

option agent.circuit-id chaîne;
option agent.remote-id chaîne;

Ces instructions sont utilisées pour enregistrer les options de l'identifiant de circuit et de l'identifiant distant envoyées par l'agent de relais, si l'agent de relais utilise l'option d'informations de l'agent de relais. Cela permet d'utiliser ces options de manière cohérente dans les évaluations conditionnelles, même lorsque le client contacte directement le serveur plutôt que par son agent de relais.

La variable vendor-class-identifier

Le serveur conserve l'option Vendor Class Identifier fournie par le client à des fins d'information et pour les restituer dans les réponses DHCPLEASEQUERY.

bootp;
reserved;

Si présents, ils indiquent que les indicateurs de basculement BOOTP et RESERVED (respectivement) doivent être définis. Les baux dynamiques BOOTP et RESERVED sont traités différemment des baux dynamiques normaux, car ils ne peuvent être utilisés que par le client auquel ils sont actuellement attribués.

LA DECLARATION DU BAIL DHCPv6 (IA)

ia_ta  IAID_DUID { instructions... }
ia_na  IAID_DUID { instructions... }
ia_pd  IAID_DUID { instructions... }

Chaque déclaration de bail commence par une balise indiquant le type de bail. ia_ta est pour les adresses temporaires, ia_na est pour les adresses non temporaires et ia_pd est pour la délégation de préfixe. Après cette balise se trouve l'IAID et le DUID combinés du client pour ce bail.

La valeur IAID_DUID est enregistrée sous forme de liste hexadécimale séparée par des deux-points ou sous forme de chaîne entre guillemets. Si elle est enregistrée sous forme de chaîne entre guillemets et qu'elle contient un ou plusieurs caractères non imprimables, ces caractères sont représentés par des échappements octaux : un caractère d'antislash suivi de trois chiffres octaux. Le format utilisé est régi par le paramètre lease-id-format, qui est par défaut octal.

cltt date;

L'instruction cltt est l'heure de la dernière transaction du client.

LA DECLARATION DU ETAT DU PAIR DE BASCULEMENT

L'état de tout arrangement de paires de basculement est également enregistré dans le fichier de bail, en utilisant l'instruction failover peer :

failover peer nom state {
my state état at date;
peer state état at date;
}

L'état du pair nommé nom est enregistré. L'état du serveur en cours d'exécution (my state) et celui de l'autre partenaire de basculement (peer state) sont enregistrés. Les états suivants sont possibles : unknown-state, partner-down, normal, communications-interrupted, resolution-interrupted, potential-conflict, recover, recover-done, shutdown, paused, et startup.
