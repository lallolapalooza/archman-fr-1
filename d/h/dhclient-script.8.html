NOM

dhclient-script - Script de configuration réseau du client DHCP

DESCRIPTION

Le script de configuration réseau du client DHCP est invoqué de temps à autre par dhclient(8). Ce script est utilisé par le client dhcp pour définir la configuration initiale de chaque interface avant de demander une adresse, pour tester l'adresse une fois qu'elle a été proposée, et pour définir la configuration finale de l'interface une fois qu'un bail a été acquis. Si aucun bail n'est acquis, le script est utilisé pour tester les bails prédéfinis, le cas échéant, et est également appelé une fois si aucun bail valide ne peut être identifié.

Ce script n'est pas destiné à être personnalisé par l'utilisateur final. Si des personnalisations locales sont nécessaires, elles doivent être possibles à l'aide des crochets (hooks) d'entrée et de sortie fournis (voir HOOKS pour plus de détails). Ces crochets permettront à l'utilisateur de remplacer le comportement par défaut du client lors de la création d'un /etc/resolv.conf .

Aucun script client standard n'existe pour certains systèmes d'exploitation, même si le client réel peut fonctionner ; un utilisateur pionnier devra donc peut-être créer un nouveau script ou en modifier un existant. En général, les personnalisations spécifiques à un ordinateur particulier doivent être effectuées dans le fichier ETCDIR/dhclient.conf . Si vous constatez que vous ne pouvez pas effectuer une telle personnalisation sans personnaliser ETCDIR/dhclient.conf ou sans utiliser les crochets d'entrée et de sortie, veuillez soumettre un rapport de bogue.

CROCHETS (HOOKS)

Au démarrage, le script client définit d'abord une fonction de shell, make_resolv_conf , qui est ensuite utilisée pour créer le fichier /etc/resolv.conf . Pour remplacer le comportement par défaut, redéfinissez cette fonction dans le script de crochet d'entrée.

Après avoir défini la fonction make_resolv_conf, le script client vérifie la présence d'un script exécutable ETCDIR/dhclient-enter-hooks et, s'il est présent, il invoque le script en ligne, en utilisant la commande `.` du shell Bourne. Tout l'environnement documenté sous OPÉRATION est disponible pour ce script, qui peut modifier l'environnement si nécessaire pour changer le comportement du script. Si une erreur se produit lors de l'exécution du script, il peut définir la variable exit_status à une valeur non nulle, et CLIENTBINDIR/dhclient-script se terminera avec ce code d'erreur immédiatement après la sortie du script client.

Une fois tout le traitement terminé, CLIENTBINDIR/dhclient-script vérifie la présence d'un script exécutable ETCDIR/dhclient-exit-hooks qui, s'il est présent, est invoqué à l'aide de la commande `.`. Le code de sortie de dhclient-script sera transmis à dhclient-exit-hooks dans la variable de shell exit_status, et sera toujours zéro si le script a réussi la tâche pour laquelle il a été invoqué. Le reste de l'environnement, comme décrit précédemment pour dhclient-enter-hooks, est également présent. Le script ETCDIR/dhclient-exit-hooks peut modifier la valeur de exit_status pour changer le code de sortie de dhclient-script.

OPÉRATION

Lorsque dhclient doit invoquer le script de configuration du client, il définit un ensemble de variables dans l'environnement, puis invoque CLIENTBINDIR/dhclient-script. Dans tous les cas, $reason est défini sur le nom de la raison pour laquelle le script a été invoqué. Les raisons suivantes sont actuellement définies : MEDIUM, PREINIT, BOUND, RENEW, REBIND, REBOOT, EXPIRE, FAIL, STOP, RELEASE, NBI et TIMEOUT.

MEDIUM

Le client DHCP demande que le type de média d'une interface soit défini. Le nom de l'interface est passé dans $interface, et le type de média est passé dans $medium.

PREINIT

Le client DHCP demande qu'une interface soit configurée comme requis afin d'envoyer des paquets avant de recevoir une adresse réelle. Pour les clients qui utilisent la bibliothèque de sockets BSD, cela signifie configurer l'interface avec une adresse IP de 0.0.0.0 et une adresse de diffusion de 255.255.255.255. Pour d'autres clients, il peut être possible de simplement configurer l'interface sans lui attribuer d'adresse IP du tout. Le nom de l'interface est passé dans $interface, et le type de média dans $medium.

Si un alias IP a été déclaré dans dhclient.conf, son adresse sera passée dans $alias_ip_address, et cet alias ip doit être supprimé de l'interface, ainsi que toutes les routes vers celui-ci.

BOUND

Le client DHCP a effectué une liaison initiale avec une nouvelle adresse. La nouvelle adresse ip est passée dans $new_ip_address, et le nom de l'interface est passé dans $interface. Le type de média est passé dans $medium. Toutes les options acquises auprès du serveur sont passées en utilisant le nom d'option décrit dans dhcp-options, sauf que les tirets (`-`) sont remplacés par des underscores (`_`) afin de créer des variables de shell valides, et que les noms de variables commencent par new_. Par exemple, le nouveau masque de sous-réseau serait passé dans $new_subnet_mask. Les options provenant d'un univers non par défaut auront le nom de l'univers préfixé au nom de l'option, par exemple $new_dhcp6_server_id. Les options que le client a explicitement demandées via une option PRL ou ORO sont passées avec le même nom d'option que ci-dessus mais préfixé par requested_ et avec une valeur de 1, par exemple requested_subnet_mask=1. Aucune variable de ce type n'est définie pour les options non demandées par le client ou les options qui ne nécessitent pas d'option de demande, comme l'adresse ip (*_ip_address) ou le temps d'expiration (*_expiry).

Avant de configurer réellement l'adresse, dhclient-script devrait effectuer un ARP pour celle-ci et se terminer avec un statut non nul s'il reçoit une réponse. Dans ce cas, le client enverra un message DHCPDECLINE au serveur et acquerra une autre adresse. Cela peut également être fait dans les états RENEW, REBIND ou REBOOT, mais ce n'est pas requis et peut en fait ne pas être souhaitable.

Lorsqu'une liaison a été effectuée, de nombreux paramètres réseau devront probablement être configurés. Un nouveau /etc/resolv.conf doit être créé, en utilisant les valeurs de $new_domain_name et $new_domain_name_servers (qui peuvent lister plus d'un serveur, séparés par des espaces). Une route par défaut doit être définie à l'aide de $new_routers, et des routes statiques peuvent nécessiter d'être configurées à l'aide de $new_static_routes.

Si un alias IP a été déclaré, il doit être configuré ici. L'adresse IP de l'alias sera écrite dans $alias_ip_address, et les autres options DHCP définies pour l'alias (par exemple, le masque de sous-réseau) seront passées dans des variables nommées comme décrit précédemment mais commençant par $alias_ au lieu de $new_. Il faut veiller à ne pas utiliser l'adresse IP de l'alias si elle est identique à l'adresse IP liée ($new_ip_address), car les autres paramètres de l'alias peuvent être incorrects dans ce cas.

RENEW

Lorsqu'une liaison a été renouvelée, le script est appelé comme dans BOUND, sauf qu'en plus de toutes les variables commençant par $new_ et $requested_, il existe un autre ensemble de variables commençant par $old_. Les paramètres persistants qui ont pu changer doivent être supprimés - par exemple, si une route locale vers l'adresse liée est configurée, l'ancienne route locale doit être supprimée. Si la route par défaut a changé, l'ancienne route par défaut doit être supprimée. Si les routes statiques ont changé, les anciennes doivent être supprimées. Sinon, le traitement peut être effectué comme avec BOUND.

REBIND

Le client DHCP s'est relié à un nouveau serveur DHCP. Cela peut être géré comme avec RENEW, sauf que si l'adresse IP a changé, la table ARP doit être vidée.

REBOOT

Le client DHCP a réussi à réacquérir son ancienne adresse après un redémarrage. Cela peut être traité comme avec BOUND.

EXPIRE

Le client DHCP n'a pas réussi à renouveler son bail ou à en acquérir un nouveau, et le bail a expiré. L'adresse IP doit être libérée, et tous les paramètres associés doivent être supprimés, comme dans RENEW et REBIND.

FAIL

Le client DHCP n'a pas pu contacter de serveurs DHCP, et aucun des bails testés ne s'est avéré valide. Les paramètres du dernier bail testé doivent être déconfigurés. Cela peut être géré de la même manière que EXPIRE.

STOP

Le dhclient a été informé de s'arrêter proprement, le dhclient-scriptpt devrait déconfigurer ou arrêter l'interface de manière appropriée.

RELEASE

Le dhclient a été exécuté avec le drapeau -r, indiquant que l'administrateur souhaite qu'il libère son/ses bail(s). dhclient-script devrait déconfigurer ou arrêter l'interface.

NBI

No-Broadcast-Interfaces... dhclient n'a pas pu trouver d'interfaces sur lesquelles il pensait devoir démarrer le DHCP. Ce que dhclient-script doit faire dans cette situation dépend entièrement de l'implémenteur.

TIMEOUT

Le client DHCP n'a pas pu contacter de serveurs DHCP. Cependant, un ancien bail a été identifié et ses paramètres ont été transmis comme avec BOUND. Le script de configuration du client devrait tester ces paramètres et, s'il a des raisons de croire qu'ils sont valides, il devrait se terminer avec une valeur de zéro. Sinon, il devrait se terminer avec une valeur non nulle.

V6ONLY

Le client DHCPv4 a reçu une option préférée valide v6-only. Le système devrait désactiver l'IPv4 sur l'interface. De son côté, le dhclient attend V6ONLY_WAIT secondes (le minuteur est transporté par l'option avec un minimum de MIN_V6ONLY_WAIT) avant de retourner à l'état INIT.

La manière habituelle de tester un bail est de configurer le réseau comme avec REBIND (puisque cela peut être appelé pour tester plus d'un bail) puis de pinger le premier routeur défini dans $routers. Si une réponse est reçue, le bail doit être valide pour le réseau auquel l'interface est actuellement connectée. Il serait plus complet d'essayer de pinger tous les routeurs listés dans $new_routers, ainsi que ceux listés dans $new_static_routes, mais les scripts actuels ne le font pas.

FILES

Chaque système d'exploitation devrait généralement avoir son propre fichier de script, bien que les fichiers de script pour des systèmes d'exploitation similaires puissent être similaires voire identiques. Les fichiers de script inclus dans la distribution DHCP d'Internet Systems Consortium apparaissent dans l'arbre de distribution sous client/scripts, et portent les noms des systèmes d'exploitation sur lesquels ils sont destinés à fonctionner.

BUGS

Si plus d'une interface est utilisée, il n'y a aucun moyen évident d'éviter les conflits entre les paramètres de configuration fournis par le serveur - par exemple, le script dhclient standard réécrit /etc/resolv.conf. Si plus d'une interface est configurée, /etc/resolv.conf sera initialisé de manière répétée avec les valeurs fournies par un serveur, puis par l'autre. En supposant que les informations fournies par les deux serveurs sont valides, cela ne devrait pas causer de problèmes réels, mais cela pourrait être déroutant.
