DESCRIPTION

L'ensemble des fonctions dhcpctl fournit une API qui peut être utilisée pour communiquer avec et manipuler un serveur DHCP ISC en cours d'exécution. Toutes les fonctions retournent une valeur de type isc_result_t. Les valeurs de retour reflètent le résultat des opérations sur les structures de données locales. Si une opération échoue sur le serveur pour une raison quelconque, alors le résultat d'erreur sera retourné via le second paramètre de l'appel dhcpctl_wait_for_completion().

dhcpctl_initialize() initialise les structures de données dont la bibliothèque a besoin pour fonctionner. Cette fonction doit être appelée une fois avant toute autre.

dhcpctl_connect() ouvre une connexion au serveur DHCP à l'hôte et au port spécifiés. Si un authentificateur a été créé pour la connexion, il est passé comme 4ème argument. En cas de succès, l'adresse pointée par le premier argument aura un nouveau objet de connexion qui lui sera attribué.

Par exemple :

s = dhcpctl_connect(&cxn, "127.0.0.1", 7911, NULL);

se connecte au serveur DHCP sur la machine locale via le port 7911 (le port OMAPI standard). Aucune authentification n'est utilisée pour la connexion.

dhcpctl_timed_connect() ouvre une connexion au serveur DHCP à l'hôte et au port spécifiés. Si un authentificateur a été créé pour la connexion, il est passé comme 4ème argument. En cas de succès, l'adresse pointée par le premier argument aura un nouveau objet de connexion qui lui sera attribué. La durée pendant laquelle la fonction attend que la connexion soit établie est dictée par la valeur du paramètre timeout. Si la valeur est nulle, elle attendra indéfiniment. Sinon, elle attendra le temps spécifié par timeout (tv_sec:tv_usec). Des valeurs nulles pour les deux champs sont valides mais déconseillées. Un exemple est montré ci-dessous :

Par exemple :

struct timeval timeout;
timeout.tv_sec = 5;   /* attendre 5 secondes */
timeout.tv_usec = 0;

s = dhcpctl_connect(&cxn, "127.0.0.1", 7911, NULL, &timeout);

se connecte au serveur DHCP sur la machine locale via le port 7911 (le port OMAPI standard). Aucune authentification n'est utilisée pour la connexion. Elle autorise 5 secondes pour que la connexion aboutisse.

dhcpctl_disconnect() ferme la connexion ouverte spécifiée par le premier paramètre, cxn. Notez que cet appel libérera l'objet de connexion et cxn sera mis à nul. Si le second paramètre, force, est non nul, la connexion sera fermée immédiatement. Sinon, l'extrémité réceptrice sera arrêtée mais toutes les données non envoyées seront envoyées avant de réellement fermer le socket. Notez que la déconnexion détruit uniquement l'objet de connexion, tous les autres objets précédemment créés existeront toujours.

Par exemple :

s = dhcpctl_disconnect(&cxn, 1);

fermera la connexion immédiatement. Cette fonction doit être considérée comme EXPÉRIMENTALE.

dhcpctl_timed_wait_for_completion() envoie un message en attente au serveur et attend la réponse. La durée pendant laquelle la fonction attend une réponse est déterminée par la valeur du troisième paramètre, timeout. Si la valeur est nulle, elle attendra indéfiniment ou jusqu'à ce que la connexion soit perdue. Sinon, elle attendra pendant la durée spécifiée par timeout (tv_sec:tv_usec). Des valeurs de zéro pour les deux champs sont valides mais non recommandées. Le résultat de la demande tel que traité sur le serveur est renvoyé via le second paramètre. Un exemple est montré ci-dessous

struct timeval timeout;
timeout.tv_sec = 5;   /* wait for 5 seconds */
timeout.tv_usec = 0;

s = dhcpctl_wait_for_completion(cxn, &wv, &timeout);
if (s != ISC_R_SUCCESS) {
	local_failure(s);
} else if (wv != ISC_R_SUCCESS) {

Veuillez noter que même si la fonction ne attend plus de réponse, le serveur n'abandonne pas la demande et peut toujours répondre en écrivant la réponse sur le socket. Un appel ultérieur à cette fonction ou à dhcpctl_wait_for_completion() verra ces données et les lira. Selon la logique de flux de l'application, cela peut être souhaité ou non. Actuellement, cependant, le seul mécanisme pour « rincer » ces données est de fermer la connexion en appelant disconnet(), puis en se reconnectant via connect(). Veuillez noter que cette fonction doit être considérée comme EXPÉRIMENTALE

dhcpctl_get_value() extrait la valeur d'un attribut du handle. La valeur peut être de n'importe quelle longueur et est traitée comme une séquence d'octets. Le handle doit avoir été créé au préalable avec dhcpctl_new_object() et ouvert avec dhcpctl_open_object(). La valeur est renvoyée via le paramètre nommé « value ». Le dernier paramètre est le nom de l'attribut à

récupérer. 
dhcpctl_data_string value = NULL;
dhcpctl_handle lease;
time_t thetime;

s
= dhcpctl_get_value (&value, lease, "ends"); assert(s == ISC_R_SUCCESS &&
value->len == sizeof(thetime)); memcpy(&thetime, value->value, value->len);

dhcpctl_get_boolean() extrait un attribut à valeur booléenne du handle de

l'objet.

Les dhcpctl_set_value(), dhcpctl_set_string_value(), dhcpctl_set_boolean_value(), et dhcpctl_set_int_value() définissent tous une valeur sur le handle de

l'objet.

dhcpctl_object_update() met en file d'attente une demande pour que toutes les modifications apportées au handle de l'objet soient envoyées au distant pour traitement. Les modifications apportées aux attributs sur le handle seront appliquées à l'objet distant si cela est

autorisé.

dhcpctl_object_refresh() met en file d'attente une demande pour qu'une copie à jour de toutes les valeurs d'attributs soit envoyée depuis le distant pour actualiser les valeurs dans le handle de l'objet

local.

dhcpctl_object_remove() met en file d'attente une demande pour la suppression sur le serveur de l'objet référencé par le

handle.

La dhcpctl_set_callback() définit une fonction définie par l'utilisateur à appeler lorsqu'un événement se termine sur le handle d'objet donné. Cela est nécessaire pour le traitement asynchrone des événements, par rapport au traitement synchrone donné par dhcpctl_wait_for_completion(). Lorsque la fonction est appelée, le premier paramètre est l'objet pour lequel l'événement est arrivé, le deuxième est le statut du message qui a été traité, le troisième est la même valeur que le second paramètre donné à dhcpctl_set_cal

lback().

La dhcpctl_new_authenticator() crée un nouvel objet authentificateur à utiliser pour signer les messages qui traversent le réseau. Les valeurs « name », « algorithm » et « secret » doivent toutes correspondre à ce que le serveur utilise et sont définies dans son fichier de configuration. L'objet créé est renvoyé via le premier paramètre et doit être utilisé comme 4ème paramètre pour dhcpctl_connect(). Notez que la valeur 'secret' ne doit pas être encodée en base64, ce qui est différent de l'apparence de la valeur dans le fichier dhcpd.

conf.

dhcpctl_new_object() crée un handle local pour un objet sur le serveur. Le paramètre « object_type » est le nom ascii du type d'objet auquel on accède. p. ex. "lease". Cette fonction ne fait que configurer les structures de données locales, elle ne met aucun message en file d'attente pour être envoyé au côté distant, dhcpctl_open_object() fait

cela.

EXEMPLE

S

Le programme suivant se connectera au serveur DHCP s'exécutant sur l'hôte local et récupérera les détails du bail existant pour l'adresse IP 10.0.0.101. Il affichera ensuite l'heure à laquelle le bail doit expirer. Notez que la plupart des vérifications d'erreur ont été omises par souci de

concision. 
#include <sys/time.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdarg.h>

#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>

#include "omapip/result.h"
#include "dhcpctl.h"

int main (int argc, char **argv) {
	dhcpctl_data_string ipaddrstring = NULL;
	dhcpctl_data_string value = NULL;
	dhcpctl_handle connection = NULL;
	dhcpctl_handle lease = NULL;
	isc_result_t waitstatus;
	struct in_addr convaddr;
	time_t thetime;

        dhcpctl_initialize ();

        dhcpctl_connect (&connection, "127.0.0.1",
			 7911, 0);

        dhcpctl_new_object (&lease, connection,
			    "lease");

        memset (&ipaddrstring, 0, sizeof
		ipaddrstring);

        inet_pton(AF_INET, "10.0.0.101",
		  &convaddr);

	omapi_data_string_new (&ipaddrstring,
			       4, MDL);
	memcpy(ipaddrstring->value, &convaddr.s_addr, 4);

	dhcpctl_set_value (lease, ipaddrstring,
			   "ip-address");

	dhcpctl_open_object (lease, connection, 0);

	dhcpctl_wait_for_completion (lease,
				     &waitstatus);
        if (waitstatus != ISC_R_SUCCESS) {
		/* server not authoritative */
		exit (0);
        }

	dhcpctl_data_string_dereference(&ipaddrstring,
					MDL);

        dhcpctl_get_value (&value, lease, "ends");

	memcpy(&thetime, value->value, value->len);

	dhcpctl_data_string_dereference(&value, MDL);

	fprintf (stdout, "ending time is %s",
		 ctime(&thetime))
;
}
