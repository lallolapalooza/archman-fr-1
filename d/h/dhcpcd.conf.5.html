Bien que dhcpcd puisse tout faire depuis la ligne de commande, il y a des cas où il est plus simple de le faire une seule fois dans un fichier de configuration. La plupart des options trouvées dans dhcpcd(8) peuvent être utilisées ici. Le premier mot de la ligne est l'option et le reste de la ligne est la valeur. Les espaces en début et en fin de l'option et de la valeur sont supprimés. Vous pouvez échapper les caractères dans la valeur en utilisant le caractère \. Les commentaires peuvent être préfixés par le caractère #. Les valeurs de chaîne doivent être entourées de guillemets (")

.

Demande un Préfixe Délégué DHCPv6 pour iaid. Cette option doit être utilisée dans un bloc interface. Sauf si un sla_id de 0 est assigné avec la même longueur de préfixe résultante que la délégation, une route de rejet est installée pour le Préfixe Délégué afin d'empêcher la résolution en amont des adresses non allouées. Si aucune interface n'est donnée, alors nous assignerons un préfixe à chaque autre interface avec un sla_id équivalent à l'index d'interface assigné par l'OS. Sinon, les adresses ne sont assignées que pour chaque interface et sla_id. Pour éviter de déléguer à une interface, utilisez - comme nom d'interface invalide. Chaque adresse assignée aura un suffix, par défaut 1. Si le suffix est 0, alors une adresse SLAAC est assignée. Vous ne pouvez pas assigner un préfixe à l'interface demandant sauf si le serveur DHCPv6 supporte l' RFC 6603 Prefix Exclude Option. dhcpcd doit être en cours d'exécution pour toutes les interfaces auxquelles il délègue. Un prefix_len par défaut de 64 est supposé, sauf si le sla_id maximum ne tient pas. Dans ce cas, le prefix_len est augmenté au multiple de 8 le plus élevé pouvant accueillir le sla_id. sla_id est un entier qui doit être unique à l'intérieur du iaid et est ajouté au préfixe qui doit tenir à l'intérieur du prefix_len moins la longueur du préfixe délégué. Vous pouvez spécifier plusieurs interface / sla_id / prefix_len par ia_pd, séparés par des espaces. IPv6RS devrait être désactivé globalement lors de la demande d'une Délégation de Préfixe.

Dans l'exemple suivant, eth0 est l'interface externe à configurer pour IPv4 et IPv6. Le serveur DHCPv4 nous fournira une adresse IPv4 et une route par défaut. Le serveur DHCPv6 va nous fournir une adresse IPv6, une route par défaut et un sous-réseau /64 à déléguer à l'interface interne. L'interface eth1 sera automatiquement configurée pour IPv6 en utilisant la première adresse (::1) du préfixe délégué. Un second préfixe est demandé et assigné à deux autres interfaces. rtadvd(8) peut être utilisé avec un fichier de configuration vide sur eth1, eth2 et eth3, pour fournir la configuration automatique d'adresses IPv6 pour le réseau

interne.

denyinterfaces eth2      # Don't touch eth2 at all
interface eth0 ipv6rs # enable routing solicitation for eth0 ia_na 1 #
request an IPv6 address ia_pd 2 eth1/0 # request a PD and assign it to eth1 ia_pd 3 eth2/1 eth
3/2 # req a PD and assign it to eth2 and eth3 ia_pd 4 - # request a PD but don't assign it

option option
Demande l'option du serveur. Il peut s'agir d'une variable à utiliser dans dhcpcd-run-hooks(8) ou de sa valeur numérique. Vous pouvez spécifier plusieurs options séparées par des virgules, des espaces ou plusieurs lignes option. Ajoutez dhcp6_ devant l'option pour demander une option DHCPv6. Si aucune option DHCPv6 n'est configurée, les options DHCPv4 sont mappées à des options DHCPv6 équivalentes.

Ajoutez nd_ devant l'option pour gérer les options ND, mais cela ne fonctionne que pour les options nooption, reject et require.

Pour voir la liste des options disponibles, appelez dhcpcd avec l'argument -V, --variables.

nooption option
Supprime l'option du message avant qu'il ne soit traité.
require option
Exige que l'option soit présente dans tous les messages, sinon le message est ignoré. Pour s'assurer que dhcpcd ne répond qu'aux serveurs DHCP et non aux serveurs BOOTP, vous pouvez require dhcp_message_type. Cependant, ce n'est pas une science exacte car un serveur BOOTP peut envoyer des options similaires à DHCP.
reject option
Rejette un message qui contient l'option. Ceci est utile lorsque vous ne pouvez pas utiliser require pour sélectionner / désélectionner les messages BOOTP.
destination option
Si dhcpcd.conf détecte une adresse ajoutée à une interface point à point (PPP, TUN, etc.), il définira les options DHCP listées à l'adresse de destination de l'interface.
profile nom
Les options suivantes ne seront analysées que pour ce profil nom.
quiet
Supprime toute sortie de dhcpcd sur la console, sauf les erreurs.
reboot secondes
Autorise reboot secondes avant de passer à la phase DISCOVER si nous avons un ancien bail à utiliser. Autorise reboot secondes avant de démarrer les états de secours à partir de la phase DISCOVER. IPv4LL est démarré lorsque le premier délai reboot est atteint. La valeur par défaut est de 5 secondes. Un réglage de 0 seconde provoque dhcpcd.conf à sauter la phase de redémarrage et à passer directement à DISCOVER. Ceci est souhaitable pour les utilisateurs mobiles car si vous passez du réseau A au réseau B et qu'ils utilisent le même sous-réseau et que l'adresse du réseau A n'est pas utilisée sur le réseau B, alors le serveur DHCP restera silencieux même s'il est autoritaire, ce qui signifie que dhcpcd expirera avant de revenir à la phase DISCOVER. Ceci n'a aucun effet sur DHCPv6, à l'exception du saut de la phase de redémarrage.

Utilise script au lieu du script par défaut /usr/lib/dhcpcd/dhcpcd-run-hooks.

Sélectionne l'identifiant d'interface utilisé pour les adresses IPv6 générées par SLAAC. Si private est utilisé, une adresse RFC 7217 est générée. static value
Configure une valeur statique value. Si vous définissez ip_address, alors dhcpcd ne tentera pas d'obtenir un bail et utilisera simplement la valeur pour l'adresse avec une durée de bail infinie. Si vous définissez une valeur vide, cela supprime toutes les allocations statiques antérieures pour la même valeur. Ceci est utile lors de l'utilisation de profils et dans le cas de ip_address, cela supprimera l'allocation statique. Notez que la définition de 0.0.0.0 conserve l'allocation statique mais attend qu'un tiers configure l'adresse. Si vous définissez ip6_address, dhcpcd continuera la configuration automatique comme d'habitude.

timeout seconds
Temps d'attente après seconds, au lieu des 30 par défaut. Un paramètre de 0 seconds fait que dhcpcd attend indéfiniment pour obtenir un bail. Si dhcpcd travaille sur une seule interface, dhcpcd se terminera lorsqu'un délai d'attente se produira, sinon dhcpcd passera en arrière-plan. Si vous utilisez IPv4LL, dhcpcd démarrera le processus IPv4LL après le délai d'attente et attendra ensuite un peu plus longtemps avant de réellement expirer.
userclass string
Étiquette le message DHCPv4 avec la classe d'utilisateur. Vous pouvez en spécifier plusieurs.
msuserclass string
Étiquette le message DHCPv4 avec la classe d'utilisateur Microsoft. Contrairement à l'option userclass, celle-ci ne peut être ajoutée qu'une seule fois. Elle ne doit être utilisée que pour les serveurs DHCP Microsoft et vendorclassid doit être défini sur "MSFT 98" ou "MSFT 5.0". Cette option n'est pas conforme aux RFC.

Ajoute une option d'information spécifique au fournisseur encapsulée (Option DHCP 43). code doit être compris entre 1 et 254 inclus. Pour ajouter une chaîne de fournisseur brute, omettez code mais conservez la virgule. Exemples.

Définit l'option fournisseur 01 avec une adresse IP.

vendor 01,192.168.0.2
Définit l'option fournisseur 02 avec un code hexadécimal.
vendor 02,01:02:03:04:05
Définit l'option fournisseur 03 avec une adresse IP sous forme de chaîne.
vendor 03,"192.168.0.2"
Définit une option fournisseur non encapsulée sur "hello world".
vendor ,"hello world"
vsio en code,value
Ajoute une option d'information spécifique au fournisseur encapsulée (Option DHCP 125) avec le numéro d'entreprise attribué par l'IANA en, suivi du code qui doit être compris entre 1 et 255 inclus, et de la value après la virgule. Exemples :

Définit le vsio pour le numéro d'entreprise 155, option 01, avec une adresse IPv4.

vsio 155 01,192.168.1.1
Définit le vsio pour le numéro d'entreprise 155, option 02, avec une chaîne.
vsio 155 02,"hello world"
Définit le vsio pour le numéro d'entreprise 255, option 01, avec un code hexadécimal.
vsio 255 01,01:02:03:04:05
vsio6 en code,value
Ajoute une option d'information spécifique au fournisseur encapsulée (Option DHCPv6 17) avec le numéro d'entreprise attribué par l'IANA en, suivi du code qui doit être compris entre 1 et 65535 inclus, et de la value après la virgule. Exemples :

Définit le vsio pour le numéro d'entreprise 155, option 01, avec une adresse IPv6.

vsio6 155 01,2001:0db8:85a3:0000:0000:8a2e:0370:7334
Définit le vsio pour le numéro d'entreprise 155, option 02, avec une chaîne.
vsio6 155 02,"hello world"
Définit le vsio pour le numéro d'entreprise 255, option 01, avec un code hexadécimal.
vsio6 255 01,01:02:03:04:05
vendorclassid string
Définit la classe d'utilisateur du vendeur DHCP. DHCPv6 possède sa propre option comme indiqué ci-dessous. La valeur par défaut est dhcpcd-<version>:<os>:<machine>:<platform>. Par exemple
dhcpcd-5.5.6:NetBSD-6.99.5:i386:i386
Si elle n'est pas définie, aucune n'est envoyée. Certains serveurs DHCP mal configurés rejettent les vendorclassid inconnus. Pour contourner ce problème, essayez d'imiter Windows en utilisant le MSFT vendorclassid.
vendclass en data
Ajoute la classe d'identification du vendeur DHCPv6 avec le numéro d'entreprise attribué par l'IANA en avec les data. Cette option peut être définie plusieurs fois pour ajouter plus de données, mais le comportement, conformément à la RFC 3925, est indéfini si le numéro d'entreprise diffère.
waitip [4 | 6]
Attend qu'une adresse soit attribuée avant de passer en arrière-plan. 4 signifie attendre qu'une adresse IPv4 soit attribuée. 6 signifie attendre qu'une adresse IPv6 soit attribuée. Si aucun argument n'est donné, dhcpcd.conf attendra qu'un protocole d'adresse quelconque soit attribué. Il est possible d'attendre plusieurs protocoles d'adresse et dhcpcd.conf ne passera en arrière-plan que lorsque toutes les conditions d'attente seront satisfaites.
xidhwaddr
Utilise les quatre derniers octets de l'adresse matérielle comme xid DHCP au lieu d'un nombre généré aléatoirement.

Définition de nouvelles options

DHCP, ND et DHCPv6 permettent l'utilisation d'options personnalisées, et les options de fournisseur RFC 3925 pour DHCP peuvent également être fournies. Chaque option doit commencer par la directive define, definend, define6 ou vendopt. Ceci peut éventuellement être suivi des options embed ou encap. Les deux peuvent être spécifiés plus d'une fois et embed doit précéder encap.

define code type variable
Définit l'option DHCP code de type type avec un nom variable exporté vers dhcpcd-run-hooks(8).
definend code type variable
Définit l'option ND code de type type avec un nom variable exporté vers dhcpcd-run-hooks(8), avec un préfixe de nd_.
define6 code type variable
Définit l'option DHCPv6 code de type type avec un nom variable exporté vers dhcpcd-run-hooks(8), avec un préfixe de dhcp6_.
vendopt code type variable
Définit les options de fournisseur identifiant le fournisseur (Vendor-Identifying Vendor Options). Le code est le numéro d'entreprise IANA qui décrira de manière unique les options encapsulées. type est normalement encap. variable nomme l'option fournisseur à exporter.
embed type variable
Définit une variable embarquée au sein de l'option définie. La longueur est déterminée par le type. Si la variable n'est pas la même que celle définie dans l'option parente, elle est préfixée par la variable parente, précédée d'un trait de soulignement. Si la variable a le nom de reserved, elle n'est pas traitée.
encap code type variable
Définit une variable encapsulée au sein de l'option définie. La longueur est déterminée par le type. Si la variable n'est pas la même que celle définie dans l'option parente, elle est préfixée par la variable parente, précédée d'un trait de soulignement.

Préfixe de type

Ces mots-clés précèdent le type lui-même, pour le décrire plus complètement. Vous pouvez en utiliser plusieurs, mais ils doivent apparaître dans l'ordre indiqué ci-dessous.

request
Demande l'option par défaut sans avoir à la spécifier dans la configuration utilisateur.
norequest
Cette option ne peut pas être demandée, quelle que soit la configuration utilisateur.
optional
Cette option est optionnelle. N'a de sens que pour les options embarquées comme l'option FQDN du client, où la chaîne FQDN elle-même est optionnelle.
index
L'option peut apparaître plus d'une fois et sera indexée.
array
Les données de l'option sont divisées en un tableau séparé par des espaces, chaque élément étant du même type.
truncated
L'option peut être tronquée par rapport à sa longueur normale. La fin de la taille normale est complétée par des zéros lors de l'expansion. Actuellement, cela n'est pris en charge que pour les `ip6address` où il s'agit d'un préfixe.

Types à définir

Le type affecte directement la quantité de données consommées dans l'option. Les données restantes sont normalement ignorées. Des longueurs peuvent être spécifiées pour les types chaîne et binhex, mais c'est généralement avec d'autres données intégrées ensuite dans la même option.

ipaddress
Une adresse IPv4, 4 octets.
ip6address
Une adresse IPv6, 16 octets.
string [: length]
Une chaîne ASCII NVT de caractères imprimables.
byte
Un octet.
bitflags: flags
Un octet représenté comme une chaîne de drapeaux, le bit le plus significatif en premier. Par exemple, en utilisant ABCDEFGH, A serait égal à 10000000, B 01000000, C 00100000, etc. Si le bit n'est pas défini, le drapeau n'est pas imprimé. Un drapeau de 0 n'est pas imprimé même si la position du bit est définie. Ceci permet de réserver les premiers bits tout en attribuant les derniers bits. Un drapeau de 1 imprime le bit défini ou non défini.
int16
Un entier signé de 16 bits, 2 octets.
uint16
Un entier non signé de 16 bits, 2 octets.
int32
Un entier signé de 32 bits, 4 octets.
uint32
Un entier non signé de 32 bits, 4 octets.
flag
Une valeur fixe (1) pour indiquer que l'option est présente, 0 octet.
domain
Une chaîne encodée selon RFC 3397.
dname
Une chaîne validée selon RFC 1035.
uri
S'il s'agit d'un tableau, les deux premiers octets représentent la longueur de l'URI dans les données de l'option. Sinon, toutes les données de l'option constituent l'URI. Comme l'espace n'est pas autorisé dans le codage URI, les URI sont séparés par des espaces.
binhex [: length]
Données binaires exprimées en hexadécimal.
embed
Contient des options embarquées (implique également `encap`).
encap
Contient des options encapsulées (implique également `embed`).
option
Fait référence à une option définie globalement.

Exemple de définition

# Option DHCP 81, Nom de domaine complètement qualifié, RFC 4702
define 81 embed fqdn
embed byte flags
embed byte rcode1
embed byte rcode2
embed domain fqdn
# Option DHCP 125, Option d'informations spécifiques au vendeur, RFC 3925
define 125 encap vsio
embed uint32 enterprise_number
# Options définies pour le numéro d'entreprise
encap 1 ipaddress ipaddress

Protocoles d'authentification pris en charge

token
Envoie un jeton en texte clair que le serveur attend et qui correspond à un jeton envoyé par le serveur. Les jetons n'ont pas besoin d'être identiques. Si non spécifié, le jeton avec un secretid de 0 sera utilisé pour envoyer des messages et valider les messages reçus.
delayedrealm
Authentification retardée. dhcpcd enverra une option d'authentification sans clé ni MAC. Le serveur verra cette option et sélectionnera une clé pour dhcpcd.conf, en y écrivant le realm et le secretid. dhcpcd recherchera ensuite un jeton non expiré avec un realm et un secretid correspondants. Ce jeton est utilisé pour authentifier tous les autres messages.
delayed
Identique à ce qui précède, mais sans royaume.

Si aucun n'est spécifié, monotonic est le défaut. Si cela est modifié par rapport à ce qui était utilisé précédemment, ou si le moyen de le calculer ou de le stocker est défectueux, le serveur DHCP devra probablement avoir sa notion de la valeur de détection de rejeu du client réinitialisée.
