DESCRIPTIO

N

Un langage de programmation est composé de syntaxe et de sémantique. La sémantique de Fennel ne diffère de celle de Lua que de petites manières (toutes indiquées ci-dessous). La syntaxe de Fennel provient de la famille de langages lisp. Les lisps ont une syntaxe très uniforme et prévisible, ce qui facilite le codage qui opère sur du code ainsi que l'édition structurée

.

Si vous connaissez déjà Lua et un lisp, vous vous sentirez tout à fait à l'aise dans Fennel. Même si ce n'est pas le cas, Lua est l'un des langages de programmation les plus simples qui existent, donc si vous avez déjà programmé, vous devriez pouvoir le prendre en main sans trop de difficultés, surtout si vous avez utilisé un autre langage impératif à typage dynamique avec des fermetures. Le manuel de référence de Lua est un bon endroit pour trouver les détails, mais la Primer Lua de Fennel est plus courte et couvre

l'essentiel.

Si vous avez déjà du code d'exemple en Lua et que vous voulez juste voir à quoi il ressemblerait en Fennel, vous pouvez apprendre beaucoup en le mettant dans antifenne

l
.

Fonctions et

lambdas

Utilisez fn pour créer des fonctions. Si vous fournissez un nom facultatif, la fonction sera liée à ce nom dans la portée locale ; sinon, c'est simplement une valeur

anonyme.

Une brève note sur les noms : les identifiants sont généralement en minuscules séparés par des tirets (aussi appelé « kebab-case »). Ils peuvent contenir des chiffres aussi, tant qu'ils ne sont pas au début. Vous pouvez aussi utiliser le point d'interrogation (généralement pour les fonctions qui renvoient un vrai ou un faux, ex., at-max-velocity?). Les tirets bas (_) sont souvent utilisés pour nommer une varia

La liste d'arguments est fournie entre crochets. La dernière valeur du corps est

renvoyée.

(Si vous n'avez jamais utilisé de lisp auparavant, la principale chose à noter est que la fonction ou la macro appelée va à l'intérieur des parenthèses, pas à l'extérieur.

Les fonctions peuvent prendre une docstring facultative sous la forme d'une chaîne qui suit immédiatement la liste d'arguments. En compilation normale, celle-ci est retirée du Lua émis, mais pendant le développement dans la REPL, la docstring et l'utilisation de la fonction peuvent être consultées avec la commande ,doc

...) ;; Prints args as a string, delimited by sep

Comme d'autres lisps, Fennel utilise les points-virgules pour les

commentaires.

Les fonctions définies avec fn sont rapides ; elles n'ont aucun surcoût d'exécution par rapport à Lua. Cependant, elles n'ont pas non plus de vérification d'arité. (C'est-à-dire qu'appeler une fonction avec le mauvais nombre d'arguments ne provoque pas d'erreur.) Pour un code plus sûr, vous pouvez utiliser lambda qui garantit que vous recevrez au moins autant d'arguments que vous en définissez, sauf si vous indiquez qu'un d'eux peut être omis en commençant son nom par un ?

) z)))) (print-calculation 5)
; -> error: Missing argument z

Locaux et

variables

Les variables locales sont introduites avec let avec les noms et les valeurs enveloppés dans un seul ensemble de crochets

: 
(let [x (+ 89 5.2)
      f (fn [abc] (print (* 2 abc)))]
(f
x)
)

Ici x est lié au résultat de l'addition de 89 et 5.2, tandis que f est lié à une fonction qui affiche le double de son argument. Ces liaisons ne sont valides qu'à l'intérieur du corps de l'appel let. Toutes les valeurs sont à typage

dynamique.

Vous pouvez aussi introduire des locaux avec local, ce qui est pratique lorsqu'ils seront utilisés dans tout le fichier, mais en général let est préféré à l'intérieur des fonctions car c'est plus clair d'un coup d'œil où la valeur peut être utilisée

Les locaux définis de cette manière ne peuvent pas recevoir de nouvelles valeurs, mais vous pouvez introduire de nouveaux locaux qui masquent les noms externes

(let [x 19]
  ;; (set x 88)
<- not allowed! (let [x
88] (print (+ x 2))) ;
-> 90 (print x)) ; -> 19

Si vous devez changer la valeur d'un local, vous pouvez utiliser var qui fonctionne comme local sauf qu'il permet set de fonctionner dessus. Il n'existe pas d'équivalent imbriqué de type let pour var

Tables

Certaines tables sont utilisées pour stocker des données parcourues séquentiellement ; les clés dans ce cas sont simplement des nombres commençant à 1 et s'incrémentant. Fennel fournit une syntaxe alternative pour ces tables avec des crochets

La fonction table.insert intégrée à Lua est conçue pour être utilisée avec des tables séquentielles ; tous les éléments après la valeur insérée sont décalés d'un index : Si vous ne fournissez pas d'index à table.insert, elle ajoutera la valeur à la fin de la

table.

La fonction table.remove fonctionne de manière similaire ; elle prend une table et un index (qui par défaut est la fin de la table) et supprime la valeur à cet index, la

retournant. 
(local ltrs ["a" "b" "c" "d"])

(tab

à la fin (table.insert ltrs 1 "a") ; Ajoute "a" au début (. ltrs 2)
; -> "b" ;; ltrs est de retour à sa valeur initiale ["a" "b" "c" "d"]

La forme length retourne la longueur des tables séquentielles et des chaînes

(let [tbl ["abc" "def" "xyz"]]
  (+ (length tbl)

Notez que la longueur d'une table contenant des trous est indéfinie ; elle peut retourner un nombre correspondant à n'importe laquelle des positions "frontières" de la table entre nil et des valeurs

La bibliothèque standard de Lua est très petite, et ainsi plusieurs fonctions que vous pourriez vous attendre à voir incluses, comme map, reduce, et filter sont absentes. En Fennel, des macros sont utilisées à la place ; voir icollect, collect, et accumulat

Itératio

n

La boucle sur les éléments d'une table se fait avec each et un itérateur comme pairs (utilisé pour les tables générales) ou ipairs (pour les tables séquentielles)

(each [key value (pairs {"key1" 52
"key2" 99})] (print key value)) (
each [index value (ipairs ["abc" "d
ef" "xyz"])] (print index value))

Notez que le fait qu'une table soit séquentielle ou non n'est pas une propriété inhérente de la table mais dépend de l'itérateur utilisé avec elle. Vous pouvez appeler ipairs sur n'importe quelle table, et elle n'itérera que sur les clés numériques commençant à 1 jusqu'à ce qu'elle rencontre un nil

Vous pouvez utiliser n'importe quel itérateur Lua avec each, mais voici les plus courants. Voici un exemple qui parcourt les correspondances dans

Conditionnelle

s

Enfin, nous avons les conditionnelles. La forme if en Fennel peut être utilisée de la même manière que dans d'autres langages Lisp, mais elle peut aussi être utilisée comme cond pour plusieurs conditions compilées en branches elseif

(let [x (math.random 64)]

Avec un nombre impair d'arguments, la dernière clause est interprétée comme

En tant que Lisp, Fennel n'a pas d'instructions, donc if retourne une valeur comme expression. Les programmeurs Lua seront heureux de savoir qu'il n'est pas nécessaire de construire des chaînes précaires de and/or juste pour obtenir une valeur

GESTION DES

ERREURS

Les erreurs en Lua peuvent prendre deux formes. Les fonctions en Lua peuvent retourner un nombre quelconque de valeurs, et la plupart des fonctions qui peuvent échouer indiqueront l'échec en utilisant deux valeurs de retour : nil suivi d'un message d'échec sous forme de chaîne. Vous pouvez interagir avec ce style de fonction en Fennel en plaçant l'appel de fonction dans une table et en faisant du pattern matching sur la table

: 
(case [(io.open "file")]
  ;; quand io.open réussit, il retourne un fic
hier, mais s'il échoue ;; il retourne nil et une chaîne err-msg décri
vant pourquoi [f] (do (use-file-contents (f:read :*all)) (f
:close)) [nil err-msg] (report-error "Could not open file:" err-msg))

Vous pouvez écrire votre propre fonction qui retourne plusieurs valeurs en appelant values

. 
(fn use-file [filename]
  (if (valid-file-name? filename)
      (open-file filename)
      (values nil (.. "Invalid filename: " filename)
)
)
)

Note : tandis que les erreurs sont la raison la plus courante de retourner plusieurs valeurs d'une fonction, cela peut être utilisé dans d'autres cas également. C'est la fonctionnalité la plus complexe de Lua, et une discussion complète est hors du cadre de ce tutoriel, mais c'est https://benaiah.me/posts/everything-you-didnt-want-to-know-about-lua-multivals/ bien couvert

ailleurs.

Le problème avec ce type d'erreur est qu'il ne se compose pas bien ; le statut d'erreur doit être propagé tout au long de la chaîne d'appels de l'intérieur vers l'extérieur. Pour y remédier, vous pouvez utiliser error. Cela terminera tout le processus sauf s'il est dans un appel protégé, de manière similaire à la façon dont dans d'autres langages, lancer une exception arrêtera le programme s'il n'est pas dans un try/catch. Vous pouvez faire un appel protégé avec s="Li">pc

all : 
(let [(ok? val-or-msg) (pcall potentially
-disastrous-call filename)] (if ok?
(print "Got value" val-or-msg) (p
rint "Could not get value:" val-or-msg)))

L'invocation pcall signifie que vous exécutez en mode protégé (potentially-disastrous-call filename). pcall prend un nombre arbitraire d'arguments qui sont transmis à la fonction. On peut voir que pcall renvoie un booléen (ok? ici) pour indiquer si l'appel a réussi ou non, et une deuxième valeur (val-or-msg) qui est la valeur réelle en cas de succès ou un message d'erreur en cas

d'échec.

La fonction assert prend une valeur et un message d'erreur ; elle appelle error si la valeur est nil et la renvoie sinon. Cela peut être utilisé pour transformer des échecs à valeurs multiples en erreurs (un peu l'inverse de pcall qui transforme les erreurs en échecs à valeurs multiples) 

:

filename)) conten
ts (f.read f "*all")]
(f.close f) contents)

Dans cet exemple, parce que io.open renvoie nil et un message d'erreur en cas d'échec, un échec déclenchera une error et interro

mpra l'ex

FONCTIONS

VARIADIQUES

Fennel prend en charge les fonctions variadiques (en d'autres termes, les fonctions qui acceptent un nombre quelconque d'arguments) comme de nombreux langages. La syntaxe pour prendre un nombre variable d'arguments dans une fonction est le symbole ... qui doit être le dernier paramètre d'une fonction. Cette syntaxe est héritée de Lua plutôt que de

Lisp.

La forme ... n'est ni une liste ni une valeur de premier ordre, elle se développe en plusieurs valeurs en ligne. Pour accéder aux éléments individuels du vararg, vous pouvez déstructurer avec des parenthèses, ou d'abord l'envelopper dans un littéral de table ([...]) et l'indexer comme une table normale, ou utiliser la fonction select de la bibliothèque standard de Lua. Souvent, le vararg peut être passé directement à une autre fonction telle que print sans avoir besoin de le

lier. 
(fn print-each [...]
  (each [i v (ipairs [...])]
    (print (.. "Argument " i " is " v))))
(print-each :a
:b
:c) 
(fn myprint [prefix ...]
  (io.writ
e prefix) (io.write (.. (select "
#" ...) " arguments given: ")) (p
rint ...)) (myprint ":D " :d :e :f)

Les varargs sont portés d'une manière différente des autres variables également - ils ne sont accessibles qu'à la fonction dans laquelle ils sont créés. Contrairement aux valeurs normales, les fonctions ne peuvent pas les capturer. Cela signifie que le code suivant ne fonctionnera PAS, car les varargs dans la fonction interne sont hors de

portée. 
(fn badcode [...]
  (fn []
    (print .

VÉRIFICATION STRICTE DES

GLOBALES

Si vous obtenez une erreur disant unknown global en mode strict, cela signifie que vous essayez de compiler du code utilisant une globale que le compilateur Fennel ne connaît pas. La plupart du temps, cela est dû à une erreur de codage. Cependant, dans certains cas, vous pouvez obtenir cette erreur avec une référence légitime à une globale. Si cela se produit, cela peut être dû à une limitation inhérente à la stratégie de Fennel. Vous pouvez utiliser _G.myglobal pour y faire référence d'une manière qui contourne cette vérification et attire l'attention sur le fait qu'il s'agit en fait d'une

globale.

Une autre cause possible de cette erreur est un environnement de fonction modifié. La solution dépend de la manière dont vous utilisez Fennel 

:
•
Fennel embarqué peut avoir son chercheur modifié pour ignorer certaines (ou toutes) globales via le paramètre allowedGlobals. Voir la page de l'API Lua pour les
instructions.
•
La CLI de Fennel possède le paramètre --globals, qui accepte une liste de globales séparées par des virgules à ignorer. Par exemple, pour désactiver le mode strict pour les globales x, y et
z

PIÈGE

S

Il y a quelques surprises qui peuvent surprendre les lispers expérimentés. La plupart de celles-ci résultent nécessairement de l'insistance de Fennel à imposer zéro surcoût d'exécution sur

Lua.
•
Les opérateurs arithmétiques, de comparaison et booléens ne sont pas des fonctions de premier ordre. Ils peuvent se comporter de manière surprenante avec des fonctions renvoyant plusieurs valeurs, car le nombre d'arguments qui leur sont passés doit être connu à la
compilation.
•
Il n'y a pas de fonction apply ; utilisez plutôt table.unpack ou unpack selon votre version de Lua : (f 1 3 (table.unpack [4 9])) fait ce que (apply f 1 3 [4 9]) ferait dans d'autres
lisps.
•
Les tables sont comparées pour l'égalité par identité, et non sur la base de la valeur de leur contenu, comme selon Bake
r.
•
Les valeurs de retour dans le repl seront joliment imprimées, mais appeler (print tbl) émettra une sortie comme table: 0x55a3a8749ef0. Si vous n'en avez pas déjà une, il est recommandé pour le débogage de définir une fonction d'impression qui appelle fennel.view sur son argument avant de l'imprimer : (local fennel (require :fennel)) (fn _G.pp [x] (print (fennel.view x))). Si vous ajoutez cette définition à votre fichier ~/.fennelrc, elle sera disponible dans le repl
standard.

MULTIPLES

Vous pouvez utiliser la fonction require pour charger du code depuis d'autres

(let [lume (require :lume)

Les modules en Fennel et Lua sont simplement des tables contenant des fonctions et d'autres valeurs. La dernière valeur d'un fichier Fennel sera utilisée comme la valeur de l'ensemble du module. Techniquement, cela peut être n'importe quelle valeur, pas seulement une table, mais l'utilisation d'une table est la plus courante pour de bonnes

raisons.

Pour requérir un module qui se trouve dans un sous-répertoire, prenez le nom du fichier, remplacez les barres obliques par des points et supprimez l'extension, puis passez cela à require. Par exemple, un fichier appelé lib/ui/menu.lua serait lu lors du chargement du module lib.ui.m

enu.

Lorsque vous exécutez votre programme avec la commande fennel , vous pouvez appeler require pour charger des modules Fennel ou Lua. Mais dans d'autres contextes (comme la compilation en Lua puis l'utilisation de la commande lua, ou dans des programmes qui embarquent Lua), elle ne connaîtra pas les modules Fennel. Vous devez installer le chercheur qui sait comment trouver les fichiers .fnl

Il existe plusieurs façons d'écrire une bibliothèque qui utilise des modules. L'une d'entre elles est de s'appuyer sur quelque chose comme LuaRocks pour gérer l'installation de la bibliothèque et la disponibilité de celle-ci et de ses modules. Une autre façon est d'utiliser le style require relatif pour charger des modules imbriqués. Avec le require relatif, les bibliothèques ne dépendent pas du nom du répertoire racine ou de son emplacement lors de la résolution des chemins des modules

internes.

;; file example/init
.fnl: (local a (requi
re :example.module-a)
) {:hello-a a.hello}

Ici, le module principal requiert le module supplémentaire example.module-a, qui contient l'implémentation 

: 
;; file example/modu
le-a.fnl (fn hello [
] (print "hello from
a")) {:hello hello}

Le problème principal ici est que le chemin vers la bibliothèque doit être exactement example, c'est-à-dire que la bibliothèque doit être requise comme (require :example) pour qu'elle fonctionne, ce qui ne peut pas être imposé à l'utilisateur de la bibliothèque. Par exemple, si la bibliothèque était déplacée dans libsan> répertoire du projet pour éviter le désordre, et requis comme (require :libs.example), il y aura une erreur d'exécution. Cela se produit parce que la bibliothèque essaiera elle-même de requérir :example.module-a et non :libs.example.module-a, qui est maintenant le chemin du module correct :

runtime error: module 'example.module-a' not found:
        no field package.preload['example.module-a']
        ...
        no file './example/module-a.lua'
        ...
stack traceback:
  [C]: in function 'require'
  ./libs/example/init.fnl:2: in main chunk

LuaRocks résout ce problème en imposant à la fois le nom du répertoire et le chemin d'installation, en remplissant la variable d'environnement LUA_PATH pour rendre la bibliothèque disponible. Cela peut, bien sûr, être fait manuellement en définissant LUA_PATH par projet dans le pipeline de construction, en le pointant vers le bon répertoire. Mais ce n'est pas très transparent, et lors de la requéria d'une bibliothèque locale au projet, il est préférable de voir le chemin complet, qui correspond directement à la structure des fichiers du projet, plutôt que de chercher où LUA_PATH est modifié.

Dans l'écosystème Fennel, nous encourageons une manière plus simple de gérer les dépendances de projet. Il suffit généralement de déposer une bibliothèque dans l'arborescence de votre projet ou d'utiliser un sous-module git, et les chemins de requéria devraient être gérés par la bibliothèque elle-même.

Voici comment un chemin de requéria relatif peut être spécifié dans libs/example/init.fnl pour le rendre indépendant du nom/chemin, en supposant que nous y avons déplacé notre bibliothèque example :

;; fichier libs/example/init.fnl:
(local a (require (.. ... :.module-a)))
{:hello-a a.hello}

Maintenant, peu importe le nom de la bibliothèque ou où nous la plaçons, nous pouvons la requérir depuis n'importe où. Cela fonctionne parce que lors de la requéria de la bibliothèque avec (require :lib.example), la première valeur dans ... contiendra la chaîne "lib.example". Cette chaîne est ensuite concaténée avec ".module-a", et require trouvera et chargera correctement le module imbriqué à l'exécution sous le chemin "lib.example.module-a". C'est une fonctionnalité Lua, et non quelque chose de spécifique à Fennel, et cela fonctionnera de la même manière lorsque la bibliothèque sera compilée AOT en Lua.

Include relatif à la compilation

Depuis Fennel v0.10.0, cela fonctionne également à la compilation, lors de l'utilisation de la spéciale include ou de l'indicateur --require-as-include, avec la contrainte que l'expression peut être calculée à la compilation. Cela signifie que l'expression doit être autonome, c'est-à-dire qu'elle ne doit pas faire référence à des variables locales ou globales, mais intégrer toutes les valeurs directement. En d'autres termes, le code suivant ne fonctionnera qu'à l'exécution, mais pas avec include ou --require-as-include car current-module n'est pas connu à la compilation :

(local current-module ...)
(require (.. current-module :.other-module))

Ceci, en revanche, fonctionnera à la fois à l'exécution et à la compilation :

(require (.. ... :.other-module))

Les arguments de module ... sont propagés pendant la compilation, donc lorsque l'application qui utilise cette bibliothèque est compilée, tout le code de la bibliothèque est correctement inclus dans le fichier Lua autonome.

La compilation d'un projet qui utilise cette bibliothèque example avec --require-as-include inclura la section suivante dans le code Lua résultant :

package.preload["libs.example.module-a"] = package.preload["libs.example.module-a"] or function(...)
  local function hello()
    return print("hello from a")
  end
  return {hello = hello}
end

Notez que l'entrée package.preload contient un chemin complètement qualifié "libs.example.module-a", qui a été résolu à la compilation.

Requérir des modules depuis des modules autres que init.fnl

Pour requérir un module depuis un module autre que le module init, nous devons conserver le chemin jusqu'au module actuel, mais supprimer le nom du module. Par exemple, ajoutons un module greet dans libs/example/utils/greet.fnl et requérons-le depuis libs/example/module-a.fnl :

;; fichier libs/example/utils/greet.fnl:
(fn greet [who] (print (.. "hello " who)))

Ce module peut être requis comme suit :

;; fichier libs/example/module-a.fnl
(local greet (require (.. (: ... :match "(.+)%.[^.]+") :.utils.greet)))
(fn hello [] (print "hello from a"))
{:hello hello :greet greet}

Le nom du module parent est déterminé en appelant la méthode match sur la chaîne du nom du module actuel (...).
