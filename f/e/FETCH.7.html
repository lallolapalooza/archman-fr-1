NOM

FETCH - récupérer des lignes d'une requête en utilisant un curseur

SYNTAXE

FETCH [ direction ] [ FROM | IN ] nom_curseur
où direction peut être l'un des éléments suivants :
    NEXT
    PRIOR
    FIRST
    LAST
    ABSOLUTE compteur
    RELATIVE compteur
    compteur
    ALL
    FORWARD
    FORWARD compteur
    FORWARD ALL
    BACKWARD
    BACKWARD compteur
    BACKWARD ALL

DESCRIPTION

FETCH récupère des lignes en utilisant un curseur préalablement créé.

Un curseur a une position associée, qui est utilisée par FETCH. La position du curseur peut être avant la première ligne du résultat de la requête, sur une ligne particulière du résultat, ou après la dernière ligne du résultat. Lors de sa création, un curseur est positionné avant la première ligne. Après avoir récupéré certaines lignes, le curseur est positionné sur la ligne la plus récemment récupérée. Si FETCH atteint la fin des lignes disponibles, le curseur est laissé positionné après la dernière ligne, ou avant la première ligne si la récupération se fait en arrière. FETCH ALL ou FETCH BACKWARD ALL laisseront toujours le curseur positionné après la dernière ligne ou avant la première ligne.

Les formes NEXT, PRIOR, FIRST, LAST, ABSOLUTE, RELATIVE récupèrent une seule ligne après avoir déplacé le curseur de manière appropriée. S'il n'y a pas de telle ligne, un résultat vide est retourné, et le curseur est laissé positionné avant la première ligne ou après la dernière ligne, selon le cas.

Les formes utilisant FORWARD et BACKWARD récupèrent le nombre de lignes indiqué en se déplaçant dans la direction avant ou arrière, laissant le curseur positionné sur la dernière ligne retournée (ou avant/après toutes les lignes, si le compteur dépasse le nombre de lignes disponibles).

RELATIVE 0, FORWARD 0, et BACKWARD 0 demandent tous la récupération de la ligne courante sans déplacer le curseur, c'est-à-dire, la récupération de la ligne la plus récemment récupérée. Cela réussira sauf si le curseur est positionné avant la première ligne ou après la dernière ligne ; dans ce cas, aucune ligne n'est retournée.


Note

Cette page décrit l'utilisation des curseurs au niveau de la commande SQL. Si vous essayez d'utiliser des curseurs à l'intérieur d'une fonction PL/pgSQL, les règles sont différentes — voir la section 41.7.3.

PARAMETRES

direction

direction définit la direction de récupération et le nombre de lignes à récupérer. Elle peut être l'une des suivantes :

NEXT

Récupère la ligne suivante. C'est la valeur par défaut si direction est omise.

PRIOR

Récupère la ligne précédente.

FIRST

Récupère la première ligne de la requête (équivalent à ABSOLUTE 1).

LAST

Récupère la dernière ligne de la requête (équivalent à ABSOLUTE -1).

ABSOLUTE compteur

Récupère la compteur-ième ligne de la requête, ou la abs(compteur)-ième ligne à partir de la fin si compteur est négatif. Se positionne avant la première ligne ou après la dernière ligne si compteur est hors limites ; en particulier, ABSOLUTE 0 se positionne avant la première ligne.

RELATIVE compteur

Récupère la compteur-ième ligne suivante, ou la abs(compteur)-ième ligne précédente si compteur est négatif. RELATIVE 0 récupère à nouveau la ligne courante, le cas échéant.

compteur

Récupère les prochaines compteur lignes (équivalent à FORWARD compteur).

ALL

Récupère toutes les lignes restantes (équivalent à FORWARD ALL).

FORWARD

Récupère la ligne suivante (équivalent à NEXT).

FORWARD compteur

Récupère les prochaines compteur lignes. FORWARD 0 récupère à nouveau la ligne courante.

FORWARD ALL

Récupère toutes les lignes restantes.

BACKWARD

Récupère la ligne précédente (équivalent à PRIOR).

BACKWARD compteur

Récupère les compteur lignes précédentes (en parcourant à l'envers). BACKWARD 0 récupère à nouveau la ligne courante.

BACKWARD ALL

Récupère toutes les lignes précédentes (en parcourant à l'envers).

compteur

compteur est une constante entière éventuellement signée, déterminant la position ou le nombre de lignes à récupérer. Pour les cas FORWARD et BACKWARD, spécifier un compteur négatif équivaut à changer le sens de FORWARD et BACKWARD.

nom_curseur

Le nom d'un curseur ouvert.

SORTIES

En cas de succès, une commande FETCH retourne une étiquette de commande de la forme

FETCH compteur

Le compteur est le nombre de lignes récupérées (potentiellement zéro). Notez que dans psql, l'étiquette de commande ne sera pas réellement affichée, car psql affiche les lignes récupérées à la place.

NOTES

Le curseur doit être déclaré avec l'option SCROLL si l'on a l'intention d'utiliser des variantes de FETCH autres que FETCH NEXT ou FETCH FORWARD avec un compteur positif. Pour les requêtes simples, PostgreSQL autorisera la récupération arrière depuis des curseurs non déclarés avec SCROLL, mais il est préférable de ne pas se fier à ce comportement. Si le curseur est déclaré avec NO SCROLL, aucune récupération arrière n'est autorisée.

Les récupérations ABSOLUTE ne sont pas plus rapides que la navigation vers la ligne souhaitée par un déplacement relatif : l'implémentation sous-jacente doit parcourir toutes les lignes intermédiaires de toute façon. Les récupérations absolues négatives sont encore pires : la requête doit être lue jusqu'à la fin pour trouver la dernière ligne, puis parcourue à l'envers à partir de là. Cependant, revenir au début de la requête (comme avec FETCH ABSOLUTE 0) est rapide.

DECLARE est utilisé pour définir un curseur. Utilisez MOVE pour changer la position du curseur sans récupérer de données.

EXEMPLES

L'exemple suivant parcourt une table en utilisant un curseur :

BEGIN WORK;
-- Configuration d'un curseur :
DECLARE liahona SCROLL CURSOR FOR SELECT * FROM films;
-- Récupère les 5 premières lignes du curseur liahona :
FETCH FORWARD 5 FROM liahona;
 code  |          title          | did | date_prod  |   kind   |  len
-------+-------------------------+-----+------------+----------+-------
 BL101 | The Third Man           | 101 | 1949-12-23 | Drama    | 01:44
 BL102 | The African Queen       | 101 | 1951-08-11 | Romantic | 01:43
 JL201 | Une Femme est une Femme | 102 | 1961-03-12 | Romantic | 01:25
 P_301 | Vertigo                 | 103 | 1958-11-14 | Action   | 02:08
 P_302 | Becket                  | 103 | 1964-02-03 | Drama    | 02:28
-- Récupère la ligne précédente :
FETCH PRIOR FROM liahona;
 code  |  title  | did | date_prod  |  kind  |  len
-------+---------+-----+------------+--------+-------
 P_301 | Vertigo | 103 | 1958-11-14 | Action | 02:08
-- Ferme le curseur et termine la transaction :
CLOSE liahona;
COMMIT WORK;

COMPATIBILITE

La norme SQL définit FETCH pour une utilisation uniquement en SQL embarqué. La variante de FETCH décrite ici retourne les données comme s'il s'agissait d'un résultat de SELECT plutôt que de les placer dans des variables hôtes. À part ce point, FETCH est entièrement compatible ascendante avec la norme SQL.

Les formes de FETCH impliquant FORWARD et BACKWARD, ainsi que les formes FETCH compteur et FETCH ALL, dans lesquelles FORWARD est implicite, sont des extensions de PostgreSQL.

La norme SQL n'autorise que FROM précédant le nom du curseur ; l'option d'utiliser IN, ou de les omettre complètement, est une extension.
