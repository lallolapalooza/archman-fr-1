DÉFINITION DU NŒUD

AST

L'AST renvoyé par l'analyseur se compose de structures de données représentant le code. Le passage des nœuds AST à la fonction fennel.view vous donnera une chaîne qui devrait faire un aller-retour à travers l'analyseur pour vous rendre les mêmes données. Il en va de même avec tostring, sauf qu'il ne fonctionne pas avec les tables non-séquentielles

.

La fonction fennel.ast-source prend un nœud AST et renvoie une table avec les données de source autour du nom de fichier, du numéro de ligne, etc., si possible. Certains nœuds AST ne peuvent pas fournir ces données, par exemple les nombres, les chaînes et les booléens, ou les symboles construits à l'intérieur des macros en utilisant la fonction sym au lieu du

backtick.

Les nœuds AST peuvent être de n'importe quels de ces types

:

lis

t

Une liste représente un appel à une fonction/macro, ou le dégroupage de plusieurs valeurs de retour dans un contexte de liaison. Elle est représentée comme une table qui peut être identifiée en utilisant la fonction prédicat fennel.list? ou construite en utilisant fennel.list qui prend un nombre quelconque d'arguments pour le contenu de la

liste.

Notez que les listes sont des constructions au moment de la compilation en Fennel. Elles n' existent pas à l'exécution, sauf dans les cas où le compilateur est utilisé à

l'exécution.

La liste contient également ces clés indiquant où elle a été définie : filename, line, col, endcol, bytestart, et byteend. Ces données sont utilisées pour les traces de pile et pour localiser les messages d'erreur du compilateur. Notez que les numéros de colonne sont basés sur l

e nombre de caractères, ce qui ne correspond pas toujours aux colonnes visuelles ;
par exemple "วัด" est trois caractères mais seulement deux colonnes visuelles.

table séquence/clé-valeu

r

Ce sont des littéraux de table dans le code Fennel produits par des crochets (séquences) ou des accolades (tables k/v). Les séquences peuvent être identifiées en utilisant la fonction fennel.sequence? et construites en utilisant fennel.sequence. Il n'y a pas de prédicat ou de constructeur pour les tables k/v ; toute table qui n'est pas de l'un des autres types est supposée être l'une

d'elles.

À l'exécution, il n'y a pas de différence entre les séquences et les tables k/v qui utilisent des cléslly croissantes, mais le parseur est capable de distinguer entre elles pour améliorer le signalement

d'erreurs.

Les séquences et les tables k/v ont leurs données source dans filename, line, etc clés de leur métatable. La métatable des tables k/v inclut aussi une clé sequence qui indique dans quel ordre les clés sont apparues à l'origine, puisque les tables

k/v sont non ordonnées et qu'il n'y aurait si
non aucun moyen de reconstruire cette information.

symbo

l

Les symboles représentent typiquement des identifiants dans le code Fennel. Les symboles peuvent être identifiés avec fennel.sym? et construits avec fennel.sym qui prend un nom de chaîne de caractères comme premier argument et une table de données source comme second. Les symboles sont représentés comme des tables qui stockent leurs données source (filename, line, col, etc) dans des champs sur eux-mêmes. Contrairement aux autres tables de l'AST, ils ne représentent pas des collections ; ils sont utilisés comme types

scalaires.

Les symboles peuvent faire référence non seulement directement à des locaux, mais aussi à des références de table comme tbl.x pour la recherche de champ ou access.channel:deny pour l'invocation de méthode. La fonction fennel.multi-sym? retournera une table contenant les segments si le symbole en est un, ou nil

sinon.

Note : nil n'est pas un AST valide ; le code qui fait référence à nil aura le symbole nommé "nil" qui malheureusement s'imprime d'une manière visuellement indistinguable de l'actuel nil

Par défaut, les AST omettent les commentaires. Cependant, lorsque le champ :comment est défini dans les options du parseur, les commentaires seront inclus dans les valeurs analysées. Ils sont identifiés en utilisant fennel.comment? et construits en utilisant la fonction fennel.comment. Ils sont représentés comme des tables qui ont des données source comme champs à

Dans la plupart des contextes de données, les commentaires sont simplement inclus en ligne dans une liste ou une séquence. Toutes les options peuvent être définies à {:once some-value} pour forcer leur valeur à être some-value mais seulement pour le niveau courant. Vous pouvez définir une méthode __fennelview sur une table pour remplacer son comportement de sérialisation. Elle devrait prendre la table étant sérialisée comme premier argument, une fonction comme second argument, la table d'options comme troisième argument, et le montant courant d'indentation comme dernier argument

: 
(fn [t view options indent]

la fonction view contient un imprimeur formaté qui peut être utilisé pour sérialiser les éléments stockés dans la table étant sérialisée. Si votre méthode produit une représentation indentée, vous devriez passer le paramètre indent à view augmenté du montant d'indentation additionnelle que vous avez introduite. Cette fonction a la même interface que la méthode __fennelview, mais en plus accepte colon-string? comme dernier argument. Si colon? est true, les chaînes seront imprimées comme chaînes deux-points quand c'est possible, et si sa valeur est false, les chaînes seront toujours imprimées entre guillemets doubles. Si omis ou nil, elle prendra par défaut la valeur de l'option :prefer-co

lon?.

la table options contient les options décrites ci-dessus, et aussi la fonction visible-cycle?, qui prend une table étant sérialisée, détecte et sauvegarde l'information sur un cycle possible atteignable. Devrait être utilisée dans __fennelview pour implémenter la détection de

cycles.

la méthode __fennelview devrait toujours retourner une table de lignes correctement indentées lors de la production d'une sortie multi-lignes, ou une chaîne lorsqu'elle retourne toujours un élément sur une seule ligne. fennel.view transformera votre structure de données en représentation multi-lignes correcte quand nécessaire. Il n'y a pas besoin de concaténer la table manuellement jamais - fennel.view appliquera des règles générales pour votre structure de données, dépendamment des options courantes. Par défaut, la sortie multi-lignes n'est produite que lorsque les structures de données internes contiennent des nouvelles lignes, ou lorsque retourner une table de lignes comme une seule ligne résulte en une largeur supérieure à l'option line

-size.

La représentation multi-lignes peut être forcée en retournant deux valeurs depuis __fennelview - une table de lignes indentées comme première valeur, et true comme seconde valeur, indiquant que la représentation multi-lignes devrait être

forcée.

Il n'y a pas besoin d'incorporer d'indentation au-delà de ce qui est nécessaire pour aligner correctement les éléments dans la représentation imprimée de votre structure de données. Par exemple, si vous voulez imprimer une table multi-lignes, comme ceci

:

[1
2
3]

["@my-table[
1" "
2" "
3]"]

additionnelle.

(fn pp-doc-example [t view options indent]
  (let [lines (icollect [i v (ipairs t)]
                (let [v (view v options (+ 10 indent))]
                  (if (= i 1) v
                      (.. "          " v))))]
    (doto lines
      (tset 1 (.. "@my-table[" (or (. lines 1) "")))
      (tset (length lines) (.. (. lines (length lines)) "]
")))
)
)

Note de performance sur les

métadonnées

L'activation des métadonnées dans le compilateur/eval/REPL fera en sorte que chaque fonction stocke une nouvelle table contenant l'arglist et le docstring de la fonction dans la table de métadonnées, référencée faiblement par la fonction elle-même en tant que

Cela peut avoir un impact sur les performances dans certaines applications en raison

ion des métadonnées n'est actuellement recommandée que dans un but de développement.

PLUGINS Le système de plugins de Fennel est extrêmement expérimental et expose les internes du compilateur d'une manière qu'aucune autre partie du compilateur ne fait. Il doit être considéré comme instable ; les modifications du compilateur dans les futures versions casseront probablement les plugins, et chaque plugin ne doit être supposé fonctionner qu'avec des versions spécifiques du compilateur avec lesquelles il a été testé. Les garanties de rétrocompatibilité du reste de Fennel n

e

s'appliquent pas aux

plugins.
Les plugins du compilateur permettent d'étendre les fonctionnalités du compilateur de diverses manières. Un plugin est un module contenant diverses fonctions dans des champs
nommés d'après différents points d'extension du compilateur. Lorsque le compilateur atteint un point d'extension, il appellera la fonction de chaque plugin pour ce point d'extension, si elle est fournie, avec divers arguments ; généralement l'AST en question et la table de portée. Chaque fonction de plugin devrait normalement effectuer des effets de bord et retourner nil ou provoquer une erreur. Si une fonction retourne non-nil, cela fera en sorte que le reste des plugins pour un événement donné soit ignoré.

fennel-api - Interface de programmation d'application Fennel

DESCRIPTION

Ce document décrit les différentes fonctions et fonctionnalités exposées par le langage Fennel, que ce soit pour une utilisation dans le REPL, la compilation ou la programmation.

DÉMARRER UN REPL CONFIGURABLE

Le REPL de Fennel peut être étendu avec des plugins. Ces plugins sont des modules Fennel qui exposent des fonctions pour modifier le comportement du REPL. Les fonctions de plugin doivent être exposées comme des champs dans la table de module du plugin.

Voici les hooks de plugin disponibles:

repl-command-<nom>

Ajoute une nouvelle commande au REPL. Le nom de la commande est déduit du nom de la fonction dans le module du plugin.

Par exemple, un plugin avec la définition suivante:

(local fennel (require :fennel))

(fn locals [env read on-values on-error scope chars opts]
  "Affiche tous les locaux dans la portée de la session REPL."
  (on-values [(fennel.view env.___replLocals___)]))

{:repl-command-locals locals}

sera exécuté comme suit:

$ fennel --plugin locals-plugin.fnl
Bienvenue dans Fennel 0.8.0 sur Lua 5.4!
Utilisez ,help pour voir les commandes disponibles.
>> (local x 4)
nil
>> (local abc :xyz)
nil
>> ,locals
{
  :abc "xyz"
  :x 4
}

La docstring de la fonction sera utilisée comme résumé dans la liste des commandes ",help". Contrairement aux autres champs de hook de plugin, seule la première commande de REPL fournie par un plugin sera utilisée.

ACTIVATION

Les plugins sont activés en passant l'argument --plugin en ligne de commande, qui doit être un chemin vers un fichier Fennel contenant un module qui a certaines des fonctions listées ci-dessus. Si vous utilisez le compilateur par programme, vous pouvez inclure une table :plugins dans la table d' options de la plupart des fonctions d'entrée du compilateur.

Votre plugin doit contenir un champ :versions qui contient soit une liste de chaînes de caractères indiquant toutes les versions de Fennel avec lesquelles il a été testé, soit une chaîne de caractères contenant un motif qui est vérifié par rapport à la version de Fennel avec string.find. Si votre plugin est utilisé avec une version de Fennel qui ne correspond pas à :versions, il émettra un avertissement. Vous devriez également avoir un champ :name avec le nom du plugin.
