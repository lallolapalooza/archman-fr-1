feature(3perl) Guide de référence des programmeurs Perl feature(3perl)

NOM

feature - pragma Perl pour activer de nouvelles fonctionnalités

SYNOPSIS

use feature qw(fc say);
# Sans le "use feature" ci-dessus, ce code ne pourrait pas trouver
# les fonctions intégrées "say" ou "fc" :
say "The case-folded version of $x is: " . fc $x;
# définit les fonctionnalités pour correspondre au lot :5.36, ce qui peut
# activer ou désactiver plusieurs fonctionnalités (voir "LOTS DE
# FONCTIONNALITÉS" ci-dessous)
use feature ':5.36';
# charge implicitement le lot de fonctionnalités :5.36
use v5.36;

DESCRIPTION

Il est généralement impossible d'ajouter de nouvelles syntaxes à Perl sans casser certains programmes existants. Ce pragma fournit un moyen de minimiser ce risque. De nouvelles constructions syntaxiques, ou de nouvelles significations sémantiques pour des constructions plus anciennes, peuvent être activées par "use feature 'foo'", et ne seront analysées que lorsque le pragma feature approprié est dans la portée. (Néanmoins, le "CORE::" préfixe donne accès à tous les mots-clés Perl, indépendamment de ce pragma.)

Effet lexical

Comme d'autres pragmas ("use strict", par exemple), les fonctionnalités ont un effet lexical. "use feature qw(foo)" ne rendra la fonctionnalité "foo" disponible qu'à partir de ce point jusqu'à la fin du bloc englobant.

{
    use feature 'say';
    say "say is available here";
}
print "But not here.\n";

"no feature"

Les fonctionnalités peuvent aussi être désactivées en utilisant "no feature "foo"". Cela a également un effet lexical.

use feature 'say';
say "say is available here";
{
    no feature 'say';
    print "But not here.\n";
}
say "Yet it is here.";

"no feature" sans fonctionnalités spécifiées réinitialisera au groupe par défaut. Pour désactiver toutes les fonctionnalités (une demande inhabituelle !) utilisez "no feature ':all'".

FONCTIONNALITÉS DISPONIBLES

Lisez "LOTS DE FONCTIONNALITÉS" pour le résumé de la fiche de référence des fonctionnalités.

La fonctionnalité 'say'

"use feature 'say'" indique au compilateur d'activer la fonction "say" inspirée de Raku.

Voir "say" dans perlfunc pour plus de détails.

Cette fonctionnalité est disponible à partir de Perl 5.10.

La fonctionnalité 'state'

"use feature 'state'" indique au compilateur d'activer les variables "state" .

Voir "Persistent Private Variables" dans perlsub pour plus de détails.

Cette fonctionnalité est disponible à partir de Perl 5.10.

La fonctionnalité 'smartmatch'

"use feature 'smartmatch'" indique au compilateur d'activer l'opérateur de correspondance intelligente "~~". Elle est activée par défaut, mais peut être désactivée pour interdire l'opérateur "~~" .

Cette fonctionnalité est désactivée par défaut à partir du lot de fonctionnalités 5.42 :

$x ~~ $y; # fine
use v5.42;
$x ~~ $y; # error

Cela n'a aucun effet sur les correspondances intelligentes implicites faites par "when".

Voir "Smartmatch Operator" dans perlop pour plus de détails.

La fonctionnalité 'switch'

"use feature 'switch'" indique au compilateur d'activer la construction given/when de Raku.

Voir "Switch Statements" dans perlsyn pour plus de détails.

Cette fonctionnalité est disponible à partir de Perl 5.10. Elle est activée par les lots de fonctionnalités 5.10 à 5.34, et désactivée à partir du lot de fonctionnalités 5.36.

La fonctionnalité 'unicode_strings'

"use feature 'unicode_strings'" indique au compilateur d'utiliser les règles Unicode dans toutes les opérations sur les chaînes exécutées dans sa portée (sauf si elles sont également dans la portée de "use locale" ou "use bytes"). La même chose s'applique à toutes les expressions régulières compilées dans la portée, même si elles sont exécutées en dehors. Cela ne change pas la représentation interne des chaînes, mais seulement la manière dont elles sont interprétées.

"no feature 'unicode_strings'" indique au compilateur d'utiliser les règles Perl traditionnelles où les règles du jeu de caractères natif sont utilisées sauf s'il est clair pour Perl qu'Unicode est souhaité. Cela peut conduire à quelques surprises lorsque le comportement change soudainement. (Voir "The "Unicode Bug"" dans perlunicode pour plus de détails.) Pour cette raison, si vous utilisez potentiellement Unicode dans votre programme, la "use feature 'unicode_strings'" sous-pragma est fortement recommandé.

Cette fonctionnalité est disponible à partir de Perl 5.12 ; a été presque entièrement implémentée dans Perl 5.14 ; et étendue dans Perl 5.16 pour couvrir "quotemeta"; a été étendue plus loin dans Perl 5.26 pour couvrir l'opérateur de plage ; et a été étendue à nouveau dans Perl 5.28 pour couvrir la division en mots pour les espaces blancs à cas particulier.

Les fonctionnalités 'unicode_eval' et 'evalbytes'

Ensemble, ces deux fonctionnalités sont destinées à remplacer la fonction d'évaluation de chaîne "eval" , qui se comporte de manière problématique dans certains cas. Elles sont disponibles à partir de Perl 5.16, et sont activées par défaut par une "use 5.16" ou une déclaration supérieure.

"unicode_eval" change le comportement de l'évaluation de chaîne simple "eval" pour fonctionner de manière plus cohérente, en particulier dans le monde Unicode. Certains (mauvais) comportements ne pouvaient pas être changés sans casser certaines choses qui en dépendaient, donc la fonctionnalité peut être activée et désactivée. Les détails sont dans "Under the "unicode_eval" feature" dans perlfunc.

"evalbytes" est comme l'évaluation de chaîne "eval", mais il traite son argument comme une chaîne d'octets. Les détails sont dans "evalbytes EXPR" dans perlfunc. Sans une "use feature 'evalbytes'" ni une déclaration "use v5.16" (ou supérieure) dans la portée actuelle, vous pouvez toujours y accéder en écrivant à la place "CORE::evalbytes".

La fonctionnalité 'current_sub'

Cela fournit le "__SUB__" jeton qui retourne une référence à la sous-routine actuelle ou "undef" en dehors d'une sous-routine.

Cette fonctionnalité est disponible à partir de Perl 5.16.

La fonctionnalité 'array_base'

Cette fonctionnalité prenait en charge la variable "$[" héritée. Voir "$[" dans perlvar. Elle était activée par défaut mais désactivée sous "use v5.16" (voir "CHARGEMENT IMPLICITE", ci-dessous) et indisponible depuis perl 5.30.

Cette fonctionnalité est disponible sous ce nom à partir de Perl 5.16. Dans les versions précédentes, elle était simplement toujours activée, et ce pragma ne savait rien à ce sujet.

La fonctionnalité 'fc'

"use feature 'fc'" indique au compilateur d'activer la fonction "fc" , qui implémente le pliage de cas Unicode.

Voir "fc" dans perlfunc pour plus de détails.

Cette fonctionnalité est disponible à partir de Perl 5.16.

La fonctionnalité 'lexical_subs'

Dans les versions de Perl antérieures à 5.26, cette fonctionnalité permettait la déclaration de sous-routines via la syntaxe "my sub foo", "state sub foo" et "our sub foo" . Voir "Lexical Subroutines" dans perlsub pour plus de détails.

Cette fonctionnalité est disponible à partir de Perl 5.18. De Perl 5.18 à 5.24, elle était classée comme expérimentale, et Perl émettait un avertissement pour son utilisation, sauf si elle était explicitement désactivée :

no warnings "experimental::lexical_subs";quot;;

Depuis Perl 5.26, l'utilisation de cette fonctionnalité ne déclenche plus d'avertissement, bien que la "experimental::lexical_subs" catégorie d'avertissements existe toujours (par compatibilité avec le code qui la désactive). De plus, cette syntaxe n'est plus seulement expérimentale, mais elle est activée pour tout code Perl, indépendamment des déclarations de fonctionnalités en portée.

Les fonctionnalités 'postderef' et 'postderef_qq'

La fonctionnalité 'postderef_qq' étend l'applicabilité de la syntaxe de déréférencement postfixe afin que le déréférencement postfixe de tableau, le déréférencement postfixe de scalaire et l'accès à l'index le plus élevé d'un tableau soient disponibles dans les interpolations entre guillemets doubles. Par exemple, elle rend les deux instructions suivantes équivalentes :

my $s = "[@{ $h->{a} }]";
my $s = "[$h->{a}->@*]";

Cette fonctionnalité est disponible à partir de Perl 5.20. Dans Perl 5.20 et 5.22, elle était classée comme expérimentale, et Perl émettait un avertissement pour son utilisation, sauf si elle était explicitement désactivée :

no warnings "experimental::postderef";

Depuis Perl 5.24, l'utilisation de cette fonctionnalité ne déclenche plus d'avertissement, bien que la "experimental::postderef" catégorie d'avertissements existe toujours (par compatibilité avec le code qui la désactive).

La fonctionnalité 'postderef' était utilisée dans Perl 5.20 et Perl 5.22 pour activer la syntaxe de déréférencement postfixe en dehors des interpolations entre guillemets doubles. Dans ces versions, son utilisation déclenchait l'avertissement "experimental::postderef" de la même manière que la fonctionnalité 'postderef_qq'. Depuis Perl 5.24, cette syntaxe n'est plus seulement expérimentale, mais elle est activée pour tout code Perl, indépendamment des déclarations de fonctionnalités en portée.

La fonctionnalité 'signatures'

Cela active la syntaxe pour déclarer les arguments de sous-routine en tant que variables lexicales. Par exemple, pour cette sous-routine :

sub foo ($left, $right) {
    return $left + $right;
}

Appeler "foo(3, 7)" assignera 3 à $left et 7 à $right.

Voir « Signatures » dans perlsub pour plus de détails.

Cette fonctionnalité est disponible à partir de Perl 5.20. De Perl 5.20 à 5.34, elle était classée comme expérimentale, et Perl émettait un avertissement pour son utilisation, sauf si elle était explicitement désactivée :

no warnings "experimental::signatures";

Depuis Perl 5.36, l'utilisation de cette fonctionnalité ne déclenche plus d'avertissement, bien que la "experimental::signatures" catégorie d'avertissements existe toujours (par compatibilité avec le code qui la désactive). Cette fonctionnalité est maintenant considérée comme stable, et est activée automatiquement par "use v5.36" (ou supérieur).

La fonctionnalité 'refaliasing'

AVERTISSEMENT: Cette fonctionnalité est toujours expérimentale et l'implémentation peut changer ou être supprimée dans les futures versions de Perl. Pour cette raison, Perl émettra un avertissement lorsque vous utiliserez cette fonctionnalité, sauf si vous avez explicitement désactivé l'avertissement :

no warnings "experimental::refaliasing";

Cela permet l'aliasing par assignation à des références :

\$a = \$b; # $a et $b pointent maintenant vers le même scalaire
\@a = \@b; #                     vers le même tableau
\%a = \%b;
\&a = \&
foreach \%hash (@array_of_hash_refs) {
    ...
}

Voir « Assigning to References » dans perlref pour plus de détails.

Cette fonctionnalité est disponible à partir de Perl 5.22.

La fonctionnalité 'bitwise'

Cela fait traiter les quatre opérateurs bitwise standard ("& | ^ ~") leurs opérandes de manière cohérente comme des nombres, et introduit quatre nouveaux opérateurs à points ("&. |. ^. ~.") qui traitent leurs opérandes de manière cohérente comme des chaînes. La même chose s'applique aux variantes d'assignation ("&= |= ^= &.= |.= ^.=").

Voir « Bitwise String Operators » dans perlop pour plus de détails.

Cette fonctionnalité est disponible à partir de Perl 5.22. À partir de Perl 5.28, "use v5.28" activera la fonctionnalité. Avant 5.28, elle était encore expérimentale et émettait un avertissement dans la catégorie "experimental::bitwise".

La fonctionnalité 'declared_refs'

AVERTISSEMENT: Cette fonctionnalité est toujours expérimentale et l'implémentation peut changer ou être supprimée dans les futures versions de Perl. Pour cette raison, Perl émettra un avertissement lorsque vous utiliserez cette fonctionnalité, sauf si vous avez explicitement désactivé l'avertissement :

no warnings "experimental::declared_refs";

Cela permet à une référence d'une variable d'être déclarée avec "my", "state", ou "our", ou localisée avec "local". Elle est principalement destinée à être utilisée en conjonction avec la fonctionnalité "refaliasing". Voir « Declaring a Reference to a Variable » dans perlref pour des exemples.

Cette fonctionnalité est disponible à partir de Perl 5.26.

La fonctionnalité 'isa'

Cela permet l'utilisation de l'opérateur infixé "isa" , qui teste si le scalaire donné par l'opérande de gauche est un objet de la classe donnée par l'opérande de droite. Voir « Class Instance Operator » dans perlop pour plus de détails.

Cette fonctionnalité est disponible à partir de Perl 5.32. De Perl 5.32 à 5.34, elle était classée comme expérimentale, et Perl émettait un avertissement pour son utilisation, sauf si elle était explicitement désactivée :

no warnings "experimental::isa";

Depuis Perl 5.36, l'utilisation de cette fonctionnalité ne déclenche plus d'avertissement (bien que la "experimental::isa" catégorie d'avertissements existe toujours pour la compatibilité avec le code qui la désactive). Cette fonctionnalité est maintenant considérée comme stable, et est activée automatiquement par "use v5.36" (ou supérieur).

La fonctionnalité 'indirect'

Cette fonctionnalité permet l'utilisation de la syntaxe d'objet indirect pour les appels de méthode, par ex. "new Foo 1, 2;". Elle est activée par défaut, mais peut être désactivée pour interdire la syntaxe d'objet indirect.

Cette fonctionnalité est disponible sous ce nom à partir de Perl 5.32. Dans les versions précédentes, elle était simplement activée en permanence. Pour interdire (ou émettre un avertissement pour) la syntaxe d'objet indirect sur les anciennes versions de Perl, voir le module CPAN indirect. Elle est désactivée à partir du paquet de fonctionnalités 5.36.

La fonctionnalité 'multidimensional'

Cette fonctionnalité active l'émulation de tableaux multidimensionnels, une fonctionnalité de perl 4 (ou antérieur) qui était utilisée pour émuler des tableaux multidimensionnels avec des hachages. Cela fonctionne en convertissant du code comme $foo{$x, $y} en $foo{join($;, $x, $y)}. Elle est activée par défaut, mais peut être désactivée pour désactiver l'émulation de tableaux multidimensionnels.

Lorsque cette fonctionnalité est désactivée, la syntaxe qui est normalement remplacée signalera une erreur de compilation.

Cette fonctionnalité est disponible sous ce nom à partir de Perl 5.34. Dans les versions précédentes, elle était simplement activée en permanence. Elle est désactivée à partir du paquet de fonctionnalités 5.36.

Vous pouvez utiliser le module multidimensional sur CPAN pour désactiver l'émulation de tableaux multidimensionnels pour les anciennes versions de Perl.

La fonctionnalité 'bareword_filehandles'

Cette fonctionnalité active les descripteurs de fichier en mots nus pour les opérations des fonctions intégrées, une pratique généralement déconseillée. Elle est activée par défaut, mais peut être désactivée pour désactiver les descripteurs de fichier en mots nus, à l'exception des exceptions listées ci-dessous.

Les descripteurs de fichier intégrés de perl "STDIN", "STDOUT", "STDERR", "DATA", "ARGV", "ARGVOUT" et le spécial "_" sont toujours activés.

Cette fonctionnalité est disponible sous ce nom à partir de Perl 5.34. Dans les versions précédentes, elle était simplement activée en permanence. Elle est désactivée à partir du paquet de fonctionnalités 5.38.

Vous pouvez utiliser le module bareword::filehandles sur CPAN pour désactiver les descripteurs de fichier en mots nus pour les anciennes versions de perl.

La fonctionnalité 'try'

AVERTISSEMENT: Cette fonctionnalité est toujours partiellement expérimentale, et l'implémentation peut changer ou être supprimée dans les futures versions de Perl.

Cette fonctionnalité active la syntaxe "try" et "catch" , qui permet la gestion des exceptions, où les exceptions lancées depuis le corps du bloc introduit avec "try" sont capturées en exécutant le corps du bloc "catch" .

Cette fonctionnalité est disponible à partir de Perl 5.34. Avant Perl 5.40, elle était classée comme expérimentale, et Perl émettait un avertissement pour son utilisation, sauf si elle était explicitement désactivée :

no warnings "experimental::try";

Depuis Perl 5.40, l'utilisation de cette fonctionnalité sans un "finally" bloc ne déclenche plus d'avertissement. Le bloc optionnel "finally" est toujours considéré comme expérimental et émet un avertissement, sauf s'il est explicitement désactivé comme ci-dessus.

Pour plus d'informations, voir « Try Catch Exception Handling » dans perlsyn.

La fonctionnalité 'defer'

AVERTISSEMENT: Cette fonctionnalité est toujours expérimentale et l'implémentation peut changer ou être supprimée dans les futures versions de Perl. Pour cette raison, Perl émettra un avertissement lorsque vous utiliserez cette fonctionnalité, sauf si vous avez explicitement désactivé l'avertissement :

no warnings "experimental::defer";

Cette fonctionnalité active la syntaxe de bloc "defer" , qui permet à un bloc de code d'être différé jusqu'à ce que le flux de contrôle quitte le bloc qui le contenait. Pour plus de détails, voir « defer » dans perlsyn.

Cette fonctionnalité est disponible à partir de Perl 5.36.

La fonctionnalité 'extra_paired_delimiters'

AVERTISSEMENT: Cette fonctionnalité est toujours expérimentale et l'implémentation peut changer ou être supprimée dans les futures versions de Perl. Pour cette raison, Perl émettra un avertissement lorsque vous utiliserez cette fonctionnalité, sauf si vous avez explicitement désactivé l'avertissement :

no warnings "experimental::extra_paired_delimiters";

Cette fonctionnalité permet l'utilisation de plus de délimiteurs de chaîne appariés que les quatre traditionnels, "< >"pan>, "( )", "{ }", et "[ ]". Lorsque cette fonctionnalité est activée, par exemple, vous pouvez écrire "qr«pat»".

Comme pour toute utilisation de délimiteurs non-ASCII dans un fichier source encodé en UTF-8, vous devrez vous assurer que l'analyseur décodera le code source depuis des octets UTF-8 grâce à une déclaration telle que "use utf8".

Cette fonctionnalité est disponible à partir de Perl 5.36.

Pour la liste complète des caractères disponibles, voir « List of Extra Paired Delimiters » dans perlop.

La fonctionnalité 'module_true'

Cette fonctionnalité supprime la nécessité de renvoyer une valeur vraie à la fin d'un module chargé avec "require" ou "use". Toute erreur pendant la compilation provoquera un échec, mais le fait d'atteindre la fin du module lorsque cette fonctionnalité est en vigueur empêchera "perl" de lever une exception indiquant que le module « did not return a true value ».

La fonctionnalité 'class'

AVERTISSEMENT: Cette fonctionnalité est encore expérimentale et l'implémentation peut changer ou être supprimée dans les futures versions de Perl. Pour cette raison, Perl émettra un avertissement lorsque vous utiliserez cette fonctionnalité, sauf si vous avez explicitement désactivé l'avertissement :

no warnings "experimental::class";

Cette fonctionnalité active la "class" syntaxe de bloc et d'autres mots-clés associés qui implémentent le système d'objets « new », précédemment nommé « Corinna ».

La fonctionnalité 'apostrophe_as_package_separator'

Cette fonctionnalité permet d'utiliser "'" (apostrophe) comme alternative à l'utilisation de "::" comme séparateur dans les noms de paquets et autres noms globaux.

Elle est activée par défaut, mais désactivée à partir du paquet de fonctionnalités 5.42. Dans les versions précédentes, elle était toujours activée.

Cela ne désactive que "'" dans les symboles de votre code source ; la conversion interne de "'" vers "::", y compris pour les références symboliques, est toujours activée.

La fonctionnalité 'keyword_any'

AVERTISSEMENT: Cette fonctionnalité est encore expérimentale et l'implémentation peut changer ou être supprimée dans les futures versions de Perl. Pour cette raison, Perl émettra un avertissement lorsque vous utiliserez cette fonctionnalité, sauf si vous avez explicitement désactivé l'avertissement :

no warnings "experimental::keyword_any";

Cette fonctionnalité active le "any" mot-clé d'opérateur. Cela permet de tester si l'une des valeurs d'une liste satisfait une condition donnée, avec un comportement de court-circuit dès qu'elle en trouve une.

La fonctionnalité 'keyword_all'

AVERTISSEMENT: Cette fonctionnalité est encore expérimentale et l'implémentation peut changer ou être supprimée dans les futures versions de Perl. Pour cette raison, Perl émettra un avertissement lorsque vous utiliserez cette fonctionnalité, sauf si vous avez explicitement désactivé l'avertissement :

no warnings "experimental::keyword_all";

Cette fonctionnalité active le "all" mot-clé d'opérateur. Cela permet de tester si toutes les valeurs d'une liste satisfont une condition donnée, avec un comportement de court-circuit dès qu'elle en trouve une qui ne la satisfait pas.

use feature ":5.10";

Le ":default" paquet représente l'ensemble des fonctionnalités activé avant toute déclaration "use feature" ou "no feature" .

Spécifier des sous-versions telles que le 0 dans 5.14.0 dans les paquets de fonctionnalités n'a aucun effet. Les paquets de fonctionnalités sont garantis identiques pour toutes les sous-versions.

use feature ":5.14.0";    # same as ":5.14"
use feature ":5.14.1";    # same as ":5.14"

Vous pouvez aussi faire :

use feature ":all";

ou

no feature ":all";

mais la première peut activer des fonctionnalités d'une version ultérieure de Perl qui changent la signification de votre code, et la seconde peut désactiver des mécanismes qui font partie du comportement actuel de Perl et qui ont été transformés en fonctionnalités, tout comme "indirect" et "bareword_filehandles" l'ont été.

CHARGEMENT IMPLICITE

Au lieu de charger les paquets de fonctionnalités par nom, il est plus simple de laisser Perl faire le chargement implicite d'un paquet de fonctionnalités pour vous.

Il y a deux façons de charger la pragma "feature" implicitement :

  • En utilisant l'option "-E" sur la ligne de commande de Perl au lieu de "-e". Cela activera le paquet de fonctionnalités pour cette version de Perl dans l'unité de compilation principale (c'est-à-dire la ligne de commande qui suit "-E").
  • En exigeant explicitement un numéro de version minimum de Perl pour votre programme, avec la construction "use VERSION" . C'est-à-dire 
    use v5.36.0;

    fera implicitement

    no feature ':all';
use feature ':5.36';

    et ainsi de suite. Notez comment la sous-version finale est automatiquement retirée de la version.

    Mais pour éviter des avertissements de portabilité (voir « use » dans perlfunc), vous préférerez peut-être :

    use 5.036;

    avec le même effet.

    Si la version requise est antérieure à Perl 5.10, le paquet de fonctionnalités ":default" est chargé automatiquement à la place.

    Contrairement à "use feature ":5.12"", écrire "use v5.12" (ou toute version supérieure) fait aussi l'équivalent de "use strict"; voir « use » dans perlfunc pour plus de détails.

VÉRIFICATION DES FONCTIONNALITÉS

"feature" fournit quelques API simples pour vérifier quelles fonctionnalités sont activées.

Ces fonctions ne peuvent pas être importées et doivent être appelées par leurs noms qualifiés complets. Si vous n'avez pas autrement besoin de définir une fonctionnalité, vous devrez vous assurer que "feature" est chargé avec :

use feature ();
feature_enabled($feature)
feature_enabled($feature, $depth)
package MyStandardEnforcer;
use feature ();
use Carp "croak";
sub import {
  croak "disable indirect!" if feature::feature_enabled("indirect");
}

NAME

    
feature - pragma for enabling/disabling language features


    
SYNOPSIS

    
  use feature 'foo';
  use feature qw( foo bar );
  use feature ':5.10';
  use feature ':default';
  use feature qw( :5.10 foo );
  use feature (); # Turn off all features for this scope
  no feature 'foo';
  no feature qw( foo bar );
  no feature ':5.10';
  no feature ':default';
  no feature qw( :5.10 foo );

  # Accessing features
  feature::feature_enabled('foo');
  feature::features_enabled();
  feature::feature_bundle();


    
DESCRIPTION

    
The feature pragma is used to enable
        or disable various language features. These features are grouped into
        named features (e.g. say, state)
        and feature bundles (e.g. :5.10, :default).
        Using the pragma is generally preferred over setting the
        $PERL_VERSION environment variable, as it is
        lexically scoped and does not affect other parts of the program.

    
When use feature is used, it enables
        features for the current scope and all nested scopes.

    
When no feature is used, it disables
        features for the current scope and all nested scopes.

    
The features are normally enabled and disabled implicitly by
        `use` statements of the form use vX.Y; or
        use vX.Y; version 'X.Y';, which enable the bundle
        of features associated with that Perl version.

    
The available features and feature bundles are described
        below.


    
AVAILABLE FEATURES

    

      
say

      

        
use feature 'say';

        
Enables the say function, which is
            like print but automatically appends a
            newline.

      

      
state

      

        
use feature 'state';

        
Enables the state declaration, which
            allows lexical variables to retain their values between calls to a
            subroutine.

      

      
switch

      

        
use feature 'switch';

        
Enables the switch statement, which
            provides a more structured way to handle multiple cases.

      

      
unicode_strings

      

        
use feature 'unicode_strings';

        
Enables Unicode stringification for strings that contain
            Unicode characters.

      

      
evalbytes

      

        
use feature 'evalbytes';

        
Enables evalbytes, which evaluates
            a string as Perl code in byte context.

      

      
regexp_sets

      

        
use feature 'regexp_sets';

        
Enables the use of character set extensions in regular
            expressions, such as [[:ascii:]].

      

      
signatures

      

        
use feature 'signatures';

        
Enables subroutine signatures, allowing parameters to be
            declared with types and default values.

      

      
array_and_hash_lexicals

      

        
use feature 'array_and_hash_lexicals';

        
Enables lexical arrays and hashes, which are scoped to the
            current block or subroutine.

      

      
postderef

      

        
use feature 'postderef';

        
Enables postfix dereferencing for arrays and hashes.

      

      
lexical_subs

      

        
use feature 'lexical_subs';

        
Enables lexical subroutines, which are scoped to the current
            block or subroutine.

      

      
multi_dispatch

      

        
use feature 'multi_dispatch';

        
Enables multimethod dispatch, allowing multiple subroutines
            with the same name but different parameter lists to be defined.

      

    


    
FEATURE BUNDLES

    
Feature bundles group related features together, typically
        corresponding to a specific Perl version.

    

      
:default

      

        
use feature ':default';

        
Enables the set of features that were considered default
            in a specific earlier version of Perl. This is usually equivalent to
            enabling the features for Perl 5.10.

      

      
:5.10

      

        
use feature ':5.10';

        
Enables the features that were introduced in Perl 5.10.
            This includes say, state,
            and switch.

      

      
:5.12

      

        
use feature ':5.12';

        
Enables the features that were introduced in Perl 5.12.
            This includes unicode_strings,
            evalbytes, and
            regexp_sets.

      

      
:5.14

      

        
use feature ':5.14';

        
Enables the features that were introduced in Perl 5.14.
            This includes signatures.

      

      
:5.16

      

        
use feature ':5.16';

        
Enables the features that were introduced in Perl 5.16.
            This includes array_and_hash_lexicals and
            postderef.

      

      
:5.18

      

        
use feature ':5.18';

        
Enables the features that were introduced in Perl 5.18.
            This includes lexical_subs and
            multi_dispatch.

      

    


    
IMPLICIT LOADING

    
The feature pragma can be used to
        enable features that are not enabled by default. For example, to use
        the say function, you would typically write:

    
  use feature 'say';
  say "Hello, world!";

    
Alternatively, you can enable a bundle of features associated
        with a specific Perl version:

    
  use feature ':5.10'; # Enables say, state, and switch

    
You can also specify a comma-separated list of features and
        bundles:

    
  use feature qw( :5.10 foo bar );

    
To disable features, use the no
        keyword:

    
  no feature 'say';

    
If you want to disable all features for a scope, you can use:

    
  use feature ();

    
And to re-enable all default features:

    
  use feature ':default';


    
CHECKING FEATURES

    
The feature module provides functions
        to check the status of features at runtime.

    

      
feature_enabled()

      

      
feature_enabled($name)

      

        
package ReportEnabledFeatures;
use feature "say"; # Example: Enable 'say'
sub import {
  say STDERR "Checking feature 'say' at depth 1:";
  say STDERR feature::feature_enabled('say');
  say STDERR "Checking feature 'state' at depth 1:";
  say STDERR feature::feature_enabled('state');
}


        
Test whether a named feature is enabled at a given level in
            the call stack, returning a true value if it is.
            $depth defaults to 1, which checks the scope
            that called the scope calling feature::feature_enabled().

        
croaks for an unknown feature name.

      

      
features_enabled()

      

      
features_enabled($depth)

      

        
package ReportEnabledFeatures;
use feature "say";
sub import {
  say STDERR join " " , feature::features_enabled();
}


        
Returns a list of the features enabled at a given level in the
            call stack. $depth defaults to 1, which checks
            the scope that called the scope calling
            feature::features_enabled().

      

      
feature_bundle()

      

      
feature_bundle($depth)

      
Returns the feature bundle, if any, selected at a given level in the call
          stack. $depth defaults to 1, which checks
          the scope that called the scope calling feature::feature_bundle().
        
Returns an undefined value if no feature bundle is selected in
            the scope.

        
The bundle name returned will be for the earliest bundle
            matching the selected bundle, so:

            
use feature ();
use v5.12;
BEGIN { print feature::feature_bundle(0); }


        
will print 5.11.

        
This returns internal state, at this point
            "use v5.12;" sets the feature bundle,
            but " use feature ":5.12"; "
            does not set the feature bundle. This may change in a future release of
            perl.
