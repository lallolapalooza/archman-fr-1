FFI::CheckLib(3) Documentation Perl contribuée par les utilisateurs FFI::CheckLib(3)

NOM

FFI::CheckLib - Vérifier qu'une bibliothèque est disponible pour FFI

VERSION

version 0.31

SYNOPSIS

use FFI::CheckLib;

check_lib_or_exit( lib => 'jpeg', symbol => 'jinit_memory_mgr' );
check_lib_or_exit( lib => [ 'iconv', 'jpeg' ] );

# ou demander le chemin vers la bibliothèque puis :
print "où trouver la bibliothèque jpeg : ";
my $path = <STDIN>;
check_lib_or_exit( lib => 'jpeg', libpath => $path );

DESCRIPTION

Ce module vérifie si une bibliothèque dynamique particulière est disponible pour FFI. Il est fortement inspiré de Devel::CheckLib, mais trouvera les bibliothèques dynamiques même lorsque les paquets de développement ne sont pas installés. Il fournit également une fonction find_lib qui renverra le chemin complet vers la bibliothèque dynamique trouvée, qui peut être transmis directement à FFI::Platypus ou un autre système FFI.

Bien qu'il soit principalement destiné aux modules FFI via FFI::Platypus et similaires, ce module n'utilise en fait aucun FFI pour sa détection et son sondage. Ce module n'a aucune dépendance d'exécution hors du noyau. La suite de tests dépend de Test2::Suite.

FONCTIONS

Toutes ces fonctions prennent les mêmes paramètres nommés et sont exportées par défaut.

find_lib

my(@libs) = find_lib(%args);

Cela renverra une liste de bibliothèques dynamiques, ou une liste vide si aucune n'a été trouvée.

[version 0.05]

Si appelé en contexte scalaire, elle renverra la première bibliothèque trouvée.

Les arguments sont des paires clé-valeur avec les clés suivantes :

lib
Doit être soit une chaîne avec le nom d'une seule bibliothèque, soit une référence vers un tableau de chaînes de noms de bibliothèques. Selon votre plateforme, "CheckLib" préfixera "lib" ou suffixera ".dll" ou ".so" lors de la recherche.

[version 0.11]

Comme cas particulier, si "*" est spécifié, alors toutes les bibliothèques trouvées correspondront.

libpath
Une chaîne ou un tableau de chemins supplémentaires où chercher les bibliothèques.
systempath
[version 0.11]

Une chaîne ou un tableau de chemins système où chercher au lieu de laisser FFI::CheckLib déterminer le chemin système. Vous pouvez définir ceci à "[]" afin de ne pas chercher dans les chemins système.

symbol
Une chaîne ou une liste de noms de symboles qui doivent être trouvés.
verify
Une référence de code utilisée pour vérifier qu'une bibliothèque est bien celle que vous voulez. Elle doit prendre deux arguments, qui sont le nom de la bibliothèque et le chemin complet vers le chemin du fichier de la bibliothèque. Elle doit renvoyer vrai si elle est acceptable, et faux sinon. Vous pouvez utiliser ceci en conjonction avec FFI::Platypus pour déterminer si elle répondra à vos besoins. Exemple : 
use FFI::CheckLib;
use FFI::Platypus;

my($lib) = find_lib(
  lib => 'foo',
  verify => sub {
    my($name, $libpath) = @_;

    my $ffi = FFI::Platypus->new;
    $ffi->lib($libpath);

    my $f = $ffi->function('foo_version', [] => 'int');

    return $f->call() >= 500; # nous acceptons la version 500 ou supérieure
  },
);
recursive
[version 0.11]

Rechercher récursivement les bibliothèques dans tous les chemins non système (ceux fournis via "libpath" ci-dessus).

try_linker_script
[version 0.24]

Certains fournisseurs fournissent des fichiers ".so" qui sont des scripts de liaison pointant vers la vraie bibliothèque partagée binaire. Ces scripts de liaison peuvent être utilisés par gcc ou clang, mais ne sont pas directement utilisables par FFI::Platypus et compagnie. Sur certaines plateformes, cette option utilisera la commande de liaison ("ld") pour tenter de résoudre le vrai ".so" pour les fichiers non binaires. Comme il y a un surcoût supplémentaire, cette option est désactivée par défaut.

Un exemple est libyaml sur les distributions Linux basées sur Red Hat. Sur Debian, cela est géré avec des liens symboliques et aucune astuce n'est nécessaire.

alien
[version 0.25]

Si aucune bibliothèque ne peut être trouvée, essayer les aliens donnés à la place. Les classes Alien spécifiées doivent fournir l'interface Alien::Base pour les bibliothèques dynamiques, c'est-à-dire qu'elles doivent fournir une méthode appelée "dynamic_libs" qui renvoie une liste de bibliothèques dynamiques.

[version 0.28]

Dans la version 0.28 et ultérieures, si l'Alien n'est pas installé, il sera ignoré et ce module ne cherchera que dans les répertoires système ou spécifiés. Ce module lèvera toujours une exception si l'Alien ne ressemble pas à un nom de module ou s'il ne fournit pas une méthode "dynamic_libs" (qui est implémentée par toutes les sous-classes d'Alien::Base).

[version 0.30] [changement cassant]

À partir de la version 0.30, les bibliothèques fournies par les Aliens sont préférées aux bibliothèques système. La réflexion initiale était que vous vouliez préférer les bibliothèques système car elles sont plus susceptibles d'être corrigées par les mises à jour système régulières. Malheureusement, la raison pour laquelle un module a besoin d'installer un Alien est probablement parce que la bibliothèque système n'est pas assez récente, nous préférons donc maintenant les Aliens.

assert_lib

assert_lib(%args);

Cela se comporte exactement comme find_lib, sauf qu'au lieu de renvoyer une liste vide en cas d'échec, elle lève une exception.

check_lib_or_exit

check_lib_or_exit(%args);

Cela se comporte exactement comme assert_lib, sauf qu'au lieu de mourir, elle émet un avertissement (avec exactement le même message d'erreur) et se termine. Ceci est destiné à être utilisé dans "Makefile.PL" ou "Build.PL"

find_lib_or_exit

[version 0.05]

my(@libs) = find_lib_or_exit(%args);

Cela se comporte exactement comme find_lib, sauf que si la bibliothèque n'est pas trouvée, elle appellera exit avec un diagnostic approprié.

find_lib_or_die

[version 0.06]

my(@libs) = find_lib_or_die(%args);

Cela se comporte exactement comme find_lib, sauf que si la bibliothèque n'est pas trouvée, elle mourra avec un diagnostic approprié.

check_lib

my $bool = check_lib(%args);

Cela se comporte exactement comme find_lib, sauf qu'elle renvoie vrai (1) si les bibliothèques appropriées sont trouvées, et faux (0) sinon.

which

[version 0.17]

my $path = which($name);

Renvoie le chemin vers la première bibliothèque qui correspond au nom donné.

Non exportée par défaut.

where

[version 0.17]

my @paths = where($name);

Renvoie les chemins vers toutes les bibliothèques qui correspondent au nom donné.

Non exportée par défaut.

has_symbols

[version 0.17]

my $bool = has_symbols($path, @symbol_names);

Renvoie vrai si tous les symboles peuvent être trouvés dans la bibliothèque dynamique située au chemin donné. Peut être utile en conjonction avec "verify" avec "find_lib" FFI::CheckLib(3pm)

NAME

FFI::CheckLib - Find shared libraries

VERSION

0.28

SYNOPSIS

    use FFI::CheckLib;

    # Check for a library
    if ( check_lib_or_abort('libfoo.so') ) {
        print "Found libfoo.so!\n";
    }

    # Get the path to the library
    my $libfoo_path = find_lib_path('libfoo.so');
    if ( $libfoo_path ) {
        print "Found libfoo.so at $libfoo_path\n";
    }

    # Get the path to a function in a library
    my $libfoo_func_path = find_lib_func_path('libfoo.so', 'foo_function');
    if ( $libfoo_func_path ) {
        print "Found foo_function in $libfoo_func_path\n";
    }

    # Get the path to a library that might be named differently
    my $libsomething_path = find_lib_path('libsomething.so', [qw( libanother.so libother.so )]);
    if ( $libsomething_path ) {
        print "Found libsomething (or alternative) at $libsomething_path\n";
    }

DESCRIPTION

FFI::CheckLib is a module that can be used to find shared libraries on a system. It's designed to be used by other modules that need to link against shared libraries.

This module has been designed to provide a portable way of finding libraries on Unix systems and also on Windows.

The basic idea is that you can ask for a library, and it will try to find it for you. It knows about various system paths, and the "PATH" environment variable (on Windows), and can be told about other paths as well.

It also knows about various package managers, like Homebrew and MacPorts on macOS.

FUNCTIONS

check_lib_or_abort

    check_lib_or_abort($libname, $alt_libname, ...)
    check_lib_or_abort($libname, \@alt_libnames)
    check_lib_or_abort($libname, \@alt_libnames, $funcname)
    check_lib_or_abort($libname, $funcname)

This is the most common function to use. It will look for $libname (and any alternatives specified). If a library is found, it returns true. If not, it will die with a message indicating that the library was not found, and giving some hints.

If $funcname is provided, it will look for that function within the library. If the function is not found, it will die.

This function is not exportable, even on request.

find_lib_path

    find_lib_path($libname, $alt_libname, ...)
    find_lib_path($libname, \@alt_libnames)

Looks for $libname (and any alternatives). Returns the path to the library if found, or undef if not found. This function will not die.

This function is not exportable, even on request.

find_lib_func_path

    find_lib_func_path($libname, $funcname)
    find_lib_func_path($libname, \@alt_libnames, $funcname)

Looks for $libname (and any alternatives), and also looks for $funcname within that library. Returns the path to the library if the function is found within it, or undef if not found.

This function is not exportable, even on request.

system_path

[version 0.20]

my $path = FFI::CheckLib::system_path;

Returns the system path as a list reference. On some systems, this is "PATH" on others it might be "LD_LIBRARY_PATH" on still others it could be something completely different. So although you may add items to this list, you should probably do some careful consideration before you do so.

This function is not exportable, even on request.

ENVIRONMENT

FFI::CheckLib responds to these environment variables:

FFI_CHECKLIB_PACKAGE
On macOS platforms with Homebrew http://brew.sh and/or MacPorts https://www.macports.org installed, their corresponding lib paths will be automatically appended to $system_path. In case of having both managers installed, Homebrew will appear before.

This behaviour can be overridden using the environment variable "FFI_CHECKLIB_PACKAGE".

Allowed values are:

- "none": Won't use either Homebrew's path nor MacPorts - "homebrew": Will append "$(brew --prefix)/lib" to the system paths - "macports": Will append "port"'s default lib path

A comma separated list is also valid:

export FFI_CHECKLIB_PACKAGE=macports,homebrew

Order matters. So in this example, MacPorts' lib path appears before Homebrew's path.

FFI_CHECKLIB_PATH
List of directories that will be considered by FFI::CheckLib as additional "system directories". They will be searched before other system directories but after "libpath". The variable is colon separated on Unix and semicolon separated on Windows. If you use this variable, "FFI_CHECKLIB_PACKAGE" will be ignored.
PATH
On Windows the "PATH" environment variable will be used as a search path for libraries.

On some operating systems "LD_LIBRARY_PATH", "DYLD_LIBRARY_PATH", "DYLD_FALLBACK_LIBRARY_PATH" or others may be used as part of the search for dynamic libraries and may be used (indirectly) by FFI::CheckLib as well.

FAQ

Why not just use "dlopen"?
Calling "dlopen" on a library name and then "dlclose" immediately can tell you if you have the exact name of a library available on a system. It does have a number of drawbacks as well.
No absolute or relative path
It only tells you that the library is somewhere on the system, not having the absolute or relative path makes it harder to generate useful diagnostics.
POSIX only
This doesn't work on non-POSIX systems like Microsoft Windows. If you are using a POSIX emulation layer on Windows that provides "dlopen", like Cygwin, there are a number of gotchas there as well. Having a layer written in Perl handles this means that developers on Unix can develop FFI that will more likely work on these platforms without special casing them.
inconsistent implementations
Even on POSIX systems you have inconsistent implementations. OpenBSD for example don't usually include symlinks for ".so" files meaning you need to know the exact ".so" version.
non-system directories
By default "dlopen" only works for libraries in the system paths. Most platforms have a way of configuring the search for different non-system paths, but none of them are portable, and are usually discouraged anyway. Alien and friends need to do searches for dynamic libraries in non-system directories for "share" installs.
My 64-bit Perl is misconfigured and has 32-bit libraries in its search path. Is that a bug in FFI::CheckLib?
Nope.
The way FFI::CheckLib is implemented it won't work on AIX, HP-UX, OpenVMS or Plan 9.
I know for a fact that it doesn't work on AIX as currently implemented because I used to develop on AIX in the early 2000s, and I am aware of some of the technical challenges. There are probably other systems that it won't work on. I would love to add support for these platforms. Realistically these platforms have a tiny market share, and absent patches from users or the companies that own these operating systems (patches welcome), or hardware / CPU time donations, these platforms are unsupportable anyway.
