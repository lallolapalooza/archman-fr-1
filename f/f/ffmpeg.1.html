DESCRIPTIO

N

ffmpeg est un convertisseur de médias universel. Il peut lire une grande variété d'entrées - y compris les périphériques de capture/enregistrement en direct - les filtrer et les transcoder dans une pléthore de formats de

sortie.

ffmpeg lit depuis un nombre arbitraire d'entrées (qui peuvent être des fichiers ordinaires, des tubes, des flux réseau, des périphériques de capture, etc.), spécifiées par l'option "-i", et écrit vers un nombre arbitraire de sorties, qui sont spécifiées par une simple url de sortie. Tout ce qui est trouvé sur la ligne de commande et qui ne peut pas être interprété comme une option est considéré comme une url de

sortie.

Chaque entrée ou sortie peut, en principe, contenir un nombre quelconque de flux élémentaires de types différents (vidéo/audio/sous-titres/pièce jointe/données), bien que le nombre de flux autorisés et/ou les types puissent être limités par le format de conteneur. La sélection des flux de quelles entrées qui iront dans quelle sortie est soit effectuée automatiquement soit avec l'option "-map" (voir le chapitre Sélection des flux)

.

Pour faire référence aux entrées/sorties dans les options, vous devez utiliser leurs indices (basés sur 0). Par exemple, la première entrée est 0, la deuxième est 1, etc. De même, les flux au sein d'une entrée/sortie sont référencés par leurs indices. Par exemple "2:3" fait référence au quatrième flux dans la troisième entrée ou sortie. Voir aussi le chapitre Spécificateurs de

flux.

En règle générale, les options sont appliquées au fichier spécifié suivant. Par conséquent, l'ordre est important, et vous pouvez avoir la même option sur la ligne de commande plusieurs fois. Chaque occurrence est alors appliquée à l'entrée ou au fichier de sortie suivant. Les exceptions à cette règle sont les options globales (par ex. le niveau de verbosité), qui doivent être spécifiées en

premier.

Ne mélangez pas les fichiers d'entrée et de sortie -- spécifiez d'abord tous les fichiers d'entrée, puis tous les fichiers de sortie. Ne mélangez pas non plus les options qui appartiennent à différents fichiers. Toutes les options ne s'appliquent QU'AU prochain fichier d'entrée ou de sortie et sont réinitialisées entre les

fichiers.

Streamcopy

Le pipeline le plus simple dans ffmpeg est le streamcopy à flux unique, c'est-à-dire la copie des paquets d'un flux élémentaire d'entrée sans les décoder, filtrer ou encoder. Par exemple, considérons un fichier d'entrée nommé ENTREE.mkv avec 3 flux élémentaires, dont nous prenons le deuxième pour l'écrire dans le fichier SORTIE.mp4. Une représentation schématique d'un tel pipeline ressemble à ceci :

┌──────────┬─────────────────────┐
│ démultiplexeur │                     │ inutilisé
╞══════════╡ flux élémentaire 0 ├────────╳
│          │                     │
│ENTREE.mkv ├─────────────────────┤          ┌
──────────────────────┬───────────┐ │ │ │ paquets │ │ multiplexeur │ │ │ flux élémentaire 1 ├─────────►│ flux élémentaire 0 ╞═══════════╡ │ │ │ │ │SORTIE.mp4 │ │ ├─────────────────────┤ └──────────────────────┴───────────┘ │ │ │ inutilisé │ │ flux élémentaire 2 ├────────╳ │ │ │ └──────────┴─────────────────────┘

Le pipeline ci-dessus peut être construit avec la commande suivante :

ffmpeg -i ENTREE.mkv -map 0:1 -c copy SORTIE.mp4

Dans cette ligne de commande

  • il y a une seule entrée ENTREE.mkv;
  • il n'y a pas d'options d'entrée pour cette entrée;
  • il y a une seule sortie SORTIE.mp4;
  • il y a deux options de sortie pour cette sortie :
  • "-map 0:1" sélectionne le flux d'entrée à utiliser - de l'entrée d'index 0 (c'est-à-dire la première) le flux d'index 1 (c'est-à-dire le deuxième);
  • "-c copy" sélectionne l'encodeur "copy", c'est-à-dire la copie de flux sans décodage ni encodage.

La copie de flux est utile pour changer le nombre de flux élémentaires, le format du conteneur, ou modifier les métadonnées au niveau du conteneur. Comme il n'y a ni décodage ni encodage, c'est très rapide et il n'y a aucune perte de qualité. Cependant, cela peut ne pas fonctionner dans certains cas en raison de divers facteurs (par exemple, certaines informations requises par le conteneur cible ne sont pas disponibles dans la source). L'application de filtres est évidemment également impossible, car les filtres travaillent sur les images décodées.

Des scénarios de copie de flux plus complexes peuvent être construits - par exemple, combiner des flux de deux fichiers d'entrée en une seule sortie :

┌──────────┬────────────────────┐         ┌───────────────────┬───────────┐
│ démultiplexeur 0│                    │ paquets │                    │   multiplexeur   │
╞══════════╡flux élémentaire 0 ├────────►│flux élémentaire 0 ╞═══════════╡
│ENTREE0.mkv│                    │         │                    │SORTIE.mp4 │
└──────────┴────────────────────┘         ├───────────────────┤           │
┌──────────┬────────────────────┐         │                    │           │
│ démultiplexeur 1│                    │ paquets │flux élémentaire 1 │           │
╞══════════╡flux élémentaire 0 ├────────►│                    │           │
│ENTREE1.aac│                    │         └────────────────────┴───────────┘
└──────────┴────────────────────┘

qui peut être construit par la commande

ffmpeg -i ENTREE0.mkv -i ENTREE1.aac -map 0:0 -map 1:0 -c copy SORTIE.mp4

L'option de sortie -map est utilisée deux fois ici, créant deux flux dans le fichier de sortie - un alimenté par la première entrée et un par la seconde. L'unique instance de l'option -c sélectionne la copie de flux pour chacun de ces flux. Vous pourriez également utiliser des instances multiples de cette option conjointement avec les Spécificateurs de flux pour appliquer des valeurs différentes à chaque flux, comme cela sera démontré dans les sections suivantes.

Un scénario inverse consiste à diviser plusieurs flux d'une seule entrée en plusieurs sorties :

│ démultiplexeur │                     │ paquets  │                   │ multiplexeur 0   │

Ces exemples peuvent bien sûr être généralisés en remappage arbitraires de n'importe quel nombre d'entrées vers n'importe quel nombre de sorties.

Transcodage

Le transcodage est le processus de décodage d'un flux puis de le ré-encoder. L'encodage étant généralement coûteux en calcul et dans la plupart des cas dégradant la qualité du flux (c'est-à-dire qu'il est avec perte), vous ne devriez transcoder que lorsque c'est nécessaire et effectuer une copie de flux sinon. Les raisons typiques de transcoder sont :

  • l'application de filtres - par exemple, redimensionnement, désentrelacement, ou superposition de vidéo ; ré-échantillonnage ou mixage audio ;
  • vous voulez alimenter le flux à quelque chose qui ne peut pas décoder le codec original.

Notez que ffmpeg transcodera tous les flux audio, vidéo et sous-titres à moins que vous ne spécifiiez -c copy pour eux.

Filtrage

Lors de la transcodification, les flux audio et vidéo peuvent être filtrés avant l'encodage, avec un graphique de filtres *simple* ou *complexe*.

Graphiques de filtres simples

Les graphiques de filtres simples sont ceux qui ont exactement une entrée et une sortie, toutes deux du même type (audio ou vidéo). Ils sont configurés avec l'option -filter par flux (avec les alias -vf et -af pour -filter:v (vidéo) et -filter:a (audio) respectivement). Notez que les graphiques de filtres simples sont liés à leur flux de sortie, donc par exemple, si vous avez plusieurs flux audio, -af créera un graphique de filtres séparé pour chacun d'eux.

Graphiques de filtres complexes

Les graphiques de filtres complexes sont ceux qui ne peuvent pas être décrits comme une simple chaîne de traitement appliquée à un seul flux. C'est le cas, par exemple, lorsque le graphique a plus d'une entrée et/ou sortie, ou lorsque le type de flux de sortie est différent de celui de l'entrée. Les graphiques de filtres complexes sont configurés avec l'option -filter_complex. Notez que cette option est globale, car un graphique de filtres complexe, par sa nature, ne peut pas être associé sans ambiguïté à un seul flux ou fichier. Chaque instance de -filter_complex crée un nouveau graphique de filtres complexe, et il peut y en avoir un nombre quelconque.

Un exemple trivial de graphique de filtres complexe est le filtre "overlay", qui a deux entrées vidéo et une sortie vidéo, contenant une vidéo superposée à une autre. Son homologue audio est le filtre "amix".

Décodeurs en boucle

Bien que les décodeurs soient normalement associés aux flux de démultiplexage, il est également possible de créer des décodeurs "en boucle" qui décodent la sortie d'un encodeur et permettent de la réinjecter dans des graphiques de filtres complexes. Ceci est fait avec la directive "-dec", qui prend comme paramètre l'index du flux de sortie qui doit être décodé. Chaque directive de ce type crée un nouveau décodeur en boucle, indexé avec des entiers successifs commençant à zéro. Ces indices doivent ensuite être utilisés pour faire référence aux décodeurs en boucle dans les étiquettes de liaison du graphique de filtres complexe, comme décrit dans la documentation de -filter_complex.

Les AVOptions de décodage peuvent être passées aux décodeurs en boucle en les plaçant avant "-dec", de manière analogue aux options d'entrée/sortie.

Par exemple, l'exemple suivant :

ffmpeg -i INPUT                                        \
  -map 0:v:0 -c:v libx264 -crf 45 -f null -            \
  -threads 3 -dec 0:0                                  \
  -filter_complex '[0:v][dec:0]hstack[stack]'          \
  -map '[stack]' -c:v ffv1 OUTPUT

SÉLECTION DE FLUX

ffmpeg fournit l'option "-map" pour un contrôle manuel de la sélection des flux dans chaque fichier de sortie. Les utilisateurs peuvent ignorer "-map" et laisser ffmpeg effectuer la sélection automatique des flux comme décrit ci-dessous. Les options "-vn / -an / -sn / -dn" peuvent être utilisées pour omettre l'inclusion des flux vidéo, audio, sous-titres et données respectivement, qu'ils soient sélectionnés manuellement ou automatiquement, à l'exception des flux qui sont les sorties de graphes de filtres complexes.

Description

Les sous-sections suivantes décrivent les diverses règles impliquées dans la sélection des flux. Les exemples qui suivent montrent ensuite comment ces règles sont appliquées en pratique.

Bien que tous les efforts soient faits pour refléter fidèlement le comportement du programme, FFmpeg est en développement continu et le code peut avoir changé depuis la rédaction de ce document.

Sélection automatique des flux

En l'absence de toute option de mappage pour un fichier de sortie particulier, ffmpeg inspecte le format de sortie pour vérifier quels types de flux peuvent y être inclus, à savoir : vidéo, audio et/ou sous-titres. Pour chaque type de flux acceptable, ffmpeg sélectionnera un flux, lorsqu'il est disponible, parmi toutes les entrées.

Il sélectionnera ce flux selon les critères suivants :

  • pour la vidéo, c'est le flux avec la plus haute résolution,
  • pour l'audio, c'est le flux avec le plus grand nombre de canaux,
  • pour les sous-titres, c'est le premier flux de sous-titres trouvé, mais il y a une mise en garde. L'encodeur de sous-titres par défaut du format de sortie peut être basé sur du texte ou sur des images, et seul un flux de sous-titres du même type sera choisi.

Dans le cas où plusieurs flux du même type sont à égalité, le flux avec l'indice le plus bas est choisi.

Les flux de données ou de pièces jointes ne sont pas sélectionnés automatiquement et ne peuvent être inclus qu'en utilisant "-map".

Sélection manuelle des flux

Lorsque "-map" est utilisé, seuls les flux mappés par l'utilisateur sont inclus dans ce fichier de sortie, avec une exception possible pour les sorties de graphes de filtres décrites ci-dessous.

Graphes de filtres complexes

S'il existe des flux de sortie de graphes de filtres complexes avec des tampons non étiquetés, ils seront ajoutés au premier fichier de sortie. Cela entraînera une erreur fatale si le type de flux n'est pas pris en charge par le format de sortie. En l'absence de l'option de mappage, l'inclusion de ces flux conduit à l'omission de la sélection automatique des flux de leurs types. Si des options de mappage sont présentes, ces flux de graphes de filtres sont inclus en plus des flux mappés.

Les flux de sortie de graphes de filtres complexes avec des tampons étiquetés doivent être mappés une fois et une seule fois.

Gestion des flux

La gestion des flux est indépendante de la sélection des flux, à l'exception des sous-titres décrits ci-dessous. La gestion des flux est définie via l'option "-codec" s'adressant aux flux d'un fichier de sortie spécifique. En particulier, les options de codec sont appliquées par ffmpeg après le processus de sélection des flux et n'influencent donc pas ce dernier. Si aucune option "-codec" n'est spécifiée pour un type de flux, ffmpeg sélectionnera l'encodeur par défaut enregistré par le multiplexeur du fichier de sortie.

Une exception existe pour les sous-titres. Si un encodeur de sous-titres est spécifié pour un fichier de sortie, le premier flux de sous-titres trouvé, quel que soit son type (texte ou image), sera inclus. ffmpeg ne vérifie pas si l'encodeur spécifié peut convertir le flux sélectionné ou si le flux converti est acceptable dans le format de sortie. Cela s'applique généralement aussi : lorsque l'utilisateur définit manuellement un encodeur, le processus de sélection des flux ne peut pas vérifier si le flux encodé peut être multiplexé dans le fichier de sortie. Si ce n'est pas le cas, ffmpeg s'arrêtera et *tous* les fichiers de sortie ne seront pas traités.

Options AV

Ces options sont fournies directement par les bibliothèques libavformat, libavdevice et libavcodec. Pour voir la liste des Options AV disponibles, utilisez l'option -help. Elles sont séparées en deux catégories :

générique
Ces options peuvent être définies pour n'importe quel conteneur, codec ou périphérique. Les options génériques sont listées sous les options AVFormatContext pour les conteneurs/périphériques et sous les options AVCodecContext pour les codecs.
privée
Ces options sont spécifiques au conteneur, périphérique ou codec donné. Les options privées sont listées sous leurs conteneurs/périphériques/codecs correspondants.

Par exemple, pour écrire un en-tête ID3v2.3 au lieu de la version ID3v2.4 par défaut dans un fichier MP3, utilisez l'option privée id3v2_version du multiplexeur MP3 :

ffmpeg -i input.flac -id3v2_version 3 out.mp3

Toutes les options AV de codec sont par flux, et donc un spécificateur de flux doit leur être attaché :

ffmpeg -i multichannel.mxf -map 0:v:0 -map 0:a:0 -map 0:a:0 -c:a:0 ac3 -b:a:0 640k -ac:a:1 2 -c:a:1 aac -b:2 128k out.mp4

Dans l'exemple ci-dessus, un flux audio multicanal est mappé deux fois en sortie. La première instance est encodée avec le codec ac3 et un débit de 640k. La deuxième instance est réduite à 2 canaux et encodée avec le codec aac. Un débit de 128k lui est spécifié en utilisant l'indice absolu du flux de sortie.

Note : la syntaxe -nooption ne peut pas être utilisée pour les Options AV booléennes, utilisez -option 0/-option 1.

Note : l'ancienne méthode non documentée pour spécifier les Options AV par flux en préfixant v/a/s au nom de l'option est maintenant obsolète et sera supprimée prochainement.

En tant qu'option de sortie, désactive l'enregistrement des données, c'est-à-dire la sélection ou le mappage automatique de tout flux de données. Pour un contrôle manuel complet, voir l'option "-map".

Utilise une échelle de qualité fixe (VBR). La signification de q/qscale dépend du codec. Si qscale est utilisé sans spécificateur_de_flux, il s'applique uniquement au flux vidéo, ceci afin de maintenir la compatibilité avec le comportement précédent et car la spécification de la même valeur spécifique au codec pour 2 codecs différents, audio et vidéo, n'est généralement pas ce qui est prévu lorsqu'aucun spécificateur_de_flux n'est utilisé.
-filter[:spécificateur_de_flux] graphe_de_filtres (sortie,par-flux)
Crée le graphe de filtres spécifié par graphe_de_filtres et l'utilise pour filtrer le flux.

graphe_de_filtres est une description du graphe de filtres à appliquer au flux, et doit avoir une seule entrée et une seule sortie du même type que le flux. Dans le graphe de filtres, l'entrée est associée à l'étiquette "in", et la sortie à l'étiquette "out". Voir le manuel ffmpeg-filters pour plus d'informations sur la syntaxe du graphe de filtres.

Voir l'option -filter_complex si vous souhaitez créer des graphes de filtres avec plusieurs entrées et/ou sorties.

-reinit_filter[:spécificateur_de_flux] entier (entrée,par-flux)
Cette option booléenne détermine si les graphes de filtres auxquels ce flux est alimenté sont réinitialisés lorsque les paramètres des images d'entrée changent en cours de flux. Cette option est activée par défaut car la plupart des filtres vidéo et tous les filtres audio ne peuvent pas gérer les déviations des propriétés des images d'entrée. Lors de la réinitialisation, l'état existant du filtre est perdu, comme par exemple la référence au compteur d'images "n" disponible dans certains filtres. Les images mises en mémoire tampon au moment de la réinitialisation sont perdues. Les propriétés dont un changement déclenche la réinitialisation sont, pour la vidéo, la résolution de l'image ou le format des pixels ; pour l'audio, le format des échantillons, le taux d'échantillonnage, le nombre de canaux ou la disposition des canaux.
-drop_changed[:spécificateur_de_flux] entier (entrée,par-flux)
Cette option booléenne détermine si une image avec des paramètres d'image différents en cours de flux est ignorée au lieu d'entraîner une réinitialisation du graphe de filtres, car cela entraînerait une perte d'état du filtre. Utile en général pour éviter les paquets corrompus mais décodables dans les flux d'entrée en direct. La valeur par défaut est false.
-filter_threads nb_threads (global)
Définit le nombre de threads utilisés pour traiter un pipeline de filtres. Chaque pipeline produira un pool de threads avec ce nombre de threads disponibles pour le traitement parallèle. La valeur par défaut est le nombre de CPU disponibles.
-filter_buffered_frames nb_frames (global)
Définit le nombre maximum d'images mises en mémoire tampon autorisées dans un graphe de filtres. Dans des circonstances normales, un graphe de filtres ne devrait pas mettre en mémoire tampon plus que quelques images, surtout si les images lui sont fournies et lues de manière équilibrée (ce qui est le comportement prévu dans ffmpeg). Cela dit, cette option vous permet de limiter le nombre total d'images mises en mémoire tampon sur toutes les liaisons d'un graphe de filtres. Si plus d'images sont générées, le filtrage est interrompu et une erreur est renvoyée. La valeur par défaut est 0, ce qui signifie aucune limite.

-progress url (global)
Envoie des informations de progression conviviales pour les programmes à url.

Les informations de progression sont écrites périodiquement et à la fin du processus d'encodage. Elles sont composées de lignes "clé=valeur". La clé ne contient que des caractères alphanumériques. La dernière clé d'une séquence d'informations de progression est toujours "progress" avec la valeur "continue" ou "end".

La période de mise à jour est définie à l'aide de "-stats_period".

Par exemple, pour enregistrer les informations de progression sur stdout :

Active l'interaction sur l'entrée standard. Activé par défaut sauf si l'entrée standard est utilisée comme entrée. Pour désactiver explicitement l'interaction, vous devez spécifier "-nostdin".

Affiche des informations sur les horodatages/la latence. Désactivé par défaut. Cette option est principalement utile à des fins de test et de débogage, et le format de sortie peut changer d'une version à l'autre, elle ne doit donc pas être utilisée par des scripts portables.

Voir aussi l'option "-fdebug ts".

-attach nom_de_fichier (sortie)
Ajoute une pièce jointe au fichier de sortie. Ceci est supporté par quelques formats comme Matroska, par exemple pour les polices utilisées dans le rendu des sous-titres. Les pièces jointes sont implémentées comme un type spécifique de flux, donc cette option ajoutera un nouveau flux au fichier. Il est alors possible d'utiliser des options par flux sur ce flux de la manière habituelle. Les flux de pièces jointes créés avec cette option seront créés après tous les autres flux (c'est-à-dire ceux créés avec "-map" ou les mappages automatiques).

Notez que pour Matroska, vous devez également définir la balise de métadonnées mimetype :

ffmpeg -i INPUT -attach DejaVuSans.ttf -metadata:s:2 mimetype=application/x-truetype-font out.mkv

(en supposant que le flux de pièce jointe sera le troisième dans le fichier de sortie).

-dump_attachment[:spécificateur_de_flux] nom_de_fichier (entrée,par-flux)
Extrait le flux de pièce jointe correspondant dans un fichier nommé nom_de_fichier. Si nom_de_fichier est vide, alors la valeur de la balise de métadonnées "filename" sera utilisée.

Par exemple, pour extraire la première pièce jointe dans un fichier nommé 'out.ttf' :

ffmpeg -dump_attachment:t:0 out.ttf -i INPUT

Pour extraire toutes les pièces jointes dans des fichiers déterminés par la balise "filename" :

ffmpeg -dump_attachment:t "" -i INPUT

Note technique -- les pièces jointes sont implémentées comme des données supplémentaires de codec, donc cette option peut en fait être utilisée pour extraire des données supplémentaires de n'importe quel flux, pas seulement des pièces jointes.

-r[:spécificateur_flux] fps (entrée/sortie,par-flux)
Définit la fréquence d'images (valeur Hz, fraction ou abréviation).

En tant qu'option d'entrée, ignore tous les horodatages stockés dans le fichier et génère à la place des horodatages en supposant une fréquence d'images constante fps. Ce n'est pas la même chose que l'option -framerate utilisée pour certains formats d'entrée comme image2 ou v4l2 (c'était la même chose dans les anciennes versions de FFmpeg). En cas de doute, utilisez -framerate au lieu de l'option d'entrée -r.

En tant qu'option de sortie :

encodage vidéo
Duplique ou supprime des images juste avant de les encoder pour atteindre une fréquence d'images de sortie constante fps.
copie_flux_vidéo
Indique au multiplexeur que fps est la fréquence d'images du flux. Aucune donnée n'est supprimée ou dupliquée dans ce cas. Cela peut produire des fichiers invalides si fps ne correspond pas à la fréquence d'images réelle du flux telle que déterminée par les horodatages des paquets. Voir aussi le filtre de flux binaire "setts".
-fpsmax[:spécificateur_flux] fps (sortie,par-flux)
Définit la fréquence d'images maximale (valeur Hz, fraction ou abréviation).

Limite la fréquence d'images de sortie lorsque la fréquence d'images de sortie est définie automatiquement et est supérieure à cette valeur. Utile dans le traitement par lots ou lorsque la fréquence d'images d'entrée est détectée à tort comme étant très élevée. Elle ne peut pas être définie en même temps que "-r". Elle est ignorée lors de la copie de flux.

-s[:spécificateur_flux] taille (entrée/sortie,par-flux)
Définit la taille de l'image.

En tant qu'option d'entrée, ceci est un raccourci pour l'option privée video_size, reconnue par certains démultiplexeurs pour lesquels la taille de l'image n'est pas stockée dans le fichier ou est configurable -- par exemple, vidéo brute ou enregistreurs vidéo.

En tant qu'option de sortie, ceci insère le filtre vidéo "scale" à la fin du graphe de filtres correspondant. Veuillez utiliser directement le filtre "scale" pour l'insérer au début ou à un autre endroit.

Le format est lxh (par défaut - identique à la source).

-aspect[:spécificateur_flux] rapport_aspect (sortie,par-flux)
Définit le rapport d'aspect d'affichage vidéo spécifié par rapport_aspect.

rapport_aspect peut être une chaîne de caractères représentant un nombre à virgule flottante, ou une chaîne de la forme num:den, où num et den sont le numérateur et le dénominateur du rapport d'aspect. Par exemple, "4:3", "16:9", "1.3333" et "1.7777" sont des valeurs d'arguments valides.

Cette option remplace les métadonnées de rotation/transformation d'affichage stockées dans le fichier, le cas échéant. Lorsque la vidéo est transcodée (plutôt que copiée) et que "-autorotate" est activé, la vidéo sera tournée à l'étape de filtrage. Sinon, les métadonnées seront écrites dans le fichier de sortie si le multiplexeur les prend en charge.

Si les options "-display_hflip" et/ou "-display_vflip" sont données, elles sont appliquées après la rotation spécifiée par cette option.

Sélectionne le numéro de passage (1 ou 2). Il est utilisé pour effectuer un encodage vidéo en deux passes. Les statistiques de la vidéo sont enregistrées lors de la première passe dans un fichier journal (voir aussi l'option -passlogfile), et lors de la deuxième passe, ce fichier journal est utilisé pour générer la vidéo au débit binaire exact demandé. Lorsque le redimensionnement automatique est désactivé, toutes les images de sortie du graphe de filtres peuvent ne pas avoir la même résolution et peuvent être inadéquates pour certains encodeurs/multiplexeurs. Par conséquent, il n'est pas recommandé de le désactiver à moins que vous ne sachiez vraiment ce que vous faites. Désactivez le redimensionnement automatique à vos risques et périls.

-force_key_frames[:spécificateur_flux] temps[,temps...] (sortie,par-flux)
-force_key_frames[:spécificateur_flux] expr:expression (sortie,par-flux)
-force_key_frames[:spécificateur_flux] source (sortie,par-flux)
force_key_frames peut prendre des arguments de la forme suivante :
temps[,temps...]
Si l'argument est constitué d'horodatages, ffmpeg arrondira les horodatages spécifiés à l'horodatage de sortie le plus proche, selon la base de temps de l'encodeur, et forcera une image clé sur la première image dont l'horodatage est égal ou supérieur à l'horodatage calculé. Notez que si la base de temps de l'encodeur est trop grossière, les images clés peuvent être forcées sur des images dont les horodatages sont inférieurs au temps spécifié. La base de temps de l'encodeur par défaut est l'inverse de la fréquence d'images de sortie, mais peut être définie différemment via "-enc_time_base".

L'expression dans expression peut contenir les constantes suivantes :

n
le numéro de l'image en cours de traitement, commençant à 0
n_forced

NOM

ffmpeg — enregistreur et lecteur multimédia FFmpeg

SYNTAXIS

ffmpeg [options] [input_file...] [output_file...]

DESCRIPTION

ffmpeg est un convertisseur vidéo et audio très rapide, capable de lire des données issues de diverses sources et de les transcoder dans différents formats, y compris des formats audio et vidéo propriétaires, tels que ceux utilisés par Apple, MS-$(WORD_UPPERCASE) ou Real Networks, ainsi que des formats libres tels que Ogg Vorbis.

La liste des formats et codecs supportés est très longue. Utilisez les options -formats, -codecs, -decoders, -encoders, -bsfs, -protocols, -filters pour lister les capacités de votre build de ffmpeg.

ffmpeg peut utiliser les bibliothèques libavcodec, libavformat, libavutil et libswscale.

EXEMPLES

Acquisition vidéo et audio

Si vous spécifiez le format et le périphérique d'entrée, alors ffmpeg peut acquérir la vidéo et l'audio directement.

ffmpeg -f oss -i /dev/dsp -f video4linux2 -i /dev/video0 /tmp/out.mpg

Ou avec une source audio ALSA (entrée mono, ID de carte 1) au lieu d'OSS :

ffmpeg -f alsa -ac 1 -i hw:1 -f video4linux2 -i /dev/video0 /tmp/out.mpg

Notez que vous devez activer la bonne source et le bon canal vidéo avant de lancer ffmpeg avec n'importe quel visualiseur TV tel que http://linux.bytesex.org/xawtv/ par Gerd Knorr. Vous devez également régler correctement les niveaux d'enregistrement audio avec un mixeur standard.

Acquisition X11

Acquisition de l'écran X11 avec ffmpeg via

ffmpeg -f x11grab -video_size cif -framerate 25 -i :0.0 /tmp/out.mpg

0.0 est le numéro de display.screen de votre serveur X11, identique à la variable d'environnement DISPLAY.

ffmpeg -f x11grab -video_size cif -framerate 25 -i :0.0+10,20 /tmp/out.mpg

0.0 est le numéro de display.screen de votre serveur X11, identique à la variable d'environnement DISPLAY. 10 est le décalage x et 20 le décalage y pour l'acquisition.

Conversion de format de fichiers vidéo et audio

N'importe quel format de fichier et protocole supporté peut servir d'entrée pour ffmpeg :

Exemples :

  • Vous pouvez utiliser des fichiers YUV en entrée : 
    ffmpeg -i /tmp/test%d.Y /tmp/out.mpg

    Cela utilisera les fichiers :

    /tmp/test0.Y, /tmp/test0.U, /tmp/test0.V,
/tmp/test1.Y, /tmp/test1.U, /tmp/test1.V, etc...

    Les fichiers Y utilisent une résolution deux fois supérieure à celle des fichiers U et V. Ce sont des fichiers bruts, sans en-tête. Ils peuvent être générés par tous les décodeurs vidéo décents. Vous devez spécifier la taille de l'image avec l'option -s si ffmpeg ne peut pas la deviner.

  • Vous pouvez entrer à partir d'un fichier YUV420P brut : 
    ffmpeg -i /tmp/test.yuv /tmp/out.avi

    test.yuv est un fichier contenant des données planaires YUV brutes. Chaque trame est composée du plan Y suivi des plans U et V à moitié de la résolution verticale et horizontale.

  • Vous pouvez sortir vers un fichier YUV420P brut : 
    ffmpeg -i mydivx.avi hugefile.yuv
  • Vous pouvez définir plusieurs fichiers d'entrée et de sortie : 
    ffmpeg -i /tmp/a.wav -s 640x480 -i /tmp/a.yuv /tmp/a.mpg

    Convertit le fichier audio a.wav et le fichier vidéo YUV brut a.yuv en fichier MPEG a.mpg.

  • Vous pouvez également faire des conversions audio et vidéo en même temps : 
    ffmpeg -i /tmp/a.wav -ar 22050 /tmp/a.mp2

    Convertit a.wav en audio MPEG à une fréquence d'échantillonnage de 22050 Hz.

  • Vous pouvez encoder vers plusieurs formats en même temps et définir un mappage des flux d'entrée vers les flux de sortie : 
    ffmpeg -i /tmp/a.wav -map 0:a -b:a 64k /tmp/a.mp2 -map 0:a -b:a 128k /tmp/b.mp2

    Convertit a.wav en a.mp2 à 64 kbits et en b.mp2 à 128 kbits. '-map fichier:index' spécifie quel flux d'entrée est utilisé pour chaque flux de sortie, dans l'ordre de définition des flux de sortie.

  • Vous pouvez transcoder des VOBs déchiffrés : 
    ffmpeg -i snatch_1.vob -f avi -c:v mpeg4 -b:v 800k -g 300 -bf 2 -c:a libmp3lame -b:a 128k snatch.avi

    C'est un exemple typique de rippage de DVD ; l'entrée est un fichier VOB, la sortie un fichier AVI avec vidéo MPEG-4 et audio MP3. Notez que dans cette commande nous utilisons des B-frames, donc le flux MPEG-4 est compatible DivX5, et la taille du GOP est de 300, ce qui signifie une image intra toutes les 10 secondes pour une vidéo d'entrée à 29.97 ips. De plus, le flux audio est encodé en MP3, vous devez donc activer le support LAME en passant "--enable-libmp3lame" à configure. Le mappage est particulièrement utile pour le transcodage de DVD afin d'obtenir la langue audio souhaitée.

    NOTE : Pour voir les formats d'entrée supportés, utilisez "ffmpeg -demuxers".

  • Vous pouvez extraire des images d'une vidéo, ou créer une vidéo à partir de nombreuses images :

    Pour extraire des images d'une vidéo :

    ffmpeg -i foo.avi -r 1 -s WxH -f image2 foo-%03d.jpeg

    Cela extraira une image vidéo par seconde de la vidéo et les sortira dans des fichiers nommés foo-001.jpeg, foo-002.jpeg, etc. Les images seront redimensionnées pour s'adapter aux nouvelles valeurs WxH.

    Si vous souhaitez extraire seulement un nombre limité d'images, vous pouvez utiliser la commande ci-dessus en combinaison avec l'option "-frames:v" ou "-t", ou en combinaison avec -ss pour commencer l'extraction à partir d'un certain moment.

    Pour créer une vidéo à partir de nombreuses images :

    ffmpeg -f image2 -framerate 12 -i foo-%03d.jpeg -s WxH foo.avi

    La syntaxe "foo-%03d.jpeg" spécifie d'utiliser un nombre décimal composé de trois chiffres complété par des zéros pour exprimer le numéro de séquence. C'est la même syntaxe supportée par la fonction printf de C, mais seuls les formats acceptant un entier normal sont appropriés.

    Lors de l'importation d'une séquence d'images, -i supporte également l'expansion des motifs de type wildcard de shell (globbing) en interne, en sélectionnant l'option "-pattern_type glob" spécifique à image2.

    Par exemple, pour créer une vidéo à partir de noms de fichiers correspondant au motif glob "foo-*.jpeg" :

    ffmpeg -f image2 -pattern_type glob -framerate 12 -i 'foo-*.jpeg' -s WxH foo.avi
  • Vous pouvez mettre plusieurs flux du même type dans la sortie : 
    ffmpeg -i test1.avi -i test2.avi -map 1:1 -map 1:0 -map 0:1 -map 0:0 -c copy -y test12.nut

    Le fichier de sortie résultant test12.nut contiendra les quatre premiers flux des fichiers d'entrée dans l'ordre inverse.

  • Pour forcer la sortie vidéo CBR : 
    ffmpeg -i myfile.avi -b 4000k -minrate 4000k -maxrate 4000k -bufsize 1835k out.m2v
  • Les quatre options lmin, lmax, mblmin et mblmax utilisent des unités 'lambda', mais vous pouvez utiliser la constante QP2LAMBDA pour convertir facilement des unités 'q' : 
    ffmpeg -i src.ext -lmax 21*QP2LAMBDA dst.ext
