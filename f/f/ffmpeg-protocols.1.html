OPTIONS DE

PROTOCOLE

La bibliothèque libavformat fournit certaines options globales génériques, qui peuvent être définies pour tous les protocoles. De plus, chaque protocole peut prendre en charge les soi-disant options privées, qui sont spécifiques à ce

composant.

Les options peuvent être définies en spécifiant -option valeur dans les outils FFmpeg, ou en définissant la valeur explicitement dans les options "AVFormatContext" ou en utilisant l'API libavutil/opt.h pour un usage

programmatique.

La liste des options prises en charge suit

:
protocol_whitelist liste (entrée
)
Définit une liste de protocoles autorisés séparés par des virgules. "ALL" corres
pond à tous les protocoles. Les protocoles préfixés par "-" sont désactivés. Tous
les protocoles sont autorisés par défaut, mais les protocoles utilisés par un autre
protocole (protocoles imbriqués) sont restreints à un sous-ensemble par protocole.

PROTOCOLE

S

Les protocoles sont des éléments configurés dans FFmpeg qui permettent l'accès à des ressources nécessitant des protocoles

spécifiques.

Lorsque vous configurez votre compilation FFmpeg, tous les protocoles pris en charge sont activés par défaut. Vous pouvez lister tous les protocoles disponibles en utilisant l'option de configuration "--list-protocols"

.

Vous pouvez désactiver tous les protocoles en utilisant l'option de configuration "--disable-protocols", et activer sélectivement un protocole en utilisant l'option "--enable-protocol=PROTOCOLE", ou vous pouvez désactiver un protocole particulier en utilisant l'option "--disable-protocol=PROTOCOLE"

.

L'option "-protocols" des outils ff* affichera la liste des protocoles pris en

charge.

amq

p

Le protocole de messagerie avancé (AMQP) version 0-9-1 est un protocole de communication publish-subscribe basé sur un

broker.

FFmpeg doit être compilé avec --enable-librabbitmq pour prendre en charge AMQP. Un broker AMQP distinct doit également être exécuté. Un exemple de broker AMQP open-source est

RabbitMQ.

Après avoir démarré le broker, un client FFmpeg peut diffuser des données vers le broker en utilisant la commande

: 
ffmpeg -re -i input -f mpegts amqp://[[user]:[password]@]hostname[:port]
[/vhost]

Où hostname et port (la valeur par défaut est 5672) est l'adresse du broker. Le client peut également définir un utilisateur/mot de passe pour l'authentification. La valeur par défaut pour les deux champs est "guest". Le nom de l'hôte virtuel sur le broker peut être défini avec vhost. La valeur par défaut est

"/".

Plusieurs abonnés peuvent diffuser depuis le broker en utilisant la commande

: 
ffplay amqp://[[user]:[password]@]hostname[:port]
[/vhost]

Dans RabbitMQ, toutes les données publiées vers le broker passent par un exchange spécifique, et chaque client abonné a une file/buffer assignée. Lorsqu'un paquet arrive à un exchange, il peut être copié dans la file d'un client en fonction des champs exchange et

routing_key.

Les options suivantes sont prises en charge

:
exchan
ge
Définit l'exchange à utiliser sur le broker. RabbitMQ a plusieurs exchanges prédéfinis : "amq.direct" est l'exchange par défaut, où le publieur et l'abonné doivent avoir un routing_key correspondant ; "amq.fanout" est identique à une opération de diffusion (c'est-à-dire que les données sont transférées à toutes les files sur l'exchange fanout indépendamment du routing_key) ; et "amq.topic" est similaire à "amq.direct", mais permet une correspondance de motifs plus complexe (consultez la documentation de RabbitMQ)
.
routing_k

Définit la clé de routage. La valeur par défaut est "amqp". La clé de routage est utilisée sur les exchanges "amq.direct" et "amq.topic" pour décider si les paquets sont écrits dans la file d'un
abonné.
pkt_si
ze
Taille maximale de chaque paquet envoyé/reçu vers le broker. La valeur par défaut est 131072. Le minimum est 4096 et le maximum est une grande valeur quelconque (représentable par un int). Cookies HTTP

Certaines requêtes HTTP seront refusées à moins que des valeurs de cookies ne soient passées avec la requête. L'option cookies permet de spécifier ces cookies. Au minimum, chaque cookie doit spécifier une valeur avec un chemin et un domaine. Les requêtes HTTP qui correspondent à la fois au domaine et au chemin incluront automatiquement la valeur du cookie dans le champ d'en-tête HTTP Cookie. Plusieurs cookies peuvent être délimités par un saut de ligne.

La syntaxe requise pour lire un flux en spécifiant un cookie est :

ffplay -cookies "nlqptid=nltid=tsn; path=/; domain=somedomain.com;" http://somedomain.com/somestream.m3u8

sap://<destination>[:<port>][?<options>]

Les paquets RTP sont envoyés à destination sur le port port, ou au port 5004 si aucun port n'est spécifié. options est une liste séparée par des &. Les options suivantes sont prises en charge:

announce_addr=adresse
Spécifier l'adresse IP de destination pour l'envoi des annonces. Si omis, les annonces sont envoyées à l'adresse de multidiffusion SAP couramment utilisée 224.2.127.254 (sap.mcast.net), ou ff0e::2:7ffe si destination est une adresse IPv6.
announce_port=port
Spécifier le port sur lequel envoyer les annonces, par défaut 9875 si non spécifié.
ttl=ttl
Spécifier la valeur de durée de vie (time to live) pour les annonces et les paquets RTP, par défaut 255.
same_port=0|1
Si défini à 1, envoyer tous les flux RTP sur la même paire de ports. Si zéro (par défaut), tous les flux sont envoyés sur des ports uniques, chaque flux sur un port 2 numéros plus élevé que le précédent. VLC/Live555 exige que cela soit défini à 1 pour pouvoir recevoir le flux. La pile RTP dans libavformat pour la réception exige que tous les flux soient envoyés sur des ports uniques.

Des lignes de commande exemples suivent.

Pour diffuser un flux sur le sous-réseau local, pour le regarder dans VLC:

ffmpeg -re -i <input> -f sap sap://224.0.0.255?same_port=1

De même, pour regarder dans ffplay:

ffmpeg -re -i <input> -f sap sap://224.0.0.255

Et pour regarder dans ffplay, sur IPv6:

ffmpeg -re -i <input> -f sap sap://[ff0e::1:2:3:4]

Demultiplexeur

La syntaxe pour une URL SAP donnée au demultiplexeur est:

sap://[<adresse>][:<port>]

adresse est l'adresse de multidiffusion sur laquelle écouter les annonces, si omise, la valeur par défaut 224.2.127.254 (sap.mcast.net) est utilisée. port est le port sur lequel écouter, 9875 si omis.

Le demultiplexeur écoute les annonces sur l'adresse et le port donnés. Une fois une annonce reçue, il essaie de recevoir ce flux particulier.

Des lignes de commande exemples suivent.

Pour lire le premier flux annoncé sur l'adresse de multidiffusion SAP normale:

ffplay sap://

Pour lire le premier flux annoncé sur l'adresse de multidiffusion SAP IPv6 par défaut:

ffplay sap://[ff0e::2:7ffe]
