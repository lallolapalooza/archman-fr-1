DESCRIPTIO

N

ffprobe collecte des informations à partir de flux multimédias et les imprime de manière lisible par l'homme et par la

machine.

Par exemple, il peut être utilisé pour vérifier le format du conteneur utilisé par un flux multimédia ainsi que le format et le type de chaque flux média qu'il

contient.

Si une URL est spécifiée en entrée, ffprobe essaiera d'ouvrir et de sonder le contenu de l'URL. Si l'URL ne peut pas être ouverte ou reconnue comme un fichier multimédia, un code de sortie positif est

renvoyé.

Si aucune sortie n'est spécifiée comme sortie avec o, ffprobe écrira sur

stdout.

ffprobe peut être utilisé à la fois comme application autonome ou en combinaison avec un filtre textuel, qui peut effectuer un traitement plus sophistiqué, par exemple un traitement statistique ou un tracé

graphique.

Les options sont utilisées pour lister certains des formats pris en charge par ffprobe ou pour spécifier quelles informations afficher, et pour définir comment ffprobe les

montrera.

La sortie de ffprobe est conçue pour être facilement analysable par un filtre textuel, et se compose d'une ou plusieurs sections d'une forme définie par le rédacteur sélectionné, qui est spécifié par l'option output_format

.

Les sections peuvent contenir d'autres sections imbriquées, et sont identifiées par un nom (qui peut être partagé par d'autres sections), et un nom unique. Voir la sortie de sections

.

Les balises de métadonnées stockées dans le conteneur ou dans les flux sont reconnues et imprimées dans la section correspondante "FORMAT", "STREAM", "STREAM_GROUP_STREAM" ou "PROGRAM_STREAM

"
.

OPTION

S

Toutes les options numériques, si rien n'est spécifié d'autre, acceptent une chaîne représentant un nombre en entrée, qui peut être suivie de l'un des préfixes d'unités SI, par exemple : 'K', 'M' ou

'G'.

Si 'i' est ajouté au préfixe d'unité SI, le préfixe complet sera interprété comme un préfixe d'unité pour les multiples binaires, qui sont basés sur les puissances de 1024 au lieu des puissances de 1000. L'ajout de 'B' au préfixe d'unité SI multiplie la valeur par 8. Cela permet d'utiliser, par exemple : 'KB', 'MiB', 'G' et 'B' comme suffixes de

nombre.

Les options qui ne prennent pas d'arguments sont des options booléennes, et définissent la valeur correspondante à true. Elles peuvent être définies à false en préfixant le nom de l'option par "no". Par exemple, l'utilisation de "-nofoo" définira l'option booléenne nommée "foo" à

false.

Les options qui prennent des arguments prennent en charge une syntaxe spéciale où l'argument donné sur la ligne de commande est interprété comme un chemin vers le fichier à partir duquel la valeur réelle de l'argument est chargée. Pour utiliser cette fonctionnalité, ajoutez un slash '/' immédiatement avant le nom de l'option (après le tiret initial). Par

exemple 
ffmpeg -i INPUT -/filter:v filter.script
OUTPUT

chargera une description de graphe de filtres à partir du fichier nommé filter.sc

ript.

Spécificateurs de

flux

Certaines options sont appliquées par flux, par exemple le débit binaire ou le codec. Les spécificateurs de flux sont utilisés pour spécifier précisément à quel(s) flux une option donnée

appartient.

Un spécificateur de flux est une chaîne généralement ajoutée au nom de l'option et séparée de celui-ci par deux-points. Par exemple "-codec:a:1 ac3" contient le spécificateur de flux "a:1", qui correspond au deuxième flux audio. Par conséquent, il sélectionnerait le codec ac3 pour le deuxième flux

audio.

Un spécificateur de flux peut correspondre à plusieurs flux, de sorte que l'option est appliquée à tous. Par exemple, le spécificateur de flux dans "-b:a 128k" correspond à tous les flux

audio.

Un spécificateur de flux vide correspond à tous les flux. Par exemple, "-codec copy" ou "-codec: copy" copieraient tous les flux sans

réencodage.

Les formes possibles de spécificateurs de flux sont

ex

La numérotation des flux est basée sur l'ordre des flux tel que détecté par libavformat, sauf si un spécificateur de groupe de flux ou un ID de programme est également spécifié. AVOption

s

Ces options sont fournies directement par les bibliothèques libavformat, libavdevice et libavcodec. Pour voir la liste des AVOptions disponibles, utilisez l'option -help. Elles sont séparées en deux catégories

génériq

Ces options peuvent être définies pour tout conteneur, codec ou dispositif. Les options génériques sont listées sous les options AVFormatContext pour les conteneurs/dispositifs et sous les options AVCodecContext pour les
codecs.
privé
es
Ces options sont spécifiques au conteneur, dispositif ou
codec donné. Les options privées sont listées sous
leurs conteneurs/dispositifs/codecs correspondants.

Par exemple, pour écrire un en-tête ID3v2.3 au lieu d'un ID3v2.4 par défaut dans un fichier MP3, utilisez l'option id3v2_version privée du multiplexeur MP3

Toutes les AVOptions de codec sont par flux, et donc un spécificateur de flux doit leur être attaché

: 
ffmpeg -i multichannel.mxf -map 0:v:0 -map 0:a:0 -map 0:a:0 -c:a:0 ac3 -b:a:0 640k -ac:a:1 2 -c:a:1 aac -b:2 128k out.
mp4

Dans l'exemple ci-dessus, un flux audio multicanal est mappé deux fois pour la sortie. La première instance est encodée avec le codec ac3 et un débit de 640k. La deuxième instance est réduite à 2 canaux et encodée avec le codec aac. Un débit de 128k est spécifié pour elle en utilisant l'index absolu du flux de

sortie.

Remarque : la syntaxe -nooption ne peut pas être utilisée pour les AVOptions booléennes, utilisez -option 0/-option

1.

-show_entries section_entr
ies
Définit la liste des entrées à afficher.

Les entrées sont spécifiées selon la syntaxe suivante. section_entries contient une liste d'entrées de section séparées par ":". Chaque entrée de section est composée d'un nom de section (ou nom unique), éventuellement suivi d'une liste d' entrées locales à cette section, séparées par ","

.

Si le nom de section est spécifié mais n'est suivi d'aucun "=", toutes les entrées sont imprimées dans la sortie, ainsi que toutes les sections qu'elle contient. Sinon, seules les entrées spécifiées dans la liste des entrées locales de section sont imprimées. En particulier, si "=" est spécifié mais que la liste des entrées locales est vide, alors aucune entrée ne sera affichée pour cette

section.

Notez que l'ordre de spécification des entrées locales de section n'est pas respecté dans la sortie, et l'ordre d'affichage habituel sera

conservé.

La syntaxe formelle est donnée

par : 
<LOCAL_SECTION_ENTRIES> ::= <SECTION_ENTRY_NAME>[,<LOCAL_SECTION_ENTRIES>]
<SECTION_ENTRY>         ::= <SECTION_NAME>[=[<LOCAL_SECTION_ENTRIES>]]
<SECTION_ENTRIES>       ::= <SECTION_ENTRY>[:<SECTION_ENTRIES>]

Par exemple, pour afficher uniquement l'index et le type de chaque flux, et l'heure PTS, la durée et l'index de flux des paquets, vous pouvez spécifier l'argument :

packet=pts_time,duration_time,stream_index : stream=index,codec_type

Pour afficher toutes les entrées de la section « format », mais uniquement le type de codec dans la section « stream », spécifiez l'argument :

format : stream=codec_type

Pour afficher toutes les étiquettes des sections stream et format :

stream_tags : format_tags

Pour afficher uniquement l'étiquette "title" (si disponible) dans les sections stream :

stream_tags=title

Affiche les informations de journalisation du décodeur sur chaque image, conformément à la valeur définie dans loglevel (voir "-loglevel"). Cette option nécessite "-show_frames".

Les informations pour chaque message de journal sont imprimées dans une section dédiée nommée « LOG ».

-show_streams
Affiche des informations sur chaque flux média contenu dans le flux multimédia d'entrée.

Les informations de chaque flux média sont imprimées dans une section dédiée nommée « STREAM ».

-show_programs
Affiche des informations sur les programmes et leurs flux contenus dans le flux multimédia d'entrée.

Les informations de chaque flux média sont imprimées dans une section dédiée nommée « PROGRAM_STREAM ».

-show_stream_groups
Affiche des informations sur les groupes de flux et leurs flux contenus dans le flux multimédia d'entrée.

Les informations de chaque flux média sont imprimées dans une section dédiée nommée « STREAM_GROUP_STREAM ».

-show_chapters
Affiche des informations sur les chapitres stockés dans le format.

Chaque chapitre est imprimé dans une section dédiée nommée « CHAPTER ».

-count_frames
Compte le nombre d'images par flux et le signale dans la section de flux correspondante.
-count_packets
Compte le nombre de paquets par flux et le signale dans la section de flux correspondante.
-read_intervals read_intervals
Lit uniquement les intervalles spécifiés. read_intervals doit être une séquence de spécifications d'intervalles séparées par « , ». ffprobe se positionnera au point de départ de l'intervalle et poursuivra la lecture à partir de là.

Chaque intervalle est spécifié par deux parties optionnelles, séparées par « % ».

La première partie spécifie la position de départ de l'intervalle. Elle est interprétée comme une position absolue, ou comme un décalage relatif par rapport à la position actuelle si elle est précédée du caractère « + ». Si cette première partie n'est pas spécifiée, aucun positionnement ne sera effectué lors de la lecture de cet intervalle.

La seconde partie spécifie la position de fin de l'intervalle. Elle est interprétée comme une position absolue, ou comme un décalage relatif par rapport à la position actuelle si elle est précédée du caractère « + ». Si la spécification du décalage commence par « # », elle est interprétée comme le nombre de paquets à lire (sans inclure les paquets de vidage) à partir du point de départ de l'intervalle. Si aucune seconde partie n'est spécifiée, le programme lira jusqu'à la fin de l'entrée.

Notez que le positionnement n'est pas précis, ainsi le point de départ réel de l'intervalle peut différer de la position spécifiée. De plus, lorsqu'une durée d'intervalle est spécifiée, l'heure de fin absolue sera calculée en ajoutant la durée au point de départ de l'intervalle trouvé lors du positionnement dans le fichier, plutôt qu'à la valeur de départ spécifiée.

La syntaxe formelle est donnée par :

<INTERVAL>  ::= [<START>|+<START_OFFSET>][%[<END>|+<END_OFFSET>]]
<INTERVALS> ::= <INTERVAL>[,<INTERVALS>]

Voici quelques exemples.

  • Se positionner à l'heure 10, lire les paquets jusqu'à 20 secondes après le point de positionnement trouvé, puis se positionner à la position "01:30" (1 minute et trente secondes) et lire les paquets jusqu'à la position "01:45". 
    10%+20,01:30%01:45
  • Lire seulement 42 paquets après s'être positionné à la position "01:23" : 
    01:23%+#42
  • Lire seulement les 20 premières secondes à partir du début : 
    %+20
  • Lire depuis le début jusqu'à la position "02:30" : 
    %02:30
-show_private_data, -private
Affiche les données privées, c'est-à-dire les données dépendant du format de l'élément affiché. Cette option est activée par défaut, mais vous pourriez avoir besoin de la désactiver pour des utilisations spécifiques, par exemple lors de la création de sorties XML conformes XSD.
-show_program_version
Affiche des informations relatives à la version du programme.

Les informations de version sont imprimées dans une section nommée « PROGRAM_VERSION ».

-show_library_versions
Affiche des informations relatives aux versions des bibliothèques.

Les informations de version pour chaque bibliothèque sont imprimées dans une section nommée « LIBRARY_VERSION ».

-show_versions
Affiche des informations relatives aux versions des programmes et des bibliothèques. C'est l'équivalent de la définition des deux options -show_program_version et -show_library_versions.
-show_pixel_formats
Affiche des informations sur tous les formats de pixel pris en charge par FFmpeg.

Les informations sur le format de pixel pour chaque format sont imprimées dans une section nommée « PIXEL_FORMAT ».

-show_optional_fields value
Certains écrivains, notamment JSON et XML, omettent l'impression des champs dont les valeurs sont invalides ou non applicables, tandis que d'autres écrivains les impriment toujours. Cette option permet de contrôler ce comportement. Les valeurs valides sont "always"/1, "never"/0 et "auto"/-1. La valeur par défaut est auto.
-analyze_frames
Analyse les images et/ou leurs données secondaires jusqu'à l'intervalle de lecture fourni, en fournissant des informations supplémentaires qui peuvent être utiles au niveau du flux. Doit être associé à l'option -show_streams, sinon il n'aura aucun effet.

Actuellement, les champs supplémentaires fournis par cette option lorsqu'elle est activée sont les champs "closed_captions" et "film_grain".

Par exemple, pour analyser les 20 premières secondes et remplir ces champs :

ffprobe -show_streams -analyze_frames -read_intervals "%+20" INPUT
-bitexact
Force une sortie bit-exact, utile pour produire une sortie qui ne dépend pas de la compilation spécifique.
-i input_url
Lit input_url.
-o output_url
Écrit la sortie vers output_url. Si non spécifié, la sortie est envoyée vers stdout.

ÉCRIVAINS

Un écrivain définit le format de sortie adopté par ffprobe, et sera utilisé pour imprimer toutes les parties de la sortie.

Un écrivain peut accepter un ou plusieurs arguments, qui spécifient les options à adopter. Les options sont spécifiées sous forme de liste de paires clé=valeur, séparées par « : ».

Tous les écrivains prennent en charge les options suivantes :

string_validation, sv
Définit le mode de validation des chaînes de caractères.

Les valeurs suivantes sont acceptées.

fail
L'écrivain échouera immédiatement en cas de séquence de chaîne (UTF-8) invalide ou de point de code trouvé dans l'entrée. Ceci est particulièrement utile pour valider les métadonnées d'entrée.
ignore
Toute erreur de validation sera ignorée. Cela entraînera une sortie potentiellement incorrecte, surtout avec les écrivains JSON ou XML.
replace
L'écrivain substituera les séquences UTF-8 invalides ou les points de code par la chaîne spécifiée avec string_validation_replacement.

La valeur par défaut est replace.

string_validation_replacement,
string_validation
Spécifie la manière dont les séquences invalides doivent être traitées. Il peut prendre les valeurs suivantes :
report
Les séquences invalides déclenchent une erreur. Le programme se termine, sauf si l'option level est utilisée.
ignore
Les séquences invalides sont ignorées et donc retirées de la sortie.
replace
Les séquences invalides sont remplacées par la chaîne définie par l'option replace_string. Si cette dernière n'est pas spécifiée, elles sont remplacées par une chaîne vide.
replace_string
Chaîne de remplacement à utiliser au cas où string_validation serait réglée sur replace.

Si l'option n'est pas spécifiée, l'écrivain utilisera la chaîne vide, c'est-à-dire qu'il supprimera les séquences invalides des chaînes d'entrée.

La description des écrivains actuellement disponibles suit.

default

Format par défaut.

Imprime chaque section sous la forme:

[SECTION]
clé1=val1
...
cléN=valN
[/SECTION]

Les balises de métadonnées sont imprimées sous forme de ligne dans la section FORMAT, STREAM, STREAM_GROUP_STREAM ou PROGRAM_STREAM correspondante, et sont préfixées par la chaîne "TAG:".

La description des options acceptées suit.

nokey, nk
Si réglé sur 1, spécifie de ne pas imprimer la clé de chaque champ. La valeur par défaut est 0.
noprint_wrappers, nw
Si réglé sur 1, spécifie de ne pas imprimer l'en-tête et le pied de section. La valeur par défaut est 0.

compact, csv

Format compact et CSV.

L'écrivain "csv" est équivalent à "compact", mais supporte des valeurs par défaut différentes.

Chaque section est imprimée sur une seule ligne. Si aucune option n'est spécifiée, la sortie a la forme:

section|clé1=val1| ... |cléN=valN

Les balises de métadonnées sont imprimées dans la section "format" ou "stream" correspondante. Une clé de balise de métadonnées, si elle est imprimée, est préfixée par la chaîne "tag:".

La description des options acceptées suit.

item_sep, s
Spécifie le caractère à utiliser pour séparer les champs sur la ligne de sortie. Ce doit être un seul caractère imprimable, c'est "|" par défaut ("," pour l'écrivain "csv").
nokey, nk
Si réglé sur 1, spécifie de ne pas imprimer la clé de chaque champ. Sa valeur par défaut est 0 (1 pour l'écrivain "csv").
escape, e
Définit le mode d'échappement à utiliser, par défaut "c" ("csv" pour l'écrivain "csv").

Il peut prendre l'une des valeurs suivantes:

c
Effectue un échappement de type C. Les chaînes contenant un saut de ligne (\n), un retour chariot (\r), une tabulation (\t), un saut de page (\f), le caractère d'échappement (\) ou le caractère séparateur SEP sont échappées en utilisant un style C, de sorte qu'un saut de ligne est converti en la séquence \n, un retour chariot en \r, \ en \\ et le séparateur SEP est converti en \SEP.
csv
Effectue un échappement de type CSV, tel que décrit dans la RFC4180. Les chaînes contenant un saut de ligne (\n), un retour chariot (\r), un guillemet double ("), ou SEP sont entourées de guillemets doubles.
none
N'effectue aucun échappement.
print_section, p
Imprime le nom de la section au début de chaque ligne si la valeur est 1, le désactive avec la valeur réglée sur 0. La valeur par défaut est 1.

flat

Format plat.

Une sortie libre où chaque ligne contient une paire clé=valeur explicite, telle que "streams.stream.3.tags.foo=bar". La sortie est échappée pour le shell, de sorte qu'elle peut être directement intégrée dans des scripts sh tant que le caractère séparateur est un caractère alphanumérique ou un underscore (voir l'option sep_char).

La description des options acceptées suit.

sep_char, s
Caractère séparateur utilisé pour séparer le chapitre, le nom de la section, les identifiants et les éventuelles balises dans la clé du champ imprimé.

La valeur par défaut est ..

hierarchical, h
Spécifie si la spécification du nom de la section doit être hiérarchique. Si réglé sur 1, et s'il y a plus d'une section dans le chapitre courant, le nom de la section sera préfixé par le nom du chapitre. Une valeur de 0 désactivera ce comportement.

La valeur par défaut est 1.

ini

Sortie au format INI.

Imprime la sortie dans un format basé sur INI.

Les conventions suivantes sont adoptées:

  • toutes les clés et valeurs sont en UTF-8
  • . est le séparateur de sous-groupe
  • les sauts de ligne, \t, \f, \b et les caractères suivants sont échappés
  • \ est le caractère d'échappement
  • # est l'indicateur de commentaire
  • = est le séparateur clé/valeur
  • : n'est pas utilisé mais est généralement analysé comme séparateur clé/valeur

Cet écrivain accepte des options sous forme de liste de paires clé=valeur, séparées par :.

La description des options acceptées suit.

hierarchical, h
Spécifie si la spécification du nom de la section doit être hiérarchique. Si réglé sur 1, et s'il y a plus d'une section dans le chapitre courant, le nom de la section sera préfixé par le nom du chapitre. Une valeur de 0 désactivera ce comportement.

La valeur par défaut est 1.

json

Format basé sur JSON.

Chaque section est imprimée en utilisant la notation JSON.

La description des options acceptées suit.

compact, c
Si réglé sur 1, active la sortie compacte, c'est-à-dire que chaque section sera imprimée sur une seule ligne. La valeur par défaut est 0.

Pour plus d'informations sur JSON, voir http://www.json.org/.

xml

Format basé sur XML.

La sortie XML est décrite dans le fichier de description de schéma XML ffprobe.xsd installé dans le répertoire de données de FFmpeg.

Une version mise à jour du schéma peut être récupérée à l'URL http://www.ffmpeg.org/schema/ffprobe.xsd, qui redirige vers le dernier schéma intégré dans l'arbre de code source de développement de FFmpeg.

Notez que la sortie produite sera conforme au schéma ffprobe.xsd uniquement lorsqu'aucune option de sortie globale spéciale (unit, prefix, byte_binary_prefix, sexagesimal etc.) n'est spécifiée.

La description des options acceptées suit.

fully_qualified, q
Si réglé sur 1, spécifie si la sortie doit être entièrement qualifiée. La valeur par défaut est 0. Ceci est requis pour générer un fichier XML qui peut être validé par un fichier XSD.
xsd_strict, x
Si réglé sur 1, effectue des vérifications supplémentaires pour garantir que la sortie est conforme au XSD. La valeur par défaut est 0. Cette option définit automatiquement fully_qualified à 1.

Pour plus d'informations sur le format XML, voir https://www.w3.org/XML/.

TIMECODE

ffprobe supporte l'extraction du Timecode:

  • Le timecode MPEG1/2 est extrait du GOP, et est disponible dans les détails du flux vidéo (-show_streams, voir timecode).
  • Le timecode MOV est extrait de la piste tmcd, il est donc disponible dans les métadonnées du flux tmcd (-show_streams, voir TAG:timecode).
  • Les timecodes DV, GXF et AVI sont disponibles dans les métadonnées du format (-show_format, voir TAG:timecode).
