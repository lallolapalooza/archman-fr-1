DÉMULTIPLEXEU

RS

Les démultiplexeurs sont des éléments configurés dans FFmpeg qui peuvent lire les flux multimédias d'un type de fichier

particulier.

Lorsque vous configurez votre compilation FFmpeg, tous les démultiplexeurs pris en charge sont activés par défaut. Vous pouvez lister tous ceux qui sont disponibles en utilisant l'option de configuration "--list-demuxers"

.

Vous pouvez désactiver tous les démultiplexeurs en utilisant l'option de configuration "--disable-demuxers", et activer sélectivement un seul démultiplexeur avec l'option "--enable-demuxer=DEMUXER", ou le désactiver avec l'option "--disable-demuxer=DEMUXER"

.

L'option "-demuxers" des outils ff* affichera la liste des démultiplexeurs activés. Utilisez "-formats" pour afficher une liste combinée des démultiplexeurs et multiplexeurs

activés.

Démultiplexeur de script de concaténation

Ce démultiplexeur lit une liste de fichiers et d'autres directives depuis un fichier texte et les démultiplexe les uns après les autres, comme si tous leurs paquets avaient été multiplexés

ensemble.

Les horodatages dans les fichiers sont ajustés so que o primeiro arquivo começa em 0 e cada arquivo seguinte começa onde o anterior termina. Note que isso é feito globalmente e pode causar lacunas se todos os fluxos não tiverem exatamente o mesmo comprimento.

Todos os arquivos devem ter os mesmos fluxos (mesmos codecs, mesma base de tempo, etc.).

A duração de cada arquivo é usada para ajustar os carimbos de data/hora do arquivo seguinte: se a duração estiver incorreta (porque foi calculada usando a taxa de bits ou porque o arquivo está truncado, por exemplo), isso pode causar artefatos. A diretiva "duration" pode ser usada para substituir a duração armazenada em cada arquivo.

Syntax

O script é um arquivo de texto em extended-ASCII, com uma diretiva por linha. Linhas vazias, espaços iniciais e linhas que começam com '#' são ignoradas. A seguinte diretiva é reconhecida:

"file path"
Caminho para um arquivo a ser lido; caracteres especiais e espaços devem ser escapados com barra invertida ou aspas simples.

Todas as diretivas relacionadas a arquivos subsequentes aplicam-se a esse arquivo.

"ffconcat version 1.0"
Identifica o tipo e a versão do script.

Para fazer o FFmpeg reconhecer o formato automaticamente, esta diretiva deve aparecer exatamente como está (sem espaço extra ou BOM) na primeira linha do script.

"duration dur"
Duração do arquivo. Esta informação pode ser especificada a partir do arquivo; especificá-la aqui pode ser mais eficiente ou ajudar se a informação do arquivo não estiver disponível ou for imprecisa.

Se a duração for definida para todos os arquivos, então é possível buscar em todo o vídeo concatenado.

"inpoint timestamp"
Ponto de entrada do arquivo. Quando o demuxer abre o arquivo, ele busca instantaneamente para o carimbo de data/hora especificado. A busca é feita de modo que todos os fluxos possam ser apresentados com sucesso no ponto de entrada.

Esta diretiva funciona melhor com codecs intra-frame, pois para os não intra-frame você geralmente obterá pacotes extras antes do ponto de entrada real e o conteúdo decodificado mais provavelmente conterá quadros antes do ponto de entrada também.

Para cada arquivo, os pacotes antes do ponto de entrada terão carimbos de data/hora menores que o carimbo de data/hora de início calculado do arquivo (negativo no caso do primeiro arquivo), e a duração dos arquivos (se não especificada pela diretiva "duration") será reduzida com base em seu ponto de entrada especificado.

Devido a possíveis pacotes antes do ponto de entrada especificado, os carimbos de data/hora dos pacotes podem se sobrepor entre dois arquivos concatenados.

"outpoint timestamp"
Ponto de saída do arquivo. Quando o demuxer atinge o carimbo de data/hora de decodificação especificado em qualquer um dos fluxos, ele o trata como uma condição de fim de arquivo e pula os pacotes atuais e todos os restantes de todos os fluxos.

O ponto de saída é exclusivo, o que significa que o demuxer não produzirá pacotes com carimbo de data/hora de decodificação maior ou igual ao ponto de saída.

Esta diretiva funciona melhor com codecs intra-frame e formatos onde todos os fluxos são estritamente intercalados. Para codecs não intra-frame, você geralmente obterá pacotes adicionais com carimbo de data/hora de apresentação após o ponto de saída, portanto, o conteúdo decodificado mais provavelmente conterá quadros após o ponto de saída também. Se seus fluxos não forem estritamente intercalados, você pode não obter todos os pacotes de todos os fluxos antes do ponto de saída e pode apenas decodificar o fluxo mais antigo até o ponto de saída.

A duração dos arquivos (se não especificada pela diretiva "duration") será reduzida com base em seu ponto de saída especificado.

"file_packet_metadata key=value"
Metadados dos pacotes do arquivo. Os metadados especificados serão definidos para cada pacote do arquivo. Você pode especificar esta diretiva várias vezes para adicionar várias entradas de metadados. Esta diretiva está obsoleta, use "file_packet_meta" em vez disso.
"file_packet_meta key value"

Introduz um fluxo no arquivo virtual. Todas as diretivas subsequentes relacionadas a fluxos aplicam-se ao último fluxo introduzido. Se nenhum fluxo for definido no script, os fluxos do primeiro arquivo são copiados.

Opções

Este demuxer aceita a seguinte opção:

safe
Se definido como 1, rejeita caminhos de arquivo e diretivas inseguros. Um caminho de arquivo é considerado seguro se não contiver uma especificação de protocolo, for relativo e todos os componentes contiverem apenas caracteres do conjunto de caracteres portáteis (letras, dígitos, ponto, sublinhado e hífen) e não tiverem ponto no início de um componente.

Se definido como 0, qualquer nome de arquivo é aceito.

O padrão é 1.

auto_convert
Se definido como 1, tenta realizar conversões automáticas nos dados dos pacotes para tornar os fluxos concatenáveis. O padrão é 1.

Atualmente, a única conversão é adicionar o filtro de bitstream h264_mp4toannexb a fluxos H.264 no formato MP4. Isso é necessário, em particular, se houver alterações de resolução.

segment_time_metadata
Se definido como 1, cada pacote conterá os valores de metadados de pacote lavf.concat.start_time e lavf.concat.duration, que são o horário de início e a duração dos respectivos segmentos de arquivo na saída concatenada, expressos em microssegundos. O metadado de duração só é definido se for conhecido com base no arquivo concat. O padrão é 0.

dash

Demuxer Dynamic Adaptive Streaming over HTTP.

Este demuxer apresenta todos os AVStreams encontrados no manifesto. Ao definir os sinalizadores de descarte nos AVStreams, o chamador pode decidir quais fluxos realmente receber. Cada fluxo espelha as propriedades "id" e "bandwidth" da "<Representation>" como chaves de metadados nomeadas "id" e "variant_bitrate", respectivamente.

Opções

Este demuxer aceita a seguinte opção:

cenc_decryption_key
Chave de 16 bytes, em hexadecimal, para descriptografar arquivos criptografados usando ISO Common Encryption (CENC/AES-128 CTR; ISO/IEC 23001-7).

dvdvideo

Demuxer DVD-Video, alimentado por libdvdnav e libdvdread.

Pode ingerir diretamente títulos de DVD, especificamente PGCs sequenciais, em um pipeline de conversão. Ativos de menu, como vídeo de fundo ou áudio, também podem ser demuxados dadas as coordenadas do menu (no melhor esforço).

Dispositivos de bloco (unidades de DVD), arquivos ISO e estruturas de diretório são aceitos. Ative com "-f dvdvideo" antes de uma dessas entradas.

Este demuxer NÃO possui código de descriptografia de qualquer tipo. Você está por sua conta ao lidar com DVDs criptografados e não deve esperar suporte nesse assunto.

A reprodução subjacente é tratada pela libdvdnav e o parsing da estrutura pela libdvdread. O FFmpeg deve ser compilado com suporte de biblioteca GPL disponível, bem como com as opções de configure "--enable-libdvdnav" e "--enable-libdvdread".

Você precisará fornecer o "número do título" desejado ou coordenadas exatas de PGC/PG. Muitos players e ferramentas de DVD de código aberto podem ajudar a fornecer essas informações. Se não especificado, o demuxer usará o título 1 como padrão, o que funciona para muitos discos. No entanto, devido à flexibilidade do formato, é recomendado verificar manualmente. Existem muitos discos que são autorados de forma estranha ou com cabeçalhos inválidos.

Se a entrada for uma unidade de DVD real, observe que existem algumas unidades que podem falhar silenciosamente na leitura de setores defeituosos do disco, retornando bits aleatórios em vez disso, o que efetivamente corrompe os dados. Isso é especialmente proeminente em discos antigos ou em decomposição. Uma segunda passagem e verificações de integridade seriam necessárias para detectar a corrupção. Isso não é um problema do FFmpeg.

Background

DVD-Video não é um formato de contêiner linear diretamente acessível no sentido tradicional. Em vez disso, ele permite a reprodução complexa e programática de fluxos MPEG-PS cuidadosamente multiplexados que são armazenados em arquivos VOB sem cabeçalho. Para o usuário final, esses fluxos são conhecidos simplesmente como "títulos", mas a sequência de reprodução lógica real é definida por uma ou mais "PGCs", ou Program Group Chains, dentro do título. O PGC é composto por múltiplos "PGs", ou "Programs", que são os segmentos de vídeo reais (e para um longa-metragem típico, ordenados sequencialmente). A estrutura do PGC, juntamente com o layout e os metadados do fluxo, são armazenados em arquivos IFO que precisam ser

e parsés. Les PGC peuvent être considérés comme des listes de lecture, pour faire

simple.

Un lecteur DVD réel s'appuie sur l'interaction de l'utilisateur avec l'interface graphique via les menus et une machine virtuelle interne pour piloter le démuxage. Généralement, l'utilisateur navigue (via les menus) ou est automatiquement redirigé vers le PGC de son choix. Pendant ce processus et la lecture qui s'ensuit, la machine virtuelle interne du lecteur DVD maintient également un état et exécute des instructions qui peuvent créer des sauts vers différents secteurs pendant la lecture. C'est pourquoi libdvdnav est impliqué, car une lecture linéaire des blocs MPEG-PS sur le disque (VOBs) ne suffit pas à produire la bonne séquence dans de nombreux

cas.

Il existe de nombreuses autres structures DVD (un sujet long) qui ne seront pas abordées ici. Les paquets NAV, en particulier, sont traités par ce démuxeur pour construire une chronologie précise mais ne sont pas émis en tant que flux. Pour une bonne compréhension de haut niveau, consultez : https://code.videolan.org/videolan/libdvdnav/-/blob/master/doc/dvd_structure

Un script SBG peut mélanger des horodatages absolus et relatifs. Les muxeurs mov, mp4, et ismv prennent en charge la fragmentation. Normalement, un fichier MOV/MP4 a toutes les métadonnées sur tous les paquets stockées dans un seul

emplacement.

Ces données sont généralement écrites à la fin du fichier, mais elles peuvent être déplacées au début pour une meilleure lecture en ajoutant "+faststart" à "-movflags", ou en utilisant l'outil qt-fastst

art).

Un fichier fragmenté se compose d'un certain nombre de fragments, où les paquets et les métadonnées sur ces paquets sont stockés ensemble. L'écriture d'un fichier fragmenté a l'avantage que le fichier est décodable même si l'écriture est interrompue (alors qu'un MOV/MP4 normal n'est pas décodable s'il n'est pas correctement terminé), et cela nécessite moins de mémoire lors de l'écriture de fichiers très longs (puisque l'écriture de fichiers MOV/MP4 normaux stocke les informations sur chaque paquet individuel en mémoire jusqu'à la fermeture du fichier). L'inconvénient est qu'il est moins compatible avec d'autres

applications.

fifo

Multiplexeur FIFO (First-In First-Out).

Le pseudo-multiplexeur fifo permet la séparation de l'encodage et du multiplexage en utilisant une file d'attente premier entré, premier sorti et en exécutant le multiplexeur réel dans un thread séparé.

Ceci est particulièrement utile en combinaison avec le multiplexeur tee et peut être utilisé pour envoyer des données à plusieurs destinations avec une fiabilité/vitesse d'écriture/latence différente.

Le multiplexeur cible est soit sélectionné à partir du nom de sortie, soit spécifié via l'option fifo_format.

Le comportement du multiplexeur fifo si la file d'attente se remplit ou si la sortie échoue (par exemple, si un paquet ne peut pas être écrit en sortie) est sélectionnable :

  • La sortie peut être redémarrée de manière transparente avec un délai configurable entre les tentatives basé sur le temps réel ou le temps du flux traité.
  • L'encodage peut être bloqué pendant une défaillance temporaire, ou continuer de manière transparente en abandonnant des paquets si la file d'attente FIFO se remplit.

Les utilisateurs de l'API doivent être conscients que les fonctions de rappel ("interrupt_callback", "io_open" et "io_close") utilisées dans son "AVFormatContext" doivent être thread-safe.

Options

attempt_recovery bool
En cas d'échec, tenter de récupérer la sortie. Ceci est particulièrement utile lorsqu'utilisé avec une sortie réseau, car cela permet de redémarrer le streaming de manière transparente. Par défaut, cette option est réglée sur "false".

Si réglé sur "true", dans le cas où la file d'attente fifo se remplit, les paquets seront abandonnés plutôt que de bloquer l'encodeur. Cela permet de continuer le streaming sans retarder l'entrée, au détriment de l'omission d'une partie du flux. Par défaut, cette option est réglée sur "false", donc dans de tels cas, l'encodeur sera bloqué jusqu'à ce que le multiplexeur traite certains paquets et qu'aucun d'entre eux ne soit perdu.

Spécifie le nom du format. Utile s'il ne peut pas être déduit du suffixe du nom de sortie.
