Lève

NOM

Float.Array - tableau de flottants

SYNTAXE

val map : (float -> float) -> t -> t
val map_unsafe : (float -> float) -> t -> t
val map2 : (float -> float -> float) -> t -> t -> t
val map2_unsafe : (float -> float -> float) -> t -> t -> t

DESCRIPTION

Ce module fournit des opérations sur les tableaux de flottants. Les tableaux de flottants sont implémentés comme des tableaux standards de nombres à virgule flottante 64 bits en double précision (selon la norme IEEE 754).

Les opérations sur les tableaux de flottants ne sont pas atomiques et peuvent être coûteuses en mémoire. L'utilisation de tableaux de flottants peut être plus efficace que l'utilisation de tableaux génériques lorsque vous manipulez un grand nombre de nombres à virgule flottante.

Array mapping

val map : (float -> float) -> t -> t

map f a applique la fonction f à tous les éléments du tableau a et construit un nouveau tableau de flottants avec les résultats retournés par f : [| f a.(0); ...; f a.(length a - 1)|].

val map_unsafe : (float -> float) -> t -> t

Similaire à map, mais les bornes ne sont pas vérifiées. L'utilisation de cette fonction sur un tableau dont la taille n'est pas connue est déconseillée.

val map2 : (float -> float -> float) -> t -> t -> t

map2 f a b applique la fonction f à tous les éléments de a et b, et construit un tableau de flottants avec les résultats retournés par f : [| f a.(0) b.(0); ...; f a.(length a - 1) b.(length b - 1)|].

Lève Invalid_argument si les tableaux de flottants n'ont pas la même taille.

val map2_unsafe : (float -> float -> float) -> t -> t -> t

Similaire à map2, mais les bornes ne sont pas vérifiées. L'utilisation de cette fonction sur un tableau dont la taille n'est pas connue est déconseillée.

Lève Invalid_argument si les tableaux de flottants n'ont pas la même taille.

Array scanning

val for_all : (float -> bool) -> t -> bool

for_all f [|a1; ...; an|] vérifie si tous les éléments du tableau de flottants satisfont le prédicat f. C'est-à-dire, elle retourne (f a1) && (f a2) && ... && (f an).

val exists : (float -> bool) -> t -> bool

exists f [|a1; ...; an|] vérifie si au moins un élément du tableau de flottants satisfait le prédicat f. C'est-à-dire, elle retourne (f a1) || (f a2) || ... || (f an).

val mem : float -> t -> bool

mem a set est vrai si et seulement si il existe un élément de set qui est structurellement égal à a, c'est-à-dire s'il existe un x dans set tel que compare a x = 0.

val mem_ieee : float -> t -> bool

Identique à Float.Array.mem, mais utilise l'égalité IEEE au lieu de l'égalité structurelle.

Array searching

val find_opt : (float -> bool) -> t -> float option

val find_index : (float -> bool) -> t -> int option

find_index f a retourne Some i, où i est l'indice du premier élément du tableau a qui satisfait f x, s'il existe un tel élément.

Elle retourne None s'il n'existe aucun tel élément.

Sorting and shuffling

val sort : (float -> float -> int) -> t -> unit

Trie un tableau de flottants par ordre croissant selon une fonction de comparaison. La fonction de comparaison doit retourner 0 si ses arguments sont égaux, un entier positif si le premier est plus grand, et un entier négatif si le premier est plus petit (voir ci-dessous pour une spécification complète). Par exemple, compare est une fonction de comparaison appropriée. Après avoir appelé sort, le tableau est trié sur place par ordre croissant. sort est garanti de s'exécuter en espace tas constant et (au plus) en espace pile logarithmique.

L'implémentation actuelle utilise le tri par tas (Heap Sort). Elle s'exécute en espace pile constant.

Spécification de la fonction de comparaison : Soit a le tableau de flottants et cmp la fonction de comparaison. Les propriétés suivantes doivent être vraies pour tout x, y, z dans a:

- cmp x y > 0 si et seulement si cmp y x < 0

- si cmp x y >= 0 et cmp y z >= 0 alors cmp x z >= 0

Lorsque sort retourne, a contient les mêmes éléments qu'auparavant, réorganisés de telle sorte que pour tous les indices i et j valides de a :

- cmp a.(i) a.(j) >= 0 si i >= j

val stable_sort : (float -> float -> int) -> t -> unit

Identique à Float.Array.sort, mais l'algorithme de tri est stable (c'est-à-dire que les éléments qui se comparent comme égaux sont conservés dans leur ordre d'origine) et n'est pas garanti de s'exécuter en espace tas constant.

L'implémentation actuelle utilise le tri fusion (Merge Sort). Elle utilise un tableau de flottants temporaire de longueur n/2, où n est la longueur du tableau de flottants. Elle est généralement plus rapide que l'implémentation actuelle de Float.Array.sort.

val fast_sort : (float -> float -> int) -> t -> unit

Identique à Float.Array.sort ou Float.Array.stable_sort, selon celui qui est le plus rapide sur une entrée typique.

val shuffle : rand:(int -> int) -> t -> unit

shuffle rand a permute aléatoirement les éléments de a en utilisant rand pour l'aléatoire. La distribution des permutations est uniforme.

rand doit être telle qu'un appel à rand n retourne un nombre aléatoire uniformément distribué dans l'intervalle [ 0 ; n-1 ]. Random.int peut être utilisé pour cela (n'oubliez pas d'initialiser le générateur avec Random.self_init).

val map_to_array : (float -> 'a) -> t -> 'a array

map_from_array f a applique la fonction f à tous les éléments de a et construit un tableau de flottants avec les résultats retournés par f.

Arrays and concurrency safety

Il faut être prudent lors de l'accès concurrent aux tableaux de flottants à partir de plusieurs domaines : l'accès à un tableau ne fera jamais planter le programme, mais des accès non synchronisés pourraient donner des résultats surprenants (non séquentiellement cohérents).

Atomicity

Toutes les opérations sur les tableaux de flottants qui accèdent à plus d'un élément du tableau ne sont pas atomiques. Cela inclut l'itération, le balayage, le tri, la division et la combinaison de tableaux.

Par exemple, considérez le programme suivant :

let size = 100_000_000
  let a = Float.Array.make size 1.
  let update a f () =
     Float.Array.iteri (fun i x -> Float.Array.set a i (f x)) a
  let d1 = Domain.spawn (update a (fun x -> x +. 1.))
  let d2 = Domain.spawn (update a (fun x ->  2. *. x +. 1.))
  let () = Domain.join d1; Domain.join d2

Après l'exécution de ce code, chaque élément du tableau de flottants a sera soit 2., 3., 4. ou 5.. Si l'atomicité est requise, alors l'utilisateur doit implémenter sa propre synchronisation (par exemple, en utilisant Mutex.t).

Data races

Si deux domaines n'accèdent qu'à des parties disjointes du tableau, le comportement observé est équivalent à un entrelacement séquentiel des opérations des deux domaines.

Une "data race" (course aux données) se produit lorsque deux domaines accèdent au même élément de tableau sans synchronisation et qu'au moins un des accès est une écriture. En l'absence de data races, le comportement observé est équivalent à un entrelacement séquentiel des opérations provenant de différents domaines.

Dans la mesure du possible, les data races doivent être évitées en utilisant la synchronisation pour médiatiser les accès aux éléments du tableau.

En effet, en présence de data races, les programmes ne planteront pas, mais le comportement observé peut ne pas être équivalent à un quelconque entrelacement séquentiel des opérations provenant de différents domaines. Néanmoins, même en présence de data races, une opération de lecture retournera la valeur d'une écriture antérieure à cet emplacement, à quelques exceptions près.

Tearing

Les tableaux de flottants présentent deux considérations supplémentaires en présence de data races.

Premièrement, l'opération blit peut copier un tableau octet par octet. Les data races entre une telle opération blit et une autre opération peuvent produire des valeurs surprenantes dues au "tearing" : des écritures partielles entrelacées avec d'autres opérations peuvent créer des valeurs flottantes qui n'existeraient pas avec une exécution séquentielle.

Par exemple, à la fin de

let zeros = Float.Array.make size 0.
  let max_floats = Float.Array.make size Float.max_float
  let res = Float.Array.copy zeros
  let d1 = Domain.spawn (fun () -> Float.Array.blit zeros 0 res 0 size)
  let d2 = Domain.spawn (fun () -> Float.Array.blit max_floats 0 res 0 size)
  let () = Domain.join d1; Domain.join d2

le tableau de flottants res pourrait contenir des valeurs qui ne sont ni 0. ni max_float.

Deuxièmement, sur les architectures 32 bits, l'obtention ou la définition d'un champ implique deux accès mémoire distincts. En présence de data races, l'utilisateur peut observer du "tearing" sur n'importe quelle opération.
