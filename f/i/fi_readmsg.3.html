NOM

fi_rma - Opérations d'accès à la mémoire distante

fi_read / fi_readv / fi_readmsg
Initialise une lecture depuis la mémoire distante

fi_write / fi_writev / fi_writemsg fi_inject_write / fi_writedata : Initialise une écriture vers la mémoire distante

SYNTAXE

#include <rdma/fi_rma.h>
ssize_t fi_read(struct fid_ep *ep, void *buf, size_t len, void *desc,
    fi_addr_t src_addr, uint64_t addr, uint64_t key, void *context);
ssize_t fi_readv(struct fid_ep *ep, const struct iovec *iov, void **desc,
    size_t count, fi_addr_t src_addr, uint64_t addr, uint64_t key,
    void *context);
ssize_t fi_readmsg(struct fid_ep *ep, const struct fi_msg_rma *msg,
    uint64_t flags);
ssize_t fi_write(struct fid_ep *ep, const void *buf, size_t len,
    void *desc, fi_addr_t dest_addr, uint64_t addr, uint64_t key,
    void *context);
ssize_t fi_writev(struct fid_ep *ep, const struct iovec *iov, void **desc,
    size_t count, fi_addr_t dest_addr, uint64_t addr, uint64_t key,
    void *context);
ssize_t fi_writemsg(struct fid_ep *ep, const struct fi_msg_rma *msg,
    uint64_t flags);
ssize_t fi_inject_write(struct fid_ep *ep, const void *buf, size_t len,
    fi_addr_t dest_addr, uint64_t addr, uint64_t key);
ssize_t fi_writedata(struct fid_ep *ep, const void *buf, size_t len,
    void *desc, uint64_t data, fi_addr_t dest_addr, uint64_t addr,
    uint64_t key, void *context);
ssize_t fi_inject_writedata(struct fid_ep *ep, const void *buf, size_t len,
    uint64_t data, fi_addr_t dest_addr, uint64_t addr, uint64_t key);

ARGUMENTS

ep
Point de terminaison du fabric sur lequel initier l'opération de lecture ou d'écriture.
buf
Tampon de données local dans lequel lire (cible de lecture) ou à partir duquel écrire (source d'écriture).
len
Longueur des données à lire ou écrire, spécifiée en octets. Les transferts valides vont de 0 octet jusqu'à la taille maximale de message (max_msg_size) du point de terminaison.
iov
Tampon de données vectorielles.
count
Nombre d'entrées de données vectorielles.
addr
Adresse de la mémoire distante à accéder. Ce sera l'adresse virtuelle de la région distante dans le cas de FI_MR_BASIC, ou le décalage par rapport à l'adresse de départ dans le cas de FI_MR_SCALABLE.
key
Clé de protection associée à la mémoire distante.
desc
Descripteur associé au tampon de données local. Voir fi_mr(3).
data
Données CQ distantes à transférer avec l'opération.
dest_addr
Adresse de destination pour les transferts d'écriture sans connexion. Ignoré pour les points de terminaison connectés.
src_addr
Adresse source à partir de laquelle lire pour les transferts sans connexion. Ignoré pour les points de terminaison connectés.
msg
Descripteur de message pour les opérations de lecture et d'écriture.
flags
Indicateurs supplémentaires à appliquer pour l'opération de lecture ou d'écriture.
context
Pointeur spécifié par l'utilisateur pour l'associer à l'opération. Ce paramètre est ignoré si l'opération ne génère pas une complétion réussie, sauf si un indicateur d'opération spécifie que le paramètre de contexte doit être utilisé pour une entrée requise.

DESCRIPTION

Les opérations d'accès à la mémoire distante (RMA - Remote Memory Access) sont utilisées pour transférer des données directement entre un tampon de données local et un tampon de données distant. Les transferts RMA se font à la granularité de l'octet, et aucune limite de message n'est maintenue.

Les fonctions d'écriture – fi_write, fi_writev, fi_writemsg, fi_inject_write, et fi_writedata – sont utilisées pour transmettre des données dans un tampon de mémoire distante. La principale différence entre les fonctions d'écriture réside dans le nombre et le type de paramètres qu'elles acceptent en entrée. Sinon, elles effectuent la même fonction générale.

Les fonctions de lecture – fi_read, fi_readv, et fi_readmsg – sont utilisées pour transférer des données d'une région de mémoire distante vers des tampons de données locaux. Similairement aux opérations d'écriture, les opérations de lecture sont asynchrones. Les utilisateurs ne doivent pas manipuler les tampons de données postés tant que l'opération de lecture n'est pas terminée.

Les opérations RMA complétées sont rapportées à l'utilisateur via une ou plusieurs files de complétion associées au point de terminaison. Les utilisateurs fournissent un contexte qui est associé à chaque opération et est renvoyé à l'utilisateur dans le cadre de la complétion. Voir fi_cq pour les détails des événements de complétion.

Par défaut, le point de terminaison distant ne génère pas d'événement et ne notifie pas l'utilisateur lorsqu'une région mémoire a été accédée par une opération de lecture ou d'écriture RMA. Cependant, des données immédiates peuvent être associées à une opération d'écriture RMA. Les écritures RMA avec données immédiates généreront une entrée de complétion au point de terminaison distant, afin que les données immédiates puissent être livrées.

fi_write

L'appel fi_write transfère les données contenues dans le tampon de données spécifié par l'utilisateur vers une région de mémoire distante.

fi_writev

L'appel fi_writev ajoute la prise en charge d'une liste scatter-gather à fi_write. fi_writev transfère l'ensemble des tampons de données référencés par le paramètre iov vers la région de mémoire distante.

fi_writemsg

L'appel fi_writemsg prend en charge les transferts de données sur des points de terminaison connectés et sans connexion, avec la capacité de contrôler l'opération d'écriture par appel grâce à l'utilisation d'indicateurs. La fonction fi_writemsg prend en entrée une structure fi_msg_rma.

struct fi_msg_rma {
    const struct iovec *msg_iov;     /* tableau scatter-gather local */
    void               **desc;       /* descripteur d'opération */
    size_t             iov_count;    /* nombre d'éléments dans msg_iov */
    fi_addr_t          addr;        /* adresse de point de terminaison optionnelle */
    const struct fi_rma_iov *rma_iov;/* SGL distant */
    size_t             rma_iov_count;/* nombre d'éléments dans rma_iov */
    void               *context;     /* contexte défini par l'utilisateur */
    uint64_t           data;         /* données immédiates optionnelles */
};
struct fi_rma_iov {
    uint64_t           addr;         /* adresse RMA cible */
    size_t             len;          /* taille du tampon cible */
    uint64_t           key;          /* clé d'accès */
};

fi_inject_write

L'appel d'écriture par injection (write inject) est une version optimisée de fi_write. Il fournit des sémantiques de complétion similaires à fi_inject de fi_msg(3).

fi_writedata

L'appel d'écriture avec données (write data) est similaire à fi_write, mais permet l'envoi de données CQ distantes (voir l'indicateur FI_REMOTE_CQ_DATA) dans le cadre du transfert.

fi_inject_writedata

L'appel d'injection d'écriture avec données (inject write data) est similaire à fi_inject_write, mais permet l'envoi de données CQ distantes (voir l'indicateur FI_REMOTE_CQ_DATA) dans le cadre du transfert.

fi_read

L'appel fi_read demande au point de terminaison distant de transférer des données de la région mémoire distante vers le tampon de données local.

fi_readv

L'appel fi_readv ajoute la prise en charge d'une liste scatter-gather à fi_read. fi_readv transfère des données de la région mémoire distante vers l'ensemble des tampons de données référencés par le paramètre iov.

fi_readmsg

L'appel fi_readmsg prend en charge les transferts de données sur des points de terminaison connectés et sans connexion, avec la capacité de contrôler l'opération de lecture par appel grâce à l'utilisation d'indicateurs. La fonction fi_readmsg prend en entrée une structure fi_msg_rma.

NAME

fi_readmsg, fi_writemsg - transfer data with message semantics

SYNOPSIS

#include <rdma/fi_domain.h>
#include <rdma/fi_endpoint.h>

ssize_t fi_readmsg(struct fid_ep *ep, const struct fi_msg *msg,
    uint64_t flags);
ssize_t fi_writemsg(struct fid_ep *ep, const struct fi_msg *msg,
    uint64_t flags);

ARGUMENTS

ep
The endpoint to use for the operation.
msg
The message structure containing data and addressing information. See fi_msg(3) for details.
flags
Flags that control the behavior of the read/write operation.

DESCRIPTION

The fi_readmsg and fi_writemsg calls are used to transfer data between endpoints using message semantics. Message semantics imply that the data transferred is self-describing and contains addressing information sufficient to deliver the data to the intended destination. This is in contrast to derived message semantics, which rely on pre-established connections or endpoints.

The fi_msg structure is used to specify the data buffers, addressing information, and other parameters for the message transfer. The contents of the fi_msg structure are detailed in the fi_msg(3) man page.

FLAGS

The fi_readmsg and fi_writemsg calls allow the user to specify flags which can change the default data transfer operation. Flags specified with fi_readmsg / fi_writemsg override most flags previously configured with the endpoint, except where noted (see fi_endpoint.3). The following list of flags are usable with fi_readmsg and/or fi_writemsg.

FI_REMOTE_CQ_DATA
Applies to fi_writemsg. Indicates that remote CQ data is available and should be sent as part of the request. See fi_getinfo for additional details on FI_REMOTE_CQ_DATA. This flag is implicitly set for fi_writedata and fi_inject_writedata.
FI_COMPLETION
Indicates that a completion entry should be generated for the specified operation. The endpoint must be bound to a completion queue with FI_SELECTIVE_COMPLETION that corresponds to the specified operation, or this flag is ignored.
FI_MORE
Indicates that the user has additional requests that will immediately be posted after the current call returns. Use of this flag may improve performance by enabling the provider to optimize its access to the fabric hardware.
FI_INJECT
Applies to fi_writemsg. Indicates that the outbound data buffer should be returned to user immediately after the write call returns, even if the operation is handled asynchronously. This may require that the underlying provider implementation copy the data into a local buffer and transfer out of that buffer. This flag can only be used with messages smaller than inject_size.
FI_INJECT_COMPLETE
Applies to fi_writemsg. Indicates that a completion should be generated when the source buffer(s) may be reused.
FI_TRANSMIT_COMPLETE
Applies to fi_writemsg. Indicates that a completion should not be generated until the operation has been successfully transmitted and is no longer being tracked by the provider.
FI_DELIVERY_COMPLETE
Applies to fi_writemsg. Indicates that a completion should be generated when the operation has been processed by the destination.
FI_COMMIT_COMPLETE
Applies to fi_writemsg when targeting persistent memory regions. Indicates that a completion should be generated only after the result of the operation has been made durable.
FI_FENCE
Applies to transmits. Indicates that the requested operation, also known as the fenced operation, and any operation posted after the fenced operation will be deferred until all previous operations targeting the same peer endpoint have completed. Operations posted after the fencing will see and/or replace the results of any operations initiated prior to the fenced operation.

The ordering of operations starting at the posting of the fenced operation (inclusive) to the posting of a subsequent fenced operation (exclusive) is controlled by the endpoint’s ordering semantics.

RETURN VALUE

Returns 0 on success. On error, a negative value corresponding to fabric errno is returned. Fabric errno values are defined in rdma/fi_errno.h.

ERRORS

-FI_EAGAIN
See fi_msg(3) for a detailed description of handling FI_EAGAIN.
