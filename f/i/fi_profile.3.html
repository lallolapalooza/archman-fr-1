NOM

fi_profile - Interface de profilage de fabric

fi_profile_open / fi_profile_close
Ouvre/ferme un objet profil sur un point de terminaison ou un domaine spécifié par le fid ou associé à l'objet profil.
fi_profile_query_vars / fi_profile_query_events
Interroge les variables/événements de profilage disponibles associés à l'objet profil.
fi_profile_read_u64
Lit la valeur d'une variable de type FI_UINT64.
fi_profile_reg_callback
Enregistre une fonction de rappel pour un événement de profilage.
fi_profile_start_reads / fi_profile_end_reads
Contrôle l'accès consécutif à plusieurs variables en même temps.

SYNOPSIS

include <rdma/fi_profile.h>
int fi_profile_open(struct fid *fid, uint64_t flags,
    struct fid_profile **prof_fid, void *context);
int fi_profile_close(struct fid_profile *prof_fid);
void fi_profile_reset(struct fid_profile *prof_fid,  uint64_t flags);
ssize_t fi_profile_query_vars(struct fid_profile *prof_fid,
    struct fi_profile_desc *varlist, size_t *count)
ssize_t fi_profile_query_events(struct fid_profile *prof_fid,
    struct fi_profile_desc *eventlist, size_t *count);
int fi_profile_register_callback(struct fid_profile *prof_fid,
    uint32_t event_id,
    int (*callback)(struct fid_profile *prof_fid, 
                    struct fi_profile_desc *event, void *param, 
                    size_t size, void *context),
    void *context);
sszie_t fi_profile_read_u64(struct fid_profile *prof_fid, uint32_t var_id,
    uint64_t *data);
void fi_profile_start_reads(struct fid_profile *prof_fid, uint64_t flags);
void fi_profile_end_reads(struct fid_profile *prof_fid, uint64_t flags);

ARGUMENTS

fid
Référence vers un point de terminaison ou un domaine qui est la cible du profilage.
prof_fid
Référence vers un objet profil associé au fid cible.
flags
Drapeaux pour contrôler le profilage ou l'opération.
context
Contexte associé aux opérations de profilage.
varlist
Un tableau de variables de profilage.
eventlist
Un tableau d'événements de profilage.
count
Nombre de variables ou d'événements disponibles dans le fournisseur.
var_id
Un identifiant unique pour une variable.
event_id
Un identifiant unique pour un événement.
callback
Fonction de rappel enregistrée pour un événement. Voir la description des rappels ci-dessous.
data
La valeur actuelle d'une variable.

DESCRIPTION

L'interface de profilage de fabric permet aux utilisateurs d'obtenir des propriétés de configuration ou d'exécution des fournisseurs sous la forme de « variables ». Les fournisseurs définissent des variables et les rendent lisibles par les utilisateurs via l'interface de profilage. Les fournisseurs définissent des événements et les utilisent pour signaler qu'une opération s'est produite ou qu'un état a changé où une ou plusieurs variables peuvent changer leurs valeurs. Les utilisateurs peuvent enregistrer des fonctions de rappel pour un ou plusieurs événements et recevoir des notifications des fournisseurs une fois qu'un événement se produit.

Pour prendre en charge l'interface de profilage, un point de terminaison ou un domaine dans un fournisseur doit maintenir un objet fid_profile et implémenter les opérations de profilage à cet endroit. Pour démarrer un profilage, un appel open doit être effectué sur le point de terminaison ou l'objet domaine cible pour obtenir l'objet fid_profile. Si l' objet cible ne prend pas en charge le profilage, l'appel open échouera avec le code d'erreur -FI_ENOSYS. Une fois qu'un objet fid_profile a été obtenu avec succès, il peut être utilisé pour interroger les variables ou événements disponibles et lire les valeurs des variables.

VARIABLES

Les variables de profilage sont définies dans les fournisseurs et sont accessibles via l'interface de profilage. Les variables sont spécifiées en utilisant le struct fi_profile_desc décrit ci-dessous. Une variable peut être un paramètre de configuration, un état d'exécution ou un compteur associé à un point de terminaison ou à un domaine. Certaines variables sont communes et disponibles dans la plupart des fournisseurs, tandis que d'autres sont spécifiques au fournisseur et ne sont disponibles que dans un fournisseur. Les utilisateurs peuvent interroger les variables disponibles et leurs valeurs en utilisant l'interface de profilage.

Les variables spécifiques au fournisseur sont hors du champ d'application de cette page man. Les variables définies par libfabric et leurs types de données sont décrits ci-dessous.

FI_VAR_UNEXP_MSG_CNT (type de données : uint64_t)

Cette variable renvoie le nombre actuel de messages inattendus qui ont été reçus par le fournisseur et qui attendent des tampons de réception correspondants.

FI_VAR_UNEXP_MSG_QUEUE (type de données : struct fi_cq_err_entry)

Cette variable renvoie les informations actuelles de la file d'attente des messages inattendus, chaque entrée dans la file correspond à un message inattendu présenté dans la structure fi_cq_err_entry.

ÉVÉNEMENTS

Des événements de profilage sont définis pour notifier les utilisateurs qu'une opération s'est produite ou que l'état d'un objet a changé, ce qui indique généralement qu'une ou plusieurs variables ont été modifiées. Les événements sont spécifiés en utilisant le struct fi_profile_desc décrit ci-dessous. Similairement aux variables, les événements peuvent être prédéfinis par libfabric ou spécifiques au fournisseur. Les utilisateurs peuvent enregistrer un rappel pour être notifiés lorsqu'un événement se produit. Les événements définis par libfabric et les données correspondantes à l'événement, le cas échéant, sont décrits ci-dessous.

Les applications peuvent lire les valeurs des variables à partir du rappel d'événement lorsque cela est autorisé, mais ne peuvent pas enregistrer ou désenregistrer des événements, interroger les variables ou événements de profilage.

Les événements prédéfinis par libfabric incluent :

FI_EVENT_UNEXP_MSG_RECVD

Cet événement indique qu'un message inattendu a été reçu et a été mis en file d'attente par le fournisseur.

FI_EVENT_UNEXP_MSG_MATCHED

Cet événement indique qu'un message inattendu qui a été précédemment mis en file d'attente par le fournisseur a été apparié.

Ces deux événements peuvent notifier un utilisateur sans aucune donnée et comptent sur l'utilisateur pour lire les variables, par exemple FI_VAR_UNEXP_MSG_CNT, pour obtenir la longueur actuelle de la file d'attente des messages inattendus. Ils peuvent aussi notifier un utilisateur avec des données de variable, par exemple FI_VAR_UNEXP_MSG_QUEUE, pour fournir les informations sur les messages de la file d'attente actuelle des messages inattendus.

PROFIL DESCRIPTION

Les variables et les événements sont décrites en utilisant le struct fi_profile_desc :

enum fi_profile_type {
    fi_primitive_type,
    fi_defined_type,
};
struct fi_profile_desc {
    uint32_t id;
    enum fi_profile_type datatype_sel;
    union {
        enum fi_datatype primitive;
        enum fi_type defined;
    } datatype;
    uint64_t flags;
    size_t size;
    const char *name;
    const char *desc;
};

id

Chaque variable ou événement a un identifiant unique (id). Les fournisseurs fournissent cet id et les utilisateurs l'utilisent pour obtenir la valeur de la variable ou enregistrer des rappels pour l'événement.

datatype

Le type de données de la variable. Il peut être soit fi_profile(3) - Libfabric Programmer’s Manual

NAME

fi_profile - fabric profiling interface

SYNOPSIS

#include <rdma/fi_profile.h>

FI_PROFILE_QUERY_VARS

FI_PROFILE_QUERY_EVENTS

FI_PROFILE_REG_CB

FI_PROFILE_OPEN

FI_PROFILE_CLOSE

FI_PROFILE_QUERY_VARS

FI_PROFILE_QUERY_EVENTS

FI_PROFILE_REG_CALLBACK

FI_PROFILE_READ_U64

FI_PROFILE_START_READS

FI_PROFILE_END_READS

ARGUMENTS

fid
Fabric resource identifier, such as fid_domain or fid_ep.
prof_fid
A pointer to the fid_profile object.
varlist
A pointer to an array of fi_profile_var structures. Used to return a list of available variables.
eventlist
A pointer to an array of fi_profile_desc structures. Used to return a list of available events.
count
The number of entries in the buffer (varlist or eventlist).
cb
A pointer to the callback function.
param
Optional user-defined parameter for the callback.
context
User-defined context for the callback.
var_id
The identifier of the variable to read.
val
A pointer to store the read value.

DESCRIPTION

The libfabric fabric profiling interface provides a mechanism for gathering runtime information about fabric operations. This can be useful for performance tuning and debugging.

The interface is accessible via the fid_profile object, which is obtained by calling fi_profile_open on a fabric domain (fid_domain) or endpoint (fid_ep).

The profiling interface exposes profiling variables and events. Variables represent specific metrics or counters (e.g., number of messages sent, bandwidth used), while events represent significant occurrences during fabric operations (e.g., connection established, error occurred).

Users can query available variables and events using fi_profile_query_vars and fi_profile_query_events, respectively. They can then read variable values using fi_profile_read_u64 or register callbacks for events using fi_profile_reg_callback.

The fi_profile_start_reads and fi_profile_end_reads functions can be used to group multiple variable reads to ensure they are captured from a consistent snapshot.

All profiling resources should be released by calling fi_profile_close.

PROFILE DESCRIPTION

The profiling interface uses the following structures to describe variables and events:

fi_profile_var
Structure used to describe a profiling variable.
name
A string identifier for the variable.
id
A unique identifier for the variable.
type
The data type of the variable. Can be a primitive type defined in enum fi_datatype or a libfabric structure type defined in enum fi_type.
datatye_sel
The selector for the data type. Indicates if the data type is from enum fi_datatype or enum fi_type.
flags
Flags indicating features or restrictions of the variable.
size
The size of the data in bytes.
desc
A reference to the description of the variable. Storage is managed by the provider. Variables with the same name should have identical IDs.
fi_profile_desc
Structure used to describe a profiling event.
name
A string identifier for the event.
id
A unique identifier for the event.
type
The data type of the event. Can be a primitive type defined in enum fi_datatype or a libfabric structure type defined in enum fi_type.
datatye_sel
The selector for the data type. Indicates if the data type is from enum fi_datatype or enum fi_type.
flags
Flags indicating features or restrictions of the variable.
size
The size of the data in bytes.
desc
A reference to the description of the event. Storage is managed by the provider. Events with the same name should have identical IDs.

fi_profile_open

Initiates profiling on a target endpoint or domain specified by fid. Upon successful return, a fid_profile object is returned and can be used for profiling operations. If the target does not support the fabric profiling interface, the call fails with error code -FI_ENOSYS.

fi_profile_close

Closes profiling operations and releases related resources.

fi_profile_query_vars / fi_profile_query_events

Queries available variables or events from the target endpoint or domain associated with the profile object. On input, the buffer (varlist or eventlist) should be allocated, and count indicates the maximum number of entries allowed. On output, count indicates the actual number of variables or events available. If the buffer is NULL, only count is set. Users can use this count to allocate space and call the function again. The return value indicates the number of entries returned in the buffer.

fi_profile_reg_callback

Registers a callback function to an event. The event must be in the event list obtained using fi_profile_query_events; otherwise, an error code -FI_EINVAL is returned.

Callback

Used to receive notifications from a provider when an event occurs. A callback can also take optional parameters allowing the provider to push data to the user when an event occurs.

A callback is defined by the user and called by a provider as an additional operation, normally before or after a data transfer operation. This increases the overhead of the operation. Callback functions must avoid blocking calls or taking significant time. They should limit interactions with a provider to reading variables only, if allowed.

The signature of the callback function is:

int (*callback)(struct fid_profile *prof_fid, struct fi_profile_desc *event,
                void *param, size_t size, void *context)
prof_fid
Reference to the profile object.
event
The description of the event to which the callback has been registered.
param
An optional parameter passed to the callback associated with the event. The data type and size of the parameter are defined in the event description.
size
The amount of data pointed to by param if param is not NULL.
context
The application context passed when the callback was registered.

fi_profile_read_u64

A wrapper function for FI_UINT64-type variables. It returns a uint64_t value of the specified variable. The variable must be in the variable list obtained using fi_profile_query_vars; otherwise, an error code -FI_EINVAL is returned.

fi_profile_start_reads / fi_profile_end_reads

Used when attempting to read multiple variables simultaneously. Variables read between these two calls are expected to have values from a single snapshot.

NOTES

Users should call fi_profile_close to release all resources allocated for profiling in the provider.

RETURN VALUES

Returns 0 on success. On error, a negative value corresponding to a fabric errno is returned. If the provider does not support the profiling interface, -FI_ENOSYS is returned. For fi_profile_query_vars and fi_profile_query_events, a positive return value indicates the number of variables or events returned in the list.

Fabric errno values are defined in <rdma/fi_errno.h>.
