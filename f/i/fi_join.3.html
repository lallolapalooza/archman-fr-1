NOM

fi_cm - Opérations de gestion de connexion

fi_connect / fi_listen / fi_accept / fi_reject / fi_shutdown
Gérer l'état de connexion d'un point d'accès.
fi_setname / fi_getname / fi_getpeer
Définir l'adresse locale, ou retourner l'adresse locale ou du pair.
fi_join / fi_close / fi_mc_addr
Rejoindre, quitter ou récupérer une adresse multicast.

SYNOPIS

#include <rdma/fi_cm.h>
int fi_connect(struct fid_ep *ep, const void *addr,
    const void *param, size_t paramlen);
int fi_listen(struct fid_pep *pep);
int fi_accept(struct fid_ep *ep, const void *param, size_t paramlen);
int fi_reject(struct fid_pep *pep, fid_t handle,
    const void *param, size_t paramlen);
int fi_shutdown(struct fid_ep *ep, uint64_t flags);
int fi_setname(fid_t fid, void *addr, size_t addrlen);
int fi_getname(fid_t fid, void *addr, size_t *addrlen);
int fi_getpeer(struct fid_ep *ep, void *addr, size_t *addrlen);
int fi_join(struct fid_ep *ep, const void *addr, uint64_t flags,
    struct fid_mc **mc, void *context);
int fi_close(struct fid *mc);
fi_addr_t fi_mc_addr(struct fid_mc *mc);

ARGUMENTS

ep / pep
Point d'accès tissu sur lequel changer l'état de la connexion.

fid Point d'accès actif ou passif pour obtenir/définir l'adresse.

addr
Tampon pour l'adresse. Lors d'un appel de définition, le point d'accès se verra attribuer l'adresse spécifiée. Lors d'une récupération, l'adresse locale sera copiée dans le tampon, jusqu'à l'espace fourni. Pour la connexion, ce paramètre indique l'adresse du pair à laquelle se connecter. L'adresse doit être dans le même format que celui spécifié à l'aide de fi_info: addr_format lors de la création du point d'accès.
addrlen
En entrée, spécifie la taille du tampon addr. En sortie, stocke le nombre d'octets écrits dans le tampon addr.
param
Données spécifiées par l'utilisateur échangées dans le cadre de l'échange de connexion.
paramlen
Taille du tampon param.
info
Informations sur le tissu associées à une demande de connexion.
mc
Groupe multicast associé à un point d'accès.
flags
Indicateurs supplémentaires pour contrôler l'opération de connexion.
context
Contexte utilisateur associé à la requête.

DESCRIPTION

Les fonctions de gestion de connexion sont utilisées pour connecter un point d'accès orienté connexion (FI_EP_MSG) à un pair écouteur.

fi_listen

L'appel fi_listen indique que le point d'accès spécifié doit être transitionné vers un état de connexion passive, lui permettant d'accepter les demandes de connexion entrantes. Les demandes de connexion à un point d'accès en écoute sont rapportées de manière asynchrone à l'utilisateur via une file d'événements CM liée, en utilisant le type d'événement FI_CONNREQ. Le nombre de demandes de connexion en attente qui peuvent être mises en file d'attente sur un point d'accès est limité par le paramètre de backlog du point d'accès en écoute. Le backlog est initialisé en fonction des valeurs de configuration administratives, mais peut être ajusté via l'appel fi_control.

fi_connect

L'appel fi_connect initie une demande de connexion sur un point d'accès orienté connexion vers l'adresse de destination. fi_connect ne peut être appelé sur un point d'accès qu'une seule fois dans sa vie.

fi_accept / fi_reject

Les appels fi_accept et fi_reject sont utilisés du côté passif (écouteur) d'une connexion pour accepter ou rejeter une demande de connexion, respectivement. Pour accepter une connexion, l'application en écoute attend d'abord un événement de demande de connexion (FI_CONNREQ). Après avoir reçu un tel événement, l'application alloue un nouveau point d'accès pour accepter la connexion. Ce point d'accès doit être alloué en utilisant une structure fi_info faisant référence au handle de cet événement FI_CONNREQ. fi_accept est ensuite appelé avec le point d'accès nouvellement alloué. Si l'application en écoute souhaite rejeter une demande de connexion, elle appelle fi_reject avec le point d'accès en écoute et une référence à la demande de connexion.

Une demande de connexion acceptée avec succès entraînera l'apparition d'un événement FI_CONNECTED du côté actif (connecteur) sur sa file d'événements associée. Une demande de connexion rejetée ou échouée générera un événement d'erreur. L'entrée d'erreur fournira des détails supplémentaires décrivant la raison de l'échec.

Un événement FI_CONNECTED sera également généré du côté passif pour le point d'accès accepteur une fois que la connexion a été correctement établie. Le fid de l'événement FI_CONNECTED sera celui du point d'accès passé à fi_accept, par opposition au point d'accès passif écouteur. Les transferts de données sortants ne peuvent pas être initiés sur un point d'accès orienté connexion avant qu'un événement FI_CONNECTED n'ait été généré. Cependant, les tampons de réception peuvent être associés à un point d'accès à tout moment.

fi_shutdown

L'appel fi_shutdown est utilisé pour déconnecter gracieusement un point d'accès de son pair. Le paramètre flags est réservé et doit être 0.

Les opérations en cours postées sur le point d'accès lorsque fi_shutdown est appelé seront annulées ou rejetées. La notification des opérations annulées sera rapportée par le fournisseur aux files de complétion correspondantes. Les opérations rejetées seront silencieusement abandonnées, sans générer de complétions. Le choix entre annuler et rejeter les opérations dépend du fournisseur. Cependant, toutes les complétions annulées seront écrites avant le retour de fi_shutdown.

Lorsqu'il est appelé, fi_shutdown n'affecte pas les complétions déjà écrites dans une file de complétion. Toutes les complétions mises en file d'attente associées à des opérations asynchrones postées sur le point d'accès peuvent toujours être récupérées des files de complétion correspondantes après qu'un point d'accès a été arrêté.

Un événement FI_SHUTDOWN sera généré pour un point d'accès lorsque le pair distant émet une déconnexion en utilisant fi_shutdown ou ferme abruptement le point d'accès. Notez que dans le cas de fermeture abrupte, un événement FI_SHUTDOWN ne sera généré que si le système distant est joignable et qu'un agent de service ou du noyau sur le système distant est capable de notifier le point d'accès local que la connexion a été interrompue.

fi_close

fi_close est utilisé pour dissocier un point d'accès d'un groupe multicast et fermer toutes les ressources associées au groupe. fi_close doit être appelé sur tous les groupes multicast que rejoint un point d'accès.

fi_setname

L'appel fi_setname peut être utilisé pour modifier ou attribuer l'adresse du point d'accès local. Il est conceptuellement similaire à l'opération bind de socket. Un point d'accès peut se voir attribuer une adresse lors de sa création, via la structure fi_info. L'appel fi_setname permet de créer un point d'accès sans l'associer à un service spécifique (par exemple, numéro de port) et/ou une adresse de nœud (par exemple, réseau), l'adressage étant attribué dynamiquement. Le format des données d'adressage spécifiées doit correspondre à celui spécifié via la structure fi_info lors de la création du point d'accès.

Si aucune adresse de service n'est spécifiée et qu'aucune adresse de service n'a encore été attribuée au point d'accès, le fournisseur allouera une adresse de service et l'attribuera au point d'accès. Si une adresse de nœud ou de service est spécifiée, alors, après la fin réussie de fi_setname, le point d'accès se verra attribuer l'adressage donné. Si une adresse ne peut pas être attribuée, ou si l'adresse du point d'accès ne peut pas être modifiée, un numéro d'erreur fabric approprié est retourné.

fi_getname / fi_getpeer

Les appels fi_getname et fi_getpeer peuvent être utilisés pour récupérer l'adresse du point d'accès local ou du pair, respectivement. fi_getname n'est pas garanti de retourner une adresse source valide tant que le point de terminaison spécifié n'a pas été activé ou n'a pas eu d'adresse assignée. Une adresse peut être assignée à l'aide de fi_setname. fi_getpeer n'est pas garanti de retourner une adresse de pair valide tant que le point de terminaison n'a pas été complètement connecté – un événement FI_CONNECTED n'a pas été généré.

fi_join

Cette fonction attache un point de terminaison à un groupe de multidiffusion. Par défaut, le point de terminaison rejoindra le groupe en fonction des capacités de transfert de données du point de terminaison. Par exemple, si le point de terminaison a été configuré pour à la fois envoyer et recevoir des données, alors le point de terminaison pourra initier et recevoir des transferts vers et depuis le groupe de multidiffusion. Les indicateurs de fi_join peuvent être utilisés pour restreindre l'accès au groupe de multidiffusion, sous réserve des limitations de capacité du point de terminaison.

Les opérations de jointure de multidiffusion se terminent de manière asynchrone. Un point de terminaison doit être lié à une file d'événements avant d'appeler fi_join. Le résultat de l'opération de jointure sera signalé à la file d'événements (EQ) sous la forme d'un événement FI_JOIN_COMPLETE. Les applications ne peuvent pas émettre de transferts de multidiffusion avant de recevoir la notification indiquant que l'opération de jointure est terminée. Notez qu'un point de terminaison peut commencer à recevoir des messages du groupe de multidiffusion dès que la jointure est terminée, ce qui peut survenir avant la génération de l'événement FI_JOIN_COMPLETE.

Les applications doivent appeler fi_close sur le groupe de multidiffusion pour déconnecter le point de terminaison du groupe. Après qu'une opération de jointure est terminée, l'appel fi_mc_addr peut être utilisé pour récupérer l'adresse associée au groupe de multidiffusion.

fi_mc_addr

Retourne l'adresse fi_addr_t associée à un groupe de multidiffusion. Cette adresse doit être utilisée lors de la transmission de données à un groupe de multidiffusion et associée à l'indicateur d'opération FI_MULTICAST.

INDICATEURS

Sauf dans les fonctions notées ci-dessous, les indicateurs sont réservés et doivent être 0.

FI_SEND
S'applique à fi_join. Cet indique que le point de terminaison doit rejoindre le groupe de multidiffusion en tant que membre en émission uniquement. Le point de terminaison doit être configuré pour les opérations de transmission afin d'utiliser cet indicateur, sinon une erreur se produira.
FI_RECV
S'applique à fi_join. Cet indique que le point de terminaison doit rejoindre le groupe de multidiffusion avec des permissions de réception uniquement. Le point de terminaison doit être configuré pour les opérations de réception afin d'utiliser cet indicateur, sinon une erreur se produira.

VALEUR RETOURNÉE

Retourne 0 en cas de succès. En cas d'erreur, une valeur négative correspondant à errno de la fabrique est retournée. Les valeurs de errno de la fabrique sont définies dans rdma/fi_errno.h.

ERREURS

NOTES

Pour les points de terminaison orientés connexion, le tampon référencé par param sera envoyé dans le cadre de la demande ou de la réponse de connexion, sous réserve des contraintes du protocole de connexion sous-jacent. Les applications peuvent utiliser fi_getopt avec l'option de point de terminaison FI_OPT_CM_DATA_SIZE pour déterminer la taille des données d'application qui peuvent être échangées dans le cadre d'une demande ou d'une réponse de connexion. Les appels fi_connect, fi_accept et fi_reject tronqueront silencieusement toute donnée d'application qui ne peut pas tenir dans les messages du protocole sous-jacent. Les données utilisateur échangées dans le cadre du processus de connexion sont disponibles dans la structure fi_eq_cm_entry, pour les événements FI_CONNREQ et FI_CONNECTED, ou comme err_data supplémentaire à fi_eq_err_entry, dans le cas d'une connexion rejetée.
