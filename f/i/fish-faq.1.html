QUELLE EST L'ÉQUIVALENT DE CE CHOSE DE BASH (OU D'AUTRES SHELLS) ?

Voir Fish pour les utilisateurs de bash <>

COMMENT PUIS-JE DÉFINIR OU EFFACER UNE VARIABLE D'ENVIRONNEMENT ?

Utilisez la commande set <> :

set -x clé valeur # typiquement set -gx clé valeur
set -e clé

Depuis fish 3.1, vous pouvez définir une variable d'environnement pour une seule commande en utilisant la syntaxe clé=valeur une commande, comme dans d'autres shells. Les deux lignes ci-dessous se comportent de manière identique - contrairement aux autres shells, fish affichera valeur les deux fois :

clé=valeur écho $clé
begin; set -lx clé valeur; écho $clé; end

Notez que « exporté » n'est pas une portée <#variables-scope>, mais un état supplémentaire. Une variable peut être globale et exportée, ou locale et exportée, ou même universelle et exportée. Typiquement, il est logique de rendre une variable exportée globale.

COMMENT PUIS-JE VÉRIFIER SI UNE VARIABLE EST DÉFINIE ?

Utilisez set -q var. Par exemple, if set -q var; écho variable définie; end. Pour vérifier plusieurs variables, vous pouvez les combiner avec and et or comme ceci :

if set -q var1; ou set -q var2
    écho l'une ou l'autre variable définie
end

Gardez à l'esprit qu'une variable définie peut également être vide, soit parce qu'elle n'a aucun élément (si définie comme set var), soit parce qu'elle n'a que des éléments vides (si définie comme set var ""). Lisez la suite pour savoir comment gérer cela.

COMMENT PUIS-JE VÉRIFIER SI UNE VARIABLE N'EST PAS VIDE ?

Utilisez string length -q -- $var. Par exemple, if string length -q -- $var; écho pas vide; end. Notez que string length interprétera une liste de plusieurs variables comme une disjonction (c'est-à-dire une condition OU) :

if string length -q -- $var1 $var2 $var3
    écho au moins une de ces variables n'est pas vide
end

Alternativement, utilisez test -n "$var", mais n'oubliez pas que la variable doit être mise entre guillemets doubles. Par exemple, if test -n "$var"; écho pas vide; end. La commande test fournit ses propres opérateurs et (-a) et ou (-o) :

if test -n "$var1" -o -n "$var2" -o -n "$var3"
    écho au moins une de ces variables n'est pas vide
end

Si vous voulez savoir si une variable n'a aucun élément, utilisez set -q var[1].

POURQUOI SET -UX (VARIABLES UNIVERSELLES EXPORTÉES) NE SEMBLE-T-IL PAS FONCTIONNER ?

Une variable globale du même nom existe déjà.

Les variables d'environnement telles que EDITOR ou TZ peuvent être définies universellement en utilisant set -Ux. Cependant, s'il existe une variable d'environnement déjà définie avant le démarrage de fish (par exemple, par des scripts de connexion ou par les administrateurs système), elle est importée dans fish en tant que variable globale. Les portées de variables <#variables-scope> sont recherchées de l'« intérieur vers l'extérieur », ce qui signifie que les variables locales sont vérifiées en premier, suivies des variables globales, et enfin des variables universelles.

Cela signifie que la valeur globale a la priorité sur la valeur universelle.

Pour éviter ce problème, envisagez de modifier le paramètre dont fish hérite. Si cela n'est pas possible, ajoutez une instruction à votre fichier de configuration <#configuration> (généralement ~/.config/fish/config.fish) :

set -gx EDITOR vim

COMMENT PUIS-JE EXÉCUTER UNE COMMANDE À CHAQUE CONNEXION ? QUEL EST L'ÉQUIVALENT FISH DE .BASHRC OU .PROFILE ?

Modifiez le fichier ~/.config/fish/config.fish [1], en le créant s'il n'existe pas (Notez le point de départ).

Contrairement à .bashrc et .profile, ce fichier est toujours lu, même dans les shells non interactifs ou de connexion.

Pour faire quelque chose uniquement dans les shells interactifs, vérifiez status is-interactive comme suit :

if status is-interactive
    # utiliser le thème coolbeans
    fish_config theme choose coolbeans
end
[1]
La partie « ~/.config » de ceci peut être définie via $XDG_CONFIG_HOME, c'est juste la valeur par défaut.

COMMENT PUIS-JE DÉFINIR MON PROMPT ?

Le prompt est le résultat de la fonction fish_prompt. Placez-la dans ~/.config/fish/functions/fish_prompt.fish. Par exemple, un prompt simple est :

function fish_prompt
    set_color $fish_color_cwd
    echo -n (prompt_pwd)
    set_color normal
    echo -n ' > '
end

Vous pouvez également utiliser l'outil de configuration Web, fish_config <>, pour prévisualiser et choisir parmi une galerie de prompts d'exemple.

Ou vous pouvez utiliser fish_config depuis la ligne de commande :

> fish_config prompt show
# affiche tous les prompts fournis par fish
> fish_config prompt choose disco
# charge le prompt disco dans le shell actuel
> fish_config prompt save
# rend le changement permanent

Si vous souhaitez modifier votre prompt existant, vous pouvez utiliser funced <> et funcsave <> comme suit :

>_ funced fish_prompt
# Ceci ouvre votre éditeur (défini dans $EDITOR).
# Modifiez la fonction,
# sauvegardez le fichier et répétez jusqu'à satisfaction.
# Une fois que vous êtes satisfait :
>_ funcsave fish_prompt

Ceci s'applique également à fish_right_prompt <> et fish_mode_prompt <>.

POURQUOI MON PROMPT AFFICHE-T-IL UN [I] ?

C'est le fish_mode_prompt <>. Il est affiché par défaut lorsque vous avez activé le mode vi à l'aide de fish_vi_key_bindings.

Si vous n'avez pas activé le mode vi intentionnellement, vous avez peut-être installé un thème ou un plugin tiers qui le fait.

Si vous souhaitez modifier ou désactiver cet affichage, modifiez la fonction fish_mode_prompt, par exemple via funced <>.

COMMENT PERSONNALISER LES COULEURS DE LA COLORATION SYNTAXIQUE ?

Utilisez l'outil de configuration Web, fish_config <>, ou modifiez la famille de variables d'environnement fish_color <#variables-color>.

Vous pouvez également utiliser fish_config sur la ligne de commande, comme ceci :

> fish_config theme show
# pour démontrer tous les schémas de couleurs
> fish_config theme choose coolbeans
# pour charger le thème "coolbeans"
> fish_config theme save
# pour rendre le changement permanent

COMMENT PUIS-JE MODIFIER LE MESSAGE DE BIENVENUE ?

Modifiez la valeur de la variable fish_greeting ou créez une fonction fish_greeting <>. Par exemple, pour supprimer le message de bienvenue, utilisez :

set -U fish_greeting

Ou si vous préférez ne pas utiliser de variable universelle, utilisez :

set -g fish_greeting

dans config.fish <#configuration>.

COMMENT PUIS-JE EXÉCUTER UNE COMMANDE DE L'HISTORIQUE ?

Tapez une partie de la commande, puis appuyez sur les touches de flèche haut (↑) ou bas (↓) pour naviguer dans les correspondances de l'historique, ou appuyez sur ctrl-r pour ouvrir l'historique dans un pager consultable. Dans ce pager, vous pouvez appuyer sur ctrl-r ou ctrl-s pour aller vers un historique plus ancien ou plus récent

respectivement.

Les raccourcis clavier par défaut supplémentaires incluent ctrl-p (haut) et ctrl-n (bas). Voir Recherche dans l'historique des comman

des <#history-search>
pour plus d'informations.

POURQUOI LA SUBSTITUTION D'HISTORIQUE ("!$" ETC.) NE FONCTIONNE-T-ELLE PAS

?

Parce que la substitution d'historique est une interface maladroite qui a été inventée avant même que l'édition de ligne interactive ne soit possible. Au lieu de ajouter cette pseudo-syntaxe, fish opte pour de bonnes fonctionnalités de recherche et de rappel d'historique. Le changement nécessite un petit ajustement de vos habitudes : si vous voulez modifier une ancienne ligne/mot, rappelez-le d'abord, puis

éditez-le.

Dans un cas particulier, la substitution d'historique est la plupart du temps utilisée comme sudo !!. Dans ce cas, appuyez sur alt-s, et cela rappellera votre dernière ligne de commande avec sudo en préfixe (ou basculera un préfixe sudo sur la ligne de commande actuelle s'il y en a un)

.

En général, le rappel d'historique de fish fonctionne ainsi

:
  • Comme d'autres shells, la flèche vers le haut, up rappelle des lignes entières, en commençant par la dernière ligne exécutée. Ainsi, au lieu de taper !!, vous appuierez sur la flèche vers le
    • haut.
  • Si la ligne que vous voulez est loin dans l'historique, tapez n'importe quelle partie de la ligne et appuyez ensuite sur Up une ou plusieurs fois. Cela filtrera les lignes rappelées pour n'inclure que celles qui contiennent ce texte, et vous atteindrez la ligne voulue beaucoup plus vite. Cela remplace "!vi", "!?bar.c" et autres. Si vous voulez voir plus de contexte, vous pouvez appuyer sur ctrl-r pour ouvrir l'historique dans le
    • pager.
  • alt-up rappelle des arguments individuels, en commençant par le de
    • rnier argument de la dernièr
e ligne exécutée. Cela peut être
utilisé à la place de "!$".

Voir la documentation <#editor> pour plus de détails sur l'édition de ligne dans

fish.

Cela dit, vous pouvez utiliser les Abréviations <#abbreviations> pour implémenter la substitution d'historique. Voici !! uniquement

: 
function last_history_item; echo $history[1]; end
abbr -a !! --position anywhere --function
last_history_it
e
m

Exécutez ceci et !! sera remplacé par la dernière entrée de l'historique, n'importe où sur la li

gne de commande. Mettez-le dans config.fi
sh <#configuration> pour le conserver.

COMMENT EXÉCUTER UNE SOUS-COMMANDE ? LES ACCOLADES GRAVES NE FONCTIONNENT PAS

!

fish utilise les parenthèses pour les sous-commandes. Par exemple

: 
for i i
n (ls)
echo
$i end

Il prend également en charge la syntaxe familière $(), même dans les guillemets. Les accents graves ne sont pas pris en charge car ils sont découragés même dans les shells POSIX. Ils s'imbriquent mal et sont difficiles à distinguer des guillemets simples (''

)
.

MA COMMANDE (PKG-CONFIG) DONNE SA SORTIE EN UNE SEULE LONGUE CHAÎNE

?

Contrairement à d'autres shells, fish ne divise les substitutions de commande que sur les nouvelles lignes, pas sur les espaces, les tabulations ou les caractères de

$IFS.

Cela signifie que si vous

exécutez 
count
(printf
'%s '
a b c)

Cela affichera 1, parce que "a b c " est utilisé en un seul bloc. Mais si vous

faites 
count (
printf
'%s\n'
a b c)

cela affichera 3, parce que cela a donné à count les arguments "a", "b" et "c"

séparément.

Dans la grande majorité des cas, la division sur les espaces est indésirable, c'est donc une amélioration. C'est pourquoi vous entendez parler de problèmes avec les noms de fichiers contenant des espaces, après

tout.

Cependant, parfois, surtout avec pkg-config et les outils associés, la division sur les espaces est

nécessaire.

Dans ces cas, utilisez string split -n " " comme ceci

: 
g++ example_01.cpp (
pkg-config --cflags
--libs gtk+-2.0 |
string split -n " ")

Le -n est là pour que les éléments vides soient

supprimés comme le fera
ient les shells POSIX.

MA COMMANDE IMPRIME "NO MATCHES FOR WILDCARD" MAIS FONCTIONNE DANS

BASH

En bref : mettez entre guillemets <#quotes> ou échappez <#escapes> le caractère générique

Lorsque fish voit un * non entouré de guillemets, il effectue l'expansion des caractères génériques <#expand-wildcard>. Cela signifie qu'il essaie de faire correspondre des noms de fichiers à la chaîne

donnée.

Si le caractère générique ne correspond à aucun fichier, fish affiche une erreur au lieu d'exécuter la commande

: 
> echo *this*does*not*exist

echo *this*does*not*exist
^

Maintenant, bash essaie aussi de faire correspondre des fichiers dans ce cas, mais lorsqu'il ne trouve pas de correspondance, il transmet la chaîne littérale du caractère générique à la

place.

Cela signifie que des commandes comme celles

ci-dessus

stall

gres-*

semblent fonctionner, parce que la plupart du temps la chaîne ne correspond pas et donc elle transmet string-*, qui est ensuite interprété par le programme de

réception.

Mais cela signifie aussi que ces commandes peuvent cesser de fonctionner à tout moment dès qu'un fichier correspondant est rencontré (parce qu'il a été créé ou la commande est exécutée dans un répertoire de travail différent), et pour gérer cela bash a besoin de solutions de contournement

étendus.

POURQUOI SSH/SCP/RSYNC NE S'CONNECTE-T-IL PAS CORRECTEMENT QUAND FISH EST MON SHELL DE CONNEXION

?

Ce problème peut se manifester par des messages comme "Received message too long", "open terminal failed: not a terminal", "Bad packet length", ou "Connection refused" avec une sortie étrange dans les messages ssh_exchange_identification du journal de

débogage.

Cela se produit généralement parce que fish lit le fichier de configuration utilisateur <#configuration> (~/.config/fish/config.fish) toujours, qu'il s'agisse d'un shell interactif ou de connexion ou non interactif ou non de

connexion.

Cela simplifie les choses, mais cela signifie aussi que lorsque config.fish produit une sortie, il le fera même dans des shells non interactifs comme celui que ssh/scp/rsync lancent lorsqu'ils se

connectent.

Tout dans config.fish qui produit une sortie doit être protégé avec status is-interactive (ou status is-login si vous préférez)

: 
if statu
s is-inte
ractive
... end

La même chose s'applique par exemple lorsque vous lancez tmux dans config.fish sans protection, ce qui causera un message comme sessions should be nested w

ith care, unset
$TMUX to force.

Dans un terminal, l'application qui s'exécute à l'intérieur et le terminal lui-même doivent s'accorder sur la largeur des caractères afin de gérer le mouvement du

curseur.

C'est plus important pour fish que pour d'autres shells parce que des fonctionnalités comme la coloration syntaxique et les suggestions automatiques sont implémentées en déplaçant le

curseur.

Parfois, il y a un désaccord sur la largeur. Il y a de nombreuses causes et solutions pour cela

:
  • Il est possible que le caractère soit trop récent pour que votre système le connaisse - dans ce cas, vous devez vous abstenir de
    • l'utiliser.
  • Fish ou votre terminal pourraient ne pas connaître le caractère ou le gérer mal - dans ce cas, fish ou votre terminal doit être corrigé, ou vous devez mettre à jour vers une version
    • corrigée.
  • Le caractère a une largeur "ambiguë" et fish pense que cela signifie une largeur de X alors que votre terminal pense que c'est Y. Dans ce cas, vous devez soit changer la configuration de votre terminal, soit définir $fish_ambiguous_width sur la valeur
    • correcte.
