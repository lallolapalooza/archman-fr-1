Pour spécifier une complétion, utilisez la commande complete . complete prend en paramètre le nom de la commande pour laquelle spécifier une complétion. Par exemple, pour ajouter une complétion pour le programme myprog, commencez la commande de complétion par complete -c myprog ...

Pour une description complète des différents commutateurs acceptés par la commande complete , consultez la documentation de la commande interne complete <>, ou écrivez complete --help à l'intérieur du shell fish .

Pour fournir une liste de complétions possibles pour myprog, utilisez le commutateur -a . Si myprog accepte les arguments start et stop, cela peut être spécifié comme complete -c myprog -a 'start stop'. L'argument du commutateur -a est toujours une seule chaîne. Au moment de la complétion, elle sera tokenisée sur les espaces et les tabulations, et l'expansion de variables, la substitution de commandes et les autres formes d'expansion de paramètres auront lieu :

# Si myprog peut lister les sorties valides avec la sous-commande list-outputs :
complete -c myprog -l output -a '(myprog list-outputs)'

fish a une syntaxe spéciale pour prendre en charge la spécification des commutateurs acceptés par une commande. Les commutateurs -s, -l et -o sont utilisés pour spécifier un commutateur court (un seul caractère, comme -l), un commutateur long de style gnu (comme --color) et un commutateur long de style ancien (avec un seul -, comme -shuffle), respectivement. Si la commande 'myprog' a une option qui peut être écrite comme -o ou --output, c'est-à-dire :

complete -c myprog -s o -l output

Si cette option prend un argument facultatif, vous ajouteriez également --argument ou -a, et lui donneriez les arguments possibles :

complete -c myprog -s o -l output -a "yes no"

Cela propose les arguments "yes" et "no" pour :

> myprog -o<TAB>
> myprog --output=<TAB>

Par défaut, les arguments d'options sont facultatifs, donc les candidats ne sont proposés que directement attachés comme cela, ils ne sont donc pas donnés dans ce cas :

> myprog -o <TAB>

Habituellement, les options nécessitent un paramètre, vous donneriez donc --require-parameter / -r:

complete -c myprog -s o -l output -ra "yes no"

ce qui propose yes/no dans ces cas :

> myprog -o<TAB>
> myprog --output=<TAB>
> myprog -o <TAB>
> myprog --output <TAB>

Fish proposera aussi les fichiers par défaut, en plus des arguments que vous avez spécifiés. Vous inhiberiez la complétion de fichiers pour une seule option :

complete -c myprog -s o -l output --no-files -ra "yes no"

ou avec une condition spécifique :

complete -c myprog -f --condition '__fish_seen_subcommand_from somesubcommand'

ou vous pouvez désactiver les complétions de fichiers globalement pour la commande :

complete -c myprog -f

Si vous les avez désactivées globalement, vous pouvez les activer juste pour une condition ou une option spécifique avec l'option --force-files / -F :

# Désactiver les fichiers par défaut
complete -c myprog -f
# mais les réactiver pour --config-file
complete -c myprog -l config-file --force-files -r

Comme exemple plus complet, voici un extrait commenté des complétions pour le timedatectlde systemd :

# Toutes les sous-commandes que timedatectl connaît - c'est utile pour plus tard.
set -l commands status set-time set-timezone list-timezones set-local-rtc set-ntp
# Désactiver les complétions de fichiers pour la commande entière
# car elle ne prend pas de fichiers nulle part
# Notez que cela peut être annulé en utilisant "-F".
#
# Les complétions de fichiers doivent aussi être désactivées
# si vous voulez avoir plus de contrôle sur les fichiers proposés
# (par ex. seulement les répertoires, ou seulement les fichiers se terminant par ".mp3").
complete -c timedatectl -f
# Cette ligne propose les sous-commandes
# -"status",
# -"set-timezone",
# -"set-time"
# -"list-timezones"
# si aucune sous-commande n'a été donnée jusqu'à présent.
#
# L'option `-n`/`--condition` prend un script sous forme de chaîne, qu'elle exécute.
# S'il retourne vrai, la complétion est proposée.
# Ici, la condition est la fonction d'aide `__fish_seen_subcommand_from`.
# Elle retourne vrai si l'une des commandes données est utilisée sur la ligne de commande,
# comme déterminé par une heuristique simple.
# Pour des utilisations plus complexes, vous pouvez écrire votre propre fonction.
# Voir par exemple les complétions de git pour un exemple.
#
complete -c timedatectl -n "not __fish_seen_subcommand_from $commands" \
    -a "status set-time set-timezone list-timezones"
# Si la sous-commande "set-timezone" est utilisée,
# proposer la sortie de `timedatectl list-timezones` comme complétions.
# Chaque ligne de sortie est utilisée comme un candidat séparé,
# et tout ce qui suit une tabulation est pris comme la description.
# Il est souvent utile de transformer la sortie d'une commande avec `string` sous cette forme.
complete -c timedatectl -n "__fish_seen_subcommand_from set-timezone" \
    -a "(timedatectl list-timezones)"
# Les candidats de complétion peuvent aussi être décrits via `-d`,
# ce qui est utile si la description est constante.
# Essayez de les garder courts, car cela signifie que l'utilisateur en voit plus à la fois.
complete -c timedatectl -n "not __fish_seen_subcommand_from $commands" \
    -a "set-local-rtc" -d "Maintain RTC in local time"
# Nous pouvons aussi limiter les options à certaines sous-commandes en utilisant des conditions.
complete -c timedatectl -n "__fish_seen_subcommand_from set-local-rtc" \
    -l adjust-system-clock -d 'Synchronize system clock from the RTC'
# Ce sont des options simples qui peuvent être utilisées partout.
complete -c timedatectl -s h -l help -d 'Print a short help text and exit'
complete -c timedatectl -l version -d 'Print a short version string and exit'
complete -c timedatectl -l no-pager -d 'Do not pipe output into a pager'

Pour des exemples de la façon d'écrire vos propres complétions complexes, étudiez les complétions dans /usr/share/fish/completions. (Le chemin exact dépend du préfixe d'installation que vous avez choisi et peut être légèrement différent)

FONCTIONS UTILES POUR ÉCRIRE DES COMPLÉTIONS

fish est livré avec plusieurs fonctions qui peuvent être utiles lors de l'écriture de complétions spécifiques à une commande. La plupart de ces noms de fonctions commencent par la chaîne __fish_. De telles fonctions sont internes à fish et leur nom et leur interface peuvent changer dans les futures versions de fish. Quelques-unes de ces fonctions sont décrites ici.

Les fonctions commençant par la chaîne __fish_print_ impriment une liste de chaînes séparées par des sauts de ligne. Par exemple, __fish_print_filesystems imprime une liste de tous les systèmes de fichiers connus. Les fonctions commençant par __fish_complete_ impriment une liste de complétions séparées par des sauts de ligne avec des descriptions. La description est séparée de la complétion par un caractère de tabulation.

  • __fish_complete_directories STRING DESCRIPTION effectue une complétion de chemin sur STRING, n'autorisant que les répertoires, et leur donnant la description DESCRIPTION.
  • __fish_complete_path STRING DESCRIPTION effectue une complétion de chemin sur STRING, leur donnant la description DESCRIPTION.
  • __fish_complete_groups imprime une liste de tous les groupes d'utilisateurs avec les membres du groupe comme description.
  • __fish_complete_pids imprime une liste de tous les identifiants de processus avec le nom de la commande comme description.
  • __fish_complete_suffix SUFFIX effectue une complétion de fichiers mais trie les fichiers se terminant par SUFFIX en premier. C'est utile en conjonction avec complete --keep-order.
  • __fish_complete_users imprime une liste de tous les utilisateurs avec leur nom complet comme description.
  • __fish_print_filesystems imprime une liste de tous les systèmes de fichiers connus. Actuellement, c'est une liste statique, et non dépendante des systèmes de fichiers que le système d'exploitation hôte comprend réellement.
  • __fish_print_hostnames imprime une liste de tous les noms d'hôtes connus. Cette fonction recherche dans le fstab les serveurs nfs, dans ssh les hôtes connus et vérifie le fichier /etc/hosts .
  • __fish_print_interfaces imprime une liste de toutes les interfaces réseau connues.

OÙ PLACER LES COMPLÉTIONS

Les complétions peuvent être définies sur la ligne de commande ou dans un fichier de configuration, mais elles peuvent aussi être automatiquementchargé. Fish recherche automatiquement dans tous les répertoires de la variable $fish_complete_path, et toutes les complétions définies sont automatiquement chargées lorsque nécessaire. Un fichier de complétion doit avoir un nom de fichier composé du nom de la commande à compléter et du suffixe .fish.

Par défaut, Fish recherche les complétions dans les emplacements suivants, en utilisant le premier fichier disponible qu'il trouve :

  • Un répertoire où les utilisateurs finaux peuvent conserver leurs propres complétions, généralement ~/.config/fish/completions (contrôlé par la variable d'environnement XDG_CONFIG_HOME) ;
  • Un répertoire où les administrateurs système peuvent installer des complétions pour tous les utilisateurs du système, généralement /etc/fish/completions ;
  • Un répertoire spécifié par l'utilisateur pour les complétions de fournisseurs tiers, généralement ~/.local/share/fish/vendor_completions.d (contrôlé par la variable d'environnement XDG_DATA_HOME) ;
  • Un répertoire où les fournisseurs de logiciels tiers peuvent distribuer leurs propres complétions pour leurs logiciels, généralement /usr/share/fish/vendor_completions.d ;
  • Les complétions distribuées avec fish, généralement installées dans /usr/share/fish/completions ; et
  • Les complétions générées automatiquement à partir du manuel du système d'exploitation, généralement stockées dans ~/.cache/fish/generated_completions (contrôlé par la variable d'environnement XDG_CACHE_HOME).

Ces chemins sont contrôlés par des paramètres définis au moment de la compilation, de l'installation ou de l'exécution, et peuvent différer des valeurs par défaut énumérées ci-dessus.

Cette large recherche peut prêter à confusion. Si vous n'êtes pas sûr, vos complétions appartiennent probablement à ~/.config/fish/completions.

Si vous avez écrit de nouvelles complétions pour une commande Unix courante, veuillez envisager de partager votre travail en le soumettant via les instructions dans Aide et développement supplémentaires <#more-help>.

Si vous développez un autre programme et souhaitez distribuer des complétions avec votre programme, installez-les dans le répertoire de complétions "vendor". Comme ce chemin peut varier d'un système à l'autre, le cadre pkgconfig doit être utilisé pour découvrir ce chemin avec la sortie de pkg-config --variable completionsdir fish.
