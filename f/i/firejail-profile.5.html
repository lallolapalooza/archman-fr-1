Construction manuelle d'un profil

:
Commencez avec le modèle dans /usr/share/doc/firejail/profile.template et modifiez-le dans un éditeur de texte. Pour intégrer le programme dans votre environnement de bureau, copiez le fichier de profil dans le répertoire ~/.config/firejail et exécutez « sudo firecfg »

DESCRIPTIO

N

Plusieurs options de ligne de commande peuvent être passées au programme à l'aide de fichiers de profil. Firejail choisit le fichier de profil comme suit

:

1. Si un fichier de profil est fourni par l'utilisateur avec l'option --profile, le fichier de profil est chargé. Si un nom de profil est donné, il est d'abord recherché dans le répertoire ~/.config/firejail et s'il n'est pas trouvé, alors dans le répertoire /etc/firejail. Les noms de profils n'incluent pas le suffixe .profile. Exemple

:
$ firejail --profile=/home/netblue/icecat.profile icecat
Lecture du profil /home/netblue/icecat.profile
[...
]
$ firejail --profile=icecat icecat-wrapper.sh
Lecture du profil /etc/firejail/icecat.profile
[...
]

2. Si un fichier de profil portant le même nom que l'application est présent dans le répertoire ~/.config/firejail ou dans /etc/firejail, le profil est chargé. ~/.config/firejail a la priorité sur /etc/firejail. Exemple

:
$ firejail icecat
Nom de la commande #icecat#
Profil icecat trouvé dans le répertoire /home/netblue/.config/firejail
Lecture du profil /home/netblue/.config/firejail/icecat.profile
[...
]

3. Utilisez un fichier default.profile si la bac à sable est démarrée par un utilisateur normal, ou un fichier server.profile si la bac à sable est démarrée par root. Firejail recherche ces fichiers dans le répertoire ~/.config/firejail, puis dans /etc/firejail. Pour désactiver le chargement du profil par défaut, utilisez l'option de commande --noprofile. Exemple

:
$ firejail
Lecture du profil /etc/firejail/default.profile
PID parent 8553, PID enfant 8554
Processus enfant initialisé
[...]

$ firejail --noprofile
PID parent 8553, PID enfant 8554
Processus enfant initialisé
[

.
..
]

Ces entrées de profil définissent un système de fichiers chroot construit par-dessus le système de fichiers existant de l'hôte. Chaque ligne décrit un fichier/répertoire qui est inaccessible (blacklist), un fichier ou répertoire en lecture seule (read-only), un tmpfs monté par-dessus un répertoire existant (tmpfs), ou le montage en bind d'un répertoire ou fichier par-dessus un autre répertoire ou fichier (bind). Utilisez private pour définir le mode privé. Le globbing de fichiers est pris en charge, et les répertoires PATH et HOME sont recherchés, voir la firejail(1) section FILE GLOBBING pour plus de détails. Exemples

file_or_directory
Mettre un répertoire ou un fichier sur liste blanche. Un système de fichiers temporaire est monté sur le répertoire supérieur. Dans le contexte de firejail, répertoire supérieur signifie, si le chemin du fichier sur liste blanche est par exemple /etc/somedir/somefile, alors le répertoire supérieur serait /etc. Tous les autres répertoires supérieurs comme /opt, /usr et ainsi de suite, n'ont pas changé, donc tous les fichiers qui s'y trouvent sont toujours accessibles, sauf si un fichier ou répertoire à l'intérieur est également sur liste blanche. C'est pourquoi il est parfois bénéfique d'utiliser blacklist en combinaison avec whitelist, s'ils sont utilisés pour différents répertoires supérieurs.

Les fichiers sur liste blanche sont montés en bind à l'intérieur. Les modifications des fichiers sur liste blanche sont persistantes, tout le reste dans le même répertoire supérieur est jeté lorsque la sandbox est

fermée.

Le répertoire supérieur peut être la plupart des répertoires dans /, mais il y a quelques cas particuliers. Les répertoires supérieurs /proc et /sys ne sont pas autorisés, mais /sys/module l'est. De même /run/user/$UID, $HOME et tous les répertoires dans /usr sont traités comme un répertoire

supérieur.

Filtrage

DBus

L'accès aux sockets UNIX DBus de session et système peut être autorisé, filtré ou désactivé. Pour désactiver les sockets abstraits (et forcer les applications à utiliser le socket UNIX filtré), vous devriez demander un nouvel espace de noms réseau en utilisant la commande --net. Une autre option est de retirer unix de l'ensemble

--protocol.

Le filtrage nécessite l'installation de l'utilitaire xdg-dbus-proxy. Des règles de filtrage peuvent être spécifiées pour les noms DBus bien connus, mais elles sont aussi propagées au nom unique propriétaire. Les permissions sont "collantes" et sont conservées même si le nom bien connu correspondant est libéré (cependant, les applications libèrent rarement les noms bien connus en pratique). Les noms peuvent avoir un suffixe .* pour correspondre à tous les noms situés en dessous d'eux, y compris eux-mêmes (par ex. "foo.bar.*" correspond à "foo.bar", "foo.bar.baz" et "foo.bar.baz.quux", mais pas "foobar"). Pour plus d'informations, voir xdg-dbus-proxy(1)

.
