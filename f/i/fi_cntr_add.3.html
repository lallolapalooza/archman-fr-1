fi_cntr - Opérations de compteur d'achèvement et d'événement

fi_cntr_open / fi_close
Allouer/libérer un compteur
fi_cntr_read
Lire la valeur actuelle d'un compteur

DESCRIPTION

Les compteurs enregistrent le nombre d'opérations demandées qui se sont achevées. Les compteurs peuvent fournir un mécanisme d'achèvement léger en permettant la suppression des entrées d'achèvement CQ. Ils sont utiles pour les applications qui ont seulement besoin de connaître le nombre de requêtes qui se sont achevées, et non les détails de chaque requête. Par exemple, les compteurs peuvent être utiles pour implémenter un contrôle de flux basé sur des crédits ou suivre le nombre de processus distants qui ont répondu à une requête.

Les compteurs comptent généralement uniquement les achèvements réussis. Cependant, si une opération se termine en erreur, elle peut incrémenter une valeur d'erreur associée. C'est-à-dire qu'un compteur stocke en fait deux valeurs distinctes, les achèvements d'erreur mettant à jour une valeur spécifique aux erreurs.

Les compteurs sont mis à jour suivant les sémantiques d'événements d'achèvement définies dans fi_cq(3). Le moment de la mise à jour est basé sur le type de transfert et les indicateurs d'opération spécifiés.

fi_cntr_open

fi_cntr_open alloue un nouveau compteur de fabric. Les propriétés et le comportement du compteur sont définis par la structure fi_cntr_attr.

struct fi_cntr_attr {
    enum fi_cntr_events  events;    /* type d'événements à compter */
    enum fi_wait_obj     wait_obj;  /* objet d'attente demandé */
    struct fid_wait     *wait_set;  /* ensemble d'attente optionnel, déprécié */
    uint64_t             flags;     /* indicateurs d'opération */
};
events
Un compteur capture différents types d'événements. Le type spécifique qui est compté est l'un des suivants :
- FI_CNTR_EVENTS_COMP
Le compteur s'incrémente pour chaque achèvement réussi qui se produit sur un point de terminaison lié associé. Le type d'achèvements – envois et/ou réceptions – qui sont comptés peut être restreint à l'aide d'indicateurs de contrôle lors de la liaison du compteur et du point de terminaison. Les compteurs s'incrémentent sur tous les achèvements réussis, indépendamment du fait que l'opération génère une entrée dans une file d'attente d'événements.
- FI_CNTR_EVENTS_BYTES
Le compteur est incrémenté par le nombre d'octets utilisateur, à l'exclusion de toute donnée CQ, transférés dans un message de transport lors de l'atteinte de la sémantique d'achèvement spécifiée. Pour les compteurs côté initiateur, le compte reflète la taille du transfert demandé et est mis à jour après que le message atteint le niveau d'achèvement souhaité (FI_INJECT_COMPLETE, FI_TRANSMIT_COMPLETE, etc.). Pour les opérations d'envoi et d'écriture, le compte reflète le nombre d'octets transférés au pair. Pour les opérations de lecture, le compte reflète le nombre d'octets renvoyés dans une réponse de lecture. Les opérations qui peuvent écrire et lire des données, comme les atomiques, se comportent comme des opérations de lecture à l'initiateur, mais comme des écritures à la cible. Pour les compteurs côté cible, le compte reflète la taille des données utilisateur reçues et est incrémenté selon les sémantiques d'achèvement côté cible. Dans la plupart des cas, cela indique FI_DELIVERY_COMPLETE, mais peut différer lors de l'accès à la mémoire du périphérique (HMEM). En cas d'erreur, la taille du transfert n'est pas appliquée au champ d'erreur ; ce champ est incrémenté de 1. Le type de transfert FI_COLLECTIVE n'est pas pris en charge.
wait_obj
Les compteurs peuvent être associés à un objet d'attente spécifique. Les objets d'attente permettent aux applications de bloquer jusqu'à ce que l'objet d'attente soit signalé, indiquant qu'un compteur a atteint un seuil spécifique. Les utilisateurs peuvent utiliser fi_control pour récupérer l'objet d'attente sous-jacent associé à un compteur, afin de l'utiliser dans d'autres appels système. Les valeurs suivantes peuvent être utilisées pour spécifier le type d'objet d'attente associé à un compteur : FI_WAIT_NONE, FI_WAIT_UNSPEC, FI_WAIT_SET, FI_WAIT_FD, FI_WAIT_MUTEX_COND (déprécié), et FI_WAIT_YIELD. La valeur par défaut est FI_WAIT_NONE.
- FI_WAIT_NONE
Utilisé pour indiquer que l'utilisateur ne bloquera pas (n'attendra pas) les événements sur le compteur.
- FI_WAIT_UNSPEC
Spécifie que l'utilisateur n'attend que sur le compteur en utilisant les appels d'interface fabric, tels que fi_cntr_wait. Dans ce cas, le fournisseur sous-jacent peut sélectionner l'objet d'attente le plus approprié ou le plus performant disponible, y compris des mécanismes d'attente personnalisés. Les applications qui sélectionnent FI_WAIT_UNSPEC ne sont pas garanties de pouvoir récupérer l'objet d'attente sous-jacent.
- FI_WAIT_SET (déprécié)
Indique que le compteur d'événements doit utiliser un objet d'ensemble d'attente pour attendre les événements. Si spécifié, le champ wait_set doit référencer un objet d'ensemble d'attente existant.
- FI_WAIT_FD
Indique que le compteur doit utiliser un descripteur de fichier comme mécanisme d'attente. Un objet d'attente de descripteur de fichier doit être utilisable dans les routines select, poll et epoll. Cependant, un fournisseur peut signaler un objet d'attente FD en le marquant comme lisible, écrivable ou avec une erreur.
- FI_WAIT_MUTEX_COND (déprécié)
Spécifie que le compteur doit utiliser un mutex pthread et une variable de condition comme objet d'attente.
- FI_WAIT_YIELD
Indique que le compteur attendra sans objet d'attente mais cédera plutôt à chaque attente. Permet l'utilisation de fi_cntr_wait via une boucle serrée.
wait_set (déprécié)
Si wait_obj est FI_WAIT_SET, ce champ référence un objet d'attente auquel le compteur d'événements doit s'attacher. Lorsqu'un événement est ajouté au compteur d'événements, l'ensemble d'attente correspondant sera signalé si toutes les conditions nécessaires sont remplies. L'utilisation d'un ensemble d'attente permet une méthode optimisée pour attendre les événements sur plusieurs compteurs d'événements. Ce champ est ignoré si wait_obj n'est pas FI_WAIT_SET.
flags
Les indicateurs sont réservés pour une utilisation future et doivent être mis à 0.

fi_close

L'appel fi_close libère toutes les ressources associées à un compteur. Lors de la fermeture du compteur, aucun point d

e terminaison ouvert, contexte d'émission, contexte de réception ou région mémoire ne doit être associé au compteur
. Si des ressources sont toujours associées au compteur lors de la tentative de fermeture, l'appel renverra -FI_EBUSY.

NOTE

S

Afin de prendre en charge diverses implémentations de compteurs, les mises à jour apportées aux valeurs des compteurs (par ex. fi_cntr_set ou fi_cntr_add) peuvent ne pas être immédiatement visibles pour les opérations de lecture du compteur (c.-à-d. fi_cntr_read ou fi_cntr_readerr). Un petit délai, mais indéfini, peut survenir entre la modification du compteur et la mise à jour de la valeur rapportée. Cependant, une valeur mise à jour finale sera éventuellement reflétée dans la valeur du compteur

lue.

De plus, les applications doivent s'assurer que la valeur d'un compteur est stable et non susceptible de changer avant d'appeler fi_cntr_set ou fi_cntr_seterr. Sinon, la valeu

r résultante du compteur après fi_cntr_set / fi_cntr_seterr est indéfinie, car les mises à jour du compteur peuvent être perdues. Une valeur de compteur est considérée comme st
able si toutes les mises à jour précédentes utilisant fi_cntr_set / fi_cntr_seterr et les résultats des opérations associées sont reflétés dans la valeur observée du compteur.
