Tk_FindPhoto(3) Procédures de la bibliothèque Tk Tk_FindPhoto(3)

NOM

Tk_FindPhoto, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoGetImage, Tk_PhotoBlank, Tk_PhotoExpand, Tk_PhotoGetSize, Tk_PhotoSetSize - manipuler les données d'image stockées dans une image photo.

SYNOPSISSE

#include <tk.h>

Tk_PhotoHandle
Tk_FindPhoto(interp, imageName)

int
Tk_PhotoPutBlock(interp, handle, blockPtr, x, y, width, height,compRule)

int
Tk_PhotoPutZoomedBlock(interp, handle, blockPtr, x, y, width, height,zoomX, zoomY, subsampleX, subsampleY, compRule)

int
Tk_PhotoGetImage(handle, blockPtr)

void
Tk_PhotoBlank(handle)

int
Tk_PhotoExpand(interp, handle, width, height)

void
Tk_PhotoGetSize(handle, widthPtr, heightPtr)

int
Tk_PhotoSetSize(interp. handle, width, height)

ARGUMENTS

Tcl_Interp *interp (in)
Interpréteur dans lequel l'image a été cré et dans lequel la remontée d'erreurs doit être effectuée.
const char *imageName (in)
Nom de l'image photo.
Tk_PhotoHandle handle (in)
Descripteur opaque identifiant l'image photo à affecter.
Tk_PhotoImageBlock *blockPtr (in)
Spécifie l'adresse et la disposition en mémoire des données d'image.
int x (in)
Spécifie la coordonnée X où le coin supérieur gauche du bloc doit être placé dans l'image.
int y (in)
Spécifie la coordonnée Y où le coin supérieur gauche du bloc doit être placé dans l'image.
int width (in)
Spécifie la largeur de la zone de l'image à affecter (pour Tk_PhotoPutBlock) ou la largeur d'image souhaitée (pour Tk_PhotoExpand et Tk_PhotoSetSize).
int compRule (in)
Spécifie la règle de composition utilisée lors de la combinaison de pixels transparents dans un bloc de données avec une image photo. Doit être l'une des valeurs suivantes : TK_PHOTO_COMPOSITE_OVERLAY (qui place le bloc de données par-dessus l'image photo existante, le contenu précédent étant visible à travers les bits transparents) ou TK_PHOTO_COMPOSITE_SET (qui ignore le contenu de l'image photo existante dans le rectangle couvert par le bloc de données.)
int height (in)
Spécifie la hauteur de la zone de l'image à affecter (pour Tk_PhotoPutBlock) ou la hauteur d'image souhaitée (pour Tk_PhotoExpand et Tk_PhotoSetSize).
int *widthPtr (out)
Pointeur vers l'emplacement où stocker la largeur de l'image.
int *heightPtr (out)
Pointeur vers l'emplacement où stocker la hauteur de l'image.
int subsampleX (in)
Spécifie le facteur de sous-échantillonnage dans la direction X pour les données d'image en entrée.
int subsampleY (in)
Spécifie le facteur de sous-échantillonnage dans la direction Y pour les données d'image en entrée.
int zoomX (in)
Spécifie le facteur de zoom à appliquer dans la direction X aux pixels étant écrits dans l'image photo.
int zoomY (in)
Spécifie le facteur de zoom à appliquer dans la direction Y aux pixels étant écrits dans l'image photo.

DESCRIPTION

Tk_FindPhoto renvoie un descripteur opaque utilisé pour identifier une image photo particulière auprès des autres procédures. Le paramètre est le nom de l'image, c'est-à-dire le nom spécifié à la commande image create photo , ou assigné par cette commande si aucun nom n'a été spécifié. Si imageName n'existe pas ou n'est pas une image photo, Tk_FindPhoto renvoie NULL.

Tk_PhotoPutBlock est utilisé pour fournir des blocs de données d'image à afficher. L'appel affecte une zone de l'image de taille width x height pixels, avec son coin supérieur gauche aux coordonnées (x,y). Tous les valeurs de width, height, x, et y doivent être non négatives. Si une partie de cette zone se trouve en dehors des limites actuelles de l'image, l'image sera agrandie pour inclure la zone, sauf si l'utilisateur a spécifié une taille d'image explicite avec les options de configuration de widget -width et/ou -height (voir photo(n)) ; dans ce cas, la zone est discrètement rognée aux limites de l'image.

Le paramètre block est un pointeur vers une structure Tk_PhotoImageBlock , définie comme suit :

typedef struct {
    unsigned char *pixelPtr;
    int width;
    int height;
    int pitch;
    int pixelSize;
    int offset[4];
} Tk_PhotoImageBlock;
Le champ pixelPtr pointe vers le premier pixel, c'est-à-dire le pixel supérieur gauche dans le bloc. Les champs width et height spécifient les dimensions du bloc de pixels. Le champ pixelSize spécifie la différence d'adresse entre deux pixels horizontalement adjacents. Il devrait être 4 pour les données d'image RGB et 2 pour les données d'image en niveaux de gris. D'autres valeurs sont possibles, si les décalages dans le tableau offset sont ajustés en conséquence (par exemple pour les données rouge, vert et bleu stockées dans des plans différents). L'utilisation d'une telle disposition est toutefois fortement déconseillée. En raison d'un bogue, elle pourrait ne pas fonctionner correctement si un canal alpha est fourni. (voir la section BUGS ci-dessous). Le champ pitch spécifie la différence d'adresse entre deux pixels verticalement adjacents. Le tableau offset contient les décalages depuis l'adresse d'un pixel vers les adresses des octets contenant les composantes rouge, verte, bleue et alpha (transparence). Si les décalages pour le rouge, le vert et le bleu sont égaux, l'image est interprétée en niveaux de gris. S'ils diffèrent, des données RGB sont supposées. Normalement, les décalages seront 0, 1, 2, 3 pour les données RGB et 0, 0, 0, 1 pour les niveaux de gris. Il est possible de fournir des données d'image sans canal alpha en définissant le décalage pour l'alpha à une valeur négative et en ajustant le champ pixelSize en conséquence. Cette utilisation est toutefois déconseillée (voir la section BUGS ci-dessous).

Le paramètre compRule de Tk_PhotoPutBlock spécifie une règle de composition indiquant quoi faire des pixels transparents. La valeur TK_PHOTO_COMPOSITE_OVERLAY indique que le contenu précédent de l' image photo doit être visible à travers, et la valeur TK_PHOTO_COMPOSITE_SET indique que le contenu précédent de l'image photo doit être complètement ignoré, et que les valeurs du bloc doivent être copiées directement. Le comportement dans Tk8.3 et les versions antérieures était équivalent à l'utilisation de TK_PHOTO_COMPOSITE_OVERLAY comme règle de composition.

Les valeurs données pour les paramètres width et height de Tk_PhotoPutBlock n'ont pas à correspondre aux valeurs spécifiées dans block. Si elles sont plus petites, Tk_PhotoPutBlock extrait un sous-bloc des données d'image fournies. Si elles sont plus grandes, les données fournies sont répliquées (de manière carrelée) pour remplir la zone spécifiée. Ces règles fonctionnent indépendamment dans les directions horizontale et verticale.

Tk_PhotoPutBlock renvoie normalement TCL_OK, bien que si elle ne peut pas allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR soit renvoyé à la place et, si l'argument interp est non-NULL, un message d'erreur soit placé dans le résultat de l'interpréteur.

Tk_PhotoPutZoomedBlock fonctionne comme Tk_PhotoPutBlock sauf que l'image peut être réduite ou agrandie pour l'affichage. Les paramètres subsampleX et subsampleY permettent de réduire la taille de l'image par sous-échantillonnage. Tk_PhotoPutZoomedBlock n'utilisera que les pixels de l'image en entrée dont les coordonnées X sont des multiples de subsampleX, et dont les coordonnées Y sont des multiples de subsampleY. Par exemple, une image de 512x512 pixels peut être réduite à 256x256 en définissant subsampleX et subsampleY à 2.

Les paramètres zoomX et zoomY permettent d'agrandir l'image par réplication de pixels. Chaque pixel de l'image en entrée (éventuellement sous-échantillonnée) sera écrit dans un bloc de zoomX pixels de large et zoomY pixels de haut de l'image affichée. Le sous-échantillonnage et le zoom peuvent être utilisés ensemble pour des effets spéciaux.

Tk_PhotoGetImage peut être utilisé pour récupérer des données d'image à partir d'une image photo. Tk_PhotoGetImage remplit la structure pointée par le paramètre blockPtr avec des valeurs décrivant l'adresse et la disposition des données d'image que l'image photo a stockées en interne. Les valeurs sont valides jusqu'à ce que l'image soit détruite ou que sa taille soit modifiée.

Il est possible de modifier une image en écrivant directement dans les données vers lesquelles le champ pixelPtr pointe. La taille de l'image ne peut cependant pas être modifiée de cette manière. De plus, les modifications effectuées en écrivant directement dans pixelPtr ne seront pas immédiatement visibles, mais seulement après un appel à Tk_ImageChanged ou après un événement qui cause le redessin des widgets intéressés. Pour ces raisons, il est généralement préférable d'effectuer les modifications à une copie des données de l'image et de la réécrire avec Tk_PhotoPutBlock ou Tk_PhotoPutZoomedBlock.

Tk_PhotoGetImage renvoie 1 pour des raisons de compatibilité avec la procédure correspondante dans l'ancien widget photo.

Tk_PhotoBlank met en blanc toute la zone de l'image photo. Les zones blanches d'une image photo sont transparentes.

Tk_PhotoExpand demande que l'image du widget soit agrandie pour faire au moins largeur x hauteur pixels de taille. La largeur et/ou la hauteur ne sont pas modifiées si l'utilisateur a spécifié une largeur ou une hauteur d'image explicite avec les -width et/ou -height options de configuration, respectivement. Si les données de l'image sont fournies en nombreux petits blocs, il est plus efficace d'utiliser Tk_PhotoExpand ou Tk_PhotoSetSize au début plutôt que de laisser l'image s'agrandir de nombreux petits incréments à mesure que les blocs d'image sont fournis.

Tk_PhotoExpand renvoie normalement TCL_OK, bien que si elle ne peut pas allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est renvoyé à la place et, si l'argument interp est non-NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoSetSize spécifie la taille de l'image, comme si l'utilisateur avait spécifié les valeurs largeur et hauteur données aux -width et -height options de configuration. Une valeur de zéro pour largeur ou hauteur ne change pas la largeur ou la hauteur de l'image, mais permet à la largeur ou à la hauteur d'être modifiée par des appels ultérieurs à Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock ou Tk_PhotoExpand.

Tk_PhotoSetSize renvoie normalement TCL_OK, bien que si elle ne peut pas allouer suffisamment de mémoire pour contenir l'image résultante, TCL_ERROR est renvoyé à la place et, si l'argument interp est non-NULL, un message d'erreur est placé dans le résultat de l'interpréteur.

Tk_PhotoGetSize renvoie les dimensions de l'image dans *widthPtr et *heightPtr.

PORTABILITÉ

Dans Tk 8.3 et les versions antérieures, Tk_PhotoPutBlock et Tk_PhotoPutZoomedBlock avaient des signatures différentes. Si vous voulez compiler du code qui utilise l'ancienne interface contre 8.4 sans mettre à jour votre code, compilez-le avec l'indicateur -DUSE_COMPOSITELESS_PHOTO_PUT_BLOCK. Le code lié en utilisant Stubs contre des versions plus anciennes de Tk continuera de fonctionner.

Dans Tk 8.4, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoExpand et Tk_PhotoSetSize ne prenaient pas d'argument interp et ne renvoyaient aucun code de résultat. Si la mémoire était insuffisante pour une image, Tk paniquait. Ce comportement est toujours pris en charge si vous compilez votre extension avec l'indicateur supplémentaire -DUSE_PANIC_ON_PHOTO_ALLOC_FAILURE. Le code lié en utilisant Stubs contre des versions plus anciennes de Tk continuera de fonctionner.

BUGS

La structure Tk_PhotoImageBlock utilisée pour fournir des données d'image à Tk_PhotoPutBlock promet une grande flexibilité dans la disposition des données (par exemple des plans séparés pour les canaux rouge, vert, bleu et alpha). Malheureusement, l'implémentation ne tient pas cette promesse. Le problème est que le champ pixelSize est (incorrectement) utilisé pour déterminer si l'image a un canal alpha. Actuellement, si le décalage pour le canal alpha est supérieur ou égal à pixelSize, tk_PhotoPutblock suppose qu'aucune donnée alpha n'est présente et rend l'image entièrement opaque. Cela signifie que pour les dispositions où les canaux sont séparés (ou toute autre disposition exotique où pixelSize doit être plus petit que le décalage alpha), le canal alpha ne sera pas lu correctement. Afin d'être prudent si ce problème est corrigé dans une version future, il est fortement recommandé de toujours fournir des données alpha - même si l'image n'a pas de transparence - et d'utiliser uniquement la disposition "standard" avec un pixelSize de 2 pour les données en niveaux de gris et 4 pour les données RGB avec des décalagess de 0, 0, 0, 1 ou 0, 1, 2, 3 respectivement.
