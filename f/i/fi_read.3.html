NOM

fi_rma - Opérations d'accès à la mémoire distante

fi_read / fi_readv / fi_readmsg
Initie une lecture depuis la mémoire distante

fi_write / fi_writev / fi_writemsg fi_inject_write / fi_writedata : Initie une écriture vers la mémoire distante

SYNTAXE

#include <rdma/fi_rma.h>
ssize_t fi_read(struct fid_ep *ep, void *buf, size_t len, void *desc,
    fi_addr_t src_addr, uint64_t addr, uint64_t key, void *context);
ssize_t fi_readv(struct fid_ep *ep, const struct iovec *iov, void **desc,
    size_t count, fi_addr_t src_addr, uint64_t addr, uint64_t key,
    void *context);
ssize_t fi_readmsg(struct fid_ep *ep, const struct fi_msg_rma *msg,
    uint64_t flags);
ssize_t fi_write(struct fid_ep *ep, const void *buf, size_t len,
    void *desc, fi_addr_t dest_addr, uint64_t addr, uint64_t key,
    void *context);
ssize_t fi_writev(struct fid_ep *ep, const struct iovec *iov, void **desc,
    size_t count, fi_addr_t dest_addr, uint64_t addr, uint64_t key,
    void *context);
ssize_t fi_writemsg(struct fid_ep *ep, const struct fi_msg_rma *msg,
    uint64_t flags);
ssize_t fi_inject_write(struct fid_ep *ep, const void *buf, size_t len,
    fi_addr_t dest_addr, uint64_t addr, uint64_t key);
ssize_t fi_writedata(struct fid_ep *ep, const void *buf, size_t len,
    void *desc, uint64_t data, fi_addr_t dest_addr, uint64_t addr,
    uint64_t key, void *context);
ssize_t fi_inject_writedata(struct fid_ep *ep, const void *buf, size_t len,
    uint64_t data, fi_addr_t dest_addr, uint64_t addr, uint64_t key);

ARGUMENTS

ep
Point de terminaison fabric sur lequel initier l'opération de lecture ou d'écriture.
buf
Tampon de données local pour lire dedans (cible de lecture) ou écrire depuis (source d'écriture).
len
Longueur des données à lire ou écrire, spécifiée en octets. Les transferts valides vont de 0 octet jusqu'à la taille de message maximale du point de terminaison.
iov
Tampon de données vectorielles.
count
Nombre d'entrées de données vectorielles.
addr
Adresse de la mémoire distante à accéder. Ce sera l'adresse virtuelle de la région distante dans le cas de FI_MR_BASIC, ou le décalage par rapport à l'adresse de départ dans le cas de FI_MR_SCALABLE.
key
Clé de protection associée à la mémoire distante.
desc
Descripteur associé au tampon de données local. Voir fi_mr(3).
data
Données de CQ distantes à transférer avec l'opération.
dest_addr
Adresse de destination pour les transferts d'écriture sans connexion. Ignoré pour les points de terminaison connectés.
src_addr
Adresse source à lire pour les transferts sans connexion. Ignoré pour les points de terminaison connectés.
msg
Descripteur de message pour les opérations de lecture et d'écriture.
flags
Indicateurs supplémentaires à appliquer pour l'opération de lecture ou d'écriture.
context
Pointeur spécifié par l'utilisateur pour l'associer à l'opération. Ce paramètre est ignoré si l'opération ne génère pas d'achèvement réussi, sauf si un indicateur d'opération spécifie que le paramètre context doit être utilisé pour une entrée obligatoire.

DESCRIPTION

Les opérations d'accès à la mémoire distante (RMA - Remote Memory Access) sont utilisées pour transférer directement des données entre un tampon de données local et un tampon de données distant. Les transferts RMA s'effectuent par granularité d'octet, et aucune limite de message n'est maintenue.

Les fonctions d'écriture – fi_write, fi_writev, fi_writemsg, fi_inject_write, et fi_writedata – sont utilisées pour transmettre des données dans un tampon de mémoire distant. La principale différence entre les fonctions d'écriture réside dans le nombre et le type de paramètres qu'elles acceptent en entrée. Sinon, elles effectuent la même fonction générale.

Les fonctions de lecture – fi_read, fi_readv, et fi_readmsg – sont utilisées pour transférer des données d'une région de mémoire distante vers un ou plusieurs tampons de données locaux. Similairement aux opérations d'écriture, les opérations de lecture sont asynchrones. Les utilisateurs ne doivent pas toucher les tampons de données publiés avant que l'opération de lecture ne soit terminée.

Les opérations RMA terminées sont signalées à l'utilisateur via une ou plusieurs files d'attente d'achèvement associées au point de terminaison. Les utilisateurs fournissent un contexte qui est associé à chaque opération et est renvoyé à l'utilisateur dans le cadre de l'achèvement. Voir fi_cq pour les détails des événements d'achèvement.

Par défaut, le point de terminaison distant ne génère pas d'événement et ne notifie pas l'utilisateur lorsqu'une région mémoire a été accédée par une opération de lecture ou d'écriture RMA. Cependant, des données immédiates peuvent être associées à une opération d'écriture RMA. Les écritures RMA avec données immédiates généreront une entrée d'achèvement au point de terminaison distant, afin que les données immédiates puissent être livrées.

fi_write

L'appel fi_write transfère les données contenues dans le tampon de données spécifié par l'utilisateur vers une région mémoire distante.

fi_writev

L'appel fi_writev ajoute la prise en charge d'une liste de scatter-gather à fi_write. fi_writev transfère l'ensemble des tampons de données référencés par le paramètre iov vers la région mémoire distante.

fi_writemsg

L'appel fi_writemsg prend en charge les transferts de données sur les points de terminaison connectés et non connectés, avec la possibilité de contrôler l'opération d'écriture par appel grâce à l'utilisation d'indicateurs. La fonction fi_writemsg prend une structure fi_msg_rma en entrée.

struct fi_msg_rma {
    const struct iovec *msg_iov;     /* tableau scatter-gather local */
    void               **desc;       /* descripteur d'opération */
    size_t             iov_count;    /* nb d'éléments dans msg_iov */
    fi_addr_t          addr;        /* adresse de point de terminaison optionnelle */
    const struct fi_rma_iov *rma_iov;/* SGL distant */
    size_t             rma_iov_count;/* nb d'éléments dans rma_iov */
    void               *context;     /* contexte défini par l'utilisateur */
    uint64_t           data;         /* données immédiates optionnelles */
};
struct fi_rma_iov {
    uint64_t           addr;         /* adresse RMA cible */
    size_t             len;          /* taille du tampon cible */
    uint64_t           key;          /* clé d'accès */
};

fi_inject_write

L'appel d'injection d'écriture est une version optimisée de fi_write. Il fournit des sémantiques d'achèvement similaires à fi_inject fi_msg(3).

fi_writedata

L'appel d'écriture de données est similaire à fi_write, mais permet l'envoi de données de CQ distantes (voir l'indicateur FI_REMOTE_CQ_DATA) dans le cadre du transfert.

fi_inject_writedata

L'appel d'injection d'écriture de données est similaire à fi_inject_write, mais permet l'envoi de données de CQ distantes (voir l'indicateur FI_REMOTE_CQ_DATA) dans le cadre du transfert.

fi_read

L'appel fi_read demande au point de terminaison distant de transférer les données de la région mémoire distante vers le tampon de données local.

fi_readv

L'appel fi_readv ajoute la prise en charge d'une liste de scatter-gather à fi_read. fi_readv transfère les données de la région mémoire distante vers l'ensemble des tampons de données référencés par le paramètre iov.

fi_readmsg

L'appel fi_readmsg prend en charge les transferts de données sur les points de terminaison connectés et non connectés, avec la possibilité de contrôler l'opération de lecture par appel grâce à l'utilisation d'indicateurs. La fonction fi_readmsg prend une structure fi_msg_rma en entrée.

INDICATEURS

Les opérations RMA peuvent être modifiées par les indicateurs suivants, qui sont spécifiés dans le champ flags des appels fi_readmsg et fi_writemsg, ou par l'intermédiaire des champs correspondants pour les autres appels.

FI_COMMITVERIFIED
Si ce drapeau est défini, le transfert ne sera pas considéré comme terminé tant que le point de terminaison distant n'a pas confirmé que les données ont été écrites dans la mémoire distante et que le transfert a été validé. Ce drapeau est applicable uniquement aux opérations d'écriture.
FI_DELIVERY_COMPLETE
Indique que les données doivent être livrées à l'application avant que l'opération ne soit considérée comme terminée. Ceci est différent de FI_COMMITVERIFIED car il s'agit d'une exigence de livraison de données au niveau de l'application plutôt que d'une validation matérielle.
FI_REMOTE_CQ_DATA
Transfère des données supplémentaires, spécifiées dans le champ data de la structure fi_msg_rma, avec l'opération RMA. Ces données seront transmises à la file d'attente des completions (CQ) distante.
FI_INJECT
Indique que l'opération doit être traitée de manière optimisée en tant que transfert injecté. Ce drapeau est généralement utilisé pour les transferts de petite taille qui ne nécessitent pas de descripteur de transfert explicite. L'implémentation de libfabric peut choisir de ne pas prendre en charge ce drapeau pour certaines opérations ou configurations.
FI_COMPLETION
Indique que cette opération doit générer une entrée de complétion. Par défaut, les opérations RMA (read/write) ne génèrent pas de complétion au point de terminaison distant pour des raisons de performance, sauf si l'opération inclut des données immédiates ou si ce drapeau est explicitement défini.
FI_DIRECT
Utilise le transfert direct. Ceci est applicable aux opérations qui peuvent ne pas être liées à des tampons locaux enregistrés. L'utilisation de ce drapeau peut avoir des implications sur les performances et la gestion de la mémoire.

VALEUR DE RETOUR

Les fonctions RMA retournent le nombre d'octets transférés en cas de succès. En cas d'erreur, une valeur négative est retournée, indiquant le code d'erreur spécifique.

  • -FI_EAGAIN : L'opération ne peut pas être terminée immédiatement en raison de ressources limitées. L'application doit réessayer plus tard.
  • -FI_EINVAL : Paramètre invalide fourni à la fonction.
  • -FI_ENOMEM : Impossible d'allouer la mémoire nécessaire pour traiter l'opération.
  • -FI_ETOOMANY : Trop d'opérations en cours.

Les opérations RMA sont généralement asynchrones. Le retour de la fonction n'indique que le succès de la publication de l'opération, et non son achèvement. L'achèvement réel est signalé via la file d'attente des completions (CQ).

fi_read.3 - Libfabric Programmer’s Manual

NAME

fi_read, fi_readmsg, fi_readv - read data from an endpoint

SYNOPSIS

#include <rdma/fi_endpoint.h>

ssize_t fi_read(struct fi_endpoint *endpoint, void *buf, size_t len,
    const void *addr, uint64_t flags);

ssize_t fi_readmsg(struct fi_endpoint *endpoint,
    const struct fi_msg *msg, uint64_t flags);

ssize_t fi_readv(struct fi_endpoint *endpoint,
    const struct fi_iov *iov, size_t iovcnt, const void *addr,
    uint64_t flags);

ARGUMENTS

endpoint
The communication endpoint to read from.
buf
The buffer to read data into.
len
The maximum number of bytes to read into the buffer.
addr
The address of the remote data to read. This parameter is optional and depends on the fi_read operation mode. If the endpoint is configured for a connectionless communication mode (e.g., fi_connect or fi_join is used), then the addr parameter may be NULL. If the endpoint is configured for connectionless mode, the remote address is specified during connection establishment. For connectionless communication, addr specifies the source address to read from, and may be NULL if the source address is not needed or implicit.
flags
Flags that modify the behavior of the read operation. See the FLAGS section below for details.
msg
A struct fi_msg structure that contains information about the read operation. See fi_msg(3) for details.
iov
An array of struct fi_iov structures specifying the scatter/gather buffers to read data into. See fi_readv(3) for details.
iovcnt
The number of elements in the iov array.

DESCRIPTION

The fi_read, fi_readmsg, and fi_readv calls are used to initiate a read operation from a remote host. The data is read from the specified remote address addr into the provided buffer(s).

The fi_read call is a simple interface for reading data into a single buffer.

The fi_readmsg call is a more general interface that allows specifying a message structure, which can include control data, tags, and other information relevant to the read operation.

The fi_readv call supports scatter/gather reads, allowing data to be read into multiple, non-contiguous buffers.

Flags specified with these calls can modify the default data transfer operation. Flags specified with fi_readmsg override most flags previously configured with the endpoint, except where noted (see fi_endpoint.3). The following list of flags are usable with fi_readmsg and/or fi_writemsg.

FLAGS

FI_REMOTE_CQ_DATA
Applies to fi_writemsg. Indicates that remote CQ data is available and should be sent as part of the request. See fi_getinfo for additional details on FI_REMOTE_CQ_DATA. This flag is implicitly set for fi_writedata and fi_inject_writedata.
FI_COMPLETION
Indicates that a completion entry should be generated for the specified operation. The endpoint must be bound to a completion queue with FI_SELECTIVE_COMPLETION that corresponds to the specified operation, or this flag is ignored.
FI_MORE
Indicates that the user has additional requests that will immediately be posted after the current call returns. Use of this flag may improve performance by enabling the provider to optimize its access to the fabric hardware.
FI_INJECT
Applies to fi_writemsg. Indicates that the outbound data buffer should be returned to user immediately after the write call returns, even if the operation is handled asynchronously. This may require that the underlying provider implementation copy the data into a local buffer and transfer out of that buffer. This flag can only be used with messages smaller than inject_size.
FI_INJECT_COMPLETE
Applies to fi_writemsg. Indicates that a completion should be generated when the source buffer(s) may be reused.
FI_TRANSMIT_COMPLETE
Applies to fi_writemsg. Indicates that a completion should not be generated until the operation has been successfully transmitted and is no longer being tracked by the provider.
FI_DELIVERY_COMPLETE
Applies to fi_writemsg. Indicates that a completion should be generated when the operation has been processed by the destination.
FI_COMMIT_COMPLETE
Applies to fi_writemsg when targeting persistent memory regions. Indicates that a completion should be generated only after the result of the operation has been made durable.
FI_FENCE
Applies to transmits. Indicates that the requested operation, also known as the fenced operation, and any operation posted after the fenced operation will be deferred until all previous operations targeting the same peer endpoint have completed. Operations posted after the fencing will see and/or replace the results of any operations initiated prior to the fenced operation.

The ordering of operations starting at the posting of the fenced operation (inclusive) to the posting of a subsequent fenced operation (exclusive) is controlled by the endpoint’s ordering semantics.

RETURN VALUE

Returns 0 on success. On error, a negative value corresponding to fabric errno is returned. Fabric errno values are defined in rdma/fi_errno.h.

ERRORS

-FI_EAGAIN
See fi_msg(3) for a detailed description of handling FI_EAGAIN.
