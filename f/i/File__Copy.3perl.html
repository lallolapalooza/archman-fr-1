DESCRIPTIO

N

Le module File::Copy fournit deux fonctions de base, "copy" et "move", qui sont utiles pour déplacer le contenu d'un fichier d'un endroit à un

autre.
co
py
La fonction "copy" prend deux paramètres : un fichier source et un fichier destination. Chacun des arguments peut être une chaîne, une référence FileHandle ou un glob FileHandle. Évidemment, si le premier argument est un filehandle d'un certain type, il sera lu, et s'il s'agit d'un nom de fichier, il sera ouvert en lecture. De même, le deuxième argument sera écrit. Si le deuxième argument n'existe pas mais que le répertoire parent existe, alors il sera créé. Tenter de copier un fichier dans un répertoire inexistant est une erreur. Tenter de copier un fichier par-dessus lui-même est également une erreur. "copy" n'écrasera pas les fichiers en lecture seule.

Si la destination (le deuxième argument) existe déjà et est un répertoire, et que la source (le premier argument) n'est pas un filehandle, alors le fichier source sera copié dans le répertoire spécifié par la destination, en utilisant le même nom de base que le fichier source. C'est un échec d'avoir un filehandle comme source lorsque la destination est un

répertoire.

Notez que passer des fichiers comme handles au lieu de noms peut entraîner une perte d'informations sur certains systèmes d'exploitation ; il est recommandé d'utiliser des noms de fichiers chaque fois que c'est possible. Les fichiers sont ouverts en mode binaire lorsque c'est applicable. Pour obtenir un comportement cohérent lors de la copie d'un filehandle vers un fichier, utilisez "binmode" sur le

filehandle.

Un troisième paramètre facultatif peut être utilisé pour spécifier la taille du tampon utilisée pour la copie. Il s'agit du nombre d'octets du premier fichier qui seront conservés en mémoire à un moment donné, avant d'être écrits dans le deuxième fichier. La taille du tampon par défaut dépend du fichier, mais sera généralement le fichier entier (jusqu'à 2 Mo), ou 1 kio pour les filehandles qui ne font pas référence à des fichiers (p. ex. les

sockets).

Vous pouvez utiliser la syntaxe "use File::Copy "cp"" pour accéder à l'alias "cp" de cette fonction. La syntaxe est exactement la même. Le comportement est presque le même également : à partir de la version 2.15, "cp" préservera les bits de permission du fichier source comme l'utilitaire shell cp(1) le ferait avec les options par défaut, tandis que "copy" utilise les permissions par défaut pour le fichier cible (qui peuvent dépendre du "umask" du processus, de la propriété du fichier, des ACL héritées, etc.). C'est-à-dire, si le fichier de destination existe déjà, "cp" laissera ses permissions inchangées ; sinon, les permissions sont prises du fichier source et modifiées par le "umask". Si une erreur survient lors du réglage des permissions, "cp" renverra 0, que le fich

ier ait été copié a
vec succès ou non.

La fonction "move" prend également deux paramètres : le nom actuel et le nom prévu du fichier à déplacer. Si la destination existe déjà et est un répertoire, et que la source n'est pas un répertoire, alors le fichier source sera renommé dans le répertoire spécifié par la destination.

Si possible, move() renommera simplement le fichier. Sinon, il copie le fichier vers le nouvel emplacement et supprime l'original. Si une erreur survient lors de ce processus de copie-et-suppression, vous pouvez vous retrouver avec une copie (possiblement partielle) du fichier sous le nom de

destination.

Vous pouvez utiliser l'alias "mv" pour cette fonction de la même manière que vous pouvez utiliser l'alias "cp" pour "cop

y
".

File::Copy fournit également la routine "syscopy", qui copie le fichier spécifié dans le premier paramètre vers le fichier spécifié dans le deuxième paramètre, en préservant les attributs spécifiques à l'OS et la structure du fichier. Pour les systèmes Unix, cela équivaut à la simple routine "copy", qui ne préserve pas les attributs spécifiques à l'OS. Pour les systèmes VMS, cela appelle la routine "rmscopy" (voir ci-dessous). Pour les systèmes OS/2, cela appelle directement le XSUB "syscopy". Pour les systèmes Win32, cela appelle "Win32::CopyFile".

Comportement spécial si "syscopy" est défini (OS/2, VMS et Win32)

:

Si les deux arguments de "copy" ne sont pas des file handles, alors "copy" effectuera une « copie système » du fichier d'entrée vers un nouveau fichier de sortie, afin de préserver les attributs du fichier, la structure de fichier indexée, etc. Le paramètre de taille du tampon est ignoré. Si l'un des arguments de "copy" est un handle vers un fichier ouvert, les données sont copiées à l'aide des opérateurs Perl, et aucun effort n'est fait pour préserver les attributs du fichier ou la structure des

enregistrements.

La routine de copie système peut également être appelée directement sous VMS et OS/2 sous le nom de "File::Copy::syscopy" (ou sous VMS sous le nom de "File::Copy::rmscopy", qui est la routine qui fait le travail réel pour

syscopy)
.
rmscopy($from,$to[,$date_flag]
)
Le premier et le deuxième argument peuvent être des chaînes, des typeglobs, des références de typeglob, ou des objets héritant de IO::Handle ; ils sont utilisés dans tous les cas pour obtenir le filespec des fichiers d'entrée et de sortie, respectivement. Le nom et le type du fichier d'entrée sont utilisés comme valeurs par défaut pour le fichier de sortie, si nécessaire.

Une nouvelle version du fichier de sortie est toujours créée, qui hérite de la structure et des attributs RMS du fichier d'entrée, sauf pour le propriétaire et les protections (et possiblement les horodatages ; voir ci-dessous). Toutes les données du fichier d'entrée sont copiées vers le fichier de sortie ; si l'un des deux premiers paramètres de "rmscopy" est un file handle, sa position est inchangée. (Notez que cela signifie qu'un file handle pointant vers le fichier de sortie sera associé à une ancienne version de ce fichier après le retour de "rmscopy", et non à la version nouvellement

créée.)

Le troisième paramètre est un drapeau entier, qui indique à "rmscopy" comment gérer les horodatages. S'il est < 0, aucun des horodatages du fichier d'entrée n'est propagé vers le fichier de sortie. S'il est > 0, alors il est interprété comme un masque de bits : si le bit 0 (le LSB) est défini, alors les horodatages autres que la date de révision sont propagés ; si le bit 1 est défini, la date de révision est propagée. Si le troisième paramètre de "rmscopy" est 0, alors il se comporte beaucoup comme la commande DCL COPY : si le nom ou le type du fichier de sortie a été spécifié explicitement, alors aucun horodatage n'est propagé, mais s'ils ont été pris implicitement du filespec d'entrée, alors tous les horodatages autres que la date de révision sont propagés. Si ce paramètre n'est pas fourni, il vaut 0 par

défaut.

"rmscopy" est spécifique à VMS et ne peut pas être exporté ; il doit être référencé par son nom complet,

p. ex. : 
File::Copy::rmscopy($from, $to) or die
$!;
