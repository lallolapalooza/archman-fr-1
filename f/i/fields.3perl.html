fields(3perl) Guide du programmeur Perl fields(3perl)

NOM

fields - champs de classe au moment de la compilation

SYNOPIS

{
    package Foo;
    use fields qw(foo bar _Foo_private);
    sub new {
        my Foo $self = shift;
        unless (ref $self) {
            $self = fields::new($self);
            $self->{_Foo_private} = "c'est le secret de Foo";
        }
        $self->{foo} = 10;
        $self->{bar} = 20;
        return $self;
    }
}
my $var = Foo->new;
$var->{foo} = 42;
# cela générera une erreur à l'exécution
$var->{zap} = 42;
# cela générera une erreur à la compilation
my Foo $foo = Foo->new;
$foo->{zap} = 24;
# héritage
{
    package Bar;
    use base 'Foo';
    use fields qw(baz _Bar_private);        # non partagé avec Foo
    sub new {
        my $class = shift;
        my $self = fields::new($class);
        $self->SUPER::new();                # initialisation des champs de base
        $self->{baz} = 10;                  # initialisation des propres champs
        $self->{_Bar_private} = "c'est le secret de Bar";
        return $self;
    }
}

DESCRIPTION

Le pragma "fields" active les champs de classe vérifiés au moment de la compilation et de l'exécution.

NOTE : L'implémentation actuelle conserve les champs déclarés dans la table de hachage %FIELDS du paquet appelant, mais cela pourrait changer dans les versions futures. Ne mettez **pas** à jour directement la table de hachage %FIELDS, car elle doit être créée au moment de la compilation pour être pleinement utile, comme le fait ce pragma.

Si une variable lexicale typée (my Class $var) contenant une référence est utilisée pour accéder à un élément de hachage et qu'un paquet portant le même nom que le type a déclaré des champs de classe en utilisant ce pragma, alors la clé de hachage est vérifiée au moment de la compilation. Si les variables ne sont pas typées, l'accès n'est vérifié qu'à l'exécution.

Le pragma associé "base" combinera les champs des classes de base et tous les champs déclarés en utilisant le pragma "fields". Cela permet aux champs hérités de fonctionner correctement. Les champs hérités peuvent être écrasés, mais cela générera un avertissement si les avertissements sont activés.

Uniquement valide pour Perl 5.8.x et antérieur : Les noms de champs commençant par un caractère underscore sont rendus privés à la classe et ne sont pas visibles par les sous-classes.

De plus, **en Perl 5.8.x et antérieur**, ce pragma utilise des pseudo-hachages, l'effet étant que vous pouvez avoir des objets avec des champs nommés qui sont aussi compacts et rapides d'accès que des tableaux, tant que les objets sont accédés via des variables correctement typées.

Les fonctions suivantes sont prises en charge :

new
fields::new() crée et "bless" une table de hachage des champs déclarés en utilisant le pragma "fields" dans la classe spécifiée. C'est la manière recommandée de construire un objet basé sur des champs.

Cela permet d'écrire un constructeur comme suit :

package Critter::Sounds;
use fields qw(cat dog bird);
sub new {
    my $self = shift;
    $self = fields::new($self) unless ref $self;
    $self->{cat} = 'meow';                      # élément scalaire
    @$self{'dog','bird'} = ('bark','tweet');    # tranche
    return $self;
}
phash
Cette fonction fonctionne uniquement dans Perl 5.8.x et antérieur. Les pseudo-hachages ont été supprimés de Perl à partir de la version 5.10. Envisagez d'utiliser des hachages restreints ou fields::new() à la place (qui lui-même utilise des hachages restreints sous 5.10+). Voir Hash::Util. L'utilisation de fields::phash() sous 5.10 ou une version supérieure provoquera une erreur.

fields::phash() peut être utilisé pour créer et initialiser un pseudo-hachage simple (non "blessé"). Cette fonction doit toujours être utilisée au lieu de créer des pseudo-hachages directement.

Si le premier argument est une référence vers un tableau, le pseudo-hachage sera créé avec les clés de ce tableau. Si un second argument est fourni, il doit également être une référence vers un tableau dont les éléments seront utilisés comme valeurs. Si le second tableau contient moins d'éléments que le premier, les éléments restants du pseudo-hachage ne seront pas initialisés. Cela le rend particulièrement utile pour créer un pseudo-hachage à partir des arguments d'une sous-routine :

sub dogtag {
   my $tag = fields::phash([qw(name rank ser_num)], [@_]);
}

fields::phash() accepte également une liste de paires clé-valeur qui seront utilisées pour construire le pseudo-hachage. Exemples :

my $tag = fields::phash(name => "Joe",
                        rank => "capitaine",
                        ser_num => 42);
my $pseudohash = fields::phash(%args);
