File::Fetch(3perl) Guide du programmeur Perl File::Fetch(3perl)

NOM

File::Fetch - Un mécanisme générique de récupération de fichiers

SYNOPSIS

use File::Fetch;
### construire un objet File::Fetch ###
my $ff = File::Fetch->new(uri => 'http://some.where.com/dir/a.txt');
### récupérer l'uri dans cwd() ###
my $where = $ff->fetch() or die $ff->error;
### récupérer l'uri dans /tmp ###
my $where = $ff->fetch( to => '/tmp' );
### éléments analysés à partir de l'uri ###
$ff->uri;
$ff->scheme;
$ff->host;
$ff->path;
$ff->file;

DESCRIPTION

File::Fetch est un mécanisme générique de récupération de fichiers.

Il vous permet de récupérer n'importe quel fichier pointé par un URI de type "ftp", "http", "file", "git" ou "rsync" par différents moyens.

Voir la section "COMMENT CA MARCHE" plus bas pour les détails.

ACCESSEURS

Un objet "File::Fetch" possède les accesseurs suivants :

$ff->uri
L'URI que vous avez passé au constructeur
$ff->scheme
Le schéma de l'URI (comme 'file', 'http', etc.)
$ff->host
Le nom d'hôte dans l'URI. Sera vide si le nom d'hôte était à l'origine 'localhost' pour une URL 'file://'.
$ff->vol
Sur les systèmes d'exploitation où le concept de volume existe, le deuxième élément d'un 'file://' est considéré comme la spécification du volume pour le fichier. Ainsi, sous Win32, cette routine retourne le volume, sur d'autres systèmes d'exploitation, elle ne retourne rien.

Sous Windows, cette valeur peut être vide si l'URI pointe vers un partage réseau, auquel cas la propriété 'share' sera définie. De plus, les spécifications de volume qui utilisent '|' au lieu de ':' seront converties à la lecture pour utiliser ':'.

Sur VMS, qui a un concept de volume, ce champ sera vide car les spécifications de fichiers VMS sont converties au format UNIX absolu et les informations de volume sont incluses de manière transparente.

$ff->share
Sur les systèmes où le concept de partage réseau existe (actuellement seulement Windows), retourne le nom du partage à partir d'une URL file:////. Sur les autres systèmes d'exploitation, retourne vide.
$ff->path
Le chemin de l'URI, sera au minimum un '/' unique.
$ff->file
Le nom du fichier distant. Pour le nom de fichier local, le résultat de $ff->output_file sera utilisé.
$ff->file_default
Le nom du fichier local par défaut, auquel $ff->output_file se rabattra s'il ne retourne normalement aucun nom de fichier. Par exemple, lors de la récupération d'une URI comme http://www.abc.net.au/, le contenu récupéré peut provenir d'un fichier distant appelé 'index.html'. La valeur par défaut de cet attribut est littéralement 'file_default'.
$ff->output_file
Le nom du fichier de sortie. C'est la même chose que $ff->file, mais les paramètres de requête sont supprimés. Par exemple : http://example.com/index.html?x=y

ferait que le fichier de sortie serait "index.html" plutôt que "index.html?x=y".

MÉTHODES

$ff = File::Fetch->new( uri => 'http://some.where.com/dir/file.txt' );

Analyse l'URI et crée un objet File::Fetch::Item correspondant, prêt à être récupéré par "fetch", et le retourne.

Retourne false en cas d'échec.

$where = $ff->fetch( [to => /my/output/dir/ | \$scalar] )

Récupère le fichier que vous avez demandé et retourne le chemin complet du fichier.

Par défaut, il écrit dans cwd(), mais vous pouvez remplacer cela en spécifiant l'argument "to" :

### récupérer le fichier dans /tmp, chemin complet du fichier dans $where
$where = $ff->fetch( to => '/tmp' );
### fichier chargé dans $scalar, chemin complet du fichier dans $where
### le fichier est téléchargé dans un répertoire temporaire et nettoyé à la sortie
$where = $ff->fetch( to => \$scalar );

Retourne le chemin complet du fichier téléchargé en cas de succès, et false en cas d'échec.

$ff->error([BOOL])

Retourne la dernière erreur rencontrée sous forme de chaîne de caractères. Passez-lui une valeur vraie pour obtenir plutôt la sortie de Carp::longmess().

COMMENT CA MARCHE

File::Fetch est capable de récupérer une variété d'URIs, en utilisant plusieurs programmes et modules externes.

Ci-dessous une correspondance entre les utilitaires qui seront utilisés, dans quel ordre, et pour quels schémas, s'ils sont disponibles :

file    => LWP, lftp, file
http    => LWP, HTTP::Tiny, wget, curl, lftp, fetch, HTTP::Lite, lynx, iosock
ftp     => LWP, Net::FTP, wget, curl, lftp, fetch, ncftp, ftp
rsync   => rsync
git     => git

Si vous souhaitez désactiver l'utilisation d'un ou plusieurs de ces utilitaires et/ou modules, voir la variable $BLACKLIST plus bas.

Si un utilitaire ou un module n'est pas disponible, il sera marqué dans un cache (voir la variable $METHOD_FAIL plus bas), donc il ne sera pas essayé à nouveau. La méthode "fetch" échouera uniquement lorsque toutes les options auront été épuisées et qu'il n'aura pas été possible de récupérer le fichier.

L'utilitaire "fetch" est disponible sur FreeBSD. NetBSD et Dragonfly BSD peuvent également l'avoir via "pkgsrc". Nous ne vérifions "fetch" que sur ces trois plateformes.

"iosock" est un mécanisme très limité basé sur IO::Socket::INET pour récupérer les URL de schéma "http". Il ne suit pas les redirections, par exemple.

"git" ne prend en charge que les URL de type "git://".

Une note spéciale sur la récupération de fichiers à partir d'une URI ftp :

Par défaut, toutes les connexions ftp sont effectuées en mode passif. Pour changer cela, voir la variable $FTP_PASSIVE plus bas.

De plus, les URI ftp ne prennent en charge que les connexions anonymes, donc aucune paire utilisateur/mot de passe nommée ne peut être passée.

La commande "/bin/ftp" est mise sur liste noire par défaut ; voir la variable $BLACKLIST plus bas.

VARIABLES GLOBALES

Le comportement de File::Fetch peut être modifié en changeant les variables globales suivantes :

$File::Fetch::FROM_EMAIL

C'est l'adresse email qui sera envoyée comme mot de passe ftp anonyme.

La valeur par défaut est "File-Fetch@example.com".

$File::Fetch::USER_AGENT

C'est l'agent utilisateur tel que rapporté par "LWP".

La valeur par défaut est "File::Fetch/$VERSION".

$File::Fetch::FTP_PASSIVE

Cette variable contrôle si la variable d'environnement "FTP_PASSIVE" et tous les commutateurs passifs des outils en ligne de commande seront définis sur vrai.

La valeur par défaut est 1.

Note : Lorsque $FTP_PASSIVE est vrai, "ncftp" ne sera pas utilisé pour récupérer des fichiers, car le mode passif ne peut être défini

Comment utiliser un proxy avec File::Fetch

?

"File::Fetch" prend actuellement en charge les proxies uniquement avec LWP::UserAgent. Vous devrez définir vos variables d'environnement en conséquence. Par exemple, pour utiliser un proxy ftp : $ENV{ftp_proxy} = 'foo.com'; Consultez la page de man de LWP::UserAgent pour plus de détails.
