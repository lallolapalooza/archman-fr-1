DESCRIPTIO

N

Les messages étiquetés sont des transferts de données qui portent une clé ou une étiquette avec le tampon de message. L'étiquette est utilisée au point de terminaison de réception pour faire correspondre le message entrant avec un tampon de réception correspondant. Les étiquettes de message correspondent lorsque l'étiquette du tampon de réception est la même que celle du tampon d'envoi, les bits ignorés étant masqués. Cela peut être exprimé comme suit

: 
send_tag & ~ignore =
= recv_tag & ~ignore
ou send_tag | ignore
== recv_tag | ignore

En général, les étiquettes de message sont vérifiées par rapport aux tampons de réception dans l'ordre dans lequel les messages ont été publiés sur le point de terminaison. Voir la discussion sur l'ordre ci-dessous pour plus de

détails.

Les fonctions d'envoi – fi_tsend, fi_tsendv, fi_tsendmsg, fi_tinject et fi_tsenddata – sont utilisées pour transmettre un message étiqueté d'un point de terminaison à un autre. La principale différence entre les fonctions d'envoi réside dans le nombre et le type de paramètres qu'elles acceptent en entrée. Sinon, elles effectuent la même fonction

générale.

Les fonctions de réception – fi_trecv, fi_trecvv, fi_recvmsg – publient un tampon de données sur un point de terminaison pour recevoir des messages étiquetés entrants. Similairement aux opérations d'envoi, les opérations de réception fonctionnent de manière asynchrone. Les utilisateurs ne doivent pas toucher au(x) tampon(s) de données publié(s) tant que l'opération de réception n'est pas terminée. Les tampons de réception publiés sont appariés aux messages d'envoi entrants en fonction des étiquettes associées aux tampons d'envoi et de

réception.

Un point de terminaison doit être activé avant qu'une application puisse y publier des opérations d'envoi ou de réception. Pour les points de terminaison connectés, les tampons de réception peuvent être publiés avant que connect ou accept ne soit appelé sur le point de terminaison. Cela garantit que les tampons sont disponibles pour recevoir les données entrantes immédiatement après l'établissement de la

connexion.

Les opérations de message terminées sont signalées à l'utilisateur via un ou plusieurs collecteurs d'événements associés au point de terminaison. Les utilisateurs fournissent un contexte qui est associé à chaque opération et qui est retourné à l'utilisateur dans le cadre de l'événement de complétion. Voir fi_cq pour les détails sur les événements de

complétion.

d

a été configuré différemment, le tampon de données passé à fi_tsend ne doit pas être touché par l'application tant que l'appel fi_tsend n'est pas terminé de manière asynchrone.

X

Les appels fi_trecvmsg et fi_tsendmsg permettent à l'utilisateur de spécifier des drapeaux qui peuvent modifier le traitement par défaut des messages de l'extrémité. Les drapeaux spécifiés avec fi_trecvmsg / fi_tsendmsg remplacent la plupart des drapeaux précédemment configurés avec l'extrémité, sauf indication contraire (voir fi_endpoint). La liste suivante de drapeaux est utilisable avec fi_trecvmsg et/ou

fi_tsendmsg.
FI_REMOTE_CQ_D
ATA
S'applique à fi_tsendmsg. Indique que des données CQ distantes sont disponibles et doivent être envoyées dans le cadre de la requête. Voir fi_getinfo pour plus de détails sur FI_REMOTE_CQ_DATA. Ce drapeau est implicitement défini pour fi_tsenddata et
fi_tinjectdata.
FI_COMPLETI
ON
Indique qu'une entrée de complétion doit être générée pour l'opération spécifiée. L'extrémité doit être liée à une file de complétion avec FI_SELECTIVE_COMPLETION correspondant à l'opération spécifiée, sinon ce drapeau est
ignoré.
FI_MO
RE
Indique que l'utilisateur a des requêtes supplémentaires qui seront placées immédiatement après le retour de l'appel courant. L'utilisation de ce drapeau peut améliorer les performances en permettant au fournisseur d'optimiser son accès au matériel de
fabric.
FI_INJE
CT
S'applique à fi_tsendmsg. Indique que le tampon de données sortantes doit être rendu à l'utilisateur immédiatement après le retour de l'appel d'envoi, même si l'opération est traitée de manière asynchrone. Cela peut nécessiter que l'implémentation du fournisseur sous-jacent copie les données dans un tampon local et les transfère depuis ce tampon. Ce drapeau ne peut être utilisé qu'avec des messages plus petits que
inject_size.
FI_MULTI_RE
CV
S'applique aux opérations de réception étiquetées placées lorsque la capacité FI_TAGGED_MULTI_RECV est activée. Ce drapeau permet à l'utilisateur de placer un seul tampon de réception étiqueté qui recevra
plusieurs messages entrants. Les messages reçus seront empaquetés dans le tampon de réception jusqu'à ce que le tampon soit consommé. L'utilisation de ce drapeau peut faire qu'une seule opération de réception pl
acée génère plusieurs événements lorsque des messages sont placés dans le tampon. Le placement des données reçues dans le tampon peut être soumis à des restrictions d'alignement spécifiques au fournisseur.

Le tampon sera libéré par le fournisseur lorsque l'espace de tampon disponible descend en dessous du minimum spécifié (voir FI_OPT_MIN_MULTI_RECV). Notez qu'une entrée dans la file de complétion de réception associée sera toujours générée lorsque le tampon a été consommé, même si d'autres complétions de réception ont été supprimées (c'est-à-dire que le contexte Rx a été configuré pour FI_SELECTIVE_COMPLETION). Voir le drapeau de complétion FI_MULTI_RECV fi_cq(3)

appariée.

    NOM

    fi_tsendv — Envoie plusieurs objets de messages dans un contexte.

    SYNTAXE

    #include <rdma/fi_domain.h>

    int fi_tsendv(struct fid_mr *mr, const struct iovec *iov, int iovcnt, void *desc);

    DESCRIPTION

    La fonction fi_tsendv démarre une opération d'envoi sur plusieurs segments de mémoire (scatter/gather).

    Le paramètre mr est une référence vers un objet de domaine, un objet endpoint, ou un objet de mémoire enregistrée. Il est utilisé pour associer des informations de contexte à l'opération d'envoi.

    Le paramètre iov est un tableau de structures iovec, où chaque structure décrit un segment de mémoire à envoyer. Le paramètre iovcnt spécifie le nombre de structures iovec dans le tableau.

    Le paramètre desc est un pointeur vers un descripteur de transfert facultatif. Si ce paramètre est utilisé, il doit faire référence à un descripteur de transfert alloué à l'aide de fi_alloc_desc.

    OPTIONS

    Aucune option spécifique n'est disponible pour cette fonction. Les comportements sont contrôlés par les attributs de la connexion.

    VALEUR DE RETOUR

    La fonction fi_tsendv retourne 0 en cas de succès. En cas d'échec, elle retourne un code d'erreur négatif.

    ERREURS

    -FI_ENOMSG
    Le message est trop long pour la MTU.
    -FI_ETOOMANYREQS
    Trop de requêtes d'envoi en attente.
    -FI_EAGAIN
    Opération tentée trop tôt.
    -FI_EHOSTUNREACH
    L'hôte de destination est injoignable.
    -FI_ENOTSUP
    L'opération n'est pas prise en charge.
