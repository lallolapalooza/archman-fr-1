DESCRIPTION

Les messages tagués sont des transferts de données qui portent une clé ou un tag avec le tampon du message. Le tag est utilisé au point de terminaison de réception pour faire correspondre le message entrant avec un tampon de réception correspondant. Les tags de message correspondent lorsque le tag du tampon de réception est identique au tag du tampon d'envoi avec les bits ignorés masqués. Cela peut être énoncé comme suit :

send_tag & ~ignore == recv_tag & ~ignore
ou
send_tag | ignore == recv_tag | ignore

En général, les tags de message sont comparés aux tampons de réception dans l'ordre dans lequel les messages ont été postés sur le point de terminaison. Voir la discussion sur l'ordre ci-dessous pour plus de détails.

Les fonctions d'envoi – fi_tsend, fi_tsendv, fi_tsendmsg, fi_tinject, et fi_tsenddata – sont utilisées pour transmettre un message tagué d'un point de terminaison à un autre point de terminaison. La principale différence entre les fonctions d'envoi réside dans le nombre et le type de paramètres qu'elles acceptent en entrée. Sinon, elles effectuent la même fonction générale.

Les fonctions de réception – fi_trecv, fi_trecvv, fi_recvmsg – postent un tampon de données à un point de terminaison pour recevoir les messages tagués entrants. Semblables aux opérations d'envoi, les opérations de réception fonctionnent de manière asynchrone. Les utilisateurs ne doivent pas toucher aux tampons de données postés avant que l'opération de réception ne soit terminée. Les tampons de réception postés sont mis en correspondance avec les messages d'envoi entrants en fonction des tags associés aux tampons d'envoi et de réception.

Un point de terminaison doit être activé avant qu'une application puisse y poster des opérations d'envoi ou de réception. Pour les points de terminaison connectés, les tampons de réception peuvent être postés avant que connect ou accept ne soit appelé sur le point de terminaison. Cela garantit que des tampons sont disponibles pour recevoir des données entrantes immédiatement après l'établissement de la connexion.

Les opérations de message terminées sont signalées à l'utilisateur via un ou plusieurs collecteurs d'événements associés au point de terminaison. Les utilisateurs fournissent un contexte associé à chaque opération, qui est renvoyé à l'utilisateur dans le cadre de l'achèvement de l'événement. Voir fi_cq pour les détails sur les événements d'achèvement.

fi_tsend

L'appel fi_tsend transfère les données contenues dans le tampon de données spécifié par l'utilisateur vers un point de terminaison distant, en maintenant les limites des messages. Le point de terminaison local doit être connecté à un point de terminaison ou à une destination distante avant que fi_tsend ne soit appelé. Sauf si le point de terminaison a été configuré différemment, le tampon de données passé à fi_tsend ne doit pas être modifié par l'application tant que l'appel fi_tsend n'est pas terminé de manière asynchrone.

fi_tsendv

L'appel fi_tsendv ajoute la prise en charge d'une liste scatter-gather à fi_tsend. fi_sendv transfère l'ensemble des tampons de données référencés par le paramètre iov vers un point de terminaison distant sous forme d'un seul message.

fi_tsendmsg

L'appel fi_tsendmsg prend en charge les transferts de données sur des points de terminaison connectés et sans connexion, avec la possibilité de contrôler l'opération d'envoi par appel grâce à l'utilisation d'indicateurs. La fonction fi_tsendmsg prend une structure fi_msg_tagged en entrée.

struct fi_msg_tagged {
    const struct iovec *msg_iov; /* tableau scatter-gather */
    void               *desc;    /* descripteur de données */
    size_t             iov_count;/* nombre d'éléments dans msg_iov */
    fi_addr_t          addr;    /* adresse de point de terminaison optionnelle */
    uint64_t           tag;      /* tag associé au message */
    uint64_t           ignore;   /* masque appliqué au tag pour les réceptions */
    void               *context; /* contexte défini par l'utilisateur */
    uint64_t           data;     /* données immédiates optionnelles */
};

fi_tinject

L'appel d'injection tagué est une version optimisée de fi_tsend. Il fournit des sémantiques d'achèvement similaires à celles de fi_inject fi_msg(3).

fi_tsenddata

L'appel d'envoi de données taguées est similaire à fi_tsend, mais permet d'envoyer des données CQ distantes (voir l'indicateur FI_REMOTE_CQ_DATA) dans le cadre du transfert.

fi_tinjectdata

L'appel d'injection de données taguées est similaire à fi_tinject, mais permet d'envoyer des données CQ distantes (voir l'indicateur FI_REMOTE_CQ_DATA) dans le cadre du transfert.

v

L'appel fi_trecv publie un tampon de données dans la file de réception de l'extrémité correspondante. Les réceptions

publiées sont recherchées dans l'ordre où elles ont été publiées afin de correspondre aux envois. Les limites des
messages sont conservées. L'ordre dans lequel les réceptions se terminent dépend du type d'extrémité et du protocole.

    NOM

    fi_tsenddata - Envoyer des données à une transaction

    SYNTAXE

    int fi_tsenddata(struct fi_context *ctx, const void *buf, size_t len, uint64_t tag, uint64_t data);

    DESCRIPTION

    La fonction fi_tsenddata est utilisée pour envoyer des données dans le cadre d'une transaction. Elle est généralement appelée après la création d'une transaction avec fi_transaction_create et avant sa validation ou son annulation. Les données envoyées sont associées à un identifiant de balise (tag) et à des données supplémentaires (data).

    OPTIONS

    Aucune option spécifique n'est documentée pour cette fonction.

    VALEUR DE RETOUR

    La fonction fi_tsenddata renvoie 0 en cas de succès, et un code d'erreur en cas d'échec.

    ERREURS

    Les erreurs potentielles incluent, sans s'y limiter :

    • FI_ENODATA: Aucune donnée à envoyer.
    • FI_EINVAL: Paramètres invalides.
    • FI_EPROTO: Erreur de protocole.

    VOIR AUSSI

    fi_transaction_create(3), fi_transaction_commit(3), fi_transaction_abort(3)
