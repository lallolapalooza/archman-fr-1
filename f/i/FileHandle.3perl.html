FileHandle(3perl) Guide du programmeur Perl FileHandle(3perl)

NOM

FileHandle - fournir des méthodes d'objet pour les descripteurs de fichier

SYNTAXE

use FileHandle;
my $fh = FileHandle->new;
if ($fh->open("< fichier")) {
    print <$fh>;
    $fh->close;
}
my $fh = FileHandle->new("> FOO");
if (defined $fh) {
    print $fh "bar\n";
    $fh->close;
}
my $fh = FileHandle->new("fichier", "r");
if (defined $fh) {
    print <$fh>;
    undef $fh;       # ferme automatiquement le fichier
}
my $fh = FileHandle->new("fichier", O_WRONLY|O_APPEND);
if (defined $fh) {
    print $fh "corge\n";
    undef $fh;       # ferme automatiquement le fichier
}
my $pos = $fh->getpos;
$fh->setpos($pos);
$fh->setvbuf(my $buffer_var, _IOLBF, 1024);
my ($readfh, $writefh) = FileHandle::pipe;
autoflush STDOUT 1;

DESCRIPTION

NOTE : Cette classe est maintenant une interface pour les classes IO::*.

"FileHandle::new" crée un "FileHandle", qui est une référence à un nouveau symbole créé (voir la classe Symbol). S'il reçoit des paramètres, ils sont passés à "FileHandle::open" ; si l'ouverture échoue, l'objet "FileHandle" est détruit. Sinon, il est retourné à l'appelant.

"FileHandle::new_from_fd" crée un "FileHandle" comme le fait "new". Il nécessite deux paramètres, qui sont passés à "FileHandle::fdopen" ; si le fdopen échoue, l'objet "FileHandle" est détruit. Sinon, il est retourné à l'appelant.

"FileHandle::open" accepte un paramètre ou deux. Avec un paramètre, ce n'est qu'une interface pour la fonction intégrée "open". Avec deux paramètres, le premier paramètre est un nom de fichier qui peut contenir des espaces blancs ou d'autres caractères spéciaux, et le second paramètre est le mode d'ouverture, éventuellement suivi d'une valeur de permission de fichier.

Si "FileHandle::open" reçoit une chaîne de mode Perl (">", "+<", etc.) ou une chaîne de mode fopen() POSIX ("w", "r+", etc.), il utilise l'opérateur Perl de base "open".

Si "FileHandle::open" reçoit un mode numérique, il passe ce mode et la valeur de permission optionnelle à l'opérateur Perl "sysopen". Par commodité, "FileHandle::import" essaie d'importer les constantes O_XXX du module Fcntl. Si le chargement dynamique n'est pas disponible, cela peut échouer, mais le reste de FileHandle fonctionnera toujours.

"FileHandle::fdopen" est comme "open" sauf que son premier paramètre n'est pas un nom de fichier mais plutôt un nom de descripteur de fichier, un objet FileHandle, ou un numéro de descripteur de fichier.

Si les fonctions C fgetpos() et fsetpos() sont disponibles, alors "FileHandle::getpos" retourne une valeur opaque qui représente la position actuelle du FileHandle, et "FileHandle::setpos" utilise cette valeur pour revenir à une position précédemment visitée.

Si la fonction C setvbuf() est disponible, alors "FileHandle::setvbuf" définit la politique de mise en mémoire tampon pour le FileHandle. La séquence d'appel pour la fonction Perl est la même que pour son homologue C, y compris les macros "_IOFBF", "_IOLBF", et "_IONBF", sauf que le paramètre buffer spécifie une variable scalaire à utiliser comme tampon. ATTENTION : Une variable utilisée comme tampon par "FileHandle::setvbuf" ne doit pas être modifiée de quelque manière que ce soit tant que le FileHandle n'est pas fermé ou tant que "FileHandle::setvbuf" n'est pas appelé à nouveau, sinon une corruption de mémoire peut en résulter !

De plus, pour effectuer des E/S normales, vous pourriez avoir besoin de ceci :

$fh->print
Voir "print" dans perlfunc.
$fh->printf
Voir "printf" dans perlfunc.
$fh->getline
Ceci fonctionne comme <$fh> décrit dans "Opérateurs d'E/S" dans perlop, sauf que c'est plus lisible et peut être appelé en toute sécurité dans un contexte de liste mais retourne toujours une seule ligne.
$fh->getlines
Ceci fonctionne comme <$fh> lorsqu'il est appelé dans un contexte de liste pour lire toutes les lignes restantes d'un fichier, sauf que c'est plus lisible. Il provoquera également un croak() s'il est accidentellement appelé dans un contexte scalaire.

Il existe de nombreuses autres fonctions disponibles car FileHandle est hérité de IO::File, IO::Seekable et IO::Handle. Veuillez consulter ces pages respectives pour la documentation sur les fonctions supplémentaires.
