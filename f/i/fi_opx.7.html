fi_opx — Le fourn

isseur de fabric
Omni-Path Express

PRÉSENTATIO

N

Le fournisseur opx est un fournisseur libfabric natif adapté à une utilisation avec les fabrics Omni-Path. OPX offre une excellente évolutivité et des performances élevées lors de l'exécution de c

ouches de message prenant en charge libfabric. OPX nécessite 3 bibliothèques de développement
externes supplémentaires pour la compilation : libuuid, libnuma et les en-têtes du noyau Linux.

FONCTIONNALITÉS PRISES EN

CHARGE

Le fournisseur OPX prend en charge la plupart des fonctionnalités définies pour l'API

libfabric.

Les fonctionnalités clés incluent

:
Types de point de
terminaison
Le matériel HFI Omni-Path est sans connexion et fiable. Le fournisseur OPX ne prend en charge que le type de point de terminaison
FI_EP_RDM.
Capacit
és
Les capacités prises en charge incluent FI_MSG, FI_RMA, FI_TAGGED, FI_ATOMIC, FI_SOURCE, FI_SEND, FI_RECV, FI_MULTI_RECV, FI_DIRECTED_RECV, FI_S
OURC
E*.

Notes sur la capacité FI_DIRECTED_RECV : les données immédiates envoyées dans l'appel « senddata » pour prendre en charge FI_DIRECTED_RECV pour OPX doivent faire exactement 4 octets, que OPX utilise pour identifier complètement l'adresse source pour un nombre de rangs de niveau exascale pour l'appariement de balises sur la réception et qui peut être géré dans le paquet MU. Par conséquent, l'attribut de domaine « cq_data_size » est défini à 4, qui est le minimum standard

OFI.
Mod
es
Deux modes sont définis : FI_CONTEXT2 et FI_ASYNC_IOV. Le fournisseur OPX requiert FI_CONTEXT
2.
Fonctionnalités
supplémentaires
Les fonctionnalités supplémentaires prises en charge incluent FABRIC_DIRECT et les compt
eurs.
Progress
ion
FI_PROGRESS_MANUAL et FI_PROGRESS_AUTO sont pris en charge ; pour de meilleures performances, utilisez FI_PROGRESS_MANUAL lorsque c'est possible. FI_PROGRESS_AUTO créera 1 thread par
CQ.
Vecteur
d'adresses
FI_AV_MAP et FI_AV_TABLE sont tous deux pris en charge. FI_AV_MAP est la valeur par
défaut.
Modes d'enregistrement de
mémoire
Seul FI_MR_SCALABLE
est p
ris en
charge.

LIMITATION

S

OPX prend en charge les versions MPI suivantes

:

Intel MPI de Parallel Studio 2020, mise à jour 4. Intel MPI de OneAPI 2021, mise à jour 3. Open MPI 4.1.2a1 (les versions plus anciennes d'Open MPI ne fonctionneront pas). MPICH 3.4.2 et versions

ultérieures.

Utilisation

:

Si vous l'utilisez avec OpenMPI 4.1.x, désacti

vez les transports UCX et openib. OPX n'est
pas compatible avec PML/BTL d'Open MPI 4.1.x.

OPTIONS DE

CONFIGURATION
OPX_
AV
OPX prend en charge l'option de définir le mode AV
à utiliser lors de la compilation. 3 paramè
tres sont pris en charge : - table - map - runtime

L'utilisation de table ou map n'autorisera OPX qu'à utiliser FI_AV_TABLE ou FI_AV_MAP. L'utilisation de runtime permettra à OPX d'utiliser l'un ou l'autre mode AV selon ce que l'application demande. Cependant, la spécification de map ou table peut entraîner une légère amélioration des performances selon

l'application.

Pour changer OPX_AV, ajoutez OPX_AV=table, OPX_AV=map ou OPX_AV=runtime à la commande configure. Par exemple, pour créer une nouvelle compilation avec OPX_AV=table

:

OPX_AV=table .

/configure

make

install

Il n'y a aucun moyen de changer OPX_AV après qu'il

a été défini. Si OPX_AV n'est pas défini dan
s configure, la valeur par défaut est runtime.

D'EXÉCUTION
FI_OPX_UU
ID
OPX requiert un ID unique pour chaque job. Afin que tous les processus d'un job puissent communiquer entre eux, ils doivent utiliser le même UUID. Cette variable peut être définie avec FI_OPX_UUID=${RANDOM}. Le UUID par défaut est 00112233445566778899aabbccddee
ff.
FI_OPX_FORCE_CPUAFFIN
ITY
Booléen (1/0, on/off, true/false, yes/no). Force le thread à se lier au cœur de CPU sur lequel il s'exécute. Par défaut à «
No »
FI_OPX_RELIABILITY_SERVICE_USEC_
MAX
Entier. Ce paramètre contrôle la fréquence à laquelle la fonction de fiabilité/rejeu émettra des requêtes PING vers une connexion distante. Réduire cette valeur peut améliorer les performances au prix d'un trafic accru sur le fabric OPX. La valeur par défaut est
500.
FI_OPX_RELIABILITY_SERVICE_MAX_OUTSTANDING_BY
TES
Entier. Ce paramètre contrôle le nombre maximal d'octets autorisés à êtr
e en vol (envoyés mais non acquittés par le récepteur) par flux de fiabi
lité (communication unidirectionnelle entre deux points de terminaison).

Les valeurs valides se situent dans la plage de 8192 à 150 994 944 (8 Ko à 144 Mo),

inclusivement.

La valeur par défaut est 7 340 032 (7 Mo)

.
FI_OPX_RELIABILITY_SERVICE_PRE_ACK_R
ATE
Entier. Ce paramètre contrôle la fréquence à laquelle un rang récepteur enverra des acquittements (ACK) pour les paquets qu'il a reçus sans être
sollicité par une requête PING. Une valeur non nulle N indique au rang récepteur d'envoyer un acquittement pour les N derniers paquets tous les
N paquets. Utilisé en conjonction avec une valeur accrue pour FI_OPX_RELIABILITY_SERVICE_USEC_MAX, cela peut améliorer les performances.

Les valeurs valides sont 0 (désactivé) et les puissances de 2 dans la plage de 1 à 32 768,

inclusivement.

La valeur par défaut est

64.
FI_OPX_RELIABILITY_MAX_UNCONGESTED_PI
NGS
Entier. Ce paramètre contrôle le nombre de requêtes PING que la fonction de fiabilité/rejeu émettra par itération de FI_OPX_RELIABILITY_SERVICE_USEC_MAX dans les situations où le trafic sortant du HFI est moins en concurrence. La valeur par défaut est 128. La plage de valeurs valides est de 1 à
65535.
FI_OPX_RELIABILITY_MAX_CONGESTED_PI
NGS
Entier. Ce paramètre contrôle le nombre de requêtes PING que la fonction de fiabilité/rejeu émettra par itération de FI_OPX_RELIABILITY_SERVICE_USEC_MAX dans les situations où le trafic sortant du HFI est plus en concurrence. La valeur par défaut est 4. La plage de valeurs valides est de 1 à
65535.
FI_OPX_SELIN
UX
Booléen (1/0, on/off, true/false, yes/no). Défini à true si vous exécutez un Linux à sécurité renforcée. Cela permet la mise à jour du Jkey utilisé en fonction des paramètres du système. Par défaut à «
No »
FI_OPX_HFI_SEL
ECT
Chaîne. Contrôle la manière dont OPX choisit le HFI à utiliser lors de l'ouverture d'un contexte
. Deux formes : - <hfi-unit> Force le fournisseur OPX à utiliser hfi-unit. - <selector1>[,
<selector2>[,...,<selectorN>]] Sélectionne le HFI en fonction du premier sélecteur correspondant

Où le sélecteur est l'une des formes suivantes : - default pour utiliser la logique par défaut - fixed:<hfi-unit> pour fixer à un hfi-unit - <selector-type>:<hfi-unit>:

<selector-data>

Les champs ci-dessus ont la signification suivante : - selector-type Les critères de sélection que l'appelant ouvrant le contexte évaluetraduit contre. - hfi-unit L'HFI à utiliser si l'appelant correspond au sélecteur. - selector-data Données auxquelles l'appelant doit correspondre (par exemple, ID de nœud NUMA).

Où selector-type est l'un des suivants : - numa Vrai lorsque l'appelant est local à l'ID de nœud NUMA donné par selector-data. - core Vrai lorsque l'appelant est local au cœur CPU donné par selector-data.

Et selector-data est l'un des suivants : - value La valeur spécifique à faire correspondre - <range-start>-<range-end> Correspond à toute valeur dans cette plage

Dans la deuxième forme, lors de l'ouverture d'un contexte, OPX utilise l'hfi-unit du premier sélecteur correspondant. Les sélecteurs sont évalués de gauche à droite. OPX renverra une erreur si l'appelant ne correspond à aucun sélecteur.

Dans l'une ou l'autre forme, il est erroné si l'HFI spécifié ou sélectionné n'est pas à l'état Actif. Dans ce cas, OPX renverra une erreur et l'exécution ne continuera pas.

Avec cette option, il est possible de faire en sorte qu'OPX essaie d'ouvrir plus de contextes sur un HFI qu'il n'y a de contextes libres sur cet HFI. Dans ce cas, un ou plusieurs des appels d'ouverture de contexte échoueront et OPX renverra une erreur. Pour la deuxième forme, comme l'HFI sélectionné dépend des propriétés de l'appelant, une sélection HFI déterministe nécessite des propriétés d'appelant déterministes. Par exemple, pour le sélecteur numa, si l'appelant peut migrer entre les domaines NUMA, la sélection HFI ne sera pas déterministe.

La logique utilisée sera toujours la première valide dans une liste de sélecteurs. Par exemple, default et fixed correspondront à tous les appelants, donc si l'un d'eux est au début d'une liste de sélecteurs, vous n'utiliserez que fixed ou default, peu importe s'il y a d'autres sélecteurs.

Exemples : - FI_OPX_HFI_SELECT=0 Tous les appelants ouvriront des contextes sur l'HFI 0. - FI_OPX_HFI_SELECT=1 Tous les appelants ouvriront des contextes sur l'HFI 1. - FI_OPX_HFI_SELECT=numa:0:0,numa:1:1,numa:0:2,numa:1:3 Les appelants locaux aux nœuds NUMA 0 et 2 utiliseront l'HFI 0, les appelants locaux aux domaines NUMA 1 et 3 utiliseront l'HFI 1. - FI_OPX_HFI_SELECT=numa:0:0-3,default Les appelants locaux aux nœuds NUMA 0 à 3 (inclus 0 et 3) utiliseront l'HFI 0, et tous les autres utiliseront la logique de sélection par défaut. - FI_OPX_HFI_SELECT=core:1:0,fixed:0 Les appelants locaux au cœur CPU 0 utiliseront l'HFI 1, et tous les autres utiliseront l'HFI 0. - FI_OPX_HFI_SELECT=default,core:1:0 Tous les appelants utiliseront la logique de sélection HFI par défaut.

FI_OPX_PORT
Entier. Numéro de port HFI1. Si le port spécifié n'est pas disponible, un port actif par défaut sera sélectionné. La valeur spéciale 0 indique tout port disponible. Par défaut, le port 1 sur OPA100 et n'importe quel port sur CN5000.
FI_OPX_DELIVERY_COMPLETION_THRESHOLD
Entier. Sera déprécié. Veuillez utiliser FI_OPX_SDMA_BOUNCE_BUF_THRESHOLD.
FI_OPX_SDMA_BOUNCE_BUF_THRESHOLD
Entier. La longueur maximale du message en octets qui sera copiée dans le tampon de rebond SDMA. Pour les messages plus longs que ce seuil, l'envoi ne sera pas terminé tant que le destinataire n'aura pas accusé réception. La valeur doit être comprise entre 16385 et 2147483646. Par défaut, 16385.
FI_OPX_SDMA_DISABLE
Booléen (1/0, on/off, true/false, yes/no). Désactive le matériel de décharge SDMA. Par défaut : 0.
FI_OPX_MAX_PKT_SIZE
Entier. Définit la taille maximale du paquet qui doit être inférieure ou égale à la taille MTU (Maximum Transmission Unit) du pilote. Valeurs valides : 2048, 4096, 8192, 10240. Par défaut, 10240 pour les bibliothèques compilées sur des systèmes CN5000 et 8192 pour les bibliothèques compilées sur des systèmes OPA100.
FI_OPX_SDMA_MIN_PAYLOAD_BYTES
Entier. La longueur minimale en octets pour laquelle le SDMA sera utilisé. Pour les messages plus petits que ce seuil, l'envoi sera terminé en utilisant PIO. La valeur doit être comprise entre 64 et 2147483646. Par défaut, 16385.
FI_OPX_SDMA_MAX_WRITEVS_PER_CYCLE
Entier. Le nombre maximum de fois que writev sera appelé pendant un cycle de sondage. La valeur doit être comprise entre 1 et 1024. Par défaut, 1.
FI_OPX_SDMA_MAX_IOVS_PER_WRITEV
Entier. Le nombre maximum d'IOV passés à chaque appel writev. La valeur doit être comprise entre 3 et 128. Par défaut, 64.
FI_OPX_SDMA_MAX_PKTS
Entier. Le nombre maximum de paquets transmis par demande SDMA lorsque la réception attendue (TID) N'EST PAS utilisée. La valeur doit être comprise entre 1 et 128. Par défaut, 32.
FI_OPX_SDMA_MAX_PKTS_TID
Entier. Le nombre maximum de paquets transmis par demande SDMA lorsque la réception attendue (TID) EST utilisée. La valeur doit être comprise entre 1 et 512. Par défaut, 64.
FI_OPX_TID_MIN_PAYLOAD_BYTES
Entier. La longueur minimale en octets où le TID (réception attendue) sera utilisé. Pour les messages plus petits que ce seuil, l'envoi sera terminé en utilisant l'Eager Receive. La valeur doit être comprise entre 4096 et 2147483646. Par défaut, 4096.
FI_OPX_RZV_MIN_PAYLOAD_BYTES
Entier. La longueur minimale en octets où le rendezvous sera utilisé. Pour les messages plus petits que ce seuil, l'envoi essaiera d'abord d'être terminé en utilisant eager ou multi-packet eager. La valeur doit être comprise entre 64 et 65536. Par défaut, 16385.
FI_OPX_MP_EAGER_DISABLE
Booléen (1/0, on/off, true/false, yes/no). Désactive l'eager multi-paquets. Par défaut : 0.
FI_OPX_TID_DISABLE
Booléen (1/0, on/off, true/false, yes/no). Désactive l'utilisation de l'ID de jeton (TID). Par défaut : 0.
FI_OPX_EXPECTED_RECEIVE_ENABLE
Déprécié. Utilisez FI_OPX_TID_DISABLE à la place.
FI_OPX_PROG_AFFINITY
Chaîne de caractères. Ceci définit l'affinité à utiliser pour tous les threads de progression. Défini comme un triplet séparé par des deux-points start:end:stride, où stride contrôle l'intervalle entre les cœurs sélectionnés. Par exemple, 1:5:2 utilisera les cœurs 1, 3 et 5 comme cœurs valides pour les threads de progression. Par défaut, aucune affinité n'est définie.
FI_OPX_AUTO_PROGRESS_INTERVAL_USEC
Déprécié/ignoré. Les threads de progression automatique sont maintenant pilotés par interruption et ne sondent que lorsque des données sont disponibles.
FI_OPX_PKEY
Entier. Clé de partition, un entier positif de 2 octets. Par défaut, c'est la Pkey à l'index 0 de la table Pkey de l'unité et du port sur lesquels le contexte est créé.
FI_OPX_SL
Entier. Niveau de service. Ceci déterminera également la classe de service et la voie virtuelle. Par défaut : 0.
FI_OPX_GPU_IPC_INTRANODE
Booléen (0/1, on/off, true/false, yes/no). Ce paramètre contrôle si l'IPC sera utilisé pour faciliter les copies intra-nœuds GPU vers GPU via PCIe, NVLINK ou xGMI. Lorsque ceci est désactivé, les données GPU seront copiées vers l'hôte avant d'être copiées vers un autre GPU, ce qui est plus lent que l'utilisation de l'IPC. Ceci n'a d'effet qu'avec les builds OPX activés pour HMEM. Par défaut : activé.
FI_OPX_DEV_REG_SEND_THRESHOLD
Entier. Le seuil de paquet individuel où les longueurs supérieures n'utilisent pas une copie enregistrée par le périphérique lors de l'envoi de données depuis le GPU. Le seuil par défaut est 4096. Ceci n'a aucun sens si Libfabric n'a pas été configuré avec le support GDRCopy ou ROCR.
FI_OPX_DEV_REG_RECV_THRESHOLD
Entier. Le seuil de paquet individuel où les longueurs supérieures n'utilisent pas une copie enregistrée par le périphérique lors de la réception de données dans le GPU. Le seuil par défaut est 8192. Ceci n'a aucun sens si Libfabric n'a pas été configuré avec le support GDRCopy ou ROCR.
FI_OPX_MIXED_NETWORK
Booléen (1/0, on/off, true/false, yes/no). Indique que le travail nécessite le support OPA100. Défini à 0 si le support OPA100 n'est pas nécessaire. Par défaut : 1.
FI_OPX_ROUTE_CONTROL
Entier. Spécifie le contrôle de routage pour chaque type de paquet. Le format est - <valeur du type de paquet injecté>:<valeur du type de paquet eager>:<valeur du type de paquet multi-paquets eager>:<valeur du paquet dput>:<valeur du paquet de contrôle de rendezvous>:<valeur du paquet de données de rendezvous>.

Chaque valeur peut varier de 0 à 7. 0-3 est utilisé pour l'ordre et 4-7 est utilisé pour le désordre. Si Token ID (TID) est activé, les contrôles de routage en désordre sont désactivés.

Par défaut, 0:0:0:0:0:0 sur OPA100 et 4:4:4:4:0:4 sur CN5000.

FI_OPX_SHM_ENABLE
Booléen (1/0, on/off, true/false, yes/no). Active le shm sur tous les ports et unités hfi du nœud. Le définir à NON désactive le shm sauf pour les pairs ayant le même lid et le même hfi1 (boucle locale). Par défaut : "YES"
FI_OPX_LINK_DOWN_WAIT_TIME_MAX_SEC
Entier. Le temps maximum en secondes pour attendre qu'un lien se rétablisse. Par défaut : 70 secondes.
FI_OPX_MMAP_GUARD
Booléen (0/1, on/off, true/false, yes/no). Active les protections autour des mmaps OPX/HFI. Lorsqu'il est activé, cela provoquera un segfault lorsque la mémoire mappée est accédée illégalement par des dépassements ou des sous-dépassements de tampon. Par défaut : false.
FI_OPX_CONTEXT_SHARING
Booléen (1/0, on/off, true/false, yes/no). Active le partage de contexte dans OPX. Par défaut : FALSE (1 contexte HFI par point de terminaison).
FI_OPX_ENDPOINTS_PER_HFI_CONT
EXT
Entier. Spécifie combien d'endpoints doivent partager un seul contexte HFI. Les valeu
rs valides vont de 2 à 8. La valeur par défaut est déterminée en fonction du nombre d
e contextes disponibles sur le système et du nombre de processeurs en ligne. Applica
ble uniquement si le partage de contexte est activé. Sinon, cette valeur est ignorée.
