NOM

fi_fabric - Opérations réseau de fabric

fi_fabric / fi_close
Ouvrir / fermer un réseau de fabric
fi_tostr / fi_tostr_r
Convertir les attributs, drapeaux et capacités de fabric en chaîne imprimable

SYNOPSIS

#include <rdma/fabric.h>
int fi_fabric(struct fi_fabric_attr *attr,
    struct fid_fabric **fabric, void *context);
int fi_close(struct fid *fabric);
char * fi_tostr(const void *data, enum fi_type datatype);
char * fi_tostr_r(char *buf, size_t len, const void *data,
    enum fi_type datatype);

ARGUMENTS

attr
Attributs du fabric à ouvrir.
fabric
Réseau de fabric
context
Contexte spécifié par l'utilisateur associé à l'objet ouvert. Ce contexte est renvoyé dans le cadre de tout événement asynchrone associé.
buf
Tampon de sortie dans lequel écrire la chaîne.
len
Taille en octets de la mémoire référencée par buf.
data
Données d'entrée à convertir en chaîne. Le format des données est déterminé par le paramètre datatype.
datatype
Indique les données à convertir en chaîne imprimable.

DESCRIPTION

Un identifiant de fabric est utilisé pour référencer les ressources de fabric ouvertes et les objets liés à la bibliothèque.

Le réseau de fabric représente une collection de ressources matérielles et logicielles qui accèdent à un réseau physique ou virtuel unique. Tous les ports réseau d'un système qui peuvent communiquer entre eux via leurs réseaux attachés appartiennent au même fabric. Un réseau de fabric partage des adresses réseau et peut s'étendre sur plusieurs fournisseurs. Une application doit ouvrir un réseau de fabric avant d'allouer d'autres ressources réseau, telles que des points de terminaison de communication.

fi_fabric

Ouvre un fournisseur de réseau de fabric. Les attributs du fournisseur de fabric sont spécifiés via l'appel d'ouverture et peuvent être obtenus en appelant fi_getinfo.

fi_close

L'appel fi_close est utilisé pour libérer toutes les ressources associées à un objet de fabric. Tous les éléments associés au fabric ouvert doivent être libérés avant d'appeler fi_close.

fi_tostr / fi_tostr_r

Convertit les attributs d'interface de fabric, les capacités, les drapeaux et les valeurs enum en une chaîne imprimable. Le paramètre data accepte un pointeur vers l'attribut ou la ou les valeurs à afficher, le paramètre datatype indiquant le type de données référencé par le paramètre data. Les valeurs valides pour datatype sont listées ci-dessous, avec le datatype ou la valeur de champ correspondant.

FI_TYPE_EP_CAP

FI_TYPE_OP_FLAGS

FI_TYPE_ADDR_FORMAT

FI_TYPE_PROGRESS

FI_TYPE_PROTOCOL

FI_TYPE_MSG_ORDER

FI_TYPE_AV_TYPE

FI_TYPE_ATOMIC_OP

fi_tostr() renverra un pointeur vers un tampon interne de libfabric qui ne doit pas être modifié et qui sera écrasé la prochaine fois que fi_tostr() est invoqué. fi_tostr() n'est pas sûr dans un environnement multithread.

La fonction fi_tostr_r() est une version réentrante et sûre dans un environnement multithread de fi_tostr(). Elle écrit la chaîne dans un tampon fourni par l'appelant. fi_tostr_r() renvoie le début du tampon de l'appelant.

NOTES

Les ressources suivantes sont associées aux domaines de fabric : domaines d'accès, points de terminaison passifs et files d'événements CM.

ATTRIBUTS DE FABRIC

La structure fi_fabric_attr définit l'ensemble des attributs associés à un fabric et à un fournisseur de fabric.

struct fi_fabric_attr {
    struct fid_fabric *fabric;
    char              *name;
    char              *prov_name;
    uint32_t          prov_version;
    uint32_t          api_version;
};

fabric

En entrée de fi_getinfo, un utilisateur peut définir ceci sur une instance de fabric ouverte pour restreindre la sortie au fabric donné. En sortie de fi_getinfo, si aucun fabric n'a été spécifié, mais que l'utilisateur a une instance ouverte du fabric nommé, celui-ci référencera la première instance ouverte. Si aucune instance n'a été ouverte, ce champ sera NULL.

L'instance de fabric retournned par fi_getinfo ne doit être considéré comme valide que si l'application ne ferme aucune instance de tissu à partir d'un autre thread pendant que fi_getinfo est en cours de traitement.

name

Un identifiant de tissu.

prov_name - Nom du fournisseur

Le nom du fournisseur de tissu sous-jacent.

Pour demander un fournisseur utilitaire superposé sur un fournisseur de base spécifique, les deux noms de fournisseurs doivent être spécifiés en utilisant “;” comme délimiteur.

par exemple “ofi_rxm;verbs” ou “verbs;ofi_rxm”

À des fins de débogage et d'administration, des variables d'environnement peuvent être utilisées pour contrôler quels fournisseurs de tissu seront enregistrés auprès de libfabric. Spécifier “FI_PROVIDER=foo,bar” permettra à tous les fournisseurs nommés “foo” ou “bar” d'être enregistrés. De même, spécifier “FI_PROVIDER=^foo,bar” empêchera tout fournisseur nommé “foo” ou “bar” d'être enregistré. Les fournisseurs qui ne sont pas enregistrés n'apparaîtront pas dans les résultats de fi_getinfo. Les applications qui ont besoin d'un ensemble spécifique de fournisseurs devraient implémenter leur propre filtrage des résultats de fi_getinfo plutôt que de s'appuyer sur ces variables d'environnement dans un environnement de production.

prov_version - Version du fournisseur

Informations sur la version du fournisseur de tissu, au format majeur.mineur. L'utilisation des macros de version FI_MAJOR() et FI_MINOR() peut être utilisée pour extraire les données de version majeure et mineure. Voir fi_version(3).

Dans le cas d'un fournisseur utilitaire superposé sur un fournisseur de base, la version ferait toujours référence à celle du fournisseur utilitaire.

api_version

La version de l'interface demandée par l'application. Cette valeur correspond au paramètre version passé à fi_getinfo(3).

VALEUR DE RETOUR

Retourne FI_SUCCESS en cas de succès. En cas d'erreur, une valeur négative correspondant à l'errno du tissu est retournée. Les valeurs d'errno du tissu sont définies dans rdma/fi_errno.h.
