NOM

filter-a - filtre les A dans les réponses DNS lorsqu'un AAAA est présent

SYNTAXE

plugin query "filter-a.so" [{ paramètres }];

DESCRIPTION

filter-a.so est un module de plugin de requête pour named <#std-iscman-named>, permettant à named <#std-iscman-named> d'omettre certaines adresses IPv4 lors des réponses aux clients.

Par exemple :

plugin query "filter-a.so" {
        filter-a-on-v6 yes;
        filter-a-on-v4 yes;
        filter-a { 192.0.2.1; 2001:db8:2::1; };
};

Ce module est destiné à faciliter la transition de l'IPv4 vers l'IPv6 en supprimant les adresses IPv4 des clients DNS qui ne sont pas connectés à l'Internet IPv4, lorsque le nom recherché dispose d'une adresse IPv6 disponible. L'utilisation de ce module n'est pas recommandée sauf absolue nécessité.

Note : Ce mécanisme peut, par erreur, empêcher d'autres serveurs de fournir des enregistrements A à leurs clients. Si un serveur récursif disposant de connexions réseau IPv6 et IPv4 interroge un serveur faisant autorité qui utilise ce mécanisme via IPv6, il se voit refuser les enregistrements A même si son client utilise IPv4.

OPTIONS

filter-a
Cette option spécifie une liste d'adresses client pour lesquelles le filtrage des A doit être appliqué. La valeur par défaut est any.
filter-a-on-v6
Si défini sur yes, cette option indique que le client DNS est à une adresse IPv6, dans filter-a. Si la réponse n'inclut pas de signatures DNSSEC, alors tous les enregistrements A sont supprimés de la réponse. Ce filtrage s'applique à toutes les réponses, pas seulement aux réponses faisant autorité.

Si défini sur break-dnssec, alors les enregistrements A sont supprimés même lorsque DNSSEC est activé. Comme son nom l'indique, cela entraîne l'échec de vérification de la réponse, car le protocole DNSSEC est conçu pour détecter les suppressions.

Ce mécanisme peut, par erreur, empêcher d'autres serveurs de fournir des enregistrements A à leurs clients. Si un serveur récursif disposant de connexions réseau IPv6 et IPv4 interroge un serveur faisant autorité qui utilise ce mécanisme via IPv6, il se voit refuser les enregistrements A même si son client utilise IPv4.

filter-a-on-v4
Cette option est identique à filter-a-on-v6, sauf qu'elle filtre les réponses A aux requêtes des clients IPv4 au lieu des clients IPv6. Pour filtrer toutes les réponses, définissez les deux options sur yes.
