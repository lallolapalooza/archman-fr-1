NOM

fi_direct - Accès direct au fournisseur de fabric

SYNTAXE

-DFABRIC_DIRECT
#define FABRIC_DIRECT

Le fabric direct fournit un mécanisme permettant aux applications de compiler contre un fournisseur de fabric spécifique sans passer par le framework libfabric ou les tables de fonctions. Cela permet une optimisation extrême grâce à l'inlining de fonctions, au prix de la prise en charge de plusieurs fournisseurs ou de différentes versions du même fournisseur.

DESCRIPTION

L'utilisation du fabric direct est destinée uniquement aux applications qui nécessitent une latence logicielle minimale absolue et qui sont disposées à recompiler pour du matériel de fabric spécifique. Les fournisseurs qui prennent en charge le fabric direct implémentent leurs propres versions des appels statiques inline qui sont définis dans les fichiers d'en-tête libfabric, définissent des valeurs énumérées sélectionnées et fournissent des définitions pour les optimisations au moment de la compilation. Les applications peuvent alors coder contre les appels libfabric standards, mais se lier directement aux appels du fournisseur en définissant FABRIC_DIRECT dans le cadre de leur build.

En général, l'utilisation du fabric direct ne nécessite pas de modifications du code source de l'application, mais est limitée au processus de construction.

Les fournisseurs prenant en charge le fabric direct doivent installer les versions `direct' de tous les fichiers d'en-tête libfabric. Pour plus de commodité, les sources libfabric contiennent des exemples de fichiers d'en-tête qui peuvent être modifiés par un fournisseur. Les noms des fichiers d'en-tête `direct' ont `fi_direct' comme préfixe : fi_direct.h, fi_direct_endpoint.h, etc.

Les fournisseurs directs sont interdits de remplacer ou de modifier les structures de données existantes. Cependant, les extensions spécifiques au fournisseur sont toujours disponibles. En plus des appels de fonction directs du fournisseur vers le code du fournisseur, un fournisseur de fabric direct peut définir zéro ou plusieurs des définitions de capacité suivantes. Les applications peuvent vérifier ces capacités afin d'optimiser les chemins de code au moment de la compilation, plutôt que de s'appuyer sur des vérifications à l'exécution.

DÉFINITIONS DE CAPACITÉS

Afin que le code de l'application puisse être optimisé au moment de la compilation, les fournisseurs directs doivent fournir des définitions pour diverses capacités et modes, si ces capacités sont prises en charge. Les valeurs #define suivantes peuvent être utilisées par une application pour tester la prise en charge par le fournisseur des fonctionnalités prises en charge.

FI_DIRECT_CONTEXT
Le fournisseur définit FI_CONTEXT ou FI_CONTEXT2 pour fi_info:mode. Voir fi_getinfo pour plus de détails. Lorsque FI_DIRECT_CONTEXT est défini, les applications doivent utiliser la structure fi_context dans leurs définitions, même si FI_CONTEXT2 est défini.
FI_DIRECT_LOCAL_MR
Le fournisseur définit FI_LOCAL_MR pour fi_info:mode. Voir fi_getinfo pour plus de détails.

VOIR AUSSI

fi_getinfo(3), fi_endpoint(3), fi_domain(3)
