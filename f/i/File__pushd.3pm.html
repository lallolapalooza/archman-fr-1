DESCRIPTIO

N

File::pushd effectue un "chdir" temporaire qui est facilement et automatiquement annulé, similaire à "pushd" dans certains shells de commandes Unix. Il fonctionne en créant un objet qui met en cache le répertoire de travail original. Lorsque l'objet est détruit, le destructeur appelle "chdir" pour revenir au répertoire de travail original. En stockant l'objet dans une variable lexicale avec une portée limitée, cela se produit automatiquement à la fin de la

portée.

C'est très pratique lorsqu'on travaille avec des répertoires temporaires pour des tâches comme les tests ; une fonction est fournie pour simplifier l'obtention d'un répertoire temporaire depuis File::

Temp.

Par commodité, l'objet se convertit en la forme canonique du chemin absolu du répertoire dans lequel on est

entré.

Avertissement : si vous créez plusieurs objets "pushd" dans la même portée lexicale, leur ordre de destruction n'est pas

garanti et vous pourriez ne pas vous
retrouver dans le répertoire attendu.

UTILISATI

ON 
use File::
pushd;

L'utilisation de File::pushd importe automatiquement les fonctions "pushd" et "tempd"

.

push

d 
{
    my $dir = pushd( $target_directory );
}

Met en cache le répertoire de travail courant, appelle "chdir" pour changer vers le répertoire cible, et renvoie un objet File::pushd. Lorsque l'objet est détruit, le répertoire de travail revient au répertoire

original.

Le répertoire cible fourni peut être un chemin relatif ou absolu. S'il est appelé sans arguments, il utilise le répertoire courant comme cible et revient au répertoire courant lorsque l'objet est

détruit.

Si le répertoire cible n'existe pas ou si le changement de répertoire échoue pour une raison quelconque, "pushd" terminera avec un message

d'erreur.

Un hashref peut être donné en second argument optionnel. La seule option prise en charge est "untaint_pattern", qui est utilisé pour décontaminer les chemins de fichiers concernés. Sa valeur par défaut est {qr{^("" in -+@\w.+)$}}, ce qui est raisonnablement restrictif (par ex. il n'autorise même pas les espaces

dans le chemin). Modifiez-le pour adapter à vos circonstances et besoins en sécurité si vous exécutez en mode tain
t. *Note* : vous devez inclure les parenthèses dans le motif pour capturer la partie non contaminée du chemin.

temp

d 
{
    my $dir = tempd();
}

Cette fonction est comme "pushd" mais crée et appelle automatiquement "chdir" vers un répertoire temporaire créé par File::Temp. Contrairement au nettoyage normal de File::Temp qui se produit à la fin du programme, ce répertoire temporaire est supprimé lorsque l'objet est détruit. (Mais voir aussi "preserve".) Un avertissement sera émis si le répertoire ne peut pas être

supprimé.

Comme pour "pushd", "tempd" terminera avec une erreur si "chdir" éc

houe.

Un hash d'options unique peut lui être donné, qui sera passé en interne à "pus

hd
".

preserv

e 
{
    my $dir = tempd();
    $dir->preserve;      # marquer pour préserver à la fin de la portée
    $dir->preserve(0);   # marquer pour supprimer à la fin de la portée
}

Contrôle si un répertoire temporaire sera nettoyé lorsque l'objet est détruit. Sans arguments, "preserve" définit le répertoire à préserver. Avec un argument, le répertoire sera préservé si l'argument est vrai, ou marqué pour nettoyage si l'argument est faux. Seuls les objets "tempd" peuvent être marqués pour nettoyage. (Les répertoires cibles de "pushd" sont toujours préservés.) "preserve" renvoie vrai si le

répertoire
sera préservé,
et faux sinon.

DIAGNOSTIC

S

"pushd" et "tempd" émettent un avertissement avec le message "Useless use of File::pushd::%s in void context" s'ils sont appelés dans un contexte vide et si la catégorie d'avertissements "void" est

activée. 
{
  use warnings 'void';
  pushd();
}
