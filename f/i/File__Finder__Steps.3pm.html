File::Finder::Steps(3pm) Documentation Perl fournie par l'utilisateur File::Finder::Steps(3pm)

NOM

File::Finder::Steps - étapes pour File::Finder

SYNOP.

## Voir File::Finder pour une utilisation normale des étapes
## exemple de sous-classement :
BEGIN {
  package My::File::Finder;
  use base File::Finder;
  sub _steps_class { "My::File::Finder::Steps" }
}
BEGIN {
  package My::File::Finder::Steps;
  use base File::Finder::Steps;
  sub bigger_than { # vrai si plus grand que N octets
    my $self = shift;
    my $bytes = shift;
    return sub {
      -s > $bytes;
    }
  }
}
my $over_1k = My::File::Finder->bigger_than(1024);
print "Fichiers temporaires de plus de 1 Ko :\n";
$over_1k->ls->in("/tmp");

DESCRIPTION

"File::Finder::Steps" fournit les prédicats testés pour "File::Finder".

MÉTHODES DES ÉTAPES

Ces méthodes sont appelées sur une classe ou une instance pour ajouter une "étape". Chaque étape s'ajoute à une liste d'étapes, retournant le nouvel objet. Cela vous permet de chaîner les étapes pour former une formule.

Comme dans find, l'opérateur par défaut est "et", et une évaluation court-circuitée est effectuée.

or
Comme "or" de find.
left
Comme une parenthèse gauche. Utilisé pour l'imbrication avec "right".
right
Comme une parenthèse droite. Utilisé pour l'imbrication avec "left". Par exemple : 
my $big_or_old = File::Finder
  ->type('f')
  ->left
    ->size("+100")->or->mtime("+90")
  ->right;
find($big_or_old->ls, "/tmp");

Vous avez besoin de parenthèses car l'opérateur "or" a une priorité plus faible que le "et" implicite, pour la même raison que vous en avez besoin ici :

find /tmp -type f '(' -size +100 -o -mtime +90 ')' -print

Sans les parenthèses, -type serait lié à -size, et non au choix entre -size ou -mtime.

Les parenthèses mal appariées ne seront pas trouvées avant que la formule ne soit utilisée, provoquant une erreur fatale.

begin
Alias pour "left".
end
Alias pour "right".
not
Comme le "!" de find. Opérateur préfixe, peut être placé devant des termes individuels ou des parenthèses ouvertes. Peut être imbriqué, mais quel est l'intérêt ? 
# liste tous les non-fichiers dans /tmp
File::Finder->not->type('f')->ls->in("/tmp");
true
Retourne toujours vrai. Utile lorsqu'une sous-expression peut échouer, mais que vous ne voulez pas que le code global échoue : 
... ->left-> ...[peut retourner faux]... ->or->true->right-> ...

Bien sûr, c'est l'idiome de la commande find :

find .... '(' .... -o -true ')' ...
false
Retourne toujours faux.
comma
Comme la "," de find GNU. Le résultat de l'expression (ou de la sous-expression si entre parenthèses) jusqu'à ce point est écarté, et l'exécution continue à partir de là. Utile lorsqu'une partie de l'expression est nécessaire pour ses effets secondaires, mais ne doit pas affecter le reste de la chaîne "et"-ée. 
# liste tous les fichiers et répertoires, mais ne descend pas dans le contenu du répertoire CVS :
File::Finder->type('d')->name('CVS')->prune->comma->ls->in('.');
follow
Active le suivi des liens symboliques, et retourne vrai.
name(NOM)
Vrai si le nom de base correspond à NOM, qui peut être donné sous forme de modèle glob ou d'objet d'expression régulière : 
my $pm_files = File::Finder->name('*.pm')->in('.');
my $pm_files_too = File::Finder->name(qr/pm$/)->in('.');
perm(PERMISSION)
Comme le "-perm" de find. Le signe "-" signifie "tous ces bits". Le signe "+" signifie "n'importe lequel de ces bits". La valeur est dés-octalisée si un 0 préfixe est présent, ce qui est probablement seulement si elle est passée sous forme de chaîne. 
my $files = File::Finder->type('f');
# trouve les fichiers qui ont exactement le mode 644
my $files_644 = $files->perm(0644);
# trouve les fichiers qui sont au moins exécutables par tous :
my $files_world_exec = $files->perm("-1");
# trouve les fichiers qui ont un bit d'exécution défini :
my $files_exec = $files->perm("+0111");
type(TYPE)
Comme le "-type" de find. Tous les types Perl natifs sont supportés. Notez que "s" est un socket, correspondant à "-S" de Perl, pour être cohérent avec find. Retourne vrai ou faux, comme approprié.
print
Imprime le nom complet sur "STDOUT", suivi d'un saut de ligne. Retourne vrai.
print0
Imprime le nom complet sur "STDOUT", suivi d'un caractère NUL. Retourne vrai.
fstype
Pas encore implémenté.
user(NOM_UTILISATEUR|UID)
Vrai si le propriétaire est NOM_UTILISATEUR ou UID.
group(NOM_GROUPE|GID)
Vrai si le groupe est NOM_GROUPE ou GID.
nouser
Vrai si l'entrée n'appartient à aucun utilisateur connu.
nogroup
Vrai si l'entrée n'appartient à aucun groupe connu.
links( +/- N )
Comme "-links N" de find. Le plus préfixe signifie "plus que", le moins signifie "moins que".
inum( +/- N )
Vrai si le numéro d'inode correspond à la qualification.
size( +/- N [c/k])
Vrai si la taille du fichier correspond à la qualification. Par défaut, N est en blocs de demi-Ko. Ajoutez un "k" à la fin du nombre pour indiquer des blocs de 1 Ko, ou un "c" pour indiquer des caractères (octets).
atime( +/- N )
Vrai si le temps d'accès (en jours) correspond à la qualification.
mtime( +/- N )
Vrai si le temps de modification (en jours) correspond à la qualification.
ctime( +/- N )
Vrai si le temps de changement d'inode (en jours) correspond à la qualification.
exec(@COMMANDE)
Forks le processus enfant via system(). Toute apparition de "{}" dans un argument est remplacée par le nom de fichier courant. Retourne vrai si le statut de sortie de l'enfant est 0. La liste est passée directement à "system", donc s'il s'agit d'un argument unique, il peut contenir la syntaxe de "/bin/sh". Sinon, c'est une commande pré-analysée qui doit se trouver dans le PATH.

Notez que je n'ai pas réussi à trouver comment manipuler le répertoire courant facilement, j'utilise donc $_ ici au lieu de "File::Find::name", plus traditionnel. Cela fonctionne toujours, car nous sommes toujours `chdir` dans le répertoire, mais cela semble étrange lors d'un traçage. Déclenchez "no_chdir" dans "find" si vous souhaitez un chemin complet find traditionnel.

my $f = File::Finder->exec('ls', '-ldg', '{}');
find({ no_chdir => 1, wanted => $f }, @starting_dirs);

Oui, il me serait trivial d'ajouter une méthode no_chdir. Bientôt.

ok(@COMMANDE)

File::Finder::Steps(3pm) - Perl

NAME

File::Finder::Steps - custom find methods

SYNOPSIS

  use File::Finder;
  my $finder = File::Finder->new;
  $finder->type('f')->size('+10k')->exec('rm -f %s');
  $finder->in('/tmp')->ls->depth->exec('cpio -dump /backup/%Y%m%d');
  my @results = $finder->in('/some/dir');

DESCRIPTION

This class provides a set of methods that can be used to build complex directory traversal predicates.

exec(CMD)
Like find's "-exec", but prompts for confirmation. If the command fails, or the response wasn't yes, returns false, otherwise true.
exec_yes(CMD)
Like "exec", but displays the command line first, and waits for a response. If the response begins with "y" or "Y", runs the command. If the command fails, or the response wasn't yes, returns false, otherwise true.
prune
Sets $File::Find::prune, and returns true.
xdev
Not yet implemented.
newer
Not yet implemented.
eval(CODEREF)
Ah yes, the master escape, with extra benefits. Give it a coderef, and it evaluates that code at the proper time. The return value is noted for true/false and used accordingly. 
my $blaster = File::Finder->atime("+30")->eval(sub { unlink });

But wait, there's more. If the parameter is an object that responds to "as_wanted", that method is automatically called, hoping for a coderef return. This neat feature allows subroutines to be created and nested:

my $old = File::Finder->atime("+30");
my $big = File::Finder->size("+100");
my $old_or_big = File::Finder->eval($old)->or->eval($big);
my $killer = File::Finder->eval(sub { unlink });
my $kill_old_or_big = File::Finder->eval($old_or_big)->ls->eval($killer);
$kill_old_or_big->in('/tmp');

Almost too cool for words.

depth
Like find's "-depth". Sets a flag for "as_options", and returns true.
ls
Like find's "-ls". Performs a "ls -dils" on the entry to "STDOUT" (without forking), and returns true.
tar
Not yet implemented.
[n]cpio
Not yet implemented.
ffr($ffr_object)
Incorporate a "File::Find::Rule" object as a step. Note that this must be a rule object, and not a result, so don't call or pass "in". For example, using "File::Find::Rule::ImageSize" to define a predicate for image files that are bigger than a megapixel in my friends folder, I get: 
require File::Finder;
require File::Find::Rule;
require File::Find::Rule::ImageSize;
my $ffr = File::Find::Rule->file->image_x('>1000')->image_y('>1000');
my @big_friends = File::Finder->ffr($ffr)
  ->in("/Users/merlyn/Pictures/Sorted/Friends");
contains(pattern)
True if the file contains "pattern" (either a literal string treated as a regex, or a true regex object). 
my $plugh_files = File::Finder->type('f')->contains(qr/plugh/);

Searching is performed on a line-by-line basis, respecting the current value of $/.

EXTENDING

A step consists of a compile-time and a run-time component.

During the creation of a "File::Finder" object, step methods are called as if they were methods against the slowly-growing "File::Finder" instance, including any additional parameters as in a normal method call. The step is expected to return a coderef (possibly a closure) to be executed at run-time.

When a "File::Finder" object is being evaluated as the "File::Find" "wanted" routine, the collected coderefs are evaluated in sequence, again as method calls against the "File::Finder" object. No additional parameters are passed. However, the normal "wanted" values are available, such as $_, $File::Find::name, and so on. The "_" pseudo-handle has been set properly, so you can safely use "-X" filetests and "stat" against the pseudo-handle. The routine is expected to return a true/false value, which becomes the value of the step.

Although a "File::Finder" object is passed both to the compile-time invocation and the resulting run-time invocation, only the "options" self-hash element is properly duplicated through the cloning process. Do not be tempted to add additional self-hash elements without overriding "File::Finder"'s "_clone". Instead, pass values from the compile-time phase to the run-time phase using closure variables, as shown in the synopsis.

For simplicity, you can also just mix-in your methods to the existing "File::Finder::Steps" class, rather than subclassing both classes as shown above. However, this may result in conflicting implementations of a given step name, so beware.
