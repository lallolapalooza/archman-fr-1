DESCRIPTIO

N

firewall-cmd est le client en ligne de commande du démon firewalld. Il fournit une interface pour gérer les configurations d'exécution et

permanentes.

La configuration d'exécution dans firewalld est séparée de la co

nfiguration permanente. Cela signifie que des modifications peuvent
être apportées dans la configuration d'exécution ou permanente.

OPTION

S

Les options de séquence sont les options qui peuvent être spécifiées plusieurs fois, le code de sortie est 0 s'il y a au moins un élément qui a réussi. Les ALREADY_ENABLED (11), NOT_ENABLED (12) et aussi ZONE_ALREADY_SET (16) erreurs sont traitées comme des succès. S'il y a des problèmes lors de l'analyse des éléments, ceux-ci sont traités comme des avertissements et ne changeront pas le résultat tant qu'il y a un élément réussi. Sans aucun élément réussi, le code de sortie dépendra des codes d'erreur. S'il y a exactement un code d'erreur, celui-ci est utilisé. S'il y en a plus d'un alors UNKNOWN_ERROR (254) sera

utilisé.

Options

d'état

--stat

e
Vérifie si le démon firewalld est actif (c'est-à-dire en cours d'exécution). Retourne un code de sortie 0 s'il est actif, RUNNING_BUT_FAILED si une erreur s'est produite au démarrage, NOT_RUNNING sinon. Voir la section intitulée « CODES DE SORTIE ». Cela affichera également l'état sur STDOUT
.

--reloa

d
Recharge les règles du pare-feu et conserve les informations d'état. La configuration permanente actuelle deviendra la nouvelle configuration d'exécution, c'est-à-dire que toutes les modifications faites uniquement en mode exécution jusqu'au rechargement seront perdues avec le rechargement si elles n'étaient pas aussi dans la configuration permanente.

Remarque : Si FlushAllOnReload=no, les modifications d'exécution appliquées via l'interface directe ne sont pas affectées et resteront donc en place jusqu'à ce que le démon firewalld soit complètement redémarré. Pour FlushAllOnReload, voir firewalld

.conf
(5).

--complete-reloa

d
Recharge complètement le pare-feu, y compris les modules du noyau netfilter. Cela terminera très probablement les connexions actives, car les informations d'état sont perdues. Cette option ne devrait être utilisée qu'en cas de problèmes graves avec le pare-feu. Par exemple, s'il y a des problèmes d'informations d'état pour lesquels aucune connexion ne peut être établie avec des règles de pare-feu correctes.

Remarque : Si FlushAllOnReload=no, les modifications d'exécution appliquées via l'interface directe ne sont pas affectées et resteront donc en place jusqu'à ce que le démon firewalld soit complètement redémarré. Pour FlushAllOnReload, voir firewalld

.conf
(5).

--runtime-to-permanen

t
Enregistre la configuration d'exécution active et écrase la configuration permanente avec celle-ci. Le principe de fonctionnement est le suivant : lorsque vous configurez firewalld, vous ne faites que des modifications d'exécution et une fois que vous êtes satisfait de la configuration et que vous avez vérifié qu'elle fonctionne comme vous le souhaitez, vous enregistrez la configuration sur le
disque.

--permanen

t
L'option permanente --permanent peut être utilisée pour définir des options de manière permanente. Ces modifications ne prennent pas effet immédiatement, seulement après le redémarrage/rechargement du service ou le redémarrage du système. Si vous souhaitez apporter une modification dans les configurations d'exécution et permanente, utilisez le même appel avec et sans l'option --permanent

[--permanent] [--zone=zone] [--permanent] [--policy=policy] --add-service=service [--timeout=timeval

]
Ajouter un service. Cette option peut être spécifiée plusieurs fois. Si un délai d'expiration est fourni, la règle sera active pendant la durée spécifiée et sera automatiquement supprimée par la suite. timeval est soit un nombre (de secondes), soit un nombre suivi de l'un des caractères s (secondes), m (minutes), h (heures), par exemple 20m ou 1h.

Le service est l'un des services fournis par firewalld. Pour obtenir une liste des services pris en charge, utilisez firewall-cmd --get-

services.

L'option --timeout n'est pas combinable avec l'option --permanent

Remarque : Certains services définissent des assistants de suivi de connexion. Les assistants qui peuvent fonctionner en mode client (par exemple tftp) doivent être ajoutés à une politique sortante plutôt qu'à une zone pour prendre effet pour les clients. Sinon, l'assistant ne sera pas appliqué au trafic sortant. Le trafic associé, tel que défini par l'assistant de suivi de connexion, sur le chemin de retour (entrée) sera autorisé par les règles du pare-feu à

état.

Exemple de politique sortante pour les assistants de suivi de connexion

: 
# firewall-cmd --permanent --new-policy clientConntrack
# firewall-cm
d --permanent --policy clientConntrack --add-ingress-zone HOST # fire
wall-cmd --permanent --policy clientConntrack --add-egress-zone ANY #
firewall-cmd --permanent --policy clientConntrack --add-service tftp

Options directes

OBSOLÈTE

L'interface directe a été dépréciée. Elle sera supprimée dans une future version. Elle est remplacée par les politiques, voir firewalld.policies(5).

Les options directes donnent un accès plus direct au pare-feu. Ces options exigent que l'utilisateur connaisse les concepts de base d'iptables, c'est-à-dire le tableau (filter/mangle/nat/...), la chaîne (INPUT/OUTPUT/FORWARD/...), les commandes (-A/-D/-I/...), les paramètres (-p/-s/-d/-j/...) et les cibles (ACCEPT/DROP/REJECT/...).

Les options directes ne doivent être utilisées qu'en dernier recours lorsqu'il n'est pas possible d'utiliser, par exemple, --add-service=service ou --add-rich-rule='règle'.

Attention : le comportement des règles directes diffère selon la valeur de FirewallBackend. Voir CAVEATS dans firewalld.direct(5).

Le premier argument de chaque option doit être ipv4 ou ipv6 ou eb. Avec ipv4, ce sera pour IPv4 (iptables(8)), avec ipv6 pour IPv6 (ip6tables(8)) et avec eb pour les ponts Ethernet (ebtables(8)).

[--permanent] --direct --get-all-chains

Obtient toutes les chaînes ajoutées à tous les tableaux. Cette option ne concerne que les chaînes précédemment ajoutées avec --direct --add-chain.

[--permanent] --direct --get-chains { ipv4 | ipv6 | eb } tableau

Obtient toutes les chaînes ajoutées au tableau tableau sous la forme d'une liste séparée par des espaces. Cette option ne concerne que les chaînes précédemment ajoutées avec --direct --add-chain.

[--permanent] --direct --add-chain { ipv4 | ipv6 | eb } tableau chaîne

Ajoute une nouvelle chaîne nommée chaîne au tableau tableau. Assurez-vous qu'il n'existe aucune autre chaîne portant ce nom.

Il existe déjà des chaînes de base à utiliser avec les options directes, par exemple la chaîne INPUT_direct (voir la sortie de iptables-save | grep direct pour toutes). Ces chaînes sont appelées avant les chaînes des zones, c'est-à-dire que chaque règle placée dans INPUT_direct sera vérifiée avant les règles des zones.

[--permanent] --direct --remove-chain { ipv4 | ipv6 | eb } tableau chaîne

[--permanent] --direct --add-rule { ipv4 | ipv6 | eb } tableau chaîne priorité args

Ajoute une règle avec les arguments args à la chaîne chaîne dans le tableau tableau avec la priorité priorité.

La priorité est utilisée pour ordonner les règles. Une priorité de 0 signifie que la règle est ajoutée en haut de la chaîne. Plus la priorité est élevée, plus la règle sera ajoutée bas. Les règles ayant la même priorité sont au même niveau et l'ordre de ces règles n'est pas fixe et peut changer. Si vous voulez vous assurer qu'une règle sera ajoutée après une autre, utilisez une faible priorité pour la première et une priorité plus élevée pour la suivante.
