DESCRIPTIO

N

Les opérations RMA (accès à la mémoire distante) sont utilisées pour transférer des données directement entre un tampon de données local et un tampon de données distant. Les transferts RMA se produisent au niveau de l'octet, et aucune limite de message n'est

maintenue.

Les fonctions d'écriture – fi_write, fi_writev, fi_writemsg, fi_inject_write et fi_writedata – sont utilisées pour transmettre des données vers un tampon de mémoire distant. La principale différence entre les fonctions d'écriture réside dans le nombre et le type de paramètres qu'elles acceptent en entrée. Sinon, elles effectuent la même fonction

générale.

Les fonctions de lecture – fi_read, fi_readv et fi_readmsg – sont utilisées pour transférer des données depuis une région de mémoire distante vers un ou plusieurs tampons de données locaux. Comme pour les opérations d'écriture, les opérations de lecture fonctionnent de manière asynchrone. Les utilisateurs ne doivent pas toucher aux tampons de données publiés jusqu'à ce que l'opération de lecture soit

terminée.

Les opérations RMA terminées sont signalées à l'utilisateur via une ou plusieurs files d'attente de complétion associées au point de terminaison. Les utilisateurs fournissent un contexte qui est associé à chaque opération, et qui est retourné à l'utilisateur en tant que partie de la complétion. Voir fi_cq pour les détails des événements de

complétion.

Par défaut, le point de terminaison distant ne génère pas d'événement ni ne notifie l'utilisateur lorsqu'une région de mémoire a été accédée par une lecture ou une écriture RMA. Cependant, des données immédiates peuvent être associées à une opération d'écriture RMA. Les écritures RMA avec données immédiates généreront une entrée de complétion au point de terminaison distant, afin que les données immédiates puissent être

délivrées.

fi_inject_writedata(3) — Libfabric Programmer’s Manual

NAME

fi_inject_writedata, fi_readmsg, fi_writemsg - transfer data with control flags

SYNOPSIS

#include <libfabric/fi_endpoint.h>

ssize_t fi_readmsg(struct fid_ep *ep, const struct fi_msg *msg,
    uint64_t flags);
ssize_t fi_writemsg(struct fid_ep *ep, const struct fi_msg *msg,
    uint64_t flags);
ssize_t fi_inject_writedata(struct fid_ep *ep, const void *buf, size_t len,
    const void *desc, uint64_t flags);

ARGUMENTS

ep
The fabric endpoint to use for the operation.
msg
A pointer to a fi_msg structure containing information about the operation, including send/receive buffers, addresses, and tags.
flags
A set of flags that modify the behavior of the operation.
buf
The buffer containing the data to inject.
len
The length of data in the buffer.
desc
Optional descriptor for the data buffer. Ignored if not used.

DESCRIPTION

The fi_readmsg and fi_writemsg calls are used to initiate non-connected read and write operations, respectively. These calls allow for the specification of various flags that can alter the default data transfer behavior configured with the endpoint.

fi_inject_writedata is a specialized call for writing data. It is intended for small messages that can be injected directly into the fabric without the need for explicit buffer management by the user. This call implicitly sets the FI_INJECT flag and is generally more efficient for small, frequent writes.

FLAGS

The fi_readmsg and fi_writemsg calls allow the user to specify flags which can change the default data transfer operation. Flags specified with fi_readmsg / fi_writemsg override most flags previously configured with the endpoint, except where noted (see fi_endpoint.3). The following list of flags are usable with fi_readmsg and/or fi_writemsg.

FI_REMOTE_CQ_DATA
Applies to fi_writemsg. Indicates that remote CQ data is available and should be sent as part of the request. See fi_getinfo for additional details on FI_REMOTE_CQ_DATA. This flag is implicitly set for fi_writedata and fi_inject_writedata.
FI_COMPLETION
Indicates that a completion entry should be generated for the specified operation. The endpoint must be bound to a completion queue with FI_SELECTIVE_COMPLETION that corresponds to the specified operation, or this flag is ignored.
FI_MORE
Indicates that the user has additional requests that will immediately be posted after the current call returns. Use of this flag may improve performance by enabling the provider to optimize its access to the fabric hardware.
FI_INJECT
Applies to fi_writemsg. Indicates that the outbound data buffer should be returned to user immediately after the write call returns, even if the operation is handled asynchronously. This may require that the underlying provider implementation copy the data into a local buffer and transfer out of that buffer. This flag can only be used with messages smaller than inject_size.
FI_INJECT_COMPLETE
Applies to fi_writemsg. Indicates that a completion should be generated when the source buffer(s) may be reused.
FI_TRANSMIT_COMPLETE
Applies to fi_writemsg. Indicates that a completion should not be generated until the operation has been successfully transmitted and is no longer being tracked by the provider.
FI_DELIVERY_COMPLETE
Applies to fi_writemsg. Indicates that a completion should be generated when the operation has been processed by the destination.
FI_COMMIT_COMPLETE
Applies to fi_writemsg when targeting persistent memory regions. Indicates that a completion should be generated only after the result of the operation has been made durable.
FI_FENCE
Applies to transmits. Indicates that the requested operation, also known as the fenced operation, and any operation posted after the fenced operation will be deferred until all previous operations targeting the same peer endpoint have completed. Operations posted after the fencing will see and/or replace the results of any operations initiated prior to the fenced operation.

The ordering of operations starting at the posting of the fenced operation (inclusive) to the posting of a subsequent fenced operation (exclusive) is controlled by the endpoint’s ordering semantics.

RETURN VALUE

Returns 0 on success. On error, a negative value corresponding to fabric errno is returned. Fabric errno values are defined in rdma/fi_errno.h.

ERRORS

-FI_EAGAIN
See fi_msg(3) for a detailed description of handling FI_EAGAIN.
