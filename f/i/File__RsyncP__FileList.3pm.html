DESCRIPTIO

N

Le module File::RsyncP::FileList est utilisé pour encoder et décoder les listes de fichiers en utilisant le même format que

Rsync.

Le côté émetteur de Rsync crée une liste de tous les fichiers qui vont être envoyés. Cette liste est envoyée au côté récepteur dans un format compact. Chaque côté trie ensuite la liste et supprime les entrées en double. À partir de ce moment, tous les fichiers sont référencés par leur index entier dans la liste de fichiers

triée.

Un nouvel objet de liste de fichiers est créé en appelant File::RsyncP::FileList->new. Un objet peut être utilisé pour décoder ou encoder une liste de fichiers. Il n'existe pas de mécanisme pour réinitialiser l'état d'une liste de fichiers : vous devez créer un nouvel objet chaque fois que vous devez effectuer un nouveau décodage ou

encodage.

La fonction new() prend une référence de hachage d'options, qui correspondent à diverses options de ligne de commande de rsync. Celles-ci doivent correspondre exactement aux arguments du rsync distant, sinon le format de la liste de fichiers ne sera pas compatible et le décodage

échouera. 
$fileList = File::RsyncP::FileList->new({
    preserve_uid        => 1,       # --owner
    preserve_gid        => 1,       # --group
    preserve_links      => 1,       # --links
    preserve_devices    => 1,       # --devices
    preserve_hard_links => 0,       # --hard-links
    always_checksum     => 0,       # --checksum
    remote_version      => 26,      # remote protocol version
})
;

Décodag

e

Les fonctions de décodage prennent un flux d'octets du rsync distant et les convertissent en une structure de données interne. Plutôt que de stocker la liste de fichiers sous forme de liste perl native de hachages (ce qui occupe trop de mémoire pour les grandes listes de fichiers), la même structure de données interne que rsync est utilisée. Les entrées individuelles de la liste de fichiers peuvent être retournées avec la fonction get()

.

Les données de la liste de fichiers lues depuis le rsync distant doivent être passées à la fonction decode(). Les données peuvent être lues et traitées en morceaux de taille arbitraire. La fonction decode() retourne le nombre d'octets réellement traités. Il est de la responsabilité de l'appelant de retirer ce nombre d'octets de l'argument d'entrée, en conservant les octets restants pour le prochain appel à decode(). La fonction decodeDone() retourne vrai lorsque la liste de fichiers est complète. La fonction fatalError() retourne vrai s'il y a eu une erreur irrécupérable lors du

décodage.

La fonction clean() doit être appelée après que le décodage de la liste de fichiers est terminé. La fonction clean() trie la liste de fichiers et supprime les entrées répétées. Sauter cette étape produira des résultats inattendus : puisque les fichiers sont référencés à l'aide d'entiers, chaque côté référencera des fichiers différents si les listes de fichiers ne sont pas triées et purgées de la même manière

exacte.

Une boucle de décodage typique ressemble à

: 
while ( !$fileList->decodeDone && !$fileList->fatalError ) {
    $data .= readMoreDataFromRemoteRsync();
    $bytesDone = $fileList->decode($data);
    $data = substr($data, $bytesDone) if ( $bytesDone > 0 );
}
$fileList->
clean;

Après que clean() a été appelé, le nombre de fichiers dans la liste de fichiers peut être trouvé en appelant count(). Les fichiers peuvent être récupérés en appelant la fonction get(), avec un index de 0 à count()-1

: 
$fileInfo = $fileList->get(5)
;

La fonction get() retourne une référence de hachage avec diverses entrées

: 
name      chemin d'accès du fichier (relatif au répertoire rsync) :
          égal à dirname/basename
basename  nom du fichier, sans le répertoire
dirname   répertoire où se trouve le fichier
sum       somme de contrôle MD4 du fichier (uniquement présent si --checksum est spécifié)
uid       identifiant utilisateur du fichier
gid       identifiant de groupe du fichier
mode      mode du fichier
mtime     heure de modification du fichier
size      longueur du fichier
dev       numéro de périphérique sur lequel se trouve le fichier
inode     inode du fichier
link      contenu du lien si le fichier est un lien symbolique
rdev      numéro de périphérique majeur/mineur si le fichier est un caractère/bloc
spécial

Divers champs n'auront des valeurs valides que si les options correspondantes sont définies (par exemple : uid si preserve_uid est défini, dev et inode si preserve_hard_links est défini, etc.)

.

Par exemple, pour afficher chacun des hachages, vous pourriez faire ceci

: 
use Data::Dumper;
my $count = $fileList->count;
for ( my $i = 0 ; $i < $count ; $i++ ) {
    print("File $i is:\n");
    print Dumper($fileList->get($i));
}

Encodag

e

La fonction encode() est utilisée pour construire une liste de fichiers en préparation de l'encodage et de l'envoi d'une liste de fichiers à un rsync distant. La fonction encode() prend un argument de référence de hachage avec les paramètres pour un fichier. Elle doit être appelée une fois pour chaque fichier. Les noms des paramètres sont les mêmes que ceux retournés par get(

).

Dans cet exemple, les valeurs correspondantes de stat() sont montrées

: 
$fileList->encode({
        name  => $filePath,
        dev   => $stat[0],
        inode => $stat[1],
        mode  => $stat[2],
        uid   => $stat[4],
        gid   => $stat[5],
        rdev  => $stat[6],
        size  => $stat[7],
        mtime => $stat[9],
    })
;

Il n'est pas nécessaire de spécifier basename et dirname ; ceux-ci sont extraits de name. Vous n'avez besoin de spécifier que les paramètres qui correspondent aux options données à new(). Vous pouvez également spécifier sum et link si

nécessaire.

Pour calculer les données de la liste de fichiers encodées, la fonction encodeData() doit être appelée. Elle peut être appelée à chaque fois que encode() est appelée, ou une seule fois à la fin de toutes les appels à encode(). Elle retourne les données encodées qui doivent être envoyées au rsync distant

: 
$data = $fileList->
encodeData;

Il est recommandé que encodeData() soit appelée fréquemment pour éviter la nécessité d'allouer de grands tampons internes pour contenir la liste de fichiers entière encodée. Puisque encodeData() ne sait pas quand le dernier fichier a été encodé, il est de la responsabilité de l'appelant d'ajouter l'octet nul final (par exemple : pack("C", 0)) aux données pour indiquer la fin des données de la liste de

fichiers.

Après que toutes les entrées de la liste de fichiers ont été traitées, vous devriez appeler clean()

: 
$fileList->
clean;

Cela garantit que chaque côté (

émetteur/récepteur) a des listes
de fichiers triées identiques.

Fonctions

utilitaires

La fonction count() retourne le nombre total de fichiers dans la liste de fichiers interne (soit décodée, soit encodée)

.

La fonction fatalError() retourne vrai si une erreur fatale s'est produite lors du d

écodage des fichiers. Elle doit être appe
lée dans la boucle de décodage pour s'as
surer qu'aucune erreur ne s'est produite.
