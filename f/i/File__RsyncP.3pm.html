DESCRIPTIO

N

File::RsyncP est une implémentation Perl d'un client Rsync. Elle est compatible avec Rsync 2.5.5 - 2.6.3 (versions de protocole 26-28). Elle peut envoyer ou recevoir des fichiers, soit en exécutant rsync sur la machine distante, soit en se connectant à un démon rsyncd sur la machine

distante.

Quelle est l'utilité de File::RsyncP ? Le but principal est que File::RsyncP sépare toute l'E/S du système de fichiers dans un module distinct, qui peut être remplacé par n'importe quel module de votre propre conception. Cela permet de développer avec une relative facilité des interfaces rsync vers des types de données non basés sur le système de fichiers (par exemple : des bases de données)

.

File::RsyncP a été écrit initialement pour fournir une interface Rsync pour BackupPC, http://backuppc.sourceforge.net. Voir BackupPC pour des exemples de

programmation.

File::RsyncP ne fournit pas encore d'interface en ligne de commande qui imite Rsync natif. À la place, il fournit une API qui rend possible l'écriture de scripts simples qui communiquent avec rsync ou

rsyncd.

Le module File::RsyncP::FileIO contient les fonctions d'accès par défaut au système de fichiers. File::RsyncP::FileIO peut être sous-classé ou remplacé par un module personnalisé pour fournir l'accès à des types de données non basés sur le système de

fichiers.

Pour

commencer

D'abord quelques informations de contexte. Lorsque vous exécutez rsync, il analyse ses arguments en ligne de commande, puis il se connecte soit à un démon rsyncd distant, soit exécute un rsync sur la machine distante via ssh ou rsh. À ce stade, il y a deux processus rsync : celui que vous avez invoqué et celui sur la machine distante. Celui sur la machine locale est appelé le client, et celui sur la machine distante est le serveur. Un côté (soit le client, soit le serveur) enverra des fichiers et l'autre les recevra. Le rsync émetteur génère une liste de fichiers et l'envoie au côté récepteur. Le rsync récepteur créera un processus

enfant.

File::RsyncP n'a pas (encore) de script en ligne de commande qui imite le traitement de démarrage de rsync. Considérez File::RsyncP comme un niveau en dessous du rsync en ligne de commande. File::RsyncP implémente le côté client de la connexion, et File::RsyncP sait comment exécuter le côté distant (par exemple, via rsh ou ssh) ou se connecter à un démon rsyncd distant. File::RsyncP ajoute automatiquement les options internes --server et --sender (si nécessaire) aux options passées au rsync

distant.

Pour initier toute session rsync, la fonction File::RsyncP->new devrait être appelée. Elle prend une référence de hachage de paramètres

Communication avec un démon Rsync

distant

File::RsyncP peut se connecter à un démon Rsync distant en utilisant cette séquence de fonctions

:
serverConnect(host,
port)
Se connecte au démon Rsync sur l'hôte (chaîne host) et le port (entier port) donnés. L'argument port est optionnel et vaut par défaut 873. En cas d'erreur, serverConnect retourne un message d'erreur sous forme de chaîne. En cas de succès, elle retourne
undef.
serverService(module, authUser, authPasswd,
authRequired)
Spécifie quel module utiliser (un « module » est le nom symbolique qui apparaît à l'intérieur de "[...]" dans /etc/rsyncd.conf), les identifiants de l'utilisateur (authUser et authPasswd) et si l'autorisation est obligatoire (authRequired). Si défini à une valeur non nulle, authRequired garantit que le démon Rsync distant exige une authentification. Si nécessaire, cela permet de s'assurer que vous ne vous connectez pas à un démon Rsync non sécurisé. Les arguments d'auth sont optionnels si le module rsyncd sélectionné n'exige pas d'authentification.

Consultez la page de manuel rsyncd.conf pour plus d'informations. Par exemple, si un hôte appelé navajo avait un /etc/rsyncd.conf contenant ces

lignes : 
[test]
        path = /data/test
        comment = test module
        auth users = craig, celia
        secrets file = /etc/rsyncd.

craig:
xxx

0);

LIMITATION

S

La version initiale de File::RsyncP (0.10) présente un certain nombre de limitations

:
  • File::RsyncP n'implémente qu'un sous-ensemble modeste des options et fonctionnalités de Rsync. En particulier, à partir de la version 0.10, seules ces options sont prises en charge : 
    --numeric-ids
--perms|-p
--owner|-o
--group|-g
--devices|D
--links|-l
--ignore-times|I
--block-size=i
--verbose|-v
--recursive|-r
    --relative|-R

    Les liens physiques (hardlinks) ne sont actuellement pas pris en charge.

    Les autres options qui n'affectent que le côté distant fonctionneront
    • correctement car elles sont transmises au Rsync distant inchangées.
  • De plus, la sémantique de --relative n'est pas implémentée pour correspondre à rsync, et le comportement du "/" final de rsync (signifiant le contenu du répertoire, et non le répertoire lui-même) n'est pas implémenté dans File::
    • RsyncP.
  • File::RsyncP ne fournit pas encore d'interface en ligne de commande qui imite Rsync
    • natif.
  • File::RsyncP pourrait fonctionner avec des versions légèrement antérieures de Rsync mais cela n'a pas été testé. Cela ne fonctionnera certainement pas avec des versions anciennes de
    • Rsync.
  • File::RsyncP ne calcule pas les différences de fichier (c'est-à-dire qu'il se comporte comme si --whole-file était spécifié) et n'implémente pas les options d'exclusion ou d'inclusion lors de l'envoi de fichiers. File::RsyncP gère les différences de fichier et les options d'exclusion et d'inclusion lors de la réception de
    • fichiers.
  • File::RsyncP n'implémente pas encore les fonctionnalités côté serveur
    • (agir comme l'extrémité distante d'une connexion ou un démon). Comme
le protocole est relativement symétrique, cela n'est pas difficil
e à ajouter, cela devrait donc apparaître dans une version future.
