DESCRIPTIO

N

Les fonctions de gestion des connexions sont utilisées pour connecter un point de terminaison orienté connexion (FI_EP_MSG) à un pair en

écoute.

fi_liste

n

L'appel fi_listen indique que le point de terminaison spécifié doit passer à l'état de connexion passif, lui permettant d'accepter les demandes de connexion entrantes. Les demandes de connexion adressées à un point de terminaiso

n en écoute sont signalées de manière asynchrone à l'utilisateur via une file d'événements CM liée, en utilisant le type d'événement FI_CONNREQ. Le nombre de demandes de connexion en attente pouvant être mises en file d'attente
sur un point de terminaison est limité par le paramètre backlog du point de terminaison en écoute. Le backlog est initialisé en fonction des valeurs de configuration administratives, mais peut être ajusté via l'appel fi_control.

fi_connec

t

L'appel fi_connect initie une demande de connexion sur un point de terminais

on orienté connexion vers l'adresse de destination. fi_connect ne peut être a
ppelé qu'une seule fois sur un point de terminaison pendant sa durée de vie.

fi_accept /

fi_reject

Les appels fi_accept et fi_reject sont utilisés sur le côté passif (en écoute) d'une connexion pour accepter ou rejeter une demande de connexion, respectivement. Pour accepter une connexion, l'application en écoute attend d'abord un événement de demande de connexion (FI_CONNREQ). Après avoir reçu un tel événement, l'application alloue un nouveau point de terminaison pour accepter la connexion. Ce point de terminaison doit être alloué à l'aide d'une structure fi_info faisant référence au handle de cet événement FI_CONNREQ. fi_accept est ensuite invoqué avec le point de terminaison nouvellement alloué. Si l'application en écoute souhaite rejeter une demande de connexion, elle appelle fi_reject avec le point de terminaison en écoute et une référence à la demande de

connexion.

Une demande de connexion acceptée avec succès entraînera le fait que le point de terminaison actif (en cours de connexion) verra un événement FI_CONNECTED sur sa file d'événements associée. Une demande de connexion rejetée ou échouée générera un événement d'erreur. L'entrée d'erreur fournira des détails supplémentaires décrivant la raison de la tentative

échouée.

Un événement FI_CONNECTED sera également généré sur le côté passif pour le point de terminaison acceptant une fois la connexion correctement établie. Le fid de l'événement FI_CONNECTED s

era celui du point de terminaison passé à fi_accept, et non celui du point de terminaison passif en écoute. Les transferts de données sortants ne peuvent pas être initiés sur un point
de terminaison orienté connexion tant qu'un événement FI_CONNECTED n'a pas été généré. Cependant, les tampons de réception peuvent être associés à un point de terminaison à tout moment.

fi_shutdow

n

L'appel fi_shutdown est utilisé pour déconnecter proprement un point de terminaison de son pair. Le paramètre flags est réservé et doit être

0.

Les opérations en attente soumises au point de terminaison au moment où fi_shutdown est appelé seront annulées ou abandonnées. La notification des opérations annulées sera rapportée par le fournisseur à la ou les files de complétion correspondantes. Les opérations abandonnées seront silencieusement supprimées, sans génération de complétions. Le choix d'annuler plutôt que d'abandonner les opérations dépend du fournisseur. Cependant, toutes les complétions annulées seront écrites avant le retour de

fi_shutdown.

Lorsqu'il est appelé, fi_shutdown n'affecte pas les complétions déjà écrites dans une file de complétion. Toutes les complétions en file d'attente associées aux opérations asynchrones soumises au point de terminaison peuvent toujours être récupérées depuis la ou les files de complétion correspondantes après qu'un point de terminaison a été

fermé.

Un événement FI_SHUTDOWN sera généré pour un point de terminaison lorsque le pair distant émet une déconnexion via fi_shutdown ou ferme brutalemen

t le point de terminaison. Notez que dans le cas d'une fermeture brutale, un événement FI_SHUTDOWN ne sera généré que si le système du pair est ac
cessible et si un service ou un agent noyau sur le système du pair peut notifier le point de terminaison local que la connexion a été interrompue.

fi_clos

e

Fi_close est utilisé pour dissocier un point de terminaison d'un groupe de multidif

fusion et fermer toutes les ressources associées au groupe. Fi_close doit être appe
lé sur tous les groupes de multidiffusion auxquels un point de terminaison rejoint.

fi_setnam

e

L'appel fi_setname peut être utilisé pour modifier ou attribuer l'adresse du point de terminaison local. Il est conceptuellement similaire à l'opération de liaison de socket. Un point de terminaison peut se voir attribuer une adresse lors de sa création, via la structure fi_info. L'appel fi_setname permet de créer un point de terminaison sans qu'il soit associé à un service spécifique (par exemple, un numéro de port) et/ou à une adresse de nœud (par exemple, réseau), l'adressage étant attribué de manière dynamique. Le format des données d'adressage spécifiées doit correspondre à celui spécifié via la structure fi_info lors de la création du point de

terminaison.

Si aucune adresse de service n'est spécifiée et qu'aucune adresse de service n'a encore été attribuée au point de terminaison, alors le fournisseur allouera une adresse de service et

l'attribuera au point de terminaison. Si une adresse de nœud ou de service est spécifiée, alors, lors de l'achèvement réussi de fi_setname, le point de terminaison se verra attri
buer l'adressage donné. Si une adresse ne peut pas être attribuée, ou si l'adresse du point de terminaison ne peut pas être modifiée, un code d'erreur de fabric approprié est renvoyé.

fi_getname /

fi_getpeer

Les appels fi_getname et fi_getpeer peuvent être utilisés pour récupérer respectivement l'adresse du point de terminaison local ou du pair. En entrée, le paramètre addrlen doit indiquer la taille du tampon addr. Si l'adresse réelle est plus grande que ce qui peut tenir dans le tampon, elle sera tronquée et -FI_ETOOSMALL sera renvoyéfi_getname n'est pas garanti de renvoyer une adresse source valide tant que le point de terminaison spécifié n'a pas été activé ou

n'a

Par exemple, si le point de terminaison a été configuré pour à la fois envoyer et recevoir des données, alors le point de terminaison pourra initier et recevoir des transferts vers et depuis le groupe de diffusion. Le résultat de l'opération de rejoindre sera rapporté à la file d'événements sous la forme d'un événement FI_JOIN_COMPLETE.
