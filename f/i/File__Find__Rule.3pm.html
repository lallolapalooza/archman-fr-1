File::Find::Rule(3) Documentation Perl contribuée par les utilisateurs File::Find::Rule(3)

NOM

File::Find::Rule - Interface alternative à File::Find

SYNOPSIS

use File::Find::Rule;
# trouver tous les sous-répertoires d'un répertoire donné
my @subdirs = File::Find::Rule->directory->in( $directory );
# trouver tous les fichiers .pm dans @INC
my @files = File::Find::Rule->file()
                            ->name( '*.pm' )
                            ->in( @INC );
# idem, mais sans chaînage de méthodes
my $rule =  File::Find::Rule->new;
$rule->file;
$rule->name( '*.pm' );
my @files = $rule->in( @INC );

DESCRIPTION

File::Find::Rule est une interface plus conviviale pour File::Find. Elle vous permet de construire des règles qui spécifient les fichiers et répertoires désirés.

MÉTHODES

"new"
Un constructeur. Vous n'avez pas besoin d'invoquer "new" manuellement, sauf si vous le souhaitez, car chacune des méthodes de création de règles créera automatiquement un objet approprié si elle est appelée comme méthode de classe.

Règles de correspondance

name( @patterns )
Spécifie les noms qui doivent correspondre. Peuvent être des globs ou des expressions rationnelles. 
$set->name( '*.mp3', '*.ogg' ); # mp3 ou oggs
$set->name( qr/\.(mp3|ogg)$/ ); # la même chose sous forme d'expression rationnelle
$set->name( 'foo.bar' );        # juste les éléments nommés foo.bar
Tests -X
Des synonymes sont fournis pour chacun des tests -X. Voir "-X" dans perlfunc pour plus de détails. Aucune de ces méthodes ne prend d'arguments. 
 Test | Méthode               Test |  Méthode
------|-------------        ------|----------------
  -r  |  readable             -R  |  r_readable
  -w  |  writeable            -W  |  r_writeable
  -w  |  writable             -W  |  r_writable
  -x  |  executable           -X  |  r_executable
  -o  |  owned                -O  |  r_owned
      |                           |
  -e  |  exists               -f  |  file
  -z  |  empty                -d  |  directory
  -s  |  nonempty             -l  |  symlink
      |                       -p  |  fifo
  -u  |  setuid               -S  |  socket
  -g  |  setgid               -b  |  block
  -k  |  sticky               -c  |  character
      |                       -t  |  tty
  -M  |  modified                 |
  -A  |  accessed             -T  |  ascii
  -C  |  changed              -B  |  binary

Bien que certains tests soient assez dénués de sens en tant que drapeaux booléens ("modified", "accessed", "changed"), ils ont été inclus par souci d'exhaustivité.

# trouver les fichiers non vides
$rule->file,
     ->nonempty;
Tests stat
Les méthodes suivantes basées sur "stat" sont fournies : "dev", "ino", "mode", "nlink", "uid", "gid", "rdev", "size", "atime", "mtime", "ctime", "blksize", et "blocks". Voir "stat" dans perlfunc pour plus de détails.

Chacune de ces méthodes peut prendre plusieurs cibles, qui suivront la sémantique de Number::Compare.

$rule->size( 7 );         # exactement 7
$rule->size( ">7Ki" );    # plus grand que 7 * 1024 * 1024 octets
$rule->size( ">=7" )
     ->size( "<=90" );    # entre 7 et 90, inclus
$rule->size( 7, 9, 42 );  # 7, 9 ou 42
any( @rules )
or( @rules )
Permet une évaluation booléenne à court-circuit, comme alternative à la nature par défaut de type « et » des règles combinées. "any" et "or" sont interchangeables. 
# trouver les avis, les movs, les éléments de plus de 200M et les fichiers vides
$rule->any( File::Find::Rule->name( '*.avi', '*.mov' ),
            File::Find::Rule->size( '>200M' ),
            File::Find::Rule->file->empty,
          );
none( @rules )
not( @rules )
Négationne une règle. (L'inverse de "any".) "none" et "not" sont interchangeables. 
# fichiers qui ne sont pas sûrs en 8.3
$rule->file
     ->not( $rule->new->name( qr/^[^.]{1,8}(\.[^.]{0,3})?$/ ) );
"prune"
Ne pas parcourir plus loin. Cette règle correspond toujours.
"discard"
Ne pas conserver ce fichier. Cette règle correspond toujours.
"exec( \&subroutine( $shortname, $path, $fullname ) )"
Permet des règles définies par l'utilisateur. Votre sous-routine sera invoquée avec $_ défini au nom court actuel, et avec en paramètres le nom, le chemin dans lequel vous vous trouvez, et le nom de fichier relatif complet.

Renvoyez une valeur vraie si votre règle a correspondu.

# obtenir les éléments avec de longs noms
$rules->exec( sub { length > 20 } );
grep( @specifiers )
Ouvre un fichier et le teste ligne par ligne.

Pour chaque ligne, il évalue chacun des spécificateurs, s'arrêtant au premier qui correspond. Un spécificateur peut être une expression rationnelle ou une sous-routine. La sous-routine sera invoquée avec les mêmes paramètres que une sous-routine ->exec.

Il est possible de fournir un ensemble de spécificateurs négatifs en les enfermant dans des tableaux anonymes. Si un spécificateur négatif correspond, l'itération est interrompue et la clause échoue. Par exemple :

$rule->grep( qr/^#!.*\bperl/, [ sub { 1 } ] );

Est une clause qui passe si la première ligne d'un fichier ressemble à une ligne shebang perl.

maxdepth( $level )
Descendre d'au plus $level (un entier non négatif) niveaux de répertoires sous le point de départ.

Peut être invoqué plusieurs fois par règle, mais seule la valeur la plus récente est utilisée.

mindepth( $level )
Ne pas appliquer de tests à des niveaux inférieurs à $level (un entier non négatif).
extras( \%extras )
Spécifie des valeurs supplémentaires à transmettre à "File::File::find" dans le hachage d'options.

Par exemple, cela vous permet de spécifier le suivi des liens symboliques comme ceci :

my $rule = File::Find::Rule->extras({ follow => 1 });

Peut être invoqué plusieurs fois par règle, mais seule la valeur la plus récente est utilisée.

"relative"
Supprimer la partie initiale de tout chemin trouvé
"canonpath"
Normaliser les chemins trouvés en utilisant "File::Spec-"canonpath>. Cela renverra des chemins avec un séparateur de fichiers natif pour votre système d'exploitation (tel que déterminé par File::Spec),
au lieu du "/"par défaut.

Par exemple, cela renverra "tmp/foobar" sur les systèmes d'exploitation de type Unix et "tmp\foobar" sur Win32.

"not_*"
Version négative de la règle. Un raccourci efficace lié à ! dans l'interface procédurale. 
$foo->not_name('*.pl');
$foo->not( $foo->new->name('*.pl' ) );

Méthodes de requête

in( @directories )
Évalue la règle, renvoie une liste de chemins vers les fichiers et répertoires correspondants.
start( @directories )
Démarre une recherche dans les répertoires spécifiés. Les éléments correspondants peuvent ensuite être interrogés à l'aide de "match". Cela vous permet d'utiliser une règle comme un itérateur. 
my $rule = File::Find::Rule->file->name("*.jpeg")->start( "/web" );
while ( defined ( my $image = $rule->match ) ) {
    ...
}
"match"
Renvoie le fichier suivant qui correspond, faux s'il n'y en a plus.

Extensions

Des modules d'extension sont disponibles sur CPAN dans le namespace File::Find::Rule. Afin d'utiliser ces extensions, utilisez-les directement :

use File::Find::Rule::ImageSize;
use File::Find::Rule::MMagic;
# maintenant vos règles peuvent utiliser les clauses fournies par les
# extensions ImageSize et MMagic

ou, spécifiez que File::Find::Rule doit les charger pour vous :

use File::Find::Rule qw( :ImageSize :MMagic );

Pour des notes sur la mise en œuvre de vos propres extensions, consultez File::Find::Rule::Extending

Autres exemples

Trouver des scripts perl
my $finder = File::Find::Rule->or
 (
  File::Find::Rule->name( '*.pl' ),
  File::Find::Rule->exec(
                         sub {
                             if (open my $fh, $_) {
                                 my $shebang = <$fh>;
                                 close $fh;
                                 return $shebang =~ /^#!.*\bperl/;
                             }
                             return 0;
                         } ),
 );

Basé sur ce message http://use.perl.org/comments.pl?sid=7052&cid=10842

ignorer les répertoires CVS
my $rule = File::Find::Rule->new;
$rule->or($rule->new
               ->directory
               ->name('CVS')
               ->prune
               ->discard,
          $rule->new);

Notez ici l'utilisation d'une règle nulle. Les règles nulles correspondent à tout ce qu'elles voient, de sorte que l'effet est de correspondre (et d'écarter) les répertoires nommés 'CVS' ou de correspondre à tout.

DEUX POUR LE PRIX D'UNE

File::Find::Rule vous donne également une interface procédurale. Celle-ci est documentée dans File::Find::Rule::Procedural

EXPORTS

"find", "rule"

INTERACTION AVEC LE MODE TAINT

Depuis la version 0.32, File::Find::Rule ne capture pas le répertoire de travail courant d'une manière non sûre pour le mode taint. File::Find lui-même effectue encore des opérations que le système taint signalera comme non sécurisées, mais vous pouvez utiliser la fonctionnalité "extras" pour demander à File::Find d'effectuer internement "untaint" sur les chemins de fichiers avec une expression rationnelle comme ceci :

my $rule = File::Find::Rule->extras({ untaint => 1 });

Veuillez consulter la documentation de File::Find pour "untaint", "untaint_pattern", et "untaint_skip" pour plus d'informations.

BUGS

Le code utilise le mot-clé "our" et requiert par conséquent la version 5.6.0 ou plus récente de perl.

Actuellement, il n'est pas possible de supprimer une clause d'un objet règle. Si cela devient un problème significatif, cela sera traité.
