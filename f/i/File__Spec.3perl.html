File::Spec(3perl) Guide de référence du programmeur Perl File::Spec(3perl)

NOM

File::Spec - effectuer des opérations portables sur les noms de fichiers

SYNOPIS

use File::Spec;
my $x = File::Spec->catfile('a', 'b', 'c');

qui renvoie 'a/b/c' sous Unix. Ou :

use File::Spec::Functions;
my $x = catfile('a', 'b', 'c');

DESCRIPTION

Ce module est conçu pour prendre en charge les opérations couramment effectuées sur les spécifications de fichiers (généralement appelées « noms de fichiers », mais à ne pas confondre avec le contenu d'un fichier, ni avec les descripteurs de fichiers de Perl), telles que la concaténation de plusieurs noms de répertoires et de fichiers en un seul chemin, ou la détermination si un chemin est absolu. Il est basé sur du code directement extrait de MakeMaker 5.17, code écrit par Andreas König, Andy Dougherty, Charles Bailey, Ilya Zakharevich, Paul Schinder, et d'autres.

Étant donné que ces fonctions sont différentes pour la plupart des systèmes d'exploitation, chaque ensemble de routines spécifiques au système d'exploitation est disponible dans un module distinct, notamment :

File::Spec::Unix
File::Spec::Mac
File::Spec::OS2
File::Spec::Win32
File::Spec::VMS

Le module approprié pour le système d'exploitation actuel est automatiquement chargé par File::Spec. Comme certains modules (comme VMS) utilisent des installations disponibles uniquement sous ce système d'exploitation, il peut ne pas être possible de charger tous les modules sous tous les systèmes d'exploitation.

Étant donné que File::Spec est orienté objet, les sous-routines ne doivent pas être appelées directement, comme suit :

File::Spec::catfile('a','b');

mais plutôt comme méthodes de classe :

File::Spec->catfile('a','b');

Pour des utilisations simples, File::Spec::Functions fournit des formes fonctionnelles pratiques de ces méthodes.

MÉTHODES

canonpath
Aucune vérification physique sur le système de fichiers, mais un nettoyage logique d'un chemin. 
$cpath = File::Spec->canonpath( $path ) ;

Notez que cela ne *réduit* pas les sections x/../y en y. C'est intentionnel. Si /foo sur votre système est un lien symbolique vers /bar/baz, alors /foo/../quux est en fait /bar/quux, et non /quux comme le donnerait une suppression naïve de ../. Si vous souhaitez effectuer ce type de traitement, vous voudrez probablement utiliser la fonction realpath() de "Cwd" pour parcourir réellement le système de fichiers et nettoyer les chemins de cette manière.

catdir
Concatène deux ou plusieurs noms de répertoires pour former un chemin complet se terminant par un répertoire. Mais supprime la barre oblique finale de la chaîne résultante, car elle n'est pas esthétique, n'est pas nécessaire et perturbe OS/2. Bien sûr, s'il s'agit du répertoire racine, ne supprimez pas la barre oblique finale :-) 
$path = File::Spec->catdir( @directories );
catfile
Concatène un ou plusieurs noms de répertoires et un nom de fichier pour former un chemin complet se terminant par un nom de fichier 
$path = File::Spec->catfile( @directories, $filename );
curdir
Renvoie une représentation textuelle du répertoire courant. 
$curdir = File::Spec->curdir();
devnull
Renvoie une représentation textuelle du périphérique nul. 
$devnull = File::Spec->devnull();
rootdir
Renvoie une représentation textuelle du répertoire racine. 
$rootdir = File::Spec->rootdir();
tmpdir
Renvoie une représentation textuelle du premier répertoire inscriptible parmi une liste de répertoires temporaires possibles. Renvoie le répertoire courant si aucun répertoire temporaire inscriptible n'est trouvé. La liste des répertoires vérifiés dépend de la plateforme ; par exemple, File::Spec::Unix vérifie $ENV{TMPDIR} (sauf si le mode taint est activé) et /tmp. 
$tmpdir = File::Spec->tmpdir();
updir
Renvoie une représentation textuelle du répertoire parent. 
$updir = File::Spec->updir();
no_upwards
Étant donné une liste de fichiers dans un répertoire (provenant par exemple de readdir()), supprime '.' et '..'.

NOTE DE SÉCURITÉ : Ceci ne filtre PAS les chemins contenant '..', comme '../../../../etc/passwd', seulement les correspondances littérales avec '.' et '..'.

@paths = File::Spec->no_upwards( readdir $dirhandle );
case_tolerant
Renvoie une valeur vraie ou fausse indiquant, respectivement, que la casse alphabétique n'est pas ou est significative lors de la comparaison des spécifications de fichiers. Cygwin et Win32 acceptent un argument optionnel de lecteur. 
$is_case_tolerant = File::Spec->case_tolerant();
file_name_is_absolute
Prend en argument un chemin et renvoie vrai s'il s'agit d'un chemin absolu. 
$is_absolute = File::Spec->file_name_is_absolute( $path );

Cela ne consulte pas le système de fichiers local sur Unix, Win32, OS/2 ou Mac OS (Classic). Cela consulte l'environnement de travail pour VMS (voir "file_name_is_absolute" dans File::Spec::VMS).

path
Ne prend aucun argument. Renvoie la variable d'environnement "PATH" (ou l'équivalent de la plateforme locale) sous forme de liste. 
@PATH = File::Spec->path();
join
join est identique à catfile.
splitpath
Sépare un chemin en parties volume, répertoire et nom de fichier. Sur les systèmes sans concept de volume, renvoie '' pour le volume. 
($volume,$directories,$file) =
                   File::Spec->splitpath( $path );
($volume,$directories,$file) =
                   File::Spec->splitpath( $path, $no_file );

Pour les systèmes n'ayant pas de syntaxe différenciant les noms de fichiers des répertoires, suppose que le dernier élément est un chemin, sauf si $no_file est vrai ou si un séparateur final ou /. ou /.. est présent. Sur Unix, cela signifie que $no_file vrai fait renvoyer ( '', $path, '' ).

Le composant répertoire peut être renvoyé avec ou sans une barre oblique finale.

Les résultats peuvent être passés à "catpath()" pour récupérer un chemin équivalent (généralement identique) au chemin d'origine.

splitdir
L'inverse de "catdir". 
@dirs = File::Spec->splitdir( $directories );

$directories doit être uniquement la partie répertoire du chemin sur les systèmes qui ont le concept de volume ou qui ont une syntaxe de chemin qui différencie les fichiers des répertoires.

Contrairement à une simple séparation des répertoires par le séparateur, des noms de répertoires vides ('') peuvent être renvoyés, car ils sont significatifs sur certains systèmes d'exploitation.

catpath()
Prend les parties volume, répertoire et fichier et renvoie un chemin complet. Sous Unix, $volume est ignoré, et le répertoire et le fichier sont concaténés. Une '/' est insérée si nécessaire. Sur d'autres systèmes d'exploitation, $volume est significatif. 
$full_path = File::Spec->catpath( $volume, $directory, $file );
abs2rel
Prend un chemin de destination et un chemin de base optionnel et renvoie un chemin relatif du chemin de base au chemin de destination : 
$rel_path = File::Spec->abs2rel( $path ) ;
$rel_path = File::Spec->abs2rel( $path, $base ) ;

Si $base est absent ou '' alors Cwd::cwd() est utilisé. Si $base est relatif, alors il est converti en forme absolue en utilisant "rel2abs()". Cela signifie qu'il est considéré comme relatif à Cwd::cwd().

rel2abs()
Convertit un chemin relatif en chemin absolu. 
$abs_path = File::Spec->rel2abs( $path ) ;
$abs_path = File::Spec->rel2abs( $path, $base ) ;

Si $base est absent ou '', alors Cwd::cwd() est utilisé. Si $base est relatif, alors il est converti en forme absolue en utilisant "rel2abs()". Cela signifie qu'il est considéré comme relatif à Cwd::cwd().

Sur les systèmes avec le concept de volume, si $path et $base semblent se trouver sur deux volumes différents, nous n'essaierons pas de résoudre les deux chemins, et nous retournerons plutôt simplement $path. Notez que les versions précédentes de ce module ignoraient le volume de $base, ce qui entraînait des résultats erronés une partie du temps.

Sur les systèmes dont la grammaire indique les noms de fichiers, ceci ignore également le nom de fichier $base . Sinon, tous les composants de chemin sont supposés être des répertoires.

Si $path est absolu, il est nettoyé et retourné en utilisant "canonpath".

Aucune vérification n'est effectuée sur le système de fichiers. Sur VMS, il y a interaction avec l'environnement de travail, car les logiques et les macros sont développés.

Basé sur du code écrit par Shigio Yamaguchi.

Pour plus d'informations, veuillez consulter File::Spec::Unix, File::Spec::Mac, File::Spec::OS2, File::Spec::Win32, ou File::Spec::VMS.
