NOM

filefuncs - fournit certaines fonctionnalités liées aux fichiers à gawk

SYNOPSIS

@load "filefuncs"

result = chdir("/some/directory")

result = stat("/some/path", statdata [, follow])

flags = or(FTS_PHYSICAL, ...)
result = fts(pathlist, flags, filedata)

result = statvfs("/some/path", fsdata)

DESCRIPTION

L'extension filefuncs ajoute plusieurs fonctions qui donnent accès à des fonctionnalités liées aux fichiers.

chdir()

La fonction chdir() est un accroche directe à l'appel système chdir(2) pour changer le répertoire courant. Elle renvoie zéro en cas de succès ou une valeur inférieure à zéro en cas d'erreur. Dans ce dernier cas, elle met à jour ERRNO.

stat()

La fonction stat() fournit un accroche à l'appel système stat(2) . Elle renvoie zéro en cas de succès ou une valeur inférieure à zéro en cas d'erreur. Dans ce dernier cas, elle met à jour ERRNO. Par défaut, elle utilise lstat(2). Cependant, si un troisième argument est passé, elle utilise stat(2)à la place.

Dans tous les cas, elle vide le tableau statdata . Lorsque l'appel réussit, stat() remplit le tableau statdata avec les informations récupérées depuis le système de fichiers, comme suit :

statdata["name"]
Le nom du fichier, égal au premier argument passé à stat().
statdata["dev"]
Correspond au champ st_dev dans struct stat.
statdata["ino"]
Correspond au champ st_ino dans struct stat.
statdata["mode"]
Correspond au champ st_mode dans struct stat.
statdata["nlink"]
Correspond au champ st_nlink dans struct stat.
statdata["uid"]
Correspond au champ st_uid dans struct stat.
statdata["gid"]
Correspond au champ st_gid dans struct stat.
statdata["size"]
Correspond au champ st_size dans struct stat.
statdata["atime"]
Correspond au champ st_atime dans struct stat.
statdata["mtime"]
Correspond au champ st_mtime dans struct stat.
statdata["ctime"]
Correspond au champ st_ctime dans struct stat.
statdata["rdev"]
Correspond au champ st_rdev dans struct stat. Cet élément n'est présent que pour les fichiers de périphérique.
statdata["major"]
Correspond au champ st_major dans struct stat. Cet élément n'est présent que pour les fichiers de périphérique.
statdata["minor"]
Correspond au champ st_minor dans struct stat. Cet élément n'est présent que pour les fichiers de périphérique.
statdata["blksize"]
Correspond au champ st_blksize dans struct stat, si ce champ est présent sur votre système. (Il est présent sur tous les systèmes modernes que nous connaissons.)
statdata["pmode"]
Une version lisible par l'humain de la valeur du mode, telle que celle imprimée par ls(1). Par exemple, "-rwxr-xr-x".
statdata["linkval"]
Si le fichier nommé est un lien symbolique, cet élément existera et sa valeur sera la valeur du lien symbolique (vers quoi le lien symbolique pointe).
statdata["type"]
Le type du fichier sous forme de chaîne. L'un de "file", "blockdev", "chardev", "directory", "socket", "fifo", "symlink", "door", ou "unknown". Tous les systèmes ne prennent pas en charge tous les types de fichiers.

fts()

La fonction fts() fournit un accroche à l'ensemble de routines fts(3) pour parcourir les hiérarchies de fichiers. Au lieu de renvoyer des données sur un fichier à la fois dans un flux, elle remplit un tableau multidimensionnel avec des données sur chaque fichier et répertoire rencontré dans les hiérarchies demandées.

Les arguments sont les suivants :

pathlist
Un tableau de noms de fichiers. Les valeurs des éléments sont utilisées ; les valeurs d'index sont ignorées.
flags
Il doit s'agir du OU bit à bit d'un ou plusieurs des valeurs de drapeau prédéfinies suivantes. Au moins l'un de FTS_LOGICAL ou FTS_PHYSICAL doit être fourni ; sinon fts() renvoie une valeur d'erreur et définit ERRNO.
FTS_LOGICAL
Effectue un parcours de fichiers « logique », où les informations renvoyées pour un lien symbolique se rapportent au fichier lié, et non au lien symbolique lui-même. Ce drapeau est mutuellement exclusif avec FTS_PHYSICAL.
FTS_PHYSICAL
Effectue un parcours de fichiers « physique », où les informations renvoyées pour un lien symbolique se rapportent au lien symbolique lui-même. Ce drapeau est mutuellement exclusif avec FTS_LOGICAL.
FTS_NOCHDIR
Par optimisation de performance, les routines fts(3) changent de répertoire lorsqu'elles parcourent une hiérarchie de fichiers. Ce drapeau désactive cette optimisation.
FTS_COMFOLLOW
Suit immédiatement un lien symbolique nommé dans pathlist, que FTS_LOGICAL soit défini ou non.
FTS_SEEDOT
Par défaut, les routines fts(3) ne renvoient pas d'entrées pour « . » et « .. ». Cette option fait que les entrées pour « .. » sont également incluses. (L'extension AWK inclut toujours une entrée pour « . », voir ci-dessous.)
FTS_XDEV
Lors d'un parcours, ne pas traverser vers un système de fichiers monté différent.
FTS_SKIP
Lorsqu'il est défini, empêche la descente dans les répertoires de premier niveau.
filedata
Le tableau filedata est d'abord vidé. Ensuite, fts() crée un élément dans filedata pour chaque élément dans pathlist. L'index est le nom du répertoire ou du fichier donné dans pathlist. L'élément pour cet index est lui-même un tableau. Il y a deux cas.
Le chemin est un fichier.
Dans ce cas, le tableau contient deux ou trois éléments :
"path"
Le chemin complet filefuncs(3am)

NAME

filefuncs – file traversals and information

SYNOPSIS

function fts(pathlist, flags)
function statvfs(fsdata)

DESCRIPTION

This extension provides AWK functions for performing file traversals and retrieving file and filesystem information.

The fts() function takes an array, pathlist, containing the list of files and directories to process. The optional flags argument is a bitmask that controls the behavior of the traversal. The traversal proceeds recursively through directories.

The pathlist array must be an associative array. The keys of the array are the file or directory names. The values are the information returned about each file or directory. The traversal starts from the root(s) specified in the pathlist.

The flags argument is an integer where individual bits control the behavior of fts(). The following flags are recognized:

FTS_COMFOLLOW
Do not follow symbolic links.
FTS_LOGICAL
Traverse the file hierarchy according to the interpretation of the `name' field. If any component of the path is a symbolic link, it is treated as a file and its information is returned. If FTS_LOGICAL is not specified, fts() will follow symbolic links.
FTS_NOCHDIR
Do not change directories. This is the default.
FTS_NOSTAT
Do not obtain file status. This is useful for walking the hierarchy quickly.
FTS_PHYSICAL
Traverse the file hierarchy physicaly. If any component of the path is a symbolic link, it is followed.
FTS_ROOT
For each element in the pathlist array, this flag causes fts() to return information about the entry itself, prior to descending into it if it is a directory. This flag is implicitly set if the pathlist contains directories.
FTS_SEEDOT
Include dot-files (files starting with a period) in the output. Normally, fts() skips these files.
FTS_XDEV
Do not descend directories on other filesystems.

The fts() function returns an associative array containing information about the file or directory. The array contains the following elements:

"path"
The full path to the file or directory.
"stat"
This element is itself an array, containing the same information as provided by the stat() function described earlier for its statdata argument. The element may not be present if stat(2) for the file failed.
"error"
If some kind of error was encountered, the array will also contain an element named "error", which is a string describing the error.
The path is a file.
In this case, the array contains two or three elements: "path", "stat", and optionally "error". The "path" element is the file's name, with the appropriate path prepended if the file was not found in the current directory. The "stat" element is the information returned by stat(2). The "error" element is present only if there was an error.
The path is a directory.
In this case, the array contains one element for each entry in the directory. If an entry is a file, that element is as for files, just described. If the entry is a directory, that element is (recursively), an array describing the subdirectory. If FTS_SEEDOT was provided in the flags, then there will also be an element named "..". This element will be an array containing the data as provided by stat().

In addition, there will be an element whose index is ".". This element is an array containing the same two or three elements as for a file: "path", "stat", and "error".

The fts() function returns 0 if there were no errors. Otherwise it returns -1.

statvfs()

The statvfs() function provides a hook into the statvfs(2) system call on systems that supply this system call. It returns zero upon success or less than zero upon error. In the latter case it updates ERRNO.

When the call is successful, statvfs() fills the fsdata array with information retrieved about the filesystem, as follows:

fsdata["bsize"]
Corresponds to the bsize member in the struct statvfs.
fsdata["frsize"]
Corresponds to the f_frsize member in the struct statvfs.
fsdata["blocks"]
Corresponds to the f_blocks member in the struct statvfs.
fsdata["bfree"]
Corresponds to the f_bfree member in the struct statvfs.
fsdata["bavail"]
Corresponds to the f_bavail member in the struct statvfs.
fsdata["files"]
Corresponds to the f_files member in the struct statvfs.
fsdata["ffree"]
Corresponds to the f_ffree member in the struct statvfs.
fsdata["favail"]
Corresponds to the f_favail member in the struct statvfs.
fsdata["fsid"]
Corresponds to the f_fsid member in the struct statvfs. This member is not available on all systems.
fsdata["flag"]
Corresponds to the f_flag member in the struct statvfs.
fsdata["namemax"]
Corresponds to the f_namemax member in the struct statvfs.

NOTES

The AWK fts() extension does not exactly mimic the interface of the fts(3) routines, choosing instead to provide an interface that is based on associative arrays, which should be more comfortable to use from an AWK program. This includes the lack of a comparison function, since gawk already provides powerful array sorting facilities. While an fts_read()-like interface could have been provided, this felt less natural than simply creating a multi-dimensional array to represent the file hierarchy and its information.

Nothing prevents AWK code from changing the predefined FTS_xx values, but doing so may cause strange results when the changed values are passed to fts().

BUGS

There are many more file-related functions for which AWK interfaces would be desirable.

It's not clear why I thought adding FTS_SKIP was a good idea.

EXAMPLE

See test/fts.awk in the gawk distribution for an example.
