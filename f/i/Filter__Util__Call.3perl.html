Filter::Util::Call(3perl) Guide du programmeur Perl Filter::Util::Call(3perl)

NOM

Filter::Util::Call - Module utilitaire de filtre source Perl

SYNOPSIS

use Filter::Util::Call ;

DESCRIPTION

Ce module vous fournit le cadre pour écrire des filtres source en Perl.

Une interface alternative à Filter::Util::Call est maintenant disponible. Voir Filter::Simple pour plus de détails.

Un filtre source Perl est implémenté comme un module Perl. La structure du module peut prendre l'un des deux formats globalement similaires. Pour les distinguer, le premier sera appelé filtre par méthode et le second filtre par fermeture.

Voici un squelette pour le filtre par méthode :

package MyFilter ;
use Filter::Util::Call ;
sub import
{
    my($type, @arguments) = @_ ;
    filter_add([]) ;
}
sub filter
{
    my($self) = @_ ;
    my($status) ;
    $status = filter_read() ;
    $status ;
}
1 ;

et voici le squelette équivalent pour le filtre par fermeture :

package MyFilter ;
use Filter::Util::Call ;
sub import
{
    my($type, @arguments) = @_ ;
    filter_add(
        sub 
        {
            my($status) ;
            $status = filter_read() ;
            $status ;
        } )
}
1 ;

Pour utiliser l'un des deux modules de filtre ci-dessus, placez la ligne ci-dessous dans un fichier source Perl.

use MyFilter;

En fait, les modules squelettes montrés ci-dessus sont des filtres source pleinement fonctionnels, bien qu'assez inutiles. Tout ce qu'ils font est de filtrer le flux source sans le modifier du tout.

Comme vous pouvez le voir, les deux modules ont une structure globalement similaire. Ils utilisent tous deux le module "Filter::Util::Call" et ont tous deux une méthode "import". La différence entre eux est que le filtre par méthode nécessite une méthode "filter", tandis que le filtre par fermeture obtient l'équivalent d'une méthode "filter" avec la sous-routine anonyme passée à "filter_add".

Pour utiliser correctement le filtre par fermeture montré ci-dessus, vous devez avoir une bonne compréhension du concept de fermeture. Voir perlref pour plus de détails sur la mécanique des fermetures.

use Filter::Util::Call

Les fonctions suivantes sont exportées par "Filter::Util::Call" :

filter_add()
filter_read()
filter_read_exact()
filter_del()

import()

La méthode "import" est utilisée pour créer une instance du filtre. Elle est appelée indirectement par Perl lorsqu'il rencontre la ligne "use MyFilter" dans un fichier source (Voir "import" dans perlfunc pour plus de détails sur "import").

Elle aura toujours au moins un paramètre automatiquement passé par Perl - cela correspond au nom du paquet. Dans l'exemple ci-dessus, ce sera "MyFilter".

En dehors du premier paramètre, import peut accepter une liste optionnelle de paramètres. Ceux-ci peuvent être utilisés pour passer des paramètres au filtre. Par exemple :

use MyFilter qw(a b c) ;

résultera en ce que le tableau @_ aura les valeurs suivantes :

@_ [0] => "MyFilter"
@_ [1] => "a"
@_ [2] => "b"
@_ [3] => "c"

Avant de se terminer, la fonction "import" doit installer explicitement le filtre en appelant "filter_add".

filter_add()

La fonction "filter_add" installe réellement le filtre. Elle prend un paramètre qui doit être une référence. Le type de référence utilisé dictera lequel des deux types de filtre sera utilisé.

Si une référence CODE est utilisée, un filtre par fermeture sera supposé.

Si une référence CODE n'est pas utilisée, un filtre par méthode sera supposé. Dans un filtre par méthode, la référence peut être utilisée pour stocker des informations de contexte. La référence sera bénite dans le paquet par "filter_add", à moins que la référence n'ait déjà été bénite.

Voir les filtres à la fin de ce document pour des exemples d'utilisation d'informations de contexte en utilisant à la fois les filtres par méthode et les filtres par fermeture.

filter() et la sous-routine anonyme

La méthode "filter" utilisée avec un filtre par méthode et la sous-routine anonyme utilisée avec un filtre par fermeture sont toutes deux là où le traitement principal du filtre est effectué.

La grande différence entre les deux types de filtre est que le filtre par méthode utilise l'objet passé à la méthode pour stocker toute donnée de contexte, tandis que le filtre par fermeture utilise les variables lexicales qui sont maintenues par la fermeture.

Notez que le seul paramètre passé à la méthode filtre, $self, est la même référence qui a été passée à "filter_add", bénie dans le paquet du filtre. Voir les exemples de filtres plus loin pour les détails sur l'utilisation de $self.

Voici une liste des caractéristiques communes de la sous-routine anonyme et de la méthode filter().

$_
Bien que $_ n'apparaisse pas explicitement dans les filtres d'exemple ci-dessus, il est implicitement utilisé dans un certain nombre d'endroits.

Premièrement, lorsque soit la méthode "filter", soit la sous-routine anonyme sont appelées, une copie locale de $_ sera automatiquement créée. Elle contiendra toujours une chaîne vide à ce stade.

Ensuite, "filter_read" et "filter_read_exact" ajouteront toutes les données source lues à la fin de $_.

Enfin, lorsque "filter" ou la sous-routine anonyme auront terminé leur traitement, elles devront renvoyer la source filtrée en utilisant $_.

Cette utilisation implicite de $_ simplifie grandement le filtre.

$status
La valeur de statut qui est retournée par la méthode "filter" de l'utilisateur ou la sous-routine anonyme et les fonctions "filter_read" et "read_exact" prennent le même ensemble de valeurs, à savoir : 
< 0  Erreur
= 0  EOF
> 0  OK
filter_read et filter_read_exact
Ces fonctions sont utilisées par le filtre pour obtenir soit une ligne, soit un bloc du filtre suivant dans la chaîne, soit le fichier source réel s'il n'y a pas d'autres filtres.

La fonction "filter_read" prend deux formes :

$status = filter_read() ;
$status = filter_read($size) ;

La première forme est utilisée pour demander une ligne, la seconde demande un bloc.

En mode ligne, "filter_read" ajoutera la ligne source suivante à la fin du scalaire $_.

En mode bloc, "filter_read" ajoutera un bloc de données qui est <= $size à la fin du scalaire $_. Il est important de souligner que "filter_read" ne lira pas nécessairement un bloc qui est exactement de $size octets.

Si vous avez besoin de pouvoir lire un bloc d'une taille exacte, vous pouvez utiliser la fonction "filter_read_exact". Elle fonctionne de manière identique à "filter_read" en mode bloc, sauf qu'elle essaiera de lire un bloc d'une taille exacte de $size octets. Les seules circonstances où elle ne renverra pas un bloc de $size octets sont en cas d'EOF ou d'erreur.

Il est très important de vérifier la valeur de $status après chaque appel à "filter_read" ou "filter_read_exact".

filter_del

"filter_del", est utilisé pour désactiver le filtre courant. Cela n'affecte pas l'exécution du filtre. Tout ce qu'il fait est de dire à Perl de ne plus appeler filter.

Voir "Exemple 4 : Utilisation de filter_del" pour plus de détails.

real_import
Fonction interne qui ajoute le filtre, en fonction du type de l'argument filter_add.
unimport()
Peut être utilisé pour désactiver un filtre, mais est rarement nécessaire. Voir filter_del.

LIMITATIONS

Voir "LIMITATIONS" dans perlfilter pour un aperçu des problèmes généraux liés au filtrage du code uniquement au niveau des lignes textuelles.

__DATA__ est ignoré
Le contenu du bloc __DATA__ n'est pas filtré. C'est une limitation sérieuse, par exemple pour le module Switch. Voir http://search.cpan.org/perldoc?Switch#LIMITATIONS pour plus d'informations.
Taille de code max. limitée à 32 bits
Actuellement, les longueurs des tampons internes sont limitées à 32 bits.

EXEMPLES

Voici quelques exemples qui illustrent les concepts clés - en tant que tels, la plupart d'entre eux ont peu d'utilité pratique.

Le sous-répertoire "examples" contient des copies de tous ces filtres implémentés à la fois comme filtres de méthode et comme filtres de fermeture.

Exemple 1 : Un filtre simple.

Ci-dessous se trouve un filtre de méthode qui est codé en dur pour remplacer toutes les occurrences de la chaîne "Joe" par "Jim". Pas particulièrement utile, mais c'est le premier exemple et je voulais le garder simple.

package Joe2Jim ;
use Filter::Util::Call ;
sub import
{
    my($type) = @_ ;
    filter_add(bless []) ;
}
sub filter
{
    my($self) = @_ ;
    my($status) ;
    s/Joe/Jim/g
        if ($status = filter_read()) > 0 ;
    $status ;
}
1 ;

Voici un exemple d'utilisation du filtre :

use Joe2Jim ;
print "Where is Joe?\n" ;

Et voici ce que le script ci-dessus affichera :

Where is Jim?

Exemple 2 : Utilisation du contexte

L'exemple précédent n'était pas particulièrement utile. Pour le rendre plus général, nous utiliserons les données de contexte et permettrons l'utilisation de chaînes arbitraires de départ et de fin . Cette fois, nous utiliserons un filtre de fermeture. Pour refléter son rôle amélioré, le filtre est appelé "Subst".

package Subst ;
use Filter::Util::Call ;
use Carp ;
sub import
{
    croak("usage: use Subst qw(from to)")
        unless @_ == 3 ;
    my ($self, $from, $to) = @_ ;
    filter_add(
        sub 
        {
            my ($status) ;
            s/$from/$to/
                if ($status = filter_read()) > 0 ;
            $status ;
        })
}
1 ;

et est utilisé comme ceci :

use Subst qw(Joe Jim) ;
print "Where is Joe?\n" ;

Exemple 3 : Utilisation du contexte dans le filtre

Voici un filtre qui est une variante du filtre "Joe2Jim" . En plus de substituer toutes les occurrences de "Joe" par "Jim" , il conserve un compteur du nombre de substitutions effectuées dans l'objet contexte.

Une fois la fin de fichier (EOF) détectée ($status vaut zéro), le filtre insérera une ligne supplémentaire dans le flux source. Lorsque cette ligne supplémentaire sera exécutée, elle affichera le nombre de substitutions réellement effectuées. Notez que $status est défini à 1 dans ce cas.

package Count ;
use Filter::Util::Call ;
sub filter
{
    my ($self) = @_ ;
    my ($status) ;
    if (($status = filter_read()) > 0 ) {
        s/Joe/Jim/g ;
        ++ $$self ;
    }
    elsif ($$self >= 0) { # EOF
        $_ = "print q[Made ${$self} substitutions\n]" ;
        $status = 1 ;
        $$self = -1 ;
    }
    $status ;
}
sub import
{
    my ($self) = @_ ;
    my ($count) = 0 ;
    filter_add(\$count) ;
}
1 ;

Voici un script qui l'utilise :

use Count ;
print "Hello Joe\n" ;
print "Where is Joe\n" ;

Sortie :

Hello Jim
Where is Jim
Made 2 substitutions

Exemple 4 : Utilisation de filter_del

Une autre variation sur un thème. Cette fois, nous modifierons le filtre "Subst" pour permettre de spécifier un motif de début et de fin en plus des motifs de départ et de fin . Si vous connaissez l'éditeur vi , c'est l'équivalent de cette commande :

:/start/,/stop/s/from/to/

Lorsqu'il est utilisé comme filtre, nous voulons l'invoquer ainsi :

use NewSubst qw(start stop from to) ;

Voici le module.

package NewSubst ;
use Filter::Util::Call ;
use Carp ;
sub import
{
    my ($self, $start, $stop, $from, $to) = @_ ;
    my ($found) = 0 ;
    croak("usage: use Subst qw(start stop from to)")
        unless @_ == 5 ;
    filter_add( 
        sub 
        {
            my ($status) ;
            if (($status = filter_read()) > 0) {
                $found = 1
                    if $found == 0 and /$start/ ;
                if ($found) {
                    s/$from/$to/ ;
                    filter_del() if /$stop/ ;
                }
            }
            $status ;
        } )
}
1 ;

Filter::Simple

Si vous prévoyez d'utiliser la fonctionnalité Filter::Call, je vous recommande vivement de consulter l'excellent module Filter::Simple de Damian Conway. Le module de Damian fournit une interface beaucoup plus propre que Filter::Util::Call. Bien qu'il ne permette pas le contrôle fin que Filter::Util::Call offre, il devrait être suffisant pour la majorité des applications. Il est disponible à l'adresse

http://search.cpan.org/dist/Filter-Simple/
