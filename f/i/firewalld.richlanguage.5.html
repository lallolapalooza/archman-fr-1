NOM

firewalld.richlanguage - Documentation du langage enrichi

DESCRIPTION

Avec le langage enrichi, des règles de pare-feu plus complexes peuvent être créées de manière facile à comprendre. Le langage utilise des mots-clés avec des valeurs et est une représentation abstraite des règles ip*tables.

Le langage enrichi étend les éléments de zone actuels (service, port, icmp-block, icmp-type, masquerade, forward-port et source-port) avec des adresses source et destination supplémentaires, la journalisation, les actions et les limites pour les journaux et les actions.

Cette page décrit le langage enrichi utilisé dans le client en ligne de commande et l'interface D-Bus. Pour des informations sur la représentation du langage enrichi utilisée dans les fichiers de configuration de zone, veuillez consulter firewalld.zone(5).

Une règle fait partie d'une zone. Une zone peut contenir plusieurs règles. Si certaines règles interagissent/se contredisent, la première règle qui correspond "gagne".

Structure générale d'une règle

rule
  [source]
  [destination]
  service|port|protocol|icmp-block|icmp-type|masquerade|forward-port|source-port
  [log|nflog]
  [audit]
  [accept|reject|drop|mark]

La règle complète est fournie sous forme de chaîne de caractères sur une seule ligne. Une destination est autorisée ici tant qu'elle n'entre pas en conflit avec la destination d'un service.

Structure de règle pour la liste noire ou blanche des sources

rule
  source
  [log|nflog]
  [audit]
  accept|reject|drop|mark

Ceci est utilisé pour accorder ou limiter l'accès d'une source à cette machine ou aux machines accessibles par cette machine. Une destination n'est pas autorisée ici.

Informations importantes sur les options des éléments : Les options des éléments dans une règle doivent être ajoutées exactement après l'élément. Si l'option est placée ailleurs, elle peut être utilisée pour un autre élément tant qu'elle correspond aux options de l'autre élément ou cela résultera en une erreur de règle.

Règle

rule [family="ipv4|ipv6"] [priority="priorité"]

Si la famille de règle est fournie, elle peut être soit "ipv4" soit "ipv6", ce qui limite la règle à IPv4 ou IPv6. Si la famille de règle n'est pas fournie, la règle sera ajoutée pour IPv4 et IPv6. Si des adresses source ou destination sont utilisées dans une règle, la famille de règle doit être fournie. C'est également le cas pour le transfert de port/paquet.

Si la priorité de la règle est fournie, elle peut être dans la plage de -32768 à 32767 où les valeurs inférieures ont une précédence plus élevée. Les règles enrichies sont triées par priorité. L'ordre des règles ayant la même valeur de priorité est indéfini. Une valeur de priorité négative sera exécutée avant d'autres primitives de firewalld. Une valeur de priorité positive sera exécutée après d'autres primitives de firewalld. Une valeur de priorité de 0 placera la règle dans une chaîne basée sur l'action, conformément à la section "Informations sur la journalisation et les actions" ci-dessous.

Source

source [not] address="adresse[/masque]"|mac="adresse-mac"|ipset="ipset"

Avec l'adresse source, l'origine d'une tentative de connexion peut être limitée à l'adresse source. Une adresse est soit une adresse IP unique, soit une adresse IP réseau, une adresse MAC ou un IPSet. L'adresse doit correspondre à la famille de règle (IPv4/IPv6). Le masque de sous-réseau est exprimé en notation décimale pointée (/x.x.x.x) ou en notation préfixe (/x) pour IPv4, et en notation préfixe (/x) pour les adresses réseau IPv6. Il est possible d'inverser le sens d'une adresse en ajoutant not avant address. Toutes les adresses sauf celle spécifiée correspondront alors.

Destination

destination [not] address="adresse[/masque]"|ipset="ipset"

Avec l'adresse de destination, la cible peut être limitée à l'adresse de destination. L'adresse de destination utilise la même syntaxe que l'adresse source.

L'utilisation des adresses source et destination est facultative et l'utilisation d'adresses de destination n'est pas possible avec tous les éléments. Cela dépend de l'utilisation des adresses de destination, par exemple dans les entrées de service.

Service

service name="nom du service"

Le service nom du service sera ajouté à la règle. Le nom du service est l'un des services fournis par firewalld. Pour obtenir une liste des services pris en charge, utilisez firewall-cmd --get-services.

Si un service fournit une adresse de destination, il entrera en conflit avec une adresse de destination dans la règle et entraînera une erreur. Les services utilisant des adresses de destination en interne sont principalement les services utilisant la multidiffusion.

Port

port port="valeur du port" protocol="tcp|udp|sctp|dccp"

Le port valeur du port peut être soit un numéro de port unique portid, soit une plage de ports portid-portid. Le protocole peut être tcp, udp, sctp ou dccp.

Protocole

protocol value="valeur du protocole"

La valeur du protocole peut être soit un numéro d'identifiant de protocole, soit un nom de protocole. Pour connaître les entrées de protocole autorisées, veuillez consulter /etc/protocols.

Tcp-Mss-Clamp

tcp-mss-clamp="valeur=pmtu|valeur=nombre >= 536|Aucun"

Le tcp-mss-clamp définit la taille maximale du segment dans la règle.

Le tcp-mss-clamp a un attribut optionnel, la valeur peut être définie sur "pmtu" ou sur un nombre supérieur ou égal à 536. Si la valeur de l'attribut n'est pas présente, la taille maximale du segment est automatiquement définie sur "pmtu".

Blocage-ICMP

icmp-block name="nom du type icmp"

Le type icmp est l'un des types icmp pris en charge par firewalld. Pour obtenir une liste des types icmp pris en charge : firewall-cmd --get-icmptypes

Il n'est pas autorisé de spécifier une action ici. icmp-block utilise l'action reject en interne.

Masquerade

masquerade

Active le masquage dans la règle. Une adresse source et une adresse de destination peuvent être fournies pour limiter le masquage à cette zone.

Il n'est pas autorisé de spécifier une action ici.

Remarque : Le transfert IP sera implicitement activé.

Type-ICMP

icmp-type name="nom du type icmp"

Le type icmp est l'un des types icmp pris en charge par firewalld. Pour obtenir une liste des types icmp pris en charge : firewall-cmd --get-icmptypes

Transfert-de-Port

forward-port port="valeur du port" protocol="tcp|udp|sctp|dccp" to-port="valeur du port" to-addr="adresse"

Transfère le port/les paquets du port local valeur du port avec le protocole "tcp" ou "udp" vers un autre port localement, ou vers une autre machine, ou vers un autre port sur une autre machine.

La valeur du port peut être soit un numéro de port unique, soit une plage de ports portid-portid. Le to-addr est une adresse IP. Le protocole peut être tcp, udp, sctp ou dccp.

Il n'est pas autorisé de spécifier une action ici. forward-port utilise l'action accept en interne.

Remarque : Le transfert IP sera implicitement activé si to-addr est spécifié.

Source-Port

source-port port="valeur du port" protocol="tcp|udp|sctp|dccp"

Le source-port valeur du port peut être soit un numéro de port unique portid, soit une plage de ports portid-portid. Le protocole peut être tcp, udp, sctp ou dccp.

L

log [prefix="prefix text"] [level="emerg|alert|crit|error|warning|notice|info|debug"] [limit value="rate[/duration]"]

La chaîne prefix text sera ajoutée au début de chaque message de log. La valeur du niveau de log est celle définie dans syslog. La limite est un taux d'événements par durée, par exemple rate=5/m (5 par minute).

Nflog

nflog [prefix="prefix text"] [group="group number"] [limit value="rate[/duration]"]

La chaîne prefix text sera ajoutée au début de chaque message de log. Le groupe est un nombre de groupe et il est utilisé pour regrouper les messages de log par ulogd. La limite est un taux d'événements par durée, par exemple rate=5/m (5 par minute).

Audit

audit [limit value="rate[/duration]"]

Les événements correspondants seront audités par le noyau Linux. La limite est un taux d'événements par durée, par exemple rate=5/m (5 par minute).

Actions

Les actions suivantes sont disponibles :

accept
Accepte le paquet.
reject
Rejette le paquet avec un message ICMP port-unreachable (pour TCP) ou host-unreachable (pour UDP).
drop
Supprime le paquet silencieusement.
mark
Marque le paquet. La marque est un entier de 32 bits et est stockée dans le champ de données d'extension de paquet FW_MARK. Ce marquage peut ensuite être utilisé par d'autres règles pour prendre des décisions.

Chaque règle doit avoir une action, sauf si l'action est implicitement définie par un élément. Les éléments qui définissent implicitement une action sont :

  • icmp-block : utilise reject
  • forward-port : utilise accept

Si plusieurs actions sont disponibles (par exemple, l'action implicite et une action spécifiée), l'action spécifiée dans la règle a la précédence.

Les actions log, nflog et audit peuvent être utilisées avec n'importe quelle action.

Limites de vitesse et durées

Les limites de vitesse et les durées sont utilisées pour limiter la fréquence des journaux ou des actions. La syntaxe est rate[/duration]. La duration est optionnelle. Les unités possibles pour la durée sont s, m, h, d, w, M, y (secondes, minutes, heures, jours, semaines, mois, années).

Exemples :

  • limit value="5/m" : 5 événements par minute
  • limit value="1/h" : 1 événement par heure
  • limit value="100" : 100 événements (sans limite de durée)

Exemples

Autoriser les connexions SSH depuis un réseau spécifique :

firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" source address="192.168.1.0/24" service name="ssh" accept'

Rejeter les connexions depuis une adresse IP spécifique :

firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" source address="198.51.100.1" reject'

Autoriser le trafic HTTP et HTTPS et le journaliser avec un préfixe personnalisé :

firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" service name="http" log prefix="HTTP" level="info" accept'
firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" service name="https" log prefix="HTTPS" level="info" accept'

Transférer le port 8080 vers le port 80 sur une autre machine :

firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" forward-port port="8080" protocol="tcp" to-port="80" to-addr="198.51.100.5"'

Autoriser uniquement les connexions depuis des adresses MAC spécifiques pour le service telnet (en supposant que vous utilisiez les listes ipset) :

firewall-cmd --permanent --new-ipset=allowed_macs type=hash:mac
firewall-cmd --ipset=allowed_macs --add-entry=00:11:22:33:44:55
firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" source ipset="allowed_macs" service name="telnet" accept'

Autoriser le trafic UDP sur le port 53 et le port 123 avec une limite de 3 paquets par minute :

firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" port port="53" protocol="udp" log limit="3/m" accept'
firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" port port="123" protocol="udp" log limit="3/m" accept'

Bloquer toutes les connexions sauf celles du réseau local :

firewall-cmd --zone=public --set-target=DROP
firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" source address="192.168.1.0/24" accept'

Voir aussi
