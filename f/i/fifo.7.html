NOM

fifo - fichier spécial premier entré, premier sorti (FIFO), tube nommé

DESCRIPTION

Un fichier spécial FIFO (un tube nommé) est similaire à un tube, sauf qu'il est accessible dans le cadre du système de fichiers. Il peut être ouvert par plusieurs processus en lecture ou en écriture. Lorsque les processus échangent des données via le FIFO, le noyau transmet toutes les données en interne sans les écrire sur le système de fichiers. Ainsi, le fichier spécial FIFO n'a aucun contenu sur le système de fichiers ; l'entrée du système de fichiers sert uniquement de point de référence pour que les processus puissent accéder au tube en utilisant un nom dans le système de fichiers.

Le noyau maintient exactement un objet tube pour chaque fichier spécial FIFO qui est ouvert par au moins un processus. Le FIFO doit être ouvert aux deux extrémités (lecture et écriture) avant que des données ne puissent être transmises. Normalement, l'ouverture du FIFO bloque jusqu'à ce que l'autre extrémité soit également ouverte.

Un processus peut ouvrir un FIFO en mode non bloquant. Dans ce cas, l'ouverture en lecture seule réussit même si personne n'a encore ouvert le côté écriture, et l'ouverture en écriture seule échoue avec ENXIO (aucun tel périphérique ou adresse) à moins que l'autre extrémité n'ait déjà été ouverte.

Sous Linux, l'ouverture d'un FIFO en lecture et écriture réussit en mode bloquant et non bloquant. POSIX laisse ce comportement indéfini. Cela peut être utilisé pour ouvrir un FIFO en écriture alors qu'aucun lecteur n'est disponible. Un processus qui utilise les deux extrémités de la connexion afin de communiquer avec lui-même doit être très prudent pour éviter les interblocages.

NOTES

Pour les détails de la sémantique des I/O sur les FIFOs, voir pipe(7).

Lorsqu'un processus essaie d'écrire dans un FIFO qui n'est pas ouvert en lecture de l'autre côté, le processus reçoit un signal SIGPIPE.

Les fichiers spéciaux FIFO peuvent être créés par mkfifo(3), et sont indiqués par ls -l avec le type de fichier 'p'.
