NOM

Firecfg - Utilitaires d'intégration de bureau pour le logiciel Firejail.

SYNOPSIS

firecfg [OPTIONS]

DESCRIPTION

Firecfg est l'utilitaire d'intégration de bureau pour le sandbox Firejail. Il permet à l'utilisateur de sandboxer automatiquement les applications en cliquant sur les icônes et les menus du gestionnaire de bureau.

L'intégration couvre :

- les programmes lancés dans un terminal - taper "firefox" suffirait pour lancer un navigateur Firefox sandboxé.

- les programmes lancés en cliquant sur les menus du gestionnaire de bureau - tous les principaux gestionnaires de bureau sont supportés.

- les programmes lancés en cliquant sur des icônes de fichiers dans le gestionnaire de fichiers - seuls les gestionnaires de bureau Cinnamon, KDE, LXDE/LXQT, MATE et XFCE sont supportés pour le moment.

Note : Les exemples utilisent sudo, mais doas est également supporté.

Pour le configurer, exécutez "sudo firecfg" après avoir installé le logiciel Firejail. La même commande doit également être exécutée après l'installation de nouveaux programmes. Si le programme est supporté par Firejail, le lien symbolique dans /usr/local/bin sera créé.

Pour configurer la liste des programmes utilisés par firecfg lors de la création de liens symboliques, voir FICHIERS et SYNTAXE.

Pour une intégration manuelle pilotée par l'utilisateur, voir la section INTÉGRATION DE BUREAU de man 1 firejail.

ACTIONS PAR DÉFAUT

Les actions suivantes sont implémentées par défaut lors de l'exécution de sudo firecfg :

- définir ou mettre à jour les liens symboliques pour l'intégration de bureau ;

- ajouter l'utilisateur courant à la base de données d'accès utilisateur de Firejail (firecfg --add-users) ;

- corriger les fichiers .desktop dans $HOME/.local/share/applications/ (firecfg --fix).
- charge et force automatiquement le profil AppArmor "firejail-default".

OPTIONS

--add-users utilisateur [utilisateur]
Ajoute la liste des utilisateurs à la base de données d'accès utilisateur de Firejail.

Exemple :
$ sudo firecfg --add-users dustin lucas mike eleven

--bindir=répertoire
Crée et recherche des liens symboliques dans le répertoire au lieu de l'emplacement par défaut /usr/local/bin. Le répertoire doit précéder /usr/bin et /bin dans la variable d'environnement PATH.
--clean
Supprime tous les liens symboliques de firejail.
--fix
Corrige les fichiers .desktop. Certains fichiers .desktop utilisent le chemin complet de l'exécutable. Firecfg vérifiera les fichiers .desktop dans /usr/share/applications/, remplacera le chemin complet par le nom s'il est dans le PATH, et écrira le résultat dans $HOME/.local/share/applications/. Cette action est effectuée par défaut lors de l'exécution de "sudo firecfg". Nous l'avons comme option séparée pour les utilisateurs réguliers.
--fix-sound
Crée un fichier ~/.config/pulse/client.conf approprié sans prise en charge de shm. Sur certaines versions de PulseAudio, la prise en charge de la mémoire partagée (shm) casse l'espace de noms des identifiants de processus. Le logiciel PulseAudio a été conçu il y a longtemps, et l'introduction de l'espace de noms PID dans le noyau Linux casse leur conception. Cela aurait été corrigé dans la version 9 de PulseAudio. Si vous rencontrez des problèmes de son sur votre système, exécutez la commande "firecfg --fix-sound" dans un terminal, suivi d'une déconnexion/connexion pour appliquer les changements.
--guide
Configuration guidée pour les nouveaux utilisateurs.

Exemple :
$ sudo firecfg --guide

--debug
Affiche les messages de débogage.
-?, --help
Affiche les options et quitte.
--list
Liste tous les liens symboliques de firejail.
--version
Affiche la version du programme et quitte.

Exemple :

$ sudo firecfg
/usr/local/bin/firefox créé
/usr/local/bin/vlc créé
[...]
$ firecfg --list
/usr/local/bin/firefox
/usr/local/bin/vlc
[...]
$ sudo firecfg --clean
/usr/local/bin/firefox supprimé
/usr/local/bin/vlc supprimé
[...]

SYNTAXE

Syntaxe du fichier de configuration :

Une ligne commençant par # est considérée comme un commentaire.
Une ligne commençant par !PROGRAMME signifie qu'il faut ignorer "PROGRAMME" lors de la création des liens symboliques et de la correction des fichiers .desktop.
Toute autre ligne est considérée comme le nom d'un exécutable et firecfg tentera de créer un lien symbolique pour celui-ci.

Par exemple, pour empêcher firecfg de créer des liens symboliques pour "firefox" et "patch" tout en tentant de créer un lien symbolique pour "myprog", les lignes suivantes pourraient être ajoutées à /etc/firejail/firecfg.d/10-my.conf :

!firefox
!patch

myprog

Notez que certains programmes peuvent utiliser des schémas de nommage différents pour leur fichier .desktop par rapport à l'exécutable principal. Pour s'assurer que les deux fichiers sont gérés de la même manière, il est recommandé de lister les deux noms dans la configuration. Par exemple, si Spectacle a son exécutable principal dans /usr/bin/spectacle et son fichier .desktop dans /usr/share/applications/org.kde.spectacle.desktop, alors les lignes suivantes peuvent être utilisées pour ignorer les deux :

!org.kde.spectacle
!spectacle

FICHIERS

Les fichiers de configuration sont recherchés et analysés dans les chemins suivants :

1. /etc/firejail/firecfg.d/*.conf (par ordre alphabétique)
2. /etc/firejail/firecfg.config

Les programmes qui sont supportés par défaut sont listés dans /etc/firejail/firecfg.config. Il est recommandé de le laisser tel quel et de placer toutes les personnalisations dans /etc/firejail/firecfg.d/.

Les fichiers de profil sont également recherchés dans le répertoire de configuration utilisateur :

3. ~/.config/firejail/*.profile

Pour chaque fichier PROGRAMME.profile trouvé, firecfg tente de créer un lien symbolique pour "PROGRAMME", comme si "PROGRAMME" était listé dans un fichier de configuration.
