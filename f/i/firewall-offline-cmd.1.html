NOM

firewall-offline-cmd - client en ligne de commande hors ligne de firewalld

SYNOPSIS

firewall-offline-cmd [OPTIONS...]

DESCRIPTION

firewall-offline-cmd est un client en ligne de commande hors ligne du démon firewalld. Il ne doit être utilisé que si le service firewalld n'est pas en cours d'exécution. Par exemple, pour migrer depuis system-config-firewall/lokkit ou dans l'environnement d'installation pour configurer les paramètres du pare-feu avec kickstart.

Certaines options de lokkit ne peuvent pas être converties automatiquement pour firewalld ; elles entraîneront un message d'erreur ou d'avertissement. Cet outil tente de convertir autant que possible, mais il existe des limitations, par exemple avec les règles personnalisées, les modules et le masquerading.

Vérifiez la configuration du pare-feu après avoir utilisé cet outil.

OPTIONS

Si aucune option n'est donnée, la configuration de /etc/sysconfig/system-config-firewall sera migrée.

Les options de séquence sont les options qui peuvent être spécifiées plusieurs fois ; le code de sortie est 0 s'il y a au moins un élément qui a réussi. Les ALREADY_ENABLED (11), NOT_ENABLED (12) et aussi ZONE_ALREADY_SET (16) erreurs sont considérées comme des succès. S'il y a des problèmes lors de l'analyse des éléments, ceux-ci sont traités comme des avertissements et ne changeront pas le résultat tant qu'il y a un élément réussi. Sans aucun élément réussi, le code de sortie dépendra des codes d'erreur. S'il y a exactement un code d'erreur, celui-ci est utilisé. S'il y en a plus d'un, alors UNKNOWN_ERROR (254) sera utilisé.

Les options suivantes sont prises en charge :

Options générales

-h, --help

Affiche un court texte d'aide et se termine.

-V, --version

Affiche la chaîne de version de firewalld et se termine.

-q, --quiet

Ne pas afficher les messages d'état.

--default-config

Chemin vers la configuration par défaut de firewalld. Cela vaut généralement par défaut /usr/lib/firewalld.

--system-config

Chemin vers la configuration système (utilisateur) de firewalld. Cela vaut généralement par défaut /etc/firewalld.

Options d'état

--enabled

Activez le pare-feu. Cette option est une option par défaut et activera le pare-feu s'il n'est pas déjà activé, tant que l'option --disabled n'est pas donnée.

--disabled

Désactivez le pare-feu en désactivant le service firewalld.

--check-config

Exécute des vérifications sur la configuration permanente (par défaut et système). Cela inclut la validité XML et la sémantique.

Cela peut être utilisé avec --system-config pour vérifier la validité des fichiers de configuration manuscrits avant de les copier vers l'emplacement standard.

--reset-to-defaults

Réinitialise la configuration à la configuration par défaut de firewalld

Options de compatibilité Lokkit

Ces options sont presque identiques aux options de lokkit.

--migrate-system-config-firewall=fichier

Migre la configuration de system-config-firewall depuis le fichier donné. Aucune autre

--addmodule=module

Cette option entraînera un message d'avertissement et sera ignorée.

La gestion des assistants netfilter a été entièrement fusionnée dans les services. L'ajout ou la suppression d'assistants netfilter en dehors des services n'est donc plus nécessaire. Pour plus d'informations sur la gestion des assistants netfilter dans les services, veuillez consulter firewalld.zone(5).

--removemodule

Cette option entraînera un message d'avertissement et sera ignorée.

La gestion des assistants netfilter a été entièrement fusionnée dans les services. L'ajout ou la suppression d'assistants netfilter en dehors des services n'est donc plus nécessaire. Pour plus d'informations sur la gestion des assistants netfilter dans les services, veuillez consulter firewalld.zone(5).

--remove-service=service

Supprime un service de la zone par défaut. Cette option peut être spécifiée plusieurs fois.

Le service est l'un des services fournis par firewalld. Pour obtenir une liste des services pris en charge, utilisez firewall-cmd --get-services.

-s service, --service=service

Ajoute un service à la zone par défaut. Cette option peut être spécifiée plusieurs fois.

Le service est l'un des services fournis par firewalld. Pour obtenir une liste des services pris en charge, utilisez firewall-cmd --get-services.

-p portid[-portid]:protocol, --port=portid[-portid]:protocol

Ajoute le port à la zone par défaut. Cette option peut être spécifiée plusieurs fois.

Le port peut être soit un numéro de port unique, soit une plage de ports portid-portid. Le protocole peut être tcp, udp, sctp ou dccp.

-t interface, --trust=interface

Cette option entraînera un message d'avertissement.

Marque une interface comme de confiance. Cette option peut être spécifiée plusieurs fois. L'interface sera liée à la zone de confiance.

Si l'interface est utilisée dans une connexion gérée par NetworkManager ou s'il existe un fichier ifcfg pour cette interface, la zone sera changée vers la zone définie dans la configuration dès qu'elle sera activée. Pour changer la zone d'une connexion, utilisez nm-connection-editor et définissez la zone sur trusted ; pour un fichier ifcfg, utilisez un éditeur et ajoutez "ZONE=trusted". Si la zone n'est pas définie dans le fichier ifcfg, la zone par défaut de firewalld sera utilisée.

-m interface, --masq=interface

Cette option entraînera un message d'avertissement.

Le masquerading sera activé dans la zone par défaut. L'argument interface sera ignoré. Cela concerne IPv4 uniquement.

--custom-rules=[type:][table:]filename

Cette option entraînera un message d'avertissement et sera ignorée.

Les fichiers de règles personnalisées ne sont pas pris en charge par firewalld.

--forward-port=if=interface:port=port:proto=protocol[:toport=port de destination:][:toaddr=adresse de destination]

Cette option entraînera un message d'avertissement.

Ajoute le port de transfert IPv4 dans la zone par défaut. Cette option peut être spécifiée plusieurs fois.

Le port peut être soit un numéro de port unique portid soit une plage de ports portid-portid. Le protocole peut être tcp, udp, sctp ou dccp. L'adresse de destination est une adresse IP.

--block-icmp=icmptype

Cette option entraînera un message d'avertissement.

Ajoute un blocage ICMP pour icmptype dans la zone par défaut. Cette option peut être spécifiée plusieurs fois.

Le icmptype est l'un des types ICMP pris en charge par firewalld. Pour obtenir une liste des types ICMP pris en charge : firewall-cmd --get-icmptypes

Options de journalisation des refus

--get-log-denied

Affiche le paramètre de journalisation des refus.

--set-log-denied=value

Ajoute des règles de journalisation juste avant les règles de rejet et de rejet dans les chaînes INPUT, FORWARD et OUTPUT pour les règles par défaut, ainsi que les règles de rejet et de rejet finales dans les zones pour le type de paquet de couche liaison configuré. Les valeurs possibles sont : all, unicast, broadcast, multicast et off. Le paramètre par défaut est off, ce qui désactive la journalisation.

Il s'agit d'un changement à l'exécution et permanent, et cela rechargera également le pare-feu pour pouvoir ajouter les règles de journalisation.

Options pour gérer les liaisons des sources

Lier une source à une zone signifie que les paramètres de cette zone seront utilisés pour restreindre le trafic provenant de cette source.

Une adresse source ou une plage d'adresses est soit une adresse IP, soit une adresse IP de réseau avec un masque pour IPv4 ou IPv6, soit une adresse MAC, soit un ipset avec le préfixe ipset:. Pour IPv4, le masque peut être un masque réseau ou un nombre simple. Pour IPv6, le masque est un nombre simple. L'utilisation de noms d'hôtes n'est pas prise en charge.

Les options de cette section n'affectent qu'une zone particulière. Si elles sont utilisées avec --zone=zone , elles affectent la zone zone. Si l'option est omise, elles affectent la zone par défaut (voir --get-default-zone).

Options directes

OBSOLÈTE

L'interface directe est obsolète. Elle sera supprimée dans une version future. Elle est remplacée par les politiques, voir firewalld.policies(5).

Les options directes donnent un accès plus direct au pare-feu. Ces options nécessitent que l'utilisateur connaisse les concepts de base d'iptables, c'est-à-dire table (filter/mangle/nat/...), chaîne (INPUT/OUTPUT/FORWARD/...), commandes (-A/-D/-I/...), paramètres (-p/-s/-d/-j/...) et cibles (ACCEPT/DROP/REJECT/...).

Les options directes ne devraient être utilisées qu'en dernier recours, quand il n'est pas possible d'utiliser par exemple --add-service=service ou --add-rich-rule='rule'.

Avertissement: Le comportement des règles directes diffère selon la valeur de FirewallBackend. Voir CAVEATS dans firewalld.direct(5).

Le premier argument de chaque option doit être ipv4 ou ipv6 ou eb. Avec ipv4 ce sera pour IPv4 (iptables(8)), avec ipv6 pour IPv6 (ip6tables(8)) et avec eb pour les ponts ethernet (ebtables(8)).

--direct --get-all-chains

Obtenir toutes les chaînes ajoutées à toutes les tables.

Cette option ne concerne que les chaînes précédemment ajoutées avec --direct --add-chain.

--direct --get-chains { ipv4 | ipv6 | eb } table

Obtenir toutes les chaînes ajoutées à la table table sous forme de liste séparée par des espaces.

Cette option ne concerne que les chaînes précédemment ajoutées avec --direct --add-chain.

--direct --add-chain { ipv4 | ipv6 | eb } table chain

Ajouter une nouvelle chaîne nommée chain à la table table.

Il existe déjà des chaînes de base à utiliser avec les options directes, par exemple la chaîne INPUT_direct (voir la sortie de iptables-save | grep direct pour toutes les voir). Ces chaînes sont sautées avant les chaînes des zones, c'est-à-dire que chaque règle placée dans INPUT_direct sera vérifiée avant les règles des zones.

--direct --remove-chain { ipv4 | ipv6 | eb } table chain

Supprimer la chaîne nommée chain de la table table.

--direct --query-chain { ipv4 | ipv6 | eb } table chain

Indiquer si une chaîne nommée chain existe dans la table table. Retourne 0 si vrai, 1 sinon.

Cette option ne concerne que les chaînes précédemment ajoutées avec --direct --add-chain.

--direct --get-all-rules

Obtenir toutes les règles ajoutées à toutes les chaînes dans toutes les tables sous forme de liste séparée par des sauts de ligne de la priorité et des arguments.

--direct --get-rules { ipv4 | ipv6 | eb } table chain

Obtenir toutes les règles ajoutées à la chaîne chain dans la table table sous forme de liste séparée par des sauts de ligne de la priorité et des arguments.

--direct --add-rule { ipv4 | ipv6 | eb } table chain priority args

Ajouter une règle avec les arguments args à la chaîne chain dans la table table avec la priorité priority.

La priorité est utilisée pour ordonner les règles. Une priorité 0 signifie ajouter la règle en haut de la chaîne, avec une priorité plus élevée la règle sera ajoutée plus bas. Les règles de même priorité sont au même niveau et l'ordre de ces règles n'est pas fixe et peut changer. Si vous voulez vous assurerl be added after another one, use a low priority for the first and a higher for the following.

--direct --remove-rule { ipv4 | ipv6 | eb } table chain priority args

Remove a rule with priority and the arguments args from chain chain in table table.

--direct --remove-rules { ipv4 | ipv6 | eb } table chain

Remove all rules in the chain with name chain exists in table table.

This option concerns only rules previously added with --direct --add-rule in this chain.

--direct --query-rule { ipv4 | ipv6 | eb } table chain priority args

Return whether a rule with priority and the arguments args exists in chain chain in table table. Returns 0 if true, 1 otherwise.

--direct --get-all-passthroughs

Get all permanent passthrough as a newline separated list of the ipv value and arguments.

--direct --get-passthroughs { ipv4 | ipv6 | eb }

Get all permanent passthrough rules for the ipv value as a newline separated list of the priority and arguments.

--direct --add-passthrough { ipv4 | ipv6 | eb } args

Add a permanent passthrough rule with the arguments args for the ipv value.

--direct --remove-passthrough { ipv4 | ipv6 | eb } args

Remove a permanent passthrough rule with the arguments args for the ipv value.

--direct --query-passthrough { ipv4 | ipv6 | eb } args

Return whether a permanent passthrough rule with the arguments args exists for the ipv value. Returns 0 if true, 1 otherwise.
