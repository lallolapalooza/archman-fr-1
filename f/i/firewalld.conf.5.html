NOM

firewalld.conf - fichier de configuration de firewalld

SYNTAXE

/etc/firewalld/firewalld.conf

DESCRIPTION

firewalld.conf est chargé par firewalld pendant le processus d'initialisation. Le fichier contient les options de configuration de base pour firewalld.

OPTIONS

Voici les options qui peuvent être définies dans le fichier de configuration :

DefaultZone

Définit la zone par défaut pour les connexions ou les interfaces si la zone n'est pas sélectionnée ou spécifiée par NetworkManager, les scripts d'initialisation ou l'outil en ligne de commande. La zone par défaut est public.

MinimalMark

Obsolète. Cette option est ignorée et n'est plus utilisée. Les marques ne sont plus utilisées en interne.

CleanupModulesOnExit

Définir cette option sur oui ou vrai décharge tous les modules du noyau liés au pare-feu lorsque firewalld est arrêté. La valeur par défaut est non ou faux.

CleanupOnExit

Si firewalld s'arrête, il nettoie toutes les règles du pare-feu. Définir cette option sur non ou faux laisse les règles de pare-feu actuelles intactes. La valeur par défaut est oui ou vrai.

IPv6_rpfilter

Effectue un filtrage de chemin inverse (RPF) sur les paquets IPv6 conformément à la RFC 3704. Valeurs possibles : - strict : Effectue un filtrage « strict » conformément à la RFC 3704. Cette vérification s'assure que l'interface d'entrée est la même interface qui serait utilisée pour envoyer une réponse de paquet à la source. C'est-à-dire, entrée == sortie. - loose : Effectue un filtrage « lâche » conformément à la RFC 3704. Cette vérification s'assure uniquement qu'il existe une route de retour vers la source via n'importe quelle interface ; même si ce n'est pas celle sur laquelle le paquet est arrivé. - strict-forward : Ceci est presque identique à « lâche », mais n'effectue pas de RPF pour les paquets destinés à l'hôte (INPUT). - loose-forward : Ceci est presque identique à « lâche », mais n'effectue pas de RPF pour les paquets destinés à l'hôte (INPUT). - no : Le RPF est complètement désactivé. Le rp_filter pour IPv4 est contrôlé via sysctl.

Note : Cette fonctionnalité a un impact sur les performances. Dans la plupart des cas, l'impact n'est pas suffisant pour causer une différence notable. Elle nécessite des recherches de route et son exécution a lieu avant le chemin rapide des connexions établies. En tant que tel, elle peut avoir un impact significatif sur les performances s'il y a beaucoup de trafic. Elle est activée par défaut pour des raisons de sécurité, mais peut être désactivée si les performances sont une préoccupation. Alternativement, l'une des variantes qui ne fait du RPF que sur les paquets transférés peut être utilisée.

IndividualCalls

Si cette option est désactivée (elle l'est par défaut), des appels combinés -restore sont utilisés et non des appels individuels pour appliquer les changements au pare-feu. L'utilisation d'appels individuels augmente le temps nécessaire pour appliquer les changements et démarrer le démon, mais est utile pour le débogage car les messages d'erreur sont plus spécifiques.

LogDenied

Ajoute des règles de journalisation juste avant les règles reject et drop dans les chaînes INPUT, FORWARD et OUTPUT pour les règles par défaut ainsi que les règles reject et drop finales dans les zones pour le type de paquet de niveau lien configuré. Les valeurs possibles sont : all, unicast, broadcast, multicast et off. Le réglage par défaut est off, ce qui désactive la journalisation.

AutomaticHelpers

Obsolète. Cette option est ignorée et n'est plus utilisée.

FirewallBackend

Sélectionne l'implémentation du backend du pare-feu. Les valeurs possibles sont : nftables (par défaut), ou iptables. Ceci s'applique à toutes les primitives de firewalld. La seule exception concerne les règles directes et passthrough qui utilisent toujours les backends traditionnels iptables, ip6tables et ebtables.

Note : Le backend iptables est obsolète. Il sera supprimé dans une future version.

FlushAllOnReload

Vider toutes les règles d'exécution lors d'un rechargement. Dans les versions précédentes, une partie de la configuration d'exécution était conservée lors d'un rechargement, notamment : l'affectation d'interfaces aux zones et les règles directes. Cela était déroutant pour les utilisateurs. Pour obtenir l'ancien comportement, définissez cette option sur « non ». Par défaut, « oui ».

ReloadPolicy

La politique lors du rechargement. Par défaut, tout trafic à l'exception des connexions établies est rejeté pendant le rechargement des règles du pare-feu. Ceci peut être remplacé pour INPUT, FORWARD et OUTPUT. Les valeurs acceptées sont « DROP », « REJECT » et « ACCEPT », qui s'appliquent alors à toutes les tables. Alternativement, la politique peut être spécifiée par table, comme « INPUT:REJECT,FORWARD:DROP,OUTPUT:ACCEPT ». Par défaut : « INPUT:DROP,FORWARD:DROP,OUTPUT:DROP ».

RFC3964_IPv4

Conformément à la RFC 3964, filtre le trafic IPv6 avec des adresses de destination 6to4 qui correspondent à des adresses IPv4 qui ne devraient pas être acheminées sur l'internet public. Par défaut : « oui ».

StrictForwardPorts

Si défini sur oui, les règles de translation d'adresses NAT de destination (DNAT) générées N'ACCEPTERONT PAS le trafic qui a été DNATé par d'autres entités, par exemple docker. Firewalld sera strict et n'autorisera pas les ports de conteneur publiés tant qu'ils ne sont pas explicitement autorisés via firewalld. Si défini sur non, alors docker (et podman) s'intègre de manière transparente avec firewalld. Les ports de conteneur publiés sont implicitement autorisés. Par défaut : « non ».

AllowZoneDrifting

Obsolète. Cette option est ignorée et n'est plus utilisée.

NftablesFlowtable

Cela peut améliorer le débit du trafic transféré en activant la table de flux nftables. C'est un chemin rapide logiciel qui évite d'appeler l'évaluation des règles nftables pour les paquets de données. Sa valeur est une liste d'interfaces séparées par des espaces. Exemple de valeur : « eth0 eth1 ». Par défaut : « off ».

NftablesCounters

Si défini sur oui, ajoute un compteur à chaque règle nftables. Ceci est utile pour le débogage et entraîne un léger coût en termes de performances. Par défaut : « non ».

NftablesTableOwner

Si défini sur oui, l'ensemble de règles nftables généré sera exclusivement détenu par firewalld. Cela empêche d'autres entités de modifier involontairement (ou malicieusement) l'ensemble de règles de firewalld. Si vous modifiez intentionnellement les règles de firewalld, vous devrez définir cette option sur « non ». Par défaut : « oui ».
