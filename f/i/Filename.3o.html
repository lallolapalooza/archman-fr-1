Module NomDeFichier
: sig fin

Opérations sur les noms de fichiers.

val nom_repertoire_courant : string

Le nom conventionnel du répertoire courant (par exemple, . sous Unix).

val nom_repertoire_parent : string

Le nom conventionnel du répertoire parent du répertoire courant (par exemple, .. sous Unix).

val separateur_repertoire : string

Le séparateur de répertoire (par exemple, / sous Unix).

Depuis 3.11.2

val concatener : string -> string -> string

concatener dir fichier renvoie un nom de fichier désignant le fichier fichier dans le répertoire dir.

val est_relatif : string -> bool

Renvoie true si le nom de fichier est relatif au répertoire courant, false s'il est absolu (c'est-à-dire, sous Unix, commence par /).

val est_implicite : string -> bool

Renvoie true si le nom de fichier est relatif et ne commence pas par une référence explicite au répertoire courant ( ./ ou ../ sous Unix), false s'il commence par une référence explicite au répertoire racine ou au répertoire courant.

val verifier_suffixe : string -> string -> bool

verifier_suffixe nom suff renvoie true si le nom de fichier nom se termine par le suffixe suff.

Sous les ports Windows (y compris Cygwin), la comparaison ne tient pas compte de la casse, s'appuyant sur String.lowercase_ascii. Notez que cela ne correspond pas exactement à l'interprétation de l'équivalence des noms de fichiers non sensible à la casse de Windows.

val couper_suffixe : string -> string -> string

couper_suffixe nom suff supprime le suffixe suff du nom de fichier nom.

Lève Invalid_argument si nom ne se termine pas par le suffixe suff.

val couper_suffixe_opt : suffixe:string -> string -> string option

couper_suffixe_opt ~suffixe:nom_suffixe nom_fichier supprime le suffixe du nom_fichier si possible, ou renvoie None si le nom de fichier ne se termine pas par le suffixe.

Sous les ports Windows (y compris Cygwin), la comparaison ne tient pas compte de la casse, s'appuyant sur String.lowercase_ascii. Notez que cela ne correspond pas exactement à l'interprétation de l'équivalence des noms de fichiers non sensible à la casse de Windows.

Depuis 4.08

val extension : string -> string

extension nom est le plus court suffixe ext de nom0 où :

- nom0 est le plus long suffixe de nom qui ne contient pas de séparateur de répertoire ;

- ext commence par un point ;

- ext est précédé d'au moins un caractère non-point dans nom0.

Si un tel suffixe n'existe pas, extension nom est la chaîne vide.

Depuis 4.04

val supprimer_extension : string -> string

Renvoie le nom de fichier donné sans son extension, telle que définie dans NomDeFichier.extension. Si l'extension est vide, la fonction renvoie le nom de fichier donné.

L'invariant suivant est vrai pour tout nom de fichier s :

supprimer_extension s ^ extension s = s

Depuis 4.04

val couper_extension : string -> string

Identique à NomDeFichier.supprimer_extension, mais lève Invalid_argument si le nom donné a une extension vide.

val nom_base : string -> string

Sépare un nom de fichier en nom de répertoire / nom de fichier de base. Si nom est un nom de fichier valide, alors concatener (nom_repertoire nom) (nom_base nom) renvoie un nom de fichier équivalent à nom. De plus, après avoir défini le répertoire courant à nom_repertoire nom (avec Sys.chdir), les références à nom_base nom (qui est un nom de fichier relatif) désignent le même fichier que nom avant l'appel à Sys.chdir.

Cette fonction est conforme aux spécifications de POSIX.1-2008 pour l'utilitaire basename.

val nom_repertoire : string -> string

Voir NomDeFichier.nom_base. Cette fonction est conforme aux spécifications de POSIX.1-2008 pour l'utilitaire dirname.

val nul : string

nul est "/dev/null" sous POSIX et "NUL" sous Windows. Il représente un fichier sur le système d'exploitation qui ignore toutes les écritures et renvoie la fin de fichier à la lecture.

Depuis 4.10

val fichier_temporaire : ?temp_dir:string -> string -> string -> string

fichier_temporaire prefixe suffixe renvoie le nom d'un nouveau fichier temporaire dans le répertoire temporaire. Le nom de base du fichier temporaire est formé en concaténant prefixe, puis un nombre entier choisi de manière appropriée, puis suffixe. L'argument optionnel temp_dir indique le répertoire temporaire à utiliser, qui par défaut est le résultat courant de NomDeFichier.obtenir_nom_repertoire_temporaire. Le fichier temporaire est créé vide, avec des permissions de 0o600 (lisible et inscriptible uniquement par le propriétaire du fichier). Le fichier est garanti d'être différent de tout autre fichier existant au moment où fichier_temporaire a été appelé.

Avant 3.11.2 pas d'argument optionnel ?temp_dir

Lève Sys_error si le fichier n'a pas pu être créé.

val ouvrir_fichier_temporaire : ?mode:open_flag list -> ?perms:int -> ?temp_dir:string -> string -> string -> string * out_channel

Identique à NomDeFichier.fichier_temporaire, mais renvoie à la fois le nom d'un nouveau fichier temporaire et un canal de sortie ouvert (de manière atomique) sur ce fichier. Cette fonction est plus sûre que fichier_temporaire : il n'y a aucun risque que le fichier temporaire soit modifié (par exemple, remplacé par un lien symbolique) avant que le programme ne l'ouvre. L'argument optionnel mode est une liste de drapeaux supplémentaires pour contrôler l'ouverture du fichier. Il peut contenir une ou plusieurs des valeurs Open_append, Open_binary et Open_text. La valeur par défaut est [Open_text] (ouvert en mode texte). Le fichier est créé avec les permissions perms (par défaut, lisible et inscriptible uniquement par le propriétaire du fichier, 0o600).

Avant 4.03 pas d'argument optionnel ?perms

Avant 3.11.2 pas d'argument optionnel ?temp_dir

Lève Sys_error si le fichier n'a pas pu être ouvert.

val repertoire_temporaire : ?temp_dir:string -> ?perms:int -> string -> string -> string

repertoire_temporaire prefixe suffixe crée et renvoie le nom d'un nouveau répertoire temporaire avec les permissions perms (par défaut 0o700) à l'intérieur de temp_dir. Le nom de base du répertoire temporaire est formé en concaténant prefixe, puis un nombre entier choisi de manière appropriée, puis suffixe. L'argument optionnel temp_dir indique le répertoire temporaire à utiliser, qui par défaut est le résultat courant de NomDeFichier.obtenir_nom_repertoire_temporaire. Le répertoire temporaire est créé vide, avec des permissions de 0o700 (lisible, inscriptible et navigable uniquement par le propriétaire du fichier). Le répertoire est garanti d'être différent de tout autre répertoire existant au moment où repertoire_temporaire a été appelé.

Si temp_dir n'existe pas, cette fonction ne le crée pas. Au lieu de cela, elle lève Sys_error.

Depuis 5.1

Lève Sys_error si le répertoire n'a pas pu être créé.

val obtenir_nom_repertoire_temporaire : unit -> string

Le nom du répertoire temporaire : sous Unix, la valeur de la variable d'environnement TMPDIR, ou "/tmp" si la variable n'est pas définie.

Sous Windows, la valeur renvoyée par GetTempPath2 (si disponible) ou GetTempPath.

Le répertoire temporaire peut être modifié avec NomDeFichier.definir_nom_repertoire_temporaire.

Sous Windows, avant OCaml 5.4, il renvoyait la valeur de la variable d'environnement TEMP, ou "." si la variable n'était pas définie.

Depuis 4.00

val definir_nom_repertoire_temporaire : string -> unit

Change le répertoire temporaire renvoyé par NomDeFichier.obtenir_nom_repertoire_temporaire et utilisé par NomDeFichier.fichier_temporaire et NomDeFichier.ouvrir_fichier_temporaire. Le répertoire temporaire est une valeur locale au domaine qui est héritée par les domaines enfants.
