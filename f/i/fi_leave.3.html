NOM

fi_cm - Opérations de gestion des connexions

fi_connect / fi_listen / fi_accept / fi_reject / fi_shutdown
Gérer l'état de connexion d'un point de terminaison.
fi_setname / fi_getname / fi_getpeer
Définir l'adresse locale, ou renvoyer l'adresse locale ou du pair.
fi_join / fi_close / fi_mc_addr
Rejoindre, quitter ou récupérer une adresse de multidiffusion.

SYNOPSIS

#include <rdma/fi_cm.h>
int fi_connect(struct fid_ep *ep, const void *addr,
    const void *param, size_t paramlen);
int fi_listen(struct fid_pep *pep);
int fi_accept(struct fid_ep *ep, const void *param, size_t paramlen);
int fi_reject(struct fid_pep *pep, fid_t handle,
    const void *param, size_t paramlen);
int fi_shutdown(struct fid_ep *ep, uint64_t flags);
int fi_setname(fid_t fid, void *addr, size_t addrlen);
int fi_getname(fid_t fid, void *addr, size_t *addrlen);
int fi_getpeer(struct fid_ep *ep, void *addr, size_t *addrlen);
int fi_join(struct fid_ep *ep, const void *addr, uint64_t flags,
    struct fid_mc **mc, void *context);
int fi_close(struct fid *mc);
fi_addr_t fi_mc_addr(struct fid_mc *mc);

ARGUMENTS

ep / pep
Point de terminaison de tissu sur lequel changer l'état de connexion.

fid Point de terminaison actif ou passif pour obtenir/définir l'adresse.

addr
Tampon d'adresse. Lors d'un appel de définition, le point de terminaison se verra attribuer l'adresse spécifiée. Lors d'un appel de récupération, l'adresse locale sera copiée dans le tampon, dans la limite de l'espace fourni. Pour connect, ce paramètre indique l'adresse du pair à laquelle se connecter. L'adresse doit être dans le même format que celui spécifié via fi_info: addr_format lors de la création du point de terminaison.
addrlen
En entrée, spécifie la taille du tampon addr. En sortie, stocke le nombre d'octets écrits dans le tampon addr.
param
Données spécifiées par l'utilisateur et échangées dans le cadre de l'échange de connexion.
paramlen
Taille du tampon param.
info
Informations de tissu associées à une demande de connexion.
mc
Groupe de multidiffusion associé à un point de terminaison.
flags
Drapeaux supplémentaires pour contrôler l'opération de connexion.
context
Contexte utilisateur associé à la requête.

DESCRIPTION

Les fonctions de gestion des connexions sont utilisées pour connecter un point de terminaison orienté connexion (FI_EP_MSG) à un pair en écoute.

fi_listen

L'appel fi_listen indique que le point de terminaison spécifié doit passer à un état de connexion passif, lui permettant d'accepter les demandes de connexion entrantes. Les demandes de connexion adressées à un point de terminaison en écoute sont signalées de manière asynchrone à l'utilisateur via une file d'événements CM liée, en utilisant le type d'événement FI_CONNREQ. Le nombre de demandes de connexion en attente qui peuvent être mises en file d'attente sur un point de terminaison est limité par le paramètre backlog du point de terminaison en écoute. Le backlog est initialisé en fonction des valeurs de configuration administratives, mais peut être ajusté via l'appel fi_control.

fi_connect

L'appel fi_connect initie une demande de connexion sur un point de terminaison orienté connexion vers l'adresse de destination. fi_connect ne peut être appelé qu'une seule fois sur un point de terminaison au cours de sa durée de vie.

fi_accept / fi_reject

Les appels fi_accept et fi_reject sont utilisés sur le côté passif (en écoute) d'une connexion pour accepter ou rejeter une demande de connexion, respectivement. Pour accepter une connexion, l'application en écoute attend d'abord un événement de demande de connexion (FI_CONNREQ). Après avoir reçu un tel événement, l'application alloue un nouveau point de terminaison pour accepter la connexion. Ce point de terminaison doit être alloué en utilisant une structure fi_info faisant référence au handle de cet événement FI_CONNREQ. fi_accept est ensuite invoqué avec le point de terminaison nouvellement alloué. Si l'application en écoute souhaite rejeter une demande de connexion, elle appelle fi_reject avec le point de terminaison en écoute et une référence à la demande de connexion.

Une demande de connexion acceptée avec succès entraînera le fait que le point de terminaison actif (en cours de connexion) verra un événement FI_CONNECTED sur sa file d'événements associée. Une demande de connexion rejetée ou échouée générera un événement d'erreur. L'entrée d'erreur fournira des détails supplémentaires décrivant la raison de la tentative échouée.

Un événement FI_CONNECTED sera également généré sur le côté passif pour le point de terminaison acceptant une fois que la connexion a été établie correctement. Le fid de l'événement FI_CONNECTED sera celui du point de terminaison passé à fi_accept, par opposition au point de terminaison passif en écoute. Les transferts de données sortants ne peuvent pas être initiés sur un point de terminaison orienté connexion tant qu'un événement FI_CONNECTED n'a pas été généré. Cependant, les tampons de réception peuvent être associés à un point de terminaison à tout moment.

fi_shutdown

L'appel fi_shutdown est utilisé pour déconnecter gracieusement un point de terminaison de son pair. Le paramètre flags est réservé et doit être 0.

Les opérations en attente postées sur le point de terminaison lorsque fi_shutdown est appelé seront annulées ou abandonnées. La notification des opérations annulées sera rapportée par le fournisseur à la ou les files d'achèvement correspondantes. Les opérations abandonnées seront silencieusement supprimées, sans qu'aucun achèvement ne soit généré. Le choix d'annuler ou d'abandonner les opérations dépend du fournisseur. Cependant, tous les achèvements annulés seront écrits avant le retour de fi_shutdown.

Lorsqu'il est appelé, fi_shutdown n'affecte pas les achèvements déjà écrits dans une file d'achèvement. Tous les achèvements mis en file d'attente associés aux opérations asynchrones postées sur le point de terminaison peuvent toujours être récupérés depuis la ou les files d'achèvement correspondantes après qu'un point de terminaison a été arrêté.

Un événement FI_SHUTDOWN sera généré pour un point de terminaison lorsque le pair distant émet une déconnexion via fi_shutdown ou ferme brutalement le point de terminaison. Notez que dans le cas d'une fermeture brutale, un événement FI_SHUTDOWN ne sera généré que si le système du pair est joignable et qu'un service ou un agent noyau sur le système du pair est capable de notifier le point de terminaison local que la connexion a été interrompue.

fi_close

Fi_close est utilisé pour dissocier un point de terminaison d'un groupe de multidiffusion et fermer toutes les ressources associées au groupe. Fi_close doit être appelé sur tous les groupes de multidiffusion qu'un point de terminaison rejoint.

fi_setname

L'appel fi_setname peut être utilisé pour modifier ou attribuer l'adresse du point de terminaison local. Il est conceptuellement similaire à l'opération de liaison (bind) des sockets. Un point de terminaison peut se voir attribuer une adresse lors de sa création, via la structure fi_info. L'appel fi_setname permet à un point de terminaison d'être créé sans être associé à un service spécifique (par exemple, un numéro de port) et/ou à une adresse de nœud (par exemple, réseau), l'adressage étant attribué dynamiquement. Le format des données d'adressage spécifiées doit correspondre à celui spécifié via la structure fi_info lors de la création du point de terminaison.

Si aucune adresse de service n'est spécifiée et qu'une adresse de service n'a pas encore été attribuée au point de terminaison, alors le fournisseur allouera une adresse de service et l'attribuera au point de terminaison. Si une adresse de nœud ou de service est spécifiée, alors, à l'issue du succès de fi_setname, le point de terminaison se verra attribuer l'adressage donné. Si une adresse ne peut pas être attribuée, ou si l'adresse du point de terminaison ne peut pas être modifiée, un numéro d'erreur de tissu approprié est renvoyé.

fi_getname / fi_getpeer

Les appels fi_getname et fi_getpeer peuvent être utilisés pour récupérer respectivement l'adresse du point de terminaison local ou du pair. En entrée, le paramètre addrlen doit indiquer la taille du tampon addr. Si l'adresse réelle est plus grande que ce qui peut tenir dans le tampon, elle sera tronquée et -FI_ETOOSMALL sera renvoyé. En sortie, addrlen est défini à la taille du tampon nécessaire pour stocker l'adresse, qui peut être supérieure à la valeur d'entrée.

fi_getname n'est pas garanti de renvoyer une adresse source valide tant que le point de terminaison spécifié n'a pas été activé ou n'a pas reçu d'adresse assignée. Un point de terminaison peut être activé explicitement via fi_enable, ou implicitement, par exemple via fi_connect ou fi_listen. Une adresse peut être assignée à l'aide de fi_setname. fi_getpeer n'est pas garanti de renvoyer une adresse de pair valide tant qu'un point de terminaison n'a pas été complètement connecté – un événement FI_CONNECTED n'a pas été généré.

fi_join

Cette fonction attache un point de terminaison à un groupe de diffusion. Par défaut, le point de terminaison rejoint le groupe en se basant sur les capacités de transfert de données du point de terminaison. Par exemple, si le point de terminaison a été configuré pour à la fois envoyer et recevoir des données, alors le point de terminaison pourra initier et recevoir des transferts vers et depuis le groupe de diffusion. Les indicateurs de fi_join peuvent être utilisés pour restreindre l'accès au groupe de diffusion, sous réserve des limitations des capacités du point de terminaison.

Les opérations de jonction de diffusion s'achèvent de manière asynchrone. Un point de terminaison doit être lié à une file d'événements avant d'appeler fi_join. Le résultat de l'opération de jonction sera rapporté à la file d'événements (EQ) sous la forme d'un événement FI_JOIN_COMPLETE. Les applications ne peuvent pas émettre de transferts de diffusion tant qu'elles n'ont pas reçu la notification indiquant que l'opération de jonction est terminée. Notez qu'un point de terminaison peut commencer à recevoir des messages du groupe de diffusion dès que la jonction est terminée, ce qui peut survenir avant la génération de l'événement FI_JOIN_COMPLETE.

Les applications doivent appeler fi_close sur le groupe de diffusion pour déconnecter le point de terminaison du groupe. Après qu'une opération de jonction est terminée, l'appel fi_mc_addr peut être utilisé pour récupérer l'adresse associée au groupe de diffusion.

fi_mc_addr

Renvoie l'adresse fi_addr_t associée à un groupe de diffusion. Cette adresse doit être utilisée lors de la transmission de données à un groupe de diffusion et associée à l'indicateur d'opération FI_MULTICAST.

INDICATEURS

À l'exception des fonctions mentionnées ci-dessous, les indicateurs sont réservés et doivent être 0.

FI_SEND
S'applique à fi_join. Cet indique que le point de terminaison doit rejoindre le groupe de diffusion en tant que membre en émission seule. Le point de terminaison doit être configuré pour les opérations de transmission afin d'utiliser cet indicateur, sinon une erreur se produira.
FI_RECV
S'applique à fi_join. Cet indique que le point de terminaison doit rejoindre le groupe de diffusion avec des permissions de réception uniquement. Le point de terminaison doit être configuré pour les opérations de réception afin d'utiliser cet indicateur, sinon une erreur se produira.

VALEUR RENVOYÉE

Renvoie 0 en cas de succès. En cas d'erreur, une valeur négative correspondant à errno de fabric est renvoyée. Les valeurs de errno de fabric sont définies dans rdma/fi_errno.h.

ERREURS

NOTES

Pour les points de terminaison orientés connexion, le tampon auquel fait référence param sera envoyé dans le cadre de la requête ou de la réponse de connexion, sous réserve des contraintes du protocole de connexion sous-jacent. Les applications peuvent utiliser fi_getopt avec l'option de point de terminaison FI_OPT_CM_DATA_SIZE pour déterminer la taille des données applicatives qui peuvent être échangées dans le cadre d'une requête ou d'une réponse de connexion. Les appels fi_connect, fi_accept et fi_reject tronqueront silencieusement toute donnée applicative qui ne peut pas tenir dans les messages du protocole sous-jacent. Les données utilisateur échangées dans le cadre du processus de connexion sont disponibles dans la structure fi_eq_cm_entry, pour les événements FI_CONNREQ et FI_CONNECTED, ou comme err_data supplémentaire à fi_eq_err_entry, dans le cas d'une connexion rejetée.
