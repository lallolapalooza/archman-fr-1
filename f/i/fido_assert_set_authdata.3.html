DESCRIPTION

Les fonctions de la famille fido_assert_set_authdata définissent les différents paramètres d'une assertion FIDO2, permettant à un type fido_assert_t d'être préparé pour un appel ultérieur à fido_dev_get_assert(3) ou fido_assert_verify(3). Pour la spécification complète d'une assertion FIDO2 et le format de ses parties constitutives, veuillez vous référer à la norme Web Authentication (webauthn).

La fonction fido_assert_set_count() définit le nombre d'instructions d'assertion dans assert à n.

Les fonctions fido_assert_set_authdata() et fido_assert_set_sig() définissent les données de l'authentificateur et les parties de signature de l'instruction avec l'index idx de assert à ptr, où ptr pointe vers len octets. Une copie de ptr est faite, et aucune référence au pointeur passé n'est conservée. Veuillez noter que la première instruction d'assertion de assert a un idx de 0. Les données de l'authentificateur passées à fido_assert_set_authdata() doivent être une chaîne d'octets encodée en CBOR, telle qu'obtenue à partir de fido_assert_authdata_ptr(). Alternativement, un bloc binaire brut peut être passé à fido_assert_set_authdata_raw().

La fonction fido_assert_set_clientdata_hash() définit le hachage des données client de assert à ptr, où ptr pointe vers len octets. Une copie de ptr est faite, et aucune référence au pointeur passé n'est conservée.

La fonction fido_assert_set_clientdata() permet à une application de définir le hachage des données client de assert en spécifiant les données client non hachées de l'assertion. Ceci est requis par Windows Hello, qui calcule le hachage des données client en interne. Pour la compatibilité avec Windows Hello, les applications doivent utiliser fido_assert_set_clientdata() au lieu de fido_assert_set_clientdata_hash().

La fonction fido_assert_set_rp() définit l'id du partie de confiance (relying party) de assert, où id est une chaîne UTF-8 se terminant par un caractère nul. Le contenu de id est copié, et aucune référence au pointeur passé n'est conservée.

La fonction fido_assert_set_extensions() définit les extensions de assert au masque de bits flags. Pour le moment, seules les extensions FIDO_EXT_CRED_BLOB, FIDO_EXT_HMAC_SECRET et FIDO_EXT_LARGEBLOB_KEY sont prises en charge. Si flags est zéro, les extensions de assert sont effacées.

fido_assert_set_hmac_salt() et fido_assert_set_hmac_secret() définissent les parties hmac-salt et hmac-secret de assert à ptr, où ptr pointe vers len octets. Une copie de ptr est effectuée, et aucune référence au pointeur passé n'est conservée. L'extension HMAC Secret (hmac-secret) est une extension CTAP 2.0. Notez que le hmac-secret résultant varie selon que la vérification de l'utilisateur a été effectuée par l'authentificateur. La fonction fido_assert_set_hmac_secret() n'est normalement utile que lors de l'écriture de

tests.

Les fonctions fido_assert_set_up() et fido_assert_set_uv() définissent les attributs up (présence de l'utilisateur) et uv (vérification de l'utilisateur) de assert. Les deux sont FIDO_OPT_OMIT par défaut, permettant à l'authentificateur d'utiliser ses paramètres par

défaut.

La fonction fido_assert_set_winhello_appid() définit l'application U2F id (« U2F AppID ») de assert, où id est une chaîne UTF-8 terminée par NUL. Le contenu de id est copié, et aucune référence au pointeur passé n'est conservée. La fonction fido_assert_set_winhello_appid() est sans effet (no-op) sauf si assert est passé à fido_dev_get_assert(3) avec un appareil dev sur lequel fido_dev_is_winhello(3) est vrai. Dans ce cas, libfido2 demandera à Windows Hello d'essayer l'assertion deux fois, d'abord avec l' id passé à fido_assert_set_rp(), et une seconde fois avec l' id passé à fido_assert_set_winhello_appid(). Si la seconde assertion réussit, fido_assert_rp_id(3) pointera vers l'U2F AppID une fois fido_dev_get_assert(3) terminé. Ce mécanisme existe dans Windows Hello pour assurer la compatibilité ascendante avec U2F sans que l'application ne demande involontairement à l'utilisateur deux fois. Notez que fido_assert_set_winhello_appid() n'est pas nécessaire sur les plateformes offrant les primitives CTAP, car l'authentificateur peut être interrogé silencieusement pour l'existence d'identifiants

U2F.

L'utilisation de l'ensemble de fonctions fido_assert_set_authdata peut se produire dans deux situations distinctes : lors de la demande à un appareil FIDO2 de produire une série d'assertions, avant fido_dev_get_assert(3) (c'est-à-dire dans le contexte d'un client FIDO2), ou lors de la vérification d'assertions à l'aide de fido_assert_verify(3) (c'est-à-dire dans le contexte d'un serveur FIDO2)

.

Pour une description complète de la génération d'une assertion FIDO2 et de sa vérification, veuillez consulter la spécification FIDO2. Un exemple de l'utilisation de l'ensemble de fonctions fido_assert_set_authdata se trouve dans le fichier examples/assert.c fourni avec libf

ido2.

VALEURS DE

RETOUR

Les fonctions fido_assert_set_authdata retournent FIDO_OK en cas de succès. Les codes d'erreur retournés par l'ensemble de fonctions fido_assert_set_authdata sont définis dans <fido/er

r.h
>.
