DESCRIPTIO

N

Les opérations RMA (accès à la mémoire distante) sont utilisées pour transférer des données directement entre un tampon de données local et un tampon de données distant. Les transferts RMA se produisent au niveau de l'octet, et aucune limite de message n'est

maintenue.

Les fonctions d'écriture – fi_write, fi_writev, fi_writemsg, fi_inject_write et fi_writedata – sont utilisées pour transmettre des données vers un tampon de mémoire distant. La principale différence entre les fonctions d'écriture réside dans le nombre et le type de paramètres qu'elles acceptent en entrée. Sinon, elles effectuent la même fonction

générale.

Les fonctions de lecture – fi_read, fi_readv et fi_readmsg – sont utilisées pour transférer des données depuis une région de mémoire distante vers des tampons de données locaux. Comme pour les opérations d'écriture, les opérations de lecture fonctionnent de manière asynchrone. Les utilisateurs ne doivent pas toucher les tampons de données publiés tant que l'opération de lecture n'est pas

terminée.

Les opérations RMA terminées sont signalées à l'utilisateur via une ou plusieurs files de complétion associées au point de terminaison. Les utilisateurs fournissent un contexte qui est associé à chaque opération et qui est retourné à l'utilisateur dans le cadre de la complétion. Voir fi_cq pour les détails des événements de

complétion.

Par défaut, le point de terminaison distant ne génère pas d'événement ni ne notifie l'utilisateur lorsqu'une région de mémoire est accédée par une opération de lecture ou d'écriture RMA. Cependant, des données immédiates peuvent être associées à une opération d'écriture RMA. Les écritures RMA avec données immédiates généreront une entrée de complétion au point de terminaison distant, afin que les données immédiates puissent être

délivrées.

fi_readmsg / fi_writemsg remplacent la plupart des drapeaux configurés précédemment avec le point de terminaison, sauf indication contraire (voir fi_endpoint.3). La liste suivante de drapeaux est utilisable avec fi_readmsg et/ou fi_writemsg.

FI_REMOTE_CQ_DATA
S'applique à fi_writemsg. Indique que les données de la CQ distante sont disponibles et doivent être envoyées dans le cadre de la requête. Voir fi_getinfo pour plus de détails sur FI_REMOTE_CQ_DATA. Ce drapeau est implicitement défini pour fi_writedata et fi_inject_writedata.
FI_COMPLETION
Indique qu'une entrée d'achèvement doit être générée pour l'opération spécifiée. Le point de terminaison doit être lié à une file d'attente d'achèvement avec FI_SELECTIVE_COMPLETION qui correspond à l'opération spécifiée, sinon ce drapeau est ignoré.
FI_MORE
Indique que l'utilisateur a des requêtes supplémentaires qui seront immédiatement postées après le retour de l'appel actuel. L'utilisation de ce drapeau peut améliorer les performances en permettant au fournisseur d'optimiser son accès au matériel de la fabric.
FI_INJECT
S'applique à fi_writemsg. Indique que le tampon de données sortantes doit être retourné à l'utilisateur immédiatement après le retour de l'appel d'écriture, même si l'opération est gérée de manière asynchrone. Cela peut nécessiter que l'implémentation du fournisseur sous-jacent copie les données dans un tampon local et transfère à partir de ce tampon. Ce drapeau ne peut être utilisé qu'avec des messages plus petits que inject_size.
FI_INJECT_COMPLETE
S'applique à fi_writemsg. Indique qu'un achèvement doit être généré lorsque les tampons source peuvent être réutilisés.
FI_TRANSMIT_COMPLETE
S'applique à fi_writemsg. Indique qu'un achèvement ne doit pas être généré tant que l'opération n'a pas été transmise avec succès et n'est plus suivie par le fournisseur.
FI_DELIVERY_COMPLETE
S'applique à fi_writemsg. Indique qu'un achèvement doit être généré lorsque l'opération a été traitée par la destination.
FI_COMMIT_COMPLETE
S'applique à fi_writemsg lorsqu'il cible des régions de mémoire persistante. Indique qu'un achèvement doit être généré uniquement après que le résultat de l'opération a été rendu durable.
FI_FENCE
S'applique aux transmissions. Indique que l'opération demandée, également connue sous le nom d'opération clôturée, et toute opération postée après l'opération clôturée seront différées jusqu'à ce que toutes les opérations précédentes ciblant le même point de terminaison pair soient terminées. Les opérations postées après la clôture verront et/ou remplaceront les résultats de toute opération initiée avant l'opération clôturée.

L'ordre des opérations commençant par la publication de l'opération clôturée (incluse) jusqu'à la publication d'une opération clôturée subséquente (exclue) est contrôlé par les sémantiques d'ordre du point de terminaison.

RETURN VALUE

Retourne 0 en cas de succès. En cas d'erreur, une valeur négative correspondant à l'errno de fabric est retournée. Les valeurs d'errno de fabric sont définies dans rdma/fi_errno.h.

ERRORS

-FI_EAGAIN
Voir fi_msg(3) pour une description détaillée de la gestion de FI_EAGAIN.
