init_module(2) Manuel des appels système init_module(2)

NOM

init_module, finit_module - charger un module du noyau

BIBLIOTHQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/module.h>    /* Définition des constantes MODULE_* */
#include <sys/syscall.h>     /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(unsigned long taille;
            SYS_init_module,
            void image_module[taille], unsigned long taille,
            const char *valeurs_param);
int syscall(SYS_finit_module, int fd,
            const char *valeurs_param, int flags);

Note : glibc ne fournit pas de wrappers pour ces appels système, nécessitant l'utilisation de syscall(2).

DESCRIPTION

init_module() charge une image ELF dans l'espace noyau, effectue les éventuelles relocations de symboles nécessaires, initialise les paramètres du module aux valeurs fournies par l'appelant, puis exécute la fonction init du module. Cet appel système nécessite des privilèges.

L'argument image_module pointe vers un tampon contenant l'image binaire à charger ; taille spécifie la taille de ce tampon. L'image du module doit être une image ELF valide, construite pour le noyau en cours d'exécution.

L'argument valeurs_param est une chaîne contenant des spécifications séparées par des espaces des valeurs pour les paramètres du module (définis à l'intérieur du module à l'aide de module_param() et module_param_array()). Le noyau analyse cette chaîne et initialise les paramètres spécifiés. Chacune des spécifications de paramètre a la forme :

nom[=valeur[,valeur...]]

Le nom du paramètre est l'un de ceux définis dans le module à l'aide de module_param() (voir le fichier source du noyau Linux include/linux/moduleparam.h). La valeur du paramètre est optionnelle dans le cas des paramètres bool et invbool. Les valeurs pour les paramètres de tableau sont spécifiées sous forme de liste séparée par des virgules.

finit_module()

L'appel système finit_module() est similaire à init_module(), mais lit le module à charger à partir du descripteur de fichier fd. Il est utile lorsque l'authenticité d'un module du noyau peut être déterminée à partir de son emplacement dans le système de fichiers ; dans les cas où cela est possible, la surcharge liée à l'utilisation de modules signés cryptographiquement pour déterminer l'authenticité d'un module peut être évitée. L'argument valeurs_param est identique à celui de init_module().

L'argument flags modifie le comportement de finit_module(). C'est un masque de bits créé en combinant zéro ou plus des drapeaux suivants :

MODULE_INIT_IGNORE_MODVERSIONS
Ignore les hachages de version de symbole.
MODULE_INIT_IGNORE_VERMAGIC
Ignore le magic de version du noyau.
MODULE_INIT_COMPRESSED_FILE (depuis Linux 5.17)
Utilise la décompression de module dans le noyau.

Il existe des contrôles de sécurité intégrés dans un module pour s'assurer qu'il correspond au noyau sur lequel il est chargé. Ces contrôles sont enregistrés lors de la construction du module et vérifiés lors du chargement du module. Premièrement, le module enregistre une chaîne « vermagic » contenant le numéro de version du noyau et les caractéristiques principales (comme le type de CPU). Deuxièmement, si le module a été construit avec l'option de configuration CONFIG_MODVERSIONS activée, un hachage de version est enregistré pour chaque symbole utilisé par le module. Cet hachage est basé sur les types des arguments et la valeur de retour de la fonction nommée par le symbole. Dans ce cas, le numéro de version du noyau dans la chaîne « vermagic » est ignoré, car les hachages de version de symbole sont supposés être suffisamment fiables.

L'utilisation du drapeau MODULE_INIT_IGNORE_VERMAGIC indique que la chaîne « vermagic » doit être ignorée, et le drapeau MODULE_INIT_IGNORE_MODVERSIONS indique que les hachages de version de symbole doivent être ignorés. Si le noyau est construit pour permettre le chargement forcé (c'est-à-dire configuré avec CONFIG_MODULE_FORCE_LOAD), le chargement continue, sinon il échoue avec l'erreur ENOEXEC comme attendu pour les modules malformés.

Si le noyau a été construit avec CONFIG_MODULE_DECOMPRESS, la fonctionnalité de décompression dans le noyau peut être utilisée. Le code de l'espace utilisateur peut vérifier si le noyau prend en charge la décompression en lisant l'attribut /sys/module/compression. Si le noyau prend en charge la décompression, le fichier compressé peut être directement passé à finit_module() en utilisant le drapeau MODULE_INIT_COMPRESSED_FILE. Le décompresseur de modules dans le noyau prend en charge les algorithmes de compression suivants :

•
gzip (depuis Linux 5.17)
•
xz (depuis Linux 5.17)
•
zstd (depuis Linux 6.2)

Le noyau n'implémente qu'une seule méthode de décompression. Celle-ci est sélectionnée lors de la génération du module en fonction de la méthode de compression choisie dans la configuration du noyau.

VALEUR DE RETOUR

En cas de succès, ces appels système retournent 0. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EBADMSG (depuis Linux 3.7)
La signature du module est mal formatée.
EBUSY
Délai d'attente lors de la tentative de résolution d'une référence de symbole par ce module.
EFAULT
Un argument d'adresse faisait référence à un emplacement en dehors de l'espace d'adressage accessible du processus.
ENOKEY (depuis Linux 3.7)
La signature du module est invalide ou le noyau ne possède pas de clé pour ce module. Cette erreur n'est retournée que si le noyau a été configuré avec CONFIG_MODULE_SIG_FORCE ; si le noyau n'a pas été configuré avec cette option, un module invalide ou non signé « salit » simplement le noyau.
ENOMEM
Pas assez de mémoire.
EPERM
L'appelant n'avait pas les privilèges (ne possédait pas la capacité CAP_SYS_MODULE), ou le chargement de modules est désactivé (voir /proc/sys/kernel/modules_disabled dans proc(5)).

Les erreurs suivantes peuvent survenir en plus pour init_module :

EEXIST
Un module portant ce nom est déjà chargé.
EINVAL
valeurs_param est invalide, ou une partie de l'image ELF dans image_module contient des incohérences.
ENOEXEC
L'image binaire fournie dans image_module n'est pas une image ELF, ou est une image ELF invalide ou pour une architecture différente.

Les erreurs suivantes peuvent survenir en plus pour finit_module :

EBADF
Le fichier référencé par fd n'est pas ouvert en lecture.
EFBIG
Le fichier référencé par fd est trop grand.
EINVAL
flags est invalide.
EINVAL
Les vérifications d'intégrité du décompresseur ont échoué, lors du chargement d'un module compressé avec le drapeau MODULE_INIT_COMPRESSED_FILE défini.
ENOEXEC
fd ne fait pas référence à un fichier ouvert.

L'appel système init_module() n'est pas pris en charge par glibc. Aucune déclaration n'est fournie dans les en-têtes de glibc, mais, à cause d'un particularisme historique, les versions de glibc antérieures à glibc 2.23 exportaient bien une ABI pour cet appel système. Par conséquent, afin d'utiliser cet appel système, il suffit (avant glibc 2.23) de déclarer manuellement l'interface dans votre code ; ou, alternativement, vous pouvez invoquer l'appel système en utilisant syscall

(2).
