File::Slurp(3) Documentation Perl contribuée par les utilisateurs File::Slurp(3)

NOM

File::Slurp - Lecture/écriture/modification simples et efficaces de fichiers complets

SYNOPSIS

use File::Slurp;
# lire un fichier entier dans un scalaire
my $text = read_file('/path/file');
# lire un fichier entier dans un tableau de lignes
my @lines = read_file('/path/file');
# écrire un fichier entier à partir d'un scalaire
write_file('/path/file', $text);
# écrire un fichier entier à partir d'un tableau de lignes
write_file('/path/file', @lines);
# Voici une méthode simple et rapide pour charger et sauvegarder un fichier de configuration simple
# composé de lignes clé=valeur.
my %conf = read_file('/path/file') =~ /^(\w+)=(.*)$/mg;
write_file('/path/file', {atomic => 1}, map "$_=$conf{$_}\n", keys %conf);
# insérer du texte au début d'un fichier
prepend_file('/path/file', $text);
# édition sur place pour remplacer toutes les occurrences de 'foo' par 'bar' dans le fichier
edit_file { s/foo/bar/g } '/path/file';
# édition sur place pour supprimer toutes les lignes contenant 'foo' du fichier
edit_file_lines sub { $_ = '' if /foo/ }, '/path/file';
# lire tous les noms de fichiers d'un répertoire (en ignorant . et ..)
my @files = read_dir('/path/to/dir');

DESCRIPTION

Ce module fournit des sous-programmes qui vous permettent de lire ou d'écrire des fichiers entiers avec un seul appel simple. Ils sont conçus pour être simples à utiliser, offrent des moyens flexibles de passer ou d'obtenir le contenu des fichiers et sont très efficaces. Il existe également un sous-programme pour lire tous les fichiers d'un répertoire.

AVERTISSEMENT - RUINE IMMINENTE

Bien que vous puissiez techniquement le faire, n'utilisez PAS ce module pour travailler avec des descripteurs de fichiers, des tubes, des sockets, l'entrée/sortie standard, ou le "DATA" handle. Ce sont des fonctionnalités implémentées il y a longtemps qui ne devraient vraiment pas être détournées ici.

Soyez averti : cette activité entraînera un encodage/décodage inexact des données.

Toutes les mentions ultérieures d'actions sur les éléments ci-dessus ont été supprimées de cette documentation et cet ensemble de fonctionnalités sera probablement déprécié à l'avenir.

En d'autres termes, si vous n'avez pas de nom de fichier à passer, envisagez d'utiliser le standard "do { local $/; <$fh> }", ou Data::Section/Data::Section::Simple pour travailler avec "__DATA__".

FONCTIONS

File::Slurp implémente les fonctions suivantes.

append_file

use File::Slurp qw(append_file write_file);
my $res = append_file('/path/file', "Some text");
# équivalent à
my $res = write_file('/path/file', {append => 1}, "Some text");

La fonction "append_file" est simplement un synonyme pour la fonction "write_file" de File::Slurp, mais garantit que l'option "append" est définie.

edit_file

use File::Slurp qw(edit_file);
# perl -0777 -pi -e 's/foo/bar/g' /path/file
edit_file { s/foo/bar/g } '/path/file';
edit_file sub { s/foo/bar/g }, '/path/file';
sub replace_foo { s/foo/bar/g }
edit_file \&replace_foo, '/path/file';

La fonction "edit_file" lit un fichier dans $_, exécute un bloc de code qui doit modifier $_, puis réécrit $_ dans le fichier. La fonction "edit_file" lit le fichier entier et appelle le bloc de code une seule fois. Elle est équivalente aux options de ligne de commande "-pi" de Perl, mais vous pouvez l'appeler depuis l'intérieur de votre programme sans avoir à créer un processus enfant.

Le premier argument de "edit_file" est un bloc de code ou une référence de code. Le bloc de code n'est pas suivi d'une virgule (contrairement à "grep" et "map") mais une référence de code est suivie d'une virgule.

L'argument suivant est le nom de fichier.

L'argument (ou les arguments) suivant est soit une référence de hash, soit un hash aplati, des paires "clé => valeur" . Les options sont transmises à la fonction "write_file" de File::Slurp. Toutes les options sont décrites là-bas. Seules les options "binmode" et "err_mode" sont prises en charge. L'appel à "write_file" de File::Slurp a l'option "atomic" définie, vous aurez donc toujours un fichier cohérent.

edit_file_lines

use File::Slurp qw(edit_file_lines);
# perl -pi -e '$_ = "" if /foo/' /path/file
edit_file_lines { $_ = '' if /foo/ } '/path/file';
edit_file_lines sub { $_ = '' if /foo/ }, '/path/file';
sub delete_foo { $_ = '' if /foo/ }
edit_file \&delete_foo, '/path/file';

La fonction "edit_file_lines" lit chaque ligne d'un fichier dans $_, et exécute un bloc de code qui doit modifier $_. Elle réécrit ensuite $_ dans le fichier. Elle est équivalente aux options de ligne de commande "-pi" de Perl, mais vous pouvez l'appeler depuis l'intérieur de votre programme sans avoir à créer un processus enfant.

Le premier argument de "edit_file_lines" est un bloc de code ou une référence de code. Le bloc de code n'est pas suivi d'une virgule (contrairement à "grep" et "map") mais une référence de code est suivie d'une virgule.

L'argument suivant est le nom de fichier.

L'argument (ou les arguments) suivant est soit une référence de hash, soit un hash aplati, des paires "clé => valeur" . Les options sont transmises à la fonction "write_file" de File::Slurp. Toutes les options sont décrites là-bas. Seules les options "binmode" et "err_mode" sont prises en charge. L'appel à "write_file" de File::Slurp a l'option "atomic" définie, vous aurez donc toujours un fichier cohérent.

use File::Slurp qw(ef);
# perl -0777 -pi -e 's/foo/bar/g' /path/file
ef { s/foo/bar/g } '/path/file';
ef sub { s/foo/bar/g }, '/path/file';
sub replace_foo { s/foo/bar/g }
ef \&replace_foo, '/path/file';

La fonction "ef" est simplement un synonyme pour la fonction "edit_file" de File::Slurp.

efl

use File::Slurp qw(efl);
# perl -pi -e '$_ = "" if /foo/' /path/file
efl { $_ = '' if /foo/ } '/path/file';
efl sub { $_ = '' if /foo/ }, '/path/file';
sub delete_foo { $_ = '' if /foo/ }
efl \&delete_foo, '/path/file';

La fonction "efl" est simplement un synonyme pour la fonction "edit_file_lines" de File::Slurp.

overwrite_file

use File::Slurp qw(overwrite_file);
my $res = overwrite_file('/path/file', "Some text");

La fonction "overwrite_file" est simplement un synonyme pour la fonction "write_file" de File::Slurp.

prepend_file

use File::Slurp qw(prepend_file);
prepend_file('/path/file', $header);
prepend_file('/path/file', \@lines);
prepend_file('/path/file', { binmode => ':raw'}, $bin_data);
# équivalent à :
use File::Slurp qw(read_file write_file);
my $content = read_file('/path/file');
my $new_content = "hahahaha";
write_file('/path/file', $new_content . $content);

La fonction "prepend_file" est l'opposée de "append_file" de File::Slurp car elle écrit de nouveaux contenus au début du fichier au lieu de la fin. C'est une combinaison de "read_file" de File::Slurp et de "write_file" de File::Slurp. Elle fonctionne en utilisant d'abord "read_file" pour lire le fichier en mémoire, puis en appelant "write_file" avec les nouvelles données et les données du fichier existant.

Le premier argument de "prepend_file" est le nom de fichier.

L'argument (ou les arguments) suivant est soit une référence de hash, soit un hash aplati, des paires "clé => value". Les options sont transmises à la fonction "write_file" de File::Slurp. Toutes les options y sont décrites.

Seules les options "binmode" et "err_mode" sont prises en charge. L'appel à "write_file" a l'option "atomic" définie de manière à ce que vous disposiez toujours d'un fichier cohérent.

read_dir

use File::Slurp qw(read_dir);
my @files = read_dir('/path/to/dir');
# tous les fichiers, même les points
my @files = read_dir('/path/to/dir', keep_dot_dot => 1);
# garder le chemin complet du fichier
my @paths = read_dir('/path/to/dir', prefix => 1);
# contexte scalaire
my $files_ref = read_dir('/path/to/dir');

Cette fonction renvoie une liste des noms de fichiers dans le répertoire fourni. En contexte de liste, un tableau est renvoyé, en contexte scalaire, une référence de tableau est renvoyée.

Le premier argument est le chemin d'accès au répertoire à lire.

L'argument ou les arguments suivants est soit une référence de hachage, soit un hachage aplati, des paires "clé => valeur". Les options suivantes sont disponibles :

  • err_mode

    L'option "err_mode" a trois valeurs possibles : "quiet", "carp", ou par défaut, "croak". En mode "quiet", toutes les erreurs seront silencieuses. En mode "carp", toutes les erreurs seront émises sous forme d'avertissements. Et, en mode "croak", toutes les erreurs seront émises sous forme d'exceptions. Jetez un œil à Try::Tiny ou Syntax::Keyword::Try pour savoir comment intercepter les exceptions.

  • keep_dot_dot

    L'option "keep_dot_dot" est une option booléenne, par défaut à faux (0). La définir sur vrai (1) renverra également les fichiers "." et ".." qui sont supprimés de la liste des fichiers par défaut.

  • prefix

    L'option "prefix" est une option booléenne, par défaut à faux (0). La définir sur vrai (1) ajoutera le répertoire comme préfixe au fichier. Le répertoire et le nom de fichier sont joints en utilisant "File::Spec->catfile()" pour garantir que le séparateur de répertoire approprié est utilisé pour votre système d'exploitation. Voir File::Spec.

read_file

use File::Slurp qw(read_file);
my $text = read_file('/path/file');
my $bin = read_file('/path/file', { binmode => ':raw' });
my @lines = read_file('/path/file');
my $lines_ref = read_file('/path/file', array_ref => 1);
my $lines_ref = [ read_file('/path/file') ];
# ou nous pouvons lire dans un tampon :
my $buffer;
read_file('/path/file', buf_ref => \$buffer);
# ou nous pouvons définir la taille du bloc pour la lecture
my $text_ref = read_file('/path/file', blk_size => 10_000_000, array_ref => 1);
# ou nous pouvons obtenir une référence scalaire
my $text_ref = read_file('/path/file', scalar_ref => 1);

Cette fonction lit un fichier entier et renvoie son contenu à l'appelant. En contexte scalaire, elle renvoie le fichier entier sous forme d'un seul scalaire. En contexte de liste, elle renverra une liste de lignes (en utilisant la valeur actuelle de $/ comme séparateur, y compris la prise en charge du mode paragraphe lorsqu'il est défini sur '').

Le premier argument est le chemin d'accès au fichier à lire.

L'argument ou les arguments suivants est soit une référence de hachage, soit un hachage aplati, des paires "clé => valeur". Les options suivantes sont disponibles :

  • array_ref

    L'option "array_ref" est une option booléenne, par défaut à faux (0). La définir sur vrai (1) n'aura de pertinence que si la fonction "read_file" est appelée en contexte scalaire. Lorsqu'elle est vraie, la fonction "read_file" renverra une référence à un tableau des lignes du fichier.

  • binmode

    L'option "binmode" est une option de type chaîne, par défaut vide (''). Si vous définissez l'option "binmode", sa valeur est transmise à un appel à "binmode" sur le descripteur ouvert. Vous pouvez l'utiliser pour définir le fichier à lire en mode binaire, utf8, etc. Voir "perldoc -f binmode" pour plus d'informations.

  • blk_size

    Vous pouvez utiliser cette option pour définir la taille du bloc utilisée lors de la lecture à partir d'un descripteur déjà ouvert (comme "\*STDIN"). Elle est par défaut à 1 Mo.

  • buf_ref

    L'option "buf_ref" peut être utilisée conjointement avec toutes les autres options. Vous pouvez utiliser cette option pour passer une référence scalaire et le contenu du fichier lus sera stocké dans le scalaire. Cela évite une copie supplémentaire du fichier lu et peut réduire l'utilisation de la RAM par rapport au retour du fichier. C'est généralement le moyen le plus rapide de lire un fichier dans un scalaire.

  • chomp

    L'option "chomp" est une option booléenne, par défaut à faux (0). La définir sur vrai (1) provoquera le "chomp" de chaque ligne. Cette option fonctionne en contexte de liste ou en contexte scalaire avec l'option "array_ref".

  • err_mode

    L'option "err_mode" a trois valeurs possibles : "quiet", "carp", ou par défaut, "croak". En mode "quiet", toutes les erreurs seront silencieuses. En mode "carp", toutes les erreurs seront émises sous forme d'avertissements. Et, en mode "croak", toutes les erreurs seront émises sous forme d'exceptions. Jetez un œil à Try::Tiny ou Syntax::Keyword::Try pour savoir comment intercepter les exceptions.

  • scalar_ref

    L'option "scalar_ref" est une option booléenne, par défaut à faux (0). Elle n'a de signification qu'en contexte scalaire. La valeur de retour sera une référence scalaire vers une chaîne qui est le contenu du fichier lu. Ce sera généralement plus rapide que de renvoyer le scalaire brut. Cela économisera également de la mémoire car cela ne fera pas de copie du fichier à renvoyer.

use File::Slurp qw(rf);
my $text = rf('/path/file');

La fonction "rf" est simplement un synonyme de la fonction "read_file" de File::Slurp.

slurp

use File::Slurp qw(slurp);
my $text = slurp('/path/file');

La fonction "slurp" est simplement un synonyme de la fonction "read_file" de File::Slurp.

wf

use File::Slurp qw(wf);
my $res = wf('/path/file', "Some text");

La fonction "wf" est simplement un synonyme de la fonction "write_file" de File::Slurp.

write_file

use File::Slurp qw(write_file);
write_file('/path/file', @data);
write_file('/path/file', {append => 1}, @data);
write_file('/path/file', {binmode => ':raw'}, $buffer);
write_file('/path/file', \$buffer);
write_file('/path/file', $buffer);
write_file('/path/file', \@lines);
write_file('/path/file', @lines);
# binmode
write_file('/path/file', {binmode => ':raw'}, @data);
write_file('/path/file', {binmode => ':utf8'}, $utf_text);
# buffered
write_file('/path/file', {buf_ref => \$buffer});
write_file('/path/file', \$buffer);
write_file('/path/file', $buffer);
# append
write_file('/path/file', {append => 1}, @data);
# no clobbering
write_file('/path/file', {no_clobber => 1}, @data);

Cette fonction écrit un fichier entier en un seul appel. Par défaut, "write_file" renvoie 1 en cas de succès de l'écriture du fichier ou "undef" s'il a rencontré une erreur. Vous pouvez modifier la manière dont les erreurs sont gérées avec l'option "err_mode".

Le premier argument de "write_file" est le nom du fichier.

L'argument ou les arguments suivants est soit une référence de hachage, soit un hachage aplati, des paires "clé => valeur". Les options suivantes sont disponibles :

  • append

    L'option "append" est une option booléenne, par défaut à faux (0). La définir sur vrai (1) provoquera l'écriture des données à la fin du fichier actuel. Interne, cela définit l'indicateur de mode "sysopen" "O_APPEND".

    La fonction "append_file" de File::Slurp définit cette option par défaut.

  • atomic

    L'option "atomic" est une option booléenne, par défaut à faux (0). La définir sur vrai (1) provoquera l'écriture du fichier de manière atomique. Un nom de fichier temporaire est créé en utilisant "tempfile" de File::Temp. Après la fermeture du fichier, il est renommé avec le nom de fichier d'origine (et "rename" est une opération atomique sur la plupart des systèmes d'exploitation). Si le programme utilisant ceci crashait au milieu de cette opération, le fichier temporaire pourrait rester.

  • binmode

    L'option "binmode" est une option de type chaîne, par défaut vide (''). Si vous définissez l'option "binmode", sa valeur est transmise à un appel à "binmode" sur le descripteur ouvert. Vous pouvez l'utiliser pour définir le fichier à lire en mode binaire, utf8, etc. Voir "perldoc -f binmode&quo t; pour plus de détails.

  • buf_ref

    L'option "buf_ref" est utilisée pour passer une référence scalaire contenant les données à écrire. Si cette option est définie, tous les arguments de données (y compris le raccourci de référence scalaire) dans @_ seront ignorés.

  • err_mode

    L'option "err_mode" possède trois valeurs possibles : "quiet", "carp", ou, par défaut, "croak". En mode "quiet" , toutes les erreurs seront silencieuses. En mode "carp" , toutes les erreurs seront émises sous forme d'avertissements. Et, en mode "croak" , toutes les erreurs seront émises sous forme d'exceptions. Consultez Try::Tiny ou Syntax::Keyword::Try pour savoir comment capturer les exceptions.

  • no_clobber

    L'option "no_clobber" est une option booléenne, dont la valeur par défaut est false (0). Définir cette option à true (1) garantira qu'un fichier existant ne sera pas écrasé.

  • perms

    L'option "perms" définit les permissions des fichiers nouvellement créés. Cette valeur est modifiée par le "umask" de votre processus et vaut par défaut 0666 (identique à "sysopen").

    NOTE : cette option est nouvelle depuis la version 9999.14 de File::Slurp.

EXPORT

Ceux-ci sont exportés par défaut ou avec

use File::Slurp qw(:std);
# read_file write_file overwrite_file append_file read_dir

Ceux-ci sont exportés avec

use File::Slurp qw(:edit);
# edit_file edit_file_lines

Vous pouvez exporter toutes les sous-routines du module avec

use File::Slurp qw(:all);

VOIR AUSSI

  • File::Slurper - Fournit un ensemble simple de fonctions pour les tâches les plus courantes de lecture/écriture de fichiers texte et binaires.
  • Path::Tiny - Manipulation de fichiers légère et complète, incluant des méthodes simples pour lire, écrire et modifier des fichiers texte et binaires.
  • Mojo::File - Similaire à Path::Tiny pour la boîte à outils Mojo, fonctionne toujours en octets.
