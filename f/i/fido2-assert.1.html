FIDO2-ASSERT(1) Manuel des commandes générales FIDO2-ASSERT(1)

NOM

fido2-assert — obtenir/vérifier une assertion FIDO2

SYNOPSIS

fido2-assert -G [-bdhpruvw] [-t option] [-i fichier_entrée] [-o fichier_sortie] périphérique

fido2-assert -V [-dhpv] [-i fichier_entrée] fichier_cle [type]

DESCRIPTION

fido2-assert obtient ou vérifie une assertion FIDO2.

L'entrée de fido2-assert est définie par les paramètres de l'assertion à obtenir/vérifier. Voir la section FORMAT D'ENTRÉE pour plus de détails.

La sortie de fido2-assert est définie par le résultat de l'opération sélectionnée. Voir la section FORMAT DE SORTIE pour plus de détails.

Si une assertion est obtenue ou vérifiée avec succès, fido2-assert se termine avec le code 0. Sinon, fido2-assert se termine avec le code 1.

Les options sont les suivantes :

-G
Indique à fido2-assert d'obtenir une nouvelle assertion depuis périphérique.
-V
Indique à fido2-assert de vérifier une assertion à l'aide de la clé publique encodée en PEM dans fichier_cle de type type, où type peut être es256 (désignant ECDSA sur NIST P-256 avec SHA-256), es384 (désignant ECDSA sur NIST P-384 avec SHA-384), rs256 (désignant RSA 2048 bits avec rembourrage PKCS#1.5 et SHA-256), ou eddsa (désignant EDDSA sur Curve25519 avec SHA-512). Si type n'est pas spécifié, es256 est supposé.
-b
Demande le « largeBlobKey » de l'identifiant d'accès, une clé symétrique de 32 octets associée à l'identifiant d'accès asserté.
-h
Lors de l'obtention d'une assertion, active l'extension hmac-secret FIDO2. Lors de la vérification d'une assertion, vérifie si le bit de données de l'extension a été signé par l'authentificateur.
-d
Fait que fido2-assert émet une sortie de débogage sur stderr.
-i fichier_entrée
Indique à fido2-assert de lire les paramètres de l'assertion depuis fichier_entrée au lieu de stdin.
-o fichier_sortie
Indique à fido2-assert d'écrire la sortie sur fichier_sortie au lieu de stdout.
-p
Lors de l'obtention d'une assertion, demande la présence de l'utilisateur. Lors de la vérification d'une assertion, vérifie si le bit de présence de l'utilisateur a été signé par l'authentificateur.
-r
Obtient une assertion à l'aide d'un identifiant d'accès résident. Si -r est spécifié, fido2-assert ne s'attendra pas à recevoir un identifiant d'accès dans son entrée, et peut produire plusieurs assertions. Les identifiants d'accès résidents sont appelés « identifiants d'accès découvrables » dans CTAP 2.1.
-t option
Bascule une option clé/valeur, où option est une chaîne de la forme « clé=valeur ». Les options prises en charge actuellement sont :
up=true|false
Demande à l'authentificateur d'activer ou de désactiver la présence de l'utilisateur.
uv=true|false
Demande à l'authentificateur d'activer ou de désactiver la vérification de l'utilisateur.
pin=true|false
Indique à fido2-assert s'il doit demander un code PIN et demander la vérification de l'utilisateur.

L'option -t peut être spécifiée plusieurs fois.

-u
Obtient une assertion à l'aide de U2F. Par défaut, fido2-assert utilisera FIDO2 si l'authentificateur le prend en charge, et reviendra à U2F sinon.
-v
Lors de l'obtention d'une assertion, demande à l'utilisateur un code PIN et demande la vérification de l'utilisateur à l'authentificateur. Lors de la vérification d'une assertion, vérifie si le bit de vérification de l'utilisateur a été signé par l'authentificateur.
-w
Indique à fido2-assert que la première ligne d'entrée lors de l'obtention d'une assertion doit être interprétée comme des données client non hachées. Ceci est requis par Windows Hello, qui calcule l'empreinte des données client en interne.

Si un tty est disponible, fido2-assert l'utilisera pour obtenir le code PIN. Sinon, stdin est utilisé.

FORMAT D'ENTRÉE

L'entrée de fido2-assert se compose de blobs base64 et de chaînes UTF-8 séparés par des caractères de nouvelle ligne ('\n').

Lors de l'obtention d'une assertion, fido2-assert attend que son entrée se compose de :

  1. empreinte des données client (blob base64) ;
  2. identifiant du tiers de confiance (chaîne UTF-8) ;
  3. identifiant d'accès, si l'identifiant d'accès n'est pas résident (blob base64) ;
  4. sel hmac, si l'extension hmac-secret FIDO2 est activée (blob base64) ;

Lors de la vérification d'une assertion, fido2-assert attend que son entrée se compose de :

  1. empreinte des données client (blob base64) ;
  2. identifiant du tiers de confiance (chaîne UTF-8) ;
  3. données d'authentificateur encodées en CBOR (blob base64) ;
  4. signature de l'assertion (blob base64) ;

Les chaînes UTF-8 passées à fido2-assert ne doivent pas contenir de caractères de nouvelle ligne ou NUL incorporés.

FORMAT DE SORTIE

La sortie de fido2-assert se compose de blobs base64 et de chaînes UTF-8 séparés par des caractères de nouvelle ligne ('\n').

Pour chaque assertion générée, fido2-assert produit :

  1. empreinte des données client (blob base64) ;
  2. identifiant du tiers de confiance (chaîne UTF-8) ;
  3. données d'authentificateur encodées en CBOR (blob base64) ;
  4. signature de l'assertion (blob base64) ;
  5. identifiant utilisateur, si l'identifiant d'accès est résident (blob base64) ;
  6. secret hmac, si l'extension hmac-secret FIDO2 est activée (blob base64) ;
  7. la clé symétrique de 32 octets associée à l'identifiant d'accès (« largeBlobKey »), si demandée (blob base64).

Lors de la vérification d'une assertion, fido2-assert ne produit aucune sortie.

EXEMPLES

En supposant que cred contient un identifiant d'accès es256 créé selon les étapes décrites dans fido2-cred(1), obtenez unen assertion d'un authentificateur à /dev/hidraw5 et la vérifier :

$ echo assertion challenge | openssl sha256 -binary | base64 > assert_param
$ echo relying party >> assert_param
$ head -1 cred >> assert_param
$ tail -n +2 cred > pubkey
$ fido2-assert -G -i assert_param /dev/hidraw5 | fido2-assert -V pubkey es256
