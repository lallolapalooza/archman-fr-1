DESCRIPTION

Un fournisseur de tissu (fabric provider) implémente les interfaces logicielles destinées à l'application, nécessaires pour accéder aux protocoles, pilotes et matériels spécifiques au réseau. Les interfaces et structures définies par cette page man sont exportées par la bibliothèque libfabric, mais elles sont destinées aux implémentations de fournisseurs plutôt qu'à une utilisation directe par la plupart des applications.

Les fournisseurs intégrés sont ceux construits directement dans la bibliothèque libfabric elle-même. Les fournisseurs externes sont chargés dynamiquement par libfabric au moment de l'initialisation. Les fournisseurs externes doivent se trouver dans un chemin de bibliothèque standard ou dans le chemin de recherche des bibliothèques libfabric spécifié par une variable d'environnement. De plus, les fournisseurs externes doivent être nommés avec le suffixe « -fi.so » à la fin du nom.

Les objets nommés sont des ressources à usage spécial accessibles directement aux applications. Ils peuvent être utilisés pour améliorer ou modifier le comportement du noyau de la bibliothèque. Pour plus de détails, voir l'appel fi_open ci-dessous.

fi_prov_ini

Ce point d'entrée doit être défini par les fournisseurs externes. Au chargement, libfabric invoquera fi_prov_ini() pour récupérer la structure fi_provider du fournisseur. Les interactions supplémentaires entre le noyau libfabric et le fournisseur se feront via les interfaces définies par cette structure.

fi_param_define

Définit un paramètre de configuration pour un fournisseur spécifié. Les arguments help_string et param_name doivent être non-NULL, help_string doit en outre être non vide. Ils sont copiés en interne et peuvent être libérés après l'appel à fi_param_define.

fi_param_get

Récupère la valeur d'un paramètre de configuration défini précédemment à l'aide de fi_param_define(). La valeur provient de la variable d'environnement nommée sous la forme FI__, le tout converti en majuscules.

Si le paramètre a été défini précédemment et que l'utilisateur a défini une valeur, FI_SUCCESS est renvoyé et (*value) pointe vers la valeur récupérée.

Si le nom du paramètre a été défini précédemment, mais que l'utilisateur n'a pas défini de valeur, -FI_ENODATA est renvoyé et la valeur de (*value) est inchangée.

Si le nom du paramètre n'a pas été défini précédemment via fi_param_define(), -FI_ENOENT sera renvoyé et la valeur de (*value) est inchangée.

Si la valeur dans l'environnement n'est pas valide pour le type de paramètre, -FI_EINVAL sera renvoyé et la valeur de (*value) est inchangée.

fi_log_enabled / fi_log_ready / fi_log

Ces fonctions contrôlent la sortie de journalisation de débogage et d'information. Les fournisseurs accèdent généralement à ces fonctions via les macros FI_LOG et connexes dans fi_log.h et n'appellent pas ces fonctions directement.

fi_open

Ouvre une ressource de bibliothèque à l'aide d'un nom bien connu. Cette fonctionnalité permet aux applications et aux fournisseurs un mécanisme qui peut être utilisé pour modifier ou améliorer les services et le comportement du noyau de la bibliothèque. Les détails sont spécifiques en fonction du nom de l'objet demandé. La plupart des applications n'auront pas besoin de ce niveau de contrôle.

La version de l'API de la bibliothèque connue de l'application doit être fournie via le paramètre version. L'utilisation des attributs dépend de l'objet. Si nécessaire, les attributs doivent être fournis via le paramètre attr, avec attr_len défini sur la taille de la structure d'attribut référencée. Voici une liste des noms publiés, avec les descriptions du service ou de la ressource auxquels ils correspondent.

mr_cache
L'objet mr_cache fait référence au cache d'enregistrement mémoire interne utilisé par les différents fournisseurs. Des informations supplémentaires sur le cache sont disponibles dans la page man fi_mr(3).
logging
L'objet logging fait référence au sous-système de journalisation interne utilisé par les différents fournisseurs. Une fois ouvert, des rappels de journalisation personnalisés peuvent être installés. Ne peut être ouvert qu'une seule fois et seul le dernier import est utilisé si importé plusieurs fois.

fi_import

Cette fonction utilitaire est une combinaison de fi_open et fi_import_fid. Elle peut être utilisée pour importer un objet de tissu créé et possédé par l'utilisateur de libfabric. Cela permet aux bibliothèques de niveau supérieur ou à l'application de redéfinir ou de définir le comportement de bas niveau de libfabric.

fi_import_log

Fonction utilitaire pour remplacer le système de journalisation de bas niveau de libfabric par de nouvelles fonctions de rappel.

    int (*enabled)(const struct fi_provider *prov, enum fi_log_level level,

    struct fid          fid;

FOURNISSEUR

La structure fi_provider définit les points d'entrée que le noyau libfabric utilise pour accéder au fournisseur. Tous les autres appels vers un fournisseur se font par l'intermédiaire de pointeurs de fonction associés à des objets

alloués.
