NOM

fi_join_collective
Opération où un sous-ensemble de pairs rejoint un nouveau groupe collectif.
fi_barrier / fi_barrier2
Opération collective qui ne se termine que lorsque tous les pairs ont appelé la barrière.
fi_broadcast
Un seul émetteur transmet des données à tous les pairs, y compris lui-même.
fi_alltoall
Chaque pair distribue une partie de ses données locales à tous les pairs.
fi_allreduce
Opération collective où tous les pairs diffusent une opération atomique à tous les autres pairs.
fi_allgather
Chaque pair envoie une copie complète de ses données locales à tous les pairs.
fi_reduce_scatter
Appel collectif où les données sont collectées auprès de tous les pairs et fusionnées (réduites). Les résultats de la réduction sont distribués aux pairs, chaque pair recevant une partie des résultats.
fi_reduce
Appel collectif où les données sont collectées auprès de tous les pairs vers un pair racine et fusionnées (réduites).
fi_scatter
Un seul émetteur distribue (éparpille) une partie de ses données locales à tous les pairs.
fi_gather
Tous les pairs envoient leurs données à un pair racine.
fi_query_collective
Retourne des informations sur les opérations collectives prises en charge par un fournisseur, et les limitations collectives.

DESCRIPTION

En général, les opérations collectives peuvent être considérées comme des opérations atomiques coordonnées entre un ensemble de points de terminaison pairs. Les lecteurs doivent se référer à la page de manuel fi_atomic(3) pour des détails sur les opérations atomiques et les types de données définis par libfabric.

Une opération collective est un échange de communication de groupe. Elle implique plusieurs pairs échangeant des données avec d'autres pairs participant à l'appel collectif. Les opérations collectives nécessitent une coordination étroite de tous les membres participants. Tous les participants doivent invoquer le même appel collectif avant qu'un seul membre puisse terminer son opération localement. En conséquence, les appels collectifs peuvent mettre à rude épreuve le tissu, ainsi que les tampons de données locaux et distants.

Les interfaces collectives de Libfabric ciblent les tissus qui prennent en charge la décharge de portions de la communication collective dans les commutateurs réseau, les cartes réseau et d'autres périphériques. Cependant, aucune exigence d'implémentation n'est placée sur le fournisseur.

La première étape pour utiliser un appel collectif est d'identifier les points de terminaison pairs qui participeront. L'adhésion collective suit l'un des deux modèles, tous deux pris en charge par libfabric. Dans le premier modèle, l'application gère l'adhésion. Cela signifie généralement que l'application effectue elle-même une opération collective à l'aide de communications point à point pour identifier les membres qui participeront. De plus, l'application peut interagir avec un gestionnaire de ressources de tissu pour réserver les ressources réseau nécessaires à l'exécution d'opérations collectives. Dans ce modèle, l'application informera libfabric que l'adhésion a déjà été établie.

Un modèle distinct déplace la gestion de l'adhésion sous libfabric et directement dans le fournisseur. Dans ce modèle, l'application doit identifier quelles adresses de pairs seront membres. Ces informations sont transmises au fournisseur libfabric, qui est alors responsable de la coordination de la création du groupe collectif. Dans le modèle géré par le fournisseur, le fournisseur effectuera généralement l'opération collective nécessaire pour établir le groupe de communication et interagira avec tous les agents de gestion du tissu.

Dans les deux modèles, l'adhésion collective est communiquée au fournisseur en créant et en configurant un ensemble de vecteurs d'adresses (AV set). Un ensemble AV représente un sous-ensemble ordonné d'adresses dans un vecteur d'adresses (AV). Des détails sur la création et la configuration d'un ensemble AV sont disponibles dans fi_av_set(3).

Une fois qu'un ensemble AV a été programmé avec les informations d'adhésion collective, un point de terminaison est joint à l'ensemble. Ceci utilise l'opération fi_join_collective et fonctionne de manière asynchrone. Cela diffère de la manière dont un point de terminaison est associé synchro
