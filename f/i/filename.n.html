Sur chaque plateforme, Tcl prend en charge les noms de fichiers dans les formes standard pour cette plateforme. De plus, sur toutes les plateformes, Tcl prend en charge une syntaxe de type Unix destinée à fournir un moyen pratique de construire des noms de fichiers simples. Cependant, les scripts destinés à être portables ne doivent pas supposer une forme particulière pour les noms de fichiers. Au lieu de cela, les scripts portables doivent utiliser les commandes file split et file join pour manipuler les noms de fichiers (voir l' entrée de manuel de file pour plus

CHEMINS

Les noms de fichiers sont regroupés en trois types généraux en fonction du point de départ du chemin utilisé pour spécifier le fichier : absolu, relatif, et relatif au volume. Les noms absolus sont entièrement qualifiés, donnant un chemin vers le fichier par rapport à un volume particulier et au répertoire racine sur ce volume. Les noms relatifs ne sont pas qualifiés, donnant un chemin vers le fichier par rapport au répertoire de travail courant. Les noms relatifs au volume sont partiellement qualifiés, donnant soit le chemin par rapport au répertoire racine sur le volume courant, ou par rapport au répertoire courant du volume spécifié. La commande file pathtype peut être utilisée pour déterminer le type d'

un chemin donné. SYNTA

Tcl prend également en charge

la substitution

de

tilde de style csh. Si un nom de fichier commence par un tilde, alors le nom de fichier sera interprété comme si le premier élément est remplacé par l'emplacement du répertoire personnel de l'utilisateur donné. Si le tilde est immédiatement suivi d'un séparateur, alors la variable d'environnement $HOME est substituée. Sinon, les caractères entre le tilde et le séparateur suivant sont pris comme un nom d'utilisateur, qui est utilisé pour récupérer le répertoire personnel de l'utilisateur pour la substitution. Cela fonctionne sur Unix, macOS et Windows (sauf les très anciennes versions). Les anciennes plateformes Windows ne prennent pas en charge la substitution de tilde lorsqu'un

nom

d'utilisateur suit le tilde. Sur ces plateformes, les tentatives d'utiliser un tilde suivi d'un nom d'utilisateur généreront une erreur indiquant que l'utilisateur n'existe pas lorsque Tcl tente d'interpréter cette partie du chemin ou d'accéder autrement au fichier. Le comportement de ces chemins lorsqu'on ne tente pas de les interpréter est le même que sur Unix. Les noms de fichiers qui ont un tilde sans nom d'utilisateur seront correctement substitués en utilisant la variable d'environnement $HOME, tout comme pour Unix. mes de fichier

De plus, les jeux de caractères autorisés sur différents périphériques peuvent différer, donc les scripts doivent choisir des noms de fichiers qui ne contiennent pas de caractères spéciaux comme : <>:?"/\|. L'approche la plus sûre est d'utiliser des noms composés uniquement de caractères alphanumériques. Il faut faire attention avec les noms de fichiers qui contiennent des espaces (communs sur les systèmes Windows) et les noms de fichiers où l'antislash est le séparateur de répertoires (noms de chemin natifs Windows).
