NOM

File::Tail - Extension Perl pour la lecture de fichiers continuellement mis à jour

SYNTAXE

use File::Tail;
$file=File::Tail->new("/chemin/vers/un/fichier/journal");
while (defined($ligne=$file->read)) {
    print "$ligne";
}
use File::Tail;
$file=File::Tail->new(nom=>$nom, intervalle_max=>300, ajuster_apres=>7);
while (defined($ligne=$file->read)) {
    print "$ligne";
}

OU, vous pouvez utiliser tie (des paramètres supplémentaires peuvent être passés avec le nom, ou être définis en utilisant $ref) :

use File::Tail;
my $ref=tie *FH,"File::Tail",(nom=>$nom);
while (<FH>) {
    print "$_";
}

Notez que le script ci-dessus ne se terminera jamais. S'il n'y a rien d'écrit dans le fichier, il se bloquera simplement.

Vous pouvez trouver plus d'exemples dans le fichier logwatch, qui est inclus dans la distribution.

Note : La fonctionnalité select a été ajoutée dans la version 0.9, et a nécessité une révision de toutes les routines. S'il vous plaît, faites-moi savoir si vous rencontrez quelque chose d'étrange.

Vous pouvez trouver deux façons d'utiliser select dans le fichier select_demo qui est inclus dans la distribution.

DESCRIPTION

L'objectif principal de File::Tail est de lire et d'analyser des fichiers journaux pendant qu'ils sont écrits, ce qui est particulièrement utile si vous surveillez le processus de journalisation avec un outil comme MRTG de Tobias Oetiker.

Le module essaie très fort de ne pas rester en attente active ("busy-wait") sur un fichier qui a peu de trafic. Chaque fois qu'il lit de nouvelles données du fichier, il compte le nombre de nouvelles lignes, et divise ce nombre par le temps écoulé depuis que les données ont été écrites dans le fichier avant cela. Ceci est considéré comme le temps moyen avant que de nouvelles données ne soient écrites. Lorsqu'il n'y a pas de nouvelles données à lire, "File::Tail" dort pendant ce nombre de secondes. Par la suite, le temps d'attente est recalculé dynamiquement. Notez que "File::Tail" ne dort jamais plus longtemps que le nombre de secondes défini par "maxinterval".

Si le fichier n'est pas modifié pendant un certain temps, "File::Tail" devient méfiant et commence à vérifier si le fichier a été tronqué, ou déplacé et recréé. Si quelque chose de ce genre s'est produit, "File::Tail" rouvrira silencieusement le fichier et continuera la lecture. La seule façon d'affecter ce qui se passe lors de la réouverture est de définir le paramètre reset_tail (voir ci-dessous). L'effet est que les scripts n'ont pas besoin d'être conscients lorsque les fichiers journaux sont déplacés, ils continueront simplement à fonctionner silencieusement.

Notez que le sommeil et le temps utilisé proviennent de Time::HiRes, donc ce module devrait faire ce qu'il faut même si le temps de sommeil est inférieur à une seconde.

Le script logwatch (également inclus) démontre plusieurs façons d'appeler les méthodes.

CONSTRUCTEUR

nouveau ([ ARGUMENTS ])

Crée un "File::Tail". S'il n'a qu'un seul paramètre, il est supposé être le nom de fichier. Si l'ouverture échoue, le module effectue un croak. Je cherche actuellement un moyen de définir $! et de retourner undef.

Vous pouvez passer plusieurs paramètres à new :

nom
C'est le nom du fichier à ouvrir. Le fichier sera ouvert en lecture. Il doit s'agir d'un fichier régulier, pas d'un tube ou d'un terminal (c'est-à-dire qu'il doit être positionnable).
maxintervalle
Le nombre maximum de secondes (nombre réel) pendant lequel on dormira. La valeur par défaut est 60, ce qui signifie que "File::Tail" ne passera jamais plus de soixante secondes sans vérifier le fichier.
intervalle
Le nombre initial de secondes (nombre réel) pendant lequel on dormira, avant que le fichier ne soit vérifié pour la première fois. La valeur par défaut est dix secondes, ce qui signifie que "File::Tail" dormira pendant 10 secondes, puis déterminera combien de nouvelles lignes sont apparues dans le fichier.
ajuster_apres
Le nombre de "fois" que "File::Tail" attend l'intervalle courant, avant d'ajuster l'intervalle à la hausse. La valeur par défaut est 10.
reset_apres
Le nombre de secondes après le dernier changement, lorsque "File::Tail" décide que le fichier a pu être fermé et rouvert. La valeur par défaut est ajuster_apres * maxintervalle.
maxbuf
La taille maximale du tampon interne. Lorsque File::Tail a soudainement trouvé une quantité énorme d'informations dans le fichier (par exemple, si les paramètres de nouvelle tentative étaient réglés sur une vérification très peu fréquente et que le fichier a été déplacé), File::Tail a parfois ingéré beaucoup trop de données en mémoire. Ceci définit la taille maximale du tampon de File::Tail.

La valeur par défaut est 16384 (octets).

Un grand tampon interne peut entraîner une diminution des performances (ainsi qu'une augmentation de l'utilisation de la mémoire), car File::Tail devra travailler davantage pour traiter le tampon interne.

no_attente
Ne se bloque pas lors de la lecture, mais renvoie une chaîne vide s'il n'y a rien à lire. NE PAS UTILISER ceci, sauf si vous savez ce que vous faites. Si vous l'utilisez dans une boucle, vous ne savez probablement PAS ce que vous faites. Si vous voulez lire les fins de plusieurs fichiers, utilisez select.
ignorer_non_existant
    Ne pas se plaindre si le fichier n'existe pas lors de sa première 
ouverture ou lorsqu'il doit être rouvert. (Le fichier peut être rouvert après 
que `resetafter` secondes se soient écoulées depuis la dernière donnée trouvée.)
queue
    Lors du démarrage initial, lire et retourner C<n> lignes du fichier. 
Si C<n> est zéro, commencer à la fin du fichier. Si C<n> est négatif, 
retourner l'intégralité du fichier.
    La valeur par défaut est C<0>.
reset_queue
    Identique à `queue`, mais s'applique après un reset. (c'est-à-dire après 
que le fichier ait été automatiquement fermé et rouvert). La valeur par défaut 
est C<-1>, c'est-à-dire qu'elle ne saute aucune information présente dans le 
fichier lors de sa première vérification.
   Pourquoi voudriez-vous que ce soit différent ? J'ai vu des fichiers qui ont 
été cyclés comme suit :
   grep -v le_mois_dernier journal >nouveau_journal
   mv journal archive/le_mois_dernier
   mv nouveau_journal journal
   kill -HUP logger

Évidemment, si cela se produit et que vous avez réglé reset_tail à c<-1>, vous obtiendrez soudainement un grand nombre de lignes - des lignes que vous avez déjà vues. Donc, dans ce cas, reset_tail devrait probablement être réglé sur un petit nombre positif ou même 0.

changements_nom
Certains systèmes de journalisation modifient le nom du fichier dans lequel ils écrivent, parfois pour inclure une date, parfois un numéro de séquence, parfois d'autres changements encore plus bizarres.

Au lieu d'essayer d'implémenter diverses méthodes de détection intelligentes, File::Tail appellera la référence de code définie dans changements_nom. La référence de code doit renvoyer la chaîne qui est le nouveau nom du fichier à essayer d'ouvrir.

Notez que si le fichier n'existe pas, File::Tail signalera une erreur fatale (sauf si ignorer_non_existant a également été spécifié).

debug
Mettre à une valeur non nulle si vous voulez en savoir plus sur le fonctionnement interne de File::Tail. Sinon, non utile.
mode_erreur
Modélisé d'après les méthodes de Net::Telnet, ici vous décidez comment les erreurs doivent être gérées. Le paramètre peut être une référence de code qui est appelée avec la chaîne d'erreur comme paramètre, un tableau avec une référence de code comme premier paramètre et d'autres paramètres à passer à la sous-routine de gestion, ou l'un des mots :

retourner - ignorer toute erreur (mettre simplement le message d'erreur dans errmsg). avertir - afficher le message d'erreur mais continuer mourir - afficher le message d'erreur et quitter

La valeur par défaut est mourir.

METHODES

lire

"lire" r

etourne une ligne du fichier d'entrée. S'il n'y a pas de lignes disponibles, il se bloque jusqu'à ce qu'il y en ait.

select

"select" est destiné à permettre au programmeur d'attendre simultanément des entrées sur des descripteurs de fichiers normaux et sur des descripteurs de fichiers File::Tail. Bien sûr, vous pouvez l'utiliser simplement pour lire à partir de plusieurs descripteurs de fichiers File::Tail à la fois.

Fondamentalement, vous appelez File::Tail::select comme vous appelleriez select normalement, avec des champs pour rbits, wbits et ebits, ainsi qu'un délai d'attente, mais vous pouvez ajouter un nombre quelconque d'objets File::Tail (et non des descripteurs de fichiers File::Tail !) à la fin.

Exemple d'utilisation :

foreach (@ARGV) {
    push(@files,File::Tail->new(name=>"$_",debug=>$debug));
}
while (1) {
  ($nfound,$timeleft,@pending)=
            File::Tail::select(undef,undef,undef,$timeout,@files);
  unless ($nfound) {
    # délai d'attente dépassé - faites autre chose ici, si vous en avez besoin
  } else {
    foreach (@pending) {
       print $_->{"input"}." (".localtime(time).") ".$_->read;
  }
}
#
# Il y a un exemple plus élaboré dans select_demo dans la distribution.
#

Lorsque vous faites cela, select de File::Tail émule le select normal, avec deux exceptions :

a) il retournera s'il y a une entrée sur n'importe lequel des paramètres (c'est-à-dire des descripteurs de fichiers normaux) _ou_ sur des File::Tail.

b) En plus de "($nfound, $timeleft)", le tableau de retour contiendra également une liste d'objets File::Tail qui sont prêts à être lus. $nfound contiendra le bon nombre de descripteurs de fichiers à lire (c'est-à-dire à la fois les normaux et les File::Tail).

Une fois que select a retourné, lorsque vous voulez déterminer quels objets File::Tail ont une entrée prête, vous pouvez soit utiliser la liste d'objets retournée par select, soit vérifier chaque objet individuellement avec $object->predict. Cela retourne la quantité de temps (en secondes fractionnaires) après laquelle le descripteur s'attend à une entrée. S'il retourne 0, il y a une entrée en attente. Il n'y a aucune garantie qu'il y aura une entrée en attente après que le nombre de secondes retourné soit écoulé. Cependant, File::Tail n'effectuera aucune E/S sur le fichier avant que ce temps soit écoulé. Notez que la valeur de $timeleft peut être correcte ou non - cela dépend du système d'exploitation sous-jacent (et de son select), il vaut donc mieux NE PAS s'y fier.

Notez également que si vous déterminez quels fichiers sont prêts pour l'entrée en appelant chaque predict individuellement, la valeur $nfound peut être invalide, car un ou plusieurs objets File::Tail peuvent être devenus prêts entre le moment où select a retourné et le moment où vous l'avez vérifié.
