on Perl pour la copie récursiv

SYNOPSI

S 
use File::Copy::Recursive qw(fcopy rcopy dircopy fmove rmove dirmove);
fcopy($orig,$new[,$buf]) or die $!;
rcopy($orig,$new[,$buf]) or die $!;
dircopy($orig,$new[,$buf]) or die $!;
fmove($orig,$new[,$buf]) or die $!;
rmove($orig,$new[,$buf]) or die $!;
dirmove($orig,$new[,$buf]) or die $!;

rcopy_glob("orig/stuff-*", $trg [, $buf]) or die $!;
rmove_glob("orig/stuff-*", $trg [,$buf]) or die
$!

DESCRIPTIO

N

Ce module copie et déplace des répertoires récursivement (ou des fi

chiers individuels, individuellement) jusqu'à une profondeur optionn
elle et tente de préserver le mode de chaque fichier ou répertoire.

EXPORTATI

ON

Aucune par défaut. Mais vous pouvez exporter toutes les fonctions comme dans l'exemple ci-dessus et les fonctions path* si vous le

souhaitez.

fcopy(

)

Cette fonction utilise la fonction copy() de File::Copy pour copier un fichier mais pas un répertoire. Les répertoires sont créés récursivement si nécessaire. Une différence avec File::Copy::copy() est que fcopy tente de préserver le mode (voir Préserver le mode ci-dessous). Le $buf optionnel dans le synopsis est identique au 3ème argument de File::Copy::copy(). Cette fonction renvoie la même valeur que File::Copy::copy() en contexte scalaire et 1,0,0 en contexte liste pour s'accommoder du contexte liste de rcopy() sur les fichiers régul

iers. (Voir ci-dessous p
our plus d'informations)

dircopy(

)

Cette fonction parcourt récursivement la structure du répertoire $orig et le copie récursivement dans le répertoire $new. $new est créé si nécessaire (plusieurs répertoires inexistants sont acceptés (c'est-à-dire foo/bar/baz). Le script les crée tous logiquement et de manière portable si nécessaire). Elle tente de préserver le mode (voir Préserver le mode ci-dessous) et par défaut elle copie jusqu'en bas du répertoire (voir Gérer la profondeur, ci-dessous). Si un répertoire n'est pas spécifié, elle émet un croak tout comme fcopy émet un croak si ce qui est spécifié n'est pas un

fichier.

Cette fonction renvoie vrai ou faux : pour vrai en contexte scalaire elle renvoie le nombre de fichiers et de répertoires copiés, tandis qu'en contexte liste elle renvoie le nombre de fichiers et de répertoires, le nombre de répertoires uniquement, et le niveau de profondeur

parcouru. 
my $num_of_files_and_dirs = dircopy($orig,$new);
my($num_of_files_and_dirs,$num_of_dirs,$depth_traversed) = dircopy($orig,$new)
;

Normalement elle s'arrête et renvoie si une copie échoue. Pour continuer malgré tout, définissez $File::Copy::Recursive::SkipFlop

à 
vrai.
local $File::Copy::Recursive::SkipFlop =
1;

De cette façon elle copiera tout ce qu'elle peut dans un répertoire et ne s'arrêtera pas à cause des permissions, etc.

.
.

rcopy(

)

Cette fonction vous permet de spécifier un fichier *ou* un répertoire. Elle appelle fcopy() si vous avez passé un fichier et dircopy() si vous avez passé un répertoire. Si vous appelez rcopy() (ou fcopy() pour ce qui est de cela) sur un fichier en contexte liste, les valeurs seront 1,0,0 puisqu'aucun répertoire et aucune profondeur ne sont ut

ilisés. C'est important parce que si c'est un répertoire en contexte list
e et qu'il n'y a que le répertoire initial, la valeur de retour est 1,1,1.

rcopy_glob(

)

Cette fonction vous permet de spécifier un motif adapté à File::Glob::bsd_glob() de perl comme premier argument. Ensuite, chaque chemin renvoyé par File::Glob::bsd_glob() de perl est rcopy()

ié.

Elle renvoie un tableau dont les éléments sont des références de tableaux contenant la valeur de retour de chaque appel à rcopy

().

Elle force le comportement comme si $File::Copy::Recursive

::CPRFComp
était vrai.

fmove(

)

Copie le fichier puis supprime l'original. Vous pouvez gérer le chemin dans lequel se trouve le fichier original selon $Remv

Bas
e.

dirmove(

)

Utilise dircopy() pour copier le répertoire puis supprime l'original. Vous pouvez gérer le chemin dans lequel se trouve le répertoire original selon $Remv

Bas
e.

rmove(

)

Comme rcopy() mais appelle fmove() ou dirmove()

à la p
lace.

rmove_glob(

)

Comme rcopy_glob() mais appelle rmove() au lieu de rcopy(

)

$RemvBase

La valeur par défaut est faux. Lorsqu'il est défini à vrai, les fonctionsmove() tenteront non seulement de supprimer le fichier ou le répertoire original mais supprimeront aussi le chemin donné dans lequel il se

trouve.

Ainsi si vous

: 
rmove('foo/bar/baz', '/etc/');
# "baz" est supprimé de foo/bar après avoir été copié avec succès dans /etc/

local $File::Copy::Recursive::Remvbase = 1;
rmove('foo/bar/baz','/etc/');
# si baz est copié avec succès dans /etc/ :
# d'abord "baz" est supprimé de foo/bar
# ensuite "foo/bar" est supprimé via
pathrm()

$ForcePt

h

La valeur par défaut est faux. Lorsqu'il est défini à vrai, il appelle pathempty() avant que des répertoires ne soient supprimés pour vider le répertoire afin qu'il puisse être rmdir()é quand $RemvBase

est a
ctif.

Création et suppression de

chemins

$NoFtlPth

La valeur par défaut est faux. S'il est défini à vrai, rmdir(), mkdir(), et les appels à pathempty() dans pathrm() et pathmk() ne return() pas en cas

d'échec.

S'il est défini à vrai, ils continuent simplement leur travail en silence quel que soit le résultat. Ce n'est pas une bonne idée mais c'est là si vous le

voulez.

$DirPerms

Mode à passer à tous les appels à mkdir(). Par défaut 0777 comme dans le POD de umask(). Avoir cela explicitement permet aux anciennes versions de perl d'utiliser FCR et pourrait ajouter un peu de flexibilité pour

vous.

Toute valeur que vous lui définissez doit être adaptée pour oct(

).

Fonctions de

chemin

Ces fonctions existent uniquement parce qu'elles étaient nécessaires pour que les fonctions de déplacement et de copie aient les fonctionnalités qu'elles ont, et non parce qu'elles sont en elles-mêmes le but de ce module. Cela dit, voici comment elles fonctionnent pour que vous compreniez comment fonctionnent les fonctions de copie et de déplacement et que vous puissiez les utiliser par vous-même si vous le

souhaitez.

pathrm(

)

Supprime un chemin donné récursivement. Elle supprime le chemin *entier* alors soyez prudent!!

!

Renvoie 2 si le chemin donné n'est pas un

répertoire. 
File::Copy::Recursive::pathrm('foo/bar/baz') or die $!;
# foo n'existe
plus

Équivalent

à : 
rmdir 'foo/bar/baz' or die $!;
rmdir 'foo/bar' or die $!;
rmdir 'foo' or die $!
;

Un deuxième argument optionnel la fait appeler pathempty() avant chaque rmdir() lorsqu'il est défini à

vrai. 
File::Copy::Recursive::pathrm('foo/bar/baz', 1) or die $!;
# foo n'existe
plus

Équivalent à :

PFSCheck 
File::Copy::Recursive::pathempty('foo/bar/baz') or die $!;
rmdir 'foo/bar/baz' or die $!;
File::Copy::Recursive::pathempty('foo/bar/') or die $!;
rmdir 'foo/bar' or die $!;
File::Copy::Recursive::pathempty('foo/') or die $!;
rmdir 'foo' or die $!
;

Un troisième argument optionnel agit comme $File::Copy::Recursive::NoFtlPth, encore une fois probablement pas une bonne

idée.

pathempty(

)

Supprime récursivement le contenu du répertoire donné pour qu'il soit vide. Renvoie 2 si l'argument donné n'est pas un répertoire, 1 si le répertoire a été vidé avec

succès. 
File::Copy::Recursive::pathempty($pth) or die $!;
# $pth est maintenant un répertoire
vide

pathmk(

)

Crée un chemin donné récursivement. Crée foo/bar/baz même si foo n'existe

pas. 
File::Copy::Recursive::pathmk('foo/bar/baz') or die $!
;

Un deuxième argument optionnel s'il est vrai agit tout comme $File::Copy::Recursive::NoFtlPth, ce qui signifie que vous ne recevriez jamais votre die() si quelque chose se passe mal. Encore une fois, probablement une *mauvaise*

idée.

pathrmdir(

)

Comme rmdir() mais elle appelle pathempty() d'abord pour le vider récursivement d'abord puisque rmdir ne peut pas supprimer un répertoire avec du contenu. Elle supprime seulement le répertoire supérieur du chemin donné au lieu du chemin entier comme pathrm(). Renvoie 2 si l'argrgument does not exist (i.e. it'

s already gone). Returns false if i
t exists but is not a directory.

Préservation du

mode

Par défaut, une tentative silencieuse est faite pour changer le mode du nouveau fichier ou répertoire à celui de l'ancien. Pour désactiver ce comportement, définissez
$File::Copy::Recursi

ve::KeepMod
e à false;

Gestion de la

profondeur

Vous pouvez définir la profondeur maximale de récursion d'une structure de répertoires en définissant :
$File::Copy::Recursive::MaxDepth à

un nombre entier
supérieur à 0.

Liens

symboliques

Si votre système prend en charge les liens symboliques, alors les liens symboliques seront copiés en tant que liens symboliques au lieu de la cible du fichier. Le symlink() de Perl est utilisé au lieu du copy() de File::Copy. Vous pouvez personnaliser ce comportement en définissant $File::Copy::Recursive::CopyLink à une valeur vraie ou fausse. Il est déjà défini à true ou false en fonction de la prise en charge des liens symboliques par votre système, vous pouvez donc le vérifier avec une instruction if pour voir comment il se comportera

: 
if($File::Copy::Recursive::CopyLink) {
    print "Symlinks will be preserved\n";
} else {
    print "Symlinks will not be preserved because your system does not support it\n";
}

Si les liens symboliques sont copiés, vous pouvez définir $File::Copy::Recursive::BdTrgWrn à true pour qu'il émette un avertissement (carp) lorsqu'il copie un lien dont la cible n'existe pas. C'est false par

défaut. 
local $File::Co
py::Recursive:
:BdTrgWrn = 1;

Suppression du fichier ou du répertoire cible existant avant la

copie.

Cela peut être fait en définissant $File::Copy::Recursive::RMTrgFil ou $File::Copy::Recursive::RMTrgDir pour le comportement des fichiers ou des répertoires

respectivement.

0 = désactivé (C'est la valeur par

défaut)

1 = carp() $! si la suppression

échoue

2 = retourne si la suppression

échoue 
local $File::Copy::Recursive::RMTrgFil = 1;
fcopy($orig, $target) or die $!;
# if it fails it does warn() and keeps going
local $File::Copy::Recursive::RMTrgDir = 2;
dircopy($orig, $target) or die $!;
# if it fails it does your "or
die"

Cela devrait être inutile la plupart du temps, mais c'est là si vous en avez besoin

:
)

Désactivation de la vérification

stat()

Par défaut, les fichiers ou les répertoires sont vérifiés pour voir s'ils sont les mêmes (c'est-à-dire liés, ou deux chemins (absolu/relatif ou chemins relatifs différents) vers le même fichier) en comparant les informations stat() du fichier. C'est une vérification très efficace qui échoue (croak) s'ils le sont, et elle ne devrait pas être désactivée, mais si vous devez le faire pour une raison étrange, définissez simplement $File::Copy::Recursive::PFSCheck à une valeur fausse. (« PFS »

signifie « Physical File System
» (système de fichiers physique))

Émulation de cp -rf dir1/

dir2/

Par défaut, dircopy($dir1,$dir2) mettra le contenu de $dir1 directement dans $dir2 que $dir2 existe ou

non.

Vous pouvez faire en sorte que dircopy() émule cp -rf en définissant $File::Copy::Recursive::CPRFComp à

true.

REMARQUE : Cela n'émule -f que dans le sens où cela ne demande pas de confirmation. Cela ne supprime pas le fichier ou le répertoire cible s'il existe. Si vous devez le faire, utilisez les variables $RMTrgFil et $RMTrgDir décrites dans « Suppression du fichier ou du répertoire cible existant avant la copie »

ci-dessus.

Cela signifie que si $dir2 existe, cela met le contenu dans $dir2/$dir1 au lieu de $dir2, tout comme cp -rf. Si $dir2 n'existe pas, alors le contenu va dans $dir2 comme d'habitude (également comme cp -rf)

.

En supposant 'foo/file'

: 
dircopy('foo', 'bar') or die $!;
# if bar does not exist the result is bar/file
# if bar does exist the result is bar/file
$File::Copy::Recursive::CPRFComp = 1;
dircopy('foo', 'bar') or die $!;
# if bar does not exist the result is bar/file
# if bar does exist the result is
bar/foo/file

Vous pouvez également spécifier une étoile pour un comportement de type glob cp -rf

: 
dircopy('foo/*', 'bar') or die $!;
# if bar does not exist the result is bar/file
# if bar does exist the result is bar/file
$File::Copy::Recursive::CPRFComp = 1;
dircopy('foo/*', 'bar') or die $!;
# if bar does not exist the result is bar/file
# if bar does exist the result is
bar/file

REMARQUE : Le « * » est seulement comme cp -rf foo/* et *N'EXPAN

DE PAS LES NOMS DE RÉPERTOIRES PARTIELS COMME LE FAIT VOTRE S
HELL* (c'est-à-dire pas comme cp -rf fo* pour copier foo/*).

Autorisation des boucles de

copie

Si vous voulez autoriser

: 
cp -rf .
foo/

un comportement de ce type, définissez $File::Copy::Recursive::CopyLoop à

true.

C'est false par défaut afin qu'une vérification soit faite pour voir si le répertoire source contiendra le répertoire cible, et cela échoue (croak) pour éviter ce

problème.

Si vous trouvez jamais une situation où $CopyLoop = 1 est souhaitable, faites-le moi savoir. (c'est-à-dire c'est une très mauvaise idée mais c'est là si vous le

voulez)

(Note : Sur Windows, cela était nécessaire car il utilise stat() pour déterminer l'identité, et stat() est essentiellement inutile pour cela sur Windows. Le test est maintenant simplement i

gnoré sur Windows, mais je préférerais avoir
une vérification réellement fiable si quelqu'un
dans le monde de Microsoft voulait bien partager)
