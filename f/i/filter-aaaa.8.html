NOM

filter-aaaa - filtre les AAAA DNS lorsque les A sont présents

SYNTAXE

plugin query "filter-aaaa.so" [{ paramètres }];

DESCRIPTION

filter-aaaa.so est un module de plugin de requête pour named <#std-iscman-named>, permettant à named <#std-iscman-named> d'omettre certaines adresses IPv6 lors de la réponse aux clients.

Jusqu'à BIND 9.12, cette fonctionnalité était implémentée nativement dans named <#std-iscman-named> et activée avec l'ACL filter-aaaa et les options filter-aaaa-on-v4 et filter-aaaa-on-v6. Ces options ne sont plus disponibles dans named.conf <#std-iscman-named.conf> mais peuvent être passées comme paramètres au plugin filter-aaaa.so, par exemple :

plugin query "filter-aaaa.so" {
        filter-aaaa-on-v4 yes;
        filter-aaaa-on-v6 yes;
        filter-aaaa { 192.0.2.1; 2001:db8:2::1; };
};

Ce module est destiné à faciliter la transition d'IPv4 à IPv6 en supprimant les adresses IPv6 des clients DNS qui ne sont pas connectés à l'Internet IPv6, lorsque le nom interrogé a une adresse IPv4 disponible. L'utilisation de ce module n'est pas recommandée, sauf en cas de nécessité absolue.

Note : Ce mécanisme peut, par erreur, empêcher d'autres serveurs de fournir des enregistrements AAAA à leurs clients. Si un serveur récursif avec des connexions réseau IPv4 et IPv6 interroge un serveur autoritaire utilisant ce mécanisme via IPv4, il se voit refuser les enregistrements AAAA même si son client utilise IPv6.

OPTIONS

filter-aaaa
Cette option spécifie une liste d'adresses de clients pour lesquelles le filtrage des AAAA doit être appliqué. La valeur par défaut est any.
filter-aaaa-on-v4
Si réglée sur yes, cette option indique que le client DNS se trouve à une adresse IPv4, dans filter-aaaa. Si la réponse n'inclut pas de signatures DNSSEC, alors tous les enregistrements AAAA sont supprimés de la réponse. Ce filtrage s'applique à toutes les réponses, pas seulement aux réponses autoritaires.

Si réglée sur break-dnssec, alors les enregistrements AAAA sont supprimés même lorsque le DNSSEC est activé. Comme son nom l'indique, cela entraîne l'échec de la vérification de la réponse, car le protocole DNSSEC est conçu pour détecter les suppressions.

Ce mécanisme peut, par erreur, empêcher d'autres serveurs de fournir des enregistrements AAAA à leurs clients. Si un serveur récursif avec des connexions réseau IPv4 et IPv6 interroge un serveur autoritaire utilisant ce mécanisme via IPv4, il se voit refuser les enregistrements AAAA même si son client utilise IPv6.

filter-aaaa-on-v6
Cette option est identique à filter-aaaa-on-v4, à l'exception près qu'elle filtre les réponses AAAA aux requêtes provenant de clients IPv6 au lieu de clients IPv4. Pour filtrer toutes les réponses, définissez les deux options sur yes.
