NOM

firewalld.helper - fichiers de configuration des helpers firewalld

SYNTAXE

/etc/firewalld/helpers/helper.xml
/usr/lib/firewalld/helpers/helper.xml

DESCRIPTION

Un fichier de configuration de helper firewalld fournit les informations d'une entrée de helper pour firewalld. Les options de configuration les plus importantes sont les ports, la famille et le module.

Cet exemple de fichier de configuration montre la structure d'un fichier de configuration de helper :

<?xml version="1.0" encoding="utf-8"?>
<helper module="nf_conntrack_module" [family="ipv4|ipv6"]>
  <short>court</short>
  <description>description</description>
  <port portid[-portid]" protocol="tcp|udp|sctp|dccp"/>
</helper>

OPTIONS

La configuration peut contenir ces balises et attributs. Certains sont obligatoires, d'autres facultatifs.

helper

La balise de début et de fin obligatoire helper définit le helper. Cette balise ne peut être utilisée qu'une seule fois dans un fichier de configuration de helper. Il y a un attribut obligatoire et également des attributs facultatifs pour helper :

module="chaîne"

Le module obligatoire du helper. C'est l'un des modules de suivi de connexion netfilter. Le nom commence par nf_conntrack_.

family="ipv4|ipv6"

La famille facultative du helper. Il peut s'agir de l'un de ces types IP : ipv4 ou ipv6. Si la famille n'est pas spécifiée, le helper est utilisable pour IPv4 et IPv6.

version="chaîne"

Pour donner une version au helper.

short

Est une balise de début et de fin facultative et est utilisée pour donner un nom plus lisible à un helper.

description

Est une balise de début et de fin facultative pour avoir une description d'un helper.

port

Est une balise obligatoire à élément vide et peut être utilisée plusieurs fois pour avoir plus d'une entrée de port. Tous les attributs d'une entrée de port sont obligatoires :

port="chaîne"

La chaîne de port peut être un numéro de port unique ou une plage de ports portid-portid ou même vide pour correspondre uniquement à un protocole.

protocol="chaîne"

La valeur du protocole peut être tcp, udp, sctp ou dccp.
