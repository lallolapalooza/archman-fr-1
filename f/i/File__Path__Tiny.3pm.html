DESCRIPTIO

N

L'objectif ici est simplement de fournir des versions récursives de mkdir() et rmdir() avec le moins de code et de surcoût

possible.

Ce module n'est en aucun cas destiné à dénigrer File::Path et ne constitue en aucun cas une incitation à remplacer toutes les utilisations de File::Path par File::Path::

Tiny.

File::Path est très bon dans ce qu'il fait mais il se passe tout simplement beaucoup de choses dont nous pouvons nous passer la plupart du

temps.

Voici quelques éléments que File::Path possède/fait et que ce module tente d'éviter

:

  • chdir()

File::Path::Tiny::

mk()

Prend un chemin unique (comme mkdir()) à créer récursivement et, optionnellement, un masque (comme mkdir()) pour tous les appels mkdir()

suivants.

Le masque par défaut est 0700 (également comme mkdir()

)

Renvoie faux s'il n'a pas pu être créé, vrai sinon (renvoie ‘2’ si c'est déjà

-d)

Il est récursif dans le sens où étant don

File::Path::Tiny::

rm()

Prend un chemin unique (comme rmdir()) à vider et supprimer

récursivement.

Renvoie faux s'il n'a pas pu être vidé ou supprimé, vrai sinon (renvoie ‘2’ si ce n'est déjà pas -d). Voir aussi

DIAGNOSTICS.

Il est récursif dans le sens où étant donné « /foo/bar/baz » comme chemin à supprimer, il videra récursivement ‘baz’ puis le supprimera de

/foo/bar.

Ses parents, /, /foo et /foo/bar ne sont *pas*

touchés.

Comment puis-je créer/supprimer plusieurs chemins

?

Pour des raisons de simplicité && le statut ::Tiny, ce module doit être très très très

simple.

Cela dit, il est aussi très simple de traiter plusieurs chemins

: 
for my $path (@paths) {
    File::Path::Tiny::::mk($path) or _my_handle_failed_mk($path, $!);    
}

for my $path (@paths) {
    File::Path::Tiny::::rm($path) or _my_handle_failed_rm($path, $!);
}

Cela vous permet aussi de continuer ou d'interrompre ou de gérer les erreurs comme vous le souhaitez

: 
PATH:
for my $path qw(foo/bar bar/rat) {
    if (!File::Path::Tiny::mk($path)) {
        print "problem unlinking '$path': $!\n";
        last PATH;
    }
    else {
        print "No error encountered with '$path'\n" 
    }
}

Comment m'assurer que le chemin est sûr à créer ou supprimer

?

Bien sûr la réponse dépend de ce que vous entendez par « sûr »

.

Ce module ne fait aucune hypothèse sur l'interprétation de la « sûreté » d'un chemin, tout comme mkdir() et rmdir()

.

Également comme mkdir() et rmdir(), vous trouverez généralement que les permissions du système de fichiers sont un outil assez fiable (bien sûr si le code sera exécuté en tant que root, vous voudriez d'abord faire setuid...

)

Vous pourriez utiliser Cwd::abs_path() pour assainir un chemin avant de l'envoyer pour être créé ou

supprimé.

Même après cela, cela pourrait ne pas être

« sûr » donc vous devrez discerner qu
elle est votre définition particulière de «
sûr » et prendre l'action appropriée.
