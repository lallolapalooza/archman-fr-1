NOM

fido2-token — trouver et gérer un authentificateur FIDO2

SYNOPSIS

fido2-token -C [-d] device

fido2-token -D [-d] -i cred_id device

fido2-token -D -b [-d] -k key_path device

fido2-token -D -b [-d] -n rp_id [-i cred_id] device

fido2-token -D -e [-d] -i template_id device

fido2-token -D -u [-d] device

fido2-token -G -b [-d] -k key_path blob_path device

fido2-token -G -b [-d] -n rp_id [-i cred_id] blob_path device

fido2-token -I [-cd] [-k rp_id -i cred_id] device

fido2-token -L [-bder] [-k rp_id] [device]

fido2-token -R [-d] device

fido2-token -S [-adefu] device

fido2-token -S [-d] -i template_id -n template_name device

fido2-token -S [-d] -l pin_length device

fido2-token -S -b [-d] -k key_path blob_path device

fido2-token -S -b [-d] -n rp_id [-i cred_id] blob_path device

fido2-token -S -c [-d] -i cred_id -k user_id -n name -p display_name device

fido2-token -S -m rp_id device

fido2-token -V

DESCRIPTION

fido2-token gère un authentificateur FIDO2.

Les options sont les suivantes :

-C device
Change le code PIN de device. L'utilisateur sera invité à saisir le code PIN actuel et le nouveau.
-D -i id device
Supprime la résidence d'identification (credential) spécifiée par id de device, où id est l'identifiant de la credential encodé en base64. L'utilisateur sera invité à saisir le code PIN.
-D -b -k key_path device
Supprime un « largeBlob » chiffré avec key_path de device, où key_path contient la clé de chiffrement AES-256 GCM de 32 octets encodée en base64 du blob. Un code PIN ou un geste équivalent de vérification de l'utilisateur est requis.
-D -b -n rp_id [-i cred_id] device
Supprime un « largeBlob » correspondant à rp_id de device. Si rp_id a plusieurs credentials enregistrées sur device, l'identifiant de la credential doit être spécifié à l'aide de -i cred_id, où cred_id est un blob encodé en base64. Un code PIN ou un geste équivalent de vérification de l'utilisateur est requis.
-D -e -i id device
Supprime l'enrôlement biométrique spécifié par id de device, où id est l'identifiant de modèle de l'enrôlement encodé en base64. L'utilisateur sera invité à saisir le code PIN.
-D -u device
Désactive la fonctionnalité CTAP 2.1 « user verification always » sur device.
-G -b -k key_path blob_path device
Récupère un « largeBlob » CTAP 2.1 chiffré avec key_path depuis device, où key_path contient la clé de chiffrement AES-256 GCM de 32 octets encodée en base64 du blob. Le blob est écrit dans blob_path. Un code PIN ou un geste équivalent de vérification de l'utilisateur est requis.

DESCRIPTION

fido2-token est un utilitaire en ligne de commande pour interagir avec des périphériques FIDO2 et U2F.

-C device
Supprime toutes les informations d'identification du résident sur device. L'utilisateur sera invité à entrer le code PIN.
-C -i cred_id device
Supprime l'information d'identification du résident spécifiée par cred_id sur device. cred_id est un identifiant d'information d'identification encodé en base64. L'utilisateur sera invité à entrer le code PIN.
-C -r rp_id device
Supprime toutes les informations d'identification du résident associées à rp_id sur device. L'utilisateur sera invité à entrer le code PIN.
-E device
Désactive la confirmation des informations d'identification de résident sur device. L'utilisateur sera invité à entrer le code PIN.
-E -a device
Désactive l'attestation d'entreprise CTAP 2.1 sur device.
-E -c -i cred_id -k user_id device
Définit l'attribut -c (confirmation) pour l'information d'identification du résident spécifiée par cred_id et user_id sur device, où cred_id et user_id sont des blobs encodés en base64. Un code PIN ou un geste de vérification utilisateur équivalent est requis.
-E -e device
Supprime toutes les inscriptions biométriques sur device. L'utilisateur sera invité à entrer le code PIN.
-E -e -i template_id device
Supprime l'inscription biométrique spécifiée par template_id sur device, où template_id est encodé en base64. L'utilisateur sera invité à entrer le code PIN.
-E -f device
Définit la politique de vérification utilisateur CTAP 2.1 sur always sur device.
-E -l device
Désactive la politique de vérification utilisateur CTAP 2.1 sur device.
-E -u device
Supprime la liste des ID de parties responsables autorisées à récupérer la longueur minimale du code PIN de device. L'utilisateur sera invité à entrer le code PIN.
-G device
Enregistre une nouvelle information d'identification du résident sur device. L'utilisateur sera invité à entrer le code PIN. L'attribut -n doit spécifier le nom de l'information d'identification à enregistrer.
-G -i cred_id device
Récupère les métadonnées de l'information d'identification du résident sur device. L'utilisateur sera invité à entrer le code PIN.
-G -k rp_id device
Imprime l'identifiant de l'information d'identification (encodé en base64) et la clé publique (encodée en PEM) de l'information d'identification du résident spécifiée par rp_id sur device. rp_id est un ID UTF-8 de partie responsable. L'utilisateur sera invité à entrer le code PIN.
-G -l device
Récupère la liste des informations d'identification du résident sur device. L'utilisateur sera invité à entrer le code PIN.
-G -r rp_id device
Imprime les informations d'identification du résident associées à la partie responsable spécifiée par rp_id sur device. L'utilisateur sera invité à entrer le code PIN.
-H device
Vérifie l'état de l'avertissement de sécurité sur device.
-I device
Récupère des informations sur device.
-I -c device
Récupère les métadonnées de l'information d'identification du résident sur device. L'utilisateur sera invité à entrer le code PIN.
-I -k rp_id -i cred_id device
Imprime l'identifiant de l'information d'identification (encodé en base64) et la clé publique (encodée en PEM) de l'information d'identification du résident spécifiée par rp_id et cred_id, où rp_id est un ID UTF-8 de partie responsable et cred_id est un identifiant d'information d'identification encodé en base64. L'utilisateur sera invité à entrer le code PIN.
-L
Produit une liste des authentificateurs trouvés par le système d'exploitation.
-L -b device
Produit une liste de “largeBlobs” CTAP 2.1 sur device. Un code PIN ou un geste de vérification utilisateur équivalent est requis.
-L -e device
Produit une liste d'inscriptions biométriques sur device. L'utilisateur sera invité à entrer le code PIN.
-L -r device
Produit une liste de parties responsables avec des informations d'identification de résident sur device. L'utilisateur sera invité à entrer le code PIN.
-L -k rp_id device
Produit une liste d'informations d'identification de résident correspondant à la partie responsable rp_id sur device. L'utilisateur sera invité à entrer le code PIN.
-R
Effectue une réinitialisation sur device. fido2-token ne demandera PAS de confirmation.
-S
Définit le code PIN de device. L'utilisateur sera invité à entrer le code PIN.
-S -a device
Active l'attestation d'entreprise CTAP 2.1 sur device.
-S -b -k key_path blob_path device
Définit un “largeBlob” CTAP 2.1 crypté avec key_path sur device, où key_path contient la clé de cryptage AES-256 GCM de 32 octets encodée en base64 du blob. Le blob est lu depuis blob_path. Un code PIN ou un geste de vérification utilisateur équivalent est requis.
-S -b -n rp_id [-i cred_id] blob_path device
Définit un “largeBlob” CTAP 2.1 associé à rp_id sur device. Le blob est lu depuis blob_path. Si rp_id a plusieurs informations d'identification enregistrées sur device, l'identifiant de l'information d'identification doit être spécifié en utilisant -i cred_id, où cred_id est un blob encodé en base64. Un code PIN ou un geste de vérification utilisateur équivalent est requis.
-S -c -i cred_id -k user_id -n name -p display_name device
Définit les attributs name et display_name de l'information d'identification du résident identifiée par cred_id et user_id, où name et display_name sont des chaînes UTF-8 et cred_id et user_id sont des blobs encodés en base64. Un code PIN ou un geste de vérification utilisateur équivalent est requis.
-S -e device
Effectue une nouvelle inscription biométrique sur device. L'utilisateur sera invité à entrer le code PIN.
-S -e -i template_id -n template_name device
Définit le nom convivial de l'inscription biométrique spécifiée par template_id sur template_name sur device, où template_id est encodé en base64 et template_name est une chaîne UTF-8. L'utilisateur sera invité à entrer le code PIN.
-S -f device
Force un changement de code PIN sur device. L'utilisateur sera invité à entrer le code PIN.
-S -l pin_length device
Définit la longueur minimale du code PIN de device à pin_length. L'utilisateur sera invité à entrer le code PIN.
-S -m rp_id device
Définit la liste des ID de parties responsables autorisées à récupérer la longueur minimale du code PIN de device. Plusieurs ID peuvent être spécifiés, séparés par des virgules. L'utilisateur sera invité à entrer le code PIN.
-S -u device
Active la fonctionnalité “vérification utilisateur toujours” CTAP 2.1 sur device.
-V
Imprime les informations de version.
-d
Cause fido2-token à émettre des sorties de débogage sur stderr.

Si un tty est disponible, fido2-token l'utilisera pour demander les codes PIN. Sinon, stdin est utilisé.

fido2-token se termine avec 0 en cas de succès et 1 en cas d'erreur.

VOIR AUSSI

fido2-assert(1), fido2-cred(1)

CAVEATS

Le flux utilisateur réel pour effectuer une réinitialisation est en dehors du champ d'application de la spécification FIDO2 et peut donc varier en fonction de l'authentificateur. Les authentificateurs Yubico ne permettent pas les réinitialisations après 5 secondes suivant la mise sous tension et s'attendent à ce qu'une réinitialisation soit confirmée par l'utilisateur par contact dans les 30 secondes.

Le chemin d'un authentificateur peut contenir des espaces.

Les informations d'identification de résident sont appelées “informations d'identification découvrables” dans CTAP 2.1.

Que la fonctionnalité CTAP 2.1 “vérification utilisateur toujours” soit activée ou désactivée après une réinitialisation de l'authentificateur dépend du fournisseur.
