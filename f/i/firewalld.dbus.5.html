org.fedoraproject.FirewallD1.direct

OBSOLÈTE

L'interface direct a été dépréciée. Elle sera supprimée dans une future version. Elle est remplacée par les politiques, voir firewalld.policies(5).

Cette interface permet un accès plus direct au pare-feu. Elle permet la manipulation d'exécution des chaînes et des règles. Pour la configuration permanente, voir l'interface org.fedoraproject.FirewallD1.config.direct.

Méthodes

addChain(s: ipv, s: table, s: chain) → Nothing

Ajoute une nouvelle chain à la table pour ipv, qui peut être ipv4 (iptables), ipv6 (ip6tables) ou eb (ebtables). Assurez-vous qu'il n'y a pas d'autre chaîne portant ce nom. Il existe déjà des chaînes de base à utiliser avec les méthodes directes, par exemple la chaîne INPUT_direct. Ces chaînes sont appelées avant les chaînes des zones, c'est-à-dire que chaque règle placée dans INPUT_direct sera vérifiée avant les règles des zones. Pour les opérations permanentes, voir org.fedoraproject.FirewallD1.config.direct.Methods.addChain.

Erreurs possibles : INVALID_IPV, INVALID_TABLE, ALREADY_ENABLED, COMMAND_FAILED

addPassthrough(s: ipv, as: args) → Nothing

Ajoute une règle de transmission suivie avec les arguments args pour ipv, qui peut être ipv4 (iptables), ipv6 (ip6tables) ou eb (ebtables). Les commandes valides dans args sont uniquement -A/--append, -I/--insert et -N/--new-chain. Cette méthode est (contrairement à la méthode passthrough) suivie, c'est-à-dire que firewalld s'en souvient. Elle est utile avec org.fedoraproject.FirewallD1.Methods.runtimeToPermanent. Pour les opérations permanentes, voir org.fedoraproject.FirewallD1.config.direct.Methods.addPassthrough.

Erreurs possibles : INVALID_IPV, ALREADY_ENABLED, COMMAND_FAILED

addRule(s: ipv, s: table, s: chain, i: priority, as: args) → Nothing

Ajoute une règle avec les arguments args à la chain dans la table avec la priority pour ipv, qui peut être ipv4 (iptables), ipv6 (ip6tables) ou eb (ebtables). La priorité
ité est utilisée pour ordonner les règles. Une priorité de 0 signifie ajouter la règle en haut de la chaîne, avec une priorité plus élevée la règle sera ajoutée plus bas. Les règles avec la même priorité sont au même niveau et l'ordre de ces règles n'est pas fixe et peut changer. Si vous voulez vous assurer qu'une règle sera ajoutée après une autre, utilisez une priorité basse pour la première et une plus élevée pour la suivante. Pour l'opération permanente voir org.fedoraproject.FirewallD1.config.direct.Methods.addRule.

NAME

firewalld.dbus - D-Bus interface to firewalld

OBJECT PATHS

The firewalld daemon exposes its functionality through D-Bus. The main object path for the daemon is /org/fedoraproject/FirewallD1.

The object paths for the specific features are:

/org/fedoraproject/FirewallD1/zone-name
Represents a firewall zone. See firewalld.zone(5).
/org/fedoraproject/FirewallD1/service-name
Represents a firewall service. See firewalld.service(5).
/org/fedoraproject/FirewallD1/icmptype-name
Represents an ICMP type. See firewalld.icmptype(5).
/org/fedoraproject/FirewallD1/ipset-name
Represents a firewall ipset. See firewalld.ipset(5).
/org/fedoraproject/FirewallD1/helper-name
Represents a firewall helper. See firewalld.helper(5).
/org/fedoraproject/FirewallD1/rich-rule-id
Represents a firewall rich rule. See firewalld.richlanguage(5).
/org/fedoraproject/FirewallD1/policy-name
Represents a firewall policy. See firewalld.policy(5).

The firewalld daemon provides the following D-Bus interfaces:

org.fedoraproject.FirewallD1

Provides methods for managing a specific firewall zone.
org.fedoraproject.FirewallD1.Service
Provides methods for managing a specific firewall service.
org.fedoraproject.FirewallD1.IcmpType
Provides methods for managing a specific ICMP type.
org.fedoraproject.FirewallD1.IpSet
Provides methods for managing a specific firewall ipset.
org.fedoraproject.FirewallD1.Policy
Provides methods for managing a specific firewall policy.
