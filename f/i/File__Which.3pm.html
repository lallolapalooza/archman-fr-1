File::Which(3) Documentation Perl fournie par l'utilisateur File::Which(3)

NOM

File::Which - Implémentation Perl de l'utilitaire which sous forme d'API

VERSION

version 1.27

SYNOPSIS

use File::Which;                  # exporte which()
use File::Which qw(which where);  # exporte which() et where()

my $chemin_exe = which 'perldoc';

my @chemins = where 'perl';
# Ou
my @chemins = which 'perl'; # un tableau force la recherche de tous

DESCRIPTION

File::Which trouve les chemins complets ou relatifs vers les programmes exécutables sur le système. C'est normalement la fonction de l'utilitaire "which". "which" est généralement implémenté soit comme un programme, soit comme une commande intégrée au shell. Sur certaines plateformes, comme Microsoft Windows, il n'est pas fourni en tant que partie intégrante du système d'exploitation. Ce module fournit une API cohérente à cette fonctionnalité, quelle que soit la plateforme sous-jacente.

L'objectif de ce module est la correction et la portabilité. Par conséquent, sur les plateformes où le répertoire courant fait implicitement partie du chemin de recherche, comme Microsoft Windows, les exécutables du répertoire courant seront trouvés, tandis que sur les plateformes comme UNIX où ce n'est pas le cas, les exécutables du répertoire courant ne seront trouvés que si le répertoire courant est explicitement ajouté au chemin.

Si vous avez besoin d'un "which" portable en ligne de commande dans un environnement qui ne le fournit pas, installez App::pwhich qui fournit une interface en ligne de commande à cette API.

Implémentations

File::Which recherche dans les répertoires du "PATH" de l'utilisateur (l'implémentation actuelle utilise File::Spec#path pour déterminer le bon "PATH"), à la recherche de fichiers exécutables portant le nom spécifié en paramètre à "which". Sous les systèmes Win32, qui n'ont pas la notion de fichiers directement exécutables, mais utilisent des extensions spéciales telles que ".exe" et ".bat" pour les identifier, "File::Which" prend des mesures supplémentaires pour s'assurer que vous trouverez le bon fichier (ainsi, par exemple, vous pourriez rechercher "perl", il essaiera perl.exe, perl.bat, etc.)

Linux, *BSD et autres UNIX

Il ne devrait pas y avoir de surprises ici. Le répertoire courant ne sera pas recherché à moins qu'il ne soit explicitement ajouté au chemin.

Windows modernes (y compris NT, XP, Vista, 7, 8, 10 etc.)

Windows NT possède une variable d'environnement spéciale appelée "PATHEXT", qui est utilisée par le shell pour rechercher des fichiers exécutables. Habituellement, elle contiendra une liste sous la forme ".EXE;.BAT;.COM;.JS;.VBS" etc. Si "File::Which" trouve une telle variable d'environnement, il analyse la liste et l'utilise comme les différentes extensions.

Cygwin

Cygwin fournit un environnement de type Unix pour les utilisateurs de Microsoft Windows. À bien des égards, il fonctionne comme d'autres environnements Unix et Unix-like, mais sur quelques aspects clés, il fonctionne comme Windows. Comme pour d'autres environnements Unix, le répertoire courant n'est pas inclus dans la recherche à moins qu'il ne soit explicitement inclus dans le chemin de recherche. Comme sous Windows, les fichiers avec les extensions ".EXE" ou ".BAT" seront découverts même s'ils ne font pas partie de la requête. Les extensions ".COM" ou celles spécifiées à l'aide de la variable d'environnement "PATHEXT" ne seront PAS découvertes sans le nom complètement qualifié, cependant.

Windows ME, 98, 95, MS-DOS, OS/2

Cet ensemble de systèmes d'exploitation n'a pas la variable "PATHEXT", et généralement vous y trouverez des fichiers exécutables avec les extensions ".exe", ".bat" et (moins probable) ".com". "File::Which" utilise cette liste codée en dur s'il s'exécute sous Win32 mais ne trouve pas de variable "PATHEXT".

Depuis 2015, aucune de ces plateformes n'est testée fréquemment (voire jamais), mais le mainteneur actuel est déterminé à ne pas supprimer intentionnellement le support des anciens systèmes d'exploitation.

VMS

Même cas que Windows 9x : utilise ".exe" et ".com" (dans cet ordre).

Depuis 2015, le mainteneur actuel ne teste pas sur VMS, et n'est même pas certain que cela ait jamais été testé sur VMS. Si cette plateforme est importante pour vous et que vous pouvez m'aider à la vérifier et/ou à la supporter sur cette plateforme, veuillez me contacter.

FONCTIONS

which

my $chemin = which $nom_exe_court;
my @chemins = which $nom_exe_court;

Exporté par défaut.

$nom_exe_court est le nom utilisé dans le shell pour appeler le programme (par exemple, "perl").

S'il trouve un exécutable portant le nom que vous avez spécifié, which() renverra le chemin absolu menant à cet exécutable (par exemple, /usr/bin/perl ou C:\Perl\Bin\perl.exe).

S'il ne trouve *pas* l'exécutable, il renvoie "undef".

Si which() est appelé dans un contexte de tableau, il renverra *toutes* les correspondances.

where

my @chemins = where $nom_exe_court;

Non exporté par défaut.

Identique à "which" en contexte de tableau. Similaire à la commande intégrée "where" de csh ou à la commande "which -a" pour les plateformes qui supportent l'option "-a". Renverra un tableau contenant tous les noms de chemins correspondant à $nom_exe_court.

GLOBALES

$IMPLICIT_CURRENT_DIR

Vrai si le répertoire courant est inclus implicitement dans la recherche sur la plateforme sur laquelle vous vous trouvez. Normalement, la valeur par défaut est raisonnable, mais sous Windows, le répertoire courant est inclus implicitement pour les shells plus anciens comme "cmd.exe" et "command.com", mais pas pour les shells plus récents comme PowerShell. Si vous outrepasser cette valeur par défaut, vous devriez TOUJOURS localiser la variable dans la portée la plus restreinte possible, car définir cette variable à partir d'un module peut affecter d'autres modules. Ainsi, sous Windows, vous pouvez obtenir le résultat correct si l'utilisateur exécute soit "cmd.exe", soit PowerShell sous Windows, vous pouvez faire ceci :

use File::Which qw( which );
use Shell::Guess;

my $chemin = do {
  my $est_power = Shell::Guess->running_shell->is_power;
  local $File::Which::IMPLICIT_CURRENT_DIR = !$est_power;
  which 'foo';
};

Pour diverses raisons, il est difficile de calculer avec précision le shell utilisé par un utilisateur, mais Shell::Guess fait un effort raisonnable.

LIMITATIONS

Ce module n'a pas de dépendances externes pour Perl 5.6.2 et supérieur.

Ce module est entièrement pris en charge à partir de Perl 5.8.1. Il peut fonctionner sur 5.8.0. Il devrait fonctionner sur 5.6.x et je pourrais même tester sur 5.6.2. J'accepterai des correctifs pour maintenir la compatibilité avec ces anciennes versions de Perl, mais vous pourriez avoir besoin de le corriger sur 5.6.x / 5.8.0 et de m'envoyer un correctif.

Non testé sur VMS bien qu'il existe du code spécifique à cette plateforme. Toute personne ayant un moment serait très gentille de m'envoyer un rapport sur le déroulement.

VOIR AUSSI
pwhich, App::pwhich
Interface en ligne de commande pour ce module.
IPC::Cmd
Nécessite Perl 5.8.3. Inclus dans le cœur de Perl à partir de la version 5.9.5.

Ce module fournot (entre autres) une "can_run" fonction, qui est similaire à "which". C'est un module beaucoup plus lourd car il fait beaucoup plus de choses, et si vous utilisez "can_run" il charge ExtUtils::MakeMaker. Cette combinaison peut être excessive pour les applications qui n'ont pas besoin de l'interface complexe d'IPC::Cmd pour exécuter des programmes, ou qui n'ont pas besoin de la surcharge mémoire nécessaire pour installer des modules Perl.

Au moins certaines anciennes versions trouveront les exécutables dans le répertoire courant, même si le répertoire courant n'est pas dans le chemin de recherche (ce qui est le défaut sur les Unix modernes).

"can_run" convertit le chemin du répertoire en version 8.3 sur Windows en utilisant "Win32::GetShortPathName" dans certains cas. C'est souvent utile pour les outils qui ont juste besoin d'exécuter quelque chose en utilisant "system" en mode scalaire, mais peut être gênant pour des outils comme App::pwhere où la lisibilité par l'utilisateur est primordiale. S'appuyer sur "Win32::GetShortPathName" pour produire des noms de fichiers sans espaces est problématique, car les noms de fichiers 8.3 peuvent être désactivés avec des modifications du registre (voir https://technet.microsoft.com/en-us/library/cc959352.aspx).

Devel::CheckBin
Nécessite Perl 5.8.1.

Ce module prétend « vérifier qu'une commande est disponible », mais ne fournit aucune documentation sur la manière dont vous pourriez l'utiliser.

Ce module s'appuie également sur ExtUtils::MakeMaker et a donc les mêmes charges de surcharge qu'IPC::Cmd.
