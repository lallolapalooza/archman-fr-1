FIND-DEBUGINFO(1) Commandes utilisateur FIND-DEBUGINFO(1)

NOM

find-debuginfo - trouve les informations de débogage et les traite

SYNTAXE

find-debuginfo [OPTION]... [rep_compilation]

DESCRIPTION

Génère automatiquement les informations de débogage et les listes de fichiers.

OPTIONS

[--strict-build-id] [-g] [-r] [-m] [-i] [-n] [-q] [-v] [--keep-section SECTION] [--remove-section SECTION] [--g-libs] [--no-ar-files] [-j N] [--jobs N] [-o debugfiles.list] [-S debugsourcefiles.list] [--run-dwz] [--dwz-low-mem-die-limit N] [--dwz-max-die-limit N] [--dwz-single-file-mode] [--build-id-seed SEED] [--unique-debug-suffix SUFFIX] [--unique-debug-src-base BASE] [[-l fichier]... [-p 'motif'] -o list_debuginfo] [rep_compilation]

L'option -g indique d'utiliser strip -g au lieu de strip complet sur les DSOs ou les exécutables. L'option --g-libs indique d'utiliser strip -g au lieu de strip complet UNIQUEMENT sur les DSOs. Les options -g et --g-libs s'excluent mutuellement.

L'option -r indique d'utiliser eu-strip --reloc-debug-sections.

Utilisez --keep-section SECTION ou --remove-section SECTION pour conserver explicitement une section (non allouée) dans l'exécutable principal ou pour la supprimer explicitement dans le fichier .debug. SECTION est un motif wildcard étendu. Ces deux options peuvent être utilisées plusieurs fois.

L'option --strict-build-id indique de sortir avec un statut d'échec si un binaire ELF traité ne contient pas de note build-id.

L'option -m indique d'inclure une section .gnu_debugdata (MiniDebugInfo) dans le binaire principal.

L'option -i indique d'inclure une section .gdb_index dans le fichier .debug.

L'option -n indique de ne pas recalculer le build-id.

L'option -j, --jobs N lancera N processus pour effectuer l'extraction des informations de débogage en parallèle.

Un seul commutateur -o avant tout commutateur -l ou -p renomme simplement le fichier de sortie principal de debugfiles.list à autre chose. Un commutateur -o qui suit un commutateur -p ou certains commutateurs -l produit un fichier de sortie supplémentaire avec les informations de débogage pour les fichiers dans la liste de fichiers -l, ou dont les noms correspondent au motif -p. L'argument -p est une expression régulière de style grep -E correspondant au nom d'un fichier, et ne doit pas utiliser d'ancres (^ ou $).

L'option --run-dwz indique à find-debuginfo d'exécuter l'utilitaire dwz si disponible, et --dwz-low-mem-die-limit et --dwz-max-die-limit fournissent des limites détaillées. Voir dwz(1) option -l et -L pour les détails. Utilisez --dwz-single-file-mode pour désactiver le mode multi-fichiers, voir dwz(1) option -m pour plus de détails.

Si --build-id-seed SEED est spécifié, alors debugedit est appelé pour mettre à jour les build-ids trouvés en ajoutant SEED comme graine pour recalculer le hash du build-id. Cela garantit que les build-ids dans les fichiers ELF sont uniques entre les versions et les publications du même paquet. (Utilisez --build-id-seed "%{VERSION}-%{RELEASE}".)

Si --unique-debug-suffix SUFFIX est spécifié, alors les fichiers de débogage créés pour <FICHIER> seront nommés <FICHIER>-<SUFFIX>.debug. Cela garantit que les .debug sont uniques entre la version du paquet, la publication et l'architecture. (Utilisez --unique-debug-suffix "-%{VERSION}-%{RELEASE}.%{_arch}".)

Si --unique-debug-src-base BASE est spécifié, alors le répertoire source sera appelé /usr/debug/src/<BASE>. Cela garantit que les répertoires source de débogage sont uniques entre la version du paquet, la publication et l'architecture (Utilisez --unique-debug-src-base "%{name}-%{VERSION}-%{RELEASE}.%{_arch}")

Si --no-ar-files est spécifié, alors les bibliothèques statiques seront ignorées. Sinon, elles sont uniquement traitées avec la réécriture et la collecte des chemins sources. Elles ne sont pas dénudées, car elles n'ont pas de build-ids persistants pour permettre une réunification éventuelle.

L'option -q ou --quiet désactive toute sortie non-erreur du script. L'option -v ou --verbose ajoute plus de sortie pour chaque fichier traité. Lorsque ni -q ni -v ne sont spécifiés, seule la sortie pour chaque passe est donnée.

Tous les noms de fichiers dans les commutateurs sont relatifs à rep_compilation ('.' si non spécifié).
