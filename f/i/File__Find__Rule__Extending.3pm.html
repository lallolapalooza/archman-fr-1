NOM

File::Find::Rule::Extending - le mini-guide pour étendre File::Find::Rule

SYNOPSIS

package File::Find::Rule::Random;
use strict;

# importer des éléments utiles de File::Find::Rule
use base 'File::Find::Rule';
# et forcer notre ajout dans l'espace de noms principal
sub File::Find::Rule::random () {
    my $self = shift()->_force_object;
    $self->exec( sub { rand > 0.5 } );
}

1;

DESCRIPTION

File::Find::Rule a été si bien accueilli par le public qu'il a suscité l'envie d'ajouter des fonctionnalités supplémentaires. Depuis la version 0.07, cela est devenu possible en utilisant les conventions suivantes.

Déclarer votre paquet

package File::Find::Rule::Random;
use strict;

Hériter des méthodes de File::Find::Rule

# importer des éléments utiles de File::Find::Rule
use base 'File::Find::Rule';

Forcer votre folie dans le paquet principal

# et forcer notre ajout dans l'espace de noms principal
sub File::Find::Rule::random () {
    my $self = shift()->_force_object;
    $self->exec( sub { rand > 0.5 } );
}

Oui, nous sommes très désinvoltes ici et définissons des choses dans l'espace de noms principal de File::Find::Rule. Ceci est dû à un manque d'imagination de ma part - je ne trouve tout simplement aucun moyen pour que l'interface fonctionnelle et l'interface orientée objet fonctionnent sans faire cela ou un certain type d'héritage, et l'héritage vous empêche d'utiliser deux modules File::Find::Rule::Foo ensemble.

Pour cette raison, essayez de choisir des noms distincts pour vos extensions. Si cela devient un problème, je pourrai peut-être mettre en place un registre semi-officiel des noms utilisés.

Ne pas prendre d'arguments.

Notez le prototype nul sur random. C'est une astuce pour que l'interface procédurale sache que votre sous-routine ne prend aucun argument, et permet donc ceci :

find( random => in => '.' );

Si vous n'aviez pas déclaré "random" avec un prototype nul, il aurait consommé "in" comme paramètre, puis se serait confus car il ne connaît pas la règle '.'.
