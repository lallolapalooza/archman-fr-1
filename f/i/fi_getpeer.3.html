NOM

fi_cm - Opérations de gestion de connexion

fi_connect / fi_listen / fi_accept / fi_reject / fi_shutdown
Gérer l'état de connexion du point d'extrémité.
fi_setname / fi_getname / fi_getpeer
Définir, ou retourner l'adresse locale ou distante du point d'extrémité.
fi_join / fi_close / fi_mc_addr
Rejoindre, quitter ou récupérer une adresse multicast.

SYNTAXE

#include <rdma/fi_cm.h>
int fi_connect(struct fid_ep *ep, const void *addr,
    const void *param, size_t paramlen);
int fi_listen(struct fid_pep *pep);
int fi_accept(struct fid_ep *ep, const void *param, size_t paramlen);
int fi_reject(struct fid_pep *pep, fid_t handle,
    const void *param, size_t paramlen);
int fi_shutdown(struct fid_ep *ep, uint64_t flags);
int fi_setname(fid_t fid, void *addr, size_t addrlen);
int fi_getname(fid_t fid, void *addr, size_t *addrlen);
int fi_getpeer(struct fid_ep *ep, void *addr, size_t *addrlen);
int fi_join(struct fid_ep *ep, const void *addr, uint64_t flags,
    struct fid_mc **mc, void *context);
int fi_close(struct fid *mc);
fi_addr_t fi_mc_addr(struct fid_mc *mc);

ARGUMENTS

ep / pep
Point d'extrémité Fabric sur lequel changer l'état de connexion.

fid Point d'extrémité actif ou passif pour obtenir/définir l'adresse.

addr
Buffer pour l'adresse. Lors d'un appel de définition, le point d'extrémité se verra attribuer l'adresse spécifiée. Lors d'un appel de récupération, l'adresse locale sera copiée dans le buffer, dans la limite de l'espace fourni. Pour la connexion, ce paramètre indique l'adresse du pair à contacter. L'adresse doit être dans le même format que celui spécifié en utilisant fi_info: addr_format lors de la création du point d'extrémité.
addrlen
À l'entrée, spécifie la taille du buffer addr. À la sortie, stocke le nombre d'octets écrits dans le buffer addr.
param
Données spécifiées par l'utilisateur échangées dans le cadre de l'échange de connexion.
paramlen
Taille du buffer param.
info
Informations Fabric associées à une demande de connexion.
mc
Groupe multicast associé à un point d'extrémité.
flags
Indicateurs supplémentaires pour contrôler l'opération de connexion.
context
Contexte utilisateur associé à la requête.

DESCRIPTION

Les fonctions de gestion de connexion sont utilisées pour connecter un point d'extrémité orienté connexion (FI_EP_MSG) à un pair en écoute.

fi_listen

L'appel fi_listen indique que le point d'extrémité spécifié doit être transitionné vers un état de connexion passive, lui permettant d'accepter les demandes de connexion entrantes. Les demandes de connexion adressées à un point d'extrémité en écoute sont rapportées de manière asynchrone à l'utilisateur via une file d'événements CM liée en utilisant le type d'événement FI_CONNREQ. Le nombre de requêtes de connexion en attente pouvant être mises en file d'attente sur un point d'extrémité est limité par le paramètre de backlog du point d'extrémité en écoute. Le backlog est initialisé en fonction des valeurs de configuration administrative, mais peut être ajusté via l'appel fi_control.

fi_connect

L'appel fi_connect initie une demande de connexion sur un point d'extrémité orienté connexion vers l'adresse de destination. fi_connect ne peut être appelé sur un point d'extrémité qu'une seule fois dans sa vie.

fi_accept / fi_reject

Les appels fi_accept et fi_reject sont utilisés du côté passif (écoute) d'une connexion pour accepter ou rejeter une demande de connexion, respectivement. Pour accepter une connexion, l'application en écoute attend d'abord un événement de demande de connexion (FI_CONNREQ). Après avoir reçu un tel événement, l'application alloue un nouveau point d'extrémité pour accepter la connexion. Ce point d'extrémité doit être alloué en utilisant une structure fi_info faisant référence au handle de cet événement FI_CONNREQ. fi_accept est ensuite appelé avec le point d'extrémité nouvellement alloué. Si l'application en écoute souhaite rejeter une demande de connexion, elle appelle fi_reject avec le point d'extrémité en écoute et une référence à la demande de connexion.

Une demande de connexion acceptée avec succès entraînera la génération d'un événement FI_CONNECTED sur la file d'événements associée au point d'extrémité actif (connecteur). Une demande de connexion rejetée ou échouée générera un événement d'erreur. L'entrée d'erreur fournira des détails supplémentaires décrivant la raison de la tentative échouée.

Un événement FI_CONNECTED sera également généré du côté passif pour le point d'extrémité acceptant une fois que la connexion a été correctement établie. Le fid de l'événement FI_CONNECTED sera celui du point d'extrémité passé à fi_accept par opposition au point d'extrémité passif en écoute. Les transferts de données sortants ne peuvent être initiés sur un point d'extrémité orienté connexion qu'après la génération d'un événement FI_CONNECTED. Cependant, les buffers de réception peuvent être associés à un point d'extrémité à tout moment.

fi_shutdown

L'appel fi_shutdown est utilisé pour déconnecter gracieusement un point d'extrémité de son pair. Le paramètre flags est réservé et doit être 0.

Les opérations en cours postées au point d'extrémité lorsque fi_shutdown est appelé seront annulées ou rejetées. La notification des opérations annulées sera rapportée par le fournisseur aux files d'achèvement correspondantes. Les opérations rejetées seront silencieusement abandonnées, sans générer d'achèvement. Le choix entre annuler et rejeter les opérations dépend du fournisseur. Cependant, tous les achèvements annulés seront écrits avant le retour de fi_shutdown.

Lorsqu'il est appelé, fi_shutdown n'affecte pas les achèvements déjà écrits dans une file d'achèvement. Tous les achèvements mis en file d'attente associés à des opérations asynchrones postées sur le point d'extrémité peuvent encore être récupérés des files d'achèvement correspondantes après la fermeture d'un point d'extrémité.

Un événement FI_SHUTDOWN sera généré pour un point d'extrémité lorsque le pair distant émet une déconnexion en utilisant fi_shutdown ou ferme brusquement le point d'extrémité. Notez que dans le cas d'une fermeture brusque, un événement FI_SHUTDOWN ne sera généré que si le système distant est joignable et qu'un agent de service ou du noyau sur le système distant est capable de notifier le point d'extrémité local que la connexion a été interrompue.

fi_close

Fi_close est utilisé pour dissocier un point d'extrémité d'un groupe multicast et fermer toutes les ressources associées au groupe. Fi_close doit être appelé sur tous les groupes multicast que rejoint un point d'extrémité.

fi_setname

L'appel fi_setname peut être utilisé pour modifier ou attribuer l'adresse du point d'extrémité local. Il est conceptuellement similaire à l'opération bind des sockets. Un point d'extrémité peut se voir attribuer une adresse lors de sa création, via la structure fi_info. L'appel fi_setname permet de créer un point d'extrémité sans l'associer à un service spécifique (par exemple, numéro de port) et/ou une adresse de nœud (par exemple, réseau), l'adressage étant attribué dynamiquement. Le format des données d'adressage spécifiées doit correspondre à celui spécifié via la structure fi_info lors de la création du point d'extrémité.

Si aucune adresse de service n'est spécifiée et qu'une adresse de service n'a pas encore été attribuée au point d'extrémité, le fournisseur allouera une adresse de service et l'attribuera au point d'extrémité. Si une adresse de nœud ou de service est spécifiée, alors, après achèvement réussi de fi_setname, le point d'extrémité se verra attribuer l'adressage donné. Si une adresse ne peut pas être attribuée, ou si l'adresse du point d'extrémité ne peut pas être modifiée, un numéro d'erreur Fabric approprié est retourné.

fi_getname / fi_getpeer

Les appels fi_getname et fi_getpeer peuvent être utilisés pour récupérer respectivement l'adresse locale ou distante du point d'extrémité. En entrée, le paramètre addrlen doit indiquer la taille du buffer addr. Si l'adresse réelle est plus grande que ce qui peut tenir dans le buffer, elle sera tronquée et -FI_ETOOSMALL sera retourné.

. En sortie, addrlen est défini à la taille du tampon nécessaire pour stocker l'adresse, qui peut être supérieure à la valeur

d'entrée.

fi_getname n'est pas garanti de retourner une adresse source valide tant que le point de terminaison spécifié n'a pas été activé ou n'a pas eu une adresse assignée. Un point de

terminaison peut être activé explicitement via fi_enable, ou implicitement, comme via fi_connect ou fi_listen. Une adresse peut être assignée en utilisant fi_setname. fi_getpeer n'est pas garanti de retourner une adresse de pair valide tant qu'un point de terminaison n'a pas été complètement connecté – un événement FI_CONNECTED n'a pas été généré.

fi_joi

n

Cette fonction attache un point de terminaison à un groupe de multidiffusion. Par défaut, le point de terminaison rejoindra le groupe en fonction des capacités de transfert de données du point de terminaison. Par exemple, si le point de terminaison a été configuré pour à la fois envoyer et recevoir des données, alors le point de terminaison sera capable d'initier et de recevoir des transferts vers et depuis le groupe de multidiffusion. Les indicateurs de fi_join peuvent être utilisés pour restreindre l'accès au groupe de multidiffusion, sous réserve des limitations de capacité du point de

terminaison.

Les opérations de rejoindre en multidiffusion se terminent de manière asynchrone. Un point de terminaison doit être lié à une file d'événements avant d'appeler fi_join. Le résultat de l'opération de rejoindre sera rapporté à la file d'événements (EQ) sous la forme d'un événement FI_JOIN_COMPLETE. Les applications ne peuvent pas émettre de transferts en multidiffusion avant de recevoir la notification que l'opération de rejoindre est terminée. Notez qu'un point de terminaison peut commencer à recevoir des messages du groupe de multidiffusion dès que le rejoindre est terminé, ce qui peut survenir avant que l'événement FI_JOIN_COMPLETE ne soit

généré.

Les applications doivent appeler fi_close sur le groupe de multidiffusion pour déconnecter l

e point de terminaison du groupe. Après qu'une opération de rejoindre est terminée, l'appel
fi_mc_addr peut être utilisé pour récupérer l'adresse associée au groupe de multidiffusion.

NOTE

S

Pour les points de terminaison orientés connexion, le tampon référencé par param sera envoyé dans le cadre de la demande ou de la réponse de connexion, sous réserve des contraintes du protocole de connexion sous-jacent. Les applications peuvent utiliser fi_getopt avec l'option de point de termi

essages du protocole sous-jacent. Les données utilisateur échangées dans le cadre du processus de connexion sont disponibles dans la structure fi_eq_cm_entry, pour les événements FI_CONNREQ et FI_CONNECTED, ou comme err_data supplémentaire à fi_eq_err_entry, dans le cas d'une connexion rejetée.
