DESCRIPTIO

N

"File::Temp" peut être utilisé pour créer et ouvrir des fichiers temporaires de manière sécurisée. Il existe à la fois une interface de fonction et une interface orientée objet. Le constructeur File::Temp ou la fonction tempfile() peut être utilisée pour retourner le nom et le descripteur de fichier ouvert d'un fichier temporaire. La fonction tempdir() peut être utilisée pour créer un répertoire

temporaire.

L'aspect sécurité de la création de fichiers temporaires est mis en avant de telle sorte qu'un descripteur de fichier et un nom de fichier sont retournés ensemble. Cela aide à garantir qu'une condition de course ne peut pas se produire où le fichier temporaire est créé par un autre processus entre la vérification de l'existence du fichier et son ouverture. Des niveaux de sécurité supplémentaires sont fournis pour vérifier, par exemple, que le bit collant est défini sur les répertoires accessibles en écriture à tous. Voir "safe_level" pour plus

d'informations.

Pour la compatibilité avec les fonctions populaires de la bibliothèque C, des implémentations Perl des fonctions de la famille mkstemp() sont fournies. Ce sont, mkstemp(), mkstemps(), mkdtemp() et mktemp

().

De plus, des implémentations des fonctions POSIX standard tmpnam() et tmpfile() sont fournies si

nécessaire.

Des implémentations de mktemp(), tmpnam(), et tempnam() sont fournies, mais devraient être utilisées avec prudence car elles retournent seulement un nom de fichier qui était valide au moment où la fonction a été appelée, et ne peuvent donc pas garantir que le fichier n'existera pas au moment où l'appelant ouvrira le nom de

fichier.

INTERFACE ORIENTÉE

OBJET

C'est l'interface principale pour interagir avec "File::Temp". En utilisant l'interface OO, un fichier temporaire peut être créé lorsque l'objet est construit et le fichier peut être supprimé lorsque l'objet n'est plus

nécessaire.

Notez qu'il n'y a pas de méthode pour obtenir le descripteur de fichier depuis l'objet "File::Temp". L'objet lui-même agit comme un descripteur de fichier. L'objet est un "IO::Handle" et est un "IO::Seekable", donc toutes ces méthodes sont

disponibles.

De plus, l'objet est configuré de telle sorte qu'il se convertit en chaîne vers le nom du fichier temporaire et peut donc être comparé directement à un nom de fichier. Il se convertit en nombre vers le "refaddr" comme les autres descripteurs et peut donc être comparé à d'autres descripteurs avec "=="

. 
$fh eq $filename       # comme une chaîne
$fh != \*STDOUT        # comme un
nombre

FONCTION

S

Cette section décrit l'interface recommandée pour générer des fichiers temporaires et

les répertoires.

tempfile
Ceci est la fonction de base pour générer des fichiers temporaires. Le comportement du fichier peut être modifié en utilisant diverses options : 
$fh = tempfile();
($fh, $filename) = tempfile();

Crée un fichier temporaire dans le répertoire spécifié pour les fichiers temporaires, tel que spécifié par la fonction tmpdir() de File::Spec.

($fh, $filename) = tempfile($template);

Crée un fichier temporaire dans le répertoire courant en utilisant le modèle fourni. Les caractères `X' finaux sont remplacés par des lettres aléatoires pour générer le nom du fichier. Au moins quatre caractères `X' doivent être présents à la fin du modèle.

($fh, $filename) = tempfile($template, SUFFIX => $suffix)

Identique à ce qui précède, sauf qu'un suffixe est ajouté au modèle après la traduction des `X'. Utile pour s'assurer qu'un nom de fichier temporaire a une extension particulière lorsqu'il est nécessaire à d'autres applications. Mais voir l'AVERTISSEMENT à la fin.

($fh, $filename) = tempfile($template, DIR => $dir);

Traduit le modèle comme précédemment, sauf qu'un nom de répertoire est spécifié.

($fh, $filename) = tempfile($template, TMPDIR => 1);

Équivalent à spécifier un DIR de "File::Spec->tmpdir", écrivant le fichier dans le même répertoire temporaire que celui qui serait utilisé si aucun modèle n'était spécifié du tout.

($fh, $filename) = tempfile($template, UNLINK => 1);

Retourne le nom du fichier et le descripteur de fichier comme précédemment, sauf que le fichier est automatiquement supprimé lorsque le programme se termine (dépend de $KEEP_ALL). Par défaut, le fichier est supprimé si un descripteur de fichier est demandé et conservé si le nom du fichier est demandé. Dans un contexte scalaire (où aucun nom de fichier n'est retourné) le fichier est toujours supprimé soit (selon le système d'exploitation) à la sortie, soit lorsqu'il est fermé (sauf si $KEEP_ALL est vrai lorsque le fichier temporaire est créé).

Utilisez l'interface orientée objet si un contrôle fin de quand un fichier est supprimé est requis.

Si le modèle n'est pas spécifié, un modèle est toujours généré automatiquement. Ce fichier temporaire est placé dans tmpdir() (File::Spec) à moins qu'un répertoire ne soit spécifié explicitement avec l'option DIR.

$fh = tempfile( DIR => $dir );

S'il est appelé dans un contexte scalaire, seul le descripteur de fichier est retourné et le fichier sera automatiquement supprimé lorsqu'il sera fermé sur les systèmes d'exploitation qui le supportent (voir la description de tmpfile() ailleurs dans ce document). C'est le mode de fonctionnement préféré, car si vous n'avez qu'un descripteur de fichier, vous ne pouvez jamais créer de condition de concurrence en manipulant le nom du fichier. Sur les systèmes qui ne peuvent pas délier un fichier ouvert ou ne peuvent pas marquer un fichier comme temporaire lorsqu'il est ouvert (par exemple, Windows NT utilise le "O_TEMPORARY" flag) le fichier est marqué pour suppression lorsque le programme se termine (équivalent à régler UNLINK sur 1). Le "UNLINK" flag est ignoré s'il est présent.

(undef, $filename) = tempfile($template, OPEN => 0);

Cela retournera le nom du fichier basé sur le modèle mais n'ouvrira pas ce fichier. Ne peut pas être utilisé conjointement avec UNLINK défini sur vrai. Par défaut, le fichier est toujours ouvert pour se protéger d'éventuelles conditions de concurrence. Un avertissement est émis si les avertissements sont activés. Envisagez d'utiliser les fonctions tmpnam() et mktemp() décrites ailleurs dans ce document si l'ouverture du fichier n'est pas requise.

Pour ouvrir le descripteur de fichier temporaire avec O_EXLOCK (ouvrir avec un verrou exclusif sur le fichier) utilisez "EXLOCK=>1". Ceci n'est pris en charge que par certains systèmes d'exploitation (notamment les systèmes dérivés de BSD). Par défaut, EXLOCK sera faux. Les anciennes versions de "File::Temp" définissaient EXLOCK sur vrai, donc pour être sûr d'obtenir un descripteur de fichier déverrouillé également avec les anciennes versions, définissez explicitement "EXLOCK=>0".

($fh, $filename) = tempfile($template, EXLOCK => 1);

Par défaut, le fichier temporaire est créé avec des permissions de fichier 0600. Utilisez "PERMS" pour changer cela :

($fh, $filename) = tempfile($template, PERMS => 0666);

Les options peuvent être combinées selon les besoins.

Va croak() s'il y a une erreur.

tempdir
C'est l'interface recommandée pour la création de répertoires temporaires. Par défaut, le répertoire ne sera pas supprimé à la sortie (c'est-à-dire qu'il ne sera pas temporaire ; ce comportement ne peut pas être modifié en raison de problèmes de compatibilité ascendante). Pour activer la suppression, utilisez l'option CLEANUP qui déclenchera la suppression à la sortie du programme, ou envisagez d'utiliser la méthode "newdir" de l'interface objet qui permettra au répertoire d'être nettoyé lorsque l'objet sort de sa portée.

Le comportement de la fonction dépend des arguments :

$tempdir = tempdir();

Crée un répertoire dans tmpdir() (voir File::Spec).

$tempdir = tempdir( $template );

Crée un répertoire à partir du modèle fourni. Ce modèle est similaire à celui décrit pour tempfile(). Les caractères `X' à la fin du modèle sont remplacés par des lettres aléatoires pour construire le nom du répertoire. Au moins quatre caractères `X' doivent être dans le modèle.

$tempdir = tempdir ( DIR => $dir );

Spécifie le répertoire à utiliser pour le répertoire temporaire. Le nom du répertoire temporaire est dérivé d'un modèle interne.

$tempdir = tempdir ( $template, DIR => $dir );

Prépare le nom du répertoire fourni au modèle. Le modèle ne doit pas inclure lui-même de spécifications de répertoire parent. Toute spécification de répertoire parent est supprimée du modèle avant de préparer le répertoire fourni.

$tempdir = tempdir ( $template, TMPDIR => 1 );

En utilisant le modèle fourni, crée le répertoire temporaire dans un emplacement standard pour les fichiers temporaires. Équivalent à faire

$tempdir = tempdir ( $template, DIR => File::Spec->tmpdir);

mais plus court. Les spécifications de répertoire parent sont dépouillées du modèle lui-même. L'option "TMPDIR" est ignorée si "DIR" est explicitement définie. De plus, "TMPDIR" est implicite si ni un modèle ni un répertoire ne sont fournis.

$tempdir = tempdir( $template, CLEANUP => 1);

Crée un répertoire temporaire en utilisant le modèle fourni, mais tente de le supprimer (ainsi que tous les fichiers qu'il contient) à la sortie du programme. Notez qu'une tentative sera faite pour supprimer tous les fichiers du répertoire même s'ils n'ont pas été créés par ce module (sinon pourquoi demander à le nettoyer ?). La suppression du répertoire est effectuée avec la fonction rmtree() du module File::Path. Bien sûr, si le modèle n'est pas spécifié, le répertoire temporaire sera créé dans tmpdir() et sera également supprimé à la sortie du programme.

Va croak() s'il y a une erreur.

API actuelle disponible depuis 0.05.

FONCTIONS MKTEMP

Les fonctions suivantes sont des implémentations Perl des appels système de la famille mktemp() pour la génération de fichiers temporaires.

mkstemp
Étant donné un modèle, retourne un descripteur de fichier pour le fichier temporaire et le nom du fichier. 
($fh, $name) = mkstemp( $template );

Dans un contexte scalaire, seul le descripteur de fichier est retourné.

Le modèle peut être n'importe quel nom de fichier avec un certain nombre de X appended, par exemple /tmp/temp.XXXX. Les X finaux sont remplacés par des combinaisons alphanumériques uniques.

Va croak() s'il y a une erreur.

API actuelle disponible depuis 0.05.

mkstemps
Similaire à mkstemp(), sauf qu'un argument supplémentaire peut être fourni avec un suffixe à ajouter au modèle. 
($fh, $name) = mkstemps( $template, $suffix );

Par exemple, un modèle de "testXXXXXX" et un suffixe de ".dat" généreraient un fichier similaire à testhGji_w.dat.

Retourne uniquement le descripteur de fichier lorsqu'il est appelé dans un contexte scalaire.

Va croak() s'il y a une erreur.

API actuelle disponible depuis 0.05.

mkdtemp
Crée un répertoire à partir d'un modèle. Le modèle doit se terminer par des X qui sont remplacés par la routine. 
$tmpdir_name = mkdtemp($template);

Retourne le nom du répertoire temporaire créé.

Le répertoire doit être supprimé par l'appelant.

Va croak() s'il y a une erreur.

API actuelle disponible depuis 0.05.

mktemp
Retourne un nom de fichier temporaire valide mais ne garantit pas que le fichier ne sera pas ouvert par quelqu'un d'autre. 
$unopened_file = mktemp($template);

Le modèle est identique à celui requis par mkstemp().

Va croak() s'il y a une erreur.

API actuelle disponible depuis 0.05.

FONCTIONS POSIX

Cette section décrit la réimplémentation des fonctions tmpnam() et tmpfile() décrites dans POSIX à l'aide de mkstemp() de ce module.

Contrairement aux implémentations POSIX, le répertoire utilisé pour le fichier temporaire n'est pas spécifié dans un fichier d'inclusion système ("P_tmpdir") mais dépend simplement du choix de tmpdir() retourné par File::Spec. Sur certaines implémentations, cet emplacement peut être défini à l'aide de la variable d'environnement "TMPDIR", qui peut ne pas

être sécurisé. Si cela pose problème, utilisez simplement mkstemp() et spécifiez un

modèle.

Fonctions utiles pour manipuler le descripteur de fichier et le nom de

unlin
k0
Étant donné un descripteur de fichier ouvert et le nom de fichier associé, effectue une suppression (unlink) sûre. Cela est réalisé en vérifiant d'abord que le nom de fichier et le descripteur de fichier pointent initialement vers le même fichier et que le nombre de liens vers le fichier est de 1 (tous les champs renvoyés par stat() sont comparés). Ensuite, le nom de fichier est supprimé (unlink) et le descripteur de fichier est vérifié à nouveau pour s'assurer que le nombre de liens sur ce fichier est maintenant de 0. C'est le plus proche que vous puissiez obtenir pour vous assurer que le nom de fichier supprimé était bien celui du fichier dont vous détenez le descripteur. 
unlink0($fh, $path)
   or die "Error unlinking file $path
safely";

Renvoie faux en cas d'erreur mais croak() en cas d'anomalie de sécurité. Le descripteur de fichier n'est pas fermé car cela n'est pas toujours

requis.

Sur certaines plateformes, par exemple Windows NT, il n'est pas possible de supprimer (unlink) un fichier ouvert (le fichier doit d'abord être fermé). Sur ces plateformes, la suppression réelle est différée jusqu'à la fin du programme et un statut de succès est renvoyé. Une vérification est toujours effectuée pour s'assurer que le descripteur de fichier et le nom de fichier pointent vers la même chose (mais pas au moment où le bloc END est exécuté car la suppression différée peut ne pas avoir accès au descripteur de

fichier).

De plus, sur Windows NT, tous les champs renvoyés par stat() ne peuvent pas être comparés. Par exemple, les champs « dev » et « rdev » semblent être différents. De plus, il semble que la taille du fichier renvoyée par stat() ne corresponde pas toujours, avec stat(FH) étant plus précis que stat(filename), probablement à cause de problèmes de cache même en utilisant autoflush (ce problème est généralement surmonté en attendant un moment après avoir écrit dans le fichier temporaire avant d'essayer de « unlink0

»).

Enfin, sur les systèmes de fichiers NFS, le nombre de liens du descripteur de fichier ne passe pas toujours à zéro immédiatement après la suppression. Actuellement, cette commande est censée échouer sur les disques

NFS.

Cette fonction est désactivée si la variable globale $KEEP_ALL est vraie et qu'un unlink sur un fichier ouvert est pris en charge. Si le unlink doit être différé jusqu'au bloc END, le fichier est toujours enregistré pour

suppression.

Cette fonction ne devrait pas être appelée si vous utilisez l'interface orientée objet car elle interférera avec le destructeur d'objet supprimant le

fichier.
