NOM

fi_sockets - Le fournisseur de fabric Sockets

APERÇU

Le fournisseur sockets est déprécié en faveur des fournisseurs tcp, udp et utility. Les développements futurs sur le fournisseur sockets seront minimaux. La plupart des applications devraient utiliser le fournisseur tcp à la place.

Le fournisseur sockets est un fournisseur à usage général qui peut être utilisé sur n'importe quel système supportant les sockets TCP. Le fournisseur n'est pas destiné à améliorer les performances par rapport aux sockets TCP ordinaires, mais plutôt à permettre aux développeurs d'écrire, de tester et de déboguer du code applicatif, même sur des plateformes qui ne disposent pas de matériel de fabric haute performance. Le fournisseur sockets prend en charge toutes les exigences et interfaces du fournisseur libfabric.

FONCTIONNALITÉS PRISES EN CHARGE

Le fournisseur sockets prend en charge toutes les fonctionnalités définies pour l'API libfabric. Les fonctionnalités clés incluent :

Types de points de terminaison
Le fournisseur prend en charge tous les types de points de terminaison : FI_EP_MSG, FI_EP_RDM et FI_EP_DGRAM.
Capacités des points de terminaison
L'interface de transfert de données suivante est prise en charge pour tous les types de points de terminaison : fi_msg. De plus, ces interfaces sont prises en charge pour les points de terminaison fiables (FI_EP_MSG et FI_EP_RDM) : fi_tagged, fi_atomic et fi_rma.
Modes
Le fournisseur sockets prend en charge tous les modes opérationnels, y compris FI_CONTEXT et FI_MSG_PREFIX.
Progression
Le fournisseur sockets prend en charge FI_PROGRESS_AUTO et FI_PROGRESS_MANUAL, avec une valeur par défaut à auto. Lorsque la progression est définie sur auto, un thread d'arrière-plan s'exécute pour garantir la progression des requêtes asynchrones.

LIMITATIONS

Le fournisseur sockets tente d'émuler l'ensemble complet de l'API, y compris toutes les options définies. Afin de prendre en charge le développement sur une large gamme de systèmes, il est implémenté sur des sockets TCP. Par conséquent, les chiffres de performance sont inférieurs par rapport à d'autres fournisseurs implémentés sur des fabric à haute vitesse, et inférieurs à ce qu'une application pourrait observer en s'interfaçant directement avec les sockets.

Ne prend pas en charge le format d'adresse FI_ADDR_STR.

PARAMÈTRES D'EXÉCUTION

Le fournisseur sockets vérifie les variables d'environnement suivantes :

FI_SOCKETS_PE_WAITTIME
Une valeur entière qui spécifie le nombre de millisecondes à attendre pour la progression en mode FI_PROGRESS_AUTO.
FI_SOCKETS_CONN_TIMEOUT
Une valeur entière qui spécifie le nombre de millisecondes à attendre pour l'établissement d'une connexion.
FI_SOCKETS_MAX_CONN_RETRY
Une valeur entière qui spécifie le nombre de tentatives de connexion de socket avant de signaler un échec.
FI_SOCKETS_DEF_CONN_MAP_SZ
Un entier pour spécifier la taille par défaut de la carte de connexion.
FI_SOCKETS_DEF_AV_SZ
Un entier pour spécifier la taille par défaut du vecteur d'adresses.
FI_SOCKETS_DEF_CQ_SZ
Un entier pour spécifier la taille par défaut de la file d'attente de complétion.
FI_SOCKETS_DEF_EQ_SZ
Un entier pour spécifier la taille par défaut de la file d'attente d'événements.
FI_SOCKETS_DGRAM_DROP_RATE
Une valeur entière pour spécifier le taux de perte de trames dgram lorsque le point de terminaison est FI_EP_DGRAM. Ceci est uniquement à des fins de débogage.
FI_SOCKETS_PE_AFFINITY
Si spécifié, le thread de progression est lié à la ou aux plages spécifiées d'identifiants de processeur virtuel Linux. Cette option n'est actuellement pas prise en charge sur OS X. L'utilisation est - id_start[-id_end[:stride]][,].
FI_SOCKETS_KEEPALIVE_ENABLE
Un booléen pour activer la prise en charge de keepalive.
FI_SOCKETS_KEEPALIVE_TIME
Un entier pour spécifier le temps d'inactivité en secondes avant d'envoyer la première sonde keepalive. Uniquement pertinent si FI_SOCKETS_KEEPALIVE_ENABLE est activé.
FI_SOCKETS_KEEPALIVE_INTVL
Un entier pour spécifier le temps en secondes entre les sondes keepalive individuelles. Uniquement pertinent si FI_SOCKETS_KEEPALIVE_ENABLE est activé.
FI_SOCKETS_KEEPALIVE_PROBES
Un entier pour spécifier le nombre maximum de sondes keepalive envoyées avant de fermer la connexion. Uniquement pertinent si FI_SOCKETS_KEEPALIVE_ENABLE est activé.
FI_SOCKETS_IFACE
Le préfixe ou le nom de l'interface réseau (par défaut : any)

TRAVAUX À GRANDE ÉCHELLE

Pour les exécutions à grande échelle, vous pouvez utiliser ces variables d'environnement pour définir les paramètres par défaut, par exemple : la taille du vecteur d'adresses (AV), de la file d'attente de complétion (CQ), de la carte de connexion, etc., qui satisfont les exigences du benchmark particulier. Les paramètres recommandés pour les exécutions à grande échelle sont FI_SOCKETS_MAX_CONN_RETRY, FI_SOCKETS_DEF_CONN_MAP_SZ, FI_SOCKETS_DEF_AV_SZ, FI_SOCKETS_DEF_CQ_SZ, FI_SOCKETS_DEF_EQ_SZ.
