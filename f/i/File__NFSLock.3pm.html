NOM

File::NFSLock - module Perl pour effectuer le verrouillage NFS (ou autre)

SYNOPSIS

use File::NFSLock qw(uncache);
use Fcntl qw(LOCK_EX LOCK_NB);
my $file = "somefile";
### configurer un verrou - dure jusqu'à ce que l'objet perde sa portée
if (my $lock = new File::NFSLock {
  file      => $file,
  lock_type => LOCK_EX|LOCK_NB,
  blocking_timeout   => 10,      # 10 secondes
  stale_lock_timeout => 30 * 60, # 30 minutes
}) {
  ### OU
  ### my $lock = File::NFSLock->new($file,LOCK_EX|LOCK_NB,10,30*60);
  ### faire des opérations protégées en écriture sur $file
  ### à ce moment, $file est mis en cache depuis NFS (le plus récent)
  open(FILE, "+<$file") || die $!;
  ### ou ouvrez-le comme vous le souhaitez
  ### my $fh = IO::File->open( $file, 'w' ) || die $!
  ### mettre à jour (vider le cache) d'autres fichiers
  uncache("someotherfile1");
  uncache("someotherfile2");
  # open(FILE2,"someotherfile1");
  ### déverrouiller
  $lock->unlock();
  ### OU
  ### undef $lock;
  ### OU laisser $lock sortir de la portée
}else{
  die "Je n'ai pas pu verrouiller le fichier [$File::NFSLock::errstr]";
}

DESCRIPTION

Programme basé sur le concept de la liaison dure des fichiers étant atomique sur NFS. Ce concept a été mentionné dans Mail::Box::Locker (qui a été initialement présenté dans Mail::Folder::Maildir). Certaines routines sont tirées de là -- en particulier l'idée de créer un fichier local aléatoire, de lier un fichier commun au fichier local, puis de vérifier le statut nlink. Certaines idéologies n'étaient pas complètes (mécanisme d'uncache, verrouillage partagé) et certains codages étaient même incorrects (mauvais index stat). File::NFSLock a été écrit pour être léger, générique et rapide.

USAGE

Le verrouillage s'effectue en créant un objet File::NFSLock. Si l'objet est créé avec succès, un verrou est actuellement en place et le reste jusqu'à ce que l'objet verrou quitte sa portée (ou appelle la méthode unlock).

Un objet verrou est créé en appelant la méthode new et en passant deux à quatre paramètres de la manière suivante :

my $lock = File::NFSLock->new($file,
                              $lock_type,
                              $blocking_timeout,
                              $stale_lock_timeout,
                              );

De plus, les paramètres peuvent être passés sous forme de hashref :

my $lock = File::NFSLock->new({
  file               => $file,
  lock_type          => $lock_type,
  blocking_timeout   => $blocking_timeout,
  stale_lock_timeout => $stale_lock_timeout,
});

PARAMETRES

Paramètre 1 : file
Nom du fichier sur lequel il est prévu d'écrire. Le verrouillage fournira la version la plus récente (sans cache) de ce fichier lors d'un verrouillage de fichier réussi. Il n'est pas nécessaire que ce fichier existe.
Paramètre 2 : lock_type
Le type de verrou doit être l'un des suivants : 
BLOCKING
BL
EXCLUSIVE (BLOCKING)
EX
NONBLOCKING
NB
SHARED
SH

Ou un ou plusieurs des éléments suivants joints avec '|' :

Fcntl::LOCK_EX() (BLOQUANT)
Fcntl::LOCK_NB() (NON BLOQUANT)
Fcntl::LOCK_SH() (PARTAGÉ)

Le type de verrou détermine si le verrou sera bloquant, non bloquant ou partagé. Les verrous bloquants attendront que d'autres verrous soient supprimés avant que le processus ne continue. Les verrous non bloquants retourneront undef si un autre processus détient actuellement le verrou. Le partage permettra à d'autres processus d'effectuer un verrouillage partagé en même temps tant qu'aucun verrou exclusif n'a déjà été obtenu.

Paramètre 3 : blocking_timeout (optionnel)
Le délai d'attente est utilisé en conjonction avec un délai d'attente de blocage. S'il est spécifié, File::NFSLock bloquera jusqu'au nombre de secondes spécifié dans le délai d'attente avant de retourner undef (impossible d'obtenir un verrou).
Paramètre 4 : stale_lock_timeout (optionnel)
Le délai d'attente est utilisé pour voir si un fichier de verrou existant est plus ancien que le délai d'attente de verrou périmé. Si do_lock ne parvient pas à obtenir un verrou, l'heure de modification est vérifiée et do_lock est retenté. Si stale_lock_timeout est réglé trop bas, une charge de récursion pourrait exister, donc do_lock ne récurera que 10 fois (ce n'est un problème que si stale_lock_timeout est réglé trop bas - de l'ordre d'une ou deux secondes).

METHODES

Après que l'objet $lock a été instancié avec new, comme décrit ci-dessus, certaines méthodes peuvent être utilisées pour des fonctionnalités supplémentaires.

unlock

$lock->unlock;

Cette méthode peut être utilisée pour libérer explicitement un verrou acquis. Dans la plupart des cas, il n'est pas nécessaire d'appeler unlock directement car il sera implicitement appelé lorsque l'objet quittera la portée dans laquelle il se trouve.

uncache

$lock->uncache;
$lock->uncache("otherfile1");
uncache("otherfile2");

Cette méthode est utilisée pour actualiser le contenu d'un fichier sur NFS, en ignorant ce qui est contenu dans le cache du client NFS. Elle est toujours appelée depuis le constructeur new sur le fichier pour lequel le verrouillage est tenté. uncache peut être utilisé comme méthode d'objet ou comme sous-routine autonome.

fork

my $pid = $lock->fork;
if (!defined $pid) {
  # Échec du fork
} elsif ($pid) {
  # Parent ...
} else {
  # Enfant ...
}

fork() est une méthode de commodité qui agit comme le CORE::fork() normal, sauf qu'elle garantit en toute sécurité que le verrou est conservé dans les processus parent et enfant. SANS cela, lorsque le processus parent ou enfant libère le verrou, le verrou entier sera perdu, permettant aux processus externes de réacquérir un verrou sur le même fichier, même si l'autre processus a toujours l'objet verrou dans sa portée. Cela peut entraîner une corruption car les deux processus pourraient penser qu'ils ont un accès exclusif au fichier.

newpid

my $pid = fork;
if (!defined $pid) {
  # Échec du fork
} elsif ($pid) {
  $lock->newpid;
  # Parent ...
} else {
  $lock->newpid;
  # Enfant ...
}

La synopsis de newpid() montrée ci-dessus est équivalente à celle utilisée pour la méthode fork(), mais elle n'est pas destinée à être appelée directement. Elle est appelée en interne par la méthode fork(). Pour plus de sécurité, il est recommandé d'utiliser $lock->fork() à partir de maintenant.

ECHEC

En cas d'échec, une variable globale, $File::NFSLock::errstr, doit être définie et contenir la cause de l'échec de l'obtention d'un verrou. Utile principalement pour le débogage.

EXTENSION_VERROU

Par défaut, File::NFSLock utilisera une extension de fichier de verrou de ".NFSLock". Ceci est dans une variable globale $File::NFSLock::LOCK_EXTENSION qui peut être modifiée pour convenir à d'autres usages (tels que la compatibilité dans les systèmes de messagerie).

FIFO

Les verrous ne sont pas nécessairement obtenus dans un ordre chronologique strict. Non seulement cela ne semble pas juste pour les nouveaux processus qui essaient d'obtenir un verrou, mais cela peut également causer une condition de famine de processus sur des fichiers fortement verrouillés.

DIRECTORIES

Les verrous ne peuvent pas être obtenus sur des nœuds de répertoire, ni un nœud de répertoire ne peut être mis hors cache avec la routine uncache beca
