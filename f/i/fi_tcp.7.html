NOM

fi_tcp - Fournisseur s'exécutant sur TCP/IP

APERÇU

Le fournisseur tcp est utilisable sur tous les systèmes d'exploitation pris en charge par libfabric. Il s'exécute sur des sockets TCP (SOCK_STREAM) et inclut la capacité d'exploiter les fonctionnalités spécifiques à l'opération, telles que la prise en charge du zéro copie et de io_uring. Le fournisseur implémente un protocole personnalisé sur TCP/IP nécessaire pour prendre en charge les API de communication libfabric.

FONCTIONNALITÉS PRISES EN CHARGE

Les fonctionnalités suivantes sont prises en charge :

Types d'extrémité
FI_EP_MSG FI_EP_RDM
Capacités d'extrémité
FI_MSG, FI_RMA, FI_TAGGED, FI_RMA_PMEM, FI_RMA_EVENT, FI_MULTI_RECV, FI_DIRECTED_RECV
Contexte de réception partagé
Le fournisseur tcp prend en charge le contexte de réception partagé.

PARAMÈTRES D'EXÉCUTION

Le fournisseur tcp peut être configuré à l'aide de plusieurs variables d'environnement. Un sous-ensemble des variables prises en charge est défini ci-dessous. Pour une liste complète, utilisez l'utilitaire fi_info. Par exemple, `fi_info -g tcp` affichera toutes les variables d'environnement définies pour le fournisseur tcp.

FI_TCP_IFACE
Une interface réseau spécifique peut être demandée avec cette variable.
FI_TCP_PORT_LOW_RANGE/FI_TCP_PORT_HIGH_RANGE
Ces variables sont utilisées pour définir la plage de ports à utiliser par le fournisseur tcp pour la création de ses points d'extrémité passifs. Ceci est utile lorsque seule une plage de ports est autorisée par le pare-feu pour les connexions tcp.
FI_TCP_TX_SIZE
Taille du contexte d'émission. C'est le nombre de requêtes d'émission qu'une application peut poster au fournisseur avant de recevoir -FI_EAGAIN. Par défaut : 256 pour les points d'extrémité msg, 64k pour rdm.
FI_TCP_RX_SIZE
Taille du contexte de réception. C'est le nombre de tampons de réception que l'application peut poster au fournisseur. Par défaut : 256 pour les points d'extrémité msg, 64k pour rdm.
FI_TCP_MAX_INJECT
Taille maximale des messages injectés et taille maximale d'un message inattendu qui peut être mis en tampon chez le récepteur. Par défaut : 128 octets.
FI_TCP_STAGING_SBUF_SIZE
Taille du tampon utilisé pour regrouper les iovec ou les requêtes d'envoi avant de les poster au noyau. Le tampon de staging est utilisé lorsque le socket est occupé et ne peut pas accepter de nouvelles données. Dans ce cas, les données peuvent être mises en file d'attente dans le tampon de staging jusqu'à ce que le socket reprenne l'envoi. Cela optimise le transfert d'une série de petits messages consécutifs vers la même cible. Par défaut : 9000 octets. Défini à 0 pour désactiver.
FI_TCP_PREFETCH_RBUF_SIZE
Taille du tampon utilisé pour précharger les données reçues du noyau. Lors de la réception d'un nouveau message, le fournisseur demandera au noyau de remplir le tampon de préchargement et de traiter les données reçues à partir de là. Cela réduit le nombre d'appels au noyau nécessaires pour recevoir une série de petits messages. Par défaut : 9000 octets. Défini à 0 pour désactiver.
FI_TCP_ZEROCOPY_SIZE
Seuil inférieur où les transferts zéro copie seront utilisés, si pris en charge par la plateforme, défini à -1 pour désactiver. Par défaut : désactivé.
FI_TCP_TRACE_MSG
Si activé, enregistrera les informations de message de transport sur tous les messages envoyés et reçus. Doit être associé à FI_LOG_LEVEL=trace pour afficher les détails du message.
FI_TCP_IO_URING
Utilise io_uring pour les opérations sur les sockets si disponible, plutôt que de passer par les API de socket standard (c'est-à-dire connect, accept, send, recv). Par défaut : désactivé.

OPÉRATIONS DE CONTRÔLE

Le fournisseur tcp prend en charge les opérations de contrôle suivantes (voir fi_control(3)) :

FI_GET_FD
Récupère le descripteur de fichier de socket sous-jacent associé à un point d'extrémité actif. L'argument doit pointer vers un entier où le descripteur sera stocké. Cela permet aux applications de régler les options de socket non exposées via l'API libfabric (SO_SNDBUF, SO_RCVBUF, SO_BUSY_POLL, etc.).

NOTES

Le fournisseur tcp prend en charge directement les points d'extrémité msg et rdm. La prise en charge des points d'extrémité rdm est disponible à partir de la version libfabric v1.18.0, et provient de la fusion du fournisseur net trouvé dans les versions libfabric v1.16 et v1.17. Pour la compatibilité avec les versions antérieures de libfabric, le fournisseur tcp peut être associé au fournisseur ofi_rxm comme solution alternative pour la prise en charge des points d'extrémité rdm. Il est recommandé aux applications qui n'ont pas besoin de compatibilité réseau avec les anciennes versions de libfabric d'utiliser directement la prise en charge des points d'extrémité rdm du fournisseur tcp. Cela fournira les meilleures performances.
