DESCRIPTIO

N

Les opérations RMA (accès à la mémoire distante) sont utilisées pour transférer des données directement entre un tampon de données local et un tampon de données distant. Les transferts RMA se produisent au niveau de l'octet, et aucune limite de message n'est

maintenue.

Les fonctions d'écriture – fi_write, fi_writev, fi_writemsg, fi_inject_write et fi_writedata – sont utilisées pour transmettre des données vers un tampon de mémoire distant. La principale différence entre les fonctions d'écriture réside dans le nombre et le type des paramètres qu'elles acceptent en entrée. Sinon, elles effectuent la même fonction

générale.

Les fonctions de lecture – fi_read, fi_readv et fi_readmsg – sont utilisées pour transférer des données depuis une région de mémoire distante vers des tampon(s) de données local(aux). De manière similaire aux opérations d'écriture, les opérations de lecture fonctionnent de manière asynchrone. Les utilisateurs ne doivent pas toucher aux tampon(s) de données publiés tant que l'opération de lecture n'est pas

terminée.

Les opérations RMA terminées sont signalées à l'utilisateur via une ou plusieurs files de complétion associées au point de terminaison. Les utilisateurs fournissent un contexte qui est associé à chaque opération, et qui est retourné à l'utilisateur en tant que partie de la complétion. Voir fi_cq pour les détails des événements de

complétion.

Par défaut, le point de terminaison distant ne génère pas d'événement ni ne notifie l'utilisateur lorsqu'une région de mémoire a été accédée par une lecture ou une écriture RMA. Cependant, des données immédiates peuvent être associées à une opération d'écriture RMA. Les écritures RMA avec données immédiates généreront une entrée de complétion au point de terminaison distant, afin que les données immédiates puissent être

délivrées.

NAME

fi_write, fi_writemsg - Post a write operation

SYNOPSIS

#include <rdma/fi_verbs.h>

ssize_t fi_write(struct fid_ep *ep,
                   const void *buf,
                   size_t len,
                   fi_addr_t address);

ssize_t fi_writemsg(struct fid_ep *ep,
                    const union fi_msg_data *msg,
                    uint64_t flags);

ARGUMENTS

ep
The endpoint to post the write operation on.
buf
The buffer containing the data to be sent.
len
The size of the data buffer.
address
The destination address. This address must be a valid address obtained from fi_domain(3) or derived from a connected endpoint. If the endpoint is connected, the address is ignored and the data is sent to the connected peer.
msg
A pointer to a fi_msg(3) data structure. This structure is used to specify data buffers, the destination address, and other optional parameters for the write operation.
flags
Flags that modify the behavior of the write operation. See the FLAGS section below for details.

DESCRIPTION

fi_write posts a write operation to the specified endpoint ep. The data is sent from the local buffer buf of size len to the specified address. If the endpoint is connected, the address parameter is ignored and the data is sent to the connected peer. The fi_write call is a simplified interface and is equivalent to calling fi_writemsg with a fi_msg(3) structure containing only the send buffer and length, and no flags.

fi_writemsg posts a write operation using the parameters specified in the fi_msg(3) data structure referenced by msg. The flags specified in flags can modify the default behavior of the write operation. See the FLAGS section below for details.

The fi_write and fi_writemsg calls are asynchronous operations. They initiate a write operation, but the actual data transfer may not be completed when the call returns. The user can check for operation completion by querying the associated completion queue (CQ).

The flags specified with fi_writemsg override most flags previously configured with the endpoint, except where noted (see fi_endpoint(3)).

FLAGS

The fi_readmsg and fi_writemsg calls allow the user to specify flags which can change the default data transfer operation. Flags specified with fi_readmsg / fi_writemsg override most flags previously configured with the endpoint, except where noted (see fi_endpoint.3). The following list of flags are usable with fi_readmsg and/or fi_writemsg.

FI_REMOTE_CQ_DATA
Applies to fi_writemsg. Indicates that remote CQ data is available and should be sent as part of the request. See fi_getinfo for additional details on FI_REMOTE_CQ_DATA. This flag is implicitly set for fi_writedata and fi_inject_writedata.
FI_COMPLETION
Indicates that a completion entry should be generated for the specified operation. The endpoint must be bound to a completion queue with FI_SELECTIVE_COMPLETION that corresponds to the specified operation, or this flag is ignored.
FI_MORE
Indicates that the user has additional requests that will immediately be posted after the current call returns. Use of this flag may improve performance by enabling the provider to optimize its access to the fabric hardware.
FI_INJECT
Applies to fi_writemsg. Indicates that the outbound data buffer should be returned to user immediately after the write call returns, even if the operation is handled asynchronously. This may require that the underlying provider implementation copy the data into a local buffer and transfer out of that buffer. This flag can only be used with messages smaller than inject_size.
FI_INJECT_COMPLETE
Applies to fi_writemsg. Indicates that a completion should be generated when the source buffer(s) may be reused.
FI_TRANSMIT_COMPLETE
Applies to fi_writemsg. Indicates that a completion should not be generated until the operation has been successfully transmitted and is no longer being tracked by the provider.
FI_DELIVERY_COMPLETE
Applies to fi_writemsg. Indicates that a completion should be generated when the operation has been processed by the destination.
FI_COMMIT_COMPLETE
Applies to fi_writemsg when targeting persistent memory regions. Indicates that a completion should be generated only after the result of the operation has been made durable.
FI_FENCE
Applies to transmits. Indicates that the requested operation, also known as the fenced operation, and any operation posted after the fenced operation will be deferred until all previous operations targeting the same peer endpoint have completed. Operations posted after the fencing will see and/or replace the results of any operations initiated prior to the fenced operation.

The ordering of operations starting at the posting of the fenced operation (inclusive) to the posting of a subsequent fenced operation (exclusive) is controlled by the endpoint’s ordering semantics.

RETURN VALUE

Returns 0 on success. On error, a negative value corresponding to fabric errno is returned. Fabric errno values are defined in rdma/fi_errno.h.

ERRORS

-FI_EAGAIN
See fi_msg(3) for a detailed description of handling FI_EAGAIN.

SEE ALSO

fi_getinfo(3), fi_endpoint(3), fi_domain(3), fi_cq(3)

NOM

fi_write, fi_writemsg - Poster une opération d'écriture

SYNTAXE

#include <rdma/fi_verbs.h>

ssize_t fi_write(struct fid_ep *ep,
                   const void *buf,
                   size_t len,
                   fi_addr_t address);

ssize_t fi_writemsg(struct fid_ep *ep,
                    const union fi_msg_data *msg,
                    uint64_t flags);

ARGUMENTS

ep
Le point de terminaison sur lequel poster l'opération d'écriture.
buf
Le tampon contenant les données à envoyer.
len
La taille du tampon de données.
address
L'adresse de destination. Cette adresse doit être une adresse valide obtenue à partir de fi_domain(3) ou dérivée d'un point de terminaison connecté. Si le point de terminaison est connecté, l'adresse est ignorée et les données sont envoyées au pair connecté.
msg
Un pointeur vers une structure de données fi_msg(3). Cette structure est utilisée pour spécifier les tampons de données, l'adresse de destination, et d'autres paramètres optionnels pour l'opération d'écriture.
flags
Les drapeaux qui modifient le comportement de l'opération d'écriture. Voir la section FLAGS ci-dessous pour plus de détails.

DESCRIPTION

fi_write poste une opération d'écriture sur le point de terminaison spécifié ep. Les données sont envoyées depuis le tampon local buf de taille len vers l'address spécifié. Si le point de terminaison est connecté, le paramètre address est ignoré et les données sont envoyées au pair connecté. L'appel fi_write est une interface simplifiée et équivaut à appeler fi_writemsg avec une structure fi_msg(3) ne contenant que le tampon d'envoi et la longueur, et aucun drapeau.

fi_writemsg poste une opération d'écriture en utilisant les paramètres spécifiés dans la structure de données fi_msg(3) référencée par msg. Les drapeaux spécifiés dans flags peuvent modifier le comportement par défaut de l'opération d'écriture. Voir la section FLAGS ci-dessous pour plus de détails.

Les appels fi_write et fi_writemsg sont des opérations asynchrones. Ils initient une opération d'écriture, mais le transfert de données réel peut ne pas être terminé lorsque l'appel retourne. L'utilisateur peut vérifier l'achèvement de l'opération en interrogeant la file d'attente de complétion (CQ) associée.

Les drapeaux spécifiés avec fi_writemsg remplacent la plupart des drapeaux précédemment configurés avec le point de terminaison, sauf indication contraire (voir fi_endpoint(3)).

FLAGS

Les appels fi_readmsg et fi_writemsg permettent à l'utilisateur de spécifier des drapeaux qui peuvent modifier l'opération de transfert de données par défaut. Les drapeaux spécifiés avec fi_readmsg / fi_writemsg remplacent la plupart des drapeaux précédemment configurés avec le point de terminaison, sauf indication contraire (voir fi_endpoint.3). La liste suivante de drapeaux est utilisable avec fi_readmsg et/ou fi_writemsg.

FI_REMOTE_CQ_DATA
S'applique à fi_writemsg. Indique que les données CQ distantes sont disponibles et doivent être envoyées dans le cadre de la requête. Voir fi_getinfo pour plus de détails sur FI_REMOTE_CQ_DATA. Ce drapeau est implicitement défini pour fi_writedata et fi_inject_writedata.
FI_COMPLETION
Indique qu'une entrée de complétion doit être générée pour l'opération spécifiée. Le point de terminaison doit être lié à une file d'attente de complétion avec FI_SELECTIVE_COMPLETION qui correspond à l'opération spécifiée, sinon ce drapeau est ignoré.
FI_MORE
Indique que l'utilisateur a des requêtes supplémentaires qui seront immédiatement postées après le retour de l'appel actuel. L'utilisation de ce drapeau peut améliorer les performances en permettant au fournisseur d'optimiser son accès au matériel fabric.
FI_INJECT
S'applique à fi_writemsg. Indique que le tampon de données sortant doit être retourné à l'utilisateur immédiatement après le retour de l'appel d'écriture, même si l'opération est gérée de manière asynchrone. Cela peut nécessiter que l'implémentation du fournisseur sous-jacent copie les données dans un tampon local et transfère à partir de ce tampon. Ce drapeau ne peut être utilisé qu'avec des messages plus petits que inject_size.
FI_INJECT_COMPLETE
S'applique à fi_writemsg. Indique qu'une complétion doit être générée lorsque les tampons source peuvent être réutilisés.
FI_TRANSMIT_COMPLETE
S'applique à fi_writemsg. Indique qu'une complétion ne doit pas être générée tant que l'opération n'a pas été transmise avec succès et n'est plus suivie par le fournisseur.
FI_DELIVERY_COMPLETE
S'applique à fi_writemsg. Indique qu'une complétion doit être générée lorsque l'opération a été traitée par la destination.
FI_COMMIT_COMPLETE
S'applique à fi_writemsg lors du ciblage de régions de mémoire persistante. Indique qu'une complétion doit être générée uniquement après que le résultat de l'opération ait été rendu durable.
FI_FENCE
S'applique aux transmissions. Indique que l'opération demandée, également connue sous le nom d'opération clôturée, et toute opération postée après l'opération clôturée seront différées jusqu'à ce que toutes les opérations précédentes ciblant le même point de terminaison pair soient terminées. Les opérations postées après la clôture verront et/ou remplaceront les résultats de toute opération initiée avant l'opération clôturée.

L'ordre des opérations commençant par le post de l'opération clôturée (inclus) jusqu'au post d'une opération clôturée ultérieure (exclus) est contrôlé par les sémantiques d'ordre du point de terminaison.

VALEUR DE RETOUR

Retourne 0 en cas de succès. En cas d'erreur, une valeur négative correspondant à l'errno fabric est retournée. Les valeurs d'errno fabric sont définies dans rdma/fi_errno.h.

ERREURS

-FI_EAGAIN
Voir fi_msg(3) pour une description détaillée de la gestion de FI_EAGAIN.
