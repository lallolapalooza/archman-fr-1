NOM

fido2-cred — créer/vérifier une identité FIDO2

SYNOPSIS

fido2-cred -M [-bdhqruvw] [-a mode] [-c cred_protect] [-i input_file] [-o output_file] device [type]

fido2-cred -V [-dhv] [-c cred_protect] [-i input_file] [-o output_file] [type]

DESCRIPTION

fido2-cred crée ou vérifie une identité FIDO2.

Le type d'identité type peut être es256 (désignant ECDSA sur NIST P-256 avec SHA-256), es384 (désignant ECDSA sur NIST P-384 avec SHA-384), rs256 (désignant RSA 2048 bits avec remplissage PKCS#1.5 et SHA-256), ou eddsa (désignant EDDSA sur Curve25519 avec SHA-512). Si type n'est pas spécifié, es256 est supposé.

Lors de la création d'une identité, l'authentificateur peut exiger que l'utilisateur s'authentifie avec un code PIN. Si l'option -q n'est pas spécifiée, fido2-cred demandera le code PIN à l'utilisateur. Si un tty est disponible, fido2-cred l'utilisera pour obtenir le code PIN. Sinon, stdin est utilisé.

L'entrée de fido2-cred est définie par les paramètres de l'identité à créer/vérifier. Voir la section FORMAT D'ENTRÉE pour plus de détails.

La sortie de fido2-cred est définie par le résultat de l'opération sélectionnée. Voir la section FORMAT DE SORTIE pour plus de détails.

Si une identité est créée ou vérifiée avec succès, fido2-cred se termine avec le code 0. Sinon, fido2-cred se termine avec le code 1.

Les options sont les suivantes :

-M
Indique à fido2-cred de créer une nouvelle identité sur device.
-V
Indique à fido2-cred de vérifier une identité.
-b
Demande le « largeBlobKey » de l'identité, une clé symétrique de 32 octets associée à l'identité générée.
-a mode
Lors de la création d'une identité, demande l'attestation d'entreprise. Veuillez consulter <fido/param.h> pour la liste des valeurs possibles.
-c cred_protect
Lors de la création d'une identité, définit le niveau de protection de l'identité à cred_protect, où cred_protect est le niveau de protection de l'identité en notation décimale. Veuillez consulter <fido/param.h> pour la liste des valeurs possibles. Lors de la vérification d'une identité, vérifie si le niveau de protection de l'identité a été signé par l'authentificateur en tant que cred_protect.
-d
Fait que fido2-cred émet une sortie de débogage sur stderr.
-h
Lors de la création d'une identité, active l'extension hmac-secret FIDO2. Lors de la vérification d'une identité, vérifie si le bit de données de l'extension a été signé par l'authentificateur.
-i input_file
Indique à fido2-cred de lire les paramètres de l'identité depuis input_file au lieu de stdin.
-o output_file
Indique à fido2-cred d'écrire la sortie sur output_file au lieu de stdout.
-q
Indique à fido2-cred d'être silencieux. Si un code PIN est requis et que -q est spécifié, fido2-cred échouera.
-r
Crée une identité résidente. Les identités résidentes sont appelées « identités découvrables » dans CTAP 2.1.
-u
Crée une identité U2F. Par défaut, fido2-cred utilisera FIDO2 si l'authentificateur le prend en charge, et reviendra à U2F sinon.
-v
Lors de la création d'une identité, demande la vérification de l'utilisateur. Lors de la vérification d'une identité, vérifie si le bit de vérification de l'utilisateur a été signé par l'authentificateur.
-w
Indique à fido2-cred que la première ligne d'entrée lors de la création d'une identité doit être interprétée comme des données client non hachées. Cela est requis par Windows Hello, qui calcule le hachage des données client en interne.

FORMAT D'ENTRÉE

L'entrée de fido2-cred se compose de blocs base64 et de chaînes UTF-8 séparés par des caractères de nouvelle ligne ('\n').

Lors de la création d'une identité, fido2-cred attend que son entrée se compose de :

  1. hachage des données client (bloc base64) ;
  2. identifiant du tiers de confiance (chaîne UTF-8) ;
  3. nom d'utilisateur (chaîne UTF-8) ;
  4. identifiant utilisateur (bloc base64).

Lors de la vérification d'une identité, fido2-cred attend que son entrée se compose de :

  1. hachage des données client (bloc base64) ;
  2. identifiant du tiers de confiance (chaîne UTF-8) ;
  3. format de l'identité (chaîne UTF-8) ;
  4. données d'authentificateur encodées en CBOR (bloc base64) ;
  5. identifiant de l'identité (bloc base64) ;
  6. signature d'attestation (bloc base64) ;
  7. certificat d'attestation (facultatif, bloc base64).

Les chaînes UTF-8 passées à fido2-cred ne doivent pas contenir de caractères de nouvelle ligne ou NUL intégrés.

FORMAT DE SORTIE

La sortie de fido2-cred se compose de blocs base64, de chaînes UTF-8 et de clés publiques encodées en PEM séparés par des caractères de nouvelle ligne ('\n').

Lors de la génération réussie d'une identité, fido2-cred produit en sortie :

  1. hachage des données client (bloc base64) ;
  2. identifiant du tiers de confiance (chaîne UTF-8) ;
  3. format de l'identité (chaîne UTF-8) ;
  4. données d'authentificateur encodées en CBOR (bloc base64) ;
  5. identifiant de l'identité (bloc base64) ;
  6. signature d'attestation (bloc base64) ;
  7. certificat d'attestation, s'il est présent (bloc base64).
  8. la clé symétrique de 32 octets associée à l'identité (« largeBlobKey »), si elle est présente (bloc base64).

Lors de la vérification réussie d'une identité, fido2-cred produit en sortie :

  1. identifiant de l'identité (bloc base64) ;
  2. clé de l'identité encodée en PEM.

EXEMPLES

Créer une nouvelle identité es256 sur /dev/hidraw5, la vérifier et enregistrer l'identifiant fido2-cred(1) — libfido2 — Arch Linux

NAME

fido2-cred - FIDO2 credential generation and management

SYNOPSIS

fido2-cred -i infile -o outfile

fido2-cred -M -i infile device

fido2-cred -V -o outfile device

DESCRIPTION

The fido2-cred utility is used to generate FIDO2 credentials (public key, private key and associated metadata). The generated credential can then be used by fido2-assert(1) to authenticate to a relying party.

The utility supports both USB HID and NFC devices. For USB HID devices, the correct device node needs to be specified. For NFC devices, the utility will try to find one automatically.

The utility can be used in two modes:

-M
Generate a new credential. This option requires the user to provide an input file with parameters for the credential generation. See INPUT FORMAT for more details.
-V
Verify an existing credential. This option requires the user to provide an input file with parameters for the credential verification. See INPUT FORMAT for more details.

The user needs to select the device node to use for communication with the FIDO2 device. On Linux, this is typically a path under /dev/hidraw*. On macOS, it is typically a path under /dev/hid*.

The output of the utility is stored in the file specified by the -o option. See OUTPUT FORMAT for more details.

INPUT FORMAT

The input file specified by the -i option is a text file where each line represents a parameter for the FIDO2 operation. The following parameters are supported:

challenge
The challenge string used for credential generation or verification. This is typically a random string generated by the relying party.
relying party id
The identifier of the relying party. This is typically a domain name.
user name
The user name or identifier. This is typically a username or email address.
pin
The PIN for the FIDO2 device. If not provided, the user will be prompted for the PIN.
client data
The client data JSON string. This is typically generated by the client application.
authenticator data
The authenticator data. This is typically returned by the FIDO2 device during a previous operation.

The order of the parameters in the input file is important. The utility expects the parameters in the following order:

  1. challenge
  2. relying party id
  3. user name
  4. PIN (optional)
  5. client data (for verification)
  6. authenticator data (for verification)

OUTPUT FORMAT

The output file specified by the -o option is a binary file containing the generated FIDO2 credential. The file format is as follows:

credential id
The identifier of the credential. This is a unique identifier for the credential.
public key
The public key of the credential. This key is used by the relying party to verify the signature generated by the FIDO2 device.
attestation data
The attestation data. This data is used by the relying party to verify the authenticity of the FIDO2 device.

EXAMPLES

Generate a new FIDO2 credential:

$ echo credential challenge | openssl sha256 -binary | base64 > cred_param
$ echo relying party >> cred_param
$ echo user name >> cred_param
$ dd if=/dev/urandom bs=1 count=32 | base64 >> cred_param
$ fido2-cred -M -i cred_param /dev/hidraw5 | fido2-cred -V -o cred

SEE ALSO

fido2-assert(1), fido2-token(1)

CAVEATS

Please note that fido2-cred handles Basic Attestation and Self Attestation transparently. In the case of Basic Attestation, the validity of the authenticator's attestation certificate is not verified.
