Paquet: perl-file-readbackwards

ReadBackwards(3) Documentation Perl Contribuée par l'Utilisateur ReadBackwards(3)

NOM

File::ReadBackwards.pm -- Lire un fichier à l'envers par lignes.

SYNOPIS

use File::ReadBackwards ;
# Interface objet
$bw = File::ReadBackwards->new( 'log_file' ) or
                    die "impossible de lire 'log_file' $!" ;
while( defined( $log_line = $bw->readline ) ) {
        print $log_line ;
}
# ... ou l'autre manière de lire
until ( $bw->eof ) {
        print $bw->readline ;
}
# Interface de gestion liée (Tied Handle)
tie *BW, 'File::ReadBackwards', 'log_file' or
                    die "impossible de lire 'log_file' $!" ;
while( <BW> ) {
        print ;
}

DESCRIPTION

Ce module lit un fichier à l'envers ligne par ligne. Il est simple d'utilisation, économe en mémoire et rapide. Il prend en charge une interface objet et une interface de gestion liée (tied handle).

Il est destiné au traitement de fichiers journaux et autres fichiers textes similaires qui ont généralement leurs nouvelles entrées ajoutées à la fin. Par défaut, les fichiers sont considérés comme du texte brut et possèdent une fin de ligne appropriée au système d'exploitation. Mais vous pouvez définir la chaîne de séparateur d'enregistrements d'entrée pour chaque fichier.

INTERFACE OBJET

Ce sont les méthodes de l'interface objet de "File::ReadBackwards" :

new( $file, [$rec_sep], [$sep_is_regex] )

"new" prend en arguments un nom de fichier, un séparateur d'enregistrements optionnel et un indicateur optionnel qui marque le séparateur d'enregistrements comme une expression régulière. Il renvoie l'objet en cas d'ouverture réussie, ou undef en cas d'échec. $! est défini avec le code d'erreur le cas échéant.

readline

"readline" ne prend aucun argument et renvoie la ligne précédente du fichier ou undef s'il n'y a plus de lignes dans le fichier. Si le fichier n'est pas recherchable (par exemple, un tube), undef est renvoyé.

getline

"getline" est un alias pour la méthode readline. Elle est présente pour la compatibilité avec les classes IO::* qui ont une méthode getline.

eof

"eof" ne prend aucun argument et renvoie vrai lorsque readline() a parcouru tout le fichier.

close

"close" ne prend aucun argument et ferme la gestion (handle).

tell

"tell" ne prend aucun argument et renvoie la position actuelle de la gestion de fichier. Cette valeur peut être utilisée pour y revenir en utilisant seek() avec une gestion de fichier normale.

get_handle

"get_handle" ne prend aucun argument et renvoie la gestion de fichier Perl interne utilisée par l'objet File::ReadBackwards. Cette gestion peut être utilisée pour lire le fichier vers l'avant. Sa position de recherche sera définie sur la position renvoyée par la méthode tell(). Notez que l'alternance de lectures avant et arrière peut produire des résultats imprévisibles. La seule utilisation prise en charge à l'heure actuelle est de lire un fichier à l'envers jusqu'à un certain point, puis d'utiliser 'handle' pour extraire la gestion, et de lire vers l'avant à partir de ce point.

INTERFACE GESTION LIÉE (TIED HANDLE)

tie( *HANDLE, 'File::ReadBackwards', $file, [$rec_sep], [$sep_is_regex] )

Les méthodes TIEHANDLE, READLINE, EOF, CLOSE et TELL sont des alias pour les méthodes new, readline, eof, close et tell respectivement, donc référez-vous-y pour leurs arguments et API. Une fois que vous avez lié une gestion à File::ReadBackwards, la seule opération d'E/S permise est <> qui lira la ligne précédente. Vous pouvez également appeler eof() et close() sur la gestion liée. Toutes les autres opérations sur la gestion liée généreront une erreur de méthode inconnue. Ne recherchez pas, n'écrivez pas ou n'effectuez aucune autre opération non prise en charge sur la gestion liée.

FINS DE LIGNE ET D'ENREGISTREMENTS

Comme ce module doit utiliser des E/S de bas niveau pour l'efficacité, il ne peut pas se déplacer et effectuer des E/S par blocs de manière portable sans gérer les conversions de fins de ligne. Ce module prend en charge les séparateurs d'enregistrements par défaut des chaînes de fin de ligne normales utilisées par le système d'exploitation. Vous pouvez également définir le séparateur par fichier.

Le séparateur d'enregistrements est une expression régulière par défaut, ce qui diffère du comportement de $/.

Ce n'est que si le séparateur d'enregistrements n'est pas spécifié et qu'il utilise par défaut CR/LF (par exemple, VMS, redmondware) qu'il sera converti en un seul caractère de nouvelle ligne. Les systèmes de fichiers Unix et MacOS n'utilisent qu'un seul caractère pour les fins de ligne et les lignes restent inchangées. Cela signifie que pour les fichiers texte natifs, vous devriez pouvoir traiter leurs lignes à l'envers sans aucun problème de fins de ligne. Si vous spécifiez un séparateur d'enregistrements, aucune conversion ne sera effectuée et vous obtiendrez les enregistrements comme si vous les lisiez en mode binaire.

CONCEPTION

Il fonctionne en lisant un bloc de données volumineux (8 Ko) depuis la fin du fichier. Il les divise ensuite sur le séparateur d'enregistrements et stocke une liste d'enregistrements dans l'objet. Chaque appel à readline renvoie l'enregistrement du haut de la liste et si la liste est vide, elle est remplie en lisant le bloc précédent depuis le fichier et en le divisant. Lorsque le début du fichier est atteint et qu'il n'y a plus de lignes, undef est renvoyé. Toutes les conditions limites sont gérées correctement, c'est-à-dire que s'il y a une ligne partielle finale (pas de caractère de nouvelle ligne), elle sera la première ligne renvoyée et les lignes plus grandes que la taille du tampon de lecture sont gérées correctement.

NOTES

Il n'y a pas de prise en charge du contexte de liste dans les interfaces objet ou liées. Si vous souhaitez charger toutes les lignes dans un tableau dans l'ordre inverse (et que l'utilisation de la mémoire ne vous importe pas), faites simplement ceci :

@back_lines = reverse <FH>.

Ce module est uniquement destiné à lire une ligne à la fois depuis la fin d'un fichier jusqu'au début.
