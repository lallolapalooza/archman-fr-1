fido_dev_enable_entattest(3)

Paquet: libfido2

Licences: BSD-2-Clause

FIDO_DEV_ENABLE_ENTATTEST(3) Manuel des fonctions de bibliothèque FIDO_DEV_ENABLE_ENTATTEST(3)

NOM

fido_dev_enable_entattest, fido_dev_toggle_always_uv, fido_dev_force_pin_change, fido_dev_set_pin_minlen, fido_dev_set_pin_minlen_rpid — API de configuration de l'authentificateur CTAP 2.1

SYNTAXE

#include <fido.h>
#include <fido/config.h>

int
fido_dev_enable_entattest(fido_dev_t *dev, const char *pin);

int
fido_dev_toggle_always_uv(fido_dev_t *dev, const char *pin);

int
fido_dev_force_pin_change(fido_dev_t *dev, const char *pin);

int
fido_dev_set_pin_minlen(fido_dev_t *dev, size_t len, const char *pin);

int
fido_dev_set_pin_minlen_rpid(fido_dev_t *dev, const char * const *rpid, size_t n, const char *pin);

DESCRIPTION

Les fonctions décrites dans cette page permettent la configuration d'un authentificateur CTAP 2.1.

La fonction fido_dev_enable_entattest() active la fonctionnalité Enterprise Attestation sur dev. Enterprise Attestation demande à l'authentificateur d'inclure des informations d'identification uniques dans les déclarations d'attestation ultérieures. Le paramètre pin peut être NULL si dev n'a pas de PIN défini.

La fonction fido_dev_toggle_always_uv() bascule la fonctionnalité « vérification utilisateur toujours » sur dev. Lorsqu'elle est activée, cette option impose la vérification de l'utilisateur au niveau de l'authentificateur pour tous les identifiants connus. Si dev prend en charge U2F (CTAP1) et que les méthodes de vérification utilisateur supportées par l'authentificateur ne permettent pas la protection des identifiants U2F, le sous-système U2F sera désactivé par l'authentificateur. Le paramètre pin peut être NULL si dev n'a pas de PIN défini.

La fonction fido_dev_force_pin_change() demande à dev d'exiger un changement de PIN. Les tentatives d'authentification de PIN ultérieures contre dev échoueront jusqu'à ce que son PIN soit modifié.

La fonction fido_dev_set_pin_minlen() définit la longueur minimale du PIN de dev à len. Les longueurs minimales de PIN ne peuvent qu'être augmentées.

La fonction fido_dev_set_pin_minlen_rpid() définit la liste des identifiants de partie de confiance (RP ID) qui sont autorisés à obtenir la longueur minimale du PIN de dev via l'extension CTAP 2.1 FIDO_EXT_MINPINLEN. La liste des identifiants RP est désignée par rpid, un vecteur de n chaînes UTF-8 se terminant par NUL. Une copie de rpid est effectuée, et aucune référence à celle-ci ou à son contenu n'est conservée. La valeur maximale de n supportée par l'authentificateur peut être obtenue en utilisant fido_cbor_info_maxrpid_minpinlen(3).

Les paramètres de configuration sont reflétés dans la charge utile retournée par l'authentificateur en réponse à un appel à fido_dev_get_cbor_info(3).

VALEUR DE RETOUR

Les codes d'erreur retournés par fido_dev_enable_entattest(), fido_dev_toggle_always_uv(), fido_dev_force_pin_change(), fido_dev_set_pin_minlen(), et fido_dev_set_pin_minlen_rpid() sont définis dans <fido/err.h>. En cas de succès, FIDO_OK est retourné.

VOIR AUSSI

fido_cbor_info_maxrpid_minpinlen(3), fido_cred_pin_minlen(3), fido_dev_get_cbor_info(3), fido_dev_reset(3)
