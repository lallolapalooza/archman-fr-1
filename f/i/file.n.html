file(n) Commandes intégrées Tcl file(n)

NOM

file - Manipuler les noms et attributs de fichiers

SYNOPSIS

file option nom ?arg arg ...?

DESCRIPTION

Cette commande fournit plusieurs opérations sur le nom ou les attributs d'un fichier. Nom est le nom d'un fichier ; s'il commence par un tilde, une substitution de tilde est effectuée avant d'exécuter la commande (voir la page de manuel de filename pour plus de détails). Option indique ce qu'il faut faire avec le nom du fichier. Toute abréviation unique pour option est acceptable. Les options valides sont :

file atime nom ?temps?
Retourne une chaîne décimale indiquant le moment où le fichier nom a été accédé pour la dernière fois. Si temps est spécifié, il s'agit du temps d'accès à définir pour le fichier. Le temps est mesuré de la manière POSIX standard, en secondes depuis une heure fixe (souvent le 1er janvier 1970). Si le fichier n'existe pas ou si son temps d'accès ne peut être interrogé ou défini, une erreur est générée. Sous Windows, les systèmes de fichiers FAT ne supportent pas les temps d'accès.
file attributes nom
file attributes nom ?option?
file attributes nom ?option valeur option valeur...?
Cette sous-commande retourne ou définit des valeurs spécifiques à la plateforme associées à un fichier. La première forme retourne une liste des options spécifiques à la plateforme et leurs valeurs. La deuxième forme retourne la valeur de l'option donnée. La troisième forme définit une ou plusieurs valeurs. Les valeurs sont les suivantes :

Sous Unix, -group obtient ou définit le nom du groupe du fichier. Un identifiant de groupe peut être passé à la commande, mais elle retourne un nom de groupe. -owner obtient ou définit le nom d'utilisateur du propriétaire du fichier. La commande retourne le nom du propriétaire, mais l'identifiant numérique peut être passé lors de la définition du propriétaire. -permissions récupère ou définit les permissions d'accès d'un fichier, en utilisant la notation octale par défaut. Cette option fournit également un support limité pour la définition des permissions en utilisant la notation symbolique acceptée par la commande chmod, suivant le format [ugo]?[[+-=][rwxst],[...]]. Plusieurs spécifications de permissions peuvent être données, séparées par des virgules. Par exemple, u+s,go-rw définirait le bit setuid pour le propriétaire d'un fichier ainsi que supprimerait les permissions de lecture et d'écriture pour le groupe et les autres utilisateurs du fichier. Une chaîne de style ls de la forme rwxrwxrwx est également acceptée mais doit toujours comporter 9 caractères. Par exemple, rwxr-xr-t est équivalent à 01755. Sur les versions d'Unix supportant les drapeaux de fichiers, -readonly retourne la valeur de, ou définit, ou efface l'attribut de lecture seule d'un fichier, c'est-à-dire le drapeau immuable utilisateur (uchg) pour la commande chflags.

Sous Windows, -archive donne la valeur ou définit ou efface l'attribut d'archivage du fichier. -hidden donne la valeur ou définit ou efface l'attribut caché du fichier. -longname développera chaque élément du chemin vers sa version longue. Cet attribut ne peut pas être défini. -readonly donne la valeur ou définit ou efface l'attribut de lecture seule du fichier. -shortname donne une chaîne où chaque élément du chemin est remplacé par sa version courte (8.3) du nom si possible. Pour les éléments de chemin qui ne peuvent pas être mappés à des noms courts, le nom long est conservé. Cet attribut ne peut pas être défini. -system donne ou définit ou efface la valeur de l'attribut système du fichier.

Sous macOS et Darwin, -creator donne ou définit le type créateur du Finder du fichier. -hidden donne ou définit ou efface l'attribut caché du fichier. -readonly donne ou définit ou efface l'attribut de lecture seule du fichier. -rsrclength donne la longueur de la fourche de ressources du fichier, cet attribut ne peut être défini qu'à la valeur 0, ce qui a pour conséquence de supprimer la fourche de ressources du fichier.

file channels ?motif?
Si motif n'est pas spécifié, retourne une liste des noms de tous les canaux ouverts enregistrés dans cet interpréteur. Si motif est spécifié, seuls les noms correspondant à motif sont retournés. La correspondance est déterminée selon les mêmes règles que pour string match.
file copy ?-force? ?--? source cible
file copy ?-force? ?--? source ?source ...? repertoireCible
La première forme crée une copie du fichier ou du répertoire source sous le chemin cible. Si cible est un répertoire existant, alors la deuxième forme est utilisée. La deuxième forme crée une copie à l'intérieur de repertoireCible de chaque fichier source listé. Si un répertoire est spécifié comme source, alors le contenu du répertoire sera copié récursivement dans repertoireCible. Les fichiers existants ne seront pas écrasés sauf si l'option -force est spécifiée (auquel cas Tcl tentera également d'ajuster les permissions sur le fichier ou répertoire de destination si nécessaire pour permettre à la copie de se poursuivre). Lors de la copie au sein d'un même système de fichiers, file copy copiera les liens symboliques (c'est-à-dire que les liens eux-mêmes sont copiés, pas les éléments auxquels ils pointent). Tenter d'écraser un répertoire non vide, d'écraser un répertoire avec un fichier, ou d'écraser un fichier avec un répertoire entraînera des erreurs même si -force a été spécifié. Les arguments sont traités dans l'ordre spécifié, s'arrêtant à la première erreur, le cas échéant. Un -- marque la fin des options ; l'argument suivant le -- sera traité comme une source même s'il commence par un -.
file delete ?-force? ?--? ?chemin ... ?
Supprime le fichier ou le répertoire spécifié par chaque argument chemin. Les répertoires non vides ne seront supprimés que si l'option -force est spécifiée. Lors de l'opération sur des liens symboliques, les liens eux-mêmes seront supprimés, pas les objets auxquels ils pointent. Tenter de supprimer un fichier inexistant n'est pas considéré comme une erreur. Tenter de supprimer un fichier en lecture seule entraînera la suppression du fichier, même si l'option -force n'est pas spécifiée. Si l'option -force est spécifiée sur un répertoire, Tcl tentera à la fois de changer les permissions et de déplacer le répertoire courant “pwd” hors du chemin donné si cela est nécessaire pour permettre la suppression. Les arguments sont traités dans l'ordre spécifié, s'arrêtant à la première erreur, le cas échéant. Un -- marque la fin des options ; l'argument suivant le -- sera traité comme un chemin même s'il commence par un -.
file dirname nom
Retourne un nom composé de tous les composants de chemin dans nom à l'exclusion du dernier élément. Si nom est un nom de fichier relatif et ne contient qu'un seul élément de chemin, retourne alors “.”. Si nom fait référence à un répertoire racine, alors le répertoire racine est retourné. Par exemple,
file dirname c:/

retourne c:/.

Notez que la substitution de tilde ne sera effectuée que si elle est nécessaire pour compléter la commande. Par exemple,

file dirname ~/src/foo.c

retourne ~/src, tandis que

file dirname ~

retourne /home (ou quelque chose de similaire).

file executable nom
Retourne 1 si le fichier nom est exécutable par l'utilisateur actuel, 0 sinon. Sous Windows, qui n'a pas d'attribut exécutable, la commande traite tous les répertoires et tous les fichiers avec les extensions exe, com, cmd ou bat comme exécutables.
file exists nom
Retourne 1 si le fichier nom existe et que l'utilisateur actuel a des privilèges de recherche pour les répertoires qui y mènent, 0 sinon.
file extension nom
Retourne tous les caractères dans nom après et incluant le dernier point dans le dernier élément de nom. S'il n'y a pas de point dans le dernier élément de nom, retourne la chaîne vide.
file join nom ?nom ...?
Cette commande génère un nouveau nom de fichier en joignant les noms de fichiers donnés par les arguments nom. La génération est effectuée en utilisant les conventions de nommage de fichiers appropriées à la plateforme actuelle. Par exemple, sur Unix, cela pourrait produire /usr/local/bin/myprog, tandis que sous Windows, cela pourrait produire C:/Program Files/MyApp/config.sys. La commande gère également correctement les barres obliques inverses et les barres obliques (par exemple, l'invocation file join a b/c d\\e produirait a/b/c/d/e sous Unix et a\b\c\d\e sous Windows).

Cette procédure montre comment rechercher des fichiers C dans un répertoire donné qui ont un fichier objet du même nom dans le répertoire courant

: 
proc findMatchingCFiles {dir} {
    set files {}
    switch $::tcl_platform(platform) {
        windows {
            set ext .obj
        }
        unix {
           set ext .o
        }
    }
    foreach file [glob -nocomplain -directory $dir *.c] {
        set objectFile [file tail [file rootname $file]]$ext
        if {[file exists $objectFile]} {
            lappend
files $file }
} return $files }
