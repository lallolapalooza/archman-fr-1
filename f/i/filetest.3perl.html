NOM

filetest - Pragma Perl pour contrôler les opérateurs de test de fichiers

SYNTAXE

$peut_peut_etre_lire = -r "fichier";      # utiliser les bits de mode
{
    use filetest 'access';          # intuitivité accrue
    $peut_vraiment_lire = -r "fichier";
}
$peut_peut_etre_lire = -r "fichier";      # utiliser les bits de mode à nouveau

DESCRIPTION

Ce pragma indique au compilateur de modifier le comportement des opérateurs de test de fichiers, "-r" "-w" "-x" "-R" "-W" "-X" (voir perlfunc).

Le comportement par défaut des opérateurs de test de fichiers est d'utiliser les bits de mode simples retournés par la famille d'appels système stat(). Cependant, de nombreux systèmes d'exploitation disposent de fonctionnalités supplémentaires pour définir des droits d'accès plus complexes, par exemple les ACL (listes de contrôle d'accès). Pour de tels environnements, "use filetest" peut aider les opérateurs de permission à retourner des résultats plus cohérents avec d'autres outils.

Les instructions "use filetest" ou "no filetest" affectent les tests de fichiers définis dans leur bloc, jusqu'à la fin du bloc le plus proche (ils sont limités lexicalement au bloc).

Actuellement, seule la sous-pragma "access" est implémentée. Elle active (ou désactive) l'utilisation de access() lorsque disponible, c'est-à-dire sur la plupart des systèmes UNIX et autres environnements POSIX. Voir les détails ci-dessous.

Considérez ceci attentivement

Les bits de mode de stat() sont probablement corrects pour la plupart des fichiers et répertoires de votre système, car peu de gens veulent utiliser les fonctionnalités supplémentaires offertes par access(). Mais vous pourriez avoir des surprises si votre programme s'exécute sur un système utilisant des ACL, car les informations de stat() ne refléteraient pas les permissions réelles.

Il peut y avoir une légère diminution des performances des opérations de test de fichiers lorsque le pragma filetest est actif, car vérifier des bits est très peu coûteux.

Notez également que l'utilisation des tests de fichiers à des fins de sécurité est une cause perdue dès le départ : il existe une fenêtre ouverte aux conditions de concurrence (qui peut dire que les permissions n'auront pas changé entre le test et l'opération réelle ?). Par conséquent, si vous êtes sérieux au sujet de la sécurité, essayez simplement l'opération réelle et testez son succès - pensez en termes d'opérations atomiques. Les tests de fichiers sont plus utiles pour les tâches d'administration du système de fichiers, lorsque vous n'avez pas besoin du contenu des éléments sur le disque.

La sous-pragma "access"

Les systèmes UNIX et POSIX fournissent un appel système abstrait access(), qui doit être utilisé pour interroger les droits de lecture, d'écriture et d'exécution. Cette fonction masque diverses approches distinctes dans des fonctionnalités de sécurité supplémentaires spécifiques au système d'exploitation, telles que les listes de contrôle d'accès (ACL).

La fonctionnalité étendue de test de fichier n'est utilisée par Perl que lorsque l'argument des opérateurs est un nom de fichier, pas lorsqu'il s'agit d'une poignée de fichier.

Limitation concernant "_"

Comme access() n'invoque pas stat() (du moins pas d'une manière visible pour Perl), le cache de résultat de stat "_" n'est pas défini. Cela signifie que le résultat des deux tests suivants est différent. Le premier a les bits de stat de /etc/passwd dans "_", et dans le second cas, cela contient toujours les bits de "/etc".

{ -d '/etc';
  -w '/etc/passwd';
  print -f _ ? 'Oui' : 'Non';   # Oui
}
{ use filetest 'access';
  -d '/etc';
  -w '/etc/passwd';
  print -f _ ? 'Oui' : 'Non';   # Non
}

Bien sûr, à moins que votre OS n'implémente pas access(), auquel cas le pragma est simplement ignoré. Il est préférable de ne pas utiliser "_" du tout dans un fichier où le pragma filetest est actif !

En conséquence, comme "_" ne fonctionne pas, les opérateurs de test de fichiers empilés ("-f -w $fichier") ne fonctionneront pas non plus.

Cette limitation pourrait être supprimée dans une future version de perl.
