DESCRIPTIO

N

Ce module est conçu pour fonctionner avec les fichiers .desktop. Le format de ces fichiers est spécifié par la spécification freedesktop « Desktop Entry ». Ce module peut analyser ces fichiers mais sait aussi comment exécuter les applications définies par ces

fichiers.

Pour ce module, la version 1.0 de la spécification a été

utilisée.

Ce module a été écrit pour prendre en charge File::MimeInfo::

Applications.

Veuillez vous rappeler : la cas

se est significative pour les n
oms des clés Desktop Entry.

VARIABLE

S

Vous pouvez définir la variable globale $File::DesktopEntry::VERBOSE. Si elle est définie, le module affiche un avertissement chaque fois qu'une commande est

exécutée.

La variable globale $File::DesktopEntry::LOCALE indique la locale par défaut utilisé

e. Cependant, la modifier ne chan
gera pas la locale par défaut.

Obtient une valeur pour KEY à partir de GROUP. Si GROUP n'est pas spécifié, 'Desktop Entry' est utilisé. Toutes les valeurs sont traitées comme des chaînes, donc par exemple les booléens seront renvoyés sous forme de chaînes littérales "true" et "false".

Lorsque KEY ne contient pas de code de langue, vous obtenez la traduction dans la locale actuelle si elle est disponible, ou une valeur par défaut appropriée. Pour demander une langue spécifique, vous pouvez ajouter la partie langue. Par exemple "$entry->get('Name[nl_NL]')" peut renvoyer soit la valeur de la clé 'Name[nl_NL]', 'Name[nl]' ou 'Name' dans le fichier Desktop Entry. L'ordre exact d

'analyse des langues peut être trouvé dans la spécification. Pour forcer l'

"set(KEY => VALUE, ..

"set(GROUP, KEY => VALUE, ..

Définit des valeurs pour une ou plusieurs clés. Si GROUP n'est pas donné, "Desktop Entry" est utilisé. Toutes les valeurs sont traitées comme des chaînes, les barres obliques inversées, les nouvelles lignes et les tabulations sont échappées. Pour définir une clé booléenne, vous devez utiliser les chaînes littérales "true" et "false".

Contrairement à l'appel get(), les langues ne sont pas gérées automatiquement pour set(). KEY doit inclure la partie langue si vous souhaitez définir une traduction. Par exemple "$entry->set("Name[nl_NL]" => "Tekst Verwerker")" définira une traduction néerlandaise pour la clé Name. L'utilisation de "Name[C]" ou "Name[POSIX]" sera équivalente à ne pas donner d'argument de

PLATEFORMES

NON-UNIX

Ce module contient quelques morceaux de code pour le faire fonctionner sur Windows. Il gère les uri "file://" un peu différemment et il utilise Win32::Process. Sur les autres plateformes, l'expérience peut

varier.

Veuillez noter que la spécification cible uniquement les plateformes Unix et n'aura qu

'une pertinence limitée sur les autres plateformes. Tout comportement dépendant de la
plateforme dans ce module doit être considéré comme une extension de la spécification.

LIMITATION

S

Si vous essayez d'exécuter un fichier distant avec une application qui ne peut traiter que des fichiers sur le système de fichiers local, nous devrions -selon la spécification- télécharger le fichier dans un emplacement temporaire. Cela n'est pas pris en charge. Utilisez la méthode wants_uris() pour vérifier si une application prend en charge les

urls.

Les valeurs des différentes clés Desktop Entry ne sont pas analysées (sauf pour la clé Exec). Cela signifie que les booléens seront retournés sous la forme des chaînes "true" et "false" et que les listes seront toujours séparées par ";

".

Si l'icône est donnée sous forme de nom et non de chemin, elle devrait être résolue pour le code %i dans la clé Exec. Nous avons besoin d'un module séparé pour la spécification des icônes afin de gérer

cela.

Selon la spécification, les commentaires peuvent contenir n'importe quel encodage. Cependant, comme ce module lit les fichiers en utf8, des caractères UTF-8 invalides dans un commentaire provoqueront une

erreur.

Il n'y a pas de support pour l'encodage mixte hérité (Legacy-Mixed Encoding). Tout le monde utilise utf8 maintenant ... n'est-ce

pas
?
